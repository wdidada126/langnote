# 笔记：静态指针 / 函数指针 / 智能指针 概念介绍

> **整理日期**：2026-09-12
> **性质**：概念梳理笔记（非译文）
> **一句话概括**：**静态指针**说的是指针**自己的存储期与作用域**（`static` 修饰指针变量本身）；**函数指针**是"指向代码的指针"，用来做回调与策略分派；**智能指针**是用 RAII 包装裸指针、**自动管理生命周期**的类模板。

---

## 0. 先立好坐标系：指针有三个彼此独立的属性

一切混淆都来自把下面三件事混在一起：

| 属性 | 含义 | 由什么决定 |
|---|---|---|
| **存储期 / 作用域** | 指针**变量自己**活多久、哪里可见 | `static`、`extern`、声明位置 |
| **类型 / 可写性** | 指针**能指向什么**、**指向的对象能否改**、**指针自己能否改** | `const` 的位置、指向类型 |
| **所有权 / 生命周期管理** | 指向的**资源**谁来释放 | 裸指针（人管）vs 智能指针（RAII） |

**关键**：`static` 只影响第一列，`const` 影响第二列，智能指针解决第三列。三者互不替代。

---

## 1. 静态指针（static pointer）

### 1.1 术语先澄清

`静态指针`**不是 C/C++ 标准里的术语**，标准里只有"**静态存储期**（static storage duration）"这一属性。中文语境下它通常指下面两类之一：

1. **由 `static` 修饰的指针变量**（绝大多数情况）——即指针**本身**具有静态存储期。
2. **类的静态指针成员**（`static T* ptr;`）——本质是第 1 类，只是作用域在类里。

要点一句话：**`static` 修饰的是"指针这个变量"，与它指向什么对象、对象在哪儿毫无关系。**

### 1.2 语法：`static` 加在指针名之前（修饰指针变量）

```cpp
static int *p;        // ✅ p 是"静态存储期的 int 指针"
int * static p;       // ❌ 语法错误，static 是存储类说明符，位置不能这样放
static int* const p2 = &g;   // ✅ 静态 + 指针本身不可改
```

- `static int *p;` 中的 `static` **不是**类型的一部分，`p` 的类型仍然是 `int*`。
- 可以同时叠加 `const`，但二者管的是**不同维度**（见 §1.6 对照表）。

### 1.3 三种典型出现位置

**(1) 函数内的静态局部指针 —— 只初始化一次，函数返回后依然存活**

```cpp
void f() {
    static int *p = nullptr;      // 只在第一次进入函数时初始化
    if (!p) p = new int(42);      // 做一次性初始化 / 缓存
    ++*p;                         // 下次调用仍能看到上次的值
}
```

> 存储位置在 `.data` / `.bss` 段（不是栈），所以**函数返回后地址依然有效**。常用于单例、懒加载缓存、计数器。

**(2) 文件作用域（全局）的静态指针 —— 内部链接，不导出给其它翻译单元**

```cpp
// file_a.cpp
static int *g_cache = nullptr;    // 只在本文件可见（internal linkage）
```

在 C/C++ 中 `static` 修饰全局变量/函数时，含义是**内部链接**，避免与其他 `.cpp` 中的同名符号冲突（C++ 中更推荐匿名的 `namespace { }` 或 `const`）。

**(3) 类的静态指针成员 —— 属于类，不属于某个对象**

```cpp
class Logger {
public:
    static Logger *instance;              // 声明（类内，不分配空间）
};
Logger *Logger::instance = nullptr;       // 定义（类外，C++17 起可 inline static）
```

- 所有对象**共享同一份**，可用 `Logger::instance` 直接访问，无需对象。
- C++17 起可用 `inline static Logger *instance = nullptr;` 在类内直接定义，免去类外定义。

### 1.4 初始化的两个时机（C++ 里最容易踩的点）

| 初始化方式 | 时机 | 用途 |
|---|---|---|
| **静态初始化**（常量表达式） | 程序加载时（`.data`/`.bss`） | `static int *p = nullptr;` |
| **动态初始化**（需运行期计算） | `main` 之前、由运行时逐个执行 | `static Cfg *c = make_cfg();` |

- 多个翻译单元的**动态初始化顺序是未定义的** → 经典问题 **静态初始化顺序惨案（SIOF）**：A 文件里的静态指针在 B 文件里被使用，但 B 执行时 A 可能还没初始化 → 拿到 `nullptr`。
- **规避手段**：改成"函数内静态局部变量"（C++11 起线程安全的懒初始化，首次调用才构造）：

```cpp
Config& cfg() {                 // Meyers Singleton：替代全局静态对象/指针
    static Config c;            // C++11 起保证线程安全的一次性初始化
    return c;
}
```

### 1.5 静态指针最大的风险：悬空（dangling）

静态存储期意味着**指针活得比一般变量都久**，于是"指向一个已死对象"的概率大增：

| 危险写法 | 后果 |
|---|---|
| `static int *p = &localVar;` 指向栈上局部变量 | 函数返回后指向已释放栈帧，使用即 UB |
| `static std::string *p = new std::string("x");` 从不 `delete` | 有意/无意的"永久泄漏"（进程退出才回收） |
| `static Widget *p = &someObj;`，`someObj` 后被析构 | 指针仍非空但对象已亡——**判空检查救不了你** |
| 多线程下 `static T *p` 被并发读写 | 指针变量本身**不是原子的**，需加锁或 `std::atomic<T*>` |

> 建议：静态指针只用于"生命周期贯穿整个进程"的场景；指向堆对象时优先改为**智能指针**（`static std::unique_ptr<T>` / `static std::shared_ptr<T>`）。

### 1.6 与 `const` 系列的区别（面试高频混淆点）

```cpp
int  a = 1, b = 2;

static int *p1 = &a;          // 「静态指针」：说的是 p1 的存储期（活到进程结束）
const  int *p2 = &a;          // 指向常量的指针：*p2 不可改，p2 本身可改
int  * const p3 = &a;         // 常量指针（指针本身为 const）：p3 不可改，*p3 可改
const int * const p4 = &a;    // 两者都不可改
static const int * const p5 = &a;  // 三者叠加：静态存储期 + 双向只读
```

**读法（从右往左，或从内到外）**：先看**紧挨变量名的 `const`** → 它管"指针自己能不能改"；其余的 `const` 管"指向的对象能不能改"。

| 写法 | 指针自己可变？ | 指向对象可变？ | `static` 管什么 |
|---|---|---|---|
| `static int *p` | ✅ | ✅ | 存储期/链接性 |
| `const int *p` | ✅ | ❌ | — |
| `int * const p` | ❌ | ✅ | — |
| `static int * const p` | ❌ | ✅ | 存储期/链接性 |

## 2. 函数指针（function pointer）

### 2.1 概念

函数在编译后也是**代码段中一段有地址的指令序列**，所以可以取地址、可以被指针保存。函数指针就是**存放"函数入口地址"的变量**，通过它调用函数称为**间接调用**。

函数名在大多数语境下会**退化（decay）为函数指针**，所以 `&f` 和 `f` 基本等价。

### 2.2 语法：难读的地方在于"名字要写在中间"

```cpp
void hello(int x) { std::cout << x; }

void (*fp)(int) = hello;      // 声明：fp 是"指向 返回void、参数int 的函数"的指针
fp(42);                       // 直接调用（等价于下面两种）
(*fp)(42);                    // 显式解引用
(&hello)(42);                 // 直接取地址再调用
```

**记忆法**：把 `void (*fp)(int)` 里的 `(*fp)` 换成 `fp`，剩下的 `void (int)` 就是这个函数的签名。

### 2.3 现代写法：一律用 `using` / `typedef` 起别名

```cpp
using Handler = void(*)(int);              // C++11 起推荐
// typedef void (*Handler)(int);           // 等价的旧写法

Handler h = hello;
std::vector<Handler> pipeline{h1, h2};     // 可放进容器
```

> 读难声明的诀窍：先从变量名出发，逐层向外剥（"右左法则"）。

### 2.4 典型用途

| 用途 | 说明 |
|---|---|
| **回调（callback）** | 事件驱动、GUI 信号槽、异步完成通知 |
| **策略/工厂分派表** | `std::map<OpCode, Handler>`，用查表取代长长的 `if/else`、`switch` |
| **C 接口** | `qsort` 的比较函数、`pthread_create` 的线程体、`atexit` |
| **运行时插件** | `dlsym()` / `GetProcAddress()` 取出符号后强转为函数指针 |
| **跳板 / 元编程** | 编译期把函数指针当模板参数（`template<auto F>` C++17） |

```cpp
// 分派表示例
using Op = int(*)(int, int);
Op table[] = { add, sub, mul, div_ };
int r = table[opcode](a, b);
```

### 2.5 成员函数指针：与普通函数指针**不是一回事**

非静态成员函数调用时需要 `this`，所以成员函数指针的特殊性在于：

- **写法**：`void (Widget::*p)() = &Widget::draw;`，调用需绑对象：`(w.*p)()` / `(ptr->*p)()`。
- **大小**：在多重继承 / 虚继承下，成员函数指针可能需要携带 `this` 调整信息，**大小可能与普通指针不同**（常见为 2 个机器字），且**各编译器实现不一致**。
- **虚函数**：通过成员函数指针调用虚函数仍然会走**动态分派**。
- **静态成员函数**：没有 `this`，所以"静态成员函数指针"就是**普通函数指针**，二者可互相赋值。

```cpp
class Widget { public: void draw(); static void reset(); };

void (Widget::*mp)() = &Widget::draw;   // 非静态：需对象
Widget w; (w.*mp)();

void (*sp)() = &Widget::reset;          // 静态：就是普通函数指针
sp();
```

### 2.6 与 lambda / `std::function` 的关系

| 方案 | 能否捕获 | 类型 | 开销 | 适用 |
|---|---|---|---|---|
| **裸函数指针** | ❌ | 具体类型，可比较、可放置于 C 接口 | 间接调用一次 | 回调、C API、分派表 |
| **无捕获 lambda** | ❌ | 有唯一的**闭包类型**，但**可隐式转为函数指针** | 同上（转换后无捕获开销） | 写回调的简洁写法 |
| **`std::function`** | ✅ | 类型擦除的多态包装 | 可能**堆分配** + 虚调用，无法内联 | 需要存任意可调用对象 |
| **模板形参 / `auto`** | ✅ | 编译期具体类型 | **零开销**（可内联） | 泛型算法、`std::sort` 的比较器 |

```cpp
void (*fp)() = []{ /* 无捕获 */ };                 // ✅ 隐式转换
// void (*fp2)() = [x]{ };                         // ❌ 有捕获则不行
std::function<void()> f = [x]{ std::cout << x; };  // ✅ 有捕获也能存
```

> 工程原则：**能用模板/`auto` 就别用 `std::function`；只发给 C 接口时才退化为裸函数指针。**

### 2.7 常见坑

| 坑 | 说明 |
|---|---|
| **返回局部函数的指针** | 函数指针本身不会指向"栈上的函数"，但**返回指向已卸载模块的函数指针**（`dlclose` 后）会崩溃 |
| **签名不一致的强转** | 调用约定（`__cdecl` / `__stdcall` / `__fastcall`）或参数类型不匹配 → 栈失衡/UB，编译器不报错 |
| **空函数指针调用** | 与空指针解引用同类，直接崩溃；调用前判空 |
| **用函数指针做"相等比较"的陷阱** | 内联/ICF（相同代码折叠）后，不同函数的地址可能相同；反之同一函数经 thunk 也可能不同 |
| **悬空的成员函数指针对象** | 对象已析构后再 `(obj.*mp)()` → UB |

## 3. 智能指针（smart pointer）

### 3.1 概念：用 RAII 把"所有权"表达出来

裸指针的问题不是"能指向"，而是**没人负责释放**：忘记 `delete` → 泄漏；重复 `delete` → UB；异常路径提前返回 → 泄漏。智能指针把裸指针包进一个对象，**在析构函数里释放**，让"释放"这件事绑定到作用域上。

**智能指针是"栈对象"**：它的析构由编译器保证，于是资源释放也被保证（含异常栈展开时）。

### 3.2 三个标准智能指针

| 类型 | 所有权 | 可拷贝 | 开销 | 典型场景 |
|---|---|---|---|---|
| `std::unique_ptr<T>` | **独占** | ❌（只能 `std::move`） | **零开销**（默认删除器下与裸指针同尺寸） | 默认首选：资源独占 |
| `std::shared_ptr<T>` | **共享** | ✅（引用计数） | 2 个指针 + 原子计数（控制块） | 真正需要共享所有权 |
| `std::weak_ptr<T>` | **不持有**（弱引用） | ✅ | 与控制块共用 | 打破循环引用、观察者/缓存 |

```cpp
auto up = std::make_unique<Widget>(1, 2);   // ✅ 独占
auto sp = std::make_shared<Widget>(1, 2);   // ✅ 共享（一次分配对象+控制块）

sp->draw();
up->draw();

std::weak_ptr<Widget> wp = sp;              // 弱引用，不影响 use_count
if (auto locked = wp.lock()) {              // 使用前必须 lock() 升级
    locked->draw();
}
```

### 3.3 关键差异与选型

**(1) 所有权语义是首要判断依据**

- 语义上**只有一个主人** → `unique_ptr`（比 `shared_ptr` 更快、更安全，因为不存在意外的"计数不减"）。
- 确实**多个主人、生命周期互相独立** → `shared_ptr`。
- 只在**旁边看着**、不该延长生命周期 → `weak_ptr`。

**(2) `unique_ptr` 可以"升级"为 `shared_ptr`**

```cpp
std::shared_ptr<T> sp = std::move(up);      // ✅ 转移所有权，控制块被创建
```

**(3) `shared_ptr` 的坑（详见 `cpp11-shared-ptr-notes.md`）**

- **循环引用**：`A ⇄ B` 互持 `shared_ptr` → 计数永不归零。把一方改 `weak_ptr`。
- **同一个实例的并发读写不安全**（计数是原子的，但指针变量本身不是）。
- **`use_count()` 多线程下只是近似值**。
- **`make_shared` 的代价**：对象与控制块同块内存，只要还有 `weak_ptr`，整块内存都不归还。
- **按值传参有开销**：只读参数用 `const std::shared_ptr<T>&`。

**(4) 自定义删除器**

```cpp
// 释放 C 风格资源
std::unique_ptr<FILE, decltype(&fclose)> fp(fopen("a.txt", "r"), &fclose);

std::shared_ptr<T> sp(raw, [](T* p){ custom_free(p); });   // shared_ptr 支持
// 注意：make_shared / make_unique 不支持自定义删除器
```

`unique_ptr` 的删除器是**类型的一部分**（可优化为零开销）；`shared_ptr` 的删除器**类型擦除**到控制块里（不改变智能指针自身的类型）。

**(5) 数组与旧工具**

```cpp
auto arr = std::make_unique<int[]>(10);      // unique_ptr<T[]> 支持数组；shared_ptr 自 C++17 起支持 T[]
// std::auto_ptr 已在 C++17 移除，禁止使用
```

**(6) 该不该用智能指针**

- 只**借助**对象、不涉及所有权（函数参数、遍历）→ **用 `T*` 或 `T&`**，不要传智能指针。
- **返回**新对象 → 返回 `unique_ptr`（表达"给你了"）。
- 需要表达"可能为空且不拥有" → `T*`（或 `std::optional<std::reference_wrapper<T>>`）。

## 4. 三者对比总表

| 维度 | 静态指针 | 函数指针 | 智能指针 |
|---|---|---|---|
| **解决的问题** | 指针变量的**存储期 / 生命周期长**（跨调用、跨文件共享） | 在运行期**选择要调用哪个函数** | 资源**由谁释放**（所有权） |
| **本质** | 一个普通的 `static` 变量（类型是 `T*`） | 保存代码地址的变量（类型是 `R(*)(Args...)`） | 一个**类模板**对象（含析构逻辑） |
| **`static` 作用** | 修饰**变量**的存储期 | — | — |
| **典型写法** | `static T *p;`、`static T* cls::m;` | `void (*fp)(int);`、`using F = int(*)(int);` | `auto p = std::make_unique<T>();` |
| **关键风险** | **悬空引用**（活太久，指向已死对象） | 签名不匹配 / 空指针调用 / 跨模块失效 | 循环引用、误用 `shared_ptr` 表达独占 |
| **是否管理生命周期** | ❌（只影响自己活多久） | ❌（不涉及数据生命周期） | ✅（核心职责） |
| **现代首选替代** | 函数内静态局部变量 / Meyers 单例；堆对象用智能指针 | C++11 后优先 lambda + 模板；需要擦除再用 `std::function` | — |

## 5. 高频混淆清单（自查表）

| 说法 | 实质 |
|---|---|
| **指针常量 / 常量指针** | `int * const p`（指针不可改）；`const int *p`（指向对象不可改，常被叫"指向常量的指针"，**注意别和前者混说**） |
| **`static` 指针 vs 静态局部变量** | 都是静态存储期；指针只是"变量类型恰好是指针" |
| **静态成员指针 vs 成员函数指针** | 前者是 `static` 指针成员变量；后者是 `void (C::*)()` |
| **数组指针 vs 指针数组** | `int (*a)[10]`（指向数组） vs `int *a[10]`（10 个指针） |
| **返回函数指针的函数** | `void (*g(int))(int)` → 用 `using` 拆两行写，别硬记 |
| **函数指针 vs 函数对象** | 前者是地址；后者是重载了 `operator()` 的类（可携带状态） |
| **智能指针 vs 裸指针性能** | `unique_ptr` 零开销；`shared_ptr` 有原子计数与控制块成本 |
| **`shared_ptr` 线程安全** | 计数原子安全；**同一实例并发读写不安全**；被指向对象本身需自行同步 |

## 6. 常见陷阱速查

1. `static int *p = &local;` → **悬空**，函数返回即失效。
2. 全局静态指针存在**动态初始化顺序**问题 → 用函数内静态局部变量规避。
3. 静态指针被多线程共享写入 → 需 `std::atomic<T*>` 或加锁。
4. `static C *p = new C;` → 进程级"永久泄漏"；改用 `static std::unique_ptr<C>`。
5. 函数指针**签名/调用约定不一致的强转** → 编译通过但运行期 UB。
6. `std::function` 在热点路径上被滥用 → 堆分配 + 类型擦除开销；能用模板就用模板。
7. 成员函数指针**不是**普通指针，大小、语义、跨编译器兼容性都不同。
8. `shared_ptr(A ⇄ B)` 循环引用 → 泄漏；`weak_ptr` 破环。
9. `shared_ptr<T>(this)` → 第二个控制块 → 双重析构；应 `enable_shared_from_this`。
10. 用 `delete` 删除 `unique_ptr::release()` 之外的裸指针 / 混合 `new[]`/`delete` → UB。

## 7. 附：与 Rust 的对照（本仓库为 Rust 项目，便于迁移理解）

| C++ 概念 | Rust 对应 | 说明 |
|---|---|---|
| 静态指针 `static T *p` | `static mut` / `std::sync::OnceLock` / `lazy_static` | Rust 用类型系统强制同步，`static mut` 访问需 `unsafe` |
| 函数指针 `R(*)(Args)` | `fn(Args) -> R` | 同为 Copy 的代码地址；Rust 另有 `Fn`/`FnMut`/`FnOnce` trait |
| 闭包转函数指针 | `fn` 指针 + 闭包 trait | 无捕获闭包可强转 `fn`；有捕获的闭包实现 `Fn` 等 trait |
| `std::function` | `Box<dyn Fn()>` | 都是类型擦除，都有动态分派开销 |
| `unique_ptr` | `Box<T>` | 独占所有权，零额外开销 |
| `shared_ptr` | `Rc<T>`（单线程）/ `Arc<T>`（多线程） | 引用计数；`Arc` 计数是原子的 |
| `weak_ptr` | `Weak<T>` | 同样用于破环，需 `upgrade()` |
| `shared_ptr` 的可变共享 | `Rc<RefCell<T>>` / `Arc<Mutex<T>>` | 把"共享"与"可变"拆开，编译期检查别名规则 |

---

## 8. 一句话总结

- **静态指针**：`static` 管的是**指针变量自己的寿命**，与指向对象无关；最大风险是它活得太久导致**悬空**。
- **函数指针**：保存**代码地址**，是回调与分派表的原始手段；成员函数指针是另一套语义，现代代码优先 lambda + 模板。
- **智能指针**：把**所有权**写成类型，让释放与作用域绑定；默认 `unique_ptr`，需要共享才用 `shared_ptr`，破环用 `weak_ptr`。
