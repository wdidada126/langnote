> **一句话概括**：想让语法分析器**扫一遍输入就能定下来**（不回搠），就必须先对 CFG 做两步预处理 —— **提取左公因子** + **消除左递归**，再用 **First/Follow** 构造预测分析表；分析表无冲突的文法就叫 **LL(1) 文法**。

## 0. 全文脉络（一张图看懂）

```

                                                        │

```

## 1. 动机：为什么要从 CFG 走到 Parser

### 1.1 类比：RE→DFA 与 CFG→Parser 是同一个问题

- **RE→DFA 是为了什么？** 手上有正则表达式定义的各类词素（单词、数字、注释……），把它们的 NFA 合并、确定化成 DFA 后，就**知道了"所有状态 + 每个状态遇到什么输入该跳到哪里"**，据此直接生成词法分析程序。词法分析器的输出是 **Token 序列**，每个 Token 记录：
  - `lexeme`：词本身（如 `int`、`123`）
  - `catalog`：种类（自己用 RE 定义的类别，如 ID、NUM）
  - `InnerCode`：内部码
- **CFG→Parser 是为了什么？** 已经有了语言的上下文无关文法和词法分析出的**有序单词序列**，接下来要判定**这些单词之间的语法关系** —— 相当于从"主语 谓语 宾语"的有序词里识别出句子成分，判断这串词**符不符合语法**、**对应语法树长什么样**。

> 结论：RE 解决"**单个词是不是合法**"，CFG 解决"**词与词组合起来是不是合法、怎么组合**"。前者对应词法分析，后者对应语法分析（Parser）。

## 2. 朴素方案：递归下降分析法（Recursive Descent Parsing）

**核心思想**：**为每个非终结符写一个函数**，靠递归 + 回溯（原文写作"回搠"）试错。

> **Example**：`S → ABC`，`A → aA | ε`，`B → bB | ε`，`C → cC | ε`

```c
main() {
    i = S();
}

int S() {
    i = A();
    if (i == 1) {
        j = B();
        if (j == 1) {
            return C();
        } else {
            error();
        }
    } else {
        error();
    }
}

int A() {
    ch = getChar();
    if (ch == 'a') return A();
    else return 1;
}
```

**问题**：遇到复杂文法时**回搠次数爆炸**，效率极低。原文的策略是"先找出回搠的原因，做一定预处理，让**一遍就能判断对**"——这就引出了预测分析法。

## 3. 预测分析法（Predictive Parsing）

### 3.1 回溯的两大成因

| 成因 | 形态 | 后果 |
|---|---|---|
| **公共左因子** | `A → aB \| aC` | 读到 `a` 时不知道选哪条产生式 |
| **左递归** | `A → Aa` | 自顶向下会**无限递归**（栈溢出），永远无法前进 |

> 把这两个问题消掉，才能保证"看到当前输入字符就能唯一确定用哪条产生式"。

### 3.2 预处理一：提取最大左因子

原文规则：名字即做法。

```
A → aB | aC | bD     ⇒     A → aE | bD ,  E → B | C
```

**通用形式**（整理者补充）：

```
A → αβ₁ | αβ₂ | … | αβₙ | γ₁ | … | γₘ
⇒  A → αA' | γ₁ | … | γₘ
   A' → β₁ | β₂ | … | βₙ
```

需**反复提取**直到任意两条产生式再无公共前缀。

### 3.3 预处理二：消除左递归

#### (1) 直接左递归 —— 一个套路

形如 `A → Aα | β`，它描述的是"以 β 开头、后面跟 n 个 α"的串，即 βαⁿ，于是：

```
A → Aα | β      ======>      A → βA'
                             A' → αA' | ε
```

**多产生式的通用公式**（整理者补充，原文只给了单条形式）：

```
A → Aα₁ | Aα₂ | … | Aαₙ | β₁ | β₂ | … | βₘ
⇒  A → β₁A' | β₂A' | … | βₘA'
   A' → α₁A' | α₂A' | … | αₙA' | ε        （A' 是新引入的非终结符）
```

**例**（原文示例）：

```
E → E + T | T
```
把 `+T` 看作 α、`T` 看作 β：

```
E → T E'
E' → + T E' | ε
```

#### (2) 间接左递归 —— 先"化环为直"

原文例子构成了一个**环**：

```
S → Qc | c
Q → Rb | b
R → Sa | a
```

处理办法：**代入消环**，把间接变成直接。例如把 `S → Qc | c` 中的 `Q` 展开：

```
S → Qc | c
  → Rbc | bc     （代入 Q → Rb | b）
  → Sabc | abc   （代入 R → Sa | a）
```

此时变成直接左递归，套上面的公式即可解决。

> 原文说"这里可以用到优先级的概念，比如规定 S 不可以推出 Q 和 R"——**说法的实质是"排序 + 代入"**：给非终结符定一个顺序，只允许用**序号更小**的非终结符替换，从而保证环被打开。标准算法见 §7 补充。

#### (3) 混合左递归 —— 顺序不能反

**先消直接左递归，再消间接左递归**；即"圈中套圈时，先把**内部**的圈消掉，再消外部的圈"，否则永远消不掉，陷入死循环。

## 4. 制表：First 与 Follow

### 4.1 为什么要这两个集合

目的：**扫一遍输入就能知道当前非终结符该展开成什么**。所以需要一张描述"非终结符 × 终结符 → 用哪条产生式"的表。构造这张表依赖两个集合。

**First 的直觉**（原文）：

- `A → aB`、`A → bC`：状态为 A 时读到 `a`，就把 A 推导为 `aB`。
- `A → BC`，`B → bC`：读到 `b` 也把 A 推导为 `BC`，因为 **A 首先推导出的终结符是 b**。

**Follow 的直觉**（原文）：

考虑 `S → AD`，`A → BC`，`B → ε | bB`，`C → ε | cC`，`D → eD`。
`First(A) = {b, c, ε}`。当处于 A 而读到的字符是 **`e`** 时，仍然要选 `A → BC`，让 `B`、`C` 都推成 ε，把位置让给后面的 `D → eD` 去匹配这个 `e`。所以**除了 First，还要知道"这个非终结符后面可能出现什么"** —— 这就是 Follow。

### 4.2 形式化定义（原文）

**First**：若 α ⇒ α₁α₂…αₙ，则

```
First(α) = First(α₁)                          , if ε ∉ First(α₁)
First(α) = (First(α₁) - {ε}) ∪ First(α₂)      , if ε ∈ First(α₁)
```

**Follow**：若 `B → αAβ`，则

```
Follow(A) = First(β)                          , if β 不会推出 ε
Follow(A) = (First(β) - {ε}) ∪ Follow(B)      , if β 推出 ε
```

若 `B → αA`（A 在末尾），则

```
Follow(A) ⊆ Follow(B)      （原文写作 Follow(A) <= Follow(B)）
```

右边没有了怎么办？**在文末补上终止符 `$`**，它也是 Follow 的一部分。

**制表用法**：对预处理后 CFG 的**每条产生式右部**求 First；**若含 ε 则改求 Follow**。

> **例**：对 `E → TE'`，`First(TE') = { i , ( }`，于是**在 i 列和 ( 列**都填上 `E → TE'`。

### 4.3 完整的 First / Follow 与预测分析表（整理者补充）

原文未给出完整表格，这里以经典 LL(1) 文法补全（下文的 `i` 即原文中的标识符）：

```
① E  → T E'
② E' → + T E' | ε
③ T  → F T'
④ T' → * F T' | ε
⑤ F  → ( E ) | i
```

**First**

| 符号 | First |
|---|---|
| `E` / `T` / `F` | `{ ( , i }` |
| `E'` | `{ + , ε }` |
| `T'` | `{ * , ε }` |

**Follow**

| 非终结符 | Follow | 推导依据 |
|---|---|---|
| `E` | `{ $ , ) }` | 开始符号含 `$`；`F → ( E )` 中 E 后面是 `)` |
| `E'` | `{ $ , ) }` | `E → TE'`，E' 在末尾 → 继承 Follow(E) |
| `T` | `{ + , ) , $ }` | `E' → +TE'` 中 T 后是 `+`；ε 产生式再继承 Follow(E') |
| `T'` | `{ + , ) , $ }` | `T → FT'`，T' 在末尾 → 继承 Follow(T) |
| `F` | `{ * , + , ) , $ }` | `T' → *FT'` 中 F 后是 `*`；继承 Follow(T') |

**预测分析表**

| | `i` | `+` | `*` | `(` | `)` | `$` |
|---|---|---|---|---|---|---|
| `E` | ① | | | ① | | |
| `E'` | | ②`+TE'` | | | ②`ε` | ②`ε` |
| `T` | ③ | | | ③ | | |
| `T'` | | ④`ε` | ④`*FT'` | | ④`ε` | ④`ε` |
| `F` | ⑤`i` | | | ⑤`(E)` | | |

## 5. 处理：栈式分析流程

原文的算法描述：

1. **初始化**：把 `$` 和开始符号 `E` 压栈；输入串末尾也补一个 `$`。
2. **查表**：若输入首字符为 `i`，查表得 `E → TE'`，则 **E 出栈**，把右部 **逆序压栈**（先压 `E'` 再压 `T`，这样 `T` 在栈顶）。
   > 注意理由：LL 是**最左推导**，左边的符号要先被处理，所以**左边的要最后压栈**。
3. **匹配**：若栈顶是终结符且与当前输入相同 → 输入指针后移；否则报错。
4. 重复 2–3，直到匹配到 `$` 为止。

**原文的 9 步推导（输入 `i+i`）**：

```
1. E  => T E'
2. T  => F T'
3. F  => i
4. T' => ε
5. E' => + T E'
6. T  => F T'
7. F  => i
8. T' => ε
9. E' => ε
```

按这 9 步即可画出 `i+i` 的**语法分析树**（原文给了图）。

**栈的变化走查**（整理者补全，输入 `i+i$`）：

| 步 | 栈（底→顶） | 剩余输入 | 动作 |
|---|---|---|---|
| 0 | `$ E` | `i+i$` | 初始化 |
| 1 | `$ E' T` | `i+i$` | `E → TE'`（逆序压栈） |
| 2 | `$ E' T' F` | `i+i$` | `T → FT'` |
| 3 | `$ E' T'` | `+i$` | `F → i`，匹配 `i` |
| 4 | `$ E'` | `+i$` | `T' → ε` |
| 5 | `$ E' T` | `i$` | `E' → +TE'`，匹配 `+` |
| 6 | `$ E' T' F` | `i$` | `T → FT'` |
| 7 | `$ E' T'` | `$` | `F → i`，匹配 `i` |
| 8 | `$ E'` | `$` | `T' → ε` |
| 9 | `$` | `$` | `E' → ε`，匹配 `$` → **接受** |

## 6. LL(1) 文法

**定义**（原文）：

> A grammar whose parsing **table has no multiply-defined entries** is said to be **LL(1)**.

三个字母的含义：

| 符号 | 含义 |
|---|---|
| 第一个 **L** | scanning the input from **L**eft to right —— 从左向右扫描 |
| 第二个 **L** | producing a **L**eftmost derivation —— 最左推导 |
| **1** | 每步只用一个输入符号（1 symbol look-ahead）做决策 |

**适用范围**：递归下降分析法与预测分析法**都只适用于 LL(1) 文法**（经预处理后满足 LL(1)）。

## 7. 整理者补充与勘误

### 7.1 原文笔误与不严谨处

| # | 原文 | 更正 |
|---|---|---|
| 1 | "公共子因子" | 规范叫法是**公共左因子**；操作叫"提取左公因子"（left factoring） |
| 2 | "回搠"（多处） | 应为**回溯**（backtracking） |
| 3 | `Follow(A) <= Follow(B)` | 符号方向含糊，正确含义是 **`Follow(B) ⊆ Follow(A)`**（B 的 Follow 全部并入 A 的 Follow），且**只在 `B → αA`（A 在最右）时成立** |
| 4 | First 递推只写到 α₂ | 定义**没穷尽**：若 `α₁α₂…αₖ` 全都能推出 ε，则还要并入 `First(αₖ₊₁)`；若**整个 α 都能推出 ε**，则 **`ε ∈ First(α)`**。补充规定：**`First(ε) = {ε}`**、`First(a) = {a}`（a 为终结符） |
| 5 | Follow 定义 | 需补两条：**① Follow 只对非终结符有意义，且永不含 ε**；② **开始符号的 Follow 一定含 `$`** |
| 6 | 直接左递归只给了 `A → Aα \| β` | 应给出**多条产生式的通用公式**（见 §3.3(1)） |
| 7 | "可以用到优先级的概念" | 实质是**排序 + 代入消环**的标准算法（见 §7.2） |
| 8 | 消除左递归后 `E → TE', E' → +TE' \| ε` | **语义提醒**：原文法 `E → E+T \| T` 表达**左结合**，改写后的文法形式上变成"右递归"，**结合性信息丢失了** —— 需要靠 AST 构造方式（`build_right_assoc` vs 迭代成左倾树）额外还原，否则 `a-b-c` 会被建成 `a-(b-c)` |

### 7.2 标准的间接左递归消除算法（教科书三步骤）

设非终结符为 `A₁, A₂, …, Aₙ`：

```
for i = 1 to n:
    for j = 1 to i-1:                        # 只允许用"序号更小"的替换，保证环被打开
        把形如 Aᵢ → Aⱼγ 的产生式替换为：
            Aᵢ → δ₁γ | δ₂γ | … | δₖγ        # 其中 Aⱼ → δ₁ | δ₂ | … | δₖ 是当前的 Aⱼ 产生式
    消除 Aᵢ 的直接左递归
化简：删除不可达、不可终止的非终结符
```

原文说的"规定 S 不可以推出 Q 和 R"，就是这里的"**只能代入序号更小的**"。

### 7.3 左递归对不同分析器的影响（重要）

| 分析器类型 | 左递归 | 说明 |
|---|---|---|
| **递归下降 / LL(1)（自顶向下）** | ❌ **必须消除** | 会无限递归、栈溢出；分析表也会冲突 |
| **LR / SLR / LALR（自底向上）** | ✅ **天然支持**，甚至**更喜欢** | 左递归让栈增长即可；左结合由 `E → E + T` 的形式天然表达 |

> 所以"消除左递归"**不是普适要求**，而是**自顶向下分析的前提**。原文下一篇讲 SLR(1) 正是自底向上路线，那里并不需要消左递归。

### 7.4 预测分析表的构造算法（原文说"制表"但没给算法）

对每个产生式 `A → α`：

1. 对每个终结符 `a ∈ First(α)`：置 `M[A, a] = A → α`；
2. 若 `ε ∈ First(α)`：对每个 `b ∈ Follow(A)`：置 `M[A, b] = A → α`；
3. 其余表项填 `error`。

**LL(1) 的判定条件**（等价于"表无多重定义"）：对每个非终结符 A 的任意两条不同产生式 `A → α`、`A → β`：

- `First(α) ∩ First(β) = ∅`；
- 若 `β ⇒* ε`，则 `First(α) ∩ Follow(A) = ∅`（反之亦然）。

### 7.5 递归下降的工程写法（对照原文代码）

原文代码只演示了"每个非终结符一个函数"的思想，实际实现要点：

- **用 First 集合决定 if/else 分支**：`if (lookahead ∈ First(α₁)) 用产生式1 else if ...`；
- **用 Follow 决定 ε 分支**：`else if (lookahead ∈ Follow(A)) A → ε`；
- **真正回溯**需要保存并恢复输入位置（原文代码并未实现恢复，所以严格说不算回溯，只是单字符试探）；
- 现代做法：**预测（LL(1)）不用回溯**；需要回溯时优先改用 LR 或 PEG 的 packrat 记忆化。

**原文代码的具体缺陷**：

| 位置 | 问题 |
|---|---|
| `int S()` | `error()` 分支**没有 return**，函数有路径无返回值 → 未定义行为；单字符变量 `i/j` 语义含糊，应 `enum` 返回状态 |
| `int A()` | `ch` 未声明；只 `getChar()` 一次，无法处理"不是 a 也不是 ε"的报错路径；没有输入回退 |
| `main()` | `i = S();` 返回值未使用，应判断接受/拒绝并输出结果 |

### 7.6 与其他笔记的呼应

- 本篇的"**CFG → 栈式分析器**"正是 `pushdown-automaton-notes.md` 里 **PDA = 有限状态 + 一个栈** 的工程实现：LL(1) 分析器的**显式栈**对应 PDA 的栈；递归下降则用**调用栈**代替显式栈。
- LL(1) 只覆盖**很小一部分** CFL；更强的路线依次是 **LL(k) → SLR(1) → LALR(1) → LR(1)**，后者都是自底向上、支持左递归、能力更强（原文下一篇即 SLR(1)）。

## 8. 一句话总结

**先消病因，再查表：** 用「**提取左公因子**」和「**消除左递归**」把 CFG 改造成"看一个字符就能定"的形式，再用「**First / Follow**」把决策**预先烧进一张表**，运行时只需一个栈按表出栈/逆序压栈 —— 这就是 LL(1) 分析法，也就是 PDA 在编译器里的直接落地。
