# RESP

RESP3 与 RESP2
https://redis.io/docs/latest/develop/data-types/json/resp3/

https://redis.ac.cn/docs/latest/develop/reference/protocol-spec/

RESP3 (Redis Serialization Protocol version 3) 是 RESP2 的一次重大升级，于 Redis 6.0 引入，旨在解决旧协议在语义表达上的不足。它在保持向下兼容的同时，引入了多种新数据类型，让客户端能更精确地理解和处理服务器返回的复杂结果。

核心区别对比如下：

| 特性 | RESP2 | RESP3 |
| :--- | :--- | :--- |
| 核心目标 | 简单、高效、易于实现 | 增强语义，更准确地表达数据结构，解决歧义 |
| 引入版本 | Redis 2.0 | Redis 6.0 |
| 协议切换 | 默认协议（客户端可直接使用） | 需协商：客户端发送 `HELLO 3` 命令切换 |
| NULL值表示 | 使用 `$-1\r\n`（空批量字符串）或 `*-1\r\n`（空数组）表示，存在二义性 | 独立类型，使用 `_\r\n` 表示，语义清晰 |
| 错误类型 | 仅简单错误（`-`），非二进制安全 | 增加二进制安全错误（`!`） |
| 基础类型 | 整数（`:`）、简单字符串（`+`）、批量字符串（`$`）、数组（`*`） | 新增：布尔值（`#`）、浮点数（`,`）、大数字（`(`） |
| 复合类型 | 只有数组（`*`） | 新增：有序Map（`%`）、无序Set（`~`）、逐字字符串（`=`）、带外推送数据（`>`）和属性（`|`） |
| 典型示例 | 集合类型返回值均为数组，如 `SMEMBERS` 返回 `*2\r\n$3\r\none\r\n$3\r\ntwo\r\n` | `SMEMBERS` 返回 `~2\r\n$3\r\none\r\n$3\r\ntwo\r\n`，明确其为 Set 结构 |
| 版本兼容 | - | 完全向下兼容RESP2，可无缝理解旧版命令 |

### 需要注意的潜在影响
尽管 RESP3 旨在消除歧义，但在一些细微之处仍需留意。例如，`HELLO` 命令的回复在 RESP2 和 RESP3 下结构不同，某些 JSON 命令（如 `JSON.GET`）在两种协议下的返回值结构也可能存在差异。另外，RESP3 中的 Map 类型是有序的，在实现客户端解析时需要加以注意。

### 总结
对于新项目或可以完全控制客户端的场景，建议拥抱 RESP3，它能带来更精确的数据表达和更现代的编程体验。

而对于需要兼容老客户端的场景，选择 RESP2 更稳妥。所有 RESP2 客户端都能与启用了 RESP3 的 Redis 6.0+ 服务端正常通信（因为默认协议仍是 RESP2），只是无法享受到新类型带来的优势。

你目前的计划里，是准备在新项目里直接上 RESP3，还是要兼容老客户端？
