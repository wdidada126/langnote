# tcp

Nagle算法是一种用于网络传输的优化算法，其目的是减少网络上小数据包的数量，从而提高网络利用率和性能。它主要应用于基于TCP的网络协议中，通过合并小的数据包，降低网络拥塞，避免网络资源的浪费。下面是Nagle算法的详细解释：

### 背景：
在网络通信中，小的数据包会带来较高的开销，尤其是在每个数据包都附带TCP和IP头的情况下。频繁地发送小包会使网络产生许多空闲时间，导致带宽利用率低。Nagle算法通过合并小数据包来减少传输中的这种开销。

### Nagle算法的原理：
1. 当有数据要发送时，首先检查是否存在未确认的（Unacknowledged）数据包。
2. 如果有未确认的数据包，新的数据将暂时缓存，直到现有的包得到确认或者缓存的数据量足够大（达到MSS，最大报文段大小）。
3. 如果没有未确认的数据包或者数据量足够大，立即发送新的数据包。

### 工作流程：
- 发送第一个小数据包，然后等待确认。
- 在收到确认（ACK）之前，所有的后续数据将被合并到缓冲区，除非它们的大小达到MSS。
- 在收到ACK后，发送缓冲区中的数据。

### 优点：
- 减少小数据包：通过合并小数据包，减少网络中的传输负载和带宽浪费。
- 提高效率：提高了网络传输效率，减少网络拥塞。

### 缺点：
- 增加延迟：对于实时交互式应用，例如在线游戏或某些即时消息通信，可能会增加延迟，因为发送方需要等待ACK来发送缓存中的数据。

### 禁用Nagle算法：
由于Nagle算法可能增加延迟，对于实时应用，通常会禁用它。可以通过设置TCP_NODELAY选项来禁用：

在C语言的Socket API中：
```c
int flag = 1;
setsockopt(socket_fd, IPPROTO_TCP, TCP_NODELAY, (char *) &flag, sizeof(int));
```

### 适用场景：
- 适用于需要高效传输大量小数据的场景，例如文件传输、非实时通信等。
- 不适用于需要低延迟的实时应用。

## 慢启动
TCP慢启动（Slow Start）是TCP协议的一种拥塞控制机制，主要用于初始阶段或网络出现问题后的恢复阶段。它通过逐步增加网络传输速度来避免网络拥塞的发生。它的提出背景与拥塞问题直接相关。

### 慢启动的提出背景：
1. 网络拥塞问题：
   在20世纪80年代，互联网的使用率逐渐上升，但网络带宽有限。大量的数据包在网络上传输，如果不进行流量管理，容易导致网络拥塞。拥塞发生时，路由器或链路可能无法处理过多的数据包，导致大量数据包丢失和延迟急剧增加。
2. 早期TCP协议的缺陷：
   早期的TCP协议没有良好的拥塞控制机制。一旦连接建立，就会以固定的速度发送数据，导致网络无法动态调整传输速率，容易造成过度拥塞和严重的网络性能下降。
3. TCP Tahoe和TCP Reno：
   在1988年，Van Jacobson提出了TCP Tahoe（后来改进为TCP Reno），这两个协议成为现代TCP拥塞控制机制的基础。它们引入了多个机制，包括慢启动、拥塞避免、快速重传和快速恢复等。其中，慢启动主要用于控制初始阶段的数据发送速率，避免快速增加流量导致拥塞。

### 慢启动的原理：
1. 初始状态：
   当TCP连接开始或经过拥塞恢复阶段时，发送方的拥塞窗口（Congestion Window, cwnd）设置为一个初始值，通常是1个MSS（最大报文段大小）。
2. 指数增长：
   发送方每收到一个ACK确认包，就将拥塞窗口增大1个MSS。因此，在每一轮RTT（往返时延）中，发送窗口会呈指数级增长。
3. 阈值判断：
   当拥塞窗口达到预先设定的阈值（慢启动阈值，ssthresh）时，慢启动阶段结束。此后，将进入拥塞避免阶段，窗口增长方式转变为线性增长。

### 总结：
TCP慢启动的提出主要是为了解决早期互联网中普遍存在的网络拥塞问题。它通过谨慎地增加传输速度，在初始阶段有效地控制拥塞窗口的增长速度，减少网络拥塞风险，同时确保数据传输效率。

1、阻塞与非阻塞
是相对于连接过程是否等待，或者说连接中是否可做其它事。
serverSocket接收socket连接且等待直到连接上为止，即为阻塞。
serverSocket接口连接后，不等待连接上，又去接收新的连接，轮询地处理连接或连接就绪等事件，即为非阻塞。

2、同步与异步
是相对于结果而言的，即是否等待结果返回。等待结果的即是同步，不等待结果的即是异步。
在这里，socket等待直到读取到数据为止，即是同步。
socket不等待读取到数据，而去做别的事，当数据准备好后，会通知socket数据已经准备好了，这就是异步。

Twip（Tencent WEB Real-Time Communication Protocol）是腾讯公司开发的一种实时通信协议，用于在互联网上传输实时音视频数据。Twip基于UDP协议，提供了实时、高效和低延迟的通信能力。

KCP（KCP over UDP）是一种快速可靠的数据传输协议，它使用UDP协议进行传输，但在传输过程中采用了类似于TCP的可靠性和流量控制机制。KCP通过快速重传、快速恢复和拥塞控制等技术，提高了数据传输的可靠性和效率。
