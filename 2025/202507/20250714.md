Java 中也有类似 Rust 的 可变（mutable）和不可变（immutable） 的概念，但它的实现方式和语法与 Rust 有显著不同。

### 核心对比

| 特性 | Rust | Java |
| :--- | :--- | :--- |
| 默认可变性 | 不可变（变量默认是 `immutable`） | 可变（变量默认是 `mutable`） |
| 使变量不可变的关键字 | `let`（默认不可变），`let mut` 使可变 | `final` 使不可变 |
| 使变量可变 | `let mut x = ...` | 不加 `final` 就是可变的 |

### Java 中的“不可变性”

在 Java 中，一个变量是否“不可变”是通过 `final` 关键字来控制的。

#### 1. `final` 变量（类似 Rust 的默认 `let`）

```java
final int x = 10;
x = 20; // ❌ 编译错误！不能重新赋值

final String name = "Alice";
name = "Bob"; // ❌ 编译错误！不能重新赋值
```

   这类似于 Rust 中 `let x = 10;`（默认不可变）。
   一旦用 `final` 声明并初始化，就不能再给这个变量赋新值。

#### 2. 普通变量（可变，Java 默认）

```java
int y = 10;
y = 20; // ✅ 合法，y 是可变的

String name = "Alice";
name = "Bob"; // ✅ 合法，name 可以指向新的字符串
```

   这相当于 Rust 中 `let mut y = 10;`。

### 对象内部状态的可变性

⚠️ 重要区别：Java 的 `final` 只保证变量引用本身不可变，不保证对象内部状态不可变。

```java
final List<String> list = new ArrayList<>();
list.add("Hello"); // ✅ 合法！list 引用没变，但对象内容变了
list = new ArrayList<>(); // ❌ 编译错误！不能改变 list 的引用

final StringBuilder sb = new StringBuilder("Hello");
sb.append(" World"); // ✅ 合法！修改了对象内部状态
```

这与 Rust 不同：

   在 Rust 中，如果你有一个不可变引用 `&T`，你通常不能调用会修改对象状态的方法（除非使用 `Cell`/`RefCell` 等内部可变性）。
   在 Java 中，`final` 只冻结了引用，对象本身的 `public` 方法仍然可以被调用并修改其内部状态。

### 总结

   有：Java 确实有“可变”和“不可变”的概念。
   方式不同：
       Rust 默认不可变，用 `mut` 显式声明可变。
       Java 默认可变，用 `final` 显式声明不可变（仅针对引用）。
   深度不同：
       Rust 的不可变性更严格，通常延伸到对象内部状态。
       Java 的 `final` 主要是“引用不可变”，对象内部状态是否可变取决于对象自身的设计（如 `String` 是不可变类，`ArrayList` 是可变类）。

所以，虽然概念相似，但 Java 的机制不如 Rust 的所有权和借用系统那样严格和全面。
