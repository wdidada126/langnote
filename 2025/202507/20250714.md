`VC_redist.x64.exe` 是 Microsoft Visual C++ Redistributable for Visual Studio 的可再发行组件安装包，专为 64位（x64）Windows 系统设计。

###  主要作用

这个文件的作用是 在目标计算机上安装运行使用 Microsoft Visual C++ 开发的应用程序所必需的运行时组件。

简单来说：  
> 很多用 C++ 编写的软件（如游戏、办公软件、图像处理工具等）在开发时依赖 Visual C++ 的库（如 `MSVCR120.dll`、`VCRUNTIME140.dll` 等）。这些库不会自动包含在 Windows 系统中，需要单独安装。  
> `VC_redist.x64.exe` 就是用来安装这些库的官方安装程序。

### 包含哪些内容？

该安装包通常包含以下运行时组件：

- C Runtime Library (CRT)
- Standard C++ Library
- MFC (Microsoft Foundation Classes，部分版本)
- OpenMP、ATL 等支持库

这些库支持软件进行：
- 内存管理
- 字符串操作
- 异常处理
- 多线程
- 标准模板库（STL）等

###  常见问题
1. “找不到 VCRUNTIME140.dll” 或 “MSVCP140.dll 丢失”  
   → 通常是因为缺少对应版本的 Visual C++ Redistributable，需要运行 `VC_redist.x64.exe` 安装。
2. 为什么电脑上有多个 VC_redist？  
   → 因为不同软件可能使用不同版本的 Visual Studio 编译，所以需要安装多个版本的运行库。
3. 是否安全？  
   → 官方版本是安全的。建议从 [Microsoft 官方网站](https://learn.microsoft.com/zh-cn/cpp/windows/latest-supported-vc-redist) 下载，避免从第三方网站获取。

### 核心对比

| 特性 | Rust | Java |
| :--- | :--- | :--- |
| 默认可变性 | 不可变（变量默认是 `immutable`） | 可变（变量默认是 `mutable`） |
| 使变量不可变的关键字 | `let`（默认不可变），`let mut` 使可变 | `final` 使不可变 |
| 使变量可变 | `let mut x = ...` | 不加 `final` 就是可变的 |

### Java 中的“不可变性”
在 Java 中，一个变量是否“不可变”是通过 `final` 关键字来控制的。
#### 1. `final` 变量（类似 Rust 的默认 `let`）
```java
final int x = 10;
x = 20; // ❌ 编译错误！不能重新赋值

final String name = "Alice";
name = "Bob"; // ❌ 编译错误！不能重新赋值
```
   这类似于 Rust 中 `let x = 10;`（默认不可变）。
   一旦用 `final` 声明并初始化，就不能再给这个变量赋新值。

#### 2. 普通变量（可变，Java 默认）
```java
int y = 10;
y = 20; // ✅ 合法，y 是可变的

String name = "Alice";
name = "Bob"; // ✅ 合法，name 可以指向新的字符串
```

   这相当于 Rust 中 `let mut y = 10;`。
### 对象内部状态的可变性
重要区别：Java 的 `final` 只保证变量引用本身不可变，不保证对象内部状态不可变。

```java
final List<String> list = new ArrayList<>();
list.add("Hello"); // ✅ 合法！list 引用没变，但对象内容变了
list = new ArrayList<>(); // ❌ 编译错误！不能改变 list 的引用

final StringBuilder sb = new StringBuilder("Hello");
sb.append(" World"); // ✅ 合法！修改了对象内部状态
```

这与 Rust 不同：
   在 Rust 中，如果你有一个不可变引用 `&T`，你通常不能调用会修改对象状态的方法（除非使用 `Cell`/`RefCell` 等内部可变性）。
   在 Java 中，`final` 只冻结了引用，对象本身的 `public` 方法仍然可以被调用并修改其内部状态。
### 总结
   有：Java 确实有“可变”和“不可变”的概念。
   方式不同：
       Rust 默认不可变，用 `mut` 显式声明可变。
       Java 默认可变，用 `final` 显式声明不可变（仅针对引用）。
   深度不同：
       Rust 的不可变性更严格，通常延伸到对象内部状态。
       Java 的 `final` 主要是“引用不可变”，对象内部状态是否可变取决于对象自身的设计（如 `String` 是不可变类，`ArrayList` 是可变类）。
所以，虽然概念相似，但 Java 的机制不如 Rust 的所有权和借用系统那样严格和全面。
