# 20250710

在使用 `git clone` 时，如果你希望保留代码中的换行符为 Linux 风格的 LF（而不是 Windows 上默认转换成的 CRLF），你需要配置 Git 的 自动换行符处理行为。

---

## 正确做法：设置 Git 的 `core.autocrlf`

### 如果你在 Windows 上开发，但想保留原始的 LF 换行风格：

```bash
git config --global core.autocrlf input
```

> 这样 Git 在提交时不会自动把 LF 转为 CRLF，在检出时不转回 LF。适合跨平台协作、服务器部署是 Linux 的场景。

---

### 如果你在 Linux/macOS 上开发：

你不需要做特别配置，默认就是：

```bash
git config --global core.autocrlf false
```

> 表示 Git 不对换行符做任何转换，保留原样。

---

## 如何确认当前配置？

运行以下命令查看当前配置：

```bash
git config --global core.autocrlf
```

输出可能是：
- `true`（Windows 默认）：LF → CRLF 检出，CRLF → LF 提交
- `input`：提交时将 CRLF 转为 LF，检出保持 LF
- `false`：不做任何转换

---

## 验证是否生效

你可以用以下方式验证：

1. 克隆一个原本是 LF 换行的仓库。
2. 使用二进制编辑器或如下命令检查文件换行符：

```bash
file your_file.txt
```

如果输出类似：

```
your_file.txt: ASCII text, with very long lines
```

说明是 LF 格式；如果有：

```
your_file.txt: ASCII text, with CRLF line terminators
```

说明换行符被转成了 Windows 风格。

---

## 已有项目中修正换行符问题

如果你已经克隆了项目，并且发现换行符被错误地修改过，可以尝试重新规范化换行符：

```bash
git rm --cached -r .
git reset
git config core.autocrlf input   # 或 false，根据你的系统
git add .
git commit -m "Normalize line endings to LF"
```

---

## 小贴士

- `.gitattributes` 文件可以更细粒度控制换行符策略（推荐添加到项目根目录）：

```gitattributes
# 设置所有文本文件使用 LF
* text=auto

# 明确指定某些文件类型的行为
*.sh text eol=lf
*.bat text eol=crlf
```

这样即使不同开发者本地设置不同，也能统一规范。
