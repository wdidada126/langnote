在 C++ 中，`std::vector` 是一个非常常用的动态数组容器。它的迭代器失效（iterator invalidation）问题是开发中常见的陷阱之一。

## 什么是“迭代器失效”？

当 `vector` 的内存重新分配或元素被修改时，指向该 `vector` 元素的迭代器、指针、引用可能会变成“无效”，继续使用这些迭代器会导致 未定义行为（Undefined Behavior, UB）。

## 清空 vector 与迭代器失效

调用以下方法清空 `vector` 时：

- `vec.clear();`
- `vec = {};`
- `vec.resize(0);`

所有指向 vec 中元素的迭代器、指针、引用都会失效。

## 可执行示例代码（演示 clear 后使用迭代器导致崩溃）

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> vec = {1, 2, 3, 4, 5};

    // 获取 begin 迭代器
    auto it = vec.begin();

    std::cout << "Before clear: *it = " << *it << std::endl;

    // 清空 vector
    vec.clear();

    // 此时 it 已经失效！访问它会导致未定义行为
    if (it != vec.end()) {
        std::cout << "After clear: *it = " << *it << std::endl;  // ❌ 未定义行为
    } else {
        std::cout << "Iterator is equal to vec.end()" << std::endl;
    }

    return 0;
}
```

---

## ⚠️ 输出结果（可能）

取决于编译器和运行环境，你可能会看到：

- 程序崩溃（segmentation fault）
- 输出乱码值（如：`*it = 0` 或随机数）
- 控制流异常中断
- 或者看起来“正常”的输出（但这是危险的假象）

## ✅ 正确做法：清空后不要使用旧迭代器

### ✅ 示例：正确使用迭代器遍历 + 清空

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> vec = {1, 2, 3, 4, 5};

    // 遍历并打印
    for (auto it = vec.begin(); it != vec.end(); ++it) {
        std::cout << *it << " ";
    }
    std::cout << std::endl;

    // 清空
    vec.clear();

    // 再次遍历是安全的，因为重新获取了新的 begin/end
    for (auto it = vec.begin(); it != vec.end(); ++it) {
        std::cout << *it << " ";
    }
    std::cout << "(size: " << vec.size() << ")" << std::endl;

    return 0;
}
```

### ✅ 输出：
```
1 2 3 4 5 
(size: 0)
```

---

## 🔒 总结：vector 清空时的注意事项

| 操作 | 是否导致迭代器失效 |
|------|-------------------|
| `clear()` | ✅ 是 |
| `resize(0)` | ✅ 是 |
| `swap(vec, std::vector<int>())` | ✅ 是 |
| `vec = {}` | ✅ 是 |

📌 结论：
- 清空 `vector` 后，任何之前保存的迭代器都不可再使用。
- 若需要再次使用迭代器，请在清空之后重新调用 `begin()` / `end()`。

## 📌 常见错误场景回顾

```cpp
std::vector<int> v{1, 2, 3};
auto it = v.begin();
v.clear();
*it;  // ❌ 错误！it 失效
```

## 🧪 补充：其他导致迭代器失效的操作

| 操作 | 是否导致迭代器失效 | 条件说明 |
|------|--------------------|----------|
| `push_back()` | ✅ 是 | 如果引起扩容 |
| `insert()` | ✅ 是 | 插入点之后的迭代器全部失效 |
| `erase()` | ✅ 是 | 被删除元素及其之后的迭代器失效 |
| `reserve()` | ❌ 否 | 仅改变容量，不改变 size |
| `shrink_to_fit()` | ✅ 是 | 数据可能移动到新内存 |
| `clear()` | ✅ 是 | 所有迭代器失效 |
