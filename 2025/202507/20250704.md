##  步骤一：自己源码安装 tinyrpc

假设你是通过以下方式安装的：

```bash
git clone https://github.com/xxx/tinyrpc.git
cd tinyrpc
mkdir build && cd build
cmake ..
make -j$(nproc)
sudo make install
```

默认情况下，`make install` 会把头文件放到 `/usr/local/include/tinyrpc`，库文件放到 `/usr/local/lib/libtinyrpc.a` 或 `.so/.dylib`。

##  步骤二：创建 `cmake/FindTinyRPC.cmake`

将以下内容保存为 `cmake/FindTinyRPC.cmake` 文件：

```cmake
# FindTinyRPC.cmake
# 查找 tinyrpc 库，并设置相关变量

# 查找头文件位置
find_path(TINYRPC_INCLUDE_DIR
    NAMES tinyrpc/common/log.h  # 根据你的实际头文件路径修改
    PATHS /usr/local/include
    DOC "tinyrpc 头文件目录"
)

# 查找库文件
find_library(TINYRPC_LIBRARY
    NAMES tinyrpc
    PATHS /usr/local/lib
    DOC "tinyrpc 库文件"
)

include(FindPackageHandleStandardArgs)

# 使用标准方式处理查找结果
find_package_handle_standard_args(TinyRPC
    REQUIRED_VARS TINYRPC_INCLUDE_DIR TINYRPC_LIBRARY
    VERSION_VAR TINYRPC_VERSION_STRING
)

if(TINYRPC_FOUND)
    message(STATUS " 找到 tinyrpc")
    message(STATUS "    包含路径: ${TINYRPC_INCLUDE_DIR}")
    message(STATUS "    库路径: ${TINYRPC_LIBRARY}")
else()
    message(FATAL_ERROR "
 错误：未找到 tinyrpc 库。
请确保你已经成功从源码安装 tinyrpc：
    git clone https://github.com/xxx/tinyrpc.git
    cd tinyrpc && mkdir build && cd build
    cmake .. && make && sudo make install
")
endif()
```

在 C++ 中，以下两行代码：

```cpp
EventLoop loop;
EventLoop* loop = new EventLoop();
```

虽然都用于创建 `EventLoop` 对象，但它们有本质的区别。下面我将详细说明这两者的**联系与区别**。

##  联系

- 两者都是用来创建一个 `EventLoop` 类型的对象。
- 都可以用于后续调用该对象的方法或操作。
- 都依赖于 `EventLoop` 这个类已经正确定义（比如构造函数是可访问的）。

---

## ❌ 区别

| 特性 | `EventLoop loop;` | `EventLoop* loop = new EventLoop();` |
|------|------------------|---------------------------------------|
| **内存分配方式** | 在栈上分配内存 | 在堆上分配内存 |
| **生命周期管理** | 生命周期由编译器自动管理（进入作用域创建，离开作用域销毁） | 必须手动使用 `delete` 释放内存，否则会内存泄漏 |
| **访问方式** | 直接通过变量名访问（如 `loop.doSomething()`） | 通过指针访问（如 `loop->doSomething()`） |
| **适用场景** | 简单、局部使用的对象，不需要动态分配 | 需要动态分配、长期存在、跨作用域使用 |
| **性能** | 更快，因为栈分配效率高 | 比栈分配慢，涉及堆内存管理 |
| **异常安全性** | 不会抛出 bad_alloc 异常（除非栈溢出） | 可能抛出 `std::bad_alloc`（如果内存不足） |

---

## 示例对比

### 栈上对象 (`EventLoop loop;`)
```cpp
void func() {
    EventLoop loop;            // 创建栈上对象
    loop.run();                // 使用它
}                              // 离开作用域时自动析构
```

### 堆上对象 (`EventLoop* loop = new EventLoop();`)
```cpp
void func() {
    EventLoop* loop = new EventLoop();  // 创建堆上对象
    loop->run();                        // 使用它
    delete loop;                        // 必须手动释放
}
```

或者更好的做法是配合智能指针：
```cpp
#include <memory>

void func() {
    std::unique_ptr<EventLoop> loop = std::make_unique<EventLoop>();
    loop->run();   // 使用它，离开作用域自动释放内存
}
```


##  总结建议

- 如果你只需要一个局部使用的对象，优先使用 `EventLoop loop;`（栈上分配），更安全高效。
- 如果你需要动态创建对象（例如根据运行时条件决定是否创建，或者对象很大不适合栈上分配），使用 `new` 或智能指针。
- 永远不要忘记使用 `delete` 来释放堆内存，或者使用智能指针来避免内存泄漏。

好的！我们来举一个 **`EventLoop* loop = new EventLoop();` 跨作用域使用** 的例子。


##  场景说明

假设你有一个 `EventLoop` 对象，你想在某个函数中创建它，然后把它传给其他线程或模块使用，而不是在当前函数结束时销毁它。这种情况下你就需要 **动态分配内存（使用 `new`）**，因为栈对象会在函数返回后被销毁。


##  示例代码：跨作用域使用 `EventLoop`

```cpp
#include <iostream>
#include <thread>
#include <chrono>

class EventLoop {
public:
    void run() {
        std::cout << "EventLoop is running in thread: " << std::this_thread::get_id() << std::endl;
        while (!stopFlag) {
            std::this_thread::sleep_for(std::chrono::milliseconds(500));
            std::cout << "Looping..." << std::endl;
        }
        std::cout << "EventLoop stopped." << std::endl;
    }

    void stop() {
        stopFlag = true;
    }

private:
    bool stopFlag = false;
};

// 全局指针，用于跨作用域访问
EventLoop* globalLoop = nullptr;

void createEventLoopInFunction() {
    // 在堆上创建 EventLoop 对象
    globalLoop = new EventLoop();

    std::thread t([globalLoop]() {
        globalLoop->run();  // 在子线程中运行事件循环
    });

    t.detach();  // 分离线程，继续执行
}

int main() {
    createEventLoopInFunction();

    std::cout << "Main thread continues. Press ENTER to stop the event loop..." << std::endl;
    std::cin.get();  // 等待用户输入

    if (globalLoop != nullptr) {
        globalLoop->stop();
        delete globalLoop;       // 手动释放堆内存
        globalLoop = nullptr;
    }

    return 0;
}
```


## 代码解析

- `createEventLoopInFunction()` 函数中通过 `new EventLoop()` 创建了一个堆上的对象。
- 这个对象赋值给了全局指针 `globalLoop`，从而可以跨越函数作用域使用。
- 子线程中调用了 `globalLoop->run()`，即使 `createEventLoopInFunction()` 返回了，对象依然存在。
- 主线程等待用户按下回车键后调用 `stop()` 并 `delete` 内存。


##  注意事项

- 使用 `new` 后必须手动调用 `delete`，否则会造成内存泄漏。
- 更现代的做法是使用智能指针（如 `std::shared_ptr` 或 `std::unique_ptr`）来管理生命周期：
  ```cpp
  std::shared_ptr<EventLoop> globalLoop;
  ```
  这样可以在多个模块之间共享所有权，并自动释放资源。


##  总结

| 特性 | 示例中的体现 |
|------|----------------|
| 跨作用域使用 | 通过全局指针保存堆上对象 |
| 动态分配 | 使用 `new EventLoop()` |
| 生命周期长 | 主线程结束后仍然运行直到用户按回车 |
| 需要手动释放 | 最后调用 `delete globalLoop` |
