当你在使用 Git 推送代码到远程仓库时遇到错误信息 [remote rejected] main -> main (shallow update not allowed)，这通常意味着你正在尝试推送到一个使用了“浅克隆”（shallow clone）的远程仓库。浅克隆指的是只下载了仓库的一部分历史记录，而不是完整的历史记录。

解决方法

完整克隆仓库：
如果你的本地仓库是从远程仓库浅克隆的，你可以尝试重新克隆仓库，但这次要使用完整的历史记录。使用以下命令：

```bash
git clone --depth 1 <repository-url>
cd <repository-name>
git fetch --unshallow
```

这将确保你的本地仓库包含完整的提交历史。

推送前拉取更新：
在推送前，确保你的本地分支是最新的。先拉取远程分支的最新更改：

```bash
git pull origin main
```

解决可能存在的冲突后，再次尝试推送：

```bash
git push origin main
```

直接推送到远程主分支：
如果你有权限直接推送到主分支，确保你的分支是最新的，然后直接推送：

```bash
git push origin main
```

检查远程仓库设置：
如果你不能更改本地仓库的设置（例如，如果你使用的是第三方服务如 GitHub、GitLab），可能需要联系仓库的管理员或检查仓库的设置是否允许浅克隆。在某些情况下，管理员可以更改仓库的配置以允许浅克隆。

使用 Git 命令行选项：
如果你确实需要在浅克隆的基础上进行操作，你可以在推送时使用 --depth 选项指定深度：

```bash
git push origin main --depth=100
```

这里 100 是你希望保留的提交数量。注意这种方法在某些情况下可能不被所有 Git 服务器支持。

注意事项
权限问题：确保你有足够的权限向远程仓库的主分支推送代码。
仓库配置：如果你在一个组织或团队环境中工作，可能需要管理员的帮助来调整仓库设置。
备份：在进行任何重大操作前（如重新克隆），确保备份你的工作。

通过上述方法，你应该能够解决这个推送问题。如果问题仍然存在，可能需要进一步检查具体的 Git 服务器或仓库配置。
