一、JSON 转 XML 方案
方案1：使用现成库serde（推荐）

Cargo.toml:
```
[dependencies]
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"
serde-xml-rs = "0.6"
```


代码示例：
```
use serde::{Deserialize, Serialize};
use serde_xml_rs::{from_str, to_string};

#[derive(Debug, Serialize, Deserialize)]
struct Person {
    name: String,
    age: u32,
    hobbies: Vec<String>,
}

fn json_to_xml(json_str: &str) -> Result<String, Box<dyn std::error::Error>> {
    // JSON 解析
    let person: Person = serde_json::from_str(json_str)?;
    
    // 转成 XML
    let xml = to_string(&person)?;
    Ok(xml)
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let json_data = r#"
    {
        "name": "Alice",
        "age": 30,
        "hobbies": ["reading", "swimming"]
    }
    "#;
    
    let xml = json_to_xml(json_data)?;
    println!("{}", xml);
    Ok(())
}
```

方案2：手动转换（更灵活）

use std::collections::HashMap;

fn json_value_to_xml(value: &serde_json::Value, tag_name: &str) -> String {
    match value {
        serde_json::Value::Object(obj) => {
            let mut xml = format!("<{}>", tag_name);
            for (key, val) in obj {
                xml.push_str(&json_value_to_xml(val, key));
            }
            xml.push_str(&format!("</{}>", tag_name));
            xml
        }
        serde_json::Value::Array(arr) => {
            let mut xml = String::new();
            for (i, item) in arr.iter().enumerate() {
                xml.push_str(&json_value_to_xml(item, &format!("item_{}", i)));
            }
            xml
        }
        serde_json::Value::String(s) => {
            format!("<{}>{}</{}>", tag_name, s, tag_name)
        }
        serde_json::Value::Number(n) => {
            format!("<{}>{}</{}>", tag_name, n, tag_name)
        }
        serde_json::Value::Bool(b) => {
            format!("<{}>{}</{}>", tag_name, b, tag_name)
        }
        serde_json::Value::Null => {
            format!("<{}/>", tag_name)
        }
    }
}

```
示例：JSON 解析器
use pest::Parser;
use pest_derive::Parser;

#[derive(Parser)]
#[grammar = "json.pest"]  // 语法规则文件
pub struct JSONParser;
```

// json.pest 文件内容：
```
/*
value = { object | array | string | number | "true" | "false" | "null" }
object = { "{" ~ (string ~ ":" ~ value)? ~ ("," ~ string ~ ":" ~ value)* ~ "}" }
array = { "[" ~ (value)? ~ ("," ~ value)* ~ "]" }
string = { "\"" ~ (!"\"" ~ ANY)* ~ "\"" }
number = { ("+" | "-")? ~ ASCII_DIGIT+ ~ ("." ~ ASCII_DIGIT+)? }
*/

fn main() {
    let json = r#"{"name": "Alice", "age": 30}"#;
    let pairs = JSONParser::parse(Rule::value, json).unwrap();
    
    for pair in pairs {
        println!("{:?}", pair);
    }
}
```

三、完整的 JSON 转 XML 项目示例

Cargo.toml:
[package]
name = "json2xml"
version = "0.1.0"
edition = "2021"

[dependencies]
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"
serde-xml-rs = "0.6"
clap = { version = "4.0", features = ["derive"] }


src/main.rs:

```
use clap::{Arg, Command};
use serde_json::Value;
use std::fs;

fn json_to_xml(value: &Value, root_tag: &str) -> String {
    match value {
        Value::Object(obj) => {
            let mut xml = format!("<{}>", root_tag);
            for (key, val) in obj {
                xml.push_str(&json_to_xml(val, key));
            }
            xml.push_str(&format!("</{}>", root_tag));
            xml
        }
        Value::Array(arr) => {
            let mut xml = String::new();
            for item in arr {
                xml.push_str(&json_to_xml(item, "item"));
            }
            format!("<{}>{}</{}>", root_tag, xml, root_tag)
        }
        Value::String(s) => {
            format!("<{}><![CDATA[{}]]></{}>", root_tag, s, root_tag)
        }
        _ => {
            format!("<{}>{}</{}>", root_tag, value, root_tag)
        }
    }
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let matches = Command::new("json2xml")
        .arg(Arg::new("input").short('i').long("input").required(true))
        .arg(Arg::new("output").short('o').long("output"))
        .get_matches();

    let input_file = matches.get_one::<String>("input").unwrap();
    let json_content = fs::read_to_string(input_file)?;
    let json_value: Value = serde_json::from_str(&json_content)?;

    let xml = format!(
        "<?xml version=\"1.0\" encoding=\"UTF-8\"?>\n{}",
        json_to_xml(&json_value, "root")
    );

    if let Some(output_file) = matches.get_one::<String>("output") {
        fs::write(output_file, xml)?;
    } else {
        println!("{}", xml);
    }

    Ok(())
}
```

三地址码（Three-Address Code）

中间代码生成是编译器的关键阶段，它连接了前端（词法、语法、语义分析）和后端（目标代码生成/优化）。
中间代码生成的作用
中间代码生成将AST（抽象语法树） 和符号表转换为一种与机器无关的中间表示形式。
从你的代码看，生成的是三地址码（Three-Address Code）

具体来说，你的 QuadItem 类生成的是四元式，这是三地址码的一种常见形式：
// 四元式结构：(操作符, 操作数1, 操作数2, 结果)
class QuadItem {
OpType op;      // 操作类型
Arg arg1;       // 第一个操作数  
Arg arg2;       // 第二个操作数
Arg result;     // 结果
};


具体生成什么？
1. 算术运算中间代码

// 源代码：c = a + b * 3
// 生成的中间代码：
QuadItem(temp1, multiply, b, 3)    // temp1 = b * 3
QuadItem(c, addtion, a, temp1)     // c = a + temp1


2. 控制流中间代码

// 源代码：if (a > b) c = 1; else c = 2;
// 生成的中间代码：
QuadItem(_, JUMP_GT, a, b, label_true)  // 如果 a > b 跳转到真分支
QuadItem(_, JUMP, _, _, label_false)     // 否则跳转到假分支
QuadItem(label_true)                      // 真分支标签
QuadItem(c, assign, 1)                   // c = 1
QuadItem(_, JUMP, _, _, label_end)       // 跳转到结束
QuadItem(label_false)                     // 假分支标签  
QuadItem(c, assign, 2)                   // c = 2
QuadItem(label_end)                       // 结束标签


3. 函数调用中间代码

// 源代码：result = add(x, y)
// 生成的中间代码：
QuadItem(_, PARAM, x)                    // 参数压栈
QuadItem(_, PARAM, y)
QuadItem(temp, CALL, add)                // 调用函数
QuadItem(result, assign, temp)           // 获取返回值


完整的编译流程


源代码 → 词法分析 → 语法分析 → 语义分析 → 中间代码生成 → 目标代码生成
↓           ↓           ↓
Token流     AST抽象语法树  中间代码(三地址码)
↓
符号表(变量类型、作用域)

    // 生成方法

    void Generate(AbstractAstNode* node, SymbolTable* table);

实际生成示例

假设有这段C代码：
int main() {
int a = 5;
int b = a + 3;
if (b > 0) {
return 1;
}
return 0;
}


经过你的中间代码生成器后，可能产生：

// 四元式序列
1: (ASSIGN, 5, _, a)          // a = 5
2: (ADD, a, 3, temp1)         // temp1 = a + 3  
3: (ASSIGN, temp1, _, b)       // b = temp1
4: (JUMP_GT, b, 0, label1)    // if b > 0 goto label1
5: (ASSIGN, 0, _, ret_val)     // ret_val = 0
6: (JUMP, _, _, label_end)     // goto end
7: (LABEL, label1)             // label1:
8: (ASSIGN, 1, _, ret_val)      // ret_val = 1
9: (LABEL, label_end)           // label_end:
10: (RETURN, ret_val)           // return ret_val


为什么需要中间代码？

1. 目标机器无关性：同一份中间代码可以生成x86、ARM等不同目标代码
2. 优化便利：在中间代码级别进行优化比在AST或目标代码级别更容易
3. 分层设计：前端和后端解耦，便于维护和扩展
4. 调试信息：中间代码比汇编更易读，便于调试编译器本身

## 三地址码
三地址码是编译器设计中最重要的中间表示形式之一。它得名于大多数指令最多包含三个地址（操作数）。

一、基本概念

什么是三地址码？

每条指令最多包含：
• 一个操作符

• 最多两个操作数（源操作数）

• 一个结果（目标操作数）

基本形式：result = arg1 op arg2

与汇编语言的区别

; 汇编语言（机器相关）
mov eax, 5      ; 寄存器操作
add eax, 10     ; 特定指令集

; 三地址码（机器无关）
t1 = 5 + 10     ; 抽象操作，使用临时变量


二、三地址码的表示形式

1. 四元式 - 你的代码采用的形式

// (操作符, 操作数1, 操作数2, 结果)
(op, arg1, arg2, result)


示例：
// 源代码：x = a + b * c
(*, b, c, t1)     // t1 = b * c
(+, a, t1, x)     // x = a + t1


2. 三元式

// (操作符, 操作数1, 操作数2)
// 结果通过位置隐式表示
(op, arg1, arg2)  // 结果存储在临时位置


3. 间接三元式

包含指向三元式的指针列表，便于优化时重排。

三、三地址码指令类型

1. 算术运算指令

// 二元运算
t1 = a + b       // 加法
t2 = x * y       // 乘法  
t3 = p / q       // 除法

// 一元运算
t4 = -a          // 取负
t5 = !b          // 逻辑非


2. 赋值指令

x = 5            // 常量赋值
y = z            // 变量赋值
a = b + c        // 表达式赋值


3. 控制流指令

// 无条件跳转
goto L1

// 条件跳转
if a > b goto L1
if x == 0 goto L2

// 标签定义
L1:


4. 函数相关指令

// 参数传递
param x
param y

// 函数调用
t1 = call add, 2    // 调用add，2个参数

// 返回指令
return result


5. 数组和指针操作

// 数组访问
t1 = i * 4        // 计算偏移量（假设int为4字节）
t2 = a[t1]        // 数组读取
a[t1] = value     // 数组写入

// 地址操作
t3 = &x           // 取地址
t4 = *p           // 解引用


四、实际转换示例

C 代码 → 三地址码

// 源代码
int main() {
int a = 5;
int b = 10;
int c = a * b + 2;

    if (c > 50) {
        return 1;
    } else {
        return 0;
    }
}


生成的三地址码：
// 初始化
main:
a = 5
b = 10

// 算术运算
t1 = a * b
c = t1 + 2

// 条件判断
if c > 50 goto L1
goto L2

// 真分支
L1:
return 1

// 假分支  
L2:
return 0


五、三地址码的优势

1. 简单规整

// 复杂的表达式被分解为简单步骤
// 源代码：y = a * b + c * d - e / f

// 三地址码（易于处理）：
t1 = a * b
t2 = c * d  
t3 = t1 + t2
t4 = e / f
y = t3 - t4


2. 便于优化

// 常量传播
a = 5
b = a + 3     →  b = 5 + 3  →  b = 8

// 公共子表达式消除
t1 = x * y
t2 = x * y     →  t2 = t1


3. 目标机器无关

同一份三地址码可生成不同目标架构的代码：
// 三地址码
t1 = a + b

// x86汇编
mov eax, [a]
add eax, [b]
mov [t1], eax

// ARM汇编
ldr r0, [a]
ldr r1, [b]
add r2, r0, r1
str r2, [t1]


4. 便于寄存器分配

// 显式的临时变量使用

c = t1 * 2     // t1可重用


六、你的代码实现分析

你的 QuadItem 类正是实现了四元式表示的三地址码：
class QuadItem {
public:
Arg result;    // 结果地址
OpType op;     // 操作符
Arg arg1;      // 第一个操作数
Arg arg2;      // 第二个操作数

    // 各种构造函数对应不同的指令格式
    QuadItem(Symbol* result, OpType op, Symbol* arg1, Symbol* arg2);
    QuadItem(int result, OpType op, int arg1);  // 标签跳转
};

三地址码是编译器设计的核心中间表示，它：
• 将复杂表达式分解为简单指令
• 提供机器无关的优化平台
• 简化代码生成过程
• 支持各种编译优化技术

一、经典必读（“龙书”系列）

• 别称："龙书" (因封面有恐龙图案)
• 特点：编译领域的圣经，最新版（第二版）对中间代码表示（包括三地址码）有极其系统和深入的阐述。
• 相关章节：
  • 第6章：中间代码生成（Intermediate-Code Generation）
  • 第8章：代码生成（Code Generation）
  • 详细介绍了三地址码的各种形式（四元式、三元式、间接三元式）、控制流语句的翻译、回填技术等。

二、现代实践派
2. 《Engineering a Compiler》
• 作者：Keith Cooper & Linda Torczon
• 特点：非常注重工程实践，对如何设计和实现中间表示（IR）有很好的指导，包含大量具体例子和数据结构设计。
• 相关章节：第二部分（The Front End）和第三部分（The Back End）都深入探讨了中间表示的构建和优化。
3. 《Modern Compiler Implementation in C / Java / ML》（“虎书”）
• 作者：Andrew W. Appel
• 别称："虎书"

四、书籍内容重点导读
当你阅读这些书籍时，可以重点关注以下与三地址码直接相关的核心内容：
书籍 关键知识点

六、核心概念总结（这些是书中会详细讲解的重点）
通过阅读这些书籍，你将彻底掌握以下关于三地址码的核心知识：
1.  三地址指令的类型：赋值、算术/逻辑运算、控制流（跳转、条件分支）、过程调用、地址计算。
2.  三地址码的表示形式：四元式（Quadruples）、三元式（Triples）、间接三元式（Indirect Triples） 的优缺点和实现方式。
3.  从AST生成三地址码的翻译方案：如何为每种语法结构（表达式、语句、控制流、函数调用）生成对应的三地址指令序列。
4.  临时变量的管理：如何分配和管理临时变量名（如t1, t2）。
5.  符号表的作用：如何利用符号表中的类型信息来确定运算的宽度和地址计算方式。
6.  控制流语句的翻译：特别是布尔表达式的“短路”计算以及用于实现if、while等语句的回填（Backpatching） 技术。
7.  数组和结构体的地址计算：如何生成计算数组元素地址的三地址指令序列。
