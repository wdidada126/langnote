3. MySQL的具体API使用示例

// 示例：InnoDB的文件操作
dberr_t os_file_create_func(
    const char* name, os_file_t* file, ulint type, ulint purpose) {
    
#ifdef _WIN32
    // Windows实现
    *file = CreateFile(name, 
                       GENERIC_READ | GENERIC_WRITE,
                       FILE_SHARE_READ | FILE_SHARE_DELETE,
                       NULL,
                       OPEN_ALWAYS,
                       FILE_FLAG_RANDOM_ACCESS | 
                       FILE_FLAG_OVERLAPPED,  // 异步I/O
                       NULL);
#else
    // Linux/Unix实现
    int flags = O_RDWR | O_CREAT;
    
    // 使用O_DIRECT绕过页缓存
    if (srv_unix_file_flush_method == SRV_UNIX_O_DIRECT) {
        flags |= O_DIRECT;
    }
    
    // 使用O_SYNC确保数据安全
    if (srv_unix_file_flush_method == SRV_UNIX_O_SYNC) {
        flags |= O_SYNC;
    }
    
    *file = open(name, flags, S_IRUSR | S_IWUSR);
#endif
    
    return DB_SUCCESS;
}

3. 直接I/O vs 缓冲I/O

直接I/O (O_DIRECT):
  - 优点: 避免双缓存，减少内存拷贝
  - 缺点: 需要应用自己管理缓存
  - 使用者: MySQL InnoDB(可选), RocksDB
  
缓冲I/O (默认):
  - 优点: 利用OS页面缓存
  - 缺点: 可能双缓存
  - 使用者: PostgreSQL, LevelDB(默认)

总结

现代数据库系统对OS API的使用：

1. 基础API：open/read/write/fsync
2. 高级特性：
   • 直接I/O（O_DIRECT）

   • 异步I/O（libaio）

   • 内存映射（mmap）

   • 稀疏文件

3. 优化策略：
   • 对齐访问

   • 批量提交

   • 预读优化

   • 压缩合并

4. 现代趋势：
   • 用户态驱动（SPDK）

   • 持久化内存（PMEM）

   • 新硬件支持（NVMe, Optane）

不同数据库的选择差异主要在于：
• 事务保证 → 同步策略

• 性能需求 → 缓存策略

• 硬件环境 → I/O模式

• 工作负载 → 压缩/合并策略

理解这些底层API的使用，对于数据库性能调优和故障排查至关重要。
