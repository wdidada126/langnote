在Flex词法分析器中，要获取某个token所在的行号，你可以使用Flex内置的全局变量 yylineno。下面是一个快速参考表格，帮助你理解相关的变量和API：

变量/方法 说明 示例/备注

yylineno 全局变量，通常记录当前行号（从1开始）。 需在Flex文件定义部分用%option yylineno声明。

yytext 全局变量（char*），存储当前匹配的token文本。 匹配"int"时，yytext就是"int"。

yylex() 词法分析函数，每次调用返回下一个token。 返回值通常是token类型，yylineno在调用后更新。

YY_USER_ACTION 宏，在每个规则匹配后、执行动作前执行。 可在此自定义位置信息（如列号）的更新逻辑。

🛠️ 具体实现步骤

1.  启用行号跟踪
    在你的Flex文件（通常是.l文件）的定义部分（第一个%%之前），添加%option yylineno选项。这会指示Flex自动声明和维护yylineno变量。
    %{
    #include "tokens.h" // 假设你的token类型定义在这里
    %}
    %option yylineno
    %%
    

2.  在规则动作中返回行号
    在你的词法规则部分，当匹配到某个token模式时，你可以在动作中访问yylineno来获取它所在的行号。通常，你需要将行号信息通过某种方式传递给语法分析器（如Bison）。常见的做法是将其赋值给一个全局变量，或者更好的是，利用Bison协作时传入的yylval参数（如果你使用了Bison）。
    一个简单的例子，将行号打印出来：
    "int"       { printf("Found keyword 'int' at line: %d\n", yylineno); return INT; }
    [a-zA-Z]+   { printf("Found identifier '%s' at line: %d\n", yytext, yylineno); return IDENTIFIER; }
    \n          { /* 遇到换行符，yylineno 会自动增加 */ }
    

💡 进阶：精确定位（行和列）

如果你需要更精确的定位信息（例如列号），以便在错误提示中给出第X行第Y列，你需要手动维护列信息。这通常通过定义YY_USER_ACTION宏来实现。

1.  定义位置跟踪变量
    在定义部分声明一个全局变量（如current_column）并定义YY_USER_ACTION。
    %{
    #include "tokens.h"
    int current_column = 1;
    #define YY_USER_ACTION \
        yylloc->first_line = yylloc->last_line = yylineno; \
        yylloc->first_column = current_column; \
        yylloc->last_column = current_column + yyleng - 1; \
        current_column += yyleng;
    %}
    %option yylineno
    %%
    

2.  在规则中处理特殊字符
    对于换行符\n，需要重置列计数器；对于制表符\t，则需要根据你的制表符宽度进行特殊处理。
    %%
    \n          { current_column = 1; /* 重置列号 */ }
    \t          { current_column += 8; /* 假设制表符宽度为8 */ }
    

💎 小结

获取Flex中token的行号，核心是使用 yylineno 变量，并记得用 %option yylineno 启用它。如果需要更详细的定位信息（如列号），则需通过 YY_USER_ACTION 宏和自定义变量来手动维护。

GNU Bison 3.8.2 并不是一个提供传统意义上的“API列表”的库，而是一个解析器生成器工具（parser generator）。它本身不直接暴露运行时 API 给用户程序调用，而是根据你编写的 .y（或 .yy）语法文件生成 C/C++ 源代码，这些生成的代码中包含了一组标准接口函数和变量，供你集成到自己的程序中。

不过，我们可以将“Bison 的 API”理解为：

1. Bison 命令行工具的选项（用于控制生成行为）
2. Bison 生成的解析器所暴露的编程接口（即你在 C/C++ 程序中需要使用或实现的函数/变量）

一、Bison 命令行选项（CLI API）

这是调用 bison 命令时可用的参数，用于控制解析器生成过程。常用选项包括：

bash
bison [OPTION]... FILE

选项 说明
------ ------
-d, --defines 生成头文件（如 y.tab.h），包含 token 定义等
-o FILE, --output=FILE 指定输出 C 文件名
-v, --verbose 生成 .output 文件，包含状态机详细信息
-g, --graph 生成 .dot 文件，可视化语法分析状态图
--report=TYPE 生成详细报告（如 state, itemset, solved 等）
-W[category] 启用特定警告（如 midrule-values, other）
--language=LANGUAGE 指定目标语言（c, c++, java 等，默认 c）
--name-prefix=PREFIX 自定义函数/变量前缀（默认 yy，可改为 my_ 等）
--debug 启用调试模式（需在代码中定义 YYDEBUG）

完整选项见官方手册：
https://www.gnu.org/software/bison/manual/html_node/Invoking-Bison.html

二、Bison 生成的解析器接口（C 接口）

当你运行 bison grammar.y，它会生成一个 C 文件（如 grammar.c），其中包含以下标准接口：
1. 主要函数

函数 作用 是否需用户实现
------ ------ ----------------
int yyparse(void) 启动语法分析 ✅ 自动生成，但依赖 yylex()
int yylex(void) 词法分析器（返回 token） ❌ 必须由用户实现（通常用 Flex 生成）
void yyerror(const char msg) 报告语法错误 ❌ 必须由用户实现（简单打印即可）
2. 全局变量（可通过 %define api.prefix {xxx} 修改前缀）

变量 类型 说明
------ ------ ------
yylval YYSTYPE 传递 token 或非终结符的语义值（联合体）
yylloc YYLTYPE （可选）记录位置信息（行号、列号等）
yychar int 当前 lookahead token（调试用）
yydebug int 若设为非零，启用解析过程跟踪（需编译时定义 YYDEBUG）
默认前缀是 yy，可通过 %define api.prefix {my} 改为 my，则函数变为 myparse()、myerror() 等。
3. 类型定义（在 y.tab.h 中）
YYSTYPE：语义值类型，默认为 int，可通过 %union 或 %define api.value.type {type} 自定义。
YYLTYPE：位置类型（若启用 %locations）。

示例自定义：
bison
%define api.value.type {struct ast_node }
%define api.prefix {sql_}

则生成 sqlparse()、sqlval 等。

三、高级接口（可选特性）

特性 说明
------ ------
%pure-parser / %define api.pure full 生成可重入（reentrant）解析器，所有状态通过参数传递
%lex-param {…} / %parse-param {…} 为 yylex 和 yyparse 添加额外参数（用于线程安全或上下文传递）
%destructor 自动释放语义值内存（避免内存泄漏）
%printer 调试时打印语义值内容
GLR 模式 (%glr-parser) 支持歧义文法，返回多个解析结果

四、总结：Bison “API” 实质

类别 内容
------ ------
工具层 API bison 命令行参数
生成代码接口 yyparse(), yylex(), yyerror(), yylval, yydebug 等
可配置性 通过 %define、%option 等指令定制接口名称和行为
扩展能力 支持纯解析器、位置追踪、GLR、C++ 等

✅ 建议：
若你需要构建一个解析器，典型流程是：

1. 编写 .l 文件（Flex）→ 生成 yylex()
2. 编写 .y 文件（Bison）→ 定义语法规则 + 实现 yyerror()
3. 运行 bison -d parser.y 和 flex lexer.l
4. 编译 lex.yy.c + parser.tab.c + 你的主程序
