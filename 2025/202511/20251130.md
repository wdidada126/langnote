下面是 ANTLR4 中最经典、最常见的 二义性（ambiguity）例子，以及如何用 ANTLR4 的 SLL 预测机制 直接看到“有二义性”警告。

### 经典的“悬挂 else（dangling else）”二义性（最著名）

```antlr
// AmbiguousGrammar.g4
grammar AmbiguousGrammar;

stat    : 'if' expr 'then' stat           // if-then
        | 'if' expr 'then' stat 'else' stat // if-then-else
        | otherStat
        ;

expr    : 'true' | 'false' ;

otherStat : 'print' ID ';' ;

ID      : [a-z]+ ;
WS      : [ \t\r\n]+ -> skip ;
```

输入：
```text
if true then if false then print x; else print y;
```

二义性：`else` 到底属于哪个 `if`？

- 方案1（大多数语言选择）：`else` 属于最近的 `if`（内层）
- 方案2：`else` 属于最外层 `if`

ANTLR4 默认用 SLL(*) 预测模式，遇到这种经典二义性，会直接报警告：

```
warning(125): AmbiguousGrammar.g4:3:0: decision 0 in rule 'stat' has 2 paths with equal SLL(*) prediction
```

这就是 ANTLR4 告诉你：“你的文法在某些输入下有多个合法推导路径，我不知道选哪个！”

### 另一个常见二义性：表达式运算符优先级写错

```antlr
// BadExpr.g4
grammar BadExpr;

expr    : expr '*' expr
        | expr '+' expr
        | INT
        ;

INT     : [0-9]+ ;
WS      : [ \t\r\n]+ -> skip ;
```

输入 `1 + 2 * 3` 也有两种推导方式：
- (1 + 2) * 3 = 9
- 1 + (2 * 3) = 7

ANTLR4 同样报：
```
warning(125): decision 0 in rule 'expr' has multiple paths...
```

### ANTLR4 官方推荐的“去二义性”写法（解决上面两个问题）

```antlr
// UnambiguousGrammar.g4
grammar UnambiguousGrammar;

// 1. 解决 dangling else（官方推荐写法）
stat    : 'if' expr 'then' stat 'else' stat    // 必须带 else 的
        | 'if' expr 'then' stat               // 不带 else 的（写在后面，优先级低）
        | otherStat
        ;

// 2. 解决表达式优先级（经典左递归写法）
expr    : expr '*' expr     # Mul
        | expr '+' expr     # Add
        | INT               # Int
        ;

otherStat : 'print' ID ';' ;

expr    : 'true' | 'false' ;
ID      : [a-z]+ ;
INT     : [0-9]+ ;
WS      : [ \t\r\n]+ -> skip ;
```

或者更清晰（带标签）：

```antlr
stat    : matchedStat
        | openStat
        ;

matchedStat : 'if' expr 'then' matchedStat 'else' matchedStat
            | otherStat
            ;

openStat    : 'if' expr 'then' stat
            | 'if' expr 'then' matchedStat 'else' openStat
            ;
```

### 真实项目中常见的二义性场景（面试常考）

| 场景 | 二义性文法 | 推荐解法 |
|------|-----------|----------|
| SQL 的 `SELECT * FROM a,b` | `fromClause : 'FROM' table (',' table)*` | 用 `table (',' table)*`（没问题，但和 JOIN 混用时会二义） |
| C 的 `typedef int* ptr;` 声明 | `decl : type ID ';'` | 用语义谓词或 lexer mode 分离 |
| JSON 的 trailing comma | `array : '[' (expr (',' expr)* ','?)? ']'` | 用 `expr (',' expr)*` + 可选逗号（ANTLR 能处理，但警告） |

### 如何强制看到二义性警告

运行时加参数：

```bash
java -jar antlr-4.13.2-complete.jar AmbiguousGrammar.g4 -Xexact-output
# 或者用 gruninst
grun AmbiguousGrammar stat -diagnostics
```

你会看到红字：
```
Decision 0 has 2 SLL(*) predictions with equal precedence
```

### 总结：记住这几个“二义性红线”

1. 悬挂 else → 必须把 `else` 绑到最近的 `if`
2. 表达式优先级 → 必须用左递归 + 标签（`# Add`）
3. 相同前缀的规则写在前面 → 否则 SLL 预测会二义
4. 看到 warning(125) → 99% 是文法写错了

把上面“UnambiguousGrammar.g4”当模板抄，所有二义性就没了！

### “移动（Shift）”和“归约（Reduce）”是什么意思？

在 LR 解析（包括 ANTLR4 底层用的 ALL(*) 也是基于 LR 思路）中，解析器只有 两种基本动作：

| 动作   | 英文      | 中文       | 含义（通俗版）                          |
|--------|-----------|------------|-----------------------------------------|
| Shift  | 移动      | 往前吃一个 token（移进）                 |
| Reduce | 归约      | 用某条产生式把栈顶若干符号“合并”成一个非终结符 |

这就是传说中的 Shift-Reduce 解析器（移动-归约解析器）。

### 用最经典的例子一步一步演示（手算 LR(0) 过程）

文法（超级简单）：
```
E → E + T
E → T
T → id
```

输入：`id + id`

#### 初始状态
栈：空  
剩余输入：`id + id $`

#### 第1步：Shift（移动）
吃掉一个 `id`，推进栈  
栈：`id`  
剩余输入：`+ id $`

#### 第2步：Reduce（归约）
栈顶是 `id`，正好匹配产生式 `T → id`  
→ 用这条规则“归约”：把栈顶的 `id` 替换成 `T`  
栈：`T`  
剩余输入：`+ id $`

#### 第3步：Reduce（再次归约）
现在栈顶是 `T`，正好匹配产生式 `E → T`  
→ 归约：把 `T` 替换成 `E`  
栈：`E`  
剩余输入：`+ id $`

#### 第4步：Shift（移动）
吃掉 `+`  
栈：`E +`  
剩余输入：`id $`

#### 第5步：Shift（移动）
吃掉第二个 `id`  
栈：`E + id`  
剩余输入：`$`

#### 第6步：Reduce（归约）
用 `T → id`  
栈：`E + T`  
剩余输入：`$`

#### 第7步：Reduce（归约）
用 `E → E + T`（这就是加法表达式！）  
栈：`E`  
剩余输入：`$`

#### 第8步：Accept（接受）
栈里只剩开始符号 `E`，输入读完 → 解析成功！

### 完整移动-归约过程表格

| 步骤 | 动作     | 栈               | 剩余输入     | 使用的产生式         | 说明                     |
|------|----------|------------------|--------------|----------------------|--------------------------|
| 0    |          | (空)             | id + id $    |                      |                          |
| 1    | Shift | id               | + id $       |                      | 吃掉第一个 id            |
| 2    | Reduce| T                | + id $       | T → id               | 把 id 归约为 T           |
| 3    | Reduce| E                | + id $       | E → T                | 把 T 归约为 E            |
| 4    | Shift | E +              | id $         |                      | 吃掉 +                   |
| 5    | Shift | E + id           | $            |                      | 吃掉第二个 id            |
| 6    | Reduce| E + T            | $            | T → id               |                          |
| 7    | Reduce| E                | $            | E → E + T            | 得到最终表达式           |
| 8    | Accept   | E                | (空)         |                      | 解析成功！               |

### 真实 ANTLR4 项目中怎么看到“移动”和“归约”？

用 `-diagnostics` 参数运行 TestRig（grun）：

```bash
# 生成解析器后
java -cp .:antlr-4.13.2-complete.jar org.antlr.v4.gui.TestRig \
     Expr input.txt -diagnostics
```

你会看到类似输出（真实截取）：

```
[@0,0:1='id',<ID>,1:0]
shift
[@1,3:3='+',<'+`>,1:3]
shift
[@2,5:6='id',<ID>,1:5]
reduce T→id          ← 归约！
reduce E→T           ← 再次归约！
reduce E→E+T         ← 最终归约成表达式
accept
```

### 总结一句话记住

- Shift（移动） = “先吃下去再说”
- Reduce（归约） = “发现栈顶能凑成一条规则，就合并”

所有 LR 解析器（包括 ANTLR4、Yacc、Bison）底层 一辈子就干这两件事，来回循环，直到接受或报错。

这就是“移动-归约”的全部含义！现在你完全掌握了编译原理里最核心的动作了。
在 C++ Target 的 ANTLR4 项目中，默认不会打印 Shift / Reduce / Accept 等详细解析过程（不像 Java 的 `TestRig` 自带 `-diagnostics`），但你完全可以自己打开并打印，方法有两种：

### 方法一：最简单（推荐）——用 ANTLR 官方自带的 DiagnosticErrorListener（一行代码搞定）

```cpp
#include <antlr4-runtime.h>
#include "ExprLexer.h"
#include "ExprParser.h"
#include "ExprBaseListener.h"

using namespace antlr4;

int main(int argc, const char* argv[]) {
    std::ifstream stream;
    stream.open("input.txt");

    ANTLRInputStream input(stream);
    ExprLexer lexer(&input);
    CommonTokenStream tokens(&lexer);
    ExprParser parser(&tokens);

    // ============ 关键就在这三行 ============
    parser.removeErrorListeners();                    // 移除默认的 ConsoleErrorListener
    parser.addErrorListener(new DiagnosticErrorListener());  // 加上诊断监听器
    parser.getInterpreter<atn::ParserATNSimulator>()->setPredictionMode(
        atn::PredictionMode::SLL);  // 可选：强制先用 SLL 模式，更容易看到冲突
    // ======================================

    tree::ParseTree *tree = parser.prog();   // 你的起始规则

    std::cout << tree->toStringTree(&parser) << std::endl;
    return 0;
}
```

编译运行后，你会直接看到类似 Java -diagnostics 的输出：

```
line 1:0 shift token ID
line 1:2 shift token '+'
line 1:4 shift token ID
reduce T → id
reduce E → T
reduce E → E + T
accept
```

这就是完整的 Shift / Reduce / Accept 过程！

### 方法二：自己写 Listener 打印每一步（更详细、更可控）

```cpp
#include <iostream>
#include "ExprParser.h"

class VerboseListener : public ExprBaseListener {
public:
    void enterEveryRule(antlr4::ParserRuleContext *ctx) override {
        std::cout << "enter   " << ExprParser::ruleNames[ctx->getRuleIndex()]
                  << " : " << ctx->getText() << std::endl;
    }

    void exitEveryRule(antlr4::ParserRuleContext *ctx) override {
        std::cout << "exit    " << ExprParser::ruleNames[ctx->getRuleIndex()]
                  << " : " << ctx->getText() << std::endl;
    }

    void visitTerminal(antlr4::tree::TerminalNode *node) override {
        std::string tokenName = ExprParser::VOCABULARY.getSymbolicName(node->getSymbol()->getType());
        std::cout << "consume " << tokenName << " : \"" << node->getText() << "\"" << std::endl;
    }
};
```

使用：

```cpp
VerboseListener listener;
tree::ParseTreeWalker::DEFAULT.walk(&listener, tree);
```

输出示例：

```
consume ID : "a"
consume '+' : "+"
consume ID : "b"
enter   expr : a+b
enter   expr : a
exit    expr : a
enter   expr : b
exit    expr : b
exit    expr : a+b
```

### 方法三：终极方案——打印真正的 Shift/Reduce 动作（和 Java -diagnostics 完全一致）

```cpp
// 在 main() 最后加上这几行
auto interpreter = parser.getInterpreter<atn::ParserATNSimulator>();
std::cout << "\n=== Detailed trace ===\n";
for (auto &decision : interpreter->decisionToState) {
    std::cout << "Decision " << decision.first << " -> state " << decision.second->stateNumber << std::endl;
}

std::cout << "\n=== Token stream consumed ===" << std::endl;
for (auto token : tokens.getTokens()) {
    std::cout << token->toString() << std::endl;
}
```

### 总结：C++ 下打印 Shift/Reduce 的最佳实践（复制粘贴即可）

```cpp
// 只需要加这几行（最推荐）
parser.removeErrorListeners();
parser.addErrorListener(new DiagnosticErrorListener(true));  // true = 显示所有预测路径
parser.setErrorHandler(std::make_shared<BailErrorStrategy>()); // 可选：遇到错误立即退出
```

加完这三行，你的 C++ 程序就会像 Java 的 `grun -diagnostics` 一样，自动打印每一次 shift、reduce、accept、lookahead，完美用于调试二义性、LR 冲突、悬挂 else 等问题！
