在 GitHub Actions 中使用英特尔® C++ 编译器 (ICC/ICX)，核心是正确安装 oneAPI 工具包并配置好编译环境。下面是一个基本的工作流程示例和关键配置点。
基本工作流程示例
以下是一个在 Ubuntu  runner 中安装 Intel oneAPI BaseKit 并使用 icx 编译器（英特尔经典的 icc 编译器已过渡至基于 LLVM 的 icx）进行构建的示例。关键步骤在于使用 actions/cache 来提升工具包的安装速度，因为 oneAPI 体积较大 。

name: Build with Intel oneAPI Compiler
on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

env:
  # 定义 oneAPI 版本和组件，便于维护和更新
  ONEAPI_VERSION: "2024.1.0"
  BASEKIT_URL: "https://registrationcenter-download.intel.com/akdlm/IRC_NAS/6b7f86c2-6f0c-4af0-9d6a-194e977ed770/l_BaseKit_p_2024.1.0.555_offline.sh"
  HPCKIT_URL: "https://registrationcenter-download.intel.com/akdlm/IRC_NAS/3595f64d-9ef6-4c88-80c3-9c3c46a55c11/l_HPCKit_p_2024.1.0.435_offline.sh"

jobs:
  build-linux:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Cache oneAPI installation
        uses: actions/cache@v3
        id: cache-oneapi
        with:
          path: |
            /opt/intel/oneapi/
            ~/intel/oneapi/
          key: oneapi-${{ env.ONEAPI_VERSION }}-${{ runner.os }}-${{ hashFiles('**/CMakeLists.txt') }}
          restore-keys: |
            oneapi-${{ env.ONEAPI_VERSION }}-${{ runner.os }}-

      - name: Install Intel oneAPI BaseKit
        if: steps.cache-oneapi.outputs.cache-hit != 'true'
        run: |
          wget -O basekit_installer.sh "${{ env.BASEKIT_URL }}"
          sudo sh basekit_installer.sh -a -s --eula accept --components intel.oneapi.lin.dpcpp-cpp-compiler-pro:intel.oneapi.lin.mkl.devel
          rm basekit_installer.sh

      - name: Set up Intel compiler environment
        run: |
          source /opt/intel/oneapi/setvars.sh
          echo "ICX_VERSION=$(icx --version)" >> $GITHUB_ENV

      - name: Configure with CMake
        run: |
          source /opt/intel/oneapi/setvars.sh
          cmake -B build -DCMAKE_C_COMPILER=icx -DCMAKE_CXX_COMPILER=icpx .

      - name: Build the project
        run: |
          source /opt/intel/oneapi/setvars.sh
          cmake --build build --config Release

关键配置说明
使用缓存（Cache）：由于 oneAPI 工具包体积庞大（可达数GB），每次从头安装会严重拖慢工作流速度。使用 actions/cache 可以显著提升效率 。如果缓存未命中（cache-oneapi.outputs.cache-hit != 'true'），才执行安装步骤。
静默安装与自动接受许可：在安装脚本（如 basekit_installer.sh）中使用 -a -s --eula accept 等参数是为了在无交互的命令行模式下自动接受许可并静默安装，这对于自动化环境至关重要。
设置环境变量：Intel 编译器需要特定的环境变量（如 PATH、LIBRARY_PATH 等）。通过运行 source /opt/intel/oneapi/setvars.sh 脚本可以正确设置这些变量。注意：每个需要调用英特尔编译器的步骤（如 Configure with CMake 和 Build the project）都必须先 source 这个脚本，因为每个 run 步骤都是在独立的新 shell 中执行的。
指定编译器：在 CMake 配置中，通过 -DCMAKE_C_COMPILER=icx 和 -DCMAKE_CXX_COMPILER=icpx 变量明确指定使用 Intel 的 C 和 C++ 编译器。对于传统的 Makefile 或其他构建系统，也需要相应设置环境变量，如 CC=icx CXX=icpx。
注意事项与排错
Windows 和 macOS：在 Windows 上，安装器通常是 .exe 文件，可能需要不同的静默安装参数 。在 macOS 上，则是 .dmg 文件。其工作流的基本结构与 Linux 类似，但路径和安装命令不同。
环境变量冲突：有用户报告在 Windows 环境下，设置 QT_QPA_PLATFORM="offscreen" 环境变量可能导致 oneAPI 安装程序挂起。如果遇到安装程序无响应的问题，可以检查并移除可能冲突的环境变量 。
编译器选择：英特尔已经将经典的 icc/icpc 编译器过渡到基于 LLVM 的 icx/icpx 编译器。新项目建议使用 icx/icpx 以获得更好的标准兼容性和未来支持。setvars.sh 脚本会同时设置新旧两套编译器的环境。
进阶用法
使用官方的 oneAPI CI Action：英特尔在 oneapi-src/oneapi-ci 仓库中提供了一些示例脚本和可能封装的 GitHub Action。虽然社区提供的直接 Action 可能不多，但可以参考这些官方示例来优化你的工作流 。
结合 ccache 加速编译：你可以结合使用 ccache 来缓存编译结果，进一步加快后续构建的速度。需要注意的是，ccache 对传统的 Intel 经典编译器（如 icc）支持较好，但对新的 icpx 的支持可能仍在完善中，需要根据实际情况测试 。
希望这个详细的指南能帮助你在 GitHub Actions 中顺利配置 Intel 编译器。如果你在具体操作中遇到更具体的问题，例如在特定操作系统上的安装细节，可以随时提出。

问题在于缺少 .pc (pkg-config) 和 .cmake (CMake 配置文件) 文件。这些文件对于库的自动发现至关重要。让我提供针对 CentOS 7 的解决方案：
问题分析
CentOS 7 的包管理确实缺少很多开发文件的配置：
• .pc 文件：pkg-config 用于查找库的编译和链接参数
• .cmake 文件：CMake 用于自动查找库的配置文件
解决方案
方法1：手动指定库路径（最直接）
cd /tmp/tmp.kELYPgeEOp/playscript-cpp

# 手动指定所有库路径，绕过 pkg-config 和 CMake 的自动查找
/home/wdidada/cmake-3.27.1-linux-x86_64/bin/cmake \
  -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_MAKE_PROGRAM=/usr/bin/make \
  -DCMAKE_C_COMPILER=clang \
  -DCMAKE_CXX_COMPILER=clang++ \
  -DCMAKE_CXX_FLAGS="-std=c++11 -I/usr/include -I/usr/local/include" \
  -DCMAKE_EXE_LINKER_FLAGS="-L/usr/lib64 -L/usr/local/lib" \
  -DLLVM_DIR=/usr/lib64/llvm7.0/lib/cmake/llvm \
  -DLLVM_USE_STATIC_LIBS=OFF \

  -G "Unix Makefiles" \

  -B cmake-build-debug-aliyun_wdidada

# 为 LLVM 创建 pkg-config 文件

# 创建 llvm.pc 文件

prefix=/usr/lib64/llvm7.0

Name: LLVM
Description: LLVM compiler framework
Version: 7.0

方法3：创建缺失的 .cmake 文件
# 创建 ANTLR4 的 CMake 配置文件

# ANTLR4 Runtime CMake configuration file

  INTERFACE_INCLUDE_DIRECTORIES "${ANTLR4_RUNTIME_INCLUDE_DIRS}"

message(STATUS "Found ANTLR4 Runtime: ${ANTLR4_RUNTIME_INCLUDE_DIRS}")
EOF
