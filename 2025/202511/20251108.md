学习路径总览：从晶体管到处理器

这系列Lab的最终目标通常是让学生自己设计并实现一个能运行高级语言（如C语言）的完整计算机系统。路径如下：
graph TD
    A[布尔逻辑与数字电路] --> B[处理器微架构设计]
    B --> C[汇编语言编程]
    C --> D[程序编译与链接]
    D --> E[完整计算机系统]

一、计算机体系结构类大作业

这类Lab侧重于设计，即创造一台计算机（或其中的关键部件）。

国外经典课程与Lab

1.  CMU 18-447: Introduction to Computer Architecture
    ◦ 核心Lab：自己设计一个流水线CPU。
    ◦ 内容：使用硬件描述语言（HDL，如Verilog或VHDL），从一个单周期CPU开始，逐步添加指令、解决数据冒险、控制冒险，最终实现一个支持MIPS或RISC-V指令集的五级流水线处理器。这是体系结构课程的巅峰体验。
    ◦ 工具：Verilog/VHDL，仿真工具（如ModelSim），FPGA开发板（用于将设计烧录到可编程芯片上实际运行）。

2.  Berkeley CS61C: Great Ideas in Computer Architecture
    ◦ 核心Lab：从Logisim到CPU。
    ◦ 内容：
        ▪ Lab 1-2：使用图形化数字电路仿真工具Logisim，从与门、或门开始，逐步搭建出ALU（算术逻辑单元）、寄存器等组件。
        ▪ Lab 3-4：将这些组件组合成一个简单的CPU，能够执行有限的指令集。这是对冯·诺依曼体系结构最直观的理解。

    ◦ 特点：非常适合入门，避免了HDL的语法困扰，直击概念本质。

3.  MIT 6.004: Computation Structures
    ◦ 核心Lab：Beta处理器设计。
    ◦ 内容：一个非常经典的系列Lab，学生需要设计一个名为Beta的32位RISC处理器。课程提供了完整的软件工具链，学生设计的CPU最终能运行C程序。
    ◦ 理念：强调计算结构的整体性，涵盖从数字电路到操作系统。

国内经典课程与Lab

1. 清华大学《计算机组成原理》/《计算机体系结构》
    ◦ 核心Lab：硬件CPU设计 与 软件模拟器开发 并重。
    ◦ 内容：
        ▪ 硬件部分：类似国外课程，使用Verilog在FPGA上实现一个支持MIPS或自研指令集的流水线CPU。
        ▪ 软件部分：用C/C++编写一个该CPU的指令集模拟器（Instruction Set Simulator, ISS），可以加载并执行二进制程序。这要求学生深刻理解指令编码、寻址方式等。
    ◦ 特点：要求全面，既懂硬件实现，又懂软件行为。

2. 北京大学/浙江大学/上海交通大学等
    ◦ Lab内容：与清华类似，主流方向都是基于RISC-V指令集设计CPU。RISC-V因其开源、简洁的现代设计，已成为国内外高校教学的首选。
    ◦ 常见任务：完成一个支持RV32I基础整数指令集的处理器，并在此基础上添加乘除法指令、中断异常处理等。

二、汇编语言类大作业
这类Lab侧重于编程，即在已有的计算机（或模拟的计算机）上，用最底层的语言与之对话。

国外经典课程与Lab
1.  CMU 15-213: Introduction to Computer Systems (CS:APP)
    ◦ 这是全球最著名的计算机系统入门课，其Lab是经典中的经典。
    ◦ 核心Lab：
        ▪ Data Lab： 纯位操作，用极其有限的运算符完成复杂的逻辑和算术功能，深刻理解数据的机器级表示。
        ▪ Bomb Lab： “拆炸弹”。通过反汇编和GDB调试，分析一个二进制炸弹程序，输入正确的字符串来“拆除”每一阶段的炸弹。极富趣味性，是逆向工程的入门神作。
        ▪ Attack Lab： 缓冲区溢出攻击。利用程序漏洞，通过精心构造的输入，改变程序执行流，执行自己的代码。这是理解栈帧布局和系统安全性的绝佳方式。
        ▪ Architecture Lab： 优化程序的性能，理解CPU流水线、分支预测等对程序性能的影响。

2.  Stanford CS107: Computer Organization & Systems
    ◦ 核心Lab：汇编代码的阅读、编写和调试。
    ◦ 内容：使用GCC和GDB，学习x86-64汇编。Lab包括分析编译器生成的汇编代码，编写一些小的汇编函数，以及调试复杂的底层程序。

国内经典课程与Lab
国内的汇编语言课程大作业与CS:APP的思路非常相似，但可能更侧重于：

1.  MASM/TASM环境下的DOS汇编编程
    ◦ 内容：虽然较老，但仍是很多学校的起点。包括：
        ▪ 编写简单的I/O程序（如输入姓名、输出欢迎信息）。
        ▪ 实现数学运算（如斐波那契数列、阶乘）。
        ▪ 图形模式下的编程（如绘制图形、动画）。
    ◦ 目标：理解实模式下的内存分段、中断调用等概念。

2.  Linux下的GAS（AT&T语法）或NASM（Intel语法）汇编
    ◦ 内容：与现代课程接轨。
        ▪ 编写函数，与C语言进行混合编程。
        ▪ 理解系统调用（System Call）的实现。
        ▪ 进行简单的性能优化实验。

总结与对比
特征 国外顶尖课程（如CMU, MIT） 国内顶尖课程（如清华，北大）
核心目标 构建“计算机系统”的整体世界观，从程序到电路 深入理解计算机组成与工作原理，打下扎实基础
Lab特点 趣味性强、故事性完整（如拆炸弹）、强调逆向工程和系统安全 系统性、工程性强，要求从硬件到软件的全栈实现
技术栈 x86-64, C, GDB, 硬件HDL MIPS/RISC-V, C/Verilog， 自研模拟器
侧重点 理解、分析、优化一个现有系统 设计、实现、构建一个新系统

实践示例：C与NASM混合编程

下面是一个简单的示例项目结构，你可以基于这个模板开始：

项目结构


c_asm_mixed/
├── Makefile
├── main.c
├── math_ops.asm
└── syscalls.asm


main.c - C主程序
#include <stdio.h>

// 声明外部汇编函数
extern int add_numbers(int a, int b);
extern void print_message(const char* msg);

int main() {
    int result = add_numbers(10, 20);
    printf("Result from assembly: %d\n", result);
    
    print_message("Hello from C and Assembly!");
    return 0;
}


math_ops.asm - 数学运算汇编函数
section .text
global add_numbers

add_numbers:
    push rbp
    mov rbp, rsp
    
    ; 参数在 edi 和 esi 中 (System V AMD64 ABI)
    mov eax, edi
    add eax, esi
    
    pop rbp
    ret


syscalls.asm - 系统调用封装
section .text
global print_message

print_message:
    push rbp
    mov rbp, rsp
    
    ; 系统调用: write(1, msg, len)
    mov rax, 1          ; sys_write
    mov rdi, 1          ; stdout
    mov rsi, [rbp+16]   ; 消息地址 (第一个参数)
    mov rdx, 13         ; 消息长度
    syscall
    
    pop rbp
    ret


Makefile - 构建文件
CC = gcc
ASM = nasm
CFLAGS = -Wall -g
ASMFLAGS = -f elf64

TARGET = mixed_program
SOURCES_C = main.c
SOURCES_ASM = math_ops.asm syscalls.asm
OBJECTS = $(SOURCES_C:.c=.o) $(SOURCES_ASM:.asm=.o)

all: $(TARGET)

$(TARGET): $(OBJECTS)
	$(CC) $(CFLAGS) -o $@ $^

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

%.o: %.asm
	$(ASM) $(ASMFLAGS) $< -o $@

clean:
	rm -f $(OBJECTS) $(TARGET)

.PHONY: all clean


学习建议
1. 从简单开始: 先掌握基本的系统调用（如write、exit）
2. 理解调用约定: 重点学习System V AMD64 ABI调用约定
3. 使用调试器: 熟练使用GDB调试汇编代码
4. 性能测试: 编写基准测试对比C和汇编版本的性能
5. 阅读源码: 多研究上述仓库中的高质量代码

这些资源涵盖了从入门到进阶的所有内容，建议按照顺序逐步学习实践。

你遇到的正是 GitHub Actions 上 “只有 ubuntu-latest + clang 才会挂” 的经典陷阱：

```
undefined reference to `yylex'
undefined reference to `yyparse'
```

根本原因：  
Ubuntu 22.04 的 `libfl-dev` 包里，clang 默认找不到 `liby.so`！

- GCC 链接时会自动搜索 `/usr/lib/x86_64-linux-gnu/` → 找到 `libfl.so` 和 `liby.so` → 成功  
- Clang 默认只搜索 `/usr/lib` 和 `/lib`，不搜索 `/usr/lib/x86_64-linux-gnu/` → `liby.so` 找不到 → 链接失败

### 100% 修复方案（只改 1 行 CMake + 1 行 workflow）

#### 1. CMakeLists.txt 加上这 3 行（放在 `target_link_libraries` 前面）
```cmake
# 解决 ubuntu-clang 找不到 liby.so 的终极方案
if(CMAKE_C_COMPILER_ID MATCHES "Clang" AND CMAKE_SYSTEM_NAME STREQUAL "Linux")
    # 强制告诉 clang 去 gcc 的三元组目录找库
    link_directories(/usr/lib/x86_64-linux-gnu)
    # 或者更狠：直接写绝对路径
    # target_link_libraries(json2xmlxml2json /usr/lib/x86_64-linux-gnu/libfl.so /usr/lib/x86_64-linux-gnu/liby.so)
endif()
```

#### 2. 完整终极版 CMakeLists.txt（复制粘贴就过）
```cmake
cmake_minimum_required(VERSION 3.16)
project(JsonXmlConverter LANGUAGES C)

find_package(FLEX REQUIRED)
find_package(BISON REQUIRED)

add_definitions(-DYYDEBUG=1)

FLEX_TARGET(JsonScanner json.l ${CMAKE_CURRENT_BINARY_DIR}/json.lex.c)
FLEX_TARGET(XmlScanner  xml.l ${CMAKE_CURRENT_BINARY_DIR}/xml.lex.c)
BISON_TARGET(JsonParser json.y ${CMAKE_CURRENT_BINARY_DIR}/json.tab.c DEFINES_FILE ${CMAKE_CURRENT_BINARY_DIR}/json.tab.h)
BISON_TARGET(XmlParser  xml.y ${CMAKE_CURRENT_BINARY_DIR}/xml.tab.c DEFINES_FILE ${CMAKE_CURRENT_BINARY_DIR}/xml.tab.h)

ADD_FLEX_BISON_DEPENDENCY(JsonScanner JsonParser)
ADD_FLEX_BISON_DEPENDENCY(XmlScanner XmlParser)

add_executable(json2xmlxml2json
    main.c
    ${FLEX_JsonScanner_OUTPUTS}
    ${FLEX_XmlScanner_OUTPUTS}
    ${BISON_JsonParser_OUTPUTS}
    ${BISON_XmlParser_OUTPUTS}
)

target_include_directories(json2xmlxml2json PRIVATE ${CMAKE_CURRENT_BINARY_DIR})

# ============ 关键修复区 ============
if(APPLE)
    target_link_libraries(json2xmlxml2json
        /opt/homebrew/opt/flex/lib/libfl.dylib
        /opt/homebrew/opt/bison/lib/liby.a
    )
elseif(UNIX)  # Linux
    # 解决 ubuntu-clang 找不到 liby.so 的问题
    if(CMAKE_C_COMPILER_ID MATCHES "Clang")
        link_directories(/usr/lib/x86_64-linux-gnu)
    endif()
    
    target_link_libraries(json2xmlxml2json fl y)
endif()
```
