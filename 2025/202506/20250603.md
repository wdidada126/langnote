# 20250603
安全测试：使用安全工具（如 OWASP ZAP 或 Burp Suite）检查页面是否存在 XSS 漏洞。

你提到：

- 使用的是 Spring Boot 2.7.14
- 已按推荐配置设置了 `server.error.include-stacktrace=never`
- 但 HTTP 400 错误页面仍然显示了 Java 异常堆栈信息

这个问题在 Spring Boot 中确实存在一些特殊情况，尤其是在处理 非由 Controller 抛出的异常（如请求解析错误、URL 格式非法等）时。

---

## 🚫 为什么 `server.error.include-stacktrace=never` 没有效果？

### 原因说明：

Spring Boot 的 `server.error.include-stacktrace=never` 只对以下情况生效：

✅ 在你的应用中通过代码抛出的异常（比如 Controller 层、Service 层）

❌ 对于容器底层抛出的异常（如 URL 解析失败、协议错误、非法字符等），Spring Boot 无法控制这些错误的展示方式。

例如：

```
java.lang.IllegalArgumentException: Invalid character found in the request target
```

这类异常是由 Servlet 容器（TongWeb / Tomcat） 抛出的，不是 Spring MVC 管理的异常流程，因此 Spring Boot 的全局异常处理器和 `ErrorController` 都不会介入。

---

## ✅ 正确解决方法

要屏蔽这类异常的堆栈输出，你需要从 容器级别 和 错误页面配置 两方面入手。

---

### ✅ 方法一：配置自定义错误页面（推荐）

#### 1. 修改 `web.xml` 或 `application.properties` 设置错误页面

如果你是使用嵌入式的 Tomcat/TongWeb，可以在 `application.properties` 中设置：

```properties
spring.mvc.throw-exception-if-no-handler-found=false
spring.boot.admin.client.enabled=false
```

然后创建一个实现 `ErrorController` 的类来接管 `/error` 路径：

#### 2. 自定义 ErrorController 示例：

```java
import org.springframework.boot.web.servlet.error.ErrorAttributes;
import org.springframework.boot.web.servlet.error.ErrorController;
import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.RequestMapping;

import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.util.Map;

@Controller
public class CustomErrorController implements ErrorController {

    private final ErrorAttributes errorAttributes;

    public CustomErrorController(ErrorAttributes errorAttributes) {
        this.errorAttributes = errorAttributes;
    }

    @RequestMapping("/error")
    public String handleError(HttpServletRequest request, HttpServletResponse response) {
        // 获取错误状态码
        Integer statusCode = (Integer) request.getAttribute("javax.servlet.error.status_code");

        if (statusCode != null && statusCode == 400) {
            return "error/400"; // 返回你自定义的 HTML 页面名称（如 Thymeleaf 模板）
        }

        return "error/generic";
    }

    @Override
    public String getErrorPath() {
        return "/error";
    }
}
```

#### 3. 创建 Thymeleaf 页面 `/resources/templates/error/400.html`

```html
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
    <title>Bad Request</title>
</head>
<body>
<h1>400 - Bad Request</h1>
<p>The server could not understand the request due to invalid syntax.</p>
</body>
</html>
```

这样可以确保即使出现 400 错误，也不会暴露堆栈信息。

---

### ✅ 方法二：禁用容器默认的错误报告（适用于 TongWeb）

在 `server.xml` 或相关配置中添加或修改 `ErrorReportValve`：

```xml
<Valve className="org.apache.catalina.valves.ErrorReportValve"
       showReport="false"
       showServerInfo="false"/>
```

这将关闭容器自动输出的堆栈信息。

---

### ✅ 方法三：设置日志级别为 ERROR（可选）

如果你不想让这些异常写入日志文件，也可以调整日志级别（不推荐完全关闭，除非你知道后果）：

```yaml
# application.yml
logging:
  level:
    org.apache.coyote.http11: ERROR
    com.tongweb.connector.http11: ERROR
```

## 🔍 总结

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| `server.error.include-stacktrace=never` 不生效 | 请求解析错误发生在容器层，Spring Boot 无法控制 | 使用自定义 `ErrorController` + 自定义错误页面 |
| 客户端看到堆栈信息 | 默认容器会打印详细错误页 | 关闭 `ErrorReportValve.showReport` |
| 请求含非法字符导致 400 | `[test]` 是非法参数格式 | 客户端应正确编码 URL 参数 |

---

## 🧪 补充建议

- 生产环境务必避免暴露服务器版本号、堆栈信息等敏感内容。
