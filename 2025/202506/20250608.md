在C/C++中动态加载共享库（.so文件）和静态链接库（.a文件）是两个不同的概念。对于工业级应用，通常更关注的是如何安全、高效地动态加载.so库文件，并执行其中的代码。下面介绍一些常用的开源方案和技术来实现这一目标。

### 动态加载 .so 文件

在C/C++中，可以使用`dlopen` API来动态加载.so文件。这是一组POSIX标准定义的函数，允许程序在运行时加载并调用共享库中的函数。以下是一个简单的例子展示如何使用这些API：

```c
#include <dlfcn.h>
#include <stdio.h>

int main() {
    void *handle;
    double (*cosine)(double);
    char *error;

    // 打开共享库
    handle = dlopen("libm.so", RTLD_LAZY);
    if (!handle) {
        fprintf(stderr, "%s\n", dlerror());
        return 1;
    }

    // 清除之前的错误
    dlerror();

    // 获取符号（函数）
    *(void ) (&cosine) = dlsym(handle, "cos");

    if ((error = dlerror()) != NULL)  {
        fprintf(stderr, "%s\n", error);
        return 1;
    }

    // 调用从共享库中获取的函数
    printf("%f\n", (*cosine)(2.0));

    // 关闭共享库
    dlclose(handle);
    return 0;
}
```

在这个例子中，我们首先使用`dlopen`打开共享库，然后通过`dlsym`查找特定的函数，最后调用这个函数。

### 静态链接库 (.a 文件)

对于`.a`文件，它们是在编译期间被静态链接到你的应用程序中的，因此不涉及运行时动态加载的概念。如果你需要在程序运行时选择性地加载功能模块，你应该考虑使用共享库（.so文件）而不是静态库（.a文件）。

### 开源方案

虽然`dlopen`等API提供了基本的功能，但在实际的工业级应用中，你可能需要更加健壮和功能丰富的解决方案。这里有几个推荐的开源库：

- Boost.DLL: Boost库的一部分，提供了一种跨平台的方法来处理动态链接库。它简化了库的加载、符号解析以及异常安全的资源管理。
  
- Qt's Plugin System: 如果你正在开发一个基于Qt的应用程序，Qt提供了一个强大的插件系统，可以很容易地加载和使用动态库作为插件。

- Google's Bazel Build System: 尽管Bazel本身不是一个直接用于动态加载库的工具，但它提供了一套机制来管理和构建复杂的项目结构，包括动态库的支持。
