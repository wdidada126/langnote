std::print 还不是 C++23 的正式标准功能！

虽然 C++23 引入了 std::print，但目前主流编译器（如 MSVC、GCC、Clang）尚未完全支持这一特性。特别是你在使用的是 MSVC Visual Studio 2022 (v14.38)，它还不支持 std::print。



在 Oracle SQL 中，如果你的 `UPDATE` 语句中某个字段值包含特殊字符 `&`（例如字符串 `'Tom&Jerry'`），你需要特别处理它，否则：

- 在 SQL*Plus 或 PL/SQL Developer 等工具中执行时，Oracle 会把 `&` 当作变量替换符（variable substitution）来处理；
- 导致报错或提示输入变量值，从而阻止语句正常执行。


正确处理方式

方法一：使用 `q'[]'` 字符串引用 + 转义（推荐）
如果你直接写 SQL 脚本（如 `.sql` 文件），可以使用 Oracle 的 `q'[...]'` 引用方式，避免对 `&` 进行变量替换：

```sql
UPDATE your_table SET your_column = q'[Tom&Jerry]' WHERE id = 1;
```

`q'[...]'` 是 Oracle 提供的一种“带引号文字分隔符”，允许你在字符串中包含特殊字符而无需转义。


方法二：关闭变量替换（适用于 SQL*Plus、脚本）

如果你在 SQL*Plus 或 SQLcl 中运行脚本，可以在脚本顶部加上：

```sql
SET DEFINE OFF;
```

这样可以禁用 `&` 变量替换功能，之后你可以直接使用：

```sql
UPDATE your_table
SET your_column = 'Tom&Jerry'
WHERE id = 1;
```

注意：这个设置只影响当前会话或脚本。

方法三：使用绑定变量（适用于 PL/SQL、程序中调用）

如果你是在程序（Java、Python、C#、PL/SQL 等）中调用 SQL，建议使用参数化查询（绑定变量），就不会涉及 `&` 替换的问题。

示例（PL/SQL）：

```sql
DECLARE
    v_value VARCHAR2(100) := 'Tom&Jerry';
BEGIN
    UPDATE your_table
    SET your_column = v_value
    WHERE id = 1;
    COMMIT;
END;
```

或者 Java 使用 JDBC、Python 使用 cx_Oracle 时，也应使用参数占位符而不是拼接 SQL 字符串。


示例演示

假设表结构如下：

```sql
CREATE TABLE test_table (
    id NUMBER PRIMARY KEY,
    content VARCHAR2(100)
);
```

插入含 `&` 的数据：

```sql
SET DEFINE OFF;

UPDATE test_table
SET content = 'Tom&Jerry'
WHERE id = 1;
```

或者：

```sql
UPDATE test_table
SET content = q'[Tom&Jerry]'
WHERE id = 1;
```

| 方法 | 场景 | 是否推荐 |
|------|------|----------|
| `q'[Tom&Jerry]'` | SQL 脚本、PL/SQL Developer 等 |  推荐 |
| `SET DEFINE OFF` | SQL*Plus / SQLcl 执行脚本 |  推荐 |
| 绑定变量（程序中使用） | Java / Python / PL/SQL |  最佳实践 |
