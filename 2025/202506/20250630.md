## 四、源码详解

### 1️⃣ `boot.asm` - 启动扇区（512 字节）

```nasm
[BITS 16]
[ORG 0x7C00]

start:
    cli                     ; 关中断
    xor ax, ax
    mov ds, ax
    mov es, ax
    mov ss, ax
    mov sp, 0x7C00          ; 设置栈指针

    ; 加载内核到 0x1000:0x0000
    mov ah, 0x02            ; BIOS 读扇区
    mov al, 4               ; 读取4个扇区
    mov ch, 0               ; 柱面0
    mov cl, 2               ; 扇区2
    mov dh, 0               ; 磁头0
    mov bx, 0x1000          ; 目标地址段
    mov es, bx
    xor bx, bx              ; 偏移0
    int 0x13

    ; 跳转到内核
    jmp 0x1000:0x0000

times 510 - ($ - $$) db 0
dw 0xAA55
```



### 2️⃣ `pv.s` - 实现 P/V 操作的汇编函数

```nasm
[BITS 32]

section .text

global p_semaphore
global v_semaphore

; void p_semaphore(int* lock)
p_semaphore:
    push ebp
    mov ebp, esp

.retry:
    mov eax, [ebp + 8]      ; lock 地址
    xor ecx, ecx            ; ecx = 0 （期望值）
    mov edx, 1              ; edx = 1 （新值）
    lock cmpxchg [eax], edx ; 如果 *eax == ecx，则设置为 edx
    jnz .retry              ; 否则继续重试

    pop ebp
    ret

; void v_semaphore(int* lock)
v_semaphore:
    push ebp
    mov ebp, esp

    mov eax, [ebp + 8]
    mov dword [eax], 0      ; 释放锁，设为0

    pop ebp
    ret
```



### 3️⃣ `kernel.c` - 内核主程序（C 语言）

```c
void kmain(void) {
    char* video = (char*)0xb8000;
    int lock = 0;

    // 第一个进程尝试获取锁
    p_semaphore(&lock);
    video[0] = 'A';
    video[1] = 0x0f;

    // 第二个进程尝试获取锁
    p_semaphore(&lock);
    video[2] = 'B';
    video[3] = 0x0f;

    // 死循环防止返回
    while (1);
}
```

> 注意：实际应使用多线程或定时器实现并发，这里简化演示。



### 4️⃣ `linker.ld` - 链接脚本

```ld
ENTRY(kmain)

SECTIONS
{
    . = 0x100000;

    .text : {
        *(.text)
    }

    .data : {
        *(.data)
    }

    .bss : {
        *(.bss)
    }
}
```



### 5️⃣ `Makefile` - 编译构建脚本

```makefile
CC = i686-elf-gcc
AS = nasm
LD = i686-elf-ld

all: os-image

boot.o: boot.asm
    $(AS) -f bin $< -o $@

kernel.o: kernel.c
    $(CC) -m32 -ffreestanding -c $< -o $@

pv.o: pv.s
    $(CC) -m32 -ffreestanding -c $< -o $@

kernel.bin: linker.ld boot.o kernel.o pv.o
    cat boot.o kernel.o > kernel.bin

os-image: kernel.bin
    dd if=kernel.bin of=os-image.img bs=512 count=2880

run:
    qemu-system-i386 -fda os-image.img

clean:
    rm -f *.o *.bin *.img
```



### 6️⃣ `run_qemu.sh`（可选）

```bash
#!/bin/bash
qemu-system-i386 -fda os-image.img
```

蔗糖和白砂糖密切相关，但不完全等同，以下是两者的关系：

#### 成分角度
- 蔗糖：是一种天然存在的双糖，分子式为C₁₂H₂₂O₁₁，由一分子葡萄糖和一分子果糖组成，广泛存在于甘蔗、甜菜等植物中。
- 白砂糖：主要成分是蔗糖，纯度可达99.5%以上，是通过将甘蔗或甜菜榨汁，经过过滤、澄清、蒸发、结晶、脱色、干燥等多道工序加工而成的。

#### 生产工艺角度
- 蔗糖：从植物中提取汁液后，经过初步浓缩等处理即可得到不同形态的蔗糖产品。
- 白砂糖：在蔗糖的基础上，进行了更精细的加工，包括脱色、多次结晶等步骤，去除了更多的杂质和色素，得到了颗粒均匀、颜色洁白的结晶状产品。

#### 外观与性质角度
- 蔗糖：根据来源和加工方式不同，外观可能有所差异，如原蔗糖可能呈淡黄色，晶体相对较大且不规则。
- 白砂糖：颗粒细小均匀，呈白色结晶状，质地松散，甜味纯正。

#### 用途角度
- 蔗糖：除食用外，在一些工业领域如化工原料等方面也有应用。
- 白砂糖：因其纯度高、色泽洁白、甜味纯正，常用于烘焙食品、饮料、糖果等的制作，能增加产品的甜味和光泽。

综上所述，蔗糖是白砂糖的主要成分，但白砂糖是经过精炼加工的蔗糖产品，具有更高的纯度和特定的外观、性质。在日常生活中，白砂糖是最常见的蔗糖制品，广泛用于食品加工和烹饪。



在64位系统中，C++指针通常占用8个字节。这是因为：

#### 寻址范围需求
- 64位系统的地址总线宽度为64位，理论上可以寻址$2^{64}$个内存地址。
- 每个内存地址需要64位来表示，即8个字节。

#### 指针的作用
- 指针用于存储内存地址，以便访问对应的数据。
- 为了满足寻址整个内存空间的需求，指针本身需要足够大，能够容纳最大的地址值。

#### 实际应用
- 无论是`int*`、`char*`还是`void*`等类型的指针，在64位系统中都占用8个字节。
- 这使得指针能够唯一地标识64位系统中任意位置的内存。

示例：

```cpp
#include <iostream>
using namespace std;

int main() {
    int* ptr;
    cout << "指针大小：" << sizeof(ptr) << "字节" << endl; // 输出：8
    return 0;
}
```

注意事项：

- 指针大小与数据类型无关：指针的大小仅取决于系统的位数，与指针所指向的数据类型大小无关。
- 跨平台编程：在编写跨平台的C++程序时，需要注意指针大小的差异。可以使用`sizeof`运算符在运行时确定指针的大小，或者使用`<cstdint>`头文件中的`intptr_t`和`uintptr_t`类型，它们分别是带符号和无符号的整数类型，其大小足以存储指针的值。

综上所述，在64位系统中，C++指针占用8个字节，以充分利用系统的寻址能力。

如何在Drogon中使用C++14/17特性
在Drogon中，开发者可以充分利用C++14和C++17带来的便利。例如，通过lambda表达式的使用，可以轻松定义事件处理器或路由回调函数，使得代码逻辑更加清晰直观。下面是一个简单的示例，展示了如何使用lambda函数来响应HTTP请求：

```cpp
#include <drogon/drogon.h>
// 定义一个简单的 GET 请求处理器
app.get("/hello", [](const HttpRequestPtr &req) {
    return HttpResponse::newHttpResponse()
        ->setBody("Hello, World!")
        ->setStatusCode(k200OK);
});
```

在这个例子中，我们使用了一个lambda 函数来处理所有指向 /hello 路径的 GET 请求。当请求到达时，函数会生成一个新的 HTTP 响应对象，并设置响应体和状态码。这样的编写方式不仅简洁，而且易于理解和维护。

此外，Drogon 还支持使用 C++17 的结构化绑定来简化变量声明，例如在处理数据库查询结果时：

```cpp
auto [rows, err] = db->execSql("SELECT * FROM users WHERE id = ?", userId);
if (err) {
    // 处理错误情况
} else {
    for (const auto &[id, name, email] : rows) {
        // 使用结构化绑定直接访问查询结果
    }
}
```

通过这种方式，我们可以直接获取查询结果中的每一项，而无需显式地遍历每一列，大大减少了代码量，提高了开发效率。Drogon 对 C++14/17 特性的支持，使得开发者能够在构建高性能 Web 应用的同时，享受现代 C++ 带来的诸多便利。
