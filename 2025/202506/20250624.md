vtable.md

`-fdump-class-hierarchy` 是 **GCC 编译器** 提供的一个调试选项，用于 **输出 C++ 类的继承结构和虚函数表（vtable）信息**。这个选项对于理解多态、虚函数调用、类布局等底层机制非常有用。

---

## ✅ 作用总结：

| 参数 | 作用 |
|------|------|
| `-fdump-class-hierarchy` | 让 GCC 输出所有类的继承关系和 vtable 信息到一个 `.class` 文件中 |

---

## 🧾 输出内容包含：

1. **类的继承层次**
2. **每个类的虚函数表（vtable）结构**
3. **虚函数在 vtable 中的位置**
4. **RTTI（运行时类型信息）**
5. **虚基类偏移量（适用于虚继承）**

---

## 🛠️ 使用方法

### 示例代码：`main.cpp`

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void speak() { cout << "Animal" << endl; }
    virtual ~Animal() {}
};

class Dog : public Animal {
public:
    void speak() override { cout << "Dog" << endl; }
};

int main() {
    Animal* a = new Dog();
    a->speak();
    delete a;
    return 0;
}
```

### 编译命令：

```bash
g++ -fdump-class-hierarchy main.cpp -o main
```

编译完成后，会生成一个文件，比如：

```
main.cpp.002i.class
```

## 📌 说明关键字段含义

| 字段 | 含义 |
|------|------|
| `Vtable for Animal` | 表明这是类 `Animal` 的虚函数表 |
| `offset 0, 8, 16...` | 虚函数表中的偏移位置（以字节为单位） |
| `Animal::speak()` | 函数地址或名称，表示该偏移处是哪个虚函数 |
| `vptr=...` | 对象内部的虚指针指向的 vtable 地址 |
| `base size` | 基类部分的大小 |
| `RTTI info` | 运行时类型信息（typeinfo）地址，用于支持 `dynamic_cast` 和 `typeid` |

## 🔍 **vptr 和 vtable 的区别**

| 术语 | 中文名 | 含义 |
|------|--------|------|
| `vtable` | 虚函数表（virtual table） | 编译器为每个有虚函数的类生成的一张表，里面存放着虚函数的地址、RTTI 等信息 |
| `vptr`   | 虚函数指针（virtual pointer） | 每个对象内部的一个隐藏指针，指向它所属类的 `vtable` |

---

## 🧠 它们的关系

你可以把它们想象成这样的关系：

```
[ Dog 对象 ]
│
├── vptr → ──┐
│           │
└───────────┘
             ↓
        [ vtable for Dog ]
        ├──── speak()       ← Dog::speak()
        ├──── ~Dog()         ← 析构函数
        └──── typeinfo       ← RTTI 类型信息
```

- **vptr** 是一个指针，存在于每一个对象中。
- **vtable** 是一张全局共享的表格，所有该类的对象都指向同一个 vtable。

---

## 🛠️ 在构造函数中发生了什么？

当你创建一个对象时，比如：

```cpp
Dog dog;
```

编译器会自动调用构造函数，在构造函数执行前或执行中，会完成以下关键操作：

### ✅ 步骤 1：分配内存空间
为对象分配足够的内存（包括 `vptr` 所占的空间）。

### ✅ 步骤 2：设置 vptr
在构造函数体执行之前，编译器会插入代码，将当前类的 `vtable` 地址写入对象头部的 `vptr`。

例如：

```cpp
dog.vptr = &vtable_for_Dog;
```

> 这是一个伪代码表示，实际上这是由编译器自动处理的底层机制。

### ✅ 步骤 3：执行构造函数体
执行你写的构造函数逻辑（如初始化成员变量等）。

## 🔄 多态调用过程回顾

以如下代码为例：

```cpp
Animal* animal = new Dog();
animal->speak(); // 多态调用
```

执行流程如下：

1. `animal` 是一个指向 `Dog` 对象的指针。
2. 通过 `animal` 取出其头部的 `vptr`。
3. 根据 `vptr` 找到 `vtable`。
4. 从 `vtable` 中取出 `speak()` 函数的地址。
5. 调用 `Dog::speak()`。

对应的汇编大致如下（简化版）：

```asm
mov     rax, QWORD PTR [animal] ; 获取 vptr
mov     rdx, QWORD PTR [rax]    ; 取出第一个虚函数地址（speak）
mov     rdi, animal             ; 设置 this 指针
call    rdx                     ; 调用 Dog::speak()
```

---

## ⚠️ 注意：构造函数中不能多态！

虽然构造函数中可以调用虚函数，但此时 **多态是“静态”的**。因为：

- 在构造 `Dog` 的时候，先调用 `Animal` 的构造函数。
- 在 `Animal` 构造函数中调用 `speak()`，此时 `vptr` 指向的是 `Animal` 的 `vtable`，而不是 `Dog` 的。
- 因为 `Dog` 还没有完全构造完毕，所以编译器不会让虚函数调用动态绑定到子类。

示例：

```cpp
class Animal {
public:
    Animal() { speak(); }  // 构造函数中调用虚函数
    virtual void speak() { cout << "Animal" << endl; }
};

class Dog : public Animal {
public:
    void speak() override { cout << "Dog" << endl; }
};

int main() {
    Dog dog;  // 输出的是 "Animal"，不是 "Dog"
}
```

输出结果是：

```
Animal
```

这说明：
> **在构造函数中调用虚函数，不会发生多态行为，只会调用当前类的版本。**

## 📌 总结对比表

| 特性 | vtable | vptr |
|------|--------|------|
| 存储位置 | 全局数据段（只读） | 对象内存起始处 |
| 生命周期 | 程序运行期间存在 | 随对象生命周期而存在 |
| 数量 | 每个类一个 vtable | 每个对象一个 vptr |
| 修改时机 | 编译期确定 | 构造函数和析构函数中设置 |
| 作用 | 存放虚函数地址、RTTI 等信息 | 指向当前对象的 vtable |
| 是否可见 | 不可直接访问 | 不可见（编译器自动管理） |

## 🧪 小实验：查看 vptr 的值（不推荐生产使用）

虽然 `vptr` 是隐藏的，但我们可以通过强制类型转换访问它：

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    virtual void foo() {}
};

int main() {
    Base b;
    void** vptr = *(void***)(&b);  // 取出 vptr
    void* vtable = vptr[0];        // vtable 第一个槽位通常是 RTTI 信息
    cout << "vptr: " << vptr << endl;
    cout << "vtable: " << vtable << endl;
}
```

注意：这种方式仅用于学习目的，不要用于生产环境！
