OceanBase 支持的索引方式（Index Algorithm/Organization），而不是广义的索引类型（如唯一索引、全文索引等）。我来明确区分并回答：

### OceanBase 支持的索引方式（底层组织结构/算法）
OceanBase 用户创建索引时，底层支持的索引组织方式（类似 MySQL 的 USING BTREE/HASH）如下（截至 2025年12月最新版本 4.3.x / 4.4.x）：

1. B+Tree（默认且唯一用户可直接指定的普通索引方式）  
   - 所有普通二级索引（非唯一/唯一）、主键（聚簇索引）默认且强制使用 B+Tree 结构。  
   - 创建语法中无需指定（也没有 USING 选项），直接 `CREATE INDEX idx_name ON table(col)` 就是 B+Tree。  
   - 支持范围查询、排序、前缀索引、多列索引等。

2. Hash（内部使用，非用户直接创建）  
   - OceanBase 不支持 用户显式创建 Hash 索引（不像 MySQL MEMORY 引擎的 USING HASH）。  
   - 但在某些场景下内部会使用 Hash 结构加速：  
     - 内存表（MEMTABLE）中单行 GET 操作可能使用 Hash 加速。  
     - 分区表的分区键哈希分区（Hash Partitioning）内部使用哈希算法。  
     - 等值查询优化器可能利用 Hash Join 等，但不是索引本身是 Hash。

3. 其他专用索引的底层方式  
   - 全文索引（Full-Text Index）：底层使用倒排索引（Inverted Index） + 分词器（IK 分词等），不是 B+Tree 或 Hash。  
   - 向量索引（Vector Index）：底层支持 IVF（Inverted File） 和 HNSW（Hierarchical Navigable Small World） 两种近似最近邻（ANN）算法，用于向量相似度搜索。  
   - 多值索引（Multi-Value Index）：底层基于 B+Tree 扩展，实现对 JSON 数组等的多值提取索引。

### 总结表（索引方式视角）

| 索引方式          | 是否用户可直接创建 | 支持情况                  | 备注 |
|-------------------|-------------------|---------------------------|------|
| B+Tree       | 是（默认）        | 全面支持（所有普通索引）  | 主力方式 |
| Hash         | 否                | 仅内部优化使用            | 无 USING HASH 语法 |
| Inverted Index | 否（通过 FULLTEXT 创建） | 全文索引专用             | 分词 + 倒排 |
| IVF / HNSW   | 否（通过 VECTOR INDEX 创建） | 向量索引专用            | AI 场景 |
| R-Tree 等    | 否                | 当前不支持空间索引        | - |

所以，OceanBase 在用户可控的索引方式上，目前只有 B+Tree 一种（普通索引默认就是它）。其他如 Hash、IVF、HNSW 等都是专用索引内部实现或系统优化，无法像 MySQL MEMORY 那样显式指定 USING HASH。
