### 最新SQL Query Planning算法列表（基于2023-2025年研究）

当前SQL查询规划（Query Planning/Optimization）领域的主要趋势是机器学习增强的优化器（Learned Query Optimizers），包括基数估计（Cardinality Estimation）、成本模型（Cost Models）和计划枚举（Plan Enumeration）。传统成本-based优化器仍在演进，但学习方法正逐步解决传统方法的基数估计误差和计划空间爆炸问题。同时，自适应查询处理（Adaptive Query Processing）和LLM-based方法成为热点。

以下是近年来（2023-2025）代表性规划算法/框架的列表及其简介（按类别分组）：

#### 1. Learned Query Optimizers（学习型查询优化器）
- Lero (Learning-to-Rank Query Optimizer, 2023)  
  使用学习到排序（Learning-to-Rank）模型直接对计划进行排名，避免传统成本模型的误差，支持高效计划选择。
  
- LEON (ML-Aided Query Optimization Framework, 2023)  
  机器学习辅助的框架，整合卡迪纳尔估计和成本预测，提高复杂查询的计划质量。
  
- LOGER (Learned Optimizer for Efficient and Robust Plans, 2023)  
  生成高效且鲁棒的执行计划，结合深度学习处理计划空间。
  
- GLO (Generalized Learned Query Optimization, 2024)  
  泛化学习优化器，支持跨不同工作负载和数据库的迁移。
  
- Delta (Learned Mixed Cost-based Framework, 2025)  
  混合价值-based和成本-based方法，两阶段规划（价值生成 + 成本选择），平衡训练成本和准确性。
  
- Reqo (Robust and Explainable Cost Model, 2025)  
  鲁棒且可解释的成本模型，使用ML处理树状计划表示，提高预测可靠性。

#### 2. Learned Cost Models（学习型成本模型）
- Learned Cost Models for Batch to Streaming (2025)  
  从批处理扩展到流系统的学习成本模型，支持实时查询优化。
  
- Execution Plan Features-based Cost Estimation (2025)  
  使用真实执行计划特征（如PostgreSQL EXPLAIN）训练ML模型，直接预测运行时而非抽象成本。

#### 3. Adaptive Query Processing（自适应查询处理）
- Simple Adaptive vs. Learned Optimizers (2023)  
  比较简单自适应方法（如中途重优化）和学习优化器，发现简单自适应在许多场景下更鲁棒。
  
- POLAR (Plans of Least Resistance, 2024)  
  非侵入式自适应连接顺序选择，低开销集成到现有系统中，在执行中动态调整计划。

#### 4. LLM-based Query Planning（大语言模型辅助）
- LLM for Direct Plan Generation (2025, e.g., Can LLMs Be Query Optimizers?)  
  使用LLM（如GPT系列）直接从SQL生成执行计划，或翻译成多模态计划（关系运算 + UDF），减少枚举开销。
  
- CAESURA (2024)  
  LLM将自然语言查询转为混合计划，支持Python UDF等扩展。

#### 5. 其他新兴方法
- BASE (Bridging Cost and Latency, 2023)  
  桥接成本和延迟的优化，平衡估计准确性和规划速度。
  
- Hybrid Learned + Traditional (多种2024-2025论文)  
  结合传统动态规划与ML（如零样本成本预测），提高泛化能力。

这些算法主要解决传统规划（如System R风格的动态编程）的痛点：基数估计不准、成本模型偏差、计划空间过大。学习型方法通常在基准（如JOB、TPC-H）上提升10-50%性能，但面临训练数据需求和鲁棒性挑战。自适应方法更易集成到现有系统（如PostgreSQL、SQL Server），而LLM方法正快速发展，但解释性和稳定性仍需改进。

如果你在SimpleDB-like简单实现基础上想升级，建议先添加基本成本模型 + 动态编程枚举，再考虑集成简单学习基数估计（如NeuroCard变体）。

### 最新SQL Query Planning算法的开源实现列表
基于2023-2025年论文，许多learned query optimizers和相关组件（如基数估计）已有开源实现，主要集中在GitHub上（通常集成到PostgreSQL或独立框架）。以下是之前列出的算法中有公开开源代码的代表性项目（按类别整理），包括简介和仓库链接。许多较新论文（如2025年的Delta、Reqo）已明确开源代码，其他（如LEON、GLO、POLAR）暂未找到独立仓库，可能需联系作者或集成在更大框架中。

#### 1. Learned Query Optimizers
- Lero (2023, Learning-to-Rank)  
  使用pairwise ranking模型提升计划选择鲁棒性。  
  开源：https://github.com/AlibabaIncubator/Lero-on-PostgreSQL (主仓库)  
  变体：https://github.com/Blondig/Lero-on-PostgreSQL 和 https://github.com/Blondig/Lero-on-Spark
- LOGER (2023, Efficient and Robust Plans)  
  DRL-based，生成高效join order和operators，提升鲁棒性。  
  开源：https://github.com/TianyiChen0316/LOGER
- Delta (2025, Learned Mixed Cost-based)  
  两阶段混合（value生成 + cost选择），平衡训练成本和准确性。  
  开源：https://github.com/PengJiazhen408/Delta
- Reqo (2025, Robust and Explainable Cost Model)  
  提升成本估计准确性、鲁棒性和可解释性。  
  开源：https://github.com/BaomingChang/Reqo-on-PostgreSQL
- Balsa (基础框架，常用于多种learned optimizer)  
  无专家演示的端到端learned optimizer，使用DRL。  
  开源：https://github.com/balsa-project/balsa

#### 2. LLM-based Query Planning
- CAESURA (2024, Multi-Modal Query Planners)  
  使用LLM将自然语言查询转为多模态执行计划（支持UDF等）。  
  开源：https://github.com/DataManagementLab/caesura
#### 3. 相关基数估计（Cardinality Estimation，常用于optimizer）
- NeuroCard (2021, 但仍SOTA基准)  
  单模型跨表join基数估计，无独立假设。  
  开源：https://github.com/neurocard/neurocard
#### 其他综合/测试框架
- Learned Cardinality Estimation Testbed  
  多种learned CE模型比较（包括NeuroCard、MSCN等）。  
  开源：https://github.com/postechdblab/learned-cardinality-estimation
- LQO (Learned Query Optimizer 示例)  
  基于Neo + Tree-Transformer的RL join order优化。  
  开源：https://github.com/simplerick/LQO

这些仓库大多支持PostgreSQL集成，便于在SimpleDB-like简单实现基础上实验升级（如添加learned成本模型）。如果想快速起步，推荐从Lero或Balsa开始，它们有完整demo和基准支持。如果你需要特定算法的更多细节或集成指导，可进一步探索这些repo的README。
