Selinger算法
Selinger算法（也称为System R优化器或Selinger-style动态规划查询优化器）是1979年IBM System R项目中由Pat Selinger等人提出的经典基于代价的查询优化算法，主要使用动态规划（Dynamic Programming）来枚举连接顺序（Join Order），结合统计信息和代价模型选择最优执行计划。它是现代关系型数据库查询优化器的基础框架（如PostgreSQL、Oracle等都受其影响）。

### 开源实现或库推荐
Selinger算法本身是学术/工程框架，没有官方独立的开源库，但有以下开源项目实现了其核心思想（动态规划 + 代价估计）：

1. Berkeley CS186课程项目（最经典的教育实现）  
   - GitHub搜索“CS186 Query Optimizer”或直接参考Berkeley大学数据库课程项目。  
   - 实现包括：代价估计（IO Cost）、Selinger动态规划枚举左深树（left-deep joins）。  
   - 示例仓库：https://cs186.gitbook.io/project/（课程文档，有完整代码骨架）。

2. sameerkhanna786/Cost-Estimation-and-Selinger-Query-Optimization  
   - GitHub：https://github.com/sameerkhanna786/Cost-Estimation-and-Selinger-Query-Optimization  
   - 完整实现了查询优化器的两部分：代价估计器 + Selinger风格的最优计划选择器（动态规划）。

3. Apache Calcite（工业级开源优化器框架）  
   - GitHub：https://calcite.apache.org/  
   - 广泛用于Flink、Hive、Drill、Kylin等大数据系统，支持基于规则（RBO）和基于代价（CBO）的优化，可扩展实现Selinger-style动态规划。许多项目基于Calcite自定义Join Order枚举。

4. PostgreSQL源码（生产级实现）  
   - PostgreSQL优化器（planner.c等）部分继承Selinger思路：对于小表连接用动态规划，大表用遗传算法（GEQO）。  
   - 开源地址：https://github.com/postgres/postgres（查看src/backend/optimizer/）。

5. ORCA（Pivotal/Greenplum开源优化器）  
   - GitHub：https://github.com/greenplum-db/gpdb/tree/main/src/backend/orca  
   - 使用自顶向下的动态规划变体，支持更复杂的查询。

如果你想学习或实验Selinger算法，推荐从CS186课程项目或上述GitHub仓库入手（Java实现，易懂）。实际数据库如CockroachDB、TiDB等也使用了类似动态规划的Join Order优化。如果你需要具体代码示例或某个仓库的深入解释，再告诉我！

- MIT 的 SimpleDB 是学生逐步实现的（从 heap file、buffer pool 到 B+ tree、join、transaction、recovery 等 lab），框架提供测试和部分骨架代码，学生填空完成。

简单说，虽然都叫 SimpleDB、都用 Java、都用于教学数据库实现，但它们是两个独立的系统，代码结构和内容不相同，不能直接互换使用。

方法一：通过工具栏按钮（最快捷）
找到工具栏上的 "显示所有字符" 按钮
图标是：¶（类似一个反向的P）
或者通过菜单：视图 → 显示符号 → 显示所有字符
点击后，文档中将显示：
制表符 → 显示为右箭头：→
空格 → 显示为中间点：·
换行符 → 显示为：
CRLF (Windows)：↵或显示为 CRLF
LF (Unix/Linux)：↵
CR (Mac)：↵

这是一个非常好的问题，涉及到文本文件的物理存储和不同软件的显示逻辑之间的区别。
简单回答：你的理解是正确的，Java 词法解析器在源代码中确实将换行符识别为 \n，但 Notepad++ 显示的是文件在磁盘上实际存储的字节格式。两者是不同层面的概念。
让我详细解释：
1. 物理存储层面（Notepad++ 显示的内容）
在磁盘上，不同操作系统使用不同的字符表示换行：

操作系统 换行符表示 字节序列 Notepad++ 显示
Windows CRLF \r\n (0x0D 0x0A) CR LF
Unix/Linux/Mac LF \n (0x0A) LF
旧版 Mac CR \r (0x0D) CR

当 Notepad++ 显示 "CRLF" 时，它告诉你：
• 这个文件在磁盘上实际存储的是 \r\n 两个字节
• 文件很可能是在 Windows 系统上创建的，或者用 Windows 风格的换行保存的

2. Java 词法解析层面（JLS 规定）
Java 语言规范（JLS）规定：

1. 在源代码中，无论实际存储的是什么，换行符都被规范化为：
   • 单个 \n (LF, U+000A)
   • 单个 \r (CR, U+000D)
   • 或 \r\n 序列

2. 词法分析时，Java 编译器会统一处理：
   // 无论文件实际是 CRLF 还是 LF
   // Java 词法解析器都会将换行识别为 "\n"
   // 例如，源码中的字符串：
   String s = "第一行\n第二行";  // 这里的 \n 是转义字符
   // 或者在正则表达式中：
   String[] lines = text.split("\n");

3. Java 编译器会自动转换：
   • 读取源代码时，编译器会识别 \r\n、\r 或 \n 作为行终止符
   • 但在词法层面，统一视为行终止符，而不是特定的转义序列

3. 示例说明
假设你有一个Test.java文件，在Windows上创建：
public class Test {
    public static void main(String[] args) {
        System.out.println("Hello");
        System.out.println("World");
    }
}

在磁盘上（十六进制查看）：

70 75 62 6C 69 63 20 63 6C 61 73 73 20 54 65 73 74 20 7B 0D 0A
public class Test {..  // 注意这里的 0D 0A (\r\n)

在 Notepad++ 中：
• 状态栏显示：Windows (CR LF)
• 如果开启"显示所有字符"，会看到每个行尾都有 ↵ 符号
但 Java 编译器看到的是：

1. 读取字节流
2. 遇到 0D 0A 时，识别为一个行终止符
3. 在词法分析中，这个行终止符用于分隔 token
4. 在字符串字面量中，\n 转义字符被识别为行终止符

4. 验证实验

你可以用以下代码验证：

```
import java.io.*;
import java.nio.file.*;

public class LineEndingTest {
    public static void main(String[] args) throws IOException {
        // 读取文件原始字节
        byte[] bytes = Files.readAllBytes(Paths.get("LineEndingTest.java"));
        
        // 查找换行符
        for (int i = 0; i < bytes.length; i++) {
            if (bytes[i] == 0x0D) {
                System.out.println("位置 " + i + ": CR (\\r)");
            }
            if (bytes[i] == 0x0A) {
                System.out.println("位置 " + i + ": LF (\\n)");
            }
        }
        
        // 用Java读取行
        System.out.println("\n--- 按行读取 ---");
        try (BufferedReader br = new BufferedReader(
            new FileReader("LineEndingTest.java"))) {
            int lineNum = 1;
            while (br.readLine() != null) {
                System.out.println("第 " + lineNum + " 行");
                lineNum++;
            }
        }
    }
}
```

总结
层面 表示 说明
磁盘物理存储 CRLF / LF / CR Notepad++ 显示的实际字节
Java 词法解析 \n (标准化) Java 编译器统一处理后的逻辑表示
Java 字符串字面量 \n 转义 源代码中的转义字符，编译时转换为行终止符
关键点：Java 语言处理的是逻辑上的换行，而不关心底层是 \r\n 还是 \n。Notepad++ 显示的是物理存储格式。这种抽象使得 Java 代码可以跨平台移植，只要编译器能识别出各种格式的行终止符即可。

建议在团队开发中统一使用 LF 格式，以避免跨平台问题。在 Notepad++ 中可以通过 编辑 → 文档格式转换 → 转换为 Unix (LF) 来转换。
