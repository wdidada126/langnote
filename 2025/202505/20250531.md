在 Linux（如 Ubuntu）中执行 `.sh` Shell 脚本时，默认情况下不会自动显示哪一行出错。但你可以通过以下几种方法让脚本在出错时打印错误行号信息：

---

## ✅ 方法一：在脚本开头加上 `set -e` 和 `trap` 命令

这是最常用的方法，可以让你知道具体是哪一行执行失败。

### 📄 示例脚本：`test.sh`

```bash
#!/bin/bash
set -e  # 遇到错误立即退出
trap 'echo "Error on line $LINENO"' ERR

# 示例命令
echo "Step 1"
false   # 这个命令会失败
echo "Step 2"  # 不会执行到这里
```

### 🔧 执行方式：

```bash
chmod +x test.sh
./test.sh
```

### 💡 输出示例：

```
Step 1
Error on line 7
```

---

## ✅ 方法二：使用 `PS4` 和 `set -x` 查看每一行执行过程（调试用）

如果你想看到每一行的执行过程和行号，可以启用调试输出：

```bash
#!/bin/bash
set -e
set -x  # 显示每行执行内容
PS4='+ Line $LINENO: '

echo "Step 1"
false
echo "Step 2"
```

### 💡 输出示例：

```
+ Line 5: echo Step 1
Step 1
+ Line 6: false
```

然后脚本因为 `set -e` 立即退出。

---

## ✅ 方法三：运行脚本时启用追踪（不修改脚本）

你也可以不在脚本里加任何调试代码，而是运行时加上 `-x` 参数：

```bash
bash -x test.sh
```

这样也能看到每一行执行的内容和对应的行号。

---

## ✅ 方法四：封装成函数（可复用）

如果你希望多个脚本都支持错误提示，可以封装一个函数或通用头文件：

```bash
#!/bin/bash

on_error() {
  echo "❌ Error on line $1 in script $0"
  exit 1
}

trap 'on_error $LINENO' ERR
set -e

echo "Start..."
false
echo "This will not be printed"
```

---

## ✅ 总结

| 方法 | 描述 | 是否推荐 |
|------|------|----------|
| `set -e` + `trap 'echo $LINENO' ERR` | 自动提示哪一行出错 | ✅ 推荐 |
| `set -x` + `PS4='+ Line $LINENO: '` | 查看所有执行步骤及行号 | ✅ 调试时推荐 |
| `bash -x script.sh` | 外部调试，不改脚本 | ✅ 快速调试 |
| 封装 `on_error` 函数 | 可复用、结构清晰 | ✅ 高级用法 |

你遇到的错误是：

```
-bash: ./build2.sh: /bin/bash^M: bad interpreter: No such file or directory
```

---

## ❗ 错误含义解释：

这个错误通常是因为你的 Shell 脚本文件 `build2.sh` 是 Windows 格式（CRLF），而不是 Unix 格式（LF）。

- Windows 换行符是 `CRLF`（即 `\r\n`），在 Linux 中显示为 `^M`
- Unix/Linux 换行符是 `LF`（即 `\n`）

所以脚本第一行的 shebang 行：

```bash
#!/bin/bash
```

会被识别成：

```
/bin/bash^M
```

而 Linux 系统找不到这个路径 `/bin/bash^M`，于是报错 ❌

---

## ✅ 解决方案：将脚本转换为 Unix 格式

### ✅ 方法一：使用 `dos2unix` 工具（推荐）

#### 1. 安装 `dos2unix`

```bash
sudo apt update
sudo apt install dos2unix
```

#### 2. 转换脚本格式

```bash
dos2unix build2.sh
```

#### 3. 再次运行脚本

```bash
./build2.sh
```

✅ 应该就不会再报错了。

---

### ✅ 方法二：使用 `sed` 命令手动删除 `^M` 字符

```bash
sed -i 's/\r$//' build2.sh
```

这会把每一行结尾的 `\r`（也就是 Windows 的换行符）删除。

然后再次运行脚本：

```bash
./build2.sh
```

---

### ✅ 方法三：用 Vim 编辑器查看/转换（可选）

```bash
vim build2.sh
```

在 Vim 中输入以下命令进行转换：

```vim
:set fileformat=unix
:wq
```

---

## 🔍 如何避免这个问题？

### 🛡️ 在 Windows 上编辑后，保存时选择 Unix 格式

如果你是在 Windows 上用编辑器（如 VS Code、Notepad++、Sublime） 编写脚本，请确保：

- 右下角显示的是 `LF`（不是 `CRLF`）
- 或者在保存时选择“Unix 格式”

### 💡 示例：VS Code 设置默认换行符为 LF

1. 打开设置（Settings）
2. 搜索 `Files: Eol`
3. 设置为 `\n`

---

## ✅ 总结解决方案

| 方法 | 命令 | 说明 |
|------|------|------|
| 使用 `dos2unix` | `dos2unix build2.sh` | 推荐，最简单直接 |
| 使用 `sed` 删除 \r | `sed -i 's/\r$//' build2.sh` | 不依赖额外工具 |
| 使用 `vim` 转换 | `:set fileformat=unix` | 手动方式，适合调试 |
| 避免问题 | 编辑器保存为 Unix (LF) 格式 | 开发阶段就避免 |

