## 🔤 一、"Mutex" 的中文翻译

Mutex 是 Mutual Exclusion 的缩写，中文通常翻译为：

> ✅ 互斥锁

### 其他常见译法：
- 互斥量
- 互斥器
- 排他锁
- 独占锁

其中 “互斥锁” 是最常用、最标准的中文术语，在操作系统、并发编程、Java 文档中广泛使用。

---

## 🧱 二、Mutex 的核心概念

| 概念 | 说明 |
|------|------|
| 目的 | 保证同一时刻只有一个线程可以访问共享资源 |
| 行为 | 线程必须先“加锁”才能进入临界区，用完后“解锁” |
| 特性 | 原子性、唯一性（同一时间只能一个线程持有） |
| 场景 | 防止数据竞争（Data Race）、保证操作原子性 |

```c
mutex.lock();    // 加锁
// 操作共享资源
mutex.unlock();  // 解锁
```

## 🐘 三、Java 中有 mutex 吗？对应的类是什么？

Java 没有叫 `Mutex` 的类，但 有多个等价的互斥锁实现！

### ✅ Java 中最常用的互斥锁类：

| Java 类 | 说明 | 是否可重入 | 推荐程度 |
|--------|------|------------|---------|
| `synchronized` 关键字 | 内置锁（Intrinsic Lock） | ✅ 是 | ⭐⭐⭐⭐⭐ |
| `ReentrantLock` | 显式锁（Explicit Lock） | ✅ 是 | ⭐⭐⭐⭐⭐ |
| `ReentrantReadWriteLock.WriteLock` | 写锁（也是互斥锁） | ✅ 是 | ⭐⭐⭐ |

---

### 1. `synchronized` —— Java 最基础的互斥锁

```java
public class Counter {
    private int count = 0;

    // 方法锁（锁住 this）
    public synchronized void increment() {
        count++;
    }

    // 代码块锁
    public void decrement() {
        synchronized (this) {
            count--;
        }
    }
}
```

- 优点：简单、自动释放（异常时也会释放）
- 缺点：不灵活（不能尝试加锁、不能设置超时）

> ✅ `synchronized` 就是 Java 的 内置 mutex。

---

### 2. `ReentrantLock` —— 显式的 mutex

```java
import java.util.concurrent.locks.ReentrantLock;

public class Counter {
    private final ReentrantLock lock = new ReentrantLock();
    private int count = 0;

    public void increment() {
        lock.lock();  // 加锁（阻塞）
        try {
            count++;
        } finally {
            lock.unlock();  // 必须在 finally 中释放！
        }
    }

    // 尝试加锁（非阻塞）
    public boolean tryIncrement() {
        if (lock.tryLock()) {
            try {
                count++;
                return true;
            } finally {
                lock.unlock();
            }
        }
        return false;
    }
}
```

- 优点：
  - 可尝试加锁 `tryLock()`
  - 可设置超时 `tryLock(timeout, unit)`
  - 可中断 `lockInterruptibly()`
  - 公平锁/非公平锁可选
- 缺点：必须手动释放，容易忘记（建议用 try-finally）

> ✅ `ReentrantLock` 是 Java 中最接近操作系统 mutex 的类。

## 🧩 四、为什么叫 `ReentrantLock` 而不是 `Mutex`？

因为 Java 的锁是 可重入的（Reentrant）：

- 同一个线程可以多次获取同一个锁
- 每次 `lock()` 必须对应一次 `unlock()`
- 防止死锁（自己锁自己）

```java
public void methodA() {
    lock.lock();
    try {
        methodB();  // 同一线程再次获取锁
    } finally {
        lock.unlock();
    }
}

public void methodB() {
    lock.lock();  // 不会死锁！因为是可重入的
    try {
        // ...
    } finally {
        lock.unlock();
    }
}
```

操作系统中的 mutex 也通常是可重入的（如 pthread mutex），但 Java 显式命名为 `ReentrantLock` 以强调这一特性。

##  五、Java 中其他“锁”与 mutex 的关系

| 类型 | 是否 mutex | 说明 |
|------|-----------|------|
| `ReentrantReadWriteLock.ReadLock` | ❌ 否 | 共享锁，多个线程可同时读 |
| `ReentrantReadWriteLock.WriteLock` | ✅ 是 | 互斥锁，写操作独占 |
| `StampedLock` | 部分是 | 提供乐观读、写锁（互斥） |
| `Semaphore(1)` | ✅ 是 | 信号量设为 1 时，等价于 mutex |
| `synchronized` | ✅ 是 | 内置互斥锁 |
| `ReentrantLock` | ✅ 是 | 显式互斥锁 |

##  六、总结：一句话回答你的问题

> “Mutex” 的中文是 “互斥锁”，Java 中没有叫 `Mutex` 的类，但 `synchronized` 关键字 和 `ReentrantLock` 类 就是 Java 中标准的、功能完整的 互斥锁实现。

---

### 🎯 推荐使用建议：

| 场景 | 推荐方案 |
|------|---------|
| 简单同步 | `synchronized`（足够用） |
| 需要尝试加锁、超时、中断 | `ReentrantLock` |
| 读多写少 | `ReentrantReadWriteLock` |
| 高性能读 | `StampedLock` |
