# 20250815

vcpkg-cmake
vcpkg-cmake-config

是 vcpkg 工具链中用于集成 CMake 的“支持模块”或“内部组件”。
vcpkg-cmake	vcpkg 内部的 CMake 集成脚本	帮你在 CMake 项目中使用 vcpkg 管理的库
vcpkg-cmake-config	vcpkg 的另一种 CMake 集成方式（基于 find_package）	更现代的方式，支持 find_package(Boost) 这种写法

非常好的问题！我们来清晰地解释一下：

>  `vcpkg-cmake` 和 `vcpkg-cmake-config` 是库吗？和 Boost 一样吗？

答案是：不，它们不是像 Boost 那样的 C++ 库。它们是 vcpkg 工具链中用于集成 CMake 的“支持模块”或“内部组件”。


##  一、先说结论

| 名称 | 类型 | 作用 |
|------|------|------|
| Boost | C++ 第三方库（如容器、智能指针、网络等） | 提供实际功能代码，供你程序调用 |
| vcpkg-cmake | vcpkg 内部的 CMake 集成脚本 | 帮你在 CMake 项目中使用 vcpkg 管理的库 |
| vcpkg-cmake-config | vcpkg 的另一种 CMake 集成方式（基于 `find_package`） | 更现代的方式，支持 `find_package(Boost)` 这种写法 |

 所以：  
 Boost 是“被使用的库”  
 vcpkg-cmake / vcpkg-cmake-config 不是库，是“帮助你使用库”的工具组件


##  二、vcpkg 是什么？（背景）

[vcpkg](https://github.com/microsoft/vcpkg) 是由 Microsoft 开发的 C++ 跨平台包管理器，用于：

- 自动下载、编译、安装 C++ 第三方库（如 Boost、OpenSSL、fmt、SQLite 等）
- 解决 C++ 缺乏统一包管理的痛点

```bash
vcpkg install boost-asio
vcpkg install openssl
```

安装后，这些库就可以在你的 CMake 项目中使用了。


##  三、vcpkg-cmake 和 vcpkg-cmake-config 到底是干嘛的？

当你用 `vcpkg install xxx` 安装一个库后，vcpkg 需要告诉你的 CMake 构建系统：库在哪、怎么链接。

这就需要“集成”到 CMake 中，而集成方式有两种，对应两个“集成包”：


###  1. `vcpkg-cmake`（旧式集成，基于 `VCPKG_TARGET_TRIPLET`）

- 作用：提供 CMake 脚本，让 CMake 知道从 vcpkg 安装的库路径加载头文件和库文件。
- 使用方式：
  ```cmake
  # 在 CMakeLists.txt 中手动设置
  set(CMAKE_TOOLCHAIN_FILE "path/to/vcpkg/scripts/buildsystems/vcpkg.cmake")
  ```
- 特点：
  - 通过修改 `CMAKE_PREFIX_PATH` 等变量，让 `find_library()`、`find_path()` 找到 vcpkg 的库
  - 不支持现代 CMake 的 `find_package(Boost CONFIG)` 风格
  - 是较早的集成方式


###  2. `vcpkg-cmake-config`（新式集成，推荐）

- 作用：让 vcpkg 生成符合 CMake `find_package(... CONFIG)` 规范的 `.cmake` 文件。
- 使用方式：
  ```bash
  vcpkg install boost-asio --triplet=x64-windows
  ```
  vcpkg 会为 Boost 生成 `BoostConfig.cmake`，然后你可以在 CMake 中这样写：

  ```cmake
  find_package(Boost REQUIRED COMPONENTS system filesystem)
  target_link_libraries(myapp PRIVATE Boost::system)
  ```
- 依赖包：`vcpkg-cmake-config` 是启用这种模式所需的“元包”或配置模块。
- 特点：
  - 更符合现代 CMake 最佳实践
  - 支持 `find_package(LibName CONFIG)`
  - 推荐使用

## 💡 六、你应该怎么做？

如果你在使用 vcpkg，建议：

```bash
# 1. 安装库（自动使用当前集成方式）
vcpkg install boost-asio

# 2. 在 CMake 中启用 vcpkg 支持
cmake -B build -S . \
  -DCMAKE_TOOLCHAIN_FILE=[your vcpkg path]/scripts/buildsystems/vcpkg.cmake
```

然后就可以：

```cmake
find_package(Boost REQUIRED COMPONENTS asio)
target_link_libraries(myapp PRIVATE Boost::asio)
```

> 只要你配置了 `vcpkg.cmake` 工具链文件，`vcpkg-cmake-config` 的行为就会自动启用（现代 vcpkg 默认支持）。


### ✅ 最后一句话总结：

> - Boost 是“你要吃的饭”（功能库）  
> - vcpkg-cmake / vcpkg-cmake-config 是“帮你把饭端上桌的筷子和碗”（构建集成工具）

它们完全不同层级，但协同工作，让你更方便地使用 C++ 第三方库。

要开启 `vcpkg-cmake-config` 模式（即使用现代 CMake 的 `find_package(... CONFIG)` 方式集成 vcpkg 安装的库），其实 不需要单独安装 `vcpkg-cmake-config` 这个包 —— 它不是一个独立可安装的库，而是 vcpkg 的一种集成模式或功能特性。

从 vcpkg 较新版本（2022 年以后）开始，`vcpkg-cmake-config` 风格的集成是 默认推荐并自动启用的，只要你正确配置了 CMake 工具链。

## ✅ 正确开启 `vcpkg-cmake-config` 模式的方法

### ✅ 步骤 1：确保使用较新版本的 vcpkg

```bash
# 更新 vcpkg 到最新
git pull
./vcpkg update
```

现代 vcpkg（2022+）默认支持 `find_package(... CONFIG)` 模式，无需额外配置。

---

### ✅ 步骤 2：在 CMake 中指定 vcpkg 工具链文件

这是最关键的一步。你需要在调用 CMake 时，通过 `-DCMAKE_TOOLCHAIN_FILE` 指向 vcpkg 提供的工具链文件。

```bash
cmake -B build \
      -S . \
      -DCMAKE_TOOLCHAIN_FILE=/path/to/vcpkg/scripts/buildsystems/vcpkg.cmake
```

> ⚠️ 替换 `/path/to/vcpkg` 为你的实际路径，例如：
> - Windows: `C:/dev/vcpkg/scripts/buildsystems/vcpkg.cmake`
> - Linux/macOS: `~/vcpkg/scripts/buildsystems/vcpkg.cmake`

---

### ✅ 步骤 3：使用 `find_package(... CONFIG)` 语法

一旦你设置了 `CMAKE_TOOLCHAIN_FILE`，vcpkg 就会自动生成并注册 `*Config.cmake` 文件（如 `BoostConfig.cmake`、`fmtConfig.cmake`），你就可以使用现代 CMake 风格：

```cmake
# CMakeLists.txt
cmake_minimum_required(VERSION 3.14)
project(myapp)

# 查找 Boost（使用 CONFIG 模式）
find_package(Boost REQUIRED COMPONENTS system filesystem)

# 或查找其他库
find_package(fmt REQUIRED)
find_package(OpenSSL REQUIRED)

add_executable(myapp main.cpp)

# 链接
target_link_libraries(myapp PRIVATE Boost::system Boost::filesystem fmt::fmt OpenSSL::SSL)
```

## 🔍 验证是否开启了 `vcpkg-cmake-config` 模式

### 方法 1：检查生成的 `find_package` 路径

构建时，CMake 会从 vcpkg 的 `installed/<triplet>/share` 目录加载 `*Config.cmake` 文件。

例如：

```
vcpkg/installed/x64-windows/share/boost/CMakeLists.txt
vcpkg/installed/x64-windows/share/boost/BoostConfig.cmake
```

如果你能成功 `find_package(Boost)`，说明 `vcpkg-cmake-config` 模式已生效。

---

### 方法 2：查看 CMake 输出日志

在 `cmake` 命令输出中，你会看到类似：

```
-- Found package configuration file:
  /home/user/vcpkg/installed/x64-linux/share/boost/BoostConfig.cmake
```

这表示使用了 `CONFIG` 模式，即 `vcpkg-cmake-config` 风格。

## ⚙️ 高级配置（可选）

### 1. 强制使用 CONFIG 模式（避免 MODULE 模式）

```cmake
find_package(Boost REQUIRED CONFIG COMPONENTS system)
```

加上 `CONFIG` 关键字，强制使用 `BoostConfig.cmake`，而不是旧的 `FindBoost.cmake`。

---

### 2. 设置默认 triplet（避免每次指定）

```bash
# 设置环境变量
export VCPKG_DEFAULT_TRIPLET=x64-linux
# 或 Windows
set VCPKG_DEFAULT_TRIPLET=x64-windows
```

---

### 3. 使用 `vcpkg.json` 清单模式（推荐）

在项目根目录创建 `vcpkg.json`：

```json
{
  "name": "myapp",
  "version": "1.0.0",
  "dependencies": [
    "boost",
    "fmt",
    "openssl"
  ]
}
```

然后运行：

```bash
vcpkg install
```

vcpkg 会自动解析依赖并生成对应的 `*Config.cmake` 文件。

## 📦 `find_package()` 基本语法回顾

```cmake
find_package(<PackageName> [version] [EXACT] [QUIET] [MODULE]
             [REQUIRED] [[COMPONENTS] [components...]]
             [OPTIONAL_COMPONENTS components...]
             [NO_POLICY_SCOPE])
```

你问的是：

```cmake
find_package(LibName CONFIG REQUIRED)
```

我们重点看 `CONFIG` 和 `REQUIRED`。

##  一、`CONFIG` 参数的作用

###  作用：
告诉 CMake：优先使用 `<PackageName>Config.cmake` 或 `Find<PackageName>.cmake` 文件来查找包，而不是使用 CMake 内置的查找逻辑。

###  查找模式对比：

| 模式 | 命令写法 | 查找目标 |
|------|---------|----------|
| Module 模式（默认） | `find_package(Boost)` | CMake 尝试使用内置的 `FindBoost.cmake` 脚本 |
| Config 模式 | `find_package(Boost CONFIG)` | CMake 查找 `BoostConfig.cmake` 或 `boost-config.cmake` 文件 |

> ⚠️ 注意：即使不写 `CONFIG`，如果 `Find<PackageName>.cmake` 找不到，CMake 也会自动 fallback 到 `CONFIG` 模式。


###  使用 `CONFIG` 的好处：

1. 更可靠：使用库自带或包管理器（如 vcpkg/conan）生成的 `.cmake` 配置文件
2. 避免冲突：防止 CMake 内置的 `FindXXX.cmake` 找到系统旧版本
3. 支持现代 CMake 最佳实践

###  示例：

```cmake
# 使用 vcpkg 安装后，它会生成 fmtConfig.cmake
find_package(fmt CONFIG REQUIRED)
```

如果不加 `CONFIG`，CMake 会先找 `Findfmt.cmake`（可能不存在或不匹配），再找 `fmtConfig.cmake`，不如直接指定 `CONFIG` 明确。


###  加 `CONFIG` vs 不加 `CONFIG`

| 场景 | 是否加 `CONFIG` | 区别 |
|------|----------------|------|
| 使用 vcpkg/conan/自建库 | ✅ 建议加 | 直接使用生成的 `*Config.cmake`，更准确 |
| 使用系统库（如 OpenGL） | ❌ 通常不加 | 使用 CMake 内置 `FindOpenGL.cmake` |
| 想强制使用配置文件 | ✅ 加 `CONFIG` | 避免 fallback，提高可预测性 |


##  二、`REQUIRED` 参数的作用

###  作用：
如果找不到该包，CMake 配置阶段会报错并终止。

###  加 `REQUIRED` vs 不加 `REQUIRED`

| 写法 | 行为 | 适合场景 |
|------|------|----------|
| `find_package(Boost REQUIRED)` | 找不到直接报错，停止配置 | 项目必须依赖该库 |
| `find_package(Boost)` | 找不到不会报错，`Boost_FOUND` 为 `FALSE` | 可选依赖，后续用 `if(Boost_FOUND)` 判断 |


###  示例对比

####  不加 `REQUIRED`（静默失败）

```cmake
find_package(Boost COMPONENTS system)
# 如果 Boost 没找到，CMake 不会报错，但后续链接会失败
if(Boost_FOUND)
    target_link_libraries(myapp PRIVATE ${Boost_LIBRARIES})
else()
    message(WARNING "Boost not found, some features disabled")
endif()
```

####  加 `REQUIRED`（失败即终止）

```cmake
find_package(Boost REQUIRED COMPONENTS system)
# 如果 Boost 没找到，CMake 直接报错：
#   Could not find a package configuration file named "BoostConfig.cmake"
#   ... terminating.
target_link_libraries(myapp PRIVATE ${Boost_LIBRARIES})
```


##  三、`CONFIG` 和 `REQUIRED` 一起用：最佳实践

```cmake
find_package(fmt CONFIG REQUIRED)
```

意味着：

1. 使用 `fmtConfig.cmake` 文件查找库（精确、可靠）
2. 如果找不到，立即报错（避免后续构建失败）

这是现代 CMake + 包管理器（vcpkg/conan）的推荐写法。


##  四、完整对比表

| 写法 | CONFIG | REQUIRED | 行为 |
|------|--------|----------|------|
| `find_package(Boost)` | ❌ Module 模式 | ❌ 可选 | 先用 `FindBoost.cmake`，失败不终止 |
| `find_package(Boost REQUIRED)` | ❌ Module 模式 | ✅ 必需 | 用 `FindBoost.cmake`，失败则终止 |
| `find_package(Boost CONFIG)` | ✅ Config 模式 | ❌ 可选 | 用 `BoostConfig.cmake`，失败不终止 |
| `find_package(Boost CONFIG REQUIRED)` | ✅ Config 模式 | ✅ 必需 | 推荐！精确查找，找不到立即报错 |


##  五、什么时候不加？

| 参数 | 什么时候不加？ |
|------|----------------|
| `CONFIG` | 依赖系统库，且没有 `*Config.cmake` 文件（如旧版库） |
| `REQUIRED` | 该库是可选功能，项目可以降级运行（如日志、GUI） |


##  总结

| 参数 | 作用 | 建议 |
|------|------|------|
| `CONFIG` | 强制使用 `*Config.cmake` 文件查找包 | ✅ 用 vcpkg/conan 时强烈建议加 |
| `REQUIRED` | 找不到包时立即报错 | ✅ 项目核心依赖必须加 |

> ✅ 最佳实践：
> ```cmake
> find_package(YourLib CONFIG REQUIRED)
> ```

这样既保证了查找的准确性，又保证了依赖的强制性，是现代 CMake 项目的标准写法。
