当你要自己编写一个库并定义类似 `class DROGON_EXPORT` 这样的宏时，主要目的是为了在不同的编译环境（如 Windows 和 Linux）下正确地导出和导入库中的类、函数等符号。下面详细介绍实现步骤和示例代码。

### 1. 理解宏的作用
在 Windows 系统中，动态链接库（DLL）需要明确指定哪些符号（类、函数等）要被导出供其他程序使用，通过 `__declspec(dllexport)` 关键字来标记导出的符号，使用 `__declspec(dllimport)` 关键字来标记导入的符号。而在 Linux 等类 Unix 系统中，默认情况下所有符号都会被导出，一般不需要特殊标记。

### 2. 定义宏

#### 2.1 创建头文件
创建一个公共的头文件，例如 `MyLibraryExport.h`，在其中定义宏。

```cpp
// MyLibraryExport.h
#pragma once

// 判断是否是 Windows 平台
#ifdef _WIN32
    // 如果定义了 MYLIBRARY_EXPORTS，说明正在编译库本身，使用 __declspec(dllexport) 导出符号
    #ifdef MYLIBRARY_EXPORTS
        #define MYLIBRARY_API __declspec(dllexport)
    // 否则，说明是在使用库，使用 __declspec(dllimport) 导入符号
    #else
        #define MYLIBRARY_API __declspec(dllimport)
    #endif
// 非 Windows 平台，不需要特殊标记，宏为空
#else
    #define MYLIBRARY_API
#endif
```

### 3. 使用宏

#### 3.1 定义类和函数
在库的头文件中使用定义好的宏来标记需要导出的类和函数。

```cpp
// MyClass.h
#pragma once

#include "MyLibraryExport.h"

// 使用 MYLIBRARY_API 标记类
class MYLIBRARY_API MyClass {
public:
    MyClass();
    ~MyClass();
    void doSomething();
};

// 使用 MYLIBRARY_API 标记函数
extern "C" MYLIBRARY_API void myFunction();
```

#### 3.2 实现类和函数
在源文件中实现类的成员函数和函数。

```cpp
// MyClass.cpp
#include "MyClass.h"
#include <iostream>

MyClass::MyClass() {
    std::cout << "MyClass constructor" << std::endl;
}

MyClass::~MyClass() {
    std::cout << "MyClass destructor" << std::endl;
}

void MyClass::doSomething() {
    std::cout << "MyClass is doing something." << std::endl;
}

// 实现函数
extern "C" void myFunction() {
    std::cout << "myFunction is called." << std::endl;
}
```

### 4. 编译库

#### 4.1 CMake 配置
使用 CMake 来编译库，在 `CMakeLists.txt` 中添加以下内容。

```cmake
cmake_minimum_required(VERSION 3.10)
project(MyLibrary)

# 设置 C++ 标准
set(CMAKE_CXX_STANDARD 17)

# 定义 MYLIBRARY_EXPORTS 宏，表明正在编译库本身
add_definitions(-DMYLIBRARY_EXPORTS)

# 添加库的源文件
add_library(MyLibrary SHARED MyClass.cpp)

# 安装库和头文件
install(TARGETS MyLibrary DESTINATION lib)
install(FILES MyClass.h MyLibraryExport.h DESTINATION include)
```

#### 4.2 编译和安装
在项目根目录下创建 `build` 目录，进入该目录进行编译和安装。

```bash
mkdir build
cd build
cmake ..
make
make install
```

### 5. 使用库

#### 5.1 创建使用库的项目
创建一个新的项目，包含库的头文件并链接库。

```cpp
// main.cpp
#include "MyClass.h"

int main() {
    MyClass obj;
    obj.doSomething();

    myFunction();

    return 0;
}
```

#### 5.2 CMake 配置
在使用库的项目的 `CMakeLists.txt` 中添加以下内容。

```cmake
cmake_minimum_required(VERSION 3.10)
project(MyApp)

# 设置 C++ 标准
set(CMAKE_CXX_STANDARD 17)

# 查找库
find_library(MYLIBRARY NAMES MyLibrary)
find_path(MYLIBRARY_INCLUDE_DIR MyClass.h)

# 添加可执行文件
add_executable(MyApp main.cpp)

# 包含库的头文件目录
target_include_directories(MyApp PRIVATE ${MYLIBRARY_INCLUDE_DIR})

# 链接库
target_link_libraries(MyApp PRIVATE ${MYLIBRARY})
```

#### 5.3 编译和运行
在使用库的项目根目录下创建 `build` 目录，进入该目录进行编译和运行。

```bash

```

- 在使用库的阶段：当其他项目使用这个库时，没有定义 `MYLIBRARY_EXPORTS`，此时 `MYLIBRARY_API` 被定义为 `__declspec(dllimport)`。这使得在使用库的代码中，能够正确地导入库中导出的类和方法，以便在自己的代码中使用这些功能。

下面为你提供一个具体的 C++ 代码示例，展示当两个或多个 `std::shared_ptr` 相互引用时，如何导致引用计数永远不会变为 0，进而造成内存泄漏，同时给出使用 `std::weak_ptr` 解决该问题的方案。

### 导致内存泄漏的示例代码
```cpp
#include <iostream>
#include <memory>

class B;

class A {
public:
    std::shared_ptr<B> bPtr;
    ~A() {
        std::cout << "A 对象被销毁" << std::endl;
    }
};

class B {
public:
    std::shared_ptr<A> aPtr;
    ~B() {
        std::cout << "B 对象被销毁" << std::endl;
    }
};

int main() {
    {
        std::shared_ptr<A> a = std::make_shared<A>();
        std::shared_ptr<B> b = std::make_shared<B>();

        // 相互引用
        a->bPtr = b;
        b->aPtr = a;
    }
    std::cout << "作用域结束，对象应该被销毁，但由于循环引用，内存泄漏了" << std::endl;
    return 0;
}
```

#### 代码解释
1. 类的定义：定义了两个类 `A` 和 `B`，每个类都包含一个 `std::shared_ptr` 成员，分别指向对方类的对象。
2. 对象创建与引用：在 `main` 函数的作用域内，创建了 `A` 和 `B` 的 `std::shared_ptr` 对象 `a` 和 `b`，然后让它们相互引用，即 `a` 中的 `bPtr` 指向 `b`，`b` 中的 `aPtr` 指向 `a`。
3. 内存泄漏问题：当作用域结束时，`a` 和 `b` 离开作用域，它们的引用计数会减 1，但由于它们相互引用，各自的引用计数仍然为 1，不会变为 0，因此 `A` 和 `B` 对象不会被销毁，造成内存泄漏。从输出中可以看到，`A` 和 `B` 的析构函数没有被调用。

### 使用 `std::weak_ptr` 解决循环引用问题的示例代码
```cpp
#include <iostream>
#include <memory>

class B;

class A {
public:
    std::shared_ptr<B> bPtr;
    ~A() {
        std::cout << "A 对象被销毁" << std::endl;
    }
};

class B {
public:
    // 使用 std::weak_ptr 打破循环引用
    std::weak_ptr<A> aPtr;
    ~B() {
        std::cout << "B 对象被销毁" << std::endl;
    }
};

int main() {
    {
        std::shared_ptr<A> a = std::make_shared<A>();
        std::shared_ptr<B> b = std::make_shared<B>();

        // 相互引用
        a->bPtr = b;
        b->aPtr = a;
    }
    std::cout << "作用域结束，对象正常销毁，没有内存泄漏" << std::endl;
    return 0;
}
```

#### 代码解释
1. `std::weak_ptr` 的使用：将 `B` 类中的 `aPtr` 类型从 `std::shared_ptr<A>` 改为 `std::weak_ptr<A>`。`std::weak_ptr` 是一种弱引用，它不会增加所指向对象的引用计数。
2. 解决循环引用：当 `a` 和 `b` 离开作用域时，它们的引用计数会减 1，由于 `b` 中的 `aPtr` 是 `std::weak_ptr`，不会影响 `a` 的引用计数，因此 `a` 的引用计数变为 0，`A` 对象被销毁。`A` 对象销毁后，`b` 的引用计数也变为 0，`B` 对象也被销毁，避免了内存泄漏。从输出中可以看到，`A` 和 `B` 的析构函数被正常调用。

通过这个示例，你可以清楚地看到 `std::shared_ptr` 循环引用导致的内存泄漏问题，以及如何使用 `std::weak_ptr` 来解决该问题。
