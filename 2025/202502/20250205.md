# Nginx 实现 类 Spring Cloud Gateway 工业级限流 + 授权 完整方案
这是生产可用、支持高并发、可监控、可灰度的标准落地方案，完全对标 Spring Cloud Gateway 限流 + 认证授权能力。

我直接给你 可复制粘贴到生产的配置 + 原理 + 最佳实践。

# 一、整体架构（工业级标准）
```
客户端 → Nginx → 【限流模块】 → 【授权认证模块】 → 后端服务
```

Nginx 官方原生模块就能实现：
1. 限流（速率限制 + 并发限制）
2. 授权认证（JWT / API_KEY / OAuth2 / 白名单）
3. 熔断、重试、降级
4. 统一返回格式（JSON 格式错误）
5. 监控埋点（Prometheus）

完全替代 Spring Cloud Gateway 网关能力。

# 二、工业级限流（2 套方案：漏桶 + 令牌桶）
Nginx 官方两大限流模块：
- `limit_req`：漏桶限流（控制 QPS，防突刺）
- `limit_conn`：并发连接限流（防 CC 攻击）

## 1. 全局配置（nginx.conf）
```nginx
# 限流共享内存（全局）
limit_req_zone $binary_remote_addr zone=api_qps:100m rate=100r/s;
limit_conn_zone $binary_remote_addr zone=api_conn:100m;

# JWT / API_KEY 维度限流（更精准）
limit_req_zone $http_x_api_key zone=key_qps:100m rate=50r/s;
limit_req_zone $jwt_sub zone=user_qps:100m rate=30r/s;
```

## 2. 接口级限流（server/location）
```nginx
location /api/ {
    # QPS 限流（漏桶）
    limit_req zone=api_qps burst=20 nodelay;

    # 并发连接限流
    limit_conn api_conn 100;

    # 被限流时返回 JSON（和网关一致）
    limit_req_status 429;
    error_page 429 = /429.json;
}
```

## 3. 统一限流返回格式（/429.json）
```nginx
location = /429.json {
    default_type application/json;
    return 429 '{"code":429,"msg":"too many requests","data":null}';
}
```

# 三、工业级授权认证（3 套企业级方案）
## 方案 1：API_KEY 认证（最简单、最常用）
```nginx
location /api/ {
    # 必须带 X-API-KEY
    if ($http_x_api_key = "") {
        return 401 '{"code":401,"msg":"unauthorized"}';
    }

    # 白名单校验（生产可放到 map 块/redis）
    set $valid_key 0;
    if ($http_x_api_key ~* "key_abc123|key_def456") {
        set $valid_key 1;
    }
    if ($valid_key = 0) {
        return 403 '{"code":403,"msg":"invalid key"}';
    }

    proxy_pass http://backend;
}
```

## 方案 2：JWT 认证（对标 Spring Cloud Gateway 最主流）
使用 Nginx 官方 `ngx_http_auth_jwt_module`（工业级标准）

### 配置
```nginx
location /api/ {
    # JWT 开启
    auth_jwt "api realm";
    auth_jwt_key_file /etc/nginx/public.pem;

    # 校验过期、非空
    auth_jwt_require exp iss aud;

    # 把 JWT 信息传给后端
    proxy_set_header X-User-Id $jwt_claim_sub;
    proxy_set_header X-User-Role $jwt_claim_role;

    proxy_pass http://backend;
}
```

### 拒绝时返回 JSON
```nginx
error_page 401 = /401.json;
location = /401.json {
    default_type application/json;
    return 401 '{"code":401,"msg":"invalid token"}';
}
```

## 方案 3：内部授权服务校验（微服务架构）
适合：OAuth2、SSO、自定义权限中心

```nginx
location /api/ {
    # 先访问授权服务
    auth_request /auth/verify;

    # 授权通过才转发
    proxy_pass http://backend;
}

location /auth/verify {
    internal;
    proxy_pass http://auth-service/verify;
    proxy_pass_request_body off;
    proxy_set_header Content-Length "";
    proxy_set_header X-Token $http_authorization;
}
```

# 四、Nginx + 限流 + 授权 完整生产配置（可直接上线）
```nginx
http {
    limit_req_zone $binary_remote_addr zone=api_qps:100m rate=100r/s;
    limit_conn_zone $binary_remote_addr zone=api_conn:100m;
    limit_req_zone $jwt_sub zone=user_qps:100m rate=30r/s;

    server {
        listen 80;

        # JWT 授权
        auth_jwt "api";
        auth_jwt_key_file /etc/nginx/public.pem;

        # 限流
        location /api/v1/ {
            limit_req zone=api_qps burst=20 nodelay;
            limit_conn api_conn 100;

            auth_jwt_require exp;
            proxy_set_header X-User $jwt_claim_sub;
            proxy_pass http://backend;
        }

        # 错误返回
        error_page 401 403 429 /error.json;
        location = /error.json {
            default_type application/json;
            return 429 '{"code":$status,"msg":"request denied"}';
        }
    }
}
```
