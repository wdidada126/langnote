在 Windows 11 专业版中安装 WSL 和 Ubuntu 22.04 时遇到问题，可以尝试以下解决方法：


1.检查系统版本和功能是否启用
确保 Windows 11 的内部版本号为 22000 或更高。同时，检查是否已启用以下功能：

• 虚拟机平台（Virtual Machine Platform）

• 适用于 Linux 的 Windows 子系统（Windows Subsystem for Linux）

可以通过以下步骤启用这些功能：

1. 按`Win + R`键，输入`OptionalFeatures`并回车。

2. 在“可选功能”窗口中，勾选上述两项功能。

3. 如果提示重启，请重启计算机。


2.通过命令行安装 WSL 和 Ubuntu 22.04
在 Windows 11 中，可以直接通过命令行安装 WSL 和指定的 Linux 发行版。以管理员权限打开 PowerShell 或命令提示符，执行以下命令：

```bash
wsl --install -d Ubuntu-22.04
```

该命令会自动下载并安装 WSL 和 Ubuntu 22.04。


3.手动下载和安装 WSL
如果通过命令行安装失败，可以手动下载 WSL 安装包：

1. 访问[WSL GitHub 发布页面]下载最新版本的 WSL 安装包。

2. 安装完成后，重启计算机。


4.通过 Microsoft Store 安装 Ubuntu 22.04
如果上述方法仍无法解决问题，可以尝试从 Microsoft Store 安装 Ubuntu 22.04：

1. 打开 Microsoft Store，搜索“Ubuntu 22.04”并下载。

2. 安装完成后，首次运行时会提示设置 Linux 用户名和密码。


5.解决网络问题
如果在安装过程中遇到网络问题（如下载速度慢或无法连接），可以尝试以下方法：

• 手动下载 WSL 和 Ubuntu 的安装包。

• 使用 GitHub 上提供的安装脚本。


6.检查错误日志
如果安装过程中出现错误（如“灾难性故障”），可以查看 WSL 的日志文件以获取更多信息。日志文件通常位于：

```
%USERPROFILE%\AppData\Local\Temp\WSL\Logs
```



7.其他注意事项

• 确保 Windows 11 系统已更新到最新版本。

• 如果之前安装过 WSL 或 Linux 发行版，建议先卸载相关组件，然后重新安装。

如果按照上述步骤仍未解决问题，可以提供更多错误信息以便进一步排查。

在 Rust 中，所有权（Ownership）是语言的核心概念之一，它确保了内存安全，同时避免了垃圾回收机制（GC）带来的性能开销。所有权规则是 Rust 的核心特性之一，它通过编译时检查来保证内存安全，避免了诸如空指针、野指针、数据竞争等常见问题。

以下是 Rust 所有权的几个关键规则和概念：


1.所有权（Ownership）

• 定义：每个值（Value）都有一个所有者（Owner），并且在任意时刻，每个值只能有一个所有者。

• 作用：当所有者超出作用域（Scope）时，值会被自动销毁（Drop），从而释放分配的内存。


示例：

```rust
{
    let s = String::from("hello"); // s 是字符串的所有者
} // s 超出作用域，被自动销毁
```


在这个例子中，`s`是字符串的所有者，当`s`超出作用域时，Rust 会调用`drop`函数来释放分配的内存。


2.移动（Move）

• 定义：当一个值的所有权从一个变量转移到另一个变量时，这个过程称为“移动”。

• 规则：移动后，原变量不再持有所有权，因此不能再次使用。

• 适用类型：默认情况下，所有自定义类型（如`String`、`Vec`等）和一些复杂类型（如`Box`）都遵循移动规则。


示例：

```rust
let s1 = String::from("hello");
let s2 = s1; // s1 的所有权被移动到 s2
// println!("{}", s1); // 错误：s1 已经失去所有权
println!("{}", s2); // 正确
```


在这个例子中，`s1`的所有权被移动到`s2`，因此`s1`不再有效。


3.复制（Copy）

• 定义：对于一些简单的数据类型（如整数、浮点数、布尔值等），Rust 提供了“复制”语义。

• 规则：当变量被赋值给另一个变量时，数据会被复制一份，两个变量都是独立的。

• 适用类型：所有实现了`Copy`特性（Trait）的类型，如`i32`、`f64`、`bool`等。


示例：

```rust
let x = 5;
let y = x; // x 的值被复制到 y，x 和 y 都可以使用
println!("x = {}, y = {}", x, y); // 正确
```


在这个例子中，`x`的值被复制到`y`，因此`x`和`y`都是独立的。


4.借用（Borrowing）

• 定义：在 Rust 中，可以通过引用（Reference）来访问一个值，而不改变其所有权。

• 规则：

1. 引用分为可变引用（`&mut T`）和不可变引用（`&T`）。

2. 同一时间，一个值只能有一个可变引用或多个不可变引用。

3. 引用必须始终有效，不能悬垂（Dangling）。


示例：

```rust
let s = String::from("hello");
let len = calculate_length(&s); // 使用不可变引用
println!("The length of '{}' is {}.", s, len);

fn calculate_length(s: &String) -> usize {
    s.len()
}
```


在这个例子中，`calculate_length`函数接收一个不可变引用，这样既不会改变`s`的所有权，也不会影响`s`的使用。


5.可变引用（Mutable References）

• 定义：可变引用允许修改被引用的值。

• 规则：

1. 同一时间，一个值只能有一个可变引用。

2. 可变引用和不可变引用不能同时存在。


示例：

```rust
let mut s = String::from("hello");
change(&mut s); // 使用可变引用

fn change(s: &mut String) {
    s.push_str(", world");
}
```


在这个例子中，`change`函数通过可变引用修改了`s`的内容。


6.悬挂引用（Dangling References）

• 定义：悬挂引用是指引用了一个已经被释放的值。

• 规则：Rust 编译器会阻止悬挂引用的出现。


错误示例：

```rust
fn dangle() -> &String {
    let s = String::from("hello");
    &s // 错误：s 超出作用域，引用悬垂
}
```


在这个例子中，`s`在函数返回时被销毁，返回的引用会悬垂，因此 Rust 编译器会报错。


7.所有权和函数

• 定义：函数可以接收所有权或引用，并返回所有权或引用。

• 规则：函数的参数和返回值的所有权转移遵循 Rust 的所有权规则。


示例：

```rust
fn takes_ownership(some_string: String) {
    println!("{}", some_string);
} // some_string 被销毁

fn makes_copy(some_integer: i32) {
    println!("{}", some_integer);
} // some_integer 被复制

let s = String::from("hello");
takes_ownership(s); // s 的所有权被移动到函数中

let x = 5;
makes_copy(x); // x 的值被复制到函数中
```



总结
Rust 的所有权系统通过以下方式确保内存安全：

1. 每个值都有一个所有者。

2. 所有权在变量之间移动时，原变量失效。

3. 借用机制允许临时访问值，而不改变所有权。

4. 编译器严格检查引用的有效性和作用域，避免悬挂引用和数据竞争。

所有权是 Rust 的核心特性之一，虽然初学者可能会觉得有些复杂，但它能够从根本上解决内存安全问题，同时提供高性能的内存管理机制。




LVGL开源库介绍
LVGL（Light and Versatile Graphics Library）是一个开源的嵌入式图形库，专为资源有限的微控制器（MCU）和微处理器（MPU）设计，能够创建美观的图形用户界面（GUI）。它以轻量级、高性能和高度可定制性著称，适用于各种嵌入式设备。
主要特点
1. 低资源占用：LVGL仅需最低32 KB的RAM和128 KB的Flash，适合资源受限的嵌入式系统。
2. 功能丰富：提供30多种内置控件（如按钮、滑块、图表等）、强大的样式系统、布局管理器和多语言排版支持。
3. 跨平台支持：兼容多种硬件平台和操作系统，包括Arduino、ESP32、STM32、NXP等。
4. 高度可定制：通过配置文件（如`lv_conf.h`）和宏定义，用户可以灵活调整库的功能和性能。
5. 活跃社区：LVGL拥有活跃的开发者社区，提供丰富的文档、示例代码和工具支持。


应用场景
• 智能设备：如智能手表、智能家居设备等。
• 工业控制：如工业控制面板、医疗设备显示屏。
• 教育与培训：作为教学工具，帮助学生学习嵌入式系统和GUI设计。


使用与部署
1. 安装：可以从GitHub克隆LVGL库，并根据需求配置开发环境。

```bash
   git clone https://github.com/lvgl/lvgl.git
   ```

2. 配置：通过`lv_conf.h`文件启用或禁用特定功能，优化内存使用。
3. 开发工具：LVGL支持多种开发工具，如PlatformIO、Arduino IDE等。


相关项目与工具
• LVGL-Watch：基于LVGL 8.0的开源智能手表固件项目，支持丰富的功能和硬件扩展。
• EEZ Studio：一款低代码可视化工具，支持LVGL，适合快速设计和开发嵌入式GUI。


优势总结

• 轻量级设计：适合低性能硬件，即使在资源受限的设备上也能流畅运行。
• 高性能渲染：支持动画、抗锯齿、阴影等高级特性。
• 开源与免费：遵循MIT协议，完全免费，适合商业和非商业项目。
LVGL是一个强大的开源图形库，适用于嵌入式系统开发，无论是初学者还是专业开发者，都能从中受益。

要读懂C++代码报错的汇编代码，可以按照以下步骤进行：


1.生成汇编代码
使用编译器将C++代码编译为汇编代码。例如，使用`g++`可以执行以下命令：

```bash
g++ -S yourfile.cpp -o output.s
```

这会生成一个`.s`文件，其中包含汇编代码。


2.理解符号名称
C++的函数名在汇编中会被“名称修饰”（name mangling），例如`C0::c0f1`会被编译器转换为`_ZN2C04c0f1Ev`。可以使用`c++filt`工具对这些符号进行反修饰，使其更易读。


3.查看汇编代码

• 使用调试器：如果已经有可执行文件，可以使用GDB等调试器查看汇编代码。例如：

```bash
  gdb ./yourprogram
  (gdb) disassemble main
  ```

这将显示`main`函数的汇编代码。

• 使用IDE：在Visual Studio等IDE中，可以直接在调试模式下查看汇编代码。将光标放在代码的某一行，右键选择“Go To Disassembly”。


4.分析报错的汇编代码

• 定位报错位置：在调试器中，查看崩溃时的寄存器状态和指令指针（IP），找到出错的汇编指令。

• 结合源代码：将汇编代码与C++源代码对照阅读，理解指令与代码的对应关系。

• 上下文分析：查看报错指令的上下文，理解指令的逻辑和数据依赖。


5.使用工具辅助分析

• IDA Pro：用于反汇编和分析二进制文件。可以加载可执行文件，查看汇编代码的上下文，并结合符号信息进行分析。

• Windbg：用于分析崩溃转储文件（dump）。可以通过Windbg查看崩溃时的汇编指令和寄存器状态。


6.注意事项

• 编译器优化会影响汇编代码的可读性，建议在Debug模式下生成汇编代码。

• 直接阅读汇编代码难度较大，建议结合调试器和工具进行分析。

通过以上方法，你可以逐步读懂C++代码报错的汇编代码，并定位问题。

Rust 的所有权系统是其核心特性之一，也是 Rust 语言区别于其他语言的重要机制。所有权系统的设计目标是通过编译时的规则来保证内存安全，而无需运行时的垃圾回收（GC）。以下是 Rust 所有权系统的详细解析：


---



1.所有权的基本概念


1.1 所有权（Ownership）

• 定义：所有权是 Rust 中管理内存的一种机制。每个值（变量、数据结构等）都有一个“所有者”，并且在任何时刻，一个值只能有一个所有者。

• 作用：当所有者超出作用域时，值将被自动销毁。这避免了内存泄漏和悬空指针等问题。


1.2 作用域（Scope）

• 定义：作用域是程序中变量或值的生命周期范围。当变量的作用域结束时，Rust 会自动调用`drop`方法来释放其占用的资源。

• 示例：

```rust
  {
      let x = String::from("hello"); // `x` 进入作用域
  } // `x` 退出作用域，资源被释放
  ```



---



2.所有权的规则


2.1 每个值都有一个所有者

• 在 Rust 中，每个值（如变量、结构体等）都有一个所有者，且在任何时刻只能有一个所有者。

• 示例：

```rust
  let s = String::from("hello"); // `s` 是字符串的所有者
  ```



2.2 当所有者超出作用域时，值将被销毁

• 当变量超出其作用域时，Rust 会自动调用`drop`方法释放其占用的资源。

• 示例：

```rust
  {
      let s = String::from("hello"); // `s` 进入作用域
      // 使用 `s`
  } // `s` 退出作用域，资源被释放
  ```



2.3 所有权的转移（Move）

• 当一个值被赋给另一个变量时，所有权会从一个变量转移到另一个变量。原变量将不再有效。

• 示例：

```rust
  let s1 = String::from("hello");
  let s2 = s1; // `s1` 的所有权被转移到 `s2`
  // println!("{}", s1); // 错误：`s1` 已经被移动，不再有效
  println!("{}", s2); // 正确
  ```



---



3.借用（Borrowing）


3.1 引用（Reference）

• Rust 提供了引用机制，允许在不转移所有权的情况下访问值。

• 不可变引用（Immutable Reference）：使用`&T`，表示对值的只读访问。

• 可变引用（Mutable Reference）：使用`&mut T`，表示对值的可写访问。

• 示例：

```rust
  let s = String::from("hello");
  let s_ref = &s; // 不可变引用
  println!("{}", s_ref);

  let mut s2 = String::from("hello");
  let s2_ref = &mut s2; // 可变引用
  s2_ref.push_str(", world");
  println!("{}", s2_ref);
  ```



3.2 借用规则

• 不可变引用：可以有多个不可变引用，但不能同时存在可变引用。

• 可变引用：在同一作用域中，只能有一个可变引用。

• 示例：

```rust
  let mut s = String::from("hello");
  let s1 = &s; // 不可变引用
  let s2 = &s; // 不可变引用
  // let s3 = &mut s; // 错误：不能同时存在可变引用
  println!("{}, {}", s1, s2);
  ```



---



4.生命周期（Lifetime）


4.1 生命周期的概念

• 生命周期是引用的存活时间范围。Rust 编译器需要确保引用在其生命周期内始终有效。

• 生命周期的引入是为了防止悬空指针问题。

• 示例：

```rust
  fn first_word(s: &str) -> &str {
      let bytes = s.as_bytes();
      for (i, &item) in bytes.iter().enumerate() {
          if item == b' ' {
              return &s[0..i];
          }
      }
      &s[..]
  }
  ```



4.2 生命周期注解

• 在某些情况下，Rust 编译器无法自动推导引用的生命周期，需要手动添加生命周期注解。

• 示例：

```rust
  fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
      if x.len() > y.len() {
          x
      } else {
          y
      }
  }
  ```



---



5.克隆（Clone）和拷贝（Copy）


5.1 Clone

• `Clone`是一个 trait，用于显式地复制值。

• 当调用`.clone()`时，会创建一个值的深拷贝。

• 示例：

```rust
  let s1 = String::from("hello");
  let s2 = s1.clone(); // 显式克隆
  println!("{}, {}", s1, s2);
  ```



5.2 Copy

• `Copy`是一个 trait，用于实现值的自动拷贝。

• 当一个类型实现了`Copy`trait 时，赋值操作不会转移所有权，而是自动进行拷贝。

• 示例：

```rust
  let x = 5;
  let y = x; // `x` 的值被自动拷贝，不会移动
  println!("{}, {}", x, y);
  ```



---



6.所有权与函数


6.1 函数参数和返回值的所有权

• 当值作为参数传递给函数时，所有权会转移到函数内部。

• 如果函数返回一个值，所有权会转移到调用者。

• 示例：

```rust
  fn takes_ownership(s: String) {
      println!("{}", s);
  }

  fn returns_ownership() -> String {
      String::from("hello")
  }

  let s = String::from("hello");
  takes_ownership(s); // `s` 的所有权被转移
  // println!("{}", s); // 错误：`s` 已经被移动

  let s2 = returns_ownership(); // 返回值的所有权被转移
  println!("{}", s2);
  ```



6.2 借用与函数

• 函数可以接受引用作为参数，从而避免所有权的转移。

• 示例：

```rust
  fn calculate_length(s: &String) -> usize {
      s.len()
  }

  let s = String::from("hello");
  let length = calculate_length(&s); // 传递引用，不转移所有权
  println!("The length of '{}' is {}.", s, length);
  ```



---



7.总结

Rust 的所有权系统通过以下机制保证内存安全：

1. 所有权：每个值都有一个所有者，且在任何时刻只能有一个所有者。

2. 作用域：当所有者超出作用域时，值将被自动销毁。

3. 借用：通过引用访问值，而不转移所有权。

4. 生命周期：确保引用在其生命周期内始终有效。

5. 克隆和拷贝：通过`Clone`和`Copy`实现值的显式或自动拷贝。

所有权系统的核心目标是通过编译时的规则来避免内存泄漏、悬空指针和数据竞争等问题，同时保持高性能。虽然初学者可能会觉得所有权系统有些复杂，但一旦理解其原理，它将成为编写安全、高效 Rust 程序的强大工具。





`mod.rs`文件在 Rust 中用于定义模块和组织子模块，其支持可以追溯到 Rust 的早期版本。在 Rust 1.30 版本之前，`mod.rs`是定义嵌套子模块的唯一方式。从 Rust 1.30 开始，引入了新的模块命名约定，允许直接使用`<module_name>.rs`文件来定义模块，而不再强制要求使用`mod.rs`。

尽管如此，`mod.rs`仍然被广泛支持，并且在一些项目中仍然被使用，尤其是在需要清晰组织子模块时。





在 Rust 中，`mod.rs`文件是模块系统中的一个重要组成部分，它的作用主要体现在以下几个方面：


1.模块的定义和组织

• 模块的作用域：`mod.rs`文件用于定义一个模块的作用域。当你在一个目录下创建一个`mod.rs`文件时，这个目录就成为了一个模块的私有作用域。你可以在这个文件中定义模块内的公共（`pub`）和私有（`private`）项（如函数、结构体、枚举等）。

• 子模块的组织：如果一个模块包含多个子模块，`mod.rs`文件可以将这些子模块组织起来。例如，你可以在`mod.rs`文件中声明子模块，并在子模块的目录中使用`mod.rs`文件进一步组织内容。


2.模块的声明和引用

• 声明子模块：在`mod.rs`文件中，你可以使用`mod`关键字声明子模块。例如：

```rust
  mod submodule;
  ```

这会告诉 Rust 编译器在当前模块的目录下查找一个名为`submodule.rs`或`submodule/mod.rs`的文件，并将其内容作为子模块加载。

• 引用模块内容：通过在`mod.rs`文件中声明模块和子模块，你可以方便地在父模块中引用子模块的内容。例如：

```rust
  pub mod submodule {
      pub fn function() {
          println!("This is a function in submodule.");
      }
  }
  ```



3.封装和私有化

• 封装功能：`mod.rs`文件可以将相关功能封装在一起，形成一个逻辑单元。模块内部的私有项（未标记为`pub`的项）只能在模块内部访问，这有助于隐藏实现细节，减少模块之间的耦合。

• 控制可见性：通过在`mod.rs`文件中定义模块的公共接口（`pub`），你可以控制哪些功能可以被外部代码使用，哪些功能是内部实现细节。


4.方便的目录结构

• 清晰的目录结构：使用`mod.rs`文件可以让你的项目目录结构更加清晰。例如，一个复杂的模块可以被拆分成多个子模块，每个子模块都有自己的`mod.rs`文件，这样可以方便地管理代码。

• 避免文件命名冲突：在大型项目中，多个子模块可能会有相同的文件名。通过使用`mod.rs`文件，你可以避免这种命名冲突，同时保持模块的清晰组织。


示例
假设你有一个项目结构如下：


```
src/
├── main.rs
├── my_module/
│   ├── mod.rs
│   ├── submodule1.rs
│   ├── submodule2/
│       └── mod.rs
```



• `my_module/mod.rs`文件内容：

```rust
  pub mod submodule1;
  pub mod submodule2;
  ```



• `my_module/submodule1.rs`文件内容：

```rust
  pub fn function1() {
      println!("Function 1 in submodule1");
  }
  ```



• `my_module/submodule2/mod.rs`文件内容：

```rust
  pub fn function2() {
      println!("Function 2 in submodule2");
  }
  ```


在`main.rs`中，你可以这样引用这些模块：

```rust
mod my_module;

fn main() {
    my_module::submodule1::function1();
    my_module::submodule2::function2();
}
```



总结
`mod.rs`文件是 Rust 模块系统的核心组成部分，它用于定义模块的作用域、组织子模块、封装功能以及控制可见性。通过合理使用`mod.rs`文件，你可以构建清晰、可维护的项目结构。

Tomcat 的`sessionId`是由 Tomcat 服务器自己生成的，而不是来自 Postman。


生成机制

• 当客户端第一次访问 Tomcat 服务器时，通过调用`HttpServletRequest.getSession(true)`方法，Tomcat 会创建一个新的`HttpSession`对象，并为其生成一个唯一的`sessionId`。

• `sessionId`的生成由`ManagerBase`类中的`generateSessionId()`方法完成，通常使用随机数、时间戳以及 JVM 的唯一标识（`JvmRoute`）等信息组合生成。

• 默认情况下，Tomcat 使用`StandardSessionIdGenerator`类来生成`sessionId`。


Postman 的作用

• Postman 是一个 API 测试工具，它可以用来发送 HTTP 请求并接收响应。

• 当 Postman 发送请求到 Tomcat 服务器时，如果请求中没有携带`sessionId`，Tomcat 会生成一个新的`sessionId`并返回给 Postman。

• Postman 可以通过响应头中的`Set-Cookie`字段获取到`sessionId`，并在后续的请求中将其作为`Cookie`发送给服务器。


总结
Tomcat 的`sessionId`是由 Tomcat 自己生成的，用于标识客户端的会话。Postman 只是一个工具，用于发送请求和接收响应，并不参与`sessionId`的生成过程。

---

### 1. 构建 Vue 项目
首先确保你的 Vue 项目已经构建完成（生成静态文件）：
```bash
npm run build
```
构建产物默认会生成在 `dist` 目录下。

### 2. Apache 部署配置
#### (1) 将 `dist` 目录文件放到 Apache 的 Web 根目录
- 例如，将 `dist` 目录下的所有文件复制到 Apache 的默认站点目录（如 `/var/www/html`）。
- 或者，在 Apache 的虚拟主机配置中指定目录路径。

#### (2) 配置 Apache 虚拟主机
修改 Apache 的配置文件（如 `/etc/apache2/sites-available/000-default.conf` 或新建一个配置文件），示例如下：
```apache
<VirtualHost *:80>
    ServerName your-domain.com
    DocumentRoot /path/to/your/vue-project/dist

    <Directory "/path/to/your/vue-project/dist">
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
        FallbackResource /index.html
    </Directory>

    # 可选：配置 Gzip 压缩
    <IfModule mod_deflate.c>
        AddOutputFilterByType DEFLATE text/html text/css application/javascript
    </IfModule>
</VirtualHost>
```

#### (3) 启用 `mod_rewrite` 模块（解决前端路由问题）
如果 Vue 使用了 history 模式（如 `vue-router`），需确保 Apache 的 `mod_rewrite` 已启用，并在项目目录中添加 `.htaccess` 文件：
```bash
# 启用 mod_rewrite
sudo a2enmod rewrite
sudo systemctl restart apache2
```

在 `dist` 目录下创建 `.htaccess` 文件：
```apache
<IfModule mod_rewrite.c>
    RewriteEngine On
    RewriteBase /
    RewriteRule ^index\.html$ - [L]
    RewriteCond %{REQUEST_FILENAME} !-f
    RewriteCond %{REQUEST_FILENAME} !-d
    RewriteRule . /index.html [L]
</IfModule>
```

#### (4) 重启 Apache 服务
```bash
sudo systemctl restart apache2
```

---

### 3. 验证部署
访问 `http://your-domain.com`，检查 Vue 应用是否正常加载，且前端路由（如刷新页面或直接访问子路径）无 404 错误。

---

### 关键注意事项
1. 权限问题  
   确保 Apache 用户（如 `www-data`）对项目目录有读取权限：
   ```bash
   sudo chown -R www-data:www-data /path/to/your/vue-project/dist
   ```

2. 前端路由模式  
   - 如果使用 hash 模式（URL 中有 `#`），无需额外配置。
   - 如果使用 history 模式，必须通过 `.htaccess` 或 FallbackResource 将所有请求重定向到 `index.html`。

3. 性能优化  
   Apache 和 Nginx 在性能上的差异对于小型项目可以忽略。如需高并发，可考虑优化 Apache 配置（如启用 `mod_cache` 和 `mod_expires`）或换用 Nginx。

### 总结
- Apache 完全可以替代 Nginx 部署 Vue 项目，只需正确配置静态文件托管和路由重定向。
- 选择 Apache 还是 Nginx 通常取决于你的熟悉程度和服务器环境需求。
