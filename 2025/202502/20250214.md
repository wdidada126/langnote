CPU with SSE4.1
SSE4.1 是 Streaming SIMD Extensions 4.1 的缩写，即单指令多数据扩展指令集 4.1，是英特尔公司开发的一种 CPU 指令集扩展技术，具有以下特点和作用：
技术特点
提高数据处理效率：SSE4.1 指令集增加了新的指令，能够在一条指令中同时对多个数据进行操作，这种并行处理能力可以显著提高 CPU 在处理特定类型数据时的效率。
增强多媒体处理能力：它针对多媒体应用进行了优化，例如在视频编码、解码、图像渲染、音频处理等方面，能够更高效地处理相关数据，提升多媒体处理的速度和质量。
提升计算性能：对于一些需要进行大量数据运算的应用，如科学计算、金融分析等，SSE4.1 指令集可以通过并行计算和优化的数据处理方式，减少计算时间，提高整体计算性能。
应用场景
视频编码与解码：在视频编辑软件、视频播放应用以及视频流服务中，SSE4.1 有助于加速视频的编码和解码过程，使高清视频甚至 4K、8K 视频的处理更加流畅，减少卡顿现象，提高视频播放的帧率和画质。
图像与图形处理：在图像处理软件如 Adobe Photoshop 等中，SSE4.1 可以加速图像的滤镜效果、色彩调整、缩放等操作。在游戏开发和图形渲染中，也能提升 3D 图形的渲染速度和质量，使游戏画面更加细腻、流畅，减少锯齿和延迟。
音频处理：在音频编辑软件和音乐制作中，SSE4.1 能够加快音频的混音、特效添加、格式转换等处理速度，提高音频处理的效率和质量，让用户能够更快速地完成音频制作任务。
如果 CPU 支持 SSE4.1 指令集，那么在运行支持该指令集的软件时，能够充分发挥其性能优势，提升软件的运行效率和响应速度。但如果软件不支持 SSE4.1 指令集，那么 CPU 的这一特性就无法得到充分利用。

在 Spring Boot 中，可以通过 application.properties 或 application.yml 文件来配置 Tomcat 的会话 Cookie，也可以通过编程方式进一步自定义配置。以下是具体的配置方法：
1. 通过 application.properties 配置
Spring Boot 提供了 server.servlet.session.cookie.* 命名空间来配置会话 Cookie 的属性。以下是一些常用的配置示例：
# 自定义会话 Cookie 名称
server.servlet.session.cookie.name=CUSTOM_SESSION_ID
# 设置 Cookie 的路径
server.servlet.session.cookie.path=/
# 设置 Cookie 的域名
server.servlet.session.cookie.domain=.yourdomain.com
# 设置 Cookie 的最大存活时间（秒）
server.servlet.session.cookie.max-age=3600
# 是否启用 HttpOnly 标志
server.servlet.session.cookie.http-only=true
# 是否启用 Secure 标志（仅通过 HTTPS 传输）
server.servlet.session.cookie.secure=true
# 设置会话超时时间（如 30 分钟）
server.servlet.session.timeout=30m
2. 通过编程方式配置
如果需要更灵活的配置，可以通过实现 EmbeddedServletContainerCustomizer 接口来动态配置。例如：
import org.springframework.boot.web.server.WebServerFactoryCustomizer;
import org.springframework.boot.web.embedded.tomcat.TomcatServletWebServerFactory;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
@Configuration
public class CustomTomcatConfig {
    @Bean
    public WebServerFactoryCustomizer<TomcatServletWebServerFactory> containerCustomizer() {
        return factory -> {
            factory.addContextCustomizers(context -> {
                context.setSessionCookieConfig(config -> {
                    config.setName("CUSTOM_SESSION_ID"); // 自定义会话 Cookie 名称
                    config.setDomain(".yourdomain.com"); // 设置域名
                    config.setPath("/"); // 设置路径
                    config.setHttpOnly(true); // 启用 HttpOnly 标志
                    config.setSecure(true); // 启用 Secure 标志
                    config.setMaxAge(3600); // 设置最大存活时间（秒）
                });
            });
        };
    }
}
3. 使用 Spring Session 进行高级会话管理
如果需要更高级的会话管理功能（例如分布式会话存储），可以引入 Spring Session。Spring Session 提供了对 Redis、JDBC 等存储的集成，可以将会话数据存储在外部存储中，从而支持分布式部署。
首先，添加依赖：
<dependency>
    <groupId>org.springframework.session</groupId>
    <artifactId>spring-session-core</artifactId>
</dependency>
然后，启用 Spring Session 并自定义会话存储：
import org.springframework.context.annotation.Bean;
import org.springframework.session.MapSessionRepository;
import org.springframework.session.config.annotation.web.http.EnableSpringHttpSession;
@EnableSpringHttpSession
public class SessionConfig {
    @Bean
    public MapSessionRepository sessionRepository() {
        return new MapSessionRepository(new ConcurrentHashMap<>());
    }
}
通过上述方法，可以在 Spring Boot 中灵活地配置和管理 Tomcat 的会话 Cookie。

当浏览器禁用 Cookie 时，session 信息无法通过 Cookie 自动传递，但可以通过以下几种方式将 session ID 传递给前端：
1. URL 重写
服务器可以在生成的每个 URL 中附加 session ID，客户端在后续请求中通过 URL 将 session ID 传递回服务器。例如：
•  http://example.com/page?jsessionid=abc123
•  或者使用路径形式：http://example.com/page;jsessionid=abc123。
2. 表单隐藏字段
在 HTML 表单中添加一个隐藏字段，用于存储 session ID。当表单提交时，session ID 会随表单数据一起发送到服务器。例如：
<form action="nextPage.jsp" method="post">
  <input type="hidden" name="sessionId" value="<%= sessionId %>" />
  <input type="submit" value="Submit" />
</form>
3. 自定义请求头
前端可以在每个请求中通过自定义请求头（如 X-Session-ID）传递 session ID。例如：
fetch('/api/data', {
  method: 'GET',
  headers: {
    'X-Session-ID': 'your-session-id'
  }
});
4. 请求参数
将 session ID 作为请求参数传递。例如：
fetch(`/api/data?sessionId=${sessionId}`, {
  method: 'GET'
});
后端需要从请求参数中提取 session ID。
注意事项
•  安全性：通过 URL 或表单传递 session ID 会增加安全风险，因为 session ID 会以明文形式暴露在 URL 或表单中，容易被第三方劫持。
•  用户体验：URL 重写可能导致 URL 过长，影响用户体验。
通过上述方式，即使浏览器禁用了 Cookie，也可以继续使用 session 机制，但需要在服务器端进行相应的代码修改和配置。


在嵌入式 Tomcat 9 中，sessionId 的生成是由后端的 SessionIdGenerator 组件负责的。具体来说，sessionId 的生成逻辑主要涉及以下类和方法：
1.  SessionIdGenerator 接口：
•  这是 Tomcat 提供的接口，用于定义会话 ID 的生成逻辑。
•  其标准实现是 StandardSessionIdGenerator。
2.  SessionIdGeneratorBase 类：
•  这是 SessionIdGenerator 的一个基础实现类，负责生成安全的随机会话 ID。
•  它使用 SecureRandom 来生成随机数，并确保生成的会话 ID 是唯一的。
3.  ManagerBase 类：
•  这是会话管理器的基类，负责创建和管理会话对象。
•  在创建会话时，ManagerBase 类会调用 generateSessionId() 方法来生成新的 sessionId。
4.  generateSessionId() 方法：
•  这个方法在 ManagerBase 类中被调用，用于生成新的会话 ID。
•  它会委托给 SessionIdGenerator 的实现类（如 StandardSessionIdGenerator）来完成实际的 ID 生成。
示例代码
以下是 ManagerBase 类中生成 sessionId 的核心代码片段：
protected String generateSessionId() {
    String result = null;
    do {
        if (result != null) {
            duplicates++;
        }
        result = sessionIdGenerator.generateSessionId();
    } while (sessions.containsKey(result)); // 确保生成的 sessionId 是唯一的
    return result;
}
在上述代码中，sessionIdGenerator.generateSessionId() 是生成会话 ID 的关键调用。
配置会话 ID 生成器
如果需要自定义会话 ID 的生成逻辑，可以通过配置 SessionIdGenerator 来实现。例如，可以在 context.xml 中配置 Manager 元素来指定会话 ID 的长度和生成算法：
<Manager
    sessionIdLength="20"
    secureRandomAlgorithm="SHA1PRNG"
    secureRandomClass="java.security.SecureRandom"
/>
