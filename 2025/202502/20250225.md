Rust说到底，就是写web前端生态链工具链的在玩，其他用地方用得不多，前端写js的有些人想规避nodejs 和v8 cpp的历史原因。

在C++中，没有像Java或Python中那样的`finally`关键字。`finally`通常用于异常处理机制中，确保在`try`代码块执行完毕后，无论是否发生异常，`finally`代码块都会被执行。这种机制在C++中并不存在。

不过，C++提供了其他机制来实现类似的功能，比如RAII（Resource Acquisition Is Initialization），即资源获取即初始化。RAII是一种通过对象生命周期管理资源（如内存、文件句柄、锁等）的技术。当一个对象被创建时，它会获取资源；当对象被销毁时，它会释放资源。通过RAII，可以确保资源在对象生命周期结束时被正确释放，从而实现类似`finally`的功能。

例如：


```cpp
class ScopedResource {
public:
    ScopedResource() {
        // 获取资源
        acquireResource();
    }

    ~ScopedResource() {
        // 释放资源
        releaseResource();
    }

private:
    void acquireResource() {
        // 打开文件、分配内存等
    }

    void releaseResource() {
        // 关闭文件、释放内存等
    }
};

void someFunction()    {
 try {
        ScopedResource resource;
        // 可能抛出异常的代码
    } catch (...) {
        // 处理异常
    }
    // 无论是否发生异常，ScopedResource的析构函数都会被调用，资源会被释放
}
```


在这个例子中，`ScopedResource`对象的生命周期确保了资源的获取和释放。即使在`try`代码块中发生异常，`ScopedResource`的析构函数也会被调用，从而保证资源被正确释放。

此外，C++23标准引入了`std::scope_exit`，可以更直接地实现类似`finally`的功能。`std::scope_exit`允许在作用域结束时执行一段代码，无论是否发生异常。例如：


```cpp
#include <scope>

void someFunction() {
    try {
        // 可能抛出异常的代码
    } catch (...) {
        // 处理异常
    }
    std::scope_exit {
        // 作用域结束时执行的代码，类似finally
        std::cout << "This will be executed at scope exit." << std::endl;
    };
}
```

总之，虽然C++没有`finally`关键字，但通过RAII和`std::scope_exit`等机制，可以实现类似的功能。
