在Java中使用 ESAPI（OWASP Enterprise Security API） 处理JSON数据中的XSS漏洞时，需确保对JSON中的所有字符串字段进行适当的编码或验证。以下是针对JSON数据的XSS防护方案，结合ESAPI实现：

### 1. 核心思路
- 遍历JSON结构：递归处理JSON中的每个字段（包括嵌套对象和数组），对所有字符串值进行XSS过滤。
- 上下文敏感编码：根据数据最终的使用场景（HTML、JavaScript、URL等），选择合适的编码方式。
- 避免破坏JSON结构：确保编码操作不会损坏JSON的语法（如引号、转义符等）。

### 2. 依赖配置
确保项目中包含ESAPI依赖：
```xml
<dependency>
    <groupId>org.owasp.esapi</groupId>
    <artifactId>esapi</artifactId>
    <version>2.5.0.0</version> <!-- 使用最新版本 -->
</dependency>
```

### 3. 实现代码示例
#### (1) 递归处理JSON数据
使用`org.json`库或其他JSON解析工具（如Jackson/Gson），遍历所有字符串字段并编码：

```java
import org.owasp.esapi.Encoder;
import org.owasp.esapi.reference.DefaultEncoder;
import org.json.JSONObject;
import org.json.JSONArray;

public class JsonXssFilter {
    private static final Encoder encoder = DefaultEncoder.getInstance();

    public static Object sanitizeJson(Object data) {
        if (data instanceof JSONObject) {
            return sanitizeJsonObject((JSONObject) data);
        } else if (data instanceof JSONArray) {
            return sanitizeJsonArray((JSONArray) data);
        } else if (data instanceof String) {
            // 根据上下文选择合适的编码（此处以HTML为例）
            return encoder.encodeForHTML((String) data);
        }
        return data;
    }

    private static JSONObject sanitizeJsonObject(JSONObject jsonObject) {
        JSONObject sanitized = new JSONObject();
        for (String key : jsonObject.keySet()) {
            Object value = jsonObject.get(key);
            sanitized.put(key, sanitizeJson(value));
        }
        return sanitized;
    }

    private static JSONArray sanitizeJsonArray(JSONArray jsonArray) {
        JSONArray sanitized = new JSONArray();
        for (int i = 0; i < jsonArray.length(); i++) {
            Object value = jsonArray.get(i);
            sanitized.put(sanitizeJson(value));
        }
        return sanitized;
    }
}
```

#### (2) 使用示例
```java
// 原始JSON数据（可能包含XSS payload）
String rawJson = "{\"name\": \"<script>alert(1)</script>\", \"nested\": {\"data\": \"javascript:alert(1)\"}}";
JSONObject input = new JSONObject(rawJson);

// 执行XSS过滤
JSONObject sanitized = JsonXssFilter.sanitizeJsonObject(input);

// 输出结果：{"name":"&lt;script&gt;alert(1)&lt;/script&gt;","nested":{"data":"javascript:alert(1)"}}
System.out.println(sanitized.toString());
```

### 4. 上下文敏感编码
根据数据最终使用场景选择ESAPI编码方法：

| 上下文         | ESAPI编码方法                     | 示例场景                     |
|---------------------|---------------------------------------|------------------------------|
| HTML Body       | `encodeForHTML()`                    | 数据插入到HTML元素内容中      |
| HTML Attribute  | `encodeForHTMLAttribute()`           | 数据作为HTML属性值（如`href`）|
| JavaScript      | `encodeForJavaScript()`              | 数据嵌入到JavaScript代码中    |
| URL             | `encodeForURL()`                     | 数据作为URL参数              |
| CSS             | `encodeForCSS()`                     | 数据插入到CSS样式            |

---

### 5. 进阶优化
#### (1) 白名单验证
在编码前，可通过正则表达式或白名单策略验证数据格式（如邮箱、电话号码）：
```java
public static String validateAndEncode(String input, String regex) {
    if (!input.matches(regex)) {
        throw new IllegalArgumentException("Invalid input format");
    }
    return encoder.encodeForHTML(input);
}
```

#### (2) 自定义序列化（Jackson/Gson）
在JSON序列化阶段自动应用编码：
```java
// 使用Jackson自定义序列化器
public class XssSafeSerializer extends JsonSerializer<String> {
    @Override
    public void serialize(String value, JsonGenerator gen, SerializerProvider provider) 
      throws IOException {
        String encoded = encoder.encodeForHTML(value);
        gen.writeString(encoded);
    }
}

// 注册到ObjectMapper
ObjectMapper mapper = new ObjectMapper();
SimpleModule module = new SimpleModule();
module.addSerializer(String.class, new XssSafeSerializer());
mapper.registerModule(module);
```

#### (3) 性能优化
- 避免重复解析JSON，尽量在一次遍历中完成所有操作。
- 使用缓存机制减少Encoder实例化开销。

---

### 6. 注意事项
1. 不要过度编码：确保编码后的JSON仍为合法结构（如保留引号`"`）。
2. 区分数据类型：仅对字符串类型编码，避免误处理数字、布尔值等。
3. 前端协作：即使后端已编码，前端也需根据上下文再次处理（防御深度防御策略）。

---

通过上述方法，可以系统化地防御JSON数据中的XSS攻击。需根据实际场景调整编码策略，并配合其他安全措施（如CSP、输入验证）形成完整防护体系。

以下是 Java Servlet 中 `forward`（请求转发）和 `redirect`（重定向）的完整代码示例及区别说明：

---

### 1. Forward（请求转发）
#### 代码示例
```java
@WebServlet("/sourceServlet")
public class SourceServlet extends HttpServlet {
    protected void doGet(HttpServletRequest request, HttpServletResponse response) 
            throws ServletException, IOException {
        
        // 设置请求属性（传递数据）
        request.setAttribute("message", "Hello from SourceServlet!");
        
        // 获取 RequestDispatcher 对象，并转发到目标 Servlet/JSP
        RequestDispatcher dispatcher = request.getRequestDispatcher("/targetServlet");
        dispatcher.forward(request, response);
    }
}

@WebServlet("/targetServlet")
public class TargetServlet extends HttpServlet {
    protected void doGet(HttpServletRequest request, HttpServletResponse response) 
            throws ServletException, IOException {
        
        // 获取转发来的数据
        String message = (String) request.getAttribute("message");
        response.getWriter().println("Forwarded Message: " + message);
    }
}
```

#### 关键特性
- 服务器端跳转：客户端浏览器无感知，地址栏 URL 不变。
- 共享请求数据：通过 `request.setAttribute()` 传递数据。
- 路径规则：使用相对路径或绝对路径（以 `/` 开头时，相对于当前 Web 应用的根目录）。

---

### 2. Redirect（重定向）
#### 代码示例
```java
@WebServlet("/redirectServlet")
public class RedirectServlet extends HttpServlet {
    protected void doGet(HttpServletRequest request, HttpServletResponse response) 
            throws ServletException, IOException {
        
        // 将数据存入 Session（用于跨请求传递）
        HttpSession session = request.getSession();
        session.setAttribute("redirectMessage", "Hello from RedirectServlet!");
        
        // 重定向到目标地址
        response.sendRedirect(request.getContextPath() + "/targetPage.jsp");
    }
}
```

#### 目标 JSP 页面 (`targetPage.jsp`)  
```jsp
<%@ page contentType="text/html;charset=UTF-8" language="java" %>
<html>
<head>
    <title>Target Page</title>
</head>
<body>
    <%
        // 从 Session 中获取数据
        String message = (String) session.getAttribute("redirectMessage");
    %>
    <h1>Redirected Message: <%= message %></h1>
</body>
</html>
```

#### 关键特性
- 客户端跳转：浏览器会发起新请求，地址栏 URL 变化。
- 无法直接共享请求数据：需通过 `Session` 或 URL 参数（如 `response.sendRedirect("target?param=value")`）传递数据。
- 路径规则：必须使用绝对路径（`request.getContextPath()` 确保路径正确）。

---

### 3. 对比总结
| 特性              | Forward（转发）                     | Redirect（重定向）               |
|-----------------------|-----------------------------------|---------------------------------|
| 请求次数           | 1 次（服务器内部处理）             | 2 次（浏览器发起新请求）         |
| 地址栏变化         | 否                                | 是                              |
| 数据传递方式       | `request.setAttribute()`          | `Session` 或 URL 参数           |
| 目标资源类型       | 同一 Web 应用内的资源              | 任意 URL（可跨应用或外部站点）   |
| 性能               | 更高（无额外网络请求）             | 较低（两次请求）                 |

---

### 4. 使用场景
- Forward：  
  - 需要共享请求数据的场景（如表单提交后跳转到结果页）。  
  - 隐藏实际资源路径（如权限控制后转发到登录页）。  

- Redirect：  
  - 防止表单重复提交（POST-REDIRECT-GET 模式）。  
  - 跳转到外部站点或不同 Web 应用的资源。  

---
