# 20251028
这个错误表明程序运行时找不到 libre2.so.11 动态链接库。以下是完整的解决方案：

问题原因

1. 您通过源码安装了 RE2 库（安装到 /usr/local/lib）
2. 但系统默认的库搜索路径不包含 /usr/local/lib
3. 卸载系统包 libre2-dev 后，动态链接库路径更混乱

解决方案

方法 1：临时解决方案（快速验证）

# 临时添加 /usr/local/lib 到库搜索路径
export LD_LIBRARY_PATH=/usr/local/lib:$LD_LIBRARY_PATH
./your_program


方法 2：永久解决方案（推荐）

# 1. 创建RE2库的配置文件
sudo bash -c 'echo "/usr/local/lib" > /etc/ld.so.conf.d/re2.conf'

# 2. 更新动态链接器缓存
sudo ldconfig

# 3. 验证库是否被找到
ldconfig -p | grep libre2

应该会显示：

libre2.so.11 (libc6,x86-64) => /usr/local/lib/libre2.so.11


方法 3：重新链接（如果方法2无效）

# 1. 检查已安装的RE2库
ls -l /usr/local/lib/libre2.*

# 2. 确保符号链接正确
sudo ln -sf /usr/local/lib/libre2.so.11.0.0 /usr/local/lib/libre2.so
sudo ldconfig

# 3. 重建项目
rm -rf build/ && mkdir build && cd build
cmake .. && make


方法 4：完全重装RE2（终极方案）

# 1. 彻底清理旧安装
sudo rm -rf /usr/local/include/re2 /usr/local/lib/libre2.*

# 2. 重新编译安装
cd re2
make clean
make -j$(nproc)
sudo make install
sudo ldconfig


CMake项目特别配置

在您的 CMakeLists.txt 中确保包含：
find_package(re2 REQUIRED)
target_link_libraries(your_target PRIVATE re2::re2)

或手动指定路径：
include_directories(/usr/local/include)
link_directories(/usr/local/lib)


错误排查命令

# 检查程序依赖的库
ldd ./your_program | grep re2

# 查看库搜索路径
echo $LD_LIBRARY_PATH
cat /etc/ld.so.conf.d/*.conf

# 验证库文件是否存在
ls -l /usr/local/lib/libre2.so*


GitHub Actions 适配

在 CI 中需要显式添加路径：
- name: Run tests
  run: |
    export LD_LIBRARY_PATH=/usr/local/lib:$LD_LIBRARY_PATH
    ./your_program


根本原因分析

1. Linux 默认不搜索 /usr/local/lib（除非配置了 /etc/ld.so.conf）
2. 源码安装和包管理器安装的库可能冲突
3. 动态链接器缓存（ldconfig）未及时更新

按照上述方法操作后，您的程序应该能正确找到 RE2 库。如果仍有问题，请提供：
1. ldd ./your_program 的输出
2. ls -l /usr/local/lib/libre2* 的结果
