## 为什么 `cl.exe` 不行？典型原因分析（以 cURL 为例）

### 1. GCC 扩展语法
```c
// cURL 中常见
#define inline __inline
__attribute__((visibility("default"))) void curl_function() { ... }
```
`cl.exe` 不支持 `__attribute__`，会报错 `C2059: syntax error: '__attribute__'`

### 2. POSIX 头文件
```c
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
```
这些头文件 仅在 MinGW/MSYS2 环境中存在，`cl.exe` + Windows SDK 无定义。

### 3. 内联汇编
```c
asm volatile ("cpuid" : ...);
```
`cl.exe` 使用 `__asm`，语法不同，且不支持 `volatile` 修饰。

### 4. `configure` 脚本依赖 GCC
```bash
checking for gcc... gcc
checking whether the C compiler works... yes
```
`configure` 检测到 `cl.exe` 会失败或跳过关键特性（如 `-fPIC`、`-pthread`）。

## 推荐 Windows 编译环境（2025 标准）

| 工具 | 版本 | 下载方式 |
|------|------|----------|
| MSYS2 | 2024-09-15+ | https://www.msys2.org |
| MinGW-w64 | GCC 13.2.0 或 14.1.0 | `pacman -S mingw-w64-x86_64-gcc` |
| CMake | 3.30+ | `pacman -S mingw-w64-x86_64-cmake` |
| Ninja | 1.12+ | `pacman -S mingw-w64-x86_64-ninja` |
| Git | 2.46+ | `pacman -S git` |

## 实战示例：编译 cURL 8.10.1（Windows）

```bash
# 1. 安装 MSYS2 + MinGW
# 打开 MSYS2 MinGW x64 终端

# 2. 安装依赖
pacman -S mingw-w64-x86_64-gcc
pacman -S mingw-w64-x86_64-cmake
pacman -S mingw-w64-x86_64-openssl
pacman -S mingw-w64-x86_64-zlib
pacman -S mingw-w64-x86_64-libssh2
pacman -S make

# 3. 下载 cURL
git clone https://github.com/curl/curl.git
cd curl
git checkout curl-8_10_1

# 4. 编译（必须用 MinGW）
./buildconf
./configure --prefix=/mingw64 --with-ssl --with-libssh2 --with-zlib
make -j8
make install
```

不能用 `cl.exe`：如果你尝试用 Visual Studio 开发者命令提示符运行 `nmake -f Makefile.vc`，会缺失大量 POSIX 支持，且汇编不兼容。

## 其他项目类似要求

| 项目 | 关键依赖 | 编译命令 |
|------|---------|----------|
| FFmpeg | `yasm`, `nasm`, `pkg-config` | `./configure --enable-shared --toolchain=mingw` |
| Git | `zlib`, `openssl`, `libiconv` | `make prefix=/mingw64` |
| nginx | `pcre2`, `openssl` | `./auto/configure --with-cc=gcc --prefix=/mingw64` |

## 总结：Windows 编译开源 C 项目黄金法则

| 规则 | 说明 |
|------|------|
| 有 `configure` 脚本 → 必须 MinGW | 99% Unix 移植项目 |
| 有 `__attribute__` → 必须 GCC | `cl.exe` 不支持 |
| 有 `unistd.h` / `sys/*.h` → 必须 MinGW | Windows SDK 无 |
| 有内联汇编 `asm(` → 必须 GCC | `cl.exe` 用 `__asm` |
| 有 `Makefile` 而无 `*.vcxproj` → 建议 MinGW | 避免 `nmake` 兼容性问题 |
