### C/C++ 构建工具中的分布式编译概述

C/C++ 项目编译耗时长，尤其是大型项目（如 Chromium、LLVM），分布式编译可以将编译任务分发到多台机器（本地或远程），显著加速构建过程。常见构建工具包括 Make、CMake、Ninja 等，这些工具支持并行编译（通过 `-j` 选项），但分布式需结合专用工具如 distcc、icecc（icecream）、ccache（缓存加速）、FASTBuild、yadcc 等。ccache 常与分布式工具结合使用，提供缓存机制，进一步提升效率。

分布式编译的核心原理：客户端预处理源代码，将独立编译任务（.c/.cpp 文件）分发到远程节点编译，远程节点返回对象文件（.o），客户端完成链接。挑战包括网络延迟、工具链一致性（编译器版本、库依赖）和防火墙配置。

以下基于开源工具和行业实践，详细说明常见工具及其设置方法。数据来源于 GitHub、CSDN、Stack Overflow 等公开资源（2025 年最新）。推荐从 distcc + ccache 开始，适合初学者。

#### 如何设置分布式编译（以 distcc + ccache 为例）

distcc 是最易上手的开源工具，支持 Linux/Mac/Windows。假设局域网有 3 台机器（客户端：192.168.1.100；服务器：192.168.1.101/102）。步骤如下（基于 Ubuntu/Debian，2025 年版本兼容）。

##### 1.  安装工具 
- 在所有机器上安装：
  ```
  sudo apt update
  sudo apt install distcc ccache gcc g++  # 或 clang
  ```
- Windows：使用 MSYS2 或 WSL；Mac：`brew install distcc ccache`。

##### 2.  配置服务器端（远程节点） 
- 在服务器（101/102）上启动 distccd 守护进程（监听端口 3632，默认 TCP）：
  ```
  sudo distccd --daemon --allow 192.168.1.0/24 --log-file /var/log/distccd.log
  ```
  - `--allow`：允许客户端 IP 段（CIDR 格式）。
  - 防火墙：`sudo ufw allow from 192.168.1.0/24 to any port 3632`。
  - 持久化：使用 systemd 服务（`/etc/systemd/system/distccd.service`）：
    ```
    [Unit]
    Description=distccd daemon
    [Service]
    ExecStart=/usr/bin/distccd --daemon --no-fork --allow 192.168.1.0/24
    Restart=always
    [Install]
    WantedBy=multi-user.target
    ```
    启用：`sudo systemctl enable --now distccd`。

- 工具链一致性：确保所有节点 GCC/Clang 版本相同（`gcc --version`）。若不同，使用容器（如 Docker）隔离。

##### 3.  配置客户端（发起构建机） 
- 设置环境变量（添加至 `~/.bashrc` 或 `~/.profile`，然后 `source ~/.bashrc`）：
  ```
  export DISTCC_HOSTS="localhost/4 192.168.1.101/8 192.168.1.102/8"  # localhost/核心数，远程/槽位（jobs）
  export CCACHE_PREFIX="distcc"  # ccache 前缀调用 distcc
  export PATH="/usr/lib/ccache:$PATH"  # ccache 包装器优先
  export CC="ccache gcc"  # 或 clang
  export CXX="ccache g++"
  ```
  - `DISTCC_HOSTS`：主机列表，格式 `host/maxjobs`（maxjobs ≈ 核心数 × 1.5）。
  - 若用 SSH 传输（更安全）：`export DISTCC_SSH_SERVERS="user@101 user@102"`，需配置无密码 SSH。

- 测试连接：
  ```
  distcc --show-hosts  # 显示可用主机
  distcc gcc -c -o test.o test.c  # 简单测试
  ```

##### 4.  集成构建系统 
-  Make ：
  ```
  make CC="ccache distcc gcc" CXX="ccache distcc g++" -j$(distcc -j)  # -j 自动计算总槽位
  ```
-  CMake （推荐，跨平台）：
  ```
  cmake -B build -S . -DCMAKE_C_COMPILER_LAUNCHER="ccache;distcc" -DCMAKE_CXX_COMPILER_LAUNCHER="ccache;distcc"
  cmake --build build -j$(distcc -j)
  ```
  - Ninja 生成器更快：`-G Ninja`。

-  缓存配置 （ccache）：
  - 共享缓存：`export CCACHE_DIR=/nfs/shared/ccache`（NFS 挂载）。
  - 清理：`ccache -C`；统计：`ccache -s`（命中率 >80% 为佳）。

##### 5.  验证与优化 
- 监控：`distccmon-gnome`（图形化显示任务分布）。
- 性能：首次全量构建慢（预处理），后续增量快。网络延迟 <10ms 最佳。
- 常见问题：
  - 编译失败：检查工具链版本、头文件路径（使用 pump 模式分发预处理：`distcc-pump`）。
  - 缓存失效：升级编译器后清空 ccache。
  - 加速倍数：4 机集群可达 3-4 倍（视网络/CPU）。

#### icecc (icecream) 的快速设置（高级选项）
若需中央调度：
1. 安装：`sudo apt install icecc icecc-monitor`。
2. 启动调度器（一台机）：`icecc-scheduler -d`。
3. 守护进程（所有节点）：`iceccd -d`。
4. 客户端：`export PATH="/usr/libexec/icecc/bin:$PATH"`；`make -jN`（N=总核心 ×2）。
5. 工具链打包：`icecc --build-native` 生成 tarball，分发一致环境。
更多：Fedora 指南 [ctrl.blog](https://www.ctrl.blog/entry/how-to-icecc-distributed-compiler.html)。

#### 其他工具简要设置
-  FASTBuild ：下载二进制，编写 `fbuild.bff` 配置目标，分发到多机运行 `fbuild.exe`。
-  yadcc ：`git clone https://github.com/Tencent/yadcc --recurse-submodules`；配置 `~/.yadrc`，运行 daemon，支持 Bazel。
-  商业：Incredibuild ：安装代理，VS 插件一键集成，无需手动配置。

分布式编译可将小时级构建缩短至分钟，但需网络稳定和一致环境。建议从小集群测试。若需特定工具（如 CMake 集成）或代码示例，请补充细节！

### Bazel 支持分布式编译的概述

Bazel 是 Google 开源的构建工具，专为大规模、多语言项目设计。它通过  远程执行 (Remote Execution)  和  远程缓存 (Remote Caching)  机制实现分布式编译。这些功能允许将编译任务分发到远程机器（如数据中心或云服务器）上执行，从而显著加速大型项目的构建过程，尤其适用于 C++、Java 等语言的复杂依赖图。

-  远程执行 ：将实际的编译动作（如编译源文件、运行测试）委托给远程 worker 节点执行，支持无限扩展的并行度。
-  远程缓存 ：缓存构建输出（如对象文件、库），避免重复编译相同的动作，提高增量构建效率。

这些功能基于开源的 gRPC 协议实现，与 Google 内部的 Blaze 系统类似，但 Bazel 提供灵活的开源实现。

---

### 关键特性
-  可扩展性 ：支持任意数量的远程机器，无需修改构建规则。动作（action）作为最小单位分发执行。
-  确定性构建 ：确保相同输入产生相同输出，支持沙箱执行，减少环境差异。
-  缓存重用 ：团队成员可共享缓存，减少重复工作；支持本地 + 远程缓存混合模式。
-  兼容性 ：适用于多平台、多语言项目，但需确保规则适应远程环境（如避免本地文件路径依赖）。

益处包括：构建时间缩短（例如，从小时级到分钟级）、一致的环境、CI/CD 集成优化。

---

### 如何配置和设置
要启用分布式编译，需要设置远程执行和缓存服务。Bazel 不内置服务器，但可集成第三方服务（如 BuildBuddy、EngFlow）或自建服务器。以下是基本步骤（基于 Bazel 官方文档，适用于 Bazel 7.x+ 版本）：

#### 1.  前提条件 
-  Bazel 版本 ：确保使用支持远程执行的版本（Bazel 0.15+，推荐最新版）。
-  规则适应 ：构建规则需符合远程执行要求，例如：
  - 使用相对路径，避免绝对路径或本地特定命令。
  - 工具链（如编译器）需在远程环境中可用（通过 Docker 或 hermetic 工具）。
  - 参考：https://docs.bazel.build/versions/main/remote-execution-rules.html。
-  网络 ：客户端需访问远程服务端口（通常 gRPC over HTTP/2）。
-  认证 ：大多数服务需 API 密钥或 OAuth。

#### 2.  配置 Bazel（客户端侧） 
在 `.bazelrc` 文件（项目根目录）中添加标志：
```
# 启用远程执行和缓存
build:remote --remote_executor=grpcs://your-service.example.com:443
build:remote --remote_cache=grpcs://your-cache.example.com:443

# 可选：并行度（默认自动）
build:remote --jobs=50  # 根据远程容量调整

# 认证示例（使用服务令牌）
build:remote --remote_header=authorization=Bearer your-token

# 实例命名（避免缓存冲突）
build:remote --remote_instance_name=your-project/instances/default
```
- `--remote_executor`：指定执行服务器 URL。
- `--remote_cache`：指定缓存服务器 URL。
- 运行构建：`bazel build //your:target --config=remote`。

#### 3.  设置远程服务（服务器侧） 
-  使用第三方服务 （推荐入门）：
  -  BuildBuddy ：免费层支持小项目。注册后获取 gRPC URL 和令牌，替换上述配置。 支持 UI 查看构建日志和缓存统计。
  -  EngFlow  或  Remote Build Execution ：企业级，集成 Google Cloud。
-  自建服务器 ：
  1. 安装 Bazel Remote Execution Proxy (REP) 或 BuildFarm（开源实现）。
     - GitHub: https://github.com/bazelbuild/remote-apis。
  2. 部署 worker 节点（Docker 容器，确保包含编译工具如 GCC/Clang）。
  3. 配置 Scheduler 和缓存后端（如 Redis、S3）。
  4. 启动服务：暴露 gRPC 端口。
-  Docker 支持 ：远程执行可使用平台描述（Platform）指定镜像，如 `--remote_platform=exec_properties:container-image=docker://ubuntu:20.04`。

#### 4.  测试和优化 
- 运行 `bazel build //... --config=remote --announce_rc` 查看远程使用情况。
- 监控：使用 `--remote_upload_local_results` 上传本地结果到缓存。
- 常见问题：
  - 缓存命中率低：确保输入确定性（使用 `--incompatible_strict_action_env`）。
  - 内存/超时：调整 `--remote_max_connections` 或 worker 配置。
- 性能提示：对于 C++ 项目，结合 `--copt` 优化编译器标志。

### 示例：简单 C++ 项目
假设项目有 `BUILD` 文件：
```
cc_binary(
    name = "hello",
    srcs = ["hello.cc"],
)
```
配置 `.bazelrc` 后，运行 `bazel build //:hello --config=remote`，Bazel 会将编译分发到远程节点，输出本地可用。

---

### 注意事项
-  安全性 ：远程执行暴露构建输入，使用 TLS (grpcs://) 和认证。
-  局限性 ：不适合所有规则（如需本地 I/O 的 genrule）；需测试兼容性。
-  资源 ：官方文档（https://bazel.build/remote-caching 和 https://docs.bazel.build/versions/main/remote-execution.html）提供最新细节。 对于 TensorFlow 等大型项目，可参考社区讨论集成 distcc 作为补充。

通过这些机制，Bazel 已成为 Google 等公司处理百万行代码的首选工具。如果需要特定服务的详细教程，请提供更多上下文！
