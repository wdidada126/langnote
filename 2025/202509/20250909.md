##  `explicit` 关键字：添加 vs 不添加的区别

###  作用
`explicit` 用于 防止隐式类型转换，只能用于 单参数构造函数（或支持单参数的转换构造）。


###  不加 `explicit`（允许隐式转换）

```cpp
class MyString {
public:
    MyString(const char* str) {
        // 构造逻辑
    }
};

void print(const MyString& s) {
    // 打印字符串
}

int main() {
    print("hello"); //  编译通过！
                    // 隐式转换：const char* → MyString
}
```

> ❗ 问题：可能引发意外转换，代码可读性差。

---

###  加 `explicit`（禁止隐式转换）

```cpp
class MyString {
public:
    explicit MyString(const char* str) {
        // 构造逻辑
    }
};

void print(const MyString& s) { /*...*/ }

int main() {
    print("hello");        // ❌ 编译错误！
    print(MyString("hello")); // ✅ 必须显式构造
}
```

---

###  最佳实践

```cpp
// 推荐写法：防止意外转换
explicit MyString(const std::string& s);
explicit MyString(int size);
```

>  除非你明确希望支持隐式转换，否则都加 `explicit`。

##  `std::string_view`（C++17）

###  用途
`std::string_view` 是一个 非拥有式（non-owning）的字符串视图，它不复制字符串内容，只持有指针和长度。

### 🎯 解决的问题
避免不必要的 `std::string` 构造和拷贝。

---

### 示例对比

#### ❌ 低效写法（拷贝）

```cpp
void log(const std::string& msg) {
    // 即使传 char*，也可能构造临时 string
}

log("Hello"); // 构造临时 std::string → 拷贝
```

####  高效写法（零拷贝）

```cpp
#include <string_view>

void log(std::string_view msg) {
    // 只传指针 + 长度，无拷贝
    std::cout << msg << std::endl;
}

log("Hello");           //  直接构造 string_view
log(std::string("Hi")); //  也可以从 string 构造
```


###  特点

| 特性 | 说明 |
|------|------|
| 零拷贝 | 不复制数据 |
| 轻量 | 通常只有两个成员：`const char*`, `size_t` |
| 安全风险 | 指向的数据必须比 `string_view` 活得久！ |
| 适用场景 | 函数参数、日志、解析、配置读取等 |

>  不要返回局部字符串的 `string_view`！

##  `std::optional<T>`（C++17）

###  用途
表示一个值 可能存在，也可能不存在，替代 `nullptr`、特殊值（如 `-1`）或 `bool + out param`。

---

### 示例：查找用户年龄

####  传统做法（不安全）

```cpp
int findAge(const std::string& name); // 找不到返回 -1？
```

####  使用 `optional`

```cpp
#include <optional>

std::optional<int> findAge(const std::string& name) {
    if (/* 找到 */) {
        return 30;
    } else {
        return std::nullopt; // 表示无值
    }
}

// 使用
if (auto age = findAge("Alice")) {
    std::cout << "Age: " << *age << std::endl;
} else {
    std::cout << "Not found" << std::endl;
}
```


###  优点

- 类型安全
- 可读性强
- 避免 magic number（如 -1）
- 支持 `operator->`, `value_or()`, `has_value()` 等

##  `std::pair<T, U>`

###  用途
存储 两个不同类型的数据，常用于：
- 函数返回多个值
- `std::map` 的迭代器（`key`, `value`）
- 临时组合数据

---

### 示例

```cpp
#include <utility>
#include <iostream>

std::pair<std::string, int> getUser() {
    return {"Alice", 25};
}

auto [name, age] = getUser(); // C++17 结构化绑定
std::cout << name << ", " << age << std::endl;

// 也可以用 make_pair
auto p = std::make_pair(1, "hello");
```


###  与 `std::tuple` 的区别

| 类型 | 说明 |
|------|------|
| `std::pair` | 固定两个元素 |
| `std::tuple` | 可变数量元素（`tuple<int, string, double>`） |

##  `uint32_t` vs `int32_t` vs `int64_t`

###  区别

| 类型 | 含义 | 范围 | 头文件 |
|------|------|------|--------|
| `int32_t` | 有符号 32 位整数 | -2,147,483,648 ~ 2,147,483,647 | `<cstdint>` |
| `uint32_t` | 无符号 32 位整数 | 0 ~ 4,294,967,295 | `<cstdint>` |
| `int64_t` | 有符号 64 位整数 | -9,223,372,036,854,775,808 ~ 9,223,372,036,854,775,807 | `<cstdint>` |
| `uint64_t` | 无符号 64 位整数 | 0 ~ 18,446,744,073,709,551,615 | `<cstdint>` |

---

###  使用场景

- `uint32_t`：计数器、位操作、网络协议（如 IP 地址）
- `int32_t`：通用整数计算
- `int64_t`：大数、时间戳（毫秒）、数据库 ID

>  推荐使用这些固定宽度类型，避免平台差异（如 `int` 在 Windows 是 32 位，Linux 可能是 64 位）

## 6️ Rust 中的 `i32`, `i64`, `u32`, `u64`

###  Rust 类型系统

Rust 有非常明确的整数类型：

| Rust 类型 | 含义 |
|----------|------|
| `i32` | 有符号 32 位整数（默认 `int` 类型） |
| `u32` | 无符号 32 位整数 |
| `i64` | 有符号 64 位整数 |
| `u64` | 无符号 64 位整数 |
| `isize` / `usize` | 指针大小的整数（32 或 64 位，取决于平台） |


### 示例

```rust
let a: i32 = 42;
let b: u64 = 100;
let c = 1i64; // 带后缀

// 类型推断：默认是 i32
let x = 42; // x: i32
let y = 42i64; // y: i64
```

>  Rust 强类型，不允许自动类型转换，必须显式 `as` 转换。


##  总结对比表

| 概念 | C++ | Rust |
|------|-----|------|
| 防止隐式转换 | `explicit` | 无（Rust 不支持隐式构造） |
| 字符串视图 | `std::string_view` | `&str` |
| 可选值 | `std::optional<T>` | `Option<T>` |
| 键值对 | `std::pair<K,V>` | `(K, V)` 元组 |
| 32位有符号整数 | `int32_t` | `i32` |
| 32位无符号整数 | `uint32_t` | `u32` |
| 64位有符号整数 | `int64_t` | `i64` |

掌握这些概念，你就能写出更安全、高效、现代的 C++ 和 Rust 代码！
