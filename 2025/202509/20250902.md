在 CMake 中，通过 add_subdirectory 添加多个子目录时，每个子目录中的 CMakeLists.txt 文件都拥有自己独立的变量作用域。这意味着，默认情况下，不同子目录中定义的普通变量（非缓存变量）不会直接冲突。

为了让你能快速理解变量在不同场景下的行为，我准备了一个表格：

变量类型 作用域规则,在add_subdirectory子目录中的行为,冲突风险

普通变量，遵循目录作用域。父目录的变量会复制到子目录，但子目录的修改不会影响父目录。
默认情况下，子目录中定义的普通变量只在该子目录及其更深层的子目录中有效。 低缓存变量全局作用域。在整个 CMake 项目中可见，并且值会持久化到CMakeCache.txt文件。 在任何地方（包括子目录）定义的缓存变量，其他所有目录都能访问和修改。 高环境变量 通过 $ENV{VAR} 访问，全局有效（针对CMake进程）。 所有子目录共享同一套系统环境变量。在子目录中通过 set(ENV{VAR} ...) 修改会影响后续所有操作。 

详细说明与最佳实践
1.  普通变量不会直接冲突：正如表格所述，子目录中的普通变量是独立的。例如：
    ◦   在 subdir1/CMakeLists.txt 中 set(MY_VAR "Value1")
    ◦   在 subdir2/CMakeLists.txt 中 set(MY_VAR "Value2")
    这不会冲突，因为它们在不同的作用域内。
2.  缓存变量需特别注意：缓存变量是全局的。如果在不同的子目录中定义了同名的缓存变量，后执行的 set 命令（尤其是使用了 FORCE 选项）会覆盖先前的值，这可能引发意外的行为。 这是最需要警惕的“冲突”情况。
3.  向上传递变量：如果子目录需要向父目录传递信息，可以使用PARENT_SCOPE选项：
    # 在子目录的 CMakeLists.txt 中
    set(SOME_RESULT "important_value" PARENT_SCOPE)
    但这需要父目录明确知道变量名并主动使用，并非自动共享。

4.  目标名称必须全局唯一：虽然变量有作用域，但通过 add_library 或 add_executable 创建的目标名称必须是全局唯一的，无论这些命令在哪个子目录中调用。如果两个子目录创建了同名的目标，CMake 会报错。

降低冲突风险的最佳实践
•   使用唯一且具描述性的变量名：为不同子目录的变量添加前缀，如 SUBDIR1_OPTION 和 SUBDIR2_OPTION。
•   谨慎定义缓存变量：仅在必要时定义全局缓存变量，并确保其名称足够唯一和描述性。
•   利用函数封装：将子目录中复杂的逻辑封装在函数(function())中，因为函数内定义的变量默认是局部的，这有助于隔离变量。
•   明确变量传递：如果需要共享值，清楚地使用 PARENT_SCOPE 或返回值机制，避免隐式依赖。

CMake提供了丰富的内置变量来控制和描述构建过程的各个方面。下面我将这些变量分类整理，并解释它们的含义、联系与区别。
变量类别 核心变量示例 (部分) 主要用途
提供信息 (Information) PROJECT_SOURCE_DIR, CMAKE_VERSION 提供项目路径、CMake版本、系统信息等只读信息。
改变行为 (Behavior) CMAKE_BUILD_TYPE, BUILD_SHARED_LIBS 控制构建类型、库的生成方式（动态/静态）、查找路径等行为。
描述系统 (System) CMAKE_SYSTEM_NAME, UNIX, WIN32 描述目标系统（如Linux、Windows）和主机系统的信息。
控制构建 (Build) CMAKE_RUNTIME_OUTPUT_DIRECTORY 控制编译和链接过程，如输出目录、编译器标志、运行时库等。
语言相关 (Languages) CMAKE_CXX_STANDARD, CMAKE_C_COMPILER 设置特定语言的编译器、编译标准、编译选项等。
环境变量 (Environment) ENV{PATH} 访问和修改系统环境变量。
项目变量 (Project) <PROJECT-NAME>_VERSION, PROJECT_NAME 由 project() 命令自动生成，提供项目相关信息。

变量定义与使用

CMake 中主要通过 set() 命令定义变量，并通过 ${VAR_NAME} 语法引用。
set(MY_VAR "Hello, World!") # 定义一个普通变量
message(${MY_VAR}) # 引用并打印变量

环境变量通过 $ENV{VAR_NAME} 读写，缓存变量则通过 $CACHE{VAR_NAME} 引用。
message("PATH=$ENV{PATH}") # 读取系统PATH环境变量
set(ENV{TEMP_DIR} "/tmp") # 设置环境变量 (仅当前进程有效)
set(MY_CACHE_VAR "default" CACHE STRING "A sample cache variable") # 定义缓存变量

注意事项与最佳实践
1.  作用域 (Scope):
    ◦   普通变量：遵循词法作用域，在当前目录（通过 add_subdirectory() 引入的会创建新作用域）、函数或宏内有效。使用 set(... PARENT_SCOPE) 可以向父作用域传递变量。
    ◦   缓存变量：全局有效，存储在 CMakeCache.txt 文件中，跨 CMake 运行持久化。
    ◦   环境变量：在 CMake 进程内有效，不会真正改变系统环境。
2.  覆盖策略：当普通变量与缓存变量同名时，引用 {VAR_NAME} 默认获取的是普通变量的值（如果存在），这可能会“遮盖”缓存变量。使用 CACHE{VAR_NAME} 可以明确指定访问缓存变量。此行为可通过策略 CMP0126 精确控制。
3.  调试变量:
    ◦   使用 message(STATUS "VAR=${VAR}") 打印变量值。
    ◦   使用 cmake -LAH 命令列出所有缓存变量及其帮助信息。

4.  最佳实践:
    ◦   最小作用域原则：尽量将变量的作用域限制在需要的范围内。
    ◦   清晰的命名：考虑为项目自定义的变量添加统一前缀，以减少冲突。
    ◦   缓存变量注释：定义缓存变量时，务必提供清晰的说明文档（<docstring>）。
    ◦   谨慎使用全局变量：避免滥用 CACHE 和 GLOBAL 变量导致配置难以维护。
