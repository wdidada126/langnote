为什么poi生成excel不用字体就能显示汉字，itext需要汉字字体才能生成pdf？
这个问题涉及到Apache POI和iText两个库在处理文本时的工作原理，特别是它们如何处理字符编码和字体。

### 1. 字符编码与字体的关系
#### 字符编码
- 字符编码 是将字符集中的每个字符映射到一个特定的数字。例如，ASCII 编码只能表示 128 个字符（包括英文字母、数字和一些符号），而 Unicode 则可以表示几乎所有语言的字符。
- PDF 文件本质上是一个二进制文件格式，它需要明确知道如何渲染每一个字符。因此，PDF 需要指定用于显示这些字符的字体信息。
#### 字体的作用
- 字体 定义了字符的外观（形状）。不同的字体支持不同的字符集。例如，标准的 Helvetica 字体不包含中文字符的定义，因此无法直接在 PDF 中显示中文。
- 当使用 iText 创建 PDF 文档时，如果使用默认字体（如 Helvetica），由于该字体不包含中文字符的定义，所以会出现乱码或方框的情况。因此，必须使用支持中文的字体（如 SimSun、SimHei 或 Source Han Sans）来确保正确显示中文字符。
### 2. 为什么 Apache POI 不需要显式指定字体？
#### Excel 文件的特性
- Excel 文件（`.xls` 或 `.xlsx`）是基于表格的数据存储格式，它并不像 PDF 那样依赖于具体的字体来进行文本渲染。
- 在 Excel 文件中，数据是以结构化的方式存储的，而不是以最终的视觉呈现形式存储。这意味着 Excel 文件本身并不直接关心你使用的字体是什么，除非你在 Excel 文件中明确设置了单元格的字体属性。
- 当你用 Apache POI 创建 Excel 文件时，你可以选择设置字体，但这并不是必需的。即使你不设置字体，Excel 应用程序在打开文件时会根据系统默认字体或其他预设字体来显示内容。
#### 自动回退机制
- Excel 具有自动回退机制，当找不到指定字体时，它会自动使用系统默认字体或其他可用字体来显示文本。这种机制使得 Excel 文件在不同系统上都能正常显示文本，即使某些字体不可用。
### 3. 总结

- iText 需要显式指定支持所需字符集的字体，因为 PDF 文件格式要求对每一个字符的显示都进行精确控制，确保在任何平台上都能正确显示文档中的所有字符。
- Apache POI 创建的 Excel 文件则更注重数据的结构化存储，而不直接涉及最终的文本渲染细节，因此不需要显式指定字体即可显示汉字。Excel 应用程序在打开文件时会负责根据当前环境选择合适的字体进行显示。
