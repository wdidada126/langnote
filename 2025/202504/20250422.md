c++模板类必须写在定义的地方吗？
不能声明和实现分离吗？
模板类哪有定义，全是声明，定义都是编译时编译器弄的

在 C++ 中，模板类的声明和定义确实有一些特殊之处，这常常会导致你所描述的情况，即看到的很多代码中模板类只有声明，而定义在编译时由编译器处理。以下是对这种现象的详细解释：

### 模板类的声明和定义分离问题
- 声明部分：模板类的声明通常放在头文件（`.h` 或 `.hpp`）中，它描述了模板类的结构、成员函数和成员变量等信息，但并不包含具体的实现细节。例如：
```cpp
// 模板类声明
template <typename T>
class Stack {
public:
    Stack();
    void push(const T& item);
    T pop();
    bool empty() const;
private:
    // 假设使用 std::vector 来实现栈
    std::vector<T> data;
};
```
- 定义部分：模板类的成员函数定义可以写在头文件中，也可以分离到源文件（`.cpp`）中。但当分离到源文件时，会出现一些问题。因为模板类在编译时，编译器需要根据具体的模板参数实例化出对应的类和成员函数。如果定义在源文件中，编译器在编译包含声明的源文件时，无法看到模板的具体实现，也就无法进行实例化。

例如，若将 `Stack` 类的成员函数定义写在 `stack.cpp` 中：
```cpp
// stack.cpp
#include "stack.h"
#include <vector>

template <typename T>
Stack<T>::Stack() {}

template <typename T>
void Stack<T>::push(const T& item) {
    data.push_back(item);
}

template <typename T>
T Stack<T>::pop() {
    T item = data.back();
    data.pop_back();
    return item;
}

template <typename T>
bool Stack<T>::empty() const {
    return data.empty();
}
```
在另一个 `main.cpp` 文件中使用 `Stack` 类：
```cpp
#include "stack.h"
int main() {
    Stack<int> intStack;
    intStack.push(10);
    return 0;
}
```
编译时，编译器在处理 `main.cpp` 时，虽然看到了 `Stack` 类的声明，但由于 `Stack` 类成员函数的定义在 `stack.cpp` 中，编译器无法直接实例化 `Stack<int>` 的成员函数，会导致链接错误。

### 解决方法
- 将定义放在头文件中：为了让编译器能够正确实例化模板类，通常的做法是将模板类的成员函数定义也放在头文件中。这样，当其他源文件包含该头文件时，编译器就能看到完整的声明和定义，从而在编译时根据具体的模板参数进行实例化。
```cpp
// stack.h
#include <vector>

template <typename T>
class Stack {
public:
    Stack() {}
    void push(const T& item) {
        data.push_back(item);
    }
    T pop() {
        T item = data.back();
        data.pop_back();
        return item;
    }
    bool empty() const {
        return data.empty();
    }
private:
    std::vector<T> data;
};
```
- 显式实例化：也可以在源文件中进行显式实例化，告诉编译器为特定的模板参数生成实例。例如，在 `stack.cpp` 中：
```cpp
#include "stack.h"
#include <vector>

// 显式实例化 Stack<int>
template class Stack<int>;
```
这样，编译器会为 `Stack<int>` 生成实例代码，但如果需要使用其他类型的 `Stack`，还需要再次显式实例化。

所以，在很多情况下，为了方便和避免链接错误，模板类的定义会和声明一起放在头文件中，使得编译器在编译时能够自动根据使用的模板参数进行实例化。
