# 医院信息平台与医疗数据治理

## 定位

医院信息平台/HIE 负责跨系统的主数据、标准、交换、服务目录、身份权限、审计和数据质量治理。它不是“把所有系统接到 ESB”或“建一个大数据仓库”就完成；平台的价值是使不同系统在明确数据主权和责任边界下协同。

## 分层与数据流

```text
源业务系统：HIS/EMR/PIS/LIS/RIS/PACS/护理/SPD/财务等
  -> 交换层：API、消息、文档、文件、集成引擎和接口监控
  -> 治理层：MPI、人员/机构/科室、术语、目录、权限、审计、数据质量
  -> 数据服务层：临床文档库、主题库、数据仓库、科研数据集、指标服务
  -> 消费方：临床工作站、患者服务、区域平台、公卫、医保、运营、科研
```

源系统负责产生和更正业务事实；交换层负责可靠传递和可观测性；治理层负责身份、编码与授权；数据服务层提供带来源、时间和质量说明的副本。分析/科研数据不应反向直接覆盖生产业务数据。

## 关键能力

| 能力 | 数据流责任 | 常见错误 |
| --- | --- | --- |
| MPI/EMPI | 维护患者多标识、匹配、合并/拆分和审计；向各系统分发受控标识 | 仅按姓名或证件号硬合并，造成患者串档。 |
| 主数据/术语 | 维护人员、机构、科室、药品、项目、诊断/手术等编码版本与映射 | 用同名文本代替标准编码，接口看似成功但语义错误。 |
| 接口治理 | 定义契约、版本、幂等键、超时、重试、死信、补偿和监控 | 生产系统数据库直连、无限重试、无业务对账。 |
| 文档与消息 | 记录谁在何时发布了什么业务事实及版本 | 将文件传输成功误认为下游已完成业务处理。 |
| 数据质量 | 完整性、唯一性、一致性、及时性、可追溯性与责任闭环 | 数据仓库发现问题后直接改数，未回源纠正。 |
| 权限与审计 | 按岗位、就诊关系、用途、最小必要原则控制访问 | 用共享账号和全库导出满足“临时查询”。 |

## 互操作边界

HL7 v2、CDA、DICOM、FHIR 等适用于不同的交换场景。标准定义表示与交互方式，不保证本地编码、患者匹配、业务流程、数据质量或安全授权天然一致。每份接口契约至少应包含：业务目的、源与目标系统、权威字段、标识规则、字段与术语映射、状态机、错误码、幂等/重试、性能指标、审计和变更流程。

## 验收场景

1. 消息重复、乱序、缺失、延迟、目标系统不可用和恢复重放，验证不会重复收费、重复发药或覆盖新版本。
2. 患者合并/拆分、科室变更、药品项目停用和术语版本切换，验证历史数据可追溯、新旧映射受控。
3. 接口字段错误、编码不匹配和数据质量告警要能定位到来源系统、责任人和修复闭环。
4. 测试敏感数据查询、批量导出、远程运维、科研取数、授权撤回和日志检索。
