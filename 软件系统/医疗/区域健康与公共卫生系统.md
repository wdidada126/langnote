# 区域健康与公共卫生系统

## 定位

区域健康平台、居民电子健康档案、基层医疗卫生信息系统和公共卫生业务系统面向连续健康管理、分级诊疗与公共卫生责任。它们不是医院 HIS 的备份库，也不应因“数据共享”绕开患者隐私、机构责任和最小必要原则。

## 主要系统

| 系统/能力 | 小类 | 主要数据来源/责任 |
| --- | --- | --- |
| 区域全民健康信息平台 | 目录、交换、主索引、授权、审计、转诊协同 | 区域卫生主管部门/平台运营方治理交换规则，来源机构对原始数据质量负责。 |
| 居民电子健康档案（EHR） | 档案首页、健康问题、检查、免疫、慢病、老年健康等摘要 | 基层和医疗机构按授权归集；必须标识来源、时间与更新状态。 |
| 基层医疗系统 | 家庭医生、签约、随访、慢病、处方、转诊、基本公卫服务 | 基层机构对服务记录和随访事实负责。 |
| 专项公卫系统 | 免疫规划、妇幼、疾控监测、传染病报告、应急处置 | 依法定业务规则、时限和上报口径管理，不能用通用 BI 替代。 |

## 数据流

```text
医院 HIS/EMR 与基层/公卫系统产生本机构业务记录
  -> 机构信息平台完成编码映射、质量校验、授权和审计
  -> 区域平台按目录/文档/消息归集可共享数据
  -> 电子健康档案形成带来源和时间的健康信息摘要
  -> 经授权向转诊、家庭医生、患者服务或监管场景提供最小必要数据
  -> 数据更正、撤回、失效和访问日志按来源与责任链处理
```

患者匹配不能仅使用姓名、手机号或身份证号任一字段；需要多标识匹配策略、置信度、人工复核和合并/拆分审计。区域平台缓存的数据不应覆盖来源医院已修订的病历事实。

## 验收与治理

1. 建立数据目录、用途、授权主体、共享字段、保留期限、接口责任人和质量指标，而非只统计接入系统数。
2. 测试患者跨机构就诊、身份冲突、档案合并/拆分、来源记录修订、授权撤回和网络中断补传。
3. 对传染病等法定报告场景，验证触发规则、时限、审核、退卡/订正和回执；不能将一般数据交换当作法定上报完成。
4. 对向患者开放的数据说明来源、更新时间、专业解释与纠错渠道，避免把原始临床数据未经解释直接当健康结论。
