# 电子病历与临床信息系统（EMR/CIS）

## 定位

EMR 是电子病历，记录诊疗过程中形成的临床文书和结构化信息；CIS 是临床信息系统，常覆盖医生站、医嘱、护理、手术、重症及临床质控。系统名称因医院不同而不同，关键是区分：EMR/CIS 对临床决策和医疗记录负责，HIS 对患者就诊、费用和部分业务交易负责，二者必须通过就诊、医嘱、执行和收费状态闭环协同。

## 核心能力

| 能力 | 小类 | 核心数据 |
| --- | --- | --- |
| 临床文书 | 首程、病程、知情同意、出院小结、模板、签名、修订 | 文书版本、作者、签署、封存、修订理由和时间。 |
| 医嘱与处方 | 长期/临时医嘱、处方、申请、停止/撤销、套餐 | 医嘱 ID、版本、状态、开立/停止人和执行条件。 |
| 临床协同 | 会诊、转科、转诊、交接班、路径、任务 | 临床责任人、状态、时限和交接记录。 |
| 决策支持 | 过敏、相互作用、合理用药、危急值、路径、质控 | 规则版本、触发依据、建议、人工确认或忽略原因。 |

## 数据流

```text
HIS/MPI 建立患者、就诊、科室、床位等基础上下文
  -> EMR/CIS 创建病历、诊断、医嘱和申请
  -> HIS 对可计价项目生成费用/医保处理
  -> PIS、LIS、RIS/PACS、手术麻醉、护理等专业系统执行
  -> 专业系统回写执行、结果、报告、取消或异常
  -> EMR/CIS 展示结果并形成病程/出院记录
  -> 病案质控、DRG/DIP、数据平台在授权范围内消费文档和结构化数据
```

EMR/CIS 不能把“医嘱已开立”视为“已执行”，也不应以复制结果文本替代专业系统结果。临床侧至少要保留来源系统、结果版本、获取时间和关键状态；专业执行系统仍保留其专业事实。

## 高风险边界

1. 病历修订、补录、封存和电子签名必须有时序和审计，不可直接覆盖原记录。
2. 医嘱修改/停止要靠版本和幂等键传播到药学、检验、检查、护理等系统，避免旧任务继续执行。
3. 过敏、诊断、体重、肾功能等被 CDSS 使用的数据要有来源、有效期和人工确认，不能把缺失值当正常值。
4. 患者合并/拆分、转科转床、出院后补录、跨院区就诊是接口和权限测试的重点。
