# 医药研发、生产与临床试验系统

## 定位

药企、CRO、器械企业和医院研究机构使用的软件覆盖研发、临床试验、生产质量、供应链、药物警戒、注册和上市后监测。它与医院 HIS 的连接主要发生在受试者诊疗、样本、药品器械追溯、研究数据和真实世界数据场景，不能因研究便利直接读取或修改医院生产病历。

## 系统与职责

| 系统 | 职责 | 核心数据/控制 |
| --- | --- | --- |
| CTMS | 临床试验项目、中心、预算、受试者访视、监查与资源管理 | 方案/中心状态、访视计划、研究团队和稽查轨迹。 |
| EDC | 电子病例报告表与研究数据采集、查询、锁库 | 受试者研究 ID、CRF 版本、修改痕迹、查询和锁库状态。 |
| IRT/IWRS | 随机化、盲态、试验药供应和发放 | 随机号、盲态权限、药物包、发放与回收。 |
| eTMF | 试验主文件、版本、签署、归档与稽查 | 文件完整性、版本、审批与保留期限。 |
| LIMS | 研发/生产实验室样本、方法、仪器、结果和报告 | 样本链、方法/仪器版本、原始数据和审核。 |
| QMS/eQMS | 偏差、CAPA、变更、投诉、培训、审计 | 质量事件、责任、时限、批准和有效性检查。 |
| PV | 药物警戒、不良事件、信号、病例处理和监管报告 | 病例来源、医学评估、时限、重复合并和报告回执。 |

## 医院与研究系统的数据流

```text
受试者签署知情同意并完成筛选
  -> CTMS 管理访视和中心流程，IRT 分配试验治疗（如适用）
  -> 医院 EMR/HIS 产生真实诊疗、检验、影像、用药等源数据
  -> 经授权的研究团队按方案从源数据核对/摘录到 EDC
  -> EDC 形成受控研究数据，产生质疑、修订和锁库记录
  -> SAE 等安全事件进入 PV 并按时限处理/报告
  -> 试验药、样本和器械通过供应/库存/UDI 等系统追溯
```

EMR/HIS 是临床源数据系统，EDC 是研究 CRF 数据系统；两者的差异需要按方案进行核查和更正，不可让 EDC 反写生产病历。受试者身份与研究编号的映射需要严格权限控制，盲态信息不得经普通接口泄露给不应知情角色。

## 验收与合规要点

1. 验证知情同意版本、生效时间和撤回后的访问/使用边界；未同意数据不得进入研究数据集。
2. 验证 EDC 修改痕迹、查询关闭、电子签名、锁库、解盲和稽查导出，不能把普通业务日志替代审计追踪。
3. 验证 SAE、投诉、偏差、CAPA 的来源、责任人、时限、升级和监管报告回执。
4. 样本、试验药、器械和冷链要能按研究、中心、受试者、批号/序列号追溯；研究结束后按方案和法规处理归档与数据保留。
