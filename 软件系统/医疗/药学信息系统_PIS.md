# 药学信息系统（PIS）

## 定位

PIS（Pharmacy Information System）管理医院药品目录、处方/医嘱审核、调剂、发药、库存、批号效期、退药、处方点评和药学服务。它不是单纯的药房库存软件：PIS 的核心职责是把“临床医嘱可安全、可追溯地转化为药品供应和用药记录”。药库、门急诊药房、住院药房、静配中心和药学质控可由一套或多套系统承担，但必须明确每个库存账和处方状态的权威来源。

## 功能与数据主权

| 子系统 | 主要功能 | 权威数据/状态 |
| --- | --- | --- |
| 药品主数据 | 通用名、商品名、规格、剂型、厂家、药理分类、医保属性、价格和替代规则 | 药品编码与启停版本；不能由各药房各自维护同名药。 |
| 处方/医嘱审核 | 适应证、剂量、频次、配伍、过敏、相互作用、抗菌药权限、审方干预 | 审核结论、干预原因、审核人和规则版本。 |
| 调剂与发药 | 接方、配药、复核、发药、叫号、配送、交接 | 处方行的调剂/发药状态、药品批号、执行人和时间。 |
| 药库与药房库存 | 采购入库、领用、调拨、盘点、损耗、报损、效期和退货 | 库存流水、可用量、占用量、批号效期和账实差异。 |
| 住院摆药/单剂量 | 按医嘱生成摆药任务、批次摆药、病区交接、退药 | 摆药批次、患者/床位、药品批号和退药原因。 |
| 药学管理 | 处方点评、抗菌药管理、药品不良反应、用药监测、统计 | 点评结果、干预闭环、上报记录和统计口径。 |

药品字典的维护责任可在药学部门，但收费项目、医保目录、供应商和财务科目往往来自不同系统。PIS 必须保存映射版本和生效时间，不能只用一个展示名称关联。

## 核心数据流

### 门急诊处方

```text
EMR/医生站创建处方或医嘱
  -> HIS 计价/医保预结算，返回可收费或拦截结果
  -> PIS 审方（通过、拦截、修改后重审）
  -> HIS/支付确认收费成功
  -> PIS 生成调剂任务 -> 配药/复核 -> 发药
  -> PIS 回写发药结果、药品批号和退药状态
  -> HIS/财务按发药、退药、撤销事实对账
```

处方已开立、已收费、已审核、已调剂、已发药、已退药是不同状态。支付回调成功不能直接标记“已发药”；撤方、退费和退药也不能跳过已执行状态检查。

### 住院医嘱与病区摆药

```text
EMR 创建/变更/停止住院医嘱
  -> PIS 校验医嘱版本并生成摆药需求
  -> 药房按批次调剂、复核、出库
  -> 病区/移动护理签收和执行
  -> 护理系统回写执行、拒绝、遗漏或退药原因
  -> PIS 更新库存与患者用药记录 -> HIS/成本系统对账
```

住院场景必须处理医嘱停止与摆药批次并发、患者转床/出院、临时医嘱、未执行退药和夜间紧急用药。医嘱以 EMR 为权威，药品库存以 PIS/SPD 为权威，护理执行以护理系统为权威；PIS 只保存为追溯所需的关联副本和状态。

## 接口与控制点

| 上游/下游 | 交换内容 | 必须控制 |
| --- | --- | --- |
| HIS/EMR | 患者、就诊、处方、医嘱、诊断、收费状态 | 使用处方/医嘱 ID 和版本号；撤销、修改、停止要幂等处理。 |
| 护理系统 | 病区、床位、执行、退药、交接 | 不能把“出库”误写为“患者已用药”。 |
| SPD/WMS | 采购、入出库、批号效期、二级库、盘点 | 统一药品编码、库存单位和批次；库存变更必须有可追溯流水。 |
| 医保/价格 | 目录、限制条件、结算结果 | 保存规则版本、失败原因和重试/人工处理记录。 |
| CDSS/知识库 | 相互作用、剂量、抗菌药权限等规则 | 规则版本、触发输入、建议与人工处理结果可审计。 |
| 财务/成本 | 收费、发药、退药、消耗、损耗 | 每日/班次对账；不可用汇总报表替代逐笔差异定位。 |

## 验收与风险

1. 用真实场景验证处方修改、撤销、欠费、退费、发药后退药、跨药房调剂、住院医嘱停止和患者出院。
2. 验证高警示药、毒麻精药、抗菌药、儿童/肾功能剂量等规则的生效范围、告警留痕和人工豁免权限。
3. 验证批号效期、冷链、召回、盘点和账实差异能追到患者/处方/操作人，而非只追到库存总数。
4. 对接口延迟、重复投递、离线发药和网络恢复做补偿与对账演练，避免重复扣库存或重复发药。
