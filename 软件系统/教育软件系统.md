# 教育软件系统

## 领域边界

教育软件覆盖招生、学籍、教务、教学、考试、学生发展、科研、人事财务和教育治理。LMS 不等于完整的学校信息化：LMS 管学习活动与资源，SIS 管学生生命周期和学籍/成绩等正式记录，教务排课与考试系统管理教学运行，校园 ERP 管人财物。系统设计首先要定义“正式记录”和“学习过程数据”的边界，不能让在线学习平台直接成为学籍或成绩的唯一权威来源。

教育数字化的重点已从单点资源上网转向平台化、智能化和治理能力，但 AI 工具不能绕过学生隐私、教师评价权和考试诚信。教育部 2025 年意见强调应用导向、治理为基和可信可控安全；具体学校仍应以学段、办学类型和属地要求制定数据治理边界。

## 核心系统地图

| 系统 | 主要小类 | 权威数据/责任 |
| --- | --- | --- |
| 招生与录取（ADM） | 招生计划、报名、资格审核、志愿、录取、缴费 | 报名材料、审核意见、录取状态和录取批次。 |
| 学生信息系统（SIS） | 学籍、院系班级、培养层次、注册、异动、毕业/学位 | 学生主索引、学籍状态、行政组织关系和正式成绩归档。 |
| 教务管理系统 | 培养方案、课程库、排课、选课、学分、成绩、教室资源 | 课程/教学班、选课资格、教学任务、成绩发布与变更审计。 |
| 学习管理系统（LMS） | 课程资源、作业、讨论、学习路径、在线课堂、学习分析 | 学习过程、作业提交、资源访问和过程性评价证据。 |
| 考试与评价 | 题库、组卷、监考、阅卷、成绩复核、证书 | 考试场次、答卷、评分规则、阅卷轨迹和复核结论。 |
| 学工与成长服务 | 宿舍、资助、心理、就业、社团、奖惩、辅导员 | 敏感学生服务数据需按用途和角色严格授权。 |
| 校园 ERP 与科研 | 人事、薪酬、预算、采购、资产、科研项目、成果 | 人财物和科研项目的业务凭证；不应由教学系统替代。 |
| 数据/身份平台 | SSO、统一身份、组织、数据中台、BI、开放平台 | 身份、权限、目录、审计和跨系统数据服务。 |

## 关键数据流

### 学生从录取到毕业

```text
招生系统审核录取
  -> SIS 创建学生主档、学籍和组织归属
  -> 统一身份平台开通账号、角色和校园服务
  -> 教务系统同步培养方案、课程资格和教学班
  -> LMS 建立课程空间并沉淀学习过程
  -> 考试/阅卷系统生成评价结果
  -> 教务系统审核并发布正式成绩 -> SIS 归档学籍与学分
  -> 毕业审核消费经确认的成绩、学分、学籍与学位规则
```

在线作业分数、教师暂存分、阅卷分、教务发布分和 SIS 归档分是不同阶段。成绩修改应从教务流程触发，保留申请、审批、修改前后值和影响范围；不能由 LMS 覆盖已归档成绩。

### 教学资源与 AI 助教

```text
教师/教研部门发布经审核的课程资源 -> LMS/资源平台分发
  -> 学生在授权课程内学习、提交作业、参与讨论
  -> 学习分析生成辅助指标 -> 教师人工解读与干预
  -> 过程性评价经教务规则确认后进入正式成绩流程
```

AI 助教、自动批改和学习分析应保存模型/规则版本、输入范围、人工复核与申诉路径。不得将学生画像、心理、成绩、未公开作品等敏感数据无边界提供给第三方模型服务。

## 数据治理与验收

1. 学号、证件、录取号和统一身份需建立映射与合并/拆分审计；不得以手机号作为唯一学生标识。
2. 验证转学、休复学、转专业、留级、学籍异动、重修、成绩复核、毕业延期等状态流转和历史追溯。
3. 统一身份平台下发最小角色权限；教师仅访问自己教学任务所需学生，辅导员/心理/资助数据分域授权并审计。
4. 排课、选课、考试与缴费高峰需要限流、幂等、排队和可恢复性；报名成功、支付成功、选课成功分别对账。
5. 科研、教学分析和 AI 训练应使用经审批的数据集，不直接高负载访问 SIS/教务生产库。
