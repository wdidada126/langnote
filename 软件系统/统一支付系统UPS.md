# 统一支付系统UPS
### 银行统一支付系统功能点列表及与核心系统关系

在银行软件系统中，“统一支付系统”（Unified Payment System）通常指银行内部或中国人民银行主导的现代化支付系统（如大额实时支付系统HVPS和小额批量支付系统IBPS），用于处理资金清算、转账和结算。它与“核心系统”（Core Banking System，CBS）密切相关：核心系统负责全行账户管理、存款贷款等基础业务，而统一支付系统则作为支付清算层，与核心系统通过接口（如API或消息队列）交互，实现资金实时划拨和对账。简单来说，核心系统是“账本”，统一支付系统是“桥梁”，确保交易安全、高效传输。

以下基于中国人民银行支付系统和典型银行支付架构（如支付网关、渠道接入），总结统一支付系统的核心功能点列表（分为大额和小额系统）。数据来源于中国人民银行官网及支付架构分析。

#### 统一支付系统功能点列表

| 功能模块 | 主要功能点 | 适用场景 | 与核心系统关系 |
|----------|------------|----------|---------------|
| **支付指令处理** | - 接收/发送支付指令（批量或实时）。<br>- 验证指令格式、金额、账户有效性。<br>- 支持多种格式（如SWIFT、CNAPS）。 | 大额：企业间大额转账。<br>- 小额：个人工资、社保支付。 | 核心系统提供账户余额查询和验证接口；支付系统反馈划拨结果至核心系统更新账户。 |
| **资金清算与结算** | - 全额清算资金（逐笔实时或批量）。<br>- 计算净额结算、多边清算。<br>- 自动对账、差错处理。 | 大额：债券交易结算。<br>- 小额：海量小额交易（如电商）。 | 核心系统作为资金源头，支付系统调用其余额冻结/解冻；结算后回写至核心系统账务。 |
| **风险控制与风控** | - 实时监控异常交易（反洗钱、欺诈检测）。<br>- 设置限额、黑白名单。<br>- 加密传输（SSL/TLS）。 | 所有支付场景。 | 核心系统共享客户风险模型；支付系统触发核心系统冻结高风险账户。 |
| **渠道接入与接口** | - 支持多渠道接入（网银、ATM、移动APP、第三方支付）。<br>- 统一API封装（RESTful或SOAP）。<br>- 支付路由选择最佳渠道。 | 零售支付、跨境支付。 | 核心系统通过中间件（如ESB）与支付系统对接，实现交易发起和结果同步。 |
| **账户管理与钱包** | - 虚拟账户创建/销户。<br>- 余额查询、转账限额管理。<br>- 支持电子钱包集成。 | 数字人民币、移动支付。 | 核心系统维护主账户，支付系统管理子账户/虚拟余额，定期对账同步至核心。 |
| **对账与报表** | - 日终/月终对账。<br>- 生成交易报表、审计日志。<br>- 异常差错追溯。 | 监管报告、内部审计。 | 支付系统输出对账文件导入核心系统，进行账务核对和调整。 |
| **高可用与监控** | - 灾备切换、负载均衡。<br>- 实时监控TPS（交易/秒）。<br>- 告警通知。 | 高峰期交易（如双11）。 | 核心系统提供冗余数据备份；两者通过心跳机制确保同步一致性。 |
| **监管合规** | - 接入央行CNAPS系统。<br>- 报告支付数据至监管（如反洗钱）。<br>- 支持跨境支付（CIPS）。 | 国际结算、合规审计。 | 核心系统记录合规模块，支付系统推送数据至监管，同时更新核心系统合规状态。 |

**说明**：
- **大额实时支付系统（HVPS）**：聚焦实时、高额交易（单笔≥50万元），强调速度和安全性。
- **小额批量支付系统（IBPS）**：处理海量小额（单笔<50万元），强调批量效率。
- **与核心系统关系总体**：统一支付系统不存储核心账务数据，而是依赖核心系统的账户总账（GL）和明细账（SL）。交互流程：交易发起（核心系统）→支付路由（统一支付）→清算确认→回写更新（核心系统）。这避免了数据孤岛，确保全行一致性。若脱钩，可能导致资金错账风险。
- 数据来源：中国人民银行支付系统介绍、支付架构分析（如知乎/人人都是产品经理文章）。实际实施因银行（如工行、建行）而异，若需特定银行案例，可提供更多细节。
