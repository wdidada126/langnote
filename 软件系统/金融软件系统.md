# 金融软件系统

## 领域边界

金融软件不是单一“银行系统”，而是账户与账务、支付清算、信贷、资金与交易、证券基金、保险、风控合规、客户运营和财务核算等系统的组合。最重要的边界是：客户信息、合同/产品、交易指令、账户余额、会计账务、清算头寸、风控判定和监管报送分别由谁产生、何时最终确定。

银行、支付机构、券商、基金、保险和清算基础设施的业务模型不同，不能复制同一套“核心系统”架构。任何跨机构资金流都要把业务受理、风险校验、记账、清算、结算、对账和差错处理拆开，不能把接口返回成功等同于资金最终结算。

## 核心系统地图

| 系统 | 主要小类 | 权威数据/责任 |
| --- | --- | --- |
| 客户与身份 | ECIF、KYC、客户主数据、开户注册、授权 | 客户标识、证件、账户关系、风险等级和授权有效期。 |
| 核心账务（CBS） | 存款、贷款、账户、计息、额度、总分账 | 客户账户余额、可用余额、账户状态和交易明细账。 |
| 渠道与开放平台 | 柜面、网银、App、API、合作方接入、消息通知 | 受理请求、会话/设备、渠道限额和幂等请求记录。 |
| 支付与清算 | 收单、代收付、转账、路由、清分、清算、结算、对账 | 支付指令状态、清算头寸、结算结果、差错和退款链路。 |
| 授信与贷款 | 申请、审批、额度、合同、放款、还款、催收、不良资产 | 授信决策、合同、还款计划、欠款和资产分类。 |
| 交易与资管 | OMS/EMS、交易、估值、托管、清算、登记、风控 | 委托、成交、持仓、估值、保证金和交收状态。 |
| 风控合规 | 反欺诈、反洗钱、制裁筛查、交易监测、稽核、报送 | 风险规则版本、命中证据、处置、复核和报告回执。 |
| 财务与数据 | 总账、子账、会计引擎、资金头寸、监管报表、数据仓库 | 会计凭证、账务期间、对账差异和报送口径。 |

## 支付资金流

```text
渠道接收请求 -> 身份/设备/限额/反欺诈校验
  -> 核心或支付账本冻结/扣减，生成不可重复的业务流水
  -> 支付路由发送至行内、清算机构或外部机构
  -> 接收清算/结算回执，更新支付指令状态
  -> 核心账务、总账、备付金/清算头寸分别记账
  -> 对账系统按逐笔与日终文件核对，差错进入补正/退款/冲正流程
```

“已受理”“已扣账/冻结”“清算已受理”“结算成功”“对账完成”必须是独立状态。超时通常代表未知结果而非失败，重试前需以原业务流水查询；冲正不是删除原交易，而是有方向和原因的后续账务事实。

## 贷款与交易数据流

```text
贷款：渠道申请 -> KYC/征信/反欺诈 -> 授信审批与额度 -> 合同 -> 核心放款 -> 还款/计息/催收 -> 财务与监管报送
交易：客户委托 -> 适当性/风控 -> OMS/交易设施 -> 成交 -> 清算/托管/登记 -> 资金与证券交收 -> 持仓估值与对账
```

贷款审批结论、合同、放款账务、催收状态不可由同一张“订单表”含混表达。证券交易中委托、成交、清算、交收、登记和资金可用状态也不是同一时点，应按市场规则与参与方回执处理。

## 风险、对账与验收

1. 每笔跨系统交易有全局业务 ID、幂等键、原始指令、状态机、外部回执、会计凭证和审计链；不要用日志文本替代账务证据。
2. 同时做渠道对账、核心/子账对账、总账对账、清算/结算对账、资金账户对账和监管口径校验，差异要能定位与补正。
3. 灾备、日切、跨日、重复报文、乱序回执、外部超时、部分成功和人工冲正是必须演练的场景。
4. 风控/反洗钱规则应保留版本、输入快照、命中原因、人工复核和处置时限；模型分数不能作为无法解释的唯一拒绝依据。
