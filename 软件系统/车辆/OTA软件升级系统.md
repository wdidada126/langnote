# OTA 软件升级系统

OTA 系统管理软件包签名、适配、灰度发布、下载、安装、回滚和安装证据。它的目标是安全、可控地改变车端软件版本，不能把云端发布成功当作车辆已升级成功。

## 数据流

```text
PLM/ALM 放行软件基线 -> OTA 创建签名包、兼容矩阵和灰度策略
  -> TSP 筛选满足条件的车辆 -> 车端下载/校验/安装
  -> 车端回传接收、安装、失败或回滚 -> OTA 固化实际版本
  -> 售后/QMS/研发消费失败、故障和版本覆盖情况
```

软件包与发布策略由 OTA 负责，兼容性基线来自 PLM，车辆实际安装结果来自车端。升级要检查车型、硬件、现有版本、电量、网络、驻车和安全条件。

## 验收重点

1. 签名与完整性、断点续传、灰度暂停、失败回滚和降级策略。
2. 同一 VIN 重复任务、跨版本依赖、安装中断和最终状态对账。
3. 安全缺陷应急发布、审计证据和用户告知/授权边界。
