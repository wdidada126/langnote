在Elasticsearch中，索引是一个重要概念，它是文档的容器，即一类文档的集合。每个索引可以包含多个类型（type），这在旧版本中是类似于关系型数据库中的表的概念。然而，随着Elasticsearch的更新，从6.x版本开始，一个索引下只能有一个type。这是为了简化使用过程，因为多type的情况在实践中可能会带来困扰。到了7.0之后的版本，这种设计被完全移除。

另外值得一提的是文档的唯一标识_id，它与_index和_type一起，共同唯一标识和定位一个文档。总的来说，了解这些基本概念对于使用Elasticsearch非常有帮助。

三个包管理工具都用过。
xmake（自带包管理工具）国内大佬开发，从编译构建，到包管理全是自己实现，不依赖cmake，使用简便。但是文档太简略，很多功能无法实现，比如加载一个mingw架构特定版本的静态库，文档中找不到相应指令。与ide集成比较差，可以体验体验，工程化开发还是不够成熟。未来可期吧。
conan：依赖cmake，比较强大，库比较丰富，库版本控制灵活方便，库的编译参数比较丰富。2.0版本使用上做了一些简化，但是目前很多库不支持2.0构建，文档看似很简单，使用起来也是各种问题。
vcpkg：依赖cmake，你想要的功能基本都有，xmake的理念是简便第一，功能第二。vcpkg则是功能第一简便第二。去年的时候使用vcpkg还是比较恶心的需要配合各种cmake配置，还不如直接用cmake。现在主推的manifest模式算是比较简便了，就是版本控制不如conan方便，还有库的编译选项（vcpkg叫做特性）不够完善。架构选择灵活丰富，ide集成比较完善。

Conan 是一个用于管理 C++ 库和依赖项的开源工具。它允许您在开发过程中管理、构建和共享 C++ 库。

当使用 Conan 进行库的打包和上传到 Conan 服务器时，一般情况下是将编译好的库文件（如 .so 文件）和相关的头文件打包成一个二进制包（Binary Package），然后上传到 Conan 服务器。

二进制包包含了编译好的库文件以及库的头文件和其他必要文件，以便其他开发人员可以方便地使用和集成这个库到他们的项目中。通过上传二进制包到 Conan 服务器，其他开发人员可以使用 Conan 来下载和安装这个库，并自动解决其所需的依赖项。

在使用 Conan 打包和上传库时，通常会创建一个 Conan 配置文件（conanfile.py 或 conanfile.txt），其中包含了库的描述、依赖项和构建规则。根据这个配置文件，Conan 会自动构建二进制包，并将其上传到 Conan 服务器。其他开发人员可以使用相同的配置文件来下载和安装这个库。

总结起来，使用 Conan 打包和上传 C++ 库时，通常是将编译好的库文件和相关的头文件打包成二进制包，并上传到 Conan 服务器，而不是直接上传原始的源代码或编译信息。

请注意，Conan 还支持其他功能，如源代码包的管理和构建，但在常规的库共享和依赖项管理中，使用二进制包是常见的做法。

Conan 打包的二进制包是以特定的格式进行存储和传输的。这个格式称为 Conan 包格式（Conan Package Format）。

Conan 包格式是一个压缩文件，其中包含了构建好的库文件（如 .so、.dll、.dylib 等）以及相关的头文件、CMake 脚本、依赖项信息和其他必要的文件。这个压缩文件使用特定的扩展名，通常是 `.zip`、`.tar.gz` 或 `.tgz`。

Conan 包格式的具体内容和结构是由 Conan 工具定义的，并且与不同的构建系统和操作系统有关。例如，在使用 CMake 构建的库中，Conan 包可能包含以下内容：

- 构建好的库文件（例如 .so、.dll、.dylib）
- 相关的头文件和资源文件
- 依赖项的库文件和头文件
- cmake_find_package 模块或 cmake_config 模块（用于在 CMake 中轻松集成库）
- 其他必要的文件和元数据（如许可证、说明文档等）

Conan 包格式具有通用性，可以适用于不同的操作系统和构建系统。当其他开发人员使用 Conan 下载和安装这个二进制包时，Conan 会解压缩这个包，并将其中的文件复制到相应的位置，以便项目可以正确地使用这个库和其依赖项。

需要注意的是，Conan 还支持源代码包的管理和构建。在这种情况下，Conan 包含了源代码文件和构建脚本，以便在不同的环境中进行编译和构建。

总结起来，Conan 打包的二进制包是一个特定格式的压缩文件，其中包含了构建好的库文件、头文件和其他必要的文件，以便其他开发人员可以方便地使用和集成这个库。

偏向锁

在Linux C++中，没有类似Java中的AQS（AbstractQueuedSynchronizer）这样的内置同步组件。不过，C++提供了一些其他的同步原语和库，可以用于实现类似的功能。
互斥锁（Mutex）：用于保护共享资源的访问，实现线程间的互斥。C++标准库中的std::mutex提供了基本的互斥锁功能。
读写锁（Read-Write Lock）：用于多线程读写共享资源的情况。C++标准库中的std::shared_mutex（C++17起）提供了读写锁的功能。
条件变量（Condition Variable）：用于实现线程间的等待和通知机制。C++标准库中的std::condition_variable提供了条件变量的功能。
信号量（Semaphore）：用于限制对共享资源的访问权限。C++标准库中的std::counting_semaphore提供了计数信号量的功能。
未来（Future）/承诺（Promise）：用于异步计算结果的传递。C++标准库中的std::future和std::promise提供了相关的接口。
原子操作（Atomic Operations）：用于实现线程安全的操作。C++标准库中的std::atomic提供了原子操作的功能。
此外，还有一些第三方库和组件，如Boost库、Intel的Threading Building Blocks（TBB）等，它们提供了更丰富的同步原语和高级功能，可以用于构建复杂的并发程序。
请注意，虽然这些同步组件在功能上与Java的AQS有所不同，但它们可以实现相似的并发控制和同步目标。具体选择使用哪种同步组件取决于你的需求和偏好。
