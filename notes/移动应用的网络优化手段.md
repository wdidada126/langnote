# 移动应用的网络优化手段

性能评估标准
- 建立连接延迟
- 传输速率延迟
- 到达率
- 长链接：存活率

性能瓶颈原因：TCP协议的延迟
http1.1上 keep-alive 重用上次的连接，连接存活15秒，存在的话重用

Nagle算法与延迟确认（DELAYACK）


关于TCP_NODELAY或者TCP_QUICKACK
Client TCP_NODELAY
Server TCP_QUICKACK

防止拥塞机制：慢启动
如果一开始就发送大量的包，路由器的缓存可能会被占用完毕，整个连接传输速率很慢
解决方式：一开始只发一个包，成功之后再发多个（两个）包

WebView优化手段

- Spriting图片合并（类似J2ME，不利于频繁过期小图）
- 内容嵌套(base64)
- 文件合并(类似图片合并，减少请求)
- 域名分片

HTTPS
Https最影响性能的地方是证书链
Https格式
证书链：只用证书-中间证书（可能布置一个）-跟证书
每个证书都要验证

安卓上存在的问题：验证证书的时长大约1秒，太长

解决方式一：
iOS上设置锚点，新人中心证书
安卓上，采用okhttp，中间证书采取本地添加域名加SHA指纹直接通过验证
证书验证协议：RFC6960
此方法的问题，安全性降低

解决方式二：ECC证书
优点：采用椭圆曲线算法，比AES证书短，安全性相同
缺点：Android 4.0+以上兼容，目前资料少

相关内容：怎么生成证书，证书链上每一步都做了什么

可选策略

- 多连接+测速 （防抖动，最稳）
- 多连接不测速（建议连接最快）
- 复合连接（Mars），单线程请求，4秒延迟发起，第二个10秒延迟、服务器压力最小，实现最复杂，对于IP和port选择排序精准性要求严格。
