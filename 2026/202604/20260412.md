## 1. Go（最新：1.24.x）
完全支持原子类型，且非常完善。

### 标准库：`sync/atomic`
- Go 1.19+ 新增面向对象的原子类（推荐）：
  - `atomic.Bool`
  - `atomic.Int32` / `Int64`
  - `atomic.Uint32` / `Uint64` / `Uintptr`
  - `atomic.Pointer[T]`（泛型指针）

```go
package main

import (
  "sync"
  "sync/atomic"
)

func main() {
  var count atomic.Int64 // 原子整数类
  var wg sync.WaitGroup

  for i := 0; i < 1000; i++ {
    wg.Add(1)
    go func() {
      defer wg.Done()
      count.Add(1) // 原子自增
    }()
  }
  wg.Wait()
  println(count.Load()) // 1000
}
```
- 同时保留传统函数式 API：`atomic.AddInt64(&x, 1)`
- 内存模型与 C++/Java 对齐，保证顺序一致性

## 2. C#（最新：.NET 9 / C# 13）
原生支持原子操作，以 `Interlocked` 静态类为主。

### 核心：`System.Threading.Interlocked`
- 原子方法：
  - `Increment` / `Decrement`（±1）
  - `Add`（任意整数）
  - `CompareExchange`（CAS）
  - `Exchange`（交换）
  - `Read`（long 原子读）

```csharp
long count = 0;
// 原子自增
Interlocked.Increment(ref count);
// CAS
Interlocked.CompareExchange(ref count, 100, 50);
```

### .NET 6+ 增强
- 泛型 `Interlocked.CompareExchange<T>(ref T, T, T)`（引用/值类型）
- 无真正“原子类封装”，但可用封装类实现同样效果：

```csharp
// 自定义原子整数（等价 Java AtomicInteger）
public class AtomicInt {
  private int _value;
  public int Increment() => Interlocked.Increment(ref _value);
  public int CompareExchange(int newValue, int comparand)
    => Interlocked.CompareExchange(ref _value, newValue, comparand);
}
```

## 3. Python（最新：3.13 / 3.14 测试版）
标准库无内置 `AtomicInt` 类，但有两种可靠方案：

### 方案 A：标准库 + GIL 保护（简单场景）
- 单字节读写本身原子（CPython 实现）
- 整数/布尔可用 `threading.Lock` 包装
- 无 GIL 模式（3.13+ PEP 703） 必须显式原子

### 方案 B：第三方原子库（生产级，推荐）
```bash
# 支持无 GIL，完全锁-free（Rust 底层）

```

```python
from atomicx import AtomicInt

a = AtomicInt(0)
a.add(1)        # 原子自增
a.cas(1, 100)   # CAS：旧=1 → 设为100
print(a.load()) # 安全读取
```
- 同类库：`pyatomix`、`sharedatomic`

# 一句话结论
`__xxx__` 格式的方法，叫「特殊方法 / 魔法方法」，是 Python 内置规定好的。

- 不是你随便发明的
- 是 Python 解释器自己会去调用的方法
- 你写类时实现它，就是为了让你的对象能用 Python 原生语法

# 举几个最常见的（全是内置）
```python
__init__      # 初始化对象
__len__       # 对应 len(obj)
__getitem__   # 对应 obj[key]、迭代
__setitem__
__str__       # 对应 str(obj)、print(obj)
__repr__      # 对应 repr(obj)
__eq__        # 对应 ==
__lt__        # 对应 <
__add__       # 对应 +
__call__      # 让对象能像函数一样调用 obj()
```

# 它们是“内置”的两层意思
## 1. 名字是 Python 官方规定的
你不能自己乱造：
- `__my_length__` 就不是内置，`len()` 不会认它
- 只有 `__len__` 才会被 `len()` 识别

## 2. Python 解释器会自动调用
你不用自己写：
```python
obj.__len__()
```
你只需要写：
```python
len(obj)
```
Python 会自动去找 `obj.__len__()` 执行。

# 最经典例子（Fluent Python 扑克牌）
```python
class Deck:
    def __init__(self):
        self.cards = [...]

    def __len__(self):
        return len(self.cards)  # 实现内置方法

deck = Deck()
print(len(deck))  # Python 自动调用 __len__
```

# 超级总结
`__xxx__` 方法 = Python 内置的接口协议
- 你实现它
- Python 就用标准语法（len / for / print / == / []）支持你的对象

这就是 Python 面向对象设计的核心机制。
