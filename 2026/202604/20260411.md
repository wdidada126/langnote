C++11 六种  memory_order  本质是控制 原子操作的内存可见性与指令重排，解决多线程下“你写的代码顺序 ≠ CPU实际执行顺序”的问题。
 
一、先懂两个核心前提
 
- 原子性：操作不可分割（已由  std::atomic  保证）
- 内存序：额外控制 指令重排 和 线程间可见性（6种memory_order就是干这个）
 
二、六种内存序（从弱到强）
 
1. memory_order_relaxed（宽松序）
 
- 只保原子，不保顺序
- 编译器/CPU可自由重排前后指令
- 无线程间同步
- 适用：独立计数器、统计、无依赖的原子操作
 
cpp
  
atomic<int> x{0};
x.fetch_add(1, memory_order_relaxed); // 只保证+1原子，顺序不管
 
 
2. memory_order_consume（消费序，C++26弃用）
 
- 比 acquire 弱，仅约束 数据依赖 的操作
- 几乎不用，编译器常优化为 acquire
- 跳过，直接学 acquire-release
 
3. memory_order_release（释放序，写用）
 
-  Store 专用 ：之前所有读写 不能重排到后面
- 相当于“发布屏障”：写完后，前面修改对其他线程可见
- 适用：生产者、解锁、发信号
 
cpp
  
int data=0;
atomic<bool> ready=false;
// 线程1
data=100;
ready.store(true, memory_order_release); // 前面data一定先写完
 
 
4. memory_order_acquire（获取序，读用）
 
-  Load 专用 ：之后所有读写 不能重排到前面
- 相当于“接收屏障”：读到值后，能看到对方之前所有修改
- 适用：消费者、加锁、收信号
 
cpp
  
// 线程2
while(!ready.load(memory_order_acquire)); // 循环等信号
cout << data; // 一定读到100（release-acquire同步）
 
 
5. memory_order_acq_rel（获取-释放序）
 
- 读-改-写专用（CAS、exchange、fetch_add）
- 读时 acquire，写时 release
- 前后都有屏障，双向禁止重排
- 适用：无锁队列、CAS 自旋锁
 
6. memory_order_seq_cst（顺序一致序，默认）
 
- 最强、最简单：全局总顺序一致
- 所有 seq_cst 操作按全局序执行
- 性能最差（尤其ARM/PowerPC）
- 默认：不写内存序就是它
 
三、黄金组合：Release-Acquire（最常用）
 
- 线程A  release  写 → 线程B  acquire  读
- B 读到A写的值 → A之前所有操作，对B可见
- 无锁编程的基础同步模型
 
四、一句话速记
 
- relaxed：原子就行，乱序不管
- release：我写完，前面都生效
- acquire：我读到，后面都可见
- acq_rel：读写都带屏障
- seq_cst：全局顺序，简单但慢
- consume：过时，别用

先一句话总结：
Java AQS/CLH 是「线程排队+状态+阻塞唤醒」的同步框架；其他语言没有完全一样的，但有等价/更优的并发原语，或可手动实现 CLH/MCS。
 
一、C++：最接近，可手写 CLH/MCS
 
C++ 无内置 AQS，但有完整原子与线程库，最容易手写 CLH/MCS 队列锁。
 
- std::atomic + CAS + 内存序 = 可实现 AQS 核心能力
- CLH 锁（隐式前驱自旋）：cpp
  
class CLHLock {
public:
  struct Node {
    atomic<bool> locked{true};
  };
  atomic<Node*> tail{nullptr};
  thread_local static Node* curr;
  thread_local static Node* prev;

  void lock() {
    curr->locked = true;
    prev = tail.exchange(curr); // 入队
    while (prev->locked) this_thread::yield(); // 自旋等前驱
  }
  void unlock() {
    curr->locked = false;
    curr = prev; // 复用节点
  }
};
 
- MCS 锁（显式双向链表，本地自旋）：更常用、更友好
- 标准库同步： mutex 、 condition_variable 、 shared_mutex 、 latch 、 barrier 
- 无锁队列： atomic_queue 、 folly::MPMCQueue  等
 
二、Go：没有 AQS，但 Channel 是「一等公民」
 
Go 不搞 CLH 队列锁，用 Channel 统一同步与排队，设计哲学完全不同。
 
- Channel = 内置阻塞队列 + 同步原语go
  
ch := make(chan struct{}, 1) // 二元信号量
ch <- struct{}{}            // 获取（阻塞）
<-ch                        // 释放
 
- 等待队列： sync.Mutex 、 sync.RWMutex 、 sync.WaitGroup 、 sync.Cond 
- 无锁/队列库： container/list 、 gammazero/deque 、 channel  本身就是 FIFO
 
Go 风格：用 Channel 做同步与消息传递，很少手写 CLH。
 
三、Python：线程安全队列 + 锁
 
Python 全局解释器锁 GIL，并发以「线程安全队列+锁」为主 。
 
- queue.Queue（线程安全 FIFO，内置锁与阻塞）：python
  
import queue
q = queue.Queue()
q.put(item)        # 满则阻塞
item = q.get()     # 空则阻塞
 
- 同步原语： threading.Lock 、 RLock 、 Condition 、 Semaphore 
- 异步： asyncio.Queue （协程安全）
- 无 CLH 生态：很少手写，GIL 下收益不大
 
四、JS/TS：事件循环 + 异步队列 + 原子（有限）
 
JS/TS 单主线程，并发靠异步/事件/Worker，无原生线程锁 。
 
- Worker 线程：用  SharedArrayBuffer + Atomics  实现原子操作js
  
const sab = new SharedArrayBuffer(4);
const arr = new Int32Array(sab);
Atomics.store(arr, 0, 1);    // 写
Atomics.wait(arr, 0, 0);     // 阻塞等待
Atomics.notify(arr, 0, 1);   // 唤醒
 
- 异步队列： Promise  微任务、 setTimeout  宏任务、 async-await 
- 库： p-queue （并发控制）、 bull （Redis 队列）
- CLH 意义不大：单线程为主，多 Worker 场景极少
 
五、快速对比表
 
语言 类似 AQS/CLH 的方案 核心特点 
Java AQS + CLH 双向队列 官方框架、线程阻塞、可重入、条件队列

JS/TS Atomics + async queue 单主线程、Worker 原子、异步为主

- Go：忘掉 AQS，用 Channel
- Python：用  queue.Queue  + 锁就行
- JS/TS：异步 + Atomics，很少需要 CLH

二、高频面试题 + 标准答案
 
1. set 和 list 区别？
 
- set 无序、不重复、哈希表实现，查询 O(1)
- list 有序、可重复、动态数组，查询 O(n)
- set 可做去重、交并差；list 适合顺序存储
 
2. set 和 frozenset 区别？
 
-  set  可变，可 add/remove，不可哈希
-  frozenset  不可变，可哈希，能做字典 key / 放入集合
 
3. 如何快速给列表去重？
 
python

res = list(set(lst))
 
 
缺点：会打乱顺序（Python 3.7+ dict 可保序： dict.fromkeys(lst).keys() ）
 
4.  remove  和  discard  区别？
 
-  remove(x)  不存在抛异常
-  discard(x)  不存在不报错
 
5. 集合为什么不能包含可变对象（list/set/dict）？
 
因为集合底层是哈希表，元素必须可哈希（hashable）。
可变对象不可哈希，无法计算哈希值。
 
6. 什么是可哈希对象？
 
实现了  __hash__  且不可变的对象：
 
- 可哈希：int/str/bool/tuple/frozenset
- 不可哈希：list/set/dict
 
7. 如何求两个列表的交集/并集/差集？
 
python
  
a = [1,2,3]
b = [2,3,4]
set(a) & set(b)  # 交集 {2,3}
set(a) | set(b)  # 并集 {1,2,3,4}
set(a) - set(b)  # 差集 {1}
 
 
8.  s.pop()  为什么是随机删除？
 
集合无序，内部是哈希表存储，没有首尾概念，所以随机弹出。
 
9. 空集合怎么创建？ {}  是什么？
 
- 空集合： set() 
-  {}  是空字典，不是集合
 
10. 如何判断两个集合无交集？
 
python
  
s.isdisjoint(t)
 
 
返回 True 表示完全不相交。
 
11. 集合遍历会报错吗？
 
遍历时不能修改集合（add/remove/pop），否则抛  RuntimeError 。
 
12. 集合底层数据结构？
 
Python 3.6+ 为紧凑哈希表，3.6 之前是稀疏哈希表。
查询、插入、删除平均 O(1)。
 
13. 为什么 list 不能去重，set 可以？
 
set 会通过哈希值自动判重，相同元素只存一份。
list 不做重复判断。
 
14. 如何判断 s 是 t 的子集？
 
python
  
s.issubset(t)
 
 
15. 集合可以嵌套吗？
 
直接不行： {{1}}  报错。
必须用不可变集合：
 
python
  
{frozenset({1})}

from collections import OrderedDict
class LRU:
    def __init__(self, capacity):
        self.od = OrderedDict()
        self.cap = capacity
    def get(self, k):
        if k not in self.od: return -1
        self.od.move_to_end(k)
        return self.od[k]
    def put(self, k, v):
        if k in self.od:
            self.od.pop(k)
        elif len(self.od)>=self.cap:
            self.od.popitem(last=False)
        self.od[k]=v

指针、值传递、引用传递、函数传参的区别与用法。
 
 
 
1. 核心概念一句话总结
 
- 值传递：传的是副本，函数内改不动外面变量。
- 指针传递：传的是地址，可以通过地址修改外面变量。
- 引用传递：传的是别名，本质和指针一样，但语法更简洁安全。
 
 
 
2. 值传递（pass by value）
 
把变量复制一份传给函数。
函数内部修改的是副本，不影响原变量。
 
cpp
  
void func(int x) {
    x = 100;
}

int main() {
    int a = 10;
    func(a);
    // a 仍然是 10
}
 
 
特点：
 
- 安全，不会意外改外部变量
- 大对象拷贝开销大
 
 
 
3. 指针传递（pass by pointer）
 
把变量地址传给函数。
函数通过  *指针  可以直接修改原变量。
 
cpp
  
void func(int *p) {
    *p = 100;
}

int main() {
    int a = 10;
    func(&a);
    // a 变成 100
}
 
 
特点：
 
- 可以修改原变量
- 语法稍繁琐，要写  *  和  & 
- 指针可能为空，需要判断
 
 
 
4. 引用传递（pass by reference）
 
给原变量起别名，函数操作别名 = 操作原变量。
 
cpp
  
void func(int &r) {
    r = 100;
}

int main() {
    int a = 10;
    func(a);
    // a 变成 100
}
 
 
特点：
 
- 语法最简洁，不用  * 
- 本质底层还是指针，但更安全
- 引用不能为空，必须绑定变量
 
 
 
5. 三者直观对比表
 
方式 传的是什么 能否修改原变量 语法 开销 
值传递 副本 ❌ 不能 直接写变量 拷贝开销 
指针传递 地址 ✅ 能  int* p  几乎无 
引用传递 别名 ✅ 能  int& r  几乎无 
 
 
 
6. 常见使用场景
 
1. 只想传参、不想修改
→ 用值传递（简单类型）或 const 引用（大对象）cpp
  
void func(const string &s);
 
2. 需要在函数内修改外部变量
→ 优先用引用传递，更干净
→ 老代码/兼容C用指针传递
3. 对象很大（string、vector、类）
→ 绝对不要值传递，用 const &

- 值传递 = 传副本，改不动
- 指针传递 = 传地址，能改
- 引用传递 = 传别名，能改，语法更爽

给你写一段完整可直接运行、带 `if __name__ == '__main__':` 的 Python 函数式编程示例，包含常用特性：
- 纯函数
- lambda
- map / filter / reduce
- 高阶函数
- 不可变风格（尽量）

```python
from functools import reduce

# 1. 纯函数：无副作用，相同输入一定相同输出
def square(x):
    return x  2

def is_even(x):
    return x % 2 == 0

def add(a, b):
    return a + b

# 2. 高阶函数：接收函数作为参数
def apply_twice(func, x):
    return func(func(x))

# 3. main 入口
if __name__ == "__main__":
    nums = [1, 2, 3, 4, 5, 6, 7, 8]

    # map：对每个元素做变换
    squared = list(map(square, nums))
    print("平方：", squared)

    # filter：过滤
    evens = list(filter(is_even, nums))
    print("偶数：", evens)

    # reduce：归约
    total = reduce(add, nums)
    print("总和：", total)

    # lambda 匿名函数
    doubled = list(map(lambda x: x * 2, nums))
    print("翻倍（lambda）：", doubled)

    # 组合式
    even_squares = list(map(square, filter(is_even, nums)))
    print("偶数的平方：", even_squares)

    # 高阶函数使用
    print("apply_twice(square, 3) =", apply_twice(square, 3))
```

运行结果：
```
平方： [1, 4, 9, 16, 25, 36, 49, 64]
偶数： [2, 4, 6, 8]
总和： 36
翻倍（lambda）： [2, 4, 6, 8, 10, 12, 14, 16]
偶数的平方： [4, 16, 36, 64]
apply_twice(square, 3) = 81
```

### 一句话概括函数式风格：
- 少变量、少状态、少循环
- 多用函数 + 组合 + 映射 + 过滤 + 归约
- 函数可以当参数、当返回值
