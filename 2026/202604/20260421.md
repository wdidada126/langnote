# Kafka 重平衡（Rebalance）完整总结（Kafka 3.x 专属：解决问题、触发时机、版本差异、查看日志）
本文全部针对 Kafka 3.0~3.9，区分旧版 eager / 新版增量协作重平衡，附完整日志检索命令。

## 一、重平衡到底解决了什么问题？
重平衡（Consumer Group Rebalance）是消费者组分区自动分配机制，由 Broker 端 Group Coordinator 协调。
核心解决3个根本问题：
1. 保证分区独占消费：一个分区同一组内只能被1个消费者消费，保证消息顺序、不重复、不丢失
2. 负载均匀分发：分区均匀分配给组内所有消费者，避免空闲/过载
3. 故障自动容错+弹性扩缩容：消费者宕机、新增实例、分区扩容时，自动重新分配分区，无需人工干预

### Kafka 3.x 相比2.x最大改进：解决旧版重平衡致命缺陷
2.x 默认 Eager 急切式重平衡：触发时所有消费者全部放弃所有分区→全组停顿→重新分配，消费完全中断、抖动极大、频繁重平衡雪崩。
Kafka 3.x 默认 Incremental Cooperative Rebalance 增量协作重平衡（KIP-429）：
- 只回收需要重新分配的分区，不动的分区继续消费
- 无全局 Stop-The-World 停顿
- 大幅降低重平衡抖动、延迟、堆积风险

## 二、Kafka 3.x 重平衡完整触发时机（全部场景）
分为主动正常触发、被动异常触发两大类：

### 1. 消费者组成员变化（最常见）
- 新增消费者实例（扩容）
- 消费者正常下线、主动离开组
- 消费者崩溃、OOM、网络断开（被动退出）
- 消费组首次启动初始化

### 2. Topic 元数据变化
- Topic 分区数增加（Kafka不支持减分区）
- Topic 删除、新建订阅Topic
- 消费者订阅的Topic列表变更

### 3. 心跳/会话超时（生产高频坑）
- `session.timeout.ms`（默认10s）：未发送心跳 → Coordinator判定消费者死亡，踢出组触发重平衡
- `max.poll.interval.ms`（默认5min）：消息处理太慢、长时间不poll拉取 → 踢出组触发重平衡

### 4. 分配策略/组配置变更
- 消费者修改分区分配策略（range/round-robin/sticky）
- Group 元数据重置、offset重置

## 三、Kafka 3.x 重平衡版本关键区别（必考面试点）
|版本|重平衡协议|特点|3.x默认状态|
|---|---|---|---|
|2.x及以前|Eager 急切式|全组停服、全部撤销分区、全量重分配|废弃|
|3.0~3.9|增量协作式 Cooperative Rebalance|增量撤销、不停服、仅重分配变动分区|默认开启|

3.x 关键配置（开启增量重平衡）：
```properties
# Kafka 3.x 默认值
partition.assignment.strategy=org.apache.kafka.clients.consumer.CooperativeStickyAssignor
```
> 切回旧版 eager：改为 `RangeAssignor` 即可。

## 四、Kafka 3.x 如何查看重平衡日志（3种方式：消费者本地日志、Broker日志、命令行）
### 方式1：查看消费者客户端本地日志（最常用、最准）
搜索日志关键词（直接 grep/检索）：
```
Rebalance
Rejoining group
Successfully joined group
generation
Revoke assignment
Complete assignment
```

典型3.x增量重平衡日志（区分旧版全量）：
```
# 开始加入组重平衡
Rejoining group due to: need to rebalance, generation: 25
# 增量撤销（只撤销部分分区，不是全部！3.x特征）
Revoke assigned partitions: [topic-0-2, topic-0-3]
# 接收新分配
Received new assignment from group leader
# 重平衡完成
Successfully joined group with generation 25
```

旧版Eager特征日志（3.x不默认）：
```
Revoke all assigned partitions
```

### 方式2：Broker端 Coordinator 日志（服务端）
Broker日志目录：`logs/controller.log`、`logs/server.log`
检索关键词：
```
GroupCoordinator
Rebalance
group metadata updated
member removed
```

### 方式3：kafka-consumer-groups 命令行（3.x官方命令，一键查重平衡/状态）
#### 1. 查看消费组详细状态+重平衡世代（generation）
```bash
bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --describe --group 你的消费组名
```
关键字段：
- `GENERATION`：重平衡次数，持续上涨=频繁重平衡
- `STATE`：Stable/PreparingRebalance（正在重平衡）

#### 2. 查看最近重平衡原因、成员变化（3.2+支持）
```bash
bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --describe --group 你的消费组名 --verbose
```

#### 3. 查看消费组历史重平衡事件（3.3+）
```bash
bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --group 你的消费组名 --list-rebalance-events
```

## 五、生产高频：频繁重平衡排查关键词（3.x）
日志出现以下=异常频繁重平衡：
1. `session timeout expired`：心跳超时
2. `poll interval exceeded`：消息处理超时（max.poll.interval.ms）
3. `member left group`：消费者频繁上下线
4. `generation` 持续快速递增
