深度学习与神经遗传算法（Neuroevolution）的核心关系是：用遗传算法（GA）进化神经网络的权重与结构，替代或辅助传统梯度下降，特别适用于梯度不可导、奖励稀疏、环境动态性强的场景。

### 核心概念与关系
- 神经遗传算法（Neuroevolution）：用遗传算法（GA）进化神经网络的权重与结构，替代或辅助传统梯度下降。
- 遗传算法（GA）：以“种群→选择→交叉→变异→评估”循环，在解空间搜索最优解。
- 映射关系：每个神经网络=一个个体（染色体）；权重/拓扑=基因；性能=适应度。


### 三种主流融合方式
| 方式 | 做法 | 优点 | 缺点 | 典型场景 |
|---|---|---|---|---|
| 权重进化 | 固定拓扑，只进化权重 | 实现简单、计算量小 | 拓扑受限，难复杂任务 | 简单控制、游戏AI |
| 拓扑+权重进化 | 同时进化结构与权重 | 自动架构搜索，泛化强 | 搜索空间大、计算昂贵 | 图像识别、NLP超参寻优 |
| 混合进化 | GA+梯度下降（GA-BP） | 兼顾全局搜索与局部精调 | 流程复杂、协同难 | 金融预测、时序分析 |


### 经典算法与流程
1. NEAT（增强拓扑神经进化）
   核心：从简单网络开始，同时进化拓扑与权重，支持跨代物种保护。
   流程：初始化种群 → 评估适应度 → 选择优秀个体 → 交叉/变异 → 迭代收敛。

2. GA优化超参/拓扑
   编码：隐藏层数量、神经元数、学习率等→染色体。
   应用：CNN卷积核配置、LSTM层数/维度、NLP词嵌入维度。

### 为什么用它？（适用场景）
✅ 梯度不可导任务（如强化学习、游戏AI）
✅ 奖励稀疏/环境动态变化（自动驾驶、机器人）
✅ 自动架构搜索（NAS），摆脱人工调参依赖
✅ 小规模任务，梯度下降成本高时


### 与传统深度学习的区别
| 维度 | 传统DL（梯度下降） | 神经遗传算法 |
|---|---|---|
| 训练方式 | 反向传播，单网络迭代 | 种群进化，多网络并行 |
| 依赖 | 损失函数可导、光滑 | 适应度函数即可，无需可导 |
| 拓扑 | 人工预设 | 自动进化 |
| 计算成本 | 单网络训练快，易局部最优 | 种群成本高，全局搜索强 |

# 一句话核心原因
感知机最早、最原始、最本质的定位，就是一个“可学习的逻辑电路单元”。
用逻辑门讲感知机，是最自然、最容易理解、最能暴露其能力边界的方式。


# 1. 感知机的数学结构 = 逻辑门的结构完全一致
感知机做的事：
- 输入多个 0/1 信号
- 加权求和
- 超过阈值输出 1，否则 0

逻辑门（AND、OR、NAND、NOR）做的事：
- 输入 0/1
- 根据固定规则输出 0/1
- 完全是线性可分问题

两者结构一模一样，所以：
讲感知机 = 讲逻辑电路
实现感知机 = 实现逻辑门

这就是为什么一上来就讲 与门、或门、与非门。


# 2. 用逻辑门能最直观展示：感知机能做什么
- AND 门：感知机 能实现
- OR 门：感知机 能实现
- NAND 门：感知机 能实现

学生立刻就能懂：
哦，原来感知机可以模拟基本逻辑！


# 3. 用异或门（XOR）最直观展示：感知机不能做什么
XOR 是非线性可分问题。
单层感知机死活做不出来。

这就自然引出重点：
2.4 感知机的局限性

然后顺理成章讲：
单层不行 → 叠加多层 → 多层感知机 MLP → 就能解决 XOR

整个逻辑链条非常顺滑：
能做（AND/OR）
→ 不能做（XOR）
→ 怎么办（叠加多层）
→ 能做了

### 二、核心功能（你马上要用）
1. 内置完整测试用例
   - 自带几十道 SysY 测试题（`testcases/`）
   - 自动跑：编译 → 运行 → 对比输出 → 打分
   - 不用自己写测试、不用自己搭环境

2. 自动依赖 koopa、RISC-V 运行时
   - 自动链接你刚装的 `libkoopa`
   - 自带 SysY 运行时库（`sysy-runtime-lib`）
   - 不用自己配头文件、库路径

3. 一键编译、测试、调试
```bash
# 编译你的编译器
cargo build

# 自动跑所有测试
cargo test

# 单测某个案例
cargo test test_add
```

4. 支持直接生成 Koopa IR / RISC-V 汇编
   - 框架已经帮你搭好：
     `SysY → 词法/语法分析 → Koopa IR → RISC-V`
   - 你只需要填核心逻辑（Parser、IR生成、汇编生成）

### 三、和你刚 clone 的 koopa 关系
- `koopa`：库（生成/解析 Koopa IR）
- `compiler-dev`：框架/环境（调用 koopa、跑测试、管理依赖）

### 四、你现在该怎么用？（最常用）
```bash
# 1. 克隆（你已经做了）
git clone https://github.com/pku-minic/compiler-dev.git
cd compiler-dev

# 2. 直接开始写编译器
# 核心目录：
#   src/
#     main.rs        # 入口
#     ast.rs         # 抽象语法树（你来定义）
#     parser.rs      # 语法分析（你来写）
#     koopa_ir.rs    # Koopa IR 生成（你来写）
#     riscv.rs       # RISC-V 生成（你来写）

# 3. 一键测试
cargo test

# 4. 编译你的编译器
cargo build --release
```
