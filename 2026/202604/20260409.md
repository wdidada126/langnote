在 Python 工业级项目里，单纯用 pip + requirements.txt 是不够的，缺少版本锁定、环境隔离、依赖解析、构建发布等能力。

下面给你最主流、最生产级、企业真正在用的工具，按成熟度排序：

# 1. Poetry（最推荐，工业级标准）
## 用途
- 环境隔离
- 依赖管理
- 版本精确锁定
- 自动打包发布
- 无手动写 requirements.txt

## 核心文件
- `pyproject.toml` 依赖声明
- `poetry.lock` 精确锁定（类似 package-lock.json）

## 常用命令
```bash
poetry install          # 安装全部依赖
poetry add requests     # 安装包
poetry remove requests  # 删除包
poetry export -f requirements.txt --output requirements.txt --without-hashes  # 导出给老项目用
```

## 优点
- 依赖解析最强
- 环境隔离干净
- 适合生产、微服务、后台项目
- 大厂主流

# 2. PDM（现代Python包管理，速度快）
## 用途
- 比 Poetry 更快
- 标准 PEP 规范
- 适合大型项目

## 命令
```bash
pdm add requests
pdm install
pdm export -o requirements.txt
```

## 优点
- 速度快
- 兼容性强
- 适合大型团队

# 3. Pipenv（Pip + Virtualenv 合体）
## 用途
- 早期工业级工具
- 简单、稳定

## 文件
- `Pipfile`
- `Pipfile.lock`

## 命令
```bash
pipenv install
pipenv install requests
pipenv lock -r > requirements.txt
```

## 优点
- 简单稳定
- 适合中小型项目

# 4. uv（Rust写的超级快工具）
## 用途
- 最快的依赖安装
- 适合大型 monorepo、企业级项目

## 命令
```bash
uv add requests
uv sync
```

## 优点
- 极快
- 适合大型项目

# 企业级总结（你直接选）
## ✔ 新项目、后台服务、微服务 → Poetry（最推荐）
## ✔ 大型项目、追求速度 → PDM / uv
## ✔ 老项目兼容 → Pipenv

这个 `<if test="TRANS_FLAG != null and TRANS_FLAG == '1'.toString()">` 中的 `.toString()` 的作用是：

### 主要作用：强制把 `'1'` 从 char 类型转成 String 类型

详细解释：

1. 不加 `.toString()` 时（写成 `'1'`）：
   - MyBatis 的 `test` 属性使用 OGNL 表达式解析。
   - 单引号 `'1'` 在 OGNL（以及 Java）中被当成 char 类型（单个字符）。
   - 如果你的参数 `TRANS_FLAG` 是 String 类型（最常见的情况），就会出现 类型不匹配：
     - String 和 char 用 `==` 比较，经常会导致判断失败（即使值都是 "1"，也可能不进入 if）。
     - 严重时甚至会抛类型转换异常。

2. 加上 `.toString()` 后（`'1'.toString()`）：
   - 先把 `'1'`（char）调用 `toString()` 方法，转成字符串 `"1"`。
   - 这样左右两边都是 String 类型（`TRANS_FLAG` 是 String，右边也是 String）。
   - 比较就变得安全、正确。

### 总结：这个 `.toString()` 是一种保险/兼容写法

- 它是为了解决单引号导致的 char vs String 类型问题而加的。
- 属于“老派”或“保守”的写法，很多老项目里都能看到。

### 更推荐的现代写法（不需要 `.toString()`）：

```xml
<!-- 推荐写法：外层用单引号，内层字符串用双引号 -->
<if test='TRANS_FLAG != null and TRANS_FLAG == "1"'>
    ...你的SQL...
</if>
```

优点：
- 更简洁
- 可读性更好
- 不需要多余的 `.toString()`
- 双引号 `"1"` 直接被 OGNL 识别为 String 类型

### 完整建议（把你这行改成最佳实践）：

```xml
<if test='TRANS_FLAG != null and TRANS_FLAG == "1"'>
    <!-- 你的 SQL 片段 -->
</if>
```

如果你项目里很多地方都用了 `'1'.toString()`、` '0'.toString()` 这种写法，建议逐步统一改成双引号的写法，更干净。

Java 标准库（ java.util.concurrent ）里最常用、最标准的线程池就是：
 ThreadPoolExecutor  的 7 个核心参数。
 
 
 
ThreadPoolExecutor 完整参数
 
java
  
new ThreadPoolExecutor(
    int corePoolSize,
    int maximumPoolSize,
    long keepAliveTime,
    TimeUnit unit,
    BlockingQueue<Runnable> workQueue,
    ThreadFactory threadFactory,
    RejectedExecutionHandler handler
);
 
 
1. corePoolSize
 
核心线程数
 
- 线程池长期保留的最小线程数
- 默认不会被回收（除非开启  allowCoreThreadTimeOut(true) ）
 
2. maximumPoolSize
 
最大线程数
 
- 线程池能创建的最大线程总数
- 当队列满了，才会新建线程直到此上限
 
3. keepAliveTime
 
空闲线程存活时间
 
- 非核心线程空闲超过这个时间就会被回收
 
4. unit
 
时间单位
 
-  TimeUnit.MILLISECONDS  /  SECONDS  等
5. workQueue
 
任务队列
- 任务提交后，先进入队列排队
常用：
-  ArrayBlockingQueue  有界队列
-  LinkedBlockingQueue  无界/有界链表队列
-  SynchronousQueue  不存储，直接移交
 
6. threadFactory
线程工厂
- 用于自定义线程名称、优先级、守护线程等
- 默认： Executors.defaultThreadFactory() 
 
7. handler
拒绝策略（饱和策略）
当线程数达到最大 + 队列已满时触发。
内置 4 种：

1.  AbortPolicy （默认）：直接抛异常
2.  CallerRunsPolicy ：让提交任务的线程自己执行
3.  DiscardPolicy ：直接丢弃任务
4.  DiscardOldestPolicy ：丢弃队列最老任务，再尝试提交
 
执行流程（极简版）
 
1. 任务来了 → 当前线程 < core → 新建核心线程
2. 核心线程满 → 任务入队列
3. 队列满 → 当前线程 < max → 新建非核心线程
4. 达到 max + 队列满 → 执行拒绝策略
 
 
 
Executors 快捷线程池（本质也是上面的参数）
 
-  Executors.newFixedThreadPool(n) 
core = max = n，队列无界
-  Executors.newCachedThreadPool() 
core=0，max=Integer.MAX，线程 60s 回收
-  Executors.newSingleThreadExecutor() 
core=max=1，单线程串行执行
