关键字表算法，开源实现
“关键字表算法”通常指代两类场景：编译器词法分析的关键字查表（保留字识别）、文本检索的关键词表索引/多模式匹配。下面分别讲原理、数据结构与主流开源实现。
一、编译器/词法分析：关键字表（Keyword Table）
1. 核心原理
在词法分析中，识别标识符（如变量名）后，查关键字表判断是否为语言保留字（if/int/for等）。
结构：哈希表（最优）、有序数组、Trie树、DFA
时间复杂度：
哈希表：O(1) 查找
有序数组：O(log n) 二分
Trie/DFA：O(k)（k=关键字长度）

(2) 有序数组 + 二分查找
c
运行
// 按字典序排序
const char *keywords[] = {
    "auto", "break", "case", ..., "while"
};

// 二分查找
int lookup(const char *s) {
    int left=0, right=sizeof(keywords)/sizeof(*)-1;
    while (left <= right) {
        int mid = (left+right)/2;
        int cmp = strcmp(s, keywords[mid]);
        if (cmp == 0) return mid; // 关键字
        if (cmp < 0) right = mid-1;
        else left = mid+1;
    }
    return -1; // 普通标识符
}

四、极简关键字表（哈希表）C语言示例
c
运行
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

#define TABLE_SIZE 128

typedef struct {
    char *key;
    int token;
} Entry;

Entry table[TABLE_SIZE] = {0};

// 简单哈希
unsigned int hash(const char *s) {
    unsigned int h = 0;
    while (*s) h = h * 31 + *s++;
    return h % TABLE_SIZE;
}

// 插入关键字
void add_keyword(const char *key, int token) {
    unsigned int idx = hash(key);
    table[idx].key = strdup(key);
    table[idx].token = token;
}

// 查找
int lookup(const char *key) {
    unsigned int idx = hash(key);
    if (table[idx].key && strcmp(table[idx].key, key) == 0)
        return table[idx].token;
    return -1; // 不是关键字
}

int main() {
    add_keyword("if", 1);
    add_keyword("else", 2);
    add_keyword("int", 3);

    printf("if -> %d\n", lookup("if"));    // 1
    printf("abc -> %d\n", lookup("abc"));  // -1
    return 0;
}

编译原理。中间表示 vs 汇编（目标代码） 哪个先生成？
结论先说：先生成中间表示（IR），再生成汇编 / 目标代码。
标准编译流程顺序
源代码 → 2. 词法 / 语法分析 → 3. 生成中间表示 IR
对 IR 做各种优化（核心步骤）
从 IR 生成汇编代码
汇编器 → 目标文件（.o/.obj）
链接器 → 可执行文件
为什么必须先 IR、后汇编？
汇编是平台相关的（x86、ARM、RISC-V 各不相同）
IR 是平台无关的，适合做统一优化
优化算法在 IR 上实现最简单、高效
同一个前端 + 优化器，可以适配多个架构，只需要重写「IR→汇编」这一层
一句话记忆
IR 是编译器内部的 “通用汇编”，汇编是给具体 CPU 看的最终指令。顺序永远是：源码 → IR → 汇编 → 机器码

先给你一句**最核心结论**：
**InnoDB 里的 Next-Key Lock = 行锁（Record Lock） + 间隙锁（Gap Lock）**
默认 RR（可重复读）级别下，**普通的行锁查询，实际加的都是 Next-Key Lock**。

---

# 1. 三个锁的定义
## 1）Record Lock（行锁）
- 只锁**某一行记录本身**
- 锁住：`id = 10` 这一行
- 作用：防止别的事务修改/删除这一行

## 2）Gap Lock（间隙锁）
- 锁**两个索引之间的空隙**，不锁记录
- 锁住：`(5,10)` 这个区间
- 作用：**防止别的事务往这个间隙里 insert**，从而解决幻读

## 3）Next-Key Lock（临键锁）
- **行锁 + 间隙锁 合在一起**
- 锁住：`(5,10]` 左开右闭区间
- 作用：既防修改，又防插入，**彻底解决幻读**

---

# 2. 联系与区别（一句话版）
- **行锁**：锁单行，防 update/delete
- **间隙锁**：锁区间，防 insert
- **Next-Key Lock**：
  = 行锁 + 间隙锁
  = 既锁行，又锁前后间隙
  = InnoDB RR 级别下默认的锁机制

---

# 3. 举例说明（最容易懂）
假设有表：
```sql
create table t (
  id int primary key,
  val int
);
insert into t values (1,10),(5,20),(10,30),(15,40);
```

索引上的区间：
`(-∞,1], (1,5], (5,10], (10,15], (15,+∞)`

---

## 例1：行锁 Record Lock
```sql
select * from t where id = 10 for update;
```
- 只锁：`id=10` 这一行
- 允许：往 `(5,10)` 插入新行
- 不允许：修改/删除 `id=10`

---

## 例2：间隙锁 Gap Lock
```sql
select * from t where id = 10 for update;
-- 在某些条件下会退化成只锁间隙
```
更典型的是**范围查询命中不到数据**：
```sql
select * from t where id between 6 and 9 for update;
```
- 锁住区间 `(5,10)`
- 禁止 insert 任何 id 在 5~10 之间的数据
- 不锁任何已存在行

---

## 例3：Next-Key Lock（最常用）
```sql
select * from t where id = 10 for update;
```
在 RR 级别下，InnoDB 加的是：
- 行锁：锁 `id=10`
- 间隙锁：锁 `(5,10)`
合起来就是 **Next-Key Lock：(5,10]**

结果：
1. 不能修改/删除 id=10
2. 不能 insert id=6/7/8/9
3. 彻底避免幻读

---

# 4. 三者关系总结
| 锁类型 | 锁范围 | 解决问题 |
|--------|--------|----------|
| 行锁 Record | 单行 | 不可重复读 |
| 间隙锁 Gap | 索引间隙 | 防止insert |
| 临键锁 Next-Key | 行+间隙 | 完全解决幻读 |

**核心口诀：**
- 行锁：锁行
- 间隙锁：锁空
- Next-Key：锁行+锁空

---
