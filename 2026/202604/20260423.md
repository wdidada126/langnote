# 安卓 Gradle 多环境（dev/sit/uat/prod）最标准、最稳定、2026最新方案
完全对标你之前用的 Maven Profile，但这是 Gradle 安卓官方用法，能做到：
- 打包时自动切换环境
- 代码里直接拿环境变量
- XML / BuildConfig 都能用
- 命令行：`./gradlew assembleDevDebug`

我直接给你全套可复制配置，一步到位！



# 1. 先在 app/build.gradle 里配置 4 个环境（核心）
```gradle
android {
    compileSdk 35

    // 定义多环境：dev / sit / uat / prod
    flavorDimensions "env" // 固定维度名
    productFlavors {
        dev {
            buildConfigField "String", "ENV", "\"dev\""
            buildConfigField "String", "API_HOST", "\"https://dev-api.xxx.com\""
        }
        sit {
            buildConfigField "String", "ENV", "\"sit\""
            buildConfigField "String", "API_HOST", "\"https://sit-api.xxx.com\""
        }
        uat {
            buildConfigField "String", "ENV", "\"uat\""
            buildConfigField "String", "API_HOST", "\"https://uat-api.xxx.com\""
        }
        prod {
            buildConfigField "String", "ENV", "\"prod\""
            buildConfigField "String", "API_HOST", "\"https://api.xxx.com\""
        }
    }

    // 必须开启 BuildConfig（新版 Gradle 默认关闭）
    buildFeatures {
        buildConfig true
    }
}
```



# 2. 代码里直接使用（Java / Kotlin 都能用）
```kotlin
// 自动生成的类，不需要自己写
String env = BuildConfig.ENV;             // dev / sit / uat / prod
String host = BuildConfig.API_HOST;       // 对应环境接口地址
```

完全等价于 Maven profile 切换！



# 3. 打包命令（你最关心）
```bash
# dev 包
./gradlew assembleDevDebug
./gradlew assembleDevRelease

# sit
./gradlew assembleSitDebug
./gradlew assembleSitRelease

# uat
./gradlew assembleUatDebug
./gradlew assembleUatRelease

# prod
./gradlew assembleProdDebug
./gradlew assembleProdRelease
```



# 4. 对应 Android Studio 切换环境

直接选择：
- devDebug

点 Run 运行就是对应环境！



# 5. 最关键对比（你之前用 Maven，现在看秒懂）
| Maven | Gradle 安卓 |
|---|---|
| `-P dev` | `assembleDev` |
| `-P sit` | `assembleSit` |

# 我给你讲最直白、最本质、不绕弯的区别！
## 一句话总结
这俩完全不是一个东西，但可以联动！



# 1. 先给你最清晰定义（背会就懂）
## ① `application.yml` 里的
```yaml
spring:
  profiles:
    active: dev
```
叫：SpringBoot 环境配置
作用：决定项目启动时加载哪个配置文件
- `application-dev.yml`
- `application-prod.yml`
运行时生效
跟 Maven 没关系


## ② `mvn clean package -P dev`
叫：Maven 构建 Profile
作用：决定打包时用什么参数
编译/打包时生效
跟 Spring 没关系



# 2. 它们的真正关系（90%的人都搞混）
## 默认情况下：
它们互相独立，各玩各的！
你写 `active: dev`，不影响 maven 打包
你用 `-P prod`，不影响 spring 读配置



# 3. 企业级真正用法（联动起来）
我们会让 Maven 把环境变量传给 SpringBoot！

## 做法：
### 1）pom.xml 里定义
```xml
<profile>
    <id>dev</id>
    <properties>
        <env>dev</env>
    </properties>
</profile>
```

### 2）application.yml 里写成
```yaml
spring:
  profiles:
    active: @env@
```

### 3）然后打包
```bash
mvn clean package -P dev
```

### 最终效果：
Maven 的 `-P dev`
→ 把 `env=dev` 传给 Spring
→ Spring 自动激活 `dev` 环境



# 4. 超级直观对比
| 名称 | 属于谁 | 作用 | 时机 |
|---|---|---|---|
| `spring.profiles.active` | SpringBoot | 选配置文件 | 项目运行时 |
| `-P dev` | Maven | 构建参数 | 打包编译时 |



# 5. 你最容易踩的坑
### 坑1：
你在 yml 写 `active: dev`
但用 `mvn -P prod` 打包
→ 最终运行还是 dev 环境！

### 坑2：
你想打包 prod 版本
必须要么：
- yml 写 `active: prod`
要么
- 用 `@env@` + `mvn -P prod`
