你说的“防跨步”，在Web安全里一般叫 防步骤绕过 / 防跨步验证 / 防跳过验证步骤（也常被称作“业务逻辑漏洞 - 步骤绕过”）。
在“忘记密码 / 找回密码”流程里特别常见：攻击者直接跳过“验证邮箱/短信/密保”，直接访问“设置新密码”页面，从而篡改他人账号。
 
下面给你完整的：什么是跨步、为什么要防、网页上怎么实现防跨步、实战代码要点、安全书单。

一、什么是“跨步/步骤绕过”（Forgot Password场景） 
标准安全流程（3步）：
1. 输入账号/邮箱 → 2. 验证身份（邮箱/短信/验证码） → 3. 设置新密码
跨步攻击：
攻击者直接从 1 → 3，或直接访问  /reset-password?token=xxx ，跳过第2步验证。
- 原因：后端没校验步骤状态、token校验太弱、会话没绑定流程。

二、网页“忘记密码 + 防跨步”的核心实现（必做） 
1. 服务端：流程状态机（最关键）
 
- 给会话/用户设置 流程状态标记：-  step=0  未开始
-  step=1  已提交账号
-  step=2  已通过验证
-  step=3  已重置完成（失效）
- 每一步必须校验：- 只能从  step=1  进入  step=2 
- 只能从  step=2  进入  step=3 
- 不允许跳步、回退复用、跨会话复用
 
2. 重置 Token 安全规则（防伪造/防遍历）
 
- 高熵随机：≥128位随机数（UUID/密码学安全随机）
- 短时有效：15～30分钟过期
- 一次性：使用后立即标记  used=1 ，不可复用
- 强绑定：token 关联 用户ID + 会话ID + IP/设备指纹
- 不泄露：URL 只带哈希后的token，数据库存加盐哈希（bcrypt/Argon2）
 
3. 接口与页面访问控制
 
-  /reset  页面：必须校验  step=2  状态 + 有效token，否则跳回第一步
- 前端路由（Vue/React）：加路由守卫，禁止直接跳页
- 统一错误提示：不泄露“账号不存在”“token无效”等差异（防枚举）
 
4. 验证码与频率限制
 
- 邮箱/短信验证码：6位+、5分钟过期、5次错误锁10分钟
- 人机验证（reCAPTCHA/滑块）：防机器批量请求
- 全流程限速：单IP/账号 1分钟内最多3次请求
 
5. 重置成功后强化
 
- 使 所有旧会话失效（强制重新登录）
- 发送告警邮件/短信：“您的密码已重置”

# 1) 提交账号（step1）
def forgot_step1(username):
    user = get_user(username)
    if not user:
        return "重置邮件已发送（统一提示）"
    # 生成token
    token = generate_secure_token()
    token_hash = bcrypt.hash(token)
    # 存DB：user_id, token_hash, status=1, expire=15min, session_id
    save_reset_record(user.id, token_hash, session.id)
    # 发邮件：/reset?token=token（明文）
    send_reset_email(user.email, token)
    # 标记会话状态
    session['reset_step'] = 1
    return "重置邮件已发送"

# 2) 验证token/验证码（step2）
def forgot_step2(token):
    record = get_reset_record(session.id)
    if not record or record.status != 1 or record.expire < now():
        return "链接无效或过期"
    if not bcrypt.verify(token, record.token_hash):
        return "链接无效"
    # 标记通过
    record.status = 2
    update_reset_record(record)
    session['reset_step'] = 2
    return "验证通过，请设置新密码"

# 3) 设置新密码（step3）【防跨步核心】
def reset_password(new_pwd):
    # 必须校验会话状态
    if session.get('reset_step') != 2:
        return "请先完成验证"
    record = get_reset_record(session.id)
    if not record or record.status != 2 or record.expire < now():
        return "请重新申请重置"
    # 更新密码
    user = get_user(record.user_id)
    user.password = bcrypt.hash(new_pwd)
    update_user(user)
    # 标记已使用
    record.status = 3
    update_reset_record(record)
    # 清空会话、踢下线
    session.destroy()
    kick_all_sessions(user.id)
    return "密码重置成功"

一、iOS：防跨步（忘记密码）机制
 
1. 系统级安全兜底
 
- 沙箱 + 独立进程 + 权限最小化：App 数据隔离，无法越权读写
- Secure Enclave + Keychain：token、流程状态加密存储，不可篡改、不可导出 
- 防越狱检测（jailbreak detection）：越狱设备拦截敏感流程 
- 系统签名 + 代码签名（PPL）：防止 App 被篡改、注入、重打包 
 
2. 业务层防跨步（App 内）
 
- 服务端状态机（同 Web）： step=0/1/2/3 ，每步校验
- 客户端路由守卫：- 用  UINavigationController  或 SwiftUI 路由，禁止直接跳页
- 本地存  resetStep ，但以服务端会话为准
- DeepLink 安全：- 重置链接  myapp://reset?token=xxx  必须校验服务端状态
- 无效 token 直接回首页，不进入设置页 
- 一次性短时 Token：15～30 分钟、一次性、绑定  userId+session+device 
 
3. 代码要点（伪代码）

// 进入重置密码页前必须校验
func showResetPasswordVC() {
    // 1. 本地状态（辅助）
    guard UserDefaults.resetStep == 2 else {
        navigateToStep1()
        return
    }
    // 2. 服务端强校验（核心）
    api.checkResetStatus(sessionId) { status in
        if status == .verified {
            push(ResetVC())
        } else {
            navigateToStep1()
        }
    }
}
 
 
 
 
二、Android：防跨步机制
 
1. 系统级安全
 
- 沙箱 + UID 隔离 + SELinux：默认拒绝，最小权限
- Keystore + 密钥强存：敏感状态加密
- 防 root、防模拟器、防双开、防 Hook（Xposed/LSPosed） 
- APK 签名校验 + V2/V3 签名：防篡改
 
2. 业务防跨步
 
- 服务端状态机（核心）
- Activity 路由控制：- 用  startActivityForResult  / 导航组件，禁止隐式跳转
- 本地  SharedPreferences  存状态，但必须服务端二次校验
- DeepLink 防护：-  intent-filter  拦截重置链接，先请求服务端验证
- 无效直接回登录页 
 
3. 代码要点
 
kotlin
  
// 路由守卫
fun openResetPasswordActivity() {
    // 本地状态
    if (sp.getInt("resetStep", 0) != 2) {
        startStep1()
        return
    }
    // 服务端校验
    api.checkResetStatus().collect { valid ->
        if (valid) startActivity(Intent(this, ResetPwdActivity::class.java))
        else startStep1()
    }
}

四、三平台通用防跨步原则（必做）
 
1. 服务端绝对权威：客户端状态仅作展示，一切以服务端会话/状态为准
2. 流程状态机：严格  step1 → step2 → step3 ，不可跳步、不可回退复用
3. Token 安全：高熵、一次性、短时、强绑定用户/会话/设备
4. 客户端拦截：路由守卫、DeepLink 校验、防篡改环境检测
5. 失败统一提示：不泄露“账号不存在”“token 无效”等差异
6. 重置完成：清空会话、踢下线、通知用户
