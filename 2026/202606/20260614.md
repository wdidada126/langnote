四、重点：MySQL InnoDB 索引是什么树？
 
答案：B+ 树
 
不是二叉树，不是红黑树，不是 B 树。
 
为什么是 B+ 树？
 
- 多路平衡查找树，一个节点存很多 key
- 减少磁盘 IO（磁盘一次能读一整页）
- 叶子节点形成有序链表，适合范围查询
- 只有叶子节点存数据，非叶子只存索引
 
简单对比
 
- 二叉搜索树：IO 太多，不适合磁盘
- 红黑树：深度大，IO 爆炸
- B 树：数据分散，范围查询慢
- B+ 树：数据库索引标准结构
 
 
 
五、树结构必背专有名词（面试高频）
 
1. 二叉树基础
 
- 根节点 root
- 父节点 / 子节点
- 叶子节点 leaf
- 深度 depth
- 高度 height
- 满二叉树
- 完全二叉树（堆用这个）
 
2. 二叉搜索树 BST
 
- 左子树 < 根 < 右子树
- 查找 O(h)，最坏退化成链表 O(n)
 
3. 平衡二叉树 AVL
 
- 左右子树高度差 ≤1
- 旋转维持平衡：左旋、右旋、左右旋、右左旋
- 查找非常稳定，但插入删除旋转多
 
4. 红黑树
 
Java 最重要的树
 
- 节点非红即黑
- 根节点、叶子节点黑
- 红节点子节点必黑
- 任何节点到叶子的黑节点数量相同
→ 保证树高 O(log n)
→ TreeMap、TreeSet、HashMap 链表转树都用它
 
5. B 树 / B- 树
 
- 多路平衡查找树
- 一个节点多个 key
- 节点内数据有序
- 常用于文件系统
 
6. B+ 树
 
- B 树改进版
- 非叶子节点不存数据，只做索引
- 叶子节点形成有序链表
- 适合磁盘、范围查询
→ InnoDB 索引结构
 
7. Trie 树（字典树）
 
- 按字符前缀分叉
- 用于前缀搜索、自动补全
 
8. 跳表 SkipList
 
- 链表+多层索引，类似树的查找效率
- 实现简单、并发友好
- Redis ZSet、ConcurrentSkipListMap 都用跳表
 
9. 哈夫曼树 Huffman Tree
 
- 带权路径最短
- 用于数据压缩
 
 
 
六、一句话终极总结
 
- Java 标准库：TreeMap/TreeSet = 红黑树，PriorityQueue = 堆
- 三方库：红黑树、跳表居多，B+ 树一般在数据库里
- InnoDB 索引 = B+ 树
- 高频树：BST → AVL → 红黑树 → B 树 → B+ 树 → 跳表 → Trie

B 树（B-Tree）概念极简清晰版
 
1. 一句话定义
 
B 树是一种多路平衡查找树**，专门为磁盘、外部存储设计，用来减少 IO 次数。**
它不是二叉树，一个节点可以有多个关键字、多个子节点。
 
 
 
2. 核心特点
 
- 多路：一个节点能存很多 key，不是只有 2 个子节点
- 平衡：所有叶子节点在同一层，树高度很小
- 有序：节点内关键字从小到大排序
- 子节点数 = 关键字数 + 1
- 所有节点都存数据（数据分散在整棵树）
 
 
 
3. 阶数 m（m 阶 B 树）
 
m 表示一个节点最多有 m 个子节点。
对 m 阶 B 树，任意非根节点满足：
 
- 最少子节点数：⌈m/2⌉
- 最少关键字数：⌈m/2⌉ - 1
- 最多关键字数：m - 1
 
高度极低，几百万数据只有 2～4 层，磁盘 IO 极少。
 
 
 
4. 结构规则（必背）
 
1. 根节点至少 1 个关键字
2. 非叶子节点关键字有序
3. 子节点值范围严格夹在关键字之间
4. 所有叶子节点在同一层
5. 节点不会太满也不会太空（保证平衡）
 
 
 
5. 查找过程
 
1. 在节点内二分查找关键字
2. 找到就返回
3. 没找到就进入对应子节点
4. 重复直到叶子节点
 
因为节点大、层数少，磁盘 IO 非常少。
 
 
 
6. B 树 vs B+ 树（最关键区别）
 
- B 树：数据存在所有节点，查找速度不稳定
- B+ 树：- 只有叶子节点存数据
- 非叶子只存索引
- 叶子连成有序链表
- 更适合范围查询
→ MySQL InnoDB 索引用 B+ 树，不是 B 树
 
 
 
7. 常见面试问答
 
B 树是什么？
 
平衡多路查找树，为磁盘设计，减少 IO。
 
为什么不用二叉树？
 
二叉树层数太高，磁盘 IO 爆炸。
 
B 树和红黑树区别？
 
- 红黑树：二叉，内存用
- B 树：多路，磁盘用

数据库为什么不用 B 树用 B+ 树？
B+ 树叶子链表适合范围查询、单次查询 IO 更稳定。
