忘记密码“跨步”原理 + 开源方案
 
你说的安全跨步，一般叫：
找回密码分步验证 / 跨页校验 / 防回退防重放 / 防暴力跳过流程
核心目的：不让人直接跳转到最后一步改密码，必须按顺序走完验证，每一步不能回退、不能跳过。
 
一、跨步（分步校验）核心原理
 
1. 流程结构（标准 3 步）
 
1. 输入账号/手机号
2. 验证身份（短信/邮箱/密保/人脸）
3. 设置新密码
 
2. 跨步安全原理（关键点）
 
（1）状态机控制流程
 
后端维护一个找回密码状态：
 
-  INIT  已输入账号
-  AUTHED  已验证身份
-  RESET  允许重置密码
 
任何一步直接访问下一步，直接拒绝。
 
（2）一次性 token + 步序校验
 
每一步返回一个临时 stepToken，只能用于下一步，不能回退、不能复用。
例如：
 
- step1 → token1
- step2 → token2（必须用 token1 换取）
- step3 → 必须用 token2 才能调用
 
（3）防回退机制
 
后端记录当前所在步骤，不允许：
 
- 从 step3 退回到 step2
- 从 step2 退回到 step1
- 刷新重复提交
 
（4）短时效 + 单设备绑定
 
- 整个流程有效期通常 5～10 分钟
- 绑定 IP 或 deviceId
- 一次有效，用完即销毁
 
（5）防暴力跳过
 
直接访问  /resetPassword  但未经过验证 →
后端检查状态不是  AUTHED  → 直接拦截。

三、开源现成方案（可直接抄）
 
1. Spring Security 完整找回密码（Java 最常用）
 
Spring Security 自带认证流程 + 状态控制，可以快速实现跨步。
核心扩展：
 
-  ForgotPasswordToken 
-  AuthenticationProvider  分步校验
- 自定义过滤器控制步骤
 
适合：Java 后端、SpringBoot 项目
 
2. Apache Shiro 自定义分步流程
 
轻量级，自己实现三步状态机非常简单。
适合：老项目、权限简单的系统。
 
3. Sa-Token（国内最流行轻量级权限框架）
 
强烈推荐
内置：
 
- 分步认证
- 一次性 token
- 防重复提交
- 防回退
- 临时身份凭证
 
文档齐全，复制粘贴即可。
 
4. 若你是单体/简单系统
 
直接自己实现状态机，100 行代码搞定：
 
- 表  pwd_reset_task -  token  varchar
-  username 
-  status  0/1/2
-  expire 
-  device 
- 每步接口校验 status + 过期时间
 
 
 
四、前端跨步怎么实现？
 
前端只是“引导”，不能做安全控制。
真正安全必须后端控制步骤。
 
前端做法：
 
- 存当前步骤  step=1 
- 不允许手动改路由跳到  /step3 
- 每次下一步请求后端获取新 token
 
 
 
五、最安全的跨步规则（企业通用）
 
1. 必须按顺序 1→2→3
2. 每步只能前进，不能后退
3. 整个流程 10 分钟过期
4. 验证码只能用一次
5. 重置后立即销毁流程
6. 同一账号同时只能一个流程
7. 改密成功强制下线所有设备
