一、Java String 为什么是不可变的？
 
 String  不可变，本质是：底层  char[]  被  final  修饰 + 类无提供任何修改字符的方法 + 类被  final  禁止继承。
 
1. 源码层面原因
 
java
  
public final class String
    implements java.io.Serializable, Comparable<String>, CharSequence {
    private final char value[];  // 核心：数组引用不可变，且无set方法
}
 
 
-  final class ：不能被继承，避免子类破坏不可变
-  private final char[] ：引用不可变，且外部无法直接修改数组内容
- 所有看似“修改”的方法（ substring / replace / concat ）都返回新 String 对象
 
2. 设计好处（为什么要这么做）
 
1. 线程安全：只读，多线程无需同步
2. 字符串常量池复用：相同字面量共享同一个对象，节省内存
3. 哈希值可缓存： HashMap  中  String  做 key 很高效， hashCode()  只算一次
4. 安全可靠：作为类名、文件路径、网络地址时不会被意外篡改
 
 
 
二、对象相等 vs 引用相等
 
1. 引用相等（ ==  比较）
 
- 比较的是：两个变量存储的内存地址是否一样
- 即：是否指向同一个对象
- 基本类型用  ==  比较值；引用类型用  ==  比较地址
 
2. 对象相等（ equals()  比较）
 
- 比较的是：对象内容/状态是否等价
- 由类自己重写  equals()  定义规则
-  String  已重写：逐字符比较内容
 
 
 
三、最直观例子
 
java
  
String s1 = "abc";
String s2 = "abc";
String s3 = new String("abc");
 
 
1.  s1 == s2  →  true 
都指向常量池同一个对象，引用相等
2.  s1 == s3  →  false 
s3 是堆上新对象，地址不同，引用不等
3.  s1.equals(s3)  →  true 
内容一样，对象相等
 
 
 
四、一句话总结
 
-  == ：比地址，是不是同一个对象
-  equals() ：比内容，是不是等价对象
- String 不可变 = 内容不能改，改就产生新对象

对象实体 vs 对象引用（面试标准答案）
 
1. 概念区别
 
- 对象实体（Object Instance）- 在堆内存中真实创建的实例
- 存储对象的成员变量、数据、状态
- 由  new  关键字创建，是真正的“对象本身”
- 对象引用（Reference）- 存在于栈内存（或方法区常量池）
- 本质是一个地址值，指向堆中的对象实体
- 相当于“遥控器/指针”，不存储对象数据
 
一句话概括：
引用是地址，实体是堆里的真实对象。
 
 
 
2. 内存位置不同
 
- 对象引用：栈帧中（局部变量表）
- 对象实体：堆内存
 
java
  
User user = new User();
 
 
-  user ：引用，在栈
-  new User() ：实体，在堆
 
 
 
3. 数量关系
 
- 一个引用可以指向 0 个或 1 个实体-  User user = null;  → 引用不指向任何对象
- 多个引用可以指向同一个实体java
  
User a = new User();
User b = a;
 
 
a 和 b 是两个引用，但指向同一个对象实体。
 
 
 
4. 赋值与修改行为不同
 
- 引用赋值：只是复制地址，不复制对象
- 修改实体：所有指向它的引用都会“看到变化”
 
示例：
 
java
  
User u1 = new User();
User u2 = u1;
u2.setName("张三");

// u1.getName() 也变成“张三”
 
 
原因：u1、u2 指向同一个对象实体。
 
 
 
5. 生命周期不同
 
- 引用：随方法出栈而销毁
- 实体：由 GC 决定回收，当没有任何引用指向时才会被回收
 
 
 
面试一句话总结（背这个）
 
对象引用是栈里的地址变量，用来指向堆中的对象实体；对象实体是真正在堆中创建的实例，存储数据和状态。多个引用可以指向同一个实体，引用赋值只是复制地址，不会创建新对象。

equals() 与 hashCode() 面试标准答案（必背）
 
一、equals() 必须遵守的 5 大规范（面试常问）
1. 自反性： x.equals(x) == true 
2. 对称性： x.equals(y)  为 true，则  y.equals(x)  也为 true
3. 传递性： x.equals(y) 、 y.equals(z)  为 true，则  x.equals(z)  也为 true
4. 一致性：多次调用结果一致，无变化则不变
5. 非空性： x.equals(null) == false 

二、equals 与 hashCode 核心约定（最重要！必背）
 
1. 两个对象 equals 为 true，则它们的 hashCode 必须相等
2. hashCode 相等，equals 不一定为 true（哈希冲突）
3. 若重写 equals，必须重写 hashCode
4. 若不重写 hashCode，默认使用对象内存地址，会导致 HashMap/HashSet 等集合无法正常工作 
 
三、为什么要同时重写？（面试高频）
- HashMap 先根据 hashCode 定位桶位置
- 再用 equals 判断是否是同一个 key
- 只重写 equals 不重写 hashCode：
→ 两个逻辑相等的对象，hashCode 不同
→ 会被放进不同桶，当成不同 key
→ 导致 Set 存重复值、Map 存重复 key
 
四、比较时注意事项
 
1. == 比较引用地址，equals 比较内容
2. 比较前先判断是否为 null，避免 NPE
3. 先判断 引用是否同一（ this == obj ），是则直接返回 true，提高效率
4. 判断 类型是否一致（ instanceof  /  getClass() ）
5. 比较关键业务字段，不要比较无关字段
6. 用于集合的对象，不要用可变字段参与 equals/hashCode
否则存入后修改属性，会导致对象“丢失”，无法 remove

五、标准写法模板（面试可直接说）
 
java
  
@Override
public boolean equals(Object o) {
    // 1. 同一对象直接返回true
    if (this == o) return true;

    // 2. 空判断 且 类型一致
    if (o == null || getClass() != o.getClass()) return false;

    // 3. 强转
    User user = (User) o;

    // 4. 比较关键字段
    return Objects.equals(id, user.id) && Objects.equals(name, user.name);
}

@Override
public int hashCode() {
    // 使用和equals相同的字段
    return Objects.hash(id, name);
}
 
 
 
 
六、面试一句话总结
 
equals 相等则 hashCode 必须相等，反之不一定；重写 equals 必须重写 hashCode，否则哈希集合失效；比较时先比引用、再比类型、最后比关键字段，避免使用可变字段。
