RAG 概念极简完整解析
 
一、全称
 
Retrieval-Augmented Generation
检索增强生成，大模型主流落地架构。
 
二、核心本质
 
原生大模型存在两大短板：
 
1. 知识截止：训练数据有时间断点，无法获取最新信息；
2. 幻觉问题：容易编造不存在的内容，引用错误资料。
 
RAG 就是先检索外部知识库，再把查到的资料喂给大模型，让它基于真实文档来回答，用外部资料约束生成结果，减少胡说、补齐新知识。
 
三、标准4步工作流程
 
1. 文档入库（预处理）
PDF/Word/网页/知识库文本 → 文本分割切块 → 向量化（Embedding）→ 存入向量数据库。
2. 用户提问
用户输入问题。
3. 检索匹配
问题同样做向量编码，在向量库中检索相似度最高的几段原文。
4. 增强Prompt+生成回答
把「用户问题 + 检索到的参考原文」一起打包发给LLM，大模型限定依据给到的材料输出答案。
 
四、核心优势
 
1. 知识可随时更新：新增文档直接入库，不用重新微调、重训大模型；
2. 大幅降低幻觉：回答有原文依据，可溯源；
3. 低成本私有化部署：企业内部机密文档不用灌进模型训练，仅向量存储，数据更安全；
4. 节约上下文窗口：只拉取相关片段，避免超长上下文浪费token。
 
五、和微调（Fine-tune）区别
 
- RAG：外挂知识库，动态改资料，适合文档问答、知识库、客服、知识库机器人；
- 微调：修改模型参数，固化知识，适合固定风格、固定格式输出、小众指令习惯。
工程上常组合使用：RAG做知识外挂 + 微调统一话术风格。
 
六、常见技术组件
 
1. 文档解析：PyPDF、Unstructured、LangChain DocumentLoader
2. 文本切分：RecursiveCharacterTextSplitter
3. 向量嵌入Embedding：OpenAI Embedding、BGE、m3e、text2vec
4. 向量数据库：Chroma、FAISS、Milvus、Qdrant、Pinecone
5. 大模型LLM：GPT、通义千问、Llama、Qwen、DeepSeek等开源/闭源模型
6. 编排框架：LangChain、LlamaIndex、Haystack
 
七、典型落地场景
 
企业知识库问答、智能客服、法律文书检索、产品手册答疑、内网文档机器人、知识库AI助手、论文文献查阅、私有数据ChatGPT。
 
八、最简一句话总结
 
RAG = 先查资料，再让AI照着查到的资料说话。
