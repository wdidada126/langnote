## 第一部分：`Host.h` 的兼容处理

```cpp
#if __has_include(<llvm/TargetParser/Host.h>)

#endif
```

背景：LLVM 在版本演进中把 `Host.h` 从一个位置挪到了另一个位置：

| LLVM 版本 | 路径 |
|-----------|------|
| 旧版本（约 LLVM 16 之前） | `llvm/Support/Host.h` |
| 新版本（LLVM 16/17+） | `llvm/TargetParser/Host.h` |

`__has_include` 是 C++17 的预处理特性（C++11/14 也可作为编译器扩展使用），用来检测某个头文件是否存在。逻辑是：

- 优先用新路径 `llvm/TargetParser/Host.h`
- 如果不存在，回退到旧路径 `llvm/Support/Host.h`

这样一份代码就能同时编译新旧 LLVM。

`Host.h` 里通常包含 `llvm::sys::getDefaultTargetTriple()`、`getHostCPUName()` 等函数。

Rust 的核心特性可以从内存安全、类型系统和异步编程三个维度来理解。以下是这些知识点的系统梳理。

### 所有权 (Ownership)：编译期的内存管理

所有权是 Rust 内存安全的基石，它在编译期通过一套规则管理内存，无需运行时垃圾回收。

三大核心规则：
1. 每个值有且只有一个所有者：变量是值的所有者，当所有者离开作用域时，值会被自动释放（通过 `Drop` trait）。
2. 所有权可转移（Move 语义）：赋值或传参时，所有权会从原变量转移到新变量，原变量随即失效。这避免了同一块堆内存被释放两次的“双重释放”错误。
3. 函数返回时可转移所有权：函数可以通过返回值将所有权交还给调用者，避免内存泄漏。

对于实现了 `Copy` trait 的类型（如整数），赋值执行的是复制而非移动，原变量仍然有效。

### 借用 (Borrowing)：临时访问数据

借用允许你通过引用临时使用数据而不获取所有权，避免了不必要的所有权转移。

两条借用规则：
*   不可变引用 `&T`：可以同时存在多个，但数据只能读取，不能修改。
*   可变引用 `&mut T`：同一时间只能存在一个，且在此期间不能有任何其他引用（包括不可变引用）。

借用检查器（Borrow Checker）在编译期强制执行这些规则，从根源上消除了数据竞争。

### 生命周期 (Lifetimes)：引用有效性的约束

生命周期是编译器用来追踪引用有效范围的机制，用于防止悬垂指针。当涉及多个引用时，需要显式标注生命周期（如 `'a`），向编译器声明这些引用的存活时间至少一样长。

### 模式匹配与代数数据类型 (ADT)

Rust 的 `enum` 是真正的代数数据类型（ADT），其变体可以携带不同类型和数量的数据，这远超 C 风格枚举的能力。

```rust
enum Message {
    Quit,                       // 无数据
    Move { x: i32, y: i32 },   // 结构体式变体
    Write(String),              // 元组式变体
    ChangeColor(i32, i32, i32),
}
```

模式匹配通过 `match` 表达式使用，核心优势在于穷尽性检查：编译器会确保所有可能的情况都被处理，否则报错。结合 `if let` 和 `while let`，可以简洁地只匹配关心的模式。

### 宏 (Macros)：编译时代码生成

宏在编译时进行代码生成和转换，是减少样板代码的利器。Rust 有两种主要宏：

声明宏（`macro_rules!`）：通过模式匹配定义语法规则，适合重复性的代码简化。

过程宏（Procedural Macros）：接收 Token 流并生成新代码，常用于自定义 `derive` 宏。使用时需要 `syn` 解析和 `quote` 生成代码。

使用原则：优先使用泛型，因为泛型更安全、错误信息更清晰；仅在泛型无法表达或需要大幅减少样板时才使用宏。

### 泛型关联类型 (GATs)

GAT 允许关联类型本身携带泛型参数（如生命周期或类型），解决了“借贷迭代器”（`LendingIterator`）等此前无法在稳定版 Rust 中表达的抽象模式。

```rust
trait LendingIterator {
    type Item<'a> where Self: 'a;
    fn next<'a>(&'a mut self) -> Option<Self::Item<'a>>;
}
```

`Item<'a>` 与 `self` 的借用生命周期绑定，使得 `next` 返回的引用不能比 `self` 的借用活得更久。Rust 1.65 稳定了 GAT。需要注意，GAT 往往需要搭配 `where Self: 'a` 这类约束来保证生命周期良构性。

### 高阶类型 (Higher-Kinded Types) 的模拟

Rust 的类型系统不直接支持真正的高阶类型（即对“类型构造器”本身的抽象）。GAT 提供了部分能力，而社区库（如 `higher`）通过 `Lift` trait 和派生宏来模拟这一特性，允许你从 `T<A>` 推导出 `T<B>`。

### async/await：Future 的语法糖

`async/await` 是 Rust 异步编程的语法糖，底层基于 `Future` trait。

*   `async fn` 返回一个实现了 `Future` 的类型。
*   `.await` 用于驱动 `Future` 执行，如果遇到 `Pending` 状态，会将控制权交还给运行时（Executor），而不是阻塞线程。

`async` 块是惰性的：创建 `Future` 不会执行任何代码，只有被 `.await` 或 Executor 驱动时才会运行。由于 `async fn` 返回的 `Future` 生命周期受参数引用约束，将引用参数移入 `async` 块内部可以延长其寿命。
