在 C++ 中，const 和 consteval（你可能笔误了 consrexp，实际是 constexpr）是三个极易混淆的关键字。它们的核心区别在于“阶段”：const 在运行期生效，而 constexpr 和 consteval 在编译期执行。

为了让你一眼看懂，我们先看核心对比表，再深入细节：

1. 一句话速查表

关键字 核心作用 值必须在编译期已知？ 能否修饰函数
const 运行期常量（只读，不可修改） 否（可在运行时赋值） 否（仅修饰成员函数）
constexpr 编译期常量（若可能，在编译期计算） 是（用于常量表达式） 是（返回值可在编译期求值）
consteval (C++20) 强制编译期执行（必须在编译期运行） 是（必须） 是（产生常量表达式）


2. 深度辨析（重点）

· const vs constexpr（变量）
  · const int a = getValue(); 合法，a 只是在运行时不能改，但值可以是动态获取的。
  · constexpr int b = getValue(); 报错，因为 getValue() 若不是 constexpr 函数，编译期无法获知值，b 必须是一个编译期确定的常量表达式（如 5 或 5+3）。
· constexpr vs consteval（函数）
  · constexpr 函数：“尽力而为”。它既可以在编译期运行（给常量赋值时），也可以在运行时运行（给普通变量赋值时）。
  · consteval 函数：“必须做到”。它只能用于编译期，如果试图在运行时调用它（如 int x = consteval_func(rand());），编译器直接报错。它适合用于必须在编译期完成校验的场景（如静态断言）。
· const 成员函数：这是 const 独有的用法，表示该函数不会修改对象的成员变量（mutable 除外），允许常量对象调用该函数。

---

3. 实战代码（一眼看懂）

```cpp
// 1. const：运行时常量
int x = 10;
const int a = x; // 合法，a 只是不能改，值来自运行时

// 2. constexpr：编译期常量
constexpr int b = 5 * 3; // 合法，编译期算出 15

// 3. constexpr 函数（灵活）
constexpr int square(int n) { return n * n; }
constexpr int c = square(10); // 编译期执行
int d = square(x);            // 运行时执行（x是变量），合法！

// 4. consteval 函数（强制编译期，C++20）
consteval int cube(int n) { return n * n * n; }
constexpr int e = cube(3);   // 合法，编译期执行
// int f = cube(x);          // 报错！因为 x 不是常量，无法在编译期执行
```

4. 使用建议（避坑指南）

· 优先用 constexpr 替代宏 (#define)，它有类型检查且遵循作用域。
· 如果你的变量必须在编译期用于数组大小或模板参数，只能用 constexpr（或 consteval）。
· 如果你只是想给变量加个“只读”锁，防止被误改，用 const 就够了，不必强求 constexpr。
· 如果你写了一个函数，只允许在编译期执行（比如用于静态反射），C++20 起请使用 consteval。

用具体例子来说明轨迹规划里的数值优化，这样最直观。

## 先搞清楚：轨迹规划在优化什么？

一句话：在满足约束的前提下，找一条让某个目标最好的运动轨迹。

数学上通常写成：

```
minimize    J(轨迹)          // 目标：平滑、快、省力...
subject to  运动学约束        // 关节限位、避障
            动力学约束        // 力矩、速度上限
            边界条件          // 起点/终点状态
```

## 例子 1：机械臂点到点，要"最平滑"

场景：六轴机械臂从 A 点移到 B 点，希望中间不抖动。

怎么变成优化问题：

- 把轨迹离散成 N 个时间点，每个点是关节角 `q₀...qₙ`
- 目标函数：最小化加加速度（jerk），让运动柔顺
  ```
  J = Σ ‖q̈(t)‖²  →  越小越平滑
  ```
- 约束：
  - `q(0) = A`，`q(T) = B`（起终点）
  - `q_min ≤ q ≤ q_max`（关节限位）
  - `|q̇| ≤ v_max`（速度上限）

数值方法：这是一个二次规划（QP） 问题——目标二次、约束线性，可以用 OSQP 秒解。工业上经典的 TOPP（时间最优路径参数化） 就是这类。

> 关键点：连续轨迹 → 离散成有限变量 → 变成标准优化问题。

## 例子 2：避障，绕开一个球

场景：机械臂末端要经过一个障碍球，不能碰到。

约束是非线性的：

```
‖p(q) - p_obstacle‖ ≥ r_safe
```

其中 `p(q)` 是末端位置，是关节角 `q` 的非线性函数（正运动学）。

这时候目标 + 约束都非线性 → 变成 非线性规划（NLP）：

```
min  J(平滑) + J(避障软惩罚)
s.t. 非线性运动学约束
```

数值方法：

- CHOMP / TrajOpt：把连续轨迹离散，用梯度下降 / SQP 迭代
- 求解器：Ipopt、SNOPT、NLopt

难点：非线性 → 有局部最优，初始轨迹不好会卡在障碍里。工程上常先用 RRT 找条粗路径，再拿它当初始解做优化。

## 例子 3：人形机器人走路（最硬核）

场景：双足机器人走路，要动态平衡不摔倒。

这不只是轨迹，是动力学 + 接触：

- 变量：关节角、关节力矩、接触力
- 动力学约束：
  ```
  M(q)q̈ + C(q,q̇) + g(q) = τ + Jᵀ·f_contact
  ```
- 接触约束：脚不能滑、不能穿透地面
- 目标：省力矩、走得快、保持平衡

数值方法：

- 直接法（Direct Collocation / Shooting）：把动力学离散，整个问题扔给 NLP 求解器
- 求解器：Ipopt、SNOPT
- 专用框架：Crocoddyl（用 DDP/iLQR）、Drake（轨迹优化 + 数学规划）

这就是为什么难：动力学本身是非线性微分方程，加上接触这种"开关式"不连续，优化问题又大又非凸。

## 例子 4：自动驾驶换道（路径 + 速度）

场景：车要换道，规划一条安全又舒适的路径。

- 变量：路径点 (x, y) + 每个点的速度 v
- 目标：
  ```
  J = w₁·(加速度)² + w₂·(jerk)² + w₃·偏离车道惩罚
  ```
- 约束：
  - 不与前车/旁车碰撞（非线性）
  - 速度、加速度、曲率上限
  - 车道边界

数值方法：

- QP 路径优化：Frenet 坐标系下，横向轨迹用五次多项式 + QP
- EM Planner / Apollo：路径和速度解耦，各自 QP
- MPC：滚动时域，每个周期解一次 QP

## 数值优化的"武器库"总结

| 问题类型 | 典型场景 | 求解器/方法 |
|---|---|---|
| QP（二次规划） | 平滑轨迹、MPC、TOPP | OSQP、qpOASES |
| NLP（非线性规划） | 避障、动力学 | Ipopt、SNOPT |
| DDP / iLQR | 最优控制、腿足 | Crocoddyl、ALTRO |
| 凸优化 | 安全走廊、SDP松弛 | Mosek、CVXPY(原型) |
| 采样规划 | 高维复杂环境 | RRT*、PRM（非优化，常做初值） |

## 一句话理解本质

> 轨迹规划 = 把"怎么动"翻译成"最小化什么、满足什么约束"，然后用数值方法迭代求解。

- 变量：轨迹离散点
- 目标：平滑 / 快 / 省力
- 约束：限位 / 避障 / 动力学
- 算法：梯度、QP、NLP、DDP
