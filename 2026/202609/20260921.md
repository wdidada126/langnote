semgrep免费扫描

将 Semgrep 接入 GitHub Actions 主要分为 基础接入、进阶配置、自定义规则 和 常见问题处理 四个部分。以下是完整的接入指南：

基础接入：最小可用配置

在仓库中创建 .github/workflows/semgrep.yml 文件，写入以下内容：

name: Semgrep Security Scan

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  semgrep:
    runs-on: ubuntu-latest
    container:
      image: semgrep/semgrep
    steps:
      - uses: actions/checkout@v4

      - name: Run Semgrep
        run: semgrep ci
        env:
          SEMGREP_APP_TOKEN: ${{ secrets.SEMGREP_APP_TOKEN }}

关键步骤说明：

1. 前往 Semgrep AppSec Platform 注册账号并登录
2. 在 Settings 中生成一个 SEMGREP_APP_TOKEN
3. 在 GitHub 仓库的 Settings → Secrets and variables → Actions 中，添加名为 SEMGREP_APP_TOKEN 的 Secret，填入上一步生成的 Token

进阶配置：触发策略与扫描模式

触发时机

Semgrep 支持多种触发方式，可以根据团队需求组合使用：

on:
  # PR 时进行差异扫描（只扫描变更文件）
  pull_request: {}

  # 按需手动触发
  workflow_dispatch: {}

  # 主分支有 workflow 文件变更时触发
  push:
    branches: [main, master]
    paths: [.github/workflows/semgrep.yml]

  # 定时全量扫描（每天 UTC 17:20）
  schedule:
    - cron: '20 17 * * *'

差异扫描 vs 全量扫描

- 差异扫描（Diff-aware）：在 pull_request 触发时，Semgrep 会自动只扫描变更的代码，减少噪音
- 全量扫描：在 schedule 或 workflow_dispatch 触发时，扫描整个代码库，适合定期全面体检

跳过 Dependabot PR

避免权限问题导致扫描失败：

jobs:
  semgrep:
    if: (github.actor != 'dependabot[bot]')
    # ...

规则配置

使用官方预设规则集

Semgrep 提供了丰富的官方规则集，通过 --config 参数指定：
规则集   用途
p/security   安全漏洞检测
p/secrets   硬编码密钥/密码检测
p/dockerfile   Dockerfile 安全检查
p/python / p/java / p/typescript   按语言的代码质量规则
p/ci   适合 CI 环境的轻量规则
auto   自动识别项目语言并加载对应规则

示例：

- name: Run Semgrep
  run: semgrep ci --config=p/security --config=p/secrets

添加自定义业务规则

在项目根目录创建 rules/ 目录，编写自定义 YAML 规则文件。例如检测内部 API 密钥泄露：

# rules/internal-api-key.yaml
rules:
  - id: internal-api-key-exposed
    patterns:
      - pattern-regex: "sk-[a-zA-Z0-9]{32,}"
    message: "疑似内部API密钥暴露在代码中"
    languages: [generic]
    severity: ERROR

然后在 workflow 中引用：

- name: Run Semgrep
  run: semgrep ci --config=p/security --config=rules/

输出与告警

生成 SARIF 报告并上传到 GitHub Security Tab

- name: Run Semgrep
  run: semgrep ci --sarif -o result.sarif

- name: Upload SARIF to GitHub
  if: always()
  uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: result.sarif
    category: semgrep

这样扫描结果会直接显示在仓库的 Security → Code scanning alerts 页面中。

控制 CI 是否阻断

- 默认情况下，发现 ERROR 级别问题会令 CI 失败，阻断 PR 合并
- 如果只想告警不阻断，添加 --suppress-errors 参数：

- name: Run Semgrep
  run: semgrep ci --suppress-errors

常见问题处理
问题   原因   解决方案
扫描超时   项目太大   加 --max-target-bytes 3MB 限制单文件大小
误报太多   规则太宽泛   用 // nosemgrep: rule-id 注释排除特定行
CI 集成报错   Token 未配置   在 GitHub Secrets 中正确配置 SEMGREP_APP_TOKEN
扫描结果为空   规则不匹配语言   检查规则中 languages 字段是否与项目一致
内存不足   大文件扫描   加 --max-memory 2048 限制内存使用

完整示例

一个生产环境推荐的完整配置：

name: Semgrep Security Scan

on:
  pull_request: {}
  workflow_dispatch: {}
  schedule:
    - cron: '0 2 * * 0'  # 每周日凌晨2点全量扫描

permissions:
  contents: read
  security-events: write

jobs:
  semgrep:
    name: semgrep/ci
    runs-on: ubuntu-latest
    if: (github.actor != 'dependabot[bot]')
    container:
      image: semgrep/semgrep

    steps:
      - uses: actions/checkout@v4

      - name: Run Semgrep
        run: semgrep ci --config=auto --config=rules/ --sarif -o result.sarif

      - name: Upload SARIF to GitHub
        if: always()
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: result.sarif
          category: semgrep

      - name: Upload SARIF as artifact
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: semgrep-results
          path: result.sarif

这样配置后，每次 PR 会自动进行差异扫描，每周进行一次全量扫描，结果同步到 GitHub Security 面板，形成完整的代码安全防线。
