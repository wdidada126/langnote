你问的是 `#[derive(Default)]` —— 这是 Rust 的一个派生宏（derive macro），用来自动为结构体或枚举实现 `Default` trait。

## 基本用法

```rust
#[derive(Default)]
struct Config {
    name: String,
    port: u16,
    debug: bool,
}
```

等价于你手写：

```rust
impl Default for Config {
    fn default() -> Self {
        Config {
            name: String::default(),  // ""
            port: u16::default(),      // 0
            debug: bool::default(),    // false
        }
    }
}
```

然后就能用：

```rust
let c = Config::default();
let c2 = Config { port: 8080, ..Default::default() }; // 结构体更新语法
```

## 规则与限制

### 1. 所有字段都必须实现 `Default`

```rust
#[derive(Default)]
struct Bad {
    v: Vec<i32>,       // ✅ Vec 实现了 Default
    s: String,         // ✅ String 实现了 Default
    // f: SomeType,    // ❌ 如果 SomeType 没实现 Default，编译失败
}
```

### 2. 每个字段用各自的 `default()` 值

- 数值类型 → `0`
- `bool` → `false`
- `String` / `Vec` / `HashMap` → 空
- `Option<T>` → `None`
- 引用 → 不能有 `Default`（除非是 `&'static T` 特殊场景，一般不行）
- 元组 / 数组 → 逐元素 `Default`，但数组长度 > 32 时旧版本不支持（现在已放宽）

### 3. 枚举也可以 derive

```rust
#[derive(Default)]
enum Color {
    #[default]
    Red,
    Green,
    Blue,
}
```

必须用 `#[default]` 标记一个无字段的变体作为默认值。这是 Rust 1.62 之后才支持的。

### 4. 不能有泛型约束自动推导

```rust
#[derive(Default)]
struct Wrapper<T> {
    value: T,
}
```

这不会自动生成 `impl<T: Default> Default for Wrapper<T>`——`derive` 宏会生成 `impl<T: Default> Default`，但需要你自己确保 `T: Default`。实际上标准库的 derive 会生成带 `T: Default` 约束的实现，所以只要 `T` 实现了 `Default` 就能用。

## 和 `new()` 的区别

| | `Default::default()` | 自定义 `new()` |
||||
| 来源 | trait，标准接口 | 普通关联函数 |
| 能否用于泛型约束 | ✅ `T: Default` | ❌ 不能约束 |
| 能否用于 `..Default::default()` | ✅ | ❌ |
| 语义 | “零值 / 空值” | 任意构造逻辑 |

所以写库时，优先实现 `Default`，再考虑是否额外提供 `new()`。

## 一句话总结

`#[derive(Default)]` = 让编译器自动生成 `impl Default`，前提是所有字段都实现 `Default`；枚举需要 `#[default]` 标记一个无字段变体。它让你能写 `Config::default()` 和 `..Default::default()`，是 Rust 里最常用的派生之一。

cargo expand（最直接）

这是专门用于查看宏展开后完整源码的工具。先安装：
cargo install cargo-expand
然后在项目目录运行：

cargo expand --bin vec

`cargo expand` 的功能核心是把宏展开和 `#[derive]` 展开后的代码原样输出给你看。除了最基础的用法，它还有不少能提升调试效率的选项。

### 精准定位：只看你想看的部分

当项目变大，展开全部代码会非常庞大。你可以用这些方式缩小范围：

*   指定目标 (Target)：你的多 `[[bin]]` 项目必须用这个。用 `--bin <名称>` 指定单个二进制，或用 `--lib` 指定库。
  ```bash
  cargo expand --bin 05_vecs_vecs2
  ```
*   指定模块或路径：只展开你关心的模块、类型或函数，比如 `cargo expand path::to::module` 或 `cargo expand my_macro`。
*   包含测试：`--tests` 可以把测试代码也展开出来。

### 🛠️ 控制输出格式

*   `--ugly`：不尝试用 rustfmt 格式化。当你只是想快速看一眼原始展开结构，或者 rustfmt 跑得很慢时有用。
*   语法高亮与分页：可以通过 `--theme <NAME>` 选主题，或用 `--themes` 列出所有主题。在配置文件里开启 `pager = true` 后，输出会自动用分页器打开，方便查看长结果。

### 更顺手的调试替代方案

虽然 `cargo expand` 很强大，但在 IDE 里直接展开宏有时更方便：
*   VS Code / rust-analyzer：把光标放在宏调用上，运行命令 `rust-analyzer: Expand macro recursively`，就能在弹出窗口里看到展开结果，不用敲命令行。
*   Neovim：有 `cargo-expand.nvim` 这类插件，可以在编辑器里直接调用 `cargo expand` 并跳转到展开后的代码。

### 一个重要的注意事项

`cargo expand` 的输出是给人类看的，不保证能编译回去。宏展开过程是有损的（Lossy），特别是在涉及卫生性（Hygiene）时。官方文档里有个经典例子：一段普通编译返回 `3` 的代码，展开后的文本如果拿去编译，结果会变成 `4`。所以，它是个纯粹的调试辅助工具，不要指望用它来做代码生成或重构。

Rust 里所有实现了 `Default` 的类型都有一个明确的“默认值”，规则是“零值 / 空值 / 无”。下面按类别列全。

## 一、标量类型

| 类型 | 默认值 |
|||
| `u8` / `u16` / `u32` / `u64` / `u128` / `usize` | `0` |
| `i8` / `i16` / `i32` / `i64` / `i128` / `isize` | `0` |
| `f32` / `f64` | `0.0` |
| `bool` | `false` |
| `char` | `'\0'`（U+0000，空字符） |

注意 `char` 的默认值是 `'\0'`，不是 `' '` 空格。

## 二、复合类型

| 类型 | 默认值 |
|||
| `()` | `()` |
| `(A, B, ...)` | 每个元素各自 `Default` |
| `[T; N]` | 每个元素 `T::default()`，即 `[T::default(); N]` |
| `&T` / `&mut T` | 不实现 `Default`（引用没有默认值） |
| `*const T` / `*mut T` | 不实现 `Default`（裸指针没有默认值） |

元组和数组的默认值都是逐元素递归生成的，例如 `(i32, bool)` 的默认值是 `(0, false)`。

## 三、标准库容器与智能指针

| 类型 | 默认值 |
|||
| `String` | `""`（空字符串） |
| `Vec<T>` | `vec![]`（空 Vec） |
| `VecDeque<T>` | 空双端队列 |
| `LinkedList<T>` | 空链表 |
| `HashMap<K, V>` | 空 map |
| `BTreeMap<K, V>` | 空 map |
| `HashSet<T>` | 空 set |
| `BTreeSet<T>` | 空 set |
| `BinaryHeap<T>` | 空堆 |
| `Box<T>` | `Box::new(T::default())`，要求 `T: Default` |
| `Rc<T>` / `Arc<T>` | `Rc::new(T::default())` / `Arc::new(T::default())`，要求 `T: Default` |
| `Cow<'a, T>` | `Cow::Owned(T::default())` 或借用空值，取决于 `T` |

注意：`Box<T>`、`Rc<T>`、`Arc<T>` 的 `Default` 要求内部 `T: Default`，默认值就是“包一个默认的 T”。

## 四、Option / Result / 其他

| 类型 | 默认值 |
|||
| `Option<T>` | `None`（不需要 `T: Default`） |
| `Result<T, E>` | 不实现 `Default` |
| `PhantomData<T>` | `PhantomData` |
| `Duration` | `Duration::ZERO` |
| `Range<T>` | 不实现 `Default` |
| 函数指针 `fn(...)` | 不实现 `Default` |
| trait 对象 `dyn Trait` | 不实现 `Default` |

`Option<T>` 的 `Default` 是 `None`，这是它特别常用的原因之一：`HashMap::entry().or_default()` 在 value 是 `Option<T>` 时直接得到 `None`。

## 五、不实现 `Default` 的常见类型

这些类型没有默认值，所以不能 `#[derive(Default)]` 包含它们，也不能用 `or_default()`：

- 所有引用 `&T`、`&mut T`
- 裸指针 `*const T`、`*mut T`
- 函数指针、闭包
- `Result<T, E>`
- `Range<T>`
- `dyn Trait`
- 任何你自定义但没实现 `Default` 的类型

如果结构体里有一个字段是这些类型，`#[derive(Default)]` 会直接编译失败。

## 六、一句话总结规律

Rust 的 `Default` 遵循“加法单位元 / 空容器 / 无”的直觉：

- 数字 → `0` / `0.0`
- 布尔 → `false`
- 字符 → `'\0'`
- 容器 → 空
- `Option` → `None`
- 指针/引用/Result → 没有默认值

---

## 一、属性部分

```rust
#[macro_export]
```
导出这个宏，让它在 crate 外部也能用。没有这个属性，`println!` 就只是 `std` 内部的私有宏，你写 `println!("hi")` 会找不到。`#[macro_export]` 会把宏放到 crate 根路径下，所以外部可以 `use std::println;` 或直接通过 prelude 使用。

```rust
#[stable(feature = "rust1", since = "1.0.0")]
```
稳定性标记。`feature = "rust1"` 是当初这个 API 进入稳定版时所属的 feature 名，`since = "1.0.0"` 表示从 Rust 1.0 起就稳定可用。这是给编译器内部和文档用的，普通代码里看不到。

```rust
#[cfg_attr(not(test), rustc_diagnostic_item = "println_macro")]
```
条件属性：只有在非测试编译时，才添加 `rustc_diagnostic_item = "println_macro"`。

- `cfg_attr(条件, 属性)`：条件为真时，才把后面的属性加上。
- `not(test)`：不在 `cargo test` 编译时。
- `rustc_diagnostic_item`：给这个宏起一个编译器内部诊断用的名字。当编译器报错时（比如 `println!` 参数不匹配），它可以用这个名字生成更友好的错误信息，而不是显示宏展开后的内部代码。测试时去掉，是因为测试环境不需要这套诊断机制。

```rust
#[allow_internal_unstable(print_internals, format_args_nl)]
```
允许这个宏内部使用不稳定的 API。`println!` 底层依赖 `print_internals` 和 `format_args_nl` 这两个未稳定的内部功能。普通用户代码不能直接用它们，但标准库宏在 `allow_internal_unstable` 的“豁免”下可以。这是标准库宏能调用内部私有功能的关键机制。

---

## 二、宏定义部分

```rust
macro_rules! println {
    () => { ... };
    ($($arg:tt)*) => { ... };
}
```

`println!` 有两个匹配分支：

### 分支 1：`()` —— 无参数

```rust
() => {
    $crate::print!("\n")
};
```

`println!()` 等价于打印一个换行符。注意用的是 `$crate::print!`，`$crate` 是宏卫生机制里的特殊标识，指向定义这个宏的 crate（这里是 `std`），保证外部调用时不会因为作用域问题找不到 `print!`。

### 分支 2：`($($arg:tt)*)` —— 任意参数

```rust
($($arg:tt)*) => {
    $crate::io::_print($crate::format_args_nl!($($arg)*))
};
```

- `$($arg:tt)*`：匹配任意 token 序列，`tt` 是“token tree”，能匹配几乎任何东西。
- `format_args_nl!`：和 `format_args!` 类似，但会在末尾自动加换行。它把参数打包成一个 `Arguments` 结构（惰性求值，不分配堆内存）。
- `_print`：标准库内部的打印函数，把 `Arguments` 写到 stdout 并加锁。

这里用 `format_args_nl!` 而不是 `format_args!`，就是 `println!` 比 `print!` 多一个换行的原因。

---

## 三、整体设计意图

这段定义体现了 Rust 标准库宏的几个惯用手法：

1. `#[macro_export]` + prelude：让 `println!` 全局可用，无需 `use`。
2. `$crate` 路径：保证宏展开后引用的 `print!`、`format_args_nl!`、`_print` 都指向 `std`，不受调用方作用域影响。
3. `allow_internal_unstable`：让稳定宏能安全地调用不稳定内部 API，用户感知不到。
4. `cfg_attr` + `rustc_diagnostic_item`：非测试时给编译器一个“友好名称”，改善报错体验。
5. 两个匹配分支：无参数时走轻量路径，有参数时走格式化路径。

## 四、和你之前问题的联系

你前面在看 `#[derive(Default)]` 的展开结果，那是派生宏；而 `println!` 是声明宏（macro_rules!）。两者都是宏，但机制不同：

| | 声明宏 `macro_rules!` | 派生宏 `#[derive(...)]` |
|---|---|---|
| 定义方式 | 模式匹配 + 替换 | 过程宏，Rust 代码生成 |
| 典型例子 | `println!`、`vec!` | `#[derive(Default)]` |
| 展开查看 | `cargo expand` | `cargo expand` |
| 能否看到源码 | 标准库源码里能直接看 | 看到的是生成结果 |

所以 `cargo expand` 对两者都管用，只是 `println!` 展开后你会看到 `format_args_nl!` 和 `_print` 这些内部调用，而 `#[derive(Default)]` 展开后看到的是 `impl Default` 块。
