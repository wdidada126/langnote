“Write Skew” 被翻译成“写偏斜”，这个“偏斜”并不是指数据被写歪了，而是来自图论 / 并发理论中的一种异常结构。要理解为什么叫“偏斜”，需要从它的原始定义和几何/图论隐喻来看。

## 一、字面来源：skew 的本义

英文 skew 有几个含义：

1. 偏斜、歪斜：比如统计中的“偏态分布”（skewed distribution），指分布不对称、向一边倾斜。
2. 斜的、不对称的：比如斜线、斜角。
3. 歪曲、偏离：偏离正常或预期的方向。

在数据库并发理论中，skew 最早用于描述读写依赖关系形成的“不对称”或“倾斜”结构，而不是简单的“写歪了”。

## 二、从依赖图看：为什么是“偏斜”

在并发控制理论中，事务之间的冲突可以用依赖图（dependency graph / serialization graph） 表示：

- 写-读依赖（wr）：T1 写了 x，T2 读了 x
- 读-写依赖（rw）：T1 读了 x，T2 写了 x（反依赖 anti-dependency）
- 写-写依赖（ww）：T1 写了 x，T2 写了 x

### 1. 丢失更新（Lost Update）的依赖结构

两个事务写同一行，依赖图是：

```
T1 --ww--> T2
```

或者带读写：

```
T1 --rw--> T2 --ww--> T1
```

这是一个对称的、直接冲突的结构。

### 2. Write Skew 的依赖结构

以医生值班为例：

- T1 读 Alice、Bob 的值班状态，写 Alice
- T2 读 Alice、Bob 的值班状态，写 Bob

依赖关系：

```
T1 --rw--> T2   （T1 读了 Bob，T2 写了 Bob）
T2 --rw--> T1   （T2 读了 Alice，T1 写了 Alice）
```

注意：两个都是 rw（反依赖），没有 ww 冲突。

在依赖图中，这形成一个环：

```
T1 --rw--> T2
↑           |
|           |
+----rw----+
```

这个环是由两个反向的读写依赖构成的，而不是由写-写冲突构成的。也就是说，冲突“绕了一圈”，但没有直接写同一行。

## 三、“偏斜”这个译名的由来

中文把 write skew 译为“写偏斜”，主要是为了体现：

1. 不是直接写冲突：两个事务写的是不同的数据项，写操作本身不“撞车”。
2. 约束被“斜着”破坏：每个事务单独看都是合法的，但合在一起就破坏了跨行约束。这种破坏是间接的、斜向的，不是正面对撞。
3. 依赖图不对称：与丢失更新的“正面对称冲突”相比，write skew 的依赖关系是交叉的、倾斜的。

可以这样类比：

- Lost Update：两个人同时改同一份文件，后保存的覆盖先保存的 → 正面对撞。
- Write Skew：两个人各改文件的不同部分，但两人都基于同一份旧副本，结果合并后整体不一致 → 斜向错位。

所以“偏斜”强调的是：冲突不是发生在同一数据项上，而是通过读写依赖“斜着”绕出来的。


## 四、为什么不用“写偏差”或“写倾斜”？

- “写偏差”：容易和“偏差（bias）”混淆，bias 在统计和机器学习中有特定含义。
- “写倾斜”：和“偏斜”意思接近，但“偏斜”在中文数据库文献中更常用，且更贴近 skew 在并发理论中的“非对称依赖环”含义。
- “写偏斜”：既保留了 skew 的“斜”的意象，又避免了与统计偏差混淆。

在中文技术社区，写偏斜 和 写倾斜 都有使用，但 写偏斜 更常见，尤其是在翻译 PostgreSQL、MySQL 文档和并发控制教材时。


## 五、一句话总结

> Write Skew 叫“写偏斜”，是因为两个事务的写操作没有正面对撞（不是写同一行），而是通过交叉的读写依赖“斜着”绕出一个环，最终破坏了跨行约束。这种冲突结构在依赖图上是倾斜的、非对称的，所以叫“偏斜”。

在数据库并发理论中，“写偏斜（Write Skew）”是快照隔离（Snapshot Isolation） 下最典型的可串行化异常。由于它涉及“依赖环”的图论结构，以下几本教材和专著对其有系统性的介绍：

### 核心教材与专著

1. 《数据库系统概念》（Database System Concepts）
这是数据库领域的经典教材。书中将写偏斜描述为“一对事务中的每一个都读取对方写的数据，但是不存在两者同时写的数据”，并指出它不可能出现在串行执行中。该定义直接从读写依赖的角度切入，是理解其图论本质的基础。

2. 《设计数据密集型应用》（Designing Data-Intensive Applications, DDIA）
这本书对写偏斜的讲解非常深入。它将写偏斜定义为：一个事务读取一些数据，根据它看到的值作出决定，并将决定写入数据库，但在写入时，决定的前提不再是真实的。书中明确指出，写偏斜的本质是广义的丢失更新，且只有可串行化隔离才能防止这种异常。

3. 《数据库事务处理的艺术：事务管理与并发控制》
这本中文专著对写偏斜的图论结构有最直接的描述。书中明确指出，写偏斜的异常现象用优先图（依赖图）表示时，可以在参与操作的事务之间画出一个环，存在环说明调度是非可串行化的。这直接点明了“偏斜”在图论上的含义——由交叉的读写依赖构成的环。

4. 《数据库系统内幕》（Database Internals）
这本书在讨论隔离级别时提到了写偏斜，将其归类为一种“写异常”，并指出它与丢失更新、脏写等异常并列，是并发控制中需要处理的问题。

### 补充说明

此外，PostgreSQL 的 SSI（Serializable Snapshot Isolation）相关论文（如 Ports & Grittner 的论文）也是理解写偏斜的必读材料。《数据库事务处理的艺术》中专门引用了该论文的示例，并展示了简单写偏斜（两个事务）和批处理写偏斜（涉及只读事务的复杂情况）两种场景下的优先图结构。

如果你需要深入了解其图论结构，可以重点阅读《数据库事务处理的艺术》中关于“优先图”与“写偏序”的章节，以及《数据库系统概念》中关于“快照隔离”的讨论。
