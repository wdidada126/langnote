`global.json` 是 .NET SDK 的版本锁定文件，用来控制某个目录及其子目录下执行 `dotnet` 命令时，具体使用哪个版本的 .NET SDK。

### 核心作用

当你在一个目录下运行 `dotnet build`、`dotnet test` 等命令时，SDK 会从当前目录向上逐级查找 `global.json`。找到后，就按里面指定的规则选择 SDK 版本；找不到就用系统默认的最新 SDK。

一个典型的 `global.json`：

```json
{
  "sdk": {
    "version": "8.0.300",
    "rollForward": "latestFeature"
  }
}
```

### 关键字段

`sdk.version`：指定 SDK 版本。它不一定要求系统精确安装这个版本，具体行为由 `rollForward` 决定。

`sdk.rollForward`：版本不匹配时的回退策略，常见值：

- `latestPatch`：只用指定版本的最新补丁（如指定 `8.0.300`，可用 `8.0.301`，但不升到 `8.0.400`）
- `latestFeature`：允许升到同一主次版本下的最新功能带（默认值，如 `8.0.300` 可升到 `8.0.4xx`）
- `latestMinor`：允许升到同一主版本下的最新次版本
- `latestMajor`：允许升到最新主版本
- `disable`：必须精确匹配指定版本，否则报错

`msbuild-sdks`：用来锁定 MSBuild 项目 SDK（如 `Microsoft.Build.NoTargets`）的版本，常和 `sdk` 一起出现。

### 为什么需要它

团队一致性：多人协作时，避免有人用 SDK 8 有人用 SDK 9，导致构建结果或行为不一致。

CI 稳定性：CI 环境里系统可能装了多个 SDK，`global.json` 确保每次构建都用预期版本，不会因为 runner 镜像更新而漂移。

精确复现：当项目依赖某个 SDK 特性的具体行为时，锁定版本能避免升级带来的意外。

### 在 C# 项目里通常放哪

放在解决方案根目录（`.sln` 同级），这样整个解决方案下的所有项目都受它约束。也可以放在子目录，只影响该子树。

### 没有它会怎样

没有 `global.json` 时，`dotnet` 命令使用系统上安装的最新 SDK。这通常没问题，但如果新 SDK 引入了破坏性变更，或者项目需要旧 SDK 的特定行为，就可能出问题。

### 一个容易混淆的点

`global.json` 管的是 SDK 版本，不是目标框架。目标框架（`net8.0`、`net9.0`）写在 `.csproj` 的 `<TargetFramework>` 里，由 SDK 来支持。两者是不同层面的东西。

如果你想为项目固定 SDK 版本，可以用 `dotnet new globaljson --sdk-version 8.0.300` 生成初始文件，再按需调整。
