# PAX（Partition Attributes Across）页格式
PAX 2001年CMU提出，**页内垂直分区的混合存储布局**，核心思想：**跨页行导向，页内列导向**，在同一个数据页内部把各个属性拆分为独立的 mini‑page（子页），兼顾行存储NSM、列存储DSM两者优势，重点优化CPU缓存命中率，减少cache miss。

## 1、三大存储模型对比
|模型|全称|存储布局|典型场景|
|---|---|---|---|
|NSM|N‑ary Storage Model 行存储|一页内：元组完整连续存放，一行所有字段挨在一起|OLTP，单行增删改查|
|DSM|Decomposition Storage Model 列存储|每一列单独文件/块，所有行同一属性连续；同一个元组分散在多个块|OLAP，大量扫描少数列|
|PAX|Partition Attributes Across|**同一个page内，拆多个mini‑page；每个mini‑page存放本页全部行的某一列；元组全部字段仍驻留在同一个物理页**|混合负载；页内享受列存局部性，不需要跨块拼接元组|

> 关键区别：
> DSM：**跨页跨块做垂直拆分**；
> PAX：**只在单个page内部垂直拆分，行不会被拆分到不同磁盘块**。

## 2、PAX页面物理结构
```
┌───────────────────────────────┐
│ Page Header 页头              │ 元数据：mini‑page偏移、行数、页校验等
├───────────────────────────────┤
│ Mini‑Page‑A（属性A所有值）     │ A₀ A₁ A₂ A₃ …（本页全部行的A字段）
├───────────────────────────────┤
│ Mini‑Page‑B（属性B所有值）     │ B₀ B₁ B₂ B₃ …
├───────────────────────────────┤
│ Mini‑Page‑C（属性C所有值）     │ C₀ C₁ C₂ C₃ …
├───────────────────────────────┤
│ 变长数据区（VARCHAR/TEXT）     │ mini‑page存偏移指针，真实字符串放尾部
└───────────────────────────────┘
```
- 一个页容纳N条元组；页内每个属性对应一块连续区域 mini‑page；
- 取第i条元组：从每个mini‑page取第i个元素，拼接得到完整tuple；**所有字段都来自同一个page，不需要读多个磁盘块**。
- 变长字段：mini‑page存偏移指针，实际变长内容放在页面尾部，和NSM处理方式一致。

## 3、读写行为
### 3.1 只查询部分列（OLAP扫描）
只加载需要的若干 mini‑page，跳过不需要的列，数据连续，CPU缓存友好，支持SIMD向量化计算，接近DSM的效率。

### 3.2 查询完整元组（OLTP）
所有属性都在同一个物理页，磁盘I/O只需要读取这一页；不像DSM，读取一条元组需要访问多个不同列块，产生大量I/O。

### 3.3 更新
- 更新单条记录：修改本页各个mini‑page对应位置的值；定长字段效率高；变长字段会产生页内碎片。
- PAX不跨页拆分元组，插入更新仍然以page为单位。

## 4、优点
1. **缓存友好**：页内同属性连续，大幅降低cache miss，论文实测缓存停顿时间减少75%。
2. **混合负载友好**：既适合扫描少数列的分析查询，也适合读取完整元组事务场景。
3. **改造代价低**：基于原有NSM存储引擎，**只修改页内部逻辑，上层存储管理器几乎不用改动**，不需要改变磁盘块分配逻辑。
4. I/O开销和NSM完全一致：一页存放的元组数量与NSM相同，没有额外I/O放大。

## 5、缺点
1. **压缩弱于纯DSM**：压缩范围仅限于本page内的数据；DSM是百万行级别连续同类型数据，压缩率更高。
2. **变长字段处理麻烦**：VARCHAR等会造成mini‑page内部碎片。
3. 不适合超大表深度OLAP：工业界Parquet/ORC是PAX思想的扩展（RowGroup），但不是原始PAX页格式；原始PAX粒度是4K数据页，Parquet RowGroup一般几十MB。

> 区分：Parquet/ORC是**文件级PAX思想**：文件切RowGroup（行组），RowGroup内部按列分column chunk；原始PAX粒度是数据库page（4KB/8KB），是内存‑磁盘页层面布局，不是文件格式。

## 6、PAX vs DSM核心易错点
1. DSM：元组的各个属性分散存储在不同磁盘块；读取一条元组需要读多个块。
2. PAX：**一个元组所有属性永远保存在同一个磁盘page，仅在page内部切分mini‑page**；读取元组只需要一次I/O。

## 7、典型考题总结（CMU15445）
1. PAX全称：Partition Attributes Across。
2. PAX在哪一层做垂直划分：**单个数据page内部**，不是跨page。
3. PAX目标：优化CPU缓存命中率，折中NSM与DSM。
4. PAX读取完整tuple：所有字段在同一个页，不需要多块I/O。
5. PAX与NSM磁盘I/O数量相同，性能收益来自CPU缓存，不是减少磁盘IO。

# N‑ary Storage Model 为什么不是 Row‑Storage Model
> N‑ary：**n元**，不是 n‑row；**NSM是学术正式名称，Row‑store是通俗叫法**。

## 1、单词 arity /ˈærəti/ 元数（数理逻辑/关系代数）
- **arity**：元数，指一个元组(tuple)有多少个属性（字段）
  - unary 一元（1个参数）
  - binary 二元（2个参数）
  - ternary 三元（3个参数）
  - **n‑ary n元：泛指任意n个属性的元组**，n可以是任意数字，一张表可以有3、5、100个字段。

> 关系数据库里：**n‑ary tuple = n‑ary relation = n元关系**，代表一条拥有n个属性的记录。
> N‑ary Storage Model：**n元元组存储模型**。含义：**把完整的n‑ary元组（整条记录）连续存放在一起**。

## 2、名字来源拆解
**N‑ary Storage Model (NSM)**
- N‑ary：n元，强调**元组本身有n个属性**；
- Storage Model：存储模型。

字面翻译：**n元元组存储模型**。
通俗叫法：**row‑store 行存储**。

### 关键区分
1. `row` 描述**物理排布形态**：一行挨着一行放；这是现象。
2. `n‑ary` 描述**关系代数概念**：存储的对象是 n‑ary tuple（n元元组）；这是学术命名的本源。

> 论文（PAX原始论文、DSM原始论文）里用NSM/DSM是70‑80年代数据库学术命名体系，那套术语基于关系代数，不是基于“行row/列column”这种物理描述词。

## 3、对比 DSM，方便记忆
- **NSM N‑ary Storage Model**：存储单元 = **完整n元元组（tuple/row）**。把一整个n属性元组连续存放。
- **DSM Decomposition Storage Model**：分解存储模型。把n元元组拆开，**按单个属性存储**（列存）。

> 命名对仗：
> NSM：不拆分，存完整 n‑ary tuple；
> DSM：Decompose（分解）这个n‑ary tuple，拆成一个个属性。

## 4、考试易错坑
1. ❌ N‑ary 的n不是行数，不是number‑of‑rows；
2. ✅ N‑ary 的n = **元组的属性数量（字段数）**；一张表可以任意多列，所以叫n‑ary；
3. NSM ≠ Row Storage Model；**NSM是正式学名，Row‑store只是别名**；考卷写全称必须写 N‑ary Storage Model，不能写成 Row Storage Model。

### 一句话速记
> N‑ary来自关系代数“n元元组”，强调存储对象是完整多属性元组；row只是看到的物理排布，是俗称，不是原始学术命名。

## 小例子
表有4个字段 `id,name,age,email`，每一条记录是**4‑ary tuple（4元元组）**。
NSM就是把这4个属性打包连续存放。当表字段改成10个，就变成10‑ary tuple；所以用泛指的 **n‑ary**。

# decomposition
英 /ˌdiːˌkɒmpəˈzɪʃn/
**名词：分解、拆分、拆解**

动词原形：**decompose** /ˌdiːkəmˈpəʊz/
> de‑ 前缀：分开、去掉；compose：组合、构成
> compose = 组合到一起
> decompose = 把组合好的东西拆开

---
## Decomposition Storage Model (DSM) 分解存储模型
关系代数视角：
原本一条记录是一个 **n‑ary tuple（n元元组）**，由多个属性拼在一起构成。
**Decomposition = 把这个完整元组拆解打散**，每个属性单独存放。

- NSM：保存完整、没有拆开的 n‑ary 元组
- DSM：**decompose（分解）元组**，每个属性单独成一列存储

### 直白理解
元组：`(id,name,age)`
- NSM：`id name age` 放一起（不拆）
- DSM：把元组**decomposition 分解**
  - id：1,2,3…
  - name：a,b,c…
  - age：20,21,22…

### 一词多义
1. 计算机：**分解**（DSM这里含义）
2. 化学：分解、腐烂（有机物decompose腐烂）

### 词根记忆
compose 组合 → decompose 拆开 → decomposition(n.)分解

### 考试记忆
DSM = **Decomposition 分解**，把元组拆开按列存；
NSM 不分解，存完整n‑ary元组；
PAX：page内部局部分解。

> 论文命名对仗：
> N‑ary Storage Model（存完整n元元组）
> **Decomposition** Storage Model（把元组做分解）。
