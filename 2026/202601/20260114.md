我来详细讲解 MVCC可见性判断 的核心逻辑，这是数据库实现隔离级别的关键机制。

一、MVCC可见性基本模型

1. 版本数据结构回顾


版本 Entry:
+-------+-------+-------+
| XMIN  | XMAX  | DATA  |
+-------+-------+-------+
创建者  删除者   实际数据


• XMIN：创建此版本的事务ID

• XMAX：删除/更新此版本的事务ID（0表示未删除）

• DATA：实际数据内容

2. 版本链示例


时间线: T1(100) → T2(200) → T3(300) → 当前事务T4(400)

数据版本链:
v1: [XMIN=100, XMAX=200, DATA="v1"]  ← T1创建，T2删除
v2: [XMIN=200, XMAX=300, DATA="v2"]  ← T2创建，T3删除  
v3: [XMIN=300, XMAX=0,   DATA="v3"]  ← T3创建，未删除


二、可见性判断算法详解

核心算法伪代码

public static boolean isVisible(TransactionManager tm, 
                                Transaction t, 
                                Entry entry) {
    long xmin = entry.getXmin();
    long xmax = entry.getXmax();
    
    // 情况1：版本由本事务创建
    if (xmin == t.xid) {
        return xmax == 0 || xmax != t.xid;  // 自己创建且未删除
    }
    
    // 情况2：版本由未提交事务创建 → 不可见
    if (!tm.isCommitted(xmin)) {
        return false;
    }
    
    // 情况3：版本创建事务在本事务开始后提交 → 不可见
    if (xmin > t.xid) {
        return false;
    }
    
    // 情况4：版本已被删除
    if (xmax != 0) {
        // 删除事务未提交 → 版本仍可见
        if (!tm.isCommitted(xmax)) {
            return true;
        }
        // 删除事务在本事务开始前提交 → 不可见
        if (xmax < t.xid) {
            return false;
        }
        // 删除事务在本事务开始后提交 → 版本可见
        return true;
    }
    
    // 情况5：版本未删除，创建事务已提交且在本事务开始前提交 → 可见
    return true;
}


三、各种场景分析

场景1：读已提交（Read Committed）

事务时间线：

T1(100): 开始 → 创建版本v1 → 提交
T2(200): 开始 → 读取数据


判断过程：
// T2(200) 查询 v1[XMIN=100, XMAX=0]
1. xmin=100 != 200
2. tm.isCommitted(100) = true
3. xmin(100) < t.xid(200) ✓
4. xmax=0 → 可见 ✅
// 结果：T2能看到T1已提交的数据


场景2：不可重复读（Read Committed问题）

// 时间点1：T2(200) 第一次查询
// v1[XMIN=100, XMAX=0] → 可见

// 时间点2：T3(300) 更新数据
// v1.setXmax(300) → v1[XMIN=100, XMAX=300]
// 创建 v2[XMIN=300, XMAX=0]
// T3提交

// 时间点3：T2(200) 第二次查询
// 检查v1: xmax=300, tm.isCommitted(300)=true, xmax(300) > t.xid(200) → 可见 ✗
// 检查v2: xmin=300, tm.isCommitted(300)=true, xmin(300) > t.xid(200) → 不可见 ✓
// 结果：T2看到v1被删除，但看不到v2 → 返回null
// 这就是"不可重复读"：同事务内两次查询结果不一致


场景3：可重复读（Repeatable Read）

实现关键：记录ReadView（事务快照）
class Transaction {
    long xid;                    // 事务ID
    long startTs;                // 事务开始时间戳
    Set<Long> activeTransactions; // 活动事务列表（快照）
}

// 可重复读的可见性判断
public static boolean isVisibleRR(Transaction t, Entry entry) {
    long xmin = entry.getXmin();
    long xmax = entry.getXmax();
    
    // 版本由本事务创建
    if (xmin == t.xid) {
        return xmax == 0 || xmax != t.xid;
    }
    
    // 版本创建时，创建事务已提交且在快照中不可见
    if (t.activeTransactions.contains(xmin) || 
        (!tm.isCommitted(xmin) && xmin != t.xid)) {
        return false;
    }
    
    // 版本删除时，删除事务在快照中或未提交
    if (xmax != 0) {
        if (xmax == t.xid) return false;
        if (!tm.isCommitted(xmax) || 
            t.activeTransactions.contains(xmax)) {
            return true;  // 删除未生效，版本仍可见
        }
        return false;  // 已删除
    }
    
    return true;
}

// InnoDB的read_view_sees_trx_id函数
bool read_view_sees_trx_id(const read_view_t* view, 
                          trx_id_t trx_id) {
    // 1. 事务ID小于视图最小ID → 已提交且可见
    if (trx_id < view->up_limit_id) {
        return(true);
    }
    
    // 2. 检查是否在活动事务列表中
    const trx_id_t* ids = view->descriptors;
    for (size_t i = 0; i < view->n_descriptors; i++) {
        trx_id_t id = ids[i];
        if (id == trx_id) {
            return(false);  // 在活动事务中，不可见
        }
        if (id > trx_id) {
            break;  // 列表有序，提前结束
        }
    }
    
    // 3. 事务ID大于等于视图最大ID → 在视图后开始，不可见
    if (trx_id >= view->low_limit_id) {
        return(false);
    }
    
    return(true);  // 在间隙中，可见
}

public static boolean isVersionSkip(TransactionManager tm, 
                                   Transaction t, 
                                   Entry entry) {
    long xmax = entry.getXmax();
    if (xmax == 0) return false;  // 未删除
    
    // 检查是否有其他事务在本事务执行期间修改了数据
    if (tm.isCommitted(xmax) && xmax > t.xid) {
        // 有其他事务在本事务开始后提交了删除/更新
        return true;
    }
    
    // 检查是否有未提交事务正在修改
    if (!tm.isCommitted(xmax) && xmax != t.xid) {
        return true;
    }
    
    return false;
}

九、总结

MVCC可见性判断的核心原则：

1. 创建时间规则：
   • 版本由已提交事务创建

   • 在当前事务开始前提交

   • → 可能可见

2. 删除时间规则：
   • 版本未被删除（XMAX=0）

   • 或删除事务未提交

   • 或删除在当前事务开始后提交

   • → 仍然可见

3. 隔离级别影响：
   • RC：每次查询新快照

   • RR：事务级快照

   • 通过控制ReadView的获取时机实现

4. 性能关键：
   • 快速判断事务状态

   • 减少版本遍历

   • 缓存优化

本质：MVCC通过多版本+时间戳实现了无锁读取和快照隔离，是现代数据库高并发的基石。

ReadView（读视图） 是MVCC实现隔离级别的核心数据结构，它记录了事务开始时数据库的快照状态，用于判断数据版本对当前事务是否可见。

三、ReadView在可见性判断中的应用

1. 可见性判断算法（基于ReadView）

class Visibility {
    /**
     * 判断版本对事务是否可见
     * @param tm 事务管理器
     * @param t 当前事务
     * @param entry 数据版本
     * @param view 读视图
     */
    public static boolean isVisible(TransactionManager tm, 
                                   Transaction t, 
                                   Entry entry,
                                   ReadView view) {
        long xmin = entry.getXmin();
        long xmax = entry.getXmax();
        
        // 情况1：版本由本事务创建
        if (xmin == t.xid) {
            // 自己创建的版本，除非自己删除，否则可见
            return xmax == 0 || xmax != t.xid;
        }
        
        // 情况2：检查版本创建事务状态
        TrxStatus xminStatus = getTrxStatus(tm, xmin, view);
        
        // 情况3：版本创建事务在当前视图中不可见
        if (!isTrxVisible(xmin, xminStatus, view)) {
            return false;
        }
        
        // 情况4：检查版本删除事务状态
        if (xmax != 0) {
            TrxStatus xmaxStatus = getTrxStatus(tm, xmax, view);
            // 版本已被删除，且删除事务可见
            if (isTrxVisible(xmax, xmaxStatus, view)) {
                return false;  // 已删除，不可见
            }
        }
        
        return true;  // 版本可见
    }
    
    // 判断事务在ReadView中是否可见
    private static boolean isTrxVisible(long trxId, 
                                       TrxStatus status, 
                                       ReadView view) {
        // 规则1：事务ID < 最小活跃事务ID → 已提交且可见
        if (trxId < view.minTrxId) {
            return true;
        }
        
        // 规则2：事务ID == 创建者事务ID → 本事务创建
        if (trxId == view.creatorXid) {
            return true;
        }
        
        // 规则3：事务在活跃事务列表中 → 未提交，不可见
        if (view.activeTransactions.contains(trxId)) {
            return false;
        }
        
        // 规则4：事务ID ≥ 最大事务ID → 在快照后开始，不可见
        if (trxId >= view.maxTrxId) {
            return false;
        }
        
        // 规则5：事务已提交且在快照前提交 → 可见
        return status == COMMITTED;
    }
}

五、ReadView的生命周期管理

1. 创建和缓存

class ReadViewManager {
    private Map<Long, ReadView> viewCache;  // 事务ID -> ReadView
    private Map<Long, Long> trxToView;      // 事务ID -> 视图ID
    
    // 为事务获取ReadView
    public ReadView getReadView(long xid, IsolationLevel level) {
        // 可重复读：缓存视图
        if (level == REPEATABLE_READ) {
            ReadView view = viewCache.get(xid);
            if (view == null) {
                view = createReadView(xid, level);
                viewCache.put(xid, view);
                trxToView.put(xid, xid);
            }
            return view;
        }
        
        // 读已提交：每次创建新视图
        if (level == READ_COMMITTED) {
            return createReadView(xid, level);
        }
        
        return null;  // 其他级别
    }
}


2. 清理过期ReadView

// 清理不再需要的ReadView
public void cleanupOldViews() {
    long now = System.currentTimeMillis();
    Iterator<Map.Entry<Long, ReadView>> it = viewCache.entrySet().iterator();
    
    while (it.hasNext()) {
        Map.Entry<Long, ReadView> entry = it.next();
        ReadView view = entry.getValue();
        
        // 清理条件：视图过期或事务已结束
        if (now - view.createTimestamp > VIEW_TTL || 
            !tm.isActive(view.creatorXid)) {
            it.remove();
            trxToView.remove(view.creatorXid);
        }
    }
}


六、性能优化策略

1. 活跃事务位图优化

class OptimizedReadView {
    // 使用位图替代HashSet，减少内存占用
    private BitSet activeTrxBits;
    private long minTrxId;
    private long maxTrxId;
    
    // 快速判断事务是否活跃
    public boolean isTrxActive(long trxId) {
        if (trxId < minTrxId || trxId > maxTrxId) {
            return false;
        }
        int index = (int)(trxId - minTrxId);
        return activeTrxBits.get(index);
    }
    
    // 批量判断
    public boolean[] batchIsTrxActive(long[] trxIds) {
        boolean[] results = new boolean[trxIds.length];
        for (int i = 0; i < trxIds.length; i++) {
            results[i] = isTrxActive(trxIds[i]);
        }
        return results;
    }
}

    private ConcurrentSkipListMap<Long, ReadView> viewByTime;
    
    public ReadView getSimilarView(long timestamp, long tolerance) {
        // 查找时间相近的现有ReadView
        Entry<Long, ReadView> entry = viewByTime.floorEntry(timestamp + tolerance);
        if (entry != null && Math.abs(entry.getKey() - timestamp) <= tolerance) {
            return entry.getValue();
        }
        return null;
    }
}

九、总结
ReadView是MVCC实现隔离级别的关键：

1. 快照记录：记录事务开始时的数据库状态
2. 可见性判断：基于快照判断数据版本是否可见
3. 隔离控制：通过不同的创建策略实现不同隔离级别
4. 性能优化：缓存、压缩、复用等策略提升效率

核心价值：
• ✅ 读已提交：避免脏读
• ✅ 可重复读：避免不可重复读
• ✅ 无锁读取：提高并发性能
• ✅ 快照隔离：提供一致的数据视图

理解ReadView的工作原理是掌握MVCC和数据库隔离级别的关键。
