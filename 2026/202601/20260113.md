.bt 和 .bt_tmp 是数据库引导文件（Booter Files），是数据库系统用于存储和管理关键元数据信息的特殊文件。

一、文件作用
.bt 文件（Booter File）
• 主引导文件：数据库启动时的核心配置文件
• 存储内容：
  • 数据库版本信息
  • 表结构元数据（Table Metadata）
  • 索引信息
  • 页大小配置
  • 检查点（Checkpoint）位置
  • 事务日志位置

• 特点：二进制格式，直接读写效率高
.bt_tmp 文件（Temporary Booter File）
• 临时引导文件：.bt 文件的临时副本
• 使用场景：
  • 元数据更新时的原子性操作
  • 防止写过程中系统崩溃导致主文件损坏
  • 实现写时复制（Copy-on-Write） 模式
• 特点：操作完成后会重命名为 .bt 文件

二、工作原理
原子更新流程
// 更新元数据的典型流程
public void updateMetadata() {
    // 1. 创建临时文件
    File tmpFile = new File("database.bt_tmp");
    
    // 2. 写入新元数据到临时文件
    writeMetadataToFile(tmpFile);
    tmpFile.getFD().sync();  // 强制刷盘
    
    // 3. 原子重命名（系统调用保证原子性）
    File mainFile = new File("database.bt");
    Files.move(tmpFile.toPath(), mainFile.toPath(), 
              StandardCopyOption.ATOMIC_MOVE);
}


崩溃恢复
启动时检查：
1. 如果只有 .bt 文件 → 正常启动
2. 如果只有 .bt_tmp 文件 → 说明上次更新未完成，回滚
3. 如果两个文件都存在 → 说明上次更新已完成，删除 .bt_tmp

四、与其他数据库对比

数据库 类似文件 作用
SQLite -journal 文件 事务日志，类似临时文件
MySQL ibdata1 中的元数据页 系统表空间存储元数据
PostgreSQL pg_control 文件 控制文件，存储关键配置
LevelDB MANIFEST 文件 清单文件，存储版本信息

五、设计优势
1. 原子性保证：通过临时文件+原子重命名，确保元数据更新原子性
2. 崩溃安全：系统崩溃时不会损坏主元数据文件
3. 简单可靠：避免复杂的日志回滚机制
4. 快速恢复：只需检查两个文件状态即可决定恢复策略

七、注意事项
1. 文件权限：需要确保有读写权限
2. 并发访问：需要加锁防止多个进程同时修改
3. 备份策略：定期备份引导文件
4. 大小限制：元数据量不能超过文件系统限制

.bt 和 .bt_tmp 文件是数据库系统的"大脑"，存储了数据库如何组织数据的关键信息，它们的稳定性和一致性对整个数据库的可靠性至关重要。
