MVCC详解：版本号维护、隔离级别与数据可见性

一、MVCC核心概念
MVCC（Multi-Version Concurrency Control，多版本并发控制）是现代数据库实现高并发的重要技术。核心思想：每个数据项维护多个版本，读操作读取快照，写操作创建新版本。

二、MVCC版本号维护机制

-- 典型的MVCC行记录结构
每条记录包含：

+----------------+----------------+----------------+----------------+
| trx_id         | roll_pointer   | version        | col1, col2...  |

3. 版本链维护

-- 示例：数据行版本链
版本链：V4 ← V3 ← V2 ← V1 (最新←最旧)
        ↓     ↓     ↓     ↓
        T4    T3    T2    T1  (事务ID)
        
-- 每个版本包含：
-- 1. 创建该版本的事务ID
-- 2. 删除/更新该版本的事务ID（或时间戳）
-- 3. 指向前一个版本的指针
-- 4. 该版本的数据值


代码实现：
// Java伪代码：版本链管理
class MVCCRow {
    private VersionChain versions;
    
    class Version {
        long createTrxId;      // 创建版本的事务ID
        long deleteTrxId;      // 删除版本的事务ID（0表示未删除）
        Version previous;      // 前一个版本
        Object[] data;         // 该版本的数据
        long createTimestamp;  // 创建时间戳
    }
    
    // 读取特定版本
    Version getVisibleVersion(Transaction tx) {
        Version current = versions.head;
        while (current != null) {
            if (isVisible(tx, current)) {
                return current;
            }
            current = current.previous;
        }
        return null;  // 对当前事务不可见
    }
}

三、MVCC与隔离级别的关系

是的，MVCC与隔离级别密切相关。不同隔离级别通过控制版本可见性来实现。

隔离级别在MVCC中的实现差异

隔离级别 MVCC实现策略 读行为 写行为

READ UNCOMMITTED 通常不使用MVCC，直接读最新数据 可能读到未提交数据 正常写

READ COMMITTED 语句级快照 每个语句看到已提交的数据 写操作可能阻塞

REPEATABLE READ 事务级快照 整个事务看到一致性快照 写操作可能阻塞

SERIALIZABLE 严格的版本控制+锁 类似REPEATABLE READ 冲突检测/锁升级

四、不同隔离级别的数据可见性规则

可见性判断核心逻辑

-- 判断版本对事务Tx是否可见的通用规则
可见性条件 = 
    (版本创建事务已提交 AND 创建时间 <= Tx开始时间)
    AND 
    (版本未删除 OR 删除事务未提交 OR 删除时间 > Tx开始时间)


1. READ COMMITTED（读已提交）

可见性规则：每个SQL语句开始时创建新快照
// 伪代码实现
class ReadCommittedIsolation {
    // 每个语句开始时获取新快照
    Snapshot takeSnapshot() {
        return new Snapshot(
            getMinActiveTrxId(),  // 所有活跃事务最小ID
            getNextTrxId()        // 下一个事务ID
        );
    }
    
    boolean isVisible(Version version, Transaction tx, Snapshot snapshot) {
        // 规则1：版本创建事务必须在当前语句开始前已提交
        if (version.createdBy == tx.trxId) {
            return true;  // 自己创建的可见
        }
        
        // 规则2：版本创建事务不在活跃事务列表中
        // 规则3：创建事务ID < 当前快照的上限
        boolean createdBefore = 
            version.createTrxId < snapshot.maxTrxId &&
            !snapshot.activeTrxIds.contains(version.createTrxId);
        
        // 规则4：如果版本被删除，删除事务必须未提交或删除在语句开始后
        boolean notDeleted = 
            version.deleteTrxId == 0 ||
            version.deleteTrxId > snapshot.maxTrxId ||
            snapshot.activeTrxIds.contains(version.deleteTrxId);
        
        return createdBefore && notDeleted;
    }
}


示例：
-- 时间线：
-- T1: BEGIN; UPDATE t SET val=100 WHERE id=1;  -- 未提交
-- T2: BEGIN; SELECT * FROM t WHERE id=1;       -- 看到val=1（旧值）
-- T1: COMMIT;
-- T2: SELECT * FROM t WHERE id=1;               -- 看到val=100（新值）
-- 同一个事务内，两次查询看到不同结果


2. REPEATABLE READ（可重复读）

可见性规则：事务开始时创建快照，整个事务使用同一快照
class RepeatableReadIsolation {
    // 事务开始时获取快照
    void startTransaction(Transaction tx) {
        tx.snapshot = new Snapshot(
            getMinActiveTrxId(),  // 所有活跃事务最小ID
            getNextTrxId()        // 下一个事务ID
        );
    }
    
    boolean isVisible(Version version, Transaction tx) {
        // 使用事务开始时获取的快照
        Snapshot snapshot = tx.snapshot;
        
        // 规则1：自己创建或修改的版本总是可见
        if (version.createTrxId == tx.trxId) {
            return true;
        }
        
        // 规则2：版本必须在事务开始前已提交
        boolean createdBeforeTxStart = 
            version.createTrxId < snapshot.maxTrxId &&
            !snapshot.activeTrxIds.contains(version.createTrxId);
        
        if (!createdBeforeTxStart) {
            return false;
        }
        
        // 规则3：版本未被删除，或删除在事务开始后
        if (version.deleteTrxId == 0) {
            return true;  // 未删除
        }
        
        // 删除事务的判断
        if (version.deleteTrxId == tx.trxId) {
            return false;  // 本事务删除的不可见
        }
        
        // 删除事务是否在快照中？
        boolean deletedAfterTxStart = 
            version.deleteTrxId >= snapshot.maxTrxId ||
            snapshot.activeTrxIds.contains(version.deleteTrxId);
        
        return deletedAfterTxStart;
    }
}


示例：
-- 时间线：
-- T1: BEGIN;                            -- 创建快照
-- T2: UPDATE t SET val=100 WHERE id=1; COMMIT;
-- T1: SELECT * FROM t WHERE id=1;        -- 看到旧值（可重复读）
-- T1: UPDATE t SET val=200 WHERE id=1;  -- 可以更新
-- T1: SELECT * FROM t WHERE id=1;        -- 看到200（自己的修改）


3. SERIALIZABLE（可串行化）

实现方式1：严格2PL + MVCC（如Oracle）
-- 实际是REPEATABLE READ + 冲突检测
BEGIN TRANSACTION ISOLATION LEVEL SERIALIZABLE;
-- 如果检测到可能的串行化异常，会回滚事务


实现方式2：谓词锁（如MySQL在某些情况下）
-- 防止幻读的关键
SELECT * FROM t WHERE age > 30 FOR UPDATE;
-- 不仅锁住现有行，还锁住未来可能插入的行（间隙锁）


PostgreSQL的可串行化实现：
// PostgreSQL使用SSI（可串行化快照隔离）

    if (hasDependencyCycle()) {

        AbortCurrentTransaction();

    }
    return false;
}

六、代码示例：完整的MVCC可见性判断

class MVCCEngine:
    def __init__(self):
        self.active_transactions = set()
        self.next_trx_id = 1
        self.rows = {}  # 数据行
        
    class Version:
        def __init__(self, data, create_trx_id, delete_trx_id=0, prev=None):
            self.data = data
            self.create_trx_id = create_trx_id
            self.delete_trx_id = delete_trx_id
            self.prev = prev
            self.create_timestamp = time.time()
    
    class Transaction:
        def __init__(self, trx_id, isolation_level="REPEATABLE_READ"):
            self.trx_id = trx_id
            self.isolation_level = isolation_level
            self.snapshot = None
            self.start_time = time.time()
            
    def begin_transaction(self, isolation_level="REPEATABLE_READ"):
        trx_id = self.next_trx_id
        self.next_trx_id += 1
        trx = self.Transaction(trx_id, isolation_level)
        self.active_transactions.add(trx_id)
        
        # 根据隔离级别创建快照
        if isolation_level in ["REPEATABLE_READ", "SERIALIZABLE"]:
            trx.snapshot = self.create_snapshot()
        return trx
    
    def create_snapshot(self):
        """创建事务快照"""
        return {
            'min_active_trx': min(self.active_transactions) if self.active_transactions else 0,
            'max_trx_id': self.next_trx_id,
            'active_trx_ids': set(self.active_transactions)  # 复制一份
        }
    
    def is_visible(self, version, trx):
        """判断版本对事务是否可见"""
        if not version:
            return False
        
        # 自己创建的版本总是可见
        if version.create_trx_id == trx.trx_id:
            return True
        
        # 根据隔离级别使用不同的可见性规则
        if trx.isolation_level == "READ_UNCOMMITTED":
            return True  # 总是看到最新版本，即使未提交
            
        elif trx.isolation_level == "READ_COMMITTED":
            # 读已提交：每个语句重新判断
            snapshot = self.create_snapshot()  # 新快照
            return self._check_visibility(version, trx.trx_id, snapshot)
            
        elif trx.isolation_level in ["REPEATABLE_READ", "SERIALIZABLE"]:
            # 可重复读：使用事务开始时的快照
            return self._check_visibility(version, trx.trx_id, trx.snapshot)
            
        return False
    
    def _check_visibility(self, version, trx_id, snapshot):
        """通用的可见性检查逻辑"""
        # 规则1：创建事务是否在活跃事务列表中？
        if version.create_trx_id in snapshot['active_trx_ids']:
            # 创建事务仍活跃，且不是自己
            if version.create_trx_id != trx_id:
                return False
                
        # 规则2：创建事务ID是否小于快照上限？
        if version.create_trx_id >= snapshot['max_trx_id']:
            return False  # 创建事务在快照之后开始
            
        # 规则3：版本是否被删除？
        if version.delete_trx_id != 0:
            # 被本事务删除
            if version.delete_trx_id == trx_id:
                return False
                
            # 删除事务是否已提交？
            if (version.delete_trx_id not in snapshot['active_trx_ids'] and
                version.delete_trx_id < snapshot['max_trx_id']):
                return False  # 已被其他事务删除
                
        return True
    
    def read(self, key, trx):
        """读取数据（MVCC版本）"""
        if key not in self.rows:
            return None
            
        # 遍历版本链，找到对当前事务可见的最新版本
        version = self.rows[key]
        while version:
            if self.is_visible(version, trx):
                return version.data
            version = version.prev
            
        return None  # 没有可见版本
    
    def write(self, key, data, trx):
        """写入数据（创建新版本）"""
        prev_version = self.rows.get(key)
        new_version = self.Version(
            data=data,
            create_trx_id=trx.trx_id,
            prev=prev_version
        )
        self.rows[key] = new_version
        
    def delete(self, key, trx):
        """删除数据（标记删除）"""
        if key in self.rows:
            current = self.rows[key]
            # 标记删除
            current.delete_trx_id = trx.trx_id

3. 可见性判断加速

// 使用位图加速活跃事务判断
// 假设事务ID从0开始递增
#define BITMAP_SIZE 65536
uint64_t active_trx_bitmap[BITMAP_SIZE / 64];

// 设置事务为活跃
void set_trx_active(long trx_id) {
    int index = trx_id / 64;
    int bit = trx_id % 64;
    active_trx_bitmap[index] |= (1ULL << bit);
}

// 检查是否活跃（O(1)时间复杂度）
bool is_trx_active(long trx_id) {
    int index = trx_id / 64;
    int bit = trx_id % 64;
    return (active_trx_bitmap[index] >> bit) & 1;
}


八、总结
关键点总结
1. MVCC版本号维护：
   • 通过事务ID或时间戳标记版本
   • 版本链按时间逆序组织
   • 定期清理过期版本

2. MVCC与隔离级别的关系：
   • 不同隔离级别=不同的可见性规则
   • 通过控制快照创建时机和可见性判断实现隔离

3. 数据可见性规则：
   • READ COMMITTED：语句开始时创建快照
   • REPEATABLE READ：事务开始时创建快照
   • SERIALIZABLE：严格版本控制+冲突检测

4. 数据库实现差异：
   • MySQL：ReadView + Undo Log
   • PostgreSQL：xmin/xmax + 事务快照
   • Oracle：SCN + 回滚段

最佳实践

1. 根据应用需求选择合适的隔离级别
2. 监控版本链长度，定期清理
3. 避免长事务，减少版本保留时间
4. 理解数据库的MVCC实现细节，优化查询

MVCC通过空间换时间（存储多个版本）实现了读写不阻塞，极大提升了并发性能，是现代数据库高并发能力的核心技术基础。
