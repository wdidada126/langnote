- 我用的Gentoo Linux，所以我不用apt或者pacman，而是使用emerge.但是呢，Gentoo Linux上的更新流程是，从git仓库更新gentoo.git和各个overlay，然后跑依赖计算emerge -uDUav @world，然后portage包管理器自动地逐个在tmpfs内存盘/tmp/portage里面编译包，编译完了安装到硬盘，包管理器自动追踪soname依赖会不会被破坏。然后手动cd到/usr/src/linux, 跑git fetch upstream && git rebase -i upstream ，然后make LLVM=1 -j32再sudo make install && sudo make modules_install，最后重启。如果要更新的包比较多，或者libc、编译器有更新，那就提前跑sudo zfs snapshot data/gentoo@20260101 瞬间创建一个快照。如果有包编译不过，或者测试不过，我可以在tmpfs里分析源码和编译日志，修改编译环境或者源码。如果有装上去的包报错或者段错误，我可以开-O0 -g重新编译包，然后上lldb、strace、改源码加printf精确分析程序行为。确定问题之后，要么改/etc/portage下面的配置，要么加patch，要么改ebuild脚本。由于我使用的musl libc和LLVM libc++和clang/flang/lld/LLVM tools比较特殊，因此我安装的1500多个包中大约30%的包需要处理。Gentoo甚至支持部分包直接用git仓库的最新版，也可以手动进行二分测试，然后把部分commit下载作为patch安装。如果启动不了，我可以在initramfs里重启到同一个ZFS存储池里安装的archlinux，再去修Gentoo Linux，或者直接从ZFS快照里捞文件/直接回退。如果掉盘了/电脑爆炸了/丢了，我可以从另一个电脑的机械硬盘里的ZFS存储池直接ssh root@nas zfs send -RVv data/gentoo@20260101 | sudo zfs receive -Fuv data/gentoo就可以把之前的快照下载回来。当然要定期反方向send快照过去。 相反的事情，我的Windows加了beta通道，目前版本是26220.7523，但是由于AB测试的存在，我根本不知道这个版本号意味着什么。Windows的补丁包是一个整体，我无法单独更新其中的一个部分。我没有源码，很难调试Windows内部问题。Windows也没有将ReFS作为系统盘的默认格式，不支持全盘快照备份。就比如我使用的一台笔记本最近不知道更新了什么，屏幕偶尔闪屏，但是Linux并不闪，明显是软件问题，但我压根无法排查到底是哪个Windows更新导致了这个问题。
