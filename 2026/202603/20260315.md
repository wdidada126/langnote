### Ubuntu 24.04 代理配置（WSL）

设置当前终端环境变量：

```bash
export http_proxy=http://172.18.176.1:20800
export https_proxy=http://172.18.176.1:20800
```

持久化到 `~/.bashrc`：

```bash
echo 'export http_proxy=http://172.18.176.1:20800' >> ~/.bashrc
echo 'export https_proxy=http://172.18.176.1:20800' >> ~/.bashrc
source ~/.bashrc
```

APT 代理配置：

```bash
sudo tee /etc/apt/apt.conf.d/95proxy >/dev/null <<'EOF'
Acquire::http::Proxy "http://172.18.176.1:20800";
Acquire::https::Proxy "http://172.18.176.1:20800";
EOF
```

Git 代理配置：

```bash
git config --global http.proxy http://172.18.176.1:20800
git config --global https.proxy http://172.18.176.1:20800
```

连通性测试：

```bash
curl -I -x http://172.18.176.1:20800 http://example.com
curl -I -x http://172.18.176.1:20800 https://example.com
```

### Shadowsocks/obfs（Shadowrocket 兼容说明）

如果 Windows 已提供 `127.0.0.1:20800` 的 HTTP/HTTPS 代理，WSL 只需配置代理即可，不必单独安装 obfs 插件。

若需要在 Ubuntu 侧自建 Shadowsocks + obfs 客户端，可使用以下包：

```bash
sudo apt update
sudo apt install -y shadowsocks-libev simple-obfs
```

示例（需替换为你的服务端信息）：

```bash
obfs-local -s <server_ip> -p <server_port> -l 1080 --obfs http --obfs-host <host>
```

然后将 WSL 代理指向本地端口：

```bash
export http_proxy=http://127.0.0.1:1080
export https_proxy=http://127.0.0.1:1080
```

ACM ICPC（现在叫 ICPC）是经典的大学团队算法竞赛，强调算法、数据结构、团队协作和现场编程。下面按你提到的三个领域（计算机领域、商业/金融领域、数学领域），列出一些同类需要写代码的知名赛事。这些赛事大多也以算法题、数据处理、建模、优化为主，很多和 ICPC 风格类似（算法题 + 时间压力 + 提交评测）。

### 计算机领域 / 纯算法 / 竞技编程类（最接近 ICPC 的）
这些是 ICPC 最直接的“兄弟姐妹”赛事，基本都要求写代码解决算法问题：

- Meta Hacker Cup（前 Facebook Hacker Cup）  
  个人赛，算法难度高，全球顶尖选手参与，奖金丰厚。

- Google Code Jam（虽然近年停办，但类似赛事仍在）  
  经典个人算法赛，曾经是和 ICPC 并列的最高殿堂之一。

- AtCoder World Tour Finals / AtCoder Regular Contests  
  日本最强平台，题目质量极高，很多题目比 ICPC 还难。

- Codeforces Global Rounds / Codeforces Round  
  几乎每周都有，参与人数最多，rating 系统最完善。

- TopCoder Open (TCO) / SRM  
  历史悠久，Marathon Match 特别适合需要优化的长时编程。

- IOI（国际信息学奥林匹克）  
  高中生最高赛事，但题目风格和大学算法赛高度重合，很多 ICPC 选手也刷 IOI 题。

其他值得一提的：  
- CodeChef Long Challenge / Cook-Off  
- AtCoder Beginner / Regular  
- LeetCode / 牛客 / 洛谷 平台周赛、国赛

### 商业 / 金融 / 定量领域（需要编程 + 商业/金融知识）
这些比赛通常结合编程 + 金融建模、数据分析、量化交易、优化等：

- Jane Street ETC (Electronic Trading Challenge)  
  量化交易巨头主办，偏交易系统、博弈、优化，代码要跑得快且稳。

- ADIA Lab Competition（阿布扎比投资局）  
  量化金融建模类，奖金很高。

- Optiver Ready Trader Go / Trading Challenge  
  很多量化公司（如 Citadel、Jump、Two Sigma）都有类似内部/公开交易编程比赛。

- Kaggle 竞赛（部分金融/量化专题）  
  虽然主要是数据科学，但很多比赛需要写大量代码建模。

- COMAP MCM/ICM 中的某些 Problem（见下文数学部分，有时偏金融优化）

- Nomura Programming Competition（野村证券主办，AtCoder 上跑）

商业领域纯编程的“ICPC 式”比赛不算特别多，大部分更偏项目制或量化面试题风格。

### 数学领域（数学建模 + 编程）
这些比赛需要大量编程来实现数学模型、数值计算、优化、模拟：

- COMAP MCM / ICM（Mathematical Contest in Modeling / Interdisciplinary Contest in Modeling）  
  最经典的数学建模比赛，3人团队，4天时间，用编程（MATLAB/Python/C++/R等）求解开放性现实问题，很多题目偏运筹、优化、数据分析、金融、物理模拟。和 ICPC 最大区别是开放题 + 写论文，但编程量非常大。

- HiMCM / MidMCM（高中版，但大学生也可以参考风格）

- Project Euler（常年开放题库）  
  纯数学 + 编程，必须写高效代码才能解到后面几百题。

- Google Hash Code（过去有，现在类似赛事仍在）  
  偏优化、图论、调度，常被认为是数学+算法的混合体。

- SIAM 某些挑战赛 或 100-Digit Challenge（历史赛事，但类似数值计算比赛仍有）

### 最新热点

2024-2025年运筹学热点聚焦于AI集成、可持续性和供应链韧性，受地缘政治和贸易政策影响。以下是关键趋势：

- 生成式AI与优化：GenAI用于供应链管理、物流和采购预测，预计50%以上的组织将在2024年投资AI和高级分析。例如，AI驱动的低触点规划和Scope 3 ESG数据报告。
- 可持续性和弹性：强调生产力、技术赋能和可持续性，如电动化未来和风险缓解。91%的领导者因美国贸易政策调整供应链策略。
- 技术采用上升：仓库/配送中心操作中，自动化、机器学习、IoT和区块链普及，纸质方法使用率下降，资本支出预算增加。
- 新兴主题：元启发式算法、车辆路径问题（VRP）和VLSI布局优化，受实时数据和动态约束影响。CLAIO 2024会议聚焦拉美运筹学趋势。

### 解决的实际问题

运筹学广泛应用于现实世界，帮助优化资源分配和决策。2024年重点包括：

- 供应链与物流：优化运输、库存和采购，减少成本并提升效率。例如，车辆路径问题用于货物配送，考虑动态约束如噪声数据和实时要求。
- 智能城市与规划：优化交通系统、能源消耗和废物管理，提升城市可持续性。
- 医疗与资源管理：COVID-19不确定性下的医院资源动态规划，使用近似动态编程。项目管理中资源分配，确保按时、预算和质量完成。
- 制造与生产：作业车间调度、库存控制和供应链集成，最小化完工时间。
- 日常应用：最短路径（通勤）、背包问题（打包）、队列理论（排队等待）、多准则决策（购物）。
- 能源与HR：能源消耗规划、激励匹配和对冲投资组合生成。

这些应用通过数学建模（如线性规划、混合整数规划）解决复杂问题，提升决策理性。

物流成本高、损耗大，正是运筹学大显身手的场景：

路径优化（Vehicle Routing Problem, VRP）：用算法规划最短/最低成本路线，减少空载、绕路，降低运输成本和损耗（生鲜尤其敏感）。
库存管理（Inventory Optimization）：EOQ模型、多级库存，减少囤货损耗。
网络设计（Facility Location）：选址冷库/前置仓/网格仓，平衡成本与时效。
供应链优化：线性规划/混合整数规划，整合产地-仓-社区团购-消费者，减少中间环节和断链。
冷链调度：考虑温度约束的动态规划/随机优化，降低生鲜损耗（中国果蔬损耗15-25%，欧美5%左右）。

实际问题如社区团购/生鲜电商的高损耗（25-30% vs 欧美1-5%），正是通过运筹学工具（如OR-Tools、PuLP建模、蚁群/遗传算法）来解决路径、调度、选址，实现降本增效。黄奇帆强调的“降5%释放6万亿”，本质上靠这些优化技术落地。
总之，黄奇帆说的“14”很可能指物流费用占GDP的14%-15%，欧美7%-8%；这背后大量运筹学应用空间，能显著降低实际损耗和成本。

### 幻方量化、DeepSeek与梁文锋概述

幻方量化（High-Flyer Quant Investment，或称宁波幻方量化/浙江高飞资产管理有限公司）是一家位于杭州的量化私募对冲基金公司，成立于2015年，由梁文锋（Liang Wenfeng，原查询中的“梁某人”）创立。他是浙江大学信息与电子工程学系本科和硕士毕业生，从2008年起就开始探索量化交易，使用机器学习等技术开发自动化交易系统。幻方量化以AI驱动的投资为核心竞争力，管理规模超过700亿元人民币（约100亿美元），是国内量化私募“四大天王”之一，曾在2021年峰值达1000亿元规模。

# 1. 先讲人话：Transformer 在做什么？
假设一句话：
> 我把杯子放在桌子上，因为它很干净。

人知道：它 = 杯子
机器以前不知道，现在 Transformer 知道。

Transformer 做的事：
给每个词，算它和句子里所有其他词的关系有多近。

- 它 ←→ 杯子：关系 很近
- 它 ←→ 桌子：关系 远

这就叫 Self-Attention（自注意力）

---

# 2. Transformer 工作流程（超简单 4 步）

## ① 把每个词变成向量（词嵌入）
机器不认识字，只认识数字。
每个词 → 一串数字（比如 512 维）。

## ② 对每个词，生成 3 个向量
对每个词向量，算 3 个东西：
- Query（查询）：我在找谁？
- Key（键）：我是谁？
- Value（值）：我有什么信息？

## ③ 算注意力分数（核心！）
用 Query × Key 看两个词相关不相关：
- 分数高 = 关系近
- 分数低 = 关系远

然后做个 softmax，让总和=1，得到注意力权重。

## ④ 用权重把 Value 加权求和
每个词的新表示 =
所有词的信息 × 注意力权重 加起来

一句话走完这一步，
每个词都“知道”整句话的重点在哪。

# 3. 为什么这东西这么强？
### 1）全局视野
LSTM 只能从左到右看，记不住前面。
Transformer 一次看完所有词。

### 2）可并行计算
LSTM 必须一个词一个词跑。
Transformer 所有词一起算，训练快 10~100 倍。

### 3）能抓长距离依赖
“它”和“杯子”隔很远也能连上。

### 4）堆叠越多层越强
- 低层：语法、近义词
- 中层：短语、逻辑
- 高层：语义、推理、意图

# 4. GPT 只用了 Transformer 的一半

- Encoder（编码器）：看懂句子 → BERT 用
- Decoder（解码器）：生成句子 → GPT 只用这个

Decoder 里的 Masked Multi-Head Attention
就是只能看前面的词，不能看后面的
这样才能逐字生成。

# 一、举个超级简单的例子
句子：
> 我把猫放在盒子里，因为它很乖。

人一看就知道：
它 = 猫

旧模型（LSTM/RNN）：
只能从左往右一个字一个字看，走着走着就忘了“猫”是谁。

Transformer：
每个字都会回头看整句话，自动发现：
“它”和“猫”关系最亲。

# 二、Transformer 工作流程（生活化版）

## 1）把每个词变成“词向量”
机器不认识字，只认识数字。
所以每个词 → 变成一串数字。
就像给每个词一个专属身份证。

---

## 2）给每个词 3 个问题（核心！）
对每个词，问 3 个问题：

1. Query（我在找谁？）
   我想关联哪些词？

2. Key（谁和我有关？）
   我能和谁匹配？

3. Value（我有什么信息？）
   我真正的内容是什么？

---

## 3）算“注意力分数”——谁和我最亲？
用：
Query × Key

得到一个分数：
- 分数高 = 关系近
- 分数低 = 关系远

比如：
- 它 ↔ 猫：分数很高
- 它 ↔ 盒子：分数低

这一步就是：
我要重点关注谁？

---

## 4）把重要信息“加权合并”
把所有词的信息，按注意力分数加权加起来。

结果：
“它”这个词，现在就包含了“猫”的信息。

---

## 5）多头注意力（Multi-Head Attention）
不是只算一次，而是算好多组不同的注意力。

- 一组看：语法关系
- 一组看：指代关系（它→猫）
- 一组看：逻辑关系
- 一组看：上下文语义

最后全部拼起来 → 信息超级丰富。

## 6）叠加很多层
一层不够，就叠 12 层、24 层、96 层。

- 低层：学词语、近义词
- 中层：学短语、句子结构
- 高层：学逻辑、推理、意图

层数越多，越聪明。
