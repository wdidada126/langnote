根据你提供的【链接2】（OpenCV-Python 项目的 README 文件）中的信息，文档明确指出：
Python bindings for OpenCV are developed in official OpenCV repository and it's the best place to report issues.
即，OpenCV 的 Python 绑定是在官方的 OpenCV 主仓库中开发的。opencv-python 这个项目本身只是一个用于打包和分发这些绑定文件的脚本库。

文档未详述的技术方案：
虽然你的链接文档没有详细解释其背后的绑定技术方案，但基于我所掌握的关于 OpenCV 生态的知识，OpenCV 官方为其 Python 接口所采用的底层绑定生成工具是 PyBind11。

以下是更详细的说明：
1.  核心历史与技术演变：早期 OpenCV 的 Python 绑定是使用一个名为 cv2.cpp 的庞大手工编写的 C 扩展模块来实现的。从 OpenCV 4.x 版本开始，官方逐步将新模块的绑定迁移到 PyBind11 上。PyBind11 是一个现代的、轻量级的 C++ 库，它可以将 C++ 代码无缝地暴露给 Python 使用，大大简化了绑定的创建和维护。
2.  opencv-python 项目的角色：opencv-python 这个 GitHub 项目（即你链接中的项目）的核心任务并不是“生成”绑定。它的工作是：
    ◦   从 OpenCV 官方仓库（opencv/opencv）和贡献模块仓库（opencv/opencv_contrib）拉取源代码，这其中已经包含了由 OpenCV 官方团队使用 PyBind11 生成的绑定代码。
    ◦   配置 CMake 参数，编译整个 OpenCV 库（包括 C++ 核心和 Python 绑定代码）。
    ◦   将编译生成的最终二进制文件（如 Windows 的 cv2.pyd 或 Linux 的 cv2.so）以及必要的依赖（如你提到的 opencv_videoio_ffmpeg*.dll）打包成 Python 的 wheel 安装包，并发布到 PyPI。

总结来说：
OpenCV 的 Python 绑定（即 cv2 模块）是在 OpenCV 官方仓库中使用 PyBind11 技术方案生成的。opencv-python 这个项目是一个“构建和分发”项目，它获取官方的源代码和绑定，进行编译，并将其打包成用户可以直接用 pip install 安装的便捷格式。因此，你通过 pip install opencv-python 安装的，正是包含基于 PyBind11 生成的二进制绑定文件的预编译包。
