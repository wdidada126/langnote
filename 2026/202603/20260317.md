git restore --staged 是 取消暂存文件 的命令。它的作用是：将已添加到暂存区（Staging Area）的文件，移回工作区（Working Directory），但保留文件的修改内容。

工作原理图示

工作区 (Working Directory)  <-- 暂存区 (Staging Area)  <-- 本地仓库 (Local Repository)
      ↑                                    ↑
      |         git add <file>             |
      |------------------------------------|
      |                                    |
      |       git restore --staged         |
      |<-----------------------------------|


具体作用
1. 只影响暂存状态：文件从"Changes to be committed"（已暂存）移动到"Changes not staged for commit"（未暂存）。
2. 不删除文件修改：文件的更改内容不会丢失，仍然保留在你的工作目录中。
3. 可重新添加：之后可以用 git add 再次暂存。

示例场景
假设你修改了文件 main.c：
# 1. 将修改添加到暂存区
git add main.c
# 2. 查看状态（main.c 在"Changes to be committed"中）
git status
# 3. 取消暂存（main.c 回到"Changes not staged for commit"）
git restore --staged main.c
# 4. 查看状态确认
git status


与相关命令的对比
命令 作用 影响范围
git restore --staged <file> 取消暂存，保留修改 仅暂存区
git restore <file> 丢弃工作区的修改 工作区
git reset HEAD <file> 同 restore --staged 仅暂存区
git rm --cached <file> 从Git删除，保留文件 从版本控制移除

你的实际情况
在你的例子中：
git restore --staged ../../.idea/

这条命令的意思是：取消 .idea/ 目录下所有文件的暂存状态，但这些文件及其内容仍然保留在你的工作目录中。
常用场景
1. 误添加了文件：不小心 git add 了不该提交的文件
2. 想分次提交：多个文件被同时暂存，但想分开提交
3. 重新审查修改：想再看一下修改内容再决定是否提交

这就是为什么你之前执行这个命令来取消 .idea 文件的暂存状态。

UC Berkeley 的 CS 262A 和 CS 262B 是研究生级别的经典系统方向课程，通常被视为一个两学期序列（year-long sequence），重点覆盖计算机系统研究的核心主题，包括操作系统、数据库系统、分布式系统、网络基础设施等。它们特别适合对系统研究感兴趣的学生（PhD-track 风格），阅读量大、paper-heavy，通常需要写 review、做 presentation 和 final project。

### CS 262A：Advanced Topics in Computer Systems
- 性质：Fall 学期为主（第一部分），广度覆盖经典到现代的系统主题。
- 典型内容：早期系统、内存管理、虚拟化、文件系统、并发、分布式基础、经典论文等。
- 当前/最近主页面（2025 Fall，由 John Kubiatowicz 教授主讲）：
  - 主课程网站：https://people.eecs.berkeley.edu/~kubitron/cs262/
  - 课程信息：https://people.eecs.berkeley.edu/~kubitron/cs262/index_information.html
  - 讲座安排（Lecture Schedule）：http://people.eecs.berkeley.edu/~kubitron/cs262/index_lectures.html （非常详细，包含 paper list 和 tentative schedule）
  - 项目展示（Final Projects）：https://people.eecs.berkeley.edu/~kubitron/cs262/index_projects.html （可以看到近年学生做的 research-style 项目）
  - Handouts / Reading Assignments：https://people.eecs.berkeley.edu/~kubitron/cs262/index_handouts.html （paper 阅读列表）

- 其他有价值的旧版参考（强烈推荐看，因为 paper list 变化不会太大）：
  - Fall 2020 版本（RISC-V / Berkeley RISe 相关）：https://ucbrise.github.io/cs262a-fall2020/
  - Eric Brewer 时代的老版本：https://people.eecs.berkeley.edu/~brewer/cs262
  - GitHub 上有人整理的 paper review + slides：https://github.com/indianwolverine/cs262a

### CS 262B：Advanced Topics in Computer Systems
- 性质：Spring 学期（续集），更偏向大规模系统、性能、扩展性、分布式数据管理等。
- 典型内容：性能测量、保护/安全、索引结构、并行查询处理、分布式文件系统/数据库、缓存、数据分析等。

### 总体建议获取资料的方式
1. 先看最新 CS 262A Fall 2025 的 lecture schedule 和 reading list，这是目前最活跃的入口，很多 paper 都会重复出现在往年。
2. 把 lecture page 里的 paper 标题列出来，然后去 Google Scholar / arXiv / ACM DL / USENIX 找 PDF（绝大部分经典系统论文都是 open access）。

从零开始用 Java 实现 Raft 算法是一个非常有价值的项目（也是很多分布式系统课程/面试的经典题目）。Raft 论文把复杂的一致性问题拆解得非常清晰，我们可以按照论文的结构逐步实现。

下面给你一个极简但完整的学习路径 + 代码骨架，目标是先跑通核心功能（选举 + 日志复制），然后再逐步加安全性和完整性。

### 推荐实现顺序（从简单到完整）
1. 定义基本数据结构（LogEntry、Raft RPC 请求/响应）
2. 实现状态机（persistent state + volatile state）
3. 实现心跳 + 选举超时（定时器）
4. 实现 RequestVote RPC（选举）
5. 实现 AppendEntries RPC（心跳 + 日志复制）
6. 实现状态转换（follower → candidate → leader）
7. 实现 leader 的日志复制逻辑（matchIndex/nextIndex）
8. 加安全性检查（论文 5.2 & 5.3）
9. 加 Apply 提交（commitIndex + lastApplied）
10. （可选）加快照、成员变更等

### 极简版核心类结构（适合从零开始）

```java
// 1. 基本枚举和常量
enum Role {
    FOLLOWER, CANDIDATE, LEADER
}

enum CommandType {  // 应用层命令示例
    SET, GET, DELETE
}

// 2. 日志条目
class LogEntry {
    long term;          // 任期
    Object command;     // 应用层命令（可以是 byte[] 或具体类型）
    // 可选：long index;  // 很多实现把 index 存在外面
}

// 3. Raft 节点核心状态（论文 Figure 2）
class RaftNode {
    // Persistent state on all servers（必须持久化）
    long currentTerm = 0;
    String votedFor = null;           // null 或 nodeId
    List<LogEntry> logs = new ArrayList<>();  // logs[0] 是 dummy 或从1开始

    // Volatile state on all servers
    Role role = Role.FOLLOWER;
    long commitIndex = 0;
    long lastApplied = 0;

    // Volatile state on leaders（仅 leader 维护）
    Map<String, Long> nextIndex;   // 每个 follower 的下一个发送索引
    Map<String, Long> matchIndex;  // 每个 follower 已匹配的最高索引

    // 网络相关（简化版）
    String nodeId;
    List<String> peers;            // 其他节点 id 列表
    // 实际中用 Netty/gRPC/简单 Socket 通信

    // 定时器（两个关键超时）
    ScheduledExecutorService scheduler;
    long electionTimeoutMs;   // 随机 150~300ms 左右
    long heartbeatIntervalMs = 50;

    // 当前 leader（volatile，可选）
    String leaderId = null;
}
```

### 核心方法骨架（伪代码风格）

```java
class RaftNode {
    // ------------------ 启动与定时器 ------------------
    void start() {
        logs.add(new LogEntry(0, null)); // index=0 占位
        resetElectionTimeout();
        scheduler.schedule(this::onElectionTimeout, electionTimeoutMs, MILLISECONDS);
    }

    void resetElectionTimeout() {
        electionTimeoutMs = 150 + new Random().nextInt(150); // 150~300ms
    }

    // ------------------ 选举超时触发 ------------------
    synchronized void onElectionTimeout() {
        if (role == Role.LEADER) return;

        role = Role.CANDIDATE;
        currentTerm++;
        votedFor = nodeId;
        long myLastLogIndex = logs.size() - 1;
        long myLastLogTerm = getLogTerm(myLastLogIndex);

        int voteCount = 1; // 自己投自己

        for (String peer : peers) {
            // 异步发送 RequestVote RPC
            sendRequestVote(peer, currentTerm, nodeId, myLastLogIndex, myLastLogTerm,
                response -> {
                    if (response.term > currentTerm) {
                        becomeFollower(response.term);
                        return;
                    }
                    if (response.voteGranted) {
                        voteCount++;
                        if (voteCount > peers.size() / 2 + 1 && role == Role.CANDIDATE) {
                            becomeLeader();
                        }
                    }
                });
        }

        resetElectionTimeout(); // 继续计时（万一没选上）
    }

    // ------------------ 成为 Leader ------------------
    void becomeLeader() {
        role = Role.LEADER;
        leaderId = nodeId;
        nextIndex = new HashMap<>();
        matchIndex = new HashMap<>();

        for (String peer : peers) {
            nextIndex.put(peer, logs.size());   // 初始化为 leader 自己下一条
            matchIndex.put(peer, 0);
        }

        // 立即发送一次空心跳
        sendHeartbeats();
        scheduler.scheduleAtFixedRate(this::sendHeartbeats, 0, heartbeatIntervalMs, MILLISECONDS);
    }

    // ------------------ AppendEntries（心跳 + 复制） ------------------
    void sendHeartbeats() {
        if (role != Role.LEADER) return;

        for (String peer : peers) {
            long next = nextIndex.getOrDefault(peer, 1L);
            long prevLogIndex = next - 1;
            long prevLogTerm = getLogTerm(prevLogIndex);

            List<LogEntry> entries = new ArrayList<>();
            if (next < logs.size()) {
                entries = logs.subList((int)next, logs.size());
            }

            sendAppendEntries(peer, currentTerm, nodeId, prevLogIndex, prevLogTerm,
                              entries, commitIndex,
                response -> handleAppendEntriesResponse(peer, response));
        }
    }

    void handleAppendEntriesResponse(String peer, AppendEntriesResponse resp) {
        if (resp.term > currentTerm) {
            becomeFollower(resp.term);
            return;
        }
        if (!resp.success) {
            // 快速回退优化（论文 5.3）
            nextIndex.put(peer, nextIndex.get(peer) - 1); // 简单版，也可以指数回退
        } else {
            long newMatch = nextIndex.get(peer) + resp.entriesSent - 1;
            matchIndex.put(peer, newMatch);
            nextIndex.put(peer, newMatch + 1);

            // 更新 commitIndex（多数派已复制）
            updateCommitIndex();
        }
    }

    // ------------------ 接收 RPC ------------------
    RequestVoteResponse onRequestVote(RequestVoteRequest req) {
        if (req.term < currentTerm) return new RequestVoteResponse(currentTerm, false);

        if (req.term > currentTerm) {
            becomeFollower(req.term);
        }

        boolean canGrant = (votedFor == null || votedFor.equals(req.candidateId)) &&
                           isLogUpToDate(req.lastLogIndex, req.lastLogTerm);

        if (canGrant) {
            votedFor = req.candidateId;
            resetElectionTimeout();
        }
        return new RequestVoteResponse(currentTerm, canGrant);
    }

    AppendEntriesResponse onAppendEntries(AppendEntriesRequest req) {
        if (req.term < currentTerm) {
            return new AppendEntriesResponse(currentTerm, false);
        }

        if (req.term > currentTerm) {
            becomeFollower(req.term);
        }

        resetElectionTimeout(); // 收到合法 leader，重置选举计时

        // 日志一致性检查
        if (!matchLog(req.prevLogIndex, req.prevLogTerm)) {
            return new AppendEntriesResponse(currentTerm, false);
        }

        // 覆盖冲突日志 + 追加新日志
        truncateLog(req.prevLogIndex + 1);
        logs.addAll(req.entries);

        // 更新 commitIndex
        if (req.leaderCommit > commitIndex) {
            commitIndex = Math.min(req.leaderCommit, logs.size() - 1);
            applyToStateMachine();
        }

        return new AppendEntriesResponse(currentTerm, true);
    }

    // 辅助方法（需实现）
    boolean isLogUpToDate(long lastIndex, long lastTerm) { ... }
    long getLogTerm(long index) { ... }
    boolean matchLog(long index, long term) { ... }
    void truncateLog(long fromIndex) { ... }
    void applyToStateMachine() { while (lastApplied < commitIndex) apply(logs.get(++lastApplied)); }
    void becomeFollower(long newTerm) { ... }
    void updateCommitIndex() { ... }  // 找多数派 matchIndex
}
```

### 极简建议实现步骤（推荐顺序）

1. 先写 LogEntry + RPC 请求/响应类（RequestVoteRequest/Response, AppendEntriesRequest/Response）
2. 实现 持久化（currentTerm, votedFor, logs） → 可以先用内存，后面加文件
3. 实现 选举超时 + RequestVote（先跑通 Leader 选举）
4. 实现 心跳（空 AppendEntries）
5. 实现 日志追加（客户端 put → leader append → replicate）
6. 加 安全性（term 检查、日志冲突处理）
7. 加 commit & apply（状态机应用）
