### 最快上手建议（推荐路径）
1. 先克隆官方最简单的（5 分钟上手）：
   ```bash
   git clone https://github.com/pybind/python_example
   cd python_example
   pip install .
   ```
   然后在 Python 里：
   ```python
   import python_example
   print(python_example.add(3, 4))   # 输出 7
   ```

2. 想用 CMake 的（大多数生产项目用这个）：
   ```bash
   git clone https://github.com/pybind/cmake_example
   cd cmake_example
   mkdir build && cd build
   cmake .. -DPYBIND11_INSTALL=ON
   make install
   ```
   （或直接 pip install . 如果有 pyproject.toml）

3. 想看多种写法：
   直接去 https://github.com/tdegeus/pybind11_examples ，里面有 10+ 个独立小例子，clone 后随便进一个文件夹看 README。

4. 配套官方文档（强烈建议同时看）：
   - https://pybind11.readthedocs.io/en/stable/basics.html （从这里开始，讲得最清楚）
   - 文档里也直接指向上面两个官方 example 仓库。

这些仓库代码都很干净，基本都是 2024–2026 年还能正常构建的。如果你遇到编译问题（比如 Python 版本、CMake 找不到 pybind11），可以先用 conda 环境：
```bash
conda create -n pybind python=3.11
conda activate pybind
conda install -c conda-forge pybind11 cmake
```

新建一个 Rust workspace（工作区）工程，目前（Rust 1.80+ 时代，Cargo 最新版）最常见、最推荐的方式有两种：

### 方式一：最简单、最常用（虚拟 manifest + cargo new 自动加入） ★★★★★

```bash
# 1. 创建空目录并进入
mkdir my-workspace
cd my-workspace

# 2. 先创建一个普通的 crate（随便起名，比如 app 或 cli），Cargo 会自动帮你创建 workspace 配置
cargo new app --bin          # 或者 --lib 如果你想要库为主

# 此时目录结构大致是这样：
# my-workspace/
# ├── Cargo.toml          ← 自动变成了 workspace 配置！
# ├── Cargo.lock
# └── app/
#     ├── Cargo.toml
#     └── src/
#         └── main.rs

# 3. 继续添加其他成员 crate（Cargo 会自动追加到 members）
cargo new utils --lib
cargo new core --lib
cargo new web --bin

# 4. 查看根 Cargo.toml，应该长这样（Cargo 自动维护）：
[workspace]
members = [
    "app",
    "utils",
    "core",
    "web",
]
resolver = "2"   # 或 "3"，取决于你的 Rust 版本

# （可选）你可以手动加一些统一设置
[workspace.package]
rust-version = "1.80"

[workspace.lints.rust]
unsafe_code = "forbid"
```

优点：最省事，Cargo 帮你维护 members 列表。  
现在 2025–2026 年主流项目（Bevy、Axum、Tokio 等）大多就是这种风格。

### 方式二：先手动创建虚拟 workspace（没有根 package）

```bash
# 1. 创建目录
mkdir my-workspace
cd my-workspace

# 2. 手动创建根 Cargo.toml（虚拟 manifest，不带 [package]）
cat > Cargo.toml << 'EOF'
[workspace]
resolver = "2"          # 或 "3"（推荐新项目用 3）
members = []            # 后面再加

# 可选：统一设置
[workspace.package]
rust-version = "1.80"

[workspace.dependencies]
# 如果想统一 tokio 版本等，可以在这里定义
tokio = { version = "1.40", features = ["full"] }
EOF

# 3. 然后添加成员（推荐放在 crates/ 或直接平铺）
cargo new crates/my-lib --lib
cargo new crates/my-bin --bin
cargo new cli --bin

# 4. 手动把路径加到 members（或用 glob 写法）
# 编辑根 Cargo.toml，改成：
members = [
    "crates/my-lib",
    "crates/my-bin",
    "cli",
]
# 或者更懒的 glob 写法（推荐）：
members = ["crates/*", "cli"]
```

优点：结构更清晰，适合大型 monorepo，没有“根 package”的噪音。  
缺点：需要手动维护 members（除非用 glob）。

### 快速对比表

| 方式               | 步骤数 | 自动维护 members | 推荐场景                     | 根目录有 package? |
|--------------------|--------|------------------|------------------------------|-------------------|
| 方式一（先 cargo new） | 最少   | 是               | 绝大多数中小型项目、快速上手 | 有（第一个 crate）|
| 方式二（虚拟 manifest）| 多1–2步| 否（但可用 glob）| 大型 monorepo、Bevy/Axum 风格 | 无                |

### 常用后续命令（在 workspace 根目录执行）

```bash
cargo build --workspace       # 编译所有成员
cargo test --workspace
cargo check --workspace
cargo clippy --workspace --all-targets

cargo run -p app              # 只跑 app 这个 crate 的 main
cargo test -p utils           # 只测 utils

cargo add serde --workspace   # （Cargo >=1.64）给所有成员都加 serde
```

### 小Tips

- 如果你想让所有 crate 继承统一的依赖版本 → 用 `[workspace.dependencies]`
- 想统一 rust-version、lints 等 → 用 `[workspace.package]` 和 `[workspace.lints]`
- 根目录放 `.gitignore`、`README.md`、`rust-toolchain.toml` 等统一文件最方便

最简单上手建议：直接用方式一，先 `cargo new myapp`，然后不断 `cargo new xxx` 添加模块就行了。
