错误信息显示 Maven 将你的参数 -Dmaven.test.skip=true 解析成了一个 生命周期阶段（Lifecycle Phase），而不是系统属性参数。

这通常发生在 Windows PowerShell 中参数传递的特殊字符问题 或 命令行解析器异常。

问题原因
在 Windows PowerShell 中，-D 参数可能被错误解析。Maven 可能收到了错误的参数格式。

解决方案
方案1：使用引号包裹参数（最有效）

mvn clean install "-Dmaven.test.skip=true"
或者
mvn clean install '-Dmaven.test.skip=true'

方案2：使用简写参数
mvn clean install -DskipTests

方案3：使用 Git Bash 或 CMD 替代 PowerShell
# 打开 Git Bash 或 Windows CMD
cd /d/d/develops/git/github/java/MIT6.824-Java
mvn clean install -Dmaven.test.skip=true
方案4：在 PowerShell 中转义参数
# 使用 -- 分隔参数
mvn clean install -- -Dmaven.test.skip=true
# 或使用 @args 语法
$mvnArgs = @("clean", "install", "-Dmaven.test.skip=true")
mvn $mvnArgs

方案5：检查 PowerShell 版本和配置
# 查看 PowerShell 版本
$PSVersionTable.PSVersion

# 临时切换到旧版参数解析
Set-StrictMode -Version 2.0
mvn clean install -Dmaven.test.skip=true

字节跳动，Go代码因为机器不够改成Rust的，别搞引用，遇事不决直接clone，写rust就跟写python和java一样
在 Rust 中，引用（Reference）和 克隆（Clone）是处理数据所有权的两种核心方式。简单来说，引用是“借来看”，克隆是“复制一份”。对于从 Go 转 Rust 的开发者，理解这两者的区别至关重要。

核心区别：借用 vs 复制

特性 引用 (Reference) 克隆 (Clone)

本质 借用数据，不拥有所有权 深度复制数据，创建新所有权

内存 指向原数据，不分配新内存 分配新内存，复制数据

性能 零成本，极快 有开销，可能慢

规则 受借用检查器严格限制 无限制，但消耗资源

1. 引用 (Reference)：只读“借阅证”

引用使用 & 符号，它允许你查看数据，但不能修改（除非是可变引用 &mut），且原数据的所有权保持不变。

示例：查看数据（只读）
fn main() {
    let s1 = String::from("hello");
    let s2 = &s1; // s2 只是借用了 s1 的数据

    println!("s1: {}", s1); // ✅ 正常，s1 仍然有效
    println!("s2: {}", s2); // ✅ 正常，打印借来的数据
}


示例：修改数据（可变引用）
fn main() {
    let mut s1 = String::from("hello");
    let s2 = &mut s1; // s2 借用了 s1 的可变权限

    s2.push_str(", world!"); // ✅ 通过 s2 修改 s1
    println!("s1: {}", s1); // 输出：hello, world!
}


⚠️ 引用限制（借用规则）
Rust 的引用有严格的规则，这是为了内存安全：
•   同一时间，要么有多个只读引用，要么有一个可变引用，不能共存。

•   引用必须总是有效的（不能悬空）。
fn main() {
    let mut s = String::from("hello");

    let r1 = &s;     // 只读引用
    let r2 = &s;     // 只读引用 ✅ 允许
    // let r3 = &mut s; // ❌ 编译错误！不能同时存在只读和可变引用
    println!("{}, {}", r1, r2);
}


2. 克隆 (Clone)：直接“复制粘贴”

克隆使用 .clone() 方法，它会完整复制一份数据。新变量拥有独立的所有权，与原数据互不影响。这是解决编译报错最直接的方法。

示例：创建独立副本
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone(); // 复制一份数据给 s2

    println!("s1: {}", s1); // ✅ 正常，s1 还在
    println!("s2: {}", s2); // ✅ 正常，s2 是独立的
}


⚠️ 克隆的代价
克隆虽然方便，但性能开销大。对于 String、Vec 等复杂类型，克隆意味着在堆上重新分配内存并复制所有数据。滥用 clone() 会导致程序变慢。

3. 实战场景：引用 vs 克隆
场景 A：函数参数传递
•   引用（推荐）：如果函数只需要读取数据，传引用。
    fn print_length(s: &String) { // 借用，不拿所有权
        println!("Length: {}", s.len());
    }
    fn main() {
        let s = String::from("hello");
        print_length(&s); // 传引用
        println!("{}", s); // ✅ s 仍然可用
    }
    
•   克隆（不推荐）：传克隆会创建副本，浪费内存。
    fn print_length(s: String) { // 拿所有权
        println!("Length: {}", s.len());
    } // s 在这里被销毁
    fn main() {
        let s = String::from("hello");
        print_length(s.clone()); // 传副本
        // println!("{}", s); // ❌ 错误！s 的所有权没动，但传的是副本，这里 s 还在吗？(其实还在，因为传的是副本，原 s 没动)
        // 修正：上面注释有误，传 clone() 后原 s 仍在，但通常不这样写。
    }
    

场景 B：数据结构共享
•   引用：如果多个地方需要同时读取同一份数据，用引用。
•   克隆：如果多个地方需要独立修改数据，用克隆。

4. 总结：什么时候该“遇事不决直接 clone”？
虽然 Rust 社区提倡少用 clone，但对于刚入门或快速原型开发，clone 是解决编译错误的“万能钥匙”。

•   写 Python/Java 的感觉：在 Python/Java 中，赋值通常是“传引用”或“浅拷贝”。在 Rust 中，如果你想要类似“两个变量指向同一份数据”的效果，你应该用引用（&）。

•   什么时候用 clone：当你遇到编译器报错说“所有权已移动，值已被使用”时，如果你不想去理解复杂的生命周期和借用规则，直接加个 .clone() 往往就能让代码跑起来。但这只是权宜之计，长期来看，学会使用引用才是正道。

一句话建议：先靠 clone 让代码跑起来，再逐步优化掉不必要的 clone，换成引用。
