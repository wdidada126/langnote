在 MySQL 5.7 中，InnoDB 存储引擎支持四种事务隔离级别（Transaction Isolation Level），默认是REPEATABLE READ（可重复读）。
### MySQL 5.7 支持的隔离级别（从低到高）
- READ UNCOMMITTED（读未提交） — 可能出现脏读
- READ COMMITTED（读已提交） — 可能出现不可重复读和幻读
- REPEATABLE READ（可重复读） — MySQL 的默认级别，InnoDB 通过 MVCC + 间隙锁防幻读（接近 Serializable 但性能更好）
- SERIALIZABLE（可串行化） — 最严格，读写都加锁，并发最低

### 如何查看当前隔离级别
```sql
-- 当前会话（session）级别
SELECT @@tx_isolation;                  -- MySQL 5.7.19 及更早版本常用
-- 或
SELECT @@transaction_isolation;         -- MySQL 5.7.20+ 推荐（tx_isolation 已弃用）

-- 全局（global）级别
SELECT @@global.tx_isolation;
-- 或
SELECT @@global.transaction_isolation;
```

### 如何更改隔离级别（三种方式）
#### 1. 仅当前会话（Session）级别生效（最常用，推荐）
```sql
-- 方式一：标准写法（推荐）
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 方式二：简写（MySQL 5.7 支持）
SET SESSION tx_isolation = 'READ-COMMITTED';   -- 5.7.19 及更早
SET SESSION transaction_isolation = 'READ-COMMITTED';  -- 5.7.20+

-- 生效后只对本连接有效，新开连接仍用默认
```

#### 2. 全局级别（影响所有新连接，不影响当前连接）
```sql
SET GLOBAL TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 或
SET GLOBAL tx_isolation = 'READ-COMMITTED';   -- 旧写法
SET GLOBAL transaction_isolation = 'READ-COMMITTED';  -- 新写法

-- 注意：已连接的会话不受影响，新连接才会使用新全局值
-- 重启 MySQL 后会丢失，除非写入配置文件
```

#### 3. 永久生效（修改配置文件，重启 MySQL）
在 `my.cnf` 或 `my.ini` 文件中添加（推荐）：

```ini
[mysqld]
transaction-isolation = READ-COMMITTED
# 或旧写法（5.7.19 及更早）
# tx_isolation = READ-COMMITTED
```

- 保存后重启 MySQL 服务（或 `systemctl restart mysqld`）
- 所有连接默认使用该级别

### 常见场景示例

想改成 READ COMMITTED（减少死锁，提高并发）：

```sql
-- 当前会话
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 全局 + 永久（配置文件）
[mysqld]
transaction-isolation = READ-COMMITTED
```

改回默认 REPEATABLE READ：

```sql
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
```

最高级别 SERIALIZABLE（严格一致性，但性能差）：

```sql
SET SESSION TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

### 注意事项（MySQL 5.7 特有）
- `tx_isolation` 在 5.7.20 后被 `transaction_isolation` 取代为推荐写法，但两者都支持（向后兼容）。
- InnoDB 只支持这四种级别，其他存储引擎（如 MyISAM）不支持事务隔离。
- 隔离级别越高，并发越低，死锁/锁等待风险越高。
- 生产环境改隔离级别前测试（尤其是从 REPEATABLE READ 改 READ COMMITTED，可能出现幻读）。
- 连接池（如 HikariCP、Druid）建议在连接初始化时执行 SET SESSION ...，避免每个事务都设。

如果你是 MySQL 5.7 的 RDS/Aurora 等云服务，可能需要在控制台参数组修改 `transaction_isolation` 参数。

在 PostgreSQL 中，事务隔离级别（Transaction Isolation Level）的默认值是 read committed（读已提交），这是全局配置参数 `default_transaction_isolation` 决定的。

你可以通过修改配置文件 `postgresql.conf` 来永久更改默认隔离级别（影响所有新事务/新连接）。PostgreSQL 支持的标准隔离级别有：

- read uncommitted（读未提交，实际行为等同 read committed）
- read committed（默认）
- repeatable read（可重复读）
- serializable（可串行化，最严格）

### 修改配置文件 postgresql.conf 的步骤

1. 找到配置文件位置  
   通常在数据目录下（运行以下命令查看确切路径）：
   ```sql
   SHOW config_file;
   ```
   常见路径示例：
   - Linux/Debian/Ubuntu：`/etc/postgresql/<version>/main/postgresql.conf` 或 `/var/lib/postgresql/<version>/main/postgresql.conf`
   - macOS (Homebrew)：`/usr/local/var/postgres/postgresql.conf`
   - Windows：`C:\Program Files\PostgreSQL\<version>\data\postgresql.conf`

2. 编辑 postgresql.conf  
   找到或添加以下行（建议放在文件末尾或 [Client Connection Defaults] 部分附近）：
   ```ini
   # 设置默认隔离级别为 repeatable read（示例）
   default_transaction_isolation = 'repeatable read'
   
   # 或者其他选项：
   # default_transaction_isolation = 'serializable'
   # default_transaction_isolation = 'read committed'   # 恢复默认
   # default_transaction_isolation = 'read uncommitted' # 实际等同 read committed
   ```

   - 值必须用单引号包围。
   - 支持的枚举值：`serializable`、`repeatable read`、`read committed`、`read uncommitted`（大小写不敏感，但建议小写）。

3. 重载配置（不需重启数据库）  
   修改后执行以下任一命令使配置生效（推荐）：
   ```sql
   -- 在 psql 或任何客户端执行
   SELECT pg_reload_conf();
   ```
   或在服务器终端：
   ```bash
   pg_ctl reload -D /path/to/data/dir
   # 或 systemd
   sudo systemctl reload postgresql
   ```

   注意：`default_transaction_isolation` 是 user 上下文参数，重载（reload）后立即对新连接生效，已有连接不受影响（需断开重连）。

4. 验证修改是否生效  
   新开一个连接（或断开重连），运行：
   ```sql
   SHOW default_transaction_isolation;
   SHOW transaction_isolation;  -- 当前事务的隔离级别（新事务开始时会继承 default）
   ```

### 其他方式设置隔离级别（对比参考）

- 会话级别（只影响当前连接，不改配置文件）：
  ```sql
  SET default_transaction_isolation = 'serializable';
  -- 或
  SET SESSION CHARACTERISTICS AS TRANSACTION ISOLATION LEVEL SERIALIZABLE;
  ```

- 数据库级别（影响特定数据库的所有用户）：
  ```sql
  ALTER DATABASE your_db_name SET default_transaction_isolation = 'repeatable read';
  ```

- 用户/角色级别（影响特定用户的所有连接）：
  ```sql
  ALTER ROLE your_user SET default_transaction_isolation = 'serializable';
  ```

- 单个事务级别（最灵活，只影响当前事务）：
  ```sql
  BEGIN;
  SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
  -- ... 你的查询 ...
  COMMIT;
  ```

### 注意事项（PostgreSQL特性）
- PostgreSQL的read uncommitted实际行为与read committed相同（文档明确说明）。
- serializable级别使用Serializable Snapshot Isolation (SSI)，性能开销较大，适合对一致性要求极高的场景。
- 改成 repeatable read 或 serializable 后，并发可能下降，死锁/事务失败率上升，生产环境要先测试。
- 如果你是云托管（如 AWS RDS、Google Cloud SQL、Azure Database for PostgreSQL），通常通过参数组修改 `default_transaction_isolation`（控制台操作），而不是直接编辑文件。

在 PostgreSQL 的源代码中，配置文件 `postgresql.conf` 中的参数 `default_transaction_isolation` 是通过 GUC（Grand Unified Configuration）系统 读取并解析的。

这个参数最终会影响全局变量 `DefaultXactIsoLevel`，它是一个 `int` 类型的值，对应内部枚举（`XACT_READ_COMMITTED`、`XACT_REPEATABLE_READ` 等）。

下面一步步详解 PostgreSQL（以主分支 / 最新稳定版为例，17/18 类似，5.x–16.x 核心逻辑几乎相同）中读取和应用这个配置的 C 代码路径。

### 1. GUC 定义位置（参数注册）
`default_transaction_isolation` 是一个 enum 类型 的 GUC 变量，在源代码中通过 `DefineEnumGUC` 或类似宏注册。

核心文件：
- `src/backend/utils/misc/guc.c`（GUC 系统核心实现）
- `src/include/utils/guc.h`（GUC 宏和结构体定义）
- `src/backend/utils/misc/guc_tables.c`（所有内置 GUC 的静态表定义）

在 `guc_tables.c` 中找到类似下面的定义（简化摘录，实际代码更复杂）：

```c
/* src/backend/utils/misc/guc_tables.c */

static struct config_enum ConfigureNamesEnum[] = {
    ...
    {
        {"default_transaction_isolation", PGC_USER, GUC_ENUM},
        &DefaultXactIsoLevel,
        "default_transaction_isolation", gettext_noop("Sets the transaction isolation level of each new transaction."),
        gettext_noop("The default is \"read committed\"."),
        NULL, NULL, NULL,
        assign_default_xact_iso_level, show_xact_iso_level, NULL,
        {
            {"serializable", XACT_SERIALIZABLE},
            {"repeatable read", XACT_REPEATABLE_READ},
            {"read committed", XACT_READ_COMMITTED},
            {"read uncommitted", XACT_READ_COMMITTED},  /* 映射为 read committed */
            {NULL, 0}
        }
    },
    ...
};
```

- `DefaultXactIsoLevel` 是全局变量（`int` 类型），定义在 `src/backend/access/transam/xact.c`
- 它的初始值（编译时默认）是 `XACT_READ_COMMITTED`（即 "read committed"）

```c
/* src/backend/access/transam/xact.c */

int DefaultXactIsoLevel = XACT_READ_COMMITTED;
int XactIsoLevel = XACT_READ_COMMITTED;  /* 当前事务的隔离级别，会在事务开始时继承 Default */
```

### 2. 配置文件读取流程（postgresql.conf → GUC 系统）

PostgreSQL 启动时（或 `pg_reload_conf()` 时）会读取配置文件，核心调用链如下：

1. Postmaster 启动阶段 → `PostmasterMain()` → `ResetAllOptions()` → `SelectConfigFiles()`
2. 读取配置文件 → `ProcessConfigFile(PGC_POSTMASTER)` 或 `PGC_SIGHUP`（reload 时）
   - 文件：`src/backend/utils/misc/guc.c` 中的 `ProcessConfigFile()`
3. 逐行解析 → 调用 `ParseConfigFile()` → `ParseConfigFp()` → `lex_one_token()`（词法分析）
4. 参数赋值 → `set_config_option()`（核心函数）

关键函数：`set_config_option()`（`guc.c`）

```c
/* src/backend/utils/misc/guc.c */

bool
set_config_option(const char *name, const char *value,
                  GucContext context, GucSource source,
                  GucAction action, bool changeVal,
                  int elevel, bool isStartup)
{
    ...
    conf = find_option(name, true, elevel);
    if (conf == NULL)
        return false;

    /* 枚举类型会调用 assign hook */
    if (conf->assign_hook)
        newval = conf->assign_hook(value, context, conf->extra);

    ...
    if (changeVal)
        assign_variable(conf, newval, isStartup);
}
```

对于 `default_transaction_isolation`，它的 `assign_hook` 是：

```c
/* 在 guc_tables.c 或相关文件中注册的 assign 函数 */
static bool
assign_default_xact_iso_level(const char *value, void *extra)
{
    int level = *((int *) extra);

    DefaultXactIsoLevel = level;

    return true;
}
```

（实际代码中通常用 `show_xact_iso_level` 做显示 hook，用 `assign_default_xact_iso_level` 或直接用内置枚举转换）

### 3. 关键全局变量赋值时机

- 启动时：`ResetAllOptions()` → `InitializeGUCOptions()` → 读取配置文件 → `set_config_option()` → 最终 `DefaultXactIsoLevel = XACT_REPEATABLE_READ`（如果配置文件中写了 `'repeatable read'`）
- 重载时（`pg_reload_conf()` 或 SIGHUP）：只重新读取 user 级别的参数（`PGC_USER`），`default_transaction_isolation` 属于 `PGC_USER`，所以 reload 后新连接立即生效（旧连接不受影响）。

### 4. 事务开始时继承

当一个新事务启动时（`StartTransaction()`），会从 `DefaultXactIsoLevel` 继承：

```c
/* src/backend/access/transam/xact.c */

void
StartTransaction(void)
{
    ...
    XactIsoLevel = DefaultXactIsoLevel;
    ...
}
```

- `XactIsoLevel` 是当前事务的隔离级别。
- 后续的 `SET TRANSACTION ISOLATION LEVEL ...` 会修改 `XactIsoLevel`，但不改 `DefaultXactIsoLevel`。

### 5. 总结：读取 → 赋值 → 生效的完整链路（简要）

```
postgresql.conf
   ↓ (解析)
ProcessConfigFile() → ParseConfigFile() → set_config_option("default_transaction_isolation", "repeatable read")
   ↓
find_option() → 找到 GUC 条目（name = "default_transaction_isolation"）
   ↓
assign hook 或直接赋值 → DefaultXactIsoLevel = XACT_REPEATABLE_READ
   ↓ (新事务开始时)
StartTransaction() → XactIsoLevel = DefaultXactIsoLevel
   ↓
事务执行中使用 XactIsoLevel 判断可见性（Snapshot 构建、谓词锁等）
```

调度为事务的并发过程中，决定事务中每个操作的执行顺序。

串行调度(serial schedule): 事务串行执行
调度定义下的并发控制:
给定一个并发调度S ，存在一个串行调度S’， 在任何数据库状态下，按照调度S和调度S’执行后所产生的结果都是相同的 。
此时调度S 被称之为可串行化调度（serializable schedule）。
可串行化调度的数量十分巨大，且难以校验，数据库中一般通过找到可串行化调度的子集（充分条件），即找到能够提前确认是可串行调度的并发调度，进而提升调度效率。
