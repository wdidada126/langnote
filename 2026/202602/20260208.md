在 Bash 中，注释使用 # 符号，而不是 //。以下是详细说明：

Bash 注释的基本语法

1. 单行注释

# 这是一个注释
echo "Hello World"  # 这是行尾注释

# 多行独立注释
# 第二行注释
# 第三行注释


2. 多行注释（文档字符串风格）

虽然 Bash 没有原生的多行注释语法，但常用以下方法：

方法一：使用 : 和 HERE DOC
: << 'COMMENT'
这是多行注释
可以写多行文字
不会被解释器执行
COMMENT


方法二：使用函数定义（不调用）
__comment() {
  这里面的内容
  可以写多行
  只要不调用这个函数就不会执行
}


方法三：使用 if false 包裹
if false; then
  这里的内容都不会执行
  可以当作注释使用
  特别是临时禁用代码块
fi


Bash 与 PowerShell注释对比
功能 Bash PowerShell
单行注释 # 注释 # 注释
行尾注释 命令 # 注释 命令 # 注释
多行注释 无原生语法 <# 多行注释 #>
注释块 需用技巧实现 原生支持
实用示例

#!/bin/bash
# ============================================
# 脚本名称: example.sh
# 功能描述: 演示Bash注释的使用
# 创建时间: 2024-01-01
# ============================================

# 定义变量
name="World"  # 设置默认名称

# 输出欢迎信息
echo "Hello, $name!"

# 临时禁用以下代码块
: << 'DISABLED'
echo "这行不会执行"
echo "这行也不会执行"
DISABLED

# 另一种禁用代码的方法
if false; then
    echo "被禁用的代码块"
    date
fi

# 函数定义
say_hello() {
    # 函数内部注释
    local msg="$1"  # 获取第一个参数
    echo "消息: $msg"
}

# 调用函数
say_hello "测试"  # 输出测试消息


特殊情况的注释技巧

1. 在管道命令中注释

# 错误示例（会破坏管道）
# cat file.txt | grep "pattern" | wc -l

# 正确示例：注释整个管道
: << 'NOTE'
cat file.txt \
  | grep "pattern" \
  | wc -l
NOTE

# 或者使用临时变量
tmp=$(cat file.txt)  # 读取文件
# tmp=$(echo "$tmp" | grep "pattern")  # 先注释掉这步
result=$(echo "$tmp" | wc -l)  # 统计行数


2. 调试时快速注释/取消注释

# 使用 : 命令临时禁用
: echo "这行不会执行"
echo "这行会执行"

# 快速切换（修改第一个字符即可）
# echo "注释状态"
: echo "执行状态"  # 将 : 改为 # 可以切换状态


3. Shebang 行注意事项

#!/bin/bash
# 上面这行必须是文件的第一行，且不能有空格
# 这行告诉系统用 bash 解释器执行本脚本


最佳实践建议

1. 脚本开头注释：
#!/bin/bash
# Script: backup.sh
# Author: Your Name
# Description: 数据库备份脚本
# Usage: ./backup.sh [options]
# Version: 1.0


2. 函数注释：
# 函数: calculate_sum
# 参数: $1 - 第一个数字
#       $2 - 第二个数字
# 返回: 两个数字的和
# 示例: calculate_sum 10 20
calculate_sum() {
    echo $(($1 + $2))
}


3. TODO/FIXME 注释：
# TODO: 需要添加错误处理
# FIXME: 这里的性能需要优化
# NOTE: 这是临时解决方案
# BUG: 在某些情况下会失败

总结
• Bash 使用 # 进行注释，// 在 Bash 中没有特殊意义，会被当作普通字符
• 多行注释需要技巧实现，常用 : << 'COMMENT' 语法
• 在命令行中也可以使用 #：
  $ echo "test"  # 这是注释
  test
记住这个简单规则：在 Bash 中，# 之后到行尾的内容都是注释（除非 # 出现在引号中或正在转义）。
