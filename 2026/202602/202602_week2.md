在 GitHub Actions 的 .yml 文件（workflow 文件）中处理 ghp_xxxxxxxxxxxx（Personal Access Token，简称 PAT）时，不能直接把真实 token 硬编码进去（如 ghp_abc123...），因为这会泄露 token，导致安全风险（GitHub 会扫描并自动禁用它）。
正确做法是把 token 存成 Repository Secret，然后在 workflow yaml 中通过 ${{ secrets.XXX }} 来引用它。GitHub 会自动在日志中脱敏（显示为 *），非常安全。
步骤详解
1. 先把 token 存成 Secret（只做一次）

去你的仓库 → Settings → Secrets and variables → Actions
点击 New repository secret
Name：建议用大写 + 下划线，如 MY_GH_PAT 或 COMPILER_PAT（随便起，但要记住）
Value：粘贴你的完整 PAT 值（ghp_xxxxxxxxxxxx...）
保存

GitHub Actions 中遇到“同名账户”（可能是指 GITHUB_TOKEN 的默认权限、或你的 Actions 运行在与私有仓库同名的用户名/组织下，但权限不足）导致 `git clone git@github.com:...`（SSH 协议）报 Permission denied (publickey) 的问题，这是非常常见的场景。

核心原因：  
- GitHub Actions 默认使用 `GITHUB_TOKEN`（HTTPS 协议），但你用了 git 协议（SSH），而 runner（虚拟机）没有预配置你的个人 SSH 私钥。  
- 私有仓库的访问需要显式授权（Deploy Key 或 PAT）。  
- “同名账户”可能指你的仓库和目标仓库属于同一个用户/组织，但 GITHUB_TOKEN 默认只对当前仓库有权限，对其他私有仓库（即使同组织）也需要额外配置。

### 推荐解决方案（最稳、最常用）：使用 Deploy Key + SSH（git 协议）

步骤 1: 生成一对专用的 SSH 密钥（不要用你本地的个人密钥）

本地电脑运行（或任何地方生成一次）：
```bash
ssh-keygen -t ed25519 -C "github-actions-clone-key" -f github-actions-key
# 直接回车，不要设置 passphrase（密码），否则 Actions 里很难处理
```

得到两个文件：
- `github-actions-key`（私钥，不要上传任何地方）
- `github-actions-key.pub`（公钥）

步骤 2: 把公钥添加到目标私有仓库的 Deploy keys

1. 打开目标私有仓库 → Settings → Deploy keys  
2. 点击 “Add deploy key”  
3. Title: 随便填（如 “Actions Clone Key”）  
4. Key: 粘贴 `github-actions-key.pub` 的全部内容  
5. 不要勾选 Allow write access（除非你需要 push）  
6. Add key

步骤 3: 把私钥存到运行 Actions 的仓库的 Secrets 里

1. 打开运行 workflow 的仓库（不是目标私有仓库） → Settings → Secrets and variables → Actions  
2. New repository secret  
   - Name: `SSH_PRIVATE_KEY`（随便起名，下面会用）  
   - Value: 打开 `github-actions-key` 文件，复制全部内容（包括 -----BEGIN OPENSSH PRIVATE KEY----- 到 END）

步骤 4: 在 workflow yaml 中配置 ssh-agent 并 clone

```yaml
name: Clone Private Repo and Run Script

on:
  push:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      # 第一步：checkout 当前仓库（可选，如果你有其他代码）
      - uses: actions/checkout@v4

      # 第二步：启动 ssh-agent 并加载私钥
      - name: Setup SSH Agent + Private Key
        uses: webfactory/ssh-agent@v0.9.0  # 推荐这个 action，很稳定
        with:
          ssh-private-key: ${{ secrets.SSH_PRIVATE_KEY }}

      # （可选）添加 known_hosts 避免首次连接提示（推荐）
      - name: Add GitHub to known_hosts
        run: ssh-keyscan github.com >> ~/.ssh/known_hosts

      # 第三步：clone 私有仓库（用 git@github.com:... 格式）
      - name: Clone Private Repository
        run: |
          git clone git@github.com:你的用户名/私有仓库名.git private-repo
          ls -la private-repo

      # 第四步：进入目录并执行 sh 脚本
      - name: Run Script
        run: |
          cd private-repo
          chmod +x your-script.sh
          ./your-script.sh
          # 或 bash your-script.sh
```

### 如果你更喜欢 HTTPS + PAT（不需要 SSH）

1. 生成 Personal Access Token (classic)：  
   Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token  
   选 `repo` 范围（至少 repo:private_repo 权限）

2. 存到 Secrets：名字如 `GH_PAT`

3. workflow 中：
```yaml
      - name: Clone with PAT
        run: |
          git clone https://username:${{ secrets.GH_PAT }}@github.com/你的用户名/私有仓库名.git private-repo
```

但你提到想用 git 协议（SSH），所以上面 Deploy Key + SSH 是最匹配的方案。

### 常见坑 & 调试

- Permission denied (publickey) 仍出现 → 检查 Deploy Key 是否正确添加到目标仓库（不是当前仓库）。
- SSH key 有 passphrase → Actions 会卡住，必须生成无密码的密钥。
- 同组织多个仓库 → Deploy Key 是每个仓库单独加的，不能跨仓库共享（除非用 GitHub App token，但更复杂）。
- 调试：在 workflow 加一步 `ssh -T git@github.com` 测试连接（会显示 Hi username! You've successfully authenticated...）。

这样就能顺利 clone 下来私有仓库，并执行里面的 sh 脚本了。
