- 20260202：元组（Tuple）： 元组是关系数据库中的基本单位，在二维表中对应一行记录。每个元组包含了一个实体的完整信息。例如，在学生表中，每个学生的完整信息（学号、姓名、年龄等）构成一个元组。；码（Key）： 码是能够唯一标识关系中元组的一个或多个属性的集合。码的主要作用是保证数据的唯一性和完整性。；数据库范式有3种：1NF(第一范式)：属性不可再分。
- 20260203：huadb多线程，除了主线程？；开启了哪些；科研速览│我院“测绘科学与技术”学科何立恒副教授团队在遥感顶刊《IEEE TGRS》发表重要研究成果.mhtml
- 20260204：Gap Lock和Next-key Lock的加锁（acquire）和释放（release）时机，以及典型使用场景，主要取决于 隔离级别、SQL语句类型和是否使用索引。1. 加锁（Locking）时机总结锁类型；主要出现在哪个隔离级别；什么时候加锁（典型场景）
- 20260205：经典多粒度锁协议（Multiple Granularity Locking）；意向锁（Intention Lock）不是 MySQL 独有的机制，它是一种经典的数据库并发控制技术，正式名称叫 Multiple Granularity Locking (MGL，多粒度锁) 中的一部分，早在20世纪70-80 年代的数据库理论论文中就已经被提出和广泛讨论。1. 意向锁的本质和通用目的（所有数据库都类似）在支持多粒度锁（database → table → page → row）的 DBMS 中，当事务想对细粒度资源（如某一行）加锁时，需要一种方式快速告诉别人：“我已经在表/页的更细粒度上加了锁/打算加锁”。没有意向锁 → 想加表级 X 锁时，必须扫描检查表里每一行/每一页有没有锁 → 效率极低；有意向锁 → 只需看表级有没有 IX/IS → 就能快速判断冲突 → 大幅提升性能
- 20260206：同研一，最近有一个需要魔改DuckDB的工作，读了一个月DuckDB的源码。个人感觉最好的阅读方式是先将数据库系统的通用部分理解清楚，即先自顶向下整体看一遍，运行一条sql 看调用堆栈，将整体pipeline（sql-> parser -> logical_plan -> optimizer -> physical_plan -> executor)搞清。再分模块去看局部细节（parser -> planner -> optimizer -> execution)，将每个模块基类和子类的调用关系画出来。最后去看DuckDB独有的部分（vector，sink and source, parallel, index, cardinality estimate）等等。后续会把对DuckDB的阅读笔记传到知乎上，希望和大家一起学习，共同进步。；链接：https://www.zhihu.com/question/629722028/answer/1900221646515730043；智谱glm大模型，出去了跟小卡拉米一样。国内疯狂收费59，69的。国外25/季
- 20260207：MySQL的最初版本（第一个公开版本）主要由以下几位核心开发人员在1994–1995年期间开发完成：；Michael "Monty" Widenius（最核心人物，常被称为“MySQL 之父”）：；他是MySQL代码的主要作者，几乎独自完成了服务器端95%以上的早期代码。开发从1994年正式开始，第一个版本于1995年5月23日发布。他用自己大女儿的名字“My” + SQL给数据库命名。
