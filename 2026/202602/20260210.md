# 嵌入式数据库比较（2026年主流选项）

| 项目                              | SQLite                          | H2                              | Apache Derby                    | DuckDB                          |
|-----------------------------------|---------------------------------|---------------------------------|---------------------------------|---------------------------------|
| 是否联网                      | 不联网（纯本地）                | 不联网（纯本地，可内存模式）    | 不联网（纯本地，可内存模式）    | 不联网（纯本地，可内存模式）    |
| 网络                          | 无（无服务器模式）              | 无（嵌入式为主，可少量网络服务器模式） | 无（嵌入式为主，有网络服务器模式） | 无（纯嵌入式，无服务器）        |
| 嵌入式                        | 是（最典型嵌入式）              | 是（Java 嵌入式首选之一）       | 是（Java 嵌入式）               | 是（现代嵌入式 OLAP）           |
| 是否支持 SQL                  | 是（丰富 SQL 方言）             | 是（标准 SQL + 部分扩展）       | 是（标准 SQL）                  | 是（PostgreSQL 兼容 SQL + 分析扩展） |
| 支持单机事务                  | 是                              | 是                              | 是                              | 是（单进程内）                  |

| 事务是否支持 ACID 属性        | 是（完整 ACID）                 | 是（完整 ACID）                 | 是（完整 ACID）                 | 是（单进程内完整 ACID）         |

| 并发模型                      | 多读单写（WAL 模式下多读）<br>锁 + MVCC-like（但偏锁） | 多版本 + 锁（MVStore）         | Strict 2PL + 锁                 | MVCC（多版本）<br>单写多读 + 并行查询 |
| 可串行化                      | 是（最高隔离级别 SERIALIZABLE）| 是（SERIALIZABLE）             | 是（SERIALIZABLE）              | 是（Serializable，默认最高）    |
| 隔离级别及其存在问题          | READ UNCOMMITTED / READ COMMITTED / REPEATABLE READ / SERIALIZABLE<br>READ COMMITTED 下可能不可重复读 | READ COMMITTED / SERIALIZABLE<br>默认 READ COMMITTED | READ COMMITTED / REPEATABLE READ / SERIALIZABLE<br>默认 READ COMMITTED | 主要 Serializable<br>无 READ COMMITTED（分析导向，少问题） |

| 读写锁 / 共享锁、排它锁       | 有共享锁（读）、排它锁（写）    | 有（但 MVStore 优化）          | 有（S / X / IS / IX / SIX）     | 无传统读写锁（MVCC 可见性判断） |
| 封锁协议                      | 部分 2PL                        | 接近 2PL                        | Strict 2PL                      | 无（纯 MVCC）                   |

| 乐观 MVCC                     | 部分（WAL + 版本，但偏悲观锁）  | 有（MVStore 多版本）           | 否（悲观锁为主）                | 是（核心是 MVCC + 乐观可见性）  |

## 说明与补充
- SQLite：最成熟、零配置、单文件，WAL 模式下并发读很好，但写仍单线程。
- H2：Java 生态友好，支持内存/文件/混合模式，常用于测试/原型。
- Apache Derby：完整企业级特性，但较重，已于2025年后维护减弱。
- DuckDB：列式 + 向量化执行，分析性能碾压其他，MVCC 实现优雅，读写不阻塞。

如需添加更多数据库（LMDB、RocksDB、SurrealDB embedded、libSQL 等）或调整维度，欢迎补充要求。

## 补充说明（2026年趋势）
- 传统 RDBMS：MySQL/MariaDB、PostgreSQL、SQL Server、Oracle 仍是主流，网络访问成熟，生态完善。
- 分布式 SQL 新星：CockroachDB（PostgreSQL 兼容 + 默认 Serializable）、TiDB（MySQL 兼容 + HTAP）、YugabyteDB（PostgreSQL 兼容 + 灵活一致性）专为云原生/全球分布设计，原生支持网络、多地域高可用。
- 隔离与并发：PostgreSQL 和分布式数据库 MVCC 更优雅（读不阻塞写）；MySQL/Oracle/SQL Server 更依赖锁。
- 迁移友好：TiDB → MySQL 生态；CockroachDB/YugabyteDB → PostgreSQL 生态。
