## 方案一：修改 Git 文件权限（推荐）

在 Windows PowerShell 项目根目录执行：

```
git update-index --chmod=+x gradlew
```

检查：

```
git ls-files --stage gradlew
```

正确结果应当以 `100755` 开头：

```
100755 xxxxxxxxxx 0 gradlew
```

如果是 `100644`，说明没有可执行权限。

然后提交：

```
git commit -m "fix: make gradlew executable"
git push
```

Git 会保存这个执行权限，GitHub Actions 在 Linux 上检出代码后即可执行 `./gradlew`。

## 方案二：GitHub Actions 中添加 chmod

如果不想修改 Git 文件权限，可以直接修改工作流：

```
name: Java 8 CI

on:
  push:
  pull_request:

jobs:
  build:
    runs-on: ubuntu-24.04

    steps:
      - uses: actions/checkout@v4

      - name: Set up JDK 8
        uses: actions/setup-java@v4
        with:
          java-version: '8'
          distribution: 'temurin'

      - name: Grant execute permission
        run: chmod +x gradlew

      - name: Build with Gradle
        run: |
          ./gradlew --version
          ./gradlew clean build
```

这两个命令都属于 Git 的底层命令（Plumbing Commands），主要用于操作和查看 Git 索引（Index，也叫暂存区 Staging Area）。

## 一、`git update-index --chmod=+x gradlew`

作用：修改 Git 索引中 `gradlew` 文件的可执行权限标记。

拆开解释：

| 部分             | 含义              |
| -------------- | --------------- |
| `git`          | Git 命令行程序       |
| `update-index` | 更新 Git 索引中的文件信息 |
| `--chmod=+x`   | 设置可执行权限标记       |
| `gradlew`      | 要修改的文件路径        |

例如：

```
git update-index --chmod=+x gradlew
```

Git 会将索引中的 `gradlew` 文件模式从：

```
100644
```

改为：

```
100755
```

两者的区别：

| Git 文件模式 | 含义                  |
| -------- | ------------------- |
| `100644` | 普通文件，不可执行           |
| `100755` | 普通文件，可执行            |
| `120000` | 符号链接（Symbolic Link） |
| `160000` | Git 子模块引用           |

注意：`git update-index --chmod=+x` 主要修改 Git 索引中的权限标记，不等同于 Linux 的 `chmod +x`，后者直接修改工作区文件的权限。

## 二、`git ls-files`

作用：列出 Git 索引中跟踪的文件。

例如：

```
git ls-files
```

输出：

```
.gitignore
build.gradle
gradlew
gradlew.bat
settings.gradle
src/main/java/Main.java
```

它与 `ls` 的区别：

| 命令                 | 查看对象                 |
| ------------------ | -------------------- |
| `ls`               | 工作目录中的文件             |
| `git ls-files`     | Git 索引中的文件           |
| `git status`       | 工作区、索引和 HEAD 之间的变更状态 |
| `git ls-tree HEAD` | 最近一次提交中的文件树          |

### `git ls-files --stage`

你之前使用的是：

```
git ls-files --stage gradlew
```

其中 `--stage` 表示输出索引中的详细信息，包括文件模式、对象 ID 和暂存阶段。

例如：

```
100755 abcdef1234567890... 0    gradlew
```

各字段含义：

| 字段          | 含义                 |
| ----------- | ------------------ |
| `100755`    | Git 文件模式           |
| `abcdef...` | Blob 对象 ID         |
| `0`         | 索引阶段（Stage 0，正常文件） |
| `gradlew`   | 文件路径               |

索引阶段还可能有 1、2、3，主要用于表示合并冲突中的不同版本。

## 三、Git Index、Working Tree、HEAD 的关系

在你的场景中，完整流程是：

```
# 1. 修改索引中的可执行权限
git update-index --chmod=+x gradlew

# 2. 查看索引中的权限
git ls-files --stage gradlew

# 3. 查看暂存的差异
git diff --cached --summary

# 4. 提交修改
git commit -m "fix: make gradlew executable"

# 5. 推送到 GitHub
git push
```

其中第三步可能显示：

```
mode change 100644 => 100755 gradlew
```

这说明 Git 已经记录了权限变化。

总结：

- `git update-index`：修改 Git 索引。
- `git ls-files`：查询 Git 索引。
- `git add`：把工作区文件内容或状态更新到索引。
- `git commit`：把索引中的快照写入 Git 仓库历史。

对于 Windows 开发、Linux GitHub Actions 构建的项目，理解 Git 的 `100644` 和 `100755` 文件模式尤其有用，因为 Windows 文件系统和 Linux 的可执行权限机制不同。
