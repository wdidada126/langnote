# 20260827

这些 `San` 后缀是 **Sanitizer（动态分析工具）** 的缩写，它们是编译器（如 GCC/Clang）内置的强大内存和并发错误检测工具。具体含义如下：

---

### 1. ASan（AddressSanitizer —— 地址消毒剂）
**作用**：检测内存访问错误。

它能捕获：
- **Use-after-free**（使用已释放的内存）
- **Heap buffer overflow**（堆缓冲区溢出）
- **Stack buffer overflow**（栈缓冲区溢出）
- **Global buffer overflow**（全局变量溢出）
- **Use-after-return**（使用已返回的栈内存）
- **Double-free**（重复释放）

**代价**：运行时性能下降约 **2倍**，内存占用增加约 **2-3倍**。

---

### 2. UBSan（UndefinedBehaviorSanitizer —— 未定义行为消毒剂）
**作用**：检测 C/C++ 中的未定义行为（UB）。

它能捕获：
- **整数溢出**（signed overflow）
- **除零错误**
- **空指针解引用**
- **类型双关（type punning）违规**
- **对齐错误**
- **违反 `noexcept` 规范**

**代价**：性能下降较小（通常 < 25%），内存开销可忽略。

---

### 3. TSan（ThreadSanitizer —— 线程消毒剂）
**作用**：检测多线程程序中的数据竞争（data race）。

它能捕获：
- **两个线程同时访问同一内存位置**
- **至少一个是写操作**
- **没有任何同步机制（如互斥锁）保护**

**代价**：运行时性能下降约 **5-15倍**，内存占用增加约 **5-10倍**。

### 🎯 你列出的 6 个 Target 组合解读

| Target | Debug/Release | Sanitizer 组合 | 适用场景 |
|:---|:---|:---|:---|
| **Release** | Release（优化开启） | **无** | 正式交付/性能测试 |
| **Debug** | Debug（符号+`-Og`） | **无** | 常规开发调试 |
| **RelASan** | Release（优化） | ASan + UBSan | 压测时检测内存/UBSan 错误 |
| **RelTSan** | Release（优化） | TSan | 压测时检测数据竞争 |
| **DebugASan** | Debug（符号） | ASan + UBSan | 开发阶段深度内存错误检测 |
| **DebugTSan** | Debug（符号） | TSan | 开发阶段排查线程问题 |

---

### ⚠️ 重要提示

1. **ASan 和 TSan 不能同时使用**：它们需要不同的编译器运行时支持，同时启用会导致链接冲突或运行时崩溃。因此你看到的组合都是 ASan 或 TSan 二选一。

2. **Release + Sanitizer 的价值**：启用优化（`-O2`/`-O3`）后，某些内存错误可能被编译器优化掩盖或改变表现，使用 RelASan/RelTSan 可以在接近生产环境的优化级别下检测问题（虽然栈回溯可能不如 Debug 清晰）。

3. **ASan 与 UBSan 常绑定**：它们可以协同工作，UBSan 捕获语义错误，ASan 捕获内存错误，两者互补。

---

### 📖 CMake 中的典型配置示例

```cmake
# ASan + UBSan
target_compile_options(your_target PRIVATE -fsanitize=address,undefined -g -O2)
target_link_options(your_target PRIVATE -fsanitize=address,undefined)

# TSan
target_compile_options(your_target PRIVATE -fsanitize=thread -g -O2)
target_link_options(your_target PRIVATE -fsanitize=thread)
```
