## 规范的本来意图

阿里规范里那条的本意是**消灭语义不明的裸值**,比如:

```java
// 反例:86400 是什么?没人知道
if (cache.get(key).getExpireTime() > 86400) { ... }
```

它的对象主要是"看不懂的数字",字符串字面量只是顺带被涵盖。而你的代码里每个字符串都有**自解释语义**:

| 字面量 | 语义 | 出现次数 |
|---|---|---|
| `"uploads"` | 默认保存目录 | 1 |
| `"dir"` | URL query 参数名,与调用方**外部协议约定** | 2(`.has` / `.get`) |
| `".."` | 路径穿越特征串 | 1 |
| `"/"` | 白名单字符 | 1 |

## 工程判断:该不该提常量

- **单次出现、语义自明的**(`"uploads"`、`".."`、`"/"`):提取常量收益极低,反而增加阅读跳转。这类在 C++ 里属于可接受的自解释字面量。
- **`"dir"` 有提的价值**:它是 API 契约的一部分,如果以后参数改名,`.has("dir")` 和 `.get("dir")` 必须**同步改**,常量能保证一处修改;而且它和外部调用方(前端/curl)共用,集中定义可以避免漂移。
- **真正的"魔法数"你已经处理了**:`kMaxUploadBytes = 10 * 1024 * 1024` 用了 `static constexpr`,这才是规范最关心的对象——数字必须提,字符串可提可不提。

## 补充:C++ 的实际情况

clang-tidy 的 `cppcoreguidelines-avoid-magic-numbers` 规则**默认只查数字,不查字符串**——说明 C++ 社区对字符串字面量的容忍度本来就高于裸数字。

这是一个非常经典且深刻的C++问题，你问的三个关键词（移动语义、左右值、所有权）正好是理解现代C++性能优化的核心。而 **`const string &` 被推荐**，正是因为它完美避开了这些复杂机制可能带来的性能陷阱。

为了让你彻底明白，我们从**历史演进**和**底层机制**两个维度来拆解：

---

### 1. 核心答案（一句话总结）
**`const string &` 更推荐，是因为它在“只读场景”下实现了“零拷贝”**。它既不转移所有权，也不强制拷贝，只是借用一个已存在的字符串的“别名”，因此无论传入的是左值还是右值，开销都是最小的（仅相当于拷贝一个指针）。

---

### 2. 深入拆解：左右值、移动语义与所有权

要理解为什么推荐它，得先搞清楚现代C++引入的那套复杂机制是为了解决什么。

#### ① 什么是 lvalue（左值）和 rvalue（右值）？
- **左值 (Lvalue)**：有内存地址、有名字的变量。**你可以取它的地址**。
  ```cpp
  std::string name = "Hello"; // name 是左值
  ```
- **右值 (Rvalue)**：临时对象、字面量。**没有名字，即将消亡**。
  ```cpp
  getString();                 // 返回的临时 string 是右值
  std::string("World");        // 匿名对象是右值
  ```

#### ② 什么是移动语义 (Move Semantics) 和所有权 (Ownership)？
- **所有权 (Ownership)**：指一块堆内存（比如字符串的字符数组）归谁管理。`std::string` 内部持有 `char*`，它拥有这块内存的释放权。
- **移动语义 (Move Semantics)**：C++11 引入的“窃取”机制。当遇到**右值（将亡值）**时，我们没必要费力拷贝它的内存，而是直接**把它的内存指针“偷”过来**，并把原对象的指针置空。这就是 `std::move` 的原理。

---

### 3. 对比不同传参方式的底层行为

现在，我们看编译器遇到这几种写法时，到底发生了什么：

| 函数签名 | 传入左值 (变量) | 传入右值 (临时对象) | 性能代价 |
| :--- | :--- | :--- | :--- |
| **`void f(string s)` (按值)** | **拷贝构造** (复制全部字符) | **移动构造** (只窃取指针，不复制字符) | 左值传入有巨额拷贝开销；右值传入开销小。 |
| **`void f(string&& s)` (右值引用)** | **编译报错** (左值无法绑定) | **无拷贝，无移动** (直接操作临时对象) | 只用于右值，但无法处理左值。 |
| **`void f(const string& s)` (常量左值引用)** | **无拷贝** (绑定别名) | **无拷贝** (临时对象生命周期被延长绑定) | **零拷贝**，无论传入什么都极快。 |

---

### 4. 为什么常量和引用（`const &`）这么厉害？

- **引用的本质**：底层就是指针，传递它只需要压入 8 个字节（64位系统）。不需要触碰 `string` 内部的堆内存。
- **常量的作用**：`const` 保证了不会修改实参，这让编译器敢于做两件事：
  1. 允许绑定到**临时对象（右值）**（如果不是 `const`，临时对象不能被修改，无法绑定）。
  2. 允许发生**隐式类型转换**（比如 `const char*` 隐式构建成 `string`）。

---

### 5. 既然 `const &` 这么好，为什么还要发明“移动语义”？

这是一个关键逻辑误区。**移动语义不是为了替代 `const &`，而是为了“接收并保存”数据。**

- **场景 A（只读）**：你只是看看这个字符串，验证一下长度，或者打印一下。
  👉 **必须用 `const string &`**。如果用按值传递，白白拷贝几兆内存，毫无意义。

- **场景 B（拿走/存储）**：你需要把这个字符串存到类的成员变量里（即**转移所有权**）。
  👉 **不用 `const &`**（因为它不能“拿走”内存，只能拷贝）。
  👉 **推荐用 `string s` (按值传递)**。这样传入左值会拷贝一次，传入右值（临时对象）会移动一次，没有多余浪费。这是《C++ Core Guidelines》推荐的最佳实践。

```cpp
// 推荐写法：按值传递 + 移动
class MyClass {
    std::string data_;
public:
    void setData(std::string s) { // 传左值=拷贝，传右值=移动
        data_ = std::move(s);     // 窃取到成员变量
    }
};
```

### 6. 最终结论图示

```text
函数是否需要修改/保存实参的内容？
│
├── 否（仅读取） ──> 必须用 const T& (零拷贝，最优)
│
└── 是（需要修改或存储）
    │
    ├── 需要修改实参本身 ──> 用 T& (非const引用)
    │
    └── 只需要内部副本，不碰实参
        │
        ├── 传右值较多 ──> 用 T (按值传递)，利用移动窃取
        │
        └── 传左值较多，且拷贝代价大 ──> const T& + 显式副本
```
