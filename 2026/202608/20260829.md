
## ⚠常见陷阱

### ❌ 错误：修改容器导致迭代器失效
```cpp
for (const auto& blog : r) {
    if (blog.isDeleted()) {
        r.erase(blog);  // ❌ 范围for中不能删除元素
    }
}
```

### 正确：需要修改容器时使用迭代器
```cpp
for (auto it = r.begin(); it != r.end(); ) {
    if (it->isDeleted()) {
        it = r.erase(it);  // 正确删除
    } else {
        ++it;
    }
}
```

### 或者使用 `std::erase_if` (C++20)
```cpp
std::erase_if(r, [](const Blog& blog) {
    return blog.isDeleted();
});
```



## 📝 最终推荐写法

根据最常见的"只读遍历"场景，推荐这样写：

- `&`：引用避免拷贝，提升性能

## 语法归属

### `using` 是 C++11 的关键字
```cpp
using query = odb::query<t_blog>;   // C++11 及以后
using result = odb::result<t_blog>; // C++11 及以后
```

### `typedef` 是 C++98 的传统语法
```cpp
typedef odb::query<t_blog> query;   // C++98 及以后
typedef odb::result<t_blog> result; // C++98 及以后
```

两者功能完全相同，都是类型别名（type alias）。



## 🔄 对比分析

| 特性 | `typedef` (C++98) | `using` (C++11) | 
||-|--|
| 基本类型别名 | 支持 | 支持 |
| 模板别名 | ❌ 不支持 | 支持（`template using`） |
| 可读性 | 较混乱（类型名在中间） | 更清晰（类型名在最后） |
| 标准 | C++98 | C++11+ |



## 为什么推荐 `using`？

### 1. 更符合阅读习惯
```cpp
// 传统 typedef：类型名在中间，易混淆
typedef std::vector<std::pair<int, std::string>> MyVector;

// 现代 using：类型名在最后，像赋值语句
using MyVector = std::vector<std::pair<int, std::string>>;
```

### 2. 支持模板别名（`typedef` 做不到）
```cpp
// ❌ typedef 无法定义模板别名
template<typename T>
typedef std::vector<T> MyVec;  // 编译错误！

// using 可以定义模板别名
template<typename T>
using MyVec = std::vector<T>;  // 正确！

MyVec<int> ints;  // 等价于 std::vector<int>
```

### 3. 可读性更强
```cpp
// 使用 using 时，类型名始终在 = 右边
using Query = odb::query<t_blog>;
using Result = odb::result<t_blog>;
using BlogList = std::list<Blog>;
```

## ODB 中的实际应用

你的代码使用 ODB（对象关系映射库），这两种写法都完全合法：

```cpp
// 方式1：C++98 风格
typedef odb::query<t_blog> query;
typedef odb::result<t_blog> result;

// 方式2：C++11 风格（推荐）
using query = odb::query<t_blog>;
using result = odb::result<t_blog>;

// 使用示例
query q("title LIKE '%C++%'");
result r = db.query<Blog>(q);

for (const auto& blog : r) {
    // 处理结果
}
```

## 最佳实践建议

### 项目中使用 `using` 的场景：
1. 现代 C++ 项目（C++11+）：全部使用 `using`
2. 需要模板别名：必须用 `using`
3. 提高可读性：优先用 `using`

### 何时保留 `typedef`：
1. 兼容 C++98 编译器（极少见）
2. 维护遗留代码（保持一致性）

## 标准引用

- C++11 标准: 7.1.3 `using` 声明引入类型别名
- C++98 标准: 7.1.3 `typedef` 定义类型别名

```cpp
// C++标准委员会推荐：优先使用 using
// 参考：C++ Core Guidelines T.43
```

## 总结

`using query = odb::query<t_blog>;` 是 C++11 的语法，ODB 只是使用了这个语法。如果编译器支持 C++11（几乎所有的现代编译器都支持），强烈推荐使用 `using` 替代 `typedef`，因为：
- 更清晰易读
- 支持模板别名
- 符合现代 C++ 编程风格
