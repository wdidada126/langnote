这句话的意思是：Docker 当前使用的防火墙后端是 iptables，这是 Linux 上标准的网络包过滤与 NAT 工具。

### 一、直白解释
- Firewall Backend: iptables → Docker 把 iptables 当作它的网络防火墙/网络规则管理工具。
- iptables：Linux 内核 netfilter 的用户态工具，用来写规则：放行/拒绝端口、做端口映射、转发、NAT 等。

### 二、Docker 用 iptables 干什么
1. 端口映射（-p）
   把宿主机端口（如 8080）转发到容器内端口（如 80），靠 iptables 的 DNAT 规则实现。
2. 容器网络隔离与互通
   - 自动创建自定义链：DOCKER、DOCKER-USER。
   - 在 filter 表的 FORWARD 链放行网桥（docker0）流量。
3. NAT 上网（容器访问外网）
   在 nat 表 POSTROUTING 做 MASQUERADE，让容器共享宿主机 IP 上网。

### 三、常见查看命令
```bash
# 查看 filter 表（放行/拒绝规则）
iptables -L -n

# 查看 nat 表（端口映射/上网）
iptables -t nat -L -n

# 只看 Docker 相关链
iptables -L DOCKER -n
iptables -L DOCKER-USER -n
```

### 四、简单结论
- iptables 是 Docker 在 Linux 上的默认防火墙/网络规则引擎。
- Docker 会自动维护它的规则，不要随便删/改 DOCKER 链，否则容器网络可能直接挂掉。
- 要加自己的防护规则，写在 DOCKER-USER 链（优先于 Docker 规则）。

# 核心结论（最重要）
1. 物理机 CentOS 部署

2. 你现在的 Dockerfile（容器化）
    这个 Nginx 只管前端 Vue，不管后端 Java。
    → 前端是前端容器，后端是后端容器，分家了！

# 为什么容器化要拆开？（工业界逻辑）
在 Docker / Kubernetes 微服务 架构下：

### 1. 职责分离
- 前端容器 (Nginx + Vue)：只负责页面显示
- 后端容器 (SpringBoot)：只负责接口逻辑
- 网关容器 (Gateway/Nginx)：专门负责统一入口、转发

### 2. 独立扩容、独立重启
- 前端改个页面，只重启前端容器，后端毫发无损
- 后端更新业务，只重启后端，前端不受影响
- 谁崩了不影响谁

### 3. 你之前的 Dockerfile 是“纯前端镜像”
```dockerfile
FROM nginx:alpine
# 只拷贝了前端 dist
COPY --from=builder /app/dist /usr/share/nginx/html
# 没有配置任何 /api 转发规则！
```
✅ 这个镜像纯粹、干净，就是个前端静态资源服务器。
❌ 它没有配置反向代理到 Java，所以不负责后端入口。

# 那请求 /api 接口怎么办？
物理机是 Nginx 转发
容器化/云原生是 另一个专门的网关转发：

架构变成了这样：
```
用户
  ↓
【网关层】(Spring Cloud Gateway / 独立 Nginx / SLB)
  ↓       ↓
前端容器   后端Java容器
```

网关统一接收所有请求，再分发给前后端容器。
前端容器里的 Nginx 只做静态服务。

# 如果你想让 Docker 里的 Nginx 和物理机一样
既管前端，又管后端（/api 转发），我现在就给你改好 Dockerfile + nginx.conf！

## 1. 修改 nginx.conf（关键！加 /api 转发）
```nginx
server {
    listen 80;
    server_name localhost;

    # 前端
    location / {
        root /usr/share/nginx/html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # 后端接口转发！(和物理机一模一样)
    location /api/ {
        # 注意：容器内访问后端地址
        proxy_pass http://host.docker.internal:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 2. 你的 Dockerfile 不用改！
因为它已经拷贝了 nginx.conf：
```dockerfile
COPY nginx.conf /etc/nginx/conf.d/default.conf
```

## 1. 自研分布式压测平台

## 2. 主流开源工具（进阶用法）

| 工具 | 特点 | 适用场景 |
| ---- | ---- | ---- |
| Gatling | Scala 编写，基于 Netty，代码化场景，实时图表 | 复杂业务场景、持续集成 |

## 3. 大厂核心压测方法论

- 全链路压测：从接入层（网关）→ 应用 → 数据库 → 中间件，整个链路一起压
- 流量染色：区分压测流量和真实流量，避免脏数据
- 容量规划：基于压测数据做容量评估和规划
- 混沌工程：在压测中注入故障，验证系统韧性
- 限流降级验证：刻意打到限流阈值，验证降级逻辑是否生效
