Lmctfy最初是为Google内部的容器化系统Borg设计的，后来成为了Google开源项目。Lmctfy提供了一组API和命令行工具，可以用于创建、启动、停止、删除和管理容器。Lmctfy支持CPU、内存、磁盘、网络等资源的隔离和限制，可以确保每个容器都拥有足够的资源，并避免容器之间的资源竞争和冲突。

1. 轻量级：Lmctfy是一个轻量级的容器管理工具，只包含必要的功能，可以快速启动和运行容器。
2. 资源隔离：Lmctfy支持CPU、内存、磁盘、网络等资源的隔离和限制，可以确保每个容器都拥有足够的资源，并避免容器之间的资源竞争和冲突。
3. 安全性：Lmctfy提供了一系列安全性功能，可以确保容器中运行的应用程序不会对主机系统造成安全漏洞。
4. 灵活性：Lmctfy提供了一组API和命令行工具，可以用于创建、启动、停止、删除和管理容器。用户可以根据自己的需要对容器进行定制和优化。

Dubbo 是一个基于 Java 的高性能 RPC 框架，它采用了 Netty 作为底层网络通信框架。在 Dubbo 中，Netty 被用来实现 Dubbo 的远程通信、序列化、反序列化、心跳检测等功能。

以下是 Dubbo 中常用的 Netty API：
1. Channel
Channel 是 Netty 的核心组件之一，它表示一个网络连接。Dubbo 通过 Channel 实现远程调用和消息传递。
2. ChannelHandler
ChannelHandler 是 Netty 的另一个核心组件，它用于处理网络事件。Dubbo 通过 ChannelHandler 实现数据编解码、心跳检测、异常处理等功能。
3. EventLoopGroup
EventLoopGroup 是 Netty 的线程池组件，它负责处理网络事件。Dubbo 通过 EventLoopGroup 管理网络连接和线程池。
4. Bootstrap
Bootstrap 是 Netty 的启动器，它用于启动网络应用程序。Dubbo 通过 Bootstrap 启动 Netty，并配置网络连接和事件处理器。
5. ByteBuf
ByteBuf 是 Netty 的数据容器，它用于存储网络数据。Dubbo 通过 ByteBuf 实现数据的读写和传输。
6. Codec
Codec 是 Netty 的编解码器，它用于将数据从字节流转换为对象，或将对象转换为字节流。Dubbo 通过 Codec 实现数据的序列化和反序列化。
7. HeartbeatHandler
HeartbeatHandler 是 Netty 的心跳检测组件，它用于检测网络连接的健康状态。Dubbo 通过 HeartbeatHandler 实现心跳检测和断线重连。
8. SslContext
SslContext 是 Netty 的安全组件，它用于实现 SSL/TLS 加密通信。Dubbo 通过 SslContext 实现网络数据的安全传输。
在 Dubbo 中，Netty 扮演了重要的角色，它为 Dubbo 提供了高效、可靠、安全的网络通信能力。如果您想深入了解 Dubbo 和 Netty 的实现原理和技术细节，可以查阅 Dubbo 和 Netty 的官方文档和 API 参考。

类加载机制
全盘负责，当一个类加载器负责加载某个Class时，该Class所依赖的和引用的其他Class也将由该类加载器负责载入，除非显示使用另外一个类加载器来载入
父类委托，先让父类加载器试图加载该类，只有在父类加载器无法加载该类时才尝试从自己的类路径中加载该类
缓存机制，缓存机制将会保证所有加载过的Class都会被缓存，当程序中需要使用某个Class时，类加载器先从缓存区寻找该Class，只有缓存区不存在，系统才会读取该类对应的二进制数据，并将其转换成Class对象，存入缓存区。这就是为什么修改了Class后，必须重启JVM，程序的修改才会生效

对象分配规则



对象优先分配在Eden区，如果Eden区没有足够的空间时，虚拟机执行一次Minor GC。
大对象直接进入老年代（大对象是指需要大量连续内存空间的对象）。这样做的目的是避免在Eden区和两个Survivor区之间发生大量的内存拷贝（新生代采用复制算法收集内存）。
长期存活的对象进入老年代。虚拟机为每个对象定义了一个年龄计数器，如果对象经过了1次Minor GC那么对象会进入Survivor区，之后每经过一次Minor GC那么对象的年龄加1，知道达到阀值对象进入老年区。
动态判断对象的年龄。如果Survivor区中相同年龄的所有对象大小的总和大于Survivor空间的一半，年龄大于或等于该年龄的对象可以直接进入老年代。
空间分配担保。每次进行Minor GC时，JVM会计算Survivor区移至老年区的对象的平均大小，如果这个值大于老年区的剩余值大小则进行一次Full GC，如果小于检查HandlePromotionFailure设置，如果true则只进行Monitor GC,如果false则进行Full GC。

日常工作中，汇编主要有两个用途，一是局部代码的汇编优化，二是debug时候解决崩溃和性能问题。
这种要求，都没必要把汇编每个细节都掌握，除了个别特殊岗位，没有必要学习怎么完全用汇编开发App，只要会写嵌入式汇编，能看到基本的汇编代码就够了。
对于X86汇编，能了解十几个指令的用途就够基本看懂大部分代码了，比如 MOV JMP(以及其它系列跳转) PUSH POP CALL RET ADD XOR LEA 等。
要做优化需要学习 SIMD指令，因为普通汇编指令能带来的性能提升很有限了，你自己写的汇编未必比编译器生成的好，只有SIMD指令才有巨大提升空间。
SIMD本身不难，难度在算法上。
