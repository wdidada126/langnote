外键约束对子表的含义: 

如果在父表中找不到候选键,则不允许在子表上进行insert/update 

 

外键约束对父表的含义: 

在父表上进行update/delete以更新或删除在子表中有一条或多条对应匹配行的候选键时,父表的行为取决于：在定义子表的外键时指定的on update/on delete子句, InnoDB支持５种方式, 分列如下 ：

 

cascade方式 

在父表上update/delete记录时，同步update/delete掉子表的匹配记录 

On delete cascade从mysql3.23.50开始可用; on update cascade从mysql4.0.8开始可用 

 

set null方式 

在父表上update/delete记录时，将子表上匹配记录的列设为null 

要注意子表的外键列不能为not null 

On delete set null从mysql3.23.50开始可用; on update set null从mysql4.0.8开始可用 

 

No action方式 

如果子表中有匹配的记录,则不允许对父表对应候选键进行update/delete操作 

这个是ANSI SQL-92标准,从mysql4.0.8开始支持 

 

Restrict方式 

同no action, 都是立即检查外键约束

纯扯淡，新产出模型论文你不看懂，你敢说你会调参数？新的SOTA落地工业界有那么容易？不得需要实验吗？sparkflink你不会能行？shellpython不会能行？任务部署，特征生产那个不需要人力，你可别瞎说了。反而对比发文章，改改模型结构，做几把实验，效果捡好的说，都是实验室走出来的，几斤几两自己掂量掂量再出来指点江山吧。

还是有差别的，做算法不止做机器学习和调参数，要解决瓶颈问题还是很心累的，功能性能优化和算法优化都要考虑。这也是为什么优秀的算法工程师很难招的原因。举个例子，和做开发最大的区别大概是，跟公司的T6安卓前端开会，死活说某个功能做不了，然后我花了10分钟想出了算法，写了个wiki，把测试方法都写出来了，让他们照着实现。

答主可能没有在美国工作过。美国做算法的（就是我们大多数人概念里的那种算法岗）有的是，亚马逊叫Applied/Research Scientist，苹果Siri的叫Machine Learning Engineer。两家公司我都干过。其中那个Applied Scientist偏工程落地，也就是被你鄙视的把现成算法拿来用，调调参数，加几个layer。Research偏研究一点，实际上Applied Scientist要求一点都不低，既要有相当好的工程能力，也要有很好的科研能力，招人的要求比SDE只高不低。除了coding面试，算法面试以外，还要做一个presentation，展示自己过去的研究经历。苹果的MLE类似。但是我们的MLE具体到每个人工作不太一样，有的人偏研究，有的人偏工程，有的人都干。前面有个回答很好，答主可能不太理解算法落地的意义。首先一个优秀的算法工程师你需要发现问题，发现需求（这本身就是工程的一部分），然后去海量的paper里选出你需要的，这对科研能力也有很高要求。没有接受过系统科研训练，连paper都读不懂。此外，每一个公司，每一个团队，甚至每一个小课题都有自己的要求和局限性。例如Siri不光要强调准确性，还极其强调低时延，而且我们的用户隐私政策十分严格，这些都是应用落地过程中必须考虑的问题，不是说随便拿一个看上去很fancy的paper随便修修改改就能用的，这些都考验着一个人的工程能力。一个优秀的算法工程师，工程能力一点都不弱。
