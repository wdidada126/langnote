Verifying vMVCC, a high-performance transaction library using multi-version concurrency control
Yun-Sheng Chang, Ralf Jung, Upamanyu Sharma, Joseph Tassarotti, M. Frans Kaashoek, and Nickolai Zeldovich
多版本并发控制（MVCC）是一种广泛使用的，复杂的方法来处理并发事务。vMVCC是第一个基于MVCC的事务库，它附带了机器检查的正确性证明，为客户端提供了一个保证，即它将正确处理所有事务，尽管设计和实现复杂，否则可能容易出错。vMVCC在Go中实现，将数据存储在内存中，并使用多种优化（例如基于RDTSC的时间戳）来实现高性能（对于YCSB和TPC-C工作负载，最先进的内存数据库筒仓的吞吐量为25-96%）。
背景
应用程序使用数据库系统在磁盘上持久地存储数据，以及确保事务在发生并发和崩溃的情况下原子执行。这简化了应用程序开发，因为应用程序开发人员不再需要担心并发错误或崩溃后遗留的部分状态。在这个模型中，应用程序的正确性和性能关键取决于数据库系统正确并高效地处理所有可能的情况。在一个数据库系统中为许多并发事务实现正确性和高性能是一个挑战。在这种情况下，多版本并发控制（MVCC）是一种广泛使用的提高性能的技术，其中数据库不仅存储数据项的最新版本，还存储过去的版本。存储过去的版本允许数据库系统执行添加新版本的写入，同时还能够使用旧版本来服务串行顺序中更早的事务的读取。
MVCC需要复杂的数据结构实现，以便有效地跟踪每个元组的多个版本、实现垃圾收集（GC）等。同时，实现还必须采用一些低级优化技术以获得高性能。因此，它极有可能存在bug，导致不正确或不可序列化的执行。这些bug可能代价高昂：它们可能导致数据丢失或损坏，同时，应用开发者可能难以追踪数据库系统中的错误。
本文提出了一个高性能的基于MVCC的事务库vMVCC，并用形式化方法证明了其正确性。vMVCC解决了数据库中事务层面临的核心技术挑战，可用于构建事务应用程序。
挑战
验证vMVCC需要解决几个难题：
形式化地给出一个规范，以简洁的方式表达MVCC事务提供的保证。
开发证明技术，以证明MVCC在并发工作负载下实现了一个串行化的执行顺序。
形式化地解释使用低级优化技术，例如分片数据结构，使用类似RDTSC的指令访问CPU时间戳计数器等。
vMVCC中解决的关键技术挑战在于，如何证明MVCC的线性化点（linearization point，即事务开始对应的时间戳）发生在事务主体运行之前。因为在线性化点处，事务尚未执行，不知道事务将写入什么数据或者它将提交还是中止。
设计
vMVCC通过采用预言变量（prophecy variables）来解决这个挑战。我们使用预言变量允许证明推测性地预测事务将要修改的状态以及它是否会提交。这转化为考虑每个可能的预测的证明，允许vMVCC在线性化点相应地更新抽象状态。当事务即将提交时，证明可以检查预测是否正确，并且或者停止进一步考虑不正确的预测，或者继续正确的预测。vMVCC并不是第一个开发或使用预言变量的——许多早期的框架开发了对预言变量的支持，并证明了它们是一种可靠的证明技术——但它是第一个证明基于MVCC的事务正确性的。
vMVCC的关键技术贡献在于：
演示如何使用预言变量对线性化点先于事务主体执行的事务进行形式化推理。该验证技术适用于使用MVCC的任何系统。
vMVCC本身是第一个验证的MVCC事务库。vMVCC提供了一个高保证和高性能的实现，并且可以用作独立于验证的Go库。
vMVCC包括其他几个技术贡献，包括使用RDTSC计算严格递增事务ID的验证算法，以及使用逻辑原子性的事务库接口的精确规范。
性能分析
本文比较silo（一种未被验证的MVCC事务实现）和vMVCC的性能差距，来证明vMVCC的竞争力。实验基于TPC-C，使用32个warehouse。实验结果（下图）发现，导致vMVCC性能下降的原因有两个：频繁的内存分配、vMVCC对范围扫描支持差。在这两方面压力较小时，vMVCC具有接近silo的性能，因此很具有竞争力。
另外，文中其余实验表明，vMVCC内集成的低级优化在开启后有效地提升了吞吐；并且vMVCC在高负载工作环境下表现出良好的可扩展性。

两阶段锁：S2PL和SS2PL

严格两阶段锁协议（strict 2PL，S2PL）
强两阶段锁协议（strong strict 2PL/rigorous 2PL，SS2PL）
使用锁机制的数据库系统，要么使用严格两阶段封锁协议，要么使用强两阶段封锁协议。

严格两段锁协议是一种常见的并发控制方法，用于控制并发数据访问的正确性。 该协议有两个阶段，即“加锁”阶段和“释放锁”阶段。 在加锁阶段中，事务需要按照严格的顺序获取锁，即如果一个事务已经持有某个锁，其他事务就不能再获取该锁，直到该事务释放该锁。

强两阶段锁协议（Strong Two-Phase Locking Protocol）是一种并发控制协议，用于确保数据库事务的隔离性和一致性。它是在数据库管理系统中广泛使用的一种锁定协议。

该协议分为两个阶段：增长（Growing）阶段和收缩（Shrinking）阶段。在增长阶段，事务获取所需的锁，并且在完成操作之前保持这些锁。在收缩阶段，事务释放已经持有的锁。
强两阶段锁协议遵循以下规则：
1. 增长阶段规则：
   - 事务在需要访问某个数据项之前，必须先获取该数据项的共享锁（读锁）或独占锁（写锁）。
   - 如果事务持有一个数据项的写锁，则其他事务不能同时获取该数据项的任何锁。这确保了数据项的独占访问。
   - 如果事务持有一个数据项的读锁，则其他事务可以同时获取该数据项的读锁。这允许多个事务并发地读取同一数据项。
2. 收缩阶段规则：
   - 事务在完成对数据项的操作后，必须释放所持有的所有锁。
   - 事务释放锁之后，其他事务才能获取这些锁继续操作。

强两阶段锁协议的目标是保证串行等价性（Serializability）。它确保事务之间的并发操作不会导致数据不一致或冲突。通过在事务执行期间对数据项进行适当的锁定和释放，该协议可以保证事务的隔离性，防止数据丢失、不一致或脏读等并发问题。
然而，需要注意的是，强两阶段锁协议可能导致死锁（Deadlock）的发生。死锁是指两个或多个事务相互等待对方所持有的资源而无法继续执行的情况。为了避免死锁，通常需要实施死锁检测和解决机制，比如超时机制或死锁检测算法。
总之，强两阶段锁协议是一种常见的并发控制协议，用于确保数据库事务的隔离性和一致性。它通过合理的锁定和释放策略，保证事务之间的并发操作不会产生数据一致性问题，并为数据库系统提供了高度的并发性和可靠性。

两段锁协议 2pc 3pc
百度百科
两段锁协议是指每个事务的执行可以分为两个阶段：生长阶段（加锁阶段）和衰退阶段（解锁阶段）。
加锁阶段：在该阶段可以进行加锁操作。在对任何数据进行读操作之前要申请并获得S锁，在进行写操作之前要申请并获得X锁。加锁不成功，则事务进入等待状态，直到加锁成功才继续执行。
解锁阶段：当事务释放了一个封锁以后，事务进入解锁阶段，在该阶段只能进行解锁操作不能再进行加锁操作。
两段封锁法可以这样来实现：事务开始后就处于加锁阶段，一直到执行ROLLBACK和COMMIT之前都是加锁阶段。ROLLBACK和COMMIT使事务进入解锁阶段，即在ROLLBACK和COMMIT模块中DBMS释放所有封锁。
1. 在对任何数据进行读、写操作之前，要申请并获得对该数据的封锁。
2. 每个事务中，所有的封锁请求先于所有的解锁请求。
例如事务T1遵守两段锁协议，其封锁序列是：
Lock A, Read A, A:=A+100, Write A, Lock B, Unlock A, Read B, Unlock B, Commit;
可以证明，若并发执行的所有事务均遵守两段锁协议，则对这些事务的任何并发调度策略都是可串行化的。
另外要注意两段锁协议和防止死锁的一次封锁法的异同之处。一次封锁法要求每个事务必须一次将所有要使用的数据全部加锁，否则就不能继续执行，因此一次封锁法遵守两段锁协议；但是两段锁协议并不要求事务必须一次将所有要使用的数据全部加锁，因此遵守两段锁协议的事务可能发生死锁。
