# serde

补充说明为什么 serde 如此重要：serde 可以直接将 Rust 语言中定义的静态的类型（struct、enum）直接与 JSON/YAML/TOML 等格式的配置文件中的结构相对应。如果没有 serde，反序列化时你需要将对应格式的文件/文本先转换为动态的类型，再尝试从中获取自己需要的字段（并手动做大量的 error handling）并验证配置文件的是否合法，序列化也是同理；而有了serde，配置文件中的必有字段、可选字段及它们的类型都会被严格规定，反序列化时不符合规则的配置文件将会无法解析，序列化时由于直接使用了静态的类型也不用担心生成的文件不符合要求。而做到这一切无需复杂的配置，只需要使用者实现两个trait就能做到，甚至大部分时候可以直接写一行 derive。

C++26 可以实现 Rust serde 效果，但生产中 protobuf cpp 这坨还是得吃，希望 2030 年前能用上具有全面统治力的静态反射序列化库吧。不过有一说一，C++ 想精确实现 Rust trait 的效果是相当费劲，直接阻碍了我从 Rust 往 C++ 搬点东西。简单来说，Rust trait 是基于名义的非侵入式静态多态，同时一套语法直接兼容非侵入式动态多态。如果我们想把一个 Rust 多态设计复制到 C++ 来用，有哪些要求和选择？第一，“非侵入式”禁用了所有基于成员函数的设计，包括成员函数定制、CRTP、虚函数等，因为不能修改原类型定义。但这样一来也没法通过点符号调用扩展方法了。更大的问题是不用友元没法访问私有成员，也许静态反射能绕过。第二，“静态”禁用了自定义虚表设计，包括 metaclass、proxy 等。这里或许有某种保证去虚化的方法，但搓起来也没那么容易。第三，“基于名义”不同于结构化类型、鸭子类型。类型的结构匹配接口，不代表语义匹配接口。当不同接口有同签名方法时，必须通过 type tag、模板特化等方式来区分，让类型选择加入接口。还有不要占用全局自定义点，允许无任何歧义的调用。说到底这是 C++ 不是 TypeScript，尽管两者都以类型体操著称。第四，静态接口定义同时兼容动态多态，不用说了，没有这个语法，只能用自定义虚表模拟，或者未来的静态反射。如果放弃非侵入式的话，以虚函数定义再静态调用甚至是最方便的方案。第五，接口方法要能以适当的方式分组，支持 required 方法和 default 方法，默认方法要能被具体实现覆盖，未实现的方法要能提前报错，而不是调用时、链接时才报错。更关键的是，不要让我每次都得写一大堆模板和 type check。函数重载、模版特化、CRTP、虚函数、ADL、CPO、tag_invoke、成员函数定制、proxy、静态反射等，这么多机制调查一圈下来没有能精确复制 Rust trait 所有效果的。就算能模拟个大概，也需要写很多模板，或者当宏孩儿，都要牺牲接口定义的可读性。万众期待的静态反射也有一个偏特化歧义的问题，不知道解决了没。[1] [2] [3] 叠甲：以上结论出自网络参考资料和 GPT5、Grok、豆包、DeepSeek、Kimi 等语言律师的讨论，我本人并不精通 C++。这里只是谈我在精确复制设计时遇到的一些麻烦，正常该用啥还是用啥。如果各位读者有符合所有要求的解决方案，或者最新的语言提案进展，也欢迎探讨，这样能跨语言来回搬运一些设计也是不错的。
