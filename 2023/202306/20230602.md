spel ognl两个表达式的区别

SpEL（Spring Expression Language）和OGNL（Object-Graph Navigation Language）都是用于在Java应用程序中进行表达式求值和访问对象属性的表达式语言。它们具有一些相似的特性，但也有一些区别。
总的来说，SpEL和OGNL在表达能力、语法和使用场景上有一些差异，选择使用哪个表达式语言取决于具体的需求和所使用的框架。对于Spring项目，SpEL是首选的表达式语言，而对于其他项目，OGNL也是一个不错的选择。

CglibAopProxy
CglibAopProxy 是 Spring 使用 CGLIB 创建 AOP 代理的核心类。主要功能是:

- 生成具体类的子类来作为代理
- 代理方法调用时,环绕 advised 方法调用

注:默认情况下,Spring 采用 CglibAopProxy 来生成 AOP 代理。

主要的类和方法:

1. CglibAopProxy 继承自 AbstractAopProxy,实现 AopProxy 接口
定义了构造函数和 getProxy() 方法。
```java
public CglibAopProxy(AdvisedSupport config) {
    // ... 
}
public Object getProxy(@SuppressWarnings("rawtypes") ClassLoader classLoader) {   
    // ...
}
```
2. 获取代理对象时,首先生成被代理类的子类:
```java
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(classBeing proxied);
enhancer.setCallbackFilter(callbacksFilter);
enhancer.setCallbacks(callbacks);  
enhancer.setCallback(new MethodInterceptor() {
    // ...
});
// 生成 proxy class 的实例
return enhancer.create();
```
3. 调用代理方法时,会执行 MethodInterceptor 的 intercept()方法,拦截并处理方法调用。
```java
public Object intercept(Object obj, Method method, Object[] args, 
        MethodProxy proxy) throws Throwable {
 
    Object retVal;
    
    // 执行 advised 方法前的逻辑  
    before(method, args);
    
    try {
        // 调用原始方法   
        retVal =  method.invoke(advised, args);
    } catch (Exception e) {
       // 处理异常
    }
    
    // 执行 advised 方法后的逻辑
    after(method, args, retVal);
    
    return retVal; 
}
```
4. MethodInterceptor 中调用了 Advice 的 before、after 等方法,从而实现 AOP 功能。
