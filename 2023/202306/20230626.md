国内专注流程引擎乃至BPM平台研发和应用的企业还是很多的，根据T媒体年初发布的《2019年BPM行业洞察报告》显示，Java领域广州天翎、炎黄盈动、.Net领域深圳奥哲、上海易正都是专注行业近20年的老牌劲旅，他们在设计理念和功能擅长上各局特色但是都已经打磨的非常成熟，比如天翎主打的就是擅长中国式复杂业务流程处理，炎黄主打流程pass模式，奥哲则推出了针对中小企业的氚云。列举上述厂商的时候为什么不多列举其他的呢？因为其他大多数厂商都是基于activiti进行改造，这些在各家的产品介绍或者产品测试页面都可以直接看出，我想大概是有这么几个原因，一方面流程引擎是业务管理系统的核心大脑，没有十年或更多的时间积累根本无法形成自主研发的技术突破；二方面是商业化竞争激烈的情况下在前人的基础上向前比自己埋头苦干可能少走弯路；三方面就是在外企在大型集团企业信息化建设仍占据主导地位的情况下activiti的规范性和事实占比仍有大量受众。当然这是技术和商业妥协的结果，每家企业面临的情况不同，我就不做过多评价了。jbpm、Activiti5的优点是规范！但这个规范更多的是对技术人员而言，比如我的系统流程引擎用了activiti，换新人的时候找同样做过activiti的就行，但国外流程引擎最大的问题就是水土不服！不服体现在两个层面：一是国内外对流程的认知和管控相差巨大，比如国外是没有回退一说的，但是国内甲方老大是不管这些的，单人办理、多人顺序、多人并行、抢占式办理、内部循环、人工合并，主办加签、会办加签、补签意 见、异步提交、指定回退、自由指派、节点排序、节点互斥、子流程单实例.....国外压根没这些概念，那流程引擎的设计也就不会考虑这些场景和问题，用起来当然水土不服啦！二是国外流程引擎在技术上不思进取，比如activiti仍然要借助Eclipse等插件，仍然要在英文页面操作，仍然要写大量代码，但国内流程引擎基本上可视化拖拉拽为主了，全中文操作界面，真香。

在 SQL 中，当你需要同时更新多个字段时，可以使用逗号 (",") 来分隔每个字段的更新操作，而不需要使用 "AND" 进行拼接。每个字段的更新操作可以单独指定，无需通过 "AND" 连接。
例如，更新表中的两个字段可以使用以下语法：
```sql
UPDATE 表名
SET 字段1 = 值1, 字段2 = 值2
WHERE 条件;
```
在上述语句中，字段1和字段2分别对应要更新的字段，值1和值2分别是相应字段要更新的值。条件部分是可选的，用于指定更新的行范围。
需要注意的是，使用逗号分隔多个字段的更新操作时，每个字段的更新操作是独立的，它们之间没有逻辑关系。如果你需要同时满足多个条件才进行更新，那么你可以使用 "AND" 连接多个条件表达式。
总结起来，对于多个字段的更新操作，使用逗号分隔各个字段的更新操作即可，而不需要使用 "AND" 进行拼接。
