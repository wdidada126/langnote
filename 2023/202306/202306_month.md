spring security，登录之后用户登录信息保存在服务端还是哪儿？
在 Spring Security 中，登录成功后的用户信息通常保存在服务端的会话（Session）中。默认情况下，Spring Security 使用基于会话的认证方式来管理用户的登录状态。

在用户成功登录后，Spring Security 会为用户创建一个会话，并将用户的身份信息保存在会话中，通常是在服务器端的内存或分布式缓存中。会话的具体实现可以通过配置来指定，常见的实现方式包括使用 Servlet 容器的 HttpSession、使用 Redis 或 Memcached 等分布式缓存。
通过会话的方式，Spring Security 可以在后续的请求中验证用户的身份信息，以及对用户进行授权和访问控制。
需要注意的是，会话的保存和管理是由 Spring Security 自动处理的，开发者无需直接操作或干预会话的创建和管理过程。Spring Security 会负责在用户登录后将用户的身份信息与会话关联起来，并在需要时进行身份验证和授权检查。
如果您有特定的需求或要使用自定义的用户信息存储方式，可以通过实现 Spring Security 的接口来自定义认证和授权逻辑，例如实现 UserDetails 接口和 UserDetailsService 接口来自定义用户信息的获取和存储方式。

总结起来，Spring Security 的默认行为是将用户登录信息保存在服务端的会话中，但您可以根据需求进行自定义。

在 Spring Security 中，判断用户已经登录不需要再次登录可以通过会话管理来实现。具体来说，可以使用 Spring Security 提供的功能来检查用户的会话状态，并根据会话状态判断用户是否已经登录。
在默认情况下，Spring Security 使用基于会话的认证方式，当用户成功登录后，会为用户创建一个会话，并将用户的身份信息保存在会话中。在后续的请求中，可以通过检查会话状态来判断用户是否已经登录。
有几种常见的方式可以实现会话状态的检查：
1. 使用 Spring Security 的 `SecurityContextHolder` 类：可以通过 `SecurityContextHolder.getContext().getAuthentication()` 方法获取当前用户的认证对象 `Authentication`。如果该对象不为 `null`，则表示用户已经登录。
2. 使用 Spring Security 的 `@AuthenticationPrincipal` 注解：可以在方法参数上使用 `@AuthenticationPrincipal` 注解，Spring Security 会将当前用户的认证对象注入到该参数中。如果注入的对象不为 `null`，则表示用户已经登录。
3. 使用 Spring Security 的表达式语言：可以在页面模板或方法注解中使用 Spring Security 的表达式语言，例如 `isAuthenticated()` 表达式，来判断用户是否已经登录。
需要注意的是，以上方式都是基于会话管理来判断用户是否已经登录。如果会话失效或过期，用户可能需要重新进行登录。
另外，如果您需要实现更高级的单点登录（Single Sign-On）功能，可以考虑使用 Spring Security 提供的其他机制，如基于 Token 的认证方式（如 JWT）或集成第三方身份验证服务（如 OAuth）来实现跨系统的登录状态共享。这些方式可以实现用户在多个系统中的无缝登录体验。
