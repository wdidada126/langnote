RequestCondition 在 Spring MVC 中主要用于映射请求与处理方法的匹配过程。

其主要作用有:

1. 封装请求的相关条件信息,如请求方法、请求参数等。不同的 RequestCondition 实现类封装不同的条件。

2. 用于请求映射的匹配过程。在处理一个请求时,通过 RequestCondition 的匹配规则来找出最佳匹配的处理方法。

3. 支持条件的组合与排序。多个 RequestCondition 可以通过组合形成更复杂的条件,并且支持排序来确定条件优先级。

4. 提供匹配度的比较。在匹配处理方法时,通过比较不同请求条件的匹配度来确定最佳匹配。

5. 支持自定义的请求条件。可以通过实现 RequestCondition 接口来定义自定义的条件判断逻辑。

主要的实现类有:

- ParamsRequestCondition:匹配请求参数
- HeadersRequestCondition:匹配请求头
- ConsumesRequestCondition:匹配请求内容类型
- PatternsRequestCondition:匹配 URL 模式

等等。

这些条件构成了 Spring MVC 的请求映射体系,是 Web 应用映射请求与方法的重要基础。

org.springframework.web.util.UrlPathHelper#getLookupPathForRequest这个方法的作用是将请求转化为用于lookup的path。

主要的处理逻辑是:

1. 从请求(HttpServletRequest)中获取请求URI。

2. 如果设置了removeSemicolonContent属性为true,会删除请求URI中的分号内容。

3. 如果设置了urlDecode属性为true,会对请求URI进行decode操作。

4. 删除任何末尾的斜杠,除非设置了removeTrailingSlashMatch属性为false。

5. 预处理路径,比如转换为小写等。

6. 返回最终得到的lookup path。

这样做的目的是将原始请求根据配置要求进行转换,得到一个标准化的path字符串,用于后续的lookup操作,比如用来从Map中查找handler等。

它通过配置属性来控制具体的转换逻辑,以支持不同的lookup需求。

在Spring MVC中,org.springframework.web.servlet.mvc.condition这个包主要包含一些请求映射条件相关的接口和类,其主要作用:
1. 提供基于特定条件来匹配请求映射的功能。
2. 主要包含两类接口:Conditional接口和RequestCondition接口。
3. Conditional接口用来判断是否匹配。RequestCondition接口用来抽象请求条件。
4. Spring MVC使用它们实现基于请求方法、请求参数等条件的请求映射。
5. 如GET、HEAD使用不同方法条件,请求参数使用ParamsRequestCondition。
6. 我们也可以实现自己的条件来控制请求映射。

典型用法:

```java
@Controller
@MyRequestMapping // 自定义条件
public class MyController {

  @RequestMapping
  public void handler() {
    // ...
  }

}
```

注解驱动会根据MyRequestMapping条件来控制对此controller的请求是否映射。

总之,该包提供自定义请求条件映射的强大支持。

@MyRequestMapping这个注解不是Spring MVC内置的,它需要自行定义实现。具体可以这么做:

1. 定义一个@MyRequestMapping注解:

```java
@Target({ElementType.TYPE, ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Mapping
public @interface MyRequestMapping {
  
  // 定义属性
  String name() default "";

}
```

2. 实现一个MyRequestCondition,实现匹配逻辑:

```java 
public class MyRequestCondition implements RequestCondition<MyRequestCondition> {

  // 匹配逻辑
  public boolean matches(HttpServletRequest request) {
    // ...
  }

}
```

3. 实现一个MyRequestMappingHandlerMapping,注册MyRequestCondition:

```java
public class MyHandlerMapping extends RequestMappingHandlerMapping {

  protected RequestCondition<?> getCustomCondition(MyRequestMapping requestMapping) {
    return new MyRequestCondition(); 
  }

} 
```

4. 在配置类中注册MyHandlerMapping

```java
@Configuration
public class WebConfig {

  @Bean
  public MyHandlerMapping myHandlerMapping() {
    return new MyHandlerMapping();
  }

}
```

这样@MyRequestMapping注解就可以被识别并使用了。

在Spring MVC的org.springframework.web.servlet.mvc.condition包中,Conditional接口和RequestCondition接口的作用如下:

1. Conditional接口:

- 该接口定义了一个matches()方法,用于判断当前请求是否满足指定的条件。

- 通常与@Conditional注解配合使用,如类级别的@Conditional将判断所有方法。

- 实现该接口的条件类可以灵活控制请求映射。

2. RequestCondition接口:

- 该接口定义了与请求条件匹配相关的几个方法。

- 如getMatchingCondition等方法,用来判断请求是否满足条件。

- 它代表一个可与请求进行匹配的条件,如请求方法、参数等。

- 继承了该接口的条件才能与处理方法映射。

3. 典型实现:

- ParamsRequestCondition:匹配请求参数的条件。

- PatternsRequestCondition:匹配请求路径的条件。

- 我们也可以自定义条件实现特定的匹配逻辑。

4. 用法示例:

```java
@MyConditional 
@Controller
public class MyController {

  @GetMapping
  public void handler() {
    // 方法映射要满足MyConditional
  }

}
```

综上,两者结合可以实现灵活的自定义请求映射条件。

@ConditionalOnClass 注解用于在类路径上存在指定的类时才实例化当前 bean。

当使用 @ConditionalOnClass 注解时，Spring 会在初始化 bean 之前检查类路径上是否存在指定的类。如果存在，则会实例化当前 bean；如果不存在，则不会实例化当前 bean。

@ConditionalOnClass 注解的参数可以是类名或类的完全限定名。例如，以下代码表示当类路径上存在 `org.springframework.web.servlet.DispatcherServlet` 类时，才会实例化当前 bean：

```
@ConditionalOnClass("org.springframework.web.servlet.DispatcherServlet")
public class MyBean {

}
```

@ConditionalOnClass 注解可以与其他条件注解一起使用，以进一步限制 bean 的实例化条件。例如，以下代码表示当类路径上存在 `org.springframework.web.servlet.DispatcherServlet` 类，并且 `spring-webmvc.jar` 文件在类路径上时，才会实例化当前 bean：

```
@ConditionalOnClass("org.springframework.web.servlet.DispatcherServlet")
@ConditionalOnProperty("spring-webmvc.jar")
public class MyBean {

}
```

Spring MVC 返回 JSON 字符串的时候，ViewResolver 不是 InternalResourceViewResolver。
InternalResourceViewResolver 是 Spring MVC 默认的 ViewResolver，它用于将请求转发到一个内部资源，例如 `/WEB-INF/jsp/index.jsp`。
Spring MVC 返回 JSON 字符串的时候，需要使用 `ContentNegotiatingViewResolver` 来处理。
`ContentNegotiatingViewResolver` 是 Spring MVC 的视图解析器，它可以根据请求头中的 `Accept` 头来选择不同的视图。
如果请求头中的 `Accept` 头中包含 `application/json`，则 `ContentNegotiatingViewResolver` 会使用 `MappingJackson2JsonView` 来处理请求。
`MappingJackson2JsonView` 是 Spring MVC 的视图，它可以将模型对象转换成 JSON 字符串。
所以，Spring MVC 返回 JSON 字符串的时候，ViewResolver 不是 InternalResourceViewResolver，而是 ContentNegotiatingViewResolver。

Spring MVC 返回 JSON 字符串的时候，可能没有经过 `ContentNegotiatingViewResolver` 类的代码。

以下是可能的原因：

* 没有配置 `ContentNegotiatingViewResolver` 类。
* 请求头中的 `Accept` 头中没有包含 `application/json`。
* 使用了 `@ResponseBody` 注解，而不是 `@RequestMapping` 注解。

如果没有配置 `ContentNegotiatingViewResolver` 类，Spring MVC 会使用 `InternalResourceViewResolver` 类来解析视图。如果请求头中的 `Accept` 头中没有包含 `application/json`，Spring MVC 会使用 `InternalResourceViewResolver` 类来解析视图。如果使用了 `@ResponseBody` 注解，而不是 `@RequestMapping` 注解，Spring MVC 会直接将模型对象转换成 JSON 字符串，而不是使用 `ContentNegotiatingViewResolver` 类来解析视图。

如果需要返回 JSON 字符串，建议使用 `@RequestMapping` 注解，并且在请求头中包含 `application/json`。如果需要使用 `@ResponseBody` 注解，建议配置 `ContentNegotiatingViewResolver` 类。
