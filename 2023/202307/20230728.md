### spring源码

#### AnnotationConfigServletWebServerApplicationContext spring-boot包里面的

AnnotationConfigServletWebServerApplicationContext和AnnotationConfigApplicationContext都是Spring中基于Java配置的ApplicationContext实现,主要区别在于:

1. 继承体系不同
- AnnotationConfigServletWebServerApplicationContext继承自ServletWebServerApplicationContext,是Web应用场景下的ApplicationContext实现。
- AnnotationConfigApplicationContext继承自GenericApplicationContext,是更通用的ApplicationContext实现。
2. 功能差异
- AnnotationConfigServletWebServerApplicationContext在GenericApplicationContext的基础上,增加了对Servlet容器的集成支持,如Tomcat、Jetty等。可以直接启动内嵌Servlet容器。
- AnnotationConfigApplicationContext比较纯粹,只提供核心的Spring框架功能,不具备直接启动内嵌容器的能力。
3. 使用场景
- AnnotationConfigServletWebServerApplicationContext多用于Web项目中,可以通过内嵌容器启动Web应用。
- AnnotationConfigApplicationContext更通用,可以应用在Web项目中,也可以应用在非Web项目中。
4. 依赖差异
- AnnotationConfigServletWebServerApplicationContext依赖Servlet API相关jar包。
- AnnotationConfigApplicationContext不依赖Servlet API。
总结:
AnnotationConfigServletWebServerApplicationContext在AnnotationConfigApplicationContext的基础上做了增强,提供了内嵌Servlet容器支持,因此更适合Web项目使用。但核心的配置方式没有区别。



#### AnnotationConfigApplicationContext spring-context包里面的


AnnotationConfigApplicationContext是Spring中一个重要的ApplicationContext实现,它可以通过Java配置类的形式来定义Bean。主要功能包括:

1. 支持@Configuration配置类
AnnotationConfigApplicationContext可以接受一个或多个@Configuration类作为构造参数,用来定义Bean。@Bean注解用于方法上供容器识别。
2. 支持@ComponentScan
可以通过@ComponentScan自动扫描指定包下的组件,如@Service,@Repository等。
3. 支持@Import导入配置类
可以通过@Import注解导入其他配置类。
4. 环境配置
可以通过register方法注册环境配置等,如PropertySourcesPlaceholderConfigurer。
5. 国际化信息配置
可以注册LocaleResolver等支持国际化的组件。
6. 事件监听器注册
可以注册事件监听器,如实现ApplicationListener接口的Bean。
7. 注解驱动
支持@Autowired、@Value等注解的注入。
8. 资源处理
可以注册ResourceLoader等用于资源访问的组件。
9. BeanFactory后处理器
可以通过addBeanFactoryPostProcessor注册BeanFactoryPostProcessor。
总结来说,AnnotationConfigApplicationContext通过支持Java配置方式创建IoC容器,使用更加简洁,可以完全不用XML,它在Spring框架中使用广泛。


#### DefaultListableBeanFactory

这里是对DefaultListableBeanFactory类的详细解析:
DefaultListableBeanFactory是Spring中最基础的BeanFactory实现,它实现了ConfigurableListableBeanFactory及BeanDefinitionRegistry接口。主要功能包括:
1. 注册/取消注册BeanDefinition
作为BeanDefinitionRegistry的实现,DefaultListableBeanFactory可以注册及取消注册BeanDefinition。注册方法主要有registerBeanDefinition和removeBeanDefinition。
2. Bean定义信息的获取
可以通过方法getBeanDefinition获取指定bean名称的BeanDefinition信息。
3. Bean实例的创建
可以通过getBean方法创建或者获取Bean实例。实例化Bean时会自动注入依赖。
4. 初始化Bean
 Spring通过BeanPostProcessor在Bean实例化后进行初始化Before和After回调。
5. 存放单例Bean实例
Spring中的Bean默认为单例,每个Bean在第一次请求时创建,后续请求直接从缓存map中取。
6. 父子容器
通过setParent方法可以建立父子容器关系,子容器可以访问父容器的Bean。
7. Bean的作用域
支持多种作用域包括singleton、prototype、request、session等。
8. 延迟初始化
可以通过设置lazy-init=true使Bean延迟初始化,只有在第一次请求时才会初始化。
总的来说,DefaultListableBeanFactory作为Spring容器的基础实现,提供了基础的IoC和DI功能,包括Bean注册、依赖注入、初始化、存储、父子容器等。这些功能对Spring容器的运作至关重要。

setInitializers((Collection) getSpringFactoriesInstances(ApplicationContextInitializer.class)); setListeners((Collection) getSpringFactoriesInstances(ApplicationListener.class));代码作用

这两行代码位于AnnotationConfigApplicationContext的构造方法中,作用是:

1. setInitializers:
- getSpringFactoriesInstances: 根据ApplicationContextInitializer.class获取所有Spring工厂类中配置的ApplicationContextInitializer实现类实例。
- setInitializers: 将获取到的ApplicationContextInitializer实现类实例设置成该ApplicationContext的initializers属性。
ApplicationContextInitializer是一个回调接口,允许我们自定义修改ApplicationContext的配置,它会在上下文被初始化之前调用。
通过这行代码,Spring会自动查找所有实现了ApplicationContextInitializer接口的类,并实例化为initializers属性。
2. setListeners:
- getSpringFactoriesInstances: 根据ApplicationListener.class获取所有Spring工厂类中配置的ApplicationListener实现类实例。 
- setListeners: 将获取到的ApplicationListener实现类实例设置成该ApplicationContext的listeners属性。
ApplicationListener是一个事件监听器接口,用于监听ApplicationContext事件。
通过这行代码,Spring会自动查找所有实现了ApplicationListener接口的类,并实例化为listeners属性,用于后续事件监听。
总结:
这两行代码实现了SpringFactories自动装配功能,可以自动装配initializer和listener,动态注册到ApplicationContext中,省去了大量手动注册的代码。



org.springframework.boot.context.ConfigurationWarningsApplicationContextInitializer
org.springframework.boot.context.ContextIdApplicationContextInitializer
org.springframework.boot.context.config.DelegatingApplicationContextInitializer


org.springframework.boot.context中的这几个ApplicationContextInitializer实现类的作用如下:
1. ConfigurationWarningsApplicationContextInitializer
用于在ApplicationContext初始化过程中检测配置问题并打印warning信息。
主要检测包括组件扫描指定basePackages是否存在,@ComponentScan扫描是否有scheme限定等。可以帮助发现早期的配置错误。
2. ContextIdApplicationContextInitializer 
用于生成ApplicationContext的id并设置到上下文中,id格式为应用名-随机十六进制字符串。
这个id可用于关联日志和应用实例,以及ObjectName等监控场景使用。
3. DelegatingApplicationContextInitializer
这个类不是真正的Initializer,而是一个组合其他所有Initializer的代理类。
它维护了一个Initializer列表,会在自己被回调时,转发回调到所有子Initializer上去。
这样就可以批量装配和回调所有Initializer实现了。
总结:
这些实现类都用于在ApplicationContext初始化阶段进行各种自定义处理,丰富了容器的初始化逻辑。

org.springframework.beans.BeanUtils#instantiateClass(java.lang.Class<T>)



 在Spring Cloud项目中,SpringApplication对象的applicationContextClass属性会在运行过程中被修改成Spring Cloud提供的ApplicationContext实现类。
主要的修改时机有两个:
1. 在SpringApplicationrun方法内部
SpringApplication的run方法负责启动整个Spring应用。在该方法内部,会根据类路径是否存在某些Spring Cloud的类来判断是否启用Spring Cloud功能,如果启用,则会将applicationContextClass设置为Spring Cloud提供的ApplicationContext实现类,如:

```java
if (ClassUtils.isPresent("org.springframework.cloud.context.config.annotation.RefreshScope", null) && !config.containsBean(RefreshScope.class)) {
  config.addBean(RefreshScope.class);
  applicationContextClass = ConfigurableApplicationContext.class; 
}
```

这里将将applicationContextClass设置为ConfigurableApplicationContext,启用了@RefreshScope注解的自动配置。
2. 在SpringApplication的prepareContext方法内部
这个方法是子类自定义ApplicationContext创建时需要重写的方法。Spring Cloud的SpringApplication子类会在该方法中重新设置applicationContextClass,例如:

```java
@Override
protected void prepareContext(ConfigurableApplicationContext context, ConfigurableEnvironment environment, SpringApplicationRunListeners listeners, ApplicationArguments applicationArguments, Banner printedBanner) {

  // 设置applicationContextClass为Spring Cloud自定义实现类
  context.setApplicationContextClass(AnnotationConfigServletWebServerApplicationContext.class);
  
  // ...
}
```

将applicationContextClass设置为Spring Cloud的AnnotationConfigServletWebServerApplicationContext。
所以简单总结,Spring Cloud主要在SpringApplication启动流程的这两个点,修改了applicationContextClass,使得自动创建的是Spring Cloud提供的ApplicationContext实现,以便使用Spring Cloud的功能。
在Spring Cloud项目中，通常会有两个`SpringApplication`对象被创建，分别代表了应用程序本身和用于管理应用程序的Spring Boot Admin Server。
`SpringApplication`是Spring Boot的核心类之一，用于启动Spring Boot应用程序。而在Spring Cloud项目中，通常会使用Spring Boot Admin来监控和管理应用程序。
因此，当启动Spring Cloud应用程序时，会创建一个`SpringApplication`对象来启动应用程序本身，同时也会创建一个`SpringApplication`对象来启动Spring Boot Admin Server。
这两个`SpringApplication`对象有各自的配置文件，因此它们可以独立地配置和管理自己的应用程序。
