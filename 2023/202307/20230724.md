org.springframework.context.annotation.Configuration#proxyBeanMethods  5.2才有，作用

@Configuration 注解的proxyBeanMethods属性是在Spring 5.2版本新增的,它的作用是控制@Configuration类中的@Bean方法是否要创建代理。

默认为true,会为@Bean方法创建代理,从而实现延迟初始化和提高容器启动性能。

如果设置为false,则不代理@Bean方法,始终会立即调用目标方法。

示例:

```java
@Configuration(proxyBeanMethods = false)
public class MyConfig {

  @Bean 
  public MyService myService() {
    return new MyService(); 
  }

}
```

这样myService()会直接初始化,而不是延迟初始化。
一般如果@Bean方法无参数,并且没有依赖,可以设置为false加快启动速度。
如果@Bean方法需要依赖注入,则保持默认的true,使用代理。
这个属性允许更细粒度控制配置类的代理行为,根据实际情况选择合适的模式。

org.springframework.boot.autoconfigure.AutoConfigureAfter

org.springframework.boot.autoconfigure.AutoConfigureBefore

在Spring Boot自动配置过程中,@AutoConfigureAfter和@AutoConfigureBefore注解都可以用来控制自动配置类的顺序。

@AutoConfigureAfter:

- 表示当前自动配置类需要在指定类后面加载配置。

- 就是当前类依赖于指定类完成的配置。

@AutoConfigureBefore:

- 表示当前自动配置类需要在指定类之前加载。

- 当前类会为指定类提供依赖的已配置环境。

例如:

```java
@AutoConfigureAfter(DataSourceAutoConfiguration.class)
public class JdbcTemplateAutoConfig {
  // 需要数据源配置后再加载
} 

@AutoConfigureBefore(DataSourceAutoConfiguration.class) 
public class DriverAutoConfig {
  // 提供DataSource配置所需的驱动定义 
}
```

这可以确保自动配置的顺序符合依赖关系,先后满足依赖,防止失败。

一般数据源依赖驱动,模板依赖数据源。

两个注解很有助于声明自动配置间的依赖。



在代码中,private int globalReadTimeoutMs = 10_000;表示将globalReadTimeoutMs变量声明为int类型,初始化值为10,000毫秒,即10秒。

这里的10_000中的下划线"_"不是整数的一部分,而是数字分隔符,用于分隔数字Pieces digitsl,以增加数值的可读性。

数字分隔符可以写在整数literals中的任何数字Piece间,不会影响实际的值。

例如:

```java
int million = 1_000_000; // 一百万

long billion = 1_000_000_000L; // 十亿

double pi = 3.14_15_9; // 圆周率近似值
```

所以在globalReadTimeoutMs的写法中,下划线没有特殊含义,仅用于分隔数字位,使其更易读。

这是一个Java 7开始支持的语法特性,可以让数值常量更易识别,十分实用。



org.springframework.context.annotation.ImportBeanDefinitionRegistrar接口
在Spring框架中,ImportBeanDefinitionRegistrar是一个接口,它允许通过注解导入额外的Bean定义。其主要作用是:

1. 它可以用来注册Import注解导入的Bean定义。

2. 当使用Import注解导入配置类时,如果导入的类实现了这个接口,则会调用其registerBeanDefinitions方法。

3. 在这个方法中,可以手动注册额外的Bean定义到容器中。

4. 这样就提供了一个在导入配置类时自定义注册额外Bean定义的扩展点。

例如:

```java
// 实现ImportBeanDefinitionRegistrar接口
public class CustomRegistrar implements ImportBeanDefinitionRegistrar {

  public void registerBeanDefinitions(AnnotationMetadata metadata, BeanDefinitionRegistry registry) {
    registry.registerBeanDefinition("myBean", new RootBeanDefinition(MyBean.class)); 
  }

}

// 导入时会被调用注册额外Bean
@Configuration
@Import(CustomRegistrar.class)
public class Config {
  
}
```

通过这种机制,Import支持扩展注册更多Bean定义。

在Spring框架中,ClassPathBeanDefinitionScanner是非常重要的一个类,它的主要作用是:

1. 它实现了Spring的组件扫描和自动检测的功能。

2. 在@ComponentScan注解配置的扫描基础包路径下,查找被@Component等注解标注的类。

3. 并为这些组件类注册Bean定义。

4. 默认会扫描指定包路径下的所有类。

5. 可以通过includeFilters和excludeFilters自定义过滤规则。

6. 也可以通过扫描器的setBeanNameGenerator设置Bean名称生成策略。

7. 是Spring组件自动检测的核心实现类。

示例用法:

```java
ClassPathBeanDefinitionScanner scanner = new ClassPathBeanDefinitionScanner(registry); 
scanner.scan("com.mycompany");
```

这将扫描com.mycompany包及子包下的组件。

综上,它是@ComponentScan注解驱动的关键类,扫描并注册Bean定义。
