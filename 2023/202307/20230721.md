在Spring中,DefaultListableBeanFactory的beanDefinitionNames变量中保存了所有已注册的Bean定义的名称。
其中的Bean名称值主要来源于以下几个方面:
1. 配置类上的@Bean方法名
例如:
```java
@Bean
public UserService userService() {
  // ...
}
```
userService会作为一个Bean名称。
2. <bean>元素的id或name属性
例如:
```xml
<bean id="userService" class="...">
</bean> 
```
id或name会成为Bean名称。
3. @Component等注解的value值
例如:
```java
@Component("userService")
public class UserService {

}
```
4. 其他生成Bean名称的命名策略
例如@Bean方法名生成或全限定类名生成等。
5. BeanDefinitionRegistryPostProcessor自定义注册的Bean定义
以上都是Bean名称的来源。最终都会存入DefaultListableBeanFactory的beanDefinitionNames变量中。
我们可以通过这些名称访问所对应的Bean定义信息。

问题：
DefaultListableBeanFactory的beanDefinitionNames是List， requestMappingHandlerMapping是如何添加到里面的


在Spring MVC中,RequestMappingHandlerMapping这个Bean的名称是如何被添加到DefaultListableBeanFactory的beanDefinitionNames中的呢?

主要过程是:

1. 在Spring MVC默认配置类WebMvcConfigurationSupport中,通过@Bean注解定义了RequestMappingHandlerMapping:

   ```java
   @Bean
   public RequestMappingHandlerMapping requestMappingHandlerMapping() {
     //...
   }
   ```

2. 在Spring容器启动时,ConfigurationClassPostProcessor会解析该配置类。

3. 它会以方法名"requestMappingHandlerMapping"作为Bean名称,注册该Bean定义。

4. 然后会调用BeanDefinitionRegistryPostProcessor接口的postProcessBeanDefinitionRegistry方法。

5. 这个方法在DefaultListableBeanFactory中实现,会把注册的Bean定义名称添加到beanDefinitionNames集合中。

6. 这样RequestMappingHandlerMapping的名称就被添加到了beanDefinitionNames中。

总结一下:

1. 通过@Bean方法定义,名称为方法名

2. ConfigurationClassPostProcessor解析注册

3. DefaultListableBeanFactory的postProcessor接口实现将名称存入beanDefinitionNames

4. 这样名称就被记录下来了



问：PathMatchConfigurer类作用
在Spring MVC中,PathMatchConfigurer用于配置路径匹配参数,主要功能包括:
1. 设置路径匹配是否区分文件扩展名。
2. 设置路径分割符,默认是'/'。
3. 设置是否自动后缀路径的点号,如"account." 自动补全为 "account.*"。
4. 设置路径匹配参数的缓存大小。
示例代码:
```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

  @Override
  public void configurePathMatch(PathMatchConfigurer configurer) {
    configurer
      .setUseRegisteredSuffixPatternMatch(true)
      .setUseTrailingSlashMatch(false)
      .setPathSeparator(".");
  }

}
```
这允许自定义路径匹配的各种细节,比如:
- 是否区分文件扩展名
- 使用自定义分隔符
- 是否自动补全点号
等等。
这样可以更灵活地调整路径匹配策略,实现RESTful API定制。

这些类都是Spring MVC中用来注册各种组件的注册类,它们的联系与区别总结如下:

联系:

- 都实现了一种组件的注册,比如视图解析器、视图控制器等
- 都将组件注册到相应的注册中心,如ViewResolverRegistry
- 提供了REGISTRATION常量标记注册的组件类型

区别:

- 注册的组件类型不同
  - ResourceHandlerRegistry:资源处理器
  - ViewResolverRegistry:视图解析器
  - ViewControllerRegistry:视图控制器
- 注册方式也不完全相同
  - 某些通过继承,某些通过组合注册中心

作用:

- ResourceHandlerRegistration:注册静态资源处理器
- ViewControllerRegistration:注册视图控制器 
- UrlBasedViewResolverRegistration: 注册基于URL的视图解析器
- 等等

综上,它们在注册流程上有共性,但针对不同组件类型,职责明确,组合起来服务于Spring MVC。


问：@Controller修饰的类如何注册到spring ioc容器中的
@CompontScan spring源码分析

@Controller修饰的类是如何被注册到Spring IOC容器中的,主要通过@ComponentScan注解驱动的过程:

1. @ComponentScan会被解析为一个Bean定义扫描器ComponentScanAnnotationParser

2. 这个扫描器包含了类解析器ClassPathBeanDefinitionScanner

3. 在扫描指定基础包时,解析器会找到被@Controller修饰的类

4. 然后利用委托的ScopeMetadataResolver解析注解元数据

5. 得到一个Controller作用域的Bean定义,并生成默认的Bean名称

6. 最后注册这个Bean定义到容器中,默认的BeanNameGenerator会将类名作为Bean名  

主要的类:

- ComponentScanAnnotationParser:扫描器
- ClassPathBeanDefinitionScanner:类解析器 
- AnnotationScopeMetadataResolver:注解解析器

流程:

- 扫描类->找到Controller类->解析注解->生成Bean定义->注册Bean

所以@ComponentScan通过类解析机制,自动识别并注册被@Controller标注的Bean。

@Controller 有两个相同的url，spring源码如何检测并报错
org.springframework.web.servlet.handler.AbstractHandlerMethodMapping.MappingRegistry#validateMethodMapping

在 Spring 框架中，请求 URL 到具体处理方法的映射是通过 `HandlerMapping` 接口的实现类完成的。其中，`AbstractHandlerMethodMapping` 是一个抽象类，它提供了默认的映射方法实现，并定义了一个名为 `validateMethodMapping` 的方法，用于检测处理方法的映射是否存在冲突。
具体来说，当你在一个 `@Controller` 中定义了两个相同的 URL 映射时，`AbstractHandlerMethodMapping` 的子类会在应用程序启动时调用 `validateMethodMapping` 方法，并抛出 `IllegalStateException` 异常，表示存在 URL 映射冲突。该异常会被 Spring MVC 框架捕获，并在应用程序启动失败时输出错误日志。
在 `AbstractHandlerMethodMapping` 的实现类中，`validateMethodMapping` 方法会遍历所有的处理方法，检查它们的 URL 映射是否存在冲突。如果存在冲突，则会抛出异常。具体的实现代码如下所示：
```
@Override
protected void validateMethodMapping(Method method, HandlerMethod handlerMethod, Map<RequestMappingInfo, HandlerMethod> mappingRegistry) {
    RequestMappingInfo requestMappingInfo = createRequestMappingInfo(method);
    HandlerMethod existingHandlerMethod = mappingRegistry.get(requestMappingInfo);
    if (existingHandlerMethod != null && !handlerMethod.equals(existingHandlerMethod)) {
        throw new IllegalStateException("Ambiguous mapping. Cannot map '" + handlerMethod.getBeanType().getName() + "' method \n" +
                handlerMethod + "\nto " + requestMappingInfo + ": There is already '" +
                existingHandlerMethod.getBeanType().getName() + "' bean method\n" + existingHandlerMethod +
                " mapped.");
    }
}
```
在这个例子中，我们看到 `validateMethodMapping` 方法的实现代码。该方法会根据处理方法创建一个 `RequestMappingInfo` 实例，并从映射注册表中获取已经存在的处理方法。如果已经存在的处理方法与当前处理方法不同，且它们的 URL 映射相同，则会抛出异常，表示存在 URL 映射冲突。
总之，Spring MVC 框架在应用程序启动时会检查 URL 映射是否存在冲突，并在发现冲突时抛出异常。这样做可以确保应用程序能够正常处理请求，并避免 URL 映射冲突带来的问题。
