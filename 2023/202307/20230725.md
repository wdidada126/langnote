org.springframework.context.annotation.ImportBeanDefinitionRegistrar

`ImportBeanDefinitionRegistrar` 接口是 Spring Framework 中的一个扩展点，用于允许开发人员在运行时动态地注册其他 BeanDefinition。

通常情况下，我们可以在 `@Configuration` 类上使用 `@Import` 注解来导入其他的 `@Configuration` 类，以便将它们的 BeanDefinition 注册到 Spring 容器中。但是，在某些情况下，我们需要在运行时动态地注册 BeanDefinition，这时就可以使用 `ImportBeanDefinitionRegistrar` 接口。

当一个 `@Configuration` 类实现了 `ImportBeanDefinitionRegistrar` 接口后，它必须实现 `registerBeanDefinitions()` 方法。在这个方法中，开发人员可以使用 `BeanDefinitionRegistry` 接口动态地注册其他的 BeanDefinition，这些 BeanDefinition 可以是通过编程方式创建的，也可以是通过解析配置文件等方式创建的。

总之，`ImportBeanDefinitionRegistrar` 接口提供了一种动态注册 BeanDefinition 的机制，使得开发人员可以更加灵活地管理 Spring 容器中的 Bean。


spring-corejar包AnnotationTypeFilter 类作用
https://www.cnblogs.com/wt20/p/10990697.html

在Spring框架的spring-core jar包中,AnnotationTypeFilter是一个类,它的作用是提供按注解类型过滤Bean定义的功能。

主要用于在注册Bean定义时 Includes/Excludes 按注解类型过滤。
1. 它实现了TypeFilter接口,可以用于自定义Type过滤。
2. 使用match()方法按注解类型匹配目标类。
3. 接收一个AnnotationMetadata参数,包含目标类注解信息。
4. 如果类上存在需要过滤的注解,则匹配成功。
示例用法:

```java
AnnotationTypeFilter filter = new AnnotationTypeFilter(Transactional.class); 

scanner.addIncludeFilter(filter);

// 只扫描带Transactional注解的Bean
```

这样配置ClassPathBeanDefinitionScanner时,就能只包含带指定注解的类了。

总结:
AnnotationTypeFilter使用注解类型条件筛选Bean定义,实现按注解扫描Bean的功能。



下面是一个使用 `ImportBeanDefinitionRegistrar` 接口的例子：

```java
@Configuration
@Import(MyBeanRegistrar.class)
public class MyAppConfig {
    // ...
}
```

在上面的代码中，`@Import` 注解指定了 `MyBeanRegistrar` 类，这个类实现了 `ImportBeanDefinitionRegistrar` 接口。当 Spring 容器加载 `MyAppConfig` 配置类时，会调用 `MyBeanRegistrar` 的 `registerBeanDefinitions()` 方法，而在这个方法中，开发人员可以动态地向 Spring 容器注册 BeanDefinition。

下面是一个简单的 `MyBeanRegistrar` 类的实现，它向 Spring 容器注册了一个名为 `myBean` 的 Bean：

```java
public class MyBeanRegistrar implements ImportBeanDefinitionRegistrar {
    @Override
    public void registerBeanDefinitions(AnnotationMetadata importingClassMetadata, BeanDefinitionRegistry registry) {
        BeanDefinitionBuilder builder = BeanDefinitionBuilder.genericBeanDefinition(MyBean.class);
        registry.registerBeanDefinition("myBean", builder.getBeanDefinition());
    }
}
```

在上面的代码中，`registerBeanDefinitions()` 方法创建了一个名为 `myBean` 的 BeanDefinition，并将其注册到了 Spring 容器中。这个 BeanDefinition 是通过 `BeanDefinitionBuilder` 类创建的，它指定了要注册的 Bean 的类型为 `MyBean.class`。

总之，通过实现 `ImportBeanDefinitionRegistrar` 接口并将其作为 `@Import` 注解的参数，开发人员可以在运行时动态地向 Spring 容器注册 BeanDefinition。这种方式可以提供更大的灵活性，使得开发人员可以更加方便地扩展 Spring 容器的功能。

org.springframework.web.context.support.GenericWebApplicationContext

在Spring框架中,ResourceLoader接口用于加载资源文件,它有多种实现类,其中GenericWebApplicationContext是一种通用的Web应用上下文实现。

GenericWebApplicationContext的作用是:
1. 它继承自WebApplicationContext,实现了对Web应用的ApplicationContext支持。
2. 同时它也实现了ResourceLoader接口,可以用于加载资源文件。
3. 提供了普通ApplicationContext和WebApplicationContext的统一功能。
4. 可以用于非Servlet环境下构建可加载资源的Web应用上下文。
5. 还可以直接在代码中构建实例来启动上下文。
示例用法:

```java
GenericWebApplicationContext ctx = new GenericWebApplicationContext();
ctx.load("classpath:app.xml");
ctx.refresh();

// 获取资源文件
Resource resource = ctx.getResource("classpath:test.txt"); 
```

综上,它提供了非Web的可加载资源的应用上下文实现,可以自由控制生命周期。




ClassPathBeanDefinitionScanner是Spring中负责组件扫描和注册的核心类,下面是一个使用它的示例:

1. 创建ClassPathBeanDefinitionScanner实例,传入Bean定义注册器(通常是GenericApplicationContext):

```java
ClassPathBeanDefinitionScanner scanner = new ClassPathBeanDefinitionScanner(applicationContext);
```

2. 设置扫描的基础包路径:

```java
scanner.scan("com.mycompany.app"); 
```

3. 添加include filter,只扫描标记了@Service的类: 

```java
scanner.addIncludeFilter(new AnnotationTypeFilter(Service.class));
```

4. 添加exclude filter,排除Dao结尾的类:

```java  
scanner.addExcludeFilter((metadataReader, metadataReaderFactory) -> 
  metadataReader.getClassMetadata().getClassName().endsWith("Dao"));
```

5. 设置Bean名称生成策略:

```java
scanner.setBeanNameGenerator(new ClassNameBeanNameGenerator()); 
```

6. 执行扫描,将会注册所有过滤通过的Bean:

```java
scanner.scan();
```

这样ClassPathBeanDefinitionScanner就可以完全自定义扫描匹配规则,非常灵活强大。

它是组件自动检测的核心工具类。





AnnotationBeanNameGenerator 实现BeanNameGenerator接口

`AnnotationBeanNameGenerator` 是 Spring Framework 中的一个类，它实现了 `BeanNameGenerator` 接口，用于为 Spring 容器中的 Bean 自动生成默认的名称。它的作用是根据注解来生成 Bean 的名称。

在 Spring 中，我们可以使用 `@Component`、`@Service`、`@Repository`、`@Controller` 等注解来标注一个类，使它成为 Spring Bean。当我们将一个带有这些注解的类注册为 Spring Bean 时，如果没有显式指定 Bean 的名称，那么 Spring 会使用 `AnnotationBeanNameGenerator` 来为它生成一个默认的名称。

默认的 Bean 名称是根据类的注解来生成的，具体规则如下：

1. 如果类上已经有 `@Bean` 注解，则使用该注解的名称；
2. 如果类上有 `@Named` 注解，则使用该注解的名称；
3. 如果类上有 `@Component`、`@Service`、`@Repository`、`@Controller` 或者其他自定义注解，则使用注解名称；
4. 如果类没有任何注解，则使用类名的首字母小写形式作为 Bean 名称。

下面是一个使用 `AnnotationBeanNameGenerator` 的例子：

```java
@Configuration
public class MyAppConfig {
    @Bean
    public MyService myService() {
        return new MyServiceImpl();
    }

    @Bean
    public MyController myController() {
        return new MyController();
    }
}
```

在上面的代码中，`MyService` 和 `MyController` 类都没有任何注解，因此它们的 Bean 名称将由 `AnnotationBeanNameGenerator` 自动生成。具体来说，`myService` 和 `myController` 分别是 `MyService` 和 `MyController` 类的首字母小写形式。
如果我们想要为一个 Bean 指定特定的名称，可以在 `@Bean` 注解中使用 `name` 属性，如下所示：

```java
@Configuration
public class MyAppConfig {
    @Bean(name = "mySpecialName")
    public MyService myService() {
        return new MyServiceImpl();
    }
}
```

在上面的代码中，`myService` Bean 的名称将会是 `mySpecialName`，而不是 `AnnotationBeanNameGenerator` 自动生成的默认名称。
总之，`AnnotationBeanNameGenerator` 用于为 Spring 容器中的 Bean 自动生成默认的名称。它可以根据类的注解来生成名称，也可以使用类名的首字母小写形式作为名称。


在Java中,java.beans.Introspector是一个类,它的主要作用是分析一个类的Bean属性和方法,用于在框架中构建bean信息模型。

主要功能有:

1. 分析类的属性、方法和事件,用于描述Bean。 

2. 通过getBeanInfo(Class)可以获取给定类的BeanInfo,描述其Bean属性、方法等。

3. 提供了描述Bean用的设计模式与工具类。

4. 被Spring、Java EE等用来解析类,获取bean信息。

使用示例:

```java
BeanInfo info = Introspector.getBeanInfo(Person.class);

PropertyDescriptor[] props = info.getPropertyDescriptors(); 

MethodDescriptor[] methods = info.getMethodDescriptors();

// 获取属性、方法描述器进行分析
```

Introspector发挥了JavaBeans描述模型的强大功能,用来解析类的属性、方法、事件等信息。

许多框架都依赖它实现对Bean模型的分析和处理。



ConstructorArgumentValues
org.springframework.beans.factory.config.ConstructorArgumentValues


`ConstructorArgumentValues` 是 Spring Framework 中的一个类，它用于保存 Bean 的构造函数参数值。在 Spring 容器创建 Bean 时，如果 Bean 的构造函数有参数，那么 Spring 会使用 `ConstructorArgumentValues` 来保存这些参数的值，并在创建 Bean 的时候将这些参数值传递给构造函数。

`ConstructorArgumentValues` 类提供了多种方法来添加和获取构造函数参数值。下面是一个使用 `ConstructorArgumentValues` 的例子：

```java
@Configuration
public class MyAppConfig {
    @Bean
    public MyService myService() {
        ConstructorArgumentValues constructorArgs = new ConstructorArgumentValues();
        constructorArgs.addIndexedArgumentValue(0, "arg1");
        constructorArgs.addIndexedArgumentValue(1, 123);
        return new MyServiceImpl(constructorArgs);
    }
}
```

在上面的代码中，`MyService` Bean 的构造函数有两个参数，一个是 `String` 类型的参数，一个是 `int` 类型的参数。我们使用 `ConstructorArgumentValues` 类来保存这两个参数的值，并将 `ConstructorArgumentValues` 实例传递给 `MyServiceImpl` 类的构造函数。

`addIndexedArgumentValue()` 方法用于添加构造函数参数值，它的第一个参数是参数的索引位置，第二个参数是参数的值。在上面的例子中，我们将 `arg1` 和 `123` 分别添加到了构造函数的第一个和第二个参数位置。

`ConstructorArgumentValues` 还提供了其他的方法来添加和获取构造函数参数值，例如 `addGenericArgumentValue()` 方法可以添加一个非索引型参数，`getArgumentValue()` 方法可以获取指定索引位置的参数值等。

总之，`ConstructorArgumentValues` 用于保存 Bean 的构造函数参数值，它可以帮助 Spring 容器在创建 Bean 的时候传递正确的参数值给构造函数。使用场景包括但不限于：在 Bean 的构造函数有参数的情况下，为 Bean 注入构造函数参数值。



org.springframework.beans.factory.support.AbstractBeanDefinition#beanClass 作用，使用场景

GenericBeanDefinition类中beanClass 作用
`AbstractBeanDefinition` 是 Spring Framework 中的一个抽象类，它用于表示 Bean 的定义信息，包括 Bean 的类名、作用域、依赖关系等。其中，`beanClass` 是 `AbstractBeanDefinition` 的一个属性，它表示 Bean 的类类型。

在 Spring 容器创建 Bean 的过程中，需要知道 Bean 的类类型，以便可以正确地实例化 Bean。当我们使用 `@Bean` 注解或者 XML 配置文件来定义一个 Bean 时，必须指定 Bean 的类类型。例如：

```java
@Configuration
public class MyAppConfig {
    @Bean
    public MyService myService() {
        return new MyServiceImpl();
    }
}
```

在上面的代码中，`MyService` Bean 的类类型是 `MyServiceImpl`。这个类类型将被保存在 `AbstractBeanDefinition` 的 `beanClass` 属性中。

`beanClass` 属性通常是在 Bean 的定义阶段指定的，也就是在使用 `@Bean` 注解或者 XML 配置文件定义 Bean 的时候。在 Spring 容器启动时，会根据这个属性来加载类并实例化 Bean。

除了 `beanClass` 属性，`AbstractBeanDefinition` 还提供了其他的属性和方法，用于描述 Bean 的定义信息，例如 `scope` 属性表示 Bean 的作用域、`setDependsOn()` 方法表示 Bean 的依赖关系等。

总之，`beanClass` 属性是 `AbstractBeanDefinition` 的一个属性，用于表示 Bean 的类类型。它是定义一个 Bean 的必要信息之一，必须在 Bean 的定义阶段指定。
