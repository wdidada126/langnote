import java.math.BigDecimal;
import java.util.ArrayList;
import java.util.Date;
import java.util.List;
import java.util.stream.Collectors;

@Data
public class WM_BL_SHIP_HDR extends BaseEntity implements Serializable {
    private static final long serialVersionUID = -2995269642550320660L;
    private Long RESERVED_NO; // 出库单号

    private BigDecimal PAY_CREDIT; // 支付信用(元)
    private Date CREDIT_END_DATE; // 到期日（出库单产生时计算获得）

    public static void main(String[] args) {
        List<WM_BL_SHIP_HDR> wmBlShipHdrList = new ArrayList<>();
        // 假设 wmBlShipHdrList 中包含 WM_BL_SHIP_HDR 对象

        List<WM_BL_SHIP_HDR> filteredList = wmBlShipHdrList.stream()
                .filter(hdr -> hdr.getPAY_CREDIT() != null && hdr.getPAY_CREDIT().compareTo(BigDecimal.ZERO) != 0)

        System.out.println(filteredList);
    }
}

请注意，上述示例假设你已经定义了合适的类和方法，并根据你的实际情况进行适当的调整。

Spring MVC框架使用了Spring的线程池实现，具体实现可以参考ThreadPoolTaskExecutor类。
在Spring MVC中，线程池的使用通常是在配置文件中进行配置，而不是在代码中直接使用。下面是一个示例配置：

java
@Configuration  
public class TaskExecutorConfig {  
    @Bean("taskExecutor")  
    @ Qualifier("taskExecutor")  
    public TaskExecutor taskExecutor() {  
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();  
        executor.setCorePoolSize(5);  
        executor.setMaxPoolSize(10);  
        executor.setQueueCapacity(25);  
        executor.setThreadNamePrefix("taskExecutor-");  
        executor.initialize();  
        return executor;  
    }  
}
在上述代码中，我们定义了一个名为taskExecutor的TaskExecutor实例，并将其注入到需要使用它的组件中。ThreadPoolTaskExecutor是Spring提供的线程池实现，我们可以设置线程池的核心线程数、最大线程数、队列容量和线程名称前缀等参数。
在Spring MVC中，控制器方法通常不会直接使用线程池，而是通过使用@Async注解将方法标记为异步执行。例如：
java
@Service  
public class MyService {  
    @Autowired  
    private TaskExecutor taskExecutor;  
  
    @Async  
    public void asyncMethod() {  
        // 异步执行的方法体  
    }  
}
在上述代码中，我们使用了@Autowired注解将TaskExecutor注入到MyService中，然后在需要异步执行的方法上添加了@Async注解。当调用该方法时，该方法会在一个新的线程中异步执行，并且使用了我们配置的线程池。


Tomcat的线程池是在Tomcat启动时初始化的，并创建一定数量的线程，这些线程会被放在线程池中等待执行。当有请求到达时，Tomcat的连接器会接收请求，并将其传递给线程池。线程池中的线程会被调度来处理请求。如果线程池中有空闲线程，将会有一个线程去执行该请求。如果线程池中没有可用线程，请求将进入等待队列。请求处理完成后，线程将返回到线程池中，变为可用状态，以供处理下一个请求。

Tomcat线程池的工作原理可以总结为以下步骤：
初始化线程池：在Tomcat启动时，会初始化线程池，并创建一定数量的线程。
接收请求：当客户端发起请求时，Tomcat的连接器将接收到请求，并将其传递给线程池。
线程池调度：线程池中的线程会被调度来处理请求。如果线程池中有空闲线程，将会有一个线程去执行该请求。如果线程池中没有可用线程，请求将进入等待队列。
请求处理：选中的线程会处理请求，包括解析请求、执行相应的业务逻辑等。该线程会一直处理请求直到完成。
请求完成：处理完请求后，线程将返回到线程池中，变为可用状态，以供处理下一个请求。
等待队列：如果线程池中没有空闲线程，新到达的请求将会进入等待队列。请求按照先到先服务的顺序排队等待处理。等待队列的长度由acceptCount参数决定。
线程重用：线程池中的线程会被重复使用，避免了频繁创建和销毁线程的开销。这个点跟普通线程池不一样。

Volley是Google提供的一个基于HTTP的轻量级网络库，它可以帮助Android开发者更方便地进行网络通信。然而，Volley本身并没有提供自定义线程池的功能。

如果你想使用自定义的线程池，可以考虑以下两种方法：

自定义Request：Volley的Request类可以继承自NetworkRequest类，从而重写它的perform()方法。在这个方法中，你可以根据自己的需要创建并启动一个新的线程来执行网络请求。例如：

java
public class CustomRequest extends NetworkRequest {  
    @Override  
    protected HttpURLConnection createConnection(URL url) throws IOException {  
        Thread thread = new Thread(new Runnable() {  
            @Override  
            public void run() {  
                try {  
                    HttpURLConnection connection = URLConnectionBuilder.build(url);  
                    // 在这里执行网络请求  
                } catch (IOException e) {  
                    // 处理异常  
                }  
            }  
        });  
        thread.start();  
        return null;  
    }  
}
自定义Queue：Volley的Queue类负责管理网络请求的队列。你可以继承Queue类，并重写它的add()方法。在这个方法中，你可以根据自己的需要将请求加入到自定义的线程池中。例如：

java
public class CustomQueue extends Queue<Request> {  
    private ExecutorService executor;  
  
    public CustomQueue(ExecutorService executor) {  
        this.executor = executor;  
    }  
  
    @Override  
    public void add(Request request) {  
        executor.execute(new Runnable() {  
            @Override  
            public void run() {  
                super.add(request);  
            }  
        });  
    }  
}
在上面的代码中，我们创建了一个自定义的线程池，并将所有的请求都加入到这个线程池中执行。你可以根据自己的需要调整线程池的大小和线程的优先级等参数。

ImageLoader是一个用于Android的开源库，用于异步加载和缓存图像。它可以帮助您在应用程序中实现流畅的用户界面，特别是在网络连接较慢或不可靠的情况下。

在Android中，多线程是通过创建Thread或Runnable对象来实现的。然而，使用ImageLoader库时，您不需要直接管理线程。ImageLoader内部已经使用了线程池来管理线程，并确保图像加载的高效性和性能。

ImageLoader库通常会使用内存缓存和磁盘缓存来存储已经加载的图像数据。当用户再次访问相同的数据时，ImageLoader会从缓存中加载图像，从而避免重复的网络请求和下载。这可以提高应用程序的性能和响应速度。

在使用ImageLoader库时，您需要配置一个ImageLoaderConfiguration，包括设置缓存大小和缓存路径等。然后，您可以使用ImageLoader的getImageLoader()方法获取一个ImageLoader对象，并使用该对象加载图像。

以下是一个使用ImageLoader库加载图像的示例代码：

java
// 配置ImageLoader  
ImageLoaderConfiguration config = new ImageLoaderConfiguration.Builder(context)  
        .threadPoolSize(3) // 设置线程池大小  
        .memoryCacheSizePercentage(70) // 设置内存缓存大小  
        .diskCacheSize(100 * 1024 * 1024) // 设置磁盘缓存大小  
        .imageDownloader(new HttpUrlConnectionImageDownloader(context)) // 设置图片下载器  
        .build();  
  
// 获取ImageLoader  
ImageLoader imageLoader = ImageLoader.getInstance();  
imageLoader.init(config);  
  
// 加载图像  
imageLoader.loadImage("http://example.com/image.jpg", new ImageLoadingListener() {  
    @Override  
    public void onLoadingStarted(String imageUri, View view) {  
        // 加载开始时的回调  
    }  
  
    @Override  
    public void onLoadingFailed(String imageUri, View view, FailReason failReason) {  
        // 加载失败时的回调  
    }  
  
    @Override  
    public void onLoadingComplete(String imageUri, View view, Bitmap loadedImage) {  
        // 加载完成时的回调  
    }  
  
    @Override  
    public void onLoadingCancelled(String imageUri, View view) {  
        // 加载取消时的回调  
    }  
});
在上述代码中，我们首先配置了一个ImageLoaderConfiguration对象，并设置了线程池大小、内存缓存大小和磁盘缓存大小等参数。然后，我们获取了一个ImageLoader实例，并使用init()方法初始化该实例。最后，我们调用loadImage()方法加载图像，并实现了ImageLoadingListener接口中的回调方法来处理加载过程中的事件。

通过这种方式，您可以在Android应用程序中使用ImageLoader库实现多线程加载图像，从而提高应用程序的性能和响应速度。
