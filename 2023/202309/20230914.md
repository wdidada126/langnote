缓存穿透
缓存雪崩

核心概念


缓存穿透是指缓存中没有但数据库中有的数据（一般是缓存时间到期），这时由于并发用户特别多，同时读缓存没读到数据，又同时去数据库去取数据，引起数据库压力瞬间增大，造成过大压力。

以下是一些常用的缓存穿透处理方法：

采用布隆过滤器，将所有可能存在的数据哈希到一个足够大的bitmap中，一个一定不存在的数据会被这个bitmap拦截掉，从而避免了对底层存储系统的查询压力附加。
设置热点数据永远不过期。

有几个Java库可以用于实现布隆过滤器来防止缓存雪崩问题。以下是一些常用的Java库推荐：
1. Google Guava：Google Guava是一个功能强大的Java库，其中包含了一个布隆过滤器实现。它提供了易于使用的API和配置选项，可以方便地在缓存系统中使用布隆过滤器进行缓存键的过滤。
2. Apache Commons Bloom Filter：Apache Commons是一个广泛使用的Java库集合，其中包含了Bloom Filter的实现。它提供了一组用于创建和管理布隆过滤器的类和方法，可以轻松地集成到缓存系统中。
3. Redisson：Redisson是一个基于Redis的Java库，提供了分布式数据结构和服务的支持。它包含了一个布隆过滤器实现，可以与Redis缓存系统集成，用于解决缓存雪崩问题。

以上这些库都提供了布隆过滤器的实现，可以帮助你在缓存系统中有效地处理缓存雪崩问题。根据你的具体需求和项目环境，选择适合的库进行集成和使用。记得查阅它们的文档和示例代码，以便正确地配置和操作布隆过滤器。

## redis cluster手动部署

要手动部署Redis Cluster，您需要遵循以下步骤：

安装Redis：首先，您需要在每个节点上安装Redis。您可以通过从Redis官方网站下载适合您的操作系统的Redis软件包来完成安装。

配置节点：在每个节点上创建一个Redis配置文件（通常是redis.conf）。您可以使用文本编辑器打开此文件并进行相应配置。确保在每个节点上设置不同的端口号。

配置集群：对于每个节点，您需要将其配置为集群模式。在redis.conf文件中，将"cluster-enabled"选项设置为"yes"。此外，您需要配置节点之间的通信。将"cluster-config-file"选项设置为节点配置文件的名称（通常是nodes.conf）。

启动节点：在每个节点上启动Redis服务器。您可以使用命令行工具来启动Redis，例如：

shell
$ redis-server /path/to/redis.conf
确保在每个节点上使用正确的配置文件路径。
5. 创建集群：在一个节点上运行以下命令来创建集群：

shell
$ redis-cli --cluster create --cluster-replicas 1 <node1_ip>:<node1_port> <node2_ip>:<node2_port> <node3_ip>:<node3_port> ...
替换<node1_ip>、<node1_port>、<node2_ip>、<node2_port>等为您的节点IP地址和端口号。--cluster-replicas选项指定每个主节点的副本数量。
6. 添加节点：如果您想在集群中添加更多节点，可以使用以下命令：

shell
$ redis-cli --cluster add-node <new_node_ip>:<new_node_port> <existing_node_ip>:<existing_node_port>
替换<new_node_ip>、<new_node_port>、<existing_node_ip>、<existing_node_port>为您要添加的新节点的IP地址和端口号以及现有节点的IP地址和端口号。
7. 删除节点：如果您要从集群中删除节点，可以使用以下命令：

shell
$ redis-cli --cluster del-node <node_ip>:<node_port>
替换<node_ip>、<node_port>为您要删除的节点的IP地址和端口号。

这些是手动部署Redis Cluster的基本步骤。请注意，这是一个简化的概述，实际部署可能涉及更多的细节和配置。确保在进行任何更改之前备份配置文件，并且小心操作以避免数据丢失。

redis-cli --cluster create
redis-cli --cluster add-node
redis-cli --cluster del-node

## redis基准测试

Redis自带了一个基准测试工具，名为redis-benchmark。这个工具可以用来测试Redis的性能指标，包括每秒钟可以执行多少个命令（QPS）、每个命令执行的平均耗时等。它是在一个单线程模型下运行的，可以模拟多个连接同时发送请求，从而测试Redis在高并发情况下的表现。

要在redis服务端和客户端都开启的情况下进行性能测试，你可以通过以下步骤使用redis-benchmark：

进入redis的安装目录。
运行以下命令进行测试：redis-benchmark -h localhost -p 6379 -c 100 -n 100000 set command_percentage_distribution_delay set

除了Redis自带的基准测试工具redis-benchmark，还有其他一些开源的Redis基准测试工具可供选择。以下是其中几个常用的工具：

1. YCSB (Yahoo! Cloud Serving Benchmark): YCSB是一个通用的云服务基准测试工具，支持多种数据库和键值存储系统，包括Redis。它提供了丰富的工作负载模型和灵活的配置选项。
2. Memtier_benchmark: Memtier_benchmark是一个轻量级的基准测试工具，专门用于测试内存缓存系统，如Redis。它支持多线程操作和多种请求模式，并提供了详细的性能指标和报告。
3. Tsung: Tsung是一个分布式负载测试工具，可以用于测试多种应用程序和协议，包括Redis。它可以模拟大量并发用户，并提供实时监控和报告功能。
4. JedisStress: JedisStress是一个基于Jedis客户端库的Redis基准测试工具。它提供了多线程操作和灵活的配置选项，可以测试Redis在高并发负载下的性能表现。

这些工具都是开源的，并且具有不同的特点和适用场景。你可以根据自己的需求选择合适的工具来进行Redis基准测试。请注意，在使用这些工具之前，确保你已经熟悉它们的使用方法并按照文档进行正确配置和操作。
