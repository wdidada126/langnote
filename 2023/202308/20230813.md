当在Spring Boot项目中使用配置文件时，可以将配置文件放置在多个地方，并且Spring Boot会根据一定的规则来加载这些配置文件。这种方式允许您以不同的方式组织和管理配置。
下面是Spring Boot的配置文件加载规则：
1. **默认位置：** 在Spring Boot中，默认的配置文件位置是`/config`目录下的`application.properties`或`application.yml`文件。这个位置是相对于项目的根目录。
1. **类路径下的根目录：** 如果在项目的类路径（`src/main/resources`目录）下直接放置了`application.properties`或`application.yml`文件，Spring Boot也会自动加载这些文件作为配置文件。
1. **外部配置文件：** 可以通过指定命令行参数或操作系统的环境变量来指定外部配置文件的位置。例如，可以使用`--spring.config.name`和`--spring.config.location`参数指定要加载的配置文件名和位置。
1. **额外的配置文件：** 除了上述位置外，还可以通过使用`@PropertySource`注解或`spring.config.additional-location`属性来加载额外的配置文件。这些额外的配置文件可以是任意位置的文件。
根据上述规则，Spring Boot会按照优先级顺序加载配置文件。默认位置的配置文件拥有最低的优先级，而其他位置的配置文件将覆盖默认位置的配置。
当存在多个配置文件时，它们的属性将合并到应用程序的运行环境中。如果存在相同的属性键，后加载的配置文件将覆盖先加载的配置文件中的值。
通过这种灵活的配置文件加载机制，您可以根据需要选择不同的配置文件位置，并根据优先级覆盖和合并属性，以满足不同环境和需求的配置要求。


在传统的Spring项目中，可以使用`PropertyPlaceholderConfigurer`或`PropertySourcesPlaceholderConfigurer`类将配置文件的内容读取并封装成对象，然后将这些对象注入到Spring的IoC容器中。

`PropertyPlaceholderConfigurer`和`PropertySourcesPlaceholderConfigurer`都是用于处理占位符的配置文件处理器，它们可以解析配置文件中的占位符，将占位符替换为具体的值。

下面是使用`PropertyPlaceholderConfigurer`的示例：

1. 创建一个配置文件（例如，`config.properties`），其中包含键值对形式的属性。

   ````
   database.url=jdbc:mysql://localhost:3306/mydb
   database.username=root
   database.password=secret
   ```

   ````

1. 在Spring的配置文件中，配置`PropertyPlaceholderConfigurer`：

   ````xml
   <bean class="org.springframework.beans.factory.config.PropertyPlaceholderConfigurer">
       <property name="location" value="classpath:config.properties" />
   </bean>
   ```

   上述配置指定了配置文件的位置。

   ````

1. 创建一个需要注入配置的对象，并使用`@Value`注解将属性与配置文件中的属性关联起来。

   ````java
   public class DatabaseConfig {
       @Value("${database.url}")
       private String url;

       @Value("${database.username}")
       private String username;

       @Value("${database.password}")
       private String password;

       // 省略getter和setter方法
   }
   ```

   通过在属性上使用`${...}`占位符，指定要注入的配置属性的键。

   ````

1. 在Spring的配置文件中，将需要注入配置的对象声明为一个bean：

   ````xml
   <bean id="databaseConfig" class="com.example.DatabaseConfig" />
   ```

   这样，`DatabaseConfig`对象将会被实例化，并且配置文件中的属性将会被注入到该对象中。

   ````

通过以上步骤，配置文件中的属性值将会被读取并注入到相应的对象属性中，使得我们可以在Spring的IoC容器中使用这些配置属性。

在Spring中，`@Value`注解用于直接将值注入到字段、方法或构造函数参数中，并不是用于从Spring IoC容器中获取对象。

当使用`${...}`语法时，`@Value`注解用于从属性源（如属性文件、环境变量或系统属性）中获取值。

对于`${database.url}`，Spring会在属性源中搜索名为`database.url`的属性，并将占位符替换为相应的值。

   ````

   ````
