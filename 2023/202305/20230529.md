TransactionSynchronizationAdapter 是一个抽象类，它提供了一些方法，可以帮助我们在事务中执行一些额外的操作。这些方法包括：

* afterCommit()：在事务提交后执行
* afterCompletion()：在事务完成后执行（无论是提交还是回滚）
* beforeCommit()：在事务提交前执行
* beforeCompletion()：在事务完成前执行（无论是提交还是回滚）

我们可以通过实现这些方法，来实现一些自定义的功能，例如：

* 在事务提交后，发送邮件通知用户
* 在事务完成后，关闭数据库连接

以下是一个使用 TransactionSynchronizationAdapter 的示例：

```java
public class MyTransactionSynchronizationAdapter extends TransactionSynchronizationAdapter {

    @Override
    public void afterCommit() {
        // 在事务提交后执行
        System.out.println("Transaction committed.");
    }

    @Override
    public void afterCompletion(int status) {
        // 在事务完成后执行（无论是提交还是回滚）
        System.out.println("Transaction completed with status " + status);
    }

}
```

我们可以通过 @Transactional 注解来使用 TransactionSynchronizationAdapter。以下是一个使用 @Transactional 注解的示例：

```java
@Transactional
public void doSomething() {
    // 执行业务逻辑

    // 在事务提交后，发送邮件通知用户
    new MyTransactionSynchronizationAdapter().afterCommit();
}
```

ApplicationListenerMethodAdapter主要是为了处理@EventListener注解定义的事件监听器。
它的主要作用是:
1. 识别带@EventListener注解的方法
2. 注册这些方法到ApplicationEventMulticaster,这样当事件发布时,这些方法就可以被调用
3. 调用注解方法,将ApplicationEvent作为参数传给注解方法
所以简单来说,ApplicationListenerMethodAdapter主要做了以下工作:
- 扫描@EventListener注解方法
- 注册这些方法为事件监听器
- 调用这些方法,将事件作为参数传给它们
其实它就是Spring框架用来处理@EventListener注解的内部逻辑。开发者定义了注解方法后,Spring会使用ApplicationListenerMethodAdapter来自动识别和调用这些注解方法。
这样开发者就可以很方便的监听事件,只需要定义注解方法即可,不用显式注册Listener。这极大地简化了事件监听的实现。
总的来说,ApplicationListenerMethodAdapter就是Spring框架用来自动处理@EventListener注解的内部Adapter。它负责识别注解方法,注册为Listener并在事件发布时调用这些注解方法。

在 Spring 框架中，`Propagation` 枚举类型定义了事务传播行为的不同选项。当一个被 `@Transactional` 注解的方法被调用时，Spring 会根据 `Propagation` 的不同选项来判断是否需要开启新的事务、将当前方法加入到已有的事务中，或者使用当前的事务。

`Propagation` 枚举类型中的每个选项都有对应的处理逻辑，这些逻辑都被封装在 Spring 中的事务拦截器中。在 Spring 源码中，`Propagation` 枚举类型的处理逻辑主要在 `TransactionInterceptor` 和 `TransactionAspectSupport` 类中实现。

例如，当 `Propagation.REQUIRED` 选项被设置时，`TransactionInterceptor` 类会检查当前是否已有事务，并根据情况决定是否需要开启一个新的事务或者将当前方法加入到已有的事务中。如果当前已有事务，则该方法会在原有事务的上下文中执行，否则会创建一个新的事务。

CGLIB是一个功能强大,高性能,高质量的Code Generation Library。它可以用于动态代理类和创建子类。

`org.springframework.cglib.proxy.Enhancer` 是 CGLIB 库中的一个类，它是 Spring 框架中用于动态生成子类的工具类之一。在 Spring 框架中，`Enhancer` 主要用于实现基于 CGLIB 的 AOP 功能。

具体来说，`Enhancer` 可以用于动态生成目标类的子类，并在子类中添加增强代码，从而实现对目标类的 AOP 增强。在生成子类时，`Enhancer` 会通过字节码技术生成一个新的类，并将其封装成一个 `MethodInterceptor` 对象。然后，通过 `setCallback` 方法将该对象设置为子类的回调函数，从而实现对目标方法的增强。

在 Spring 框架中，`Enhancer` 通常用于实现基于 CGLIB 的 AOP 拦截器链。在拦截器链中，每个拦截器都是一个 `MethodInterceptor` 对象，用于对目标方法进行增强。具体来说，当目标方法被调用时，会依次执行拦截器链中的拦截器，从而实现对目标方法的增强。

以下是一个使用 `Enhancer` 实现基于 CGLIB 的 AOP 的示例代码：

```java
public class UserServiceImpl implements UserService {
    @Override
    public void addUser(User user) {
        // 添加用户操作
    }
}

public class UserServiceInterceptor implements MethodInterceptor {
    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) throws Throwable {
        // 在目标方法执行前添加增强代码
        System.out.println("Before adding user...");
        Object result = proxy.invokeSuper(obj, args);
        // 在目标方法执行后添加增强代码
        System.out.println("After adding user...");
        return result;
    }
}

public class Main {
    public static void main(String[] args) {
        Enhancer enhancer = new Enhancer();
        enhancer.setSuperclass(UserServiceImpl.class);
        enhancer.setCallback(new UserServiceInterceptor());
        UserService userService = (UserService)enhancer.create();
        userService.addUser(new User());
    }
}
```

spring transaction是如何统一管理jms事务和数据库事务的

Spring 4.3.12 使用PlatformTransactionManager接口来统一管理不同技术的事务,包括JDBC、JMS、分布式事务等。
主要有下面几个实现:
- DataSourceTransactionManager:管理JDBC事务,用于和数据库交互
- JtaTransactionManager:管理全局事务(XA交易),用于分布式事务
- JmsTransactionManager:管理JMS事务,用于和消息代理交互
它们采用了共同的事务管理策略:
- 开启事务:调用TransactionStatus beginTransaction() 方法
- 提交事务:调用TransactionManager commit() 方法
- 回滚事务:调用TransactionManager rollback()方法
对于Java代码来说,是通过统一的`PlatformTransactionManager`接口 performing操作的。
以JMS为例,Spring管理JMS事务的主要步骤是:
1. 注入JmsTransactionManager实现
```xml
<bean id="transactionManager" class="org.springframework.jms.connection.JmsTransactionManager">
    ...
</bean>
```
2. Java代码使用PlatformTransactionManager接口管理事务
```java
@Autowired
PlatformTransactionManager transactionManager;

public void sendMessage() {
    TransactionStatus status = transactionManager.beginTransaction();
    
    // 发送JMS消息
    
    transactionManager.commit(status);
} 
```
这和管理JDBC事务的方法是一样的,只不过底层实现不同。
Spring通过此统一接口,可以很方便地管理不同技术的事务,统一的编程模型大大简化了开发。
