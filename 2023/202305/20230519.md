jdbcTemplate.batchUpdate返回的[]int 是啥，执行的是insert语句
`JdbcTemplate` 的 `batchUpdate` 方法用于执行批量更新操作，其中包括批量插入操作。当 `batchUpdate` 方法执行批量插入操作时，它会返回一个 `int[]` 数组，其中每个元素表示对应的 SQL 语句插入的行数。
例如，如果你执行了如下代码：

```java
int[] insertCounts = jdbcTemplate.batchUpdate(
    "INSERT INTO users(name, age) VALUES(?, ?)",
    new Object[][] { { "Alice", 18 }, { "Bob", 20 }, { "Charlie", 22 } });
```

那么 `insertCounts` 数组的长度将会是 3，表示执行了 3 条插入语句。如果第一条插入语句插入了 1 行，第二条插入语句插入了 2 行，第三条插入语句插入了 0 行，那么 `insertCounts` 数组的值将会是 `{ 1, 2, 0 }`。
需要注意的是，`batchUpdate` 方法返回的 `int[]` 数组中的元素顺序与 SQL 语句数组中的顺序是一致的，因此你可以通过 `insertCounts` 数组中的元素来判断每条插入语句的执行结果。
另外，如果你需要在执行 `batchUpdate` 方法的时候使用命名参数，可以使用 `batchUpdate(String sql, SqlParameterSource[] batchArgs)` 方法，其中 `batchArgs` 是一个 `SqlParameterSource` 对象数组，其中每个元素对应一条插入语句的参数。在这种情况下，`batchUpdate` 方法的返回值与使用位置参数相同，都是一个 `int[]` 数组。


maven install打包的jar没有source，如何解决

如果使用 Maven 打包项目时没有生成源代码 JAR 文件，可能是因为你没有使用 `maven-source-plugin` 插件来打包源代码。可以按照以下步骤来使用 `maven-source-plugin` 来打包源代码：
1. 在你的 Maven 项目中，打开 `pom.xml` 文件，找到 `build` 元素。
2. 在 `build` 元素中添加以下配置：

```xml
<plugins>
  <plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-source-plugin</artifactId>
    <version>3.2.1</version>
    <executions>
      <execution>
        <id>attach-sources</id>
        <phase>verify</phase>
        <goals>
          <goal>jar</goal>
        </goals>
      </execution>
    </executions>
  </plugin>
</plugins>
```

在上面的配置中，`maven-source-plugin` 插件的版本号为 `3.2.1`，这是当前最新的版本。`<id>` 标签为这个执行阶段命名为 `attach-sources`。`<phase>` 标签指定了插件在 Maven 构建生命周期的哪个阶段执行。这里我们设置为 `verify`，表示在验证阶段执行插件。`<goal>` 标签表示这个执行阶段要执行的目标，这里是 `jar`，表示生成源代码的 JAR 文件。
3. 保存 `pom.xml` 文件后，在项目的根目录下执行以下命令：

```
mvn clean install
```

这个命令会重新构建项目，并在构建完成后将生成的 JAR 文件安装到本地 Maven 仓库中。如果一切顺利，你应该可以在本地 Maven 仓库中找到生成的源代码 JAR 文件。
需要注意的是，如果你使用的是其他的构建工具（如 Gradle），也可以采用类似的方式来打包源代码。具体来说，你需要在构建文件中找到相应的插件，然后按照类似的方式进行配置即可。
