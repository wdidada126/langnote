SELECT DISTINCT
t1.*,
t2.TEXT_ AS APPR_STATUS 
FROM
	(
	SELECT
		t1.ID_ AS TASK_ID,
		t1.NAME_ AS TASK_NAME,
		t1.PROC_INST_ID_ AS PROCESS_INSTANCE_ID,
		t1.CREATE_TIME_ AS CREATE_TIME,
		t5.NAME_ AS TEMPLATE_NAME,
		t5.KEY_ AS TEMPLATE_ID,
		t6.NAME_ AS TITLE,
		t6.START_TIME_ AS START_TIME,
		t7.DEP_NAME AS APPLY_DEPART_NAME 
	FROM
		fuyao_approval_dev.ACT_RU_TASK t1
		LEFT JOIN fuyao_approval_dev.ACT_RU_IDENTITYLINK t3 ON t3.TASK_ID_ = t1.ID_
		LEFT JOIN fuyao_approval_dev.ACT_HI_VARINST t4 ON t1.PROC_INST_ID_ = t4.PROC_INST_ID_
		LEFT JOIN fuyao_approval_dev.ACT_RE_PROCDEF t5 ON t1.PROC_DEF_ID_ = t5.ID_
		LEFT JOIN fuyao_approval_dev.ACT_HI_PROCINST t6 ON t1.PROC_INST_ID_ = t6.PROC_INST_ID_
		LEFT JOIN fuyao_approval_dev.T_TEMPLATE t2 ON t5.KEY_ = t2.ID
		LEFT JOIN fuyao_user_dev.T_CUSTOM_INFO_TD t8 ON SUBSTRING_INDEX( t6.START_USER_ID_, '|', 1 ) = t8.ETP_ID 
		AND SUBSTRING_INDEX( t6.START_USER_ID_, '|',- 1 ) = t8.CUSTOM_ID 
		AND t8.VALID != 'I'
		LEFT JOIN fuyao_user_dev.T_ETP_DEPART_INFO_TD t7 ON t7.ETP_ID = t8.ETP_ID 
		AND t7.DEP_ID = t8.DEP_ID 
	WHERE
		( t1.ASSIGNEE_ = 'C2210131958191691928122893271048|c2210131958001691928044845662212' OR ( ( t1.ASSIGNEE_ IS NULL OR t1.ASSIGNEE_ = '' ) AND t3.USER_ID_ = 'C2210131958191691928122893271048|c2210131958001691928044845662212' ) ) 
		AND t2.SAAS_ID = 'GFMB'
	)  t1
	LEFT JOIN fuyao_approval_dev.ACT_HI_VARINST t2 ON t1.PROCESS_INSTANCE_ID = t2.PROC_INST_ID_ 
WHERE
	t2.NAME_ = 'APPR_STATUS' 
	AND t2.TEXT_ IN ( '01', '05' ) 
ORDER BY
	t1.CREATE_TIME DESC 
	LIMIT 10

sql 函数
`SUBSTRING_INDEX( t6.START_USER_ID_, '|', -1 )`是MySQL中的一个函数，用于从字符串中提取子串。

这个函数的参数如下：
- `t6.START_USER_ID_`：这是要处理的字符串。
- `'|'`：这是分隔符，用于指定在哪里分割字符串。
- `-1`：这是索引值，表示返回从右边开始的第一个分隔符之间的子串。

所以，`SUBSTRING_INDEX( t6.START_USER_ID_, '|', -1 )`的意思是从`t6.START_USER_ID_`字符串中提取最后一个由`'|'`分隔的子串。


tidb可以跨数据库jion表

TiDB支持跨数据库的join操作，能够对来自不同数据库的表进行关联查询。在实际的业务场景中，这种多个表的Join语句是很常见的，而Join的执行效率和各个表参与Join的顺序有关。为了优化 Join 操作，TiDB 采用了Join Reorder算法来确定多个表进行 Join 的最优顺序。此外，当优化器选择的 Join 顺序并不够好时，你可以使用STRAIGHT_JOIN语法让 TiDB 强制按照 FROM 子句中所使用的表的顺序做联合查询。

TiDB支持三种 Join 算法：Hash Join，Sort Merge Join 和 Index Look Up Join。这三种算法分别适用于不同的场景。例如，当两个表的大小相差较大时，可以采用小表广播或者lookup join：先读小表，再用索引读取大表（如果有合适的索引可用）。在处理SQL请求的过程中，TiDB Server会与PD和TiKV交互获取数据，并最终返回结果。
