# L15 I/O、总线和系统：把 CPU 接进一台完整计算机（I/O, Buses & Complete Systems）

> 参考阅读：H&H Ch.9；P&P Ch.10–11（I/O 与中断）
> 对应 Lab：Lab 9 收尾（UART/按键上板即本讲内容）

## 1. 核心概念

### 1.1 外设接入的三种 CPU 视角
- 程序控制 I/O（轮询）：读状态寄存器→数据寄存器循环——简单烧 CPU（L10 stall 思想的软件版）。
- 中断驱动 I/O：设备就绪拉 IRQ → CPU 现场保存（精确异常机制，L12 1.4）→ ISR → 恢复。
- DMA：内存拷贝外包给专用引擎，只在**块完成**时中断一次——高带宽设备的唯一 sane 选择。
三者对 CPU 时间的占用谱系：100% → 每字节 → 每块，性能直觉从此建立。

### 1.2 总线：共享导线的所有权协议
- 结构：地址/数据/控制三线组；主从仲裁（多主时的优先级编码器，L03 优先编码器登场）。
- 握手：`valid/ready`（现代 AXI/APB 简化模型）vs `req/gnt`；**stall 的硬件原语**——
  L10 "等待拍"与本讲 ready 低电平是同一条设计模式在不同层。
- 典型层级：片内 AXI/AHB/APB（ARM SoC）、RISC-V 世界的 TileLink（Chipyard）与 AXI（PULP/OpenTitan），
  片外 PCIe/USB/UART/SPI/I2C（各自协议栈）。

### 1.3 内存映射 I/O（MMIO）
外设寄存器占用地址空间：`*(volatile uint32_t*)0x...` 读写即控制设备——C 层"指针就是总线事务"。
与统一编址相对（独立 I/O 端口，x86 in/out 遗物）。要点：
- `volatile` 的硬件语义 = 禁止编译器删/重排对设备的读写（CSAPP 7.x 的省略号在此变成硬约束）。
- MMIO 区**绕过 cache 或置为 uncached/device 属性**（PTE 属性位，L14）——否则 write-back 会让命令"卡在 cache 里永不生效"（1.4 的坑）。

### 1.4 中断系统全链路
设备 → 中断控制器（PLIC/CLINT 在 RISC-V；8259A 在古代）→ CPU `irq` 线 →
硬件自动保存 EPC/cause（CSR，L08）→ 跳 `trap_vector` → 软件分发。
中断号编码=优先编码器电路（L03）；边沿/电平触发、屏蔽位（mask）、嵌套。
**中断延迟**（响应时间）是实时系统核心指标（esp32/NuttX 话题）。

### 1.5 完整系统拼装图（本课总装车间）
CPU(L09–L12) + L2 cache(L13) + MMU/DRAM 控制器(L14) + UART/SPI/GPIO + 总线(L15 1.2) = SoC。
启动序列：复位→取 PC 初值（BootROM）→加载固件→跳 main——
"PC 从哪来"在 L09 被忽略、L15 被回答：复位向量也是总线主设备的第一笔读。

## 3. 知识点在开源项目中的应用
- **projects/p05 扩展**：给 CPU 加 UART 控制台：`sw` 到 0x1000_0000 = 打印字符（"魔法地址"= MMIO 最小实现）+ 中断号引脚。
- **esp32（本讲最佳活教材）**：ESP-IDF 的 `uart_vfs`、`gpio_isr_handler`、GDMA 通道、PLIC（C3/C6）——1.1–1.4 每节都有对应驱动源码；裸机寄存器手册 TRM 就是 1.3 的字典。
- **PULP / OpenTitan**：OpenTitan 的 `uvmdv` 外设验证平台展示"寄存器即契约"的自动化（regtool 从 hjson 生成 RTL+文档+UVM）。
- **Chipyard**：TileLink 总线 + `dma`（TestChip 的 MMIO DMA 范例）——读 `diplomatic` 连线即 1.2 总线树的现代 DSL 化。
- **XiangShan**：其 SoC 顶层（XSTop）挂 DDR/PCIe/H 桥，开源 CHI/AXI 接口代码可供总线时序对照。

## 4. 常见坑
- ISR 里做重活（printf/分配）→ 中断风暴/优先级反转；"上半部记数、下半部干活"模式（Linux）值得预告。
- DMA 缓冲区与 cache 一致性：硬件 DMA 写 DRAM 而 cache 持旧行（L13 坑的正式回收）——需要 clean/invalidate 或 DMA 一致性总线（ACE/CCI）。
- 轮询循环被 `-O2` 优化掉：忘 `volatile` 时设备位读变死循环——编译器与总线的语义接缝。

## 6. 讲末速查
- 轮询烧 CPU、中断烧上下文、DMA 烧带宽——三种 I/O 是同一权衡的三档定价。
- valid/ready 握手无处不在：总线、cache 等待拍、FIFO 反压都是它换衣服。
- MMIO 三件套：地址映射 + volatile 语义 + uncached 属性，缺一个就有"命令永不生效"惨案。
- 中断五线谱：设备拉线→控制器编码裁决→硬件存现场→跳向量→软件分发——本课 CSR 与 EPC 在此汇合。
