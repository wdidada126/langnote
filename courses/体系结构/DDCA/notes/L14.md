# L14 虚拟内存与地址翻译：页表、TLB、与缓存的配合（Virtual Memory & TLB）

> 参考阅读：H&H Ch.4.6–4.7 + 课程补充讲义；CSAPP 9.8/9.12 对照
> 对应 Lab：无独立 lab；期末"两级页表 + TLB + cache"综合地址计算题必考

## 1. 核心概念

### 1.1 虚拟地址的三个承诺
隔离（每进程独立地址空间）、保护（权限位）、可重定位（换页/移动物理帧不动虚拟）。
代价：每次访存先翻译——**翻译本身必须被 cache**，于是有 TLB。本节是 CSAPP Ch.9 的硬件实现版。

### 1.2 分页与多级页表
虚拟地址 = VPN + offset；页（4KB）内免翻译。一级页表在 32/64 位下不可行 →
**多级稀疏树**：RV32 Sv32 两级（根表+叶表），x86-64 四级/五级。
页表项 PTE：物理帧号 + V/R/W/X/U/G/A/D 位——**权限与 dirty 位的硬件语义在 L15 异常与 6.S081 的 fork 写时复制中直接消费**。
缺页异常（page fault）= 精确异常的一种（L12 1.4）：OS 介入换页后重执行该指令——要求微架构保存可回滚状态。

### 1.3 TLB：地址翻译的专用 cache
- 全相联小容量（L1 DTLB 64 项级），项 = VPN→PFN+属性——命中比较即 CAM（L13 1.2 的"内容寻址"极端使用）。
- 命中路径：TLB→PA→L1 cache tag 并行/串行（现代核多为并行以掩 latency）。
- 缺失：硬件页表走（RISC-V Svinval/硬件 walker，PicoRV32 无 MMU 则无此忧）或 trap 给软件（早期 MIPS）。
- 地址加刷（address translation 一致性）：上下文切换 `sfence.vma`（RISC-V）/`invpcid`（x86）——
  **ASID/PCID 标签避免全刷**（页表的进程标签，同 L13 way 预测思想）。

### 1.4 VIPT/PIPT 与 cache 的耦合（本课最硬一段）
- PIPT：翻译完才比 tag，干净但每次访问吃满翻译延迟。
- VIPT：用虚拟 offset 直接索引 SRAM（索引与页内偏移同宽时"无别名"，L1 常用）——快但需 `n_sets×line ≤ page`。
- 别名（aliasing）：同 PA 经不同 VA 落在不同 set → 硬件 flush 或软件同色页分配（**OS 与硬件共谋的活教材**，6.S081 的 KVA 直接映射设计即此类约束的产物）。

### 1.5 端到端地址旅程（综合图）
`VA → [TLB 命中? ] → PA → [L1 tag/index 比较 → L2 → L3] → MC → [DRAM 行缓冲命中? ] → 数据`
沿途每种缺失都有时间账单（TLB miss ≈ 两次额外内存访问；page fault ≈ 微秒级）。
Mutlu 讲义特色：把"系统性能 = 各层缺失率的卷积"做成全系统视角，期末压轴题原型。

## 4. 常见坑
- TLB 项存的是"页"映射，cache 行存"块"——VPN≠块号，两者位宽/粒度不同，综合题画图先标宽度。
- 多级页表地址划分方向：根表索引是**最高**位 VPN[1]——自顶向下逐层剥（walk 方向反是经典错误）。
- 写 TLB 与页表 A/D 位的原子性：硬件更新 PTE 的 dirty 位需要总线锁/单拷贝原子性（进阶，见 CA）。

## 6. 讲末速查
- 一次 load 的最长账：TLB miss(走页表 2 次访存) → L1 miss → L2 → DRAM 行冲突——逐级加和。
- 页是 4KB、块是 64B：VPN 与 block offset 的粒度差 = TLB 与 cache 为何是两套结构。
- Sv32 两级：根表选 VPN[1]（高位）、叶表选 VPN[0]——walk 永远从高往低剥。
- 权限位（R/W/X/U）由硬件比较、违规由 OS 填坑——页表是软硬件共同签的合同的执行条款。
- VIPT 无别名条件（组数×块长 ≤ 页大小）是现代 L1 用虚拟索引仍快的根本原因。
