# L13 缓存：映射方式、替换策略、写策略与平均访存时间（Caches）

> 参考阅读：H&H Ch.5.6/Ch.8.3 + Mutlu 补充讲义；CSAPP 6.4 对照
> 对应 Lab：Lab 8/9 的 cache 参数化观察；期末题型：AMAT 与 trace 命中率手算

## 1. 核心概念

### 1.1 为什么 cache 能存在：时间局部性 + 空间局部性
程序访问的 90%+ 集中在 10% 的数据/指令上（Zipf/工作集现象）；块（line）大小利用空间局部性，
多级结构利用时间局部性。**cache = 用小而快的 SRAM（L07）代理大而慢的 DRAM（L07）**，
对软件透明——体系结构史上杠杆率最高的 20% 硬件。

### 1.2 地址划分与三种映射
块地址 tag + index + offset 三段论：
- 直接映射：index 位=log2(组数)，1 way。冲突失效严重（循环步长 = 组数×块长 → 颠簸）。
- 组相联 set-associative：index 同上，每组 E way——工程主流（L1:8 way, L2:16 way）。
- 全相联：无 index，tag 比较全部——TLB、小 cache 用（内容寻址 CAM，贵）。
命中 = `Tag[index] == tag` 的 E 路并行比较 OR；数据输出 = way-Mux（L03 Mux 第三次立功）。

### 1.3 替换策略
FIFO/LRU/Random；LRU 在 2 way 便宜（1bit），高相联代价高 → pseudo-LRU（树形）/RRIP（RISCV 学界与工业常用）。
Mutlu 研究主线之一：**Belady 最优、LRU 对 thrash 工作负载的失败、SEDI/SHiP 等预测式替换**——
他的 "Rethinking Memory System Design" 讲义把替换升格为"数据价值预测问题"。

### 1.4 写策略与一致性的最小讨论
写命中：write-back（脏位，省带宽，主流）vs write-through（简单，镜像保险）。
写缺失：write-allocate（配 WB）vs no-write-allocate（配 WT）。
**单核无一致性问题；多核（L16/CA）才有 MESI**——本课点到，CSAPP 6.6/6.S081 并发章会撞上。

### 1.5 AMAT 与多级层次
`AMAT = L1命中时间 + L1缺失率 × (下一级访问开销)`，递归展开到内存。
数字敏感：L1≈1–4ns 命中、主存≈60–100ns——缺失率 1%↔10% 差一个数量级的带宽需求（内存墙，L16）。
块大小悖论：变大→空间局部性↑ 但缺失代价与伪共享↑；存在最优曲线（CSAPP 6.4.2 实验可复现）。

## 3. 知识点在开源项目中的应用
- **projects/p06**：C 写的直接/组相联 cache 模拟器（命中率/AMAT 报告）+ Verilog 简易 cache datapath（tag 比较 + 数据阵列 + LRU）。
- **ChampSim**：研究级替换策略仿真框架，自定义 LRU/RRIP/SHiP 即插即用——本讲 1.3 的开源实验室；跑 `l2_256k_16` 配置重做 CSAPP 6.x 练习。
- **gem5**：经典/Ruby 两级模型，体系结构论文复现标准工具；`configs/cache` 目录参数化对照 1.2。
- **XiangShan / Chipyard(BOOM)**：香山 L1D/L2（含 prefetcher 目录 `src/.../prefetch`）与 BOOM 的 `tlb/cache` 配置（DTS 里 `L2-cache`）——读真实开源核的 cache 树形与容量配置。
- **esp32**：ESP32-C3 有 4KB ICACHE（指令 cache）；其 datasheet 说明 Flash 经 cache 映射进地址空间——"外设慢，cache 顶"的极端版，解释 `-mfix-esp32-psram-cache-strategy` 之类编译标志的存在理由。

## 4. 常见坑
- 混淆缺失率与缺失代价：AMAT 两项乘积关系，任何一项单独优化都可能白干。
- 写回 cache 做 I/O：DMA 写主存后 cache 旧值 → 软件必须 clean/invalidate（esp32/裸机驱动常见坑，接 L15）。
- 排除法/包含法（victim cache、inclusive L3）超出本讲，但 CA 面试常问——标记"后续见 CA"。
