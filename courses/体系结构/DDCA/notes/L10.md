# L10 多周期微架构：指令分阶段与状态机控制（Multicycle MIPS）

> 参考阅读：H&H Ch.6.6；CSAPP 4.5（SEQ/SEQ+ 对照）
> 对应 Lab：Lab 7（多周期 FSM 控制器）

## 1. 核心概念

### 1.1 复用：从"每指令一沿"到"每指令多沿"
单周期里并行的部件改为**分时复用**：同一 ALU 既算地址又算结果，DMem/IMem 共用地址寄存器。
datapath 缩小，代价：需要状态存储（MDR/MAR/IR/NPC 寄存器）+ **FSM 控制器**逐拍发微操作。
L08 1.4 的微操作序列在这里变成字面意义上的控制表。

### 1.2 经典 11 状态（H&H 版）
```
fetch:      S_Fetch(取指) → S_Decode(译码读RF)
stw:        S_Add-Addr → S_Mem-Write → S_Fetch
ld:         S_Add-Addr → S_Mem-Read → S-Alu(符号扩展写回) → S_Fetch
R-type:     S_ALU → S_Rd-Reg? → S_Fetch
beq:        S_Sub → S_Mem-Read?/NPC-Mux → S_Fetch
jal:        S_Add4-ALU → S_Store-LDAddr → S_Jump → S_Fetch
```
每状态一列微操作（A/B 选择、ALU 控制、寄存器使能）——**微编程（microprogramming）**思想：
控制信号可由组合逻辑译码，也可存进**控制存储器（control store）**当微指令读（P&P Ch.7 即此路线，
VAX/IBM 360/现代 x86 复杂指令译微码同源）。

### 1.3 性能分析：CPI 不再为 1
lw=6 拍、sw=5、R=4、beq=3/4、j=3。平均 CPI = Σ(频率×周期数) ≈ 4–5。
但周期时间 ≈ 单周期的 1/8 量级（RF 写口与 ALU 分段，最长段定 T_clk）。
IPC 反而可能更低——多周期教学价值在**FSM 控制**而非真快；工业界（MIPS R2000/Intel 8086）历史用过，
现代只剩微码 CPU 的"影子"。

### 1.4 状态机里的冒险雏形
S_Mem-Read 后立刻用该值？多周期天然错开——但**同一 FSM 内数据就绪时间不同**（如 load 比 add 多两拍）
迫使设计者排状态合并表，这是 L12 冒险检测/转发的问题前身。

### 1.5 多周期 vs 流水线的本质区别
多周期：一条指令独占全部硬件，逐拍推进（时间换空间）。
流水线：多条指令**并行占有不同段**（空间换吞吐）。同一个 datapath 切段方式决定 L11 的段数与失衡。

## 2. 与课程内外知识的衔接
- **CSAPP 4.5 SEQ**：SEQ 的 `fall/f_src/f_dst/...` 阶段 = 1.2 的状态合并版；CSAPP 用统一 6 阶段 FSM 处理所有指令（比 H&H 11 状态更规整），两版对照可体会状态机建模自由度。SEQ+ 加 st_all 暂停 = 本讲的"长周期指令多拍"处理。
- **内存层次**：多周期里 S_Mem-Read 一旦 miss 到慢速层怎么办？加"等待状态（stall）"——这一改造思想在 L13 cache 与总线接口（L15）中以 ready/wait 信号原样再现。
- **6.S081**：无直接接口；但 xv6 `sleep/wake` 的"等待慢速资源"控制流与 stall 同构，可当类比。
- **CS61C/N2T/CA**：N2T Week 8 用微程序控制 LC-3-like VM（与本讲 1.2 同路线）；CS61C 略过（直接进流水线）；ETH CA Lab 的 valid/ready 握手状态机是本讲"等待拍"的现代流控版。

## 3. 知识点在开源项目中的应用
- **projects/p05 扩展实验**：把单周期 CPU 改造为"每指令 3–5 拍 + 状态机控制"是多周期作业模板；README 给出 `cycle` 信号与状态寄存器插桩方法。
- **Rocket (Chipyard)**：其 PTW（page table walker）就是小 FSM：多次访存逐拍推进——1.2 FSM+1.4 stall 的生产级实例。
- **OpenTitan `prim_alert`/`alert_handler`**：大型微码式状态表可学其"状态→信号向量"编码风格（与 1.2 控制存储器一致）。
- **esp32**：BootROM 串口下载协议（slip 帧→命令处理）以固件 FSM 实现——同思想不同层。

## 4. 常见坑
- 状态合并需验证"任意两状态微操作序列不冲突"——漏检导致某指令走错路径（仿真过单测≠正确）。
- 使能寄存器未显式清零：一拍内所有旧值保持，多周期 datapath 忘写 `en=0` 分支会"数据残留"跨状态污染。
- `S_Decode` 同拍读 RF 与译码：RF 读是组合（L05 1.4），可同拍；改成同步读就要多一拍——接口时序合同先画清。
