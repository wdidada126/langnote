# L01 图形学入门（Introduction to Computer Graphics）

> 对应本目录 README 讲次 L01；官方 2019 视频 Lecture 01。阅读：FCG4 Ch.1。

## 1. 这门课在讲什么

计算机图形学（CG）研究**用计算机生成/处理图像**的理论与方法——更准确地说，是
"生成整个虚拟世界并把它成像成屏幕图像的一套方法"。它不是 OpenGL，也不只是光线追踪。

四大应用版图（也是全课四大板块）：

1. **建模（Modeling）**：几何如何表示——网格、曲面、隐式体（L10–L11）。
2. **成像/渲染（Rendering）**：3D 场景 → 2D 图像：光栅化（L04–L09）与光线追踪（L15–L16）。
3. **动画与模拟（Animation & Simulation）**：时间维度上的采样与物理（附录讲）。
4. **感知（Perception）**：人眼/相机如何接收光，颜色理论（L13）。

## 2. 核心示例：光栅化成像的三步

把 3D 世界画到屏幕上只有三步，但每一步都是几十年的学问：

1. **顶点（三角形）落在哪个像素里？** —— 采样（L08 的包含测试）。
2. **该像素用什么颜色？** —— 着色：材质、光照、纹理（L12–L14）。
3. **哪个三角形在前面？** —— 可见性：z-buffer（L07）。

图形学问题常可归结为**采样问题**：空间上采样（分辨率不足 → 锯齿）、时间上采样
（帧率不足 → 频闪/运动模糊不足）。这是贯穿 L08、L09、附录的信号处理视角。

## 3. 实时 vs 离线

| 维度 | 实时（游戏/交互） | 离线（电影/工业设计） |
| --- | --- | --- |
| 时间预算 | 16 ms/帧（60 FPS） | 分钟/帧 |
| 主路线 | 光栅化 + 屏幕空间近似 | 路径追踪/物理精确光传输 |
| 代表 | DirectX/Vulkan、Three.js、Filament | RenderMan、Blender Cycles、PBRT |

GAMES101 的独特之处是把两条路线放在同一套数学（变换、采样、光传输）下讲，
学完后能看懂任意渲染器的源码结构。

## 4. 与前后续讲的联系

- 本课是"自上而下"的：L01 给出全局地图，之后每一讲填一块。
- 成像的数学起点是**变换**（L04–L06）：世界坐标 → 相机坐标 → 屏幕坐标。
- 三条主线的分野在此埋下：光栅化"从像素找物体"，光线追踪"从物体（相机）找像素"，
  渲染方程则统一了"该给像素多少能量"（L15）。

## 5. 跨课程联系

- **18.06 线性代数**：全课的通用语言，L02 直接复盘。
- **CSAPP/DDCA**：图形管线本质上是一条硬件流水线（fetch → execute → writeback 的
  类比），GPU 是吞吐优化的极致产物；DDCA 中的并行单元视角有助于理解 GPU 的
  SIMD/SIMT 执行（详见 L07、CS149）。
- **CS231n / 深度生成模型**：近年的 NeRF、3D Gaussian Splatting、Dreamer 等"神经渲染"
  把 L06–L07 的相机投影 + L12 的体渲染换成了可微的神经网络表示——先学经典成像几何，
  再看神经渲染会非常顺。
- **GAMES202**：本讲的"实时/离线"分野在 GAMES202 展开为全局光照的工程实现
  （SSAO、屏幕空间反射、lightmap、探针等）。

## 6. 开源项目中的对应

- **Blender**：EEVEE（实时光栅化）与 Cycles（路径追踪）恰好是本课两条主线的成品。
- **Three.js**：浏览器里的光栅化管线，`WebGLRenderer` 的调用顺序即 L07 的管线。
- **raytracing-in-one-weekend**：一个周末实现的最小光线追踪器，对应 L15–L16。
- **Mesa (Vulkan/llvmpipe)**：llvmpipe 是纯 CPU 软件光栅化器，思路与本目录
  `projects/p2_rasterizer` 完全相同。

## 8. 自查问题

1. 为什么"哪个像素被哪个三角形覆盖"和"该像素什么颜色"是两个正交的问题？
2. 采样观点下，抗锯齿（L09）与运动模糊（附录）是同一问题的什么版本？
3. 实时渲染为何长期放弃光线追踪？（提示：可见性与时间的竞争关系。）
