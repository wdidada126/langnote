# L18 面向对象编译专题：动态派发与特征表

> 讲次：CS143 L18 ｜ 阅读：Cool Manual + Aiken  OO 编译讲义 ｜ 对应 PA5 最难部分（dispatch 序列）；本讲是"类型系统落到运行时"的压轴示范

## 核心概念

### 对象内存布局
```
COOL 对象（MIPS 下）:
  [0] 类型标签 typeID        ← e.type() / isvoid / case 分派依据
  [1] 特征表指针 dispTab     ← 本类的 dispatch table（方法）
  [2] self 回指（部分实现）
  [3..] 属性 slots（继承属性在前，自身在后——偏移编译期定）
字符串：标签 + 长度 + 字节数组（不可变 ⇒ 可驻留共享）。
```

### 特征表（Feature Table）= 虚拟方法表的教学版
- 每类一张表：`Object` 段（IO 方法 out_string/out_int/abort/type_name）+ 自定义方法段。
- 子类表 = 复制父类表 + 覆盖同名方法（偏移不变 ⇒ 父类型指针调用仍命中覆写版——**子类型替换的动态实现**）。
- 派发序列（COOL 抽象指令）：
```
load_self → load_disp_tab → load_off f_i → load_disp  → js
（取 self → 取表指针 → 取特征偏移 → 取入口地址 → 跳转）
静态派发 x@C.f：编译期直接算出 C 表 + f 偏移，绕过运行时查表——L10 lub 规则的运行时回报。
```

### 类层次分析（CHA）与去虚化
- 若 f 在全部子类中无覆写 ⇒ 直调；COOL 是封闭世界（无 dlopen）⇒ 一切 CHA 优化合法。
- 运行时反馈：单态热点（inline cache）——Smalltalk/V8 路线；COOL 教学止步于"特征表 + 手工优化"。

### case/isvoid 与类型标签
- `case e of x:T1 => ... :T2 => ...`：运行期比较 typeID 与 T_i 的"是否匹配（子类型）"——需要类型标签支持"祖先查询"，COOL 用类型对象表 + 顺序扫描；Java invokedynamic/Scala match 是更精致版本。

## 与前后讲的联系
- 上游：L10 的子类型/lub 决定"什么合法"，本讲决定"怎么做到"；L11 帧布局 + self 作为隐藏第 0 参数（闭包隐藏环境的 OO 同构）。
- 下游：L19 GC 的根扫描必须认识对象头与 slot 指针。
- 与 L15-L16：派发的间接跳转打断指令调度与内联——"OO 对后端的税"，PA5 中动态派发序列用寄存器最紧张（self 常驻建议）。

## 跨课程联系
- **CS242**：消息传递（Smalltalk）vs 虚表（C++）vs  traits 静态派发（Rust）——三种"多态合同"的运行时代价谱；COOL 特征表是教科书中间点。
- **CSAPP**：C++ 虚表在 objdump 里的 `{vtbl, ctor}` 双槽布局、Itanium ABI 的 offset-from-vptr——同一机制的工业变体。
- **CS110/6.S081 类比**：POSIX 的 vtable（struct file_operations）、syscall 表——"通过函数指针数组做运行时多态"不限于 OO 语言，OS 到处在用。
- **DDCA/CS61C**：间接跳转破坏 BTB 预测 → 派发开销的微架构根源；分支目标缓冲对 `js $t0` 的预测策略解释"为何虚函数慢"。

## 开源项目中的应用
- **CPython**：`tp_` 槽位的类型对象表就是特征表；PEP 590/向量调用（3.11）与 inline cache（3.12 specializing）= "去虚化 + 反馈"的当代演进，可与本讲 CHA 对照。
- **V8**：隐藏类（maps）+ inline cache + 多态 IC——动态派发性能工程的极限案例，博客文档充足。
- **Java/JVM**：itable vs vtable（接口方法后扫）、JIT 的 CHA 去虚化 + guard——与本讲逐条同构。
- **WASM GC**：2023 起的 GC 提案把 subtyping/vtable 设计进字节码（wasm GC types）——"为 OO 设计 ISA"的直接证据，可类比 COOL→MIPS。
- **rustc**：trait object 的 vtable（data ptr + vtable ptr 双宽指针）——单语言同时提供静态派发（泛型单态化）与动态派发（dyn）两条路，对比 COOL 的 `@C.f`。
