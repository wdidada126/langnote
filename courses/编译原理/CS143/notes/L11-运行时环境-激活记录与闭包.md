# L11 运行时环境：激活记录、静态链与闭包

> 讲次：CS143 L11 ｜ 阅读：龙书 ch7.1-7.3, 7.10 ｜ 对应 HW4 前半；projects/05 的解释器帧就是本讲的极简版

## 核心概念

### 激活记录（stack frame）布局
```
高地址
+------------------+
| 实参（调用者放）  |
| 返回地址          |  ← call 指令隐式压入
| 保存的 FP         |
| 静态链 SL         |  ← 嵌套语言才有（见下）
| 局部变量槽        |
| 保存的临时量      |
低地址            FP → 帧基准，SP → 栈顶
```
- 定长部分编译期可布局（L10 符号表偏移在此兑现）；变长（动态数组）存描述符指针。
- 调用约定（calling convention）规定：谁清栈、参数走寄存器还是栈、callee-saved 寄存器清单——CSAPP ch3 的 x86-64 表与 SPIM/MIPS 的 $a0-$a3、$sp/$fp/$ra 是两套答案。

### 存储策略三种
1. 静态分配（FORTRAN 77）：无递归，全局定址。
2. 栈分配（C/Pascal/COOL）：LIFO 纪律 ⇒ 帧可整体弹出；递归靠多帧解决。
3. 堆分配（Scheme/ML/Java）：帧生命周期不受 LIFO 约束 ⇒ 闭包 = 函数对象 + 捕获环境，活在堆上，交给 GC（L19）。

### 访问链：静态链 vs  Display
- 嵌套过程访问非局部变量：沿静态链（access link）逐层走到目标作用域帧，偏移编译期已知——`SL^d + o` 定位（d=静态深度差）。
- 优化 display：全局数组缓存各层最新指针，调用时保存/恢复——空间换链长，函数式语言里几乎绝迹（堆帧无序）。
- 课堂金句：**栈语言里"当前环境的链"与"控制历史的链"重合，堆语言里两者分离**——动态链 vs 静态链。

### 闭包编译（龙书 7.10 精选）
```
fun f x = let val y = x*2 in fn z => y + x + z end
编译方案：自由变量 y, x 无法放进栈帧（f 返回后帧销毁）
  ⇒ 堆分配记录 R = {y, x}；返回 Closure {codeptr, R}
  ⇒ 内层函数指针带环境字段，调用时以"额外隐藏参数"传入。
Scala/LambdaJ 的 "closure conversion"、Rust 的 move 闭包捕获是同一思想的现代方言。
```

## 与前后讲的联系
- 上游：L10 符号表给出每个变量的 (作用域深度, 帧偏移)；本讲把坐标翻译成地址。
- 下游：L12-L13 生成 IR 时"临时量存哪"依赖本讲；L15 代码生成的 prologue/epilogue、L18 对象头与本讲布局衔接；L19 的 GC roots 正是"栈上所有帧的活跃指针槽"。
- COOL 特例：无嵌套 ⇒ 无静态链，但**每个方法需要 self 指针与类表基址**（L18）——本讲模型的最小改造。

## 跨课程联系
- **6.S081**：xv6 的 trapframe/内核栈切换 = "激活记录"在 OS 侧的放大；`main` 之前的 `crt0`、ELF 加载即"第一个帧怎么来"。
- **CSAPP**：ch3.2 整章是本讲的机器级实证（%rbp 链、`leave` 指令、varargs 布局）；buffer overflow 攻击 = 越界写坏返回地址——运行时环境安全性的第一课。
- **CS61A**：环境模型（帧 + 父指针）与教科书静态链**完全同构**；CS61A 用 Python dict 模拟，本讲用内存偏移——同一抽象两种宿主。
- **DDCA/CS61C**：MIPS 的 $sp/$fp 约定、延迟槽对 call 序列的影响。

## 开源项目中的应用
- **RPython**：PyPy 帧对象堆分配 + JIT 的"虚拟帧内联"，把栈语义从堆布局里重建。
- **Wasmtime/WASM**：线性内存里没有原生栈（早期），Shadow stack 扩展正是"给虚拟机补一套激活记录"的标准化努力。
- **CPython**：帧对象（PyFrameObject）堆分配，3.11 起引入 "框架实例"预分配池——本讲三种策略的活标本。
- **libunwind / DWARF CFI**：`.eh_frame` 表编码了"如何从任意 PC 恢复调用者帧"——栈展开/异常/性能剖析共用；编译器后端有义务为每个帧发射 CFI（PA5 里被省略的细节）。
