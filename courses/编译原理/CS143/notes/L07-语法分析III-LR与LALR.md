# L7 语法分析 III：自底向上、LR/LALR 与冲突

> 讲次：CS143 L7 ｜ 阅读：龙书 ch4.5-4.7 ｜ 对应 HW2 后半；本讲是全课程"最硬的笔试知识点"

## 核心概念

### 规范归约 = 最右推导的逆
- 句柄（handle）：当前句型的最左可归约短语；LR 分析每步识别栈顶句柄并归约。
- 移进-归约：把输入前缀的"活前缀（viable prefix）"压栈，状态记录"我认到了哪个产生式前缀"。

### LR(0) 项目集规范族（手推例题，考试级）
```
文法增广: E' -> E ; E -> E + T | T ; T -> T * F | F ; F -> ( E ) | id
CLOSURE/ GOTO 算法:
  I0 = closure({E' -> .E, E -> .E+T, E -> .T, T -> .T*F, T -> .F, F -> .(E), F -> .id})
  GOTO(I0, E) = I1: {E' -> E., E -> E.+T}   ← 注意归约项与移进项可以共存
  ...典型状态数: 本例 LR(0) 约 12 个状态
LR(1) 项目: [A -> α . β, a]  前瞻 a 参与 closure（ Lookahead 传播算法 ）
  F->.id, +   与   F->.id, *   是两个不同项目 ⇒ 状态爆炸（可达数百）。
SLR(1): 用 FOLLOW(A) 近似 LR(1) 前瞻——构造便宜（复用 LR(0) 族），精度居中。
LALR(1): 合并 LR(1) 中"核心相同"的状态——精度接近 LR(1)，状态数接近 LR(0)。
  yacc/bison 生成的就是 LALR(1)（PA2 使用的就是它）。
能力排序: LR(0) ⊂ SLR ⊂ LALR(1) ⊂ LR(1) ⊂ 所有 CFL；LL(1) ⊂ LR(1)，但 LL(1) 与 SLR 互不包含。
```

### 冲突与消解
- 移进/归约冲突（经典：悬挂 else，`else` 在栈上时既可移进配最里 if 又可归约外层 then-part）：bison 默认**移进** ⇒ 与最近 if 配对。
- 归约/归约冲突：文法真二义或 SLR 前瞻过粗（`S -> L = R | R; R -> id` 中 `id =` 场景，SLR 冲突而 LR(1) 无冲突——考试名题）。
- 调试心法：冲突报告里的状态号 → 回看项目集 → 找"哪个产生式前缀共享状态"。

### 语法树重建
- LR 分析器归约时同步归约语义动作（L9 的 SDD 属性通过属性栈传递）——yacc 规则体里 `$$ = $1 + $2` 的属性栈就是被归约子树的"临时 AST 节点"。COOL PA2 用 bison 构 AST 正是此机制。

## 开源项目中的应用
- **bison/yacc**：LALR(1) 工业标准；`bison -v` 的 .output 文件打印项目集与冲突，学习 LR 的最佳实验台。
- **tree-sitter**：GLR——LR(1) 栈在冲突点分裂多版本再合并，解决真实语言（C++ 的 `T * p;` vs 表达式）需要上下文的问题。
- **JavaCC/PegJS**：走 LL 极端；对比它们与 bison 对同一语言的可分析性差异是极好的作业延伸。
- **PHP（Zend）**：`zend_language_parser.y` 至今是 LALR 文法的活教材，注释里能看到大量冲突消解实录。
