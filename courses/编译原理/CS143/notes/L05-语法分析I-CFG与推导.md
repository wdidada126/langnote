# L5 语法分析 I：上下文无关文法、推导与语法树

> 讲次：CS143 L5 ｜ 阅读：龙书 ch4.1-4.2 ｜ 配套：projects/02_parser（文法先行）

## 核心概念

### CFG 四元组与记法
- `G = (N, T, P, S)`：非终结符、终结符、产生式、开始符号。
- 推导 `⇒`（最左推导 ⇒lm，最右推导 ⇒rp 又称规范推导）；由最右推导逆向 ⇒ 句柄剪枝 ⇒ 自底向上分析（L7 的根）。
- 语法树 vs 推导序列：一棵树折叠了同一句子的多种推导顺序；**二义** = 同一句子两棵不同的树。

### 语法制导定义入门（为 L9 铺垫）
- 在树节点上挂属性/动作：`E -> E1 + T { E.val = E1.val + T.val }` 就是"翻译"的雏形。

### 文法 equivalence 与四大转换（作业必考）
1. **消除左递归**（自顶向下前置条件，L6）：
```
直接: A -> A α | β      （β 不以 A 开头）
改写: A  -> β A'
      A' -> α A' | ε
间接: P -> Q a, Q -> P b 先代入消环再消除。
```
2. **提取左公因子**（LL 前置条件）：`A -> αβ | αγ` ⇒ `A -> α A', A' -> β | γ`。
3. **ε 产生式清理**：先求 nullable 集，再对每条产生式枚举可选删除。
4. **化简**：删除不可达/不可生成的符号。

### 经典二义性例题（会背会修）
- 悬挂 else：`if e then S (else S)?` —— 默认与最近未匹配 if 结合；LR 中用 shift 冲突默认解决（L7）。
- 算符优先级：`E -> E + E | E * E | id` 允许 `2+3*4` 两棵树；修复为标准分层文法：
```
E -> E + T | T
T -> T * F | F
F -> ( E ) | id
```
- 后缀文法 `S -> S S + | S S * | a`（逆波兰）无二义但任何自顶向下分析器都无法处理——说明文法类与分析器能力互相约束。

## 正则表达式 → 文法
- 每个正则可机械翻译为 CFG：`R -> R|R'`、`RR` 连接、`R* -> R* R | ε`；反之右线性文法 ≡ 正则语言。
- 词法层用正则（规则局部、可判定等价），句法层必须 CFG（嵌套结构）——分工由乔姆斯基层次给定。

## 与前后讲的联系
- 上承 L3-L4：token 是终结符集 T；下启 L6-L8：所有分析算法都是"给一个句子，判定是否 ∈ L(G) 并构树"。
- COOL 文法（Cool Manual 附录）就是本讲产物：PA2 的 bison 骨架直接抄它。
- L9 的 SDD、L12 的 AST 都建立在"树存在且（在分析器选择的文法类内）唯一"之上。

## 跨课程联系
- **6.006/CS170**：CFG 成员判定是 CYK 动态规划 O(n³)——一个"给文法定元变量、给子串定区间"的经典 DP；这与龙书算法课视角完全对得上。
- **CS242/CS3110**：文法即 ADT：产生式 = 构造函数，AST = 归纳定义的载体，模式匹配 = 树消归纳；"文法决定内存布局"是编译与 PL 的双向视角。
- **MLC/10-414**：TVM 的 Relay/TIR 各是一种文法；图重写规则与产生式应用同构。

## 开源项目中的应用
- **tree-sitter**：grammar.js 即 CFG；官方文档"创建语法"一章大量使用本讲的左递归改写技巧（把 `E->E+E` 声明为 prec.left 由生成器代劳）。
- **rustc**：`rustc_parse` 对手写递归下降（L6 路线）与文法演进的取舍文档丰富。
- **CPython**：PEP 617 从 LL(1) 迁移到 PEG——PEG 永远无二义（首匹配优先），是对"二义消解"的另一种答案。
- **ANTLR**：ALL(*) 分析器直接吃左递归文法（自动改写），可用来对照本讲手工改写。
