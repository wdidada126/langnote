# L16 寄存器分配：活跃性、干涉图与图着色

> 讲次：CS143 L16 ｜ 阅读：龙书 ch9.3, 9.6 + Chaitin 论文 ｜ 对应 HW5 后半；PA5 的"寄存器 vs 栈槽"抉择在本讲有理论答案

## 核心概念

### 问题陈述
- 输入：RM 程序（无限虚拟寄存器/临时量）+ 目标机可用寄存器数 K。
- 输出：≤K 个物理寄存器的赋值，或标记"需要 spill 到栈槽（L11 帧内）"。
- 最优 K 着色可判定为 NP 完全（K≥6 一般图着色），所以一切实践都是启发式。

### 活跃性（Liveness）= L14 框架的直接应用
```
后向框架，域 = 变量集，交汇 = ∪：
  USE(s)  = 读取先于写入的变量；DEF(s) = 写入的变量
  OUT[s]  = ∪_{s∈succ} IN[s]
  IN[s]   = USE[s] ∪ (OUT[s] − DEF[s])
live 点：语句之后仍会被读；use-before-def（UBD）是"之前"版本——考试喜欢两者混考。
```

### 干涉图与着色循环（Chaitin 1981）
```
节点 = 活跃值（区间：def 到下一次 def）；边 = 某点同时活跃（干涉）。
算法（寄存器着色分配 RGA）:
  push 可移除节点（度数 < K，简化堆栈）
  全部简化成功 → 弹栈逐节点选色（避开邻居已用色）
  卡住（全 ≥ K）→ 选"spill cost 最低"节点驱逐：cost = 物化代价/使用频度×循环深度
  驱逐 → 重写程序（spill 槽 + reload）→ 重建图循环。
precolored 节点（物理寄存器、调用约定 clobber）：同色才连边——现代实现（LLVM Greedy）的复杂化来源。
```
- 图着色对 RM 程序的最优性：RM 程序着色最优 ⟺ 分配最优？（"无 spill 时着色必优"是龙书 9.6.3 定理级考点；一般情形着色法不最优，有反例）。
- 复制传播与合并（coalescing）：`b = a` 且无干涉 ⇒ 合一点——着色前规范化（SSA 风格的 φ 消除也靠它，与 L17 呼应）。

### 线性扫描（Poletto & Sarkar 1999）
- 按活跃区间起点排序，活动表维护当前区间，区间结束即释放；溢出选"活最久"者。
- 速度换质量：JIT（HotSpot、V8）与 Cranelift 的默认；LLVM Fast RegAlloc 同源。

## 与前后讲的联系
- 上游：L13 生成的临时量数量直接决定干涉图规模——IR 奢侈命名 + 本讲回收是标准分工；SSA 让"值"概念干净（每 def 一版本），干涉图更准。
- 下游：L17 优化在分配前后各跑（分配前减少压力：复制传播；分配后清 spill：peephole）。
- 与 L15：Sethi-Ullman 给"顺序保最小寄存器"，着色给"全局重排寄存器"——两代方案解决同一 issue。

## 跨课程联系
- **DDCA/CS61C**：寄存器写回端口冲突/流水线旁路是硬件侧"干涉"；编译器着色与硬件 scoreboard 共同维护 WAR/WAW。
- **CS149**：GPU 寄存器预算（每线程 ≤255）下的 occupancy 权衡 = "带资源约束的着色"，NVIDIA ptxas 的 -maxrregcount 是命令行化的 spill 策略。
- **6.006/CS170**：图着色 NP 完全 + 贪心近似——近似算法在编译器里的真实战场；简化堆栈的工作列表 = 优先队列应用。
- **CSAPP**：函数调用约定里"谁保存哪些寄存器"就是着色器的先着色约束；`objdump` 看 prologue 的 `push %rbx` 序列可反推分配决策。

## 开源项目中的应用
- **LLVM**：QoS-based Greedy Allocator（chaitin-*.cpp 已归档）；`-fdump-regalloc`/机器验证 dump 可观察干涉图与驱逐链。
- **rustc**：无自有分配器（复用 LLVM），但 MIR 的 SSA 式命名（每个临时量单次赋值）让下游着色质量显著受益——前端"配合着色器"的设计例证。
- **V8 TurboFan / HotSpot C2**：Chaitin 风格与线性扫描的混合变体（移动缩减、区间分裂），JIT 场景文档丰富。
- **CBMC/Z3**：把分配/调度编码为 ILP/SMT 求解（"编译作为约束满足"的学院派路线，GCC 的 RA 也曾有 ILP 实验）。
- **RPython/PyPy JIT**：寄存器分配在 trace 上进行，trace 的线性结构让线性扫描近乎最优——"简化 IR ⇒ 简化分配"的设计样本。
