# L15 代码生成：目标机器模型、指令选择与调度

> 讲次：CS143 L15 ｜ 阅读：课程后端讲义 + 龙书 ch8 代码生成相关节（9.5 调度思想）｜ 配套：projects/05_backend（IR→解释执行/汇编风格输出）；对应 PA5 理论

## 核心概念

### 目标机器抽象
- 有限寄存器 + 存储；寻址模式（基址+变位+比例）；条件码 vs 比较-分支两步（x86 vs MIPS/RISC-V 的核心差异——COOL 目标 MIPS 无标志位）。
- 代价模型：每条目标指令一个 cost，指令选择最小化总代价。

### issues：代码生成的三大难
1. **寄存器不足**：生成"寄存器机器程序"（RM 模型：无限寄存器的理想机），再后接着色/驱逐（L16）。
2. **指令选择**：模式匹配/树覆盖（Burg 生成器、LLVM SelectionDAG 的 pattern、GNU 的 md 文件）。
3. **顺序/调度**：满足依赖 + 寄存器最小化（Sethi-Ullman！）+ 流水线（DDCA 视角）。

### Sethi-Ullman 编号（考试与实践双料）
```
对表达式树自底向上:
  叶: su = 0
  内部节点(左 l, 右 r):
    l == r -> su = l
    l != r -> su = max(l, r) + 1   ← 更精细: 若不等则大者+1（先算大者省寄存器）
性质: su(root) = 求值该树所需的最少寄存器数；调度=按 su 降序访问兄弟。
例: a*(b+c) + d*e*f → su 传播：乘号链 su=1，加法根 su=2 ⇒ 两寄存器足够，
且必须先生成 su 大的子树——"先算 d*e*f 还是 b+c"由 su 决定。
```

### 从 IR 到汇编的三步（PA5 路线）
1. 每条三地址翻译为 RM 指令（`t = x op y` → load/alu/store 或寄存器直用）。
2. 寄存器分配（L16）+ spill：溢出槽写回帧内（L11 布局的延续）。
3. peephole：`x = y; z = x` → `z = y`；`cmp+jz` 融合——局部模式重写，机械但收益稳定。

### 指令调度入门
- 依赖图 + ASAP/ALAP + 关键路径；保留间隔（reservation table）模拟流水线吞吐——本质是列表调度。
- 硬依赖（数据）与资源冲突（功能单元）分开建模：编译器管前者，体系结构保证后者可预测。

## 开源项目中的应用
- **LLVM**：TableGen（.td）声明指令与 pattern，生成匹配器 + 调度模型；GlobalISel 是 SelectionDAG 的继任实验。
- **GCC**：RTL + machine.md（`(define_insn ...)`）——与 TableGen 两条技术路线的百年对照。
- **rustc**：后端复用 LLVM，但 `mir`→codegen 的 drop 插入是"代码生成参与语义"的独特设计（LLVM 前端义务）。
- **WASM 工具链（Cranelift/Binaryen）**：regalloc 集成 + 无标志位的"类 RISC"目标——COOL→MIPS 的现代精神续作。
- **esbuild/SWC**：JS→JS 的"代码生成"演示：同一 IR 模型可输出高级语言（反向下沉），指令选择不限于机器码。
