# L1 Introduction：编译器结构与翻译阶段总览

> 讲次：CS143 L1 ｜ 阅读：龙书 ch1 ｜ 配套：projects/01 之前的课程总览；本讲建立"阶段流水线"心智地图

## 核心概念

### 编译器 vs 解释器
- 编译器：源程序 → 目标程序（翻译与执行分离，一次翻译多次执行）。
- 解释器：读入 AST/IR 节点直接求值（翻译与执行交织，如 CS61A 的 Scheme 解释器）。
- 现代系统常是混合体：CPython 编译到字节码再由虚拟机解释；V8 解释器 + JIT 分层；COOL 编译器直接出 MIPS 汇编。

### 翻译阶段（前端—中端—后端）
1. 词法分析：字符流 → token 流（L3-L4）。
2. 语法分析：token 流 → AST（L5-L8）。
3. 语义分析：符号表、作用域、类型检查（L9-L10）。
4. 中间表示 / 中间代码生成（L12-L13）。
5. 机器无关优化：数据流分析驱动（L14, L17）。
6. 代码生成：指令选择、寄存器分配、指令调度（L15-L16）。
7. 目标代码优化。
- 贯穿全程：**符号表**（symtab）与**错误恢复**（error recovery）。编译器是"错误检测器"：每阶段都可能有合法输入上的诊断义务。

### 为什么要有 IR
- 没有 IR：m 种语言 × n 台机器 = m·n 个编译器。
- 有 IR：m + n（GCC、LLVM 的经典论证）。IR 是前后端的"合同"，也是优化算法的舞台（数据流分析只在某种 IR 上定义）。

## 关键图景：一次编译的完整旅程（以 MiniC 语句为例）

```
输入: while (i < n) { s = s + i; i = i + 1; }
词法: [while,(,i,<,n,),{,s,=,s,+,i,;,...]
语法: WhileStmt(Lt(Var i,Var n), Block[Assign,Assign])
语义: i,n,s:int 已声明，条件为 bool —— 通过
IR  : L1: t1 = i < n; ifz t1 goto L3; t2 = s + i; s = t2; ...; goto L1; L3:
优化: 归纳变量/强度削弱可把 i+1 的加法换成寄存器自增
后端: cmp %esi,%ebx; jge ...; add ...; jmp L1
```

## 开源项目中的应用
- **LLVM**：clang(前端) → LLVM IR(中端) → llc(后端) 是本讲阶段模型的工业实现。
- **GCC**：gimple RTL 双 IR；rustc：MIR/THIR/HIR 多层 IR 同样遵循本讲分层。
- **tree-sitter**：只覆盖本讲"语法分析"一步但面向 IDE 增量场景，说明阶段划分也允许"只要 AST"。
- **CPython**：ast.c(词法+语法)、compile.c(AST→字节码)、ceval.c(解释执行) 恰好是三个经典阶段的教学样本。
