# L3 词法分析 I：正则语言与有限自动机

> 讲次：CS143 L3 ｜ 阅读：龙书 ch2、ch3.1-3.6 ｜ 配套：projects/01_lexer（手写 DFA 词法器）

## 核心概念

### 词法分析的任务边界
- 输入字符流 → token 流：`{枚举类型, lexeme, 属性(值/位置)}`。
- 剥离空白与注释；最长匹配（maximal munch）决定边界：`x<=y` 中的 `<=` 优先于 `<` 后接 `=`。
- 词法器**不做**句法判断：`int int` 是两个合法 token，错误归语法层（但关键字表本身就是词法层的"上下文微知识"）。

### 三个正则代数（必须会算）
- 运算：并 `r|s`、连接 `rs`、Kleene 闭包 `r*`；优先级 `* > 连接 > |`。
- 恒等式：`(r*)* = r*`、`(r|s)* = (r*s*)*`、`r|r = r`（注意**不**满足消去律）。
- 语言方程解：`L = M L ∪ N` 的唯一解是 `L = M* N`（Arden 引理）——子集构造与正则→NFA 递归展开都靠它。

### 自动机族谱
- NFA：ε 转移、多栖状态；DFA：确定；两者**等价**（子集构造）。
- 正则表达式 ≡ NFA ≡ DFA ≡ 正则语言；标识符/注释等词法类别全部落在正则层。
- **无限嵌套括号/注释配对不是正则语言**（泵引理）——这划出了词法/语法的分工线。工程折中：给嵌套深度设上限（如 16 层，深度编进状态→仍 DFA），或让词法器持一个显式计数器（严格说是下推自动机，见 L4）。

## 算法与例子：正则 → NFA（Thompson）→ DFA

Thompson 构造：每个正则子式 → 带起止状态的小自动机，按 `|`（新起点 ε 到两支）、连接（首尾 ε 串接）、`*`（回边 ε）组合。

```
例：标识符 regex  id = letter (letter|digit)*
Thompson NFA 状态数 ≈ 3；子集构造后 DFA：q0 --letter--> q1 --letter|digit--> q1(接受)
例：数字  num = digit+ ( . digit+ )?  ( . ε )?
子集构造关键步骤：
  A = ε-closure({0}) = {0,1,2,5}
  on digit: {1,2,5} → move={2,6} → closure={2,6,7} = B(接受)
  ...得到 4~5 状态的 DFA（教学作业常考，务必手推一遍）
```

实现视角（供 projects/01 使用）：手写词法器通常不生成 DFA 表，而是**直接编码 DFA 状态转移为 switch/goto**——本质仍是"一个当前状态 + 输入字符 → 下一状态"。

## 跨课程联系
- **6.006/CS170**：子集构造是"幂集图上的 BFS"，ε-closure 是传递闭包（Floyd-Warshall/图可达性的特例）；NFA 判定为 P、正则等价性 PSPACE 完全——算法课的判定复杂度在这里落地。
- **CS61C/DDCA**：正则→DFA 的硬件实现就是组合逻辑 + 状态寄存器；grep/sed 的加速历史上用过 DFA 表在缓存中的布局技巧。
- **CSAPP**：`lex` 生成的表驱动循环对 i-cache/BTB 的行为，是"自动机即程序"的机器级注脚。
- **CS242/CS3110**：token 类型枚举 ≈ 代数数据类型的构造函数；`match` 分支即状态转移表。

## 开源项目中的应用
- **Flex**：正则→DFA 表的最小生成器（L4 展开）。
- **re2 / Rust regex crate**：可回溯正则的 NFA/DFA 模拟库——PCRE 灾难性回溯的反面教材，教学用 DFA 思路。
- **CPython `tokenize.py`**：纯正则表驱动，展示"不用生成器也能写出够用词法器"。
- **tree-sitter**：词法规约写在 grammar.js 里，内部用 GLR 语法 + 手写 DFA 词法层，正则→自动机管线内置。
- **LLVM Support/LexOps**：clang 词法器手编状态机，理由与 projects/01 相同（性能 + 错误信息可控）。
