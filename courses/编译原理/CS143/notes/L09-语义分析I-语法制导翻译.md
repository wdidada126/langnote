# L9 语义分析 I：语法制导翻译与属性文法

> 讲次：CS143 L9 ｜ 阅读：龙书 ch5.1-5.4 ｜ 对应 HW3 前半；projects/03 的类型综合即 SDD 的应用

## 核心概念

### 语法制导定义（SDD）= CFG + 属性 + 语义规则
- 属性两类：**综合属性**（S 属性，值自子节点向上）与**继承属性**（I 属性，值自兄弟/父节点向下）。
- 依赖图必须是 DAG 才有求值顺序；S 属性 → 随 LR 分析边归约边算；L 属性 → 随 LL/递归下降按文法顺序算。
- 属性文法（attribute grammar）= 带属性的文法，静态语义的"声明式规格"。

### 经典例题：进制转换（综合+继承的教科联姻）
```
输入 n.b（如 101.101b = 5.625）
SDD:
  N -> L . M     N.ic = 1;  N.fc = base
  N -> L         N.ic = 0;  N.fc = base
  N -> . M       N.ic = 1;  N.fc = 1
  L -> L1 B      L1.ic = ic; L.val = L1.val * base + B.val   (综合)
                 B.ic = ic + 1                                  (继承!)
  M -> B M1      M.val = B.val / base^... → 用 pos 继承属性:
  改进版(考试常用): N.s = 整数位长度(继承), M.pos = N.ic - 1 ...
关键观察：B 需要知道自己在第几位 ⇒ 纯 S 属性做不到 ⇒ 继承属性是"上下文"的载体。
```

### 翻译模式（translation scheme）
- 语义动作嵌入产生式的具体位置：`{...}` 在符号前/之间——递归下降里动作位置 = 代码插入点。
- 底部语义规则（bottom-up only）≈ 属性全综合 ≈ SDT 可被 LR 驱动（yacc 动作为何都写在规则末尾）。
- 消除继承属性技巧：把信息"下沉"到显式参数（projects/03 的类型检查器用自顶向下的 expected-type 参数，正是继承属性的过程化编码）。

### S-DTLR vs 手写遍历（PA2/PA3 的两条路线）
- yacc 路线：属性栈，一遍完成——快但难调试。
- AST 路线：先建树，再显式两次遍历（综合 pass + 继承 pass）——COOL 课程选它（PA3 用 visitor），因为语义、IR、优化各自需要多趟。
- 等价性：任何 SDD 都能翻译为"带属性字段的 AST + 遍历顺序"——这就是"编译器 passes 化"的理论来源。

## 跨课程联系
- **CS3110/CS242**：属性文法 ≈ catamorphism（综合）+ anamorphism 上下文（继承）；F# / Kotlin 的"elaboration 阶段"就是继承属性物化。
- **6.006/CS170**：S 属性求值 = 树形 DP；L 属性求值 = 树形 DP + 先序传播；和"树上背包"共享依赖拓扑。
- **MLC/10-414**：自动微分的前向/反向模式正是"继承/综合"两种信息流——反向模式 AD ≈ S 属性遍历（梯度沿使用边向上汇总），与属性文法的对偶结构一致（Swiridenko 2018 指出此同构）。

## 开源项目中的应用
- **LLVM/Clang**：Sema 阶段把类型作为 Expr 属性存入 AST（`Expr::getType()`），继承的 expected type 通过函数参数传递——教科书 L 属性的工程化。
- **rustc**：HIR lowering + type inference（`infcx`）是"约束求解版属性文法"：类型变量 = 待求属性，unify = 传播。
- **GHCI/Glasgow Haskell 的类型推导**：HM 推断可视为"带合一的属性文法"（DAG 依赖 + 合一求值）。
- **BNFC/ATD 等文法工具**：从文法自动生成带属性字段的 AST 骨架——属性文法作为一等规格的当代传承。
