# L20–L22 哈希：hash code 契约、分离链法、扩容与好哈希函数

> 对应 spring2024 L20–L22：hash code、separate chaining、load factor 与再哈希、字符串哈希与通用哈希。作业：Lab6（HashMap）、HW 相关。项目对应：projects/hashmap。

## 1. 核心概念

- **哈希思想**：把 key 映到 `0..cap-1` 的桶（bucket），期望 Θ(1) 定位；冲突用链/探测解决。
- **hashCode 契约（L07 equals 契约的续集）**：`a.equals(b) ⇒ a.hashCode()==b.hashCode()`；数组/自定义类若重写 equals 必须同步重写 hashCode：
  ```java
  @Override public int hashCode() { return Objects.hash(id, name); } // 组合字段
  ```
- **分离链法（separate chaining，Lab6 实现）**：每桶一条 SLList/DLList：
  ```java
  public V put(K key, V val) {
      int i = Math.floorMod(key.hashCode(), buckets.length); // floorMod 处理负 hash
      for (Node n = buckets[i]; n != null; n = n.next)
          if (n.key.equals(key)) { V old = n.val; n.val = val; return old; }
      buckets[i] = new Node(key, val, buckets[i]); size++;
      if ((double) size / buckets.length > MAX_LOAD_FACTOR) resizeAndRehash();
      return null;
  }
  ```
- **装填因子 α = size/cap**：α ≤ ~0.75 保证链长期望 O(1)；超过则**倍增扩容 + 全量再哈希**（与 L17 同构：单次 Θ(n)，摊还 Θ(1)，且 n 次插入总再哈希成本 Θ(n)）。
- **字符串哈希与 Horner 法（L22）**：`h = h*31 + c`；31 是奇素数、移位可优化（`31*i == (i<<5)-i`），且溢出回绕反而有益（低成本模 2³²）。
- **通用哈希（universal hashing）**：随机选 `h(x) = ((a*x+b) mod p) mod m`，使任意两键碰撞概率 ≤1/m——对抗"碰撞攻击"（JDK 不对 String 做，但 `HashMap` 对 key hash 做扰动：`h ^ (h >>> 16)`，把高位差异搬进低位桶选择）。

## 2. 复杂度视角

| 操作 | 期望 | 最坏 | 条件 |
| --- | --- | --- | --- |
| get/put/remove | **Θ(1)** | Θ(n) | 期望需好哈希 + α=O(1) |
| 扩容再哈希 | — | Θ(cap+size) | 摊还进 put |
| 迭代 | Θ(cap+size) | | 要扫空桶（TreeMap 迭代才按 key 数）|
| key 的 hashCode | Θ(key 长度) | | String 有缓存 hash 字段，首次后 O(1) |
| TreeSet(红黑) 对照 | Θ(log n) | Θ(log n) | 哈希不保证序 |

- 上承：L07/L09 的 equals/hashCode、L16 的桶内链表、L17 的倍增摊还——HashMap 是全课第一个"组合已学技术"的大结构。

## 4. 跨课程联系

- **CS61A**：61A 直接 `d[key] = v` 从不解释；61B 补上"字典为何平均 O(1)"。61A Scheme 的 `eq?/equal?` 区分恰好对应 hashCode 该用值还是引用——两课在此汇合。
- **6.006/CS170**：6.006 用简单均匀哈希假设（UHA）给 Θ(1+α) 期望证明；CS170 再讲 2-universal + Carter-Wegman 碰撞界。本课的 floorMod 与扰动是"工程补全"。
- **CSAPP**：桶数组 + 链节点 = 二次间接 + 指针追逐；开地址法（线性探测）缓存友好但删除要墓碑——CSAPP 的 cache 视角直接改写哈希实现选型（Rust hashbrown/Python compact dict 都选探测类）。
- **OS**：dentry cache、连接跟踪表全用哈希 + 链；页表可视为"以虚拟地址高位为 key 的函数式大哈希"。
- **DDCA**：硬件 cache 组相联映射 = 桶（组），way = 链长——α 过高即"组内溢出"。

## 5. 开源项目应用

- **JDK**：`HashMap`（JDK8+：树化桶、`hashCode` 扰动、`tableSizeFor` 取 2 幂使桶定位变 `(cap-1) & hash`）；`ConcurrentHashMap` 分段 CAS + synchronized 桶头。
- **Redis**：dict 双表渐进式 rehash（每次操作迁一点，避免一次性 Θ(n) 尖刺）——把 L21 的摊还分析做成了实时系统可用性方案。
- **RocksDB**：Bloom filter（哈希的 cousin：位图 + k 哈希函数）挡掉 99% 无意义磁盘查；block cache 以 key hash 定位。
- **Git**：`hashmap`（commit-graph、index 用 FNV/x31 哈希 + 开放寻址）；pack 的 IDX 文件用"首字节 256 桶 + 桶内二分"= 桶数组思想。
- **Lucene**：term dictionary 的 FST/BlockTree 本质是以词项哈希/排序为核心的多级结构。
