# L12–L14 异常体系、JUnit 测试与调试

> 对应 spring2024 L12–L14：受检/非受检异常、try-with-resources；JUnit 5、等价类/边界值、覆盖率；IDEA debugger。作业：Lab3（TestArrayDeque）。

## 1. 核心概念

- **异常继承树**：`Throwable ← Exception ← RuntimeException`；`Error`（OOM/StackOverflow）程序不应捕获。
  - **受检（checked）**：编译器强制处理（catch 或 throws），如 `IOException`——"可恢复的外部世界故障"。
  - **非受检（unchecked）**：`RuntimeException` 及子类（`NullPointerException`、`IndexOutOfBoundsException`、`IllegalArgumentException`）——通常是调用方 bug。
- **throw / throws / try-catch-finally**；`finally` 在 return 后仍执行（老式资源关闭的补救）。
- **try-with-resources**：实现 `AutoCloseable` 的对象按构造逆序自动 close：
  ```java
  try (BufferedReader r = Files.newBufferedReader(p)) {
      return r.readLine();
  } // 自动 close，异常时也不泄漏
  ```
- **失败快（fail fast）**：构造/入口即校验参数 `throw new IllegalArgumentException("capacity must be > 0")`，比让错误扩散到深处便宜得多。

## 2. JUnit 5 与测试设计

- 注解：`@Test` `@BeforeEach` `@ParameterizedTest` `@Disabled`；断言 `assertEquals(expected, actual)`（顺序不可反）。
- **等价类划分 + 边界值分析**：对 `subList(from, to)`，边界 `from=0`、`to=size`、`from>to`、空表是必测点。
- **测试金字塔实践**：Lab3 要求"先写测试再写实现"（TDD）：给定 spec → 列测试案例表 → 红→绿→重构。
- **Mock 与覆盖率**：行覆盖高 ≠ 正确（判据覆盖/路径覆盖更强）；助教 autograder 用随机种子 + 参考实现对比做 diff testing。

## 3. 调试方法论

- 断点 → 条件断点（`i == 1023`）→ watch 表达式 → evaluate；比 System.out 快一个数量级。
- 栈回溯（stacktrace）读法：最上一帧是抛出点，沿帧向下找"我写的最后一行"。
- 性能剖析初阶：YourKit/flight recorder 找热点，为 L15 渐近分析提供"实测 vs 理论"的对照。

## 4. 复杂度视角

| 机制 | 成本 | 说明 |
| --- | --- | --- |
| 不抛异常路径 | ≈0 | JIT 下 try 块零开销 |
| 抛/构造异常 | Θ(栈深) | 填栈回溯；热点循环内高频抛异常是性能反模式 |
| JUnit 断言 | O(断言成本) | assertEquals 对集合做 equals ⇒ 可能 O(n) |

## 7. 开源项目应用

- **JDK**：`java.util` 的 API 表逐方法列出所抛异常（`Iterator.next` 抛 `NoSuchElementException` 正是 Lab 手写迭代器必须遵守的契约）；`try-with-resources` 是 JDK7 为 I/O 泄漏 epidemic 而生。
- **Lucene**：`CorruptIndexException`（受检）把所有索引损坏路径显式暴露给调用方，是"checked exception 用于可恢复外部故障"的典范。
- **Git (JGit)**：`JGitInternalException` 包装受检异常为 unchecked，反映 Guava/现代框架"受检异常传染太广"的工程反思。
- **JUnit 本身**：5.x 的 `Assertions`、动态测试 `@DynamicTest` 即本讲工具链的源头。
