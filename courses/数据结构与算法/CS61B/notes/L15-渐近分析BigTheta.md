# L15 渐近分析：Big-Θ 与操作计数

> 对应 spring2024 L15：Big-Θ/Ω/Ο、增长阶、操作计数式成本分析。阅读：Hug 笔记 "Asymptotics"、CLRS Ch.3。作业：HW2。本节起进入"分析驱动设计"半程。

## 1. 核心概念

- **Big-Θ（紧确界）**：存在 c₁,c₂,n₀ 使 c₁·g(n) ≤ f(n) ≤ c₂·g(n)（n≥n₀）。61B 风格：Θ 用"最坏情形下操作次数的增长率"，忽略常数与低阶项。
- **Ο 上界 / Ω 下界**：6.006/CLRS 更强调 Ο（"不超过"），Hug 主张作业中能用 Θ 就用 Θ。
- **为什么忽略常数**：机器无关、编译器无关；但**常数在真实系统里会杀人**（缓存效应，见 CSAPP）。
- **操作计数法**：给关键操作（数组访问、比较、指针赋值）立账，循环逐层求和：
  ```java
  for (int i = 0; i < n; i++)      // n 次
    for (int j = 0; j < i; j++)    // 0+1+...+(n-1) = Θ(n²) 次
      count++;
  ```
- **常见增长阶**（由慢到快）：Θ(1) < Θ(log n) < Θ(n) < Θ(n log n) < Θ(n²) < Θ(2ⁿ)。

## 3. 摊还分析的预告（细节在 L17）

- "第 k 次操作最坏 Θ(k)"不等于"n 次操作总共 Θ(n²)"：动态数组单次扩容 Θ(n)，但 n 次 add 总共 Θ(n) ⇒ **摊还 Θ(1)**。区分"最坏单步"与"摊还序列"是本讲与 L17 的接缝。

- **CSAPP**：Θ 忽略的常数 = 缓存行/分支预测的世界；`array Θ(1) vs list Θ(n)` 的 get 在 n 小时可能翻转，实测才是裁判。
- **DDCA/OS**：OS 的 O(n) 页表 vs O(1) TLB 说明"复杂度类相同也要为常数买单"；DDCA 中加法器延迟 Θ(log n)（进位链）与 Θ(1)（超前进位）同框。

## 6. 开源项目应用

- **JDK**：`ArrayList`/`HashMap` 的 javadoc 直接写复杂度承诺（"amortized constant time"），API 文档即渐近合同；`TreeMap` 文档明写 Θ(log n)。
- **RocksDB**：LevelDB LSM 的写放大 Θ(log n) 层数、读放大分析全是渐近语言——compaction 策略本质是在复杂度之间做货币兑换。
- **Lucene**：倒排链跳读 skip list 的 Θ(1) advance vs 全链扫，merge 策略的几何级数段组织（与 L17 动态数组同一数学）。
- **Git**：`git log --graph` 的 commit 遍历 Θ(历史长度)，reachability 标记算法 Θ(对象数)——pack 窗口选择则是常数工程。
