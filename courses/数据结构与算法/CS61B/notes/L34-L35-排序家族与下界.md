# L34–L35 排序：插入/归并/快排、稳定性、下界与基数排序

> 对应 spring2024 L34–L35：选择/插入、归并与快排（递归树）、稳定性、比较下界、基数排序、Arrays.sort 工程。阅读：CLRS 2、6.3、7；algs4 2.1–2.5。项目对应：projects/sorts。

## 1. 核心概念

- **插入排序**：无序前缀逐个"向左冒泡入位"；近乎有序时 Θ(n + inversions)——小数组与"近乎已排"数据之王。
- **归并排序**：分治 + merge 辅助数组；稳定；Θ(n log n) 最坏；递推 T(n)=2T(n/2)+Θ(n)（递归树每层 Θ(n)、log n 层）。代价：Θ(n) 辅助空间。
- **快速排序**：选 pivot、Lomuto/Hoare 双指针分区、原地；期望 Θ(n log n)（随机 pivot），最坏 Θ(n²)（已排序+固定 pivot）。工程三板斧：三数取中、小数组切插入排序、尾递归先推小半区（栈深 O(log n)）。
  ```java
  static void quick(int[] a, int lo, int hi) {
      if (hi - lo < 8) { insertion(a, lo, hi); return; }
      int p = partition(a, lo, hi);       // pivot 归位
      quick(a, lo, p - 1); quick(a, p + 1, hi);
  }
  ```
- **堆排序**（L28 回收）：原地 Θ(n log n) 最坏，但不稳定、缓存差。
- **稳定性**：相等键保持原相对序 → 多关键字排序 = 从次要到主要各排一遍（LCS 式思维）。归并稳定、快排/堆排不稳定。
- **比较下界**：决策树叶数 ≥ n! ⇒ 高 ≥ log₂(n!) = Θ(n log n)（Stirling）。想更快必须利用键结构 → **基数排序** LSD/MSD：对 d 位、基数 R 做 d 轮计数排序，Θ(d(n+R))；d=常数时 **线性**（对定长整数/字符串）。
- **Arrays.sort 真相**：对象 `T[]` → TimSort（归并+插入混合，稳定，跑检测）；原始 `int[]` → Dual-Pivot Quicksort（不稳定、快、原地）；并行 `Arrays.parallelSort` → 归并式并行切分。

## 5. 开源项目应用

- **JDK**：`Arrays.sort` 双轨制（见上）；`TimSort` 源码注释是被迫读代码的经典（countRunAndMakeAscending + gallop）；`Collections.sort` = List.toArray + Arrays.sort + 回填。
- **Lucene**：字段排序用"文档 ID 数组 + 基数排序/多键归并"；`FieldComparator` 链正是多键稳定排序组合。
- **RocksDB**：memtable 跳表天然有序；SST 的 `block-based` 索引按 key 字典序 = 持久化"已排序"假设——排序与哈希在 LSM 里是先后关系。
- **Git**：`git log --date-order` 用堆做 k 路归并（多 parent 历史）；pack 窗口按对象路径相似度排序（MSD 基数 + 自定义比较）。
- **Spark**：`sortByKey` = range partition + 分区内排序（sort-merge shuffle），外部排序直接复用。
