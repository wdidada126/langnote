# L21 在线算法与自组织表：Move-to-Front 与伸展树

> 讲次：Fall 2011 Lecture 21 ｜ 教材：CLRS 问题 12-1（splay）+ Sleator-Tarjan 1985 ｜ 本课笔记：notes L21 ｜ 后续：L22 分页（在线算法的主战场）

## 1 问题模型

- **在线算法**：请求逐个到达，算法必须在不知未来时决策且不可撤销。评价工具 = **竞争分析**：存在 a,b 使对一切请求序列 σ，
  `cost_ALG(σ) ≤ a·cost_OPT(σ) + b`，称 ALG 是 a-竞争的（OPT = 全知离线最优）。
  - 竞争比是"最坏序列上的比值"——不是期望（L17 概率）也不是摊还（L19 单算法内账），而是**与对手比账**。
- 自组织表：线性表上的查找序列，每查后可付代价重排。策略：
  - **MTF（Move-To-Front）**：命中即移到头；
  - **Transpose**：命中即与前一位置交换；
  - 列表更新问题：ALG 与 OPT 的差距用"相邻逆序对计数"位势刻画（下界分析同一工具）。
- 伸展树（Splay Tree）：BST + 每次访问把结点 splay 到根（ zig/zig-zig/zig-zag 三层手术）——"热点自动浮升"的树版 MTF。

## 2 伪码（splay 一步）

```text
SPLAY(x):
  while parent(x) 存在:
    if parent 是根: ZIG(x)                        # 单次旋转
    elif (x 与 parent 同为左子/右子): ZIG-ZIG     # 先旋父再旋 x
    else: ZIG-ZAG                                 # 先旋 x 两次
  x 成为新根
```

## 3 竞争比推导（列表更新，关键步骤）

- 定义位势 Φ = 表的相邻逆序对数（对 OPT 而言"错位度"）。
- 单请求分解：ALG 成本 = 命中位置 = 1 + (命中前扫过的与 x 成对的逆序对数，记 2A 类) + (其余，1 类)。
- MTF 后：A 类逆序对消除、x 与其后每个结点至多新增 1 个 → ΔΦ ≥ −(#A) + #(B 类)。
- 汇总：cost_MTF ≤ 4·cost_OPT − Φ 变化 → **MTF 是 2-竞争**（Σ  telescoping + Φ ≥ 0），且该界**紧**（周期轮转序列反例）。
- Transpose 的 3-竞争类似但更繁（3Φ 放缩）——记住"MTF 最优确定性策略"结论。
- **下界**：一般访问序列下，任何确定性列表更新算法的竞争比都有 Omega(log n) 下界（对手把表分成指数递减的块轮流打击）；MTF 的 2-竞争是在"相邻逆序对位势"口径下的紧结论。记住两条：MTF 紧 2-竞争；确定性整体不可能 O(1)。随机化最佳上界 O(log n)（BIT/FOLIC 族）。
- splay 树摊还 O(log n)（L19 势函数 Φ = Σ log(size(子树))，access lemma）→ 连续 m 访问 O(m log n)，且"访问频度加权"自动布局：频繁项靠根，**静态最优树级别**（动态猜想未解）。

## 4 正确性论证思路

- 竞争分析格式：选 Φ（通常是"与 OPT 的距离"）→ 逐请求证 `cost_ALG(i) ≤ a·cost_OPT(i) + ΔΦ(i)` → 求和消 Φ。
- 随机化版本（L26 呼应）：期望竞争比可再降——"随机帮助"现象在列表更新/分页中最早被证实（随机算法相对确定性的指数级分离见 L22 分页）。
- 反例文化：给"按频率排序"直觉策略一个 Zipf 倾斜 + 突发切换序列使其崩溃——**直觉策略在竞争分析面前人人平等**。

## 7 开源项目应用

- **Linux `slab`/`list_lru`**：双链表 + 提升/降级即硬件 MTF/Transpose 混合。
- **Redis 近似 LRU（`lru.h`）**：采样池 + 年龄重排——精确 LRU 太贵的竞争分析视角（与 L22 同）。
- **Cuckoo/自组织结构**：`libcuckoo` 的 move-to-front 调试策略。
- **数据库连接池/最近最少查询缓存**：MySQL query cache 淘汰、pgbouncer 池内排序都是 MTF 族。
- **OpenJDK `ConcurrentSkipListMap`**（跳表而非 splay，L14 对照）：用随机层级换摊还，工程界对 splay 的"最坏单步尖刺"（缓存/锁场景）投了不信任票。
