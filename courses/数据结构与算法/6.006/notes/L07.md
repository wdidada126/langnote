# L07 映射与哈希表：dict 的内部世界

> 讲次：Fall 2011 Lecture 7 ｜ 教材：CLRS 11.1–11.4 ｜ 本课笔记：notes L7 ｜ 后续：L17 通用/惰性哈希与 Bloom、L24 字符串哈希

## 1 问题模型

- 字典 ADT：`insert(k,v) / lookup(k)->v / delete(k)`，键唯一。直接定址（键当数组下标）仅当宇宙 U 小且稠密；一般情形用**哈希**把 U 压进 m 个槽。
- 核心对象：哈希函数 h: U → {0..m−1}。质量目标：任意两键碰撞概率 ≈ 1/m（简单均匀假设），使 n 键负载因子 α = n/m 时平均链长 α。
- Python 具象：`dict`/`set` 就是开放寻址哈希表；键必须**可哈希**（hash(k) 与 `__eq__` 一致：相等对象同哈希）。

## 2 算法伪码

```text
# 分离链（chaining）
INSERT: T[h(k)].append((k,v))       # 先查重
LOOKUP: 遍历 T[h(k)] 比对键

# 开放寻址（open addressing, 线性探测）
PROBE(i) = (h(k) + i) mod m
INSERT: i=0; while slot occupied and key differs: i++; 放入首空/同键槽
DELETE: 写墓碑（tombstone）——否则探测链断裂
LOOKUP: 沿探测链到首个空槽止
```

- Python dict 用开放寻址 + 扰动探测（历史上 (5i+1+…)+salt），负载阈值 ~2/3 触发**倍增重建**（→ L17 惰性删除思想）。
- 字符串哈希：`hash(s) = Σ s[i]·B^i mod P` 的滚动形式（`_Py_HashRandomization` 加盐防哈希dos）；与 L24 Rabin-Karp 同一代数。

## 3 复杂度推导

- 分离链期望：一次操作 = 1 + 链长 ≈ 1 + α。α = O(1)（保持 m = Θ(n)）→ 期望 O(1)。
- 无独立性时的**通用哈希**期望界（L17 正式化）：若对任意 k≠l 有 Pr[h(k)=h(l)] ≤ 1/m，则期望链长 ≤ n/m。
- 开放寻址线性探测：随机假设下插入期望探测次数 ≤ ½(1 + 1/(1−α))（定理，需用碰撞区间计数），α→1 时急剧恶化 → 实际把 α 压在 ~0.7。
- 最坏（全碰撞）：所有操作 Θ(n)——哈希表没有"免费"可言，均匀性是被构造出来的（随机/通用/加盐）。

## 4 正确性论证思路

- 关键不变式：分离链——"键 k 存在且仅存在于槽 h(k) 的链中"；开放寻址——"k 若在表中，必在从 h(k) 起第一条不中断（墓碑不断链）的探测序列上"。
- 删除的墓碑、扩容的"先建新表再迁移"，都须论证探测不变式不被破坏；这是 PSet 高频考点。
- 语义坑：`__hash__` 与 `__eq__` 不一致 → 同一对象两个"身份"，dict 出现"明明在里面却查不到"。

## 7 开源项目应用

- **CPython `dict`（`dictobject.c` + `objects/dictobject.c`）**：紧凑存储（entries 数组 + indices 表，3.11 split-key），保序即插入序——工程对"哈希无序"的成功反击。
- **Redis**：`db->dict` 渐进式 rehash：每次读写搬一桶 + 后台定时搬，正是 L17 惰性哈希的工业版；`SETNX` 幂等去重依赖哈希。
- **Go `map`**：8 桶链 + 扩容迁移 + 随机起点（防算法复杂度攻击），文档明示 O(1)。
- **Java `HashMap`**：链长 >8 且表 ≥64 时桶内转红黑树（L14 杂交）——最坏 Θ(n) 修成 Θ(log n) 的代表作。
