# L19 摊还分析：聚合法、记账法与势函数法

> 讲次：Fall 2011 Lecture 19 ｜ 教材：CLRS 17.1–17.4 ｜ 本课笔记：notes L19 ｜ 后续：L20 并查集、L21 伸展树、L22 分页——摊还是一整段的货币

## 1 问题模型

- 单步最坏成本会说谎：动态数组 append 偶尔 Θ(n)（扩容拷贝），但任意 n 次连续操作总成本 O(n) → **均摊（amortized）O(1)**。
- 记号语义：T_i = 第 i 步真实成本，均摊成本 â_i 只需满足 Σ â_i ≥ Σ T_i（对整个操作序列）。
- 三件套（同一结论的三种记账语言）：
  1. **聚合法**：直接给序列总成本上界，再平均；
  2. **记账法**：给每类操作定价 â ≥ T，存款随对象携带（"预付运费"）；
  3. **势能法**：定义 Φ(数据结构状态)，â_i = T_i + Φ(D_i) − Φ(D_{i−1})，Φ 非负且 Φ(终) ≥ Φ(初) 即证毕。

## 2 主例：倍增动态数组

```text
APPEND(x): 满则 new 容量 2m 表 + 拷贝 + 释旧; 写入 x
n 次 append 总成本：Σ_{k=0}^{⌈log n⌉} 2^k (拷贝) + n (写入) < 3n → 均摊 < 3 = O(1)
更紧: 2-倍增 1-缩容（容量 ¼ 触发缩到 ½? 防抖动阈值）→ 均摊 ≤ 5
```

- 为什么 ×2 而不是 ×1.5/×3：×2 让拷贝总量 < 写入量（几何级数首项 2）；×3 稳态利用率降到 25%；×1.5 更省空间但拷贝次数变多（1.5^k 求和仍 O(n) 常数变大）。**策略选择=常数与抖动权衡**。

## 3 势能法示范（考试格式）

- 例 1（数组）：Φ = 2·size − capacity，直觉是"扩容预付款"。不扩容时 â = 1 + ΔΦ ≤ 2；扩容那次 T = 1 + m，ΔΦ = (2·(m+1) − 2m) − (m − m) 代入得 â = O(1)；且 Φ ≥ 0 恒成立（capacity ≤ 2·size），Φ(终) ≥ Φ(初) = 0 → 序列总成本 ≤ Σ â = O(n)。
- 例 2（栈 MULTIPOP）：Φ = 栈深。PUSH â=2、POP（含 multipop 每次）â=0，总 â ≤ 2n → 序列 Θ(n)，而单看 POP 最坏 Θ(n)——**摊还把"一次昂贵"化整为零**。
- 例 3（二项堆合并预告）：Φ = 堆中二项树个数，合并 â = O(log n)：借位链的"贵"由之前 insert 攒下的 Φ 支付。
- 通用推导习惯：势能函数选"潜在待付账单"（存款在哪个字段，Φ 就数哪个字段）。

## 4 正确性/严谨性论证思路

- 摊还界是**最坏序列界**：不是期望（≠ L07/L17 的概率）！任何操作序列满足。
- 记账法合法性的验证：证明"任意前缀余额 ≥ 0"（否则存在无法兑付的输入序列）。
- 势能法反例文化：设计 Φ 使 â_i 出现负数 → 可能非法抵扣真实成本；检查 Σ â ≥ Σ T 必须逐项成立 + 边界 Φ 条件。
- 与渐近记号的互动：均摊 O(1) + 单步 O(n) 不矛盾——分清"报告口径"（接口文档里写哪个？Redis/CPython 都写均摊，L02 呼应）。

## 7 开源项目应用

- **CPython list 扩容（`listobject.c`）**：3.4+ `new_allocated = (size_t)newsize + (newsize >> 3) + (3 if <9 else 6)` ≈ 1.125× 小步策略——空间利用率与摊还拷贝的再平衡，注释即摊还论证。
- **Go runtime slice grow**：<256 翻倍、>256 ×1.25 渐进——两段策略写进 `growslice`。
- **Redis 渐进 rehash（L07 呼应）**：把 Θ(n) 迁移拆进每次 O(1) 操作 + serverCron 限额步进，是"摊还=化整为零"的工业注释。
- **LevelDB memtable→SST flush**：写放大预算（每键摊 c 次磁盘写）用摊还记账定义 SLA。
