# L17 通用哈希、惰性哈希与 Bloom Filter

> 讲次：Fall 2011 Lecture 17 ｜ 教材：CLRS 11.2、11.3.3、11.4 延伸、附录 C 概率 ｜ 本课笔记：notes L17 ｜ 后续：L19 摊还（惰性重建）、L24 滚动哈希

## 1 问题模型

- L07 的"均匀散列"是假设；对手可以构造全碰撞输入（哈希 DoS）。两件套解决：
  1. **通用哈希族**：随机选 h ∈ H，使"任意固定键对"碰撞概率 ≤ 1/m——把保证从"对一切输入"改成"对一切输入的期望（随机性在算法里）"。
  2. **动态/惰性维护**：表负载越界时重建（rehash），且把重建成本摊到每次操作上。
- 另一极：**Bloom filter**——放弃精确字典，只要"肯定在/很可能不在"的空间压缩成员查询（概率型数据结构原型）。

## 2 核心内容

```text
通用族 H = {h_{a,b}: h(k) = ((a·k + b) mod p) mod m,  a,b ∈ [1,p), p 素 > u}
定理：k₁≠k₂ ⇒ Pr[h(k₁)=h(k₂)] ≤ 1/m。
  证明骨架：a·k₁+b ≡ a·k₂+b (mod p) 至多一解 a → 概率 1/(p−1)；mod m 合并只会更"对齐"
  → 期望链长 ≤ 1 + n/m（对一切输入！）

惰性重建（towers-of-bits / 倍增）:
  当 n > m: 建表 m' = 2m 并迁移一部分; 迁移增量摊进后续操作
  经典版本: 立即全量重建 → 单次 Θ(n), 序列 Θ(n) 总成本 (L19 聚合法)

Bloom filter(m 比特, k 个哈希):
  ADD(x): 置位 h₁..h_k(x)
  QUERY(x): k 位全 1 → "可能有"; 任一位 0 → "必无"（无假阴性）
```

## 3 复杂度推导（关键步骤）

- 通用哈希：期望 O(1 + α) 操作成本，α=n/m=O(1)（保持负载界靠重建）。
- Bloom：插入/查询 O(k)。假阳性率推导：
  - 一位仍为 0 的概率 (1 − 1/m)^{kn} ≈ e^{−kn/m}；
  - FPR ≈ (1 − e^{−kn/m})^k；对 k 求导 → 最优 k* = (m/n) ln 2；
  - 代回得 FPR ≈ 2^{−k*} = (0.618)^{m/n} —— **每元素 ≈ 1.44·log₂(1/ε) 比特** 的量化记忆。
  - 例：n=10⁶、ε=1% → m ≈ 9.6M bits ≈ 1.2MB，k=7。
- 删除不支持（位共享）→ counting Bloom（4bit 计数）或 Cuckoo filter（换指纹存，支持删除，L22 关联）。

## 4 正确性论证思路

- 通用哈希定理的"线性方程唯一解"论证要会复述（两直线交点几何直觉亦可用）。
- Bloom 无假阴性论证一行：x 加入置的位查询时不会回到 0。假阳性是"碰撞拼凑出全 1 掩码"——推导即上面指数近似；实验对拍理论曲线（projects/p03）。
- 惰性重建正确性：迁移期间新旧双表并行查询（"两阶段搬家"），证明任一时刻键恰在其中一表。

## 7 开源项目应用

- **LevelDB/RocksDB**：每 SSTable 一个 Bloom（默认 10 bit/key，1% FPR）；`filter_policy` 可换 full/filter 变体——读放大控制核心。
- **Chrome Safe Browsing**：本地 Bloom 粗筛恶意 URL，命中才联网查询；**Sentry/Scrapy** 去重队列、**Cassandra/BigTable** 行存在性过滤同款。
- **CPython**：`set`/`dict` 无通用族但用 siphash 变体+盐；`hash(x)` 与 `__eq__` 一致性责任在你。
- **rust `rustc-hash`/`foldhash`**：默认哈希从 SipHash 转向更快通用族，配 DoS 面收敛——"安全 vs 常数"的现实调参。
