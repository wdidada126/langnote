# L06 栈、队列与双端队列：接口设计与 O(1) 两端

> 讲次：Fall 2011 Lecture 6 ｜ 教材：CLRS 10.1 ｜ 本课笔记：notes L6 ｜ 后续：L09 DFS 用栈、L10 BFS 用队列、L19 动态数组实现

## 1 问题模型

- 抽象数据类型（ADT）：先定义**接口与语义**（push/pop/peek/enqueue/dequeue），再谈实现与成本。目标：两端操作均摊 O(1)。
- 三种次序：栈 LIFO（最后进来最先处理）、队列 FIFO（先来先服务）、deque 双端任意。次序即策略：撤销历史、任务调度、滑动窗口，分别对应三者。
- 规格示例：`pop` 在空栈上抛异常而非返回哨兵值——ADT 设计要显式规定错误语义。

## 2 接口与实现伪码

```text
Stack:  push(x), pop()->x, top(), is_empty()
Queue:  enqueue(x), dequeue()->x, front()
Deque:  add_front/add_rear/pop_front/pop_rear

# 数组实现栈: append 即 push, pop 即 pop —— list 天然 O(1) 栈。
# 数组实现队列: 头删是问题。两种方案:
ARRAY-QUEUE: 循环缓冲(head, tail 模 n), 满时倍增搬迁 → 均摊 O(1)（L19）
LIST-QUEUE: 链表 + 尾指针 → 两端真 O(1), 但每节点一指针的缓存税
```

- Python 现实：`list.pop(0)` 是 **O(n)**（memmove 全体）——想当然用 list 当队列是本讲最大陷阱；`collections.deque` 用**块状双向链表**（固定大小块数组 + 两端块表）兼得两者：两端 O(1)、块内顺序访问缓存友好。

## 3 复杂度推导

- 循环数组队列：单次 enqueue 最坏 O(n)（扩容），n 次操作总拷贝 Σ2^k < 2n → 均摊 O(1)（严格证明要 L19 记账法）。
- deque 块结构：块内索引 O(1)；块的新建/释放均摊 O(1)（一块含 B 元素，摊销到每元素 1/B）。
- 内存上界：循环数组占用 ≤ 2×峰值 size——倍增策略的"空间换时间"定价。

## 4 正确性论证思路

- ADT 一致性证明模板：对每个操作证明"具体表示的不变式 ⟺ 抽象模型"。循环数组不变式：`head ≤ tail < head + capacity`，逻辑序列 = a[head..tail) 模 capacity。
- 对拍测试文化：随机操作序列同时打到"参考实现（list）+ 被测实现"，比较全部返回值——工程正确性证明（PSet 风格）。

## 7 开源项目应用

- **CPython `collections.deque`（`deque.c`）**：块链结构即本讲"兼得方案"的源码范本。
- **`asyncio` 事件循环**：ready queue 用 `collections.deque`——FIFO 保证同优先级任务公平。
- **Linux 内核**：`list_head` 侵入式双向链表无处不在（task 队列、LRU 页链表 L22 呼应）；无锁环形缓冲（`kfifo`）即循环数组。
- **Netty Disruptor / LMAX**：环形队列（ring buffer）做百万级 TPS——循环数组的性能天花板案例。
- **Redis 客户端缓冲**：output buffer 用链表队列并配 `CLIENT GETNAME` 限额。
