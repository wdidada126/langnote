# L22 缓存与分页：LRU/LFU 与竞争分析

> 讲次：Fall 2011 Lecture 22 ｜ 教材：notes L22 + Sleator-Tarjan (1985)、Fiat et al. (1991) ｜ 后续：L23 vEB、L26 随机化在线

## 1 问题模型

- **分页问题**：内存容 k 页、磁盘宇宙 n 页；请求流 σ 逐页到达，命中免费，缺页必须装入（并选牺牲页）。目标：最小化缺页次数。经典 LRU/FIFO/Belady-OPT 四策略谱。
- 与 L21 共享竞争分析框架，但 OPT 更强（离线全知），竞争比随 k 变：结论——确定性 **LRU/FIFO/Marked 是 k-竞争**，且这是**紧下界**（任何确定性算法 ≥ k）。
- 同一问题无处不在：OS 页缓存、CPU cache 置换、CDN/对象存储缓存、数据库缓冲池、Web 缓存——置换策略 = 分页算法。

## 2 核心策略与标记算法

```text
Belady OPT : 驱逐"下次请求最远"的页（需未来信息, 仅离线基准）
LRU        : 驱逐最久未用（栈式算法: 命中集随 k 单调）
FIFO       : 驱逐最早进入
MARKED(均衡): 一轮 = 缺 k+1 次新页的区间; 本轮被请求过的页打标记;
             缺页时优先驱逐未标记页, 全标记则清标记开新轮再驱逐
```

- Marked（= 工作集/时钟近似的理论版）：每轮至多驱逐 k 个干净页、至多 1 个脏页成本 → **k-竞争且对任意 k 紧**；LRU 是栈式特例（FIFO 非栈式，存在 LRU 命中而 FIFO 缺页的序列）。

## 3 竞争比推导（关键步骤）

**上界（k-竞争，Marked）**：
1. 切"轮"：当即将驱逐第 k+1 个不同页时开启新轮；每轮 OPT 至少付 1 次缺页（k 个槽装不下 k+1 个新页）。
2. 轮内 ALG 缺页 ≤ 2k（k 个未标记牺牲 + 1 次清标重开）→ 每 OPT 缺页摊 ≤ 2k → 精细版做到 k+1 常数收紧到 **k**。
**下界（Ω(k) 紧）**：
- 对手构造：OPT 缓存持集合 S（|S|=k−1）外一轮转 + 引入页 x：ALG 每次缺页牺牲不同页、OPT 只牺牲 x → 对任意确定性策略给序列使 cost_ALG/cost_OPT ≥ k（分相法，"清相+扰相"）。
- 期望/随机化：随机 Marked 达到 **2H_k−1 = O(log k)** 期望竞争——**指数级分离**（L26 随机化的成名战）。

## 4 正确性/论证思路

- 与 L21 同模板：选 Φ/分轮计数 → 逐请求（逐轮）`cost_ALG ≤ a·cost_OPT + Δ` → 求和。
- 栈式性质证明 LRU 包含关系：k 容量命中集 ⊆ k+1 容量命中集（对请求后缀归纳）→ LRU 的 ANAC 分析（L21 位势）可行。
- 下界证明的"对手策略"写法：明确对手的自适应规则（保持 OPT 集已知）→ 对确定性 ALG 总可"打脸"；随机 ALG 需 Yao 引理转置（L26）。

## 7 开源项目应用

- **Linux `mm/swap.c` + `list_lru`**：active/inactive 双链表 + PG_referenced 位 = 教科书 Marked/clock 近似。
- **Redis `allkeys-lfu`（近似 LFU）**：8bit 计数器 + 对数衰减 + 10bit 年龄——"LFU 防突发"的量化（论文：Einziger-Katz "TinyLFU" 与 Redis 实现同源）。
- **Memcached/Varnish**：LRU 分 slab 与带锁分片；`slab_reassign` 治理碎片。
- **Go `groupcache` / Caffeine（Java）**：Window-TinyLFU——TTL/准入/淘汰三段论，竞争分析的工程旗舰。
- **Chrome/Safari 网络栈**：HTTP cache 的启发式新鲜度 + LRU 驱逐，协议层版本。
