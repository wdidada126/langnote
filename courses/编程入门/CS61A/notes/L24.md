## 1. 核心概念

### 1.1 关系模型：表即集合，查询即表达式
SQL 是声明式语言（L04 抽象阶梯的顶点）：描述"要什么"，执行计划交给优化器。
核心动词族：`SELECT / FROM / WHERE / GROUP BY / HAVING / ORDER BY / JOIN / LIMIT`。

```sql
-- 每门课的平均分数，只看 4 人以上的课
SELECT Course, AVG(Score) AS avg_score
FROM   Grades
GROUP  BY Course
HAVING COUNT(*) >= 4
ORDER  BY avg_score DESC;
```

### 1.2 标准库 sqlite3：Python 内的执行引擎
```python
import sqlite3
db = sqlite3.connect(':memory:')          # 或用 P3 落盘的 .db 文件
db.executescript('''CREATE TABLE login(user TEXT, course TEXT, ts INT);''')
db.executemany('INSERT INTO login VALUES (?,?,?)', rows)
for user, course in db.execute(
        'SELECT DISTINCT user, course FROM login WHERE ts > ?', (cutoff,)):
    print(user, course)
```
Lab 传统用法：`python3 lab10.py student.db` 加载后逐题填 SQL，okpy 比对结果表。

### 1.3 连接语义与常见坑
- `JOIN ... ON`（内连接）= 笛卡尔积按谓词过滤；左外连接补 NULL；
- 多表要**限定列名**（`Table.col`），重名歧义是 Lab 第一大坑；
- NULL 传染：`x = NULL` 永为假，须 `IS NULL`；聚合忽略 NULL；
- 子查询 vs 连接：`WHERE user IN (SELECT ...)` 可读性常优于自连接。

### 1.4 参数化查询 = 安全纪律
永远 `?` 占位（防注入，对应 Python 字符串格式化拼接 SQL 的事故链）。这属于
"语言的接口层契约"（L04）而非 SQL 本身，但 CS61A 明确写入评分要求。

## 4. 知识点在开源项目中的应用
- **CPython**：`Modules/_sqlite` 是 sqlite3 的薄绑定——sqlite 本体（单文件 C 库）即"嵌入式数据库=一个解释器"的范本（SQL 解析/优化/VDBE 虚拟机，结构惊人类似 P4）。
- **DuckDB**：进程内分析型 OLAP，Python API 与 sqlite3 几乎同形；列式+向量化执行是本讲查询的高速后端。
- **Datasette / dsq**：直接用 Python/CLI 跑 sqlite；`pandas.read_sql` 打通 DataFrame↔表。
- **SQLAlchemy**：把 SQL 表达为 Python 对象/方法链（ORM）——声明式语言在宿主语言的 AST 化。
