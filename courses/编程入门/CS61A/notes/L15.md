## 1. 核心概念

### 1.1 继承 = 复用 + 特化
```python
class Employee:
    def __init__(self, name, salary):
        self.name, self.salary = name, salary
    def pay(self): return self.salary

class Manager(Employee):
    def __init__(self, name, salary, team):
        super().__init__(name, salary)     # 先让父类填通用部分
        self.team = team
    def pay(self):                          # 覆盖 override
        return super().pay() * 1.2          # 扩展而非重写
```
规则：**子类可覆盖，父类不可"继承"子类的东西**；`super()` 沿 MRO 走，不是"父类"字面义。

### 1.2 MRO 与菱形继承
Python3 新式类用 **C3 线性化**：深度优先 + 每层最右优先，保证"子类先于父类、
声明顺序保持"。`A.__mro__` 可直接打印。菱形继承时方法解析沿 MRO 链，`super()`
级联调用（协作式多继承）；`__init__` 想全跑一遍需每个类都调 `super().__init__()`。

面试级小题：
```python
class A: def m(self): return 'A'
class B(A): def m(self): return 'B' + super().m()
class C(A): def m(self): return 'C' + super().m()
class D(B, C): pass
D().m()        # 'BCA' —— MRO: D,B,C,A,object；B 先执行，super() 沿链交棒给 C 再到 A
```

### 1.3 多态与"按类型分派"的两种写法
```python
# 1) 鸭子类型/动态分派：调用者不关心类型
def total_pay(employees): return sum(e.pay() for e in employees)
# 2) explicit dispatch（P3 的 Tree 常用）：按数据表示选择行为
def process(node):
    if node.is_leaf(): return node.value
    return combine([process(c) for c in node.children])
```

### 1.4 表示切换（representation change）
CP §2.4 经典题：Tree 从"children 列表"改"dict 按 key 查"——上层 `__repr__`、
`depth` 不变，只有 `__init__/children` 内部改。**对扩展开放、对修改关闭**的首次
正式登场（开闭原则），也是 P3 从 lab 到 project 的核心工程手法。

## 4. 知识点在开源项目中的应用
- **CPython**：`Objects/typeobject.c` 的 `mro()`（C3 实现）；`super` 是描述符对象而非关键字。
- **exceptions 层级**：`Exception → ValueError/TypeError…` 与 `OSError` 家族是"按职责分层"的继承样板；捕获基类即多态分派。
- **Django/DRF**：`GenericAPIView` mixin 组合（`CreateModelMixin + ListModelMixin`）是协作式多继承的工业应用。
- **Rich/Click** 等 CLI 库：`Console` 的可插拔协议类（`ConsoleProtocol`）演示鸭子类型替代继承。
