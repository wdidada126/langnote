## 1. 核心概念

### 1.1 递归的三种形态
1. **线性递归**：`factorial`——调用链深 n，展开后是一串待完成的 `*`；
2. **树递归**：`fib`（不加 memoize）——每个调用分叉两支，调用树节点数 ~ φⁿ；
3. **分治（divide & conquer）**：`hanoi`、归并——把问题切成子问题，组合子解。

```python
def fib(n):
    if n < 2: return n
    return fib(n-2) + fib(n-1)     # 指数爆炸：fib(35) 约 3000 万次调用

def hanoi(n, a='A', b='B', c='C'):
    if n == 0: return
    hanoi(n-1, a, c, b)
    print(f'{a} -> {c}')
    hanoi(n-1, b, a, c)            # 输出 2ⁿ-1 步：树递归的遍历应用
```

### 1.2 想清楚再写：递归三问
- **base case 是什么？**（空输入/最小输入怎么答）
- **子问题是否严格变小？**（否则 RecursionError）
- **信任递归**：假设 `fib(n-1)` 已正确，我只需组合。（"leap of faith"，SICP 语）

### 1.3 递归调试
- Python 默认递归深度 1000：`sys.setrecursionlimit` 只是止痛，栈真会爆（CSAPP 视角：栈区耗尽 segfault，CPython 先抛 `RecursionError`）。
- Traceback 里同一函数名重复出现 = 不收敛。在 base case 前加 `print(n)` 观察递减值。
- 手算调用树（≤4 层）比盯代码有效。

### 1.4 递归改迭代（预告 L08）
```python
def fib_iter(n):
    prev, curr = 0, 1
    for _ in range(n):
        prev, curr = curr, prev + curr   # 状态元组整体更新
    return prev
```
当"待完成的运算"可以压缩成有限几个状态变量时，线性递归 → 迭代。树递归通常不行
（它需要显式栈或队列）——这正是 L13 链表/树结构存在的理由。
