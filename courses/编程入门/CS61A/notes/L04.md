# L04 函数设计与控制流：条件、域假设与声明式风格

> Week2-L2 · 教材：CP §1.4（Functions and Domain Assumptions）、§1.5（Control Statements）

## 1. 核心概念

### 1.1 合约：前置/后置条件
CP §1.4 的核心观点：好的函数像数学函数一样**声明域与值域**，并用条件语句做边界检查。

```python
def exp(b, n):
    """b 为任意数，n 为非负整数。返回 b ** n。"""
    assert n >= 0 and isinstance(n, int), "n must be nonnegative int"
    if n == 0:
        return 1
    return b * exp(b, n - 1)
```

教学版用 `assert`（`-O` 下会被剥离）；工业版用显式 `raise ValueError`。
前置条件由**调用者**负责，后置条件由**被调者**保证，不变量在循环中维持——这套
"契约思维"直接迁移到 CS61B 的 JUnit 规格测试。

### 1.2 条件、循环与控制函数
- `if/elif/else`：条件表达式的真值性（L01）。
- `while`：带状态迭代；`for`：序列迭代（L07/L11 详述）。
- **短路控制**本身就是分支：`if x and x > 0` 里 `and` 保护了 `x` 的域。
- CP §1.5 还引入 `return` 提前退出与"守卫生则"（guard clause）风格：

```python
def classify(n):
    if n < 0:  return 'negative'
    if n == 0: return 'zero'
    return 'positive'      # 无 else 嵌套，扁平优于嵌套（The Zen）
```

### 1.3 声明式 vs 命令式
对比两段等价代码：

```python
# 命令式：怎么做
total = 0
for x in xs:
    if x % 2 == 0:
        total += x * x

# 声明式：做什么
total = sum(x * x for x in xs if x % 2 == 0)
```

声明式风格把"循环机制"让渡给语言，代码贴近问题域。CS61A 整门课就是一条
**抽象阶梯**：命令式循环 → 高阶函数（L05）→ 序列协议（L11）→ 流（L23）→
逻辑式 SQL（L24）。SQL 是这条阶梯的极端：只说"要什么"，执行计划交给引擎。

### 1.4 值的组合 vs 语句的序列
表达式产生值、语句改变状态。尽量写表达式（函数调用、推导式），少写语句；
不可变数据（tuple、frozenset、`str`）天然支持这条纪律——这是 L13 可变性的对照组。
