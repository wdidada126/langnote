# L20 写解释器 I：词法分析、语法分析与 evaluate/apply 循环

> Week10-L2 · 教材：CP §4.1.2-4.1.3；SICP §4.1.1
> 配套项目：[P4](../projects/p4_scheme/README.md) Part 1（lexer/parser）

## 1. 核心概念

### 1.1 流水线全景
```
源码字符串
  → 词法分析 lexer：字符 → token 流        （"(" "+" "1" "2" ")"）
  → 语法分析 parser：token → 表达式树       （Pair(+) → Pair(1) → Pair(2) → nil）
  → 求值 eval：树 + 环境 → 值              （3）
  → 应用 apply：过程对象 + 参数 → 结果      （内建：Python 调用；复合：再入 eval）
```
eval 与 apply 互相递归——"评估一个组合式=求值运算符与运算目后应用；应用复合过程=
在其闭合环境里求值函数体"。这就是 metacircular evaluator 的心脏（L22）。

### 1.2 词法分析：括号即结构
Scheme 的 token 只有三类：`(`、`)`、原子（数字/符号/字符串）。`scheme_read`
逐字符推进：遇 `(` 递归读表直到 `)`；遇原子读完整 token（注意 `-3` 与 `a-b` 的
符号歧义、`"str with (paren"` 的字符串态）。

```python
def next_expr(tokens):      # tokens: 迭代器
    tok = next(tokens)
    if tok == '(':
        expr = Pair(None, None)
        cur = expr
        while (peek := next(tokens)) != ')':
            cur.first = next_expr_from(peek)   # 需要 pushback 或 lookahead 设计
            cur.rest = Pair(None, None); cur = cur.rest
        ...
```
P4 骨架给了 `LineLexer`/`scheme_tokens`（正则切 token）——生产级 lexer（CPython 的
tokenizer）同样正则+状态机，只是类别更多。

### 1.3 语法分析：递归下降的镜像
语法是递归定义：`Expr = Atom | (Expr*)`。`scheme_read(src, prompt)` 直接镜像它：
是 `(` 就读子表，是原子就解析为 `int/float/str/Symbol`。**代码 = 语法规则**——
理解这一点后，加语法（如 P4 的 `quasiquote`）只是加一行分支。

### 1.4 Pair：解释器的裸金属
P4 不用 Python list 存 Scheme 表，而用自写 `Pair(first, rest)` 链表类——因为 Scheme
语义（car/cdr/mutable pair）需要，而且它让"数据即列表"的教学目标显性化（L13 链表复用）。
