## 1. 核心概念

### 1.1 为什么是 Scheme
Scheme 把语言砍到只剩骨架：`define`、`lambda`、组合式、`cond`，所有东西都是
**列表**（S-表达式）。同像性（homoiconicity）让"代码=数据"——解释器与宏因此好写。

```scheme
> (define (square x) (* x x))
square
> (square (+ 2 5))
49
> (define cube (lambda (x) (* x (square x))))
cube
```

Python 视角翻译：前缀组合式即 `call(arg...)`；`define` 即赋值；函数同样是第一类对象。

### 1.2 计算器：第一个解释器（Lab08 的 mini Scheme）
CS61A 的 Calculator DSL：
- `scheme_read(src)`：字符串 → Python 值（列表嵌套），即**语法树**；
- `eval_expr(expr, env)`：数字自求值；列表 → 查特殊形式 / `eval` 子式 / 应用过程。

```python
# 伪骨架（真实实现见 Lab08 与 P4）
def eval_add(expr, env):          # (+ 1 (square 2)) → 5
    rest = expr.rest
    first_operand = eval_add_operand(rest.first, env)
    if first_operand == 0:        # (+) 递归基：空 → 0
        return 0
    return first_operand + eval_add(rest.rest, env)
```
注意这个 Lab 故意让你**用递归而非循环**处理任意嵌套——递归数据结构（树）× 递归
过程（eval）的肌肉训练。

### 1.3 特殊形式 vs 组合式
`define/lambda/cond` 不能按"先求值所有元素"的规矩来：`(define x (+ x 1))`
里 `x` 必须先**不**求值。特殊形式 = **控制求值策略**的语法（L22 宏把这种能力
下放给用户；Scheme 的 `delay/force` 惰性求值（L23）也靠它）。

### 1.4 名字与过程的分类
- 内建过程（primitive：`+`、`*`，Python 函数挂靠）；
- 复合过程（compound：lambda 创建，携带环境闭包——与 L06 完全同构）；
- 解释器本身：`scheme_eval` 与 `scheme_apply` 互相递归（tail recursion 的用武之地，L22）。

- **Racket**：Scheme 的现代方言，CS61A 官网 REPL 即跑在 Racket 上（web schema）；`racket/base` 证明"最小核心+宏扩展"路线能长出大生态。

- 嵌入式案例：GIMP Script-Fu、Emacs 的 init 文件传统（Elisp 同宗）、Redis 之外的规则引擎（如 Clojure 的 Lisp 家族同源）。
