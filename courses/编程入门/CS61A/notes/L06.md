## 1. 核心概念

### 1.1 返回函数的函数
```python
def make_adder(n):
    def adder(k):
        return k + n      # n 来自外层框架
    return adder

add_three = make_adder(3)
add_three(4)              # 7
```
关键点：`adder` 返回后其外层框架**不会消失**——因为函数对象仍引用它。函数 +
它定义时的环境 = **闭包（closure）**。环境图中 user-defined function 的 `parent`
箭头是本题正确与否的判据。

### 1.2 currying 与链式调用
```python
def f(x):
    def f1(y):
        def f2(z):
            return x + y + z
        return f2
    return f1
f(1)(2)(3)        # 6
```
把"一次满足全部域假设"拆成分步满足；Python 标准库用 `functools.partial`
提供不完备但够用的 currying（`reduce` 式手动 curry 见 Lab03 的 make/add 挑战）。

### 1.3 装饰器 = 语法糖
```python
def memoize(fn):
    cache = {}                    # 装饰器自身的闭包！
    def wrapper(*args):
        key = (fn, args)
        if key not in cache:
            cache[key] = fn(*args)
        return cache[key]
    return wrapper

@memoize          # 等价 fib = memoize(fib)
def fib(n):
    if n < 2: return n
    return fib(n-2) + fib(n-1)
```
- 装饰器在 **def 时执行一次**，运行时只剩 wrapper 调用。
- `@property`、`@staticmethod`、`@functools.wraps`、pytest 的 `@pytest.mark.parametrize` 全是同一机制。
- 本讲顺便给出**记忆化**：指数时间 fib 降为线性——与 L08"自顶向下动态规划"衔接。

### 1.4 常见陷阱
- 循环变量捕获：`[lambda: i for i in range(3)]` 三个闭包共享同一 `i`，全返回 2；修复：`lambda i=i: i` 或工厂函数。
- 装饰器忘记返回 wrapper / 不 `@wraps(fn)` 丢失 `__name__`。

## 4. 知识点在开源项目中的应用
- **functools.lru_cache**：工业级 memoize（带 maxsize/typed），CPython C 实现，线程安全计数；标准库文档示例 `@lru_cache(None)` 直接加速递归。
- **CPython**：`MAKE_FUNCTION` 字节码带 `closure` 操作数；`__closure__` 属性暴露 cell 对象，`inspect.getclosurevars()` 可检查。
- **Flask/Django**：`@app.route` 装饰器在模块导入时注册视图——"def 时执行"的完美应用。
- **click / typer**：参数声明式 CLI，全靠堆叠装饰器。
