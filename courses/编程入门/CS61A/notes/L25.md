## 1. 核心概念

### 1.1 两个正交概念
- **并发 concurrency**：多个任务在**逻辑上**同时推进（交替即可）；
- **并行 parallelism**：多个任务在**物理上**同时执行（多核）。
线程是"共享地址空间的并发单元"，进程是"隔离地址空间的并发单元"。

### 1.2 竞态与锁
```python
import threading
counter = 0
def worker(n):
    global counter
    for _ in range(n):
        counter += 1          # 读-改-写 三步，可被打断 → race
threads = [threading.Thread(target=worker, args=(100000,)) for _ in range(4)]
for t in threads: t.start()
for t in threads: t.join()
print(counter)                # 通常 < 400000（加 Lock 后稳定 400000）
```
`with lock:` 临界区把三步焊成原子；锁粒度、死锁（锁顺序/超时）是并发课的全部分支，
CS61A 只要求识别竞态 + 会加锁（p6 项目两种写法都有）。

### 1.3 GIL：Python 的"全局解释器锁"
CPython 用一把全局锁保护对象引用计数（避免每对象加锁的巨大开销）。后果：
- **CPU 密集**线程：无法并行加速（甚至更慢）；
- **I/O 密集**线程：解释器在等待时释放 GIL，并行度照常；
- `multiprocessing`：起真进程绕过 GIL，代价是启动开销+数据要 pickle 搬运。

```python
# CPU 密集：ProcessPoolExecutor 显著快于 ThreadPoolExecutor
from concurrent.futures import ProcessPoolExecutor, ThreadPoolExecutor
def cpu_task(n): return sum(i*i for i in range(n))
with ThreadPoolExecutor(4) as ex: list(ex.map(cpu_task, [4_000_000]*4))
with ProcessPoolExecutor(4) as ex: list(ex.map(cpu_task, [4_000_000]*4))
```
p6 项目会计时对比两者并打印比值。另注：GIL 在 3.13+ 有可选 no-GIL 构建（PEP 703），
free-threading 是进行时话题。

### 1.4 消息传递作为替代
CP §2.4/并发讲义的视角：**不共享内存，只发消息**（Actor 风格，Erlang 一脉）。
L13-L14 的对象恰好是"私有状态 + 消息分派"——OOP 被重新解读为并发原语
（Alan Kay 本意）。Python 里 `queue.Queue`/`multiprocessing.Queue` 即最小消息件。

## 4. 知识点在开源项目中的应用
- **CPython**：`Python/pystate.c` 的 GIL 实现（`take_gil/drop_gil`，3.2 起 5ms 轮转间隔可配 `sys.setswitchinterval`）；3.13 free-threading（PEP 703, `--disable-gil` 构建）。
- **asyncio / uvloop**：单线程事件循环 + 回调/协程 = 协作式并发，高 I/O 并发的工业答案（`aiohttp`、FastAPI 栈）。
- **numpy**：BLAS 在 C 层多线程（不受 GIL 限，运算期释放 GIL）——"GIL 是解释器层的锁，不是计算层的锁"的实证。
- **Celery/RQ、ray**：用进程池/分布式 worker 绕单机 GIL 的任务队列生态。
