## 1. 核心概念

### 1.1 四种编程元素
任何编程语言都归结为：
1. **表达式 expression**——产生值（`3 + 2`、`sqrt(9)`）；
2. **名字 name**——绑定到值（`x = 4`）；
3. **函数 function**——组合表达式、命名复合操作（`def f(x): return x * x`）；
4. **逻辑 Logic——语言提供的组合方式**（调用、`+` 等操作符）。

CP 的核心论断："解释器求值一个组合式的过程，就是它自身递归定义的镜像"——
**先求值运算符与运算目，再应用**。这句话在 L20-L22 会变成真正的代码（`scheme_eval`）。

### 1.2 树形求值
组合式是一棵树，求值是自底向上的归约：

```python
def square(x): return x * x
square(2 + 3)      # 先求值子表达式 5，再应用函数
#       square
#      /
#    +     
#   / \
#  2   3
```

在 REPL 里观察错误位置即可验证求值顺序：`square(1/0)` 在进入 `square` 之前就抛出
`ZeroDivisionError`——Python 是**应用序**（applicative order）求值，先算参数后调用。
Scheme 大部分相同，但惰性流（L23）与宏（L22）会打破它。

### 1.3 环境 = 框架的链
**环境模型**是 CS61A 最重要的心智模型：
- 每个**框架（frame）**是一张"名字→值"的表，外加指向上层框架的指针；
- 全局框架装着 `print`、`square` 这些内建；
- 函数调用创建一个新框架，参数名绑定实参，其父链指向**定义处**的环境（不是调用处——这条规则在 L06 闭包中反复使用）。

```python
x = 5
def f():
    print(x)   # 沿环境链向外找 x → 5
f()
```

画框架图（环境图）是做 Lab 题的硬功夫：global frame / user frame 两层，箭头从参数指向
对象，从 `def` 指向函数对象（函数对象身上带着 `parent` 指针）。

### 1.4 名字解析规则
- 赋值**只影响当前框架**；想改外层名字需要 `global`/`nonlocal`（L13 可变性会再谈）。
- 读名字沿链向外、写名字停在局部——不对称性是新手 bug 的头号来源。

## 4. 知识点在开源项目中的应用
- **CPython**：`ceval.c` 里 `LOAD_NAME/LOAD_GLOBAL` 字节码就是"沿环境链查名字"的机器码形态；`dis.dis` 可直接观察：

```python
import dis
def g(): return x
dis.dis(g)   # 会看到 LOAD_GLOBAL x
```

- **PyPy**：把全局名字表做成带"版本标记"的 inline cache，函数读全局几乎零开销——环境模型的工程化典范。
- **调试器 pdb / VS Code**：变量面板分 Local/Global 两区，就是环境图的用户界面。
