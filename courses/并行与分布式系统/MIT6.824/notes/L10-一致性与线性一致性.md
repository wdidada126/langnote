# L10 一致性与线性一致性

> 阅读：Herlihy & Wing, *Linearizability: A Correctness Condition for Concurrent Objects*, TOPLAS 1990；
> 辅读：Bailis & Ghodsi 等关于 CAP/最终一致性的综述
> 主线：给"一致性"下可证明的数学定义，是理解 Dynamo（弱）与 Spanner（强）两极的标尺。

## 1. 核心问题

- "一致性"一词在分布式里被严重滥用（复制一致性、线性一致性、因果一致性、
  ACID 的 C……）。本讲给出**唯一一个可形式化、可检验的强定义：线性一致性（linearizability）**。
- 问题：多个进程并发访问一个复制/共享对象，
  **能否给每次操作指定一个"生效瞬间"，使全局历史看起来像
  一个顺序一致的单机对象，且生效瞬间落在调用的真实时间区间内**？

## 2. 线性一致性的定义与直觉

- 两条件：
  1. **合法性（legal）**：存在一个串行历史，与顺序规范（sequential spec）一致；
  2. **实时序（real-time order）**：若操作 a 在 b 开始前就完成，则序列化后 a 仍先于 b。
- 直觉：**"读不到比自己能看到的更旧的值"**——一旦某次读返回了 x=1，
  之后任何新发起的读不得返回 x=0（除非中间有合法写 0）。
- 与**顺序一致性（sequential consistency, Lamport）**的区别：
  SC 只要求所有进程看到同一全局序，不尊重真实时间；
  线性一致性额外要求"全局序 ≈ 真实时间序"。**Lamport 时钟（L07）→ SC，
  物理时间 + 外部同步 → 线性一致**。

## 3. 判定的代价与不可组合性

- 检验历史是否线性一致是 **NP 完全**（一般对象）；特殊对象（寄存器、锁）有多项式算法。
- **组合性**：线性一致对象并行组合仍线性一致（good），
  但前提是每个对象本身线性一致——**它不是可组合的"活"性质里最便宜的**。
- **锁可以打破它**：用非原子标志实现的互斥锁本身可能不线性一致，
  导致"锁内的读写看起来没生效"——工程坑。
- **共识与它的深层联系（FLP）**：Herlihy 的共识数（consensus hierarchy）证明
  **实现非平凡的线性一致对象 ⇔ 解共识** → 异步系统里受 FLP 限制，
  线性一致 = 需要部分同步/leader（把 L08 与"一致性"钉在一起）。

## 4. 一致性谱系（本讲记忆图）

```
强 <----------------------------------------------> 弱
线性一致   顺序一致   因果一致   读己之写   单调读   最终一致
(Spanner)  (SC缓存)   (CRAQ读)   (Dynamo会话)        (Dynamo默认)
```
- **最终一致**：无并发时副本终将收敛——Dynamo（L11）为可用性放弃了实时序。
- **CAP 的正名**：CAP 的 C 就是线性一致；网络分区（P）发生时，
  共识系统（CP，Raft/Spanner）拒绝少数派，NoSQL（AP，Dynamo）接受并靠 LWW/向量时钟调和。
  两者都要在分区时"放弃某物"，**没有 CA，只有分区前都想要**。

## 5. 论文间脉络

- 上游：L07 时间定义"序"，L05-L08 共识给出"实现强一致唯一可行路径"。
- 下游：L11 Dynamo（主动弱化换 AP）、L15 Spanner（TrueTime 换外部一致）、

- 主线定位：**性能/可靠性/一致性三角里，本讲把"一致性"从口号变成可判定命题**。

## 6. 跨课程联系

- **15-445/15-721**：可串行化（serializability，事务层）与线性一致（对象层）
  是两个正交强度：Spanner 同时给"可串行化 + 外部一致"；
  MVCC 的快照隔离会**违反**线性一致（不可重复读），数据库课本的 anomaly 表直接对应本讲。
- **6.S081/体系结构**：CPU 内存模型（TSO/弱序）是片内版线性一致——
  硬件用 store buffer 换性能，正如 Dynamo 用最终一致换可用；`fence/mfence` 补实时序。
- **CS149**：共享内存并行程序 data race 的"看起来像某顺序"直觉 = SC。
- **编程语言（CS242 类）**：线性一致是"并发对象精化（refinement）"的语义基础。

## 7. 开源项目中的应用

- **etcd**：默认线性一致读写（可 `serializable=true` 降级读换吞吐——
  本讲两档一致性直接做成 API 参数，是最好的教材）。
- **Redis**：单线程 = 天然对单命令线性一致；但主从异步复制下**读从库不保证**。
- **CockroachDB**：严格可串行化 + 线性一致（Raft + HLC，见 L07/L15 讨论）。
- **ZooKeeper（L12）**：承诺"顺序一致 + 原子性"，**明确不承诺线性一致读**
  （旧 follower 可读到过期值），是其 FIFO client 语义的经典考点。
- **Kafka**：单分区日志 + leader epoch 的读语义、`isolation.level=read_committed`。
