# L09 面向故障设计：可重复读存储与容错中间件

> 阅读：Fox & Schindler, *Designing for Failure*, SIGCOMM Computer Review 2001；
> 辅读：van Renesse et al., *FTW: Scaling Usable Network Storage Through Transparent Request Forwarding* (NSDI 2006)；
> 同主题延伸：HotOS'03 *Learning What to Learn: Designing for Failure in Global-Scale Networks*（作者归属待核实）
> 主线：把"故障"从异常路径提升为设计的一等公民。

## 1. 核心问题

- 前八讲反复出现的暗线：GFS/MapReduce/Raft 都在"处理"故障，
  本讲把它提炼为方法论：**大规模系统里，故障率 × 规模 = 必然事件**。
  1 万台机器、单机 MTBF 10 小时 → 平均每 1 分钟就有一台倒下。
- Fox & Schindler 的问题意识：为什么很多系统在"设计上"就无法容忍故障？
  因为**端到端契约把可用性绑在了最脆弱的一环上**（TCP 长连接、DNS、BGP、
  路由与策略耦合），故障通过共享依赖放大成全局风暴。

## 2. 关键思想

### 2.1 可重复读（Repeating Reads）
- 传统：TCP 连接建立时一次性解析 DNS/路由 → 之后拓扑变化会让连接坏死。
- 主张：**每一次数据读取/请求都重新完成"从名字到位置"的映射**，
  让系统对"中间人故障（man-through-the-middle failures）"具备自愈性。
- 现代回响：服务网格/客户端负载均衡（每请求选实例）、
  K8s Service 的每连接 iptables/IPVS 再解析、DNS TTL 调低 + 主动刷新。

### 2.2 FTW RPC：透明请求转发
- 目标：中间网络（路由/策略）故障时，让 RPC **绕开坏路径而不是放弃**。
- 机制：把 RPC 的端到端语义与"经由哪条路径"解耦——客户端把请求发给
  任意可达的转发节点，请求头带最终目的地，由它接力转发（source routing 式）。
- 结论：用少量转发节点可把可用带宽提升数倍（论文实验）。
  启示：**可用性 = 路径多样性 + 每请求重路由**，与 2.1 同构。

### 2.3 容错设计清单（本讲工程要点）
- 假设一切都会失败：网络分区、时钟跳变、进程假死（GC/页错误导致"看起来死了"）。
- **超时 + 重试 + 幂等**三件套（呼应 L01 RPC 语义）。
- 区分 crash 与 slow：fencing token（term）防"慢节点复活作恶"。
- 舱壁（bulkhead）/限流/降级：单依赖故障不得级联（2001 年的微服务雏形）。
- 复制不是银弹：**共享单点（电源/配置/DNS/运维手误）会把复制组一起带走**。

## 3. 论文间脉络

- 承接 L05-L08 的"共识给安全"，本讲讲"结构给活性"：
  共识解决"谁说了算"，可重复读解决"找不到说话对象怎么办"。
- 通向 L11 Dynamo：Dynamo 的"永远可写"（quorum + 读修复 + sloppy quorum）
  就是把本讲哲学推到极致的产品。
- 与 L22 IronFleet 互补：本讲是设计哲学，IronFleet 是"把哲学变成机器可检查的证明"。

## 4. 跨课程联系

- **自顶向下计算机网络**：DNS/TTL、BGP 收敛、TCP 重传超时——课上"协议分析"
  在本课变成"故障分析"；topdown 的"端到端原则"正是本讲论证的协议层版本。
- **6.S081**：内核的软脏（soft dirty）页追踪/进程重启 = 单机版容错中间件。
- **CS149**：备份执行（MapReduce backup task）对付 straggler，
  本讲把"对付慢"上升为与"对付死"同级的设计维度。
- **15-445**：死锁检测 vs 锁超时：数据库早已示范"用超时换不确定性下的活性"。

## 5. 开源项目中的应用

- **Envoy/Istio**：outlier detection（把坏实例踢出连接池）+ 每请求负载均衡
  = 可重复读的服务网格化。
- **Hystrix/Resilience4j/Sentinel**：舱壁、熔断、降级——本讲清单的库化。
- **Kafka**：producer 的幂等 + `delivery.timeout.ms` + ISR 收缩下的 acks 策略，
  全是"面向故障"的参数化。
- **HDFS**：短块（short block）处理慢盘/坏盘、DataNode 心跳超时重复制。
- **AWS 的故障演练（Chaos Monkey/GameDays）**：把"假设一切失败"制度化（对接 L22）。
