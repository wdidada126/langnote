# L13 云存储与新硬件：Unrolling S3 与可组合硬件

> 阅读：Werner Vogels 内部资料整理版 *Unrolling Amazon S3* (HotStorage'19 / AllThingsDistributed 2017)；
> 辅读：ElasticBF³ (SIGCOMM 2017)、Cinders/Disaggregation 相关
> 主线：把 L03 GFS 的"文件"抽象推到极致——对象存储与硬件解耦如何支撑 EB 级。

## 1. 核心问题

- 2006 年 S3 的一个 API + 一张 Excel 排期，如今承载数万亿对象。
  核心矛盾：**海量、廉价、持久、高可用、任意规模**——
  传统文件系统（POSIX 语义、元数据树）在超大规模下成为瓶颈。
- 取舍：**放弃文件系统语义换可扩展性**——扁平 key 空间（无目录）、
  不可变对象（一次写、覆盖即新版本）、HTTP 接口。

## 2. S3 的架构演化（"Unrolling"要点）

### 2.1 从单集群到"联邦"
- 早期：每个 S3 集群自包含（index + data 同地），跨集群路由在上层。
- 演化：**Index 与 Data 分离**——独立扩展、独立故障域；
  Object Store 集群按可用性/持久性分层（对应不同 SLA 与介质）。

### 2.2 元数据（Index）系统三代
1. 关系型（InnoDB）分区索引 → 扩展撞墙；
2. 自研低延迟持久 KV（NVMe 上做索引）；
3. **Ark（存储与计算分离的分布式 KV）**：把 Raft/Paxos 类共识的
   "分区（partition）+ 副本 + split/merge"做成通用底座（与 TiKV/CockroachDB 同代，L05/L06/L15）。
- 命名空间用**分区键 = bucket + key 前缀哈希**，天然水平切分。

### 2.3 数据面：Erasure Coding 取代三副本
- 三副本：3× 存储放大，写便宜读简单（L03 GFS/Dynamo 默认）。
- **纠删码（EC）**：k 数据 + m 校验分片存不同故障域，
  任意 k 片可重建 → 放大降到 1.29–1.5×，**换**：重建读放大、小对象不划算。
  S3 冷存储（Glacier/IR）激进 EC。
- 持久性设计：11 个 9（99.999999999%）来自"跨多可用区 + EC + 定期巡检修复"
  （bit rot 扫描 + 后台再平衡）。
- 不可变 + 版本 + LSM：对象写走类似 LSM 的追加，删除靠 GC（L04/L11 血统）。

### 2.4 一致性与多区域
- 2020 起 S3 默认**读你的写（强一致）**——工程上靠 index 层的共识实现
  （把"对象→位置"当作线性一致 KV，L10）；这是"最终一致够用"教条的一次公开修正。

## 3. 新硬件：可组合与解耦（composable disaggregation）

- **Disaggregation**：把计算（CPU/内存）与资源（存储/网络/加速器）拆成池，
  按需组合（ElasticBF³ 用 FPGA 做可扩展 L4 LB；Cinders 用软件定义快存储）。
- **RDMA / NVMe-oF / CXL / SmartNIC(DPU)**：绕过内核协议栈、远程直接访存
  → 把"网络往返"降到微秒级，直接改写 L05/L22 的延迟预算
  （FaRM 就是 RDMA 上的 OCC，见 L22）。
- 主线意义：**硬件解耦让"共识 + 复制"的软件假设（RTT 数百微秒）被打破**，
  催生新协议（如基于 RDMA 的原子性、lease 更细）。

## 4. 论文间脉络

- L03→L13：文件语义 → 对象语义；GFS 单 master → S3 Ark 分区共识。
- 与 L11 Dynamo 同为超大规模存储，但 S3 走"中心化 + EC + 强一致 index"，
  Dynamo 走"去中心 + quorum + 最终一致"。
- 与 L15 Spanner：都把"存储 + 共识 + 分层"做到工业极限，S3 面向对象，Spanner 面向事务数据。

## 5. 跨课程联系

- **体系结构（CS61C/DDCA）**：EC 的伽罗华域运算、RDMA 的 DMA/零拷贝是
  硬件层直接决定系统层设计取舍的例证。
- **15-445/15-721**：LSM、B+、KV 分区在 S3 index 里全部复现；
  EC 对照数据库 RAID/checkpoint 的成本模型。
- **CS149**：可组合硬件 = 把"资源"也变成可并行调度的对象。
- **自顶向下网络**：RDMA/DPDK 是本课"绕过内核 socket 栈"的极致网络实践。

## 6. 开源项目中的应用

- **Ceph（RADOS/EC pool）、MinIO（S3 兼容 + EC）、GlusterFS**：对象存储开源阵营。
- **TiKV/CockroachDB**：Raft 分区 KV 作为"通用 index 层"，与 S3 Ark 思路同构。
- **HDFS Erasure Coding（3.0+）、Kafka（Tiered Storage 上 S3）**：
  热数据本地 + 冷数据对象存储的分层，正是 S3 分层思想反哺。
- **SPDK/DPDK、CXL 内存池、AWS Nitro**：可组合硬件的落地栈。
