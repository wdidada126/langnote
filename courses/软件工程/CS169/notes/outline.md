# CS169 讲义要点（骨架，按 Agile SaaS 单元顺序）

> 每条为骨架级要点；这门课的笔记重点是"流程 + 证据"，每讲应留一个"我们团队当时怎么做/结果如何"的位置。

## L1 导论：软件工程的问题与 SaaS
- 软件工程难在需求变化与协作，而非单点算法；交付频率决定反馈质量。
- SaaS 的三重含义：托管运维、持续演进、以指标驱动决策。
- 课程主线：写 → 测 → 部署 → 观察 → 改进，一个闭环跑满 14 周。
- 与传统"计划-文档"式软工的对比：不做 100 页设计，做可运行的增量。

## L2 敏捷与 XP 价值观
- 五条 XP 价值观：沟通、简单、反馈、勇气、谦逊；实践是价值观的载体。
- 小批量增量交付的经济理由：延迟成本与不确定性。
- 迭代节奏：计划会议 → 开发 → 演示 → 回顾（retrospective）。
- 敏捷不是无文档：文档只保留对下一次交付有用的部分。

## L3 团队与工具链
- GitHub Flow：短分支 + PR + 审查 + 主干常绿；commit 信息写"为什么"。
- Issue/看板作为唯一事实来源（backlog 分层：史诗 → 故事 → 任务）。
- 团队约定（DoD、代码风格、review SLA）比工具更重要。
- 用仓库数据回顾团队行为（与 17-803 的仓库挖掘衔接）。

## L4 云端第一次部署与 12-Factor
- 12-Factor 要点：单一构建、显式依赖、配置入环境、日志当事件流。
- Procfile/启动命令、无状态进程与会话外置（Cookie/存储）。
- 部署即习惯：第一周就上线，让"能跑在我机器上"失效。
- 平台迁移记录：Heroku 免费档取消后改用 Fly.io/Render/自建 Docker 的差异。

## L5 Ruby 与 Rails 核心
- Rails 约定优于配置：目录结构、路由资源映射、ActiveRecord 命名约定。
- MVC 的职责边界：控制器薄、模型厚、视图不含业务逻辑。
- 迁移（migration）是可版本化的 schema，注意回滚与数据修复。
- Ruby 特性（block、monkey patch、元编程）是便利也是维护风险。

## L6 测试驱动开发
- Red-Green-Refactor：测试先行是设计手段，不是验收手段。
- 测试金字塔在 Rails 的比例：模型单元为主、请求/系统测试少量。
- fixture/factory 的可读性与速度取舍；避免测试相互依赖。
- 覆盖率只看趋势，真正的判据是"改坏了会红"。

## L7 结对编程与代码审查
- Driver/Navigator 轮换、静默期与"共享心智模型"的收益。
- 结对适合：复杂设计、缺陷排查、知识传递；不适合：机械重复任务。
- 审查关注规格与影响，机器能查的（风格、静态问题）交给 CI。
- 小 diff 文化：一次 PR 只做一件事，评审时间 < 30 分钟为宜。

## L8 敏捷规划与估点
- 故事卡片格式（角色-目标-价值）+ 明确验收条件。
- 规划扑克与"故事点 = 相对复杂度"，速度用滚动平均而非单点。
- 燃尽图/累计流程图用于发现瓶颈，不用于惩罚个人。
- WIP 限制：并行越少，完成越快（排队论直觉）。

## L9 CI/CD 与自动化发布
- 主干常绿：CI 必须包含测试、lint、安全扫描与构建产物。
- 部署流水线分级：staging → canary → 全量，回滚与灰度同等重要。
- 特性开关让"合并"与"发布"解耦，支持长时间开发。
- 失败要响亮：告警、通知与"谁打红谁修"的团队契约。

## L10 重构与设计模式
- 坏味道清单：长方法、大类型、特性嫉妒、发散式变化、重复代码。
- Rails 中的模式：Service Object、Form Object、Concern、Query Object。
- SOLID 在 Web 应用里的实际收益点（DIP 让测试可行）。
- 重构前先补测试，重构与功能变更不混在同一个 PR。

## L11 可扩展性与性能
- 性能预算：先测量（APM/慢查询日志）再优化，避免猜测。
- 数据库层：索引、N+1 查询、分页与连接池；读写分离。
- 缓存层：HTTP 缓存、片段/Rails cache、Redis 与失效策略（写少读多）。
- 异步化：Sidekiq/delayed_job 队列、幂等任务与重试退避。

## L12 NoSQL 与数据模型取舍
- 关系型 vs 文档 vs 键值：一致性需求、访问模式与演进成本三者权衡。
- 分片与副本：CAP 的实际表达（P 不可选），一致性等级。
- 反范式的代价：数据同步、报表与完整性靠应用层保证。
- 多数 Web 应用不需要"换库"，先解决索引与缓存。

## L13 安全与隐私
- 认证与授权分离：OAuth2/OIDC 流程、会话与令牌存放位置。
- 常见漏洞：注入、XSS、CSRF、越权（IDOR）、SSRF；OWASP Top 10 对照。
- 输入不可信原则：服务端校验 + 按上下文输出编码。
- 隐私与合规：数据最小化、日志脱敏、GDPR/CCPA 对功能的约束。

## L14 运营、产品与结课冲刺
- 真实用户监控与指标：留存、漏斗、性能指标与错误率（SLO 直觉）。
- A/B 测试与假设驱动开发：一次只改一个变量，样本量先行。
- 多租户与配额：数据隔离策略、噪声邻居与成本分摊。
- 开源与伦理：许可证选择、对用户与社会的责任（课程"engineering for social good"部分）。
