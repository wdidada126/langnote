# 6.031 讲义要点（骨架，Latest 版）

> 每条为骨架级要点。6.031 没有视频，正文笔记应以"规格写法 + 反例 + 重构 diff"三件套为主。

## L1 导论：高质量代码三目标
- Safe from bugs / Easy to understand / Ready for change 三者是同一件事的不同投影。
- 软件工程与程序设计的差别在于"变化"与"他人"：代码是给人读的。
- 课程主线：规格 → 抽象 → 复用 → 并发 → 安全，五个尺度逐级放大。
- 工具链先立：JDK 11+/17、Gradle、JUnit、Git、IDE 与静态检查。

## L2 Java 速成与代码阅读
- 值类型 vs 引用类型、别名（aliasing）是所有 bug 的温床。
- 异常是控制流的一部分：checked vs unchecked 的选择规则。
- 集合框架与迭代器；避免在循环中做 O(n) 的 contains。
- 读代码方法：从入口点追踪状态变化，用 IDE 的调用图辅助。

## L3 版本控制与协作
- 提交粒度=一个可解释的意图；主干开发与 PR 审查流程。
- rebase vs merge 的历史语义差别与团队约定。
- `.gitignore`、构建产物不入库、可重现构建是工程底线。
- 用 Git 历史做定性分析（为 17-803 的仓库挖掘埋点）。

## L4 代码审查
- 审查看什么：正确性、规格符合、抽象是否泄漏、命名、测试是否证明行为。
- 评论要指向代码而非作者；区分"必须改/建议/疑问"三档语气。
- 小 PR 优先：审查质量与 diff 规模强负相关。
- 自我审查：提交前 diff 逐行读，附上"为什么这样改"的说明。

## L5 单元测试
- 单元 ≠ 文件：一个 @Test 验证一条规格行为。
- 测试金字塔：大量单元、少量集成、极少端到端。
- 覆盖率是必要非充分；断言要具体（等价类 + 边界值）。
- 用 JUnit 的参数化与 `@RepeatedTest` 减少组合爆炸。

## L6 规格 Specification
- PRE/POST/RET/TERMINATES 四段式，客户端与服务端的责任划分。
- 弱前置条件 + 强后置条件 = 好接口；越精确越可测。
- 规格决定实现自由度：写"做什么"不是"怎么做"。
- 常见错误：把实现细节写进注释、用自然语言含糊化边界。

## L7 测试策略与派生
- 从规格输入分区（input space partition）机械导出用例，避免凭直觉。
- 属性测试（property-based）与随机化测试找出边界案例。
- 幂等/交换率/往返（round-trip）等通用属性的利用。
- 回归测试的定位：证明"曾经失败过"，而非替代单元用例。

## L8 抽象数据类型 ADT
- 三要素：AF（表示 → 抽象值）、RI（合法表示）、表示独立性。
- 安全表示暴露：不要把内部可变对象直接返回给客户端。
- 抽象层次：一个类型只承担一层职责。
- RI 检查要廉价：构造时断言，而非每个方法重复验证。

## L9 不可变类型
- final 字段 + 深不可变 + 无 setter；不可变即线程安全。
- 缓存/记忆化只在不可变前提下才正确。
- `equals/hashCode` 与"值语义"的实现要求。
- 用 Guava/Java record 与自建不可变集合对照。

## L10 接口与实现分离
- 接口是契约，不是方法集合：可替换性是判据。
- 包依赖方向应由策略指向细节（DIP 的前置）。
- 抽象泄漏的信号：客户端被迫知道实现的时序/成本。
- 接口的粒度：窄接口 + 多个实现优于胖接口。

## L11 泛型与类型参数
- 类型擦除的代价与数组协变的历史包袱。
- `? extends T` 生产者 / `? super T` 消费者（PECS）。
- 泛型方法 vs 泛型类的选择；通配符捕获技巧。
- 不变性（invariance）是并发共享的安全默认。

## L12 子类型与替换原则
- 行为子类型：任何客户端能用的地方，子类型必须同样可用（LSP）。
- 协变返回、逆变参数的类型系统支持程度。
- 继承 vs 组合：优先组合；继承易破坏表示独立性。
- 用替换检验设计：写一个子类去"破坏"父类规格，说明设计有洞。

## L13 可变 ADT
- Observer/Mutator 分离；变更者的返回值与幂等性设计。
- 表示共享（shared representation）与别名带来的隐藏耦合。
- 迭代器失效：fail-fast 与快照迭代两种工程选择。
- 可变对象 + 不可变视图（unmodifiable wrapper）的常见模式。

## L14 面向对象设计原则
- 职责驱动：命名类型要能一句话说清它"是什么东西"。
- 分层（layering）与依赖注入的可测试性收益。
- 常见坏味道：上帝类、特性嫉妒（feature envy）、贫血模型。
- 每次重构只解决一个问题，并靠测试保证行为不变。

## L15 设计模式
- 策略：替换 if-else；工厂：分离创建与使用；装饰：正交扩展。
- 组合模式处理树形递归结构；观察者处理广播与回调。
- 模式的滥用信号：为了模式而增加无行为的抽象层。
- Java 8 后许多模式可用函数式接口/lambda 替代。

## L16 并发基础
- 线程、调度与内存可见性：竞态来自"未同步的共享可变状态"。
- 原子性边界：复合操作（check-then-act）天生非原子。
- 线程安全规格写法：声明哪些操作组合是原子的、哪些不是。
- 死锁四条件与最小复现样例的构造方法。

## L17 锁与 Guarded Object
- 用锁保护不变式，而非保护字段；锁的粒度与顺序规则。
- Guarded object 模式：条件等待 + while 循环重查谓词。
- `wait/notify` 与 `Lock/Condition` 的取舍；避免 `notify` 丢失唤醒。
- 不可变 + 消息传递优于共享可变 + 锁。

## L18 更高层次并行
- ExecutorService/线程池：任务与线程解耦，控制并发度。
- 并行流的正确用法（无共享可变状态、无阻塞 IO）。
- 线程安全与"可重入"、"死锁自由"的关系。
- 用 `CountDownLatch`/`Semaphore` 表达协调而非自旋。

## L19 性能与正确性权衡
- 先测量再优化：基准测试的常见陷阱（预热、死代码消除）。
- 记忆化的失效策略与内存上界（LRU → 与 CS61B/6.006 呼应）。
- 数据结构选型对缓存友好性的影响远大于常数。
- 正确性与性能的冲突要写进注释，让人知道为什么。

## L20 服务端与 Web 服务
- 请求-响应、无状态服务与水平扩展的关系。
- REST 资源建模、方法语义与幂等性（PUT vs POST）。
- 版本化 API、错误响应规范与可观测性。
- 服务端分层：路由 → 服务 → 持久层，每层可单独测试。

## L21 客户端与服务端交互
- 客户端校验只为体验，服务端校验才是安全边界。
- JSON 反序列化的信任问题：不要相信任何来自客户端的输入。
- 同源策略与 CORS 的机制与常见误配。
- 单页应用的状态管理与后端接口粒度。

## L22 Web 安全 I：注入与 XSS
- SQL 注入根因是"代码与数据混写"；用参数化查询彻底解决。
- 输出编码按上下文（HTML/属性/JS/URL）区分；CSP 兜底。
- XSS 的存储型/反射型/DOM 型三类与复现步骤。
- 最小权限数据库账号、纵深防御与日志留证。

## L23 Web 安全 II：认证与会话
- 会话令牌、Cookie 属性（HttpOnly/Secure/SameSite）与作用域。
- CSRF 的成因与同步令牌/双重提交解法。
- 口令存储：加盐慢哈希（bcrypt/scrypt/argon2），永不自研加密。
- 访问控制在服务端做，UI 隐藏只是装饰。

## L24 综合复习与项目交付
- 用质量三目标逐项体检自己的 Project。
- 规格-测试-实现三者一致性的复审清单。
- 重构练习：把一次"能跑"改成"好懂 + 易改"。
- 与后续课衔接：CS169 讲团队如何持续做，17-803 讲如何度量做得好不好。
