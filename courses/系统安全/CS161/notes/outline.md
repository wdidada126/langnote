# CS161 讲义要点提纲（骨架）

> 每讲 3–5 条要点级提纲，正文笔记后续按讲填充。

## L1 导入：威胁模型
- 安全是属性而非产品：机密性/完整性/可用性（CIA）与真实性、不可否认性。
- 一切分析从威胁模型开始：攻击者能力、目标资产、信任边界在哪里。
- 攻击面（attack surface）最小化是贯穿全课的设计观。
- 课程五部分地图：原则 → 内存 → 密码 → Web → 网络。

## L2 安全设计原则
- Saltzer & Schroeder：开放设计、失效安全、最小特权、最小公共化、完全中介。
- 经济权衡：安全成本 vs 资产价值；可用性与安全的拉锯。
- 心理因素：用户会绕过复杂机制（可用失败默认值）。
- 案例讨论：哪些原则在真实系统中最常被违反。

## L3 访问控制
- IBAC（身份基）、RBAC（角色基）、ACL 与能力（capability）三种模型。
- 中国墙模型（Biba/Bell-LaPadulla 简述）：利益冲突约束。
- 策略与机制分离：先定义模型再选实现。
- 联系项目：文件分享系统的权限模型选型。

## L4 案例：Kerberos 与选举
- Kerberos：可信第三方 + 对称密钥的时间戳票据流程，TGT 与 session key。
- Needham-Schroeder 的错误与 Lowe 攻击：协议形式化分析的必要性。
- 密钥管理的难度往往大于密码算法本身。
- 选举系统：端到端可验证性与威胁模型的现实演练。

## L5 不安全内存
- C 的裸指针与无边界检查：off-by-one、UAF、double free、类型混淆。
- 整数溢出 → 分配尺寸错误 → 堆溢出攻击链。
- 字符串函数族（strcpy/sprintf）事故博物馆。
- Lab1 预热：阅读不安全代码找漏洞的心法。

## L6 栈溢出攻击
- 栈帧布局：返回地址紧邻局部缓冲区的历史成因。
- ret2shellcode / ret2plt / ret2libc：劫持控制流的三个层次。
- shellcode 约束：避 \x00、可注入性；ROP 为绕过 DEP 而生。
- Aleph One 文章仍是理解攻击者思维的最佳读物。

## L7 内存安全防御
- Stack canary、ASLR、DEP/NX、CFI 各自的原理与绕过方式。
- 防御纵深：编译器加固 + 运行时检查 + 硬件特权级。
- 内存安全语言（Rust/Go）从根上消解哪一类漏洞、留下哪一类（unsafe/序列化）。
- Project1 攻击链：从信息泄露到控制流劫持的组合拳。

## L8 对称加密
- 语义安全（IND-CPA）：确定性加密为什么危险（ECB 企鹅图）。
- AES 分组模式：CBC/CTR 的正确使用，IV 唯一性要求。
- 填充错误与 padding oracle：密文是可被主动攻击的数据结构。
- 工程要点：用成熟库（OpenSSL/libsodium），永远不要自研算法。

## L9 非对称加密
- 公钥密码动机：密钥分发问题的数学解（DH 密钥交换）。
- RSA：数学构造、OAEP 填充与「教科书 RSA 不安全」的教训。
- 混合加密：公钥封装 + 对称加密 Bulk 数据的现实范式。
- 椭圆曲线与密钥长度对比表。

## L10 完整性与签名
- 哈希安全：原像/第二原像/碰撞；MD5/SHA-1 的沦陷史。
- MAC（HMAC）与 AEAD（GCM）：认证加密一体化趋势。
- 数字签名：真实性+完整性+不可否认；签名而后加密 vs 加密而后签名。
- 长度扩展攻击与 HMAC 构造动机。

## L11 密钥分发与 PKI/TLS
- 信任从哪来：CA 层级、证书链验证与透明日志（CT）。
- TLS 握手（1.2 vs 1.3）：协商、前向安全（ECDHE）。
- PKP/TOFU/Web of Trust 等替代信任模型。
- Project2 直接应用：自签 vs CA、证书固定策略。

## L12 Web 基础与同源策略
- HTTP 无状态与会话：Cookie 属性（HttpOnly/Secure/SameSite）。
- 同源策略是 Web 安全的承重墙；CORS 是受控的例外通道。
- 浏览器信任模型：谁信任谁、基于 URL 还是内容。

## L13 注入与前端攻击
- SQL 注入：数据被当代码解释；参数化查询与最小权限 DB 账号。
- XSS（反射/存储/DOM 型）：上下文感知输出编码、CSP。
- CSRF：浏览器自动附带凭证的代价；反 CSRF token 与 SameSite。
- 点击劫持、开放重定向等「浏览器特性滥用」家族。

## L14 安全系统设计实战（Project 2 评审）
- 需求 → 威胁模型 → 设计 → 实现 → 对抗性测试的完整闭环。
- 文件分享系统：认证、分享令牌熵、传输加密、服务端密钥管理。
- 评审清单：哪些设计决策在攻击下退化，如何补救。
- 3k 行 Go 密集开发的经验萃取。

## L15 DNS 安全
- DNS 设计缺陷：可伪造响应、事务ID 空间小、缓存投毒面。
- DNSSEC：区域签名链与信任锚；部署代价与局限（不加密查询内容）。
- DoH/DoT 解决的是窃听与中间人改写。
- 案例：Mirai 与 DNS 放大攻击。

## L16 路由与信任（BGP）
- BGP 建立在「运营商互相依赖」的信任假设上：前缀劫持频发。
- RPKI/ROV：密码学路径验证的来源地址证明。
- 端到端原则再审视：路由层为何缺乏源认证。
- 案例：历史大型 BGP 泄露/劫持事件复盘。

## L17 DoS 与侧信道
- DoS 谱系：带宽洪泛、资源耗尽、逻辑放大（DNS/NTP 反射）。
- 防御：限流、Anycast、CDN scrubbing 的边界。
- 侧信道：时序/缓存（Spectre 家族预告）、功率与 Hertzbleed 视角。
- 安全无法外包给单点：纵深与监控。

## L18 总结与前沿
- 五部分知识图的收束：原则、内存、密码、Web、网络如何互相咬合。
- 攻防不对称：防御者要挡住所有门，攻击者只要找到一个。
- 后续路径指北：6.858（攻防系统）、6.1600（密码理论）、pwn.college（CTF 手感）、SEED Labs（实验库）。
