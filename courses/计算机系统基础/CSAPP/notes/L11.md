# L11 代码优化进阶：循环展开、SIMD 与向量化

> 阅读材料：CSAPP 5.12–5.13、5.17 ｜ 承 L09 依赖链、L08 流水线

## 核心概念

### 1. 超标量与乱序：硬件也在找 ILP
```
超标量(superscalar): 每周期发射/退休多条指令（宽度 4~6）
乱序(OoO): 记分板+保留站，只要无数据依赖即可提前执行；ROB 保序退休。
→ 软件展开的意义：把独立工作"喂"给硬件窗口（~几百条指令），
  窗口装不下的串行依赖才是天花板（L09 combine 系列复现此现象）。
```

### 2. 循环展开的完整配方（combine5→combine6）
```c
for (i = 0; i < limit - 3; i += 4) {          // 主循环
    long x0 = acc * data[i+0];
    long x1 = acc * data[i+1];
    long x2 = acc * data[i+2];
    long x3 = acc * data[i+3];
    acc = ((x0 * x1) * (x2 * x3));            // 树形合并，依赖深度 log(4)
}
for (; i < limit; i++) acc *= data[i];        // 尾循环
```
- 收益来源：削减 loop 开销 + 打破串行链制造 ILP；CPE 从"延迟"向"吞吐"逼近。
- 过度展开反噬：代码体积 → I-Cache 未命中（L10）；分支对齐变差。

### 3. SIMD：单指令多数据
```
SSE2: xmm 0~15, 128bit(2×64/4×32/16×8); AVX2: ymm 256bit; AVX-512: zmm
浮点乘加: mulsd(标量) → mulpd(2 路 double) → vmulpd(ymm 4 路 double)
combine7: 循环步长 4，float 路径 8 路（ymm 装 8 个 float）
gcc -mavx2 -O2 才自动向化；intrinsics: _mm256_mul_pd 等
```
- 整数 SIMD 乘除支持弱（历史包袱）；向量除法在多数 ISA 里缺席。
- 自动向量化失败三大原因：别名/依赖调用/归约链——逐一对照 L09 解决。

### 4. SIMD 编程三层次
```
1) 编译器自动向量化(-O3 -march=native, 看 -fopt-info-vec 报告)
2) intrinsics(手写向量, 可读性差性能顶)
3) 可移植模式库(如 xsimd / Google highway，用标准 C++ 抽象 SSE/AVX/NEON)
```
- 归约（reduction）在 SIMD 下需要"水平操作"（hadd）收尾，代价小但易忘。
- Amdahl 定律：向量化只加速可并行部分；串行段占比决定上限。

### 5. 程序级并行预告
本讲把"单核指令级并行(ILP)"推到极限；L20 起跨线程共享数据的新麻烦
（竞态）正式登场——优化与正确性开始互相制衡。
