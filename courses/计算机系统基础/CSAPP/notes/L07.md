# L07 机器级程序（IV）：数据结构、对齐与缓冲区

> 阅读材料：CSAPP 3.9–3.11 ｜ Attack Lab 发布

## 核心概念

### 1. 数组：指针算术的机器本质
```c
int E[5];  // E: %rdi
E[i] += 1;                      → movq (%rdi,%rsi,4) 基址+索引×元素大小
int A[R][C]; A[i][j] →  *(A + i*C + j)   行主序（C/C++），列主序是 Fortran
```
- 一维化：`row*C+col`；编译器对循环做"归纳变量"把乘法换成加法指针（L09 伏笔）。
- 可变长数组 VLA 的行长存在栈上，`imulq` 动态寻址。

### 2. 结构与联合：编译期偏移，运行期零开销
```c
struct s1 { short a; long b; char c; };   // 8 对齐
// a@0(2) pad@2(6) b@8(8) c@16(1) pad@17(7) → sizeof = 24
struct s2 { char c; short a; long b; };   // 重排: c@0 a@2 pad b@8 → sizeof = 16
union u { int i; char c[4]; };            // 共享起始地址，大小=最大成员
```
- 对齐规则：`K-对齐` 要求地址是 K 的倍数；结构对齐 = 成员最大对齐。
- 访问未对齐数据：x86 多数指令允许但跨缓存行变慢；ARM/RISC-V 直接 SIGBUS 类错误。
- `#pragma pack`/`__attribute__((packed))` 可省填充，代价是性能与取址陷阱。

### 3. 为什么对齐：硬件与缓存的双重理由
- 数据总线/缓存行按 8/16 字节条带取数；未对齐可能多一次条带访问。
- SSE 指令如 `movaps` 硬件级要求 16 对齐（L06 栈对齐的真正动机）。
- 原子性承诺：对齐的 word 读写天然原子（无锁结构的前提，L20 伏笔）。

### 4. 缓冲区：指针是 C 的"不安全切片"
```c
char buf[32];
gets(buf);                 // 已进 C11 黑名单；无限写 → 溢出
strcpy/strcat/sprintf      // 无边界版本 → strncpy/snprintf 族
printf(user_input);        // 格式字符串漏洞：%x 泄露栈、%n 写栈
free(p); ... *p;           // use-after-free
p = malloc(n); p[i]=...    // 引用已释放 / 越界 / 不释放
```
- 经典攻击链（Attack Lab）：溢出覆盖返回地址 → ret2text（跳到已有代码）
  → ret2shellcode（ROP 前的第一步）→ ROP（拼 gadget 绕过 NX/栈保护）。
- 防御与呼应 L06：栈金丝雀、ASLR、NX/DEP、CFI/CET。

### 5. 用机器级视角看"信息即比特"
同一块 8 字节：`long`、`double`、`char*`、结构里的两个 `int`——类型只存在于
编译期；运行期全是偏移+宽度（`%rax` vs `(%rax)` vs `(%rbp,%rax,8)`）。

## 开源项目中的应用
- **Protobuf/FlatBuffers**：wire format 变长字段 vs 内存对齐布局的取舍教科书。
- **Linux 内核 `struct page`**：严格 64 字节/页对齐，`___cacheline_aligned` 宏防伪共享。
- **Nginx `ngx_pool_t`**：内存池按对齐返回地址（`ngx_align_ptr`）。
- **网络协议头**：`struct iphdr` 位域 + packed；跨端字节序另需 `ntohl`。
