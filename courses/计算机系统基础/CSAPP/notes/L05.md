# L05 机器级程序（II）：控制与分支的汇编实现

> 阅读材料：CSAPP 3.6–3.7 ｜ 承 L04 词汇，启 L06 过程

## 核心概念

### 1. 条件码（EFLAGS）：CMP/TEST 的副产品
```
CF 进位（无符号溢出）  ZF 零  SF 符号  OF 有符号溢出(补码)
CF|OF 组合恰好能判加减法溢出；硬件只有一套减法，软件"各取所需"解读标志。
```

### 2. 跳转指令家族
```
jmp  Label / jmp *%rax(间接) / jmp *(%rbx)
条件跳转 jcc（对 cmp/test 置起的标志做判定）：
  有符号      无符号      含义
  je/jne      je/jne      等 / 不等          (ZF)
  jl/jge      jb/jae      小于 / 大于等于     (SF≠OF | CF)
  jle/jg      jbe/ja      小于等于 / 大于     (ZF|(SF≠OF) | CF|ZF)
  js/jns      —           负 / 非负          (SF)
  jp/jnp      —           奇偶为 1 / 0（浮点比较判 NaN 用 PF）
setcc %al       # 把标志写成字节，常配 movzbl 取回
cmovcc src,dst  # 条件移动：无分支 if-else，利于流水线
testq %rax,%rax → setne %al（判非 0 惯用法）
```

### 3. 编译器如何翻译 if / 三元
```c
long cmov_max(long x, long y) { if (x < y) x = y; return x; }
```
```asm
cmov_max:
    movq  %rdi, %rax
    cmpq  %rsi, %rdi       # 计算 x - y，只留标志
    cmovl %rsi, %rax       # x < y 时 rax = y —— 全程无跳转
    ret
```
- GCC `-O1` 起倾向用 `cmov` 消除分支；但条件为真概率不均时分支预测更划算。
- Bomb phase_3/4 反复出现 `cmp/test + jg + scanf("%d")` 套路。

### 4. 循环：全部规范化为 do-while
```c
for (i=0; i<n; i++) sum += i;
```
```asm
    movl $0,%esi          # i=0
    jmp  .L_test_prepared # for 先测后执行 → 前置 jmp
.L_body:
    addq %rsi,%rax        # sum += i
    addq $1,%rsi          # i++
.L_test_prepared:
    cmpq %rdx,%rsi        # i < n ?
    jl   .L_body
```
- while：直接条件放头部；do-while：条件放尾部，天然少一次 jmp。
- while(true)+break：条件取反跳转。

### 5. switch：跳转表（O(1) 分支）
```asm
movq (%rdi),%rax
cmpq $8,%rax              # 越界检查
ja   .Ldefault
jmp  *table(,%rax,8)      # 表基址 + 索引×8 间接跳
.section .rodata
table: .quad .L3,.L4,.L5,...   # 编译器生成的 .rodata 表
```
- case 连续密集 → 跳转表；稀疏 → 二分决策树（Bomb phase_4 的经典）。

### 6. 浮点比较的陷阱
- `ucomiss/ucomisd` 只能设 ZF/CF/PF，SF/OF 清零；NaN 使 PF=1。
- C 的 `a < b` 在 a 为 NaN 时应为假：汇编用组合条件表达，呼应 L03。

- **DDCA**：跳转表 = 多路选择器；分支 = 控制单元的标志判定电路。
- **CS143/编译**：if/loop/switch 的代码生成、寄存器分配前 CFG。

## 开源项目中的应用
- **Linux 内核 `__jump_table`**：static keys/tracepoint 用跳转表热补丁。
- **LuaJIT VM**：解释主循环 switch → 计算 goto；GCC 用 computed goto（`&&label`）。
- **Redis `latency`/事件循环**：热路径分支用 `likely/unlikely`（内核宏）指导预测。
- **Btrfs/内核代码**：`switch` 密集解析器（如 ELF/ASN.1 解析）依赖跳转表。
