# L12 链接：目标文件、符号解析、重定位

> 阅读材料：CSAPP 7.1–7.9 ｜ Attack Lab 截止 ｜ 从"单程序"走向"多模块世界"

## 核心概念

### 1. 链接发生在何时
```
静态链接期(ld)：合并 .o → 可执行文件（本讲主线）
加载期：共享库被装入（L13）
运行期：dlopen（L13）
驱动：从 1960s 分离编译需求 → 多语言/多模块 → 组件化编程
```

### 2. 目标文件三种面孔（同格式，不同用法）
- 可重定位目标文件（`.o`/`.obj`）：含二进制代码+数据，可与他合并。
- 可执行目标文件（a.out）：可直接复制到内存运行。
- 共享目标文件（`.so`/`.dll`）：动态链接用的特殊可重定位文件（L13）。

### 3. ELF 布局（Linux；Windows 对应 PE/COFF）
```
ELF Header → .text .data .bss .rodata .symtab .rela.text .debug .line
             .strtab(字符串表) .comment
.bss 不占文件空间，运行时清零；未初始化全局进 .bss，初值 0 全局在老标准进 .data
关键命令: readelf -h/-S/-s, nm, objdump -t, size
```

### 4. 符号（symbol）
三种：全局（函数+非 static 全局变量）、文件本地（static）、section 局部。
```
mangling: C++ 把重载/命名空间编进名字；extern "C" 关闭；
          nm 输出类型字母: T/t(代码) D/d/B/b(数据) R(只读) U(未定义) W(弱)
```

### 5. 符号解析规则（C 语言链接器视图）
```
强符号: 函数、已初始化全局      弱符号: 未初始化全局( tentative definition)
规则1: 多重定义强符号 → 链接错误
规则2: 一个强 + N 个弱 → 选强
规则3: 多个弱 → 任选（这就是"重复定义却安静通过"的经典事故源）
陷阱: #define MAXV 100 vs int maxvec=...  —— 类型不匹配时链接器不检查！
      同名 static 变量在不同 .c 完全正常（作用域隔离）。
```

### 6. 重定位（relocation）
```
.o 中地址全是"从 0 起步"的假想；链接期:
1) 为每个 section 分配运行地址  2) 合并同类 section  3) 按重定位表修指令
重定位条目: .rela.text: 偏移 13, 类型 R_X86_64_PC32, 符号 sum, 加数 -4
ld 顺序敏感：库放使用方之后（libx.a 依赖 liby.a → -lx -ly）
```

### 7. 静态库
```
libvector.a = 带索引(member index)的 .o 归档（ar rcs）
链接器只对"当前未决符号"扫库 → 一次扫描即弃 → 顺序即拓扑序
现代替代: --start-group/--end-group, lto
```

## 开源项目中的应用
- **binutils ld / LLVM lld / gold**：三大主流链接器；lld 快在并行 section 合并。
- **Linux 内核 vmlinux**：链接脚本 `vmlinux.lds.h` 控制段布局（__init_begin 等符号）。
- **protobuf/gRPC 静态库事故**：多版本 libprotobuf.a 混链 → 全局注册表重复符号，
  正是"规则 3"的生产级翻车。
- **LTO（-flto）**：链接期全局优化，模糊编译/链接边界。
