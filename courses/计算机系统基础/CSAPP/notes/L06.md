# L06 机器级程序（III）：过程、栈帧与递归

> 阅读材料：CSAPP 3.8 ｜ Bomb Lab 截止 ｜ 栈帧是 Attack Lab 的舞台

## 核心概念

### 1. 调用约定（System V AMD64 ABI，Linux 用；Windows x64 另有一套）
```
前 6 个整型/指针参数: %rdi %rsi %rdx %rcx %r8 %r9
第 1~4 个浮点参数:   %xmm0~%xmm3        浮点返回值: %xmm0
整型返回值: %rax（无返回值则随意）
超过 6 个: 从右往左依次 pushq 到栈上，被调方通过 16(%rbp) 等访问
```
- Windows x64：前 4 参走 `%rcx %rdx %r8 %r9`，且调用方须为被调方预留 32 字节
  "shadow space"——跨平台 C 库源码里 `#ifdef _WIN32` 的汇编差异即来源于此。

### 2. 寄存器责任分工
```
调用者保存(caller-saved): 除 %rsp 外的全部临时寄存器(%rax,%rcx,%rdx,%rsi,%rdi,%r8-r11)
被调者保存(callee-saved): %rbx, %rbp, %r12~%r15
→ 长命变量放 callee-saved，短命计算放 caller-saved，是编译器分配启发式的根。
```

### 3. 栈帧生命周期
```
        高地址
   ┌────────────────┐
   │  caller 参数区  │
   ├────────────────┤
   │ 返回地址 (call 压入)
   │ 保存的 %rbp     │ ← callee 的 %rbp；%rsp 继续向下
   │ callee-saved    │
   │ 局部变量/对齐填充│ ← %rsp 帧顶
        低地址（栈向低增长）
call Label  ≡ pushq 返回地址(%rip后) ; jmp Label
ret         ≡ popq %rip
leave       ≡ movq %rbp,%rsp ; popq %rbp
```
- 16 字节对齐 ABI：`call` 后 `%rsp % 16 == 8`（返回地址所致），故函数体常
  `subq $0x18, %rsp` 再配平，为 `movaps` 之类要求 16 对齐的 SSE 指令服务。

### 4. 一个标准 prologue/epilogue
```asm
proc:
    pushq %rbp            # 保存旧帧
    movq  %rsp, %rbp      # 建立新帧
    pushq %rbx            # callee-saved 按需（偶数个 push 保持对齐）
    subq  $16, %rsp       # 局部空间
    ...
    addq  $16, %rsp
    popq  %rbx
    popq  %rbp
    ret
```
- `-fomit-frame-pointer`（GCC ≥4.6 默认开）：不压 %rbp，全靠 %rsp+偏移寻址，
  省寄存器；代价是调试器回溯需要 .eh_frame 展开信息。

### 5. 递归 = 帧链
```c
long rfact(long n) { return n ? n * rfact(n-1) : 1; }
```
每层帧保存 n 与返回地址；深度过大 → 撞上 guard page → SIGSEGV（L16）。
尾递归 `f(n, acc)` 在 `-O2` 下可被优化成 jmp 复用帧（GCC 只对自递归做）。

### 6. 变长参数与 gotcha
- `%` 打印函数：`printf(msg)` 是不安全代码（L07 格式字符串漏洞前奏）。
- `varargs` 的 `va_start/va_arg` 依赖栈上参数区与 `%al`=向量寄存器个数约定。

## 开源项目中的应用
- **libunwind / libgcc `_Unwind_*`**：C++ 异常回溯靠 .eh_frame 遍历帧链。
- **gdb backtrace / ASAN stacktrace**：帧展开（frame unwind）实现。
- **eBPF `bpf_get_stackid`**：内核态采用户栈帧链做 profiling。
- **协程库（libaco、腾讯 Libco）**：手写汇编保存/恢复 callee-saved 集实现栈切换。
