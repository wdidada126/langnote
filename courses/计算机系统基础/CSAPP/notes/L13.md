# L13 共享库、位置无关代码与程序装载

> 阅读材料：CSAPP 7.10–7.12 ｜ 《程序员的自我修养》选读 ｜ 承 L12

## 核心概念

### 1. 为什么要共享库
```
静态库之痛: 每个进程一份副本(内存/磁盘浪费)、升级=重链所有程序
共享库: 磁盘一份、内存可多进程共享、运行期可升级/替换
代价: 间接寻址开销 + 版本地狱(DLL hell / ABI 兼容)
```

### 2. 位置无关代码（PIC）与 GOT
```
共享库须装入任意地址 → 代码段不能被改写(只读+共享) → 所有外部引用走数据表:
GOT(Global Offset Table): 数据段里的"指针数组/跳转目标表"，加载期填真实地址
PLT(Procedure Linkage Table): 代码段里的跳板，配合延迟绑定(lazy binding)
调用库函数: call foo@plt → jmp *GOT[n]（首次: 跳回 plt 调 _dl_runtime_resolve 填表）
访问库全局变量: movq foo@GOTPCREL(%rip), %rax   —— PC 相对寻址是 PIC 的基石
编译: -fPIC(gcc) / -fpic；Windows DLL 用重定位表+加载基址(ASLR)方案，无 GOT 传统
```

### 3.  libxxx.so.x.y.z 与版本
```
SONAME:  ABI 主版本（ldconfig 建软链 /etc/ld.so.conf）
符号版本脚本(symver): 同一 .so 导出多 ABI；glibc 即靠它兼容 30 年符号
依赖链: ldd 看依赖树；ldconfig -p 看缓存
```

### 4. 从 Shell 到 main：程序装载时刻表（Linux）
```
Shell fork → execve("/bin/prog") → 内核:
  解析 ELF 程序头表(program header) → 建立虚存区域(mmap 映射 .text/.data/.interp)
  → 发现 .interp(ld-linux.so) → 装载动态链接器 → 控制权交给它
  → 加载依赖库(按 DT_NEEDED 拓扑序) → 重定位/填 GOT → 跳 entry(_start)
  → __libc_start_main 准备 argc/argv/envp → main(argc, argv)   ← L01 的 hello 至此闭环
```

### 5. 装载与地址空间无关的三件事（控制反转预告）
- **dlopen/dlsym/dlclose**：应用自己决定何时装载（插件体系：nginx module、
  PHP extension、数据库 UDF）。
- **LD_PRELOAD 符号拦截（interposition）**：无需重编译替换实现
  （如 preload jemalloc/tcmalloc、拦截 open 做沙箱、LD_PRELOAD 调试神器）。
- 拦截顺序 = 依赖拓扑序：可执行文件 > 先加载的库 > 后加载的库。

### 6. 库碎片的系统侧后果
静态 vs 动态选型：容器发行版（Alpine musl 静态化）、HSM 固件常用静态链接；
glibc 静态链接有 dlopen/NSS 限制 → "musl/静态二进制复兴"工程潮流。

## 开源项目中的应用
- **glibc `elf/dl-*.c`**：ld-linux.so 全部源码；`_dl_runtime_resolve` 性能影响。
- **jemalloc/tcmalloc 部署**：`LD_PRELOAD=libjemalloc.so` 一行不改换分配器（L17 联动）。
- **Nginx 动态模块**：`--add-dynamic-module` + dlopen。
- **LLVM plugins / GCC 插件**：-fplugin 走插件接口；Sanitizer 即库 interposition 技术。
