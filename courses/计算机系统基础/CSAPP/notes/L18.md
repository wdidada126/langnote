# L18 系统级 I/O：文件、描述符与 Unix I/O

> 阅读材料：CSAPP Ch.10 ｜ 承 L14 系统调用、L16 映射 ｜ Proxy Lab 前奏

## 核心概念

### 1. 文件 = 内核提供的有序字节序列
```
内核用文件对象表示 open 文件: {v-node 指针, 当前读写位置, 引用计数}
文件类型: 普通文件(文本/二进制由程序约定，内核不懂) / 目录(特殊) / FIFO /
          socket / 设备(/dev/null /dev/tty) —— "一切皆文件"的边界其实模糊
```

### 2. Unix I/O：不带缓冲的系统调用层
```c
int open(const char *path, int flags, mode_t mode);   // O_RDONLY/WRONLY/RDWR
                                                       // O_CREAT|O_TRUNC|O_APPEND
ssize_t read(int fd, void *buf, size_t count);        // 返回: >0 计数, 0 EOF, -1 错
ssize_t write(int fd, const void *buf, size_t count); // 返回值 < count 也要重试!
lseek(fd, off, SEEK_SET/CUR/END);                     // 改当前位置, 可造成"空洞"
int close(fd);
```
- **readn/writen 健壮包**（RIO，CSAPP 自造）：处理短读/短写 + SIGCHLD 打断(EINTR)：
```c
ssize_t rio_readn(int fd, void *usrbuf, size_t n) {
    size_t nleft = n; ssize_t nread; char *bufp = usrbuf;
    while (nleft > 0) {
        if ((nread = read(fd, bufp, nleft)) < 0) {
            if (errno == EINTR) nread = 0; else return -1;   // 被信号打断→重试
        } else if (nread == 0) break;                        // EOF
        nleft -= nread; bufp += nread;
    }
    return n - nleft;
}
```

### 3. 描述符三层表（fork/dup 语义的根基）
```
进程 fd 表(每进程) → 打开文件表(内核全局, 含位置) → v-node 表(每磁盘文件一项)
fork(): 子进程 fd 表复制 → 共享"打开文件表项" → 位置共享(追加日志正需要)
dup2(oldfd, newfd): 强制指向 → 重定向 stdout 到文件(Shell 的 > 就是它)
管道 pipe(fds[2]): 父子通信用它 + dup2 改向 (L14/L15 Shell 的实现内核)
```

### 4. 文件元数据与共享语义
```c
fstat(fd, &st);  // st_size/st_mode/st_atime; test -r/-w/-x 的底层
mmap 读文件 vs read: 大随机访问→mmap 省拷贝; 顺序流式→read+预取更优
                      陷阱: SIGBUS(文件被截断) / minor fault 风暴(小页)
```

### 5. 目录与其他
```
opendir/readdir; 读目录=文件名列表+inode号; ls -i 看 inode
/dev/null(黑洞) /dev/zero(无限0) —— 重定向与测试常客
```

### 6. 标准 I/O vs Unix I/O（stdio 是本层之上的缓冲库）
- printf/scanf 带用户态缓冲（行缓冲/全缓冲），`fflush` 才见底层 write；
- 混用两套读位置会打架（stdio 的 FILE*._fileno 与 lseek）。
- Windows 对应层：CRT `_open/_read/_write`（_O_BINARY 必加），Win32 API 是
  CreateFile/ReadFile/WriteFile（句柄，非 fd；见 projects README）。
