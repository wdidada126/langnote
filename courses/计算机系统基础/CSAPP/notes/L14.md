# L14 异常控制流（I）：异常、进程与 fork/wait

> 阅读材料：CSAPP 8.1–8.5 ｜ 进入"操作系统"篇（Ch.8/9/10/11/12 全在本篇）

## 核心概念

### 1. 异常控制流（ECF）：硬件+OS 联手的时间旅行
```
异常表(向量表)：每个异常类型一个处理程序入口
分类:
  中断(Interrupt): I/O 设备异步触发，外部事件（定时器、网卡）
  陷阱(Trap):      指令同步触发，有意为之 → 系统调用（syscall/int 0x80）
  故障(Fault):     同步，可能可修复 → 缺页(page fault, L16!)、#GP
  终止(Abort):     同步，不可恢复 → 机器校验
回到中断点 or 终止进程，由异常类型决定。
```
- 应用层 ECF：C 的 `setjmp/longjmp`、C++ 异常、Java try/catch —— 同一思想的软件版。

### 2. 进程 = 内核给每个程序的一个"私有虚拟机"
- 每个进程有独立的地址空间（L16）与私有资源；通过内核调度在 CPU 上分时交错。
- **并发(concurrent)** ≠ 并行(parallel)：交错即可并发。

### 3. 系统调用视图
```
getpid / fork / wait / execve / exit / kill —— trap 进内核再返回
系统调用号(RDI) → 内核 sys_call_table；返回值 RAX，负 errno 表失败
```

### 4. 进程控制 API（本讲核心代码）
```c
pid_t pid = fork();          // 子进程返回 0，父进程返回子 pid；地址空间写时复制
if (pid == 0) { /* child */ } else { /* parent */ }
int status;
waitpid(pid, &status, 0);    // 阻塞回收; WIFEXITED/WEXITSTATUS 解析
execl("/bin/ls", "ls", "-l", (char*)0);  // 替换当前程序的映像，成功则不返回
// exec 家族: l=参数列表 v=argv数组 p=查PATH e=自带envp；均首参给路径/命令名
exit(0) / _exit: 终止并回收; return from main 亦 exit
```
- 父子并发不确定性 → 输出交错；需要同步（L15 信号量/信号、L20 锁）。
- 孤儿进程被 init(systemd) 收养；**僵尸进程** = 已 exit 但父未 wait（PCB 占坑）。
  `waitpid(-1,&status,0)` 回收任意子进程。

### 5. 没有同步的代价（Shell Lab 事故原型）
```c
/* 错误: 父不 wait → 子可能未结束，终端提示符乱序/竞态 */
if (fork() == 0) { execlp(...); }
printf("\n");                 // 与子进程输出抢终端
/* 正确: 父 waitpid 后再打印（或用 L15 信号驱动） */
```

### 6. 调试视角
```
ps aux / /proc/PID/; gdb attach; strace -f ./prog  ← 看 fork/exec 序列
```
