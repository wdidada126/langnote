# L17 动态内存分配：malloc/free 与分配器设计

> 阅读材料：CSAPP 9.9–9.10 ｜ Malloc Lab 发布 ｜ 承 L16 的堆/mmap

## 核心概念

### 1. 显式分配器契约
```c
void *malloc(size_t size);   // 返回 ≥size 可用块指针或 NULL；不初始化
void free(void *p);          // p 必须来自 malloc/calloc/realloc 且未被释放
void *calloc(n, sz);         // 清零；size*n 溢出检测
void *realloc(void *p, size_t size);  // 扩容迁移，旧内容保留
```
- 放在 L16 之后讲的原因：**分配器是"地址空间上的文件系统"**——
  管理空闲空间、防碎片、维护元数据，与磁盘块分配器同构。

### 2. 两条公理与两类碎片
```
分配器从不移动已分配块(用户指针稳定) → 空闲块必须靠"合并"自救
外部碎片: 空闲总量够但分散 → 合并(coalescing)缓解
内部碎片: 请求 5B 实给 8B(对齐+头部)
最佳适配(best fit) vs 首次适配(first fit): 空间 vs 时间的折中
```

### 3. 隐式空闲链表（能跑但慢）
```
堆 = [块0: 已分配|块1: 空闲|块2: 空闲|块3: 已分配|...]
每块 = [header: size(16B对齐低位0) | alloc位 | payload | (footer)]
边界标记(footer) → 从尾向前合并 O(1)
payload 起始地址对齐 8/16 → 呼应 L07 对齐规则
```

### 4. 显式空闲链表 + 分离存储（快）
```
空闲块自己串成双向链表(L16 指针技巧) → 遍历 O(空闲数) 而非 O(总块数)
按大小分桶: small(8-16)/medium(17-128)/large(129-512)... 桶内 best-fit
 segregated fit(sg_malloc 论文): 大小类+类内排序 → 分配 O(1) 近似
```

### 5. 垃圾回收对照（分配器的"自动挡"）
```
标记-清除/引用计数/分代: 牺牲确定性延迟换自动回收；
C 选手动 = 选性能与确定性的代价。15-445 BufferPool、Go/Java runtime 可对比。
```

### 6. malloc 错误目录（Malloc Lab 必踩）
```
double free → 空闲链表成环/崩溃   写已释放块 → 破坏元数据
越界写 → 覆盖下一块 header        不释放 → 泄漏(耗尽 → 分配失败)
free(NULL) 合法；free(&p[3]) 非法。ASAN 的 redzone 即在块间放毒字节
```

### 7. 多线程分配器（L20 预告）
- 一把全局锁 → 串行化噩梦；现代方案：**每线程 arena/cache + 无锁批量归还**。
- Malloc Lab 挑战：吞吐/内存两指标，正确性（不破坏契约）第一。

## 与前后讲联系
- 用 L16 的 brk/mmap 要空间；L10 局部性影响空闲链表走法；L07 对齐决定块大小
  粒度；L09/L11 的"以空间换时间"在本讲是桶化；L20 并发安全首次成为设计约束。

## 开源项目中的应用
- **glibc ptmalloc2**：arena + tcache（每线程小缓存）；`MALLOC_CHECK_` 调试。
- **jemalloc**：arena/decay/ prof；FreeBSD 默认，Firefox/Rust 生态常用。
- **tcmalloc**：thread-local cache + 中央空闲链表；Span 页管理。
- **mimalloc**：free-list sharding + 安全页 guard，近年论文+开源双热点。
- **Redis zmalloc**：封装统计 + 选择分配器；`maxmemory` 与 allocatorFragmentation。
