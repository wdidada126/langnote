# L15 异常控制流（II）：信号与并发 ECF、Shell 实战

> 阅读材料：CSAPP 8.5–8.6 ｜ Shell Lab 发布 ｜ 信号 = 软件中断

## 核心概念

### 1. 信号机制
```
信号 = 内核通知进程"某事件发生"的软中断（异步 ECF）
编号→默认动作表:  SIGINT(2,终止) SIGCHLD(17,忽略) SIGSEGV(11,终止+core)
                 SIGPIPE(13) SIGSTOP(暂停,不可捕获) SIGKILL(9,不可捕获)
送达(delivery) = 内核改控制流 → 执行 handler → 恢复
发出(send) ≠ 送达：未决(pending)集排队；同种信号排队合并(标准)/可能多条(实时信号)
```

### 2. 发送与接收 API
```c
kill(pid, SIGKILL);            // 发给进程; kill(0, sig) 发给整个进程组
alarm(5);                      // 5 秒后给自己送 SIGALRM
sigaction(SIGCHLD, &sa, NULL); // 注册 handler（比 signal() 可控：mask/flags）
```
- **默认动作**：忽略/终止/终止+core/停止/继续，依信号而定。

### 3. 竞态一：handler 与主流程抢全局变量
```c
volatile sig_atomic_t child_done;   // 唯一可安全跨 handler/主流的类型
void handler(int sig){ child_done = 1; }   // 只做这件事！
int main(){ install_handler(); while(!child_done) pause(); reap(); }
```
- **async-signal-safe 规则**：handler 里只许 `write/_exit/少数函数`；
  `printf/malloc` 会死锁或破坏堆（它们内部有锁/状态）。
- 老代码 `wait(NULL)` 与 SIGCHLD 到达的竞态 → `waitpid(-1,WNOHANG)` 循环收割。

### 4. 竞态二：信号何时送达不确定
```
场景: 子进程先于 kill 命令结束 → 信号丢失; handler 在 sigaction 安装前到 → 默认杀自己
工具: sigprocmask 阻塞/解阻塞; sigsuspend(&mask) 原子"等待+解除阻塞"
EINTR 文化: 被信号打断的系统调用返回 EINTR，健壮代码必须重试(read/write/accept...)
```

### 5. 非本地跳转与信号的组合陷阱
`setjmp` 返回 2 表示"信号来的"（POSIX 在 siglongjmp 语境）；`sigsetjmp/siglongjmp`
保存信号掩码——别在 handler 里 longjmp 进持锁区。

### 6. Shell Lab 的三座大山（正确姿势）
```
1) 前台作业: fork→exec→waitpid 阻塞；Ctrl-C 发给整个前台进程组(SIGINT→子)
2) 后台作业: 立即返回；SIGCHLD 驱动 reap（别 busy wait）
3) Ctrl-Z: SIGTSTP→子自己停止? 由终端生成 SIGTSTP；父记录 job 表，
   bg/fg 用 SIGCONT；SIGSTOP/SIGTSTP 不可捕获但可处理停止通知
坑: 信号竞态(用 sigsuspend)、handler 里调 waitpid 循环(WNOHANG)、
   SIGCHLD 合并丢失(while(waitpid(-1,NULL,WNOHANG)>0)); 设置信号掩码防自身
```

## 开源项目中的应用
- **Nginx 信号管理**：master 收 SIGUSR1(重开日志)/SIGHUP(热配置)/SIGQUIT(优雅退出)。
- **systemd/supervisord**：SIGCHLD 收割、watchdog 的 SIGALRM。
- **Redis**：主循环用自签信号(信号作为"事件循环打断器"，`aeMainBeforeProc`)。
- **PostgreSQL**：backend 间通信大量使用 signal + latch（`SetLatch` 用 SIGURG）。
