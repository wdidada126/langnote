# L09 程序性能优化（I）：消除循环低效率与过程间优化

> 阅读材料：CSAPP 5.1–5.11、5.14–5.16 ｜ 前提：L08 已建立流水线模型

## 核心概念

### 1. 先测量再优化：运行时间与 CPE
```
T_cpu = CPI × I × T_cycle；  T_run(n) ≈ T_overhead + CPE × n
画 T vs n 曲线，斜率即 CPE——没有曲线就没有优化（Performance Lab 方法论）
gcc -O1/-O2/-Og；别用 -O0 调优（教科书级误导）。
```

### 2. 消除循环低效率（Loop inefficiencies）
```c
// 低效：每次迭代都算 strlen（O(n) → 整体 O(n²)）
for (i = 0; i < strlen(s); i++) ...
// 高效：hoist 出循环
size_t n = strlen(s); for (i = 0; i < n; i++) ...
```
- **循环保护（guard）**：前置 `if (n<=0)` 后将 while(true)+break 规范化成 do-while，
  减少一次跳转与比较。
- 调用被 inline + 纯函数：编译器才敢做上提；`printf` 等可能改全局的调用挡住代码移动。

### 3. 过程间优化：内联是地基
`-O2` 下 `square` 被合入 `sum`，之后才能做公共子表达式/循环变换。
手动手段：`static` 小函数、`__attribute__((always_inline))`、C++ header 定义。

### 4. 循环展开（unrolling，L11 深入）
```c
for (i = 0; i < limit - 3; i += 4) {   // 4 个独立累加器
    acc0 += v[i]; acc1 += v[i+1]; acc2 += v[i+2]; acc3 += v[i+3];
}
for (; i < limit; i++) acc0 += v[i];   // 尾部（模 4 清理）
long acc = (acc0 + acc1) + (acc2 + acc3);
// 打断 loop-carried 依赖链：ALU 流水线得以重叠 4 条加法链
```

### 5. 削弱程序依赖：ALU 延迟 vs 吞吐
```
延迟(delay)：指令结果可用的周期数；吞吐(throughput)：每周期可发射数。
add: 延迟1 吞吐2；mul: 延迟3~5 吞吐1 → 乘法密集循环展开可近乎线性提速。
```
- **环路携带依赖（loop-carried dependency）是 ILP 的头号敌人**：
  `combine1`（`acc *= data[i]` 串行乘法链）CPE = 延迟×n，展开/换顺序才有救。

### 6. 存储别名（memory aliasing）与 restrict
```c
void f(long *dp, long *sp) { *dp = *sp + 1; *dp = *sp + 2; }
// 编译器无法排除 dp==sp → 不能合并两次加法
// C99: void f(long * restrict dp, long * restrict sp) → 承诺不重叠，放开优化
```
- 结构体成员/数组切片重叠同理；这是 C 比高级语言难优化的根本原因之一。

### 7. 并行性视角看循环
```c
// 归约(reduction)可并行：for i: sum += a[i] → 分块局部和 + 树形合并
// 依赖模式：独立(i) 可并；相邻(i-1) 可流水；全局(归约) 部分可并
```
