# L01 课程导论：信息、系统抽象与程序生命周期

> 阅读材料：CSAPP Ch.1 ｜ 对应教材：CSAPP 3/e 第 1 章

## 本讲定位

CSAPP 的第一课不深入任何一层细节，而是给出**整门课地图**：从晶体管到可编程网络，
程序员如何透过一层层抽象理解系统。后续 19 讲全部挂在本讲的抽象骨架上。

## 核心概念

### 1. 信息 = 比特 + 上下文
同一段 0/1 串，放在不同上下文中意义完全不同：机器指令、整数、浮点数、字符（UTF-8）、
可执行文件里的数据段。CSAPP 贯穿性口号：**"计算机只有 0 和 1，意义由解释者赋予"**。

### 2. 三层大抽象
```
        ┌──────────────┐
        │   用户程序    │
        ├──────────────┤
硬件 ←→ │  操作系统     │ ←→ 网络
        ├──────────────┤
        │  处理器/存储  │
        └──────────────┘
- 硬件系统 ISA（指令集）：隔离处理器与硬件，同一 ISA 可有不同微架构实现
  （如 x86-64 的 Intel/AMD 各代芯片可互换编译产物）。
- 操作系统两大抽象：
  * 进程（process）：对"运行中程序"的抽象，让每个程序独占 CPU/内存的假象；
  * 虚拟内存（VM）：每个进程独占一大片连续地址空间的假象；
  * 文件（file）：对 I/O 设备的统一抽象——"一切皆文件"。
- 网络：把分散的计算机抽象成一台可编程的大计算机。
```

### 3. 存储层次（第一次出现，L10 展开）
```
寄存器 → L1/L2/L3 缓存 → 主存(DRAM) → SSD → 磁盘/远程存储
速度/容量/成本 逐层递减；程序性能的本质 = 数据在这座金字塔上的移动效率。
```

### 4. 由 hello.c 看程序的生命周期
```c
#include <stdio.h>
int main() { printf("hello, world\n"); }
```
```
hello.c --预处理器(cpp)--> hello.i --编译器(cc1)--> hello.s
       --汇编器(as)--> hello.o --链接器(ld, 附 libc)--> hello(可执行文件)
       --Shell 加载--> 由内核经由 CPU + 主存 + DMA 磁盘 I/O 执行
```
- 运行期：Shell 用 `fork+execve` 启动新进程；`/bin/hello` 的 `main` 第一条指令
  被加载器从磁盘搬到主存；`printf` 最终走 `write(1, ...)` 系统调用（trap）请求内核输出。

### 5. 目录约定（本讲"信息即比特"的实操）
`ls -l a.txt` 显示的 2196 字节只是字符；同名的 `a`（可执行）与 `a.o`、`a.out` 是
ELF 格式，Windows 下是 PE 格式——**文件类型由头部魔数决定而非扩展名**。

## 知识点在开源项目中的应用
- GCC/LLVM 工具链：`gcc -v hello.c` 可直接观察 cpp→cc1→as→ld 全流程。
- ELF 格式：`file`、`readelf -h` 读魔数 `0x7f 'ELF'`，验证"扩展名不可信"。
- QEMU：用户态模拟展示了"抽象层可以互相跨越"（软件实现 ISA）。
