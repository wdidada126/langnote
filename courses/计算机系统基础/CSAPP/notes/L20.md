# L20 并发编程：线程、线程安全与竞争条件

> 阅读材料：CSAPP Ch.12 ｜ Proxy Lab 截止 ｜ 全书汇流：从 fork 到 pthread

## 核心概念

### 1. 三种并发服务器（本讲总纲）
```
基于进程:   accept 后 fork —— 隔离好、切换贵、共享数据要 IPC(消息传递)
基于 IO 多路复用: 单线程 select/poll/epoll 事件循环 —— 高效、无锁, 但无法吃满多核
基于线程:   accept 后 pthread_create —— 逻辑上"每请求一线程"，共享地址空间(L16!)
三者的取舍贯穿所有服务端设计（Nginx=多进程×事件循环；Redis=单线程事件循环；
Memcached/Java=线程池）。
```

### 2. 线程 = 共享地址空间的执行流
```
私有: 栈(L06 帧链)、寄存器/PC、线程 ID、errno(每线程!); 信号掩码
共享: 堆(L17)、全局/静态数据、打开的 fd 表(L18)、代码段
→ 通信零拷贝，但"共享即陷阱"由此开始
```

### 3. 线程安全的四个等级（CSAPP 12.7 分类法）
```c
/* 1) 脆弱: 并发执行必炸 */
void ts_bad(){ static int cnt=0; cnt++; }
/* 2) 竞争条件: 碰运气才对 */
void incr(){ cnt = cnt + 1; }   // 读-改-写非原子 → lost update
/* 3) 正确但慢: 一把大锁 */
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
void incr_ok(){ P(&m); cnt++; V(&m); }
/* 4) 线程安全且快: 缩小临界区/无锁结构/每线程副本 */
```
- 其他类别：`reentrant`（不用共享状态，如 strtok_r）、`thread-safe-with-TLS`
  （__thread/`strerror_r`）、信号安全（L15 的异步安全是同一问题的极端版）。

### 4. 信号量与互斥锁
```c
sem_init(&s, 0, 1);        // 二值信号量 = mutex 的原始形态
P(&s) = sem_wait: 原子地"若>0则--否则睡"; V = sem_post
pthread_mutex + cond 组合 → 生产者-消费者:
while (q.full) pthread_cond_wait(&notfull, &mutex);  // 注意 while 不是 if!(虚假唤醒)
pthread_cond_signal(&notempty);
```
- 死锁三要素：互斥、持有并等待、不可剥夺 → 打破环路：全局加锁顺序/超时。
- 竞态不止在数据上：初始化竞态（pthread_once）、调度竞态（join 顺序）。

### 5. 共享内存通信（回到 L16）
```
shm_open + mmap 建共享区域 → 信号量做同步 → 环形缓冲（SpscQueue）
对比: 消息传递(6.824 风格) 无共享 → 少一类 bug，多序列化成本
```

### 6. 与 L08/L09/L10/L11/L17 的暗线
- 伪共享（L10）：线程各自写同一缓存行 → 性能塌方；
- 乱序可见性（L08）：无同步时另一线程可能看到重排后的指令效果 → 需要
  memory barrier/原子（C11 `_Atomic`/lock-free）；
- 分配器竞争（L17）：malloc 的每线程 cache 就是本讲思想的产物；
- 并行归约（L09）：`sum +=` 串行链 → 分线程局部和 → 本讲 join 汇总。

## 开源项目中的应用
- **Nginx**：worker 进程间用共享内存+原子（`ngx_shmtx` 自旋+yield），
  事件循环避免线程 → 无竞态架构。
- **Redis**：单线程+epoll 消灭锁；Lua 脚本即"原子临界区"。
- **Memcached**：slab 锁、item 锁分级的经典多线程服务器。
- **glibc NPTL**：pthread 实现（futex 系统调用做阻塞唤醒）。
- **Go**：goroutine+channel="不要用锁通信" 的工业实践（Ousterhout 论文的还魂）。
