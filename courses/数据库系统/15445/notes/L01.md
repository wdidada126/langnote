# L01 关系模型（The Relational Model）

> 15-445/645 Fall 2023 · Lecture 1 · 阅读：课程 Notes "The Relational Model"；Silberschatz Ch.3–4
> 关系模型是数据库世界的"宪法"：所有上层语言（SQL）与下层实现（存储/索引）都活在它的两面。

## 1. 核心概念

### 1.1 从数学出发的三个名词
- **域（domain/attribute domain）**：值的集合，如 INT、VARCHAR(30)。
- **元组（tuple）**：各域上值的有序组合 (v1,...,vn)；**关系（relation）**= 元组的**集合**（数学上无重复、无序）。
- **关系模式（schema）**：R(A1:D1, ..., An:Dn)，即属性的有限有序列表；DBMS 可放宽为**多重集（bag）**且允许无序——这个"数学 vs 实现"的差异会贯穿全课（SQL 的 bag 语义、物理元组序）。
- **基数（cardinality）**= 元组数；**度（degree/arity）**= 属性数。

### 1.2 ER 模型 → 关系模型的映射（建模三步）
1. **实体集** → 表，实体的属性 → 列，必须选出主键（没有自然键就造 surrogate key，如 SERIAL/OID）；
2. **联系（relationship）**的翻译规则：
   - 1:1 → 外键放任意一侧（或合并表）；
   - 1:N → 外键放 N 侧（"多的一方持有引用"，避免 NULL 稀疏）；
   - M:N → **必须建连接表（junction table）**，主键=两侧外键复合；
   - 联系自带属性时（如"选课成绩"）：M:N 一律连接表，属性成为其列。
3. **弱实体/ISA**：ISA 有三种落地——单表全 NULL 位图（最省 JOIN）、每子类一表+外键、每实体一表+连接表；ORM 时代演化出 polymorphic embedding 等混合方案。这是 L05 存储模型（NULL bitmap、列存缺失值处理）的前奏。

### 1.3 键与完整性约束
- **超键 ⊃ 候选键 ⊃ 主键**；**外键**引用他表候选键（可为自身/空值，置空策略 SET NULL/CASCADE/RESTRICT）。
- 约束=声明式规则，DBMS 负责在 DML 时强制执行：主键唯一非空、外键存在性（触发行锁/索引查找——外键列要有索引，InnoDB 强制，Postgres 不强制，这是新手性能坑）。
- 约束的实现成本全落在后面的机制上：唯一性→B+ 树/哈希索引（L07-08），存在性检查→事务原子性（L15-20）。

### 1.4 关系代数：查询的语言底座
八种基本运算（封闭性：输入关系输出关系，故可任意嵌套成表达式树）：
- **选择 σ**（水平筛元组）、**投影 π**（垂直筛属性，数学上消重复，SQL 默认保留——bag 语义差异！）、
- **并 ∪**（要求并相容 union-compatible）、**差 −**、**笛卡尔积 ×**（度相加、|R|·|S| 元组，是复杂度黑洞的源头）、
- **重命名 ρ**；派生运算：**交 ∩**、**连接 ⋈**（× 后接 σ 的缩写；θ-join/equi-join/natural join/外连接）、**除 ÷**。
几个必须能秒推的等价变换（L14 优化器 RBO 规则的原型）：
- σ 下推：σ(R×S)=σR×σS；选择尽量早做；
- π 下推、× 与 ∪ 分配律、德摩根；
- 连接结合律/交换律 → L14 连接序搜索的组合爆炸来源。

## 2. 机制层面要知道的事
- 关系模型对**更新异常**（插入/删除/修改异常）的解药是**范式分解**（1NF→BCNF/4NF，本课不展开但 Homework 有涉及）；分解要**无损连接**且尽量保持依赖。
- NULL 三值逻辑（TRUE/FALSE/UNKNOWN）：`x = NULL` 永不为真，聚合忽略 NULL（COUNT(*) 例外），这是 SQL 与关系代数语义漂移的最大来源。

## 3. 前后讲联系
- 本讲的"关系=元组集合"是 L03-05 物理布局讨论的抽象被体；π 垂直切片 = L05 列存；σ 谓词 = L12-13 执行算子；× = L11 join 算法全讲的靶心；表达式树 = L12 火山模型的容器与 L14 优化器的操作对象。
- L02 把本讲的代数翻译成用户可用的 SQL。

## 4. 跨课程联系
- **CS143**：关系代数表达式树 ≈ 编译器 AST；代数等价变换 ≈ 编译器 peephole/循环不变量外提这类语义保持优化。优化器 = "查询的第二个前端+中端"。
- **6.006/数据结构**：关系代数的每个运算就是一个算法问题——σ 是线性扫描或索引查找（O(n) vs O(log n)），× 是双重循环，⋈ 是它的带谓词特化。
- **CS229/ML**：feature store 论文里"表=样本集合"仍暗合关系模型；SQL 到 DataFrame 的 API 差异本质是 bag/set 语义差异。

## 5. 开源项目应用
- **PostgreSQL**：`pg_catalog.pg_class/pg_attribute` 就是模式存储；外键触发 `RI Trig`（referential_integrity.c）。
- **MySQL/InnoDB**： FOREIGN KEY 约束 + 隐式创建外键索引。
- **DuckDB/sqlite**：sqlite 动态类型（type affinity）是对"域"概念的反模式实践——列声明 INTEGER 也能塞字符串，对比 Postgres 严格域检查。
- **ORM（Hibernate/SQLAlchemy）**：把 ISA 三种方案做成策略枚举（joined/single/table per subclass），正是 1.2 节的工程化。
