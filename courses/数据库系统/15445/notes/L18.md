# L18 多版本并发控制（MVCC：快照读与 undo 管理）

> 15-445/645 Fall 2023 · Lecture 18 · 阅读：课程讲义；Silberschatz Ch.18.5
> "读永远不阻塞写，写永远不阻塞读"——MVCC 用同一数据项的多个历史版本，让每个事务都看到为自己冻结的一致性快照。

## 1. 核心概念

### 1.1 版本与可见性
- 每个元组维护若干**版本**，写操作不覆盖旧值而是**新建版本**（旧版本进 undo）。
- 版本携带创建/失效它的**事务 ID / 时间戳 / 快照号**。
- **可见性判断**：事务在给定快照下，沿版本链找到"对我可见的最新版本"（我出生前最后提交、且未被删除我看得到的那个写）。
- 两条主流流派：
  - **快照隔离 SI（Snapshot Isolation）**：事务在读开始时拿一个快照，整个事务期间都用它（Postgres REPEATABLE READ、MySQL RR）；
  - **读已提交 RC 的 MVCC**：每条语句取新快照（Postgres READ COMMITTED 默认）。

### 1.2 两种版本组织方式
- **写时复制元组（tuple-level，Postgres）**：新版本与旧版本都存在**同一张堆表**里，靠元头 `xmin`(创建事务)/`xmax`(删除事务) 标记版本区间；读时按快照过滤可见版本。删除是"逻辑删除"（设 xmax），旧版本靠 **VACUUM** 回收。
- **回滚段存旧值（InnoDB/Oracle）**：数据页只存**最新版本**，旧版本写进 **undo log**；需要看旧快照时沿 undo 链回滚重构出历史版本（"读时重建"）。好处主数据紧凑；代价 undo 链长则读慢。

### 1.3 写-写冲突与更新丢失
MVCC 允许并发读旧快照，但两个事务**同时写同一行**冲突时不能都提交，否则丢更新。检测方式：
- **first-committer-wins**：先到者赢，后到者发现行的 `xmax` 已被设→冲突回滚或需重新求值（`SELECT FOR UPDATE`、Postgres 的 `EPQ` evaluation plan）。
- SI **不等于可串行化**：两个快照事务各写不同行、读同一集合，可产生 **write skew（写偏差）** 与 **fk 反例**——需要额外机制解决（见 1.5）。

### 1.4 GC / VACUUM（长事务之殇）
旧版本必须等"所有可能还需它的快照"结束后才能回收。
- **长事务/空闲事务持有老快照 → 阻止 vacuum → 表膨胀（bloat）、xid 回卷风险**（Postgres 著名的 `autovacuum`、`vacuum freeze`、32 位事务 ID 回卷）。
- InnoDB：undo 表空间 purge；`innodb_purge_threads`。
- 这是 MVCC "空间换并发" 的隐性账单，运维重点。

### 1.5 Serializable Snapshot Isolation（SSI）
在 SI 之上检测**危险结构（危险楔形 dangerous structure）**：两个并发事务读同一数据、又各写对方读过/将读的数据——用**跟踪读写依赖**，发现可能破坏可串行化时 abort 其一（**Postgres SERIALIZABLE = SSI，Cahill 2012**）。既保留 MVCC 高并发，又拿到可串行化——现代旗舰方案。

## 3. 跨课程联系
- **6.S081/CS162**：copy-on-write 页表 fork、RCU（读端无锁看旧版本，写端发布新版本，宽限期回收）——MVCC 是"数据版的 RCU/CoW"。
- **6.824**：快照读=读一个 Raft/Paxos 已提交日志前缀的状态；GC 的"安全点"≈ RCU grace period。
- **CSAPP**：版本链沿 undo 回溯=链表指针追逐，长快照→缓存不友好+内存膨胀。
- **Git（通识类比）**：每个版本一个提交、checkout 到某 commit 看快照——帮助理解"版本+可见性"。

## 4. 开源项目应用
- **PostgreSQL**：tuple 级 MVCC，`xmin/xmax/cid`；READ COMMITTED 每语句快照，RR 每事务快照；`VACUUM`/autovacuum 回收死元组；SSI 实现 SERIALIZABLE。
- **MySQL/InnoDB**：undo log 版本链 + ReadView（`m_ids` 活跃事务集）判断可见性；purge 线程清 undo；RR+Next-Key Lock 防幻读。
- **CockroachDB/TiDB（L22）**：Percolator 式分布式 MVCC，时间戳定版本，Raft 复制。
- **MongoDB**：快照读 + WiredTiger 历史（`retainHistory`）。
- **SQLite（WAL 模式）**：读快照 + WAL，写者追加、读者看版本偏移。
