# L07 散列表（Hash Tables：DBMS 中的哈希索引）

> 15-445/645 Fall 2023 · Lecture 7 · 阅读：课程讲义
> 哈希表=点查最快（O(1)），代价是完全放弃顺序——理解这条取舍线，就理解了它 vs B+ 树的分工。

## 1. 核心概念

### 1.1 静态哈希（Static Hashing）
- 桶数组大小 M 固定，`h(key) % M` 定位桶；装填因子 α = 记录数/桶数。
- **冲突解决**：
  - **链地址（separate chaining / closed hashing）**：每桶挂链表。桶溢出到磁盘→链越长、I/O 越多。
  - **开放寻址（open addressing）**：冲突就探测下一槽（线性/二次/双重哈希）。α 高时探测长度暴涨（主聚类）。

### 1.2 动态哈希（Dynamic Hashing）——应对数据增长
桶数可随规模伸缩，避免"预分配过大浪费 / 过小溢出"：
- **Linear Hashing（LH）**：不一次翻倍，而是**逐桶增量分裂**（用 level 指针，每分裂一个桶 level++，到达 2^n 时 level++、n++）。地址计算 `h_level(k) mod (N·2^level)`。写入友好、无惊群式扩容。
- **Extendible Hashing（可扩展哈希）**：**全局深度 gd** + 每桶**局部深度 ld**；桶目录（directory，2^gd 项指向实际桶）。插入溢出：若该桶 ld < gd，只分裂此桶并复制一半到新桶、更新目录两项；若 ld = gd，目录先翻倍再分裂。用 key 低位 bit 判断去留。
- **Uniform Hashing（Jeanninge）**：多维 bit 交错分配，保证各桶均匀。

### 1.3 磁盘上的现实问题
- 桶=一个或多个页；目录本身要能一页装下（否则多一层 I/O）。
- 删除、合并（low water mark 触发桶合并/目录收缩）比插入更棘手。
- **哈希 join** 用的内存哈希表是另一物种（L11 展开）：build side 建 in-memory hash，probe side 探测；溢写用 graceful/adaptive partitioning。

### 1.4 哈希 vs B+ 树（本讲落点）
| 维度 | Hash | B+ 树 |
|---|---|---|
| 等值点查 | O(1) | O(log n) |
| 范围/有序扫描 | 不支持 | 天然支持 |
| 排序输出 | 无 | 中序即有序 |
| 更新 | 可能触发分裂/迁移 | 类似 |
| 内存 | 目录+桶 | 内部节点 |
结论：**只等值查、不排序** 的列（如外键 join 列、session id）用哈希索引；需要 ORDER BY / BETWEEN / 前缀的用 B+ 树。

## 4. 开源项目应用
- **Memory Engine（MySQL）**：哈希索引（自适应哈希 AHI，InnoDB 内部对热点页自动建哈希，LRU 淘汰）。
- **RocksDB / LevelDB**：每个 SSTable 尾部有 hash index block（memtable 用跳表，L08 提）。
- **PostgreSQL**：`HASH` 索引类型（bighash），适合内存受限的等值场景；Hash Join 执行器。
- **Redis**：dict 用两个表做增量 rehash（= linear hashing 思想）。
- **Go map / std unordered_map**：内存哈希的通用实现参考。
