# L19 数据库日志（Database Logging：WAL、redo/undo、检查点）

> 15-445/645 Fall 2023 · Lecture 19 · 阅读：课程讲义；Mohan ARIES 论文；Project #5
> 数据库不"原地改磁盘"，而是先"记账"。日志（log）是 ACID 中 A 与 D 的唯一物理凭据：崩溃后靠它重放或撤销。

## 1. 核心概念

### 1.1 故障模型
- **事务内部故障**：约束违反/除零→回滚该事务（靠 undo）。
- **系统/进程崩溃**：断电、OS crash→内存全丢，磁盘仍在→靠日志恢复。
- **介质/磁盘故障**：磁盘坏→靠备份 + 日志重建（L20 备份/PITR 主题）。
本讲聚焦前两种（"crash recovery"）。

### 1.2 日志记录格式
每条日志追加到 **log file**（顺序写，极快），带全局单调递增 **LSN（Log Sequence Number）**。常见记录：
- **Update（physiological）**：`<tid, page_id, prev_LSN, before-image(旧值), after-image(新值)>`——既含 redo(新)又含 undo(旧)。
- **Commit/Abort**、**Begin-Transaction**、**Checkpoint**（见 1.5）。
- **粒度**：
  - **物理（physiological）**：记"对某页某偏移做了什么"——介于逻辑（记 SQL 语义）与物理（记字节 delta）之间；页级是标准（"物理于页、逻辑于 DB"），恢复时对页 redo/undo。
  - 逻辑日志（logical）：记"把 X 从 5 改成 8"，可跨版本重放更久但恢复需按序。
- **Log-Structured 变体**：只 redo 日志（Hekaton）、undo 日志、redo-only。

### 1.3 WAL（Write-Ahead Logging，写前日志）——黄金法则
> **"日志先于数据落盘"**：一个页的修改写回磁盘之前，描述该修改的日志必须先持久化。
实现机制：
- **Force-Updates vs Steal-Updates**：
  - **No-Steal**：脏页在事务提交前不能写回（缓冲池锁住）→ 不需 redo，但内存吃紧时无法换出脏页。
  - **Steal**：允许未提交事务的脏页提前刷盘（腾内存）→ 崩溃时该页可能含未提交数据→需 **undo**。
  - WAL 通常 **Steal + Force**（提交时强制刷该事务所有日志 + undo 保证原子）。
- **NO-REDO / REDO**：若已提交事务的页在崩溃前已写回（No-Steal 且已 flush）→ 无需 redo。
- 组合成 4 种（Steal/No-Steal × Force/No-Force），课程表格常考：**ARIES = Steal + No-Force**（脏页可提前刷=Steal；提交时不强制刷数据页=No-Force，靠 redo 补偿），最大化性能但需完整 redo+undo。
- **Commit 顺序**：事务 commit 记录**必须持久化（fsync 日志）后**才返回客户端"成功"——D 的来源；数据页可晚点再刷（No-Force）。

### 1.4 恢复两阶段：Redo + Undo
崩溃重启后（ARIES 思路，L20 细化）：
1. **Analysis**：从最近 checkpoint 扫日志，找出"崩溃时活跃的事务"（loser）与"脏页表"。
2. **Redo（REPEAT HISTORY）**：从 checkpoint 起**正向**重放所有日志（含未提交的），把 DB 恢复到"崩溃瞬间的确切状态"（winning+losing 都重放，保证不漏已发生的效果）。
3. **Undo**：**反向**回滚所有 loser（未提交事务）的写，用 before-image；undo 本身也写 **CLR（Compensation Log Record）**，以防 undo 过程再崩溃。
- **幂等**：redo/undo 可重复执行（靠 page 的 `page_LSN` 判断"这条日志是否已应用到该页"）。

### 1.5 检查点（Checkpoint）——限制恢复扫描量
不让每次恢复都从头扫全量日志：周期性往日志写 **checkpoint record**，记录"此刻活跃事务 + 脏页集合"。恢复从**最近的 checkpoint** 开始。三种：
- **Blank/Dirty Table Page Dump（冻结）**：暂停所有活动，刷所有脏页 + 写 checkpoint——恢复最快但停机（旧系统）。
- **Fuzzy Checkpoint（ARIES）**：不冻结！记录"写 checkpoint 时仍脏的页"，这些页允许在 checkpoint 之后继续写（带 WAL 保证顺序）；恢复时 Analysis→Redo→Undo 从该点起——**在线、并发**，工业标准。
- **Shadow Paging**：不用日志，用页表影子拷贝原子切换文件系统式（SQLite 曾/部分、某些嵌入式）；简单但碎片/并发受限。

### 1.6 Steal/No-Force 与缓冲池联动
- Steal ↔ 缓冲池可淘汰脏页（L06 换出脏页前要能 undo，即未提交页可被 steal 写出）。
- 后台 **flusher** 推进"最老未刷脏页 LSN"（dirty page table 的最小值），日志才能 **truncate**（所有 ≤ 该 LSN 的效果都已落盘，之前日志不再需要）。

## 4. 开源项目应用
- **PostgreSQL**：WAL（`xlog`/`wal`），`wal_level`、`checkpoint_timeout`、`full_page_writes`（防部分写）；`pg_waldump` 看日志。
- **MySQL/InnoDB**：redo log（WAL，循环 ib_logfile）+ undo log（兼 MVCC）+ binlog（server 层逻辑日志，两阶段提交 `innodb_flush_log_at_trx_commit=1`）。
- **RocksDB**：WAL + MANIFEST 版本集；`sync` 选项控持久性强度。
- **SQLite**：WAL 模式（-wal 文件 + checkpoint）或 rollback journal（影子式）。
