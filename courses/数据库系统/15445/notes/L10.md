# L10 排序与聚合（Sorting and Aggregations）

> 15-445/645 Fall 2023 · Lecture 10 · 阅读：课程讲义
> ORDER BY 和 GROUP BY 是"必须看到全部数据才能出结果"的两类运算——它们逼着数据库在内存放不下时想办法。

## 1. 核心概念

### 1.1 外部排序（External Sorting）
内存排序（quick/merge）要求数据装进 RAM；DB 的数据常远大于内存 → **外部归并排序（external merge sort）**：
1. **Run 生成**：分批把数据读入内存，内存排好序，写回磁盘成若干 **sorted run**；
2. **归并（merge）**：多路归并（k-way merge）这些 run，反复直到只剩一个。
- 归并趟数 = ⌈log_{B−1}(R/B)⌉，B=可用缓冲帧数，R=记录块数——**增大缓冲帧 B 可显著降趟数**（k-way 而非 2-way）。
- **优化：替换选择（replacement selection）**生成 run：不是装满就排，而是维护大小为 M 的最小堆，输出比上一输出大的记录继续塞→ run 平均长 2M → 减少初始 run 数。

### 1.2 排序的两个 DB 特有技巧
- **Prefix sorting / abbreviated key**：只对排序键的**前缀**（如前 8–12 字节）比较，把 (prefix, TID) 放内存排序，最后按 TID 取整行——省内存、增大 M。Oracle/Postgres 都用。
- **By-value vs by-reference**：
  - by-value：把整条记录放进排序缓冲——比较快但占内存、宽记录浪费；
  - by-reference：只放 (sortkey, pointer)——省内存但最后要"指针追逐"回表取行（随机 I/O）。
  - **Tie-breaker**：排序键相等时要加唯一列（如 TID/主键）保证稳定与去歧义。

### 1.3 聚合（Aggregation）
把多行折叠成一个值：SUM/COUNT/AVG/MIN/MAX，GROUP BY 则按组分别折叠。
- **无 GROUP BY（标量聚合）**：单遍扫描累加器即可，天然流式。
- **有 GROUP BY**：核心是"如何给每行找到它的组累加器"。

### 1.4 聚合算法：Sort vs Hash
| 算法 | 机制 | 内存 | 输出有序 | spill |
|---|---|---|---|---|
| **Sort-based（group aggregation）** | 先按 group key 外部排序，相同键相邻→单遍折叠 | 溢出到磁盘 | 是（可顺带 ORDER BY） | 排序溢写 |
| **Hash-based（hash aggregation）** | 内存哈希表 key→累加器，边扫边聚合 | 表大则 OOM | 否 | 见下 |
- **递归哈希分区（recursive hash partitioning）**：内存放不下时，按 hash 把输入分区（grace 分区），逐分区建小哈希表；若某分区仍太大→再细分。保证每分区能装下→单遍完成。
- **两阶段聚合（partial + final）**：先局部预聚合（分布式/并行下每 worker 各自 sum/cnt，再合并），减少数据移动——AVG 要拆成 SUM 和 COUNT 两部分才能合并。

## 2. 前后讲联系
排序是 L11 sort-merge join 的前置（两边都排序后归并连接）；也是 L02 窗口函数、L05 列存有序压缩的引擎。哈希聚合复用 L07 内存哈希；两者都是 L12 火山模型里的"阻塞算子（blocking operator）"——必须先收完所有输入才能吐第一行（与 pipelined 算子相对，L12 的核心分类）。

## 3. 跨课程联系
- **6.006/CS61B**：外部排序=分治+多路归并；replacement selection=贪心+最小堆；哈希聚合=哈希表。全是基础算法在"内存受限"下的重制。
- **CSAPP Ch.6**：多路归并的 k 权衡、by-reference 回表的指针追逐=缓存 miss——性能全在访存模式。
- **CS149/并行**：外部排序天然可并行（分区并行排、并行归并）；两阶段聚合=并行 reduce 的 map-reduce 结构。

## 4. 开源项目应用
- **PostgreSQL**：`Sort` 用快速排序+top-N heapsort（LIMIT 时）+外部归并；`GroupAggregate`（sort 后）vs `HashAggregate`（内存/磁盘）由优化器按估算行数选。
- **InnoDB/MySQL**：`filesort`（内存 sort buffer 满则归并临时表）；`innodb_sort_buffer_size`。
- **DuckDB**：hash aggregate 用**radix-partitioned hash table**（按 key 高位基数分区，兼顾内存局部性与 spill）；排序用 radix sort 对定长前缀。
- **Spark SQL**：`SortAggregate`/`HashAggregate`/`ObjectAggregate`，外部排序 spill 到 disk——分布式版同款。

## 速记自检
- Q：外部排序两阶段？——A：生成 sorted run → 多路归并（§1.1）。
- Q：增大缓冲帧为何降归并趟数？——A：k-way 归并 k≈B−1 变大（§1.1）。
- Q：prefix sort 排的是什么？——A：排序键前缀+TID，最后回表（§1.2）。
- Q：hash 聚合内存不足怎么办？——A：递归哈希分区（grace），§1.4。
