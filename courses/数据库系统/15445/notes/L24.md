# L24 嘉宾讲座：SingleStore 与内存原生 HTAP（Guest Speaker: Cheng Chen）

> 15-445/645 Fall 2023 · Lecture 24 · 嘉宾 Cheng Chen（SingleStore）· 主题：商业内存原生数据库与 HTAP
> 本课唯一由企业工程师主讲的一讲：真实产品如何在"行存 OLTP + 列存 OLAP 合一"的工程约束下做取舍。

## 1. 核心概念

### 1.1 什么是 HTAP
Hybrid Transactional/Analytical Processing：同一套系统同时扛
- **OLTP**（高频小事务、行存、低延迟）与
- **OLAP**（大扫描聚合、列存、高吞吐）。
传统做法是 OLTP 库 + ETL → 数仓（数据延迟 T+1、两份系统、一致性难）。HTAP 目标：**一份数据、零 ETL、实时分析**。

### 1.2 SingleStore（前身 MemSQL）的杀手设计：双模式行/列
- **行存**：内存原生（all-data-in-memory）OLTP，配合持久化磁盘/快照保证 D；点查/更新极快。
- **列存**（Columnar Index）：同表可再建**列存索引**，后台把行式增量"打包成列段（column segments）+ delta 区"，为分析扫描服务。
- 一表两份表示、自动同步 → 写走行存、分析走列存，各取所长。这与 L05"行列互补"的产品化落地完全对应。

### 1.3 编译执行 + 数据分片 MPP
- **Query Compilation**：查询编译成 C++ 再编成机器码（LLVM），消除火山逐元组解释开销（L12/13 的编译路线）。
- **MPP**：分布式 shared-nothing（L23），聚合/join 跨叶节点并行；`LEAF/AGGREGATOR` 架构。
- **Inkless 日志 / 无共享**：持久化用异步快照 + redo，减少写放大。

### 1.4 CodeGen 与向量化在工业的选择
嘉宾强调：内存原生场景下 JIT 编译收益大（长查询、复杂表达式），但短查询的编译开销要用"计划缓存 + 快编译"抵消——这是 L13 表格里"JIT 短查询差"的工程对策。

### 1.5 其它 HTAP 玩家对照（延伸阅读）
| 系统 | 行列策略 |
|---|---|
| SingleStore | 行主存 + 列索引双份 |
| SAP HANA | 行/列可切换，写走行、delta merge 到列 |
| TiDB | TiKV 行存(OLTP) + TiFlash 列存副本(OLAP)，Raft 同步 |
| OceanBase | 内存增量(memtable 行) + 磁盘基线(宏块列存编码) |
| ClickHouse | 纯列存 OLAP + 轻量 KV/物化视图 |
| Postgres+pg_analytics/duckdb fdw | 外挂列存做 HTAP |

## 2. 前后讲联系
本讲是把 L05（行列）、L12-13（执行）、L22-23（分布式）在一个真实商业产品里"合体示范"。TiDB 的 TiFlash 就是开源 HTAP 的同款思路（行 KV + 列 Raft  Learner 副本），可与 L22 无缝对照。

## 3. 跨课程联系
- **CS143**：codegen/LLVM JIT = 把查询当程序编译；计划缓存≈编译产物缓存。
- **CS149/CSAPP**：内存原生（数据在 DRAM）意味着 L03-06 的磁盘假设弱化、NUMA 与缓存层次成为新战场；列存 SIMD 兑现 L13。
- **6.824/L23**：MPP + 复制 = 分布式数据流。

## 4. 开源项目应用
- **TiDB + TiFlash**：`tiflash` 提供列存副本、MPP 引擎，HTAP 开源标杆。
- **ClickHouse**：列存 + 向量化 + 物化视图，很多公司用它承接"实时分析"这一半。
- **DuckDB**：进程内 OLAP，与嵌入式行存（SQLite）组合成轻量 HTAP。
- **SAP HANA / Oracle IMS**（闭源对照）：内存多模。
- **SingleStore**（部分开源 client/文档，核心闭源）：本讲主角。
