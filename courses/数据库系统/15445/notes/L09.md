# L09 索引并发控制（Index Concurrency Control）

> 15-445/645 Fall 2023 · Lecture 9 · 阅读：课程讲义；B-link tree / Bw-tree 论文
> 多个事务同时往同一棵 B+ 树读写，锁住整棵树=没有并发，锁太细=死锁与元数据竞争——本讲解决"怎么安全地下树"。

## 1. 核心概念

### 1.1 索引闩（latch）vs 锁（lock）
- **Latch（闩/短锁）**：保护内存数据结构（页、节点）在**几微秒内**不被并发写坏，纯性能、不涉及事务语义、崩溃即失效。B+ 树下降时对每个节点加 S/X latch。
- **Lock（锁）**：事务级、由锁管理器（L16/18）管、可长持、影响隔离级别与回滚。索引页闩与逻辑行锁是两层。
- 本讲聚焦 latch：如何在下降过程中既保证结构一致，又最大化并发。

### 1.2 朴素协议的问题
"从根一路 X-latch 到叶"→整棵树串行。改进：**lock coupling / crabbing（螃蟹式爬树）**：
- 下到一个节点前先 latch 子节点，安全后就松开父节点（S 或 X）→ 像螃蟹横着挪，父先锁子后解。
- 读：S-latch 一路 crabbing。
- 写：下降到将分裂/合并的节点前升级 X-latch；若下行路上无结构修改风险，可在到叶后只 X-latch 叶。

### 1.3 crabbing 的坑与优化
- **上升（root 分裂/下树中合并）需要重锁父**——昂贵。
- 优化：**只在可能改变结构的节点加 X-latch**，其余加 S-latch（如内部节点一般只读，唯叶/将分裂者写）。
- **Splits/merges 期间**兄弟指针、父键更新必须原子，否则并发读可能"走丢"。

### 1.4 B-link tree（Lehman-Yao, 1981）——主流答案
给每个节点加：(1) **right-link（兄弟指针）+ 兄弟的 key range/continuation 标记**。
- 下降时若发现父键已因并发分裂过时，**沿 right-link 前进**而非失败；
- 分裂时先建立"父→左→新右"的链接（in-transition 标记），再更新父；
- 好处：**不需要对整条根-叶路径长时间持锁，甚至可不做 crabbing**，支持高并发与无死锁的下行（先右链再解锁父）。
- 是 MongoDB WiredTiger、多数现代引擎 latch 协议的思想来源。

### 1.5 Bw-tree（Levitin & Mohan 2014）——无 latch 的现代设计
为多核 + SSD/持久内存：
- **Mapping table**：逻辑 page-ID → 物理地址的原子 CAS 表（虚拟 indirection）。
- **Delta pages / consolidate**：改动不原地覆盖，append delta 记录，后台 consolidate 成 base page。
- 读：无锁（读 mapping table 快照 + CAS 判断是否被改，重试）；写：CAS 换 mapping 指针，失败重试。
- **epoch-based / GC**：回收旧物理页要等没有活跃读者（类似 RCU）。
- 代价：读多写少时 mapping 表大、缓存不友好；split 需 stop-the-world 式协调。SQL Server Hekaton 内存优化表用之。

### 1.6 与其他并发层的接缝
- 索引 latch 保证"结构安全"；真正的**事务隔离**由 L15-18 的锁/MVCC 保证"逻辑正确"。
- 二级索引 + MVCC：可见性判断在叶子上按版本时间戳过滤（L18）。

## 4. 开源项目应用
- **PostgreSQL**：nbtree 用 **SPLIT point + kill prior + Lehman-Yao 式 rightlink**（"half split"），并配合 `BTScan` 的 pin/latch；OOM 防止"deletion 后仍见旧键"靠 marking killed。
- **InnoDB**：index 用 **latch coupling + index lock（S/X 在 index 级）+ gap/next-key lock**（逻辑锁层，L16）；分裂用"先锁住 sibling"协议。
- **WiredTiger/MongoDB**：B-link 式 cursor latch（tuneable）。
- **RocksDB**：memtable 跳表用**无锁/细粒度** + version set 的读时快照（LSM 天然把写串行到 WAL，减少 B+ 树式结构并发问题）。
