# L14 查询规划与优化（Query Planning & Optimization）

> 15-445/645 Fall 2023 · Lecture 14 · 阅读：Selinger 1979 论文；课程讲义；Project #4
> 同一条 SQL 有天文数字的执行方案；优化器的任务是在"枚举全部"与"秒级返回"之间找平衡，选出估算代价最小的计划。

## 1. 核心概念

### 1.1 逻辑 vs 物理计划
- **逻辑计划**：关系代数表达式树（L01 代数），只说"算什么"。
- **物理计划**：每个逻辑运算绑定具体算法（σ→SeqScan+Filter 或 IndexScan；⋈→NLJ/SMJ/HJ）+ 连接顺序——"怎么算"。优化 = 在等价逻辑改写后，为每个节点挑物理算子并排序。

### 1.2 统计信息（Statistics）——估行的原料
没有统计，代价全是瞎猜。DBMS 定期扫描表/索引收集：
- **表级**：行数 reltuples、页数；
- **列级**：不同值数（distinct / NDV）、min/max、NULL 数；
- **直方图**：等宽 / 等深（equi-depth）/ **MLE（最大方差优化，Postgres）**，描述值分布；
- **Most-Common-Values (MCV)**：高频值列表（对倾斜数据关键）；
- **多列**：相关性/函数依赖（Postgres `pg_stats`、extended statistics）、joins 的列相关。
统计是**采样近似**（`ANALYZE` 抽样），可能过时→误估；现代方向：query-driven、learned 统计（近5年）。

### 1.3 选择率估计（Selectivity / Cardinality Estimation）
选择率 sel = 满足谓词的元组比例。基础规则：
- 等值 `a = v`：sel = 1/NDV（有 MCV 用 MCV 频率）；
- 范围 `a between x and y`：用直方图桶内线性插值；
- 合取 `p ∧ q`：假设独立 → sel_p · sel_q（**独立性假设是误估的头号来源**——列相关时严重偏）；
- 析取、NOT 用概率公式。
基数估计 = 自底向上把选择率乘上行数；join 基数 ≈ |R|·|S| / max(NDV(R.a), NDV(S.b))。

### 1.4 代价模型（Cost Model）
物理算子的代价 = f(CPU 成本, I/O 成本, 内存, 网络)：
- 传统：以**磁盘块读取数 + 比较次数**加权（Selinger 时代 I/O 主导）；
- Postgres 的 `seq_page_cost/random_page_cost/cpu_tuple_cost` 常数标定（EXPLAIN 里 cost 就是这套单位）。
- 现代 SSD：随机 I/O 与顺序差距缩小，代价常数需重标（L03 呼应）。

### 1.5 搜索策略：自底向上 vs 自顶向下
- **System-R / Selinger（1979）**：动态规划自底向上——先算所有单表、再所有 2 表 join 的最优子计划，逐步扩展；**只考虑左深树（left-deep tree）** 以剪枝（因为火山模型下左深可 pipeline，物化最少）。经典但错过"交叉/ bushy 计划"。
- **Volcano/Cascades（Graefe）**：自顶向下 + 备忘录（memoization）+ **规则（transformation rules）驱动枚举**，能搜 bushy 树、天然支持并行与扩展规则；现代工业级（SQL Server、CockroachDB、Calcite 借鉴）。
- **基数反馈 / adaptive**：执行中发现估算错→中途换计划（Oracle adaptive、Gree/Postgres join 顺序部分支持）。

### 1.6 常见等价改写（RBO 规则）
谓词下推（selection pushdown，尽早 σ）、投影下推、常量折叠、子查询去相关、外连接化简、join 交换/结合律生成不同序。RBO（规则基）常作为 CBO（代价基）的前置预处理。

- **CS229/ML**：learned optimizer / learned cardinality（近5年）把估行当回归问题——优化器正"ML 化"。

## 4. 开源项目应用
- **PostgreSQL**：System-R 式 DP 优化器 + MCV 直方图 + 扩展统计；`planner()`；`GEQO` 对 >geqo_threshold 表用遗传算法近似（DP 爆炸时兜底）。
- **MySQL**：8.0 前是贪心（只左深、按索引可用性贪心）， famously 弱；8.0.20+ 引入 join order search 改进。
- **CockroachDB/Optimizer**：移植自 Calcite 风格的 Cascades-like 优化器（Memo + rules）。
- **DuckDB**：自适应+代价；对分析查询用统计估行。
- **Spark Catalyst**：规则(RBO)+代价(CBO) 双引擎，Rust 重写的 AQE 运行时自适应。
