# L06 内存管理（Memory Management：缓冲池置换策略）

> 15-445/645 Fall 2023 · Lecture 6 · 阅读：课程讲义；Project #1 关联
> 缓冲池（Buffer Pool Manager, BPM）是数据库的"操作系统内存管理"：用有限 RAM 缓存远大于它的磁盘页，谁被换出是全部学问。

## 1. 核心概念

### 1.1 BPM 的职责与结构
- 维护一块固定大小的**帧（frame）数组**（如 128MB / 4KB = 32768 帧），每帧可装一个磁盘页。
- **页表（page table）**：pid → frame_id 的哈希映射，`FetchPage(pid)` 命中即返回。
- **空闲帧队列（free list）**：未使用的帧。
- **置换队列（replacement list）**：已被占用、可被淘汰的帧。
- 每个页帧有元数据：`pin_count`（引用计数）、`is_dirty`（脏标记）、`lock`。

### 1.2 页面生命周期与 API
```
FetchPage(pid):  命中→pin++ 返回；未命中→拿空闲帧(空则 evict)→读盘→插入页表→pin++
NewPage(pid):    分配新页(不读盘)
UnpinPage(pid):  pin-- ；pin=0 才可被淘汰；若 dirty 保留脏标记待 flush
FlushPage(pid):  写回磁盘（异步/批量）
DeletePage/...   归还帧
```
关键不变量：**pin_count>0 的帧绝不能被换出**（正被事务/闩使用），否则数据竞争。

### 1.3 页面状态与固定计数
- **pinned**：正在被使用，锁死在内存；忘记 Unpin = 泄漏，帧永远不可回收（BusTub Project #1 的经典 bug）。
- **dirty**：内存版本比磁盘新；换出前必须 flush，否则丢更新（WAL 保证即使不 flush 也能恢复，L19）。
- 一次 `Fetch→修改→Unpin` 应 `SetDirty(true)`。

### 1.4 置换策略（Replacement Policies）——本讲灵魂
目标：最小化 miss（换出将来不再/最久不用的页）。
- **LRU**：最近最少使用换出。精确 LRU 需双向链表+哈希，O(1) 但维护成本/内存开销高，且**顺序扫描污染（scan pollution）**——一次全表扫把热页全冲掉。
- **Clock / Second-Chance（NRU）**：给每页一个引用位，环形指针扫：引用位=1 则清 0 跳过，=0 则换出。**近似 LRU、O(1)、省内存**，工业界最常用（Postgres、InnoDB 变体）。
- **LRU-K**：记录"最近第 K 次使用"时间，用 K 阶历史判断，减少偶发大扫描误伤。
- **2Q / MQ**：多级队列（in/out），A1in 存新页、A1out 存被踢摘要、Am 存热页，抗扫描。
- **ARC（Adaptive Replacement Cache）**：动态平衡 LRU 与 LFU，自适应近期+频繁。
- **Clock-Pro**：Postgres 讨论过的改进，分 test/protected，抗全表扫污染。
- **LFU**：按频率，问题=历史高频页赖着不走；需老化衰减。
- 数据库特有：**顺序预读（sequential prefetch）** 与 **pinning**——扫描器可提前 `AsyncReadPage` 下几个页并短期 pin，配合 clock-sweep 避免污染。
- 脏页刷新：换出脏页要么同步写（慢）要么后台 flusher 批量写（现代）；**检查点（L19）** 定期降脏页水位。

### 1.5 与 OS 页缓存的差异
- OS 以虚页(4K)为单位、对全进程透明、不知道"页语义"；DBMS 知道 schema、访问模式、事务，可做**语义感知置换**（如按表/索引分区缓存）。
- DBMS 用 `O_DIRECT` 绕开 OS page cache 避免双重缓冲——自己管内存。

## 4. 开源项目应用
- **PostgreSQL**：环形数组 + 使用计数（clock sweep 近似 LRU），`bgwriter`/`checkpointer` 后台刷脏；`shared_buffers`。
- **InnoDB**：LRU 改良为 **young/old  sublist（5/8 vs 3/8）**：新读入页先进 old 区冷端，只有超过 `innodb_old_blocks_time`(1s) 再被访问才晋升 young——专治全表扫污染。
- **RocksDB**：block cache 用 LRU 或 Clock（`clock_cache`），分片锁降竞争。
- **MySQL Memory Engine / Redis**：Redis 的近似 LRU（采样 N 个 key 淘汰最久未用）是同一思想的极简版。
