# L22 分布式 OLTP 数据库（Distributed OLTP Database Systems）

> 15-445/645 Fall 2023 · Lecture 22 · 阅读：Spanner / Percolator / TiDB 论文
> 把 L15-18 的 ACID 事务搬到跨地域多副本上，还要保持"外部一致性"——这是数据库工程皇冠上的明珠，也是 NewSQL 的战场。

## 1. 核心概念

### 1.1 2PC（两阶段提交，Two-Phase Commit）
跨节点事务的经典协议：协调者（coordinator）驱动。
- **Prepare 阶段**：协调者向各参与者发 prepare；每个参与者本地执行事务、写日志、拿到锁/版本，回 yes/no（"我保证能提交，除非你让我回滚"）。
- **Commit 阶段**：全 yes → 协调者写 commit 记录并广播 commit；任一 no/超时 → abort。
- **痛点**：
  - **协调者单点**：prepare 后协调者崩溃，参与者被无限阻塞（持锁）→ "in-doubt/悬挂事务"；
  - **两次同步往返**（prepare + commit）→ 延迟高，跨地域尤其致命；
  - 需 **Paxos/Raft 复制协调者日志** 消除单点（=共识化的 2PC）。
- **恢复**：in-doubt 事务靠读协调者的持久决策或阻塞式恢复。

### 1.2 Google Spanner（外部一致性）
全球分布式 NewSQL，把"物理时钟"变成可信原语：
- **TrueTime**：依赖数据中心原子钟+GPS，返回 `(earliest, latest)` **不确定区间** + 已测最大延迟 ε；提供 `TT.Timestamp()` 和 `TT.WaitAfter(t)`。
- **外部一致性（external consistency / 严格可串行化）**：任一事务 T1 提交**在** T2 开始**之前**（真实世界因果）→ commitTS(T1) < commitTS(T2)。
- 实现 = **2PL（并发，粗粒度）+ 2PC（原子）+ Paxos 复制（每分片一个 Paxos 组，容错）**，提交前用 TrueTime **commit-wait**：等不确定区间过去，保证时间戳不"倒退"——这是为外部一致性付出的延迟税。
- 读：严格 2PL 下的快照读（多版本）；用 "intent" 记录标记未决。

### 1.3 Google Percolator（乐观 + 无协调者单点）
Spanner 的前身，构建在 BigTable 上，**去 2PC 协调者**、用**行级乐观事务**：
- 每个事务有一个 **primary** 行 + 若干 **secondary** 行；两阶段写：先在各行写 **Lock**（悲观锁，防冲突）+ Write 预提交，标 secondary=pre-commit，primary 最后写 commit 时间戳；secondary 靠 primary 状态决定 finalize。
- **Timestamp Oracle (TSO)**：集中分配单调时间戳（快照读时间、提交时间）——单点但极轻量。
- 无中心协调者进程崩溃可被其他客户端"救活"（推进 commit/finalize）。

### 1.4 TiDB / CockroachDB（Percolator 与 Spanner 的开源合成）
- **TiDB**：PD 节点提供 **TSO**（全局时间戳，类 Percolator），TiKV 行级乐观/悲观事务 + Raft 复制；MVCC 用时间戳作版本；**Hybrid Logical Clock (HLC)** 在允许小误差下减少 commit-wait。支持 TiFlash（列存副本，HTAP）。
- **CockroachDB**：**Raft** per range + 事务 = 改良 HLC 时间戳 + 异步提交（async commit，减少一次往返）+ 并行提交 + 事务性 schema 变更；默认 Serializable（SI + 冲突回滚），可配置弱隔离。
- 二者都用 **MVCC + 时间戳**（L18）+ Raft 复制（L21），是 445 单机知识在分布式的自然延展。

### 1.5 关键权衡
| | Spanner | Percolator | TiDB | CockroachDB |
|---|---|---|---|---|
| 并发 | 2PL+MVCC | 乐观+Lock | 乐观/悲观 | 悲观/SI |
| 时钟 | TrueTime | 逻辑(TSO) | TSO+HLC | HLC |
| 原子 | 2PC(共识) | 主行协调 | 主行协调 | Raft/事务 |
| 一致性 | 外部一致 | 快照 | 线性一致 | 严格可串行 |

## 3. 跨课程联系
- **6.824（最直接）**：Raft/Paxos、MapReduce、一致性——Spanner 的 Paxos 组、TiDB 的 Raft region 就是 6.824 的产物；TSO ≈ Lamport clock 中心化。
