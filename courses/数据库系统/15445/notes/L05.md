# L05 存储模型与压缩（Storage Models and Compression：行存/列存）

> 15-445/645 Fall 2023 · Lecture 5 · 阅读：课程讲义；C-Store / DW compression 论文
> OLTP 读一行所有列，OLAP 读一列所有行——访问模式的对立，决定了布局的对立。

## 1. 核心概念

### 1.1 两种布局
- **行式（NSR, n-ary storage / PAX-row）**：一条记录的所有字段连续存放。适合 OLTP：点查/更新一行只碰一个页，事务改一行的多列只脏一页。
- **列式（CSM, column-store）**：一个字段的所有值连续存放（一个列一个"extent/segment"）。适合 OLAP：
  1. 投影下推——`SELECT avg(salary)` 只读 salary 列，跳过其余 → **减少 I/O 与内存带宽**；
  2. 同类型连续 → **压缩率极高**（见 1.3）→ 进一步降 I/O；
  3. 同类型连续 + SIMD → **向量化执行友好**（L13 的天然搭档）。
- **PAX（Partition-Attributes-Across-Storage）**：混合——页内按列分子块，页间按行；兼顾两者，是"亚页级列存"。

### 1.2 行存的列交错变体（回应 L01 ISA / 变长）
- 定长列 + 变长列分文件存放（避免变长列把定长区撑碎）；
- 频繁更新的列可拆到"扩展文件"（vertical partitioning）；
- 冷列（很少读的宽字段）放溢出区，让主扫描只热数据。

### 1.3 压缩（Compression）——列存的杀手锏
先讲两个维度：**lightweight（编码级，可解压即算）vs heavyweight（块/页级）**；以及**有损 vs 无损**（DB 全无损）。常用编码：
- **RLE（游程）**：连续相同值 → (value, count)，对已排序列极佳；
- **Dictionary（字典）**：值→码，配合排序后基数下降；
- **Bit-packing / Frame-of-Reference (FOR)**：存 (value − min) 用最少 bit 表示，块内基线；
- **Delta / Delta-of-Delta**：时间序列/自增键，二阶差分常近零；
- **Frequency / Huffman**：按出现频率变长编码；
- **Chimp/Patas**（2022/2023）：针对浮点（双精度）的 XOR + 前导零压缩，时序数据库用。
课堂强调：**压缩要能"在压缩态上直接计算"（compressed execution）**——谓词在码上比较，不解压整块，否则解压成本吃掉 I/O 收益。

### 1.4 何时选什么
- 混合负载（HTAP）→ 行列双存（SAP HANA、SingleStore 行存+列存镜像，L24 嘉宾课主题）；
- 现代默认：分析库=列存（Snowflake/Redshift/DuckDB/ClickHouse）；事务库=行存（MySQL/PG 默认）。
- 列存的代价：**更新/插入贵**（要散到多个列文件）、**事务回滚复杂**（一行横跨多列文件）、点查全行需"列合并"（positional merge / record ID）。

## 3. 跨课程联系
- **CSAPP Ch.6**：列存=空间局部性的极致——同类型连续遍历命中缓存行；行存宽表扫描踩缓存。向量化（L13）的 SIMD/寄存器复用建立在此。
- **6.006/数据结构**：FOR+bit-packing 是"信息论下界"的落地——值域决定 bit 数。
- **数据压缩通识**：RLE/字典/Huffman 与文件压缩同源，但 DB 压缩多了"可计算"约束。

## 4. 开源项目应用
- **C-Store / Vertica**：列存学术奠基（Stonebraker 2005），读优化+WOS/ROS 两级（写缓冲后合并=列版 LSM）。
- **ClickHouse**：列存 + 多编码（Dictionary/Delta/DoubleDelta/Gorilla）+ LZ4；时序压缩教科书。
- **DuckDB**：列存 + RLE/FOR/bit-packing 段，配合向量化执行。
- **PostgreSQL**：行存为主，但 TOAST（压缩大字段）、BRIN 索引（块范围摘要，近似列统计）体现列思想；`extension` 可加 cstore_fdw。
- **Parquet/ORC**：文件级列存格式（row group + column chunk + page + 编码），数据湖的存储模型（L23/近5年 lakehouse 呼应）。
