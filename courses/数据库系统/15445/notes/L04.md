# L04 数据库存储 II（Database Storage II：页结构与块设备交互）

> 15-445/645 Fall 2023 · Lecture 4 · 阅读：课程讲义；Architecture of a DB System Ch.4
> 页（page）是 DBMS 与块设备之间的契约单位；本讲拆解页内部如何摆放记录，以及文件如何组织页。

## 1. 核心概念

### 1.1 页式管理（Paged Management）
- DBMS 把磁盘看成**固定大小页的数组**（页号 pid），一页=一次 I/O；页大小常 4–16KB（Postgres 8K、InnoDB 16K、sqlite 4K）。
- **变长管理（Variable Management）**：像 OS 一样用 malloc 式连续空间管理整块磁盘，DBMS 自己实现 `AllocatePage/DeallocatePage/Read/Write`；页可大可小、按记录大小动态——现代主流 DBMS 几乎都选 paged。

### 1.2 记录格式（Record Format / Layout）
一条元组在页内的字节布局要解决：定长 vs 变长字段、NULL、字段数可扩展（schema evolution）。
- **Header**：元信息（字节长度、版本号、事务/时间戳槽位、NULL 位图 bitmap——1 表示该列为 NULL，跳过存储）。
- **Data**：字段值；变长字段用 (offset, length) 间接指向数据区。
- 三种经典字段摆放策略（对应 L01 的"列的排列"）：
  - **NSMR（naturally sorted / 按属性顺序）**：像 C struct，读写快但改长字段要挪位；
  - **SSMR（slotted / 列交错）**：定长部分紧凑摆放，变长部分放后段；
  - 课堂重点：**NULL 用位图省空间**、**变长字段用 offset 表**。

### 1.3 Slotted Page（槽页）——本讲核心数据结构
一页 = **固定头 + 槽数组（从页头向后生长）+ 记录区（从页尾向前生长）**：
```
| PageHeader | slot0 slot1 slot2 ... | free space | ... rec2 rec1 rec0 |
```
- 记录引用用 **(pid, slot_num)** 二元组，而非物理偏移；记录移动（插入/删除导致的 compaction）只改槽表，**元组指针 TID 保持稳定**——这是索引能引用堆元组的前提（L08 heap file + index）。
- 好处：页内碎片整理便宜；记录可以任意方向生长；删除只清槽、真正腾空间靠 reclaim。

### 1.4 堆文件的页组织（File/Record Organization）
把多条记录装进文件的策略，决定扫描/点查/范围查代价：
| 组织 | 插入代价 | 点查 | 范围查 | 说明 |
|---|---|---|---|---|
| **Heap** | 最低（有空槽就塞） | 全扫 O(n) | 全扫 | 无聚簇，配合索引 |
| **Sorted (ISAM)** | 高（插入要挪位，用 overflow 页缓冲） | 二分 | 顺序好 | 批量导入友好 |
| **Hash** | 低 | O(1) | 差（无序） | 只能等值 |
| **Clustered/B+树** | 中 | O(log) | O(log+k) | 聚簇索引，见 L08 |
- **free page / free space 管理**：DBMS 维护 freelist 记录哪些页有空槽；插入从 freelist 取。
- 一条记录不能跨页（超宽记录溢出到 **overflow page**，主链留指针）。

### 1.5 记录的插入/删除协议
- 插入：找有空间的页（freelist）→ 定位槽 → 写记录 → 更新槽表 → 更新记录计数。
- 删除：标记槽删除、清 free space 起点、更新 freelist；真正搬移留到后续 compaction（避免每次删都整理）。
- 更新 = 删除+插入（若变长），或原地改（定长且不变），后者可少写日志（L19 的更新日志类型区别）。

## 2. 前后讲联系
本讲页内布局是 L05"行 vs 列"存储模型的最小单元；(pid,slot) TID 稳定性是 L08 二级索引指向堆的前提；freelist/页固定则交给 L06 缓冲池管理。

## 3. 跨课程联系
- **CSAPP**：slotted page 的自由区=堆内存分配器的页内微缩版（first-fit、碎片）；malloc 的 chunk header 类比记录 header。
- **6.S081**：xv6 文件系统每个块用 bitmap + indirect 块；DBMS 页号数组比 FS 更"扁平直接"。
- **6.006**：offset 表→跳跃访问，是"用空间换间接层稳定性"的经典权衡。

## 4. 开源项目应用
- **PostgreSQL**：PageIdData + ItemIdData 槽数组正是 slotted page；`ctid = (block, offset)` 就是 TID；MVCC 把旧版本留在页内（HOT update 原地不改索引，L18）。
- **InnoDB**：compact row format 变长字段长度列表+NULL 位图+record header；页内 min/max free space slot 分类管理 freelist。
- **sqlite**：b-tree 页兼做表与索引，cell pointer array 从页尾生长=slotted 变体。
- **RocksDB**：block（数据块）内 restart points + prefix 压缩，是"排序键值对块"，与 slotted page 思路分叉（LSM 流派）。
