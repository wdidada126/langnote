# L15 并发控制导论（Concurrency Control Intro：事务与隔离级别）

> 15-445/645 Fall 2023 · Lecture 15 · 阅读：课程讲义；Silberschatz Ch.7
> 并发是数据库存在的理由，也是它最烧脑的部分：多个事务同时读写同一数据，既要快又要"像没冲突一样"正确。

## 1. 核心概念

### 1.1 事务与 ACID 再定位
事务=不可分割的操作序列（BEGIN…COMMIT/ROLLBACK）。L15 专注 **I（隔离）**：并发执行的效果要等价于某种**串行**执行。A/D 靠日志（L19-20），C 靠约束（L01）。

### 1.2 调度（Schedule）与可串行化
- **调度**：多事务操作的交错顺序。
- **冲突（conflict）**：两操作访问同一数据项、至少一个是写、且来自不同事务。
- **冲突可串行化（conflict serializable）**：调度经"交换非冲突操作"能变某个串行序 → 保证正确。判定工具：**优先图（precedence graph）**——T1 的某操作先于 T2 的冲突操作则画边 T1→T2；**图有环 ⟺ 不可串行化**。
- 视图可串行化更弱、实际少用。

### 1.3 并发异常（Lost Update / Dirty Read / …）
| 异常 | 场景 |
|---|---|
| **Dirty Read 脏读** | 读到别的事务**未提交**的数据（它可能回滚） |
| **Non-Repeatable Read 不可重复读** | 两次读同一行，中间别人改了并提交 |
| **Phantom Read 幻读** | 两次范围查询，中间别人插入/删除了范围内行 |
| **Lost Update 丢失更新** | 两事务都基于旧值写，后写覆盖前写 |
| **Write Skew 写偏差** | 两事务读同一集合、各写不同行、合起来违反约束 |

### 1.4 隔离级别（ANSI SQL-92 四级）
- **READ UNCOMMITTED**：允许脏读（几乎没人给写负载用）。
- **READ COMMITTED**：只读已提交；避免脏读，仍有不可重复读/幻读（Oracle/Postgres 默认，用 MVCC 实现）。
- **REPEATABLE READ**：事务内多次读一致；解决不可重复读，幻读视实现（MySQL InnoDB 用 MVCC+gap lock 在此级别消灭幻读，强于标准）。
- **SERIALIZABLE**：可串行化——最高保证，代价最大（2PL 全锁 或 特殊 MVCC 如 SSI）。
- 注：SQL 标准对"每级别禁止哪些异常"定义混乱（write skew 在 SERIALIZABLE 都不该有——靠谓词预览）。Postgres 用 ** Serializable Snapshot Isolation (SSI)** 实现可串行化+MVCC 性能。

### 1.5 并发的根本矛盾
锁得越严越正确但吞吐越低；实现两条大路——
- **悲观（2PL，L16）**：先锁再动，冲突时阻塞；
- **乐观（TO, L17 / OCC）**：先干，提交时检查冲突；
- **多版本（MVCC, L18）**：读不阻塞写、写不阻塞读，靠版本+快照。
后三讲各自展开。

## 4. 开源项目应用
- **PostgreSQL**：默认 READ COMMITTED（每条语句新快照 MVCC）；SERIALIZABLE 用 SSI（检查谓词-谓词冲突）；隔离级别在 `src/backend/access/transam/xact.c`。
- **MySQL/InnoDB**：默认 REPEATABLE READ（MVCC ReadView + Next-Key Lock 防幻读）；`innodb_locks` 视图看冲突。
- **CockroachDB**：默认 Serializable（MVCC + 2PL/事务性 schema），Raft 保证复制。
- **Spanner**：外部一致性=严格可串行化（L22 的 TrueTime + 2PL）。

- Q：write skew 与 lost update 区别？——A：前者各写不同行仍违反约束，后者覆盖同值（§1.3）。
- Q：MySQL 默认隔离级别？——A：REPEATABLE READ（MVCC+间隙锁）（§1.4）。
