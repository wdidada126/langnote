# L11 连接算法（Join Algorithms）

> 15-445/645 Fall 2023 · Lecture 11 · 阅读：课程讲义；Morsel-Parallel Hash 论文
> 连接是关系代数的"贵妇"：笛卡尔积 O(|R|·|S|)，好算法把它降到 O(|R|+|S|) 或 O(n log n)——选错算法差几个数量级。

## 1. 核心概念

记 |R|=n, |S|=m。目标：求 R ⋈_{R.a=S.b} S。

### 1.1 Nested Loop Join（NLJ，朴素双重循环）
```
for r in R: for s in S: if r.a==s.b: emit(r,s)
```
- 复杂度 O(n·m)；对**非等值连接（θ-join、范围连接 < > between）**是唯一通用解。
- **Index Nested Loop Join（INLJ）**：内表在连接列上有索引 → 外层每行做一次索引查找 O(log m) → 总 O(n log m)。**当外层小、内层大且有索引时最优**（相关子查询去相关后的常见计划）。
- **Block Nested Loop（BNL）**：一次取一块（B 页）外记录进内存，内表扫一遍与之匹配 → 内表 I/O 从 n·|S| 降到 (n/B)·|S|。MySQL 旧版曾用。

### 1.2 Sort-Merge Join（SMJ，归并连接）
两表各自按连接键排序（或用已有有序索引），然后双指针归并：相等输出、小的前进；处理重复键用"块内配对"。
- 复杂度：排序 O(n log n + m log m)（若已有序则 O(n+m)），归并 O(n+m)。
- 优点：**输出有序**（可级联给下游 ORDER BY / merge，无内存爆炸）、适合**大-大连接**、支持 θ-join（排序后范围扫）。
- 缺点：要全排序（阻塞）、内存不足要外部排序溢写。
- **Grace/ranked partitioned merge join**：排序太贵时改哈希分区再逐对连接（融合 SMJ 与哈希思想）。

### 1.3 Hash Join（哈希连接）——等值连接主力
两阶段：**Build**（把小表 R 建成内存哈希表，key=连接列）+ **Probe**（扫大表 S，逐行查哈希表输出匹配）。
- 复杂度 O(n+m)，**要求等值连接**。
- 小表选 build side（省内存）。
- **内存放不下 build 表 → Partitioned Hash Join（Grace Hash Join）**：两表都按 h(key) 分成哈希一致的分区（同 key 落同分区对），逐分区建小哈希表连接；某分区仍太大→**递归再分区**。I/O ≈ 3–4 遍扫描，几乎总是最优。
- **Symmetric Hash Join（SHJ）**：build/probe 交替、双方都可增量，流式/交互式场景。
- **Morsel-Parallel Hash Join**：把 build 表切成小"morsel"（几千行），每线程认领 morsel 用 **atomic fetch_add** 插入共享哈希表（无锁并行 build）；probe 同理切块。解决"按分区并行导致的负载不均"——现代并行引擎（Umbra/DuckDB/Self-Driving）主流。

### 1.4 外连接 / 半连接 / 反连接
- 外连接：在匹配基础上，未匹配的保留侧补 NULL（哈希表给未匹配行打位图标记）。
- 半连接（WHERE IN）：匹配到即输出外层一次，不重复。
- 反连接（NOT EXISTS）：外层且从未匹配。这些都能复用上述三种主算法。

## 2. 前后讲联系
连接算法是 L10 排序/哈希两大工具箱的"综合应用"。L12-13 把它们变成执行算子；L14 优化器的核心工作就是**为每个 join 选算法 + 定连接顺序**（n 个表的 join 序是指数级搜索空间，Catalyst/动态规划）。INLJ 依赖 L08 索引存在。

- **CS149/并行**：morsel 并行=work-stealing/动态任务粒度；分区并行=静态划分；两者负载均衡的取舍是并行经典话题。

## 4. 开源项目应用
- **PostgreSQL**：三种全有——Nested Loop（含 INLJ）、Merge Join、Hash Join，外加 Bitmap Heap Scan 辅助；由代价模型选。
- **MySQL/InnoDB**：8.0.18+ 引入 Hash Join（此前只有 BNL/INLJ， famously 落后）；8.0.20 用 hash join 取代 BNL。
- **DuckDB**：partitioned hash join + **perfection detection**（连接键近密集时退化成数组直接索引，免去哈希）+ morsel 并行。
- **Spark**：SortMergeJoin / BroadcastHashJoin（小表广播）/ ShuffleHashJoin——分布式版同款三件套。

## 速记自检
- Q：三种主 join 算法的复杂度？——A：NLJ O(n·m)、SMJ O(n log n)、HJ O(n+m)（各节）。
- Q：INLJ 何时最优？——A：外表小、内表大且有索引（§1.1）。
- Q：hash join build 侧放不下？——A：Grace 分区、递归再分（§1.3）。
- Q：morsel 并行解决什么？——A：分区并行的负载不均（§1.3）。
