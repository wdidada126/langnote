# L00 课程导论（Course Overview）

> 15-445/645 Fall 2023 · Lecture 0 · Andy Pavlo 主讲，纯线上形式（ pandemic 后延续的混合发布）
> 本课是 CMU 数据库方向研究生/高年级本科生的入门内核课：不教"怎么用 SQL"，而是教"数据库怎么跑起来"。

## 1. 核心概念

### 1.1 数据库系统是什么
DBMS = 一个管理持久化数据、并保证 **ACID**（Atomicity/Consistency/Isolation/Durability）的软件系统：
- **A**：事务内操作全做或全不做（靠日志回滚）→ L19-20；
- **C**：由应用与约束保证，DBMS 提供原语；
- **I**：并发事务互不干扰（锁/MVCC）→ L15-18；
- **D**：提交后断电不丢（WAL+检查点+fsync）→ L19-20。
性能维度则是另一个世界：存储、索引、执行、优化 → L03-14。

### 1.2 DBMS 的四大内部组件
1. **Storage Engine**：磁盘/SSD 块设备与缓冲池（L03-06）；
2. **Indexer**：哈希表与 B+ 树（L07-09）；
3. **Query Processor**：解析→计划→执行→优化（L10-14）；
4. **Concurrency/Recovery**：事务、日志（L15-20）。
之上还有分布式层（L21-23）与各种"非关系"扩展（图/OLAP/ML）。

### 1.3 课程载体：BusTub
CMU 自研教学型数据库（C++，GitHub: cmu-db/bustub），五个 Project 依次实现：
P1 缓冲池、P2 B+ 树索引、P3 执行器与 RBO、P4 并发控制（WAL+锁+恢复）。
本课配套项目（`projects/`）借鉴其思想但独立实现，标准库 only。

### 1.4 为什么"存储层次"是灵魂
数据库的一切设计都围绕 **内存与磁盘的速度差**（毫秒 vs 纳秒，百倍到万倍）：
页式 I/O、缓冲池、B+ 树的低矮胖结构、顺序读写偏好，全是这个差距的投影。
Andy 的口头禅："Everything is about the memory-disk gap."

## 2. 课程地图（26 讲结构）
- L01-02 数据模型与 SQL（用户视角）；
- L03-06 存储与内存管理（块设备→页→行/列→缓冲池）；
- L07-09 索引（哈希/B+树/并发索引）；
- L10-14 查询处理（排序聚合连接→执行模型→优化器）;
- L15-20 事务（理论→2PL→TO→MVCC→日志→恢复）；
- L21-23 分布式（共识/分布式 OLTP/OLAP）；
- L24 嘉宾讲座（SingleStore）；L25 期末串讲。

## 4. 跨课程联系
- **CSAPP（15-213）**：本课官方先修。Ch.6 存储层次（局部性、缓存）将直接升级为"磁盘→缓冲池→TLB"三级类比；malloc/虚拟内存一章对应缓冲池的地址映射设计。
- **6.S081/CS162**：文件系统=共享的缓冲池+日志；两课的"机制与策略分离"哲学一致。
- **MIT 6.824**：分布式讲（L21-23）假设你已懂 MapReduce/Raft；本课专注"单机内核+分布式事务"。
- **CS143 编译原理**：查询计划之于优化器 ≈ AST/IR 之于编译器优化，L14 会明确做这个类比。

## 5. 开源项目应用（全景）
- **PostgreSQL**：完整参考实现：缓冲池(bufmgr)+B+树(nbtinsert)+火山执行(nodeExec)+MVCC+SRL 恢复——每一讲都能在它身上找到对应物。
- **MySQL/InnoDB**：LRU-young/old 双链缓冲池、B+ 树聚簇索引、undo log MVCC。
- **RocksDB**：LSM-tree 流派（B+ 树的镜像设计），缓冲池简化为 block cache。
- **DuckDB**：向量化执行+自动向量循环，L13 的活教材。
- **TiDB/CockroachDB**：Percolator 式 MVCC+Raft，L21-22 的工程化身。
