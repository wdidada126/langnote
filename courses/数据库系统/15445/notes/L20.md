# L20 数据库恢复（Database Recovery：ARIES、介质故障、备份与 PITR）

> 15-445/645 Fall 2023 · Lecture 20 · 阅读：Mohan 1992 ARIES；课程讲义
> L19 建了日志这个"账本"，本讲是"对账与重建"的全过程：进程崩溃如何秒级复原、整块磁盘报废如何靠备份+归档日志重放到任意时刻。

## 1. 核心概念

### 1.1 ARIES 恢复算法（工业标准）
ARIES = Algorithm for Recovery and Index Consistency，把 L19 的三阶段做成完整方法学，核心思想 **REPEAT HISTORY（重放历史）**：崩溃后精确重建崩溃瞬间的内存+磁盘状态，不多不少。

三个 Pass（从日志中 `begin-checkpoint` 记录起扫）：
1. **Analysis Pass**：从最老 checkpoint  forward 扫，重建两张表：
   - **Transaction Table**：崩溃时仍活跃（未 commit/abort）的事务 = losers；
   - **Dirty Page Table (DPT)**：崩溃时内存里比磁盘新的页 + 每页的 `rec_lsn`（最早需要 redo 的日志位置）。
2. **Redo Pass**：正向扫描，对 DPT 里的页重放**所有**日志（winners 和 losers 都重放），使 DB 回到崩溃瞬间。幂等判据：`page.page_LSN ≥ log.rec_LSN` 则跳过（已应用）。
3. **Undo Pass**：对 losers 反向回滚（沿每事务的 last_LSN 链，用 before-image），每步写 **CLR**（Compensation Log Record，CLR 本身不再被 undo，保证 undo 幂等），loser 全部 undo 后写 `<T abort>`。

关键数据结构/概念：
- **Log Sequence Number (LSN)** 全序坐标；
- **page LSN** 保证 redo 幂等、**flush 顺序规则（WAL + LSN 规则）**：
  - **Update/Write-Ahead 规则**：日志先于其描述的页改动落盘；
  - **Force Log-First 规则**：写 checkpoint 前其日志必须先 flush；
  - **Transaction-First 规则**：写 commit/abort 记录前，该事务更早的日志必须先落盘。

### 1.2 变体
- **物理逻辑（physiological）日志**：页内物理、页间逻辑（B+ 树分裂记逻辑，页内容记物理）——降低日志量。
- **Log-based vs Shadow Paging**：ARIES 属 log-based；影子分页（原子换根页表）无需 undo 但有碎片/并发问题。
- **Fuzzy checkpoint**（L19）使 ARIES 在线、可增量恢复。

### 1.3 介质故障（Media Failure）与备份
进程崩溃靠本机日志即可；**磁盘物理损坏**必须：
1. 从**备份（base backup）**恢复数据文件；
2. 再 **redo 归档日志（archive log / WAL segment）** 把备份后的所有变更重放。
两种恢复时间线：
- **即时恢复（immediate）**：全库停，恢复完再开——RTO 长。
- **按需恢复（deferred / piecemeal）**：只恢复被访问到的页，坏页隔离——现代大库用。

### 1.4 PITR（Point-In-Time Recovery，时间点恢复）
"误删表/数据被污染，回到昨天 14:00 的状态"：
- 前提：**base backup + 连续 WAL 归档**。
- 机制：恢复时重放归档日志到**目标时间/事务/LSN** 处 `recovery_target_time` 停止。
- 这是备份策略的价值所在：不只是"能起得来"，而是"能回到任意过去时刻"。
- 代价：需要**归档存储**（对象存储/异地），WAL 保留窗口决定可回看多久。

### 1.5 备份类型
- **冷备份（cold / file copy）**：停库直接拷文件——简单、停机。
- **热备份（warm / online）**：运行中拷 + 期间的日志补齐一致性（`pg_start_backup`/xtrabackup）。
- **逻辑备份（dump）**：导出 SQL/CSV（pg_dump/mysqldump），跨版本、可细粒度恢复、慢、恢复即重放插入。
- **快照备份**：存储层/LVM/云盘快照（ZFS/EBS snapshot），秒级、增量。

## 3. 跨课程联系
- **6.S081/CS162**：xv6 `log.c` 崩溃只重放一个事务的块（单机 mini-ARIES）；"日志即真相、数据可重建"是 FS 与 DB 共同信条。
- **CSAPP Ch.10**：`fsync`/`fdatasync`、O_DIRECT 绕过 OS 缓存，是"备份到底拷的是什么"的底层依据；硬件磁盘缓存导致"假 fsync"→ 需 FUA/barrier。
- **6.824**：ARIES 的"重放日志到某 index" = Raft 的日志重放；PITR = 重放到某 log 位置；备份+WAL ≈ 快照 + 后续 oplog。

## 4. 开源项目应用
- **PostgreSQL**：`pg_basebackup` + WAL 归档（`archive_command`）+ `recovery.conf`/`restore_command` 做 PITR（`recovery_target_time`）；`pgBackRest`/`barman` 工具。
- **MySQL**：`xtrabackup`（热备）+ binlog/redo 做 PITR；InnoDB crash recovery = ARIES 简化版（redo 前滚 + undo 回滚，启动时自动）。
- **SQLite**：rollback journal / WAL checkpoint；备份 = 拷文件 + `VACUUM INTO`。
- **云 DB（Aurora/S3 上的库）**：把 WAL 下推到存储层、存储多副本，"备份/PITR"变成"存储层按时间戳取快照"——架构级简化（L22/23 存算分离呼应）。
- **RocksDB**：`CHECKPOINT`/backup engine + WAL 归档。
