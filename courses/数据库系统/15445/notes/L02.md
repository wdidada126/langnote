## 1. 核心概念

### 1.1 SQL 与关系代数的对应与偏离
- SELECT-FROM-WHERE ≈ π∘σ∘(×)；对应只是教学幻觉：SQL 是 **bag 语义**（默认不去重、有 ORDER BY/LIMIT/窗口这些代数里没有的原语）、三值逻辑、以及**求值顺序由优化器决定而非书写顺序**。
- 子查询家族：标量子查询、IN/EXISTS（半连接 ⋉ / 反连接 ▷）、相关子查询（可去相关 flatten 成 join——L14 优化器的重要规则）。
- 聚合：GROUP BY 把"分组"变成一等公民（L10 聚合算法的实现对象）；HAVING 是分组后的 σ；聚合函数 COUNT/SUM/AVG/MIN/MAX + DISTINCT 修饰。

### 1.2 连接语法史
`,`+WHERE（θ 谓词混在过滤里，外连接没法写）→ `INNER/LEFT/RIGHT/FULL OUTER JOIN ON`（SQL-92，连接谓词与过滤谓词分离，优化器才能自由换序）→ `NATURAL JOIN`/`USING`（按同名列自动等值连接，危险写法）。
外连接语义 = 保留侧不变 + 另一侧补 NULL；`t.* EXCEPT` 之类语法各家扩展。

### 1.3 集合操作与空值陷阱
- UNION（去重，代价=排序或哈希）vs UNION ALL（拼接，几乎免费）——90% 的场景该用 ALL。
- INTERSECT/EXCEPT；
- NULL 陷阱清单：`NOT IN (…含NULL…)` 恒为空；`COUNT(col)` ≠ `COUNT(*)`；`x <> 'a'` 不返回 NULL 行；GROUP BY 把所有 NULL 归为一组；`ORDER BY` 时 NULL 的位置各家不同（PG 默认 NULLS LAST，MySQL 最前）。

### 1.4 高级特性（本课点到为止）
- **CTE**（WITH … AS）：可读性+递归查询（图遍历！L24 图讲的前菜）；多数引擎物化与否是优化器决策（PG 12 前总是物化）。
- **窗口函数** `f() OVER (PARTITION BY … ORDER BY … ROWS/RANGE …)`：不折叠行，每行带上下文——排名、移动平均、同比环比；实现=分组排序+滑动状态（L10 的排序是其代价主体）。
- **CASE/COALESCE/GREATEST**、**PIVOT/UNPIVOT**、**UPSERT**（`INSERT … ON CONFLICT DO UPDATE`，MySQL 的 ON DUPLICATE KEY UPDATE——主键索引+锁的语法糖，L16/18 见真章）。
- **触发器/视图/存储过程**：视图=保存的查询（可更新视图条件苛刻）；本课明确不深入"SQL 层"（那是 CS186/CS346 的领地）。

### 1.5 内联与执行入口
DML/DDL/DCL/TCL 四类语句；`EXPLAIN`/`EXPLAIN ANALYZE` 是唯一值得教的"窥探执行"工具：
识别 Seq Scan vs Index Scan、Nested Loop vs Hash Join、rows=估算与实际偏差——L12-14 全部机制的可视化界面。

## 5. 课堂经典反例（值得记住）
```sql
-- 想查"没有选课记录的学生"：三种写法三种命运
SELECT * FROM students WHERE id NOT IN (SELECT sid FROM enrollments); -- 有 NULL 则恒空！
SELECT * FROM students s WHERE NOT EXISTS (SELECT 1 FROM enrollments e WHERE e.sid = s.id); -- 反连接，正确
SELECT s.* FROM students s LEFT JOIN enrollments e ON s.id = e.sid WHERE e.sid IS NULL; -- 外连接+判空，等价
```
三种写法优化器大多归一成同一 Anti Join 计划（L11 的 index/data doubly nested loop 或 hash anti join）。

## 速记自检
- Q：SQL 与关系代数的三大语义漂移是什么？——A：bag(不去重)、NULL 三值逻辑、求值顺序由优化器定（§1.1/§1.3）。
- Q：`NOT IN` 子查询为何可能恒空？——A：子查询含 NULL 使比较结果为 UNKNOWN（§1.3）。
- Q：窗口函数与 GROUP BY 的本质区别？——A：前者不折叠行、每行带上下文；后者折叠成组（§1.4）。
- Q：M:N 联系如何落地？——A：连接表（L01）。
