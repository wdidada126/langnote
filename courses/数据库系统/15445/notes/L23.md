# L23 分布式 OLAP 数据库（Distributed OLAP / MPP / 云数仓与存算分离）

> 15-445/645 Fall 2023 · Lecture 23 · 阅读：Redshift / Snowflake 论文；课程讲义
> 分析型负载 = 扫海量数据、算聚合连接、结果小；解法是把数据切片并行扫（MPP），再进化到"存储和计算各自独立伸缩"的云上架构。

## 1. 核心概念

### 1.1 OLAP vs OLTP 回顾
OLAP：读多写少、大扫描、少并发、列存（L05）、需要高吞吐聚合/join（L10/L11）、并行度是命脉。延迟容忍（秒-分钟），但吞吐量巨大（TB/PB）。

### 1.2 MPP（Massively Parallel Processing）架构
- **Shared-Nothing 集群**：每节点自带 CPU+内存+本地磁盘，数据**分片（shard/segment）** 分布到各节点。
- 查询执行 = 分布式算子树：扫描在各节点本地并行，跨节点数据重分布用 **Exchange/Shuffle**。
- **数据分布策略（分布键选择）**决定 join 是否需要 shuffle：
  - **Hash 分布**：按 join key 哈希分布 → 同 key 在同节点 → **co-located join 零网络**（最佳）；
  - **随机/轮询**：写入均匀，join 要 shuffle；
  - **广播（broadcast）小表**：小维表复制到大事实表各节点 → 避免大表 shuffle（星型模型常见）。
- **Skew（倾斜）**：分布键选不好→某节点过载，长尾决定总时间；需重分布/两阶段聚合/加盐。

### 1.3 经典产品谱系
- **Teradata**（元老 shared-nothing MPP）；
- **ParAccel / Greenplum**（PG fork + MPP，planner 生成分布式计划）；
- **Amazon Redshift**：列存 + MPP + 分布式执行；**distkey/sortkey** 调优；早期基于 ParAccel；用中间结果落盘做大规模 shuffle。
- **Druid / ClickHouse / Pinot**：实时 OLAP/OLAP 引擎，预聚合 + 列存 + 向量化。

### 1.4 云数仓与存算分离（Disaggregation）
Redshift 的痛点：存储与计算绑死，扩缩必须一起动、冷热数据同价、并发隔离差。
- **Snowflake（弹性存算分离）**：三层解耦——
  1. **Cloud Services**（全局元数据/优化器/事务，独立）；
  2. **Multi-Cluster Compute**（无状态 Virtual Warehouses，秒级启停/伸缩、互不干扰）；
  3. **Shared Storage**（对象存储 S3/Azure Blob，微分区 micro-partition + 元数据统计，是"唯一真相"）。
  - 计算是**缓存层**：本地 SSD 缓存热微分区；无共享、按秒计费。
- **Aurora / Socrates（云原生 OLTP 的存算分离）**：把 redo 日志下推到共享存储层（"log is the database"），计算节点无状态、存储 6 副本跨 3 AZ。虽属 OLTP，但存算分离思想与 Snowflake 同源。
- **Databricks Lakehouse / Delta Lake / Iceberg / Hudi**：在对象存储上做"数据湖 + 仓库"融合——开放表格式（ACID on 数据湖、time travel = 数据侧 PITR），存算彻底分离，引擎（Spark/Photon/Trino）可插拔。

### 1.5 分布式查询优化点
- **分区裁剪（partition pruning）**：按分区键（常为时间）跳过不相关分片；
- **数据跳过（data skipping / min-max zone map）**：micro-partition 记录每列 min/max，谓词不符整块跳（Snowflake/Redshift sort key/Databricks）；
- **runtime filter / Bloom join 下推**：build 侧生成过滤器下推到 probe 侧扫描（减少 shuffle）；
- **cost model 要加网络项**：跨节点传输代价主导（L14 分布式扩展）。

## 2. 前后讲联系
把 L10-13（排序/聚合/join/向量化）在节点内执行、L14 优化器升级为"考虑分布与网络"、L05 列存成为默认。承 L21-22 分布式基础但目标从"事务一致性"转向"吞吐/弹性/成本"。存算分离对 L06 缓冲池的意义：对象存储替代块盘，本地 SSD 成了"二级缓冲池"。

## 4. 开源项目应用
- **Greenplum**：PG fork，`DISTRIBUTED BY` 选分布键、Motion 算子做 shuffle。
- **ClickHouse**：分片 + 副本，`Distributed` 表引擎跨分片扇出+合并；向量化+列存。
- **DuckDB**：单机 OLAP， morsel 并行；`DuckDB over HTTP` 读 Parquet 数据湖——轻量"存算分离"实验。
- **Trino/Presto**：联邦/存算分离查询引擎，对接 Iceberg/Hive；纯计算层。
- **Apache Iceberg / Delta / Hudi**：开放表格式（元数据 + Parquet/ORC 数据 + ACID 快照 + time travel），Lakehouse 基石。
- **Snowflake**（闭源，论文《The Architecture of Snowflake》）：存算分离旗舰。
