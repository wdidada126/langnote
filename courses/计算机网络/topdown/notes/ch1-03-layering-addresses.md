# 第 3 讲 · 分层模型、封装、地址与"一台 Web 服务器的一天"

> 章节：Chapter 1 | 对应教材：§1.3、§1.5、§1.7 + 在线补充（§1.8 历史/结构）
> 中文对照：topdown_ustc 第 1 章（分层与封装）

## 1. 核心概念

- **分层的服务定义**：每层向上一层提供 `service(n) = service(n-1) + 本层新增功能`，用协议实现"水平虚对话"，用 SAP（服务访问点）做垂直接口——与 OSI 七层对照，TCP/IP 实际是 5 层（应用/运输/网络/链路/物理）。
- **封装栈（全课总纲）**：
  - 应用：HTTP 报文 → 装入运输层段
  - 运输：TCP 段（+TCP 头 20B 起）→ 装入 IP 数据报
  - 网络：IP 数据报（+IP 头 20B 起）→ 装入链路层帧
  - 链路：帧（以太头 14B + FCS 4B）→ 物理层比特
  - 每一跳：链路层头**换掉**（MAC 改写），网络层头**不变**（TTL−1、校验和重算），运输/应用头**全程不变**——这是判断"谁在哪层动手脚"的黄金准则。
- **地址即"层间绑定"**：MAC（48 位、扁平、链路内）；IP（32/128 位、分层、可聚合）；域名（应用层、层次+扁平混合）。ARP 是 IP↔MAC 的桥（第 15 讲）；DNS 是 域名↔IP 的桥（第 6 讲）。
- **§1.7 一天的全景（必背叙事）**：浏览器输入 `google.com`：DNS 迭代/递归查询 → TCP 三次握手 → HTTP GET → IP/链路逐跳封装 → 服务器 nginx worker accept → 响应回程 → 握手挥手。把这门课 7 章串成一条时间线，每个环节都是对应讲次的入口。

## 2. 关键字段/结构

- 各层首部开销（以太+IPv4+TCP 裸头）：14+4+20+20 = 58B，最大载荷 1460B（MTU 1500 下）——**MSS = MTU − 40** 的由来（第 11 讲 TCP 选项再减）。
- 封装栈练习：一个 HTTP 请求经过以太网→Wi-Fi 时，外层帧格式改变但 IP/TCP 不变（第 21 讲）。

## 3. 层次间与前后讲联系

- 本讲给出全课的"坐标系"：第 2 章（应用层）→ 第 3 章（运输层）→ 第 4/5 章（网络层数据/控制平面）→ 第 6/7 章（链路与无线）。
- "端到端原则"在本讲首次埋下：可靠/加密/序号都放在端系统（运输层），网络核心只给"尽力而为"——这是 TCP/IP 与 ATM 路线之争的胜负手。

## 4. 跨课程联系

- **CSAPP**：`read/write` 系统调用就是应用→运输层的 SAP；CSAPP 第 11 章网络编程与本讲"一天"互证。
- **CS144**：其 reassembler + router 实验让你分别实现"运输层字节流抽象"和"网络层存储转发"，正对应分层边界。
- **6.S081/CS162**：Linux 内核 `sk_buff` 结构横跨各层——一次 `ip_send_skb` 到网卡 DMA，即封装栈的物理执行；`netif_receive_skb` 则是解封装。
- **MIT6.824**：RPC 被封装为"应用层消息→TCP"，6.824 lab2 的可靠性讨论直接呼应端到端原则。
- **topdown_ustc**：郑烇老师"寄快递：面单层层贴/换"类比封装。

## 5. 开源项目应用

- **Wireshark**：同一分组在捕获里显示为 `Frame→Physical→Ethernet→IPv4→TCP→HTTP` 树，就是分层服务视图；Follow TCP Stream 提取运输层以上不变部分。
- **Nginx/Envoy**：应用层服务器，但 Envoy 把 L3.5/L4/L7 分类（HTTP/1 与 HTTP/2 代理、连接池）做成产品化抽象。
- **Linux**：`tcpdump -i eth0 'tcp port 80'` 的过滤器语法即封装栈各层偏移的 DSL（BPF）。
- **io_uring**：把"系统调用边界"（应用↔内核 SAP）做成共享环形队列，是本讲分层思想的性能极限改造。

## 7. 自查问题

1. 路由器转发时改了哪几个字段？没改哪些？（TTL、IP 校验和、外层 MAC；TCP/HTTP 不变）
2. 为什么需要 IP 又有 MAC？去掉其中一个会怎样？（分层寻址 vs 本地交付；联系第 15 讲 ARP）
3. 以太+IPv4+TCP 的最小帧与 MSS 关系？封装 VLAN tag 或 TCP timestamp 后 MSS 怎么变？
4. "一天"时间线里，DNS、TCP 握手、HTTP GET 各产生几个 RTT？首字节总时延如何估算？（联系 §2.2 对象获取时间）
5. 端到端原则反对在网络核心放什么功能？ATM 与 TCP/IP 之争的结果给了什么启示？

## 9. 记忆卡（考前 30 秒过一遍）

- 5 层模型：应用—运输—网络—链路—物理；PDU 依次：报文—段—数据报—帧—比特。
- 不变量：TCP/应用头端到端不变；可变量：链路头逐跳重写、TTL/校验和逐跳更新。
- 三套地址：域名(应用)、IP(网络, 分层)、MAC(链路, 扁平)；两把桥：DNS、ARP。
