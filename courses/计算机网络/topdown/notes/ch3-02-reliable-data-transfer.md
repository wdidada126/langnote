# 第 10 讲 · 可靠数据传输原理：rdt0 → rdt3.0、GBN 与 SR

> 章节：Chapter 3 §3.4（穿插 §3.3 末"可靠传输原则"）
> 中文对照：topdown_ustc 第 3 章（可靠传输原理）；配套项目 projects/ch3_arq

## 1. 核心概念

- **rdt 问题设定**：在不可靠信道（比特错、丢包、乱序）上构造面向应用的可靠通道。工具三件：**校验和（检错）、序号（辨重/乱序）、超时+重传（补丢）**。
- **演化阶梯（状态机必须能手推）**：
  - rdt0：理想信道，发送 `send(data)` / 接收 `receive()`。
  - rdt1.0：信道可靠但可能错——停等 + 校验和 + **ACK/NAK**（接收方 checksum 错则 NAK，发方重传；正确则 ACK 并递送）。
  - rdt2.1/2.2：ACK/NAK 本身可能出错 → 序号必须加到数据包；**用序号+期望序号丢弃重复包**；rdt2.2 把 NAK 消灭（NAK 用"带旧序号的 ACK"表达），状态机更对称。
  - rdt3.0：数据或 ACK 可能丢 → **双方各设定时器**；发方超时重传当前包，收方超时"重发上次的 ACK"；正确性依赖序号 0/1 交替——这就是"停等 ARQ"。
- **流水线的动机**：停等利用率 = `min(1, d_trans/(RTT+d_trans))`；BDP>0 时永远 <100% → 允许多个未确认包（窗口 w）。
- **GBN（回退 n 帧）**：累积确认（ACK n 表示 ≤n 全收到），发送窗 w，接收窗 **1**；任何空洞 ⇒ 全部重发。适合"丢包少、乱序≈丢包"的无线前向场景（教材对比）。
- **SR（选择重传）**：发窗=收窗=w，**每个包独立 ACK（SACK 思想前身）**，乱序包暂存接收窗、按序交付；窗口 ≤ 序号空间/2（否则旧新副本歧义——协议设计的经典"绕圈"论证）。
- **超时管理**：RTO 不能凭感觉——第 11 讲 Jacobson/Karels 估算法；重传计时器与保活计时器分离。

## 2. 关键状态机/字段

- rdt2.1 发送方：`FS0 --[send pk0; start timer]--> 等待ACK/NAK/超时`，接收方用 `rsr`（最近收到的期望序号）决定重发哪个 ACK。
- 滑动窗口不变式（TCP 同款）：`sendbase ≤ seq < sendbase + w`；GBN 只有 sendbase 移动，SR 每个 acked 都移动左沿条件不同。

## 3. 层次间与前后讲联系

- 本讲是 TCP 的"概念脚手架"：TCP = rdt3.0 + 流水线 + 累积/SACK + 定时估计 + 流控 + 拥塞控制（第 11 讲逐一叠加）。
- 与第 9 讲：可靠是端系统职责；与第 8 讲 WebRTC/QUIC 用"每流独立恢复"实现 SR 精神。
- 与第 20 讲链路层：以太网不重传（丢弃交给上层）、802.11 却在链路层做逐跳 ARQ——"可靠该放哪层"的反例对比。

- **MIT6.824**：lab 里的"至少一次/至多一次/恰好一次"语义、幂等 RPC 与本讲 rdt 严格同构；6.824 把超时重传放进应用层，是端到端原则的分布式版。

- **topdown_ustc**：rdt 状态机中文逐帧动画，最适合第一次看懂 2.1→2.2 演化。

## 5. 开源项目应用

- **Linux 内核 TCP**：`net/ipv4/tcp_input.c` 的 `tcp_ack`（累积确认+乱序队列 `out_of_order`）与 `tcp_write_xmit`（重传）——读源码时带着本讲术语表看。
- **quiche/s2n-quic**：QUIC 明确 SR 风格（每 packet 可单独 ACK，帧按流重组），与本项目 ch3_arq 的 SR 模拟直接对应。
- **Wireshark**：观察"TCP window update 里的 dup ACK"理解快重传前提（第 11 讲）；`tcp.analysis.retransmission` 过滤器。
- **iperf3**：`-w` 调窗口演示停等 vs 流水线利用率差异。

## 8. 本讲一句话

可靠传输没有魔法：校验和负责"发现错"，序号负责"分清是谁"，超时负责"补回丢的"——窗口只是把这三件事并行化。
