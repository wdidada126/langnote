# L11 虚拟内存 II：写时复制 fork（vm2 / Copy-on-Write）

> 6.1810 Lecture 11 · 阅读：xv6-mm/lab cow 材料；Ritchie & Thompson《The UNIX Time-Sharing System》(1974)
> Lab: cow——给 xv6 的 fork 加 CoW，这是全课最经典的"小改动大收益"练习。

## 1. 核心概念

### 1.1 fork 的浪费
xv6 主线 fork：`uvmcopy` 把父进程每个页复制一份——但 exec 紧跟其后就把新页表全扔掉，
复制几乎纯属浪费。1974 年 Unix 用"每页引用计数 + 只读共享"解决；现代实现全部采用 CoW。

### 1.2 CoW 协议（一页视角）
1. fork：父子页表把同一物理帧都映射为**只读**（PTE_R=1, PTE_W=0），帧引用计数 +1；
2. 任一方写 ⇒ 缺页（store fault）；内核查计数：
   - 计数 >1：复制新帧，写者独占，计数 -1；
   - 计数 =1：说明是"自己写自己的最后一页"，直接把 PTE 改回可写（免复制，lab-cow 的加分细节）；
3. 读 fault 不触发复制；`mmap(MAP_PRIVATE)` 与 vfork/CLONE_VM 是同一机器的变体。

### 1.3 页表即状态机
CoW 的难点全在边界：fork 中途被杀（半复制状态要能清理）、栈增长与写撞车、
设备 DMA 绕过页表写内存（所以共享帧的设备缓冲不能 CoW）。
教学结论：**页表不只是翻译表，它是内存所有权的账本**。

### 1.4 引用计数放哪里
帧只有 64 位 PPN，塞不下计数 ⇒ 内核维护 `struct page`/kmap 元数据表（每帧一项）；
xv6-lab 用"karray + refcount"思路，Linux `struct page._refcount` 即其工业版。
不用计数行不行？——RCU/epoch 回收（L15）给出了并发场景的替代答案。

### 1.5 安全推论
撤映射时为什么必须 `uvmclear`（清零）？共享帧上残留的父进程数据会泄漏给子进程/下一任主人。
L03 的隔离承诺在 VM 层兑现：任何页换手都过"擦除"这道门。

## 2. xv6(lab-cow) 代码走读要点
- `kernel/proc.c: fork()`：目标形态——`uvmcopy2`/`duppage` 把父 PTE 复制给子且双双去 W 位。
- `kernel/vm.c`：需要新增 `walk` 暴露 PTE 指针 + 帧引用计数操作（`pagecount/inc/decref`）。
- `kernel/trap.c: usertrap()` 缺页入口：`uvmfault` 要能识别 CoW fault：walk 发现 PTE 有效但缺 W，且 `scause` 是 store ⇒ 复制/转正。
- `kfree` 时机：计数归零才还给 freelist——lab 的 `cowstress/cowtest` 专测"中途 kill + 计数泄漏"。
- 检查点：`exec` 时旧页表 `uvmunmap(kernelpgtbl)` 会递减计数，栈页复制给 trapframe 的路径别漏计。

## 3. 跨课程联系
- **CSAPP（Ch.9.8）**：CSAPP 提了一句"fork 用 CoW"，本讲是其完整实现；Ch.10 的 mmap 私有映射实验与之呼应。
- **DDCA/CS61C**：store fault 需要 MMU 精确报告写违例（cause 15 vs 13）——硬件异常分类学决定了协议可行性。
- **NJUOS/CS162/HITOS**：rCore/nCore 把 CoW 写进类型安全的 fork 测试；HITOS 对比 Linux `fork` 的 VMA 复制（`vm_area_struct` 树克隆）与页级延迟复制两层结构；CS162 提供"复制 vs 共享"的量化权衡框架。
- **MIT 6.824**：快照/分离（split-brain）里没有 CoW，但"版本分叉点"的叙事一致：分叉时不复制，改动时才分化——分支版本系统（git）同理。

## 4. 开源项目应用
- **Linux**：`mm/memory.c: do_wp_page` 即 CoW fault 处理；`copy_page_range` 建"只读共享"初始态；`userfaultfd` 把缺页处理开放给用户态（VM 热迁移/Postcopy 靠它）。
- **gVisor**：Go 实现 CoW 页表，测试用例 `cow` 家族与 lab-cow 神似。
- **Firecracker**：快照恢复 = 写时复制的存储级应用（chunk 按需从快照文件装入）。
