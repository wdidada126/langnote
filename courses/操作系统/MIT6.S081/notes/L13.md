# L13 USB 驱动（USB）

> 6.1810 Lecture 13 · 阅读：xv6 kernel/usb.c（部分驱动）；USB 规范概览节选
> "最难的内核代码"讲：为什么插一个鼠标要穿过整整一个协议栈。

## 1. 核心概念

### 1.1 USB 是一棵树 + 一套枚举契约
主机（host）独占总线控制权，设备是被动应答者。拓扑：root hub → hub → 设备，
每层地址由拓扑决定：热插拔 ⇒ 主机用**枚举**现场发地址（SET_ADDRESS）、读描述符。

### 1.2 描述符：设备的自述文档
设备描述符 → 配置 → 接口 → 端点（endpoint）。端点是传输的"管道口"，四类型：
控制（枚举/命令）、批量（大容量存储）、中断（鼠标键盘：实为轮询保证延迟）、等时（音频：丢帧也不重传）。
描述符链是"类驱动自动装配"的数据基础——插入设备后 OS 扫描 → 匹配驱动。

### 1.3 主机控制器：OHCI→EHCI→xHCI
USB 协议与控制器实现解耦。xHCI（3.0）统一全速/高速/超速，环形命令/传输队列 +
中断票（MSI）——设计上趋近 NVMe/virtqueue 的多队列风格。驱动最难的部分全在控制器层。

### 1.4 存储与键盘：类驱动（class driver）
USB 存储（bulk-only/BOT）：批量端点上传输 SCSI 命令——USB 磁盘 = SCSI over bulk pipe。
HID 类：报告描述符自描述按键位图，驱动按报告解析。
"类驱动"让 OS 不用为每个型号写代码，这是 USB 成功的一半。

### 1.5 为什么驱动 bug 多
协议 600+ 页、设备不守规范（微软承认过）、热插拔竞态、固件被攻击面化
（BadUSB、DMA 攻击，接 L17/L18 的安全线）。USB 是内核里"复杂度债"最重的子系统之一。

## 2. xv6 代码走读要点
xv6-riscv 主线没有完整 USB；QEMU virt 无 USB 时课程以"读 Linux USB 代码 + 讲义"完成本讲。可走读的替代样本：
- `kernel/usb.c`（部分年份/分支）：枚举流程骨架——GET_DESCRIPTOR → SET_CONFIGURATION → 找 HID/STORAGE 接口。
- `drivers/hid/usbhid`（Linux 对照）：probe/disconnect 生命周期、报告解析。
- 回到 xv6 主线对照：uart 是"无协议设备"的极限简化；virtio 是"合作设备"的极限简化；
  USB 站在两者对面——"与不合作且会拔掉的陌生人对话"。

## 3. 跨课程联系
- **DDCA/CS61C**：总线仲裁、DMA、中断共享（线或）概念在这里全数登场；USB 是"串行化 ISA 总线"的现代样本。
- **CSAPP**：无直接对应；本课补上"通用总线协议栈"这一系统栈空白层。
- **NJUOS/CS162/HITOS**：NJUOS 选修涉及 USB 主机栈（xhci crate 社区实现）；HITOS 讲 Linux USB 子系统的 Urb 异步请求模型与"驱动核心 vs 主机控制器驱动 vs 类驱动"三层；CS162 视角：设备生态的复杂度如何反向塑造 OS 内核（Windows Plug and Play 史）。
- **MIT 6.824**：枚举/协商 ↔ 服务发现/心跳；描述符 ↔ 接口 IDL；"对不可靠伙伴建模"是共同主题。

## 4. 开源项目应用
- **Linux**：`drivers/usb/core`（枚举/urb）+ `host/xhci-hcd.c`；`lsusb -t` 即活教材；USB 攻击面催生 `usbguard`。
- **Zephyr/tinyusb**：设备侧协议栈（device mode）只有 Linux host 栈 1/50 规模，适合读懂"描述符驱动一切"。
- **seL4**：驱动跑在用户态 server（sDDF 框架），USB 热插拔的"拔掉即崩溃"问题被隔离边界兜住。
