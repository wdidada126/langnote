# L16 虚拟化（Virtualization）

> 6.1810 Lecture 16 · 阅读：讲义 + Xen/VMX 文档节选；Lab: vm（给 xv6 写 hypervisor）
> 当 OS 虚拟化硬件，谁来虚拟化 OS？本讲把 L03 的隔离模型再抬高一个维度。

## 1. 核心概念

### 1.1 三种实现方式：陷阱-模拟 / 直接执行 / 硬件辅助
- **经典虚拟机监视器（Goldberg）**：VMM 运行在最高特权级，客户内核的特权指令陷入模拟—— Popek & Goldberg 可虚拟化定理：敏感指令集合 ⊆ 陷入指令集合则"纯软件可虚拟"。
- **直接执行（direct execution）**（Ungar et al., "SPLOIT"，SOSP'84，出处待核实）：让 guest 直接跑用户级代码，特权操作才进 VMM 模拟——快，但要求 guest 可改写。
- **硬件辅助**：x86 VT-x（root/non-root 模式 + VMCS 状态包），ARM EL2，RISC-V H 扩展（hs-mode + vs-mode + VS 页表）——把"陷入"做成一条指令的成本。

### 1.2 影子页表 → 二维翻译
guest 管"GVA→GPA"，host 管"GPA→HPA"。早期 VMM 用影子页表合成一张 GVA→HPA 表（写保护 guest 页表捕获修改，昂贵）。
硬件解法：x86 EPT / RISC-V 两阶段翻译（`hgatp`）——每次访存走两级页表，硬件缓存（TLB 带 ASID/VMID 标记）。
lab-vm 的 satp 重定向正是在软件里模拟这个"二维 walk"。

### 1.3 设备虚拟化：全模拟 → 半虚拟化 → 直通
- 全模拟（QEMU 的 IDE）：兼容但慢；
- 半虚拟化（virtio，L12 已见）：guest 知情合作，云主流；
- 直通（VT-d/IOMMU + SR-IOV）：设备 DMA 经 IOMMU 限制在 guest 物理地址空间，性能≈裸金属，迁移困难。
Firecracker/Cloud Hypervisor 把 virtio 设备模型 Rust 化 + 极简（一 virtio-net/blk/串口）。

### 1.4 嵌套与容器
嵌套虚拟化（guest 里再跑 VMM）是硬件扩展的镜像递归。
容器（namespace+cgroup）不是虚拟化：共享内核换启动速度与安全边界——
gVisor/Firecracker 正是填"容器隔离不够、VM 太重"的中间层（接 L17 安全线）。

### 1.5 成本账
VM-exit 一次 ~μs 级：时钟中断、CPUID、HLT、EPT violation 都会"出去一趟"。
KVM 把 VMM 做成内核模块 + QEMU 用户态设备模型；开销大头在 I/O 与内存热路径——
所以出现 vhost（内核态 virtio 后端）、vDPA、内存 balloon/swap 协同（与 L10 呼应）。

## 2. xv6(lab-vm) 代码走读要点
- lab-vm 的 `vmm.c: run(first, vmenter)`：hs-mode 内核加载 vs-mode guest；guest `ecall` 陷入后按调用号转发——"trap and emulate"最小系统。
- `two_phase_translate`：手写"guest 页表 walk + host 页表 walk"，即 EPT 的软件版；理解后看 `hgatp` 规范会非常快。
- guest 的 `stvec/satp` 与 hypervisor 的 `vstvec/vsatp` 切换清单：RISC-V H 扩展在 `sstatus.SPV/VS` 位上的状态机。
- 时钟中断注入：hypervisor 收到 tick 后"伪造"给 guest 的 `sip`——虚拟化的本质=状态拦截+替身呈现。

## 3. 跨课程联系
- **CSAPP（Ch.9）**：进程/地址空间/系统调用三抽象在 VM 下复制一套（GPA 就是"VM 的地址空间"）——递归抽象观。
- **DDCA/CS61C**：特权级/异常向量是 ISA 特性，本讲展示 ISA 设计者如何为"另一个 OS"让路（Popek-Goldman 定理是体系结构课的标准附录）。
- **MIT 6.824**：云 = VM 池 + 分布式调度；Raft 日志复制跑在 VM 之上，崩溃模型多了"宿主机整体宕机"一层。
- **NJUOS/CS162/HITOS**：NJUOS 有"运行在 hypervisor 上"实验传统（Linux 跑在 rCore/Coq 上，即 xv6 lab 同思路）；HITOS 讲 KVM 架构；CS162 提供侧信道（Spectre/Meltdown）时代虚拟化的安全重审。

## 4. 开源项目应用
- **KVM/QEMU**：内核侧 `arch/riscv/kvm/vm.c` 的 vsatp/hgatp 管理，用户侧设备模型；`virsh`/libvirt 运维面。
- **Firecracker/Cloud Hypervisor**：AWS Lambda/Serverless 底座；Rust、最小设备集、热迁移（ch 支持），读它的 README 等于本讲复习。
- **seL4/Xen**：seL4 本身就是 micro-VM 式隔离；Xen 仍在云上占一席（dom0 模型与 "PV vs HVM" 正是本讲两种路线的活化石）。

## 6. 自检测验
- Popek-Goldberg 三条件：历史 x86 的哪些敏感指令违反了它，补丁思路是什么？
- EPT 两层翻译（GVA→GPA→HPA）：TLB 条目要 tag 什么？VM-entry 为什么贵？
- 设备直通时 IOMMU 保护谁？MSI 重映射缺了会开出什么攻击面？
- KVM 内核内 VMM vs Firecracker 最小设备模型：各自的性能与攻击面账本？
- 全虚拟化→半虚拟化→SR-IOV 直通：分别绕开了哪一层模拟开销？
- 把 CPU/内存/IO 三维虚拟化各写一个"退出/影子页表/环形队列"最小闭环示例。
