# L03 隔离与地址空间（Space）

> 6.1810 Lecture 3 · 阅读：xv6 book Ch.3–4；讲义主题 "space"
> 本讲是全课世界观宣言：操作系统 = 用硬件隔离机制搭起来的"受保护的多程序虚拟机"。

## 1. 核心概念

### 1.1 隔离是第一公民
没有隔离，程序一个空指针就能改写别人内存、一个 `out` 指令就能接管机器。
OS 的核心职责是把**不可信的用户代码**关进笼子，只留一扇受控的门（系统调用）。
虚拟化（分时、swap）是锦上添花，隔离才是安全边界——这个立场贯穿后半程的
separation/exceptions/virtualization 各讲。

### 1.2 硬件给的两块基石
1. **特权级**：RISC-V U/S/M mode（x86 ring 3/0）。用户态执行不了 `sfence.vma`、改不了页表基址 `satp`、访问不了设备 MMIO。
2. **地址翻译**：MMU + 页表，让每个进程拥有独立的"地址宇宙"。虚拟地址空间 = 隔离单元 = 调度单元（进程）。

### 1.3 进程地址空间的解剖
xv6 用户空间自低向高：text（只读可共享）→ data/bss → heap（brk 增长）→ 栈（向下生长，sp 之下留 guard page）→ trap 帧。
内核空间与每个进程页表**共享同一份内核映射**（直接映射物理内存 + 设备区），
这样陷入内核不用切页表——代价是用户态一旦能伪造 `satp` 就全盘皆输（L16 虚拟化再谈）。

### 1.4 系统调用 = 跨隔离边界的受控通道
调用约定：参数放 `a0–a5`，调用号放 `a7`，`ecall` 陷入；内核检查号、拷贝参数、执行、把返回值写回 `a0`，`sret` 回去。
设计原则（Unix 遗产）：接口窄、语义稳、机制策略分离。fork/exec/wait 三个调用就能组合出任意程序结构——"组合性"来自接口正交。

### 1.5 Unix 视图回顾（承 L02 的 lab-shell）
fork 复制地址空间、exec 换掉地址空间、wait 收尸——"进程创建"被拆成"复制"与"替换"两步，
这是 Unix 对 OS 接口史最大的贡献之一；shell 用管道把两个进程的 stdout/stdin 接在同一条 pipe 上。

## 2. xv6 代码走读要点
- `kernel/defs.h` + `kernel/proc.h: struct proc`——`pagetable`、`killed`、`x[]`（trap 时保存的寄存器组）是隔离的账本。
- `kernel/vm.c: uvmalloc()/uvmclear()/uvmdeallocate()`：给用户空间建页；`kvmalloc()` 只给内核直接映射。
- `kernel/entry.S`/`kernel/start.c`：内核链接在 `0x80200000`（高地址），用户页表里内核映射从 `0x80000000` 起——`walk()` 时用户 VA 命中内核映射是设计使然。
- `kernel/elf.c: loadok/loaduvm/loadtext`：exec 时校验 ELF、按程序头段建页——地址空间是"造"出来的，不是"有"的。

## 3. 跨课程联系
- **CSAPP（Ch.9 为主）**：CSAPP 画的"堆向上栈向下"图在这里变成 `uvmalloc` 的真实代码；Ch.7 链接视角下 exec 即"运行时加载器"。
- **DDCA/CS61C**：MMU/TLB 的硬件 datapath 在两门课出现；本讲补上"为什么翻译表必须每进程一份"的安全论证。
- **NJUOS/CS162/HITOS**：NJUOS 第一课同样以"地址空间 + 特权级"开篇（rCore 的 `MemorySet` 抽象更干净）；CS162 用量化语言重述保护与虚拟化的收益；HITOS 讨论工业内核里 KASLR、页表隔离（KPTI）如何演进这一隔离模型。
- **MIT 6.824**：分布式系统用网络分区与副本处理"进程会死"；单机隔离处理的是"进程会作恶"——信任模型完全不同，值得对照。

## 4. 开源项目应用
- **Linux**：`mm/mmap.c` 的 `vm_area_struct` 是地址空间的工业账本；`arch/riscv/mm` 的 swapper 页表与 xv6 `kvminit` 同构；KPTI 说明"共享内核映射"在侧信道时代需要补丁。
- **seL4**：把"隔离"作为唯一原语（CNode + 地址空间对象），xv6 的进程模型是其一个粗糙特例。
- **gVisor/Firecracker**：容器/无服务器场景下用用户态内核或轻量 VM 重新实现"进程级隔离"，思想源头即本讲。

## 6. 自检测验
- 没有 MMU 只有特权级，能做出"进程互不干扰"吗？说出缺了哪一半。
- 用户页表里为什么同时存在内核映射？这个设计的两个直接受益点和一个风险点。
- fork 与 exec 各自"动"了地址空间的哪部分？哪个可以完全不改页表内容只换指针？
- 把 trapframe 放在用户页表里（xv6 做法）而不是内核栈帧上，换来了什么、赌上了什么？
- 进程切换 = 换 satp + 换 sp + 换状态字：指出 scheduler 里各由哪几行完成。
- 为什么 kill 只置 `killed` 标志而不能立即回收资源？给出一个"立即回收"会崩的场景。
- 对照 CSAPP：xv6 的 `proc` 表相当于 CSAPP 里哪一抽象的操作系统"正解"？
