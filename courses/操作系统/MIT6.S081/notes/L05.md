# L05 系统调用（System Calls）

> 6.1810 Lecture 5 · 阅读：xv6 book Ch.5；kernel/syscall.c、trap.c；Lab: syscall（部分年份）
> 一次 `getpid()` 的完整旅程：ecall → trap 帧 → 分发表 → 返回。这是用户与内核的"边境检查站"。

## 1. 核心概念

### 1.1 trap 与中断的统一入口
RISC-V 里异常（除零、页错误）、中断（时钟、设备）、陷入（`ecall`）都跳到 `stvec` 指向的处理程序，
由 `scause` 区分来源。xv6 的 `usertrap()`：`scause==8` 且来自用户态 ⇒ 系统调用；否则按异常杀进程。

### 1.2 调用约定与寄存器保存
用户把调用号放 `a7`、参数放 `a0–a3`（最多 4 个，超过要传指针）。
陷入时硬件只保证 PC/状态寄存器（`sepc/sstatus/scause/stval`）被保存，
通用寄存器必须由软件全部压入 `p->trapframe`——"保存多少寄存器"是性能与正确性的直接交换，
这也是 lab-traps（用户级中断）里 perfcounter 一类的优化空间所在。

### 1.3 参数传递的安全协议
内核绝不能直接解引用用户指针：`argint/argptr/argstr/fetchstr` 通过 `addr_ok()` 检查 + `copyin` 拷贝，
把数据复制进内核栈上的本地变量。文件名这类字符串还要在 `namei` 前完成拷贝（用户可能并发修改）。
返回值经 `p->trapframe->a0` 写回；出错时返回 `-1` 并把 `errno` 放进 `a1`（xv6 约定）。

### 1.4 syscall 的性能账
一次 syscall 的成本 = trap 进出 + `sfence.vma`（若换页表）+ 参数拷贝。
x86 的 `syscall/sysret` 快路径、Linux `vDSO`（gettimeofday 免陷入）、io_uring 批量提交，
全部源于"高频小调用太贵"这同一动机——与后文 L20 IPC、L21 网络 fast path 一脉相承。

### 1.5 典型系统调用的实现姿势
- `fork`：复制整个地址空间（duppage，见 L11 CoW）。
- `exec`：造新页表 + 加载 ELF + 复用 trapframe 里的 argc/argv 传递。
- `wait`：睡眠在 `p->channel` 上直到子进程 `setrunnable`——sleep/wakeup 协议的标准应用。
- `exit`：释放资源 + 变成 ZOMBIE 等父进程收尸（保留 exitcode）。

## 2. xv6 代码走读要点
- `user/usys.S: syscall()` 宏：`li a7, NR_xxx; ecall`——每个用户 stub 两条指令。
- `kernel/syscall.c: syscall()`：`which > sizeof/syscallvec` 越界检查后 `(*syscallvec[which])()`；`syscallret()` 处理 `do_kill` 与 `a0` 写回。
- `kernel/trap.c: usertrap()`：切 `stvec` 到内核向量（内核态中断不再回 trap）、处理时钟中断触发调度（`yield`）。
- `kernel/trap.c: dev_trap/kerneltrap` 与 `picintr`：设备中断的入口，L06/L12 驱动讲会回来。
- `kernel/sysproc.c: sys_exec`：`exec` 失败时"旧地址空间原样保留"是易错点——先建新表、成功才换 `p->pagetable`。

## 3. 跨课程联系
- **CSAPP（Ch.8/10）**：CSAPP 的 fork/exec/wait 系统级 IO 章在这里看到内核侧实现；`readn/writen` 处理的短读短写正是内核可能提前返回的结果。
- **DDCA/CS61C**：trap 向量表、CSR 属于 ISA/微架构内容；CS61C 讲"异常 = 流水线 flush + 跳表"，xv6 展示软件侧一半。
- **NJUOS/CS162/HITOS**：NJUOS 用 S-mode trap + `S-mode syscall`（编号约定与 Linux 一致，xv6 自编表）；Linux 的 `entry_SYSCALL_64` 汇编 + `sys_call_table` 与本讲逐行对应；CS162 强调 syscall 开销在虚拟化下的放大（VM-exit 再陷一层）。
- **MIT 6.824**：RPC 是"跨机器的系统调用"——xdr 序列化 ≈ copyin 参数打包，超时重试 ≈ 中断重放。

## 4. 开源项目应用
- **Linux**：`arch/riscv/kernel/sys_riscv.c`、`kernel/entry/syscalls/syscall.tbl` 生成 `sys_call_table`；`ptrace`/`seccomp` 在 syscall 边界做策略（L17 安全讲复用）。
- **FreeRTOS/Zephyr**：没有 syscall——全部 API 是同地址空间函数调用；对比理解"隔离与否"的代价。
- **gVisor**：用户态内核拦截 syscall 重实现，说明这个接口边界宽到足以承载一个完整 OS 语义（也宽到可被攻击，见 CVE 史）。
