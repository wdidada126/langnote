# L19 物理内存分配（Physical Memory Allocation）

> 6.1810 Lecture 19 · 阅读：讲义 + DAGT/Holistic Memory Management 论文；Lab: malloc 传统（旧版 xv6 lab）
> 页表解决"地址去哪"，本讲解决"帧从哪来"——两级分配器（buddy+slab）是现代内核的地基。

## 1. 核心概念

### 1.1 帧分配器的约束
物理帧必须**连续、对齐、不能换出**（页表本身存在内存里——自举问题），
且申请/释放要快（缺页路径上每一纳秒都算）。所以内核分两层：
页帧分配器（page allocator，粒度=页）+ 通用分配器（kmalloc/slab，粒度=8B–几KB）。

### 1.2 first-fit 与碎片
xv6 的 `kalloc/kfree`：单链表 free list，`kfree` 把页挂回链头（LIFO 利于缓存但链表无序）。
first-fit 外碎片：100 个空闲页分散在 101 个空洞里，2 页的分配照样失败。
教学版分配器（projects/alloc）会量化这个现象：内部碎片=凑整浪费，外部碎片=空洞浪费。

### 1.3 buddy：用对齐换合并
把空闲页按 2^k 分桶（order），分配时向上取整找最小桶、必要时"劈半"；
释放时查伙伴（同桶、地址差恰为块大小、且空闲）即合并——O(1) 消灭大部分外碎片。
代价：平均内部碎片 25%（2 的幂凑整）。位图/桶链 + `find_first_zero` 是标准实现套路。

### 1.4 slab：对象级缓存
内核对象（proc 结构 200B、task 结构）成千上万同尺寸反复生灭。
slab 分配器：按"缓存（cache）"预留整页，页内切成对象数组，free 对象挂回 per-cache 链表——
分配 = 摘链表头（一条指针），零碎片、构造/析构可复用（Linux 还支持 redzone 调试/POISON）。
kmalloc 就是"若干固定 size-class 的 slab 组"。

### 1.5 研究前沿：分配器=系统级资源编排
- NUMA/CXL：分配决策掺入带宽/距离（interleave、local-first）；
- 异构 CPU（DAGT, ISCA 2022）：页的访问温度决定放 E-core 还是 P-core 附近——分配器成了功耗旋钮；
- 透明大页/KSM：以分配粒度换 TLB 与内存去重收益。
讲义选 DAGT 正是要说明：一个 1973 年的老算法今天仍是活跃研究对象。

## 2. xv6 代码走读要点
- `kernel/vm.c: kinit()/kfree()/kalloc()`：`kmem` = freelist 头 + 自旋锁；`kfree` 里 `memcheck` 越界检查——分配器是内核里最好的 bug 探测器。
- 帧元数据去哪了？xv6 没存（直接映射让 PA↔VA 平凡互换）；Linux `mem_map[]`/`struct page` 每帧 64B 元数据——buddy 的 order 桶需要它。
- `proc.h: struct proc` 永远从 `allocproc()` 的固定池来（xv6 是静态数组）——这就是"手工 slab"。
- lab-util/自加：把 `kalloc` 换成 buddy，跑 `cowstress` 看分配失败率与 `kfree` 合并计数。

## 3. 跨课程联系
- **CSAPP（Ch.9 malloc/dynamic memory）**：CSAPP 的 9.9 分配器实验（9.9 题）与本讲 first-fit/buddy/segregated 完全同源——CSAPP 教你写，本讲教你内核为何那样写。
- **DDCA/CS61C**：DRAM 行缓冲/页面命中延迟模型解释"分配器关心物理连续性"的硬件动机；TLB reach（页大小×条目数）回扣 L04。
- **MIT 6.824/15445**：15445 BufferPool 的 replacement + frame pin 是"数据库自带帧分配器"；6.824 不涉及但"租约/水位"式资源管理同构。
- **NJUOS/CS162/HITOS**：rCore/nCore 用 buddy（`memory::allocator`）；HITOS 深讲 Linux buddy+slub+CMA/DMA 池与内存回收水位线；CS162 的"内存是另一种 IO 设备"框架。

## 4. 开源项目应用
- **Linux**：`mm/page_alloc.c`（buddy 分区分带 migrate-type）、`mm/slub.c`；`perf` 的 `compact_stall`/`page_alloc` 事件即本讲可观测性。
- **jemalloc/mimalloc**：用户态 size-class + arena 分片，与 slab 思想平行演化；多线程扩展（per-CPU 缓存 → 无锁队列）接 L15 RCU。
- **FreeRTOS/Zephyr**：`pvPortMalloc` 提供 heap_1..heap_5 五档（从只增到合并式）——"分配器谱系"的嵌入式全收藏。

## 6. 自检测验
- first-fit 外部碎片从哪来？checkerboard 场景里空总量充足为什么仍分配失败？
- buddy 合并的"伙伴"判定（同阶、地址相邻、来自同一 split）如何用一条异或完成？
- buddy 内部碎片平均约 25%：这个常数从什么分布假设来？
- 为什么 buddy 之上还要 slab？对象数组的 cache 行对齐由哪层负责？
- xv6 kmem 单 freelist+自旋锁的瓶颈在哪？per-CPU page cache 收益与回收集结如何权衡？
- 用 projects/alloc 的 bench 画碎片率随负载时长曲线，解释 first-fit 与 buddy 分岔点。
