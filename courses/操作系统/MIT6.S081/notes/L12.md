# L12 磁盘与设备驱动（Disk Drivers / virtio）

> 6.1810 Lecture 12 · 阅读：xv6 book Ch.9 驱动节；kernel/virtio_disk.c、plic.c、uart.c
> Lab:（部分年份）无；本讲开始"内核之下"的世界：MMIO、中断、DMA。

## 1. 核心概念

### 1.1 设备即内存
现代设备通过 MMIO 寄存器暴露控制面（QEMU virt 机器上 UART 在 `0x10000000`）。
CPU 读写这些地址 = 操作设备；RISC-V 页表用 PTE_P/G/A 之外的设备属性位/
`sfence`+非缓存映射处理"地址不是 RAM"的问题（MMIO 必须 uncached 且不可重排）。

### 1.2 PLIC 中断路由
多设备中断先进平台级中断控制器（PLIC）：每台设备一个 source id，PLIC 汇总、
按优先级/目标 hart 投递外部中断（`scause` 高位=1）。xv6 的 `devintr()`：
先看 `plic_claim()` 拿 id，再分发到 `uartintr()`/`virtioreadintr()`，处理完 `plic_complete()`。

### 1.3 轮询 vs 中断 vs DMA
- 轮询：简单，烧 CPU（xv6 时钟 tick 轮询串口输入就是妥协）；
- 中断：省电及时，但要 ISR 与"慢工作"分离（top half 只应答，work 推迟到进程上下文）；
- DMA：设备自己搬内存，CPU 只下发描述符——性能三件套的最后一件，也带来
  cache 一致性（设备绕过 MMU/缓存 ⇒ 需要 unmap/flush 或 IOMMU）。

### 1.4 virtio：半虚拟化设备总线
真实磁盘控制器（IDE/NVMe）协议复杂，QEMU 无法全模拟性能 ⇒ virtio 定义
"客户机与 hypervisor 合作"的标准接口：每个设备一条 **virtqueue**：
- descriptor table：`{addr,len,flags,next}` 链，描述一块缓冲区；
- available ring：驱动说"这些描述符给你用"；
- used ring：设备说"这些做完了"。
通知机制：驱动写 MMIO notify 寄存器，设备回中断。virtio-blk/net 即两环之上的语义层。

### 1.5 块层（block layer）
驱动之上，内核把同步 `bread/bwrite` 变成异步批量：排队、合并（相邻扇区）、调度（CFQ/mq-deadline）。
xv6 的 `sleep(buf)` 在等待盘中断时让出 CPU——驱动与调度器的第一次握手。

## 2. xv6 代码走读要点
- `kernel/virtio_disk.c: virtio_disk_init()`：协商 feature（`VIRTIO_F_VERSION_1` 等），读 MMIO 设备状态机（ACK/DRIVER）。
- `virtio_disk_intr()`：回收 used ring → `wakeup(&disk.vdev)`；`virtio_disk_request()`：填描述符 → 写 notify → `sleep`。
- `kernel/disk.c: disk_rw()`：把 buf 挂进 virtio 描述符（DMA 目标是内核直接映射地址——设备没有 MMU！）。
- `kernel/uart.c: uartinit/uartintr`：16550 寄存器操作的最小样本；`console.c` 把 uart 与 stdin/stdout 缝合。
- `kernel/plic.c`：PLIC 基址 + claim/complete 偏移，20 行读完全中断入口逻辑。

## 3. 跨课程联系
- **DDCA/CS61C**：中断控制器、总线与 DMA 是两门课 I/O 章节的直接应用；MMIO 地址空间划分回到 CS61C 的 memory map。
- **CSAPP**：CSAPP 的"链接/加载"视角在这里反转——设备地址空间不属于任何 ELF 段，靠 `mmap(MAP_DEVICE)`/直接映射进入。
- **NJUOS/CS162/HITOS**：NJUOS 的 virtio-drivers crate 与 xv6 virtio_disk.c 同一协议；CS162 强调驱动 bug 是内核崩溃主因（分层防护动机）；HITOS 讲 Linux blk-mq 多队列与 NVMe 的提交/完成队列——virtqueue 思想的裸金属版。
- **MIT 6.824**：RPC 重试 ↔ IO 超时重试；"恰好一次"在设备端与网络端同样是难题（idempotence/幂等队列）。

## 4. 开源项目应用
- **Linux**：`drivers/virtio/` 核心层 + `block/virtio_blk.c`，与 xv6 单文件实现逐概念对应；DMA API（`dma_map_single`）处理 cache/一致性——xv6 直接跳过了这个复杂度。
- **Cloud Hypervisor/Firecracker**：Rust 重写的 virtio 设备端（virtio-blk/net），协议与 xv6 驱动端完全兼容；云盘"热迁移"依赖 virtio 状态可导出。
- **Zephyr/FreeRTOS**：设备树（devicetree）+ driver model 替代裸 MMIO 常量——嵌入式对"设备即内存"的工程化封装。
