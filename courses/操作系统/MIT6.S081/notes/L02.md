# L02 锁与并发（Locking / Synchronization）

> 6.1810 Lecture 2 · 阅读：xv6 book Ch.8；Lab: lock
> 多 CPU 是内核里一切并发 bug 的根源；本课第一个 lab 就是修 xv6 的 malloc 与打印。

## 1. 核心概念

### 1.1 为什么内核到处要锁
xv6 内核所有 CPU 共享同一份内存（proc 表、fd 表、buffer cache、空闲页链表）。
两个 hart 同时改一个链表 ⇒ 丢更新/断链。锁 = 把"读-改-写"变成互斥事务。

### 1.2 原子指令地基
硬件提供 RISC-V A 扩展：`lr/sc`（load-reserved/store-conditional）与 `amo*.d`（如 `amoswap`、
`amocasr` 风格比较交换）。所有自旋锁最终都编译成一条 `amoswap` 或 lr/sc 循环。
C 层用 `__sync_fetch_and_and(&tick, 1)` 这类原子测试位，是"锁的最小样本"。

### 1.3 acquire/release 语义与乱序
现代 CPU/编译器会乱序访存。xv6 在 `acquire spinlk` 里放**获取栅栏**（后续读不能提到锁前），
在 `release` 里放**释放栅栏**（之前的写不能滑到锁后）——用 GCC `__sync_synchronize()`（`fence rw,rw`）实现。
锁变量本身声明为 `volatile`，防止编译器把忙等优化掉。

### 1.4 spinlock vs mutex
- 自旋锁：持锁者可能在页错误/睡眠，因此**持锁期间绝不能睡眠**，适合微秒级短临界区。
- 互斥锁（xv6 `struct mutex`）：可以长持有、可睡眠，实现为"mutex + 等待队列（sleep chan）"。
- 读者写者锁（xv6 `rwlock`）：xv6 的实现在读者升级/饥饿场景下有已知缺陷，讲义专门讨论"为什么不安全"。

### 1.5 锁的粒度与 per-CPU 数据
锁太粗 ⇒ 串行化（全局 proc 锁）；太细 ⇒ 死锁风险。
xv6 的折中：**per-CPU 变量 + 该 CPU 的锁**（`cpuo[]`）——数据私有化减少争用，锁只保护"找到正确 CPU 的私有数据"这一小段。

## 2. xv6 代码走读要点
- `kernel/spinlock.c: acquire()/release()`：关中断（`intr_off`，写 `sstatus.SIE=0`）→ `__sync_fetch_and_and` 抢锁 → 记录 cpu/pc。关中断是为了防止同 CPU 上中断处理器抢锁造成自死锁。
- `kernel/mutex.c: acquire()/release()`：spinlock 保护 waiters 队列，睡眠者用 `sleep(&mx->lk, &ml->lk)`。
- `kernel/proc.c: sleep(chan, lk)` 协议：**先持锁检查条件，睡时原子释放锁**；`wake_up(chan)` 把等待该 chan 的进程置 RUNNABLE——丢唤醒（lost wakeup）问题的一切解药。
- lab-lock：修 `ulib.c malloc`（每 CPU 锁 + 细粒度分配）与 `printf.c`（`console.c` 里 per-CPU output buffer + `output()` 自旋提交），让 `uthread` 并发压测通过。

## 3. 跨课程联系
- **MIT 6.824**：Raft 论文里"一次只有一个 leader 改状态"本质是分布式互斥；kvraft 的粗锁与 xv6 全局锁的吞吐问题同构。
- **CSAPP（Ch.4/12 线程同步）**：CSAPP 的 P/V 与 pthread mutex 是用户态版本；xv6 展示没有 OS 支撑时锁如何从原子指令造出来。
- **DDCA/CS61C**：缓存一致性（MESI）是 `lr/sc` 的硬件前提；CS61C 讲 pipeline hazard，本课讲 memory ordering hazard。
- **NJUOS/CS162/HITOS**：NJUOS 用 Rust 类型系统强制 Send/Sync，从编译期消灭"忘加锁"；CS162 的 log structured 并发、HITOS 的 Linux 锁演化（spinlock→queued spinlock→mutex 层次）互为镜像。

## 4. 开源项目应用
- **Linux**：`spin_lock_irqsave()` 与 xv6 acquire 几乎逐行对应；Linux 的 mutex/spinlock 分层、lockdep 死锁检测都源于同样的问题域；per-CPU 变量 `DEFINE_PER_CPU` 即 xv6 `cpuo` 的工业版。
- **FreeRTOS**：单核 RTOS 用"关中断即互斥"与优先级继承互斥量，展示无多核场景下的简化。
- **Zephyr/seL4**：Zephyr 自旋锁同样带 arch fence；seL4 用"无共享 + IPC"从架构上消灭大部分锁。
