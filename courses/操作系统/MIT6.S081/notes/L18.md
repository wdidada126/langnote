# L18 异常即攻击面（Exceptions & Software Attacks）

> 6.1810 Lecture 18 · 阅读：讲义 + Dune/Cloak/tail fences 相关论文节选
> 异常处理器是内核里"用户可控输入直达控制流"的地方——本讲把 L05 的 trap 机制翻到暗面。

## 1. 核心概念

### 1.1 栈溢出 → 控制流劫持
CSAPP 3.10 的老朋友：`gets()` 覆盖返回地址 ⇒ 用户输入决定内核/库下一步跳哪。
在 OS 语境更致命：trap 帧（trapframe）就在内核栈上，若异常处理路径自身有越界写，
攻击者从"我的进程"跳进"所有人的内核"。异常边界=特权边界，必须按输入验证对待。

### 1.2 攻击谱系（按所需原语分类）
- 数据注入：栈溢出、堆溢出（unlink 攻击）、格式化字符串（`printf(s)` 直接读写任意地址）；
- 控制流：ret2libc、ROP（复用 `ret` 链）、JOP/COP（间接跳转）；
- 信息泄露：侧信道（Spectre——异常/分支预测交互，L04/L16 的阴影）、dmesg 泄漏指针（KASLR 破解）。
防御同样分层：不可执行栈（NX）→ 栈金丝雀（canary）→ ASLR → CFI → 影子栈。

### 1.3 影子栈与 tail fences
canary 防覆盖但不防"绕过返回的 ROP"；**影子栈**把返回地址存第二份（独立区域），
不匹配即自杀——x86 CET 的 SHSTK 是硬件版，ARM PAC/BTI 用指针签名+着陆垫。
Tail fences（SOSP 2021，MIT PDOS 一作论文，作者名待核实，6.1810 指定过）：让内核返回路径
经过一层"看门返回指令"，无需改编译器即拦住整类 ROP——"防御可以放在最少的代码位置"。

### 1.4 内核态异常：page fault 的 DO_SOMETHING 陷阱
缺页处理必须决定"补页还是杀进程"。用户可故意在任意地址触发写缺页：
`access_ok`/VMA 检查不周 ⇒ 内核往任意物理页写（早期 mmap_min_addr 问题）；
xv6 用 `addr_ok` + 只认 `p->trapframe/sp` 邻域增长栈，逻辑全在 20 行内——教学版正解。

### 1.5 沙箱化异常面（Dune/Keystone 线）
Dune（OSDI'08）用硬件虚拟化为进程套 hypervisor，页错误进"自己的小内核"；
与 L16 闭环：**虚拟化是隔离 bug 的机器，异常是 bug 登门的把手**。

## 2. xv6 代码走读要点
- `kernel/trap.c: usertrap()` 默认分支：非 syscall 异常直接 `die("user trap")`——kill 掉比猜对安全；思考 perf counter 溢出类"良性异常"怎么办（lab-traps 的痛点）。
- `trapframe` 布局（`proc.h`）：内核把它当普通数据读写；任何"从 trapframe 取地址再解引用"处都要 `addr_ok`（`sys_call.c: argptr/fetchstr` 即纪律示范）。
- `kernel/vm.c: uvmclear` + guard page（`ustack` 底下留空页）：栈越界=缺页=杀进程，这是 xv6 唯一且足够的栈保护。
- 实验：把 `usertrap` 的 die 改成返回 `sepc=trapframe->ra`（假装没发生）观察系统如何失控——一次课胜过十篇 CVE 报告。

## 4. 开源项目应用
- **Linux**：`CONFIG_STACKPROTECTOR`（canary）、`CONFIG_CFI_PERMISSIVE`（gcc 12 起的 KCFI）、x86 CET/ARM BTI 适配、`mmap_min_addr`。
- **seL4/Zephyr**：MPU Region 粒度保证"越界访问=硬件异常=只死该线程"；Zephyr 的 Userspace 模式复刻本讲全部纪律。
- **浏览器 JIT**：沙箱 + W^X + PAC 是"用户态版本讲"——同一套防御词汇表，换一个内核。
