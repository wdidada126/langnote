# L04 虚拟地址机制（Virtual Address Mechanism / va）

> 6.1810 Lecture 4 · 阅读：xv6 book Ch.6–7；RISC-V privileged spec Ch.3（Sv39）
> 把"地址翻译"从魔法还原成三步：查表、TLB、缺页。本讲 lab：pgtbl。

## 1. 核心概念

### 1.1 malloc 是理解地址空间的最好切口
xv6 的 `ulib.c malloc`：首次调 `sbrk` 系统调用让内核把页接在 heap 之后，
之后在用户态维护**空闲链表**（first-fit），大块内存用 `mmap` 风格思路另行管理。
用户态分配器（碎片管理、arena）与内核 `kalloc` 是同一问题的两个高度。

### 1.2 Sv39 三级页表
RISC-V 把 64 位虚拟地址取低 39 位：VPN 三段各 9 位 + 页内偏移 12 位 ⇒ 4KB 页。
`satp` CSR 存根 PPN + MODE；一次翻译 = 最多 3 次内存访问（walk）+ 1 次偏移。
叶 PTE 的 `R/W/X/U` 位决定权限，缺任何一位都触发 page fault（`scause=12/13/15`）。
大页：一级 1GiB、二级 2MiB——PTE 不再指向下级表而直接给 PPN，硬件按级检查对齐。

### 1.3 TLB 与一致性
翻译缓存让 walk 摊销为 O(1)。硬件不知道你的页表改了，所以换页表/改映射必须
`sfence.vma`（xv6 在 `uvmdealloc`、`proc.c swtch` 前后各处保守地打 fence）。
进程切换时不刷全部 TLB 的前提是 ASID——xv6 没用，RISC-V 有 `asid` 字段可选。

### 1.4 内核地址空间布局
xv6 内核用**直接映射**：`k2p/p2k` 把 `0x80000000+` 的 VA 平移到物理 RAM；
设备 MMIO 在 `walk` 里特判（`KERN_LINK_ADDR`/`W2` 之类高位窗口）。
"内核没有缺页处理"是教学假设，Linux 的 vmalloc/zswap 打破了它——记住这个边界在哪。

### 1.5 链接与加载
`kernel/kernel.ld` 把 `.text` 放在链接地址；ELF 程序头描述"哪些字节加载到哪些 VA"。
exec（L05 细看）= 造一个新页表 + 按 ELF 加载；这就是"程序如何获得地址空间"的全部真相。

## 2. xv6 代码走读要点
- `kernel/vm.c: walk(pagetable, va, alloc)`：核心 20 行，双层循环 3 级索引（`va2pn`、`PDX` 宏）；`alloc=1` 时按需分配中间页表页。
- `mappages()`：walk + 填 PTE + `sfence.vma`；`uvmunmap/uvmclear` 展示"撤映射 vs 擦数据"的区别（CoW 前必须清零防泄密）。
- `user/ulib.c: malloc/free`：free-list first-fit + 尾部合并；`free()` 的 coalesce 缺失会涨碎——projects/alloc 里会看到两种分配器的行为差异。
- `kernel/sysproc.c: sys_sbrk()`：`argint/addr_ok` 校验 + `uvmalloc` 扩 heap，注意内核从不信任用户传来的指针范围。

## 3. 跨课程联系
- **CSAPP（Ch.9.4–9.8）**：CSAPP 的"局部性 + 工作集"解释 TLB 命中率；本课补上页表项权限位的逐个语义与 `sfence` 时机。
- **DDCA/CS61C**：PAT 测试里的页表题（2 级 16 位地址）就是本讲 walk 的玩具版；MMU/TLB 流水线位置见 DDCA Ch.5 访存系统。
- **15445 BufferPool**：数据库用"逻辑页号→帧号"的自管翻译，等价于用户态页表 + clock 替换，思想与 `kalloc+walk` 互照。
- **NJUOS/CS162/HITOS**：rCore 用 `MemorySet` + 分段 trait 把页表抽象成可嵌套对象，比 xv6 裸 `walk` 现代；HITOS 讲 Linux 5 级页表与 `vmalloc` 区；CS162 提供"为什么翻译值这个代价"的性能论证。

## 4. 开源项目应用
- **Linux**：`mm/memory.c: handle_mm_fault`、`follow_page_mask` 与 xv6 `walk` 血缘相同；THP（透明大页）对应本讲大页特判。
- **jemalloc/mimalloc**：工业 malloc 的多 arena/size-class 是 `ulib.c malloc` 问题的正解方向；allocator 项目即其缩影。
- **seL4/Zephyr**：seL4 把页表变成受控能力对象（只有 owner 能映射）；Zephyr 的 MPU 区域是"无 MMU 版隔离"的退化形态。

## 6. 自检测验
- walk 链为什么要带 alloc 标志与 dirty 位？去掉 dirty 语义会丢哪类信息？
- TLB 命中但页表已改：sfence.vma 的责任在谁？忘记刷会构造出什么越权读写？
- 切换 satp 后为什么必须刷 TLB？xv6 各进程的内核映射为什么可以完全相同？
- 大页（megapage）如何降低 TLB miss？它的对齐与内部碎片代价在哪里？
- Sv39 三级 vs x86-64 四级：级数差由什么决定？页表本身占多少物理内存？
