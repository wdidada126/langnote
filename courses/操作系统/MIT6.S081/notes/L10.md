# L10 虚拟内存 I：换页与缺页处理（vm1 / Virtual Memory Part 1）

> 6.1810 Lecture 10 · 阅读：xv6 book Ch.6；xv6-mm 分支 uvm.c；Denning《Virtual Memory》(ACM CSUR 1970)
> L04 建好了翻译的"骨架"，本讲给它注入生命：页可以不在内存里， faults 可以自愈。

## 1. 核心概念

### 1.1 为什么换页（swapping）
物理内存不够时，把冷页写到 swap 分区，热页留在 RAM——地址空间可以超过 RAM，
多道程序度（degree of multiprogramming）随之提高。历史包袱：覆盖（overlay）→ 换页 → 需求分页。

### 1.2 需求分页（demand paging）
程序启动时一页都不装，首次访问缺页再装：lazy 分配（`mmap` 后不碰就不占内存）、
fork 的 CoW（L11）、文件映射按需装页，全部是"缺页 = 通用扩展点"的应用。
缺页处理程序：保存 trapframe → 分类（匿名页/文件页/栈增长/非法）→ 分配帧 → 填内容 → 改 PTE → `sret`。

### 1.3 替换算法与抖动
缺页时选谁出去：OPT（离线最优）、LRU（理论基准）、clock/二次机会（工业现实）。
工作集理论（Denning）：进程有动态"热页集合"，装不下就**抖动（thrashing）**——
缺页率飙升、CPU 空转；对策是 MPS（内存分区）/工作集调度，即现代 cgroup 内存回收的祖先。

### 1.4 页缓存（page cache）
文件读写经缓存：读命中省一次 IO，写聚合成回写（L07 的 barrier/fsync 问题正出在这里）。
页缓存 + 换页 = "内存是磁盘的缓存"统一视图；mmap 让文件页直接进地址空间（脏页写回）。

### 1.5 与 xv6 的差异
xv6-riscv 主线没有 swap；教学分支 xv6-mm 实现 `uvmfault/swapout/swapin`，
用 A/D 位（PTE 的 accessed/dirty）做 clock 选择牺牲页——本讲代码走读按该分支进行。

## 2. xv6(-mm) 代码走读要点
- `kernel/trap.c: usertrap()` 增加缺页分支：`scause==13/15` 调 `uvmfault(p, R_W, stval)`——trap 入口是 VM 的心脏起搏点。
- `kernel/vm.c/uvm.c: uvmfault()`：walk 找 PTE → 区分"未映射"与"已换出"（xv6-mm 用 PTE 高位存 swap 索引的 hack）→ 分配页/读盘 → 填 PTE。
- `swapout()`：遍历页表找 `A=0` 的页，写盘、改 PTE、`sfence.vma`；`A` 位清零让下轮 clock 重新计票。
- `allocpage()/freepage()`：给每页挂引用计数与"类型标签"（USER/KERNEL/SWAP）——Linux `struct page` 的教学原型。
- 性能实验：matrix 逐列访问（每次缺一页）vs 逐行访问（工作集 = 一行）——空间局部性的内核版证明。

## 3. 跨课程联系
- **CSAPP（Ch.9.6–9.9）**：CSAPP 的"缺页 → 磁盘 → TLB miss"流程图在这里成为可改的代码；YAMPP 的 locality 题与 1.5 节实验同源。
- **DDCA/CS61C**：TLB/页表硬件、A/D 位由 MMU 维护——本课依赖这些行为做 clock 算法，软硬契约的活例。
- **15445**：BufferPool 的 clock replacer 就是 1.3 的 clock 算法；ksize/工作集 ↔ 数据库 BP pin 计数。
- **NJUOS/CS162/HITOS**：rCore 从第一课就 demand-paging（内核自己跑在缺页上）；CS162 用排队论分析缺页开销；HITOS 讲 Linux 三级水线回收与 zswap——把"换页"从算法题变成吞吐工程。

## 4. 开源项目应用
- **Linux**：`mm/vmscan.c`（kswapd/direct reclaim）、`mm/truncate.c`；透明大页（THP）是"页粒度"的再权衡；zram/zswap 用内存压缩延缓 IO。
- **FreeRTOS**：无 MMU 无缺页——对照理解"没有 VM 的世界"里 malloc 失败即真失败。
- **Unikernel/OSv**：干脆不做 swap，全部驻留，换取无上下文切换的性能（与 L21 fast network 同属"放弃通用性换性能"家族）。
