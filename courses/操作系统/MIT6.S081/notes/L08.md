# L08 文件系统扩展（fs+：给 xv6 fs 加功能与换设计）

> 6.1810 Lecture 8 · 阅读：lab-fs 相关材料；xv6 fs 局限讨论

## 1. 核心概念

### 1.1 从 lab-fs 说起：日志重放的复用
lab-fs 让你把 L07 的 redo-log 机制移植进一个键值存储（`bit.c` 位图 + 块分配 + 崩溃恢复测试）。
要点是：日志协议与"记录什么语义"无关——kv 和 fs 用同一套 begin/commit/recover。
"机制与策略分离"在本讲第三次出现（前有 syscall、锁）。

### 1.2 给 xv6 fs 加功能的经典题目
- **符号链接（symlink）**：inode 多一个类型，`namei` 遇到 T_SYM 要读出目标路径继续解析；随之带来环检测问题（Linux 的 `MAXSYMLINKS=40`）。
- **大小写不敏感**：namei 比较函数改造——看起来一行的改动，实际牵动所有已存在文件的访问路径。
- **硬链接配额/回收**：ref 计数在崩溃下的一致性（log 保护了，但 `iput` 的递减发生在锁外时机要考）。
结论：文件系统没有"小功能"，每个功能都活在"并发 × 崩溃"的交叉面上。

### 1.3 数据布局的换代：间接块 → extent
xv6 每文件用 12+1 间接块记录块号：随机访问 O(1) 但元数据爆炸（大文件要读一堆间接块）。
现代文件系统（ext4/XFS/APFS）用 **extent**（起始块+长度）：一段连续区间一条记录，
元数据缩小几个数量级，顺带让内核/驱动可以做更大范围的预读与合并。

### 1.4 元数据结构的换代：位图 → B+树 → copy-on-write
块位图：分配快但碎片看运气；目录线性数组：查找 O(n) ⇒ ext4 htree / XFS B+树目录；
ZFS/Btrfs 更进一步：全部元数据进 COW B+树，快照与校验和免费获得。
"换数据结构 = 换一代文件系统"是本课对存储工程史的一句话总结。

### 1.5 锁的粗与细
xv6 fs 的全局 `log.list` 锁 + 每缓冲锁在多核下串行化。改进谱系：
按块分组锁、目录子树锁（Linux `i_rwsem` + dentry 锁）、到 fssched 论文（SOSP'21）的主张——
**锁不是被优化的对象，而是被重排批处理节奏的原因**。这段是 L14 与 projects/minifs 的直接引子。

## 2. xv6 代码走读要点
- `kernel/fs.c: create()` 若改造成带 parent 引用计数（lab 的"O_TRUNC 打开即崩溃丢文件"问题）：学会在 `namei`/`createi` 间找"半完成事务"。
- `kernel/fs.c: stbuf()/writei()/trunc()`：文件增长只改 `ip->size` + 分配块——加 extent 时这些函数全要重写。
- `kernel/bio.c`：缓冲表锁 `bcache.lock` 全局唯一——多核压测（`make fs-test` 并发用例）先在这里现形。
- 对照 lab-fs 骨架：`begin_op/end_op` 的嵌套语义、`log_clean` 恢复后检查——测试即规格。

## 4. 开源项目应用
- **Linux**：ext4 extent 树（`fs/ext4/extents.c`）；XFS 全元数据 B+树；btrfs/NILFS2 把"日志结构"做到极致。
- **Zephyr/LittleFS**：嵌入式 COW + 块对垃圾回收——小 flash 上的"换代设计"样本。
- **RocksDB**：extent/块管理交给文件系统，自身 LSM compaction 是 LFS 思想的上层回声。
