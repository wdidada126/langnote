# L21 快速网络栈（Fast Network / Kernel Bypass）

> 6.1810 Lecture 21 · 阅读：讲义（fast network）+ Seastar/DPDK/AF_XDP 论文或文档节选；xv6 net.c；Lab: net
> 网卡快过内核：一次收包在 Linux 里要过 4 层拷贝与 2 次中断/软中断——旁路运动由此而起。

## 1. 核心概念

### 1.1 内核网络栈的税单
收包路径：IRQ → NAPI 软中断 → 驱动 → sk_buff 分配 → 协议栈（IP/TCP）→ socket 缓冲 →
`recvfrom` 拷贝进用户内存。每一跳都是 syscall 税（L05）、拷贝税（L20）、调度税（L02）的叠加。
10G/100G 网卡下，每包预算只有微秒级——传统栈结构性失守。

### 1.2 旁路（bypass）的三条路线
1. **用户态驱动**：DPDK 把网卡队列（类似 L12 virtqueue）直接 mmap 给用户进程，轮询收包，UIO/VFIO+IOMMU 保安全（接 L16/L17）；
2. **混合**：AF_XDP——内核 eBPF 决定哪些帧走无锁 ring 进用户空间，其余仍走内核栈；
3. **换栈**：Seastar/OSv/TCP offload（TOE，网卡做状态机）——"网络栈在用户态重写一遍"。

### 1.3 设计公理：分片 + 单线程 + 共享无锁
- **RSS**：网卡按五元组哈希把流钉到固定队列/核——无跨核锁、每核独立协议栈（sharding）；
- **run-to-completion**：包处理无状态化，避免 L02/L15 的全局同步；
- **batching**：收/发批量摊薄每包开销（与 L07 日志 commit、L14 fssched 同题材——批处理是系统性能的统一律）。

### 1.4 zero-copy 的真实含义
DMA 直达用户缓冲（需 IOMMU 或物理连续页）、`sendfile()`/splice 省内核↔用户拷贝、
mbuf 链避免线性化。注意：缓存一致性 DMA 与 CoW（L11）冲突 ⇒ 共享给网卡的页要"钉住"（pin）禁止复制。

### 1.5 xv6 的 socket 视图
xv6-net 分支实现 BSD socket 子集：`net.c` 里 sockalloc/bind/connect/recv/send，
协议处理在 **时钟轮询循环**（无中断）里做，每 socket 一个接收队列——把 L20 管道换成"带序号的远端管道"。

## 2. xv6(lab-net) 代码走读要点
- `kernel/net.c`：`sockalloc/sockbind/sockconnect` 状态机（LISTEN/SYN-SENT…的极简化）；ARP 表在 `arp_table[]`——协议栈 = 状态机 + 定时器。
- `virtio_net` 收发包：`net_transmit()` 把 skb 式结构交给 L12 的 virtqueue；接收在 `netread` 轮询。
- lab-net 的 `sock_test`：SYN flood 测试考察"队列有界 + 伪造连接回收"——DoS 防御的最小自觉。
- `user/netcat.c`：socket ↔ 标准输入的双向泵——select 式单线程多路复用的微型示范。
