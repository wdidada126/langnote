# L20 IPC 与消息传递（Inter-Process Communication）

> 6.1810 Lecture 20 · 阅读：Chew et al.《Message Processing in Modular Operating Systems》(SOSP 99)；Liedtke《Improving IPC by Kernel Design》(CPL 93)；xv6 pipe/net
> 微内核的阿喀琉斯之踵与续命丹：一切服务皆消息，消息必须快。

## 1. 核心概念

### 1.1 管道：最小 IPC 的解剖
xv6 `pipe.c`：环形缓冲（PIPEBUF=512B）+ 两个睡眠队列（rwait/wwait）+ 双向 fd 引用计数。
读空 ⇒ 睡；写满 ⇒ 睡；最后写端 close ⇒ 读返回 0（EOF）——POSIX 管道语义全部在此 150 行。
一次 512B 写 = 两次上下文切换 + 四次 memcpy 的一半在拷贝进环形缓冲：这就是 IPC 性能问题的起点。

### 1.2 Mach：端口、权利与异步消息
Mach 把 IPC 原语定为 **port**（收件箱）+ **send/receive right**（能力）：
无连接、异步、任意消息。结果：每次消息都要内核查 capability、拷贝、调度——
"Mach 慢"成为 90 年代经典案例（Chew & Ma 1997 用微基准量化；也是 Mac OS X 重写 XNU 的动因之一）。

### 1.3 L4 的快 IPC 配方
Liedtke 证明 IPC 可以比 syscall 还快，三板斧：
1. **同步 rendezvous**：发送即阻塞、接收唤醒即配对——省去排队与调度往返；
2. **短消息走寄存器**（≤4 条不经过内存拷贝）；长消息用 **map 传递**（把发送者页直接映射进接收者地址空间，copy 变 remap）；
3. 调度器为 IPC 优化（优先级继承、直接交接）。
seL4 继承此配方：小消息 ~百纳秒级。

### 1.4 拷贝才是成本中心
IPC 开销 ≈ 陷入 + 拷贝 + TLB/cache 扰动。优化谱系：
寄存器传参 → 页共享（零拷贝）→ 共享内存环形队列（io_uring/DPDK ring）→ 用户态直接调用（ unikernel）。
"消息系统的第一定律：不要复制，除非必须"。

### 1.5 调用风格：同步 RPC vs 异步消息
微内核上"函数调用"（RM/Vous 型 stub，同步往返）与"消息"（异步）之争，
对应分布式里 RPC vs 队列之争（6.824）——同一权衡：接口自然性 vs 并发吞吐 vs 错误语义。

## 2. xv6 代码走读要点
- `kernel/pipe.c: pipewrite/piperead`：`while(n < cc)` 循环 + `sleep(&p->rr, &p->nread)`——sleep/wakeup 协议（L02）的完整应用；注意先 wakeup 对端再释放锁。
- `kernel/file.c: pipewrite` 经 `struct file` 分发：管道与文件共用 fd 层，证明"接口正交"。
- `kernel/sysfile.c: sys_pipe`：fd 数组 `[readfd, writefd]`；fork/dup 后引用计数何时归零——`EOF 语义` 的全部细节。
- 思考题：把 xv6 `read` 改到 4KB 一次会发生什么？（PIPEBUF 分片写 ⇒ 原子写上限 PIPE_BUF 的来历，接 L21 网络分包。）

## 3. 跨课程联系
- **MIT 6.824**：RPC = 跨机 IPC；超时重试、幂等、 Exactly-once 在两课都是同一组问题；Mach 端口的"能力"与分布式 key 同构。
- **CSAPP（Ch.8.5/9?）**：CSAPP 的信号与管道是用户视角；本课给出内核环形缓冲与睡眠队列实现。
- **DDCA/CS61C**：cache/TLB 扰动决定 IPC 常数成本——体系结构的" locality 决定一切"在系统软件层再现。
- **NJUOS/CS162/HITOS**：rCore 的进程间 socket 实验；HITOS 讲 Linux 的 netlink/eventfd 与 futex（"用户态锁内核帮忙"——IPC 与同步的合流点）；CS162 把 IPC 列入"虚拟化 CPU"章节的暗线。

## 4. 开源项目应用
- **Linux**：futex + 共享内存 + eventfd/signalfd 的"穷人 IPC 组合拳"；io_uring 用 SQ/CQ 环消掉 per-IO syscall（L05 成本账的终极答案）。
- **seL4**：全部服务（设备、文件系统）= 用户态 server + seL4 IPC；CAmkES 自动生成 RPC stub——Mach 教训的正确打开方式。
- **DPDK/SPDK**：用户态轮询环形队列，IPC 退化为"无锁共享内存 + 内存屏障"——L21 与 L15 的汇流。
