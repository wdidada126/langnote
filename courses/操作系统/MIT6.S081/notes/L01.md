# L01 课程导论（Introduction）

> 6.1810 (Fall 2022) Lecture 1 · 阅读：xv6 book Ch.1–2；Lab: util
> 本课以 xv6-riscv 为载体，目标不是"会用 OS"而是"能在两周内写出/改出一个真内核"。

## 1. 核心概念

### 1.1 操作系统是什么
xv6 教材的定义：OS 是运行在硬件之上的**软件层**，为上层程序提供三类抽象：
- **隔离（separation）**：让多个程序互不干扰地共享机器——进程 + 虚拟地址空间；
- **虚拟化（virtualization）**：让程序以为独占 CPU/内存/磁盘——调度、swap、页缓存；
- **统一接口（uniform interface）**：把五花八门的硬件统一成 `open/close/read/write/lseek` 少数几个调用。

### 1.2 Unix 传统：文件 + 进程模型
xv6 直接继承 V6/32V 血统：一切皆文件（fd → open 文件 → inode/vnode），
进程由 fork/exec/wait/exit 生命周期管理，shell 通过组合这些原语装配出工作流。
"机制与策略分离"贯穿全课：内核只提供机制，策略留给用户态程序（shell、init）。

### 1.3 用户/内核双态与系统调用
CPU 以不同特权级运行用户代码与内核代码（RISC-V 的 U/S mode）。
用户程序唯一"越权"通道是 `ecall` 陷入内核；跨边界传参必须拷贝（copyin/copyout），
这就是后面 L05（syscall）、L17（separation）、L18（exceptions）三讲的地基。

### 1.4 xv6 源码地图
- `kernel/`：约 6000 行 C + 少量 RISC-V 汇编。main.c 初始化 → user/ 下的用户程序。
- `kernel/proc.c`（进程）、`vm.c`（地址空间）、`syscall.c`（系统调用表）、
  `fs.c/log.c/bio.c`（文件系统）、`spinlock.c/kalloc.c`（并发与内存）。
- `user/user.c`：init/shell/grep 等，是最贴身的实验对象。

### 1.5 课程结构
前半程逐层拆内核（锁→地址空间→syscall→文件系统→VM→驱动），
后半程进入研究前沿（RCU、虚拟化、安全、内存分配、IPC、网络、直接执行）。
11 个 lab 全部在真内核里改代码，测试框架本身超千行，写不完就过不了 CI。

## 2. xv6 代码走读要点
- `kernel/start.c` → `kernel/entry.S` → `kernel/main.c: main()`：从机器模式跳监管模式、开页表、初始化各子系统。
- `main()` 里依次 `kinit()`（物理内存 freelist）、`vminit()`、`consinit()`、`devinit()`，然后 `userinit()` 拉起第一个进程 init。
- `kernel/printf.c: printf()` 同时服务内核与 `user/`（vsnprintf 复用），是读代码期最好的 trace 工具。
- `Makefile`：`qemu-system-riscv64 -machine virt`，`make qemu-gdb` 挂 gdb；lab-util 第一步就是让 `make grade` 跑通。

## 3. 跨课程联系
- **CSAPP**（Ch.1/8/10）：CSAPP 从程序视角看 fork/链接/IO，本课从实现者视角重写它们；学完 xv6 再回看 CSAPP 8.2-8.5 会有"原来如此"的质变。
- **DDCA/CS61C**：RISC-V ISA、特权级、访存硬件是 xv6 的运行时底座；CS61C 的 ISA 层级视角在本课变成真实指令。
- **MIT 6.824**：6.824 假设单机 OS 可靠，本课解释"可靠"从哪来（日志、崩溃恢复正是两课共享的思想源）。
- **NJUOS/CS162/HITOS**：NJUOS 用 rCore 走同一条路（Rust 版 xv6 式内核）；CS162 偏概念与量化分析，xv6 偏源码实证；HITOS 从工业 Linux 视角回看这些机制的真实代价。

## 4. 开源项目应用
- **Linux**：`init/main.c: start_kernel()` 与 xv6 `main()` 一一对应，只是规模 30 倍；xv6 的 `struct proc` 对应 `task_struct`。
- **FreeRTOS/Zephyr**：嵌入式世界里"小内核"的另一支——FreeRTOS 没有用户/内核分离与 MMU 依赖，Zephyr 则向"设备驱动即服务"演化，可与 xv6 对照理解"OS 可以有多小"。
- **seL4**：形式化验证的微内核，把 xv6 后半程论文课里的隔离思想推到数学证明的极限。
