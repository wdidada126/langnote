# L17 隔离与内核最小化（Separation / Kernel Minimization）

> 6.1810 Lecture 17 · 阅读：Engler & Kaashoek《Exokernel》(SOSP 95)；seL4 论文；Liedtke《Splendid Isolation》(待核实)
> 把"隔离"推到极端：内核只做隔离与复用，策略全部交给应用库 libOS。

## 1. 核心概念

### 1.1 单体内核的"过度代理"
Linux 替应用决定：页缓存策略、调度器、网络栈——应用只能逆着内核的假设优化。
Exokernel 的批判：抽象（abstraction）扼杀了"针对用途的设计"；应提供**保护（protection）而非抽象**：
内核只分配/复用物理资源（页、TLB 区间、磁盘块、特权级），libOS 在应用内自由造抽象。

### 1.2 安全复用（secure resource reuse）
Exokernel 的难点：资源回收时必须"洗干净"再复用——页清零、TLB shootdown、
磁盘块覆盖、权限掩码撤回（"visibility mask" 思想）。
这与 L11 的 `uvmclear`、L04 的 sfence 是同一条安全线：**隔离的强度=复用时擦除的彻底性**。

### 1.3 分离内核与微内核谱系
- 分离内核（Miller 等）：无 IPC，只有静态划分 + 帧调度——军标安全域（EAL7 血统）；
- 微内核（L4/seL4/Mach）：极简内核 + 用户态服务，IPC 为 glue（L20 展开）；
- seL4：功能正确性形式化证明 + 非干扰（non-interference）信息流定理——把本讲主题变成数学。

### 1.4 能力（capability）模型
地址空间、端口、IRQ 都是可传递/可撤销的"权利凭证"。
xv6 的 fd 是弱化版能力（进程私有、不可跨进程传）；seL4 的 CNode 是真能力树。
"最小特权"从格言变成数据结构。

### 1.5 工业回声
Windows Nano/Runtime（历史上 Exokernel 影响）、Unikernel（Nabla/Solo5：应用+libOS 单镜像）、
gVisor（用户态内核当"沙箱"）、Keystone/ARM CCA（用隔离做机密计算，L22 的 SecureMemory 线同源）。

## 2. xv6 代码走读要点
xv6 无 Exokernel 实现，走读用"对照"法：
- `kernel/vm.c` 的共享内核映射 → Exokernel 不允许（TLB 区间分段映射，ASID 轮换）——找出 xv6 里"应用能感知内核存在"的所有点（syscall 号、`sfence` 成本、内核栈越界时的可观测行为）。
- `kernel/proc.c: scheduler()`：Exokernel 会让应用选调度类；对照 Linux `SCHED_*` 与 ck 调度器的可插拔化。
- `user/` 与 `kernel/` 的边界清单（`usys.pl` 生成的 19 个调用）：数一数哪些是"机制"哪些混入了"策略"（如管道 512B 缓冲大小）。
- lab-pgtbl/自加练习：实现"把某页直接映射给两个进程但权限不同"——体会 Exokernel 的安全复用协议要挡什么。

## 3. 跨课程联系
- **CSAPP**：CSAPP 把 OS 当黑箱服务；本课从"能不能更小"再问一层——黑箱的大小就是性能与安全的面包。
- **DDCA/CS61C**：硬件保护位（PTE_U、ASID、TLB 标记）是 Exokernel 方案的可行性前提；"硬件不合作就没有隔离"在此成为可验证论断。
- **MIT 6.824**：微内核"机制策略分离"与 RPC 层"传输/语义分离"是同构设计哲学。
- **NJUOS/CS162/HITOS**：NJUOS/arceos 微内核路线实验直接踩这条线；HITOS 讲 Linux 内核对微内核思想的吸收（eBPF=内核可编程，"既不当大管家也不放权"的第三条路）；CS162 用 Exokernel 论文训练"抽象的代价"批判性阅读。

## 4. 开源项目应用
- **seL4 + CAmkES/SDS**：验证内核 + 组件系统；其"能力 + 非干扰"是本讲定理的工程项目。
- **Unikraft/Solo5**：库操作系统框架，`virtio` 后端 + 选单文件系统即"自带 libOS"；跑在 Firecracker 上把 L16 与本讲拼成完整链路。
- **Linux**：io_uring/eBPF/SCH_BPF 让策略进内核、由用户代码提供——"Exokernel 的渐进主义实现"（措辞可争论，工程事实清楚）。

## 6. 自检测验
- 隔离内核的"非干涉"性质和普通功能正确性证明，难点差在哪？
- seL4 的能力（capability）推导规则如何同时充当访问控制与 IPC 寻址？
- L4 的 sender-based scheduling 为什么省一次上下文切换？
- TCB 最小化的度量是什么？把驱动搬出内核后，fault 域怎么划？
- 微内核 IPC 拷贝开销的缓解手段（映射/寄存器传参/shared data page）各牺牲什么？
- "Splendid Isolation"主张硬件直接给多域隔离：与虚拟化方案的本质分歧在哪？
