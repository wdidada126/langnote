# L14 文件系统性能优化（Optimizing File Systems）

> 6.1810 Lecture 14 · 阅读：讲义 + LFS/Flash 论文节选；lab-fs 性能测试背景
> 一致性讲完后回到老问题：快。文件系统 99% 的优化都是对"介质特性"的顺应。

## 1. 核心概念

### 1.1 介质决定架构
- 磁盘：寻道时间 ⇒ 顺序化一切（提前分配、块组、电梯调度）；
- SSD/flash：页（4KB）读、块（数百页）擦 ⇒ 必须顺序写 + 磨损均衡（FTL），原地重写=放大灾难；
- 持久内存（PMEM/CXL）：字节寻址 ⇒ "文件系统"可能退化成"内存 + flush 语义"（Shapiro & Bernstein 的主题）。
xv6 把磁盘当"每次 512B 原子"的理想介质，本讲把理想戳破。

### 1.2 缓存家族
页缓存（read 命中零 IO）、buffer head、预读（readahead：顺序检测后批量拉页）、
写回合并（把多次小写攒成一次大 IO）。xv6 对应物只有 `bio.c` 512 槽缓存——对比即教材。

### 1.3 元数据优化
- extent（L08）消灭间接块链；
- 目录 B+树（ext4 htree/XFS）消灭线性扫目录——`ls` 十万文件的仓库为何卡死；
- 延迟分配（delayed allocation，ext4/XFS）：`write` 时只记账不落块，回写时一次性选最优布局
  ——性能与碎片的双赢，但崩溃语义变复杂（文件可能"存在但全是 0"直到 fsync）。

### 1.4 日志的瓶颈与绕路
全局 journal = 串行化点：fssched（SOSP'21）指出 fsync 风暴下"批处理掩盖锁开销"不可持续，
应让锁调度迁就日志顺序；ext4 `fast commit` 只提交增量记录；
Btrfs/ZNFS 走 COW：不锁"日志"，锁树根；LFS 干脆全顺序写 + 段清理（代价：GC 与读碎片）。

### 1.5 度量：微基准与真实负载
fio/dbench/postgres TPC-C 是 fs 优化的裁判。经典教训：PostgreSQL 的 fsync 风暴
（walwriter 排队）曾让 ext4 barrier 成本显形——上层写模式决定下层最优设计，再次"机制与策略分离"。

## 2. xv6 代码走读要点
- `kernel/bio.c: bget()`：LRU 命中条件（`b->committed`）——"正在被 log 引用的块不能被回收"，缓存与日志的第一处咬合。
- `kernel/log.c`：一次 `commit()` = 2×数据量 + 1 header + 1 superblock 的 IO 放大；数一下 mkdir 的落盘块数即可体会 ext4 fast commit 省什么。
- `kernel/fs.c: balloc/bfree + alloc()`：first-fit 位图分配 ⇒ 天然碎片；改成"按组/extent"需要动哪些函数（`balloc`/`writei` 的 `BALLOC` 路径）。
- 实验思路（lab-fs 之外自加）：把 `D_BIO/D_LOG` 调试开关打开（`printf.c` 或 `kprintf` 插桩），统计一次 `cp` 的块读写次数——优化从计数开始。

## 3. 跨课程联系
- **15445**：预读 ↔ BufferPool 的 prefetch；延迟分配 ↔ 数据库"页粒度写"约束；LSM compaction 与 LFS segment cleaning 是同一枚硬币（顺序写换空间）。
- **MIT 6.824**：GFS 的 chunk 定位/追加优化 ↔ 本课"元数据换 IO"；分布式 FS 的一致性与本地日志共享 "happens-before" 语言。
- **DDCA/CS61C**：局部性层级（缓存→内存→盘→云）中文件系统占据"内存→盘"缝；本讲是 DDCA 附录存储层级课的 OS 侧镜像。
- **CSAPP/NJUOS/CS162/HITOS**：CSAPP Ch.10 的性能实验（块大小 vs 带宽）在此深化；HITOS 专讲 Linux 页缓存回收与 dirty ratio；NJUOS 的 mmap 实验用 fio 量性能。

## 4. 开源项目应用
- **Linux**：`mm/readahead.c`、ext4 `fs/ext4/extents.c` 与 delayed alloc、XFS 的 per-ag 并行、io_uring 把提交路径摊薄（与 L05 syscall 成本呼应）。
- **F2FS**：Android 默认，flash 亲和的多日志头设计——"日志结构"的现代还魂。
- **SPDK/Seastar**：用户态 NVMe 驱动 + 无锁 per-core 队列，把"优化文件系统"升级为"绕过文件系统"——内核旁路哲学（L21 网络同套路）。
