# 第 4 章　分布式事务原理

## 核心精讲

（以下为教学性梳理，伪代码/SQL 均**教学示意，不参与构建**。）

### 4.1 单机 → 分布式事务

- **单机（4.1.1）**：事务靠锁/日志（WAL）+ MVCC 在单节点内保证 ACID。
- **分布式（4.1.2）**：事务跨多个分片/参与者，额外要解决的 two 件事：① 并发控制在多节点间协调；② **原子提交**（要么全提交要么全回滚）——后者靠 4.6 的 2PC。

### 4.2–4.4 三种并发控制

- **锁 / 2PL（4.2）**：读写前加锁，提交才放锁。正确但读写互斥、易死锁。
- **OCC（4.3）**：三阶段——读阶段（记读集写集）、验证阶段（检查与并发事务是否冲突）、写阶段（冲突则回滚重试）。**适合低冲突**（如读多写少）。

```text
# 教学示意，不参与构建：OCC 验证阶段（简化）
for 每个并发事务 T':
  if T'.写集 与 本事务.读集 相交: 冲突 -> 回滚本事务
  else: 提交
```

- **MVCC（4.4）**：每行存多版本 + 版本由时间戳/事务号标识；读拿「快照」看到一致旧版本，**写不阻塞读、读不阻塞写**。是现代 OLTP 的基石。

```sql
-- 教学示意，不参与构建：MVCC 快照读
-- 事务 T1 (快照时间戳=100) 读一行: 看到 version<=100 的最新版本
-- 同时 T2 (时间戳=120) 在写新版本 -> T1 不受影响, 仍读旧版本
-- 这就是 "读写不互斥"
```

### 4.6 分布式提交：2PC

- **两阶段提交**：协调者先「准备」（各参与者写 undo/redo 并回 YES）→ 再「提交」（或回滚）。
- **痛点**：协调者单点、同步阻塞（参与者持锁等协调者）、网络分区下可能堵住。

```text
# 教学示意，不参与构建：2PC
Coordinator: PREPARE -> Participants: 写日志, 回 YES/NO
if 全 YES: Coordinator: COMMIT  -> Participants: 提交
else      : Coordinator: ROLLBACK -> Participants: 回滚
# 协调者崩溃且已在 COMMIT 前 -> 参与者阻塞等待 (这是 2PC 的著名缺陷)
```

### 4.7 可串行化演进

- 严格 2PL（最稳但最慢）→ 快照隔离 SI（MVCC，高并发但有写倾斜 anomaly）→ **可串行化快照隔离 SSI**（靠检测危险结构在 MVCC 上拿到真正可串行化，PostgreSQL 9.1+ 采用）。

## 版本演进

- **本书无第二版**；本节写 2021 年口径 → 2026 年视角的变化。
- **SSI 成为强隔离主流之一**：PostgreSQL、CockroachDB 用 SSI 在 MVCC 上拿到可串行化而免 2PL 的锁开销。本书 4.7 述及演进，方向正确。
- **确定性并发控制（Calvin 系）**：FaunaDB 等用「先排序再执行」的确定性调度绕开提交期协调，🔧 本书 4.5 点出前沿但未详，2026 年属重要路线。
- **HTAP 下的并发控制**：行存 TP 用 MVCC，列存 AP 用快照，资源隔离避免互相干扰（见 [06-新技术与分布式数据库架构.md](06-新技术与分布式数据库架构.md) 6.4）。🔧 本书 2021 对 HTAP 的并发控制耦合论述少。
- **2PC 仍是原子提交核心，但被优化**：Spanner 用「Paxos 组 + 2PC」、NewSQL 用「Percolator 模型避开同步阻塞」——见第 7–9 章。

- **SSI 落地**：PostgreSQL、CockroachDB 把 SSI 工程化；🔧 本书成书后 SSI 在 NewSQL 的权重更高。

## 常见误区与本书需修正之处

| 误区 | 事实 | 书目 |
| --- | --- | --- |
| 「MVCC 就没有写冲突」 | MVCC 解决读写不互斥，但写写冲突仍需检测（SI 下有写倾斜） | 4.4 |
| 「快照隔离 = 可串行化」 | SI 存在写倾斜异常，SSI 才是可串行化 | 4.7 |
| 「2PC 不会丢数据」 | 2PC 保证原子性，但协调者崩溃可阻塞；它不解决「长时间持锁」 | 4.6 |
| 「OCC 一定比加锁快」 | 高冲突下 OCC 大量回滚重试，反而更慢 | 4.3 |
| 🔧 本书未把 SSI 作为 2026 主流强隔离重点 | SSI 已是 PostgreSQL/CockroachDB 的默认强隔离，建议补权重 | 4.7（🔧 补） |
| 🔧 本书对确定性并发控制（Calvin 系）着墨少 | 跨地域低延迟场景下确定性调度是重要路线，2026 需补 | 4.5（🔧 延伸） |
| 🔧 本书未讲业务层分布式事务（Saga/TCC） | 微服务时代常见，与数据库内 2PC 互补，2026 需补 | 4.6 / 4.8（🔧 补） |
