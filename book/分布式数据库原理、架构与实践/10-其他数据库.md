## 核心精讲

（以下为教学性梳理，伪代码/示意均**教学示意，不参与构建**。）

### 10.1 Hekaton（内存型）

- SQL Server 的**内存优化表**引擎：数据全在内存、多版本（MVCC）+ 无锁（乐观）并发控制，原生编译存储过程减解释开销。
- 事务机制：靠多版本 + 验证（类似 OCC）绕开传统锁瓶颈，极致降低延迟。

### 10.2 MongoDB（文档型）

- **模型**：JSON/BSON 文档，集合无强 schema；天然「聚合内原子」。
- **分布式**：分片（sharding，按 shard key 切）+ 副本集（Replica Set，一主多备、选主靠 Raft 系协议）。
- **事务演进**：4.0（2018）起支持**副本集内多文档 ACID**；4.2 起支持**分片间多文档事务**（代价更高）。

```text
# 教学示意，不参与构建：MongoDB 副本集
ReplicaSet: 1 Primary + N Secondary (选主用 Raft 系)
写走 Primary, 读可走 Secondary (最终一致 or 配置读关注)
分片: 按 shardKey 把集合切到多个 Shard (各含 ReplicaSet)
```

### 10.3 HBase（列存）

- 基于 **HDFS** 的宽列存储；数据按 RowKey 分 Region，Region 自动分裂/迁移。
- 写走 **LSM**（MemStore → HFile），适合高吞写；**单行事务强、跨行/跨表事务弱**（原生不提供分布式 ACID，需上层协调）。

```text
# 教学示意，不参与构建：HBase 写入路径
写 -> WAL (HDFS, 持久) + MemStore(内存)
MemStore 满 -> flush -> HFile (HDFS, 有序, LSM 的基层)
读 -> BlockCache + MemStore + HFile 合并
```

### 10.4 Greenplum（MPP 分析型）

- 基于 PostgreSQL 的 **MPP** 数据仓库：数据按分布键 hash 到多 Segment，查询并行执行、中间结果 shuffle。
- 强项是 OLAP 批量扫描/聚合；事务语义偏 OLTP 轻量，主战场是分析。

### 10.5–10.6 其他模型与架构讨论

- **图/键值/文档事务**：不同模型「事务边界」不同（图的事务常围绕子图、键值常只单行原子）；并非关系库专属，但隔离/一致语义差异大。
- **10.6 架构收束**：回看「一致性（第 2 章）→ 解法（第 3 章）→ 事务（第 4 章）→ 架构（第 5–6 章）→ 案例（第 7–9 章）」的权衡链条，强调没有银弹，只有权衡。

## 版本演进

- **本书无第二版**；本节写 2021 年口径 → 2026 年视角的变化。
- 🔧 **MongoDB 事务已成熟**：4.0/4.2 的多文档 ACID + 5.0+ 时序/集群，2026 年 MongoDB 已是「文档 + 分布式事务」完整形态（star 见下）。
- 🔧 **HBase 仍活跃但「湖仓」分流**：HBase 在实时 KV 列存仍有位，但分析场景被 Iceberg/Delta/Hudi 湖仓表格式分流（见 [../湖仓架构大规模数据平台的设计和实现/00-总览与阅读地图.md](../湖仓架构大规模数据平台的设计和实现/00-总览与阅读地图.md)）。
- 🔧 **Greenplum 开源生态变化**：Greenplum 的 GitHub 仓库 `greenplum-db/gpdb` 本次 `gh api` 实测返回 **404（star 数未能核实，未杜撰）**；其开源形态近年有调整，引用时以官方为准。
- 🔧 **内存型引擎普及**：Hekaton 思想（内存 + MVCC + 无锁）在 2026 年已成主流库标配（PostgreSQL 内存表、Redis 等），非 SQL Server 独有。
