# 第 4 部分 效率（Efficiency，Item 16–24）

> 对应英文原版 Part "Efficiency"（条目英文名已核实自 Addison-Wesley/InformIT 官方目录页）：
> Item 16 Remember the 80-20 rule；Item 17 Consider using lazy evaluation；
> Item 18 Amortize the cost of expected computations；Item 19 Understand the origin of temporary objects；
> Item 20 Facilitate the return value optimization；Item 21 Overload to avoid implicit type conversions；
> Item 22 Consider using `op=` instead of stand-alone `op`；Item 23 Consider alternative libraries；
> Item 24 Understand the costs of virtual functions, multiple inheritance, virtual base classes, and RTTI。
> 九条是一条因果链：**测量定位热点（16）→ 算法层少算（17/18）→ 对象层少建少拷（19–22）→
> 借用别人算好的（23）→ 最后才为语言机制的账单买单（24）**。

## 核心概念速览（中英对照）

- **80-20 法则** — 80-20 rule：约 20% 的代码消耗 80% 的资源；性能工作必须先由分析器（profiler）定位。
- **懒惰计算** — lazy evaluation：把计算推迟到真需要时，可能永远不需要（共享字符串、引用计数、缓存表）。
- **分期摊还 / 备忘** — amortization / memoization / caching：一次昂贵计算的结果复用多次，均摊成本趋近零。
- **共享表示** — shared representation：多个对象视图指向同一底层数据（COW 字符串的 Rep），拷贝只拷指针。
- **临时对象** — temporary object：编译器为"隐式转换 + 按值传参/返回 + 表达式中间结果"自动生成的无名对象。
- **返回值优化** — return value optimization (RVO/NRVO)：编译器在调用方对象存储上直接构造返回值，省掉拷贝。
- **虚函数成本** — cost of virtual function calls：间接调用 + 阻碍内联 + 无法常量折叠。
- **调址垫片** — thunk / offset fixup：多继承下经第二基类调用成员时先调整 this 的小片段代码。
- **RTTI 成本** — cost of RTTI：`dynamic_cast` 沿继承图搜索、`typeid` 对多态类型需运行期取 vtable。

## 动机：性能讨论的正确打开方式是"先算账"

Meyers 在这一部分反对两种极端：为了抽象付冤枉钱而不自知（临时对象、虚调用），
以及不看账本凭感觉优化（把时间花在 20% 的冷代码上）。他给出的层次非常现代：
**算法与数据结构 >> 对象流动 >> 语言机制微调**；最后那条（Item 24）恰恰是"理解成本后
仍然选择多态"的理性依据，不是劝退。

## 机制精讲

### Item 17/18：懒惰与摊还——在时间轴上重排计算

懒惰计算的三件工具在书中依次是：**共享表示 + 写时复制**（多个 String 共享一块字符缓冲，
真要改写时才独占）、**引用计数**（判断"是否唯一持有"的廉价前提）、**智能指针/代理**
（把对象构造推迟到解引用时——Item 28–30 的技术部分伏笔）。
摊还计算（Item 18）给出更通用的形态：**惰性缓存 + 部分结果**。书中例子是对整数求质因子个数：
`map<int, size_t> numFactors` 边算边存，后续查询 O(1)；更妙的是**把中间结果也存进表**——
下次遇到链上的任意数直接续算。权衡：缓存的失效策略、内存占用、以及多线程下的同步成本
（1996 年他没展开，今天这是 COW 字符串死掉的主因，见演进节）。

### Item 19：临时对象的三个来源

1. **隐式用户定义转换**：`double d = 2.5 * rational;` 会生成 `Rational(double)`、
   乘法的返回值、`operator<<` 链上的中间对象——书中 UPC 示例一行代码触发约五次构造/析构
   （确切数字 ⚠️ 未逐字核对原书）。
2. **按值传参/返回**：每个 `void f(T)`、`T g()` 都是一台拷贝制造机。
3. **表达式求值的落脚点**：`a > b ? a : b` 返回 prvalue 时必须有对象存储。
诊断工具很朴素：给 T 的构造函数/拷贝/析构加计数器（🔧 本章 Item 20 实测用的就是这招）。

### Item 20：RVO——把返回值直接建在调用方的地盘上

机制：编译器看到 `return` 一个局部对象，若可行，就让"局部对象"**就住在调用方的目标存储里**，
构造一次到位。🔧 已实测（g++ 15.2，`-std=gnu++23`，`-O0`，对象计数器法，实录输出）：

```text
ctor=3 copy=0 move=0 (a/b/c 三个对象)   // NRVO 在 -O0 下也发生；转发链 retChain 同样零拷贝
```

促成的写法：返回**对象**而非引用/指针；不要"先在别处构造好再拷进返回值"；
单一具名返回路径最有利——**NRVO 不是义务**，`return a.size() > b.size() ? a : b;`
返回两个不同具名对象，多数编译器放弃 NRVO。C++17 起纯右值 `return T();` 是**强制省略**
（连拷贝构造的调用都不存在，见演进节），但具名对象的 NRVO 依然"许以希望、不给保证"。

### Item 21/22：用重载和复合赋值掐断隐式拷贝

- Item 21：与其让 `T * U` 走"隐式转换 + 通用 `T * T`"，不如**重载出所有实际用到的组合**，
  把临时对象在源头消灭。书中坦承组合爆炸的维护代价（3 类型 × 3 类型 = 9 个版本），
  建议只对热点类型做。
- Item 22：`x = x + y` 是"构造临时 + 拷贝赋值 + 析构"三件套；`x += y` 原地完成。
  并且**用 `+=` 实现 `+`**（`T result(x); result += y; return result;`）保证两套语义不漂移。
  今天 `+` 的惯用实现已进化为"按值参数 + 移动"：`T operator+(T a, const T& b) { a += b; return a; }`。

### Item 23：换库——手写实现的隐性全成本

论证方式是把"库的成熟度"当资产：STL 容器/算法经过编译器厂商级调优（`std::vector` 增长策略、
`std::sort` 的 introsort），手写链表/快排几乎不可能赢；哈希表当年用扩展库（rope/hash_map）。
今天的对应判断依旧成立：**先查标准库与头部开源库（Abseil/Folly/fmt），再考虑自己写**。

### Item 24：语言机制的价签（对象模型视角）

- **虚函数**：一次内存取 vtable + 一次取槽 + 间接 call；更狠的是**挡住内联/常量传播**。
  编译器可用去虚化（devirtualization）、LTO 部分回血，但只有当静态分析能证明唯一定象时。
- **单继承 vs 多继承**：多继承本身不慢；"经 B2 调成员要调址"（thunk/offset fixup）是一次加法。
  🔧 已实测（g++ 15.2，`-std=gnu++23`，实录输出）：

  ```text
  D at 000000cfe97ff730; B1-subobject delta=0; B2-subobject delta=16
  sizeof(D)=32
  ```

- **虚基类**：对象布局里多一条到"vbtable"的间接路径，成员访问从"定长偏移"变"两次取表"；
  构造责任上移（最终派生类负责虚基构造）也增加运行期簿记（某些实现有守卫标志）。
- **RTTI**：`dynamic_cast<Derived*>(basePtr)` 对多态类型是运行期图搜索——书中警告
  "深继承 + 宽兄弟 + 热路径"时可达数百时钟周期；`typeid(*p)` 对多态类型同样要查 vtable。
  替代方案：虚函数本身、Visitor（Item 31）、或 `std::variant`（见 [05-技术.md](05-技术.md)）。

**权衡的总账**：24 条的结论不是"别用多态"，而是"把多态放在正确的层"——
冷路径随便用；热循环内用 `final`/CRTP（编译期多态，见
[08-补编-从MEC++到Loki定制技法谱系.md](08-补编-从MEC++到Loki定制技法谱系.md)）/整数标签分支。

## 最新演进与工业实践

- **移动语义（C++11）重写 Item 19–22 的账本**：临时对象从"拷贝+析构"降为"偷指针"；
  标准惯用法 `T operator+(T a, T b) { a += b; return a; }`（按值参数 + 移动）
  正是 21/22 两条的移动化变体（见 [../Effective_Modern_C++.md](../Effective_Modern_C++.md) Item 29–30 语境的讨论）。
- **保证拷贝省略（C++17，[P0135](https://wg21.link/p0135)，提案号已实测可达）**：纯右值省略从优化变成语义，
  Item 20 一半的劝诫自动化了；NRVO 仍是"编译器自愿"，C++26 周期内也有试图保证 NRVO 的提案活动 ⚠️ 结果未核实。
- **`constexpr` 把"摊还"推到编译期**：Item 18 的 memoization 在 `constexpr`/模板元编程里
  变成 `constexpr` 表与编译期计算（详见 [../C++模板元编程.md](../C++模板元编程.md)、
  [../C++20模板元编程.md](../C++20模板元编程.md)）。
- **异构查找与透明比较器（C++14，[P1084](https://wg21.link/p1084) 等）**：`map<string,T>` 用
  `std::less<>` 后 `find("literal")` 不再造 `std::string` 临时——Item 21 "重载消灭转换临时物"
  的标准库制度化作答。
- **COW 字符串的死刑**：多线程共享计数更新需要原子操作，`std::string` 拷贝成本不可隐藏，
  C++11 起标准禁止 COW（`operator[]` 非 const 版本语义改变即为此）；现代选择是 **SSO**
  （短字符串内联）+ 移动。懒惰计算活得好好的，只是换了载体：Ranges 视图（C++20）
  就是"惰性序列"的标准化。
- **`[[nodiscard]]`（C++17/20，[P0479](https://wg21.link/p0479)）**：与效率相关的作用是标明
  "返回新对象而非改本体的 op"，让误用 `x + y;`（丢弃结果）在编译期报警。
- **性能工程工具化**：Item 16 的 profiler 如今是 perf/VTune/Tracy + 连续基准（Google Benchmark、
   folly/Benchmark），`absl::flat_hash_map` 与 F14（<https://github.com/facebook/folly>）
  则是 Item 23 "换库"的当代答案。

  与 [../每个程序员都应该知道的内存知识.md](../每个程序员都应该知道的内存知识.md)；
  对象模型布局细节见 [../深度探索C++对象模型.md](../深度探索C++对象模型.md)。
