# 第 1 部分 基础技法（Basics，Item 1–4）

> 对应英文原版 Part "Basics"（条目英文名已核实自 Addison-Wesley/InformIT 官方目录页）：
> Item 1 Distinguish between pointers and references；Item 2 Prefer C++-style casts；
> Item 3 Never treat arrays polymorphically；Item 4 Avoid gratuitous default constructors。
> 中文部分名「基础技法」沿用侯捷译本的习惯叫法（与仓库单文件大纲 [../More%20Effective%20C++.md](../More%20Effective%20C++.md) 的「基础议题」一节对应，措辞略有出入 ⚠️ 未逐字核对译本）。
> 本章回答的问题是：**对象以什么方式被命名、被转换、被组织、被默认构造——这四种"最基础"的动作里各藏着什么坑。**

## 核心概念速览（中英对照）

- **引用** — reference：对象的别名，语法上不可为空、不可重绑定；底层通常以地址实现，但语义层级比指针高。
- **指针** — pointer：持有地址的对象本身，可为空、可重绑定、可做算术。
- **C++ 风格转型** — C++-style cast：`static_cast` / `const_cast` / `dynamic_cast` / `reinterpret_cast` 四种具名操作，意图显式、可 grep。
- **C 风格转型** — C-style cast：`(T)expr`，按规则悄悄挑选四种转型中最"宽容"的一个，掩盖意图。
- **数组多态** — polymorphic arrays：以基类指针索引派生类数组；因步长（stride）错位而必然损坏，语言层面无法根治。
- **切片** — slicing：以值方式传递派生类对象给基类参数，派生部分被"切掉"——数组多态是它的批量版。
- **不必要的默认构造函数** — gratuitous default constructor：允许创建"语义不完整"的对象，把初始化检查从构造期推迟到使用期。
- **类不变式** — class invariant：对象在任何公开操作前后都应成立的约束；默认构造往往意味着不变式暂时无效。

## 动机：为什么"基础"反而最容易翻车

这四条覆盖的是每天写几十次的动作：取别名、换类型、摆数组、给默认值。它们的风险不在语法，
而在**语义与底层机制的错位**：你以为引用是"另一个名字"，ABI 上它是地址；你以为转型是"换个看法"，
C 风格转型可能同时剥掉 const 并做指针重解释；你以为基类指针指向数组没问题，索引却在按错误的
步长跑；你以为默认构造是"贴心"，它却打开了"半初始化对象"这一整个错误类别。

## 机制精讲

### Item 1：引用 vs 指针——语义两层皮，ABI 一层肉

书中论点：指针与引用的差异**首先是语义的**（可否为空、可否重绑定、有无 `&` 算术语义、
`sizeof(T&)` 得到的是被引用对象的大小），**其次才是实现的**。在主流 ABI（Itanium x86-64、
MSVC）里，非空引用就是一个 `const T* const` 级别的地址值：传参时占一个机器字，
`sizeof(reference member)` 等于指针宽度。🔧 已实测（g++ 15.2 `-std=gnu++23`，MinGW，输出实录）：

```text
sizeof(int&)=4 sizeof(int*)=8   &r==&n: 1     // sizeof 引用得对象大小；引用与对象同地址
```

**权衡**：优先用引用的理由是"把'不得为空'写进类型"，让 API 自文档化；但引用**不能阻止悬垂**
（绑定到将亡对象后照常使用），所以"引用比指针安全"只在**空值检查**这一个维度成立，
生命周期安全要靠所有权类型（见本目录 [05-技术.md](05-技术.md) 的智能指针一节）。
另一个 ABI 细节：返回引用的函数不能返回局部对象的引用——编译器只警告甚至不警告，
悬垂在运行期才爆炸（cppreference: [Dangling reference](https://en.cppreference.com/w/cpp/language/reference)）。

### Item 2：四种具名转型 vs 一个通吃的 `(T)`

机制：C 风格转型 `(T)e` 等价于**依次尝试** `const_cast< T >`、`static_cast< T >`
（含派生→基、基→派生的隐式向下转换！）、`static_cast`+`const_cast`、
`reinterpret_cast`+`const_cast` 中第一个可行的。也就是说，同一个 `(T)e`
在不同代码位置可能触发强度完全不同的操作。书中两条硬论据：

1. **可 grep 性**：`static_cast` 能全文检索，`(int)` 淹没在海量括号语法里——维护期这是真实成本。
2. **失败模式**：C++ 风格把"剥 const""向下转型""重解释位模式"三种危险分级明码标价，
   `reinterpret_cast` 的视觉冲击本身就是一种代码评审拦截。

`dynamic_cast` 是唯一需要运行期类型信息（RTTI）的：沿继承图做可达性检查，成本为常数到数百时钟周期
量级（实现相关，多态类型越深越贵；虚基类还需调址）——它的成本剖析在 Item 24，见
[04-效率.md](04-效率.md)。

### Item 3：绝不用数组做多态——步长错位的算术必然性

机制：`bp[i]` 展开为 `*(bp + i)`，指针加法按 `sizeof(元素静态类型)` 走步。
派生类数组静态类型却是基类，步长于是错了 `sizeof(Derived) - sizeof(Base)` 字节。🔧 已实测：

```cpp
struct Base    { int x; virtual void f(); };            // sizeof = 16
struct Derived : Base { double y; };                     // sizeof = 24
Derived darr[2]; Base* bp = darr;                        // 语法合法，语义已坏
// 实测：&bp[1] - &bp[0] = 16 字节；而真正的 darr[1] 在 24 字节处
```

**编译器为何不能拦截**：`Base* bp = darr;` 单对象视角完全合法（派生→基隐式转换），
数组降级为指针后类型信息即丢失——这是 C 兼容性留下的结构性漏洞。
**相邻概念对比**：这与"切片"（按值传派生对象给基类参数）是同一病根的两个症状：
值语义假设大小固定，多态假设大小可变。现代解法见下文演进一节（`vector<unique_ptr<T>>` 等）。

### Item 4：非必要不提供默认构造函数

机制：默认构造允许对象进入"存在但未就绪"状态，于是每个成员函数都要自卫式检查
"我是否已被初始化"，类不变式（class invariant）在构造后不再自动成立。书中建议：
如果某个"默认值"其实是**语义上有意义的缺省**（如空串），提供默认构造无妨；
如果默认只是"还没赋值"，就该强迫调用方给参数。🔧 最小对比（示意）：

```cpp
class UpboundString {           // 强制提供初值：构造完成即不变式成立
    std::string s;
public:
    explicit UpboundString(std::string init) : s(std::move(init)) {}
    // 刻意不写默认构造；"稍后再赋值"用 std::optional<UpboundString> 显式建模
};
```

**权衡**：不提供默认构造的代价是该类型不能再进 `T arr[10];`、`std::vector<T>` 的
`resize` 等要求默认构造的场合——1996 年这是真约束；C++11 之后 `std::optional`、
`emplace_back`、`reserve`+`push_back` 使这条约束基本消失。

## 权衡与相邻概念对比

| 维度 | 指针 | 引用 | 结论 |
| --- | --- | --- | --- |
| 空值 | 合法 | 非法（但可悬垂） | 表达"必非空"用引用，其余用指针/智能指针 |
| 重绑定 | 可以 | 语法上不可以 | 需要"改指向"的语义只能用指针 |
| ABI 成本 | 一地址 | 通常同左 | 性能不是选型理由，语义才是 |
| `sizeof` | 指针宽度 | 被引用对象大小 | 模板元编程里可见两者不同 |

四组转型横向对比（`static`/`const`/`dynamic`/`reinterpret` 的合法性矩阵与成本）细节展开在
[04-效率.md](04-效率.md) Item 24 一节，本章只立语义边界。

## 最新演进与工业实践

- **C++11 `=delete` 直接封死默认构造**：`UpboundString() = delete;` 让"禁止"成为类型的一部分，
  比"声明为 private 不实现"的旧花招诊断信息清晰得多（见 [05-技术.md](05-技术.md) Item 26/27）。
- **`std::optional<T>`（C++17）成为"合法的空"的标准表达**：取代裸默认值与哨兵值；
  `operator bool` 的设计直接回应了本书 Item 1/4 对"可检查状态"的诉求。
- **GSL 把 Item 1/3 写成可检查的规约**：[C++ Core Guidelines](https://github.com/isocpp/CppCoreGuidelines)
  F.60（"T&" 表示必非空可改）、F.61（`not_null<T*>`）；`gsl::span` 让"数组+长度"成对传递，
  指针式数组降级不再发生。微软 GSL：<https://github.com/microsoft/GSL>。
- **数组多态的现代替身**：`std::vector<std::unique_ptr<Base>>` 或 C++20
  `std::vector<std::reference_wrapper<Base>>`；值语义多态则交给 `std::variant`（见
  [05-技术.md](05-技术.md) Item 31）。C++23 的 `std::expected` 让"未初始化即错误"可以返回而不抛。
- **`std::from_range`（C++23）**：容器构造不再依赖元素默认可构造，Item 4 当年"没有默认构造进不了
  容器"的顾虑在标准库层面被拆除 ⚠️ 细节以 cppreference 为准。
- 相关书目：引用/转型的底层布局分析在侯捷译《深度探索 C++ 对象模型》最系统，见
  [../深度探索C++对象模型.md](../深度探索C++对象模型.md)；`static_cast` 在 constexpr 中的
  解禁史见 [../C++17完全指南.md](../C++17完全指南.md)。
