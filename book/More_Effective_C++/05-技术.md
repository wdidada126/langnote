# 第 5 部分 技术（Techniques，Item 25–31）

> 对应英文原版 Part "Techniques"（条目英文名已核实自 Addison-Wesley/InformIT 官方目录页）：
> Item 25 Virtualizing constructors and non-member functions；Item 26 Limiting the number of objects of a class；
> Item 27 Requiring or prohibiting heap-based objects；Item 28 Smart pointers；
> Item 29 Reference counting；Item 30 Proxy classes；
> Item 31 Making functions virtual with respect to more than one object。
> 中文部分名「技术」（侯捷译法习惯，与单文件大纲 [../More%20Effective%20C++.md](../More%20Effective%20C++.md)
> 的「技术（高阶 patterns）」一节对应）。这一部分是 1996 年"设计模式热"在 C++ 语言上的投影：
> 七条里有五条今天已被**标准库直接收编**（智能指针、引用计数的退役、variant 双分派），
> 但它们正是理解那些标准件"为什么长成这样"的最佳化石层。

## 核心概念速览（中英对照）

- **虚构造函数** — virtual constructor：构造函数不能虚，用"抽象基 + 虚 clone/CreateAndAdd"在运行期按动态类型造对象。
- **对象计数** — counting objects：静态计数器 + 基类构造/析构钩子统计实例数；多态共享计数器是第一个坑。
- **仅堆/仅栈对象** — heap-only / stack-only：私有析构（外部分不了 delete）与私有 `operator new` 的对偶技巧。
- **智能指针** — smart pointer：重载 `*` 与 `->` 的模板类；`operator->` 可链式递归直到裸指针。
- **所有权转移** — ownership transfer：`auto_ptr` 拷贝即夺权（源变 null）——反直觉语义的历史标本。
- **引用计数** — reference counting：共享堆内表示 + 计数决定释放；唯一持有判断是写时复制的前提。
- **代理类** — proxy class：冒充"另一种类型"的中间人对象；转换目标本身是代理时会产生"代理的代理"陷阱。
- **双分派 / 多分派** — double / multiple dispatch：让一个操作按**两个**参数的动态类型选择实现；虚函数只分派一个。
- **访问者模式** — Visitor pattern：`accept/visit` 互递归把双分派拆成两次单分派——代价是"开环"与反向依赖。

## 动机：虚函数只分派一个对象——其余全要靠设计补

Item 25 与 31 首尾呼应，是这一部分的世界观：**成员函数的虚拟化对象永远是 `*this`**。
要按别的对象分派（构造时的"目标类型"、二元运算的"第二个操作数"），就必须把那个对象
**也变成一个虚调用**。其余五条（计数、堆栈限制、智能指针、引用计数、代理）都是
"用对象的生命周期与转换语义做设计材料"的具体工艺。

## 机制精讲

### Item 25：虚拟化构造与非成员函数

机制：`Shape* p = new Circle;` 的类型在编译期写死。运行期"按已有对象的类型造同类"，
需要 GoF 的 Factory Method 变体——书中称之为 virtual constructor / virtual assign：

```cpp
class Shape {
public:
    virtual Shape* clone() const = 0;               // "虚拷贝构造"：唯一能按动态类型 new 的地方
    virtual void swap(Shape& rhs) = 0;              // 虚拟化 operator= 的载体
};
class Circle : public Shape {
public:
    virtual Shape* clone() const { return new Circle(*this); }
};
```

配套：`CreateAndAdd(list)` 工厂——基类声明纯虚，派生类各自注册。非成员函数（如二元
`operator*`）的虚拟化则拆成"非成员壳 + 虚成员核 + 第二参数再虚分派"，即 Item 31 的
virtual-virtual 雏形。

### Item 26/27：给类的"存在方式"立规矩

- **计数**：每个类一份静态计数器在 1996 年编译器上有共享难题（基类静态成员被派生类共用），
  书中用 `type_info` 作键的计数表解决——本质是给每个派生类找回"自己的 static"。
  今天这类需求由 `=delete`（禁拷贝）、`final`（禁继承）、工厂 + 私有构造（单例）等
  类型级手段分解，"数对象"退化为测试与内存池的专门工具。
- **仅堆对象**：析构设 private——栈上定义需要编译器可见且可访问的析构，于是直接编译失败；
  外部销毁经成员静态 `destroy()`（成员内可见私有析构），或配自定义删除器进智能指针。
  🔧 已实测（g++ 15.2，`-std=gnu++23`，`unique_ptr` + 函数指针删除器版可正常析构，实录）：

  ```text
  HeapOnly::~HeapOnly payload=7
  sizeof(D)=32, unique_ptr with custom deleter works
  ```

- **禁堆**：`operator new` 设 private（或 deleted）。注意书未言明的现代坑：重载成员
  `operator new` 会影响该类型**所有** new 表达式（含 placement 决议），C++17 起过对齐分配
  还要配对 `operator delete(void*, size_t, align_val_t)` ⚠️ 细节以 cppreference 为准。

### Item 28：智能指针——从 auto_ptr 标本到现代三件套

书中机制三件套：`operator*`/`operator->` 转发、**`operator->` 的编译器递归**（返回智能指针
就继续解，直到拿到裸指针）、以及 bool 化陷阱（`if (sp)` 与 `if (sp == sp2)` 两种误用）。
`std::auto_ptr` 的拷贝即转移所有权在 STL 容器上直接违约（容器要求 value_type 可拷贝后两者皆有效），
这是它一生的原罪。今天：`unique_ptr`（移动独占 + 零开销删除器）、`shared_ptr`（侵入式外的
控制块计数）、`weak_ptr`（破环 + 观察）。演进详表放 [07-补编-35条现代继承对照表.md](07-补编-35条现代继承对照表.md)。

### Item 29：引用计数——COW 的引擎与它的线程安全死因

🔧 已实测（g++ 15.2，`-std=gnu++23`，本目录教学版 RCString，赋值走 copy-and-swap，实录输出）：

```text
shared refs=2, c=hello
v.size=2 refs now=5
```

第二行是彩蛋：把 RCStr 塞进"扩容数组"后计数变 5 而不是 4——因为**声明了析构/拷贝的类型
不会隐式生移**，`std::move(rc)` 退化成拷贝。这一行输出同时演示了 Item 29 与"五法则"的
断层（见演进节）。机制要点：计数更新非原子 → 多线程共享同一 Rep 即竞态；这正是 C++11
禁止 `std::string` 写时复制的原因。书中完整的 RCString 实现与 CUJ 杂志文章
"Implementing Reference-Counting Classes"（Scott Meyers，1998）同源 ⚠️ 期号未逐字核实。

### Item 30：代理类——两个经典形态

1. **转换代理**：Rational 想支持 `cout << r` 又不想公开分子分母 → `operator RCObject&()`
   返回一个只有 `operator double` 的代理，把"多级隐式转换"掐死在一级（呼应
   [02-操作符.md](02-操作符.md) Item 5）。
2. **语义扩展代理**：二维数组 `a[i][j]`：`a[i]` 返回行代理，行代理再 `operator[]` 才返回真引用。
   书中自曝的深坑：代理再返回代理时，`operator[]` 若返回"引用的引用"则语言不支持，
   必须返回一个**能继续扮演引用的对象**——每一层都要把赋值、转型、bool 化全套重载，
   代码量与心智负担陡峭。STL 的 `vector<bool>` 就是官方踩过的这个坑。

### Item 31：对一个以上的对象虚拟化

- **virtual-virtual**：`operator*(a,b)` 非成员壳 → `a.virtualCore(b)` 虚成员 → 核内再
  `b.virtualHelper(a)`——两次单分派拼出双分派。
- **Visitor**：`a.accept(v)` + `v.visit(concreteA)` 互递归；书中承认的代价：Visitor 要**预知全部
  派生类集合**，加类改全楼（开环方向相反）；`dynamic_cast` 链方案则是"用 RTTI 手搓分派表"。
- 🔧 **现代替身已实测**（g++ 15.2，`-std=gnu++23`，`std::variant` + 双参数 `std::visit`，实录）：

  ```text
  Int2 + Int3 = Int5
  Text+Text = foo
  Text+Double = <无定义的组合>
  ```

  9 种组合在编译期枚举，漏写即编译错误；没有 vtable、没有 new。C++26 的 deducing this
  （[P0847](https://wg21.link/p0847)，提案号已实测可达）进一步让"按 this 真实类型分派"
  可以写成 `self` 形参，简化 Item 25 的 clone 家族。

## 权衡与相邻概念对比

| 方案 | 加新类型 | 加新操作 | 运行期成本 | 备注 |
| --- | --- | --- | --- | --- |
| 虚函数/Visitor | 改一处（加派生类） | 全楼改 | vtable 间接 | "开环"方向：类型开、操作闭 |
| variant + visit | 全改（类型集封闭） | 改一处（加 visitor） | 表跳转 | 与上互补，即表达式问题的两解 |
| dynamic_cast 链 | 不改 | 集中一处 | O(深度×宽度) | 失去穷尽检查，本书与 Guidelines 都劝退 |
| CRTP 编译期多态 | 不改 | 编译期展开 | 零（可内联） | 见 08 补编谱系 |

## 最新演进与工业实践

- **智能指针标准化**：`auto_ptr` C++11 弃用、C++17 移除（[P0008 "Removing auto_ptr and bstring()"，2015](https://wg21.link/p0008)，提案号已实测可达）；
  `make_unique`（C++14）、`weak_ptr::reset(id)` 类设施补齐；`std::atomic<shared_ptr>` → C++20
  `std::atomic<std::shared_ptr<T>>`。循环引用破环靠 `weak_ptr`——Item 28 担忧的正是这套。
- **五法则/零法则**：Item 29 实测的"std::move 退化拷贝"即三法则时代代码的典型症状；
  C++11 移动构造/移动赋值补全法则（拥有资源则写满五件），更现代的处方是**零法则**——
  全部成员用值类型（vector/unique_ptr），特殊成员编译器生成。
- **引用计数退休，代理转世**：`std::string` 禁 COW；代理思想的当代赢家是
  `std::reference_wrapper`/ranges 视图/`std::span`，以及未纳入标准的 Object views 系提案
  （[P0707](https://wg21.link/p0707)，提案号已实测可达，截至 C++26 未采纳）。
- **双分派语言化进行时**：`std::variant` + `visit`（C++17）覆盖封闭类型集；模式匹配提案
  （[P1371](https://wg21.link/p1371)，未采纳）试图给 open match；泛型 lambda + 重载集
  （C++14/17）让 visitor 的书写成本大降。
- **库里的对应物**：Eigen 表达式模板是 Item 30 代理 + Item 17 懒惰计算的高性能合体
  （<https://gitlab.com/libeigen/eigen>）；Folly `fbvector`/Abseil 容器的分配器设计吸收 26/27 的
  "控制对象生存方式"诉求（<https://abseil.io/tips/>）。
- 相关书目：模式原文见 GoF；本书技术的模板化升级见 [../C++20设计模式.md](../C++20设计模式.md)、
  对象模型支撑见 [../深度探索C++对象模型.md](../深度探索C++对象模型.md)。
