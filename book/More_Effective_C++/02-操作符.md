# 第 2 部分 操作符（Operators，Item 5–8）

## 核心概念速览（中英对照）

- **用户定义转换函数** — user-defined conversion function：`operator T()` 成员，令本类型隐式变成 T；威力大、事故也多。
- **代理类型** — proxy class：用"专用于转换的小类型"替代直接写转换函数，把隐式转换限制到唯一目标（Item 30 详述，见 [05-技术.md](05-技术.md)）。
- **前缀/后缀自增** — prefix/postfix increment：`operator++()` 与 `operator++(int)`；后者多一个哑元参数以从签名上区分。
- **短路求值** — short-circuit evaluation：`&&`/`||` 的右侧可能根本不参与运算；重载后该保证荡然无存。
- **求值顺序** — sequence points：重载逗号/逻辑运算符把内建的严格求值顺序降格为"函数调用"，顺序未定。
- **new 运算符 vs operator new** — new operator / operator new：前者是"分配+构造+异常处理"的语言构造，后者只是可重载的分配函数。
- **nothrow new** — nothrow new：`new (std::nothrow) T`，失败返回空指针而非抛 `bad_alloc`。
- **new 处理器** — new handler：`std::set_new_handler` 注册的低内存回调，C++11 弃用、C++17 移除。
- **数组配额** — array cookie：数组 new 藏在首元素之前的元素计数，delete[] 靠它逐个析构——跨编译器不可依赖。

## 动机：操作符是"带语法的函数"，语义保证才是要害

四条共享同一主题：**操作符重载能改变行为，但改不掉（或不小心毁掉了）语言承诺的语义**。
转换函数毁掉重载决议的可预期性；逻辑与逗号的重载毁掉求值顺序保证；`new` 关键字与
`operator new` 函数的混名毁掉对分配失败路径的理解。

## 机制精讲

### Item 5：转换函数是"隐式的万能钥匙"

机制：`Rational::operator double() const` 一旦存在，编译器会在**任何**需要 double 的重载决议中
悄悄插入这次转换。书中招牌事故：`cout << x * rational;` 这类表达式被解析成
`double` 版本甚至 `operator<<` 的整数/指针重载，编译通过、输出错得离谱。两条军规：

1. **不要写隐式转换函数**——用一个具名函数（`toDouble()`）或不具转换能力的显式接口替代。
2. 若转换不可替代，**返回代理类型**而非目标类型：`operator RCObject&()` 只把转换引向
   一个没有其它隐式入口的代理（这是 Item 30 代理类的伏笔）。

### Item 6：前缀返回引用，后缀返回旧值副本

差异清单：前缀 `Counter& operator++()` 自增后返回 `*this` 的引用；后缀
`Counter operator++(int)` 必须先拷贝旧值再自增——**后缀天然多一次构造+析构**。
🔧 已实测（g++ 15.2，`-std=gnu++23`，实录输出）：

```text
after prefix: a.v=1; after postfix: b.v=1 c.v=2   // 后缀返回的是自增前的副本
```

实现纪律：后缀用前缀实现（`Counter old(*this); ++(*this); return old;`），
否则两套语义会漂移。**性能论据**在迭代器时代仍然成立：前置自增不产生临时对象，
这也是标准库与 Guidelines（ES./"prefer 前缀"）一致的建议。C++20 起 `operator++(int)`
对某些概念（`std::input_or_output_iterator` 只要求前置）更加边缘化。

### Item 7：绝不重载 `&&`、`||`、`,`

机制拆解，三个损失各有其根源：

- **短路**：内建 `a && b` 中 `a` 为假则 `b` 不求值；重载后两者都作为实参**先求值**再进函数——
  `if (ptr && ptr->member())` 被重载版本执行，直接空指针解引用。
- **求值顺序**：内建逗号、`&&`、`||` 是序列点；函数调用的实参求值顺序未定。
  重载逗号后 `f(a, b)` 与 `op,(op,(a,b)...)` 的行为差异让模板库（当年的 boost::tie 式用法）
  至今对"逗号重载"讳莫如深。
- **语义劫持**：调试技巧 `cerr << "here", x;` 这类依赖内建逗号的写法在重载环境集体失效。

相邻概念：`operator,` 并非总是被禁止——Boost.Spirit/Xpressive 曾重载逗号构造解析表达式树，
那是"域专用语言"里明知求值顺序无关时的例外；通用代码请遵守本条。

### Item 8：new 的四副面孔

必须分层的四个概念（侯捷译本同样反复强调这组区分）：

```text
new 表达式（T* p = new T(args)）    ← 语言构造：operator new 分配 → 构造 → 失败抛 bad_alloc
operator new(size_t)               ← 可替换的全局分配函数；还有 nothrow 与 placement 重载
operator new[]                      ← 数组版；实现可在此藏 cookie（元素数）
placement new（new (buf) T）        ← 只调用构造函数，不分配；buf 须由你保生命周期
```

- **nothrow 版**：`new (std::nothrow) T` 失败返回空指针。书中态度：**别用**——它让分配失败
  检查退化回 C 式"每 new 一查"，与异常模型背道而驰，而且多数代码根本不查。
- **set_new_handler**：1996 年的"内存不足最后一道防线"。历史命运：C++11 弃用，**C++17 移除**
  （cppreference: [std::set_new_handler](https://en.cppreference.com/w/cpp/memory/new/set_new_handler)）。
- **数组 cookie**：`delete[]` 要知元素数，实现把计数藏在返回指针之前的"配额"里；因此
  `new T[n]` 的原始内存块与 `operator new[]` 的申请大小并不相等——**依赖此布局是 UB**，
  跨编译器/跨 `-fsized-deletion` 配置都会翻车。
- **配套纪律**：new 与 delete 必须同约定（标量/数组各自配对）；重载了 `operator new` 就要
  重载对应 `operator delete`（含 placement 版），否则"构造抛异常时的归还路径"错配。

## 权衡与相邻概念对比

| 概念对 | 一线之隔 | 记忆锚点 |
| --- | --- | --- |
| 转换函数 vs 构造函数 | 方向相反，都会参与隐式转换 | 构造函数加 `explicit`，转换函数 C++11 起也可加 |
| `operator new` vs malloc | 只分配不调构造；失败走 handler/异常/空指针三选一 | malloc(0) 行为未定义式，new 至少给类型 |
| delete vs 析构函数 | delete = 析构 + 归还内存 | 栈对象只能析构，不能 delete |
| 内建 `&&` vs 重载 `&&` | 短路 + 序列点 | 重载即函数调用，参数先求值 |

## 最新演进与工业实践

- **`explicit operator bool()`（C++11）**：Item 5 的"别写隐式转换"有了标准出口——智能指针与
  `std::optional` 的可见性测试都用它；上下文限定转换（contextual conversion）不再污染重载决议。
- **`std::allocator` 与 PMR（C++11/17）**：分配失败的现代处理不是 new handler 而是
  `allocator_traits::allocate` 抛 `bad_alloc`，或用 `std::pmr::polymorphic_allocator` +
  `set_memory_resource`（如 `null_memory_resource`、单调资源）把"内存耗尽策略"做成可注入对象；
  Folly 的 `Arena`、Abseil 的 `absl::Allocator` 是工业对应物
  （<https://github.com/facebook/folly>，<https://abseil.io/tips/>）。
- **sized deallocation（C++14 `operator delete(void*, size_t)`）**：delete 时把分配大小交回分配器，
  小对象池回收省一次元数据查找——cookie 依赖被进一步削弱。
- **`std::destroy_at` / `std::construct_at`（C++20/17）**：placement new 的手写伴侣（显式析构调用
  `p->~T()`）有了标准算法形式，语义不变。
- **`[[nodiscard]]`（C++17/20）**：对"分配/转换类函数"可强制检查返回值，弥补 nothrow 风格
  "没人查空指针"的原始动机——现在不查会被编译警告。
- **迭代器时代的前后缀**：Ranges（C++20）的 `iterator` 概念只要求前置自增；写泛型代码时
  后缀自增几乎永远不该出现在热路径——Item 6 的结论被概念体系制度化。

  运算符重载的全量规约见 [../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md)。
