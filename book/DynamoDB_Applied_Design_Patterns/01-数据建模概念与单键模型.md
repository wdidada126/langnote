## 1. 章定位

- 本章是全书概念地基：把 DynamoDB 的**单键模型**讲成一种以访问模式为输入的数据建模语言。
- 本书性质=设计模式册而非功能手册：2014 年时点官方术语仍是 hash attribute / range attribute ⚠️，本册行文处即术语断层带。
- 导读句 ✅ 证明概念在场：tables、items、attributes、primary keys、indexes、design patterns 六词并列于同一句——本册把它们编成一条建模流水线。
- 与波4 兄弟册的时间纵深：本册 2014 概念原型 ⇄ [../Amazon_DynamoDB_TDG/00-总览与阅读地图.md](../Amazon_DynamoDB_TDG/00-总览与阅读地图.md) 02 章（表与数据模型，2022 API 版，写前验名 ✅ 在盘）。

## 2. 表-项-属性三件套

| 概念 | 定义（2014 语义 ⚠️） | 关系世界对照 | 现状锚 ✅ |
|---|---|---|---|
| Table 表 | 项的集合，主键唯一标识 | 表（无列约束） | WorkingWithTables.html |
| Item 项 | 属性嵌套集合，单行文档 | 一行≈一个文档 | Introduction.html |
| Attribute 属性 | 标量/嵌套/集合三类类型系统 | 列值（同行可异构） | data-modeling.html |
| 主键 | 单键（仅分区）或复合键（分区+排序） | 聚簇索引键前缀 | WorkingWithTables.html |

要点展开（逐条）：

- 类型系统：S/N/B 标量 + NULL + 集合（SS/NS/BS）+ 嵌套（List/Map）✅（文档口径）。
- 项上限 **400KB** ✅（现行同值）。
- 无外键、无 CHECK/DEFAULT、无 UNIQUE 约束（键除外）⚠️——完整性全部上浮应用层。
- **schema-on-read**：表的「结构」= 键结构 + 应用读写代码的约定 ⚠️。
- 集合类型的读时不可部分更新（历史上整值替换）⚠️（现代集合原子更新已有文档记载 ✅，属演进，见文末节）。

## 3. 单键模型：本书的心脏

DynamoDB 的物理布局、路由与计费都由分区键决定 ⚠️（转述口径：分区键定散布，访问必带键）：

1. **访问模式先行**：先枚举全部查询形态（QPS、键、过滤、排序、投影），再反推键——本书步骤化 ⚠️；官方现行同口径 ✅（data-modeling.html、best-practices.html）。
2. **复合键=有序对**：同分区键的项按排序键聚簇，「前缀取一族」即 Query 雏形（→ [05-查询与扫描访问模式.md](05-查询与扫描访问模式.md)）。
3. **没有键就没有高效访问**：非键条件=Scan，计费陡增 ⚠️；索引与冗余写是两大补偿（→ [03-索引体系GSI与LSI.md](03-索引体系GSI与LSI.md)）。
4. **热点即设计缺陷**：低基数/倾斜键=限流头号成因 ⚠️；bucketing 加盐是本书时代标准解 ⚠️（术语在 ✅ 导读 design patterns 所辖概念场内）。
5. **关系映射原语**：1:N 用排序键前缀；M:N 双写镜像 ⚠️——官方后以 adjacency graph 专页收编 ✅（URL 台账 [00-总览与阅读地图.md](00-总览与阅读地图.md) §7）。
6. **表数量哲学**：2014 本册倾向少表多索引 ⚠️；2022 官方单/多表博客改推「访问模式驱动、默认多表」✅（同台账）。

## 4. 设计模式词汇表（本册概念容器 ⚠️）

| 模式 | 意图 | 主要代价 |
|---|---|---|
| 附件/嵌套（adjacency） | 一次读全聚合 | 400KB 上限、更新放大 |
| 状态属性（status） | 多视图单行 | 条件更新需求上浮 |
| 实体分解（denormalized copy） | 跨实体单读 | 双写一致性靠应用 |
| 计算属性 | 索引排序即结果 | GSI 吞吐费 ⚠️ |
| 加盐分桶 | 摊薄热点 | 键空间治理复杂 |
| 查找表 | 外部 ID 反查真键 | 多一跳读 |
| 多类型表 | 表数最小化 | 同键空间异构项并存 |

- 模式清单是「本书导读六词」的展开容器 ⚠️：逐模式的原书页码/章界不可证，故全表标 ⚠️，不冒充原文结构。

## 5. 建模操作流（章内方法论 ⚠️+✅）

1. 写访问模式清单（读/写/峰值/过滤/排序/投影六字段）⚠️。
2. 每项查询标注「键可得性」：能全键命中？键前缀？还是非键？✅ 口径。
3. 非键行≥高频 ⇒ 立即触发索引或冗余决策（→ [03-索引体系GSI与LSI.md](03-索引体系GSI与LSI.md)）⚠️。
4. 键基数与均匀性审查（→ [04-分片与容量规划.md](04-分片与容量规划.md)）⚠️。
5. 嵌套深度审查：聚合完整 vs 更新放大权衡 ⚠️。
6. 用 🔧 类比方格纸先在纸上走一遍全部查询形态（本机习惯平移，见 §6）。

## 6. 🔧 本机类比实验（SQLite 3.45.3 / DuckDB 1.5.5；**非 DynamoDB 行为**）

| 组 | 实验与真实输出 | 类比点 | 边界 |
|---|---|---|---|
| T1 | 复合主键 `PRIMARY KEY(ordertid,customerid)` WITHOUT ROWID；`WHERE ordertid='o1'`→2 行 | 分区键前缀取一族 | 无配额/无 400KB |
| T5 | `profile TEXT` 存 JSON：`{"name":"alice","orders":[…]}` | 项=文档、嵌套属性 | 无服务端类型 |
| T6 | `JOIN USING(customerid)` 成功返回 2 行 | **反衬**：DynamoDB 2014 无 JOIN ⚠️ | 关系引擎本行 |
| D6 | `a='p1'`→17 行；`AND b BETWEEN 's2' AND 's6'`→11 行 | 复合键范围语义 | 同上 |
| D7 | `EXPLAIN QUERY PLAN`→`SEARCH t USING PRIMARY KEY (a=? AND b=?)` | 键命中可观测性 | SQLite 计划≠消耗单位 |
| D10 | 同表项键集各异：`p0→['e','n']`、`p1→['n']` | schema-on-read 异构项 | 无类型系统 |
| D14 | 1000 项均匀散布 10 键、每分区 100 行、前缀读 100 行 | 键散布/热点的形状 | 无自动分裂 |

**诚实声明**：本机无任何 AWS 凭证与 DynamoDB Local 容器（零新装纪律），AWS 侧行为一律 ⚠️+✅URL；以上类比**止于形状**，代价模型（RCU/WCU、异步索引、项上限）在 SQLite/DuckDB 中不存在。

## 7. 常见误区（2014 语境 ⚠️ + 现状提醒）

- 把 DynamoDB 当「可任意条件查询的 KV」：非键=Scan 账单 ✅（Scan.html）。
- 低基数分区键（status/gender 类）：单分区承载全部流量 ⚠️。
- 先建表后想查询：与本书方法论整体相反 ⚠️。
- 嵌套过深省表数：400KB+更新放大双罚 ⚠️。
- 照搬范式/反范式任一极端：按**读形态**定形才是单键模型 ⚠️。
- 用关系直觉找「二级索引=加速」：索引是第二键空间不是优化器选项（→ [03-索引体系GSI与LSI.md](03-索引体系GSI与LSI.md)）⚠️。

## 9. 建模三步走（本章方法论收拢 ⚠️）

1. **列**：把业务的每个读/写动作写成一行「动词+主语+条件+排序+频率」。
2. **猜键**：对每行猜一个「必带键组合」，猜不出=该行是 Scan 候选。
3. **合并**：把同构键空间并表、异构键空间分表或加索引——输出即 [03-索引体系GSI与LSI.md](03-索引体系GSI与LSI.md)/[04-分片与容量规划.md](04-分片与容量规划.md) 的输入。

三步走的本质=**把查询计划前移到设计期**：DynamoDB 运行期没有优化器替你补救 ⚠️（对照 SQLite/DuckDB 优化器兜底——**非 DynamoDB 行为**）。

## 10. FAQ（读者三问 ⚠️）

- 问：能一张表塞下整个系统吗？
  答：能，但 2022 后官方口径改推默认多表 ✅（单/多表博客 URL），本书 2014 倾向单表 ⚠️——两代口径辨析见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §8。
- 问：属性命名有讲究吗？
  答：有——保留字/特殊字符需表达式占位名 ⚠️→✅（best-practices.html 线收录）。
- 问：先建索引再改键来得及吗？
  答：LSI 不可事后加 ⚠️→✅（SecondaryIndexes.html），GSI 可但改不了基表键——键错=重建迁移 ⚠️。
