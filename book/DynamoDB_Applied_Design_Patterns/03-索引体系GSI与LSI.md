# 03 · 索引体系：GSI 与 LSI

> 章题 ⚠️ 推定（重构依据：✅ 官方导读句「Discover what global and local secondary indexes are and their importance in DynamoDB」，见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §2/§6）。三态：✅ 实证 / ⚠️ 转述推定 / 🔧 本机类比实测（**非 DynamoDB 行为**）。

## 1. 章定位

- 索引=为「第二种访问模式」**再造一个键空间**，不是关系库意义上的「加速手段」⚠️。
- 2014 年 DynamoDB 只有两类二级索引：LSI 与 GSI；两者都是**稀疏、异步（GSI）、可投影**的窄索引——三个定语构成本章全部工程含义 ⚠️→✅。
- 导读把索引单列一句 ✅，证明其板块地位；与 [01-数据建模概念与单键模型.md](01-数据建模概念与单键模型.md) 的六词清单中 "indexes" 直接呼应。

## 2. 两类索引机制对照（概念 ⚠️，术语现状 ✅）

| 维度 | LSI（local secondary index） | GSI（global secondary index） |
|---|---|---|
| 分区键 | 与基表相同 | **可以是全新分区键** |
| 排序键 | 自定义 | 自定义 |
| 创建时机 | 仅建表时 ⚠️→✅ | 建表时或事后 ✅ |
| 一致性 | 同分区聚簇，可强一致读 ⚠️→✅ | 异步复制，恒最终一致 ⚠️→✅ |
| 吞吐计费 | 与基表共享写配额 ⚠️→✅ | 独立 RCU/WCU 配额 ⚠️→✅ |
| 投影 | KEYS_ONLY / INCLUDE / ALL ⚠️→✅ | 同左 ✅ |
| 官方锚 | ✅ …/SecondaryIndexes.html（curl 200，台账 §7） | 同左 |

- 现代口径 ✅（文档现行页）：GSI 支持读写容量独立分配；LSI「仅建表时可加」至今未放宽 ⚠️ 转述。
- 波4 兄弟对位：[../Amazon_DynamoDB_TDG/00-总览与阅读地图.md](../Amazon_DynamoDB_TDG/00-总览与阅读地图.md) 04 章（索引体系 GSI 与 LSI，写前 ls 验名 ✅ 在盘）以 2022 API 重述同题——本章是其 2014 概念原型。

## 3. 索引的设计语义（方法论 ⚠️+✅）

1. **先有第二查询形态，后有索引**：✅ 与 data-modeling.html「access pattern 先行」同构。
2. **稀疏性（sparse）**：项缺索引键属性即不进索引——「哪些行参与哪个视图」被编码进属性有无 ✅/⚠️。
3. **投影三档**：ALL=整项复制（写放大）、KEYS_ONLY=最省、INCLUDE=折中 ✅ 概念。
4. **排序即结果**：索引排序键可存计算属性（预拼的视图序），查询零后处理 ⚠️。
5. **索引数=写成本倍数**：每个索引独立配额 ⚠️→✅（与 [04-分片与容量规划.md](04-分片与容量规划.md) 强耦合）。

## 4. 模式清单（本章概念容器 ⚠️）

- 视图反转：基表 (user,time) + GSI (status,time) 支撑管理端列表 ⚠️。
- 查找表：外部 ID 作 GSI 分区键，反查真实键 ⚠️。
- 分区内副排序：LSI 换排序维（cost/updated）⚠️。
- 投影直取：INCLUDE 目标列，免回表 ⚠️。
- 反向边索引：adjacency 双向边各挂 GSI（官方专页 ✅ 收录，用法推定 ⚠️）。
- 预排序聚合：计算排序键（如 `yyyy#mm#dd` 拼接）⚠️。

## 5. 走查示例：三视图一个键空间（演示域自拟 ⚠️）

需求：订单表要支持「按用户查」「按状态查」「按金额查」。

1. 基表主键 (userId, orderId) 承接查询一 ⚠️。
2. GSI-A：分区键 status + 排序键 createdAt，投影 INCLUDE(total)；**只对活跃订单写 status** ⇒ 稀疏索引天然过滤历史单 ⚠️。
3. GSI-B：分区键 amountBucket + 排序键 amount（金额分桶=加盐变体，联动 [04-分片与容量规划.md](04-分片与容量规划.md)）⚠️。
4. 写入代价：一次 PutItem=基表 WCU+两个 GSI 配额 ⚠️→✅。
5. 读旧影：写完立即查 GSI-A 可能为空 ⇒ 应用侧补偿（基表回读/重试）⚠️→✅。
6. 分桶键：GSI-B 分区键用桶号而非裸金额——低基数视图键会把流量灌进单分区（联动 [04-分片与容量规划.md](04-分片与容量规划.md)）⚠️。
7. 回表审计：INCLUDE 之外的展示列，优先扩投影而非回基表二次读——读放大⇄写放大互换的显式决策 ⚠️。
8. 视图退役：长期零查询的 GSI 应删除省配额——2014 只能人工盯指标 ⚠️。
9. 复盘：若查询三从「按金额」改为「按金额+状态」组合，GSI-B 的排序键改计算属性即可——**索引可演进性远好于 LSI** ⚠️（LSI 定型后不可换排序键 ⚠️→✅）。

## 6. 🔧 本机类比实验（**非 DynamoDB 行为**）

| 组 | 实验与真实输出 | 类比点 | 边界 |
|---|---|---|---|
| T2 | `gsi_price ON orders(price)` 命中范围+排序查询 | GSI：非键列可过滤可排序 | 同成本池 |
| T1 | 复合主键前缀查询 | LSI：同分区键换排序维 | 无「仅建表可加」约束 |
| D20 | 稀疏索引：`status='ACTIVE'` 命中 40 行、`ORDER BY ts DESC` 走索引计划；LSI 形计划 `USING INDEX lsi (pk=?)` | 稀疏性+排序即结果+两种计划形态 | 无配额/无投影概念 |

| D5 | DuckDB `SEQ_SCAN` | 无索引=扫描形态 | 无计费 |

## 7. 工程告诫 ⚠️+✅

- GSI 事后建在大表上是重运维动作 ⚠️→✅（文档标注创建期状态/耗时）。
- 热点项×多索引=限流放大器 ⚠️（联动 [04-分片与容量规划.md](04-分片与容量规划.md)）。
- 投影 ALL 的隐藏成本：容量近似翻倍 ⚠️→✅。
- 「索引当优化器用」的思维在 DynamoDB 行不通：索引=键空间，不是 B 树 ⚠️。

## 9. 索引选型决策清单（文字版决策树 ⚠️）

1. 第二查询形态带原分区键吗？带 → 只缺排序维？→ **LSI**（前提：还没建表 ⚠️→✅）。
2. 第二查询形态要换分区键？→ **GSI**。
3. 该视图只覆盖部分项？→ 稀疏化：只给参与项写索引键属性 ✅/⚠️。
4. 查询列⊂索引键+少量属性？→ INCLUDE 投影，别 ALL ⚠️→✅。
5. 视图需要「排好序的结果」？→ 排序键放计算属性 ⚠️。
6. 写完立即读该视图？→ 不行：GSI 异步 ⇒ 基表/LSI 回读补偿 ⚠️→✅。
7. 索引数量 ≥3？→ 回 [01-数据建模概念与单键模型.md](01-数据建模概念与单键模型.md) 重审访问模式清单，多半有键可合并 ⚠️。

## 10. 术语桥（本书旧语 ⇄ 现行 ✅）

- 「GSI 写容量并入基表」的 2014 口径 ⚠️ → 现行 GSI 独立预配置/按需分配 ✅（SecondaryIndexes.html）。
- 「投影=拷贝多少」的直觉 ⇄ 现行 projection 三值模型 ✅ 同词。
- LSI 的「local」= 分区局部复制；GSI 的「global」= 全分区重散布 ⚠️ 释义。
- 读法约定：凡 ✅ 导读句所辖结论可直接引用；具体配额数字/上限一律 ⚠️（不可证，勿抄二手博客假数）。

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| 全局二级索引 | global secondary index (GSI) | 新分区键的第二键空间 ✅ |
| 本地二级索引 | local secondary index (LSI) | 同分区键自定义排序，仅建表时 ⚠️→✅ |
| 稀疏索引 | sparse index | 缺键属性不入索引 ✅/⚠️ |
| 投影 | projection (KEYS_ONLY/INCLUDE/ALL) | 索引复制多少基表 ✅ |
| 回表 | fetch-back | 投影不足时的二次代价 ⚠️ |
| 异步复制 | asynchronous replication | GSI 滞后窗口 ⚠️→✅ |
| 独立配额 | separate throughput | GSI 自有 RCU/WCU ⚠️→✅ |
| 访问模式载体 | access-pattern carrier | 索引第一性定义 ⚠️ |
| 写放大 | write amplification | 一写多索引成本结构 ⚠️ |
| 查找表 | lookup table | 外部 ID 反写真键 ⚠️ |
