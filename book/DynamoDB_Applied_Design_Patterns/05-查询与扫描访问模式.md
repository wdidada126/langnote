# 05 · 查询与扫描访问模式

> 章题 ⚠️ 推定（重构依据：✅ 官方导读句「Conduct query and scan operations on DynamoDB tables to get efficient results」，见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §2/§6）。三态：✅ 实证 / ⚠️ 转述推定 / 🔧 本机类比实测（**非 DynamoDB 行为**）。

## 1. 章定位：两种读与它们的经济学

- DynamoDB 的读只有两个动词：**Query（带键）**与 **Scan（不带全键）** ✅（Query.html / Scan.html，台账 §7）。
- 「efficient results」是本章题眼：效率不由引擎优化器保证，而由**键设计+投影+过滤位置**三件事决定 ⚠️——这正是本书「Applied」的落点。
- 04 章管「容量是否够」，本章管「每次读花多少」✅ 分工。

## 2. Query 语义全解 ⚠️+✅

结构（现代文档口径 ✅，Query.html）：

1. `KeyConditionExpression`：**分区键必等值**；排序键可用等值/前缀/比较/区间（BETWEEN 形）⚠️→✅。
2. `FilterExpression`：命中键后再滤——**过滤前的读量照样计费** ✅/⚠️（这是效率陷阱本体）。
3. `ProjectionExpression`：只取所需属性，省读放大 ✅。
4. 排序方向 `ScanIndexForward`；分页 `LastEvaluatedKey`→`ExclusiveStartKey` ✅。
5. 一致性选择：`ConsistentRead` 对基表/LSI 可用，GSI 恒最终一致 ⚠️→✅。
6. 可指向 GSI/LSI 作「另一键空间」的 Query（→ [03-索引体系GSI与LSI.md](03-索引体系GSI与LSI.md)）✅。

本书 2014 表述差异 ⚠️：Query 过滤当时用 `QueryFilter`+`ExclusiveStartKey` 旧参数族；表达式语法（Expression 家族）约 2015 引入 ⚠️——读原书代码示例需做参数名翻译。

## 3. Scan 语义与合法用途 ✅+⚠️

- 全分区迭代+可选过滤+Limit ✅（Scan.html）。
- 并行扫描：分段 Segment 并行是本书时代的标准加速手段 ⚠️→✅（现代文档仍收录 parallel scan ✅ 口径）。
- 合法场景 ⚠️：管理端小表枚举、离线导出预处理、缺索引的一次性回填。
- 非法场景 ⚠️：热路径 API 里用 Scan+Filter 假装 Query——RCU 黑洞。
- 现代补充 ✅/⚠️：官方把「查询前先想键，Scan 是最后手段」写入 best-practices.html。

## 4. 一致性读 vs 最终一致读 ⚠️→✅

| 维度 | 最终一致（默认） | 强一致 |
|---|---|---|
| 半价 RCU | ✅/⚠️（现行文档明言 ✅） | 全额 |
| 可见新写 | 滞后窗口（通常亚秒 ⚠️） | 立即可见 |
| 适用 GSI | 仅（GSI 无强一致读 ⚠️→✅） | 基表/LSI |
| 典型误用 | 写后读回 UI 用默认读 ⚠️ | 全表滥用抬高账单 ⚠️ |

## 5. 效率军械库（模式级 ⚠️，概念全部 ✅ 在场于导读 design patterns）

1. **投影先行**：ALL 索引+宽查询=白读；按需 ProjectionExpression ⚠️。
2. **键内排序代替应用排序**：排序键设计成目标视图序（含计算属性）⚠️。
3. **分页游标外露**：把 LastEvaluatedKey 编进 API cursor ⚠️。
4. **Filter 只当保险丝**：期望结果集≈命中集，Filter 仅剔边角 ⚠️。
5. **并行 Scan 分片治理**：Segment 数=并发数，配额联动（→ [04-分片与容量规划.md](04-分片与容量规划.md)）⚠️。
6. **缓存层外置**：读热点上 ElastiCache/DAX 类 ⚠️（DAX 为 2017 后产物，本书时代只能自建缓存 ⚠️）。

## 6. 走查示例：博客域三读（本机方格纸推演，非 AWS 行为）

访问模式清单（设计输入 ⚠️ 自拟演示域）：

- R1 按用户取时间线（高频）→ 分区键 `userId`，排序键 `timestamp`：Query 直接命中。
- R2 按帖子取评论（中频）→ 评论另分区键 `postId` 或 GSI `(postId, createdAt)`。
- R3 全站最新热帖（低频）→ 计算属性 `status='published'` 上 GSI `(status, score)`，稀疏索引只收录已发布项。

每一步在 🔧 实验中都有形状对应（见 §7）；三读若全用 Scan 演示，RCU 消耗与延迟阶差即「为什么必须先建模后建表」的论证素材 ⚠️。

## 7. 🔧 本机类比实验（SQLite 3.45.3 / DuckDB 1.5.5；**非 DynamoDB 行为**）

| 组 | 实验与真实输出 | 类比点 | 边界 |
|---|---|---|---|
| D6 | 前缀 17 行→键范围 11 行 | Query 键区间收窄读量 | 无计费 |
| D7 | `SEARCH USING PRIMARY KEY (a=? AND b=?)` | 全键命中计划 | SQLite 无 RCU |
| D14 | 10 分区各 100 行，前缀读=100 行 | 一次 Query 只见一个分区 | 无并行 Segment |
| D16 | 无键条件+Filter+LIMIT：计划出 `SCAN i` | Scan 形态显形 | 全表扫≠分区扫 |
| D18 | DuckDB `WHERE` 下推进 FILTER 节点 | 过滤发生在读层之外 vs FilterExpression 在读层内计费 | 代价方向相反 |
| T7 | UPDATE 冲突条件 0 行返回 | 读己所写的强一致直觉 | 单机事务语义 |

结论句：Query/Scan 之别在**键可得性**；本机实验把「键可得性→计划形态」可视化，但**读量计费与限流**在 SQLite/DuckDB 中不存在——类比止于形状。

## 8. 误区与自检（⚠️）

- 把 Filter 当 WHERE：Filter 是「读后丢弃」不是「少读」✅ 口径。
- 分页=Limit：游标未持久化导致深翻 ⚠️。
- GSI 上做强一致读：不存在该选项 ⚠️→✅。
- 排序在应用层重做：浪费服务端键序红利 ⚠️。
- 并行 Scan 不设 Segment 上限：自造限流风暴 ⚠️。
- 自检四问：键全吗？投影省吗？Filter 薄吗？一致性对吗？⚠️

## 10. 走查示例：Scan 改 Query 三级 refactor（演示域自拟 ⚠️）

原始坏查询：`scan + Filter(status=ACTIVE 且 ts>now-7d)`，每 5 秒轮询一次 ⚠️ 典型反模式。

- L1 改键：把轮询读变成 Query(分区键=视图名, 排序键区间)——建 (viewName, ts) 复合键 ⚠️。
- L2 改索引：原键已被占用 ⇒ 挂 GSI(viewName-hash 桶, ts)，写入侧同步维护 ⚠️。
- L3 改触发：轮询读改 Streams 推（→ [07-AWS生态协同Redshift_S3_MapReduce.md](07-AWS生态协同Redshift_S3_MapReduce.md)）⚠️→✅。
- 账单叙事：三级各砍一个成本因子——L1 砍分区扫全、L2 砍非键项读、L3 砍空轮询 ⚠️。
- 本机形状复演：D16（SCAN 计划）→ D6（键区间收窄）→ T3（变更推代替轮询）。

## 11. 一页总结（本章带走的三个判断 ⚠️+✅）

- 判断一读用不用得起：读量≈键命中量×项大小——估不出就别上线 ⚠️。
- 判断二索引该不该有：第二键空间使用率>阈值才养得起 ⚠️（→ [03-索引体系GSI与LSI.md](03-索引体系GSI与LSI.md)）。
- 判断三一致性选哪边：写后读 UI 强一致、报表类最终一致吃半价 ✅/⚠️。

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| 键查询 | Query | 分区键必带的高效读 ✅ |
| 全表扫描 | Scan | 迭代+过滤的最后手段 ✅ |
| 键条件 | KeyConditionExpression | 键上的谓词（2015 后语法 ⚠️） |
| 过滤表达式 | FilterExpression | 读后丢弃，不省计费 ✅/⚠️ |
| 投影表达式 | ProjectionExpression | 列裁剪 ✅ |
| 并行扫描 | parallel scan (Segment/TotalSegments) | 分段并发换延迟 ⚠️→✅ |
| 强一致读 | strongly consistent read | 全额 RCU 的立即可见 ✅ |
| 最终一致读 | eventually consistent read | 半价默认，滞后窗口 ⚠️ |
| 分页游标 | LastEvaluatedKey | 续读令牌 ✅ |
| 反向序 | ScanIndexForward | 服务端键序双向 ✅ |
