## 核心精讲
- 装饰器本质：返回函数的可调用对象，套在被装饰对象外层。
  - 函数装饰器：`@functools.wraps(target)` 必加，保留 `__name__`/`__doc__`（第 7 章 9.2）。
  - 带参装饰器：`def deco(arg): def _(f): ...; return _; return _`（第 9 章 9.4）。
  - 类装饰器：直接对类做修改/注册（第 9 章 9.12）。
- 元类：`class M(type): def __new__(mcs, n, b, ns): ...`；控制类创建。
  - 轻量替代：`__init_subclass__`（3.6+，第 9 章 9.17）覆盖绝大多数「类注册/规约」需求。
- 类型保留：`ParamSpec`（3.10）让装饰器不丢被包装函数签名类型。

```python
# 教学示意，不参与构建
import functools
def trace(func):
    @functools.wraps(func)
    def wrapper(*a, **k):
        print(func.__name__, a, k)
        return func(*a, **k)
    return wrapper

class Registerable:
    _reg = {}
    def __init_subclass__(cls, **kw):
        super().__init_subclass__(**kw)
        Registerable._reg[cls.__name__] = cls
```

## 版本演进
- **3.6 PEP 0487**：`__init_subclass__` 让轻量元编程免元类。
- **3.10 PEP 0612**：`ParamSpec`/`Concatenate` 类型安全装饰器。
- **3.12 PEP 0695**：`type T = ...`/`def f[T]` 泛型语法，取代部分元类泛型。
- **3.14 PEP 0649**：注解延迟求值，装饰器/元类读注解更省。
- 🔧 现代法则：「能用 `dataclass`/`__init_subclass__`/装饰器解决，就别上元类」。

## 近年研究与工业界（2015–2026）
- 装饰器在 Web 框架（路由、鉴权、缓存、日志）无处不在。
- ORM（SQLAlchemy/Django）用描述符 + 元类做声明式模型。
- 静态类型（mypy/pyright）让 `ParamSpec`/`TypeVar` 元编程类型安全。

## 常见误区与本书需修正之处
| 误区 | 修正 |
|---|---|
| 装饰器不写 `@wraps` | 必加，否则丢元信息 |
| 所有类约束都上元类 | 3.6+ 优先 `__init_subclass__` |
| 元类过度设计 | 装饰器/`dataclass` 多已足够 |
| 注解运行时滥用 | 3.14 前注解即执行，注意成本 |
