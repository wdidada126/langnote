## 核心精讲
- 15.1 `ctypes`：`libc = ctypes.CDLL('libc.so.6'); libc.printf(b"hi\n")`（免编译，最易上手）。
- 15.10 **现代首选 Cython**：`def f(int x): return x * 2` 编译为扩展，性能接近 C。
- 15.7 释放 GIL：`with nogil:`（Cython）或 `Py_BEGIN_ALLOW_THREADS`（C API），让 C 计算并行。
- 15.17 文件名传给 C：用 `os.fsencode`/`PyUnicode_AsEncodedString`（🔧 平台文件系统编码）。
- 15.21 段错误诊断：`faulthandler`（3.3+ 内置）、`gdb` 附加。

## 版本演进
- **3.8 `multiprocessing`/共享内存**：纯 Python 并行有时可取代 C 扩展（15.2 场景）。
- **3.12 PEP 703（实验）**：free-threading 让 C 扩展线程模型更复杂（🔧 扩展需声明 `Py_mod_gil`）。
- **3.13**：C API 稳定化（`Py_UNUSED` 等）；`capi` 逐步受限。
- **3.11+ `faulthandler`**：诊断段错误（15.21）更顺手。
- 🔧 现代扩展多走 `pybind11`（C++）/Cython，原书手写 Python/C API 仅参考。

## 近年研究与工业界（2015–2026）
- `pybind11` 成 C++ 绑定主流；`numba` JIT 免手写扩展。
- `cffi` 在 PyPy 上更高效；Rust→Python（`PyO3`/`maturin`）爆发。
- 科学计算（numpy/scipy）核心是 C/Fortran 扩展。

## 常见误区与本书需修正之处
| 误区 | 修正 |
|---|---|
| 手写 Python/C API 扩展 | 现代用 Cython/pybind11/PyO3 |
| 扩展中忘释放 GIL | 长计算用 `nogil` 提升并行 |
| 段错误无诊断 | 启用 `faulthandler` |
| 文件名直接传 C 串 | 用 `os.fsencode` 处理文件系统编码 |
| 忽视 free-threading | 3.12+ 扩展需声明 GIL 策略 |
