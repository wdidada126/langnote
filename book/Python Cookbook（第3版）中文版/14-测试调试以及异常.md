# 14 章 测试、调试以及异常（原书 pp.约 751–805）

## 本章地图
| 节 | 内容 | 结论 |
|---|---|---|
| 14.1–14.5 | 测试 stdout、打补丁、测异常、日志、忽略/期望失败 | `unittest.mock`/`pytest` |
| 14.6–14.10 | 多异常、捕获所有、自定义异常、抛另异常、重抛 | `except`/`raise ... from` |
| 14.11 | 警告信息 | `warnings` |
| 14.12–14.14 | 崩溃调试、性能测试、加速 | `pdb`/`cProfile`/`timeit` |

## 核心精讲
- 14.2 `unittest.mock.patch` 替换依赖；🔧 现代 `pytest` + `monkeypatch` 更简洁。
- 14.9 `raise NewError("x") from e` 保留链（🔧 优于裸 `raise NewError` 丢原因）。
- 14.10 重抛用 `raise`（不带参数）保留栈。
- 14.13 性能：`cProfile.run('f()')`；14.14 加速定位热点。
- 14.12 调试：`pdb.set_trace()`（3.7+ 用 `breakpoint()`）。

```python
# 教学示意，不参与构建
import warnings
def f(): warnings.warn("deprecated", DeprecationWarning)
try:
    risky()
except ValueError as e:
    raise RuntimeError("bad") from e
```

## 版本演进
- **3.7 PEP 0553**：内置 `breakpoint()` 取代 `pdb.set_trace()`（14.12 升级）。
- **3.11 PEP 0654**：`ExceptionGroup` + `except*`（14.6/14.9 多异常场景现代写法）。
- **3.11 PEP 0678**：`add_note()` 给异常加上下文笔记。
- **3.11**：`traceback` 更丰富；`cProfile` 稳定。
- **3.12+**：`pytest` 生态为测试事实标准（14.1–14.5）。
- 🔧 原书基于 `unittest`，现代项目多用 `pytest`。

## 近年研究与工业界（2015–2026）
- `pytest` + `hypothesis`（基于属性测试）成主流。
- `ExceptionGroup` 让库能一次性报告多错误（如 pydantic v2）。
- 结构化日志 + `rich.traceback` 提升排障体验。

## 常见误区与本书需修正之处
| 误区 | 修正 |
|---|---|
| `except Exception: pass` 吞异常 | 显式捕获，必要时 `raise` |
| 裸 `raise New from None` 丢链 | 用 `raise New from e` 保留原因 |
| 多异常逐一 try | 3.11+ `except* ValueError` |
| `pdb.set_trace()` | 3.7+ 用 `breakpoint()` |
| 仅 `unittest` | 现代用 `pytest` + `monkeypatch` |
