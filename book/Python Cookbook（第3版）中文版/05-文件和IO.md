# 05 章 文件和 I/O（原书 pp.约 251–309）

## 本章地图
| 节 | 内容 | 结论 |
|---|---|---|
| 5.1–5.3 | 读写文本、输出到文件、分隔符/行尾 | `open(mode='rt')`、`print(..., file=)` |
| 5.4–5.6 | 字节数据、仅当不存在才写、字符串 I/O | `io.BytesIO`/`StringIO` |
| 5.7–5.10 | 压缩文件、固定记录迭代、缓冲区、内存映射 | `gzip`/`mmap` |
| 5.11–5.15 | 路径操作、存在性、列表、忽略编码、打印非法名 | `pathlib`（3.4+） |
| 5.16–5.21 | 改编码、字节写文本、fd 包装、临时文件、串口、序列化 | `tempfile`、`pickle` |

## 核心精讲
- 5.1 `with open(path, 'rt', encoding='utf-8') as f: data = f.read()`。
- 5.7 `gzip.open(path, 'rt')` 透明读写压缩文件。
- 5.11 现代写法用 `pathlib.Path`：`p = Path('a/b.txt'); p.read_text(encoding='utf-8')`。
- 5.19 `tempfile.NamedTemporaryFile(delete=False)` 建临时文件。
- 5.21 `pickle.dump(obj, f)`（🔧 仅信得过的数据，反序列化有 RCE 风险）。

```python
# 教学示意，不参与构建
from pathlib import Path
import gzip, tempfile
text = Path("data.txt").read_text(encoding="utf-8")
with gzip.open("x.gz", "wt") as g: g.write(text)
```

## 版本演进
- **3.4 PEP 0428**：`pathlib` 成为首选路径 API，取代 `os.path` 拼接（5.11–5.15 整体升级）。
- **3.6**：`Path.read_text/write_text/read_bytes/write_bytes` 便捷方法。
- **3.12**：`pathlib` 大量增强（`Path.walk` 等）。
- **3.13 PEP 594**：移除 `formatter` 等旧模块；`pickle` 仍是标准但需谨慎（5.21）。
- `mmap`（5.10）仍可用，但大文件多改用 `mmap`/`numpy.memmap` 或流式。

## 经典论文与原始文献
- PEP 0428 `pathlib`（3.4）；PEP 0519 `os`/`os.scandir` 性能。
- `io` 模块（`StringIO`/`BytesIO`）设计；`gzip`/`mmap` 标准库。
- 🔧 具体编号/年份以 https://peps.python.org/ 为准。

## 近年研究与工业界（2015–2026）
- `pathlib` 几乎统一路径操作；类型检查器（`mypy`）原生支持 `Path`。
- 大文件流式用 `mmap`/`readinto`；对象存储（S3）催生 `smart_open` 之类抽象。
- 序列化安全：JSON/MessagePack 取代 `pickle` 跨信任边界场景。

## 常见误区与本书需修正之处
| 误区 | 修正 |
|---|---|
| 用 `os.path.join` 拼路径 | 3.4+ 用 `pathlib.Path`（PEP 428） |
| `pickle` 随意反序列化外部数据 | 有 RCE 风险，改 JSON/MessagePack |
| 手写临时文件 | 用 `tempfile`（5.19），勿自造 |
| 忽略 `encoding` | 显式 `encoding='utf-8'`，避免平台默认码 |
| `mmap` 大文件当万能 | 多数场景流式 IO 够用，必要时 `numpy.memmap` |
