## 核心精讲
- 9.2 `import functools; @functools.wraps(func)` 保留 `__name__`/`__doc__`（不加会丢元信息）。
- 9.4 带参装饰器：`def deco(arg): def _(f): ...; return _; return _`。
- 9.13 元类 `class Meta(type): def __call__(cls, *a, **k): ...` 控制实例创建。
- 9.18 运行时建类：`T = type('T', (Base,), {'x': 1})`。
- 9.21 用 `__init_subclass__` 取代轻量元类（3.6+ 优先）。

```python
# 教学示意，不参与构建
import functools
def logged(func):
    @functools.wraps(func)
    def wrapper(*a, **k):
        print(func.__name__)
        return func(*a, **k)
    return wrapper
```

## 版本演进
- **3.6 PEP 0487**：`__init_subclass__` 让多数「类注册/规约」无需元类（9.17 简化）。
- **3.9 PEP 0591**：`@final` 在元编程约束中有用。
- **3.10 PEP 612**：`ParamSpec` 让装饰器保留被包装函数签名类型。
- **3.12 PEP 695**：`type T = ...`/`class C[T]` 取代部分元类泛型技巧。
- **3.14 PEP 649**：注解延迟求值（装饰器/元类读注解更省、更安全）。
- 🔧 现代实践「能用 `__init_subclass__` 就别上元类」。

## 近年研究与工业界（2015–2026）
- 装饰器在 Web 框架（路由、鉴权）、缓存、日志中无处不在。
- ORM（SQLAlchemy/ Django）用描述符+元类做声明式模型。
- 静态类型（mypy/pyright）让 `ParamSpec`/`TypeVar` 元编程类型安全。

## 常见误区与本书需修正之处
| 误区 | 修正 |
|---|---|
| 装饰器不写 `@wraps` | 必加 `functools.wraps`，否则丢元信息 |
| 所有「类约束」都上元类 | 3.6+ 优先 `__init_subclass__` |
| 元类过度设计 | 多数场景装饰器/`dataclass` 足够 |
| 注解当运行时数据滥用 | 3.14 前注解即执行，注意成本；3.14 延迟求值 |
| `exec` 解析源码 | 用 `ast` 模块更安全（9.24） |
