## 核心精讲
- 2.1 `re.split(r'[;,\s]\s*', s)` 多分隔符拆分。
- 2.5 `re.sub(r'(\d+)', r'\1', s)` 替换；用函数回调做复杂替换。
- 2.9 `unicodedata.normalize('NFC', text)` 合并等价字符，比较前先归一化。
- 2.11 `s.translate(str.maketrans('', '', '　'))` 删除字符（🔧 演示用全角空格占位，实际按需列）。
- 2.15 字符串插入变量：`str.format` 或 3.6+ f-string（更简洁）。

```python
# 教学示意，不参与构建
import re, unicodedata
tokens = re.split(r"[;,\s]\s*", "a, b; c  d")
clean = unicodedata.normalize("NFC", "café")
name = "world"
greet = f"hello {name}"  # 3.6+
```

## 版本演进
- **3.6 PEP 498**：f-string 取代 2.15 的 `.format`/模板占位（更可读、更快）。
- **3.9 PEP 616**：`str.removeprefix`/`removesuffix` 取代手写切片或 `re` 去前缀后缀。
- **3.12 PEP 701**：f-string 语法放开（可复用引号、多行、内嵌反斜杠），旧式引号冲突配方升级更自由。
- **3.14 PEP 750**：`t-string`（模板字符串）引入，适合安全拼接 SQL/HTML 等场景，弥补 2.17 手写转义的不足。
- `str`/`bytes` 严格区分（3.x 默认），2.20 字节串处理与文本串需显式 `decode`/`encode`。

## 经典论文与原始文献
- `re` 模块（Henry Spencer 正则引擎移植）；`fnmatch` 通配语义。
- PEP 0498 f-string（3.6）；PEP 0616 前后缀删除（3.9）；PEP 0701 f-string 放宽（3.12）；PEP 0750 t-string（3.14）。
- 🔧 具体编号/年份以 https://peps.python.org/ 为准。

## 近年研究与工业界（2015–2026）
- Web 框架（FastAPI/Starlette）大量用类型化字符串与 Pydantic 校验，文本解析趋于「声明式」。
- 安全转义（2.17）被模板引擎、ORM 参数化查询接管，手写 `html.escape` 仍有用。
- `regex` 第三方库支持更全的 Unicode 属性，作为标准 `re` 补充。

## 常见误区与本书需修正之处
| 误区 | 修正 |
|---|---|
| 用 `%`/`.format` 拼字符串 | 3.6+ 优先 f-string（PEP 498） |
| 切片去前缀/后缀 | 3.9+ 用 `removeprefix`/`removesuffix`（PEP 616） |
| 比较 Unicode 前未 normalize | 先用 `unicodedata.normalize('NFC', ...)` |
| 手写 HTML/SQL 转义 | 用模板引擎/参数化，3.14+ 可试 t-string |
| 把 `bytes` 当 `str` 混用 | 3.x 严格区分，显式编解码 |
