# 第 4 章 当索引行不通时（原书 pp.54-63）

> 一句话定位：用「名字 → 值」的映射取代「位置 → 值」的序列，讲清 `dict` 的创建、键类型约束、字符串格式化与全部方法，并点出它相对于 list 的性能优势。基线：原书 Python 3.5；本目录按 3.12+ 校验。
> 对应英文章名：Dictionaries: When Indices Won't Do

## 核心精讲

> 以下均为**教学示意，不参与构建**：片段自足，可直接 `python x.py` 运行。

### 1. 键必须可哈希——这是 dict 唯一的硬约束

```python
# demo_ch4_keys.py —— 教学示意，不参与构建
d = {"name": "Ann", "age": 42, 42: "answer", (1, 2): "coord"}
print(d["name"], d[42], d[(1, 2)])     # Ann answer coord

try:
    d[[1, 2]] = "oops"                 # TypeError: unhashable type: 'list'
except TypeError as e:
    print("不可哈希：", e)

print(hash("abc") == hash("abc"))      # True（同进程内稳定）
# 注意：str/bytes 的 hash 带随机盐，跨进程不保证相同（PYTHONHASHSEED）
```

判据：**键必须是不可变（可哈希）对象**——`str`/`int`/`float`/`bool`/`None`/`tuple`（元素也必须可哈希）/`frozenset`。

### 2. 四种构造方式 + 视图对象

```python
# demo_ch4_build.py —— 教学示意，不参与构建
a = dict(name="Ann", age=42)                  # 关键字（键必须是合法标识符）
b = dict([("name", "Ann"), ("age", 42)])      # 键值对序列
c = dict(zip(["name", "age"], ["Ann", 42]))   # zip 拉链
d = dict.fromkeys(["a", "b"], 0)              # 同默认值；注意默认值是可变对象时同样共享
e = {k: v * 2 for k, v in zip("abc", range(3))}  # 字典推导
print(a == b == c, d, e)                      # True {'a': 0, 'b': 0} {'a': 0, 'b': 2, 'c': 4}

print(a.keys(), a.values(), a.items())        # 视图对象，不是 list
print(list(a.items()))                        # [('name', 'Ann'), ('age', 42)]
print("age" in a.keys(), "Ann" in a.values(), ("age", 42) in a.items())  # True True True
print(len(a.keys() & {"name"}))               # 1 —— 视图支持集合运算
```

**视图是动态的**：字典改了，视图立刻反映，不需要重新取。这与 `list(d.keys())`（快照）行为不同。

### 3. 方法全家桶与「缺省值」三种写法

```python
# demo_ch4_methods.py —— 教学示意，不参与构建
d = {"a": 1, "b": 2}
print(d.get("z", 0))                  # 0 —— 取不到给默认，不改字典
print(d.setdefault("z", []))          # [] —— 取不到就写入并返回
print(d)                              # {'a': 1, 'b': 2, 'z': []}
print(d.pop("z"), d.pop("zz", None))  # [] None —— pop 必须给缺省才安全
d.update({"c": 3}, d=4)               # 批量更新（可传映射或关键字）
print(d)                              # {'a': 1, 'b': 2, 'c': 3, 'd': 4}
print(d.popitem())                    # ('d', 4) —— 3.7+ 保证 LIFO（删最后插入的）
print({**d, "e": 5})                  # {'a':1,'b':2,'c':3,'e':5} 解包合并
print(d | {"x": 0})                   # 3.9+ 合并运算符，同上但更清晰
d |= {"x": 0}                         # 3.9+ 就地更新
print(d)
```

分组/计数场景的三种写法（**2026 年推荐顺序从上到下**）：

```python
# demo_ch4_group.py —— 教学示意，不参与构建
from collections import defaultdict, Counter

words = ["a", "b", "a", "c", "b", "a"]
print(Counter(words).most_common(2))              # [('a', 3), ('b', 2)]

g = defaultdict(list)                              # 比 setdefault 更省心
for i, w in enumerate(words):
    g[w].append(i)
print(dict(g))                                     # {'a': [0,2,5], 'b': [1,4], 'c': [3]}
```

- `setdefault` 每次都要构造默认对象（`d.setdefault(k, []).append(v)` 会白造一个 list）；`defaultdict` 只在缺键时才造。
- 原书只用 `setdefault` 演示，2026 年**计数用 `Counter`、分组用 `defaultdict`** 是常态。

### 4. 用字典做字符串格式化：原书写法 vs 现代写法

```python
# demo_ch4_format.py —— 教学示意，不参与构建
person = {"name": "Ann", "age": 42}
print("Hi, {name}! You are {age}.".format_map(person))  # 原书 4.2.3 的写法
print(f"Hi, {person['name']}! You are {person['age']}.")  # 3.6+ 推荐：能看清来源
print("{name}".format(**person))                    # 也可，但多一次解包
```

`format_map` 的意义在于**不拷贝字典**（`format(**d)` 会生成新字典）；在模板外部化时仍有价值。

## 近年研究与工业界开源实践（2015–2026）

- **紧凑 dict（3.6）**：CPython 把「稀疏索引表 + 紧凑条目数组」分开，纯数字键场景内存显著下降。这是工程优化而非论文，记录于 CPython 的 `Objects/dictobject.c` 注释与开发者博客（非同行评审）。
- **哈希随机化**：`PYTHONHASHSEED` 默认随机，用于防御 Hash-DoS（构造大量同桶键把 O(1) 打成 O(n)）。这是 Web 框架普遍强制的安全实践，与本章「键必须可哈希」直接相关。
- **类型化字典**：`TypedDict`（3.8 起）让「字典当结构化记录」有了静态类型；`pydantic`/`msgspec` 把这套思路推进到运行时校验与序列化，是原书完全未覆盖的 2020 年代主流。
- **持久化与序列化**：`json`/`orm` 层普遍以 dict 为中间表示；`SQLAlchemy` 的 `Row._mapping`、`dataclasses.asdict` 都是「对象 ↔ dict」转换。
- **研究侧**：哈希表研究（如 Swiss Tables、Robin Hood hashing）影响的是 C++ 生态（`abseil`）；CPython 仍用开放寻址的自定义实现，本章结论不受影响。🔧 具体论文本目录不引用，避免编造。

## 常见误区与本书需修正之处

| # | 原书说法 / 常见误解 | 问题 | 2026 正确写法 |
| --- | --- | --- | --- |
| 1 | 🔧「字典是无序的」（原书基于 3.5 口径） | 3.7 起**语言规范保证插入序** | 可以放心依赖顺序；需要排序仍用 `sorted(d.items())` |
| 2 | 「`d[k]` 取不到返回 `None`」 | 抛 `KeyError` | `d.get(k, default)` 或 `d[k] if k in d else ...` |
| 3 | 🔧「用 `setdefault` 分组」 | 每次都构造默认对象 | `collections.defaultdict(list)`，计数用 `Counter` |
| 4 | 「`dict.copy()` 是深拷贝」 | 浅拷贝，值里的 list 仍共享 | `copy.deepcopy(d)`（注意性能与循环引用） |
| 5 | 「`{**a, **b}` 与 `a.update(b)` 一样」 | 前者产生新 dict，后者改 `a` | 要新对象用 `a \| b`（PEP 584）或 `{**a, **b}` |
| 6 | 🔧「用 `typing.Dict` 注解」 | 3.9 起软弃用 | `dict[str, int]`（PEP 585） |
| 7 | 「遍历 dict 时增删会怎样」 | 抛 `RuntimeError: dictionary changed size during iteration` | 先 `list(d.items())` 快照，或用推导式重建 |
| 8 | 「`keys()` 返回列表」 | 返回**视图**（动态、支持集合运算） | 需要列表就 `list(d)` / `list(d.keys())` |
| 9 | 「元组当键一定安全」 | 元素也必须可哈希 | `(1, [2])` 不可哈希；用 `(1, (2,))` 或 `frozenset` |
| 10 | 用 `bool` 键与 `1`/`0` 混用 | `hash(True) == hash(1)`，会互相覆盖 | 避免同一 dict 里混用 `True/1`、`False/0` |
| 11 | 🔧 原书未提 `|` 运算符合并字典 | 3.9 起有更直观的写法 | `merged = a \| b`；就地 `a \|= b` |
| 12 | 「字典查找一定 O(1)」 | 哈希碰撞严重时退化 | 对用户可控的键输入，注意 Hash-DoS 防护（框架层通常已处理） |
