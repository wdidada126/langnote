## 核心精讲

### 1. Tkinter 三步走（原书示例的现代写法）

> 教学示意，不参与构建。Tkinter 需要图形环境：**本机 Python 未编译 Tk 支持**（`import tkinter` 报 `ModuleNotFoundError`），下列代码仅做语法校验；Linux 需装 `python3-tk`，Windows/macOS 用 python.org 官方安装包即可。

```python
import tkinter as tk
from tkinter import messagebox, ttk


class Editor(tk.Frame):
    def __init__(self, master=None):
        super().__init__(master)
        self.pack(fill=tk.BOTH, expand=True)
        self.text = tk.Text(self, wrap=tk.WORD)
        self.text.pack(fill=tk.BOTH, expand=True)
        self.text.bind("<KeyRelease>", self.on_change)          # 事件绑定
        ttk.Button(self, text="字数", command=self.on_count).pack(side=tk.LEFT)
        ttk.Button(self, text="退出", command=self.master.destroy).pack(side=tk.RIGHT)

    def on_change(self, event):
        self.master.title(f"已输入 {len(self.text.get('1.0', 'end-1c'))} 字")

    def on_count(self):
        words = len(self.text.get("1.0", "end-1c").split())
        messagebox.showinfo("字数", str(words))


def main():
    root = tk.Tk()
    root.title("简易编辑器")
    Editor(root)
    root.mainloop()                                              # 事件循环


if __name__ == "__main__":
    main()
```

要点：

- **`tkinter`（全小写）**：Python 2 的 `Tkinter` 在 Python 3 已改名，网上旧代码照抄会 `ModuleNotFoundError`。
- **几何管理器**：`pack` 按边堆叠、`grid` 按行列（复杂表单首选）、`place` 绝对定位（几乎只在做自定义画布时用）。三者**不要混用在同一个容器里**。
- **事件**：`command=` 给按钮，`bind("<KeyRelease>", handler)` 给键盘/鼠标，`StringVar`/`IntVar` 做数据与控件双向绑定。
- **`mainloop()` 之后不再往下走**：所有逻辑都在回调里发生；耗时任务必须丢给线程/`asyncio`/子进程，再用 `root.after()` 把结果送回主线程更新 UI（Tk 不是线程安全的）。

### 3. 2026 年的选择：GUI 工具包对照

| 方案 | 许可 | 安装 | 适用 |
| --- | --- | --- | --- |
| **Tkinter** | Python 自带 | 无需安装（部分发行版需 `python3-tk`） | 教学、小工具、无依赖分发 |
| **PySide6**（Qt for Python） | LGPL | `pip install pyside6` | 跨平台桌面应用的默认选择 |
| **PyQt6** | GPL / 商业双许可 | `pip install pyqt6` | 同上，注意许可 |
| **wxPython** | wxWindows 许可 | `pip install wxpython` | 原生外观，老项目常见 |
| **Kivy** | MIT | `pip install kivy` | 触控、移动端、非标准界面 |
| **Textual**（+ Rich） | MIT | `pip install textual` | **终端 UI**，无需图形环境，SSH 友好 |
| **NiceGUI / Streamlit / Gradio** | 多为 Apache-2.0 | `pip install nicegui` | 用 Python 写 Web UI，内部工具与数据应用 |
| **Web 前端 + FastAPI** | — | 见第 15 章 | 团队内部系统的主流形态：浏览器即客户端 |

选择原则：**要分发给外部用户的桌面程序 → Qt；给团队用的内部工具 → Web UI（FastAPI/NiceGUI）；运维/CLI 场景 → Textual**；Tkinter 只在你必须「零依赖」时才占优。

### 4. Textual 的最小骨架（需安装后运行）

> 教学示意，不参与构建：需先 `pip install textual`，且要真终端。

```python
from textual.app import App, ComposeResult
from textual.widgets import Button, Label


class Hello(App):
    def compose(self) -> ComposeResult:
        yield Label("你好，终端 UI")
        yield Button("点我")

    def on_button_pressed(self) -> None:
        self.exit("done")


if __name__ == "__main__":
    Hello().run()
```

它是**声明式**的（`compose` 描述结构、事件方法响应），与 Tkinter 的命令式「一个个 new 出来再 pack」形成对照——这也是近十年 UI 框架的整体走向。

## 近年研究与工业界开源实践（2015–2026）

- **声明式 UI 成为主流**：从 Web 的 React/Vue 到桌面 SwiftUI/Jetpack Compose，再到 Python 侧的 Textual、NiceGUI，共性是「描述状态 → 框架负责渲染」；Tkinter 的命令式写法在复杂界面上维护成本明显更高。
- **PySide6 / PyQt6**：Qt 6 时代信号槽与 QML 分工明确，官方 Qt for Python 绑定（PySide6）因 LGPL 许可被商业项目广泛采用。
- **终端 UI 复兴**：Textual + Rich 让「SSH 里也能有好看的界面」成为现实，特别适合运维工具与开发机上的仪表盘（工具文档，非同行评审）。
- **Web UI 化**：NiceGUI、Streamlit、Gradio 把「写界面」压缩成几十行 Python，数据/ML 场景几乎已经不用桌面 GUI；代价是部署从「发一个 exe」变成「起一个服务」。
- **分发与打包**：桌面端仍要面对 PyInstaller/Nuitka 打包、代码签名、自动更新与 Tcl/Tk 依赖；这是 Tkinter 之外所有桌面方案共同的隐性成本（见第 18 章）。
- 以上均为**工业界实践或工具文档，非同行评审论文**。

## 常见误区与本书需修正之处

| # | 原书说法 / 常见误区 | 问题 | 2026 正确写法 |
| --- | --- | --- | --- |
| 1 | 🔧 沿用 `import Tkinter`（大写 T） | Python 3 已改名小写 `tkinter`，照抄旧代码直接报错 | `import tkinter as tk`；主题控件用 `from tkinter import ttk` |
| 2 | 🔧 把 Tkinter 当作「Python GUI 的默认选择」 | 它仍在标准库，但界面风格与现代需求（HiDPI、异步、富组件）脱节 | 桌面用 PySide6/PyQt6；内部工具用 Web UI；CLI 场景用 Textual |
| 3 | 认为装了 Python 就一定有 Tkinter | Linux 发行版常把 Tk 拆成 `python3-tk`；精简镜像也可能缺 | 先 `importlib.util.find_spec("tkinter")` 自检 |
| 4 | 在回调里跑网络请求/大计算 | 阻塞事件循环，界面假死 | 线程 / `asyncio` / 子进程 + `root.after()` 回到主线程更新 UI |
| 5 | 混用 `pack` 与 `grid` | 同一容器内混用会报几何管理器冲突 | 一个容器只用一种；复杂布局用嵌套 `Frame` |
| 6 | 用 `place(x=..., y=...)` 排全部控件 | 绝对坐标在缩放/换字体后全乱 | 只在画布类场景用；常规布局用 `grid` |
| 7 | 跨线程直接改控件 | Tk 非线程安全，可能随机崩溃 | 只在主线程操作控件，用队列/`after` 传递 |
| 8 | 业务逻辑写在控件类里 | 无法单测，且与 GUI 框架绑死 | 逻辑与界面分离，逻辑层纯 Python 可测（呼应第 16 章） |
| 9 | 认为 GUI 程序「跑完 `main()` 就结束」 | 控制权在 `mainloop()` | 退出用 `destroy()` / `App.exit()`，并在退出前收尾线程与文件 |
