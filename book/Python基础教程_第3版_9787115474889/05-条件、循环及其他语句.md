# 第 5 章 条件、循环及其他语句（原书 pp.64-89）

## 核心精讲

> 以下均为**教学示意，不参与构建**：片段自足，可直接 `python x.py` 运行。

### 1. 赋值魔法

```python
# demo_ch5_assign.py —— 教学示意，不参与构建
a, b = 1, 2
a, b = b, a                       # 交换：右侧先求值为元组，再解包
print(a, b)                       # 2 1

first, *middle, last = range(5)   # 星号收集剩余
print(first, middle, last)        # 0 [1, 2, 3] 4
name, _, _, score = ("Ann", 42, "x", 99)   # _ 作「我不关心」占位
print(name, score)                # Ann 99

x = y = []                        # 🔴 二者指向同一列表
x.append(1); print(y)             # [1]
x, y = [], []                     # 想要两个独立列表就要写两次

nums = [1, 2]
alias = nums
nums += [3]                       # list.__iadd__：就地扩展
print(alias)                      # [1, 2, 3] —— alias 也变了
n = 1
n += 1                            # int 不可变：重新绑定，不涉及就地
```

### 2. 条件与布尔：短路是「免费的 if」

```python
# demo_ch5_cond.py —— 教学示意，不参与构建
print(bool(""), bool([]), bool(0), bool("0"), bool([0]))   # False False False True True
print(1 < 2 < 3, 1 == 1 < 2)                               # True True —— 链式比较
print([] == [], [] is [])                                   # True False —— 值相等 vs 同一对象

name = None
print(name or "anonymous")         # anonymous —— or 返回第一个真值（或其本身）
print(name and name.upper())       # None

x = 5
print("even" if x % 2 == 0 else "odd")     # odd —— PEP 308 条件表达式
if (n := len([1, 2, 3])) > 2:              # 3.8+ 海象运算符（PEP 572）
    print(f"too many: {n}")
```

### 3. 循环、迭代工具与 `else` 子句

```python
# demo_ch5_loops.py —— 教学示意，不参与构建
names = ["ann", "bob"]
scores = [90, 80]
for i, nm in enumerate(names, start=1):        # PEP 279
    print(i, nm, sep=" -> ", end="; ")
print()

for nm, sc in zip(names, scores, strict=True):  # 3.10+ strict 防长度不一致
    print(f"{nm}: {sc}")

for nm in reversed(sorted(names)):              # reversed 需要序列/实现 __reversed__
    print(nm, end=" ")
print()

d = {"a": 1, "b": 2}
for k, v in d.items():                          # 迭代字典的标准写法
    print(k, v, end=" ")
print()

# 循环 else：没被 break 才执行
for n in range(2, 10):
    for p in range(2, int(n ** 0.5) + 1):
        if n % p == 0:
            break
    else:
        print(n, end=" ")                       # 2 3 5 7
print()

while True:                                     # 未知次数的循环
    s = "quit"
    if s == "quit":
        break

assert len(names) == 2, "names 应有两个元素"      # 断言：内部不变量
```

### 4. 推导式与 `match`（3.10+ 补充）

```python
# demo_ch5_comp.py —— 教学示意，不参与构建
squares = [x * x for x in range(5)]
evens = [x for x in range(10) if x % 2 == 0]
matrix = [[r * c for c in range(3)] for r in range(3)]
word_len = {w: len(w) for w in ["a", "bb"]}
uniq = {len(w) for w in ["a", "bb", "c"]}
flat = [x for row in matrix for x in row]        # 嵌套推导：外层循环在前
print(squares, evens, word_len, uniq, len(flat)) # [0,1,4,9,16] [0,2,4,6,8] {'a':1,'bb':2} {1,2} 9

def describe(v):
    match v:                                     # PEP 634/635/636
        case [first, *rest] if len(rest) > 1:
            return f"list: {first} +{len(rest)}"
        case {"name": str(n), "age": int(a)}:
            return f"person {n} ({a})"
        case int() | float():
            return "number"
        case _:
            return "other"

print(describe([1, 2, 3]), describe({"name": "Ann", "age": 3}), describe(1.5))
```

### 5. 三人行：`pass` / `del` / `exec`+`eval`

```python
# demo_ch5_three.py —— 教学示意，不参与构建
def todo():      # pass 作占位，保证语法完整
    pass

a = [1, 2, 3]
del a[1]         # del 删的是「名字/槽位」，不是对象；对象由 GC 回收
print(a)         # [1, 3]

scope: dict[str, object] = {}
exec("value = 6 * 7", scope)     # exec 无返回值，需传命名空间承接结果
print(scope["value"])            # 42
print(eval("6 * 7"))             # 42 —— eval 只求值单个表达式
print(eval("x + 1", {"x": 1}))   # 2
# ❌ 反例（不要做）：eval(user_input) —— 等价把解释器交给用户
```

`exec` 在函数内有个经典陷阱：**它无法修改函数的局部变量**（局部命名空间在编译期已确定），必须显式传入 dict。

## 近年研究与工业界开源实践（2015–2026）

- **静态检查取代「断言式防御」**：`ruff` 与 `mypy`/`pyright` 把「不可达分支、冗余 `else`、循环变量泄漏」等检查进 CI；`flake8`/PyLint（原书第 16 章提到的工具）在 2026 年已基本被 `ruff` 取代（社区工具演进，非同行评审）。
- **`match` 的实际采纳**：`match` 在**解析类代码**（AST 遍历、协议分派、CLI 参数树）中收益最大；在普通业务逻辑里，`if/elif` 仍更易读——这是 CPython 与社区多轮讨论后的普遍共识（非同行评审）。
- **`exec/eval` 的安全共识**：OWASP 与各类安全指南把 `eval(user_input)` 列为代码注入；替代品是 `ast.literal_eval`（只解析字面量）、`json.loads`、或专用 DSL + 白名单。
- **循环性能**：3.11 的 Faster CPython 与 3.12 的推导式内联让 `[x for x in it]` 明显快于 `list.append` 循环；`for` 循环本身也被 specialized adaptive interpreter 加速。
- **教学研究侧**：关于「先教 `while` 还是先教 `for`」「块结构用缩进还是花括号」的研究属于编程教育（computing education research）领域，结论因学习者背景而异；🔧 本目录不引用具体论文，避免编造。

## 常见误区与本书需修正之处

| # | 原书说法 / 常见误解 | 问题 | 2026 正确写法 |
| --- | --- | --- | --- |
| 1 | 🔧「`print` 后要加括号吗」的旧困惑 | 3.x 是函数，必加括号 | `print(a, b, sep=", ", end="", file=sys.stderr)` |
| 2 | 「`x = y = []` 得到两个空列表」 | 同一对象 | `x, y = [], []` |
| 3 | 「`a += b` 一定等价于 `a = a + b`」 | 对 list 是**就地扩展**，会波及别名 | 想要新列表写 `a = a + b` 或 `a[:] = ...` |
| 4 | 「`==` 与 `is` 差不多」 | `==` 比值，`is` 比身份 | 判 `None` 用 `is`；判值用 `==` |
| 5 | 「`0 < x < 10` 是怪写法」 | 链式比较，语义正确且可读 | 放心使用；等价于 `0 < x and x < 10`（且 `x` 只求值一次） |
| 6 | 🔧 原书用 `while i < len(seq): ... i += 1` | 非地道 | `for item in seq`，要下标用 `enumerate` |
| 7 | 「循环 `else` 是 if-else 的 else」 | 是「未被 `break`」时执行 | 常用于搜索收尾；读代码时容易误读，可考虑改写成早返回 |
| 8 | 「`assert` 可用于参数校验」 | `-O` / `PYTHONOPTIMIZE` 会剔除断言 | 公开接口校验用 `if ...: raise ValueError(...)` |
| 9 | 🔧「`eval(input())` 方便」 | 代码注入 | `ast.literal_eval` / `json.loads` / 明确的类型转换 |
| 10 | 「`exec` 能改函数里的局部变量」 | 局部命名空间编译期固定 | 显式传 `exec(code, namespace_dict)` |
| 11 | 🔧「多分支用 `if/elif/elif/...` 到底」 | 3.10 起有模式匹配 | 数据结构分派用 `match`；简单值判断仍用 `elif` |
| 12 | 「`del x` 会立刻释放内存」 | 只解绑名字，对象由 GC 处理 | 只删引用；循环引用靠 GC 回收 |
| 13 | 「推导式里可以随便改外部变量」 | 3.12 内联后作用域更严格，且推导式本就有独立作用域 | 需要副作用就写显式 `for` 循环 |
