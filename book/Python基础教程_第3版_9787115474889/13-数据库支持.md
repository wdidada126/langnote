## 核心精讲

> 教学示意，不参与构建：以下片段全部用内存数据库，可直接运行。

### 1. DB-API 2.0 的四块拼图

| 组成 | 内容 | 备注 |
| --- | --- | --- |
| 全局变量 | `apilevel`（"2.0"）、`threadsafety`（0–3）、`paramstyle`（`qmark`/`format`/`numeric`/`named`/`pyformat`） | `sqlite3` 用 **`qmark`**（`?`）；`psycopg` 用 `pyformat`（`%s`） |
| 异常 | `StandardError`→`Warning`；`Error`→`InterfaceError`/`DatabaseError`→`DataError`/`OperationalError`/`IntegrityError`/`InternalError`/`ProgrammingError`/`NotSupportedError` | 在 `sqlite3` 里都挂在 `sqlite3` 模块下，如 `sqlite3.IntegrityError` |
| 连接对象 | `close()`、`commit()`、`rollback()`、`cursor()` | 事务在连接上 |
| 游标对象 | `execute()`、`executemany()`、`fetchone()`、`fetchmany(n)`、`fetchall()`；属性 `description`、`rowcount`、`arraysize` | `rowcount` 对 `SELECT` 常为 -1，别依赖它 |

```python
import sqlite3

conn = sqlite3.connect(":memory:")
print("apilevel / paramstyle:", sqlite3.apilevel, sqlite3.paramstyle)
try:
    conn.execute("SELECT * FROM nope")
except sqlite3.OperationalError as e:      # 只捕准备处理的那一层
    print("异常链:", type(e).__name__, "->", type(e).__mro__[1].__name__)
conn.close()
```

### 2. `sqlite3` 起步：参数化查询是硬规矩

```python
import sqlite3

with sqlite3.connect(":memory:") as conn:
    conn.execute("CREATE TABLE food (id INTEGER PRIMARY KEY, name TEXT UNIQUE)")
    conn.executemany(
        "INSERT INTO food (name) VALUES (?)",      # ? 占位符，绝不字符串拼接
        [("apple",), ("banana",)],
    )
    cur = conn.execute("SELECT id, name FROM food WHERE name LIKE ?", ("a%",))
    print("description:", [d[0] for d in cur.description])
    print("fetchall:", cur.fetchall())
```

`with sqlite3.connect(...)` 在**成功时 `commit()`、异常时 `rollback()`**，但**不会 `close()`**——要关闭请显式 `conn.close()`，或用 `contextlib.closing`。这一点常被记反。

拼字符串的代价：

```python
import sqlite3

with sqlite3.connect(":memory:") as conn:
    conn.execute("CREATE TABLE food (id INTEGER PRIMARY KEY, name TEXT)")
    name = "x'; DROP TABLE food; --"
    # conn.execute(f"SELECT * FROM food WHERE name = '{name}'")   # ❌ 拼接：注入
    print("参数化查询:", conn.execute("SELECT * FROM food WHERE name = ?", (name,)).fetchall())
    print("表还在吗:", conn.execute("SELECT count(*) FROM sqlite_master WHERE type='table'").fetchone())
```

### 3. 事务：3.12 起多了一个 `autocommit`

```python
import sqlite3

legacy = sqlite3.connect(":memory:")
print("默认 autocommit:", legacy.autocommit)       # -1：沿用旧的 isolation_level 行为
explicit = sqlite3.connect(":memory:", autocommit=True)
print("显式 autocommit:", explicit.autocommit)     # True：每条语句自动提交
legacy.close(); explicit.close()
```

`Connection.autocommit` 是 **3.12 新增**的属性（本机 3.13 验证）：默认 `-1` 表示沿用 `isolation_level` 的旧事务控制；设为 `True`/`False` 可显式切换；🔧 语义细节以 `sqlite3` 官方文档为准。旧代码里常见的 `conn.isolation_level = None`（关闭隐式事务）现在有了更清晰的对口写法。

### 4. 数据库应用程序示例：把 SQL 收进数据层

```python
import sqlite3


def init(db_path=":memory:"):
    conn = sqlite3.connect(db_path)
    conn.execute("PRAGMA foreign_keys = ON")        # SQLite 默认不开启外键约束
    conn.execute("CREATE TABLE IF NOT EXISTS food (id INTEGER PRIMARY KEY, name TEXT UNIQUE)")
    return conn


def add_food(conn, name):
    with conn:                                      # 事务：成功 commit，异常 rollback
        conn.execute("INSERT OR IGNORE INTO food (name) VALUES (?)", (name,))


def find(conn, keyword):
    conn.row_factory = sqlite3.Row                  # 让行像 dict 一样取值
    cur = conn.execute("SELECT * FROM food WHERE name LIKE ?", (f"%{keyword}%",))
    return [dict(row) for row in cur.fetchall()]


conn = init()
add_food(conn, "apple")
add_food(conn, "banana")
print(find(conn, "a"))
print("UPDATE 影响行数:", conn.execute("UPDATE food SET name='pear' WHERE name='banana'").rowcount)
conn.close()
```

原书 13.2.2 的示例是同样的结构（建表 → 插入 → 按条件查询 → 交互取值），差别只在今天应做到：**SQL 只出现在数据层函数里，业务层不碰连接对象**。

### 5. 再往上：ORM 与连接池

| 场景 | 2026 做法 | 安装 |
| --- | --- | --- |
| 原型 / 单机 / 测试 | `sqlite3` 裸写 + `row_factory` | 标准库 |
| 需要类型与校验 | SQLModel / SQLAlchemy 2.0 ORM | `pip install sqlmodel` / `pip install sqlalchemy` |
| Web 应用 | Django ORM（或 FastAPI + SQLAlchemy） | `pip install django` |
| 生产数据库（PostgreSQL） | `psycopg` 3 + 连接池 | `pip install "psycopg[binary,pool]"` |
| 迁移 | Alembic / Django migrations | `pip install alembic` |

要点：**连接不是线程共享的**（Web 应用里按请求取放连接池）；SQLite 跨线程要 `check_same_thread=False` 或干脆一线程一连接；长事务会锁库，写操作要短。

## 近年研究与工业界开源实践（2015–2026）

- **SQLAlchemy 2.0（2023）**：`session.execute(select(...))` 风格统一了 Core 与 ORM，配合 `asyncio` 扩展支撑异步 Web 后端；是「DB-API 之上还需要什么」的成熟答案。
- **`psycopg` 3**：原生支持 `COPY`、服务端绑定参数与连接池，取代 `psycopg2`；说明 DB-API 只是最小契约，高性能用法要靠驱动扩展。
- **嵌入式分析的兴起**：DuckDB 让「本地文件即数据库 + 列式分析」成为常态，`sqlite3` 常被它替代做分析型查询；两者都免运维。
- **迁移工具成为标配**：Alembic/Django migrations 把「改表结构」纳入代码评审与 CI，避免手工 SQL 脚本漂移。
- **安全基线**：参数化查询 + 最小权限账号 + 迁移审计，是 Code Review 的固定检查项；ORM 能挡住大部分拼接错误，但 `text()` / raw SQL 仍是注入高发区。
- 以上均为**工业界实践或工具文档，非同行评审论文**。

## 常见误区与本书需修正之处

| # | 原书说法 / 常见误区 | 问题 | 2026 正确写法 |
| --- | --- | --- | --- |
| 1 | 用 f-string / `%` 拼 SQL | 注入与转义错误 | 一律参数化：`execute("... WHERE name = ?", (name,))`；注意 `?` 只能占位**值**，不能代表表名/列名 |
| 2 | 以为 `with sqlite3.connect()` 会关闭连接 | 它只 commit/rollback，**不 close** | 显式 `conn.close()` 或 `contextlib.closing(...)` |
| 3 | 依赖 `cur.rowcount` 判断 SELECT 结果数 | 多数驱动对 SELECT 返回 -1 | 用 `len(rows)` 或 `SELECT COUNT(*)` |
| 4 | 假设所有驱动都用 `?` 占位符 | `paramstyle` 各不相同 | 先读 `mod.paramstyle`；跨库代码用 ORM 或 SQLAlchemy Core |
| 5 | 🔧 用 `conn.isolation_level = None` 关隐式事务 | 语义绕，易与 DDL 混用出错 | 3.12+ 用 `sqlite3.connect(..., autocommit=True)` 或设 `conn.autocommit`；🔧 细节以官方文档为准 |
| 6 | 以为 SQLite 默认检查外键 | `PRAGMA foreign_keys` 默认 **OFF** | 每次连接后执行 `PRAGMA foreign_keys = ON` |
| 7 | 在多线程里共享一个连接 | `sqlite3` 默认要求同线程 | 一线程一连接，或用连接池 / `check_same_thread=False` |
| 8 | 认为 DB-API 已被 ORM 淘汰 | PEP 249 至今有效，ORM 建立在它之上 | 读懂一次 DB-API，能显著降低换库/排查成本 |
| 9 | 把 SQL 散落在业务代码里 | 改表结构就要全库搜字符串 | 数据层集中封装；迁移用 Alembic |
| 10 | 长事务里做网络请求 | SQLite 会锁库，PostgreSQL 会膨胀 | 事务尽量短，只包住必要的写 |
