# 第 22 章 项目3：万能的XML（原书 pp.340–352）

> 一句话定位：本章用一份 XML 描述网站的**结构**（目录 / 页面 / 内容），再用 `xml.sax` 的事件把它「翻译」成 HTML 文件树——核心是**分派器混合类**这一招，以及「SAX 事件 → 方法名」的约定。基线：原书 Python 3.5；本目录按 3.12+ 校验。
> 对应英文章名：**Project 3: XML for All Occasions**。

## 核心精讲

> 以下均为**教学示意，不参与构建**；SAX 部分已在 Python 3.13 实机运行验证。

### 1. 样例 XML（原书 22.3）

```xml
<website>
  <page name="index" title="Home">
    <h1>Welcome to my <em>Home</em> page</h1>
    <a href="http://example.com">A link</a>
  </page>
  <directory name="foo">
    <page name="bar" title="Bar Page">
      <h1>Nested page</h1>
    </page>
  </directory>
</website>
```

`<page>` 是「切文件」的信号，`<directory>` 是「进子目录」的信号，其余标签一律**透传**成 HTML。

### 2. 初次实现：直接继承 `ContentHandler`（原书 22.4）

```python
# simple_sax.py —— 教学示意，不参与构建
from xml.sax import parseString
from xml.sax.handler import ContentHandler


class HeadlineHandler(ContentHandler):
    """记录文档里出现过的元素名与文本。"""

    def __init__(self):
        super().__init__()
        self.seen = []
        self._buf = []

    def startElement(self, name, attrs):
        self.seen.append(name)

    def characters(self, content):
        self._buf.append(content)          # 注意：characters 可能被调用多次

    def endElement(self, name):
        text = "".join(self._buf).strip()
        if text:
            print(f"{name}: {text}")
        self._buf.clear()


handler = HeadlineHandler()
parseString("<page><h1>Title</h1><p>Body text</p></page>", handler)
print(handler.seen)          # ['page', 'h1', 'p']
```

三个回调就是 SAX 的全部。**`characters` 会被调用多次**（实体、缓冲、换行都切断文本），
所以真实解析器要**累积**而不是替换——这是 SAX 新手的头号坑。

### 3. 再次实现：分派器混合类（原书 22.5 的核心）

```python
# dispatcher.py —— 教学示意，不参与构建
class Dispatcher:
    """把 startElement/endElement 分派到 start_<tag> / end_<tag> 方法。"""
    def dispatch(self, prefix, name, attrs=None):
        mname = prefix + "_" + name                 # start_page / end_page
        dname = "default_" + prefix                 # default_start / default_end
        method = getattr(self, mname, None)
        if callable(method):
            args = ()
        else:
            method = getattr(self, dname, None)
            args = (name,) if name else ()
        if prefix == "start":
            args += (attrs,)
        if callable(method):
            method(*args)
    def startElement(self, name, attrs): self.dispatch("start", name, attrs)
    def endElement(self, name): self.dispatch("end", name)
```

> 🔧 原书用 camelCase 方法名（`startPage`），本目录按 **PEP 8** 改为 `start_page`，
> 分派逻辑相应从 `prefix + name.capitalize()` 改为 `prefix + "_" + name`。功能等价，风格统一。

**混合类（mixin）**的用法是 `class WebsiteConstructor(Dispatcher, ContentHandler)`：
`Dispatcher` 提供分派逻辑，`ContentHandler` 提供 SAX 接口与默认实现，**两个职责互不耦合**。

### 4. 完整的网站构造器（原书 22.5 整合版）

```python
# website.py —— 教学示意，不参与构建（已在 Python 3.13 验证）
import os
from xml.sax.handler import ContentHandler          # Dispatcher 见上一段


class WebsiteConstructor(Dispatcher, ContentHandler):
    passthrough = False
    def __init__(self, directory):
        self.directory = directory
        self.ensure_directory()
    def ensure_directory(self):
        if not os.path.isdir(self.directory): os.makedirs(self.directory)
    # ---- 首部 / 尾部：页面骨架只在这里定义一次 ----
    def write_header(self, title):
        self.out.write(f"<html>\n  <head>\n    <title>{title}</title>\n  </head>\n  <body>\n")
    def write_footer(self):
        self.out.write("\n  </body>\n</html>\n")
    # ---- 默认处理：未识别的标签原样透传 ----
    def default_start(self, name, attrs):
        if not self.passthrough: return
        self.out.write("<" + name)
        for key, val in attrs.items():
            self.out.write(f' {key}="{val}"')
        self.out.write(">")
    def default_end(self, name):
        if self.passthrough: self.out.write(f"</{name}>")
    def characters(self, chars):
        if self.passthrough: self.out.write(chars)
    # ---- 具体标签：page 开文件，directory 换目录 ----
    def start_page(self, attrs):
        path = os.path.join(self.directory, attrs["name"] + ".html")
        self.out = open(path, "w", encoding="utf-8")
        self.write_header(attrs["title"])
        self.passthrough = True
    def end_page(self):
        self.passthrough = False
        self.write_footer()
        self.out.close()
    def start_directory(self, attrs):
        self.directory = os.path.join(self.directory, attrs["name"])
        self.ensure_directory()
    def end_directory(self):
        self.directory = os.path.split(self.directory)[0]
```

调用与产物：

```python
# 教学示意，不参与构建
from xml.sax import parseString

parseString(XML, WebsiteConstructor("site"))     # XML 见第 1 节
# 产出：site/index.html  与  site/foo/bar.html
```

`index.html` 内容（已验证，空行略）：

```html
<html>
  <head><title>Home</title></head>
  <body>
    <h1>Welcome to my <em>Home</em> page</h1>
    <a href="http://example.com">A link</a>
  </body>
</html>
```

三个值得学的细节：**`passthrough` 开关**把「是否输出」变成一个布尔状态；
**`attrs["name"]` 的 KeyError 就是天然的结构校验**（缺属性立刻崩，比静默出错好）；
**`end_directory` 用 `os.path.split` 回退一层**，天然支持任意嵌套。

### 5. 安全：原书完全没提，2026 年是必修课

| 攻击 | 原理 | 现状与对策 |
| --- | --- | --- |
| XXE（外部实体） | `<!DOCTYPE x SYSTEM "file:///etc/passwd">` 读本地文件 / 打内网 | 标准库 `ElementTree`/`xml.sax` **默认不解析外部实体**，风险较低；仍应禁用 DTD |
| billion laughs | 嵌套实体指数膨胀，内存打爆 | 🔧 较新版本 CPython（内置 expat）已有「输入放大倍数」限制，会抛 `ParseError`；**起始版本以官方安全公告为准** |
| 大文件 / 深嵌套 DoS | 解析耗时与内存随输入增长 | 限流、限大小、限深度 |

```python
# xml_safety.py —— 教学示意，不参与构建（仅用标准库，Python 3.13 验证）
import xml.etree.ElementTree as ET

evil = ('<?xml version="1.0"?><!DOCTYPE foo SYSTEM "file:///etc/passwd">'
        "<foo>&xxe;</foo>")
try:
    ET.fromstring(evil)
except ET.ParseError as e:
    print("外部实体被拒绝:", e)        # undefined entity &xxe;
```

生产建议：**解析任何外部来源的 XML 都用 `defusedxml`**（`pip install defusedxml`），
它把 SAX / ElementTree / minidom / lxml 等入口全部换成安全版本：

```python
# 教学示意，不参与构建；需 pip install defusedxml
from defusedxml.ElementTree import fromstring

root = fromstring(open("untrusted.xml", "rb").read())     # 传 bytes，禁止外部实体
```

### 6. 2026 年等价做法

| 目标 | 方案 | 说明 |
| --- | --- | --- |
| 只读一份配置 / 文档 | **`xml.etree.ElementTree`** | 标准库、树形 API；`iterparse` 可流式处理大文件 |
| 要 XPath / XSLT / schema 校验 | **lxml** | 功能最全，XPath 与 XSLT 1.0 的主流选择 |
| 要「XML ↔ 数据类」 | **pydantic-xml / xsdata** | 像 pydantic 一样声明模型，自动生成与校验 |
| 「XML 定义网站」这件事本身 | **Sphinx / MkDocs** | Markdown + 主题 + 交叉引用 + 搜索，不必自造 XML 方言 |
| 新项目的数据格式 | **JSON / TOML / YAML** | XML 已基本退场，只在老系统与企业集成中遇到 |

ElementTree 版（同等功能，代码短一半）：

```python
# website_et.py —— 教学示意，不参与构建
import os
import xml.etree.ElementTree as ET


def render(node, outdir):
    if node.tag == "page":
        path = os.path.join(outdir, node.attrib["name"] + ".html")
        with open(path, "w", encoding="utf-8") as f:
            f.write(f"<html><head><title>{node.attrib['title']}</title></head><body>")
            for child in node:
                f.write(ET.tostring(child, encoding="unicode"))
            f.write("</body></html>")
    elif node.tag == "directory":
        sub = os.path.join(outdir, node.attrib["name"])
        os.makedirs(sub, exist_ok=True)
        for child in node:
            render(child, sub)


render(ET.parse("website.xml").getroot(), "site")
```

**SAX vs 树形 API**：SAX 流式、**内存 O(1)**、适合超大文件与「边读边写」的生成场景（正是本章）；
ElementTree 树形、代码短、适合「读进来反复查询」。**本章选 SAX 是正确的。**

## 常见误区与本书需修正之处

| # | 原书说法 / 常见想法 | 问题 | 2026 正确写法（🔧 = 需修正） |
| --- | --- | --- | --- |
| 1 | 🔧 原书未涉及 XML 安全 | 外部 XML 有 XXE / billion laughs 风险 | 🔧 用 `defusedxml`；禁用 DTD；限制输入大小与嵌套深度 |
| 2 | 认为标准库「天然安全」就够了 | 🔧 不同解析器行为不一致，lxml 需显式 `resolve_entities=False` | 🔧 统一走 `defusedxml` 入口 |
| 3 | `characters()` 里直接赋值 `self.text = content` | 该方法被调用多次，文本会被切断 | 用列表累积，在 `endElement` 里 `''.join` |
| 4 | 用 `if name == 'page': ... elif ...` 长链 | 加一种标签要改一遍 | 🔧 用分派器（本章核心）或 `match`（PEP 634） |
| 5 | 原书 camelCase 方法名 `startPage` | 不符合 PEP 8 | 🔧 `start_page`，分派前缀改为 `prefix + "_" + name` |
| 6 | 把 XML 属性直接写进 HTML | 🔧 **未转义，存在 XSS** | 🔧 `html.escape(attrs["title"])` 或用模板引擎自动转义 |
| 7 | 手写字符串拼 HTML | 易出错、不保证闭合 | 用 Jinja2 模板或 `xml.etree` 生成节点 |
| 8 | 认为「XML 是配置的好格式」 | 🔧 2026 年新项目首选 TOML/YAML/JSON | 🔧 只在对接遗留系统时用 XML |
| 9 | 忽略命名空间 | 真实 XML 带 `xmlns` 时 `tag` 会变成 `{uri}name` | 用命名空间字典或通配符 `*{tag}` |
| 10 | `open(filename, "w")` 不指定编码 | 🔧 Windows 上默认编码可能不是 UTF-8 | 🔧 显式 `encoding="utf-8"`（本目录示例已改） |
| 11 | 🔧 原书未涉及 | 无测试 | 补：`render` 与分派逻辑对纯函数友好，可直接 `pytest` 断言输出 |
