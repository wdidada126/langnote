# 第 23 章 项目4：新闻汇总（原书 pp.353-363）

> 一句话定位本章：把分散在多个新闻源里的标题与链接**抓下来、解析成结构化数据、再渲染成一份可浏览的报告**——这是本书第一个完整的「数据管道」项目，也是第一次把网络抓取、解析、持久化与渲染串成一条链。
> 基线：原书 Python 3.5；本目录按 3.12+ 校验。
> 对应英文章名：Project 4: In the News

## 核心精讲

> 以下代码均为**教学示意，不参与构建**：本目录不搭建真实抓取服务，示例用于对齐概念与 API 形态。

### 23.1–23.3 问题描述与工具选型

管道的四个环节，每一环都有明确的失败模式，工程上应当**分别**处理：

| 环节 | 失败模式 | 应对 |
| --- | --- | --- |
| 抓取 | 超时、4xx/5xx、重定向循环、编码声明缺失 | 超时 + `raise_for_status()` + 限制重定向次数 + 显式 `User-Agent` |
| 解析 | feed 版本混杂（RSS 0.9x/2.0、Atom）、字段缺失 | 用 `feedparser` 做宽容解析，所有字段走 `.get()` 兜底 |
| 结构化 | 时间格式千奇百怪、标题含 HTML 实体 | 统一为 `dataclass`，时间解析失败就退化为字符串 |
| 渲染 | HTML 注入（标题里带 `<script>`） | 模板引擎开启 autoescape，**永不**手工拼 HTML |

### 23.4 初次实现：单源最小闭环（按 3.12+ 写法）

原书这一环节用标准库 `urllib.request` 抓取、手工切分字符串取标题，再用 `print` 逐行输出 HTML 标签。
2026 年的等价写法是「HTTP 客户端 + 宽容解析 + 最小模板」：

```python
# step1_single_source.py —— 教学示意，不参与构建
# pip install httpx feedparser jinja2
from __future__ import annotations

import httpx
import feedparser
from jinja2 import Environment, select_autoescape

FEED = "https://blog.python.org/feeds/posts/default?alt=rss"
HEADERS = {"User-Agent": "langnote-news-demo/1.0 (+https://example.com/bot)"}

def fetch(url: str, *, timeout: float = 10.0) -> bytes:
    with httpx.Client(headers=HEADERS, timeout=timeout, follow_redirects=True) as client:
        resp = client.get(url)
        resp.raise_for_status()          # 4xx/5xx 直接抛异常，不做静默降级
        return resp.content

def parse(raw: bytes, source: str) -> list[dict]:
    parsed = feedparser.parse(raw)       # RSS 0.9x/1.0/2.0/Atom 通吃
    return [
        {
            "source": source,
            "title": entry.get("title", "(无标题)"),
            "link": entry.get("link", ""),
            "published": entry.get("published", entry.get("updated", "")),
        }
        for entry in parsed.entries[:10]
    ]

TEMPLATE = """<!doctype html>
<meta charset="utf-8"><title>{{ source }}</title>
<h1>{{ source }}</h1>
<ol>
{% for item in items %}<li><a href="{{ item.link }}">{{ item.title }}</a>
  <small>{{ item.published }}</small></li>
{% endfor %}
</ol>"""

def render(items: list[dict], source: str) -> str:
    # autoescape 是这里的生命线：标题里的 < > & " 会被转义
    env = Environment(autoescape=select_autoescape(["html"]), trim_blocks=True)
    return env.from_string(TEMPLATE).render(source=source, items=items)

if __name__ == "__main__":
    raw = fetch(FEED)
    items = parse(raw, "Python 官方博客")
    print(render(items, "Python 官方博客")[:400])
```

### 23.5 再次实现：多源聚合 + 合规抓取 + 缓存

原书的「再次实现」把多个源并列输出。真正需要补的是三件原书没有做的事：**抓取礼仪、并发、缓存**。

```python
# step2_aggregator.py —— 教学示意，不参与构建
# pip install httpx feedparser jinja2
from __future__ import annotations

import concurrent.futures as futures
import datetime as dt
import json
import pathlib
import urllib.robotparser

import httpx

FEEDS = {
    "Python 官方博客": "https://blog.python.org/feeds/posts/default?alt=rss",
    "PyPI 最近更新": "https://pypi.org/rss/updates.xml",
}
HEADERS = {"User-Agent": "langnote-news-demo/1.0 (+https://example.com/bot)"}
CACHE = pathlib.Path(".feedcache")

def allowed(url: str) -> bool:
    """抓取礼仪第一关：先看 robots.txt。查不到时默认放行（以站点策略为准）。"""
    rp = urllib.robotparser.RobotFileParser()
    rp.set_url(f"{url.split('//')[0]}//{url.split('/')[2]}/robots.txt")
    try:
        rp.read()
    except Exception:
        return True
    return rp.can_fetch(HEADERS["User-Agent"], url)

def fetch_one(name_url: tuple[str, str]) -> tuple[str, bytes]:
    name, url = name_url
    if not allowed(url):
        return name, b""
    # 第二关：条件请求。服务端返回 304 时不重复解析，省流量也省对方带宽
    cache_file = CACHE / (name.replace("/", "_") + ".xml")
    headers = dict(HEADERS)
    if cache_file.exists():
        meta = json.loads((CACHE / (cache_file.stem + ".json")).read_text(encoding="utf-8"))
        if etag := meta.get("etag"):
            headers["If-None-Match"] = etag
        if modified := meta.get("last_modified"):
            headers["If-Modified-Since"] = modified
    with httpx.Client(headers=headers, timeout=10.0, follow_redirects=True) as client:
        resp = client.get(url)
        if resp.status_code == 304:                 # 未修改，直接用缓存
            return name, cache_file.read_bytes()
        resp.raise_for_status()
        CACHE.mkdir(exist_ok=True)
        cache_file.write_bytes(resp.content)
        (CACHE / (cache_file.stem + ".json")).write_text(json.dumps({
            "etag": resp.headers.get("etag", ""),
            "last_modified": resp.headers.get("last-modified", ""),
            "fetched_at": dt.datetime.now(dt.UTC).isoformat(),
        }), encoding="utf-8")
        return name, resp.content

def main() -> None:
    # 第三关：并发要克制。聚合器用 4 个 worker 足够，别把对方站点当压力测试目标
    with futures.ThreadPoolExecutor(max_workers=4) as pool:
        results = list(pool.map(fetch_one, FEEDS.items()))
    total = sum(len(r) for _, r in results)
    print(f"抓取完成：{len(results)} 个源，共 {total} 字节（304 命中不重复下载）")

if __name__ == "__main__":
    main()
```

要点：`If-None-Match` / `If-Modified-Since` 是 RSS 抓取**唯一正确**的礼貌做法；没有它们，定时抓取就是持续给对方站点加压。

### 23.6 进一步探索：从「脚本」到「系统」

| 方向 | 做法 | 涉及能力 |
| --- | --- | --- |
| 去重与排序 | 用 `link` 做主键，按 `published_parsed` 排序 | `feedparser` 的 `*_parsed` 字段是已解析的 `time.struct_time` |
| 全文检索 | 标题 + 摘要入 SQLite FTS5 | 第 13 章 `sqlite3` |
| 定时 | 系统 cron / `systemd timer`，而不是脚本里 `while True: sleep` | 第 19 章配置 |
| 输出形态 | Jinja2 渲染静态 HTML，或用静态站点生成器（MkDocs 等） | 免去 CGI/服务端 |
| 可观测 | `logging` 记录源级失败率，单个源挂掉不影响整体 | PEP 282 |

## 近年研究与工业界开源实践（2015–2026）

- **`httpx`**：把同步与异步 HTTP 客户端统一到一套 API，并原生提供超时、`follow_redirects`、HTTP/2，是本书 `urllib` 章节事实上的现代替代。
- **`feedparser`**：长期维护的宽容 feed 解析库，能把 RSS 0.9x/1.0/2.0、Atom、CDF 归一到同一套字段，是「别自己写正则解析 XML」的最直接论据。
- **`parsel` / Scrapy**：从 HTML 里抽取数据用 CSS/XPath 选择器，比正则可靠；Scrapy 把抓取中的并发、去重、限速（`AUTOTHROTTLE`）做成了框架级能力，可视为本章「进一步探索」的工业化答案。
- **`BeautifulSoup4`**：容错解析破损 HTML，配合 `html5lib`/`lxml` 解析器使用；教学场景首选，超大规模抓取建议换成 `parsel`。
- **`Jinja2`**：autoescape 是防御 HTML 注入的第一道闸门，也把「结构」与「文本」彻底分离。
- **静态站点生成器（MkDocs / Sphinx 等）**：把本章的报告输出从「跑一个服务」降级为「生成一批文件」，运维成本与安全面都大幅缩小。
- **`defusedxml`**：处理**不可信** XML 时的加固库（防实体膨胀等），任何解析外部 XML 的场景都值得评估。
- **合规侧**：近年站点普遍引入速率限制与 WAF，抓取方需要显式 `User-Agent`、退避重试与 `robots.txt` 遵守；这类结论来自站点运营实践，非同行评审论文。

## 常见误区与本书需修正之处

| # | 原书写法 / 常见误区 | 问题 | 2026 年正确写法 |
| --- | --- | --- | --- |
| 1 | 🔧 用 CGI 脚本 + `cgi` 模块输出 HTML 报告 | `cgi`/`cgitb` 已在 **3.13 移除（PEP 594）**；CGI 每请求启进程，性能与安全面都差 | FastAPI/Flask 等 ASGI/WSGI 框架，或干脆渲染成静态文件 |
| 2 | 🔧 手工拼 HTML 字符串 | 标题含 `<script>` 就变成存储型 XSS | `Jinja2(autoescape=...)` 或 `html.escape` |
| 3 | 🔧 用正则从 XML 里抠标题 | XML 不是正则可处理的语言；feed 版本一变就崩 | `feedparser`；HTML 用 `parsel`/`BeautifulSoup4` |
| 4 | 🔧 `urllib.request` 不设超时 | 默认无超时，一个挂起的连接能拖死整个聚合器 | `httpx.Client(timeout=10.0)`，并为每请求设上限 |
| 5 | 🔧 定时全量重抓、不做条件请求 | 浪费双方带宽，容易被限流或封禁 | `If-None-Match` / `If-Modified-Since`，缓存 ETag |
| 6 | 忽略 `robots.txt` 与抓取频率 | 法律与服务条款风险，且容易被封 IP | `urllib.robotparser` 预检 + 退避 + 低并发 |
| 7 | 🔧 在解析里 `print` 打日志 | 无法分级、无法关掉、污染输出 | `logging`（PEP 282），按源记录失败率 |
| 8 | 认为「抓取 = 爬虫项目」 | 本章只是**聚合器**：源是确定的、字段是约定的 | 保持「源清单 + 解析器 + 渲染器」三段分离 |
| 9 | 🔧 把 feed 内容直接当纯文本存库后原样输出 | 二次注入 | 入库前净化（`bleach` 之类）或输出时转义，二选一即可但必须做 |
| 10 | 用 `time.sleep` 在脚本内做定时 | 进程崩溃即停摆，且无重试语义 | cron / systemd timer，或任务队列 |
