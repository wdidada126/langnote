## 核心精讲

> 教学示意，不参与构建：以下片段自足可运行，用 `tempfile` 造临时文件，不污染你的磁盘。

### 1. 打开文件：模式串速查

| 模式 | 含义 | 备注 |
| --- | --- | --- |
| `r` | 读（默认） | 文件不存在抛 `FileNotFoundError` |
| `w` | 写，**截断**已有内容 | 慎用，会清空 |
| `x` | 独占创建 | 已存在则抛 `FileExistsError`，适合「别覆盖」场景 |
| `a` | 追加 | 写指针永远在末尾 |
| `b` | 二进制 | 与 `r/w/x/a` 组合；**读写 bytes，不做编码转换与换行转换** |
| `+` | 读写 | `r+` 不截断，`w+` 截断 |
| `t` | 文本（默认） | 可省略 |

```python
import pathlib, tempfile

tmp = pathlib.Path(tempfile.mkdtemp())
p = tmp / "hello.txt"
p.write_text("第一行\n第二行\n", encoding="utf-8")        # 内部就是 open + write + close
print(p.read_text(encoding="utf-8"))
with p.open("a", encoding="utf-8") as f:                  # 追加一行
    f.write("第三行\n")
print("行数:", p.read_text(encoding="utf-8").count("\n"))
```

`pathlib` 的 `write_text` / `read_text` / `open` 都接受 `encoding`，**比裸 `open()` 更难忘掉编码**。原书几乎通篇用字符串路径与 `open()`，今天应默认 `Path`。

### 2. 二进制与随机访问

文本模式下的 `seek` 只对 `tell()` 给出的「不透明数字」或 0 可靠；**按字节偏移定位请用二进制模式**（`seek(offset, whence)`，`whence` 取 0/1/2）。

```python
import pathlib, tempfile

p = pathlib.Path(tempfile.mkdtemp(), "data.bin")
with p.open("wb") as f:
    f.write(b"abcde")
with p.open("rb") as f:
    print("读 2 字节:", f.read(2), "当前位置:", f.tell())
    f.seek(-1, 2)                       # 相对文件末尾回退 1 字节
    print("末字节:", f.read())
```

### 3. 按行读写与「管道重定向」

```python
import contextlib, io, pathlib, tempfile

p = pathlib.Path(tempfile.mkdtemp(), "lines.txt")
with p.open("w", encoding="utf-8") as f:
    f.writelines(f"{i} 行\n" for i in range(3))     # 换行要自己加
with p.open(encoding="utf-8") as f:
    print("readline:", f.readline().rstrip())
    print("readlines:", [ln.rstrip() for ln in f.readlines()])

buf = io.StringIO()
with contextlib.redirect_stdout(buf):               # 取代 sys.stdout = open(...)
    print("被捕获的输出")
print("捕获到:", buf.getvalue().strip())
```

原书演示管道重定向是直接改 `sys.stdout`；今天用 `contextlib.redirect_stdout`（可嵌套、异常安全），或者干脆让函数**返回字符串**而不是 `print`——这样天然可测试。

### 4. 关闭文件：`with` 是唯一正确姿势

```python
from contextlib import contextmanager


@contextmanager
def tag(name):
    print(f"<{name}>")
    try:
        yield
    finally:
        print(f"</{name}>")


with tag("html"):
    print("  body")
```

`with` 走的是上下文管理器协议（`__enter__` / `__exit__`），文件对象的 `__exit__` 会 `close()`；**即使中间抛异常也会关**。原书的 `try/finally` 写法只是 `with` 的手写展开。需要注意：`with` 退出只是把数据交给 OS，**不保证落盘**，真要持久用 `f.flush()` + `os.fsync(f.fileno())`。

### 5. 迭代文件内容的五种方式

```python
import fileinput, pathlib, tempfile

p = pathlib.Path(tempfile.mkdtemp(), "it.txt")
p.write_text("ab\ncd\nef\n", encoding="utf-8")

with p.open(encoding="utf-8") as f:
    print("每次一个字符:", [f.read(1) for _ in range(3)])
with p.open("rb") as f:
    print("每次一个字节:", [f.read(1) for _ in range(2)])
with p.open(encoding="utf-8") as f:
    print("每次一行:", [ln.rstrip() for ln in f])       # 首选：惰性、内存 O(1)
with p.open(encoding="utf-8") as f:
    print("一次读完:", f.read().splitlines())           # 仅小文件
for line in fileinput.input(files=[str(p)], encoding="utf-8"):
    print("fileinput:", line.rstrip())                  # 多文件/stdin 当一条行流
```

取舍：**按行迭代是默认答案**；`read()` 全读只用于确定很小或必须整体处理（如正则跨行匹配）的文件；`fileinput` 的价值在「命令行过滤器」场景（`python script.py a.txt b.txt`，或 `-` 读 stdin）。2026 年等价写法是 `argparse` 收文件列表 + `for fp in files: for line in fp.open(encoding="utf-8")`。

## 近年研究与工业界开源实践（2015–2026）

- **`pathlib` 成为事实标准**：主流库（Django、FastAPI、pandas、black、ruff）内部与文档均已默认 `Path`；`os.path` 只在兼容旧代码时出现。
- **大文件处理**：单机 GB 级文本的行迭代 + `mmap` / 分块（chunked）读取是常态；列式与压缩场景由 `polars`/`pyarrow`/`duckdb` 接管，Python 侧不再自己写缓冲逻辑。
- **远端/对象存储抽象**：`fsspec`、`universal_pathlib`、`obstore` 把 `open()` / `Path` 语义推广到 S3、GCS、HTTP，让「文件」不再等于本地磁盘。
- **编码现实的收敛**：UTF-8 已是绝大多数协议与文件的默认；Windows 侧的遗留 GBK/CP1252 数据仍需在读取时显式声明，这也是「必须写 encoding」的现实理由。
- **可测试性**：函数返回字符串/写入 `io.StringIO`，而不是直接 `print` 到 `sys.stdout`，是单元测试友好度分水岭。
- 以上均为**工业界实践或工具文档，非同行评审论文**。

## 常见误区与本书需修正之处

| # | 原书说法 / 常见误区 | 问题 | 2026 正确写法 |
| --- | --- | --- | --- |
| 1 | 🔧 `open(name)` 不写 `encoding` | 编码随平台变（Windows 常为 GBK/CP1252），同一份代码换机器就乱码 | 一律 `open(name, encoding="utf-8")` 或 `Path.read_text(encoding="utf-8")` |
| 2 | 用 `os.path.join` 拼字符串路径 | 跨平台与转义易错 | `pathlib.Path`：`p = base / "sub" / "a.txt"` |
| 3 | 手动 `f.close()` / `try...finally` | 容易漏关，异常路径更易漏 | `with open(...) as f:`（PEP 343）；多个文件用 `contextlib.ExitStack` |
| 4 | 🔧 `fileinput` 当主力读文件方式 | 现在只在「命令行多文件过滤器」场景有价值 | 单文件 `for line in f`；多文件 `Path.glob` + `open`；CLI 用 `argparse` |
| 5 | `sys.stdout = open(...)` 做重定向 | 异常时难恢复，且不组合 | `contextlib.redirect_stdout`，或直接返回字符串 |
| 6 | `f.writelines(list)` 期待自动换行 | 原样写入，不加分隔符 | 自己拼 `"\n"` 或用 `"\n".join(...)` |
| 7 | 用 `read()` 读大文件 | 一次性占用与文件等大的内存 | 逐行迭代或分块 `f.read(size)` |
| 8 | 认为 `with` 退出即「已落盘」 | 只是缓冲交给 OS | 需持久时用 `flush()` + `os.fsync()` |
| 9 | 文本模式下用 `seek(n)` 跳到第 n 字节 | 文本模式的偏移不是字节语义 | 二进制模式 `rb` 做字节级定位 |
| 10 | 🔧 期待「UTF-8 已是默认所以可不写 encoding」 | 🔧 该变化尚未成为可依赖的行为（以官方文档为准） | 显式写死 `encoding="utf-8"`，写错也比赌默认值强 |
