# 第 21 章 项目2：绘制图表（原书 pp.332–339）

> 一句话定位：本章把「一堆数字」变成一张**可交付的 PDF 折线图**，核心不是绘图 API，而是「先手工画出来搞清楚坐标，再用现成图表类」的两段式推进法。基线：原书 Python 3.5；本目录按 3.12+ 校验。
> 对应英文章名：**Project 2: Painting a Pretty Picture**。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 21.1 问题描述 | 从文本文件（如逐年的观测数据）读入数值，输出一张折线图 PDF | 输入是「序列」，输出是「矢量图」 |

## 核心精讲

### 1. 安装与数据准备（原书 21.2–21.3）

```bash
pip install reportlab            # 生成 PDF；5.x 依赖 pillow
```

数据获取与解析（教学示意，不参与构建）：

```python
# load_data.py —— 教学示意，不参与构建（仅用标准库）
def load_pairs(path):
    """读入每行一个数值的文本文件，产出 (序号, 数值) 序列。"""
    pairs = []
    with open(path, encoding="utf-8") as f:
        for i, line in enumerate(f, start=1):
            line = line.strip()
            if line:
                pairs.append((i, float(line)))
    return pairs


print(load_pairs.__doc__)
```

要点：**先让数据变成干净的 `(x, y)` 序列**，再谈画图。原书把「获取数据」放在再次实现里，
是因为初次实现阶段先用硬编码数据最快——这正是 [19-趣味编程.md](19-趣味编程.md) 的原型原则。

### 2. 初次实现：手工画折线（原书 21.4）

```python
# report1.py —— 教学示意，不参与构建（已在 reportlab 5.0.1 验证）
from reportlab.graphics.shapes import Drawing, PolyLine, String
from reportlab.graphics import renderPDF

data = [(1, 5), (2, 9), (3, 7), (4, 14), (5, 11), (6, 18), (7, 15)]

drawing = Drawing(400, 200)
drawing.add(PolyLine(data, strokeColor=(0.2, 0.2, 0.8), strokeWidth=1.5))
drawing.add(String(10, 180, "Sunspots (demo)", fontSize=9))
renderPDF.drawToFile(drawing, "report1.pdf", "demo")
```

`Drawing(width, height)` 是一块**以点（pt）为单位的画布**，原点在**左下角**（不是左上角！），
这是初次画图最容易踩的坑。`PolyLine` 只负责连线，没有坐标轴——所以下一步才是 `LinePlot`。

### 3. 再次实现：用 `LinePlot`（原书 21.5）

```python
# report2.py —— 教学示意，不参与构建（已在 reportlab 5.0.1 验证）
from reportlab.lib import colors
from reportlab.graphics import renderPDF
from reportlab.graphics.shapes import Drawing
from reportlab.graphics.charts.lineplots import LinePlot
from reportlab.graphics.widgets.markers import makeMarker

data = [(1, 5), (2, 9), (3, 7), (4, 14), (5, 11), (6, 18), (7, 15)]

lp = LinePlot()
lp.x, lp.y, lp.width, lp.height = 50, 30, 300, 150   # 图表在画布中的位置与大小
lp.data = [data]                                     # 外层列表 = 多条序列
lp.lines[0].strokeColor = colors.HexColor("#3366cc")
lp.lines[0].strokeWidth = 1.5
lp.lines[0].symbol = makeMarker("FilledCircle")

lp.xValueAxis.valueMin, lp.xValueAxis.valueMax = 1, 7
lp.xValueAxis.valueSteps = [1, 2, 3, 4, 5, 6, 7]
lp.yValueAxis.valueMin, lp.yValueAxis.valueMax = 0, 20
lp.yValueAxis.valueSteps = [0, 5, 10, 15, 20]

drawing = Drawing(400, 200)
drawing.add(lp)
renderPDF.drawToFile(drawing, "report2.pdf", "demo2")
```

三条 🔧 版本提醒（原书基于旧版 ReportLab，与当前版本有差异）：

1. 🔧 **`lp.lines[0].strokeColor` 要传 `colors` 对象**（`colors.HexColor(...)`），直接赋 RGB 元组会抛
   `AttributeError: Illegal assignment ...`（reportlab 5.x 的 `validateSetattr` 校验）。以当前版本文档为准。
2. 🔧 `lp.data` 是**序列的列表**：一条线是 `[data]`，两条线是 `[data1, data2]`，忘了套外层会静默出错。
3. 🔧 旧版示例里的一些属性名（如 `lines[0].symbol` 的可选值、`xLabelFormat`）随版本调整，
   以 `help(LinePlot)` 或官方文档为准。

### 4. 中文字体：原书完全没提，2026 年必须补

ReportLab 内置 Adobe 的 CJK CID 字体，注册后即可写中文（教学示意，不参与构建）：

```python
# cjk_demo.py —— 教学示意，不参与构建（已在 reportlab 5.0.1 验证）
from reportlab.graphics import renderPDF
from reportlab.graphics.shapes import Drawing, String
from reportlab.pdfbase import pdfmetrics
from reportlab.pdfbase.cidfonts import UnicodeCIDFont

pdfmetrics.registerFont(UnicodeCIDFont("STSong-Light"))     # 内置宋体，无需字体文件

drawing = Drawing(400, 200)
drawing.add(String(10, 100, "中文标题示例", fontName="STSong-Light", fontSize=14))
renderPDF.drawToFile(drawing, "cjk.pdf", "cjk")
```

若要嵌入自定义 TTF（如企业字体）：`pdfmetrics.registerFont(TTFont("MyFont", "my.ttf"))`，
并注意**字体授权**与**子集化**（只嵌入用到的字形，避免 PDF 体积暴涨）。

### 5. 2026 年等价做法

| 需求 | 首选 | 说明 |
| --- | --- | --- |
| 交互式图表（网页 / Notebook） | **Altair 或 Plotly** | 声明式、导出 HTML，Plotly 支持 `fig.write_image()` |
| 论文 / 静态图 | **matplotlib** | 生态最大，样式可控，PDF/SVG/PNG 全支持 |
| 报表 PDF（批量、模板化） | **ReportLab**（本章） | 仍是 Python 生成 PDF 的主力，尤其 `platypus` 排版 |
| 大数据量 | datashader / Vaex 配合 matplotlib | 点数超过百万时普通折线会卡 |

matplotlib 版（已在 Python 3.13 + matplotlib 3.10 验证）：

```python
# plot_mpl.py —— 教学示意，不参与构建
import matplotlib

matplotlib.use("Agg")                      # 无显示器环境（CI / 服务器）必须切换后端
import matplotlib.pyplot as plt

years = list(range(2000, 2021))
values = [12, 15, 9, 20, 33, 28, 40, 55, 61, 48, 39,
          44, 52, 60, 71, 66, 58, 63, 70, 77, 81]

# 中文字体：不设置会渲染成方框（原书未涉及）
plt.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei", "Noto Sans CJK SC"]
plt.rcParams["axes.unicode_minus"] = False   # 负号显示成方块的老问题

fig, ax = plt.subplots(figsize=(8, 4), dpi=120)
ax.plot(years, values, marker="o", linewidth=1.5, label="示例指标")
ax.set_title(f"示例折线图（{len(values)} 个数据点）")
ax.set_xlabel("年份")
ax.set_ylabel("数值")
ax.grid(alpha=0.3)
ax.legend()
fig.tight_layout()
fig.savefig("plot.png")
```

**为什么今天更推荐 matplotlib/Altair**：ReportLab 的 `graphics` 包适合「把图放进 PDF 报表」，
但交互、坐标系细节、配色与主题都不如专注可视化的库；两者常**组合使用**
（matplotlib 出图 → ReportLab 排版进 PDF）。

## 近年研究与工业界开源实践（2015–2026）

- **matplotlib**（`matplotlib/matplotlib`）：仍是静态图的事实标准；
  近年的重点是把 **WebAssembly 后端**与原生 HTML 后端推向前台，让 Notebook 里的图可交互。
- **Altair / Vega-Lite**（`vega/vega-lite`）：声明式语法（`mark_line().encode(x=..., y=...)`），
  直接对应 Wickham 的「图形语法」，是研究思维落地最快的一条路。
- **Plotly**（`plotly/plotly.py`）：浏览器端交互 + 服务端 Python 双形态；
  `plotly.express` 一行出图，导出静态图需 `kaleido`。
- **ReportLab**（`MrBitBucket/reportlab-mirror` 等镜像源）：商业报表/PDF 场景仍活跃；
  其 `platypus` 排版引擎（文档模板、表格、分页）是它区别于绘图库的真正壁垒。
- **中文/多语言渲染**：这是中文用户的头号坑。解决路径是
  **注册字体 + 指定 fontName + 子集化**，matplotlib 侧则靠 `rcParams["font.sans-serif"]`
  与 `axes.unicode_minus`；云端容器里还需先装字体包（`fonts-noto-cjk` 等）。
- **研究侧**：近年可视化研究集中在**大规模数据的可视化（datashader 类的聚合渲染）**、
  **可复现与不确定性可视化**（误差带、置信区间），以及 **图表的可访问性（色盲友好配色）**。

## 常见误区与本书需修正之处

| # | 原书说法 / 常见想法 | 问题 | 2026 正确写法（🔧 = 需修正） |
| --- | --- | --- | --- |
| 1 | 直接照抄原书 `LinePlot` 代码 | 🔧 旧版 API；reportlab 5.x 对属性赋值做校验 | 🔧 颜色用 `colors.HexColor(...)`；以当前版本 Release Notes 为准 |
| 2 | `lp.data = data` | 少了外层列表，多序列会失效 | 🔧 `lp.data = [data]`（每条线一个内层列表） |
| 3 | 用 RGB 元组给 widget 赋颜色 | reportlab 5.x 抛 `Illegal assignment` | 🔧 用 `colors.Color` 子类；`PolyLine`（shape）接受元组但建议统一用 `colors` |
| 4 | 中文直接 `String(...)` 输出 | 原书未涉及；结果是空白或方框 | 🔧 注册 `UnicodeCIDFont("STSong-Light")` 或 TTF，并指定 `fontName` |
| 5 | PDF 里嵌整个字体文件 | 体积从几十 KB 涨到数 MB | 🔧 子集化（ReportLab `TTFont` 支持 subset；matplotlib 设 `pdf.fonttype = 42` 并子集） |
| 6 | 用 `urllib` 抓数据然后手写解析 | 🔧 原书时代只能如此 | 🔧 用 `httpx`/`requests` 抓，用 `pandas.read_csv` 解析；注意超时与重试 |
| 7 | 硬编码数据范围（0–20） | 换批数据就要改代码 | 🔧 从数据计算 `min/max` 并留边距；这属于 [19-趣味编程.md](19-趣味编程.md) 的「配置外置」 |
| 8 | 画布坐标当屏幕坐标用 | ReportLab 原点在**左下角** | 记住 y 轴向上；或用 `platypus` 的 Flowable 自动排版 |
| 9 | 在服务器上直接 `plt.show()` | 无显示器会失败或挂起 | 🔧 `matplotlib.use("Agg")` + `savefig` |
| 10 | 图表越花哨越好 | 装饰性元素（3D、渐变、双 Y 轴）常误导读者 | 参考 Tufte 的「数据墨水比」原则：能省的装饰都省 |
| 11 | 🔧 原书未涉及 | 原书没有测试与类型注解 | 补：数据解析函数是可测纯函数；序列用 `list[tuple[float, float]]` 注解 |
| 12 | 🔧 原书未涉及 | 原书没讲图表的可访问性 | 补：色盲友好配色（viridis 等）、为关键图提供数据表替代 |
