## 核心精讲

> 教学示意，不参与构建：以下片段可直接粘贴进 REPL 或 `.py` 运行，不依赖第三方库。

### 1. 构造函数：`__init__` 其实不是构造函数

真正的构造函数是 **`__new__`**（创建实例），`__init__` 只是**初始化方法**；只有继承不可变类型（`str`/`tuple`/`int`）或做元类、单例时才动 `__new__`。

```python
class Bird:
    def __init__(self):
        self.hungry = True

    def eat(self):
        print("Aaaah ..." if self.hungry else "No, thanks!")


class SongBird(Bird):
    def __init__(self):
        super().__init__()          # 2026 年唯一写法：无参 super()
        self.sound = "Squawk!"

    def eat(self):                  # 重写普通方法
        print(self.sound)


class UpperStr(str):                # 不可变类型：必须在 __new__ 里加工
    def __new__(cls, value):
        return super().__new__(cls, value.upper())


sb = SongBird()
sb.eat()
print(UpperStr("hello"))            # HELLO
```

原书的 `super(SongBird, self).__init__()` 与 `Bird.__init__(self)`（未关联超类构造）都是 Python 2 遗产：前者冗长且类改名时易错，后者只在多继承下刻意绕过 MRO 时才需要。

### 2. 元素访问：序列与映射协议

`len(obj)` → `__len__`；`obj[k]` / `for` / `in` / 切片 → `__getitem__`；`obj[k] = v` → `__setitem__`；`del obj[k]` → `__delitem__`。

```python
class ArithmeticSequence:           # 等差数列：惰性计算 + 局部覆盖
    def __init__(self, start=0, step=1):
        self.start, self.step, self.changed = start, step, {}

    def __getitem__(self, key):
        if not isinstance(key, int):
            raise TypeError("索引必须是整数")
        return self.changed.get(key, self.start + key * self.step)

    def __setitem__(self, key, value):
        self.changed[key] = value


s = ArithmeticSequence(1, 2)
print(s[4], s[100])                 # 9 201
s[4] = 2
print(s[4])                         # 2 —— 被局部覆盖
```

从 `list`/`dict`/`str` **派生**是另一条路，但 3.x 下内置类型的方法不会相互协同（`CounterList.append` 不走你重写的 `__setitem__`）；**推荐实现协议，或继承 `collections.UserList`/`UserDict`/`UserString`**。

### 3. 特性：`property` 与属性拦截

```python
class Rectangle:
    def __init__(self, width=0, height=0):
        self.width, self.height = width, height

    @property
    def size(self):                     # 读：仍是 r.size，不是 r.get_size()
        return self.width, self.height

    @size.setter
    def size(self, value):
        self.width, self.height = value


class Lazy:
    def __getattr__(self, name):        # 仅在常规查找失败时兜底
        return f"<lazy:{name}>"


class Loud:
    def __getattribute__(self, name):   # 每次属性访问都触发
        print("访问:", name)
        return super().__getattribute__(name)


r = Rectangle(3, 4)
r.size = 10, 20
print(r.width, r.height, r.size)        # 10 20 (10, 20)
print(Lazy().anything)                  # <lazy:anything>
loud = Loud(); loud.x = 1
print(loud.x)                           # 访问: x \n 1
```

`property` 的价值是**保持调用方语法不变**：先用普通属性，后来需要校验/计算再改成 `property`，外部一行不动；原书的 `size = property(get_size, set_size)` 仍有效，但装饰器形式已是主流。`__getattr__` 与 `__getattribute__` 必须分清（原书只重点讲了前者）：前者只在**查找失败**时调用，适合代理与懒加载；后者**每次**访问都经过，写错就是无限递归，内部必须 `super().__getattribute__(name)`；同理 `__setattr__` 要用 `super().__setattr__`。

### 4. 迭代器协议

**可迭代对象**有 `__iter__`（返回迭代器）；**迭代器**既有 `__iter__`（通常 `return self`）又有 `__next__`。`for` = 先 `iter()` 再反复 `next()` 直到 `StopIteration`。

```python
from itertools import islice


class Fibs:
    def __init__(self):
        self.a, self.b = 0, 1

    def __iter__(self):
        return self                     # 自己就是迭代器

    def __next__(self):
        self.a, self.b = self.b, self.a + self.b
        return self.a


print(list(islice(Fibs(), 8)))          # [1, 1, 2, 3, 5, 8, 13, 21]
print(list(iter("abc")))                # 从迭代器创建序列：list() 一次抽干（9.6 末尾）
```

### 5. 生成器：把迭代器写成函数

```python
def flatten(nested):
    if isinstance(nested, (str, bytes)):    # 字符串是叶子，否则会无限递归
        yield nested
        return
    try:
        for sub in nested:
            yield from flatten(sub)     # PEP 380：替代 for + yield 样板
    except TypeError:                   # 不可迭代 → 它就是叶子
        yield nested


def counter():
    n = 0
    while True:
        got = yield n                   # yield 表达式的值来自 send()
        n = n + 1 if got is None else got


print(list(flatten([[1, 2], [3, [4, 5]], "ab"])))   # [1, 2, 3, 4, 5, 'ab']
g = counter()
print(next(g), g.send(10), next(g))                 # 0 10 11
g.close()                                           # 在挂起点抛 GeneratorExit
```

`yield from` 不只是语法糖：它把 `send()`、`throw()`、`close()` 与返回值**透传**给子生成器，手写 `for x in sub: yield x` 做不到。`send`/`throw`/`close` 让生成器升级为「协程的最小形态」；想「模拟生成器」，用普通函数攒一个列表再返回即可，代价是失去惰性。

### 6. 八皇后：生成器 + 回溯

状态用**元组**：索引是行号，值是该行皇后的列。冲突条件只有一个公式——同列（`dx == 0`）或同对角线（`|dx| == |dy|`）。

```python
def conflict(state, next_x):
    next_y = len(state)
    return any(abs(state[i] - next_x) in (0, next_y - i) for i in range(next_y))


def queens(num, state=()):
    if len(state) == num:               # 基线条件：摆满 → 产出
        yield state
        return
    for pos in range(num):              # 递归条件：逐列试探，冲突则剪枝
        if not conflict(state, pos):
            yield from queens(num, (*state, pos))


print(sum(1 for _ in queens(8)))        # 92；原书「扫尾工作」是逐行 '. ' * pos + 'X ' 把解画出来
```

### 7. 3.12 起：泛型类的写法变了

```python
class Stack[T]:                         # PEP 695 类型参数语法，无需 TypeVar
    def __init__(self):
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        return self._items.pop()


s = Stack[int](); s.push(3)
print(s.pop(), Stack.__type_params__)   # 3 (T,)
```

旧写法 `T = TypeVar("T")` + `Generic[T]` 仍可用，但新语法把类型参数作用域收紧到类/函数本身，错误提示更好。

## 近年研究与工业界开源实践（2015–2026）

- **CPython 源码**：生成器实现在 `Objects/genobject.c` 与字节码分派路径上，`yield from` 的透传语义见 `gen_send_ex`；读它比读二手教程准确。
- **结构化并发（`asyncio`、`anyio`、`trio`）**：把「生成器即协程」推到极致——`async with` + `TaskGroup` 取代手写 `send()` 调度。
- **`attrs` / `pydantic`**：把「自己写 `__init__`/`property`/`__eq__`」自动化，`pydantic` 更进一步把校验塞进 `__init__` 与 `__setattr__`，是 `property` 思想的工业版。
- **类型检查器（`mypy`、`pyright`）**：PEP 484/695 之后魔法方法的签名会被静态检查（`__len__` 必须返回 `int`）；**free-threading（PEP 703）** 下迭代器的局部状态（如 `Fibs.a/b`）在多线程共享不再安全。以上均为**工业界实践或工具文档，非同行评审论文**。

## 常见误区与本书需修正之处

| # | 原书说法 / 常见误区 | 问题 | 2026 正确写法 |
| --- | --- | --- | --- |
| 1 | 🔧 `super(SongBird, self).__init__()` | Python 2 遗留；冗长且类改名时易错 | `super().__init__()`（无参形式已是常态） |
| 2 | 🔧 把 `__getattr__` 说成「属性访问拦截器」 | 它只在**查找失败**时兜底 | 要拦截**所有**访问才用 `__getattribute__`，且内部必须 `super().__getattribute__(name)`，否则无限递归 |
| 3 | 🔧 泛型类用 `TypeVar` + `Generic[T]` | 3.12 起有更简洁的原生语法 | `class Stack[T]:`、`def first[T](xs: list[T]) -> T:`（PEP 695） |
| 4 | 递归生成器写 `for x in sub: yield x` | 不能透传 `send()`/`throw()` | `yield from sub`（PEP 380） |
| 5 | 🔧 本章不区分生成器与异步生成器 | 3.6 起 I/O 场景应用 `async def` + `yield` | `async def tick(): ... yield ...`，消费端 `async for`（PEP 525） |
| 6 | 继承 `list`/`dict`/`str` 定制容器 | 内置类型方法彼此不协同，容易「重写了却没被调用」 | 实现协议，或继承 `UserList`/`UserDict`/`UserString`、`collections.abc.MutableSequence` |
| 7 | `property(get_size, set_size)`；9.1 节讲 Python 2 旧式类与 `__metaclass__` | 前者不够直观；后者 Python 3 已无旧式类 | 优先 `@property` + `@x.setter`；元类写作 `class C(Base, metaclass=M)` |
| 8 | 依赖 `__del__` 释放资源；手写迭代器类才算「会用迭代器」 | 前者解释器退出时可能不调用；后者多数场景生成器一行搞定 | 用 `with` + `__enter__`/`__exit__`（PEP 343）；能用 `yield` 就别手写 `__next__` |
| 9 | 🔧 认为生成器/迭代器状态天然线程安全 | PEP 703 free-threading 下共享不再安全 | 跨线程共享显式加锁，或用队列传递；无限惰性配 `itertools.islice` |
