### 29.4 初次实现：最小可玩循环

```python
# squish_min.py —— 教学示意，不参与构建
# pip install pygame
# 运行：python squish_min.py        无显示环境：SDL_VIDEODRIVER=dummy python squish_min.py
from __future__ import annotations

import random
import sys

import pygame

WIDTH, HEIGHT, FPS = 800, 600, 60
BG = (24, 24, 32)

class Weight(pygame.sprite.Sprite):        # 从天而降的铅球：落到底部算玩家躲过一次
    def __init__(self, speed: int) -> None:
        super().__init__()
        self.image = pygame.Surface((32, 32)); self.image.fill((110, 118, 140))
        self.rect = self.image.get_rect()  # 没有素材时用纯色块代替
        self.speed = speed
        self.reset()

    def reset(self) -> None:
        self.rect.topleft = (random.randrange(WIDTH - self.rect.width), -self.rect.height)

    def update(self, dt: float) -> bool:
        self.rect.y += int(self.speed * dt)            # dt：按时间移动，帧率无关
        if self.rect.top > HEIGHT:
            self.reset()
            return True                                # 躲过一球
        return False

class Banana(pygame.sprite.Sprite):        # 玩家：跟随鼠标横向移动
    def __init__(self) -> None:
        super().__init__()
        self.image = pygame.Surface((64, 24)); self.image.fill((240, 214, 62))
        self.rect = self.image.get_rect(midbottom=(WIDTH // 2, HEIGHT - 24))

    def update(self, mouse_x: int) -> None:
        self.rect.centerx = mouse_x
        self.rect.clamp_ip(pygame.Rect(0, 0, WIDTH, HEIGHT))

def main() -> None:
    pygame.init()                                      # 返回 (成功数, 失败数)，失败不自动抛错
    screen = pygame.display.set_mode((WIDTH, HEIGHT))
    pygame.display.set_caption("Squish（最小版）")
    clock = pygame.time.Clock()
    font = pygame.font.Font(None, 36)                  # None → 默认字体，省掉字体文件

    banana = Banana()
    weights = pygame.sprite.Group(Weight(180) for _ in range(6))
    score, lives, paused = 0, 3, False

    while True:
        dt = clock.tick(FPS) / 1000.0                  # 秒；原书按固定帧移动，这里做 dt
        for event in pygame.event.get():
            # match 里必须用「带点名」的值模式（pygame.QUIT）：裸名会被当成捕获模式
            match event.type:                          # 结构模式匹配（PEP 634/635/636）
                case pygame.QUIT:
                    return pygame.quit()
                case pygame.KEYDOWN if event.key == pygame.K_ESCAPE:
                    return pygame.quit()
                case pygame.KEYDOWN if event.key == pygame.K_p:
                    paused = not paused
                case pygame.MOUSEMOTION:
                    banana.update(event.pos[0])

        if not paused:
            for w in weights:
                if w.update(dt):
                    score += 1
            if pygame.sprite.spritecollide(banana, weights, dokill=False):
                lives -= 1
                for w in weights:
                    w.reset()                          # 全部回到顶部，给玩家喘息
                if lives <= 0:
                    print(f"游戏结束，得分 {score}")
                    return pygame.quit()

        screen.fill(BG)
        weights.draw(screen)
        screen.blit(banana.image, banana.rect)
        screen.blit(font.render(f"分数 {score}  生命 {lives}", True, (235, 235, 235)), (12, 12))
        pygame.display.flip()

if __name__ == "__main__":
    main()
```

三个容易踩的点：**①** `pygame.init()` 不会在失败时抛异常，需检查返回值或用 `pygame.get_init()`；**②** 精灵必须有 `image` 与 `rect` 两个属性，`Group.draw()` 才认；**③** 退出必须 `pygame.quit()`，否则在无显示环境下进程可能挂住；**④** `match` 里要写 `pygame.QUIT` 这样的**带点名**，裸的 `QUIT` 会被当成「捕获模式」并直接 `SyntaxError`。

### 29.5 再次实现：状态机与关卡

原书的「再次实现」把游戏拆成 `State` 与 `Level` 两个类：`State` 管暂停/关卡切换/结束，`Level` 管本关的精灵与分数。下面是等价的精简版：

```python
# squish_states.py —— 教学示意，不参与构建（依赖上一节的 Weight / Banana）
import pygame

class State:                               # 状态基类：先画自己，再决定下一个状态是谁
    def handle(self, event: pygame.event.Event) -> None:
        match event.type:
            case pygame.QUIT:
                raise SystemExit
            case pygame.KEYDOWN if event.key == pygame.K_ESCAPE:
                raise SystemExit
            case pygame.KEYDOWN if event.key == pygame.K_p:
                self.paused = not self.paused
            case pygame.KEYDOWN if event.key == pygame.K_r:
                self.finished = True                   # 请求重开

    def update(self, dt: float) -> None: ...
    def draw(self, screen: pygame.Surface) -> None: ...
    def next(self) -> "State | None": ...

class Level(State):
    def __init__(self, number: int, sprite_count: int, speed: int) -> None:
        self.number, self.speed = number, speed
        self.sprites = pygame.sprite.Group()
        self.scores = 0
        self.paused = self.finished = False

    def next(self) -> "State | None":      # 本关达标 → 下一关；重开请求 → 新的第一关
        if self.finished:
            return Level(1, 4, 160)
        if self.scores >= 10 * self.number:
            return Level(self.number + 1, 4 + self.number, self.speed + 40)
        return None

# 主循环变成：state = Level(1, 4, 160)
# while True:
#     for e in pygame.event.get(): state.handle(e)
#     state.update(dt); state.draw(screen); pygame.display.flip()
#     if (nxt := state.next()) is not None: state = nxt     # 海象运算符（PEP 572）
```

状态机的价值：**每个状态的 `update` / `draw` / `next` 各自闭环**，新增「开始界面」「结算界面」只是新增一个类，主循环一行都不用改。

### 29.6 进一步探索与「2026 年等价做法」

| 方向 | 做法 |
| --- | --- |
| 素材与音效 | `pygame.image.load(...).convert_alpha()` 加速带透明通道的 blit；`pygame.mixer` 需先 `init()` |
| 动画与关卡数据 | 精灵帧序列 + `USEREVENT` 定时切帧；关卡配置放 JSON/TOML（`tomllib`，PEP 680） |
| 现代替代 | `arcade`（Pythonic 的 2D 引擎，API 更现代）；或直接用 Godot/Unity |

| 原书环节 | 原书做法（pygame 1.9） | 2026 年做法（pygame 2.x） |
| --- | --- | --- |
| 安装 | 官网下载二进制 wheel | `pip install pygame`（提供主流平台的 wheel） |
| 移动 | 每帧固定像素 | 按 `dt` 移动，帧率无关 |
| 事件常量 | 从 `pygame.locals` 导入 | 同上；`pygame.QUIT` 等也可直接访问 |
| 字体 | 指定字体文件路径 | `pygame.font.Font(None, size)` 用默认字体，或用 `pygame.font.SysFont` |
| 退出 | `sys.exit()` | 先 `pygame.quit()` 再退出，避免资源泄漏 |

## 近年研究与工业界开源实践（2015–2026）

- **pygame 2.x**：主线持续维护，wheel 覆盖主流平台，`pip install pygame` 即可用；文档与 1.9 时代的资料差异较大，查资料务必看版本。
- **pygame-ce**：🔧 **社区分支**，维护与发布节奏独立于主线，具体差异与现状**以官方公告为准**；本目录不对其做结论性判断。
- **`arcade` / `pyglet`**：前者是面向 2D 游戏的现代 Python 库（内置窗口、精灵、物理 `Pymunk` 与示例集）；后者无外部依赖，是若干游戏库的底层选择。
- **Godot / Unity**：需要「做完整游戏」时的现实选择，Python 不再处于这条路线的中心。
- **游戏循环的工程共识与研究方向**：固定时间步长的物理更新 + 可变渲染（"Fix Your Timestep!" 一文，业界经验文章，非同行评审）；游戏 AI 与程序化内容生成（PCG）近年集中在强化学习与生成模型。🔧 版本号与 API 细节以官方文档为准。

## 常见误区与本书需修正之处

| # | 原书写法 / 常见误区 | 问题 | 2026 年正确写法 |
| --- | --- | --- | --- |
| 1 | 🔧 按 pygame 1.9 的 API 查资料照抄 | 2.x 有变化（事件、字体、Surface 细节） | 以当前 pygame 官方文档为准 |
| 2 | 🔧 每帧固定像素移动 | 帧率一变，游戏速度就变 | `dt = clock.tick(FPS)/1000`，按时间移动 |
| 3 | 🔧 忽略 `pygame.init()` 的返回值 | 子系统初始化失败不报错，后面莫名崩溃 | 检查返回值 / `pygame.get_init()` |
| 4 | 🔧 退出时只 `sys.exit()` | 资源未释放，无头环境可能挂住 | 先 `pygame.quit()` 再退出 |
| 5 | 🔧 `pygame.image.load()` 后不 `convert_alpha()` | 每次 blit 都做像素格式转换，明显变慢 | 加载后立刻 `convert_alpha()` |
| 6 | 🔧 精灵没有 `image` / `rect` | `Group.draw()` 直接报错 | 两个属性是 `Sprite` 的契约 |
| 7 | 🔧 把状态判断写成一堆 `if` | 加一个界面就要改主循环 | `State` / `Level` 状态机（原书思路仍成立） |
| 8 | 🔧 不做帧率上限、或认为 pygame 只能做教学 | CPU/GPU 空转，风扇狂转；低估 2.x 的性能与生态 | `clock.tick(FPS)`；需要编辑器/发布管线时再考虑引擎 |
| 9 | 🔧 不确定 pygame 与 pygame-ce 的关系就下结论 | 两条维护线并存 | 🔧 以官方公告为准，本目录不作判断 |
