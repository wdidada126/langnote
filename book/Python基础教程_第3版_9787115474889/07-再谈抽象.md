## 核心精讲

> 以下均为**教学示意，不参与构建**：片段自足，可直接 `python x.py` 运行。

### 1. 多态：不靠继承，靠「有没有这个方法」

```python
# demo_ch7_poly.py —— 教学示意，不参与构建
class Duck:
    def speak(self): return "quack"
class Person:
    def speak(self): return "hello"
class Robot:          # 不继承任何东西，只要有 speak 就能参与
    def speak(self): return "beep"

for obj in (Duck(), Person(), Robot()):
    print(obj.speak())            # quack hello beep —— 鸭子类型

def talk(x):
    return x.speak()              # 静态类型下写：x: typing.Protocol
print(talk(Duck()))
```

Python 的多态不需要公共基类；2026 年要给这类接口写类型，用**结构化类型**（`typing.Protocol`，3.8 引入）🔧 对应 PEP 编号未在已核对清单内，以官方文档为准。

### 2. 类属性 vs 实例属性、封装与名称改写

```python
# demo_ch7_attr.py —— 教学示意，不参与构建
class Counter:
    total = 0                     # 类属性：所有实例共享
    def __init__(self, name):
        self.name = name          # 实例属性
        self.count = 0
        Counter.total += 1

a, b = Counter("a"), Counter("b")
print(a.name, b.name, Counter.total)     # a b 2

class Bag:
    def __init__(self):
        self.items = []           # ✅ 每个实例一份
class WrongBag:
    items = []                    # ❌ 共享：append 会影响所有实例
    def __init__(self):
        pass

class Secretive:
    def __init__(self):
        self.__hidden = 42        # 名称改写为 _Secretive__hidden
    def get(self):
        return self.__hidden

s = Secretive()
print(s.get(), s._Secretive__hidden)     # 42 42 —— 改写不等于真私有
print(hasattr(s, "__hidden"))            # False
```

### 3. 继承、`super()` 与 MRO

```python
# demo_ch7_inherit.py —— 教学示意，不参与构建
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "..."

class Dog(Animal):
    def __init__(self, name, breed="mixed"):
        super().__init__(name)          # 零参 super()：按 MRO 找下一个
        self.breed = breed
    def speak(self):
        return "woof"

d = Dog("Rex")
print(d.name, d.speak(), isinstance(d, Animal), issubclass(Dog, Animal))  # Rex woof True True
print(Dog.__bases__, Dog.__mro__)        # (<class 'Animal'>, ...) 含 object
print(type(d), d.__class__ is type(d))   # <class 'Dog'> True

# 多重继承与协作式 super
class Flyer:
    def __init__(self):
        print("Flyer init")
        super().__init__()               # 协作式：把调用继续沿 MRO 传下去
class Swimmer:
    def __init__(self):
        print("Swimmer init")
        super().__init__()
class Duckling(Flyer, Swimmer):
    pass
print(Duckling())                        # 先 Flyer 再 Swimmer（沿 MRO）
print([c.__name__ for c in Duckling.__mro__])   # Duckling, Flyer, Swimmer, object
```

多重继承的实操建议：**主类（真正的行为来源）放前面，mixin 放后面；所有 `__init__` 用 `super()` 协作并接受 `**kwargs`**。

### 4. 抽象基类与内省

```python
# demo_ch7_abc.py —— 教学示意，不参与构建
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...
    @property
    @abstractmethod
    def name(self) -> str: ...

class Square(Shape):
    def __init__(self, side): self.side = side
    def area(self): return self.side ** 2
    @property
    def name(self): return "square"

try:
    Shape()                       # TypeError: Can't instantiate abstract class
except TypeError as e:
    print("ABC:", e)
print(Square(3).area())           # 9

class FileLike:
    def read(self): return "data"
Shape.register(FileLike)          # 虚拟子类：不继承但被 isinstance 认可
print(issubclass(FileLike, Shape), isinstance(FileLike(), Shape))   # True True
```

内省四件套：`hasattr(obj, "x")` / `getattr(obj, "x", default)` / `setattr(obj, "x", v)` / `callable(obj)`。
注意 **`getattr` + 默认值**比 `hasattr` 后再取值更地道（EAFP 风格，见第 8 章）。

### 5. 2026 年的补充：数据类与「少写模板」

```python
# demo_ch7_dataclass.py —— 教学示意，不参与构建
from dataclasses import dataclass, field

@dataclass(frozen=True, slots=True)     # 3.7+ dataclass；slots 为 3.10+ 参数
class Point:
    x: float
    y: float = 0.0
    tags: list[str] = field(default_factory=list)   # 可变默认值必须经过 factory

p = Point(1.0, 2.0)
print(p, p == Point(1.0, 2.0))          # Point(x=1.0, y=2.0, tags=[]) True
# p.x = 5                                # frozen=True → dataclasses.FrozenInstanceError
```

`dataclass` 直接消掉了本章大量「`__init__` 里逐个赋值」的模板代码——这是原书完全没覆盖、但今天最常用的类写法。

## 近年研究与工业界开源实践（2015–2026）

- **`dataclasses` 与生态**：`attrs`（更早）、`pydantic`（运行时校验 + 序列化）、`msgspec`（高性能）把「类当作数据契约」推进为主流；PEP 557 的 `dataclass` 是标准库侧的回应。
- **类型系统**：`typing.Protocol` 让「鸭子类型」可被静态检查；`mypy --strict` 与 `pyright` 在大型代码库成为 CI 门禁，本章的「接口」概念因此从运行时内省转向编译期契约。
- **框架中的继承 vs 组合**：Django ORM 的模型继承、`SQLAlchemy` 的 declarative/mapped class 展示了「继承用于共享元数据」；Web 与依赖注入框架（FastAPI 等）则普遍用组合 + 函数式配置。
- **MRO 实践**：C3 线性化（Python 2.3 引入）的正式表述见于 Dylan / CLOS 的方法分派研究；CPython 文档给出算法。🔧 具体论文本目录不引用，避免编造。
- **研究侧**：面向对象设计的实证研究长期质疑「深继承层次」的可维护性；工业规范（如 Google Python Style Guide）明确建议优先组合——与本章 7.3 的口径一致。

## 常见误区与本书需修正之处

| # | 原书说法 / 常见误解 | 问题 | 2026 正确写法 |
| --- | --- | --- | --- |
| 1 | 🔧「多态需要共同的基类」 | Python 是鸭子类型 | 只要实现同名方法即可；要静态表达用 `typing.Protocol` |
| 2 | 「双下划线是真私有」 | 只是名称改写（`_Cls__x`） | 靠约定 `_x`；不要依赖它做安全边界 |
| 3 | 「把可变对象放类属性当默认值」 | 所有实例共享 | 在 `__init__` 里创建实例属性 |
| 4 | 🔧「`super(Child, self).__init__()`」 | 冗长且易写错类名 | 3.x 一律 `super().__init__()` |
| 5 | 「多重继承就是多个爸爸随便挑」 | MRO 决定顺序，构造顺序易错 | 主类在前、mixin 在后；用 `super()` 协作；查 `__mro__` |
| 6 | 「`isinstance` 判断类型就是坏味道」 | 有时是必要的边界处理 | 与 `hasattr` 二选一：能「请求宽恕」就别「三思而后行」（见第 8 章） |
| 7 | 「`hasattr` 检查后一定能取到」 | 属性可能是动态生成且抛异常 | 直接 `getattr(obj, "x", default)` |
| 8 | 🔧 原书用普通类承载数据 | 模板代码多 | `@dataclass`（PEP 557）；需要校验用 `pydantic` |
| 9 | 「继承越多越好」 | 层次深则难改 | 优先组合；继承只表达「是一种」 |
| 10 | 「`self` 是关键字」 | 只是约定名（PEP 8 建议） | 改名能跑但不要改；类方法用 `cls` |
| 11 | 「抽象基类能阻止你实例化子类」 | 只阻止**未实现全部抽象方法**的子类 | 实现了就能实例化；`register` 可造虚拟子类 |
| 12 | 🔧 原书未提 `__slots__` | 大量实例时内存可观 | `dataclass(slots=True)` 或手写 `__slots__`（注意与多继承/弱引用限制） |
| 13 | 「类体里只能写 `def`」 | 类体是普通命名空间，可执行任意语句 | 常见用法：常量、推导式、`__slots__` |
