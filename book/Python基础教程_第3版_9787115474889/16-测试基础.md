# 第 16 章 测试基础（原书 pp.273–285）

> 一句话定位：本章是全书的「工程化起点」——它不教新语法，而是教**如何把「我要什么」写成可执行的需求**，再用工具反复验证。基线：原书 Python 3.5；本目录按 3.12+ 校验。
> 对应英文章名：**Testing, 1-2-3**。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 16.1 准确的需求说明 | 把「要做什么」写成具体、可判定的输入/输出约定；TDD 不是先写测试，而是**先想清楚** | 需求模糊时，写测试就是澄清需求的过程 |
| 16.1 做好应对变化的准备 | 代码必然要改，测试是**允许你放心改**的前提 | 没有测试的重构 = 赌博 |
| 16.1 测试四步曲 | ① 定需求 → ② 写测试 → ③ 写最小实现 → ④ 重构并保持测试通过 | 循环推进，每轮只迈一小步 |
| 16.2 `doctest` | 在 docstring 里写 `>>>` 交互示例，由解释器验证 | 适合**文档与示例同步**，不适合复杂测试 |
| 16.2 `unittest` | `TestCase` + `setUp/tearDown` + `assertXxx` | 标准库自带、零依赖，但样板代码多 |
| 16.3 PyChecker / PyLint | 静态检查源码（拼错的名字、未用的变量、风格） | 🔧 两者都已过时，今天用 **ruff + mypy/pyright** |
| 16.3 性能分析 | 先测再优化；`timeit` 微基准、`cProfile` 全程序 | 🔧 今天再加 `py-spy`（采样式、线上可用）与 `scalene`（行级 + 内存） |
| 16.4 小结 | 测试是给未来的自己写的，不是给老师写的 | 见「常见误区」表 |

## 核心精讲

> 以下所有代码均为**教学示意，不参与构建**：本目录不搭建测试工程，示例可直接复制进临时目录运行。

### 1. 测试四步曲（原书 16.1）

```
① 需求：确定这个改动「做什么」，写成一句话 + 一组输入/输出例子
② 测试：把上面的例子写成会失败的测试（红）
③ 实现：写最少的、能让测试通过的代码（绿）——可以先写占位函数
④ 重构：清理重复与坏味道，测试必须仍然通过（重构不改行为）
        ↑______________________________________________|
```

四步里最容易省掉的是第 ① 步：很多人从「我先写个函数试试」开始，于是测试的其实是
「我现在写出来的行为」，而不是「我真正需要的行为」。

### 2. `doctest`：文档即测试（原书 16.2）

`stats.py`（教学示意，不参与构建）：

```python
# stats.py —— 教学示意，不参与构建
def mean(values: list[float]) -> float:
    """返回算术平均值。

    >>> mean([1, 2, 3, 4])
    2.5
    >>> mean([])
    Traceback (most recent call last):
        ...
    ZeroDivisionError: division by zero
    """
    return sum(values) / len(values)


if __name__ == "__main__":
    import doctest
    print(doctest.testmod())          # 运行本模块内所有 docstring 示例
```

运行：`python stats.py`（零输出即全部通过）或 `python -m doctest -v stats.py` 看逐条结果。

要点：`doctest` 比较的是**解释器 repr 的文本**，所以浮点、字典顺序、对象地址都可能导致误报；
它最适合作为「README 里的示例不会腐坏」的守卫，而不是主力测试框架。

### 3. `unittest`：标准库方案（原书 16.2）

`test_stats.py`（教学示意，不参与构建）：

```python
# test_stats.py —— 教学示意，不参与构建
import unittest

from stats import mean


class MeanTest(unittest.TestCase):
    def setUp(self):
        self.data = [1, 2, 3, 4]

    def test_mean(self):
        self.assertEqual(mean(self.data), 2.5)

    def test_empty(self):
        with self.assertRaises(ZeroDivisionError):
            mean([])


if __name__ == "__main__":
    unittest.main()
```

运行：`python -m unittest -v` 或直接 `python -m pytest -q`（pytest 能直接跑 `unittest` 用例，
这是迁移期最省事的过渡方案）。

### 4. 2026 年的默认选择：pytest

```bash
pip install pytest pytest-cov hypothesis   # 一次性安装
```

`test_stats_pytest.py`（教学示意，不参与构建）：

```python
# test_stats_pytest.py —— 教学示意，不参与构建
import pytest

from stats import mean


@pytest.fixture
def data():
    return [1, 2, 3, 4]


@pytest.mark.parametrize(
    ("values", "expected"),
    [([1, 2], 1.5), ([1, 2, 3, 4], 2.5), ([-1, 1], 0.0)],
)
def test_mean(values, expected):
    assert mean(values) == expected


def test_empty():
    with pytest.raises(ZeroDivisionError):
        mean([])
```

pytest 相对 `unittest` 的三点关键优势：**断言用裸 `assert`**（失败时自动展示中间值）、
**fixture 可组合/可作用域化**（`scope="module"`、`tmp_path`、`monkeypatch` 开箱即用）、
**parametrize 替代复制粘贴的用例**。原书靠 `unittest` 教的「测试结构」依然成立，只是表达层换掉了。

### 5. 属性测试：从「几个例子」到「一类性质」

```python
# test_stats_hypothesis.py —— 教学示意，不参与构建
from hypothesis import given
from hypothesis import strategies as st

from stats import mean


@given(st.lists(st.integers(), min_size=1))
def test_mean_between_extremes(values):
    m = mean(values)
    assert min(values) <= m <= max(values)
```

`hypothesis` 会**自动生成反例并缩小到最小复现**，特别适合边界密集的纯函数。
它补的正是原书「手工挑几个例子」的短板。

### 6. `ExceptionGroup` 与断言写法（3.11+）

一条记录同时违反多条校验时，3.11 之前只能报第一个错；PEP 654 后可以一次收集：

```python
# exc_group_demo.py —— 教学示意，不参与构建（需要 Python 3.11+）
def validate(rec: dict) -> None:
    errors: list[Exception] = []
    if "id" not in rec:
        errors.append(KeyError("id"))
    if rec.get("age", 0) < 0:
        errors.append(ValueError("age"))
    if errors:
        raise ExceptionGroup("invalid record", errors)


try:
    validate({"age": -1})
except* KeyError as eg:
    print("key problems:", [str(e) for e in eg.exceptions])
except* ValueError as eg:
    print("value problems:", [str(e) for e in eg.exceptions])
```

测试侧对应写法：`with pytest.raises(ExceptionGroup) as ei: ...` 再断言
`ei.value.exceptions` 的类型集合；`unittest` 侧可用 `self.assertRaises(ExceptionGroup)`。
注意 `except*` 是**并行处理同一组的多个子异常**，不是 `except` 的语法糖。

### 7. 性能分析：先测量，再优化

| 场景 | 工具 | 命令 |
| --- | --- | --- |
| 微基准（单行） | `timeit`（标准库） | `python -m timeit "'-'.join(str(n) for n in range(100))"` |
| 全程序热点 | `cProfile`（标准库） | `python -m cProfile -s cumtime app.py` |
| 已运行的进程 | `py-spy`（第三方） | `py-spy top --pid 1234` / `py-spy record -o prof.svg --pid 1234` |
| 行级 + 内存 + GPU | `scalene`（第三方） | `scalene app.py` |

`cProfile` 输出常配合 `pstats` 或直接 `python -m cProfile -o prof.out app.py` 后用
`snakeviz` 可视化。**不要凭直觉优化**：原书强调「优化前先 profile」，这条在 2026 年依然是一号纪律。

## 版本演进

| 版本 | 与本章相关的变化 |
| --- | --- |
| 3.5（原书基线） | `unittest` 已有 `subTest`、`mock` 已进入标准库（`unittest.mock`）；`doctest` 行为稳定 |
| 3.6 | f-string（PEP 498）让测试里的失败信息更好写 |
| 3.7 | `breakpoint()` 取代手写 `pdb.set_trace()`；`unittest` 支持 `-k` 过滤（3.7 起） |
| 3.8 | `unittest.IsolatedAsyncioTestCase` 出现（3.8），异步测试不必再手写循环 |
| 3.9 | 内置泛型（PEP 585）让 fixture 注解不必写 `typing.List` |
| 3.10 | `match`（PEP 634）可用于断言失败分支的分派 |
| 3.11 | 🔴 `ExceptionGroup` / `except*`（PEP 654）改变「多错误」断言写法；Faster CPython 让基准数字整体变化 |
| 3.12 | 类型参数语法（PEP 695）让测试辅助函数可直接写 `def make[T](cls: type[T]) -> T` |
| 3.13 / 3.14 | 🔴 free-threading（PEP 703）下**并发测试必须显式加锁断言**；3.14 注解延迟求值（PEP 649 系）让 `typing.get_type_hints` 在测试中的开销下降 🔧 |

## 近年研究与工业界开源实践（2015–2026）

- **pytest**（`pytest-dev/pytest`）：事实标准测试框架。关键能力——fixture 依赖注入、
  `parametrize`、插件生态（`pytest-cov`、`pytest-asyncio`、`pytest-xdist` 并行、
  `pytest-randomly` 打乱顺序以暴露测试间耦合）。下列工具文档均属**非同行评审**的工业界资料。
- **hypothesis**（`HypothesisWorks/hypothesis`）：属性测试的 Python 实现，起源于
  Haskell 的 QuickCheck 思想；其「shrinking（反例缩小）」是差异化价值。
- **ruff**（`astral-sh/ruff`）：Rust 实现的 linter + formatter，一个二进制替代
  flake8 / isort / pyupgrade / black 的大部子集，取代原书的 PyChecker 与 PyLint。
- **mypy / pyright / basedpyright**：静态类型检查；与测试互补——类型检查消除一整类错误，
  测试覆盖运行时行为。类型注解的规范基础是 PEP 484。
- **coverage**（`nedbat/coveragepy`）：行覆盖 + 分支覆盖（`--branch`）；注意
  **覆盖率 100% ≠ 测试充分**，它只证明「跑过」，不证明「断言对」。
- **mutation testing**（`mutmut`、`cosmic-ray`）：故意往代码里注入错误，看测试是否失败，
  比覆盖率更能反映测试质量。
- **py-spy / scalene**：采样式与行级分析器；py-spy 以外部进程方式读取目标进程内存，
  可**不重启**地分析线上 Python 服务，这是原书 `cProfile` 做不到的事。
- **研究侧**：关于「测试充分性」的学术工作集中在 **变异测试的成本削减**
  （选择性地只变异被覆盖到的行）与 **基于 LLM 的测试生成**；后者当前结论是
  **能快速产出骨架、仍需人工审定断言**，🔧 具体结论以最新评测为准。

## 常见误区与本书需修正之处

| # | 原书说法 / 常见想法 | 问题 | 2026 正确写法（🔧 = 需修正） |
| --- | --- | --- | --- |
| 1 | 用 `doctest` 做主力测试 | 依赖 repr 文本、难覆盖复杂对象、报错信息差 | 🔧 `doctest` 保留作**文档守卫**；主力用 pytest |
| 2 | 用 `unittest` 写全部测试 | 样板多、断言表达弱、插件生态弱 | 🔧 新项目直接 pytest；存量 `unittest` 可被 pytest 直接运行，逐步迁移 |
| 3 | 测试写在 `main()` 里、靠 `unittest.main()` 启动 | 与 IDE/CI 集成差 | 🔧 用文件约定 `test_*.py`，命令行 `pytest -q` |
| 4 | 用 PyChecker 检查源码 | 🔧 PyChecker 已长期无维护，不支持 Python 3 | 🔧 用 `ruff check`（规则集涵盖 pyflakes + 大量现代规则） |
| 5 | 用 PyLint 检查源码 | PyLint 仍在维护但慢、配置重、默认规则吵 | 🔧 首选 `ruff`；需要深度语义分析时叠加 mypy/pyright |
| 6 | 性能分析只有 `cProfile` | 侵入式、只看到 CPU、无法看已运行进程 | 🔧 加 `timeit`（微基准）、`py-spy`（线上采样）、`scalene`（行级 + 内存） |
| 7 | 「测试通过了就没 bug」 | 测试只覆盖你**想到**的输入 | 🔧 补 `hypothesis` 属性测试与边界用例；用变异测试检验测试质量 |
| 8 | 覆盖率越高越好 | 高覆盖率可伴随全无断言 | 🔧 看分支覆盖 + 变异得分，别把 100% 当 KPI |
| 9 | 多错误场景只能报第一个 | 3.11 前确实如此 | 🔧 PEP 654：`raise ExceptionGroup(...)` + `except*`；pytest 用 `pytest.raises(ExceptionGroup)` |
| 10 | 先写代码再补测试 | 补出来的测试往往复述现状 | 至少先写下输入/输出约定（可以只是注释），再实现 |
| 11 | 重构时顺手改测试 | 会让测试失去保护意义 | 重构阶段**只改实现不动断言**；断言要改说明需求变了 |
| 12 | 🔧 原书未涉及 | 原书没有类型检查、CI、并行测试 | 补：`mypy` 进 CI、`pytest -n auto`（xdist）、`pre-commit` 跑 ruff |
| 13 | 🔧 原书未涉及 | 测试依赖真实时间与随机数会产生 flaky | 补：`freezegun`/`monkeypatch` 固定时间，`random.seed` 固定随机数 |
