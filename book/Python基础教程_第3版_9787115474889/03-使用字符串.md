## 核心精讲

> 以下均为**教学示意，不参与构建**：片段自足，可直接 `python x.py` 运行。

### 1. 不可变性是理解一切字符串行为的前提

```python
# demo_ch3_basics.py —— 教学示意，不参与构建
s = "python"
print(s[0], s[-1], s[1:4], s[::-1])   # p n yth nohtyp
try:
    s[0] = "P"                        # TypeError: 'str' object does not support item assignment
except TypeError as e:
    print("不可变：", e)
print(s.replace("p", "P"))            # Python —— 返回新串，原串不变
print(s.upper(), s)                   # PYTHON python
print("th" in s, "x" not in s)        # True True
```

因为不可变，**循环中反复 `s += piece`** 在 CPython 里靠解释器优化常常「看起来不慢」，但这是实现细节；正确写法是收集到 list 再一次 `join`。

### 2. 格式说明符的完整语法（本章最需要背的一张图）

```
format_spec ::= [[fill]align][sign]["z"]["#"]["0"][width][grouping]["." precision][type]
                └─── 对齐 ───┘  └符号┘        └宽度┘  └千位┘   └精度┘   └转换┘
示例："{:>10,.2f}".format(1234.567)  →  '  1,234.57'
      填充=空格（默认） 对齐=右  千位=,  精度=2  类型=f
```

```python
# demo_ch3_format.py —— 教学示意，不参与构建
print("{} {}".format("a", 1))              # a 1
print("{1} {0} {1}".format("x", "y"))      # y x y       位置可复用
print("{name} is {age}".format(name="A", age=3))  # A is 3

# 基本转换
print("{!s} {!r} {!a}".format("ä", "ä", "ä"))   # ä 'ä' '\xe4'
print("{:b} {:o} {:x} {:X}".format(255, 255, 255, 255))  # 11111111 377 ff FF
print("{:e} {:g} {:%}".format(12345.6789, 12345.6789, 0.25))  # 1.234568e+04 12345.7 25.000000%

# 宽度 / 精度 / 千位
print("|{:10}|".format("hi"))              # |        hi|
print("|{:.2f}|".format(3.14159))          # |3.14|
print("{:,}".format(1234567890))           # 1,234,567,890

# 符号 / 对齐 / 0 填充
print("|{:<10}|{:^10}|{:>10}|".format("a", "b", "c"))
print("{:+} {:+}".format(3, -3))           # +3 -3
print("{:=+8d}".format(-42))               # -     42   （= 把符号与数字分开填充）
print("{:08.2f}".format(3.5))              # 00003.50
print("{:#b} {:#o}".format(10, 10))        # 0b1010 0o12
print("{{}}".format())                     # {} —— 双花括号转义
```

### 3. f-string：2026 年的默认写法（PEP 498 / PEP 701）

```python
# demo_ch3_fstring.py —— 教学示意，不参与构建
name, price, n = "apple", 3.5, 12
print(f"{name:>8}: {price:>6.2f} × {n:>3d} = {price * n:>8,.2f}")
print(f"{price = }")                       # 3.8+ 调试语法：price = 3.5
print(f"{price = :.3f}")                   # 可与格式说明符连用
print(f"{'嵌套引号'}")                      # 3.12+（PEP 701）：内外同类引号不再报错
print(f"{name.upper()}")                   # 插值位置是完整表达式
# 多行 f-string（3.12+ 可含注释与换行）
msg = f"""
result: {price * n
         # 单价 × 数量
         :,.2f}
"""
print(msg)
```

f-string 与 `str.format` 的能力对比：

| 维度 | `str.format` | f-string |
| --- | --- | --- |
| 表达式内联 | 只能取变量/下标/属性 | 任意表达式（含函数调用） |
| 模板复用 | 模板可存变量、可外部化（i18n） | 字面量内联，难外部化 |
| 性能 | 需解析模板 | 编译期拼装，通常更快 |
| 转义自由度 | 一直自由 | 3.12 起（PEP 701）才自由 |

**结论**：业务代码用 f-string；需要把模板存进配置/翻译文件时，仍用 `str.format`。

### 4. 高频字符串方法

```python
# demo_ch3_methods.py —— 教学示意，不参与构建
print("hi".center(10, "*"))                # ****hi****
print("abcabc".find("bc"), "abc".find("z"))  # 1 -1  （find 找不到返回 -1，index 抛异常）
print("a-b-c".split("-"), "a b\nc".split())  # ['a','b','c'] ['a','b','c']
print("a.b.c".rsplit(".", 1))              # ['a.b', 'c']
print("  x  ".strip(), "xxaxx".strip("x"))  # x a
print(",".join(["a", "b"]))                # a,b
print("Hello".lower().title().swapcase())   # hELLO
print("a,b".replace(",", "-"))             # a-b

table = str.maketrans("abc", "xyz", " ")   # 第三参：映射到 None（删除）
print("a b c".translate(table))            # xyz
print("Python3".startswith("Py"), "42".isdigit(), "  ".isspace())
```

判断类方法一览（原书 3.4 末尾）：

| 方法 | 含义 | 注意 |
| --- | --- | --- |
| `isalnum/isalpha/isdecimal/isdigit/isnumeric` | 字符类别判断 | 三者的 Unicode 范围递增，中文数字在 `isnumeric` 下为 `True` |
| `islower/isupper/istitle` | 大小写形态 | 无大小写字符时返回 `False` |
| `isspace/isprintable/isidentifier` | 空白 / 可打印 / 是否合法标识符 | `isidentifier` 不排除关键字 |
| `isascii`（3.7+） | 是否纯 ASCII | 原书未覆盖 |

## 近年研究与工业界开源实践（2015–2026）

- **模板安全**：Web 与 ORM 领域长期被「字符串拼接构造 SQL / HTML」的注入问题困扰。工业界答案是**参数化查询 + 转义模板引擎**（Jinja2 自动转义）；3.14 的 t-string 是语言层面的同方向尝试（非同行评审的 CPython 提案与博客讨论为主）。
- **格式化性能**：CPython 3.12 起 f-string 走新的解析器路径，`pyperf` 基准（CPython 官方基准套件，非论文）显示 f-string 通常优于 `%` 与 `str.format`。
- **i18n / l10n**：`gettext` + `%`-style 或 `{}` 占位符仍是主流，因为**模板需要外部化**；这是 f-string 无法完全取代 `format` 的现实原因。
- **日志**：`logging` 模块刻意保留 `%`-style 惰性格式化（`logger.info("x=%s", x)`），避免无谓的字符串构造——PEP 282 引入的模块至今未改此约定。
- **文本处理生态**：`regex`（第三方，支持 `\p{...}` 与可变宽 lookbehind）、`Unidecode`、`ftfy` 等库补足标准库对 Unicode 边界情况的处理；🔧 具体能力以各库文档为准。

## 常见误区与本书需修正之处

| # | 原书说法 / 常见误解 | 问题 | 2026 正确写法 |
| --- | --- | --- | --- |
| 1 | 🔧「用 `format` 拼接字符串」作为首选 | 3.6 起有更直接的选择 | 优先 f-string：`f"{name}: {price:.2f}"` |
| 2 | 「`format` 已过时，别学」 | 模板外部化（翻译/配置）时必需 | 保留 `str.format`；判断标准是「模板要不要脱离代码」 |
| 3 | 「`find` 找不到会报错」 | `find` 返回 `-1`，`index` 才抛 `ValueError` | 需要「找不到就失败」时用 `index` |
| 4 | 「`strip()` 去掉字符串中间空格」 | 只处理两端 | 中间用 `replace(" ", "")` 或 `"".join(s.split())` |
| 5 | 「`"".join(list)` 与 `+` 循环等价」 | 循环 `+` 是 O(n²)（虽有解释器优化） | 一律先收集后 `join` |
| 6 | 「`split()` 与 `split(" ")` 一样」 | 无参 `split()` 按**任意空白**切且忽略连续空白 | 要精确按单空格切才传 `" "` |
| 7 | 「`{:.2f}` 用于字符串会截断」 | 精度 `.n` 对非数字类型就是截断字符数 | 截断字符串用切片 `s[:n]` |
| 8 | 「`{:010}` 是宽度 10 补 0」 | `0` 是「符号感知的零填充」标志 | 一般补零用 `{:0>10}` 更直观；`0` 与 `<^>` 同时写时后者优先 |
| 9 | 「`translate` 只能单字符替换」 | 配合 `str.maketrans` 可传 dict（键为码点） | `str.maketrans({ord("a"): "x"})` |
| 10 | 🔧 原书未提 `removeprefix/removesuffix` | 3.9 起有官方方法 | `s.removeprefix("http://")` 取代 `s[7:]` |
| 11 | 「字符串是字节数组」 | `str` 是 Unicode 码点序列 | 长度用 `len(s)`（字符数）；字节数用 `len(s.encode())` |
| 12 | 拼接 SQL / HTML 用 f-string | 注入风险 | 参数化查询、模板引擎自动转义 |
