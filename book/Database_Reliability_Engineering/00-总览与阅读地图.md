### ⚠️ 同名书歧义澄清（本会话实测，重要）

英文世界有两本都叫 *Database Reliability Engineering* 的书，极易混淆：

| | 本书（Hardy & Stubbs, 2016） | 撞名书（Campbell & Majors, 2014） |
| --- | --- | --- |
| 全名 | Database Reliability Engineering（O'Reilly 平台）| Database Reliability Engineering: Designing and Operating Resilient Database Systems |
| 出版社 | 自出版/CreateSpace，O'Reilly 平台电子书 | Apress（Springer 分销） |
| 中文改版 | — | 《数据库可靠性工程：数据库系统设计与运维指南》，人民邮电出版社 2020-11，ISBN 9787115548863 |
| 定位 | 数据工程师的**可靠性实践与心智**（工程文化 + 无停机变更 + 容量/混沌） | DBA 视角的**设计与运维手册**（虚拟化/存储/备份/复制，偏 Oracle） |

✅ 实测依据（2026-09，本会话）：
- Amazon 商品页 `/dp/1491925949` 实抓：标题即撞名书全名、页面出现 Campbell×14 / Majors×15 / Hardy×0——ISBN 前缀 14919 被 Apress 电子书使用；
- 当当/孔夫子/读酥/百度百科命中「数据库可靠性工程」均指向撞名书的图灵中文版；
- 豆瓣书目接口 `subject_suggest?q=Database Reliability Engineering` 仅返回撞名书（subject/26948564）。

**结论**：中文互联网上「数据库可靠性工程」一词几乎全部指向 Campbell & Majors；本目录主角 Hardy & Stubbs 一书资料稀少、多数检索通道不可达，故其目录逐章标 ⚠️。

## 本书主题一句话

**数据库是有状态系统的例外，SRE 方法论必须为它改写**：容量是一等公民、变更必须无停机、
失败要被主动演练、数据是「生产资料」而不是一次性消耗品——这四条撑起了后来十年
「数据库 SRE / DataOps」的雏形。

## 阅读路径建议

- **主线 A（角色认知）**：00 → 01 → 07。先弄清 DBRE 是什么、为谁存在，再看它
  的世界观底座（数据 = 生产资料）。适合被「设不设 DBRE 岗」困扰的团队。
- **主线 B（工程硬线，推荐）**：05 → 02 → 04 → 07。
  变更纪律是全书杠杆最大的一章，从你最晚要做的那件事（今晚的 DDL）倒序读起。
- **主线 C（SRE 迁移线）**：01 → 03 → 06 → 07。
  适合已从 Google SRE 方法论过来、想知道「有状态要改哪些规则」的读者。
- **插叙**：任何主线中，04 章文件是 02/03/05/07 的公共前置概念（体积影响一切）。

   凡「最新演进」节的结论均给出可点击来源与可达性状态。

   云数据库/厂商行为一律「转述 + ⚠️」，临时脚本与数据一律落在
   `D:\develops\tmp\dbwave_dre\`，repo 内零构建产物。

## 本目录在数据库系列中的定位

本书补的是「**工程实践/组织角色**」维度：系列内其他书目讲引擎机制（InnoDB、查询优化器）、
讲 SQL 理论、讲分布式共识，而本书讲**围绕数据库这个有状态服务如何组织工程活动**——
它是 [../数据库系列·总索引.md](../数据库系列·总索引.md) 中「可靠性与运维实践」线的枢纽。
