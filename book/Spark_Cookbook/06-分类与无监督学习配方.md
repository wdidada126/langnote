## 1. 章域定位

Ch8 是全书食谱密度最高的机器学章节：逻辑回归、SVM、决策树、随机森林、梯度提升树、朴素贝叶斯六个分类器逐一给「数据准备→训练→评估」三件套，评估侧统一用 `BinaryClassificationMetrics`/`MulticlassMetrics`（AUC/precision/recall/混淆矩阵）。Ch9 用 k-means、PCA、SVD 三题补齐无监督面。两章合起来是一份 **2015 年经典 ML 算法在 Spark 上的可达性清单**——今天它的算法层完全不过时，过时的是调用面（RDD 旧 API）与默认超参。

## 3. 精读块一：线性分类器三连（8.1/8.2 + 承接 05 章正则话题）

**问题**：同一份 LabeledPoint 数据，逻辑回归与 SVM 到底怎么选。
**配方骨架**：两者都走 `WithSGD` 家族；逻辑回归输出概率（阈值可调）、SVM 输出间隔决策值（hinge 损失、对离群点更硬）；评估统一 `areaUnderROC`。
**评注 ⚠️**：2026 答案基本是「先 LogisticRegression（可解释 + 概率校准 via calibration 参数），效果不足再上树系」——但食谱教的「同一评估管道换模型」方法论仍是 ML 工程第一课。SVM 在大样本上 SGD 训练慢的痛点后来由 LinearSVC+LBFGS 缓解；核方法 SVM 从未进入 MLlib，这一留白至今由外部库补 ⚠️。
**坑**：类别不平衡时 AUC 好看而 PR 崩盘，8.1-8.2 食谱全用均衡样例，生产需自补重采样/类权（`weightedMetrics`、threshold 调整）。

## 4. 精读块二：树系三件套（8.3/8.4/8.5）

**要点**：单树吃 maxDepth 与分裂质量（variance/gini）；随机森林靠 bagging+特征子采样降方差、天然抗过拟合、可白嫖特征重要性；GBT 靠 boosting 降偏差、对 learningRate×轮次成对敏感、易过拟合需早停。
**评注 ⚠️**：当年三食谱各自训练单模型，今天默认动作是 pipeline + `CrossValidator`/`TrainValidationSplit` 自动选参；特征重要性在 GBT/RF 间的解释差异（gain vs impurity）是食谱未触及、面试与生产都常考的续题。XGBoost/LightGBM/Spark ML 原生系并存的格局下，8.3-8.5 的算法直觉迁移到任何一家都成立。
**对位阅读**：姊妹册的完整树案例见 [../Advanced_Analytics_with_Spark_2e/04-用决策树预测森林植被.md](../Advanced_Analytics_with_Spark_2e/04-用决策树预测森林植被.md)（真实数据集 + 调参纵深）。

## 5. 精读块三：无监督三题（9.1-9.3）

- **k-means**：k 用肘部/轮廓系数定（食谱直给 k=2 教学值 ⚠️）；k-means|| 初始化在旧 API 即已存在，现代 ml.KMeans 默认并行化 k-means||；聚类结果当特征喂下游模型是食谱没教的组合拳。
- **PCA**：RowMatrix 路线只给主成分，无解释方差输出；ml.PCA 的 `explainedVarianceRatio` 才让「保留 95% 方差」成为可操作配方。
- **SVD**：截断 SVD 是推荐系统 latent factor 的同族工具——与 07 章 ALS 形成「矩阵分解双面」的伏笔，食谱把 SVD 放降维、ALS 放推荐，实际数学同源。
- **坑**：无标准化直接聚类 = 让大尺度特征垄断距离，与 05 章正则化坑是同一根子；距离度量在稀疏向量上的稀疏性优化（只算交集维度）当年无 API 支持，需自实现。
**对位阅读**：k-means 真实案例见 [../Advanced_Analytics_with_Spark_2e/05-K均值聚类网络异常检测.md](../Advanced_Analytics_with_Spark_2e/05-K均值聚类网络异常检测.md)。

## 8. 配方骨架速查（考古重构，⚠️ 转述，语法按 1.x 旧 API 惯例）

- **8.1/8.2**：`LogisticRegressionWithSGD.train(data, iterations, step)` 与 `SVMWithSGD.train(...)` 同族；阈值二值化后用 `BinaryClassificationMetrics(scoreAndLabels)` 出 AUC ⚠️。
- **8.3**：`DecisionTree.trainClassifier(data, numClasses, categoricalFeaturesInfo, impurity, maxDepth, maxBins)` ⚠️。
- **8.4/8.5**：`RandomForest.trainClassifier(data, numClasses, featureInfo, numTrees, subsetStrategy, impurity, maxDepth, maxBins)`；`GradientBoostedTrees.train(data, strategy)`，strategy 内 learningRate/numIterations 成对 ⚠️。
- **8.6**：`NaiveBayes.train(labeledPoints, lambda, modelType)`（伯努利/多项式/高斯三型）⚠️。
- **9.1**：`KMeans.run(points, k, runs)`；k-means|| 初始化在默认路径 ⚠️。
- **9.2/9.3**：`new RowMatrix(rows).principalComponents(k)`、`RowMatrix... ._computeSVD(k)`；稀疏行矩阵即可跑 ⚠️。

## 11. 易混点辟谣（快问快答）

- **误区：AUC 高就能上线**——阈值敏感与不平衡场景下看 PR 曲线与业务成本矩阵。
- **误区：随机森林不用调**——maxBins/maxNodes 直接决定内存画像，树深不够时 RF 也欠拟合。
- **误区：GBT 强就都用它**——标签噪声大时 boosting 放大噪声，bagging 系反而稳。
- **误区：MLlib 的 SVM 能核化**——只有线性族（SGD/网格路线），核方法 2026 仍在 Spark 体制外 ⚠️。
- **误区：k-means 惯性下降=聚类变好**——惯性随 k 单调降，选型要靠轮廓系数/业务粒度等外部判据。
- **误区：PCA 与 SVD 是两门魔法**——同族矩阵分解，前者看协方差方向、后者服务稀疏低秩近似。

## 核心概念速览（中英对照）

- **逻辑回归** — logistic regression：线性决策面 + sigmoid 概率输出的分类 baseline。
- **SVM/hinge 损失** — support vector machine：间隔最大化分类器，MLlib 仅线性核。
- **AUC/ROC** — area under ROC curve：阈值无关的排序质量指标，8.x 统一评估口径。
- **混淆矩阵** — confusion matrix：MulticlassMetrics 的矩阵化正确/错误视图。
- **基尼/方差** — gini/variance impurity：分类树/回归树分裂质量函数。
- **bagging/boosting** — 随机森林/GBT 两大集成范式：降方差 vs 降偏差的教科书对照。
- **特征重要性** — feature importances：树系模型的副产品解释接口。
- **朴素贝叶斯** — Naive Bayes：条件独立假设的频率计数分类器，文本/类别特征利器。
- **k-means||** — scalable k-means initialization：并行初始化策略，旧 API 已内置。
- **主成分分析** — PCA：方差最大方向投影，解释方差比是其选型依据。
- **截断 SVD** — truncated SVD：稀疏大矩阵的隐语义分解，与 ALS 数学同源。
- **类不平衡** — class imbalance：AUC 陷阱的生产级前提，食谱盲区之一。
- **轮廓系数** — silhouette score：k-means 选 k 的评估工具，食谱未给需自补。

## 最新演进与工业实践

- **调用面**：六分类器全部有 ml pipeline 对位（LogisticRegression/LinearSVC/DecisionTreeClassifier/RandomForestClassifier/GBTClassifier/NaiveBayes），官方 ML 指南 ✅ https://spark.apache.org/docs/latest/ml-guide.html （2026-10-01 验活）按「分类/聚类/降维」章法重组本章内容；旧 mllib 算法族进入维护期 ⚠️。
- **超参自动化**：`ParamGridBuilder + CrossValidator`（k-fold）是本章九个食谱的现代统一前缀；GPU 加速（RAPIDS Spark）让树系训练在 PB 级特征表上进入小时级——食谱手工 for 循环时代结束 ⚠️。
- **竞品格局**：工业表格学习里 XGBoost-Spark/LightGBM 与 MLlib 树系三分天下，GDTs 的分布式的 Spark 原生性与外部库的单机优化互为替代；「Spark 负责特征、专项库负责训练」的分工在特征平台化（feature store）浪潮中进一步固化 ⚠️。
- **无监督现状**：k-means/PCA/SVD 仍是批式大宽表标配（十亿级向量聚类、embedding 压缩）；但向量检索场景已移交给向量索引生态（Faiss/HNSW/DVFA 类），Spark 侧只留批式生成与重建管线——概念史见 [../bigdata/04-SparkSQL与结构化数据.md](../bigdata/04-SparkSQL与结构化数据.md) 相关延伸。
- **评估纪律**：8.x 的「训练即评估」单切分演示在 2026 被判定为反模式——时间切分、泄漏审计、跨验证窗口成为标准操作，MLflow/元数据平台负责把评估证据链留存 ⚠️。
