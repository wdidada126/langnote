# 第13章 模板和泛型编程 — T: Templates and generic programming（T.1–T.150）

> 本章目录版：[← 00-总览与阅读地图](00-总览与阅读地图.md) ｜ 单文件笔记：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md) ｜ 系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)

**本章对象**：current master 实测 T 组 **54 条**，分节：T.gp（泛型思想）、T.concepts/T.con-use/T.concepts.def
（概念条款——C++20 后指南的"已兑现"区）、Template interfaces（T.40–T.49）、T.def（定义侧）、
T.temp-hier、T.var（变参）、T.meta（元编程）、杂项（T.140–T.150）。格林的写法很德国式清醒：
**泛型是抽象的放大器，也是错误的放大器**——T 组一半规则在教"何时不用模板"。

## 核心概念速览（中英对照）

- **泛型编程** — generic programming (T.gp)：以类型为参数写算法，约束即文档
- **概念** — concept (T.10/T.20)：模板参数的语义谓词——不只是语法拼写检查
- **标准概念** — standard concepts (T.11)：`std::integral`/`std::ranges::range` 等优先自制
- **约束** — requires-clause/constraints (C++20)：概念进入函数签名的语法
- **SCARY 问题** — SCARY (T.61)：外层模板参数污染内层类型唯一性（SCary=Shared/Unshared 的旧缩写）
- **标签分派** — tag dispatch (T.65)：按能力选实现的编译期重载技术
- **CTAD** — class template argument deduction (T.44 相关)：`std::pair p{1,2.0}` 免写模板实参
- **变参模板** — variadic template (T.100)：类型不定的参数包；折叠表达式承接处理
- **TMP** — template metaprogramming (T.120)：仅在确需时用的编译期计算
- **type erasure** — 类型擦除 (T.49)：`std::function`/`any` 运行期多态与模板编译期多态的三角关系
- **两阶段查找** — two-phase name lookup：模板名查找的语法期/实例化期分工——T.69 等规则的物理基础
- **定制点** — customization point (T.69/T.165 族)：模板通过非限定调用开放给用户类型的钩子
- **de-duplication** — 模板去膨胀 (T.62)：非依赖成员下沉非模板基，控制代码膨胀

## 动机：C++20 让本章成为"改写章"而非"新增章"

指南成文（2015–2017）时 concepts 未入标，T 组大量条款是"伪概念工程学"（enable_if、
static_assert 手搓约束）。C++20 concepts 落地后，T.10–T.13、T.48（"用 enable_if 伪装概念"）
一夜从"技术指南"变成"技术史"。格林处理得好：**先讲条款背后的恒常问题（约束要表达语义而非
语法），再讲设施换了几茬**。本章与 03 章 I.9、02 章 P.1/P.5 形成"约束三部曲"的三个层次。

## 机制：模板使用的问题链

```text

```

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### T.1/T.2/T.3: 用模板提升抽象级/表达通用算法/表达容器
- 理由：同一算法第 N 次手写即失控开始；泛型把"类型变化"从复制粘贴预算中销账。
- 承接：ranges 库（P0896R4，wg21.link 实测 302）即 T.2/T.3 的标准库兑现；
  clang-tidy `readability-duplicate-include` 等只查表皮，真正的承接是"算法进库、调用点组合"。

### T.10: Specify concepts for all template arguments
- 理由：未约束模板参数=把文档写在注释里、把错误写在实例化栈深处；概念把契约变成
  类型系统公民（P.1/P.3 在模板域的直译）。
- 承接：C++20 `<concepts>`（P0898R3，实测 302）；🔧 本章实测约束报错落点；
  clang-tidy `modernize-use-constraints`（已核对官方表：enable_if → requires 迁移检查器）。

### T.11/T.12/T.13: 优先标准概念；简单单类型约束用缩写语法
- 理由：标准概念（`std::regular`/`std::invocable`）自带语义词典；`void f(auto&& x)` 缩写
  省样板但伤显式性——判据仍是"读者能否一眼看到约束"。
- 承接：`<ranges>` 的 `range`/`input_range` 族；概念别名 `template<class T> concept MyRange = ...`。

### T.20/T.21/T.22: 概念要有语义、要成集、要有公理
- 理由：`Copyable` 若只查"有拷贝构造"而不定义值语义，就是语法检查伪装语义约束；
  概念应规定定律（如 `==` 等价关系），否则泛型代码无法推理。
- 承接：ranges 概念系的"迭代器类别逐级强化"是教科书兑现（T.23 精化概念的官方样本）；
  公理不可机器检查——指南原话承认这是文档责任。

### T.44/T.47: 用函数模板推导实参；警惕高可见度的无约束同名模板
- 理由：CTAD/推导减样板；但 `<algorithm>` 级可见度下裸 `template<class T> T max(T,T)`
  会截胡 ADL——"你的模板"与"标准名字"的 namespace 战争。
- 承接：CTAD（C++17 语言设施，⚠️ 提案号未实测故不引）；名字卫生靠 SF.6/SF.7（using namespace 禁令）联防。

### T.48/T.49: enable_if 伪装概念（旧技术）；能避免类型擦除就避免
- 理由：T.48 在 C++20 后自动退休——`modernize-use-constraints` 就是给它送葬的检查器；
  T.49：`std::function` 的堆分配+间接调用+擦除后的错误延迟，与模板的"每型一份、编译期全知"相比
  各有明确账单。
- 承接：🔧 本章实测对照（concepts vs SFINAE 报错）；folly `FunctionRef`/abseil 同类设施细分场景成本。

### T.61/T.62: SCARY 与公共体下沉
- 理由：全依赖的类型参数组合=每种组合一份代码（膨胀）；非依赖成员放非模板基，
  一份基类体服务所有实例化。
- 承接：`extern template`（显式实例化声明）+链接器；20 章的膨胀/性能账在 09 章 Per 组互证。

### T.80–T.84: 层次与模板的结合禁区
- 理由：模板数组化多态对象（切片+尺寸错配）、成员函数模板虚化（语言禁止）、
  模板化层次（ABI 脆断）——三大"能想到就能写错"的组合技。
- 承接：`static_assert(sizeof/alignof)` 守卫；C.152（T.81 的同题镜像）；
  CRTP 作为合法替身的纪律见 `bugprone-crtp-constructor-accessibility`（已核对官方表）。

### T.100/T.103: 变参模板的适用与误用
- 理由：异构可变参数（打印/元组转发）正当；同构列表（`f(1,2,3)`）该用 initializer_list/span——
  类型同质却用变参=放弃了长度与元素类型检查。
- 承接：折叠表达式（C++17）与 `std::apply` 处理包；🔧 04 章实测 va_arg→format 同题（F.55）。

### T.120/T.123/T.125: TMP 门槛与 constexpr 取代
- 理由："真需要才 TMP"；类型计算用别名模板、值计算用 constexpr 函数、
  别手搓 MPL 轮子（用标准 traits）。
- 承接：`<type_traits>` 全家；C++20 `requires` 吃掉一半传统 TMP 用例；
  13 章旧技术考古可跳读 [../C++模板元编程.md](../C++模板元编程.md)。

## 🔧 实测：T.10 约束的报错落点——concepts vs 无约束（已实测 g++ 15.2）

```cpp
#include <concepts>
template <std::integral T>
T gcd(T a, T b) { while (b) { T t = a % b; a = b; b = t; } return a; }
int main() { return gcd(2.5, 3.5); }   // 违反 std::integral
```

`-std=gnu++20 -Wall -Wextra -c` 真实报错（节选骨架）：

```text
error: no matching function for call to 'gcd(double, double)'
note: candidate: 'template<class T>  requires  integral<T> T gcd(T, T)'
note: constraints not satisfied
note: the expression 'is_integral_v<_Tp> [with _Tp = double]' evaluated to 'false'
```

对照无约束版本（GCC 会实例化后进 `%` 运算才报 `invalid operands of types 'double' to binary '%'`，
把病灶埋在模板体内几十行栈里）：**concepts 的收益不是报错短，而是判决发生在调用点、
理由直接印在案发现场**（与 [../C++编程惯用法/00-总览与阅读地图.md](../C++编程惯用法/00-总览与阅读地图.md) 实测结论同文互证）。

## 权衡与边界

- **约束过紧 vs 过松**：T.41"只要求本质属性"——`std::random_shuffle` 教训：约束越多库越长寿，
  但泛用性越差；判据是"算法真正依赖什么"。
- **编译期/运行期多态三角**（T.5）：模板（每型特化）、虚函数（运行期分派）、类型擦除（包装器）
  三选一没有全赢解；指南建议组合（外模板内虚函数/外擦体内特化）。
- **错误信息预算**：缩写 `auto` 参数语法省了签名噪声，也弱化了约束可见度——工业团队倾向显式 requires。

## 最新演进与工业实践

- C++20/23 兑现：`<=>` 概念系（`std::strong_ordering`）、`std::invocable`/`std::predicate` 精化、
  Deducing this（C++23，⚠️ 提案号未实测不引）削弱 CRTP 的"静态多态必须手架"地位。
- C++26 方向：reflection 路线与契约提案（P2900R14，实测 302）可能改写 T.22 公理条款的可检查性
  （⚠️ 反射相关提案号未经 wg21 实测，故不引编号）。
- 工业界：abseil 大量 `EnableIf`/`disjunction` 旧式约束正迁移到 `std::enable_if_t` 保留层（C++17/20 兼容线）；
  Google 风格长期限制"模板的可见使用面"（仅容器/工具层）——T 组在工业的采用是"分层放闸"样本；
  fmt/ranges-v3 是 concepts 工程学的最佳开源教材。
