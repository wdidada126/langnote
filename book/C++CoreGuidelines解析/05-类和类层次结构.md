## 核心概念速览（中英对照）

- **不变式** — class invariant (C.2/C.40)：class 与 struct 的分界：成员间存在需要维护的逻辑关系才用 class
- **具体类型优先** — prefer concrete types (C.10)：无层次需求就别引多态，值语义类型可测可移可缓存
- **正则类型** — regular type (C.11)：== 有意义、可拷贝可交换，像 int 一样行为良好的类型
- **零之法则** — Rule of Zero (C.20)：最好的默认操作声明是一个都不写（资源交给成员管理）
- **五之法则** — Rule of Five (C.21)：一旦手写析构/拷贝/移动之一，就显式处理全套
- **完整初始化** — fully initialized (C.41)：构造结束时对象必须满足不变式，禁止两阶段初始化
- **explicit 默认** — C.46：单参构造默认 `explicit`，堵住隐式转换侧门
- **拷贝要真拷贝** — a copy operation should copy (C.61)：拷贝构造/赋值语义不得"顺手"共享资源
- **自赋值安全** — self-assignment safe (C.62/C.65)：`x = x` 不得毁掉 x
- **移动不抛** — move noexcept (C.66)：容器扩容策略依赖它（🔧 见 04 章实测）
- **多态类抑制拷贝** — suppress public copy/move (C.67)：经基类操作的对象不该被值语义切片
- **clone 深拷贝** — virtual clone (C.130)：多态对象深拷贝的唯一正解
- **实现/接口继承之辨** — implementation vs interface inheritance (C.129/C.135–C.137)
- **dynamic_cast 定位** — C.146–C.148：层次导航不可避免时的受控下转，失败语义决定指针/引用版本
- **裸 union 禁** — avoid naked unions (C.181)：用 `std::variant` 或带 tag 的 union
- **切片** — slicing (ES.63/C.67)：派生对象塞进基类值，多性静默蒸发

## 动机：类章在体系中的双重身份

一是**资源章的前置**：C.30–C.33（有资源必有析构）把"类=RAII 载体"的因果链接通第 7 章；
二是**OOP 的判决书**：C.10/C.120 明确"类层次只在概念本身有层次时才配存在"，

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### C.2: class 若有不变式；struct 若成员可独立变化
- 理由：关键字即设计声明。`struct Point` 不该偷偷加"x>y"约束；`class Date` 就该在构造点把关。
- 承接：clang-tidy 无直接检查（语义判断），但 `cppcoreguidelines-pro-type-member-init`（成员默认初始化族）
  与 `-Weffc++` 风格提示部分覆盖；真正的承接是不变量测试框架+契约（P2900，实测 302）。

### C.10/C.11: 具体类型优先；把具体类型做成正则类型
- 理由：值语义对象无别名、可并发拷贝、可进容器、可测试断言（== 齐全）；多态只在"运行期换实现"确实需要时买单。
- 承接：C++20 defaulted `operator==`、`std::hash` 特化模板化；
  概念侧 `std::regular`（`<concepts>`，C++20）把 C.11 直接变成可编译查询的约束。

### C.20/C.21: Rule of Zero 与 Rule of Five
- 理由：手写析构=宣告"我要亲自管资源"，编译器随即禁用拷贝/移动的安全默认；
  不写=让成员（unique_ptr/vector）自己记账。写了其一就要写全五，防止部分默认+部分手写的语义裂缝。
- 承接：clang-tidy `cppcoreguidelines-special-member-functions`（已核对官方表）；
  `=delete`（C++11）作显式禁止声明（C.81）。

### C.35/C.127–C.128: 基类析构要么 public+virtual 要么 protected+非虚；virtual/override/final 三选一
- 理由：经 `Base*` delete 而基类析构非虚=派生部分永不析构（未定义行为）；
  三个标记词混写（如重写处再写 virtual）掩盖意图。
- 承接：🔧 本章实测 GCC 警告直接点名；clang-tidy `cppcoreguidelines-virtual-class-destructor`（已核对官方表）、
  `modernize-use-override`（已核对官方表）。

### C.41/C.42: 构造必须造出完整合法对象；造不出来就抛
- 理由：两阶段初始化让"半构造对象"游离在不变式之外（NR.5 专列为伪规则）；
  构造失败的正确出口是异常，不是错误码+垃圾对象。
- 承接：NSDMI（C++11）+ 委托构造（C.51）；`std::expected`（C++23，🔧 11 章实测）为
  "不抛环境的工厂函数"提供现代替身；`-Wuninitialized` 家族。

### C.60–C.67: 拷贝移动的全家桶纪律
- 理由：赋值返回 `T&`、按 `const&` 收参数、移动标 `noexcept`、自赋值/自移动安全——
  每一条都是容器行为与异常安全的地基。
- 承接：🔧 04 章 noexcept 实测即 C.66 取证；clang-tidy `performance-noexcept-move-constructor`、
  `cppcoreguidelines-c-copy-assignment-signature`、`misc-non-copyable-objects`（名称均已核对官方表）。

### C.120/C.121: 类层次只表达天然层次；当接口用时要纯抽象
- 理由：为"复用几行代码"而继承=脆弱基类+切片+销毁语义纠缠；纯抽象基类（无数据、全虚析构受保护）
  才是安全合成块（I.25 呼应）。
- 承接：concepts/泛型在"单方法复用"场景替代 interface 类（13 章）；
  C++20 `override` 语言化（C.128）让层次错误编译期出局。

### C.137/C.152: virtual 基类慎用；派生数组基指针永不允许
- 理由：vbase 的共享子对象由"最派生类"构造，布局与构造协议双重复杂；
  `Base* p = new Derived[n]` 让指针算术错位（元素尺寸不同），是切片数组版的静默灾难。
- 承接：布局税实测账本在 [../深度探索C++对象模型/05-构造析构拷贝语意学.md](../深度探索C++对象模型/05-构造析构拷贝语意学.md)（16/32/40/48 字节表）；
  ES.63 `-Wc++-compat`? 编译器普遍无切片警告——静态分析 `cppcoreguidelines-slicing`（已核对官方表）补位。

### C.146–C.148: dynamic_cast 的受控使用
- 理由：下转本身不是罪，罪在无验证的 static_cast 下转与"到处下转"的层次设计失败；
  引用版（失败即异常）与指针版（失败即空）按业务语义二选一。
- 承接：`-Wdelete-non-virtual-dtor` 邻族警告 + RTTI 开销账（vtable+type_info，见对象模型笔记）；
  clang-tidy `cppcoreguidelines-pro-type-static-cast-downcast`（已核对官方表，点名"该用 dynamic_cast 处用了 static_cast"）。

### C.181/C.183: 裸 union 与 type punning
- 理由：union 不记 tag、活跃成员切换是 UB 温床；type punning 交给 `std::bit_cast`（C++20）这个合法出口。
- 承接：`std::variant`（C++17）自带类型安全 tag 与访问器；`std::bit_cast`（C++20）替代 memcpy 强转。

## 🔧 实测：C.35 非虚基类析构被 GCC 当场点名（已实测 g++ 15.2）

```cpp
struct Base { virtual void f() {} ~Base() {} };   // C.35/C.127 违规：有虚函数却非虚析构
struct Derived : Base { int payload[8]; };
int main() { Base* p = new Derived; delete p; }
```

`-std=gnu++17 -Wall -Wextra` 真实警告：

```text
warning: deleting object of polymorphic class type 'Base' which has non-virtual destructor
might cause undefined behavior [-Wdelete-non-virtual-dtor]
```

注意 `Derived` 含 32 字节 payload 却不会有任何运行期报错——**警告是这条 UB 唯一的现场目击者**；
clang-tidy `cppcoreguidelines-virtual-class-destructor` 在同一位置给出规则级诊断。

## 权衡与边界

- **C.67 抑制拷贝的代价**：多态类不可拷贝后，调用方被迫显式 clone 或智能指针——设计摩擦正是提醒功能。
- **CRTP 双刃**：C.129 家族推荐静态接口（CRTP）避开虚调用，但错误信息（13 章）与实例化膨胀反弹回来。
- **运算符重载克制**（C.160–C.167）：指南允许"模仿常规用法"，反对一切"聪明"重载（`operator,`、`operator&&`）。
