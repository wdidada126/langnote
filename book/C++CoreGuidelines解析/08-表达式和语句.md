# 第8章 表达式和语句 — ES: Expressions and statements（ES.1–ES.107）

> 本章目录版：[← 00-总览与阅读地图](00-总览与阅读地图.md) ｜ 单文件笔记：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md) ｜ 系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)

**本章对象**：current master 实测 ES 组 **64 条**——仅次于 C 组的第二大户，也是"编译器/静态分析
能替你查到什么"最密集的一章。分组：ES.dcl（声明与初始化）、ES.expr（表达式与转换）、
ES.stmt（语句选择）、Arithmetic（算术与符号）。⚠️ 旧版"Types and variables (T)"的部分变量规则
（ES.20 系）历史上曾挂 G 组编号（G.es.*），引用旧评论需换算。

## 核心概念速览（中英对照）

- **作用域最小化** — keep scopes small (ES.5)：变量可见面越窄，可推理面越大
- **总是初始化** — always initialize (ES.20)：未初始化读=UB 直通车
- **大括号初始化** — `{}`-initializer (ES.23)：防窄化、防 vexing parse、统一形式
- **窄化转换之禁** — avoid lossy/narrowing conversions (ES.46)：`int i{d}` 编译期出局
- **魔法常数之禁** — avoid magic constants (ES.45)：裸数字换 `constexpr` 具名常量
- **nullptr** — ES.47：`0`/`NULL` 的身份危机终结者
- **具名转换** — named casts (ES.49)：禁 C 风格强转，四种各表意图
- **不丢 const** — don't cast away const (ES.50)：除非接口边界，const_cast 即设计招供书
- **求值顺序陷阱** — undefined order of evaluation (ES.43/ES.44)：同一表达式多次副作用/参数求值序未定
- **不切片** — don't slice (ES.63)：把派生对象拷进基类对象=多态信息蒸发
- **std::move 的克制** — ES.56：只在"确实要移交出当前作用域"处写 move
- **range-for 优先** — ES.71：无索引需求就不裸写循环
- **switch 落空之禁** — no implicit fallthrough (ES.78)：`[[fallthrough]]`（C++17）显式化
- **符号数纪律** — signed/unsigned (ES.100–ES.107)：算术不混符号、位操作用无符号、下标用 `gsl::index`
- **溢出即错误** — don't overflow (ES.103/ES.104)：有符号回绕/无符号环绕都不是"小事"

## 动机：本章是"写出来的代码"与"编译器看得懂的代码"之间的翻译层

I/F/C 章管设计形状，ES 章管每一行的**表达卫生**：初始化、转换、运算符、语句选择、符号数。
格林的解析风格在此章最"逐行化"——每条规则给一段"能编译但不能跑"的反例与一段
"编译期/静态分析双绿"的正例。ES.46 的窄化与 ES.100 的符号混用是新手与老手共同的事故田。

## 机制：四大 subgroup 的判据

```text
ES.dcl   何时、何地、以什么形式引入名字（scope/init/命名长度/宏退场）
ES.expr  表达式不依赖未定义行为（求值序/cast/移动/切片/解引用合法性）
ES.stmt  语句形态服从意图（for/while/switch/goto/break 的选择梯）
Arithmetic 符号类型按用途选（算术 signed、位图 unsigned、下标 index）
```

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### ES.20: Always initialize an object
- 理由：读未初始化内存是 UB；"稍后赋值"在每条路径都被执行前，对象处于法律真空。
- 承接：NSDMI + `std::numeric_limits`；clang-tidy `cppcoreguidelines-init-variables`（已核对官方表）、
  `-Wmaybe-uninitialized`、`-Wuninitialized`。

### ES.23/ES.46: `{}` 初始化 & 拒绝有损窄化
- 理由：`int i(d)` 静默截断，`int i{d}` 编译期判决——把"我以为你会小心"改成"你敢就不过编译"。
- 承接：🔧 本章实测；clang-tidy `cppcoreguidelines-narrowing-conversions`、`bugprone-narrowing-conversions`
  （均已核对官方表）。

### ES.43/ES.44: 求值顺序
- 理由：C++17 前 `f(g(), h())` 顺序未定、`v[i++] = v[i]` 直接 UB；指南要求表达式一次只干一件有副作用的事。
- 承接：C++17 部分钉死（赋值右先于左、函数参数仍未定但 postfix 表达式分组）；
  `-Wsequence-point`；ES.43 的"逗号滥用"另有 `readability-*` 兜底。

### ES.48/ES.49: 少 cast，必须 cast 用具名
- 理由：C 风格 cast 是四合一万能钥匙（const 去除/下转/reinterpret/静态），意图不可查、风险不可分。
- 承接：clang-tidy `cppcoreguidelines-pro-type-cstyle-cast`、`cppcoreguidelines-pro-type-reinterpret-cast`、
  `cppcoreguidelines-pro-type-static-cast-downcast`（均已核对官方表）；`-Wold-style-cast`（GCC/Clang 均有）。

### ES.50: Don't cast away const
- 理由：对真 const 对象的写=UB；对非 const 对象绕道写=欺骗设计。两者都值得一次 code review 争论。
- 承接：clang-tidy `cppcoreguidelines-pro-type-const-cast`（已核对官方表）；
  接口层解法回到 Con 章（const 正确性从源头消灭需求）。

### ES.56/ES.63/F.48 族: move 的纪律与切片的沉默
- 理由：不必要的 `std::move` 阻断优化（04 章已实测 NRVO 侧）；切片是"拷贝构造基类部分"的正常语义
  遇上"我想要多态"的错误期望——编译器无权知道你后悔。
- 承接：clang-tidy `performance-no-automatic-move`、`cppcoreguidelines-slicing`（已核对官方表）。

### ES.65: Don't dereference an invalid pointer
- 理由：`nullptr` 解引用、越界解引用、悬垂解引用三兄弟占运行期崩溃事故榜前列（P.7 的现场版）。
- 承接：`not_null`（构造点断言）、ASan 家族、P2573R2 生命周期静态分析（实测 302）。

### ES.70/ES.71/ES.75/ES.76: 语句选择梯
- 理由：`switch` 表达多路等值分派优于 if 链（编译器跳转表+枚举穷尽检查）；range-for 消灭索引；
  `do-while` 的"至少跑一次"常常是 off-by-one 的温床；`goto` 唯一残存正当用途是出口清理——RAII 已接管。
- 承接：`-Wswitch`/`-Wswitch-default`（GCC）+ `cppcoreguidelines-avoid-goto`、
  `cppcoreguidelines-avoid-do-while`（均已核对官方表）、`[[fallthrough]]`（C++17）。

### ES.100–ES.107: 符号数的完整判据链
- 理由：混符号比较在 `int`/`size_t` 间静默把 -1 变成天文数字；无符号不是"非负保证"而是"模运算语义"；
  下标用 `gsl::index`（有符号且与 size 同宽）折中。
- 承接：🔧 本章实测；`-Wsign-compare`（-Wextra 内）、`-Wsign-conversion`；clang-tidy
  `bugprone-narrowing-conversions`；下标比较一律转 `std::make_signed_t<size_t>` 族思路（gsl::index 即其具名化）。

## 🔧 实测一：ES.46 窄化——警告即判决（已实测 g++ 15.2）

```cpp
int main() { double d = 3.5; int i{d}; return i; }   // 大括号初始化拦截有损转换
```

`-std=gnu++17 -Wall -Wextra -c` 真实输出：

```text
warning: narrowing conversion of 'd' from 'double' to 'int' [-Wnarrowing]
```

（GCC 对该 perm-error 默认以警告呈现；Clang 直接 error。同一行改 `int i = d;` 则完全无声——
ES.23 的价值就在这声与不声之间。）

## 🔧 实测二：ES.100 符号混比（已实测 g++ 15.2）

```cpp
#include <vector>
int main() { std::vector<int> v(3); int i = -1; return v.size() == i; }
```

`-std=gnu++17 -Wall -Wextra -c` 真实输出：

```text
warning: comparison of integer expressions of different signedness:
'std::vector<int>::size_type' {aka 'long long unsigned int'} and 'int' [-Wsign-compare]
```

`v.size() == -1` 的真实语义是 `18446744073709551615 == 0x…ffff` 比较——无符号回绕把逻辑错误
变成永久假。ES.107 的 `gsl::index`/C++20 `std::type_identity_t` 类缓解均不如一条警告常驻。

## 权衡与边界

- **`auto` 双面（ES.11）**：指南支持用 `auto` 消重复、反对用它藏类型——
  判据是"读者能不能从上下文唯一推断类型语义"。
- **ALL_CAPS 与宏的余权**：ES.30–ES.33 不消灭宏，只限其权（include 守卫、条件编译、日志开关）——
  对预处理器现实的政治妥协。
- **`gsl::index` 的尴尬**：依赖 GSL 且与标准容器 API 的 `size_type` 存在摩擦，工业界采用率一般（20 章）。

## 最新演进与工业实践

- C++20/23：范围 for 初始化语句（C++20 `for (init; cond; : range)`）、`[[likely]]/[[unlikely]]`
  分支提示（承接 ES.stmt 的"性能直觉归位"）、`std::bit_cast`（ES.49 家族的安全 reinterpret 替身）；
  P1023R0（指针比较合法化，实测 302）修正 ES.62 周边规则。
- C++26 方向：P2674R1（实测 302）继续压缩"出参式语句"的生存空间；生命周期 profile 静态化（P2573R2，实测 302）。
- 工业界：LLVM/Chromium 将 `-Werror=sign-compare,narrowing` 类警告纳入 CI 门禁——
  ES 组约七成条目已进入"编译器默认+项目加严"的两级承接，剩余依赖 clang-tidy。
