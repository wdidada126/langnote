# 第18章 伪规则和误解 — NR: Non-Rules and myths（NR.1–NR.7）

> 本章目录版：[← 00-总览与阅读地图](00-总览与阅读地图.md) ｜ 单文件笔记：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md) ｜ 系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)

**本章对象**：current master 实测 NR 节 7 条（grep `^### .*NR\.` 计数=7），编号连续无缺。
NR = Non-Rules and myths："在某处流行、但我们**刻意不推荐**的规则"。这是指南唯一以
**否定式**成文的章节——它反对的不是坏代码，而是**被奉为圭臬的旧纪律**（结构化编程时代的
遗产与过时的"常识"）。节首免责声明值得全文背诵：某些"不适用场景"确实存在（如硬实时下
慎用异常），但"不要天真地相信'常识'"——那些"效率"论断可能来自几十年前或别的语言。
⚠️ 本书第 18 章的展开论述（如把 NR 与常见面试误区对照）系格林增益，非指南原文。

## 核心概念速览（中英对照）

- **伪规则** — non-rule：被广泛执行但指南明确反对的"纪律"
- **神话** — myth：以效率/安全为名、未经测量检验的口头禅
- **声明置顶律之废** — NR.1：老式 C 遗产；距离越短，未初始化窗口越小（接 ES.20/ES.21）
- **单出口律之废** — NR.2：单一 return 强迫引入中间状态变量，反而更长更慢更难读
- **异常回避律之废** — NR.3：无证据不禁用异常（接 E 章；证据要求见 Per.11）
- **一类一文件律之废** — NR.4：源文件按逻辑单元组织，不按类计数（接 SF 章）
- **两阶段初始化** — two-phase initialization (NR.5)：构造不做完、Init() 补课的病态模式
- **半成品对象窗口** — not-ready-to-use object：`Picture(100,0)` 在 Init 失败后仍是活对象——事故源
- **goto exit 清场律之废** — NR.6：pre-exception 时代的 RAII 替身，手工维护清理清单必漏
- **protected 数据** — NR.7：类层次里的全局变量（继承面对实现细节开门）

## 动机：为什么规则书需要一章"反规则"

448 条正面规则会给人错觉：合规=好代码。NR 章戳破另一半真相：**错误的规则也是规则**，
而且往往比没规则更糟——它让违反者在审计表上打勾。团队 code review 里最常见的五种"依据"
（声明置顶、单 return、禁异常、一类一文件、init 函数模式）恰好对应 NR.1/NR.2/NR.3/NR.4/
NR.5：这一章是把"上一代编码规范"送进博物馆的死亡证明。格林把它放大成"误解"章，⚠️ 具体
病例清单为本书增益。

## 机制：每条伪规则都替代了某种语言机制

伪规则的共同结构：**在 C++ 提供机制之前，用纪律模拟机制**。

| 伪规则 | 它在模拟 | 机制上位替代 |
|---|---|---|
| NR.1 声明置顶 | 早期语言的声明/语句分离 | 就近初始化（ES.20/ES.21，C++11 统一初始化） |
| NR.2 单 return | 结构化编程的"一个出口"教条 | RAII + 异常让任意点返回自动完成清理 |
| NR.3 禁异常 | 错误码手工传播（无语言级栈展开） | 异常/`expected`（E 章、11 章实测） |
| NR.4 一类一文件 | 手工管理编译依赖的错觉 | include 守卫 + 命名空间组织（SF 章，15 章实测） |
| NR.5 两阶段初始化 | 没有初始化列表语义的时代 | 成员初始化列表 + `Expects`（C.41/C.42） |
| NR.6 goto exit | 没有析构函数的清理 | RAII / `gsl::finally`（7 章、11 章） |
| NR.7 protected 数据 | 无友元/访问控制粒度的取巧 | private + 受控接口（C.9/C.12） |

纪律模拟机制的代价：纪律靠人守，机制靠编译器守——**NR 章的全部论证可以压缩成这一句**。

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### NR.1 别把声明都堆函数头 → 理由：拉长"未初始化→使用"距离即放大 bug 概率 → 承接：`cppcoreguidelines-init-variables` + `-Wmaybe-uninitialized`

- 原文反例 `int i; char c; double d;` 三变量声明后隔了"some stuff"才被分支使用——
  指南自己标注"编译器能抓很多 use-before-set，但抓不完，而且真实 bug 没这么小"。
- 工具承接（均已核对官方检查列表）：`cppcoreguidelines-init-variables` 反向执法——
  不允许"先声明后初始化"的裸变量存在；GCC `-Wmaybe-uninitialized`（-O 下）是编译期搭档。

### NR.2 别坚持单 return → 理由：单出口催生状态变量与深嵌套，"越长越慢" → 承接：`readability-function-size` 看门

- 指南的 `sign(T)` 例子对比清晰：卫语句三连返回 vs 引入 `string res` 中转——后者
  "both longer and likely to be less efficient"，且函数越大妥协越痛。
- 单 return 教条的真实动机是可追踪性（cleanup 集中），但 C++ 已用析构函数把"集中清理"
  做成了语言保证——**NR.2 是 NR.6 的同一场战役**（都反对手工汇聚出口）。
- 工具层无"必须多 return"检查（合理），但 `readability-function-size`/圈复杂度类检查
  客观上奖励早退式写法。

### NR.3 别 avoiding exceptions → 理由："没有证据的禁用是神话" → 承接：`misc-throw-by-value-catch-by-reference` 治理用法而非存废

- 节首硬实时免责条款 + E 章 E.4（"不要无证据禁用异常"）+ Per.11（性能声明必须带测量）
  构成指南的**实证主义三角**：禁异常要交数据，交不出就用。
- 11 章 🔧 实测的拷贝/移动计数（noexcept 前后 copies=3/moves=4 vs copies=0/moves=7）
  演示的正是"有证据的异常相关优化"，而非立场之争。
- 工具承接：clang-tidy `misc-throw-by-value-catch-by-reference`（官方列表实测存在）默认
  即假定异常是合法设施，只规范其用法；`bugprone-exception-escape` 检查异常逃逸路径。

### NR.5 别做两阶段初始化 → 理由：构造函数要么给出可用对象，要么不给对象 → 承接：C.41 + 编译器直接执法 🔧

- 原文反例 `Picture` 的罪案清单密集得罕见：构造体内赋值（违 C.42）、裸 `malloc` 拥有指针
  （违 R.3/R.11）、`Init()` 返回 bool（违 E 章）、`Cleanup()` 公开可调（RAII 缺席）——
  NR.5 把**一整条旧 Windows 风格 API**（`Create`/`Init`/`Cleanup` 三件套）打包送葬。
- 正解的核心是"单点验证"技巧：静态 `check_size` 放进制表符初始化列表，让
  `Expects(size > 0)` 在成员初始化**之前**执行——构造失败=对象不存在，半成品窗口归零。
- 🔧 **实测**（已实测 g++ 15.2）：把"半成品"写进类型系统（`const` 成员想留给二阶段）时，
  编译器直接拒绝：

  ```cpp
  struct Config {
      const int id;
      Config() {}             // C.41/NR.5: wants to leave init to a later "phase"
      void second_phase(int i);
  };
  int main() { Config c; }
  ```

  `g++ -std=gnu++17 -Wall -Wextra` 真实输出：

  ```text
  t18_twophase.cpp: In constructor 'Config::Config()':
  t18_twophase.cpp:3:5: error: uninitialized const member in 'const int' [-fpermissive]
      3 |     Config() {}             // C.41/NR.5: wants to leave init to a later "phase"
        |     ^~~~~~
  t18_twophase.cpp:2:15: note: 'const int Config::id' should be initialized
      2 |     const int id;
        |               ^~
  ```

  一条 `-fpermissive` 级错误坐实：**语言本身不给两阶段初始化留位置**（对 const 成员而言），
  NR.5 不是偏好是物理。
- 工具承接：`cppcoreguidelines-pro-type-member-init`（19 章 profile 清单 Type.6 的执法者）
  把"别忘了初始化"从纪律降格为兜底，正解仍是 C.41/C.42 的构造即完整。

### NR.6 别 `goto exit` 清场 → 理由：这是异常出现前的手工 RAII → 承接：`cppcoreguidelines-avoid-goto`（已核对官方列表）

- 原文"and spot the bug"式反例：`int* p = malloc` 在第一个 `goto exit` **之后**才声明，
  而 exit 标签处 `free(p)`——直接编译错误级的悬空清理。指南故意留白让读者找 bug：
  把 4 个 early return 改成 4 个 goto 后，清理清单和分配清单**双账本对不上**是必然，
  加一行分配就要改一处 exit 区——这就是"纪律模拟机制"的维护税。
- 19 章 profile 视角：`cppcoreguidelines-avoid-goto` 是少数"检查名即规则原文"的对应物；
  配套 `bugprone-branch-clone` 常在同一具尸体上报警。
- 正向替代见 E 章 re-finally：`gsl::finally`（20 章）给不能抛异常的场合留了逃生门——
  NR 章反对的是**神话驱动**的写法，不是约束驱动的特例。

### NR.7 别把数据成员设为 protected → 理由：protected 数据=类层次版全局变量 → 承接：无直接 check，靠 C.8/C.9 派生审查

- 攻击面论证值得记：任何未来派生类（不可枚举的代码量）都能改写基类不变量——
  封装的"有界豁免"（friend 是作者显式点名的）与"无界豁免"（protected 是对未知的承诺）
  之差。
- 工具现状：clang-tidy 无"protected data"专用检查（实测其 cppcoreguidelines-* 全表无此项），
  这是"语义规则难执法"的样本（呼应 P.3）；可行近似是 `readability-isolate-declaration`
  之类风格约束配合评审清单。
- 替代表达：protected **函数**（受控构造辅助）仍合法；要共享表示就用 private 成员 +
  受保护访问器，或直接按 C.112 管理好层次。

### 配套深读：NR.4 一类一文件 → 承接：SF.12/SF.23 组织判据是"概念"不是"实体计数"

- 15 章实测过的重定义/多重定义双错误恰好证明：**文件的职责是 ODR 边界管理**，
  一个概念簇（互操作的小类型组）共文件反而降低查找成本。NR.4 反对的是把文件系统当
  UML 类图存档。

## 权衡与边界

- **NR 不是"这些做法永远错"**：节首白纸黑字承认"时与地"——硬实时禁异常、certified
  代码走单出口以过工具链（MISRA 就要求单 return/单退出点）。NR 反对的是**无证据的教条**，
  MISRA 有证据（可追溯的约束），口头禅没有。
- **NR 与正面规则互为影子**：NR.1↔ES.21、NR.3↔E.4、NR.5↔C.41、NR.6↔ES.76（避免 goto）、
  NR.7↔C.9——复习时把 7 条伪规则当 7 组正面规则的**负片**看，一份记忆存两幅图像。
- **本章的元教训**：任何编码规范的每条规则都该能回答"你在模拟哪个尚不存在的机制，
  或你在防哪个仍在发生的事故"——两者都答不出来的，就是下一条待埋葬的 NR。

## 相邻概念对比

- **NR 章 vs A 章（17 章）**：两章都是指南的"非执法区"，方向相反——A 是**没写够**的草稿
  （??? 占位实测），NR 是**刻意反对**的完成品。
- **NR.2/NR.6 vs 整洁之道**：[../C++代码整洁之道.md](../C++代码整洁之道.md) 一脉的"函数单一
  出口/早失败"讨论在 C++ 语境下必须叠加析构语义这层才能下结论——这正是 NR 章留白、
  本书补讲的部分，⚠️ 对比论断为笔记立场。
- **NR.3 vs Effective Modern C++**：[../Effective_Modern_C++.md](../Effective_Modern_C++.md)
  item 8（不可移动类型退化传引用）默认异常可达的生态位；两书合读=立场+技法。
- **两阶段初始化 vs 建造器模式**：合法的 builder（[../C++20设计模式/](../C++20设计模式/00-总览与阅读地图.md)）
  把半成品限制在**不可外泄的独立对象**里，终产物仍一次构造完成——与 NR.5 打击的
  "this 上的半成品"有本质区别，面试高频混淆点。

## 最新演进与工业实践

- C++20 `constinit`/立即函数使"构造即完整"更容易零成本执行；C.41+`Expects` 的指南正解
  在合约落地后将获得语言级语法（21 章，P2900R14/P2388R4 均已 302 验证）。
- abseil/TensorFlow 时代"禁异常"路线（Status 返回）与 NR.3 的张力是活案例：abseil 用
  `absl::Status` 的实质理由是可传播+可测试，**有证据**，故不构成 NR.3 打击对象——
  判据在论证质量不在结论方向。
- Chromium 风格指南对 goto/单出口的处理可作为 NR.2/NR.6 的工业对照：它以 Cleanup 钩子
  （scope::Cleanup，`gsl::finally` 同物）替代 goto exit，方向与指南完全一致。
- clang-tidy 对 NR 各条的承接呈不均匀分布（goto/init 有、单 return 无、protected 数据无），
  这个"执法空洞图"本身就是 19 章 profile 思想的注脚：工具追规则，永远慢半拍。
