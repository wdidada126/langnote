# 第4章 函数 — F: Functions（F.1–F.56）

> 本章目录版：[← 00-总览与阅读地图](00-总览与阅读地图.md) ｜ 单文件笔记：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md) ｜ 系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)

**本章对象**：全书规则密度最高的一组（current master 实测 38 条带编号规则标题，
F.def 组织、F.call 传参、返回值语义 F.42–F.49、lambda F.50–F.56）。⚠️ 2019 年前后原版的
D（Function design）组（D.1–D.43）在重构中并入 F/ES，本书中文章节按新版 F 组讲解；
凡引用旧 D 编号处均已换为新编号并标注。格林的轴心问题：**函数边界上每个方向语义（in/in-out/out/move/forward）
该怎么写、编译器与工具各能替你查到哪一步**。

## 核心概念速览（中英对照）

- **单一逻辑操作** — single logical operation (F.2)：函数粒度判据不是行数而是"一件事"
- **参数方向语义** — parameter direction (F.15–F.19)：in 值/const&、in-out 引用、will-move-from `X&&`、forward `TP&&`
- **廉价可拷贝类型** — cheaply-copied types (F.16)：小整型/指针类按值传，其余按 `const&`
- **输出用返回值** — prefer return values (F.20)：出参是"绕过返回值语法"的历史包袱
- **返回 struct 聚合多值** — return a struct (F.21)：多 out 值时给结果命名而非元组黑洞
- **noexcept 承诺** — noexcept (F.6)：不可抛的接口要写进类型，参与容器/算法策略选择
- **悬垂返回** — dangling return (F.43)：返回局部对象的指针/引用=生命周期倒置
- **T&& 不返回** — don't return `T&&` (F.45)：右值引用返回几乎总是悬垂或过度承诺
- **勿对局部量 return std::move** — F.48：扼杀 NRVO/隐式移动的古早习惯
- **智能指针只表所有权语义** — F.7/R.30：非拥有场景传 `T*`/`T&`，别传 `shared_ptr` 参数
- **va_arg 禁区** — don't use `va_arg` (F.55)：变参绕过全部类型检查
- **lambda 捕获纪律** — capture discipline (F.52–F.54)：局部用引用捕获、跨线程/逃逸用值捕获、禁 `[=]` 默认捕 this

## 动机：函数是接口章的执行机构

I 章说"接口要显式、强类型"，F 章回答"怎么写函数签名才能兑现"。传参方向的每个选择
（值/`const&`/`&&`/`TP&&`）都是性能与语义的双向下注：F.16–F.19 一组实质上是
**用签名把移动语义的四百年旧账（拷贝浪费、悬垂引用、转发失配）逐类结清**。

## 机制：一张签名决策表

```text
数据流向          写法               理由条款        工具线索
in（廉价拷贝）    T                  F.16           performance-unnecessary-value-param
in（重对象）      const T&           F.16           clang-tidy 同上
in-out            T&                 F.17           —
will-move-from    T (by value)+move  F.18           performance-move-const-arg
forward           TP&&               F.19           —
out（首选）       返回值             F.20           bugprone-move-forwarding-reference
out（多选）       返回 struct        F.21           —
位置/可空         T*                 F.60/F.42      —
非空约束         not_null<T>        I.12/F.23      GSL
```

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### F.2/F.3: 一个函数=一个逻辑操作，短而简单
- 理由：可测试粒度、可命名粒度、审查粒度三者重合；>5 行的"顺手"复合函数是 bug 温床。
- 承接：clang-tidy `readability-function-size`、`-fno-inline` 调试对照见 `../C++代码调试的艺术/09-Release版调试.md`。

### F.4: If a function might have to be evaluated at compile time, declare it `constexpr`
- 理由：`constexpr` 不强制编译期求值（可运行期用），只**打开**编译期通道——零成本承诺。
- 承接：C++20 放宽（虚函数不能 constexpr 之外几乎全能）、C++23 `constexpr stdlib` 子集；P2546R5 Generators
  等提案继续扩大 constexpr 领地（实测 302）。

### F.6: If your function must not throw, declare it `noexcept`
- 理由：`noexcept` 是移动/交换/容器扩容策略的开关（🔧 本章下方实测），也是优化器敢重排的前提。
- 承接：clang-tidy `performance-noexcept-move-constructor`、`cppcoreguidelines-noexcept-move-operations`、
  `cppcoreguidelines-noexcept-swap`（名称均已核对官方检查表）。

### F.7 / R.30: Take `T*` or `T&` rather than smart pointers for general use
- 理由：函数若只"看"对象不"管"对象，把 `shared_ptr` 写进签名=白付引用计数税、误导所有权。
- 承接：本规则是"ownership 单则 unique_ptr"运动的签名侧（R.21 见 [07-资源管理](07-资源管理.md)）。

### F.16: For "in" parameters, pass cheaply-copied types by value and others by reference to const
- 理由：小类型过寄存器/栈拷贝比间接寻址快；`const&` 避免大对象构造，同时允许临时量绑定。
- 承接：clang-tidy `performance-unnecessary-value-param`（已核对官方表）。

### F.18/F.19: will-move-from 用 `X&&`+move；转发用 `TP&&`+只 forward
- 理由：`X&&` 参数若内部再 move 是"消费"，`TP&&` 转发保持值类别——两种写法不可互换。
- 承接：`std::forward`（C++11）；clang-tidy `bugprone-move-forwarding-reference`（已核对官方表）。

### F.20/F.21: 出参改返回值 / 多值返回 struct
- 理由：未初始化出参是 ES.20 重灾区；返回值可进 const 变量、可组合、强制初始化。
  struct 命名元素优于 `std::tuple` 的匿名索引。
- 承接：C++17 结构化绑定消费多值；P2674R1（实测 302）继续讨论高性能 out 参数设施。

### F.43/F.45: 不返回局部对象的指针/引用；不返回 `T&&`
- 理由：局部量在 return 后死亡，逃逸的 `T*`/`T&`/`T&&` 全部悬垂；`T&&` 还会让调用点误接 rvalue。
- 承接：编译器内建 `-Wreturn-local-addr`（GCC 默认开）；clang-tidy `bugprone-dangling-handle`、
  `bugprone-return-const-ref-from-parameter`（均已核对官方表）；静态生命周期分析提案 P2573R2（实测 302）。

### F.48: Don't `return std::move(local)`
- 理由：C++11 起返回局部对象本就触发 NRVO/隐式移动；显式 `std::move` 反而**阻断** NRVO 退化为真移动。
- 承接：clang-tidy `performance-no-automatic-move`（已核对官方表）；编译器优化报告 `-fdump-tree-*`。

### F.55: Don't use `va_arg` arguments
- 理由：`printf("%d", 3.5)` 编译运行都不拦——类型系统在 `...` 处裸奔（ES.34 同族）。
- 承接：clang-tidy `cppcoreguidelines-pro-type-vararg`（已核对官方表）+ `-Wformat`；
  C++20 `std::format`（P0645R10，实测 302）给出类型安全替身——🔧 下方实测。

### F.52/F.53: lambda 捕获方向纪律
- 理由：局部/算法用 `[&]` 缩短拷贝，逃逸 lambda（返回、入堆、跨线程）用值捕获，否则引用悬垂。
- 承接：`-Wdangling-reference`（GCC 13+ 启发式）；C++23 广义 `[this]` 捕获 P2096R2（实测 302）；
  clang-tidy `bugprone-dangling-handle` 家族。

## 🔧 实测一：F.55 违规 vs 合规（已实测 g++ 15.2）

```cpp
#include <cstdio>
#include <format>
#include <string>
int main() {
    std::printf("%d", 3.5);                       // F.55 违规样本：变参
    std::string s = std::format("{:.1f}", 3.5);   // C++20 合规替身
    std::printf("\n%s\n", s.c_str());
}
```

`-std=gnu++23 -O2 -Wall -Wextra` 真实输出（编译警告 + 运行结果）：

```text
warning: format '%d' expects argument of type 'int', but argument 2 has type 'double' [-Wformat=]
0
3.5
```

即：printf 路线靠 `-Wformat` 兜底且**照跑**（输出 `0`，实为 UB），format 路线编译期直接拒收错型
（fmt 风格格式串检查）——工具承接"运行期垃圾→编译期出局"的教科书对照。

## 🔧 实测二：F.6/noexcept 决定容器扩容用拷贝还是移动（已实测 g++ 15.2）

```cpp
#include <vector>
#include <cstdio>
int copies = 0, moves = 0;
struct NoMove  { NoMove(const NoMove&){++copies;} NoMove(NoMove&&){++moves;} };
struct GoodMove{ GoodMove(const GoodMove&){++copies;} GoodMove(GoodMove&&) noexcept {++moves;} };
// 各 push_back 4 个元素触发 vector 扩容搬家
```

`-std=gnu++23 -O2 -Wall -Wextra` 运行：

```text
no-noexcept move type: copies=3 moves=4
noexcept move type   : copies=0 moves=7
```

移动构造不标 `noexcept`，`vector` 为保证强异常安全只能用拷贝搬家（`copies=3` 即扩容复制），
F.6/C.66 的"承诺进类型系统"在此有可测量兑现（对照 [../Effective_Modern_C++/05-右值移动完美转发.md](../Effective_Modern_C++/05-右值移动完美转发.md) item 14）。

## 权衡与边界

- **F.16 的"廉价"阈值**：指南建议 ≤2 字走值、≥3 字走 `const&`，真实分界依赖 ABI 寄存器数——别背数字背原理。
- **返回值 vs 输出迭代器**：大容器"填充分"场景返回副本可能诱发意外拷贝，`in-out` 引用参数仍合法（F.17）。
- **constexpr 的编译期账单**：把热点函数 constexpr 化可能显著拉长编译时间（与 13 章 TMP 权衡共享）。

## 最新演进与工业实践

- C++20/23：`std::format` 全面承接 F.55；`[[nodiscard]]`（P0600R1，实测 302）把"返回值必须被消费"
  写进签名，与 F.20 形成闭环；lambda 模板形参（C++20）改写 F.11/F.50 的复用账。
- C++26 在途：contracts（P2900R14，实测 302）将把 F.6/前条件表达从"注释+GSL"升为语言子句；
  生命周期安全分析（P2573R2，实测 302）瞄准 F.43/悬垂返回的静态判定。
- 工业界：folly `fbthrift` 接口代码生成大量依赖"返回 struct"模式（F.21 实证）；abseil 用
  `ABSL_ATTRIBUTE_MUST_USE_RESULT`/Status 返回承接 F.20+nodiscard 组合。
