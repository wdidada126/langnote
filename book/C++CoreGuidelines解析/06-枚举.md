# 第6章 枚举 — Enum: Enumerations（Enum.1–Enum.8）

> 本章目录版：[← 00-总览与阅读地图](00-总览与阅读地图.md) ｜ 单文件笔记：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md) ｜ 系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)

**本章对象**：全书最短的"语言设施章"——current master 实测 8 条规则（Enum.1–Enum.8）。
枚举是 C++ 里"名义类型"最便宜的载体，也因此是历史包袱最重的一块（隐式转 int、ALL_CAPS 宏污染、
无长度位域）。格林把本章当作**类型安全（P.4）的最小实验场**：8 条规则全是在教
"怎样让一枚枚举值不再和一枚整数互相私通"。

## 核心概念速览（中英对照）

- **枚举类型** — enumeration type：一组具名整型常量的类型
- **类枚举/带作用域枚举** — class enum / scoped enum (Enum.3)：`enum class`——枚举项不泄漏到外围作用域、不隐式转整型
- **普通枚举** — plain/unscoped enum (Enum.3 反面)：`enum`——历史形态，双重泄漏
- **无名枚举之禁** — avoid unnamed enumerations (Enum.6)：`enum {a,b};` 连类型名都不留=最失控形态
- **底层类型** — underlying type (Enum.7)：`enum class E : uint8_t`——只在需要位域/接口布局时显式指定
- **枚举项赋值** — enumerator values (Enum.8)：只在协议/ABI 要求时写死数值
- **宏转枚举** — prefer enumerations over macros (Enum.1)：`#define RED 1` 们应退休为 `constexpr`/枚举
- **枚举集合** — sets of related named constants (Enum.2)：枚举是"相关常量的家族"，不是数字别名
- **枚举运算** — define operations on enumerations (Enum.4)：需要 `|`/`&` 时显式重载或用 flags 惯用法
- **ALL_CAPS 专属宏** — Enum.5/NL.9：全大写保留给宏，让"预处理器的东西"肉眼可辨

## 动机：为什么 8 条规则值得单独成章

枚举横跨多个主题章：宏替换（ES.30–ES.32）、类型安全（P.4）、位标志（ES.101）、协议编码（CPL 章）。
重构后的指南把这些散点收拢为独立 Enum 节，本书照单成章。实际事故密度最高的是两件事：
普通枚举的隐式转换（`if (color == 3)` 的魔法数陷阱，ES.45 联动）和位标志枚举的运算缺失
（默认没有 `|`，人人手搓一遍）。

## 机制：8 条规则的层次

1. **存在理由**（Enum.1/Enum.2）：具名、成组、进类型系统——对比宏的三缺陷（无作用域、无类型、调试不可见）；
2. **形态选择**（Enum.3/Enum.6）：`enum class` 默认，普通枚举仅限与 C/旧代码互操作，无名枚举全禁；
3. **数值治理**（Enum.7/Enum.8）：底层类型与显式值都归入"只有外部协议才配写"的白名单逻辑；
4. **使用面**（Enum.4/Enum.5）：运算要显式定义，命名向宏宣战结束（ALL_CAPS 归还宏）。

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### Enum.1: Prefer enumerations over macros
- 理由：`#define` 常量无类型、无视作用域、崩溃时调试器看不见；枚举/`constexpr` 全赢。
- 承接：clang-tidy `modernize-macro-to-enum`、`cppcoreguidelines-macro-to-enum`（均已核对官方表）。

### Enum.2: Use enumerations to represent sets of related named constants
- 理由：枚举的本职是"**一组**语义同源的名字"（状态机阶段、错误类别）；零散的单一常量应直接
  `constexpr`，把不相干数字包装进枚举只是给类型系统添丁而不买保险。
- 承接：无 lint 可判"这组常量是否同源"（语义判断，P.3 类）；评审判据：枚举成员间应能写出
  "同一量纲/同一生命周期"的一句话——写不出即拆回 `constexpr`。

### Enum.3: Prefer class enums over "plain" enums
- 理由：普通枚举把枚举项倒进外围作用域（两个枚举同名项即冲突）且自由出入 `int`——
  把"星期几"和"错误码"相加这类荒谬在类型层面畅通。`enum class` 两项都锁死。
- 承接：🔧 本章实测：`Color::red == 0` 编译失败；clang-tidy `cppcoreguidelines-use-enum-class`（已核对官方表）。

### Enum.4: Define operations on enumerations for safe and simple use
- 理由：指南承认"枚举当位标志用"的现实，但要求把 `|`/`&`/`~` 显式重载并约束在枚举类型上，
  而不是散回整型怀抱。
- 承接：标准库至今无位标志设施（`std::flags` 方向在 C++26 草案讨论中，⚠️ 未实测提案号故不引 P 号）；
  通行做法是 `enum class` + 手写位运算重载 + `std::underlying_type_t` 显式下行。

### Enum.5: Don't use ALL_CAPS for enumerators
- 理由：全大写是宏的专属交通灯；枚举项混用 ALL_CAPS 会让"这是预处理器符号吗"成为日常悬案。
- 承接：clang-tidy `readability-identifier-naming`（枚举项规则可配置 EnumConstantCase）；NL.9 呼应。

### Enum.6: Avoid unnamed enumerations
- 理由：`enum {min, max};` 匿名=无法在签名中引用、无法重载区分、项名直接污染文件作用域。
- 承接：无专名检查器；以 clang-tidy `readability-enum-initial-value`、`readability-identifier-naming`
  与命名纪律兜底（名称均已核对官方表）。

### Enum.7/Enum.8: 底层类型与枚举值只在必要时指定
- 理由：默认底层类型保持实现自由；`uint8_t` 只在该枚举进序列化结构/位域时才写死——
  过早钉数值=协议与代码双重冻结。
- 承接：`std::to_underlying`（C++23）提供受控下行转换；协议场景 `-Wconversion` 系列看住整型退化。

## 🔧 实测：Enum.3 的两种命运（已实测 g++ 15.2）

```cpp
enum class Color { red, green };
enum Plain     { black, white };
int main() {
    bool b1 = (Color::red == 0);     // 期望：编译失败
    bool b2 = (Plain::black == 0);   // 期望：悄悄通过
    return b1 + b2;
}
```

`-std=gnu++17 -Wall -Wextra` 真实报错（第 4 行）：

```text
error: no match for 'operator==' (operand types are 'Color' and 'int')
```

同一程序里 `Plain::black == 0` 无声通过——魔法数比较照常成立。**一枚 `class` 关键字换来整类 bug 的
编译期出局**，这是全书性价比最高的一条规则（格林语气的中文复述）。

## 权衡与边界

- **与 C 互操作**：C 头文件枚举只能对普通枚举，包一层 `enum class` + 显式转换函数是指南认可的隔离带（CPL 章）。
- **位标志的双重人格**：`enum class Flags` 默认不能 `|`，重载后又鼓励了"两个不相干标志相或"——
  指南未完全解决的灰区，实操用专门 strong-flag 模板收敛。
- **枚举值比较 `==` vs 序比较 `<`**：枚举语义上无大小（`red < green` 合法但无意义），
  排序需求交给显式映射——工具不查，纯靠设计纪律。

## 相邻概念对比

| 相邻 | 差异一句话 |

## 最新演进与工业实践

- C++23 `std::to_underlying` 为 Enum.7 提供唯一官方"下行通道"；反射提案（P2996 路线）若落地，
  枚举↔字符串将不再需要手写 `to_string` switch（⚠️ 按公开路线图表述）。
- C++26 草案的位标志库设施（`std::flags` 方向，⚠️ 未实测提案号故不引 P 号）长期回应 Enum.4 的落地难。
- 工业界：abseil 的 `ABSL_ENUM`/`MAKE_ENUM_BITWISE_OPERATORS` 宏组是 Enum.4 的工业化答案；
  protobuf/flatbuffers 生成码全用 `enum class` + 显式底层类型（Enum.7/8 的"协议白名单"实证）。
