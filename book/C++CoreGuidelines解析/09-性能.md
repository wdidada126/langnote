# 第9章 性能 — Per: Performance（Per.1–Per.30）

> 本章目录版：[← 00-总览与阅读地图](00-总览与阅读地图.md) ｜ 单文件笔记：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md) ｜ 系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)

**本章对象**：current master 实测 Per 组 18 条（Per.1–Per.6 方法论、Per.7 设计为优化让路、
Per.10–Per.19 静态结构类、Per.30 系统类）。⚠️ 旧版 N 组（N.1–N.R3、NR/NF/NO/NT 前缀）在重构中
一分为三：性能方法论进 Per、数值卫生进 ES、并发测量进 CP——本书按新版行文。
格林的解析带着明显的"反直觉训练"意图：本章一半规则在拆除程序员脑中的民间性能迷信。

## 核心概念速览（中英对照）

- **有理由才优化** — don't optimize without reason (Per.1)：理由=测量数据，不是审美
- **过早优化** — premature optimization (Per.2)：Knuth 引用的工程化落地（先正确后快）
- **关键路径** — performance critical path (Per.3/Per.30)：只优化被证明热的部分与系统调用边界
- **复杂≠快** — complicated code is not necessarily faster (Per.4)：手搓位运算常被 -O2 反杀
- **低级≠快** — low-level code is not necessarily faster (Per.5)：抽象层的现代编译器红利
- **无测量不宣称** — don't make claims without measurements (Per.6)：性能结论的同行评议制度
- **为优化而设计** — design to enable optimization (Per.7)：把可优化性当作接口属性（内联可见性、别名清晰）
- **信任静态类型** — rely on the static type system (Per.10)：类型信息越足，编译器自由度越大
- **计算前移到编译期** — move computation from run time to compile time (Per.11)
- **冗余别名/间接** — redundant aliases/indirections (Per.12/Per.13)：多余的指针层级吃掉缓存与重排空间
- **分配次数最小化** — minimize allocations (Per.14)：批量分配/池化/栈上对象三板斧
- **热路径不分配** — do not allocate on a critical branch (Per.15)：实时/中断路径的硬约束
- **紧凑数据结构** — compact data structures (Per.16/Per.17)：缓存行经济学的成员布局
- **空间即时间** — space is time (Per.18)：以空间换时间的合法前提是被测量过
- **可预测访存** — access memory predictably (Per.19)：遍历顺序>指令选择
- **上下文切换** — context switch (Per.30)：并发程序的头号隐性税

## 动机：性能章在规范体系里的真实职能

编码规范谈性能常常两极：要么"别优化"（可读性原教旨），要么"处处优化"（民间玄学）。
Per 组的立场是第三条：**把优化的举证责任制度化**。Per.1–Per.6 六连"Don't"全是程序性约束
（先档案、再定位、后动手、必复测），Per.10–Per.30 才谈技术性手段。这也是本章与第 2 章
P.9"不浪费"的分工：P.9 给预算制，Per 给执行手册。

## 机制：三层规则栈

1. **方法论层**（Per.1–Per.6）：性能档案、热点定位、测量纪律——对应工业的 profiling→优化→回归测试闭环；
2. **设计层**（Per.7/Per.10–Per.13）：让编译器能优化的代码形状（头文件暴露可内联体、减少别名、
   避免无谓间接）；
3. **资源层**（Per.14–Per.19/Per.30）：分配、布局、访存、上下文——硬件经济学四张账单。

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### Per.3/Per.6: 只优化关键部分；用数据说话
- 理由：80/20 法则的规范表述——热点通常在 20% 代码；不在热区的"优化"只增加错误面与理解成本。
- 承接：perf/VTune/Tracy 等采样分析器；CI 基准门禁（Google/Benchmark 库的 `BENCHMARK` 回归）；
  `-O2` 前后对照见本章实测。

### Per.7: Design to enable optimization
- 理由：跨 TU 优化受可见性限制——把可内联的小函数体放头文件、用 LTO 缝合边界，
  设计期决定的是"优化器的视野"，不是某条指令。
- 承接：`-flto`（GCC/Clang 标配）、C++20 modules（⚠️ 与性能的提案关联未实测 P 号，不引）；
  编译器侧 `__attribute__((always_inline))` 仅作逃生舱。

### Per.10: Rely on the static type system
- 理由：`int*` 与 `char*` 的严格别名规则是向量化与重排的地基；union 型双关与 `reinterpret_cast`
  链条直接废掉优化器的知识（ES.49/C.183 的性能侧镜像）。
- 承接：`-O2` 向量化报告（`-fopt-info-vec`）；`std::bit_cast`（C++20）给合法类型双关一条快车道。

### Per.11: Move computation from run time to compile time
- 理由：编译期算一次、运行期零成本——constexpr 表/查找结构物化是 C++ 特色的"预计算"。
- 承接：`constexpr`/`consteval`（C++20）、字面算子、模板元（13 章 T.120 限定"确需时"）；
  运行时侧 `-O2` 常量传播自动完成一部分。

### Per.14/Per.15: 分配账本
- 理由：通用分配器是"平均情况最优"，热点路径要自己记账：批量分配、对象复用、
  `reserve` 一次性买断增长序列；实时路径干脆禁分配。
- 承接：🔧 本章实测；`std::pmr::polymorphic_allocator`+`monotonic_buffer_resource`（C++17）、
  `std::deque/list` 选型、mimalloc/jemalloc 替换分配器。

### Per.16/Per.17/Per.19: 布局即性能
- 理由：缓存行 64B 是当代 C++ 的真实"字长"；高频成员放头部、SoA 优于 AoS 的遍历场景、
  顺序访存 > 花哨指令——数据布局的收益常比算法换壳大。
- 承接：`alignas`、`__builtin_prefetch`；性能分析器的 cache-miss 火焰图；
  工业替身：absl::flat_hash_map（Per.16 实证）。

### Per.30: Avoid context switches on the critical path
- 理由：一次自愿/非自愿上下文切换的成本（µs 级）远超一次函数调用（ns 级）；
  锁竞争、阻塞 IO、过度线程化都体现在这张账单上（与 CP.3/CP.40 共享判据）。
- 承接：`std::jthread` 与线程数治理（CP 章）、busy-wait+`std::atomic` 的克制使用、perf 的 cs 事件计数。

## 🔧 实测：Per.14 "reserve 一次性买断"（已实测 g++ 15.2）

```cpp
#include <vector>
#include <chrono>
#include <cstdio>
int main() {
    using clk = std::chrono::steady_clock;
    std::vector<int> a, b;
    auto t0 = clk::now();
    for (int i = 0; i < 5'000'000; ++i) a.push_back(i);          // 倍增扩容+反复搬运
    auto t1 = clk::now();
    b.reserve(5'000'000);
    for (int i = 0; i < 5'000'000; ++i) b.push_back(i);          // 一次到位
    auto t2 = clk::now(); /* 打印毫秒差 */
}
```

`-std=gnu++23 -O2 -Wall -Wextra` 编译，两轮真实运行输出：

```text
push_back w/o reserve: 6 ms | with reserve: 2 ms
push_back w/o reserve: 7 ms | with reserve: 3 ms
```

3 倍差距、数字可复现——但注意 Per.6 的完整姿势：这是在 -O2、5e6 元素、冷分配器场景下的
一次测量；元素更大/拷贝更贵时比例变化，**结论强度止步于"此处值得 reserve"**。

## 权衡与边界

- **Per.2 与"提前设计"的界线**：Per.7 要求设计期预留优化空间——这与 Knuth 戒律不矛盾：
  买"可优化的形状"，不买"具体的技巧"。
- **缓存友好的重构成本**：SoA 化伤可读性伤抽象——Per.19 生效前请回读 Per.1（理由）与 Per.6（测量）。
- **编译期计算的隐形账单**：Per.11 收益换编译时间与模板错误可读性（13 章实测过落点差异）。

## 最新演进与工业实践

- C++20/23：`std::span` 零拷贝视图、ranges 的组合式惰性求值（减少中间容器分配）、
  `std::atomic_ref`（P0019R8，实测 302，C++20）把原子税限定到需要的对象上。
- C++26 方向：constexpr 全面库化（P2552R3 constexpr vector，实测 302）扩大 Per.11 的战线；
  senders（P2300R10，实测 302）为 Per.30 提供"少切换"的任务化抽象。
- 工业界：abseil 基准库 + `raw_hash_map`、folly `FBVector`（Per.14/16 的工业化注脚）、
  SIMD 化 JSON（simdjson）证明"Per.19 布局>指令技巧"在解析负载上的量级收益。
