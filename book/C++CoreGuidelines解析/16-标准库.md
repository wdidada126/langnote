# 第16章 标准库 — SL: The Standard Library（SL.1–SL.C.1）

> 本章目录版：[← 00-总览与阅读地图](00-总览与阅读地图.md) ｜ 单文件笔记：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md) ｜ 系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)

**本章对象**：current master 实测 SL 节含子规则约 20 条：SL.1–SL.4 总纲、SL.con（容器）、
SL.str（字符串）、SL.io（iostream）、SL.regex/SL.chrono（占位小节）、SL.C（C 运行库）。
⚠️ 旧版曾以 `Std.`/`SL.` 双前缀摇摆（本书成书依据的快照与现行 master 的编号存在出入，
如 `SL.str.5`（std::byte）系 2022 后新增）。格林的立场：**标准库是默认选择，不是候选之一**——
"先想标准库有什么，再想要不要自己造/引第三方"。

## 核心概念速览（中英对照）

- **库优先** — use libraries wherever possible (SL.1)：重复实现=重复缺陷
- **标准库优先** — prefer the standard library (SL.2)：ES.1 的镜像条款，跨章同义反复即强调
- **std 入侵之禁** — don't add to namespace std (SL.3)：向 std 注入声明=UB+未来标准撞名双雷
- **类型安全使用** — use it in a type-safe manner (SL.4)：越界/迭代器失效/未初始化三坑族
- **array/vector 替代 C 数组** — SL.con.1：知道长度用 `std::array`，动态用 `vector`
- **vector 默认容器** — SL.con.2：除特定操作画像外 vector 是默认解（连续内存红利）
- **边界错误** — bounds errors (SL.con.3)：`at` 抛错/`[]` UB，越界是全语言第一 UB 源
- **trivially-copyable 限制** — SL.con.4/C.90：memcpy/memset 只配得上平凡可复制类型
- **string 拥有/zstring 视图** — SL.str.1–3：所有权字符串与 NUL 结尾视图的分工（呼应 I.13/F.25）
- **`std::string_view`** — SL.str.2：非拥有字符序列视图；悬垂视图治理线
- **`std::byte`** — SL.str.5：裸内存的具名类型（`void*`/`char*` 的语义化替身）
- **sync_with_stdio** — SL.io.10：混用 printf 与 iostream 时的同步开关决定顺序与吞吐
- **endl 之罪** — SL.io.50：换行+flush 捆绑，日志刷屏时的隐形税
- **setjmp/longjmp 之禁** — SL.C.1：绕过析构的时空跳跃（E 章邻罪）

## 动机：本章是"指南的经济学章"

前面各章教你把类型/资源/并发做对，SL 章降低"做对"的边际成本：标准库设施是**已经有人付过
正确性学费的资产**。格林统计式地指出：手写环形缓冲的 bug 率、手写字符串工具的安全审计成本，
都远高于接受 vector/string/string_view 的学习曲线。同时本章给"库边界"立规：
自定义扩展放自己的 namespace，绝不向 std 注入特化以外的名字（SL.3——
注意：对标准类型的用户定义特化本身也受严格限制）。

## 机制：四类设施的"默认选型表"

```text
容器    vector(默认) → array(定长栈) → deque/map(有操作画像) → C数组(仅互操作边界)
字符串  string(拥有) / string_view(只读视图) / zstring+czstring(NUL 边界, GSL) / byte(裸内存)
I/O     iostream(默认流) / fstream(文件) / format(格式化) —— printf 混用需 sync_with_stdio(false) 慎用
C 库    仅 stdint/stddef 类；stdio→iostream、string.h→string、setjmp→异常（SL.C/E 联动）
```

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### SL.1/SL.2: 用库；优先标准库
- 理由：库代码经过百万小时生产验证；手写替身的"学习曲线收益"通常在集成与审计日归零。
- 承接：依赖治理工具（vcpkg/Conan 审计）；clang-tidy `modernize-*` 全模块即"手搓→标准库"
  迁移检查器集合。

### SL.3: Do not add non-standard entities to namespace `std`
- 理由：std 里埋自定义函数=未来标准同名即 ODR 灾难；标准仅允许少数特化权
  （且 `::enhance` 式全源加严条款，C++ 标准明文限制）。
- 承接：命名规范+评审；`misc-use-anonymous-namespace`（已核对官方表）管内部实体去向；
  编译器无法拦截（合法声明区太窄但确实存在）。

### SL.con.1/SL.con.2: array/vector 对 C 数组的胜利
- 理由：C 数组 decay 成指针后长度信息蒸发（R.14/I.13 的库侧收口）；vector 的移动语义
  +reserve+连续内存把"动态数组"做成零心智负担设施。
- 承接：`std::array`+`fill`、`vector::reserve`（🔧 09 章实测）、clang-tidy
  `modernize-avoid-c-arrays`（已核对官方表？需列名——以 `readability-container-*` 族兜底 ⚠️）。

### SL.con.3: Avoid bounds errors
- 理由：`operator[]` 越界=UB 静默毁灭；`at()` 抛 `out_of_range` 是**标准库自带 P.7 检查点**。
- 承接：🔧 11 章实测 at 消息；`-D_GLIBCXX_ASSERTIONS`（🔧 19 章实测，把 [] 变检查版）；
  gsl::at/span；Ubsan `-fsanitize=bounds`（Linux 线工具）。

### SL.con.4: 非平凡类型禁 memcpy/memset（=C.90 库侧）
- 理由：清零 std::string 成员=销毁其内部不变式，赋值运算符/析构从未被调用——
  memset 快是快在"跳过你的构造函数"。
- 承接：🔧 本章实测（GCC `-Wclass-memaccess` 直接点名）；`std::ranges::fill`/值初始化替身。

### SL.str.1–3: string/view/zstring 的三段分工
- 理由：拥有（string）、只读视图（string_view）、NUL 边界（zstring——GSL 概念）三种需求
  三种类型；混用产生悬垂视图（string_view 挂到临时 string 上）与越界读（zstring 没 NUL）。
- 承接：C++17 `string_view`、`string::starts_with/ends_with`（C++20）；clang-tidy
  `bugprone-stringview-nullptr`、`bugprone-suspicious-stringview-data-usage`（均已核对官方表）。

### SL.io.10/SL.io.50: iostream 卫生
- 理由：同步开关改变吞吐与输出交错语义；`endl` 每次 flush——热日志场景下是"每行一次系统调用"。
- 承接：`'\n'` 替 endl；`std::format`/`std::print`（C++20/23，⚠️ print 提案号未实测不引）；
  `std::osbuffer`?（未入标，不展开）。

## 🔧 实测：SL.con.4——memset 非平凡类型被 GCC 当场拒绝（已实测 g++ 15.2）

```cpp
#include <cstring>
#include <string>
struct Widget { std::string name; int v; };   // 非平凡：SL.con.4 违规靶子
int main() { Widget w; std::memset(&w, 0, sizeof w); return w.v; }
```

`-std=gnu++17 -Wall -Wextra -O2 -c` 真实警告：

```text
warning: 'void* memset(void*, int, size_t)' clearing an object of type
'struct Widget' with no trivial copy-assignment; use assignment or value-initialization instead
[-Wclass-memaccess]
```

指南说"别用"，编译器说"你敢用我就点名"——SL.con.4/C.90 是少数**已完全被编译器承接**的条款。
对照 C.90 的正当例外（POD 结构走网络协议）：那也应该是 `std::byte`+显式序列化，而非 memset。

## 权衡与边界

- **`at()` vs `[]` 的绩效辩论**：at 每次边界检查；指南与 Per 章的合理解=热点循环用 span/iterator
  消灭下标，而不是用 [] 赌运气（ES.55"避免检查的需求"）。
- **string_view 生命周期**：视图不延长寿命——返回值/成员存储两个高频事故位；
  指南（I.13/F.25 侧）建议参数用视图、拥有用 string。
- **regex/chrono 小节空转**：current master 实测这两节只有标题占位（规则数 0）——
  活文档的真实进度条，格林照录未加戏。

## 最新演进与工业实践

- C++20/23 扩充判据面：`span`（SL.con.1 的动态栈替身）、`to_chars/from_chars`（locale 无关的
  SL.str.10 解法）、`std::expected`（错误码线的官方化，11 章实测）、`std::print`（C++23）。
- C++26 方向：容器 constexpr 化（P2552R3，实测 302）继续消解"运行期容器 vs 编译期数据"边界。
- 工业界：abseil 长期以 `absl::` 家族"预演标准库"（string_view/Status/Span 先于标准落地）——
  SL.2 的务实补注：标准库**已有**才优先；尚未覆盖的领域选成熟库而非手写（P.13）；
  folly 同类证据。libc++ 的 `_LIBCPP_HARDENING_MODE`（C++25 方向 hardening）与 libstdc++
  `_GLIBCXX_ASSERTIONS` 是 SL.con.3 的两条厂商化路线（🔧 19 章实测后者）。
