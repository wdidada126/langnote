# 第1章 简介 — In: Introduction（文档元规则 · In.0 等）

> 本章目录版：[← 00-总览与阅读地图](00-总览与阅读地图.md) ｜ 单文件笔记：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md) ｜ 系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)

**本章对象**：赖纳·格林（Rainer Grimm）对 Stroustrup 原版 *C++ Core Guidelines* 开篇部分的解析——
"这份文档是什么、为谁而写、目标与非目标是什么"。对应原版 `In:` 组规则与文档骨架
（In.0 "Don't panic!"、In.force、In.struct、In.sec；2026-09 抓取的 current master 实测：一级标题 32 个，
In.sec 自列"主要节 16 + 支撑节 13"，带编号规则条目标题 448 条）。⚠️ 本书依赖的 2023-07 快照编号与 current master 略有出入，本章及后续各章
均以实测 current master 编号为口径并单独标注差异。

## 核心概念速览（中英对照）

- **核心指南** — C++ Core Guidelines：Stroustrup 与 Ellis 主持、开源社区共同维护的 C++ 编码规范活文档
- **指南支持库** — Guidelines Support Library (GSL)：承载指南概念类型（`not_null`/`span`/`owner` 等）的参考库
- **规则前缀体系** — rule prefixes（P/I/F/C/R/ES/Per/CP/E/Con/T/CPL/SF/SL/A/NR/Pro/GSL/NL）：按主题分组且全局唯一可引用的规则编号
- **非目标** — non-aims：文档明示"不是教程、不是风格规范、不承诺穷尽"的自我边界声明
- **执行/强制检查** — enforcement：每条规则附"如何被工具检查"的落地设计，无执行手段的规则降级为建议
- **编译期检查优先** — prefer compile-time checking：把错误从运行期前移到编译期的总纲（P.5 的先声）
- **别慌** — In.0 Don't panic!：告诉读者无需一次读完、可按主题跳读的使用协议
- **静态类型安全 + 生命周期安全** — static type safety & lifetime safety：全指南赖以成立的两大支柱
- **活文档记号** — `???`/simple/saturated 状态词：直接印在规则文本上的自我治理标注
- **FAQ 节** — FAQ.1–FAQ.66：21 组"常见质疑答辩"（实测 current master FAQ 前缀规则 21 条、
  FAQ.50–60 专答 GSL），简介章的"读者异议预处理的"延伸部
- **主要节/支撑节** — major/supporting sections（In.sec 实测 16+13）：规则前缀即主要节的
  缩写；支撑节（A/NR/RF/Pro/GSL/NL/FAQ/附录 A–D/Glossary/To-do）不产出编号规则族却承载词汇与执法
- **正交性声明** — "These sections are not orthogonal"：指南自认主题交叉，一条规则可属多节
  （如 ES.46 同时在 Type profile 视野内）——读表不许问"这条到底属于哪章"

## 动机：为什么要先读"简介"

格林在开篇反复强调一件事：**把 Guidelines 当"法律条文"读会立刻失望，当"带执行方案的工程共识"读才有收益**。
简介章解决三个困惑：①它不是 ISO 标准（FAQ.6 实测：委员会未批准）；②它不规定缩进括号这类风格
（那是 clang-format 的事）；③它的目标读者是"愿意用现代设施替换旧惯用法的 C/C++ 程序员"。
不先钉住这三条边界，后面 19 章的规则会被误读为教条。

## 机制：文档骨架怎么组织知识

1. **三层结构**：大节（章级主题，如 `F: Functions`）→ 规则（`F.16: ...`，每条含理由、示例、例外）→
   执行注记（Enforcement 小节，指名检查工具或不可检原因）。
2. **规则状态词**：`???`（存疑待定）、`simple`/`saturated`（完备度）等记号直接印在规则文本上——
   这是活文档的自我治理机制，也是第 19 章"规格配置"讨论的基础。
3. **目标/非目标对照表**：aims（安全、简单、高效、符合直觉）与 non-aims（全面性、教学性、风格统一）
   成对出现，格林的解析方式是每条配一个"违反后会发生什么"的反例。

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### In.0: Don't panic!（别慌！）
- 理由：指南条目多、互相引用，逐条对照读会瘫痪；应按"当前碰到的问题域"索引式取用。
- 现代工具承接：IDE/文档搜索 + [官方规则索引页](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)；
  本笔记体系的"核心概念速览"就是同一读法的落地。

### In.force: Enforcement（没有执行手段就没有规则）
- 理由：无工具检查的规范在 code review 里必然漂移；"每条规则要么给出检查方案，要么诚实标注不可检"。
- 现代工具承接：clang-tidy 的 `cppcoreguidelines-*` 模块（43 项，名称已实测核对于
  clang.llvm.org 官方检查表）即该理念的工业实现；MSVC 侧为 CppCoreCheck（原版附录 D 点名工具）。

### In.struct / In.sec（结构与主要章节）
- 理由：规则按"抽象层级"而非"语言特性"排列——先接口（I）再函数（F）再类（C）最后资源（R），
  体现"设计先于语法"的知识图谱。
- 现代工具承接：本书 20 章与原指南 `In.sec` 大节一一对应（映射表见 [00-总览与阅读地图](00-总览与阅读地图.md)）。

### S.1 → 现 SF.1（文件后缀约定）〔旧编号示例〕
- 理由：连"怎么给文件起名"都进指南，是为了让"头文件=接口、源文件=实现"的边界可被工具识别。
- 现代工具承接：SF.1（current master 实测编号）；构建系统与 include-what-you-use 等依赖分析工具受益。

## 🔧 实测：用 `<version>` 宏确认"你在用哪一层现代设施"（已实测 g++ 15.2）

指南要求"用 ISO 标准 C++、用设施先确认存在"（P.2: Write in ISO Standard C++，current master 实测原文；
`<version>` 特性宏探测头为 libstdc++ 官方文档约定，⚠️ 非原指南条文）：

```cpp
#include <version>
#include <cstdio>
int main() { /* 打印 __cpp_lib_jthread 等特性宏值 */ }
```

`-std=gnu++23 -O2 -Wall -Wextra` 编译运行，真实输出：

```text
__cpp_lib_jthread=201911 __cpp_lib_expected=202211 __cpp_impl_three_way_comparison=201907
```

本机 MinGW g++ 15.2 的 libstdc++ 已带 `std::jthread` 与 `std::expected`——后续各章的"现代工具承接"
节全部可在本机复现，这正是简介章要求的"先盘点工具链再谈规范"。

## 权衡与边界

- **活文档 vs 出版物的时间差**：格林 2023 年中文书面对的规则编号/条数与今天的 master 已有出入
  （如 Con 组从 2022 年前后的 20+ 条收缩为 5 条、G 组并入 C 组）。读法：以章主题为锚，编号当坐标而非经文。
- **解析书 vs 译本**：本书不逐字翻译原版（原版本身就要求"引用规则而非复制条文"），
  格林的增量是"每章一组可运行的对比示例 + 工具落地"。
- **不覆盖 C++23/26**：2023-07 出版的书不可能讨论 `std::expected`、senders 等新设施——由本目录版
  各章"最新演进与工业实践"节补位。
- **In 节自身只有 1 条编号规则**（In.0，current master 实测）：简介章的"规则密度"最低而
  "元信息密度"最高，是本笔记体系把 00 总览单列一册的原因——文档协议的收益在地图，不在条文。

## 相邻概念对比

| 概念 | 它管什么 | 与本章关系 |
| --- | --- | --- |
| ISO C++ 标准 | 语言与库的合法性 | 指南是"如何用标准"而非"什么进标准"（FAQ.6/9） |
| clang-format 风格规范 | 排版/缩进 | 指南 non-aims 明确排除；NL 节只做"建议" |
| MISRA C 等合规规范 | 可审计的强制条款 | 指南靠工具与共识，不靠认证 |
| 本书（解析） | 逐章讲解 + 示例 | 简介章教的就是这本书的使用方法 |

## 最新演进与工业实践

- **提案化维护**：2020 年 P2187R5（Glossable Rules in the C++ Core Guidelines，wg21.link 实测 302）
  与 P2188R1（Core Guidelines on Evolving，实测 302）把"规则可摘引、文档可演化"写成标准委员会层面的
  治理文本——简介章"活文档"定位的制度化；两文均为 Andrew Brown 执笔，服务 Guidelines 与标准的双向通道。
- **2022-2023 大重构**：原 G（类层次）并入 C、N（数值/性能）拆分出 Per/CP/Enum 等前缀，形成
  In.sec 所列 16 个主要节（本书第 1–16 章的骨架）+ A/NR/Pro/GSL/NL 等支撑节（本书第 17–20 章）。
- **工业侧**：Google Style Guide 与指南并行存在（abseil 项目按前者执行）；LLVM 用 clang-tidy 模块之一
  承接指南规则；本仓库 `../C++代码整洁之道.md` 谱系对比节有分工说明。
