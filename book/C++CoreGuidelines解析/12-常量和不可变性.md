# 第12章 常量和不可变性 — Con: Constants and immutability（Con.1–Con.5）

> 本章目录版：[← 00-总览与阅读地图](00-总览与阅读地图.md) ｜ 单文件笔记：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md) ｜ 系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)

**本章对象**：current master 实测 Con 组仅 5 条（Con.1–Con.5）。⚠️ 注意版本落差：本书 2023 年版
所依据的指南快照中 Con 组更长（Con.9/Con.10/Con.20–Con.27/Con.100–Con.110 等命名与 namespace 条款），
2022–2023 的重构把它们分流到 NL（命名）、SF（namespace）与 I 组——本章按"现行 5 条 + 书中旧条款
主题"双轨讲解。格林称本章为"P.10 的实施法"：不可变优先是整个指南里单位字数防护力最高的条款族。

## 核心概念速览（中英对照）

- **不可变优先** — prefer immutable (Con.1)：默认 const/constexpr，可变是需举证的特权
- **const 成员函数** — Con.2：对象"逻辑只读"的操作全部标 `const`，让 const 对象可用
- **指向 const 的传递** — Con.3：默认 `const T&` 传指针/引用，收窄被调方的改动面
- **构造后不变** — const (Con.4)：值在初始化后不再变→const；编译期可算→constexpr（Con.5）
- **逻辑 const vs 位 const** — logical vs bitwise constness：`mutable`/`const_cast` 的哲学分界
- **consteval** — immediate function（C++20）：只能在编译期执行的函数，比 constexpr 更强的承诺
- **const 正确性** — const-correctness：让 const 成为从接口到实现的完整传染链（1992 年代术语的指南化）
- **`std::as_const`** — C++17：以表达式强制 const 视图（循环内防意外拷贝/移动）
- **constexpr 变量** — Con.5：编译期存在的值，兼作常量表达式与静态初始化豁免

## 动机：不可变性是"并发时代的默认安全色"

指南的并发章（CP.3）与常量章实际是一体两面：**不可变数据天然免疫数据竞争，
还能自由拷贝共享**。格林的解析路线：const 的每一分"碍事"（少写 const 更省事）都在换取
三类成本之一——误改（ES.50 的 cast-away）、线程不安全、优化受限。P.10 的经济学账本：
可变状态的维护成本随读者数（人/线程）线性上涨。

## 机制：四档可变性梯度

```text
档0 constexpr/consteval  编译期定死，运行期不存在存储（可 ODR 复用）
档1 const                构造后不变，运行期确定
档2 逻辑 const（mutable） 对外只读、对内记账（缓存/互斥量/观测计数）
档3 可变                  默认要降档——"为什么必须可变"写得出理由才留在档3
```

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### Con.1: By default, make objects immutable
- 理由：默认值决定代码库的熵方向——默认 const 时"放开可变"每次都是显式评审点；
  默认可变时误改无处可查。
- 承接：clang-tidy `misc-const-correctness`（已核对官方表，本地变量建议 const）；
  `-Wmissing-...` 无编译器对应，靠 lint。

### Con.2: By default, make member functions `const`
- 理由：成员函数不带 const=宣告"我可能改状态"；const 化后对象进 `const` 容器/引用后仍可查询。
- 承接：clang-tidy `readability-make-member-function-const`（已核对官方表）；
  设计侧与 F.16（in 参数）联动成"只读传染链"。

### Con.3: By default, pass pointers and references to consts
- 理由：`void print(const Widget&)` 把"只看"承诺写进签名——与 I.11/F.7 的视图语义同一句话的三个写法。
- 承接：clang-tidy `readability-non-const-parameter`（已核对官方表，"参数不必非 const"即点名建议加 const）；
  编译器无法主动建议，纯 lint 领地。

### Con.4: Use `const` to define objects with values that do not change after construction
- 理由：区分 const 与"我打算不改"：前者编译器执法，后者靠自觉。数组表、查找常量、全局配置快照全归它。
- 承接：🔧 本章实测（写 const 即报错）；`-Wcast-qual`（对 const 剥夺报警，GCC 有）。

### Con.5: Use `constexpr` for values that can be computed at compile time
- 理由：编译期值免动态初始化（I.22 全局初始化顺序病的免疫体）、进模板参数、进数组维——
  一份声明三种特权。
- 承接：C++20 `consteval`；`__cpp_lib_expected` 等特性宏本身就是 constexpr 生态（01 章实测）；
  编译器：`-fconstexpr-*` 深度参数控制成本。

### Con.20–Con.27/Con.100 族（书中旧条款主题）⚠️
- 主题保留价值：指针/引用的"顶层 const vs 底层 const"表、`const` 参数在声明/定义间的不重复
  （readability-avoid-const-params-in-decls，已核对官方表）、namespace 命名与 const 无关的条款已迁走。
- 理由（史实）：这族条款是新旧指南间编号漂移最大的区域——读旧博客/教材引用时务必对版本。

### Con.100/Con.110（旧：全大写、符号常量命名）→ 现 ES.32/NL.5 族
- 理由：命名是"最低成本的可读性检查"——ALL_CAPS 让宏、`kFoo` 风格让 Google 系代码库一眼可辨。
- 承接：clang-tidy `readability-identifier-naming`（可配置全谱）。

## 🔧 实测：Con.1/Con.4 的执法现场（已实测 g++ 15.2）

```cpp
int main() { const int c = 1; c = 2; return c; }   // 违反 Con.4 承诺的"打算"
```

`-std=gnu++17 -Wall -Wextra -c` 真实报错：

```text
error: assignment of read-only variable 'c'
```

对照：若 `c` 只是"普通变量+注释说别改"，同一行静默通过。这就是 Con 章的存在论证——
**const 把约定变成编译期合同**。逻辑 const 逃生门（`mutable`）用于缓存/锁：
`std::mutex` 成员在 `const` 查询方法里加锁是指南明示的合法用法（与 CP.50"锁伴数据"合奏）。

## 权衡与边界

- **const 的传染性成本**：多线程下"只读"必须真只读（mutable 同步对象是承认了的可变），
  const 方法之间也可能竞争（const≠线程安全，格林专段强调）。
- **constexpr 的编译期开销**：递归 constexpr 求值失控会吃满编译时间——`-fconstexpr-backtrace-limit`
  类参数是运维细节而非设计借口。
- **过度 const 化**：为"全 const"而给每个局部变量加 const 反而制造噪音——Con.1 是默认方向，不是语法刑罚。

## 最新演进与工业实践

- C++20/23：`consteval`、`std::as_const` 循环惯用法、P0515R3（三路比较，wg21.link 实测 302）要求
  `operator==/ <=>` 默认 const（语言在运算符层面执行 Con.2）。
- C++26 方向：constexpr 对象生命周期、不可变容器讨论持续；契约提案（P2900R14，实测 302）把
  "构造后不变量"从注释升级为可执行子句——与 Con.4 同题的制度化延伸。
- 工业界：Chromium/Google StyleGuide 明文"默认 const"；abseil 的 `ABSL_CONST_INIT`、
  Rust 借"默认不可变"反过来给 C++ 社区论证加热的"immutability by default"讨论——本章是
  跨语言共识最大的规则族。
