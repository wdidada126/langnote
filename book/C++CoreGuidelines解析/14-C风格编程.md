# 第14章 C 风格编程 — CPL: C-style programming（CPL.1–CPL.3）

> 本章目录版：[← 00-总览与阅读地图](00-总览与阅读地图.md) ｜ 单文件笔记：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md) ｜ 系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)

**本章对象**：current master 实测 CPL 组仅 3 条顶层规则（CPL.1/2/3），但它是全书"历史债务处理章"——
大量相关肌肉分散在 ES（vararg/宏/cast）、SL.C（C 运行库）、R.10（malloc/free）、
附录 B: Modernizing code（旧代码现代化路线）。⚠️ 旧版同名主题曾挂 `C.` 前缀（C.1–C.9 "C-style" 条款），
重构后让位给类设计的 C 组——老引用务必核对前缀含义变迁。格林的观点一句话：
**C 与 C++ 不是两种语言的两个阵营，而是同一工程的两个负债等级**。

## 核心概念速览（中英对照）

- **优先 C++** — prefer C++ to C (CPL.1)：C++ 构造严格超集方向吸收 C 惯用法，而非平行共存
- **公共子集** — common subset of C and C++ (CPL.2)：必须以 C++ 编译的 C 代码限制在子集内
- **接口 C 化、实现 C++ 化** — C interface, C++ caller (CPL.3)：跨语言边界的最小信任面
- **混合编译** — compile the C code as C++：同一份 .c 用 g++ 编译即暴露子集外写法
- **变参函数** — variadic/`va_arg` (F.55/ES.34)：C 遗产里类型不安全度最高的一项
- **VLA** — variable length array（C99）：非栈溢出机；C++ 无此设施，GNU 扩展下"看似能用"
- **realloc 语义陷阱** — 对非平凡类型用 realloc=移动构造从未被调用
- **宏依赖症** — preprocessor dependency：`#define` 常量/迷你函数是指南钦点的退休对象（ES.30–ES.32）
- **`qsort` vs `ranges::sort`**：C 比较器（三值 int+擦除指针）与 C++ 比较对象的两代设计
- **翻译边界** — translation layer：薄封装把 C API 洗成 RAII/强类型后再进内网

## 动机：三千万行 C 资产怎么在 C++ 工程里体面服刑

真实工程里"C++ 代码"常常是"C with classes"——malloc 配 free、errno 配 `#define`、
pthread 配裸指针。CPL 章的任务不是谴责，是给**迁移路线**：先冻结增量（CPL.1 默认全 C++），
再统一存量编译模式（CPL.2），最后给必须保留的 C 接口修隔离带（CPL.3）。格林补充的关键论据：
子集外写法大多在 C++ 里**合法但不同义**（`sizeof(struct)`  extern 声明、柔性数组、
VLA 扩展），这类"静默分歧"比编译错误危险十倍。

## 机制：C 遗产的三分类处理

```text
1. 语言级：VLA/隐式 void*/struct 假封装 → 编译为 C++ 暴露分歧 → 替换（std::span/vector/句柄）
2. 库级：  malloc/realloc/printf/errno/sort(qsort) → RAII+类型安全替身（make_unique/format/expected/ranges::sort）
3. 边界级：第三方 C API → 薄翻译层（CPL.3），违规集中一处（I.30 的架构版）
```

## 代表性规则深解析（规则 → 理由 → 现代工具承接）

### CPL.1: Prefer C++ to C
- 理由：同题设施里 C++ 版（enum class/重载/new 表达式语义/constexpr）几乎全面占优；
  选 C 写法=主动放弃类型系统与工具链。
- 承接：clang-tidy 整页 `modernize-*` 模块（`-std=c++20` 迁移检查器集合）；
  GCC/Clang `-Wvla`/`-Wold-style-cast` 等专项。

### CPL.2: If you must use C, use the common subset, and compile the C code as C++
- 理由：以 C++ 编译器编译存量 C 代码是**零成本静态分析**——一次编译扫出全部子集外写法；
  C 与 C++ 对同一段代码的合法性判定差集就是风险清单。
- 承接：🔧 本章实测（VLA 在 GNU 模式的暧昧与 -Wvla 点名）；构建系统双编译矩阵（C 交付、C++ 体检）。

### CPL.3: If you must use C for interfaces, use C++ in the calling code
- 理由：C ABI 是跨语言通用币（I.26），但越界后应立即进入强类型包装：
  `unique_ptr<T, decltype(&close)>` 之类让 C 句柄过 RAII 户口。
- 承接：本仓库 [../C++API设计/07-C++用法与符号导出.md](../C++API设计/07-C++用法与符号导出.md)（extern "C" 工程化）；
  abseil/zlib-ng 等库的 C API+C++ 内核双形态。

### R.10（邻章）: Avoid `malloc()` and `free()`
- 理由：三宗罪——不做构造、realloc 依赖"类型可 memcpy"假设、失败语义（null）古老；
  C++ 对象生命周期对 malloc 一无所知。
- 承接：clang-tidy `cppcoreguidelines-no-malloc`（已核对官方表）；`std::pmr`（C++17）承接"自定义分配策略"
  这一 malloc 唯一正当动机。

### F.55/ES.34（邻章）: vararg 家族
- 理由：`...`+`va_arg` 关闭参数类型检查；`printf` 格式串是 C 世界第一大运行期类型事故源。
- 承接：🔧 04 章实测（`-Wformat` 警告 + std::format 编译期拒错）；`cppcoreguidelines-pro-type-vararg`（已核对官方表）。

### ES.30–ES.33（邻章）: 宏瘦身法
- 理由：宏常量无作用域无类型、宏函数无重载无调试；C++ 替身 constexpr/inline 模板逐条碾压。
- 承接：clang-tidy `cppcoreguidelines-macro-to-enum`、`modernize-macro-to-enum`（已核对官方表）；
  SL.str/format 化后连"日志宏"都失去存在必要（编译期检查的格式化器比宏更便宜）。

### SL.C.1（邻章）: Don't use setjmp/longjmp
- 理由：绕过栈上全部析构=RAII 体系内的地道炸毁；异常机制是其正统继任（C++ 对象与 goto 的
  百年和解）。
- 承接：C++ 异常本身（11 章）；不可抛环境用错误码+显式清理（E.25–E.27），无长跳替代位。

## 🔧 实测：CPL.2——把 C 写法编译成 C++，VLA 现形（已实测 g++ 15.2）

```c
void f(int n) { int a[n]; a[0] = 1; }   // C99 VLA：C 侧合法（C11 起亦为可选特性）
int main() { f(10); }
```

同一段代码三种待遇（`-Wall -Wextra`）：

```text
g++ -std=c++17            → 通过，仅 unused 警告（GNU 扩展放行，无任何 ISO 提示）
g++ -std=c++17 -Wpedantic → warning: ISO C++ forbids variable length array 'a' [-Wvla]
gcc -std=c11              → 通过（C 侧合法；clang 下 -Wvla 可默认点名）
```

关键取证：**严格 `-std=c++17` 竟也接受 VLA**——GCC 把 GNU 扩展混进了"标准模式"，
这正是"混合工程要用 -Wpedantic 或 clang 补刀"的实证；cppcheck/clang-tidy 在 CI 中承接同类检测
（本机未装 cppcheck/clang，⚠️ 其规则存在性按官方文档表述）。C++ 侧正解：
`std::vector<int> a(n)` 或定长 `std::array`+span（ES.27/R.14）。

## 权衡与边界

- **性能幻觉**：malloc 比 new 快是老传说——现代分配器（jemalloc/mimalloc）下差距取决于
  分配大小与并发（[../提高C++性能的编程技术/](../提高C++性能的编程技术/00-总览与阅读地图.md) 有同类实测传统）。
- **真嵌入场景**：无堆环境 malloc/free 有正当性——R.10 的豁免通道是"封进一个池管理器"而非散用。
- **C 接口的稳定性红利别倒贴**：I.26（C 子集 ABI 最稳）与 CPL.2（编译为 C++）存在张力——
  对外导出面用 C 子集，内部体检用 C++ 编译器，两面都要。

## 最新演进与工业实践

- C++20/23 补齐 C 替身：`std::bit_cast`（合法 type-punning）、`<format>`、`std::midpoint`
  （防溢出中点，ES.103 数值卫生）、`std::to_chars`（格式化线收口，⚠️ 未引提案号）。
- C 侧演化让子集更小：C23 `constexpr`/属性对齐后，C/C++ 公共子集扩大方向被社区持续游说
  （WG14/WG21 联合议题，⚠️ 具体联合提案未实测不引）。
- 工业界：Linux 内核以 `-std=gnu11`+sparse 自成一派（反面参照：指南路线的镜像世界）；
  主流 C++ 团队对遗留 C 的通行策略即 CPL 三条款的 CI 化（双编译器矩阵+clang-tidy 门）。
