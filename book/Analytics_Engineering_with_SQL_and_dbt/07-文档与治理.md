## 7.1 dbt 文档系统

### 自动文档生成

dbt 从项目代码**自动生成**完整的文档网站：

```bash
dbt docs generate   # 生成文档
dbt docs serve      # 本地预览
```

| 文档来源 | 内容 |
|---------|------|
| **SQL 模型文件** | 模型名称、SQL 逻辑 |
| **schema.yml** | 描述、列描述、测试定义 |
| **DAG** | 模型间依赖关系图 |
| **warehouse metadata** | 表大小、行数（引擎提供） |

✅ dbt docs 的核心价值：**文档从代码生成，而非独立维护**——消除文档过期问题。

## 7.2 schema.yml 深度配置

### 完整的 schema.yml 结构

```yaml
version: 2

models:
  - name: dim_customers
    description: "客户维度表——包含客户基本信息和首单统计"
    docs:
      show: true          # 是否在文档中显示
    config:
      tags: ['dimension', 'customers']
    columns:
      - name: customer_id
        description: "客户唯一标识（业务主键）"
        tests:
          - unique
          - not_null
        tags: ['pk']
      - name: first_name
        description: "客户名"
        meta:
          pii: true       # 自定义元数据
      - name: email
        description: "客户邮箱"
        meta:
          pii: true
          classification: confidential
      - name: lifetime_value
        description: "客户终身价值（所有订单总额）"
```

| 字段 | 用途 |
|------|------|
| `description` | 模型/列的业务描述 |
| `docs.show` | 控制文档可见性 |
| `config.tags` | 标签，用于选择器和治理 |
| `meta` | 自定义元数据（PII、分类等） |
| `tests` | 列级数据质量测试 |

✅ `schema.yml` 是 dbt 项目的**元数据中心**——文档、测试、标签、治理信息汇聚于此。

## 7.3 文档最佳实践

使用 `doc block` 复用描述：

```yaml
docs:
  - name: customer_id_description
    value: |
      客户唯一标识。来源: raw.customers.id。变换: 无（直接映射）。
```

| 对象 | 最低覆盖率 | 推荐覆盖率 |
|------|----------|----------|
| Mart 模型 description | 100% | 100% |
| Mart 列 description | 80% | 100% |
| Staging 模型 | 50% | 80% |
| meta 标注（PII） | 关键列 | 所有敏感列 |

⚠️ 文档的最大敌人是**完美主义**——先覆盖 Mart 层，再逐步扩展。

## 7.4 数据治理与分析工程

### dbt 在治理中的角色

```
数据治理框架（战略层）
    ↓
dbt 项目（技术实现层）
    ├── schema.yml → 元数据管理
    ├── tests → 数据质量自动化
    ├── docs → 数据目录
    ├── tags → 数据分类
    └── access → 模型权限控制
```

### 治理实践清单

| 实践 | dbt 实现 | 治理价值 |
|------|---------|---------|
| **模型目录** | dbt docs + schema.yml | 数据可发现 |
| **血缘追踪** | DAG 自动生成 | 影响分析 |
| **质量保障** | schema tests + data tests | 数据可信赖 |
| **PII 管理** | meta + tags | 合规标注 |
| **变更管理** | Git PR + CI/CD | 变更可审计 |
| **访问控制** | warehouse grants + model tags | 权限可管控 |

✅ dbt 将治理从**文档和流程**转化为**代码和自动化**。

## 7.5 🔧 DuckDB / SQLite 类比（文档与治理本地化）

| # | dbt 治理概念 | DuckDB 本地实现 | SQLite 本地实现 | 标注 |
|---|-------------|----------------|----------------|------|
| 1 | `dbt docs generate` | 无自动生成，需手动维护 README 或注释 | 同 | 🔧 非本书引擎行为 |
| 2 | `schema.yml` 元数据 | 无等价物，可用 `.sql` 文件头部注释 | 同 | 🔧 非本书引擎行为 |
| 3 | DAG 血缘可视化 | 无自动 DAG，需手动追踪 VIEW 依赖 | 同 | 🔧 非本书引擎行为 |
| 4 | `meta: pii: true` | 无内置 PII 标注，需外部文档 | SQLite 无元数据系统 | 🔧 非本书引擎行为 |
| 5 | SQLFluff lint | 可独立使用 SQLFluff（与引擎无关） | 同 | 🔧 非本书引擎行为 |
| 6 | tags 标签选择器 | 无等价物 | 无等价物 | 🔧 非本书引擎行为 |

> 🔧 以上均为**非本书引擎行为**——文档自动生成和元数据管理是 dbt 框架级功能。
