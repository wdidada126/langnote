# 《Readings in Database Systems》第5版（Red Book）精读笔记——总览与阅读地图

> 定位先说清楚：**这不是一本教科书，而是一部"论文汇编 + 编者评论"**（readings, not textbook）。
> 每章 = 一篇编者亲写的导读评论 + 2–3 篇原始论文。读它的正确姿势不是"学知识体系"，
> 而是**跟着一线设计者（Stonebraker/Hellerstein/Bailis）重读他们眼中的分水岭论文，
> 看"这一篇为什么值得被收录、当年解决什么问题、今天哪个工业系统里还留着它的骨头"**。
> 本目录即按这个主轴组织：每章一个文件，串讲该主题下的代表论文，并给出深度权衡与工业落地对照。

## 阅读路径建议

- **主线 A（编年 + 主题，推荐首读）**：01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10。
  顺序即原书：先立"架构坐标系"（anatomy），再看三大系统论文，再补"人人都该知道"的底层机制，
  然后进入 2000s 后的分裂（新架构/数据流/弱隔离），最后收束在优化、分析、语言、Web 与两篇偏见。
- **主线 B（OLTP/事务方向）**：01 → 03 → 04 → 06 →（补 Gray 1981 精读）→ 10。
- **主线 C（分析/大数据方向）**：01 → 05 → 07 → 08 → 10 →（补 AlphaSort 精读）。
- **主线 D（只想读"编者打架"的部分）**：直接读 10（第 11 章 Stonebraker 与 Hellerstein 的正面交锋是全书思想密度最高的一页纸对一页纸），再倒读 04、06。
- **速览/面试**：每章「核心概念速览」+「常见误区」表。

## 三条硬结论（先给答案，再读全书）

1. **红书第5版的真正论点是"one size fits all 已死"**（第 4 章标题句）：行存/磁盘/单一引擎时代结束，
   列存（数据仓库）、内存（OLTP）、数据流（分析）、弱隔离（全球规模）各自分化成专用架构——
   而分化后各流派又在向对方回抄（NoSQL 加 SQL、数仓加湖、OLTP 加 MVCC 编译执行）。
2. **收录标准暴露了品味：只收"制造了此后争论的论文"**——System R 制造了关系可行性之争、
   Selinger/Volcano 制造了优化器两大学派、ARIES 至今仍是恢复的默认答案、MapReduce 制造了
   "数据库 vs 数据流"十年论战、Adya/Dynamo/CAP 制造了隔离与一致性的现行话语。读红书要读
   "被选中的理由"，不是读论文本身的技术摘要。
3. **它是一本诚实到罕见的书**：序言明说选集"代表我们目前的品味，请以批判眼光看待"；
   第 11/12 章干脆放弃选经典、只署"偏见"；编者之间还互相公开反驳。把 Red Book 当权威读会读窄，
   当辩论现场读才读值。
