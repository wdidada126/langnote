# 02 传统 RDBMS 三篇：System R、POSTGRES、Gamma（书第 2 章 Traditional RDBMS Systems）

> 对应书章：Chapter 2 "Traditional RDBMS Systems"，评论作者 Michael Stonebraker。
> 收录：① Astrahan, Blasgen, Chamberlin, Eswaran, Gray, Griffiths, King, Lorie, McJones, Mehl, Putzolu, Traiger, Wade & Watson,
> *System R: Relational Approach to Database Management*（ACM TODS 1(2), 1976, 97–137）；
> ② Stonebraker & Rowe, *The Design of POSTGRES*（SIGMOD 1986）；
> ③ DeWitt, Ghandeharizadeh, Schneider, Bricker, Hsiao & Rasmussen, *The Gamma Database Machine Project*（IEEE TKDE 2(1), 1990）。
> 评论开篇的判词（大意）：这（可以说是）关于 DBMS 系统最重要的三篇论文，按时间顺序读。
> 三篇分别回答三个问题：**关系模型能落地吗？关系系统能扩展吗？关系系统能并行吗？**

## 核心概念速览（中英对照）

- **关系模型的工程证明** — System R demonstration：在 Codd 1970 提出模型后，IBM 用可运行原型证明"声明式 SQL + 优化器"在真实负载上快过手写导航代码
- **SEQUEL/SQL** — Structured Query Language：System R 语言实验的产物；子查询、视图、触发器式机制多在此期定型，经 ANSI 标准化成为至今唯一存活的数据语言
- **共享锁/互斥锁与两阶段锁** — Read/write locks & 2PL：System R 并发控制定型的双锁型与"增长-收缩"协议
- **缓冲池与死锁预防** — Buffer pool & deadlock avoidance：System R 用等待图/资源探测避免死锁，而非事后检测（与同时代 IMS 式超时法相反）
- **可扩展性架构** — Extensibility (POSTGRES)：自定义类型、操作符、访问方法与规则（ECA），把"下一代表"变成可插拔对象
- **非第一范式与版次** — NF² & Time Travel：POSTGRES 允许列本身是表（数组/子表）并保留历史版本，"版本即视图"
- **规则系统** — Rules as triggers：POSTGRES 用"检索替换/插入替换"规则实现主动数据库语义，后世视图可更新与触发器的祖先之一
- **无共享并行** — Shared-nothing parallelism：Gamma 的机器形态：节点只有 CPU+内存+盘，靠高速互联搬数据，不共享磁盘
- **哈希水平分区** — Hash-range data partitioning：按哈希把元组均匀撒到所有节点，所有算子（连接/聚合）并行执行，MPP 数仓的技术原型
- **对等架构** — Symmetric architecture：每个节点软件栈完全相同（无主控/从属之分），故障与扩展都是"节点±1"
- **混合分区连接** — Hybrid hash/range partitioning & data skew：Gamma 论文对倾斜与分区粒度（fragment）的分析，是 shuffle 设计的教科书段落
- **并行数据库之死与还魂** — MPP revival：Teradata/Gamma 路线在 1990s 被数仓 appliance 埋葬、又被 Redshift/Vertica/Snowflake 复活

## 核心精讲

### 2.1 System R：论文是"实验设计书"而非"成果汇报"

**解决什么问题**：Codd 1970 的论文（仓库精读：
[../../paper/doi_10.1145_362384.362685/00-精读笔记.md](../../paper/doi_10.1145_362384.362685/00-精读笔记.md)）
给出了关系代数/演算与规范化理论，但 IBM 内外的主流判断是"声明式查询必然慢"——
导航式系统（IMS）能精确控制取数路径，而"让用户写 SQL、让机器找路径"是空想。
System R（1972 年由 Frank King 发起，⚠️ 评论中提到 Codd 未被允许领导该项目，此说为 Stonebraker 转述）
的使命就是**用原型证伪这个判断**。

**论文的工程骨架**（评论与本目录整理）：

| 部件 | System R 的答案 | 后世 |
| --- | --- | --- |
| 语言 | SEQUEL→SQL（块结构语言演化而来，评论顺带吐槽其后来变得"复杂"） | 唯一活过半个世纪的数据语言 |
| 存储 | 单一记录类型页式存储、B+ 树索引、聚簇 | 直接是 anatomy 论文的模板 |
| 优化器 | Selinger 框架（第 3 章正选论文即其展开） | 见 03 |
| 并发 | 读/写锁、2PL、页粒度意向锁（与第 3 章 Gray 文互为姐妹篇） | 见 03 |
| 恢复 | 早期版本用镜像表，后演进为 ARIES 之前的日志方案；ARIES 在 IBM 内部血脉直接接上 | 见 03 |
| 授权 | GRANT 到列级视图的授权模型 | SQL 标准照抄 |

**为什么被收录（而非 Codd 原文）**：红书第 5 版的取舍极有味道——第 3/4 版收录 Codd 1970，
第 5 版把席位让给"模型如何变成系统"。这与全书方法论一致：**红书要的是决策现场，不是公理宣言**。
Stonebraker 在评论里替读者把问题清单列出来：为什么选解释执行+游标、为什么优化器左深树、
为什么可串行化——每一条都对应后面章节的一场 ongoing 争论。

**局限与代价**：System R 是研究原型不是产品；1981 年 Bernstein 等人的历史评估（通说）总结了
死锁处理、分布式缺失、性能模型等落差。但 DB2、Oracle、Ingres 的初代设计几乎全部从这篇论文（及
同实验室的 TODS 系列）抄起——**三篇里唯一"没有它就没有后面两篇"的正是它**。

### 2.2 POSTGRES：把"可扩展"从形容词变成 API

**解决什么问题**：1980s 中，关系系统统治 OLTP 但被对象派围攻：工程/科学/AI 负载需要自定义类型、
复杂结构、版本与主动行为，"关系 DBMS 只能存矩形"的指控成立。POSTGRES（Berkeley，1986 起）的回答
是把系统本身做成**扩展框架**：

- **类型即对象**：用户定义类型（含由行组成的"扩展记录"）、其上的自定义函数与操作符全部可注册；
  新类型还能带自己的存储与索引钩子（access method 接口）。
- **NF² 列**：一列的值可以是一张表——"爱好"这种稀疏多变属性第一次不用把表拉宽。
  （对照第 1 章评论：这就是 JSON 争论的 1986 预演。）
- **规则与时间旅行**：检索/插入替换规则实现可更新视图与主动逻辑；版次（versioning）机制保留历史。
- **Postquel → 兼容层**：初期故意不用 SQL（Stonebraker 后来多次承认这是**致命的营销错误**——
  学术界与工业界只信 SQL；POSTGRES 最终靠与商业引擎拼兼容才续命，演化为 Illustra→Informix→DB2 血统与 PostgreSQL 开源血脉）。

**为什么被收录**：它是"下一代 DBMS"争论中**站对方向但输掉战场**的孤本。今天所有主流库的
自定义类型/扩展机制（PostgreSQL extension 生态、Oracle 对象类型）都认它作祖；
红书用它给第 4 章"专用架构"埋线：**当通用系统拒绝开房时，负载会出走成专用系统——
这预言了 NoSQL，也预告了自己。**

**取舍**：论文自述性能刻意让位于功能（无查询优化器、解释执行、仅单机事务）；
"扩展性优先"路线的税单由整个 1990s 的 ODB-关系映射之争支付。

### 2.3 Gamma：并行问题的机器形态答案

**解决什么问题**：1980s 末，决策支持查询（扫十亿行）让单机极限裸露。Gamma（Wisconsin, DeWitt）
用一台 100MB/s 互联、约 16节点的 shared-nothing 原型机回答三个此前无人系统回答的问题：

1. **数据怎么分**：哈希分片到 fragment（多页块，非单元组，摊薄小片开销）；论文对**倾斜**的处理
   （动态再平衡/混合哈希-范围）是所有后来 shuffle 设计的祖先——本仓库 AlphaSort 精读
   （[../../paper/doi_10.1145_191839.191884/00-精读笔记.md](../../paper/doi_10.1145_191839.191884/00-精读笔记.md)）
   处理的是同一族问题（分区+排序的缓存局部性），只是场景从单机多进程换到了集群。
2. **算子怎么并行**：选择/投影在片内做；等值连接按连接键重分区（repartmentization）后节点内连接——
   **网络搬数据以换取"每节点只见相关数据"，这就是今天 MPP 数仓与 Spark shuffle 的同一条原理**。
3. **谁付容错的账**：事务跨节点的原子性（论文自认当时最薄弱环节，留给了 2PC 研究与后来者）。

**为什么被收录**：与 Teradata（商用先行但论文贫瘠）、Sequent 共享内存路线并列的时代岔路口，
Gamma 是**把设计空间全摊开写清楚**的那篇。30 年后回看：shared-nothing 完胜（Redshift/Vertica/Snowflake/
BigQuery 全部是它的后代），共享内存/共享磁盘（Oracle RAC 一脉）退守利基。DeWitt 本人后来参与创办
Netezza，闭环回工业。

**评论冷知识**：Stonebraker 把三篇并列为"关于 DBMS 最重要的三篇"——注意他选的全是**系统论文**，
没有一篇纯理论；红书品味至此已完全暴露。

### 2.4 三篇合读：红书编排的暗线

- 时间序 = 质疑序：1976（能落地吗）→ 1986（能扩展表达吗）→ 1990（能 scale out 吗）。
- 暗线是**性能怀疑论三连胜**：每次都是"声明式/通用/单机的慢"被工程证据推翻；
  但 POSTGRES 与 Gamma 各自引入了新代价（复杂度/容错）。"解决一个问题、引入下一个问题"的链条
  正是后面第 3–7 章的组织原理。

## 常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "System R 证明的是关系模型正确" | 它证明的是**优化器+SQL 可以快**；模型的数学正确性是 Codd 的事，两回事 |
| 2 | "POSTGRES 失败了" | 产品线曲折（Illustra→Informix→DB2）+ 开源血脉（PostgreSQL）双活；"败给 SQL 兼容"是过程税，不是终局 |
| 3 | "Gamma 是学术玩具，商用是 Teradata 的事" | 玩具论对，但 MPP 复活的每家厂商的设计文档里都认哈希分区这条血脉 |
| 4 | "三篇讲的都是存储/索引" | 三篇全是**整机架构**论文；红书第 5 版根本没有"存储与索引"专章（任务书预期的 Part 结构是第 3/4 版的） |
| 5 | 把 System R 论文的恢复章节当 ARIES 读 | R 的恢复是镜像表→日志的过渡形态；ARIES 的完整论证在 03 文件 |
