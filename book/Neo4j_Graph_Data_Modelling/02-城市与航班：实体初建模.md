## 一、本章任务：给「旅行」画第一版图

全书第一张真实图只有两种实体：

```cypher
// cities.cqy 开场三件套（✅ 原文）
CREATE CONSTRAINT ON (city:City) ASSERT city.name IS UNIQUE;
CREATE (n:City{name:"Mumbai", country:"India"}) RETURN n;
// ...共 26 城：New York/Chicago/Las Vegas/Los Angeles/Toronto/London/Madrid/Paris/Athens/Rome...
```

设计决策逐条拆：

1. **业务键选 `name` 而不是自建 id**：城市名即主键，配 UNIQUE 约束兜底。⚠️ 隐患作者自己在 Ch.7 暴露——同名/改名场景要靠 `_id`(UUID) 实体（Booking/Hotel/Review 全用 `_id`）；「什么时候用自然键、什么时候用代理键」这条建模线在本章就已埋下。
2. **`country` 先当属性**：`City{... country:"India"}`——国家此刻不值得一个节点。**这正是 Ch.5 将要反悔的第一处**（第二处反悔：Ch.7 把国家升格为 `Country` 节点并进 `SUB_REGION` 层级）。读法记住：**本书的「对错」多数是「时机」**——先属性后实体是成本正确的顺序。
3. **批量 CREATE 一行建多节点**（snippet_3，✅）：`CREATE (:City{...}), (:City{...}), ...`——3.x 无 `UNWIND` 批量段时的标准姿势；输出面 `Nodes created: 8 / Labels added: 8` 这类**统计行**是 shell 给建模者的即时反馈（现代 5.x 同样返回 metrics，✅ 手册模式页）。

## 二、Flight：把「连接」放上的到底是哪一层

```cypher
// flights.cqy 模板（✅ 原文，360 连）
CREATE (flight:Flight {code:"AA9", carrier:"American Airlines", duration:314,
  source_airport_code:"JFK", departure:1300, destination_airport_code:"LAX", arrival:114})
WITH flight
MATCH (source:City {name:"New York"}), (destination:City {name:"Los Angeles"})
CREATE (source)-[:HAS_FLIGHT]->(flight)-[:FLYING_TO]->(destination);
```

- **Flight 是节点不是边**：航班有自己的属性（carrier/duration/起降时刻）与自己的身份（code UNIQUE）→ 实体；「从城市飞抵城市」拆成两段边 `HAS_FLIGHT`→Flight→`FLYING_TO`。判定口诀（本章可归纳，⚠️ 归纳）：**属性有查询价值 → 节点；属性只做描述 → 边或属性**。GD2e 对位表述见 [../Graph_Databases_2e/03-使用图进行数据建模.md](../Graph_Databases_2e/03-使用图进行数据建模.md)。
- **关系类型名携带语义**：`HAS_FLIGHT` 与 `FLYING_TO` 不叫 `REL1`/通用 `CONNECTED_TO`——语义化类型名让 Ch.3 的 `[|]` 交替类型遍历、Ch.8 的推荐模式全部直接可写。#88 TDG 用整章讲同一条纪律（[../Neo4j_The_Definitive_Guide/03-建模：从通用关系到语义关系.md](../Neo4j_The_Definitive_Guide/03-建模：从通用关系到语义关系.md)），两册互证。
- **数据里埋着双份真相**：Flight 同时存 `source_airport_code:"JFK"` 和靠边挂的 `City{name:"New York"}`——机场码是字符串、城市走边。这个**故意保留的冗余**是下一章重构的火种（⚠️ 推定作者教学意图；Ch.5 snippet 2 将把两者调和出 Airport 实体）。

## 三、方向告警：snippet_11 的公开课

```
neo4j-sh (?)$ CREATE (source)-[:HAS_FLIGHT]->(flight)-[:FLYING_TO]-(destination);
Output:
WARNING: Only directed relationships are supported in CREATE (line 1, ...)
```

3.x 起 CREATE 子句拒绝无向关系模式（MATCH 里无向依旧合法——本书后面大量用）。作者把报错原样收进 snippet：建模语义上，**`FLYING_TO` 的箭头方向就是航班方向**，写成无向等于放弃这层信息。现代对应物：Cypher 手册关系方向节 ✅（[./00-总览与阅读地图.md](./00-总览与阅读地图.md) 第十一节 patterns 链接）。

## 四、查询侧：索引先行的即时回报

```cypher
CREATE INDEX ON :City(country);                 // snippet_7
MATCH (c:City{country:"United States of America"}) RETURN c.name;  // snippet_8 → 4 rows
MATCH (source:City {name:"Los Angeles"})-[:HAS_FLIGHT]->(f:Flight)-[:FLYING_TO]->(destination:City {name:"New York"})
RETURN f.code, f.carrier;                       // snippet_14 → "UA1262"/"AA920" 两行
```

- UNIQUE 约束兼做索引、非唯一属性补 `CREATE INDEX`——3.x 两分法在 5.x 演化为统一的 **range index**（✅ https://neo4j.com/docs/cypher-manual/current/schema/constraints/ 说明约束依赖索引）。
- snippet_14 的两跳模式 `(City)-[:HAS_FLIGHT]->(Flight)-[:FLYING_TO]->(City)` 是全书最小「遍历单元」：起点经索引锚定，两跳走邻接，**没有任何一次表级组合**——这句话在 03 章 E2 类比里有关系版的代价对照（🔧，非 Neo4j 行为）。
- `departure:1300 / arrival:114`：时刻用裸整数（114=1:14?）⚠️ 原书未取证到解释，数据可读性存疑——记为本书工程瑕疵：**属性没有单位/格式约定，后面聚合就有暗雷**（Ch.6 的 4 维评分、Ch.8 的回填 `overall_rating` 都在补这课）。

## 五、本章反模式清单（对照 Ch.2 决策归纳，⚠️ 归纳）

- 反模式①：所有东西都建节点。本章 `country` 留在属性——升格要有「要挂边/要独立查询」的理由（Ch.7 才升格）。
- 反模式②：通用关系 + 属性描述边。本章若不写 `HAS_FLIGHT/FLYING_TO` 而用 `[:REL{type:"flight"}]`，Ch.3 的类型交替遍历将退化为全路径过滤。
- 反模式③：无约束裸建。26 城同名一次，后面所有 `MATCH {name:...}` 锚定全部歧化——约束先行是本书每章第一句的物理原因。

## 核心概念速览（中英对照）

- **自然键 vs 代理键** — Natural vs Surrogate Key：City 用 name、Booking 用 UUID `_id` 的分寸感，本章埋线。
- **事件实体化** — Entity vs Edge 判定：属性有独立查询价值才升节点（Flight 有 code/时刻 → 节点）。
- **语义化关系类型** — Semantic Relationship Type：`HAS_FLIGHT`/`FLYING_TO` 替代通用边，让模式语言直接可写。
- **唯一性约束** — Uniqueness Constraint：`ASSERT city.name IS UNIQUE`（3.x 旧式），兼做索引。
- **范围索引** — Range Index：`CREATE INDEX ON :City(country)`，非唯一属性锚点。
- **有向创建纪律** — Directed CREATE：3.x 拒绝对 CREATE 写无向关系（snippet_11 WARNING 实证）。
- **锚点-遍历二段式** — Anchor & Expand：属性 MATCH 走索引定锚点，其后全部邻接扩展（snippet_14 形态）。
- **批量 CREATE** — Batched CREATE：一行多节点，`Nodes created: 8` 统计行即时反馈。
- **冗余双写** — Denormalization Debt：`source_airport_code` 与 City 边并存，Ch.5 重构的火种。
- **约束先行** — Constraint-First Loading：建约束→建索引→后导数，本书 12+ 章 snippet 的共同开场。

## 最新演进与工业实践

- **语法换代**（✅ 均 200，见 00 第十一节清单）：旧式 `CREATE CONSTRAINT ... ASSERT n.k IS UNIQUE` → `... REQUIRE n.k IS UNIQUE`；`CREATE INDEX ON :L(p)` → `CREATE INDEX ... FOR (n:L) ON (n.p)`；类型交替遍历 `[():L1|L2]` 的语法族由手册 patterns 页维护。
- **建数方式的代际**：2016 年手写 `.cqy` 全量 CREATE（本章 flights.cqy 28.7KB）→ 2020s 标准姿势 `LOAD CSV ... CALL { ... } IN TRANSACTIONS`（对位 [../Neo4j_The_Definitive_Guide/02-数据导入与批量加载.md](../Neo4j_The_Definitive_Guide/02-数据导入与批量加载.md)）与 `neo4j-admin database import` 盲导；Aura 上则走 Bulk Import/Batch API ⚠️（auradb 产品页转述）。
- **时刻属性教训的现代解**：裸整数时刻应存 ISO 8601 字符串或 epoch-millis 并在建模文档定契约；5.x 类型系统仍无原生 timestamp-on-property 校验，社区实践靠约束+应用层 ⚠️。
- **工业模式沉淀**：本章「City-Flight-Airport」原型即公开语料常引的 **transit/travel 参考模型**；Neo4j 官方示例库与 GraphAcademy Data Modeling 课（✅ https://graphacademy.neo4j.com/courses/data-modeling/ ）沿用同型案例——2016 年的教学域已成入门标准域。
