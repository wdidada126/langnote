## 一、Category：第三类「软事实」进场

```cypher
// snippet_1/2/3（✅）
CREATE CONSTRAINT ON (c:Category) ASSERT c.name IS UNIQUE;
CREATE (c:Category{name:"Streets", description:"Cities where there is a rich street art, street food etc."});
MATCH (n:City{name:"Mumbai"}), (c:Category{name:"Cosmopolitan Hotspot"}) CREATE UNIQUE (n)-[:KNOWN_FOR]->(c);
```

- 城市风味标签=**受控词表节点 + 多对多 `KNOWN_FOR`**：对比「直接 `City{tags:["Streets",...]}`」——词表要描述、要复用、要和用户行为做共现，属性数组装不住（⚠️ 归纳；3.x 数组属性其实可用，但「按 Category 反查城市+按城市反查 Category」双向遍历正是数组索引给不了的）。
- `CREATE UNIQUE`  again（本册死语法清单+1，⚠️ 5.x 迁移注意，见 Ch.7 演进节同条）。
- snippet_4 的「去重中转站」手艺值得单摘：`FILTER(airport IN airports WHERE 1=LENGTH(FILTER(a IN airports WHERE a=airport)))` ——**列表函数手写「只出现一次」过滤器**，把经停/转机重复到达的机场剔掉再映射成「真正到过的城市」。3.x 无 `apoc.collections` 时代的纯 Cypher 内功（⚠️ 现代建议 APOC/推导式重写）。

## 二、推荐线：相似度全部来自共现，零预计算

```cypher
// snippet_8（✅ 骨架）：相似旅伴住过、且挂在伊斯坦布尔机场下的酒店
MATCH (user:User{email:...})-[:WROTE]->(:Review)-[:FOR_HOTEL]->(stayed:Hotel)<-[:FOR_HOTEL]-(:Review)<-[:WROTE]-(other_traveller:User)
WHERE NOT other_traveller = user
MATCH (other_traveller)-[:WROTE]->(:Review)-[:FOR_HOTEL]->(hotel)<-[:HAS_HOTEL]-(airport:Airport{code:"IST"})
RETURN DISTINCT hotel.name, COLLECT(DISTINCT other_traveller.name), COUNT(DISTINCT other_traveller)...
// snippet_10 再叠 SUM(overall_rating)/COUNT(DISTINCT other) 排序；snippet_11 用 MAX(住过的最高价) 当预算闸门
```

- **item-CF 的一跳声明式**：「和我评论过同酒店的人 → 他们评论过的目标城市酒店」——模式即算法，没有相似度矩阵、没有离线作业（snippet_5 城市版同理走 `KNOWN_FOR` 共现；snippet_7 用 `BELONGS_TO*1..` 沿 Ch.7 品牌层级找「同集团」推荐——**层级一跳，推荐语义多一档**）。
- 排序键的演进闭环：Ch.6 读时 REDUCE 平均 → **snippet_9 `MATCH (review:Review) SET review.overall_rating = toFloat(vfm+food+comfort+service)/4`（`Properties set: 159` ✅）** → snippet_10 直接消费——**从读时聚合到写时物化的教科书转身**，159 这个数字与 Ch.6 体量证据互咬。
- snippet_12/13/15 行为分析三件套（`booking.month` 出票分布 12月:7、个人出行季、行程旺季 1月:7）：**全靠 Ch.4 的 year/month 冗余拆列**——当年的存储换计算这笔账，在本章全额兑付（现代改写走 temporal 函数，见演进节；两版各有账，⚠️ 归纳）。
- 局限自白（⚠️ 归纳）：共现推荐冷启动弱、无权重衰减（相似旅伴与目标酒店同分看待）、`DISTINCT`+`COLLECT` 大集合时内存型爆——**玩具规模优雅 ≠ 生产规模优雅**，工业代位是 GDS 相似/中心性算法与向量召回（终章演进节）。

## 三、🔧 多对多爆炸实测：把「相似旅伴」自连接跑在 SQLite/DuckDB 上（**非 Neo4j 行为**）

exp.py E1/E6：800 用户×150 酒店×12,000 评论（`reviews(uid,hid)` 双索引），复现 snippet_8 的共现骨架 `r1 JOIN r2 ON r1.hid=r2.hid WHERE r1.uid=? AND r2.uid<>?`（seed=42）：

| 观测 | 数字 |
|---|---|
| 单个普通用户的共现对（uid=7） | **16,477 对 / 1.02ms**（SQLite） |
| 其中来自超级酒店#1（4,000 条评论） | **15,984 对 = 97%** |
| 限定 hid=1 的坏执行序版本 | **1,204ms**（同语义，索引序不同，×1000+） |
| DuckDB 1.5.5 同查询 | 16,477 对 / 3.11ms（向量化不吃亏也不占便宜） |

三读数：①**共现的中间积由度分布决定**——一条 god node 边就贡献 97% 组合，与 🔧 E3（28.4% 二跳过枢纽）同根：**图分析的隐形税单写在度分布上**，Neo4j 用遍历器策略消化（⚠️ 转述）、SQL 用 JOIN 顺序消化（🔧 实测 1ms vs 1.2s）。②图侧「省组合数」是语义层的（trail/邻接），不是魔法常数——E6 给出诚实对照。③生产上 snippet_8/10 这类查询**必须加 LIMIT/度上限**，玩具图 12k 行无感，真实点评站单酒店 40 万评论时按 E1 曲线推：千万级对起步（⚠️ 外推声明）。

## 核心概念速览（中英对照）

- **受控词表** — Controlled Vocabulary：Category 节点+描述，替代自由 tags 字符串。
- **共现推荐** — Co-occurrence/CF Recommendation：`(:Hotel)<-[:FOR_HOTEL]-(:Review)` 两跳反向声明 item-CF。
- **软事实层** — Semantic Overlay：KNOWN_FOR/CAN_ACCESS 等「观点/规则」边与硬结构层分离。
- **读时→写时物化** — Materialize-on-Write：`overall_rating` 回填（Properties set: 159）终结 Ch.6 的每查重算。
- **列表函数内功** — Pure-Cypher Set Ops：`FILTER(x IN xs WHERE 1=LENGTH(FILTER(...)))` 手写去重。
- **时间拆列兑付** — Denormalized Time Payoff：month 分布分析直接吃 Ch.4 冗余列。
- **度分布税** — Degree-Distribution Tax：god hotel 贡献 97% 共现对（🔧 E1）。
- **组合爆炸防线** — Traversal Guardrails：DISTINCT/LIMIT/度上限/上界跳数（🔧 E2 同族）。
- **预算闸门推荐** — Budget-Anchored Filter：MAX(已住价) 当目标酒店价格上界（snippet_11）。
- **三层图叙事** — Structure/Behavior/Semantics Layers：终章对全书构件的功能归类（⚠️ 归纳）。
- **预计算暗线** — Materialization Arc：overall_rating/AccessGroup/Category 三处读时→写时，贯穿后四章。

## 最新演进与工业实践

- **语法**：`tofloat()`→`toFloat()`；回填作业改 `CALL{...} IN TRANSACTIONS` 分批（✅ https://neo4j.com/docs/cypher-manual/current/patterns/ 及 TDG Ch.2 对位章）；「只出现一次」过滤器现代可写列表推导/`size()` 或 APOC ⚠️。
- **month 冗余列的退役**：5.x `datetime.month`、`date.trunc('month', ts)` 原生可得，snippet_12/13/15 三查询可去冗余直算 ⚠️（函数名以手册为准，未逐一机检）。
- **推荐线产品化**：模式内共现 → **GDS nodeSimilarity/社区发现/路径打分**（✅ https://neo4j.com/docs/graph-data-science/current/ ）→ 2024+ **向量索引 + 图拓扑混合召回**（✅ https://neo4j.com/docs/cypher-manual/current/indexes/semantic-indexes/vector-indexes/ ）：本书 snippet_8/10 的「相似旅伴」在 GraphRAG 时代的同族是「相似实体」，embedding 管语义相似、边管结构证据（完整工程化见 [../Neo4j_The_Definitive_Guide/13-向量检索、LLM摘要与混合推荐.md](../Neo4j_The_Definitive_Guide/13-向量检索、LLM摘要与混合推荐.md)）。
- **冷启动与权重**：工业推荐普遍离线训练+在线图查证据的混合架构，纯模式共现退守中小规模与解释性场景 ⚠️（行业转述）；本册 159 条评论+公开仓库（✅ maheshlal2910/neo4j_graph_data_modelling）作为「可重放的最小推荐图」至今是教学资产。
