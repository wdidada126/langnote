# Ch.7 区域层级与访问组安全建模：一张图两套权限（✅ 仓库最重章）

> **证据声明**：英文原题未取得 ⚠️。`chapter_7/` 为全书文件最多的章：16 个 snippet + 5 个 for_reader 脚本（`regions.cqy`/`hotel_chains.cqy`/`accor_subsidiary_hotels_access_groups.cqy`/`accor_access_groups.cqy`/`employees.cqy`）✅ 全量实抓。本章做两件事：**地理层级化**（把 Ch.2 的 country 字符串债还清）与**权限图形化**（AccessGroup 模式）。

## 一、还债：Country 从属性升格为节点

```cypher
// snippet_1/2（✅）
CREATE CONSTRAINT ON (country:Country) ASSERT country.name IS UNIQUE;
MATCH (city:City) WITH city
MERGE (country:Country{name: city.country})
WITH country, city
MERGE (country)-[:SUB_REGION]->(city);
// snippet_3/4：Region{name:"North America"}-[:SUB_REGION]->(Country)...
```

- 与 Ch.5 Airport 完全同款的「MERGE 派生实体」，**同一个关系类型 `SUB_REGION` 贯穿 城市⊂国家⊂大洲 三层**——层级语义用一种边型+递归消化，不加 `IN_COUNTRY`/`IN_CONTINENT` 三种边（对照 Ch.2 语义化类型纪律：语义相同就复用，⚠️ 归纳）。
- snippet_6 的多标签手术：`MATCH (city:City),(country:Country) SET city :Region, country :Region`（`Labels added: 26`）——**Region 成为「层级节点」的公共接口**，snippet_9 的路径报表因此能按标签拆列：`EXTRACT(node in FILTER(n in NODES(p) WHERE "Region" IN LABELS(n))| node.name)`。⚠️ 批评位：City/Country 同名追加 Region 后，`(:Region)` 查询混装两层粒度；多标签当接口用要防「标签语义稀释」（归纳评论）。
- snippet_5/9 的路径形态 `(Region)-[:SUB_REGION*1..]->(City)-[:HAS_AIRPORT]->(Airport)-[:HAS_HOTEL]->(Hotel)-[:BELONGS_TO]->(HotelChain)`：Ch.2–6 全部构件在这一条模式里合龙——**全书到中点交出一张集成图**。

## 二、AccessGroup：把行级安全写成图

```cypher
// snippet_11（✅ 原文）：给「Ibis 的欧盟酒店们」发一个可继承的通行证
MATCH (region:Region{name:"European Union"})-[:SUB_REGION*0..]->(:City)-[:HAS_AIRPORT]->(airport)-[:HAS_HOTEL]->(hotel)-[:BELONGS_TO]->(chain:HotelChain{name:"Ibis Hotels"})
WITH hotel, chain
MERGE (accessGroup:AccessGroup{_id:"089cd024-..."}) ON CREATE SET accessGroup.name="European Union"
CREATE UNIQUE (chain)-[:HAS_ACCESS_GROUP]->(accessGroup)-[:CAN_ACCESS]->(hotel);
// snippet_14：员工=链条上的另一类节点
CREATE UNIQUE (chain)<-[:EMPLOYED_BY]-(employee)-[:MEMBER_OF]->(euAccess);
// snippet_15：某员工可访问的全部酒店，一条遍历
MATCH p = (chain)<-[:EMPLOYED_BY]-(employee:Employee{_id:17812})-[:MEMBER_OF]->(:AccessGroup)-[:CAN_ACCESS*0..]->(hotel)-[:BELONGS_TO]->(hotelChain)
```

模式拆解（⚠️ 归纳为通用名）：**RBAC 的图化身**——角色=AccessGroup 节点、授权=CAN_ACCESS 边、成员=MEMBER_OF 边、作用域挂在数据侧（chain→group）。`*0..` 让「总组的组」可继承（snippet_12：Accor 母公司收编各子公司 AccessGroup，`accor_access_groups.cqy` ✅）。要点：

1. **权限判定从「应用层拼 WHERE」变成「一次遍历可达性」**——snippet_16 换员工 id 即另一份权限视图，规则数据化。
2. 对照 #88 TDG：其 Ch.6 讲**引擎内建 RBAC**（用户/角色/子图权限，5.x 语义），本册讲**应用层域权限的图式建模**——两层各管各的，互为需求侧/实现侧（[../Neo4j_The_Definitive_Guide/06-数据库安全.md](../Neo4j_The_Definitive_Guide/06-数据库安全.md)；GD2e 的 RBAC 用例对位 [../Graph_Databases_2e/05-现实世界中的图.md](../Graph_Databases_2e/05-现实世界中的图.md)）。
3. `CREATE UNIQUE`（snippet_11/12/14 ✅）：3.x 的「关系基数唯一性」声明（每 chain 对一个 group 只一条边）——**5.x 已移除，代之以应用层 MERGE 或键约束策略** ⚠️ 迁移需查手册，这是本册最危险的死语法之一。
4. 层级即数据（EU 既是大区又是权限域）：`regions.cqy` 里 EU 与 North America 并列，Accor 场景把「欧盟」同时用作地理与合规边界——**同一节点承担两种语义是图建模的省钱术也是雷**（⚠️ 归纳）。

## 三、🔧 关系式类比两组（SQLite 3.45.3，seed=42，**非 Neo4j 行为**）

**E3 枢纽/超级节点**（本章层级+机场枢纽的代价面）：人为加密后（300 随机边+60 条伦敦辐射边，360 总边）：

| 观测 | 数字 |
|---|---|
| London 度（出+入） | 81 / 360 边的 22.5% 端点份额 |
| 2 跳路径总数 | 5,771 |
| 其中中转 London | **1,640（28.4%）** |

→ 路径计数类查询被枢纽主导：图上一条「随便两跳」的流量近三成路过同一节点——god node 的读放大雏形（生产对策：拆标签/限流遍历/热点实体外移，⚠️ 转述自厂商调优语料，对位 TDG Ch.5 的 god node 讨论 [../Neo4j_The_Definitive_Guide/05-Cypher查询调优与执行计划.md](../Neo4j_The_Definitive_Guide/05-Cypher查询调优与执行计划.md)）。

**E5 层级展开：递归 CTE vs 物化闭包**（本章 `SUB_REGION*1..` 的关系侧镜像）：2,000 节点区域树（自根可达 977）：

| 方案 | 耗时 | 本质 |
|---|---|---|
| 读时递归 CTE 展开 | 0.76ms | 每查询重走树 |
| 写时物化 closure 表+索引计数 | **0.05ms** | 预计算换读速，写时维护 O(深度) 行 |

→ Neo4j 的免索引邻接两头占：不预存闭包（无写放大）而读时不走 JOIN——但**深度大、度大时遍历成本回归 E3 的枢纽曲线**，closure 思想在图侧对应「预计算传递边」的老手艺（⚠️ 定性；理论代价模型 [../Graph_Databases_2e/06-图数据库的内部结构.md](../Graph_Databases_2e/06-图数据库的内部结构.md)）。

## 四、本章反模式清单（⚠️ 归纳）

- 反模式⑭：**权限规则写死在查询谓词里**——AccessGroup 的存在就是为了把 `WHERE region IN (...)` 升为可遍历数据。
- 反模式⑮：**一种边型包打所有层级**复用是省，粒度混装（City=Region）是债——上线前给「标签当接口」的用法配命名规约。
- 反模式⑯：**无视枢纽度**：任何 `*1..n` 先测度分布（🔧 E3 的方法即最小检测）。
- 反模式⑰：**依赖 CREATE UNIQUE 护基数**：死语法（第二节第 3 点），迁移 5.x 必排查。

## 核心概念速览（中英对照）

- **传递层级边** — Homogeneous Hierarchy Edge：`SUB_REGION` 一种类型贯穿 City/Country/Region 三层。
- **标签即接口** — Label as Interface：多标签 `:Region` 让路径报表按类拆列（`Labels added: 26` 实证）。
- **访问组模式** — Access Group Pattern：角色=节点、授权=`CAN_ACCESS` 边、成员=`MEMBER_OF`，行级安全图形化。
- **权限继承** — Inherited Access：`CAN_ACCESS*0..` + 母组挂子组（Accor 收编 Ibis 组）。
- **数据化规则** — Rules as Data：授权判定由拼 WHERE 变遍历可达性。
- **CREATE UNIQUE（已死）** — Deprecated Cardinality Guard：3.x 关系唯一性声明，5.x 移除 ⚠️。
- **枢纽节点度** — Hub Degree/God Node：28.4% 二跳路径过 London（🔧 E3）。
- **闭包表** — Closure Table：层级读速 0.05ms vs 递归 0.76ms 的预计算方案（🔧 E5）。
- **合规地理同体** — Region-as-Compliance：EU 同作地理节点与权限域。
- **集成图验收** — Integrated Graph Milestone：Ch.2–6 构件在本章一条路径模式合龙。

## 最新演进与工业实践

- **权限双层论的 2025 版**：引擎层 RBAC（✅ https://neo4j.com/docs/cypher-manual/current/schema/ 权限相关章节经 cypher-manual 入口可达；TDG Ch.6 已机检）+ 应用层图式授权仍并存；本册 AccessGroup 属后者，厂商称「authorization graph」模式家族 ⚠️ 转述。
- **`CREATE UNIQUE` 迁移**：5.x 无直接替代（约束只管节点属性唯一性），基数控制回落到 MERGE/应用校验——迁移本册代码时的必查死语句 ✅（约束手册页无此语法，200 ✅ 反证）。
- **god node 治理工业做法**：热点实体拆分（如把超级机场按航站楼/时段分片）、变长模式限流、读缓存旁路 ⚠️（TDG Ch.5 与厂商调优语料转述，无独立机检）。
- **KG/合规建模回潮**：区域层级+访问组的思路在 2020s 以「数据主权/区域合规（GDPR 数据驻留）」形态重现于知识图谱与治理建模，知识图谱权限子图是 RAG 平台标配议题 ⚠️（行业叙事转述；GQL 标准对属性/子图权限未覆盖，见 00 第十一节 GQL 附录链接）。
