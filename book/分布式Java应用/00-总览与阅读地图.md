## 版本演进时间轴

- **2010-06**：本书第一版出版。背景是淘宝从单体 Java 应用向「服务化 + 分布式」转型，
  作者当时负责淘宝服务框架（HSF 前身思路），每天承担百亿级服务调用。
  SOA、ESB、SCA 是当时业界主流话语；JDK 6 是主流版本，JVM 调优围绕 HotSpot（Sun JDK）。
- **2011–2014**：微服务概念由 Martin Fowler 与 James Lewis 在 2014 年正式提出，
  直接冲击本书第 2 章的「SOA/ESB/SCA」叙事——微服务主张**去中心化、轻量协议、独立部署**，
  与 ESB 的「中心化总线」哲学相反。
- **2014–2016**：容器化（Docker 2013、Kubernetes 2014）与云原生兴起，
  本书第 6–7 章的「去单点/负载均衡/水平伸缩」被 Kubernetes 的 Service + Deployment + HPA 原生接管。
- **2016–2020**：Service Mesh（Istio 2017、Envoy）将「通信/服务治理」从应用层下沉到 sidecar，
  本书第 1 章手写通信、第 2 章 ESB 治理的很多内容被基础设施吸收。
- **2020–2026**：gRPC（HTTP/2 + Protobuf）成为跨语言 RPC 事实标准；
  Dubbo 3 转向应用级服务发现与 Triple 协议；Spring Cloud 体系成熟又面临「微服务过重型」反思；
  GraalVM 原生镜像、虚拟线程（Project Loom，JDK 21）改写本书第 3–4 章的并发与启动假设。

## 阅读顺序建议

- **主线 A（按书读）**：01 → 02 → 03 → 04 → 05 → 06 → 07。
  原书结构即因果链：「先讲通信与 SOA（1–2）→ 再讲 Java 底层机制与类库（3–4）
  → 然后讲调优与架构目标（5–7）」。
- **主线 B（按问题读）**：
  - 「系统间怎么通信」：01（→ 深入理解Apache Dubbo 补现代 RPC）；
  - 「服务怎么治理」：02（→ 微服务架构设计模式 / 未来架构 补修正）；
  - 「JVM 与类库底层」：03 → 04（→ 深入理解Java虚拟机3 / 实战Java高并发）；
  - 「上线前调优」：05（→ 深入理解Java虚拟机3 的 GC 章）；
  - 「高可用/可伸缩架构」：06 → 07（→ 大型网站技术架构 / 未来架构）。
- **对照读**：每章末尾「与其他章 / 其他书的联系」都给了对读目标；
  建议读第 2 章前先跳读《微服务架构设计模式》，读第 3–4 章前先跳读《深入理解Java虚拟机3》。
