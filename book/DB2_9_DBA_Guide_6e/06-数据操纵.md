# 06 · Manipulating Database Objects（Ch6 · DML 与数据移动三件套）

> 章名 ✅ InformIT 出版社页实抓；正文 ⚠️ 转述重构；示意语法非实测。

## 一、章定位

数据操纵章走两条线：SQL 线（INSERT/UPDATE/DELETE/MERGE/游标）与工具线（LOAD/IMPORT/EXPORT）。DB2 把"大批量数据进库"做成 DBA 核心技能而非应用副作用——LOAD 的旁路引擎与不可恢复挂起态是本章与 12/13 章的联动枢纽，也是 731 认证高频域。

## 二、SQL 线要点（⚠️ 转述）

1. INSERT：VALUES/SELECT 双形态；多行 INSERT（9.7+，⚠️ 版次存疑）；`NEXTVAL FOR seq` 取值。
2. UPDATE/DELETE 定位：`WHERE CURRENT OF cursor` 与游标 `FOR UPDATE OF cols` 配套；`OPTIMIZE FOR n ROWS` 计划偏置。
3. MERGE：`MERGE INTO ... USING ... WHEN MATCHED THEN UPDATE ... WHEN NOT MATCHED THEN INSERT`——数件装载与 SCD 的样板。
4. 游标四属性对话：SENSITIVITY（静态/动态）、HOLD（跨提交保游标，配合 RS/RR）、SCROLL、UPDATE OF。
5. 隔离级在 DML 的体现：CS 默认游标锁语义、UR 脏读许可——深水区全部推给 10 章。
6. 子查询与集合运算：UNION ALL/INTERSECT/EXCEPT、相关子查询、`FETCH FIRST n ROWS ONLY`（DB2 的 LIMIT 方言，长期特色）。

## 三、EXPORT/IMPORT（工具线第一段，⚠️ 转述）

- `EXPORT TO data.ixf OF IXF MESSAGES msg SELECT ...`：只出不入，IXF 保 DDL 信息。
- `IMPORT FROM data.ixf OF IXF INSERT/REPLACE/REPLACE_CREATE INTO t`：走 SQL 引擎，约束/触发器全生效、全记日志、可回滚；慢但安全。
- 格式族：IXF（DB2 原生含元数据）/DEL（纯分隔符）/WS/CARD（冷门不展开）。
- 选项：`COMMITCOUNT n BUFFER n` 控制事务粒度与内存，大表导入的吞吐旋钮。

## 四、LOAD 深读（工具线第二段，本章重头，⚠️ 转述）

1. 旁路 SQL 引擎直接写页；六阶段：LOAD→BUILD→DELETE（索引重建法）→STATS（可选）→INDEX_LOAD。
2. 模式：INSERT/REPLACE/RESTART/TERMINATE；RESTART 借 staging/userlog 续载（⚠️ 机制名存疑）。
3. `NONRECOVERABLE`：跳过日志 → 表空间进 **LOAD IN DOUBT / SET INTEGRITY PENDING**，必须再全量备份或 `LOAD ... REPLACE` 补救（13 章呼应）。
4. `MARKING INACTIVE/DROP PENDING`：坏行落异常表（`FOR ERROR`）的裁决语法。
5. `ALLOW_WRITE/ALLOW_READ`：并发可用性档位；与 10 章锁语义联动。
6. 锁与日志对比表（IMPORT vs LOAD）：约束校验/触发器/可回滚/日志量/索引维护方式/速度六维。

## 五、完整性与装载裁决

- LOAD 对唯一索引违例：`DUPKEY(CONTINUE|STOP)` 修饰 + 异常表；外键违例 `FKCONSTR/FKWARNING`（⚠️ 修饰词拼写以现行文档核）。
- `SET INTEGRITY`：激活约束的表态修复（LOAD/attach 分区后必用）。
- 大装载 SOP：先 DROP 非唯一索引→LOAD→CREATE INDEX→RUNSTATS→（若 nonrecoverable）立即备份。

## 六、命令速查卡（示意，非实测）

```text
db2 "MERGE INTO tgt USING src ON ... WHEN MATCHED THEN UPDATE SET ... WHEN NOT MATCHED THEN INSERT (...)"
db2 EXPORT TO /tmp/cust.ixf OF IXF MESSAGES /tmp/exp.msg SELECT * FROM cust
db2 IMPORT FROM /tmp/cust.ixf OF IXF COMMITCOUNT 10000 REPLACE INTO cust
db2 LOAD FROM /tmp/big.ixf OF IXF REPLACE INTO bigtab \
     MARKING INACTIVE 1 2 NONRECOVERABLE COPYNO 1 COPY1 /mnt/bk1
db2 "LOAD QUERY /tmp/big.ixf CUST"
db2 "SET INTEGRITY FOR bigtab IMMEDIATE CHECKED"
db2 "BACKUP DATABASE demo ONLINE TO /mnt/bk1"   # 补救挂起态（接 13 章）
```

## 七、易错雷点（例题库精华）

1. LOAD 中终端被 kill → 表挂 LOAD IN DOUBT：`LOAD ... TERMINATE` 或回滚恢复。
2. IMPORT REPLACE 触发依赖删除失败（外键）→ 顺序与视图遮蔽。
3. 忘记 MESSAGES 文件 → 百条 SQL3195N 警告无处可寻。
4. UR 隔离下"读空表"错觉：未提交装载可见性（→10 章）。
5. 自动存储库中 LOAD 指定容器路径与路径池打架（→11 章）。
6. IXF 跨平台 codepage 隐式转换乱码（→15 章数据转换）。

## 九、LOAD 修饰词深读（⚠️ 转述，拼写以现行文档核）

| 修饰/子句 | 作用 | 常见误用 |
|---|---|---|
| `MODIFIED BY DAMP n` | 写页缓冲页数以降 I/O | 调过大反伤内存 |
| `MODIFIED BY CPU_PARALLEL n` | 解析/格式化并行度 | 与索引并行混淆 |
| `MODIFIED BY USE LOAD PATH` | 读端共享内存加速（AIX/HP 系 ⚠️） | 平台不符静默忽略 |
| `ERROR n` | 容忍坏行数上限 | 超限即 Terminated 全弃 |
| `WARNING n` | 可恢复警告上限 | 与 ERROR 语义混记 |
| `STATS YES USE CURRENT` | 载后统计策略（接 12 章） | NO 忘补 RUNSTATS |
| `COPY NO/YES + COPY1/2` | 数据副本直写（接 11 章） | 与备份概念混 |
| `CPU_PARALLEL+DISK_PARALLEL` | 索引构建并行组合 | 小表过度并行反慢 |

- 读法：每行都能独立成为 731 选择题题干；组合记忆锚点是"六阶段流水线"（第四节第 1 条）。

## 核心概念速览（中英对照）

- **IXF/DEL** — 集成/定界格式：DB2 数据交换文件格式族
- **LOAD** — 装载：旁路 SQL 引擎的高速入库工具
- **IMPORT** — 导入：走 SQL 引擎的可回滚入库
- **EXPORT** — 导出：查询结果落文件
- **REPLACE/RESTART/TERMINATE** — LOAD 模式：清表重灌/续载/中止
- **NONRECOVERABLE** — 不可恢复装载：跳过日志致恢复链断
- **LOAD IN DOUBT** — 挂起态：中断后等待裁决的表状态
- **exception table** — 异常表：坏行归宿（FOR ERROR）
- **SET INTEGRITY** — 完整性激活：约束态修复命令
- **MERGE** — 合并语句：匹配则改不匹配则插
- **WHERE CURRENT OF** — 游标定位 DML：按当前行更新/删除
- **WITH HOLD** — 跨提交游标：保持游标过 COMMIT
- **FETCH FIRST n ROWS ONLY** — 前 n 行：DB2 版 LIMIT

## 最新演进与工业实践

- 工具线延续：Db2 11.5/12 的 LOAD 增加 **ONLINE 非中断 RESTART、COPY NO/COPY 1 多副本直写、分区表并行 LOAD**；SMS/IXF 仍存活但 DEL/CSV+外部管道成主流（⚠️ 转述；入口 ✅ https://www.ibm.com/docs/en/db2 ）。
- 云化：Db2 on Cloud/Db2 Warehouse 用 LOAD/EXPORT 的 API 化变体与外部存储（Cloud Object Storage）联动；传统 db2load 命令面在托管实例收缩（⚠️）。
- 概念迁移：MERGE/装载断链补救是跨引擎通识——Snowflake COPY INTO、Redshift COPY 的失败态处理同构（对照 [../Amazon_Redshift_TDG/00-总览与阅读地图.md](../Amazon_Redshift_TDG/00-总览与阅读地图.md)）。
