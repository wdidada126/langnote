# 02 · Getting Started（Ch2 · 实例与数据库的两级世界）

> 章名 ✅ InformIT 出版社页实抓；正文 ⚠️ 转述重构。DB2 不可本机实测，所有命令语义以 IBM 公开文档口径转述。

## 一、章定位

本章回答"装完之后先干什么"：实例（instance）的创建与生命周期、数据库的创建、命令行处理器 CLP 的三种形态，以及 DB2 特有的"环境变量+注册表"配置双轨。它是 11/12/13 章全部管理动作的地基。

## 二、安装与实例模型（⚠️ 转述）

1. 二进制与实例分离：先装产品代码（SWDIR 目录），再 `db2icrt -p <port> <instname>` 建实例。
2. 每实例一个所有者用户（instance owner）+ 所属组；SYSADM 组决定谁管实例。
3. Windows 上实例表现为服务（DB2 - DB2COPY1 - <inst>），UNIX 上为一组进程+共享内存段。
4. 多实例共存是常态设计：`db2ilist` 枚举；`db2stop` 全部实例后可卸补丁。
5. 实例目录（INSTALL 下 sqllib 等）与节点拓扑文件 `db2nodes.cfg`（DPF 才有意义，见 11 章）。

## 三、CLP 与配置双轨（⚠️ 转述）

- CLP 三态：命令行一次性 `db2 "SQL"`；交互 `db2 =>`；脚本文件 `db2 -tvf x.db2`（-t 分隔符 -v 回显 -e 报错续跑组合习惯）。
- 双轨配置：
  - DBM/DS 配置参数：`db2 update dbm cfg using ...`（实例级）与 `update db cfg for ...`（库级），持久化于 cfg 文件。
  - 注册表变量（registry）：`db2set -g` 读、`db2set DB2_COMPATIBILITY_VECTOR=...` 写，影响引擎行为开关。
- 环境变量：`DB2INSTANCE` 决定 `db2` 命令连到哪个实例——多实例机器上"命令跑错实例"的头号事故源。
- CLP  Plus 与 Windows 控制中心（图形面，9 时代存在，现已消亡 ⚠️）。

## 四、建库第一课（示意命令，非实测）

```text
db2 create database demo on /dbdata automatic storage yes \
  pagesize 16 bufferpool 16k 2000 default bufferpool 16k \
  codepage 1386 collate using identity territory en_US.CA
db2 connect to demo
db2 "select tabschema, tabname from syscat.tables" 
```

- `automatic storage yes`：9.1 新客默认，路径池托管容器（对比手工 DMS，见 11 章）。
- pagesize/codepage/collate 建库即定，事后改代价极高——DBA 决策点前移的教科书案例。
- `SYSIBM.SYSDUMMY1` 探活；SYSCAT/SYSIBM 双目录视图（SYSCAT 为 9 起推荐面，⚠️ 迁移细节转述）。

## 五、SAMPLE 库与学习闭环

- `db2sampl` 生成带员工/部门/产品的演示库，供后续章实验；附录 B 的 DB2DEMO 安装即其加强版（见 16 文件）。
- 学习循环模板：connect → 对象 DDL → 数据 LOAD/INSERT → snapshot 观察 → disconnect。
- 与兄弟教材对照：MySQL_8_Administrators_Guide 从"初始化 datadir"讲起；DB2 把等价步骤拆成 装码/建实例/建库 三段，纪律差异源自大机传统。

## 六、常见初学陷阱（本章例题库向）

1. 用 root 直接跑 `db2`——实例所有者才能建实例；root 只该做安装。
2. `db2start` 报共享内存错误——残留 IPC 段，`ipclean` 习惯动作（UNIX，⚠️）。
3. 连接串写了库名但没 catalog——"SQL30061N database not found"，去 03 章目录机制解决。
4. 改 `DB2INSTANCE` 后所有 `db2 get dbm cfg` 换了对象——实例错觉。
5. 授权失败误判 bug——SYSADM 组成员资格未刷新（登录会话携带组列表）。
6. Windows 服务账户改了密码——实例起不来，服务属性同步是运维规程。

## 八、命令速查卡（示意，非实测，⚠️）

```text
db2ilist / db2stop / db2start
db2icrt -a server -p svc_name inst        # 建实例
db2idrop inst                              # 删实例（须先停）
db2 get dbm cfg | more                     # 实例参数
db2 update dbm cfg using SYSADM_GROUP grp
db2 get db cfg for demo
db2 update db cfg for demo using LOGBUFsz 512
db2set -l / db2set -g / db2set DB2MEMMAXFREE=...
db2 "values special registers"             # 会话环境自测
db2 terminate                              # 收掉本终端后台 CLI 进程
db2 level / db2licm -l                     # 许可查看
```

- 读法：左列动作对应正文小节——实例生命周期（二）、双轨配置（三）、建库（四）。

## 九、DB CFG 首屏参数深读（⚠️ 转述）

1. `PAGESIZE`/`CODEPAGE`/`TERRITORY`：建库定终身三件套，改=重建+迁移。
2. `DFT_EXTENT_SZ` 等空间参数：自动存储下大量转交表空间级（11 章接管）。
3. `LOGINDEXES/LOGBUFSZ`：日志缓冲与写序基调，恢复章（13）的输入变量。
4. `AUTO_RUNSTATS/AUTO_REORG/AUTO_BACKUP`：9.1 自维护开关，12 章展开。
5. `LOCKLIST/MAXLOCKS`：锁内存配额，10 章展开——建库默认值常是中型系统第一颗雷。

## 核心概念速览（中英对照）

- **实例** — Instance：进程/内存/端口级的 DB2 服务容器，一实例多库
- **实例所有者** — Instance Owner：拥有并启动实例的 OS 用户
- **SYSADM 组** — System Administrator Group：实例级管理员 OS 组
- **CLP** — Command Line Processor：SQL 与管理命令交互壳
- **db2icrt** — Create Instance：实例创建命令（Windows 走图形向导亦可）
- **DBM CFG** — Database Manager Configuration：实例级参数集
- **DB CFG** — Database Configuration：库级参数集（logbufsz 等）
- **注册表变量** — Registry Variable：db2set 管理的引擎行为开关
- **DB2INSTANCE** — 环境变量：路由 db2 命令到目标实例
- **automatic storage** — 自动存储：建库时声明路径池托管容器
- **SYSCAT** — 目录视图 schema：9 起推荐的元数据只读面
- **db2sampl** — Sample 生成器：教学演示库脚本

## 最新演进与工业实践

- 两级模型到 2024–2026 未变：Db2 11.5/12 仍"装码→建实例→建库"，但云托管形态（Db2 on Cloud / Cloud Pak for Data）把前两级交给平台，DBA 只剩建库与参数——概念降维但命令谱系保留（✅ 入口 https://www.ibm.com/docs/en/db2 ）。
- 自动存储已成为默认且几乎唯一推荐路径，SMS 表空间进入退役通道（⚠️ 转述）。
- CLP 增强出 `db2Cli`/python ibm_db / Jcc CLI 包装；现代工业脚本面多用 `clidriver` 直连而非 CLP。
- 认证线：731 退役后安装类考点并入 Db2 11.x DBA 考试域（⚠️ 考试代码未验）；备考本册时第 16 文件+`IBM_Db2_11_1_Certification_Guide`（登记名，见 00）对照读。
- 教训迁移：其他引擎管理员可从"配置双轨"看出参数持久化层级设计——PG postgresql.conf/ALTER SYSTEM、MySQL my.cnf/SET PERSIST 同题（对照 [../Understanding_MySQL_Internals/00-总览与阅读地图.md](../Understanding_MySQL_Internals/00-总览与阅读地图.md)）。
