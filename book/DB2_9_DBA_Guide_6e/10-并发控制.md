# 10 · Concurrency（Ch10 · 锁、隔离级与并发病理）

> 章名 ✅ InformIT 出版社页实抓；正文 ⚠️ 转述重构。**🔧 实验 D 组**在第七节，为 SQLite 本机类比、非 DB2 行为。

## 一、章定位

DB2 的并发哲学与 MVCC 系（Oracle/PG）根本不同：9.x 靠**多粒度锁+隔离级阶梯**保证一致性，读也加锁（UR 除外）。本章是 DBA 病理学：锁等待、锁升级、死锁三病的机理、观测与处方。

## 二、隔离级阶梯（⚠️ 转述）

| 级别 | 代号 | 语义锚点 |
|---|---|---|
| Repeatable Read | RR | 事务内再读已读行必同值；锁持有至提交 |
| Read Stability | RS | 快照=已读行稳定+新行不漏读（幻读防护） |
| Cursor Stability | CS | 默认；游标离开当前行即放该行锁 |
| Uncommitted Read | UR | 脏读许可；报表/ETL 读大表的工业双刃剑 |

- 语法：`db2 "connect ... ` 后 `SET ISOLATION ...` 或 CLP `db2 +cl rs` 风格绑定级；应用经 `SQLSetConnectAttr`。
- RR/RS 与 ANSI 的 SERIALIZABLE/REPEATABLE READ 映射近似但不重合——认证辨析题。

## 三、锁机制（⚠️ 转述）

1. 粒度：行锁→页锁→表锁；意向锁（IX/IS）维护层次一致性。
2. **锁升级（lock escalation）**：单事务锁数超 `MAXLOCKS×LOCKLIST` 比例阈值→表锁；症状"并发骤降"，处方：索引让谓词少扫行、拆事务、调大锁内存（治标）。
3. 锁内存：`LOCKLIST`（4K 页单位）、`MAXLOCKS`（单事务占比）、`LOCKTIMEOUT`（-1 永等/秒数超时→SQL0911N）。
4. 死锁：环形等待检测→牺牲一事务（SQLCODE -911 deadlock）；事件监控器 `deadlock event` 抓现场（→14 章）。
5. CUR_COMMIT（9.5，⚠️ 版次存疑）：提交后提前释放当前工作单元锁——OLTP 锁窗口收窄的关键阀门。
6. Lock Avoidance（后续版 9.7/10.x ⚠️）：CS/RS 下"提交后版本行免锁读"，向 MVCC 的有限妥协——本册成书时无，读演进节补。

## 四、观测面（DBA 处方前提，⚠️ 转述）

```text
db2 "get snapshot for locks on demo"
db2 "select * from sysproc.admin_get_locks(...)"   # 函数面(9.x 保守 ⚠️)
db2pd -db demo -locks -wait
db2 "event deadlock ... on db2eventlog"              # 事件监控器建法示意
```

- 三板斧：snapshot 看持有者/等待者链，db2pd 免挂起快速取样，事件监控器留历史证据。
- 关联 SQL：锁定资源 → 定位语句 → 检查计划（缺索引全表扫是头号病因，→14 章）。

## 五、并发病理剧本（原书案例族，⚠️）

1. 锁等待雪崩：批处理持 RR 长事务 + 在线 CS 流量 → 排队 SQL0911N timeout。
2. 锁升级风暴：大 UPDATE 无界谓词 → 升级 → 在线交易全线表锁互斥。
3. 死锁对撞：A 更新 1 行再查 2 行、B 反序——修复靠统一访问顺序/更短事务。
4. 脏读事故：UR 读 ETL 中表出半更新态——报表用 RS/时间旅行或隔离副本。
5. 游标跨提交：WITH HOLD + 更新游标交互产生"锁提前丢/留"错位。
6. 批量装载并发：LOAD ALLOW WRITE 档与查询侧 UR 的组合拳（06 章接口）。

## 六、与 MVCC 对照（教学关键段）

- Oracle/PG：读不挡写靠多版本；DB2 9：读挡写（除 UR/CUR_COMMIT 缓解）——同一负载两侧"计划形态与等待事件"完全不同。
- 迁移视角：去 O 进 DB2 的应用常需调 LOCKTIMEOUT/隔离级映射，是 2024–2026 去 Oracle 工程（Db2 兼容模式）的真实痛点（⚠️ 趋势）。
- SQL Server 介于中间（锁+行版本双轨），MySQL InnoDB 类 MVCC——本目录兄弟册有专章：[../SQL_Server_2012_Internals/00-总览与阅读地图.md](../SQL_Server_2012_Internals/00-总览与阅读地图.md)、[../Understanding_MySQL_Internals/00-总览与阅读地图.md](../Understanding_MySQL_Internals/00-总览与阅读地图.md)。

## 七、🔧 类比实测（SQLite，**非 DB2 行为**）

实验 D 组（本机 Python 3 + 内置 sqlite3，Windows，2026-10-01，临时件 `D:\develops\tmp\dbwave_w7_db2dba\`）：

- 方法：连接 A `BEGIN IMMEDIATE` 并插入行；连接 B（timeout=0.1s）立即插入。
- 结果：B 抛 `sqlite3.OperationalError: database is locked`——写写冲突在 SQLite 退化到**库级写锁**，等效 DB2 世界"整表锁+零等待超时"的极端投影。
- 锚定概念：DB2 的 `LOCKTIMEOUT` 与 SQL0911N 即把这类"拿不到锁怎么办"参数化（-1 永等/正数秒/0 立放弃），并用**行粒度+意向锁**把冲突面从"库"降到"行"。
- 第二观测：SQLite WAL 模式（见 13 章 🔧B 组）开启"读不挡写"，概念上即 DB2 后期 Lock Avoidance/CUR_COMMIT 想解决的同一问题——**隔离级是工程取舍，不是自然律**。
- 纪律重申：以上数值与报错皆为 SQLite 行为，不得作为 DB2 结论引用。

## 九、锁观测指标表（工单化读法，⚠️）

| 指标 | 来源 | 警戒语义 | 处方方向 |
|---|---|---|---|
| Locks held（当前） | snapshot locks | 单语句持续高位 | 谓词/索引体检（14 章） |
| Lock escalations | snapshot db | 增长快 | 事务拆短+锁内存调界 |
| Lock waits / timeouts | snapshot apps | 出现即痛 | LOCKTIMEOUT 策略+热点行 |
| Deadlocks | 事件监控器/快照 | >0 必留证 | 访问顺序统一（剧本 3） |
| Locklist 使用率 | db2pd -locks | >80% 预警 | MAXLOCKS 结构治理 |
| Lock waits elapsed time | 区间快照 | P95 漂移 | 与 WLM 阈值联动（14 章） |

- 用法：左列任一指标异常→先归因到"哪条 SQL 哪个计划"，再谈参数——反向操作（先调参）是新手通病。

## 核心概念速览（中英对照）

- **RR/RS/CS/UR** — 四级隔离：DB2 特有的命名阶梯
- **lock escalation** — 锁升级：行锁泛滥转表锁的自我保护
- **LOCKLIST/MAXLOCKS** — 锁内存总量/单事务份额
- **LOCKTIMEOUT** — 锁等待超时参数（SQL0911N）
- **deadlock** — 死锁：环等待，检测即牺牲一员
- **intent lock (IX/IS)** — 意向锁：跨粒度一致性胶水
- **CUR_COMMIT** — 提交放锁：当前工作单元锁提前释放（9.5 ⚠️）
- **lock avoidance** — 锁回避：版本免锁读（书后演进 ⚠️）
- **snapshot on locks** — 锁快照：持有/等待实时取样
- **db2pd** — 进程诊断器：绕过挂起的取样工具
- **event monitor (deadlock)** — 事件监控器：死锁留证
- **WITH HOLD** — 跨提交游标与锁交互（09 章呼应）
- **dirty read** — 脏读：UR 的代价

## 最新演进与工业实践

- 锁模型现代化：Db2 9.7→11.5 的 **Lock Avoidance 默认启用、锁内存自适应、`db2 "sysproc.admin_get_locks"` 表函数化**；2024–2026 文档主干仍标"锁为本、版本为辅"（⚠️ 转述；入口 ✅ https://www.ibm.com/docs/en/db2 ）。
