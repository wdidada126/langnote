## 二、驱动与编程模型全景（Ch15 骨架，⚠️ 转述）

- 03 章驱动矩阵的展开面：CLI（C/C++，含 DB2 扩展）、ODBC（跨 DBMS 兼容层）、JDBC Type 2/4（Java 应用服务器主流）、.NET Provider、嵌入式 SQL（Pro*C/COBOL 存量）、SQLJ（边缘化）、Perl/Ruby/Python 经社区绑定（ibm_db 前身 ⚠️）。
- 编程模型三选择：静态包（09 章）/动态语句/存储过程调用；混合式（动态+参数标记）为当代默认。
- 事务与 XA：应用服务器两阶段提交经 JDBC XADataSource；本地事务用 CLI/JDBC autocommit 面——与 13 章恢复语义在"提交点"汇合。
- 元数据与结果集：目录 API（SQLTables 系）、游标模式（敏感/非敏感，06 章呼应）。
- Web 面：PHP/IBM 扩展与 XML 消费（08 章接口）是 9 时代"Web 2.0"卖点的应用侧。

## 三、部署考量（Ch16 骨架，⚠️ 转述）

1. **版本兼容**：应用绑定包跨库版本迁移需重绑/重编（09 章）；客户端 CLI 版本与服务端 FP 错配是故障库常客。
2. **字符集与转换**：库 codepage（02 章建库三件套）↔ 应用编码（UTF-8 趋势）↔ XML 声明（08 章）；隐式转换的性能与乱码双坑。
3. **连接治理**：池大小×agent 内存、CONNECT_IDLE/CONNECT_TIMEOUT 系参数（⚠️ 引入版次保守）、集中器（connection concentrator，后版特性 ⚠️）。
4. **数据迁移工程**：EXPORT/IMPORT/LOAD 三件套（06 章）+ 跨平台搬库（`db2 move`? ⚠️ 不提具体命令面）。
5. **模式演化**：ALTER 限制（列类型加宽可行、缩窄不可）、影子表+触发器双写（9 时代土法在线改表）。
6. **发布物**：SQL 脚本（CLP `-tvf`）+ 绑定文件 + 授权脚本（04 章）三位一体，缺授权脚本=迁移即断权。

## 四、性能考量的应用侧清单

- 取数：批量 `FETCH FIRST`/数组接口（CLI array 绑定 ⚠️ 名保守）vs 逐行游标循环（07 章"少写游标"的部署版）。
- 提交：小提交高频 vs 大提交稀疏——锁窗口（10 章）与日志（13 章）双向约束。
- 隔离级选型：默认 CS；报表 UR 的代价声明写入应用规格书（10 章剧本 4）。
- 参数化：动态语句一律参数标记，保语句缓存命中（14 章）兼防注入（安全双线，#51 登记名）。
- 错误处理：SQLCODE 分支表进代码评审清单（09 章 SQLCA）。

## 六、易错雷点（例题库精华）

1. Type 2 驱动随客户端装、服务器机器误装"服务端包"——依赖面混淆（03 章）。
2. 应用池化后静态包 `RELEASE(BIND)` 语义引发目录膨胀（09 章）。
3. UTF-8 库 + latin1 应用数据入库乱码：建库 codepage 与转换层职责未写进部署单。
4. 大结果集 fetch 默认缓冲把内存打爆——CLI/JDBC 取数批大小需显式治理。
5. 迁移后序列/标识起点错位（05 章雷点 5 的部署版）。
6. 只测开发库单版本、上线跨 FP——兼容性矩阵缺失（发布物纪律）。

## 核心概念速览（中英对照）

- **编程模型** — Programming Model：静态包/动态/SP 三轨
- **参数标记** — Parameter Marker：`?` 占位的语句模板化
- **array 接口** — 数组绑定：批量取/写的宿主技术（⚠️ 名保守）
- **XADataSource** — XA 数据源：容器两阶段提交入口
- **autocommit** — 自动提交：本地事务默认形态
- **连接集中器** — Connection Concentrator：代理收敛 agent 数（书后 ⚠️）
- **codepage** — 代码页：库编码基线（02 章呼应）
- **数据转换** — Data Conversion：跨编码/类型迁移治理
- **影子表** — Shadow Table：双写法在线改表载体
- **发布物** — Deployment Artifacts：脚本+绑定+授权三件套
- **重绑** — REBIND（09 章）：部署期版本对齐动作
- **兼容性矩阵** — Compatibility Matrix：客户端×服务端 FP 组合测试面
