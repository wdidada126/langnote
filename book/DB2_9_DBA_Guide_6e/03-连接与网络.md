# 03 · Getting Connected（Ch3 · 目录编目与连通层）

> 章名 ✅ InformIT 出版社页实抓；正文 ⚠️ 转述重构，DB2 连通栈以 IBM 公开文档口径叙述，不可本机实测。

## 一、章定位

DB2 的"网络与编目"章：客户端如何找到服务器（node/db 目录）、协议与端口如何配置（TCP/IP + DB2 监听）、驱动如何分层（CLI/ODBC/JDBC/.NET）。认证考 731 的连通域与运维"连不上"排错都从这里取根。

## 二、编目机制（cataloging，⚠️ 转述）

1. 本地路径：库在本地实例上直接 `db2 connect to <dbname>`，走本地 IPC。
2. 远端三件套：
   - `db2 CATALOG TCPIP NODE <nodels> HOST <h> SERVICE <port>` —— 建节点条目
   - `db2 CATALOG DB <remote_name> AS <local_alias> NODE <nodename>` —— 建数据库别名条目
   - 然后 `db2 connect to <alias> USER ...`
3. 目录存储：节点目录+数据库目录+DCS 目录，位置由 `DB2SYSTEM`/实例目录控制，`db2 LIST NODE DIRECTORY`/`LIST DATABASE DIRECTORY` 可查。
4. DCS（Distributed Connection Services）：本地服务名到远端库的映射层，把"节点+别名"组合成单一服务名供非 DB2 应用消费。
5. 认证考点：SQL30061N（库不存在）vs SQL30081N（通信失败）的根因分层——先查网络/监听，再查编目，最后查权限。

## 三、监听与进程面（⚠️ 转述）

- 服务器端：实例启动后由启动代理/监听器（TCP/IP listener）在端口（经典默认 50000/自定义 service 名）接受连接。
- 连接建立后派生 agent（线程模型：DB2 9 后线程化为主，⚠️ 进程/线程开关细节存疑）。
- 客户机侧 CLI 栈：应用 → CLI 函数（ODBC 超集）→ DRDA 打包 → TCP。
- 防火墙/端口漂移是 LUW 部署高频事故：service 名与 /etc/services 或 Windows services 文件同步是运维规程（⚠️）。

## 四、驱动矩阵（示意表，⚠️ 转述）

| 驱动 | 形态 | 典型栈 |
|---|---|---|
| CLI | C API（ODBC 超集） | 本地库与 DRDA 通吃 |
| ODBC | 标准 API | 底层复用 CLI，DSN 编目 `CATALOG DSN` |
| JDBC Type 2 | 本地库包装 | 复用 CLI，支持 XA |
| JDBC Type 4 (jcc) | 纯 Java DRDA | 应用服务器主流，无本地依赖 |
| .NET Data Provider | ADO.NET | Windows 生态 |

- 现代演进：Type 4 (IBM Data Server Driver for JDBC/CLI) 统一包发行，.NET Core 驱动跟进（⚠️ 未验 URL）。
- 互链：驱动分层思想与 MySQL Connector 家族完全同构——见 [../MySQL_8_Administrators_Guide/00-总览与阅读地图.md](../MySQL_8_Administrators_Guide/00-总览与阅读地图.md)。

## 五、连通排错剧本（本章例题精华，⚠️）

1. `db2 ping` 不可用时代之以 `telnet host port` 验监听。
2. `db2 LIST ACTIVITIES`/快照看连接数——9.5 时代常用 `db2 get snapshot for applications on db`。
3. 编目存在但连接报授权——去 04 章；报"库不存在"但服务器有库——远端别名/大小写（DB2 标识符折叠规则）问题。
4. 多实例主机：客户端环境变量 `DB2INSTANCE` 指向错实例导致"看不见已编目库"。
5. 连接泄漏治理：应用侧池化 + 库侧 CONNECT_IDLE_TIMEOUT（⚠️ 参数引入版次存疑）。
6. 联邦系统（federated）借 nickname 跨库查询，连通层复用编目概念——本册仅在 05/07 章带过（原书着墨有限 ⚠️）。

## 六、与其他引擎的连接模型对照

- MySQL：主机+端口+库三段直连，无编目层——DB2 编目≈把连接串存进 OS 侧配置库。
- Oracle：TNS 别名≈DB2 数据库别名，listener≈DB2 监听，`tnsnames.ora`≈node/db 目录——一一对应（见 [../Cost_Based_Oracle_Fundamentals/00-总览与阅读地图.md](../Cost_Based_Oracle_Fundamentals/00-总览与阅读地图.md)）。
- SQL Server：JDBC/ADO.NET 直连实例名+端口（1433），编目概念弱——对照 [../SQL_Server_2012_Internals/00-总览与阅读地图.md](../SQL_Server_2012_Internals/00-总览与阅读地图.md)。

## 七、命令与 URL 速查卡（示意，⚠️）

```text
db2 CATALOG TCPIP NODE n1 HOST 10.0.0.5 SERVICE 60000
db2 CATALOG DB remotedb AS mydb NODE n1
db2 LIST NODE DIRECTORY / db2 LIST DATABASE DIRECTORY
db2 UNCATALOG DATABASE mydb / UNCATALOG NODE n1
db2 connect to mydb user u using p
db2 CONNECT RESET   # 断当前库保会话
db2 terminate
# JDBC Type 4:
# jdbc:db2://10.0.0.5:60000/remotedb
# CLI 驱动 ODBC: 先 db2 CATALOG DSN DATABASE ... ; 再 DSN=...
```

- URL 读法：Type 4 用远端真库名可免编目——编目是"OS 侧连接串缓存"，理解这一句就理解了本章。

## 八、JDBC/CLI 深读（⚠️ 转述）

1. Type 2 与 Type 4 差异除依赖外，在 XA 支持与会话参数透传上曾有坑；jcc 特性开关走 URL 属性（`:retrieveMessagesFromServerOnGetMessage=true;`）。
2. CLI 句柄链：ENV→DBC→STMT；`SQLSetConnectAttr` 系管理隔离级（→ 10 章）。
3. 应用服务器接 DB2：数据源=JDBC 属性打包；XA 双阶段提交由容器协调（→ 15 章）。
4. 编目与连接池的冲突：池化通常倾向"无状态 URI"，编目价值在集中改名/迁移窗口（运维观点）。

## 核心概念速览（中英对照）

- **编目** — Cataloging：把远端节点/库登记进本地目录的动作
- **节点目录** — Node Directory：主机+端口的本地登记册
- **数据库目录** — Database Directory：库名到节点/别名的映射登记册
- **DCS** — Distributed Connection Services：服务名→远端库映射层
- **监听器** — Listener：实例侧接收 TCP 连接的代理进程
- **agent** — Agent：每连接的服务线程/进程
- **DRDA** — Distributed Relational Database Architecture：IBM 网络协议
- **CLI** — Call Level Interface：ODBC 超集的 C 驱动
- **Type 4 驱动** — Pure Java JDBC：无本地库依赖的 jcc
- **SQL30061N** — 库未编目错误码：连通排错分层信号
- **SQL30081N** — 通信失败错误码：网络/监听层信号
- **连接池** — Connection Pooling：应用侧复用连接的治理点

## 最新演进与工业实践

- 编目到 2024–2026：Db2 仍保留 catalog 体系，但云场景主推**无编目 URI 连接**（`jdbc:db2://host:port/db` + 环境变量），传统 CATALOG 命令退守存量脚本（⚠️ 转述）。
- 驱动整合：IBM Data Server Driver（CLI+JDBC 同包）持续发布，随 Db2 11.5/12 版本线滚动（✅ 文档入口 https://www.ibm.com/docs/en/db2 curl 200）。
- 连接治理工业化：connection concentrator、AUTOMATIC RECONNECT、CLP 脚本面 `db2 UPDATE DB CFG USING` 等 9.x 特性延续；新栈加 TLS 默认化与 IAM 式云鉴权。
- 排错方法论互通：本层"网络→编目→权限"三段式与 Oracle/SQL Server 的连通排错同构——参见 [../Oracle_Performance_Tuning_2e/00-总览与阅读地图.md](../Oracle_Performance_Tuning_2e/00-总览与阅读地图.md) 的等待事件视角类比。
- 安全衔接：连接层的认证与授权分层见本目录 04 章文件；LBAC/审计不在此层生效（先连上再谈权）。
