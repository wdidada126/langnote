# 14 · Monitoring and Tuning（Ch14 · 观测矩阵与调优方法学）

> 章名 ✅ InformIT 出版社页实抓；正文 ⚠️ 转述重构，工具输出面按公开文档口径。

## 一、章定位

管理部收官章：先把"看得见"做全（快照/事件监控器/db2pd/db2top/目录视图的观测矩阵），再立"调得动"的方法学（自顶向下找等待、自底向上验假设），落点是缓冲池/排序/包缓存/锁/日志五大战场与 9.5 WLM 治理。

## 二、观测矩阵（⚠️ 转述）

| 工具 | 形态 | 强项 | 弱项 |
|---|---|---|---|
| `db2 get snapshot` | 一次性/区间 | 全对象覆盖 | 粒度粗、量大卡顿 |
| 事件监控器 | 持续捕获到表/文件 | 死锁/语句历史留证 | 开销需裁剪 |
| `db2pd` | 进程内存直读 | 免挂起、快 | 需本地权限 |
| `db2top` | TUI 仪表盘 | 实时体感 | 历史弱 |
| MON_GET_* 表函数 | SQL 查询式（9.5 增强 ⚠️） | 可 JOIN/脚本化 | 版本兼容面 |
| SYSCAT/统计视图 | 目录+运行时 | 报表化 | 时效滞后 |

- 语句级洞察：`snapshot database` 中 Top 语句/包缓存命中；事件监控器 `STATEMENTS` 过滤器采"慢语句"。
- 诊断日志：`diagnpath` 的 `db2diag.log` 是错误第一现场（02 章实例目录呼应）。

## 三、五大战场调优清单（原书方法重构，⚠️）

1. **缓冲池**：命中率、读页/预取比、脏页清理节奏（11 章 STMM 的调优侧）；`db2 "evict buffers"`? 手工干预保守不提。
2. **排序**：`SORBTOPAESZ/SORRTHEAP` 系、内存排序溢出 TEMP 的信号（快照 sort overflows）——大分析负载主因。
3. **包/语句缓存**：`PKGDIRTR/STATEMENTHEAPSZ`、动态语句缓存命中（9.7 语句缓存 ⚠️ 书后演进）。
4. **锁**：升级/等待/死锁三联（10 章观测处方化）。
5. **日志**：提交风暴 vs LOGBUFSZ、组提交（⚠️ 机制名保守）——OLTP TPS 天花板常在此。
- 方法学主轴：**自顶向下**（应用响应时间→等待类别→资源）与**统计先行**（EXPLAIN 基数偏差→RUNSTATS，12 章闭环）。

## 四、优化器与访问路径（与 07/09 章接口）

- 成本模型：索引可用性、聚簇比、频率分布（E 组 🔧 的放大版，见 12 章第七节）驱动 IX/TL 选择。
- 星级优化：join method/index/temp；`OPTIMIZE FOR n ROWS`/`REOPT`（⚠️ 版本面）。
- `db2expln/db2exfmt` 读法复习（09 章四问）；计划劣化=统计陈旧的诊断范式。
- **db2advis** 索引/MQT 顾问：以工作负载缓存为输入出"建议+成本对比"报告——工业 DBA 第一生产力件（⚠️ 参数细节从简）。

## 五、WLM 工作负载管理（9.5 主打，⚠️ 转述）

1. 对象层级：workload class → threshold（活动/执行时间）→ action（警告/强制/降权）。
2. 分类依据：连接属性/应用名/用户 → 映射服务类（service class）。
3. 资源旋钮：排序内存/并行度/代理优先级的服务类配额。
4. DBA 视角：把"某报表拖垮联机"从事故变成可声明的策略——当时领先于多数竞品的治理叙事。

## 七、易错雷点（例题库精华）

1. 生产常开 `for all applications` 快照 → 采集开销反成瓶颈；区间快照用法。
2. 事件监控器写表模式选错表空间（TEMP/大对象）→ 空间事故（11 章）。
3. 命中率迷信：99% 命中但预取失效（顺序负载随机读）仍慢——要看物理读形态。
4. 调大 SRTHEAP 掩盖坏 SQL：先 EXPLAIN 后旋钮的次序纪律。
5. db2advis 建议索引未验证维护成本（写放大）——"建议≠部署"。
6. WLM 阈值过紧导致大批杀会话——先警告期再强制期灰度。

## 九、调优检查单 Top-12（开工前逐条打钩，⚠️ 重构）

1. 统计新鲜度：目标表 `STATS_TIME` 在维护窗口内（12 章）。
2. 计划一致性：同语句多版本计划并存?（包/语句缓存分裂）。
3. 缓冲池：命中率 + 预取效率双指标，非单看命中。
4. 排序：sort overflows 趋势与 SORRTHEAP/TEMP 页大小联动。
5. 锁：升级/等待/死锁三计数零新增?（10 章指标表）。
6. 日志：提交延迟与 LOGBUFSZ、归档 I/O 竞争（13 章）。
7. TEMP：多池分布与溢出盘符（11 章）。
8. I/O：容器热点盘与条带均衡（11 章 SOP）。
9. 包缓存：命中与目录膨胀（09 章 RELEASE 策略）。
10. 并行度：语句级与 WLM 服务类配额（第五节）。
11. 顾问复核：db2advis 建议的写放大评估（雷点 5）。
12. 回归基线：调前/调后同负载响应曲线留档——没有基线就没有调优。

## 核心概念速览（中英对照）

- **snapshot monitor** — 快照监控器：即时状态取样
- **event monitor** — 事件监控器：条件持续捕获
- **db2pd** — 进程诊断：内存结构直读免挂起
- **db2top** — TUI 仪表盘：实时体感
- **MON_GET_*** — 表函数监控：SQL 化观测面
- **db2diag.log** — 诊断日志：错误第一现场
- **hit ratio** — 命中率：缓冲池健康度代理指标
- **sort overflow** — 排序溢出：内存排序落 TEMP 的信号
- **package cache** — 包缓存：静态包语句驻留
- **statement cache** — 语句缓存：动态语句优化结果复用（⚠️ 书后面）
- **db2advis** — 顾问：索引/MQT 建议生成器
- **WLM / service class** — 工作负载管理/服务类：资源策略化
- **REOPT** — 语句重优化：以实际变量值刷新计划（⚠️ 版本面）

## 最新演进与工业实践

- 观测现代化：Db2 11.5/12 以 **MON_GET 族+库活动视图+Db2 Warehouse 监控控制台/云监控** 为主干，快照监控器弱化、事件监控器保留（⚠️ 转述；入口 ✅ https://www.ibm.com/docs/en/db2 ）。
- 自治延续：STMM+自动维护（12 章）之上叠加 **自适应编译（ACE）/查询管理（带 WLM 演进的 DB2 11.x 特征）**；调优叙事从"旋钮"转向"策略+自治"（对照 SQL Server 智能查询处理同题 [../SQL_Server_2012_Internals/00-总览与阅读地图.md](../SQL_Server_2012_Internals/00-总览与阅读地图.md)）。
- 顾问生态：db2advis 与物化视图建议仍在，但索引选择的工业前沿移到自动索引（PG `pg_auto_failover` 不相关、云厂商 AutoIndex 一类）——概念同构（[../Database_Tuning/00-总览与阅读地图.md](../Database_Tuning/00-总览与阅读地图.md) 的顾问章为通识镜像）。
- 可观测合流：db2diag/事件监控器对接 OpenTelemetry/ELK 是当代企业实践（⚠️ 趋势判断，无单一权威源）。
