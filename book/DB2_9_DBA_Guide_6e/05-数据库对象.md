# 05 · Database Objects（Ch5 · PART TWO 开篇：对象宇宙）

> 章名 ✅ InformIT 出版社页实抓；正文 ⚠️ 转述重构，语法示意自 IBM 公开文档口径，非实测。

## 一、章定位

进入"Using SQL"部：本章铺开 DB2 对象全集——表空间、表（含分区/MDC/GTT）、索引、MQT、视图、序列/标识列、包与模块。DB2 9 的对象观特色是"存储策略嵌在对象定义里"（extent/prefetch 在 DMS、聚簇在索引），这为 11 章存储管理埋满伏笔。

## 二、表空间三型与对象落位（⚠️ 转述）

1. SMS（系统管理）：委托文件系统，性能靠 OS 缓存；建库默认时代的产物。
2. DMS（数据库管理）：显式容器（文件/裸设备）、extent/prefetch 参数直控——性能敏感库的正统选择。
3. 自动存储（9.1 新增）：路径池+自动建容器/自动扩展，本质是 DMS 托管面（⚠️ 内部实现转述）。
- 对象落位语法：`CREATE TABLE t (...) IN ts_main INDEX IN ts_idx LONG IN ts_lob`——数据/索引/LOB 分表空间是容量规划第一课。

## 三、表的形态谱系（⚠️ 转述）

- 常规表；范围分区表（`PARTITION BY RANGE(col) START... END... EVERY`，历史账表标配，9.1 后自动存储联动）。
- MDC 多维聚簇表（`ORGANIZE BY (col1,col2)`）：块级多维聚簇替代单列 cluster key。
- 全局临时表（`DECLARE ... CREATE TEMPORARY TABLE` / `CREATE GLOBAL TEMPORARY`）：会话私有，ON COMMIT DELETE ROWS。
- 类型表/层次（typed table，对象关系残余，本册已边缘化 ⚠️）。
- XML 列的表（与 08 章接口）；日志属性 `NOT LOGGED INITIALLY` 的坑（激活后需重新备份，→13 章）。

## 四、索引与聚簇（⚠️ 转述）

- B 树唯一/非唯一；`CLUSTERING`+`FREERATIO/PCTFREE` 控制插入物理顺序；`CLUSTER RATIO`（9 的混合聚簇，介于完全聚簇与非聚簇之间 ⚠️ 参数名存疑）。
- XML 索引（路径/值/区域；详见 08 章）。
- 反向索引/扩展索引等冷门项原书仅列举（⚠️ 不再展开，避免臆造）。
- 索引与 RUNSTATS 共生：`CREATE INDEX ... ALLOW REVERSE SCANS` 后必跑统计（12 章）。

## 五、物化与逻辑对象

- MQT（Materialized Query Table）：`CREATE TABLE ... AS (fullselect) DATA INITIAL IMMEDIATE REFRESH SYSTEM MAINTAINED`——查询重写由优化器自动匹配（⚠️ 9.x 重写能力有限，诚实记）。
- 视图：简单/连接视图可更新性规则是 731 考点（单基表+保留键可更新类）。
- 序列（DB2 9 新增，`CREATE SEQUENCE ... NEXTVAL FOR`）vs IDENTITY 列：序列可共享、可 CYCLE——认证选择题常客（⚠️ 语法细节以现行文档为准）。
- 包（package）与模块（module）：静态 SQL 的存放对象（09 章展开）；9.5 模块为 Java/存储过程命名容器（⚠️ 引入版次存疑）。

## 六、DDL 示意块（非实测）

```text
CREATE TABLESPACE ts_dms MANAGED BY DATABASE
  USING (FILE '/dbdata/tsd1' 200M, FILE '/dbdata/tsd2' 200M)
  EXTENT_SIZE 32 PREFETCH_SIZE 32;
CREATE TABLE orders (id BIGINT NOT NULL GENERATED ALWAYS AS IDENTITY,
  cust_id INT, amount DECIMAL(12,2), created DATE)
  IN ts_dms
  PARTITION BY RANGE (created) STARTING '1/1/2005' ENDING '12/31/2007'
  EVERY 3 MONTH;
CREATE INDEX ix_ord ON orders(cust_id) CLUSTER;
CREATE SEQUENCE sq_receipt INCREMENT BY 10 NO CYCLE;
```

## 七、易错雷点（例题库精华，⚠️）

1. 分区列不在唯一索引前导列 → "SQL0660N" 类规则违例。
2. GTT 在连接结束才可见 schema 差异——SYSTOOLSAUX? 不，落 TEMP 表空间，忘建大 TEMP 是新手常态。
3. MQT 带 `USER MAINTAINED` 语义与 REFRESH TABLE 的适用差别。
4. 视图带 `WITH READ ONLY` 遗漏导致更新穿透失败报错误导。
5. 标识列 `GENERATED BY DEFAULT` 与序列迁移冲突（数据重载后序列起点）。
6. DMS 容器写满不会自动扩（除非 autostripe/自动存储），SMS/自动存储行为差是运维分叉点。

## 核心概念速览（中英对照）

- **SMS/DMS/自动存储** — 表空间三型：OS 托管/DB 显式容器/路径池托管
- **extent** — 盘区：表空间内分配粒度
- **prefetch size** — 预取尺寸：顺序读批量页参数
- **range partitioning** — 范围分区：按列区间分数据分区
- **MDC** — 多维聚簇：块级按列组合聚集
- **GTT** — 全局临时表：会话私有、落临时表空间
- **MQT** — 物化查询表：可被优化器查询重写的快照
- **identity column** — 标识列：行内自动生成值
- **sequence** — 序列：跨表共享的对象式发号器
- **cluster ratio** — 聚簇比：新行物理聚集比例控制
- **ALLOW REVERSE SCANS** — 反向扫描：索引双向可扫声明
- **NOT LOGGED INITIALLY** — 初始不记日志：首插免日志致备份断链
- **module** — 模块：存储过程/函数的命名容器（9.5 ⚠️）

## 最新演进与工业实践

- 对象谱系到 2024–2026：SMS 表空间在 Db2 11.5 文档中已是遗留项；范围分区演进为**自动范围分区（auto-partitioning）与 detach/attach 分区管理**（运维大杀器，11.x），MDC 声量式微，纯 SQL 表+列组织（BLU，10.5 起）成为数件向新默认（⚠️ 转述，入口 ✅ https://www.ibm.com/docs/en/db2 ）。
- 序列/标识列语法延续；temporal table（系统时段/有效时段，9.7+）与隐式隐藏列是书后增量——本册无、备考 #76 时需补。
- MQT 一脉发展为"global temporary + SQL cache + MDC 统计"混合优化叙事；工业界物化更多交给物化视图平台层（对照 [../Amazon_Redshift_TDG/00-总览与阅读地图.md](../Amazon_Redshift_TDG/00-总览与阅读地图.md) 的 MV 章节）。
- 对象建模通识层仍可用：表空间落位与容量规划三 IN 思路在 PG 表空间/MySQL 独立表空间中各有投影（[../Understanding_MySQL_Internals/00-总览与阅读地图.md](../Understanding_MySQL_Internals/00-总览与阅读地图.md)）。
