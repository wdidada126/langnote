# 04 · Controlling Data Access（Ch4 · 权限阶梯与安全分权）

> 章名 ✅ InformIT 出版社页实抓；正文 ⚠️ 转述重构。DB2 安全行为不可本机实测；SQLite 在本机只有"文件权限级"类比价值，故本章 🔧 见 10/12/13 章文件，不在此重复。

## 一、章定位

DB2 9 的安全章有两块骨：实例级"四级权限阶梯"（SYSADM/SYSCTRL/SYSMON/SYSMAINT，OS 组实现）与数据库级"_authorities_ + 对象特权 + SECADM 分权 + LBAC"。原书把这一章放在 PART ONE 末尾，意在先立"谁能做什么"再谈对象——阅读时把它当 05/13/14 章的前置宪法。

## 二、实例级四组（OS 组实现，⚠️ 转述）

1. **SYSADM**：实例+数据库全权；组成员即"根管理员"。
2. **SYSCTRL**：实例管理（起停/建库/表空间）但无权读任意用户数据。
3. **SYSMON**：只读监控（快照/事件监控器/诊断）。
4. **SYSMAINT**：维护委派（备份/恢复/重组可执行，不碰数据内容）。
- 关键设计：四者是 OS 组（Windows 本地组/UNIX 组），DB2 不自己存账号；Windows 上 SYSADM 亦可退回"实例所有者"单人模式。
- 组变更需重新登录生效（会话携带组列表）——02 章已埋的坑。

## 三、数据库级 authority 与对象特权（⚠️ 转述）

- 数据库级：DBADM（建对象/授权）、LOAD、QUIESCE、REFRESH、NO_FENCE、SYSADM_NO_FENCE 等；DBA 岗常给 SYSCTRL+LOAD+QUIESCE 组合而非 DBADM。
- 对象级：GRANT SELECT/INSERT/UPDATE/DELETE/CONTROL ON TABLE ... TO user WITH GRANT OPTION；CONTROL 近似对象属主。
- 其他可授对象：PACKAGE（EXECUTE）、SEQUENCE（USAGE）、FUNCTION/PROCEDURE、INDEX 无直接特权（随表）。
- 权限检查链：连接（认证）→ 实例 authority → 库 authority → 对象特权 → （可选）LBAC 标签过滤，逐层收紧。

## 四、SECADM 与职责分离（DB2 9 主打）

- DB2 9 引入 SECADM：把"授权权"从 SYSADM/DBADM 中拆出，实现三权分立（系统管理/安全管理/审计管理）。
- 审计面：`db2audit` 实例级配置 + 库级 AUDIT POLICY；事件类 LOGIN/SUCCESSDB/FAILEDOBJ/STAT（⚠️ 事件名以现行为准）；日志文件经 `db2audit extract` 出报表。
- 设计动机来自大机 RACF 传统——与 Oracle 的"SYS 万能"文化对照是认证高频题眼（对照 [../Cost_Based_Oracle_Fundamentals/00-总览与阅读地图.md](../Cost_Based_Oracle_Fundamentals/00-总览与阅读地图.md)）。

## 五、LBAC（Label-Based Access Control，⚠️ 转述）

1. 构件：security policy → label component → label → 用户/列映射。
2. 列级 LBAC（DB2 9 首发）：给列贴标签，读需"支配（dominate）"策略；行级 LBAC 随 9.x FP 跟进（⚠️ 版次存疑）。
3. SECADM 专属维护；LBAC 规则绕过优化器常规谓词，性能与计划形态有专章讨论（14 章呼应）。
4. 适用场景：合规数据产品（行级密级）；与视图法控权对比是本册老例题。

## 六、认证机制（⚠️ 转述）

- 客户端认证插件链：OS 认证（Windows 集成/UNIX 口令）→ DCS → 简单认证（用户名口令）→ LDAP 可选后端。
- 服务端 plugin/客户端 plugin 概念在 9.5/9.7 成熟（⚠️ 本书 9.x 初版仅点到 LDAP）。
- Kerberos 票据透传属后话（9.7+，⚠️），本章按原书以 LDAP 为最高形态叙述。

## 八、常见考题与运维雷点

1. "SYSCTRL 能否 SELECT 任意表？"——否；SYSCTRL 管实例不读数据（阶梯设计核心）。
2. "GRANT 了对象特权仍报错"——检查是否缺 CONNECT 或 LBAC 未支配。
3. DBADM 与 CONTROL 的层级差：前者库内管理面，后者对象内全含 GRANT 权。
4. 审计日志写满文件系统——db2audit 的日志轮转策略属 SRE 规程（⚠️ 原书一笔带过）。
5. Windows 组与 UNIX 组行为差异：组成员缓存刷新时机不同，跨平台脚本要测。

## 核心概念速览（中英对照）

- **SYSADM/SYSCTRL/SYSMON/SYSMAINT** — 实例四级权限：管理/实例操作/监控/维护
- **DBADM** — Database Administrator Authority：库内管理与授权子集
- **SECADM** — Security Administrator：9 起独立的安全管理 authority
- **对象特权** — Object Privilege：SELECT/CONTROL 等对具体对象的许可
- **WITH GRANT OPTION** — 可转授权：特权带传播能力
- **CONTROL** — 控制特权：对象级最高含再授权
- **LBAC** — 标签式访问控制：列/行级标签支配策略
- **security policy** — 安全策略：LBAC 标签体系的顶层对象
- **db2audit** — 审计工具：实例级审计配置与提取
- **LDAP 认证** — LDAP Auth：口令后端目录化
- **简单认证** — Simple Auth：用户名口令直接校验
- **CONNECT/CONNECT_NO** — 连接特权：库大门开关

## 最新演进与工业实践

- 2024–2026 状态：四级实例组+SECADM/LBAC 骨架未变；Db2 11.5 起增 **Db2 Security Event Monitor 云化**、行访问策略（Row Access Control）、列掩码（Column Mask，11.5）——与 Snowflake/Databricks 动态脱敏同赛道（✅ 文档入口 https://www.ibm.com/docs/en/db2 curl 200，具体特性页未逐一抓 → 细节 ⚠️ 转述）。
- 认证现代化：plugin 体系（OS/LDAP/OAuth 式云 token）成熟；云托管实例走 IAM，本地继续 OS 组传统。
- 审计合规：行级安全+掩码使"视图法控权"教学价值转向"理解策略引擎"（对照安全双线：波内 #51/#61 登记名见 [../数据库系列·总索引.md](../数据库系列·总索引.md) 波次表）。
- 工业实践：金融/医疗 LUW 存量仍以 LBAC+db2audit 组合过等保/SOX；新系统多迁到平台级策略引擎（⚠️ 趋势判断，无单一权威 URL）。
- 跨引擎互认：本层"职责分离+标签控制"思想与 PostgreSQL RLS、SQL Server 多级安全同构——见 [../SQL_Server_2012_Internals/00-总览与阅读地图.md](../SQL_Server_2012_Internals/00-总览与阅读地图.md)。
