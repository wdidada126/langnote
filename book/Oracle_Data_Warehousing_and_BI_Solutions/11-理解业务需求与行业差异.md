## 11.1 糟糕的部署选择如何伤害业务（p.308）

目录列六种「部署原罪」，各有独立小节（✅）——这是全书少见的**反向论证**：不谈仓库能带来
什么，只谈错误形态让业务持续付什么税：

1. **独立数据集市各自为政**（Independent Data Marts，✅ p.308）：同一指标多口径、
   跨主题关联要重做 ETL；一致性维度缺失的直接后果（术语回链 [05](05-面向可用性的模型设计.md)）。
2. **报表有限且不灵活**（✅ p.310）：预置报表之外一切都要排队开发——即席层缺位
   （对照 [06 §6.3](06-商业智能工具选型.md) 的工具面为何必须存在）。
3. **信息源限于内部数据**（✅ p.311）：缺外部基准/市场/舆情数据，分析天花板锁死在自家公司。
4. **历史数据有限**（✅ p.311）：只留当期快照 ⇒ 趋势/同环比不可算、回溯即断片——
   历史深度是 5.1.1 设计考量在业务侧的账单。
5. **缺当前高质量数据**（✅ p.312）：新鲜度与质量双失；「明早九点报表」的信用基础
   （→ 4.4/8.1）在这里被写成业务损失语言。
6. **增长弹性受限**（✅ p.313）：平台/模式两种天花板（sizing 错 + 架构写死），
   是 ch.4 与 ch.5 的失败态合订。

- ⚠️ 编者归纳：六条全部可**反向当验收清单用**——立项时按「当前部署中了哪几条」打分，
  就是最省事的业务需求说明书骨架；这一面在 ch.12 的价值度量里会变现（每条原罪对应
  一类可计量损失）。

## 11.2 项目驱动与业务类型（p.314）

目录按行业逐一过秤（✅ p.314–326，八个小节+一个「其他」合并节），每个行业的写法是
「监管/竞争压力 → 分析主题 → 数据画像」。速览表（⚠️ 编者归纳，行业要点均据目录小节名）：

| 行业（✅） | 页 | 典型驱动（⚠️ 归纳） | 仓库侧含义（⚠️） |
| --- | --- | --- | --- |
| 金融 | 314 | 监管报送、风险定价、反欺诈 | 时点可重现、审计级历史（原罪 4/5 双重敏感） |
| 医疗 | 316 | 合规隐私、临床与运营双线 | 掩蔽与分级（→ 8.3 安全面最重行业） |
| 制造 | 318 | 成本/质量/供应链三角 | 高频传感器与批次粒度并存（多粒度事实，5.2.5） |
| 媒体娱乐 | 319 | 内容收益核算、订阅行为 | 行为事件量大、留存策略常变（7.3 全量 vs 增量常客） |
| 零售 | 319 | 促销归因、库存周转 | 星型范式设计发源行业（Kimball 语境，链 [../数据仓库工具箱.md](../数据仓库工具箱.md)） |
| 电信 | 320 | 话单计费级明细、网络质量 | 数据体量天花板，分区/聚合双层重度用户（→ 4.6/5.1.2） |
| 交通与公用 | 321 | 资产利用率、监管 | 时序画像 |
| 教育机构 | 321–323 | 招生/留存/科研绩效 | 口径政治敏感（指导委员会刚需，→ 10.2） |
| 政府机构 | 323 | 公开数据、审计、隐私 | 历史深度与合规税最高 |

- ⚠️ 编者归纳：九个行业的共性抽取——**驱动永远来自「外部压力（监管/竞争）×内部
  决策频率」**；数据画像差异决定选型权重（电信→体量、医疗→安全、金融→时点重现），
  这恰是 ch.4 三维裁决与 ch.5 四选一**没有标准答案**的根本原因：行业先于技术。

## 11.3 发展范围并争取业务支持（p.326）

## 11.5 编者注记：需求面的三层结构

- ⚠️ 编者归纳（章收束框架）：本章的「理解业务」可压缩为三层——
  1. **损失层**（11.1）：六原罪中哪几条在流血、每天流多少——可直接上高管会议的语言；
  2. **驱动层**（11.2 行业表左半）：外部压力（监管/竞争）×内部决策频率——决定时效等级；
  3. **画像层**（11.2 右半）：体量/粒度/新鲜度/敏感度——决定 ch.4/05/07 的选型权重。
- 三层顺序不可倒置：跳过损失层直接谈画像层，是「技术正确但立项不过」的典型病因
  （⚠️ 编者归纳，与 12.1 损失账开场互钉）。
- 行业表的阅读纪律：每行写的是**差异发生器**而不是模板——正确用法是拿自己行业逐条过
  三层，而不是抄行。

## 核心概念速览（中英对照）

- **部署原罪** — Six Deployment Sins：碎片集市/死板报表/只有内部数据/历史断片/
  不新鲜不高质/增长封顶（✅ p.308–313）。
- **口径碎片化** — Inconsistent Metrics：独立集市的第一损失（✅ p.308）。
- **即席缺位税** — Rigidity Tax：一切新问题是开发队列长度（✅ p.310）。
- **外部基准数据** — External Data Sources：天花板解锁项（✅ p.311）。
- **时点可重现** — Point-in-Time Reproducibility：金融/政府的硬需求（⚠️ 归纳）。
- **行业×技术映射** — Vertical-First Weighting：行业决定三维裁决的权重（⚠️ 归纳）。
- **多粒度事实** — Multi-Granularity Facts：制造/电信画像（回链 5.2.5）。
- **掩蔽分级** — Masking & Classification：医疗行业安全面（回链 8.3）。
- **损失语言立项** — Loss-Language Scoping：用原罪清单写范围书（✅ p.326）。
- **外部压力×决策频率** — Driver Formula：行业驱动的共同抽取（⚠️ 编者归纳）。

- **数据欠款打分表** — Debt Scorecard：六原罪逐项 0–3 分，总分即当前负债（⚠️ 编者归纳）。

## 最新演进与工业实践

2007 → 2026 对位（⚠️ 转述 + 编者归纳）：

- **原罪清单的当代复发形态**：云工具泛滥让「独立数据集市」以「每团队一个 semantic model/
  一个 notebook 空间」的形态复活——碎片化不是历史问题而是默认熵 ⚠️（治理对策对照
  [../Data_Observability_for_Data_Engineering/00-总览与阅读地图.md](../Data_Observability_for_Data_Engineering/00-总览与阅读地图.md)、
  [../Apache_Polaris_TDG/00-总览与阅读地图.md](../Apache_Polaris_TDG/00-总览与阅读地图.md)）；
  「只有内部数据」则被第三方数据市场与开放数据生态部分解除 ⚠️。
- **历史深度新解**：湖仓分层存储（对象存储+开放表格式）让「全历史留存」第一次比
  「滚动删除」便宜——原罪 4 的经济基础反转（对照
  [../Data_Lakehouse_in_Action/00-总览与阅读地图.md](../Data_Lakehouse_in_Action/00-总览与阅读地图.md)、
  [../Architecting_an_Apache_Iceberg_Lakehouse/00-总览与阅读地图.md](../Architecting_an_Apache_Iceberg_Lakehouse/00-总览与阅读地图.md)）⚠️。
- **行业表的新增列**：金融加入实时反欺诈与开放银行 API 数据、零售加入全渠道行为流、
  医疗加入真实世界证据（RWE）、制造加入预测性维护——共同点是**时效等级整体上移一代** ⚠️；
  Oracle 侧对应 ATP/ADB-S + 流式入湖的组合拳（✅ https://docs.oracle.com/en/cloud/paas/autonomous-database/serverless/adbsb/ 、
  https://www.oracle.com/analytics/ ）⚠️。
- **监管数据主权**：行业画像里 2007 未有的强约束是跨境数据驻留（GDPR 系），政府/医疗
  首当其冲 ⚠️——它直接改写 4.2 的「硬件平台」为「区域与合规形态」。
- **FAW 行业包的镜像**：Oracle 2026 的行业策略恰是按本章逻辑出牌——把行业分析主题
  预置成 Fusion Analytics Warehouse 数据应用（金融/电信/零售/供应链等）
  （✅ https://www.oracle.com/analytics/ ）⚠️ 评价性转述：11.2 的「行业先于技术」
  最终变成了产品目录结构。
- **本机教学** 🔧：无需新实验——11.1 六原罪可直接用 E1b（缺汇总的税）、E2（历史分层
  收益）做「损失可视化」教具；均为 DuckDB/SQLite 行为，**非 Oracle 行为**。
- **需求挖掘的产品化**：11.1/11.2 的访谈与打分在 2026 有了用例管理与数据产品目录作为
  载体（对照 [../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md](../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md)）⚠️，
  但三层顺序与损失语言仍是产品无法替代的手艺。
