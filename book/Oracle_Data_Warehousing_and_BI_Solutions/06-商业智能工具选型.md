## 6.1 Oracle 门户与门户产品（p.128）

- ⚠️ 转述（归档口径）：Oracle Portal（✅ p.128–136，本节 8 页）在 10g 时代是 BI 的**分发层**——
  把报表、仪表盘、即席查询结果以 portlet 形式汇聚到统一入口；「Using Oracle Portal」（✅ p.129）
  讲消费面，「Building and Deploying Portal and Portlets」（✅ p.132）讲生产面。
- 门户的架构位置（⚠️ 编者归纳）：门户 = 当时对「BI 也要 SSO/个性化/协作」需求的回答；
  它不做计算、只做人-内容路由，因此 sizing 归 ch.4 工具层、故障归 ch.8 管理面。
- 目录信号：本节排在报表之前，说明书的观点是**先定「谁在哪里看」，再定「看什么格式」**。

## 6.2 报表（p.136）

目录并列三条报表线（✅）：

| 报表产品 | 页 | 定位（⚠️ 转述，归档口径） |
| --- | --- | --- |
| BI Publisher（XML Publisher） | 137 | 数据与版式分离：SQL/XML 数据 + FO/RTF/XSL-FO 模板 ⇒ PDF/Excel 高保真印刷级输出，格式化可控性最强 |

- 与 01 的呼应：BI Publisher 在 [01](01-Oracle商业智能全景.md) 的栈全景图里位于「分发」列，

## 6.3 即席查询与分析（p.142）

本节 20 页（✅ p.142–165），是本章重心，三个产品按「面向谁」分层：

- **BI EE（10g）**（✅ p.143–153，独占 10 页）：仓库级分析平台——语义建模层（RPD 元数据仓储，
  业务模型/关系模型/展示模型三层）⚠️、即席分析界面、仪表板与告警 ⚠️（归档口径）；
  「本章给它最多页数」= 作者认定它是 EE 版自建方案的主前端。
- **Discoverer 与 BI SE**（✅ p.153–162，9 页）：SE 版路线——Business Analyst/Worksheet 的
  文件夹式自助查询，轻量、Excel 近便；与 BI EE 的「SE vs EE」分野即 01 章两条产品线的落地。
- **电子表格插件**（✅ p.162–165）：Spreadsheet Add-ins 让 Excel 直连仓库语义，
  财务/分析用户的默认栖息地 ⚠️。
- 🔧 概念锚点（**非 Oracle 行为**）：E1c 的「1.27ms 预聚合 vs 13.3ms 现算」是即席工具
  体验差的物理来源——前端拖拽产生的高频小查询全靠库侧汇总兜住；E3 进一步给「新鲜度
  换速度」定量化（+29.5% 写入税换 75× 读红利），这解释了 6.3 三产品在 2007 年为何都强调
  「命中汇总表」（00 §9）。

## 6.4 构建 BI 应用（p.165）

- **JDeveloper 与 BI Beans**（✅ p.166–169）：把图表/仪表盘控件嵌入 Java/J2EE 应用的
  开发路径，面向「BI 是功能的一部分而非全部」的定制场景 ⚠️（归档口径）。
- **Data Miner**（✅ p.169–173 区间内，与 BI Beans 相邻）：Oracle 原生数据挖掘——算法工作流
  跑在库内，输出回填仓库供分析消费 ⚠️；19c 时代的对应物是 OML/ODMG 家族
  （✅ https://docs.oracle.com/en/database/oracle/machine-learning/ ）。

## 6.7 编者注记：工具选型的四个问题

- ⚠️ 编者归纳（章收束框架）：本章 47 页可压缩为一张「四问」决策卡——
  1. **谁用**（门户浏览者/报表消费者/即席分析师/嵌入开发者）决定进哪层（6.1→6.4）；
  2. **版式多么变**：固定印刷件 → BI Publisher；天天改 → 即席分析层（6.3）；
  3. **语义层在库还是在工具**：BI EE 的 RPD 与「工具直查表」是两种治理制度，维护费用
     截然不同——接 5.1.1 的可用性判据；
  4. **授权与运维能否与现有栈共用**：SE/EE 档位、Portal 与应用服务器复用——
     接 ch.4 成本轴与 ch.8 管理面。
- 产品血统重叠（Reports/Workbench/Publisher 三线并存）是 2007 收购期的历史状态，后继合并
  多次，但四问结构在 2026 的工具选型会上一字未改——工具是职能的容器（⚠️ 编者归纳）。
- 章际接口：买什么在本章，谁来看在 ch.8，跑得快不快在 ch.9，值不值得在 ch.12——
  本章 47 页其实是 Part II 的「接口章」。

## 核心概念速览（中英对照）

- **门户分发层** — Portal/Portlets：人-内容路由，不做计算（✅ p.128–132）。
- **BI Publisher** — 数据/版式分离的印刷级报表，前身 XML Publisher（✅ p.137）。
- **Oracle Reports** — 10g 传统报表引擎，Builder/Servlet 形态 ⚠️（✅ p.140）。
- **BI Reporting Workbench** — Actuate 合作的嵌入式报表线 ⚠️（✅ p.141）。
- **BI EE 语义层** — RP Metadata Repository：业务/关系/展示三层模型（⚠️ 归档口径）（✅ p.143）。
- **Discoverer / BI SE** — 轻量自助即席查询线（✅ p.153）。
- **Spreadsheet Add-ins** — Excel 直连仓库语义（✅ p.162）。
- **BI Beans** — Java 应用内嵌图表控件（✅ p.166）。
- **Data Miner** — 库内数据挖掘工作流（✅ p.166 起）。
- **SE vs EE 分野** — 两条产品线对应两类预算与治理成熟度（→ 01 章）。
- **工具=生态题** — Toolchain Ecosystem Choice：选型共享运维/管理预算（⚠️ 编者归纳）。

- **四问决策卡** — Tool Selection Rubric：用户/版式变更频/语义层位置/授权共用（⚠️ 编者归纳）。

## 最新演进与工业实践

2007 → 2026 对位（⚠️ 转述 + ✅ URL）：

- **四类产品被两朵云吃掉**：门户 → 融合应用工作区；报表/即席/仪表板 → **Oracle Analytics
  Cloud（OAC）+ OBI 现行线**（✅ https://www.oracle.com/analytics/ ）⚠️；Discoverer、
  BI EE 10g、Reports、BI Beans、Spreadsheet Add-ins 均已退役或停售 ⚠️（归档口径）。
- **语义层的存续**：BI EE 的 RPD 语义层思想由 OBI 的产品元数据仓储延续，并在 FAW
  预置语义中云化（✅ https://www.oracle.com/analytics/ ）⚠️；6.3 给 BI EE 独占 10 页的
  判断（语义建模是分析平台的脊梁）被后续 20 年验证——各现代栈（dbt metrics/语义层产品）
  重新发明了它（对照 [../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md](../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md)）。
- **嵌入式分析**：BI Beans 的「图表嵌进应用」诉求今天由 OAC embedded SDK / 各 BI iframe
  方案满足 ⚠️ 评价性转述。
- **数据挖掘入库的回归**：Data Miner 的路线在 19c/23ai 变成 OML4SQL/OML4Py 与
  PGX 家族（✅ https://docs.oracle.com/en/database/oracle/machine-learning/ ）⚠️——
  「模型围着数据跑」比「数据围着模型搬」更被 2026 工业实践认同。
- **自动报表**：BI Publisher 血脉仍在（OTBI/FAW 出货模板的后端之一 ⚠️ 据现行 SaaS 文档口径），
  是本章产品名单里长寿度最高者。
- **本机教学** 🔧：E3（+29.5% 写入税 vs 75× 读红利）解释「为什么即席工具要求库侧有汇总」；
  SQLite 触发器 MV ≠ Oracle 查询重写，**非 Oracle 行为**。
- **职能拆表的去处**：2026 年门户/报表/即席/嵌入四职能由 OAC、OTBI、嵌入 SDK 与第三方 BI
  重新组装，「纯 Oracle 栈选型」变成跨栈混选多数派——四问照旧管用，只是授权问更复杂
  （⚠️ 评价性转述）。
