# 讲 03 + 讲 10｜右值和移动、到底应不应该返回对象？

> **一句话**：C++11 之前，「返回大对象」天然意味着拷贝；C++11 之后，「返回对象」成了默认推荐——因为移动语义加上拷贝消除，让**按值返回既不损失正确性，也不必再为性能让路**。

## 核心精讲

> 以下均为**教学示意，不参与构建**。

### 1. 值类别决定你能不能「接管」

```cpp
// 教学示意：左值 / 右值 / 万能引用（不参与构建）
void take_ref(std::string& s)        { /* 只能绑左值 */ }
void take_const_ref(const std::string& s) { /* 左右值都能绑 */ }
void take_rref(std::string&& s)      { /* 只能绑右值 */ }

std::string a = "abc";               // a 是左值
take_ref(a);
take_const_ref(std::string("abc"));  // 临时对象是右值
take_rref(std::string("abc"));
```

设计判据很直接：**函数要不要接管调用者的资源？** 要，就接受 `T&&`；只想看，就接受 `const T&`；需要修改又不接管，接受 `T&`。

### 2. 完美转发：把值类别原样传下去

```cpp
// 教学示意：完美转发（不参与构建）
template <typename T, typename... Args>
std::unique_ptr<T> make(Args&&... args) {           // Args&& 是万能引用（引用折叠）
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}
// C++20 起可写成：return std::make_unique<T>(std::forward<Args>(args)...);
```

引用折叠规则只有两条心法：**引用叠加引用变成引用，其他情况只要出现一个右值引用就是右值引用。**

### 3. 移动构造：最简实现与三条纪律

```cpp
// 教学示意：移动语义骨架（不参与构建）
class Buffer {
    std::unique_ptr<char[]> data_;
    size_t size_ = 0;
public:
    Buffer(const char* s, size_t n) : data_(new char[n]), size_(n) {
        std::memcpy(data_.get(), s, n);
    }
    Buffer(Buffer&& other) noexcept                       // 移动：掠夺，源对象留空壳
        : data_(std::move(other.data_)), size_(other.size_) {
        other.size_ = 0;                                  // 源对象保持「可析构、可再赋值」
    }
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            data_ = std::move(other.data_);
            size_ = other.size_;
            other.size_ = 0;
        }
        return *this;
    }
    Buffer(const Buffer&)            = delete;            // 不需要拷贝就不给
    Buffer& operator=(const Buffer&) = delete;
    char* data() { return data_.get(); }
    size_t size() const { return size_; }
};
```

**moved-from 对象的三条纪律**（标准只保证它「可析构、可赋予新值」）：

1. 不要读取它的具体值；
2. 不要假设它为空；
3. 重新赋值之前不要再次使用它。

### 4. 返回值优化之外，还剩下什么

| 机制 | 是否必须发生 | 适用条件 |
| --- | --- | --- |
| RVO（返回值优化） | 不保证，实践中普遍发生 | `return T();` 之类直接构造返回值 |
| NRVO（命名返回值优化） | 不保证 | 返回的是函数内同一个具名局部对象 |
| 拷贝消除（C++17 起强制） | **保证** | 用 prvalue 初始化对象，如 `T x = f();` 中 `f()` 返回 prvalue 时直接构造 |

结论是：**不要把性能押在 RVO 上**。要保证「返回大对象不慢」，正确的做法是**提供 `noexcept` 的移动构造**——这是标准给的、可移植的保证。

```cpp
// 教学示意：按值返回的正确姿势（不参与构建）
std::vector<int> build() {                      // 直接构造返回值，省掉中间变量
    std::vector<int> v;
    v.reserve(1024);                            // 预先分配，避免多次扩容
    for (int i = 0; i < 1024; ++i) v.push_back(i * i);
    return v;                                   // 移动（或 RVO）；不会拷贝
}

std::vector<int> use() {
    std::vector<int> v = build();               // C++17：prvalue 直接构造，零中间对象
    return v;                                   // NRVO 或移动
}
```

### 5. 返回对象 vs 出参：三种「返回」方式的对比

| 方式 | 可读性 | 异常安全 | 适用场景 |
| --- | --- | --- | --- |
| `T f()` | 最好 | 对象构造失败即抛异常，调用方无需管半成品 | 默认选择 |
| `bool f(T& out)` | 一般 | 失败时 `out` 可能被部分写入 | 与 C 接口兼容、需要「失败码」时 |
| `std::optional<T> f()` | 好 | 无异常路径，调用方必须判断 | 可能失败、失败无需携带信息（C++17） |
| `std::expected<T, E> f()` | 好 | 无异常路径，可携带错误详情（C++23） | 需要错误信息且不想付异常成本（C++23） |

```cpp
// 教学示意：三种返回风格的对照（不参与构建）
std::optional<int> parse_optional(const std::string& s);      // C++17
std::expected<int, ParseError> parse_expect(const std::string& s);  // C++23

auto r = parse_expect("42");
if (!r) { report(r.error()); return; }                        // 用错误对象而非异常
use(*r);                                                      // 用 std::move(*r) 避免再次拷贝
```

> 判断顺序建议：**先按值返回；失败时若不需要信息就用 `optional`；需要结构化错误信息再上 `expected`；只有必须与 C 接口对齐、或返回多个彼此相关的结果时才考虑出参。**

### 6. 一个典型场景：swap 与异常安全的赋值

```cpp
// 教学示意：copy-and-swap 的历史价值与 2026 年的现状（不参与构建）
void swap(Buffer& a, Buffer& b) noexcept {   // noexcept 的 swap 是容器扩容的前提
    using std::swap;
    swap(a.data_, b.data_);
    swap(a.size_, b.size_);
}
// copy-and-swap 曾是实现「异常安全赋值」的经典手法；
// 但对移动赋值而言，直接写移动赋值运算符通常更快更直观。
```

## 版本演进

| 版本 | 变化 |
| --- | --- |
| C++98 | 只有拷贝；「避免返回对象」的世代建议（返回指针/出参）由此而来 |
| C++11 | 右值引用、移动语义、完美转发；标准容器普遍获得移动操作 |
| C++14 | 泛型 lambda、`decltype(auto)` 让转发代码更好写 |
| C++17 | **强制拷贝消除**（prvalue 不再物化中间对象）、`std::optional`、`inline` 变量 |
| C++20 | `constexpr` 意义上的移动、`std::string_view` 让「只读传参」不再拥有所有权 |
| C++23 | `std::expected`、`std::move_only_function`、多维下标；返回值类型进一步丰富 |
| C++26 | 反射与更完整的 `constexpr` 容器，使「编译期返回对象」成为常规操作 |

## 近年研究与工业界开源实践（2015–2026）

- **返回值成为主流风格**：现代 C++ API 普遍返回 `T`/`optional<T>`/`expected<T,E>`；出参（`out-param`）主要留在兼容 C ABI 的场合。
- **`noexcept` 的移动构造成了硬性要求**：`std::vector` 扩容若发现移动构造可能抛异常，会退化成逐元素拷贝；`folly`、`abseil` 的容器都显式要求 `noexcept` 移动。
- **`std::optional` 补上了「返回值的失败分支」**：在性能敏感路径上替代异常（异常在部分平台上仍有展开表开销与禁用约定问题）。
- **`std::pmr` 与「返回带内存资源的对象」**：多态分配器让「返回值携带分配策略」成为可能，避免了全局 `operator new` 的依赖。
- 🔧 **`std::expected` 正式进入标准（C++23）**：Google、Microsoft 的产品代码里「轻量错误返回值」的比例逐年上升；但异常并未退场——两者是**成本与可读性**的取舍，而非对错。
- 🔧 **编译期返回值**：`constexpr` 容器落地后，「返回一副棋盘、一棵树」这类操作可以直接发生在编译期，`std::array`/`std::vector` 都可以作为 `constexpr` 返回值。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「RVO 一定会被应用」 | RVO/NRVO 都不保证；可靠的是提供 `noexcept` 的移动构造 |
| 2 | 「移动之后源对象就空了」 | 标准只保证 moved-from 对象「可析构、可再赋值」，具体值不确定 |
| 3 | 「返回 `const T` 更安全」 | `const` 会抑制移动，反而强制拷贝；返回时不要加顶层 `const` |
| 4 | 「出参一定更快」 | 出参只是把构造时机挪到调用点，代价是接口可读性与异常安全变差 |
| 5 | 「返回值 + 异常是唯一组合」 | 冷路径用异常、热路径用返回值，是现代 C++ 的常见分层 |
| 6 | 「为类写移动构造就够了」 | 若移动构造可能抛异常，容器行为会退化；务必标 `noexcept`，并同时检查拷贝构造的可访问性 |
| 7 | 🔧 本讲缺少 `std::expected`（C++23）的正式落地 | 2026 年应明确：`expected<T,E>` 已进标准，新的「返回对象」代码默认从 `optional` 起步，需要错误详情时升级到 `expected` |
| 8 | 🔧 本讲未区分「返回对象的成本」与「构造对象的成本」 | 真正的大头往往是对象**内部堆缓冲的分配与释放**，返回值优化救不了它；用 `reserve`、自定义分配器或 `std::vector` 的移动缓冲 |
| 9 | 🔧 未提「返回引用 vs 返回值」的现代判据 | 返回引用仅限引用存在的对象（`std::span`、`std::string_view`）；返回局部对象应一律返回值 |
