# 讲 12 + 13 + 14 + 15｜编译期多态、编译期计算、SFINAE 与 constexpr

> **一句话**：模板不是「泛型工具」而是**一种多态机制**——把「选择怎么做」搬到编译期，零运行时开销；SFINAE 是这套机制的错误处理规则，而 `constexpr` 是它赖以成立的运行时。

## 核心精讲

> 以下均为**教学示意，不参与构建**。

### 1. 模板就是编译期的多态

```cpp
// 教学示意：同一份逻辑，不同形态（不参与构建）
template <typename T>
T max_of(T a, T b) { return a < b ? b : a; }          // 模板：为每种 T 生成一份代码

struct Shape { virtual double area() const = 0; };    // 虚函数：一份代码 + 一次间接
template <typename Derived>
struct AreaT { double area() const { return static_cast<const Derived&>(*this).area_impl(); } };

struct Circle : AreaT<Circle> { double radius; double area_impl() const { return 3.14 * radius * radius; } };
```

| 维度 | 虚函数 | 模板 / CRTP |
| --- | --- | --- |
| 绑定时机 | 运行期 | 编译期 |
| 调用开销 | 一次间接调用，通常不可内联 | 通常可内联，零开销 |
| 新增类型 | 不改模板即可（需实现接口） | 必须改模板或用 CRTP 适配 |
| 代码体积 | 一份 | 每种类型一份（实例化膨胀） |
| 错误信息 | 友好 | 常年以「模板错误金字塔」著称 |

**选择标准**：类型的集合在编译期已知且多样 → 模板；类型集合要开放给外部扩展 → 虚函数或 `std::function` + 类型擦除。

### 2. 类型推导与非类型参数

```cpp
// 教学示意：参数种类的多样性（不参与构建）
template <typename T, std::size_t N>
constexpr std::size_t byte_size() { return sizeof(T) * N; }

template <typename T>                 // 函数模板
void swap_two(T& a, T& b) noexcept(std::is_nothrow_move_constructible_v<T>) {
    T tmp = std::move(a); a = std::move(b); b = std::move(tmp);
}

template <template <typename> class Holder, typename T>   // 模板模板参数（较少用）
struct Wrap { Holder<T> inner; };
```

模板参数三兄弟：**类型参数**（最常见）、**非类型参数**（整数、指针、枚举）、**模板模板参数**（高阶抽象，实际用得少）。

### 3. `constexpr`：从「只能一条 return」到「编译期世界」

```cpp
// 教学示意：constexpr 的演进（不参与构建）
constexpr int f_cxx11(int x) { return x > 0 ? x : -x; }              // C++11：只能一条 return

constexpr int f_cxx14(int x) {                                       // C++14：多语句、循环、局部变量
    int n = 0;
    while (n * n < x) ++n;
    return n;
}

constexpr int f_cxx17(int n) {                                       // C++17：if constexpr 丢弃分支
    if constexpr (sizeof(int) == 4) { return n * 2; }
    else                            { return n; }
}
```

四条可以用来自查的规则：

1. **`constexpr` 函数是可用的函数**：编译期与运行期都能调用（除非用了 `consteval`）；
2. **`consteval`** 强制「只能在编译期求值」，用于校验函数；
3. **`constinit`** 强制「静态存储期变量必须被常量初始化」；
4. **编译期失败要可读**：`static_assert` + 适当的 `if constexpr` 分支。

### 4. `if constexpr` 与折叠表达式

```cpp
// 教学示意：编译期分派取代 tag dispatch（不参与构建）
template <typename T>
std::string to_debug(const T& v) {
    if constexpr (std::is_pointer_v<T>) { return "ptr"; }
    else if constexpr (std::is_class_v<T>) { return "class"; }
    else { return std::to_string(v); }                 // 未走到的分支不会实例化
}

template <typename... Args>
constexpr auto sum(Args... xs) {                       // C++17 折叠表达式
    return (xs + ... + 0);
}
static_assert(sum(1, 2, 3) == 6);                      // 编译期直接算完
```

> 折叠表达式的四种形态值得背下来：`(pack op ...)`、`(op ... pack)`、`(pack op ... op init)`、`(init op ... op pack)`，分别对应「二元折叠」「一元折叠」与指定初始值。

### 5. SFINAE：替换失败不是错误

```cpp
// 教学示意：经典的 enable_if 写法（不参与构建）
template <typename T>
typename std::enable_if<std::is_integral_v<T>, int>::type
only_integral(T) { return 1; }

template <typename T>
typename std::enable_if<!std::is_integral_v<T>, int>::type
only_integral(T) { return 0; }
```

现代写法（C++17 起）更短：

```cpp
// 教学示意：void_t 惯用法（不参与构建）
template <typename...> using void_t = void;
template <typename T, typename = void>
struct has_size : std::false_type {};
template <typename T>
struct has_size<T, void_t<decltype(std::declval<T&>().size())>> : std::true_type {};

static_assert(has_size<std::vector<int>>::value);
static_assert(!has_size<int>::value);
```

**SFINAE 的三条硬规则**：

1. 只有发生在**直接上下文（immediate context）** 中的失败才算 SFINAE；更深处的错误是硬错误；
2. 模板参数替换失败不等于「程序错误」，而是「这个候选不可用」，于是继续找别的候选；
3. 若所有候选都不可用，最终报「无匹配函数」——错误信息往往因此很难读（这正是 Concepts 的动机）。

### 6. 编译期字符串与哈希

```cpp
// 教学示意：consteval 校验 + 编译期哈希（不参与构建）
consteval std::size_t hash32(const char* s) {           // 只允许编译期调用
    std::size_t h = 2166136261u;
    for (; *s; ++s) { h ^= static_cast<unsigned char>(*s); h *= 16777619u; }
    return h;
}
constexpr std::size_t tag = hash32("alpha");           // 编译期算好，运行时直接用
```

## 版本演进

| 版本 | 变化 |
| --- | --- |
| C++98 | 模板可用但 `constexpr` 不存在；SFINAE 靠编译器扩展 |
| C++11 | 右尖括号修复、`constexpr` 单语句函数、`nullptr`、变长模板 |
| C++14 | **Relaxed `constexpr`**（N3652）：多语句、循环、局部变量；变量模板；泛型 lambda |
| C++17 | `if constexpr`、**折叠表达式**、`void_t`、模板参数自动推导（`auto` 参数）、`inline` 变量 |
| C++20 | **Concepts 取代大量 SFINAE**、`consteval`/`constinit`、`constexpr` 虚函数、`new`/`delete` 可用于常量表达式 |
| C++23 | **`std::vector`/`std::string` 进入常量表达式**（P2273 路线）、`static operator()`（P1169）、`if consteval`、多维下标（P2128） |
| C++26 | 反射提案推进、更多编译期容器与算法；编译期错误诊断持续改善 |

## 近年研究与工业界开源实践（2015–2026）

- **Concepts 让错误信息变好**：C++20 之后，`std::ranges` 一类库的报错从「几百行模板展开」变成「约束未满足」的一句话；这是模板技术最大的一次用户体验改善。
- **`if constexpr` 取代 tag dispatch**：曾经靠「继承一个空结构体」来分派的代码，现在只需一个 `if constexpr`，可读性显著提升。
- **编译期计算的收益被发现是双刃的**：编译期算得越多，编译时间越长、编辑器越卡；工业项目开始把「编译期/运行期的边界」当成性能指标之一（CMake 的 `-ftemplate-depth`、`-fmax-errors`、PCH/Unity build 都是相关手段）。
- **`consteval` 用于 API 校验**：把「参数必须合法」写成 `consteval` 前缀，非法输入直接编译失败。
- 🔧 **编译期容器落地（C++23/P2273）**：`constexpr std::vector`/`std::string` 让「编译期拼一张查找表」成为常规写法，配合 `if consteval` 可以让同一个函数同时服务编译期和运行期。
- 🔧 **`static operator()`（P1169）**：有状态的 functor 与无状态 functor 现在可以共存于一个变量模板，模板里不再需要为了「可转成函数指针」而反复改写法。
- 🔧 **反射提案**：C++26 方向的语言级反射一旦落地，本章的很多「手写特化 + 特化表」都会被砍掉（本文不写编号，请以 WG21 提案列表为准）。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「有虚函数就够了，模板不必学」 | 两者是不同 Mechanism：模板零开销但封闭，虚函数开放但有间接成本；CRTP 是兼得方案 |
| 2 | 「SFINAE 是模板出错时的容错机制」 | 它不是容错，而是「重载决议的候选筛选规则」；失败发生在更深处就是硬错误 |
| 3 | 「`constexpr` 函数只能在编译期跑」 | 它可以两边都跑；要用 `consteval` 才强制编译期 |
| 4 | 「`if constexpr` 和 `if` 差不多」 | 未走到的分支**根本不会实例化**，因此那里可以写任何非法代码；这是它最大的价值 |
| 5 | 「所有计算都搬到编译期就好」 | 编译时间与调试成本会同步上升；对大量实例化的代码要权衡 |
| 6 | 🔧 本讲把 `enable_if` 当作模板约束的标准手段 | 2026 年的首选是 `requires` 子句与 `std::same_as` 等概念；`enable_if` 主要留给「SFINAE 参与重载集」的场合 |
| 7 | 🔧 本讲缺少一个可用的编译期容器方案 | C++23 起 `constexpr std::vector`/`std::string` 可用；配合 `if consteval` 可以让「查表」逻辑同源 |
| 8 | 🔧 本讲未提 `static operator()`（P1169）与 `if consteval` | 前者让无捕获 lambda 可隐式转函数指针，后者让同一个函数体同时服务两个世界 |
| 9 | 🔧 对反射只字未提 | 反射（C++26 方向）会直接改写「手写特化表」这一整类模式，建议保持跟进 |
