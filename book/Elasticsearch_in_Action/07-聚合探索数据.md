# 07 · Exploring your data with aggregations（用聚合探索数据）

> 取证基座：二级节 7.1–7.4（聚合解剖/指标聚合/嵌套聚合/小结）✅ getTocHtml?id=548 实抓；正文精读重构，⚠️ 转述，🔧 本机类比（**非 ES 行为**）。

## 章定位

「不搜文档，搜数据」：把 1.x 刚成熟的 aggregation DSL（取代 facets）讲成两问——按什么**分桶**（bucket）、桶里算什么**指标**（metric）。餐厅场景落地为：菜系分布、评分直方图、每周新增点评数。聚合直接消费第 3 章的 keyword/doc_values 建模决策，是「建模错了聚合就贵」的验收章。对位 [../Elasticsearch_The_Definitive_Guide/03-聚合.md](../Elasticsearch_The_Definitive_Guide/03-聚合.md)。

## 内容地图（原书二级节 ✅ 实抓）

- 7.1 聚合解剖学：aggregations 块挂在 _search 里、与 query 平行；`terms` 桶 + `avg` 指标的最小标本；1.x 老名 `histogram`/`date_histogram`
- 7.2 指标聚合：min/max/sum/avg/stats、extended stats、percentiles（t-digest 近似，⚠️ 书涉）、cardinality（HLL 近似去重）
- 7.3 嵌套聚合：桶套桶套指标；`filter`/`filters`/`range` 作为子桶；`nested` 聚合衔接第 8 章
- 7.4 小结（成本告诫：桶的乘积=内存与 CPU 的乘积）

## 7.1 桶×指标的最小模型（⚠️ 转述）

```
GET /reviews/_search
{ "aggregations": { "by_cuisine": { "terms": {"field": "cuisine"},
    "aggs": { "avg_rating": {"avg": {"field": "stars"} } } } } }
```

terms 桶按词项分组并按 doc_count 排序（默认取 top N——**只见冰山**，其他桶并入 `sum_other_doc_count`），桶内 avg 消费 doc_values。这一「管道+子管道」递归结构 12 年未变（✅ 现代面 https://www.elastic.co/guide/en/elasticsearch/reference/8.17/search-aggregations.html 实抓）。
1.x 词汇表：`facets` 已弃、`aggs` 上位；`global`/`missing` 桶处理「跨过滤与缺值」。

🔧 类比组 G（SQLite 3.45.3 实跑，5 行餐厅点评小表）：

```sql
SELECT name, count(*), round(avg(stars),2) FROM r GROUP BY name ORDER BY count(*) DESC;
-- Thai (2, 4.5) / Pizza (2, 3.5) / Deli (1, 5.0)
SELECT substr(dt,1,7) m, count(*) FROM r GROUP BY m;   -- 2015-01:3 / 2015-02:2（≈date_histogram）
SELECT name, stars, count(*) FROM r GROUP BY name, stars;  -- ≈桶套桶
```

GROUP BY=terms 桶、聚合函数=metric、substr 分组=date_histogram——**但 SQL 是全集精确分组，ES terms 默认 top-N 截断 + 近似分位数**，语义差异正是本章 7.4 成本告诫的来源。非 ES 行为。

## 7.2 指标聚合与「近似」经济学（⚠️ 转述）

1.x 的 percentiles 用 t-digest、cardinality 用 HyperLogLog：**精确去重百万级基数的代价是内存，近似版以 ~1KB 级换 ±5% 误差**——这是全书「数据规模改变算法选择」最直白的案例。stats/extended_stats 一次给出 count/min/max/sum/avg/方差族。
今值：precision_threshold、tdigest compression 旋钮依旧（✅ 同族 8.17 search-aggregations）；精确去重需求改走 composite 聚合分页或 ES|QL 管道（⚠️；ES|QL 本体 ✅ https://www.elastic.co/docs/explore-analyze/query-filter/languages/esql）。

## 7.3 嵌套聚合：桶的乘积就是账单（⚠️ 转述）

terms(城市)→terms(菜系)→date_histogram(月)→avg(评分) 四段管道；每加一层桶，协调节点要合并的部分结果翻倍。书中告诫：`execution: heap`（1.x 直方图老旋钮）与分片数放大成本。nested 聚合（配合第 8 章）按子文档路径重新起域计数——「数组里对象的成对条件」只有它算得对。

## 工程要点与常见坑

- 聚合字段必须 keyword + doc_values；对 text 聚合触发fielddata（1.x 默认禁，报错即提醒——把第 6 章 field data 的教训再收一遍）。
- terms 的 top-N 截断会让「占比很小但重要的桶」消失——需要全量时用 composite（今式）或拆查询。
- 过滤+聚合的组合：`filter` 聚合内嵌与 query 上下文过滤结果不同（后者进相关性计分）；仪表盘正解多为 filter 聚合（✅ 现代 search-request-body 同族）。
- 高基数 date_histogram（秒级×一年）先想 interval 再想加机器（书中 7.4 的算术）。

## 聚合骨架对照（⚠️ 转述，1.x 版式）

```bash
curl -XGET 'localhost:9200/reviews/_search?pretty' -d '{
  "size": 0,                                   # 只要聚合不要文档
  "query": { "range": { "stars": { "gte": 3 } } },
  "aggs": {
    "by_cuisine": {
      "terms": { "field": "cuisine", "size": 20 },
      "aggs": {
        "avg_stars":  { "avg": { "field": "stars" } },
        "card_users": { "cardinality": { "field": "user_id" } },
        "over_time":  { "date_histogram": { "field":"date", "interval":"1M",
                             "format":"yyyy-MM" },
                        "aggs": { "p99": { "percentiles": { "field":"stars" } } } }
      }
    }
  }
}'
```

读法四层：`size:0` 是仪表盘姿势；terms 桶的 `size:20` 即 top-N 截断点；
`cardinality/percentiles` 是 7.2「近似经济学」的两个样本；
date_histogram 嵌在 terms 桶内=「菜系×月」矩阵——桶的乘积就是账单（7.4）。
1.x 的 `interval:"1M"` 今为 `calendar_interval:"1M"`（⚠️ 参数改名转述，✅ 同族 search-aggregations）。

## 章内问答（自测）

**Q1 为什么聚合不用倒排而另建正排？**
A：聚合要「值→文档集」的列式访问（doc_values），倒排是「词项→文档」且 text 分词后值失真——这是第 6 章 field data 对偶的现代答案。
**Q2 top_hits 为什么危险？**
A：每桶塞一小组完整文档，桶数×size=内存乘法爆炸；书中「别在深桶里放 top_hits」告诫今仍成立（⚠️）。
**Q3 date_histogram 空桶为何出现？**
A：`min_doc_count:0`+`extended_bounds` 显式要求补零；默认稀疏输出，画图侧自行补轴。

## 核心概念速览（中英对照）

1. **桶聚合** — Bucket Aggregation：按键把文档分组（terms/histogram/range/nested）。
2. **指标聚合** — Metric Aggregation：桶内单值/多值统计（avg/percentiles/cardinality）。
3. **terms 聚合** — Terms Agg：词项分组取 top N，doc_count 排序。
4. **date_histogram** — Date Histogram：按日历间隔分桶的时间直方图。
5. **嵌套聚合** — Nested Aggregations：桶→子桶→指标的递归管道。
6. **top-N 截断** — Size/sum_other_doc_count：terms 只见冰山，其余计数折叠。
7. **近似去重** — Cardinality (HLL)：HyperLogLog 以误差换常数内存。
8. **分位数估计** — Percentiles (t-digest)：近似分布摘要，仪表盘常客。
9. **doc_values** — Doc Values：聚合/排序消费的磁盘列存正排。
10. **composite 聚合** — Composite Agg：after_key 游标分页遍历全部桶（1.x 尚无）。
11. **filter 聚合** — Filter Agg：在聚合层重新起过滤域，与计分过滤互补。
12. **facets（已废）** — Facets：aggs 之前的旧聚合面，1.x 正处弃用点。

## 最新演进与工业实践

- **管道不变，入口翻倍**：8.x 聚合 DSL 与本章同构（✅ https://www.elastic.co/guide/en/elasticsearch/reference/8.17/search-aggregations.html）；新增矩阵/管道族（serial_diff、bucket_sort）与 composite 分页遍历（⚠️ 专页本环境未逐条验，官方聚合总览以 search-aggregations 为准）。
- **ES|QL 分流**：分析型用户从 DSL 聚合转向 ES|QL 管道（`STATS ... BY ...`）——GROUP BY 心智直接复活，官方 GA 线 ✅ https://www.elastic.co/docs/explore-analyze/query-filter/languages/esql。
- **近似算法换代**：cardinality 的 HLL++、percentiles 的 HDR 双实现并存在今（⚠️ 转述；同族参数文档 ✅ search-aggregations）。
- **仪表盘工业形态**：Kibana 把 terms/date_histogram 组合成产品化面板；Serverless 按查询算力计费让「桶的乘积=账单」从内存警告升级为真金白银（✅ https://www.elastic.co/cloud/serverless）。
- **向量时代余韵**：聚合之外新增 `weighted_sum`/retriever 内重排消费路径——「聚合=非相关性的数据探索」定位未动（⚠️，检索面 ✅ https://www.elastic.co/docs/solutions/search）。
