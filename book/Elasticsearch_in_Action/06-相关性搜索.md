## 6.1 1.x 打分公式的心智（⚠️ 转述）

书中原式骨架：`score = tfidf(query, field) × coord × query_norm × field_norm`。
- tfidf：词频×逆文档频率×词长归一（Lucene 经典 TFIDFSimilarity）。
- **coord**：命中查询词占全部词的比例（「搜两个词中一个」折半）——BM25 时代已删。
- field/query norm：字段长度与查询修饰的归一乘子——8.x 的 norms 只剩字段长度一义。
5.0 默认切 BM25 并删 constant_score_factor 类组件（✅ https://www.elastic.co/guide/en/elasticsearch/reference/5.0/breaking-changes-5.0.html 实抓）。BM25 的 k1/b 饱和度旋钮今在 index similarity 里可配（✅ 同族 8.17 https://www.elastic.co/guide/en/elasticsearch/reference/8.17/index-modules.html）。

🔧 类比组 C（SQLite 3.45.3 实跑）：三文档小语料，`bm25(r, 1.0, 10.0)` 给 title 列 10 倍权重——`elasticsearch AND search` 命中排序：'es guide'（-4.0398e-06）先于 'deep'（-3.9440e-06），**越小越靠前**。这同时类比了本章两件事：①字段权重=boost 的心智；②BM25 的列加权（= 8.x `fields^boost`）。FTS5 bm25 无 norm/coord/衰减函数——**仅排序方向与权重语义可类比，公式不同构，非 ES 行为**。

## 6.3–6.6 调权工具箱（⚠️ 转述）

- boost：查询级（`"boost": 2`）叠字段级（`title^3`）；1.x 还有索引级 `index.boost`（后删）。原则：**先建模后 boost，boost 是补丁不是设计**。
- function_score（本章王牌）：把业务信号（热度、新鲜度、地理位置、评分）乘/加进文本分。1.x 函数族 script_score/gauss/exp/linear + score_mode/operators 组合；今式函数族原样在（✅ https://www.elastic.co/guide/en/elasticsearch/reference/8.17/query-dsl-function-score-query.html 实抓，脚本函数换 painless）。
- rescore：窗口 `query_window_size` 内换更贵的打分（脚本或重查询）——今天的 kNN/learning-to-rank 精排仍是同一形态（⚠️ LTR 属第三方/官方实验线，不背书）。
- explain：`"explain": true` 返回分数因式分解树，调权闭环的眼睛（✅ 观测同族 search-profile https://www.elastic.co/guide/en/elasticsearch/reference/current/search-profile.html）。

## 6.8–6.9 脚本排序与 field data（⚠️ 转述）

sort 表达式在 1.x 由 Groovy 执行、可被任意查询触发→**脚本注入与缓存爆炸**双风险，书中警告后文成官方沙箱化叙事（5.0 默认 Painless ✅ 同族 https://www.elastic.co/guide/en/elasticsearch/reference/8.17/modules-scripting-painless.html）。
field data：从倒排「现场构建正排」的进程内缓存，OOM 重灾区；1.x 的正解是 **doc_values**（磁盘列存、构建期生成，排序/聚合默认走它）。6.9 一节等于「为什么不要现场转正排」的数据库通识——与列存数据库的预计算正排（[../DuckDB_Up_and_Running/00-总览与阅读地图.md](../DuckDB_Up_and_Running/00-总览与阅读地图.md)）同一族思想 ⚠️ 类比视角。

## 工程要点与常见坑

- must/should 混用致分数不可解释：should 默认只加分不排错，缺 minimum_should_match 时「零硬条件」查询返回 match_all 分数——第 4 章 bool 的经典回声。
- 热度衰减函数选高斯还是线性取决于业务分布，先画分布再配 decay（书中 6.7 串讲的工程美德）。
- 脚本别在 sort 里做重正则：每命中一次算一次；预算放 rescore 窗。

## 调权实验台（⚠️ 转述，1.x 版式）

```bash
curl -XGET 'localhost:9200/restaurants/_search?pretty' -d '{
  "query": {
    "function_score": {
      "query": { "bool": {
        "must":  [ { "multi_match": { "query":"greek", "fields":["name^3","dish"] } } ],
        "filter":[ { "term": { "open": true } } ]
      }},
      "gauss":   { "date": { "origin":"2015-03-08","scale":"10d","decay":0.5 } },  # 新鲜度衰减
      "field_value_factor": { "field":"stars", "modifier":"log1p" },               # 评分因子（今式名）
      "boost_mode":"multiply", "score_mode":"sum",
      "max_boost": 10
    }
  },
  "rescore": { "window_size": 100, "query": { "boost": 2 } },
  "explain": true
}'
```

逐块读法：multi_match 的 `^3` 是字段级 boost；gauss/linear/exp 构成「业务曲线」族；
`boost_mode/score_mode` 决定文本分与函数分的合流代数；explain 树里 1.x 可见
coord/norm 节点（8.x 同位置换成 BM25 的 `score`+`norm` 注释）；
rescore 窗是「先粗后精」的成本闸门——这三层结构今天分别对应 boost、retriever 权重、Rerank。

## 章内问答（自测）

**Q1 为什么 should 不影响「入围」只影响「排名」？**
A：bool 语义里 should 默认是可选项（至少 0 命中）；要硬条件须 minimum_should_match——分数与布尔门槛是两套机制。
**Q2 rescore 何时比全量精算划算？**
A：精算成本超线性（脚本/模型）且只看头部结果时；窗口=召回预算，错了就是「排名断层」。
**Q3 为什么「先建模后 boost」？**
A：boost 只改乘子不改命中集；建模（字段拆分/分析器/多字段）决定召回上限——顺序反了调的是噪声。

## 核心概念速览（中英对照）

1. **TF-IDF** — 词频×逆文档频率：1.x 默认打分的词法质量内核。
2. **BM25** — Okapi BM25：带饱和度(k1)与长度归一(b)的概率检索打分，5.0 起默认。
3. **协调因子** — Coordination（coord）：命中词占比乘子，1.x 时代遗物，已删。
4. **字段长度归一** — Field-length Norm：短字段得分更高的归一项。
5. **提升** — Boost：查询/字段/索引层叠乘的手动调权。
6. **function_score** — Function Score：业务信号（衰减/因子/脚本）合成进文本分。
7. **重排序** — Rescore：窗口内用更贵打分精算，成本换质量。
8. **explain API** — Explain：输出分数的因式分解以审计调权。
9. **doc_values** — Doc Values：构建期磁盘列式正排，排序/聚合免 field data。
10. **field data** — Field Data：运行时转正排的进程内缓存，历史 OOM 元凶。
11. **painless** — Painless：5.0 起的沙箱脚本语言，函数/排序脚本的安全载体。
12. **学习排序** — Learning to Rank（LTR）：以特征+模型替代手调 boost 的现代路线（⚠️ 本册基线无此概念）。

## 最新演进与工业实践

- **默认打分换芯**：1.x TF-IDF→5.0 BM25（✅ breaking-changes-5.0 实抓），coord/norms 精简、similarity 可配（✅ 8.17 index-modules）；本章「分数是乘积森林、explain 是唯一真相」的方法论无损。
- **function_score→retrievers/rank**：8.x 保留 function_score（✅ query-dsl-function-score-query 8.17 实抓）并在其上叠 **retriever 框架 + RRF 融合**——「文本分与语义分怎么合流」的最新官方答案（✅ https://www.elastic.co/docs/reference/elasticsearch/rest-apis/retrievers）。
- **向量精排**：dense_vector kNN + rescore 向量重打分（✅ https://www.elastic.co/docs/solutions/search/vector/knn），脚本排序的老位置现在是 inference 模型（ELSER/稠密嵌入经 inference API，✅ sparse-vector 文档同族）。
- **LLM 相关性**：工业上以 LLM 做 query rewriting 与 rerank 服务外置（⚠️ 转述）；官方检索编排（RAG/语义搜索）见 https://www.elastic.co/docs/solutions/search 与 search-labs（✅ 均实抓可达，访问 2026-09-27）。
- **工业实践**：2026 的相关性栈共识——BM25 打底、向量补语义、RRF/LTR 融合、业务 boost 兜底；调权纪律（先建模后 boost、explain 常开在灰度环境）与本章 2015 建议逐字同构。
