# 02 管道与活动：编排核心对象 — Pipelines and Activities（⚠️ 重构章，非原书 TOC）

> 章题为 ⚠️ 推定重构（00 §2）；对象模型 = 官方文档转述 ⚠️ + ✅ URL；FDF 控制台本机不可实测（⚠️），

## 2.1 管道（Pipeline）：可部署的编排单元

权威页：`https://learn.microsoft.com/en-us/fabric/data-factory/data-factory-overview` ✅ F1；
ADF 语法同源页：`https://learn.microsoft.com/en-us/azure/data-factory/control-flow-execute-pipeline-activity` ✅ A3。
要点 ⚠️：

- 管道 = **活动的有向图 + 参数签名**，是 FDF 中可独立运行、可版本化、可随部署管线迁移的
  一等 item；JSON 定义（`pipeline.json`）与 Fabric Git 集成目录一一对应（08 章展开）。
- 触发方式三族 ⚠️：手动/即时、定时（schedule）、事件驱动（官方事件触发器支持面以现行文档
  为准；本册未验到专页 URL，细节标 ⚠️）。
- 管道可嵌套管道：`ExecutePipeline` 活动（✅ A3 即该活动专页）是剧本复用的核心——
  「子管道 = 函数，主管道 = 编排脚本」，Playbook 体裁的推荐粒度。
- 参数化是管道的「函数签名」：`mystartDateTime` 一类参数贯穿 07 章增量剧本，此处先立骨架。

## 2.2 活动（Activity）四大类速览（⚠️ 转述，Fabric 支持面逐项以 F2 为准）

| 类别 | 代表活动 | 剧本角色 | 佐证 |
| --- | --- | --- | --- |
| 移动 | Copy | 数据搬运主力 | ✅ A2 copy-activity-overview / F7 copy job（03 章） |
| 控制流 | IfCondition / ForEach / Filter / Wait / ExecutePipeline / SetVariable / AppendVariable | 流程骨架 | ✅ A3 页内活动家族目录 |
| 数据操作 | Lookup / GetMetadata / Delete / Web / Azure Function 类 | 元数据驱动编排 | ✅ A3 同族（FDF 内对应活动名 ⚠️） |
| 转换 | Notebook / Spark job definition / Stored Procedure / Data Flow | 计算下沉到引擎 | ✅ F5/F6（05 章）、✅ A4（04 章） |

- **Lookup vs GetMetadata** 是本册反复使用的一对：Lookup 取「行内容」（如水位线表最后一行），
  GetMetadata 取「文件/表元数据」（修改时间、行数估计）——07 章增量剧本的传感器。
- Delete/Web 这类「小活动」是幂等剧本的胶水：先删目标分区再写入，用 GetMetadata 判断
  「文件是否已到」再触发下游，都是 Playbook 级套路 ⚠️ 编者归纳。

## 2.3 依赖、状态与失败语义（编排正确性的三根柱子）

- 活动间用 **成功/失败/完成（onSuccess/onFailure/onCompletion）** 依赖边连接 ⚠️（ADF 语法，
  FDF 同源）；无依赖边的活动可并行——「画图上找关键路径」就是 FDF 性能的第一性视角（10 章）。
- 管道运行状态机 ⚠️：InProgress/Succeeded/Failed/TimedOut/Cancelled；重试（retry 属性）
  与并发上限（ForEach 的 sequential/parallel 度）是「reliable pipelines」（副题 ✅）的
  两个最直接旋钮。
- 幂等剧本三件套 ⚠️ 编者归纳：①目标端「删后写」或「MERGE」（🔧E3 见 07 章）；②运行级
  唯一批次号参数；③失败路径显式 Fail 活动 + 告警（09 章）——副题承诺的 reliable 不是
  平台白送的，是剧本写出来的。
- 超时与重试的组合陷阱：重试次数 × 超时时长构成最坏运行时长上界，排班窗口要按上界
  而非期望值设计 ⚠️。

## 2.4 画布、JSON 与「双视图工作法」

- FDF 管道同时提供可视化画布与 JSON 视图 ⚠️；官方教程线（✅ F8
  tutorial-end-to-end-pipeline）以画布为主，工程实践建议：
  ①评审看 JSON（diff 友好，Git 集成提交的即此物 ✅ C2）；②大改结构用画布（依赖边拖拽）；
  ③表达式（`@activity(...)`、`@pipeline(...)` 动态内容）一律在 JSON 里核对转义。
- Copilot 参与创作（✅ F9 copilot-fabric-data-factory）：自然语言生成管道骨架 ⚠️，
  剧本纪律：**生成后必过 2.3 三件套检查**，不让 Copilot 决定幂等策略。

## 2.5 组织剧本：一个「到达即入库」的最小管道（⚠️ 转述级伪流程，非书中原文）

1. GetMetadata（源容器）→ 2. IfCondition（新文件存在？）→ 3. Copy（入湖暂存区）→
4. Notebook 活动（bronze→silver 清洗，05 章）→ 5. Lookup（读回行数）→ 6. SetVariable +
7. 子管道（写审计表，🔧E3 的 MERGE 语义类比）→ 失败边 → Fail + 告警（09 章）。

- 每步都对应 2.2 表中一行——这就是 Playbook 章法：**剧本 = 活动表 + 依赖图 + 失败语义**。
- 本册后续章各负责把其中一幕放大：03（步骤 3）、05（步骤 4）、07（步骤 1/2/5/7）、
  08（整条管道的部署）、09（失败边之后发生什么）。

## 核心概念速览（中英对照）

- **管道** — Pipeline：活动有向图 + 参数签名的可部署编排单元，FDF 一等 item ⚠️（✅ F1）。
- **活动** — Activity：编排最小执行单位，移动/控制流/数据操作/转换四类（2.2 表）。
- **子管道调用** — ExecutePipeline activity：管道嵌套实现「函数化复用」（✅ A3）。
- **依赖边** — Dependency (onSuccess/onFailure/onCompletion)：状态驱动的图执行语义 ⚠️。
- **查找活动** — Lookup：读源端行内容（水位线读取传感器，07 章）。
- **元数据活动** — GetMetadata：读文件/表元数据（到达性判断传感器）。
- **动态内容** — Dynamic content（`@activity(...)` 表达式族）：活动输出→下游输入的胶水 ⚠️。
- **幂等三件套** — 删后写/MERGE + 批次号 + 显式失败路径：reliable pipelines 的写法纪律 ⚠️ 编者。
- **双视图工作法** — 画布改结构、JSON 做评审：Git 集成提交物即管道 JSON（✅ C2）。
- **Copilot 生成 + 人工过检** — ✅ F9 能力面 + 2.4 纪律。

## 最新演进与工业实践

- **语法稳定性红利**（⚠️ 转述）：管道/活动 JSON 模式自 ADF 时代（✅ A2/A3 文档线多年未挪）
  高度稳定，FDF 继承后学习资产可跨三种承载复用——这是 1.5 节「三承载同族」的工程价值。
- **事件驱动与告警面扩张**：Fabric 侧监控/告警体验持续迭代（✅ F4 monitor 页现行版），
  2026 实践建议把「触发方式支持面」列入每季度复核清单 ⚠️（本册 09 章口径日 2026-10-01）。
- **工业实践**：大型 FDF 工厂普遍收敛活动类型使用面（只允许白名单内活动进生产管道）并
  把 2.3 三件套写进代码评审模板 ⚠️ 编者综合；Copilot 生成管道的评审增量成本主要在表达式
  转义与依赖边方向（2.4）。
- **本机互鉴** 🔧：想理解「依赖边状态机」，可用 python 顺序脚本 + 异常分支模拟最小版，
  体会「重试/超时上界」对排班窗口的影响（**非 Fabric 平台行为**）。
