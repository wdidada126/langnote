## 8.1 副题第一承诺：CI/CD（✅ 封面 OCR → 官方三页）

- 总览：`https://learn.microsoft.com/en-us/fabric/cicd/cicd-overview` ✅ C1 —— Fabric 的
  CI/CD 是「Git 集成 + 部署管线」双轨 ⚠️，不是单一功能。
- Git 集成：`https://learn.microsoft.com/en-us/fabric/cicd/git-integration/intro-to-git-integration` ✅ C2
  —— 工作区与外部仓库（Azure DevOps Git/GitHub 等，支持清单以 C2 现行页为准）双向同步，
  **每个 Fabric item 对应目录中的 JSON/定义文件**，管道即 `pipeline.json`（02 章双视图工作法
  的提交物）。
- 部署管线：`https://learn.microsoft.com/en-us/fabric/cicd/deployment-pipelines/intro-to-deployment-pipelines` ✅ C3
  —— dev→test→prod 工作区链的**项级提升（promotion）**与设置重绑（settings 与定义分离）⚠️。

## 8.2 两种工作流的选择（⚠️ 转述 + 编者决策表）

| 工作流 | 主干 | 适合 | 风险 |
| --- | --- | --- | --- |
| Git 集成双向 | 仓库=真相，门户可同步回写 | 数据团队日常开发（分支=工作区） | 双向同步冲突面；非代码 item 的合并语义 ⚠️ |
| 部署管线单向 | dev 门户开发→管线提升 | 环境隔离强、审批重的企业 | 仓库真相需另行保证 |

- 剧本建议 ⚠️ 编者归纳：管道/笔记本/作业定义等**可 JSON 化资产**走 Git 集成做评审；
  环境间移动走部署管线做提升；两轨并用时以「仓库为唯一真相、部署管线只搬已评审版本」
  定纪律，避免 test 环境热修不回仓的经典黑洞。
- 凭据与参数（07 章 7.1 的入参、03 章 3.2 的连接凭据）**不随定义包走** ⚠️——提升后
  重绑是部署剧本的固定步骤，写进 runbook 而不是靠记忆。

## 8.3 分支策略与管道评审（Playbook 的「合入前清单」页）

- 分支模型 ⚠️ 转述 C2 主题：Fabric Git 集成的分支映射工作区机制（分支切换=工作区内容
  切换）使「feature 分支=沙箱」零成本成立；主分支合入前评审清单：
  ①02 章幂等三件套是否齐（重试/超时/失败边）；②03 章显式列映射；③07 章窗口参数命名与
  断言；④05 章笔记本返回值契约；⑤凭据引用而非明文（Secret 面 ⚠️ 以现行文档为准）。
- 管道 JSON 的 diff 可读性技巧 ⚠️ 编者：活动排序稳定化（按依赖拓扑序手写整理一次）、
  注释字段纪律（若平台保留 ⚠️ 以现行行为为准）——评审成本主要花在乱序 diff 上。
- Copilot/可视化改动同样过此清单（02 章 2.4 纪律的部署侧延伸）。

## 8.4 测试金字塔在 FDF 的落地（⚠️ 编者框架）

- **L1 单元**：笔记本/Spark 作业内函数级测试（05 章作业定义档最受益；跑在 CI 计算资源上，
  Fabric 外测试面 ⚠️ 不夸大）。
- **L2 管道级**：test 工作区用**影子参数**（指向样本容器/小窗口）即时运行（02 章 2.1 手动
  触发档），断言=07 章审计表行数对账。
- **L3 链路级**：部署管线目标环境的冒烟管道（最小窗口跑通全链，09 章告警静默窗口配合）。
- 环境矩阵 ⚠️：dev/test/prod 工作区 + 容量分区（10 章）在 C3 管线对象中一一对应；
  「环境即工作区」是 Fabric 与传统 ADF ARM 模板路线的最大手感差异（✅ F2/F10 历史语境）。

## 8.5 版本回滚与事故剧本

- 回滚 = 仓库 revert + 再提升（Git 集成路线）或部署管线的历史版本提升（若支持 ⚠️ 以 C3
  现行页为准）；**数据不回滚**——管道版本回滚后，脏数据按 07 章 7.5 重放剧本处理，
  两件事分开写 runbook ⚠️ 编者纪律。
- 事故复盘模板字段：影响窗口（水位线区间）/受影响批次（run_id 清单，07 章审计表）/
  定义版本（commit SHA）/数据修复方案（重放参数）——编排事故的四元组定位法。

## 8.9 一页小结卡（背卡式 ⚠️ 编者）

- 双轨：Git 集成（✅ C2，仓库真相）+ 部署管线（✅ C3，环境提升）；总览 ✅ C1。
- 纪律：凭据不随包走、提升必重绑、test 热修必回仓。
- 清单：合入前七项（8.7）打印贴工位；影子参数跑 L2。
- 回滚：定义与数据分开处置；复盘四元组=窗口/批次/commit/修复。
- 演进锚：支持 item 清单季度复核（✅ C2/C3 现行页），骨架两轨不依赖清单成立。

- 环境矩阵：dev/test/prod 工作区 + 容量分区一一对位（8.4）；「环境即工作区」是与
  ADF ARM 模板路线的最大手感差（✅ F2/F10 历史语境）。

## 核心概念速览（中英对照）

- **Git 集成** — Git integration：工作区↔外部仓库双向同步，item 即文件（✅ C2）。
- **部署管线** — Deployment pipelines：dev→test→prod 项级提升与设置重绑（✅ C3）。
- **提升** — Promotion：定义跨环境移动；凭据/参数不随包走（8.2 纪律 ⚠️）。
- **分支即沙箱** — branch-to-workspace 映射：feature 分支隔离开发（✅ C2 主题）。
- **合入前清单** — 幂等/显式映射/窗口断言/返回契约/无明文密钥（8.3 五连）。
- **影子参数** — 测试用小窗口/样本容器（L2 管道级测试 ⚠️ 编者）。
- **数据不回滚** — 定义回滚与数据重放分离的 runbook 纪律（8.5）。
- **四元组定位** — 窗口/批次/版本/修复：事故复盘字段法（8.5）。
