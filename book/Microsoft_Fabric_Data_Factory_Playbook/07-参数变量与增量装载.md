## 7.1 参数与变量：管道的函数签名与局部状态（⚠️ 转述）

- **参数（parameters）**：管道级入参，运行时/触发时注入，是「同一管道多环境跑」的前提
  （08 章部署时参数重绑的对象）；ADF/FDF 语法同源（✅ A3 活动族页内表达式体系、✅ F1 概览）。
- **变量（variables）**：管道运行内可变状态，配合 SetVariable/AppendVariable 活动累积
  （✅ A3 同族文档目录中的控制流家族）。
- **动态内容表达式**：`@activity('x').output...`、`@pipeline().parameters...`、UTC 时间函数族
  ⚠️（ADF 线文档齐全，FDF 侧同名继承，以 F2 复核）。
- 剧本纪律 ⚠️ 编者归纳：窗口参数一律**命名语义化**（`windowStart/windowEnd` 而非 `p1/p2`）、
  一律 **UTC ISO8601 字符串**入参、在管道入口做一次格式断言——90% 的增量事故死于
  时区/格式在链条中段漂移。

## 7.2 增量装载主剧本：水位线（watermark）模式（⚠️ 通用工程 + 平台落点）

六步剧本（对象名对应 02 章活动表）：

1. **读上界**：Lookup 活动读审计表（`SELECT max(wm) FROM ctrl.watermark`）→ 存变量；
2. **定窗口**：`windowStart = 上次水位`，`windowEnd = min(now, 计划上界)`——表达式在入口断言；
3. **搬增量**：Copy（谓词 `modified >= windowStart AND modified < windowEnd`）落 bronze
   暂存（✅ F7/A2 的 copy 语义；源侧谓词下推支持面 ⚠️ 认 F3 连接器矩阵）；
4. **收编**：Notebook/作业定义把暂存 MERGE 进目标表（🔧E3 实证语义，05 章接缝）；
5. **推水位**：审计表更新为本批实际 max（**用数据里的水位，不用时钟**——防源端迟到/时钟偏移）；
6. **对账**：源/目标行数与校验和三层断言（03 章 🔧E1 自纠教训的制度化）。

- 迟到数据策略 ⚠️：窗口右移重叠期（lookback）+ 幂等 MERGE 吸收重跑——「至少一次 + 幂等」
  是 FDF 剧本的默认可靠性档位（02 章三件套的装载层特化）。

## 7.3 🔧 实测 E3：MERGE INTO upsert——「收编」一步的最小实证（非 Fabric 平台行为）

DuckDB 1.5.5，维表 `dim_customer(customer PK, total, updated_at)`，两轮 MERGE
（exp_out.txt 实抓）：

```
=== T3 增量水位线 + MERGE INTO upsert（增量装载模式类比）===
customer  total updated_at        <- 首轮：从 orders 聚合 upsert
    Acme 200.50 2024-01-05
    Beta  45.25 2024-01-06
   Gamma 300.00 2024-01-07
customer  total updated_at        <- 次轮：新客 Delta 插入，存量不变
    Acme 200.50 2024-01-05
    Beta  45.25 2024-01-06
   Delta   9.99 2024-01-08
   Gamma 300.00 2024-01-07
```

- 首轮 `MERGE ... WHEN MATCHED UPDATE WHEN NOT MATCHED INSERT` 全量对齐；次轮单行源演示
  「新键插入、旧键不误伤」——7.2 第 5 步「用数据里的水位」在 SQL 侧的具象：`updated_at`
  来自源行而非 `now()`。
- 失配登记 🔧：DuckDB 单机 MERGE 无并发写冲突面、无 CU 成本、无失败重放语义；FDF 端
  MERGE 跑在 Spark/SQL 引擎上（05 章），重跑幂等靠 7.2 窗口设计而非 MERGE 自身
  （**非 Fabric 平台行为**）。

## 7.4 变体剧本与选型（⚠️ 编者决策表）

| 源端条件 | 剧本 | 备注 |
| --- | --- | --- |
| 有可靠 `modified` 列 | 7.2 标准水位线 | 首选，成本最低 |
| 只有追加型自增键 | 键高水位线（max_id） | 防「补录旧行」需定期对账全量 |
| 无时间戳无键 | 全量快照 diff 或分区整写 | bronze 双日分区对比 ⚠️ |
| 源支持 CDC | 平台/源侧 CDC 能力面 ⚠️ 未逐页取证 | 本册刻意给「不依赖 CDC 的最小公分母」写法 |
| 删除要同步 | 水位线 + 删除捕获表/软删标记 | 硬删同步是增量剧本最难档 ⚠️ |

- 与调度叠加：小时级窗口 = schedule 触发（02 章 2.1）+ 窗口参数由触发器注入；
  事件到达即搬 = 事件驱动档（支持面 ⚠️ 认现行文档），剧本骨架不变。

## 7.5 回填（backfill）与重放剧本（Playbook 的「灾难演习」页）

- 回填 = 同一管道换窗口参数重跑（7.1 参数化纪律的存在理由）；**回填窗口与例行窗口必须
  互斥或有幂等保护**，MERGE 语义（🔧E3）保证重放安全的前提是键与窗口定义一致。
- 重放三查 ⚠️ 编者归纳：查重（本批键是否已在目标）、查序（下游 gold 是否需级联刷新）、
  查账（审计表水位是否回退——水位表本身要加「只允许前进或显式回拨」断言）。
- 审计表设计最小列：`pipeline, window_start, window_end, rows_src, rows_dst, wm_actual,
  status, run_id`——09 章监控告警直接订阅此表，编排层与数据层在此汇合。

## 7.7 审计表 DDL 示意（7.5 列清单的通用 SQL 化 ⚠️ 编者示例，非 FDF 专属语法）

```
CREATE TABLE ctrl.watermark (
  pipeline      TEXT,
  window_start  TIMESTAMP,
  window_end    TIMESTAMP,
  wm_actual     TIMESTAMP,           -- 数据里的水位，非时钟（7.2 第 5 步）
  rows_src      BIGINT,
  rows_dst      BIGINT,
  status        TEXT,                 -- success | partial | failed
  run_id        TEXT,                 -- 09 章事故四元组的批次键
  PRIMARY KEY (pipeline, window_start)
);
-- 水位只前进或显式回拨（7.5 断言）：
-- INSERT ... WHERE EXCLUDED.wm_actual >= watermark.wm_actual
```

- 本表即 09 章数据层告警的唯一订阅源；🔧E3 的 MERGE 语义可直接作用于推水位步。
## 核心概念速览（中英对照）

- **水位线** — Watermark：已处理数据的最高标记；推水位用数据值不用时钟（7.2 第 5 步）。
- **窗口** — Window `[start, end)`：增量批次的时间边界，UTC ISO8601 纪律（7.1）。
- **MERGE/upsert** — 匹配更新、不匹配插入：收编步的最小语义（🔧E3 实证）。
- **重叠回看** — Lookback overlap：迟到数据的幂等吸收带 ⚠️。
- **至少一次+幂等** — at-least-once idempotent：FDF 剧本默认可靠性档位（7.2）。
- **回填** — Backfill：换参重跑；与例行窗口的互斥/幂等保护（7.5）。
- **审计表** — Watermark/audit table：水位+对账+状态的持久化，09 章订阅源。
- **软删标记** — 删除同步的保守档：硬删同步最难 ⚠️（7.4 表尾行）。
