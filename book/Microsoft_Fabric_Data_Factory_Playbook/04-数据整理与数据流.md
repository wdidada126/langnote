## 4.4 🔧 实测 E5：「无代码转换」的最小内核（非 Fabric 平台行为）

数据流话术拆开 = 「带转换的 copy」。DuckDB 单机实测（exp_out.txt 实抓）：

```
=== T5 数据流（transform）类比：COPY (SELECT...) 带转换导出 ===
order_date  cnt  revenue
2024-01-05    2   200.50
2024-01-06    1    45.25
2024-01-07    1   300.00
order_date,cnt,revenue
2024-01-05,2,200.5
2024-01-06,1,45.25
2024-01-07,1,300.0
```

- `COPY (SELECT order_date, count(*), sum(amount) ... ) TO 'exp/daily_agg.csv'` 一行完成
  「读→聚合→写」，等价于数据流画布上 Source→Aggregate→Sink 三个节点 ⚠️ 类比。
- 插曲登记（取证诚实）：首跑把别名写成裸 `rows`，触发
  `Parser Error: syntax error at or near "rows"`（保留字）——数据流产品「图形界面没有语法坑」
  的另一面是「表达式黑盒」，两条路线的坑只是换了位置 ⚠️。
- 平台差异提醒 🔧：DuckDB 无「数据流」这一等对象、不可独立部署/监控——产品化的数据流
  价值全在**可维护性与治理面**，不在计算本身（**非 Fabric 平台行为**）。

## 4.5 整理层的质量闸门（bronze→silver 的通用剧本 ⚠️）

- 三件套 ⚠️ 编者归纳：①空值/类型/枚举域校验（失败行进隔离表而非静默丢弃）；
  ②业务规则断言（金额≥0、日期单调——写进转换层而不是报表层）；③行数/校验和断言
  （与 03 章 E1 对账口径联动，源目标同 SQL 口径）。
- 隔离表（quarantine）模式：坏行落独立小表 + 09 章告警订阅其行数——「reliable pipelines」
  （副题 ✅）在转换层的落点。
- 幂等：整理输出永远「整分区重写」或「MERGE」（07 章 🔧E3），不做原地 UPDATE 式修补 ⚠️。

## 核心概念速览（中英对照）

- **数据整理** — Data Wrangling：交互式清洗/整形，Power Query/M 谱系 ⚠️（✅ A4）。
- **映射数据流** — Mapping Data Flow：Spark 内核可视化数据流（ADF 线概念；FDF 支持面只认 ✅ F2）。
- **转换三分工** — 无代码/SQL/代码优先：同一转换单一权威实现（4.1 纪律 ⚠️）。
- **对比页取证法** — compare-doc discipline：记链接+取证日，不抄快照（4.3 示范）。
- **隔离表** — Quarantine table：坏行显式落地可告警，反静默丢弃 ⚠️。
- **整分区重写** — Partition overwrite：转换层幂等输出主形态 ⚠️。
- **表达式黑盒** — 图形数据流反面代价：不可 diff、坑位转移而非消失（🔧E5 对照）。
- **质量闸门三件套** — 校验/断言/对账：bronze→silver 通用剧本（4.5）。
