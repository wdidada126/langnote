## 1. 本章定位

「和磁盘对话」的一章：Spark 如何把外部世界（CSV/JSON/Parquet/ORC/JDBC/文本）变成 DataFrame，又如何把结果写回去。它是全书批处理线（3–8 章）的地基：**格式选择决定性能上限，写出语义决定管道可重跑性**——后一句直接为第 7 章管道设计与第 10 章流式输出模式埋线。

## 2. 读路径要点（⚠️ 按章题域重构）

- **统一入口** `spark.read.format(...).option(...).load(...)`：format 缺省按扩展名嗅探；schema 三种姿势——不给（采样推断，CSV 尤其危险）、给（显式 StructType，生产纪律）、`inferSchema`+抽样调参权衡。
- **文本类**：CSV（多行/引号/分隔符/编码选项）、JSON（行内对象 vs 整档数组）、text（wholeTextFiles 的键值化怪癖）。
- **列式类**：Parquet/ORC——谓词下推、列裁剪、块级统计；工程册的标准建议是「落地除非人读，一律 Parquet」（⚠️ 通行立场，非原话）。
- **选项作用域陷阱**：同一 DataFrameReader 上 options 对某些 format 静默无效——排错第一站是「确认选项被消费」。
- 官方校核入口 ✅ https://spark.apache.org/docs/latest/sql-programming-guide.html（Data Sources 全节）；RDD 文本读取旁支 ✅ https://spark.apache.org/docs/latest/rdd-programming-guide.html。

## 3. 写路径要点（⚠️ 重构）

- `df.write.mode(...)`: **append/overwrite/ignore/error(errorifexists 别名时代差异)** 四模式——写出语义的宪法条款。
- 分区写出 `partitionBy(...)`：目录即索引；高基数分区=小文件灾难的源头工程直觉。
- `saveAsTable` vs `write.parquet(path)`：表语义（走 catalog，见第 6 章）与路径语义（裸文件）的分岔。
- bucketing/排序选项（`sortBy`、`write.option("path",...)` 与表解耦）——为后文调优与 14 章资源讨论存目。
- 2022 时点 DataSource V2 已成熟但本书是否展开 ⚠️ 未证实；其对「流式写出事务」的意义在演进节补。

## 4. 本章的工程判断线：读决定格式，写决定事务

一个贯穿全章的对照（⚠️ 重构框架，非原书术语）：

| 维度 | 读侧关注 | 写侧关注 |
|------|----------|----------|
| 性能 | 下推、列裁剪、分区裁剪 | 文件尺寸、小文件、压缩编解码 |
| 正确性 | schema 对齐、时区/编码 | mode 选择、并发写者、原子性 |
| 可运维 | 坏文件隔离（`mode=PERMISSIVE/failfast`） | 重跑幂等（overwrite 分区策略） |
| 演进钩子 | 湖仓格式接管读 | 事务提交接管写（→ Delta/Paimon 互链） |

## 5. 🔧 实测·第一组：快照全量重算 vs 增量合并（微批等价性；非 Spark 行为）

DuckDB 1.5.5 实测（脚本 `D:\develops\tmp\dbwave_w8_mdes\exp.py`，输出 exp_out.txt）：

- 构造 600 行订单表（seq 为到达序模拟日志流）。
- **快照路径**：每小时窗口 `GROUP BY` 全量重算 → 31 窗、总额 `30409.25`。
- **增量路径**：物化窗口表 `whr`，只消费 `seq>300` 的新数据，UPDATE 已有窗 + INSERT 新窗 → 总额同为 `30409.25`，逐窗对得上。
- 结论：**当分区可加且迟到不发生**时，增量合并 ≡ 全量重算——这正是 Spark 微批「增量视图 + 状态合并」的成立条件；第 9/10 章的迟到与水位线讨论就是打破此条件的两个变量。
- 边界：DuckDB 无 checkpoint/血缘，实验只证「代数等价性」，不证容错（🔧）。

## 6. 写出模式的可迁移直觉（与 10 章输出模式预对齐）

- `overwrite` + 分区级目录替换 ≈ Structured Streaming 的 Complete 输出（全量重写终态）。
- `append` ≈ Append 输出（只写新增，靠外层保证不重复）。
- 分区内 merge/upsert 裸 Parquet 做不到 → 这正是湖仓格式（Delta 的 MERGE、Paimon 的主键表）接管的位置。

## 8. 事故清单（工程册标配，⚠️ 重构）

1. CSV 推断 schema 把 id 读成 integer，上游加前导零后静默错值——显式 schema 是纪律。
2. 多写者同目录 overwrite → 目录级竞态；「删旧写新」在对象存储上的可见性窗口。
3. `partitionBy` 选错列（高基数/含空值）→ 千万级小目录。
4. JSON 嵌套列 `from_json` 的 mode 不设，脏行整批报废或整列 NULL 二选一。
5. 时区：字符串时间戳不带偏移，跨区集群写出后小时窗错位——第 9 章水位线会再会它。

## 10. 格式选型速查（本章的工程决策表，⚠️ 重构）

| 场景 | 首选 | 理由 | 工程注 |
|------|------|------|--------|
| 管道中间层 | Parquet | 列裁剪+下推+压缩三全 | 落地即定 schema 契约 |
| 人类抽检/交换 | CSV | 可读可改 | 显式 schema 防推断事故 |
| 半结构化原始层 | JSON 行式 | 模式演化宽容 | `mode=PERMISSIVE` 配 `_corrupt_record` 观测 |

| 跨引擎共享 | 湖表包裹以上格式 | 元数据+事务层（→演进） | 裸格式时代遗留 |

## 11. save mode 决策树（口试级精炼，⚠️ 重构）

- 目标目录/表允许存在吗？ 否 → `ignore`/`error`；是 → 下一问。
- 这次运行是「修正终态」还是「追加事件」？ 修正 → `overwrite`（分区级最佳）；追加 → `append`。
- 追加会重复吗（重跑风险）？ 会 → 把幂等交给键控 merge（湖表/JDBC upsert，→ 5/10 章 🔧）。
- 多引擎并发写同一目标？ → 裸格式不保证，升级到事务表格式（诚实的「超出本书」出口）。

## 12. 本章实验卡（⚠️ 非原书代码）

1. 造 1 万行嵌套 JSON，先 `inferSchema` 再显式 schema 各读一次：对比耗时与列类型差异。
2. `from_json` 喂入 3 条脏记录，`PERMISSIVE` vs `FAILFAST` 行为各验一次。
3. 写出 Parquet：先 `partitionBy` 低基数列（年/月），数目录数；再换高基数列（uid），目睹小文件灾难。
4. 同目标二次 `overwrite`：确认「旧文件消失时点」的可见性窗口（本地文件系统上的原子性错觉，为湖表事务做心理铺垫）。
5. 用 `EXPLAIN` 观察 Parquet 读上的 pushed filter（对照 §4 表格与 05 章 JDBC 下推）。

## 核心概念速览（中英对照）

- **DataFrameReader/Writer** — DataFrameReader/Writer：读写统一门面，选项按 format 生效。
- **Schema 推断** — Schema Inference：采样推断类型；生产须显式 schema。
- **谓词下推** — Predicate Pushdown：过滤交给数据源减少读取量。
- **列裁剪** — Column Pruning：列存只读所需列。
- **分区目录** — Partitioned Directory：`partitionBy` 的物化布局，目录即谓词索引。
- **写出模式** — Save Mode：append/overwrite/ignore/error 四态。
- **小文件问题** — Small Files Problem：高基数分区/微批高频写出共有的病灶。
- **PERMISSIVE/failfast** — 解析模式：脏 JSON/CSV 的容忍与快速失败。
- **表语义 vs 路径语义** — Table vs Path：catalog 管理对象与裸文件的分岔。
- **增量合并** — Incremental Merge：新数据并入既有聚合，微批的数学内核（🔧 实验一）。
- **DataSource V2** — DataSource V2：可扩展数据源框架，流批共用注册。

## 最新演进与工业实践

- **Spark 4.x 读侧**：Variant 类型使半结构化 JSON 摄取免 shredding 直存（⚠️ 转述；校核 ✅ https://spark.apache.org/docs/latest/sql-programming-guide.html 的 File Formats 节，2026-10 实测 200）。
