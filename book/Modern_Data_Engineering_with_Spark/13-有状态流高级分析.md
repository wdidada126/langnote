## 1. 本章定位

Spark 流 API 的「越狱」章：当声明式聚合/连接（12 章）表达不了目标检测、会话切分、动态阈值时，进入**编程状态**（programmatic state）——`mapGroupsWithState`/`flatMapGroupsWithState` 给每键一个可自由演化的状态对象。全书技术深度顶点；也是「mission-critical」叙事中最贵的一章：状态即成本、即风险、即能力。

## 2. 编程状态 API 心智（⚠️ 按章题域重构）

- **分组即状态域**：`groupBy(key).flatMapGroupsWithState(outputMode, timeout)(f)`——每键一个强类型状态记录，函数签名 `(key, 本批行 Iterator, 状态) → 新状态/输出行`。
- **输出模式对偶**：Append（只在判定完成时发一行）vs Update（每批发变更）——目标计数类天然 Append，会话/画像类天然 Update。
- **Timeout 三态**：`ProcessTime`（静默即触发清理，含 `OnTimeout`/`Continue` 分支处理）/ `EventTime`（配合水位线）/ 无——状态 GC 的编程入口。
- **与批引擎的关系**：这是 DataFrame 声明层之外的「逃生舱」，优化器不可见其语义——正确性、测试、观测全归工程侧（→ §6）。
- ✅ 校核入口 https://spark.apache.org/docs/latest/structured-streaming-programming-guide.html（Extending with stateful operations 节，2026-10 实测 200）；Spark 4.x 增补 `transformWithState`（演进入口见本节尾）。

## 3. 本章可预期的典型状态模式（⚠️ 重构配方集）

1. **目标检测/达标告警**：累加到阈值发一次并抑制后续——Append + ProcessTime 超时清态。
2. **会话切分（sessionization）**：以「静默超阈值」闭合会话——超时分支输出终态会话行。
3. **移动窗口去重计数**：状态存最近 N 分钟事件环——近似 distinct 的编程解。
4. **动态维表富化**：状态缓存维表快照 + 定期刷新——低频查库替代每批 join（与 5 章 JDBC 呼应）。
5. **ML 在线推理**：模型载于状态函数闭包、每批评分（书中若涉 ML 大概率止于 demo 级，⚠️ 推定；纵深在 Advanced Analytics 谱系册）。

对位理论：状态的一般化讨论见 [../Streaming_Systems/07-持久状态的实践.md](../Streaming_Systems/07-持久状态的实践.md)；ML 纵深 [../Advanced_Analytics_with_Spark_2e/00-总览与阅读地图.md](../Advanced_Analytics_with_Spark_2e/00-总览与阅读地图.md)。

## 4. 状态的后端与规模线（工程册的责任段，⚠️ 重构）

- 内存态（默认）→ RocksDB 态（3.x 可用）：GB/TB 级键状态的 spills/序列化代价；键基数与状态大小预算表——14 章资源模型的输入。
- 状态可见性：state metrics listener/`numRowsTotalKeys` 类计数（版本相关，⚠️ 以文档为准）；「状态泄漏」是长跑流作业的头号慢性病。
- checkpoint 中的 state 目录（10 章 WAL 线）与状态后端的配对关系：恢复语义=offset×状态双对齐。

## 5. 🔧 实测·第三组：版本化 upsert 与状态外置（SQLite，非 Spark 行为）

脚本 `exp.py` 实验三：微批聚合以「(键, 版本水位)」upsert 进终态表——

- 数据：10 行源、按奇偶分 `a/b` 两组；水位先推到 ver=5，聚合表得 `a:(9.0,3,5) b:(6.0,2,4)`。
- **同一微批重放 3 次**：`ON CONFLICT ... WHERE agg.last_ver < excluded.last_ver` 守卫使结果逐字节不变（`unchanged_by_replay: true`）。
- 水位推进到 10：仅一次生效，终值 `a:25.0/5 行 b:30.0/5 行`。
- 与本章的接线：编程状态算子的**输出**最终也要落到这种幂等面（Update 模式行集=带键变更集）；「状态对象版本 + 比较交换」正是 §3 各配方落地生产时的通用护甲（🔧 类比止于幂等语义，Spark 状态原子的恢复机制不可见于 SQLite）。
- 语法依据 ✅ https://www.sqlite.org/lang_upsert.html（2026-10 实测 200/301→小写页 200）。

## 8. 状态转移伪码骨架（本目录重构，⚠️ 非原书代码、非可运行签名）

```text
onBatch(key, rows_in_this_batch, state_or_None, timeout_ctx):
    s = state or new_state(accum=0, done=False)
    if timeout_ctx == TIMED_OUT:
         emit(finalize(s)) if s.pending_emit; return clear()
    for r in rows:
         s.accum += r.value
         if s.accum >= s.target and not s.done:
             emit(alert(key, s)); s.done = true        # 目标检测：一次触发
    return s, maybe_update_out(s)                       # Update 模式则每批发
```

- 读点：状态是**数据结构**（版本、done 位、TTL 字段都在你手里）——声明式聚合替你隐掉的一切在此显形，这正是它能力与风险同源的原因。
- 超时三分支（未超时/即将超时/已超时）是本章的「控制流三角」；`OnTimeout` 返回的清理语义配 §3 配方 2。
- API 演进注：4.x `transformWithState` 把「每行回调+状态句柄」化为更细的粒度——心智可从上图平移（演进节已链官方）。

## 核心概念速览（中英对照）

- **编程状态** — Programmatic State：键控状态对象的自由演化 API，声明层的逃生舱。
- **flatMapGroupsWithState** — map/flatMap Groups With State：本章主 API，批行×状态→新状态(+输出)。
- **状态超时** — State Timeout：ProcessTime/EventTime 双制式的状态 GC 触发器。
- **会话切分** — Sessionization：以静默间隔闭合事件会话的经典状态模式。
- **目标检测** — Goal Detection：累加至阈值的一次性发信模式（Append 态代表）。
- **状态后端** — State Store Backend：内存 vs RocksDB 的规模线选择。
- **状态泄漏** — State Leak：未清键态单调膨胀的慢性病（→ §6 监控）。
- **版本化 upsert** — Versioned Upsert：外置幂等面的比较交换写法（🔧 实验三）。
- **在线推理** — Online Inference：模型随微批评分的近线形态（demo 级）。
- **双对齐恢复** — Offset×State Recovery：checkpoint 恢复时两个维度的重放一致性。

## 最新演进与工业实践

- **`transformWithState`（Spark 4.0 线）**：替换 mapGroupsWithState 的新状态 API，明确「一次更新一状态」模型并改善类型化与 Python 支持——本书模式的官方继任者 ⚠️（转述；校核入口 ✅ https://spark.apache.org/docs/latest/structured-streaming-programming-guide.html 与发布说明，版本细节以官方为终裁）。
