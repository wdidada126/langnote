## 1. 本章定位

「算出来之后给人看」的一章：把 10/11 章的流式产出接到分析消费面——聚合/开窗/连接的分析语义、结果表的组织、以及用 SQL 工作台/BI 工具取洞察。工程叙事上它是 6 章「数据发现」的流式对应物：**管道终点不是 sink，而是可被提问的表**。批流四册（波8兄弟 #156/#157/#199/#166，登记不链）谈的是同一话题的组织侧，本章是 Spark 实现侧。

## 2. 流式分析的算子面（⚠️ 按章题域重构）

- **聚合家族**：`groupBy(agg)`、事件时间窗口聚合（10 章已配水位线）、`rollup/cube/grouping sets`（批侧完备；流侧支持子集——差异即工程约束，⚠️ 以指南为准）。
- **开窗函数**：`Window.partitionBy().orderBy()` 上的 rank/lead/lag 在流上的可行性受「排序需要全量状态」限制——Append 模式多数不可用，Update 兜底。
- **流式连接**（本章技术天花板）：
  - stream–static join：无状态、可 Append（维表广播模式）。
  - stream–stream join：**双方都要水位线**，窗口连接 `eventTimeoutDuration` 限定配对存续期；inner 可 Append、外部连接要 Update——理论展开对位 [../Streaming_Systems/09-流式连接.md](../Streaming_Systems/09-流式连接.md)。
- **去重与集合**：`dropDuplicates` 的状态代价、`intersect/except` 在流上的受限清单（✅ 指南 Supported Operations 节）。

## 3. 结果表的消费组织（「洞察」的落地件，⚠️ 重构）

1. **物化终态表**：微批 upsert 进 JDBC/湖表（10 章模式 + 5 章 JDBC），BI 直连——最朴素也最稳的「流→分析」桥。
2. **目录暴露**：结果注册进 catalog（6 章），分析师 `SHOW TABLES` 出发。
3. **交互工作台**：Jupyter/Databricks notebook 类工具读结果（本书 hands-on 语境的「insights」大概率停在 SQL+notebook 层，⚠️ 推定）。
4. **新鲜度契约**：消费方看到的窗何时定稿——水位线与报表口径的接缝（🔧 实验一的「对账」思想在此复用：定稿窗可冻结发布，未定稿窗打 provisional 标记）。

## 4. 从聚合到指标：本章的工程审美

- 指标层（metric store 前夜形态）：把「窗×维度×度量」表设计成**可组合**而非仪表盘专用——一次建模多处消费（⚠️ 重构观点，与 dbt metrics 思潮同向）。
- 维度爆炸防护：高基数维度进 groupBy = 状态爆炸 = checkpoint 膨胀；预聚合/哈希降维/上限告警三件套。
- 迟到对报表的影响可视化：给「窗定稿时间」建监控列（watermark 进度），分析师第一眼知道自己看的是不是完整窗——本目录补充的工程做法（⚠️ 非原书内容）。

## 5. 🔧 类比·流式连接的水位线约束（DuckDB 批投影，非 Spark 行为）

用批 SQL 演示「配对存续期」的语义内核：

```python
import duckdb
con = duckdb.connect()
con.execute("""CREATE TABLE clicks(uid INT, t INT);  CREATE TABLE buys(uid INT, t INT);
               INSERT INTO clicks VALUES(1,100),(2,150),(3,300);
               INSERT INTO buys  VALUES(1,120),(2,400)""")
# 事件时间窗口连接: buys 在 clicks 后 [0,60] 秒内才算转化
print(con.sql("""SELECT c.uid, c.t click_t, b.t buy_t FROM clicks c JOIN buys b
  ON c.uid=b.uid AND b.t BETWEEN c.t AND c.t+60""").fetchall())
# 批=全已知, 可直接解; 流=未来对侧未知 → Spark 用双边水位线决定「何时放弃配对」
```

- 读数：`(1,100,120)` 命中、`(2,150,400)` 被 60 秒窗拒——**连接谓词就是配对规则**；批引擎随时光机全量重算天然满足，流引擎只能靠水位线「过期不候」。
- 边界：Spark 流连接的逐窗状态清理策略（RocksDB/TTL）在此不可见（🔧）；理论版见 [../Streaming_Systems/09-流式连接.md](../Streaming_Systems/09-流式连接.md)。

## 8. 分析面反模式清单（⚠️ 目录提炼）

1. **仪表盘直连微批目录**：读半写文件、忽增忽减——正确姿势只读「定稿标记」行或湖表快照（§3 第 4 条）。
2. **高基数当维度**：uid 进 groupBy 的状态账单 14 章来收——先问消费方真要 uid 级吗。
3. **Complete 模式配大状态**：每批全表重写，sink 变垃圾制造机——10 章矩阵的镜像教训。
4. **报表口径藏在 BI 端**：同一指标两处定义漂移——把口径上移到管道产出列（§4 指标可组合性的反面）。
5. **拿流式 join 当批 join 用**：忘设双边水位导致状态无限增长——先问「这真是流×流还是流×陈旧维」。
6. **去重窗无上限**：`dropDuplicates` 全历史语义→内存黑洞——配水位让其变「近程去重」（§2 代价列实证）。

## 9. 本章实验卡（⚠️ 非原书代码）

1. 文件源点击流：5 分钟窗 PV/UV 近似，三模式各发一遍——console 里看懂「谁何时看见什么」。
2. 流×静态维 join 成功 → 改流×流 inner（双方水位）→ 改 left（观察 Update 强制）——§2 连接梯度 climbing。
3. `rank()` 开窗套流上：Append 报错改 Update——4 章白名单与本章的接口实测。
4. 把结果 upsert 进 SQLite/JDBC 表，BI 工具（任意 SQL 客户端）直连：一条「流→分析」的最小生产链。
5. 给结果表加 `watermark_progress` 列并画图：新鲜度可视化——§3 第 4 条的手工版。

## 核心概念速览（中英对照）

- **事件时间窗聚合** — Event-Time Window Aggregation：流式分析的原子产出（10 章水位线的受益者）。
- **流流连接** — Stream-Stream Join：双无界表按时序配对，状态成本最高操作。
- **窗口连接** — Windowed Join：`eventTimeoutDuration` 限定的配对存续期（🔧 §5）。
- **静态侧广播** — Static-Side Join：流×有界的免状态连接形态。
- **操作支持矩阵** — Supported Operations：SS 对算子的 Append/Update 可行清单。
- **去重状态** — Dedup State：`dropDuplicates` 的键集记忆成本。
- **物化终态表** — Materialized Serving Table：微批 upsert 的 BI 可消费投影。
- **新鲜度标记** — Provisional/Final：以水位线给报表行盖「定稿章」的工程手法（⚠️ 目录补充）。
- **指标可组合性** — Metric Composability：一次建模多处消费的维度表设计观。
- **高基数防护** — Cardinality Guard：维度爆炸→状态爆炸的前置闸。
