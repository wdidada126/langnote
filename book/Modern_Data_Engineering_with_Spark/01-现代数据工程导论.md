## 1. 本章定位

全书唯一一章不谈 Spark API 的「职业叙事章」：把 **modern data engineer** 从「会写 ETL 的 DBA 变体」重述为横跨数据平台、管道、编排与运维的工程师角色；Spark 被放置为该角色的**主引擎**而非全部。章尾自然引出第 2 章的本地环境搭建——本书的 hands-on 承诺从第一章就立好：后续每一章都围绕「在你自己的机器上跑通」。

## 2. 数据工程角色谱系（⚠️ 推定重构）

- **与传统 DBA/BI 的分工**：DBA 管存储与事务、BI 管报表语义；数据工程管**数据如何到达、以什么形态落地、多久新鲜一次**。本书 3–8 章即这条线的批处理展开。
- **与数据科学/分析的接口**：第 12 章「分析处理与洞察」表明作者立场——数据工程的产出物是「可被分析的消费面」，而非终态报表。
- **平台工程师化**：14/15 章把部署（Standalone/K8s）划入数据工程职责域，这是 2020 年代岗位边界扩张的缩影（与 DataOps 叙事合流，⚠️ 本书未用 DataOps 术语，此为本目录补充语境的推定）。

## 3. 现代数据平台版图（⚠️ 按本书后文反推的作者覆盖面）

- **计算引擎层**：Spark（本书唯一主角）。批：DataFrame/Spark SQL；流：Structured Streaming。
- **编排层**：Apache Airflow（第 8 章专章）——作者把编排视为数据工程师的「第二母语」。
- **传输/缓冲层**：Apache Kafka（第 11 章专章）——流式管道的事实标准源与汇。
- **存储层**：本地文件系统 + JDBC 关系库（第 5 章）——本书刻意**不上云**，用「完全本地可行的数据平台」证明角色能力可自证；湖仓格式（Delta/Iceberg）在 2022 年语境下未被本书展开（⚠️ 推定），由 repo 湖仓诸册补位，见下节互链。
- **消费层**：SQL 目录与数据发现（第 6 章）+ 分析工具（第 12 章）。

## 4. 「mission-critical streaming」标题承诺的兑现路径

副题的关键在 mission-critical：作者不是要教玩具流作业，而是把「可运维性」拆进全书——

1. **可重复**：批管道幂等与分区重跑（第 7 章主题域）。
2. **可编排**：失败重试、依赖、SLA 靠 Airflow DAG 表达（第 8 章）。
3. **可容错**：checkpoint/WAL、触发器与输出模式（第 10 章）。
4. **可对接可靠消息**：Kafka 偏移语义与端到端一致性（第 11 章）。
5. **可部署**：集群资源与调度（第 14/15 章）。

> 这条「可运维性五环」是本目录对 15 章内容的一次性预拼装（⚠️ 推定的解读框架，非原书术语）。

## 6. 🔧 语境小实验（类比，非 Spark 行为）

用 DuckDB 手工模拟「数据工程师的一天」最小闭环，体会「平台=分层数据+可重放变换」：

```sql
-- 原始层 → 清洗层 → 消费层（medallion 雏形，DuckDB 1.5.5 本机可跑）
CREATE TABLE raw(id INT, v TEXT);
INSERT INTO raw VALUES (1,' a '), (2,'b  '), (3,NULL);
CREATE TABLE clean AS SELECT id, trim(v) v FROM raw WHERE v IS NOT NULL;
CREATE TABLE mart AS SELECT count(*) n FROM clean;
SELECT * FROM mart;  -- 2
```

观察：清洗脚本可从 raw **全量重放**——这正是第 7 章「管道可重跑」与第 10 章「流即无限表」概念的最小宿主。🔧 本实验只证「分层+重放」的抽象，与 Spark 的 Catalyst 执行无关。

## 8. 叙事弧重构：导论章如何给全书「上弦」（⚠️ 推定）

导论章的典型功能是把三件事一次讲清，本章按 hands-on 册惯例可预期如下展开——

1. **Why**：数据爆炸 → 单库撑不住分析负载 → 需要「以文件为底、以引擎为斧」的横向扩展形态，Spark 是这把斧头头名。
2. **What**：数据工程交付物清单——摄取（3/5 章）、变换（4 章）、组织（6 章）、编排（7/8 章）、流化（9–13 章）、投产（14/15 章）。
3. **How（预告）**：全书统一使用同一本地数据集贯穿各章（hands-on 册标准打法，⚠️ 推定），避免「每章换数据」造成的注意力损耗。

**批判性对读**：Why 环节在 2022 年尚有说服力，但 2024–2026 的工业叙事把「以文件为底」升级为「以开放表格式为底」——同一诉求（横向扩展+多引擎共享）换了实现层。读本章时建议把「裸文件」在脑中替换为「Delta/Iceberg/Paimon 承载的文件」，其余论述几乎原样成立。这正是本目录把湖仓诸册设为对位读物的原因。

## 10. 🔧 追加语境实验（SQLite 版，与 §6 同旨）

SQLite 侧重复「分层+重放」，并观察**幂等写出**（第 7 章概念的宿主）：

```sql
CREATE TABLE raw(id INTEGER PRIMARY KEY, v REAL);
CREATE TABLE mart(k TEXT PRIMARY KEY, s REAL, n INT, src_max INT);
-- 全量重放两次：同一输入, 结果不应变化
INSERT OR REPLACE INTO mart
  SELECT 'all', sum(v), count(*), max(id) FROM raw;
```

- 第一次写入后 `src_max=0, s=NULL/0, n=0`；向 raw 灌 10 行后重放同一条语句，mart 直接呈现**快照终值**——这就是「append 不可、替换可」的朴素版本，Spark 结构化流的 Complete 输出模式在语义上与之同构（🔧 类比，非本书 Spark 平台行为；对应实验台账见 `00-总览与阅读地图.md` §7 第 3 组 UPSERT）。

## 核心概念速览（中英对照）

- **数据工程** — Data Engineering：以工程化手段交付可靠、可重放、可运维的数据管道的学科。
- **现代数据栈** — Modern Data Stack：云时代组合式数据工具谱系；本书刻意用开源+本地反其道。
- **批处理** — Batch Processing：对静态数据集全量计算，本书 3–8 章主线。
- **流处理** — Stream Processing：对无界数据持续增量计算，本书 9–13 章主线。
- **关键任务应用** — Mission-Critical Application：副题关键词，指可运维/容错/可部署的生产级作业。
- **工作流编排** — Workflow Orchestration：以 DAG 表达作业依赖与重试，第 8 章 Airflow。
- **消息缓冲** — Message Broker / Log：Kafka 在本书架构中的角色（第 11 章）。
- **数据发现** — Data Discovery：借 Spark SQL Catalog 让消费者找到并理解数据（第 6 章）。
- **幂等重放** — Idempotent Replay：管道可重跑而不重复计数的性质，贯穿 7/10/11 章。
- **本地数据平台** — Local Data Platform：本书 hands-on 承诺的载体，单机复现全栈。
