## 3. 深读笔记

**3.1 ch7 的隐藏论题是"谁的数据喂谁"。
** 注意一个循环：给资产打标需要历史人工标注——而 fabric 许诺解决的正是"人工标注不存在"。
破环三法（✅ 均属公开 ML 常识）：冷启动用弱监督（列名/类型先验）、主动学习把人工预算花在最不确定样本、跨租户/跨目录迁移先验。
⚠️ 推定本书以咨询口吻强调"渐进人机协作"而少谈冷启动数学——读者若拿本章立项，冷启动预算必须自算。

**3.2 ER 是 fabric 的隐形地基。
** MDM 时代黄金记录（01 文件 §2 表）就是 ER 的产品化；
fabric 宣称自动发现"同一实体的不同投影"，其可行性全押在 ch8 这 18 页上。
**实体解析的质量上限=织点信任的上限**：血缘可以推断、标签可以抽检，唯二义性合并会污染下游一切。
因此 ch8 单章深挖在结构上不是插曲而是承重墙——这也解释了它为何值得 Crossref 独立章级 DOI（✅ `_8` 实存）。

**3.3 🔧G4：阻塞式 ER 基线的本机测量**（SQLite 3.45.3，py 绑定；
**非本书引擎/平台行为**）。
构造：A 表 20000 唯一姓名（双姓拼接，24 姓氏词表→天然多义），B 表抽 40%（8000 真匹配）注入三种噪声：大写化、追加 "Inc"、删第 4 字符。
基线=规范化后「前缀 4+后缀 3」联合阻塞键，SQL join 出候选后对 ground truth 计分。
结果：**候选 103.9 万对，tp=28564，fp=101.1 万，recall 47.95%，precision 2.75%，wall 6589ms**。
三个教科书级读数：① 大写噪声零损失（规范化先行=免费召回）；
② 截字/加后缀直接毁键（recall 天花板=键不变子集占比，47.95%≈理论值）；
③ fp 大海来自同名歧义——阻塞解决的是算力不是语义。
这正是 2.2 第二刀（ML 相似度打分+上下文特征）存在的实验证明：**规则基线的两个失败面，恰是学习型匹配器的两个卖点**。
✅ 综述佐证：深度学习 ER 技术栈全景见 Crossref 10.1145/3828660（ACM CSUR；
元数据可证，落地页反爬 403）。

**3.4 GenAI 改写了矩阵的哪几格。
** 2023 本表（⚠️ 推定接近原书）到 2026 的差分：打标/摘要/问答三行的"技术簇"列被 LLM 统一收编，出现**一个模型吃三活**的合并；
但血缘解析与 ER 反而更吃"结构先验+SQL 解析"，LLM 只做长尾兜底。
教训：赋能矩阵要按"任务是否可验证"分层——可程序验证的（血缘/阻塞）自动化激进，不可验证的（业务语义）人机协议保守。

**3.5 对观测面的依赖。

## 4. 边界与易混点

- **自动打标≠打标正确**：置信阈值以下的资产要么人审要么显式标"未定"——静默降级是目录腐烂的伪装形态。
- **ER ≠ 去重（dedup）**：ER 判定"哪些记录共指一实体"，去重是其下游动作之一；
  ch8 若混用需读者自行分开。
- **匹配率≠质量**：G4 演示了 103.9 万候选里挑 2.8 万真对的 haystack 问题——任何只报 recall 不报 precision 的厂商数字先按 G4 结构质疑。
- **本章无"训练自己的大模型"议程**：赋能语境内模型=可替换供应商件，平台设计要保住"换模型不换数据"的接口纪律。

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| 实体解析 | entity resolution (ER) | 判定多源记录共指同一实体的技术，fabric 信任的地基 |
| 阻塞 | blocking | 以廉价键把二次方比较空间砍成候选集的第一刀 |
| 匹配打分 | matching score | 第二刀：从键相等升级为相似度与概率 |
| 传递闭包爆炸 | transitive closure explosion | 链式合并把不相关记录拖进一簇的 ER 经典事故 |
| 黄金记录 | golden record | MDM 时代 ER 的产品化输出 |
| 弱监督 | weak supervision | 用启发式标注函数替代人标，冷启动破环法 |
| 主动学习 | active learning | 把最稀缺的人工预算投向模型最不确定样本 |
| 预打标+抽检 | pre-labeling with human review | 目录工程的标准人机协议 |
| 语义检索 | semantic search | 嵌入空间最近邻替代关键词匹配 |
| 可验证性分层 | verifiability tiering | 本目录方法件：按任务可否程序验证决定自动化激进度的纪律 |

## 最新演进与工业实践

- **2024→2026 矩阵增补**：LLM 结构化输出使"列→业务术语"生成可用（zero-shot 打标进入生产灰度）；
ER 线出现 LLM 重排器（候选阻塞不变，打分层叠一层语言模型仲裁）——G4 的两刀结构在 2026 变成三刀，**阻塞反而因算力便宜而回潮**（长上下文可对整块做仲裁）。
血缘线：查询日志+dbt manifest 双源推断成开源主流（OpenLineage ✅ 项目文档）。
- **工业实践**：头部数据目录产品（Collibra/Ataccama/Informatica+AWS 系）已把"AI 打标覆盖率+抽检通过率"作为可审计 SLO 出厂；
反例同样多——某金融客户目录项目预打标 92% 覆盖但业务词表口径漂移，检索正确率不升反降，验证 3.4 的"不可验证任务保守"律。
- **给平台组的三件套**：给 AI 动作留事件账（谁被自动改了什么、置信多少）、给抽检留预算（默认 5%）、给回滚留开关（自动打标可整批撤销）——ch7 主张的最小运行纪律，比任何单点模型选型重要。
