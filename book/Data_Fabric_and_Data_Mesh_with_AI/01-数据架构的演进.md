# 01 · 数据架构的演进（原书 ch1: Evolution of Data Architecture, p.3–15）

> 对位声明：章题/页码 ✅ 实证（Crossref `_1` + Springer TOC 实抓）；
章内小节与原书具体表述 ⚠️ 重构。
本章是全书 18 章最短章之一（13 页），功能是给后 17 章铺设"为什么偏偏是现在出现 fabric 与 mesh"的架构史论证。

## 1. 本章在书中的位置

- 上游：无（入口章）。
- 下游：ch2 术语立宪、ch10 架构模式、ch11 企业架构定位、ch12 混合云——全部以本章的"史观"为公理。
- 本书章群的写法特征（⚠️ 据作者咨询体裁推定）：每章以"管理层摘要式论点 + 支撑表格"展开，ch1 尤甚，13 页要装三十年的架构史，必然是**高度选择性的叙事**——读任何架构史章都要追问"作者略过了什么"。

## 2. 内容地图（⚠️ 重构：本书 ch1 覆盖的演进单元）

| 阶段 | 主导形态 | 解决的问题 | 留下的债（→引出下一代） |
|---|---|---|---|
| 主机时代（1960–80s） | 分层数据库+单体应用 | 记账与一致性 | 数据随应用孤立，无共享语言 |
| 数据集市/数仓（1990s） | Kimball/Inmon 双宗教的 ETL 中心制 | 分析要脱机、要统一口径 | N 个集市 N 份口径，"数仓墙" |
| 主数据管理/集成时代（2000s） | EII/ESB/MDM 三件套 | 点对点集成与实体统一 | 集中式团队成吞吐瓶颈，血缘靠人肉 |
| 大数据/湖时代（2010s） | Hadoop→云对象存储+湖仓 | 廉价存算、模式后置 | 数据沼泽、治理缺位、schema-on-read 反噬 |
| 云原生/多栈时代（2015–今） | 存算分离、SaaS 泛滥、跨多云 | 弹性与专业分工 | **集成债×组织债双高**——fabric 与 mesh 同题异解 |

本章的落点（⚠️）：债务的利息表现为四类活动耗时——找数据、懂数据、拿数据、信数据；
这正是 ch4"业务收益"章的计费口径，两章首尾呼应。

## 3. 深读笔记

**3.1 选择性叙事的批判读法。** 架构史章天然有"辉格史"倾向：把当下方案写成历史的必然收敛。
对读盘上两册可以校准：[../The_Data_Lakehouse/00-总览与阅读地图.md](../The_Data_Lakehouse/00-总览与阅读地图.md) 把湖仓写成"第三阶段终结者"，而本书把湖仓写成"被编织的一层"——同一对象在两书中的层级差，恰好证明架构叙事是**立场商品**而非中立事实。
工程上正确的读法：把每张阶段表当"该书的动机装置"，只取其债务清单，不取其必然性。

**3.2 本书史观的独特处：组织轴从未退场。** 主流架构史（含 #210 ch1 的钟摆模型）偏技术轴。
本书书名即宣告 mesh 与 fabric 平装，则其 ch1 必须为"组织/权责"留叙事位：领域团队在集市时代被绕过、在自助分析时代被赋权又失控、在平台工程时代被重新纳入设计——mesh 的组织学结论（ch2–3 展开）需要这条暗线支撑。
⚠️ 此为本目录对作者的同情性重构。

**3.3 为什么 AI 是第四变量。
** 传统二元（技术架构×组织），2020 后加入第三变量"可负担的智能"：LLM 之前，自动打标/血缘推断/自然语言取数的单位经济学不成立，fabric 停留在 PPT（#210 00 §6 论点 6 同型）；
本书把 AI 直接写进书名并占 ch6–9 四章，等于在其史观里给 AI 以"使能条件"地位。
✅ 概念佐证：数据为中心 AI 综述（Crossref 10.1145/3711118、10.1007/s12599-024-00857-8）确立"模型侧收益递减→数据侧收益递增"的范式论。

**3.4 中文谱系参照。
** 本章技术栈演进段与 [../bigdata/00-总览与阅读地图.md](../bigdata/00-总览与阅读地图.md) 的大数据技术全景章互为中英镜像：那边从 Hadoop 内核讲起，这边从架构债务讲起——同一个 Spark，一个看它怎么算，一个看它欠了什么。

## 4. 边界与易混点

- **"演进"≠"替代"**：本章若给读者"新架构杀掉旧架构"的印象即误读；
  本书后文（ch11）明确 fabric 叠加于存量 EA 资产。
- **Gartner 源流勿混**：data fabric 概念常溯至 2015 前后 Gartner 报告，mesh 溯至 Zhamak Dehghani 2019/2020 文章（✅ 其 #201 谱系已在盘：[../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md)）；
本书 ch2 才做术语立宪，ch1 不宜提前站队。
- **Microsoft Fabric 命名撞车**（2023 年 GA）：读本章及一切 fabric 章节时先自问是范式设计名还是产品名——防混专表见 00 §4 与 [../Fundamentals_of_Microsoft_Fabric/00-总览与阅读地图.md](../Fundamentals_of_Microsoft_Fabric/00-总览与阅读地图.md)。

## 5. 批判与连接

- 可攻击点：13 页的架构史必然是漫画；

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| 架构债务 | architectural debt | 每次解耦遗留的集成与语义欠账，按找/懂/取/信四类活动计息 |
| Extract, Transform, Load | ETL | 模式前置的搬运范式，集市时代的发动机与瓶颈 |
| 信息集成 | enterprise information integration (EII) | 不搬数据、查询时拼接的早期"虚拟化" |
| 主数据管理 | master data management (MDM) | 以黄金记录统一核心实体的集中治理形态 |
| 数据湖 | data lake | 模式后置、对象存储为底的低成本容器 |
| 湖仓 | data lakehouse | 表格式加持下湖上获得仓库事务与治理语义 |
| 存算分离 | disaggregated storage and compute | 云原生基本形态，独立扩缩两层 |
| 数据编织 | data fabric | 以主动元数据驱动的跨源发现-访问-集成层 |
| 数据网格 | data mesh | 以领域自治与数据产品为单元的社会技术架构 |
| 数据为中心的人工智能 | data-centric AI | 把迭代重心从模型/架构转向数据质量的范式主张 |

## 最新演进与工业实践

- **2024→2026 史观更新**：本章成书于生成式 AI 爆发当口，两年后的增补叙事是：①"集成债"之上又叠加"上下文债"——agent 取数错误的根因是语义供给不足，倒逼元数据从文档升级为机读契约；
② 湖仓阵营反吞：开放表格式+SQL 网关+目录一体化让"编织"能力下沉为湖仓标配（盘上 [../Architecting_an_Apache_Iceberg_Lakehouse/00-总览与阅读地图.md](../Architecting_an_Apache_Iceberg_Lakehouse/00-总览与阅读地图.md) 谱系可见此趋势）；
③ mesh 阵营产品化："数据产品市场"从隐喻变成可计费单元。
- **工业实践**：多云+监管分区（如 GDPR/EU AI Act 数据驻留条款）使本章"债务清单"在欧洲金融机构具象为跨区复制禁令与联邦查询刚需；
国内对应实践为数据要素×公共数据授权运营下的目录-登记双轨，架构史叙事需要加入"合规债"一项才算完整。
