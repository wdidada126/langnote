## 2. 内容地图（⚠️ 重构：五模式决策树 + EA 三问）

**2.1 ch10 拟含的模式族（按"数据动不动"分类，✅ 该分类为公共架构语汇）**

| 模式 | 一句话 | 甜区 | 死穴 |
|---|---|---|---|

## 3. 深读笔记

**3.1 模式章的读法是"排除法"。
** 每模式记住它的**否决条件**比记住优点更重要：P1 被数据驻留法规否决、P2 被源端 SLA 否决、P4 被域无平台能力否决。
⚠️ 推定本书咨询笔法会以"组织成熟度×监管约束"二维给推荐——本目录把它改写为否决清单，工程上更耐用。

**3.2 ch10 与 ch11 的次序本身是论点。
** 先模式后 EA 意味着"架构选择先于治理定位"——与 mesh 原教（组织第一，#201 02 章）相反。
本册的沉默立场（⚠️ 解读）：fabric 是可在 EA 框架内渐进引入的技术增量，mesh 是要重画 EA 的组织事件——两者在本书并置时，ch10–11 单元其实在演示"技术先行论"的写法长什么样。

**3.3 P3 混合模式的税单最被低估。
** 热路径物化+冷路径虚拟化的"同问同答"需要语义层单源（否则两路结果分叉）——这正是 #210 04 章统一语义层主张的工程理由，也本册 ch13 编目章的存在理由：**语义层是混合模式的裁判，裁判的数据结构就是目录**。

**3.4 P4 与 P2 的合体形态（2023 未写透、2026 已成主战场）。
** 产品 API（P4）背后的物化策略若是虚拟化（P2），产品契约的 SLA 就由远端源决定——域团队签一个自己不可控的 SLA 是组织事故。
工程解：产品层强制"可物化逃生口"（必要时快照落地）。
✅ 湖仓侧的对应件即开放表格式快照/分支（盘上 [../Architecting_an_Apache_Iceberg_Lakehouse/00-总览与阅读地图.md](../Architecting_an_Apache_Iceberg_Lakehouse/00-总览与阅读地图.md) 谱系），本目录提供模式学到表格式学的连接桥。

**3.5 EA 定位的中文语料对照。
** ch11 的 TOGAF 语境对国内团队可平移到"数据治理体系+数据架构评审"双轨实践（盘上中文谱系 数据架构之道.md 与 企业级大数据平台构建.md 提供了同问题的中方表述）；
引用本章进立项材料时，把 EA 委员会替换为"数据管理委员会+架构组"即语义等价。

## 4. 边界与易混点

- **参考架构 ≠ 模式集**：前者是给定的完整蓝图（厂商交付物），后者是可组合决策单元；
  把 P1–P5 当套餐点菜是模式章的头号误读。
- **"编织层横切"不能被画成一层盒子**：EA 图上一盒"Data Fabric"恰恰违背模式学——它是 K1–K8 能力在多层里的渗透（03 文件编号复用）。
- **P5 ≠ 流平台替换批**：事件织网改变的是"发现与血缘的时效"，不是存储拓扑；
湖仓仍是底座（对读 [../The_Data_Lakehouse/00-总览与阅读地图.md](../The_Data_Lakehouse/00-总览与阅读地图.md) 的基座论）。
- **本章模式编号 P1–P5 系本目录重构**，非原书编号；"本书提出五模式"是越权句法，禁用。

## 最新演进与工业实践

- **2024→2026 模式动态**：P2 借"warehouse-as-virtualizer"回潮（各云仓的跨源查询/语义视图件）；
P4+P3 合体为主流——"产品 API + 可选物化 + 开放表格式"三件套；
P5 与流式表格式（streaming lakehouse 线，盘上 Apache_Paimon_Streaming_Lakehouse 谱系）合流；
新增 P6 策略即代码位（✅ Open Policy Agent 官方文档 opa.io）。
- **工业实践**：模式选型评审的成熟形态是"否决清单会审"——法务先否 P1（驻留）、SRE 先否 P2（源端 SLA）、域代表先否 P4（平台能力），三方签字后余下的才是可谈方案；
比能力打分卡提前排雷。
国内头部券商/银行的"数据编织"立项书已普遍采用"逻辑为主、物化白名单"的 P3 变体，白名单本身就是审计对象。
- **读法建议**：本文件 2.1 表配合 02 文件 3.3 打分矩阵使用——矩阵定极、模式定形；
  两表交叉处即 POC 脚本。
