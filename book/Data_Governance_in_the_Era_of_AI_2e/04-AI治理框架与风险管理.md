## 一、AI 治理的定义与范围

AI 治理（AI Governance）是数据治理的自然延伸，将治理范围从**数据**扩展到
**模型 + 数据 + 决策**的完整链条。⚠️ 转述

核心治理对象：
1. **训练数据**：来源、质量、合规 → 与 Ch03 衔接
2. **模型本身**：开发、验证、部署、监控
3. **推理输出**：决策的可解释性、公平性、安全性
4. **反馈循环**：模型输出回流为训练数据的治理

## 二、AI 风险分类框架

⚠️ 转述，综合 EU AI Act + NIST AI RMF + ISO/IEC 42001：

### 2.1 按风险等级

| 等级 | 描述 | 治理要求 | 示例 |
|---|---|---|---|
| 不可接受 | 造成严重伤害 | 禁止部署 | 社会评分、操控行为 |
| 高 | 影响基本权利/安全 | 全面合规评估 | 医疗诊断、自动驾驶 |
| 中 | 有限影响 | 透明度义务 | 推荐系统、内容审核 |
| 低 | 最小影响 | 自愿行为准则 | 内部效率工具 |

### 2.2 按风险类型

| 风险类型 | 描述 | 缓解措施 |
|---|---|---|
| 偏见与歧视 | 模型对特定群体不公平 | 偏见检测 + 缓解训练 |
| 幻觉/虚构 | LLM 生成不实内容 | 事实核查 + RAG + 置信度阈值 |
| 数据投毒 | 训练数据被恶意篡改 | 数据溯源 + 完整性校验 |
| 对抗攻击 | 输入被精心设计以欺骗模型 | 对抗训练 + 输入验证 |
| 模型窃取 | 攻击者通过查询推断模型 | 速率限制 + 输出模糊化 |
| 隐私泄露 | 模型记忆并泄露训练数据 | 差分隐私 + 联邦学习 |

## 三、负责任 AI（Responsible AI）框架

⚠️ 转述

### 3.1 六大原则

| 原则 | 含义 | 治理落地 |
|---|---|---|
| 公平性（Fairness） | 不因受保护特征歧视 | 偏见审计 + 公平性约束 |
| 可靠性（Reliability） | 模型稳定可预测 | 回归测试 + 性能监控 |
| 安全性（Safety） | 不造成伤害 | 红队测试 + 安全护栏 |
| 隐私性（Privacy） | 保护个人数据 | 差分隐私 + 访问控制 |
| 可解释性（Explainability） | 决策可理解 | SHAP/LIME + 决策文档 |
| 透明性（Transparency） | 用户知道在与 AI 交互 | 披露义务 + 标识 |

### 3.2 从原则到实践的差距 ⚠️ 转述

| 差距 | 描述 | 缓解 |
|---|---|---|
| 原则→度量 | 抽象原则难以量化 | 定义可操作的 KPI |
| 度量→工具 | 度量需要工具支持 | 集成 Fairlearn / AIF360 |
| 工具→流程 | 工具需嵌入开发流程 | MLOps 集成治理检查点 |
| 流程→文化 | 需要组织文化支撑 | 培训 + 激励 + 问责 |

## 四、模型风险管理（Model Risk Management）

⚠️ 转述

### 4.1 模型生命周期治理

```
开发 → 验证 → 审批 → 部署 → 监控 → 退役
  ↑                                      |
  └──── 反馈循环（模型漂移/事件触发） ────┘
```

每个阶段的治理检查点：
- **开发**：数据合规审查 + 设计文档
- **验证**：性能基准 + 公平性测试 + 安全测试
- **审批**：风险分级 + 合规签章
- **部署**：灰度发布 + 回滚方案
- **监控**：性能漂移 + 数据漂移 + 异常检测
- **退役**：数据保留决策 + 模型归档

### 4.2 模型注册表（Model Registry）⚠️ 转述

| 字段 | 说明 |
|---|---|
| 模型 ID | 唯一标识 |
| 版本 | 语义化版本号 |
| 训练数据快照 | 数据版本引用 |
| 性能指标 | 准确率/召回率/F1 等 |
| 公平性指标 |  disparate impact / equal opportunity |
| 风险等级 | 按 AI Act 分级 |
| 审批状态 | 待审/已批/已拒/已退役 |
| 所有者 | 模型负责人 |

## 五、🔧 本地演示：DuckDB 模型注册表查询

> ⚠️ 非本书引擎/平台行为。以下演示使用 DuckDB 类比模型注册表分析。

```python
import duckdb

# DuckDB 内存数据库演示模型注册表分析
con = duckdb.connect()
con.execute('''
CREATE TABLE model_registry (
    model_id TEXT,
    version TEXT,
    risk_level TEXT,
    accuracy REAL,
    fairness_score REAL,
    deploy_date DATE,
    status TEXT
);
''')

con.execute('''
INSERT INTO model_registry VALUES
    ('fraud-det', 'v2.3', 'high', 0.94, 0.87, '2026-01-10', 'active'),
    ('credit-score', 'v1.1', 'high', 0.88, 0.72, '2025-11-20', 'active'),
    ('chatbot-cs', 'v3.0', 'limited', 0.91, 0.95, '2026-02-01', 'active'),
    ('recommend', 'v4.2', 'minimal', 0.82, 0.90, '2025-09-15', 'active'),
    ('hiring-rank', 'v1.0', 'high', 0.76, 0.65, '2025-06-01', 'suspended');
''')

# 查询：高风险模型且公平性不达标
result = con.execute('''
SELECT model_id, version, risk_level, accuracy, fairness_score, status
FROM model_registry
WHERE risk_level = 'high' AND fairness_score < 0.80
ORDER BY fairness_score ASC;
''').fetchall()

print("高风险 + 公平性不达标模型：")
for r in result:
    print(f"  {r[0]} {r[1]}: accuracy={r[3]}, fairness={r[4]}, status={r[5]}")

# 查询：各风险等级模型分布
dist = con.execute('''
SELECT risk_level, COUNT(*) as cnt,
       ROUND(AVG(accuracy), 3) as avg_acc,
       ROUND(AVG(fairness_score), 3) as avg_fair
FROM model_registry
GROUP BY risk_level ORDER BY avg_fair;
''').fetchall()

print("\n风险等级分布：")
for d in dist:
    print(f"  {d[0]}: {d[1]}个模型, avg_acc={d[2]}, avg_fairness={d[3]}")

con.close()
# 输出:
# 高风险 + 公平性不达标模型：
#   hiring-rank v1.0: accuracy=0.76, fairness=0.65, status=suspended
#   credit-score v1.1: accuracy=0.88, fairness=0.72, status=active
#
# 风险等级分布：
#   high: 3个模型, avg_acc=0.86, avg_fairness=0.747
#   limited: 1个模型, avg_acc=0.91, avg_fairness=0.95
#   minimal: 1个模型, avg_acc=0.82, avg_fairness=0.9
```

🔧 以上为本地 DuckDB 演示，⚠️ 非本书引擎/平台行为。

## 核心概念速览（中英对照）

| 概念 | 英文 | 一句话定义 |
|---|---|---|
| AI 治理 | AI Governance | 对模型+数据+决策的治理体系 |
