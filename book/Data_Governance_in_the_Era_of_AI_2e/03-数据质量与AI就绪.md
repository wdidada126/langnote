## 一、数据质量的经典维度

数据质量是 AI 治理的基石。⚠️ 转述自 DAMA-DMBOK 六维度框架：

| 维度 | 英文 | 定义 | AI 场景示例 |
|---|---|---|---|
| 准确性 | Accuracy | 数据值与真实值一致 | 标签数据是否正确 |
| 完整性 | Completeness | 必要字段无缺失 | 训练集是否有空值 |
| 一致性 | Consistency | 跨系统数据无矛盾 | 多源合并时 ID 匹配 |
| 时效性 | Timeliness | 数据在需要时可用 | 特征数据是否反映最新状态 |
| 唯一性 | Uniqueness | 无重复记录 | 训练样本去重 |
| 有效性 | Validity | 数据符合定义域规则 | 特征值在合理范围内 |

## 二、AI 对数据质量的特殊要求

### 2.1 传统 DQ vs AI-Ready DQ ⚠️ 转述

| 维度 | 传统 DQ 阈值 | AI-Ready DQ 阈值 | 原因 |
|---|---|---|---|
| 缺失值 | < 5% 可接受 | < 0.1% 或需插补策略 | 模型对缺失值更敏感 |
| 标签质量 | 不适用 | > 95% 标注一致性 | 监督学习依赖标签 |
| 类别平衡 | 不适用 | 各类别比例偏差 < 2:1 | 避免模型偏见 |
| 时序连续性 | 批处理容忍间隙 | 流式场景需无缝 | 实时推理依赖连续数据 |
| 特征漂移 | 不适用 | PSI < 0.2 | 训练/推理分布一致性 |

### 2.2 AI 就绪度评估框架 ⚠️ 重构推断

```
AI 就绪度 = f(数据量, 数据质量, 标注完备度, 特征工程成熟度, 合规就绪度)
```

五个子维度评分（1-5 分），加权求和：
- 数据量（Weight=0.15）：样本量是否满足模型需求
- 数据质量（Weight=0.30）：六维度综合得分
- 标注完备度（Weight=0.25）：监督任务标签覆盖率
- 特征工程成熟度（Weight=0.15）：特征管道自动化程度
- 合规就绪度（Weight=0.15）：数据使用授权与 DPIA 状态

### 3.2 数据质量度量指标体系 ⚠️ 转述

```
DQ_Score = Σ(w_i × dimension_i) / Σ(w_i)
```

其中 w_i 为各维度权重，dimension_i 为 0-100 分制得分。

## 四、🔧 本地演示：SQLite 数据质量评分

> ⚠️ 非本书引擎/平台行为。以下演示使用 SQLite（Python stdlib）类比数据质量评分逻辑。

```python
import sqlite3

# 创建数据质量检查结果表
conn = sqlite3.connect(':memory:')
conn.executescript('''
CREATE TABLE dq_check (
    table_name TEXT,
    column_name TEXT,
    dimension TEXT,
    score REAL,
    check_time TEXT DEFAULT (datetime('now'))
);

INSERT INTO dq_check VALUES
    ('training_data', 'label', 'accuracy', 96.5, '2026-01-15'),
    ('training_data', 'label', 'completeness', 99.2, '2026-01-15'),
    ('training_data', 'feature_age', 'validity', 88.0, '2026-01-15'),
    ('training_data', 'feature_age', 'timeliness', 72.3, '2026-01-15'),
    ('training_data', 'user_id', 'uniqueness', 100.0, '2026-01-15'),
    ('training_data', 'user_id', 'consistency', 95.8, '2026-01-15');
''')

# 计算 AI 就绪度综合评分
query = '''
SELECT table_name,
       ROUND(AVG(score), 1) AS avg_dq_score,
       MIN(score) AS min_dimension_score,
       COUNT(DISTINCT dimension) AS dimensions_checked
FROM dq_check
GROUP BY table_name
HAVING avg_dq_score >= 80;
'''
for row in conn.execute(query):
    print(f"表: {row[0]}, 综合DQ分: {row[1]}, 最低维度: {row[2]}, 检查维度数: {row[3]}")

conn.close()
# 输出: 表: training_data, 综合DQ分: 92.0, 最低维度: 72.3, 检查维度数: 6
```

🔧 以上为本地 SQLite 演示，⚠️ 非本书引擎/平台行为。

## 五、数据质量与可观测性的融合

⚠️ 转述

传统数据质量检查是**批处理、事后**的；数据可观测性是**持续、实时**的。
AI 时代要求两者融合：

| 传统 DQ | 可观测性增强 | 融合后 |
|---|---|---|
| 日级批检查 | 分钟级信号采集 | 持续质量评估 |
| 预定义规则 | 自动异常检测 | 规则+ML 混合检测 |
| 事后报告 | 实时告警 | 质量 SLA 即时通知 |
| 单一维度 | 五支柱（新鲜度/分布/量/谱系/质量） | 全面可观测 |

## 六、训练数据质量检查清单

⚠️ 重构推断

- [ ] 缺失值比例 < 阈值（按 AI 就绪标准）
- [ ] 标签一致性 > 95%（多人标注交叉验证）
- [ ] 类别分布偏差在可接受范围
- [ ] 特征漂移检测 PSI < 0.2
- [ ] 训练/验证/测试集无数据泄露（Data Leakage）
- [ ] 数据版本已锁定（DVC / MLflow Tracking）
- [ ] 数据来源合规性已审查（GDPR/版权）
- [ ] 敏感信息已脱敏或获得授权

## 核心概念速览（中英对照）

| 概念 | 英文 | 一句话定义 |
|---|---|---|
| AI 就绪度 | AI Readiness | 数据满足 AI 训练需求的综合评估 |
| 数据质量维度 | DQ Dimensions | 衡量数据质量的六个标准角度 |
| 特征漂移 | Feature Drift | 推理数据分布偏离训练数据 |
| 数据泄露 | Data Leakage | 训练集意外包含推理时才有的信息 |
| 标签质量 | Label Quality | 监督学习中标注的正确性与一致性 |
| 数据可观测性 | Data Observability | 对数据系统健康度的全面监控能力 |
