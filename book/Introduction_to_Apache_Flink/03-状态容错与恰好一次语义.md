## 核心精讲

### 1. 状态是流处理的本体，不是附件

- 每条事件的输出依赖「此前所有相关事件」——聚合值、join 缓存、模式前缀、去重集。
- 放外部 KV（Redis/HBase）行不行？**三失效**：① 一致性无法与计算原子绑定（改状态与发下游之间崩溃 = 半更新）；
  ② 快照无法涵盖外部世界；③ 每事件一跳网络。⚠️ 转述对照：
  [../Streaming_Systems/07-持久状态的实践.md](../Streaming_Systems/07-持久状态的实践.md)（盘上已验名）从
  「推给外部系统 vs 留在引擎」角度论证；湖仓侧的另一答案是 LSM 表当状态：
  [../Apache_Paimon_Streaming_Lakehouse/02-核心数据结构LSM树与主键表.md](../Apache_Paimon_Streaming_Lakehouse/02-核心数据结构LSM树与主键表.md)。
- Flink 的选择：keyed state 本地化到算子实例 + 可插拔状态后端（内存 / RocksDB）+ 随 checkpoint 一致快照。✅ 概念页。

### 2. 屏障快照：不停流的全体照片（⚠️ 转述机制，✅ 官方 checkpoint 页）

- JobManager 周期性向**所有源**注入 barrier；barrier 随数据流向下游流动。
- 算子收到**全部输入通道**的 barrier i 后（屏障对齐），把自身状态快照到持久化存储，再向下游转发 barrier。
  - 对齐 = 期间阻塞较快通道 → 延迟尖峰；反压时放大。
  - 非对齐变体：把在途缓冲一并拍进快照，用空间换延迟 ⚠️（官方 checkpointing 页含 unaligned checkpoints 配置，✅ URL 同上）。
- 一致性论证血脉：Chandy & Lamport 分布式快照（1985）。⚠️ 题名+会议转述，DOI 本环境未过 Crossref 校验，
  故**不给 DOI 链接**；盘上登记线：姊妹册
  [../Stream_Processing_with_Apache_Flink/12-补编-检查点机制与分布式快照.md](../Stream_Processing_with_Apache_Flink/12-补编-检查点机制与分布式快照.md)
  （其 00 已核实 `paper/` 无 Chandy-Lamport 专章，本册同样不造假链接）。
- 恢复 = 全体回滚到最近完成快照 + 从快照记录的**源位点**重放。

### 3. checkpoint / savepoint：两种「可回滚点」的分工

| | checkpoint | savepoint |
| --- | --- | --- |
| 触发 | 引擎自动周期 | 人/CI 显式 |
| 用途 | 崩溃自愈 | 升级、改并行度、迁移、A/B、回滚上一版 |
| 生命周期 | 保留最近 N 个，可能被裁剪 | 用户管理，不自动删 |
| 格式 | 可增量（RocksDB） | 规范全量（跨版本可移植性更好） |

✅ 两页官方文档均实测 200（URL 见头部）。🔧 类比实测 D5（**非 Flink 行为**）：SQLite 在线备份 API 把
200,000 行「作业状态表」一致性拷贝进内存库耗时 **9 ms**（`demo_out.txt`）——类比的仅是
「拍一张全体一致的照片，之后可以从照片重建」这个结构；真实 savepoint 还要处理**状态模式兼容**
（算子 uid 对位、序列化器迁移），SQLite 无此问题，⚠️ 该差异见官方 savepoints 页 "State Schema Evolution"。
工程侧升级剧本（stop-with-savepoint 流程）：[../Stream_Processing_with_Apache_Flink/10-运维监控与调优.md](../Stream_Processing_with_Apache_Flink/10-运维监控与调优.md)。

### 4. 恰好一次 = 三层合谋，缺一角就漏

1. **源可重放**（Kafka offset 随快照回滚）——否则重放起点都找不到。
2. **引擎内状态原子回滚**（屏障快照）——本节第 2 段。
3. **汇的提交与快照同代**：两阶段提交（预写 2PC，checkpoint 完成时才 commit）或幂等汇（主键覆盖写）。
- 🔧 类比实测 D4（**非 Flink 行为**，SQLite 3.45.3）：同一批 20,000 条「带全局唯一 eid」的记账事件**重放两遍**：
  - 幂等表（`INSERT OR IGNORE` + 主键）：count=20000、sum=100326.68（18 ms）——**终态与只跑一遍完全相同**；
  - 裸表（无主键 `INSERT`）：count=40000、sum=200653.36（16 ms）——**sum 被翻倍**，重放即错误。
- 读数 🔧：exactly-once 的本质不是「不重发」而是「**重发无害**」——要么终态幂等，要么提交协议把重放隔离在事务外。
  `sink 的 sum 翻倍` 正是「at-least-once + 非幂等累加」事故的单机缩影。
- ⚠️ 注意类比边界：SQLite 演示不含「提交与快照同代」问题；真实 2PC 的悬挂事务、Kafka 事务 coordinator
  切换、超时清理都在 Flink Kafka connector 文档内（✅ connectors/datastream/kafka 页实测 200）。
- 副作用（发微信/调支付接口）**不可回滚**：exactly-once 语义管不到它们——这是
  [../Streaming_Systems/05-精确一次与副作用.md](../Streaming_Systems/05-精确一次与副作用.md) 的保留曲目，务必对读。

### 5. 快照的经济学：间隔、体积、恢复时间三者互搏

- 恢复代价 ≈ 回滚重放的数据量（≈ checkpoint 间隔 × 流入速率）+ 快照下载 + 状态重建预热。
- 间隔调小的收益是少重放，代价是快照开销与对齐阻塞频率上升——没有普适值，只有业务 RTO 反推。⚠️ 转述。
- 大状态时代：增量 checkpoint（RocksDB）把「每次全量拷贝」变成「只传新 SST」；
  Fast Restore 只登记元数据、访问时懒加载 ⚠️ 转述（✅ 官方 checkpoints 概念页含增量与分层恢复表述）。
- 湖仓场景把这条曲线改写了一半：重放不丢正确性（幂等提交），丢的只是**新鲜度追赶时间**
  （对读 [../Apache_Paimon_Streaming_Lakehouse/05-写入路径与提交协议.md](../Apache_Paimon_Streaming_Lakehouse/05-写入路径与提交协议.md)）。

## 常见误区

1. 「end-to-end exactly-once 是引擎自带属性」——汇不配合（非事务、非幂等）就名存实亡（🔧 D4 裸表）。
2. 「savepoint 比 checkpoint 更可靠」——两者是不同用途的快照；可靠性机制同源 ✅ 官方两页。
3. 「开 exactly-once 就没副作用重复」——外部世界不归快照管（§4 第 3 条）。
4. 「状态大就不能开 checkpoint」——RocksDB + 增量 checkpoint 正是为大状态设计 ⚠️ 转述；调优实感见姊妹册 10 章。
5. 「checkpoint 间隔越小越安全」——间隔 vs 对齐阻塞/快照开销的权衡；反压时可能永不完成 ✅ checkpointing 页最佳实践段 ⚠️ 转述。

## 核心概念速览（中英对照）

- **键控状态** — keyed state：按 key 分区隔离的算子本地状态，并行扩缩的基本单元。
- **状态后端** — state backend：HashMap（内存）/ RocksDB（磁盘+增量快照）的存储实现层。
- **屏障** — barrier：注入流中的特殊标记，划定「哪些数据属于哪一代快照」。✅
- **屏障对齐** — barrier alignment：等最慢通道期间阻塞快通道，代价是延迟尖峰。✅
- **非对齐快照** — unaligned checkpoint：在途缓冲入照，免对齐、增体积 ⚠️。
- **检查点** — checkpoint：引擎自动、周期性、面向崩溃自愈的一致快照（含源位点）。✅
- **保存点** — savepoint：显式触发、面向运维（升级/迁移/回滚）的规范快照。✅
- **状态兼容迁移** — state schema evolution：算子 uid 对位 + 序列化器演进，savepoint 跨版本的核心难点。⚠️
- **两阶段提交** — two-phase commit (precommit/commit)：预写随 checkpoint、提交随完成，重放被事务隔离。✅
- **幂等汇** — idempotent sink：主键覆盖写使重放无害（🔧 D4 的去重表）。
- **可重放源** — replayable source：位点可回退（Kafka offset），重放的前提。
- **副作用** — side effect：引擎状态之外的世界动作，exactly-once 的语义盲区。
- **至少一次** — at-least-once：不丢可重；配非幂等累加即翻倍（🔧 D4 裸表缩影）。
