## 2. DataHub（⚠️ 转述；仓库 ✅ https://github.com/datahub-project/datahub ）

- 模型：**实体-切面 + 关系图**（`02`§1 的原型），事件溯源式变更提案（MCPS 信封，⚠️ 名词转述）。
- 栈：Java server + Kafka + （MySQL/PG）+ ES/OpenSearch；2021–2022 引入
  "Kafka-as-database"路线（⚠️ 公开设计谈资转述）。
- 生态位：连接器面最广的开源项之一（具体数 ⚠️ 不引官方营销数），企业元数据平台叙事
  （metadata platform / metadata-driven）的主要旗手。
- 风险面（⚠️ 评价性）：组件重（Kafka+ES+DB 三件套），小团队运维税高。

## 3. Amundsen（⚠️ 转述；仓库 ✅ https://github.com/amundsen-io/amundsen ）

- 模型：微服务三件套（frontend/metadata/search）+ Neo4j 图库 + ES 索引（⚠️ 架构转述，
  该册与图数据库谱系对读：[../Graph_Databases_2e/00-总览与阅读地图.md](../Graph_Databases_2e/00-总览与阅读地图.md) ✅ 盘上）。
- 历史地位：2019 年把"搜索+血缘+预览"做成可部署产品的启蒙者；CNCF 孵化背景（⚠️ 转述）。
- 现状判断（⚠️ 评价性、留余地）：2023–2025 社区活跃度信号弱于 DataHub/OpenMetadata
  （以仓库提交面为凭，不作断言），新建项目选型中多作"概念来源"而非落地项。

## 4. OpenMetadata（⚠️ 转述；仓库 ✅ https://github.com/open-metadata/OpenMetadata ）

- 模型：**类型化实体 + JSON Schema 定义**、一体化 server（PG 存真相、ES 可插拔），
  血缘为内建一等 API（⚠️ 架构转述）。
- 差异点：把"数据资产 + 契约/测试 + 洞察"塞进同一 schema 面（"generalized metadata
  object model"叙事 ⚠️）；2024–2025 进 Apache 孵化器的动向（⚠️ 转述，以 incubator 公告为准）。
- 生态位：介于 DataHub（重）与自建（轻）之间的"单体友好"开源选项（⚠️ 评价性）。

## 5. Unity Catalog（⚠️ 转述；文档 ✅ https://docs.databricks.com/aws/en/data-governance/unity-catalog/data-lineage ）

- 定位：Databricks 的**中央授权+治理 catalog**——三层命名空间（catalog.schema.object），
  管权限/血缘/审计，Delta 之上再管多格式（2024 起"Open Sourcing Unity Catalog"线，⚠️ 转述）。
- 与"目录"的语义差：UC 是**机器面 catalog（治理强制点）**，元数据检索/协作面靠外联或
  内置轻量面补足（⚠️ 评价性）——它是 `01`§4 "目录 vs catalog"辨析的现实化身。
- 引擎接入面（可实测对位 🔧 邻近）：DuckDB/Spark 等经 UC 的 REST/S3 签名协议访问托管表，
  本系列实测侧对读 [../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md](../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md)
  （✅ 盘上；其对"外部 catalog ATTACH 读"的实测口径与本目录 Iceberg REST 读结论一致——可装≠可查）。
- 血缘：表/列/文件级 lineage 系统表出口（✅ 上述文档页 200；完备度 ⚠️）。

## 6. Apache Polaris / Lakehouse 协议世代（⚠️ 转述；仓库 ✅ https://github.com/apache/polaris ）

- 出身：Tabular 团队（2024 被 Snowflake 收购，⚠️ 转述交易事实）捐给 Apache 的
  **Iceberg REST Catalog 服务端实现**，进入孵化器（⚠️ 以 ASF 页面为准）。
- 主张：catalog 即"开放元数据 API 的强制点"——凭证铸造（credential vending）、细粒度权限、
  多引擎一致视图（⚠️ README/设计面转述）。
- 与 UC 的对位：同一生态位（治理 catalog 服务端）的**开放协议版 vs 厂商托管版**竞争；
  机制底座都是 Iceberg REST Catalog 规范（✅ https://iceberg.apache.org/docs/latest/ ，
  中文机制版 [../Apache_Iceberg活用入門/07-Catalog生态.md](../Apache_Iceberg活用入門/07-Catalog生态.md) ✅ 盘上）。
- 同族：Project Nessie（git-like catalog，✅ https://projectnessie.org/ 200）代表"版本化 catalog"
  支线；Lakekeeper 等新 REST 服务端 2024–2026 涌现（⚠️ 存在性转述，本环境未逐一实查，不作清单）。

## 7. 老前辈与云托管：HMS/Glue/Data Catalog 一句话谱（⚠️ 转述）

- **Hive Metastore**：表目录协议的原点（Thrift），赢在事实标准、输在治理与人类面（`01`§3 已述）。
- **AWS Glue / GCP BigLake·Dataplex / Azure Purview→Defender 系**：云厂商"目录+爬取+治理"
  托管套餐（⚠️ 一律不给 URL 与功能断言，厂商页改姓频繁，本目录只登记物种不登记细节）。
- 教训同构：**协议寿命 > 控制台寿命**——选型时给"可导出实体模型"最高权重（⚠️ 观点）。

## 8. 选型矩阵（重构方法论，⚠️ 评价性内容全部标注）

| 维度 | 问什么 | 谱系倾向（⚠️ 评价） |
|---|---|---|
| 部署税 | Kafka+ES+DB 三件套养得起吗 | 养不起→OpenMetadata/自建轻栈（`04`🔧 路线）；养得起→DataHub |
| 栈绑定 | 是否全家 Databricks/Snowflake | 是→UC/Polaris 顺从协议；否→开放目录+OpenLineage |
| 血缘深度 | 列级要还是不要 | 要→引擎侧观测覆盖度决定一切（`03`§4），目录品牌其次 |
| 身份模型 | 与自家命名空间能对上吗 | URN 扩展面/别名机制（`02`§5）重于功能清单 |
| 退出成本 | 全量导出实体+边的 API 有吗 | 无=红灯（`01`§6 注册谬误的组织版） |

**反基座立场（重构自该书系谱的公开立场，⚠️）**：目录选型的第一性问题不是"选哪家"，而是
"元数据的真相源要不要离开源系统"——所有平台失败模式里，"把目录当第二数据库手填"排名第一（⚠️ 观点）。

## 核心概念速览（中英对照）

- **DataHub** — DataHub：LinkedIn 开源元数据平台，实体-切面图模型+事件链，连接器面最广之一（⚠️）。
- **Amundsen** — Amundsen：Lyft 开源发现微服务派目录（Neo4j+ES），2019 产品叙事启蒙者（⚠️）。
- **OpenMetadata** — OpenMetadata：Collate 开源一体化元数据 server，类型化 JSON Schema 路线（⚠️）。
- **Unity Catalog** — Unity Catalog：Databricks 治理 catalog（三层命名空间+强制点），开源化中（⚠️）✅URL。
- **Apache Polaris** — Polaris：Snowflake/Tabular 系捐 Apache 的开放 Iceberg REST Catalog 服务端（⚠️）✅URL。
- **治理强制点** — Enforcement Point：查询路径必经的鉴权/血缘/审计卡口；catalog 的新身份。
- **凭证铸造** — Credential Vending：catalog 代管对象存储短时凭据，数据不下沉到引擎配置（⚠️）。
- **三层命名空间** — Three-level Namespace：catalog.schema.object，Iceberg REST 世代通用词表。
- **Nessie** — Nessie：git-like 版本化 catalog 支线（分支/合并式数据开发）（✅URL）。
- **部署税** — Operational Tax：平台组件数×运维专业度，开源目录选型的隐性成本主项（⚠️ 观点）。
- **可导出性** — Exportability：实体+边全量 API 导出能力，目录选型的退出成本阀门（⚠️ 观点）。

## 最新演进与工业实践

- **2024–2026 主叙事：目录与 catalog 合体**。UC 开源化（⚠️ 转述；✅文档页 200）、Polaris 入 ASF
  （⚠️ 转述；✅仓库 200）、Iceberg REST 协议各家兼容竞赛（✅ https://iceberg.apache.org/docs/latest/ ）——
  "元数据目录"与"表 catalog"的分界线成为本年度最活跃的架构政治。
- **开放目录互认（2024 发起线）**：多厂商参与的开放目录倡议（⚠️ 存在性转述，本环境未获可 200
  一手页故不给 URL），方向=实体/血缘事件模型互认，与 OpenLineage（✅ https://openlineage.io/docs/ ）合流。
- **Amundsen 的遗产化**：独立部署趋冷、概念（preview 服务/三服务拆分）被吸收（⚠️ 评价性；
  仓库 ✅ https://github.com/amundsen-io/amundsen 仍在线）。
- **引擎侧消费形态**：DuckDB ATTACH Iceberg REST/元数据服务端的实测边界（可装、读路径快速演进）
  见 [../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md](../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md)（✅ 盘上，🔧 其内部实测）——
  选型测试清单（`03`§6 风格）应含"你的引擎能不能直接吃这个 catalog"一行。
- **数据（本册不实测声明）**：本章零 🔧。任何性能/成熟度对比在验收时都不应引用本目录——
