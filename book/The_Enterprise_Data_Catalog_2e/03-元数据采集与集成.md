> **证据级声明**：同 01/02 口径（取证链见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §2）。

## 1. 连接器（connector/ingestion source）：目录的供应链

目录不生产元数据，只做搬运与归一。按源类型分五族（分类学为重构 ⚠️，各族机制如下）：

| 源族 | 采什么 | 机制 | 典型坑 |
|---|---|---|---|
| 仓/库（JDBC） | schema/列/统计 | pull：`information_schema` 游标 | 大 catalog 全量扫超时；权限视图偏差（看到的 schema ≠ 别人看到的） |
| 湖/表格式 | 快照链/分区演化 | 读元数据文件（Iceberg metadata.json） | 快照爆炸（见对读章） |
| 变换层（dbt） | 模型 DAG/测试/描述 | 读 `manifest.json`（push 性质的文件交换） | 只采得到跑过 dbt 的部分，裸 SQL 成暗物质 |
| BI（Tableau/PowerBI/Superset） | 看板→查询→列使用 | 官方 API 或仓库表扫描 | 计算字段/自定义 SQL 里的血缘断头 |
| 调度/执行（Airflow/Spark） | 运行事件、真实 IO | **push 事件**（OpenLineage/WHL） | 事件乱序与幂等 |

**工程判据（⚠️ 转述口径）**：连接器价值 = 源覆盖数 × 每源"深度"（只拿表名 vs 拿到列级映射
+ 描述 + 所有者）。宣传页上的"支持 60+ 源"属于前者计数，选型 PoC 应固定考三题：
列级血缘拿不拿得到？删除同步（源端 drop 后目录里消失吗）？增量还是全量？

## 2. 扫描工程：pull 侧的脏活

- **限流与错峰**：对生产仓的 `SHOW TABLES/DESCRIBE` 风暴是真负载；实践上走只读副本/
  元数据专用账号（⚠️ 社区普遍口径）。
- **删除语义**：schema 采集是"快照事实"，必须带 `observed_at` 并做 tombstone，否则幽灵表永生。
- **写放大**：百万级表 × 每日全量 diff → 切面版本号暴涨；正确姿势是 hash 比对后只写变更切面（⚠️ 转述，
  DataHub MCP 变更处理器/EMIT 事件的公开设计谈资，仓库 ✅ https://github.com/datahub-project/datahub ）。
- **凭据卫生**：连接器凭据集中托管（Vault/KMS）而非落在 yaml——目录自己先要过合规审。

## 3. 事件上报：push 侧与 OpenLineage

OpenLineage 的 RunEvent 信封（✅ 规范文档实查 https://openlineage.io/docs/ curl 200）：

```json
{"eventType":"COMPLETE","eventTime":"...","run":{"facets":[...]},
 "job":{"namespace":"airflow","name":"dag.task"},
 "inputs":[{"namespace":"hive","name":"db.stg_orders","facets":{...}}],
 "outputs":[{"namespace":"hive","name":"db.fact_orders","facets":{...}}]}
```

- `inputs/outputs` 给出**这次运行真实读过/写过什么**——血缘证据的最小充分单元；
  facet 扩展位承载列级映射（columnLineage facet）、schema、数据质量结果等（⚠️ 各 facet
  成熟度转述）。
- 集成面（⚠️ 转述，均开源可查仓库）：Airflow 监听器、Spark spark-openlineage 插件、dbt 适配。
  历史注脚：该规范源自 2021 年 WeData/RunHistory 系血缘事件谱系（⚠️ 转述）。
- **语义提醒**：OpenLineage 事件流本质是一条**数据流**——乱序、迟到、重放、幂等去重的
  全部流处理语义原样适用，详见 [../Streaming_Systems/00-总览与阅读地图.md](../Streaming_Systems/00-总览与阅读地图.md)（✅ 盘上）。
  目录侧最常见的事故即"事件重放导致血缘边翻倍"（⚠️ 工程转述）。

## 4. 血缘的两条获取路线：解析 vs 观测（本章枢纽论点）

| | SQL 解析（静态） | 运行时观测（事件） |
|---|---|---|
| 覆盖面 | 未执行的分支也能给近似血缘 | 只记录"真发生过"的边 |
| 精度 | 动态 SQL/UDF/存储过程处断头 | 引擎说啥是啥（含隐式临时表风险） |
| 成本 | 方言解析器是长期税 | 埋点改造一次性 |
| 学术线 | 列级抽取系统持续上新：LineageX（ICDE 2025，✅ DOI 10.1109/icde65448.2025.00363 过 Crossref 200）、SQL 血缘抽取技术综述（2025，✅ DOI 10.63345/jqst.v2i1.170 过 Crossref 200） | OpenLineage/WHL 生态 |

2024–2026 的工程共识（⚠️ 转述）：**观测为主、解析兜底**——对无法埋点的遗留系统（视图、
ETL 老工具）才退到解析器；中文侧解析器实现细节见
[../数据血缘分析原理与实践.md](../数据血缘分析原理与实践.md)（✅ 盘上）。

## 5. 样例数据（data profile/sample）：目录碰不碰"数据本身"

- 目录页展示 25 行样本/列分布画像，是"可信发现"的临门一脚（⚠️ 功能普遍性转述）。
- 红线：样本即数据副本 → 采样必须在源端做**脱敏后投影**（只取非敏感列、哈希或掩码），
  目录不接原始行；PII 分级列默认禁采样。各家实现均把"样本落地策略"做成配置矩阵（⚠️ 转述）。
- 画像统计（null 率、distinct、直方图）比样例行更安全，是运营元数据的一等来源（对读 `01`§2）。

## 6. 采集面的验收测试清单（重构给读者自用，⚠️ 方法论）

1. 源端 drop 一张表 → 目录中该实体在多长时间内消失/标记？（删除同步 SLA）
2. 同一作业重放 3 次 → 血缘边数不变？（幂等）
3. 列改名 → 旧列血缘断、新列接上，还是整表重影？（身份稳定性）
4. 权限收缩账号跑连接器 → 得到的是"部分世界"还是明确报错？（残缺可见性）
5. 10 万表仓库首扫耗时与增量扫耗时之比？（扫描税）

——每题都对应 §2/§3 的一个坑；选型 PoC 直接抄此清单。

## 6b. 采集管道的工程形态（状态、水位、回放，⚠️ 转述 + 一点 🔧 邻近）

pull 侧要存"扫到哪"（表清单指纹水位），push 侧要存"消费到哪"（事件流 offset）——两套状态
都是键值对加时间戳，工程上最常见的落点就是采集器自带的 sqlite/PG 状态表；本目录 `04` 的
FTS5/递归 CTE 两次 🔧 演示（sqlite3 3.45.3，方法见 00§7）顺手验证了同一结论：**小规模采集
状态+倒排+图边三样东西，一个库文件装得下**——"目录必须分布式"在 10 万资产以下是伪需求
（⚠️ 观点，超出即反例丛生）。回放（backfill）设计两原则：源端事件带幂等键；回放与实时流
在存储层汇合点必须唯一（否则 `02`§5 的身份直接碎裂）。

## 核心概念速览（中英对照）

- **连接器** — Connector / Ingestion Source：目录从具体源拉/收元数据的适配器，价值在深度非数量。
- **pull 扫描** — Pull/Scan：定时读 information_schema 的采集拓扑；只有"现在时"，没有历史事件。
- **push 上报** — Push/Event-based：执行现场发标准事件（OpenLineage），血缘与使用画像的唯一可靠来源。
- **RunEvent** — OpenLineage 事件信封：job+run+inputs+outputs+facets 的运行事实记录。
- **facet** — Facet：事件中可插拔的扩展切面（schema、列级映射、质量结果）。
- **静态解析 vs 运行时观测** — Parse vs Observe：血缘两条获取路线；观测为主、解析兜底。
- **暗物质** — Dark Matter (unlineaged SQL)：不经统一管道执行的裸 SQL/工具写入，血缘图的永久盲区。
- **tombstone/删除同步** — Deletion Sync：源端对象消失后目录实体的清算语义，防幽灵资产。
- **数据画像** — Data Profiling：null 率/distinct/直方图等统计派元数据，比样例行合规友好。
- **脱敏采样** — Masked Sampling：源端投影+掩码后才允许进目录的样例行。
- **幂等重放** — Idempotent Replay：同事件多次到达不翻倍血缘边，元数据流处理的日常要求。

- **解析器学术线**：列级 SQL 血缘抽取在 ICDE 2025 仍有新系统（LineageX，✅ DOI 过 Crossref 200），
