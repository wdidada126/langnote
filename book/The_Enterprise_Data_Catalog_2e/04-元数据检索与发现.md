## 1. 为什么元数据检索"几乎就是"文档检索

目录实体天然是一篇小文档：`名称 + 描述 + 列名/列注 + 标签 + 术语 + 所有者` 拼接后即索引对象。
所以搜索引擎工业界的全部机制（分词→倒排→打分→facet）可以整体平移。区别只在三点（本章主线）：

1. **字段加权**：命中表名 ≫ 命中描述 ≫ 命中样例值（权重语义 ⚠️ 转述各家目录通用做法）；
2. **facet 是产品主体**：平台/环境/标签/所有者/分级作为过滤面，搜索框反而是配角；
3. **点击反馈 = 流行度信号**：运营元数据回流排序（popular/最近使用）。

## 2. 🔧 演示一：倒排索引 30 行建起来（类比：元数据检索=倒排）

对 6 条玩具目录资产（表/源/策略文档）的 `描述+标签` 做分词，DuckDB 一条 `CREATE TABLE AS`
建出倒排表 `postings(token, asset_id, tf)`：

```sql
CREATE TABLE postings AS
SELECT LOWER(t) AS token, id, COUNT(*) AS tf
FROM (SELECT id, unnest(regexp_extract_all(lower(descr || ' ' || tags),'[a-z0-9]+')) AS t
      FROM asset)
GROUP BY 1,2;
```

**实测数字（DuckDB 1.5.5，本机一次运行）**：6 资产 → **42 个去重 token、56 条 postings**。
查询 `customer pii`：对每个词元直接取 postings 行再按「命中词数 → Σtf」聚合打分——

```text
[(1, 2, 3), (4, 2, 3), (2, 1, 1), (5, 1, 1)]   # (asset_id, 命中词数, 得分)
```

资产 1（fact 表）与 4（customer 360 表）双双命中两词排前；`pii` 的 df（含该词的资产数）=4、
`customer`=2、`orders`=3——df 大的词区分度低，这就是 TF 之外还要 df/IDF 的原因（玩具版 BM25
的骨架已在）。查询耗时 8.6ms（含会话预热；机制上倒排合并是 O(匹配 postings 数)）。

**类比标注**：真实目录产品用 Elasticsearch/OpenSearch 或其衍生（⚠️ 转述），但"token→postings
→打分"三层结构与本演示完全同构；把 `asset` 表换成带权限视图的实体表，就是最小可用目录检索。

## 3. 🔧 演示二：SQLite FTS5——"真倒排"就在标准库里

本机 Python 3.13.2 内置 sqlite3（3.45.3）**编译含 FTS5**：

```python
s.execute("CREATE VIRTUAL TABLE ft USING fts5(body)")
... WHERE ft MATCH 'customer AND pii'  -- 返回 (1,), (2,)，bm25() 可算分
```

`MATCH 'pii OR order'`、前缀查询、`bm25()` 加权和全部可用。工程含义：**单体小工具/内部平台
不必为此拉一个 ES**——「PG+pgvector」之外还有一条「SQLite FTS5 目录内核」极简路线（此论为本
目录作者观点 ⚠️，非原书论点）。倒排索引机制的正主论述见
[../从Lucene到Elasticsearch.md](../从Lucene到Elasticsearch.md)（✅ 盘上，中文单文件），其 Lucene
段/跳表结构与本演示的 postings 一一对位（本演示省掉了跳表与压缩链）。

## 4. 检索之上的"发现"产品面（⚠️ 转述各家目录共有形态）

- **浏览面（browse first）**：按域/平台/所有者的目录树 + 推荐位；大量用户从不输入查询词。
- **facet 设计的 LIS 血统**：分面分类（Ranganathan 谱系）→ 目录过滤面。Olesen-Bagneux 的同名书
  （✅ 豆瓣实抓 https://book.douban.com/subject/36302667/ ，其简介明言 library and information
  science 视角）整本书押在这条线上——与 Hayes 系谱的平台工程线构成 00§3.3 的两极辨析。
- **同义词与术语表回灌**：业务词→字段的映射（glossary）参与查询扩展；"客户=consumer=cust"
  在 postings 层做 alias token 即可实现（本演示加一行 postings 插入就是）。
- **零结果治理**：搜不到 ≠ 不存在 ≠ 该新建；零结果日志是需求采集器（⚠️ 实践转述）。
- **权限感知的检索**：过滤必须发生在打分前还是展示前——正确答法取决于目录与授权系统的
  协议（push ACL 进索引 vs 查询时回源校验；⚠️ 各家实现不同，均转述）。

## 5. 语义检索：向量化进入目录（2024–2026 增量）

- 描述/列注 embedding + 查询 embedding 的向量召回，与倒排**混合**（hybrid）做粗排——
  机制与本目录姊妹册（#124 向量数据库，本波兄弟，登记于
  [00-总览与阅读地图.md](00-总览与阅读地图.md) §6，写作期不实链）完全共享。
- 元数据检索的向量特化点：语料是**亿级短文本**（列注一句话），单条 embedding 便宜但总量大；
  增量重嵌入（schema 变更后）比全量重建更关键（⚠️ 工程转述）。
- LLM 直连目录（自然语言→检索→实体页上下文→回答"哪张表能用"）是 2025–2026 的
  agentic discovery 形态；检索层不变，变的是查询生成器（⚠️ 转述；本环境无法实测任何厂商实现）。

## 6. 度量与调优（重构口径 ⚠️）

| 信号 | 用法 |
|---|---|
| 首位命中排名（MRR） | 搜索质量主指标，按域分层看 |
| 零结果率 | 语料缺口/术语缺口探测器 |
| 点击后 5 分钟留存 | 防"标题党表"（名字好描述空） |
| 搜索→建表转化 | 最诚实指标：搜而不得才重复建设 |

DataHub/OpenMetadata 搜索配置面的公开形态，转述）。

## 核心概念速览（中英对照）

- **倒排索引** — Inverted Index：token→(doc,tf) postings 表，元数据检索与文档检索的共同内核（🔧 本演示 42 token/56 postings）。
- **postings** — 倒排链表项：一条 (词, 资产, 词频) 记录；合并两条 postings 链即得 AND 命中。
- **df / IDF** — Document Frequency / Inverse DF：词的区分度度量（🔧 pii=4 vs customer=2 → 前者信息少）。
- **字段加权** — Field Boosting：表名>描述>样例值的命中计分策略，目录检索特化点一。
- **分面** — Facet：平台/环境/标签/所有者过滤面，LIS 分面分类的产品化，目录检索特化点二。
- **bm25** — BM25 打分：TF-IDF 家族的事实标准；SQLite FTS5 内置可用（🔧 实测返回分数）。
- **FTS5** — SQLite 全文检索虚表模块：单机场景免 ES 的真倒排实现（本机 Python sqlite3 3.45.3 编译含之，🔧）。
- **混合检索** — Hybrid Search：倒排召回+向量召回并集打分，2024–2026 目录检索主流形态（⚠️）。
- **零结果率** — Zero-Result Rate：搜索无命中比例，语料与术语缺口的量化探针。
- **MRR** — Mean Reciprocal Rank：首位正确资产的名次倒数均值，搜索质量主指标。
- **agentic discovery** — 智能体发现：LLM 生成查询与解释、检索层照旧的新一代目录入口（⚠️ 转述）。
