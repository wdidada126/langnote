## 1. Active Metadata：从"档案库"到"神经系统"

- 定义（⚠️ 行业共识口径，DataHub 系叙事旗手）：元数据不再只是被查阅的档案，而是
  **以事件流形式持续产生、并能触发自动化动作**的运营信号——采集→标准化→上下文富化→
  动作（trigger/steward 任务）→再采集，构成闭环（"active metadata loop"名词面 ⚠️ 转述）。
- 与 `03` 的关系：OpenLineage/查询日志是"主动"的燃料；与 `05` 的关系：影响分析从"人查图"
  升级为"图驱动工单"。
- 判别式（观点 ⚠️）：**你的目录里任何一张页面被打开时，数据是"刚扫的"还是"正在流的"**——
  前者 registry，后者 active。扫描制目录的 TTL 以天计，事件制以秒计。
- 该叙事的工业载体：2024–2026 各目录厂商把"active metadata"从口号做成自动化规则引擎
  （策略触发、SLA 断言、异常新鲜度告警）（⚠️ 转述，无一手实测）。

## 2. 数据契约（data contract）与目录的合流

- 契约=生产者与消费者的可执行承诺（schema+语义+SLA+责任），治理"事前图"；血缘是"事后图"
  （对读 `05`§5）。思想源头在 mesh 的"数据即产品契约"（✅ 原文实抓谱系：
  https://martinfowler.com/articles/data-mesh-principles.html curl 200；中文化论述见
  [../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md) 术语锚点 ✅ 盘上）。
- 目录的角色（⚠️ 转述）：契约的登记处（谁承诺了什么）、检索面（消费者找契约）、
  执法回传口（契约破坏事件回流成运营元数据）。2024–2026 出现"契约文件（YAML）即实体切面"
  的直接入库形态（⚠️ 存在性转述）。
- 与前史：Inmon 的 CIF 元数据库管的是"仓库内一致性承诺"，契约管的是"组织间接口承诺"——
  同一职能的所有权范式转移（对读 [../Building_the_Data_Warehouse/12-高级话题与企业信息工厂.md](../Building_the_Data_Warehouse/12-高级话题与企业信息工厂.md) ✅ 盘上）。

## 3. 目录在 mesh 与 fabric 叙事中的位置（三部曲辨析）

| 叙事 | 目录扮演 | 一句判词（⚠️ 观点） |
|---|---|---|
| Data Mesh（范式） | 发现/可组合性的共享基础设施，联邦治理的执行数据面 | "没有目录的 mesh 退化为烟囱林立" |
| Data Fabric（产品叙事） | 元数据驱动的集成/推荐自动化层，目录是其引擎室 | fabric ≈ active metadata 的厂商语法 |
| 目录本位（本书系谱） | 主角：技术+业务+运营元数据合流本体 | mesh/fabric 都是目录的"客户"而非替代 |

三者在 2024–2026 收敛为同一张施工图：开放表格式（catalog 协议）+ 血缘事件（OpenLineage）+
契约登记 + 自动化策略——目录厂商与 catalog 厂商互相吞并，格局对读 `06` 文末演进节（⚠️ 转述格局判断）。

## 4. LLM/AI 时代：目录是 AI 的"地图"（2024–2026 主增量）

- **RAG-for-data / text-to-SQL 的前置依赖**：LLM 要回答"上季度华东退货率"，必须先把
  "退货率"锚到指标实体、把表锚到权限内资产——目录检索面（`04`）成为 AI 工具的
  tool-calling 后端；元数据质量直接决定 AI 取数上限（⚠️ 行业共识转述，本环境不实测任何厂商）。
- **元数据的生产侧也被 LLM 接管**：自动生成描述/同义词/标签建议、从看板反推指标定义、
  血缘断口补全建议（⚠️ 各产品 2024–2026 功能面转述；人机回环确认仍是默认安全模式 ⚠️）。
- **上下文图谱（context graph）话术**：知识图谱复兴 + 元数据图的合流叙事（2025–2026 活跃 ⚠️），
  实质主张：给 LLM 的检索单元从"文档块"升级为"实体+关系子图"。对位机制：`02`§1 的三元组
  内核、`05` 的可达性查询即子图拉取。
- **风险登记**（⚠️ 观点）：LLM 生成的描述进入目录再被 LLM 检索引用，形成**元数据回声室**——
  生成内容必须带 provenance 切面（AI 生成、人审状态），否则发现层会被合成描述淹没（防线设计
  为目录作者观点 ⚠️，非该书可证内容）。

## 5. 目录与可观测性、FinOps 的合流（⚠️ 转述各一点即止）

- 数据可观测性（新鲜度/分布/体积/血缘四信号）产品与目录的双向吞并：目录吸收监控面，
  监控工具长出目录页——2024–2026 边界持续溶解（⚠️ 格局转述，不点名营销对比）。
- 成本归因：查询日志派生的"谁在扫哪张表"元数据，是 FinOps 与治理共用的同一份原料；
  运营元数据（`01`§2 第三类）的商业权重显著上升（⚠️ 观点）。

## 核心概念速览（中英对照）

- **主动元数据** — Active Metadata：事件流化、可触发自动化的元数据形态；判别式="正在流的"。
- **元数据闭环** — Active Metadata Loop：采集→富化→动作→再采集的自我强化回路（⚠️ 名词转述）。
- **数据契约** — Data Contract：生产者-消费者的可执行承诺集；目录=登记处+执法回传口。
- **context graph** — 上下文图谱：实体+关系子图作为 LLM 检索单元的话术，元数据图的 AI 化（⚠️）。
- **元数据回声室** — Metadata Echo Chamber：AI 生成元数据被 AI 再引用增殖的退化回路（⚠️ 观点）。
- **provenance 切面** — Provenance Aspect：标注元数据内容之生成者与审核状态的必备字段。
- **RAG-for-data** — 数据侧检索增强：目录检索面充当 LLM 取数工具的 tool-calling 后端（⚠️）。
- **联邦治理执行面** — Federated Governance Execution：mesh 政策在目录数据面上的机器可读化。
- **可观测性合流** — Observability Convergence：新鲜度/质量信号与目录互吞的产品边界溶解。
- **成本归因元数据** — FinOps Metadata：查询画像派生的"谁扫什么表"，治理与降本共用原料。
- **事前图/事后图** — Contract vs Lineage：契约定义应然依赖、血缘记录实然依赖，二者对账。
