# 09 Managing the Machine Learning Life Cycle（机器学习生命周期管理）

> 原书 Ch9，pp.395–429（35 页）——本册的 2021 特色收尾：入门书肯用最后一章讲 MLOps。内容主轴：MLflow 三件套（Tracking/Projects/Models）、特征平台、部署与监控。二级小节未实抓 ⚠️，主题簇依章题、页幅与 MLflow 官方文档结构推定；属**精读重构**。

## 9.1 为什么入门书要讲生命周期 ⚠️

- 论点重构：Ch8 产出一个「模型」只完成生命周期的 20%；剩下的 80% 是实验可追溯、工件可复现、上线可回滚、漂移可告警。本册把 ML 线收在「一个模型从 notebook 到生产」的旅程图上，而非算法清单。
- 与作者画像吻合（✅ Springer About the author 实抓：Hien Luu 在 Data+AI Summit、MLOps World 持续演讲）——这一章是作者兴趣所在，深度观感明显高于 Ch8 ⚠️。
- 对照：TDG 把 ML 停在算法面（[../Spark_The_Definitive_Guide/08-机器学习MLlib.md](../Spark_The_Definitive_Guide/08-机器学习MLlib.md)），生命周期叙事在本谱系里是本册独占位。

## 9.2 MLflow：实验追踪的标准答案 ⚠️

- 三件套（官方文档口径，锚点 https://mlflow.org/docs/latest/ ✅ curl 200）：**Tracking**（参数/指标/artifact 的记录与对比 UI）、**Projects**（conda/docker 环境封装的可复现运行）、**Models**（多框架导出+模型注册）。
- 与 Spark 的接缝：Spark 训练出的 `PipelineModel` 可 `mlflow.spark.log_model` 导出为 flavor（python_function 兜底可跨环境加载）⚠️；本册给的样板即「Ch8 的 GBT 管道 → MLflow 注册 → REST 服务」一条龙。
- 概念最小面：run/experiment 两级账本、`autolog` 自动埋点、比较视图——入门者先建立「**指标是记录出来的，不是记在脑子里的**」这一条纪律。

## 9.3 特征平台与数据工件 ⚠️

- Feature Store 的问题定义：训练/推理特征一致性（point-in-time correctness）、复用与发现、在线低延迟取数；Spark 侧的历史叙事：Databricks Feature Engineering（本册成书时点的新品 ⚠️）与开源 Feast 一类平台。
- 诚实标注：本册给概念+最小示例，未给在线服务架构（feature serving 的 KV/延迟预算是后续读物域）——波8 内 #150/#196 亦不深此线，盘上湖仓册对位 [../Data_Lakehouse_in_Action/00-总览与阅读地图.md](../Data_Lakehouse_in_Action/00-总览与阅读地图.md)。

## 9.4 部署、监控与回滚 ⚠️

- 部署形态三面：批量打分（Spark 作业跑预测——MLlib 模型 `transform` 直接吃 DataFrame，这是 Spark 栈的顺手处）、REST 实时服务（MLflow models serve/云托管）、边缘导出（概念级）。
- 监控四件套（重构自本章语境 ⚠️）：延迟/错误率、输入分布漂移（PSI/KL）、指标衰减、数据质量断言——与数据可观测栈合流的入口；盘上对位 [../Data_Observability_for_Data_Engineering/00-总览与阅读地图.md](../Data_Observability_for_Data_Engineering/00-总览与阅读地图.md)。
- 回滚纪律：注册表版本化 + 别名（alias）切换；「模型是工件，工件要有版本号」——把 Ch8 的可序列化管道与 9.2 的注册表缝合成闭环。

## 9.5 🔧 单机标本：版本化与重放（SQLite 3.45.3，**非本书 Spark/MLflow 行为**）

- 方法：SQLite 建 `runs(run_id, params_json, metric, ts)` 表模拟 Tracking 账本，插入 3 次「实验」，再建 `registry(run_id, alias, promoted_ts)` 模拟模型注册；查询演示：按 metric 选最优 run、`UPDATE registry SET alias='prod'` 完成一次回滚。
- 观测：账本表让「哪次实验、什么参数、什么指标」成为**可 SQL 化追问的对象**；alias 一列即回滚开关——MLflow 的核心机制在这张两表迷你模型里全部在场（仅结构在场，UI/工件存储/flavor 均缺席）。
- 边界：本标本不含 artifact 二进制管理、不含并发写入语义，勿当作 MLflow 实现笔记；数字无计时断言，纯结构演示。

## 9.7 生命周期五站图（重构 ⚠️ 本册叙事骨架）

1. **问题定义**：指标与业务量对齐（Ch8 评估器的列名从这里来）。
2. **数据与特征**：Ch3–5 的全部纪律在此复用——schema、时点正确、分区可重放。
3. **训练与记账**：MLflow Tracking（参数/指标/工件三件套）——run 是一等公民。
4. **部署**：批量打分（Spark 原生顺手）或注册模型出服务（MLflow Models flavor）。
5. **监控与再训练**：漂移告警→触发第 3 站新一轮 run→alias 切换灰度→回滚即改别名。
- 闭环读法：第 5 站的输出是第 3 站的输入——「生命周期」不是流水线而是环，本册用一章把这个环讲完是它的结构贡献。

## 9.8 MLOps 术语的最低配置（问答式重构 ⚠️）

- Q：模型注册表和 Git 有什么区别？
  A：Git 管代码版本，注册表管**工件版本+阶段+审批**；二进制工件与运行期元数据（签名、依赖镜像）Git 管不动。
- Q：为什么不直接把模型 pickle 丢到 HDFS？
  A：丢得掉，但丢不掉「加载时环境一致」——MLflow 的 flavor/签名/依赖记录就是为堵住「本地能跑线上崩」；Spark 侧对应物是 `PipelineModel` 的目录格式，两者互补 ⚠️。
- Q：漂移检测多久跑一次？
  A：与重训练节拍绑定：日级 PSI/周级指标复核是常见基线——本册不给数值答案（正确），数值是场景函数。
- Q：入门阶段 MLflow 要学到什么深度？
  A：Tracking 记账+注册表别名两件事；Projects/分布式部署细节留给平台团队——别在第 4 周学第 4 年的课。

## 9.11 生命周期黑话小词典（语境卡 ⚠️）

- 阶段（Staging/Production/Archived）：注册表版本的生命周期标签位。
- 灰度（canary）：别名按比例切流的上线仪式。
- 再训练节拍（retraining cadence）：数据漂移触发新一轮 run 的周期设计。
- 数据契约（data contract）：上游 schema 与质量承诺的书面化——可观测栈的邻居概念。
- 模型卡（model card）：模型的用途/边界/评估的说明书文化。
- MLOps 成熟度：从「手工 notebook 抛模型」到「全链路自动化」的组织刻度，本册把你放在第一格与第二格之间。
