## 核心精讲

> 以下全部是**教学示意代码，不参与构建、不编译、不运行**。

### 术语：四类安全属性

| 术语 | 英文 | 想证明什么 |
| --- | --- | --- |
| 保密 | confidentiality | 别人看不到内容 |
| 鉴别 | authentication | 你确实在和「我以为的那个人」通信 |
| 完整性 | integrity | 内容没被改过 |
| 抗抵赖 | nonrepudiation | 事后无法否认自己发过 |

> 本书第 1 章最实用的一句话是：**「加密」不等于「安全」**。一个只做保密的方案在攻击者中间插入一个人时全线崩塌——这就是第 3 章里 Eve（被动窃听）与 Mallory（主动插入）的分野。

### 简单 XOR：简洁到危险

```c
/* 教学示意，不参与构建、不编译、不运行 */
#include <stddef.h>

void xor_crypt(const unsigned char *in, unsigned char *out, size_t n,
               const unsigned char *key, size_t klen)
{
    for (size_t i = 0; i < n; ++i)
        out[i] = in[i] ^ key[i % klen];   /* 密钥短 => 周期重复 */
}
```

三个必须记住的性质：

1. **自反**：`xor_crypt(xor_crypt(pt, ct, k))` 得到 pt——所以 XOR 加密没有「加密/解密」之分；
2. **密钥重复即泄露**：密钥周期一旦短于明文，`n % klen == 0` 的位置上密文直接相等，可以用经典统计分析（1.3 节的替换密码思路）破；
3. **没有完整性**：攻击者翻转密文某个 bit，明文对应 bit 就会翻转，接收方无从察觉。

### 一次一密：不可破，但不可用

真正的 one-time pad 要求：密钥长度 ≥ 明文长度、密钥完全随机、且**一次一换**。

```python
# 教学示意，不参与构建、不编译、不运行
import os

def otp_encrypt(plaintext: bytes, key: bytes) -> bytes:
    """只在 key 长度 == plaintext 长度、且密钥是一次性使用时才安全。"""
    assert len(key) == len(plaintext)
    return bytes(p ^ k for p, k in zip(plaintext, key))

if __name__ == "__main__":
    pt = b"attack at dawn"
    key = os.urandom(len(pt))        # 关键：绝不可复用
    ct = otp_encrypt(pt, key)
    assert otp_encrypt(ct, key) == pt
```

Shannon 在 1949 年证明：一次一密的密文与明文在**信息论上独立**，无论攻击者有多少算力都破不了。代价是：密钥分发量等于通信量，且**复用一次即彻底失效**——1970 年代的「密钥复用热交换」事故（以及第 16 章讨论的 PRNG 缺陷导致的 nonce 重用）都是这条的翻车现场。

### 大数与模运算：全书的地基

```python
# 教学示意，不参与构建、不编译、不运行
def mod_exp(base: int, exp: int, mod: int) -> int:
    """重复平方求幂：RSA、DH、ECC 全都建立在这个运算上。"""
    result = 1
    base %= mod
    while exp > 0:
        if exp & 1:
            result = (result * base) % mod
        base = (base * base) % mod
        exp >>= 1
    return result

assert mod_exp(3, 40, 7) == 2     # 3^40 mod 7
```

三个容易出错的点：

- 乘法要先取模再乘，否则中等参数下就会溢出（32 位整数里 `(a*b) % m` 的 `a*b` 就已经越界）；
- 负数取模要归一到 `[0, m)`；
- 求逆要用扩展欧几里得或 Fermat 小定理（`a^(φ(m)-1) mod m`），不能靠除法。

## 版本演进

| 阶段 | 关键差异 |
| --- | --- |
| **1883** | Kerckhoffs 在 *La Cryptographie Militaire* 里提出：**算法可以公开，密钥必须保密**——这是本书隐含的全局前提 |
| **1917–1926** | Vernam 的一次一密咒语；Shannon 后来证明它信息论不可破 |
| **1949** | Shannon《Communication Theory of Secrecy Systems》把密码学纳入**信息论**， random codebook 概念诞生 |
| **1976** | Diffie-Hellman 之后，「对称 vs 非对称」这组术语才真正有意义 |
| **1996** | 本书第 1 章的术语表沿用至今，几乎没再改过 |
| **2001 之后** | 「保密 + 完整性」被合并成 **AEAD**（如 AES-GCM、ChaCha20-Poly1305），第 1 章把它们当两件事讲的框架被工程实践压缩成一次调用 |
| **2024–2026** | 后量子 era：一次一密的**密钥分发难题**再次成为研究热点（QKD 与 ML-KEM 的争论见 13 章） |

> 值得注意：第 1 章讲的「XOR 一次一密」在现代工程里以 **AES-CTR / ChaCha20** 的形式复活——区别在于密钥由短密钥通过 **PRNG 扩展** 而来，而「nonce 绝不重复」这条仍然一字未变。

## 近年研究与工业界开源实践（2015–2026）

**趋势**：「自己实现一次一密式 XOR 加密」在真实代码里几乎绝迹，取而代之的是「调用一个把 nonce 密钥管理也封装好的 AEAD」。安全研究的重心从**算法**转向**密钥与随机性管理**——这恰好是第 16–17 章的战场。

| 仓库 | star | 说明 |
| --- | --- | --- |
| `openssl/openssl` | **30844★**（2026-09-25 实测） | `EVP_Encrypt*`、`EVP_AEAD` 的现代入口，1.4 节的自反 XOR 在这里被彻底封装掉 |
| `jedisct1/libsodium` | **13962★**（实测） | `crypto_secretbox_easy` 把 nonce 与密钥管理一起打包，正是 1.5 节「可用的一次一密」形态 |

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **「加密 = 安全」的暗示** | 1.1 节把保密单列成一项，初学者容易忽略：没有完整性的加密方案在主动攻击者（Mallory）面前等于零 |
| 🔧 **XOR 被当成现代方案** | 1.4 节的 `xor_crypt` 只是讲解替换密码用的玩具；2015 年仍有大量固件/协议用它「加密」，结果被密钥复用一击致命 |
| 🔧 **一次一密被误用为「流密码」** | 1.5 节强调密钥不可复用，但实践中 nonce 复用（同一密钥 + 同一计数器）的 CVE 至今年年都有；现代要求是 **per-message unique nonce** |
| **隐写术与密码学的边界** | 1.2 节指出二者正交；但 2000 年后的「数字水印 + 加密」组合常把密钥藏在隐蔽信道里，反而降低了可审计性 |
| **「大数运算就够快了」的误解** | 1.7 节的模幂是安全的，但**常量时间实现**（防御定时攻击，见 `concepts/密码分析与侧信道.md`）在书里完全没提 |
| 🔧 **术语表缺「后量子」** | 2026 年的术语表里必须补上 *quantum-resistant*；「RSA 会长期安全」的说法现在要加限定语 |
