# 第 7 章 密钥长度（Key Length）

> **一句话**：第 7 章是全书写得最「硬」也最过期的部分——**它用算力成本给密钥长度定价**，而 1996 年的价格表已经被摩尔定律和 GPU/ASIC 重写了两次。

## 核心精讲

> 以下全部是**教学示意代码，不参与构建、不编译、不运行**。

### 穷举攻击成本的经典估算

```python
# 教学示意，不参与构建、不编译、不运行
def brute_force_space(bits: int) -> int:
    """键空间大小。1996 年的论述里，2^bits 就是「不可行」的同义词。"""
    return 1 << bits

def work_to_break(bits: int) -> float:
    """以「每秒 1e12 次尝试」的机器为基准，需要的秒数（约数）。"""
    return (1 << (bits - 1)) / 1e12

if __name__ == "__main__":
    for b in (56, 64, 128):
        print(b, "bits ->", f"{work_to_break(b):.3e} 秒")
```

> 第 7 章真正的洞见不是「用 128 位」，而是**把算力成本写下来**：一个 1996 年的「不算贵」的数字，在 2026 年是「随便」的。作者因此专门加了 7.6 的 Caveat Emptor——这在 1996 年的技术书里非常罕见，也更显先见。

### 生日攻击：为什么哈希的有效强度是「一半」

```python
# 教学示意，不参与构建、不编译、不运行
import math

def birthday_bound(bits: int) -> int:
    """n ≈ 2^(bits/2) 次尝试即可以约 50% 概率找到碰撞。"""
    return int(2 ** (bits / 2))

print(birthday_bound(160))   # SHA-1：约 2^80
```

> 这条公式的后果在 2017 年被兑现：Google 与荷兰数学界联合公布的 SHAttered 证明了 SHA-1 的碰撞成本远低于 7.4 节表里的估价。今天所有「1024 位 RSA 够用吗」之类的讨论，第一步都该是问「它对应的哈希强度是多少」。

### 对称 vs 公钥：强度换算

| 对称强度 | 公钥（RSA/DH）等价位数 | 备注 |
| --- | --- | --- |
| 80 | 1024 | 2010 年代起被 NIST 判为不足 |
| 112 | 2048 | FIPS 140 早期档位 |
| 128 | 3072 | 今天的默认下限 |
| 192 | 7680 | 长期机密 |
| 256 | 15360 | 短期不需要，长期机密（经典计算机） |

> 🔧 这张表是**经典计算机**的换算。**量子计算机上**换算完全不同：Shor 算法把 RSA/DH 的强度按**指数级**压缩，而对称密码只按常数因子约减（Grover）。因此 2024 年 NIST 的 FIPS 203/204/205 给出的后量子强度单位是「经典 Security Strength」的重算结果，不能套用本书这张表。

## 版本演进

| 阶段 | 关键差异 |
| --- | --- |
| **1996** | 本书成书：给出一张「1996 算力下的推荐长度」表，并用 7.6 明确声明「这是估算不是保证」 |
| **1998** | **EFF Deep Crack** 在 56 小时内破 DES —— 第 12.7 节「DES 今天还安全吗」的答案被机器给出 |
| **2008** | **COPACOBANA**（GPU 集群）把破 DES 的成本降到几万美元；同期 SHA-1 碰撞成本已被大幅压低 |
| **2015** | **NIST SP 800-57** 给出新的密钥强度档位与安全寿命表；80 位对称被判为「不足以长期使用」 |
| **2019** | **密途（Post-quantum）迁移启动**；NSA 的 CNSA 2.0（2022 正式）要求 2048 位以上 RSA 或等价 lattice 方案 |
| **2024-08** | FIPS 203/204/205 明确用 ML-KEM（128/192/256）替代 RSA/DH 的三档 |
| **2025–2026** | 工业界按「**密钥迁移期 = 数据的保密期**」来订长度：数据要保密 20 年就用 ML-KEM-256 级别 |

> 一条可复用的方法论：**密钥长度不是一个数字，而是「保密期 × 对手算力增长」的函数**。本书 7.5 已经给出了这个函数，只是 1996 年的算力增长曲线被严重低估。

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **1996 年的算力估价全面失效** | 7.1 的「穷举 128 位不可能」在 2026 年依然是事实，但「穷举 64 位不现实」已经不成立了；表中所有「金钱」列的单位都该按 GPU/ASIC 折旧重新算 |
| 🔧 **把 7.3 的对称/公钥换算当成通用常数** | 该表只对经典计算机成立；加上量子后必须分开讨论（Shor vs Grover），见 FIPS 203/204/205 的强度定义 |
| 🔧 **哈希强度被当成输出长度** | 7.4 的生日攻击说明有效强度是输出长度的一半；这直接决定了 SHA-1（160 位）的「112 位强度」实际上是 80 位 |
| **「密钥越长越安全」的直觉错误** | 长度只是预算，算法本身可能有结构性弱点（DES 的 56 位只是其一，RC4 的 128 位密钥长度看似充足却完全被禁） |
| 🔧 **忽略「保密期」这个变量** | 7.5 自带了正确思路：先定数据要保密多久，再反推长度；大多数组织跳过这一步 |
| 🔧 **未覆盖后量子密钥长度** | 2024 年之后「RSA-3072 仍然安全」必须加限定语：**在经典计算机上安全**，而交换的密钥可能被今天收割、十年后破译 |
| 🔧 **书中的 DES/RC4 长度建议在今天误导人** | 7.1 中针对 RC4 的 128 位建议早已被 RFC 7465 作废——**长度再够，算法结构被破也无效** |
