# 第 19 章 公钥算法（Public-Key Algorithms）

> **一句话**：第 19 章是全书最「经典」的一章——**RSA、Rabin、ElGamal、McEliece、椭圆曲线**全部在里面；它是理解今天所有公钥体系的必经之路，也第一次把「数学难题会失效」这件事摊在读者面前。

## 核心精讲

> 以下全部是**教学示意代码，不参与构建、不编译、不运行**。

### RSA 的构造：`m^e mod n` 的要点

```python
# 教学示意，不参与构建、不编译、不运行
import secrets

def gen_prime(bits: int) -> int:
    """示意：真正的实现要用 Miller-Rabin + 小素数试除 + 安全素数条件。"""
    while True:
        p = secrets.randbits(bits) | 1
        if p % 2:                       # 示意判定，实际用 Miller-Rabin
            return p

def gen_rsa(bits: int = 2048, e: int = 65537):
    p, q = gen_prime(bits // 2), gen_prime(bits // 2)
    n = p * q
    phi = (p - 1) * (q - 1)
    while phi % e == 0:                 # 必须保证 gcd(e, phi) == 1，且 p-1、q-1 不被 e 整除
        q = gen_prime(bits // 2)
        phi = (p - 1) * (q - 1)
    d = pow(e, -1, phi)                 # 私钥指数
    return n, e, d

def rsa_encrypt(n: int, e: int, m: int) -> int:
    assert 0 <= m < n
    return pow(m, e, n)                 # 与模幂：与 getrandom 的隔离无关

def rsa_decrypt(n: int, d: int, c: int) -> int:
    return pow(c, d, n)
```

> 三个必须记住的要点：
> 1. **`d` 依赖 `p`、`q` 的具体值**，所以轮换 p 就必须轮换整个公私钥对；
> 2. **`e` 必须与 `phi` 互质**，且**p-1 与 q-1 都不能被 e 整除**——否则 m^(e·d) 不是恒等映射，解密会偶发失败；
> 3. 加密前必须做**填充**（PKCS#1 v1.5 / OAEP）。1996 年之后最著名的 RSA 攻击（Bleichenbacher 的百万消息攻击）正是因为**没有正确填充 + 错误提示泄露**。

### 椭圆曲线的群运算要点（19.8）

```
y² ≡ x³ + ax + b (mod p)，且 4a³ + 27b² ≢ 0 (mod p)
点加法（P ≠ Q）：  λ = (yQ - yP) / (xQ - xP) mod p
点加自己（P = Q）：λ = (3xP² + a) / (2yP) mod p
单位元与逆元：O，以及 (xP, -yP)
```

```python
# 教学示意，不参与构建、不编译、不运行
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x: int, y: int):
        self.x, self.y = x, y

def add(P: Point, Q: Point, a: int, p: int) -> Point:
    if P.x == Q.x:                       # 同 x 时可能是「逆元」或「二倍点」
        return double(P, a, p)
    lam = (Q.y - P.y) * pow(Q.x - P.x, -1, p) % p
    x = (lam * lam - P.x - Q.x) % p
    y = (lam * (P.x - x) - P.y) % p
    return Point(x, y)

def double(P: Point, a: int, p: int) -> Point:
    lam = (3 * P.x * P.x + a) * pow(2 * P.y, -1, p) % p
    x = (lam * lam - 2 * P.x) % p
    y = (lam * (P.x - x) - P.y) % p
    return Point(x, y)
```

> 19.8 在 1996 年只有一小节，因为当时的争论是「ECC 太慢/太贵/太难调试」。今天的事实是：**secp256k1 与 Curve25519 在同等安全强度下省掉一个数量级的算力与带宽**，这也是比特币与 TLS 1.3 双双选择它的原因。唯一的坑在 19.8 没写：**曲线参数与子群阶必须验证**，否则会掉进 Pohlig-Hellman 的小因子子群里。

### 三类「密钥越长越安全」的反例

| 算法 | 1996 年的推荐长度 | 2026 年的现实 |
| --- | --- | --- |
| RSA | 512–1024 位 | 3072 位起步（2048 只用于短期） |
| 椭圆曲线 | 「160 位就够」（当时怀疑） | 256 位（secp256k1 / prime256v1） |
| 后量子（书里没有） | — | ML-KEM-512/768/1024，或 ML-DSA-44/65/87 |

> 「密钥越长越安全」这个误解在 19.3 的实证是：**RSA 的安全强度与模数长度是超线性关系**（因子分解用 NFS，复杂度约 exp(1.9·(L/1000)^0.3)），所以「+1 位没多大用」；而「密钥越长越慢」是线性的——**收益递减正是这条误解的数学根源**。

## 版本演进

| 年份 | 事件 |
| --- | --- |
| **1976** | Diffie-Hellman：公钥密码的起点 |
| **1978** | **RSA**（CACM）；同年 **McEliece** 用编码做公钥 |
| **1979/1982** | **Rabin** 的平方函数；**Merkle-Hellman 背包** |
| **1985** | **ElGamal**（离散对数加密）；**Koblitz / Miller 独立提出椭圆曲线密码** |
| **1996** | 本书成书：19.8 只有一小节，ECC 尚未被工业界接受 |
| **1999** | **Boneh-Durfee 的小私钥指数攻击**；**WAP/WTLS 的 ECC 实现事故** |
| **2003** | **Curve25519** 的设计讨论（Bernstein）；「ECC  patent 争论」尘埃落定后开始普及 |
| **2005** | **NIST 发布 P-256 等曲线**；ECC 进入 FIPS 186-3 |
| **2008** | **DNSCurve**；**公钥密码被大规模部署**（HTTPS 普及的转折点） |
| **2009** | **Shor 算法对 RSA 的现实威胁**被量化讨论；PQC 竞赛的思想萌芽 |
| **2013** | **RFC 6655**（ECDH 的曲线要求）；**NSA 的「后门」争议与「Doublespend」文件曝光** |
| **2015** | **CNSA 1.0**：NSA 转向椭圆曲线；同年 **RFC 7748（X25519/X448）** |
| **2016** | **Logjam**（CVE-2015-4000）：弱 DH 参数与「降级到 512 位 DH」 |
| **2018** | **TLS 1.3** 默认 X25519 + ECDSA/Ed25519 |
| **2022** | **CNSA 2.0**：RSA 与 ECC 退出 NSA 套件（但对称仍是 AES） |
| **2024-08-13** | **FIPS 203（ML-KEM）/ 204（ML-DSA）/ 205（SLH-DSA）** 正式发布 |
| **2025–2026** | 混合密钥交换（X25519 + ML-KEM）在主流浏览器中成为默认；**「爱丽丝与鲍勃」的时代进入后量子双栈** |

> **这一章最重要的订正**：第 19 章的全部安全性论证都建立在「**因子分解与离散对数在经典计算机上不可解**」之上。1996 年的作者无法知道这句话在 30 年后还能否作为长期前提。2024 年的 FIPS 203/204/205 不是「又一组算法」，而是**把整章的前提抽掉后的重建**。

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **「RSA 永远不会被破」的前提需要限定语** | 2024 年 FIPS 203/204/205 之后，正确表述是「**在经典计算机上**」。今天被保护的通信完全可能被「先收割、后解密」——这是本书完全没考虑的场景 |
| 🔧 **未提「密钥越长越安全」的反例与收益递减** | 19.3 只给出推荐长度，没有解释为什么 1024 → 2048 的价值远超 2048 → 2049；这是工程上最常被误解的一点 |
| 🔧 **未提填充与 Bleichenbacher 攻击** | 19.3 讲加解密公式，不讲 PKCS#1 OAEP；1998 年的百万消息攻击与 2012 年的相关失误都源于填充缺失 |
| 🔧 **19.8 对 ECC 的评价过低** | 书里把 ECC 当作「学术上好看、工程上有风险」；今天它是带宽与算力双优的默认选择 |
| **「公钥可以随意公开」** | 19.5/19.6 默认「公钥可信」；公钥的**来源与新鲜度**是另一个问题（见 07 章 8.4 与 16 章 PGP 信任网） |
| 🔧 **未覆盖后量子公钥密码** | 2024 年之后任何新系统都应考虑「混合模式」：同时做 X25519 与 ML-KEM，让两者中较弱的那个不会成为致命点 |
| **「ECC 数学难所以不安全」** | 事实上 ECC 的失败几乎全部来自**参数与实现**（如 Pohlig-Hellman 小子群、不验点的合法性），而不是曲线本身 |
| 🔧 **19.2（背包）被当作历史知识即可** | 但它的**格归约攻破方法**今天正是后量子密码（格密码）的主流工具——「1978 年的失败方案，2010 年的正确方向」，这是密码学里最反直觉的转折之一 |
