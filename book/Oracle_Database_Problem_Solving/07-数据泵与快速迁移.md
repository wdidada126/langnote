# 第 13–14 章：使用数据泵迁移数据和对象 · 数据库快速迁移数据的策略

> ⚠️ 文档转述（章题取自中译本逐字目录 ✅，章内小节自拟 ⚠️；Oracle 行为为 11gR2–12cR1 口径转述，无 Oracle 实测）。类比实验见 [04 号文件 🔧G6](04-RMAN备份恢复最佳实践.md)（在线备份/页步进，非 Oracle）。

## 本文件定位

第 13 章是"逻辑层搬家"（expdp/impdp 导出口径的对象与数据），第 14 章是"物理层搬家+最小停机"（传输表空间、增量前滚、逻辑复制）。排错视角下两章的共同主题：**搬家事故多半在停机窗口前就已注定**——依赖清单、字符集、空间配额决定成败。

## 第 13 章 使用数据泵迁移数据和对象

### 13.1 作业模型（⚠️ 转述）

- expdp/impdp 是服务器端作业：`DIRECTORY` 对象（目录授权是第一道权限坑）、PARFILE 复用的作业参数、`ATTACH` 重连监控是区别于老 exp/imp 的三根支柱。
- 过滤四件套：FULL/SCHEMA/TABLE + INCLUDE/EXCLUDE 谓词（按对象类型精确抓取）；`CONTENT=METADATA_ONLY` 拆"结构搬家"与"数据搬家"两步。
- 并行：`WORKERS=n` 按对象切分（大表无法被多 worker 拆分是常见误解——要拆得靠分区或显式多作业）；老式导出 `EXCLUDE=STATISTICS` 后补统计是计划漂移事故的预防线。

### 13.2 事故高发点（⚠️ 转述，社区口径）

| 事故 | 症状 | 处置 |
|---|---|---|
| 字符集不匹配 | 导入后 ???? 乱码或 ORA-31655 类告警 | 目标库字符集为源超集；或 CONVERT 参数显式转 |
| 版本降级导入 | ORA-39143/31617 类版本闸 | 用源版本 dump+目标兼容参数，或走第 14 章物理搬家 |
| 密码过期/账户锁定 | "用户名/口令无效"但口令没错 | 11g 延迟秒策略+改 SEC_DEFAULT 配置（老社区经典坑） |
| 空间配额 | ORA-01950 段建不出 | TABLESPACE 配额预检+`REMAP_TABLESPACE` |
| 依赖缺失 | 导入后对象 INVALID 成串 | `SQLFILE` 预演脚本+先结构后数据两遍法 |

### 13.3 网络导出入（⚠️ 转述）

`NETWORK_LINK` 直迁不落 dump：省存储省时间，但源目双方版本/字符集必须当场兼容，且长事务经 DBLink 的 UNDO 面吃紧（回看第 2 章）。大库慎用，中小库与"逐 schema 搬家"首选。

## 第 14 章 数据库快速迁移数据的策略

### 14.1 搬家技术全景（⚠️ 转述，按停机时长排序）

1. **传输表空间（TTS）**：物理文件+元数据导出，跨平台需 ENDIAN 对齐（大端 AIX/HP-UX → 小端 Linux 用 RMAN CONVERT），停机=转换+挂载时间。
2. **增量可传输 TTS（12c）**：源库持续 L1 增量（`dbms_file_transfer` 复制+前滚），把"大搬家"折成"最后一次小增量"——12c 时代异构搬家（本地→云/改 OS）的主打法。
3. **RMAN DUPLICATE/STANDBY 切换**：逻辑等价"全库在线搬家"，停机压到角色切换分钟级（Data Guard failover 语义）。
4. **GoldenGate/逻辑复制**：表级细粒度、异构可裁剪、可双向；代价是序列/大对象/DDL 同步的运维复杂度，属"搬家+长期共存"双用途。

### 14.2 决策树（⚠️ 转述）

- 数据量 TB+且停机窗口小时级 → 增量 TTS 或备库路线。
- 停机分钟级 → DG 切换；分钟也不给 → GG 类逻辑复制+应用双写灰度。
- 只要对象结构/小数据 → 数据泵两遍法，别开物理搬家这个重炮。
- 验证铁律（与第 8 章同源）：任何搬家完成后立即目标端统计收集+TOP SQL 回归比对（第 12 章 STA 工具复用）。
- 混合路线合法：结构走数据泵、大表走 TTS/增量前滚、日志类走逻辑复制——按对象重要性分层，不按工具信仰分层。
- 搬家必带"回迁预案"：目标端失败回源的成本与窗口在方案评审时就要量化，否则只是单程票。

## 13.4 PARFILE 骨架（⚠️ 按通用参数拼装，示意件、非原书清单）

```text
DIRECTORY=DP_DIR              # 服务端路径授权层（第一道权限坑）
SCHEMAS=FIN                   # 三级过滤其一：FULL/SCHEMA/TABLE
EXCLUDE=STATISTICS            # 统计交后置任务（防搬家期计划漂移）
PARALLEL=4                    # 对象级并发；大表提速靠显式分区拆作业
REMAP_TABLESPACE=OLD_TBS:NEW_TBS
DUMPFILE=exp_%U.dmp           # %U 是多 worker 落盘的前提
LOGFILE=imp_%U.log            # 每 worker 独立日志，事故定位入口
```

- 两遍法：先 `CONTENT=METADATA_ONLY` 搬结构并审 INVALID 清单，再 `CONTENT=DATA_PUMP` 搬数据——13.2 依赖缺失事故的工程化解法。

## 14.3 案例演练：大小端异构搬家、停机压到半小时（⚠️ 按章主题结构化）

1. 闸口选型：AIX（大端）→ Linux（小端），TTS 必须 CONVERT；先测"源端转（费源 CPU）vs 目标端转（费目标 IO）"哪个窗口成本更低。
2. 主循环：源库 L0 → `dbms_file_transfer` COPY+CONVERT 到目标 → RECOVER 前滚；此后每轮只送累积 L1。
3. 收敛判据：当"最后一轮增量大小/回放速率 < 停机预算"才进入切换——预算驱动循环次数，不是次数驱动。
4. 切换：源库 READ ONLY → 末轮增量 → 目标挂载表空间+数据文件头切换 → 临时对象（序列/DBLink/口令文件）单独搬家。
5. 验证：目标端统计收集 + TOP SQL 的 STA 回归比对（第 12 章工具复用）；任何回归走 SPM 回钉。
6. 回退线：源库在窗口内保持 READ ONLY 不释放，全闸口失败则解除只读回老路——回退成本为零才是可批准的方案。

## 核心概念速览（中英对照）

- **数据泵** — Data Pump（expdp/impdp）：服务器端并行导入导出作业框架 ⚠️
- **目录对象** — DIRECTORY Object：服务端文件路径的授权抽象 ⚠️
- **附加作业** — ATTACH：重连正在运行的搬家作业 ⚠️
- **仅元数据** — METADATA_ONLY：结构先行两遍法 ⚠️
- **网络直迁** — NETWORK_LINK：不落 dump 的跨库直搬 ⚠️
- **传输表空间** — TTS：物理文件+元数据挂载式搬家 ⚠️
- **字节序转换** — RMAN CONVERT：跨 ENDIAN 平台块改写 ⚠️
- **增量 TTS** — Incremental Transportable：持续 L1 前滚收敛搬家 ⚠️
- **备库切换** — DG Switchover/Failover：分钟级全库搬家 ⚠️
- **逻辑复制** — GoldenGate 类：表级异构复制，搬家+共存双用途 ⚠️
- **字符集闸口** — Charset Superset Rule：乱码事故的第一预防 ⚠️
- **回归比对** — STA 前后对比：搬家后的计划审计 ⚠️

## 最新演进与工业实践

- **搬家主航道迁移**：12c 时代增量 TTS 的位置，在 2020s 被"云搬家"接棒——Oracle Zero Downtime Migration（ZDM）CLI 与 OCI Database Migration 服务把 DG/增量 TTS/GG 路线产品化；EBS/第三方库进 Oracle 的搬家则以 GoldenGate 微服务（OGG for Big Data）为常见件 ⚠️ 转述（oracle.com 迁移工具文档 ✅ 域名可达，内容未直读）。
- **数据泵仍在岗**：23ai/19c 文档仍把 Data Pump 列为逻辑迁移正解，新增加密 dump（`ENCRYPTION_PWD_PROMPT`）补上老 dump 明文安全洞；社区对"expdp 大版本降级"的容忍度依旧低 ⚠️。
- **跨引擎镜像**：pg_dump/物理复制（PG）、mydumper+复制（MySQL）、SQLite 🔧G6 三件套，与本章"逻辑/物理/复制"三路完全同构——搬家技术是数据库世界的通用词汇表，只差引擎特定的闸口（字符集/字节序/版本）。
