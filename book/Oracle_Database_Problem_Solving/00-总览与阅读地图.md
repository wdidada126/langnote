## 三、本书体裁与排错方法论特征（用于全系列分工）

- **问题驱动（problem-per-chapter）**：每章=一类故障/瓶颈专题，体例为「症状 → 诊断视图/工具 → 根因 → 处置与预防」，与 Antognini《Troubleshooting Oracle Performance》的**方法驱动**（按可复现性分流）构成互补两极。
- **覆盖面是"DBA 全科"**：存储对象（LOB/UNDO）、等待事件（gc buffer busy/latch）、优化器行为（ACS/SPM）、备份恢复（RMAN）、监控（AWR）、集群（RAC）、迁移（数据泵/传输表空间）、硬件（SSD）、工具（SQL 顾问/SQLT）、分布式事务（XA）——一册打尽运维排错长尾。
- 与 repo 排错体兄弟的对照：**#66（本册）= Oracle 症状百科**；**#68（SQL Server Advanced Troubleshooting，在波兄弟）= 等待统计+DMV 单引擎深钻**；**MySQL排错指南.md（盘上单文件）= O'Reilly 排错指南体的 MySQL 版**。三者并读可得"排错三形态"：症状百科 / 方法论流水线 / 平台手册。

## 三之二、本书用法边界（读什么 / 别指望什么）

- **读什么**：20 类症状的"第一动作"与取证视图清单；每章内嵌的版本特定坑（如 11g 密码延迟、ACS 前提、TTS 字节序）。
- **别指望**：统一的排错流程（本书按症状分章，流程去 Antognini 册）；许可合规意见（AWR/Tuning Pack 边界只可当风险提示）；对 19c/23ai 新特性覆盖（原书停在 12cR1 语境）。
- **读法模板**：值班场景=第 9 章等待类路由 → 对应症状章 → 处置后回第 10 章做时间轴验证；项目场景=第 12 章 STA → 第 5 章 SPM → 第 6 章 DDL 工具三件套。
