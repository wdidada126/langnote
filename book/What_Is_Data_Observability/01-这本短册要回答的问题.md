## 1.1 先认清体裁：「What Is …?」短册是什么（⚠️ 系列体例归纳）

O'Reilly 的「What Is X?」系短册（short-form report）是数据出版里的一个特殊物种：

| 体裁件 | 规格 | 对读者的含义 |
|---|---|---|
| 体量 | 数十页，8–10 短章 | 一两个下午读完；不承诺完整性 |
| 功能 | 给一个热词下定义、划边界、给选型直觉 | 「概念卡」——谈话与文档的引用起点 |
| 作者姿态 | 实践者随笔，多引自家框架 | 框架即立场：读概念卡要顺带读出品方利益 |
| 半衰期 | 品类词收敛前高，收敛后急跌 | 短册常被自家长册取代（本册 ↔ #226 正是此曲线，见 07 章） |

- 一句话定位（⚠️ 编者）：**短册卖的是词汇表和三道判断题的答题模板**；母体书（#226）卖的才是解题过程。
- 本目录对这份短册的重构策略：既然原书页不可达，就把「短册四问」（是什么/不是什么/为谁服务/怎么选）当作骨架，用**可核锚点**（Moses 论文 DOI ✅、厂商公开文档 ✅、同题二手综述实抓 ✅）填肉——每个论断标明它站在哪一级证据上。

## 1.2 定义：可核的那一句与扩展的那几句

- **可核锚（✅）**：Ben Moses（Monte Carlo 联合创始人）在 WSDM '22 Companion 的短文 *The Rise of Data Observability*（DOI `10.1145/3488560.3510007`，Crossref 200 实测，承 #226 取证）把数据可观测性概括为：让数据用户能够**自行发现、诊断、解决**数据问题的新兴方向。三步动词「发现-诊断-解决」是该品类最小共识定义。
- **控制论前史（⚠️ 常识转述，同 #226 口径）**：observability 原义（Kalman 意义）是「由系统外部输出推断内部状态」的**结构性质**——不是工具清单。数据域借用该词时保留了这个内核：好数据不是「测出来的」，是「能从输出推断出来的」。
- **数据域限定（⚠️ 品类通识）**：主语是**数据资产**（表、列、管道、指标）而非服务进程；观测对象的健康判据是数据的时效/模式/分布/血缘，而非 CPU/延迟/错误率。这一限定是它和 APM、和 DBRE 的分工线（边界详见 [03-它不是什么四组边界.md](03-它不是什么四组边界.md)，软件侧对照 [../Database_Reliability_Engineering/00-总览与阅读地图.md](../Database_Reliability_Engineering/00-总览与阅读地图.md)）。
- 与母体书的定义差（⚠️ 归纳）：#226 把定义展开成五支柱 + 组织角色（其 00 七之二表，✅ 在盘可查：Freshness/Monitoring/Lineage/Documentation/Alerting）；短册体定义大概率止步于「维度清单 + 一句动机」——两册定义不同层，引用时别混标（本目录凡「五支柱」字面一律指 #226 口径）。

## 1.3 动机：数据停机（data downtime）与「作业成功 ≠ 数据正确」

概念卡类文本的标准开场是三个痛点（⚠️ 按同题可核二手件重构；CSDN neweastsun 同题综述实抓件 ✅ 200，其表述与品类通识一致）：

1. **ETL 绿了，报表错了。** 调度系统报告成功只说明「代码没抛异常」，不承诺数据面的完整、新鲜与一致——这是全品类的第一公理（#226 T2 论断同句：「作业成功 ≠ 数据正确」，✅ 母体在盘）。
2. **故障以「下游投诉」的方式被发现。** 分析师在周会上指出数字不对，比任何监控告警都先到——发现时延（TTD）以天计。
3. **复杂度让手动对账破产。** 云仓 + 湖 + 反向 ETL + 第三方 SaaS 导出，一张看板背后可能挂着几十个不受控上游（架构侧放大效应见 [../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md) 的分布式产品合同讨论）。

- **数据停机**：数据不可信、不可用的时段总和——品类用 DDT = N ×（TTD + TTR）给它定价（事件数 ×（检测时长 + 修复时长））。⚠️ 该公式出自厂商系论述的转述链（neweastsun 综述件含此式；Monte Carlo 旧域名文章 ✅ 实存但已 301 迁移至 montecarlo.ai，平台口径一律 ⚠️）；本册不引用其「行业平均 4h/9h」数字作事实，只在 04 章当**账本结构**使用。
- 🔧 预告：04 章用 DuckDB 把「滞后台账 → SLA 达成率」真实算出来（E3 组，270 次检查、91.11% 达成），把这里的修辞变成算术。

## 1.5 一分钟自检：你的组织在哪个象限（⚠️ 编辑件）

概念卡常见的隐性模型是「检测能力 × 响应能力」两轴四象限（本目录归纳，非原书图表）：

| | 响应有主 | 响应无主 |
|---|---|---|
| **检测在先** | 成熟：观测即常识 | 空转：告警无人认领（E5 组「有边无主」的组织学版，06 章实跑） |
| **检测在后** | 英雄救火：靠个别分析师肉眼 | 麻木：错误数据直接进决策 |

- 判别问题只有一句：**上一次坏数据是「谁」在「什么时刻」发现的——系统还是人？**（⚠️ 编者句，向 #226 T3「观测的产出是组织合同」靠拢）。
- 四象限中只有左上角具备谈「可观测性 ROI」的资格；其余象限的正确采购是登记纪律而不是平台（05 章末节会回到这句）。

## 1.5-bis 名词四代目：这个词是怎么被叫开的（⚠️ 谱系转述件）

概念卡类文本往往自带一段「词源」，此处以可核件重构之（细节均 ⚠️，唯 DOI 行 ✅）：

| 代际 | 时间窗 | 叙事主角 | 词汇状态 |
|---|---|---|---|
| 第一代·控制论 | 1960s | Kalman（系统论） | observability=结构性质，与数据无关 |
| 第二代·DevOps/SRE | 2010s | 站点可靠性工程谱系 | 三支柱 metrics/logs/traces，面向进程（对照件在盘：[../Database_Reliability_Engineering/00-总览与阅读地图.md](../Database_Reliability_Engineering/00-总览与阅读地图.md) ✅） |
| 第三代·数据域 | 2020–2022 起 | 观测平台创业群 + Moses 短文（✅ DOI 10.1145/3488560.3510007） | 「数据可观测性」成品类词，五维/五支柱枚举并行扩散 |
| 第四代·平台词条（本目录观测到） | 2023–2026 | 分析厂商百科页与云平台内建功能 | 词义下沉为货架标签，独立文本被百科取代（07 章展开） |

- 判别句（⚠️）：同一本短册里若同时出现「支柱/维度/检查项」三种量词，说明写作发生在第三代中途的口径混用期——这正是 02 章对照表要处理的现场。

## 1.5-ter 一句话速读板（给赶时间的概念卡读者）

1. 数据可观测性=让坏数据**在抵达决策之前**被系统而非人发现的能力（发现-诊断-解决三动词，✅ 锚）。
2. 它的对头不是坏数据，是**静默**：作业绿、表迟到、口径变了、没人知道（1.3）。
3. 它的最小检验：随机挑一张下游报表，问「错了多久你会知道」，答案带单位带数字才算数（1.5）。
4. 短册给你这三句话，母体书给你三十七页（#226），工程册给你三百个工单（#224，同波在飞登记）。

## 核心概念速览（中英对照）

- **数据可观测性** — Data Observability：从数据资产输出推断其内部健康状态的组织与工程能力（发现-诊断-解决三动词，✅ 锚点）。
- **概念卡/短册** — Short-form Report/Primer：数十页体裁，卖词汇与判断题模板，不卖解题过程。
- **数据停机** — Data Downtime：数据不可信/不可用时段，DDT = N×(TTD+TTR)（⚠️ 厂商口径）。
- **检测时延** — Time to Detect (TTD)：故障发生到被发现的时长；观测品类的第一 KPI。
- **修复时延** — Time to Resolve (TTR)：发现到恢复可信的时长；主战场在清洗/质量侧（实链 ../数据清洗.md）。
- **作业成功 ≠ 数据正确** — Green Pipeline, Bad Data：控制平面信号与数据平面信号不重合（#226 T2 同句，✅ 母体在盘）。
- **三把梳子** — Three Combs：#223 谈资 / #226 框架 / #224 工单的齿距差比喻（⚠️ 本目录语）。
- **档⓪书目** — Tier-Zero Bibliography：存在性可证、内容面全线不可达的本环境取证分级（00 §2）。
