## 5.3 🔧 E2 实跑：体量维度的最小检测器——周环比 + MAD 修正 z（DuckDB 1.5.5，非本书引擎行为）

Q2 信号面的现场教学：不用任何平台，30 行 SQL 做出能吃掉「重复回灌/部分断流」两类经典故障的检测器。基线与 #226 G4 **刻意错位**：G4 用 14 天滚动窗朴素 z-score（对季节性行数列会周末连报）；E2 用 **同一星期几环比（lag 7）+ MAD 鲁棒修正 z**（median absolute deviation，判据 |Mz|>3.5）——均值方差被异常点自己污染的问题从构造上免疫（⚠️ 方法论常识，实跑验证）。

```sql
WITH w AS (SELECT day, n, lag(n,7) OVER (ORDER BY day) AS n7 FROM rowcnt WHERE day > 7),
r AS (SELECT day, (n*1.0/n7 - 1) AS chg FROM w),
m   AS (SELECT median(chg) AS med FROM r),
mad AS (SELECT median(abs(chg - med)) AS mad FROM r, m)
SELECT day, round(chg*100,1) AS wow_pct,
       round(abs(0.6745*(chg-med)/mad),1) AS mz
FROM r, m, mad WHERE abs(0.6745*(chg-med)/mad) > 3.5 ORDER BY day;
```

**实跑结果**（120 天序列、113 个可用环比点；注入：d45 回灌 +42%、d78 断流 −47%、d103 拆表重写 +58%）：

| 命中日 | 类型 | 读法（⚠️ 判读） |
|---|---|---|
| **45 / 78 / 103** | 3 个注入点全中 | 环比幅度 +76.1%/−48.9% 区间内、\|Mz\|>3.5 |
| 52 / 85 / 110 | **T+7 回声**（各注入点的次周同日） | 环比基准被事件污染 → 一周后自动「反向报警」——非误报，是环比法的结构性影子 |

- 回声现象是本章给读者的真数字彩蛋：**任何 lag-k 环比检测器都自带 k 日影子双报**——平台「告警去重/关联」功能（⚠️ 厂商口径）在这组数字面前有了可测试的定义：把 T+7 孪生对识别为同一事件（本例 6 报 → 归并为 3 事件，归并率 50%）。
- 与 E4 拼起来就是 Q2 的最小答案：freshness 用分位基线（E4 式）+ 体量用环比 MAD（E2 式）+ 分布用 PSI（E1 式）——三件套全在单机可跑，**这就是概念卡落地与平台采购之间的分水岭数字**（⚠️ 编者）。

## 5.4 自建最小栈：五张表起（⚠️ 口径承 #226 04 五表模型，本册给选型用途版）

| 表 | 内容 | 喂给 | 本册实验对应 |
|---|---|---|---|
| assets | 资产清单+等级+SLA | E3 台账的分组键 | fresh 表 sla_h 列 |
| snaps | 快照/滞后流水 | E4 基线、达成率 | snaps 表 |
| cols/rowcnt | 结构与体量流水 | E1/E2 检测器输入 | amt/rowcnt 表 |
| lineage | 边登记表 (src,dst,job) | 影响分析 + E5 审计 | edges_tbl |
| owners | 负责人与升级链 | 告警路由 | nodes.owner（NULL 即死角） |

- 路线句（⚠️ 编者）：先用 5.3 三件套 + 五张表跑一个季度拿到**自己的**检出率/误报率/覆盖率基线，再拿这三张成绩单去和平台 POC 对赌——没有基线就采购，验收时你没有任何议价数字（#226 06「选型方法最小动作集」同向，✅ 母体在盘互证）。
- 平台补的是什么（⚠️ 结构归纳）：不是算法（E1/E2/E4 已证单机可造），是**规模与纪律**——千表级采样调度、血缘自动采集（解析式/事件式，#226 05 §5.4-bis 三采集法表 ✅ 在盘）、值班路由与协作流。买「算法先进」是营销，买「规模纪律」是采购（⚠️ 尖锐句，本目录观点）。

## 5.5 否决清单：四种不该上的情形（⚠️ 编者判断句）

1. 关键表 ≤10 张且有主——写断言 + 值班表即可（4.6 反信号）。
2. 血缘与负责人登记簿不存在——路由面（Q3）为空的观测系统=自动制造孤儿告警（E5 的 6/22 预演）。
3. SLA 从未校准——先回 4.4 的 dwd.events 教训（78.89% 不是监控不足是合同错）。
4. 把观测平台当数据修复工具——越界条款见 3.1 末句，边界纪律高于功能清单。

### 5.7-bis 十字考题的三档判分（使用细则）

- 及格线：10 题答出 7 题且有演示留痕——低于此即「PPT 平台」，约演示者重做 POC。
- 加分项：主动给出检测项的**最小样本量与误报估计**（题 6 的诚实版答法）——市场罕见，采购稀缺即议价点。
- 一票否决：拒绝题 8 的分母口径（只按边数报覆盖率）——登记簿可信度是路由面的地基，地基口径都糊的平台不进短名单（⚠️ 编者强判）。
- 判分留痕：每答一题记录演示日期与版本号，半年后重测题 1/5/6 三题即可复用作年度巡检（十字考题的第二生命是合同年检件，⚠️ 编者）。

## 核心概念速览（中英对照）

- **选型四问** — Four Buying Questions：对象面/信号面/路由面/成本面，短册末问的不老骨架（⚠️）。
- **修正 z 分数** — Modified z (MAD-based)：0.6745×(x−median)/MAD，对离群点鲁棒的异常判据（E2，阈值 3.5）。
- **周环比检测** — Week-over-Week Change：lag-7 对比吸收星期效应的体量检测法（E2 载体）。
- **T+7 回声** — Echo Alarm：环比基准被事件污染造成的次周同日孪生告警（E2 实测 3 组，归并率 50%）。
- **告警归并** — Alert Correlation：把孪生/连锁告警识别为单事件的平台功能定义（⚠️ 厂商面，本册给出可测版）。
- **五表最小栈** — Five-Table Core：assets/snaps/cols·rowcnt/lineage/owners 自建骨架（承 #226 五表模型）。
- **对赌验收** — Baseline-Bargained POC：以自跑基线为议价底的 POC 方法（⚠️ 编者）。
- **规模与纪律** — Scale & Discipline：平台相对单机脚本的真实增量（⚠️ 本章核心论断）。

## 最新演进与工业实践

- **迁站测尸样本（✅ 实测）**：montecarlodata.com→montecarlo.ai 301；微软 CAF 观测章 URL 亦改版跳转（learn.microsoft.com 两条 301 实测，00 §2）——2023 年概念卡里的功能矩阵两年内一半 URL 失效，「带访问日期引用厂商件」从礼貌升级为生存必需（⚠️ 引申）。
- **OpenLineage 与采集层标准化**：血缘事件开放标准降低自建栈第 4 层门槛（⚠️ 承 #226 演进节口径，其 06 已登记六路取证困难，本册不重复展开）；盘上方法纵深 [../数据血缘分析原理与实践.md](../数据血缘分析原理与实践.md) ✅。
- **LLM 双面（2024→2026）**：自然语言查台账（信号→叙事）与「检测器即工具调用」成为平台演示主轴；同时 LLM 应用自身产生观测需求（评测集新鲜度）——与 #226 06 演进条同源，本册只钉概念卡视角一句：**Q2 信号面的可解释性权重因 LLM 包装而上升**——说不清为什么报警的检测器在 agent 工作流里无法升级成自动处置（⚠️ 编者判断）。
- **自建 vs 采购的成本翻转点**：表数 × 检测频率 × 列宽决定单机脚本上限；E1–E5 五组合计不足 200 行 SQL、秒级跑完——这个量级的「够用」比多数人以为的来得远（⚠️ 编者，非普适承诺）。
