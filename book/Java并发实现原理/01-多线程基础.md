## 二、核心精讲

### 2.1 线程优雅关闭（协作式）
- `Thread.stop()`/`destroy()` **废弃**：强制停会留下对象不一致状态（锁释放但字段没写完）→ 数据损坏。
- 正确：用 **`volatile boolean stop` 标志位**，任务在合适点检查并退出；或 `interrupt()`。
- 守护线程：`setDaemon(true)` 的线程在 JVM 退出时不阻止退出，但**不适合做必须完成的清理工作**。

### 2.2 `interrupt`：轻量 vs 重量级阻塞
- **轻量级阻塞**：`Thread.sleep`/`join`/`wait`/`interruptible` 锁 → `interrupt` 抛 `InterruptedException` 并清标志。
- **重量级阻塞**：同步 I/O（`Socket`）、`synchronized` 阻塞 → **不响应** `interrupt`（需关资源/换 `lockInterruptibly`）。
- `t.isInterrupted()`（不清标志）vs `Thread.interrupted()`（静态、清标志）——后者易误用，见《艺术》4 章。

### 2.3 `synchronized` 的本质
- **锁的对象**：任意 Java 对象（对象头 Mark Word 存锁状态）；同步方法锁 `this`（静态方法锁 `Class`）。
- **锁的本质**：互斥访问 + 可见性保证（进入清本地缓存、退出刷主存）。
- 实现：字节码 `monitorenter/exit` → JVM `ObjectMonitor` → OS mutex（见《艺术》2 章三层实现；🔧 偏向锁 JDK 15+ 已移除）。

### 2.4 `wait/notify` 的"为什么"
- 必须配 `synchronized`：等待/通知依赖监视器，且 `wait` 释放锁让别的线程能进临界区改条件。
- `wait()` 必须释放锁：否则条件永远没人能改 → 死等。
- 问题：唤醒是"广播式"，需 `while` 重判条件谓词（过早唤醒 + 被抢）。

### 2.5 `volatile` 与 half-write
- **64 位 half-write**：JLS 允许非 volatile 的 `long`/`double` 读写拆成两步 → 可能读到"高 32 位新、低 32 位旧"的撕裂值；加 `volatile` 保证原子。
- **可见性**：写 volatile 刷主存 + 令他核缓存行失效；读从主存取。
- **DCL**：`volatile` 阻断"构造重排到引用赋值前" → 防止半构造对象（见《艺术》3 章 / 《实战》16 章）。

### 2.6 JMM / happen-before / 内存屏障
- 可见性根源：CPU 缓存 + 写缓冲 + 重排序（编译器/处理器/内存系统）。
- `as-if-serial`：单线程重排不改结果；`happen-before`：多线程的可见性偏序（八规则）。
- **JSR-133 增强**：把 `volatile` 升级为 acquire/release 语义、`final` 补安全发布。
- **内存屏障**：`volatile` 写插 `StoreStore`+`StoreLoad`、读插 `LoadLoad`+`LoadStore`（x86 仅 `StoreLoad` 实打实存在，其余被硬件禁止）。
- `C++ volatile` ≠ Java `volatile`：前者只禁编译器重排，不管线程可见性（经典坑）。

### 2.7 手写无锁队列（本章精华，递进三例）
1. **一写一读**：用内存屏障保证写者写顺序对读者可见（无 CAS，最简单）。
2. **一写多读**：用 `volatile` 让多个读者看到最新写（单写者无需 CAS）。
3. **多写多读**：用 **CAS** 抢尾指针 → Michael-Scott 队列雏形（详见《之美》`concepts/Michael-Scott无锁队列.md`）。
4. 延伸：无锁栈（Treiber）、无锁链表（Harris/Michael 的 CAS 标记删除）。

## 三、版本演进

- **JDK 5 (JSR 133)**：`volatile`/`final` 语义强化，happen-before 成体系。
- **JDK 9 (VarHandle)**：手写可用 `VarHandle` 精确控制屏障（替代 `Unsafe`）。
- **JDK 15+**：偏向锁移除；虚拟线程（JDK 21）让"手写线程调度"部分过时。

## 四、经典论文 / 原始文献

- **JSR 133 / Manson-Pugh-Adve (POPL 2005)**——happen-before 形式化。
- **Lamport, "Time, Clocks..." (1978)**——happened-before 概念。
- **Michael & Scott, "Non-Blocking..." (PODC 1996)**——手写无锁队列依据。
- **Herlihy, "Wait-Free Synchronization" (PODC 1991)**——CAS 层级。
- **Sewell et al., "x86-TSO" (CACM 2010)** / **Alglave et al., "Herding Cats" (TOPLAS 2014)**——内存屏障硬件语义。

## 六、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "`stop` 强制关线程" | 废弃且危险；用 volatile 标志 / interrupt |
| 2 | "C++ volatile = Java volatile" | 前者不管线程可见性；天壤之别 |
| 3 | "`volatile` 原子" | 只可见+单变量原子；`i++` 非原子 |
| 4 | "wait 用 if 判断" | 必须 while |
| 5 | "手写用 Unsafe 就行" | 🔧 JDK 21+ 废弃；改 VarHandle |
| 6 | "手写无锁队列不难" | 多写多读要处理 ABA/内存回收；用 jcstress 验证 |
