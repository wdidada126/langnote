# 《Java并发实现原理：JDK源码剖析》——总览与阅读地图

> 作者：冷血（笔名，技术博主/面试讲师）。本书独特定位：**从零手写 JDK Concurrent 包的每一部分**——不是"讲原理"，而是"把 AQS、ConcurrentHashMap、线程池、ForkJoinPool、CompletableFuture 用朴素代码重新实现一遍"，让读者真正看懂 JDK 源码为什么这么写。
> 版本基线：JDK 8 源码（书中以 HotSpot + J.U.C JDK 8 为准）。
> 与另外两本的关系：Goetz《实战》教"设计原则"、方腾飞《艺术》教"JVM/CPU 底层"、**冷血本书教"源码手写"**——三者构成"原则 → 底层 → 代码"的完整链条。

## 三、版本演进时间轴

- **JDK 5 (2004)**：J.U.C 引入，本书剖析对象的起点。
- **JDK 8 (2014)**：`ConcurrentHashMap` 桶级 CAS+锁、`CompletableFuture` 引入——本书基线。
- **JDK 9+**：`VarHandle` 取代 `Unsafe`（本书手写多直接用 `Unsafe`，需知 JDK 21+ 已废弃）。
- **JDK 21+**：虚拟线程 → 手写线程池/Executor 的"必要性"下降（IO 密集改虚拟线程 + 结构化并发）。

## 五、本书没覆盖的缺口

1. **`VarHandle`**（JDK 9+）：手写仍用 `Unsafe`，需迁移说明。
2. **虚拟线程 / 结构化并发**（JDK 21-25）：成书后。
3. **`LongAdder` / 伪共享 `@Contended`**：手写 Atomic 未展开分段。
4. **`StampedLock`**：未在锁章展开乐观读。
5. **`ScopedValue` / `MemorySegment`**：无。

## 七、跨语言对照

- 手写 AQS ≈ C++ `folly` / Rust `crossbeam` 的无锁结构（思想同源）。
- 手写 CAS 队列 ≈ Michael-Scott 队列（见《之美》专篇）。
- `CompletableFuture` 手写 ≈ JS Promise / Rust `Future` / Kotlin `Deferred` 的同步版。
