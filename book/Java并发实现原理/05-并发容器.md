> 手写 `ConcurrentHashMap`（分段锁版）、`CopyOnWriteArrayList`、阻塞队列、手写 `ConcurrentLinkedQueue`（Michael-Scott）。与《艺术》6 章 + 《之美》`concepts/ConcurrentHashMap演进.md`、`阻塞队列BlockingQueue.md`、`Michael-Scott无锁队列.md` 互补——本书是"写一遍"，另两本是"读 JDK 8 桶级版源码"。

## 一、本章地图

| 容器 | 手写要点 |

## 二、核心精讲

### 2.1 手写 `ConcurrentHashMap`（分段锁，JDK 7 基线）
- 结构：`Segment[]`，每 `Segment` 继承 `ReentrantLock`，内部 `HashEntry[]` 链表。
- `put`：算 key 的 segment → 锁该 segment → 链上找/插（头插或尾插按 JDK 版）。
- 并发度 = segment 数（默认 16）；**全表操作（size/clear）要锁所有 segment 再求和**。
- 🔧 **重大修正**：JDK 8 已弃分段锁，改为 `Node[]` + 桶级 CAS + `synchronized` 桶头（更细粒度，无 Segment）。本书 JDK 8 版若写"16 段"多半引旧思路；务必对照《之美》ConcurrentHashMap 演进专篇。

### 2.2 手写 `CopyOnWriteArrayList`
- `volatile Object[] array`；`add`：复制整个数组 → 新元素放末尾 → CAS/锁替换引用。
- 读 `get`：直接读当前数组（无锁，snapshot）；适合**读多写极少**（监听器列表、配置）。
- 代价：写复制全数组 → 写多即 GC 灾难。

### 2.3 手写阻塞队列
- `ArrayBlockingQueue`：数组 + 一把 `ReentrantLock` + `notEmpty`/`notFull` 两 Condition；`put` 满则 `notFull.await`，`take` 空则 `notEmpty.await`。
- 容量：数组版**有界**；链表版（`LinkedBlockingQueue`）🔧 默认 `Integer.MAX_VALUE` 无界（生产事故 TOP1），务必指定容量。

### 2.4 手写 `ConcurrentLinkedQueue`（Michael-Scott）
- `head`/`tail` 两 `AtomicReference`；入队 CAS `tail.next` 再 CAS `tail`；出队 CAS `head` 返回 `head.next.item`。
- **tail slack**：`tail` 滞后；操作时要从 `tail` 往后找真尾（详见《之美》MS 队列专篇）。
- 无锁 → 高并发吞吐好，但 `size()` 需遍历（O(n)，非精确瞬时）。

## 三、版本演进

- **JDK 5**：并发容器随 J.U.C 引入（CHM 分段、COW、阻塞队列、CLQ）。
- **JDK 7 (2011)**：CHM 仍分段（本书常见基线）。
- **JDK 8 (2014)**：CHM 桶级 CAS+锁；`LongAdder` 式分段计数。
- **JDK 21**：虚拟线程改并发模型，ForkJoin/线程池部分被结构化并发接管。

## 六、常见误区 / 本书需修正之处

| # | 误区 | 修正 |

| 1 | "CHM 是 16 段锁" | 🔧 JDK 8 起桶级 CAS+锁，无 Segment |
