# 09 索引与统计信息

> 章题 ⚠️ 推定；主题域 ✅ 实证：官方代码仓 `Chapter09/09_01.sql` 定义 `table_stats` 视图——
> 把 `pg_stat_user_tables`（seq_scan/idx_scan/tup 计数）与 `pg_statio_user_tables`
> （heap/idx 块读写命中）RIGHT JOIN 成一张"表级索引效益总表"；`09_10.sql` 演示
> `CREATE INDEX` 后立即查 `pg_class.reltuples/relpages` 的形态学观察。本章以此二码为骨架。非原书文本。

## 一、效益视图先行（09_01.sql ✅ 原文结构）

```sql
CREATE VIEW table_stats AS
SELECT stat.relname, seq_scan, seq_tup_read, idx_scan, idx_tup_fetch,
       heap_blks_read, heap_blks_hit, idx_blks_read, idx_blks_hit
FROM pg_stat_user_tables stat
RIGHT JOIN pg_statio_user_tables statio ON stat.relid = statio.relid;
```
判读法（⚠️ 教材性复原）：
- `seq_scan 高 & idx_scan≈0` 的大表 = 缺索引或索引失效（表达式不匹配）；
- `idx_scan 高但 heap_blks_read 也高` = 回表随机 IO 重，候选覆盖索引；
- `idx_blks_hit 低` = 索引本身装不进缓存，先量 05 章的池子再谈加索引。
**先测效益再动 DDL** 是本章的顺序纪律，与
[../数据库索引设计与优化.md](../数据库索引设计与优化.md)（✅ 盘上互链）的"索引审计先行"同一方法论。

## 二、B-tree 之外：PG10 时代的索引兵器谱（⚠️ 转述官方索引文档族）

| 索引 | 场景 | 性能要点 |
| --- | --- | --- |
| B-tree | 默认，范围/排序 | 唯一约束载体；浅但宽 |
| BRIN | 追加型大表（时序/日志） | 元数据级索引，体积千分之一量级 ⚠️；天然抗 07 章膨胀 |
| GIN | 全文/jsonb/数组包含 | 写放大显著，fastupdate 权衡 |
| GiST | 地理/近邻/排除约束 | 非精确平衡树，缓存友好度各异 |
| 表达式索引 | 函数谓词等值 | 查询形状必须逐字匹配 |
| 部分索引 | 热点子集（status='open'） | 体积与膨胀双降，HOT 友好 ⚠️ 链条 |

- PG10 并行索引构建（01 章）使 CREATE INDEX 窗口缩短，但 `max_parallel_maintenance_workers`
  的内存账（每 worker 复制 work_mem，05 章）必须同步审 ⚠️ 转述；
- `CONCURRENTLY` 建索引不锁写但周期长、可能留下 INVALID 索引需重建 ⚠️ 官方文档语义转述。

## 三、统计信息：reltuples 之后发生了什么（09_10.sql ✅ 现场）

CREATE INDEX 后 `pg_class` 的 reltuples/relpages 即成本模型的原料（ANALYZE 的采样估计 ⚠️）。
统计失效三症状与处方 ⚠️ 教材性：
1. 行数估计漂移（n_live_tup vs 实际）→ 查 last_analyze/last_autoanalyze；
2. 直方图选不住新倾斜（数据增长后）→ `ALTER TABLE SET (autovacuum_analyze_scale_factor=…)` 收紧；
3. 扩展统计缺失：PG10 的 `CREATE STATISTICS`（ndistinct/dependencies/mcv 组合统计）刚满一岁，
   多列相关谓词的误估仍是大表坏计划首因 ⚠️ 转述，10 章 EXPLAIN 现场回收此伏笔。

## 四、覆盖索引与索引_only 扫描（🔧 类比，非 PG）

PG 的 index-only scan 依赖 VM 可见性位图（07 章），fresh vacuum 后收益才稳定——这一
"可见性依赖"在 SQLite 无对应物。🔧 用 sqlite3 可类比的部分仅"覆盖 vs 回表"的量纲：
对 X-A 库 `SELECT count(*) WHERE v>100` 加 `CREATE INDEX ON t(v)` 后 `EXPLAIN QUERY PLAN`
显示 USING INDEX，扫描从 10.6MB 全表降到索引侧 ⚠️ 数字随缓存冷热波动，仅作形态演示
（方法同 exps.py 段 A 之上追加索引对照）。

## 五、反模式清单（⚠️ 社区共识转述）

- 给每个列建单列索引"以防万一"（写放大+优化器选择面爆炸）；
- 外键列不建索引（PG 不自动建！锁升级事故的常客 ⚠️）；
- 用函数包裹索引列使表达式索引不匹配；
- 部分索引谓词与查询谓词形状不一致；
- 只看 pg_stat_user_indexes 的 idx_scan=0 就删索引（统计窗未清零/低频关键查询被误杀 ⚠️）。

## 细案：一周索引治理冲刺排程（⚠️ 教材性；每步 SQL 形态均有书仓 Chapter09 对应物）

| 日 | 动作 | 产出 |
| --- | --- | --- |

| 周二 | 候选缺口分析：seq_scan 高×体量大的表逐一写"缺什么索引"假设 | 假设清单（02 章模板） |
| 周三 | 灰度建索引：先低峰 CONCURRENTLY 一张最痛表；记录时长与并行度（01/05 章预算） | A/B 延迟对比 |
| 周四 | 冗余清点：pg_stat_user_indexes 长期 idx_scan≈0 者进"观察名单"（不即删，00 时窗陷阱） | 观察名单 |
| 周五 | 统计补强：倾斜列建 CREATE STATISTICS（PG10 新武器），重跑坏计划样本（10 章） | 计划 diff |
| 周末 | cron 化：效益总表周报 + reltuples 漂移告警（11 章面板并入） | 自动化收尾 |

判读深水区两例（⚠️ 社区共识转述）：
- "idx_scan=0 的索引"可能是**防重唯一约束**或**外键锁保护**在支撑写路径，删前必查约束依赖；
- 表达式索引与查询形状"逐字匹配"：`WHERE lower(mail)=...` 换 `WHERE lower(mail::text)=...`
  即失配——列强类型规约（08 章）与索引审计是同一枚硬币。

## 章内自测（三问三答）

- **问：覆盖索引在 PG 为何不总带来 index-only scan？**
  答：VM 可见性位不"新"就要回堆判定（07 章），vacuum 新鲜度决定收益稳定性。
- **问：ANALYZE 与 VACUUM ANALYZE 选哪个做窗口收尾？**
  答：后者一次过两账（回收+统计），但时长计入窗口预算（07/12 章算术）。
- **问：统计视图里 heap_blks_read 高而 idx_scan 也高，什么病？**
  答：回表随机 IO 重——覆盖索引/聚簇重写候选（本表周三/周五动作），不是再加一个二级索引的信号。

## 延伸两查（速装版，⚠️ 教材性）

1. **索引体积榜**：`SELECT indexrelname, pg_size_pretty(pg_indexes_size(indrelid))` 思路的目录联查——
   写放大预算与 04 章容量账对接；
2. **重复索引雷达**：pg_index 自联比较 indkey 前缀包含关系，"被更大索引前缀覆盖的旧索引"
   候选清单一键导出（配合周三灰度节奏做减法，03 章契约）。

## 核心概念速览（中英对照）

- **效益审计** — Index Usage Audit：以 seq/idx 扫描比先定位问题（09_01.sql）。
- **覆盖索引** — Covering Index：索引含全部所需列，免回表。
- **index-only scan** — 索引仅扫描：依赖 VM 位的无堆访问路径。
- **BRIN** — 块范围索引：追加型数据的极廉价粗索引。
- **GIN** — 通用倒排：包含类查询主力，写放大换读加速。
- **表达式索引** — Expression Index：以谓词函数形状为键的索引。
- **部分索引** — Partial Index：带 WHERE 的瘦身高性价比索引。
- **CREATE STATISTICS** — 扩展统计：多列相关性/ndistinct/MCV 组合估计（PG10 新）。
- **reltuples/relpages** — 形态学字段：成本模型的表规模原料（09_10.sql）。
- **CONCURRENTLY** — 在线建索引：不锁写但慢且可残留 INVALID。
- **并行索引构建** — Parallel B-tree Build：PG10 维护并行主形态（01 章）。
- **外键索引义务** — FK Indexing Duty：PG 不自动为 FK 建列索引的运维常识 ⚠️。
