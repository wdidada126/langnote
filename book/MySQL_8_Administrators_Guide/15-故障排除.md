## 15.1 本章定位

全书任务流的"事故现场汇总"：连不上、起不来、跑得慢、数据坏了、复制断了五类剧本，
配"证据链采集→假设→最小实验→修复→复盘"的通用流程。本章与 12 章共用观测三件套，
差别在 12 章为"优化"采证、15 章为"止损"采证。

## 15.2 证据链采集顺序（⚠️ 通行口径）

1. **错误日志**（log_error）：启动失败、崩溃栈摘要（signal 6/11 文本）、磁盘满、权限、插件加载——永远第一站；
   8.0 组件化日志（`INSTALL COMPONENT 'file://component_log_sink_json'` 等，13 章两用 ⚠️）。
2. **进程与系统层**：dmesg/OOM killer、磁盘 inode/空间（binlog 膨胀经典）、fd 耗尽、时钟漂移（组复制杀手）。
3. **实例内现场**（能连上的世界）：`SHOW PROCESSLIST`/`threads` 表、`engine innodb status` 断面（锁等待图、
   最近死锁、log 年龄）、`information_schema.innodb_traps`——正名 `innodb_trx/locks/data_locks`（表名以手册 ⚠️）。
4. **语句画像**：慢日志+digest（12 章复用）；8.0.28+ 的 `information_schema.processlist` 与
   `performance_schema.threads` 双轨视角。
5. **崩溃后取证**：核心转储+`thread apply all bt`（gdb）、错误日志末段；重复崩溃先查版本已知 bug 库（bugs.mysql.com）。

## 15.3 五类剧本要点（⚠️ 转述+联动章回收）

- **连不上**：网络/端口 → 插件兼容（caching_sha2 与老驱动，11 章）→ `max_connections`/`aborted_connects` 增长源
  → 白名单与 `%` 账户冲突（11 章三查）。
- **起不来**：datadir 权限/磁盘 → 未完成事务恢复耗时（redo 回放无捷径，别在恢复中 kill -9 连环踩）→
  option 文件解析失败（`--validate-config` 预检）→ **innodb_force_recovery 阶梯（1–6）**：只用于"把数据捞出来"，
  捞完必须重建实例回放备份（4/5 章回收；级别越高越危险，⚠️）。
- **慢**：先判"全慢还是部分慢"（资源饱和 vs 计划突变）；计划突变三板斧：统计过期（ANALYZE）、
  数据倾斜新增（直方图，12 章）、版本升级回退 hint（12 章）。
- **复制断**：GTID 洞（🔧 08 章语义实验：洞≠丢数）→ 主从 schema 漂移（pt-table-checksum 谱系）→
  大事务撞 max_allowed_packet。
- **数据坏**：逻辑错误（无外键环境的孤儿行，06 章决策回收）vs 页损坏（校验和报错→备份+binlog 定点恢复，05 章剧本）。

## 15.4 🔧 类比实测：快而自洽的"证据快照"（非 MySQL 行为）

DuckDB 1.5.5 实跑（脚本 `D:\develops\tmp\dbwave_w5_myadmin\`，2026-09-27）：

- `COPY (2,000,000 行表) TO 'snap.parquet' (FORMAT PARQUET)` 耗时 **0.05 秒、产物 16,437 KB**，
  新进程回读校验 `count=2,000,000, min=0, max=1,999,999` 全对。
- 读出的排错直觉：事故现场要**先冻结一个可移走的自洽副本**再慢慢解剖——MySQL 世界的同构动作是
  "错误日志+表空间快照/Clone+binlog 位点"三件套（05 章备份锁/克隆插件的排错用途化，⚠️ 转述）；
  本实验用列存引擎证明"一致性快照导出"可以快到没有借口，**非 MySQL 行为，不可引用为 mysqldump 性能**。
- 与 05 章 SQLite `backup()` 实验（快照 1000 行 vs 活库 1168 行）互补：那组教"快照自洽且不追新"，这组教"快照要便宜到常备"。

## 核心概念速览（中英对照）

- **错误日志** — error log：服务器自述书，起不来/崩了的第一证物（组件化 sink 可 JSON 化，⚠️）。
- **--validate-config** — 配置预检：只解析不启动，变更门禁的标准件。
- **innodb_force_recovery** — 强制恢复阶梯：1–6 逐级放宽读路径，用途=数据抢救，禁用于复产（⚠️）。
- **SHOW ENGINE INNODB STATUS** — 引擎断面：锁等待图/最近死锁/log 年龄的一页 X 光。
- **digest 表** — events_statements_summary_by_digest：慢的归类证据源（12 章复用）。
- **OOM killer** — 内核猎杀：buffer pool+连接内存超预算时，凶手在 dmesg 不在 MySQL 日志。
- **binlog 膨胀** — 磁盘杀手第一名：expire_logs_days/binlog_retention 与备份策略联动（05/08 章）。
- **表漂移** — schema drift：主从结构悄悄不一致，checksum 工具谱系的猎物。
- **GTID 洞** — gtid set gap：回滚/跳过所致，合法存在（08 章 🔧 实验语义）。
- **一致性快照导出** — 🔧 实验（0.05s/16MB, DuckDB）：现场冻结的成本下界演示，非 MySQL 行为。
- **复盘四栏** — 时间线/触发因/止损/不变量化：把故障转化为 14 章清单条目的工序。
- **止损优先** — mitigate first：回滚>参数>重启>重搭；证据采完才动手的例外是"采证本身在延长故障"。
