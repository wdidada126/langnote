## 6.1 本章定位

插件式存储引擎是 MySQL 区别于单机引擎的架构招牌，而 8.0 是这块招牌**褪色**的版本：
MyISAM 退役倒计时、MEMORY/ARCHIVE 边缘化、"引擎选择"塌缩成"InnoDB 参数选择"。
本章的书内价值恰在记录这个转折点——2026 年读它是"考古+默认值确认"。

## 6.2 InnoDB：唯一的"默认答案"（⚠️ 转述）

- 能力清单：聚簇索引组织表、行级锁+MVCC、外键、崩溃恢复（redo）、变更缓冲、双写文件、
  每表一表空间（file_per_table 默认 ON）、透明页压缩、生成列/函数索引支撑。
- 管理员真正面对的"InnoDB 选择题"：
  `innodb_buffer_pool_size`（专用库 50–75% 内存起）、`innodb_log_file_size`/`innodb_redo_log_capacity`（8.0.30 前后两代口径）、
  `innodb_flush_log_at_trx_commit`（1=ACID / 2=秒级窗口 / 0=性能赌徒）、`innodb_io_capacity` 与实际 SSD 能力校准。
- 8.0 特性线：数据字典事务化（5 章联动）、即席统计与直方图（12 章）、并行读框架雏形。
- 机制纵深全部在盘上姊妹册：[../mysql/01-InnoDB与MySQL的架构.md](../mysql/01-InnoDB与MySQL的架构.md) 起整条线
  （缓冲池 02、数据页 03–05、redo 19、undo 20、MVCC 21、锁 22）。

## 6.3 二级引擎名册与 2026 存活度

| 引擎 | 书内定位 | 8.0/8.4 现状（⚠️） |
| --- | --- | --- |
| MyISAM | 历史全文/高速导入选项 | **8.0.22 起官方弃用全文索引于 MyISAM、8.4 语境只剩"迁移对象"身份**；表级锁/无崩溃安全使生产不可辩护 |
| MEMORY | 临时映射表 | 8.0.22 弃用；等价物=TempTable/应用内缓存 |
| NDB | 分布式引擎（Cluster） | 分离发行线，10 章主场；本波与 [../Understanding_MySQL_Internals/10-存储引擎掠影.md](../Understanding_MySQL_Internals/10-存储引擎掠影.md) 时代语境对照 |
| ARCHIVE | 冷数据压缩追加 | 边缘存活，多被分区+OSS 归档替代（⚠️） |
| CSV | 交换格式表 | 演示/导入通道，无索引 |
| BLACKHOLE | 丢弃一切写入 | binlog 复制过滤/压测注入技巧（⚠️ 用法属社区传统非本书） |
| FEDERATED(_B) | 远端表代理 | 脆弱、长期无人问津；跨库读写走其他方案 |
| MERGE | 视图化分表 | 事实死亡（分区表替代） |

- `SHOW ENGINES` / `CREATE TABLE ... ENGINE=x` / `ALTER TABLE ... ENGINE=x`（=一次全表 COPY 迁移，5.3 代价模型）；
  引擎无关层=SQL+binlog，引擎相关层=行存储+锁+事务（对读
  [../Understanding_MySQL_Internals/07-存储引擎接口.md](../Understanding_MySQL_Internals/07-存储引擎接口.md) 的 handler 接口叙述——
  handler 抽象的源码版，本册给任务版）。

## 6.4 选型方法论（书体裁的任务清单）

1. 默认 InnoDB，**没有例外才写 ENGINE=**；评审时"非 InnoDB 表"单独过堂。
2. 归档/日志类高吞吐插入：先想"分区表+压缩+对象存储"，再想 ARCHIVE/BLACKHOLE。
3. 跨实例查询：FEDERATED 不推荐，优先复制/CDC/数据集市（本仓湖仓线：
  [../Apache_Paimon_Streaming_Lakehouse/00-总览与阅读地图.md](../Apache_Paimon_Streaming_Lakehouse/00-总览与阅读地图.md)，✅ 盘上）。
4. 全文检索：InnoDB FTS 只当"起步货"，体量上来迁 ES/OpenSearch 谱系（对读
  [../Elasticsearch_The_Definitive_Guide/00-总览与阅读地图.md](../Elasticsearch_The_Definitive_Guide/00-总览与阅读地图.md)，✅ 盘上登记）。
5. 引擎参数改动一律"改一个、观察一周期"（联动 12/14 章监控基线）。

## 核心概念速览（中英对照）

- **插件式存储引擎** — pluggable storage engine：SQL 层之下可换的行存储后端，MySQL 架构招牌（8.0 后名存实亡）。
- **InnoDB** — 默认事务引擎：聚簇索引、行锁、MVCC、redo 恢复，全部其他选项的对照组。
- **handler 接口** — Table Handler API：Server 层与引擎的边界协议，源码纵深见 #32。
- **MyISAM** — 非事务引擎：表锁、无崩溃安全，8.0.22+ 弃用倒计时，只剩迁移学价值。
- **MEMORY** — 内存引擎：哈希索引、重启即失，8.0.22 弃用。
- **NDB Cluster** — 分布式无共享引擎：内存+磁盘、分片内建，10 章 HA 线的底座。
- **BLACKHOLE** — 黑洞引擎：收写即焚，复制过滤与注入测试的民间用法（⚠️）。
- **FEDERATED** — 远端代理引擎：表级跨实例读写，脆弱不推荐。
- **file-per-table** — 单表表空间：innodb_file_per_table 默认 ON，表=独立 ibd 文件（5 章备份粒度基础）。
- **双写缓冲** — doublewrite：防页撕裂的redo前置写区，InnoDB 崩溃一致性的沉默功臣（机制在 ../mysql/19）。
- **ALTER TABLE ... ENGINE** — 换引擎=整表重写：容量、索引、autoinc 语义全要重验。

## 最新演进与工业实践

- **8.4 的引擎终局**（⚠️ 转述）：官方手册 8.4 已把 MyISAM 系统表全面 InnoDB 化（5.7→8.0 迁移的最后一批），
  "引擎选择"在文档层面退化为"InnoDB + 例外清单"。
- **InnoDB 参数代际**：`innodb_redo_log_capacity`（8.0.30+）替代 log_file_size×组数口径；
  buffer pool chunk/instant resize 成为弹性内存管理基线——书中"重启才能改"的多数限制解除（⚠️）。
- **可插拔性的精神续作**：引擎框架转向**表空间/存储层级**扩展（tablespace 加密、归档到对象存储的
  Clone Plugin/Enterprise 备份线，见 [13-扩展MySQL8.md](13-扩展MySQL8.md)）与**生态级替换**
  （TiDB/PolarDB 复用 MySQL 协议而非引擎；本仓对照 [../设计数据密集型应用.md](../设计数据密集型应用.md) 的存储分层章节）。
- **工业现状**：新系统评审里出现非 InnoDB 引擎≈事故预告（Google/Percona 系公开指南一致口径，⚠️ 转述）。
- **取证留痕**：✅ storage-engines 镜像页 200（2026-09-27）；6.3 存活度列为 ⚠️ 手册通知主题综合，未逐条引 URL。
