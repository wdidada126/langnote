## 14.2 最佳实践清单（按对象归并，⚠️ 通行口径）

**实例与配置**
1. 参数文件进配置管理（Git/Ansible），禁用"登上去手改"；`SET PERSIST` 也纳入采集（03 章 mysqld-auto.cnf 幽灵）。
2. "双 1"+独立 tmp/redo/binlog 盘（机械盘时代遗产，NVMe 时代仍守"日志与数据分离"心智）（08 章）。
3. buffer pool 按工作集定，预留 OS/连接内存；监控 `Threads_running` 与 p_s 等待为主仪表盘（12 章）。
4. 版本策略：生产只跟 LTS（2026 语境=8.4），升级=演练过的剧本（02 章滚动升级）。

**模式设计**
5. 每表有意义的主键（短、单调、BIGINT UNSIGNED 倾向）；外键用不用是组织题，但**必须显式决策**（6/9 章：分区即弃 FK）。
6. 列类型最小化+NOT NULL+默认值；utf8mb4 全链一致；ENUM 谨慎、JSON 节制（04 章）。
7. 索引做减法：上线评审带"读写放大预算"，下线走 INVISIBLE 流程（07 章）。
8. 大表治理预铺：时间序列表从第一天就规划归档路线（09 章：分区弃用后=分表/湖仓）。

**运维纪律**
9. 备份四重身份+每周自动回放验证（05 章）；恢复演练 RTO 计时。
10. 账户三查：SUPER 存量/`%` 通配/明文口令与 login-path 普及率（11 章）。
11. 变更窗口化：DDL/参数/索引变更全部走评审+回滚单（05 章 INSTANT 也留回滚）。
12. 监控基线先行：无基线的环境里所有指标都是噪声（对读
    [../Efficient_MySQL_Performance/06-服务器指标与InnoDB.md](../Efficient_MySQL_Performance/06-服务器指标与InnoDB.md)）。

## 14.3 基准测试方法学（⚠️ 转述）

1. **为什么管理员要会跑分**：容量规划（新机/新盘/新云型号验收）、变更回归（参数/内核小版本）、
   瓶颈归因（"这版为什么慢"的证据链）。
2. **工具名册**：sysbench（OLTP 点查/范围/混合，threads/time 矩阵）、tpcc-check/TPC-C 家族（事务完整性重负载）、
   mysqlslap（轻量并发画像）、Percona Data Integrity Check（压后校验）。
3. **方法学五律**：预热到稳态再计数；单变量；保存原始时序非截图；同时采 p_s/OS 两层指标；
   **明确"基准分数≠生产容量"**（数据分布、SQL 混合、热点键全不同）。
4. **常见自欺**：拿 sysbench 空库跑分写进采购报告；忘关慢日志/性能探针的开销对照组；
   客户端与库同机抢核；用平均值汇报延迟丢尾（应报 p99，#45 北极星语境的度量观）。
5. 书内示例基线（⚠️）：sysbench oltp_read_write 三档并发对比 + "配置变更前后 A/B"模板——
   2026 年仍是验收合同的合理骨架，仅需把 MySQL 版本与参数清单换成 8.4 口径。

## 核心概念速览（中英对照）

- **配置即代码** — configuration as code：my.cnf/SET PERSIST 全量纳入版本管理，消灭口口相传参数。
- **双 1** — sync_binlog=1 + flush_log_at_trx_commit=1：持久化基线，性能税要算得明白（08 章）。
- **工作集** — working set：热数据规模，buffer pool 与"该不该分片"的共同分母。
- **恢复演练** — restore drill：备份的验收测试，RTO 计时进月报。
- **sysbench** — OLTP 基准发生器：oltp_read_write 等场景+线程矩阵的事实标准（⚠️）。
- **TPC-C** — 事务基准：强一致多表混合负载的学术谱系，验收"重 OLTP"用。
- **预热** — warmup：缓冲池/统计/计划缓存进入稳态后才可计数，基准第一律。
- **p99 延迟** — tail latency：汇报口径纪律，平均值是基准自欺的头号帮凶。
- **A/B 回归** — 单变量对比：参数/版本变更的最小实验设计（14.4 的 SQLite 纪律迁移对象）。
- **容量判定** — sizing：基准的正当用途=验收与规划，不是"我的生产能跑 X 万 QPS"的预言。
- **清单革命** — checklist engineering：本章左半书的体裁本质：把经验压缩成可审计的条目。

## 最新演进与工业实践

- **基准工具线**（⚠️ 转述）：sysbench 仍活跃（1.0.x 长稳）；云厂商验收普遍加"真实流量回放"层
  （traffic replay/影子库），纯合成基准退居二线；本仓判断：合成基准定下限、回放定上限，两者不可互替。
- **硬件语境漂移**：NVMe/optane 退潮与对象存储分层（09 章冷数据）改变了 14.2-2 的"多盘分离"教条——
  2026 版应改写为"本地 NVMe 热层 + 对象存储冷层 + 日志独立卷"三段式（⚠️ 实践口径）。
- **可观测性合流**（⚠️ 转述）：OpenTelemetry 把 DB 指标并入统一 trace/span 语境，p_s 的角色下沉为"证据源"，
