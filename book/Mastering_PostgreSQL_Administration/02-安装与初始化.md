## 核心精讲（⚠️ 文档转述重构）

### 1. 装什么、从哪装

- 生产主流是 **PGDG 官方源**（apt.postgresql.org / yum-apt.postgresql.org）：`postgresql-17` 主包 +
  `postgresql-contrib`（PG14 起 contrib 已并入主包，老运维手册口径要更新 ⚠️）+ 按需要的
  `postgresql-17-pgvector` 等扩展子包。发行版自带源版本旧且打补丁，两源混装是"扩展加载失败"的高发根因。
- 源码安装 `configure → make → make install` 的价值在定制编译开关：`--with-segsize`（段大小）、
  `--with-blocksize`（**PG12 起块大小不再是可编译选项，固定 8KB** ⚠️）、`--with-uuid=ossp` 等；
  装完的二进制与共享库分置 `libexec/postgresql`、`share/postgresql`（含 initdb 模板库的
  `share/postgresql/template1` 全局表定义——理解"模板"概念见下文第 3 节）。
- 容器/云镜像只是打包形态差异，**数据目录语义不变**：卷必须只挂给单实例，PGDATA 放网络文件系统是大忌 ⚠️。

### 2. initdb：一个新"集群"的诞生

`initdb -D /var/lib/pgsql/17/data` 依次完成（⚠️ 转述）：
1. 建目录并强制权限 0700（属主必须是运行 postmaster 的 `postgres` 系统用户；Windows 服务形态下是
   NT 权限等价物，这也是"9 月装完 10 月连不上"的常见事故：手工改过属主/权限）；
2. 写 `PG_VERSION`（内容仅一个数字；大版本目录不兼容的判据就是它）；
3. 用编译期内核模板建 **`global/`**（共享目录表：pg_database、pg_authid、pg_tablespace…，OID ≤ 16384
   系统对象，03 章物理视图续集）；
4. 建 **`base/1` = template1**、`base/` 下随后有 template0；`CREATE DATABASE` 即拷贝模板库（04 章）；
5. 建 `pg_wal/`（初始 WAL 段 16MB×N）、`pg_xact/`、`pg_stat/` 等子系目录；
6. 从 sample 文件生成 `postgresql.conf` 与 `pg_hba.conf`（hba 默认本机 trust/peer，**首启后立即收紧**）；
7. 可选 `--data-checksums`：页校验和**初始化后不可再开**（只能 pg_checksums 离线开，PG12+），
   发行版默认多数关闭——装机清单上必须有人拍板此项 ⚠️。

### 3. 首启与最小可用配置

`postgresql.conf` 三件套先改：`listen_addresses`（默认 localhost，容器/远端场景必改）、`port`、
`unix_socket_directories`；随后 `pg_hba.conf` 按 01 章四元组模型放行最小集合；
`pg_ctl start` 或 systemd `postgresql-17.service`。验收 SQL（⚠️ 转述）：

```sql
SHOW server_version;          -- 期望 17.x
SELECT datname FROM pg_database;  -- postgres | template1 | template0
```

装扩展的前置在装机时就该埋好：`shared_preload_libraries`（如 pg_stat_statements、pg_pathman 类）
属 postmaster 上下文，**后补必重启**（呼应 01 章共享内存结论）。

### 4. 卸载与升级的边界

- 卸载软件 ≠ 删除数据：包管理器 remove 后 PGDATA 原样留存（Debian `--purge` 才会连集群一起删）；
  重装即可 attach 旧目录——这是 DBA 的逃生门，但前提是 PG_VERSION 匹配。
- 大版本升级三条路：`pg_upgrade --link`（快、原地、升级后旧目录不可回退共享文件 ⚠️）、
  逻辑转储/装载（慢、顺带清膨胀）、逻辑复制（PG16/17 时代的零停机首选，见 Cookbook 07 章）。
  PG17 的 pg_upgrade 已能保留部分链路信息、PG18 起保留统计（⚠️ 转述，见 05/07 章演进节）。

## 常见坑与判读

| 现象 | 第一判读 | 取证动作（⚠️ 转述） |
| --- | --- | --- |
| initdb 报 "cannot be run as root" | 设计如此，必须专用低权用户 | 建 postgres 用户后 `sudo -u postgres initdb` |
| 服务起不来，日志空 | 日志还没配，错在 conf 解析阶段 | 前台跑 `postgres -D ... -c config_file=...` 看 stderr |
| 远程连不上本机能连 | listen_addresses 未改 / hba 未放行 / 防火墙 | 三层各证一次：ss -lntp、hba 试算、nc -z |
| 装完扩展 CREATE EXTENSION 报缺文件 | 装错源（发行版源 vs PGDG 源混装） | `apt list --installed` 过滤 postgresql 核对同源 |
| Windows 装完服务不自动起 | initdb 时未 `--no-locale` 类参数触发服务注册失败 | 用 `pg_ctl register` 显式注册 |
| locale 装错想改 | 已有库的 collation 不可原地改 | 只能 initdb 新集群 + 逻辑迁移（或 17 起部分可 ALTER COLLATION provider ⚠️） |

## 核心概念速览（中英对照）

1. **集群** — database cluster：一个 postmaster 管理的全部库的集合，= 一个 PGDATA。
2. **数据目录** — PGDATA / data_directory：一切持久化文件的根，initdb 的产物目录。
3. **初始化器** — initdb：建目录树、系统表、模板库并生成 conf 的唯一正规入口。
4. **模板库** — template1/template0：CREATE DATABASE 的拷贝源；template0 是"纯净重导出"专用。
5. **版本哨兵** — PG_VERSION：目录内一行数字文件，二进制与数据目录兼容性的闸门。
6. **页校验和** — data checksums：initdb 时一次性决定的页级损坏检测，运维不可后补的决策。
7. **预载库** — shared_preload_libraries：需常驻共享内存的扩展清单，装机时定、改动即重启。
8. **四元组放行** — pg_hba.conf record：type/database/user/address/method 行式规则。
9. **原地升级** — pg_upgrade（--link）：换版本不换数据目录的快升路径。
10. **逻辑迁移升级** — dump/restore 或逻辑复制升级：跨版本兼清膨胀的慢路径（见 05 章工具）。
11. **PGDG 源** — PostgreSQL 全球组织官方仓库：生产安装的事实标准渠道。
12. **服务注册** — pg_ctl register / systemd unit：把 postmaster 交给 OS 进程管家。

## 最新演进与工业实践

- **版本**：PG17（2024-09，✅ 新闻页 https://www.postgresql.org/about/news/postgresql-17-released-2953/ 实抓 200）；
  PG18 已发布进入 current（✅ https://www.postgresql.org/support/versioning/ 实抓 200）。装机清单类差异
  集中在默认参数与扩展打包，initdb 语义 20 年稳定。
- **contrib 并包**：PG14 起 contrib 模块随主包安装，旧文档的 `postgresql-contrib` 步骤在新源上会报
  "无此包"（PGDG 源已做过渡别名 ⚠️ 转述）。
- **扩展生态安装化**：pgvector、TimescaleDB、Citus 均以"同源扩展子包"分发；扩展版本管理走
  `ALTER EXTENSION ... UPDATE`，与主版本升级解耦（06 章维护语境衔接）⚠️。
- **不可变基础设施**：云原生 operator（CloudNativePG ✅ https://github.com/cloudnative-pg/cloudnative-pg 实抓 200）
  把"initdb + conf 渲染"代码化为 CRD 声明，传统装机手册的落点正在从 shell 迁移到 YAML，
  但本章的 initdb 知识仍是读懂 operator 生成物的地基。
