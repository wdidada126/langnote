## 核心精讲（⚠️ 文档转述重构）

### 1. 层次：库是硬墙，模式是软隔

PG 的包含链是 **集群 → 数据库 → 模式 → 对象**。关键纪律（⚠️ 转述）：
- **数据库之间是硬隔离**：不能一条 SQL 直查另一库的表（除非 dblink/FDW 外挂），连接时必须选定库；
  Oracle/SQL Server 习惯"一库多应用分 schema"的运维在 PG 社区被反复教育为反模式——
  库多了 =  Vacuum/备份/复制粒度全变碎，默认答案应是"一库多 schema"。
- **模式是搜索路径问题**：`search_path` 决定非限定名解析顺序，运维脚本安全铁律是显式
  `SET search_path = xxx, pg_temp;`（防临时模式劫持，06 章自动化脚本衔接）。
- `public` 模式的历史包袱：PG15 起**默认撤走 public 的 CREATE 权限**（官方安全加固，✅ 思路见发布说明），
  老迁移包"能建表"变"permission denied for schema public"是升级第一高报错，处置是显式授权或改用
  专用模式——08 章去 O 落地时同样先建 `app_owner` 持有的专用 schema。⚠️

### 2. USER 与 ROLE：语法糖与本体

`CREATE USER x;` 完全等价 `CREATE ROLE x LOGIN;`——PG 只有一种对象 **role**（目录 `pg_authid`，
密码列对普通用户不可读，公开视图 `pg_roles` 遮蔽之 ⚠️）。治理三要点：
1. **属性轴**：LOGIN / SUPERUSER / CREATEDB / CREATEROLE / REPLICATION / BYPASSRLS / CONNECTION LIMIT
   与权限轴 GRANT 正交，"能登录 ≠ 能干什么"；
2. **成员轴**：`GRANT app_rw TO bob;` 是成员关系，INHERIT 决定要不要自动继承（角色链上
   NOINHERIT 是特权隔离工具），会话内可 `SET ROLE` 降权排错；
3. **口令策略**：`scram-sha-256` 为默认线（PG14+ 彻底接替 md5），`password_encryption`、
   `passwordcheck` 扩展、`VALID UNTIL` 三件套管强度与时效 ⚠️。
应用账号与人类账号分离（`svc_billing` vs `alice`）、登录一律走角色组，是把 pg_hba 写短的前提。

### 3. 认证：pg_hba 是第一道闸

匹配规则：自上而下**首条命中即用**（顺序即策略，加规则要懂插队学）。常见方法面（⚠️ 转述）：
`peer`（本机 Unix 用户映射）、`scram-sha-256`（网络口令）、`cert`（双向 TLS，云上主推）、
`ldap`/`pam`/`gss`（企业目录）、`trust` 仅限本机调试且必须清除。加密传输在 `postgresql.conf`：
`ssl=on` + 证书链；`clientcert=verify-full` 与 hba 联动。01 章连接路径的认证段在此闭环。

### 4. 授权：对象级 + 默认级两层

```sql
GRANT USAGE ON SCHEMA app TO svc_report;            -- 模式进门权
GRANT SELECT ON ALL TABLES IN SCHEMA app TO svc_report;
ALTER DEFAULT PRIVILEGES FOR ROLE app_owner IN SCHEMA app
  GRANT SELECT ON TABLES TO PUBLIC_READ;             -- 未来对象自动授权 ⚠️
```

要点（⚠️ 转述）：**没有默认级，ALL TABLES 授了个寂寞**——新表不回溯，`ALTER DEFAULT PRIVILEGES`
按"授予角色 × 模式"绑定；对象创建者默认持有全部权限（不查任何 ACL）；列级 GRANT、行级 RLS
（`CREATE POLICY` + `ALTER TABLE ENABLE ROW LEVEL SECURITY`）是行/列粒度的两个正交工具；
超级账号只在运维窗口用，日常对象 DDL 应下放到 `app_owner` 类角色（08 章迁移工具同样要求专用低权账号）。

### 5. Oracle → PG 管理面对译（为 08/09 章打底）

| Oracle 概念 | PG 对译 | 迁移注意 |
| --- | --- | --- |
| user（=schema，同一物） | role + schema 两个对象 | Ora2Pg 默认"每 schema 一角色"重建映射 ⚠️ |
| tablespace | tablespace（但只影响文件位置，不隔离权限） | 热冷分层动机 ≠ 权限动机 ⚠️ |
| DBA_TAB_PRIVS | information_schema / aclexplode(pg_class.relacl) | 审计脚本要重写 ⚠️ |
| profile（口令策略） | 角色属性 + passwordcheck | 资源限额改走连接数/池化 ⚠️ |
| CONNECT/RESOURCE 预置角色 | 无对偶，自建模板角色 | 组化设计放第一天 ⚠️ |

## 常见坑与判读

| 现象 | 第一判读 | 取证动作（⚠️ 转述） |
| --- | --- | --- |
| `permission denied for schema public`（升级到 15+/17） | public CREATE 默认权已收回 | 显式 GRANT 或迁到专用模式（推荐后者） |
| GRANT SELECT ON ALL TABLES 后新表仍不可见 | ALL TABLES 不溯未来 | 补 ALTER DEFAULT PRIVILEGES，并核对 FOR ROLE 是否建表者 |
| 迁移账号能连不能查 | 只授了表级忘 schema USAGE | USAGE 与对象权分开检查，两闸串联 |
| 生产出现"人人是超级用户" | 图省事后遗症 | 从 pg_member 图倒推角色组，逐步收权（07 章可查活跃度） |
| hba 加了规则不生效 | 顺序问题：前条 trust 先命中 | `pg_hba_file_rules` 视图 + 行号复盘 |
| 应用报 role does not exist 但 psql 里看得到 | 连错库：角色是集群级、库是会话级 | 核对连接串 dbname；角色全局存在的特性反证之 |

## 核心概念速览（中英对照）

1. **数据库硬隔离** — database boundary：跨库不可直查的命名空间墙，PG 与 Oracle 习惯的最大分野。
2. **模式** — schema：库内软隔离 + 对象所有权单元。
3. **搜索路径** — search_path：非限定名解析顺序，脚本安全要素。
4. **角色** — role：USER 的唯一本体，LOGIN 属性开关出"用户"。
5. **成员关系** — role membership：GRANT role TO role，INHERIT 决定是否自动生效。
6. **主机认证表** — pg_hba.conf：顺序敏感的认证规则栈。
7. **口令加密** — scram-sha-256：现行默认口令线，替代 md5。
8. **默认权限** — ALTER DEFAULT PRIVILEGES：对未来对象生效的授权模板。
9. **公共模式收紧** — public schema CREATE revocation：PG15+ 默认安全基线。
10. **行级安全** — RLS/policy：按谓词过滤可见行的表级开关。
11. **复制角色属性** — REPLICATION attribute：流复制/逻辑解码连接的前置权。
12. **连接限额** — CONNECTION LIMIT(role)：账号粒度并发闸门（池化前置）。
