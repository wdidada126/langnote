## 8.3 工作区 RBAC：角色矩阵与最小权限

✅ `azure/synapse-analytics/security/synapse-workspace-synapse-rbac` ⚠️ 转述：

- **控制面**（Azure RBAC）：管工作区资源本身（创建/删除/扩缩）；
- **数据面**（Synapse RBAC）：Studio 内角色（Synapse SQL Administrator / Artifact
  Contributor / Big Data Analyst…）管工件与数据操作；
- 平面交叉授权需两侧对齐——经典「能连不能发管道 / 能发管道不能删表」事故源 ⚠️。
- 配套：`security/synapse-workspace-synapse-rbac-roles`（角色清单）与
  `understand-what-role-you-need`（选型向导）为 toc 实抓 ✅（正文引用以已验 200 主页面为准）。

## 8.7 治理配方三例（⚠️ 按章题语义重构——本章无仓库代码旁证，如实声明）

   how-to-review-synapse-rbac-role-assignments 线）⚠️。

## 8.9 常见误区（⚠️ 编者归纳）

1. 「接了 Purview = 治理完成」——扫描覆盖、标签质量、策略执行三环缺一不可；
2. 只审数据面不审控制面（删工作区权限比删表更危险 ⚠️）；
3. 密钥轮换从未演练（事故时首验项 ⚠️）；
4. 血缘当装饰——不用于变更影响分析则无回报；
5. 把 Fabric 治理 API 与 Synapse 接线混为一谈（演进分岔，见下节 ⚠️）。
