## 2.1 Synapse 管道 = 内嵌的 ADF：一体两面的编排层

Synapse 工作室内的「集成」页签承载 Azure Data Factory 同款引擎 ⚠️（✅
`azure/synapse-analytics/synapse-notebook-activity` 等文档以 ADF 概念为底座；原
`overview-data-pipelines` 页已 404，登记缺口）。核心对象模型 ⚠️：

- **链接服务**（Link Service）：源/汇连接串 + 凭据（托管标识优先）；
- **数据集**（Dataset）：参数化的「文件表 + 位置」抽象；
- **活动**（Activity）：Copy（搬运）、Execute Notebook（05 章主场）、Execute T-SQL、数据流等；
- **触发器**（Trigger）：定时/事件（存储到达）驱动；
- **监控**：管道运行视图 ✅ `monitoring/how-to-monitor-pipeline-runs`。

「Robust（健壮）」的章题承诺落在：参数化 + 重试/依赖图 + 增量水位线三配方（⚠️ 重构口径）。

## 2.2 主配方：Copy 活动装载专用池

✅ `azure/synapse-analytics/quickstart-copy-activity-load-sql-pool` ⚠️ 转述：Copy 活动
对专用 SQL 池的落地下推 = 先写暂存（对象存储中转）再走 PolyBase/COPY 引擎——**不是逐行
INSERT**。调优旋钮 ⚠️：并行复制度（DFCU/并行度）、暂存账户同区部署、行数校验。
🔧E6 类比：直查外部 CSV 101.4ms vs 装载后查 115.2ms（DuckDB 实测，**非 Synapse**）——
管道把「装载成本」从查询侧搬到编排侧，换取查询侧的复用红利。

## 2.3 增量与幂等：passenger count 型配方

仓库文件夹「passenger count」⚠️ 推定为「按日/按键计数增量」示例（出租车客流数据贯穿
本书——与 ch3 的 NYCTripSmall.parquet 同源题材）。企业模式三件套 ⚠️ 编者归纳：

1. **水位线表**（last processed timestamp）+ 参数化窗口过滤；
2. **分区切换落地**：新数据进暂存表 → `ALTER TABLE SWITCH` 原子换入（01 章 1.6 幂等项）；
3. **失败重放**：活动级重试 + 幂等目标写入（先删分区后写）。

监控面 ✅ `monitor-synapse-analytics`：管道运行、活动实例、告警接 Azure Monitor ⚠️。

## 2.4 转换的四种落点（编排视角的「在哪里变换」）

| 落点 | 工具 | 何时用 ⚠️ |
| --- | --- | --- |
| 数据流（Mapping Data Flow） | ADF 可视化转换引擎（Spark 托管） | 无代码团队、行级映射 |
| Notebook 活动 | Spark/PySpark（2.5 节） | 复杂逻辑、复用笔记本 |
| 存储过程/T-SQL | 专用池内 CTAS/merge | 库内轻转换、01 章衔接 |
| 外部预处理 | Databricks/自建活动 | 已有资产迁移 |

本章配方重心（⚠️ 依文件夹名）在第二行：read csv with PySpark → load DataFrame →
write the external table——**管道只做编排，转换在 Spark 里做**。

## 2.6 健壮性检查单（编者归纳 ⚠️）

1. 凭据是否全部托管标识/密钥库化（无明文连接串）？✅ `security/synapse-workspace-synapse-rbac` 角色最小化；
2. 每个 Copy 是否有行数/校验和断言活动？
3. 触发器错峰了吗（DWU 供给与管道并发互相挤占，03 章）？
4. 管道参数能否一键重放历史窗口？
5. 监控告警阈值（失败率/时长漂移）接了吗 ✅ `monitoring/how-to-monitor-pipeline-runs`？

## 2.8 触发器与调度深配方（⚠️ 转述）

- **定时触发器**：cron 式窗口挂管道；错峰与 DWU 供给联动（03 章 3.2/2.6 检查项 3）⚠️；
- **存储事件触发器**：blob 到达即触发——落地「文件驱动增量」，注意乱序与重放幂等
  （2.3 三件套兜底）⚠️；
- **跳跃窗口（tumbling window）**：按事件时间切片，补数=改窗口参数重放（水位线表
  配合）⚠️；
- **依赖图**：活动间成功/失败/补数分支；子管道 `Execute Pipeline` 做复用单元 ⚠️
  （✅ toc 实抓 control-flow-execute-pipeline-activity 线，正文以已验页面为准）。

调度反模式三例 ⚠️ 编者归纳：①用「等待固定分钟」代替事件依赖（脆弱）；②单管道
塞全部转换（不可重放）；③监控只配失败不配「时长漂移」（迟到事故）；④参数写死在
活动里而非管道级变量（改窗口即改工件，版本管理失控）。

## 核心概念速览（中英对照）

- **Synapse 管道** — Synapse pipelines：ADF 引擎内嵌于工作区的编排层 ⚠️。
- **链接服务/数据集/活动/触发器** — Link service / Dataset / Activity / Trigger：对象模型四件套 ⚠️。
- **Copy 活动下推** — Copy activity with staging：经暂存的中转批量落地，非逐行插入 ⚠️（✅ quickstart-copy-activity-load-sql-pool）。
- **水位线增量** — Watermark incremental load：last-processed 时间戳驱动窗口 ⚠️ 编者归纳。
- **分区切换** — Partition SWITCH：暂存表原子换入的幂等姿势 ⚠️。
- **Notebook 活动** — Execute Notebook activity：管道调 Spark 笔记本的胶水 ✅ synapse-notebook-activity。
- **管道监控** — Pipeline runs monitoring：活动级状态与告警 ✅ monitoring/how-to-monitor-pipeline-runs。
- **托管标识凭据** — Managed identity credentials：无明文密钥的连接面 ⚠️（✅ security RBAC 页）。
