## 3.1 MPP 骨架：分布、计算节点与控制节点

✅ `azure/synapse-analytics/sql-data-warehouse/massively-parallel-processing-mpp-architecture`
⚠️ 转述：专用 SQL 池 = 控制节点（编译/协调，SQL Server 血统）+ 计算节点（分布数据 + 本地
执行）+ 共享存储层；一条查询被切成**分布式执行计划**下发各节点。T-SQL 方言与系统视图
（`sys.pdw_*` 家族）✅ `sql-data-warehouse-reference-tsql-system-views`——这正是与盘上
SQL Server 内核谱系册的概念桥（09 章辨析表）。

## 3.2 DWU 弹性供给：把「算力档位」当旋钮

- **DWU（Data Warehouse Units）**：专用池的算力计价单位，档位阶梯（100/200/400…）每档
  算力与费率近似倍增 ⚠️（原 DWU 专页 `what-is-a-data-warehouse-performance-dwu` 已 404，
  **缺口登记**；现行供给文档 ✅ `sql-data-warehouse-manage-compute-overview`）。
- **暂停/恢复与扩缩**：按秒计费、暂停即停表；扩缩为元数据操作 + 数据重分布（大池耗时
  非零 ⚠️）。
- 🔧**E1（非本书引擎行为）**：DuckDB `SET threads=1/2/4/8` 跑 20M 行分组聚合，
  103.3 → 57.0 → 27.1 → 16.7ms，1→8 仅 **6.2×**——「档位×2 速度×2」的理想阶梯在真实
  引擎上有扩展税（调度/倾斜/固定开销）；DWU 换算读法同理：**先测自己的查询形状再定档**。
- 🔧**E2 侧证**：并行不是唯一变量——同一数据 HASH 共置 join 34.2ms vs 跨片 shuffle
  73.8ms（SQLite 8 分片实测），**布局错误的代价大于档位不足**（非 Synapse 行为）。

## 3.3 分布键三选一：HASH / REPLICATE / ROUND_ROBIN

✅ `azure/synapse-analytics/sql-data-warehouse/sql-data-warehouse-tables-distribute` ⚠️ 转述：

| 分布 | 语义 | 典型误用 |
| --- | --- | --- |
| HASH(列) | 按哈希切片，join/聚合键共置 | 选低基数/倾斜列 → 热点节点 |
| REPLICATE | 每节点全量副本（小维表） | 大表复制 → 存储爆炸 |
| ROUND_ROBIN | 轮询均匀灌，默认值 | 事实表用它 → 一切 join 都 shuffle |

🔧**E2（主类比，非 Synapse）**：8 个 SQLite 分片模拟 60/40 混合 hash/round-robin 装载
400k 行；对 `dim.region='R0'` 的共置 join（hash 侧、维表按同键分片）34.2ms，而 round-robin
侧需跨片聚合再合并 73.8ms（**≈2.2× 差距，校验和一致**）——分布键=「join 的共置合同」。
倾斜体检 SQL ⚠️：`sys.dm_pdw_sql_distribution` / DBCC PDW_SHOWSPACEUSED（✅ tables-distribute
页内引用）。Distribution Advisor ✅ `sql/distribution-advisor` 从工作负载反推键位。

## 3.4 索引与分区：CCI 默认 + 两类补充

✅ `sql-data-warehouse-tables-index` ⚠️ 转述：默认 **CCI（聚集列存索引）**；非聚集索引/
列存储仅特殊场景补；HEAP 行存留给快速暂存。**分区** ✅ `sql-data-warehouse-tables-partition`：
RANGE 分区服务装载（SWITCH）与分区裁剪，**不是**查询加速的主武器（分布才是）⚠️。
🔧**E3（非 Synapse）**：8M 行窄区间谓词，k 有序 1.6ms vs 乱序 3.7ms——列存段 min/max
剪枝吃「装载即布局」红利（01 章 1.3 呼应）；CCI 段状态机见 01 章 1.5。

## 3.7 ServerlessSQLPool.SQL 对读：直读侧的最优处理

仓库代码 `ServerlessSQLPool.SQL` + `NYCTripSmall.parquet`（✅ 名实抓）⚠️ 推定配方：
服务器端点建外部表直读 Parquet（✅ `sql/on-demand-workspace-overview`、
`sql/develop-tables-external-tables`），要点：文件按查询键分区目录布局、列裁剪、
按处理字节数管控成本 ✅ `sql/data-processed`（扫描量=计费面的治理配方）。
🔧**E4（非 Synapse）**：5M 行 Parquet 84.6MB，只读 (k,v) 两列时元数据字节 60.0M（省 29%）
——列式文件「读多少列付多少钱」的直觉；谓词组剪枝本例为 0（区间未跨行组边界，如实登记），
说明**布局决定剪枝有没有戏**。

## 核心概念速览（中英对照）

- **MPP 架构** — Massively Parallel Processing：控制节点+计算节点+分布数据 ⚠️（✅ mpp-architecture）。
- **DWU** — Data Warehouse Units：算力档位与计费阶梯；专页 404 后以 manage-compute-overview 为准 ⚠️。
- **分布键** — Distribution key：HASH/REPLICATE/ROUND_ROBIN 三选一，join 共置合同 ⚠️（✅ tables-distribute）。
- **倾斜** — Skew：热点分布导致单节点过载；用 DMV/DBCC 体检 ⚠️。
- **CCI** — Clustered Columnstore Index：默认存储形态，段级 min/max 剪枝 ⚠️（✅ tables-index）。
- **RANGE 分区** — Partitioning：服务装载 SWITCH 与裁剪，非主加速手段 ⚠️（✅ tables-partition）。
- **统计手动更新** — UPDATE STATISTICS：大批量变更后的计划质量保险 ⚠️（✅ tables-statistics）。
- **工作负载分类/资源类** — Workload classification / resource classes：内存与并发的配额制 ⚠️（✅ 两页现行）。
- **并发硬限** — Concurrency limits：超限排队/拒绝而非仅变慢 ⚠️（✅ memory-concurrency-limits）。
- **服务器端点** — Serverless SQL pool：按扫描量计费的湖上直读 ⚠️（✅ on-demand-workspace-overview、data-processed）。
