# 03 · 配置高效环境（原书 Ch.3, pp.69-95）

> 章题 ✅ Crossref 实抓（DOI 10.1007/979-8-8688-1038-1_3, "Configuring an Efficient Environment"）。章内小节为本目录自拟重构 ⚠️。Oracle 行为一律 ⚠️ 转述 + 官方 URL 取证（白名单见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §二）；本章含 1 组 🔧 本机类比（非本书引擎行为）。

## 3.1 本章的性质：内存与参数的一章

"高效环境"在原书里 = **内存管理 + 初始化参数 + 资源约束**三件事：让实例把机器资源用满但不越界。它和 07（索引）、09（字典）共同构成"性能的地基层"——没有一层能靠 SQL 调优补救内存配错的账。

## 3.2 内存架构速览（⚠️ Concepts 口径，✅ cncpt 文档）

| 结构 | 装什么 | 配错的症状 |
|---|---|---|
| SGA-Buffer Cache | 数据块的热点缓存 | 全表扫描把大表"冲"出去，命中率崩 |
| SGA-Shared Pool | 游标/字典缓存/绑定信息 | 硬解析风暴、library cache lock 类等待 |
| SGA-Large/Java Pool | 并行消息、X$KGL 大件、JVM | 罕见，ORA-04031 语境 |
| SGA-Redo Log Buffer | 变更向量暂存 | 几乎不设，log switch 语境在 04 |
| PGA | 排序/哈希区/会话私有 | workarea 落盘，排序慢十倍 |
| UGA/会话语义 | 共享服务器下的会话态 | 连接模式相关（下） |

**自动化的三层**：`memory_target`（AMM，内存目标自管）→ `sga_target/pga_aggregate_target`（ASMM，组件间自调）→ 手动 `db_cache_size` 等（专业场景才回退）⚠️。23ai/Linux 上 AMM 依赖 /dev/shm 且官方对 hugepages 环境常推荐关 AMM 用 ASMM+巨页 ⚠️（社区共识，以安装文档内存节为准）。

## 3.3 参数体系：spfile、scope、家族

- `alter system set <p>=<v> scope=memory|spfile|both`：三类生效语义决定"重启后还在不在"；scope=spfile 的改动是**延迟炸弹**，登记变更单 ⚠️。
- 参数家族（本章讲解路径）：内存组（3.2）、`processes/sessions/open_cursors`（连接容量组）、`db_create_file_dest` 等 OMF 组（→04）、`undo_retention`（→04/12）、`optimizer_*` 组（→07/CBO 线，本册只开门不装修，深水区在盘上 [../Cost_Based_Oracle_Fundamentals/00-总览与阅读地图.md](../Cost_Based_Oracle_Fundamentals/00-总览与阅读地图.md)）。
- 查参三层：`v$parameter`（会话现值）/ `v$parameter2`（多值 RAC 语境）/ `v$spparameter`（spfile 侧）⚠️——"改了没生效"先分诊这三张视图（→09 章字典方法论）。
- **隐式参数**（underscore 开头）：Pro 册的态度是"知道存在、SR 指导下动" ⚠️，本目录同口径并加风险标注。

## 3.4 连接模式与会话容量

- 专用连接（dedicated）默认；共享服务器（shared server）+ 连接池（DRCP 用于 XA/应用服务器池）在高并发小会话场景省内存 ⚠️。
- `processes` 是硬上限：撑爆时新连接报 ORA-00018/00020 家族；`sessions` 派生计算；生产上"连接数告警"应先于报错 ⚠️——与 14 章自动化阈值呼应。
- 23ai 语境补注：JSON 文档式访问（→08 章 duality 视图）鼓励短事务多会话，池化与 `open_cursors` 余量比 11g 时代更重要 ⚠️ 推定。

## 3.5 资源管理与其他约束

- Resource Manager（`dbms_resource_manager`）：按消费者组分配 CPU/并行度/会话上限，Enterprise Edition 特性 ⚠️；云托管（Exadata IORM/ATP 自动管理）本质是它的产品化 ✅（ATP 文档线 adbsb）。
- 大页（hugepages）与锁定内存（`lock_sga`）：减少 TLB/换页抖动 ⚠️。
- `filesystemio_options=setall`/异步 I/O：Linux 上 I/O 路径的基础开关 ⚠️。
- DUCK/诊断类参数一律默认 ⚠️——环境章的铁律是"少动、动则留痕"。

## 3.6 🔧 本机类比：参数即行为——SQLite PRAGMA 对照（非本书引擎行为）

Oracle 的"spfile 持久参数 vs 会话级覆盖"二分，在 SQLite 有精确同构（`PRAGMA` 可会话级、可持久进文件头）。本机 Python 3.13.2 / sqlite 3.45.3 实跑：

```
$ python - <<'EOF'
import sqlite3
c = sqlite3.connect(':memory:')
print(c.execute('pragma cache_size').fetchone())      # 默认（负数=KB 计）
c.execute('pragma cache_size=-64000')                  # 会话级改 64MB
print(c.execute('pragma cache_size').fetchone())       # (-64000,)
print(c.execute('pragma journal_mode').fetchone())     # ('memory',) 内存库
EOF
(-2000,)
(-64000,)
('memory',)
```

对照点：`cache_size` ↔ `db_cache_size`（组件内存配额）、`journal_mode` ↔ 归档/UNDO 策略（04 章）、PRAGMA 会话级 ↔ `scope=memory`。**差异更要记**：SQLite 无后台进程/无共享池，参数是"单文件行为开关"，Oracle 参数是"多进程一致性协议"——类比止于命名与生效语义两层。演示非本书引擎行为。

## 3.7 高效环境的验收清单（⚠️ 转述整理）

1. 内存：`v$pgastat`/`v$sysmetric` 看自动调优是否"顶格"（over allocation count、缓存命中趋势）；
2. 参数：spfile 与会话值 diff（3.3 三层视图）、变更台账；
3. 连接：峰值 sessions/`processes` 占比告警线；
4. I/O：异步生效验证（OS 层 `iostat` 与 `v$iostat_function` 双口径）；
5. 基线留档：AWR/STATSPACK 快照起点——为 14 章"事后分析"储备对照物 ⚠️。

## 3.8 参数族速查（本章口径 ⚠️；语义细节以参考手册为准）

| 族 | 成员示意 | 一句话职责 | 误配高频症状 |
|---|---|---|---|
| 内存总闸 | memory_target / sga_target / pga_aggregate_target | AMM/ASMM 两模式三旋钮 | 与 hugepages 打架、超限 OOM |
| 组件地板 | db_cache_size / shared_pool_size（手动模式） | 自管失效时的兜底 | 地板过高饿死 PGA |
| 连接容量 | processes / sessions / transactions / open_cursors | 会话与游标三面墙 | ORA-00018/00020/01000 |
| 存储默认 | db_create_file_dest / db_recovery_file_dest(_size) | OMF 与 FRA 双巢（04 章） | 归档挤兑备份盘 |
| 回滚窗口 | undo_retention / db_flashback_retention_target | 一致性读与闪回预算（04/12 章） | ORA-01555、闪回不可用 |
| 优化器门 | optimizer_features_enable / 系列开关 | 行为版本锁（升级期神器） | 计划漂移归因困难 |
| I/O 路径 | filesystemio_options / disk_asyn_io | 异步/直写开关 | 高并发下伪慢 |
| 容器 | 建库子句与 common_user_prefix 等语境件（02/11 章） | CDB 形态决定件 | 建库时未选、事后重迁 |

读表纪律：**每族先问"自动管还是我管"，再谈具体值**；spfile 里同族参数只留一层，混层是事故温床 ⚠️。

## 3.9 环境章的"变更三件套"（⚠️ 管理立场）

1. **台账**：参数变更=旧值/新值/scope/生效窗/回滚语句/申请人六列，进配置仓（15 章 Fleet 目标值的私有云前身）；
2. **对照**：改前取 AWR 基线段（14 章），改后同窗对比——"感觉快了"不算数；
3. **回滚位**：spfile 备份（`create pfile from spfile` 双侧留档）；scope=spfile 的延迟项单独挂起跟踪，重启窗口排进日历 ⚠️。

三件套的云端等价物：ATP 把"变更"整体收归平台（auto-tuning 事件仅通知不留申请位，✅ adbsb），私有云保留全套——读本章时左右手各拿一张：操作清单（此处）与托管清单（云），知道每格"谁签"。

## 核心概念速览（中英对照）

- **SGA** — System Global Area：实例共享内存区（缓冲/共享池/redo 暂存）。
- **PGA** — Program Global Area：服务端进程私有内存（排序/哈希区）。
- **AMM / ASMM** — automatic memory/system global area management：memory_target 全自管 / sga+pga 双目标自管。
- **hugepages** — 大页内存：降低 TLB 与换页开销的 OS 协作配置。
- **spfile** — server parameter file：实例启动读入的持久参数文件。
- **scope** — parameter scope：memory/spfile/both 三态生效语义。
- **隐式参数** — hidden/underscore parameter：受支持协议约束的下划线参数。
- **dedicated server** — 专用连接：一会话一服务端进程默认模式。
- **shared server** — 共享服务器：多会话复用进程组的省内存模式。
- **DRCP** — Database Resident Connection Pooling：驻库连接池，XA 场景。
- **Resource Manager** — 资源管理器：消费者组级的 CPU/并行/会话配额。
- **open_cursors** — 会话游标上限：应用游标泄漏的第一道闸。
- **db_cache_size** — 缓冲缓存大小：ASMM 下可被自调，手动下是硬地板。

## 最新演进与工业实践

- **内存自管已是既成事实**：12c 起 IO 校准、19c 起自动大页辅助、23ai 延续 ⚠️——DBA 手工摆 SGA 组件的时代结束，留下的是"目标值合理性审查"。官方 Administration Guide（✅ admin/index.html）内存储章仍给全手工路径，用于答疑而非日常。
- **云上这章被托管**：ATP/Exadata 把内存/参数/资源管理全部代管（✅ adbsb 文档线：auto-tuning、IORM 内置），对应岗位技能转向"读云监控+审批变更" ⚠️ 通说；私有云大库仍需要本章全部肌肉记忆。
- **参数漂移治理**：工业实践把 spfile 纳入配置仓库（GitOps 式 diff 审查），与 15 章 Fleet 的"目标值 vs 实际值"对账同构 ⚠️ 趋势转述。
- **23ai 新参数面**：向量检索（✅ vldbg 文档线）与 JSON Relational Duality（✅ adjsn）引入的内存构件（向量索引近邻搜索的 workspace 语义）在 26ai 文档重排后参数名可能再变 ⚠️，引用官方"New Features Guide"而非本目录。
- **对照盘上**：本波兄弟《Mastering PostgreSQL Administration》《PostgreSQL 16 Cookbook》（盘上目录版：../Mastering_PostgreSQL_Administration/00-总览与阅读地图.md、../PostgreSQL_16_Administration_Cookbook/00-总览与阅读地图.md）的 shared_buffers/work_mem 章即 PG 版"环境章"，PG 无 AMM 等价物（无单一 memory_target），对比读能加深对 Oracle 自管边界的理解；MySQL 侧 buffer pool 动态调整语境见 ../Understanding_MySQL_Internals/00-总览与阅读地图.md。
