# 05 · 用户与基础安全（原书 Ch.6, pp.151-174）

> 章题 ✅ Crossref 实抓（DOI 10.1007/979-8-8688-1038-1_6, "Users and Basic Security"）。章内小节自拟 ⚠️，不代表原书划分。Oracle 行为一律 ⚠️ 转述；取证：Administration Guide 安全章（✅ https://docs.oracle.com/en/database/oracle/oracle-database/23/admin/index.html 内 Security 部分）、PL/SQL 包参考（✅ https://docs.oracle.com/en/database/oracle/oracle-database/23/arpls/index.html ）。

## 5.1 安全模型一览：从口令到合规

本章是"基础安全"四件套：**账户生命周期、权限授予姿势、口令与概要文件、审计留痕**。23ai 管理纵深的安全大头（VPD/FGAC、TDE 加密、DB Vault、Network Encryption）不在此册展开，原书以引用官方 Security Guide 收口 ⚠️——本目录同口径：给地图，不冒充纵深。

## 5.2 账户与公共角色：三组必须认识的默认对象

| 对象 | 性质 | 处置（⚠️ 通识） |
|---|---|---|
| SYS/SYSTEM | 内核账户，口令文件+OS 认证 | 口令严控，禁止应用使用 |
| **PUBLIC** | 隐式成员=所有用户的角色 | 收回其默认执行权是加固第一课 |
| 示例账户（HR/SCOTT 等） | DBCA 可选装入 | 生产必锁：`alter user ... account lock` |
| DBSNMP/OUTLN 等 | 组件代理账户 | 随组件生命周期，勿手删 |

23ai 默认创建即带口令复杂性策略收紧的倾向 ⚠️（DEFAULT profile 的口令验证函数历史多次调整，以官方参考手册 profile 节为准）；`account_lock` 与密码过期（`password_life_time`）是值班工单常客。

## 5.3 权限：系统权与对象权的分界

- **系统权限**（CREATE SESSION/CREATE TABLE/...）= 对"物种类"的动作权；**对象权限**（SELECT/UPDATE ON 某表）= 对"具体个体"的动作权；`with grant option`/`with admin option` 决定转授链 ⚠️。
- 角色是权限的打包与延迟激活层；`set role`/安全角色（`identified by ... `）做会话内开关 ⚠️。
- **最小权限路径**：应用账户只给 CREATE SESSION + 自有 schema 对象权 + 经审批的角色链；DBA 日常管理走"个人命名账户 + 角色"而非共享 sysdba——审计可归人 ⚠️。
- 代理认证/OS 认证（`os_authent_prefix`）与口令文件（01 章 orapw）：三种"你是谁"通道，生产建议 LDAP/钱包化收敛 ⚠️（Kerberos/Wallet 出本章深水区）。

## 5.4 Profile：口令策略的落地件

```sql
create profile app_dev limit
  password_life_time 60 password_reuse_max 5
  failed_login_attempts 5 password_lock_time 1/24
  sessions_per_user 5 idle_time 60;
alter user demo profile app_dev;
```

- 口令族（lifetime/reuse/verify_function）与资源族（sessions/idle_time/私有 SQLA 资源）同在一个 profile 机制下 ⚠️；`verify_function` 挂 PL/SQL 函数做自定义强度（数字符/字典词），复杂场景走内置 `ora_pwd_verify_11g` 风格函数 ⚠️。
- 注意：资源限制仅在企业版且需 `resource_limit=true` ⚠️——"profile 设了没生效"的第一排查位。

## 5.5 统一审计（Unified Auditing）基础

- 12c 引入、后续版本收敛的方向：**策略化**统一审计取代旧式 `audit table by access` 散件体系——`create audit policy ... actions ...; audit policy ...;` 三拍子 ⚠️；策略对象可含角色/用户/模式/系统权限组合。
- 落盘位置：统一审计 Trail 存于 SYS.AUD$（新架构下统一存储），查询走 `unified_audit_trail` 视图 ⚠️（→09 章字典视图族）。
- 默认策略（如 ORA$SECURITY_*/ORA$DATAPUMP_TRACE 类预置 ⚠️ 名称随版本变化）开箱即含，"零配置也有留痕"是 23ai 的合规起点。
- FGA（细粒度审计，`dbms_fga`）作为列级/条件级补强在本章尾部点名 ⚠️，深水区归 Security Guide。

## 5.6 容器视角的安全增项（PDB 时代必修）

- 本地用户 vs 公共用户：`create user c##app`（公共，跨容器）与普通本地用户（限本 PDB）——多租户下命名带 `c##` 前缀是公共用户的标志 ⚠️；本地用户让"每 PDB 自治管理"成立（→11 章）。
- **PDB 锁定（lockdown）**：锁定配置文件（lockdown profile/选项）限制 PDB 内可执行语句/可访问视图/角色系统权限——"租户内 DBA 也不能翻天"的机制 ⚠️（官方 Multitenant 安全节口径）。
- 口令文件按容器共享 vs 本地化（`common_user_prefix`、`db_create_file_dest` 语境）⚠️：建 CDB 时的选择影响之后所有克隆/插拔。

## 5.7 加固清单（⚠️ 本章操作性格的汇总）

1. 收 PUBLIC 危险执行权（utl_*、dbms_* 高危包）；
2. 锁示例账户、删不用的服务；
3. DEFAULT profile 加 verify_function；
4. 审计策略至少覆盖：登录失败、DDL、特权使用、datapump 导出；
5. 传输层：listener/TLS（Wallet）纳入部署模板（与 01 章静默安装合并交付）；
6. 每季度随 RU 检查安全公告（CPU 补丁即安全事件的根修，→16 章）。

## 5.9 加固 SQL 骨架（⚠️ 示意，执行前逐项评审）

```sql
-- 1) 收 PUBLIC 高危执行权(示例两件套, 清单按应用依赖裁剪)
revoke execute on utl_file from public;
revoke execute on dbms_scheduler from public;   -- 视组件依赖, 慎一刀切
-- 2) 示例账户三合一套
alter user hr account lock password expire;
-- 3) DEFAULT profile 挂强度函数(内置函数需先经 utlpwdmg 类脚本装载, 名称以文档为准)
alter profile default limit password_verify_function <verify_fn_name>;
-- 4) 统一审计三拍子: 特权使用+登录失败
create audit policy sec_priv_use privileges select any table, drop any table;
audit policy sec_priv_use;
create audit policy sec_login_failed whenever not successful login;
audit policy sec_login_failed;
-- 5) Trail 治理: 归档+防撑爆 SYSAUX(dbms_audit_mgmt 族, 名称以文档为准)
```

骨架的意义不在抄写：五条各对应 §5.7 清单一行，**清单→SQL→验收视图→回滚语句**四联才是 Pro 交付物 ⚠️。

## 自测（能默写=过关）

- 系统权限/对象权限/角色三层各举一例并说明转授语法差异。
- profile 资源族不生效的两个前提条件。
- 统一审计三拍子命令与旧式审计的架构差；c## 前缀的含义。

## 核心概念速览（中英对照）

- **系统权限** — system privilege：对某类资源的动作权，如 CREATE TABLE。
- **对象权限** — object privilege：对具体对象的权利，带 grant option 可转授。
- **角色** — role：权限打包与默认/条件激活层。
- **PUBLIC** — 隐式全员角色：默认权限收敛的首要靶点。
- **口令文件** — password file：orapw，远端特权认证依据（01 章同源）。
- **profile** — 概要文件：口令策略+资源限制的绑定单元。
- **verify_function** — 口令验证函数：自定义强度策略的 PL/SQL 挂点。
- **统一审计** — unified auditing：策略驱动、单一 Trail 的审计体系。
- **FGA** — fine-grained auditing：条件/列级细粒度审计（dbms_fga）。
- **公共用户** — common user：c## 前缀、存在于所有容器的账户。
- **PDB 锁定配置** — lockdown profile：限制 PDB 内语句/权限/视图的护栏。
- **OS 认证** — operating system authentication：os_authent_prefix 信任链登录。
- **最小权限** — least privilege：应用账户与个人管理账户分离的实践基线。

## 最新演进与工业实践

- **口令策略的世纪转折**：NIST SP 800-63B（核 ✅ https://doi.org/10.6028/NIST.SP.800-63B 于 Crossref，2026-09-27 200 通过）推动"长口令+低频强制更换+泄露口令筛查"取代"复杂度高轮换"——Oracle DEFAULT profile 与各托管平台正向此收敛 ⚠️；本册 5.4 的 60 天示例值应理解为旧范式残余。
- **23ai 默认更严**：新版本对默认账户与口令参数趋向 out-of-box 收紧（⚠️ 转述官方发布说明通说；逐参数差异需查 /23/ 参考手册，深链不可稳定命中，口径见 00 §2.4）。
- **审计上云与不可变 Trail**：ATP 把统一审计与对象存储侧的日志防篡改组合为合规产品（✅ adbsb 安全文档线）；工业侧 SIEM 直灌审计流成常态 ⚠️ 通说。
- **数据库安全的外扩**：数据发现/分类、列脱敏（dbms_redact）、TDE 密钥管理在企业市场是"基础安全"的自然下一站——本册止步处，官方 Security Guide 接手 ⚠️；盘上对照：跨引擎治理视角见 ../数据安全架构设计与实战.md（若需中文语境）。
- **同题互参**：PG 16 的角色继承/RLS 与 Oracle 的 VPD 对照见 ../PostgreSQL_16_Administration_Cookbook/00-总览与阅读地图.md；MySQL 侧鉴权插件与口令策略对照见 ../Understanding_MySQL_Internals/00-总览与阅读地图.md——三家在 PUBLIC 概念上仅 Oracle 有"全员隐式角色"怪癖，安全清单不可互相照抄。
