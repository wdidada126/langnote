# 04 · 表空间、数据文件与控制文件/重做日志/归档（原书 Ch.4+5 合并, pp.97-149）

> 合并声明：原书 Ch.4 "Tablespaces and Data Files"（✅ 10.1007/979-8-8688-1038-1_4, pp.97-117）与 Ch.5 "Managing Control Files, Online Redo Logs, and Archivelogs"（✅ …_5, pp.119-149）同属"物理存储层"，按 [00-总览与阅读地图.md](00-总览与阅读地图.md) §三口径合并为本文件。章内小节自拟 ⚠️；Oracle 行为一律 ⚠️ 转述；本章含 🔧 类比 2 组（非本书引擎行为）。

## 4.1 两层视图：逻辑容器与物理文件

Oracle 存储的独创性在**逻辑与物理彻底解耦**：

```
数据库(逻辑) → 表空间(逻辑) → 段/区/块(逻辑+物理交界)
                  ↑ 归属
        数据文件(物理, .dbf) → OS 文件/ASM 盘组(物理)
```

- 一个段跨多文件（同表空间内），一个文件只属一个表空间——"文件是表空间的实现细节" ⚠️。
- 对照：MySQL InnoDB 每表一文件/共享表空间两种、PG 的 tablespace→$PGDATA 布局、SQLite 一个文件就是一切——Oracle 的三层抽象是本章教学重心 ⚠️（对照盘上 ../Understanding_MySQL_Internals/00-总览与阅读地图.md、../PostgreSQL_16_Administration_Cookbook/00-总览与阅读地图.md）。

## 4.2 表空间家族（23ai 口径 ⚠️）

| 成员 | 职责 | 运维要点 |
|---|---|---|
| SYSTEM | 字典+引导 | 业务对象禁入；空间告警=高优先级 |
| SYSAUX | AWRE/统计/EM 等辅助 | 常为"意外的第一大表空间"，定期清 |
| UNDO | 回滚段仓库 | 大小=峰值未提交量×retention；ORA-01555/01598 语境 |
| TEMP | 排序/哈希/临时表 | 临时表空间组（RAC）；不产生持久 redo ⚠️ |
| USERS/业务 TS | 应用段 | 本地管理+自动段空间管理（LASM）为默认 ⚠️ |
| 只读/传输 TS | 数据发布/搬迁 | 传输表空间=秒级"文件搬家"（→16 章数据移动） |
| BIGFILE vs SMALLFILE | 单大文件 vs 多文件 | BIGFILE 配合 ASM/TB 级；不能 autoextend 多文件摊 |

操作面（⚠️ 示意）：`create tablespace ts1 datafile '+DATA' size 1G autoextend on maxsize 32G extent management local segment space management auto;`、`alter tablespace ... read only/read write`、`drop tablespace ... including contents and datafiles`——删表空间永远显式带 `and datafiles`，否则留孤儿文件 ⚠️。

## 4.3 空间问题三板斧（原书案例性格）

1. **表空间满**：`dba_free_space` 聚合视图定位；autoextend 是否已到 maxsize；碎片看区分布（LASM 下缓解）。
2. **高水位 HWM**：DELETE 不还空间给 OS，`alter table ... shrink space`（需行移动开启）或重建回收 ⚠️——深水区在盘上 [../Cost_Based_Oracle_Fundamentals/02-全表扫描.md](../Cost_Based_Oracle_Fundamentals/02-全表扫描.md)（HWM 与扫描代价）。
3. **误删找回**：DROP TABLE 进回收站（`flashback database to before drop`），`recyclebin` 视图查对象——但 SYSAUX 会被回收物撑大 ⚠️，purge 是收尾动作。

**🔧 类比①（非本书引擎行为）——"文件即容器"的反例与 UNDO 的最小语义**：SQLite 没有表空间，一个库文件承载一切；其"回滚段"是整页镜像（rollback journal）或 WAL 帧。本机 sqlite 3.45.3 实跑「事务中删光→回滚复原」：

```
$ python - <<'EOF'
import sqlite3
p1 = sqlite3.connect('pdb1.db')                 # 既有 3 行 emp 的库文件
p1.execute('pragma journal_mode=wal')           # ('wal',)：改 WAL 日志模式
p1.execute('begin')
p1.execute('delete from emp')
print(p1.execute('select count(*) from emp').fetchone())   # (0,) 自己可见已删
p1.execute('rollback')
print(p1.execute('select count(*) from emp').fetchone())   # (3,) 回滚=UNDO 生效
EOF
(0,)
(3,)
```

对照点：`begin/rollback` ↔ Oracle UNDO 表空间的回滚语义；WAL 文件（实跑中确认 `pdb1.db-wal/-shm` 生成）↔ redo+archive 的"顺序日志+检查点"家族。**差异**：SQLite 回滚是页镜像整体反向覆盖，Oracle 是逻辑 UNDO 记录+读一致性（同一数据可"回读旧版本"而无需撤销）——这个差异恰是 §4.5 一致性读的原点。演示于 D:\develops\tmp\dbwave_w4_ora23，非本书引擎行为。

## 4.4 控制文件：小体量、大权柄

- 内容：数据库物理结构的"目录之目录"——数据文件/redo 成员清单、checkpoint SCN、日志序列、RMAN 元数据（→12）⚠️。
- `CONTROL_FILE_RECORD_KEEP_TIME` 决定元数据保留轮转；多路镜像（`control_files` 参数逗号列表）是廉价的单点消除 ⚠️。
- 丢失全部控制文件：从自动备份恢复（12 章 `c-...` piece）或 `alter database backup controlfile to trace` 的重建脚本——**trace 备份是被低估的保险** ⚠️。
- `RESETLOGS` 后日志序列与 DBID/incarnation 分叉，备份链必须重启认知（→12 章交叉引用）⚠️。

## 4.5 Online redo 与归档：前滚日志的日常

- redo 组循环写：组内成员多路镜像，组间轮转；`log switch`（日志切换）触发检查点 ⚠️。
-  sizing 判据：每秒/每切换的 redo 生成率与"切换过频→检查点风暴/归档追赶"的平衡；AWR 的 redo 小节给数（→14）⚠️。
- **ARCHIVELOG 模式**：切换完成的组由 ARCH 进程续档为归档文件；`log_archive_dest_1` 指路径，归档策略（保留窗口/备份即删）在 12 章展开 ⚠️。不开归档=只能冷备+丢增量——生产不可接受。
- 归档爆盘是值班第一杀手：`db_recovery_file_dest_size` 上限撑满后实例挂起（"archive log full"等待）⚠️；处置是备份+`delete archivelog`（RMAN）而非 rm（会击穿备份一致性认知，12 章 `crosscheck` 语境）。
- Standby redo（Data Guard 前置）本章点到：日志对传输的镜像需求 ⚠️（深水区出本册范围）。

**🔧 类比②（非本书引擎行为）——快照隔离的"旧版本可读"**：Oracle UNDO 的核心红利是"别人回滚中/修改中，我仍读旧值"。SQLite(WAL) 的最小同构实跑：

```
$ python - <<'EOF'
import sqlite3
a = sqlite3.connect('iso.db', isolation_level=None)
a.executescript('pragma journal_mode=wal; create table t(v int); insert into t values(1);')
b = sqlite3.connect('iso.db', isolation_level=None)
b.execute('begin')
print(b.execute('select v from t').fetchone())   # (1,) 事务内首读定快照
a.execute('update t set v=2')                    # a 提交新值
print(b.execute('select v from t').fetchone())   # (1,) b 仍读旧快照
b.execute('commit')
print(b.execute('select v from t').fetchone())   # (2,) 新事务才见新值
EOF
(1,)
(1,)
(2,)
```

对照点：b 事务全程读到 1 ↔ Oracle 一致性读靠 UNDO 物化读快照。**差异**：SQLite WAL 读旧版靠日志文件里的旧帧、且默认不报 ORA-01555 类"快照过旧"错（UNDO 保留不足错在 Oracle 是运维事件）——保留策略一章（§4.2 UNDO sizing）因此在 SQLite 无对应物。非本书引擎行为。

## 4.6 OMF 与 ASM 一笔带过位

- OMF（`db_create_file_dest`）：让 CREATE 语句省略全路径，文件命名托管给引擎 ⚠️——云/Exadata 上 ASM 是"OMG 的工业形态"，本章只处理文件系统轨，ASM 口径归演进节。
- 数据文件改名/搬家：`alter database rename file`（挂载态）或 12 章 `recover datafile` 新路径——名字与位置的字典一致性是控制文件职责（§4.4）⚠️。

## 核心概念速览（中英对照）

- **表空间** — tablespace：段的逻辑容器，映射到零或更多数据文件。
- **数据文件** — datafile：表空间的物理实现，.dbf/ASM 对象。
- **区/段/块** — extent/segment/block：分配三层次；块是 I/O 原子。
- **UNDO 表空间** — undo tablespace：回滚与读一致性的版本仓库。
- **高水位线** — high-water mark：段内已格式化块边界，DELETE 不回落。
- **回收站** — recycle bin：DROP 对象的延迟清除区，flashback 依赖。
- **控制文件** — control file：物理结构与 SCN 进度的中枢元数据。
- **多路镜像** — multiplexed control/redo：同类成员多副本抗单点。
- **在线重做日志** — online redo log：循环写的前滚日志组。
- **日志切换** — log switch：写满一组翻下一组，触发检查点。
- **归档日志** — archivelog：切换完成 redo 的续档副本，Point-in-time 恢复原料。
- **闪回区** — fast recovery area：归档/备份/闪回日志的统一配额区。
- **OMF** — Oracle Managed Files：路径与命名托管的参数族。

## 最新演进与工业实践

- **ASM/AFD 成为默认物理层**：Linux 上 ASM Filter Driver/ASMFD 与简化配置工具链让"文件系统轨"退居小库与演练环境 ⚠️（官方 ASM 文档线，本册 /23/ 深链不可稳定命中，见 00 §2.4 口径）。
- **UNDO 的退场一角**：自动保留调优（`undo_adaptive_resampling` 等 19c+ 机制 ⚠️ 参数名以官方参考手册为准）+ 大事务告警常态化；PG 侧同题膨胀治理是工业热点（vacuum 语境，对照 ../Mastering_PostgreSQL_Administration/00-总览与阅读地图.md）。
- **存储快照协作**：企业阵列快照（snapclone）与 RMAN 集成的"备份卸载"叙事在 2024+ 白皮书活跃 ⚠️；纪律不变：快照不等于备份（控制文件/归档链一致性需校验，12 章）。
- **云对位**：ATP/Exadata 把本章全部操作面（建 TS、归档路径、空间回收）托管为自动策略（✅ adbsb 文档线 storage auto-management），DBA 侧新增的是"存储成本与保留窗口"治理项 ⚠️ 通说。
- **盘上延伸**：HWM/块密度的优化器视角在 [../Cost_Based_Oracle_Fundamentals/02-全表扫描.md](../Cost_Based_Oracle_Fundamentals/02-全表扫描.md)；redo/检查点等待事件诊断在 [../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md](../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md) 第 02-05 章；中文 12c 版同题操作细节见 ../Oracle12c数据库应用与开发/03-存储结构-表空间与段区块.md 与 04-事务与redo-undo-归档.md（12c 口径，注意与本册 23ai 差异 ⚠️）。
