## 7.1 索引族谱（管理视角：每种索引的"维护税"）

| 类型 | 场景 | 管理税 ⚠️ |
|---|---|---|
| B 树（默认） | 高基数点查/范围 | DML 维护、分裂/退化监控 |
| 反向键 reverse | 热点块（序列前导递增）争用 | 范围扫描失效；迁移期慎用 |
| 函数基 FBI | 大小写/表达式谓词、分区裁剪伴生 | 谓词必须文本级对齐（含隐式转换雷） |
| 位图 bitmap | DW 低基数列、并发读 | OLTP 禁忌（锁放大）；增量物化视图的依赖件 |
| 位图连接 BCJ | 星型模型维度列 | 同上加强版 |
| 域索引（Text/Oracle Text 等） | 全文/多媒体 | 异步/同步 ctx 后台维护窗口 |
| 聚类/临时/虚拟列索引 | 伴生件 | 随宿主对象生命周期 |
| **向量索引（23ai）** | VECTOR 列近邻检索 | 新形态，见 §7.5 与演进节 ⚠️ |

## 7.2 建与不建：本章的工程判断线

原书性格是"操作+反模式"：

- **该建**：外键子表连接列（6.4 锁雷的解）、高频窄范围谓词、唯一性业务承诺（唯一索引=约束的执行器）⚠️；
- **不该建**：低基数单列（性别列）、写了不读的"保险索引"（备份窗口与 DML 延迟的隐性税）、重复前导列的套娃索引（(A,B) 存在时单建 (A) 多为冗余）⚠️；
- **监控件**：`alter index ... monitoring usage` / `v$object_usage` 抓"没人用的索引"再 invisible→drop 两步走 ⚠️——删索引永远先隐身观察（可秒回滚的删除前仪式）。

**🔧 类比（非本书引擎行为）——统计如何翻转索引决策**：Oracle"有索引未必用"的根因是代价估算；SQLite 3.45.3 本机演示同构现象（20000 行、kind 两值其中 A 占 1%）：

```
$ python - <<'EOF'
import sqlite3
q = sqlite3.connect(':memory:')
q.execute("create table t(id integer primary key, kind text, pad text)")
q.executemany("insert into t(kind,pad) values(?,?)",
              [(('A' if i%100==0 else 'B'), 'x'*50) for i in range(20000)])
q.execute('create index ix_t_kind on t(kind)')
print(q.execute("explain query plan select * from t where kind='A'").fetchall())  # 无统计
q.execute('analyze')
print(q.execute('select tbl,idx,stat from sqlite_stat1').fetchall())
print(q.execute("explain query plan select * from t where kind='A'").fetchall())  # 有统计
print(q.execute("explain query plan select kind from t where kind='A'").fetchall())  # 覆盖
EOF
[(3, 0, 0, 'SCAN t')]
[('t', 'ix_t_kind', '20000 10000')]
[(3, 0, 0, 'SEARCH t USING INDEX ix_t_kind (kind=?)')]
[(2, 0, 0, 'SEARCH t USING COVERING INDEX ix_t_kind (kind=?)')]
```

三行输出对应三个 Oracle 概念：统计缺失时保守全扫（≈优化器对未分析表的默认画像）、`20000 10000` 即"行数+不同值数"≈Num_Rows/Num_Distinct_Values（选择度 1/10000 驱动翻转为索引扫，→09 章 DBMS_STATS 的 SQLite 极简版）、`COVERING INDEX` 即"索引自足免回表"≈Oracle 的 index-only 访问路径。**差异**：SQLite 无直方图/无绑定窥视，分布敏感决策它做不了——Oracle 侧对应物在 [../Cost_Based_Oracle_Fundamentals/07-直方图.md](../Cost_Based_Oracle_Fundamentals/07-直方图.md)。演示于 tmp/dbwave_w4_ora23，非本书引擎行为。

## 7.3 生命周期四操作（online 语义是本节核心 ⚠️）

1. **CREATE INDEX**：并行+NOLOGGING 提速（备份策略联动：NOLOGGING 产物在介质恢复中不可靠，建完补备份——12 章交叉义务）；`online` 选项让 DDL 不锁 DML（代价：日志与临时段开销）⚠️。
2. **REBUILD vs COALESCE**：重建换表空间/清退化（`update block location` 在线迁移期间）；合并只收叶块链表不动结构 ⚠️；"每周末无脑 rebuild 全部索引"是被官方反复劝退的都市传说 ⚠️。
3. **DROP**：连带唯一约束的索引删除会带走约束（`drop index` 对 constraint 的影响查询先行）⚠️。
4. **VISIBLE/INVISIBLE、MONITORING**：非破坏式试验田 ⚠️。

## 7.4 分区索引与全局索引命运表（承 6.3）

- 本地索引随分区维护自洽；全局索引在 drop/split/`move partition` 后可能 UNUSABLE，12c+ 的 `global indexes maintained during partition operations`（在线维护/异步维护）改写此规则 ⚠️；
- 排查口令：`dba_ind_partitions.status` / `dba_indexes.status`——UNUSABLE 的全局索引=潜在 P1（查询要么报错要么全扫）⚠️；
- 快速恢复：`recover index partition ... online` 类局部手段优先于全量 rebuild ⚠️。

## 7.5 向量索引：23ai 的索引新成员（⚠️ 转述 + ✅ 文档）

- 23ai 引入 `VECTOR(dim, datatype)` 列与距离函数（欧氏/余弦/点积族），配套**向量索引**做近似最近邻（IVF 风格分区+精排路径 ⚠️ 具体索引类型名以文档为准）✅ AI Vector Search Guide：https://docs.oracle.com/en/database/oracle/oracle-database/23/vldbg/index.html（2026 起 301 至 /26/）。
- 管理面增量：向量维度与模型对齐（换 embedding 模型=全列重算，管道进 16 章 Data Pump/自动化叙事）、近邻精度-延迟旋钮（epsilon/相似度截距/候选数）⚠️。
- 本节在全章的定位：族谱新行，运维方法论仍复用 7.2/7.3 的"先证使用、再谈结构"纪律。

## 7.8 索引取证 SQL 骨架（⚠️ 视图族名口径，列名自取 09 章方法）

```sql
-- 谁在用什么: 使用监视开三天, 读回判断
alter index ix_sales_cust monitoring usage;
select index_name, used, start_monitor_time from v$object_usage where index_name='IX_SALES_CUST';
-- 高/低立断: 每索引 DML 维护量与大小对账
select index_name, leaf_blocks, distinct_keys, clustering_factor, last_analysis
  from dba_indexes where table_name='SALES';          -- 09 章统计联动
-- 冗余发现: 前导列包含关系自连接(粗筛后人工终审)
select a.index_name redundant_on, b.index_name keeper
  from dba_ind_columns a join dba_ind_columns b
    on a.table_name=b.table_name and a.column_position=1 and b.column_position=1
   and a.index_name<>b.index_name and a.column_name=b.column_name;
-- 隐身试验田: invisible 先行, 计划回归无波再 drop
alter index ix_sales_cust invisible;   -- 回滚=visible, 秒级
```

骨架纪律：每个索引的去留决定都要有**取证行**（used 列/clustering_factor/冗余对）+**回滚位**（invisible/monitoring）+**验收**（AWR 段对比），三件套缺一按"未做"记 ⚠️。

## 7.9 反模式小剧场（⚠️ 社区高频复盘形）

1. 隐式转换杀 FBI：谓词写 `varchar_col=123`，函数索引建在 `to_number` 上——两头都对、中间不通（06 章类型纪律的连带案）；
2. 位图进 OLTP：一次 update 百行锁一片，"索引本身没错，引擎用错场合"；
3. 外键无索引的"删父表慢"：子表全扫+锁放大，DW 库迁 OLTP 常见病；
4. 每年"例行重建全部索引"：聚簇因子不变、退化有限、备份窗口+锁风险白付——09 章取证替代迷信；
5. 组合索引列序拍脑袋：等值列前置、范围列殿后、覆盖收益量化——顺序即代价（Lewis 册 04/05 章深读）。

## 核心概念速览（中英对照）

- **B 树索引** — B-tree index：默认均衡多路树，点查/范围通吃。
- **反向键索引** — reverse key index：叶块打散写热点，牺牲范围扫。
- **函数基索引** — function-based index：表达式求值物化，谓词对齐是生效前提。
- **位图索引** — bitmap index：低基数列的压缩位阵，OLTP 锁雷区。
- **覆盖索引** — covering/index-only path：索引含全部所需列免回表（🔧 实证于 SQLite 类比）。
- **聚簇因子** — clustering factor：索引→表映射的顺序度，index scan 代价主变量（Lewis 册 05 章深潜）。
- **invisible index** — 隐身索引：存在但优化器无视，删除前试验田。
- **online DDL** — 在线维护：DDL 期间 DML 不锁，以额外日志/临时段为价。
- **NOLOGGING** — 最小日志化：提速换介质恢复缺口，必须补备份。
- **monitoring usage** — 使用监视：v$object_usage 抓空转索引。
- **本地/全局分区索引** — local/global：分区维护命运的两种剧本。
- **向量索引** — vector index：VECTOR 列近似最近邻结构（23ai 新员，✅ vldbg）。
- **自动索引** — automatic indexing：DBMS_AUTO_INDEX 的自建自弃闭环。
