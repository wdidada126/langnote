# 09 · 数据字典基础（原书 Ch.10, pp.303-325）

> 章题 ✅ Crossref 实抓（DOI 10.1007/979-8-8688-1038-1_10, "Data Dictionary Fundamentals"）。章内小节自拟 ⚠️。Oracle 行为一律 ⚠️ 转述；取证：Concepts ✅ https://docs.oracle.com/en/database/oracle/oracle-database/23/cncpt/index.html 、PL/SQL 包参考（DBMS_STATS 族）✅ https://docs.oracle.com/en/database/oracle/oracle-database/23/arpls/index.html 。含 🔧 类比 2 组（非本书引擎行为）。

## 9.1 字典是什么：数据库的自述文件

- **定义**：数据字典=描述数据的数据的集合，物理上是 SYSTEM/SYSAUX 表空间里的基表（`obj$`/`tab$`/`col$`/`ind$` 一族，`bootstrap$` 引导），对外以**视图族**供读 ⚠️。
- **两类"元数据视图"的分野**（本章第一概念轴）：
  - 静态字典：结构快照（`dba_tables`、`dba_indexes`...），源于基表，随 DDL 变；
  - 动态性能视图（`v$`）：内存结构实时投影（`v$session`、`v$sql`...），实例级、重启清零、**多实例 RAC 下只反映本实例**（`gv$` 才全局）⚠️。
- 三级命名前缀语义（⚠️）：`USER_*`=当前 schema 可见、`ALL_*`=我有权限的、`DBA_*`=全库；容器化后加 `CDB_*`=跨容器版（带 `CON_ID` 列，→11 章联动）。

## 9.2 本章操作姿势：查字典的四堂功课

1. **找对层**：先定 USER/ALL/DBA/CDB 范围，再选对象视图——"权限决定视野"不是修辞是查询计划；
2. **读关联键**：字典视图以 `obj#`/`data_object_id` 互联，对象重建于 `alter ... move` 后 `data_object_id` 变（对象身份 vs 逻辑身份，12 章恢复语境的分水岭）⚠️；
3. **版本自觉**：列名/视图在 12c→23ai 间的增删是脚本兼容的头号杀手（`dba_hist` AWR 位图族列变化史），发布脚本先过目标版本字典 ⚠️；
4. **别碰基表**：`sys.` 下划线世界只读；诊断需求全部走视图+包出口 ⚠️（Pro 线纪律句）。

**🔧 类比①（非本书引擎行为）——字典=可查询的自述**：SQLite 的 `sqlite_master` 是单视图极简字典。本机 sqlite 3.45.3 实跑（承 07 章统计实验现场）：

```
$ python - <<'EOF'
import sqlite3
q = sqlite3.connect(':memory:')
q.execute('create table t(id integer primary key, kind text, pad text)')
q.execute('create index ix_t_kind on t(kind)'); q.execute('analyze')
print([r[0] for r in q.execute(
  "select name from sqlite_master where type in ('table','index')").fetchall()])
EOF
['t', 'ix_t_kind', 'sqlite_stat1']
```

对照点：`analyze` 生成的 `sqlite_stat1` 与表/索引同列表出现——Oracle 世界里统计信息不在 `dba_tables` 列里"混住"，而是独立 `dba_tab_statistics` 视图族；SQLite"字典即几个系统表"与 Oracle"基表+数千视图+固定表三层"是同一概念的两个量级。**差异**：SQLite 无权限分级视野（USER/DBA 之分不存在），也解释了 §9.2 功课 1 为何在轻量引擎无对应物。非本书引擎行为。

## 9.3 统计信息：字典章的第二主角

- **对象统计**：表（行数/块数/并行度）、列（NDV/空值/最小最大/密度）、**直方图**（频率/高度平衡/宽频 top-frequency/hybrid ⚠️ 家族史）——写入字典、供 CBO 取数；
- **系统统计**：CPU 速度/I/O 时延画像（`dba_aux_stat$` 族，NOWORKLOAD/WORKLOAD 两模式）⚠️；
- **收集工程**：`DBMS_STATS.GATHER_*` 家族——并行、estimate_percent、`METHOD_OPT FOR ALL COLUMNS SIZE AUTO`（默认入口）、级联列/索引统计、统计锁定与传输（`export/import` 统计——迁移调优的"随身画像"）⚠️；✅ 包参考：https://docs.oracle.com/en/database/oracle/oracle-database/23/arpls/index.html ；
- **自动维护任务**：夜间自动收集 job 与 stale 判定（`dba_autotask_*` 视图观察窗口）⚠️——Pro 立场：自动任务管地板，关键表手动管天花板；
- **计划稳定性配套**：SQL Plan Baseline/SQL Profile/补丁（优化器家族但与字典同层取证，`dba_sql_plan_baselines`）⚠️，深水区转盘上 [../Cost_Based_Oracle_Fundamentals/00-总览与阅读地图.md](../Cost_Based_Oracle_Fundamentals/00-总览与阅读地图.md) 与 [../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md](../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md)。

**🔧 类比②（非本书引擎行为）——information_schema 一脉**：DuckDB 1.5.5 的字典视图族近似"无权限分级的 DBA_ALL"：

```
$ python - <<'EOF'
import duckdb
d = duckdb.connect()
d.execute('create table emp(name text, dept int)')
print(d.execute("select table_name, column_name, data_type from duckdb_columns()
                 where table_name='emp'").fetchall())
print(d.execute('select count(*) from duckdb_tables()').fetchone())
EOF
[('emp', 'name', 'VARCHAR'), ('emp', 'dept', 'INTEGER')]
(1,)
```

对照点：`duckdb_columns()/duckdb_tables()` ↔ Oracle `dba_tab_columns/dba_tables`——"以 SQL 查结构"是 SQL 阵营的共同发明（ANSI INFORMATION_SCHEMA 的各家方言）；**差异**：DuckDB 无统计视图的用户入口（优化器统计为内部自动收集，无 DBMS_STATS 可对话面），Oracle 把统计做成**可管理对象**恰是本章存在的原因。非本书引擎行为。

## 9.4 字典的运维断面（本章"管理"落点 ⚠️）

- **SYSAUX 膨胀治理**：AWR 保留窗口、EM 上传残留、优化统计自动任务历史——`v$sysaux_occupants` 定位大头后按 occupant 各自 API 清理（删数据走包接口，禁 delete 基表）；
- **字典升级一致性**：RU/补丁后 `datapatch` 对齐字典层（→16 章），`dba_registry_sqlpatch` 为验收视图 ⚠️；
- **对象身份事件**：闪回版本查询（`versions between scn`）与逻辑一致性读都吃 UNDO——9.3 的统计、04 的 UNDO、本节的字典在"查询昨天的行"处三线合一 ⚠️；
- **对象定义的提取**：`DBMS_METADATA.GET_DDL` 取对象创建源码是"看对象真相"的第一命令，配合字典 trace 类事件用于深度取证（事件号不在此展开 ⚠️）⚠️：`dbms_metadata.get_ddl('TABLE','T1','HR')`；

## 9.6 字典三误区（⚠️ 社区高频）

1. **v$ = 字典**：v$ 是内存投影、多数不下盘、重启即失忆——历史取证靠 AWR 快照（14 章），别拿 v$ 当账本；
2. **DBA 前缀=特权**：DBA_* 只是视野档（查询者需相应字典查询权），安全边界在 05 章授权体系——只读账号也能查部分 DBA_ 视图，"视野≠权限"要分清；
3. **统计=真相**：统计是画像快照，采样率与收集窗决定失真方向（07 🔧 类比端可见"无统计→保守计划"）——计划异常先 `last_analyzed` 后 hint，顺序不可反 ⚠️。

## 核心概念速览（中英对照）

- **数据字典** — data dictionary：结构的自述基表+视图族，存于 SYSTEM/SYSAUX。
- **动态性能视图** — dynamic performance (V$) views：实例内存实时投影。
- **gv$** — global V$：RAC 全实例合并视图。
- **USER/ALL/DBA/CDB 前缀** — 视野四档：从本 schema 到跨容器的权限化视野。
- **对象统计** — object statistics：表/列/索引级画像（行数、NDV、直方图）。
- **系统统计** — system statistics：CPU/I/O 速度画像，代价模型的地基。
- **DBMS_STATS** — 统计包：收集/锁定/传输/删除统计的统一入口 ✅ arpls。
- **直方图** — histogram：列值分布分桶画像（height-balanced/top-frequency/hybrid）。
- **统计锁定/传输** — locking/transport：把画像钉死或随身搬运的调优术。
- **自动维护任务** — automatic tasks：夜间统计收集等调度框架（dba_autotask_*）。
- **DBMS_METADATA** — 对象定义提取：GET_DDL 看对象的"源码真相"。
- **SYSAUX 占用者** — occupants：AWR/EM/统计历史等同住租户，膨胀排查地图。
- **datapatch** — 字典补丁对齐器：RU 安装后字典层的收敛动作（→16）。

## 最新演进与工业实践

- **统计自动化加深（⚠️ 转述）**：19c→23ai 线自动收集更自适应（stale 阈值可调、列使用跟踪→直方图 AUTO 化）；官方持续劝退"手工统计当日常"，保留 export/锁定当逃生门 ✅（admin/arpls 文档线口径）。
- **字典视图的版本漂移**是跨库监控产品的头号兼容源：23ai 新对象（duality 视图、向量列、注解类）各自带来字典侧新视图/新列（✅ 族主页 /23/ 新特性文档线；逐视图名未实证，标 ⚠️），26ai 更名后列级差异需按目标版本重测 ⚠️——本目录 00 §2.4 白名单即为此设。
- **可观测性合流**：v$ 族 + AWR 之上叠 OS 指标，工业侧把 Oracle 导出进 Prometheus/Grafana（oracledb_exporter 类开源件 ⚠️ 通说），字典视图成为 SQL 侧"指标抓取端点"的事实标准。
- **元数据即产品**：治理层对"结构自述"的需求催生了目录/血缘生态——延伸读物盘上 [../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md](../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md)、[../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md)；字典章读者升级到治理视角时无需换语言，DBA_* 视图就是原始 API ⚠️ 本目录立场。
- **中文语境**：12c 时代同题章（含 dba_/v$ 操作案例）在 ../Oracle12c数据库应用与开发/00-总览与阅读地图.md 的 03/07 章有中文对照，可作本章术语的母语复训；理论线（字典/元数据在 DBMS 教材中的位阶）见 ../../db/db.md。
