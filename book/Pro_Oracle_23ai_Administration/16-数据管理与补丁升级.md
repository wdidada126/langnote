# 16 · 数据管理与补丁升级（原书 Ch.18, pp.557-580）

> 章题 ✅ Crossref 实抓（DOI 10.1007/979-8-8688-1038-1_18, "Data Management"，全书收束章）。章内小节自拟 ⚠️，主题范围按章题与前后章衔接重构（Data Pump/传输/补丁升级生命周期为公理件，GoldenGate 类复制仅点名 ⚠️）。Oracle 行为一律 ⚠️ 转述；取证：Database Upgrade Guide 族（深链口径 00 §2.4）、PL/SQL 包 ✅ https://docs.oracle.com/en/database/oracle/oracle-database/23/arpls/index.html 。

## 16.1 收束章的视角：数据与库的"移动性"

前 17 章管好"一个库的一生"，本章管"东西怎么进来/出去/换代"：

- **数据移动**：Data Pump（逻辑）、传输表空间/完全可传输（物理）、外部表（不动，13 章）；
- **版本移动**：RU 补丁与升级到 23ai 的工程化（AutoUpgrade/datapatch）；
- **两者交汇**：升级即"字典与代码换代+数据兼容性审计"——02/09/15 章在此合流。

## 16.2 Data Pump 双件套（expdp/impdp ⚠️ 操作主干）

- 服务器端作业（目录对象落 dmp+日志，13 章地基）：`expdp schemas=hr directory=dp dumpfile=hr_%U.dmp logfile=hr.log parallel=4` —— `%U` 多卷+并行是体量正解；
- 过滤与变形：`include/exclude/query`、`transform=segment_attributes:n`（对象落新 TS 的脱壳术）、`table_exists_action=append|replace|truncate`（重放语义）⚠️；
- **网络直导**：`impdp ... networks_link=tgt` 免落盘中转（15 章常规路线的引擎）；
- 一致性点：`flashback_scn` 参数=全作业读同一快照（04 章一致性读的搬运应用）⚠️；
- 数据泵的重活身份：迁移/整备/对象迁移（字典对齐后 `dba_objects` 审计，09 章）；**加密导出**（`encryption` 参数族）把"备份件=明文资产"的旧风险关进密码学 ⚠️（合规联动 05 章）。
- 排障：master 进程日志+`attach` 会话接管作业（`expdp attach=...` 看进度/改并行）⚠️。
- 作业对象化：expdp/impdp 即 Scheduler job（14 章框架托管）——进度、日志、重试、告警四件白得，手写 shell 循环包 expdp 属于重复造轮子 ⚠️。

## 16.3 物理传输与"整库搬家"谱（承 13/15 章 ⚠️）

- 表空间传输：关闭-拷贝-插入三部曲+字节序转换（`dbms_file_transfer` 走 ASM/远端）；跨平台矩阵是可行性第一关（官方支持表，⚠️ 文档域）；
- 完全可传输=Data Pump 元数据层+物理层的合体（15.3 剧本的展开）；
- 与 12 章的契约：传输落位后**备份链语境复位**（新 PDB 纳入保留政策、`resetlogs` 分叉知情）；
- 快照/克隆件（Clonedb/PDB 热克）在开发测试环境的批量化 = "数据供给（data provisioning）"话题——湖仓与数据库共同的新前线 ⚠️ 通说。

## 16.4 补丁与升级的生命周期工程（本章管理纵深位 ⚠️）

- **补丁层**：RU（季度、累积）+ 一次性（one-off）补丁；工具：`opatch`/`opatchauto`（GI 栈自动化）、`datapatch`（字典层对齐——装 RU 后必跑/必查，`dba_registry_sqlpatch` 验收，09 章伏笔收线）；回滚=datapatch 反向+`opatch rollback`；RAC 滚动最小停机（15.4 Fleet 编排的消费对象）；
- **升级层**：**AutoUpgrade**（Java 单件工具：analyze→fixes→upgrade→dictionary 流水线，config 文件声明式批处理多库 ⚠️ 取代 DBUA 手工时代）；升级前检查面：废弃参数/特性审计（官方升级前检查报告族，条目名以 Upgrade Guide 为准 ⚠️）、统计保留（09 章 transport 把画像带上新车）、SQL 计划基线重演进（SPM 升级语境：旧计划失效窗口的性能回退防护 ⚠️）；
- **回退设计**：升级前 guaranteed restore point（闪回承诺点，04/12 章件）+"失败即 `flashback database to restore point`+重跑"剧本——Pro 册反复强调的"可逆工程" ⚠️；
- 23ai 特有审计：新类型/新默认（06 章 BOOLEAN/JSON）与旧应用兼容回归（列名冲突、驱动版本），升级=软件事件+数据契约事件两案并列 ⚠️。

## 16.5 复制与同步点名位（⚠️ 边界声明）

## 16.7 Data Pump 参数速查（⚠️ 高频 12 事，全量以 expdp/impdp parfile 帮助为准）

| 参数 | 一句话 | 常配/常坑 |
|---|---|---|
| full / schemas / tables | 作用域三档 | 表级导出丢依赖(授权/索引拆分) |
| directory + dumpfile=%U | 落盘与多卷 | 目录两把锁(13 章) |
| parallel=N | 主进程外worker | N>文件数/盘数则空转 |
| logfile | 作业台账 | 归档进变更单 |
| content=ALL/DATA_ONLY/METADATA_ONLY | 数据/定义分相 | 结构先行+数据后补的装载节奏 |
| exclude/include=statistics | 统计随行与否 | 迁移后计划稳态建议统计单传(09 章) |
| remap_schema / remap_tablespace | 落位变形 | 权限链重验(05 章) |
| transform=segment_attributes:n | 剥存储属性 | 与默认 TS 策略配合(04 章) |
| table_exists_action | 目标已存在语义 | truncate 前备份目标 |
| network_link | 过网直导 | 大对象走此路慎(10 章) |
| flashback_scn | 一致性点 | 与 UNDO 窗口联动(04 章) |
| encryption + key | 密文导出件 | 密钥托管别学"邮件传口令"(05 章) |

## 16.8 一次 RU 的标准时序（⚠️ 编排形，15.4 Fleet 为并行调度层）

1. **T-7**：读 RU release notes + one-off 冲突清单；opatch lsinventory 双侧（DB/GI HOME）留档；datapatch 相关数据库组件预查（`dba_registry_sqlpatch` 现状表）；
2. **T-1**：备份基线（12 章：level0+控制文件件）；guaranteed restore point（可选但推荐）；变更窗口通知；
3. **T0**：停层（应用摘流→监听下线→实例关停）→ `opatchauto` 或手工 roll 序（shutdown→patch→startup）→ 多实例走滚动（先 NODE1 后备 NODE2）；
4. **T+**：`datapatch -verbose`（字典对齐）→ `dba_registry_sqlpatch` 验收 → 失效对象重编译观察（`utlrp.sql` 并行度择窗）；
5. **T+1**：回退位保留至验收期满（rp 不删、旧 HOME 不卸）；漂移登记回 Fleet（15.4）⚠️。

时序的每个"留档/验收/回退位"都是审计件——**补丁的正确产物不是"打上了"，是"可证明打上且可退回"** ⚠️ 本目录立场。

## 16.9 数据移动的选型一问（本章收束形）

```
要多大粒度?   行级→应用/复制流(16.5) | 表级→DP tables | schema→DP | 库级→FTS/插拔(15 章)
```

## 核心概念速览（中英对照）

- **Data Pump** — 服务器端逻辑搬运工：expdp/impdp 作业体系与目录对象依赖。
- **网络直导** — network link import：免 dmp 落盘的跨库过网搬运。
- **transform** — 导出变形：剥存储属性/改对象形态的参数族。
- **table_exists_action** — 重放语义：append/replace/truncate 策略开关。
- **flashback_scn** — 一致性导出点：整个作业读同一 SCN 快照（04 章应用）。
- **传输表空间** — transportable tablespace：文件级跨库/跨平台搬家。
- **完全可传输** — full transportable：元数据+物理文件的整库换代搬运。
- **Release Update** — 季度累积补丁：RU/one-off 两层补丁谱系（01 章呼应）。
- **datapatch** — 字典补丁器：补丁安装后字典/代码层对齐与回滚。
- **AutoUpgrade** — 声明式升级流水线：analyze/fixes/deploy 模式族。
- **guaranteed restore point** — 保底还原点：闪回承诺的升级保险丝。
- **SPM 重演进** — 基线换代：升级后计划稳定性的防护窗。
- **数据供给** — data provisioning：克隆/快照批量开环境的开发侧流水线。

## 最新演进与工业实践

- **发布模型 2024→2026**：23ai（LTS）→ 26ai 更名与文档路径重排（✅ 00 §2.4 重定向实证；社区旁证 itpub 2026-01《Oracle AI Database 26ai 替代 23ai》一文 ⚠️ 媒体口径）——升级章知识的使用保质期反而变短：**方法（预检/回退/datapatch 语义）比版本号耐用** ⚠️ 本目录立场。
- **补丁自动化前移**：云托管（ATP）把 RU 变成"平台日历事件+用户审批位"（✅ adbsb 维护窗口文档线）；私有云侧 Fleet+黄金镜像（15 章）把 opatchauto 包进 CI/CD——本章手工命令的幸存场景集中在审计驱动的"可回溯变更窗口" ⚠️ 通说。
- **Data Pump 的当代角色**：K8s/容器化交付里 dmp 文件仍是"数据库形态的容器镜像"；与逻辑复制/流式管道（CDC 生态，盘上 [../Streaming_Systems/00-总览与阅读地图.md](../Streaming_Systems/00-总览与阅读地图.md) 的变更流视角）分工为"一次性大迁移 vs 常态同步" ⚠️。
- **升级×AI 负载**：23ai 引入的向量/JSON 对象使"升级检查"新增维度（驱动/JDBC/ORDS 版本矩阵、向量索引重建预算）✅（vldbg/adjsn 文档线，细节 ⚠️ 转述）；生产升级回归集应含 duality 映射与向量查询的 smoke 用例——18 章收束后 8 章的合流在此。
- **中文谱系收口**：12c 时代中文同题（Data Pump/升级）在 ../Oracle12c数据库应用与开发/12-备份恢复容灾与DataGuard.md 与 14-12c及以后的演进.md；本册与其差异一句话——那边写"12c 新增了什么"，这边写"23ai 里什么是既成事实" ⚠️ 谱系声明见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §四。
