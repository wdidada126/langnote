# 13 · 外部表（原书 Ch.15, pp.459-486）

> 章题 ✅ Crossref 实抓（DOI 10.1007/979-8-8688-1038-1_15, "External Tables"）。章内小节自拟 ⚠️。Oracle 行为一律 ⚠️ 转述；取证：Administration ✅ https://docs.oracle.com/en/database/oracle/oracle-database/23/admin/index.html （外部表节）、SQL 参考语言 ✅ 族主页 …/23/ （深链口径见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §2.4）。含 🔧 类比 1 组（非本书引擎行为）。

## 13.1 概念：表是协议，不是仓库

外部表=**"用 SQL 读文件"的声明**：目录对象+文件+访问驱动+列映射协议，查询时把字节流物化成行——数据不动、计算上门，ETL 的"抽"变成"读" ⚠️。家族：

| 驱动 | 吃的是什么 | 性格 |
|---|---|---|
| ORACLE_LOADER | 定界/定宽文本（.dat+控制文件） | 传统 ETL 入口，类型容错多 |
| ORACLE_DATAPUMP | 别的 Oracle 导出的 dp 文件 | 高速、跨库搬运的"铁路宽轨" |
| ORACLE_HDFS/ORACLE_HIVE | 大数据栈文件/元数据 | 湖仓接口（本册点到，盘上 bigdata/ 有主场）|
| SODA/JSON 外部源、OCS 对象存储驱动 | 云对象存储/JSON | 23ai 时代的"文件"=URL+凭据 ⚠️ |

## 13.2 三件套语法骨架（⚠️ 示意）

```sql
create directory ext_dir as '/u01/etl/in';        -- 1. 目录对象(名字→OS路径, 权限实体)
grant read on directory ext_dir to etl_user;      --    注意: OS 侧可读是前提(01 章权限)
create table sales_xt (
  id number, region varchar2(20), amount number
) organization external (
  type oracle_loader
  default directory ext_dir
  access parameters ( records delimited by newline
                     fields terminated by ','
                     missing field values are null )
  location ('sales.csv')                           -- 2. 文件清单(可通配/多件)
);
select /*+ parallel 4 */ count(*) from sales_xt;  -- 3. 查询即装载, 可并行分片读
```

要点：**坏行策略**（`reject limit`/`access parameters` 的 bad 文件、`truncate option`）、`preprocessor`（gzip 解压钩子，OS 可执行体注册进目录对象 ⚠️）、文件列表的静态性（新文件要 `alter table ... location` 追加——自动化脚本的正经活 ⚠️）。

**🔧 类比（非本书引擎行为）——"读函数即外部表"**：DuckDB 把外部表做成一等公民且零声明成本。本机 DuckDB 1.5.5 实跑：

```
$ python - <<'EOF'
import duckdb
open('ext.csv','w').write('id;name\n1;ann\n2;bob\n')
d = duckdb.connect()
print(d.execute("select count(*), min(id) from read_csv('ext.csv', sep=';')").fetchall())
EOF
[(2, 1)]
```

对照点：`read_csv(...)` ↔ `organization external`（文件→关系代数视图）；列推断自动发生 ↔ Oracle 需在列定义+控制文件里手工对齐（协议显式度差异）。**差异**：Oracle 外部表是**持久对象**（进 09 章字典、有权限体系、可被任何会话复用），DuckDB 表函数是查询局部的；Oracle 的并行分片/坏行账本/预处理钩子这套生产件在类比端全缺——"声明一次、治理复用"才是外部表章的管理学。演示于 tmp/dbwave_w4_ora23，非本书引擎行为。

## 13.3 性能与并行的真实账（⚠️）

- 无索引、无统计默认值 → 谓词全文件扫：大文件裁剪靠**分区+exchange**（13.4）与文件分片（location 多件并行读，Granule/IO 并行）⚠️；
- 列映射与类型转换在扫描器内完成：控制文件的精度/日期图（`date_format ... "mask"`）写错=静默 NULL 或坏行堆积 ⚠️——装载验收要数 reject；
- `dba_tables` 的 EXTERNAL 标记与统计收集（外部表可有统计——对 CBO 的行为像普通表 ⚠️，09 章联动）。

## 13.4 交换装载：外部表的杀手应用（⚠️ 与 06 章合流）

`insert /*+ append */ into t select ... from sales_xt`（简单快装载）之外的大招是**分区交换**：

1. 目标按月分区表，新建空分区或用 `exchange partition`；
2. `alter table t exchange partition p202501 with table sales_xt including indexes`——秒级把"文件"变成"分区"（数据实际仍是文件？否：exchange 时 ORACLE_LOADER 外部表不允许交换，**DATAPUMP 外部表才可行**⚠️ 关键约束）；
3. 装载窗口从小时级缩到语句级，回滚=再换回来。

配套陷阱清单（⚠️ 原书性格）：字符集不匹配（NLS_LANG 三方对表）、换行符（Windows CRLF）、目录对象权限与 OS 权限"两把锁"、preprocessor 安全审计（可执行体=新攻击面）、并行度与文件数不匹配（空转通道）。

## 13.5 外部表在 23ai 栈里的位阶（⚠️ 转述+观点）

- 与 **JSON Relational Duality/原生 JSON**（06/08 章）：文档装载可走外部表 JSON 驱动，也可直插 JSON 列——前者批量治理友好，后者事务友好；
- 与 **DBMS_CLOUD/object store**（10 章演进）：文件从目录路径升格为 https URI+凭据对象，本章"目录对象"课变成"密钥/ACL"课 ⚠️；
- 与 **湖仓表格式**（盘上 Iceberg/Delta/Paimon 三目录版）：外部表是"库读文件"，表格式是"引擎读账本"——本册读者理解后者只需再加一层"元数据账本"概念 ⚠️ 本目录立场。

## 13.7 loader 控制文件小课（ORACLE_LOADER 的"方言"层 ⚠️ 示意）

外部表列定义之外的读取协议写在 `access parameters` 里，骨架：

```
access parameters (
  records delimited by newline          -- 行形: 换行/自定义串/定宽均可
  badfile ext_dir:'sales_xt.bad'        -- 坏行落盘, 与 reject limit 联动
  logfile ext_dir:'sales_xt.log'
  fields terminated by "," optionally enclosed by '"' missing field values are null
  ( id, region, amount, loaded_ts date "yyyy-mm-dd\"T\"hh24:mi:ss" default null
    char(32) )
)
```

要点四条：**列序=文件列序**（错位是外部表第一冤案，按位不按名）；**日期 mask 精确到分隔符**（差一字符全列转坏行）；`default null` 容缺列；定宽文件用 `(start_position:end_position type)` 三元组替代分隔符 ⚠️。

排账三件：**bad 文件行数**（装载质量 KPI 原始数据）、**reject limit 触发史**、**目录两侧权限**（两把锁的 OS 半把最常被忘）——验收脚本以三件为断言源 ⚠️。

## 13.8 文件清单自动化骨架（承 14 章例行化）

外部表 `location` 是静态列表，日增文件的常规解两式：

1. **视图化通配**：location 用 `'sales_*.csv'`（驱动支持的通配形）+ 定期 `alter table ... location` 重指；
2. **装载器生成 DDL**：shell/PLSQL 扫目录拼出最新文件清单，`alter` 或重建外部表语句由 14 章作业触发——"文件到、清单到、权限到"三连进同一作业体 ⚠️。

**分区外挂形态**：每日一个"当日外部表"+ 视图 union 或按日 exchange——把静态性转化为分区管理的例行件（13.4/06 章的合流点）。

## 核心概念速览（中英对照）

- **外部表** — external table：数据驻留文件、以表接口暴露的持久对象。
- **目录对象** — directory object：OS 路径的库内命名与授权实体。
- **访问驱动** — access driver：ORACLE_LOADER/DATAPUMP/HDFS 等解码插件。
- **控制文件** — access parameters：定界/类型/日期图的读取协议。
- **坏行限额** — reject limit：容忍脏数据的熔断阈值。
- **预处理钩子** — preprocessor：读前解压/转换的可执行体挂点。
- **分区交换** — exchange partition：文件/表与分区秒级互换的装载术。
- **append 直载** — direct-path insert：绕过缓冲池的批量写通道。
- **并行读** — parallel query on XT：文件分片×通道数的扫描扩展。
- **对象存储外部表** — OCS/dcs 驱动：以 URI+凭据为"文件"的云形态 ⚠️。
- **统计可见性** — XT 统计：外部表亦可有画像参与 CBO 决策 ⚠️。
- **两把锁** — 目录授权+OS 权限：外部表读成败的最小与条件。

## 最新演进与工业实践

- **文件→对象存储→表格式的三段迁移**：2024+ 新增装载管道大量绕开"OS 目录外部表"，直上云对象存储与开放表格式；Oracle 侧对应进化是 DBMS_CLOUD/对象存储驱动与自动压缩/清单管理（✅ 包参考线 arpls 含 DBMS_CLOUD 族 ⚠️ 细节转述）——本章的协议学仍是这些产品的底座语法。
- **零 ETL 叙事对撞（盘上）**：湖仓三目录版（[../Apache_Iceberg活用入門/00-总览与阅读地图.md](../Apache_Iceberg活用入門/00-总览与阅读地图.md)、[../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md](../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md)、[../Apache_Paimon_Streaming_Lakehouse/00-总览与阅读地图.md](../Apache_Paimon_Streaming_Lakehouse/00-总览与阅读地图.md)）与 bigdata/ 目录的"表即视图"路线，与外部表"表即文件协议"是同一哲学两代实现；DuckDB 生态（[../DuckDB_in_Action/00-总览与阅读地图.md](../DuckDB_in_Action/00-总览与阅读地图.md)）把 read_csv/parquet 做成默认工作流，可作本章的轻量对照实验室。
- **数据质量前置**：装载即校验（外部表 reject 账本+`merge` 幂等装载+对账 SQL）在金融/电信 ETL 规范中是硬条款 ⚠️ 通说；"坏行零容忍"与"限额放行"的策略选择写进 SLO。
- **安全侧**：preprocessor 与目录可达性进入主机加固清单（14 章自动化与 05 章权限的交叉项）；对象存储凭据用 Wallet/密钥保管服务收敛 ⚠️（钱包机制同 05 章）。
