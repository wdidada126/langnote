# 02 · 创建数据库（原书 Ch.2, pp.29-67）

> 章题 ✅ Crossref 实抓（DOI 10.1007/979-8-8688-1038-1_2, "Creating a Database"）。章内小节为本目录自拟重构 ⚠️。Oracle 行为一律 ⚠️ 转述；官方取证：Administration Guide ✅ https://docs.oracle.com/en/database/oracle/oracle-database/23/admin/index.html 、Concepts ✅ …/23/cncpt/index.html（/23/ 路径 2026 起 301 至 /26/，见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §2.4）。

## 2.1 建库 = 三件物的合成

23ai 语境下"CREATE DATABASE"一条语句背后是三层产物：

| 层 | 产物 | 校验位 |
|---|---|---|
| 实例 | SGA+后台进程（NOMOUNT 前的 RAM/进程结构） | `v$instance` |
| 控制 | 控制文件（数据库的"目录之目录"） | 04 章 |
| 物理 | 数据文件/redo 组/字典对象 | `v$datafile`、字典脚本 |

建库顺序：STARTUP NOMOUNT（吃 spfile）→ CREATE DATABASE（写控制文件、开 seed 数据文件、跑字典）→ 脚本收尾（catalog/catproc）⚠️。本章原书占 39 页，重心在"每一层坏了怎么办"的前置认知。

## 2.2 DBCA 与脚本化两轨

- **DBCA（Database Configuration Assistant）**：图形/静默双模。静默模板 `dbca -silent -createDatabase -templateName xxx.dbt ...` 把建库固化为可审计的文本 ⚠️——Pro 线立场与 01 章响应文件一致：**能模板化的一律不留向导手点**。
- **裸 SQL 建库**：手写 CREATE DATABASE 子句（数据文件清单、redo 大小、字符集、UNDO 表空间、MAXDATAFILES 等），价值在理解 DBCA 替你做了什么，以及灾难时手工重建控制文件（→04 章 `RESETLOGS` 语境）。
- 23ai 的 Free/标准安装默认走 CDB 架构：一个 root 容器（CDB$ROOT）+ 种子 PDB$SEED + 至少一个业务 PDB ⚠️——非 CDB 轨道在 23ai 已停止前进（12c 时代双轨、19c 收敛、23ai 事实上单轨；详 11 章）。

## 2.3 建库时的不可逆决策清单

| 决策 | 为什么几乎不可逆 | 23ai 默认/建议（⚠️） |
|---|---|---|
| 字符集 | 全库重转是高危工程 | AL32UTF8 唯一体面答案 |
| 国家字符集 | 影响 NVARCHAR/NCLOB | AL16UTF16 |
| 块大小 | 缓存与空间管理基座，建后难换 | 8K 起步；特殊表空间可异块 |
| 多租户 or 非 | 迁移=整库工程（→15 章） | 多租户（CDB/PDB） |
| UNDO 表空间 sizing | 长查询/闪回窗口约束 | AUTO，按峰值事务量放大 |
| redo 组数/大小 | 决定切换频率与检查点行为 | 按峰值 redo 生成率，避免 log switch 风暴 |
| 归档模式 | 决定备份策略上限（→04/12 章） | 生产必 ARCHIVELOG |
| 口令/审计基线 | 事后再紧等于裸奔期无解 | 见 05 章 profile 与统一审计 |

## 2.4 字典脚本收尾与种子内容

`catalog.sql/catproc.sql` 传统两件套在版本化打包下已并入统一并行脚本（`@?/rdbms/admin/catctl.sql` 类入口，⚠️ 具体文件名各 RU 有变，以 SQL*Plus 启动时的推荐脚本为准）；DBCA 建的库默认已含。PDB$SEED 的作用：此后每个 `CREATE PLUGGABLE DATABASE` 从这里复制字典层 ⚠️——种子不干净，全家 PDB 都不干净（→11 章）。

## 2.5 示例路径（⚠️ 示意语法，非实测）

```sql
create database cdb1
  user sys identified by "***"
  controlfile reuse
  maxloghistory 512
  logfile group 1 ('/u01/oradata/cdb1/redo01.log') size 512M,
          group 2 ('/u01/oradata/cdb1/redo02.log') size 512M,
          group 3 ('/u01/oradata/cdb1/redo03.log') size 512M
  datafile '/u01/oradata/cdb1/system01.dbf' size 800M autoextend on
  sysaux datafile '/u01/oradata/cdb1/sysaux01.dbf' size 800M
  extent management local
  character set AL32UTF8 national character set AL16UTF16
  default tablespace users datafile ... size 100M
  default temporary tablespace temp tempfile ... size 100M
  undo tablespace undotbs1 datafile ... size 512M
  enable pluggable database
    seed file_name_convert=('/u01/oradata/cdb1/seed','/u01/oradata/cdb1/pdbseed');
```

要点：`enable pluggable database` 一句即宣告多租户轨；redo 三组 512M 是"生产下限姿势"的示意；每子句对应 04 章一个物理对象族。

## 2.6 建库失败的典型断点（⚠️ 排障地图）

1. NOMOUNT 起不来：spfile 参数与内存配额（SGA_TARGET 超可用内存）、AIO 内核参数。
2. CREATE DATABASE 中途死：磁盘满在哪个文件上（`v$diag_info` 查 alert 路径）→ 重跑前的清理语义（RESETLOGS vs 删文件重建）⚠️。
3. 字典脚本报 ORA-0403x：并行度与临时表空间不足，重跑脚本通常收敛。
4. 字符集选错后的"能跑但错字"：从建库第一天就是错的数据卫生问题，比技术故障更贵。

## 2.7 DBCA 静默命令速记（⚠️ 示意语法，参数名以文档为准）

```bash
dbca -silent -createDatabase \
  -templateName General_Purpose.dbc \
  -gdbname cdb1 -sid cdb1 \
  -createAsContainerDatabase true \
  -numberOfPDBs 1 -pdbName pdb_app \
  -pdbAdminPassword '***' \
  -sysPassword '***' -systemPassword '***' \
  -characterSet AL32UTF8 -nationalCharacterSet AL16UTF16 \
  -memorySize 4096 -automaticMemoryManagement false \
  -storageType FS -datafileDestination /u02/oradata \
  -emConfiguration NONE
# 常用姊妹命令: -createTemplateFromDB 固化为模板; -deleteDatabase 可逆性为零, 入变更单
```

读法：模板（What）+ 容器开关（How-arch）+ 字符集/内存/存储（不可逆决策件，§2.3）——静默建库脚本本身就是一份**建库决策评审单**的机器可执行形态，这是 Pro 线"模板化一切"立场的最小样例 ⚠️。

## 2.8 建库后 30 分钟验收清单（⚠️ 值班习惯）

| 检查 | 语句/动作 | 不合格处置 |
|---|---|---|
| 组件有效性 | `dba_registry`/`dba_registry_sqlpatch`（09 章视图） | 组件 INVALID→重跑对应 cat*.sql |
| 服务与监听 | `lsnrctl services` 可见 `<sid>_XPTYPE` 与 PDB 服务 | 注册延迟等 PMON；静态兜底 |
| 默认表空间三件套 | USERS/TEMP 属性、DEFAULT PROFILE 链接（05 章） | 生产建库即改 profile |
| 归档模式 | `archive log mode`（→04/12） | 生产必改+重启+全备基线 |
| 示例组件 | 未装示例 schema；若装即锁 | account lock+过期口令 |
| 备份基线 | 建库后立即 level0（12 章链起点认知） | 未基线=无备份状态 |
| 监控纳管 | 实例注册进监控/EM 仓库（14 章） | 无监控库不进生产门 |

## 2.9 常见误区三则（⚠️ 社区高频）

1. **"字符集以后能改"**：子集→超集勉强有路（且高危），含中文生产库第一次就选错已是重工程——AL32UTF8 没有讨论必要；
2. **"块大小选 16K 为性能"**：无 OLAP 混合负载证据时，8K+合理 redo/UNDO 配比才是默认正解；换块=换缓存策略全局评估；
3. **"DBCA 建的不干净"**：生产就绪化=§2.8 清单+05 加固，而非手工裸 SQL 重演——手工建库的溢价只在"懂 DBCA 做了什么"，不在替代它。

## 核心概念速览（中英对照）

- **CREATE DATABASE** — create database：NOMOUNT 后写控制文件与 seed 文件的原子建库语句。
- **DBCA** — Database Configuration Assistant：图形/静默建库与模板工具。
- **模板文件** — template (.dbt)：把建库参数固化可审计的文本。
- **CDB$ROOT / PDB$SEED** — root container / seed PDB：字典宿主与新 PDB 复制源。
- **enable pluggable database** — enable PDB：建库语句里的多租户开关。
- **字符集** — database character set：建库定死、后改即重工程的 AL32UTF8 决策。
- **UNDO 表空间** — undo tablespace：回滚段容器，读一致性与回滚的地基。
- **redo 日志组** — online redo log group：前滚日志的循环成员组。
- **ARCHIVELOG** — archive log mode：redo 续档模式，在线备份的前置。
- **AUTOEXTEND** — autoextend on：数据文件按需自涨，便利与爆盘的双刃。
- **catalog/catproc** — dictionary scripts：数据字典与 PL/SQL 基础设施脚本。
- **RESETLOGS** — reset logs：重建日志序列的高危动作，DBID/SCN 分叉点。

## 最新演进与工业实践

- **建库正在变成"建 PDB"**：23ai 管理员日常是 `CREATE PLUGGABLE DATABASE`（秒级、从种子/远程克隆）而非整库 CREATE——本章知识的重心迁移到 11/15 章；⚠️ 转述，官方 Multitenant 指南口径（✅ 族主页 https://docs.oracle.com/en/database/oracle/oracle-database/23/ ）。
- **Free 版建库零配置**：Oracle Database Free 安装即得一个含单 PDB 的 CDB（✅ ladbi 安装文档线），"建库"教学价值从操作转为原理——这与本目录 🔧 类比方向一致。
- **ATP 把建库参数全部代答**：自治库（✅ https://docs.oracle.com/en/cloud/paas/autonomous-database/serverless/adbsb/ ）替你做完 §2.3 全部不可逆决策中的大半（ECPU 规格外几乎无决策项），工业岗位描述中"建库"字样急速萎缩 ⚠️ 通说。
- **IaC 化建库**：Terraform/Ansible + dbca -silent 响应文件是金融/政企私有云主流（⚠️ 社区通说，无权威统计）；本章示例应改写为 Git 里的模板 + CI 里的冒烟建库。
- **跨引擎对照（盘上）**：同题"实例 vs 数据库"二分在 MySQL 侧见 ../Understanding_MySQL_Internals/00-总览与阅读地图.md（InnoDB 表空间族谱）；PG 侧建库语义（模板库 template1 复制出新库）与 PDB$SEED 机制惊人同构，见 ../PostgreSQL_16_Administration_Cookbook/00-总览与阅读地图.md——三种引擎的"种子"设计可作一页对照卡。
