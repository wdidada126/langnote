# 14 · 自动化与故障排查（原书 Ch.16, pp.487-531）

> 章题 ✅ Crossref 实抓（DOI 10.1007/979-8-8688-1038-1_16, "Automation and Troubleshooting"）。章内小节自拟 ⚠️。Oracle 行为一律 ⚠️ 转述；取证：Administration ✅ https://docs.oracle.com/en/database/oracle/oracle-database/23/admin/index.html 、DBMS_SCHEDULER 包 ✅ …/23/arpls/index.html 。

## 14.1 本章双主角：让它自己跑 & 出事看得见

Pro 册把"自动化"与"排障"合为一章的用意：**值班解放的两条腿**——例行事务脚本化（Scheduler），异常路径证据化（ADR/追踪工具）。前后各章的工具（09 字典视图、12 RMAN 报表、04 归档水位）在本章串成值班手册。

## 14.2 DBMS_SCHEDULER：库内调度全家桶 ⚠️

对象层次（每层都是字典里的可管对象 →09 章视野）：

| 层 | 对象 | 一句话 |
|---|---|---|
| 内容 | program（PL/SQL 块/存储过程/外部脚本类） | 跑什么 |
| 节奏 | schedule（日历表达式/频率） | 何时跑 |
| 绑定 | job = program+schedule+argument | 具体实例 |
| 护栏 | credential（OS 账户凭据对象）+ destination（跑在哪台机） | 以谁何处 |
| 编排 | chain/rule（步骤图） | 依赖与分支 |
| 窗口 | window + job class 资源切换 | 与 Resource Manager 联动的"业务时段"（03 章联动）|

- 观测：`dba_scheduler_jobs/_job_run_details`（成败/错误码/时长史）——告警接入点；`run_job` 手工触发+`stop_job` 熔断是演练两键 ⚠️；
- 窗口自带统计收集任务挂载（09 章自动任务即跑在 window 框架内）⚠️；
- 与 OS cron/systemd timer 的分工：依赖库内一致性/资源治理的用 Scheduler，纯 OS 事项（备份脚本外壳、文件搬运）用 cron——**混用无对错，台账要统一** ⚠️ 本目录立场。

## 14.3 ADR：诊断证据的中枢（01 章伏笔收线 ⚠️）

- 结构：`diag/rdbms/<db>/<inst>/` 下 `alert`（XML+文本双轨）、`trace`（后台/服务端进程跟踪）、`incident/<n>`（一次错误的证据包裹：核心转储摘要+跟踪文件索引）⚠️；
- 工具：`adrci`（show problem/incident、purge、打包 ips 生成诊断 ZIP 递 SR）；`v$diag_info` 查路径——"ORA-600/7445 怎么办"的标准答案第一层就是"别慌，先收 incident" ⚠️；
- 保留治理：ADR 倾斜策略（`control` 里 `SHORTP_POLICY/LONGP_POLICY`）——diag 盘满也是 P2，纳入 04 章空间水位同一告警族 ⚠️；
- 告警通知：OFA（Oracle-Flexible/Alert 通知机制）+ `dbms_scheduler` 事件型作业（`sys.server_alerts` AQ 队列订阅）可做"错误号→自动收证→通知"流水线 ⚠️。

## 14.4 追踪与取证工具箱（排障的"显微镜"层 ⚠️）

- **会话级**：`dbms_monitor`/oradebug 设 10046（SQL+绑定+等待，级别 4/8/12）、10053（优化器决策内情——深读在盘上 [../Cost_Based_Oracle_Fundamentals/14-10053跟踪文件.md](../Cost_Based_Oracle_Fundamentals/14-10053跟踪文件.md)）；
- **事后聚合**：AWR 快照/ASH 采样（许可注意 EE+Pack ⚠️）——数据面在 `dba_hist_*` 与 `v$active_session_history` 视图族，入口有 AWR/ASH 文本报告与 EM/CLI 通道 ⚠️；
- **SQL 面**：`v$sql`/执行计划字典（`dbms_xplan.display_cursor`）与 SQL Monitoring 实时算子流 ⚠️；方法论（可复现/不可复现分诊）整本在盘上 [../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md](../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md)——本章给工具位，它给诊断学；
- **锁与阻塞链**：`v$session.blocking_session`/`v$lock`/ASH 的 enqueue 事件，`kill session` 前先看是否已是"牺牲者链条" ⚠️；
- **健康检查**：Health Monitor（`adrci`/EM 的 HM run）：数据块/事务/字典/缓存一致性等套件化体检 ⚠️——12 章 validate 的"体检版"。

## 14.5 值班自动化剧本（⚠️ 本章的交付物形态）

1. **空间**：表空间/FRA/归档/ASM 盘四水位→阈值告警→自动扩展申请单（04 章数据的消费端）；
2. **作业**：Scheduler 失败即重跑一次→仍败则升级（幂等设计要求写进 program 模板）；
3. **备链**：RMAN report need backup 日检（12 章）+ 演练日历；
4. **取证前置**：ORA 错误号白名单触发 adrci 打包+告警附链接——把"人肉查 alert"从 SLA 里删除；
5. **周报**：top 等待事件/top SQL/容量趋势三表——从 v$ 族自动拼（09 章视野的报表化）；
6. **变更冻结窗**：window 与业务日历对齐（14.2 窗口族的本业）。

## 14.6 Scheduler 剧本骨架（⚠️ 示意，值以文档为准）

```sql
begin dbms_scheduler.create_job(
  job_name   => 'DLY_TS_WATERMARK',
  job_type   => 'STORED_PROCEDURE',
  job_action => 'PKG_DBA.P_TS_ALERT',      -- 查 dba_free_space/写告警台账
  start_date => timestamp '2025-02-01 02:00:00 Asia/Shanghai',
  repeat_interval => 'FREQ=DAILY;BYHOUR=2;BYMIN=0',
  enabled => false, auto_drop => false);
  dbms_scheduler.set_job_argument_value('DLY_TS_WATERMARK',1,'85');   -- 阈值参数化
  dbms_scheduler.enable('DLY_TS_WATERMARK'); end;
/
-- 失败可见性: run_details 轮询作业(告警出口 14.5 第 2 条的本体)
select job_name,status,error#,to_char(log_date,'mm-dd hh24:mi') 
  from dba_scheduler_job_run_details
 where log_date > systimestamp - 1/24 order by log_date desc;
-- 事件驱动式(错误号→自动动作): 事件型作业骨架(job_type=EVENT, 队列名以文档为准, 如告警 AQ)
begin dbms_scheduler.create_job('EVT_ALERT_PACK',
  job_type=>'EVENT', queue_name=>'SYS.ALERT_QUEUE',
  job_action=>'PKG_DBA.P_INCIDENT_BUNDLE',
  enabled=>false);
  dbms_scheduler.set_job_queue_watcher('EVT_ALERT_PACK', true, 1);
  dbms_scheduler.enable('EVT_ALERT_PACK'); end;
/
```

两条设计红线：**作业必须幂等**（重跑无副作用——14.5 第 2 条的前提）；**窗口错峰**（自动统计收集/备份/自建作业同窗互踩是"慢在凌晨两点"名案，用 window/job class 排布）⚠️。

## 14.7 adrci 与跟踪件速查（⚠️ 命令族）

```bash
adrci> show home                      # 多实例诊断巢位确认(01 章目录)
adrci> show problem -terms 20         # 近期问题摘要(错误号/首次/次数)
adrci> show incident -mode detail -p "incident_id=42"
adrci> ips pack incident_id=42        # SR 报送包(14.3 流程的机器件)
adrci> purge -age 10080 -age ...      # 按龄清理(单位分钟示意; 保留政策进台账)
# 会话级显微镜(14.4 的落地形):
oradebug setospid <pid>; oradebug event 10046 trace name context forever, level 12
# 用完即关: oradebug event 10046 trace name context off  ——trace 泄漏=diag 盘事故
```

alert log 侧：文本版 `alert_<sid>.log` 人读、XML 版 `log.xml` 机读（adrci/EM 的数据源）——**grep 文本版做快速定位、adrci 做结构化取证**双轨并行 ⚠️。

## 核心概念速览（中英对照）

- **DBMS_SCHEDULER** — 库内调度引擎：program/schedule/job 三元组与窗口框架 ✅ arpls。
- **窗口** — schedule window：与时段资源策略联动的日历对象。
- **作业类别** — job class：调度与 Resource Manager 的接缝。
- **credential 对象** — 凭据对象：外部脚本/远端执行的身份封装。
- **chain** — 调度链：以规则编排的有向作业图。
- **ADR** — Automatic Diagnostic Repository：alert/trace/incident 三层证据库。
- **adrci** — ADR 命令行：查题、打包（IPS）、清理的入口。
- **incident** — 事件包：单次严重错误的自证物集合。
- **10046 trace** — SQL 跟踪事件：绑定/等待级执行实录。
- **10053 trace** — 优化器跟踪：代价决策的内心戏（Lewis 册 14 章深读）。
- **AWR/ASH** — 负载仓库/活动会话历史：事后聚合双库（许可件 ⚠️）。
- **Health Monitor** — 健康检查套件：字典/块/事务一致性体检。
- **dbms_xplan** — 计划显示包：游标字典里的执行计划取证 ⚠️。

## 最新演进与工业实践

- **可观测性外滚**：v$/AWR/ADR 的数据出口全面对接 Prometheus/Grafana/OpenTelemetry 生态（开源 exporter 件 ⚠️ 通说），"值班剧本 14.5"在多数团队已是平台功能而非自研脚本；Oracle 自家收敛为 Enterprise Manager（on-prem）与 OCI Observability+Explorer（云 ATP ✅ adbsb 线）双轨 ⚠️。
- **自治化蚕食 routine**：ATP 把空间自愈、索引建议、统计维护、补丁窗口全部托管（✅ adbsb），本章在云岗位的新形态是"审阅引擎自报告+策略例外管理"——Scheduler 幸存场景集中在跨系统编排与业务时钟类作业 ⚠️ 趋势句。
- **AIOps 试点**：以 ASH/ADR 历史训练异常检测与根因排序的论文与开源实验在 2023-2026 持续产出 ⚠️（未锁定单一 DOI，避免虚构引用；检索词 "Oracle ASH anomaly detection" 可复现文献面）；工业成熟度仍低——14.5 的手工剧本模板短期不可替代 ⚠️ 本目录判断。
