# 06 · 表与约束（原书 Ch.7, pp.175-226）

## 6.1 表的物理形态家族（本章第一地图）

| 形态 | 关键属性 | 管理动作 |
|---|---|---|
| 堆表 heap | 默认；插入位置自由 | 空间/统计常规（04/09 章） |
| IOT 索引组织表 | 行按主键 B 树存储，无独立堆 | overflow 表、PK 设计=物理设计 |
| 外部表 | 数据在文件，表是"读取协议"（→13 章） | 目录对象/驱动 |
| 临时表 | 事务/会话级私有数据 | TEMP 表空间承载（04 章） |
| 集群表 cluster | 多表共置一簇（罕见，维护税高） | ⚠️ 现代实践基本回避 |
| 分区表 | 一表多段，裁剪/维护粒度细化 | §6.3 |

**组织形态即性能契约**：IOT 点查快/大事务慢（行锁在索引上）、堆表反之 ⚠️——选型题在建模期做，不在调优期做。

**🔧 类比（非本书引擎行为）——IOT 的最小标本**：SQLite 的 `WITHOUT ROWID` 表就是"按主键 B 树存放整行"的 IOT 同款结构。本机 sqlite 3.45.3 实跑：

```
$ python - <<'EOF'
import sqlite3
g = sqlite3.connect(':memory:')
g.execute('create table iot(id int primary key, v text) without rowid')
g.execute("insert into iot values(1,'a')")
print(g.execute('explain query plan select v from iot where id=1').fetchall())
EOF
[(2, 0, 0, 'SEARCH iot USING PRIMARY KEY (id=?)')]
```

`SEARCH ... USING PRIMARY KEY` 表明定位发生在主键结构本身、无回表一跳——对应 Oracle IOT 的 "index scan 即 row 获取"；普通堆表+索引则是"索引→rowid→表块"两跳（对照 [../Cost_Based_Oracle_Fundamentals/04-B树索引基础访问.md](../Cost_Based_Oracle_Fundamentals/04-B树索引基础访问.md)）。**差异**：Oracle IOT 有 overflow 段与逻辑锚定（MOVING PRIMARY KEY 重组），SQLite 无这些运维维度。演示于 tmp/dbwave_w4_ora23，非本书引擎行为。

## 6.2 列类型：23ai 的一次家谱扩容（⚠️ 重点转述）

- 经典家族：NUMBER（精度语义/PLSQL 索引类型）、VARCHAR2/NVARCHAR2（字节 vs 字符语义 `NLS_LENGTH_SEMANTICS`，中文库的 4000 字节墙）、DATE（含时分秒的历史命名包袱）、TIMESTAMP+Nano、INTERVAL、RAW/ROWID ⚠️。
- **23ai 新增**（✅ Concepts/新特性文档线）：
  - `BOOLEAN`：SQL 层原生布尔（此前只有 PL/SQL 有），可建默认/检查但破坏性升级兼容需评估 ⚠️；
  - `JSON` 原生类型：列级 JSON 校验内建（存底层仍走 LOB/BINARY JSON 形态 ⚠️→10 章与 08 章 duality 交界）；
  - 域/语义标注相关新对象（In-database 注解供向量生成管道 ⚠️，细节出本册管理范围）。
- 大版本换代的兼容纪律：新类型/新默认值对**滚动升级与回退**的影响在 16 章补丁线处理 ⚠️。

## 6.3 分区：从技术到生命周期管理

分区形态（range/list/hash + 复合 + interval 自动扩区 ⚠️ 11g 起）在本册语境是**运维工具**而非性能咒语：

- 裁剪（partition pruning）优化器行为 → 归 CBO 线（[../Cost_Based_Oracle_Fundamentals/09-查询变换.md](../Cost_Based_Oracle_Fundamentals/09-查询变换.md) 邻域）；
- 管理员动作：`add/drop/truncate/split/merge/move exchange partition`——drop 老分区=秒级清理，exchange=批量装载魔术（外部表→分区，13 章联动）⚠️；
- interval 分区把"每月记得加分区"从 cron 里删掉——本章自动化案例的主角 ⚠️；
- 全局索引 vs 本地索引的维护代价分叉：drop partition 使全局索引 UNUSABLE 的处置（→07 章）⚠️。

## 6.4 约束：声明式完整性的全部家当

| 约束 | 陷阱位（⚠️） |
|---|---|
| PRIMARY KEY | 隐式 NOT NULL+唯一索引；禁用作"文档注释"式的伪约束 |
| FOREIGN KEY | 无索引子表→父表删除全表扫描锁战；孤儿行治理走 EM 官方脚本/out$ 反查（⚠️ 无通用包，勿用禁约束糊弄） |
| UNIQUE | 与 PK 的存储差（均 B 树，NULL 语义不同） |
| CHECK | 旧数据不重验：`enable validate/novalidate` 四态 |
| NOT NULL/DEFAULT | 23ai 身份列（`generated always/as identity`）与 `default on null` 语法糖进约束家族 |

- **enable/disable × validate/novalidate** 矩阵是批量装载与历史脏数据并存的正道：`disable keep` 装载→`enable novalidate`→后台 `enable validate` 分批收敛 ⚠️——比"删约束重建"少一个数量级的风险。
- 延迟约束（deferrable）给事务内乱序写入合法通道 ⚠️。
- DEFERRED SEGMENT CREATION（11g 起默认）：空表不建段 → `allocate extent` 手工还权，"建了表没空间报错却查不到段"的谜底 ⚠️。

## 6.5 表级运维动作集

- `alter table ... move`：重排段（收 HWM）、换表空间、改压缩属性——索引随之 UNUSABLE 的重建清单（→07）⚠️；
- 行移动（`enable row movement`）是 shrink 的前置 ⚠️；
- 压缩家族（basic/OLTP/混合分区压缩）许可与 CPU/空间权衡 ⚠️（OLTP 压缩为 EE+选项，装完先查许可再谈启用——合规雷区）；
- `inmemory` 条款在本册仅点名：内存列存是"另一张桌子上的菜" ⚠️（官方 In-Memory Guide 线）。

## 6.6 分区生命周期脚本骨架（⚠️ 示意，interval 之外的手工档）

```sql
-- 月度 range 分区表: 预建下月+清理 24 月前(值班月例行, 14 章 Scheduler 化)
alter table sales add partition p202502 values less than (date '2025-03-01');
alter table sales drop partition p202201 update indexes;   -- 索引命运显式声明(07 章)
-- interval 表: 首分区+间隔声明后自动扩区, 例行件只剩"保留期删除"
create table log_events(...) partition by range(ts)
  interval (numtoyminterval(1,'MONTH'))
  (partition p0 values less than (date '2025-01-01'));
-- exchange 装载(DATAPUMP 外部表/预清洗表): 秒级换入+统计补收(09 章)
alter table sales exchange partition p202502 with table stg_sales including indexes;
call dbms_stats.gather_table_stats('HR','SALES');
```

例行三问：**谁建未来分区（interval/作业）、谁删历史（保留政策）、谁补统计（装载后钩子）**——三问皆有主，分区表才不养事故 ⚠️。

## 6.7 大表 DDL 的当代姿势（⚠️ 在线化谱系）

- 加列：`default` 常量值走"元数据秒改"（11g 后 default-no-null 优化）；带表达式/非默认路径回全表重写 ⚠️；
- 改类型/收缩：在线重定义（`dbms_redefinition`）+ clog 追平 + 瞬间换名——12c 后多数场景被 `alter table ... modify online` 家族吸收 ⚠️；
- 一切在线 DDL 的共同暗账：UNDO/TEMP 放大 + 伴生临时对象（04 章资源观）+ 长事务挡住收尾换名（Flashback 时代的经典死锁形态）⚠️——发布窗口预留"最后一秒独占"。

- IOT 与堆表的锁/IO 性格差与选型问句。

## 核心概念速览（中英对照）

- **堆表** — heap table：行落位自由的默认表形态。
- **IOT** — index-organized table：整行按主键 B 树存储，可带 overflow 段。
- **WITHOUT ROWID** — SQLite 的 IOT 同构（🔧 类比项，非本书引擎）。
- **IDENTITY 列** — identity column：序列托管的自增语义列。
- **DEFAULT ON NULL** — 显式传 NULL 也触发默认值的 12c+ 语义。
- **外键索引** — FK index：子表连接键索引缺失=锁与性能双雷。
- **novalidate** — enable novalidate：新行守法、旧账不追的约束上线姿势。
- **DEFERRABLE** — 延迟约束：事务提交时再验。
- **interval 分区** — 自动扩区：按间隔物化新分区免手工。
- **exchange partition** — 分区交换：非分区表与分区秒级互换的装载术。
- **本地/全局索引** — local/global index：分区维护时索引命运的分叉。
- **延迟段创建** — deferred segment creation：空表不占段的默认行为。
- **行迁移/链接** — migrated/chained rows：块满搬迁与跨块行的读取惩罚。

## 最新演进与工业实践

- **BOOLEAN/JSON 进 SQL 的生态效应**（⚠️ 转述）：23ai 后应用层布尔三态/JSON 文档列不再需要 NUMBER(1) 与 VARCHAR2+CLOB 补丁模式；JSON 原生列与 duality 视图（→08）+ AI 向量（→07/08 演进）构成"文档-关系-向量"同库三形态，这是 2024+ Oracle 对抗文档/向量专用库的主叙事 ✅（adjsn/vldbg 文档线）。
- **逻辑模式演进工具化**：Flyway/Liquibase 类迁移工具在 Oracle 侧依赖的正是本章约束四态与分区交换的低风险组合 ⚠️ 通说；"DDL 即部署物"入 Git 后，6.4 的矩阵成为回滚脚本设计的语法书。
- **分区粒度上移**：SaaS 多租户以 PDB 为租户边界后（→11/15 章），表内分区更多服务时间线/合规保留而非租户隔离——设计问句从"按什么分区"变为"这还需要分区吗" ⚠️ 本目录立场。
- **跨引擎对照（盘上）**：PG 的约束四态同语法（NOT VALID 一脉）与 MySQL 8 的即时 DDL/instant 列演进，见 ../PostgreSQL_16_Administration_Cookbook/00-总览与阅读地图.md、../Understanding_MySQL_Internals/00-总览与阅读地图.md；Oracle 的 move+rebuild 重组税在 12c 后增量降低（在线分区维护、`alter table move online` ⚠️），对照读可校准"哪家 DDL 最不打扰业务"的直觉。
