## 核心精讲

### 10.1 锚定与 tuple 树

原书强调「可靠」的前提是**锚定**：一个 Bolt 产出新 tuple 时，必须声明它源自哪个输入 tuple，
从而把整条处理链连成一棵 **tuple 树**。只有当整棵树都被 ack，根 tuple 才算「完整处理」。

```text
# 教学示意，不参与构建：tuple 树
Spout t0
  └─ BoltA 收到 t0, 锚定产出 t1
        └─ BoltB 收到 t1, 锚定产出 t2
整棵树 {t0,t1,t2} 都 ack => t0 完整; 任一超时 => t0 重发
```

### 10.3 异或校验（Storm 经典算法）

原书实现的 acker 用 **XOR 累积 messageId**：每发出/每 ack 一个 tuple 就把它 id 异或进
该 rootId 的校验和；当校验和归零，说明树完整。

```text
# 教学示意，不参与构建：acker 异或(对应第5章5.3)
acker[rootId] ^= msgId     # 发出新 tuple 时加入(锚定)
acker[rootId] ^= msgId     # 该 tuple 被 ack 时再异或(抵消)
if acker[rootId] == 0:     # 归零 => 树完整 => 通知 Spout.ack(rootId)
else if timeout:           # 超时 => Spout.fail(rootId) => 重发根 tuple
```

> 关键性质：**XOR 同一数两次得 0**，所以「发出即加、ack 即减」能精准检测遗漏。
> 但重发会带来**重复**（同一 tuple 可能被处理两次），所以这只是 **at-least-once**。
> exactly-once 见第 12 章。

## 版本演进

- **本书无第二版**；本节写 2016 年口径 → 2026 年视角的变化。
- **10.3 的 at-least-once → exactly-once 快照**：2026 年主流是 **Flink 的
  分布式快照（Chandy-Lamport）**——定期对算子状态做全局一致快照，故障从快照恢复，
  对应用透明地达到 exactly-once，比 acker + 事务性拓扑（第 12 章）更通用。
- **acker 的扩展性问题**：XOR acker 在超大拓扑/超高频下是中心瓶颈；
  现代框架把可靠性下沉到**状态后端 + 快照**，避免中心 acker（🔧 补）。
- **幂等是 exactly-once 的廉价替代**：很多场景用「at-least-once + 幂等 sink」
  取代 true exactly-once，性价比高（🔧 补）。

## 近年研究与工业界开源实践（2015–2026）

- **Flink 分布式快照 exactly-once**：`apache/flink`（26367★）用 Chandy-Lamport 快照 +
  可重放源（Kafka）实现端到端 exactly-once，应用无需写 acker 逻辑——本书 10.3 的范式升级。
- **Kafka 的 exactly-once / 事务**：`apache/kafka`（33849★）提供幂等生产者 +
  事务，使「at-least-once + 幂等 sink」成为常见落地（🔧 补 10.1）。
- **Storm 自身**：`apache/storm`（6695★）仍用 acker，但已非主流可靠性方案。
- **Pulsar**：`apache/pulsar`（15338★）的「消息去重 + 幂等」同样支撑可靠流处理。

## 常见误区与本书需修正之处

| # | 误区 | 事实 | 书目 |
| --- | --- | --- | --- |
| 1 | 「acker 保证 exactly-once」 | acker 只给 **at-least-once**；重发会重复 | 10.1/10.3 |
| 2 | 「锚定可有可无」 | 不锚定就无法构建 tuple 树，acker 失效 | 10.1 |
| 3 | 「XOR 不会出错」 | XOR 有极低概率碰撞（id 巧合 XOR 归零误判），大拓扑需防 | 10.3 |
| 4 | 🔧 应补「分布式快照 exactly-once」 | 现代主流是 Chandy-Lamport 快照，非 acker | 10.3 |
| 5 | 🔧 应补「幂等 sink 替代真 exactly-once」 | 性价比更高的落地路线 | 10.1 |
| 6 | 🔧 应补「acker 的中心瓶颈」 | 超大规模下中心 acker 是瓶颈，需状态后端下沉 | 10.3 |
