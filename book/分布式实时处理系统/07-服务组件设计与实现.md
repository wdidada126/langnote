# 第 7 章　服务组件设计与实现

> 原书第 7 章实现第 6 章架构里的两个**运行时载体**：`Executor`（工作进程/线程容器）

## 核心精讲

### 7.1 Executor：线程模型与任务队列

原书让 Executor 持有多个 Task，每个 Task 在一个线程（或用线程池）上循环驱动。
Executor 负责把收到的 tuple 路由给对应 Task，并把 Task 产出的 tuple 交给网络层发出。

```text
# 教学示意，不参与构建：Executor 的内部循环(定性)
Executor:
  tasks:  map<taskId, Task>          // 本 Executor 承载的 Spout/Bolt
  inbox:  线程安全队列<Tuple>         // 网络层收到的待处理 tuple
  loop:
    for task in tasks:
        if task is Spout: task.nextTuple()      // 主动拉/推数据
        if task is Bolt:  pop inbox -> task.execute(t)
        task 产生的 tuple -> 交给网络层 emit(经 Collector)
```

> 这与第 4 章 4.3「事件循环/多线程」的工程取舍直接相关：Hurricane 在 Executor 内用
> 少量线程驱动多 Task，避免在 Task 级「每连接一线程」。

### 7.2 Task：业务逻辑的承载

Task 把第 6 章的 `ISpout`/`IBolt` 接口实例化并驱动其生命周期：

```cpp
// 教学示意，不参与构建：Task 驱动一个 Bolt
struct Task {
    IBolt* bolt;
    void run(const Tuple& input) {
        bolt->execute(input);   // 用户逻辑; 内部通过 collector->emit 产出
    }
};
// Spout 型 Task 则周期性调用 nextTuple(), 由 collector 向外发源数据
```

> Task 与 Executor 的「一对多」关系是 Storm 的 `Worker:Executor:Task` 三层模型简化版
> （Storm 中 Worker > Executor(线程) > Task(实例)）。本书把 Executor 与 Task 直接对应，
> 工程上更薄，便于教学。

## 版本演进

- **本书无第二版**；本节写 2016 年口径 → 2026 年视角的变化。
- **线程模型**：2026 年现代框架（如 Seastar 的 shared-nothing 纤程、或 Flink 的
  算子线程 + 网络线程分离）比「Executor 内简单轮询」更精细；C++20 协程可大幅简化 7.1 的循环。
- **背压（🔧 必补）**：本章未提背压——当下游 Task 处理慢、inbox 堆积时怎么办。
  现代框架必须有背压（Storm 的 backpressure / Flink 的 credit-based），否则内存爆。
- **无锁队列**：高吞吐下 7.1 的「线程安全队列」应是无锁（MPMC）队列，原书可能用锁，
  2026 年应点明。

## 近年研究与工业界开源实践（2015–2026）

- **Flink 的线程模型**：`apache/flink`（26367★）每个算子有独立多线程 + 网络线程，
  用**基于 credit 的背压**天然防止 inbox 堆积——直接补本书 7.1 缺失的背压。
- **Seastar 共享无关 + 纤程**：`scylladb/seastar` 让每个核跑独立事件循环、任务间零锁，
  是 7.1「Executor 内多 Task」的高性能演进方向。
- **无锁 MPMC 队列**（如 moodycamel）是 2026 年 C++ 高并发 inbox 的默认选择。

## 常见误区与本书需修正之处

| # | 误区 | 事实 | 书目 |
| --- | --- | --- | --- |
| 1 | 「Executor 轮询就够快」 | 高频 tuple 下轮询有空转/延迟；需事件驱动或高效队列 | 7.1 |
| 2 | 「Task 多了加线程就行」 | 线程数过多引发切换爆炸（见 4.3）；需合理映射 | 7.1 |
| 3 | 🔧 缺失「背压」 | 下游慢时 inbox 堆积会 OOM；现代框架必须背压 | 7.1 |
| 4 | 🔧 应补「无锁队列/内存序」 | 高吞吐 inbox 要无锁，涉内存序正确性 | 7.1 |
| 5 | 🔧 应补「C++20 协程简化循环」 | 协程让异步驱动代码更可读，避免回调 | 7.1/7.2 |
