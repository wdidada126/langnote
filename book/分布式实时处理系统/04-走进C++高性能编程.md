# 第 4 章　走进 C++ 高性能编程

> 原书第 4 章是**写给「会 C++ 但不懂服务器编程」的读者的过渡章**：用一个
> 「基于 C++ 的留言板系统」从无到有，引出服务器常见的三类痛点——「来自服务器的天书」
> （并发/乱序日志）、「繁忙的服务器」（吞吐/阻塞）、「消失不见的内存」（内存泄漏/资源管理）。
> 这一章为后面用 C++11 写 Hurricane 与 Meshy 做工程准备。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 4.1 基于 C++ 的留言板系统 | 一个最小服务器：接收请求、存留言、返回列表 | 同步阻塞模型最简单也最脆弱 |
| 4.2 来自服务器的天书 | 多线程下日志交错、难以排查 | 并发带来不确定性，需要结构化日志/追踪 |

| 4.5 本章小结 | 收束 | — |

## 核心精讲

### 4.3 为什么同步阻塞撑不住流处理

原书用「繁忙的服务器」点出核心矛盾：每个连接一个线程的模型，在线程数超过几百后
**线程切换与内存（每线程栈）成为瓶颈**。这正是流处理框架（高并发连接 + 高吞吐 tuple）
必须采用 **I/O 多路复用 + 事件循环** 的原因——也是第 11 章 Meshy 用 `epoll`/`kqueue`
的动机。

```text
# 教学示意，不参与构建：两种服务器模型的吞吐对比(定性)
thread_per_conn:  每连接一线程
   优点: 编程直观
   缺点: 千级连接 => 千级线程 => 上下文切换爆炸 + 内存爆
   结论: 不适合流框架的万级连接

event_loop(epoll/kqueue):  单/少数线程 + 多路复用
   优点: 少量线程撑万级连接, 无切换爆炸
   缺点: 回调/异步编程复杂(可用 C++11 async/lambda 缓解)
   结论: Meshy(第11章) 采用的路线
```

### 4.4 C++11 的资源管理：RAII 与智能指针

原书 4.4 针对「消失的内存」，强调 C++ 必须用 **RAII（资源获取即初始化）** 配合
`std::shared_ptr` / `std::unique_ptr` 把资源生命周期绑定到作用域，避免手动 `new/delete`
导致的泄漏与悬垂。

```cpp
// 教学示意，不参与构建：用 unique_ptr 避免泄漏
#include <memory>
#include <vector>

struct Connection { /* socket 句柄等 */ };

void handle(std::vector<std::unique_ptr<Connection>>& conns) {
    auto c = std::make_unique<Connection>();  // 构造即拥有
    conns.push_back(std::move(c));            // 所有权转移
}                                              // 离开作用域自动释放, 不漏
```

> 🔧 2026 视角：现代 C++（14/17/20）进一步提供 `std::string_view`、`std::span`、
> 移动语义优化，减少拷贝；且 **Sanitizers（ASan/TSan/UBSan）** 是排查 4.2/4.4 问题的
> 标配工具，原书 2016 年尚未普及。

## 版本演进

- **本书无第二版**；本节写 2016 年口径 → 2026 年视角的变化。
- **C++ 标准演进**：本书基于 C++11；2026 年生产线已普遍到 **C++17/20**，
  带来 `std::string_view`、`std::filesystem`、结构化绑定、协程（`std::coroutine`，
  可大幅简化 4.3 的事件循环异步代码）等。C++20 协程让「异步但不回调地狱」成为可能，
  是重写 Meshy 风格网络库的有力工具。
- **排查工具**：ASan/TSan/UBSan、perf、eBPF 火焰图已成为 4.2/4.4 问题的标准解法。
- **内存模型**：C++11 的内存序（`std::memory_order`）是写无锁并发的基础，
  原书若深入并发（第 7/11 章）会用到；2026 年更强调「先无锁数据结再利用内存序」。

## 近年研究与工业界开源实践（2015–2026）

- **Seastar / 用户态网络栈**：`scylladb/seastar` 用 **shared-nothing + 纤程 + DPDK**
  把 C++ 高并发服务器性能推到极致，是 4.3「事件循环」思路的激进演进（无锁分片 + 无内核栈切换）。
- **C++ 协程库**：`boost::asio` 的 C++20 协程支持、以及 `libunifex` 等，让异步代码
  写成看似同步的形态，直接缓解 4.3 的「异步编程复杂」痛点。
- **Sanitizer 工具链普及**：Google 的 ASan/TSan 已进入 LLVM/GCC 主干，是 4.4 内存问题的
  生产级解法；原书 2016 年这类工具在国内尚未普及。
- **Folly（Meta）/ Abseil（Google）**：工业级 C++ 基础库，提供高效容器/线程池/异步原语，
  是写 Hurricane 这类框架的现代底座（原书用标准库 + 自研）。

## 常见误区与本书需修正之处

| # | 误区 | 事实 | 书目 |

| 1 | 「每连接一线程最直观也好用」 | 高并发下线程切换/内存爆炸，流框架必须事件循环 | 4.3 |

| 4 | 🔧 应补「C++17/20 新特性」 | 协程/string_view/移动语义大幅简化服务器代码 | 4.1/4.3 |
| 5 | 🔧 应补「Sanitizer/perf/eBPF 工具链」 | 2026 年排查内存/并发问题的标配，原书未提 | 4.2/4.4 |
