## 核心精讲

### 16.2 流上频繁项集的难点

离线 Apriori 可扫描全量数据；**流上只能看「近期窗口」**。原书用滑动窗口 + 共现计数近似：

```text
# 教学示意，不参与构建：流上二项集挖掘(定性)
窗口内每个事务 = {a,b,c}
  for 每对 (x,y) in 事务: 共现计数[x,y] += 1
支持度(x,y) = 共现计数 / 窗口事务数
if 支持度 >= 阈值: 输出 (x,y) 为频繁二项集

问题: 窗口状态需容错 -> 接第10章 acker / 第12章事务
      状态量大 -> 需近似结构(🔧 Count-Min Sketch, 本书未提)
```

> 🔧 2026 视角：流上频繁项集常用 **Count-Min Sketch / Space-Saving** 等 sketch 近似计数，
> 避免存全量共现矩阵；且用 Flink 的 `keyed state + 窗口` 内建托管状态（见第 14 章 🔧）。

### 16.3–16.5 实现

- Spout：产出事务（如用户行为流）；
- Bolt：解析事务、计算共现、按阈值输出；
- 状态（共现表）需持久化/容错，呼应第 12 章事务或第 14 章 Squared 的状态。

## 版本演进

- **本书无第二版**；本节写 2016 年口径 → 2026 年视角的变化。
- **sketch 近似算法**：高频流挖掘几乎必用 Count-Min Sketch 等，避免状态爆炸（🔧 补 16.2）。
- **Flink 内建状态**：窗口+keyed state 让共现计数自动容错，无需手搓（🔧 补）。
- **算法演进**：频繁项集从 Apriori 到 FP-Growth 到流式近似，本书取最经典 Apriori 思路。

## 常见误区与本书需修正之处

| # | 误区 | 事实 | 书目 |
