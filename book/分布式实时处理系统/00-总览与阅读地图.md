## 本书没覆盖的缺口（2026 视角）

- **没有 Kafka / Kafka Streams**：本书成书与 Kafka Streams 发布同年（2016），未纳入；
  而 2026 年「流处理 = Kafka 作为流存储 + 计算引擎消费」已成定式。
- **没有 Flink / Dataflow 模型**：事件时间（event time）、水印（watermark）、
  乱序处理、窗口触发这些现代流处理核心概念全书未出现。
- **没有真正的 exactly-once 检查点机制**：第 12 章的「事务性 Topology」是
  Storm 式（强有序批处理）方案，而非 Flink 式分布式快照（Chandy-Lamport）。
- **没有 SQL-on-Stream**：Flink SQL、Kafka Streams DSL 这类声明式 API 全书未提。
- **没有云原生 / Kubernetes 部署**：第 17 章是 AWS/阿里云 **虚拟机手工部署**，
  与今天的 Operator / 容器化调度相去甚远。
- **C++ 流框架是孤例**：工业界主流流处理均为 JVM（Flink/Storm）或 Go，
  Hurricane 作为 C++11 教学实现价值高，但工程落地极少。
- **没有安全 / 鉴权 / 多租户**：全书假定可信内网。
- **没有背压（backpressure）的系统化讨论**：Storm 的背压机制本书未展开，
  而背压是现代流系统稳定性的基石。

## 实验工具链

- **语言/编译**：C++11（g++ ≥ 4.8 / clang++ ≥ 3.3，需支持 `std::thread`、
  `std::async`、`lambda`、`std::shared_ptr` 等）；构建用 CMake / Make。
- **网络库（自研）**：第 11 章的 **Meshy**——基于 `epoll`（Linux）/ `kqueue`（macOS）
  的 I/O 多路复用 TCP 网络库，替代 Storm 的 ZeroMQ。
- **序列化/IDL**：第 3 章用 **Apache Thrift** 实现公告牌服务（示例）。
- **多语言接口**：第 13 章 C/Python/JavaScript/Java/Swift，依赖各语言运行时与 JSON/文本协议。
- **部署目标**：第 17 章 AWS EC2 / 阿里云 ECS（虚拟机），依赖 SSH 与脚本分发。
- **（未纳入，2026 补）**：Docker / Kubernetes、Prometheus 监控、Kafka/Pulsar 作为消息总线。
