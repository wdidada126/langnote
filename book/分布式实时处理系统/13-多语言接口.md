## 核心精讲

### 13.1 为什么用 C 接口做边界

C 的 ABI（调用约定、名字修饰、结构体布局）在各编译器间最稳定，且几乎每种语言都能
`ffi` 调用 C。原书把 Hurricane 的核心暴露成一组 `extern "C"` 函数，上层语言再包一层。

```cpp
// 教学示意，不参与构建：C 边界接口(简化)
extern "C" {
    void* hurricane_create_topology(const char* name);
    void  hurricane_add_bolt(void* topo, const char* name,
                            void (*process)(const char* tuple_json));
    void  hurricane_run(void* topo);
}
// Python 用 ctypes 调上面; JS/Java/Swift 各有 FFI 机制
```

### 13.2–13.5 子进程 vs 同进程 FFI

Storm 的多语言用的是**子进程 + stdin/stdout + 多行 JSON** 协议（进程隔离、崩溃不影响 JVM）。
原书对脚本语言（Python/JS）更可能走类似「进程 + 文本协议」路线，对 Java/Swift 则可走
同进程 FFI。两者权衡：

```text
# 教学示意，不参与构建：两种多语言路线
子进程+JSON:  隔离好(语言崩不影响主框架)、但有序列化+IPC开销
同进程FFI:    零拷贝、快、但一种语言崩可能带崩整个 Executor
```

> 🔧 2026 视角：现代多语言更常见的是 **(a) 主框架就是 JVM 直接写 Java/Scala（Flink），
> (b) PyFlink 用进程+状态桥接，或 (c) 用 WASM 做安全沙箱**。C++ 框架自研五语言绑定
> 维护成本高，工业界罕见。

## 版本演进

- **本书无第二版**；本节写 2016 年口径 → 2026 年视角的变化。
- **PyFlink / 多语言成主流**：2026 年 Python 是流处理第一公民（PyFlink、Spark PySpark），
  但实现方式是「主引擎 JVM + Python 进程做 UDF」，而非 C++ 框架自研绑定。
- **WASM 作为沙箱**：用 WebAssembly 跑用户 UDF 在多语言隔离上更安全，是新兴方向（🔧 补）。
- **跨语言序列化**：仍靠 Protobuf/JSON，与第 3 章 3.4 一致。

## 近年研究与工业界开源实践（2015–2026）

- **PyFlink**：`apache/flink`（26367★）的 Python API 是 2026 年多语言事实标准，
  用「JVM 主 + Python UDF 进程 + 状态桥」模式。
- **Apache Beam 多语言**：Beam 的 SDK 跨 Java/Python/Go，体现「一套模型多语言写」。
- **WASM UDF**：如 Kafka/部分引擎探索用 WASM 沙箱跑多语言函数，比子进程更轻更安全。
