## 核心概念速览（中英对照）

- **大海迷航** — Lost at Sea：Bjarne 给 C++17 的判词——"约 21 个语言特性＋13 个库组件，但没有一个称得上 major；找不到统一主题，只是一堆被投票机器抛进语言的'好点子'"
- **major 的定义** — "majorness"：Bjarne 自定标尺——"改变我们思考编程与组织代码的方式"；他直言 C++11 有此 web，C++17 没有，"这让我非常不安"
- **动态异常规约** — Dynamic exception specifications（`throw(T1,T2)`）：1989 年为让异常过关的"首付"；2010 年废弃（Gregor），2017 年**全票**移除——C++ 史上删除旧特性最干净的一次
- **noexcept 规约** — noexcept Specifications：0/1 版异常规约（详见 03 册 §4.5.3）；廉价、可判定、可优化；但"在 throw 与 handler 之间加一个 noexcept，就能让原本正确的程序在运行时 terminate"
- **异常的类型系统支持** — Type System Support for Exceptions：异常进类型系统=函数类型的一部分——被否决的真实理由是**重编译脆弱性**与 C 回调；Bjarne 数出"四种异常方案＋指针函数组合=16 种alternatives"的恐怖图景
- **两轨理想** — Two mechanisms：异常管"稀有或调用方处理不了"，错误码管"就地可处理"；Bjarne 的著名天真问句："**一个错误要多罕见才算 exceptional？**"——答案是 it depends
- **N+1 问题** — the N+1 problem：新错误处理方案进来，旧方案不会消失（异常把流行方案从 7 种变 8 种；(value,error) 对已有"十几二十种变体"）
- **构造函数模板参数推导** — Constructor Template Argument Deduction (CTAD)：Spertus/Smith 攻克——`pair p("Hi!"s,129)` 不再需要 make_pair  workaround；与 scoped_lock 组成 C++17 罕见的"互相支撑"范例
- **结构化绑定** — Structured Bindings：Kona 2015 **午餐前 45 分钟**起死回生；位域需求进场后设计复杂度翻倍——"孤立评估一项新增是危险的"标本
- **variant / optional / any**：三兄弟"案例教科书式的设计失败"——Bjarne 原话："委员会决定标准化这三个类型。不幸的是，三者被当作**用例互不相交**分开讨论……它们是经典的 design by committee"
- **网络库 / asio** — Networking：Kohlhoff 2003 动手、2005 入 Boost、2006 提案 TR2、2018 才成 TS——"生产使用 15 年后我们仍要至少等到 2023"；executors 是它的连环扣（"the best is the enemy of the good"再引用）
- **点运算符** — Operator Dot（`operator.()`）：1990 Adcock 首提案→1991 Koenig/Stroustrup→2004 Powell/Gregor/Järvi→2014/2016 Stroustrup/Dos Reis——"三十年、六份提案、许多讨论与实现工作，**我们一无所有**（we have nothing）"
- **统一调用语法** — Uniform Call Syntax (UCS)：2014 Sutter 与 Bjarne 各自提案随即合并；"接口稳定性"论战（Google 系 vs "该担忧被**极度夸大**"）；2016 战死，遗言：modules 落地后或可借"模块名可见性"复活
- **缺省比较 / 三路比较** — Default Comparisons / `<=>`：Smolsky 2014 递刀；本册只讲到"进入 C++20 成 spaceship"，完整"意外后果" saga 在 06 册 §9.3.4

## 一、§7 错误处理：一篇"四十年辩护词"

7.1 从 C 的遗产讲起：返回码、特殊值（`getchar()` 返回 -1）、errno、回调——"1980 年代的早期用户发现这些技术**令人困惑且不够用**"。(value,error) pair 流行的代价：主流逻辑与错误处理纠缠（"有些系统里错误处理占代码多数也是最复杂部分"）、ABI 传结构体的性能税（"此问题 2020 年仍在，尤其嵌入式 C ABI"）、**构造函数无处返回错误码**。异常（1988–89 设计、ARM 记载、进 C++98）＋RAII 解决了最难的那批问题，运行时代价"通常低于 3%"。但 Bjarne 罕见自我检讨："异常从来不是没有争议的，**我低估了它的争议潜力**。"

7.2 的坦白程度是全文最高的一节：不适合异常的真实场景（小内存、硬实时、不可靠计算机群的 crash-and-restart——"所以所有实现都有 -fno-exceptions 开关"）与 error-code 无解的真实场景（构造失败、运算符、回调、非 C++ 代码、调用链深处新增错误种类、**人忘记检查**）。然后逐条列"实际问题"：烂指针代码的人把矛头指向异常而非旧代码；不懂 RAII 的人把 try-catch 当 if-then 用（"更丑、更大、更慢"）；实现低效（MS 结构化异常泛化、GCC 为保 backtrace 走两遍栈）；**最狠的一条**："为了异常过关我们加了异常规约……宣称的可维护性从未兑现，啰嗦与开销一字不差兑现——而当年喊得最响要规约的人，后来参与了 Java 的设计。"净效应：社区分裂成 exception 阵营与 non-exception 阵营——"no-exceptions 事实上是一门方言，而方言正是标准要避免的东西（§3.1）"。零开销原则是否被违反（Sutter 2018 质疑）一节，Bjarne 引 1989 年 Koenig 的论证（表页可驻虚拟内存）后承认：无虚拟内存的嵌入式场景确是认真问题。

7.3/7.4 是本册实测样例的正面战场：noexcept 是废弃动态规约后的"简化廉价替代"（详见 03 册），但警告 maintenance 加 noexcept 可致 terminate；异常进类型系统（compile-time checked exceptions，Sutter 2018 又提）的否决理由三十年未变——函数重编译风暴＋C 回调函数指针——"少数函数需要两个函数指针参数，否则要面对 16 种组合"。**7.5 "回归基础"**：理想世界只有两轨（异常＋错误码），但 `(value,error)` 变体"广泛使用的有十几二十种（std::map::insert() 就是伪装），2018 年 WG21 还在新增（Botet/Bastien、Sutter）"。Bjarne 的现场实验建议值得抄给每次争论："调用链深 N 层、错误率 1:1000——异常快得多；深度 1、错误率 50%——测试完胜。**差距是整数倍，不是百分之几。**"结尾彩蛋：当年反对者嫌异常**不够**通用（要求 resumption 语义），Bjarne 赌它会让异常慢至少一倍——"看，问题从来不是特性不够，而是方向没有共识。"filesystem 的双接口（每操作两个重载：throw 版＋error_code& 出参版）是"两轨理想"在标准库里的唯一制度化落地。

## 二、g++ 实测：动态异常规约之死与 noexcept 的 terminate（s05/s05b）

```cpp
// s05b.cpp —— 1993 年的"首付"
void old_style(int n) throw(std::runtime_error) {   // 动态异常规约
    if (n < 0) throw std::runtime_error("neg");
}
```

已实测 g++ 15.2：`-std=gnu++98` 编译**通过**（rc=0，"它真的活了二十多年"）；`-std=c++17` 报错：

```
error: ISO C++17 does not allow dynamic exception specifications
  note: 'throw()' replaces 'throw(...)' ...
```

——2010 废弃、2017 全票移除，在本机上能"亲眼看到行刑记录"。

```cpp
// s05.cpp —— noexcept 的双刃
void risky(int n) noexcept {
    std::vector<int> v{1,2,3};
    std::cout << "size=" << v.size() << '\n';
    if (n) { std::cout << "即将违约...\n"; v.resize(static_cast<size_t>(n) - 100); } // length_error
}
int main() { risky(0); }        // 无异常路径：正常退出
```

已实测 g++ 15.2（`-std=c++20`）：编译期即警告 `-Wterminate: 'throw' will always call 'terminate'`——§7.3 "noexcept 把 throw 变 terminate" 被编译器静态抓到；运行输出 `size=3`。把 `risky(0)` 改为 `risky(50)` 后：

```
size=3
即将违约...
terminate called after throwing an instance of 'std::length_error'
  what():  vector::_M_default_append        // exit code = 3
```

——异常在 noexcept 边界被"处决"，本地清理（flush 日志等 §7.3 场景）全部跳过。这正是 §7.2 所列"两阵营"各自论据的机器可复现版本。

## 三、§8 C++17 八小节：21 个"好点子"的成色检验

开篇数据：约 21 语言特性＋约 13 库组件；Bjarne 的总判词（第一节已引）。逐册点评其"互相支撑"程度：

- **8.1 CTAD**（Spertus/Smith 2015）：解决"为什么函数能推导模板参数而构造函数不能"的三十年之问——Bjarne 自白当年被"怕歧义"吓退；推导指南（deduction guides）是歧义逃生门。
- **8.2 结构化绑定**：Sutter/Stroustrup/Dos Reis 2015 提案**迟到**，Kona 2015 会议冻结特性集的当天，" lunch 前剩 45 分钟，我拉 EWG 看了它——minutes 记为 *Encouragement by acclamation*"。生死悬念之后还有两场拉锯：为 complex 类开放自定义 `get<N>()`（"有效但要用户写不雅的样板"）；" late alternatives"病理学（§3.3）现场发作——位域/数组返回值的支持需求进场，"最终设计至少是原提案的两倍复杂。**我对'结构化绑定该支持位域'是否值回它的复杂度，至今存疑**"。
- **8.3 variant/optional/any**：三者都有 Boost 前史（2003 年前后即有实现），标准化却按"互不相交"分头进行，得到**三套不兼容记法**（index 访问/has_value/has_value? 各家口吻）＋访问需要 `std::visit`＋那段"该进标准"的 overloaded 样板（`template<class...Ts> struct overloaded : Ts... { using Ts::operator()...; };`——2020 年仍未进，见后续）。Bjarne 的判词罕见严厉："经典的 design by committee。"
- **8.4/8.5/8.6/8.7**：scoped_lock/shared_lock（与 CTAD 组成 `lock_guard lg{m};` 的罕见"双特性互撑"）；parallel STL（Intel PPL 捐作 C++17 执行策略版）；filesystem（Dawes 2002 Boost→2014 TS→C++17，path 抽象+双错误接口，见第一节）；条件内显式测试（`if (auto p = lookup(k); p) {...}`——"像 for 的条件"）。
- **8.8 四大遗珠**：networking/asio 时间线（见速览）；operator dot 三十年史——2014 N4173 与 2016 P0416R1（✅ 已实测两号可达）"获 EWG 通过但从没进全委员会投票"，死因是"委员对 C++ 是什么没有共享愿景"（→06 册 DG 的由来）；UCS——与 operator dot 相反，**进了**全委员会投票并被 Google 系"稳定性"论点击沉（"类成员集是封闭的所以可管理" vs Bjarne："用命名空间同样能圈定自由函数集"），Bjarne 在 8.8.3 结尾放出全论文最自我批判的一句："**我后悔当年（1985）不该引入面向对象记法**——f(x,y) 足够，还能白送多重方法、省下 visitor 模式这坨 workaround"；default comparisons——Smolsky 2014 递刀，2020 年以 `<=>` 形态进 C++20，"意外后果"完整故事在 06 册。

## 最新演进与工业实践

以"出版后又过了 6 年"（2020→2026）的裁决视角清点：

- **§7 的最大变量：std::expected 落地 C++23**。P2505R5（wg21.link/p2505 ✅302，"Monadic Functions for std::expected"）——Bjarne 数出的"十几二十种 (value,error) 变体"第一次有了**标准版**：`std::expected<int, std::string>` 携 then/and_then/map 单子接口，正是"就地可处理错误"的官方答案；本目录 07 册附第二个实测样例（s07：C++20 编译失败→C++23 通过）。异常阵营未再扩张：动态规约尸体无人喊冤；GCC/Clang 的 -fno-exceptions 阵营与异常阵营在 2023 后出现缓和信号——Google 公开风格指南修订允许在满足 ABI 约束的项目中使用异常（工业实践转向，⚠️ 本笔记未直接核对指南原文措辞）。
- **§8.8 遗珠的六年后账**：networking 仍未全量进标准——Bjarne 那句"至少还要等到 2023"的预言落空为"更久"：其前置条件 executors 执行模型已随 std::execution（P2300R10 ✅302）定于 C++26， asio 系网络库本身截至 2026 仍是 SG4 在途工作（⚠️ 单一"终结提案号"本笔记未逐一实测，不列）；operator dot 的**精神续作** deducing this 成功进 C++23：P0847R7（wg21.link/p0847 ✅302，"Deducing this"）——智能引用喊了三十年没等来 operator.()，等来的是 `this Self&&` 参数，代理类终于可写；UCS 借 modules 名字可见性复活尝试仍未果（⚠️ 未列提案号，未实测）；default comparisons 的 spaceship"意外后果"（== 不再自动合成）已成定局，详见 06 册。
- **工业实践**：`std::optional`/`variant` 三件套记法不互容的代价由生态自补——fmt/abseil 各自提供 expected 前身（absl::StatusOr、tl::expected），"overloaded 样板"已成为 C++17 访客代码的事实惯用法并被广泛抄写（Bjarne"该进标准"六年未进，C++26 亦无共识提案 ⚠️）；filesystem 双接口在 2026 年新代码评审中仍是-no-exceptions 项目的标准依赖。
