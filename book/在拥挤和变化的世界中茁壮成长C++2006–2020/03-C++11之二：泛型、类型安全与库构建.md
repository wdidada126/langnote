## 核心概念速览（中英对照）

- **lambda 表达式** — Lambda：就地匿名函数对象；根脉可追到 BCPL 代码块＋C 反复被拒的本地函数＋函数对象
- **变参模板** — Variadic Templates：`template<typename... Args>`，Gregor/Järvi/Powell（Indiana，2004）贡献，终结"宏＋N 份重载"时代
- **别名模板** — Aliases：`template<class T> using Vec = std::vector<T, My_alloc<T>>`，补齐 typedef 不能带模板参数的缺角
- **tuple** — tuples：函数"多返回值"的标准化句柄，源自 boost::tuple，泛函数式传统的移植
- **静态类型安全** — Static Type Safety：C++11 的立论两理由——把意图写清楚（帮人也帮编译器抓错）＋帮编译器生成更好的码
- **SFINAE** — Substitution Failure Is Not An Error："当且仅当谓词成立才提供操作"的暗黑艺术，概念缺席年代的基础库支柱
- **类型特征** — Type Traits：`is_copy_assignable` 等编译期内省工具，C++11 一次性提供数十个
- **noexcept 规约** — noexcept Specifications：动态异常规约的死与再生——0/1 语义、可判定、近零开销
- **标准库组件** — Standard-Library Components：C++11 新增 hash 容器、chrono、regex、随机数、array、tuple 等的集体亮相

## 一、泛型编程四补件（§4.3）

论文按"改进对泛型编程的支持"统摄这四个子节——泛型编程（GP）是 C++ 标准库的骨架（§10.5.1），C++98 给了容器算法却缺"就地组合"的胶水，C++11 补齐：

- **lambda（4.3.1）**：史实链很讲究——BCPL 允许代码块作表达式，Ritchie 为省编译器空间没进 C；Bjarne 跟 C 走，但用 inline 函数换回"无调用开销的码"，仍缺的是"能携带上下文环境的就地代码"。C++03 时代用函数对象仿冒（写一个类＋构造传参＋operator()），冗长到没人愿意为一次排序写类。论文把 lambda 列为"从别的语言借来的东西进入 C++ 后必然变形"的样板（§2.4）：捕获列表、推导返回类型、与 STL 算法的结合都是"C++ 化"产物。机制教例见 → [../c++之旅3/04-模板与概念和泛型编程.md](../c++之旅3/04-模板与概念和泛型编程.md)。
- **变参模板（4.3.2）**：2004 年 Indiana 三人组（Gregor/Järvi/Powell）提案（N2242 为措辞稿，[wg21.link/n2242](https://wg21.link/n2242) ✅302，标题实测 "Proposed Wording for Variadic Templates (Revision 2)"）。此前"可变参数模板"靠手工 0..9 元重载＋宏生成（boost.function 的 famously ugly 实现）；`Args&&... args`＋`forward<Args>(args)...`＋递归/（C++17 折叠，见本册 04 章呼应）之后，一个模板通吃。与 tuple（4.3.4）同构互撑：tuple 是"编译期可变长记录"，是变参的原生载体。
- **别名（4.3.3）**：typedef 不能带模板参数，于是 C++03 时代"给 traits 起小名"必须套 struct；`using` 别名模板（Dos Reis 2007，N2258，[wg21.link/n2258](https://wg21.link/n2258) ✅302"Templates Aliases"）一举补角——这也是 Concepts TS 时代 concept 与变量模板语法辩论（6.3.6）的舞台板。
- **tuple（4.3.4）**：函数返回多值的老问题（出参、struct 手搓）终于有通用件；论文提醒 tuple 被**过度使用**——"若多个值彼此不独立，我更愿意具名类"。§3.3 的"特性交互"病例也点名 tuple：为孤立可用而膨胀。

## 二、静态类型安全的清单政治（§4.4）

论文的 4.4 不是特性列表而是**立论**：两个理由（表意＋防错→优化）＋一个警告：光靠内建类型（int/string 可代表任何东西）谈不上类型安全——要"细粒度区分"（物理单位检查等，constexpr 帮得上）。清单：线程锁的类型安全接口、range-for、移动语义、资源管理指针、统一初始化、constexpr、用户字面量、**enum class**（消弱类型整数常量）、std::array（消数组到指针的意外 decay）。
关键裁决史实：*"委员会该禁掉不安全特性（内建数组、强转）吗？"*——Bjarne 答"**deprecate 屡试屡败**：用户无视警告并逼实现方保留"。可行路径＝**指南＋可执行检查＋标准保持兼容**（→ §10.6 Core Guidelines/静态分析，本目录 07 册）。这段是理解"C++ 为何不学 Rust 强制安全"的钥匙。

## 三、库构建支持：SFINAE 的辉煌与耻（§4.5）

§4.5.1 开篇是论文自嘲浓度最高的一段：基础库的"暗黑艺术"（dark arts）——多数程序员一生无需知晓，但新手最爱围观最吓人的模板码并（常错地）布道，博主讲者靠炫技赢声誉，"这是 C++ 名声复杂的**主要来源**；别的语言里这种技巧藏在优化器里或不提供"。随后点名 SFINAE：pair 的赋值"当且仅当两成员都可拷贝赋值"——enable_if＋traits 的实现"极丑但极有用"。C++11 的 type traits 家族＋enable_if 全入标准库；副作用是**编译器内部被迫改进**（模板实例化失败要能无副作用回退，抑制了非局部状态）。
§4.5.2 把 2000s 元编程比作**狂野西部**：报错惨烈、编译慢、资源耗尽、人人重新发明轮子。救济双线：语言（concepts〔失败，→ 04 章〕、constexpr、lambda、别名）＋库（tuple、traits、enable_if）。结论句：concepts 失败使"基于 traits＋enable_if 的丑陋易错 workaround"泛滥成风——这段是 04 章三部曲的报幕。
§4.5.3 noexcept：完整的"特性生死样本"——C++98 为让异常过关被迫搭售**动态异常规约**（`void f() throw(X)`，运行时检查、逐层解压重复检查、源码膨胀，全被 Bjarne 言中）；2010 弃用（Gregor N3050 一系），**C++17 一致投票移除**；替代者 noexcept 出自 Abrahams/Gregor 提案：`void f() noexcept` 违约即 terminate、近零开销；**条件 noexcept**（`noexcept(noexcept(expr))`）才是真实动机——vector 移动扩容需要"知道移动会不会抛"来决定走移动还是拷贝强异常保证。实测见下一节 s05 之外另见 05 章。

## 四、C++11 标准库全家福（§4.6）

## 五、g++ 实测：变参模板＋完全转发，C++98 无路可走

```cpp
// s03.cpp 摘要：一个模板顶替 C++03 的 9 份重载；lambda 替代函数对象
template <class T, class... Args>
unique_ptr<T> factory(Args&&... args) {      // 转发引用：&& 此处是"万能引用"
    return unique_ptr<T>(new T(forward<Args>(args)...));
}
sort(begin(xs), end(xs), [](int a, int b) { return a > b; }); // 4.3.1：不写类也能定制比较
```

已实测 g++ 15.2：`-std=c++98` 失败（**10 个 error**：`'unique_ptr' does not name a type`、`'move' was not declared`…）；`-std=c++11` 通过：

```
hello 42 2.71828 ctors=1
desc: 5 4 3 1 1
```

`ctors=1` 直接验证完全转发链只构造一次目标对象——C++03 时代同样的工厂需要为 0/1/2/3 参数写 4 份模板（真实库写 9–15 份）。

## 最新演进与工业实践

- **C++17/20/23 演化补位**：折叠表达式（论文 §8 特性清单点名 [Sutton and Smith 2014] 一系）终结递归模板尾巴；`std::invoke`/`std::apply`（C++17）补 tuple 工具面；**concepts 接管 enable_if**（C++20，→ [04 章](./04-C++14与概念的三部曲.md)）后，新库（std::execution P2300R10 ✅302）一律用 concept 写约束——Bjarne "狂野西部"时代正式落幕。
- **工业界对应**：fmt（Zverovich，后经 §9.3.7 入标）与 range-v3（Niebler，§9.3.5 前身）是 traits+SFINAE 巅峰与 concepts 后时代的分水岭标本；abseil 至今保留大量 SFINAE（须兼容 C++14 库版本），folly 在 F14 容器等热点处仍 SFINAE/concept 混用——读大厂库源码＝读这一节的活化石。
- **现代重估**：noexcept 已成为 ABI 级设计语言（vector 增长、移动构造、swap 三件套），Core Guideline F.6/GS.6 一脉源自本节；"deprecate 必败"论在 2024–2026 硬化路线中得到再验证——治理不安全代码靠工具告警（-fsanitize=undefined、GS 检查）而非删语法。
