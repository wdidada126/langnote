## 核心概念速览（中英对照）

- **隐形的 C++** — Invisible C++：10 章总判断——"对多数程序员 C++ 仍是后台：稳定、可靠、可移植、高性能；对最终用户 C++ 是**不可见的**"；它没有变成 web-app 语言，但咖啡机（Nespresso）、洗碗机、养猪场监测系统（Big Dutchman）与 NASA 深空网络并用同一门语言
- **440 万开发者** — JetBrains 2015 委托调查（Kazakova 2015）：北美/欧洲中东/亚太海量使用、"南美的一些使用=40 万开发者"、总数 440 万；行业排序：金融、银行、游戏、前-office、电信、电子、投行、营销、制造、零售（⚠️ 口径未复核，见 00 册第七节第 3 条）
- **无中心的社区** — No center to the C++ community："我从没有（现在也没有）建立组织的天赋"＋AT&T 贝尔实验室无意做社区 → 各家厂商自建面向自己客户的 C++ 社区；2020 年补救清单：**C++ Foundation**(2014，非营利、只推 ISO C++、主办 CppCon)、**Boost**(1999，同行评审库+年会)、**Meeting C++**(2012，德国起网的 meetup 帝国)、**ACCU**(1984，"所有幸存 C++ 组织的祖父")、isocpp.org、cppreference.com、免费会议视频（YouTube 在部分大国被墙——论文原话）
- **教育哀叹** — Education laments："多数国家的大学生带出**薄弱且不准确的 C++ 理解**——这对社区是严重问题"；"把编程当低层技能而非基础学科"是体制病灶；一学期教不会英语莎士比亚，也教不会 C++ 惯用法；解药：SG20(教育)、Kate Gregory 教学视频、三本书对口分流（PPP 大一/TC++PL 老手 200 页/Discovering DMC++ 数学系）
- **工具链欠账** — Tools：1990s 中期 C++ 工具并不差（GUI/IDE 先行者），之后资金流向可控语言（Java/C#/ObjC）——"正式委员会为所有人利益设计"在投资人眼里是**公地悲剧变体**；宏＋字符流定义=没有可用的内部表示（Dos Reis/Stroustrup 2009/2011 图表示"但社区的文字传统太难克服"）；2020 到货清单：VS/CLion、**Compiler Explorer**(Godbolt 2016)、Wandbox、Qt/GTKmm/wx（"问题不是没有好 GUI 库，是**多到选不出**"；Qt 的 MOP 让程序"不只是 ISO C++"→反射来救）、coverity/clang-tidy、LLVM、build2/CMake、Conan/vcpkg、WebAssembly、Cling/RC++（"26 个编译期代码生成系统、几十个包管理器——**需要的是标准化**"）
- **draw_all 多范式样本** — Programming styles：自 Simula 湿墨绘图仪时代传下来的老例子，C++20 写法 `void draw_all(range auto& seq) { for (Shape& s : seq) s.draw(); }`——同一段代码"显然是 OOP（虚函数+类层级）、显然是 GP（range 概念即模板）、显然是命令式（for 循环）"；Bjarne 的范式观："支持多风格不是为了让你**选一种最爱的**，而是为了**组合它们**表达单范式写不出的更好解"
- **TMP 忏悔录** — Metaprogramming：fac<> 模板阶乘与 constexpr 函数阶乘并排（"要算值，**函数就是最好方式**，尤其在编译期"）；"我见过两百行聪明 TMP 让 30GB 内存的机器编译失败、报错数千行"；"理性程序员发现 TMP 带着疣也比替代方案好——甚至写出高于人肉汇编的代码"；"当人们开始觉得 fac<> 平常，我就担忧"；boost::MPL（最好也最坏的 TMP）→ boost::Hana（constexpr 化）→ SG7 反射
- **核心指南与 SELL** — Core Guidelines："我的终极 C++：显著更简单、完全类型安全（无隐式越界无悬垂）、完全资源安全（无泄漏免 GC）、无宏易造工具、不慢于当下、可预测性能、不减表达力"；安全子集四十年四败因（"定义不了 safe"、**"不安全特性恰是构建安全抽象所需"**、表达力不足、低效）→ "完美靠限制"至多在极窄场景成立 → 纲领句："**助好编程重于防错**（It is more important to enable good programming than to prevent errors）" → 但"指南要在工业规模生效必须**工具可强制**"；方法=SELL（**S**ub**e**t-of-superset，先扩展库底座、再删不安全）＋规则＋基础库＋静态分析鸡尾酒
- **生命周期静态分析** — Static analysis：两大目标（不指已亡对象/不碰失效对象）；`return &x;`（局部）判死、`&glob`/参数/new 放行；vector push_back 后指针失效之难（"哪些函数会搬移对象都说不清；初版把所有非 const 操作都算失效——太保守误报成灾"）；规格 Sutter 2019、实现 MacIntosh→Visual Studio 分析器、clang-tidy、Cevelop；"渐进选择性采纳——全面采纳卡在工具"
- **C++ 模型八支柱** — The C++ model（11.1）：内建/自定义类型平权的静态类型系统／值与引用语义／系统性资源管理（RAII）／高效 OOP／灵活高效 GP／编译期编程／直接与机器和操作系统打交道／库（常以内部指令实现）的并发支持；对"managed 模型"（Java/C#/Python/JS+GC）的替代性宣言——better 的定义六连："**更简、更可能对、更好维护、更省内存、更省能、更快**"；且声明八支柱**互相支撑**（引用语义让 jthread/vector 这类值类型高效；平权规则让 GP 不为内建类型开特例；编译期编程让抽象负担得起……）
- **生态位** — The niche（11.2）："成功理由很简单：**高效使用硬件并管理可观复杂度的应用**——若你烧得起 25% 甚至 99% 的硬件容量，语言多的是；若你的低层需求只有几千行，C 或汇编够用"；2014 版两行摘要（直接映射硬件←C；零开销抽象←Simula"当年那玩意不是零开销"）；2000s 技术功劳簿首条=**内存模型**
- **五块需要补课的田** — Areas that need work（11.3）："进步的障碍**很少是无知**，多半是**缺方向、缺资源、怕破坏存量代码**"；工具（字符流+宏原罪）、教育（backward-looking）、打包分发（"新手想找到-下载-安装-跑起两个主流库，路还很长"）、字符集与图形（语言和标准库**押注 ASCII**，应用全在用 Unicode；图形 GUI 更难）、**清理旧账**（隐式窄化之祸"几千亿行代码 unpredictable 地依赖它"；"加更现代特性替代旧方式"必入 N+1 陷阱）
- **四条经验法则与四种死法** — Lessons（11.4）：法则——问题驱动/从简单高效易用的解**泛化**/零开销/**别弄坏我的代码**；死法——Experts only（一步满足全部专家）/Imitative（"语言 X 流行所以我们要"）/Theoretical（理论说有就必须有）/Revolutionary（重要到可破坏兼容）；总括："**尽早定方向与预期**，晚则人多口杂再无连贯"
- **记住瓦萨号** — Remember the Vasa!：2018 论文点名 51 个在途提案"个个单独看说得通，**合起来是疯狂，足以危及 C++ 未来**"——1628 年瑞典巨舰因设计后期加层未测、首航即沉斯德哥尔摩港；"1990s 委员会常自警瓦萨，2010s 似乎忘了"
- **程序员权利法案** — The C++ Programmers' Bill of Rights（DG 2018）：①编译期稳定（新标准行为变化须可被旧版编译器检出）②链接期稳定（ABI 破坏须罕见+书面理由）③编译性能稳定④运行性能稳定⑤每次修订让某重要领域**更强**⑥每次修订让某重要领域**更简**⑦**按时发货**；"接下来几十年看它如何兑现"
- **C++23 大胆计划** — Voutilainen 2019（布拉格 2020-02 与 C++20 定稿同刻通过）：协程库支持/模块化标准库/executors/网络 四大件＋反射/模式匹配/契约三推进——"重点在库"；远期基本面三条：完全资源安全类型安全的 C++/支持多样硬件/守住稳定兼容纪录

## 一、§10 生态图景：一张"从社区到静态分析"的横切面

§10 开题三句是全章的取景框：领域分布与 2006（§2.3）大体相同——"新增了一些领域，但主要是在相同与相似领域里更宽更深的渗透"；"C++ 没有突然变成 web-app 语言（尽管那里也确有使用）"；然后两句判词入册——"对多数程序员，C++ 仍是**背景里的东西**：稳定、可靠、可移植、高性能。对最终用户，C++ 是不可见的"；真正的剧变在风格侧："**编程风格的变化比领域更戏剧性。C++11 远比 C++98 好：更容易用对、更能表达、性能更好。2020 年部署形态的 C++20 相对 C++11 是一次同量级的改进。**"

10.1 的数据与名单两分。数据：没人知道 C++ 用在何处如何用——2015 年 JetBrains 委托研究〔Kazakova 2015〕给出北美/欧洲中东/亚太"海量使用"＋"南美的'一些使用'=40 万开发者"、**总数 440 万**；行业十强排序（金融、银行、游戏、front office、电信、电子、投行、营销、制造、零售）；"所有迹象都表明 2015 年以来用户规模与使用领域在稳步增长"（⚠️ 口径未复核，00 册第七节第 3 条）。

名单（Bjarne 自认"必然个人化、印象式、极不完整"的十一类，标本级密度照录）：**工业**——电信（AT&T/Ericsson/华为/西门子）、移动设备（"基本上全部"：信号处理、屏幕渲染、性能/可移植敏感应用）、微电子（AMD/Intel/Mentor Graphics/Nvidia）、金融（Morgan Stanley/Renaissance）、游戏（"几乎全部"）、图形动画（Maya/Disney/SideFx）、区块链（Ripple）、数据库（SAP/Mongo/MySQL/Oracle）、云（Google/微软/IBM/Amazon）、AI/ML（TensorFlow 库）、运营支撑（Maersk/AT&T）。

**科学**——航天（SpaceX、火星车、Orion 载人飞船、韦伯望远镜）、高能物理（CERN/SLAC/Fermilab）、生物学（遗传学、基因组测序）、百亿次（exascale）计算；**教学**——"全球大多数工程学院"；**软件开发本身**——TensorFlow、工具、库、编译器、**Emscripten**（C++ 生成 asm.js/WebAssembly）、运行期代码生成、LLVM（"许多新语言与大半工具构建的后端脊梁"）、XML/JSON 解析器、异构计算（SYCL、HPX）；**Web 基础设施**——浏览器（Chrome/Edge/FireFox/Safari）、JS 引擎（V8/SpiderMonkey）、JVM（HotSpot/J9）、Google 级组织（搜索、map-reduce、文件系统）；**大型 Web 应用**——阿里、Amadeus（机票）、亚马逊、苹果、Facebook、PayPal、腾讯（微信）、Yandex。

**工程**——达索（CAD/CAM）、洛克希德·马丁（飞机）；**汽车**——辅助驾驶（ADAS/Mobileye/NVIDIA）、软件架构（AUTOSAR）、机器视觉（OpenCV）、BMW/GM/奔驰/特斯拉/丰田/沃尔沃/大众/Waymo；**嵌入式**——智能手表与健康监测（Garmin）、相机摄像（Olympus/Canon）、导航（TomTom）、**咖啡机（Nespresso）**、牲畜监测（Big Dutchman）、产线温控（嘉士伯）；**安全**——Kaspersky、**NSA**、Symantec；**医学生物**——监护与影像（Siemens/GE/Toshiba/Philips）、断层扫描（CAT）、基因组分析、生物信息、放疗（Elekta/Varian）。

收束三连："这只刮到皮毛"＋"绝大多数使用对（间接）用户不可见"＋"**没有哪个现代大型系统只用一种语言写成**，但上面每一处 C++ 都扮演要角"。最人情味的一段："容易忘记许多用途非常日常、却对你的生活很重要。是的，C++ 在帮 NASA 运行深空网络，但它也在熟悉的小器具里跑着：咖啡机、立体声音箱、洗碗机。**我惊讶地发现它被用于经营现代养猪场的高级系统**。"

10.2 的社区叙事从自省开场："与多数语言社区相比，C++ 社区历来**惊人地无序、碎裂**。问题始于早期——**我从来（现在也是）没有建立组织的天赋**。当时我的雇主 AT&T 贝尔实验室毫无发展 C++ 社区的愿望。"后果：人人自扫门前雪——"Apple、Borland、GNU、IBM、Microsoft、Zortech 等许多公司各自建立了**面向自己客户**的 C++ 社区——但没有总社区，**C++ 社区没有中心**"；杂志少有人读、会议"被吸收或突变成一般性'面向对象'/'软件开发'会议"、没有总用户组。

2020 年补救清单（逐条建账）：**C++ Foundation**（2014，非营利、"推广 ISO C++ 而非任何厂商的 C++"、主办 CppCon）、**Boost**（1999，同行评审库＋建成并使用它的社区＋年会议）、**Meeting C++**（2012，德国起家的用户组网络，"几十场大会与小聚会"）、**ACCU**（1984 年作为 **C** 用户组创立，"所有幸存 C++ 组织的祖父"，出两本杂志办年会）、isocpp.org（基金会官网）、cppreference.com（"出色的在线参考——**甚至自带历史区**！"）、会议群像（CppCon/ACCU/Meeting++/C++ Now（前身 BoostCon）/Qt/NDC/std::cpp＋波兰俄罗斯中国以色列多处＋"一般软件大会上的 C++ 专题也在增多"）、博客与播客、**视频**（"已成为 C++ 新动向的主要信息源；大会普遍免费挂讲稿视频；访谈视频走红；最大托管站 YouTube——**不幸在 C++ 开发者大军所在的一些大国被墙（例如中国）**"）、GitHub（"共享代码与组织联合项目更容易了"）。结算句："这远不能与某些语言/厂商的集中式组织相比，但它是**一组活跃多变的互联社区**，比 2006 年热闹得多得多"（企业用户组仍在）。

10.3 教育："自 2006 年的惨淡状态以来 C++ 教育改善了吗？**也许吧，但它肯定仍不是 C++ 的强项**——新努力多半面向在职人员的资讯与培训。多数国家的大学生离开校门时带着**薄弱且不准确的 C++ 理解**——这对社区是严重问题。**没有一门语言能在一贯供应熟练掌握其关键设计与实现技术的热情程序员的工业规模上成功而没有它**（意译：工业规模的成功需要稳定supply）！"体制病灶："教育机构常把编程当作低层技能而非奠基性学科。**好软件对我们文明不可或缺**——管理它，需要像对待数学物理一样严肃地对待关键系统的软件开发。"一揽子解方三连："一刀切的教学不成立；**一学期不够**。我们不会指望几个月教完英语就盼学生欣赏莎士比亚——懂语言的机械语法与掌握专家惯用法是两回事。C++ 像任何主流现代语言一样需要**按学习者背景与需求调配的多种教学法**。"即便机构有心，课程表过挤、教师难追工业实践——SG20（教育）在描绘现代 C++ 教学路径、SG15（工具）可能因让教学工具更易得而变得重要。2011 年以来的意识觉醒案例：Kate Gregory 的教学视频系列〔2015/2017/2018〕；三本书按人群分流——**PPP**（大学新生与自学）、**Tour of C++**（约 200 页、给老手）、**Discovering Modern C++**（Gottschling，数学背景强的学生）；Bjarne 自陈两篇半学术文（Software Development for Infrastructure 2012、What should we teach software developers? Why? 2010）＋**CppCon 2017 开幕主题演讲《Learning and Teaching Modern C++》**。2014 年前后视频与网课暴涨——"这对 C++ 特别合适：**不需要中心组织也不需要大额资金**"。

研究抽样清单（八大类，本目录视角拣要）：概念/GP（Dehnert & Stepanov 2000、C++0x Concepts〔Gregor 等 2006〕、使用模式〔Dos Reis & Stroustrup 2006〕、库设计〔Sutton & Stroustrup 2011〕）；理论与形式化（继承模型、模板与重载、模板语义、对象布局、构造析构、**代码操作的表示**〔Dos Reis & Stroustrup 2009/2011——modules/反射的远祖〕、资源模型〔Stroustrup 等 2015〕）；动态查找（快速 dynamic_cast、模式匹配、多重方法）；静态分析（可靠表示、实践经验〔Engler 组"几十亿行之后"〕）；性能（代码膨胀、异常实现）；语言比较；并发并行（**Batty 等内存模型形式化三部曲 2011/2012/2013**、HPX、STAPL、TBB）；协程（数据库优化实证）；软件工程（代码组织与优化、常量表达式求值）。Bjarne 判词："还有大量机会（异常处理、编译期编程、资源管理＋实效实证研究）"；社区学术习惯一句趣谈："**最活跃的成员们极少愿意写学术论文——写书似乎更受欢迎**。"

10.4 工具链欠账的两页账。史：1990 年代初 C++ 的工业工具与编程环境并不差——"图形用户界面与集成开发环境就是为 C++ **率先**开拓的"；随后"开发与投资的重心转向**专有语言**（Java/C#/Objective-C）与**更简单的语言**（C/GNU）"。病因两条：①**资金**——"组织偏好**自己能控制、能对竞品形成差异化优势**的语言与工具。从这个视角看，C++ 由一个强调'所有人受益'的正式标准委员会控制反而是劣势——**公地悲剧的一个变体**"；②**宏与文本定义**——"C++ 没有简单、广泛可用的内部表示来便利基于源码造工具；宏的滥用**保证程序员看到的不是编译器分析的**。像 C 一样，C++ 用字符序列而非直接代表抽象的构造来定义。我和 Dos Reis 定义过这样的表示〔2009/2011〕，**但社区字符导向的传统太难撼动——给未按此建造的东西 retrofit 规整结构，难**。"后果："2006–2020 年间 C++ 在支撑工具上被其他语言打得满地找牙。"

回暖清单（九类标本）：工业级 IDE（Visual Studio、CLion——不止编辑调试、还有分析与简单变换）；**在线编译器**（Compiler Explorer〔Godbolt 2016〕、Wandbox——浏览器里编译/运行，"用于实验、审视代码质量、比较编译器与版本"）；GUI 库（Qt/GTKmm/wxWidgets——"不幸 Qt 依赖元对象协议 MOP，**Qt 程序不只是 ISO C++**；静态反射终有一天解掉它。C++ 社区的问题不是没有好 GUI 库，而是**多到选不出**"）；分析器（Coverity、VS 的 Core Guidelines 分析器、clang-tidy）；编译器工具底座（LLVM——"不只 C++，恩泽众新语言"）；构建系统（build2/CMake/GNU make——"照例，没有标准就难选"）；包管理器（Conan/vcpkg）；运行环境（WebAssembly——"把 ISO C++ 编成浏览器字节码的系统"）；运行期编译/JIT（Cling——CERN 交互解释器、RC++）。判词："上面只是样本。照例，用户的问题是**备选项的数量**：RC++ 列了 26 个编译期代码生成系统、包管理器几十个。**需要的是某种标准化**。""截至 2020 年，工具仍不是 C++ 的强项，但全线都在进步。"

10.5 多范式章眼与两份谱系。开篇立论："演化的一个关键驱动力：**多数现实问题的最优解涉及技术组合**。这当然冒犯了自称'单一简明最优解（编程范式）'的人——但支持多风格从来是 C++ 的根本强项。"标本：自 Simula 湿墨绘图仪时代传下来的 draw_all 例子，C++20 写法（`void draw_all(range auto& seq) { for (Shape& s : seq) s.draw(); }`）——"这是什么范式？"三句连答："显然是 OOP（虚函数＋类层次）；显然是 GP（用 range 概念参数化即模板）；显然是传统命令式（for 循环＋f(x) 调用）"。可继续加码：Shape 通常有可变状态、可以用 lambda、可以调 C 函数、可以再加 Drawable 概念约束——"按'更好'的各种定义，**合适的混搭胜过任何单一范式能给我的解**"。收束句（速览条）："支持多风格的本意不是让你挑一种最爱，而是**组合使用**以表达单风格写不出的更好解。"10.5.1 GP 谱系四拍：2006 年大量代码仍是"OOP 风格＋C 风格"混合（2020 年依然不少）；C++98 让 STL 式 GP"广为人知"、用户代码开始越过标准库的简单应用；**C++11 的 GP 强化"开闸放水"（opened the floodgates）进生产代码**；"C++17 没有 concepts 至今仍在拖累 GP 的使用"。文化氛围一句："**几乎所有专家都读过 Stepanov & McJones 的《The Elements of Programming》（EoP）并受其影响**。"脊骨清单（泛型模板撑起标准库）：容器、ranges、算法、iostreams、file system、随机数、线程、锁、时间、字符串、正则、format——每一处都回指前面各册。10.5.2 TMP 忏悔录（速览条的完整底稿）：出身"与 GP 同源（都靠模板）"；根子=模板图灵完备的发现〔Vandevoorde & Josuttis 2002；Veldhuizen 2003，"以多少有用的形式提供编译期纯函数式编程"〕；判词三连——"常常**非常丑**；有时用宏遮丑、**制造更多问题**；但**TMP 的实用性的明证是它几乎无处不在——不写元编程就实现不了 C++14 标准库**"；技术史定位：多数技巧 2006 年前已有，是"C++11＋更好的编译器＋变参模板＋lambda"给了它主流的临门一脚；库侧补给——conditional（`conditional<(sizeof(int)<4), double, int> x;`"int 太小就用 double"）、type traits（"X 能安全逐位拷贝吗？"）、enable_if。标本对照双码：fac<> 模板阶乘（enum 承载值＋0 特化收口）——"**特化是关键角色，是 C++98 里被严重低估的特性**（算决策表、展开循环）"；constexpr 函数版阶乘并排——"**要值，函数就是计算它的最好方式——尤其恰恰在编译期**。传统模板元编程最好留给计算新类型与控制结构"。黑历史实录："聪明库与真实代码里，enable_if 级原语撑起了数百乃至数千行的程序；早期 TMP 炫技含**完整编译期 Lisp 解释器**〔Czarnecki & Eisenecker 2000〕。**调试极难、维护可怕（horrendous）**；我见过两百行（承认是聪明的）TMP 把编译拖进分钟级、**在 30GB 内存的机器上编译到内存耗尽而失败**；小错的编译器报错可达数千行。**然而 TMP 被广泛使用——清醒的程序员发现它带着疣也胜过替代品；我见过 TMP 生成的代码好过我认为称职人手写的汇编**。"担忧句："当人们开始把 fac<> 这样的代码**当作平常**，我就担忧。那不是表达普通数值算法的好方式。"解药：concepts＋constexpr"能戏剧化简化元编程"；库侧编年——Järvi 的 boost::lambda"是 TMP 的早期应用，帮人们确信 lambda 有用**且需要语言直接支持**"（回指 03 册 §4.3.1）；boost::MPL"端出传统 TMP 的**最好与最坏**"；boost::Hana"用 constexpr 的更现代库"；WG21 研究组"在培育更好的标准元编程系统、连编译期反射一起"。

10.6 是"指南"两页，先亮终极靶心（速览条六连原样）："我的终极 C++：显著更简单／完全类型安全（无隐式违例无悬垂）／完全资源安全（无泄漏免 GC）／无宏易造工具／不慢于当下（零开销）／可预测性能（嵌入式适用）／**不减表达力（好好驾驭硬件）**"——Bjarne 自注"这与《D&E》(1994) 的设计目标没什么两样。**显然是个天价订单，且与多数老 C/C++ 用法不兼容**"。安全子集四十年四败因（速览条）之后是纲领翻转："**It is more important to enable good programming than to prevent errors**"→ 需要的是"好用法"的**指南**而非语言规则——"但要在工业规模生效，指南必须**工具可强制**"。悬垂指针作反面教材：`int* p = new int{7,9,11,13}; ... delete p; ... *p = 7; // likely disaster`——"许多程序员有防悬垂技巧，但悬垂仍是多数大型代码库的大问题，且**安全问题比过去严重得多：某些悬垂指针可被当作安全漏洞利用**"。

10.6.1 一般方法（SELL，速览条的完整底稿）：谱系两笔——2004 年参与飞控软件编码指南〔Lockheed Martin 2005〕"近似我的安全/灵活/性能理想"；2014 年动笔广谱指南，动机一半是"用好用 C++11 的**响亮需求**"、一半是"**看到某些人自认为的好 C++11 而毛骨悚然**"。随即发现同路人众，于是老手＋工具建造者＋库建造者合流开 C++ Core Guidelines 项目〔Stroustrup & Sutter 2014–2020〕：MIT 开源、贡献者名单挂在 GitHub、早期主力含摩根士丹利（Bjarne 自居）、微软（Sutter/Dos Reis/MacIntosh）、红帽（Wakely）、CERN、Facebook、Google。"不是唯一的指南项目，但**最高调也最有野心**"——完全类型/资源安全的理想与基本模型早在〔Stroustrup et al. 2015〕给出。**鸡尾酒三味**（各配自限）：①规则（大集，荐有效实践、禁已知错误源）②基础库（多数取自标准库 variant/vector，加一小册 ISO C++ 写的 GSL）③静态分析（检测违规、强制关键条）——"每味都有长历史，**单味都扛不动工业规模**；我最看好的那类分析（如消悬垂）在程序员可任意分离编译＋动态链接的前提下**理论上不可能＋算力上不可行**"。方法命名 SELL〔Stroustrup 2005〕（速览条两拍）。GSL 的终局写得最清楚："**想法是最终消灭 GSL——让它被 ISO 标准库吸收**。span 已进 C++20 作证；GSL 里那点可怜的契约支持，一旦真正的契约可用（9.6.1）就该换下。"

10.6.2 静态分析（速览条的完整底稿）加两条注脚：规模化的代价是**彻底局部化**（一次一个函数/一个类）；"要让程序安全容易——**全禁就是了**。但同时保住 C++ 的表达力与性能才是指南的目标，所以不能靠限制换安全：**要的是更好的 C++，不是被阉割的慢子集**。"指南的附带红利："把教育聚焦到 C++ 更有效的一面（陈述原则、显式化好实践、机械化已知问题检查），也**减缓语言直接迎合时髦的压力**。"落地名单：规格=Herb Sutter 2019、实现=其微软同事＋MacIntosh 初版进 Visual Studio、部分规则进 Clang 与 HSR 的 Cevelop（Eclipse 插件）、若干课程与书采纳规则〔Stroustrup 2018f〕。结句即速览条"渐进选择性采纳——**全面采纳卡在工具**"。本章两个钩子由此挂齐：**其一**，10.4 的 Compiler Explorer/Wandbox 把"改一行看汇编"的实验成本打到零——**实验民主化**是风格迁移（10.5）得以发生的物质基础；**其二**，GSL 是"库先行、语言后进"三级火箭的燃料舱：`gsl::span`→`std::span`（9.3.8）已点火，GSL 契约→语言契约（9.6.1）在 06 册§六看它能否起飞——Bjarne 在 11.5 会把这枚火箭写成一般定律："**库、指南与工具常是语言改动的更优替代**"。

## 二、§11 四十年回望：模型、生态位、补课清单、课程表

§11 开题把"语言设计者何时开始欠债"说得斩钉截铁："语言设计的终极目的，是改善程序员思考与工作方式、交付有用应用。有的语言被认定为'仅是实验'——但**一旦一门语言被用于与语言自身无关的工作，设计者就对用户负起了责任**：正确性、恰当性、稳定性、足够性能成了大事。**对 C++，这发生在 1979 年——仅仅 6 个月之后**。C++ 兴旺了 40 年。为何？如何？"然后把本文与前两篇 HOPL 的分工划线：1993/2007 两篇从 1991/2006 视角作答；"搁下语言特性与库组件不谈，此后**变化最大的恰恰是标准委员会的角色与影响（§3）**"——这句是全论文对"从个人天才到委员会治理"这条暗线的官方盖章。

11.1 C++ 模型（速览条八支柱的完整展开）。先立功劳簿性质："C++ 脱颖而出成为对苛刻应用主要、部分领域主导的语言——**没有严肃商业背书，没有营销**。许多现代语言从它复制了特性与想法（2.4）。"八支柱逐条带论文内引用（此处按册归口）：①内建/自定义类型**平权**的静态类型系统（§2.1）②值与引用语义（§4.2.3——03 册move 主线）③系统性的通用资源管理 RAII（§2.2）④高效 OOP（§2.1）⑤灵活高效 GP（§10.5.1——本节）⑥编译期编程（§4.2.7）⑦**直接使用机器与操作系统资源**（§1）⑧经库（常以内部指令实现）的并发支持（§4.1/§9.4）。对"managed 模型"（Java/C#/Python/JS 的 GC＋厚重运行期）的替代性宣言后面缀着 better 的六词定义（速览条）——注意原文的谦词是 "for many application areas better"，不是普适。

八支柱**互相支撑**的四例（速览条括注的出处）：引用语义（裸指针与智能指针）让带值语义的高级类型（**jthread、vector**）得以高效实现；内建/自定义平权规则让 GP 不必为内建类型开特例；编译期编程让一整套抽象技术"对有效利用硬件变得**负担得起**"；RAII 让自定义类型**无需任何专门配合**就能管理资源——包括内存之外的资源。这四条把 02–06 册的散点焊回同一块底盘。

11.2 技术成功，先给生态位（速览条）并补两句上下文："根本原因很简单：填补了编程版图上重要生态位——**需要高效使用硬件并管理可观复杂度的应用**。"两个边角都圈死了：烧得起 25%/99% 硬件容量则语言多的是；低层需求只有几千行则 C/汇编足够。"40 年里，这个生态位**大到足以让社区持续增长**。"2014 版两行摘要（速览条）后 Bjarne 特别澄清：与 1995《D&E》的描述相比，"焦点从编程技巧移到了问题域——**那是讲解风格与受众兴趣之差，不是语言设计之差**。两个摘要今天准确，当年也准确。"

2000s 技术功劳簿（11.2 清单，速览条"首条=内存模型"的完整版）：①**内存模型**（§4.1.1——一切 type-safe 并发的地基）②type-safe 并发：线程与锁（§4.1.2）、并行算法（§8.5）、可汇合线程（§9.4）③类型推导：auto（§4.2.1）、concepts（§6）、模板实参推导（§8.1）、变参模板（§4.3.2）④简化使用：auto、range-for（§4.2.2）、并行算法、ranges（§9.3.5）、lambda（§4.3.1）⑤**move 语义**（§4.2.3）⑥编译期编程：constexpr（§4.2.7）、编译期循环（§5.5）、编译期求值保证与容器（§9.3.3）、元编程（§10.5.2）⑦GP：STL（§10.5.1）、concepts、用户自定义类型作模板参数（§9.3.3）、lambda ⑧元编程（§10.5.2）。Bjarne 自评："条条与零开销原则相关，**但最后两条有点出人意料**——因为 2006–2020 这段时间 C++ 对它俩的支持并不完整。"收束两段（速览条两句的出处）："若 C++ 碎裂成不兼容方言、或长期不可依赖，以上全部作数不了——**稳定与兼容是命根子（1.1/11.4）**"；C++11 起的新特性带出了标准库改进（**unique_ptr、chrono、format、scoped_lock** 点名）与众多他库。最后一句把功劳转给使用者："C++ 的目的是**造应用**的工具——那些伟大应用（2.3/10.1 所列）才是 C++ 真正的成功。"

11.3 需要补课的田（速览条五块的完整底稿）。开题先破"无能论"："没有哪门语言对所有人所有事都完美——**最懂这点的正是同时认真使用并维护多门语言的人**。进步的障碍很少是无知；真正拦路的是**缺方向、缺开发资源、怕破坏存量代码**。"病根一句："C++ 生在**现代 IDE、构建系统、GUI 体系与 Unicode 之前**。我预期它慢慢追上。"五块田逐块（速览条）：工具（字符流＋词法 token＋#include/宏组织源码是造工具的主要屏障；modules 应当帮忙，规整内部表示本来就能造〔Dos Reis/Stroustrup 2009/2011〕）；教育（今天教的 C++ 大多仍**过时、 backward-looking**；核心指南是一种现代化路径，SG20 与会议教学专场说明问题已被领认）；打包分发（"C++ 生在'用独立开发维护的部件组装软件'普及**之前**"；构建系统与包管理器有了但**没一个标准**——有的难做简单事、有的扛不住 C++ 级巨型系统；2017 CppCon 主题演讲向社区下战书；"Boost 是努力、GitHub 在成形，但**新手要找到-下载-安装-跑起两个主流库，路还很长**"）；字符集与图形（语言与标准库**押注 ASCII**、应用全用 Unicode，SG 在找标准化出路；**标准图形/GUI 缺席是更难的问题**）；清理旧账（"令人不快地难"——隐式窄化之祸人尽皆知，但**几千亿行代码以不可预测的方式依赖着它**；"加现代特性替代旧方式"必然踩进 N+1 陷阱（§4.2.5）；**更好的工具（静态分析与程序变换）是唯一的希望**"）。收束（速览条外）："大型语言社区的挑战多样、**没有单一简明解**；这不只关乎语法、类型论或基础设计——**有些问题是商业性的**。工业规模成功所需技能之广令人气短。时间会证明社区能否全部接住。**我 modestly optimistic（有所保留地乐观）——因为每个领域都有倡议在跑（3.2）**。"

11.4 经验教训。前提："C++ 由一个**成员多元且流动的大型委员会**掌控（3.2），所以除技术问题还得看**过程里什么管用**："四条经验法则（速览条）原文——Problem driven（由真实世界的具体问题驱动）／Simple（**从简单、高效、易用的解泛化**而生）／Efficient（语言与标准库服从零开销原则）／**Stable（别弄坏我的代码！）**。配文两条："最成功的那部分（全部？）都守了这四条'经验法则'。它们天然**限制语言的范围——这是好事。C++ 不打算做所有人的所有事**。"且"这些原则迫使 C++ 基于真实挑战**相对缓慢地生长**、吃得到反馈"——与《D&E》和 HOPL2 的法则清单同脉："**There is continuity.**（这是连续的）"。反面四死法（速览条）原文补一句判决："**没有对准大社区问题清晰聚焦而设计的设施通常失败**。"课程表批判（速览条外的重话）："委员会章程几乎只关注语言与库设计——**这有局限性**。动态链接、构建系统、静态分析这些重要话题被大多忽略。**That's a mistake.** 工具是开发者世界的巨大组成部分，它们不该在语言设计的边缘徘徊。"——10.4 的工具欠账在此升格为过程教训。**记住瓦萨号**（速览条全史）：2018 论文点名 51 个在途提案的原文长引——"我列的是我认为**能显著改变我们写码方式**的提案，每一个都对教学、维护、编码指南有重大意义，多数还牵动实现。**单独看，许多（多数？）提案都说得通。合起来是疯狂，到了危及 C++ 未来的地步**。"论文接着解释船："瓦萨是 17 世纪瑞典的宏伟战舰，因设计**后期加码＋测试不足，首航即在斯德哥尔摩港沉没**。**1990s 委员会常以瓦萨自警；2010s，这课似乎忘了**。"DG 的约束尝试（速览条七条的原文口径）：编译期稳定＝"新标准中任何显著的**行为变化，必须可被上一版标准的编译器检出**"；链接期稳定＝"ABI 破坏须回避，例外罕见且**须书面理由**"；编译性能稳定＝"不给存量代码带来显著额外编译开销"；运行性能稳定＝"不给存量代码带来显著额外运行开销"；Progress＝"每次修订让某个重要编程活动或社区**获得更强支持**"；Simplicity＝"每次修订让某个重要编程活动**获得简化**"；Timeliness＝"每次修订按公示日程**按时发货**"。Bjarne 只留一句判词："**接下来的几十年将见分晓**。"（本笔记"最新演进"节替 2026 年的读者对了一部分账。）

11.5 未来，三层时间尺度。近期（速览条前半）："**C++20 将对社区有 C++11 同等的恩惠**。"布拉格 2020-02 定稿 C++20 的**同一场会**上还表决通过了 Voutilainen 的 C++23 大胆计划（速览条）——四大件后 Bjarne 加了那声重要的注脚："**注意：重点是库**。"推进三件后是一句罕见的选情预测："这些题目工作已相当先进，**委员会大概率能完成大半**；那么大一帮热心人能再折腾出什么、达成共识，就难说了。"中期（委员会内）：DG 点名四个可继续开垦的方向〔Hinnant et al. 2020，Bjarne 本人是 DG 成员〕——**改善 Unicode 支持／简单图形与简单用户交互／支持新型硬件／探索更好的错误处理风格与实现**（第四条正是 05 册整册主线的官方续命）；委员会外，"我预期构建系统、包管理、静态分析会有大进展（10.4）"。远期（速览条基本面三条）："再往后——五年十年或更多——**我的水晶球开始起雾**。那个尺度要看基本面而非具体特性。希望委员会听话（11.4）、盯住基本面（11.1）：追求完全资源安全类型安全的 C++／好好支持多样的硬件／守住稳定（兼容）纪录。"守成的机理说得很白："**维持稳定需要既盯兼容、又忍住诱惑**——不去靠堆一堆'完美'特性替换不完美的或不时髦的旧方式。**新特性必然带来惊讶（有的讨喜，有的不讨喜）**，而旧特性不会自己消失。**Remember the Vasa!** 常常，库、指南与工具优于语言改动。"

远期压力清单四味（速览条外的原文）：**硬件**——"单线程计算不再变快，效率的溢价就还在，各种并发并行的支持压力只增（2.3）；专用硬件会大量滋生（多种内存架构、专用处理器）——**这反而利好 C++ 这类能用上它的语言**。唯一比硬件性能涨得更快的，是**人类的期望**。"**复杂度**——系统越来越复杂→负担得起的抽象机制越来越要紧；实时交互系统里可预测性能是硬要求（"许多实时系统**禁动态存储**"）。**安全**——依赖加深＋高手黑客增多→"防守一方，**我押硬件保护与支撑更好静态分析的结构化系统**，而不是无尽的低层临时运行期检查"。**互操作**——"语言与系统之间的互操作仍将不可或缺；**很少有大系统用单一语言写成**"（回指 10.1 收束句）。教育是压轴（速览条外的完整判词）："系统更复杂、可信要求更高→**对设计与编码质量的需要在暴涨**。我认为 C++ 准备得不错、C++23 计划还会加固它。**但光有语言特性不够**——需要**工具支撑的指南**保证有效使用（10.6），尤其要把完全类型安全与资源安全落到实处，并且**反映到教育里**。要兴旺，C++ 需要更好的新手教材、也需要帮老手掌握现代 C++ 的材料——**聪明炫技与高级用法的演讲不仅不够，还会伤害语言**（坐实它'复杂'的坏名声）。"

收官两段的成色配得上全文结尾。方法论反转（速览条的完整底稿）："出于很多原因，**我们要简化 C++ 的大多数日常用法**。C++ 已演化到允许这样做，我预期趋势继续（4.2）。**配得上代码中类型系统与抽象的更好优化器**正在起作用。过去几年这戏剧性地改变了我优化代码的方式：**我先把聪明复杂的玩意儿扔掉——bug 就藏在那儿；如果我理解起来都费劲，编译器和优化器也一样**。这条路通常给我**小到可观**的提速，顺便简化未来的维护。只有到还达不到我要的性能，才动用高级（即复杂）数据结构与算法。**这是 C++ 抽象机制设计的胜利。**"最后的告别词把镜头摇向其他语言："我期待看到更多用 C++ 造出的激动人心的应用、更多新惯用法与设计技术。**我希望其他语言从 C++ 的成功里学到东西——若 C++ 演化的教训只留在 C++ 社区，那就可悲了。**我指望在别的语言与系统里看到 C++ 模型的关键侧面——那才是**成功的真正度量**。一定程度上这已经发生（2.4）。"

## 三、g++ 实测：§7.5 与 §9.3.7 的合订兑现——std::expected 进 C++23（s07）

```cpp
// s07.cpp —— "就地可处理的错误"终于有了标准词汇；printf 式格式化类型安全入标
#include <format>
#include <expected>
std::expected<int, std::string> to_int(std::string_view sv) {
    int v; auto [p, ec] = std::from_chars(sv.data(), sv.data() + sv.size(), v);
    if (ec != std::errc{}) return std::unexpected(std::format("bad input: {}", sv));
    return v;
}
```

已实测 g++ 15.2：`-std=c++20` 失败（`error: 'expected' does not name a type`——论文截止 2020 年时它还在 P0323 之路上）；`-std=c++23` 通过，运行输出：

```
parse(42) -> 42
parse(oops) -> error: bad input: oops
```

工具链坦白（⚠️ 00 册第七节第 5 条）：同机本想用 §9.3.7 家族的 `std::println` 输出，编译过而**链接失败**（`undefined reference to std::__open_terminal`）——MinGW 15.2 build 的 print 后端缺陷，非标准问题；样例改用 `std::format` 流。一个 2026 年的 C++ 学习者在这台机器上同时收获标准演进史（expected：论文在途→已交付）与工具链滞后史（print：已交付→未就绪）——恰是 11.3"补课清单"的活体标本。

## 最新演进与工业实践

以"出版后又过了 6 年"（2020→2026）的裁决视角清点 §10–§11：

- **权利法案第 7 条首考及格**：C++23 按 2024-02 如期批准（无延期）；C++26 目标 2024-12 冻结后的下一班（2026-06 前后）——"按时发货"目前 2/2，但第 1/3 条的成色由 hardening 议题检验：P2674（wg21.link/p2674 ✅302，"hardening"谱系——带既有函数安全替换/静态断言化）是"编译期稳定＋工具强制"路线的 2023 新证据（02 册同款引用互见）。
