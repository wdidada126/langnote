## 核心概念速览（中英对照）

- **内存模型** — Memory Model：多线程下原子量与内存序的正式语义，C++11"庞大且不可或缺"的地基
- **线程和锁** — Threads and Locks：thread/mutex/lock_guard 层；Bjarne 称之为"最糟的并发模型，但对系统语言必不可少"
- **期值** — Futures：packaged_task/async/future 的更高层抽象，源自 Multilisp 谱系
- **自动类型推导** — auto and decltype：从初始化式推导类型，"老如群山"（1983 年就实现过）
- **范围 for** — Range-for：对序列 first..last 的整容器循环，直接灵感是 STL 序列
- **移动语义** — Move Semantics：将亡值窃取句柄，补全 1979 年构造/析构开始的资源管理闭环
- **资源管理指针** — Resource-Management Pointers：unique_ptr 独占所有权、shared_ptr 计数共享，"智能指针让泄漏成为历史"
- **统一初始化** — Uniform Initialization：花括号初始化统一多种初始化记法并禁窄化
- **nullptr** — nullptr：类型安全的空指针字面量，取代 0/NULL 重载歧义
- **constexpr 函数** — constexpr Functions：把值计算写成普通函数并在编译期求值，终结宏滥用
- **用户定义字面量** — User-Defined Literals：让自定义类型拥有与内建类型同等的字面量记法（1.2+3.4i）
- **原始字符串字面量** — Raw literals：免转义字符串，正则与 Windows 路径救星
- **属性** — Attributes：`[[...]]` 给实体附加任意信息（carries_dependency 等）
- **垃圾收集** — Garbage Collection：C++11 采纳 Boehm/Spertus 的可选 GC 接口，"几乎无人注意到"

## 一、为什么 C++11"感觉像一门新语言"（§4 开篇）

论文引 Bjarne 自己 2013/2014 的判断"C++11 feels like a new language"被广泛认为准确。原因：特性不是散点，而是**密集互撑网**——auto/range-for/move/smart pointer/lambda/constexpr 组合起来改变了"写 C++ 的方式"。本目录 02/03 两册覆盖论文最大的单节（§4 约 20 页）。本册讲并发（§4.1）与"简化使用"（§4.2）——后者正是"简单的事情变简单"纲领的集中兑现。

## 二、并发三件套：从硬件现实到类型安全（§4.1）

§4.1.1 内存模型：多核、缓存、推测执行、指令重排之下必须精确定义访存规则。史实点名：IBM 的 Paul McKenney 长期推动内存保证；剑桥 Mark Batty 的形式化研究（Batty et al. 2010–2013）与 McKenney 等 2010 论文（13 人联署含 Boehm/Williams/Owens/Sarkar/Sewell/Weber/Wong/Crowl/Kosnik）支撑了正式化——"这是 C++11 庞大且不可或缺的一部分"。三则论文亲曝的内幕：

- **Java 模型否决案**：委员会起初想直接采纳 Java 内存模型（Pugh 2004）——"我发现 Intel 和 IBM 的代表实际上一票否决了这个主意，理由是：**给 C++ 采纳 Java 模型会让所有 JVM 至少慢两倍**——为了保护 Java 的性能，我们只好给 C++ 采纳一个复杂得多的模型。然后充满讽刺且可预测地，C++ 因为内存模型比 Java 复杂而被批评。"
- **双原语拼车**：最难的决定是同时接受 Intel x86（TSO＋少量原子操作）与 IBM PowerPC（弱一致性＋栅栏）——"逻辑上只需一套；McKenney 说服我：深埋复杂算法里的栅栏存量代码太多，IBM 不可能改弦更张。有一天我 literal 地在大房间两个角落间做**穿梭外交**。后来我建议两套都支持——成了 C++11 的方案。再后来人们发现栅栏与原子量合用胜过任何单独一套，我（和别人）非常欣慰。"
- 理论底座：happens-before（Lamport 1978）＋可选顺序一致（Lamport 1979）＋atomic 类型与无锁编程支持；C11 后来采纳同一模型，但 C 投票前最后一刻塞进的记号不兼容"成为 C/C++ 实现者的长期痛点"。裁决视角：没有内存模型，后面所有库级并发（含 §8.5 parallel STL、§9.4 jthread）都无从谈起；"多数程序员看不见它——一阶近似下它只是**让代码按你期待的方式工作**"（被严重低估的原因）。

§4.1.2 线程和锁：类型安全的 threads/locks 取代 POSIX/Windows 的 `void**`＋宏（§4.4 把这点列为"提高静态类型安全"条目）。论文原话的四件套：thread（join/detach）、mutex（lock/unlock＋保证解锁的 RAII 包装）、condition_variable、thread_local。细节档案：

- 线程库首提案：Pete Becker（Dinkumware）2004，基于 boost::thread 接口的自家实现——**与首份内存模型提案（Alexandrescu et al. 2004）同台提交**（2004-09 Redmond WA 会议）；
- 设计依赖声明：`std::thread` 构造函数是**变参模板**（→ 03 册 4.3.2），lambda（→ 03 册 4.3.1）让 `<thread>` 的多数用法简化——"语言新特性同届用于标准库"被论文总结为四条红利：更好的库、好用法示范、免造轮子、**逼特性设计者直面真实用例**（当时的反对声："太激进了"）；
- 死锁防线：`lock(lck1, lck2, lck3)` "同时"获取多锁＋RAII 隐式释放——"C++17 有更优雅解法（8.4 scoped_lock）"；
- **取消（cancellation）风波**——本节最大争议："几乎每个 C++ 委员会成员都想要某种形式的线程取消"；C 委员会 WG14 发来了**史上唯一一封** WG14→WG21 正式函表示反对；Austin Group（POSIX 管理人）派出的代表"100% 反对任何形式"，坚称取消既非必要也不可能安全。Bjarne 的回嘴值得抄："**但 C 没有析构函数，没有 RAII 来做系统性资源清理**——我注意到这一点，可 Windows 都有变体、C++ 又不是 C，对 POSIX 人们毫无意义。我担心他们是在保卫自己的生意和 C 语言世界观，而不是为 C++ 找最好的解。"后果：并行搜索里"先找到答案的线程该能停掉其他线程"（§8.5 场景）十五年无标准解，直到 C++20 的 stop token（9.4，→ 06 册）才算还账。

论文金句：**"我认为线程-锁层是最糟的应用并发模型，但对 C++ 这样的语言必不可少"**——C++ 必须支持 OS 最低层能力（内核、驱动），更高层模型在其上盖。Bjarne 个人偏好消息传递（消灭数据竞争这个最微妙并发 bug 之源）。配套书目：Anthony Williams 的书（2012/2018）被点名为深度参考。

§4.1.3 期值：类型安全的 future/promise 对标 POSIX/Windows 式回调。会议政治实录（论文 §4.1.3 原文）：一派想要"POSIX 加改进类型"（点名 PJ. Plauger），一派指出"POSIX 基本是 1970 年代设计、'人人'已在用更高层设施"——**2007 年 Kona 会议妥协**：C++0x 提供 promise/future＋异步任务启动器 `async()`（允许但不要求线程池）。"像多数妥协，**Kona 妥协让所有人都不满意**——但许多用户视之为成功，他们多数人不知道那是妥协。"被记名的更大遗憾：Matt Austern 与 Bjarne 推**消息队列（channels）＋线程池**，被"没时间做好"顶回；Bjarne 的哀求原文值得抄进任何并发课程——"**如果你们不做，请至少给我一种、哪怕一种、无需显式同步就能在线程间传递信息的方式！**"这条线 15 年后以 std::execution（P2300R10，[wg21.link/p2300](https://wg21.link/p2300) ✅302）落地（→ 本册第五节）。

## 三、简化使用十一连：把"熟悉"当成"简单"的纠偏工程（§4.2）

逐节精读要点（机制细节教例见 → [../c++之旅3/01-基础与用户自定义类型.md](../c++之旅3/01-基础与用户自定义类型.md)、[../c++之旅3/10-并发.md](../c++之旅3/10-并发.md)）：

- **auto/decltype（4.2.1）**：省掉冗长且易错的显式类型；Bjarne 自述 1983 年做过类似机制、当时不觉得新。
- **range-for（4.2.2）**：`for (auto x : v)`，避免手写 first/last 的范围错误；§3.3 记名"digit separators 花的委员会时间比 range-for 多"——优先级缺失的标本。
- **移动语义（4.2.3）**：本章技术核心。史实链：1982 年 Bjarne 就用"在调用者栈帧上构造返回值"的优化但只是优化不是保证；2002 年 Hinnant/Abrahams/Dimov 提出右值参考一般形式；`&&` 记号出自 **John Spicer 2002 年与 Abrahams、Hinnant 的会议**；2010 年匹兹堡会 CWG 午前陷入僵局，Bjarne 午间写出"两大原语（**has identity / can be moved from**）推导 5 值分类"的分析，午后即被接受——移动语义保住了 C++11 席位（Stroustrup 2010a，即 N2840 一系，见下方提案实测台账）。矩阵例子要点：`Matrix m3 = m1+m2+m3;` **不需要临时量**——标准库全部容器同步改造，"有些 C++98 程序不改源码就变快"。定位判断："移动语义完成了 1979 年构造/析构开启的对象生命周期控制"，是 C++ 资源管理模型的基石（Stroustrup et al. 2015 资源模型论文）。匹兹堡分析的二元表（论文图景的文字版）：

| 有标识 | 可被搬空 | 类别 | 记法例 |
|---|---|---|---|
| 是 | 否 | lvalue | 具名变量 `x` |
| 是 | 是 | xvalue | `std::move(x)` |
| 否 | 是 | rvalue（纯右值） | 字面量、临时量 `f()` |
| 否 | 否 | （函数指示符等） | `&T::f` |

  ——三类右值/左值/将亡值的全部歧义都从这两个正交问题导出；`T&&` 在模板推导中"退化"为转发引用（universal reference，Scott Meyers 造词）是这张表的推论（→ 03 册变参模板）。
- **资源管理指针（4.2.4）**：shared_ptr（Dimov 等 2003）是计数式 GC、能正确管非内存资源；unique_ptr（Hinnant 2002/2006）取代设计有缺陷的 auto_ptr——"drop-in 替换"给了标准**移除一个坏设施**的罕见机会。论文点出的反模式：拿 shared_ptr 当工厂返回值，计数 1→2→1，多线程下是带同步的慢操作——这是后来"裸 new 只在 unique_ptr 构造点出现"风格（GSL/Core Guideline）的论据。
- **统一初始化（4.2.5）**：多种初始化记法语义互异是历史包袱；花括号统一之并禁止意外窄化。此处埋下 N+1 问题定义（§8.8.3 呼应）："任何新方案不会让旧方案消失，只多一种选择。"
- **nullptr（4.2.6）**：小特性走了三年（§3.3 拖延案例）。
- **constexpr（4.2.7）**：2010 年 Dos Reis & Stroustrup 论文主张"编译期算值应写成普通函数"；C++11 版限制多（§3.3：constexpr 全程 5 年＋少数否决两案齐上），到 C++14 放松（5.5）、C++20 大成（9.3.3）。
- **用户定义字面量（4.2.8）**：让 `1.2+3.4i` 这类"自定义类型有内建型待遇"的平等主义表达；Bjarne 推销时被人嫌 complex<double>(1.2,3.4) 记法不常规。
- **原始字符串（4.2.9）**：`R"(10\\Zip\)"`，反斜杠地狱（美国邮编正则例）直解。
- **属性（4.2.10）**：`[[...]]` 语法为语言级注解开闸（carries_dependency→后来 C++17 的 [[nodiscard]] 等，§8 特性清单点名）。
- **垃圾收集（4.2.11）**：Boehm/Spertus 设计的 conservative GC 接口进标准（GC/安全点模型、`std::allocate` 等）；论文自评"几乎没人注意，用的人更少"——但它在规范上确立了"手动 delete 非唯一合法生命期策略"，2024 起的"硬化"路线（→ 07 册）把它变成可检测 UB 的护栏。

## 四、g++ 实测：C++98 编译不过，C++11 起成立（移动＋unique_ptr 工厂）

选论文 4.2.3/4.2.4 点名特性（Matrix 句柄移动、unique_ptr 工厂、异常安全）：

```cpp
// s02.cpp 摘要
Matrix(Matrix&& a) : n(a.n), elem(a.elem) { ++moves; a.elem = nullptr; a.n = 0; } // 4.2.3 "steals the representation"
Matrix operator+(const Matrix& b) { Matrix r(n + b.n); return move(r); }          // 4.2.3 大对象按值返回
unique_ptr<Blob> make_Blob(const string& t) {   // 4.2.4 工厂惯用法
    unique_ptr<Blob> p(new Blob(t));
    if (t.empty()) throw runtime_error("empty");  // 异常不泄漏（RAII）
    return p;
}
```

已实测 g++ 15.2：`-std=c++98` 失败（7 个 error：`expected ',' or '...' before '&&' token`、`'move' was not declared` 等——右值引用整体不存在）；`-std=c++11` 通过：

```
m3=200 copies=0 moves=1
blob=blob
caught: empty (无泄漏)
```

`-std=c++17` 重编译输出相同（保证复制消除改变了优化自由度，不改行为）——论文"不改源码就变快"的一句注脚的可复现版。

## 五、2020–2026 裁决视角：论文里"在路上"的并发去哪了

- **executors/channels 之愿的 15 年续命**：P2300R10 `std::execution`（[wg21.link/p2300](https://wg21.link/p2300) ✅302，标题 "std::execution" 实测）2024/2025 两度进入 C++26 工作草案——论文 4.1.3  Austern/Bjarne 想要的"线程间传信息的方式"终于有了正式候选形态。
- **jthread 与 stop_token**（C++20，P1135R6 ✅302）：4.1.2 线补齐 RAII 线程；atomic<shared_ptr> 特化（P0019R8 为 atomic_ref 姊妹提案 ✅302）缓解工厂模式计数开销。
- **std::expected（C++23）**：4.2.4/§7 的"value+error"线索的标准化，详见 → [05 章](./05-错误处理与C++17：大海迷航.md)实测样例。
- **GC 接口**至今仍是"几乎无人用"；但 ISO 侧 2022 年起以 `std::hardening`（[wg21.link/p2674](https://wg21.link/p2674) ✅302）延续 Boehm 路线的护栏思路，与 Core Guidelines 静态分析合流（→ 07 册）。

## 最新演进与工业实践

- **工业对应**：unique_ptr 工厂＝现代 API 的 `std::make_unique` 惯用法（C++14，Bjarne 点名 make_unique 为"改进"之一）；folly 的 `folly::Future`、seastar 的 future/线程每核模型就是 §4.1.3"专家不做，学生乱造"预言的工业实证；abseil 文档明确"优先 absl::Status（expected 系）而非异常"——正是 §7 双轨论的 Google 站队版。
- **现代重估**：C++11 并发三件套被公认是"近二十年最重要的标准化成果"——它使 lock-free 库（如 moodycamel queue）、Rust 借用检查（对照设计）、所有"每核一线程"框架成为可移植代码而非平台赌注。写并发代码先学这节；学"怎么用"去旅3 → [../c++之旅3/10-并发.md](../c++之旅3/10-并发.md)。
