## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话定义 |
|---|---|---|
| 纯函数 | pure function | 相同输入必得相同输出，且不产生可观察副作用（Saumont 全书的地基） |
| 引用透明 | referential transparency | 表达式可被其值替换而程序意义不变——纯函数的可验证推论 |
| 副作用 | side effect / effect | Saumont 术语：函数对"外界"（参数之外的一切：全局态、IO、异常……）的影响 |
| 函数组合 | function composition | `f andThen g` / `g after f`：像流水线一样把小函数接成大函数 |
| 部分应用 | partial application | 只喂一部分实参、留下一个新函数；与柯里化（currying，把多元函数变形为单参链）相邻 |
| 高阶函数 | higher-order function | 以函数为参数或返回值的函数——`map/filter/fold` 的共性 |
| 确定性与可替代性 | determinism / substitutability | 测试纯函数只需断言输出，无需 mock 世界 |

## 复演：Saumont 式渐进重构叙事（本档演进链）

Saumont 的招牌讲法是**同一段坏代码一路改到代数结构**。本档按记忆复演第一条链：
"读配置算折扣"从命令式改到纯组合（⚠️ 情节复演，非逐字引书）：

**第 0 态——命令式+隐藏输入**（坏在：函数"看见"了签名之外的世界）：

```kotlin
var discountRate = 0.10                     // 全局可变态：隐形第四参数
fun computeDiscount(price: Double, qty: Int): Double {
    if (System.getenv("VIP") != null)       // 读环境：副作用之一
        discountRate = 0.20                 // 改全局：副作用之二
    return price * qty * (1 - discountRate)
}
```

**第 1 态——把一切输入摆进参数表**（消失的效果：读环境、写全局）：

```kotlin
fun computeDiscount(price: Double, qty: Int, rate: Double): Double =
    price * qty * (1 - rate)                // 纯函数：可替代性立现
```

**第 2 态——部分应用找回便利**（调用方嫌传 rate 烦）：

```kotlin
fun discountWith(rate: Double): (Double, Int) -> Double =
    { price, qty -> computeDiscount(price, qty, rate) }
val vip = discountWith(0.20)                // 环境读取被挤到程序边界的一次性动作里
```

**第 3 态——组合成管道**（加税、加运费）：

```kotlin
fun <A> A.pipe(f: (A) -> A): A = f(this)    // 示意；书里 Saumont 用 andThen/扩展
val finalPrice = ::computeDiscount
    .let { { p: Double, q: Int, r: Double -> it(p, q, r) } }
// 更 Saumont 风味：(price, qty, rate) andThen 折扣 andThen 税费 andThen 运费
```

每一步只消灭一种 effect，签名越来越诚实——这就是本书"渐进重构叙事"的手感，
与 FPIK（[../Functional_Programming_in_Kotlin/00-总览与阅读地图.md](../Functional_Programming_in_Kotlin/00-总览与阅读地图.md)）"自顶向下给代数结构"正相反。

## Java / C++ 对照

- **Java**：`static` 方法天然是"类作用域里的自由函数"，但 JVM 不阻止方法读 `System.getenv`
  或改静态字段——纯性靠纪律不靠类型。Java 8 的 `Function.andThen` 对应第 3 态的组合，
  但部分应用在 Java 里没有语法位，只能手写适配器。
- **C++**：`constexpr` 函数是"编译期可求值的纯函数"的近似子集（C++20 起有 `constinit`/
  更严规则），比 Kotlin 强在编译器**强制**无副作用可达路径；弱在组合设施（Ranges 之前的
  pipe 文化）与模板噪音。库内对照可看
  [../C++20模板元编程/01-模板的简介.md](../C++20模板元编程/01-模板的简介.md) 的"零开销"心态——
  Kotlin 的 lambda 组合会装箱/建对象类，纯函数在 JVM 上有实打实的对象分配成本。
- **Kotlin 特色**：扩展函数让"组合"读起来像方法链，`it`/尾lambda 语法让高阶函数样板极薄——
  这是 Saumont 选 Kotlin 讲 FP 的语言学理由（⚠️ 推定作者意图）。

## 🔧 微实验（未实测）

```kotlin
// 实验 1：验证"引用透明"是编译器能帮你抓的事——把纯函数塞进 const-like 上下文
fun area(r: Double) = Math.PI * r * r
fun main() {
    val a1 = area(2.0); val a2 = area(2.0)
    println(a1 == a2)          // 恒 true；若 area 内含 Random 则不可重现
}
// 实验 2：替换测试——手工把 computeDiscount(3.0, 2, 0.1) 全部替换为 5.4，
// 程序行为不变（第 1 态）；对第 0 态做同样替换则每次运行结果漂移。
// 运行：kotlinc disc.kt -include-runtime -d disc.jar && java -jar disc.jar
```

预期观察：第 0 态两次运行输出不同、第 1 态永远同——这就是"引用透明可检验"的微证明。🔧
