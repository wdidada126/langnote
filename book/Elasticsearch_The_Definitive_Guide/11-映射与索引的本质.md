# 11 映射与索引的本质（print 第 13 章：Mappings and the Nature of Indexes）

> 内容锚点（✅ 实抓官方仓库）：052_Mapping_Analysis（"Mapping and Analysis"：25_Data_type_differences、30_Exact_vs_full_text、35_Inverted_index、40_Analysis、45_Mapping、50_Complex_datatypes）+ 070_Index_Mgmt/25_Mappings。本章与 10 章共构"schema 层"。转述 ⚠️。

## 1. "索引是什么"的本质回答

书中定义链：索引=**为查询优化的数据结构集合**；同一条原始 JSON 会被拆成多份结构同时保存：
1. `_source`（原文，给取回/更新/高亮）；
2. 倒排（分析字段，给词法匹配）；
3. doc_values 列存（精确值字段，给排序/聚合）；
4. （1.x）`_all` 聚合倒排——**已死**（00 表 §4-2）。

> "数据只存一份、索引多份结构"与 DDIA「写入模型≠存储模型」完全同构 → [../设计数据密集型应用/03-存储与检索.md](../设计数据密集型应用/03-存储与检索.md)。

## 2. 核心类型清单（1.x 名 → 现代名）

| 书代类型 | 说明 | 今况 |
|---|---|---|
| `string: analyzed/not_analyzed` | 一个类型两种指数法 | **分裂为 text / keyword**（5.x），全目录版第一翻译项 |
| `text`（1.x 亦有此名） | 分析文本 | 健在 |
| number/integer/long/double/… | 数值 | 健在+新半精度 `half_float` 等 ⚠️ |
| date（可多格式） | epoch/自定义格式统一存 UTC 毫秒 | 健在 |
| boolean/ip/geo_point/binary | — | 健在；binary 不索引 |
| `object` | **JSON 对象被拍平：字段丢失组内关联** | 健在（坑不变） |
| `nested` | 拍平的解药：组内独立 Lucene 文档+关联查询 | 健在，代价见下 |
| `parent/child`（1.x `_parent`） | join 语义的 ES 式补丁 | `_parent` 删除→**join field** 替代（⚠️ 对位） |
| `completion` | 建议器专用字段 | 健在 |
| `attachment`（ingest） | Base64 文档抽取 | 插件时代→ingest-attachment |

## 3. multi-fields：一字多相

`title: text + subfields: title.raw(keyword)`（书代惯用 `.raw` 命名）= **"既全文搜又聚合排序"的正解**——_all 之死与 keyword 双字段的兴起全在这一节；现代 `copy_to` 承接 _all 的部分职能（✅ 字段类型总览 https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/field-data-types ）。

## 4. 嵌套的两张面孔（在线版 402/404 章同题）

- `nested`：同一父文档组内字段进**同一隐藏子文档**+块内 join——查询用 `nested query`、聚合用 `reverse_nested`；代价：**索引膨胀（每子文档独立 doc）+ 更新即整体重写**；
- `parent/child`：跨文档关联，查询期 join 成本 O(匹配文档数)、**子文档与父同分片靠 `routing` 保证**；书代结论（2026 年仍是社区共识）："能 nested 不 parent-child，能反范式化不 nested"；
- 关系数据库迁移者的心法：书中把"该 join 还是该冗余"的决策画成矩阵：**按"父:子基数 × 子改频度"** 定方案——本章最值钱的一张表。

## 5. 动态映射的字段推断表（书代）

字符串→string(analyzed)、日期可解析→date、数值→long/double、对象→object、数组→继承元素类型…；"推断只增字段不改类型"、"新字段自动扩 mapping"与 `dynamic templates` 的收口，配合 [10 章](10-索引管理与调优.md) strict。

## 5.1 拍平事故示范（object 的经典教学例，⚠️ 转述示意）

文档：`{"name":"joe","children":[{"name":"sue","age":41},{"name":"mary","age":36]}`（书代原例族）——
object 索引后倒排里是 `children.name:{joe? no: sue,mary}` 与 `children.age:{41,36}` **两个独立集合**；查询 `children.name:sue AND children.age:36` **照样命中**（41 也是 joe 家孩子的？错配已不可辨）。
nested 的解法：数组每个元素生成隐藏子文档、组内共 docID 块，`nested` 查询做组内关联；代价清单：
- 索引膨胀（子文档独立占号、占 _source 之外全套结构）；
- **更新任一子元素=整个父文档重索引**；
- 取回/聚合都要 `path` 进 `reverse_nested` 出（[03 章](03-聚合.md)top_hits 同题）。

## 5.2 关系建模决策树（书中矩阵的列点化）

```
需要"关联"吗？
├─ 读多写少、父改子不频繁 ──→ 反范式化（把子揉进父文档）【首选】
├─ 子独立更新、组内需查询 ──→ nested
├─ 高频改父/子、基数爆炸   ──→ parent/child（join field）【最后手段】
└─ 强事务外键完整性        ──→ 留在关系库，ES 只做搜索副本（[14 章](14-数据分布扩展与冗余.md)）
```
书代附赠的第三问："关联的检索模式是'过滤'还是'打分'？"——过滤→nested/term 就够；打分（子项贡献相关性）→join field 的 has_child 打分语义才有意义（⚠️ 转述）。

## 5.3 日期与格式：被低估的 mapping 细节

- date 多格式（`"format":"date_optional_time||epoch_millis"` 书代样式 ⚠️）；统一内部 UTC 毫秒、输出按 `time_zone`（[03 章](03-聚合.md)日界漂移的根）；
- `ignore_malformed`/`coerce`（书代已引入/后出边界 ⚠️ 未逐一核）——"脏数据进不进索引"的第一道闸；
- ip/geo_point 的"多值即数组"：ES 数组无声明，**任何字段都是数组**（书中三大洗脑点之一：`"tags":"one"` 与 `["one","two"]` 同一 mapping）。

## 跨代误读备忘（本章专属换算清单）

1. `"index": "not_analyzed"` → `"type": "keyword"`；`"type":"string"` → text/keyword 二选一——**mapping 断代双雄**，任何照抄都直接 400；
2. `_all`/`_boost`/`_timestamp`/`_source.enabled:false` 等 meta 段按 [10 章](10-索引管理与调优.md)表处理；`_field_names`（书代 exists 机制）保留但默认 `ignore_above:1000`；
3. `_parent`/`_child` 映射（1.x join）→ 现代 `join` 字段类型+`has_parent/has_child/inner_hits`；书中"父文档子文档同 routing"的机制仍在，配置名全换（⚠️ 转述）；
4. `geo_point` 的 `tree:geohash/tree_prefix` 参数群已删，现代点/形状双类型（geo_shape 重写成 CYCLE/TREE 模型）——书代 geo 例子的**语义目标不变、语法全弃**；
5. `ip` 类型书代已存（ipv4），现代双栈 ipv6+`ip_range` 聚合；
6. `nested._ttl/_not_analyzed` 等旧参数出现在老 mapping 样本里时先查"该键是否还存在"再迁移（reindex 前置体检：现代 Upgrade Advisor 代劳 ⚠️）；
7. 本章数组观、对象拍平观、"映射是指数方案不是约束"三观 **零断代**——2026 年教 ES 建模仍从这三句开始。

## 核心概念速览（中英对照）

- **映射** — Mapping：字段的指数方案声明（≠SQL 约束：不校验、可拍平）
- **text/keyword 分裂** — Analyzed vs exact：书代 string 开关的现代终态 ⚠️
- **_source 双存** — Source + indices：一份原文多份索引结构
- **multi-fields** — 多字段：title(text)+title.keyword 的一词多相
- **copy_to** — 复制合成字段：_all 的继任者
- **object 拍平** — Flattening：数组内对象丢关联的默认行为
- **nested** — 嵌套：组内独立子文档保关联；膨胀+整文档重写
- **parent/child/join** — 跨文档关联：查询期 join，routing 同片约束
- **基数×更新频率矩阵** — Denormalization decision：join 与冗余的决策表
- **dynamic mapping** — 字段自动推断：便利与事故的叠加态
- **geo_point** — 地理点：经纬度双指数（doc_values+tree）⚠️ 书代 geo 树
- **ip 类型** — IP 索引：段树式范围结构的前身之一

## 最新演进与工业实践

1. **类型表持续加粗，骨架未动**：`dense_vector`/`sparse_vector`/`semantic_text`/`search_as_you_type`/`flattened`/`wildcard`/`percolator`/`join`/`rank_feature` 等新类型全部挂在书中"每类型=一种指数法"的旧定义下（✅ 同上 field-data-types 链接）。
2. **runtime fields（7.11+）**：查询期定义字段、免索引——对书中"先 mapping 后写入"教条的松弛（⚠️ 转述）。
3. **nested 的新用途**：8.x+ nested 承载 dense_vector 做文档内多向量；书代"膨胀"告诫依旧有效。
4. **向量/语义时代的关系观**：embedding 相似度替代了一半 parent-child 的"找相关东西"需求（✅ https://www.elastic.co/docs/solutions/search/vector/knn ）；但"实体-事件"型强关联仍走 join/nested——书中矩阵换了参数没换形状。
