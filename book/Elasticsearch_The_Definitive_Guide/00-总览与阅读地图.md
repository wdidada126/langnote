## 4. 本版最大特征：「书止于 2.x，引擎已至 9.x」大对位表

> 读这本书必须人手一张的翻译表：左列是书中 1.x/2.x 口径，右列是 2026 年现状（以 Elastic 官方文档转述为主，全部 ⚠️ 未实测；引用 URL 均已 `curl` 验证可达）。

| # | 书中口径（1.x/2.x） | 2026 现状（9.x） | 断点 |
|---|---|---|---|
| 1 | 索引内多 mapping types（`/index/type/_search`，`_all` 索引所有字段） | **types 彻底删除**，URL 固定 `_doc`；官方"types"文档页已改名为 Field types（https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/field-data-types ） | 5.x 警告→6.x 单 type→**7.0（2019）删除** |
| 2 | `_all` 虚拟大字段 | **已移除**；替代：`copy_to` 组合字段或 `multi_match` | 6.x 默认关、7.0 移除 |
| 3 | `facets`（书中主检索统计） | **删除**，全面由 aggregations 取代 | 3.0 移除 |
| 4 | `filtered`/`and`/`or`/`not` query 与"filter 缓存"分章讲 | **删除**；统一 `bool.filter`（Query DSL 总览：https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl ） | 5.0 移除 |
| 5 | 默认排序相似度 TF/IDF | **BM25 自 5.0 起为默认**（书第 9 章公式骨架仍适用，norm/idf 同构） | 5.0 |
| 6 | `string` 类型 + `index: not_analyzed` | `text`（分析）/`keyword`（精确）两型；`not_analyzed` 选项删除 | 5.x mapping breaking |
| 7 | `_timestamp`、`_source` 开关式 meta 字段 | `_timestamp` 删除；`_source` 常开，溯源/更新依赖 | 5.0 |
| 8 | scan search type + scroll 深分页 | scan type 删除；scroll 保留但官方推荐 **PIT + search_after**；ES|QL 提供游标式分页 | 5.x/7.10+/9.x |
| 9 | 书中 API 只有 Query DSL/`query_string` | **ES|QL 管道语言**（`FROM … | WHERE … | KEEP …`，https://www.elastic.co/docs/reference/query-languages/esql ）8.11 预览、**9.0 GA**；旧 Query DSL 仍是主力检索接口 | 2024–2025 |
| 10 | 跨集群 = 书无此概念（多集群靠插件/复制） | **CCS + ES|QL 跨集群查询（`remote:index`）与 lookup join** 为 9.x 官方能力（Elasticsearch 主页声明，细目版本点 ⚠️ 未逐一核对） | 8.x/9.x |
| 11 | 相关=词频倒排（无向量） | **语义检索栈**：`semantic_text` 字段（https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/semantic-text ）、inference API、ELSER、**k-NN 向量检索**（https://www.elastic.co/docs/solutions/search/vector/knn ）、RRF 混合排序 | 8.0+ |
| 12 | delete-by-query / update-by-query 反复存废 | 已固化为 **reindex 族协调式 API**（https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-delete-by-query ）；书中"为什么被删"的教训仍是经典 | 2.3+/5.x |
| 13 | river 插件从关系库拉数据 | river 删除；生态位 = Logstash/Beats + Debezium CDC + ingest pipelines | 5.x |
| 14 | Zen discovery（`minimum_master_nodes` 手调防脑裂） | **voting configuration 集群协调层**（7.8+）自动仲裁，书中"quorum 公式"仍是理解基础；手调设置已废 | 7.x/8.x |
| 15 | index warmers | 删除（段缓存等引擎自动管理） | 5.x |
| 16 | fielddata 堆内排序/聚合调优是核心技能 | **doc_values 列式默认**（5.x 起除 text 外全默认），fielddata 仅剩兜底；书中"堆爆炸"警告转化为"用 keyword 别用 text 聚合" | 2.x→5.x |
| 17 | transport client / 各语言 Thin client | REST-only；8.x Java 用官方 Java API Client（`co.elastic.clients`），传输层 client 删除 | 6–8.x |
| 18 | 安全 = 商业 Shield 插件；集群裸奔 | **x-pack security 免费默认开**：8.x 起 TLS/认证默认启用；9.x 云与 Serverless 形态 | 6.x/8.x |
| 19 | Lucene 4（书时代），引擎"32GB 堆 + compressed oops" | Lucene 9（ES 8）→ **Lucene 10（ES 9，https://lucene.apache.org/core/ ）**；JDK 21+ 捆绑、9.x 默认生成式 ZGC（⚠️ 细节版本未逐一核）；31GB 堆经验仍有效 | 8.x/9.x |
| 20 | "Elasticsearch 是 Apache/Lucene 之上的开源项目" | **OpenSearch 分叉谱系**：ES 7.10 为 Apache-2.0 末代（2021 年 AWS 据此分叉 OpenSearch，https://opensearch.org/ ）；ES 8+ 转 SSPL/Elastic License。社区版概念随书中 1.x 一起定格 | 2021 |

## 6.1 三个预读问答

- **Q1：这本书值得精读吗？** 值得，但只精读 04–08、12 三个原理文件与 13–15 的故障思维——概念层（倒排、段、NRT、路由、尽力而为复制）保鲜 12 年；语法层（types、facets、filtered、m_m_n）按大对位表整体作废。
- **Q2：为什么不直接看 9.x 新文档？** 新文档回答"怎么做"，本书回答"为什么长这样"；两阶段搜索、filter 缓存、近似聚合、分片预算这些"设计动机叙事"在官方参考里已稀释。
- **Q3：在线版能替 print 吗？** 主题覆盖约 90%（见 §3.3 映射列），但 print 的章节叙事更紧、在线版独有以下部：Aggregations 全 6 章、Geolocation、Modeling Your Data——需要时按 §3.2 直接读仓库文件。
