# 06 搜索内览（print 第 7 章：Searching Inside Out）

> 内容锚点（✅ 实抓官方仓库）：060_Distributed_Search（"Distributed Search Execution"：05_Query_phase、10_Fetch_phase、15_Search_options、20_Scan_and_scroll）、056_Sorting（含 90_What_is_relevance、95_Fielddata）。转述 ⚠️。

## 1. 一次搜索的两阶段协议（本章主干）

**查询阶段（query phase）**：
1. 协调节点把查询广播到**每个相关分片副本**（轮转选择主/副）；
2. 各分片本地算出 top-N 文档 id（只带排序所需的"轻量信息"），返回给协调节点；
3. 协调节点归并排序，得到全局 top-N 的 **id 列表**。

**取回阶段（fetch phase）**：协调节点向持有这些 id 的分片**并行**取 `_source`/高亮片段等重组文档，最终组装响应。

书中两条推论：
- `from/size` 的真实成本：第一阶段每分片要回 `from+size` 个 id——**深分页时协调节点内存与网络线性恶化**；`max_result_window`（默认 1 万）是硬闸；
- 两阶段之间**不保证一致性**：refresh 发生在中间会导致"查时无、取时有"的罕见不一致——书中教用 `search_type=scan`（已删）/scroll 导出（⚠️ 对位见演进节）。

## 2. 分布式打分为什么"基本够用"

`query_then_fetch` 各分片用**本地 IDF** 打分——分片小、词分布偏时会错排。书中给出 **`dfs_query_then_fetch`**：第一阶段前先广播 DF/TermStats 收集，全局 IDF 再排。代价：多一轮全分片往返；建议"仅对少量高价值查询/小结果集"使用——**同名选项 2026 年仍在**。

## 3. 排序的三个世界（056_Sorting 部）

| 排序依据 | 书时代机制 | 现代命运 |
|---|---|---|
| `_score` | 相关性（默认） | 不变 |
| 数值/日期 | **doc_values 正排列存**（1.x 需显式开启，2.x+ 默认 true） | 默认全开 |
| 分析型字符串 | **fielddata 堆内加载词典到 docID 数组**——书中整页警告 OOM/熔断 | 基本被 keyword+doc_values 取代；text 排序=事故 |

书中"按日期排序要 **ignore_unavailable/missing** 组合"与"多字段排序+`_score` 兜底"仍是日常写法；`unmapped_type` 处理跨索引缺字段问题（多索引查询时代 7 章就讲了）。

## 4. 深分页的正确姿势（书时代三选）

1. `from/size`：前 N 页；
2. **scan search type + scroll**（1.x 的导出姿势；search_type=scan **5.x 删除**）：首次 `scroll=5m` 拿快照游标，后续 `_search/scroll`——书中把 scroll 定位为"翻页给用户看是错的，离线导出才是对的"；
3. 排序键游标（`search_after` **6.x 才出现，书里没有** ⚠️）。

## 5. 其他选项（15_Search_options）

`preference`（固定分片/副本亲和）、`routing`（单分片加速）、`terminate_after`（熔断早停）、`timeout`（协调端部分结果语义：响应可带 `_shards` 不完整标记）——这些语义 2026 年几乎原样保留（⚠️ 转述）。

## 5.1 两阶段协议的形式化走位（书中伪码改列点）

**query phase**
1. 协调节点选副本轮转 → 向每分片发 `query(shard, size=from+size)`；
2. 分片内：词项字典定位 → postings 求交/并 → 打分 → 局部优先队列 top-(from+size) 个 **docID+排序键**；
3. 回传协调节点（不含 _source）；
4. 协调节点 k 路归并 → 全局排序 → 截出 [from, from+size) 的 (shard, docID) 对；
5. **fetch phase**：按分片分组发 `fetch(ids)`；
6. 分片取回：load doc→解析 _source→（可选）高亮重分析；
7. 协调节点组装 hits，附 `_shards` 统计（failed/skipped 语义在此）。

**深分页算术（书代例题风格）**：10 分片、from=9900/size=100 → 每分片 10000 条 id、协调节点堆 10 万条——第 1000 页之后每页成本线性涨；`max_result_window=10000` 即从"堆预算=1 万条"倒推的工程闸门（⚠️ 转述）。

## 5.2 排序内存模型（fielddata 一节的教学价值保留）

- 堆内结构本质：**词项字典的反向数组**（docID→值），字符串排序时=全量词典加载；
- 书中给出的三个避坑动作：(a) 排序字段 `not_analyzed`（今 keyword）；(b) 能按数值/日期排序就别按文本（doc_values 廉价）；(c) 用 `unmapped_type`/`missing` 处理跨索引缺字段；
- 现代熔断对应：`fielddata` breaker 与 [13 章](13-均衡集群.md)的位图/filter 缓存共享 parent breaker 预算（⚠️ 转述）；
- 排序与 `track_scores`、`_score` 兜底稳定性——"同分乱序翻页跳单"现象书代已示范。

## 跨代误读备忘（本章专属换算清单）

1. `search_type=scan`、`scan_and_scroll` 请求样例在 5.x 后整体作废；scroll 的 `search` 端点 5.x 起独立（`_search/scroll`）；
2. `field_data` 预热、`index.fielddata.cache` 与书中"sort 前算 fielddata"的操作手册：**现代唯一正解是改 mapping 用 keyword**，按书操作=自造事故；
3. `dfs` 的选项名仍在但现代少用——多数"打分不一致"投诉的真实根因是**数据倾斜+分片数规划失误**（[13 章](13-均衡集群.md)预算表）而非缺全局 IDF；
4. 书代 `_search_template`（1.x 无 → 2.x 有）与 "mustache"——本目录未展开模板机制，遇到老帖先分清代际；
5. 书中 `timeout` 语义（协调侧超时仍返回部分结果）今天原样——**"timeout 不是取消后端工作"** 的警告逐字有效；
6. 向量检索的引入让"query/fetch 两阶段"长出新变体（每分片 HNSW 出 top-k）——心智模型无需重学（见演进节 3）。

## 核心概念速览（中英对照）

- **查询阶段** — Query phase：各分片出本地 top-N 文档 id+排序值
- **取回阶段** — Fetch phase：只对全局胜者取 _source/高亮
- **协调归并** — Global sort at coordinator：部分结果合成全局视图
- **max_result_window** — 结果窗口硬限：默认 10k，防 from/size 失控
- **DF 预收集** — DFS / distributed term stats：全局 IDF 修正分片间打分偏差
- **doc_values** — 列式正排：数值/日期排序与聚合的地基（书时显式开，今默认）
- **fielddata** — 堆内词典反转：分析字符串排序的昂贵旧路，现代弃用 ⚠️
- **ignore_unavailable/missing** — 缺字段排序语义：跨索引查询的补丁
- **unmapped_type** — 未映射字段类型提示：空分片不报错
- **preference/routing** — 分片/副本亲和：缓存与单分片加速
- **terminate_after** — 早停：牺牲全局精确换时间
- **scroll（书时代）** — Scroll：快照游标，导出正解、翻页错解；scan type 已删

## 最新演进与工业实践

1. **scan 死、scroll 退居二线**：官方深分页答案改为 **PIT + search_after**（✅ https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-open-point-in-time ）与 ES|QL 游标（✅ https://www.elastic.co/docs/reference/query-languages/esql ）；scroll 仍可查老帖但云托管上受限（⚠️ 转述）。
2. **fielddata → keyword**：书中"给 text 排序"的教训固化为默认 schema：**分析文本只留倒排，精确值走 keyword 双字段**（multi-field 见 [11 章](11-映射与索引的本质.md)）；fielddata 熔断器仍在，用途收窄到"显式救场"。
3. **两阶段模型的现代扩展**：kNN 检索把 query 阶段变为"每分片出 HNSW top-k 再归并"（✅ https://www.elastic.co/docs/solutions/search/vector/knn ）——本章"分片局部 top-N+协调归并"的框架一字不改地复用；向量时代"本地近似全局"的偏差讨论（召回率损失）是 DFS-IDF 问题的当代翻版。
4. **观测性**：`profile: true` 逐分片逐查询耗时、`_cat/nodes` 看协调内存——书中没有 profile 细节但思路即"把两阶段拆成可计时单元"（⚠️ 转述）。
5. 交叉链接：协议与"部分结果"的一致性语义 → [../设计数据密集型应用/00-总览与阅读地图.md](../设计数据密集型应用/00-总览与阅读地图.md)；批式"扫描全量"的对应物（scan+scroll→ 大数据侧 MapReduce 分片读）→ [../bigdata/00-总览与阅读地图.md](../bigdata/00-总览与阅读地图.md)。
6. **协调器下推**：8.x 起部分聚合/排序逻辑继续向数据节点/文件缓存层下推（如列式 doc_values 读取路径优化 ⚠️ 转述），但"scatter 局部 top-N → gather 全局归并"的两阶段骨架从 1.x 到 9.x 未变——这正是本章值得精读的原因。
7. **ES|QL 视角**：`FROM index | SORT | LIMIT` 在引擎内仍编译为同一分布式查询计划（⚠️ 转述官方 esql 文档），深翻页的游标语义即 PIT+search_after 的托管封装——旧 scroll 应用迁移时优先换此组合。
