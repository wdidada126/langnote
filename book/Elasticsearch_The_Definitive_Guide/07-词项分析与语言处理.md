# 07 词项分析与语言处理（print 第 8 章）

> 内容锚点（✅ 实抓官方仓库）：Part「Dealing with Human Language」全 8 章（200_Language_intro、210_Identifying_words、220_Token_normalization、230_Stemming、240_Stopwords、260_Synonyms、270_Fuzzy_matching）+ 052_Mapping_Analysis/40_Analysis。转述 ⚠️。本章是全书"搜索质量"的胜负手。

## 1. 分析器解剖学

书中公式：**analyzer = char filters → tokenizer → token filters**，同一组件在**索引期与分析期各用一次**，且两者可以不同（`analyzer/search_analyzer` 对偶是本章高阶考点）。

- 默认 `standard` 分析器：Unicode 文本分割（UTS#29 词元边界）→ 小写 → 去停用词？**不去**（1.x 默认 stop 列表为空，书中明确"开箱 ES 不删停用词，删了会破坏短语与评分"——这条反直觉劝告沿用至今）。
- 验证工具：`POST /idx/_analyze {"analyzer":"standard","text":"..."}`——书中每个论断都用 _analyze 实证，这个习惯 2026 年仍是分析调优唯一入口。

## 2. 词元切分（210）

- 空格/标点切分对英欧语系够用；**中日韩无词界**：书时代给 ICU tokenizer/smartcn 等插件思路（现代：kuromoji/icu/nori/smartcn 皆官方分词器，✅ 文本分析总览 https://www.elastic.co/docs/manage-data/data-store/text-analysis ）；
- keyword tokenizer（整串不切）= "精确值字段"的底座——**它和 terms 查询的组合是全链路第一对拍**（呼应 [08 章](08-相关性实战与精确值搜索.md)精确值部分）。

## 3. 归一化（220）：Unicode 与大小写变音

- `lowercase` vs ICU `folding`；é→e、İ→i 等变音折叠的得失（书中演示德/土语案例）；
- 中文案例（书外补充惯例）：全角半角、简体繁体——ICU transform 链。归一化顺序错误会**污染倒排词项**，事后无法补救（只能重建），书中反复出现"改分析=重建索引"（见 [10 章](10-索引管理与调优.md)reindex）。

## 4. 词干化（230）与停用词（240）

- Porter/Kstem/Lancaster/Snowball 家族对比 + `stemmer_override` 词典；书中警告：**词干化过激**（runs→run 好，university→universe 坏）→ 用 stemmer_filter 覆盖表兜底；
- 停用词：删词改变位置信息→短语/邻近查询失真；`common_grams`/`stop` 放置位置（索引期 vs 查询期）的博弈是本章最烧脑一节；
- 现代同义/词干路线的延续与"模型化替代"见尾部演进。

## 5. 同义词（260）

书中两难（经典到可以直接背）：
1. **索引期同义词**（synonym_graph filter 放索引链）：查询便宜，但改词典=重建全量索引，且 tf 被污染（同义词都记到同一词项的频次上）；
2. **查询期同义词**（search-time）：可热更、不污染正排，但**必须用 `synonym_graph`+正确短语支持**，且每次查询展开有成本。
书中判例："entity search（人名商品名）用索引期；短语敏感的模糊搜索用查询期"。

## 6. 容错与部分匹配（270 + print 第 10 章边缘话题）

- 拼写纠错：`fuzzy`（编辑距离 ≤2）、**音素匹配 phonetic**（Soundex/Metaphone）、**ngram 词典**（索引期切滑窗）——书中结论：查询期 fuzzy/phonetic 便宜但准头差，索引期 ngram 贵但可控；
- "did-you-mean"配方：term suggester（查询期看词频词典）+ 用户行为数据 → 现代 suggesters 被 completion/查询模板取代一部分（⚠️ 转述）。

## 6.1 分析器流水线全图（书代标准链的示范，⚠️ 转述示意）

输入 `"Dr. Martini's  QUÄCKEN!  runs at 3mph"` 过 `standard`：

1. char filter（可选）：HTML 剥离/实体还原（`html_strip`）；
2. tokenizer：按 Unicode 词元边界 → `dr` `martini` `s` `quäcken` `runs` `at` `3mph`（标点消失、所有格切碎）；
3. lowercased → `QUÄCKEN→quäcken`；
4. （可选挂上）`icu_folding` → `quacken`；`stemmer` → `run`；`stop` → 删 `at`；`synonym` → 扩 `sprint`；
5. 输出词项序列+位置增量进 postings。

**每一环的取舍都会永久写进倒排**——所以"改任何一环 = reindex 全量"（[10 章](10-索引管理与调优.md)）。

## 6.2 配方库（书中示范过的组合拳）

- 人名/实体：索引期 `metaphone`+`phonetic`+synonym，查询期 fuzzy 兜底；
- 商品搜索：`edge_ngram(3..20)` 索引分析器 + `keyword` 查询分析器 + `min_gram` 与拼写错误联动；
- 搜索框纠错：查询期 `fuzzy` 与 `term_suggester` 双层；"did-you-mean"的置信来源=用户点击回填词典（书中思想实验）；
- 中文（书外补充惯例 ⚠️）：`smartcn`/`ik_smart`/`ik_max_word` + `pinyin` 兜底——分析器选型直接决定 CJK 搜索可用性的上限；
- 德语/土耳其语大小写：`czech`/`turkish` lowercase filter 特例——书中"İ/i 一对多"案例；
- 同义词热更：查询期 synonym + 独立词典索引（现代 Synonyms API 前身思想）。

## 核心概念速览（中英对照）

- **分析链** — Analysis chain：char filters→tokenizer→token filters 三段流水线
- **索引期/查询期分析** — Index-time vs query-time analyzer：可不对称的双通道
- **_analyze API** — Analyze API：分析器显微镜，本章一切论断的证据工具
- **standard tokenizer** — 标准分词：按 Unicode 词元边界切；不删停用词
- **词干化** — Stemming（Porter/Kstem/Snowball）：词形归一，过杀用 override 词典治
- **停用词** — Stopwords：删除破坏位置与评分；1.x 默认空表是故意的
- **同义词双路** — Synonyms index-time vs query-time：重建成本 vs 展开成本的经典对偶
- **synonym_graph** — 同义词图 filter：短语正确性的现代补丁 ⚠️ 书尾已现雏形
- **编辑距离容错** — Fuzzy query：1-2 距离的位图代价
- **音素匹配** — Phonetic（Metaphone）：拼错但读音对的救药
- **ngram** — N-gram：滑窗切片换部分匹配速度
- **edge_ngram** — 前缀 ngram：search-as-you-type 的索引期方案
- **改分析=重建** — Rebuild on analyzer change：分析决策不可逆性警告

## 最新演进与工业实践

1. **官方分词器矩阵成型**：kuromoji（日）、nori（韩）、smartcn/smart_english/icu_folding（中）、ICU 全套——✅ https://www.elastic.co/docs/manage-data/data-store/text-analysis ；书时代"装插件"的段落可整体替换为"开内置"。
2. **同义词工业化**：索引期同义词仍嫌重，主流做法是 **search-time synonym_graph + Synonyms API**（同义词列表可热更，⚠️ 转述）+ Query Rules（8.x 的"人工置顶+同义词"产品化，✅ querydsl 同族文档可达）。
3. **语义检索不是替代而是叠层**：embedding 让"车/汽车"这类近义匹配离开词典进入向量空间（✅ https://www.elastic.co/docs/solutions/search/vector/knn 、https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/semantic-text ），但书中分析器链仍是：倒排精确层、RRF 混合、生成式答案的上下文供给——2026 年"hybrid search"栈里词法层就是本章全家桶。
4. **中文实操换算**：书时代"装 plugin 改 elasticsearch.yml"的中文方案，今天是 `smart_cn`/ICU 内置或自定义 `analyzer` 直写 create-index JSON；`_analyze` API 调试流程与书中完全同构（✅ 同上 text-analysis 文档页）。
5. **观测面**：`_termvectors` 与 profile 里的 analyzer 计时是 2026 年排查"文档明明在却搜不到"的两板斧——书中"先 `_analyze` 后 `_search`"的诊断顺序一字未变（⚠️ 转述）。
4. **中文实战**：ik（OpenSearch-analysis-ik 一脉）vs 官方 smartcn 的取舍、`pinyin` 插件补音——社区生态远超书内容（⚠️ 未实测）。
