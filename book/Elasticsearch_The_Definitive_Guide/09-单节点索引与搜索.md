# 09 单节点索引与搜索（print 第 11 章：Indexing and Searching a Single Node）

> 内容锚点（✅ 实抓官方仓库）：030_Data_In_Data_Out（"Data In, Data Out"：Document/Index/Get/Exists/Update/Create/Delete/Version control/Partial update/Mget/Bulk）、040_Distributed_CRUD 首部。本章是"写入 API 的语义学"。转述 ⚠️。

## 1. 文档的三个坐标

书中把每个文档钉在 `(index, type(1.x), id)` 三元组上（**type 已死，现代是 (index, _doc, id)**），并逐条讲四对语义细节：

- **create vs index**：`PUT /i/t/1?op_type=create`（1.x）= 存在即 409 冲突 → 现代 `PUT /i/_doc/1` 天然幂等创建、`POST /i/_doc` 自动 id（**自动 id 走"重试可容许"路径，书中区分"可安全重试"与"不能重试"写入的两类**）；
- **delete 语义**：删除不即时物理回收（呼应 [04 章](04-Lucene入门.md) 段不可变），`op_type` 与 404/409 处理矩阵；
- **exists**：HEAD 端点只判存在，零传输；
- **get vs search**：GET by id **走 translog/段直读，不受 refresh 影响**（近实时豁免通道，呼应 [05 章](05-近实时搜索.md)）。

## 2. 更新 = 删旧 + 写新（本章最重要的机制揭底）

书中明确：Lucene 没有原地更新 → ES 的 update 是 **GET 当前 _source → 应用合并/脚本 → 索引新文档 + 标记删除旧文档**。由此派生三个代价：
1. **读放大**：部分更新要先读全文；`_source: false` 时脚本更新直接不可用（书中原话级的因果链）；
2. 版本与 seq_no 演进；
3. 大量部分更新喂养删除位图与 merge——"更新密集的 mapping 设计要偏向整体重写"。

`doc_as_upsert`、scripted upsert 均在此章定型，现代 API 同名存续（⚠️ 转述）。

## 3. 乐观并发控制：版本向量

- 内部 `_version` 单调；**`version_type=external`** 让外部系统（如数据库时间戳）当版本源——书中给出与 RDB 行版本同步的完整模式；
- 书中只有 `_version` 条件写——**`_seq_no/_primary_term` 条件写是 6.x 才引入**（对位登记：现代并发写防覆盖的正确工具是 seq_no 对，书中方法已不完整，ABA 式边角在其后版本才修净 ⚠️）。

## 4. 批量：mget 与 _bulk

- `/_mget`：一次取多文档，**按分片拆包并行**；书中演示 fields 裁剪省 `_source` 解析；
- `/_bulk`：NDJSON 换行协议、**每操作独立成败**（响应逐条状态码）、"一次批量不要同步等结果、失败单条重试"的重试矩阵——NDJSON 协议 2026 年原样在用；
- 书中容量经验：bulk 大小"5–15MB 起步观测吞吐"仍是现代官方教程数量级（⚠️ 转述）。

## 5. 单节点视角的全链路

本章末尾把"索引→buffer→refresh→段→merge→translog"画成闭环（与 [04/05 章](04-Lucene入门.md) 同一张图的操作面），给出索引吞吐的调优顺序：bulk 尺寸 → refresh_interval → replica（建索引时先 0）→ 字段瘦身（`_source` include/exclude）。

## 5.1 端点语义矩阵（书代 → 现代一一对位，⚠️ 转述）

| 意图 | 1.x（书代） | 2026 现代等价 |
|---|---|---|
| 指定 id 创建/覆盖 | `PUT /i/t/1` | `PUT /i/_doc/1`（覆盖语义不变：全量替换+新版本） |
| 仅创建 | `PUT /i/t/1?op_type=create` | `PUT /i/_create/1` |
| 自动生成 id | `POST /i/t` | `POST /i/_doc`（**不可幂等**） |
| 部分更新 | `POST /i/t/1 {"doc":{…}}` | `POST /i/_update/1`（doc 语法存活至今） |
| 取文档 | `GET /i/t/1` | `GET /i/_doc/1` |
| 删文档 | `DELETE /i/t/1` | `DELETE /i/_doc/1` |
| 批量 | `/_bulk` 含 type 行 | `/_bulk` NDJSON **action 行去 type**（协议骨架不变） |

## 5.2 bulk 的 NDJSON 骨架（协议级稳定 12 年，示意）

```
{"index":{"_index":"i","_id":"1"}}          ← 1.x 此处还有 "_type":"t"，已删
{"f":"v"}
{"delete":{"_index":"i","_id":"2"}}
```
- 每 action 独立结果：`errors:true` 时逐条查 status（429=线程池满→退避重试，503=资源不足）；
- 书中重试纪律：只有"幂等且可安全重放"的条目才进重试队列——自动 id 的 index 行重试=重复文档；
- 背压三层：bulk 线程池 → 写入队列 → 磁盘水位线，任何一层满都会把 429 甩回客户端（⚠️ 现代分层未逐一核，书代已有前两层的描述）。

## 5.3 更新/删除的隐藏成本清单

1. update = GET（可能读 translog）+ 融合 + 删旧 + 写新——**一次网络往返变四次内部操作**；
2. 删除只标位图——**删除密集索引的段膨胀**直接拖慢搜索（merge 追不上，链回 [04/05 章](04-Lucene入门.md)）；
3. `_source:false` 时 update/upsert/高亮/reindex 全部瘸腿（[10 章](10-索引管理与调优.md)meta 字段账）；
4. 高频"改一个计数器"类需求在书代答案是 `scripted_upsert`+`doc_as_upsert`，2026 答案仍是它——或干脆换时序/OLAP 引擎（[../bigdata/00-总览与阅读地图.md](../bigdata/00-总览与阅读地图.md)）。

## 跨代误读备忘（本章专属换算清单）

1. 一切 URL 含 type 的端点已断代（`/i/t/1`→`/i/_doc/1`、`/i/t/_search`→`/i/_search`、bulk action 行删 `_type`）；
2. `?version=`+`version_type=create` 的 1.x 并发配方 → 现代 `if_seq_no/if_primary_term`（**语义更强**：主term 防"同 seq_no 不同代"，书代有洞）；
3. 书中 `/_mget` 的 `fields` 参数 → 现代 `_source` includes/excludes 与 `stored_fields`，`fields` 在 mget 语境已废（⚠️ 转述）；
4. `consistency` 参数（1.x get 的 `consistency=one/quorum/all`，[14 章](14-数据分布扩展与冗余.md)）——**现代已移除**，读一致性不再可调；
5. 书代"部分更新用 `doc`、脚本用 `script`"的 body 结构 2.x 起收进 `{"doc":..}/{"script":..}` 顶层键——老帖里裸 script 串（1.x 旧式）不再接受；
6. `_bulk` 响应里"status 逐条"的现代新增项：`operation_errors`/429 文案与 backpressure（`es_rejected_execution_exception`）语义不变，处理逻辑可直接复用。

## 核心概念速览（中英对照）

- **文档坐标** — Document identity：(index, type⚠️, id) → (index, _doc, id)
- **create 语义** — op_type=create / 条件写：幂等创建与冲突码 409
- **部分更新** — Partial update：GET-融合-REINDEX 循环，不是原地改
- **doc_as_upsert** — Upsert：更新或插入二合一
- **脚本更新** — Scripted upsert：依赖 _source 开启
- **外部版本** — External versioning：外部时间戳/序列做防乱序写
- **乐观并发** — Optimistic concurrency：409 + retry；现代正解 _seq_no/_primary_term ⚠️
- **mget** — Multi-get：按分片拆包的批量点读
- **bulk/NDJSON** — Bulk API：换行 JSON 批协议，逐条成败、可重试
- **读放大** — Read amplification：更新隐含的 GET 代价
- **_source 裁剪** — Source filtering：include/exclude 省带宽与解析
- **索引期零副本** — Replica 0 during load：吞吐优化经典手筋

## 最新演进与工业实践

1. **API 路径换代**：一切含 type 的示例需机械替换为 `_doc`；条件写标准姿势为 `if_seq_no/if_primary_term`（✅ API 目录 https://www.elastic.co/docs/api/doc/elasticsearch ）——书时代版本语义的现代正确版。
2. **写入大流量配方未变**：bulk+refresh 调大+replica 后置，三件套在官方"indexing performance"指南中仍是标题级建议（⚠️ 转述）。
