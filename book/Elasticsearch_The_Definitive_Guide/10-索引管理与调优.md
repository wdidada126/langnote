# 10 索引管理与调优（print 第 12 章：Index Management and Tuning）

> 内容锚点（✅ 实抓官方仓库）：070_Index_Mgmt 全 12 文件（Create_Delete、Settings、Configure_Analyzer、Custom_Analyzers、Mappings、Root_Object、Metadata_source/_all/_id、Dynamic_Mapping、Custom_Dynamic_Mapping、Default_Mapping、Reindexing、Aliases）。转述 ⚠️。

## 1. 索引即配置：settings 解剖

书中把一个索引拆成两份"出生证明"：`settings`（分析器、分片数、刷新间隔、自定义类路径）与 `mappings`（字段类型，见 [11 章](11-映射与索引的本质.md)）。`PUT /index1 {"settings":{…}}` 时代就强调两条铁律：
1. **number_of_shards 建后不可改**（改=重建 reindex + 别名切换——路由数学原因见 [14 章](14-数据分布扩展与冗余.md)）；
2. settings 里 analyzer 部分需先建自定义类型再引用。

## 2. 分析器配置实务

- `index.analysis` 块：analyzer/tokenizer/filter 三类组件声明 + 组合；书中完整给了 **index_analyzer ≠ search_analyzer** 的搜索框配方（edge_ngram 索引期、标准查询期）；
- 自定义分析器命名后在 mapping 引用——"settings 管造、mappings 管用"的分工沿用至今。

## 3. 根对象 meta 字段群（1.x 世界观，重灾区）

print 版的 `_meta`、`_source`、`_all`、`_id`、`_index/_type`、`_boost` 一整套 meta 字段的今昔：

| 书时代 meta | 2026 命运 |
|---|---|
| `_source` 开关（关可省 2 倍盘） | 常开；关闭场景基本绝迹（脚本/更新/高亮全依赖它） |
| `_all`（默认开） | **移除**；替代 `copy_to`/multi-field（00 表 §4-2） |
| `_id` 生成 | 保留；书代已警告"能复用外部 id 就别让 ES 生成"（省一次哈希） |
| `_boost` 字段级永久 boost | 早删；运行时 boost 替代 |
| `_meta` 自由元数据 | 健在，常用于 schema 版本戳 |

## 4. 动态映射与其代价

`dynamic: true|false|strict` 三态、日期探测、数值探测；书的态度：**演示可放任，生产必须 `strict` 或显式 mapping**——动态映射制造"同名字段在不同索引类型冲突"（17 章搜索翻车根因之一）与 mapping 爆炸。

## 5. 重建索引四部曲（本章的运维主线）

书中给出改 mapping 的标准作业（**2026 年仍然一字不改适用**，✅ reindex API https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-reindex ）：

1. 新索引 v2（改好的 settings/mappings）；
2. `_reindex`（书时代无原生 reindex，用 scroll+b bulk 搬运或 logstash ——**原生 `_reindex`/`_update_by_query` 是 5.x 定型**，对位 ⚠️）；
3. 双写/追增量（外部版本防乱序，见 [09 章](09-单节点索引与搜索.md)）；
4. **`_aliases` 原子切换**：同节点"删旧别名+挂新别名"一个请求完成——本章最值得背的 API。

> 别名还有多索引查询、"按日滚动索引+latest 别名"等用法，是现代 ILM（✅ https://www.elastic.co/docs/manage-data/lifecycle/index-lifecycle-management ）的时间祖先。

## 6. 调优清单（书中分散各处，此汇总）

- 批量导入：`refresh_interval=-1` + `replicas=0` → 完成后恢复+forcemerge（书代用 `_optimize` API **已改名 `_forcemerge`** ⚠️ 对位）；
- 慢查询定位：`search slowlog`/`indexing slowlog`（1.x 已存在，日志器名 index.search.slowlog…）；
- `max_result_window`、`mapping.total_fields.limit`（书代还没有字段数熔断，登记为后出 ⚠️）。

## 6.1 settings 的动/静二分（书代分类，现代大体沿用 ⚠️）

- **static（建索引时定，改=重建/关闭再开）**：`number_of_shards`、分析器全家、`index.codec`；
- **dynamic（热改）**：`number_of_replicas`、`refresh_interval`、`blocks.*`、slowlog 阈值、水位线相关（索引级）。
- 关闭索引再开（`_close`）即可改部分 static——书中演示的"半重建"技巧；现代同样受限，**分析器改动永远要 reindex**。

## 6.2 索引模板与自动化（书代手工流 → 现代产品化）

1. 书代：脚本每天建 `logs-2014.06.01` + `_aliases` 挂 `logs_latest`；`_meta` 里存 schema 版本；
2. 后出对位（书里没有，防照抄 ⚠️）：index templates（compose/priority）→ **data streams** → **ILM** 三段生命周期 → SLM 定时快照；
3. 别名的高级玩法（书代已全）：`is_write_index` 概念的前身=手工"读写分离两个别名"；现代 `_aliases` 单请求原子增删仍是**唯一的零停机切换原语**（✅ https://www.elastic.co/docs/api/doc/elasticsearch ）。

## 6.3 一张"何时必须重建"判定表（把 5 节内容压成决策器）

| 变更 | 需要 reindex？ | 备注 |
|---|---|---|
| 加字段 | 否（动态/显式均可） | mapping 只增不改 |
| 改字段类型 | **是** | 索引结构已按旧类型生成 |
| 改分析器/analyzer 链 | **是** | 倒排词项已污染（[07 章](07-词项分析与语言处理.md)） |
| 改 refresh/replicas | 否 | 热改 |
| 改主分片数 | **是**（或 shrink/split 后出 ⚠️） | 路由数学（[14 章](14-数据分布扩展与冗余.md)） |
| 加多字段（multi-fields） | 新字段生效、旧文档不回填 | 要旧文档可搜需 update-by-query/reindex（书代=手工搬） |
| 删字段 | 实质无效（_source 还在） | 真要瘦身只能重建（[11 章](11-映射与索引的本质.md)） |

## 跨代误读备忘（本章专属换算清单）

1. `index.warmer.*`（书代招牌：预热线程/定时 warmer）——**5.x 整体删除**，现代只剩 dense_vector 图构建预热等专用路径 ⚠️；
2. `_optimize` → `_forcemerge`（同名动作两个名字，老帖里两者指一事）；`max_num_segments:1` 的适用面收窄（只给不再写的索引！书中同款警告仍有效）；
3. 书中"给 `cache_filter:true` 的大字段关缓存"一类 mapping 级缓存旋钮（`index`/`norms`/`store` 布尔群）部分已删/改名——现代用 `_index_options` 统一表达（⚠️ 转述）；
4. `index.ttl.*`、`index.timestamp.*`（1.x 内建）已死，周期管理归 ILM/data streams（✅ https://www.elastic.co/docs/manage-data/lifecycle/index-lifecycle-management ）；
5. 模板：书中只有手工脚本 → 现代 `index_template`（compose/priority/pattern 匹配）+ data stream 模板，**创建逻辑别再写 curl 轮子**；
6. `_aliases` 原子切换语法 12 年一字未变——本章最值得原样保留的 API。

## 核心概念速览（中英对照）

- **settings/mappings 二分** — 索引两份出生证明：分析配置 vs 字段结构
- **不可变分片数** — Immutable primary shard count：路由数学的硬约束（14 章）
- **自定义分析器** — Custom analyzer：组件声明+组合引用
- **index/search analyzer 对** — 非对称分析：搜索框配方的核心
- **_meta** — 文档外的索引元数据槽（schema 版本戳惯用法）
- **_source/_all/_boost** — meta 字段群：两存一亡的样本 ⚠️
- **dynamic: strict** — 动态映射收口：生产纪律
- **reindex 流水线** — Reindex-and-switch：改 mapping 的唯一安全道
- **别名原子切换** — Alias swap：读写分离的蓝绿发布
- **滚动索引** — Rolling indices：按日索引+别名的前身，ILM 的祖宗
- **slowlog** — 查询/索引慢日志：书代已有
- **_optimize→_forcemerge** — 段合并加速导入的收尾动作（改名 ⚠️）
- **max_result_window** — 深分页熔断：与协调内存挂钩（06 章）

## 最新演进与工业实践

1. **生命周期接管**：滚动索引+别名手工流被 **ILM（hot-warm-cold-delete）** 产品化（✅ 上注 ILM 链接）；书中手工模板 → 官方 `index templates`（compose/priority 机制）。
2. **Data streams**：时序/日志场景把"按日索引+别名"封装成 data stream（⚠️ 转述，书代无此概念）。
3. **Serverless 视角的反转**：云上"分片数不可变"由平台代管，本地部署仍需背这一课（✅ https://www.elastic.co/elasticsearch ）。
4. **字段治理**：mapping explosion 防护（total_fields 熔断、`flattened`/`wildcard` 新字段类型）是书代没有的后手（⚠️ 转述）。
