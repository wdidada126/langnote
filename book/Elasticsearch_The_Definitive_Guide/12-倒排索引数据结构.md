# 12 倒排索引数据结构（print 第 14 章：Inverted Index Data Structures）

> 内容锚点（✅ 实抓官方仓库）：052_Mapping_Analysis/35_Inverted_index、075_Inside_a_shard/20_Making_text_searchable。本章是全书"数据结构课"，也是最经得起时间检验的一章。转述 ⚠️ + 一处 🔧 类比实测（非 ES）。

## 1. 双词典模型

书中把"使文本可搜"拆成两半：
- **term dictionary**：词项 → posting 列表的入口。书代实现为**按字节序排序的 trie/平衡树系**（"前缀共享、有序可扫"）；现代 Lucene 为 FST（有限状态转写机）+ 块结构——**抽象不变：有序、可前缀扫、可二分**；
- **postings**：`(docID, tf?, position?, offset?, norm)` 的压缩链表；docID 单调递增 ⇒ **delta 编码 + 位打包**是书代就定型的核心招（ForDelta/PFOR 谱系 ⚠️ 具体格式名未逐一核）。

## 2. 为什么 term 查询便宜、分析字段贵

- 精确值（keyword/not_analyzed）：**整串=词项**，一次词典定位+取链表；
- 分析字段：词项被切碎归一，查询侧必须**同链分析**再逐词查——"term 查询 text 字段会命中什么"的排错答案在这里；
- 位图世界：filter 结果集是 Roaring 位图（书代开始引入），集合运算=位运算，"高选择性词项链短、低选择性链长"决定了 **AND 从最短链表开始、跳表加速 seek**（skip lists：书中画出跳表图 ⚠️ 示意）。

## 3. OR / AND / NOT 的合并代数（书中伪码转述）

- **OR = 归并**：两条有序链表线性扫；
- **AND = 迭代求交**：从最短链开始，对长链 `advance(docID)`——跳表使 seek 摊还 O(log n)；
- **NOT = 补集位图**：全 doc 域 XOR——"NOT foo 先物化整个 foo 补集"的代价警告；
- **短语 = 位置交集**：positions 链再跑一遍差分匹配；
- **评分在合并后**：tf/norm 负载随取随用，WAND 类剪枝是后话（书代未讲，登记为后出 ⚠️）。

## 4. 🔧 本机类比实测（SQLite FTS5 / DuckDB；非 ES 结论）

方法：`D:\develops\tmp\dbwave_estdg\demo_inverted.py`，Python 3.13 + sqlite3 3.45 + duckdb 1.5.5，10 万合成短文档（20 词条模板、随机 8 词），单进程一次性计时（量级参考，不追性能结论）：

| 操作 | 耗时 | 读数 |
|---|---|---|
| 普通表 `LIKE '%inverted index%'` 全扫 | **21.2 ms** | 命中 56,636 |
| FTS5 建倒排 | 346 ms（一次性） | 索引不是免费的 |
| FTS5 `MATCH 'inverted index'` | **4.9 ms** | 命中 56,636=**与 LIKE 完全一致**：查询串=词项时，倒排=查表 |
| Porter 词干：`MATCH 'invert'` | 同链命中 | "invert"命中 "inverted index"——分析链两侧同构的证据（[07 章](07-词项分析与语言处理.md)） |
| `bm25(fts)` 排序 | 即时 | tf/idf 负载在 postings 上取数 |
| DuckDB 200 万行 `GROUP BY` | **4.4 ms** | 列式扫描+哈希聚合 ≈ doc_values 聚合为何快（[03 章](03-聚合.md)）的类比 |

> 边界声明：FTS5/DuckDB 与 Lucene 的编码/段模型不同，此实验只证"倒排换查询、列存换聚合"的**结构性直觉**，不证 ES 性能。ES 本身按纪律不实测 ⚠️。

## 5.1 postings 合并算法（书中伪码的列点版，⚠️ 转述示意）

**AND（k 路求交）**
1. 按链长升序取驱动链 `p1`；
2. 对 `p1.current` 在 `p2` 上 `advance()`（跳表快进）；不等则推进 `p1`；
3. 匹配 `p2` 后在 `p3` 上继续，失败则回滚到新的 `p1` 候选；
4. 全链命中→候选文档进入打分队列（或 WAND 剪枝类优化——后出 ⚠️）。

**短语（positions 差分）**
1. 取两词的 positions 链（段内同样升序）；
2. 双指针求"差 1 共现"（`fox,hound` 要求 pos+1 相邻；slop=k 放宽到 ±k）；
3. 命中位置数即该文档短语 tf。

**NOT**
1. `ALL_DOCS` 域 ⊖ 目标链（位图域运算）；
2. **代价与补集大小成正比**——`NOT color:blue` 在"99% 都是 blue"的索引上便宜、反之灾难；
3. filter 上下文的 NOT 走缓存位图，query 上下文每次重算（[02 章](02-高级搜索与查询DSL.md)二分法的位图根源）。

## 5.2 字典侧结构小账（前缀查询为什么只能"最左快"）

- 有序字典：`fox*` = 二分定位 "fox" + 顺序扫到 "foyal"——扫过词项数 ∝ 结果宽度；
- `*ox` = 全词典扫描（O(词表大小)）——书中"昂贵"判词；**后出解药**：reverse-index（存反写词）/ngram/wildcard 字段类型（⚠️ 标注后出）；
- regex 同理走字典自动机交并——"查询期分析器"思想（[07 章](07-词项分析与语言处理.md)）在字典层的投影；
- FST 时代（书代后）：前缀共享+终态权重，词典常驻近磁盘 mmap——**性质不变、编码换代**。

## 核心概念速览（中英对照）

- **词项字典** — Term dictionary：有序词表；trie→FST→块化，可前缀扫可二分
- **postings 列表** — Postings：docID 升序链，带 tf/pos/norm 负载
- **delta 编码** — Delta/PF 压缩：升序整数链的位打包
- **跳表** — Skip list：postings 上的多级快车道，advance 的 O(log n) 来源
- **FST** — 有限状态转写机：书代后词项字典的主流形态 ⚠️
- **归并 OR / 求交 AND** — Union/Intersection：链代数；从最短链起
- **补集 NOT** — Negation bitmap：先物化全集减集，代价警告
- **短语匹配** — Position intersection：词位差分校验
- **位图缓存** — Filter cache bitmap：布尔谓词的缓存形态
- **负载** — Payload：postings 携带的 tf/位置/偏移附加数据
- **列存正排** — doc_values：排序/聚合侧的"另一本账"（🔧 DuckDB 类比）
- **HNSW（后出）** — 图近邻索引：倒排家族的 2026 新成员 ⚠️
