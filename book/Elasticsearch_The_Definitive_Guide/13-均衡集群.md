# 13 均衡集群（print 第 15 章：A Well-Balanced Cluster）

> 内容锚点（✅ 实抓官方仓库）：020_Distributed_Cluster（"Life Inside a Cluster"：空集群→集群健康→加索引→加故障转移→水平扩展→应对故障 的文件序列）、410_Scaling。本章进入集群拓扑学。转述 ⚠️。

## 1. 从空集群讲起（书中实验剧本）

书按 `/_cluster/health` 的三种色渐进演示：
- 空集群：green（没错，空即绿）；
- 建 5 主 1 副索引：yellow——**"所有主分片就位、有副本未分配"即 yellow**；单节点时副本无处安放，这是新手第一大困惑，书中用整节拆掉；
- 起第二节点：replica 分配、转 green；起第三节点：分片再平衡开始搬家。

`/_cat/shards`、`/_cluster/state` 输出被当作"集群的 X 光片"逐字段解读——这套诊断肌肉 2026 年仍是 ES 运维第一课。

## 2. 节点角色分工（1.x 口径 → 现代对位）

| 书代角色 | 职责 | 现代 |
|---|---|---|
| master-eligible | 集群状态选举/发布、分片分配 | 8.x 起 `master` 角色，建议 3 台 |
| data node | 持有分片，执行 CRUD/聚合 | `data`/分层（content/logs）细分 |
| coordinating only | 聚合请求、合并结果 | 健在，官方推荐大集群显式留 |
| client（1.x 混合概念） | — | 已并入 coordinating |
| **book 专讲**：`node.master:false` 等 1.x 开关 | — | ⚠️ 设置名换代 |

## 3. 脑裂与法定数（本章的皇冠）

书中公式：**`discovery.zen.minimum_master_nodes = (主可选节点数 / 2) + 1`**——不配这个，两半集群各自选主、双写分片、合流时数据分叉（"split brain"整页演示）。这是 1.x 时代最重要的一条运维军规。

**现代命运**（00 表 §4-14）：7.x 起 zen discovery 被**基于投票配置的集群协调层（voting configuration_excludes、quorum 自动）**替代，`minimum_master_nodes` **已删除**；公式的教学价值在于理解新协调层为什么"天生免疫经典脑裂"。⚠️ 转述官方文档。

## 4. 分片分配与再平衡

- 分配决策链（书中）：节点是否含同分片副本（硬约束）→ 过滤感知（zone/rack awareness：`cluster.routing.allocation.awareness.attributes`）→ 平衡权重（分片数/磁盘/IoLoad 三因子）；
- 再平衡参数：`cluster.routing.allocation.node_concurrent_recoveries`、磁盘高水位（**85%/90% 水位线**：超线先禁新增副本、再迁分片——书中"只读洪水标记"read-only-allow-delete_block 的成因）；
- `allocate_stale_primary / allocate_empty_primary` 命令行手术刀（cluster-reroute）：书中给足警告，"最后手段"定位至今未变。

## 5. 扩展的两种方式（与 16 章的分界）

本章只管"节点进出、分片搬家"，扩容分片数（逻辑变更）留给路由数学（[14 章](14-数据分布扩展与冗余.md)）；书中"热数据在少量节点、冷数据在大盘节点"的 **hot-warm 架构**原型出自本章，2026 年被 ILM 产品化（✅ https://www.elastic.co/docs/manage-data/lifecycle/index-lifecycle-management ）。

## 5.1 集群健康 API 的"等待语义"（书代已讲，CI/CD 里最常用）

- `GET /_cluster/health?wait_for_status=green&timeout=30s`——阻塞到状态达标，**部署脚本的同步原语**（书中给的就是这套参数）；
- `wait_for_nodes=3`、`wait_for_no_relocating_shards=true` 等条件族（⚠️ 参数名按书代/现代交集，个别后出未逐一核）；
- 颜色≠全部事实：`unassigned_shards>0` 要再看 `_cluster/allocation/explain`（**后出 API**，书代只能读 reroute 决策日志 ⚠️）——"为什么这个副本没落地"今天一调用即答。

## 5.2 分片放置的完整判定链（书中分散三节，此处串链）

1. **硬性过滤**：同分片的副本≠主的节点；awareness 属性约束（zone/rack）；include/exclude 定向；
2. **阈值闸**：磁盘 high/low/flood 三段水位（超闸先停新分配、再搬离）；
3. **平衡打分**：分片数 → 磁盘用量 → 索引/读取负载 三因子加权（`balance_shard_*_weight` 系）；
4. **节流**：`node_concurrent_recoveries`、`node_initial_primaries_recoveries`、`indices.recovery.max_bytes_per_sec`（⚠️ 具体键名代际）；
5. **延迟决策**：节点离开不立刻搬（`unassigned.node_left.delayed_timeout` 默认 1m）——"重启别慌"的官方兜底。

> 这条链是"为什么我刚加了一台机器，流量先抖再稳"的唯一正解；`_cat/recovery` 全程可观测。

## 5.3 分片尺寸与数量的现代口径（对照书中基线）

| 项目 | 书代基线 | 2026 通行口径（⚠️ 转述） |
|---|---|---|
| 单分片大小 | 10–50GB 视负载 | 日志类 10–50GB 仍常引用；向量/大宽表另算 |
| 分片数/GB 堆 | ~20 分片/GB | 官方"每 GB 堆 ≤10–20 分片"量级沿用 |
| 索引形态 | 单大索引 | **时序按滚动索引/数据流**（[10 章](10-索引管理与调优.md)） |
| 副本 | 固定 1 | 热层 1、冷层 0/1+可搜索快照省副本 |
| 主分片变更 | 只能重建 | shrink/split/可分裂时序索引（后出 ⚠️） |

## 跨代误读备忘（本章专属换算清单）

1. `discovery.zen.*` 全家（ping/minimum_master_nodes/publish_timeout）→ 7.8+ **cluster.initial_master_nodes** + voting configuration；书代"手调 m_m_n"的每一步在现代集群里都会得到 `setting [discovery.zen.minimum_master_nodes] is not supported` 报错（⚠️ 转述）；
2. `gateway.expected_nodes/expected_data_nodes/recover_after_time` → 现代 quorum+自动延迟分配，设置删除——"全集群冷启动"问题并未消失，只是不再可手调；
3. 1.x 的 `node.data/node.master` 布尔组合 → 8.x `node.roles:[...]+[ml, transform]` 列表（角色细分远超书代）；
4. 书中"客户端/负载均衡"一节推荐 Smart Routing/transport client → 现代只有 HTTP/REST 与官方负载均衡实践（coordinating 节点组）；
5. `_cluster/reroute` 命令 JSON 骨架未变——书代 `cancel/allocate_*` 示例今天仍可仿写；`retry_failed=true` 是常配后手；
6. `cluster.info.update.interval`、shard 大小启发式（书代 50GB 口径）与"每 GB 堆 10–20 分片"的现代值之间取**现文档**（⚠️ 数字代际混排，见 5.3 表）。

## 核心概念速览（中英对照）

- **集群健康三色** — green/yellow/red：红=有主分片缺失，不可查
- **协调节点** — Coordinating node：无状态合并层，可显式部署
- **法定数（旧）** — minimum_master_nodes：防脑裂手调公式，已删 ⚠️
- **脑裂** — Split brain：双主双写、副本分叉
- **投票配置（后出）** — Voting configuration：新协调层的自动仲裁（7.x+）
- **分片感知** — Awareness attributes：机架/可用区反亲和
- **再平衡** — Rebalancing：分片按权重搬家，限流可调
- **磁盘水位线** — Low/High flood-stage：85/90/95 三段闸门 ⚠️ 书代数值口径
- **只读块** — Read-only block：flood stage 的自保锁，需手工解除
- **cluster-reroute** — 分配手术刀：initialize/start/shutdown 三指令
- **hot-warm** — 冷热架构：本章原型，ILM 继任
- **分片预算** — Shard sizing heuristics：书代"20GB/分片、20 分片/GB 堆"⚠️ 口径随代更新

## 最新演进与工业实践

1. **协调层换代**：8.x/9.x 集群协调全部走 voting config + 自动 `excludes`；书中"手调 quorum"成为面试史题，但《分布式系统》视角的"部分同步+稳定主"仍是其直接案例 → [../设计数据密集型应用/08-分布式系统的麻烦.md](../设计数据密集型应用/08-分布式系统的麻烦.md)、[09-一致性与共识.md](../设计数据密集型应用/09-一致性与共识.md)。
2. **分片数焦虑的解放**：书代"主分片数不可变"在 9.x 出现**可分裂/可合并的索引类型（如 logsdb/tsdb 系 time-series indices）**方向（⚠️ 具体版本点未逐一核，转述官方发布材料）；"每索引几主片"的容量规划从玄学走向官方 sizing 计算器。
3. **Serverless/Cloud 形态**：分片分配、水位线、扩缩由平台代管；自管集群仍要背本章全部（✅ https://www.elastic.co/elasticsearch ）。
