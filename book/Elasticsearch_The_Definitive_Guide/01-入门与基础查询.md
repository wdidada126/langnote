# 01 入门与基础查询（print 第 1+2 章）

> 内容锚点（✅ 实抓官方仓库）：在线版 Part I「Getting Started」之 010_Intro（首节标题 "You Know, for Search…"）、050_Search「Searching—The Basic Tools」。以下叙述为 1.x 口径转述 ⚠️。

## 1. Elasticsearch 是什么（书中定义框架）

- 一句话：**构建在 Apache Lucene 之上的实时分布式检索与分析引擎**——书中反复强调"没有哪个单独部件是新的（全文检索、分析、分布式数据库早就存在），革命在于把部件合成一个连贯的实时应用"。
- 开篇案例（✅ 仓库部前言原文实抓）：Wikipedia 用其做带高亮的全文检索与"边输边搜/你是否想找"；The Guardian 把访客日志+社交数据做实时编辑反馈；Stack Overflow 全文+地理+more-like-this；GitHub 查询 1300 亿行代码。书中还有一句定调："Elasticsearch 鼓励你去**使用**数据，而不是因为太难查询而让数据在仓库里烂掉。"
- 与关系库的分工（1.x 口径）：ES 不是 OLTP 库——无 join、无事务、弱一致性写入、schema-on-index；它承担"人查询"和"机器聚合"两类负载。此论断在 2026 年由 ES|QL/向量检索进一步放大（见尾部演进）。

## 2. 第一组心智概念（书中"四大词"）

| 1.x 术语 | 书中释义 | 现代命运（详见 00 大对位表） |
|---|---|---|
| node | 一个运行实例；cluster=共享 cluster.name 的节点池 | 不变 |
| cluster | 数据+全部节点的集合 | 不变 |
| index | 同类文档的容器，含分片 | 不变 |
| **document type** | 索引内"表的表"（如 blog 下 user/post/comment） | **7.0 起删除**，全书最大口径陷阱 |
| shard | 索引的 Lucene 实例分片（primary+replica） | 不变 |
| replica | 主的只读拷贝，服务查询+容灾 | 不变 |

书中用一张"关系 vs ES"对照表（database→index、table→type、row→document、schema→mapping、SELECT *→GET _all）——**这张表今天必须带着 ⚠️ 读**：type 一行已失效，"无 join/无事务"两行反而更加成立。

## 3. REST 层：四个动词 + 一个 JSON

1.x 全书统一用 `curl + 9200 端口` 演示（⚠️ 转述）：

```bash
# 文档 CRUD（1.x 路径含 type！现代必须换成 /blog/_doc/1）
curl -XGET  localhost:9200/blog/user/1?pretty
curl -XPUT  localhost:9200/blog/user/1 -d '{ "full_name": "John Smith" }'
curl -XPOST localhost:9200/blog/user/1   # 部分更新（1.x 语义）
curl -XDELETE localhost:9200/blog/user/1
# 集群/索引检查
curl -XGET localhost:9200/_cluster/health?pretty
```

书中强调的三条底层规矩（至今有效）：
1. 写入响应里带 `_version`、`_creation_date`、`_updated_date`——**这些是当时的 meta 字段，`_timestamp/_source` 等已删**，现代只剩 `_version` 与 `_seq_no/_primary_term`；
2. ES 返回是"分布式部分结果的全局视图"——每个请求都可能踩到复制滞后，书在第 9 章（本目录 [09-单节点索引与搜索](09-单节点索引与搜索.md)）给乐观并发控制；
3. `?pretty` 只是给人看——"JSON 是 API 本身"，客户端应把返回当数据当流处理。

## 4. 基础查询（print 第 2 章：Basic Queries）

书中把查询教学分为三步递进（本文件按 1.x 口径转述，⚠️）：

### 4.1 query_string 一把梭
`GET /_search?q=apple` ——URL 查询串适合脚本与调试，不适合生产：转义地狱 + 无参数化。书中原话是 query string "适合手工实验，应用程序应该使用请求体"。

### 4.2 字段选择与分页
```bash
GET /_search?q=title:elasticsearch&fields=title,content&from=10&size=10
```
书中解释 `from/size` 的真实成本：协调节点必须向**每个分片**要 `from+size` 条再合并——深分页是分布式检索的第一课（现代替代见 [06-搜索内览](06-搜索内览.md) 的 PIT/search_after）。

### 4.3 过滤与"查询串里的等值"
1.x 用 `q=title:es AND +status:published` 的加减号语法做必选过滤，并提前埋下伏笔："能走 filter 缓存的谓词与打分的全文条件是两类东西"——这句话直接生长出第 3 章的 `filtered` query（已删除）与今天的 `bool.filter`。

### 4.4 排序
`sort=content.date` ——书中已警告：对分析型字符串排序会撞 fielddata/内存墙（详见 [06-搜索内览](06-搜索内览.md)）。

## 5.1 多索引、类型与元数据检索（书代惯用法，⚠️ 转述）

1.x 时代"跨索引查询"的三板斧，今天只剩前两件：

- `GET /index1,index2/_search`——逗号列表 + `ignore_unavailable=true`（书代惯配）；
- `GET /_all/_search`——全索引扫，现代仍可用但**官方劝退**（用别名/数据流圈范围）；
- `GET /_search?types_filter=user&fields=*_content`——按类型过滤、按通配选字段；**types_filter 随类型一起死亡**，`fields` 通配演化为 `_source` includes/excludes（现代健在，✅ API 目录 https://www.elastic.co/docs/api/doc/elasticsearch ）。

配套的"元端点"清单（书中都出现过，现代同名或换名）：`/_cat/indices`、`/_cat/shards`、`/_alias`、`/_mapping`、`/_settings`、`/_cluster/health`、`/_cluster/state`。

## 5.2 高频踩坑汇总（新手第一年会全踩一遍）

- URL 里裸放 JSON/空格未编码 → 400：书中教 `--data-urlencode` 或改 POST body；
- 忘加 `?pretty` 后对着压缩 JSON 发呆——"pretty 给人，机器不要"；
- `POST /index/type`（无 id）自动生成 id 却拿来当"更新"用 → 重复文档：现代仍如此，自动 id 场景下"更新"必须走 `_update`；
- 把 search 当 GET by id 用查单文档 → 慢一个数量级且受 refresh 影响（[05 章](05-近实时搜索.md)）；
- 以为写后即可搜 → "数据丢了"假报警（NRT 第一课，[05 章](05-近实时搜索.md)）；
- 用 `q=title:elasticsearch AND` 的 URL 语法做生产查询 → 转义与注入风险（现代正解：请求体 DSL，[02 章](02-高级搜索与查询DSL.md)）；
- 把 `_id` 当业务唯一键做幂等 → 自动 id 不可幂等，需确定性 id（[09 章](09-单节点索引与搜索.md)）；
- 直接照抄书中 `/blog/user/1` 路径 → 现代 404/400：类型段必须换成 `_doc`（**第一大断代**，[00 §4-1](00-总览与阅读地图.md)）。

## 核心概念速览（中英对照）

- **检索与分析引擎** — Search & analytics engine：倒排为主、列存(doc_values)为辅的读优化引擎
- **近实时** — Near Real-Time (NRT)：写入到可见约经 refresh 间隔（默认 1s），非强一致
- **文档** — Document：JSON 原子写入单元，1.x 时代"每文档自动存 _source"是卖点
- **类型** — Document type：1.x 索引内二级分类，**已死概念**（7.0 删除）
- **分片** — Shard：Lucene 实例＝索引的水平切分，主分片数建索引后不可变
- **副本** — Replica：主的拷贝，读扩展+容灾，可动态调
- **协调节点** — Coordinating node：合并各分片部分结果成全局视图
- **REST 层** — REST API over HTTP：书中以 curl 为教学语言；现为唯一入口（Thrift/Memcached 网关 2.x 已删 ⚠️）
- **query_string** — Query string：URL 内迷你语法，适合调试不适合生产
- **from/size 成本** — Deep pagination cost：每分片回收 from+size 条，翻页越深越贵
- **pretty 打印** — Pretty-print：响应是数据不是报告，客户端勿依赖缩进
- **乐观并发** — Optimistic concurrency：以 _version（今 _seq_no/_primary_term）防写覆盖

## 最新演进与工业实践

1. **路径与 type**：任何照抄书中 `PUT /blog/user/1` 的教程都过期了——现行为 `PUT /blog/_doc/1`；官方字段类型文档见 https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/field-data-types （✅ 已验可达）。
2. **客户端生态**：curl 教学依旧成立，但生产客户端收敛为官方 Java API Client、Elasticsearch Serverless/Cloud 上的语言客户端族；"Thin/Transport client 全家桶"已消失（版本点 ⚠️ 未逐一核，转述官方文档）。
3. **API 总入口**：REST API 目录 https://www.elastic.co/docs/api/doc/elasticsearch （✅）；书中"四大词 CRUD"逐条可在此找到同名端点——这是本书"概念骨架仍活着"的最直观证据。
4. **安全默认值反转**：1.x 裸 HTTP 即可读写；8.x 起 TLS+认证默认开启，本地 curl 教学需要先关安全或带凭据——**跟书敲命令在今天第一步就会 401/403**。
5. **形态**：2026 年工业实践以 Elastic Cloud/Serverless、自管 8.x/9.x 集群与 OpenSearch（Apache-2.0 分叉，https://opensearch.org/ ✅）三分；书的内容是这三者共同的"古文经"。
6. 交叉链接：倒排与 Lucene 的中文原创入门见 [../从Lucene到Elasticsearch.md](../从Lucene到Elasticsearch.md)；"为什么不是关系库"的更严格表述见 [../设计数据密集型应用/00-总览与阅读地图.md](../设计数据密集型应用/00-总览与阅读地图.md)。
