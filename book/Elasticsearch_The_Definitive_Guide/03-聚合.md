# 03 聚合（print 第 4 章）

> 内容锚点（✅ 实抓官方仓库）：在线版 Part「Aggregations」301–306 六个章文件（Overview/Example Walkthrough/Making Graphs/Approximate Aggregations/Significant Terms/Practical Considerations）。print 第 4 章处于 facets 向 aggs 过渡的当口，以下口径按书与在线 1.x/2.x 实录转述 ⚠️。

## 1. "搜索回答'是什么'，聚合回答'有多少'"

书中开篇对照：SQL 的 `WHERE` 对应查询 DSL，`GROUP BY + count()` 对应聚合。但 ES 的卖点是**同一次请求同时返回命中文档与聚合结果**，且聚合在协调-分片两层树状执行：

```
（1.x 请求体，⚠️ 转述示意）
{ "aggs": { "by_date": { "date_histogram": { "field": "ts", "interval": "month" },
            "aggs": { "avg_price": { "avg": { "field": "price" } } } } } }
```

- **桶（bucket）与指标（metric）** 二分：桶=分组规则（terms/range/date_histogram/histogram/filter/nested…），指标=对桶内文档的数（avg/min/max/stats/cardinality…）；**子聚合可任意嵌套**，书的比喻是"俄罗斯套娃"，代价是每多一层桶，协调节点合并的组合数爆炸。
- 1.x 语境声明：print 版主体教的是 **facets**（terms/statistical/date_range 三类，平铺不能嵌套），同时用整章预告 aggs API 为"facets 的未来"。**facets 在 3.0 即被移除**（✅ 大对位表 §4-3），今天读本章必须整体心译为 aggs——本文件直接以 aggs 正名叙述，facets 仅作历史注脚。

## 2. terms 聚合的"近似"真相（本章最重要）

书中 304_Approximate 一节讲了两层近似（现代行为同源 ⚠️ 转述官方文档）：

1. **分片局部 top-N**：协调节点向每个分片要 `size × shard_size_factor`（默认乘数 1.5，可调 `shard_size`）条再合并——**全局计数对，排名可错**；
2. **长尾词项被丢弃**：文档高度倾斜时，小词项在个别分片落入 tail，其总数被截断。书里给出的诊断字段是 `doc_count_error_upper_bound`（误差上界）与 `sum_other_doc_count`（桶溢出）。

> 2026 年口径：`terms` 聚合的这两个返回字段与 `shard_size` 调法**原样健在**（✅ https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl 同站文档族）。本章是"分布式系统近似语义"最好的入门案例之一，对照 [../设计数据密集型应用/00-总览与阅读地图.md](../设计数据密集型应用/00-总览与阅读地图.md) 的"最终一致性读"讨论。

## 3. 指标聚合家族（书中清单）

- `stats`/`extended_stats`/`percentiles`（t-digest 近似分位数，1.x 引入 ⚠️ 版本点未逐一核）；
- **`cardinality` = HyperLogLog++**：书中专节讲"精确去重为什么不可行"——每词项/用户集合全量存位图内存爆炸，HLL++ 用 ~KB 级误差换 O(1) 内存；给出精度权衡表（precision_threshold）。这是全书第一次也是唯一一次把概率数据结构当应用接口暴露；
- `date_histogram` + `interval`：**书中动态间隔 `interval: auto` 与 date_histogram 的"日历意识"（月长不等）**，现代演化为 `calendar_interval`/`fixed_interval`（5.x 起拆分）；
- `top_hits`（书 306 节重点）：每个桶里再取文档——nested 场景唯一解药，代价巨大；
- 桶家族：`range`/`date_range`/`histogram`/`filters`/`global`/`reverse_nested`。

## 4. significant_terms：本书的"差异化招牌"

305_Approximate 之后的 significant_terms 教**"什么词在这堆结果里显著异常"**（对比背景语料），给出 JLH/percentage/NDR 等打分法。它是"推荐/异常检测式搜索"的最早产品化之一；2026 年同名聚合仍在（⚠️ 转述），思想被 LLM 时代的 embedding 显著性分析部分吸收，但作为"无监督词表差异"工具依然独一份。

## 5. 做图与工程告诫（303/306 节）

- 聚合的 `format`/`time_zone` 输出设计让客户端零计算（书中演示 Kibana 前身用法）；
- **高基数 terms（user_id 级）是内存炸弹**：桶数 = 协调节点合并的堆占用；书中解法三条：(a) precision 换内存；(b) `composite` 分页聚合——**注意：composite 是 6.x 才有的**，print 时代只能 shard_size 调参（⚠️ 版本对位，书里没有的不假装书里有）；
- 嵌套桶组合爆炸：每层 terms top-K × 子聚合 K' → 请求变成 O(K^K')，书中原话是"聚合树有深度预算"。

## 5.1 聚合速查卡（书代参数 → 现代键名，⚠️ 转述对位）

| 聚合 | 书代关键参数 | 现代键名/状态 |
|---|---|---|
| terms | size/shard_size/order(按子聚合) | 同名健在；多指标排序扩展 |
| date_histogram | interval/pre_zone/post_zone | **calendar_interval/fixed_interval**（5.x 拆分）+ time_zone |
| histogram | interval/min_doc_count | 同名；extended_bounds 画空桶 |
| range/date_range | ranges 数组 | 同名 |
| filters | 旧 filters 数组→**named 键值对** | 书代已处过渡期 ⚠️ |
| stats/extended_stats | fields→field（单字段化） | 5.x 改单字段；多指标靠子聚合 |
| percentiles | compression(默认100) | 同名，t-digest 参数化 ⚠️ |
| cardinality | precision_threshold | 同名；上限 40000（现代值，⚠️） |
| top_hits | size/sort/_source | 同名 |
| global | 无参 | 同名（"忽略查询的总数"） |
| nested/reverse_nested | path | 同名（[11 章](11-映射与索引的本质.md)关联模型） |
| missing | field | 后被 filters 取代（⚠️ 弃用时间未核） |

## 5.2 一次聚合请求的资源账（书中分散各节，此处结总账）

1. 分片侧：桶在**各分片本地用内存堆表**构建——高基数 terms 先打爆分片堆（熔断器 `request` 域，[15 章](15-集群存活保障与生产运维.md)）；
2. 协调侧：合并 K 个分片 × N 个桶，复杂度 O(ΣK)；子聚合让每层再乘一遍；
3. I/O 侧：doc_values 列扫（🔧 列存 GROUP BY 类比见 [12 章](12-倒排索引数据结构.md)）；`percentiles` 的 t-digest 合并、`cardinality` 的 HLL++ 寄存器合并是**可交换摘要**——这正是 DDIA「可合并数据结构」一节的实例 → [../设计数据密集型应用/02-数据模型与查询语言.md](../设计数据密集型应用/02-数据模型与查询语言.md)；
4. 时间轴：date_histogram 是日志聚合的基本桶，`pre_zone` 时代时区错位的"日界漂移"是书中经典案例。

## 跨代误读备忘（本章专属换算清单）

1. print 示例里的 `"facets":{...}` 全部作废；`"aggs"` 骨架（顶层对象、按名嵌桶）12 年未变——**本章是全书"语法化石最少"的一章**；
2. `"fields":[...]`（stats 多字段）→ 5.x 起 `"field"` 单数；多指标改多子聚合；
3. `interval` 一词在 date_histogram 里被拆成 `calendar_interval`（日历月/年）与 `fixed_interval`（1440m 秒级精确）——书中"一个月=30 天"的演示按新键二选一重读；
4. `missing` 聚合 → 用 `filters`/`missing` 子句替代（弃用路径 ⚠️ 未核细节）；
5. 书代 `order` 按子聚合排序需 `reverse`，现代 `order:[{_count:desc},...]` 数组式；
6. 没有 `composite`、没有 `auto_date_histogram`、没有矩阵聚合——遇到"书里说做不到"的高基数遍历，先查现代同名解法再下结论。

## 核心概念速览（中英对照）

- **桶与指标** — Buckets & Metrics：聚合代数的两原语；分组+数数
- **aggs API** — Aggregations API：1.x 时代新客，3.0 后 facets 的唯一后继
- **facets（史）** — Facets：平铺不可嵌套的前代统计接口，已删 ⚠️
- **shard_size** — Shard size：分片级预取倍数（默认 1.5×），控排名误差
- **误差上界** — doc_count_error_upper_bound：terms 近似排名的诚实申报
- **HyperLogLog++** — cardinality 聚合：概率去重，KB 级内存换全量精度
- **t-digest** — percentiles：近似分位数的压缩数据结构（书时代引入 ⚠️）
- **date_histogram** — 日期直方图：日历感知的分桶（现代拆 fixed/calendar_interval）
- **top_hits** — Top hits：桶内取代表文档；nested 必备，昂贵
- **significant_terms** — 显著词项：前景 vs 背景语料的统计学排序，招牌功能
- **嵌套爆炸** — Aggregation tree cost：桶深组合数=协调节点内存×CPU
- **composite（后出）** — Composite aggs：分页式桶遍历，print 版没有 ⚠️

## 最新演进与工业实践

1. **接口长存、语法微调**：aggs JSON 是 Query DSL 之外第二套"全版本兼容区"；书里的 terms/date_histogram/percentiles 例子今天改改字段名仍可跑（✅ 总入口 https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl ）。
2. **ES|QL 对聚合的重写**：9.x 的 `STATS … BY …`（✅ https://www.elastic.co/docs/reference/query-languages/esql ）把"桶+指标"翻译回 SQL 方言，HLL/t-digest 变成 `APPROX_COUNT_DISTINCT()/MEDIAN()`——书中"近似语义"的决策树在 ESQL 里由优化器代管（细节 ⚠️ 未实测）。
3. **doc_values 让聚合免堆外调优**：print 时代"聚合前先想 fielddata"的运维课（见 [11 章](11-映射与索引的本质.md)）被 5.x 起默认列存（doc_values）终结；2.x 时代"给 text 开 fielddata 做聚合"今天等同事故（text 默认无 doc_values，须 keyword 或 runtime field ⚠️ 转述）。
4. **矩阵聚合与 ML**：8.x/9.x 的 matrix_stats、Inference/ML 聚合作为书中统计家族的扩展存在（⚠️ 转述官方文档，未逐一核）。
5. **工业实践**：日志平台的 terms-over-`@timestamp` 看板、电商 facet 导航（对照书中"搜索+聚合一次请求"）仍是 aggs 的两大消耗方；高基数聚合的对策从"shard_size 调参"升级为"ES|QL 聚合下推 + ILM 降热数据规模"（✅ ILM 文档 https://www.elastic.co/docs/manage-data/lifecycle/index-lifecycle-management ）。
6. 对照阅读：列式聚合为何快 → [../bigdata/09-存储与文件格式.md](../bigdata/09-存储与文件格式.md)（列存/压缩块）；🔧 本机类比（DuckDB 2M 行 GROUP BY 4.4ms）见 [12-倒排索引数据结构](12-倒排索引数据结构.md) 实测节——聚合走 doc_values 的直觉与列存扫描同源。
