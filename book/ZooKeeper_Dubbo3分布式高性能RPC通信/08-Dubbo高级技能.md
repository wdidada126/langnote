## 核心精讲

（以下为教学性梳理，图示/配置均**教学示意，不参与构建**。） 

### 8.1 服务提供者集群

- 同一服务部署**多个 Provider 实例**并都注册到注册中心；
- 价值双重：**水平扩展吞吐** + **实例级高可用**（一个挂了还有别的）。
- 与第 1/3 章 ZK 的「集群容错」是不同层：ZK 集群保证**协调服务**可用，
  Provider 集群保证**业务服务**可用。

### 8.2 集群容错（本章核心）

```text
# 教学示意，不参与构建：Dubbo 集群容错策略速查
Failover  (默认) -> 调用失败自动换另一台重试；适合读，不适合非幂等写
Failfast        -> 失败立即报错，不重试；适合非幂等写
Failsafe        -> 失败忽略（记日志）；适合审计/统计类可丢调用
Failback        -> 失败后台定时重试；适合通知类
Forking         -> 并行调多台取首个成功；延迟敏感、资源换速度
Broadcast       -> 广播给所有实例；适合刷新缓存等
```

> 关键认知：**重试（Failover）只对幂等调用安全**。非幂等写用 Failfast 避免重复执行。
> 这与第 1 章「RPC 三态（成功/失败/超时）」一脉相承——超时时服务端可能已执行。

### 8.3 负载均衡

| 策略 | 逻辑 | 适用 |
| --- | --- | --- |
| Random | 加权随机 | 默认，简单通用 |
| RoundRobin | 加权轮询 | 需均匀轮转 |
| LeastActive | 选活跃调用数最少者 | 自动避让慢节点 |
| ConsistentHash | 按参数哈希固定落点 | 有状态/缓存亲和 |

```text
# 教学示意，不参与构建：LeastActive 的直觉
节点A 正在处理 10 个调用，节点B 处理 2 个
新请求 -> 选 B（最不忙），自然把流量从慢/忙节点引开
```

## 版本演进

- **本书无第二版**；本节写 2022 年口径 → 2026 年视角的变化。
- **熔断/限流/降级（本书缺口）**：本章只有「容错 + 负载」，但生产高可用三件套还应包括
  **熔断（Circuit Breaker）、限流（Rate Limit）、降级（Fallback）**，通常由 Sentinel /
  Hystrix 系与 Dubbo 整合实现。本书 8.2 的「容错」不等于「熔断降级」，需补。
- **标签路由 / 条件路由（本书缺口）**：Dubbo 3 的精细化流量治理（金丝雀、按标签分流）
  是 8.1/8.3 的现代升级，本书停留在基础策略。
- **Triple 对高可用的跨语言意义（本书缺口）**：本书高可用链路全在 Java 私有协议内；
  Triple（HTTP/2+Protobuf）让跨语言服务也能纳入同一套容错/负载体系，本书未覆盖。
- **与 Kubernetes 服务治理的边界**：2026 年部分负载均衡/熔断职责可由 K8s + 网格承担，
  与 Dubbo SDK 治理互补，本书未触及。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「Failover 重试万能」 | 重试仅对**幂等**调用安全；非幂等写用 Failfast，否则重复执行 |
| 2 | 「容错 = 高可用全部」 | 高可用还需熔断/限流/降级，本书只讲了容错+负载 |
| 3 | 「负载均衡随机就好」 | 慢节点场景 LeastActive 更优；有状态用 ConsistentHash |
| 4 | 🔧 缺熔断/限流/降级 | 生产高可用三件套（Sentinel 系），本书 8.2 未覆盖 |
| 5 | 🔧 缺标签/条件路由 | Dubbo 3 精细化流量治理（金丝雀），本书仅基础策略 |
| 6 | 🔧 高可用链路锁死 Java 私有协议 | 缺 Triple 使跨语言服务难纳入同一容错体系，本书未覆盖 |
| 7 | 🔧 未提与 K8s/网格治理边界 | 2026 年部分治理职责下沉 K8s+网格，与 SDK 治理互补 |
