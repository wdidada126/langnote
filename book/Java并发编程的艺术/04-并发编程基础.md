## 二、核心精讲

### 2.1 线程的 6 状态（JDK 5+ 精确）
- `NEW`：未 start。
- `RUNNABLE`：就绪或运行中（JVM 不区分，OS 调度决定）。
- `BLOCKED`：等 `synchronized` 的监视器锁（**仅此一种**）。
- `WAITING`：`wait()`/`join()`/`LockSupport.park()` 无超时。
- `TIMED_WAITING`：带超时的上述。
- `TERMINATED`：run 结束。
- 注意：`BLOCKED` 仅指 `synchronized` 竞争；`ReentrantLock` 的等待属于 `WAITING`（在 AQS 队列里 park）。

### 2.2 中断（与《实战》7 章 + 《之美》中断专篇互补）
- `thread.interrupt()`：设中断标志；若线程在 `wait/sleep/join` 阻塞则抛 `InterruptedException` **并清除标志**。
- `isInterrupted()`（不清标志） vs `interrupted()`（静态，清标志）——后者是"自清"，易误用。
- 正确处理：catch `InterruptedException` 后**要么抛出、要么重新 `interrupt()`**，绝不能吞。
- `synchronized` 阻塞**不响应**中断 → 要可中断用 `ReentrantLock.lockInterruptibly()`。

### 2.3 等待/通知机制
- 必须在 `synchronized(obj)` 内调用 `obj.wait()`，否则抛 `IllegalMonitorStateException`。
- 经典范式：`synchronized(lock){ while(!condition) lock.wait(); ... }`，用 `notifyAll` 更安全。
- `wait()` 释放锁 → 进入等待集 → 被 `notify` 唤醒后**重新抢锁**才返回。
- 现代替代：`Lock + Condition`（可多等待集）、`CompletableFuture`（异步回调）、`StructuredTaskScope`（作用域取消）。

### 2.4 `ThreadLocal`
- 每个线程持有自己的变量副本；常用于"线程内上下文传递"（事务 ID、用户身份、SimpleDateFormat 线程安全化）。
- 实现：线程持有 `ThreadLocalMap`，key 是 `ThreadLocal` 弱引用。
- **内存泄漏根因**：key 弱引用会被 GC，但 value 是强引用 → 线程池线程长期存活时 value 无法回收（见《之美》`concepts/ThreadLocal与内存泄漏.md` 专篇 + 修正用 `ScopedValue`）。

## 三、版本演进

- **JDK 1.0**：`stop/suspend/resume`（后废弃）、`Thread.run`。
- **JDK 5 (2004)**：`Callable`/`Future`、`ThreadPoolExecutor`、`LockSupport` 引入；线程状态精化为 6 态。
- **JDK 8**：`CompletableFuture` 异步编排（`thenApply/thenCompose` 替代手工 `wait/notify`）。
- **JDK 21-25**：虚拟线程（JEP 444）→ 线程不再是"昂贵资源"，`ThreadLocal` 的"一线程一副本"成本模型改变；`ScopedValue`（JEP 506, JDK 25 GA）替代 `ThreadLocal` 做不可变上下文。

## 四、经典论文 / 原始文献

- **Goetz, "Java Concurrency in Practice" 第 1/4/7 章**——线程状态与中断的工程权威。
- **Hoare, "Monitors: An Operating System Structuring Concept" (CACM 1974)**——wait/notify 监视器语义源头。
- **Dijkstra, "Cooperating Sequential Processes" (1965)** / **"GOTO Considered Harmful" (1968)**——结构化控制流（中断/取消应受作用域约束）。
- **JEP 444 / 453 / 506**——虚拟线程、结构化并发、ScopedValue。

## 六、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "`BLOCKED` 包含所有等待" | 仅 `synchronized` 竞争；`ReentrantLock` 等待是 `WAITING` |
| 2 | "catch `InterruptedException` 空着" | 必须 reInterrupt 或上抛，否则信号丢失 |
| 3 | "`wait` 用 `if` 判断" | 必须 `while`（过早唤醒 + 被抢） |
| 4 | "`ThreadLocal` 不会泄漏" | 线程池下 value 强引用泄漏；用 `remove()` 或 `ScopedValue` |
| 5 | "`interrupted()` 和 `isInterrupted()` 一样" | 前者清标志（静态），后者不清 |
| 6 | "新代码手写 wait/notify" | 用 `Condition`/`CompletableFuture`/结构化并发 |
