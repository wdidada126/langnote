## 二、核心精讲

### 2.1 `ConcurrentHashMap`（本书重点，含 JDK 7/8 对比）
- **JDK 7**：`Segment[]` 数组，每 `Segment` 是一把 `ReentrantLock`，默认 16 段 → 段级并发（写不同段不互斥）。代价：全表操作（size/clear）要锁所有段。
- **JDK 8（本书第 2 版已覆盖）**：废弃分段锁，改为 **`table` + `Node` 桶**，并发粒度降到**单个桶**：空桶用 CAS 放头节点，非空桶对桶头 `synchronized` 锁。**更细粒度、更高并发**。
- `size()` 用 `baseCount` + `CounterCell[]`（分段计数，类似 `LongAdder`）避免全局锁。
- 🔧 第 1 版基于 JDK 7 分段锁；第 2 版已更新 JDK 8。注意旧笔记若写"16 段"多半引自第 1 版。

### 2.2 `CopyOnWriteArrayList` / `CopyOnWriteArraySet`
- 写时**复制整个底层数组** → 读操作**完全无锁**（snapshot 读），适合**读多写极少**（如监听器列表、配置）。
- 代价：写昂贵（复制 + 全量），且读看到的是**写之前的快照**（弱一致性，非实时）。
- 误用：写频繁的集合用 COW 会 GC 压力爆炸。

### 2.3 阻塞队列（7 种，与《之美》专篇互补）
- `ArrayBlockingQueue`：数组 + 一把 `ReentrantLock` + 两个 `Condition`（notEmpty/notFull）；**有界、默认不公平**。
- `LinkedBlockingQueue`：链表，**默认容量 `Integer.MAX_VALUE`**（无界，生产事故 TOP1）；读写各一把锁。
- `PriorityBlockingQueue`：堆结构、无界、无阻塞取（永远有，除非空）。
- `DelayQueue`：基于 `PriorityBlockingQueue` + 延时；`DelayedWorkQueue` 是 `ScheduledThreadPoolExecutor` 的内部实现（见《之美》09 章）。
- `SynchronousQueue`：不存元素，直接 handoff；`CachedThreadPool` 的投递通道（见《之美》专篇 Scheduler-Lea-Scott）。
- `LinkedTransferQueue`：dual data structure（data/item 两种节点），`transfer` 阻塞等消费者。
- `LinkedBlockingDeque`：双端阻塞队列。

### 2.4 `ForkJoinPool`（工作窃取）
- 每个 worker 一个**双端队列（deque）**；自己从**头**取任务，偷别人的从**尾**取 → 减少竞争。
- `fork()` 把子任务压自己队列头；`join()` 等结果（若自己空则去偷）。
- `parallelStream()` / `CompletableFuture` 默认 ForkJoinPool（除非指定）。
- 适合**可分解的 CPU 密集**任务；I/O 阻塞任务会卡住窃取（虚拟线程更合适）。

### 2.5 `ConcurrentLinkedQueue`
- Michael-Scott 无锁队列（详见《之美》`concepts/Michael-Scott无锁队列.md`）：头尾指针 + CAS；`tail` 有 slack（不总指向真正尾）。

## 三、版本演进

- **JDK 5**：`ConcurrentHashMap`（分段）、`CopyOnWriteArrayList`、阻塞队列、`ConcurrentLinkedQueue`、`ForkJoinPool` 全部随 J.U.C 引入。
- **JDK 7 (2011)**：`ConcurrentHashMap` 仍是分段锁（本书第 1 版基线）。
- **JDK 8 (2014)**：`ConcurrentHashMap` 重写为桶级 CAS+锁；`LongAdder` 式分段计数。
- **JDK 21**：虚拟线程 → ForkJoinPool 不再是"I/O 并发"首选，结构化并发接管编排。

## 六、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "CHM 是 16 段锁" | 🔧 JDK 8 起是桶级 CAS+锁，无 Segment |
| 2 | "`LinkedBlockingQueue` 无界安全" | 默认 `Integer.MAX_VALUE` → 内存撑爆；务必指定容量 |
| 3 | "COW 适合写多" | 写复制全数组，写多即 GC 灾难；仅读多写极少 |
| 4 | "ForkJoin 适合所有并发" | 仅 CPU 密集可分解任务；I/O 阻塞用虚拟线程 |
| 5 | "阻塞队列都公平" | `ArrayBlockingQueue` 默认非公平（可指定） |
