## 核心概念速览（中英对照）

- **只做一件事** — Do Only One Thing：函数停留在单一抽象层级，"一件事"由抽象层级而非行数定义（4.3.1）
- **让函数尽可能小** — Let Them Be Small：原书给出的量化建议是"理想约 4–5 行，最多约 10–15 行"（⚠️ 见下方取证说明）（4.3.2）
- **函数命名** — Function Naming：动词/动词短语，成员函数名不重复类名信息（4.3.3）
- **意图揭示名称** — Intention-Revealing Name：用 `createDetailedInvoice()` 取代 `createInvoice(true)`（4.3.4，L4-22/26）
- **标志参数** — Flag Argument：布尔参数暴露"这个函数做两件事"（4.3.5，L4-24/25）
- **参数对象** — Parameter Object：一组参数总在成对出现/传递时，提升为一个类型（4.3.5 的处方）
- **输出参数** — Output Parameter / In-Out Parameter：以引用回传结果，破坏"读起来像表达式"（4.3.5 反对）
- **按值返回** — Return by Value：C++11 后大对象按值返回不再是性能问题（4.3.5，L4-28）
- **C 风格字符串** — Old C-Style `char*`：`char buf[64]` + 无边界检查 API 的历史包袱（4.4.1）
- **不安全格式化族** — `printf`/`sprintf`/`gets`：格式串与实参类型不匹配无编译期保障（4.4.2）
- **C 风格数组** — C-style Array：退化为指针、丢失长度、与算法库不亲（4.4.3）
- **C 风格转换** — Old-Style Cast `(T)x`：无法区分意图（常量提升？向下转型？重新解释？），`-Wold-style-cast` 可查（4.4.4）
- **宏** — Macro：文本替换的双求值、无类型、无作用域、调试不可见（4.4.5，L4-31/32）

## 1. 动机：函数是"抽象层级"的原子，C 风格是"信任契约"的漏洞

4.3 的核心不是长度而是**层级**：一个函数里若同时出现"业务流程"与"字节位操作"，读者必须同时持有两套心智模型。
长度阈值只是这个判据的粗筛器。作者在这里明确引 Martin《Clean Code》那句"函数应该小，还应该更小"。

> ⚠️ 取证说明：原版该节的量化句子在 PDF 文本层丢失了连字符，显示为 "Ideally 45 lines, maximum 1215 lines"，
> 按上下文与 Martin 口径推定为 **4–5 / 10–15 行**。引用本书"几行"主张时请注意该数值为推定，不宜当硬指标转述。

4.4 的动机则是 C++ 工程的特有病症：**"C 工程里长出来的 C++"**——`char*`、`printf`、裸数组、`(T)` 强转、宏。
它们不是因为坏而存在，是因为**在 C++98 之前没有替代品**；C++11/17 之后替代品齐了，旧写法就纯粹是风险。

## 2. 机制：五条函数规则 + 五条除旧规则

**4.3.5 参数与返回值的判据链（作者自己给 Martin 打的折扣，值得全引）**：
Martin 的"理想 0 参、1 参、2 参，3 参尽量避免、4 参需特殊辩护"被作者逐条审视后指出：
Martin 的例子是 Java，他说的其实是**方法**；C++ 成员函数天然带隐式 `this`，"0 参方法"意味着**读改对象状态**，
副作用反而更大。作者给出的现代判据是：**参数是否共同表达一个概念**（`x,y` 是一个点、`begin,end` 是一个区间），
以及**别用输出参数伪装返回值**——按值返回 + 移动语义（L4-28）在 C++11 后已无性能借口。

**4.4 各条的替代品（原书 → 现代）**：

| 旧写法 | 本书建议 | C++17/20/23 后的最优解 |
| --- | --- | --- |
| `char buf[N]` + `strcpy` | `std::string` / `std::ostream` | `std::string_view` 做只读入参；`std::format` 生成 |
| `printf("%.2f", x)` | 流或更安全的封装 | `std::format`（C++20）/ `std::print`（C++23）——**格式串编译期检查** |
| `gets(buf)` | 绝不用 | C++17 起标准库已移除；仍在 CRT 里（见实测） |
| `int a[10]` | `std::array` / `std::vector` | `std::span`（C++20）做非拥有视图 |
| `(int)d`、`(double*)p` | `static_cast`/`reinterpret_cast` | 语义化转换 + `gsl::narrow` 类工具 |
| `#define SQUARE(x) ((x)*(x))` | `constexpr` 函数 / 变量 | `constexpr auto square = [](auto x){return x*x;}` |

## 🔧 实测：这些旧写法今天由谁接管

**(1) 宏的双求值——不是传说，是可复现的错误。** `g++ -std=gnu++17 -Wall -Wextra` 编译并运行 `SQUARE(n++)`：
**已实测 g++ 15.2**（诊断 + 运行输出）：

```text
a1_cstyle.cpp:16:42: warning: operation on 'n' may be undefined [-Wsequence-point]
   16 |     printf("SQUARE(n++) = %d\n", SQUARE(n++));
运行输出：
SQUARE(n++) = 20
n after = 6
```

期望 16（先乘后自增）或 25（先自增后乘），**实得 20**——因为宏展开成 `((n++) * (n++))`，两次自增在同一表达式里
无顺序保证。编译器只能给出"未定义"警告，运行时给你任意值。这就是 4.4.5 全部论证的浓缩版。

**(2) `printf` 族：类型不匹配只在部分场合被抓住。**

```text
g1c_badsprintf.cpp:2:44: warning: format '%d' expects argument of type 'int', but argument 2 has type 'double' [-Wformat=]
运行输出：0        <-- UB：本应打印 1.5，实得 0
```

同一个错误换成 `std::format("{:d}", 1.5)`，**g++ 15.2 在编译期直接判决**：

```text
error: call to consteval function 'std::basic_format_string<char, double>("{:d}")' is not a constant expression
error: call to non-'constexpr' function 'void std::__format::__failed_to_parse_format_spec()'
```

**(3) `sprintf`/`string`/`format`/`sstream` 的行为差异（整洁 ≠ 同输出）。** 同一组实参，
**已实测 g++ 15.2**（`-std=gnu++23 -Wall -Wextra`）：

```text
sprintf : Widget x3 = 4.50 EUR
format  : Widget x3 = 4.50 EUR
sstream : Widget x3 = 4.5 EUR      <-- 流默认精度，不是"更整洁的等价物"
string_view 零拷贝: clean-cpp (size=9, 无临时对象)
容器取代 C 数组: <a><b><c>
```

要点：4.4.1 推荐流替换 `printf` 时**没有提醒默认精度差异**——迁移 C 代码时这是真实的静默行为变更。
`std::format` 才是"语义等价且类型安全"的现代替换。

**(4) `gets()` 在 2026 年的工具链现状**（标准移除 ≠ 编译失败）：

```text
warning: call to 'gets' declared with attribute warning: Using gets() is always unsafe - use fgets() instead [-Wattribute-warning]
```

C++17 已把 `gets` 从标准中移除，但 MinGW 的 CRT 仍导出它并挂了 `warning` 属性——**平台层留了后门，
语言层只能靠警告**。要在 CI 里真正禁掉，需要 `-Werror` 或链接期符号封禁。

**(5) C 风格转换的定位**：`-Wold-style-cast` 逐点报出 `use of old-style cast to 'double*'`，配合
`-Werror` 可把 4.4.4 变成硬门禁（已实测 g++ 15.2，三个旧式转换三行诊断）。

## 3. 权衡

- **小函数 vs 跳转成本**：拆到 4 行的函数会让"阅读=反复跳转"。作者的补救是"自上而下读代码，像讲故事"（4.2.1），
  但真实约束是**编辑器/评审工具**：今天的 diff 视图与 tag jump 已把成本压低，10 年前并非如此。
- **禁止输出参数 vs 性能**：热路径里"往已有 buffer 里写"是合理模式（`std::ranges` 的 `to`、`format_to` 都是它）。
  判据是**缓冲区是不是函数的概念一部分**——是，就明写 `OutputIt`/`span` 参数；不是，就按值返回。
- **禁宏 vs 现实**：条件编译、`assert`、日志级别、跨编译器 intrinsic 至今仍需宏。本书立场应读作
  "**宏不做算术与常量**（那是 `constexpr` 的活），只做预处理该做的事"。
- **`-Wold-style-cast` 的可接受噪声**：`(void)unused;`、`static_cast` 场景里的合法 C 转换（如 `(char)` 字面量）
  会报一堆；工业项目通常只在**新代码目录**开启。

## 4. 相邻概念对比

| 概念对 | 差别 | 为什么容易混 |
| --- | --- | --- |
| 小函数 vs 短函数 | 小=抽象层级单一；短只是行数 | 用行数指标考核，产出 120 行"一行语句拆成 40 行"的假整洁 |
| `std::string_view` vs `std::string` 参数 | 视图零拷贝但**不拥有**，生命周期归调用方 | 悬垂引用是 C++20 后新增事故类型：函数返回 `string_view` 指向局部 `string` |
| `static_cast` vs `reinterpret_cast` | 前者表达"可证明的值转换"，后者表达"我要绕过类型系统" | C 风格 `(T)` 把两者混成一个记号，所以本书要求拆开 |
| `constexpr` 函数 vs 宏 | 有类型、有作用域、可调试、可求值于编译或运行期 | 宏仍不可替代之处只有"跨翻译单元的文本技巧" |
| 按值返回 vs 输出参数 | 按值返回可读且移动友好；输出参数必要前提是缓冲区属于概念 | 老代码库中"返回 bool + 输出参数"模式与异常式 API（本书 5.7）互斥，迁移时要一并处理 |

## 最新演进与工业实践

- **标准提案与版本对位**：`std::format` 源自 fmt 库，提案 wg21.link/P0645（实测标题 *Text Formatting*，R10）→ C++20；
  `std::print` 为 wg21.link/P2093（实测标题 *Formatted output*，R14）→ C++23。
  ⚠️ 本机 libstdc++ 15 的 `<print>` 在其他书目实测中出现过链接缺符号问题，使用前先跑冒烟测试；`<format>` 在本机
  `gnu++20/gnu++23` 实测可用，`gnu++17` 下 `std::format` 不存在（实测报 `'format' is not a member of 'std'`）。
- **`std::span`（C++20）与 GSL**：4.4.3 的"用容器替代数组"在**不拥有内存**的边界上由 `std::span<std::byte>`/
  `gsl::span` 收尾；`gsl::narrow<T>` 把"可能丢值的转换"从注释变成运行期检查——正是 4.4.4 的落地形态。
- **clang-tidy 对应项**（⚠️ 本机未安装，规则名按上游文档口径）：
  `bugprone-macro-parentheses`、`bugprone-suspicious-semicolon`、`cert-err34-c`（不检查 scanf 返回值）、
  `cppcoreguidelines-pro-type-vararg`（禁 `printf` 类可变参数）、`cppcoreguidelines-pro-bounds-pointer-arithmetic`、
  `cppcoreguidelines-pro-type-cstyle-cast`、`modernize-use-std-print`、`readability-function-cognitive-complexity`
  （4.3.2 的可测量替身）。
- **工业仓库**：fmt 库本体即"整洁函数设计"的样本（`format_to`/`format_to_n`/`formatted_size` 一组命名精确到
  是否写入、写多少）；abseil 指南明令"不用宏做常量与算术"，并把 `ABSL_PREDICT_*` 这类**必须**的宏集中管理。
- **测试生态**：4.3 的重构安全前提仍是第 2 章的安全网。Catch2/doctest 的 `TEMPLATE_TEST_CASE` 让
  "一个小函数 × 多类型"的验证成本几乎为零；GoogleTest 的 `EXPECT_DEATH` 可覆盖"参数非法即终止"这类契约行为。
