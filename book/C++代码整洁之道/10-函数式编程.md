## 核心概念速览（中英对照）

- **纯函数** — Pure Function：结果仅由参数决定（同输入必同输出），且无可观察副作用（7.1.2）
- **不纯函数** — Impure Function：读写隐藏状态、IO、或依赖时间等外部量——C++ 里绝大多数函数属于此类，问题在于**管住**它们
- **一等公民函数** — First-Class Functions：可存进变量、作参数传递、从函数返回
- **仿函数** — Functor / Function Object：重载 `operator()` 的类，可携带状态（7.2.2）
- **生成器/谓词** — Generator / Predicate：零参每次产值的函子 / 返回 `bool` 的判断函子（7.2.2 语境）
- **函数包装器** — `std::function`：类型擦除的可调用对象容器，存任何东西但付堆与间接的成本（7.2.3）
- **绑定** — `std::bind`：把参数预填进可调用对象生成新可调用对象（7.2.3）
- **Lambda 表达式** — Lambda：就地写的匿名闭包，捕获列表决定按值还是按引用（7.2.4）
- **泛型 Lambda** — Generic Lambda：参数写 `auto` 的 lambda（C++14），本质是编译器生成的模板函子（7.2.5）
- **高阶函数** — Higher-Order Function：以函数为参数或返回值的函数（7.3）
- **Map-Filter-Reduce** — map / filter / reduce：函数式三件套，C++ 对应 `transform` / `copy_if` / `accumulate`（7.3）
- **擦除-移除惯用法** — erase-remove Idiom：算法无权改容器大小，`std::remove` 挪出尾洞、容器 `erase` 收尾（7.4）
- **引用透明** — Referential Transparency：纯表达式可随时替换为其值——可推理、可缓存、可并行的前提（本章补充）

## 1. 动机：为什么整洁书要收编函数式

作者的论证路线是"整洁 = 可推理"，而**副作用是推理的头号敌人**：06 章用 RAII 管资源的时间维，
09 章用原则管对象的状态维，本章给出第三条腿——**把计算组织成数据流上的纯变换**。
函数式在 C++ 里不是换一种语言，而是给"可调用对象"建立纪律：优先纯函数、优先命名算法、
优先就地小闭包，杜绝散落的隐式状态。7.1 特意强调 C++ 是多范式语言：函数式是工具箱成员，不是信仰。

## 2. 机制：C++ 可调用对象五代同堂的谱系

**纯与不纯的判据（7.1.2）**：`constexpr int square(int)` 可证纯；带 `static` 计数的 `next_id()` 不纯；
灰色地带是"逻辑上不纯、实践上无害"（如返回缓存值）。C++ 的诚实处理是给纯函数贴
`constexpr`（编译期可用即一种纯度证明）与文档标注，标准层的 `pure` 属性（GCC `__attribute__((pure))`）
原书未提，本目录不展开。
**模板即函数式（7.2.1）**：模板把"类型也是参数"纳入函数抽象——与 09 章 concepts 呼应，编译期的泛型比虚表更廉价。
**函子（7.2.2）**：`struct Weighted { double factor; double operator()() }`——状态与行为的结合体，
算法库的设计原点（比较器、谓词都是它）。带状态函子因此天然"不纯"，这正是它比裸函数指针强的地方。
**bind 与 function（7.2.3）**：`std::bind` 造偏函数，`std::function` 做类型擦除存储。
两者在今天都退居二线：bind 可读性差，`function` 有堆分配/间接调用成本——API 边界之外慎用。
**lambda（7.2.4–7.2.5）**：就地匿名函子，`[=]/[&]/[x]/[&r = expr]` 把捕获语义写在脸上；
泛型 lambda 把"我要写个模板但不想起名字"的成本降为零。
**高阶函数（7.3）**：`<algorithm>` 全员高阶；把 Map-Filter-Reduce 用
`transform/copy_if/accumulate` 串起来，就是 C++ 版的管道。
**整洁收尾（7.4）**：能用命名算法就不要裸循环；erase-remove 是"算法与容器分权"的必然产物
（算法不能改变容器大小，只能由容器自己 `erase`）。

## 🔧 实测（已实测 g++ 15.2，fp_demo 用 `-std=gnu++20 -Wall -Wextra`，`-std=gnu++17` 亦可去 ranges 段编译）

```text
filter+reduce=56
erase-remove size=3
apply_twice(square,3)=81
3 3.75 ab
1 4 16 25
functor=15 impure-id=1,2
```

逐行对位：`56`=2²+4²+6²（filter 后 reduce）；`size=3` 是 erase-remove 清掉两个空串；
`81`=square(square(3)) 是"函数作为参数"的高阶最小例；`3 3.75 ab` 是同一个泛型 lambda
对 int/double/string 三实例化；`1 4 16 25` 是 `views::filter(x%3!=0) | views::transform(square)`
的**惰性**输出（管道本身不物化中间容器）；末行是带状态函子与不纯 `next_id()`。

**erase-remove 的 C++20 结局**（另样本，`-std=gnu++20` 实测，C++17 档下报
`error: 'erase' is not a member of 'std'`）：

```text
std::erase size=3 erase_if removed=1
```

## 3. 权衡：可调用对象的选型表

| 载体 | 携带状态 | 编译期可内联 | 可读性 | 适用 |
| --- | --- | --- | --- | --- |
| 函数指针 | 无 | 难 | 一般 | C 边界、回调 ABI |
| `std::function` | 有（堆） | 难 | 好 | API 参数、需要存储回调 |
| `std::bind` 结果 | 有 | 难 | 差 | 旧代码；新代码用 lambda |
| lambda（auto 接收） | 有（闭包） | **可** | 好 | 算法实参、局部管道 |
| 具名函子 | 有（成员） | 可 | 好 | 复用逻辑、复杂状态机 |
| 模板参数传可调用 | 随实参 | **可** | 报错噪声 | 性能敏感泛型库 |

函数式的代价同样真实：闭包捕获引用导致的悬垂（比 05 章的输出参数更隐蔽）、
链式管道的调试断点困难、模板实例化膨胀编译期。作者给的解药是朴素的：**管道保持短、
捕获尽量按值、每级只做一件事**——就是 4.3.1 的函数纪律换了一层皮。

## 4. 相邻概念对比

| 概念对 | 差别 | 为什么容易混 |
| --- | --- | --- |
| 纯函数 vs `const` 成员函数 | `const` 只保证不改*这个对象*，仍可打文件/读全局/改 `mutable`；纯是更强的数学性质 | 把"签名带 const"当成"可安全并行"，是缓存失效类事故的温床 |
| 函子 vs lambda | 同族：lambda 是编译器生成的匿名函子；具名函子可复用、可带多成员状态 | 泛型 lambda 出现后，绝大多数短函子失去了具名的理由 |
| `std::function` vs 模板参数 | 前者类型擦除（存什么都行、每调用一次间接），后者静态多态（每个类型一份代码、可内联） | 库作者常惯性用 `function` 当参数，热路径上白付两笔成本 |
| `std::remove` vs `erase` | `remove` 只是把幸存元素前移并返回新尾；`erase` 才真正缩容器 | 名字就是最大误导——这正是 C++20 `std::erase` 统一命名的动机 |
| eager 中间容器 vs lazy views | `transform` 到临时 vector 每级都物化；`views` 只在遍历时算 | 老代码习惯逐级建中间容器，数据量大时内存与拷贝双爆 |
| Map-Filter-Reduce vs 一条 range-for | 前者声明"做什么"，后者写死"怎么做"（顺序、累加器暴露） | range-for 里夹带状态变更，等于在函数式外壳下开了不纯内核 |

## 最新演进与工业实践

- **ranges 是本章的"官方续命"**：C++20 ranges（wg21.link/P0896，302→p0896r4 实测；标题复核沿用 00 的 ⚠️ 口径）
  把 7.3/7.4 的管道愿望标准化：`|` 组合、惰性求值、`views::filter/transform/reverse` 等；
  配套概念（`indirectly_unary_invocable` 等）把"可调用对象该满足什么契约"写进标准——09 章 concepts 与本
  章函子学的合流点。深读：[../C++20模板元编程/08-范围和算法.md](../C++20模板元编程/08-范围和算法.md)、
  [../C++20模板元编程/09-范围库.md](../C++20模板元编程/09-范围库.md)。
- **C++20 `std::erase` / `std::erase_if`**：成员版 `s.remove_if` 的容器无关自由函数版（上文实测），
  教科书级"惯用法被标准吸收"案例；老 erase-remove 仍需在自定义容器与 C++17 场景使用。
- **`std::bind` 的退场**：社区共识"能用 lambda 就不用 bind"——占位符 `_1` 可读性差、参数求值规则微妙；
  ⚠️ C++26 有将其标记弃用的讨论方向，本目录未复核到可用提案号，只作提示。
- **可调用性与 `function_ref`**：非拥有型可调用引用（类似 C# `Func&`）多年在标准边缘徘徊，
  是 `std::function` 堆成本的现代解药——⚠️ 提案号未复核，写作时请自查 wg21。
- **静态检查**：clang-tidy `readability-use-anyofallof`（把"手写循环 + 提前返回 bool"翻成
  `any_of/all_of`）、`modernize-avoid-bind`（bind → lambda 直译建议）——规则名按上游文档口径 ⚠️。
- **工业样本**：原书续作 *Clean C++20*（00 已核实其官方源码仓 `Apress/clean-cpp20` 存活）
  的第 8 章即把本章示例全面改写到 ranges；Google/Abseil 风格的 C++ 代码里"纯函数 + 值语义"
  的密度显著高于虚多态，与本章主张同向。异步管道的前瞻形态是
  `std::execution`（senders/receivers，wg21.link/P2300，302→p2300r10 实测）——把
  "函数作为参数传递计算"推进到"带调度语义的组合子"。
