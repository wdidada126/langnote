## 核心概念速览（中英对照）

- **单一职责原则** — Single Responsibility Principle（SRP）：一个类只有一个变化的原因（6.3.2）
- **开闭原则** — Open-Closed Principle（OCP）：对扩展开放、对修改关闭，靠多态而非 if-else 分支实现（6.3.3）
- **里氏替换原则** — Liskov Substitution Principle（LSP）：子类型可在任何需要父类型处替换且不破坏契约——前置条件不得加强、后置条件不得削弱（6.3.4）
- **接口隔离原则** — Interface Segregation Principle（ISP）：不强迫任何使用者依赖它用不到的方法，胖接口要拆（6.3.5）
- **无环依赖原则** — Acyclic Dependency Principle（ADP）：包/头文件的依赖图不允许出现环（6.3.6）
- **依赖倒置原则** — Dependency Inversion Principle（DIP）：高层与低层都依赖抽象，抽象不依赖细节（6.3.7）
- **迪米特法则** — Law of Demeter（LoD）：只与直接朋友（自身/参数/成员/工厂产物）说话，拒绝 `a.getB().getC().doX()` 链（6.3.8）
- **贫血类** — Anemic Class：只有字段和 getter/setter、没有领域行为的"结构体穿了西装"（6.3.9）
- **只说不问** — Tell, Don't Ask：把决策连同动作一起交给对象，而不是查询状态后在外面分支（6.3.10）
- **静态成员之害** — Static Members：隐藏的全局状态，破坏封装、独立性与可测性（6.3.11）
- **契约式设计** — Design by Contract：不变式/前置/后置条件，LSP 的判定语言（6.3.4 本目录补充）
- **抽象** — Abstraction：忽略无关细节、只暴露意图——本章认为它是应对复杂性的关键（6.2）

## 1. 动机：本书唯一"纯 OO"的一章在防什么

01–05 解决"写得像人"，06–08 解决"资源与错误不漏"，本章解决**抽象层的腐化**：类一旦成型，
它就成为别人的依赖。作者把 OO 的烂法分为三类——**巨大的上帝类**（违反 6.3.1/6.3.2）、
**脆弱的替换**（违反 LSP/ISP）、**纠缠的依赖网**（违反 ADP/DIP/LoD），再补两条 C++ 特色条款：
别把类写成数据袋（贫血）与别用 static 藏全局。
与前章的接缝：4.3 的函数纪律在类里同样成立；5.7 的异常契约正是 6.3.4 LSP 里"后置条件"的载体。

## 2. 机制：十一条的分层结构

**体量与职责（6.3.1–6.3.2）**：类是理解单位，小类优先；SRP 的判据不是"文件行数"而是**变化原因的数量**——
一个既管业务规则又管持久化的 `Customer` 会因两件不相干的事被修改。
**扩展与替换（6.3.3–6.3.4）**：OCP 在 C++ 里有两条实现路：虚函数（运行时扩展）与模板（编译期扩展）；
LSP 的违反通常是契约性的：`Rectangle/Square` 经典例（setWidth 在 Square 里连带改高，后置条件被偷换），
以及"派生类抛出基类承诺之外的异常类型"。C++ 还在签名层面兜底：覆写函数返回类型必须兼容
（仅指针/引用可协变），实测报错见下。
**接口形状（6.3.5）**：胖接口是依赖传染的温床；纯抽象基类应只承载**一种能力**。
**依赖拓扑（6.3.6–6.3.7）**：原书用 `Customer.h ↔ Account.h` 互相 include 演示环——环让编译单元绑死、
测试无法拆分；破环手段（前置声明、把公共类型下沉、反转方向）是 DIP 的具体操作。
**调用纪律（6.3.8）**：LoD 禁止穿越对象拓扑；修复方式是让中间对象**代理**一步（或干脆 Tell Don't Ask）。
**行为完整性（6.3.9–6.3.10）**：贫血类把领域逻辑赶到服务层，制造上帝服务；
`if (c.isOverLimit()) sendReminder(c)` 应改写为 `c.handleOverdue()`——查询者不决策。
**状态归属（6.3.11）**：类的 static 可变成员=带伪装的全局变量，直接违反 2.5.3 的测试独立性。

## 🔧 实测（已实测 g++ 15.2，`-std=gnu++20 -Wall -Wextra`）

**(1) 用 C++20 concepts 把"可替换性"写成编译期检查**——`Sellable` 抽象（ISP/SRP）+ 组合类
`BundledSale`（成员只持 `unique_ptr<Sellable>`，DIP），`static_assert(IsSellable<Book>)` 把关；
违规时编译器直接点名（第二份样本故意 `static_assert(IsSellable<int>)`）：

```text
bundle total=69.4
static_assert passed for Book/BundledSale; AnemicPair sizeof=40
```

```text
error: static assertion failed
note: constraints not satisfied
note:   'Sellable' is not a base of 'int'
```

`AnemicPair` 是特意放的贫血对照组：`{title, price}` 两个字段一个 `sizeof`，零行为——它能过编译，
但通不过本章任何一条原则。

**(2) LSP 在纯虚签名层的兜底**（`-std=gnu++20 -fsyntax-only`，无 override 的返回类型篡改）：

```text
error: conflicting return type specified for 'virtual int D::kind() const'
note: overridden function is 'virtual const char* Base::kind() const'
```

签名之外的契约违反（strengthened precondition 之类）编译器管不了，那是 5.7.1 契约断言与测试的职责。

## 3. 权衡：OO 在 C++ 里的账要算三遍

| 维度 | 运行时多态（虚函数） | 编译期多态（模板/concepts） | 直接组合（无多态） |
| --- | --- | --- | --- |
| OCP 扩展方式 | 派生新类，调用点不动 | 新类型满足约束即可 | 改组合点 |
| LSP 保障 | 签名检查 + 测试 | concepts 可机检（见上） | 天然无替换问题 |
| 成本 | vtable、切片风险、跨 DLL 需导出基类 | 代码膨胀、报错噪声、C++20 前难诊断 | 无 |
| 可测性 | 抽象基类=天然的测试替身插槽（接 12 章 DI） | 单测即模板实例化 | 取决于设计 |

作者的立场是"OO 有用但别过买"：本章十一条给**边界**（什么时候该有抽象），不是鼓励继承树。
工业界共识与之一致：优先值语义与小类，多态只放在**真的会变化**的轴上——这正是 6.3.3/6.3.2 的交集。

## 4. 相邻概念对比

| 概念对 | 差别 | 为什么容易混 |
| --- | --- | --- |
| SRP vs ISP | SRP 管"谁提需求"（一个类服务一个角色），ISP 管"谁依赖接口"（客户端不该看见用不到的方法） | 都靠"拆"来治疗，但拆的依据不同：按变化原因 vs 按使用场景 |
| LSP vs OCP | OCP 是目标（不改编旧码），LSP 是达成它的前提（替换必须无害） | 破了 LSP 的"扩展"会让 OCP 的乐观假设变成定时炸弹 |
| DIP vs DI | DIP 是原则（依赖抽象），DI 是其实现技法（把抽象从外部注入） | 12 章 9.2.1 的 DI 正是本章 6.3.7 的落地，混用会让"原则"听起来像框架功能 |
| LoD vs Tell Don't Ask | LoD 限制"能调谁"，TDA 要求"把决策交给对象"；TDA 是 LoD 违规的处方 | 只做代理方法（修 LoD）但仍在外面查询分支（违 TDA），治标不治本 |
| 贫血类 vs DTO | DTO 跨层搬运数据、**设计上就无行为**；贫血类是本该有领域行为的实体被掏空 | 形状相同、意图相反；判据：它是否代表一个有规则的领域概念 |
| static 成员 vs 单例 | 单例至少是一个有生命周期的对象（可控创建/销毁），static 可变成员完全无治理 | 都是共享状态；6.3.11 反的是"可变+隐藏"，不是"共享"本身 |

## 最新演进与工业实践

- **concepts 是本章节的"后补编译器"**：原书只能靠评审核对的接口纪律，C++20 可以写成约束——
  标准库自身的 ranges 概念体系（`indirect_unary_predicate` 等）即"接口即概念"的官方示范。
  提案对位：wg21.link/P0734（Concepts TS，302→p0734r0 实测）、wg21.link/P0898（Standard Library Concepts，
  302→p0898r3 实测；⚠️ 标题层复核沿用 00 的口径）。
- **静态类型替代部分虚多态**：现代 C++ 的倾向（也是续作 *Clean C++20* 的改法）——能用值语义 + concepts
  约束的模板，就不引入继承树；真要运行时多态，用抽象基类 + DI（见 [12-设计模式与C++惯用法.md](12-设计模式与C++惯用法.md)）。
  延伸读物：[../C++20设计模式/01-导论-模式体系与C++20惯用法.md](../C++20设计模式/01-导论-模式体系与C++20惯用法.md)。
- **ADP 的现代形态是模块**：头文件环在 C++20 `import` 下从根上消失（cycle 在模块依赖图里是编译错误）；
  提案 wg21.link/P1103（Modules，302→p1103r3 实测，标题复核沿用 00 的 ⚠️ 口径）；工程侧深读
  [../大规模C++程序设计/03-物理层与层级化：非循环依赖与增量测试.md](../大规模C++程序设计/03-物理层与层级化：非循环依赖与增量测试.md)。
- **编译器/静态检查门禁**：LSP 签名纪律 GCC/Clang 原生报（上文实测）；Clang `-Winconsistent-missing-override`
  可抓"该 override 没写"的漏网（本机无 Clang，未实测 ⚠️）；clang-tidy 侧 `cppcoreguidelines-virtual-class-destructor`、
  `readability-make-member-function-const` 等把"基类析构、const 正确性"变成 CI 规则（规则名按上游文档口径 ⚠️）。
- **信息隐藏的源头**：本章所有"藏"的论断都站在 Parnas 1972 肩上——
  *On the criteria to be used in decomposing systems into modules*，DOI 10.1145/361598.361623
  （api.crossref.org 实测，Commun. ACM 1972-12）。
