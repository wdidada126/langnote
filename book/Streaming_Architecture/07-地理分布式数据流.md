## 7.1 问题的物理来源

跨地域系统唯一不可谈判的约束是**光速**。作者把这一点量化为工程直觉：

| 距离 | 单程物理下限（约） | 往返（RTT）下限（约） |
| --- | --- | --- |
| 同机房 | 亚毫秒 | ~1 ms |
| 同区域不同 AZ | 1–3 ms | 3–6 ms |
| 跨大陆（如美东西岸） | 数十 ms | 60–80 ms |
| 跨洲（美 ↔ 欧/亚） | 数十至上百 ms | 150–250 ms |

⚠️ 表中数值为通用物理量级常识（作者在本章亦以量级方式表述），
**本目录未做网络实测（零新装纪律，且本机无法测量真实跨洲 RTT）**，不作为性能结论。

**推论**：任何"全球强一致"的方案都必须付出"每次写等待一个 RTT"的代价，
因此在延迟敏感路径上，**强一致在全球尺度上是不可用的，不是不便宜的**。

## 7.2 三种跨地域数据传播模型

本章把选择空间整理为三类：

| 模型 | 机制 | 读到的状态 | 写冲突 |
| --- | --- | --- | --- |
| 单主 + 异步复制 | 一个区域写主，其余区域只读副本 | 副本区可能读到旧值 | 不存在（写被集中） |
| 多主 + 冲突解决 | 各区可写，事后合并 | 最终一致 | 必然出现，需策略 |
| **两地写日志 + 合并** | **各区只写本地日志，日志互相复制后各自重放** | 最终一致 | 由日志顺序 + 合并语义处理 |

作者倾向第三种：**把"数据"表达成"事件日志"，冲突问题就从"两个值谁对"
变成"两个日志序列如何合并"**——后者更容易给出可证明的性质。

## 7.3 CRDT：让并发更新可交换

本章引入 **CRDT（Conflict-free Replicated Data Types，无冲突复制数据类型）** 作为
"日志合并"的数学工具。核心要求可以写成一条可检验的性质：

> 若两个副本各自应用的**事件集合相同**（顺序可不同），则它们最终状态相同。

满足该性质的操作通常要求合并函数是**交换、结合、幂等**的。常见例子：

- **计数器**：只加不减（G-Counter）→ 天然可交换；带删除的 PN-Counter 需按副本记分量。
- **集合并（G-Set）**：只增不删；带删除需 Add-Witness Set 等变体。
- **最后写入胜出（LWW-Register）**：用时间戳选版本，简单但会丢并发意图。
- **语言/文本协同编辑类**：需要保留插入位置语义，构造远比计数器复杂。

**本章的关键提醒**：CRDT 不是"免费的最终一致"，它把冲突处理的责任从**运行时协调**
转移到了**类型设计**。设计者必须提前决定"哪些并发意图值得保留"。

## 7.4 地理时间：把"何时"与"何地"绑在一起

作者把其在时空（geo-temporal）数据上的既有工作引入本章：**地理坐标与时间戳共同构成
事件的定位轴**，很多真实问题只在二者联合索引下才可解。典型：

- 同一账户在 10 分钟内出现在相距 900 km 的两地 → 物理不可能 → 强欺诈信号。
  这类判断**必须**在流上做，因为事后批处理已无决策价值（回指 06 章）。
- 索引结构需要能回答"某区域内、某时间段内的事件"，
  这本质是把二维空间曲线填充 + 时间前缀拼成一个可排序键。

### 🔧 D4 实测：速度层漏计与批层重算修正（迟到事件，**非本书平台行为**）

跨地域复制的必然结果是**乱序与迟到**（RTT 与分区可用性导致事件到达顺序偏离事件时间顺序）。
02/06 章反复主张"批层重算可修正速度层的近似"，本实验量化这个修正的必要性与幅度。

方法（SQLite 3.45.3）：生成 60,000 条事件，事件时间均匀落在 1 小时内，
迟到时长服从均值 40 秒的指数分布；窗口宽 600 秒（共 7 个窗口）。
速度层只统计"到达时间 ≤ 窗口关闭 + 允许迟到 L"的事件：

| 允许迟到 L | 速度层漏计事件数 | 漏计占比 |
| --- | --- | --- |
| 0 s | 3,803 | **6.338%** |
| 30 s | 1,786 | 2.977% |
| 120 s | 180 | 0.300% |
| 600 s | 0 | 0.000% |
| **批层全量重算** | **0** | **0.000%** |

**三条结论**：

1. 迟到分布有长尾时，"窗口关闭即出结果"会**系统性低估**计数（此处 6.3%），
   且低估不是随机噪声而是**方向一致的偏差**——报表看起来"稳定偏小"最危险。
2. 允许迟到从 0 提到 120 s，误差从 6.3% 降到 0.3%，但**延迟预算付出 4 倍**；
   这是典型的"新鲜度 ⇄ 准确性"曲线，不存在免费点。
3. 只有批层重算能同时做到 0 漏计——这正是 Lambda 双层的原始动机；
   而 Kappa 式重放（见 02 章 2.6）用"重放日志"替代"另写一套批代码"来达成同一效果。

**限度声明**：本实验在单机 SQLite 上模拟，**没有真实网络分区、没有跨地域 RTT、
没有分布式提交协议**；它类比的是"迟到 → 窗口结果偏差 → 重算修正"这一算术结构，
不能据此推断任何流引擎的水位线行为（引擎侧真实语义见
[../Streaming_Systems/03-水位线.md](../Streaming_Systems/03-水位线.md)）。
脚本：`D:\develops\tmp\dbwave_w8_starch\exp.py`（结果存 `results.json`）。

## 7.5 全局有序是个幻觉

本章与 04 章 4.2 呼应并升级结论：

- 单分区内有序是**可实现的**（本地单调偏移量）。
- 跨分区有序**已经不可实现**（Kafka 语义）。
- **跨地域全局有序在物理上不可实现**（除非接受每次写付一个 RTT）。

工程后果：任何"按全局顺序做决策"的设计在跨地域部署时都会静默失效。
可迁移的替代是**按实体键分区**（同一用户/同一账户的事件保持有序），
把有序性需求缩小到"业务真正需要的粒度"。

## 7.6 本章的架构清单

1. 明确**一致性等级**：哪些读数可以旧（可容忍一个 RTT 的偏差），哪些必须新。
2. 把"必须新"的部分**限制在单地域内**，跨地域一律走异步日志复制。
3. 为每个跨地域状态选/设计**可合并类型**，把冲突解决写进类型而非运维手册。
4. 保留**每个副本的本地日志**：合并靠日志重放，不靠"最新值覆盖"。
5. 监控**复制滞后**而非只监控可用性：滞后是跨地域系统的一等健康指标。
6. 为"两地都写"的场景准备**对账作业**（批层），D4 显示重算是唯一能把误差归零的手段。

## 核心概念速览（中英对照）

- **光速约束** — Speed-of-light constraint：跨地域写协调的不可压缩延迟下限，决定强一致的可用性边界。
- **单主复制** — Single-leader replication：写集中于一个区域，其余区域读可能陈旧的副本。
- **多主复制** — Multi-leader replication：各区均可写，冲突在事后合并阶段解决。
- **日志合并** — Log merge：各副本交换并合并事件日志、由重放得到一致状态的传播模型。
- **CRDT** — Conflict-free Replicated Data Types：合并满足交换/结合/幂等，从而并发副本可自动收敛的数据类型。
- **G-Counter / PN-Counter** — 增长计数器 / 正负计数器：只增可交换；带删除需按副本分量分别记录。
- **LWW-Register** — Last-Write-Wins Register：以时间戳择版的寄存器，实现简单但会丢并发意图。
- **最终一致** — Eventual consistency：无新写入时副本终将收敛，不承诺收敛时限。
- **地理时间索引** — Geo-temporal index：以空间填充曲线前缀 + 时间列构造的可排序复合键。
- **物理不可能检测** — Impossible-travel detection：同一实体在短时至远距离内出现于两地的欺诈信号。
- **全局有序幻觉** — Global ordering illusion：跨分区/跨地域的全局顺序在物理上不可实现。
- **按实体键分区** — Entity-key partitioning：把有序性需求收缩到单实体粒度的设计手法。
- **复制滞后** — Replication lag：跨地域副本落后源的程度，是跨地域系统的一等健康指标。
- **对账作业** — Reconciliation job：周期性以全量重算校正增量结果的批层兜底机制。
- **新鲜度⇄准确性权衡** — Freshness/accuracy trade-off：允许迟到越长结果越准但越不新鲜，二者不可兼得。

## 最新演进与工业实践

**（1）本章的两条主张在 2026 年都赢了**

- "把数据表达成事件日志、用日志合并代替值覆盖"——今天体现为
  以 changelog/CDC 为跨系统交换介质、以表格式快照 + 增量做对账的主流做法。
- "CRDT 用于跨地域状态收敛"——已从论文进入产品：协同文档、离线优先应用、
  以及全球分布式 KV/元数据存储普遍内建 CRDT 或等价的合并语义。

**（2）"跨地域流复制"从平台特性变成独立产品层**
