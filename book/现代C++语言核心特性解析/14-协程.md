# 14 协程

> 对应原书 **第33章 协程（C++20）**
> 导航：[系列索引](../C++系列·总索引.md) ｜ [单文件笔记](../现代C++语言核心特性解析.md) ｜ [00 总览](00-总览与阅读地图.md)

## 核心概念速览（中英对照）

- **协程** — coroutine：可在 `co_await/co_yield/co_return` 处挂起并恢复的函数
- **无栈协程** — stackless coroutine：挂起状态存堆帧而非保存整个调用栈（C++20 形态）
- **协程帧** — coroutine frame：编译器为协程生成的堆分配对象（局部变量+句柄+promise）
- **promise_type** — 定制协议类：决定协程"返回什么、挂起时做什么、异常怎么办"
- **coroutine_handle** — 恢复机器：`resume()/done()/destroy()/promise()` 四件套
- **awaiter** —  Awaitable 的三问协议：`await_ready/await_suspend/await_resume`
- **initial/final_suspend** — 起点与终点的挂起策略（惰性启动 vs 急切启动）
- **yield_value** — co_yield 的落地函数：产出值并返回 awaiter
- **unhandled_exception** — 帧内异常收容所：无 catch 时的协议回调
- **合成范围** — std::generator（C++23）：本章 promise_type 手工实现的标准化
- **发送者/接收者** — sender/receiver（std::execution，P2300）：协程之上的组合层

## 动机

回调地狱（异步代码被切成碎片函数+状态机手工化）、线程每等待烧 8MB 栈、
生成器要手写迭代器状态类——三个老痛点共享一个解：**把"暂停/恢复"做进函数本身**。
C++20 协程采纳 Coroutines TS（P0673/P0912R5，实测 302："Merge Coroutines TS into
C++20 working draft"），特点是**语言只给机器（帧+suspend 点），不给车**：
标准库到 C++20 连一个可用协程类型都没有，promise_type 协议全靠库作者拼装。

## 机制（编译器视角）——本书卖点章

编译器把一个含 `co_*` 的函数 lower 成五步（GCC 在 GIMPLE 层有专门的
`COROUTINE_SEP`/builtin 支持，帧分配点可 `objdump` 看到 `operator new` 调用）：

1. **分配帧**：`co_await` 前按估算大小 `operator new`（帧含：参数副本、挂起点后仍存活的
   局部变量、promise 对象、句柄、suspend 点状态字）；
2. **构造 promise**：放置于帧头；`get_return_object()` 生成对外句柄（本例 Generator）；
3. **`initial_suspend()`**：返回 suspend_always → 惰性协程（本次调用不执行函数体，
   直到第一次 resume；本实测即此模式）；
4. **每个挂起点**：`co_yield v` ≈ `promise.yield_value(v)` → 其返回的 awaiter 决定
   `await_ready/suspend/ resume` 三拍；`co_await e` 按 `e.await_transform()`/
   直接协议展开；**suspend 时保存"返回地址+状态字"并立刻 return 给恢复者**——
   这就是"无栈"：调用栈不留协程帧；
5. **`co_return`/结束**：`return_void()/return_value()` → `final_suspend()`；返回
   suspend_never 时帧自毁——**句柄悬挂的根源**。`unhandled_exception()` 是帧内
   抛出且无处 catch 的收容所。

实测取证（🔧）：手写 `Generator<int>` 约 20 行 promise_type，
`countdown(3)` 输出 `3 2 1`——没有线程、没有回调、函数体就是 `while+co_yield`。

## 权衡

- **帧分配 = 每次调用一次堆分配**：小任务高频场合成致命开销；工业做法是
  池化 promise（folly::coro 的 Task 用 `frame_alloc` 定制/栈缓存分配器）——
  语言层 P2869? 未落地（⚠️ 不引号）。
- **生命周期责任全在用户**：协程句柄不拥有帧的"存活期"（destroy 由谁做）、
  挂起的协程对象被析构=悬挂；Clang `-fsanitize=coroutine`? 生态工具有限，
  "协程+悬垂引用捕获"是 2020s C++ 最难查 bug 家族（呼应文件 05 init-capture 纪律）。
- **组合爆炸**：语言只定机制，`when_any/when_all/retry` 全靠库；不同库
  （cppcoro/folly::coro/Asio 原生）promise 互不兼容——**接口标准之争至今未完**
  （见"最新演进"）。

## 相邻概念对比

| 模型 | 挂起保什么 | 切换成本 | 表达力 |
| --- | --- | --- | --- |
| 线程/纤夫(fiber) | 完整栈 | 高（栈分配/换栈指令） | 任意函数可阻塞 |
| 回调+状态机 | 手写状态 | 极低 | 逻辑被打散 |
| C++20 协程 | 帧（活跃变量+IP） | 中（堆分配+两次函数返回） | 同步风格写异步 |
| generator(库/标准) | 同上特化 | 同上 | 惰性序列 |
| executor 体系 | 同上+调度器 | 同上 | 异步组合 |

## 🔧 实测样例（已实测 g++ 15.2，-std=gnu++20）

```cpp
#include <coroutine>
template<class T> struct Generator {
  struct promise_type {
    T current;
    Generator get_return_object(){ return Generator{std::coroutine_handle<promise_type>::from_promise(*this)}; }
    std::suspend_always initial_suspend(){ return {}; }        // 惰性启动
    std::suspend_always final_suspend() noexcept { return {}; } // 不自毁: 由 ~Generator 管
    std::suspend_always yield_value(T v){ current = v; return {}; }
    void return_void(){}
    void unhandled_exception(){ std::terminate(); }
  };
  std::coroutine_handle<promise_type> h;
  bool next(){ return h ? (h.resume(), !h.done()) : false; }
  T value() const { return h.promise().current; }
  ~Generator(){ if(h) h.destroy(); }
};
Generator<int> countdown(int n){ while(n>0){ co_yield n; --n; } }
int main(){ auto g = countdown(3); while (g.next()) printf("%d ", g.value()); printf("\n"); }
```
实测输出：`3 2 1`。协议点逐条验证：`initial_suspend` 返回 suspend_always → 创建时
未执行体；`yield_value` 的 `current` 即帧内 promise 成员（`g.value()` 读的是堆帧）；
`final_suspend` 返回 suspend_always + 手工 `destroy()` ——**帧所有权显式化**。
（libstdc++ 15 的 `<coroutine>` 在 MinGW 直接可用，无需 -fcoroutines——
GCC 10 需要该开关的历史在此记录 ⚠️ 版本号未本机逐一验证。）

## 最新演进与工业实践

- **C++23：`std::generator`（P2850R1，wg21.link/p2850 实测 302，PDF 标题机读未成功 ⚠️）**
  就是本章 Generator 的标准化：`std::generator<int> rng(){ for(...) co_yield ...; }`
  加 `yield_values` 包装；libstdc++ GCC 12+ 提供（本机 g++ 15.2 `-std=gnu++23` 实测
  `gen sum=6` 通过，见文件 16 的 t23 样例合集）。
- **C++26：`std::execution`（P2300R10，实测 302）**发送者/接收者网络：
  `when_all/schedule/let_value` 组合子标准化，协程是其上"同步风格"的用户界面——
  Asio/STL2 路线之争以 P2300 入 IS 为节点阶段性收场。
- **`monadic co_await`（P2552? ⚠️ 不引未验证号）**与 `co_await std::optional` 类
  扩展讨论持续中；C++26 协程帧分配标准化（"allocator-aware frame"）也是热区。
- **工业库**：cppcoro（Lewis Baker，本书时代的参考实现）、folly::coro（Meta 生产体系，
  `Task/Try/AsyncScope` 全套+帧池化）、Asio 20+ 的 awaitable 改造（`co_spawn`）。
  生产规则共识：**协程体捕获用 init-capture/显式成员；句柄必须被某 Scope 拥有**
  （folly 的 `AsyncScope` 就是这个 Scope）。
- 支持矩阵（谨慎）：GCC 10+（-fcoroutines 起步，本机 15.2 原生可用）、Clang 14+
  （C++20 模式）、MSVC 19.28+；协程+异常路径三家实现差异是 2021 年代联调高发区
  （⚠️ 未逐一复测差异，仅登记为工程史事实）。
