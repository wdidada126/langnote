# 03 类型占位符与推导

## 核心概念速览（中英对照）

- **auto 占位符** — auto placeholder：以初始化器为推导源的编译期类型替换
- **退化推导** — decayed deduction：auto 按"传值实参"规则丢引用/数组/函数指针
- **decltype 说明符** — decltype specifier：不求值地查询表达式的类型与值类别
- **cv 限定符推导** — cv-qualification deduction：顶层 const 被 auto 丢弃、decltype 保留
- **decltype(auto)** — decltype(auto)：返回类型 = decltype(返回表达式)，C++14
- **返回类型后置** — trailing return type：`auto f() -> T`，返回类型可引用后文声明
- **模板返回类型推导** — template return type deduction：对 return 表达式集合做统一化简
- **类型别名** — type alias：`using I = int;`，与 typedef 同义但可加说明符
- **别名模板** — alias template：`template<class T> using Ptr = T*;`，C++11
- **缩写函数模板** — abbreviated function template：`void f(auto x)`，C++20 把 auto 当占位模板形参
- **非类型模板形参占位符** — placeholder for NTTP：`template<auto N>`，C++17

## 动机

泛型代码的"类型书写成本"在 C++98 是三重税：迭代器类型 `vector<T>::const_iterator`
嵌套名、模板返回类型依赖表达式（`a*b` 该返回 `T` 还是 `decltype(a*b)`?）、
以及 `int(*)(int)` 函数指针声明的可读性灾难。auto/decltype 分别补足"让编译器写类型"
的两块拼图：**auto 从值推型**、**decltype 从表达式问型**；后置返回与别名模板是把这
两个能力接到"声明语法"上的桥。

## 机制（编译器视角）

- **auto 的推导 = 模板实参推导的第一条规则**：Clang 诊断信息直接把它写成
  `auto x = expr;` 等价于 `decltype(expr&&) x = expr;`（按值初始化语境）。要点：
  1. 丢弃引用与**顶层 const**：`const int i; auto a = i;` → a 是 `int`（可写）；
  2. 数组/函数名退化为指针：`int arr[3]; auto p = arr;` → `int*`（实测 sizeof(p)=8）；
  3. `auto&`/`auto&&` 关闭退化、进入引用折叠语境（与 04 文件衔接）。
- **decltype 的三分法**（编译器在 Sema 层按表达式的"形态"判决）：
  - 变量名/函数名（未被括号包裹）→ 声明类型（含 const，不含值类别加工）；
  - 其他表达式 → 类型 + 值类别：lvalue→`T&`、xvalue→`T&&`、prvalue→`T`；
  - **`decltype((x))` 永远 `int&`**（加括号即普通 lvalue 表达式）——`decltype(auto)`
    返回悬垂引用的头号来源（实测 g2() 返回 int& 见 🔧）。
- **`decltype(auto)` 的返回类型推导在实现上就是 `return (expr);` 语境套 decltype**，
  GCC 在 AST 里把它 lowering 成对返回表达式直接做 decltype 查询；因此
  `return (局部变量)` 编译不报错、运行悬垂——**没有任何诊断**（机制级危险点，
  `-Wdangling-reference` 只在部分形态报警，⚠️ 本机未逐一验证覆盖率）。
- **后置返回类型的语法动机是"作用域可见性"**：`template<class A,class B> auto mul(A a,B b) -> decltype(a*b)`
  里 decltype 需要看到形参名，声明期普通位置在形参之前不可见。C++11 同时让 `auto f() { return ...; }`
  （函数体推导）成为可能，C++14 推广到普通函数与递归（多次 return 需统一化简，
  GCC 对 `int/double` 混合 return 报 "deduced return type inconsistent"）。
- **别名模板不是 typedef 的参数化**：`template<class T> using Ptr = T*;` 是**模板**，
  不能被类模板特化匹配（`Ptr<int>` 永远等于展开结果，特化 `template<> struct Ptr<int>` 非法）；
  编译器在需要"可特化的别名"时惯用 `struct` 间接层（type_traits 全部如此，见 C++20模板元编程目录）。
- GCC lowering 证据：`auto` 声明在 `-fdump-tree-all` 前后仅是类型替换，无运行期产物；
  真正留痕的是 `std::initializer_list` 推导（见 06）与 `decltype(auto)` 引用返回。

## 权衡

- `auto` 少写类型 ≠ 少思考类型：`std::atomic<int>` 的 `auto x = m;` 直接编译失败（拷贝删除），
  `auto` 反而暴露了"你以为的可拷贝其实不可拷贝"（Meyers Item 5 视角，链 EMCF 01）。
- `vector<bool>::reference` 类代理：`auto b = v[0];` 拿到代理对象而非 bool，位图更新丢失——
  代理类型是 auto 的头号暗坑（04 文件的 CRTP/代理对象话题在此埋线）。
- `decltype(auto)` 用在返回"具名变量+括号"处最危险，用在"表达式直传"处最香（`return obj[i];`
  保值类别）。团队规范常规定：**只允许在完美转发包装/操作符重载中使用**（工程纪律，非语言问题）。
- 别名模板 vs `struct` traits：别名模板 `std::enable_if_t` 简洁，但**SFINAE 语境里
  "替换进别名模板的失败发生在别名展开内部"**，报错行会跳进 `<type_traits>`（实测见 16 文件
  SFINAE 诊断长这样）。

## 相邻概念对比

| 工具 | 求值表达式? | 保引用? | 保顶层const? | 主要用途 |
| --- | --- | --- | --- | --- |
| `auto x = e;` | 是（拿类型时按"传值"退化） | 否 | 否 | 简洁声明 |
| `decltype(e) x;` | 否 | 是（lvalue→T&） | 是 | 精确类型查询 |
| `decltype(auto) f(){return e;}` | 否（对返回表达式套 decltype） | 是 | 是 | 保值类别转发 |
| `-> decltype(e)` 后置 | 否 | 依 decltype 规则 | 依规则 | 依赖形参的返回类型 |
| `using`/别名模板 | 不涉 | 不涉 | 保留全部 | 命名与简写 |

## 🔧 实测样例（已实测 g++ 15.2，-std=gnu++17）

```cpp
#include <cstdio>
#include <type_traits>
int x = 1;
int& rx = x;
decltype(auto) g1(){ return x; }    // decltype(具名变量) -> int
decltype(auto) g2(){ return (x); }  // decltype((表达式)) -> int&
template<class T> decltype(auto) pass(T&& t){ return (t); }
int main(){
  static_assert(std::is_same_v<decltype(g1()), int>);
  static_assert(std::is_same_v<decltype(g2()), int&>);
  int a[3] = {1,2,3};
  auto p = a;  static_assert(std::is_same_v<decltype(p), int*>);   // 数组退化
  auto& r = a; static_assert(std::is_same_v<decltype(r), int(&)[3]>); // 关闭退化
  g2() = 42;
  printf("x=%d sizeof(p)=%zu sizeof(r)=%zu\n", x, sizeof(p), sizeof(r));
  int arr_dummy[3]; (void)arr_dummy;
  auto&& lr = pass(a);  static_assert(std::is_same_v<decltype(lr), int(&)[3]>); // 引用转发保数组
}
```
实测输出：`x=42 sizeof(p)=8 sizeof(r)=12`。三行断言分别钉死：**括号改变 decltype**、
**auto 数组退化而 auto& 不**、**decltype(auto)+转发引用可以把数组原样带回来**（`sizeof(r)=12`
证明 r 真的是数组而非指针）。

## 最新演进与工业实践

- **C++20 缩写函数模板（abbreviated template）**：`void f(auto x, std::same_as<int> auto y)`
  ——auto 从"类型推导"升格为"模板形参占位"，可挂概念约束；本书 41 章的
  `contract`/缩写写法对照在 **文件 16**。
- **P0846R0（实测 302，"ADL and Function Templates that are not Visible / Mismatched"）**：
  C++20 允许**别名模板展开后的函数也能被 ADL 找到**等推导改进，与本章"别名模板"
  的历史坑直接相关；编译器支持：GCC 10+/Clang 9+/MSVC 19.2x+（按 C++20 模式，⚠️ 未逐项装版验证）。
- **`std::type_identity`（C++20）**：官方"类型屏障"，`type_identity_t<T>` 阻断 T 的推导——
  处理"参数二义推导"（如 `std::max(1, 2L)`）的标准解，替代各家库自造的非推导上下文包装。
- 工业面：abseil 大量使用 `using` 别名收敛模板噪音（`absl::string_view` 本体就是给
  `basic_string_view<char>` 起的名字）；`auto` 在 Google Style 中被要求"右侧类型显而易见
  或迭代器场景"——语言给了自由度，规范负责收回去。
- C++26 无继续放宽 auto 推导的通过提案（检索印象，⚠️）；相关热度话题是"占位符在
  generic lambda 签名里的 constexpr 形参"（P2830? 未验证，不引号）。
