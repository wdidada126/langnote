# 04 右值引用、移动语义与完美转发

> 对应原书 **第6章 右值引用（C++11 C++17 C++20）**
> 导航：[系列索引](../C++系列·总索引.md) ｜ [单文件笔记](../现代C++语言核心特性解析.md) ｜ [00 总览](00-总览与阅读地图.md)

## 核心概念速览（中英对照）

- **左值/右值** — lvalue / rvalue：可取地址、有身份 vs 临时、可窃取
- **将亡值** — expiring value (xvalue)：C++11 新增第三类值类别，有身份但即将消亡
- **纯右值** — prvalue：C++11 重定义（临时对象/字面量），C++17 起"临时量不物化"
- **右值引用** — rvalue reference（T&&）：绑定 xvalue/prvalue 以实施资源窃取
- **移动构造/赋值** — move constructor / move assignment：指针接管 + 源置空
- **转发引用（万能引用）** — forwarding reference：`auto&&`/模板 `T&&` deduction 语境专用词
- **引用折叠** — reference collapsing：`& + && → &`，`&& + && → &&`，其余原样
- **std::move** — cast to rvalue：本质 `static_cast<T&&>`，**不移动任何东西**
- **std::forward** — conditional cast：`static_cast<T&&>`，按推导的 T 还原值类别
- **隐式移动** — implicit move：return 局部变量/异常参数时按右值重载决议
- **NRVO** — named return value optimization：具名返回值原地构造，消灭移动

## 动机

C++98 拷贝一切：`vector<T>` 扩容把 N 个元素逐个深拷贝；工厂函数返回大对象要经历
"构造→拷贝→析构"三重开销。语言此前无法区分"我在拿走它"和"我在复制它"——因为
只有 `const T&` 一种万能绑定。C++11 把"可窃取"编码进类型系统（`T&&`），一次性兑现
三件事：**移动语义**（性能）、**完美转发**（工厂 API 保真传参）、**`unique_ptr`**
（独占所有权成为可表达的类型，见 EMCF 04）。

## 机制（编译器视角）

- **值类别是编译器的判决函数**，规则浓缩为两问："有身份吗？可窃取吗？"
  `int i;` 之后：`i`→lvalue、`(i)`→lvalue、`i++`→prvalue、`std::move(i)`→xvalue、
  `Foo()`→prvalue、`arr[2]`→lvalue、`f()`（返回 Foo&&）→xvalue。
  实测钉死一条最常被误记的：**`decltype((i))` 是 `int&`**（括号使表达式化，走 lvalue 规则）。
- **重载决议优先级**：完全匹配 > 转换；`T&&` 对右值是**绑定**不是转换，
  所以 `void f(const T&)` 与 `void f(T&&)` 遇右值选后者、遇左值选前者——移动/拷贝
  分派的全部魔法就在这张偏好表上。
- **std::move 的编译器视角是"零代码"**： constexpr 模板函数 `static_cast<T&&>(x)`，
  优化后不存在；它只改变重载决议输入。真正的资源窃取发生在移动构造的函数体里
  （接管指针 + `o.h = nullptr`，实测见 🔧 与 [11-noexcept与确定求值顺序.md](11-noexcept与确定求值顺序.md)）。
- **引用折叠是模板 deduce 的产物**：`probe(T&&)` 传左值时 `T=int&` → `T&&=int&`；
  传右值时 `T=int` → `T&&=int&&`。**注意：传右值时 T 是 `int` 而不是 `int&&`**——
  实测输出 `is_lvalue_ref:0 is_rvalue_ref:0` 直接证明这一点（T 本身不是引用，
  `T&&` 才是折叠结果）。
- **完美转发 = 折叠 + 条件 cast 的组合拳**：`std::forward<T>(t)` 当 `T` 是左值引用时
  展开为 `static_cast<L&>`（还原 lvalue），否则 `static_cast<T&&>`（保右值）。
- **隐式移动**（编译器在两个位置把 return 的参数按"先当右值做决议"处理）：
  返回局部对象、返回 catch 参数。C++17 的 PRVO（强制纯右值不物化临时量）进一步
  把"返回 prvalue 初始化另一个对象"变成原地构造——**拷贝省略从优化变成语义**
  （`T f(){return T{};}` 连移动都不需要，T 甚至可以不移动可拷贝）。
- **NRVO 实测**：返回具名局部对象时 GCC -O0 也做了原地构造——实测程序里
  `Obj c = make_lvalue();` **没有**任何 copy/move 打印，只有 ctor。

## 权衡

- 移动把"源仍可用"变成"源处于有效但未定义内容状态"——可析构、可赋值、可比较
  （moved-from string 为空），但**不可假设值**。API 文档义务随之而来。
- 写了移动操作就进入"五法则"（Rule of five）：任一用户声明（拷贝/移动/析构）都会
  **静默抑制**其他隐式生成——见文件 07 的实测：用户析构导致移动退化为拷贝。
- 转发引用 + auto 的组合扩大了 overload 集，`f(int)`/`f(int&&)` 二义与
  "万能引用贪婪吃掉一切实参"是工程规范限制 `T&&` 自由度的原因（EMCF Item 26 立场）。
- `std::move` 到已删除拷贝的类型上会报"移动被抑制→尝试拷贝"的绕路错误：诊断常显示
  copy constructor deleted，根因是移动操作因某成员不可移动而被 SFINAE 掉——
  先查成员再查调用点。

## 相邻概念对比

| | 左值引用 T& | 右值引用 T&& | 转发引用 T&&/auto&& | const T& |
| --- | --- | --- | --- | --- |
| 绑定左值 | ✓ | ✗ | ✓（折叠成 T&） | ✓ |
| 绑定右值 | ✗ | ✓ | ✓（T 推为非引用） | ✓（只读借用） |
| 可窃取 | ✗ | ✓ | 依实参值类别 | ✗ |
| 悬垂风险 | 同 | 同 | 同 | 延长临时量生命期（少数例外） |
| 语境 | 通用 | 移动语义 | 模板/auto 专用 | 通用只读 |

## 🔧 实测样例（已实测 g++ 15.2，-std=gnu++17）

```cpp
#include <cstdio>
#include <type_traits>
#include <utility>
struct Obj{
  int* h;
  Obj(): h(new int(0)) { puts("ctor"); }
  Obj(const Obj& o): h(new int(*o.h)) { puts("copy"); }
  Obj(Obj&& o) noexcept: h(o.h) { o.h=nullptr; puts("move"); }
  ~Obj(){ if(h) delete h; }
};
template<class T> void probe(T&&){
  printf("is_lvalue_ref:%d is_rvalue_ref:%d\n",
     std::is_lvalue_reference_v<T>, std::is_rvalue_reference_v<T>);
}
template<class T> using add_rref = T&&;        // 折叠只在模板/typedef 语境发生
using collapsed = add_rref<int&>;              // int& && -> int&
Obj make_lvalue(){ Obj o; return o; }         // NRVO 候选
int main(){
  static_assert(std::is_same_v<collapsed, int&>);
  int i=0;
  static_assert(std::is_lvalue_reference_v<decltype((i))>); // 括号=表达式→int&
  Obj x;
  probe(x);                 // 左值: is_lvalue_ref:1
  probe(std::move(x));      // 右值: 两 flag 皆 0 —— T 推导为 Obj 本身
  Obj c = make_lvalue();    // NRVO 生效: 只打印 ctor
}
```
实测输出（逐行对应结论）：

```text
ctor
is_lvalue_ref:1 is_rvalue_ref:0
is_lvalue_ref:0 is_rvalue_ref:0
ctor
```

（注：`Obj c = make_lvalue();` 无 copy/move 打印 → NRVO 在 -O0 下已原地构造。
移动/拷贝的代价对比见文件 11 的 vector 增长实测：无 `noexcept` 时 15 次 emplace 增长
全走 **copy**，加 `noexcept` 后全走 **move**。）

## 最新演进与工业实践

- **C++17 PRVO 与保证拷贝省略**（本文件机制节；提案面为 P0135R1——⚠️ 本目录未对其做
  wg21 实测，故只述语义不引号）。
- **C++20 的续作**：P0847R7 **Deducing this**（实测 302，已入 **C++23**）让
  `void f(this auto& self)` 直接捕获对象值类别，终结"CRTP 转发/const&& 四重复制粘贴"
  的模板工匠活；本机 g++ 15.2 `-std=gnu++23` 实测通过（`auto dist(this const Pt&)` 样例，
  输出 `deducing-this=1.5`，完整记录见文件 16「最新演进」）。
- **值类别与范围的边界案件**：`std::expected` 的单参数构造、`generator` 的
  yield 值类别（`co_yield x` 是 xvalue 语境）——理解移动语义才读得懂这些接口为什么
  长那样（文件 14、16 各自延伸）。
- **工业设施**：folly 的 `folly::movedFrom` 语义约定、abseil `absl::optional` 的移动
  支持、GSL `Owner<T>`（只允许移动的类型表达"我持有资源"）——都是本章规则的类型化封装。
  Chromium 的 `base::MoveOnly` 模式同样源于此。
- **规范回摆**：Google Style 明确"慎用右值引用形参（只允许 `&&`+std::move 单次消费场景）"——
  语言特性 vs API 可读性，工业选择了后者（⚠️ 措辞以当前官方文档为准）。
