# 08 强枚举与非受限联合

> 对应原书 **第11章 非受限联合类型（C++11）· 第14章 强枚举类型（C++11 C++17 C++20）**
> 导航：[系列索引](../C++系列·总索引.md) ｜ [单文件笔记](../现代C++语言核心特性解析.md) ｜ [00 总览](00-总览与阅读地图.md)

## 核心概念速览（中英对照）

- **无作用域枚举** — unscoped enumeration：C++98 的 `enum`，枚举数泄漏到外围、隐式转整型
- **强枚举类型** — scoped enumeration（`enum class`/`enum struct`）：限域 + 默认不隐转
- **底层类型** — underlying type：枚举的整数表示，可显式指定 `: unsigned char`
- **固定枚举** — fixed enumeration type：底层类型已知的枚举，值域可越出枚举数列表
- **打开枚举** — using enum X（C++20）：把强枚举的枚举数批量引入作用域而不失类型
- **非受限联合** — unrestricted union：C++11 允许联合体含非平凡（有构造/析构）成员
- **活跃成员** — active member：联合中当前"活着"的那个成员，读写非法成员=UB
- **联合体标签** — discriminant / tag：手工维护的"当前活跃成员"标记，tagged union 的 tag
- **位域** — bit-field：`unsigned a : 3;`，枚举与联合的相邻老朋友（本书第1章/30章有对齐语境）

## 动机

C++98 的 `enum` 是"带名字的整数"而非类型：枚举数泄漏污染命名空间、任何枚举可与
任何枚举/整数比较（`Color()==Season()` 编译通过）、`sizeof` 不定。`enum class` 一次
修三处。`union` 的问题是另一个方向：为了节省内存把所有备选塞进同一块存储，但
C++98 禁止成员有构造/析构——"能 union 的都不是好类型"，工程只能退化成
`char buf[N]`+placement new。C++11 放开非平凡成员，代价是把**生命周期管理**
（构造/析构/拷贝谁负责）完全交还程序员。

## 机制（编译器视角）

- **枚举布局**：`enum Color{red}` 未指定底层类型时，GCC 按"能容纳所有枚举数的最小
  有符号整型，默认 `int`"选择——实测 `sizeof(Color)=4`（哪怕只有 1 个枚举数！
  未固定枚举不追求紧凑）；`enum class Status : unsigned char{...}` 实测 `sizeof=1`。
  **编译器视角结论：要紧凑存储必须显式指定底层类型，"enum 很小"是错觉。**
- **强枚举的类型墙**：`static_assert(!std::is_convertible_v<Status,int>)` 实测成立；
  跨墙只能 `static_cast`；`==`/`<` 自动可用（同类型比较由底层类型实现，无函数调用）。
- **`using enum`（C++20）**：只改名称查找（把枚举数注入当前作用域），
  类型仍受限域保护；与 02 文件 inline namespace 的"名字注入"是同一设计哲学。
- **非受限联合的 lower**：`union Task{ std::string s; int i; }`——
  1. `sizeof(Task)=max(成员)`，实测 `=32`（libstdc++ std::string 恰为 32 字节），
     `alignof(Task)=8`；
  2. **联合自身不生成拷贝/移动/析构**：任一成员非平凡 → 联合的特殊成员全部被**删除**
     （实测需手写 `~Task(){}` 才能过编译）；
  3. 活跃成员切换是纯手工协议：先析构旧成员、再 placement new 构造新成员
     （实测 `t.s.~basic_string(); new (&t) Task{42};`，随后**不得**再析构 s——
     误析构非活跃成员直接堆损坏/崩溃，本目录开发期真实踩中一次，输出见 🔧）；
  4. C++20 constexpr 联合允许在常量求值中切换活跃成员（本书 27.13，归文件 10）。
- **std::variant 是对本章痛点的库式回答**：带 tag、正确析构、访问器校验活跃成员，
  `std::get` 越界抛 `bad_variant_access`。语言层"非受限联合"给的是原料，
  variant 是成品（链《C++新经典_设计模式》variant 章）。

## 权衡

- 强枚举不能隐式转整数 = 序列化/位标志场景要手写 `|`/`&` 运算符（或引 magic_enum 类
  反射库，C++26 reflection P2996 才是官方解，见"最新演进"）。位标志惯用法
  `flags |= Read` 在 enum class 下必须重载——**枚举数当位标志是 enum class 的高频误用**。
- 非受限联合的"自由"是拿 UB 风险换的：没有调试器能可靠告诉你活跃成员是谁；
  工程答案优先级：`std::variant` > tagged union（自写+严格测试） > 裸 union。
  裸 union 仅存的正当场景：类型双关（type punning）读字节（TrType punning 是 UB，
  `std::bit_cast`(C++23)/`memcpy` 才是合法姿势）、placement new 存储缓冲。
- 联合的 EBO 邻居：`[[no_unique_address]]`（文件 13）在"空成员省空间"上比 union 更通用。

## 🔧 实测样例（已实测 g++ 15.2，-std=gnu++17）

```cpp
#include <cstdio>
#include <string>
#include <type_traits>
#include <new>
enum Color { red, green };
enum class Status : unsigned char { ok = 1, err = 200 };
union Task{
  std::string s; int i;
  Task(const char* p): s(p) {}
  Task(int v): i(v) {}
  ~Task(){}                     // 成员非平凡 → 联合特殊成员全被删, 必须手写
};
int main(){
  printf("sizeof(Color)=%zu sizeof(Status)=%zu sizeof(Task)=%zu alignof(Task)=%zu\n",
     sizeof(Color), sizeof(Status), sizeof(Task), alignof(Task));
  static_assert(std::is_enum_v<Status> && !std::is_convertible_v<Status, int>);
  using U = std::underlying_type_t<Status>;
  static_assert(std::is_same_v<U, unsigned char>);
  int raw = static_cast<int>(Status::err);
  Task t("hello"); printf("%s %d\n", t.s.c_str(), raw);
  t.s.~basic_string(); new (&t) Task{42};   // 手工切换活跃成员
  printf("%d\n", t.i);                       // 此后绝不能再析构 t.s
}
```
实测输出：

```text
sizeof(Color)=4 sizeof(Status)=1 sizeof(Task)=32 alignof(Task)=8
hello 200
42
```

同一程序若在切换后误执行 `t.s.~basic_string()`（活跃成员已是 `int`），
本机实测直接异常退出（bash rc=127）——**非活跃成员析构=堆破坏**的现场证据，
比任何文字警告都直观。

## 最新演进与工业实践

- **`std::variant`/`std::visit`（C++17）**：本章的直接继任者；`std::monostate` 解决
  "无可取值"状态；P2602（monostate/variant  constexpr 化，C++23? ⚠️ 未实测提案号，
  按效果描述：C++23 起 variant 更多 constexpr 能力）。
- **枚举反射的两代方案**：工业用 `magic_enum`（编译期枚举名↔值，靠扫字节实现，
  依赖固定底层类型——正好是本章 `: unsigned char` 的用场）；官方解在推进
  **P2996R13 "Reflection for C++26"（wg21.link 实测 302）**——注意勘误：
  **P2562 实为 constexpr Stable Sorting（实测 302 核实），网络常见"P2562=reflection"
  说法不成立**（呼应 00 总览的 wg21 实测记录）。
- **`std::bit_cast`（C++23）**：合法类型双关的标准答案，收编裸 union 最后一个正当场景；
  libstdc++ 自 GCC 11 提供（`<bit>`），本机 g++ 15.2 直接可用（未单列实测，⚠️）。
- **folly::poly/abseil**：abseil 的 `absl::Status`（enum 化的状态码 + 对象载荷）与
  folly::Optional 组合，是"强枚举+variant"在大规模代码库的落地形态（⚠️ 未逐行核实，
  按公开 API 描述）。
- 支持矩阵（谨慎）：`using enum` GCC 11+/Clang 13+/MSVC 19.28+（按各家 C++20 里程碑，
  ⚠️ 未逐版验证）；非受限联合 GCC 4.6 实验/4.8 稳定，MSVC 2010 起扩展式支持。
