# 07 特殊成员函数、继承构造与 override/final

> 对应原书 **第10章 默认和删除函数（C++11）· 第13章 继承构造函数（C++11）· 第16章 override和final说明符（C++11）**
> 导航：[系列索引](../C++系列·总索引.md) ｜ [单文件笔记](../现代C++语言核心特性解析.md) ｜ [00 总览](00-总览与阅读地图.md)

## 核心概念速览（中英对照）

- **特殊成员函数** — special member functions：默认构造/拷贝构造/拷贝赋值/析构/（C++11 加）移动构造/移动赋值
- **显式默认** — explicitly-defaulted（`=default`）：要求编译器生成隐式实现
- **显式删除** — explicitly-deleted（`=delete`）：把函数声明为"已定义但不可用"
- **隐式生成规则** — implicit generation rules：用户声明某族函数会抑制另一族的生成
- **平凡类型** — trivial type：所有特殊成员隐式且可用的类型，memcpy 语义的前提
- **继承构造函数** — inherited constructor：`using Base::Base;` 批量转发
- **重写/重载/隐藏** — override / overload / hiding：同名跨作用域三种关系
- **override 说明符** — override specifier："必须重写某个虚函数，否则编译错误"
- **final 说明符** — final specifier：终止虚函数重写链或禁止类被继承
- **协变返回类型** — covariant return type：重写时返回类型向派生方向变化仍合法

## 动机

C++98 控制"编译器替你写了什么"的手段只有 `private + 不实现`（错误在链接期或
调用方可见性上爆出，且友元绕过）。C++11 把三个诉求语法化：
① "我要标准实现"→ `=default`；② "永远别想调它"→ `=delete`（编译期、对所有人）；
③ "多态意图要可检查"→ `override/final`（重写忘签名/const 不匹配的静默新增虚函数
是 C++98 最阴的 bug 之一——编译器不报错，运行时调不到）。

## 机制（编译器视角）

- **隐式生成是"按族判决"的矩阵**（编译器在 Sema 阶段为每个类跑这张表，
  实测 🔧 用运行时打印取证）：
  - 用户声明**拷贝构造/拷贝赋值/移动任一/析构** → **移动构造+移动赋值不再生成**
    （实测：有用户拷贝构造的 C，`std::move(c)` 初始化兜底走 **copy**——
    打印 `C: copy(移动被抑制后的兜底)`；有用户析构的 D 同理无移动，但拷贝平凡所以无打印）。
  - 用户声明移动操作 → 拷贝构造/赋值被**删除**（五法则的一半）。
  - `is_trivially_move_constructible_v<A>`：无任何用户声明才为真（实测 A=1 B=1 C=0）。
  - C++20（P0848R3，实测 302）：基类虚析构非平凡不再连带让派生类的移动"变删除"——
    **conditionally trivial**：析构非平凡但移动仍可平凡化（按成员判决）。
- **`=delete` 的实现位置在重载决议之后**：函数仍是候选、仍可匹配，但匹配后触发
  "use of deleted function" 诊断——这正是它比 private-未实现强的机制根因：
  报错在调用点编译期、对所有访问者一致、友元也拦不住。
  附带红利：可以**只删某个重载**（`f(int&&)=delete`）做参数类型封禁。
- **`=default` 不是"恢复默认"而是"要求隐式定义存在"**：对虚析构在类外 `~X() noexcept(false) = default`
  之类的特化场景，编译器按位置生成独立函数体。
- **继承构造函数是"批量 using"**：`using Base::Base;` 对基类每个构造生成一个
  **转发的隐式构造**（模板化的成员初始化列表 `Base(args...)`），
  但**拷贝/移动构造不在继承范围**（仍按规则合成）；默认构造若基类有则生成。
  实测打印链 `Base(int)`/`Base()` 由委托+继承混合样例给出（见 🔧）。
- **override/final 在编译器里是纯检查位**：AST 的 `CXXMethodDecl` 上有 override/final flag，
  不参与代码生成；但 `final` 会被优化器/调用点利用——Devirtualization：
  对 `Derived` 对象的虚调用若编译器类型感知可证明，`-O2` 直接内联（GCC/Clang/LLVM 均有此
  pass；MSVC `/GL` 家族同样）。这是"说明符改变代码生成"的少数字例。
- 实测诊断（g++ 15.2）：签名写歪的 `override` 报错逐字为
  `'bool Der::eq(long int) const' marked 'override', but does not override`——
  一句话版本，比 C++98 时代"静默新增成员函数"进步一整代。

## 权衡

- `=delete` 会**参与重载决议并胜出**再报错——想"静默降级"到别的重载时反而阻断，
  需要小心 `f(int)=delete` 与 `f(long)` 并存时的匹配优先级。
- 抑制移动的规则太容易被无意触发：**写了空析构 `~D(){}` 就全族失去移动**（实测），
  而"加个析构打日志"是存量代码高频动作——这是 vector 增长退化拷贝的头号根因
  （与文件 11 的 noexcept 实测互为姊妹案）。默认选择永远是"什么都不声明"。
- `final` 冻结扩展点：框架基类滥用 final 会让下游无法多态扩展；收益（去虚化）要用
  性能数据换，别凭感觉（链《提高C++性能的编程技术》视角）。

## 相邻概念对比

| 手法 | 报错时机 | 可见范围 | 典型用途 |
| --- | --- | --- | --- |
| private+不实现 | 链接期/使用点 | 友元可绕 | C++98 遗留 |
| `=delete` | 编译期重载决议 | 所有人 | 禁拷贝/禁某重载 |
| `=default` | —（要求生成） | — | 恢复被抑制的默认实现 |
| `override` | 编译期检查 | 声明者自己 | 防签名漂移 |
| `final` | 编译期检查 | 继承链 | 冻结重写/提示去虚化 |

## 🔧 实测样例（已实测 g++ 15.2，-std=gnu++17）

生成规则矩阵取证（拷贝兜底可视化）：

```cpp
#include <cstdio>
#include <type_traits>
#include <utility>
struct A{ int x; };
struct B{ B(int v):x(v){} int x; };
struct C{ C(){} C(const C&){ puts("C: copy(移动被抑制后的兜底)"); } int x; };
struct D{ D(){} ~D(){ } int x; };
int main(){
  static_assert(std::is_trivially_move_constructible_v<A>);
  static_assert(std::is_trivially_move_constructible_v<B>);
  C c; C c2 = std::move(c);   // 打印 copy
  D d; D d2 = std::move(d);   // 无打印: 兜底拷贝是平凡默认生成
  printf("A=%d B=%d C trivially-move=%d\n",
     std::is_trivially_move_constructible_v<A>,
     std::is_trivially_move_constructible_v<B>,
     std::is_trivially_move_constructible_v<C>);
}
```
实测输出：

```text
C: copy(移动被抑制后的兜底)
A=1 B=1 C trivially-move=0
```

继承构造+委托构造混合执行序（见 06 文件 🔧 的 `Derived` 样例，同码实测：
`Base() → Base(const char*) → Derived(const char*)`）。
`override` 诊断实测：

```text
error: 'bool Der::eq(long int) const' marked 'override', but does not override
```

（把 `eq(long)` 改回 `eq(const Base&) override` 后编译通过，完整输出见
[12-三向比较与基础特性其他优化.md](12-三向比较与基础特性其他优化.md) 的太空船样例。）

## 最新演进与工业实践

- **C++20 P0848R3（Conditionally Trivial Special Member Functions，实测 302）**：
  析构的平凡性不再一票否决移动的平凡性，带虚基类/虚析构的叶子类恢复可平凡移动——
  libstdc++/libc++/MSVC 随 C++20 模式生效（⚠️ 未逐版验证）。
- **explicit(bool)（C++20）** 同属"特殊函数声明控制"家族，实测样例与语义在
  文件 16（`explicit(!storeable<T>)` 编译+static_assert 通过，g++ 15.2）。
- **`=delete` 的工业模板用法**：单例禁止拷贝 `X(const X&)=delete;`、
  状态机"只允许移动"类型（folly::coro task 句柄）、`std::atomic`（GSL Owner）——
  全部以"删除拷贝"作为类型契约的表达；abseil 的 `absl::noncopyable` 宏是它的封装。
- **`override` 在现代代码检查中的地位**：clang-tidy `modernize-use-override`
  （C++98 风格自动改写）、MSVC `/w1xxx` 系列警告、GSL I.8? 未逐条核对（⚠️），
  工业事实标准：**无 override 的虚函数重写视为 code smell**。
- C++26 方向：契约（P2695R1 contracts plan，实测 302）可能把"禁止非法调用"从
  `=delete` 的编译期扩展到运行期断言面——与本章"声明即策略"的精神同源（文件 10 展开）。
