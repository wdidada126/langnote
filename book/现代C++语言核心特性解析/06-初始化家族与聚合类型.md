# 06 初始化家族与聚合类型

> 对应原书 **第8章 非静态数据成员默认初始化（C++11 C++20）· 第9章 列表初始化（C++11 C++20）· 第12章 委托构造函数（C++11）· 第15章 扩展的聚合类型（C++17 C++20）**
> 导航：[系列索引](../C++系列·总索引.md) ｜ [单文件笔记](../现代C++语言核心特性解析.md) ｜ [00 总览](00-总览与阅读地图.md)

## 核心概念速览（中英对照）

- **NSDMI** — non-static data member initializer：类体内 `int x = 0;` 的默认成员初值
- **列表初始化** — list-initialization：`{...}` 统一初始化语法，禁隐式缩窄
- **std::initializer_list** — initializer list 视图类型：轻量对象，元素存于编译器生成数组
- **缩窄转换** — narrowing conversion：`{3.5}`→int 被列表初始化明令禁止
- **聚合类型** — aggregate type：无用户构造/私有成员/虚基类的"纯数据"类
- **指定初始化** — designated initializer：`{.y = 5}`，C++20（P0329R4，实测 302）
- **圆括号聚合初始化** — parenthesized aggregate initialization：`Pt(7,8)`，C++20（P0960R3，实测 302）
- **委托构造函数** — delegating constructor：本构造在 mem-initializer 里调同类其他构造
- **继承构造函数** — inherited constructor：`using Base::Base;`（机制在文件 07 展开）
- **值初始化/零初始化/默认初始化** — value/zero/default initialization：`T()`、`={}=`、`T a;` 三兄弟
- **聚合的拷贝列表初始化** — copy-list-initialization of aggregates：`T x{a,b}` 直接初始化成员

## 动机

C++98 的初始化是"语法的百慕大"：`= 8, 9`（老式聚合）、`int a(3)`、`new T[3]`、
构造函数复制粘贴（每加一个字段改所有构造）、成员默认值只能写在构造初始化列表。
C++11 用**统一初始化语法 + NSDMI** 收编；C++20 再把"聚合"这个最高效的构造路径
重新开放（指定初始化、圆括号形式），并让 NSDMI 参与聚合初始化（此前"有 NSDMI 就
出局"的奖励倒挂被掰正）。

## 机制（编译器视角）

- **NSDMI 的 lower 位置是"每个构造函数的成员初始化列表"**：编译器把类体内初值
  **文本替换进**每个未显式初始化该成员的构造函数入口。因此
  ① 手写初始化列表覆盖 NSDMI；② GCC 在 C++98 模式把 NSDMI 当扩展放行（`-std=gnu++98`
  可编译，⚠️ 未在本机复测，参考库内《C++语言程序设计_阚道宏》三态实测结论）——
  看汇编/dump 能看到 NSDMI 常量被内联进 ctor 的 prologue。
- **`{}` 的决议顺序**（列表初始化优先级，编译器按此顺序匹配）：
  1. `std::initializer_list`  overload 优先（哪怕 `(int,int)` 构造更匹配——
     `vector<int> v{3}` 是 1 个元素 3，不是 3 个元素——实测经典陷阱）；
  2. 常规构造重载决议；
  3. 聚合初始化；
  4. 都失败才考虑显式转换等。
  缩窄检查发生在第 2/3 步成员初始化处：`int b{3.5}` 直接编译错误
  （实测诊断：`narrowing conversion of '3.5e+0' from 'double' to 'int' [-Wnarrowing]`）。
- **initializer_list 的实现**：编译器为 `{1,2,3}` 生成一个**静态常量数组**
  （GCC 里是 `.rodata` 中的 `std::initializer_list` 临时对象，含指针+长度两个字段），
  成员指针即指向它——所以 initializer_list 的**拷贝廉价但元素生命期系于那个临时数组**，
  "返回 initializer_list 后指针悬垂"是标准明文保证的合法用法（临时数组延长生命期）。
- **委托构造的 lower**：被委托 ctor 先执行完（含其 mem-initializer），再执行委托者的
  函数体；**成员初始化列表不能与委托共存**（会双初始化）。异常语义安全：委托失败时
  对象从未"完整构造"，析构不跑——实测输出顺序 `Base(const char*) → Derived(const char*)`
  印证"下层先建"（见 🔧）。
- **聚合定义的逐代放宽**（本书 15 章主线）：

  | 标准 | 放宽点 | 仍禁止 |
  | --- | --- | --- |
  | C++11 | —— | 有用户构造/虚/基类/私有成员即出局，NSDMI 也出局 |
  | C++14 | NSDMI 允许 | 仍无用户构造 |
  | C++17 | 允许含（public 非静态的）基类成员，虚基类除外 | 仍无用户构造 |
  | C++20 | **用户声明构造也可以**（只要初始化不选它） | P0960：可 `Pt(7,8)` |
  C++20 的"扩展聚合+自定义构造"意味着聚合与类的界限变成"选择哪条初始化路径"而非"类型属性一票否决"。

## 权衡

- 列表初始化 vs 圆括号：`T x{}` 与 `T x()` 的"最 vexing parse"教训让 `{}` 成为默认姿势；
  但 `vector<int> v(3)`（3 个 0）与 `v{3}`（1 个 3）的语义分裂是长期可读性税。
- NSDMI 减少"构造忘了初始化成员"一类 UB，与重载构造数量呈正相关收益；代价是
  类体内初值出现在头文件里，改动触发更多 TU 重编（编译防火墙视角，链大规模C++）。
- 指定初始化**强制声明序**（乱序 `{.y,.x}` 非法）、**部分省略=默认/NSDMI**——比 C 的
  designated init 严格，跨语言移植时要记住。
- 委托构造深链（A 委托 B 委托 C…）在循环委托时 UB/递归栈溢出，标准禁止环，编译器
  对直接环给诊断、间接环不一定（GCC 实测对自委托报 "recursive constructor" 警告/错误，
  ⚠️ 间接环覆盖度未测）。

## 相邻概念对比

| 写法 | 名字 | 谁能用 | 典型坑 |
| --- | --- | --- | --- |
| `T a;` | 默认初始化 | 任意 | 内置类型值未定义（除非 constinit/零初始化语境） |
| `T a{};` | 值初始化/列表 | 任意 | `T a();` 是最 vexing parse |
| `T a{1,2};` | 列表初始化 | initializer_list 优先 | vector{3}≠vector(3) |
| `T a(1,2);` | 直接初始化 | 构造/聚合(C++20) | C++17 下聚合不可用圆括号（实测报错） |
| `T a{.x=1};` | 指定初始化 | 聚合(C++20) | 乱序非法、不能与 NSDMI 冲突(可共存) |

## 🔧 实测样例（已实测 g++ 15.2）

gnu++20（NSDMI+指定初始化+P0960 三合一）：

```cpp
#include <cstdio>
struct Pt{ int x = 1; int y = 2; };          // NSDMI；C++20 起仍是聚合
int main(){
  Pt a{5,6}; Pt d{.y = 9}; Pt p(7,8);        // 列表 / 指定 / 圆括号聚合初始化
  printf("%d %d | %d %d | %d %d\n", a.x,a.y, d.x,d.y, p.x,p.y);
}
```
实测输出：`5 6 | 1 9 | 7 8`。同码 `-std=gnu++17` 实测报错：

```text
error: no matching function for call to 'Pt::Pt(int, int)'
```

（`Pt p(7,8)` 在 C++17 不合法——P0960 是 C++20 增量，一字之差的年代证据。）

缩窄禁令实测（gnu++17）：`int bad{3.5};` →

```text
error: narrowing conversion of '3.5e+0' from 'double' to 'int' [-Wnarrowing]
```

委托构造执行序实测（gnu++17）：

```cpp
struct Base{ Base(){ puts("Base()"); } Base(const char*){ puts("Base(const char*)"); } int n; };
struct Derived : Base{
  using Base::Base;                                     // 继承构造
  Derived(const std::string& s) : Derived(s.c_str()) {} // 委托到 ↓
  Derived(const char* p) : Base(p) { puts("Derived(const char*)"); }
};
int main(){ Derived d1; Derived d2(std::string("x")); }
```
实测输出：

```text
Base()
Base(const char*)
Derived(const char*)
```

`Derived(string)` 一行没打印——委托构造里**委托者函数体在被委托者完整执行后才跑**，
本例其函数体为空，打印链因此是 `Base(const char*) → Derived(const char*)`。

## 最新演进与工业实践

- **C++20 之后无破坏性续作**；C++23/26 的相关提案以"把 `std::pair/tuple` 也变聚合"
  （P1020? ⚠️ 未实测不引）与 CTAD 聚合推导（已在文件 16）为主。
- **库侧对照**：GSL 用 `gsl::narrow<T>` 把"缩窄"从编译期禁令扩展到运行期断言的转换面；
  `std::to_array`（C++20）是"数组字面量进右值上下文"的标准答案，配合
  `constexpr` 数组初始化与本家族合流。
- **工业惯用法**：配置结构体（settings struct）从 C 的 `{0,}`+memset 演化到
  "NSDMI+指定初始化"的现代写法——abseil 的 `absl::Mutex` options、folly 的
  `AsyncSocketOption` 都是"聚合+指定 init"风格（⚠️ 具体类型名未逐一复核，按模式描述）。
- 编译器矩阵（谨慎）：指定初始化 GCC 4.6 扩展/7 正式（gnu++20 默认），Clang 3.3 扩展/
  5 正式，MSVC 19.28+；P0960 GCC 10、Clang 8、MSVC ⚠️（未装版验证）。本机 g++ 15.2
  在 gnu++17 拒绝 P0960/指定初始化、gnu++20 全放行（实测如上）。
