# 10 静态断言与常量表达式体系

> 对应原书 **第19章 static_assert声明 · 第27章 常量表达式（C++11～C++20）**
> 导航：[系列索引](../C++系列·总索引.md) ｜ [单文件笔记](../现代C++语言核心特性解析.md) ｜ [00 总览](00-总览与阅读地图.md)

## 核心概念速览（中英对照）

- **静态断言** — static_assert：编译期求值的断言，失败即诊断（C++20 起消息可省）
- **常量表达式** — constant expression：核心求值器（constant evaluator）可算出的表达式
- **constexpr 变量** — constexpr variable：常量求值语境初始化的对象
- **constexpr 函数** — constexpr function：既可在编译期也可在运行期调用的函数
- **consteval 立即函数** — immediate function：只能编译期调用（C++20）
- **constinit** — 常量初始化声明符：拒绝动态初始化，不要求 constexpr 语义（C++20）
- **if constexpr** — 编译期分支：条件为假的一侧不实例化（C++17）
- **字面量类型** — literal type：可出现在常量求值中的类型族
- **常量求值环境判定** — std::is_constant_evaluated：constexpr 函数内"此刻是否在算常量"（C++20）
- **constexpr 虚拟/异常/联合** — C++20 扩展三件套：常量求值器能力边界的续作

## 动机

模板元编程时代（文件 16）用类型运算模拟计算：`Factorial<N>::value` 既是算术又是类型体操。
C++11 的 `constexpr` 把"编译期计算"从**类型层的 hack** 提升为**函数层的语言设施**：
同一函数体，编译器在需要常量表达式时核心求值，否则生成普通代码——"一份代码两个世界"。
`static_assert` 配套提供编译期断言出口，让"验证"也脱离模板特化黑魔法。

## 机制（编译器视角）

- **两条执行路径，一个函数体**：GCC 内部有 `cxx_eval_constant_expression`（C++ 核心求值器，
  在 trees/constexpr.c），constexpr 函数首次进入常量语境时按 GIMPLE/AST 直接"解释执行"
  （递归+分支+局部变量都在编译器内存里模拟）；**运行时版本照常生成机器码**。
  实测：`fact6=720` 同时来自编译期 `static_assert(maybe_rt(5)==120)` 和运行期调用。
- **constexpr 的逐代放宽 = 核心求值器的能力清单**：
  | 年代 | 新能力（编译器侧） |
  | --- | --- |
  | C++11 | 单 return 函数体；循环都不行（靠递归+条件运算符） |
  | C++14 | 循环/mutation/多返回/推导返回类型 |
  | C++17 | if constexpr（不实例化死分支）、inline 变量 |
  | C++20 | constexpr 虚函数、try/catch（可抛但必须在求值内消化）、union 活跃成员切换、
  平凡默认初始化、`std::is_constant_evaluated`、容器部分 constexpr |
- **consteval 是编译器的"强制常量语境"检查位**：函数在 AST 上打 immediate 标志，
  任何调用必须进入核心求值器，否则诊断。实测报错逐字：
  `call to consteval function 'only_rt(x)' is not a constant expression` +
  `'x' is not a constant expression`（两行连击）。
- **constinit 管的是初始化档位不是常量性**：`constinit int g = 0;` 保证进
  `.data`/启动前常量初始化，**拒绝**动态初始化（防静态初始化顺序灾难的编译器护栏）；
  `constinit constexpr` 冲突（constexpr 已隐含）。它与 `thread_local` 的懒初始化
  （文件 02）形成"动态初始化"的两个收容所。
- **if constexpr 的实现是模板实例化过滤器**：假分支在 instantiation 阶段被丢弃
  （仍做语法解析但不做名字查找/代码生成），因此 `return v/2` 与 `return v/2.0`
  两种返回类型互不矛盾——"只实例化活分支"是它区别于普通 if 的本质。
- **static_assert 的 C++20 单参形态**：消息串变成可选（模板报错上下文已足够定位，
  `template<bool B = requires{...}>` 时代断言常直接复用表达式诊断）。
- `std::is_constant_evaluated` 的 lower：编译器在核心求值器里把该 intrinsic 折叠为
  `true`，运行时路径折叠为 `false`——`__builtin_is_constant_evaluated()` 一个内建，
  两侧常量传播。惯用法：constexpr 平方根里"编译期走牛顿迭代、运行期走硬件 sqrt"。

## 权衡

- constexpr 函数**不保证**编译期算：混用运行期实参就退化为普通函数——想要"必须编译期"
  用 consteval；想要"最好编译期"用 constexpr+static_assert 验一把。
- 常量求值器限制仍是硬约束：`volatile` 读、浮点异常路径、依赖运行期内存布局的
  reinterpret 类操作不可进；错误信息（"not a constant expression"）指认根因能力弱，
  大函数体内二分定位是日常。
- if constexpr 让"模板里两个互斥返回类型"合法，但也把**实例化期错误**后移成
  "你的 if 选错了"——过度使用会让"接口即约束"变得模糊（与 concepts 分工见文件 16）。
- static_assert 消息写得好坏决定编译期诊断的人道程度；单参形态把命名责任转移给
  表达式本身（`static_assert(sizeof(void*)==8);` 失败时读者要自己脑补意图 ⚠️ 编者立场）。

## 相邻概念对比

| 声明 | 语义档位 | 运行期可调用? | 典型用途 |
| --- | --- | --- | --- |
| `const T x = f();` | 只读对象，初始化可在运行期 | — | 普通常量 |
| `constexpr` 变量/函数 | 必须可常量求值（函数允许另有运行期路径） | 函数可 | 编译期计算 |
| `consteval` 函数 | 只能常量求值 | 否 | 强制编译期契约 |
| `constinit` 变量 | 常量初始化档位保证 | 可变对象 | 抗静态初始化灾难 |
| `static_assert` | 编译期断言 | — | 模板接口校验 |
| `assert()` | 运行期断言，NDEBUG 可关 | — | 调试期不变量 |

## 🔧 实测样例（已实测 g++ 15.2，-std=gnu++20）

```cpp
#include <cstdio>
#include <type_traits>
consteval int only_rt(int n){ return n*n; }        // 立即函数
constexpr int maybe_rt(int n){ return n < 2 ? 1 : n * maybe_rt(n-1); }
static_assert(maybe_rt(5) == 120);                 // 编译期: 核心求值器递归
template<class T> auto half(T v){
  if constexpr (std::is_integral_v<T>) return v/2; // 实例化只留一臂
  else return v/2.0;
}
constexpr int pick = only_rt(6);
static_assert(pick > 0);                            // C++20 单参数 static_assert
constinit int global_counter = 0;                   // 拒绝动态初始化
struct Node{ constexpr virtual int cost() const { return 1; } };   // C++20 constexpr 虚
struct Leaf final : Node{ constexpr int cost() const override { return 2; } };
int main(){
  int r = maybe_rt(6);                              // 同一函数运行期路径
  Leaf l; constexpr int v = l.Leaf::cost();         // 常量求值中的(限定)虚族调用
  static_assert(v == 2);
  printf("pick=%d fact6=%d half_int=%d half_dbl=%.1f\n", pick, r, half(7), half(7.0));
}
```
实测输出：`pick=36 fact6=720 half_int=3 half_dbl=3.5`，且 `global=0` 版本
（thread_local/constinit 混合小样）输出 `v=2 global=0`。
**注意**：样例中 `l.Leaf::cost()` 是限定名调用（非动态派发）——标准虽在 C++20 允许
constexpr 虚函数，但"常量求值中经基类引用动态派发"在 libstdc++ 15 仍有已知失败案例
（与库内《C++20模板元编程》笔记"constexpr 虚函数 g++15.2 gnu++23 实测仍失败"互证），
接口设计不要依赖这条路径。
consteval 违约调用的实测诊断：

```text
error: call to consteval function 'only_rt(x)' is not a constant expression
note: 'x' is not a constant expression
```

## 最新演进与工业实践

- **C++23 的 constexpr 继续扩面**：`std::optional/variant` 补 constexpr（P2231R1，
  实测 302）、`std::bitset`（P2417R2，实测 302）、更多算法/容器 constexpr 化（
  P1023? 标题未能机读，不引 ⚠️）；libstdc++ 15 已覆盖大部分，但
  `constexpr <cmath>` **仍无**（P1383 → C++26 方向；与库内《C++模板元编程实战》
  的实测记录互证）。
- **`if consteval`（C++23）**：`std::is_constant_evaluated()` 的语句化糖——编译期/运行期
  双路径函数（如 constexpr sqrt）的标准写法；本机 g++ 15.2 编译通过（含该语句的文件
  编译成功、链接失败原因在 `<print>`，见文件 01 记录——if consteval 本身无碍，⚠️ 表述从简）。
- **std::expected（C++23）与契约式编程**：`[[assume]]`（C++26，P2811 实测 302，
  标题机读未成功 ⚠️ 谨慎引用）把"编译期已证明的性质"下发给优化器——static_assert 管
  "证明"，[[assume]] 管"据此优化"；P2695R1 Contracts plan（实测 302）则尝试把
  pre/post 断言标准化，运行时契约的 static_assert 化（C++26 在途）。
- **工业实践**：Google Style 把 `static_assert` 用作 ABI/布局守卫（序列化协议 sizeof/
  offset 校验）与模板接口哨兵；range-v3 的实现大量 constexpr+`if constexpr`（其
  `detail::tag_invoke` 派发体系是 15/16 文件话题的交叉样本）；fmt 库的 FMT_COMPILE
  把格式串解析整个塞进核心求值器——"constexpr 能力边界"就是库设计的能力边界。
