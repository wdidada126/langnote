> 对应原书 **第35章 可变参数模板（C++11 C++17 C++20）· 第36章 typename优化（C++17 C++20）· 第37章 模板参数优化（C++11 C++17 C++20）**

## 核心概念速览（中英对照）

- **形参包** — parameter pack：`class... T`/`Args...`，一类"多实例"声明
- **展开上下文** — pack expansion：`...` 操作符，模式 `f(args),...` 处逐一复制
- **sizeof...运算符** — 包元素个数的编译期查询
- **递归展开** — 模板递归：C++11 唯一的展开引擎（尾递归+重载终止）
- **折叠表达式** — fold expression：`(args + ...)` 四形态，C++17
- **一元空包折叠** — 空包特判：`(&args && ...)` 为 true、`||` 为 false、逗号为 `()`
- **using 声明包展开** — C++17：`using Base::visit...;` 一行组装重载集
- **推导上下文** — deduction context：`T&&` 上包推导的所在
- **typename 代替 class** — C++17：模板形参三关键词解禁；嵌套名限定符可省（C++20）
- **ADL 与不可见函数模板** — ADL for function templates（C++20，P0846R0 实测 302）
- **字面量类类型 NTTP** — literal class type as non-type template parameter：指针/字面量型当模板参数（C++11/17/20 逐级）
- **外部模板** — extern template：抑制隐式实例化（42 章，归本篇尾）

## 动机

"对任意个任意类型做同一件事"是泛型库的元需求：`make_tuple`、`emplace`、日志格式化、
信号槽。C++98 靠**预处理宏生成 15 个重载**（Boost 的 `PP_NATURAL` 时代）；
C++11 给语言加了"参数数量的维度"（`T...`），但展开要手写递归；C++17 折叠表达式把
最常见的"一元操作贯穿全包"收成一行；using 展开则解决变参类的**成员可见性**配套问题。

## 机制（编译器视角）

- **包是编译器内部的"数量维度"**：AST 上 `T...` 是一个 `PackExpansionType`，
  实例化时按实参个数**逐份复制模式**；没有运行期循环——`print_all` 实测输出的
  `10 20 30` 展开成三个独立 `printf` 调用（逗号折叠），看汇编就是三条 call。
- **推导规则**：`f(Args... args)` 对每个实参独立推一个 `Args_i`；
  折叠方向决定运算顺序：`(args - ...)` 是 `a1-(a2-(a3))`，`(... - args)` 是
  `((a1-a2)-a3)`，**非结合运算结果不同**（除法/减法实测差异经典）。
- **空包的四张安全卡**：一元 `&&...`→true、`||...`→false、`,`→空、其余操作符
  **编译错误**（`(+...)` 不允许）——标准用特判把折叠炸点前移到编译期。
- **递归展开的编译器成本**（C++11 时代）：模板实例深度=包长，MSVC 默认深度 2456 报错
  是历史名场面；`__cpp_variadic_templates` 探测 + `-ftemplate-depth` 调参是那个年代的
  构建脚本标配。C++17 折叠让实例数从 O(N) 降到 O(1)（编译器仍需展开 N 份模式，
  但不再经 N 层模板实例化）。
- **`using Base::visit...;`（C++17）**：展开成逐名 using——`variant` 访客模式
  `overloaded` 惯用法的关键一行（实测见文件 16 的 tuple-like 话题）；
  与 lambda 初始化捕获包展开 `[...xs = std::move(args)]`（C++20，P0780R2 实测 302）
  同属"展开上下文扩面"。
- **typename 三章合一的编译器视角**：
  ① `template<typename T>` 与 `class` 语义相同（历史包袱消除）；
  ② C++20 起**依赖基类的成员函数模板调用可省 `template` 关键字**、
     非限定成员名前的 `typename` 多数场景可省——诊断成本转移给更聪明的解析器；
  ③ `T&&` 上 ADL 的 P0846R0：别名模板展开出的函数模板/不可见声明也能被 ADL 命中
  （实测 302，标题机读确认）。
- **NTTP 的"可比较性"底线**：非类型模板参数必须是**两个值可判定相等**的类型——
  浮点(不能 NaN)、指针、字面量类类型（C++20 `P0732` 系比较算子要求，⚠️ 提案号未实测
  故不引）；`template<auto V>`（C++17）则让编译器同时推导"类型+值"（文件 03 呼应）。

## 权衡

- 变参错误诊断地狱：包长不匹配/某个元素不可推导时报错横跨整个展开链——
  `static_assert(sizeof...(Args)==N)` 前置检查是 C++17 时代的标准自卫术，
  concepts（文件 16）才是根治。
- 折叠只处理"同一运算符贯穿"；稍微异构的聚合（先过滤再 fold）仍需递归或
  `std::apply`+initializer_list 的间接层。
- 完美转发包 `Args&&...` 与左值实参的引用折叠组合把"签名可读性"压低——
  库代码三件套：`using` 别名、`requires`（后时代）、清晰文档。

## 相邻概念对比

| 年代 | 手段 | 代价 |
| --- | --- | --- |
| C++98 | 宏生成 N 重载 | 组合爆炸/不可维护 |
| C++11 | 递归模板展开 | 实例深度/模板名噪音 |
| C++14 | tuple 索引技巧（`index_sequence`） | 可读性换编译期能力 |
| C++17 | 折叠 + using 展开 + `std::apply` | 覆盖常见形态 |
| C++20 | 概念约束包（`requires (T+...+)` 形态校验） | 文件 16 |
| C++26 | 包索引 Args[I]（P2662R3，实测 302"Pack Indexing"） | 待普及（见 16） |

## 🔧 实测样例（已实测 g++ 15.2，-std=gnu++17）

```cpp
#include <cstdio>
template<class... T> auto sum(T... v){ return (v + ... + 0); }        // 一元右折叠带初值
template<class... T> void print_all(T... v){ ((printf("%d ", v)), ...); puts(""); } // 逗号二元折叠
int main(){
  printf("sum=%g\n", sum(1, 2, 3.5));   // 异构类型逐参数独立推导
  print_all(10, 20, 30);                // 展开=三条 printf call
}
```
实测输出：

```text
sum=6.5
10 20 30
```

（`sum` 的返回类型 `double` 来自 `1+2+3.5` 的常规算术转换——包不改变逐元素类型推导，
折叠只做语法串联。）
C++20 的 lambda 包展开捕获实测通过（本目录另样：`[...xs = std::move(args)]` 语法在
gnu++20 编译干净，与文件 05 的 init-capture 一脉）。

## 最新演进与工业实践

- **C++26 P2662R3 Pack Indexing（实测 302）**：`Args...[I]` 直接按下标取包元素——
  终结 `std::tuple_element_t<I, std::tuple<Args...>>` 式包装纸语法，对库作者
  是"递归拆包"的替代原语（libstdc++/libc++ 支持 ⚠️ 未验证本机：g++ 15.2 尚无该语法，
  实测写 `Args...[0]` 直接语法错误——如实登记）。
- **P2096?（多字符常量等）不相关；变参的库侧终局是 `std::apply/invoke`（C++17）+
  ranges 的投影机制**：abseil `absl::string_view` 格式化、fmt 的 `format_args`
  把变参包编译期打包成类型擦除数组——"变参+折叠+索引技巧"的工业天花板样本。
- **fmt/range-v3 对照**：fmt 的 `FMT_COMPILE` 把格式串解析+参数打包全放 constexpr
  （变参包与折叠是其 `args...` 管道本体）；range-v3 的 `concepts::posable` 用
  SFINAE→concepts 双形态包裹变参（文件 16 话题）。
- **工程纪律**：Google Style 限制"模板元编程炫技"，变参转发签名必须注释值类别意图；
  `static_assert(sizeof...(Args)==N)` 在 ABI 边界（RPC 桩代码生成器 gencode）仍是
  主流防御（protobuf/abseil 的 .pb 桩即此类）。
