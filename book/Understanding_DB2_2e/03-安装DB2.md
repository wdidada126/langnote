## 核心精讲

### 1. 安装前置（⚠️ 转述）
LUW 安装清单四件套：OS 版本与内核参数（UNIX 侧信号量/共享内存内核调优是 9.5 年代重头戏，Linux 后期版本多已自动化）、内存/磁盘配额、用户名规划（实例所有者如 db2inst1、围栏用户如 db2fenc1、DAS 用户 db2das——命名是惯例非强制）、端口与服务名（/etc/services 的 DB2c_实例名 50000 系，⚠️ Windows 走注册表）。

### 2. 安装类型三档（⚠️ 与 01 章呼应）
- **Complete**：全功能，能建实例、能当服务器；
- **Data Server**：服务器子集；
- **Runtime Client**：瘦客户端，只能连接既有服务器（驱动栈 CLI/JDBC 随行）。
选错档位的典型后果：Runtime Client 上调 db2icrt 直接失败——"先问角色再装机"是本章程式。

### 3. 实例=一次"户口登记"（⚠️ 转述）
- UNIX：实例所有者 OS 用户即"户主"，一个 OS 用户对一个实例（惯例口径）；
- Windows：实例是服务，db2admin 服务账号体系（后续版本已弱化此约束 ⚠️）；
- 命令面：db2icrt（建）、db2idrop（删）、db2ilist（列）、db2srvlst（端口占用体检）；
- 实例的家：实例目录/安装目录下的 sqllib，命令与脚本的总入口。

### 4. DAS 与围栏（fenced）机制（⚠️ 转述）
DB2 Administration Server（DAS，db2das）为控制中心类图形工具提供远程管理服务；**围栏进程**把"外伸函数/触发器与某些工具执行"隔离到独立围栏用户下运行，避免插件崩溃拖垮实例或越权——这是 DB2 安全模型里少被注意却重要的一环（呼应 [11](11-安全实现.md)）。

### 5. 补丁与升级（⚠️ 转述）
9.5 时代的 fixpack 流程：停实例→打补丁→升级目录（db2updv*）→回归验证；大版本升级用 INSTALL 覆盖+目录升级工具链（具体号与工具名 ⚠️ 勿背死，以现行文档为准）。

### 6. 卸载与故障排查入门（⚠️ 转述）
- 卸载次序与安装相反：删实例→停 DAS→卸二进制；残留 sqllib/注册表项要人工核对。
- 装不上的三板斧：看安装日志目录、查 OS 前置（内核参数/权限/端口占用）、看 db2diag.log 首异常（诊断体系放大在 [15](15-性能与问题诊断.md)）。

### 7. 安装章的"现代读法"
2026 年读者不必复刻 9.5 向导截图，但**心智模型全部存续**：三档安装类型、实例/围栏/DAS 的角色分工、补丁与目录升级的依赖次序——只是 GUI 向导换成响应式/静默安装与容器化（演进节）。

## 常见误区（安装版）

1. "装完就能建库"——要先有实例；实例是第二级门槛（[05](05-环境与实例数据库.md)）。
2. "实例名=db2inst1"——那只是默认惯例；多实例共存时命名与端口规划才是重点。
3. "Windows 和 UNIX 一个规矩"——UNIX 的"OS 用户=实例所有者"模型在 Windows 上是服务账号模型，运维手感不同。
4. "先装再想角色"——三档安装类型选错=重装或补装，安装前的角色问题比安装中的点击问题重要一个量级。
5. "围栏用户可有可无"——关掉隔离换来的不是省事，是把插件执行的爆炸半径放进实例进程（⚠️ 权衡口径转述）。

【微讲堂】安装章的"见面四连"（示意，⚠️ 非实测——动作序列的次序感是本章程式）：

```text
# 1) 以实例所有者登录（如 db2inst1）
$ db2ilist                # 看这台机器已有哪些实例户口
$ db2icrt myinst          # 建实例：户口登记（端口占用先用 db2srvlst 体检）
$ db2start                # 实例起飞：DAS/围栏/后台代理按角色就位
$ db2 "create database demo" # 第一次真正建库——下一章工具章接棒
```

## 核心概念速览（中英对照）

1. **安装类型** — Complete / Data Server / Runtime Client: 装机三档角色选择。
2. **实例所有者** — Instance Owner: UNIX 下承载实例的 OS 用户。
3. **db2icrt / db2idrop** — Instance Create/Drop: 实例户口登记与注销。
4. **sqllib** — SQL Library: 实例的命令/脚本/库总目录。
5. **DAS** — DB2 Administration Server: 为图形管理工具服务的实例辅助守护。
6. **围栏用户** — Fenced User: 隔离外伸执行的低权 OS 账号。
7. **fixpack** — Fix Pack: 版本内累积补丁包。
8. **db2updv** — Upgrade Utilities: 目录/系统对象升级工具族（⚠️ 名称随版本变）。
9. **服务名/端口** — Service Name: /etc/services 或注册表里 DB2c_实例名 的映射。
10. **内核参数调优** — Kernel Tuning: UNIX 装 DB2 的前置重头（共享内存/信号量）。
11. **db2srvlst** — Service List: 端口与实例占用体检命令。
12. **静默安装** — Response File Install: 无人值守安装方式（现代主流）。

- **GUI 向导已退役**：Db2 11.5 LUW 以 db2setup/响应文件静默安装与容器化为主（⚠️ 转述；官方安装文档入口 https://www.ibm.com/docs/en/db2 ，curl 200 ✅）。
- **容器与云形态**：官方 ibmcom/db2 镜像（现经 IBM Container Registry 分发）成为开发态主流——盘上 [../../db/db2/db2.md](../../db/db2/db2.md) 的 docker 备忘正是这条线的民间注脚。
- **许可换代**：CDKey 时代终结为 CPEL/注册服务与按需档位（CPC/ILMT 合规语境 ⚠️ 二手口径，不贴深链）。
- **内核参数自动化**：现行 Linux 上 DB2/Db2 安装前置检查大幅自动化，"手调信号量"的记忆负担可以卸下（⚠️）。
- **读本章的正确姿势**：把三档角色/实例户口/围栏隔离三个模型带走；截图年代感与具体向导页全部忘掉。
