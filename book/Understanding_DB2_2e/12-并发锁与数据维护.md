## 核心精讲

### 1. 隔离级别：DB2 的默认哲学（⚠️ 转述）
契约四档：RR/RS（RS=默认，含幻读防护）、RC（游标稳定性折中）、RU；隔离级别在 CONNECT 或会话级设定，影响锁持有与共享读行为（共享锁提前释放的 RC 语义 ⚠️）。"默认最严"意味着应用常需显式降档换并发——与 SQL Server 默认 RC 的取向正相反（跨厂记忆锚点）。

### 2. 锁的经济学（⚠️ 转述）
行/页/表粒度、意向锁族（IX/IS…）、LOCKSIZE 表提示（TABLE/ROW 与 ALLOW WRITE）；锁内存锁在 **LOCKLIST** 池，逼近高水位触发**锁升级**（row→table），MAXLOCKS 控单表份额（⚠️ 升级判据细节以官方文档为准）；latch 与锁的分界（内存结构轻量闩 ⚠️）。

### 3. 等锁、超时、死锁（⚠️ 转述）
LOCKTIMEOUT 旋钮与死锁检测（后台代理周期性检测并牺牲一方）、`MON_UNLOCK_WAIT`/快照锁信息取"谁在等谁"（9.5 快照语境，11.5 换 MON_GET_* 表函数 ⚠️）——本章的排障套路在 15 章诊断框架里收口。

### 4. RUNSTATS：优化器的粮食（⚠️ 转述）
`RUNSTATS ON TABLE ... WITH DISTRIBUTION AND DETAILED INDEXES ALL`：行数/页数/列频数直方图/列相关度（ndist）；统计过期→坏计划——"维护章的第一曲线"。统计配置文件（statistics profile）固化采样档位。【对照】🔧 E1 演示"统计前后计划翻转"。

### 5. REORG 与聚簇度（⚠️ 转述）
REORGCHK 体检指标（FSPSTAT 类）+ REORG 重建表/索引页序；删除-插入造成的行散布使顺序读退化，聚簇索引/聚簇比率随维护窗口复位；离线 REORG 锁表、（9.7+）在线演进（⚠️ 版本分界）。【对照】🔧 E2 已在 [08](08-存储模型.md) 演示"删 30% 行只还 4 页、VACUUM 3.9ms 归 0"。

### 6. 数据搬运工具族（⚠️ 转述）
LOAD（旁路直写+可非恢复式、备份 pending 后果、 REPLACE/INSERT 模式）、IMPORT（走 SQL、慢但活表友好）、EXPORT/UNLOAD、db2move（多表导出入+db2look 配套=轻量迁移三件套）；与 [04](04-DB2工具集.md) Data Manager 向导的 GUI/CLI 双路。

### 7. 维护排班方法论（本章工程观）
"统计跟数据动、重组跟碎片动、绑定跟对象动"三句话；把 E1 的教训推广：**任何批量装载后 RUNSTATS 不是可选项**（⚠️ 转述的 DB2 运维铁律，🔧 E1 在 SQLite 上验证了同一因果链）。

## 🔧 类比实验一 E1：统计信息翻转计划（SQLite，**非 DB2 行为**）

方法（Python sqlite3 3.45.3，2026-10-01；join 查询 `small→big`，先无统计后 ANALYZE）：
- 前：`SCAN big` + `SEARCH small USING COVERING INDEX small_a`（以 big 为外表）；
- ANALYZE 后：`SCAN small` + `SEARCH big USING INDEX big_a`（**驱动表翻转**）✅；
- 统计落库：sqlite_stat1 写入 `small/small_a="200 29"`、`big/big_a="20000 20"`（行数+每值均行数）✅。
- 对位：DB2 装载/大变更→RUNSTATS→优化器重估——**"统计新鲜度改变计划"的因果链在任何 CBO 引擎都成立**（Oracle 侧同题 → [../Cost_Based_Oracle_Fundamentals/07-直方图.md](../Cost_Based_Oracle_Fundamentals/07-直方图.md)）；SQL 方言与旋钮参数不同，不可互抄。

## 🔧 类比实验二 E3：WAL 下的读写并发（SQLite，**非 DB2 行为**）

方法：1 万行表，journal_mode delete→WAL；连接 A 开事务写入未提交，连接 B 并发读；连接 C（timeout=0.2s）再写。
- B 读到 **10000**（旧快照，不被脏写污染）✅；-wal 文件出现（0B 起步）✅；
- C 写 → `database is locked`（0.2s 超时）✅；A 提交后 B 见 10001 ✅。
- 对位：读不挡写/写不挡读的版本化直觉 ≈ DB2 的 RC/RS 读行为差异与锁等待超时；**差异**：SQLite 是库级写锁，DB2 是行锁+锁升级体系——粒度账完全不同，勿混（DB2 侧见精讲 2 ⚠️）。

## 常见误区

1. "RS 下读会挡写"——共享读不挡写但持锁久，降 RC/CS 的权衡要算账（⚠️ 转述）。
2. "LOAD 完就完事"——备份 pending+统计缺失两颗雷（精讲 6/4）。
3. "REORG 天天跑才健康"——按 REORGCHK 指标触发，非日历触发。
4. "锁等待=死锁"——等待与环路检测两回事（精讲 3）。

## 核心概念速览（中英对照）

1. **隔离级别** — Isolation Level: RU/RC/RS/RR 四档契约（DB2 默认 RS）。
2. **可重复读** — Repeatable Read: 同事务内重复读一致（含幻读防护）。
3. **游标稳定性** — Cursor Stability: DB2 的"类 RC"主打档（⚠️ 定名以官方为准）。
4. **意向锁** — Intent Lock: 粒度层的"我在下级有锁"声明。
5. **锁列表** — LOCKLIST: 锁内存总量旋钮，逼近水位升级。
6. **锁升级** — Lock Escalation: row→table 的降粒度自保。
7. **锁超时/死锁** — LockTimeout/Deadlock: 等不起与互相等。
8. **RUNSTATS** — 统计收集: 行数/分布/索引三级新鲜度。
9. **统计配置文件** — Statistics Profile: 采样档位固化。
10. **REORGCHK/REORG** — 体检与重组: 聚簇度复位两连。
11. **LOAD/IMPORT** — 两速装载: 旁路直写 vs 走 SQL。
12. **备份待定** — Backup Pending: LOAD 非恢复式的偿还债。
13. **db2move/db2look** — 搬运与 DDL 抽取: 轻量迁移三件套。
14. **MON 等待监控** — 锁等待取证: 9.5 快照/11.5 表函数（版本分界 ⚠️）。
