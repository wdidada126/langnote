## 核心精讲

### 1. 三层世界（⚠️ 转述）
- **OS 层**：DB2 是"寄生"于 OS 的应用——文件、内存段、TCP 栈、认证都由 OS 供给；LUW 上进程/线程模型差异（Windows 多线程 vs UNIX 多进程）由 DB2 抽象掉（放大见 [14](14-进程模型与内存模型.md)）。
- **实例层**：实例=一组后台进程+一套配置注册表+一个 sqllib 家目录；实例本身不存业务数据，它"托管"数据库。
- **数据库层**：表空间、目录（SYSIBM/SYSCAT 视图）、日志（primary/secondary logs）三位一体；备份恢复的粒度、锁的粒度都最终落在这里（05/08/12/13 章）。

### 2. 一次 SQL 请求的旅行（⚠️ 转述）
1. 应用经 CLI/JDBC 驱动发出语句；
2. 服务器端**协调 agent** 接单：权限检查→动态语句缓存查找→未命中则**编译/优化**（访问路径选择）；
3. 执行引擎按页向**缓冲池**要数据，缺页则触发异步预取（prefetcher），脏页由**页清道夫**（page cleaner）延后刷盘；
4. 结果以游标分批回传。
【图】这条流水线是 14/15 两章的目录：agent 与后台进程=进程模型；缓冲池与内存堆=内存模型；优化器与预取=性能章。

### 3. 配置的两级抽屉（⚠️ 转述）
- **实例级**：注册表变量（db2set 设置的 DB2_* 旋钮）+ 实例配置参数（db2 get/update dbm cfg）。
- **数据库级**：db2 get/update db cfg（缓冲池大小、日志归档、锁列表…）。
- 同名参数两级可叠加生效，优先级口径 ⚠️ 以现行文档为准（ibm.com/docs/en/db2 入口 ✅）。

### 4. 全景里的高可用/复制选项（⚠️ 转述）
9.5 时代 DB2 LUW 的"官方工具箱"：HADR（日志级镜像库）、复制（Q Replication/CDC 语境）、分区数据库内建并行；备份恢复自成体系（[13](13-备份与恢复.md)）。本册只识轮廓——细节是 #77 DBA 卷的地盘（三册分工见 [00-总览与阅读地图.md](00-总览与阅读地图.md)）。

### 5. DPF：把"扩展性"画进总图（⚠️ 转述）
DPF=Database Partitioning Feature：数据按分布键哈希切片到多分区，每分区独立缓冲池/容器，跨分区查询由协调器并行分发（DB2_PARALLEL? 旋钮语境 ⚠️）。它是 DB2 在 Shared-Nothing 阵营的答卷——与今天分布式 SQL 引擎（如 MPP 云数仓）的理念同构，本目录在 [15](15-性能与问题诊断.md) 演进节挂现代对照。

### 6. 新手误区三则
1. "实例=数据库"——错，实例是运行实体，一个实例可挂多个数据库（放大见 [05](05-环境与实例数据库.md)；🔧 E6 用 ATTACH 演示"一个会话多库"的类比形态，非 DB2 行为）。
2. "大图=架构组件堆砌"——错，2-A 的信息量在**两条流的分工**：控制流走 agent，数据流走页。
3. "DPF 人人可用"——⚠️ 企业档选装件，普通 Express/Workgroup 语境碰不到。
4. "看清图=学会 DB2"——大图只是坐标系；不装不跑（本目录不可实测）时，务必配合官方文档逐层核对术语现行状态（ibm.com/docs/en/db2 入口 ✅）。

## 核心概念速览（中英对照）


1. **三层世界** — OS / Instance / Database: DB2 概念定位的第一坐标系。
2. **协调 agent** — Coordination Agent: 代表应用连接执行请求的服务进程/线程。
3. **预取器** — Prefetcher: 异步把页提前读进缓冲池的后台代理。
4. **页清道夫** — Page Cleaner: 异步把脏页延后刷盘的后台代理。
5. **缓冲池** — Bufferpool: 页级内存缓存，与表空间页大小挂钩。
6. **注册表变量** — Registry Variable: db2set 管理的实例/安装级旋钮。
7. **数据库配置参数** — Database Configuration: db cfg 抽屉（缓冲池/日志/锁等）。
8. **HADR** — High Availability Disaster Recovery: 日志重放级镜像高可用选项。
9. **DPF** — Database Partitioning Feature: Shared-Nothing 多分区并行选装。
10. **分布键** — Partition Key: 决定行哈希落点的列。
11. **控制流/数据流** — Control/Data Path: 大图上两种箭头的分工。
12. **目录** — Catalog（SYSIBM/SYSCAT）: 自描述元数据，附录 D 主题。
13. **游标** — Cursor: 结果集分批回传的服务器对象。
14. **SQL 请求旅行** — Request Flow: 接单→鉴权→优化→执行→返回的流水线。
15. **快照监控** — Snapshot Monitoring: 9.5 时代"给系统拍照片"的监控法（后被表函数取代）；其取数入口即在实例家目录 sqllib。

## 最新演进与工业实践

- **大图本身没过时**：实例/数据库/表空间/缓冲池的层级在 Db2 11.5 仍是官方文档的组织方式（入口 https://www.ibm.com/docs/en/db2 ，curl 200 ✅）。
- **请求旅行的现代版**：动态语句缓存、section cache、监控表函数（MON_*）已换代；9.5 的快照监控口径在现行文档中被表函数取代（⚠️ 转述，本目录 [15](15-性能与问题诊断.md) 有对照）。
- **DPF 的今天**：分区数据库仍是 LUW 企业形态选项，但工业界大量并行需求已迁移到云 MPP/湖仓引擎——概念同构可对照 [../Amazon_Redshift_TDG/00-总览与阅读地图.md](../Amazon_Redshift_TDG/00-总览与阅读地图.md)（Redshift=云上 Shared-Nothing 直系后代）与 [../DuckDB_in_Action/00-总览与阅读地图.md](../DuckDB_in_Action/00-总览与阅读地图.md)（单机向量化对照）。
- **HADR 的今天**：仍是 Db2 LUW 主力 DR 方案，并衍生自动故障转移/仲裁等形态（⚠️ 细节以官方文档为准）。
