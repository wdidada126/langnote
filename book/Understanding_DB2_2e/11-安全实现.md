## 核心精讲

### 1. 认证：先证明"你是你"（⚠️ 转述）
PLUGIN 谱系：CLIENT/GSSPLUGIN（KRB5）/LDAP/OS 等；SERVER 模式（服务器 OS 验口令）是默认最省事也最裸的档；CLIENT 模式客户端先验再转交。**认证决定连接能不能进，授权决定进来后能干什么**——两章级概念分界务必分清（联动 [06](06-客户端服务器连接配置.md) 精讲 5）。

### 2. 授权 ID（Authorization ID）（⚠️ 转述）
用户/组/角色映射为授权 ID（数据库内身份的统称）；同名 OS 用户与数据库对象属主（schema 户主）的交互规则、PUBLIC 隐式组的默认放行面，是"权限排查"第一站（目录视图 SYSCAT.DBAUTH/TABAUTH/COLAUTH ⚠️ 视图名口径）。

### 3. 三级特权模型（⚠️ 转述）
实例级四件套 SYSADM（顶点）/SYSCTRL/SYSMAINT/SYSMON；数据库级 DBADM（库内顶点）、DATAACCESS/DBDEFINER 类细分与**角色**体系（9.5 是否已有 CREATE ROLE 口径 ⚠️ 存疑不写死——9.7 明确角色普及，读本章请带此分界）；对象级 SELECT/INSERT/UPDATE/DELETE/ALTER/CONTROL 等与列级/例程 EXECUTE。**SECADM 独立于 DBADM** 的"三权分立"设计（安全管理员与数据管理员分人）是政企采购常考点。

### 4. GRANT/REVOKE 链（⚠️ 转述）
WITH GRANT OPTION 的传播链、REVOKE 的级联口径（按 GRANT 记录反查 ⚠️）；schema 级授权对象（库级/模式级/表级/列级四级下发）。运维常用"权限断点定位法"：从连接串→认证模式→库权限→表权限→列权限逐层查目录视图。

### 5. LBAC：行级安全的一等公民（⚠️ 转述）
安全管理员（SECADM）建：组件（有序/无序/集合）、规则（比较算子+敏感序）、策略（组件×规则组合）、标签（L1 等挂到列值）；表加 LBAC 列并挂策略；用户授予"可读写标签集"。政府/军工/医疗的多密级场景刚需——也是 DB2 相对同期开源引擎的招牌差异（对照：MySQL 8 无、PG 靠 RLS，演进节）。

### 6. 审计（⚠️ 转述）
db2 audit 类机制+审计例程/审计日志落点；与 OS 审计、TAM 类产品（后由 IBM Security Guardium 等承接 ⚠️）的分工：数据库内留痕 vs 独立旁路审计。

### 7. 最小权限实践清单（本目录提炼）
应用账号只给 DML+EXECUTE、禁 DDL；管理职能拆 DBADM/SECADM/WLMADM；PUBLIC 默认面先审计再收紧；LBAC 列宁缺毋滥（写放大代价）。【注】此清单风格仿原书章末 Tip 块。

## 🔧 E7 反例实验：没有引擎内 RBAC 会怎样（SQLite，**非 DB2 行为**）

方法（本机 Python sqlite3 3.45.3 实跑 2026-10-01）：对库文件直接执行 `CREATE USER u`、`GRANT SELECT ON t TO u`。
- 结果：两条均 `OperationalError: near "USER"/"GRANT": syntax error` ✅——SQLite 完全没有引擎内用户/授权语法；库里 view 计数 0。
- 推论：嵌入式引擎的安全模型=**文件权限+宿主进程**；DB2 的三道门（认证/授权/LBAC）是"服务器引擎"的物种特征。此反例帮读者把 11-A 图的第一象限"如果没有门"看明白——**非 DB2 行为，仅对照演示**。

## 常见误区

1. "认证过了就能查全库"——PUBLIC 授权面可能过大，查库级/表级目录。
2. "SYSADM 可以做一切"——SECADM 职能分离后，系统管理员无权改 LBAC 策略（⚠️ 转述考点）。
3. "LBAC=视图过滤"——引擎内核级行/列比较与视图的"性能+绕过面"完全不同。
4. "审计=日志"——事务日志不为取证设计（联动 [13](13-备份与恢复.md) 的日志用途边界）。

## 核心概念速览（中英对照）

1. **认证** — Authentication: 证明身份的插件谱系（CLIENT/SERVER/LDAP/KRB）。
2. **授权 ID** — Authorization ID: 数据库内主体身份的统称。
3. **SYSADM** — 系统管理员特权: 实例级顶点（⚠️ 与 z/OS SECADM 分离口径）。
4. **DBADM** — 数据库管理员特权: 库级顶点。
5. **SECADM** — 安全管理员特权: 授权/LBAC 专属权（三权分立考点）。
6. **GRANT OPTION** — 授权传播: 可转发链与级联回收。
7. **PUBLIC** — 隐式组: 全体主体的默认权限面。
8. **列级权限** — Column Privilege: UPDATE/INSERT 的列粒度下发。
9. **LBAC** — 基于标签的访问控制: 组件/规则/策略/标签四件套。
10. **安全策略** — Security Policy: 组件×规则的比对框架。
11. **审计** — Auditing: db2 audit/审计例程/旁路审计谱系。
12. **围栏** — Fencing: 插件执行隔离（03 章联动的爆炸半径）。
13. **最小权限** — Least Privilege: 本章 Tip 块的工程化清单。

## 最新演进与工业实践

- **认证现代化**：LDAP/Kerberos 插件之外，云形态引入 IAM/令牌体系；操作系统认证在 11.5 被明确降级（⚠️ 转述；入口 https://www.ibm.com/docs/en/db2 curl 200 ✅）。
- **RBAC 补课**：角色体系（CREATE ROLE）在 9.7 后完善、11.5 成熟——本章 9.5 口径读现代文档要打的第一个补丁。
- **行级安全普及**：LBAC 的"引擎内行级管控"生态位今日由原生 **Row Access Control + 数据掩码（Query Rewriting/Column Mask）** 承接（⚠️ 11.5 特性名转述）；跨厂对照：PostgreSQL RLS、SQL Server Always Encrypted/动态掩码。
- **安全大盘**：列加密/密钥管理（Trusteer/Guardium 系）与合规审计（等保/ GDPR）成为采购主话题；"库内权限"只是防线之一——本目录安全双线（#51）落盘后互链。
- **读本章姿势**：三道门模型+三权分立+LBAC 四件套带走；具体视图名/参数名当作可查即查的字典项，勿背。
