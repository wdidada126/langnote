## 核心精讲

### 1. schema：对象的户主（⚠️ 转述）
AUTHID 默认建同名 schema，CURRENT SCHEMA 决定非限定名解析；全限定 schema.tab 是脚本稳健性的第一习惯（与 [05](05-环境与实例数据库.md) 的别名体系分层）。

### 2. 表的三件事：列、组织、落位（⚠️ 转述）
列类型家族（定长/变长/数值/LOB/XML——XML 单列形态见 [10](10-pureXML.md)）；**ORGANIZE BY**（9.5 时代 MDC 多维聚类/维度块 ⚠️ 后续版本路线有变）与 **IN tablespace / INDEX IN** 落位子句把逻辑表钉到物理表空间（08 章接手）；ALTER 大部分可在线，异表重建类变更需 REORG（12 章）。

### 3. 约束与标识列（⚠️ 转述）
PK/FK（RESTRICED/NODELAY 延迟检查）、CHECK、GENERATED ALWAYS AS IDENTITY（9.5 起官方推行的序列式自增，旧 GENERATED ALWAYS FOR EACH ROW 派生列并存语境 ⚠️）；约束与 REORG/统计的联动（ADD COLUMN 后何时必须重算）放 [12](12-并发锁与数据维护.md)。

### 4. 索引家族（⚠️ 转述）
唯一/重复、聚簇（CLUSTER，配合表空间预取口味）、INCLUDE 覆盖列、块索引（BBIPAGES，大表顺序扫描的块粒度选项 ⚠️ 口径）；键序与谓词匹配是访问路径第一性原理（15 章）；升降序键与 COLSEQ 从目录键列视图 SYSCAT.INDEXCOLS 可读。

### 5. 视图 / MQT / 触发器（⚠️ 转述）
视图=存储 SELECT（只读+INSTEAD OF 触发器写路径）；**MQT**（Materialized Query Table，REFRESH SYSTEM/DEFERRED，优化器自动匹配改写）是 DB2 数仓看家件、后由 MVs 路线延续；触发器 BEFORE/AFTER + REFERENCING + 列级 UPDATE OF（OLD/NEW 像 SQL Server 的 inserted/deleted，与 Oracle 行级写法相异——跨厂记忆锚点）。

### 6. 序列 / 别名 / nickname（⚠️ 转述）
SEQUENCE 对象（NEXTVAL/PREVIOUS/FETCH/CACHE，替代触发器自增的正统路线）；别名=对象可换名（与 [05](05-环境与实例数据库.md) 数据库别名不同层）；Federated nickname=远端表映射（跨库集成入口，本册只点名）。

### 7. 目录表自述（附录 D 主题 ✅ 归属）
SYSCAT.* 现行视图族（SYSTABLES 老口径与 SYSCAT 新口径的换代在 9 代已完成 ⚠️）：元数据即视图、SELECT 即诊断；本目录把"用目录表回答对象问题"的动作放到 [15](15-性能与问题诊断.md) 的排障语境复用。

## 常见误区

1. "视图能当表写"——需 INSTEAD OF 或 MQT 刷新策略配合。
2. "IDENTITY=SEQUENCE"——前者表列派生、后者独立对象+CACHE，用法与并发成本不同（⚠️ 转述）。
3. "建聚簇索引后永久聚簇"——插入漂移会稀释聚簇度，配合 REORG/统计维护才成立（12 章）。
4. "MDC 万能"——9.5 的多维组织在后续版本让位于块索引/自适应路线（⚠️，演进节）。
5. "改完表结构就生效"——对象状态/表空间 pending、绑定包失效（REVALIDATE）都要检查（12/15 章）。

【微讲堂】对象章最小 DDL 流（示意，⚠️ 非实测）：

```text
CREATE TABLE sales.orders (
  id BIGINT GENERATED ALWAYS AS IDENTITY (START 100 INCREMENT 1 CACHE 20),
  cust INTEGER NOT NULL,
  amount DECIMAL(11,2),
  CONSTRAINT ord_pk PRIMARY KEY (id),
  CONSTRAINT ord_fk FOREIGN KEY (cust) REFERENCES customers(custid)
) IN userspace1 INDEX IN idxspace1 ORGANIZE BY COLUMN (orderdate);
CREATE INDEX ix_ord_amount ON sales.orders (amount DESC) INCLUDE (cust);
```

## 核心概念速览（中英对照）

1. **schema** — 模式: 对象的命名户主与权限边界。
2. **ORGANIZE BY** — 组织子句: 9.5 多维聚类（MDC）建表口味（⚠️ 后代路线有变）。
3. **IN / INDEX IN** — 落位子句: 数据与索引分置表空间。
4. **IDENTITY 列** — Generated Always As Identity: 序列式自增列。
5. **INCLUDE 索引** — Covering Index: 非键列入叶实现覆盖扫。
6. **聚簇索引** — Clustered Index: 键序与物理序对齐的一次投资。
7. **MQT** — Materialized Query Table: 可自动刷新的实体化查询表。
8. **INSTEAD OF 触发器** — 视图写路由: 对视图的 DML 改道执行。
9. **nickname** — 联邦昵称: 远端对象的本地别名。
10. **SYSCAT 视图** — Catalog Views: 目录即视图的自描述族（附录 D）。
11. **延迟约束** — Constraint WITH NODELAY/DELAY: 检查时机旋钮（⚠️ 语法细节转述）。
12. **db2look** — DDL 抽取: 从目录反向生成建库脚本的实用工具。
13. **REVALIDATE** — 包重校验: 对象变更后使依赖失效重绑。

## 最新演进与工业实践

- **MDC 谢幕**：多维聚类在后续版本淡出，块索引/自适应预取接棒（⚠️ 口径；官方文档入口 https://www.ibm.com/docs/en/db2 curl 200 ✅）——2008 年"ORGANIZE BY"的手感今天应替换为"分区表+统计+块粒度"的新三件套。
- **MQT→MVs**：物化路线在 Db2 Warehouse 与 SQL:1999 系引擎（Oracle MV/PG 物化视图/StarRocks 异步 MV）已成显性军备，概念同源 → [../Trino_The_Definitive_Guide_2e/00-总览与阅读地图.md](../Trino_The_Definitive_Guide_2e/00-总览与阅读地图.md) 等盘上近亲（湖仓侧的"物化"变体）。
- **IDENTITY 统一语法**：GENERATED AS IDENTITY 已入 SQL 标准多年，其它引擎（PG IDENTITY/MySQL AUTO_INCREMENT/SQLite STRICT rowid）各自靠拢——本章对象语法是"方言趋同"的最佳观察窗。
- **目录表今用**：SYSCAT/SYSIBM/AUDIT 式目录视图仍是运维主力；Db2 11.5 增加监控表函数族替代快照（衔接 [15](15-性能与问题诊断.md) 演进节）。
- **实操建议**：拿任意开源库（如 SQLite 版示例库）过一遍"目录表回答 10 个对象问题"，再回看本章——**元数据即文档**的 DB2 世界观在 2026 依然值钱。
