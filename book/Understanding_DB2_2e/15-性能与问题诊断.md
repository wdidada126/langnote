### 1. 访问路径：优化器的选择题（⚠️ 转述）

### 2. 语句准备的成本（⚠️ 转述）
动态 SQL 的编译代价藏在"第一次执行"：节（section）缓存/语句缓存/包缓存（pckcachesz/statement cache 两级 ⚠️ 名目）；PREPARE 复用与参数标记（?）减少重编；对象变更后包失效需 REVALIDATE（[12](12-并发锁与数据维护.md) 联动）。

### 3. IO 的三驾马车（⚠️ 转述）

### 4. 内存-磁盘两本账（⚠️ 转述）

## 🔧 类比实验 E4：索引不一定被用——访问路径的诚实课（DuckDB 1.5.5，**非 DB2 行为**）

方法（本机实跑 2026-10-01）：200 万行表 f(id,s,a)，a=(range*37)%1000 均匀分布，建 ART 索引 i_a；跑 `SELECT count(*), sum(id) WHERE a=137` 与选择性 LIMIT 查询，取 EXPLAIN。
- 结果一：谓词聚合 **8.0ms** 返回 (2000, 1999602000)——快，但 **EXPLAIN 计划仍是 SEQ_SCAN**（聚合类查询规划器不选索引）✅；
- 结果二：投影+LIMIT 查询同样走 SEQ_SCAN ✅（小结果集早停更便宜）。
- 教训对位 DB2：访问路径是**成本模型的决策**而非"有索引就用"的开关——统计（E1）、谓词形态、算子需求共同决定；读 EXPLAIN 是性能章的第一习惯（精讲 6"计划层"在任意引擎都成立）。**边界**：DuckDB 向量化顺序扫描极快，其成本观不能外推 DB2/行存引擎的数值结论。

## 常见误区

1. "加索引=变快"——写放大+计划未必用（🔧 E4 负结果实证）。
2. "调参先于测量"——无基线数字的参数调整是占卜（原书三角图中心语）。
3. "db2diag 只给错误看"——警告与时间线对齐才是定位艺术。
4. "统计一次收永久新"——数据动、统计动（[12](12-并发锁与数据维护.md) 排班）。
5. "并行万能"——单查询并行救不了锁等与坏计划。

## 核心概念速览（中英对照）

1. **访问路径** — Access Path: 索引匹配+连接算法+谓词顺序的总称。
2. **成本模型** — Cost Model: 优化器选择题的评分函数。
3. **星连接优化** — Star Join: 数仓事实-维度图样的专用招。
4. **MQT 匹配** — Query Rewrite: 物化表自动命中改写（07 联动）。
5. **节/语句/包缓存** — Section/Statement/PKG Cache: 免重编译三级缓存。
6. **预取** — Prefetch: 顺序/列表异步读。
7. **条带化** — Striping: 多容器均摊 IO。
8. **排序溢盘** — Sort Overflow: 堆→临时空间（14 联动）。
9. **快照** — Snapshot: 9.5 时代"拍照片"监控法（11.5 换表函数）。
10. **XEVENT** — 扩展事件监视: 9.5 轻量取证新枪。
11. **db2diag.log** — 诊断日志: 错误+警告+时间线主账本。
12. **db2pd** — 免 SQL 验尸刀: 实例内部状态直读。
13. **db2expln/dynexpln** — 计划解读双工具: 静态/动态语句配对。
14. **Visual Explain** — 框图计划: 04 章工具露脸处的完全体。
15. **先测量后动手** — Measure First: 优化三角的中心公理。
