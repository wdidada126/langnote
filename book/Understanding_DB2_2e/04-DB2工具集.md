## 核心精讲

### 1. CLP：一切工具的地基（⚠️ 转述）
Command Line Processor（`db2`）是 DB2 的"正门"：SQL、db2 命令、CLP 脚本三种语句同窗可发；交互态里的 `:x`/`q`、多行缓冲与 `-td` 自定义结束符是新手第一道坎。【注】本书所有 GUI 操作，章末都会给"CLP 等价命令"——视觉学习向也坚持"命令行是真相之源"。

### 2. CLP 脚本与自动化（⚠️ 转述）
`db2 -tvf script.db2` 式批执行（-t 分句、-v 回显、-s 静默出错继续的取舍组合）；脚本头 `CONNECT` 语句与 `%db2` 环境替换是老派但有效的复用手法。调度交给 OS cron/任务计划——DB2 不提供现代工作流编排（对比见演进节）。

### 3. Command Editor：表单化的 db2 命令（⚠️ 转述）
按对象树选命令→填参数→生成命令文本→执行或直接拷贝。**学习价值大于生产价值**：它是最好的"命令语法教学机"，生产自动化仍应回到 CLP/脚本。

### 4. Control Center 家族分工（⚠️ 转述）
- Control Center：实例/数据库/表空间的树状管理+右键向导（建表、备份、RUNSTATS 都能点出来）；
- Command Center：即席 SQL+结果网格；
- Development Center：SQL/Java 例程开发（存储过程写作间）；
- Data Manager：导入/导出/LOAD 向导+数据克隆（呼应 [12](12-并发锁与数据维护.md) 维护工具与 [13](13-备份与恢复.md)）；
- Replication Center：CD/CDC 复制配置台（本册只点名）。

### 5. Health Center 与监控入口（⚠️ 转述）
Health Center 用"仪表灯+告警阈值"把快照监控可视化；专业诊断仍走 db2 get snapshot/db2pd/diag 日志——工具是入口不是结论（放大在 [15](15-性能与问题诊断.md)）。

### 6. 工具选择方法论（本目录提炼）
按"读→写→批→诊"四问选工具：看一眼用 CLP；反复调同一命令用 Command Editor 生成后转脚本；数据搬运用 Data Manager 向导起步、LOAD/EXPORT 脚本收尾；异常从 GUI 灯墙进入、以 snapshot/db2pd 出结论。

## 常见误区

1. "GUI 操作≠命令行操作会留痕不同"——GUI 底层就是发 db2 命令；审计与复现一律看命令面（⚠️ 转述）。
2. "CLP 里 SQL 和命令随便混着写"——语句类型与分隔规则不同，`db2 "SQL"` 与裸 db2 命令的边界要拎清。
3. "Health Center 报警=故障"——灯墙是阈值提示，不是根因。
4. "Command Editor 会跟着版本一直活"——⚠️ 控制中心系 GUI 在 9.7/10.1 后陆续退役（见演进节）。
5. "工具章可跳过"——05/12/13/15 各章的动作全在这套工具面上执行，跳章=后面全盲。

【微讲堂】一个 CLP 脚本最小骨架（示意，⚠️ 非实测；次序感即本章程式）：

```text
-- mytask.db2（用 db2 -tvf mytask.db2 执行）
CONNECT TO demo USER db2inst1 USING ******;
RUNSTATS ON TABLE db2inst1.emp WITH DISTRIBUTION AND DETAILED INDEXES ALL;
CONNECT RESET;
```

## 核心概念速览（中英对照）

1. **CLP** — Command Line Processor: db2 命令/SQL/脚本三合一正门。
2. **CLP 脚本** — CLP Script: -tvf 批执行的 .db2 文本。
3. **语句结束符** — Statement Terminator: -td 自定义分句符（默认分号）。
4. **Command Editor** — 命令编辑器: 表单→命令文本的生成器。
5. **Control Center** — 控制中心: 树+详情主 GUI（db2cc）。
6. **Command Center** — 命令中心: 即席 SQL 与结果网格窗口。
7. **Development Center** — 开发中心: SQL/Java 例程写作间。
8. **Data Manager** — 数据管理器: 导入导出/备份/克隆向导群。
9. **Replication Center** — 复制中心: CD/CDC 配置台。
10. **Health Center** — 健康中心: 阈值灯墙式监控 GUI。
11. **Visual Explain** — 可视化执行计划: 框图式计划呈现。
12. **db2pd** — 进程级诊断工具: 不走 SQL 的"验尸刀"（15 章展开）。
13. **CONNECT RESET** — 连接复位: 脚本内断开当前连接的惯用句。

## 最新演进与工业实践

- **GUI 大退役**：Control Center/Health Center/Command Editor 等 9.x 图形件在 Db2 10.1/11.x 时代陆续退出官方支持面；现行管理入口=db2 CLP + 云控制台 + IBM Data Server Manager（其后又演进）等新一代 Web 工具（⚠️ 换代细节以官方文档为准，入口 https://www.ibm.com/docs/en/db2 ，curl 200 ✅）。
- **CLP 长存**：命令行正门地位未变，Db2 11.5 仍是 db2 命令+SQL 双模；新增云托管场景下多经 REST/CLI 包装（⚠️）。
- **第三方 GUI 生态**：DBeaver/DataGrip 等通用 SQL IDE 成为多数团队的"新控制中心"——本书"GUI 是教学机、CLI 是真相之源"的方法论反而更成立。
- **调度补课**：原书"OS cron 凑合"的现状被 Airflow/dbt 类编排工具替代，跨书对照可读 [../Unlocking_dbt/00-总览与阅读地图.md](../Unlocking_dbt/00-总览与阅读地图.md)（盘上已有，工具世界观对位）。
