## 本章地图

本章是全书的**收束章**：前面讲了 Paxos/Raft/ZAB 怎么「做对」，本章讲**为什么它们都不可能「既永远安全、又一定终止」**。

```
FLP（Fischer, Lynch, Paterson, JACM 1985）：
在异步系统中，即使只有一个进程可能崩溃（fail-stop），
也不存在「确定性」的共识算法能同时保证 安全性 + 终止性。
```

- **10.1.2 环境模型**：把假设列清楚——结论的强度完全来自这些假设；
- **10.1.3 Paxos 为什么是正确的**：Paxos 的安全性**不依赖任何时序假设**，只有活性依赖——这正是「FLP 说不可能，Paxos 却是对的」的答案；
- **10.2**：证明骨架（配置 / 事件 / 价性 / 三个引理 / 构造无限不决定的运行）；
- **10.3**：指导意义——既然无解，工程上到底绕开了哪一条假设。

## 核心精讲

### 10.1.2 FLP 的环境模型（假设清单）

| 假设 | 内容 | 放松它会怎样 |
| --- | --- | --- |
| **异步（asynchronous）** | 无共享时钟、无时钟漂移上界、**处理与消息延迟无上界** | 放松 → 部分同步（Dwork/Lynch/Stockmeyer, JACM 1988）下可解 |
| **消息可靠** | 消息最终必达，可乱序、可任意延迟，但**不丢失、不重复、不伪造** | 这条是「加强」假设：即使消息可靠都无解，那消息不可靠更无解 |
| **故障模型** | 进程只能**崩溃停止（fail-stop）**，不作恶 | 拜占庭故障只会更难 |
| **故障数量** | **最多 1 个**进程故障 | 只容 1 个故障都无解，容 $f$ 个更无解 |
| **算法性质** | **确定性**（不含随机化） | 放松 → 随机化共识（Ben-Or 1983、Rabin 1983）可「以概率 1 终止」 |

> **结论的强度来自假设的强度**：FLP 是在「消息可靠、只容 1 个崩溃故障」这个**很宽松**的条件下证明「仍无解」，所以它是一条非常强的不可能结论。

### 10.1.3 Paxos 为什么是正确的（本章最该读懂的一节）

FLP 说「不可能」，Paxos 却被公认为正确——两者不矛盾，因为**它们要求的性质不同**：

| 性质 | FLP 要求 | Paxos 保证 |
| --- | --- | --- |
| **Agreement（一致性）** | 要求 | ✅ 保证，且**不依赖任何时序假设** |
| **Validity（有效性）** | 要求 | ✅ 保证 |
| **Termination（终止性）** | 要求 | ❌ **不保证**（活锁时永远无法决定） |

**关键认识**：
- Paxos 的安全性是**无条件**的：无论消息延迟多久、多少个 proposer 抢号、多少次换主，都不会选出两个不同的值；
- Paxos 的活性是**有条件**的：需要一个「最终稳定的 Leader + 最终及时的网络」（即**部分同步**）。当这个条件不满足时，它就表现为活锁——**这正是 FLP 所预言的**。

### 10.2.1 基础定义

| 概念 | 定义 |
| --- | --- |
| **Configuration（配置）** $C$ | 全局状态快照：所有进程的本地状态 + 所有在途消息 |
| **Event/Step（事件/步）** $e = (p, m)$ | 进程 $p$ 收到消息 $m$ 后：更新本地状态 + 发送若干消息 |
| **Schedule / Run** | 一串可应用的事件 |
| **Decision value** | 某个进程在该配置之后能决定的值 |
| **0-valent / 1-valent** | 从该配置出发**只能**决定 0 / 只能决定 1（**univalent**） |
| **Bivalent（二价）** | 从该配置出发**两种决定都可能**（结果未定） |

### 10.2.2 完全正确（Total Correctness）

FLP 定义的「正确求解共识」包含两部分，缺一不可：

1. **安全性（Safety / Partial Correctness）**：无两个进程决定不同的值；被决定的值必是某个进程提议过的（agreement + validity + non-triviality）；
2. **活性（Liveness / Termination）**：**每个**正确进程**最终**都要决定。

FLP 的定理说：**不存在同时满足这两者的确定性算法**。

### 10.2.3–10.2.5 三个引理

> ⚠️ 二手材料对三个引理的编号口径不一。下面采用与 FLP 原论文对应的映射（可对照 Constable 一派「构造版 FLP」的说明：其 Initialization Lemma 对应原文 Lemma 2、One Step Lemma 对应 Lemma 3、Commutativity Lemma 对应 Lemma 1）。**本书 10.2.3–10.2.5 的具体编号与内容未能核实原文，存疑。**

- **引理 1（可交换性 / Commutativity）**：若两个事件 $e=(p,m)$、$e'=(q,m')$ 作用**在不同进程**上（$p \ne q$），且都可在配置 $C$ 上应用，则
  $e'(e(C)) = e(e'(C))$。
  - 直觉：进程是确定性的，只看自己的本地状态和收到的消息；两个不同进程的收消息顺序互换不影响结果。

- **引理 2（存在二价的初始配置 / Initial Bivalency）**：任何「能容忍 1 个崩溃故障地求解共识」的确定性算法，**必然存在一个二价的初始配置**。
  - 直觉（反证）：假设所有初始配置都是 univalent。把 $2^n$ 个初始配置按「每次只翻转一个进程的输入」排成格雷码序列；全 0 输入必须决定 0、全 1 输入必须决定 1，于是序列中**必有一对相邻配置**一个是 0-valent、一个是 1-valent。让「这两个配置唯一不同的那个进程」崩溃并保持静默——两个配置在其余进程看来完全一致，于是它们的后续运行也完全一致，决定值必须相同，矛盾。

- **引理 3（Pumping / One-Step）**：若 $C$ 是二价配置，$e$ 是可在 $C$ 上应用的事件，则**一定存在一个二价配置，它可通过「把 $e$ 放到最后才应用」到达**。
  - 构造：设 $\mathcal{C}$ 为从 $C$ 出发**不应用 $e$** 可达的配置集合，$\mathcal{D} = \{e(C') \mid C' \in \mathcal{C}\}$。断言 $\mathcal{D}$ 中必有二价配置。
  - 反证：假设 $\mathcal{D}$ 全是 univalent。因为 $C$ 二价，$\mathcal{D}$ 中既有 0-valent 也有 1-valent（否则 $C$ 就不二价了）。于是存在相邻的 $C_0, C_1 \in \mathcal{C}$（$C_1 = e'(C_0)$，且 $C_0$ 应用 $e$ 后为 0-valent、$C_1$ 应用 $e$ 后为 1-valent）。分两种情形：
    - 若 $e'$ 与 $e$ 作用在**不同进程** → 由引理 1 可交换 → $e(e'(C_0)) = e'(e(C_0))$，两者 valency 应相同，矛盾；
    - 若 $e'$ 与 $e$ 作用在**同一进程** → 可让该进程崩溃（FLP 允许 1 个故障），此时 $e$ 与 $e'$ 都无法区分，同样推出矛盾。

### 10.2.6 证明：构造一条永不决定的运行

```text
// 教学示意：FLP 的「对手调度」（不参与构建、不编译、不运行）
C = 引理2 给出的二价初始配置
loop:
    e = 当前可应用、「等待最久」的那个事件          // 一个公平的选择规则
    按引理3，找到一条路径使得「e 最后才被应用」且结果仍是二价
    走完这条路径（可能为空），应用 e，得到新的二价配置 C
    // 每一步系统都「还能决定 0、也还能决定 1」→ 永远不决定
```

由于每一步之后配置仍是二价的（结果未定），而消息又必须最终被投递（模型要求每个可应用事件最终会被调度），这条**无限长的运行**满足「所有消息都被投递、没有进程非法行为」，却**永远没有进程决定** → 违反终止性 → 定理得证。

**证明的三个直觉要点**（帮助记忆）：

1. **二价性是可以一直保持的**（引理 3）：只要还有事件没被应用，对手就能挑一个「让它最后发生」的顺序，使结果仍未定；
2. **随机化之所以能绕开**，正是因为对手**不能预知**随机选择——它无法再构造出那条「永远推迟决定事件」的调度；
3. **部分同步之所以能绕开**，是因为在某个时刻之后网络变快，对手失去了「无限延迟某条消息」的能力。

> 这三条也解释了为什么工程系统几乎都采用「**超时（部分同步）+ 随机化**」的组合：前者让「无限延迟」不再可能，后者让「可预测的调度攻击」失效。

## 版本演进

- **1983**：Ben-Or 的《Another Advantage of Free Choice》与 Rabin 的《Randomized Byzantine Generals》给出**随机化**绕行方案（以概率 1 终止）；
- **1985**：FLP 发表（JACM），给异步共识「判了死刑」；
- **1988**：Dwork、Lynch、Stockmeyer《Consensus in the Presence of Partial Synchrony》（JACM）给出**部分同步**模型——「存在未知的时间上界 GST（全局稳定时刻）后网络及时」，在该模型下共识可解；这是所有工程系统的理论基础；
- **1996**：Chandra & Toueg（JACM）给出**故障检测器**视角：◊W（最终弱检测器）是解共识的最弱类别；异步系统里不存在这样的检测器（等价于 FLP）；
- **1998–2014**：Paxos 与 Raft 都是在「部分同步 + 超时 + 随机化」框架下工作的具体实现；
- **2021–2025**：研究前沿转向**更精细的下界**（如 PODC 2025 的《Revisiting Lower Bounds for Two-Step Consensus》讨论两步共识所需进程数），而不是「能不能解」；
- **2023（本书）**：把 FLP 作为「番外篇」收束全书，是很好的编排——它让读者在学完所有算法后回过头理解「这些算法各自放弃了什么」；
- **2026 视角**：FLP 早已不是「坏消息」，而是**设计清单**：每一个生产共识系统都能明确指出它放松了哪一条假设（通常是「部分同步」+「随机化」+「超时」）。

## 近年研究与工业界开源实践（2015–2026）

> star 数均为 2026-09 用 `gh api repos/OWNER/REPO --jq '.stargazers_count'` 实测。

- **FLP 在 2026 年的工程含义**：它不再阻止任何人写共识系统，而是规定了「**必须明确列出时序假设**」。所有主流实现都在这条线上：

| 系统 / 库 | star | 它放松了 FLP 的哪一条 |
| --- | --- | --- |
| `etcd-io/etcd`（含 `etcd-io/raft`，1,128★） | 52,310★ | 部分同步（超时）+ 随机化选举超时 |
| `hashicorp/raft` | 9,136★ | 同上 |
| `sofastack/sofa-jraft` | 3,824★ | 同上（含 PreVote 抑制被隔离节点的扰动） |
| `Tencent/phxpaxos` | 3,379★ | 同上（基于 Paxos 的 Master 选举 + 租约） |
| `apache/zookeeper` | 12,811★ | 同上（ZAB 的 epoch + session/心跳超时） |
| `tikv/tikv` / `cockroachdb/cockroach` | 16,878★ / 32,508★ | 同上 + **分组调度**（把故障域缩小到一个组） |

- **随机化在工程里的具体形态**：Raft 的**随机化选举超时**（论文示例 150–300ms）就是 Ben-Or/Rabin 一脉思想的工程版本——它把「两个节点同时超时导致选票瓜分」的概率压到极低，从而**以概率 1 终止**，正好对应 FLP 的绕行路径之一。
- **近年来研究**：
  - **下界研究精细化**：从「能不能解」转向「要用多少进程/多少步才能解」（如 PODC 2025 的两步共识下界重估）；
  - **故障检测器工程化**：PreVote / CheckQuorum / 租约，本质上都是在实现一个「足够好」的（不完美的）故障检测器——FLP 说它不可能完美，工程上就接受「会误判但有界」；
  - **形式化验证**：共识实现普遍引入 TLA+ 规格与模型检查，把「安全性无条件、活性有条件」这条界线写成可检验的定理。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「FLP 说分布式共识不可能」 | FLP 说的是：**异步 + 确定性 + 容 1 崩溃故障**下，不存在**同时**满足安全性与终止性的算法。放松任一条假设即可解 |
| 2 | 「Paxos/Raft 推翻了 FLP」 | 它们**放松了「异步」假设**（采用部分同步 + 超时），并引入**随机化**；安全性仍无条件，活性有条件——完全符合 FLP |
| 3 | 「FLP 假设消息会丢」 | 恰好相反：FLP 假设消息**可靠**（最终必达）。这让结论更强：最宽松的条件下仍无解 |
| 4 | 「FLP 只考虑了 1 个节点故障，所以对 3 副本没意义」 | 只容 1 个故障就无解 ⇒ 容 $f$ 个故障更无解；1 是最宽松的情形 |
| 5 | 「随机化能『解决』FLP」 | 随机化让**终止概率为 1**（几乎必然终止），但仍有测度为 0 的不终止执行；工程上够用，理论上仍不违反 FLP |
| 6 | 🔧 本书未把「部分同步」作为绕行主线讲透 | 补：**Dwork/Lynch/Stockmeyer（JACM 1988）的部分同步模型**是所有生产共识系统的理论基础——存在一个未知但存在的「全局稳定时刻 GST」，之后网络延迟有界。工程上的「超时」就是对 GST 的具体假设。**这一节应作为 10.3 的核心** |
| 7 | 🔧 本书未把「故障检测器」视角纳入 | 补：Chandra & Toueg（JACM 1996）证明 ◊W（最终弱检测器）是解共识的最弱检测器类别；异步系统中不存在这样的检测器（FLP 的等价表述）。工程上的心跳/租约/PreVote 都是在实现一个**不完美但有界**的检测器——FLP 说明它不可能完美 |
| 8 | 🔧 本书未指出「Raft 的随机化选举超时」就是 FLP 绕行手段 | 补：Raft 的随机化超时（论文示例 150–300ms）正是 Ben-Or/Rabin 一脉随机化思想的实现——把选票瓜分的概率压到极低，使系统「以概率 1」推进。这一条把本章与 [07-Raft.md](07-Raft.md) 直接连起来 |
| 9 | 🔧 本书未给出 FLP 之后的现代研究坐标 | 补：2020 年代的研究已不再问「能不能解」，而是问「**多少进程、几步能解**」（如 PODC 2025《Revisiting Lower Bounds for Two-Step Consensus》重新审视两步共识下界）。这提示读者：FLP 是起点，不是终点 |
