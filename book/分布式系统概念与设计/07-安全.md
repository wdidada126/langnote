## 核心精讲（教学示意，不参与构建）

### 11.1 密码学基础
- **对称加密**：加解密同钥（DES/AES 一脉）；快，但密钥分发难——这直接引出
  Needham-Schroeder 与 Kerberos。
- **非对称加密（公钥）**：公钥加密、私钥解密（RSA/椭圆曲线）；慢，但天然解决密钥分发。
- **摘要函数（secure hash）**：MD5（已破）、SHA-1（已弃）、SHA-2/SHA-3（现行）；
  性质：单向、抗碰撞。摘要本身不保密——必须与密钥结合（HMAC）或作为签名输入。
- **椭圆曲线概要**（摘录关键词）：同等安全强度下密钥更短（256 位 EC ≈ 3072 位 RSA），
  计算量小，适合资源受限设备——TLS 1.3 握手默认曲线即 EC 一族。

### 11.2 数字签名与证书
- **签名 = 用私钥对摘要运算**；验签 = 用公钥验证。提供完整性 + 不可否认性；
  对称方案的等价物是 MAC（HMAC），提供完整性 + 认证但不提供不可否认。
- **证书与 PKI**：公钥的真实性由 CA 签名保证；证书链、根信任、吊销（CRL/OCSP）。
- 🔧 混合加密才是实际形态：非对称协商会话密钥 + 对称加密传输数据——TLS 即此结构。

### 11.3 Needham-Schroeder 协议
- 目标：在不可信网络上，借助可信第三方（认证服务器）让两方建立共享会话密钥。
- 对称密钥版骨架（原书第 11 章经典流程，教学示意）：
  1. A → AS：A、B、随机数 Na（「我要和 B 通话」）；
  2. AS → A：{Na, B, Kab, {Kab, A}密钥B}密钥A（票证转发给 B）；
  3. A → B：{Kab, A}密钥B；
  4. B → A：{Nb}Kab；A → B：{Nb-1}Kab（B 确认 A 持钥，防重放的质询-响应）。
- **经典缺陷**（Denning & Sacco, 1981）：第 2 步的票证无时间戳/有效期，旧票证被重放后
  攻击者可持旧 Kab 冒充——**用时间戳修复**，Kerberos 即此修复版。
- 公钥版（NSL）则通过在质询中携带双方身份标识修复中间人攻击，成为认证协议
  形式化验证的标准测试用例（摘录「形式化描述语言」指此传统；BAN 逻辑、ProVerif/Tamarin
  均以此类协议为标的，TLS 1.3 的 Tamarin 形式化验证是同一传统的当代成果）。

### 11.4 案例：Kerberos
- 三个角色：认证服务器 AS（管主密钥）+ 票据授予服务器 TGS + 客户与服务器；
  **票证（ticket）+ 会话密钥**是基本货币。
- 登录后：AS 发放 TGT（用用户主密钥加密）；访问服务时以 TGT 换服务票证；
  时间戳（时钟偏移容忍，通常 5 分钟）防重放——**Kerberos 假设同步时钟**，
  这是第 2 章「同步系统假设」在安全协议中的真实用例。
- 现状：Windows AD 域的核心协议；`krb5/krb5`（604★，2026-09 `gh api` 实测）为 MIT 参考实现。

### 11.5 案例：TLS（原书按 SSL/TLS 1.2 口径讲授）
- 结构：**握手协议**（协商套件、认证、密钥交换）+ **记录协议**（对称加密、完整性、分帧）；
  经典握手 = 证书链验证 → RSA/（EC）DHE 密钥交换 → 双方导出会话密钥。
- 🔧 **TLS 1.3（RFC 8446, 2018）要点，原书未及**：
  - 握手 1-RTT（可 0-RTT 恢复，但有重放风险）；
  - 删除全部静态 RSA 密钥交换与前向不安全套件，仅保留 (EC)DHE 前向安全；
  - 密钥推导重写为 HKDF；握手同时加密；
  - 摘录者「对 TLS1.3 协议形式化描述」的批注即其 Tamarin/ProVerif 机器检查证明。
- 证书生态：Let's Encrypt 普及免费证书、证书透明度（CT 日志）。

### 11.6 访问控制（ACL 与权能）
- **保护域**（第 6 章呼应）：（对象，权力）集合；分布式系统的两种实现（摘录原文口径）：
  - **访问控制列表 ACL**：按对象存「谁能做什么」——DNS/文件系统/云 IAM 的模式；
  - **权能（capability）**：按主体持「不可伪造的引用即权力」——Kerberos 票证、
    令牌（JWT）皆是其现代变体；权能可传递但难吊销，ACL 好吊销但中心化。
- 安全的工程常态：**认证（你是谁）→ 授权（你能做什么）→ 审计（你做了什么）**三段链。

### 11.7 工作例题：Kerberos 登录到访问服务的完整时序（教学重述）
1. 客户端登录：口令 → 派生用户主密钥 Kc（口令不网上传输）；
2. AS → C：{TGT, 会话密钥 Kc,tgs}Kc，其中 TGT = {Kc,tgs, C, 地址, 有效期}Ktgs；
3. 访问服务 S：C → TGS：TGT + {时间戳}Kc,tgs → 得到服务票据
   {Kc,s, C, 有效期}Ks + Kc,s；
4. C → S：票据 + 认证符 {C, 时间戳}Kc,s；S 校验时间戳偏移 ≤ 5 分钟即放行，
   并可缓存认证符拒绝重放。
- 教学要点：**两次「会话密钥 + 时间戳」的复用**（对 TGS、对服务）；票证用服务密钥加密所以
  客户端不可篡改；弱点也来自时间戳——**依赖同步时钟**与 5 分钟重放窗口（ Kerberos 后来引入
  可重放缓存弥补）。
- 🔧 与 JWT 映射：TGT ≈ refresh token（长有效、只对 AS 有效），服务票据 ≈ 短期 access
  token；认证符 ≈ 请求签名；差异在于 Kerberos 有状态（KDC 在线）而 JWT 无状态验证。

### 11.8 TLS 1.2 vs TLS 1.3 对照速查（🔧 原书未及，笔记补写）
| 维度 | TLS 1.2（原书口径） | TLS 1.3（RFC 8446） |
| --- | --- | --- |
| 握手往返 | 2-RTT | 1-RTT（恢复可 0-RTT） |
| 密钥交换 | RSA 静态传输 / (EC)DHE | 仅 (EC)DHE，前向安全 |
| 握手保密 | 明文证书 | 握手加密（证书保密） |
| 密钥推导 | PRF | HKDF（分阶段密钥 Schedule） |
| 套件数量 | 数十个 | 仅 5 个 AEAD 套件 |
- 教学要点：1.3 把「密码学选择」从运维配置问题变成协议强制——可选项越少越安全；
  0-RTT 的重放风险是其唯一新攻击面（幂等设计或禁用）。

### 11.9 访问控制矩阵与两种实现（原书框架重述）
- 逻辑模型：矩阵 M[主体, 对象] = 权力集合。
- **ACL**：按列存（对象挂权限表）——易回答「谁能读这个文件」、易吊销；DNS/文件系统/IAM 模式。
- **权能**：按行存（主体持票据）——易传递、无需查表即可验证；Kerberos/JWT/对象存储
  预签名 URL 模式。
- 分布式的关键差异：ACL 需要权威节点在线判定（中心化），权能可离线验签（去中心化）但
  **吊销难**——解法永远是「短有效期 + 续期」即租约。

- 🔧 2026 视角（本章需要整体增补）：
  1. **TLS 1.3 全面普及**，SSL/TLS1.0/1.1 已废弃；
  2. **零信任（Zero Trust）**：边界模型失效，默认不信任内网——「持续认证 + 最小权限 +
     每次访问验证」；对应原书 ACL/权能讨论需要重写；
  3. **mTLS**：服务网格内双向证书认证成为微服务默认；
  4. **JWT/OIDC**：权能思想的令牌化——无状态签名令牌（JWT）+ 授权框架
     （OAuth 2.0 / OpenID Connect）取代自建会话与票证体系；short-lived token 即「租约」。

## 近年研究与工业界开源实践（2015–2026）

- `openssl/openssl`（30841★，2026-09 `gh api` 实测）：TLS 的主导实现；TLS 1.3 于 1.1.1 支持。
- `krb5/krb5`（604★）：MIT Kerberos 参考实现，Windows AD/Kerberos 生态依旧庞大但
  新系统多改用 OIDC。
- **零信任与身份**：SPIFFE/SPIRE（工作负载身份证书短租约）、Istio/Linkerd 的 mTLS、
  云厂商 IAM（AWS STS 临时凭证 = 权能租约）。
- 🔧 判断：Kerberos 的「票据 + 时间戳」思想没有过时，只是载体从 KDC 迁到
  **JWT/OIDC + 短期令牌**；读原书时把「票证 ≈ 签名令牌、TGT ≈ refresh token」映射，豁然开朗。

### 11.10 威胁 → 协议映射总表（本章复习总纲）
| 威胁（第 2 章） | 本章回应机制 | 遗留风险 |
| --- | --- | --- |
| 窃听 | 加密（TLS 记录层） | 端点侧明文、弱套件配置 |
| 篡改 | MAC/HMAC、签名 | 碰撞攻击（MD5/SHA-1 已废） |
| 伪造身份 | 证书链、Kerberos 认证 | CA 被冒、密钥泄漏 |
| 重放 | 质询-响应、时间戳、序号 | 时钟依赖（Kerberos 5 分钟窗） |
| DoS | 冗余、过滤 | 资源放大攻击、SYN flood |
| 移动代码 | 沙箱、代码签名 | 供应链攻击（当代新增形态） |
- 读法：每行左边是「第 2 章安全模型的账」，中间是「第 11 章的还法」，右边是「还完还欠的」——
  安全设计是持续欠账管理，不是一次结清。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「加密就能保证安全」 | 加密只解决机密性；认证、完整性、可用性需各自机制（签名/审计/冗余） |
| 2 | 「摘要函数可以当加密用」 | 摘要是单向的，不是加密；带密钥的 MAC/HMAC 才有认证含义 |
| 3 | 「内网是可信的」 | 零信任视角下的错误默认；横向移动（lateral movement）正是利用该假设——原书写作年代的内网假设需显式修正 |
| 4 | 「TLS 1.2 仍是推荐版本」 | 2026 年应默认 TLS 1.3；静态 RSA 交换与 CBC 套件均已废弃 |
| 5 | 「权能不可伪造所以绝对安全」 | 权能难吊销、可被泄露转发；实践中靠短租约 + 撤销列表折中 |
| 6 | 🔧 本书未覆盖 | TLS 1.3、零信任、mTLS、JWT/OIDC、证书透明度、后量子密码（NIST 标准化进行中） |
| 7 | 🔧 版次注记 | 英文原版第 5 版无本章；本章内容框架承自第 4 版，中译第 5 版恢复为第 11 章——检索英文目录时勿按「第 11 章」找 Security |
