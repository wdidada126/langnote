# 第 3 章 网络和网际互连

> **覆盖原书**：中译第 5 版第 3 章「网络和网际互连」。
> **本章地图**：网络类型与性能指标（延迟/带宽/抖动）→ LAN/WAN/互连网络 → 以太网与
> 无线局域网（802.11）→ 网际互连：IP 协议栈（IPv4/IPv6、IP 路由、ICMP）→ 传输层端到端
> （TCP/UDP 概述，细节归第 4 章）→ 域名与 DNS 概述 → 移动 IP → 服务质量（QoS）。

## 本章地图

- 原书立论：底层网络的**性能、可靠性、可伸缩性、移动性、服务质量**五类特征直接决定上层
  分布式系统的行为——第 2 章交互模型中的「延迟带宽抖动」在这里落到实处。
- 本章是全书唯一的「网络物理课」：从以太网帧到 IP 分组到 TCP 流的完整封装路径，
  为第 4 章（进程间通信）准备协议语境。
- 大纲摘录中的「cdn」「dns」两条关键词落在本章的域名系统与 Web 基础设施讨论中。

## 核心精讲（教学示意，不参与构建）

### 3.1 网络类型与性能
- PAN/LAN/WAN/互联网（internetwork）的量级划分：带宽从 Mbps 到 Gbps，延迟从纳秒（同机）到
  毫秒（洲际）到秒级重传（广域故障）。
- **性能三指标**：延迟（latency：往返时间 RTT）、带宽（单位时间数据量）、抖动（jitter：
  延迟的方差，多媒体系统第 20 章的关键指标）。
- **数据流（data streaming）**：多媒体通信需要保持带宽的同时控制延迟变化——QoS 问题的由来。

### 3.2 局域网与无线
- **以太网**：原书按 CSMA/CD（载波侦听多路访问/冲突检测）版本讲授；交换式以太网
  （每个端口一个冲突域）已是默认形态，原版总线式 10BASE5 只作历史。
- **802.11 无线局域网**：共享无线介质，CSMA/CA；安全机制（WEP 的失败到 WPA2/WPA3）在
  第 11 章呼应（大纲摘录「802.11 wifi」即此）。
- 🔧 以今天的知识修正：CSMA/CD 在全双工交换以太网中**已名存实亡**；数据中心已转向
  RDMA（RoCE）以获得微秒级延迟与低 CPU 开销——这是原书未及的重大演变。

### 3.3 网际互连：IP 层
- 互连网络（internet）的关键抽象：**统一的数据报格式 + 统一编址 + 路由**，
  把异构的底层网络（以太网、无线、点对点链路）拼成一个网络。
- **IPv4 分组结构**：地址 32 位、TTL 防环、分片与重组；**IPv6**：128 位地址、简化报头、
  取消分片（源端路径 MTU 发现）。
- **IP 路由**：默认路由器/网关、RIP（距离向量）与 OSPF（链路状态）；**ICMP** 提供差错与
  诊断（ping/traceroute）。
- **TCP/UDP 概述**：UDP 提供不可靠数据报（开销最小），TCP 提供可靠字节流（确认、重传、
  流控、拥塞控制）；完整语义在第 4 章。
- **防火墙与 NAT**：内网私有地址 + NAT 端口转换成为互联网事实架构，对 P2P（第 10 章）
  造成打洞难题。

### 3.4 域名与移动性
- **DNS**（域名系统）：分层命名空间与分布式解析（大纲摘录「dns」）；权威服务器、递归解析器、
  缓存与 TTL——原书第 13 章专讲。
- **移动 IP**：家乡地址/转变地址 + 家乡代理转发，解决主机移动后可达性；与 DHCP（动态
  主机配置）共同构成接入层机制。
- 🔧 CDN（大纲摘录「cdn」）：原书只在可伸缩性讨论中提及内容分发；今天 CDN（边缘缓存 +
  Anycast + TLS 终结在边缘）承载了 Web 的大部分流量，是「IP 之上、应用之下」的隐藏层。

### 3.6 工作例题：一次跨网请求的完整旅程（教学重述）
以浏览器请求 `https://example.com/page.html` 为线，把本章知识点串成一条路径：
1. **DNS 解析**（3.4）：查本地缓存 → 递归解析器 → 根/顶级域/权威服务器，得到 IP；
   摘录关键词「dns」即此环节，第 13 章（后半目录）展开分层命名；
2. **路由选路**（3.3）：默认网关 → OSPF 域内 → BGP 域间（原书以 RIP/OSPF 为主，BGP 简述），
   每一跳 TTL 减 1，ICMP 差错可能反馈「不可达/超时」；
3. **链路传输**（3.2）：以太网帧（APR 解析 MAC）或 802.11 无线帧（CSMA/CA）；
4. **端到端传输**（3.3/3.5）：TCP 三次握手（或 QUIC 1-RTT，🔧 见下）→ TLS 握手 →
   HTTP 请求；拥塞窗口从慢启动爬升；
5. **中间设施**：NAT 改写四元组、防火墙过滤、CDN 可能直接在边缘终结（摘录关键词「cdn」）。
- 读法：每一步都对应一个「原书小节 + 可能失败的环节」——DNS 失败、路由黑洞、无线丢包、
  拥塞重传、NAT 超时。第 2 章交互模型的「延迟/带宽/抖动」在此获得具体出处。

### 3.7 拥塞控制速览（3.3 的深化）
- 经典 TCP Reno：慢启动（指数增）→ 拥塞避免（AIMD 线性增）→ 丢包触发（快速重传/恢复）；
  核心假设：**丢包 ≈ 拥塞**。
- 🔧 现代修正：无线与长肥管道中丢包常非拥塞所致——BBR 类算法改用**带宽与 RTT 测量**
  建模瓶颈；数据中心内则以 DCTCP/ECN 显式拥塞通知替代丢包推断。
- 与第 4 章衔接：QUIC 在 UDP 上自建拥塞控制，可按连接粒度换算法，内核无需升级——
  这是「传输层功能上移到用户态」的完整论证。

### 3.5 服务质量（QoS）
- 参数化：带宽、延迟、抖动、丢失率；IntServ（RSVP 逐流预留）vs DiffServ（按类标记）。
- 🔧 现实修正：IntServ/DiffServ 未曾在公网普及；**QoS 事实标准退化为「端点自治」**——
  应用层自适应码率（视频）、QUIC 的丢包恢复、CDN 就近接入。教科书 QoS 只在专线/5G 网络切片存活。

### 3.8 IPv4 vs IPv6 报头速查（3.3 的补充）
| 维度 | IPv4（20 字节起，可变长） | IPv6（固定 40 字节） |
| --- | --- | --- |
| 地址 | 32 位点分十进制 | 128 位冒分十六进制 |
| 分片 | 路由器可分片（效率差） | 仅源端分片（PMTU 发现） |
| 校验和 | 有（每跳重算） | 取消（靠链路层/传输层） |
| 选项 | 报头内嵌 | 扩展头链 |
| 广播 | 有 | 无（改用组播/anycast） |
- 教学要点：IPv6 的每个「删除」都是为了让路由器转发路径更短——可伸缩性来自**做减法**；
  这与第 1 章「可伸缩性四子问题」直接对应。

### 3.9 移动性与接入机制速查（3.4 深化）
- **DHCP**：新主机加入 → 广播请求 → DHCP 服务器分配 IP/网关/DNS，租约续期；
- **移动 IP**：家乡地址不变（可达性标识）+ 转变地址（位置标识）+ 家乡代理隧道转发；
  「身份与位置分离」的思想后来演化为 HIP/LISP 等研究路线与 5G 的会话管理。
- 🔧 现代补全：原书未及的 Wi-Fi 漫游、蜂窝切换（handover）下的 TCP 连接存活问题——
  QUIC 的连接迁移（连接 ID 与四元组解耦）正是对该问题的当代回答（见 04 文件 🔧 节）。

- 第 3 版 → 第 5 版：主干稳定；第 5 版加强了 **IPv6、802.11、移动 IP** 的篇幅，
  反映 2005–2012 年无线接入的普及；以太网部分从共享介质全面改写为交换式。
- 🔧 2026 视角的重大缺口（原书成书时未发生或未成熟）：
  1. **QUIC/HTTP3**：传输层在 UDP 上重建（可靠、有序、多路复用、0-RTT），绕开内核 TCP 栈，
     TCP 队头阻塞问题在应用层解决；
  2. **io_uring**：Linux 异步 I/O 接口，把「进程-内核」交互从系统调用改为共享环，
     高并发网络服务的事件循环被重新设计；
  3. **eBPF**：内核可编程包处理（XDP/TC），防火墙、负载均衡（如 Katran）、可观测性
     在内核态完成，网络栈从「固定协议分层」走向「可编程数据平面」。

## 近年研究与工业界开源实践（2015–2026）

- **QUIC 与 HTTP/3**：IETF RFC 9000（2021）定稿；主流浏览器与大型站点默认启用。
  开源实现：`cloudflare/quiche`（12609★，2026-09 `gh api` 实测，Rust 实现，支撑 Cloudflare
  边缘网络）；`nginx/nginx`（31731★）已合入 HTTP/3 模块。
- **内核网络栈改造**：`torvalds/linux`（250162★）主线中的 io_uring（5.1 起）与 eBPF
  （XDP/TC 钩子）重构了「进程 ↔ 网卡」的数据通路；Cilium 等项目用 eBPF 替代 iptables
  做服务网格数据面。
- 🔧 值得对读的工程判断：QUIC 把第 4 章要讲的「可靠流 vs 不可报文」选择权重新交还应用；
  eBPF 则模糊了原书「操作系统支持（第 7 章）」与「网络（第 3 章）」的边界——可编程性
  成为两者的公共语言。

### 3.10 互连设备速查：谁工作在哪一层（教学重述）
| 设备 | 工作层次 | 决策依据 | 隔离什么 |
| --- | --- | --- | --- |
| 中继器/Hub | 物理层 | 无（电信号复制） | 无（同一冲突域） |
| 交换机 | 链路层 | MAC 地址表 | 冲突域（不隔离广播域） |
| 路由器 | 网络层 | IP 路由表 | 广播域（= 故障域边界） |
| NAT 网关 | 网络层+传输层 | 五元组映射 | 私有地址空间 |
| 应用网关/防火墙 | 传输层–应用层 | 端口/协议/内容 | 策略域 |
- 教学要点：**每上一层，决策信息越丰富、转发越慢、可控性越强**——负载均衡从四层（LVS）
  走向七层（Nginx/Envoy）正是这条规律的工程化；而 eBPF/XDP 又把七层决策下压到驱动层，
  规律被「可编程性」打破，见 🔧 节。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「以太网靠 CSMA/CD 避免冲突」 | 交换全双工后无冲突域；CSMA/CD 只活在历史题里 |
| 2 | 「TCP 慢是因为协议本身」 | 多为拥塞控制策略与丢包把丢包当拥塞的假设；长肥管道（LFN）问题另有 BBR 类算法缓解 |
| 3 | 「QoS 靠网络层标记 DSCP 就能保证」 | 公网不兑现逐流预留；端到端 QoS 实际由应用自适应 + CDN + 协议改进（QUIC）组合实现 |
| 4 | 「NAT 是临时方案」 | IPv4 NAT 已成永久基础设施；IPv6 部署缓慢，P2P 打洞（STUN/TURN/ICE）因此成为必备技能 |
| 5 | 🔧 本书未覆盖 | QUIC/HTTP3、io_uring、eBPF/XDP、RDMA（数据中心低延迟互连）、5G 网络切片 |
| 6 | 🔧 大纲摘录遗留 | 「atm网络 -ip」：ATM（异步传输模式）作为 WAN 底层在本版已被 MPLS/以太网替代性叙述边缘化，仅存历史地位 |
| 7 | 「路由器是网络层设备所以不管应用」 | CDN/Anycast/ECMP 把应用语义（地域、健康度）写进了路由决策；「分层互不越界」在工程上从来是软约束 |
| 8 | 「IPv6 只是地址更长」 | 还取消了路由器分片（源端 PMTU 发现）、简化定长报头、取消校验和重算——可伸缩性收益主要来自转发路径变简 |
