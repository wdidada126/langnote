## 三条阅读主线

1. **隐藏与兼容线（全书脊柱）**：`02` → `07` → `08` → `09` → `11`。
   Pimpl/句柄隐藏布局 → 符号导出控制链接面 → 内联/暴露容器欠的性能-兼容债 → 版本策略与符号版本化 → 插件 ABI 期末考。
2. **接口形状线（设计决策）**：`01` → `05` → `06` → `03`/`04`。
   特征清单 → 流程与错误处理 → 风格四选一 → 具体模式落地。
3. **可信度线（工程配套）**：`05`（契约）→ `10`（文档/测试）→ `11`（跨界回归）。

**最短上手路径**（要给别人设计一个库的人）：`01` → `05` → `02` → `06` → `09`。
**只关心 ABI/发布工程的人**：`02` → `07` → `09` → `11`。

## 本书定位（为什么 2013 年的书还要读、要怎么读）

本书是 **2013 年前后「C++ API 设计」领域的奠基书之一**：它第一次把散落在组件工程、
库维护与 COM/跨语言实践里的经验，整理成以「接口即契约」为中心的可教体系——
Pimpl/不透明指针、符号导出、兼容性分级、弃用流程、插件 ABI、脚本绑定这些今天的常识话题，
它都有专节成文。但成书于 C++03/C++11 过渡期：**移动语义、智能指针定型、constexpr/concepts/
modules、std::expected、[[nodiscard]]、符号版本化工具链、WASM 绑定**全部发生在它身后——
所以本目录每章的「最新演进与工业实践」不是装饰，而是**把书的结论重新放回 2026 年的工具链与
开源惯例（LLVM/abseil/folly/Qt/GSL/doctest/cpp-httplib…）中复验**。两者叠加才是当代可用的 API 设计知识。
同工程互补：物理设计看 [../大规模c++程序设计.md](../大规模c++程序设计.md)（Lakos），
语言级写法看 [../Effective_Modern_C++.md](../Effective_Modern_C++.md)。
