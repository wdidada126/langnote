## 核心概念速览（中英对照）

- **命名空间** — namespace：库级名字容器；API 语境的职责是「防污染」——只进一个具名空间，别 using 进全局。
- **编译器生成函数** — implicitly-declared special members：默认构造/拷贝/移动/析构由编译器代笔；API 设计者必须逐函数「准笔或拒笔」（6.2.1 即 Rule of 0/3/5 前身）。
- **explicit**：单参构造与转换操作符的「不许暗渡」开关——杜绝 `f(3)` 悄悄构造 `Complex(3)` 一族的隐式转换事故。
- **const 正确性** — const correctness：方法级（这个操作不改对象）/参数级（这个承诺只读）/返回值级（别把内部可变性送出去）三层。
- **逻辑 const** — logical constancy：`mutable` 缓存/引用计数在「值不变」意义下仍 const——const 契约表达的是**观察等价**而非比特不变。
- **隐式实例化** — implicit instantiation：模板代码在使用点由用户 TU 生成——「头文件即 ABI」的根源（6.4.2）。
- **显式实例化** — explicit instantiation：库侧为固定类型集生成代码 + `extern template` 抑制用户侧重复——模板风格与二进制分发的折中（6.4.3）。
- **操作符重载** — operator overloading：语法糖的契约面——`==` 必须等价语义等价、转换符隐式触发、重载不进全局命名空间滥用（6.5 诸节）。
- **NULL 哨兵参数** — null sentinel parameter：指针参数「可空=可选」语义；引用则承诺非空——6.6.1 的选型标准。
- **默认参数** — default argument：写在头文件里的**调用方补丁**；库升级改默认值即 ABI/源码双震（6.6.2 反对理由）。
- **导出符号** — exported symbol：动态库对外可见的符号集合；默认导出一切是事故源，应当显式清单化（6.9）。
- **dllexport / visibility** — 导出/可见性机制：Windows `__declspec(dllexport)`、ELF `-fvisibility=hidden` + `__attribute__((visibility("default")))` 两条平行路线。

## 动机：语言特性即接口承诺

第 6 章的位置在全书很特别：它不讲模式讲语法，但每种语法都被翻译成**一句承诺**：
`const` 是「观察不变」承诺；`explicit` 是「不擅自造对象」承诺；默认参数是「此值随头文件发布，改即破坏」承诺；
导出符号是「这些名字我永久负责」承诺（09 章的弃用流程从这里领账单）。写 C++ 代码的每一笔都在签合约。

## 机制

### 1. 特殊成员函数逐笔表态（6.2）

```cpp
// 🔧 现代 Rule of 0 写法：成员自带语义，类不再手写五件套
class Document {
    std::string fName;                    // 可拷贝可移动
    std::unique_ptr<Impl> fImpl;          // 可移动不可拷贝 → 类自动同款
public:
    explicit Document(std::string name);  // explicit：禁"字符串即文档"的暗转换
};
```

书 6.2.2 的「深拷贝类要自己成套写」在 Pimpl/智能指针时代退化为「写对成员，类即对」。
剩余雷区：**基类析构非 virtual**（经基类指针 delete 即 UB）与**虚函数调用中的构造**——两处都属 ABI/行为契约而非常识。

### 2. const 三层与返回值决定（6.3）

```cpp
int  size() const;                 // 方法层：我不动对象
void open(const std::string& p);   // 参数层：我只读它
const std::vector<Page>& pages() const;   // 返回值层：只读视图——但!
pages_mut();                                // 想改就要另一个非 const 入口（或 span/迭代器）
```

返回值的三选一（6.3.3）：值（贵但安全）/ const 引用（便宜且禁改）/ 非 const 指针（能改、
内部可变性外泄——**每次调用返回同一对象内部，就把它公开进了 ABI**）。
C++17 起补了第四选项：`std::string_view`/`std::span` 只读视图（见「最新演进」）。

### 3. 模板进库的两条路（6.4）

```text
隐式实例化（6.4.2）：实现进头文件 → 用户编译器生成代码
   承诺 = 头文件即接口 + 实现，模板无法再"二进制兼容"（无 ABI 可言，只有源码兼容）
显式实例化（6.4.3）：库内 for {int,double,...} 生成 + extern template 声明
   承诺 = 类型清单是接口的一部分（"还支持别的类型吗"成为兼容性话题）
```

两条路间还有「接口部分进库、钩子留模板参」的混合形态——STL 容器（库外实现）与
现代 `std::format`（部分可 extern template）都是现实注脚 ⚠️ 实现细节随标准库而异，勿背。

### 4. 符号可见性：默认封闭（6.9，已实测 g++ 15.2）

```cpp
// 🔧 平台统一导出宏（书时代的宏 + 现代 CMake 生成物同名同义）
#if defined(_WIN32)
#  define LIB_API __declspec(dllexport)          // 建库时
#else
#  define LIB_API __attribute__((visibility("default")))
#endif
```

MinGW g++ 15.2 实测三件事（临时件在 `D:\develops\tmp\cppsnippets_api\`，仓库无产物）：
(a) PE 下 `objdump -p libapi.dll` 导出表**只含** `extern "C" + dllexport` 的三个符号——
「不标即不导」在 Windows/GCC 组合是默认行为，与 ELF `-fvisibility=hidden` 语义等效；
(b) C++ 函数未标导出时符号呈 `_Z6vis_fnv` 改编名，跨编译器互认无望（6.9 强调导出面要小而平的实证）；
(c) `-fvisibility=hidden` 在本 g++/Windows 组合**不报错、不改导出面**（PE 本就按 dllexport 圈定），
visibility 的主战场仍是 ELF——写书时 GCC/Windows 常直接忽略该属性，工具链态度已经变化，以实测为准。

### 5. #define 常量与友元（6.7/6.8）

`#define PI 3.14` 的四宗罪（无类型/无作用域/不可调试/入所有下游）→ `constexpr double kPi = 3.14;`（头文件里
inline 变量 C++17 免重复定义）。友元（6.8）的 API 语义是「把白名单写进头文件」——可用于 Pimpl 的 Impl 访问，
但别让它成为类间常态耦合通道。

## 权衡

| 手法 | 换来 | 付出 |
| --- | --- | --- |
| explicit 一刀切 | 零隐式转换事故 | 常用转换要写 `T{...}` 显式化（便捷性换安全） |
| 默认参数 | 调用点少打字 | 值进头文件=进兼容承诺；重载集随参数数漂移 |
| extern template | 编译期省 + 代码进库 | 实例化清单成公开接口 |
| 全符号导出（偷懒） | 零维护成本 | 名字即债务：内部重构被「已导出」锁死；链接冲突概率上升 |
| 导出白名单 | 演化自由、加载快、冲突少 | 要维护宏与清单（CMake 时代已低开销） |

## 相邻概念对比

- **const 方法 vs 线程安全**：「同一对象并发只读」需要 const **且**无隐藏可变状态（mutable 缓存就破功）。
- **指针 vs 引用参数**（6.6.1）：可空语义选指针、非空承诺选引用——返回观察句柄时同理（`not_null`/`gsl::pointer` 补中间档）。
- **友元 vs 公有 setXXX**：友元是「定向开放」，setter 是「全量开放」——ABI 债务后者大。
- **导出宏 vs 链接脚本**：宏在声明处逐符号标记（跨平台），版本脚本/map 文件在链接处整批圈定（平台特定，见 09 章符号版本化）。

## 最新演进与工业实践

- **参数类型四代目**：`const T&`（书时代）→ `std::string_view`（C++17，免拷贝只读串参）→ `std::span<const T>`
  （C++20，替代 `ptr+size` 对，6.6/7.8 的直接现代化）→ GSL `not_null<T*>`（非空指针的中间档）。
- **[[nodiscard]] / [[maybe_unused]] / [[deprecated]]**（C++17/20）：const 正确性与错误通道的属性化延伸，
  与 4.7.4、09 章弃用流程直接咬合。
- **C++20 modules 对「头文件承诺」的重写**：`export module mylib;` 后，接口分区（module interface）替代头文件，
  实现分区不导出即不可见——6.9 的「显式导出面」从宏/脚本级上升为**语言级**；ABI 工具（模块接口稳定化）
  尚不成熟，工业主流仍是头文件/动态库组合 ⚠️（不点名提案号：任务提及的 P2523 经核实为
  "Request for re-inclusion of std::hive"，与 modules/ABI 无关，故不引用）。
- **CMake 的可见性三件套**：`set(CMAKE_CXX_VISIBILITY_PRESET hidden)` +
  `CMAKE_VISIBILITY_INLINES_HIDDEN ON` + `generate_export_header()`——ELF 世界「默认封闭」的工程定型；
  Windows 侧与我们实测一致（dllexport 白名单）。对照仓库 [../ModernCMakeforC++.md](../ModernCMakeforC++.md)。
- **Google/Chromium 风格规**：禁头文件 `using namespace`、限定导出、`absl/` 与 `base/` 命名空间纪律——
  6.1/6.9/6.10 的工业化成文版本（各风格规公开可查）。
- **`override`/`final` 强制**（C++11）：6.2/继承承诺的静态检查器——漏写 override 即签名漂移事故（编译器代抓）。
