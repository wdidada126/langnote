## 核心概念速览（中英对照）

- **编译防火墙** — compile firewall：以声明/定义分离与前置声明切断 include 传染——02 章 Pimpl 的轻量亲戚。
- **无所不包型头文件** — kitchen-sink header：一个 `everything.h` 拉全库——编译期依赖网的震中（7.2.1 点名反对）。
- **写时复制** — copy-on-write (COW)：拷贝只增计数、首写才分家——把「值语义」装进「引用语义」的钱包。
- **隐式共享** — implicit sharing：Qt 对 COW 的叫法（QByteArray/QString），语义同一件事。
- **小字符串优化** — small string optimization (SSO)：短字符串住进对象本体、免堆分配——与 COW 相反方向的分配策略。
- **初始化列表** — member init list：进构造函数体**之前**完成成员初始化；书 7.4 的立场是「永远用列表初始化」。
- **内联的双重身份** — inline：建议（编译器决定采纳）与承诺（函数体进头文件 = 参与源码兼容却**不**参与符号 ABI）。
- **迭代访问模式** — iteration pattern：迭代器抽象（7.8.1，书担心其拷贝/间接开销）vs 随机访问（7.8.2）vs 数组引用（7.8.3）。
- **时效性剖析** — time profiling：采样式热点定位（perf 一族），先测后改的纪律（7.9.1）。
- **内存剖析** — memory profiling：分配热点/峰值/泄漏画像（7.9.2）；**多线程剖析**：竞争与同步开销（7.9.3）。
- **性能即兼容** — performance as contract：公开 API 的渐近行为一旦发布，退化为兼容性的一部分（本目录的补充论点）。

## 动机：API 章为什么讲性能

因为多数性能决定**发生在接口上**而非实现里：按值传参、暴露容器类型、把方法写成虚函数、
头文件里塞满实现——这些是设计决定，改它们要断兼容。7 章的清单因此本质是一张
「性能-兼容联合检查表」；而 7.9 收尾给出纪律：**不剖析不改**——优化直觉在 API 规模上常常错。

## 机制

### 1. 传参：从 const 引用到视图类型（7.1 及其后继）

```cpp
// 🔧 书时代答案（对）：大对象输入一律 const 引用
void render(const Document& doc);
// 🔧 现代补充分支：
void render(std::string_view text);        // 只读串：免构造 std::string（C++17）
void render(std::span<const Page> pages);  // 只读序列：替代 ptr+size 与 vector&（C++20）
void take(Document doc);                   // 移动语义后，"要存下来"的入参按值+move 反而更优（C++11）
```

判据演化出一条清晰时间线：**const 引用是默认，string_view/span 是「只观察不持有」的正式化，
按值 + `std::move` 是「要持有」时的新默认**（书成文于移动语义前夜，这条是最大补丁，已实测 g++ 15.2 编译运行）。

### 2. include 依赖网：编译期的分布式性能（7.2）

机制三件套：(a) 头文件只放**声明**需要的东西（前置声明代替 include，02 章 Pimpl 的轻量版）；
(b) 反「无所不包」：`everything.h` 让一处实现改动触发全工程重编——编译时间即 CI 时间即迭代速度；
(c) include guard/`#pragma once` 防重复包含，但防不了「传递依赖当直接依赖用」——
IWYU 原则（include what you use）是它的现代执法者。

### 3. 内联：性能小旋钮，兼容大闸门（7.6）

「除非需要勿用内联」的 API 读法：内联函数体进头文件 → 它对用户**永远是源码**，
库升级改了内联体，未重编的旧用户 .o 里还带着旧体——**两份真相并存**，这是 ODR 深渊也是
「库改了没生效」玄学的真身（已实测：朴素头文件的内联访问器直接编进用户 .o、无任何外部引用——
与 02 章 Pimpl 用户 .o 只剩 4 个函数名对照，内联把「库边界」抹掉了）。
结论：热小函数可内联，**策略性逻辑别内联**；库内性能交给 LTO 而非头文件承诺。

### 4. 写时复制：值语义的表演术（7.7）

```text
拷贝:  O(1) 只加计数        —— 用户看到"值"
写:    检测计数>1 → 真复制 —— 第一次写付全价
代价账: 每对象常驻计数头 + 每写一次原子 RMW + 多线程下"读也触发分配"（计数非原子时才是纯读）
```

书把 COW 列为「Pimpl 的语义选项 + 独立性能手段」两处；当代判决更严：
C++11 起 `std::string` 标准实质淘汰了 COW 实现（O(1) `swap`、`data()` 连续性、移动语义都与之冲突），
Qt 6 重写了大部分容器并放弃了它们的隐式共享（QString/QByteArray 等仍保留 ⚠️ 细节以 Qt 6 移植指南为准）。
**SSO + 移动**成为「让拷贝便宜」的主流答案——
「便宜拷贝」的三件兵器（COW/SSO/move）各藏不同的接口承诺，选型要按 02 章的复制语义表对号。

### 5. 迭代与访问形态（7.8）

书的提醒今天读来是**容器接口设计题**：暴露 `iterator` 型 API（返回 `container::iterator`）
把实现类型写进接口；返回 `span`/下标区间/回调，则容器可换实现不动 ABI。
7.8.3「数组引用」（`T(&arr)[N]`）的现代形态是 `std::to_address` + span 的 CTAD 推导。

### 6. 三类剖析（7.9）

时效性（采样热点）、内存（分配/峰值/泄漏）、多线程（竞争/同步开销）——对应工具链已是标配：
perf/VTune、ASan+LSan/valgrind/massif、TSan/IRTF。API 设计视角的补充：**先给性能场景建基准用例，
再谈优化**——基准代码走的就是你的公开 API，它同时是「性能兼容性」的回归网。

## 权衡

| 决定 | 换来 | 付出 |
| --- | --- | --- |
| Pimpl/前置声明 | 重编面骤减 | 二次分配、访问间接（02 章实测 sizeof=8 的账） |
| 内联公开 | 热点免调用开销 | 实现进头文件，库侧改不动（双真相） |
| COW | 拷贝 O(1)、内存共享 | 计数头常驻；原子化后写路径变贵；移动语义可替代 |
| SSO | 小对象免堆 | 对象变大（空态也占内联缓冲） |
| 按值 + move 传参 | 接口简单、存家免费 | 对"只看不存"的调用方多一次构造 |
| 暴露具体容器 | 用户直接吃 STL 生态 | 容器类型进 ABI，换实现=断兼容 |

## 相邻概念对比

- **性能 vs 兼容**：本目录一贯论——性能手段多是**提前兑现的兼容债务**（内联赌实现不变，暴露容器赌类型不换）。
- **7.3 声明常量 vs 6.7 避 #define**：同一枚硬币两面（`constexpr` 既是优化提示也是接口规范）。
- **剖析 vs 测试**：10 章找 bug（正确性），本章 7.9 找热点（性能）；共用基准设施。
- **编译防火墙 vs 链接防火墙**：include 切断的是编译期依赖，导出白名单切断的是链接期依赖（07 章）——两个战场一套兵法。

## 最新演进与工业实践

- **移动语义（C++11）重写了 7.1/7.7**：按值返回 + NRVO/move 取代 COW 成为"大对象出库"的标准姿势；
  `noexcept` 移动保证容器复用你的 move（不标即退化拷贝）——对照 [../Effective_Modern_C++.md](../Effective_Modern_C++.md) item 23–30。
- **`[[no_unique_address]]`（C++20）**：空优化基类的正式化——「零开销持有」的布局工具，7.5 内存优化的语言级新件。
- **对齐与分配器时代**：`alignas`/`std::align`（书后）、`std::pmr` 多态分配器（C++17）让
  「内存优化」从私有技巧变成可注入接口——库可把分配策略做成 API 的一部分（arena/bump allocator 作为
  性能敏感库的公开选项，游戏引擎与 LLVM 的 `BumpPtrAllocator` 是工业样本；后者细节 ⚠️ 以源码为准）。
- **编译期性能工程**：Modules（C++20）是「include 传染」的釜底抽薪方案——编译单元直接交换语义 IR，
  7.2 的全部手法理论上退役；现实是 CMake + 各大库的模块化分发（std module 仍未标准化 ⚠️）仍在路上。
- **剖析工具标准化**：perf/Intel VTune/Tracy（帧级剖析，游戏工业开源标准）+ 火焰图（Brendan Gregg
  方法，⚠️ 书目未核实为书）+ Continuous Profiling（C++26 有 P2892 系讨论 ⚠️ 不点名引用，见标准追踪页）。
- **header-only 的性能另一面**：cpp-httplib/doctest 全量内联 → 用户 TU 编译时间换零链接复杂度——
  7.2 的编译期成本在「单头库」上**合法地转移给了用户**，API 设计要声明这一点。
