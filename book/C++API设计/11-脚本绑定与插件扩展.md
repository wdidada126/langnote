## 核心概念速览（中英对照）

- **扩充 vs 嵌入** — extending vs embedding：给脚本语言加模块（扩充解释器）/ 把解释器装进应用（嵌入）——11.1.1 的第一岔路。
- **绑定层** — language bindings：把 C++ 类型/函数映射到目标语言对象模型的胶水；所有权与生命周期的翻译官。
- **跨语言多态** — cross-language inheritance：脚本子类覆写 C++ 虚函数、C++ 回调进脚本——绑定技术难度的天花板（书 11.3.6/11.4.6 专节）。
- **所有权鸿沟** — ownership mismatch：C++ 显式所有权 vs GC 语言（Python 引用计数/Ruby GC）——绑定事故的头号产地。
- **SWIG**：interface 文件驱动的通用绑定生成器（书用 Ruby 示例）；一份 `.i` 打到多门语言。
- **Boost.Python / Python-SIP**：书时代的 C++↔Python 两路线（SIP 服务 Qt/PyQt 生态）。
- **插件** — plugin：运行时发现的动态库，按约定接口扩展宿主；12.1 是本目录全部 ABI 知识的期末考。
- **ABI 稳定契约** — stable ABI contract：宿主与插件之间的最小二进制约定——通常收敛为「extern "C" 入口 + 纯虚接口对象 + 接口版本号」。
- **插件管理器** — plugin manager：扫描/加载/校验/登记/卸载的生命周期管家（12.1.6）。
- **接口查询** — interface query：`queryInterface("IFoo_v2")` 式协商——COM 思想在插件系统里的直系应用。
- **基于策略的模板** — policy-based templates：把可变量作模板参数在编译期装配（12.3.1，Andrei Alexandrescu 路线）。
- **CRTP** — Curiously Recurring Template Pattern：派生类把自身作模板参传入基类——编译期多态与静态扩展点（12.3.2）。
- **访问者模式** — visitor：对类层次分派双动操作（12.2.5）；`std::variant + overload` 是其当代标准库化。

## 动机：为什么要跨这两道边界

脚本化的收益（11.1.2）：交互式试验、批量小任务、让非 C++ 用户写扩展、GUI/DAW 的「宿主+胶水」分工。
插件的收益：不重编宿主即加功能、第三方生态、按需加载。二者的**共同成本**才是本书的重点：
一边是对象模型/所有权/异常/GC 的语言翻译，一边是符号/布局/版本/编译器配对的 ABI 翻译——
设计者真正要签的是「跨界契约」。

## 机制

### 1. 绑定的技术分层（11.2 的当代重排）

```text
手写适配器（书 FMOD/boost.python 教程路线）—— 控制力最强、成本最高
生成器（SWIG）                              —— 广撒网多语言，接口质量靠 typemap 苦功
模板元注册（Boost.Python → pybind11/nanobind）—— 现代主流：C++11 头文件库，类型推导 + 所有权语义映射
跨进程 RPC 绑定（COM/CORBA 的今日对应：gRPC/protobuf、Python 包 pybind11 已取代大半；
  Windows 上 COM 仍是活的）                  —— 用「协议」换「同进程 ABI」风险归零
```

所有权翻译的定型答案（书 11.3 用样板讲透，现代库已内置）：
C++ 工厂返回 → 绑定层持有并挂进目标语言对象生命周期；C++ 侧存脚本对象 → weak 引用 + `own()` 语义；
异常 → 目标语言错误（pybind11 的 `py::register_exception`）。**跨语言多态**（覆写回调）靠
「trampoline 子类」（pybind11 `PYBIND11_OVERRIDE`）——书 11.3.6 手工样板的现代自动化形态。

### 2. 插件系统：C++ 实现的 ABI 契约（12.1.3/12.1.4）

```cpp
// 🔧 宿主与插件的最小稳定契约（三件套：C 入口 + 接口版本串 + 纯虚接口）
// —— 头文件宿主/插件共享，但**不**共享任何具体类布局
#define PLUGIN_API_VERSION "1"
extern "C" MODLIB_API const char* plugin_abi_version();      // 加载时先验，不匹配即拒载
extern "C" MODLIB_API void*       plugin_create(const char* iid);  // "IRenderer_v1"
struct IRenderer {                                            // 只含虚函数的接口=可协商的 vtable
    virtual int32_t ABI_tag() const { return 0xIREN1; }       // 接口级校验（书的 12.1.4 立场）
    virtual void  render(const void* fb, int32_t w, int32_t h) = 0;
    virtual void  release() = 0;                              // 跨边界的 delete 禁忌 → 显式 release
};
```

六条设计律，条条有出处：(1) **入口必须 extern "C"**（mangling 不跨编译器，06/07 章实测）；
(2) **接口只增不改**——加函数=开 `IRenderer2`（vtable 槽序承诺，09 章）；(3) **对象跨边界创建/释放
必须配对**——所以用 `create/release` 而非公有析构；(4) **STL 类型不过境**（12.2.3 的教训反过来用：
容器/allocator/运行时版本都可能是地雷，接口传 `ptr+size` 或 `span`）；(5) **枚举值不可重排**（12.2.4）；
(6) **版本三元组校验**：宿主 ABI、插件 ABI、构建指纹（编译器/运行时）——书 12.1.7 的升级形态。

### 3. 继承扩展与访问者（12.2）

「通过继承扩展」＝允许用户派生你的基类：加功能（覆写/新增方法）与改功能（覆写改变契约——
LSP 红线，05 章）。书的警示集中在两处：派生自 STL 容器（12.2.3：无虚析构、切片、ADL 灾难）
与「枚举扩展陷阱」（新增枚举值打断用户 switch）。12.2.5 访问者模式：对类层次做双分派的标准解，
代价是「加新类型难、加新操作易」；12.2.6「禁止子类化」给出反向工具（非虚析构保护、final——final 为 C++11 后补）。

### 4. 模板扩展（12.3）

策略模板：`Font<Encoding, Loading, Rendering>` 式编译期乐高——扩展发生在**实例化**时，零运行时成本，
但所有实现必须进头文件（= 无二进制边界，06 章模板风格的账）；CRTP：基类静态知道派生类，
提供 `static_cast<Derived*>(this)` 的编译期多态与通用方法注入——两者在书时代以 boost/ADMX 风格存在，
当代被 C++20 concepts 约束重写（模板参数从「祈祷 duck-typing」变成「签名即契约」）。

## 权衡

| 决定 | 换来 | 付出 |
| --- | --- | --- |
| 提供脚本绑定 | 试验效率、生态外溢 | 多一套接口要维护+测试；所有权/异常/GC 翻译长期出错点 |
| 插件接口 = C + 纯虚 | 可跨编译器、可版本协商 | 表达力降级（无模板/重载/值语义）；接口粒度要预先设计 |
| 允许用户子类化公开类 | 无限扩展可能 | 行为承诺扩散；虚表成 ABI；禁止容易允许难（12.2.6 的反向） |
| 策略/CRTP 扩展 | 零开销、组合自由 | 头文件全公开；报错晦涩（concepts 前）；无法运行时切换 |
| 绑定生成器（SWIG） | 一份定义多语言 | 生成代码质量与目标语言地道性折损 |

## 相邻概念对比

- **绑定 vs 插件**：都是「不改宿主核心即加能力」；绑定跨语言类型系统，插件跨二进制布局——后者的
  失败模式（ABI 错配）更静默，前者的失败模式（引用泄漏）更慢性。
- **注册式工厂（03 章）vs 插件系统**：同一条路的前后景——注册键从 `std::string` 变成
  「接口版本串 + 加载器校验」就是插件化。
- **访问者 vs variant/模式匹配**：同一双分派问题的模式时代与标准库时代答案。
- **数据驱动 API（06 章 5.4）vs 插件**：改参数 vs 换实现单元；宿主可给「配置+插件」两级开放。

## 最新演进与工业实践

- **pybind11 与 nanobind 接管 Boost.Python 的位置**：二者皆 header-only、C++11+/C++17+；
  nanobind（pybind11 主作者 Jakob Wenzel 的新作）以「更快编译、更小二进制、优先稳定 API 绑定」为卖点
  （github.com/wjakob/nanobind，仓库存在已核实；量化数字 ⚠️ 未本机复测）。书 11.3 的构造/迭代器/
  跨语言多态诸节，今天全部对应 `class_<...>`/`PYBIND11_OVERRIDE`/`__iter__` 自动映射。
- **CPython 稳定 ABI（Stable ABI / limited API，PEP 384）** 与 Python 3.13 的 free-threading 实验（PEP 703 ⚠️ 细节以 CPython 文档为准）：
  绑定层的「版本兼容」终于有了官方杠杆——与 09 章符号版本化同题；SWIG/Boost.Python 时代「Python 小版本
  重编风暴」的制度化解药。
- **WASM 是新的「脚本化」**：C++ → WebAssembly（Emscripten/WASM 工具链）让浏览器 JS 直接吃 C++ API——
  书 11 章「跨语言障碍」的当代最大流量形态；导出面退化为 `extern "C" + wasm` 边界（与实测的导出白名单同法）。
- **COM 活着、CORBA 已死**：COM 仍是 Windows 组件事实标准（接口 IID+QueryInterface=书 12.1.4 的定型版）；
  CORBA 作为书内技术选项已过时 ⚠️ 诚实注记。
- **工业 ABI 姿态两极**：LLVM/Chromium 明确「插件 ABI 随版本锁死」（编译时同棵树，放弃跨版本兼容换实现自由）；
  反例是 GStreamer/Qt 插件/VST3 音频插件（Steinberg VST3 SDK 公开其 ABI 安全接口设计 ⚠️ 细节以官方 spec 为准）
  与 **SFX**（Principled Bits 的开源插件 ABI 方案：单一 C 入口 + 能力字符串协商 + vtable 尾部追加规则，
  github.com/PrincipledBits/sfx-plugin-abi，仓库存在已核实）——三种立场构成「插件 ABI 契约」光谱。
- **ODABN**：ESI Group 的开放设备适配器二进制命名规范，把 ABI 指纹编进文件名 12 字段（编译器/运行时/平台/架构/版本）——
  12.1.7 插件版本控制的「最重型」答案；采纳范围有限 ⚠️（规范原文未逐字核实）。
- **策略模板的当代化**：concepts（C++20）把 12.3.1 的「任意类型皆可传」改为「签名上声明约束」——
  `template <class P> requires Renderer<P>` 即「策略即接口」的编译期版本；CRTP 仍活跃于 ranges 适配器
  与 folly（`folly::MoveOnly`/`EmptyBase` 类件）；对照 [../C++20模板元编程.md](../C++20模板元编程.md)。
