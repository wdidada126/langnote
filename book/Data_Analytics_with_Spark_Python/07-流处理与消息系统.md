## 精读重构·DStream 半章（p.209–222）

- **微批模型（p.210–211）**：接收器离散化时间线→每批次产 RDD 对列；吞吐/延迟权衡由 batch interval 控制；
  Receiver 容错与 WAL 语境（⚠️ 推定书中提及，TOC 无专节）。
- **DStream 即「时间分片的 RDD」**：Ch4 全部转换/行动词汇表原样可用（map/flatMap/reduceByKey/window），
  这是本章前半篇幅小、大量回指 Ch4 的结构性原因 ⚠️ 推定。
- **State Operations（p.219）**：`updateStateByKey`——跨批次状态闭包，键状态字典常驻驱动侧 executor；
  状态膨胀与检查点依赖（Ch5 p.134 checkpoint 的第三次回指）。
- **Sliding Window（p.221）**：`window(w, s)` 对「窗宽 w、滑动 s」的批次子集再聚合；
  w/s 倍数关系决定每批次被重读次数 ⚠️ 转述。

## 精读重构·Structured Streaming 半章（p.223–228）

- **定位（p.223）**：把流当作「无界表」，查询是增量物化视图——表达力直接继承 Ch6 DataFrame/SQL。
- **Sources/Sinks（p.224–225）**：源=文件流/socket/rate/kafka；汇=foreach/表写入/流式 console，TOC 只列类目 ⚠️ 推定展开。
- **Output Modes（p.226）**：append / complete / update 三模式及与聚合窗口的兼容性矩阵 ⚠️ 转述。
- **Operations（p.227）**：事件时间窗口 `window(ts, "30 seconds")`、水印 watermark 迟容、
  聚合与 join 的流式限制（p.223–228 的官方语义，repo 现行版展开见互链）。

示意（Spark 2.x ⚠️ 未实测，本机 pyspark 不可装——沿用波6 实测结论）：

```python
lines = spark.readStream.format("socket").option("port", 9999).load()
words = lines.select(explode(split(lines.value, " ")).alias("word"))
counts = words.groupBy("word").count()
q = counts.writeStream.outputMode("update").format("console").trigger(processingTime="5 seconds").start()
```

## 常见误区与读法提示

1. 把 DStream 语法当现行技能树积累——错；读它只为理解「微批」思想，日用 API 一律 Structured Streaming。
2. 一次语义三角（at-least-once / 恰一次 / 尽力）在本章只出现在 Kafka 语境，2026 年面试仍考——用 E5 模型自证之。
3. socket/rate 源是玩具源，生产从 Kafka 族接——书中练习选 socket 是为零依赖，工程迁移需另学认证与 schema registry ⚠️ 转述。

## 复习要点与自测清单

1. 微批三参数：batch interval/窗宽/滑动，画时间轴说明每批被重读次数。
2. DStream 与 Structured Streaming 的「表抽象层级」差异各用一句概括。
3. `updateStateByKey` 的内存风险与 Ch5 checkpoint 依赖关系复述。
4. 输出模式兼容矩阵默写：append 为何拒绝无窗口的全局聚合？complete 为何只适合水位后小状态？
5. 水印三问：定义在哪列、迟到多久还收、超期数据去哪（drop）——用 E5 模型口头推演。
6. Kafka 语义题：at-least-once 幂等写与 offset 事务提交顺序，哪个组合导致恰好一次？
7. Kinesis shard ↔ Kafka partition ↔ Spark 任务槽三者映射的同构与差异。
8. 🔧 实验迁移：把 E5（12 批×500 行、批均 0.40 ms）的批大小改为 50 行重新计时，
   预测新鲜度与开销曲线形状并解释 batch interval 下界（单机版处理时间≈批循环耗时，非 Spark 行为）。

## 核心概念速览（中英对照）

- **离散化流** — Discretized Stream (DStream)：按批次间隔切出的 RDD 序列，旧流 API 的载体类型。
- **微批** — Micro-Batch：以小时间片重复执行批算子的流处理范式，Spark Streaming 的根设计。
- **接收器** — Receiver：把外部字节流桥接进 DStream 的常驻任务，可靠性依赖 WAL/重放 ⚠️。
- **updateStateByKey** — UpdateStateByKey：跨批次按键维持可变状态的旧 API 状态原语。
- **窗口算子** — Window Operation：窗宽 w 与滑动 s 定义的批次子集聚合，s<w 时同批多次重读。
- **无界表** — Unbounded Table：Structured Streaming 对流的概念化——时间维度上追加的 DataFrame。
- **输出模式** — Output Mode：append（只新行）/complete（全状态）/update（变更行）三种结果发射策略。
- **水印** — Watermark：事件时间上允许迟到的界限，决定状态清理与窗口完结时机。
- **触发器** — Trigger：processingTime/once/availableNow 类执行节奏开关 ⚠️ 现行语义含未定批次。
- **检查点** — Streaming Checkpoint：流查询断点续跑的 offset/状态持久化，Ch5 checkpoint 概念直系。
- **分区并行** — Partition-per-Task：Kafka partition/Kinesis shard 到 Spark 任务槽的映射单元。
- **恰好一次** — Exactly-Once：幂等写+位点事务组合保证的不重不丢语义，本章可靠性讨论终点。
