# 03 · 内存索引结构（Part II — Memory-Based Index Structures）

> 对应原书 Memory-Based Index Structures（pp.33–58）。✅ 章名/页码取自 Crossref。本章讨论**常驻主存**的序结构：二叉搜索树、平衡树（AVL/红黑）、跳表、Trie/数字树，以及它们对范围查询的支持。与下一章磁盘 B 树的根本区别在于——内存结构以**指针追逐（cache 不友好）**为主要代价，磁盘结构以 **I/O 次数**为主要代价，两者优化目标截然不同。

## 1. 从"可随机定位"到"保留顺序"

哈希（02 章）放弃了顺序换 O(1) 点查。本章反过来：**保留键的全序**，从而支持 `range`、`ORDER BY`、`min/max`、Top-k，代价是点查从 O(1) 变 O(log N) 或 O(log N) 期望。

- 核心能力增量：一旦结构中"中序遍历即有序"，范围查询 `k∈[a,b]` 就能定位到 a、沿序走到 b，成本≈`O(log N + 命中数)` 而非扫全表。
- 这正是 02 章末表格中"哈希不支持 range、树支持"的机理来源。

## 2. 二叉搜索树与其失衡问题

BST：左小右大，中序有序。缺陷：插入顺序决定形态，退化链表时 O(N) 扫描。

- **AVL 树**：以"左右子树高差 ≤1"强制平衡，靠旋转维护；查找严格 O(log N)，但每次插入可能触发多处旋转 → 写放大，适合读多写少。
- **红黑树**：以"红黑着色 + 最长路径 ≤2× 最短路径"放松平衡，换取更少的重平衡次数；写更友好，故 STL `map`、Linux 内核、JDK `TreeMap` 多用红黑。⚠️（转述，具体实现以各库文档为准）

## 3. 跳表（skiplist）：以随机化换简单

跳表用多层"快速通道"链表：顶层稀疏、底层是全序链。查找从顶层贪心前进，失败下沉一层，期望 O(log N)；插入只需局部随机提升，实现远简于自平衡树的旋转。

- 优点：无复杂旋转、天然支持范围（底层就是有序链表）、并发/无锁实现友好。
- 应用：Redis 有序集（ZSET）、部分 LSM-tree 引擎的内存表。⚠️ 转述。
- 与本书主线的关系：跳表是"内存序结构里工程性价比最高的一个"，但仍是**低维（1 维）**结构，无法直接搬到高维。

## 4. Trie 与数字树：按"位/字符"而非"比较"索引

- **Trie（前缀树）**：按键的字符/位逐层分支，查找 O(键长) 与 N 无关；支持前缀匹配 `LIKE 'abc%'`——这是比较树做不到的（比较树只知 `< = >`，不知"共享前缀"）。
- **Patricia / radix trie**：压缩单子链，省空间；ART（自适应基数树，见 🔧/02 章）即此家族的现代工程化。
- **数字检索视角**：Trie 把"序"变成"地址位"，是通往哈希（02）与通往高维空间索引（把多维坐标交错成分支）的桥梁。

## 5. 内存结构的隐藏代价：cache locality

自平衡树/BST 的"一次比较跳一个随机指针"，在多级 cache 体系里意味着频繁 cache miss。跳表/Trie 亦不免疫。故：

- 纯内存点查，哈希仍最快（少跳）；
- 范围/前缀需求把选择推向跳表/Trie；
- **数据大到装不进 cache 甚至装不进内存时，本族的局部性劣势逼你转向"以页为单位"的磁盘结构——即下一章 B 树**。这条"何时该离开内存结构"的过渡，是 Part II→Part III 的接缝。

## 6. 各结构能力矩阵（本章小结）

| 结构 | 点查 | 范围 | 前缀 | 有序遍历 | 写重平衡 |
|---|---|---|---|---|---|
| 哈希 | O(1) | ❌ | ❌ | ❌ | 低 |
| BST | O(log N)~O(N) | ✅ | ❌ | ✅ | 失衡风险 |
| AVL/红黑 | O(log N) | ✅ | ❌ | ✅ | 中/低 |
| 跳表 | O(log N) 期望 | ✅ | 弱 | ✅ | 低 |
| Trie/radix | O(key长) | 前缀✅ | ✅ | 字典序✅ | 低 |

## 7. 🔧 实测：序结构带来的范围收益（非本书引擎行为）

内存序结构本身 SQLite/DuckDB 不以纯内存树暴露给用户，但其二级索引即"有序结构"，可借其观察"有序 → 范围剪枝"的效应，与 02 章点查形成对照。

🔧 G2（SQLite 3.45.3，2M 行，有 B+树 `ix_t_k`）：`SELECT count(*) FROM t WHERE k BETWEEN 1000 AND 60000` ×50 共 **130.6 ms**，`EXPLAIN QUERY PLAN` = `SEARCH t USING INDEX ix_t_k (k>? AND k<?)`（有序叶定位 + 顺序扫叶）。
对照同语句去索引后实测 **6058.7 ms**（全表扫描）。→ 有序结构让"区间命中"从"看遍全表"降到"跳到区间头、顺叶链走"，这正是本章"保留顺序"的价值兑现（约 **46×**）。

> 说明：`DROP INDEX` 后 SQLite 的 `EXPLAIN QUERY PLAN` 文本会命中计划缓存、仍打印旧索引行（本机复核确证），故无索引 6058.7ms 的"全扫"结论以计时为准，不以其 EQP 文本为据。数字登记于 [00-总览与阅读地图.md](00-总览与阅读地图.md) §7。

## 8. 常见误区（⚠️）

- "红黑/AVL 是数据库默认索引"——错。它们属内存/容器结构；磁盘默认是 B+树（04），因为树扇出太小、I/O 次数太高。
- "跳表只是玩具"——恰恰因实现简单 + 无锁友好，工程界（Redis、部分 LSM 引擎）大量使用。
- "Trie 只能存字符串"——把键看成位串，Trie 即多维/前缀检索的通用骨架，也是 ART、乃至高维结构的一条入口。

## 6.5 复杂度一览（点查 / 范围 / 空间，⚠️ 标准结论）

| 结构 | 点查 | 范围(命中 K) | 前缀 | 最坏空间 | 维护 |
|---|---|---|---|---|---|
| BST（退化） | O(N) | O(N) | ❌ | O(N) | 会失衡 |
| AVL | O(log N) | O(log N + K) | ❌ | O(N) | 旋转频繁 |
| 红黑 | O(log N) | O(log N + K) | ❌ | O(N) | 旋转较少 |
| 跳表 | O(log N) 期望 | O(log N + K) | 弱 | O(N) 期望 | 随机提升 |
| Trie | O(L) | 前缀 O(L+K) | ✅ | 与字符集/键长相关 | 低 |

（L=键长，K=命中数）——可见"保留顺序"后范围/遍历成本从"扫全表 N"降到"定位 log N + 输出 K"，这正是 01 章代价尺第 2 条的实现。

## 6.6 并发与无锁（为何跳表受工程偏爱）

自平衡树的旋转会横跨多个节点指针，加锁要么粗（锁整树，串行化）要么易死锁（多节点细锁 + 旋转）。跳表/Trie 的修改常局部于少数层/少数前缀节点，更易做 **fine-grained 或乐观并发**，因此 Redis、部分 LSM 引擎内存表、若干内核结构倾向跳表。⚠️ 转述（具体实现各异）。

```

      │否

      │是

```

## 7.5 何时"离开内存结构"进入磁盘结构（Part II→III 的临界）

内存序结构的适用上限由两条决定：**容量**（数据 > 可用内存则装不下）与 **局部性**（工作集 > L2/L3 cache 则每次跳跃都 miss）。当二者任一被突破，"把多个键打包进一页、每页一次 I/O"的 B+树（04）便以更少的访问次数胜出——即便它逻辑层数更多。这条临界不是理论线，而是"数据规模 vs 内存/缓存层次"的经验线，本书把它留作 Part III 的开篇动机。⚠️ 概念梳理。

## 核心概念速览（中英对照）

- **内存索引结构** — Memory-based index structure：常驻主存、以指针/跳跃为主要代价的序结构族。
- **二叉搜索树** — BST：左小右大、中序有序的二叉树，退化时 O(N)。
- **AVL 树** — AVL tree：高差 ≤1 的严格自平衡 BST，读优写劣。
- **红黑树** — Red-black tree：以着色维持近似平衡，写友好的自平衡 BST。
- **旋转** — Rotation：自平衡树局部改指针以恢复平衡的操作。
- **跳表** — Skiplist：多层快通道链表，期望 O(log N)，天然支持范围。
- **Trie/前缀树** — Trie：按键字符/位逐层分支，支持前缀匹配，O(键长)。
- **基数树/Patricia** — Radix/Patricia trie：压缩单子链的 Trie；ART 属此家族。
- **cache 局部性** — Cache locality：随机指针跳跃导致 cache miss，是内存结构的隐藏代价。
- **前缀匹配** — Prefix match：`LIKE 'abc%'` 型检索，仅 Trie 类结构高效。
- **中序有序性** — In-order sortedness：树/跳表"中序遍历即升序"的性质，是范围查询的基础。
- **重平衡代价** — Rebalancing cost：自平衡树插入/删除后旋转的开销，AVL 高于红黑。
- **基数树 ART** — Adaptive Radix Tree：Trie 与哈希融合的现代内存索引（DuckDB 默认）。

## 最新演进与工业实践

- **ART（自适应基数树）成现代内存索引代表**：DuckDB 的默认二级索引即 ART，把 Trie 与哈希结合（惰性展开 + 节点类型自适应），在低基数列省内存。🔧 本机 DuckDB 1.5.5 可建 ART，但分析型优化器常不采纳（见 02 章 G3）。✅ 实测（非本书引擎）。
- **红黑/跳表在引擎内存件中的分工**：内存 buffer 内 hash map、ordered map 常见红黑；有序集/延迟队列常见跳表（Redis ZSET）。⚠️ 转述。
- **与后续章的接口**：本章"何时该离开内存序结构 → 转向页式磁盘结构"的判断，正是读 04 章的动机；而"前缀/位视角"在高维处回收为空间填充曲线与前缀过滤（08/09）。✅ 见 [04-磁盘层次索引结构.md](04-磁盘层次索引结构.md)。
- **姊妹册对位**：工程侧对"该建哪列有序索引"的决策规则见 [../Physical_Database_Design/04-索引选择方法.md](../Physical_Database_Design/04-索引选择方法.md)；本章只讲结构本身。✅ 实链在盘。
- **内存结构与 LSM/WAL 的关系**：LSM-tree 引擎（RocksDB 等）的"内存表"多用跳表或有序数组，配合磁盘 B+树/不可变段——把本章内存序与 04 磁盘序串成一条读写权衡链。⚠️ 转述。
