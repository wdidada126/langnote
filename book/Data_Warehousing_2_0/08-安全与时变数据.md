# 08 · 安全与时变数据（原书第 10+11 章，pp.181–189 / 191–201 ✅）

> 精读重构册。依据：Elsevier 官方书页 TOC「10. Security in the DW 2.0 environment」「11. Time variant data – data structure representation」✅ + Crossref 页码 181–189、191–201 ✅。合并理由：安全章太短（9 页）难独立成册；且两章共享同一批"行级标记"技术底座（⚠️ 编者联结）。细则为框架重构。

## 一、章定位

第 10 章把安全从 BI 工具层的"报表权限"升格为**环境属性**：DW 2.0 是常开、分布式、多区迁徙的活系统，权限必须跟着数据走而不是跟着报表走。第 11 章则是全书**技术密度最高**的一章：把第 2 章构件 1（historically variant data）落到数据结构表征——时变到底在表里长什么样。两章一个管"谁能看什么"，一个管"什么时候的值"，合起来回答审计的灵魂拷问："**2003 年 3 月 17 日，谁看到了什么？**"

## 二、精读札记：第 10 章安全（✅ 章题）

### 2.1 一代安全欠账清单（⚠️ 推定）

- 权限寄生在报表工具，仓内裸奔；
- 备份介质即后门（全量历史拷贝散落磁带）；
- 多集市复制导致同一敏感数据 N 份，脱敏策略无法收敛；
- SOX（2002）/隐私法起步期合规压力无处落点。

### 2.2 DW 2.0 的安全架构位（⚠️ 推定 + 与元数据章钩连）

安全规则作为**企业/技术元数据**登记（04 章三层），由连通层（12 章）与粒度管理器（14 章）在执行时读取——即"权限是元数据的一种，不是外挂"。要点四条：源级脱敏在 ETL 入区时定格（此后随数据迁徙全程有效）；区际权限分级（归档区可读窗口≠交互区）；审计流本身入仓（07 章自监控同构）；时变权限（08.2.3）——**权限也有有效期**，这是时变思想在安全侧的投影。

### 2.3 2005 局限登记

无行列级安全产品成熟形态（本章理想清单要等云仓 RBAC/行级策略十年），作者把"该有什么"列对了吗——基本对；"怎么做到"——当年做不到，读者须带此意识阅读。

## 三、精读札记：第 11 章时变数据表征（✅ 章题「data structure representation」）

### 3.1 时变的两类时钟

Inmon 一贯框架（BDW 同源，本册收编 ✅ 概念）：**出现时间**（transaction/入库时刻）与**有效时间**（valid/业务生效时刻）。时变表征的目标=两类时间都能问、都能答。

### 3.2 数据结构选项（✅ 章题所指"representation" + ⚠️ 名录推定）

| 表征 | 结构 | 答得了什么 | 代价 |
|---|---|---|---|
| 当前覆盖 | 单行 UPDATE | 只答"现在" | 历史蒸发（一代默认，即病灶） |
| 快照重复 | 每期全量复制 | 任意"期末" | 空间爆炸 |
| SCD2 区间行 | 旧行封口(valid_to)+新行开区(valid_from→∞) | **任意 as-of 点** | 连接复杂度上移（05 章粘合层） |
| 双时态四戳 | valid_from/valid_to + tx_from/tx_to | "当时你以为的 vs 当时真实的" | 建模与查询门槛最高 |

### 3.3 本机 🔧 实测标本（非本书引擎/平台行为，DuckDB 1.5.5 实跑 ✅）

SCD2 区间行 + as-of 查询最小闭环：cust_dim 四行版本（客户1 三代 bronze/silver/gold 区间封链，客户2 单行）——

- `as-of 2023-05-17` → **silver**；`as-of 2024-06-01` → **gold**（两问即中 ✅）。
- 要点：区间不重叠 + 开区用哨兵 9999-12-31，一条 BETWEEN 谓词就是"时变基础设施"的全部兑现。
- 对照：把同表换成 Iceberg 快照链，"as-of"从行游戏变成 `FOR SYSTEM_VERSION AS OF` 表游戏——结构表征升维，教义未变。

## 四、主题深读：安全×时变=「可审计性」这枚 2026 硬通货

单看任一章都不惊艳，合看才明白 2005 的作者在拼**企业级可审计性**的最小完备底座：数据有时变版本（能答"当时是什么"）+ 权限有登记与审计流（能答"当时谁能看"）= 今天监管科技（GDPR 类、金融审计 ⚠️）的两大支柱。湖仓 2026 的补课顺序恰好是先补时变（时间旅行成为标配）再补安全（catalog 统一权限），与本章双章结构一一对应——盘上实务册：[../Practical_Lakehouse_Architecture/06-湖仓架构中的数据与AI治理和安全.md](../Practical_Lakehouse_Architecture/06-湖仓架构中的数据与AI治理和安全.md)。

## 深读补充：SCD2 区间维护三坑与断言（承 🔧 标本，⚠️ 编者实操学）

| 坑 | 症状 | 一条 SQL 断言可防 |
|---|---|---|
| 区间重叠 | as-of 查询返回两行版本 | `GROUP BY id HAVING count(*) FILTER (now BETWEEN f AND t) > 1` 应为空集 |
| 断链 | 旧行封口了、新行没开——历史"蒸发" | 每个 id 必存在 `t = 哨兵值` 的开区行 |
| 哨兵漂移 | 有人用 NULL、有人用 9999、有人用 'present' | 单一约定写进 04 章技术元数据，评审比对 |

三坑对应 07 章"结构质量"的三条断言——**时变不是建模决定，是每日断言决定的**；2026 把它做成 CI 测试，2005 只能做成值班巡检，这就是本章教义与工艺的代差。

## 双时态最小 DDL 草图（⚠️ 编者代拟，落空项的招魂幡）

```
policy_state(id, status,
  valid_from, valid_to,          -- 业务世界生效期
  recorded_at, superseded_at)    -- 环境知晓期（追加不可改）
```

- 四条时间轴齐备时可答终极审计题："**2024-01-05 录入时，我们以为 2023-09 的状态是什么？**"（按 recorded_at≤录入日取当时信念行）——一代二代（本册）主流都答不了，只有双时态答得了。
- 2026 现实：保险/法务/央行类系统仍手工维持四轴；通用引擎层"信念即数据"（bitemporal as a service）品类未出生——Inmon 超前量：约一个时代。

## 最新演进与工业实践

- **判决**：SCD2/时间旅行全面兑现；**双时态是本册判定的全书最大落空项**——工程界用"快照+审计日志拼接"土法应答，真正的 bitemporal DBMS 从未商品化普及（学术时态 SQL:2011 支持面零星 ⚠️）；Inmon 在 2005 押注最深的结构，恰是 2026 最缺的市场。
- **兑现变形**：时间旅行把"历史"从表内行变成表外版本（元数据层的游戏），as-of 从业务 SQL 技能变成引擎能力；但业务口径版本（同一"收入"定义在两时期的不同算法）仍须 SCD2 式人工建模——**引擎版本≠语义版本**，本章教义在语义层继续服役。
- **安全产业**：行列级策略、动态脱敏、capsule 化查询审计已是云仓/catalog 标配（⚠️ 转述：docs.snowflake.com、iceberg.apache.org 口径已波内验真）；"权限入元数据"由 catalog 统一权限面实现，Polaris/Unity 两册在盘可读（目录已验名）。
- 本机 🔧 汇总（非本书引擎/平台行为）：本章 SCD2 as-of（双问双中）+ 05 章静/时变分表联查 + 10 章双粒度对账构成"时变三件套"，读者可在 DuckDB 一次跑完全部断言。
