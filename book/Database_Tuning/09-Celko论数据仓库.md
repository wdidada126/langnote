# 09 Celko 论数据仓库（Celko on data warehouses）

> 原书第 9 章，pp.261–274，作者 ✅ Joe Celko（Crossref 记录）。
> DOI: 10.1016/b978-155860753-8/50010-x（✅ Crossref 200）。
> 章题、页幅、作者 ✅ 实抓；正文为主题级精读重构，细断言标 ⚠️。

## 这一章在讲什么

14 页由 Joe Celko（SQL 标准化老将、《SQL for Smarties》作者 ⚠️ 背景通识）执笔的**数仓建模观点章**——
全书唯一的"建模即调优上游"专章：结构选错了，后面第 10 章的所有手段都是给坏房子刷漆。

### Celko 立场的主题级重构（⚠️ 依其公开一贯观点与本章节题推定）

1. **星型模型的批判性审视**
   - Celko 长期警惕"无脑星型"：把维度属性全部塞进宽维度表、用退化列换连接，
     会制造更新异常与冗余失控；他更信任规范化的桥梁表与真关系约束 ⚠️ 推定本章有涉及。
   - 但对**事实表**他又承认大宽事实 + 时间键的扫描友好性——即"建模要为访问形状服务"。
2. **层次/树结构的 SQL 表达**
   - 嵌套集合（nested sets，他标志性的推广）与路径枚举 vs 邻接表 + 递归查询的权衡 ⚠️ 推定；
     这为第 4 章"闭包表/递归"话题提供建模侧呼应。
3. **时间建模**
   - 有效区间（valid time/transaction time）、缓慢变化维度（SCD）的类型学 ⚠️ 推定，
     Celko 对"用 CURRENT_DATE 隐式关联"深恶痛绝。
4. **约束与数据质量**
   - 数仓也要 CHECK/主键外键纪律（当年 ETL 圈流行"装完再补约束"，他反对裸装 ⚠️ 推定）。
5. **可移植性**
   - 少用厂商私有扩展（外连接语法旧写法、PIVOT 类），多走 SQL 标准——既是工程也是调优（换引擎成本） ⚠️。

### 与第 10 章的分工

本章管"仓库长什么样"，第 10 章管"仓库怎么跑得快"：建模是**一次性的形状选择**，
调优是**持续的代价平衡**——Celko 章在前是合理编排。

## 2002 → 2026 的位置

星型 vs 规范化的辩论被**湖仓 + dbt 流水线**改写战场：
维度建模（Kimball）以 dbt 分层模型（staging/mart）的形态制度化，Celko 警告的冗余失控
由测试框架（dbt tests）与契约（schema contract）兜底；SCD 类型学直接变成 dbt snapshot /
Merge on key 的原生模式。他的"层次结构 SQL 表达"在递归 CTE 标准化后基本收敛为工程常识。
"建模是调优的上游"这句 2026 依然字字有效——查询成本的第一决定项是表形状与分布键。

## 阅读提示（怎么读这一章）

- Celko 的行文以反例推进，读时给每个反例配一个自家表名，记忆留存翻倍。
- 先读 SCD 与时间建模段，再读星型批判段：前者是共识、后者是立场，顺序反了容易误读全书。
- 本章立场与 Kimball 教派的张力请带着'访问形状'这把尺子来裁决，别站队。
- 14 页里最可迁移的一条：任何'先装完再说'的纪律豁免都要写明补账时点。
- 与 [10](10-数据仓库调优.md) 连读：建模决定扫描量的上限，调优只能逼近它。

## 常见误读与澄清

- 误读：星型=数仓唯一正确形状
  澄清：Celko 的警告即针对教条：宽表冗余与更新异常有长期利息；形状要按访问与演化速率选
- 误读：建模章与调优无关
  澄清：分布键/分区键/粒度在 MPP 上是一次性决定后续十年扫描量的调优项——本章是第 10 章的前置
- 误读：约束拖慢装载所以不要
  澄清：装载期可暂缓、装完必补；裸装载把质量问题利息化，ETL 返工成本更高

## 章要速览：三个要点与三个坑

- 要点：建模是调优的上游，形状错误后期无法廉价修复；SCD/时间轴要显式建模不是日期列碰运气；约束纪律不因数仓豁免。
- 坑：无脑星型把一切塞宽表；裸装载后永不补约束；CURRENT_DATE 隐式关联制造口径漂移。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 星型模型 | star schema | 事实表居中、维度表放射的数仓布局 |
| 雪花模型 | snowflake schema | 维度再规范化展开的星型变体 |
| 缓慢变化维度 | slowly changing dimension (SCD) | 维度属性随时间演化（type 1 覆盖 / type 2 拉链）的建模问题 |
| 拉链表 | history rows / effective-dated rows | SCD2 的物理形态：起终有效期一行一版本 |
| 退化维度 | degenerate dimension | 无属性、直接留在事实表的键（订单号类）|
| 桥梁表 | bridge table | 多对多/不定基数关系在星型中的中间表 |
| 嵌套集合 | nested sets | 用左右值编码树、支持整子树聚合的表示法 |
| 有效时间 | valid time | 事实在现实世界成立的时间轴 |
| 事务时间 | transaction time | 事实在库中被记录/替换的时间轴 |
| 一致性事实 | conformed fact/grain | 跨主题共享的度量口径与粒度定义 |
| 裸装载 | load-before-constraint | 先灌数后补约束的 ETL 惯例，Celko 所反对 |
