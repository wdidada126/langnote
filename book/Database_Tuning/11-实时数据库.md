### 实时负载与传统调优的分界（⚠️ 依据该领域通识重构）

- 传统调优优化**均值/吞吐**；实时系统优化**截止时间（deadline）的可满足率**：
  错过截止的事务即使最终完成也算失败——目标函数换掉了。
- 关键概念群：事务截止期（绝对/相对）、价值函数（value of commitment）、
  准入控制（admission control，过载时"扔"低价值事务）、优先级调度与优先级反转防护 ⚠️ 术语群为领域通识。
- 并发控制要重设计：两阶段锁的阻塞不可接受，于是有"悲观 + 乐观混合、按截止期仲裁"等方案谱 ⚠️。
- 缓冲池也实时化：页面置换按"即将过期的事务需要哪些页"决策（优先级页替换）⚠️。
- 过载哲学：与其全线超时，不如主动降级保住高价值事务——这正是当年"torture the database"
  实验精神（[01-基本原则.md](01-基本原则.md)）在实时域的镜像 ⚠️ 联系为推定。

## 2002 → 2026 的位置

"实时数据库"作为独立产品类目消失了（Taiji/TimeBox 等研究原型未商品化 ⚠️），
但其问题被三个后继语系瓜分：

1. **流处理**：Flink 以事件时间水位线（watermark）把"截止期"改写成"乱序容忍度"，
   调度按反压/检查点维持 SLO——本章的准入控制思想在"背压即拒绝"里复活。
2. **HTAP/低延迟 OLTP**：金融行情、5G 计费类负载今天用"内存引擎 + 确定性调度"实现，
   截止期语义进入 SLO/P99 预算分解。
3. **汽车/工业边缘**：AUTOSAR/DDS 类实时栈与数据库解耦，RTDBMS 的遗产变成中间件调度问题。

读史价值：这是全书唯一"目标函数根本不是快，而是按时"的章节——2026 年做 SLO 工程仍绕不开这个区分。

## 章要速览：三个要点与三个坑

- 要点：实时调优的目标函数是按时率不是快；过载时主动降级优于全线崩溃；截止期语义要贯穿并发/缓冲/调度全栈。
- 坑：用均值延迟验收实时系统；高优先级事务被低优先级持锁反杀；过载时仍来者不拒导致有效吞吐归零。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 硬实时 | hard real-time | 错过截止期即系统性失败（安全关键）|
| 软实时 | soft real-time | 超时降低价值但系统仍运行 |
| 截止期 | deadline | 事务必须完成的时间约束 |
| 可满足率 | schedulability | 截止期约束下能被按时完成的事务比例 |
| 准入控制 | admission control | 过载时按价值拒绝新事务的保护机制 |
| 价值函数 | value function | 事务完成价值随时间变化的函数 |
| 优先级反转 | priority inversion | 低优先级持有资源阻塞高优先级事务 |
| 优先级页替换 | priority-based buffering | 按紧迫事务需求决定哪些页驻留 |
| 过载崩溃 | overload collapse | 全体系超时导致有效吞吐归零的病理 |
| 水位线（后继语义） | watermark | 流处理中对"迟到界限"的声明式表达 |
| SLO 预算分解 | latency budget | 2026 版"截止期工程"：端到端延迟按环节拆分 |
