# 04 调优关系系统（Tuning relational systems）

> 原书第 4 章，pp.123–163，作者 ✅ Dennis Shasha & Philippe Bonnet（Crossref 记录）。
> DOI: 10.1016/b978-155860753-8/50005-6（✅ Crossref 200）。
> 章题与页幅 ✅ 实抓；正文为主题级精读重构，未对照原文的细断言标 ⚠️。

## 这一章在讲什么

41 页的"SQL 与关系结构层调优"：第 3 章调**数据结构**，本章调**查询的形状与执行策略**——
在给定负载下改写查询、组织表、引导连接顺序，让优化器落在好的计划上。

### 1. 连接策略的操纵

- 嵌套循环/排序合并/哈希连接各自的适用形状（小驱动大、已有序、等值大批量）⚠️ 讲法细节。
- "驱动表选择"时代的产物：当年（及本章）大量建议围绕连接次序提示（join order hints）与
  把大表拆开分而治之；今天多数优化器已自管连接次序，人转交"边界条件"（统计、行数反馈）⚠️ 映射推定。
- 半连接/ EXISTS 与 IN 的改写：用"只要存在性"替代"去重全物化" ⚠️。

### 2. 派生表、子查询与物化

- 该内联（merge）的派生表别物化、该物化的公共子表达式别重算——"视图是调优对象而非逻辑装饰"
  的立场 ⚠️ 推定。
- 物化视图/MQA 类聚合缓存被作为数仓与报表负载的桥梁引出（细节留给第 10 章）⚠️。

### 3. 表组织与反规范化

- 聚集存储（把常一起访问的行放一起）：外键方向聚集、嵌套表/索引组织表（IOT）⚠️ 覆盖面。
- 适度反规范化（冗余列消除连接）是本章反复出现的"显式代价交换"：读收益 vs 写代价 vs 一致性风险 ⚠️。
- 分区/分表思想在 2002 年以"手工拆分大表 + UNION ALL 视图"的形态出现 ⚠️ 推定。

### 4. 特殊查询形态

- 排名/百分位（rank/percentile）类查询的早期写法（自连接计数、相关子查询）——
  这正是第 13 章时序分位数问题的 SQL 侧 ⚠️ 呼应推定。
- 递归查询（层次展开）的代价与替代（闭包表）⚠️。

## 2002 → 2026 的位置

本章的"手写连接次序 + 提示引导"技能大幅贬值，但**查询形状感**更值钱：
今天引导优化器的正确接口是统计（扩展统计、行数反馈）、约束声明（主键/外键/NOT NULL 信息复用）
与结构（分区裁剪键），不是硬提示。学习型优化器（Lero/Bao/LOGER，见文末）则干脆把"给提示"
变成"给小模型/给 hint-set 选择"。

## 常见误读与澄清

- 误读：改写清单可以背
  澄清：形状与代价绑定负载：同一条 IN→EXISTS 改写在有无 NULL、复用度不同两侧收益相反，永远以计划复核
- 误读：提示是长期方案
  澄清：本章与第 14 章一致：提示为止血；长期解在统计/约束/索引，提示会随数据演化变毒
- 误读：反规范化等于放弃一致性
  澄清：冗余列配触发器/事件维护即可收敛；它放弃的是'免费的一致性'，换来的是连接消除——显式记账即可

## 章要速览：三个要点与三个坑

- 要点：连接算法各有形状偏好；该物化/该内联取决于复用度与基数；反规范化是显式代价交换不是偷懒。
- 坑：硬提示固化劣计划；驱动表选错导致中间结果爆炸；把该留在引擎的集合运算搬进应用循环。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 连接算法 | join method | NLJoin/SortMerge/HashJoin 三大族，各有适用形状 |
| 驱动表 | driving table | 连接次序的第一步选择，决定中间结果规模 |
| 半连接 | semi-join | 只保留"存在匹配"的外侧行，不做完全匹配展开 |
| 派生表内联 | view merging | 把子查询并入外层，避免物化开销 |
| 物化 | materialization | 把中间结果落表复用或缓存 |
| 反规范化 | denormalization | 冗余换连接消除，显式承担写代价与一致性风险 |
| 聚集存储 | clustered storage | 关联行物理相邻以摊薄访盘 |
| 索引组织表 | index-organized table (IOT) | 数据按主键组织，点查极快、二级索引带主键后缀 |
| 提示 | hint | 人工指定计划形状（索引/连接次序/方法）的旁路接口 |
| 闭包表 | closure table | 用显式祖先-后代对替代递归查询 |
| 行数反馈 | row correction | 优化器按执行时实际基数修正后续计划 |
| 分区裁剪 | partition pruning | 用谓词裁掉不可能命中的分区 |
