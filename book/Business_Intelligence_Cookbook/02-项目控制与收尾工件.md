## 2. 配方骨架精读重构（⚠️ 编者按题名+时代文档推定）

**3.1 RTM**——问题：BI 需求以「报表感觉不对」形式回流，无法定位改动点。骨架 ⚠️：行=需求条目（来自 Ch6 优先级
清单），列=语义模型对象/物理表/ETL 转换/测试用例/发布号；任何一列变更可反查受影响需求。RTM 与 Ch6 的
「Decomposing the reports and requirements」共享同一需求 ID 空间——**这是全书最关键的跨章数据契约**。
2026 等价：血缘目录（数据血缘自动化，对照 Ch8）+ 语义层对象标签替代手工矩阵。坑：矩阵粒度到「报表」而非
「口径」，改一个度量仍要全报表回归。

**3.2–3.4 三本台账**——问题：风险/问题/缺陷在 BI 项目里互相转化（源数据质量风险→剖出问题→ETL 缺陷）。
骨架 ⚠️：风险册按「驱动因子暴露面」评分（呼应 2.8：源系统数×转换数即质量风险敞口）；问题册区分运行事件与
口径争议；缺陷与增强**同册分流**（3.4 题名已宣告此立场）——增强走 Ch6 需求通道重进 RTM。
2026 等价：Issue tracker 模板化，但「口径争议」仍无工具解，只有评审机制。坑：三册 ID 互不引用，
风险落地成问题后失去可追溯性。

**3.5 cyclical build and test**——问题：ETL 全量重跑不可回归。骨架 ⚠️：固定周期（书时代典型为双周）内
「构建（重生成 OWB/ODI 工件）→ 装载增量 → 对账（Ch11 对账配方）→ 抽样回归」四步火车；测试数据以 Ch9
剖析脚本的域值断言为基线。这是**数据版 CI** 的 2012 表述。2026 等价：dbt test + CI 流水线 + 环境隔离
（对照盘上 [../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md](../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md) ✅ 写前验名）。

**3.6–3.7 协作环境**——问题：OWB/SDM/OBIEE 的工件天然「长在服务器/单机 GUI 里」，多人开发互相覆盖。
骨架 ⚠️：3.6 定规约（工件命名/分支策略/谁可改 RPD），3.7 装客户端（OWB Client、SQL Data Modeler、
ODI Studio、OBIEE Administration Tool）统一版本。Subversion 是书中版本库主角（Ch10 前四食谱全部围绕
SDM×SVN 展开，✅ 题名可证）。2026 等价：Git+声明式工件（OAC 语义模型导出、APEX 应用 SQL 脚本化）；
Administration Tool 的 RPD 二进制合并痛点在文本化语义层里消失 ⚠️ 转述。坑：把 OBIEE catalog（报表对象）
也塞进 SVN——书中 catalog 安全另在 Ch14 处理，两域工具不同。

**4.1–4.5 五类代码工件**——问题：项目「收尾」不是写总结，而是**把四类工具的私有状态导出为可版本化的文本/
二进制工件**。骨架 ⚠️（每题同构：导出→命名→入库→重建验证）：
- OWB：设计器工程+生成的映射/过程脚本（⚠️ OWB 11gR2 归档口径，永久链失效，见 00 §11 弃用清单）；
- OBIEE：RPD 三层层（物理/商务/展示）导出 + webcat 目录对象（✅ 题名级证据：4.2 与 Ch14 catalog 食谱呼应）；
- APEX：应用导出 SQL（f100 类脚本）；
- ODI：知识库（repository）导出 + 场景/包清单；
- script：散落脚本入统一目录规约。
五题合计宣告本书的工件宇宙：**BI 交付物=四工具工件+脚本**，收尾质量决定 Ch3.5 构建火车能否续跑。
2026 等价：四类工件全部收敛为「Git 仓库+流水线部署」，APEX 应用导出至今仍是 SQL 脚本 ✅
（https://docs.oracle.com/en/database/oracle/application-express/ 200 ✅）。

**4.6–4.7**——问题：上线即散伙→增强积压→系统腐烂。骨架 ⚠️：4.6 把 3.4 增强登记册接进 3.5 构建火车
（小步演进），4.7 定义业务方节奏（发布说明/口径变更公告/满意度回路）。两题是「程序」视角（1.1）的落地闭环：
程序不死，项目才谈得上收尾。

## 最新演进与工业实践

- **版本化**：2012 的 Subversion+二进制工件 → 2026 Git+声明式工件+流水线；OWB 消亡（终态停售 ⚠️ 归档口径），
  ODI 12c 文档仍在线 ✅ https://docs.oracle.com/middleware/1213/odi/index.html ，云侧由 OCI Data Integration
  承接 ⚠️（其公开文档精确链 404，见 00 §11 弃用清单，不编 URL）。
- **RTM→血缘**：手工矩阵由自动血缘+目录标签替代；OBIEE catalog 对象治理并入 OAC 项目管理
  ✅ https://docs.oracle.com/en/middleware/bi/analytics-server/index.html （200 ✅，⚠️ 转述）。
- **构建火车→数据 CI/CD**：dbt/Great Expectations 类工具把 3.5+Ch11 对账合成流水线断言；发布火车思想未变。
- **APEX 工件**：应用导出 SQL+Workspace 导出仍是现行部署方式 ✅ https://docs.oracle.com/en/database/oracle/application-express/ 。
- **反馈回路**：产品分析（报表使用埋点）让 4.7 从会议节奏变成数据节奏 ⚠️ 编者归纳。
