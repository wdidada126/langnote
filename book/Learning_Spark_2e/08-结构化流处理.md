## 8.1 引擎演变与"哲学"

- 谱系：Spark 1.x DStream（微批 RDD 流）→ 2.0 Structured Streaming 转正——**把流当"无界表"（unbounded table）用同一套 DataFrame API 处理**；
- 章首"演变/微批出现"两节复述流计算通史：低延迟诉求催生 Storm 类逐事件引擎，吞吐与容错代价催生微批复兴（Spark Streaming），再到"批流一套 API"的统一主张；
- 2e 的哲学表述（重构转述）：**流是批的连续极限**——查询定义不变，执行按增量批次推进；Exactly-once 靠 checkpoint + 幂等/事务 sink 达成。这套叙事与 Google《Streaming Systems》的"统一时间"观点同期，本书是工程侧同调者。

## 8.2 编程模型与五步骤

1. 定义 source（`readStream.format("kafka"/"file")`）；
2. 定义转换（无界表上照常 DataFrame 操作）；
3. 定义 watermark（事件时间迟到界限，状态清理依据）；
4. 定义 sink + output mode（append/complete/update）+ trigger（默认微批节奏/processingTime/once/availableNow 前夜）；
5. `start()` 起跑，`awaitTermination()` 挂住，查询在后台循环。

- **主动查询内部机制**：每轮触发把"新增输入段"合入执行计划、复用编译缓存、增量状态更新——书里明说"查询不是重启的作业，是带状态的常驻计划"。

## 8.3 状态与聚合（本章硬核）

- **有状态聚合**：`groupBy().agg()` 在流上按窗口/键维持增量状态；`mapGroupsWithState`/`flatMapGroupsWithState`（粗粒度状态 API，⚠️ 转述）给自定义状态机；
- **Watermark 三合一职责**：允许迟到、界定窗口完成、触发状态删除——错设=结果漂移或状态爆炸；
- **流-静态 join**：维表侧版本化（`join(withWatermark(dim))` 的 as-of 语义，2.0 引入）；**流-流 join**：双边窗口约束（watermark 界定保留区间）；
- **增量执行**：输出只动"变化的键"（update 模式）是吞吐红利来源。

🔧 **微批增量聚合模拟（非本书 Spark 引擎行为）**：SQLite 3.45.3/WAL 复刻"批次→增量 upsert"结构（meas.txt G5 组）：5 个批次×200 行事件表 `events(id,k,v,batch)`，每批执行
`INSERT INTO agg SELECT k,count(*),sum(v) FROM events WHERE batch=? GROUP BY k ON CONFLICT(k) DO UPDATE SET cnt=cnt+excluded.cnt, sumv=sumv+excluded.sumv` 后 commit；总耗时 **1187.1ms**（含建库/插入），最终 7 键聚合各 142–143 行、sumv 与全量重算一致。**教学点**：①"每批只处理新段 + 状态表按键 upsert"正是 Structured Streaming 增量聚合的最小模型；②append-vs-update 输出对应 ON CONFLICT 写法的取舍；③批次的 commit 边界≈checkpoint 的容错边界（Spark 侧实现细节 ⚠️ 转述，不做等价保证）。

## 8.7 重建示例：五步骤落码 + 监控钩子（本目录重做；⚠️ 语义转述官方 SS 指南 ✅）

```python
from pyspark.sql import functions as F

q = (spark.readStream.format("kafka")
        .option("topic", "orders").option("bootstrap.servers", "b:9092").load()
     .select(F.from_json(F.col("value").cast("string"),
                         '{"id":LONG,"k":STRING,"v":DOUBLE,"ts":TIMESTAMP}').alias("j"))
     .withWatermark("j.ts", "10 minutes")                        # 步骤3：迟到界限
     .groupby(F.window("j.ts", "1 minute"), "j.k")
     .agg(F.sum("j.v").alias("s"), F.count("*").alias("n")))

(q.writeStream.outputMode("update").trigger(processingTime="30 seconds")
    .option("checkpointLocation", "ck/orders")
    .foreachBatch(lambda b, i: b.write.mode("append").insertInto("agg_orders")).start())

# 监控钩子（镜像小节对应件）：
#   q.lastProgress / q.recentProgress          —— StreamingQuery 状态
#   .option("metrics.receiver", true)          —— Dropwizard 导出
#   q.addListener(MyQueryListener())           —— 自定义监听（onQueryProgress 里发告警）
# 任意状态（3.x 线）：flatMapGroupsWithState(timeoutConf=ProcessingTimeTimeout(5))
```

## 核心概念速览（中英对照）

- **无界表** — Unbounded Table：流=不断追加的表的世界观。
- **readStream/writeStream** — 流式读写的对称入口。
- **Trigger** — 触发节奏：默认微批/processingTime/once。
- **Output Mode** — append/update/complete 三态输出语义。
- **Watermark** — 迟到界限+状态清理+窗口完成的三重闸门。
- **Stateful Aggregation** — 按键维持增量状态的聚合。
- **mapGroupsWithState** — 粗粒度状态机 API（⚠️ 转述）。
- **Stream-Static Join** — 流×版本化静态维表（as-of 语义）。
- **Stream-Stream Join** — 双流水窗 join：窗口约束保正确性。
- **Checkpoint Location** — 位点+状态容错目录。
- **foreach/foreachBatch** — 自定义落库；3.0 批流合写枢纽。
- **Exactly-Once** — 端到端一次语义：幂等/事务 sink + 位点。
- **DStream** — 旧微批 API（演变史坐标）。
