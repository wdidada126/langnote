# 01 · 内部服务导论（Internal Services: What and Why）

> ⚠️ 本章为**主题重构口径**（原书 TOC 不可达，见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §3）；内容是基于该书主题域公开共识、Oracle 官方文档与本目录取证结论的**精读重构**，不是原书文本。Oracle 不可本机实测：一切 Oracle 行为为 ⚠️ 转述；🔧 段为**非 Oracle** 的 SQLite 类比实测。

## 1.0 本章导读

「内部服务」四个字是进入本册全部六章的钥匙。本章回答三个问题：这个词指什么（1.1）、为什么 1999 年需要一本书专门讲它（1.2）、观测它的门在哪里（1.3），并在 1.4 划定边界、1.5 用一次本机实验让你亲手摸到"引擎自描述"是什么手感（🔧 非 Oracle）。

## 1.1 「内部服务」是什么

「内部服务」（Internal Services）是 Steve Adams 为本书确立的命名框架（✅ 书名自题）：把数据库引擎内核里**不直接对应任何 SQL 语义、却决定一切 SQL 能否正确且高效执行**的四组机制并列——

1. **Waits（等待服务）**：会话"不在 CPU 上跑"的每一秒都在回答"我在等什么"。→ [02-等待服务.md](02-等待服务.md)
2. **Latches（闩锁服务）**：保护 SGA 内链表/哈希桶等易变结构的轻量串行化。→ [03-闩锁服务.md](03-闩锁服务.md)
3. **Locks（锁服务）**：以数据库对象（行、表、事务）为语义的可排队序列化。→ [04-锁服务.md](04-锁服务.md)
4. **Memory（内存服务）**：SGA/共享池/库缓存的分配、钉住（pin）与淘汰。→ [05-内存与共享池.md](05-内存与共享池.md)

⚠️ 转述：四者的共同点是**都活在共享内存里、都有专属的动态性能视图可观测**——这正是 134 页短文能"以薄写深"的原因：不讲 SQL、不讲存储管理，只讲这四张视图背后发生了什么。

## 1.2 为什么 DBA 需要内部服务视角（8i 时代的动机）

⚠️ 转述（社区长期共识，与本书出版同期）：

- **统计量是平均值，问题发生在瞬间**。`v$sysstat` 的累计命中比率会掩盖一次 3 秒的闩锁风暴；只有等待/闩锁/锁的**实例级视图**能还原"那一刻谁在等什么、谁持有它"。
- **调优的因果链在内部服务里**：一条 SQL 慢 → 会话在某等待事件上 → 事件指向某闩锁/锁/内存结构 → 根因在并发设计或内存配置，而非 SQL 本身。这条链在今天的 ASH 时代依旧成立（见 [../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md](../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md) 的时间模型，它是本链的现代仪器化）。
- **8i 的诊断窗口是"瞬时+事后"**：没有 ASH、没有 AWR（AWR 要等 10g 的 STATSPACK 进化，⚠️），`v$session_wait` 只能看当下——所以本书教的是"持续采样 + 联查"的手艺，本目录 [06-内部视图观测与调优.md](06-内部视图观测与调优.md) 重构的正是这门手艺。
- 一个时代注脚（⚠️ 转述）：90 年代末 Oracle 性能社区正从"猜参数"转向"读事件"，本书与同时期 Millsap 的响应时间学说是同一转向的两翼——前者讲"内核在做什么"，后者讲"该看哪张表"。
- 本书的体裁（⚠️ 推断）：134 页 = 短文小册子（O'Reilly Safari 时代常见形态），注定"密度换广度"——四服务各给一张机制图与一组视图读法，不追求全景。
- 对读者的先修要求（重构口径）：懂 SQL、知道实例/会话/进程三概念、最好读过一份 Oracle 概念指南（[#44 Oracle_Essentials_5e](../Oracle_Essentials_5e/00-总览与阅读地图.md)，✅ 已落盘互验）即可进入本册。

## 1.3 观测入口：V$ 视图与 x$ 固定表

⚠️ 转述（架构常识层，与现行文档一致）：

| 入口 | 对象 | 说明 |
|---|---|---|
| `x$` 固定表 | 内核数据结构的直接透视 | 由固定 VAM 驱动"表"化，列名贴近 C 结构体 |
| `V$` 视图 | x$ 上的语义化封装 | v$session_wait / v$latch / v$lock / v$sga 等 |
| 统计类 | 累计计数器 | v$sysstat、v$latch 的 gets/misses/sleeps |
| 参数类 | 配置面 | v$parameter（含隐藏参数族 ⚠️ 本书基本不碰） |

- 权限现实：查 `x$` 需要 SYS 或专属权限，普通调优在 `V$` 层即可完成——本书篇幅也基本停在 V$ 层（⚠️ 推断，TOC 不可达）。
- 现行文档佐证：`V$SESSION_WAIT`、`V$LATCH` 至今仍是 Oracle Database 23ai 的文档化参考视图（✅ URL 见文末两节），列语义与 8i 一脉相承。
- 常用入口速记（⚠️ 视图名转述）：会话=v$session；等待=v$session_wait；闩锁=v$latch（含 name/level）；锁=v$lock；块态=v$bh；内存=v$sga/v$sgastat；累计=v$sysstat/v$system_event。
- 词汇预告：视图列 `EVENT`/`P1TEXT..P3TEXT`/`STATE=WAITING|WAITED SHORT TIME|...` 的组合读法在 02 章展开；`GETS/MISSES/SLEEPS` 在 03 章；`LMODE/REQUEST/BLOCK` 在 04 章；`HIT_RATIO` 一族陷阱在 05 章。
- 一条实用提醒（⚠️）：V$ 视图行集是"活的"，同一条查询连跑两次结果可不同——这是本章 06 章纪律"一次改一个变量、读数成对记录"的微观理由。

## 1.5 🔧 类比实测 G1：引擎的"自描述"到底长什么样（非 Oracle）

Oracle 用 x$/V$ 把内核状态摊开；SQLite 同样把"编译期事实"做成可查询对象。🔧 本机实测（Python 3.13.2 / sqlite 3.45.3，Windows；输出存 `D:\develops\tmp\dbwave_w7_oraint\ch01_probe.txt`）：

```sql
select * from pragma_compile_options;   -- 43 行：COMPILER=msvc-1942、DEFAULT_CACHE_SIZE=-2000 …
select sqlite_version();                -- 3.45.3
pragma journal_mode;  -- 内存库返回 memory
pragma locking_mode;  -- normal
pragma page_size;     -- 4096
pragma cache_size;    -- -2000（= 约 2 MB）
```

- 观察 1：`pragma_compile_options` 是一张"固定表"味十足的透视集——**构建期常量**直接暴露为行集，对应 Oracle 里 `v$version`/编译参数类透视（⚠️ 类比转述）。
- 观察 2：`pragma cache_size` 返回 `-2000` 这类"带符号语义"的值（负数=KB 口径），与 Oracle 参数"单位隐藏在值的形态里"的风格形似（⚠️ 类比）。
- 观察 3：`:memory:` 库上 `pragma mmap_size` **返回空行集**（实测 TypeError 源头）——透视面会因上下文不同而"有列无值"，这恰是查 V$ 视图时"某些列为 NULL 因实例形态而异"的同类体验（⚠️ 类比）。
- 方法复现：`sqlite3 :memory:` 执行上述语句即可。
- 边界：SQLite 没有并发共享内存，因此它的"自描述"只有**配置态**，没有**争用态**；后者的对照实验在 [02-等待服务.md](02-等待服务.md)/[03-闩锁服务.md](03-闩锁服务.md)（🔧 busy_timeout、checkpoint）。
- 本实验与本册的接缝：Oracle 固定表/动态视图提供的是**运行时争用面**，`pragma_compile_options` 只提供**构建面**——读透这一层差距，06 章联查图才知道自己缺了什么（⚠️ 类比校准）。

## 核心概念速览（中英对照）

- **内部服务** — Internal Services：waits/latches/locks/memory 四组内核机制的统称，本书命名框架。
- **等待事件** — Wait Event：会话非 CPU 活动的一次"在等什么"的具名记录。
- **闩锁** — Latch：SGA 内部结构的轻量互斥，快速获取快速释放，无对象语义。
- **锁** — Lock（Enqueue）：带对象语义（表/行/事务）的可排队序列化机制。
- **动态性能视图** — Dynamic Performance View（V$）：内核状态的关系化透出口。
- **固定表** — Fixed Table（x$）：V$ 视图底层的内核结构直读表。
- **VAM** — Virtual Access Method：固定表把内存结构伪装成表的可插拔访问机制（⚠️ 术语转述）。
- **瞬时视图** — Point-in-Time View：只反映"此刻"、需靠采样累积历史的视图形态。
- **统计计数器** — Statistics Counter：gets/misses/sleeps 这类累计量，平均化会掩盖尖峰。
- **编译期选项透视** — Compile-Options Introspection：SQLite `pragma_compile_options`，引擎自描述的类比样本（🔧 实测 43 行）。
- **DB Time** — Database Time：CPU 时间 + 非空闲等待之和，等待世界观的总账（⚠️ 后视转述）。
- **主题重构** — Topic Reconstruction：TOC 不可达时以书自题元素重建章序的降级方法（本册全目录适用）。
