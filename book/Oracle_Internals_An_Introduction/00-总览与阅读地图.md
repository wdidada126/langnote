## 核心概念速览（中英对照）

- **内部服务** — Internal Services：Steve Adams 对本册主题的命名，指引擎内核里管理等待、闩锁、锁、内存的机制集合。
- **等待接口** — Wait Interface：会话以事件为单位记录「在等什么」的机制，8i 时代入口是 V$SESSION_WAIT。
- **闩锁** — Latch：保护 SGA 内部结构（链表/哈希桶）的轻量串行化原语，无对象化持有语义。
- **锁/入队** — Lock / Enqueue：以数据库对象为语义、可排队可持有的显式序列化机制。
- **自旋与挂起** — Spin and Sleep：闩锁未命中先 CPU 重试，超阈值转入等待队列。
- **SGA** — System Global Area：多进程共享的实例内存区（缓冲池+共享池+日志缓冲等）。
- **共享池 / 库缓存** — Shared Pool / Library Cache：缓存 SQL 解析产物（游标、句柄、pin）的 SGA 分区。
- **钉住计数** — Pin Count：内存对象被使用时免淘汰的引用计数机制。
- **固定表** — Fixed Tables（x$）：内核数据结构的透视表，V$ 视图的底座。
- **主题重构** — Topic Reconstruction：TOC 不可达时按书自题元素重建章结构的降级方法（本册适用）。
- **辨析建档** — ISBN Disambiguation：同名/近号书目按 13 位 ISBN+机读记录判定并档或独立（本册 §2 判独立）。
- **校验位重算** — Checksum Recomputation：ISBN-10 模 11 / ISBN-13 模 10 的手工验号法（本册两号均验 ✅）。
- **引而不证** — Cite-but-not-evidence：403 反爬页可引用不作内容依据的取证红线（O'Reilly 全站适用）。

## 最新演进与工业实践

- **等待接口到 ASH/AWR**（⚠️ 转述）：V$SESSION_WAIT 在 11g 后被 V$ACTIVE_SESSION_HISTORY 秒级采样取代，8i「事后拼快照」进化为「连续时间线」；现行文档 [https://docs.oracle.com/en/database/oracle/oracle-database/23/refrn/V-SESSION_WAIT.html](https://docs.oracle.com/en/database/oracle/oracle-database/23/refrn/V-SESSION_WAIT.html) ✅ 本机验证（302 跟随后 200，终页并入 26ai 文档树）。
- **闩锁统计口径延续**：V$LATCH 仍是官方文档化视图，23ai 文档 [https://docs.oracle.com/en/database/oracle/oracle-database/23/refrn/V-LATCH.html](https://docs.oracle.com/en/database/oracle/oracle-database/23/refrn/V-LATCH.html) ✅ 可达；现代闩锁争用多让位于 mutex/细粒度并发（11g+），属 ⚠️ 转述。
- **作者谱系**：Steve Adams 的等待服务研究由 Oracle 调优社区长期引用；本册机读记录 [https://book.douban.com/subject/1458922/](https://book.douban.com/subject/1458922/) ✅。
- **同名书澄清**：Auerbach 2001《Oracle Internals》为无关同名书，Crossref 记录 [https://api.crossref.org/works/10.1201/9780203997536](https://api.crossref.org/works/10.1201/9780203997536) ✅ 200（作者字段缺失 ⚠️）。
- **类比工具现状**（✅ 本环境经代理实抓；直连 curl 不可达已注明）：SQLite 等待处理 [https://sqlite.org/c3ref/busy_timeout.html](https://sqlite.org/c3ref/busy_timeout.html)、WAL [https://sqlite.org/wal.html](https://sqlite.org/wal.html)、共享缓存锁模型 [https://sqlite.org/sharedcache.html](https://sqlite.org/sharedcache.html)——本目录 🔧 实验全部对齐上述现行行为。
- **工业实践一笔**（⚠️ 转述）：现代云/自治数据库不再向用户暴露闩锁/入队细节，争用分析收敛到「等待事件 + TOP SQL」两层；本册这类内核服务书的价值转为「理解等待语义的底层原理」，与 [../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md](../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md) 的现代工具箱互为头尾。
