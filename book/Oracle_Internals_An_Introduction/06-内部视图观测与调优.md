## 6.1 联查图：四视图如何拼出"那一刻"

⚠️ 转述（8i 现实：无 ASH/AWR，观测＝自写采样循环 + 快照差分）：

```
v$session ──sid──► v$session_wait ──p1/事件名──► v$latch / v$lock / (文件,块)
     ▲                        │
     └──统计背景: v$sysstat、v$system_event 两次快照差分 ÷ Δt
```

三步定位法（本书世界观的操作性总结）：

1. **谁在等**：循环采 `v$session_wait`，聚非空闲事件直方图（短等待靠增量兜底——[02-等待服务.md](02-等待服务.md)）。
2. **等什么**：事件参数落到对象——latch 地址 → `v$latch` 指名（[03-闩锁服务.md](03-闩锁服务.md)）；enqueue ID → `v$lock` 找 `BLOCK=1` 的持锁者（[04-锁服务.md](04-锁服务.md)）；文件/块号 → `v$bh` 看块态（[05-内存与共享池.md](05-内存与共享池.md)，state=CUR/current 时顺会话反查持有者 ⚠️）。
3. **谁持有**：8i 的缺口在这里——`x$latchholder`/oradebug 类手段属 SYS 域（⚠️ 推断，细节不展开），社区此后以 STATSPACK（8.1.6 起，⚠️）与自写 trc 脚本补洞。

采样伪代码（重构，工具无关）：

```
repeat: snapshot(v$session_wait where state='WAITING')
        sleep(0.1s)
until 结束条件
聚合: 按 (事件, p1..p3, sql_hash_value) 计数 → 直方图 + 众数参数
```

- 参数取值经验（⚠️ 转述）：采样间隔取"短等待均值的 1/3~1/5"；过密会把采样器自己变成争用者（6.3 的镜像教训）——这一权衡正是 ASH 把间隔定为 1 s 的历史前情。
- 记录纪律：每轮采样落盘"时间戳+读数"两列，事后任何结论都要能指回某一对原始行；凭记忆描述的"当时看到 latch free"不算证据。

## 6.3 🔧 类比实测 G3b：读者快照限制日志回收——"观测者改变被观测系统"（非 Oracle）

🔧 实测（脚本 `D:\develops\tmp\dbwave_w7_oraint\exp_sqlite.py`，sqlite 3.45.3，读数存 `exp_results.txt`）：

```
连接 R: BEGIN; SELECT count(*) FROM t        # 持旧快照不放
连接 W: 再写 1500 行并提交 → WAL = 684 KiB
W: PRAGMA wal_checkpoint(PASSIVE) → (0, 170, 0)，WAL 仍 684 KiB
（对照无读者时同容量检查点 (0,336,336) → TRUNCATE 后 0 KiB）
```

- 读法：读者把 WAL 的"可复制前缀"钉死在它的快照点——**检查点无法越过最老活动读者**，日志空间被观测者本身撑大。这正是 Oracle "长查询/未提交事务 ⇒ undo 膨胀 + 日志复用点受检查点队列牵制"的镜像实验（⚠️ 类比：Oracle 靠 undo 保读、靠 checkpoint 队列保 redo 回收，机制不同、"最老一致性需求决定回收界"这一守恒律同形）。
- 观测学教训同构：在 8i 轮询 V$ 视图本身就是负载（共享池/闩锁压力）——**采样器也是争用者**；现代 ASH 以内存内 1Hz 快照摊薄该成本（⚠️ 转述）。
- 复跑要点：读者连接必须**保持事务不结束**（BEGIN 后已读），写者提交后再触发 PASSIVE——顺序颠倒则挡不住。
- 台账一致性：G3 与 G3b 同容量检查点返回从 (0,336,336) 退化为 (0,170,0)，唯一变量是读者快照——单变量对照是 🔧 块能进目录的门槛（00 §7）。

## 6.5 排错脚本之外：方法论的三条纪律（重构）

⚠️ 转述（通行纪律，本册时代与今天同义）：

1. **先量后猜**：任何"我觉得是 XX 问题"必须先有联查图上的一个读数支撑；没有瞬时证据就退而看增量差分（6.1）。
2. **一次改一个变量**：spin_count/共享池尺寸/提交模式的调整互相纠缠（03×05 章闭环），A/B 快照序列是唯一诚实的记录。
3. **区分慢性与风暴**：`v$sysstat` 累计值抓慢性，采样循环抓风暴——8i 工具面只给你这两种镜子（ASH 之后才有"任意时刻回放"）。

## 6.6 场景演练（重构，⚠️ 转述级）

1. **风暴现场**：用户报"整点卡 10 秒"→ 采样循环 1 分钟 → 直方图众数 `latch: library cache`，p2 同值 → `v$latch.name` 确认 → 病因指向解析风暴 → 处方：游标共享检查（`v$sysstat` parse counts 差分）→ 机制回读 [03-闩锁服务.md](03-闩锁服务.md)/[05-内存与共享池.md](05-内存与共享池.md)。
2. **慢性出血**：吞吐缓慢下滑无瞬时异常 → `v$lock` 差分发现同一 TX 锁排队常态化 → 热点行（计数更新）→ 处方在应用设计（[04-锁服务.md](04-锁服务.md) 4.5）。
3. **假警报**：`log file sync` 均值 8 ms 次数巨大 → 查 LGWR 侧 `log file parallel write` 是否同步恶化 → 是则存储面、否则组提交面（05 章 G7 的类比直觉：提交形态决定日志成本，🔧 非 Oracle 数字）。

## 核心概念速览（中英对照）

- **联查图** — Join Map：session→wait→latch/lock/块 的三段定位路径（8i 手工版）。
- **采样循环** — Sampling Loop：轮询瞬时视图把短等待攒成直方图的手艺。
- **快照差分** — Snapshot Delta：累计计数器两次读数相减得速率。
- **持有者定位** — Holder Identification：找"谁占着闩锁/锁"的（8i 最难）一步。
- **观测者负载** — Observer Effect：采样查询自身制造共享池/闩锁压力（🔧 G3b 同构教训）。
- **最老一致性需求** — Oldest Read Point：日志/undo 回收界由最老活动读者决定（🔧 G3b 实证形态）。
- **STATSPACK** — 快照报告工具：8.1.6 起的官方差分报告器，AWR 前身（⚠️ 后视转述）。
- **症状—机制—处方** — Symptom–Mechanism–Remedy：本册方法论的三段式。
- **CPU 迷雾** — CPU Masking：等待视图无异常而系统慢的误诊态（⚠️ 转述）。
- **v$bh** — Buffer Header 视图：块副本状态级观测面（⚠️ 转述）。
- **机制—模型—方法三角** — 本册×CBOF×TOP2e 的盘上分工（目录级自述）。
