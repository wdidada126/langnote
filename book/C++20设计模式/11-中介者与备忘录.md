# 11 中介者模式与备忘录模式（对应原书第 17–18 章）

> 对应原书第三部分（行为型）第 17 章「中介者模式」、第 18 章「备忘录模式」（推定英文章题 Mediator / Memento ⚠️）。
> 合并理由：两模式都处理「对象间耦合的**形状**」——Mediator 把网状依赖压成星型，
> Memento 把「暴露内部状态以保存/恢复」压进不透明令牌；一收通信，一收状态。

## 核心概念速览（中英对照）

- **中介者** — Mediator：用一个中心协调者封装对象间的交互，各同事只认识中介。
- **同事** — Colleague：参与协作、彼此不再直接引用的对象。
- **星型 vs 网状** — star vs mesh：Mediator 的结构收益——N 个对象互知从 O(N²) 降为 O(N)。
- **事件中介** — event-based mediation：中介=事件总线，同事发事件/订事件——与 Observer 的合体形态（见第 12 章）。
- **空气中介反模式** — mediator as god object：中介积累全部业务逻辑，同事退化成空壳——Mediator 的头号病灶。
- **备忘录** — Memento：在不破坏封装的前提下捕获对象状态并稍后恢复。
- **发起人/负责人** — Originator / Caretaker：状态的owner / 保存恢复时序的保管者。
- **不透明备忘录/窄接口** — opaque memento：C++ 惯用手法——备忘录的存还原只对发起人可见（友元/pimpl），负责人只见空壳。
- **快照** — snapshot：值语义下的备忘录=一次拷贝；「恢复」=一次赋值/移动。
- **RAII 令牌** — RAII token/scope guard：离开作用域自动还原——备忘录与守卫代理的组合惯用法（原书第 1 版即有 "RAII memento" 讨论 ⚠️ 术语推定）。
- **检查点** — checkpoint：持久化系统的备忘录（数据库快照、文件版本）——工业级命名。

## 动机：耦合的两副面孔

- **Mediator**：对话框里「确定/取消/输入框/复选」彼此知道对方存在，改一个控件牵一片；
  聊天室里人人互相广播。中介者把「谁知道谁」换成「谁知道规则」。
- **Memento**：撤销栈、事务回滚、存档点——都需要「在某时刻冻结对象，稍后解冻」；
  若靠公开 getter/setter 逐字段搬运，对象的**内部表示**就泄漏给了保管者。

## 机制

### 中介者：两种体质

🔧（教学示意）

```cpp
struct ChatMediator;
struct User {
    std::string name; ChatMediator& med;
    void send(const std::string& msg);            // 只认识中介
};
struct ChatMediator {
    std::vector<User*> users;
    void broadcast(const std::string& msg, const User* from) {
        for (auto u : users) if (u != from) u->receive(msg);   // 规则集中在此
    }
};
```

- **被动中介**（事件总线）：只路由不决策——退化成消息系统；**主动中介**（状态机+校验）：业务规则所在。
- C++20 表达：中介持有的同事集合用 `std::vector<colleague*>` + 生命周期协议，或用信号槽把「注册/注销」外包（见 [12-空对象与观察者.md](12-空对象与观察者.md)）。

### 备忘录：值语义 + RAII

🔧（教学示意）三种体质：

```cpp
// 1) 快照备忘录：C++ 里 memento == 拷贝（值语义红利）
class Editor {
    struct State { std::string text; int caret; };
    State s_;
public:
    State save() const { return s_; }                 // 备忘录=不可拆的黑盒值
    void restore(const State& m) { s_ = m; }
};

// 2) RAII 令牌：作用域结束自动还原（原书风格的 C++ 惯用法 ⚠️ 推定）
class FlagGuard {
    bool& f_; bool old_;
public:
    explicit FlagGuard(bool& f) : f_(f), old_(f) {}
    ~FlagGuard() { f_ = old_; }
};

// 3) 不透明备忘录：窄接口+友元，负责人看不到内容
class ConfigMemento;                    // 负责人只见类型名，不见字段
class Config {                          // Originator
    std::map<std::string,std::string> d_;
public:
    ConfigMemento capture() const;      // 定义处才能碰 d_
    void restore(const ConfigMemento&);
    friend class ConfigMemento;
};
class ConfigMemento {
    std::map<std::string,std::string> d_;
public:
    explicit ConfigMemento(const Config& c) : d_(c.d_) {}
};
```

- **GoF 三对象分工**（Originator/Caretaker/Memento）在值语义语言里的压缩版：
  快照就是一个 `State` 拷贝；封装靠**接口纪律**（别把 State 字段公开）而非 C++ 访问控制也能成立，
  真要硬隔离就上友元/pimpl。
- **撤销栈** = `vector<Memento>`；巨型对象用**增量备忘录**（diff/CRDT 思路）而非全量拷贝。

**反模式/何时不用**：

- **中介者变上帝类**：所有 if 都搬进中介——检验标准：中介应只有「协调规则」没有「业务实现」。
- **事件总线当银弹**：类型化消息表 + 字符串主题名 = 第二套私有 RPC；规模一大需要 schema 治理（与 [03-工厂方法与抽象工厂.md](03-工厂方法与抽象工厂.md) 的注册表同病）。
- **无界备忘录栈**：每步全量快照，内存 O(操作数×对象大小)；设上限/落盘/增量三选一。
- **RAII 令牌用于跨作用域恢复**：令牌的生命周期=还原时机，撤销栈要的是**显式存储**——别混用两种备忘录。

## 权衡与相邻概念对比

| 维度 | Mediator | Observer | Command | Memento |
| --- | --- | --- | --- | --- |
| 通信拓扑 | 星型（经中心） | 一对多广播 | 点对点（封装后） | 无通信，只存取状态 |
| 谁掌握规则 | 中介 | 无（订阅者各自） | 命令对象 | 发起人 |
| 可撤销性 | 取决于是否配命令栈 | 否 | **是** | **是**（恢复即撤销） |
| 耦合方向 | 同事→中介单向 | 主题→观察者单向 | 调用者→接收者 | 负责人↔备忘录（不透明） |
| 现代对应物 | 事件总线/ECS/actor | signals/slots | 任务/事件溯源 | 快照/版本控制/CRDT |

**Mediator vs Facade**：Facade 在子系统**外面**收窄接口（单向调用），Mediator 在同事**中间**转发交互（双向协调）——见 [07-外观与享元.md](07-外观与享元.md)。
**Memento vs Prototype vs Flyweight**：Prototype 复制了**继续用**（要新身份），Memento 复制了**存起来**（要恢复旧我）；Flyweight 根本不想复制（见 [04-原型与单例.md](04-原型与单例.md)、[07-外观与享元.md](07-外观与享元.md)）。

## 最新演进与工业实践

- **经典文献**：GoF 1994 之 Mediator / Memento 条（书目见 [../设计模式GoF/04-行为型模式.md](../设计模式GoF/04-行为型模式.md)）。
- **C++20→26**：C++26 静态反射（P2996，2025 年起草定稿含之 ✅）对备忘录是「自动快照生成器」——字段级遍历免手写 save/restore；
  对中介者是消息 schema 的编译期登记——事件总线从字符串主题走向类型化路由。
- **工业体现**：
  - **EnTT（skypjack/entt）**：ECS 的 `registry.on<Comp>()` 信号 + group 调度=「数据级 Mediator」——实体互不认识，协调在注册表。
  - **Qt**：`QCoreApplication`/事件过滤器链=中介；`QUndoStack` 内部存命令+目标状态=Command+Memento 合成。
  - **leveldb/rocksdb**：`Snapshot`（版本链上打点、读时可见性冻结）+ `Checkpoint/BackupEngine`=持久化备忘录；
    WAL+回滚=事务级 save/restore。
  - **编辑器/IDE 生态**：Vim diff 模式、VSCode 的 local history、Git 的对象库=进程外的备忘录工业形态。
- **2026 判断**：Mediator 的教学正例越来越少（事件总线/服务编排接管），
  但「中介的 god object 化」警告在微服务编排器（Orchestrator）语境里逐字适用（见 [../微服务架构设计模式.md](../微服务架构设计模式.md)）；
  Memento 在值语义 + diff/CRDT 生态里从「类模式」升格为「系统能力」（快照、时间旅行调试、可重复构建）。
