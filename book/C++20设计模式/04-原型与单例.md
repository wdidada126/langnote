# 04 原型模式与单例模式（对应原书第 4–5 章）

> 对应原书第一部分（创建型）第 4 章「原型模式」、第 5 章「单例模式」（推定英文章题 Prototype / Singleton ⚠️）。
> 两章合并成篇：它们是创建型里互为镜像的一对——Prototype 回答「对象从**样本**来」，Singleton 回答「全世界只有**这一个**」。
> 原书单例章含大量「单例的坏味道」讨论（按第 1 版结构推定 ⚠️），本章照此基调并补 C++23 之后的实践。

## 核心概念速览（中英对照）

- **原型** — Prototype：以现有实例为模板，`clone()` 出可改写的副本，避免子类化工厂。
- **虚拟拷贝/多态拷贝** — polymorphic copy：基类指针下造出**同派生类**的新对象，Prototype 的正式问题陈述。
- **克隆中转层** — clone middleware（`virtual_clone_base` ⚠️ 本书第 1 版术语，原样推定）：一层 CRTP 适配器，把「写两个 clone」缩成「声明基类」。
- **原型注册表** — prototype registry：`map<key, prototype*>`，按样本键控生成新对象，是 Prototype 与注册式工厂的合体。
- **值语义拷贝** — value semantics：C++ 中 `T b = a;` 天然就是原型拷贝；Prototype 模式只在下有多态时才挣得存在权。
- **单例** — Singleton：保证一个类仅一个实例并提供全局访问点。
- **Meyers 单例** — Meyers' Singleton：`static Inst& i() { static Inst inst; return inst; }`——函数内局部 static。
- **线程安全初始化** — thread-safe init：C++11 起 magic statics 保证局部 static 初始化恰好一次且并发安全。
- **双检锁** — double-checked locking：magic statics 之前的手工方案；今天仅作历史与内存序教学案例。
- **静态初始化顺序灾难** — static init order fiasco：跨翻译单元全局对象顺序未定义；单例的第一坑。
- **依赖注入** — dependency injection：单例的现代替代品——把「那个唯一对象」作为构造参数传入而非全局索取。
- **`NoDestructor`/`Permanent` 存储** — leaked singleton 家族：故意不析构以躲开销毁顺序问题（abseil 提供 `absl::NoDestructor` ✅ 该工具存在）。

## 动机：两个「构造的例外」

- Prototype 的动机：工厂方法要求「知道类型才能造类型」；当你只有**一个别处的对象**而没有类型信息
  （多态基类指针、插件给的样本），唯一出路是让对象自己会复制自己。
- Singleton 的动机：某些资源天然唯一——日志、配置、硬件句柄、窗口系统连接；
  多处 `new` 它们要么浪费（重复状态），要么错误（破坏系统级唯一性）。
  注意 GoF 原文口径是「保证仅一个实例 + 提供全局访问点」两个约束，**后者才是被后世诟病的部分**。

## 机制

### 原型：三层写法

🔧（教学示意，模式结构已实测等价于 g++ 15.2 下可编译的双分派骨架）朴素双 clone + CRTP 中转层：

```cpp
struct Poly {
    virtual ~Poly() = default;
    virtual std::unique_ptr<Poly> clone() const = 0;
};
template <typename Derived, typename Base = Poly>
struct PolyClone : Base {
    std::unique_ptr<Poly> clone() const override {
        return std::make_unique<Derived>(static_cast<const Derived&>(*this)); // 依赖值拷贝
    }
};
struct Line : PolyClone<Line> {
    std::vector<Point> points;
};
```

要点：中转层把「每个派生类写一次 `clone` 样板」压缩成一次继承；
真正干活的是 C++ 的**值语义拷贝构造**——这是 GoF 时代用 Smalltalk/C++ 裸指针讲 Prototype 时不存在的前提。

**原型注册表**：`unordered_map<string, shared_ptr<const Prototype>>` + 工厂函数 `create(key)` → `pool[key]->clone()`。
与 [03-工厂方法与抽象工厂.md](03-工厂方法与抽象工厂.md) 的注册式工厂同构，差别在注册的不是构造函数而是**样本实例**——
新对象携带样本的全部字段值（配置类对象的正确克隆姿势）。

### 单例：现代最小形态

🔧（已实测 g++ 15.2 同型骨架，见 t4）：

```cpp
class Config {
public:
    static Config& instance() { static Config c; return c; }
private:
    Config() = default;
};
```

- C++11 magic statics 使上述写法**懒初始化 + 线程安全**，双检锁彻底退役。
- 禁拷贝/禁移动（`= delete`），否则「全局唯一」被一个 `Config c2 = Config::instance();` 打破。
- 需要显式生命周期控制（测试注入假配置）时，退化为「普通类 + 依赖注入」，
  只保留一个可选的默认访问点——即「单例作为实现细节，不作为公共接口」。

**反模式/何时不用**：

- **单例作为全局可变状态**：隐式依赖不可测（测试间顺序污染）、隐藏耦合、析构顺序不可控。工业共识（Meyers、abseil 文档）是**能 DI 就 DI**。
- **Singleton 而非一次性资源**：只需一个实例时，一个 `static` 对象或函数内构造即可，不需要类级别的模式。
- **Prototype 滥用**：拷贝即切片——忘写 `clone` 中转层的派生类通过基类拷贝构造丢数据；用 CRTP 层把该义务编译期化。
- **值可拷贝时硬套 Prototype**：没有多态就没有模式，`T b = a;` 就是原型。

## 权衡与相邻概念对比

| 维度 | Prototype | Factory Method | Singleton |
| --- | --- | --- | --- |
| 新对象来源 | 既有样本 | 类型知识（代码） | 不适用（仅一个） |
| 类型知识在谁手里 | 被复制的对象自己 | 工厂子类/注册表 | 类自身（`instance()`） |
| 客户端改动成本 | 新增原型免改工厂 | 新增类型须动工厂侧 | 无扩展点 |
| C++ 里的天然支撑 | 拷贝构造/`clone` | `unique_ptr`+虚函数 | magic statics |
| 主要现代替身 | `shared_ptr<const T>` 共享样本 | 概念工厂/`variant` | DI 容器/显式传参 |

**Prototype vs Flyweight**：Prototype 造新副本，Flyweight 共享原件（见 [07-外观与享元.md](07-外观与享元.md)）——同样一张对象表，语义相反。
**Singleton vs 命名空间/全局函数**：无状态则用 namespace 常量；有状态但可配置则 DI——剩下「有状态且真全局」这一窄带才轮到 Singleton。

## 最新演进与工业实践

- **经典文献**：GoF 1994 之 Prototype / Singleton 条（书目见 [../设计模式GoF/02-创建型模式.md](../设计模式GoF/02-创建型模式.md)）；
  Meyers, *Effective C++* 3rd ed. Item 4（单例的自我复制问题）与 *Essential C++*（Meyers 单例定名出处）。
- **标准化口径**：C++11 [static.local]/magic statics（线程安全局部 static ✅ 语言事实，多译本称「魔性静态变量」）；
  无后续提案削弱该保证。C++20 `constinit` 给 POD 级全局以编译期初始化保证，是单例的零依赖替代之一。
- **工业体现**：
  - **abseil**：`absl::NoDestructor<T>`——故意泄漏、躲析构顺序的单例现代形态（官方文档 ✅ 存在性核实）。
  - **folly**：`folly::Singleton<T>`——带类型安全访问器与依赖声明的 DI 式单例容器。
  - **leveldb**：`Env::Default()` 进程级唯一环境对象——「资源句柄型」单例的正名案例。
  - **Qt**：`QCoreApplication::instance()`——平台约束下的合法单例；而 Qt 对「万物单例」同样持保留口径。
- **2026 判断**：教学语境里 Singleton 已滑向「反面教材区」（配合依赖注入讲）；
  工程语境里它收缩为两类残存——**进程级资源句柄**与**故意泄漏的配置/缓存**。Prototype 随值语义与移动语义普及而淡出，
  残存场景集中于多态容器元素拷贝（`vector<unique_ptr<Base>>` 深拷贝）。
