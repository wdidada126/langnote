# 10 解释器模式与迭代器模式（对应原书第 15–16 章）

> 对应原书第三部分（行为型）第 15 章「解释器模式」、第 16 章「迭代器模式」（推定英文章题 Interpreter / Iterator ⚠️）。
> 合并理由：两章共同回答「**结构化数据怎么被逐元素消费**」——解释器把语法树编成求值流程，
> 迭代器把聚合编成访问协议；且两者都是 C++20/23 语言设施吸收得最狠的模式（ranges/generator 正面覆盖）。

## 核心概念速览（中英对照）

- **解释器** — Interpreter：为特定领域小语言（DSL）构造文法表示并解释执行。
- **语法树节点** — grammar node：每产生式一个类/类型分支；解释器 = Composite 在语言构造上的应用。
- **上下文** — context：解释过程共享的环境（变量表、符号表、选项）。
- **终结符/非终结符** — terminal / nonterminal：树叶（数值、变量）与树枝（运算、语句）。
- **组合子解析** — parser combinator：用小解析器函数的高阶组合搭文法——解释器的免语法文件路线。
- **迭代器** — Iterator：顺序访问聚合元素而不暴露其表示。
- **迭代器范畴** — iterator categories：input/output/forward/bidirectional/random_access——C++20 用**概念格**（`input_iterator`⊂…⊂`random_access_iterator`）取代旧五类继承表。
- **哨兵** — Sentinel (`std::sentinel_for`)：C++20 中 begin/end 允许**异构类型**；终点可以是「空」「定长」「生成器耗尽」等任意停止条件。
- **不可达哨兵** — unreachable sentinel：无限范围（生成器流）的 end 类型，永不与 begin 相等。
- **range 概念** — `std::ranges::range`：「有 begin/end 且合法」的编译期谓词；聚合访问的统一契约。
- **代理迭代** — proxy iterator：`zip`/`transform` 的 `*it` 返回的不是引用而是值/代理对象——迭代器模式里的「按值通道」。
- **生成器** — `std::generator`（C++23）：协程版的拉取式迭代器；手写 iterator 的惰性序列退化成几十行 `co_yield`。

## 动机：两类「按结构消费」

- **Interpreter**：重复出现的小语法问题——正则式、查询 DSL、模板语言、配置表达式。
  为每个都上 Yacc/Bison 太重，手写 if-else 太烂；给文法一个对象模型，求值就交给多态。
- **Iterator**：容器作者与算法作者的**契约解耦**：算法不应知道 `list` 与 `vector` 的指针差别。
  GoF 时代的迭代器是**外部堆对象**（`reset()/next()/is_done()`），C++ 把它改造成**零成本值类型**——这是「模式被语言吸收」最纯粹的案例。

## 机制

### 解释器：variant 语法树 + visit 求值

🔧（教学示意；与 [06-组合与装饰器.md](06-组合与装饰器.md) 的表达式树同族）

```cpp
// 整数四则 DSL：Number | Plus | Minus
struct Num   { int v; };
struct Plus  { std::unique_ptr<struct Expr> l, r; };
struct Minus { std::unique_ptr<struct Expr> l, r; };
using Expr = std::variant<int, Plus, Minus>;   // 简化：树深=1 的教学版

int eval(const Expr& e) {
    return std::visit(overloaded{
        [](int v)        { return v; },
        [](const Plus& p)  { return eval(*p.l) + eval(*p.r); },
        [](const Minus& m) { return eval(*m.l) - eval(*m.r); }
    }, e);
}
```

- 运行时开放（加新类型=改 variant）与开放操作（加新函数=加个 visitor）的取舍，**整章在 [14-模板方法与访问者.md](14-模板方法与访问者.md) 展开**。
- 工业解释器很少用「每产生式一类」：lexer/parser 分离、访问循环解释字节码（Lua/CPython）——
  模式给的是**思维脚手架**不是实现蓝图。

### 迭代器：C++20 概念格与哨兵

🔧（教学示意）自定义范围：

```cpp
struct IntRange {                      // 不存 vector，按需生成
    int b, e;
    struct iter {
        int v;
        int operator*() const { return v; }
        iter& operator++() { ++v; return *this; }
        bool operator==(const iter& o) const { return v == o.v; }
    };
    iter begin() const { return {b}; }
    iter end()   const { return {e}; }
};
static_assert(std::ranges::range<IntRange>);
```

- C++20 起迭代器**不是类而是概念**：满足 `++`/`*`/`==`（或异构 `==`）协议即可进 ranges 管道。
- **哨兵解放终点**：`std::default_sentinel` 与流迭代器配对、`unreachable_sentinel` 表示无限流——
  终点不再被迫是「同类型的一个位置」。
- **范畴即约束**：算法模板用 `std::ranges::random_access_range<R>` 之类概念声明需求，
  不满足时报错回到调用点（concepts 的可读性红利，同 [03-工厂方法与抽象工厂.md](03-工厂方法与抽象工厂.md) 的概念工厂）。

**反模式/何时不用**：

- **解释器滥用**：DSL 膨胀成图灵完备语言=无底洞；能用组合子+受限文法就别发明语法。
- **手写外部迭代器对象**（GoF 原型 `Iterator* it = collection->createIterator()`）：堆分配+虚调用+指针语义，
  C++ 的值迭代器全面占优；今天只剩「语言无关游标 API」（JDBC 式）场景配得上外部迭代器。
- **失效的迭代器**：vector 扩容使迭代器悬垂——`erase` 惯用法/`stable_*` 容器（folly）/索引替代是 C++ 特色补丁，GoF 没有这门课。
- **代理迭代器返回引用假象**：`zip` 解包拿到的 pair 是临时量，写 `for (auto& [a,b] : views::zip(x,y))` 要当心存悬垂。

## 权衡与相邻概念对比

| 维度 | 迭代器（GoF 外部式） | C++20 迭代器/范围 | C++23 generator |
| --- | --- | --- | --- |
| 形态 | 堆分配游标对象 | 栈上值类型/概念 | 协程惰性序列 |
| 状态在哪 | 迭代器对象里 | 迭代器就是位置 | 协程帧里（可携带任意局部状态） |
| 多态代价 | 虚函数 | 零（模板具化） | 协程框架一次分配 |
| 组合性 | 无 | `|` 管道任意组合 | 可直接写递归/回溯 |

**Interpreter vs Visitor**：解释器的「每节点一 evaluate()」是模板方法/虚分派形态；把操作外置就滑向 Visitor（下一章）。
**Iterator vs Visitor**：迭代器把控制权给**消费者**（拉），Visitor 把控制权给**结构**（推）——这条轴在 [12-空对象与观察者.md](12-空对象与观察者.md) 的协程对偶里再次出现。

## 最新演进与工业实践

- **经典文献**：GoF 1994 之 Interpreter / Iterator 条（书目见 [../设计模式GoF/04-行为型模式.md](../设计模式GoF/04-行为型模式.md)）；
  Stepanov & Lee 的迭代器与算法分离论述（STL 源头）。
- **标准化口径**：C++20 ranges/concepts/sentinel（✅ 语言事实）；
  C++23 `std::generator`（P2502R2 ⚠️ 修订号未复核，特性已入 C++23 ✅，本目录在 g++ 15.2 `-std=gnu++2b` 实测可用，见 t5）。
- **工业体现**：
  - **range-v3 → std::ranges**：「迭代器模式被标准库吸收」全程的活化石。
  - **libgit2/llvm::StringRef 类项目**：C API 里仍活着的外部迭代器（`git_tree_iterate`）——对照教材原型。
  - **EnTT/skia**：SoA 数据布局下「按组件过滤的游标」用视图+生成器重写（EnTT 的 `query` 即 range 语义）。
  - **正则/JSON 路径**：RE2、jq 等实现=解释器工业形态；`std::regex` 是标准库里最后的解释器（性能口碑促成 RE2/fmt 系替代 ⚠️ 口碑判断，非基准数据）。
- **2026 判断**：Iterator 作为「要写的模式」已终结——今天写迭代器=写符合 `std::ranges::range` 的类型；
  Interpreter 在配置/查询 DSL 领域持续，且与「结构化打印/序列化」（反射辅助）融合出新形态。
