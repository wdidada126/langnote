# 08 代理模式（对应原书第 12 章）

> 对应原书第二部分（结构型）第 12 章「代理模式」（推定英文章题 Proxy ⚠️）。
> 本章在原书中位置特殊：它既是结构型收尾，又为行为型的「拦截/记账」思想铺路；
> 智能指针、`reference_wrapper`、协程 awaiter 这三代 C++ 设施都与代理有血缘。

## 核心概念速览（中英对照）

- **代理** — Proxy：提供与被代理对象同接口的替身，以**控制访问**为目的（加料在 Decorator，翻译在 Adapter，控制在 Proxy）。
- **虚代理/惰性代理** — virtual proxy：延迟昂贵初始化（加载图片、建连接），按需真正创建。
- **保护代理** — protecting/guard proxy：访问前鉴权；按调用方身份放行或拒绝。
- **智能引用代理** — smart reference proxy：引用计数、写时复制、空悬检测——C++ 智能指针谱系。
- **远程代理** — remote proxy：本地替身把调用编组送到远端（RPC stub、gRPC channel）。
- **缓存代理** — caching proxy：把昂贵调用的结果记在代理侧（memoization）。
- **日志/记账代理** — logging/protection+audit：每次转发顺带记录——AOP「切面」的最小手工版。
- **写时复制** — copy-on-write：值语义下的共享+分叉；C++11 后 `std::string` 不再使用（见权衡）。
- **`std::reference_wrapper`** — 标准库代理：把引用包成可拷贝、可放进容器的对象。
- **透明性分级** — transparency level：编译期透明（模板代理）→ 运行期同接口（虚代理）→ 显式句柄（API 网关式）。
- **awaiter** — 协程 awaiter：`co_await` 的等待协议对象，本质是「对异步值的访问控制代理」。
- **代理 vs 装饰器一句话判据** — 拆掉这层壳，客户端功能是否少了一块？少=装饰器；没少但「何时/能否/多大代价」变了=代理。
- **连接池/租约** — pooling & lease：对「昂贵可复用资源」的代理化管理（数据库连接、GPU 上下文）——远程代理的工业同族。

## 动机：访问需要被管

客户端要用的永远是**那个对象**，但「直接用」有代价/风险：

- 太贵（加载 10MB 图片）→ 虚代理延迟到真正使用；
- 太敏感（root 级 API）→ 保护代理加锁/鉴权；
- 太远（另一进程/机器）→ 远程代理本地化；
- 易误用（裸引用悬垂）→ 智能指针代理化。

代理与装饰器的分水岭：**装饰器改变「做什么」，代理改变「能不能、何时、以何种代价做」**。

## 机制

🔧（已实测 g++ 15.2，见 t4）虚代理 + 缓存的复合形态：

```cpp
class Image { public: virtual ~Image() = default; virtual std::string render() const = 0; };

class LazyImageProxy : public Image {
    mutable std::unique_ptr<RealImage> real_;
    std::string loc_;
    const RealImage& img() const {
        if (!real_) real_ = std::make_unique<RealImage>(load(loc_));
        return *real_;
    }
public:
    explicit LazyImageProxy(std::string l) : loc_(std::move(l)) {}
    std::string render() const override { return img().render(); }
};
```

要点与变体：

- **同接口纪律**：代理必须实现客户端面向的那个接口（`Image`），否则它变成另一个抽象（那是 Facade/Adapter）。
- **组合优先于继承**：让 `RealImage` 作成员而非基类——代理继承被代理类会连带继承其实现依赖（GoF 警告）。
- **C++ 标准库的代理全家**：`unique_ptr`/`shared_ptr`（所有权代理）、`weak_ptr`（访问许可代理——`lock()` 就是「能不能」）、
  `reference_wrapper`（引用代理，喂给 `std::sort`/回调表）、`std::expected` 的引用特化（C++23）。
- **协程 awaiter 即异步虚代理**：`co_await` 的协议对象把「何时可读、从哪读」封在三段里——与虚代理
  `if (!real_) real_ = load()` 同构：

🔧（教学示意；协程骨架与已实测的 t3 生成器同框架）

```cpp
struct LazyValueAwaiter {
    std::function<int()> loader; int cache = -1; bool ready = false;
    bool await_ready() const { return ready; }               // 已有→不挂起（同 if(real_)）
    void await_suspend(std::coroutine_handle<> h) {          // 无→登记恢复
        cache = loader(); ready = true; h.resume();
    }
    int await_resume() { return cache; }                     // 恢复即取值
};
```

- **保护代理与能力（capability）**：与其在每个方法开头查权限表，不如让代理本身携带能力令牌——
  `FileGuarded{ File&, Permit }`；调用无法绕过令牌。

**反模式/何时不用**：

- **代理链套代理**：懒加载代理里塞日志代理再塞远程代理——栈深三层以上就该合并为一个「服务客户端」类；调试栈帧成本剧增。
- **写时复制在 C++11 后的失宠**：移动语义把大对象转移的成本降为指针搬运，CoW 的收益（省深拷贝）消失、
  代价（引用计数分支）还在——`std::string` 的 CoW 实现被标准（线程安全要求）判死刑是定论事件。
- **代理里写业务**：代理只做控制；一旦 `render()` 的转发顺带改了参数语义，客户端拿到的就不再是「透明替身」。
- **用代理模拟继承的「部分覆盖」**：只为重写一两个方法而造代理，用组合+显式转发或直接改原类。
- **缓存代理与享元串门**：把「结果缓存」做成 `shared_ptr<const T>` 池——那是 [07-外观与享元.md](07-外观与享元.md) 的领地；代理缓存的是**这一次调用的返回值**，池共享的是**这一类对象的规范值**，别用一张表混装两种语义。

## 权衡与相邻概念对比

| 维度 | Proxy | Decorator | Adapter | Bridge |
| --- | --- | --- | --- | --- |
| 接口 | 同 | 同 | 异 | 抽象侧自定义 |
| 目的 | 控制访问 | 叠加职责 | 接口互译 | 两轴独立演化 |
| 被包对象生命周期 | 常由代理管理 | 客户端装配传入 | 客户端持有 | 实现族独立存在 |
| 谁决定用哪个真实对象 | 代理（惰性/路由） | 客户端 | 客户端 | 抽象侧配置 |
| C++20 吸收者 | 智能指针/awaiter | ranges view | reference_wrapper/ranges | Env/后端句柄 |

## 最新演进与工业实践

- **经典文献**：GoF 1994 之 Proxy 条（书目见 [../设计模式GoF/03-结构型模式.md](../设计模式GoF/03-结构型模式.md)）；
  Stroustrup 对 handle/body 智能引用的论述（*The C++ Programming Language* 4e，书目级引用）。
- **C++20→26**：协程 awaiter/`promise_type` 成为异步代理的标准化协议；
  C++26 `std::senders/receivers` 进一步把「异步值的访问控制」做成库间通用货币（⚠️ 编号以标准文本为准，本目录不引提案号）。
- **工业体现**：
  - **gRPC C++**：`Channel`/`ClientContext` 是远程代理的工业标本——本地 stub 的每次调用被编组、鉴权、重试、打点。
  - **folly**：`Future<T>`/`SemiFuture<T>`——「尚不存在之值」的代理；`via(executor).thenValue(...)` 把访问时机与执行器都纳入控制。
  - **Qt**：`QPointer`/`QWeakPointer` 对 QObject 生命周期的访问代理；`QUndoView` 等模型视图层的懒加载代理。
  - **abseil**：`absl::Mutex` 的 `ReaderMutexLock` 等包装——把「许可」本身做成 RAII 代理对象。
- **2026 判断**：手写「类形态」代理继续减少（智能指针与协程协议覆盖大半），
  但「服务形态」代理（API 网关、sidecar、连接池）在分布式尺度重新繁荣——模式没死，只是换了物理位置。
