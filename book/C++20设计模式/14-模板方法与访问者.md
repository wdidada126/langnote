# 14 模板方法模式与访问者模式（对应原书第 23–24 章）

> 对应原书第三部分（行为型）第 23 章「模板方法模式」、第 24 章「访问者模式」（推定英文章题 Template Method / Visitor ⚠️）。
> 合并理由：全书收尾恰好落在「**虚函数的两个巅峰用法**」上——模板方法是「用虚函数复用流程」，
> 访问者是「用双虚调用扩展操作」；而 C++20 的 concepts/CRTP 与 `variant/visit` 又分别吃掉了它们的半壁江山。
> 原书访问者章含「基于 std::function 的访问者」等现代变体（按第 1 版结构推定 ⚠️）。

## 核心概念速览（中英对照）

- **模板方法** — Template Method：骨架算法固定在基类，可变步骤延迟为虚钩子由子类实现。
- **钩子操作** — hook operation：骨架里留给子类的虚函数插槽。
- **静态模板方法** — static template method（CRTP 版）：骨架编译期展开，零虚调用；「政策模式」的近亲。
- **CRTP** — Curiously Recurring Template Pattern：派生类把自己作为模板参数传给基类——静态多态的地基。
- **里氏替换警戒** — LSP caution：模板方法的子类钩子若破坏骨架不变式（重写 final 该禁的方法），模式即溃堤。
- **访问者** — Visitor：把「对元素结构的操作」外置成对象；元素侧只需一个 `accept(visitor)`。
- **双分派** — double dispatch：第一次虚调用定元素、第二次定访问者——(元素×操作) 矩阵的运行期求解法。
- **具体元素/具体访问者** — ConcreteElement / ConcreteVisitor：双分派矩阵的两轴。
- **开放/封闭轴翻转** — open/closed axis trade-off：GoF Visitor 易加操作难加元素；`variant+visit` 易加操作**且**类型集封闭——两形态的正反话。
- **`overloaded{}` 惯用法** — overloaded lambdas：`[...]{ using Ts::operator()...; }` 把一组 lambda 捏成 visit 用的仿函数（C++17 CTAD ✅）。
- **无环访问者** — acyclic visitor：双访问者打破「Visitor 依赖所有具体元素」的环——大型 AST 的补丁。
- **模式即语言缺口** — pattern as language gap：Visitor 是「操作一等公民」缺失的代偿（对照多方法/模式匹配语言）。

## 动机：流程复用与操作外置

- **Template Method**：框架（Servlet 生命周期、应用启动序列）要把「不变顺序」锁死、只开「可变化步骤」。
  策略模式换的是整段算法；模板方法锁的是流程、只换步骤。
- **Visitor**：语法树/图形场景（元素稳定）上，操作需求不断新增（求值、打印、序列化、校验）。
  每加一个操作都改元素类违反 OCP——把操作搬出去成独立类。

## 机制

### 模板方法：虚函数版与 CRTP 版

🔧（已实测 g++ 15.2 的 CRTP 版，见 t3）：

```cpp
// 虚函数版（GoF 原型）：骨架在基类
class AppFramework {
public:
    void run() { init(); loop(); shutdown(); }    // final 语义（C++11 可标 final）
protected:
    virtual void init() = 0; virtual void loop() = 0; virtual void shutdown() = 0;
};

// CRTP 版：编译期模板方法，零虚表
template <typename Derived>
class Serializer {
public:
    std::string process(const auto& obj) {
        return static_cast<Derived*>(this)->header(obj)
             + static_cast<Derived*>(this)->body(obj) + "]";
    }
};
class JsonLike : public Serializer<JsonLike> {
public:
    std::string header(const auto&) { return "{"; }
    std::string body(const auto& o) { return o; }
};
```

- C++20 增强：`requires` 可把「子类必须提供的钩子」写成约束（配合概念工厂手法，见 [03-工厂方法与抽象工厂.md](03-工厂方法与抽象工厂.md)）；
  `auto` 模板参数让钩子接受任意可调用。
- **何时不用**：只有 1–2 个步骤且无共享骨架→直接 `std::function` 注入（那就是策略/回调）；
  骨架顺序本身要可配→流程编排（pipeline）而非模板方法。

### 访问者：三种形态的完整对照

🔧（已实测 g++ 15.2，见 t2）`variant + visit` 版：

```cpp
using Shape = std::variant<Circle, Square, Text>;

double area(const Shape& sh) {
    return std::visit(overloaded{
        [](const Circle& c)  { return 3.14159 * c.r * c.r; },
        [](const Square& q)  { return q.side * q.side; },
        [](const Text& t)    { return double(t.s.size()); }
    }, sh);
}
```

| 形态 | 加新类型 | 加新操作 | 遍历谁写 | 运行/编译期 |
| --- | --- | --- | --- | --- |
| GoF 双分派（`accept/visit`） | 改所有访问者（痛苦） | 加一个访问者类 | 访问者手写 | 运行期×2 虚调用 |
| `variant + visit` | 改 variant+全部 visit 重载 | 写一个函数（爽） | 结构自带（树则递归） | 运行期查分支/编译期跳转 |
| 反射/模式匹配式（C++26/展望） | 编译期自动登记 | 编译期遍历成员 | 自动 | 编译期 |

- GoF 形态在 C++ 里的当代残存：AST 的 `StmtVisitor/ExprVisitor`（Clang 的 RecursiveVisitor）、
  编译器后端的多轴扩展——**类型集大且操作轴多**时才付得起双分派税。
- **无环访问者**要点：元素只认识 `ElementVisitor<具体元素>` 基类，具体访问者注册进元素时按轴拆分——
  用 CRTP+模板破解编译依赖环。

**反模式/何时不用**：

- **Visitor 写无操作需求的结构**：只有一个访问者时，成员函数更直白；「将来可能有多个操作」不是理由（YAGNI）。
- **`variant` 上追加类型的静默破窗**：加进 variant 而忘加一处 visit 分支=编译错误——这是**优点**（穷尽性检查 ✅），
  GoF 运行期 Visitor 漏一个元素只会在运行时炸。
- **模板方法滥用继承**：子类只想要骨架里的一步，被迫继承整类——拆成普通函数或用策略注入该步。

## 权衡与相邻概念对比

| 维度 | Template Method | Strategy | Visitor | 命令 |
| --- | --- | --- | --- | --- |
| 复用粒度 | 流程+插槽步骤 | 整段算法 | 跨结构的一组操作 | 单个请求 |
| 扩展方向 | 加派生类 | 加策略类/函数 | 加访问者（操作轴） | 加命令类 |
| 语言吸收者 | CRTP/concepts/协程框架 | `std::function`/模板参数/投影 | `variant+visit`/反射 | lambda/任务/事件溯源 |
| 与继承的爱恨 | 为复用而继承 | 为替换而组合 | 为外置而双分派 | 无继承也成立 |

**Template Method vs Visitor**：一个锁「流程在基类」，一个锁「结构在元素、操作在外面」——
两者在「框架回调」（框架遍历、用户挂钩子）处会师：现代框架用协程+模板方法写遍历、用 visit 式类型表写分发。

## 最新演进与工业实践

- **经典文献**：GoF 1994 之 Template Method / Visitor 条（书目见 [../设计模式GoF/05-策略、状态、模板方法与访客.md](../设计模式GoF/05-策略、状态、模板方法与访客.md)）。
- **C++20→26（访问者的终局之争，本书最前瞻的对照读点）**：
  P2996（"Reflection for C++26"，✅ 提案号与标题为通行口径）提供 `^struct`/`->data_members` 等反射原语，
  可写出「遍历任意类型成员」的通用序列化/打印——即**编译期、零登记的 Visitor 替代**；
  Qt 社区已据此讨论淘汰 moc 的信号槽生成（来源：Qt wiki "C++ reflection (P2996) and moc"，2025 ✅ 检索可得）。
  模式匹配（is-check-cast 提案族）仍在路上，此处不引编号 ⚠️。
- **工业体现**：
  - **fmtlib/fmt**：`formatter<T, Char>` 偏特化=**编译期按类型查表**的访问者——加类型=加特化，中心函数不动；CRTP+concept 约束其使用（与 [01-导论-模式体系与C++20惯用法.md](01-导论-模式体系与C++20惯用法.md) 首尾呼应）。
  - **Clang/MLIR**：`clang::RecursiveASTVisitor`、MLIR `TypeSwitch`——工业级 Visitor 的双壁（前者 GoF 形，后者表驱动现代形）。
  - **EnTT**：ECS 宣言「把行为从实体里搬走」——它反对的正是 Visitor 的「操作外置到系统」的另一种极端：数据外置（SoA），操作遍历（系统）。与 [11-中介者与备忘录.md](11-中介者与备忘录.md) 的 ECS 中介观互补。
  - **abseil**：`absl::Status`/`StatusOr` 作为「操作失败」的统一返回轴——visit 各分支返回 `Status` 时的标准错误货币。
- **2026 判断**：Visitor 是本书 24 章里**形态变化最剧烈**的一个——从「双分派类图」变成「variant 穷尽匹配」，
  下一步是反射元循环；Template Method 则从「继承骨架」变成「框架即协程」，两者都在等语言把样板吃完。
