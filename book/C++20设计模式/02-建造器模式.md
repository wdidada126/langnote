# 02 构造器模式（对应原书第 2 章）

> 对应原书第一部分（创建型）第 2 章「构造器模式」（推定英文章题 Builders ⚠️）。
> 原书以逐字段流式 Builder、分步（step）Builder、Director 等展开（具体小节划分未逐字核实 ⚠️）；
> 本章按「动机→机制→权衡→相邻对比」重写，并补充 C++20 指示初始化这一 Builder 的免样板替代（原书是否展开未核实 ⚠️）。

## 核心概念速览（中英对照）

- **建造器** — Builder：将复杂对象的构造过程与表示分离，分步收集参数、终点一次性校验并产出。
- **流式接口** — Fluent Interface：每个 setter 返回自身引用，使调用连成 `b.name(x).age(y).build()` 一条链。
- **分步建造器** — Step Builder：每步返回「下一个合法步骤的类型」，用类型状态机强制顺序与完整性。
- **导演者** — Director：把「建造顺序知识」外置到第三个类，对同一 Builder 复用流程（GoF 原图角色，本书弱化处理 ⚠️）。
- **指示初始化** — designated initializer：C++20 `T{.member = value, ...}`，聚合体上最廉价的「具名参数」。
- **聚合体** — aggregate：无用户声明构造函数的类，可被列表/指示初始化直接构造。
- **望远镜式构造函数** — telescoping constructors：重载 `(a)`, `(a,b)`, `(a,b,c)`… 的反模式，Builder 的经典动机。
- **参数对象** — Parameter Object / Named Arguments：把参数打包成配置结构体，配指示初始化等效「具名实参」。
- **终态校验** — terminal validation：把合法性检查放在 `build()`/类型系统而非每个 setter。
- **原地构造** — in-place builder：Builder 直接操作目标内存（`emplace` 风格），避免中间对象搬运。

## 动机：构造函数为什么撑不住

对象参数一多，构造函数有三条死路（Java/C++ 通用）：

1. **望远镜重载**：`Person(string)`, `Person(string,int)`, `Person(string,int,bool)`… 组合爆炸，且相邻同类型参数写反（`(age, height)` 传成 `(height, age)`）编译不报错。
2. **JavaBean setter**：对象在「半构造」状态游走，无法维持不变式，无法 `const` 化。
3. **巨型 ctor**：`Person("Bob", 27, false, "", 0, 0, 0, …)`——魔法字面量长龙，可读性归零。

Builder 的答案：**把「参数收集」与「合法性」分开**——收集阶段允许乱序缺省，产出阶段一次性把关。

## 机制：C++20 的四档实现

🔧（已实测 g++ 15.2）CRTP 流式 Builder——`build()` 只出现在终点类，基类步骤返回派生类引用：

```cpp
struct Person { std::string name; int age = 0; };

template <typename Derived>
class PersonBuilderBase {
public:
    Derived& with_name(std::string s) { p_.name = std::move(s); return static_cast<Derived&>(*this); }
    Derived& with_age(int a) { p_.age = a; return static_cast<Derived&>(*this); }
protected:
    Person p_;
};
class PersonBuilder : public PersonBuilderBase<PersonBuilder> {
public:
    Person build() const { return p_; }
};
// Person p = PersonBuilder().with_name("Alice").with_age(30).build();
```

🔧（已实测 g++ 15.2）concepts 终态校验——字段未齐时 `build()` 直接不在重载集里：

```cpp
template <bool HasName, bool HasAge>
class StrictBuilder {
    Person p_;
public:
    Person build() const requires (HasName && HasAge) { return p_; }
};
```

四档由轻到重（按「参数复杂度」选档，这是本章的核心工程判断）：

| 档 | 手段 | 适用 |
| --- | --- | --- |
| 0 | 普通 ctor + 默认实参 | ≤3 个参数且顺序无歧义 |
| 1 | C++20 指示初始化 `Person{.name="A", .age=30}` | 聚合体；参数多但无跨字段校验 |
| 2 | 流式 Builder（值/引用语义皆可） | 需链式、需副作用式收集（如拼接子对象） |
| 3 | 分步 Builder / concepts 约束终点 | 构造顺序与完整性是业务不变式 |

**C++23 deducing this 对第 2 档的改写**（已核实：P0847R7 入 C++23）：

```cpp
struct PersonBuilder2 {
    Person p_;
    auto with_name(this auto& self, std::string s) { self.p_.name = std::move(s); return self; }
    Person build(this const PersonBuilder2& self) { return self.p_; }
};
```

不再需要 CRTP 样板——这是本书成书之后 Builder 形态最大的简化。

**反模式/何时不用**：

- 参数本来就少且语义清晰时，Builder 是纯仪式成本；先试指示初始化。
- `build()` 可重复调用且每次返回同值——若 Builder 内部含消耗性资源（移动走的 unique_ptr），二次 `build()` 产生半空对象；约定一次性语义并置 `bool done_` 断言。
- Builder 继承体系当「配置基类」用：派生 Builder 的 `build()` 返回切片基类对象——终点返回类型必须写死为完整派生类型。

## 权衡与相邻概念对比

**Builder vs Abstract Factory**（与 [03-工厂方法与抽象工厂.md](03-工厂方法与抽象工厂.md) 的谱系分界）：

| 维度 | Builder | Abstract Factory |
| --- | --- | --- |
| 回答的问题 | 「怎么分步造**一个**复杂对象」 | 「造**一族**相关对象，且不暴露具体类」 |
| 客户端控制什么 | 构造过程与中间状态 | 只选工厂，不选产品细节 |
| 产出时机 | 显式 `build()` 终点 | 每个方法即时返回产品 |
| 典型场景 | 配置/查询/文档对象 | 跨主题 UI 套件、跨平台驱动族 |
| 组合关系 | 可作为 Abstract Factory 产品的建造手段 | 工厂内部可藏 Builder（本书与 GoF 均指出二者「互补不互斥」） |

**Builder vs 指示初始化**：后者是前者的退化形态——没有校验、没有顺序强制、没有行为收集；
换来零样板、constexpr 友好（指示初始化可用于常量求值）。GoF 动机段在 C++20 的第一条修正就是：
「默认参数 + 具名初始化吃掉了 60% 的教材级 Builder 案例」。

**Director 的当代处境**：框架里少见独立的 Director 类，其职责被「配置 DSL / TOML→对象映射层」吸收
（如 CMake 的 target 属性流水线、gRPC C++ 的 `GrpcServerBuilder`/`GrpcComponentBuilder` ⚠️ 类名以 gRPC v1.44+ 口径，未逐一复核）。

## 最新演进与工业实践

- **经典文献**：GoF 1994 之 Builder 条（书目见 [../设计模式GoF/02-创建型模式.md](../设计模式GoF/02-创建型模式.md)）；
  Bloch, *Effective Java* 2nd ed. Item 2「consider a builder when faced with many constructor parameters」——Builder 在现代语言教学里的定名出处。
- **标准化时间线**：C++20 指示初始化（提案 P0329 系 ⚠️ 修订号未复核，特性已入 C++20 ✅）；
  C++23 deducing this（P0847R7 ✅ 通行编号）。
- **C++23/C++26 展望**：`std::expected<T, E>`（提案 P2300R6 入 C++23 ✅ 通行编号）把
  `build()` 的失败路径从异常换成返回值，Builder 的「校验失败」终于有了零成本表达。
- **工业体现**：protobuf C++ 的动态消息 `MessageBuilder` API（3.21+ ⚠️ 版本号未复核）——运行时 schema 上的通用 Builder；
  gRPC C++ 组件装配 builder、LLVM `MLIR` 的 OpBuilder（构造过程携带上下文状态=Director 内化）；
  fmt 的 `format_string` 编译期校验（构造「格式化请求」这条轻量 builder 思路——先解析再产出可执行体）。
- **2026 判断**：语言侧的 Builder 样板持续消解（deducing this、指示初始化、`expected`），
  但「多步协议的正确性」仍是手写领域——step builder 的替代方案（类型状态机）没有标准库化迹象。
