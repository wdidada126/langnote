# 12 空对象模式与观察者模式（对应原书第 19–20 章）

> 对应原书第三部分（行为型）第 19 章「空对象模式」（推定英文章题 Null Object ⚠️——注意它**不在 GoF 23 之内**，
> 源自 Woolf 的 PLoP 论文）、第 20 章「观察者模式」（推定英文章题 Observer ⚠️）。
> 合并理由：空对象是「无行为的存在」，观察者是其经典用武之地（Null 日志记录器=最常用 Null Object）；
> 两章又共同通向协程 generator 的「拉 vs 推」对偶论证。

## 核心概念速览（中英对照）

- **空对象** — Null Object：提供一个「什么都不做」的合法实现，让客户端无需判空。
- **哨兵实现** — benign sentinel：Null Object 的别名口径——错误路径的统一出口。
- **判空分支** — null-check branch：每个调用点重复写 `if (p)`——Null Object 要消灭的噪音。
- **`std::optional`** — 语言级「可能没有」：表示**值域**（可能无值），与 Null Object（表示**行为**）互补而非同义。
- **空实现三件套** — no-op logger/observer/iterator：日志、观察者、迭代器——Null Object 的经典工业落点（`std::ostream` 的 failbit 亦同族）。
- **观察者** — Observer：主题维护订阅者列表，状态变化自动通知（一对多依赖）。
- **主题/订阅者** — Subject / Observer：通知的发出方与接收方；现代命名 publisher/subscriber。
- **推 vs 拉** — push vs pull：通知带数据（推）还是只说「变了」（拉，订阅者再查询）。
- **信号与槽** — signals and slots：Qt 对 Observer 的标准化——类型安全 + 断连 RAII（`QMetaObject::Connection` ⚠️ 细节以 Qt 文档为准）。
- **悬垂订阅** — dangling subscription：订阅者先于主题死亡/注销遗漏——Observer 的头号事故源。
- **`boost::signals2` 连接生命周期** — scoped connection：`shared_connection_block`/自动析连的工程答案。
- **生成器（拉取式观察者）** — `std::generator`/手写 coroutine Generator：把「事件来了叫你」翻转成「我按节拍取事件」——Observer 的协程对偶。
- **`folly::ObserverPtr`** — 安全观察指针：对象销毁时自动置空——悬垂订阅的语言级补丁（⚠️ API 名按 folly 仓库口径）。

## 动机：判空与通知

- **Null Object**：`if (logger_) logger_->log(...)` 在每个调用点重播；把「没有日志器」做成一个合法对象，
  调用点永久安静。它的真正价值在**接口完整性**——「什么都不做」是一种被建模的行为。
- **Observer**：模型变了，视图、撤销栈、网络同步都要动；让模型点名每个订阅者=重新制造依赖。
  通知机制把「谁关心」从模型里剥离。

## 机制

### 空对象：从虚基类到 variant

🔧（教学示意）

```cpp
struct Logger { virtual ~Logger() = default; virtual void log(std::string_view) = 0; };
struct NullLogger : Logger { void log(std::string_view) override {} };   // 什么都不做
struct ConsoleLogger : Logger { void log(std::string_view s) override { puts(s.data()); } };

// C++20 惯用法：std::function 自身就是合法空对象
using Sink = std::function<void(std::string_view)>;
Sink sink;                 // 未装载=Null 语义
if (sink) sink("msg");     // 或直接 sink ? sink("msg") : void();
// 工厂返回 Null 兜底，客户端无判空：
Logger& logger_or_null(const std::string& kind) {
    static NullLogger null;
    static ConsoleLogger console;
    return kind == "console" ? console : null;
}
```

- **Null Object vs `optional`**：`optional<T>` 说「这里可能没有值」，调用方**仍要**检查；
  Null Object 说「这里永远有一个可用的行为」，检查被模式吃掉。选型判据：无值是否是**业务状态**（是→optional），
  还是**配置缺省**（是→Null Object）。

### 观察者：类型擦除 + 生命周期纪律

🔧（教学示意）最小信号实现：

```cpp
template <typename... Args>
class Signal {
    std::vector<std::pair<void*, std::function<void(Args...)>>> subs_;
public:
    void* connect(std::function<void(Args...)> fn, void* owner) {
        subs_.emplace_back(owner, std::move(fn)); return owner;
    }
    void disconnect(void* owner) {                    // 订阅者析构时必须调用
        std::erase_if(subs_, [&](auto& p){ return p.first == owner; });
    }
    void emit(const Args&... a) { for (auto& [_, fn] : subs_) fn(a...); }
};
```

工程要点（按痛切程度排序）：

1. **注销比注册重要**：C++ 没有 GC，Observer 析构时主题还活着=悬垂调用；
   解法三档——订阅者 RAII 断连（`scoped_connection`）、弱引用（`weak_ptr` 存订阅者）、安全指针（`folly::ObserverPtr` 思路）。
2. **迭代中修改订阅表**：通知里 unsubscribe 导致 UB——emit 前先拷贝订阅表或用稳定句柄。
3. **拉式通知防通知风暴**：细粒度变更攒成一次「脏了」通知，订阅者批量重查（Qt 的 `update()` 惯例）。

### 拉取对偶：协程 generator 作为「消费者驱动的观察者」

🔧（已实测 g++ 15.2，见 t3/t5）拉取式：

```cpp
Generator<int> counter(int n) {        // 手写版（本章 t3）；C++23 用 std::generator
    for (int i = 0; i < n; ++i) co_yield i * i;   // 事件在产出点挂起
}
// 消费端 while (gen.next()) ... 控制流在消费者手里：Observer 的镜像
```

- 推送模型：主题决定「何时叫你」，回调栈深不可控；拉取模型：消费者决定「何时取」，背压天然形成。
- C++23 `std::generator` 把协程帧、析构顺序、迭代器协议打包好——手写 Generator 只剩教学价值。

**反模式/何时不用**：

- **Null Object 掩盖真正的缺失**：配置缺失本该报错时返回 Null=静默吞错；Null 适合「可选行为」，不适合「必备依赖」。
- **Observer 网状失控**：五层转发链里一个 setter 触发十个回调再改十个字段——数据流变成控制流泥潭；
  改用显式更新（拉）或单向数据流（Redux 式状态树）。
- **用 Observer 做请求/响应**：需要「一次、等结果、可取消」的是 Command/async，不是一群人的广播（见 [09-职责链与命令.md](09-职责链与命令.md)）。

## 权衡与相邻概念对比

| 维度 | Observer（推） | Iterator/generator（拉） | Mediator | Null Object |
| --- | --- | --- | --- | --- |
| 控制权在 | 主题 | 消费者 | 中介 | 不适用 |
| 一对多 | 是 | 否（单消费者） | 是 | 否 |
| 背压 | 无（推爆） | 有 | 取决于实现 | — |
| 生命周期痛点 | 悬垂订阅 | 协程帧/迭代器失效 | 中介持有同事 | 被共享的静态 Null 需线程安全 |
| C++20/23 对应 | signals2/Qt/EnTT | `std::generator` | 事件总线 | 空 `std::function`/`optional` |

## 最新演进与工业实践

- **经典文献**：GoF 1994 之 Observer 条（书目见 [../设计模式GoF/04-行为型模式.md](../设计模式GoF/04-行为型模式.md)）；
  Alan Woolf, "Null Object", PLoP 1996 年会（模式出处，书目级引用，不引编号）。
- **标准化口径**：C++23 `std::generator`（✅ 见 [10-解释器与迭代器.md](10-解释器与迭代器.md)）为拉取式观察者提供标准库载体；
  C++26 静态反射（P2996）对信号是「按字段自动生成变更通知」的潜在路径（⚠️ 展望口径，非既成事实）。
- **工业体现**：
  - **Qt**：信号槽是 C++ 界 Observer 的官方答案——moc 代码生成处理签名匹配与断连；
    Qt 6 继续收紧（`Q_PRIVATE_SLOT` 等历史包袱清理 ⚠️ 细节以文档为准）。
  - **boost::signals2**：`scoped_connection`/线程安全 emit——无代码生成的纯库方案。
  - **EnTT**：`registry.on<Position>().construct(...)`——ECS 的组件事件；`std::function` 型汇接点同样暴露悬垂风险，故推荐按实体 id 再查（拉）。
  - **folly**：`folly::Function` + `ObserverPtr`/`Lifetime` 工具链——大型服务端对「安全订阅」的工程化。
- **2026 判断**：手写裸 Observer 列表在绿地（greenfield）代码里应视为**架构缺陷候选**（用现成信号库/响应式框架）；
  Null Object 则相反——它以「更便宜的形态」（空 `function`、no-op span）活在每一天的 API 设计里。
