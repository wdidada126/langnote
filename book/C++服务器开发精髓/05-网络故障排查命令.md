# 第5章 网络通信故障排查常用命令 — 八件工具的诊断树

> 对应原书第 5 章（§5.1–5.8，原书第 397–421 页）。目录经豆瓣条目 35491437 核实 ✅。
> 本章是全书唯一的"纯工具章"：ifconfig/ping/telnet/netstat/lsof/nc/curl/tcpdump 八件套，
> 每节按"命令机制→典型输出解读→服务端实战问句"组织（如「TIME_WAIT 堆积该看哪个参数」）。
> ⚠️ 实测边界：本章工具以 Linux 为主，本机为 Windows——可实测项见下文实测记录，
> 不可实测项按各工具 man 手册转述并标注。

## 核心概念速览（中英对照）

- **接口配置** — interface configuration（`ifconfig`/`ip addr`）：网卡地址、MTU、up/down 状态的第一现场
- **连通性探测** — ping（ICMP Echo）：可达性/RTT 探针；**能 ping 通 ≠ 端口能通**（ICMP 与 TCP 分属两栈层）
- **端口连通测试** — telnet host port：剥掉应用协议的"能否建立 TCP 连接+裸文本往来"实验
- **连接五元表观** — netstat（`-ano`/`-s`）：全量 socket 状态直方图，TIME_WAIT/CLOSE_WAIT 堆积的账本
- **打开文件表** — lsof：Linux"一切皆文件"的连接视图——`lsof -p`/`-i` 查 fd 泄漏与端口占用
- **瑞士军刀收发** — netcat（`nc -l`/`nc host port`）：手搓监听端/连接端，验证防火墙、复现半关闭
- **HTTP 客户端探针** — curl（`-v`/`-H`/`--data`）：协议级复现客户端行为，带 verbose 全握手输出
- **线缆判官** — tcpdump（BPF 过滤器 + `-w pcap`）：内核旁路抓包，争议的终审证据
- **半关闭** — half-close：单方向 FIN 后的连接状态（4.2 状态机的排查侧镜像）
- **`SO_LINGER` 与 TIME_WAIT** — 主动关闭者 2MSL 等待：netstat 里最常见的大数字，本章与 04/07 章的交汇点

## 动机：故障排查是"分层剪枝"，命令是每层的剪刀

书给出的诊断树（按章序即按 OSI 层次自底向上）：
路由/接口层（5.1 ifconfig、5.2 ping）→ 传输层端口（5.3 telnet、5.4 netstat）→
进程资源（5.5 lsof）→ 协议复现（5.6 nc、5.7 curl）→ 全量取证（5.8 tcpdump）。
每条命令回答一个特定问句，**顺序错了就是无头苍蝇**：应用层报错先 tcpdump 是新手最常犯的时间浪费。

## 机制：八件套各自的关键细节

1. **ifconfig**（5.1）：flags（UP/RUNNING/PROMISC）、MTU、RX/TX errors/dropped——`dropped` 持续增长指向
   驱动环形缓冲/软中断处理不过来（现代工具为 `ip -s link`）。
2. **ping**（5.2）：TTL 反推跳数/OS、`-s` 大包探 MTU 分片、`-f` flood 探缓冲；书提醒很多机房 ICMP 限速或封禁。
3. **telnet**（5.3）：三用例——端口通不通；手工扮演 SMTP/HTTP 客户端（5.3 用 SMTP 对话做教具，直接预习 6.11）；
   `Ctrl+]` escape 后 `close`/`quit` 演示主动半关闭，观察服务端 recv 返回 0。
4. **netstat**（5.4）：`-tlnp` 监听清单、`-an | awk '{print $6}' | sort | uniq -c` 状态直方图；
   CLOSE_WAIT 堆积 = **本端没 close**（应用 bug）；TIME_WAIT 堆积 = 短连接风暴（07 章 7.1.3 长连接化的量化理由）。
5. **lsof**（5.5）：`lsof -i :8080` 查端口归属；`lsof -p pid | wc -l` 对 `ulimit -n`——"Too many open files"
   的标准验尸（fd 泄漏多与 4.3 closesocket/accept 异常路径配对出现）。
6. **nc**（5.6）：`nc -l -p 9000` 手搓 echo 服务端验证网络策略；`nc -z` 端口扫描；
   书用 nc 演示"发一半关自己"的半关闭对端行为——比写测试程序快。
7. **curl**（5.7）：`-v` 的 TLS/TCP 分层时间线（`-w` 的 time_connect/time_starttransfer 是微型 APM）；
   用 `-X POST -H` 复现 6.10 的 HTTP 协议细节。
8. **tcpdump**（5.8，本章最厚）：BPF 过滤器语法（proto/dir/port/host 组合）；
   `-i any -nn -s0 -w` 四件套；**RST 的三种成因鉴别**（对端无监听/半关闭后仍写/防火墙中间设备）、
   零窗口（TCP window 0）→ 服务端收侧缓冲背压（4.10/7.7.3 的线上证据）、重传（`retransmission`）与
   乱序的判读。书特别讲"抓包点选择"：网卡镜像/`-i lo` 本机回环差异。

## 诊断树：问句 → 命令 → 判读（🔧 一行式速查，5.1–5.8 压缩）

| # | 问句 | 命令 | 关键判读 |
| --- | --- | --- | --- |
| 1 | 网卡/路由正常吗 | `ip -s link`（ifconfig） / `ping 网关` | errors/dropped 增长？ping 通而业务不通→端口层 |
| 2 | 谁在监听这个端口 | `ss -ltnp 'sport = :8080'`（netstat -tlnp） | 没进程→服务没起/绑错地址（4.4 bind 复盘） |
| 3 | 连接建了吗 | `telnet host port` / `nc -zv host port` | 通而卡→应用层握手/协议；立刻 RST→没监听 |
| 4 | 状态堆积在哪 | `ss -s` / `netstat -an \| awk '{print $6}' \| sort \| uniq -c` | CLOSE_WAIT↑=我没关；TIME_WAIT↑=短连接风暴（7.1.3）；SYN-SENT↑=对端不回或防火墙黑洞 |
| 5 | fd 够不够/漏没漏 | `ls /proc/PID/fd \| wc -l` + `lsof -p PID \| wc -l` 对 `ulimit -n` | accept 异常路径没 close、timerfd 泄漏 |
| 6 | 对端什么姿势断的 | `nc host port` 手谈 / `tcpdump -i any tcp port P -w x.pcap` | FIN 先发方=关闭者；RST 三成因（5.8 表）；零窗口=它不收（7.7.3） |
| 7 | HTTP 层对不对 | `curl -v -w '@fmt' http://...` | time_connect 大→网络层；time_starttransfer 大→应用层 |
| 8 | 全链路延迟在谁 | `mtr host`（ping+traceroute 合体） | 某跳持续丢且后跳不丢→该跳 ICMP 限速，别冤枉 |

使用铁律（书意）：**每问一层再下一层；上一命令的结论是下一命令的过滤条件**
（tcpdump 过滤器里带上前四步查出的 IP/port/PID 线索，而不是 `-i any` 全抓）。

## 权衡与边界

- **telnet 的教训**：它测的是"TCP 可连通"，不是"服务可用"——对端 accept 队列满时 connect 仍可成功（SYN 进 backlog），
  这正是 7.12.1 listenfd 与 backlog 知识在诊断侧的投影。
- **tcpdump 的成本**：libpcap 走 AF_PACKET，高流量下丢包（`-s` 截短 snaplen）、CPU 开销；
  生产抓包要 `-w - | pcap rotate` 限体积，或直接上 eBPF（见演进）。
- **netstat 已过时**：`ss` 从 /proc/net/tcp 与内核 netlink 直读，快 netstat 一个量级——本章命令全部有 iproute2 时代替身。

## 相邻概念对比

| 问句 | 首选 | 备用 |
| --- | --- | --- |
| 网卡起来了吗/错包 | `ip -s link`（ifconfig） | ethtool |
| 三层可达？ | ping | traceroute/mtr |
| 端口有人听吗 | `ss -ltnp`（netstat） | lsof -i |
| 连接卡在哪状态 | `ss -tan state …` | netstat 直方图 |
| 是不是 fd 泄漏 | lsof + /proc/pid/fd | /proc/pid/limits |
| 应用协议对不对 | nc/telnet 手谈 | curl -v |
| 谁发了 RST/零窗口 | tcpdump + Wireshark 判读 | ss -ti（重传计数） |

## 三个排查演练（把诊断树跑成肌肉记忆）

1. **"服务连不上"三分法**：ping 通不通（1）→ `ss -ltnp` 有没有监听（2）→ `nc -zv` 通不通（3）。
   二分定界后才知道该查防火墙、应用日志还是内核 backlog（`ss -s` 的 overflow 计数，对应 7.12.1 backlog 满）。
2. **"偶发超时"取证**：`ss -ti` 看目标连接的 retrans 计数（内核层证据）→ 对不上就 tcpdump 定时抓 5 分钟
   （`-G 60 -W 5` 轮转）→ Wireshark 过滤 `tcp.analysis.retransmission || tcp.analysis.zero_window`。
3. **"Too many open files" 定位**：`lsof -p PID | awk '{print $4}' | sort | uniq -c | sort -rn | head`
   看 fd 类型分布 → 若是 socket 成山：accept 错误路径漏 close（4.3）或上游 DNS 解析对象没析构（4.17 的隐藏 fd）。

## 最新演进与工业实践

- **iproute2 全家桶**：`ip/ss/tcp/bridge/nstat` 替代 net-tools（书成书时 netstat/ifconfig 仍是默认，现多数发行版已移除 net-tools）；
  `ss -ti` 直接打印每连接重传/RTT/cwnd——把半个 tcpdump 搬进了状态工具。
- **eBPF/bpftrace**：`tcplife`（连接生灭账本）、`tcpconnect/tcpaccept`（无需改代码统计谁连谁）、
  `tcpretrans`（定位丢包层）；一手文档 [bpftrace 官方](https://bpftrace.org/)（检索可达核实），
  项目源自 Brendan Gregg 体系（其博客 [brendangregg.com](https://www.brendangregg.com/blog/) 为公开非正式出版物 ⚠️ 标注）。
  "生产上不敢抓包"的时代终结：eBPF 采样代替 tcpdump 全量。
- **Windows 对照表**（本机环境）：`ipconfig`/`Get-NetIPInterface`、`Test-NetConnection`（=ping+tcpPing 一体）、
  `netstat -ano` + `Get-Process -Id`（=lsof -p 的孪生）、`pktmon`/`netsh trace` + Network Monitor 归档器（=tcpdump+Wireshark），
  Process Explorer 看句柄。**实测**：本机 `netstat -ano` 与 `Test-NetConnection` 流程可完整走通 5.3–5.5 的对应问句。
- **curl 的后继**：`httpie/xh` 人机交互、`--http3`（curl 支持 QUIC 后端）对应 06 章 HTTP/3；
  `curl -w @format` 仍是 CI 里最便宜的 SLO 探针。

## 本章小结

八件工具是一条因果链的八个探针：**包在路上吗 → 端口通吗 → 状态堆积吗 → 谁的 fd 没关 →
协议对话对不对 → 线缆上到底发生了什么**。章末 tcpdump 判读表（RST/零窗口/重传）是把前五节攒下的
TCP 知识（04 章 4.2/4.6、06 章 6.1）在故障现场合并兑现。
