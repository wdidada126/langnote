# 第1章 C++必知必会 — RAII、pimpl 与 C++11/14/17 工具箱

> 对应原书第 1 章（§1.1–1.11，原书第 1–70 页）。目录经豆瓣条目 35491437 核实 ✅。
> 本章在全书中的角色：作者自述本书「从操作系统原理角度讲 C++ 服务器开发」，而第 1 章是
> 入场券——把后面 3/4/7 章反复使用的语言设施（RAII、pimpl、智能指针、emplace 语义）一次讲清。

## 核心概念速览（中英对照）

- **资源获取即初始化** — RAII (Resource Acquisition Is Initialization)：资源所有权绑定到对象生命周期，离开作用域自动释放
- **指向实现的指针** — pointer to implementation (pimpl)：公有接口只持前置声明的 Impl 指针，实现细节移出头文件
- **注解标签** — attributes（`[[deprecated]]`/`[[nodiscard]]`/`[[maybe_unused]]`）：C++11 引入、C++17 标准化的编译器可读标注
- **统一初始化** — uniform initialization / `std::initializer_list`：`{}` 语法统一各类初始化并支持自定义容器式构造
- **智能指针** — smart pointer（`unique_ptr`/`shared_ptr`/`weak_ptr`）：用对象语义表达所有权/共享所有权/观测权
- **从派生类共享** — `std::enable_shared_from_this`：让被 `shared_ptr` 管理的对象安全地再生出自己的共享句柄
- **原位构造** — in-place construction / `emplace` 系列：参数直达元素存储位置构造，省一次拷贝/移动
- **就地插入不覆盖** — `try_emplace` / `insert_or_assign`：C++17 为 map 补上的两个"意图明确"插入语义
- **结构化绑定** — structured bindings：`auto [k, v] = *it;` 把 tuple 式对象解包进具名变量
- **基于范围的循环** — range-based for：依赖 `begin()/end()` 协议，可为自定义类型实现以支持
- **移动语义** — move semantics（`std::move`/右值引用）：把"窃取资源"表达为可优化的构造/赋值 overload
- **`final`/`override`/`=delete`** — 类层次控制关键字：锁死继承/覆写、显式删除函数

## 动机：为什么服务器书要先讲语言子集

服务器代码的三大长期运行特征是**高频分配释放、多线程共享、异常/错误路径必须清理资源**。
本章每个设施都对应一个服务端事故类别：忘了 close/free → 泄漏（1.1 RAII 用三个"不完美版本"
——裸写、goto 统一出口、`do{...}while(0)` 宏——逼出 RAII 的必要性）；头文件传染 → 全量重编
（1.2 pimpl）；拷贝语义下的双重所有权 → 崩溃（1.11 智能指针谱系）。这不是泛泛的"C++ 特性介绍"，
是把特性按"服务器事故防御清单"重新排序。

## 机制：四条主线各自的实现层细节

### 1.1 RAII 四版演化（书中最值得精读的小节之一）

书用同一个"打开文件→申请内存→连 socket→逐步失败需逆序回滚"的例子写了四个版本：

1. 裸写：每个错误分支手工回滚，路径组合爆炸，漏一条即泄漏；
2. `goto fail3; fail2; fail1;`：Linux 内核风格，逆序集中清理，但仍要人肉维护编号对应；
3. `do { ... } while (0)`：给宏一个语句体的惯用法，配 goto 也能统一出口；
4. RAII：每类资源一个包装类，析构顺序=构造逆序，**回滚逻辑由编译器自动织入**。

关键机制点：RAII 的确定性析构依赖"栈展开/return/异常沿同一个作用域模型走"，所以
**它的对手是显式 longjmp、`exit()`、线程被TerminateThread 强杀**——这三条路都不会析构栈对象，
为 3.1 章"线程崩溃语义"与 9.3 日志落盘埋下伏笔。

### 1.2 pimpl：把 ABI 债与编译债一起还

书给出的形态是 `class Widget { struct Impl; Impl* p_; };`（原始裸指针版）。机制上它同时解决三件事：
头文件不暴露私有成员布局（改实现不重编用户代码）、切断第三方类型的 include 传染、隐藏线程句柄等
不可拷贝资源。**代价**：构造多一次堆分配、成员访问多一次指针追逐、特殊成员函数需手工转写。
`unique_ptr<Impl>` 版可解所有权问题，但要在**析构函数定义在 .cpp**（否则 `delete` 需要 Impl 完整类型，
头文件里默认生成的析构会编译失败）——这是 EMC++ item 22 的著名细节 ⚠️ 书中用了裸指针版，现代默认写法是 `std::unique_ptr<Impl>`。
实测对照（sizeof 恒 8/16  vs 朴素版随成员漂移）见 [../C++API设计/02-不透明指针与Pimpl.md](../C++API设计/02-不透明指针与Pimpl.md)（同工程目录版，g++ 15.2 已实测）。

### 1.3–1.9 特性层：每条都给"为什么存在"

- 1.4 统一初始化：`std::initializer_list` 让自定义类支持 `{a,b,c}`（本质是构造一个持有 const 数组视图的轻量对象），同时 `{}` 收窄了隐式窄化转换；坑：`vector v{5}` 是 5 个元素不是 size=5。
- 1.5 attributes：书把 C++17 的 `[[nodiscard]]/[[maybe_unused]]/[[deprecated]]/[[fallthrough]]` 与 GNU/MSVC 老式 `__declspec`/`__attribute__` 做了谱系对照。
- 1.6 `final/override/=default/=delete`：`override` 是**签名级防错**（改基类虚函数签名后派生类静默失配的事故）；`=delete` 精确关闭拷贝保移动。
- 1.8 range-for 展开为 `auto&& __tmp = 容器; for (__it=begin(__tmp); ...)`：**悬垂 range 陷阱**（`for (auto x : getTemp())` 中临时量生命周期）与自定义 `begin/end` 支持协议在此节讲透。
- 1.9 结构化绑定：`auto [k,v]` 为 pair/tuple/公有成员三元组解包，配合 1.10 的 try_emplace 返回值是标准用法。

### 1.10–1.11 容器与智能指针：所有权的三种表达

- `emplace` 系与 `try_emplace/insert_or_assign`（1.10.2）：书特别强调 `operator[]` 会**静默默认构造**、
  `insert` 对已存在 key 的构造参数求值浪费，try_emplace "存在则不动、不存在才原位构造"，配合
  mapped_type 不可默认构造的容器是救命语义。
- 智能指针谱系（1.11）：`auto_ptr` 的"拷贝即窃取所有权"失败史 → `unique_ptr`（零开销，删除器进类型/进对象两态）→
  `shared_ptr`（引用计数控制块：两个原子计数+删除器，拷贝只加计数不复制对象）→ `weak_ptr`（破解循环引用、观测不持有）。
  1.11.6「智能指针对象的大小」是本版独有：`unique_ptr` 默认删除器下 sizeof 等于裸指针（空基优化），
  `shared_ptr` 恒为两指针（对象指针+控制块），自定义删除器入类型则 `unique_ptr` 变胖。1.11.7 注意事项：
  禁止 `shared_ptr<T>(this)`（双重控制块→双重释放），必须走 `enable_shared_from_this`；
  `shared_ptr` 对数组用 `shared_ptr<T[]>`（C++17）而非手写删除器。🔧 实测（g++ 15.2, x64）：
  `sizeof(unique_ptr<FILE*>)=8`、`sizeof(shared_ptr<T>)=16`，与书中结论一致。

## 权衡与边界

| 手段 | 买到的 | 付的账 | 替代 |
| --- | --- | --- | --- |
| RAII 包装 | 自动逆序回滚 | 每资源一个类的设计成本 | goto 出口（仅 C 可行） |
| pimpl | 编译防火墙+ABI 稳 | 一次间接/堆分配 | 不透明句柄 C 接口 |
| `shared_ptr` 图 | 多所有者安全共享 | 原子计数开销、循环引用 | `unique_ptr` 树+`weak_ptr` 反向边 |
| `emplace` | 省一次移动/拷贝 | 参数转发失败报错难读 | push 临时对象（可读性优先） |
| 结构化绑定 | 解包样板归零 | 名字非成员、可捕获性差 | tie 左值元组 |

## 相邻概念对比

- **RAII vs GC**：确定性 vs 吞吐优先；服务器长连接资源（fd/session）必须确定性释放——本书站队 RAII。
- **`unique_ptr` vs `shared_ptr`**：所有权唯一性是最强文档；`shared_ptr` 滥用 = 所有权民主化 = 没人负责。
- **pimpl vs 不透明指针**：见 [../C++API设计/02-不透明指针与Pimpl.md](../C++API设计/02-不透明指针与Pimpl.md)（C 句柄版的动机与本章同源）。
- **`try_emplace` vs `operator[]` vs `insert`**：三者对"key 存在"的处理分别是"不动/覆盖默认值后再改/不插入但仍可能构造 value"，意图表达完全不同。

## 最新演进与工业实践

- **C++20/23 续集**：`std::span`（视图化"缓冲指针+长度"，9.3 日志与 7.7 收发缓冲的天然参数类型）、
  `std::bit_cast`、`consteval/constinit`、`std::expected`（C++23，错误码路径的标准化，直接对话本书 9.4 错误码系统）。
  `[[likely]]/[[unlikely]]`（C++20）是 1.5 attributes 线的续集。
- **`std::make_unique<T[]>`**（C++14 补全）与 `shared_ptr<T[]>`（C++17）终结了"智能指针+数组"最后一片手工区。
- **契约与 [[nodiscard]] 的工业执法**：P2388 "Minimum Contract Support"（C++26，已核实于
  [wg21.link/p2388](https://wg21.link/p2388)）与 GSL 的 `Expects/Ensures`；LLVM/abseil 把 [[nodiscard]] 作为 API 默认审查项。
- **fmt/格式库**：1.x 各节没讲格式化，而 9.3 日志要用；`std::format`（C++20）+ {fmt}
  （[fmtlib/fmt](https://github.com/fmtlib/fmt)，经检索核实）已是当代默认，替代 sprintf 家族。
- **现代重估**：本章 80% 结论在 2026 年依然逐字成立；失效的主要是示例载体（`auto_ptr` 已在 C++17 删除、
  CMake 3.5+ 时代语法见 02 章），以及"pimpl 用裸指针"的写法（现代一律 `unique_ptr`）。
