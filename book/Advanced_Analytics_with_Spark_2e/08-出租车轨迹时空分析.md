## 章定位

**全书法文（DataFrame/SQL）转向的样板章**（2e 相对 1e 重写幅度最大的一章 ✅ 由仓库目录 `ch08-geotime` 与中译公告目录双源对位）：NYC 出租车行程 CSV，用 Spark SQL 完成时间解析、聚合窗口、地理计算、目的地分类。数据集 ✅ 仓库 README：`storage.googleapis.com/aas-data-sets/trip_data_1.csv.zip`（2013 Q1，约 1710 万行程；原源 NYC TLC 已改版 ⚠️）。

## 8.1 脏 CSV 的第一公里

- 典型脏数据：起止时间字符串（`2013-01-01 00:28:00`）混在列里、费率/小费需派生、经停点缺失、`rate_code`/机场标志需人工规则 ⚠️。
- 书中路径：先 RDD 清洗（regex 抽取字段、`to_timestamp`）→ 再注册 DataFrame——2e 特意演示"从 RDD 上升到 DataFrame"两条腿 ⚠️。
- Schema 显式定义（`StructType`）而非推断：CSV 大文件 `inferSchema` = 全量扫两遍+类型误判，书中列为反例 ⚠️✅（csv 数据源选项见 sql-data-sources-load-save-functions.html）。

## 8.2 时间维度：解析、分组、窗口聚合

- 解析：`unix_timestamp/to_date/date_format`、`hour(ts)/dayOfWeek(ts)` 派生列（SQL 函数面 ✅ https://spark.apache.org/docs/latest/sql-ref-functions-builtin.html ）⚠️。
- 分组报表：按（小时×星期）count、avg(fare)——即"热力图底料"；`groupBy().agg()` + `pivot`（2.x 中期引入）⚠️。
- **窗口函数**（本章技术高点）：`Window.partitionBy("start_hour").orderBy("ts")` + `rowsBetween`/`rangeBetween` 做累计流量、滑窗计数、环比；等价 SQL `OVER (PARTITION ... ORDER ...)` ✅ https://spark.apache.org/docs/latest/sql-ref-syntax-qry-select-window.html 。
- 🔧 窗口语义类比（**非 Spark**）：DuckDB 在播放表上实测累计和：u1 组 `ROWS UNBOUNDED PRECEDING→current` = (5, 8)，lag 列首行为 NULL；**RANGE 与 ROWS 的分叉演示**：u2 两行 (ts=3,cnt=2),(ts=9,cnt=4)，`RANGE BETWEEN 2 PRECEDING` 第二行=4（ts=3 落在窗口外），`ROWS BETWEEN 2 PRECEDING` 第二行=6（全部纳入）——Spark 文档同款 range（按值域）/rows（按行数）区分即此语义 ⚠️+URL ✅。
- 节假日/时钟陷阱：时区（EST/EDT）与 `timestamp` 类型换算在 2.x 有已知坑（改过多次），书提醒固定 `spark.sql.session.timeZone` ⚠️。

## 8.3 空间维度：点到点与分类

- 书中不引专门 GIS 库：haversine 距离用三角函数内建手写 ⚠️；机场=JFK/LGA/EWR 经纬度框 + `rate_code` 双规则分类目的地类型。
- 地理分层：把城市切网格/区划（zip、borough）做 groupBy——"空间聚合=离散化后的分组聚合"观点 ⚠️。
- 距离带分布：`width_bucket` 式分箱（书中 floor(d/1000)）+ count → 距离直方图；`ntile`/分位数替代 ⚠️。
- 现代对照：`spark-geo`/GeoSpark 已并入 **Apache Sedona**（Spark 空间扩展），书内手写公式仅作教学 ⚠️✅（https://sedona.apache.org/latest/ 本机 curl 200，2026-09）。

## 8.4 分析结果的呈现与验证

- 书中以"按小时流量曲线 + 机场流向表"作图前收口；聚合结果落 Parquet 给 BI ⚠️。
- 正确性三板斧（本章可迁移方法论）：①与 TLC 官方月度统计对总数；②抽样手算验证窗口累计；③NULL/负票价过滤规则显式写出 ⚠️。

## 逐节精读扩展（重构笔记）

1. **trip_data_1 字段表**（书口径 ⚠️）：medallion（车）、hack_site、vendor、rate_code、pickup/dropoff datetime、passenger_count、trip_distance、fare、tip、tolls、total、payment_type——13 列里 4 个派生目标（时长、距离/分钟、机场标志、小费率）⚠️。
2. **从 RDD 清洗到 DF 的完整桥段**（本章方法论骨架 ⚠️）：
   - 首列脏时间用正则组抽取 → `to_timestamp`；
   - 清洗后的元组 `toDF(cols)` 注册 `spark.sql("CREATE TEMP VIEW trips")`；
   - 此后全书风格突变：**SQL 字符串成为主要 API**——2e 的叙事实验 ⚠️。
3. **时间派生函数族**（✅ sql-ref-functions-builtin 已验 200）：`unix_timestamp(ts2)`、`hour()/minute()`、日期减法求时长、`floor(ts/3600)*3600` 分桶——"分桶=除法取整再乘回"的万能式在 Spark/DuckDB/SQLite 三栈同形（🔧 见 4）⚠️。
4. **🔧 聚合分桶跨栈复述（非 Spark）**：DuckDB 播放表按 `ts` 直接分组与"分钟桶"两种粒度语义，同 [03 章 §3.1](03-音乐推荐与Audioscrobbler数据集.md) D1；SQLite `SUM(CASE...)` 复核同值——时间桶是**分组键的函数**，与引擎无关的纯算术 ⚠️+🔧。
5. **窗口在本章的三用法**（书案例线 ⚠️）：
   - 小时流量累计：`sum(cnt) over (order by hour)`（🔧 D2 实测 u1 累计 5→8 与 lag 首 NULL）；
   - 滑窗去重计数：`rangeBetween(-3600,0)` 按值域（🔧 D2range 演示 RANGE=4 vs ROWS=6 的分叉，u2 两行）；
   - 环比：`lag`+`lead` 组合成三段 CASE——书用它标"异常涨落小时"。
6. **机场分类的地理规则**（书原文逻辑 ⚠️）：JFK/LGA/EWR 各给经纬度圆（r≈1.5km）+ `rate_code==2` 双信号取或；分类错误率用 TLC 官方机场单程统计对账——**空间规则也要做 QA** ⚠️。
7. **haversine 手写版**：`2R·asin√(sin²Δφ/2+cosφ₁cosφ₂sin²Δλ/2)`；书强调先转弧度、`cos` 用 double 防 float 精度塌缩（30km 内误差即显）⚠️。
8. **距离带直方图**：`floor(trip_distance/5)` 分箱 + count + 累计占比窗口——本章的"报表交付物"；现代等价 = `width_bucket`/`ntile`（DuckDB 原生 ✅，Spark 需手写除取整 ⚠️）。
9. **性能伏笔**（为 05 章铺垫 ⚠️）：1700 万行 CSV 首扫 inferSchema 双阶段耗时是显式 schema 的 3~5 倍——书附实测对比（量级转述 ⚠️）；Parquet 化后二次分析跳过解析，路径见 [../Use_Iceberg_with_Spark/03-数据读写与MERGE-INTO.md](../Use_Iceberg_with_Spark/03-数据读写与MERGE-INTO.md)。

## 本章自问自答

- **Q1：本章到底算 RDD 章还是 SQL 章？** A：桥章——前半 RDD 清洗后半 DataFrame/SQL；2e 用它宣告"默认面换 SQL" ⚠️。
- **Q2：窗口帧 RANGE/ROWS 何时选哪个？** A：时间连续性语义→RANGE；"最近 N 条"语义→ROWS；🔧 分叉实测见 §8.2。
- **Q3：时区坑怎么一次防住？** A：入库即 UTC epoch、展示层转换；Spark 固定 session.timeZone；跨引擎同纪律 ⚠️。
- **Q4：不用 Sedona 能做多边形区域归属吗？** A：能（射线法 UDF）但慢；本章圆近似是刻意降维——生产上点面归属交给 Sedona/索引 ⚠️。
- **Q5：pivot 和窗口谁替代谁？** A：形状变换（行转列）→pivot；累计/排名→窗口；书演示两者组合成"小时×星期热力表" ⚠️。
- **Q6：本章数据换成 Iceberg 表收益？** A：schema 演化（新增 payment 列）、时间旅行对账、隐藏分区裁剪——04/05 篇已展开：[../Use_Iceberg_with_Spark/04-时间旅行与元数据表.md](../Use_Iceberg_with_Spark/04-时间旅行与元数据表.md)、[../Use_Iceberg_with_Spark/05-演化与隐藏分区.md](../Use_Iceberg_with_Spark/05-演化与隐藏分区.md)。

## 书中写法 ↔ 现代写法速查（迁移表）

| 书中（2.x） | 现代（3.5/4.x） | 状态 |
|---|---|---|
| `spark.sql("CREATE TEMP VIEW")` | `createOrReplaceTempView` + SQL 混用 | ✅ 稳定 |
| regex 抽时间串再 `unix_timestamp` | `to_timestamp(col, fmt)` 直解 | 内建进化 ✅ |
| `Window...rowsBetween` | 同左；SQL `RANGE` 语法完善 | ✅ window 参考页（已验 200） |
| 手写 haversine | Sedona `ST_Distance` | 库化 ⚠️✅（sedona 已验 200） |
| `floor(d/5)` 分箱 | `width_bucket` 系函数（方言差异大 ⚠️） | 半迁移 |
| RDD 清洗→DF 混合流 | 全 DF（schema 直读 + `try_cast`） | ANSI/try_cast 进化 ✅ |
| 落 Parquet 给 BI | Iceberg 表 + 时间旅行 | 湖仓换代（见接点） |
| `session.timeZone` 手设 | 同左 + `timestamp_ntz` 新类型 | 新增选项 ⚠️ |

**本章 SQL 骨架默写卡**（书案例顺序 ⚠️）：①`hour(pickup)` 分组计数=热力原料；②`SUM(...) OVER (ORDER BY hour)`=累计；③`LAG()` 环比+CASE 标异常涨落；④机场圆+rate_code 双信号分类；⑤距离带 `WHERE BETWEEN` 直方图——五段合成本章全部报表。

**数据量纲备忘**：约 1710 万行 ×13 列 CSV 为 GB 级（⚠️ 记忆量级，未本机复核）；Parquet 化+列裁剪后再降——本章"空间换时间"第一账本。

**QA 五查**（§8.4 展开 ⚠️）：行数对官方月报、时长无负、fare≥起步价、机场量级对账、窗口累计三点手算一致——五查齐了才出图。

## 本章金句与误读提醒

1. 金句（书意转述 ⚠️）："时间不是列，是函数；空间不是字段，是算式。"
2. 误读一：`inferSchema` 省事——大 CSV 上它是双倍扫描+错误类型的来源；显式 schema 是纪律不是洁癖 ⚠️。
3. 误读二：窗口帧一律用 ROWS——时序报表里行数≠时间跨度，RANGE/ROWS 分叉（🔧 D2range 实测 4 vs 6）就是事故样本 ⚠️。
4. 误读三：圆近似能糊弄——机场分类可以，行政区归属不行；把近似边界写进需求再动工 ⚠️。
5. 一个可带走的原则：每个聚合数字都要有对账对象（官方统计/手算三点），无对账即不可发布 ⚠️。

## 核心概念速览（中英对照）

1. **行程事实表** — trip fact table：一行一行程的星型事实粒度。
2. **schema 显式声明** — explicit schema：StructType 定义，免推断双扫描。
3. **窗口帧** — window frame：ROWS/RANGE + UNBOUNDED/PRECEDING 的滑窗定义。
4. **range vs rows** — RANGE 按值域、ROWS 按行数（🔧 已实测分叉）。
5. **累计聚合** — running aggregate：累计流量/环比的载体。
6. **pivot** — pivot：分组结果转列宽表。
7. **haversine** — haversine formula：球面两点距离。
8. **地理分箱** — spatial binning：网格化后转分组问题。
9. **session timezone** — 会话时区：`spark.sql.session.timeZone` 固定解析。
10. **rate code** — 费率类别：纽约出租车官方分类字段（机场单程等）。
11. **数据对账** — reconciliation：与官方统计核对总量。
12. **Parquet 落盘** — columnar handoff：分析结果交 BI 层的列存中间层。
