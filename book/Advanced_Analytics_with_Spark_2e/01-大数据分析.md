## 章定位

本章是全书的"问题域地图"：不写代码，回答三个问题——什么是高级分析（advanced analytics）、为什么需要大数据工具、Spark 在这套工作流里扮演什么角色。2e 相较 1e 的主要变化是把叙事从"批处理 RDD"转向"结构化数据 + ML 流水线"，本章即给出全书 10 个案例章的索引 ⚠️（依据中译公告章序与官方仓库 `2nd-edition` 分支目录对位，见 00 §3）。

## 1.1 高级分析的定义与驱动力

- 本书语境的"高级分析"= 在**超出单机内存的数据规模**上运行**统计/机器学习/图/文本/模拟**类算法，产出的不是报表而是**模型与预测** ⚠️。
- 三股驱动力（本书框架）⚠️：数据量（传感器、日志、基因组、影像）、算力（廉价集群 + 内存化引擎）、算法（可扩展的 ML/图算法成熟化）。
- 与商业智能（BI）的分工：BI 回答"发生了什么"（聚合/切片），高级回答"会/该怎样"（预测/推荐/异常检测）；两者在 Spark 上共享同一存储与 DataFrame 层 ⚠️。

## 1.3 Spark 工作流与生态位

- 抽象栈（2e 时点）：存储层（HDFS/S3/本地）→ RDD 内核 → DataFrame/SQL（Catalyst）→ MLlib/GraphX/ML 管道 → 应用 ⚠️；原理细节在盘上笔记：[../bigdata/01-大数据技术全景.md](../bigdata/01-大数据技术全景.md)、[../bigdata/02-Spark核心与RDD模型.md](../bigdata/02-Spark核心与RDD模型.md)。
- "分析工程师画像"：本书目标读者是会用编程手段做分析的人（统计学家写代码、工程师做分析），Spark 提供"单机脚本 → 集群"的连续统 ⚠️。
- 为什么不是 MapReduce/Hadoop：内存驻留、DAG 调度、迭代算法友好（ML 需要几十轮遍历数据）⚠️ —— 工程化论证见 [../bigdata/10-计算引擎的演进.md](../bigdata/10-计算引擎的演进.md)。

## 1.5 本章方法论要点

1. 先认"问题族"再选算法：推荐=分解、分类=树、异常=距离/频率、文本=向量空间、图=消息传递。
2. 数据可获取性优先：全书数据集全部公开（UCI/维基/1000Genomes/NYC TLC）✅（清单在仓库 README「Data Sets」节）。
3. 迭代算法是 Spark 的甜点负载：窄依赖链 + 广播不变量 + 持久化，见下一章机制层。

## 逐节精读扩展（重构笔记）

1. **"高级"的三重含义**（书意归纳 ⚠️）：
   - 问题高级：从描述性统计跨入预测性/规范性分析；
   - 算法高级：ML/图/模拟/信息论工具，而非 SUM/COUNT；
   - 数据高级：半结构化、多模态（XML/二进制 BAM/影像 TIF），"CSV 之外皆异端"的世界。
2. **为什么每个案例选那类数据**（编排逻辑 ⚠️）：推荐=行为日志（最大规模真实 RDD 练习）、树=表格（特征工程）、聚类=安全（无标注现实）、LSA=文本、图=生物文献、时空=DataFrame、模拟=金融、基因组/影像=极限自定义格式。10 章合起来是 Spark API 面的**覆盖矩阵测试** ✅（与 sryza/aas 目录对位）。
3. **数据-算法-规模三角**（本章方法论）：先问数据放得下内存吗（放不下→分区策略）、算法可分解为 map+shuffle 吗（不可→改模型或单机）、规模需要多集群吗（需要→本节全部案例重排优先级）⚠️。
4. **与邻域学科的划界**（书中立场 ⚠️）：统计学关心估计无偏，ML 关心预测误差， hacking data（书自嘲语）关心"能跑且有用"；本书站第三立场但借用前两者的体检指标。
5. **工程师画像节选**（本章职业论断 ⚠️）：目标读者="会写代码的分析师"与"懂统计的工程师"的重叠带；2026 年这一重叠带的通用语言已从 Scala 换到 Python/SQL——读本章概念不换读本章工具建议。
6. **规模门槛的诚实数字**（书给的心理刻度 ⚠️）：GB 级→单机 Spark 即可；TB 级→集群甜点区；PB 级→本书模式多需改造（文本/图切分策略变复杂）——三档划分与 [../bigdata/01-大数据技术全景.md](../bigdata/01-大数据技术全景.md) 的"规模光谱"同构。
7. **本章未讲而盘上已补**：数据治理（波4 #189 登记）、数据质量画像（[../bigdata/12-数据质量与工程实践.md](../bigdata/12-数据质量与工程实践.md)）、成本工程（云时代"该不该用 Spark"的钱问，本书 2019 语境未展开 ⚠️）。

## 本章自问自答

- **Q1：高级分析 = 机器学习吗？** A：不是。本书含模拟（09）、图算法（07）、格式工程（10）等非学习范式；ML 只是子集 ⚠️。
- **Q2：为什么 2e 要弱化 RDD 叙事？** A：DataFrame/SQL 在 2.x 已证明性能与易用双优，案例章从 08 章起明显迁移 ⚠️+02 章。
- **Q3：案例数据集 2026 年还能下载吗？** A：部分能（KDD ✅ 200、covtype 308→新址 ✅、维基 dumps ✅ 滚动、audioscrobbler 书方桶 ✅ 模式存在但未逐 URL 探活 ⚠️、NCBI ftp ⚠️）；见各章演进节勘误。
- **Q4：学完本书能直接上生产吗？** A：模式可迁移，API 需换代（每章"最新演进"即迁移表）；生产还需盘上湖仓/流式/运维三块拼图 ⚠️。
- **Q5：本书和《Learning Spark》区别？** A：后者讲引擎与 API 本身，本书讲"用引擎做什么分析"；盘上前者未建目录版（00 §11 登记）。
- **Q6：为什么图章用共现网而非社交网？** A：MEDLINE 主题词表是**现成的、带权威语义标注的**共现实验场，答案可人肉验证——教学可控性优先 ⚠️。
- **Q7：Spark 会取代数仓吗？** A：2019 书的隐含乐观在 2026 被修正为分工：仓内 SQL（含湖仓）与集群 ML 双轨，互喂数据 ⚠️；三巨头侧见同波云仓册登记。

## 核心概念速览（中英对照）

1. **高级分析** — advanced analytics：以模型与预测为产出、面向超大规模数据的统计/ML 实践。
2. **隐式反馈** — implicit feedback：从行为（播放/点击）而非评分推断偏好，本书推荐章主线。
3. **异常检测** — anomaly detection：以稀有性（聚类距离/频率）识别偏离样本。
4. **潜在语义分析** — latent semantic analysis (LSA)：以低秩矩阵近似捕捉词-文档隐含语义。
5. **伴生网络** — co-occurrence/companion network：实体因共同出现而连边的图。
6. **蒙特卡罗模拟** — Monte Carlo simulation：并行随机采样估计分布与风险度量。
7. **变异检测** — variant calling：从测序比对推断个体基因组差异位点。
8. **RDD** — resilient distributed dataset：Spark 内存容错分布式集合抽象（详见 02 章）。
9. **DataFrame** — DataFrame：带 schema 的分布式表，2e 案例逐步采用的上层抽象。
10. **MLlib** — MLlib：Spark 官方 ML 库（分类/聚类/分解/评估）。
11. **GraphX** — GraphX：Spark 图计算组件，属性图 + Pregel 风格。
12. **问题族** — problem pattern：本书组织单元：一类业务问题 ↔ 一套可扩展算法。

## 最新演进与工业实践

1. **3e 已出版**：官方仓库 README 标注 "3rd edition (current)"，master 分支对应 3e ✅ https://github.com/sryza/aas ；3e 全面转 PySpark、新增作者 Akash Tandon ⚠️（apachecn 著录，纸质年份未独立核验）。2e 的 Scala-first 叙事在 2024+ 已非首选。
2. **Spark 版本线（2026-09 实测 ✅）**：spark.apache.org/downloads.html 当前列 4.2.0 / 4.1.3 / 4.0.4 / 3.5.9；本书 2.x 基线跨了 8 个次版本，配读时以 `docs/latest` 为准。
3. **SQL-first 收敛**：官方文档将 SQL/DataFrame 定为主接口（https://spark.apache.org/docs/latest/sql-programming-guide.html ✅），RDD 降级为"扩展作者 API"；本书 RDD-heavy 案例（04/05/10 章）现代等价物多为 DataFrame/UDF。
4. **Pandas API on Spark**：pandas 语法原生跑集群（https://spark.apache.org/docs/latest/api/python/reference/pyspark.pandas/index.html ✅ 200），"分析工程师"可平移 pandas 技能，替代本书 Scala 教学路径。
5. **Spark Connect**：客户端-服务端架构 GA（https://spark.apache.org/docs/latest/spark-connect-overview.html ✅），Notebook/远程分析场景与 2019 年"本地 spark-shell"截然不同。
6. **Lakehouse 落地**：本书直读裸文件的案例（CSV/BAM/TIF）在现代企业多落 Iceberg/Parquet：见 [../Use_Iceberg_with_Spark/00-总览与阅读地图.md](../Use_Iceberg_with_Spark/00-总览与阅读地图.md)、[../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md](../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md)。
7. **ML 平台化**：单库 MLlib → 生态（MLflow 追踪、Databricks 托管、feature store），本书手工特征工程多被平台取代 ⚠️。
8. **工业采用**：大规模数据分析仍是 Spark 基本盘（ETL+ML），但"交互式分析"份额被 DuckDB/Polars/ClickHouse 蚕食——小数据问题别上集群，与本书 2019 判断一致并更强化 ⚠️。
9. **对照阅读**：原理侧最新演进（AQE、variant、collations 等 Spark 3.x/4.x 特性）已系统写在 [../bigdata/05-Spark性能优化.md](../bigdata/05-Spark性能优化.md) 与 [../bigdata/10-计算引擎的演进.md](../bigdata/10-计算引擎的演进.md)，本书各章演进节不重复、只补案例域动态。
10. **流式格局**：DStreams 已于 Spark 3.0 移除，Structured Streaming 独存；流式分析对照见 [../bigdata/07-实时计算与流式架构.md](../bigdata/07-实时计算与流式架构.md)（本书 2e 未设流处理专章——1e 亦无，名册"流处理章"说法修正为：时空/聚合章的演进节覆盖）。
