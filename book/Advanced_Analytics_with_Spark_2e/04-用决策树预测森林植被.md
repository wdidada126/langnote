# 04 · 用决策树算法预测森林植被（Classifying Entities with Tree Models）

> 《Advanced Analytics with Spark, 2e》第 4 章精读重构 ｜ 总览见 [00-总览与阅读地图.md](00-总览与阅读地图.md) ｜ ✅ / ⚠️ / 🔧（DuckDB 1.5.5 类比，非 Spark 行为）

## 章定位

监督学习案例：UCI **Covertype** 数据集（✅ 仓库 README 指向 archive.ics.uci.edu/ml/machine-learning-databases/00210/）——58 万条、10 维连续 + 44 维独热、7 类森林植被覆盖类型，目标=按地形特征预测类别。代码目录 `ch04-rdf`（Random Decision Forest）✅。本章同时是"RDD 特征工程"最重的一章：MLlib 旧 RDD 版 `DecisionTree`/`RandomForest`/`GradientBoostedTrees` 的全流程 ⚠️。

## 4.1 数据与特征工程

- 原始 CSV：`Elevation, Aspect, Slope, ... Soil_Type（44 独热列）, Cover_Type(标签 1-7)` ⚠️。
- 标签变换：`label - 1` 成 0-based 多分类；特征向量 = `DenseVector(连续) ++ SparseVector(独热)`——**稀疏表示是规模关键**（54 维里最多 ~11 个非零）⚠️✅（linalg 文档 https://spark.apache.org/docs/latest/ml-features.html ）。
- 训练/测试切分：`randomSplit([0.8,0.2], seed)`；类别不均衡（多数类占近半、少数类不足 1%，具体占比 ⚠️ 以 UCI 页 class 分布为准，本机未下载核验）——书中给每类抽样/加权重训 ⚠️。
- 特征选择讨论：海拔/坡度等地理直觉筛除无效列（ wilderness area/soil 独热组降权），2e 提醒"别只信直觉，看重要性"⚠️。

## 4.2 树模型机制（书所讲 vs 现代实现）

- **CART 贪心二分**：不纯度（分类=Gini，回归=方差）下降最大处分裂；MLlib 树用**分位数分箱**（maxBins）把连续列离散成候选阈值——这是它可扩展的核心（分布式直方图 + Shuffle）⚠️✅（decision-tree-guide）。
- 2e 亮点（相对 1e）：MLlib 树实现重写（2.0 起）——**两遍数据、按分区聚合直方图、预测广播**；旧版 1.6 前内存/速度问题严重，书中专节对比 ⚠️。
- **随机森林**：行抽样（bootstrap）× 列抽样（maxFeatures）× 多棵树投票；并行训树=独立模型平均，Shuffle 友好 ⚠️。
- **GBT**：顺序拟合残差，学习率 shrink；树深小（3-5）× 树多；过拟合风险高需监控验证误差 ⚠️。
- 模型导出：`model.toDebugString()` 打印树结构——书中用来做"人肉解释"，特征重要性 = 各树不纯度下降累计 ✅（mllib-tree-concepts 口径）。

## 4.3 评估与调参清单

1. 指标矩阵：per-class precision/recall/F1 + 混淆矩阵（旧 RDD API `MulticlassMetrics`；现代 `MulticlassClassificationEvaluator`）✅ https://spark.apache.org/docs/latest/mllib-evaluation-metrics.html 。
2. 调参优先级：maxDepth ≥ maxBins ≥ 抽样比 ≥ 类别权重；网格搜索用 `sample` 小数据先行 ⚠️。
3. 基线纪律：先测"多数类占比"基线（Covertype 近半，⚠️ 同上）与单层规则树，再评 RF 增益；2e 明确"没有基线的准确率无意义"⚠️。
4. 🔧 本机类比（非 Spark）：Gini/不纯度的可计算定义用 SQL 表达——在 DuckDB 8 行播放表上 `SELECT sum(p*p)` 型聚合算 impurity 完全可行（聚合语义已在 [03-音乐推荐与Audioscrobbler数据集.md](03-音乐推荐与Audioscrobbler数据集.md) 🔧 验证：NULL 组、FILTER 子句行为）；MLlib 的分位数分箱思想对应 DuckDB `approx_quantile`——Spark `approxQuantile` 文档 ✅ https://spark.apache.org/docs/latest/api/python/reference/pyspark.sql/api/pyspark.sql.DataFrame.approxQuantile.html （本机无法执行 Spark 侧，仅 URL 取证 ⚠️）。

## 4.4 坑与经验（书中案例复盘）

- **过拟合信号**：训练 95%+ 而验证 70%——2e 用此章讲透"树深=10 全记忆"现象；正则手段在 RF 是 bagging 不在树本身 ⚠️。
- `maxBins` 与 `maxCategories` 对独热列的交互坑：类别特征基数大时被误当连续列切分 ⚠️。
- 数据倾斜：某土壤类型占比极端 → 分裂点搜索热点分区慢；对策=重分区/两阶段直方图（新实现已内置）⚠️。
- 复现性：MLlib 树分裂遍历序非稳定排序，同 seed 不同版本结果可微差——书中注记 ⚠️。

## 逐节精读扩展（重构笔记）

1. **Covertype 特征字典**（UCI 公开口径 ⚠️）：
   - 连续 10 列：海拔、方位、 slope、 三向山体阴影、 四组水分指数；
   - 二值 44 列：4  wilderness area + 40 soil type；
   - 标签 7 类植被——"用地理直觉做特征选择"的教学数据集：列名即语义，重要性可直接人话解释 ⚠️。
2. **分布式树的分箱机制**（现代实现 ✅ decision-tree-guide）：
   - 单次扫描每分区算 per-feature 分位数直方图；
   - 全局合并 → maxBins 个候选分裂点；
   - 第二次扫描按候选点聚合左右子节点类计数 → 选 Gini 降最大处；
   - 递归——每层树一次两阶段聚合，深度×Shuffle 的成本公式由此背熟 ⚠️。
3. **`maxBins` 是本章第一旋钮**：越大阈值越细、内存 O(maxBins×特征数)/分区；书演示 maxBins=4 的欠拟合阶梯到 32 的收敛 ⚠️。
4. **随机森林的并行本质**：t 棵树= t 个独立作业塞同一个 Spark 集群—— embarrassingly parallel；对比 GBT 的串行层，训练时间近似线性于树数 ⚠️✅。
5. **GBT 早停**：验证误差不降反升的拐点回退——2e 时代需手工，现代 `CrossValidator`/学习率衰减接管 ⚠️。
6. **类别不平衡工具箱**（本章列法 ⚠️）：过采样少数类（`sample(by=class)` 加权）、类权重（新版 `weightedMeans`）、阈值后处理（按先验调操作点）；书中诚实承认"没有银弹，看混淆矩阵挑方案"。
7. **特征解释链**：森林重要性 → per-class 视角再看一遍（某列对类 7 重要、对类 2 无用）→ 地理合理性复核——本书"模型当探针"的数据科学观样例 ⚠️。
8. **RDD→DataFrame 迁移示范**：同一数据集，`spark.ml` 写法把向量化/训练/评估变成 Pipeline stages ✅（ml-pipeline.html 已验 200）；2e 正文 RDD 版保留原因=让读者看见"分箱 Shuffle 到底发生在哪一步" ⚠️——盘上机制解释见 [../bigdata/03-Shuffle与宽依赖.md](../bigdata/03-Shuffle与宽依赖.md)。
9. **🔧 类比补充（非 Spark）**：D4 分位数实测（cont [500.5,950.05] vs disc [500,950]）说明"分箱阈值=分位数家族"：maxBins 的分位点选择和 `approxQuantile` 是同一算法族（✅ approxQuantile 页已验 200）。

## 本章自问自答

- **Q1：Gini 与信息熵结果差吗？** A：几乎总同向，工程默认 Gini（少一次 log）⚠️。
- **Q2：为什么独热列要 `maxCategories`？** A：告诉 ML 哪列是类别（按枚举而非阈值切）；设错=把 soil_type 当连续切区间，语义灾难 ⚠️。
- **Q3：森林能处理倾斜 key 吗？** A：行抽样天然缓解；极端类仍需在抽样层加权重 ⚠️。
- **Q4：验证集泄露在本章怎么防？** A：切分在特征工程**之前**做（先 split 再标准化/重要性），书中流程按此排列 ⚠️。
- **Q5：`toDebugString` 与 SHAP 谁替代谁？** A：结构解释（路径）vs 贡献度（扰动）；2026 标准姿势是两者并用 ⚠️。
- **Q6：本章算法今天还值得手写一遍吗？** A：分箱+聚合的树**实现**值得（面试与排障刚需），**调用**不值得（用 `spark.ml`/XGBoost）⚠️。
- **Q7：为什么不用线性模型打基线？** A：地理特征强非线性交互（海拔×坡向），LR 基线远低于树——书附对比数据（量级 ⚠️ 未本机复现）。
- **Q8：GPU 上训本章模型现实吗？** A：RAPIDS Spark（cuML RandomForest）2024+ 可跑但生态仍在成熟 ⚠️；表格学习工业默认仍是 XGBoost/LGBM 单机+数据并行。

## 核心概念速览（中英对照）

1. **CART** — classification and regression tree：二分递归贪心树。
2. **Gini 不纯度** — Gini impurity：1−Σpᵢ²，分类分裂准则。
3. **方差减少** — variance reduction：回归分裂准则。
4. **maxBins** — max bins：连续特征分位数分箱上限，可扩展性关键。
5. **随机森林** — random forest：行×列抽样投票树集。
6. **GBT** — gradient boosted trees：顺序残差拟合树集。
7. **特征重要性** — feature importance：不纯度下降累计归一。
8. **OOB** — out-of-bag：bagging 未采样样本做内部验证。
9. **混淆矩阵** — confusion matrix：多分类逐类对角评估。
10. **类别不均衡** — class imbalance：稀有类召回崩塌的主因。
11. **独热编码** — one-hot encoding：类别特征 0/1 展开。
12. **LabeledPoint** — MLlib RDD 样本表示：label + features 向量。

## 最新演进与工业实践

1. **RDD 树 API 已废**：`spark.mllib.tree` 不再演进，`spark.ml`（DataFrame 版 DecisionTree/RandomForest/GBT + `DecisionTreeClassifier`）为唯一主线 ✅ https://spark.apache.org/docs/latest/mllib-decision-tree.html 。
2. **GBM 生态位易主**：工业表格学习转向 XGBoost/LightGBM on Spark（Databricks/GPU 版）与 RAPIDS cuML 随机森林 GPU 线——MLlib GBT 性能与功能双双落后 ⚠️。
3. **ML 管道统一**：本章手工"特征向量化→训→评"流程被 `Pipeline`/`CrossValidator`/`OneHotEncoder`（spark.ml）接管 ✅ https://spark.apache.org/docs/latest/ml-pipeline.html ；`StringIndexer` 处理类别列，独热坑的官方解法。
