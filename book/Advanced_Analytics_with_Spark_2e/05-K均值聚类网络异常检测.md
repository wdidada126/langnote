# 05 · 基于 K 均值聚类的网络流量异常检测（Anomaly Detection via Clustering）

> 《Advanced Analytics with Spark, 2e》第 5 章精读重构 ｜ 总览见 [00-总览与阅读地图.md](00-总览与阅读地图.md) ｜ ✅ / ⚠️ / 🔧（DuckDB 1.5.5 类比，非 Spark 行为）

## 章定位

无监督学习案例：KDD Cup **1999** 网络连接数据集（✅ 仓库 README 指向 kdd.ics.uci.edu/databases/kddcup99/ ，并特别警告**不要**用 sigkdd.org 旧镜像——README 自注那份副本有一行损坏数据，取证细节 ✅）+ MLlib RDD 版 **K-means** 做主机行为聚类，找"离群主机"式异常。代码目录 `ch05-kmeans` ✅。

## 5.1 问题设定与数据

- 背景：DARPA 仿真网络（7 周）+ 攻击注入；每行=2 秒窗口内一条连接记录，41 特征 + `difficulty_level`/label（normal、neptune、satan、buffer_overflow 等 22 类，99% 是正常流量中的 neptune DoS）⚠️。
- 任务变形：不做逐连接监督分类（特征泄露 label 风险），而是**按主机聚合行为向量 → 聚类 → 小簇=可疑**：无监督 + 粗粒度实体（主机/天）三步降维 ⚠️。
- 主机级特征工程（本章精华）⚠️：`count、failed登录数、flag分布、热/端口扇出（distinct destinations per service）`等——把"行为统计"而非原始包作为聚类输入；书中强调**特征选择决定 80% 成败**。

## 5.2 K-means 与可扩展性

- 目标：argmin Σ‖x−μ_c(x)‖²；Lloyd 交替（分配/更新）NP-hard 但收敛快 ⚠️✅（mllib-clustering 文档 https://spark.apache.org/docs/latest/mllib-clustering.html ）。
- 初始化决定一切：随机取点易碎 → MLlib 用 **k-means||**（并行化 K-MC² 加权采样，O(log k) 轮）✅ 同上文档；书 2e 专节讲其原理与 `runs`/`initializationMode` 参数。
- 分布式机理：每分区只算"点到 k 中心距离 + 局部和向量"，reduce 合并——每轮一次小 Shuffle（k×d 摘要），大数据 k 小聚类天然 MapReduce 友好 ⚠️。
- 收敛判据：`epsilon` 中心位移 + `maxIterations`；`kmeansModel.computeCost` 肘部法选 k ⚠️。
- 🔧 一步 Lloyd 迭代的 SQL 语义（**非 Spark**）：DuckDB 在 5 点 1 维数据 {(1.0,1.5),(5.0,5.5),(9.0)}、中心 {0:1.2, 1:5.2} 上跑 `arg_min(k, abs(x-mu))` 分配 + 重算均值，得 **cluster0: n=2, μ=1.25；cluster1: n=3, μ=6.5**（点 9.0 并入簇 1）——完整复刻"分配→更新"一轮；Spark 侧同语义在 MLlib kernel 内部（本机无 pyspark，实测不可行 ✅ ModuleNotFoundError）。

## 5.3 评估：无监督的评估没有标准答案

- 书中双轨 ⚠️：①内部指标（cost/轮廓系数的 RDD 手算版）看簇紧度；②外部验证拿 label 查"攻击落在哪些簇"——小簇富集 rare attacks（buffer_overflow 等）则方法有效。
- 反直觉结论（书明说）⚠️：K-means 检出**行为异常**而非**协议特征**；对"合法但小众"（管理员主机）误报高——异常检测的永恒权衡。
- 归一化前置：41 特征量纲悬殊（duration 秒级 vs logged_in 0/1），z-score 标准化否则簇被大尺度特征垄断；MLlib `StandardScaler` ✅ ml-features.html#standardscaler。
- `VectorScaler`/稀疏向量、以及把主机×天窗口切成 RDD[(host, DenseVector)] 的 `groupByKey` 热点坑 → 见 [02-用Scala和Spark进行数据分析.md](02-用Scala和Spark进行数据分析.md) §2.3。

## 逐节精读扩展（重构笔记）

1. **KDDCup99 字段地图**（41 特征三类 ⚠️✅ 官方页已验 200）：
   - 基本特征：duration、protocol、service、flag、状态字节数；
   - **内容特征**（本任务主角）：同 host 2 秒窗口内 out/src 连接计数、same/diff/srv 速率、server error rate、systime——天然"行为画像"词表；
   - 目标：label + difficulty_level（book 用它做外部验证的作弊参考）。
2. **主机行为向量的构造配方**（书中三步 ⚠️）：
   - 时间分桶（按天）→ 每 (host,day) 聚合 41 特征均值/计数/比例；
   - 派生：失败登录比、端口扇出 distinct、跨协议比；
   - `mapPartitions` 内用固定 schema 直解 CSV（避免每记录 split）——RDD 性能常识复用 [02 章](02-用Scala和Spark进行数据分析.md)。
3. **k-means|| 原理压缩版**（✅ mllib-clustering.html 已验 200）：
   - 轮 1：按密度概率采 O(l·k) 候选（l≈2）；
   - 轮 2~O(log l)：以"到已选中心距离²"再采——模拟加权 Voronoi 划分；
   - 末端加权 k-means 精修中心；对比随机初始化的"质心坍缩"惨案，书中给对照图景 ⚠️。
4. **成本模型**（书给的估算式 ⚠️）：每迭代 Shuffle ≈ k×d×8B 的局部和 + 全量"点→中心"距离计算 O(n×k)；n=千万、k≤50 时分钟级——"k 小"是本章全部工程假设。
5. **聚类→异常的四条改道**（书中讨论 ⚠️）：①小簇全体标异常（阈值=簇规模分位）；②簇内距离 topN；③每簇质心做原型库、新点距离超阈告警（在线化）；④k 增大逼近"稀有模式各自成簇"——②③最可落地。
6. **label 复盘的数字直觉**（书结论 ⚠️ 未本机复算）：主流攻击（neptune/satan）混入正常大簇——**频率型攻击≠行为异常**；检出富集的是 buffer_overflow/multihop 类"行为确实怪"的少数攻击——K-means 检行为偏离不检签名的实锤。
7. **🔧 Lloyd 一步细节复述（非 Spark）**：分配 `arg_min(k, abs(x-mu))` 后更新：点 9.0 距 μ1=5.2 为 3.8、无第三中心 → 并入簇 1，μ 被拉到 6.5——"k 选小→异常被吞进大簇"的现象在这 5 个点里就能演示；这就是演进 1 里"变密度簇 DBSCAN/HDBSCAN"存在的理由。
8. **数据/脚本考古**：README 给的 sigkdd 镜像损坏警告 ✅ 原文在案；UCI 页含 `kddcup.data_10_percent` 抽样版，教学够用 ⚠️。

## 本章自问自答

- **Q1：为什么不直接监督分类（label 都有）？** A：演示无监督的"新攻击开放集"能力；监督对未见类必瞎——两范式互补，本章故意只走难路 ⚠️。
- **Q2：k 怎么选？** A：肘部 + 业务粒度（想分几类行为）双约束；书用 k=8~20 区间演练 ⚠️。
- **Q3：距离用欧氏还是余弦？** A：画像向量量纲已标准化→欧氏；关注形状→cosine（新版 `distanceMeasure` 支持）✅ ml-clustering。
- **Q4：MiniBatchKMeans 呢？** A：大 n 的提速默认项；收敛抖动小数据下不划算——书时代 RDD 版无此选项 ⚠️。
- **Q5：主机画像窗口长度敏感吗？** A：极敏感（2 秒 vs 1 天两种行为语义）——特征时间粒度=分析世界观，本章最大教训 ⚠️。
- **Q6：能上生产吗？** A：KDD99 上能；真实网络需先解决加密流量特征替代（字节序列统计/TLS 指纹）⚠️。

## 书中写法 ↔ 现代写法速查（迁移表）

| 书中（mllib RDD 线） | 现代（spark.ml DF 线） | 状态 |
|---|---|---|
| `KMeans.run(rdd, k, runs=)` | `KMeans(k=, initMode="k-means||")` | ✅ ml-clustering（已验 200） |
| `KMeansModel.predict(v)` | `transform(df)` 出 distance/prediction 列 | DF 批量 ✅ |
| `model.computeCost(rdd)` | `transform` 后聚合 distortion | 口径一致 ⚠️ |
| mllib `StandardScaler` | ml `feature.StandardScaler` | 迁移 ✅ ml-features |
| 距离阈值手工告警 | 同思想；可 streaming 化 | 模式存活 ⚠️ |
| `groupByKey` 做主机画像 | `groupBy(host, day).agg(...)` | DF 重写更短 ✅ |
| 全量 k-means | `MiniBatchKMeans` 优先 | 现代默认 ⚠️ |

**画像特征清单复述**（书口径 ⚠️）：连接数、同服务速率、失败登录比、flag 分布、dest/dest_sport distinct、srv_error_rate——可逐条改写成 DF `agg`；分桶键=(host, day) 复合列。

**异常分数三写法**（书给第一种，后两种为现代补全 ⚠️）：①小簇全体标；②点到质心欧氏距离 topN；③距离/簇内平均距（相对化跨簇可比）——③在 HDBSCAN 时代演化"相对可达距离"概念，思想同源。

**KDD 字段速记**：duration、protocol_type、service、flag、src_bytes、dst_bytes + 同 host/同 log/源机/同域窗口特征（same_srv_rate、serror_rate 等）+ label——41 列里"同实体窗口"子集正是行为画像原料 ⚠️✅（字段族见官方页）。

## 本章金句与误读提醒

1. 金句（书意转述 ⚠️）："聚类不告诉你什么是攻击，只告诉你什么是少数。"
2. 误读一：把 K-means 当"攻击检测器"——它检测的是行为稀有性，合法小众同样上榜；处置流程必须按"待核查"而非"确认"设计 ⚠️。
3. 误读二：把 41 原始特征直接扔进聚类——不聚合到主机、不标准化，簇只会按流量大小分层 ⚠️。
4. 误读三：k 越大越准——k 过大则正常长尾被切碎，异常与噪声混居，富集度反而下降 ⚠️。
5. 一个可带走的原则：先定义"谁的异常"（主机/用户/进程），再做特征与簇——实体粒度先于算法参数 ⚠️。

## 核心概念速览（中英对照）

1. **K-means** — k-means：质心最小化平方误差的划分聚类。
2. **k-means||** — k-means parallel initialization：加权多轮并行采样初始化。
3. **Lloyd 迭代** — Lloyd's algorithm：分配/更新交替的局部收敛主循环。
4. **肘部法** — elbow method：cost 对 k 拐点选簇数。
5. **轮廓系数** — silhouette score：簇内紧度 vs 簇间距的个体评分。
6. **行为特征** — behavioral features：按实体聚合的统计画像（扇出/失败率）。
7. **异常检测** — anomaly detection：识别偏离主体分布的少数样本。
8. **误报权衡** — false-positive trade-off：小众合法行为被判异常。
9. **标准化** — standardization：z-score 消除量纲垄断。
10. **computeCost** — clustering cost：簇内平方和，收敛监控量。
11. **稀疏表示** — sparse vector：`SparseVector` 处理独热/长尾维度。
12. **KDD Cup 1999** — KDD Cup 99：经典入侵检测数据集，含损坏镜像陷阱。
