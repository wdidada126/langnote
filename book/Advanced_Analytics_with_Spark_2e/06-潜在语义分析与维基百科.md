# 06 · 基于潜在语义分析算法分析维基百科（Text Analysis / LSA）

> 《Advanced Analytics with Spark, 2e》第 6 章精读重构 ｜ 总览见 [00-总览与阅读地图.md](00-总览与阅读地图.md) ｜ ✅ / ⚠️ / 🔧（DuckDB 1.5.5 类比，非 Spark 行为）

## 章定位

文本分析案例：把英文维基百科转成**词-文档矩阵**，用 TF-IDF 加权 + **SVD 低秩分解**实现潜在语义分析（LSA），回答"哪篇文章与给定文章语义最像"。代码目录 `ch06-lsa` ✅；数据 ✅ 仓库 README 指向 `dumps.wikimedia.org/enwiki/latest/enwiki-latest-pages-articles-multistream.xml.bz2`（官方当前快照，本书写作时用当年快照 ⚠️）。

## 6.1 文档语料管线

- 维基 dump 是**多流拼接的 XML**（multistream bz2）：每 `<page><title>…</title><text>…</text></page>`；书中自写流式切分（按 `<page>` 边界拆 RDD 分区，避免整文件进 driver）⚠️——这是"自定义输入格式"的教科书例，与 [10-基因数据分析.md](10-基因数据分析.md) 的 BAM 切分同构。
- 清洗：去重（消歧义页/重定向）、去超短页、去标记语言噪声（{{模板}}、[[链接]]、图片注释）；分词=正则 `[a-z]+` 小写切；**停用词**表（the/of/and…）与词干化（Porter）按 `minFrequency/maxDocuments` 阈值裁剪词表 ⚠️✅（文档 https://spark.apache.org/docs/latest/mllib-feature-extraction.html ）。
- 规模控制：百万页 × 平均千词 = 十亿级 token，先按 `maxDocumentsPerWord` 截断高频词——词表维度直接决定 SVD 可行性 ⚠️。

## 6.2 TF-IDF 与向量空间

- tf（词频，书用 log 抑制）、idf=ln(N/n_w)（逆文档频率压常识词）、cosine 相似度归一化——三件套构成"向量空间模型"（VSM）⚠️✅（tf-idf 文档节 ml-features.html#tf-idf）。
- 🔧 本机类比（非 Spark）：DuckDB 对 3 文档×8 词次小语料跑 SQL 版 TF-IDF（tf 按文档内 max 归一 + idf=ln(N/n+1)），实测：doc1 {spark 0.5108, data 0.2554}、doc2 {spark 0.5108, graph 0.2877}、doc3 {data 0.5108}——"高频词被 idf 压低、独有词权重上浮"的教科书曲线真实再现。Spark 侧 `HashingTF/IDF` 内建（✅ 同上 URL），语义同构。
- 稀疏矩阵表示：MLlib `RowMatrix[Vector]`（坐标矩阵，行=文档）；转置以做词×文档需 `blockMatrix` 昂贵操作——书中明确"一次转置靠重算列"⚠️。

## 6.3 LSA = 截断 SVD

- 原理：A ≈ U Σ Vᵀ，取前 k 个奇异值（k=100~500）；文档在"k 维语义空间"的坐标 = VΣ^(1/2)；同义词/多义词通过**低秩投影**拉近/摊平（LSA 论文：Deese 1960s 语义空间；Landauer & Dumais 1997 ⚠️ 标题+期刊+年份，未过 Crossref）。
- 计算：MLlib `RowMatrix.computeSVD(k, oversampling=10, seed)` 走 **Lanczos 迭代**（随机投影加速）；约束：k ≪ min(m,n)、奇异值向量放 driver 内存——"高瘦矩阵可以，宽矩阵免谈"⚠️✅（https://spark.apache.org/docs/latest/mllib-dimensionality-reduction.html ）。
- 相似度检索：query 文档向量 × 全库做 cosine top-K——书中用 `rowMatrix.multiply(V)` 投影后暴力点积；分布式 ANN 是 2019 后话（见演进）⚠️。
- 2e 对比 1e 的更新：改用 DataFrame 特征管道叙述 + 强调 ML 管道化趋势 ⚠️。

## 6.4 案例评估与坑

- 语义抽查法（无标注时的主流评估）：输入"apple"看邻居是否含 fruit/ios——书的定性评估清单 ⚠️。
- 坑①：词表截断阈值决定矩阵稀疏度，minFreq 太小 → 长尾词噪声把小奇异值污染。
- 坑②：driver 内存——`computeSVD` 返回的 V 是 DenseMatrix，k=500 时 ~4MB/千词表尚可，词表再大直接 OOM ⚠️。
- 坑③：XML dump 版本漂移：不同月份快照页数/标题不同，结果不可跨时间复现——书中提醒固化快照 ⚠️。

## 逐节精读扩展（重构笔记）

1. **multistream dump 的物理结构**（本章工程第一课 ⚠️✅ 维基官方文档线 https://dumps.wikimedia.org/backup-index.html 未单验 ⚠️）：
   - 文件=多个独立 bz2 流拼接，每流自带 magic header——**流边界可在任意处起解**；
   - 书中先扫一遍定位流边界偏移、再按边界造 RDD 分区（`newAPIHadoopFile` 思路的 raw 实现）；
   - 与 [10 章](10-基因数据分析.md) BGZF 块切分同族："**格式感知分片**"是本书最被低估的通用技能。
2. **词表裁剪公式**（书给的参数语义 ⚠️）：
   - `minFrequency`：全库出现次数下限（滤 OCR 噪声/罕见专名）；
   - `maxDocumentsPerWord`：跨文档数上限（滤 the/be 级停用炸弹）；
   - 参数直接决定矩阵形状 → 决定 SVD 可行域（k≪维度）——先想矩阵再调参。
3. **LSA 的几何直觉**（Landauer-Dumais 论域 ⚠️）：词与文档共现在同一"概念子空间"→低秩把"多义词各义项"摊到不同奇异方向→**用同一空间距离近似语义距离**；失败模式：反义同框（hot/cold 高相似）——书的诚实注脚。
4. **Lanczos 流程压缩**（✅ mllib-dimensionality-reduction.html 已验 200）：随机 Ω(n×(k+p)) → AΩ 幂迭代 p 次 → QR → 小规模 SVD → 收奇异对；`computeSVD` 参数 k、oversampling p（默认 10）、maxIterations、seed——每个参数含义在 6.3 的约束下都有存在理由 ⚠️。
5. **查询交互设计**（书的 demo 线 ⚠️）：输入标题→取该文档 k 维向量→全库 cosine→Top10 列表；"标题不在库"走词袋合成查询向量；书给样例对（"apple"→fruit/tech 混邻）人肉评审。
6. **转置问题的处理**：LSA 检索侧需要"词→文档"时不转置矩阵，而是**反向再算一遍**（词中心化的第二遍 RowMatrix）——driver 内存/宽矩阵禁忌的绕行方案 ⚠️。
7. **🔧 TF-IDF 数字细读（非 Spark）**：D6 中 'spark' 在 doc1/doc2 同权重 0.5108（各为其文档最高频），'data' 因跨两文档被压至 0.5108→doc3 的 0.2554；idf=ln(N/n)+1 平滑防零——手算一遍即可内化"tf 饱和+idf 惩罚"两股力的方向。
8. **评估的无标尺困境**：没有 ground truth 时书中采用"邻居合理性+下游任务（检索命中）"双轨——这正是后来 word-embedding 评测学（analogy 测试集）要解决的问题 ⚠️。

## 本章自问自答

- **Q1：LSA 与 LDA 什么关系？** A：SVD 低秩 vs 贝叶斯混合模型；LDA 可视为"可解释随机版的低秩分解"，书仅注不展开 ⚠️。
- **Q2：为什么不用 `spark.ml` TF-IDF 管道重写本章？** A：本章核心是 **SVD 与 RowMatrix**，管道只解决特征构造一半；2e 已用 DF 叙述特征侧 ⚠️。
- **Q3：k 取多少？** A：任务驱动：检索 100~500；降噪可视化 2~50；书用 k 递增观察邻居质量拐点 ⚠️。
- **Q4：多语言/中文怎么改？** A：换分词器（ICU/jieba）+ 停用表；矩阵语义不变——工程改动集中在 6.1 管线 ⚠️。
- **Q5：SVD 结果为何每次略不同？** A：Lanczos 依赖随机 Ω（seed 固定则稳定）；数值噪声使小奇异值方向漂移——取前 k 稳、尾部勿解读 ⚠️。
- **Q6：本章方法今天还活在哪？** A：BM25 的统计稀疏检索仍在一线（RAG 混合召回），SVD 语义投影被 embedding 替代 ⚠️。

## 本章金句与误读提醒

1. 金句（书意转述 ⚠️）："SVD 不是在做压缩，是在给语义找坐标系。"
2. 误读一：认为 LSA 懂"含义"——它只懂共现分布；反义同框与多义漂移是原理级缺陷，不是调参问题 ⚠️。
3. 误读二：把词表规模当质量——词表越大矩阵越稀，小奇异值全是噪声；裁剪即建模 ⚠️。
4. 误读三：忽视 dump 快照日期——结果不可跨月复现不是 bug，是数据源属性；版本化输入是唯一解 ⚠️。
5. 一个可带走的原则：任何"维度 k"的选择都是对"你相信几个主题"的公开表态，写进文档 ⚠️。

## 核心概念速览（中英对照）

1. **向量空间模型** — vector space model：文档=词频向量，相似度=cosine。
2. **TF-IDF** — term frequency–inverse document frequency：加权突出区分性词。
3. **停用词** — stopwords：高频无语义词表，入矩阵前剔除。
4. **词干化** — stemming：复数/时态归一（Porter 算法）。
5. **SVD** — singular value decomposition：A=UΣVᵀ 低秩近似。
6. **LSA** — latent semantic analysis：截断 SVD 后的语义空间检索。
7. **奇异值** — singular values：分量重要性谱，截断即降噪。
8. **Lanczos 算法** — Lanczos iteration：稀疏矩阵顶部奇异对的迭代近似。
9. **oversampling** — oversampling：Lanczos 随机子空间冗余参数，稳收敛。
10. **RowMatrix** — row matrix：MLlib 分布式行主序稀疏矩阵。
11. **minDF/maxDF** — document frequency 阈值：词表裁剪旋钮。
12. **语义邻居** — semantic neighbors：低秩空间中近邻词/文档。

## 最新演进与工业实践

1. **embedding 革命**：LSA → word2vec(2013)/GloVe → BERT 系（2018+）→ LLM 句向量；本章"手工统计语义"教学价值保留，生产检索已换代 ⚠️。
2. **MLlib 现状**：`RowMatrix.computeSVD`（Lanczos/ARPACK）仍在维护 ✅ mllib-dimensionality-reduction.html；但文本管道官方推荐 `spark.ml` 的 `Tokenizer→StopWordsRemover→HashingTF→IDF` 链 ✅ ml-features.html#tf-idf（HashingTF 避免词表收集作业）。
3. **向量检索工业栈**：top-K 相似度从"广播暴力点积"→ ANN 库（Faiss、hnswlib）/向量数据库：盘上专著 [../Vector_Databases/00-总览与阅读地图.md](../Vector_Databases/00-总览与阅读地图.md)（在盘 ✅）。
4. **RAG 语境**：本章是"检索增强生成"里 BM25 的统计学前辈；现代混合检索=TF-IDF/BM25（稀疏）+ embedding（稠密）双路融合 ⚠️。
5. **数据快照**：维基 dump 现为 zstd 多流格式，老 bz2 脚本需改 `--zstd`；`dumps.wikimedia.org` 仍活 ✅（README 引用的 URL 模式不变，快照名随月滚动 ⚠️）。
6. **分布式 SVD 替代**：tqSVD/randomized SVD（sklearn 移植、rapids-cuml）提供更稳的近似选项；Spark 内无新增大矩阵分解 API（QR 除外）⚠️。
