# 09 · 基于蒙特卡罗模拟的金融风险评估（Monte Carlo Simulation / Risk）

> 《Advanced Analytics with Spark, 2e》第 9 章精读重构 ｜ 总览见 [00-总览与阅读地图.md](00-总览与阅读地图.md) ｜ ✅ / ⚠️ / 🔧（DuckDB 1.5.5 类比，非 Spark 行为）

## 章定位

可扩展**模拟**案例（非监督/非预测，而是"并行随机试验"）：对约 20 只股票组合做多元正态收益抽样，计算 **VaR（在险价值）**。RDD 线性代数（`DistributedML`/`MultivariateSummaryStatistics`/`Matrices`+`LinearAlgebra.chol`）在本章集中展示——"driver 端小矩阵 + executor 端大样本"的混合架构 ⚠️。代码目录 `ch09-risk` ✅（仓库 README 注明本章数据下载脚本已失效，样本以生成方式获取 ⚠️✅）。

## 9.1 问题与数学骨架

- 组合价值 V=Σᵢ wᵢPᵢ(T)；日收益假设联合正态：r ~ N(μ, Σ)；VaR_α = −quantile_α(ΔV)（α=5%/1%）⚠️。
- 抽样核心：**Cholesky 分解** Σ=LLᵀ → 对 z~N(0,I) 取 Lz+μ 得相关正态样本；每分区独立种子防重复流（`sc.parallelize(indices).mapPartitions(...)` 内建局部 Random(seed)）⚠️✅（线性代数指南 https://spark.apache.org/docs/latest/ml-linalg-guide.html ）。
- 模拟量设计：十万级路径即可稳定 5% 分位——"够用的并行"是本章观点；书中对比 1e 用 6.4M 路径、单机 Excel 时代不可行 ⚠️。

## 9.2 Spark 侧实现要点

1. 协方差/均值估计：`MultivariateSummaryStatistics`（MLlib statistics）一遍算 Σᵢxᵢxᵢᵀ 的分布式累加 ⚠️✅（mllib-statistics 口径 https://spark.apache.org/docs/latest/mllib-statistics.html ）。
2. 分解在 **driver**：k×k（k=股票数）矩阵进 `LinearAlgebra.chol`——executor 只产样本，避免迭代线性代数上分布式的伪需求 ⚠️。
3. 分位数收口：`rdd.stats()` 或 `approxQuantile(0.05)`——GK 摘要换取单遍流式 ✅ https://spark.apache.org/docs/latest/api/python/reference/pyspark.sql/api/pyspark.sql.DataFrame.approxQuantile.html 。
4. 路径相关扩展（书中讨论）：几何布朗运动参数化、随机种子管理、伪随机数质量（`java.util.Random` vs 并行 RNG）⚠️。
5. 反模式警示（本章名场面）⚠️：用累加器求和→不可靠（见 [02-用Scala和Spark进行数据分析.md](02-用Scala和Spark进行数据分析.md) §2.4）；正确写法是 `fold/reduce`。

## 9.3 🔧 分位数语义类比实测（非 Spark）

- DuckDB 1.5.5 在 1..1000 精确数集：`quantile_cont(v,[0.5,0.95])` = **[500.5, 950.05]**（线性插值=连续分位数）、`quantile_disc` = **[500.0, 950.0]**（取实际值=离散分位数）。
- 对应关系（⚠️ 类比声明）：Spark `approxQuantile`（GK 摘要，有 rankError 保证）≈ cont 与 disc 之间的近似带；`percentile_approx` SQL 函数同理；VaR 报告里"cont vs disc"的差异在 1% 尾部会放大——本章演示的正是"分位数定义必须先于数字"这条风控纪律。

## 9.4 金融与计算的交汇讨论

- 正态假设的已知罪：肥尾（leptokurtosis）→ 书中给 t 分布/经验 Bootstrap 两条出路 ⚠️；2008 后工业界对 VaR 转向 ES（Expected Shortfall，FRTB 监管口径）⚠️。
- 可复现性：种子、并行归约序、浮点求和非结合——审计场景要求固定分区数与 merge 顺序（书中实践：先小样本对单机实现）⚠️。
- 计算/沟通成本：模拟参数表（路径数×组合数×种子）作为模型文档一部分 ⚠️。

## 逐节精读扩展（重构笔记）

1. **数据形态**：CSV `date, 20 列股票日收盘` → 收益率 r_t=(P_t−P_{t−1})/P_{t−1}；书用 ~2000 交易日估 μ（20 维向量）与 Σ（20×20）——**估计在历史窗、模拟在未来窗**的双窗设定 ⚠️。
2. **为什么 Cholesky 而不是特征分解**：Σ 正定（或近正定加抖动 λI）、L 下三角使采样 O(k²) 且实现唯一；`LinearAlgebra.chol` 在 driver 一步完成——k=20 时分布式是伪需求（书反复强调"别把小矩阵分布式化"）⚠️✅ ml-linalg-guide.html（200 已验）。
3. **并行采样的正确姿势**（本章最容易写错处 ⚠️）：
   - `sc.parallelize(0 until nSim, parts)` → `mapPartitions` 内 `new Random(seed + index)`；
   - 每分区生成 `pathLength` 步累计到 T 的组合损益；
   - 严禁在闭包里共享同一 `Random` 实例（跨分区复制同一流→伪独立）——书中专段警告。
4. **VaR 收口两条路** ⚠️：`rdd.stats().getNth(0.05)`（排序全量、driver 内存 O(n)）vs `approxQuantile`（GK 单遍流式、误差 εR）；模拟样本十万级时两法几乎重合，百万级必须后者——🔧 D4 演示 cont/disc 之差在整数列 1..1000 上仅 0.05，但**定义分歧**（插值 vs 取值）要先向业务方讲清。
5. **组合与权重**：等权 vs 市值权重的 VaR 差一个数量级；书附"每 100 美元名义额"标准化报告口径——**报告口径先于数字** ⚠️。
6. **模型风险清单**（书的自我批判 ⚠️）：正态肥尾低估、Σ 非平稳（危机期相关性→1）、波动聚集（GARCH 一族未讲）、路径依赖产品需多因子扩散——"20 只股票日频 VaR"是教学玩具而非风控产品。
7. **结果解读**：5% VaR=单日最坏 5% 分位的亏损下界；书展示 1%/5%/10% 三档 + 与等权指数对照，讨论"相关性抬升→组合 VaR 高于个股 VaR 和的假象"（实际相反：分散化压缩尾部）⚠️。
8. **工程账本**（书中数字量级 ⚠️）：10 万路径×1 天 vs 1 万路径×10 天——总抽样量同级但语义不同；并行度=分区数×核数；driver 只收组合损益标量——"大模拟、小收口"的架构模板 ⚠️。

## 本章自问自答

- **Q1：为什么模拟章反而最简单？** A：计算正交（路径间无依赖）——Spark 上最像"纯并行函数调用"的负载，适合当回归测试 ⚠️。
- **Q2：随机数质量要看吗？** A：要。java.util.Random 流间独立性够用；学术级验证走 philox/PCG（演进 5）⚠️。
- **Q3：VaR 和 ES 用同一套样本能一起算吗？** A：能：VaR 取分位后对更尾部样本再取均值即 ES——书留作练习（口径 ⚠️）。
- **Q4：为什么不用 Copula？** A：超出教学半径；书用多元正态=线性相关单点假设，其余留给"模型风险"讨论 ⚠️。
- **Q5：本章代码在 Spark 4 上还跑吗？** A：RDD+MLlib `DistributedML` 部分 API 已挪窝；核心数学（手写 cholesky+Random）与引擎无关，迁移成本主要是 import ⚠️。
- **Q6：GPU 提速值得吗？** A：路径 >10⁷ 时值得（cuDF/cuPy 批量采样）；书量级单机 CPU 即秒级——诚实条款 ⚠️。

## 书中写法 ↔ 现代写法速查（迁移表）

| 书中（2.x RDD） | 现代（3.5/4.x） | 状态 |
|---|---|---|
| `MultivariateSummaryStatistics` | DF `corr()` + summarizer / pandas 协方差 | 组合替代 ⚠️ |
| `LinearAlgebra.chol`（driver） | `ml.linalg` 同语义 | 稳定 ✅ ml-linalg-guide（已验 200） |
| `DistributedML` 小矩阵乘 | 广播矩阵 + DF 表达式 | 迁移 ⚠️ |
| `rdd.stats().getNth(0.05)` | `df.approxQuantile(...)` | 推荐路线 ✅（已验 200） |
| mapPartitions + java Random | numpy Generator / `mapInPandas` 批量采样 | 换代 ✅ |
| 单机脚本收口报告 | pandas API + MLflow 记录 seed/参数 | 平台化 ⚠️ |

**数学骨架默写卡**：①收盘价→日收益；②历史窗估 μ,Σ；③Σ=LLᵀ；④每分区 z~N(0,I)、r=Lz+μ；⑤路径累乘/累加到 T；⑥组合损益分布；⑦α 分位=VaR；⑧尾部再均值=ES——八步中只有④需要并行，其余全在 driver 小尺寸完成 ⚠️。

**报告口径三要素**（书强调 ⚠️）：名义额基准（如每 100 美元持仓）、持有期（日）、置信度（1/5/10%）必须与数字同印；缺任一要素的 VaR 无审计意义。

**模型风险练习三题**：a) 收益换 t 分布看尾部放大系数；b) Σ 做 Ledoit-Wolf 收缩看 VaR 稳定性；c) 危机子窗 vs 全窗对比——把"模型风险"从口号变成可动手的数 ⚠️。

## 本章金句与误读提醒

1. 金句（书意转述 ⚠️）："蒙特卡罗的并行度买的是方差缩减，不是新信息。"
2. 误读一：路径越多越准——收敛按 O(1/√N) 走，十万级后的提升以"再等一小时"换"第三位小数"；报告精度与抽样预算要匹配 ⚠️。
3. 误读二：共享 Random 实例无妨——同一流被复制进多个分区，相关性伪装成独立性，尾部分位失真；这是本章唯一"必犯则必错"的坑 ⚠️。
4. 误读三：VaR 数字=风险本身——数字只承载模型内的风险；正态/静态 Σ 之外的一切都被它沉默掉 ⚠️。
5. 一个可带走的原则：分位数定义（cont/disc/approx）先于分位数数值——🔧 D4 的 0.05 差距在 1% 尾部会放大成不可比的两个数 ⚠️。

## 核心概念速览（中英对照）

1. **蒙特卡罗模拟** — Monte Carlo simulation：随机采样近似分布/积分。
2. **VaR** — value at risk：给定置信度的最坏损失分位。
3. **ES/CVaR** — expected shortfall：尾部条件均值，VaR 的后继监管度量 ⚠️。
4. **协方差矩阵** — covariance matrix：Σ，相关结构的载体。
5. **Cholesky 分解** — Cholesky decomposition：Σ=LLᵀ，正定矩阵开"相关根"。
6. **多元正态** — multivariate normal：Lz+μ 构造相关样本。
7. **几何布朗运动** — GBM：股价路径连续时间模型。
8. **分位数估计** — quantile estimation：cont/disc/approx 三族（🔧 已类比）。
9. **GK 摘要** — Greenwald-Khanna sketch：单遍 ε-近似分位。
10. **分区种子** — per-partition seed：并行 RNG 不重不漏的关键。
11. **肥尾** — heavy tails：正态低估尾部风险的现实修正。
12. **MultivariateSummaryStatistics** — MLlib 分布式矩/协方差估计器。
