## 核心概念速览（中英对照）

- **执行环境** — execution environment：`StreamExecutionEnvironment`，程序与运行时之间的句柄；本地/远程由同一份代码决定。
- **本地运行时** — local runtime / MiniCluster：JVM 内起一个迷你集群，`main` 方法直接跑作业，用于开发与调试。
- **Maven archetype** — 工程骨架：`flink-scala_2.11` / `flink-java` 等 archetype 生成的标准目录与依赖。
- **provided 作用域** — provided scope：`flink-streaming-java`/`-scala` 标为 `provided`，因为集群发行版已带这些 jar。
- **胖 jar / shade** — fat jar / maven-shade-plugin：把用户依赖打进提交 jar；过度打包会与集群 jar 冲突。
- **类加载顺序** — classloader resolve order：`child-first`（默认，用户 jar 优先）与 `parent-first`，是依赖冲突的第一开关（09 章）。
- **Web UI** — 作业可视化：本地运行默认 `http://localhost:8081`，展示 dataflow 图、反压、检查点、指标。
- **远程执行** — remote execution：把 jar 提交到集群（`bin/flink run`）或在 IDE 里指向远端 REST 地址 ⚠️（书中提到 IDE 内远程调试流程）。
- **日志与调试输出** — logging：Flink 用 slf4j + log4j；`stdout` 走 `.out` 文件，`print()`  sink 与日志不是一回事。

## 核心精讲

### 4.1 依赖骨架 🔧

> 🔧 Maven（`pom.xml` 关键片段，教学示意，不参与构建；版本号以你实际使用的 Flink 发行版为准）。
> 原书时代为 Flink 1.7 + Scala 2.11/2.12；现代版本至少需要 Scala 2.12/2.13，Java 8 → 11/17 ⚠️。

```xml
<properties>
  <flink.version>1.7.2</flink.version>   <!-- ⚠️ 仅为对齐本书；新版本请换号 -->
  <scala.binary.version>2.12</scala.binary.version>
</properties>

<dependencies>
  <!-- 核心：集群已提供，必须 provided -->
  <dependency>
    <groupId>org.apache.flink</groupId>
    <artifactId>flink-streaming-scala_${scala.binary.version}</artifactId>
    <version>${flink.version}</version>
    <scope>provided</scope>
  </dependency>
  <!-- 连接器：集群未必有，需要打进 jar 或由集群装载 -->
  <dependency>
    <groupId>org.apache.flink</groupId>
    <artifactId>flink-connector-kafka_${scala.binary.version}</artifactId>
    <version>${flink.version}</version>
  </dependency>
  <!-- 本地跑 UI（仅开发期，别进生产 jar）⚠️ 现代版本用 flink-runtime-web + minicluster 方式已变 -->
</dependencies>
```

**为什么 provided 是本章第一个真知识点**：集群 `lib/` 里已有 `flink-dist`，
用户 jar 再打一份会出现「同一类两个类加载器」的 `ClassCastException` / 序列化器不一致，
症状常常是「本地跑得好、集群上报类型错误」（09 章类加载一节对应）。

### 4.2 工程骨架与示例导入 🔧

```bash
# 🔧 生成骨架（archetype 名称随版本变化；书中给的是 flink-quickstart 一类）
mvn archetype:generate \
  -DarchetypeGroupId=org.apache.flink \
  -DarchetypeArtifactId=flink-scala_2.12 \
  -DarchetypeVersion=1.7.2
# 产物：src/main/scala/.../DataSetJob.scala（骨架可能给的是批作业示例，改成流即可）
```

生成的 `main` 结构（Scala）：

```scala
// 🔧 教学示意
object StreamingJob {
  def main(args: Array[String]): Unit = {
    val env = StreamExecutionEnvironment.getExecutionEnvironment   // IDE 里 = MiniCluster
    env.enableCheckpointing(10000)                                 // 本地也能练检查点（03/12 章）
    env.setStreamTimeCharacteristic(TimeCharacteristic.EventTime)
    env.getConfig.setLogTimestampsDisplayFormat("yyyy-MM-dd HH:mm:ss.SSS")
    // ... 构图
    env.execute("Local Debug Job")
  }
}
```

`sbt` 路线（原书亦提到 Scala 用户可用 sbt）：`libraryDependencies` 同样把核心标 `% "provided"` ⚠️ 具体任务名未核实。

### 4.3 在 IDE 里运行与调试：三件必做

1. **并行度先设 1**：`env.setParallelism(1)`。多子任务下断点会在多个线程同时命中，日志交错，几乎无法读。
2. **断点打在函数内部**：`map`/`process`/`onTimer` 的方法体才是执行期代码；写在 `main` 里的断点只在构图阶段命中一次。
   这是新手最常见的困惑来源——「我在 main 里打的断点为什么不触发」。
3. **注意 `Serializable`**：算子类里携带的字段必须可序列化（Java 的 `Serializable`、Scala 的闭包捕获）。
   闭包捕获了一个不可序列化的外部对象，会在**提交时**报 `InvalidProgramException: Not serializable`，
   而不是运行时；解决手段是把配置读成局部变量或放进 `ParameterTool`（05 章函数一节）。

### 4.4 打包与提交

🔧 提交前检查清单（本目录实操口径）：

```
□ mvn clean package 产出的是 shaded jar（含你的类与第三方依赖，不含 flink-dist）
□ 集群版本与编译版本一致（flink --version）
□ 连接器 jar 是打进用户包，还是放 lib/ 由集群提供（两种都可以，别两边都放）
□ 主类清单：bin/flink run -c com.example.MyJob job.jar arg1
□ 需要检查点目录：-D state.checkpoints.dir=file:///tmp/ckpt  （或写在 flink-conf.yaml）
□ 分离模式提交：bin/flink run -d ... （否则终端断开可能取消作业 ⚠️ 行为依版本而定）
```

## 版本与兼容性

- 原书按 **Flink 1.7 + JDK 8 + Scala 2.11/2.12** 展开；今天（2026）Flink 主线要求 JDK 11/17，Scala 2.12/2.13 ⚠️
  具体以官方「Getting Started」页为准。用 JDK 17 跑旧版本 Flink 常见 `IllegalAccessException`（反射被模块系统拦住）。
- archetype 名称与坐标多次变化（`flink-quickstart` / `flink-java` / `flink-scala_2.12`）⚠️ 以对应版本文档为权威。
- 本地起 Web UI 的做法（`flink-runtime-web` 依赖）在新版本中需要额外的 `WebMonitorUtils`/MiniCluster 配置差异 ⚠️。
- Flink 2.x 移除了 Scala API 的旧入口与 DataSet API ⚠️（本书 Scala 示例在 2.x 上多数需要改写为 DataStream Java 或 Table）。
- 现代工程更常见的是「用 Flink 官方发行版 + 只带连接器的 jar」，与本书「把 connector 打进 fat jar」的做法并存，注意别重复。

## 常见误区

| 误区 | 事实 |
| --- | --- |
| 把 `flink-dist`/`flink-streaming-java` 打进 fat jar | 与集群 lib 冲突；核心依赖必须 `provided`（连接器看部署方式决定） |
| 「本地能跑 = 集群能跑」 | 本地是单 JVM、无网络 shuffle、类加载层次不同；并行度、序列化、连接器版本问题只在集群暴露 |
| 断点打在 `main` 里等运行时命中 | `main` 只构图；运行时逻辑在算子回调里（05 章函数类） |
| 闭包捕获 `StreamExecutionEnvironment` | 环境对象不可序列化，提交即失败；只把需要的值传进函数 |
| 用 `print()` 当生产输出 | `print` 是 sink，写 TaskManager 的 `.out`，量大时拖慢作业；生产用日志或真 sink（08 章） |
| 忽略 `parallelism` 默认值 | 本地默认 = 到 CPU/配置的并行度，键分布随机性会让本地结果「看起来正常」而集群上倾斜（02/10 章） |
| 改 IDE 的 run configuration 内存当成集群调优 | 集群内存由 `taskmanager.memory.*` 决定（09 章），与 IDE 的 `-Xmx` 无关 |
