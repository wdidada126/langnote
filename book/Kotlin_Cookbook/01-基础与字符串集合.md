## 核心概念速览（中英对照）

- **默认参数** — default arguments：编译期缺省值替代重载/Builder（见 R1）。
- **只读接口** — read-only collection interface：`List<T>` 是**接口层只读**，非不可变（R3/R4）。
- **解构声明** — destructuring declaration：靠 `componentN()` 约定展开（R8）。
- **惰性序列** — sequence：`Sequence<T>` 逐元素拉取，与 `Iterable` 的逐操作物化对照（R7）。
- **穷尽 when** — exhaustive when：subject 形式对 sealed/枚举可免 `else`（R9）。
- **平台类型** — platform type：Java 集合返回值的空性在边界处丢失，详见 [06 章](06-工程与互操作食谱.md)平台类型段（原规划 05 章「空安全与异常Result」未单列建档 ⚠️欠账）。

## R1 · "怎么把 Java Builder 换成默认参数？"
`[✅ | ⚠️ 归属推定：基础章参数惯用法 | 🔧]`

**Problem.** 从 Java 迁移，每个类配一个 80 行 Builder，Kotlin 里还要不要？

**Solution.** 🔧

```kotlin
// Java 侧：new HttpRequest.Builder(url).timeout(30).retries(3).build()
data class HttpRequest(
    val url: String,
    val timeoutSeconds: Int = 30,
    val retries: Int = 3,
    val headers: Map<String, String> = emptyMap(),
)
val r1 = HttpRequest("https://example.com")                      // 只给必填
val r2 = HttpRequest("https://example.com", retries = 5)         // 命名参数跳位
```

```kotlin
// 必填多到难记时，仍用命名参数 + 首位无默认值的构造函数
fun post(url: String, headers: Map<String, String> = emptyMap(), body: String = "") =
    HttpRequest(url).copy(headers = headers)                     // copy 见 R2
```

**Discussion.** 默认参数在**调用侧**展开（无 `@JvmOverloads` 时字节码仍只有一个全参构造，
Java 调用方看不到缺省——互操作补救在 [06 章](06-工程与互操作食谱.md) R4）。规范侧
Effective Kotlin 会强调"默认值必须是廉价表达式"（函数调用做默认值按调用点求值 ✅）。
Builder 没有被消灭：跨模块演化频繁、参数 >5 且 Java 消费方存在时，`toBuilder()`/`copy()` 
组合仍是折中 ⚠️ 工程判断。

## R2 · "copy() 和再构造一次有什么区别？"
`[✅ | ⚠️ | 🔧]`

**Problem.** data class 改一个字段，直接 `copy` 就行，但 `copy` 会不会绕过校验？

**Solution.** 🔧

```kotlin
data class User(val name: String, val email: String) {
    init { require('@' in email) { "bad email: $email" } }       // 校验放 init
}
val u = User("Ken", "ken@example.com")
val v = u.copy(email = "ken@bad")      // 只走构造器？——不会：copy 调用全参构造，init 重跑
```

```kotlin
data class Cfg(val level: Int = 1) {
    val doubled: Int get() = level * 2                            // 非构造参数
    fun bump() = copy(level = level + 1)                          // copy 后 doubled 自动新值
}
```

**Discussion.** `copy()` 是编译器生成的**全参委托构造调用**，所以 `init` 块与属性校验会重新执行 ✅；
它不会复制"构造外赋值的 var"——那些不属于构造参数。私有构造器的 data class 能否被外部 `copy`：
`copy` 与构造器同可见性 ✅，这是 R（02 章）"data class 作不可变值"的机关。

## R3 · "listOf 出来的列表到底能不能改？"
`[✅ | ⚠️ | 🔧]`

**Problem.** `val list = listOf(1,2,3)`，`list` 是 `List<Int>`——`val` 和 `List` 谁负责只读？

**Solution.** 🔧

```kotlin
val a: List<Int> = listOf(1, 2, 3)          // 接口只读：没有 add 方法可叫
val b: MutableList<Int> = a as? ArrayList<Int> ?: arrayListOf()
b.add(4)                                     // 运行时 a/b 是同一个 ArrayList——a 也变 4 元素
val fixed: List<Int> = listOf(1, 2, 3).map { it }  // map 返回新 ArrayList，仍非不可变对象
```

```kotlin
fun readOnlyView(src: MutableList<Int>): List<Int> = src          // 类型上只读，实现上共享
```

**Discussion.** Kotlin 标准库没有提供真正不可变的 `List` 工厂；`listOf` 对空/单元素走
`EmptyList`/`SingletonList`（改会抛 `UnsupportedOperationException`），多元素就是 `ArrayList` ✅。
所以"只读"是**编译期接口约束 + 防御性拷贝问题**，不是运行期保证。规范条目（"暴露集合返回
只读类型、入参拷贝"）从 Effective Kotlin；这里的即查即用结论是：**跨边界传集合请 `toList()` 拷贝** 🔧。

## R4 · "为什么 is MutableList 检查不拦住 Java 传进来的可变列表？"
`[✅ | ⚠️ | 🔧]`

**Problem.** 想用 `if (list is MutableList)` 判断能否安全 add，结果对 Java 的 `Collections.emptyList()` 也为真？

**Solution.** 🔧

```kotlin
fun describe(list: List<String>) = when {
    list is MutableList<String> && list !== readOnlyCopy(list) -> "可能可变（不可靠！）"
    else -> "按只读处理"
}
fun readOnlyCopy(l: List<String>) = ArrayList(l) as List<String>
```

```kotlin
val javaList: MutableList<String> = java.util.Collections.unmodifiableList(
    java.util.ArrayList(listOf("a"))
)   // 类型上 MutableList，add 时运行期 UnsupportedOperationException
```

**Discussion.** JVM 层面 `List<T>` 与 `MutableList<T>` **都映射到 `java.util.List`**，擦除后
`is` 检查根本区分不了 ✅——`is MutableList` 事实上等价"是不是 java.util.List"。Kotlin 自己的
只读包装（非 ArrayList 实现）会让 `is MutableList` 为假，但这只是实现巧合不是契约 🔧。
结论：可变性判定没有运行期语法，只能靠约定 + 拷贝。这是 05 章平台类型坑的近亲。

## R5 · "split 和正则拆分怎么选？Java split 的尾部空串坑还在吗？"
`[✅ | ⚠️ | 🔧]`

**Problem.** Java `String.split(",")` 丢尾部空串、要转义点号，Kotlin 呢？

**Solution.** 🔧

```kotlin
"a,b,,".split(",")                 // ["a","b","",""] —— Kotlin 保留尾部空串，与 Java 行为不同 ✅
"1.2.3".split(".")                 // ["1","2","3"]：Char 重载按字面量，无正则转义问题
"1.2.3".split(Regex("\\."))        // 显式正则版本
"a1 b22".split(Regex("\\d+"))      // ["a"," ","b22" 前的 "b"] → ["a", " ", "b"]... 逐次实测为准 🔧
```

```kotlin
lineSequence().map { it.trim() }.filter(String::isNotEmpty).toList()
```

**Discussion.** `split(vararg delimiters: Char)` 与 `split(regex)` 是两组不同 API ✅；
"Kotlin split 不丢尾部空串"是与 Java 迁移最相关的一处行为差异 ✅（1.4 起的规整，Java 互调
`String.split` 仍有旧坑——平台类型视角见 [06 章](06-工程与互操作食谱.md)）。
`CharSequence.split` 系列另有 `ignoreCase/matchLeading/matchTrailing` 参数 ✅。

## R6 · "列表拼字符串还要 StringBuilder 循环吗？"
`[✅ | ⚠️ | 🔧]`

**Problem.** Java 里 `StringJoiner`/`StringBuilder` 的活，Kotlin 一行？

**Solution.** 🔧

```kotlin
val users = listOf(User("Ken", "k@e.com"), User("Ada", "a@e.com"))
users.joinToString(prefix = "[", postfix = "]", separator = ", ") { it.name }
// "[Ken, Ada]"
users.joinToString(transform = User::email)          // 函数引用作 transform
```

```kotlin
buildString {
    repeat(3) { append("ab").append('|') }            // StringBuilder DSL
    setLength(length - 1)                              // 去掉尾部分隔符
}
```

**Discussion.** `joinToString` 默认 `separator=", "、limit=100、truncated="..."` ✅——
大集合打印自动截断是很多人踩过的"为什么日志少了 200 条"答案。`buildString` 与
`buildList/buildMap/buildSet`（kotlin.text/collections DSL）同族 ✅。

## R7 · "集合链式 map/filter 和 asSequence 什么时候真的省？"
`[✅ | ⚠️ | 🔧]`

**Problem.** 老手都知道"中间集合是开销"，但 Kotlin 里 `asSequence()` 什么时候反而更慢？

**Solution.** 🔧

```kotlin
(1..1_000_000)
    .asSequence()
    .filter { it % 3 == 0 }
    .map { it * 2 }
    .take(10)                     // 短路：只消费到第 10 个命中项
    .toList()
```

```kotlin
// 对比：不用 sequence 时 filter+map 各物化一个 33 万/100 万元素的 ArrayList
(1..1_000_000).filter { it % 3 == 0 }.map { it * 2 }.take(10).toList()
```

**Discussion.** Sequence 的收益条件是**链条长且有短路/中间数据大**；小集合上 sequence 的
迭代器与 lambda 调用开销反而更高 🔧（O'Reilly 本书与 Effective Kotlin 都持"先测量再 sequence"
口径 ✅ 原则一致，仲裁：规范从 Effective）。`generateSequence`、`sequenceScope` 见函数章 [03](03-函数与Lambda食谱.md)。

## R8 · "swap 两个元素、展开对象的惯用写法？"
`[✅ | ⚠️ | 🔧]`

**Problem.** Java 需要 getter 全家桶才能"解构"，Kotlin？

**Solution.** 🔧

```kotlin
data class Point(val x: Int, val y: Int)
val (px, py) = Point(3, 4)                    // 靠 component1()/component2() ✅
var (a, b) = 1 to 2
a = b.also { b = a }                          // swap 惯用法 🔧
map.forEach { (k, v) -> println("$k=$v") }    // 解构进 lambda 参数
// 注意：解构没有 "vararg 剩余模式"（*rest 写法编译不过 ✅），想要尾部集合自行 drop(1) 🔧
```

```kotlin
class Vec2 { val x = 0; val y = 0
    operator fun component1() = x             // 非 data class 手写 componentN 即可参与解构
    operator fun component2() = y
}
```

**Discussion.** 解构是**纯语法约定**：编译期展开成 `componentN()` 调用，data class 只是帮你
生成这套约定 ✅。命名坑：属性名与解构变量名可不同步（解构拿位置语义），规范上 Effective 
Kotlin 主张"3 个以上分量别解构裸传" ⚠️ 条目号未核。

## R9 · "when 什么时候可以不写 else？"
`[✅ | ⚠️ | 🔧]`

**Problem.** 枚举/sealed 分支写全了，IDE 还提示加 `else`？

**Solution.** 🔧

```kotlin
enum class Suit { CLUBS, HEARTS, SPADES, DIAMONDS }
fun score(s: Suit) = when (s) {               // subject 形式 + 全覆盖：表达式可免 else ✅
    Suit.CLUBS, Suit.DIAMONDS -> 1
    Suit.HEARTS, Suit.SPADES -> 2
}
fun flag(b: Boolean?) = when {                // subject-less 形式：布尔条件逐条
    b == true -> "yes"
    b == false -> "no"
    else -> "unknown"                         // Boolean? 无 else 不穷尽
}
```

**Discussion.** 规则：`when` 作**表达式**必须穷尽 ✅；作语句对枚举/sealed subject 新版本缺 
`else` 会告警/报错 ✅（1.7 起，精确版本线 ⚠️）。加枚举常量后让编译器帮你找漏网分支，
是"sealed/枚举 + 无 else when"作为迷你模式匹配的核心价值——完整 sealed 策略在
[02 章](02-面向对象与data-value类选型.md) R1 与 [06 章](06-工程与互操作食谱.md)（原 05 章 R9 未单列建档 ⚠️欠账）。

## R10 · "字符串模板里 $ 和 ${} 的边界在哪？"
`[✅ | ⚠️ | 🔧]`

**Problem.** `"$user.name"` 为什么把 `.name` 打出来成了字面量？

**Solution.** 🔧

```kotlin
val user = User("Ken", "k@e.com")
println("$user.email")        // "User(name=Ken, ...).email"：$ 只吃掉标识符 ✅
println("${user.email}")      // "k@e.com"：表达式必须进 ${}
println("$${'$'}100")         // 打 $ 用 ${'$'} ✅（$$ 不是转义）
val raw = """路径 C:\temp ${'$'}{x} 原样输出"""   // raw string 反斜杠不转义、模板仍生效 ✅
```

**Discussion.** 模板发生在编译期（拼 `invokedynamic`/`StringBuilder`，实现细节 🔧）。
raw string 的缩进由**最小缩进行**决定，可配 `.trimIndent()`/`.trimMargin("|")` ✅。
迁移提醒：GString（Groovy）式嵌套引号在 Kotlin 里一律 `${}`，没有 `$()`。
