# 第 4 章 并发操作的同步

> **一句话**：等待只有两种形态——**等某个条件成立**（条件变量）和**等某个一次性结果**（future）；前者必须配谓词循环，后者可以组合成流水线。

## 核心精讲

### 4.1 条件变量的正确写法

```cpp
// 教学示意：线程安全队列（不参与构建）
template<typename T>
class threadsafe_queue {
    std::queue<T> data_queue;
    mutable std::mutex mut;
    std::condition_variable data_cond;
public:
    void push(T new_value) {
        std::lock_guard lk(mut);
        data_queue.push(std::move(new_value));
        data_cond.notify_one();
    }
    void wait_and_pop(T& value) {
        std::unique_lock lk(mut);
        data_cond.wait(lk, [this]{ return !data_queue.empty(); });  // 带谓词
        value = std::move(data_queue.front());
        data_queue.pop();
    }
};
```

三个经典陷阱：

| 陷阱 | 说明 | 对策 |
| --- | --- | --- |
| 虚假唤醒 | 没有 notify 也可能从 wait 返回 | 用带谓词的 wait，或在 while 里检查 |
| 丢失唤醒 | notify 发生在 wait 之前 | 状态必须用同一把互斥保护，检查与等待在同一个临界区内完成 |
| 惊群 | 唤醒了所有等待者却只有一个能干活 | 单元素入队时用 `notify_one` |

### 4.2 future 家族

```cpp
// 教学示意（不参与构建）
auto fut = std::async(std::launch::async, []{ return 42; });
std::promise<int> p;
auto f = p.get_future();
std::thread t([&]{ p.set_value(7); });
std::cout << f.get();
t.join();
```

要点：

- `std::async` 的默认策略是 `async|deferred`，是否开新线程由实现决定；要保证异步必须显式写 `std::launch::async`。
- `future::get()` 只能调用一次；需要多方消费请用 `shared_future`。
- 异常会先保存在 future 里，等到 `get()` 时重新抛出。这是把工作线程异常传回调用方的标准手段。

### 4.3 限时等待

| 概念 | 例子 | 说明 |
| --- | --- | --- |
| 时钟 | `steady_clock`、`system_clock` | **计时必须用 `steady_clock`**，它不受系统时间调整影响 |
| 时长 | `std::chrono::milliseconds(100)` | 单位在编译期检查 |
| 时间点 | `steady_clock::now() + 100ms` | `wait_until` 用时间点，`wait_for` 用时长 |

### 4.4 future 的组合与线程闩、线程卡

- **`when_all`**：等待一组 future 全部就绪。
- **`when_any`**：等待其中任意一个就绪，常用于「多个冗余请求谁先返回就用谁」。
- **`std::latch`**（C++20）：一次性门闩，计数器减到 0 就永远打开。
- **`std::barrier`**（C++20）：可重复使用的栅栏，支持相位完成回调。

本书 4.4.8 之后讲的是 `std::experimental::*` 版本；2026 年请直接用标准版本。

## 近年研究与工业界开源实践

- **协程与 future 的结合**：C++20 协程可以 `co_await` 一个 future，把阻塞等待变成挂起。
- **P2300 执行器提案**：未来的 `std::execution` 以 sender/receiver 为基础，future 会退居次要位置。这正是本书 4.4 中 experimental 部分的归宿。
- **超时是可靠性的关键**：工业界的故障复盘反复指出，缺少超时会导致级联故障放大；所有阻塞调用都应带时限。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「用 if 检查谓词就行」 | 必须是循环或带谓词的 wait，否则虚假唤醒会导致错误返回 |
| 2 | 「notify 之前不必持锁」 | 先解锁再 notify 是允许的微优化，但状态修改必须在锁内 |
| 3 | 「async 一定开新线程」 | 默认策略不确定，要保证异步必须显式指定 `launch::async` |
| 4 | 「future::get() 可以多次调用」 | 只能一次；多方消费请转 `shared_future` |
| 5 | 🔧 本书的 experimental 部分已过时 | C++20 已有 `std::latch`、`std::barrier`、`std::semaphore` |
| 6 | 🔧 本书未强调超时必填 | 生产代码中所有 wait 都应带时限，避免级联阻塞 |
