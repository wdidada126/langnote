# 第 2 章 线程管控

> **一句话**：`std::thread` 的核心不是「怎么起线程」，而是**归属权与生命周期**——谁负责 join、异常时怎么办、参数怎么安全传递。

## 核心精讲

### 2.1 发起线程必须在析构前决定去向

```cpp
// 教学示意：RAII 的 thread_guard（不参与构建）
class thread_guard {
    std::thread t;
public:
    explicit thread_guard(std::thread t_) : t(std::move(t_)) {}
    ~thread_guard() { if (t.joinable()) t.join(); }   // 异常路径也能 join
    thread_guard(const thread_guard&) = delete;
    thread_guard& operator=(const thread_guard&) = delete;
};
```

> 这是第 1 章 Hello World 的**正确版**。C++20 的 `jthread` 已经内置了这一行为（析构时自动 `request_stop()` + `join()`）。

**要点**：`std::thread` 析构时若仍 `joinable()`，会调用 `std::terminate()`。这是新手最常踩的崩溃来源。

### 2.2 传参的两层拷贝

```cpp
// 教学示意（不参与构建）
void f(int i, std::string const& s);
std::thread t(f, 3, "hello");       // "hello" 先被转成 std::string（可能在调用线程，
                                    // 也可能在新线程 → 悬垂风险）
```

陷阱清单：

| 陷阱 | 现象 | 修正 |
| --- | --- | --- |
| 传递 `char const*` 给 `std::string const&` 参数 | 转换时机不确定，参量的生命周期可能悬垂 | 先显式构造实参：`std::thread t(f, 3, std::string("hello"))` |
| 想要引用却拿到拷贝 | 默认按值 | 用 `std::ref(x)` |
| 传指针/引用到局部变量 | 线程里用到时可能已销毁 | 用 `shared_ptr` 或延长生命周期 |

### 2.3 归属权转移

`std::thread` 是 move-only 类型：

```cpp
std::thread t1(f);
std::thread t2 = std::move(t1);      // OK；t1 变为不可 join 的空对象
// std::thread t3 = t2;              // ❌ 编译错误：不可拷贝
```

这让 `thread` 可以被放进容器（`vector<thread>`）、作为函数返回值、在对象之间移交。

### 2.4 运行时选择线程数

```cpp
unsigned n = std::thread::hardware_concurrency();   // 可能返回 0！
```

建议：`std::max(1u, hardware_concurrency())`。注意它返回的是**逻辑核数**（含超线程），CPU 密集型任务通常不应超过物理核数。

## 近年研究与工业界开源实践

- **协作式取消成为标配**：C++20 的 `stop_token` 体系让父子任务链可以逐级请求停止；这与 Java 的中断机制、Go 的 `context.Context`、Rust 的 `CancellationToken` 是同一范式。
- **`jthread` 逐步取代裸 `thread`**：新项目建议直接用 `jthread`，避免析构终止。
- **线程池 vs 裸线程**：生产系统几乎不直接起线程（代价高、无法限流），而是用线程池 / task arena（见第 9 章、以及 folly / oneTBB 的实现）。

| 实现 | star | 说明 |
| --- | --- | --- |
| `facebook/folly` | ≈**30.5k★** | `folly::CPUThreadPoolExecutor` / `IOThreadPoolExecutor`，线程取名与 affinity 配置都比裸线程完善 |
| `uxlfoundation/oneTBB` | ≈**6.8k★** | `task_arena` 与 `task_group`，用任务而非线程表达并行 |
| `boostorg/boost` | ≈**8.6k★** | Boost.Thread 是 `<thread>` 的直系前身，`boost::thread_group` 仍有参考价值 |

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「忘了 join 只是资源泄漏」 | 会直接 **`std::terminate()` 崩溃** |
| 2 | 「detach 出去就万事大吉」 | 分离后的线程仍可能访问局部变量或静态对象，主线程退出时极易造成悬垂访问 |
| 3 | 「传引用就用 `std::ref`」 | `std::ref` 只是绕过拷贝，被引用对象的生命周期仍由你负责 |
| 4 | 「`hardware_concurrency()` 一定 > 0」 | 标准允许返回 0（实现无法判断时） |
| 5 | 🔧 本书的 `thread_guard` 需要删拷贝构造 | 本书示例代码强调了这一点，自写时别忘了同时删拷贝赋值 |
| 6 | 🔧 本书未讲 `jthread` | 本书出版时 C++20 尚未 Coverage；2026 年应直接使用 `std::jthread` |
