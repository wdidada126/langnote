## 一、本章定位

22 页走完"函数依赖 → 范式阶梯 → 分解算法 → 多值依赖"的完整链条，但保持 Teorey 的工程口径：**规范化不是目的，是概念模型落库后的"质量检查器"**——第 5 章映射给出"合法"模式，本章给出"好"模式的判据与反例（插入/删除/更新异常）。

## 二、依赖语言（地基）

- **函数依赖** — functional dependency (FD)：X→Y 意为"X 定则 Y 定"；是"属性间语义约束"的形式化。
- **平凡/非平凡、部分/传递**：术语三件套先立规矩。
- **闭包** — attribute closure X⁺：求闭包是唯一需要肌肉记忆的算法（找候选键、判超键、验依赖全用它）。
- **候选键形式化**：K 是候选键 ⇔ K⁺ = 全集 且任何真子集不满足。
- **Armstrong 公理**（自反/增广/传递）与覆盖（cover）、等价依赖集 ⚠️ 本章是否展开公理体系未证实，按"够用作判据"深度转述。

## 三、范式阶梯（每级配一种异常）

| 范式 | 判据（口语版） | 消除的异常 |
|---|---|---|
| 1NF | 列不可再分（多值属性出局） | 结构歧义 |
| 2NF | 非主属性不完全依赖候选键 | 部分依赖型更新异常 |
| 3NF | 非主属性不传递依赖候选键 | 派生值存储异常（如 DEPT→ dean，员工表存 dean） |
| BCNF | **每一**决定方都是超键 | 主属性间依赖异常（教师-科目-课本反例） |
| 4NF | 非平凡多值依赖 X↠Y 的决定方是超键 | 冗余配对（教师-科目-研究兴趣反例） |
| 5NF | 连接依赖不可再分 | 极边缘，本书点到即止 ⚠️ |

- 阶梯记忆法：每上一层，"决定方的资格"升一级（候选键→超键→禁多值）。
- **分解两性质**：无损连接（lossless-join，用共享键能拼回原表且无增广）与依赖保持（dependency preservation，检查 FD 不用跨表）。BCNF 分解必无损（交集含决定方），但可能丢依赖保持；3NF 分解两者兼得——这是本章必须会证的最小结论。

## 四、无损/有损：🔧 本机实测的直观证据

Python sqlite3 3.45.3（脚本 `D:\develops\tmp\dbwave_dmd5e\demo3.py`）：

- 关系 `r(s, c, g)`，FD 集 {s→c, c→g}，候选键 s，样本 3 行 (1,10,db),(2,11,db),(3,12,os)；
- **有损分解** (s,g)+(c,g)（共享 g，g 不是任何一侧的键）：自然连接回 **5 行 > 原 3 行**——测得 2 个增广元组（spurious tuples），正是 (1,11,db),(2,10,db) 这类"没发生过却推出来"的事实 🔧 实测；
- **无损分解** (s,c)+(c,g)（共享 c 是 r2 的候选键）：重建与原表 EXCEPT 双向比对，缺 0 增 0 🔧 实测；
- 结论落点：分解算法里"共享属性必须是某侧超键"一句话，不是形式游戏，是**假数据生成器开关**。

## 五、规范化的边界（本章的诚实部分）

- 性能反例：完全规范化=查询常需 4-6 表 JOIN；报表/数仓读侧负载会主动反规范化——本书第 7 章案例与 PDD 第 15 章是同一论证的两个高度（[../Physical_Database_Design/12-数据仓库OLAP与反范式化.md](../Physical_Database_Design/12-数据仓库OLAP与反范式化.md)）。
- 决策顺序（Teorey 立场，重构转述 ⚠️）：**先规范化到 3NF/BCNF 建立基线，再按负载画像定点反范式化并登记为"派生结构"**——反范式是物理设计预算，不是逻辑设计偷懒。
- 4NF 实务少用：多值依赖在真实需求里罕见，遇到时通常意味着建模漏了联系（回到第 2 章补桥接实体）。

## 六、本章算法清单（手到擒来级）

1. 求 X⁺；2. 求全部候选键（闭包枚举）；3. 判 BCNF（每个非平凡 FD 左部是否超键）；4. BCNF 分解循环（找违反→按左部∪右部/其余拆）；5. 3NF 合成算法（极小覆盖按左部分组+保键）⚠️ 原书是否给 3NF 合成算法未证实，按标准教材口径标注；6. 无损性检验表（chase）——第 4 步的收据。

**易错**：① 把"非主属性"当"非第一列"；② 判 2NF/3NF 时忘了多个候选键场景；③ 分解后不验依赖保持就宣布胜利；④ 用代理键"绕过"BCNF 判定（决定方仍在数据语义里）；⑤ 见到 MVD 先拆表而非先补建模。

## 补充一、闭包与候选键：一道手算到底的例题

关系 `ENROLL(sid, course_id, semester, instructor_id, room, grade)`，FD 集：
- `course_id → dept`（若另有 dept 列）；` (course_id, semester, instructor_id) → room`；`sid + (course_id, semester) → grade`；`instructor_id → dept_id`。

手算工序（对应第 6 节算法 1/2）：
1. 从组合键 {sid, course_id, semester} 出发求闭包：加 grade；有 dept 链则继续——若闭包=全集则该组合是超键；
2. 去左部冗余：逐个真子集重算闭包，都失败则它是候选键；
3. 找出全部候选键后，"非主属性"才有定义，2NF/3NF 判定才成立（易错①的根源）；
4. 判 BCNF：扫每条 FD 左部是否超键——`instructor_id → dept_id` 左部不是超键 → 违反，拆 `INSTRUCTOR(instructor_id, dept_id)`；
5. 每次拆分后**重新求候选键**（被拆掉的列可能在余表成为键）。

## 补充二、反例博物馆（每范式的"标准翻车现场"）

| 范式 | 经典反例 | 异常表现 |
|---|---|---|
| 1NF 违规 | 学生表存 `phone_list='138..;139..'` | 无法检索单号码、长度失控 |
| 2NF 违规 | PK(student, course)，非主 `course_avg` 只依赖 course | 改课程均分需动 N 行学生记录 |
| 3NF 违规 | student→dept, dept→dean，学生表存 dean | 换院长要扫全体学生行 |
| BCNF 违规 | (teacher, subject, book)：teacher→book，多候选键时主属性间依赖 | 换教材产生冗余或删失 |
| 4NF 违规 | teacher 的 subject 集合与 book 集合独立多值，挤一表 | |subject|×|book| 的配对冗余（增广的表内版） |

- 用法：评审时逐行对照"你的表像不像其中任何一个"——比抽象判据快得多。

## 补充三、范式之外：被本章省略的质量维度

- **键的稳定性**：BCNF 不检查"业务上会不会改主键"（身份证号做主键照样过检）；
- **NULL 纪律**：范式不管可空性设计（全参与要 NOT NULL，第 5 章 R6 补）；
- **约束可达性**：依赖保持若靠跨表触发器实现，形式上"保持"了，运维上没保持；
- **语义可读性**：过度分解（每列一表也满足 BCNF）杀死可读性——反"atomization"极端；
- 这些维度由 Hoberman 的模型记分卡式审计补足（[../数据建模经典教程.md](../数据建模经典教程.md)），两书并读恰成互补。

### 本章一页总结

- 依赖是语义的投影：FD 不是数学游戏，是"业务上谁决定谁"的形式化——需求访谈里的每个"只要…就一定…"都是一条候选 FD；
- 范式阶梯的每一步都只买一种异常的单，别指望一次分解解决所有质量问题；
- 无损连接与依赖保持的取舍是本章唯一"必须会推"的定理级内容，其余是判据应用；
- 工序立场：**先 BCNF 基线，后按负载画像反范式**——反范式的每一列冗余都要有工单（决策日志+同步机制+校验报表），否则三年后它会变成"没人敢删的祖传列"。

## 核心概念速览（中英对照）

1. **函数依赖** — functional dependency：属性集间"定则同定"约束
2. **属性闭包** — attribute closure：由依赖推出的全部决定结果
3. **候选键** — candidate key：决定全集的最小属性集
4. **覆盖 / 极小覆盖** — cover / minimal cover：等价依赖集的精简形
5. **部分依赖** — partial dependency：对组合键真子集的依赖（2NF 禁区）
6. **传递依赖** — transitive dependency：经由非键决定方的依赖（3NF 禁区）
7. **BCNF** — Boyce-Codd normal form：凡决定方必为超键
8. **多值依赖** — multivalued dependency：X↠Y 的独立多重配对
9. **4NF** — 4th normal form：禁非键多值依赖
10. **无损连接分解** — lossless-join decomposition：可拼回且无增广
11. **依赖保持分解** — dependency-preserving decomposition：FD 检查不跨表
12. **增广元组** — spurious tuple：有损分解制造的假事实
13. **基线后反范式** — normalize-then-denormalize：先 3NF 再定点反范式的工序立场
