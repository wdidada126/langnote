## 10.1 Neo4j 5 集群拓扑词汇表

5.x 抛弃旧 Causal Clustering 命名，本章的星座（⚠️ 转述 + 图名佐证）：

- **Core Server**：参与共识、持有可写数据库副本（`10-1-basic-cluster` 三 core）；
- **Read Replica**：只拉流、只读分流（`005-create-db-secondaries`/`10-10`）；
- 数据库级副本配置：`CREATE DATABASE x IF NOT EXISTS WAIT ONLINE ON SERVERS {primary: 3}` 类语法（`001-create-db-3-primaries` ✅ 文件名直指）；
- `SHOW SERVERS`（`004` ✅）看成员与角色。

## 10.2 多数派：写路径的仲裁数学

`10-2-majority` 讲 Raft 式多数派提交：写需 ⌊N/2⌋+1 个 core 确认。演示链（图名串起来 ⚠️ 逆推）：

1. 三 core 正常写（10-3 协议浏览器观察提交流）；
2. **杀掉一个 core**（`10-6-after-kill-1`）：仍有 2/3 多数，写继续；
3. 杀掉两个：无多数，`10-7-follower-only` → `10-8-no-more-writers-allowed`——集群**降级为只读**而非乱写；
4. 恢复后追日志重入多数派。

这与 DDIA 共识章（[../设计数据密集型应用.md](../设计数据密集型应用.md)）严格同构；图库的差别在“每库独立选主”——多数据库平面把共识按库切分（`001` 的 per-db 语法 ✅）。

## 10.3 “因果一致性”的客户语义（10-13）

`10-13-causal-consistency`：客户端会话保证“我读必见我已写”（session causality），跨会话则可能读到旧版——读副本场景的必修课。运维口诀（重构 ⚠️）：

- 同连接/同书签（bookmark，协议层机制 ⚠️ 转述）→ 因果一致；
- 报表/搜索类旁路读 → 接受有界滞后，用监控盯复制落后（接 Ch.11）。

## 10.4 Composite Database：官方“分片”

`008-create-composite` + `composite-query-1..5` + 10-14/15/16 图：把多个成员库聚合成一个可查询库——

```cypher
// 示意重构（⚠️）
CREATE DATABASE prod IF NOT EXISTS
  TOPOLOGY (server1+"dbEU"=1, server2+"dbUS"=1) WITH PRIMARY dbEU, dbUS;
USE prod MATCH (n) RETURN count(n);   -- 跨分片聚合查询
```

五连脚本的教学节奏（逆推 ⚠️）：建成员库 → 组复合库 → 单分片查询 → 跨分片聚合 → 带谓词下推/部分失败语义的高级形态。**这是 Neo4j 对“图太大放单机放不下”的官方答案**：不自动再平衡，手工拓扑即分片观。

## 10.5 边界与不做的事

- 无自动分片/再平衡（与 TigerGraph/分布式 NewSQL 的差别 ⚠️ 转述）；
- 写仍在单一主副本，跨库写事务不在本章射程；
- 社区版无集群——本章全部依赖企业许可镜像（docker `.env` ✅ 需接受许可条款的镜像）。

边界清单反过来读更有用：本章**教了什么**——副本拓扑声明、成员观测、复合聚合、降级行为——恰好覆盖“把单机 Neo4j 放大成服务”的全部客户可见面；没教的那一半（自动再平衡、跨分片事务、全局二级索引）是其他系统的疆域，对照表见 10.8 ⚠️（重构）。

## 10.8 三册集群词汇对照卡（第 3 波兄弟登记）

| 本册（Neo4j 5.x） | MongoDB 副本集 | Cassandra |
|---|---|---|
| Core Server | voting member | 对等节点（gossip） |
| Read Replica | secondary 只读分流 | 每节点皆可协调读 |
| 每库独立主（per-DB primary） | 整套一 primary | 无 leader，per-partition 仲裁 |
| 失多数 → 拒写保一致 | 无主 → 写停 | 达不到 quorum → 报错 |
| Composite DB（手工拓扑分片） | sharded cluster（自动 balancer） | token ring vnode（自动） |
| 会话因果一致（bookmark） | read-your-writes 会话 | 一致性级别旋钮 |

设计分野一句话：**Neo4j 把“自动再平衡”明确不做**（10.5），容量决策留给架构师；两兄弟把这件事交给了守护进程。选哪种不是信仰问题，是“图不能跨分片遍历的代价”与“再平衡窗口的代价”之比 ⚠️（对照列为他书常识级转述，兄弟册互链登记见 00 第七节，已于波尾闭环 ✅（2026-09-27，00 级））。

## 10.10 Composite 适用边界清单（重构）

**适合**：按地域/数据主权的分区（每区一成员库）、按租户的物理隔离、按冷热年代的分区——共同点是**跨分片查询模式少**。
**不适合**：跨分片多跳遍历、跨分片写事务、需要动态 re-shard 的增长型业务——图的连通性假设与切分天然打架。
决策问句（一句话版）：验收查询里穿越成员边界的占比超过 5% 吗？超了先回到 10.1 的“单大库 + 多读副本”形态再谈分片 ⚠️（判断性阈值，书中无实测数据）。

## 10.12 一页纸小结（重构）

**一句话**：Neo4j 的扩展观 = 复制保可用（core/RR + 多数派）、拓扑保分片（composite）、会话保语义（bookmark）——三件事各配一套命令、互不越界。读完本章的检验：能对“三 core 挂一、RR 滞后 40s、composite 停一成员库”三连故障各自说出预期行为，即为通过 ⚠️（预期行为均转述自 10.2/10.3/10.9 的图示与脚本序）。

## 核心概念速览（中英对照）

- **Core Server** — Core：参与共识、可承载主副本的集群成员
- **Read Replica** — Read Replica：只读分流成员，不参与投票
- **多数派** — Quorum：⌊N/2⌋+1 的法定人数提交规则
- **每库选主** — Per-DB Primary：共识按数据库粒度独立运作
- **只读降级** — Writer Unavailable：失去多数时集群拒写保一致
- **因果一致** — Causal Consistency：会话内“读己之写”保证
- **书签** — Bookmark：客户端携带的一致性令牌 ⚠️ 转述
- **复合数据库** — Composite Database：多成员库聚合出的虚拟分片库
- **拓扑声明** — Topology Clause：手工指定服务器×库副本分布
- **成员库** — Member Database：复合库的被聚合方
- **仲裁** — Membership/Arbitration：第三成员（arbiter）辅助投票形态 ⚠️ 书未证
