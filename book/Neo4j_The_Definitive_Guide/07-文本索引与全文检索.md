# 07 · 文本索引与全文检索（Ch.7，章题为 ⚠️ 逆推重构）

> 取证锚点（✅ 实抓配套仓库 chapter07/cypher，26 个脚本）：`001-match-track`、`002-create-index`、`003-match-lower`、`004-transform-text`、`005-match-lower-b`、`006-contains`、`007-recreate-index`、`008-text-limit-reached`、`009-combined-match`、`010-create-fts-index`、`011-query-fts-index`、`012/013` test-fts、`014/015` more-test-data、`016-multi-token-search`、`017-or-query`、`018-and-query`、`019-phrase-search`、`020/021-wildcard(-prefix)`、`022-fuzzy-search`、`023-026 persons-db/fts-and-normal/artist-search`。脚本序列完整暴露论证路线：**范围索引治不了文本搜索 → 变换函数与 lower 索引 → 索引容量上限 → 全文索引（FTS）语法课 → 双库分工**。

## 7.1 问题起点：MATCH 里的字符串谓词困不住全扫

- `003-match_lower`：`WHERE toLower(t.name) CONTAINS 'guns'`——函数包裹属性，索引序/Seek 全部作废（Ch.5 sorting-5 的同款教训）；
- `004-transform-text`：入库时**预计算** `nameLower` 属性；`005-match-lower-b` 在预计算列上建索引后 Seek 复活——“查询期函数 → 存储期列”的经典交换；
- `006-contains`：`CONTAINS` 中段匹配即便有 range 索引也只能扫后过滤——range 索引只救前缀。

结论（本章第一定律 ⚠️ 重构）：**等值/区间找索引，词法找全文索引**——与 ES TDG 的“query vs filter”二分同构。

## 7.2 索引的容量边界（008-text-limit-reached）

`text-limit-reached` 演示 Neo4j 5 文本索引（旧 token index 的遗产）的条目上限与“索引失效→退化为扫描”的行为 ⚠️（细节转述）。工程含义：

- 索引不是免费的：token 索引在超高重复度字段（如“rock”）上先撞内存/上限墙；
- 撞墙后计划器静默降级，PROFILE 里才看得见（接 Ch.5 方法论）。

## 7.3 FTS 索引：Lucene 坐在图库里

`010-create-fts-index`（`CALL db.index.fulltext.createNodeIndex`，5.x 已被 `CREATE FULLTEXT INDEX` 取代 ⚠️ 两代语法书中所处位置推定）到 `011-query-fts-index`（`db.index.fulltext.queryNodes('idx', 'query')`）是本章脊柱：

- 分词、打分（relevance score）、`analyzer` 可配置；
- 查询字符串小语言：`017-or`/`018-and`/`019-phrase "exact phrase"`/`020-wildcard guns*`/`022-fuzzy ~2`——Lucene query parser 的语义词表在图库内直达；
- 结果可继续进模式：`YIELD node AS t MATCH (t)<-[:HAS_TRACK]-(p)` ——**全文检索当遍历入口**，这是图库做搜索差异化的关键句。

对照 [../Elasticsearch_The_Definitive_Guide/00-总览与阅读地图.md](../Elasticsearch_The_Definitive_Guide/00-总览与阅读地图.md)：同一 Lucene 血统，两套运维面（内嵌 vs 独立集群）。选型问题（何时把文本“搬出去到 ES/独立搜索”）本章未展开，属本册留白 ⚠️（判断）。

## 7.4 混合查询的形状（009-combined-match）

`009-combined-match` 把 FTS 打分结果与图约束谓词合成一个查询——“搜索 + 过滤 + 关系加权”三合一：

1. FTS 出候选（带 score）；
2. 模式段裁掉不合规候选（如“仅今年发行的专辑”）；
3. 关系维度再排序（如“我朋友也收藏的加分”）。

这个三段式即 2025 年 GraphRAG 检索管线的雏形——Ch.13 的向量版把第 1 段换成近邻搜索，骨架不变。

## 7.5 测试驱动：persons 小库的独立实验场

`023-test-persons-db`、`024-persons-fts-index`、`025-fts-and-normal-search`、`026-artist-search`：作者另开一个小数据集/库做 FTS 行为实验，最后回到主库做艺人搜索——**为教学构造最小可证伪库**的习惯值得记录（GD2e 04 章“测试驱动的数据模型开发”的延续）。

## 7.6 拼写容错与召回工程（022-fuzzy）

- fuzzy 编辑距离参数与召回/噪声的权衡 ⚠️（书中阈值推定）；
- 多词（`016-multi-token-search`）的默认 OR 语义与显式 AND 的分数差——搜索引擎初学者最常翻车处，本章用双查询对照教学。

## 7.7 全章决策表

| 需求 | 武器 | 本章证据 |
|---|---|---|
| 精确键查找 | range 索引/唯一约束 | 002 |
| 大小写不敏感 | 预计算小写列+索引 | 004/005 |
| 前缀匹配 | range 索引即可 | 006 反衬 |
| 中段子串 | FTS 或放弃精确位置 | 006 |
| 词组/布尔/通配/模糊 | FTS 查询小语言 | 017-022 |
| 搜索+关系加权 | FTS YIELD 进模式 | 009 |

## 7.8 analyzer 与语言面（Lucene 惯例 ⚠️ 转述）

FTS 索引可指定 `analyzer`（index/query 两侧可不同），这是本章最容易被跳过的工程面：

- 默认 standard 分词对 CJK 逐字切、精度差；中英文混排的艺人库要显式选 analyzer——**analyzer 决策即 schema 决策**，改 analyzer = 重建索引（回填期查询退化，接 Ch.4 索引生命周期卡）；
- 7.1 的预计算小写列服务 range 索引路径；FTS 在索引内部另做一遍小写/词干归一——**两条查询路、两层归一化**，别指望共享；
- `020/021-wildcard(-prefix)` 的前缀形态 `guns*` 是安全形状；**首字符通配**在倒排结构里天然慢（无法定位词项起点 ⚠️ Lucene 常识转述）；
- 词干化（stemming）让 `listen/listening` 互召回——但也带来误召回，`019-phrase` 的引号形态是关闭扩散的阀门。

## 7.9 从 FTS 到向量：同一骨架的换代（Ch.13 预告）

| 需求 | Ch.7 答案 | Ch.13 升级 |
|---|---|---|
| “像这个词” | fuzzy/wildcard 词形近似 | embedding 语义近似 |
| 混合排序 | FTS score + 关系加权（7.4） | 向量 score + 图谓词，RRF 融合 |
| 输入噪声 | 归一化列 + 容错查询 | embedding 天然抹平拼写 |
| 精确键/枚举 | 仍是 range 索引/约束 | 不变——向量不接管这一格 |

结论（重构）：**向量索引没有替代 FTS，而是给 7.4 三段式的第一段加了第二条召回通道**——两路并行、融合层合并，骨架十年未变。这句话也是 Ch.13 全章的公理。

## 7.10 检索排障 SOP（重构）

1. **零结果**：先怀疑 analyzer 与文本语言不匹配，再核查询串语法（AND/OR 大小写敏感是 Lucene query parser 的经典坑 ⚠️）；
2. **结果过泛**：默认多词 OR 语义（7.6）——显式 `+term`/AND；对照 `017/018` 两脚本的分数谱差；
3. **打分怪异**：短文档天然高分（长度归一 ⚠️），检查 YIELD score 是否被下游 collect/avg 摊平；
4. **突然变慢**：`SHOW INDEXES` 看 state/填充进度（7.2 退化事故的回放键）；
5. **中文召回差**：换 analyzer 重建，而不是退回 `CONTAINS` 全扫——后者是 7.1 已判死刑的路。

🔧 概念类比（DuckDB 1.5.5，非 Neo4j 行为）：关系侧 `WHERE lower(name) LIKE '%guns%'` 即“中段子串”的全扫原型，demo 系列实测其正确性等价、代价 O(N)——这正是 7.1 第一定律在另一个引擎里的镜像证明；FTS 扩展超出本目录口径，不再展开。

## 7.11 收尾：本章决策树在索引家族全景中的位置

5.x 索引家族五格（range/point/text/fulltext/vector），本章占两格、预告一格：

```
查询形状 ──┬─ 精确键/枚举 ────────→ 唯一约束/range（Ch.2/Ch.4）
           ├─ 区间/前缀/点 ───────→ range/point（Ch.4）
           ├─ 词法（短语/模糊/通配）→ FTS（本章主场）
           └─ 语义（"像不像"）────→ vector（Ch.13）
```

`026-artist-search` 回到主库做艺人搜索是这棵树的现场演示：**同一业务入口，词法支与键支并存**，选支的判据是 7.1 第一定律而不是个人偏好。

## 核心概念速览（中英对照）

- **范围索引** — Range Index：等值/区间/前缀的通用二级索引
- **全文索引** — Fulltext Index：基于 Lucene 的分词倒排索引
- **分词器** — Analyzer：文本→词元的可配置流水线
- **相关性打分** — Relevance Score：FTS 查询返回的匹配度
- **谓词下推失效** — Index Unusable：函数包裹属性导致 Seek 作废
- **预计算列** — Materialized Lowercase：以存储换查询期函数
- **短语查询** — Phrase Query：引号内精确词序匹配
- **模糊查询** — Fuzzy Query：编辑距离容错检索
- **通配符** — Wildcard：前缀/中段 `*` 模式匹配
- **搜索入口遍历** — Search-then-Traverse：FTS 候选进图模式的两段式
- **索引上限退化** — Index Limit Degradation：超容量后静默转扫描
