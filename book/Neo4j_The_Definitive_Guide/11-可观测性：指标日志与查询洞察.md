> 取证锚点（✅ 实抓配套仓库 chapter11）：`commands.md` 通篇是可直接复制的观测操作（`docker exec -it neo4j-tdg cat .../server-logs.xml`、`curl http://localhost:2004 | grep ...` 六连、Loki LogQL 三条）；`log4j2-examples/` 下 **11 个日志定制示例目录**（agent-filter、authenticated-user-filter、composite-filters×2、cypher-query-filter、database-name-filter、json-layout、logs-to-console、querylog-file-per-db、source-filter、tx-event-filter、tx-metadata-filter）；`python-scripts/001-attaching-metadata.py、002-loki-meta.py`；figures 13 张（grafana-metrics-1..3、loki-all/2/3/4、metrics、node-count(-delta)、user-logs、select-loki、grafana1）。本章证据密度全书第一档：**给的是命令，不是概念**。

## 11.1 Neo4j 可观测三支柱（本章坐标系）

1. **指标（metrics）**：`http://localhost:2004` 端点的 Prometheus 文本格式（✅ commands 用它做六项 grep）；
2. **日志（logs）**：`neo4j.log / security.log / debug.log / query.log` 文件族（✅ commands 实读前三种 + query.log grep 实验），布局由 `server-logs.xml`（log4j2）定制；
3. **查询洞察（query insights）**：常驻内存的最近查询统计，与 query.log 互补——日志是历史，insights 是“现在正在疼的地方”⚠️（该过程面语义转述自 5.x 文档惯例，`SHOW QUERY PARAMETERS`/insights 视图名以手册为准）。

对位：Ch.5 的 PROFILE 是**单查询显微镜**，本章是**机群望远镜**；02 章 2.10 埋的观测钩子在此全面接上。

## 11.2 指标端点走查（✅ commands.md 六连原样）

```bash
curl -s http://localhost:2004 | grep 'neo4j_dbms_vm_heap_used'    # JVM 堆
curl -s http://localhost:2004 | grep 'vm_gc_time'                 # GC 压力
curl -s http://localhost:2004 | grep 'page_cache'                 # 页缓存命中（Ch.9 内存世界观的仪表盘）
curl -s http://localhost:2004 | grep 'connections_running'        # Bolt 并发（Ch.10 读流量分流）
curl -s http://localhost:2004 | grep 'count.node'                 # 逻辑计数（增长趋势线）
curl -s http://localhost:2004 | grep 'execution_latency_millis'   # 执行延迟分位
```

六项正对应四类事故：堆/GC → 大事务（Ch.2/5）；pagecache → 慢查询通病（Ch.5）；connections → 连接池配置（Ch.10 RR 分流）；count/latency → 业务面容量与 SLO。`node-count` 与 `node-count-delta` 两张图（✅）说明作者特意区分**存量与增速**——增速才是告警对象。

## 11.3 日志文件族与慢查询 grep（✅ 原文命令）

- `tail -n 10 security.log`：授权事件留痕（Ch.6 运维边）；`tail -n 0 -f debug.log`：细粒度诊断；
- 慢查询考古（本章最实用一行 ✅）：

```bash
cat logs/query.log | grep -E ' ([5-9][0-9]{3}|[1-9][0-9]{4,}) ms:'   # >5s 的查询
```

正则语义：耗时字段落在“5000–9999ms 或 ≥10000ms”——**无依赖工具的冷启动排障**；Grafana 面板是它的奢侈品版本。

- query.log 里直接 grep 回原语句（`grep 'MATCH (n:Playlist)'` ✅）：从“有人抱怨慢”反查到具体 Cypher，是 Ch.5 SOP 的入口动作。

## 11.4 server-logs.xml：日志是配置出来的

11 个 log4j2 示例目录（✅）把“默认日志布局不够用”讲透，高频三件套：

- `querylog-file-per-db`：**每库一份 query.log**——多数据库实例（Ch.10）下按库分流是排障刚需；
- `cypher-query-filter` / `source-filter` / `agent-filter`：按语句内容/来源地址/客户端 agent 裁剪——“只记录那条贵查询”的语法；
- `json-layout`：为 Loki/ELK 采集而生的结构化输出（11.5 的前提）。

`authenticated-user-filter`、`tx-event-filter`、`tx-metadata-filter`（✅ 目录名）则把事务元数据接进日志——**应用侧身份要靠事务元数据透传**，见 11.6。

## 11.5 Grafana + Loki 观测栈（✅ compose 命令）

```bash
docker compose -f docker-compose.yml -f docker-compose-observability.yml up -d
```

LogQL 实例（✅ commands 原文）：

```
{job="neo4j", filename="/logs/query.log"} | json
{job="neo4j", filename="/logs/query.log"} | json | database="neo4j"
```

- `| json` 把 json-layout 的字段解析成 Loki 标签，随后按 database/应用维度过滤——Loki 系列图（loki-all/2/3/4、select-loki ✅）即此流程截图；
- 观测数据写进专用 `observability` 库（`CREATE DATABASE observability WAIT` ✅），与业务库同址演示——生产上应外置 ⚠️（判断）；
- 压力实验脚本（`UNWIND range(1,5000) CREATE (n:TestNode)` 后删 1000 ✅）专供面板“看见波峰”：可观测性要先**可观测地造一次事**。

## 11.6 元数据透传：让日志认识你的业务（✅ 两脚本）

`001-attaching-metadata.py` / `002-loki-meta.py`（✅ 文件名与主题）演示驱动侧给事务/查询挂元数据（如 request id、tenant），日志侧（tx-metadata-filter ✅）把它捞进 query.log，Loki 再按标签切分。**没有透传，日志只认识 neo4j 用户；有了透传，日志才认识 Alice 的哪次请求。** 这是 Ch.6 `observer` 角色（✅ commands 里 CREATE ROLE observer + GRANT ACCESS 两行）之外的另一半：权限决定谁能看，元数据决定看见的可不可归属。

## 11.8 告警阈值速查（社区经验重构 ⚠️，非书中数字）

| 指标（✅ 端点名） | 关注形态 | 经验阈值语义 | 第一响应 |
|---|---|---|---|
| `page_cache_hit_ratio` | 持续 <1 | 工作集超内存 | 重配 9.9 内存比/加读副本 |
| `neo4j_dbms_vm_heap_used` | 锯齿基线爬升 | 泄漏/大事务堆积 | SHOW TRANSACTIONS（Ch.2） |
| `vm_gc_time` | 占比突增 | heap 挤压前兆 | 同上 + 查 12 章投影驻留 |
| `connections_running` | 逼近池上限 | 慢查询连锁占坑 | 11.3 考古慢查询 |
| `execution_latency_millis` p95 | 阶跃 | 计划翻转/统计过期 | Ch.5 SOP/5.11 |
| query.log 慢查询条数 | 任意非零趋势 | 业务/模型漂移 | 验收查询回归（Ch.3） |

阈值的正确用法是**画趋势后定基线**，抄别人的数字只会收获噪声——本章 5000 TestNode 压力实验（✅）的存在就是教读者：先制造一次已知事件，再给面板画线。

## 核心概念速览（中英对照）

- **指标端点** — Metrics Endpoint：2004 端口暴露的 Prometheus 文本面
- **查询日志** — Query Log：逐查询耗时/语句/身份的历史流水
- **查询洞察** — Query Insights：引擎内常驻的近期查询统计 ⚠️
- **server-logs.xml** — Log4j2 布局文件：日志分流/过滤/格式化的配置面
- **每库日志** — Query Log per Database：多数据库形态下的按库分流
- **json-layout** — JSON Layout：为日志采集器准备的结构化输出
- **LogQL** — Loki Query Language：标签选择 + `| json` 解析的日志查询
- **元数据透传** — Transaction Metadata：把应用身份带进引擎日志的链路
- **存量 vs 增速** — Count vs Count-Delta：node-count 双图的告警学
- **压力注入** — Synthetic Load：造测试波峰验证观测链路
- **observer 角色** — Observer Role：只读观测面的最小权限（✅ commands）
