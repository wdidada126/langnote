## 2.1 为什么第 2 章就讲导入

本书的体裁（PoC→production 食谱）决定了导入前置：第 1 章用 LIMIT 预览过数据后，**一切建模、调优、观测都需要一个装满真数据的库**。配套 README 的“Step 1: Downloading the dataset”就是这个意思——先给全量素材，后面 11 章都在同一份 Spotify 数据上说话。

## 2.2 LOAD CSV：Cypher 内的第一批处理器

本章主干工具是 `LOAD CSV`（⚠️ 语法细节转述自官方文档惯例）：

- `LOAD CSV WITH HEADERS FROM 'file:///...' AS row`——首行当表头，字段按列名取；
- `USING PERIODIC COMMIT 1000`——旧式分批提交；在 5.x 中由 `CALL {} IN TRANSACTIONS` 子句接管（仓库脚本 `004-call-in-transactions` 的存在 ✅ 佐证本书讲新语法）；
- 文件必须放在 Neo4j 服务器 `import` 目录（服务器模式）或项目目录（Desktop/Docker 挂载，书用 docker 目录 ✅）。

**为什么必须分批**：单事务导入百万行会把事务日志撑到不可接受的大小，且失败全回滚。5.x 的 `IN TRANSACTIONS` 把“批大小、失败重试、错误日志（`SHOW TRANSACTIONS`/error 文件）”变成声明式选项。

## 2.3 约束先行，索引随后：导入顺序的纪律

脚本序 `002-create-constraint` 出现在 `003-load-tracks` **之前**，这是本章真正的论点：

1. 先建**唯一约束**（`CREATE CONSTRAINT track_id IF NOT EXISTS FOR (t:Track) REQUIRE t.id IS UNIQUE`）；
2. 约束自动附带索引，MERGE 匹配不再全表扫；
3. 不这样做时，每个 MERGE 都是 O(N) 扫描，导入曲线是二次方——`005/006` 的 locking/wait-spinning 演示（✅ 文件名）正是“锁与等待”反面教材：并发批量 MERGE 同一键时的自旋与争用。

书中表格（tab-1-1、tab-2-1、tab-3-1，✅ 脚本名）对应“有无约束 × 分批与否 × 并发与否”的对照实验 ⚠️（表格内容推定）。

## 2.4 neo4j-admin database import：千万级走旁路

`admin-import.md`（✅ 实抓文件）讲的是 `neo4j-admin database import full`：

- 离线工具，库必须未运行/为空；
- 直接生成存储文件，绕开 Cypher 事务层，速度量级提升（⚠️ 具体倍率书中数字未核到，不编造）；
- 代价：不走约束校验、需要预先摆好 CSV 分片（`--multiline-fields` 等开关）、错误恢复靠重跑。

选型口诀（重构自本章论证 ⚠️）：**百万以内 LOAD CSV+IN TRANSACTIONS，千万以上 admin import，流式增量走驱动**（`python-scripts/` ✅ 本章已出现 Python 批量写示例，为 Ch.13 埋线）。

## 2.5 驱动侧批量写与幂等

Python 脚本示例的骨架（⚠️ 依 neo4j Python 驱动通行惯例重构）：

```python
with driver.session(database="playlists") as s:
    s.run(
        "UNWIND $rows AS r MERGE (t:Track {id:r.id}) SET t.name=r.name",
        rows=chunk,  # 每块 ~5k-10k 行
    )
```

要点：`UNWIND` 参数表 + `MERGE` 让客户端也能声明式幂等；`execute_query`/`session.execute_write` 提供重试。事务重试要幂等，幂等靠约束——三件事是一件事。

## 2.6 数据清洗的图式做法

Spotify 数据脏点在本章的处理（Ch.8 会升级成实体解析）：

- 艺人名带引号/撇号（`Guns 'N' Roses`）——CSV 转义与 `trim/toString` 处理；
- 流派是字符串化列表 `"[hard rock, heavy metal]"`——先整串入属性，**本章刻意不炸开**，炸开成节点是 Ch.4 的建模决策；
- 同一名多个 SpID——本章只按 SpID 建节点，重复实体问题挂起，Ch.8 用“resolved entities”回收伏笔。

🔧 旁证（DuckDB 1.5.5，概念类比非 Neo4j）：解析 `gnr-genres.csv` 时若不清洗，`"[synthwave]"` 会带上尾随 `]`——第一版脚本的 genre 列确实分裂出 `synthwave]` 与 `synthwave` 两种值（demo 运行记录），**一行代码的转义差异就制造假实体**。这为 Ch.8 的必要性给了个关系侧的直观注脚。

## 2.7 导入完成后的体检清单（重构）

- `SHOW DATABASES` 确认大小与 home 库；
- `CALL db.schema.visualization` 看标签/类型是否如建模预期 ⚠️（5.x 过程名以手册为准）；
- 约束清单与行数比对：`MATCH (t:Track) RETURN count(t)` vs CSV 行数；
- 度分布抽样：`MATCH (n) RETURN n ORDER BY size((n)-->) * -1 LIMIT 10`——提前看见 god node（Ch.5 主题）；
- `SHOW TRANSACTIONS` 观察残余写事务（对应 `010-transactions-info` ✅）。

## 2.8 常见事故与本书处方

| 事故 | 根因 | 处方（本章位置） |
|---|---|---|
| 导入越来越慢 | MERGE 无约束索引 | 约束先行（2.3） |
| 导入中途 OOM | 单事务吃全量 | IN TRANSACTIONS 分批（2.2） |
| 重复节点成对出现 | 导入键不唯一/大小写差异 | 唯一约束 + 清洗（2.6） |
| 并发导入死锁自旋 | 多线程写同一批键 | 分区导入/降并发（2.3 反面教材） |
| 库文件巨大 | 空闲页未回收 | 留到 Ch.9 store 清理讲 |

## 2.9 导入通道选型卡（重构）

| 通道 | 数据量级 | 库状态要求 | 约束校验 | 失败语义 | 本章工具位 |
|---|---|---|---|---|---|
| Browser/驱动逐条写 | <10k | 在线 | 有 | 逐事务回滚 | 001 预览期 |
| LOAD CSV + CALL IN TRANSACTIONS | 1万–1千万 | 在线（import 目录） | 有 | 批级失败/错误日志 | 003/004 |
| 驱动 UNWIND 参数表 | 1万–100万 | 在线 | 有 | 事务重试（须幂等） | python-scripts |
| neo4j-admin database import | 1千万+ | 离线空库 | **无**（直写文件） | 整体重跑 | admin-import.md |

口诀复述：**在线有校验、旁路无校验；量级不到位先查约束索引，再谈换通道**——2.3/2.8 两类事故的共同根因都是第二行没做。

## 2.10 导入进行中的观测钩子（为 Ch.11 埋点）

导数据时应当“看得见”（⚠️ 过程/命令名按 5.x 文档惯例转述，使用前以手册核对）：

- `SHOW TRANSACTIONS`（对应脚本 `010-transactions-info` ✅）：看谁在持锁、哪批卡住；
- 事务日志滚动速率是导入吞吐的第一信号：日志段切换过快 = 批过小、提交开销占比高（深化在 Ch.9）；
- 速度曲线必须是近似直线——**二次方曲线 = MERGE 无索引扫描**（2.3 定理的运维表述）；
- 2.7 的度分布抽样在导入 25%/50%/100% 各跑一次：god node 越早看见越便宜。

🔧 概念类比（DuckDB 1.5.5，非 Neo4j 行为）：关系侧的“约束先行”同样真实——demo 系列若在 `CREATE TABLE` 时不声明主键，gnr 数据的重复 Artist ID 会静默进入边表（demo2.py 运行记录）。存储引擎换、**“先声明完整性、后批量灌数”的因果链不换**。

## 2.11 本章与全书结构的关系

dataset.zip 单一数据集（✅ 直链 HEAD 200）贯穿 13 章，决定了两种工程心态：

1. **可复现性**：每章脚本在同一份 store 上跑，Ch.5 的 PROFILE 数字、Ch.12 的社区计数才可比——数据不漂移是教材级实验台的全部前提；
2. **增量建模**：Ch.4 的 Genre 炸开、Ch.8 的实体解析都在“本章导入的原始形态”上做手术——导入不是一次性事件，而是**模型演进图的第一个节点**；本章保留脏数据（引号、字符串化流派列表、多 SpID）正是为了给后面留活。

## 核心概念速览（中英对照）

- **LOAD CSV** — LOAD CSV：Cypher 内建 CSV 装载器，配 `file:///` 引用 import 目录
- **分批事务** — CALL IN TRANSACTIONS：子查询按批提交，替代旧 USING PERIODIC COMMIT
- **唯一约束** — Uniqueness Constraint：节点键唯一性声明，兼提供索引，MERGE 的前提
- **管理员工具导入** — neo4j-admin database import：离线直写存储文件的批量通道
- **幂等性** — Idempotency：重跑不产生重复的写入性质，靠约束+MERGE 达成
- **UNWIND 批量** — UNWIND Batch：参数表展开成逐行模式，驱动侧批量写惯用法
- **锁自旋** — Lock Spinning/Wait：并发 MERGE 争同一键资源的等待形态（脚本 006 主题 ⚠️）
- **错误日志** — Error Log：分批导入中记录失败批次的旁路文件 ⚠️
- **转义清洗** — Escaping/Cleansing：引号/括号/空格导致的字段级数据卫生处理
- **假实体** — Duplicate Entity：同一现实对象的多个节点变体，Ch.8 实体解析的对象
- **多行字段** — Multiline Fields：CSV 字段含换行时需专用开关解析 ⚠️
