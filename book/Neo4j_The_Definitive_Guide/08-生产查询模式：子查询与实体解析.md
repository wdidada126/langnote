## 8.1 子查询：把 Cypher 变成有作用域的语言

`003-subquery` 讲 `CALL { ... }`：

- 隔离作用域：内部变量不外泄，跨段只传表列——大查询的可维护性单位；
- `CALL { } UNION`（`005/006-post-union-a/b`）：多来源结果并集，替代断连 OR 模式（Ch.5 Product 教训的正解）；
- `CALL { } IN TRANSACTIONS`：Ch.2 批量写工具的归属地正式揭晓——**子查询是事务批处理的作用域载体**。

模式表达式（pattern comprehension，`004`）：`(a)-[:R]->(b) | b.name` 内联成列表——“小 JOIN 不出表达式”，避免整段 MATCH 的上下文污染。

## 8.2 度统计陷阱（007/008-degree-broken）

`007-degree` vs `008-degree-broken`：`size((n)-->)` 在更新事务内/无方向模式上的计数陷阱与正确姿势 ⚠️（细节转述）：

- 未提交事务中的度数读取语义、双向模式重复计数两类坑；
- 与 Ch.5 degrees 系列呼应：这次不是性能视角而是**正确性**视角。

## 8.3 实体解析：Guns N' Roses 问题

本章的灵魂段落（README “Modeling resolved entities” ✅）。真实素材（✅ 官方 CSV 实抓）：

| ID | Music Artist | Genre |
|---|---|---|
| 3qm84nBOXUEQ2vnTfUTTFC | Guns N' Roses | hard rock, heavy metal |
| b7f3a2c9e5d1x8k6m4n0p2q9r | Guns 'N' Roses | hard rock |
| t5k9j2h7f1w6m3n8p4q0r2s6x | Guns n roses | power ballad |
| z6r4k9n2h7p3m1j5f8x0w2d4q | GNR | heavy metal |
| fused-3qm84nBOXUEQ2vnTfUTTFC | Guns N' Roses | power ballad, heavy metal, hard rock |

同一现实艺人五个节点、三个拼法、两个 SpID 域。脚本链给出解法：

1. `009-genres-export`：先**导出**候选对（按名字归一/共同流派聚合）——解析第一步是关系型批处理；
2. `010-primary-artist`：定“主节点”（primary）；
3. `011-resolve-artist`：`MERGE (v)-[:RESOLVED_AS]->(primary)` 把变体挂靠；
4. `012-match-resolved`：查询时沿 `RESOLVED_AS` 归并统计；
5. `013-resolve-no-apoc`：不用 APOC 的纯 Cypher 实现（对照组）；
6. `014/015-qpp`：**查询处理流水线**（query processing pipeline ⚠️ 展开推定）收尾——把解析进例行管道而非一次性运动。

`fused-` 前缀行本身就是答案的一部分：融合节点是解析**产物**而非源数据——作者把它留在样例里当教学彩蛋。

## 8.4 🔧 DuckDB 1.5.5 实测：在这份真数据上复现最短路径与连通语义

**声明：SQL 复现概念，非 Neo4j 行为；数据为 Ch.8 官方 `gnr-genres.csv`；脚本与输出在 `D:\develops\tmp\dbwave_w3_neo4j\`（demo3.py）。**

把艺术家-流派解析成边表（炸开 `[hard rock, heavy metal]` 列表列，9 条 artist–genre 边）后：

**(a) 最短路径（BFS，递归 CTE）**——从 `3qm84...`（Guns N' Roses）出发，路径定义为艺术家经共享流派互达：

| 目标节点 | 跳数 |
|---|---|
| Guns N' Roses（3qm84，起点） | 0 |
| fused 节点 / GNR / Guns 'N' Roses | 1 |
| Guns n roses（t5k9...） | 2 |
| Gunship（3PALZ...） | NULL（不可达） |

读法：`t5k9` 只带 power ballad，必须借道 fused 节点两跳可达——“二度关系”在 SQL 里是递归 CTE 的 depth 列 + 路径数组防环（`NOT list_contains(path, e2.aid)`），在 Cypher 里是 `shortestPath((a)-[:G|G*]-(b))` 一行；两种写法都逃不过“**已访问集合必须按节点键而非显示名**”的坑：本演示第一版按艺人名防环，被重名（三个 Guns N' Roses）截断可达集，改按主键后数字才对——**实体不解析，遍历即失真**，这正是本章主题的跨引擎证言 🔧。

**(b) 连通分量（可达闭包）**：递归闭包 `reach(src,dst)` 聚合得 5 个“枪花家族”节点互相可达（各 4 个可达同伴，✅ demo3 输出），Gunship 独立成孤点——GDS 社区发现的最小近亲（12 章）在玩具数据上的对应物。

## 8.7 子查询四形态对照表（重构）

| 形态 | 语义 | 何时用 | 本章脚本 |
|---|---|---|---|
| `CALL { ... }` | 作用域隔离，只进出列 | 大查询分段/独立聚合 | 003 |
| `CALL { ... UNION }` | 多路结果并集 | 断连 OR 模式 → 避 Product（Ch.5） | 005/006 |
| `CALL { ... } IN TRANSACTIONS [OF n ROWS]` | 自动分批提交 | 批量写/在线重构（Ch.2/4） | 归属地揭晓 |
| 模式推导 `(a)-[:R]->(b) | expr` | 内联列表，不开新上下文 | “小 JOIN 不出表达式” | 004 |

配套语法 `COUNT { (c)-[:R]->() }` 子计数（Ch.12 commands 实战在用 ✅）与 `size()` 在未提交事务上的语义差，正是 `008-degree-broken` 的取证角度 ⚠️。

## 8.8 实体解析运营 SOP（重构）

把 8.3 的一次性手术变常驻管道：

1. **阻断**：规范化键（lower/去标点/去引号）分组 + 共同流派聚合，导出候选对（009 ✅）；
2. **匹配**：规则打分（同名 +10 / 共流派 +1），阈值进配置不进代码；
3. **合并**：只建 `RESOLVED_AS` 边、不物理合并节点——保留反悔权（03 章“边即缓存”同款姿势）；
4. **查询改写**：全部聚合沿 `(v)-[:RESOLVED_AS]?->(p)` 归并到主节点（012 ✅，`?` 可选关系语法 ⚠️）；
5. **回归**：每轮增量后全量重跑阻断；解析率/融合率做成 Ch.11 面板指标；
6. **升级路**：规则打分不够用时换 embedding 阻断——Ch.13 向量索引即承接点（8.6 “先管道后算法”的注脚）。

🔧 复现指引：`demo3.py`（DuckDB 1.5.5，非 Neo4j）在官方 gnr 真数据上执行第 3-4 步等价物——按 ID 去重后 5 变体互相可达、各自 4 个同伴（✅ 输出）；关系侧“改写到主节点”是 `JOIN resolved USING (primary_id)` 视图，图库优势在改写动作是模式里一跳的自然延伸而非额外结构。

## 8.9 为什么本章以 EXPLAIN 开场（重读注记）

`001-explain-all-tracks` 是本章第一支脚本（✅）：写法纪律（作用域/UNION/批分段）的前提是看得见代价——Ch.5 的方法论在这里已内化为“先 explain 再说话”的肌肉记忆。**本书不为任何语法糖豁免成本论证**，这个脚本序本身是体裁宣言。同理 `016-security-setup-a` 压在章尾：一切写法最终要在“有角色的世界”里跑——Ch.6 的账在这里结。

本章语法清单（验收口径）：`CALL{}`/`UNION`/`IN TRANSACTIONS`/模式推导/`COUNT{}`/可选关系 `(v)-[:R]?->(p)` 六个构造，每个至少出现在一支本章脚本中——**写法章的词汇表以仓库脚本名为词典**，比任何语法书都硬 ✅。

## 核心概念速览（中英对照）

- **CALL 子查询** — Call Subquery：带作用域的查询组合单元，可 UNION、可进事务
- **模式表达式** — Pattern Comprehension：模式→列表的内联推导
- **实体解析** — Entity Resolution：同一现实对象多变体节点的识别与归并
- **RESOLVED_AS 边** — Resolution Edge：变体→主节点的挂靠关系
- **主节点** — Primary Entity：解析后保留查询身份的目标节点
- **阻断** — Blocking：候选对生成的粗筛步骤（009 导出对应 ⚠️）
- **查询处理流水线** — Query Processing Pipeline：解析任务例行化（qpp 脚本 ⚠️）
- **防环路径** — Path De-duplication：递归遍历的已访问集
- **暂存库** — Staging Database：解析/实验用副本库
- **无方向度数** — Undirected Degree：`size((n)-->)` 的计数语义陷阱
- **纯 Cypher 对照** — No-APOC Variant：不靠扩展库的基线实现
