## 核心概念速览（中英对照）

- **定长数组** — std::array：零开销 C 数组包装，长度进类型，可整体拷贝比较。
- **动态数组** — vector：连续内存 + 容量倍增；默认序列容器。
- **双端队列** — deque：分块连续、两端 O(1) 插删的中间形态。
- **链表** — list / forward_list：双向/单向链表；节点稳定，splice 零成本转移。
- **排序字典** — set / map（及其 multi 版）：红黑树（实现约定俗成，标准只要求 O(log n) ⚠️）。
- **哈希容器** — unordered_set / unordered_map：桶 + 哈希函数 + 等价判据，平均 O(1)。
- **容量与大小** — capacity vs size：`shrink_to_fit`（C++11）只「请求」收缩；`reserve` 只保证不下穿。
- **置后构造** — emplace/emplace_back：参数直达元素构造；`vector` 上仍可能触发重分配。
- **安插/移除** — insert/erase 家族：返回值语义各容器不同（erase 返回后继是 C++11 统一的关键）。
- **list 特殊成员** — splice/merge/sort/unique/remove*：链表才有的结构性手术，算法族的「成员版」。
- **节点抽取** — extract/merge（node handle）：**C++17 才有，本书未覆盖 ⚠️**；换键改值的合法通道。
- **策略接口** — Policy Interface：key_comp/value_comp/equal/hash_function/桶参数——查「容器的脾气」。
- **分配器支持** — Allocator Support：容器带 `get_allocator()`；构造函数尾部可选 allocator 参数。

## 动机：容器之争本质是三问

1. **访问形状**：随机访问（下标）？两头进出？还是「按键找」？
2. **修改位置**：尾部？任意点？还是「位置根本不重要（有序/哈希）」？
3. **指针/迭代器要不要稳定**：嵌入式回调持迭代器 → 排除 vector 增长；持元素地址 → 排除一切会重排内存的容器。

第 7 章每容器两页纸（能力 + 操作 + 实例）回答 1、2，第 8 章按成员族回答 3 与复杂度。

## 机制

### 1. 共通能力与三种「拷贝」（7.1、8.2–8.4）

构造家族：默认 / 尺寸 n / 区间 `[beg,end)` / 拷贝 /（C++11）移动 / `initializer_list` / 分配器变体。
赋值同构。比较：`== != < <= > >=` 按字典序逐元素——`<` 要求元素有 `<`，unordered 容器**没有** `<`。
`swap`：容器间交换是 O(1)（换指针/控制块），与 `std::swap` 特化同义——排错时「先 swap 再验证」的基础。

### 2. 逐容器要点（7.2–7.9）

- **array**：`at` 检查、`[]` 不检查；可当 tuple（`std::get<I>`）；传给 C API 用 `.data()`。
- **vector**：增长策略实现定义（libstdc++ ×2、libc++ ×1.5/×2 ⚠️ 各版有变）——「倍增」是共识不是标准。
  `vector<bool>` 是**位压缩特例**：`operator[]` 返回代理引用（proxy），
  因此 `auto& r = v[i]` 绑不住真 bool；`&v[0]` 不合法。这是本书 7.3.6 点名批评、C++ 史上最著名标准失误之一。
- **deque**：块 map + 块内连续；两端 O(1)；**没有 capacity 概念**；`insert(中间)` 从较近的一端搬。
- **list/forward_list**：唯一保证「已定位元素插入/删除 O(1) 且不失效他者」；
  `size()` 在标准里 O(1)（C++11 起强制；SGI 时代是 O(n)，侯捷源码版记载的是老规矩 📄
  [../STL源码剖析.md](../STL源码剖析.md)）。
- **set/multiset/map/multimap**：节点容器；`insert` 对 set 返回 `pair<iterator,bool>`、对 multi 返回迭代器；
  `operator[]`（map）= 找不到就**值初始化插入**——拼错键静默造出 0。`at()` 是 C++11 的防呆版。
- **unordered_***（7.9）：哈希函数默认 `std::hash<Key>`，可相等性用 `std::equal_to<Key>`；
  `load_factor = size/bucket_count`，超过 `max_load_factor` 触发 rehash。桶迭代器是 forward 类。
  同桶内是链表（闭链哈希，实现约定俗成 ⚠️），故 rehash 后**迭代器**失效但**元素引用/地址**不失效（节点式）。

### 3. 复杂度总表（合并 7.12 与 8 章各处；n=size）

| 操作 | vector | deque | list | set/map | unordered_* |
| --- | --- | --- | --- | --- | --- |
| 随机访问 `[]` | O(1) | O(1) | — | — | — |
| 头插/头删 | O(n) | **O(1)** | O(1) | —（按序） | — |
| 尾插（摊销） | O(1) | O(1) | O(1) | O(log n) | O(1) |
| 已定位处插/删 | O(n) | O(min(到两端)) | **O(1)** | O(log n)+ | O(1) |
| 查找 | O(n) | O(n) | O(n) | **O(log n)** | **O(1) 平均** |
| 迭代器类别 | RA | RA | BiDi | BiDi | Fwd |

「已定位处」= 你手里已有指到该位置的迭代器；否则先加一次查找的代价。

### 4. 失效规则表（8.7 各节合并；STL 第一大坑）

| 容器 | 追加 push_back/resize 越容量 | 中间 insert | erase(p) |
| --- | --- | --- | --- |
| vector/deque | 全体失效 / deque 规则：迭代器全废、**引用不失效** | p 及之后失效 | p 及之后失效 |
| list/forward_list | 不失效 | 不失效 | 仅 p |
| set/map（含 multi） | 不适用（无预分配） | 不失效 | 仅 p |
| unordered_* | rehash 则迭代器全废；**不 rehash 不废迭代器**；引用/指针两者都永不失效 | 同左 | 仅 p（迭代器） |
| 任何容器 clear() | 全部失效 | | |

🔧 已实测 g++ 15.2（`-std=gnu++23`）——erase 返回后继 + C++20 统一 erase + unordered 桶接口：

```cpp
std::vector<int> v{1,2,3,4,5};
auto it = v.erase(v.begin()+1);        // it → 3（返回后继，安全续走）
std::erase(v, 3);                      // C++20：value 版 erase，vector 上没有成员函数版
// unordered_map<string,int> 初始 13 桶；max_load_factor(0.1)+rehash(64) 后 67 桶（GCC 取素数）
```

正确的「边走边删」惯用法（8.7.3）：

```cpp
for (auto i = c.begin(); i != c.end(); ) {
  if (should_delete(*i)) i = c.erase(i);   // 序列容器通用
  else ++i;
}
// 关联式 multi 容器在 C++11 前：erase(i++)；今天统一 i = c.erase(i) 亦可。
```

### 5. list 特殊成员与「成员 vs 算法」（8.8、6.7.3 呼应）

`splice`（O(1) 节点转移，跨容器亦可——只要 allocator/比较器兼容）、`merge`、`sort`（归并，稳）、
`unique`、`remove/remove_if`（真删除，算法族做不到）。规则复述：**链表上的结构性操作一律用成员**。

### 6. 策略接口与分配器（8.9、8.10）

`key_comp/value_comp/value_eq` 取回准则对象；unordered 的 `bucket_count/bucket_size/load_factor/rehash/reserve`
是性能治理面板（预热场景 `reserve(n)` 再灌数据，避免连锁 rehash）。
分配器构造参数在 C++11 时代还是「模板第二参数」，C++17 P0316 系改革后弱化为构造参数（见演进节）。

## 权衡：选型矩阵（7.12 的中文化压缩）

| 场景关键词 | 首选 | 次选 | 排除 | 一句话理由 |
| --- | --- | --- | --- | --- |
| 只追加 + 随机访问 | vector | deque | list | 缓存连续 + 零间接 |
| 头部也频繁进出 | deque | list(仅指针稳定时) | vector | 两端 O(1) 且可随机访问 |
| 元素地址必须稳定 | list | unordered_*（节点式）/set | vector/deque | 节点容器不搬家 |
| 大量中间插删 + 已定位 | list | — | vector | O(1) 手术 |
| 键唯一 + 要有序遍历 | set/map | 排序 vector（终态构建） | unordered | 区间查询 `equal_range` |
| 键查找为主不排序 | unordered_map | 排序 vector+二分 | map | 常数平均 + 桶可控 |
| 编译期定长 | array | 原生数组 | 一切堆容器 | 零开销 |
| 多值 + 有序 | multimap（键值配对） | list+排序 | unordered_multimap | `equal_range` 语义清晰 |
| 键可变的「引用语义表」 | map<K*,V>/map<shared_ptr<K>,V> | — | — | 容器永远值语义（6.11.2/7.11） |

## 相邻概念对比

- **`vector` vs `deque`**：都有 `[]`；deque 无 capacity 治理问题但小块缓存局部性差、`insert(中间)` 移动量取决于离哪端近。
- **`map` vs `unordered_map`**：稳定性都「只废所指迭代器」（节点式）；差异在有序遍历、最坏 O(n)、
  哈希质量依赖、以及「`operator[]` 插入」两边同款陷阱。
- **`set<T>` vs `sorted vector` vs C++23 `flat_set`**：树给增量更新，排序 vector 给查询与紧凑，
  flat_set 想两者兼顾（插入 O(n) 换缓存命中）。

## 最新演进与工业实践

- **C++11（本书自身即这波）**：移动进容器（vector 扩容搬移自动走 noexcept 移动，否则退回拷贝——EMC++ 条款 23 📄
  [../Effective_Modern_C++.md](../Effective_Modern_C++.md)）、emplace 族、`initializer_list`、`array/forward_list/unordered_*` 入列。
- **C++14**：set/map 透明比较器异构查找（P0919R3，已核）：`find("字面量")` 不再构造临时 string。
- **C++17**：`try_emplace` / `insert_or_assign`（map 精确控制「存在则不覆盖」）；node handle `extract/merge`
  （改键的正道：摘下节点改 key 再插回，免拷贝）；CTAD（`std::vector v{1,2,3}` 免写模板参数）；
  **分配器模板参数退役**：`vector<T, Alloc>` 类型里不再体现分配器（P0302R1 方向，⚠️ 本次未核实编号），类型系统瘦身。
- **C++20**：`std::erase/std::erase_if` 统一序列容器按值删除（P1209R0，已核，实测见上）；
  关联/无序容器获得 `contains(key)`——存在性判断不必再借 `count/find` 迂回；
  `starts_with` 系在 string（见第 8 站）。
- **C++23**：`flat_set/flat_map` 进入标准（⚠️ 提案号本次未核实，只记版次）；
  有序/无序容器全量异构查找（P2363R5，已核）——`unordered_map<string,...>::find(string_view)` 终获合法；
  `contains` 补齐。
- **工业实践**：
  - 高性能服务普遍「构建期用 vector、查询期用排序 + 二分/`equal_range`」，abseil 直接给出
    `flat_hash_map`（控制字节 + SIMD 探测的开放地址哈希，[abseil-cpp](https://github.com/abseil/abseil-cpp)），
    速度换走 std::unordered_map 的理由只剩「要标准类型接口」。
  - 桶接口治理：预热 `reserve()`、`max_load_factor(0.25)` 降碰撞，是缓存敏感场景的常规三板斧。
  - `vector<bool>` 规避：位集合用 `std::bitset`（定长）或 boost::dynamic_bitset（⚠️ 非标准）。
  - 行为以 [cppreference](https://en.cppreference.com/w/cpp/container) 各页为准；实现差异看
    [libstdc++](https://github.com/gcc-mirror/gcc)/[libc++](https://github.com/llvm/llvm-project/tree/main/libcxx) 测试。
