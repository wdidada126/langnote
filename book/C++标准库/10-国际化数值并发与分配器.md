# 第 10 站 · 国际化、数值、并发与分配器（原书第 16–19 章）

> 覆盖原书收尾四章：16 国际化（locale/facet）、17 数值（随机数/complex/valarray）、
> 18 并发（async/future/thread/mutex/condition_variable/atomic）、19 分配器。
> 四章共性：都是「横切组件」——locale 被 I/O 消费、随机数被 shuffle 消费、
> 并发与异常（01 站 exception_ptr）咬合、allocator 被容器（04 站 8.10）预留插槽。

## 核心概念速览（中英对照）

- **地域** — Locale：按类别（numeric/monetary/time/collation…）打包的文化层；流与 string 的隐藏参数。
- **切面** — Facet：locale 内的单个服务对象（numpunct/ctype/collate/codecvt…），以 `use_facet/get` 取用。
- **校勘** — Collation：按语言的字符串比较（collate facet），区别于 char_traits 码位序。
- **随机数引擎** — Engine：`mt19937/ranlux/linear_congruential`——确定性伪随机比特源，可播种可序列化。
- **分布** — Distribution：uniform/normal/poisson/bernoulli…，把引擎流转成目标统计形状。
- **复数** — complex：`abs/arg/polar` 与运算符族；科学计算遗留件。
- **值阵列** — valarray：定长数值数组 + 切片（slice/gmask）+ 表达式模板原型；实践中近乎弃用 ⚠️。
- **异步门面** — std::async / future：任务→结果通道的高级接口；`launch::async|deferred` 决定谁在何时执行。
- **线程句柄** — std::thread：OS 线程的 RAII 壳；**既不 join 也不 detach 就析构 = terminate**。
- **承诺** — promise / packaged_task：手动填值的 future / callable+future 接线盒。
- **互斥族** — mutex 家族与 Lock：`mutex/recursive_mutex/timed_mutex/…` + `lock_guard/unique_lock`（C++11）、
  `scoped_lock`（C++17）。
- **条件变量** — condition_variable：等待-通知；**永远配谓词**（防虚假唤醒与丢唤醒）。
- **原子量** — atomic：无锁最小同步；`fetch_add/compare_exchange_*` + 内存次序（默认 seq_cst）。
- **分配器** — Allocator：`allocate/deallocate/construct/destroy`（C++11 后两者归 traits）的内存策略插槽。

## 动机：为什么把这四章放最后一站

原书的排序逻辑如此：先语言、再 STL、再组件、最后「系统级与扩展级」。
并发（第 18 章）是 C++11 新增的**库化**成果——本书时代之前，线程不属于标准（📄 单文件笔记记载的
「附录 Boost 线程预告」口径经核实**不成立**：第 2 版第 18 章就是 std 并发正文，见目录 18.1–18.7）。
分配器（19 章）与国际化（16 章）则是标准库「接口与实现分离」哲学的两个极端标本。

## 机制

### 1. locale/facet（16.2–16.4）

```cpp
std::locale loc("");                    // 环境决定（LC_ALL/LC_*）
std::cout.imbue(loc);                   // 之后 << 走 num_put facet
auto& np = std::use_facet<std::numpunct<char>>(loc);
np.decimal_point();  np.thousands_sep();   // '.' ',' 还是 ' '？
std::collate<char>::compare(...)           // 校勘：'ä' 与 'z' 谁大依语言
```

- 16.1 的字符编码铺垫（多字节 vs 宽字符、UTF 在 wchar_t(16/32) 平台的尴尬）是全书理解 Unicode 困境的入口。
- facet 只读不可变、按 id 索引、引用计数回收——16.4 的细究解释「为什么 `use_facet` 不抛也要检查」。
- 16.4.2/16.4.3 的货币与时间格式化演示了标准 I/O 国际化能力的**广度与难用度**成正比。

### 2. 随机数两层架构（17.1）

- **引擎**（17.1.2）：`minstd_rand0`（LCG）、`mt19937/mt19937_64`（梅森旋转，状态大、质量好）、
  `ranlux24/48`（减时滞，统计更净、更慢）；`seed()/discard()/operator==`（可重放！测试利器）。
- **分布**（17.1.4）：`uniform_int`（闭区间！）、`uniform_real`（半开 [0,1)）、`normal/poisson/bernoulli/binomial`。
- **正确姿势**：引擎是**有状态发生器**，一个线程一个（或加锁），不要每次调用现造：

```cpp
thread_local std::mt19937_64 eng{std::random_device{}()};  // 播种一次
std::uniform_int_distribution<> die(1, 6);
int roll = die(eng);            // 🔧 已实测 g++ 15.2：shuffle 亦以 mt19937(42) 播种可重放
```

`random_device` 可能是真随机也可能又是伪随机（实现定义），**不要**把它当循环内熵源。

### 3. 并发阶梯（18.1–18.6）

```text
阶梯          接口                                    心智负担
任务级   async(lambda)→future    ◄── 最省：结果即异常即值（18.1 的 rethrow 机制接 01 站）
手动任务 promise/packaged_task   ◄── 线程与结果通道自己接线
线程级   std::thread             ◄── join 纪律；参数拷贝进新线程（引用须 std::ref）
同步     mutex+lock_guard/unique_lock/condition_variable/atomic
```

- 18.4「当心 Concurrency」用无保护共享 `stack` 的双线程事故给出 **data race** 的直觉定义，
  随后 18.5/18.7 分别给锁与原子两条解法——本节是全书对「为什么语言层面需要内存模型」最平实的解释。
- `condition_variable::wait(lk, pred)` 双检循环被封装；忘谓词 = 虚假唤醒 bug。
- `atomic`（18.7）三级接口：运算符族 / `fetch_*`/CAS / C 风格自由函数 + 底层 `atomic_*`（address 版）；
  默认 seq_cst，性能敏感处再谈 acquire/release（深水区转介并发笔记，见「联系」）。

### 4. 分配器（19 章 + 8.10）

C++11 时代接口的核心矛盾：容器**类型**含分配器（`vector<T, MyAlloc>`）→ 接口不兼容爆炸；
rebind 机制、`allocator_traits`（C++11 已引入，作为「可选成员补齐 + 转发」的适配层）、
`scoped_allocator_adaptor`（嵌套容器传播）三件套是 19.2–19.3 的主线。
19.1 给应用开发者的结论是实用的：**没有明确理由不写自定义分配器**。

## 权衡与相邻概念对比

- **async(deferred) 的暗坑**：`launch::deferred` 任务**在调用 get() 的线程上同步执行**——
  「等两个任务」（18.1.2 实例）时若系统判定 deferred，`wait_for` 会永远阻塞（它从不运行）而不是超时；
  需要真异步请显式 `launch::async`。
- **lock_guard vs unique_lock**：前者零开销不能转手/延迟；后者配 condition_variable（要 unlock/relock）、
  try_lock、move 转所有权。默认 lock_guard，需要才升级。
- **mutex vs atomic**：单字更新 → atomic 快；多变量不变式 → 必须锁（atomic 组之间没有事务）。
- **valarray vs vector+算法**：17.4 的切片语法是「表达式模板」的历史标本（📄 同期思想见
  [../C++模板元编程.md](../C++模板元编程.md)）；现代数值线是 mdspan（C++23）/第三方（Eigen）。
- **locale vs ICU/自写**：16 章能力全但 API 古老、 facet 派生样板厚重；工业界文本国际化普遍走 ICU/gettext 系 ⚠️。

## 最新演进与工业实践

- **C++14**：`shared_timed_mutex`（带超时的读写锁 ⚠️ 提案号未核，N3710 常被引用）；
  `std::integer_sequence` 等 traits 小件补齐。
- **C++17**：`shared_mutex`（轻量版读写锁）；`scoped_allocator_adaptor` 完善；`std::execution` 并行策略
  进入**算法层**（07 站）——并发从「手写线程」迈向「声明执行场所」。
- **C++20**：`std::jthread`（自动 join + stop_token 协作取消）、`latch/barrier/semaphore`（C 族同步原语标准化）；
  `atomic_ref`（P0883R2，已核——对既有非原子对象挂原子视图）；`atomic<shared_ptr>` 特化。
- **C++23**：`std::mdspan`（P2630R4/P0009R14 谱系，已核——非拥有多维视图，BLAS/图像世界的 `string_view`）；
  `expected`（错误处理的第四轨，与 01 站「异常 vs 错误码」之争呼应）；`std::print`。
- **C++26 在途**：`std::execution` sender/receiver（P2300R3，已核）、`at_scope_exit`（P2675R1，已核）、
  `hazard_pointer`/`atomic_shared` 无锁件。分配器改革：C++20 `allocator` 概念收紧、
  C++23 统一分配器构造参数（`allocator_arg` 弱化）⚠️ 具体提案号未逐一核实。
- **工业实践**：
  - 内存池/ arenas：`std::pmr`（C++17，`polymorphic_allocator` + `memory_resource`，**本书之后**的分配器革命——
    把分配器从类型参数移到运行时对象，`pmr::vector<T>` 类型统一）；容器选型请优先 pmr 而非手写 allocator。
  - 并发数据结构与内存序深水区：Anthony Williams《C++ 并发编程实战（第 2 版）》整本专治此处，
    本目录只在 18 章范围给地图（链接见下）。
  - 随机数可重放测试（seed 固定 + 引擎序列化）是仿真/RL 环境的标准做法。
  - 查证：[cppreference concurrency](https://en.cppreference.com/w/cpp/thread)、libstdc++/libc++ 的
    `testsuite`（[gcc-mirror/gcc](https://github.com/gcc-mirror/gcc)、[llvm/llvm-project](https://github.com/llvm/llvm-project)）。
