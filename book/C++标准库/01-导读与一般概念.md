## 核心概念速览（中英对照）

- **一致性初始化** — Uniform Initialization：`int i{42};`、`vector<int> v{1,2,3};`——统一花括号形态，且能挡窄化。
- **初值列** — Initializer List：`std::initializer_list<T>` 类型，让任何容器/对象都能用列表字面量构造。
- **类型自动推导** — Type Deduction (auto / decltype)：auto 按初始化式推类型，decltype 按表达式推声明类型。
- **域化枚举** — Scoped Enumeration：`enum class Color : uint8_t`——不隐式转 int、枚举名不倾泻到外层作用域。
- **大 O 复杂度标记** — Big-O Notation：标准库用常数/对数/线性/线性对数四类承诺每个操作的成本上界。
- **异常类层次** — Exception Hierarchy：`std::exception` 为根，`logic_error` 与 `runtime_error` 两大分支。
- **异常指针** — exception_ptr：把「正在传播的异常」捕获成可存储、可跨线程重抛的句柄。
- **可调用体** — Callable：函数指针、函数对象、lambda、`std::function`、`reference_wrapper` 的统称。
- **命名空间 std** — Namespace std：所有标准组件的家；对 std 类型使用时的 ADL 使它常常「不写限定也能找到」。
- **分配器（概念层）** — Allocator：容器内存获取/释放的策略插槽，第 4 章只给概念，第 19 章才展开。

## 动机：为什么一本「参考书」要花 40 页讲语言

Josuttis 的读者画像是在 C++98 代码库里挣扎的老手：第 2 版引入 C++11 后，**库的很多新能力其实是语言能力的投影**——
没有 move 语义就没有 `vector` 的廉价扩容搬运，没有 `initializer_list` 就没有 `push_back({a,b})` 这类接口，
没有 lambda 则每个算法都要配一个 functor。所以第 3 章把 auto/uniform-init/range-for/move/noexcept/constexpr/lambda
逐个过一遍（📄 小节清单见 [../C++标准库.md](../C++标准库.md) 目录 3.1.1–3.1.14），
为的是后文「库在哪受益」。读法建议：熟 C++11 者可只翻 3.1.3（一致性初始化）与 3.1.5（move）两节。

## 机制

### 1. 头文件的三套家族（4.2 节）

```text
<cmath> 风格   ：C 头文件 + c 前缀去 .h，内容置于 std（<cmath> vs 遗留 <math.h>）
无扩展名风格   ：标准 C++ 组件 <vector> <algorithm> <memory>
组件后缀       ：<iostream> <fstream> <sstream>；<system_error> 等 C++11 新增
关键差异       ：<xxx> 保证 std:: 限定名；<xxx.h> 同时污染全局名——新代码只用前者。
```

### 2. 复杂度语言（2.2 节）

| 类别 | 记号 | 典型操作 |
| --- | --- | --- |
| 常数 | O(1) | `push_back`(摊销)、`size`、`std::swap`、随机访问 `[]` |
| 对数 | O(log n) | `map/set` 的 find/insert/erase（红黑树高度） |
| 线性 | O(n) | `vector::insert(中间)`、`find`、`copy`、`list::size`（C++11 起 O(1)，见 04） |
| 线性对数 | O(n log n) | `sort`、`make_heap` 归并族 |
| 二次 | O(S×N) / O(n²) | `search` 朴素匹配最坏情形（书中给「子序列长 S、容器长 N」的乘积上界）；对前向迭代器套朴素查找 |

标准承诺的是**上界**，实现可以更快（如 introsort 遇近乎有序仍承诺 O(n log n)）。

### 3. 异常类层次与使用约定（4.3 节）

```text
                 exception
          ┌─────────┴──────────┐
      logic_error          runtime_error
   domain_error           overflow_error / underflow_error
   invalid_argument       range_error
   length_error           system_error(C++11) / ios_base::failure
   out_of_range           timeout_error / filesystem_error(C++17,本书无 ⚠️)
```

- 标准库组件**只**抛上面这些（容器越界 `at()` 抛 `out_of_range`，分配失败抛 `bad_alloc`）。
- `what()` 返回实现定义的字符串，跨分支唯一可用的接口；**不要依赖其内容**。
- 4.3.3 的 `exception_ptr`：`current_exception()` 捕获 → 存入 → `rethrow_exception()` 在另一线程重演，
  是 `std::future` 把后台异常搬回 `get()` 处的底层通道（见 [10-国际化数值并发与分配器.md](10-国际化数值并发与分配器.md)）。
- 🔧 已实测 g++ 15.2：

```cpp
try { std::vector<int> v; v.at(5); }
catch (const std::out_of_range& e) { std::cout << e.what(); }   // "vector::_M_range_check: ..."
std::exception_ptr p = std::make_exception_ptr(std::runtime_error("boom"));
try { std::rethrow_exception(p); } catch (const std::exception& e) { /* "boom" */ }
```

顺带的现代注脚：`at()` 在 C++20 起标了 `[[nodiscard]]`——忽略返回值会收到警告，本书时代没有这约定 ⚠️。

### 4. Callable 的五种形态（4.4 节）

| 形态 | 携带状态 | 可内联 | 类型可拼写 |
| --- | --- | --- | --- |
| 函数指针 | 无 | 间接调用 | 是 |
| 函数对象 | 成员即状态 | ✅（模板参数下通常内联） | 是 |
| lambda | 闭包捕获 | ✅（类型匿名） | 否（ decltype 可） |
| `std::function` | 类型擦除堆存储 | ❌（间接+可能分配） | 是 |
| `reference_wrapper` | 引用转发 | ✅ | 是 |

这张表是第 6 站（函数对象与 lambda）的地基，也是「性能敏感回调为什么忌 `std::function`」的第一次答案。

## 相邻概念对比

- **`auto` vs `decltype`**：`auto x = v[0]` 丢引用与顶层 const；`decltype(auto)`（C++14）全保留——转发返回值的钥匙。
- **`noexcept` vs 动态异常规范**：C++98 的 `throw()` 是运行时检查（`unexpected`  terminate），
  `noexcept` 是编译期契约且参与重载解析/`is_nothrow_*` 萃取；后者胜，前者 C++17 移除、C++20 彻底废弃 ⚠️。
- **标准异常 vs 自定义异常**：4.3.5 建议从标准异常派生（保持 `what()` 接口 + 捕获兼容），而非另起 root。

## 最新演进与工业实践（C++14–C++26 对本站的增补）

- **C++14**：泛型 lambda（`[](auto a, auto b)`)、`decltype(auto)`、单引号数字分隔符 `1'000'000`。
- **C++17**：内联变量（头文件定义 ODR 问题的解药）、`std::byte`（`<cstddef>` 家族扩展）、
  折叠表达式（可变参模板样板大减）、动态异常规范彻底移除；`std::source_location` 属 C++20
  （P1208R6，提案存在已核 wg21.link 302）。
- **C++20**：concepts（P0898R3，已核）把「SFINAE 脚手架」升级为可声明的约束——本书 5.4 时代所有
  `enable_if` 花招的现代归宿；`ranges` 让「迭代器对」协议退居二线（见 [05-迭代器.md](05-迭代器.md)）。
- **C++23**：`std::expected<T,E>`（配合 `std::unexpected`，把「可失败值」拉进错误处理第二轨）、
  `static_call`/`hazard_pointer` 等库设施继续蚕食手写技巧；`deducing this` 让「在 lambda 里递归」有了无分配写法 ⚠️ 提案号未核。
- **工业实践**：Google C++ Style 与 Core Guidelines 均建议——错误要么异常要么 expected，别混用两套；
  库边界（`.so`/DLL）上避免抛标准异常跨模块（ABI 脆弱），用错误码或 `expected` 出口。
  参见 [../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md)、[../C++API设计.md](../C++API设计.md)。
