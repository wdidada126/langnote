# 第 2 站 · 通用工具与智能指针（原书第 5 章）

> 覆盖原书第 5 章「通用工具」全部 8 节：pair/tuple、智能指针、numeric_limits、
> type trait 与 type utility、辅助函数（min/max/swap）、ratio、chrono、`<cstddef>`/`<cstdlib>`/`<cstring>`。
> 这是 STL 之外的「零件抽屉」：智能指针是其中最重要的两件，值得单独精读。

## 核心概念速览（中英对照）

- **值组** — Pair / Tuple：pair 是二元素值组（map 节点的砖），tuple 是其编译期长度的推广。
- **共享指针** — shared_ptr：引用计数共享所有权；拷贝廉价（计数++），控制块决定生死。
- **弱指针** — weak_ptr：不拥有、可升格（lock/expired）的观察把手，破循环引用与做对象缓存。
- **独占指针** — unique_ptr：零开销独占所有权；不可拷贝只可移动，删除器编译期进类型。
- **别名构造** — Aliasing Constructor：`shared_ptr<T>(other, ptr)`——共享寿命、指向他物，C++11 指向成员的替代。
- **使能共享** — enable_shared_from_this：让对象安全产出指向自身的 shared_ptr（否则双重控制块）。
- **数值极限** — numeric_limits：每标量类型的编译期属性袋（digits/epsilon/quiet_NaN/is_signed）。
- **类型萃取** — Type Traits：`is_*`/`has_*`（未进标准）/`*_cast` 家族的编译期内省；`enable_if` 是分发开关。
- **引用外覆器** — reference_wrapper / `std::ref`：唯一能进容器的「引用替身」，也是 tuple 输出的把手。
- **函数外覆器** — std::function：可调用体的类型擦除容器，运行时灵活但付间接与堆的代价。
- **编译期分数** — ratio：`ratio<3600>` 之类精确有理数，chrono 单位体系的地基。
- **时间段/时间点/时钟** — duration / timepoint / clock：chrono 三件套；steady_clock 单调、system_clock 对表。

## 动机：裸 new 的三个不可调和矛盾 → 三种所有权回答

裸指针同时宣称「我拥有、我非空、我能穿透边界」，三条都常是谎言。C++11 标准库的解法是把三件事拆开：
**所有权**交给 `unique_ptr`（默认）/`shared_ptr`（确需共享时），**非空**交给引用与 not_null 思想（标准外，见演进节），
**穿透边界**交给裸指针——降级为「观察」语义。原书 5.2 用五小节（shared/weak/误用/细究/unique）铺这件事，
「误用」一节（5.2.3）列举的坑（同一裸指针构造两个 shared_ptr、vector<shared_ptr> 的间接泄漏）至今仍是代码评审高频项。

## 机制

### 1. shared_ptr 的控制块经济学

```text
make_shared<T>() : 1 次堆分配（对象 + 控制块[强计数|弱计数|删除器|分配器] 同块）
new T + shared_ptr<T>(p): 2 次堆分配，但 weak_ptr 释放后对象可提前死
共享语义        : 拷贝只 ++强计数（原子操作）；归零 → 调删除器 → 若弱计数也为零才释放内存
线程安全边界    : 控制块操作线程安全；指向的对象本身 NOT —— 与任何共享对象同规则
```

🔧 已实测 g++ 15.2——循环引用导致两者皆不析构：

```cpp
struct Node { std::shared_ptr<Node> next; ~Node(){ std::puts("~Node"); } };
auto a = std::make_shared<Node>(); auto b = std::make_shared<Node>();
a->next = b; b->next = a;   // 程序结束也不打印 ~Node（实测无输出；use_count==2）
```

破法即 `weak_ptr`：`next` 声明为 `weak_ptr<Node>`，用时 `lock()` 升格，`expired()` 只能作为
「无竞态判断」的演示（检查与升格之间可被其他线程插队），生产一律直接 `lock()` 后判空。

### 2. unique_ptr 的删除器为什么进类型

```cpp
std::unique_ptr<FILE, int(*)(FILE*)> f(std::fopen("x","r"), &std::fclose); // 函数指针版：+8B，运行时
struct FCloser { void operator()(FILE* p) const { std::fclose(p); } };
std::unique_ptr<FILE, FCloser> g(...);   // 空类版本：EBO 后与裸指针同尺寸、可 noexcept
```

对比 shared_ptr：删除器存在控制块里（类型不变、擦除）。unique_ptr 无控制块，删除器只能进模板参数——
这就是 5.2.6「细究」里 `default_delete` 的全部存在理由。**默认场景永远先选 unique_ptr**，
工厂返回值 + `std::move` 出作用域即毁，零额外空间与时间。

### 3. tuple 与其邻居们

- `std::tie(a,b,c) = m.emplace(k,v)`：接收 pair 而不构造中间量（emplace 返回 `pair<iterator,bool>`）。
- `tuple` 的 I/O 不存在（5.1.3 演示的是手工展开）——这是 C++23 `operator<<` for tuple 缺席的前史 ⚠️。
- 多返回值惯用法：`if (auto [it, ok] = s.insert(v); ok)`（C++17 结构化绑定，本书时代用 tie）。

### 4. chrono 的单位安全

```cpp
using namespace std::chrono;
auto d1 = 2s + 100ms;                  // 混合单位自动通分到 ms，编译期完成
auto t0 = steady_clock::now();  work(); auto dt = t0 - steady_clock::now();
auto ms = duration_cast<milliseconds>(dt);   // 显式收窄，防隐式窄化
```

`duration<double, ratio<1,60>>` 展示 ratio 作为分母可表达「非整数倍秒」；
`high_resolution_clock` 只是两者之一的别名（实现定义），**不要**在跨平台代码里当第三种时钟。

## 权衡与选型

| 需求 | 选 | 不选 | 理由 |
| --- | --- | --- | --- |
| 单一所有者、离开作用域即毁 | unique_ptr | shared_ptr | 零开销；共享是设计气味 |
| 对象生命周期跨线程/跨容器不确定 | shared_ptr | 裸 new | 计数原子；但对象仍需另行加锁 |
| 观察者/父引用/缓存 | weak_ptr | shared_ptr | 破环；`lock()` 语义 = 「还活着吗」 |
| 回调注册但怕对象已死 | weak_ptr 升格 | 悬垂 this 捕获 | lambda 捕获 `wp = weak_from_this()`（C++17） |
| 可调用体要存进成员/容器 | std::function | 模板参数 | 类型可拼写；付间接+可能堆分配 |
| 热循环里传给算法 | lambda/函数对象 | std::function | 可内联；本书 10.1 的实测精神 |

## 相邻概念对比

- **`std::function` vs 函数模板参数**：前者一次类型擦除处处可用（回调表、异步任务签名），后者全静态分发。
- **`numeric_limits::max()` vs `<climits>` 宏**：模板化、逐类型、带 `is_specialized` 自查；宏无符号/浮点盲区。
- **`std::ref` vs 直接捕获**：把对象塞进 `std::function`/`bind`/tuple 时想按引用共享，必须 `std::ref` 包一层，
  否则拷贝进目标——本书 5.4.3 与 10.2.3 两处呼应。
- **type traits vs concepts**：`enable_if_t<is_integral_v<T>>` 的报错是「候选列表为空」天书；
  C++20 `integral auto` 一句顶三句（P0898R3，已核）。

## 最新演进与工业实践

- **C++14**：`make_unique`（补 C++11 漏掉的对称件）；自定义字面量 `14h`、`5min` 进 chrono（`literals::chrono_literals`）。
- **C++17**：`weak_ptr::owner_before` 之外的利器 `std::weak_from_this()`；
  `std::optional`（C++17 由多份提案合并进标准 ⚠️ 单一提案号未核）——值语义「可空」替代 shared_ptr 当可选返回；
  `std::variant`（P0088R3，已核）与 `std::any`（P0393R3，已核）补全「无继承多态三件套」；
  `std::byte`；**`auto_ptr` 移除**——本书 5.2.7 整节自此只具史料价值。
- **C++20**：`std::to_address`（萃取智能指针的裸地址，写分配器/容器必备）；
  `atomic<shared_ptr>`/`atomic<weak_ptr>` 特化加入；`is_integral_v` 等全套 `_v` 变量简化 traits 书写。
- **C++23/26**：`expected<T,E>`（C++23）与 optional 单体操作链 `and_then/or_else/transform`（P0798R8，已核）；
  C++26 计划引入 `std::inplace_ptr` 与 `weak_ptr::observe()` ⚠️（提案号未核实，只记标题与目标版次）。
- **工业实践**：
  - Microsoft GSL / abseil 的 `not_null<T>`、`AnyInvoke` 等证明「工具抽屉」是库文化的载体：
    [abseil 仓库](https://github.com/abseil/abseil-cpp) 的 `absl::Mutex`、`Cleanup`（即 `std::experimental::scope_exit` 前身）
    对应本书「没有但需要」的件；C++26 的 `at_scope_exit`（P2675R1，已核）终于标准化 Cleanup 思想。
  - libstdc++/libc++ 测试套件是 traits 行为的第一手裁判：[llvm/llvm-project](https://github.com/llvm/llvm-project)（libc++ 在 `libcxx/`）、
    [gcc 镜像](https://github.com/gcc-mirror/gcc)（`libstdc++-v3/`）。
  - 回调性能：热路径用模板参数或 `function_ref`（非标准；llvm::function_ref、folly::Function 是工业替身），
    `std::function` 只在类型必须可拼写处使用——EMC++ 条款 21 立场（📄 [../Effective_Modern_C++.md](../Effective_Modern_C++.md)）。
