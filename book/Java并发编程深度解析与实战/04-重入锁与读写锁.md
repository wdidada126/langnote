# 第 4 章 深入浅出分析 J.U.C 中的重入锁和读写锁

> `ReentrantLock`（AQS 独占、`state`=重入次数、CLH 排队）、`ReentrantReadWriteLock`（AQS 共享/`state` 高 16 位读计数 + 低 16 位写计数）、公平/非公平、与 `synchronized` 对比。本书重「AQS state 如何编码两类锁」。详见方腾飞《艺术》5 章、之美 06 章、之美 concepts/AQS抽象同步队列.md。

## 一、核心精讲

### 2.1 🔧 state 编码
- `ReentrantLock`：`state` 记重入次数（0=无主，>0=owner 重入 N 次）。
- `ReentrantReadWriteLock`：`state` 32 位拆高 16（读持有计数，含每个线程 `HoldCounter`）低 16（写重入）（🔧 CAS 同时改两部分，巧妙但「写饥饿」潜在）。

### 2.2 公平 vs 非公平
- 非公平：抢锁直接 CAS，易饿死但吞吐高（默认）；公平：严格 FIFO（🔧 非公平在「刚释放又被抢」场景下吞吐更高，但长任务可能饿）。

### 2.3 读写锁写饥饿
- 读多写少时读不停，写长期等（🔧 用 `StampedLock` 乐观读替代；见之美 06 章、高并发核心编程 concepts/JUC显式锁）。
