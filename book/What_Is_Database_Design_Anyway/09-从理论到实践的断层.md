## 讲解精要

### 9.1 断层体检：SQL 偏离模型清单（🔧 逐条实测，SQLite 3.45.3 / DuckDB 1.5.5，均**非本书引擎**）

| 偏离 | 模型要求 | 现实 | 🔧 取证（EX6 系） |
| --- | --- | --- | --- |
| 重复元组 | 集合无重复 | 包语义默认放行 | 同值两行连插，`COUNT(*)=2` ✅ |
| 列序 | 标题是无序集合 | 左到右真实存在 | `PRAGMA table_info` 返回 `['c2','c1']` ✅ |
| NULL/3VL | 两值逻辑+缺失值类型 |  UNKNOWN 渗入布尔代数 | `c2=1 OR NOT c2=1` 不排除任何行、也匹配不到含 UNKNOWN 比较的行（2:2 打印）✅ |
| 断言 | 数据库层全称约束 | 无 `CREATE ASSERTION` | `near "ASSERTION": syntax error` ✅（[06 章](06-约束是设计的一部分.md) EX3） |
| 会话级完整性 | 约束无条件 | FK 随 pragma 开合 | `foreign_keys=(0,)` 默认 ✅ |
| 关系值属性 | 1NF 争论的另一侧 | 嵌套以 LIST/STRUCT 复活 | `INTEGER[]` 存 `[2,3]` 成功——但非关系语义封闭（[03 章](03-关系与关系变量的地基.md) 3.4/文末）✅ |
| 序的滥用 | 无位置语义 | DuckDB `ORDER BY` 入 CTAS 结果保留 `(4,3,2,1,0)`（观测登记，不推断标准行为 ⚠️） | ✅ 实测 |

（判语总纲盘上已有：#12 14 章"SQL 只在它不偏离模型时才是关系型的"；本表是其在 2026 轻量引擎上的体检单。）

### 9.2 断层为什么修不平（立场重构 ⚠️）

1. **兼容性重力**：SQL 的每一处偏离都养着存量代码；改正=破坏（UNIQUE-NULL 之争三十年无解，[04 章](04-码是意义而不是习惯.md) 🔧）。
2. **教学回路**：工程师从产品文档学 SQL，不从模型学——偏离被当作"数据库的样子"代际传递。
3. **工具的中间层缺位**：#8/#12 的 Tutorial D 无产业载体；断层两侧各说各话。
4. **设计科学的缺席**：即使全员改用"正确 SQL"，[02 章](02-设计就是谓词的决定.md) 的谓词决定仍是手工艺——题面文章真正瞄的是这个。

### 9.3 "更多科学"长什么样（Date 纲领的重构 ⚠️）

- 输入：业务规律的自然语言陈述（可审计）；输出：谓词清单 + 依赖集 + 验收测试；
- 每一步须**可反驳**：谓词错了要能被业务反例证伪（比"图好不好看"科学）；
- 与相邻学科的接壤：需求工程（谓词从哪来）、物理设计（何时消费冗余，[08 章](08-反规范化的正确位置.md)）、
  数据治理（断言归谁维持，[06 章](06-约束是设计的一部分.md)）。
- 学院侧最接近的成体系替代：逻辑设计+ER 验证线（[../Database_Modeling_and_Design_5e/00-总览与阅读地图.md](../Database_Modeling_and_Design_5e/00-总览与阅读地图.md)）与
  教材总纲（[../数据库系统概念6/08-关系数据库设计.md](../数据库系统概念6/08-关系数据库设计.md)）；本目录判其"算法强、目的论弱"（[02 章](02-设计就是谓词的决定.md) 2.4）。

### 9.6 断层观察的一行复现命令（读者自测版）

```bash
python -c "import sqlite3;c=sqlite3.connect(':memory:');print(c.execute('PRAGMA foreign_keys').fetchone())"   # → (0,)：完整性会话开关
python -c "import sqlite3;c=sqlite3.connect(':memory:');c.execute('CREATE TABLE k(u TEXT UNIQUE)');c.execute('INSERT INTO k VALUES(NULL)');c.execute('INSERT INTO k VALUES(NULL)');print(c.execute('SELECT COUNT(*) FROM k').fetchone())"   # → (2,)：UNIQUE 放双 NULL
```

两行跑完，9.2 第 1 条"兼容性重力"就不再是修辞——这是本册把理论钉回可观测现实的最后一公里。

## 常见误区

1. **"断层=SQL 全错"**：偏离是可列清单的局部（9.1 表），日常用法里大量语句与模型兼容；清单的意义是**知道边界在哪**。
2. **"换语言=换设计"**：Tutorial D 也救不了坏谓词（[02 章](02-设计就是谓词的决定.md)）；语言断层与设计科学缺席是两个病（9.2/9.3）。
3. **"理论派不懂工程"**：EX5 类交易（[08 章](08-反规范化的正确位置.md)）表明理论给的是**交易合法性判据**，不是禁令。
4. **"本册是入门鸡汤"**：它钉住的是三本教科书共同缺席的目的层——题面文放在母书收尾正因此 ⚠️。

## 核心概念速览（中英对照）

1. **偏离清单** — deviation list：SQL 对关系模型不忠诚点的枚举（9.1 表）。
2. **兼容性重力** — backward-compatibility gravity：错误难以改正的产业力学。
3. **三值逻辑** — three-valued logic (3VL)：TRUE/FALSE/UNKNOWN；比较传染布尔代数（🔧 EX6）。
4. **包语义** — bag semantics：允许重复行的 SQL 默认宇宙（🔧 重复行实测）。
5. **设计科学** — design science (the missing one)：从业务规律到谓词清单的可教可检程序（9.3）。
6. **可反驳性** — falsifiability：谓词陈述须能被业务反例证伪。
7. **目的论层** — teleological layer：三本教科书共缺、题面文独钉的一层（9.4）。
8. **验收测试** — acceptance test：无损性/断言/谓词计数的工程化载体（05/06/07 章 🔧 系）。
9. **Tutorial D** — 教学语言：模型正统的载体，无产业部署（⚠️ 本机不可运行，全册声明）。
10. **ETNF/DKNF** — 高阶范式：理论前沿与产品现实的时差样本（[../Database_Design_and_Relational_Theory/13-额外的范式.md](../Database_Design_and_Relational_Theory/13-额外的范式.md)）。
11. **多模型共存** — multi-model：断层外的新世界；谓词观照常适用（9.3 接壤）。
12. **闭域事故** — CWA accident：不在⇒断假的设计侧病根（02/03 章总回指）。
