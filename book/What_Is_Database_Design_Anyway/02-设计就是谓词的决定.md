## 本章定位与取证依据

题面文章（[01 章](01-同名文章与本书定位.md)）若只留一个论点，就是这个：**数据库设计的全部自由，都在于你决定让数据库断言哪些命题；
其余一切（表、列、范式、索引）都是这个决定的推论。** 本章把该论点重构为可操作的论证。

## 讲解精要

### 2.1 谓词、命题、以及"数据库会说谎"的确切含义

- **谓词（predicate）**是含自由变量的陈述开语句，如 `s 是位于城市 c 的供应商`；把变量代入具体值后成为**命题（proposition）**，有真假。
- 一个关系变量（relvar）在 Date 体系里 = 一个谓词的**外延扩展**：某时刻关系中存在的每个元组，都被数据库断言为该命题为真；
  不在关系中的元组，在闭域假设下被断言为假。⚠️（教程口径见 [../Relational_Theory_for_Computer_Professionals/02-关系和关系变量.md](../Relational_Theory_for_Computer_Professionals/02-关系和关系变量.md)）。
- **"数据库自己发明事实"**（ghost tuple）= 数据库断言了设计者本意之外的命题。两条经典发生路径：
  1. 有损分解重连接造出幽灵元组（🔧 EX2：3 元组分解重连成 4，幽灵 `(s2,p1,10)` 是本机可复现的"发明"，见 [05 章](05-规范化是为真理而分解.md)）；
  2. 一个 relvar 混装多个谓词，NULL 占位元组让"某供应事实存在"被错误断言（🔧 EX4，见 [07 章](07-正交性与冗余的两面.md)）。
- 因此**设计正确性 = 谓词清单正确性**，范式只是维持它的机器（[05](05-规范化是为真理而分解.md)/[06](06-约束是设计的一部分.md) 章）。

### 2.2 从谓词到关系变量：设计工作的正典流程

⚠️ Date 各书未给过统一编号流程，下述综合自 #8/#12 的章序（各自盘上可查）：

1. **收集并写下谓词**（自然语言，含业务真值条件）——这一步在多数方法论里根本不存在，ER 法从"实体"开始 ⚠️，对位批判见 [../Database_Modeling_and_Design_5e/00-总览与阅读地图.md](../Database_Modeling_and_Design_5e/00-总览与阅读地图.md)（该派把语义负担放在图形约定上）。
2. **一个谓词 → 一个 relvar**（正交原则，[07 章](07-正交性与冗余的两面.md)）。
3. **由谓词的逻辑结构读出依赖**：`供应商号 → 所在城市` 单值化，就是 FD；谓词里的等词/存在量词模式就是 JD/MVD 的源头 ⚠️（机器细节在 [../Database_Design_and_Relational_Theory/04-函数依赖与BCNF非正式.md](../Database_Design_and_Relational_Theory/04-函数依赖与BCNF非正式.md) 与 09–12 章）。
4. **依赖转成约束声明**（[06 章](06-约束是设计的一部分.md)）——不能停留在"约定"。
5. **验证无损**（[05 章](05-规范化是为真理而分解.md) 🔧 EX2 口径）。

### 2.3 "唯一权威"论：什么不算设计输入

- 用户界面、报表布局、对象类的属性表、框架的表名复数规则——都不是谓词来源 ⚠️。
- Date 反复强调的一点（SRT/04 盘上可查）：**「供应商有且只有一个状态」不是谓词，是约束；谓词是「存在供应商 s 具有状态 p」**——
  前者是模态断言，后者才是 relvar 的语义。混淆这两者导致"把约束写进注释"的普遍事故（[06 章](06-约束是设计的一部分.md)）。

### 2.4 本册立场 vs 教材立场（为什么学院派不这么说）

- 教材口径（[../数据库系统概念6/08-关系数据库设计.md](../数据库系统概念6/08-关系数据库设计.md)）把规范化讲成**分解算法 + 依赖演算**，
  谓词理论几乎缺席；Date 的批判（⚠️ 一贯立场）：算法只能保证"分解不丢数据"，不能保证"合起来的 relvar 说的是同一件事"——
  后者恰是设计的全部问题所在。
- 两派并不冲突在定理层，冲突在**目的层**：学院派以 BCNF 为终点，Date 以"数据库只说出真命题"为终点。题面文章的 Anyway 就落在这里。

## 谓词清单工作模板（本目录对 2.2 流程的落地件）

⚠️ 编辑自拟的操作件（非原书物），与 #8/#12 的机器衔接使用：

| 栏 | 填法 | 反例（当场退回） |
| --- | --- | --- |
| 谓词陈述 | 「存在⟨参量列表⟩使得⟨业务关系⟩」一句自然语言 | 句子里出现"表/字段/系统"——层级混入 |
| 真值判据 | 业务上谁能证实/证伪这条陈述 | "数据里没见到反例"——采样≠必然（[04 章](04-码是意义而不是习惯.md) 4.2） |
| 参量类型 | 每参量对应属性+域 | 类型栏空着——地基塌（[03 章](03-关系与关系变量的地基.md) 3.2） |
| 决定关系 | 哪些参量单值决定哪些 | 全箭头交叉成网——依赖混装候选（[05 章](05-规范化是为真理而分解.md)） |
| 否定形态 | 该陈述为假时数据库如何表达 | 只能靠 NULL 表达——CWA 事故入口（2.1） |
| 验收测试 | 一条能证伪该谓词的构造数据 | 写不出测试——谓词没定清（[09 章](09-从理论到实践的断层.md) 9.3 可反驳性） |

**模板用法**：一 relvar 一张卡；卡间引用（外码）在"决定关系"栏成对登记，汇入 [06 章](06-约束是设计的一部分.md) 的约束清单。
评审会即逐卡过"真值判据"一栏——把 9.2 的手工艺至少变成**可审计**的手工艺。

### 2.5 三个高频误置谓词（现场教学样本 ⚠️）

1. **"用户表"**：`存在用户 u` 几乎从不是一级谓词——真谓词是「存在账号 a 由自然人 n 在 t 时开立…」；
   以"实体名词"为 relvar 是 ER 惯性，谓词层会漏掉时态与角色（同一个人既是申请人又审批人=两谓词一实体）。
2. **"关联表"**：`S(pno, sno)` 被叫作"多对多中间表"——在谓词观下它是**一等事实**「供应关系存在」，
   没有任何从属地位；命名习惯反过来会诱使设计者不给它挂约束（[06 章](06-约束是设计的一部分.md)）。
3. **"配置表"**：`存在参数 k 取值 v` 把类型系统压成两列字符串——谓词本是「部署 D 的超时为 t」；
   KV 化的每一格都是放弃声明的一处设计（域缺失病，[03 章](03-关系与关系变量的地基.md) 3.4/3.2）。

### 2.6 谓词观的一句检验（编辑口诀 ⚠️）

拿到任何 schema，逐表问："这张表的**一行存在**，翻译成正文是哪句话？"
一句话⇔合格；两句话⇔拆（[07 章](07-正交性与冗余的两面.md)）；半句话（"这是明细表"）⇔谓词失踪；
需要指着别表才能补全句子⇔断言散落在应用层（[06 章](06-约束是设计的一部分.md)）。
题面文章若被压成一条可执行纪律，就是这句。

## 常见误区

1. **"谓词是学究气，能建表就行"**：🔧 EX1 的数字（一条事实 3 处冗余、UPDATE 触碰行数 3:1）说明谓词没定清时，代价以行数计量。
2. **把 ER 的"实体-关系"直接映射成表就当完成设计**：映射规则（1:N 外键化等）默认了谓词已被想清；跳过第 2.1 步的方法论把最难的 80% 藏进了"显然" ⚠️。
3. **一个 relvar 多个谓词 + NULL**：这不是"灵活"，是谓词污染；判定法：数一数你能对这个表说出的**存在性断言**有几种（🔧 EX4 的谓词计数）。
4. **把闭域假设当"数据库不知道"**：在 Date 体系里，元组不在 ⇒ 数据库**积极断言其假**，这不是无知识而是错误知识的入口（设计者以为它只说真话）。
5. **用列名当语义**：`is_paid` 存 NULL 时它既不真也不假（3VL），谓词从名字迁移到数据后即失真 ⚠️（[../SQL_and_Relational_Theory/06-NULL与三值逻辑3VL.md](../SQL_and_Relational_Theory/06-NULL与三值逻辑3VL.md)）。

## 核心概念速览（中英对照）

1. **谓词** — predicate：含自由变量的开语句；relvar 的语义身份。
2. **命题** — proposition：谓词的实例化，元组=数据库断言为真的命题。
3. **闭域假设** — closed-world assumption (CWA)：不在关系中 ⇒ 断言为假；设计事故的发生面。
4. **断言** — assert：数据库替设计者"说出"；设计的自由即决定说什么。
5. **幽灵元组** — ghost tuple：分解重连造出的非本意命题（🔧 EX2 实测 1 例）。
6. **谓词污染** — predicate mixing：一 relvar 承载多个存在性断言（🔧 EX4 计数法）。
7. **值与变量** — value vs. variable：关系是值、relvar 是变量；设计的载体是变量。
8. **单值化** — functional determination：谓词参量间函数依赖的语义来源。
9. **真值条件** — truth condition：元组为真的业务判据，验收设计的唯一凭据。
10. **外延** — extension：某时刻 relvar 取值（当前关系），随状态变化。
11. **约束≠谓词** — constraint vs. predicate：「唯一」是约束，「存在」才是谓词；层次不可混。
12. **设计权威** — design authority：只有业务真值能定谓词，界面/框架不能。
