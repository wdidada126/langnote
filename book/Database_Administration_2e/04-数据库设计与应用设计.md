## 3. 反规范化（Denormalization，p.160）

## 10. 事务设计审查十问（⚠️ 重构自检问句，对应 p.205–221 三节）

1. 一个事务是否恰好等于一个业务原子动作？
2. 事务内语句数与交互次数能否再削？
3. 是否含等待人类输入的挂点（表单/审批在事务外）？
4. 隔离级别是选的还是默认漂移的？异常（脏读/幻读）逐个排除过吗？
5. 热点行（计数/库存/账务日切）有无队列化或分片方案？
6. 锁升级/大表扫描会不会撞在线窗口（第 8 章 p.274 ✅ 问题族）？
7. 死锁预案：超时值、重试语义、幂等键？
8. 长事务对日志/回滚段的增长账算过吗（第 16/18 章 ⚠️ 联动推定）？
9. 批任务能否拆成可重放的小事务段？
10. 失败路径的补偿逻辑在应用侧还是数据侧，谁留痕？

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 物理设计 | Physical Database Design | 逻辑结构在具体引擎/存储上的落法 |
| 索引策略 | Index Strategy | 按访问路径系统规划索引的取舍框架 |
| 覆盖索引 | Covering Index | 包含查询全部列、免回表的索引 ⚠️ 通用术语转述 |
| 反规范化 | Denormalization | 受控冗余换性能的四手法族（派生/复制/提取/重定义） |
| 兼容视图 | Compatibility View | 以视图隔离结构变更对应用的影响 ⚠️ 推定用途 |
| 嵌入式 SQL | Embedded/Static SQL | 预编译进宿主程序的 SQL，可控性最高 |
| 动态 SQL | Dynamic SQL | 运行期构造的 SQL，灵活但难治理 |
| 存储过程 | Stored Procedure | 服务端编译的 SQL 过程，减少往返 |
| 事务边界 | Transaction Boundary | BEGIN/COMMIT 的划法，短事务原则 |
| 锁粒度/锁模式 | Lock Granularity / Mode | 行页表级与 S/X/U/意向锁的组合 |
| 死锁 | Deadlock | 循环等待，需侦测或超时破解 |
| 时态数据 | Temporal Data | 带有效时间/事务时间的历史数据形态 |

## 最新演进与工业实践

1. **反规范的现代替身是「物化+缓存+列存」**：2024–2026 的工程实践中，p.160 手法族大多不再手改表结构，而是交给
   物化视图/增量计算层与列存副本：PG 的物化视图与逻辑复制把派生数据搬出 OLTP 主表（PostgreSQL 文档
   https://www.postgresql.org/docs/current/sql-createtable.html 等 current 页均 curl 200 验证，⚠️ 转述用法边界）；
   湖仓侧由表格式承接，见 [../The_Data_Lakehouse/00-总览与阅读地图.md](../The_Data_Lakehouse/00-总览与阅读地图.md)。
2. **锁与事务：教科书地位不变**：隔离级别异常分类（ANSI 四级）在 DDIA 中获得更工程化的重述，对照
   [../设计数据密集型应用.md](../设计数据密集型应用.md)（存在已验证）；「短事务」纪律在连接池时代反而更严格 ⚠️ 转述。
3. **应用接口的位移**：嵌入式 SQL 边缘化，ORM/查询构建器成为默认——带来本书「可控性 vs 灵活性」论断的新形态：
   生成的 SQL 必须回炉审查（EXPLAIN 门禁），恰是第 12 章 Reviewing Access Paths（p.394 ✅）在 CI 里的复活 ⚠️ 转述。
4. **时态表落地**：SQL:2011 系统版本化语法进入 DB2/SQL Server 等实现，审计合规（第 15 章主题）是其最大买单方 ⚠️ 文档转述；
   本册未实测任何时态功能。
5. **波内已闭环**：[#11《Database Modeling and Design 5e》](../Database_Modeling_and_Design_5e/00-总览与阅读地图.md)、[#45《Efficient MySQL Performance》](../Efficient_MySQL_Performance/00-总览与阅读地图.md)（均落盘）分别接住本节 1/3 与 5/6 节的纵深，义务登记见 00。
