## 2. 备份（Backup，p.517）

本章第一大块（✅ 页 517–537，20 页）。类型学（⚠️ 重构为通行框架，与 TOC 篇幅吻合）：
1. **完整/增量/差分**：成本与恢复链条长度的权衡；
2. **冷备/热备（offline/online）**：一致性点获取——热备依赖日志序列与检查点机制 ⚠️ 文档转述；
3. **日志备份（事务日志归档）**：把 RPO 从「上次全备」压到「上次日志」的机制，也是时间点恢复（PITR）的燃料 ⚠️ 转述；
4. **对象级导出**（逻辑备份，与第 19 章 EXPORT/IMPORT p.622 ✅ 共用工具面）；
5. 备份窗口工程：并行度、介质带宽、与批处理窗口的错峰（回指第 5 章 p.221 ✅）。
- 验证与治理：备份的成功判定不是返回码而是**恢复试验**；保留策略与合规归档（第 15 章 p.498 ✅）分账管理 ⚠️ 推定。

## 3. 恢复（Recovery，p.537）

本章第二大块（✅ 页 537–554，17 页）。恢复目录（⚠️ 重构，机制描述一律文档转述）：
- **重启恢复**：实例崩溃后凭日志的前滚/回滚（与第 5/8 章日志、可用性小节联动 ✅）；
- **介质恢复**：还原+前滚，凭日志备份推进到任意检查点；
- **时间点恢复（PITR）**：日志序列上的精确回放——本书把它列为高级必备能力 ⚠️ 转述；
- **对象级恢复**：表空间/表粒度，避免为丢一行重放全库 ⚠️ 重构；
- **逻辑错误恢复之困**：用户误删不被日志视为「错误」，PITR 会连同误删一起重放——须靠延迟副本/闪回/备份池另解（下节 Alternatives 承接）⚠️ 转述，
  这是本章最常被引用的一节判断。
- 恢复决策树（⚠️ 推定编排）：损失范围 → 一致性目标 → 手段选择 → 时间核算——与第 8 章 Ensuring Availability（p.287 ✅）共用决策文化。

## 8. 恢复类型速查决策表（⚠️ 重构，对应 p.537–554；损失范围→手段映射）

| 故障形态 | 首选手段 | 时间尺度 | 前置条件 |
| --- | --- | --- | --- |
| 实例崩溃 | 重启恢复（日志自动前滚/回滚） | 分钟 | 日志未损 |
| 单盘/单文件损 | 文件级还原+介质恢复 | 分钟–小时 | 备份+日志可续 |
| 整库损毁 | 全链还原+日志前滚到Latest | 小时 | 异地副本可达 |
| 逻辑错误（发错指令/错批） | **PITR 到错误前一刻**或对象级恢复+差异回补 | 小时，最费判断 | 日志保留够长 ⚠️ 转述 |
| 误删单表/单行 | 对象级恢复/导出回补（别动整库！） | 快 | 逻辑备份存在 |
| 全站灾 | 第 17 章接管流程（本表降级为其子步） | 天 | DRP 已演练 |

- 决策纪律（⚠️ 转述）：恢复前先冻结现场（保留坏介质与日志）——**事故同时是取证对象** ⚠️ 推定。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 完整/增量/差分备份 | Full/Incremental/Differential Backup | 三种备份粒度的成本-链条权衡 |
| 冷备/热备 | Offline/Online Backup | 停机一致 vs 运行中一致（依赖日志机制） |
| 日志备份 | Log Backup/Archive | 事务日志的持续归档，PITR 的燃料 |
| 时间点恢复 | Point-in-Time Recovery (PITR) | 前滚到日志序列任一指定时刻 |
| 介质恢复 | Media Recovery | 还原备份+日志前滚的恢复形式 |
| 重启恢复 | Restart Recovery | 崩溃后凭日志自动前滚回滚 ⚠️ 术语对应转述 |
| 一致性点 | Consistency Point | 备份/恢复可停靠的事务边界 |
| 恢复演练 | Restore Test/Drill | 用真恢复验证备份有效性的例行动作 |
| RPO/RTO | Recovery Point/Time Objective | 可忍丢失量/可忍停机时长（本书以近义词表述 ⚠️） |
| 日志传送 | Log Shipping | 连续日志投递到副本的准热备 |
| 存储快照 | Storage Snapshot | 阵列/文件系统层的瞬时副本 |
| 逻辑备份 | Logical Backup/Export | 以数据内容形态的可移植备份 |

## 最新演进与工业实践

1. **PITR 成为托管服务默认项**：AWS RDS（https://aws.amazon.com/rds/ ✅curl 200）、Azure/Cloud SQL 均内建自动备份+任意时间点恢复；
   自管线开源自建 PITR 的事实标准是 pgBackRest（https://pgbackrest.org ，curl 200 验证）——本章的增量链/日志归档/独立保留三件套在工具有序实现 ⚠️ 转述。
2. **备份验证的制度化**：「未验证的备份不存在」升级为**持续恢复验证（restore-as-code）**：定时自动还原到隔离环境+数据断言，
   DBRE 册（[../Database_Reliability_Engineering/00-总览与阅读地图.md](../Database_Reliability_Engineering/00-总览与阅读地图.md)）把它归入「数据作为生产资料」支柱 ⚠️ 对照。
3. **勒索软件改变了威胁模型**：2024–2026 备份纪律新增三要件——**不可变存储（WORM/对象锁定）、离线副本、最小权限的备份账号**；
   「备份凭证可被同一域账号删除」= 备份不存在 ⚠️ 行业共识转述（无单一权威 URL，不附）。
4. **复制/快照的合法上位**：p.554 替代方案节所述在云上已是主方案之一（跨区副本、秒级快照），但作者「不取消备份义务」的结论
   在 3-2-1 原则中复活 ⚠️ 转述；引擎线细节可续读 [../MySQL高可用解决方案.md](../MySQL高可用解决方案.md)、[../高性能mysql.md](../高性能mysql.md)（存在已验证）。
5. **波内兄弟**：[#89《Expert Apache Cassandra Administration》](../Expert_Apache_Cassandra_Administration/00-总览与阅读地图.md) 的 snapshot/nodetool 体系与 [#87《Using SQLite》](../Using_SQLite/00-总览与阅读地图.md) 的
   单文件备份是本章类型学的两个端点（分布式多副本 vs 单机拷贝即备份），义务波尾闭环。
