## 2. 授权与回收（Granting and Revoking Authority，p.456）

本章最长小节之一（✅ 页 456–466，10 页）：
- GRANT/REVOKE 语法语义、对象级（库/表/列/视图/例程）与语句级权限的层级 ⚠️ 转述；
- WITH GRANT OPTION 的权限传播风险——回收不级联产生的「孤儿授权」是经典事故源 ⚠️ 转述；
- 授权的正确姿势：对**角色**而非个人授权、按应用账号分格——为下节铺垫 ⚠️ 推定。
- 现代权威口径：PG 权限文档与 MySQL 权限模型各自成册；本目录仅转述概念框架，行为差异以
  [../PostgreSQL_16_Administration_Cookbook/00-总览与阅读地图.md](../PostgreSQL_16_Administration_Cookbook/00-总览与阅读地图.md) 与 [../mysql/00-总览与阅读地图.md](../mysql/00-总览与阅读地图.md) 为准 ⚠️ 转述。

## 4. 其他机制与加密（Other Database Security Mechanisms p.468；Encryption p.470）

- Other Mechanisms ✅（页 468–470）：行级/标签安全（LBAC/RLS 一族）、列掩码、视图即权限切片的复用 ⚠️ 转述；

- Encryption ✅（页 470–473）：传输加密（TLS 到库）与**静态加密**（TDE/磁盘级/列级）三层；密钥管理的责任划分

## 5. SQL 注入（SQL Injection，p.473）

- ✅ 独立小节（页 473–477，4 页）。本书处置框架（⚠️ 重构）：成因=动态 SQL 拼接+输入未校验（回指第 5 章 p.186 动态 SQL、第 12 章 p.399 绑定变量戒律）；
  对策=参数化语句、最小权限兜底（注入得手也越不出格）、输入校验与错误信息卫生、以及**库端加固不能替代代码端修复**的分工声明 ⚠️ 转述。
- 权威现行清单：OWASP SQL Injection Prevention Cheat Sheet
  https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html （curl 200 验证）——结论与本书一致且更细（含 ORM 转义、二阶注入）⚠️ 转述。
- 本书未及的后续史实：注入在 2010s 随 ORM/参数化默认化而下降，但**提示注入（LLM 场景）**在 2024–2026 让「不可信输入拼进可执行语句」的抽象问题重新上岗 ⚠️ 趋势转述。

## 6. 审计、外部安全与补丁（Auditing p.477；External Security p.478；DBMS Fixpacks and Maintenance p.480）

## 8. 精读要点备忘（重构）

1. 本章 10 个小节的密度 ✅ 表明作者把安全定义为「流程集合」而非「功能清单」：授权-角色-加密-注入-审计-外部-补丁各有归处 ⚠️ 推定。
2. 「最小权限 + 每人一账号 + 补丁不停」三条在本章互为前提，任何一条失守则其余两条失去意义——本章的隐含三角 ⚠️ 重构。
3. 把 SQL 注入写进 DBA 章而非附录，等于宣告「DBA 对应用代码有安全发言权」——与第 6 章评审权同源 ⚠️ 转述。

## 9. 权限矩阵样例（⚠️ 重构模板，对应 p.456–466 授权与角色；角色名为通用公约数）

| 角色 | DDL | DML 读写 | 字典查询 | 授权转授 | 审计配置 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| APP_<系统名> | ✗ | 仅所属对象 | ✗（或白名单视图） | ✗ | ✗ | 应用连接账号，禁人用 |
| READONLY_<域> | ✗ | 指定视图只读 | 限定目录 | ✗ | ✗ | 报表/分析 |
| SUPPORT | ✗ | 诊断包所需最小 | ✓ | ✗ | ✗ | 排障会话单独计时 ⚠️ |
| DEPLOY | 受流程的 ✓ | ✗ | ✓ | ✗ | ✗ | 变更流水线专用（第 7 章 ✅） |
| SECURITY | ✗ | ✗ | ✓ | ✓（角色间） | ✓ | 与 DBA 日常操作分离 ⚠️ 转述 |
| DBA_<域> | ✓（所辖） | 按需审批 | ✓ | ✗（走 SECURITY） | 只读自证 | 特权可拆则拆 ⚠️ 推定 |

- 三条铁律（⚠️ 重构）：人人经角色、应用经专用账号、**任何账号不跨域复用**；违例即第 15 章审计可查事故 ⚠️ 联动推定。

## 12. 攻防账小例（⚠️ 重构示意，非原书数字）

- 攻击面 = 账号 × 路径 × 对象 的三乘积：共享账号使「人」维归零、旁路 ETL 使「路径」维失控——两乘积项任一失守，
  其余控制只是装饰 ⚠️ 方法论推定；
- 防御排序按「被绕过的难度」：声明式约束/引擎强制 ＞ 角色最小化 ＞ 审计威慑 ＞ 流程约定（回指 [09](09-数据完整性.md)/[11](11-法规遵从与数据治理.md) 号文件同构表）⚠️ 排序推定。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 最小权限 | Least Privilege | 只授予完成任务必需的最小权限集 |
| 授权/回收 | GRANT / REVOKE | SQL 权限授予与撤消语句族 |
| 权限传播 | Grant Option | 被授权者可否再授权他人 |
| 角色 | Authorization Role | 权限的命名集合，授权的一级公民 |
| 行级安全 | Row-Level Security / LBAC | 按行/标签过滤可见性的机制族 |
| 数据掩码 | Data Masking | 以假值/变形值遮蔽敏感数据 |
| 传输加密 | Encryption in Transit | TLS 通道保护连接 |
| 静态加密 | Encryption at Rest / TDE | 存储介质上的透明加密 |
| SQL 注入 | SQL Injection | 不可信输入改变语句语义的攻击 |
| 二阶注入 | Second-Order Injection | 存库后于二次使用点触发 ⚠️ OWASP 口径 |
| 数据库审计 | Auditing | 记录访问与变更以备追责的机制 |
| 外部安全集成 | External Security | 目录/SSO 承担的集中身份认证 |

## 最新演进与工业实践

1. **权限与密钥的平台化**：2024–2026 的默认架构是「 Secrets 集中托管 + 动态凭据短时效化」，HashiCorp Vault
   （https://www.vaultproject.io ，curl 200 验证）代表数据库凭据即签即焚的路线；本书「每人一账号」升级为「每人一短时凭证」⚠️ 转述。
2. **静态加密从加分项变成默认项**：托管服务普遍内建加密与 KMS 集成（AWS RDS https://aws.amazon.com/rds/ ✅200 的能力口径 ⚠️ 转述）；
   列级/确定性加密与**动态掩码**在云数仓成熟（Snowflake 的掩码策略能力以其官方文档为准 ⚠️ 未获可验证 URL，仅名提及；本 repo 对口的现代深读见 [../Snowflake_The_Definitive_Guide/00-总览与阅读地图.md](../Snowflake_The_Definitive_Guide/00-总览与阅读地图.md)，存在已验证）。
3. **注入对策的迁移**：经典注入防线（参数化+ORM）已是 CI 静态检查标配；OWASP Cheat Sheet（✅ 见上）持续更新到含 GraphQL/NoSQL 注入形态；
   LLM 代理读写库的「提示→SQL」链路带来回归风险，审计粒度需覆盖自动生成的语句 ⚠️ 趋势转述、无权威定量结论。
4. **审计的可分析化**：审计日志进湖仓集中分析成为合规取证主流，接 [../The_Data_Lakehouse/00-总览与阅读地图.md](../The_Data_Lakehouse/00-总览与阅读地图.md) 与血缘侧 [../数据血缘分析原理与实践.md](../数据血缘分析原理与实践.md)（存在已验证）。
