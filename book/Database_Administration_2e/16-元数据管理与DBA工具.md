## 一、第 22 章：元数据管理

## 1. 什么是元数据（What Is Metadata?，p.685）

- ✅ 开篇定义：**关于数据的数据**——结构、语义、血缘、规则、归属的登记信息；本书把它抬到「与数据同级的资产」地位，
  并声明元数据管理是「多数组织的第一块治理基础设施」⚠️ 转述/重构。
- 论证链（⚠️ 推定编排）：没有元数据，则第 2 章标准无从检查、第 7 章影响分析（p.250 ✅）无从计算、第 15 章合规（p.488 ✅）无从举证——
  本章因此是全书流程线的「账本室」⚠️ 结构实抓/联系推定。

## 2. 元数据的类型（Types of Metadata，p.689）

- ✅ 三分（⚠️ 重构为通行名目）：
  1. **技术元数据**：表/列/索引/视图/程序对象的结构与定义（系统目录可自动采集）；
  2. **业务元数据**：名词术语、业务规则、数据所有者（必须人工维护——本书强调的缺口所在 ⚠️ 转述）；
  3. **操作/管理元数据**：变更史、作业运行史、访问史（与第 15 章审计 p.490 ✅ 共源）。
- 采集策略：自动抓取（目录导出）+人工登记双轨，登记责任落到人 ⚠️ 转述。

## 3. 仓储与数据字典（Repositories and Data Dictionaries，p.691）

- ✅ 页 691–696，本章落点。概念辨析（⚠️ 转述）：**数据字典=引擎自带的系统目录**（权威但只到技术层），
  **元数据仓储=跨引擎/跨工具的集中库**（可含业务层，但需维护投入）；两者的同步与真相源之争在书中是明确的管理议题 ⚠️ 推定。
- 仓储选型考量：与建模工具（第 3 章生态 ✅）、ETL（第 19 章 p.623 ✅）、报表层的开放接口 ⚠️ 转述。
- 中文纵深：血缘与元数据体系化叙述见 [../数据血缘分析原理与实践.md](../数据血缘分析原理与实践.md)（存在已验证）；
  建模×元数据见 [../数据建模与DB设计.md](../数据建模与DB设计.md)（存在已验证）。

## 二、第 23 章：DBA 工具

## 4. DBA 工具的类型与收益（Types and Benefits of DBA Tools，p.699）

本章主体（✅ 页 699–728，独占 29 页——按任务域铺品类矩阵 ⚠️ 重构品类名目）：
1. 监视与告警；2. 性能/调优分析；3. 备份恢复增强；4. 变更与版本发布；5. 空间与对象管理；6. SQL 工作台与诊断；
7. 复制与数据移动；8. 高可用接管；9. 安全与审计加固；10. 元数据/目录（与第 22 章相咬合 ✅）。

## 8. 元数据资产登记模型（⚠️ 重构模板，对应 p.689 Types 与 p.691 仓储设计）

**对象主档（技术层，自动采集）**
| 字段 | 来源 |
| --- | --- |
| 对象 ID/类型/所属库/schema | 系统目录导出（数据字典 ✅ p.691） |
| DDL 哈希与版本史 | 迁移流水线（对接 [05](05-设计评审与变更管理.md)） |
| 行数/空间/增长率 | 统计作业（对接 [14] 空间账 ⚠️ 联动推定） |
| 访问频次画像 | 审计/性能视图（对接第 10 章 p.345 ✅） |

**语义附加（业务层，人工维护——投入缺口常在此 ⚠️ 转述）**
| 字段 | 维护者 |
| --- | --- |
| 业务名称与定义 | 数据域负责人 |
| 敏感级与合规标签 | 安全/法务联合（→ [11](11-法规遵从与数据治理.md)） |
| 数据来源与血缘边 | ETL/平台自动+人工补注 |
| 质量规则引用 | 登记卡 ID（→ [09] 第 8 节 ⚠️ 联动推定） |

- 治理铁律（⚠️ 重构）：**字典自动、语义签账**；无主的语义字段等于不存在 ⚠️ 结论推定。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 元数据 | Metadata | 关于数据的数据：结构、语义、血缘、归属、历史 |
| 技术元数据 | Technical Metadata | 对象定义与结构信息，可自动采集 |
| 业务元数据 | Business Metadata | 术语、规则、所有者，须人工维护 |
| 操作元数据 | Operational Metadata | 变更/作业/访问的历史信息 |
| 数据字典 | Data Dictionary | 引擎自带的系统目录（权威技术层） |
| 元数据仓储 | Metadata Repository | 跨源集中元数据库，含业务层 |
| 血缘 | Lineage | 数据流转与变换的路径记录 |
| 影响分析 | Impact Analysis | 变更沿血缘传播的预估计算 |
| DBA 工具 | DBA Tools | 按任务域固化的第三方/原生工具族 |
| 原生工具 | Native Tools | DBMS 自带管理工具集 |
| 供应商评估 | Vendor Evaluation | 功能/平台/集成/存续/培训五维选型法 ⚠️ 重构名目 |
| 自动化 | Automation | 第 24 章口号的采购与集成落地面 |

## 最新演进与工业实践

1. **元数据品类整体升格为「数据目录平台」**：本书的仓储设想在 2024–2026 由开放目录实现——OpenMetadata
   （https://open-metadata.org ✅curl 200）与 DataHub（https://docs.datahub.com ✅curl 200）为开源代表，
   Collibra/Alation/Atlan 为商用侧 ⚠️ 转述；血缘从「仓储字段」升为「自动采集的运行时图谱」，p.250 影响分析获得机器执行者。
2. **DBA 工具的两大分流**：一类被云控制台/托管服务吸收（备份、监控、参数组，见 https://aws.amazon.com/rds/ ✅200 能力面 ⚠️ 转述），
   一类以开源专业件存续：pgBackRest（https://pgbackrest.org ✅200）、迁移三件套 Flyway/Liquibase/Atlas
   （https://flywaydb.org / https://www.liquibase.com / https://atlasgo.io ，均 ✅200）——本书「先用原生走到极限再加购」的纪律照旧适用 ⚠️ 转述。
3. **可观测性栈补上监视品类**：指标-日志-链路三件套（Grafana Loki https://grafana.com/oss/loki/ ✅200 为日志侧代表）承担第 10 章 p.345 监视小节的现代实现 ⚠️ 转述。
4. **AI 助手进入工作台品类（2024–2026）**：NL2SQL 与运维 Copilot 类产品流行，但其审查闭环恰好回到本书第 6 章评审与
   第 12 章访问路径审查（见 [05](05-设计评审与变更管理.md)/[08](08-应用性能与SQL调优.md) 号文件）⚠️ 趋势转述，无权威定量结论。
