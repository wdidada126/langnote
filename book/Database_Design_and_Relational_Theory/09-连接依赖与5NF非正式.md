> 9.3 循环规则 / 9.4 结束语）✅ O'Reilly 北京页；英文章题 ✅ Crossref 第 2 版同名章。

## 本章定位

FD 的账算完（03–08），第三部分换主角：**连接依赖 JD**。核心惊奇：一个 relvar 可以 BCNF
满分毕业，仍然藏着冗余——因为冗余未必以"非键决定"的面目出现，也可以以
"多片连接才拼得出原事实"的面目出现。5NF 就是治这个的。

## 机制精讲

### 9.1 连接依赖的基本思路

**（非正式）定义**：设 X1,…,Xn 覆盖 R 的全部属性。若对 R 的每个合法状态 r 都有
r = π_{X1}(r) ⋈ … ⋈ π_{Xn}(r)，则 R 满足连接依赖 `*{X1,…,Xn}`。
读法："R 中的事实完全由它在各组属性上的投影决定"——即**整体信息 = 局部信息 + 连接**。

- 平凡 JD：某 Xi = R 全体属性。
- FD 与 JD 的关系（非正式方向，正式在 10 章）：X→Y 允许把 R 无损拆成 {XY, R−Y∪X} 两片，
  故每条 FD 都"诱发"一个两元 JD；但 JD 表达的是**三类及以上片同时成立**的约束，量纲不同。
- 🔧 与 05 章希思分解对照：希思给的是"有 FD 就能拆两片"；JD 问的是"拆成 n 片还回得来吗"。

### 9.2 一个属于 BCNF 但不属于 5NF 的关系变量

取全键 relvar `SPJ{S#, P#, J#}`（谓词：供应商 s 向工程 j 供应零件 p；键 {S#,P#,J#}，无其他 FD）。
唯一成立的 FD 皆平凡 ⇒ **BCNF 自动满足** ✅（04 章判据）。

但若世界还讲道理地成立约束：

```
*{ {S#,P#}, {S#,J#}, {P#,J#} }     （"s 向 j 供 p" ⇔ 三对局部事实同时成立）
```

则 SPJ 不属 5NF。此时数据被**强制循环闭包**：🔧 实测（demo D4）——
存 3 条 `(s1,p1,j1),(s1,p2,j2),(s2,p1,j2)` 是 BCNF 实例，但若 JD 成立，它**不合法**：
三投影连接强制生成伪元组 `('s1','p1','j2')`（实测连接=4 行、伪元组恰此一条）。
后果：任何一次插入都可能**连锁**要求补插若干元组——更新异常以 FD 理论看不见的形式复活。

### 9.3 循环规则

JD *{SP,SJ,PJ} 的别名："若 s 供 p、p 用于 j、s 供往 j，则 s 必以 p 供往 j"（三个二元事实
围成一个圈，第四件事实被圈住）。**5NF（非正式）**：relvar 是 5NF ⇔ 它不满足任何"不平凡的、
不由键逼出"的此类 JD ⇔ 它**不该**再被无损分解成更多片。
- "由键逼出"的直观版（正式化见 10 章）：若键本身保证循环闭包（如二元 relvar 之间、或某投影片
  含超键），JD 平凡成立，不构成 5NF 违例。🔧 对照实验（demo D4 第二段）：把 4 元组补成
  循环闭包后，|R|=连接=4、无损 `True`——合法状态的样子就是这个闭包形状。
- 判定实务：三目/多目关系（事实表的"全键"表）是 JD 违例高发地——数据仓库桥表尤其可疑
  （对照 [../数据仓库工具箱3.md](../数据仓库工具箱3.md) 的桥接表讨论）。

### 9.4 结束语（重构）

作者的修辞重点：5NF **不是**"为了拆而拆"的偏执——绝大多数真实 relvar 的 JD 要么不存在、
要么由键逼出；但**存在**（SPJ 全键三元表 + 循环规则）就必须在场，否则"BCNF=无冗余"这句
安全承诺是假的。

## 常见误区

- 「全键表没有非键依赖所以绝对健康」：9.2 的反例专治此症；BCNF 的证书只管 FD。
- 「JD 只是 FD 的别名（无损分解不就是希思吗）」：两片 vs 多片、且多片间的"同时性"约束
  FD 语言写不出（7 章末尾埋过：JD 无完备公理）。
- 「数据里没出现伪元组，说明 JD 不存在」：又混淆实例与约束（03 章 3.4 第三次点名）——
  JD 是关于"不许出现"的约束。
- 「5NF 分解永远安全」：分解片间的独立性要到 6.8/10 章才定义清楚；乱切多片可能把一条 JD
  换成另一条更难维护的 JD。

## 核心概念速览（中英对照）

- **连接依赖** — join dependency (JD)：r = π_{X1}⋈…⋈π_{Xn} 对一切合法状态成立；记 *{X1,…,Xn}
- **平凡 JD** — trivial JD：某分量覆盖全属性
- **循环规则** — cyclic rule：*{SP,SJ,PJ} 的口头名；三边成圈锁死第四事实
- **循环闭包** — cyclic closure：对非 5NF 数据强制补全的闭包操作（🔧 demo 复现）
- **伪元组** — spurious tuple：投影连接凭空造出的元组；JD 违例的显形
- **第五范式** — 5NF / PJ/NF：每个成立的 JD 都由键逼出
- **全键 relvar** — all-key relvar：唯一键为全属性；BCNF 自动过、5NF 未必
- **多片无损** — lossless n-way join：希思两片论的高维推广
- **BCNF 的盲区** — blind spot：非 FD 型冗余（JD 型）
- **连锁插入** — forced insertion：一条新事实触发闭包补全义务
- **桥接表** — bridge table：多对多对多 junction 表；5NF 违例高发地（数仓侧有意的反例）
- **键逼出** — implied by keys：JD 合法化的唯一来源（非正式表述；正式化在 10 章）
- **投影片** — projection component：JD 的 Xi；"分量"一词的由来（11 章）
- **实例≠约束** — relvar vs relvar value：JD 违例无须伪元组真实出现即成立（03 章口径第四次运用）

## 最新演进与工业实践

- **一手文献通道** ✅：JD/5NF 的原始出处之一 Fagin, "Normal forms and relational database
  operators"（SIGMOD 1979，DOI:10.1145/582095.582120，api.crossref 200 已核）；教科书口径另见
  [../数据库系统概念6/00-总览与阅读地图.md](../数据库系统概念6/00-总览与阅读地图.md)（其对 5NF 着墨极省，
  本书的差异化价值正在此处）。
- **数仓桥表的"故意不 5NF"** ⚠️：维度建模明确接受桥接表引入 fan trap 并用一致性维度/聚合事实控制
  （见 [../数据仓库工具箱3.md](../数据仓库工具箱3.md)、[../Data_Vault_2_0/00-总览与阅读地图.md](../Data_Vault_2_0/00-总览与阅读地图.md)）；
  这是工程对 9.3 的回应：OLTP 按 5NF，分析层以显式建模换取查询形态——分歧在"冗余由谁、在哪层、怎么还"。
- **检测实践**：JD 成立与否**不可**靠实例检查（9.3 误区 3）；现代表建模工具（如 ER/数据建模套件的
  n 元关系自动转三个二元关系 ✅ 通识）实质是替你做 5NF 分解；反向——从二元表拼回 n 元事实时，
  必须**显式声明**这条 JD，否则 9.2 的连锁插入义务丢失。
- **理论边界**：JD 蕴含问题无完备公理化（Rissanen 1979 ⚠️ 未核 DOI，仅记名）——所以工业界
  对 5NF 的实际操作是"分解保守 + 约束文档化"，而非求解。
