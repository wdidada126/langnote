## 本章定位

第二部分的总纲：先给"病"（更新异常）下定义，再给"药柜"（范式层次）画地图，最后钉住一个
容易被忽略的论点——**规范化永远是相对于约束集的规范化**。没有约束，谈不上范式。

## 机制精讲

### 3.1 规范化用于两个目的

（重构表述，忠实于节题）规范化的目标不是"把表拆小"这种审美动作，而是：
1. **消除更新异常**：让每个事实只被表示一次（"一个事实一处出现"）。
2. **消除无关的 NULL/占位**：设计坏时，某些行对某些属性"不适用"，只能用 NULL 顶包——
   三值逻辑病灶从设计端就该掐灭（查询端的治疗见兄弟目录
   [../SQL_and_Relational_Theory/06-NULL与三值逻辑3VL.md](../SQL_and_Relational_Theory/06-NULL与三值逻辑3VL.md)）。

两个目的其实同根：都是"relvar 与谓词不对齐"的症状。

### 3.2 更新异常（定义 + 🔧 实测）

设设计不当的 `SPSJ(S#, SNAME, STATUS, CITY, P#, J#, QTY)`，其中 S#→SNAME,STATUS,CITY。三类病：

- **修改异常**：改一个事实要改多行。🔧 实测：造 4 行（S1 占 3 行），把 S1 的 STATUS 从 20 改 25，
  `update SPSJ set ST=25 where S='S1'` 报 `changes()`=**3**——一个供应商状态这一个事实动了 3 行。
- **删除异常**：🔧 实测：`delete from SPSJ where S='S2'` 删掉 S2 唯一供货行后，"S2 是巴黎的供应商"
  这一独立事实随元组一起消失（S2 出现次数归 0）。
- **插入异常**：没有供货也要登记新供应商时，只能把 P#/J#/QTY 置 NULL——把"未知"写进本不该
  出现该概念的位置（回到 3.1 目的 2）。

> 关键论断：**异常不是 SQL 的行为怪异，而是逻辑设计错误的必然推论**；根因是关系里混入了
> "非键决定的依赖"。这把病灶精确到 FD 上，第 4–8 章处理之。

### 3.3 范式层次结构

| 范式 | 引入的约束类型 | 对应本目录章 |
| --- | --- | --- |
| 1NF | 属性取值为原子标量值（作者版：无重复组、无关系值属性伪装） | 04 |
| 2NF | 非主属性完全函数依赖于键（针对复合键） | 04（作者视其为冗余的中间站 ⚠️ 一贯立场） |
| 3NF | 非主属性不传递依赖于键 | 04/05 |
| BCNF | **每个决定因素都是超键** | 04/05 |
| 4NF | 每个**多值**依赖的决定因素都是超键 | 12 |
| 5NF | 每个**连接**依赖都被键蕴含 | 09/10 |
| 6NF/其他 | 时态/区间、等式依赖、SKNF/NRNF/DK-NF | 13 |

层次是**逐层严格加强**的链（5NF⇒4NF⇒BCNF⇒3NF⇒2NF⇒1NF；4NF 与 BCNF 的包含关系在 JD/MVD
框架下见第 12 章）。⚠️ 注意：不同文献对"5NF⇒4NF"的细节表述有差异，本表取本书口径。

### 3.4 规范化和约束

- 依赖是**约束**（对 relvar 所有可达取值的限制），不是"某张实例上的巧合"。
  判定"R 是否 BCNF"必须量化"所有合法状态"——用一两张截图证明范式等级是常见错误。
- 同一个关系相对不同约束集范式等级不同：`SPJ{S#,P#,J#,QTY}` 在键 {S#,P#,J#} 下 BCNF ✅；
  若世界还有事实 `S#→CITY`（即把供应商城市混进 SPJ），立刻跌出 BCNF。
- **约束先行**：先把 FD/JD/MVD 从谓词里读出来，再谈分解——"拆表"是约束分析的副产品。
- 反规范化的合法动机由此被釜底抽薪：你不能"绕过约束"，只能改变约束声明的位置（见 08 章）。

### 3.5 结束语（重构）

作者强调规范化是手段不是目的：目的回到 1.5/1.6 的"更好的设计、更少的 NULL、更准的直觉"。
层次表背下来不等于会设计；后面每一级范式都是"某种依赖的决定因素必须是超键"的同构定理。

## 常见误区

- 「3NF 就够了，BCNF 是学究气」：BCNF 与 3NF 的差距恰在第 6 章的"保持依赖冲突"上才看得清；
  跳过后既不理解何时可妥协、也无从评价妥协。
- 「拿一个实例看不出重复就宣布已规范」：范式是状态空间的性质（3.4）。
- 「规范化=拆表越多越好」：过度分解有连接代价与语义损失（第 9 章 SP/SPJ 例子、第 8 章反规范化之辨）。
- 「性能问题只能靠反规范化解决」：第 8 章整章反驳；现代引擎物化视图/索引路线见 08 文末。

## 核心概念速览（中英对照）

- **规范化** — normalization：把 relvar 分解到与约束对齐的过程；相对约束集而言
- **更新异常** — update anomalies：插入/修改/删除三类病（🔧 本章有行数实证）
- **冗余** — redundancy：同一事实多处出现；异常之源
- **一个事实一处出现** — one fact one place：设计的口号化判据
- **修改异常** — modification anomaly：改 1 个事实要动 n 行
- **删除异常** — deletion anomaly：删一处顺带丢了独立事实
- **插入异常** — insertion anomaly：登记 A 被迫虚构 B 或塞 NULL
- **范式** — normal form：以"决定因素须为超键"为母题的约束等级
- **范式层次** — hierarchy of normal forms：1NF⊃2NF⊃3NF⊃BCNF⊃4NF⊃5NF（本书口径）
- **约束** — constraint：对所有可达状态成立的谓词；范式判定的量化域
- **超键 / 候选键** — superkey / candidate key：决定全属性的键 / 极小超键
- **决定因素** — determinant：某依赖左侧属性集
- **完全/部分依赖** — full/partial FD：2NF 的判词；对复合键而言
- **传递依赖** — transitive FD：3NF 的判词：X→Y→Z 且 Y 不含于键
- **依赖相对性** — relativity：同一关系在不同约束集下范式等级不同
