## 核心概念速览（中英对照）

- **vptr 初始化语意学** — semantics of the vptr：每个 ctor **在自己代码开头**把 vptr 指向**自己类**的 vtable——
  构造/析构期间的虚调用一律降级为静态绑定（实测 t5：`V::V(){g();}` 直接 `call _ZN1V1gEv`）。
- **默认构造四步骤** — default constructor expansion：①虚基类构造 ②主基类构造 ③成员按声明序构造 ④才轮到你的函数体。
- **C1/C2、D0/D1/D2** — base-object/complete-object ctor、dtor、deleting dtor：实测 nm 符号
  `_ZN4VirtC1Ev/C2Ev/D1Ev/D2Ev/D0Ev`（Itanium）；MSVC 用 `??0/??1` + `??_E`（deleting）表示同一套分工。
- **complete object constructor** — `_ZTC`：虚继承时"为完整对象重排虚基偏移"的包装 ctor（实测 `_ZTC7Diamond0_4Mid1`）。
- **纯虚函数** — pure virtual function：vtable 槽填守卫函数（实测引用 `__cxa_pure_virtual`）；
  纯虚**可以**有类外定义，派生类显式 `Base::pf()` 调用合法。
- **虚析构** — virtual destructor：多态基类的删除协议；无虚析构 + `delete` 基类指针 = 未定义行为。
- **对象复制/切片** — object copy / slicing：`Base b = derived;` 只拷基类子对象——5.3 用布局解释了这一"沉默的降级"。
- **deleting vs non-deleting dtor**：`D0` 释放内存（`this` 视为堆块头），`D1` 只毁灭对象；`delete p;`（p 为多态类）
  静态绑到 `D0`。

## 动机：三个"看不见"合成一件事

用户写 `T t;`、`t = u;`、`delete p;`，编译器实际发射：偏移量回填、vptr 切换、虚基登记、成员析构链、
可选的 `operator delete`。Lippman 用 cfront 的翻译样本证明：**这些代码每一行都花你的时间**，
但"效能"结论（5.4）远比"别用 ctor"温和——开销集中在多态与虚继承，普通类近乎零。

## 机制

### 1. 无继承情况的构造展开（5.1）

```text
class NoInh { Numeric _radius; string _name; ... } 
NoInh::NoInh(string n): _radius(0.0), _name(n) { ... }
展开(g++ 实测形态):
  ① _radius.Numeric::Numeric(0.0)   // 列表顺序≠执行顺序→声明顺序
  ② _name.string::string(n)
  ③ 函数体
若类有虚函数: 体前插 "lea vtable,%rdx; mov %rdx,(%rax)"   ← 实测 t5：store 指令在构造函数体 0x17 处
若为派生做准备(虚析构等): 同上
```

### 2. 虚拟规格与签名匹配（书中 5. 前小节）

"虚拟性"按**名字+类型签名**匹配；返回类型协变（covariant return）C++98 才加入，const 成员函数与
非 const 版**不同签名**——书中"虚拟规格中 const 的存在"一节讲的就是这条易踩线。`override`（C++11）
把全部此类坑变成编译错误。

### 3. 继承体系下的构造顺序与 vptr 时序（5.2）

```text
Order{ T1 a; T2 b; Base1 c; Base2 d; } 的完整构造序（标准语意；实测 t1 的 C1/C2/_ZTC 符号链即其脚手架）:
  虚基类(按声明/派生图拓扑) → 非虚基类按声明序(cBase1, cBase2) → 成员按声明序(a, b) → 体
vptr 时间线（以 Derived:Virt 为例）:
  Virt::C2 开头: vptr ← Virt#vt   ← 此刻对象"是"一个 Virt
  Derived::C1 开头: vptr ← Derived#vt（调用 Virt::C2 返回之后）
```

书中 cfront 与后来的 Itanium 都遵守同一**标准语意**（构造期动态类型 = 当前类）。实现层细节：
Itanium 为"构造期间的虚拟表"引入 **VTT / 构造版 vtable**（✅ ABI 文档 §2.6），让每层 ctor 拿到自己那张表；
cfront 时代的具体切表策略属历史内容，本书正文以"每层 ctor 各设各的 vptr"叙述，读时以标准语意为准。

### 4. 纯虚函数的存在（书中 5 首节）

实测（g++ 15.2，🔧 t13）：抽象类 `B` 的 vtable 中 `g` 槽链接到 `__cxa_pure_virtual`；
构造期经基类 ctor 调它 → 运行时落到守卫（通常崩溃）而非派生实现。
书中"为纯虚函数提供定义"的逃生门真实存在：`B::g(){...}` 合法，只能被 `b.B::g()` 显式触发——
现代代码里它专职承担"析构期回调"（`~B(){ g(); }` 静态绑定到 `B::g` 定义）。

### 5. 析构语意学（5.5）

```text
delete polyPtr;                 // polyPtr 为多态类基指针
翻译: (*(polyPtr->vptr)[dtor_slot])(polyPtr, 1)   ; 槽里是 D0(deleting)
p->~T();                        // 显式析构 → D1(non-deleting), 不释放内存
展开链: ~Derived → Derived体 → 成员逆序析构 → 基类逆序析构 → (若有) vptr 切回上一层
```

实测符号：`_ZN4VirtD0Ev`（内部 `call operator delete`）与 `D1Ev` 并存；非多态类的 `delete`
静态绑定 D1 + 直调 `operator delete`。**析构期再切一次 vptr**：`~Virt` 体执行时 vptr 已指回 `Virt#vt`，
此刻调虚函数拿到的是 `Virt` 版本——与构造期对称（第 4 章 GoogleMock 禁例的根源）。

### 6. 对象复制与效能（5.3/5.4）

- `Base b = d;`：只复制 `sizeof(Base)` 个字节——布局图上一眼看出派生部分"在副本外"；
- `Base* pb = &d;`：零复制，虚分派继续工作（实测 t9：基类指针 `this` 打印为完整对象地址）；
- 效能小结（书中立场+实测印证）：非多态类构造≈等价 C 代码；多态类 +1 store（vptr）；
  虚继承 MSVC 侧每对象 +8B（vbptr）、Itanium 侧虚表变长，构造期多一次完整对象偏移回填（`_ZTC`）。

## 权衡

- **切表策略**：每层 ctor 各设 vptr（Itanium）代码冗余但模块化；cfront 的"派生覆写"少几条指令、
  调试器视角更迷惑。今天没人需要重新发明。
- **虚析构税**：基类一旦加 `virtual ~`，所有派生类免费获得（必要的）vptr——这是"为删除协议预付的定金"；
  不想付就按 Effective C++ Item 的路线禁继承或 protected 非虚析构。
- **C1/C2 双胞胎**：完整对象（`C1`）与基类子对象（`C2`）各一份代码，换"虚基偏移只在顶层回填一次"；
  体积×2 的风险由内联/链接期折叠兜底（实测 t1：空 `Mid1` 的 C1 与 C2 地址不同、体量相当）。

## 相邻概念对比

- **构造 vs 赋值**：构造可以碰 const/reference/无默认构造的成员，赋值不行（第 2 章列表语意的延伸）。
- **vptr 初始化（本章）vs vtable 生成（第 4 章）**：表是静态数据、编译期躺在 .rdata；ptr 是每对象字段、
  运行期在 ctor 第一行被写入。
- **`delete p` vs `p->~T()` vs free(p)**：三档破坏力递减，与 placement new（[06-执行期语意学.md](06-执行期语意学.md)）配套。

## 最新演进与工业实践

- **`=default` 虚析构 + 零/五法则**：多态基类写 `virtual ~Base() = default;` 是当前标准姿势
  （C++ Core Guidelines C.67/C.66，仓库有 [../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md)）。
- **constexpr 与构造展开**：常量求值里 vptr/偏移回填不存在（无动态类型阶段），constexpr 类的"构造"
  退化为字段直填——实测 `static_assert(cobj.v==3)`（g++ 15.2）。书第 6 章"构造时机"话题在编译期有了镜像世界。
- **协程帧（C++20）**：`co_await` 挂起点之后对象活在堆上帧里，其"构造时机"由 promise_type 与
  编译器生成的 resume 函数接管——对象生命周期主题在 2020 年代最热的扩展面
  （cppreference 的 coroutine frames 章节 ⚠️ 本笔记未实测帧布局）。
- **实现锚点**：Clang `CGCXXABI.cpp` 的 `EmitCXXConstructor` / Itanium VTT 发射路径与
  GCC `g++ -fdump-tree-all` 的 ctor 展开（源码 ✅ llvm/llvm-project）。
- **测试工程实践**：GoogleMock 文档明确警告不要在 ctor/dtor 里调用 mock 虚函数——vptr 时序问题的工程回响
  （仓库 ✅ google/googletest）。

## 常见误区与自查

1. ❌"构造期虚函数会调到派生版"——不会；实测直调本类版本（t5）。
2. ❌"纯虚函数不能在基类有实现"——可以有，且是析构期回调的标准手法。
3. ❌"`delete` 基类指针安全"——无虚析构时 UB；槽都不会被查。
4. ✅ 自查：给 `D : B1, virtual VB` 排出构造顺序与 vptr 时间线，并解释 `_ZTC` 为什么存在。
