## 核心概念速览（中英对照）

- **全局对象初始化时机** — initialization of global objects：`main` 之前按链接序执行；
  跨 TU 顺序未定——书中"以 exit 钩子解决初始化顺序"的处方今天叫 Meyers' Singleton。
- **`__cxa_atexit`** — register destruction：实测 nm：全局数组 `A ga[2];` 的构造包装函数里注册
  `atexit`/`__cxa_atexit`，把析构挂到退出链表。
- **局部静态对象** — local static objects：首次执行到声明处才构造；C++11 起线程安全
  （magic statics），实测符号 `__cxa_guard_acquire` + 守卫变量 `_ZGVZ1fvE1c`（g++ 15.2 -O2）。
- **`new` 的三手分工** — operator new / ctor / placement：`new T(args)` = ①`operator new(size)` 拿内存
  ②以 args 调 ctor ③返回 `T*`；`operator new` 只负责**挖坑**，不负责**埋人**。
- **数组 new 的记账** — array new cookie：`new T[n]` 调 `_Znaj`（实测 nm 符号），`delete[]` 调 `_ZdaPv`；
  非平凡 dtor 的数组需要记住 n——cookie（隐藏的元素计数头）就是这一账本的 cfront/Itanium 形态。
- **Placement new** — placement operator new：`new(ptr) T()` **不调任何 allocator**（实测：该调用不引用
  `_Znw*`），只在既有地址上跑 ctor——对象池、union 成员切换、`std::vector` 的底层砖。
- **临时性对象** — temporary objects / materialization：编译器在表达式中途生成的无名字对象；
  寿命原则上到"完整表达式"结尾（full-expression），绑定 const 引用可续命。
- **临时对象的三个迷思** — myths（书中 6.3 末）：①"在定义处诞生"②"活到函数结束"③"析构顺序随便"——
  全部为假，实际按表达式边界逆序批量毁灭。
- **no_throw 版本** — `new(std::nothrow)`：分配失败返回空指针而非抛 `bad_alloc`；书中"no-nothrow 老接口"已退役。

## 动机：一条 `T t = f();` 背后的全部账单

```text
T t = f();
可能发射: operator new(24)   ←堆? 不, 局部对象在栈; 但 f 返回 vector 时堆在内部
          T::T(...)          ← f 体内构造
          T::T(const T&)     ← 若 elision 失败(见 02 章: -O0 下 g++ NRVO 已省掉)
          T::~T()            ← 完整表达式/作用域边界
          operator delete    ← 仅当曾有分配
```

编译器逐条决定，且不同优化级别结论不同——所以 Lippman 说"不要猜，去看布局与时机"。

## 机制

### 1. 全局对象（6.1）

实测（g++ 15.2，nm t4.o）：含非平凡 ctor 的全局数组生成
`__static_initialization_and_destruction_0` 风格的初始化函数 + `U atexit` 引用；
`main` 之前由 CRT 构造函数驱动。析构=逆注册序。跨 TU 顺序仍是"未定义但可实现"——
书中给 cfront 的 `.init/.exit` 表安排，现代对应物是 GCC `.init_array` 段（ELF）与 MSVC `.CRT$XCU`。

### 2. 局部静态对象与 magic statics（6.1）

```asm
; 实测 t14 (-O2): int& f(){ static int c=seed+1; return c; }
push ... __cxa_guard_acquire(& _ZGVZ1fvE1c)   ; 原子标志: 初始化了吗?
call init; __cxa_atexit(~init...)? ; 首线程赢, 其余自旋等待
```

C++98 时代"局部静态是否线程安全"由厂商决定（书中语境：多数不是）；
C++11 §6.7/4 规定为竞态自由。旧代码库的 `pthread_once` 包装由此退位。

### 3. 对象数组与默认构造（6.1 末）

`T arr[10];` → 循环调 10 次 ctor（有非平凡 ctor 时发射 loop）；
`new T[n]` → `_Znaj` + 循环 + **cookie**（当 dtor 非平凡时记录 n，供 `delete[]` 逆序毁灭后释放）。
书里"指针强转数组首元素再 delete 是慢性自杀"的警告，本质是**绕开 cookie 的删除协议**。

### 4. new/delete 语意分解（6.2）

| 表达式 | 分配 | 构造 | 可替换点 |
| --- | --- | --- | --- |
| `T* p = new T(a);` | `operator new(sizeof T)` | `T::T(a)` | 类级/全局 operator new |
| `T* p = new(buf) T(a);` | 无 | `T::T(a)`，写入 buf | 你的池/arena |
| `delete p;` | (多态则查 vptr→D0) | `~T` | `operator delete` |
| `p->~T();` | 无 | `~T` | 与 placement 配对（显式毁灭） |

实测印证：t4 的 `plat()`（placement new）不引用标量 `operator new(size_t)` 符号，构造直接在 `buf` 上展开；
`arr()` 引用 `_Znaj`（数组 new）；同一目标文件里还出现 `_ZdaPvy`/`_ZdlPvy`（sized delete 家族，
来自分配-构造异常回退路径）。

### 5. 临时性对象（6.3）

```text
polymorphic pointer 场景: screen.mov( point.x, Point(z).y );
书中时代: 可能生成 1 个临时 Point + ctor + dtor 三段
现代实测: 内联后常为零对象(参数直接进寄存器/栈槽) —— elision 的胜利率远高于 1996
迷思修正: 临时对象在"需要它做左值底座"时才 materialize(std::move 只是 cast 不生成对象)
```

"引用不是指针"（第 7 章预告）在临时对象语境下同样关键：`const string& s = "hi";`
**必然**生成临时 string（字面量不是 string），寿命延至引用作用域末——这一条 cfront/现代实现无差异。

## 权衡

- **cookie vs 存长度于调用方**：`std::vector` 拒绝 cookie 路线（自己存 size），所以它用
  placement new + 显式 dtor 管理元素——第 6 章机制在标准库里找到的最大用户（对照
  [../STL源码剖析.md](../STL源码剖析.md) 的 allocator/construction 接口 `std::uninitialized_*`/`std::destroy_at`）。
- **`new` 可被重载**：每类自带 `operator new` 是"小型对象进内存池"的合法后门（书中示例），
  现代更推荐 pmr/单调资源而非重定义全局 new。
- **临时对象成本 vs 代码简洁**：书中"在使用者层面消灭临时对象"的建议，被 C++11 move + C++17 强制 elision
  大幅稀释；今天的默认答案是"信优化器，别为省一次拷贝写丑码"（例外：显式类型析构的 RAII 场景）。

## 相邻概念对比

- **全局对象 vs 局部静态**：注册驱动 vs 首用驱动；后者天然免疫"静态初始化顺序恶魔"。
- **`new T` vs `new T[n]`**：不同分配函数（`_Znw` vs `_Znaj`）、不同删除函数——**永不互换**（UB）。
- **placement new vs memcpy**：前者执行 ctor（有 vptr 时逐字段正确），后者连第 2 章的 bitwise 禁区都可能踩。

## 最新演进与工业实践

- **magic statics（C++11）**：已如上；LLVM/Chromium 风格指南明确"优先用局部静态做单例"。
- **`std::construct_at`/`std::destroy_at`（C++20）**：把 placement new+dtor 的手艺标准化为 constexpr 友好 API；
  libc++/libstdc++ 均已实现（可于 [../C++标准库.md](../C++标准库.md) 条目语境查阅）。
- **polymorphic allocators（C++17 pmr）**：内存池话题的官方终稿——书中"自定义 operator new"的集中替代。
- **异常安全交易**：`new` 失败抛 `bad_alloc`（1993 后标准）；6.2 节的"no-throw 宏"已归档；
  `nothrow` 版本保留给 C 互操作与嵌入式（实测异常家族符号见 [07-站在对象模型的尖端.md](07-站在对象模型的尖端.md)）。
- **UBSan 视角**：`-fsanitize=address` 会把"绕过 cookie 的 `delete p`"、"placement 对象当堆块释放"
  当场报 `alloc-dealloc-mismatch`——对象模型知识在现代工具链里的自我证明（clang/gcc 内置，✅ llvm.org/docs 有 sanitizer 文档）。

## 常见误区与自查

1. ❌"`new` 就是分配内存"——new 表达式 = 分配 + 构造两阶段，各自可替换。
2. ❌"`delete p[]` 与 `delete p` 差不多"——分配协议不同（实测符号都不同）。
3. ❌"局部静态在多线程下会重复初始化"——C++11 后由 guard 保证恰好一次（实测 `__cxa_guard_acquire`）。
4. ✅ 自查：给定 `void g(std::string s); g("abc");`，数出临时对象个数并说明它在何处析构。
