# 第 5 章 高级 SQL

> 高级特性：函数与过程（存储过程/函数）、触发器、递归查询（`WITH RECURSIVE`）、窗口函数（OLAP 排名/聚合）、OLAP 分组（`ROLLUP`/`CUBE`）、游标、动态 SQL、SQL 与宿主语言接口（JDBC/ODBC）。

## 一、核心精讲

### 5.1 🔧 窗口函数（分析查询利器）
- `ROW_NUMBER()/RANK()/DENSE_RANK()`、`LEAD/LAG`、聚合 over `PARTITION BY ... ORDER BY`（🔧 与 `GROUP BY` 区别：窗口函数**不折叠行**，每行都保留并附带计算结果；Top-N 每组前 K 行必备）。

### 5.2 递归查询
- `WITH RECURSIVE`（如树形菜单、图遍历）（🔧 由基例 + 递归项 + 终止条件构成）。

### 5.3 触发器
- `BEFORE/AFTER` + `INSERT/UPDATE/DELETE`，行级/语句级（🔧 适合审计/派生数据；但隐式副作用难排查，现代倾向应用层或 CDC）。

### 5.4 存储过程 vs 应用逻辑
- 存储过程在 DB 内执行（省网络往返），但难版本化/测试/移植（🔧 现代微服务倾向应用侧逻辑 + DB 只存数据）。

## 二、版本演进 / 论文 / 前沿

- 标准：SQL:1999（递归/触发器）、SQL:2003（窗口函数/序列）、SQL:2011（时态）。
- 工业界：PostgreSQL 窗口函数最完善；CDC（Debezium）替代部分触发器场景。
- 开源 stars（2026-09）：postgres 17k / debezium 10k.

## 三、常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "窗口函数=GROUP BY" | 不折叠行 |
| 2 | "触发器万能" | 隐式副作用，慎用于审计 |
| 3 | "存储过程应放全部逻辑" | 难测试/移植 |
