# 第 13 章 查询优化（重点章）

> 优化的两大手段：**等价变换（逻辑优化/重写）** + **代价估计选物理计划**；等价规则（选择下推/投影下推/连接顺序/外连接化简）、**连接顺序枚举**（动态规划/左深树/遗传算法）、统计信息（直方图/基数估计）、物化视图与查询改写。本章是「为什么 SQL 慢」的根因章。

## 一、核心精讲

### 13.1 🔧 等价变换（重写）
- **选择下推**（尽早过滤，减少中间结果）、**投影下推**（尽早去掉无用列）、**连接交换律/结合律**（重排连接顺序）、常量折叠、`OR` 转 `UNION`、子查询去关联（🔧 现代优化器还会做「子查询转半连接 semi-join」「外连接化简」——这些是 SQL 突然变快的常见原因）。

### 13.2 连接顺序枚举
- n 个表连接有 (2n-2)!… 种左深树顺序，**指数爆炸** → 用动态规划（左深树，O(3^n)）或遗传/贪心（表多时）（🔧 表数超阈值（PG `join_collapse_limit`=8）优化器会退化，需 SQL 显式指定顺序或用 hint）。

### 13.3 基数估计与统计信息
- 直方图/高频值/不同值数（NDV）估计选择率；**估计错误会级联放大**（🔧 生产务必定期 `ANALYZE`/更新统计；MySQL 8 有直方图，PG 有扩展统计/多列统计）。

## 二、版本演进 / 论文 / 前沿

- 论文：Selinger System R 优化器（SIGMOD 1979）；Graefe《The Cascades Framework》(1995，Volcano/Cascades 是现代优化器骨架，PG/Calcite 用)；Leis et al.《How Good Are Query Optimizers, Really?》(VLDB 2015)。
- 工业界：PostgreSQL（GEQO 遗传优化）、MySQL、Apache Calcite（优化器框架，4k）、ClickHouse。
- 开源 stars（2026-09）：calcite 4k / clickhouse 37k.

## 三、常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "SQL 写法不影响性能" | 逻辑等价但优化器可能被难住（OR/函数包裹列致索引失效） |
| 2 | "统计信息不用管" | 过期会选错计划，定期 ANALYZE |
| 3 | "连接顺序无所谓" | 是优化核心，差数量级 |
| 4 | "列上加函数仍能走索引" | 通常失效，改函数索引或重写 |
