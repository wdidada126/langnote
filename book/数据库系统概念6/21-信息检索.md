# 第 21 章 信息检索

> **本章地图**：信息检索（IR）与数据库查询的本质差异 → **全文检索与倒排索引** → 查询类型（**布尔 / 短语 / 邻近 / 通配符**）→ **相关性排序**（TF-IDF、向量空间模型、**余弦相似度**、**BM25**）→ 检索效果评价（**precision / recall / MAP / NDCG**）→ Web 检索（**PageRank / HITS**，作弊与应对）→ 词干、停用词、同义词与查询扩展 → 与结构化数据的融合（XML / 半结构化检索）→ 现代：向量检索与 RAG。

## 二、核心精讲

### 21.1 IR 与数据库查询的根本差异
|  | 数据库（结构化） | 信息检索（非结构化） |
| --- | --- | --- |
| 数据 | 有模式、离散字段 | 自由文本、无模式 |
| 查询 | 精确匹配（SQL，布尔语义） | **模糊、按相关性排序** |
| 正确性 | 有唯一正确答案 | 「答案」是排序结果，靠评测指标衡量 |
| 技术核心 | B+ 树 / 哈希 | **倒排索引** |

- 🔧 关键认识：数据库强调「**找全找对**」，IR 强调「**把最相关的排在前面**」；两者的正确性标准不同，不要拿 SQL 的语义要求去苛责 IR。

### 21.2 倒排索引（inverted index）
- **正排**：文档 → 词项列表。**倒排**：词项 → 文档（+ 位置、词频）列表，即 `posting list`。
- 索引构建：词法分析 → **去停用词** → **词干化 / 归一化（stemming / lemmatization）** → 生成 `(term, docID, positions)`。
- 存储优化：**字典（term dictionary，常用 FST 或前缀树，Lucene 用 FST）+ posting list 压缩**（**variable byte / PForDelta / Roaring bitmap**）；**跳表（skip list / skip pointer）** 加速 posting list 交并。
- 🔧 与数据库的对应：倒排索引 ≈ 数据库的「**位图索引**」；Lucene 的 segment 是不可变的，更新靠段合并 —— 和 **LSM-tree** 的思想一致（都是「不可变文件 + 后台合并」）。

### 21.3 查询类型
- **布尔查询**（AND/OR/NOT，posting list 交并差）；
- **短语查询**（利用 position 信息，验证词序相邻）；
- **邻近查询**（`/k`，两词距离 ≤ k）；
- **通配符查询**（`*a*b`，用 **permuterm index** 或 **n-gram 索引**）；
- **拼写纠错**（编辑距离 + 词频，Lucene 的 fuzzy query 用 Levenshtein 自动机）。

### 21.4 相关性排序
- **TF（词频）**：$tf_{t,d}$，常用 $1 + \log tf$ 做次线性衰减。
- **IDF（逆文档频率）**：$idf_t = \log\frac{N}{df_t}$，稀有词权重高。
- **TF-IDF** = tf × idf；**向量空间模型**：文档和查询都表示为高维向量，用**余弦相似度**排序。
- **BM25（Okapi BM25）**：现代默认算法（Robertson & Zaragoza, 2006），引入文档长度归一化与 tf 饱和：
  $$\text{score}(D,Q)=\sum_{t\in Q} idf_t \cdot \frac{tf_{t,D}(k_1+1)}{tf_{t,D}+k_1\left(1-b+b\frac{|D|}{avgdl}\right)}$$
  （默认 $k_1 \approx 1.2$，$b \approx 0.75$）。🔧 **Elasticsearch 5.0 起默认用 BM25 取代 TF-IDF**，这正是教科书公式与工业实现的差距所在。
- **PageRank**（Page et al., 1999）：$PR(p) = \frac{1-d}{N} + d\sum_{q \in in(p)}\frac{PR(q)}{|out(q)|}$（$d\approx0.85$）——基于链接结构的**查询无关权威性**；**HITS**（Kleinberg, JACM 1999）区分 hub 与 authority。
- **作弊（spam）应对**：链接农场检测、TrustRank、以及现代搜索引擎的海量特征 + 机器学习排序（**learning to rank**：RankNet、LambdaMART，LightGBM/XGBoost 的 `lambdarank` 目标函数）。

### 21.5 评测指标
- **Precision**（检出的有多少相关）、**Recall**（相关的检出了多少）、**F1**、**MAP**（平均精度均值）、**NDCG**（考虑排序位置与多级相关性，现代首选）。
- 🔧 工程现实：线上系统的效果最终靠 **A/B 实验与在线指标**（CTR、停留时长、转化率），离线 NDCG 只是代理指标。

### 21.6 查询扩展与反馈
- **相关反馈（relevance feedback）**（Rocchio 算法）、**伪相关反馈（blind feedback）**、**同义词词典 / WordNet**、**词向量扩展**（Word2Vec → BERT/LLM embedding）。

### 21.7 现代延伸：向量检索与 RAG
- **稠密向量检索（dense retrieval）**：DPR（Karpukhin et al., EMNLP 2020）、ANCE、ColBERT（SIGIR 2020 的 late interaction）；**ANN 索引**：HNSW（Malkov & Yashunin, 2016）、IVF-PQ（FAISS）、DiskANN、ScaNN。
- **混合检索（hybrid search）**：BM25 + 向量 + 倒数排名融合（RRF）—— Elasticsearch 8 / OpenSearch / pgvector 生态的标准做法。
- **RAG（Retrieval-Augmented Generation，Lewis et al., NeurIPS 2020）**：把检索结果作为 LLM 的上下文 —— 2023 年后 IR 最大的应用场景。
- 🔧 数据库视角：PostgreSQL 的 **pgvector**（HNSW/IVFFlat 索引 + 与 SQL 事务一致）、ClickHouse/Milvus 的向量列；**向量检索正在被并入通用数据库**，而非独立系统。

## 四、近年研究与工业界开源实践

- **近年研究**：**LLM 驱动的检索**（重排序 rerank 用 cross-encoder 或 LLM；HyDE 假设性文档嵌入）；**ColBERTv2 / PLAID**（SIGIR 2022，late interaction 的效率改进）；**稀疏-稠密混合**（SPLADE）；**向量数据库的索引与过滤融合**（filtered ANN、ACORN）。
- **工业界开源**（star 数 2026-09 实测）：
  - `elastic/elasticsearch`（≈78.0k★）：倒排 + BM25 + 聚合；8.x 支持 HNSW 向量检索与 RRF 混合检索。
  - `apache/lucene`（≈3.6k★）：倒排索引与检索算法的**源码教科书**（FST 字典、PForDelta 压缩、BM25 实现、`KnnVectorQuery`）。
  - `facebookresearch/faiss`（≈41.0k★）：ANN 向量库基准实现。
  - `milvus-io/milvus`（≈46.2k★）：云原生向量数据库。
  - `pgvector/pgvector`：PostgreSQL 的向量扩展，把 ANN 与事务型 SQL 结合。
  - `qdrant/qdrant`、`weaviate/weaviate`：RAG 时代的新一代向量库。

## 五、常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "TF-IDF 是最好的排序公式" | 工业界早已默认 **BM25**（tf 饱和 + 长度归一化），TF-IDF 只作教学 |
| 2 | "倒排索引和 B+ 树索引是一回事" | 倒排服务于词项→文档的相关性检索；B+ 树服务于精确匹配与范围 |
| 3 | "PageRank 决定搜索结果排序" | 只是众多特征之一；现代排序是**数百特征 + LTR / 神经网络** |
| 4 | "相关性和召回率能同时到 100%" | 二者此消彼长，需按场景权衡（法律/医疗检索重召回） |
| 5 | 🔧 本书未覆盖 | **向量检索 / ANN / 稠密检索 / RAG / learning-to-rank** —— 这是 IR 2015–2025 年的全部重心，必须另读 Manning 教材与近年 ACL/SIGIR 论文 |
