## 一、问题清单（真实工程问题 → 通行解法梗概）

1. **「整层属性加 `readonly`/`?`/去掉 `?`，一行怎么写？」** — 映射类型修饰符三件套：`{ -?readonly [K in keyof T]: T[K] }`；`+` 可省、`-` 只能减不能加。工具类型 `Readonly/Required/Pick/Omit` 全是这一族。
2. **「深只读（deep readonly）到底防住什么？」** — 只防**编译期写操作**：递归 `readonly [K in keyof T]` 后，运行时对象照常可改、`Object.isFrozen` 恒 false——🔧 实验 M1 实测改值成功。要真墙只能 `Object.freeze`（运行时）两层叠加。
3. **「键名批量重排/加前缀/生成 getter 表？」** — 「as 键重映射」：`{ [K in keyof T as K extends string ? \`get_${K}\` : never]: () => T[K] }`；`never` 分支=删键（`Omit` 即此机关）。C++ 无对偶语法，Trait 变换只能改值类型不能改「名字」。
4. **「索引签名、Record、Map 类型三者怎么选？」** — 键是字面量联合且**异质**值：判别式对象或 Record 联合；键任意同构：`Record<string, V>`/索引签名；运行时要增删查、键非字符串：JS `Map`（类型层只是 `Map<K,V>` 类实例）。「键集合编译期可知」是本带总开关。
5. **「接口/类型别名结构相同就互相赋值，想造『名义类型』怎么办？」** — brand 惯用法：`type UserId = string & { readonly __brand: "UserId" }`——交叉一个不可构造的标记字段，用赋值语义换编译器区别对待；对照 Effective 2e「别名≠新类型」条方向 ⚠️。
6. **「多余属性检查（excess property check）为什么时对时不对？」** — 只对**新鲜对象字面量**直接赋值触发：`const o: T = {…}` 会查，先存变量再赋/展开后赋不查。不是「值类型查、引用不查」，是字面量新鲜性检查。
7. **「映射类型对 union / array / tuple  behaves 不同？」** — 同态映射（`in keyof T`）保修饰符且穿数组/tuple；union 进 `keyof` 得**交集键**、进索引访问 `T[K]` 得**联合值**——`T[K] extends …` 是否触发分发（naked 类型参数）见 [05 带](05-类型级计算食谱.md)。

## 三、🔧 最小复现（node v22.14.0 `--experimental-strip-types`，exit=0）

M1 · `dro.ts`：

```ts
type DeepReadonly<T> = { readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K] };
const cfg: DeepReadonly<{ db: { host: string; port: number } }> = { db: { host: "h", port: 5432 } };
cfg.db.host = "evil";   // 编译器红波浪线；strip-types 不查，运行时照改
cfg.db.port = 9999;
console.log(JSON.stringify(cfg), Object.isFrozen(cfg), Object.isFrozen(cfg.db));
```

实测输出：`{"db":{"host":"evil","port":9999}} false false` ✅——
「深」只深在类型层；**运行时没有一层墙**（`as` 同理：撒谎无成本，见 01 带问题 7）。

M2 · 键重映射最小形（🔧 推演，运行面=普通对象）：`Getters<Cfg>` 的键 `` `get_${K}` `` 在产物 JS 里就是普通方法名——模板字面量类型不生成代码 ✅（对照专题档实验 A）。

## 五、中英对照

| 中文 | 英文 | 一句话 |
| --- | --- | --- |
| 映射类型 | mapped type | 对 keyof 集合逐项变换 |
| 同态映射 | homomorphic mapping | `in keyof T` 保修饰符、穿数组 |
| 键重映射 | key remapping (`as`) | `never` 分支删键 |
| 修饰符增删 | modifier add/remove (`+?` `-?` `readonly`) | `-` 只能减不能加 |
| 深只读 | deep readonly | 编译期禁写，运行时零保护 |
| 品牌类型 | branded / nominal typing | 交叉不可构造标记造名义 |
| 多余属性检查 | excess property check | 只查新鲜对象字面量 |
