## 一、问题清单（真实工程问题 → 通行解法梗概）

1. **「联合类型收窄到 else 分支，我怎么知道编译器看到什么？」** — 把怀疑分支赋给 `never` 变量（`const x: never = v`），报错信息会直接打印剩余类型；这是无 IDE 时的自证术。
2. **「JSON.parse 回来是 any，到处漏。」** — 边界一律按 `unknown` 处理：`const d: unknown = JSON.parse(s)`，再用 typeof/in/谓词逐层收窄；`any` 三罪状（关检查/传染性/假信任）见 [Effective 2e Ⅰ 部方向](../Effective_TypeScript_2e/00-总览与阅读地图.md)。
3. **「自定义守卫 `(v is T)` 和返回 boolean 的函数差在哪？」** — 谓词签名让调用侧发生收窄；boolean 返回不会。谓词内部允许宽松判断，但**说谎无运行时后果**（擦除，见二.2）。
4. **「不用标准库工具类型，Partial/Pick/Record 怎么写？」** — 全是映射类型一行：`type Partial<T> = { [K in keyof T]?: T[K] }`；再造一遍是最快的映射类型入学礼（03 带主场）。
5. **「`?` 和 `| undefined` 是一回事吗？关闭开关后为什么编译不过？」** — `?` = 「可缺键」，`| undefined` = 「值可为 undefined」；`exactOptionalPropertyTypes` 打开后二者分离，`{a?: number}` 不接受显式 `{a: undefined}`。
6. **「字符串变量索引对象，TS 说 no index signature。」** — 别断言，泛化调用点：`function get<T, K extends keyof T>(o: T, k: K): T[K]`——把键的合法性推给推断。
7. **「什么时候该用断言 as？」** — 通行答案「尽量不用」：断言是**向编译器撒谎**，运行时零检查零转换（专题档戒律 2 ✅）；能 `satisfies`/收窄就别 `as`。

## 三、🔧 最小复现（node v22.14.0 `--experimental-strip-types`，exit=0）

U1 · `pick.ts` —— 工具类型是纯编译期裁剪，运行时一个字段不少：

```ts
type User = { id: number; name: string; email: string };
const u: User = { id: 1, name: "a", email: "a@b" };
const p: Partial<User> = { name: "b" };
const k: Pick<User, "id"> = u;
console.log(Object.keys(u), Object.keys(p), Object.keys(k), Object.isFrozen(u));
```

实测输出：`[ 'id', 'name', 'email' ] [ 'name' ] [ 'id', 'name', 'email' ] false`——
`Pick` 不删字段、`isFrozen` 不因 `Partial` 变真：**类型层裁剪 0 运行痕迹** ✅。

U2 · 谓词说谎面（🔧 推演，报错需 tsc）：`function isCat(v: unknown): v is {meow: 1} { return true }` 恒真——
编译器全盘相信，运行时无人复核；机制同专题档戒律 2 ✅。
