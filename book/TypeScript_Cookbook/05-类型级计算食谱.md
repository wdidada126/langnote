## 一、问题清单（真实工程问题 → 通行解法梗概）

1. **「类型层的 if-else 链太长就糊了。」** — 通行解型：条件类型**串联而非嵌套**（TS 官方风格建议）；终止垫 `never`。每加一层嵌套可读性雪崩，链式 `A extends … ? B : X extends … ? …` 尚可平读。
2. **「union 钻进条件类型，结果逐成员展开了，不想分发怎么办？」** — 分发律（distributive conditional）：`T extends U ? X : Y` 只对**裸类型参数**分发；包一层元组 `[T] extends [U]` 即关闸。`Extract/Exclude/NonNullable` 的「好使」全靠分发开着。
3. **「字符串模式匹配：路由 `/docs/page/42` 抠出资源名和页号？」** — 模板字面量 + `infer` 对拆：`` type M = R extends `/${string}/page/${infer N}` ? N : never ``；贪婪匹配坑用 `${infer H}` 再递归削尾。**全在编译期**——🔧 实验 C1 实测运行时它就是个 `typeof string` 的普通串 ✅。
4. **「类型级算术/循环没有数字，怎么数？」** — 借元组：`type Len = [1,2,3]["length"]`；累加用 `[...Acc, 1]["length"]`，字符串版 `Acc["length"]` 同样可当计数器（C1 的 `Repeat` 即此招）。
5. **「递归类型什么时候炸『Type instantiation is excessively deep』？」** — 深度上限/实例化爆炸是**编译器报错面**（约 100 层、具体阈值与版本相关 ⚠️ 不写死）；食谱解型：累加器尾递归形态、union 分块。本机无 tsc ⚠️ 欠实测。
6. **「体操解怎么带测试？」** — `Expect<Equal<A,B>>` 惯用法：`type Equal<A,B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false`，断言失败=tsc 报错——「报错即测试」（00 档实测口径原话）。需 tsc ⚠️。
7. **「类型级解析器（KV 串/路径）值得手写吗？」** — 工程裁决：路由/事件名/i18n 键这类**有限文法**可写；图灵完备倾向（真数学、真 JSON 全解析）转 schema-first 库——副标题「把体操当工程工具而非杂技」的边界在这 ⚠️ 归属推定。

## 三、🔧 最小复现（node v22.14.0 `--experimental-strip-types`，exit=0）

C1 · `tlit.ts` —— 模板字面量类型 + 字符串长度计数器：

```ts
type Route = `/${string}/page/${number}`;
const r: Route = "/docs/page/42";
type Repeat<S extends string, N extends number, Acc extends string = ""> =
  Acc["length"] extends N ? Acc : Repeat<S, N, `${Acc}${S}`>;   // 尾累加器形态
type R3 = Repeat<"ab", 3>;                                       // "ababab"
const built: R3 = "ababab";
console.log("route raw:", r, "typeof:", typeof r, "built:", built, built.length);
```

实测输出：`route raw: /docs/page/42 typeof: string built: ababab 6` ✅——
类型级「解析器」与「算术」跑完后，运行时只剩普通字符串：`Route` 不校验、`Repeat` 不生成。
反例位（🔧 需 tsc ⚠️）：`const bad: Route = "/x"` 应报错；`R3` 赋 `"abab"` 应报错——报错存在性即 00 档「@ts-expect-error 断言」实验项。
