## 一、问题清单（真实工程问题 → 通行解法梗概）

1. **「一个对象五个字段三个只在某状态下有，`?` 满天飞。」** — 判别联合正解：每状态一成员、共享字面量判别键（`kind`/`type`），非法组合**不可构造**——「make impossible states unrepresentable」的 TS 原生形态（无 nominal 帮助下的最强表达，对照 Kotlin sealed class ↔ [02 面向对象带](../Kotlin_Cookbook/02-面向对象与data-value类选型.md)）。
2. **「switch 全分支还报 not assignable to never？」** — 穷尽性哨兵：`default: const _: never = e`——加新成员忘加分支时该行变红；`assertNever` 函数是同款另一皮。
3. **「async 请求的四态（idle/loading/success/error）怎么摆？」** — 教科书形：`{kind:"loading"} | {kind:"success", data: T} | {kind:"error", error: E}`——success 带 data **不带** error；用大对象+可选字段则是把状态机交给自律。
4. **「action 联合的 reducer 里 payload 类型对不上？」** — payload 跟着判别键走：`type Action = {type:"add", a: number, b: number} | {type:"rm", id: number}`，收窄后各分支只见自己的键（🔧 D1 实测 `add` 分支读 `a+b` 成立）。
5. **「判别联合的穷尽 switch 运行时也『穷尽』吗？」** — **不！**穷尽只是编译期定理：外来数据（JSON/API）伪造 `kind:"zap"` 进来，switch 静默落空、函数返回 `undefined`，exit=0——🔧 D1 实测 ✅。运行时护栏要自己装（default 抛错 or zod 式 schema-first，即「把类型重造为值」，专题档戒律 3）。
6. **「handler map（`Record<Kind, Fn>`）替代 switch，收窄还在吗？」** — 用 `keyof` 索引类型保住：`handlers[e.kind](e)` 需 handler 签名吃 union 或用分发式泛型；map 丢穷尽检查，除非 `satisfies Record<Kind, …>` 让键集全查 ⚠️（报错位待 tsc）。
7. **「事件总线 `on("x", cb)` 怎么按事件名绑 payload 类型？」** — 事件表接口 + `keyof` 泛型：`on<K extends keyof Events>(name: K, cb: (p: Events[K]) => void)`——01 带问题 6 的总线版；对照 Kotlin Cookbook 无对偶（Kotlin 靠类型系统外库）。

## 三、🔧 最小复现（node v22.14.0 `--experimental-strip-types`，exit=0）

D1 · `disc.ts`：

```ts
type Ev = { kind: "add"; a: number; b: number } | { kind: "rm"; id: number };
function run(e: Ev): string {
  switch (e.kind) {                       // 编译期：穷尽；运行时：两条普通 if
    case "add": return "add:" + (e.a + e.b);
    case "rm":  return "rm:" + e.id;
  }
}
console.log(run({ kind: "add", a: 1, b: 2 }));
const bogus = { kind: "zap" } as unknown as Ev;   // as = 撒谎（01 带问题 7）
console.log("bogus ->", run(bogus));              // 无 default：静默 undefined
```

实测输出：`add:3` 与 `bogus -> undefined` ✅——判别键收窄的**全部运行时事实**就是
一次普通字符串属性访问；穷尽定理不出编译期。工程结论：外部数据入口必须 schema 校验（default 抛错是下限）。
