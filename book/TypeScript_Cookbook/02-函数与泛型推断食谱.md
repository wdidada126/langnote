## 一、问题清单（真实工程问题 → 通行解法梗概）

1. **「给我一个函数类型，怎么抠出它的参数表/返回值？」** — `infer` 双标准姿势：`Parameters<F> = F extends (...args: infer A) => unknown ? A : never`；返回值同理 `infer R`。这是所有 `infer` 食谱的根。
2. **「可选参数 `_cb?` 运行时算不算 arity？」** — 不算……也不对：`?` 只是类型层标记，JS 签名照常收位——🔧 实验 F1 实测 `f.length = 3`（含可选参）。**可选性是编译期的，arity 是运行时的**，两轨永不相见。
3. **「泛型恒等函数 `(x) => x` 传对象进去，出来是同一个引用还是拷贝？」** — 同一个引用：泛型参数是纯类型层变量，运行时零转换（F1 实测 `g(o) === o` ✅）。
4. **「装饰器/包装函数怎么保原函数签名？」** — 用 `A extends unknown[], R` 捕获再回放：`<A extends unknown[], R>(f: (...a: A) => R) => ((...a: A) => R)`。这是高阶食谱的模板答案。
5. **「重载（overload）写不动了，有没有 union 路线？」** — 通行口径：**优先条件返回类型/交叉，重载最后用**（Effective 2e「优先交叉而非重载」方向 ⚠️ 条号未核）；两个重载签名之间不存在「更具体者优先」的直觉保证。
6. **「字面量参数想留住 `"add"` 而不是被推成 `string`？」** — 约束加字面量类型（`T extends "add" | "rm"`）或 TS 5 的 `const` 类型参数 `<const T>`；`as const` 在调用点也可但污染表达 ⚠️（const 泛型进本带欠账：需 tsc 版 TS≥5.0 验证）。
7. **「回调里的 `this` 类型丢了/被谁吃了？」** — 首参 `this: void` 声明「本函数不许依赖 this」，防止误作方法传递；`ThisParameterType<T>` 是它的读取版。

## 三、🔧 最小复现（node v22.14.0 `--experimental-strip-types`，exit=0）

F1 · `inferfn.ts`：

```ts
type Ret<F> = F extends (...args: any[]) => infer R ? R : never;
function cb2(x: number): string { return "s" + x; }
const f = (a: number, b: string, _cb?: (x: number) => string): Ret<typeof cb2> => b;
const g: <T>(x: T) => T = (x) => x;
console.log("f.length:", f.length, "g.length:", g.length, "g(42):", g(42),
  (() => { const o = {}; return g(o) === o; })());
```

实测输出：`f.length: 3 g.length: 1 g(42): 42 true` ✅——
`infer` 抽取的返回类型**只活在编译期**；可选参进 `length`（擦除后就是普通位）；泛型恒等 = 原样引用。

F2 · 反例方向（🔧 待 tsc）：`Parameters<typeof f>` 应为 `[number, string, ((x: number) => string)?]`——
报错面/精确可选标记需 `tsc --noEmit` 配 `@ts-expect-error` 断言矩阵 ⚠️。

## 五、中英对照

| 中文 | 英文 | 一句话 |
| --- | --- | --- |
| 条件推断 | conditional inference (`infer`) | 在 extends 右侧占位捕获 |
