# 第 7 章　C 语言客户端

> 原书第 7 章是 API 部分的「另一半」：Java 之外，ZK 官方提供了 **C 客户端**，供 C/C++ 项目（以及
> 通过 C 客户端封装的其他语言）使用。核心知识点有两个：**mt（多线程）/ st（单线程）两套库**，
> 以及 C 端同样有**同步/异步**两套调用风格。这一章对纯 Java 读者可略读，对 C/C++ 基础设施开发者是
> 刚需。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 两个库：mt 与 st | `libzookeeper_mt` 自带 IO 与回调线程；`libzookeeper_st` 需调用方自己 `zookeeper_interest` 驱动事件循环 | 多线程程序用 mt，嵌入已有事件循环用 st |
| 建立连接 | `zookeeper_init(host, watcher, recv_timeout, clientid, context, flags)` | 返回 `zhandle_t*`，同样**不保证已连上**，靠 watcher 状态 |
| 同步 API | `zoo_create / zoo_get / zoo_set / zoo_get_children / zoo_exists ...` 阻塞返回 `ZOK` 或错误码 | C 没有异常，一律用**返回码 + 输出参数** |
| 异步 API | `zoo_acreate / zoo_aget / zoo_aset / ...` 配 `void* completion` 回调 | 回调在 mt 库的 IO 线程或 st 的事件循环里触发 |
| 监视器与状态 | C 的 watcher 回调 `(zk, type, state, path, watcherCtx)` 与 Java 同源 | 仍需先判 `state` 再判 `type` |
| 编译与链接 | 依赖 `pthread`（mt）、`cppunit`（测试），头文件 `zookeeper.h` | C 客户端是「C 封装 + C++ 实现」，编译要 C++ 工具链 |

## 核心精讲

（以下为教学性梳理，C 片段均**教学示意，不参与构建**。）

### 7.1 mt vs st：谁驱动事件循环

| 库 | 事件循环由谁驱动 | 适用 |
| --- | --- | --- |
| `libzookeeper_mt`（多线程） | 库内部起 IO 线程 + 回调线程，自动处理网络与超时 | 普通多线程应用，最省心 |
| `libzookeeper_st`（单线程） | 调用方周期性调 `zookeeper_interest()` 拿到 fd/超时，自己 `zookeeper_process()` 喂事件 | 嵌入 libevent / libuv / 自有事件循环 |

```c
/* 教学示意，不参与构建：mt 库最简连接 */
zookeeper_init("127.0.0.1:2181", my_watcher, 15000, 0, NULL, 0);
/* 连接状态在 my_watcher 里用 state 判断，和 Java 的 Watcher 思路一致 */
```

### 7.2 C 的同步 API：返回码 + 输出参数

```c
/* 教学示意，不参与构建：创建节点并读取 */
char buf[1024]; int buflen = sizeof(buf);
struct Stat stat;
int rc = zoo_create(zh, "/app/config", "v1", 2,
                    &ZOO_OPEN_ACL_UNSAFE, 0, NULL, 0);
/* rc == ZOK 成功；ZNODEEXISTS 等错误码直接返回，无异常 */

rc = zoo_get(zh, "/app/config", 0, buf, &buflen, &stat);
/* 数据写入 buf，长度回写 buflen，元数据写入 stat */
```

- C 没有异常，所有错误走返回码（`ZOK / ZCONNECTIONLOSS / ZNONODE / ZNODEEXISTS ...`），
  与 Java 的 `KeeperException.Code` 一一对应；
- 这与第 3 章 Java 异常体系是**同一套语义的不同表达**，迁移语言时概念可直接复用。

### 7.3 C 的异步 API：回调签名的几个坑

```c
/* 教学示意，不参与构建：异步创建 */
void create_completion(int rc, const char *name, const void *data) {
    /* rc: 返回码；name: 实际创建路径(含顺序号)；data: 透传上下文 */
}
zoo_acreate(zh, "/app/tasks/task-", "payload", 7,
            &ZOO_OPEN_ACL_UNSAFE, ZOO_SEQUENCE, create_completion, "ctx");
```

- `zoo_acreate` 末尾的 `string_completion` 回调在 **mt 的 IO 线程**或 **st 的事件循环**里调用；
- 注意：回调里**不要做长耗时操作**，否则阻塞 IO 线程会拖垮整个客户端（mt 尤其明显）。

### 7.4 监视器回调：先 state 后 type

```c
/* 教学示意，不参与构建：C watcher 形态 */
void my_watcher(zhandle_t *zh, int type, int state, const char *path, void *ctx) {
    if (state == ZOO_CONNECTED_STATE) {
        /* 连接已建立（type 此时通常是 ZOO_SESSION_EVENT） */
    } else if (state == ZOO_EXPIRED_SESSION_STATE) {
        /* 会话过期：重建句柄、重注册（同第 5 章） */
    } else if (type == ZOO_CHANGED_EVENT) {
        /* 节点数据变化：重新 getData 并视需要重注册 watch */
    }
}
```

- 与 Java 完全同构：`state` 是连接级，`type` 是节点级，必须先分流再处理。

## 版本演进

- **本书无第二版**；本节写 2013 年口径 → 2026 年视角的变化。
- **C 客户端的 mt/st 双库形态在 3.5+ 基本稳定**，API 向后兼容；但**新项目更常通过语言原生客户端
  （Go/Python/Rust）而非 C 客户端**间接使用 ZK，C 客户端主要服务老 C/C++ 基础设施。
- **C 客户端的编译依赖（`pthread` + C++ 工具链）在容器化 / musl 环境下偶有坑**，2026 年部署时
  需注意静态链接与符号可见性（见第 10 章运维）。
- **libzookeeper 与 Curator（Java）不是替代关系**：C 侧没有等价于 Curator 的官方高层封装，
  复杂配方要自己实现或借 `zkclient`（社区）封装。

## 近年研究与工业界开源实践（2015–2026）

- **C/C++ 生态更常用其他协调客户端**：Go（`go-zookeeper`）、Rust（`zookeeper-async`）、Python
  （`kazoo`）等社区客户端逐年活跃，纯 C 客户端的相对份额在下降。
- **etcd 的 gRPC 客户端同样有 C/C++ binding**：`etcd-io/etcd`（52309★）的 clientv3 提供多语言绑定，
  新 C++ 基础设施若选 etcd 而非 ZK，走 gRPC 路线，与本章 C 客户端对照。
- **ClickHouse Keeper（C++ 实现 ZK 协议兼容）**：`ClickHouse/ClickHouse`（50091★）用 C++ 实现
  兼容 ZK 协议的协调服务，是「ZK 协议 + 非 JVM 实现」的工业样本，对 C/C++ 基础设施有参考意义。
- **ZK 自身**：`apache/zookeeper`（12811★）C 客户端随发行包提供，持续维护。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「C 客户端和 Java 客户端行为不同」 | 共享同一套 ZK 语义（watch / 顺序 / 会话），只是异常 vs 返回码的表达差异 |
| 2 | 「mt 库不需要关心线程安全」 | 回调在库线程触发，回调内共享数据仍需自己加锁；长耗时操作会阻塞 IO 线程 |
| 3 | 「st 库比 mt 更简单」 | st 要自己驱动 `zookeeper_interest/process` 事件循环，集成进现有事件框架才省心 |
| 4 | 🔧 第 7 章未提容器/musl 下的编译坑 | 2026 年 C 客户端在 Alpine/musl、静态链接场景有符号与线程库坑，需补 |
| 5 | 🔧 未提 C 侧缺 Curator 级高层封装 | C/C++ 复杂配方要自实现，或借社区 `zkclient`，与 Java 生态差距需说明 |
| 6 | 🔧 未对比 etcd gRPC C++ binding | 新 C++ 基础设施多走 etcd gRPC，与 ZK C 客户端路线不同，选型应补 |
