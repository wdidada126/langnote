## 核心精讲

### 1. 慢查询归因四步（Ch10）

1. `EXPLAIN (ANALYZE, BUFFERS)`：比 `actual rows` vs `plans rows`，偏差 >10× 即统计问题；
2. 看节点形态：顺扫大表 → 缺索引或索引失剪；嵌套循环行数爆炸 → join 顺序/连接键类型不匹配；
3. `shared_blks_read` 高 → IO 问题（回表/冷数据/膨胀），与 [04-监控诊断与日常维护.md](04-监控诊断与日常维护.md) 的 pg_stat_io 呼应；
4. 修完回归：`pg_stat_statements` 取 mean 时延做前后对照。

文档转述 ⚠️：

```sql
EXPLAIN (ANALYZE, BUFFERS, SETTINGS) SELECT ...;
ANALYZE VERBOSE orders;
SET LOCAL enable_nestloop = off;   -- 诊断用：验证代价模型偏好，禁作调优手段
```

### 2. 统计与扩展统计（Ch10）

- `default_statistics_target`（列级可调）换直方图精度；表达式索引会触发隐式 `ANALYZE` 表达式统计。
- 多列相关性：`CREATE STATISTICS s1 (dependencies, ndistinct) ON col_a, col_b FROM t;`——
  PG16 优化器对组合条件的行数估算明显更稳（✅ 16.0 发行说明含"增量排序覆盖更多场景（含 DISTINCT）"等改进）。

### 3. 并行查询的开关与边界（Ch10）

```text
max_parallel_workers_per_gather = 2       # 单查询并行度上限
parallel_workers = 8                      # 表级存储属性，给大表固定并行度
min_parallel_table_scan_size = 8MB
```

- 并行只治**扫描/聚合/连接**，不治写路径；Gather 以上才值得并行。
- PG16 并行面扩大（✅ 发行说明）：**FULL 外连接与内部右外连接哈希 join 可并行**；逻辑订阅端**大事务并行应用**；
  顺扫可借助同步顺序扫描（多后端共享游标，冷数据批量读不再各扫一遍）。
- 判据：并行后 `blocks` 读放大但时延下降才真正赚；OLTP 短查询常因 `parallel_setup_cost` 直接放弃并行。

### 4. JIT（Ch10）

- `jit=on` 且代价超 `jit_above_cost`（默认 100000）时编译表达式/聚合；小查询被编译开销反噬，
  短事务系统建议关 JIT 或调高门限；`EXPLAIN` 里 `JIT:` 块给出 functions/inlining/timing 分解。

### 5. 索引做减法（Ch10，呼应 Ch9）

- BRIN 超大表按时间列（体积近乎免费）；部分索引 `WHERE flag` 治布尔倾斜；表达式索引对齐查询谓词写法。
- 删冗余索引前先 `pg_stat_user_indexes.idx_scan` 观察一个完整业务周期；PG16 的 `REINDEX ... CONCURRENTLY`
  与在线删除是低峰维护的标准动作。

### 6. 锁、死锁与乐观并发（Ch10）

```sql
SELECT l.pid, l.locktype, l.relation::regclass, l.granted, a.query
FROM pg_locks l JOIN pg_stat_activity a USING (pid) WHERE NOT l.granted;
SELECT * FROM pg_stat_activity WHERE wait_event_type = 'Lock';
```

- 死锁：`log_lock_waits=on` + `deadlock_timeout`（默认 1s）进日志，PG 自动杀代价小的那一方。
- 悲观：`SELECT ... FOR UPDATE NOWAIT/SKIP LOCKED`（任务队列模式标准写法）；
  乐观：行上带 `version`/`xmin::text` 比较，更新语句 `WHERE id=$1 AND version=$2`，受影响行数 0 即冲突重试——
  本书"乐观锁"食谱与 `xmin` 系统列技巧同源。

## 常见坑与判读

| 症状 | 根因 | 处置 |
| --- | --- | --- |
| 并行没起来 | `max_parallel_workers_per_gather=0` 或查询含不可并行节点（部分自定义函数） | `PARALLEL SAFE` 标注、检查计划无 Gather |
| JIT 让快查询变慢 | 编译开销 | `jit=off` 或调高门限 |
| 索引越加越慢 | 写放大 + 优化器误选 | idx_scan 审计、冗余索引删除 |
| 偶发 deadlock detected | 两事务反序加锁 | 统一加锁顺序 / NOWAIT 快速失败重试 |

## 核心概念速览（中英对照）

- **执行计划** — query plan：EXPLAIN 产物；ANALYZE 选项真实执行并回填行数。
- **统计目标** — statistics target：直方图桶数，列级可调精度。
- **扩展统计** — extended statistics：多列依赖/相关性建模。
- **Gather 节点** — parallel gather：并行子进程结果汇合点，并行收益的分水岭。
- **同步顺序扫描** — synchronized sequential scans：PG16 多后端共享顺标游标。
- **JIT 编译** — LLVM just-in-time：表达式/聚合的即时编译，大查询受益。
- **BRIN** — block range index：超大规模有序表近似零成本索引。
- **部分索引** — partial index：带 WHERE 的小索引。
- **并发建索引** — CREATE INDEX CONCURRENTLY：两遍扫描不锁写。
- **FOR UPDATE SKIP LOCKED** — 悲观锁跳过：任务队列标准姿势。
- **乐观并发控制** — optimistic concurrency：版本比较 + 冲突重试。
- **死锁检测** — deadlock detector：wait-for 图破环，杀代价小者。

## 最新演进与工业实践

- **PG17（✅ 发行说明）**：顺扫流式 IO、多值 `IN` 的 B-tree 搜索优化、高并发下写吞吐改进；VACUUM 内存体系重做。
- **PG18（✅）**：异步 I/O 子系统（`io_uring`）使顺序扫描/位图扫描等读路径管道化，官方定位为"性能形态级变化"；
  B-tree **skip scan** 让多列索引在更多查询里可用（`ONLINE` 级 B-tree 改良）；`uuidv7()` 终结随机 UUID 主键的
  索引局部性灾难。
- **并行演进时间线**：并行查询自 PG9.6/10 起步，PG16 补上"FULL/RIGHT OUTER 哈希连接并行 + 逻辑复制并行应用"
  （✅ 16.0 发行说明）；写路径并行仍不在路线图上（社区 RFC 阶段，⚠️ 转述）。
- **工业实践**：慢查询治理平台（pt-query-digest 的 PG 对应物 pgBadger + pg_stat_statements 采集器）+
  自动索引推荐（OtterTune/phoenixai 一类研究系统，⚠️ 转述不作依据）；2024–2026 生产圈共识仍是"统计先行、索引做减法、
  并行看表体量"，与本书口径一致。
