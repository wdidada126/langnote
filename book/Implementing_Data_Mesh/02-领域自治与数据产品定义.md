# 02 · 领域自治与数据产品定义——所有权落到工件上

> 主题重构册声明：本章章题为笔记作者编排，非原书目录（见 `00` §4）。#201 的 02/03 章（领域所有权、数据即产品）是本章的范式上游，本章只写"从原则到工件"的增量。

## 2.1 域不是部门：切分判据的工件化

#201 给了 DDD 战略设计的移植（见 [Data_Mesh/02-领域所有权原则](../Data_Mesh/02-领域所有权原则.md)），实现侧的痛点是**判据无法自动执行**。本书一侧的解法思路（⚠️ 主题级重构，据作者公开工件归纳）：把"域"登记为一个**有主工件**——域注册表条目含 owner、上游源、下游消费承诺。落到工程上：

1. **一个域至少一个数据源适配器 + 至少一个产品接口**：源（数据库 CDC、文件、API）归域封装，消费者不得直连源——类比 🔧-B 的只读挂载。
2. **域的边界=写权限的边界**：域内表只有域团队可写；跨域取数一律走"已发布接口"。
3. **域原型（domain archetype）裁剪义务**：源域（source-aligned）、消费者域、提供者混合域承担不同的契约义务——这条直接继承 #201 02 章三分法，本书贡献是把它写进模板/脚手架（⚠️ 推断）。

## 2.2 数据产品的五件套定义

综合 ODCS/ODPS 线（Perrin 系谱 ✅）与本书副题，一个"数据产品"在工件层面=以下五件齐备，缺一件则退回"数据集"：

| 工件 | 内容 | 缺失后果 |
|---|---|---|
| 契约（contract） | schema、质量规则、SLA、语义定义 | 消费者不敢用 |
| 接口（port） | 批表/流主题/文件/API 至少一种 | 用不了 |
| 元数据（catalog entry） | 可发现：负责人、域、样例、血缘锚点 | 找不到 |
| 文档与样例 | 可读：字段业务含义、示例查询 | 不会用 |
| 运维承诺 | 可观测：新鲜度、就绪探针、事件通知 | 用不长 |

这与 #201 03 章"消费者旅程五步"（发现→理解→消费→信任→组合）逐件对位——**五件套就是五步的工件名**。

## 2.3 所有权经济学：谁付计算与存储的账

实现向册绕不开的问题：产品接口背后的存储/计算成本归属。可执行的切分（⚠️ 主题级）：域承担**发布面**成本（转换后的产品存储、接口出口流量），消费者承担**读取面**成本（查询计算）——这与湖仓"表格式归域、引擎归消费者"的分账结构一致，参见 [Data_Lakehouse_in_Action/00](../Data_Lakehouse_in_Action/00-总览与阅读地图.md)。联邦治理下的补贴问题（平台向产品团队收内部账单）本书语焉不详处 ⚠️，可回看 #201 04 章平台经济学论证。

## 2.4 案例走查：气候观测域的产品化（⚠️ 重构口径）

以 1.4 的贯穿形状演示"源→产品"三步：

1. **源封装**：机构 A 的原始观测 CSV（单位混杂、缺测以 -999 表示）进域落地区，域内转换清洗——原始形状永不出域。
2. **产品定义**：`obs-clean` 产品=观测表 + 契约（单位声明 ℃、值域 [-100,100]、缺测=NULL、日更新 SLA）+ 批接口（表）+ 流接口（增量事件）。
3. **发布**：契约与元数据进目录（06 章），接口进市场可检索。

关键实现判断：**缺测语义是契约的一部分**，不是 schema 的一部分——`-999` 与 `NULL` 类型兼容但语义相反，纯结构校验拦不住（03 章语义层由此获得存在理由）。

## 2.5 🔧 类比实验组（SQLite/DuckDB 本机实测，**非本书平台行为**）

**🔧-E 域内接口自洽性（本章最硬的一条类比）**：SQLite 强制"视图不得引用其他附加库的对象"——

```sql
CREATE VIEW orders_dp.v_x AS SELECT 1 FROM customers_dp.customers;
-- 实测报错：view v_x cannot reference objects in database customers_dp
```

即：**产品接口（视图）必须在域库内自洽定义**，跨域组合只能发生在消费侧查询里。实测消费侧组合成功：`SELECT v.order_id, v.api, u.region FROM orders_dp.v_order_enriched v JOIN customers_dp.customers u ...` → `[('o1','v1','EU'),('o2','v1','EU')]`（E2）。这是"域自治+联邦组合"在单机引擎里的意外精确投影。

**🔧-F 只读消费面**：域库以 `mode=ro` 挂给消费者，写被拒（E2，`attempt to write a readonly database`）——所有权边界的物理面。

**🔧-G 域文件即部署单元**：三域三文件独立建表、独立提交（`db()` 各自 `CREATE TABLE ... STRICT`），主库表数 0（E1）——"域拥有其数据"的文件级类比；域销毁=删文件，无中心库残留。

**🔧-H DuckDB 跨域只读联邦 join**：`SELECT o.order_id, c.temp_c FROM orders_dp.main.orders o, climate_dp.main.obs c` 实测返回 4 行笛卡尔（E5）——组合发生在查询引擎，不在数据所有权层。

## 2.6 反模式清单（实现向）

- **共享库反模式**：两域共写一表=契约双方互踩；类比：若允许 🔧-E 的跨库视图，域内重构会静默破坏他域接口。
- **裸表发布反模式**：只有接口没有契约/目录条目——"产品"退化为"别人库里的表"。
- **源直连反模式**：消费者绕过产品直连 CDC 源，域失去演化自由（04 章兼容性策略失效）。
- **域=微服务教条反模式**：为每个微服务配一个数据产品，产品数爆炸但无消费——先验证消费存在（#201 03 章产品度量的实现侧回声）。

## 2.7 本章要点回写

1. 域自治的工件表达=写权限边界+只读发布面+域内自洽接口。
2. 数据产品五件套：契约/接口/元数据/文档样例/运维承诺，与 #201 消费者旅程一一对位。
3. 成本分账：发布面归域、读取面归消费者。
4. 缺测语义教训：结构兼容≠语义兼容，为 03 章铺题。

## 2.8 切域判据清单（实现侧打分用）

对候选域逐项打分（满足=1），≥4 建议独立成域，≤2 并入邻域（⚠️ 阈值为主题级建议）：

1. 有独立的数据生命周期决策权（谁能改口径不用开会）；
2. 有专属写路径（源系统/采集面主要服务该候选）；
3. 有可识别的外部消费者≥1 且愿意签契约；
4. 有独立的更新节奏（新鲜度 SLA 与邻域显著不同）；
5. 有独立的合规暴露面（隐私等级/监管域不同）；
6. 组织上已有事实上的数据 owner（康威顺向）。

判据 6 最容易被忽略但权重最高：**没有既成 owner 的域，契约签了也没人履约**——#201 其 `02` 章"域≠部门"的实现侧对偶：域必须能指到人名。
