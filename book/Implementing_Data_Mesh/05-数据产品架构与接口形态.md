# 05 · 数据产品架构与接口形态——端口、适配器与内嵌元数据

> 主题重构册声明：本章章题为笔记作者编排，非原书目录（见 `00` §4）。#201 第四部分（其 09–12 文件）是产品架构的范式上游，本章写实现半区：接口工件与产品内部构造。

## 5.1 产品=洋葱：核心、契约壳、接口壳

把数据产品画成三层同心圆：

1. **核心层**：域的私有实现（原始落地区、转换管线、私有表）——**永不对消费者开放**（02 章源直连反模式的正面表述）。
2. **契约壳**：03 章契约工件+质量执行器，包住核心的每次对外供数。
3. **接口壳（ports）**：批表、流主题、文件对象、API 查询等若干消费端口，每端口绑定同一契约（多形态单承诺）。

端口的价值：**演化自由**。核心层重构（换存储、改管线）只要契约壳判卷通过，接口壳与消费者零感知——这是"数据即产品"区别于"共享表"的结构根因。

## 5.2 接口形态学：批、流、文件、API 的选型表

| 端口形态 | 典型载体 | 契约映射点 | 适用 |
|---|---|---|---|
| 批表 | Iceberg/Delta 表 | 快照级质量判卷+schema 兼容 | 分析/训练集 |
| 流 | Kafka 主题+注册表 | 事件级校验（🔧-K 的逐行形态） | 新鲜度敏感消费 |
| 文件对象 | Parquet/CSV on 对象存储 | 批次指纹+清单契约 | 跨组织交换（气候案例主形态 ⚠️） |
| API | REST/GraphQL 查询 | 请求级 SLA+响应契约 | 点查、小数据高并发 |
| SQL 联邦 | 查询引擎外表 | 只读挂载+目录鉴权 | 即席分析（🔧-E/H 类比） |

选型纪律：**先问消费模式再定端口**，一个产品可多端口但只有一份契约——多份契约=多个产品（02 章五件套的计数规则）。流式端口的语义底座（水位线、精确一次）在 [Streaming_Systems/00](../Streaming_Systems/00-总览与阅读地图.md)。

## 5.3 适配器：入站封源、出站塑形

- **入站适配器**：把源系统形状（CDC 事件、机构 A 的 CSV）翻译成域内规范形状；-999→NULL 这类清洗住在这里，**不进消费者视野**。
- **出站适配器**：把核心形状投影成端口形状（表→流信封、内部列名→契约列名）。
- 架构原型=端口-适配器（六边形），与 #201 其 `10` 文件的 ports/adapters 叙事同构；本书增量是给出适配器脚手架/模板方向（⚠️ 主题级）。

## 5.4 内嵌元数据：产品随身携带的说明书

产品边界内应随数据走的最小元数据包：**契约指纹（03 🔧-J）、新鲜度戳、行数/分区清单、血缘锚点（上游产品 URN 列表）、样例查询**。反集中主义：目录（06 章）是这些元数据的**索引**而非**宿主**——目录挂了产品仍可被信任消费（文件旁挂 sidecar 清单），这是可供性设计（#201 其 `09` 文件）的实现化。

## 5.5 🔧 类比实验组（SQLite/DuckDB 本机实测，**非本书平台行为**）

**🔧-Q 出站投影=视图适配器**：域内 `CREATE VIEW v_order_enriched AS SELECT order_id, amount, 'v1' AS api FROM orders`——核心表 `orders` 加列改名都可由此视图吸收；实测消费侧只见接口列集（E2）。

**🔧-R 单底座多端口**：同一 `readings` 表，批端口=视图 `obs_v1`，"新特性端口"=`obs_v2`（含 quality 列），实测两端口并行供数互不干扰（E10）——批/表双投影的多端口类比。

**🔧-S 跨引擎端口等价**：SQLite 域文件被 DuckDB `ATTACH ... (READ_ONLY)` 直接当外表消费，实测 `[('o1', 12.5), ('o2', 7.0)]`（E5）——"同一产品，不同查询引擎端口"的最小演示（DuckDB 自带 sqlite 扩展自动加载，零新装）。

**🔧-T 元数据内嵌=目录可重建**：`duckdb_tables()` 跨附加域枚举 `[('climate_dp','obs'), ('orders_dp','orders')]`（E6）——目录内容可从产品侧自省重扫得到，证明"目录是索引不是宿主"在单机可演示；真实平台中该扫描换成清单文件+心跳。

## 5.6 产品内部参考拓扑（气候域，⚠️ 重构口径）

```
机构CSV/传感器 → [入站适配器: 清洗+单位归一] → 落地区(私有)
   → [核心: 观测规范模型(私有表)] → [契约壳: 质量判卷+指纹]
      → 端口1 批表(分析)   端口2 文件交换(跨机构)   端口3 流(告警)
   → [sidecar: 契约指纹+新鲜度+血缘锚点] → 目录索引(06章)
```

## 5.7 本章要点回写

1. 三层洋葱：私有核心不可见、契约壳单点承诺、接口壳多形态。
2. 端口选型跟着消费模式走；多端口一契约。
3. 入站封源出站塑形，演化自由由此而来。
4. 元数据内嵌随身走，目录只是索引。

## 5.8 端口选型决策树（文字版）

```
消费频率?
├─ 每次几行、亚秒应答 ──────────────► API 端口（缓存层自理）
├─ 批量扫描、天级新鲜度可忍
│   ├─ 数据量 > 网络交换舒适区? ────► 批表端口（表格式，湖仓底座）
│   └─ 跨组织/无共享基础设施? ─────► 文件端口（清单+指纹随包）
└─ 分钟级以下触发需求?
    └─ 有事件语义要求(顺序/去重)? ──► 流端口（水位线契约见 Streaming 册）
                                        否则考虑批表短周期快照（便宜一档）
```

叶子节点的共同纪律：**每个端口在契约里显式声明其形态与 SLA 差异**——流端口新鲜度 P5M、批端口 P1D 是同一承诺的两个投影，不是两份承诺。

## 5.9 内嵌元数据包字段表（sidecar 最小集）

| 字段 | 内容 | 消费者用途 | 更新时机 |
|---|---|---|---|
| contract_fingerprint | 契约文本哈希（🔧-J） | 校验"我读的数据配哪版契约" | 每次发布 |
| product_urn | 产品全局身份 | 订阅/账单/血缘主键 | 不变（major 除外） |
| freshness_stamp | 最近成功供数时刻 | 判 SLA、决定重试 | 每批次 |
| row_manifest | 分区/行数清单 | 增量消费游标、完整性自检 | 每批次 |
| upstream_urns | 上游产品 URN 列表 | 影响面分析（上游违约时定位自己） | 每次拓扑变更 |
| sample_query | 一条可跑通的示例 SQL | 上手理解（比文档有效） | 契约 major 时复核 |
| violation_feed | 违约事件指针 | 消费前查信用 | 平台回写 |

设计约束：sidecar 必须与数据**同生命周期原子更新**（写数据失败则元数据不得先行）——否则 🔧-T 的重扫重建会得到自相矛盾的目录。
