# 06 · 自助平台与数据产品市场——从目录到工厂

> 主题重构册声明：本章章题为笔记作者编排，非原书目录（见 `00` §4）。内容基底=Broda 的 Backstage 仓库线 ✅、#201 平台叙事（其 04/08/11 文件）、通用平台工程实践。

## 6.1 自助平台的判定线：12 项清单的工件化

#201 其 `04` 给了自助能力清单与平台失败模式；实现侧的判定更冷酷：**平台是产品不是项目**——有版本、有迁移公告、有内部 SLA、有"拒绝定制"的边界。落到本书主题的最小供给面：

1. **创建面**：产品脚手架模板（目录条目+契约骨架+适配器样板+CI 流水线四件套一键生成）。
2. **运行面**：托管的转换/校验执行器（04 章门3 的运行时宿主）、端口托管（表服务、主题、查询联邦入口）。
3. **消费面**：发现（目录）、申请（访问工作流）、订阅（契约变更/违约通知）。

三面对应平台三角色：产品开发者、平台团队、消费者——平台团队**不碰域逻辑**，只碰供给质量。

## 6.2 目录→注册表→市场：三段演进

| 阶段 | 能力 | 工件形态 | 风险 |
|---|---|---|---|
| 目录 catalog | 可发现：搜索、页面 | Backstage kind + 契约 sidecar 索引 | 信息过期 |
| 注册表 registry | 可判定：契约/版本/兼容性入册 | 契约 URN 全局解析（03 🔧-J） | 双主漂移 |
| 市场 marketplace | 可交易：订阅、计量、评价、SLA 挂牌 | 消费关系图+账单+信用分 | 治理真空下的劣币 |

Broda 的 `data-mesh-catalog`（"Loadable Backstage Catalog" ✅）与 `sample-dataproducts`/`sample-orgs`/`sample-systems` 仓库群给出目录段的实体形态：**数据产品作为 Backstage 一等实体（custom kind），owner/system 关系复用其 org model**——目录不是另建系统，而是接进已有工程门户。市场的"交易"并非买卖，而是**订阅关系+履约记账**（07 章度量）。

## 6.3 工厂化生产：产品线的流水线抽象

"数据产品工厂"=把 6.1 创建面做成流水线：模板实例化 → 契约 lint → 测试数据判卷 → 目录注册 → 端口开通。关键工件：**黄金路径（golden path）**——合规产品 10 分钟上线，越轨路径处处红灯（paved road 策略，靠 04 章 CI 门执行）。工厂的度量=产品从想法到可消费的 lead time，与 #201 其 `13` 章执行框架的阶段门对齐。

## 6.4 平台与域的责任切分表

| 责任 | 域 | 平台 |
|---|---|---|
| 契约内容与阈值 | ✅ | 提供模板 |
| 校验执行 | 声明 | ✅ 托管运行 |
| 端口可用性 | 消费承诺方 | ✅ 供给 SLA |
| 目录新鲜度 | 提交变更 | ✅ 索引重建 |
| 违约通知路由 | 订阅方 | ✅ 事件总线 |

灰区裁决原则：**谁拥有信息优势谁负责，谁拥有规模效应谁建设**——语义归域，机制归平台。

## 6.5 🔧 类比实验组（SQLite/DuckDB 本机实测，**非本书平台行为**）

**🔧-U 目录自省=最小注册表**：DuckDB `SELECT database_name, readonly, internal FROM duckdb_databases()` 实测返回 `[('mesh',False,False), ('orders_dp',True,False), ('climate_dp',True,False), ('system',False,True), ('temp',False,True)]`（E6）——**注册表本质是一张带属性的实例清单**：库名=产品 URN、readonly=发布态、internal=私有核心不外露。

**🔧-V 跨域枚举=目录爬取**：`duckdb_tables()` 只枚举出 `[('climate_dp','obs'), ('orders_dp','orders')]`（E6）——`temp`/`system` 被过滤，正如目录应只索引"已发布"对象；主库 `main` 当时表数为 0（E1），中心不存业务数据——**目录无宿主原则**（5.4）的单机投影。

**🔧-W 黄金路径=宏/模板复用**：平台宏 `dp_quality(t)` 一次注册、任意产品查询引用，实测三行判卷 `[('S2',True),('S3',False),('S4',False)]`（E8）——工厂供给"可执行合规件"，域只声明引用。

**🔧-X 订阅通知基线=指纹比对**：契约 JSON 文本 sha256 前 16 位 `87bcc56b76a69422`（E7）——市场向订阅者推送"契约变更"的原始机制就是新旧指纹 diff；真实平台里换成事件总线，但幂等判定仍靠指纹。

## 6.6 平台失败模式（实现侧速查）

- **门户幻觉**：只建目录不建执行面——产品照样手工上线，目录沦为过期黄页（对策：注册与 CI 门3 强绑定）。
- **平台越位**：平台团队代写域契约——语义错误域背锅、责任倒挂。
- **模板锁死**：黄金路径唯一化，特殊消费模式（高频小查询）被迫走旁门，两年后影子平台复活（#201 其 `04` 章"平台殖民"失败模式的工程显形）。
- **市场无信用**：违约不降权（4.6），消费侧用脚投票前市场已劣币化。

## 6.7 本章要点回写

1. 平台三供给面：创建/运行/消费；平台是产品。
2. 目录→注册表→市场是能力叠加不是系统替换；Backstage 线给了目录段实体形态 ✅。
3. 工厂=黄金路径+CI 门；度量用 lead time。
4. 责任切分：语义归域、机制归平台、灰区看信息优势与规模效应。

## 6.8 平台 API 面清单（自助的"自助"具体指什么）

| 面 | 端点/入口（抽象） | 调用方 | 后端工件 |
|---|---|---|---|
| 产品创建 | `POST /products`（模板实例化） | 域开发者 | 脚手架+流水线触发 |
| 契约注册 | `PUT /contracts/{urn}` | CI 门1/2 | lint+兼容判定+指纹入库 |
| 端口开通 | `POST /ports` | 模板自动 | 表/主题/文件桶供给 |
| 目录查询 | `GET /search?q=` | 消费者 | sidecar 索引（🔧-T 重扫） |
| 访问申请 | `POST /grants` | 消费者 | 审批流+只读挂载下发（🔧-F/U） |
| 订阅 | `POST /subscriptions` | 消费者 | 变更/违约通知路由 |
| 巡检 | 定时任务（🔧-Y/AA） | 平台自身 | 影子对象扫描+SLA 达成率 |

验收"自助"的硬标准：**上述全部无需工单/无需人等**；任何一格退回人工，平台即从产品降级为脚本集合。

## 6.9 市场最小数据模型（五张表）

```
product(urn, owner, status, contract_fp, created_at)
port(port_id, product_urn, kind, sla)          -- 一产品多端口(05 §5.2)
subscription(sub_id, product_urn, consumer, since, tier)
event_log(ts, product_urn, kind{change|violation|grant}, detail)
credit(product_urn, sla_attain, violation_30d,活跃度)  -- 派生视图
```

`credit` 就是 4.6"降权"与 6.6"市场无信用"反模式的正面对治：市场排序=信用分，信用分全部来自 event_log 派生，**无人工调权入口**（有则治理回潮）。

## 6.10 供给面与 05 章接口面的关系

05 章管"一个产品内部怎么搭"（微观），06 章管"一百个产品怎么被生产与发现"（宏观）；两章的接缝恰是 sidecar：产品内部把它写对（5.9 原子性），平台才能免登记地索引（🔧-T 重扫即得目录）。**接缝设计得好，平台薄；接缝靠人肉，平台厚**——这是自助平台最重要的架构判据。
