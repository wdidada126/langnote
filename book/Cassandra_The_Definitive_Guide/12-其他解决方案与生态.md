## 12.1 题纲

1. 横向坐标系：Cassandra vs HBase / MongoDB / Redis / 关系分片中间件——按"数据形状×
   访问模式×一致性预算"三维定位
2. Cassandra vs HBase：同为 BigTable 谱系的分歧（去中心 vs 中心 Master、可变 vs 不可变
   压实叙事、tserver 运维面）
3. Cassandra vs MongoDB：文档模型自由度 vs 分区纪律；2i/聚合缺失的两种哲学
4. Cassandra vs Redis：宽列权威存储 vs 内存加速层——配对而非竞品（09 章回环）
5. Spark 集成：cassandra-spark connector 的读写路径（RDD/DataFrame 时代 ⚠️）、谓词下推边界
6. Solr/ES 集成：Cassandra 当写权威、搜索侧建索引的双写架构与漂移对账
7. Hadoop 时代余音：cassandra-hadoop（bulk loader/outputformat）、Pig/Hive 桥 ⚠️
8. 趋势章的 2026 重写：从"书中提到的候选者"到"今天的现实格局"逐条对位

## 12.2 选型坐标（书中判词重构 ⚠️）

| 需求形状 | 书中首选倾向 | 理由一句话 |
|---|---|---|
| 海量写+按主键点查/范围+多活 | Cassandra | 分区模型+AP 旋钮的主场 |
| 复杂遍历/二级检索重 | HBase(协处理器/Phoenix) 或 搜索层 | Cassandra 缺即席查询语法 |
| 文档式灵活 schema+二级索引多 | MongoDB（书内语境） | CQL 的建模纪律相反 |
| 小热集+毫秒读+可重建 | Redis 作缓存+权威在后 | 内存成本曲线不允许当仓库 |
| 强关系约束+事务+JOIN 重 | 关系库（或 NewSQL 前身叙事） | 别用 LWT 硬凹 |

判词的当代校验（⚠️ 转述系列共识）：坐标没有搬家——2026 的选型讨论只是把"即席分析"
一栏的候选换成了湖仓（Iceberg/Delta）+ 把"检索"换成 ES/向量库（00 §7 兄弟目录挂点）。

## 12.3 Spark：把 OLAP 外包（2.x 时代 connector ⚠️）

书中形态：`spark-cassandra-connector`（此时仍 DataStax/GitHub 社区版 ⚠️）——
- 读：按分区键/谓词下推做"环上就近分片读"（节点亲和的 SparkTask ⚠️ 机制转述）；
- 写：批量走 native protocol，`cassandra_table` 的 saveToCassandra；
- 边界：连接器做"聚合/JOIN"=把 Cassandra 当 KV 仓库滥用——与 04.3 的"聚合缺失是诚实"
  同一论证的两面。

当代：connector 已归 Apache（`apache/cassandra-spark` ⚠️ 存在性转引 #89 册 00 的
api.github.com 实抓基线 3.5.1），Spark 侧 DataFrame API 全面取代 RDD 叙事；数据湖视角的
对照读本册 [../bigdata/04-SparkSQL与结构化数据.md](../bigdata/04-SparkSQL与结构化数据.md) 与
[../bigdata/09-存储与文件格式.md](../bigdata/09-存储与文件格式.md)（✅ 盘上）。

## 12.4 搜索双写与其继任者 CDC

前身叙事 ⚠️）在 2026 的替身是标准管道：

```
应用 → Cassandra(写权威) --CDC(change streams)--> Kafka → ES/向量库(读模型)
```

## 12.5.1 迁移与多活的工程剧本（书中案例域 ⚠️ 重构）

- **Cassandra → 湖仓**：当日全表扫痛点改由 CDC/变更流落地 Parquet/Iceberg 承接
  （对照盘上 [../Apache_Iceberg活用入門/00-总览与阅读地图.md](../Apache_Iceberg活用入門/00-总览与阅读地图.md) 与

## 核心概念速览（中英对照）

- **选型三维** — Shape/Pattern/Consistency-budget：书中横向对比的坐标系。
- **HBase 对照** — HBase contrast：同谱系不同治理（中心 Master+HDFS 依赖）。
- **写权威+读模型** — Authoritative store + serving index：双写架构母题。
- **CDC** — Change Data Capture：Cassandra 原生变更日志，双写对账的引擎化替代 ✅。
- **change streams** — Change streams：CDC 的下游消费形态 ⚠️ 术语按版核。
- **connector 下推** — Predicate pushdown：Spark 读 Cassandra 的分区级过滤边界。
- **bulk loader** — sstableloader/Hadoop bulk：离线生成 SSTable 的装载通道。
- **Phoenix/SQL 层** — HBase SQL 层：书内"即席 SQL"替代路线的代表 ⚠️。
- **NewSQL（前身语境）** — NewSQL：与 Cassandra 争夺"SQL+扩展"心智的后起者。
- **湖仓分流** — Lakehouse split：分析工作负载的 2026 去处（Iceberg/Delta 目录版互指）。
- **Apache 化** — Apache 化：驱动/connector/CCM 归入 ASF 的生态收敛 ⚠️ 转引。
- **生态厂商整合** — Vendor consolidation：IBM×DataStax 时代的托管形态（Astra ⚠️ 转引）。
