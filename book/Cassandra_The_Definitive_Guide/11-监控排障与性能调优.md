## 11.1 题纲

1. 观测面清单：JMX MBean 宇宙（thread pools/storage/metrics 家族）、`nodetool` 子命令族、
   日志四件套（system/debug/gc/audit⚠️3.x+ 才有独立审计）
2. 核心指标：Latency（ReadRequest/LatencyWrite 的 micros+count 对）、Dropped Messages
   （RPC/内部消息队列丢弃=过载真相）、Thread Pool Blocked、Compaction Pending/Bytes
3. 数据画像：`nodetool cfstats`/`tablestats`、`tablehistograms`（分区/列数的分位数显微镜）
4. 慢查询定位：`TRACING` 语句（2.x 的查询时间线 ✅ 级特性 ⚠️）、slow query log 参数族
5. 症状→病因树：超时三兄弟分诊（Write/Read timeout vs Unavailable）、paxos 残留、
   GC 尖峰与读毛刺相关性
6. 性能方法论：先形态（延迟分布 vs 均值）后参数；瓶颈四选一=CPU/盘/网络/GC
7. 调优武库（书中项）：分区整形、key cache、bloom fp、压实限流、commitlog 盘隔离、
   协议压缩、`cassandra-stress` 基准
8. 事故案例重构（⚠️ 社区叙事）：修复风暴拖垮全环/大分区热分区连环写超时

## 11.2 指标读法：分布优先，均值有罪（⚠️ 转述）

书内反复强调的观测纪律：Cassandra 的 JMX latency 暴露的是 **(时间窗计数, 累计微秒)** 对，
"p99 看直方图不看平均"——p99 恶化 2 倍在均值上几乎隐身，却已杀死应用超时。三条黄金曲线
（书中监控面板最小集 ⚠️）：

- **Dropped Messages**：任何非零都是红灯；MUTATE/READ/REQUEST-RESPONSE-* 各队列指向
  具体过载类别（写打爆 vs 修复打爆）。
- **Pending Compactions + Compaction Time**：压实欠债与偿还速率，写风暴前兆雷达。
- **GC 暂停时间序列**：与读延迟尖峰叠图找同相位（10.3 手艺的仪表盘化）。

## 11.3 超时三兄弟分诊表（书中诊断树 ⚠️）

| 异常 | 定义 | 常见根因 | 验证动作 |
|---|---|---|---|
| Unavailable | 可达副本不足 CL | 节点/DC 掉线、过激 CL 选型 | `nodetool status`、降 CL 验证 |
| WriteTimeout | 达标副本数不足但可达 | 热分区、盘饱和、GC、跨 DC 慢 | cfstats 分区分位、dropped MUTATE |
| ReadTimeout | 应答副本不足/合并超时 | 大分区无分页、2i 广播、墓碑雨 | tablehistograms、TRACING 看 fan-out |

**hint/repair 的暗线**（书内警句 ⚠️）：dropped 写≠丢数据（hint 代偿），但 hint 窗口过期
才真丢——"看 hint 交付速率与 hint 目录大小"被列为值守必修（对照 08 章）。

## 11.4 TRACING 与解剖学工具（2.x ⚠️）

```sql
TRACING ON; SELECT * FROM users WHERE id=...;   -- 输出跨节点时间线事件
-- 事件族：activity 'Parsing/Execute/read repair/hinted handoff' + source ips ⚠️ 表列按版核
```

`tablehistograms` 给分区大小/列数的 p5–p99——书中给它的定位是"建模质量验收单"（05 章
检查单最后一条的回执）：`Median partition size` 与 `Maximum` 差三个数量级=桶没分好。
离线侧：`sstableanalyze/sstablescrub` 族 ⚠️ 命名按版核，现代版工具清单见 #89 册 05/08 章。

## 11.5 调优的书中优先级（⚠️ 转述其序）

1. **改模型胜过改参数**：热分区→桶；无分页大分区→游标；2i 慢→反范式（05 章闭环）。
2. **盘与日志的物理隔离**：commitlog 独盘在 2.x HDD 时代收益巨大（SSD 时代弱化 ⚠️）。
3. **缓存的定向投放**：点查→key cache；范围重→bloom fp 降内存先测 p99。
4. **压实限流与并行**：还债速度 vs 前台延迟的再平衡（10.2 表）。
5. **协议与压缩**：跨 DC 读启用 lz4 压缩（9.2）；批量走 UNLOGGED（4.4/8.9）。
6. **JVM 终段**：GC 算法/堆形微调放最后——书中明文"前四条没做完别碰 JVM" ⚠️。

## 11.5.1 事故案例走查（书中叙事重构 ⚠️，非实测）

- **案例 A：repair 风暴拖垮全环**。白天全量 `-full` repair + 默认小 stream 并发 →
  merkle 计算挤占读线程 + dropped READ-RESPONSE 上升 → 客户端超时雪崩。教训三条：
  repair 排夜间、按 `-pr` 分段滚动、dropped 计数接告警（11.2 金标准曲线全部现身）。
- **案例 B：热分区连环 WriteTimeout**。`user_events(user_id, ts)` 但有一个"明星用户"
  写暴增 → 单分区所在副本盘饱和 → QUORUM 写超时集中在同两个节点。cfstats 显示
  平均分区大小正常、histograms p99 巨大——"均值撒谎、分位报警"的教科书演出（11.5 第 1 条）。
- **案例 C：hint 目录静默膨胀**。某 DC 节点失联一周（>hint 窗口），恢复后发现数据缺口
  ——hint 过期被丢弃；只能全量 repair+业务对账。08 章"ANY 的便宜"在此结清账单。

## 11.5.2 值守最小面板（书中面板口径 ⚠️）

1. Latency p95/p99 per table（读写分开）；2. Dropped Messages 全队列非零告警；
3. Pending Compactions + 压实吞吐；4. GC 暂停叠读延迟；5. hint 目录大小与交付速率；
6. `nodetool status` 环健康与 owner 分布；7. 磁盘水位×(压实临时空间 2 倍系数 ⚠️)。

## 11.6 cassandra-stress：书内的基准话语权（⚠️）

`cassandra-stress simple n=... cl=QUORUM` 与混合场景（`mixed` profile）用于容量验证；
书中立场：任何调参先跑 stress 立基线，"没有基线的调优=抽签"。限制也被点破：stress 无
业务语义（宽窄分区/冷热分布失真）。现代对照：#89 册 11 章的当代调优工法与
`system_views` 时代的可观测栈（文末）。

## 核心概念速览（中英对照）

- **JMX MBean** — JMX beans：2.x 的主观测面，latency 以 count/time 对暴露。
- **Dropped Messages** — 丢弃消息：队列溢出弃单的计数字典，过载金标准。
- **Pending Compactions** — 压实欠债：待压实任务数，写风暴雷达。
- **cfstats/tablestats** — 表统计：per-table 读写延迟/分区计数的粗粒度镜。
- **tablehistograms** — 分位显微：分区/列大小的 p50/p99/p999 直方图。
- **TRACING** — Query tracing：跨节点执行时间线，读路径解剖刀（2.x 特性 ⚠️）。
- **slow query log** — 慢查询日志：阈值触发的 CQL 记录参数族 ⚠️ 版本点。
- **repair cursor** — 修复进度：`nodetool netstats` 中的 merkle/流式游标视图。
- **availability analyzer** — 可用度分析器：按分区统计 CL 满足率 ⚠️ 后被砍。
- **gc logs** — GC 日志：延迟毛刺的第二时间轴（10.3）。
- **cassandra-stress** — 基准器：内置 profile 的容量/回归试验台。
- **hot partition** — 热分区：单分区流量畸高，写超时连环杀手的根因。
- **tombstone storm** — 墓碑风暴：删后重查的读放大极端态（06 章回声）。
