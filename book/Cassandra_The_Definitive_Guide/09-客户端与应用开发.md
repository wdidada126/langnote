## 9.1 题纲

1. 原生协议（native transport）：帧结构、流式多路复用、压缩（snappy/lz4 ⚠️）与协议版本对表
2. 驱动谱系：hector/pycassa（thrift 旧世）→ DataStax Java Driver 1.x/2.x/3.x、Node.js/Python
   （driver 前身）、C#（Book)  ⚠️ 书名细节不逞能
3. 集群发现：联系点（contact points）→ 控制连接拉环 → 全环拓扑轮询（02 章 seeds 误用的解药）
4. 负载均衡与令牌感知：RoundRobin/TokenAware/DCAware 三层组合的默认哲学
5. 重试与降级：默认重试策略（Unavailable→下一副本、ReadTimeout→重试）与幂等性前提 ⚠️
6. 异步与背压：ListenableFuture 风格 API、`executeAsync` 的 in-flight 限流、ResultSet 分页
7. 对象映射：`@Table`/MappingManager 时代的 DAO（ObjectMapper 前身 ⚠️），以及"避免 ORM 幻觉"
8. 连接池与批量：`ProtocolVersion` 显式钉死、prepare 语句缓存、批量=UNLOGGED 的驱动侧形态
9. 应用侧模式：计数器读缓存、唯一约束靠 LWT、分布式锁反模式劝退 ⚠️

## 9.3 驱动行为的教学点（以 Java Driver 2.x 风味 ⚠️）

```java
Cluster cluster = Cluster.build()
    .addContactPoints("10.0.0.1", "10.0.0.2")     // 只是入口，不是全环
    .withCompression(Compression.LZ4)
    .withLoadBalancingPolicy(new TokenAwarePolicy(
        new DCAwareRoundRobinPolicy.Builder().withLocalDC("dc1").build()))
    .withQueryOptions(new QueryOptions().setConsistencyLevel(ConsistencyLevel.LOCAL_QUORUM))
    .build();
Session s = cluster.connect("prod");
PreparedStatement ps = s.prepare("INSERT INTO users (id,name) VALUES (?,?)");
s.execute(ps.bind(uuid, "carpenter"));             // prepare 结果按节点缓存，复用是铁律
```

- **prepared 语句**：2.x 驱动"prepare 一次、按副本缓存 id"——频繁 prepare=隐性风暴 ⚠️。
- **token-aware + DC-aware**：协调节点选在副本一侧省一跳、写不出 DC——与 08 章 LOCAL_QUORUM
  配方拼成多 DC 应用的标准姿势。
- **重试默认值的双刃**：Unavailable 重试掩盖容量事故、ReadTimeout 重试放大热分区——书内
  建议"自定义重试+告警接入"。
- **分页透明化**：`setFetchSize` 下驱动持 paging state 自动续页——宽分区遍历的默认救生圈
  （05 章检查单回环）。

## 9.4 ORM/映射器：便利与失真之间

MappingManager→`@Table/@Column` 的声明式映射（2.x 时代 ⚠️）解决序列化，解决不了模型错位：
映射器鼓励"实体→单表→多谓词查询"的关系思路，正撞 05 章公理（一行一访问模式）。书中
判词重构 ⚠️：**先按查询建表，再为每表配一个窄 DAO；拒绝"通用实体仓储"**。当代映射层
（org.springframework.data.cassandra / Quarkus 扩展 / java-driver mapper ⚠️ 后话）继承了
同一警告语境。

## 核心概念速览（中英对照）

- **Native protocol** — 原生协议：CQL 二进制协议，v1–v4 对应 2.x–3.x 世代。
- **Contact points** — 联系点：驱动发现集群的入口地址，非配置真相的全部。
- **Control connection** — 控制连接：拉取环拓扑与 schema 版本的专用长连。
- **Token-aware policy** — 令牌感知 LB：把请求送给持有副本的节点做协调。
- **DCAware policy** — 机房感知 LB：本地 DC 优先，跨 DC 兜底。
- **Retry policy** — 重试策略：Unavailable/ReadTimeout 的自动补刀规则集。
- **PreparedStatement cache** — 预编译缓存：驱动按节点缓存 statement id。
- **Paging state** — 分页游标：服务端编码的续页令牌（fetch size 机制）。
- **MappingManager** — 对象映射器入口：注解式 DAO 的 2.x 形态 ⚠️。
- **In-flight limit** — 并发在途上限：背压的第一道闸。
- **Consistency default** — 默认 CL：QueryOptions 里的全局档，请求可覆写。
- **CCM** — Cluster Manager：本机起多节点测试集群的工具，书内标准装备。

- **驱动归 Apache**：Java 驱动仓库已迁 `apache/cassandra-driver`，当前 **4.19.3（2026-06-01）**

  https://cassandra.apache.org/doc/latest/cassandra/getting-started/drivers.html ⚠️ 站点 200 口径，未逐页抓）。

  在 2026 没有替代品。
