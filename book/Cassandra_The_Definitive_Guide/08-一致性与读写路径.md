# 08 一致性与读写路径（原书第 9 章 ✅ 译系列锚点：「Cassandra 读写数据」）

> 精读重构。本章是"可调一致性"的总账：CL 级别、R+W>N 算术、读路径的 digest/读修复、
> LWT 的 Paxos、counter 合并。基线 2.x，全部 ⚠️ 未实测；quorum 算术的 🔧 类比演示在
> #89 册 05 章（sqlite3 演示，非 Cassandra 行为），本册不重复造轮。

## 8.1 题纲

1. 一致性级别全集：ALL / QUORUM / LOCAL_QUORUM / EACH_QUORUM / THREE / TWO / ONE /
   LOCAL_ONE / ANY——每级的"参与副本集合"定义
2. quorum 算术：R+W>N 为什么保证读写集合相交；N/R/W 三数在 CQL 里的真实身份（CL 非 W）
3. 写路径细节：LWW 时间戳裁决、同毫秒冲突的 tie-breaker ⚠️（后演化为 now-in-second 之争）
4. 读路径细节：摘要请求（digest）→ 落后副本识别 → 异步全读修复的数据流
5. 读修复的两副面孔：即时修复的延迟税 vs `dclocal_read_repair_chance` 的掷骰子抽查 ⚠️
6. Hinted handoff 与收敛时限：max_window 内代存、过期丢弃=静默丢数据（与 gc_grace 呼应）
7. LWT：`IF NOT EXISTS`/`IF col = ?` 的 Paxos 两阶段、线性化读 `LIGHTWEIGHT`、慢 10 倍 ⚠️
8. counter 写读：partial replica 合并、CL 对 counter 语义的削弱 ⚠️
9. 批量一致性边界：BATCH=分区内 ACID 幻觉的破除（4.4 回环）

## 8.2 CL 级别速查（书内表 ⚠️ 转述）

| CL | 写含义 | 读含义 |
|---|---|---|
| ALL | 所有副本 ack 才返 | 全副本读，最新但最脆（任一失联即错） |
| QUORUM | ⌈(N+1)/2⌉ 本地 DC 概念外的全局 quorum | 同 |
| LOCAL_QUORUM | 本 DC quorum | 本 DC quorum（多 DC 主力） |
| EACH_QUORUM | 每 DC 都 quorum（写极慢/跨 DC 阻塞风险 ⚠️） | 不支持读 |
| ONE/LOCAL_ONE | 任一/本机架任一副本 | 同；可能读到旧版本 |
| ANY | 副本+hint 落盘即算 | 不支持 |
| TWO/THREE | 2/3 个副本 | 2/3 个副本 |

**关键澄清（书中原话级 ⚠️）**：CQL 里没有"写几个副本"的 W 参数——W 由 CL 隐式决定；
"CL=QUORUM 写"≈ W=quorum(N)。所以 R+W>N 的正确用法是"读 CL 与写 CL 的参与数相加>N"。

## 8.3 读写路径的完整数据流（2.x 叙事 ⚠️）

```
写(QUORUM, RF=3):
  coord → replicaA 本地 commitlog+memtable ack
      ↯ replicaB 远程 ack
      ↯ replicaC 失联 → hint 给"责任人副本"暂存
  2/3 ack 达标 → 客户端成功；分歧留给读修复/repair

读(QUORUM):
  coord → 三副本各回 **digest**（分区+列的哈希）
  digest 多数一致 → 返回最快副本数据
  有分歧 → 全读落后副本 + 异步发 mutation 修复其余（read repair）
```

三个后果被书中反复敲打：**读放大**（digest 广播、修复尾巴）、**LWW 遮蔽**（两 DC 各自
写过的数据在合并后只剩高时间戳版本，丢失无声 ⚠️）、**墓碑拖尾**（06 章漏斗的读侧账单）。

## 8.4 多 DC 的一致性菜单（书中场景化 ⚠️）

- 写 `LOCAL_QUORUM` + 读 `LOCAL_QUORUM`（各 DC 内 R+W>N → DC 内单调收敛，跨 DC 靠
  副本复制与时间戳）——"每 DC 自治"的标准配方。
- 写 `EACH_QUORUM`：跨 DC 同步语义的代价=任一 DC 失联写失败；书内判词"除非必须否则别用"。
- `Async`/双活进阶：书中承认 Cassandra 2.x 不提供跨 DC 的 LWW 之外的冲突解决（无向量时钟
  应用层叙事 ⚠️）——"多活业务要带版本/因果信息自己建模"。这一判词在 6.0 Accord（因果/事务）
  时代有了引擎级答案，见文末。

## 8.5 LWT：Paxos 进了 CQL（2.0+ ⚠️）

```sql
INSERT INTO accounts (id, balance) VALUES (u1, 100) IF NOT EXISTS;
UPDATE accounts SET balance = 90 WHERE id = u1 IF balance = 100;
SELECT * FROM accounts WHERE id = u1;  -- 普通读可能看到"未完成提案"的旧值 ⚠️
```

- 语义：`[applied]` 结果行、条件基于**quorum 一致状态**；线性化点由 Paxos promise/accept
  两阶段给出。
- 代价：多轮 quorum 往返+`paxos` 状态持久化（`cassandra-paxos` commitlog 族 ⚠️），
  书中口径"比常规写慢一个数量级"；`serial_consistency`（SERIAL/BETTER... ⚠️ 参数名按版核）。
- 运维暗坑：跨节点时钟漂移影响提案比较 ⚠️；分区拆分/移动时 paxos 残留清理。
- 判词：锁/唯一约束/租约的轻量场景可用；高冲突热点请回"单分区 LWW"或外部协调器。

## 8.6 Counter 与"合并家族"的另一支

counter 的读写绕过 LWW：副本各自维护 delta，读时按 `partial replica` 合并——因此
`SELECT counter` 即使在 ALL/QUORUM 下也只是"quorum 合并"，与常规列的"最新时间戳"裁决
**不同源**（书内明确 ⚠️）。连带推论：counter 不能进普通混合表、不能做条件更新、
与 read repair 的交互脆弱。当代视角（文末演进）里这支家族由 LPP（last-primitive-wins 等
⚠️ 后话）与外部聚合分流。

## 核心概念速览（中英对照）

- **Consistency Level** — CL：每请求指定的一致性档位，W 的隐式化身。
- **Quorum** — Quorum：⌈(N+1)/2⌉ 相交多数，R+W>N 的集合论保证。
- **LOCAL_QUORUM** — 本 DC quorum：多 DC 生产的主力读写档。
- **Digest read** — Digest read：多数副本回哈希摘要、分歧才全读省带宽。
- **Read repair** — Read repair：读时顺带向落后副本反推最新值的异步写。
- **read_repair_chance** — 概率性修复：2.x 的掷骰子抽查参数（后被砍 ⚠️）。
- **LWW** — Last-Write-Wins：时间戳裁决，跨副本分歧的最终默认合并器。
- **Hinted handoff** — Hint：缺席副本的写代存信箱，超窗即真丢。
- **LWT** — Lightweight transaction：IF 条件的 Paxos 条件写/读。
- **Serial consistency** — SERIAL/BETTER：LWT 提案阶段的读档名 ⚠️。
- **Partial replica** — Counter 合并参与者：计数列读时归并的副本单元。
- **Unavailable** — Unavailable：可达副本不足 CL 要求时的显式错误。
- **Write timeout / Read timeout** — 超时三兄弟：与 Unavailable 分诊的关键（11 章）。
