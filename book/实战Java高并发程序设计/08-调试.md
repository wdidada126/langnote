# 第 8 章 并行程序调试（原书）

> 并行调试实战：多线程下 print/断点会"改变时序"，要靠线程 dump、JFR、`Thread.getAllStackTraces`、jcstress。与黄文海 10 章互补，本书补"调试技巧 + 工具"。

## 一、本章地图

| 手段 | 用途 |
| --- | --- |
| 线程 dump | `jstack`/`jcmd` 看栈与死锁 |
| 日志 + MDC | 线程上下文（🔧 虚拟线程下 ScopedValue） |
| JFR | 生产低开销录制 |
| jcstress | JMM 模糊测试 |
| 不靠断点 | 断点改变调度时序，竞态消失 |

## 二、核心精讲

### 2.1 调试器的陷阱
- 断点/单步改变调度 → 竞态"消失"（heisenbug）；用日志 + dump + jcstress 而非单步。

### 2.2 线程 dump 实战
- `jstack -l <pid>`：看锁持有 + 等待链；自动报告 monitor 死锁。
- `Thread.getAllStackTraces()`：程序内取所有栈（监控端点）。

### 2.3 日志与上下文
- 线程名带业务 ID；MDC 注入（🔧 虚拟线程下 MDC 传递用 `ScopedValue` 更稳）。

### 2.4 🔧 现代
- `jcstress` 多架构 CI 跑 JMM 验证；JFR + async-profiler 生产观测。
