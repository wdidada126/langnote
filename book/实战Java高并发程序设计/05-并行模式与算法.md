## 二、核心精讲

### 2.1 基础模式
- **DCL 单例**：`volatile` 阻断半构造（必须用 volatile，见《实战》16 章）。
- **不变模式**：`final` + 不暴露引用 → 免同步（JSR 133 final 语义）。
- **生产者-消费者**：`BlockingQueue` 解耦速度差 + 背压（🔧 `LinkedBlockingQueue` 默认无界 OOM）。

### 2.2 任务编排模式
- **Master-Worker**：主线程分解任务给 Worker 池，汇聚结果 → 与 ForkJoin 思想同源（冷血 7 章）。
- **Future 模式**：提交即返回 Future，按需 `get`（阻塞到完成）。
- **保护暂停（Guarded Suspension）**：条件不满足就等（wait/notify 封装）。

### 2.3 并行算法
- 并行排序（归并/快排的并行化）、并行搜索（分块）、并行流式（`parallelStream`）。
- 注意：任务拆分有开销；小数据量串行更快（Amdahl + 拆分成本）。

### 2.4 🔧 现代
- `CompletableFuture` 链 + `StructuredTaskScope` 把"Future/Master-Worker"模式变成声明式（JDK 8/21）。

## 四、常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "DCL 不加 volatile" | 半构造对象 |
| 2 | "LinkedBlockingQueue 无界" | OOM |
