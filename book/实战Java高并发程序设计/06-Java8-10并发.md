# 第 6 章 Java 8/9/10与并发（原书）

> **本书独有"新特性"章**：Lambda/Stream 对并发的影响、`CompletableFuture` 异步编排、`parallelStream` 的坑、JDK 9 响应式流 `Flow`、模块系统。与《之美》CompletableFuture 专篇 + 冷血 8 章互补，本书重"新特性怎么落地并发"。

## 二、核心精讲

### 2.1 Lambda 与并发
- Lambda 让"传行为"变便宜 → `Executor.execute(() -> ...)`、`CompletableFuture.supplyAsync(...)` 更顺手。
- 注意：Lambda 捕获外部变量需 effectively final（与匿名类同）。

### 2.2 `CompletableFuture`（与冷血 8 章 / 之美专篇一致）
- `thenApply`/`thenCompose`/`thenCombine`/`allOf`/`anyOf` + `exceptionally`/`handle`。
- 默认 `ForkJoinPool.commonPool()`；🔧 别提交阻塞任务（饿死全局并行流）。

### 2.3 `parallelStream` 的坑
- `list.parallelStream()` 默认用 `commonPool`；有状态 Lambda（累加可变变量）→ 数据竞争。
- 嵌套 `parallelStream` 不会真正并行（同一池）；阻塞任务饿死整个池。
- 替代：显式 `CompletableFuture` + 自定义 `Executor`（隔离池）。

### 2.4 JDK 9 `Flow`（响应式）
- `Publisher`/`Subscriber`/`Subscription`/`Processor` + 背压（`request(n)`）。
- 实现：RxJava（48k）、Reactor（5.2k）；与 `CompletableFuture` 区别：背压 + 多值流。

### 2.5 🔧 现代
- 虚拟线程（JEP 444）让"异步/并行流"部分回归同步直写；结构化并发（JEP 453/505）替代 `CompletableFuture` + 手动取消。
