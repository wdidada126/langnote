## 1. 本章定位

- Data Science 工作负载 = 「训练-注册-部署预测」的轻量 ML 栈嵌进湖仓：试验（Experiment）、
  模型注册、MLflow 追踪、笔记本内训练是主叙事（⚠️ 转述）。
- 教学书的 ML 章惯例（⚠️ 推定）：一个回归/分类端到端案例 + 「模型如何被 BI 消费」的收尾，
  不追求算法深度（与专用 ML 书分工）。

## 2. 组件与工件（⚠️ 转述官方域）

- **试验（Experiment）item**：MLflow 血统的试验追踪容器——参数、指标、产物、注册（⚠️ 转述）。
- **训练面**：Spark 笔记本（[08 章](08-Notebooks与Spark工作负载.md)）+ AutoML 类快速通道 +
  自定义环境（scikit-learn/XGBoost/LightGBM 生态为主力；深度学习框架的支持边界当日核实 ⚠️）。
- **部署形态**：批量打分（湖表进湖表出）与托管端点类「user function/实时推理」线——后者命名与
  预览状态变动频繁，**一律 ⚠️ 且当日页核实**（本轮不列已验 URL 故不写细节）。
- 治理缝：模型=受权工件，随工作区/容量走（11 章）。

## 3. 与周边 item 的数据回路

1. 取数：湖仓 Silver 表（04 章）经笔记本 DataFrame 进特征工程；
2. 训练：试验记录全参数网格；最优模型注册；
3. 回馈：预测结果写回湖表/仓表 → 语义模型（10 章）→ 报表；
4. 监控：特征漂移类监控能力在 Fabric 的成熟度以当日文档为准（⚠️ 不写死）。
- 判读（⚠️ 推定本书观点位）：Fabric ML 的价值不在替代专业 MLOps 平台，而在**消灭「分析数据
  跨平台搬运」的税**——模型贴着数据训练与打分。

## 4. 特征工程的湖仓落位（⚠️ 重构教学位）

- 特征 = 湖表的一种：命名规范（entity+时间粒度）、回填策略、防泄漏切分（时间轴而非随机）——
  这三条是所有湖仓 ML 项目的通用功课；理论对读盘上工程书：
  [../Advanced_Analytics_with_Spark_2e/00-总览与阅读地图.md](../Advanced_Analytics_with_Spark_2e/00-总览与阅读地图.md)（Spark ML 工程纵深，在盘 ✅）。
- Fabric 特异点：特征表权限、血缘与 CU 消耗天然进同一治理面（与 11 章联动）（⚠️ 转述）。

## 5. 常见误区（⚠️ 重构）

- 把 Fabric 当 GPU 训练集群用——先查现行算力供给面与许可门，再定模型体量上限（⚠️ 纪律：
  本册不写「有没有 GPU」的断言，属快变区）。
- 试验不设命名契约：三个月后无人能从 300 次 run 里找回那版模型——注册与标签纪律从第一天起。
- 「模型即报表」：跳过语义模型层直接堆端点，权限与口径失控（10/11 章回链）。

## 9. 教学 FAQ（重构问答位，⚠️ 非原书）

- **问：团队已在其他 ML 平台，Fabric 还做 ML 吗？** 答：分工判据=「特征与消费离湖多近」；
  外训内用（模型注册后在 Fabric 侧批打分）是常见折中，别为统一而统一（⚠️ 判读）。
- **问：AutoML 值得教学书花篇幅吗？** 答：作为基线生成器值得；作为黑盒进生产不值得——
  本章按「先 AutoML 定基线，再手写迭代」的顺序组织（⚠️ 重构教学法）。
- **问：GPU/深度学习边界在哪？** 答：属快变区且本轮不可实证——只保留「先查供给面与许可门
  再定模型体量」的决策句，不写事实断言（§5 纪律重申）。
