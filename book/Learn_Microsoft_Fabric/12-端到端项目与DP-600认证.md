## 1. 本章定位：把前 11 章装进一个项目

- 结课项目模板（⚠️ 重构）：零售/物联网二选一的样例数据，走「集成→分层→建模→报表→治理评审」
  全链路，对应章号即工序单：06 进数 → 04/08 分层 → 05 集市 → 10 语义模型 → 07 旁路实时 →
  11 治理收口 → 02/03 全程底座。

## 2. 项目工序单（⚠️ 重构教学位）

1. **立项与坐标**（01 章）：确定负载画像与「三个统一」落位图。
2. **开通与预算**（02 章）：试用容量起步；定义 CU 观察指标与结课报告模板。
3. **进数**（06 章）：一条管道 + 一个镜像 + 一个快捷方式，三种进法各跑通一次——
   对照 🔧 E1 的「指针 vs 复制」成本结构直觉。
4. **分层**（04/08 章）：Bronze→Silver→Gold；快照读旧版练习对照 🔧 E3；碎片整理讨论对照 🔧 E2。
5. **集市**（05 章）：仓表星型；聚合性能讨论引用 🔧 E5（列存 vs 行存两个数量级）。
6. **实时旁路**（07 章）：一个事件流样例，明确「为什么这条不需要秒级」。
7. **出口**（10 章）：Direct Lake 语义模型 + 一份带 RLS 的报表；对照 🔧 E4 免导入直觉。
8. **ML 增值**（09 章，可选）：一个批打分特征→预测回流闭环。
9. **治理收口**（11 章）：逐条过治理清单，交「评审否决项」记录。
10. **运营与复盘**（本章）：部署/版本面 + 认证地图。

## 3. ALM 与生命周期面（⚠️ 转述）

- Fabric 的「源代码化」两条腿：**Git 集成**（Azure 仓库形态的工作区版本化）与
  **部署管道**（dev→test→prod 的 item 迁移通道，Power BI 血统）；item 类型对二者的支持面
  不齐是现实约束——引用支持清单当日页核实（⚠️ 纪律）。
- 命名与分区纪律（⚠️ 重构）：工作区命名=域×环境；容量=环境×敏感度；这两张表在项目第 0 天
  定稿，后期重构成本最高。

## 5. 全书复盘：五句话带走

1. 一切在 OneLake 命名空间里对话（03 章）；搬不搬数据是架构第一问（🔧 E1）。
2. 写入者唯一、读者多样：Spark 写、SQL 问、BI 直读（04/05/10 章）。
3. 进数三岔路按「频率×所有权×一致性」选（06 章）。
4. CU 是唯一硬通货，性能=供给×布局×姿势（02 章，🔧 E5/E6）。
5. 预览即负债：Fabric 的每张截图都有保质期（11 章清单末条 + whats-new 纪律）。

  模拟题只认官方样题渠道（⚠️ 考纲细节不冻结）。
- **问：作品集怎么展示 SaaS 平台经验？** 答：脱敏架构图+Runbook+复盘数字三件套，
