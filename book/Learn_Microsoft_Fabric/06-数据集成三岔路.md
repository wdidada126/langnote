## 1. 本章定位：进数据的三条路

- **管道（Pipeline）**：编排式搬运——活动/连接器/控制流，ADF 血统的「搬家流水线」（⚠️ 转述）。
- **数据流 Gen2（Dataflow Gen2）**：Power Query  Mashup 引擎的低代码转换层，PBIX 用户熟悉的
  界面语义（⚠️ 转述）。
- **镜像（Mirroring）**：源库（SQL Server/Postgres/Databricks/Synapse…）持续复制到湖表/仓表，
  「零 ETL」叙事的主角（⚠️ 转述官方 mirroring 域）。
- 记忆轴：**一次性搬 vs 人写转换 vs 自动跟变**——三问定一路。

## 2. 管道：活动与连接器世界（⚠️ 转述官方 data-factory 域）

- 结构：活动（复制/执行笔记本/等待…）+ 数据集（连接抽象）+ 参数与表达式；触发排程或上游依赖（⚠️ 转述）。
- 连接器矩阵随月更新；本机不可列实测——**引用连接器名前先查当日页**（⚠️ 纪律）。
- 与 Synapse/ADF 的迁移语义：既有 ADF 管道可「纳入」Fabric 治理面继续跑的叙事（⚠️ 转述，
  具体开关与许可条件当日核实；波内 #217/#219/#220 登记不链，总辨析留给波尾 Fabric 谱系表）。

## 3. 数据流 Gen2：转换逻辑的家应该在哪

- Power Query 表达式语言（M）为引擎——报表端数据流与 lakehouse 数据流同族（⚠️ 转述）。
- 教学判断（⚠️ 重构）：转换逻辑若 BI 团队维护 → 数据流；若工程师用 Python/SQL 维护 → 笔记本/
  存储过程，管道只做编排薄壳。**逻辑所有权决定工具选择**，不是性能。

## 4. 镜像：零 ETL 的机制与代价（⚠️ 转述官方 mirroring-overview）

- 机制：初始全量 + 变更数据捕获/事务日志读取，把源表实时物化为湖 Delta 表或仓列存表；
  目标端可查询、源端无感（⚠️ 转述，实现细节平台托管）。
- 代价账：初始快照对源库的压力、CDC 日志保留窗口、镜像目标的容量消耗曲线——
  「免费的 ETL 不存在，只是把 ETL 变成了平台订阅」（⚠️ 转述判读）。
- 与快捷方式分工（03 章）：Mirror=复制落地可高速查；Shortcut=不落地按原样读——
  「查得频否」是分水岭。

## 5. 排障心智清单（⚠️ 重构教学位）

1. 管道失败先看**活动级**错误（连接/认证/路径三选一），再看运行历史的重放；
2. 数据流性能问题查「是否把全量拉进 M 引擎再过滤」——下推与否的差别（🔧 类比下段）；
3. 镜像断点：源端日志保留期 vs 同步滞后时长赛跑；
4. 一律带 item 级监控视图截图归因（02 章 CU 联动）。

- 🔧 类比补充引用：本册 03 章 **E1（视图指针 vs 复制）**即「Shortcut vs Mirror」的最小成本结构
  演示（视图 1.0ms 常数 vs 复制 16.7ms 随量）——同一段数据两种进法，此处不重复贴值
  （见 [03 章 §4](03-OneLake统一数据湖与快捷方式.md)，标注非 Fabric 行为）。

## 8. 三岔路决策速查（重构表）

| 输入信号 | 首选 | 理由句 |
|---|---|---|
| 一次性历史回填 | 管道复制活动 | 跑完即止，成本随量线性 |
| 业务方要自助改清洗逻辑 | 数据流 Gen2 | 所有权在 BI 侧 |
| 源库持续变、要近实时可查 | 镜像 | CDC 自动化，免自建 |
| 已有 ADF/Synapse 资产 | 纳入治理面评估，勿急重写 | 迁移税最低（⚠️ 当日核） |
| 数据本就在开放湖 | 快捷方式（03 章） | 不搬家是第一原则 |

## 9. 教学 FAQ（重构问答位，⚠️ 非原书）

- **问：镜像会不会把源库拖垮？** 答：初始快照与日志读取两阶段各有压力点，源端资源与
  日志保留窗口是第一对验收指标（⚠️ 转述；数值依源端形态，不写死）。
- **问：管道、数据流、笔记本三选一在哪章判？** 答：编排归管道、转换归数据流/笔记本、
  重活归 Spark（08 章）——「一物三用」的架构洁癖是新手税（⚠️ 重构）。
- **问：复制活动的分区切片值得学吗？** 答：大表回填的吞吐旋钮，教学书通常带图演示；
  本册重构位只立「先切片后调并行」的顺序原则（⚠️ 推定）。
