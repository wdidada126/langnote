## 1. 本章定位

- OneLake 是全书的**地心**：所有工作负载章（04–10）最终都落回「数据在 OneLake 的哪里、以什么
  格式、被谁读」（⚠️ 推定本书叙事骨架）。
- 一句话定义（⚠️ 转述）：租户级**唯一逻辑数据湖**——一个命名空间、一套安全模型、一份数据，
  类比「分析界的 SharePoint for Data」。

## 2. 结构与命名空间（⚠️ 转述官方 onelake-overview）

- 路径直觉：`abfss://<容器>@<湖>.onelake.dfs.fabric.microsoft.com/<工作区>/<item>`——
  工作区与 item 直接进 URL，湖结构 = 组织结构的镜像（⚠️ 转述）。
- 组成物：
  - **湖根**：租户一湖（区域属性随首个工作区落定，跨区分布有专门说明页，本轮未验链 ⚠️）；
  - **湖项（lakehouse）**：数据工程的主容器（[04 章](04-Lakehouse与数据工程.md)）；
  - **快捷方式（shortcut）**：指向内部或外部存储的**零拷贝逻辑链接**——可跨湖、跨工作区，
    也可指向 S3 / ADLS Gen2 / Dataverse / 本地网络文件（⚠️ 转述）。
- 存储真相（⚠️ 转述）：OneLake 底层是 ADLS Gen2 形态的对象存储 + 抽象层；用户拿不到裸桶，
  一切经 API/URL 与 item 语义访问。

## 3. 快捷方式的工程语义

- 三个动词分清：
  1. **复制（Copy job/管道）**：数据搬家，双份存在，成本在存储与搬运（06 章）；
  2. **快捷方式（Shortcut）**：不搬家，把外部路径挂载进湖命名空间，读写走原存储（本章）；
  3. **镜像（Mirroring）**：持续同步，源库变更自动落地成湖表/仓表（06 章）。
- 治理张力（⚠️ 转述+推定）：快捷方式让「数据留在系统 of record」成为可能——与 Data Mesh 的
  域主权原则同构，对读 [../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md)；
  但跨云快捷方式的性能与一致性由源端决定，教学书应提醒「先测再挂」（⚠️ 推定）。
- 表格式interop（⚠️ 转述）：OneLake 原生表格式为 Delta，同时提供 Apache Iceberg 互操作视图；
  格式战争视角纵深见 [../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md](../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md) 与
  [../Apache_Iceberg活用入門/00-总览与阅读地图.md](../Apache_Iceberg活用入門/00-总览与阅读地图.md)。

## 4. 🔧 本机类比：零拷贝指针 vs 复制（非 Fabric 行为）

- 实验目的：把「Shortcut = 建指针不搬数据」量化。DuckDB 对 1M 行 / 12.18 MB Parquet 文件
  分别建**视图（指针式）**与**内表（拷贝式）**（脚本与数据落 `D:\develops\tmp\dbwave_w9_learnf\`）：

```text
E1 OneLake 快捷方式类比（DuckDB 1.5.5，2026-10-02 实测）：
  CREATE VIEW sc AS SELECT * FROM read_parquet('data/ev.parquet')
  视图创建 1.0ms；经视图查询 1,000,000 行聚合 3.8ms；磁盘新增占用 0 MB
  CREATE TABLE cp AS SELECT * FROM read_parquet(...)（复制式）：16.7ms，文件级双份存储
结论：指针成本≈常数，拷贝成本≈数据量线性——「Shortcut 免费、Copy 付费」的直觉成立。
（类比仅演示概念结构；Fabric 的 Shortcut 还牵涉跨租户授权/源端限流，本机未覆盖）
```

- 边界声明：本实验**非本书引擎/平台行为**——Fabric Shortcut 的实际语义（外部目录挂载、
  受管身份透传）一律以 ✅ 官方页当日转述为准。

## 5. 安全与治理面（⚠️ 转述）

- 「一套安全模型覆盖全湖」：湖/工作区/item 三级 + 行级安全（在表端点执行）——细节在
  [11 章](11-治理安全与租户管理.md) 汇总；本章只立心智：**权限跟着命名空间走，不跟着文件走**。
- 软删除与回收窗口、版本化（Delta 事务日志形态）由平台托管（⚠️ 转述；保留期具体数值本轮
  未实证，不写死）。
- OneLake 浏览/资源管理器（Explorer）是教学书必配的 GUI 抓手（⚠️ 推定）。

## 6. 上手机 checklist（⚠️ 重构练习位）

1. 在试用容量建湖项；用 Explorer 观察 `Files`/`Tables` 双分区。
2. 挂一个外部 ADLS/S3 快捷方式，验证「原处改、湖内即时可见」的指针语义（对应 🔧 E1 直觉）。
3. 对比实验：同一数据分别「Shortcut 挂载」与「Copy job 搬入」，记录 CU 消耗与存储占用差异。
4. 删除测试：删表 → 找回收路径 → 理解软删除窗口（⚠️ 界面名当日核实）。

## 8. 教学 FAQ（重构问答位，⚠️ 非原书）

- **问：快捷方式挂了外部存储，湖内查询很慢，是 OneLake 的问题吗？**
  答：指针语义下墙钟大头在源端与网络（🔧 E1 只演示成本结构不演示性能）——先测源端直读
  基线，再决定是否需要镜像落地（06 章分水岭判据）（⚠️ 转述方法论）。
- **问：OneLake 数据在哪个区域？会不会自动跨区复制？**
  答：租户区域属性与湖驻留规则属企业档问题，本册只立「第 0 天确认区域承诺」的纪律；
  细则当日查官方数据驻留专题（⚠️ 缺口登记，未逐页验链）。
- **问：快捷方式能不能跨租户？**
  答：跨租户的合规通道是外部分发类能力（11 章），不是把别人的湖挂成自己的快捷方式——
  两者治理含义完全不同，混用属越权事故前兆（⚠️ 转述+判读）。

## 最新演进与工业实践

- 演进追踪：OneLake 的能力扩张（外部目录治理、Iceberg first-class 化、快捷方式源类型增加）
  都在 ✅ <https://learn.microsoft.com/en-us/fabric/onelake/onelake-overview> 与
  ✅ <https://learn.microsoft.com/en-us/fabric/get-started/whats-new>（均 2026-10-02 验 200）滚动更新——
  本册快照不冻结这些细节（⚠️ 纪律）。
- 工业实践（⚠️ 转述社区共识）：大型组织普遍用「快捷方式织网」把存量数据湖纳管而非二次搬迁；
  评估 Fabric 的第一步常被建议为「把你现有 ADLS/S3 目录结构映射成 OneLake 命名空间草图」。
- 反面模式：跨地域快捷方式做低延迟报表数据源（网络墙钟不受湖语义控制）；把 Shortcut 当备份
  （指针不复制，源毁即毁）（⚠️ 推定提醒）。
