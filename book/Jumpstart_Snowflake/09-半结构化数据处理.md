## 1. 章节定位与叙事线

2019 年的差异化论点：云仓不必先"拍平"再分析——原始 JSON 可以直接入库（COPY 到 VARIANT 列），
用 SQL 的路径语法与 FLATTEN 现场展开，需要时再物化成关系表。本章叙事链：数据类型三兄弟 →
JSON/Avro/ORC/Parquet 文件入 VARIANT → `:` 与 `[]` 路径访问 → LATERAL FLATTEN 拆数组 →
TRY_CAST 治理脏类型 → 用物化视图/生成列回落星型 → 半结构化与剪枝的存储协作（自动列化 ⚠️ 时代
口径）→ 进阶技巧（QUALIFY、对象拼接函数族）⚠️ 推定。

## 3. 深读与机制重构

**（a）最小工作流（自拟示意，非书中原文）**：

```sql
CREATE TABLE web.events (id BIGINT, payload VARIANT);
COPY INTO web.events FROM (SELECT $1, parse_json(column1)
  FROM @web.raw_stage (FILE_FORMAT=>'myjson'));            -- 装载面复用 04 章

-- 路径访问：冒号即 JSON Pointer 风味
SELECT id, payload:customer.name::STRING            AS cname,
       payload:items[0].qty::INT                    AS first_qty
FROM web.events;

-- LATERAL FLATTEN：把数组爆炸成行
SELECT e.id, f.value:size::INT AS sz, f.value:sku::STRING AS sku
FROM web.events e, LATERAL FLATTEN(input => e.payload:items) f;
```

语法/语义锚点：✅ https://docs.snowflake.com/en/sql-reference/data-types-semistructured、✅
https://docs.snowflake.com/en/user-guide/querying-semistructured、✅
https://docs.snowflake.com/en/sql-reference/functions/flatten。

**（b）VARIANT 的存储真相（⚠️ 转述）**：VARIANT 不是"塞进 varchar 的文本"——落盘为自描述
二进制树；查询高频路径会被平台**自动抽取成列式子结构**参与 min/max 剪枝（与 04 章 🔧 E2 同一
剪枝世界，只是对象从整列变成路径）✅ tables-micro-partitions 族页。这一层"半结构化也有物理
设计"是本章超越语法手册的核心认知 ⚠️。

**（c）FLATTEN 的心智**：`FLATTEN` 是表函数（可 LATERAL 引用左行），把 OBJECT/ARRAY 炸成
(key, path, value) 伪列；多级数组=多级 LATERAL 嵌套。与 2026 其他引擎的 `UNNEST` 家族对照可读
🔧 E7——概念同型（数组→行），语法不同族。

**（d）何时"关系化"**：路径访问写法脆（schema 漂移即哑火）；稳定分析面应沉淀为表/视图/物化视图
✅ views-materialized，装载期或加工期用 TRY_CAST 兜脏数据——本章给出的"先灵活后固化"节奏，
即后来"ELT 两段式"行业共识的雏形 ⚠️ 评价。

## 4. 🔧 本地类比实验（E7，非 Snowflake 行为）

DuckDB 1.5.5 演示"JSON 路径 + 数组展开"两个与 VARIANT/FLATTEN 同型的概念（**DuckDB 无
VARIANT 类型/无自动列化，路径语法也不同，不构成对 Snowflake 的任何推断**）：

```text
表 v2(id INT, j JSON)：{"sensors":[{"t":10},{"t":20}]} / {"sensors":[{"t":30}]}
SELECT id, unnest(json_extract(j,'$.sensors[*].t')) AS t FROM v2;
  → (1,10) (1,20) (2,30)        —— ≈ LATERAL FLATTEN 的"数组→行"语义位
SELECT id, json_extract_string(j,'$.sensors[0].t') → (1,10) (2,30)
                                 —— ≈ 路径下标访问 payload:items[0]
```

实测输出存 `D:\develops\tmp\dbwave_w10_jpsf\exp2.txt`。可迁移结论：数组展开是跨引擎普适原语；
差异在 Snowflake 把"路径"做成类型内一等公民并接入剪枝/统计（上文 (b) 段 ⚠️+✅）。

## 5. 深读问答（自拟）

**Q1：VARIANT 列会拖慢查询吗？** A：高频过滤路径被自动列化后趋近原生列；低频探索路径扫二进制
树，成本高但免前置建模——"先宽后进"的权衡 ✅ tables-micro-partitions 族 ⚠️ 转述。
**Q2：为什么路径访问要配 TRY_CAST？** A：JSON 弱类型，`::NUMBER` 遇脏值报错、`TRY_::` 变 NULL，
管线韧性差异巨大 ⚠️+✅ querying-semistructured。
**Q3：本章与 06 章怎么咬合？** A：事件流（Kafka/Snowpipe）落 JSON→VARIANT 表，正是"连续装载×
半结构化"的黄金组合——11 章方案图的事件泳道。
