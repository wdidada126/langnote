# 14 Time Travel（pp.251–259 ✅ Crossref）

> 章定性：全书收尾的"特色能力"短章（9 页 ✅）——数据的多版本可读性：保留期、时点查询、

## 1. 章节定位与叙事线

Time Travel 把"备份-恢复"从运维仪式降维成查询语法：任何表/Schema/库在保留期内可按
`AT | BEFORE (TIMESTAMP | OFFSET)` 时点直读；误删对象 `UNDROP` 秒级复活；配合克隆（0 点
copy-on-write）派生开发/测试副本。本章叙事链 ⚠️ 推定：概念（不可变微分区+元数据版本自然
导出）→ DATA_RETENTION_TIME_IN_DAYS 参数（受 07 章版本上限约束）→ 时点查询/时点克隆句法 →
SHOW HISTORY 审计时间线 → UNDROP 三级（表/Schema/库）→ FailSafe（最后一道、平台侧协助、
不计入保留期 ⚠️ 时代口径）→ 成本面（保留=存储占用）。作为终章它同时回收 12 章（训练定版）
与 13 章（回滚保险）的伏笔。

## 3. 深读与机制重构

**（a）句法样板（自拟示意，非书中原文）**：

```sql
ALTER TABLE sales.core.orders SET DATA_RETENTION_TIME_IN_DAYS = 10;
SELECT count(*) FROM sales.core.orders AT(OFFSET => -60*5);        -- 5 分钟前
CREATE TABLE ml.train_snapshot CLONE sales.core.orders
  BEFORE (STATEMENT => '019d3f2e-...');                             -- 定版训练集（12 章）
SHOW HISTORY LIKE 'orders' IN SCHEMA sales.core;                    -- 谁在何时改了什么
UNDROP TABLE sales.core.orders;                                     -- 手滑复活（限保留期）
```

**（b）为什么它"免费顺手"（⚠️ 转述机制观）**：04 章说过微分区不可变——UPDATE/DELETE 写新块、
旧块延迟物理清理；元数据账本记录每个版本区间，于是"回到过去"只是换一条账本指针读旧块。
Time Travel、UNDROP、零拷贝克隆（✅ https://docs.snowflake.com/en/user-guide/object-clone、✅
https://docs.snowflake.com/en/sql-reference/sql/create-clone）是同一条原理的三个出口 ✅
https://docs.snowflake.com/en/user-guide/data-time-travel。

**（c）边界的诚实账**：保留期上限由版本订阅决定（07 章矩阵；2019 口径 Standard 短、Enterprise
较长、顶级版本最长——具体天数以官方现文为准 ⚠️）；超期进 FailSafe 平台侧窗口（2019 口径约
7 天、需支持介入 ⚠️；2022+ 新账户起该机制逐步转为可关/重构 ⚠️ 现行文档 slug 未在我本轮
200 名单内，按时代转述登记）；克隆副本继续写会各付存储 ✅ object-clone。

**（d）SHOW HISTORY 的运营用法**：把"数据什么时候变成现在这样"变成可审计时间线——13 章对账
与 12 章定版共用同一句法面 ⚠️+✅ data-time-travel。

## 4. 🔧 本地类比实验（E5，非 Snowflake 行为）

DuckDB 1.5.5 无 Time Travel；用 ASOF JOIN 手工搭"事件↔最近历史版本"的时点语义（**真实测量，
仅类比"按时间取正确版本"这一概念，不涉及任何自动保留/复活机制**）：

```text
prices 快照: 2019-01-01→10, 2019-06-01→12, 2019-11-01→15
查询时点:    2019-03-01(A), 2019-08-01(B), 2019-12-01(C)
ASOF JOIN → (A,10) (B,12) (C,15)     —— 每个事件对齐"当时可见"的版本
```

输出存 `D:\develops\tmp\dbwave_w10_jpsf\exp2.txt`。对照点：Snowflake 的 `AT(timestamp)` 由
平台代你维护版本轴，本实验里版本轴是手工表——差的那个"手工→自动"正是产品价值 ⚠️。

## 5. 深读问答（自拟）

**Q1：Time Travel 能替代备份吗？** A：保留期内可替代"找回旧数据"，但超期、跨账户灾难、合规
归档仍需复制/导出方案 ⚠️+✅ data-time-travel。
**Q2：UNDROP 复活的数据去向？** A：回原容器名空间；同名已存在则需先改名/清理 ⚠️（细节以
官方 undrop 页现文为准 ✅ undrop-database 族）。
**Q3：保留期怎么定不破产？** A：按对象变更频率与业务纠错窗口分级设置，冷表调 0 省存储 ✅
guides-overview-cost ⚠️ 经验口径；克隆链上的持续写入另计 ✅ object-clone。
