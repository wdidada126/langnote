## 1. 章节定位与叙事线

本章解决"历史数据/大批量文件怎么进仓"：概念链为 外部存储 →（凭据/存储集成）→ 外部 Stage →
FILE FORMAT → COPY INTO（可带 SELECT 转换）→ 装载历史与幂等（同文件不重导）→ 错误处置
（ON_ERROR / VALIDATE / LIMIT / PATTERN）。与之对照：05 章给命令行工具面（PUT/GET），06 章把
同一 COPY 机制改造成事件驱动的连续装载（Snowpipe）——三章合成本书的"数据进入"三部曲。

## 3. 深读与机制重构

**（a）三件套样板（自拟示意，非书中原文）**：

```sql
CREATE STAGE mystore
  URL = 's3://acme-landing/sales/'
  CREDENTIALS = (AWS_ROLE = 'sf-s3-role')          -- 2019 也演示 AK/SK 与预签名 URL ⚠️
  FILE_FORMAT = (TYPE = CSV FIELD_OPTIONALLY_ENCLOSED_BY = '"');
COPY INTO sales.raw_orders
  FROM @mystore
  PATTERN = '.*orders_2019.*\.csv'
  ON_ERROR = 'CONTINUE'
  FILES = ('orders_2019_01.csv');                  -- 与 PATTERN 二选一 ⚠️
COPY INTO sales.raw_orders (id, amount_c, load_ts, src_file)
  FROM (SELECT $1, $2::NUMBER(18,2), current_timestamp(), metadata$filename
        FROM @mystore (FILE_FORMAT => 'mycsv'));    -- 装载即转换（data-load-transform ✅）
```

**（b）幂等语义**：COPY 按文件级元数据跟踪"已载入且未变更"的文件，重复执行不重导——这是批量
管道可重跑性的根 ⚠️ 转述 ✅ copy-into-table；文件改名/变更则视为新文件（工业实践常见坑）。

**（c）落盘形态：微分区（micro-partition）**：COPY 写入的不是行堆，而是按列存储、自带每列
min/max 与计数统计的不可变文件块 ⚠️ 转述 ✅
https://docs.snowflake.com/en/user-guide/tables-micro-partitions；块间**没有**显式全局排序，
相关性靠"写入时的自然序 + 后续聚簇"经营（聚簇体系在 09 章深化、Tuning 册展开）✅
https://docs.snowflake.com/en/user-guide/tables-clustering-micropartitions。

**（d）装载侧的仓库选择**：COPY 吃装载仓的 credit（03 章参数直接兑付）；书内场景用 Medium/Large
夜批仓 ⚠️ 推定；观测句：`SELECT * FROM table(snowflake.account_usage.copy_history)` ✅
account-usage 主题页。

## 4. 🔧 本地类比实验（E1/E2，非 Snowflake 行为）

用 DuckDB 1.5.5 演示"列存块 + 块级 min/max 剪枝"两个与微分区同型的概念（**DuckDB 不是
Snowflake，块大小/统计结构/剪枝算法均不同，仅建立直觉**）：

```text
E1  250,000 行表 → pragma_storage_info 可见 3 个 row group（≈122,880 行/组）
    —— 类比：数据被切成定长列存块，块自带统计。
E2c 1,000,000 行、谓词 v∈[500,503]，按段统计解析 [Min,Max]：
    有序表：命中 1/18 段；乱序表：命中 18/18 段
    —— 类比：写入序=未来扫描面；聚簇键在"重排块"而非"建索引"。
```

输出存 `D:\develops\tmp\dbwave_w10_jpsf\exp.txt` / `exp2.txt`，数字为真实测量。两条可迁移
工程直觉：①装载时尽量按未来高频过滤列有序落盘（书中"sorted upload"思路同型 ⚠️）；②剪枝
收益是数量级的，先于加仓库尺寸（03 章 Q3 呼应）。

## 5. 深读问答（自拟）

**Q1：COPY 与 Snowpipe 的机制边界？** A：同一文件格式/stage 体系，差别在"谁触发"：COPY=你
触发的批；Snowpipe=事件触发的微批（06 章）✅ data-load-snowpipe-intro。
**Q2：为什么 PATTERN 误匹配是静默事故？** A：COPY 只报聚合统计，不逐文件告警；上线前应
DRY RUN（`VALIDATE` / LIMIT 0 ⚠️ 口径以官方页为准）。
**Q3：预签名 URL 装载适合什么场景？** A：一次性外送数据入仓、不便建持久 stage 时；书内作为
低摩擦路径演示 ⚠️。
