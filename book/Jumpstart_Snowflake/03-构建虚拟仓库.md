## 3. 深读与机制重构

**（a）参数样板（自拟示意，非书中原文）**：

```sql
CREATE WAREHOUSE wh_etl
  WAREHOUSE_SIZE = 'MEDIUM'
  AUTO_SUSPEND = 60            -- 秒；2019 讨论焦点：太短伤缓存、太长烧 credit
  AUTO_RESUME = TRUE
  INITIALLY_SUSPENDED = TRUE
  MAX_CONCURRENCY = 4
  COMMENT = 'nightly bulk loads (ch04) + snowpipe backpressure buffer (ch06)';
ALTER WAREHOUSE wh_etl SET WAREHOUSE_SIZE = 'LARGE';   -- 尺寸可在线改
USE WAREHOUSE wh_etl;
SELECT CURRENT_WAREHOUSE();
```

**（b）尺寸的算术**：2019 口径 credit 消耗近似与尺寸成倍数阶梯（S=2×XS 类推 ⚠️ 转述，官方
从未承诺严格等比），同 SQL 跑大仓库主要赢在"更多核+更大本地缓存"，不改变扫描的数据量——
数据量由聚簇/剪枝决定（04 章 🔧 E2 正为此埋线）。现状参数面 ✅
https://docs.snowflake.com/en/user-guide/performance-query-warehouse-size。

**（c）暂停策略 = 工作负载形态问题**：交互式 BI（分钟级、多次点击）→ 长 AUTO_SUSPEND 保缓存；
ETL 突发（一天两高峰）→ 短 AUTO_SUSPEND 甚至 INITIALLY_SUSPENDED；Snowpipe 专用小仓→ 常驻
（06 章呼应）。这套"按到达模式定停驻"的直觉，在 2026 被 Adaptive Compute 接管了大半（演进节）。

**（d）多集群仓库**：同仓库内并行多集群应对并发爆发；SHARED=按队列自动加撤、RESPONSIVE=
优先不减员 ⚠️ 转述 ✅ https://docs.snowflake.com/en/user-guide/warehouses-multicluster。
本章时代还强调"先加尺寸、再加集群"的经验序；2026 口径已改为平台自适应 ⚠️。

**（e）观测句法**：`SHOW WAREHOUSES` 看 STATE/ESTIMATED_RESTART_TIME；用量的权威源是
ACCOUNT_USAGE.WAREHOUSE_METERING_HISTORY ✅
https://docs.snowflake.com/en/sql-reference/account-usage/warehouse_metering_history（07 章
资源监视器与之合流）。

## 4. 🔧 本地类比实验（E3，非 Snowflake 行为）

以 DuckDB 线程数类比"仓库尺寸=并行核数"的直觉（**本机无 credit、无云集群，仅演示并行度对
聚合耗时的影响；不构成对 Snowflake 尺寸的任何量化推断**）：

```python
con.execute("SET threads=1");  # 5M 行聚合×3 → 459.1 ms
con.execute("SET threads=8");  # 同一查询组      → 122.9 ms   speedup≈3.74×
```

实测环境：DuckDB 1.5.5 / python 3.13.2，输出存 `D:\develops\tmp\dbwave_w10_jpsf\exp.txt`。
可迁移的结论只有一条：并行收益非线性（缓存行/争用/单点聚合限制），与书中"换仓库尺寸不是
线性买性能"的告诫同型 ⚠️。

## 5. 深读问答（自拟）

**Q1：为什么"仓库暂停后第一个查询更慢"？**
A：本地 SSD 数据缓存与结果缓存随集群释放蒸发，冷启动=重新拉存储层+重编译 ⚠️；🔧 E3 的
并行非线性提示我们：热仓收益大于盲目加尺寸。
**Q2：AUTO_SUSPEND 设 0（禁用）何时合理？**
A：近乎恒载或延迟极敏感管线，但必须配资源监视器封顶（07 章）✅ resource-monitors。
**Q3：尺寸与聚簇谁先动？**
A：先剪枝（聚簇/过滤）后算力——🔧 E2 显示有序数据可把扫描面缩到 1/18；算力解决不了全表扫。

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话释义 |
| --- | --- | --- |
| 虚拟仓库 | virtual warehouse | 租用式 MPP 算力集群，计费单元 |
| 仓库尺寸 | warehouse size (XS…X-Large) | 并行核数档位，credit 消耗主因子 |
| 自动暂停 | auto-suspend | 空闲 N 秒后释放集群省钱 |
| 自动恢复 | auto-resume | 来查询自动拉起（有冷启动等待） |
| 多集群 | multi-cluster warehouse | 同仓并集群以吞吐并发 |
| 共享/响应模式 | shared / responsive | 自动缩 vs 保集群两种扩缩策略 |
| 最大并发 | max concurrency | 集群内并行跑查上限，超出排队 |
| 冷/热仓库 | cold / warm warehouse | 缓存有无导致的时差状态 |
| 计量史 | warehouse metering history | credit 用量的权威账本视图 |
| 自适应计算 | adaptive compute | 2026 GA：尺寸/并发平台自管 |
