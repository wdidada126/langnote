## 1. 章节定位与叙事线

2019 独有卖点叙事：数据共享长期=文件投递/ETL 复制/数据库链接三件套，各有各的腐烂方式；
Snowflake 把共享做成**元数据动作**——授予 SHARE、加消费者账号、对方 `CREATE DATABASE FROM SHARE`，
此后消费方用自己的仓库（自己的 credit）实时查询提供方数据，**零拷贝、零搬运、始终最新**。
本章链：共享三原则 → SHARE 对象与授权语法 → 提供方/消费方双侧操作 → 安全视图细粒度包装
（08 章联动）→ Reader Account 给无账号消费者 → Marketplace 公/私 Offer 生态 ⚠️ 推定。

## 3. 深读与机制重构

**（a）双侧语法对照（自拟示意，非书中原文）**：

```sql
-- 提供方（Provider）
CREATE SHARE acme.core_share;
GRANT USAGE ON DATABASE sales TO SHARE acme.core_share;
GRANT USAGE ON SCHEMA sales.core TO SHARE acme.core_share;
GRANT SELECT ON VIEW sales.core.v_orders_clean TO SHARE acme.core_share;  -- 视图藏敏再共享
ALTER SHARE acme.core_share ADD ACCOUNTS = xy999001, ab111222;

-- 消费方（Consumer）
CREATE DATABASE acme_core FROM SHARE sales.core_share;
USE WAREHOUSE consumer_wh;   -- 关键：查询吃消费方自己的仓库与 credit
SELECT count(*) FROM acme_core.sales.core.v_orders_clean;
```

机制与不变量 ⚠️ 转述 ✅ https://docs.snowflake.com/en/user-guide/data-sharing-intro：共享是
跨账号读权限，不提供写；提供方改数据消费者即时可见（同一份物理微分区，04 章存储层的跨账号
投影）；计费上提供方"不付查询的钱"⚠️（现行细则以官方页为准）。

**（b）安全视图作为"共享策略层"**：直接共享裸表=放弃行/列裁量权；本章标准姿势=视图先裁后共享
（08 章 SECURE VIEW 语义在此二次利用）✅ https://docs.snowflake.com/en/user-guide/views-secure；
2026 该职责迁往 masking/row-access 策略+共享面组合（演进节）⚠️。

**（c）Reader Account 的商务意义**：给"没有 Snowflake 账号"的消费者开轻量只读账号，把共享从
"平台内协作"扩展为"平台对外供给"——Marketplace 的地基 ⚠️ 转述 ✅
https://docs.snowflake.com/en/user-guide/data-sharing-provider。

**（d）共享×半结构化**：VARIANT 表同样可共享（09 章联动）；跨账号看 JSON 明细=2019 数据产品
常见形态 ⚠️。

## 4. 🔧 本地类比实验（E6，非 Snowflake 行为）

用 SQLite 3.45.3 ATTACH 演示"共享=挂载而非复制"的最小语义（**本地 ATTACH 无跨账号权限体系、
无各自计费，仅示意目录级引用**）：

```text
pub.db 建 sales(region,amt) 两行 → main.db:
ATTACH 'pub.db' AS shared;
SELECT * FROM shared.sales;   → [('APAC',3), ('EMEA',5)]   —— pub.db 文件零拷贝零变动
main.db 自身对象清单为空       —— "消费方只见被授权对象"的粗类比
```

实测输出存 `D:\develops\tmp\dbwave_w10_jpsf\exp3.txt`。差异诚实登记：SQLite ATTACH 是全库
可读（无表级 SHARE 粒度）、同进程同账本（无 credit 隔离）——真实共享的权限/计费/审计面恰是
Snowflake 的增量价值所在 ⚠️。

## 5. 深读问答（自拟）

**Q1：共享与"再建一个只读副本仓"比，省在哪？** A：省存储复制、省同步管道、省陈旧窗口；
一致性由元数据层天然保证 ⚠️+✅ data-sharing-intro。
**Q2：消费方查询慢会影响提供方吗？** A：算力隔离（各吃各仓，03 章），提供方只暴露元数据与
存储读——这正是存算分离在协作场景的红利 ⚠️。
**Q3：共享的失效半径？** A：撤销 GRANT/ALTER SHARE 即刻生效；提供方改名/删对象=消费方断
——治理要像对外 API 一样管共享面 ⚠️。
