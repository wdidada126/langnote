# 11 Tuning Cassandra Performance（性能调优）

> 原书第 11 章章名 ✅ Crossref 实抓；小节结构为推定重构 ⚠️。无实机基准（集群不可测 ⚠️），
> 参数语义与默认倾向按 3.x 官方文档口径转述，具体默认值凡不确定处均 ⚠️ 标注。

## 题纲

调优次序铁律：**先模型（04），再拓扑（03），后参数（本章），最后才是玄学**。
Cassandra 的性能账本只有四行：写放大（commitlog/memtable/压实）、读放大（墓碑/文件数/散扫）、
空间放大（副本×压缩）、协调开销（跨节点跳数与等待）。本章逐行给出"旋钮→账单"映射，
所有动作以 10 章指标回基线为完成判据。

## 1. 写路径调优

- **commitlog fsync**：`commitlog_sync` periodic（周期 ms）vs group（批量组提交）vs
  `delay` 模式；fsync 延迟是 SSD/RAID 电池缺失集群的头号写瓶颈（09 章硬件合同回环 ⚠️）。
- **memtable**：`memtable_heap_space`/`memtable_offheap_space` 与刷盘触发
  （`memtable_cleanup_threshold` 一线参数 ⚠️ 3.x 具体键名以文档为准）；
  刷盘被压实拖住=连锁写停顿（10 章 pending flushes 证据）。
- **压实限流**：`compaction_throughput_mb_per_sec` 书内启发式≈入口写速率的 2 倍 ⚠️ 通述；
  限流过死→文件堆积→读劣化（§2 的因果链在 09 章工单模板里闭环）。
- 客户端侧：异步驱动+合理并发、batch 节制（06 章）、UNLOGGED 用于同分区批量原子场景。

## 2. 读路径调优

- **bloom filter** `bloom_filter_fp_chance`：调低省内存换假阳、调高相反——按 10 章读延迟
  与内存账折中。
- **缓存**：3.0 移除旧 row cache、以 key cache/partition cache 承接 ⚠️ 通述；
  键缓存命中率是点查集群的命门。
- **speculative retry**（SLFR/ALWAYS）：对"慢副本"提前重试，治 GC 毛刺型长尾；
  配 `read_request_timeout` 家族参数使用 ⚠️。
- 墓碑与宽分区治理：`tombstone_warn_threshold`/`warn` 调参只治报警不治病——
  病根在 04 章模型与 09 章修复节奏，TTL 替代删除是总解。
- 2i/SASI 查询改造优先于索引参数调优：能用聚簇前缀解决的查询不该活在索引上（04/06 章）。

## 3. 协调与网络

- 副本数 RF 与跳数：token-aware 驱动让协调者=本地副本，省一跳 WAN（05/07 章）。
- CL 降级使用协议：`nodetool setconsistencylevel` 等临时手段属事故工具，不是日常调优 ⚠️。
- 线程池调优保守主义：`concurrent_reads/writes` 默认按核数自适应 ⚠️ 通述，
  改前先证明队列非伪瓶颈（10 章 tpstats）；`index_summary_capacity`/page cache 类
  "别动"参数清单同样长。
- Message 池与跨 DC 带宽（03 章预算回环）；`php`（phi）参数暴露面极小，动它=玩火 ⚠️。

## 4. JVM/GC

- 3.x 书语境：大堆（8~31GB 经验带 ⚠️）、CMS 系调参、`-XX:+UseCondCardMark` 类常见建议 ⚠️ 通述；
  停顿目标=99th 延迟预算的 1/3。
- 诊断入口：gc.log（09）、`nodetool profile`（async-profiler 集成，3.x 后期 ⚠️）、
  JFR 在 JDK8u 可用 ⚠️。
- 2026 对位见文末（JDK17/G1/ZGC 换血）。

## 5. 基准与调优流程（本章的方法论收口）

1. cassandra-stress/真实回放建立基线（10 章）。
2. 用 10 章映射表定位"四行账本"中最差的一行。
3. **一次只动一个旋钮**，A/B 到等价流量，指标回基线才合单（09 工单模板）。
4. 把结论写回 runbook 与 04 章评审清单——调优的终点是模型/拓扑决定的固化，不是参数堆积。
5. 记录纪律：每个旋钮改动留档 {参数, 前值, 后值, 证据链接}，一次只动一个变量（09 章工单模板）。

## 6. 调优侦察命令卡（⚠️ 转述）

```bash
# 四行账本各取一个证据
nodetool tpstats            # 协调开销：池 pending/dropped
nodetool compactionstats    # 写放大侧：待压字节与限流效果
nodetool proxyhistograms    # 读放大侧：百分位形态
df -h && nodetool tablestats|head   # 空间放大：副本×压缩比（3.x 后期版本键名 ⚠️）
# 诊断入口
nodetool profile                            # 火焰图（3.x 后期，⚠️ 版本核对）
cqlsh> TRACING ON; SELECT ...; SHOW TRACING; # 单次读解剖（05 章路径）
bin/cassandra-stress write n=1000000 -rate threads=200 -mode native=...  # 基线钟（10 章）
```

## 核心概念速览（中英对照）

- **write amplification** — 写放大：一次写在 commitlog/刷盘/压实中被重复的倍数。
- **read amplification** — 读放大：一次读穿过的文件数×墓碑数×散扫范围。
- **compaction throttle** — 压实限流：后台重写带宽帽，读写跷跷板的支点。
- **pending flush** — 刷盘积压：memtable 冻结未落盘，写停顿前兆。
- **bloom fp chance** — 假阳率：内存与"白读文件"的兑换率。
- **key/partition cache** — 键/分区缓存：3.0 后缓存形态，点查命门。
- **speculative retry** — 投机读：向备用副本提前发读，治长尾毛刺。
- **tombstone warn** — 墓碑预警阈值：报警是病征，TTL/模型才是药。
- **concurrent_reads/writes** — 读写并行度：按核自适应，动前自证必要。
- **async-profiler / nodetool profile** — 火焰图入口：3.x 后期内置的热点显微镜。
- **GC pause budget** — 停顿预算：99th 延迟的三分之一经验线 ⚠️。
- **cassandra-stress** — 基线发生器：调优 A/B 的流量钟。
- **one knob at a time** — 单变量纪律：调优工单的防污染条款。

## 最新演进与工业实践

- **UCS（✅ 5.0 new features 页 CEP-26 实抓）**：统一压实按"窗口+层级"自适应，
  STCS/LCS/TWCS 手工选型基本退役；§1 的限流跷跷板问题大半由 UCS 的后台预算吸收。
- **SAI（CEP-7 ✅）**：索引写路径内联+内存硬上限，把"SASI 调参学"变成"配额管理"；
  向量检索（CEP-30）性能话题在 2026 年接棒了 2i/SASI 的位置（04 章对位）。
- **trie memtable（CEP-19）/trie SSTable（CEP-25）✅**：大分区顺序扫与内存账本翻新，
  §2 的"宽分区罚单"在 5.0 上显著减额 ⚠️ 效果以官方口径转述。
- **guardrails（✅ 5.0 清单 "More guardrails"）**：分区大小/IN 数量/桶比等直接拒绝
  "会拖垮集群的查询"，把 04 章评审清单变成运行时执法。
- **JDK17 换血（✅ 同页）**：CMS 剧本作废；G1 默认、低停顿场景试 ZGC/Shenandoah ⚠️ 通述；
  `nodetool profile` 之后 JFR 一等公民化趋势明显。
