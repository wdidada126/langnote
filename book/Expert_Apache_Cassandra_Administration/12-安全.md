# 12 Securing Cassandra（安全）

> 原书第 12 章章名 ✅ Crossref 实抓；小节结构为推定重构 ⚠️。安全配置语义按 3.x 文档口径
> 转述 ⚠️（无实机验证），2026 条目均注明取证方式。

## 题纲

Cassandra 的默认姿态是"内网可信"——02 章装完就能匿名读写正是这个默认。本章按
**认证（谁）→ 授权（能干什么）→ 传输加密（路上）→ 静态加密（盘上）→ 审计（事后）**
五层展开，并给出"暴露面最小化"的端口/网络合同（03 章矩阵的安全镜像）。

## 1. 认证（Authentication）

- 3.x 默认 `AllowAllAuthenticator`；生产首日改 `PasswordAuthenticator`（yaml 重启生效，
  初始超管 `cassandra/cassandra` ⚠️ 通述）。
- 角色体系（2.2 起 roles 统一用户）：`CREATE ROLE app_rw WITH PASSWORD ... AND LOGIN = true`；
  `cassandra` 超管的口令**第一件事就是改掉**（工单挂在 02 章验收后）。
- 可插拔：`Authenticator` 接口对接 LDAP/Kerberos 属外部实现——书内立场"社区实现质量自担" ⚠️。
- cqlsh/驱动侧：`-u/-p`、明文认证插件与 SSL 必须配对（否则口令裸奔 ⚠️）。

## 2. 授权（Authorization）

- 默认 `AllowAllPermissions`（放行一切）→ 换 `CassandraAuthorizer` 后 GRANT/REVOKE 才生效（06 章语法回环）。
- 粒度：键空间/表/物化视图/角色四级；`GRANT MODIFY ON TABLE app.events TO app_rw` 类语句；
  审计问题"谁能删表？"用 `LIST PERMISSIONS OF app_rw` 回答。
- 运维纪律：应用账号**永不**持有 schema 变更权；超管口令入密管系统不入代码 ⚠️ 通述。

## 3. 传输加密（Encryption in transit）

- 客户端↔集群：`client_enc_options`（keystore/truststore、`optional` vs 强制）；
  证书链与主机名验证的坑在 `require_endpoint_verification` 一线参数 ⚠️ 通述。
- 节点↔节点：`server_encryption_options` 的 `internode_encryption` = none|dc|rack|all——
  多 DC 生产建议至少 `dc`；加密全开对 CPU/尾延迟有账（11 章基准方法适用）⚠️。
- 端口合同（03 章矩阵的封锁版）：7000/7001 仅集群网段，7199 仅运维网段+**JMX 认证**
  （`local`/远程 jmxremote.password 的弱口令默认是经典事故 ⚠️），9042 才面客。
- JMX/jolokia：3.x 的 HTTP-JMX 桥默认免认证——要么关掉要么置于代理之后 ⚠️（4.0 默认禁用，✅ NEWS.txt）。

## 4. 静态加密与密钥（Encryption at rest）

- 3.x 开源版现状：**表级 AES 透明加密属 DSE/第三方方案**，开源主线以磁盘级加密
  （LUKS/云盘 KMS）+ 快照文件同等保密为兜底 ⚠️ 通述（本书语境）。
- 升级路线预告（文末）：4.0 落地开源透明数据加密（TDE）+ 外部 KMS 对接（⚠️ 版本细节转述）。
- 密钥卫生：备份介质=第二把锁（08 章快照外拷的目的地安全）；
  日志/修复流量同样含数据，加密覆盖要算到"机制全图"（05 章）。

## 5. 审计与事后取证

- 3.x `AuditLogger` 接口初建（实验色彩 ⚠️）：`bin/auditlog-archiver` 类配套简陋，
  多数生产选择"驱动侧/网关侧审计+system.log 抽取"的过渡方案 ⚠️ 通述。
- 最小审计集：登录失败、schema 变更、DROP/TRUNCATE、授权变更、超管一切操作（09 章工单模板挂钩）。
- 取证链：audit→system.log→修复历史（10 章三对齐）；"谁改了数据"Cassandra 给不了全答案
  （无行级历史），要靠 CDC/应用侧留痕（08 章 CDC 语境）。

## 6. 部署期安全基线检查单（本章交付物）

1. authenticator/authorizer 均已切换且超管口令已改。
2. 应用角色最小权限；schema 权限单独角色+双人复核。
3. internode 加密 ≥ dc 级；JMX 有口令且网段封锁；jolokia 关闭或代理化。
4. 客户端强制 TLS（或证明网络隔离等价）；证书轮换写进 09 章日历。
5. 静态加密方案选型成文（盘级 or 4.x TDE）；备份介质安全合同签署。
6. 审计最小集开启并有 30 天+ 留存（10 章留存策略）。


## 核心概念速览（中英对照）

- **AllowAllAuthenticator** — 免认证默认：内网信任姿态的化身，生产首日必须替换。
- **PasswordAuthenticator** — 口令认证器：内置 roles 体系的本地凭据源。
- **role** — 角色：用户/组统一抽象，GRANT 的主体。
- **CassandraAuthorizer** — 内置授权器：键空间/表/视图/角色四级权限引擎。
- **internode_encryption** — 节点间加密档位：none/dc/rack/all 四挡。
- **keystore/truststore** — JKS 证书容器：服务端身份与信任链的载体。
- **client_enc_options** — 客户端 TLS：optional→required 的强制化开关。
- **JMX attack surface** — JMX 暴露面：7199+jolokia 的经典弱门。
- **TDE** — 透明数据加密：开源版 4.x 才到位的表级静态加密。
- **AuditLogger (3.x)** — 审计接口初版：GA 化是 4.x/5.x 的事（文末）。
- **least privilege** — 最小权限：应用账号无 schema 权等纪律的总称。
- **secret hygiene** — 密钥卫生：口令/证书/KMS 的轮换与存放合同。
- **exposure matrix** — 暴露面矩阵：端口×网段的封锁表（03 章镜像）。

## 最新演进与工业实践

- **5.0 两大新件（✅ 官方 new features 页实抓）**：**CIDR authorizer（CEP-33）**——按源 IP 网段
  授权（"仅内网段可跑批"这类规则的表达式）；**动态数据脱敏 DDM（CEP-20）**——列级掩码按角色
  生效，脱敏从应用层下沉到数据库层。
- **审计现代化（✅ 5.0 文档树 "Audit logging 2" 专页实抓）**：4.1/5.x 的审计 v2（CEP-22 谱系）
  提供 bin 格式+归档工具链；"Full query logging"虚拟表页同树在档——§5 的过渡方案可退役。
- **开源 TDE 转正**：4.0 起透明数据加密进入主线并支持外部密钥管理（⚠️ 版本细节转述）；
  盘级加密从"唯一选择"降级为"纵深一层"。
- **默认安全化趋势**：4.0 jolokia/弱门默认收紧（✅ NEWS.txt 语境）、5.0 的 guardrails 也拦截
  危险查询形态——"默认内网可信"哲学在 2026 已被"默认最小暴露"替代。
- **云与托管**：IBM/Astra DB 体系的托管实例以 API token/证书+网络私化为主（⚠️ 报道口径），
  自建集群的上述五层合同仍是面试与审计的双标准答案。
