# 10 Monitoring, Logging, and Metrics（监控、日志与指标）

> 原书第 10 章章名 ✅ Crossref 实抓；小节结构为推定重构 ⚠️。指标体系按 3.x 口径转述 ⚠️，
> 2026 演进条目均注明取证方式。

## 题纲

Cassandra 的健康不可用"存活探测"衡量，要用**三面镜子**：吞吐/延迟直方图（用户视角）、
线程池与队列（内部视角）、磁盘/压缩/修复账单（后台视角）。本章给出 nodetool 现场工具、
JMX 指标面、日志族谱，以及一张"告警→根因"的映射表——它是 09 章每个 runbook 判据的来源。

## 1. nodetool 现场三件套（⚠️ 转述用法）

```bash
nodetool status / info / ring          # 成员与身份
nodetool tpstats                       # 线程池：pending/completed/dropped 一览
nodetool proxyhistograms               # 客户端视角读写延迟百分位直方图
```

- `tpstats` 的 `dropped mutations`（超时被弃的写）是**集群级红色警报**的第一格；
  HintedHandoff/ReadRepair/RequestResponse 池的 pending 堆积各自对应 05 章一条机制。
- `compactionstats`（待压字节、进行中任务）、`netstats`（stream/hint 流动）、
  `gossipinfo`（环上状态原文）、`tablestats/cfstats`（3.x 后期版本引入 tablestats ⚠️）。
- 脚本化：nodetool 走 JMX（7199），监控集成经 **jolokia**（3.x 时代 HTTP-JMX 桥，
  4.0 起默认禁用、cassandra-env.sh 注释开关可见 ✅ NEWS.txt 4.0 实抓）或 JMX exporter。

## 2. 指标面（3.x 口径：Codahale Metrics2 via JMX，⚠️ 转述）

按运维重要度分层采集清单：

| 层 | 关键指标 | 阈值直觉 ⚠️ | 对应章 |
|---|---|---|---|
| 客户端 | read/write latency 50/99th、unavailable/write timeouts | 99th 翻倍即工单 | 04/11 |
| 内存 | memtable 占用比、pending flushes | flush 堵→压实跟不上 | 05/11 |
| 磁盘 | live/compacting 字节比、每表文件数（sstables per table） | 文件数>压缩 fan-in 两倍即预警 | 05/09 |
| 复制 | hints 计数与积压、read repair 量 | hint 窗口临近 3h 升级 | 05/09 |
| 队列 | Message/Storage 池 pending、dropped msgs | 任意 dropped 非零=红 | 03/11 |
| JVM | heap、GC 时长/频次、老代增长 | GC>1s 尖峰=毛刺嫌疑人 | 02/09 |
| 修复 | repair 历史耗时/字节（system_distributed） | 全环耗时 vs GC grace | 09 |

## 3. 日志族谱（现场取证的层级）

- `system.log`（INFO 默认）：入环/错误/警告（tombstone 扫描警告、压缩错误都在这）。
- `debug.log`（默认关）：排查期临时开——生产常开的代价是 I/O。
- `gc.log`：09 章 JVM 合同的执行记录。
- `audit`（3.x 接口初建）：谁在什么时候做了什么（12 章启用，本章负责读）。
- `cqlshell/cassandra-stress` 日志属工具，不入监控面。
- 日志行解析：官方 `tools/bin/cassandra-stress` 之外，`$CASSANDRA_HOME/tools` 有简单
  log 统计工具；社区实践更常用采集器+面板（文末 2026 主流）。

## 4. 告警→根因映射表（本章交付物 ⚠️ 推定重构）

| 症状 | 首选证据 | 常见根因 |
|---|---|---|
| 读延迟毛刺 | proxyhistograms + debug.log tombstone 行 | 墓碑堆积/未修复分歧（04/05） |
| 写超时增 | tpstats dropped + netstats | 单节点 GC 长停顿（09/11） |
| 磁盘水位涨 | compactionstats + 每表文件数 | 压缩限流过死/残留副本未 cleanup（09） |
| hint 积压 | tpstats + 目标节点 status | 退役节点未走 decommission（03） |
| status 反复 JOINING/LEFT | gossipinfo + gc.log | 网络/时钟/磁盘 fsync 慢（09） |
| schema 版本分歧 | describecluster | 变更期间节点离线（06/09） |

## 5. 容量与基线管理

- 基准工具：cassandra-stress（混压/写压/读压，模板可调 04 章 CL/RF）；
  大促/扩容前先跑基线，指标表全部用"基线×系数"报警而非绝对值 ⚠️ 通述。
- 面板最小集（社区惯例 ⚠️）：节点×六层（§2）、环级 dropped 单图、修复日历、hint 水位。
- 日志留存：debug 轮转短存、system 长存；事故复盘=日志+指标+修复历史三对齐（9 章工单模板）。

## 6. 现场命令卡（⚠️ 转述）

```bash
nodetool tpstats | grep -Ei 'pending|dropped'        # 心电图第一格
nodetool proxyhistograms                              # 99th 一眼定嫌疑人
nodetool compactionstats; nodetool netstats           # 后台账单两连
nodetool tablehistograms app events                   # 表级分布（版本键名差异 ⚠️ 以文档为准）
nodetool disableautocompaction app events   # 修复/批量搬运前的临时闸（9 章配合，用完必须 enable）
curl -s localhost:8778/jolokia/read/… | head          # JMX 桥侦察（4.0+ 默认已关，✅NEWS）
tail -F logs/system.log | grep -Ei 'tombstone|error|warn'   # 报警行三关键词
```

## 核心概念速览（中英对照）

- **tpstats** — 线程池统计：pending/completed/dropped 三列，Cassandra 心电图。
- **dropped mutations** — 被弃写：超时即数据风险，非零必查。
- **proxyhistograms** — 代理直方图：协调者视角的读写延迟百分位。
- **Metrics2 / Codahale** — 3.x 指标框架：经 JMX 暴露的计数器/仪表/直方图。
- **jolokia** — HTTP-JMX 桥：3.x 监控集成常道，4.0 起默认关（✅ NEWS）。
- **compactionstats** — 压实现场：进行中/待压字节，11 章限流的判据源。
- **gossipinfo** — gossip 原文：排查节点"眼中的彼此"的透视镜。
- **system_distributed.parent_repair_history** — 修复履历表：09 章窗口计算的账本。
- **size_estimates / tablestats** — 规模画像：分区/表级尺寸趋势，4 章评审的输入。
- **unavailable/write timeouts** — 超时族：CL 未达标的两类签名（读不可用/写未齐）。
- **tombstone warn** — 墓碑警告行：debug.log/system.log 里的读放大预警。
- **cassandra-stress** — 官方压测器：基线与回归的流量发生器。
- **log rotation** — 日志轮转：debug 短存/system 长存的留存合同。
