## 12.3 代表配方精读

### 配方：Comparing indexed scans and sequential scans / Index lookup

- 方法：同一谓词在 `enable_seqscan=off` 前后各测（当日演示套路），让读者**亲眼看见成本翻转点**
  （选择率/表尺寸/缓存态三参数）。⚠️ 转述（题录 ✅）。
- 度量端：`pg_stat_user_indexes` 的 idx_scan 与 `pg_statio_user_indexes` 的 heap/idx_blks_read——
  "用了但没省 IO"的分辨力。配方 1 的 `indexrelid::regclass` 反查即此链第一环。

### 配方：Concurrent indexes 与索引维护工程

- `CREATE INDEX CONCURRENTLY`（8.3 起 ✅ 版本常识）：两遍扫描+等待事务，不锁写；失败留 INVALID
  索引需 DROP 重来——当日三大坑：长事务卡构建、空间放大两倍峰值、副本回放延迟。
- 对应治理：`pg_index.indisvalid` 巡检（txt 首段正是 `indisprimary IS FALSE` 型查询 ✅）。

### 配方：Combined/Partial indexes 与选择学

- 多列索引：等值列在前、范围列殿后、覆盖列可选（index-only scan 前置条件=visibility map 健康，
  与第 9 章 vacuum 联动——全书知识在此拧成一股）。
- 部分索引：`WHERE` 谓词与查询谓词匹配才进场；经典用例=布尔列真值稀薄/租户热点/唯一约束
  （`CREATE UNIQUE INDEX ... WHERE deleted IS NULL` 软删除模式）。✅ 语义，🔧 实测见 12.6。

### 配方：Clustering against an index

- `CLUSTER tbl USING idx` 重写表物理序逼近索引序→范围扫描回表局部性↑；**一次性动作不随更新维持**，
  需周期性重做（窗口=全表重写，与第 7 章备份窗口互斥安排）。
- 理论层（聚簇为何有时反而坏、MDC 替代）：[../Physical_Database_Design/07-多维聚簇MDC.md](../Physical_Database_Design/07-多维聚簇MDC.md)。

### 配方：Finding unused / Detecting missing / Forcing（治理三角）

- 未用：pg_stat_user_indexes.idx_scan=0 且跨过完整业务周期→候选删除；先 `DROP ... CONCURRENTLY`?
  （⚠️ 语法：PG 无 CONCURRENTLY DROP INDEX 语义，用 DISABLE 思路/分步）——2017 原书给删+观察法。
- 缺失：慢 SQL 的谓词组合→HypoPG 假想索引重跑 EXPLAIN（11 章演进节呼应）。
- 强制：`pg_hint_plan`（当年即推荐 ✅ 主题）或调试期关扫描类型；生产钉选需谨慎（计划漂移）。⚠️

## 12.4 机制小深潜：为什么"索引越多越慢"不是口号

每写一行=每索引一条插入+页分裂风险+vacuum/visibility 维护；本章配方 8 的存在即承认"索引债务"。
写密集系统的索引预算制（读收益 vs 写税+空间税）与 [../Database_Tuning/03-索引调优.md](../Database_Tuning/03-索引调优.md)
同构；理论选型法（列覆盖/候选生成分支定界）见
[../Physical_Database_Design/04-索引选择方法.md](../Physical_Database_Design/04-索引选择方法.md)。
引擎对照：InnoDB 二级索引=主键叶子回指、PG 堆索引=元组指针，成本结构差异直接改"覆盖索引"收益。⚠️

## 12.7 适用性判断（2026）

十章配方**九章仍有效**（度量/并发构建/组合/部分/聚簇/缺失检测全部当日可用）；被时代改写的是：
B-tree 去重（PG17）令"同值多行索引"体积大减、`CREATE INDEX ... NOT VALID`+`VALIDATE`（PG16）
让"强制/试建"更安全、BRIN 对超大表的替代、覆盖索引+index-only scan 成为默认追求。⚠️/✅见演进节。

## 高频坑与实操清单

- CONCURRENTLY 构建失败留下 INVALID 索引：占写税不被读用，`pg_index.indisvalid=false` 巡检+
  清理是例行条款（配方 1 反查语句即为此设）。
- 并发建索引被长事务卡两遍扫描（09 章老熟人）：建索引窗口前先清 xmin。
- `CLUSTER` 持 ACCESS EXCLUSIVE 且全表重写，大表=停摆级；生产替代是 pg_repack 的按簇重组。⚠️
- DROP INDEX 级联依赖（多列 UNIQUE 约束/PK 背后索引不可直删）：先查 `pg_depend` 再动手。
- "未用索引"判定必须跨过完整业务周期（月结/大促/年报），一周的 idx_scan=0 会误杀季度报表索引；
  删除前先 `RENAME` 观察一周是低成本保险。
- 部分索引谓词是**语法级匹配**：查询里多一个括号/函数改写都会让索引失去资格，应用 SQL 规范要
  与索引定义同源管理。
- index-only scan 依赖 visibility map 新鲜度：vacuum 停摆→回表激增→"索引没变查询却变慢"（09 章
  因果链第三环）。
- 覆盖索引不是越多列越好：写税+体积+失效半径，X-F 的 1495 倍收益只属于真正命中的那条谓词。
- `pg_hint_plan` 上生产前设 `hint_plans` 作用域与失效告警：钉选计划=把优化器升级红利主动退回。⚠️

## 核心概念速览（中英对照）

- **索引检索** — Index lookup/scan：按键定位元组指针再回表（PG TID 语义）。
- **仅索引扫描** — Index-only scan：免回表读索引页，依赖 visibility map。
- **并发建索引** — CREATE INDEX CONCURRENTLY：不锁写的两遍扫描构建，失败留 INVALID。
- **组合索引** — Combined (multi-column) index：列次序=等值→范围→覆盖的学问。
- **部分索引** — Partial index：带 WHERE 的瘦身索引，谓词匹配方进场。
- **聚簇** — CLUSTER：按索引序重写堆，一次性收益需周期重做。
- **未用索引** — Unused index：跨周期 idx_scan=0 的写税制造者，治理对象。
- **索引统计** — pg_statio_user_indexes：块级读/命中度量"用了值不值"。
- **提示计划** — pg_hint_plan：外置 hint 强制/试探索引选择的扩展。
- **B 树去重** — B-tree deduplication：同键值单列表项多偏移，PG17 索引体积革命。✅
- **BRIN** — Block range index：超大规模时序表的微型块范围摘要索引（后时代替代位）。⚠️

## 最新演进与工业实践

- **PG17 B-tree 去重（本章最大演进）**：重复键值合并存储，含冗余键的索引显著缩小、建索引更快，
  2017"组合索引体积税"账本需重算；`pg_stats_ext`/扩展统计配套。✅ 入口
  https://www.postgresql.org/docs/release/17.0/（curl 200，细则 ⚠️ 转述）；✅
  https://www.postgresql.org/docs/current/sql-createindex.html（NOT VALID/CONCURRENTLY 现状）。
- **索引类型谱系扩张**：PG14 起 hash 索引 WAL 化（复制/备份安全，⚠️ 转述）、BRIN 每代加料
  （multi-level 扩展参数 ⚠️）、bloom 列存式过滤（contrib）、表达式/覆盖列（INCLUDE，PG11）成标配。
- **并行与 IO 红利**：`maintenance_work_mem`+`max_parallel_maintenance_workers` 并行 B-tree 构建
  （PG11+ ⚠️）把"并发建索引=一夜窗口"改写为小时级；PG18 异步 IO 预计惠及索引扫描预读（⚠️）。
- **治理自动化**：pg_qualstats/pg_stat_monitor/pgBadger 让"缺失/未用索引"从人工 SQL（本章配方 8/10）
  变成日报与告警；AutoIndex 类学习型工具（⚠️ 存在性不背书）进入实验区。
- **工业实践**：SaaS 多租户热点=部分索引+表达式索引的天堂；时序/日志场景=BRIN+声明式分区组合，
  本章 B-tree 中心主义的配方集正在被"按数据形态选索引族"新共识接替——与 #64 第 09 章同结论。⚠️
