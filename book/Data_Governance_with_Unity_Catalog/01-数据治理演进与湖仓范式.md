## 2. 传统数据治理的四根支柱（§1）

数据治理不是纯技术问题。DAMA-DMBOK 框架（✅ dama.org 官网可查）定义 11 个
知识领域，其中与本书直接相关的：

| 支柱 | 核心内容 | 典型角色 |
| --- | --- | --- |
| **数据质量管理** | 准确性、完整性、一致性、时效性 | Data Steward |
| **元数据管理** | 业务元数据、技术元数据、操作元数据 | Metadata Manager |
| **数据安全与隐私** | 分类、脱敏、访问控制、合规 | Security Officer |
| **数据架构** | 数据模型、命名规范、血缘追踪 | Data Architect |

⚠️ 转述：传统治理通常由 CDO 办公室推动，以"数据治理委员会"为组织载体，
产出物包括数据标准文档、数据字典、RACI 矩阵。参见
[../Data_Governance_Elsevier/00-总览与阅读地图.md](../Data_Governance_Elsevier/00-总览与阅读地图.md)
（#186，Ladley 的程序方法论）。

## 3. 传统治理在湖仓时代的失效（§2）

| 失效模式 | 传统数仓 | 数据湖 | 湖仓（需要） |
| --- | --- | --- | --- |
| 元数据存储 | 单一 Hive Metastore | 文件系统无元数据 | 统一 catalog ✅ docs.databricks.com |
| 权限管理 | DBA 手动 GRANT | 文件级 ACL 混乱 | 声明式特权 + 继承 |
| 血缘追踪 | ETL 工具内置（不跨系统） | 无 | 自动跨引擎血缘 |
| 数据共享 | ETL 副本 | 文件拷贝 | 零拷贝共享（Delta Sharing） |
| 审计 | 数据库审计日志 | 无统一审计 | 系统表自动记录 |

关键洞察：**湖仓的治理挑战不是"要不要治理"，而是"治理层如何与存储解耦"**。
✅ docs.databricks.com/en/data-governance/unity-catalog："Unity Catalog is the
unified governance layer for data and AI built into Databricks."

## 4. 湖仓治理的新范式（§3）

三个核心转变：

1. **从"每个引擎各管各"到"统一治理层"**：
   - 旧模式：Spark 有自己的 Hive metastore、Presto 有自己的 catalog、
     Trino 有自己的 connector → 权限不一致、血缘断裂。
   - 新模式：Unity Catalog 作为**唯一真相源**，所有引擎通过同一接口访问。

2. **从"手动治理"到"自动化治理"**：
   - 自动血缘追踪（无需手动标注 ETL 依赖）
   - 自动分类（基于数据内容的敏感信息检测）
   - 质量监控（Lakeguard 期望值自动校验）

3. **从"副本共享"到"零拷贝共享"**：
   - Delta Sharing 协议：跨组织、跨云共享数据，无需复制。
   - Open Sharing：基于 Apache Iceberg 的开放共享标准。

## 5. Unity Catalog 的历史定位（§4）

```
 Hive Metastore (HMS)         Workspace-level HMS          Unity Catalog
 ┌─────────────────┐         ┌─────────────────┐         ┌─────────────────┐
 │ 单一 metastore  │   →     │ 每工作区一个 HMS │   →     │ 账户级统一 metastore│
 │ 数据库.表 两层  │         │ 数据库.表 两层   │         │ catalog.schema.obj│
 │ 无跨工作区共享  │         │ 无跨工作区治理   │         │ 自动血缘+审计    │
 └─────────────────┘         └─────────────────┘         │ 零拷贝共享       │
                                                          └─────────────────┘
   Hadoop 时代                    Databricks 早期             2022 GA
```

✅ 关键时间线（docs.databricks.com 文档）：
- 2022-06：Unity Catalog 正式 GA（General Availability）
- 2023：Serverless SQL 支持 UC
- 2024：AI Gateway 集成、Open Sharing 发布
- 2025：Lakeguard 质量监控、全面 AI 治理

## 最新演进与工业实践

- **2025 Q2**：Databricks 发布 AI Gateway for Unity Catalog，将 LLM 调用纳入
  统一治理（速率限制、审计、成本追踪）。✅ docs.databricks.com AI Gateway 文档。
- **2025 Q1**：Apache Polaris（Incubating）发布首个稳定版，作为 UC 的开源替代
  方案（仅 Iceberg，不绑定 Databricks）。⚠️ 转述自 Apache 邮件列表。
- **工业趋势**：治理从"合规成本"转向"AI 使能器"——没有治理就没有可信的
  AI/ML 管道，这是 UC 被定位为"Data + AI Governance"的原因。
- **对标**：AWS 的对应方案是 Lake Formation + Glue Catalog；Azure 侧是
  Purview + Unity Catalog 双轨（Purview 做业务治理，UC 做技术治理）。
