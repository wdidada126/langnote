## 2. 数据共享的三种模式（§1）

| 模式 | 机制 | 问题 |
| --- | --- | --- |
| **文件交换** | CSV/Parquet 通过 SFTP/S3 传递 | 版本失控、副本泛滥、无审计 |
| **ETL 副本** | 定时任务将数据复制到对方环境 | 延迟高、成本翻倍、一致性无保证 |
| **零拷贝共享** | 数据留在生产方，消费方直接查询 | 权限可控、单一真相、实时一致 |

✅ Unity Catalog 的共享机制属于第三种——零拷贝共享。
核心优势：数据不移动，权限可控制，访问有审计。

## 3. Delta Sharing 协议（§2）

Delta Sharing 是一个**开放的**数据共享协议（不限于 Databricks）：

```
┌─────────────────────────────────────────────┐
│  Data Provider（数据提供方）                 │
│  ┌──────────────────────────────────────┐   │
│  │ Share: "finance_data"               │   │
│  │   ├─ Table: analytics.finance.rev   │   │
│  │   └─ Table: analytics.finance.budget│   │
│  └──────────────────────────────────────┘   │
│                    ↓ 共享                    │
│  ┌──────────────────────────────────────┐   │
│  │ Recipient: "partner_a"              │   │
│  │   Token-based authentication        │   │
│  └──────────────────────────────────────┘   │
│  ┌──────────────────────────────────────┐   │
│  │ Recipient: "partner_b"              │   │
│  │   不同的行过滤条件                    │   │
│  └──────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
```

✅ 关键事实（docs.databricks.com）：
- Delta Sharing 协议规范开源（delta.io/sharing）
- 消费方可用 Spark、Pandas、Power BI 等客户端读取
- 支持行过滤（共享时可设置过滤条件，消费方无感知）
- 支持跨云共享（AWS → Azure → GCP）

## 4. UC 中的共享对象模型（§3）

Unity Catalog 中的共享涉及三个核心对象：

| 对象 | 说明 | SQL |
| --- | --- | --- |
| **Share** | 共享定义（包含哪些表） | `CREATE SHARE finance_data` |
| **Provider** | 数据提供方（跨 UC 实例） | `CREATE PROVIDER partner_a USING SHARE ...` |
| **Recipient** | 数据消费方（身份标识） | `CREATE RECIPIENT partner_b` |

```sql
-- 创建共享
CREATE SHARE finance_data;
-- 添加表到共享
ALTER SHARE finance_data ADD TABLE analytics.finance.revenue;
-- 创建接收方
CREATE RECIPIENT partner_b;
-- 授予共享给接收方
GRANT SELECT ON SHARE finance_data TO RECIPIENT partner_b;
```

⚠️ 转述：在同一 UC metastore 内，共享通过"内部共享"实现（无需 token）；
跨 metastore 时，通过 Delta Sharing 协议 + token 认证。

## 5. Open Sharing（Iceberg 兼容）（§4）

2024 年 Databricks 发布 **Open Sharing**，基于 Apache Iceberg REST catalog 规范：

| 维度 | Delta Sharing | Open Sharing |
| --- | --- | --- |
| 表格式 | Delta Lake | Apache Iceberg |
| 协议 | Delta Sharing Protocol | Iceberg REST Catalog API |
| 消费方 | Databricks / Spark / Pandas | 任何 Iceberg 兼容引擎 |
| 治理 | UC Share 对象 | REST catalog 联邦 |

✅ 关键事实：Open Sharing 使非 Databricks 引擎（Trino、Flink、StarRocks）
也能通过标准 Iceberg REST API 访问 UC 管理的表。

## 6. Databricks Marketplace（§5）

Databricks Marketplace 是数据产品的发现与分发平台：

- **数据提供者**：发布数据集（免费或付费）
- **数据消费者**：浏览、安装、查询数据
- **安装方式**：一键创建远程表引用，直接 SQL 查询

⚠️ 转述：Marketplace 的定位类似"数据的 App Store"，
但目前以免费/开放数据集为主（政府数据、开源基准数据等）。

## 最新演进与工业实践

- **2025**：Open Sharing 进入 GA，支持 Iceberg 表的跨引擎零拷贝共享。
  ✅ docs.databricks.com。
- **Marketplace 扩展**：Databricks Marketplace 开始支持第三方付费数据集，
  与 Snowflake Marketplace 形成竞争。⚠️ 转述自 Databricks 博客。
- **对标**：AWS Data Exchange + Lake Formation 共享、Azure Data Share
  是云厂商的类似方案；Delta Sharing 的优势在于开放性和跨云。
- **趋势**：数据共享从"点对点协商"转向"平台化自助"——
  类似 API 经济，数据产品通过目录发现、一键订阅。
