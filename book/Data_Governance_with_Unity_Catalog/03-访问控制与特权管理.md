## 2. 身份管理：谁在访问（§1）

Unity Catalog 的身份管理分三层：
- **账户层**：用户（email-based）、服务主体（Service Principal）、组（Group）
- **治理层**（Metastore）：特权授予给 account-level principal
- **计算层**（Workspace）：工作区角色（admin / user）+ 集群权限

✅ 关键事实（docs.databricks.com/en/data-governance/unity-catalog）：
- UC 特权授予给**账户级主体**，不是工作区级
- SCIM provisioning 可从 Azure AD / Okta 同步组和用户
- 服务主体用于 CI/CD 和自动化管道

## 3. 特权模型：GRANT/REVOKE（§2）

UC 的特权体系基于 SQL 标准 GRANT/REVOKE 语法：

```sql
-- 授予 catalog 级特权
GRANT USE CATALOG ON CATALOG analytics TO `data-team`;

-- 授予 schema 级特权
GRANT USE SCHEMA ON SCHEMA analytics.finance TO `data-team`;

-- 授予表级特权
GRANT SELECT ON TABLE analytics.finance.revenue TO `analyst-group`;
GRANT MODIFY ON TABLE analytics.finance.revenue TO `etl-service-principal`;

-- 撤销特权
REVOKE SELECT ON TABLE analytics.finance.revenue FROM `analyst-group`;
```

特权继承链：CATALOG (USE CATALOG) → SCHEMA (USE SCHEMA) → TABLE (SELECT/MODIFY/...)。
**所有权**：每个 securable 有且仅有一个 owner，owner 拥有全部特权且不可被 REVOKE。

| 特权 | 适用对象 | 含义 |
| --- | --- | --- |
| USE CATALOG | Catalog | 使 catalog 可见 |
| USE SCHEMA | Schema | 使 schema 可见 |
| SELECT | Table/View | 读取数据 |
| MODIFY | Table/View | 写入/更新/删除数据 |
| CREATE TABLE | Schema | 在 schema 中创建表 |
| CREATE SCHEMA | Catalog | 在 catalog 中创建 schema |
| USAGE | Function/Model | 调用函数/使用模型 |
| READ VOLUME | Volume | 读取卷中的文件 |
| WRITE VOLUME | Volume | 写入卷中的文件 |

## 4. 行级过滤（Row Filter）（§3）

行级过滤通过**绑定函数到表**实现动态行过滤：

```sql
-- 1. 创建行过滤函数
CREATE OR REPLACE FUNCTION filter_by_region(region_col STRING)
  RETURNS BOOLEAN
  RETURN CASE
    WHEN IS_ACCOUNT_GROUP_MEMBER('us-team') THEN region_col = 'US'
    WHEN IS_ACCOUNT_GROUP_MEMBER('eu-team') THEN region_col = 'EU'
    ELSE FALSE  -- 默认无权限
  END;

-- 2. 绑定到表
ALTER TABLE analytics.finance.revenue
  SET ROW FILTER filter_by_region (region);

-- 3. 查询时自动过滤（用户无感知）
SELECT * FROM analytics.finance.revenue;
-- us-team 成员只看到 US 行
-- eu-team 成员只看到 EU 行
```

✅ 关键特性：
- 过滤函数在**查询执行时**动态评估（非物化视图）
- 支持多列组合条件
- 一个表只能绑定一个行过滤函数
- 过滤函数本身受 UC 特权保护（USAGE）

## 5. 列级脱敏（Column Mask）（§4）

列级脱敏通过**绑定脱敏函数到列**实现：

```sql
-- 1. 创建脱敏函数
CREATE OR REPLACE FUNCTION mask_email(email_col STRING)
  RETURNS STRING
  RETURN CASE
    WHEN IS_ACCOUNT_GROUP_MEMBER('hr-team') THEN email_col
    ELSE CONCAT(SPLIT(email_col, '@')[0], '@***.com')
  END;

-- 2. 绑定到列
ALTER TABLE analytics.hr.employees
  ALTER COLUMN email SET MASK mask_email;

-- 3. 查询时自动脱敏
SELECT email FROM analytics.hr.employees;
-- hr-team: alice@company.com
-- 其他人: alice@***.com
```

⚠️ 转述：行过滤和列脱敏的组合使用可实现非常细粒度的访问控制，
类似于传统数据库的 VPD（Virtual Private Database）但更灵活。
一个表只能绑定一个行过滤函数和一个列脱敏函数（每列）。

## 6. 🔧 SQLite 模拟行级安全与列脱敏（§5）

> ⚠️ **非本书引擎/平台行为**：以下演示用 Python sqlite3（3.45.3）模拟
> Unity Catalog 的行过滤和列脱敏机制，仅做机制类比。

```python
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE current_user(name TEXT, team TEXT)")
con.execute("INSERT INTO current_user VALUES ('alice', 'us-team')")
con.execute("""CREATE TABLE revenue (year INTEGER, region TEXT, amount REAL)""")
con.execute("INSERT INTO revenue VALUES (2024, 'US', 1500000)")
con.execute("INSERT INTO revenue VALUES (2024, 'EU', 1200000)")
con.execute("INSERT INTO revenue VALUES (2024, 'APAC', 800000)")
con.execute("""CREATE TABLE employees (id INTEGER, name TEXT, email TEXT, salary REAL)""")
con.execute("INSERT INTO employees VALUES (1, 'Alice', 'alice@co.com', 120000)")
con.execute("INSERT INTO employees VALUES (2, 'Bob', 'bob@co.com', 95000)")

# 模拟行过滤：VIEW + 子查询当前用户
con.execute("""CREATE VIEW revenue_filtered AS
    SELECT * FROM revenue
    WHERE region = (SELECT team FROM current_user LIMIT 1)""")

# 模拟列脱敏：VIEW + CASE
con.execute("""CREATE VIEW employees_masked AS
    SELECT id, name,
        CASE WHEN (SELECT team FROM current_user LIMIT 1) = 'hr-team'
             THEN email ELSE SUBSTR(email, 1, INSTR(email, '@') - 1) || '@***.com'
        END AS email,
        CASE WHEN (SELECT team FROM current_user LIMIT 1) = 'hr-team'
             THEN salary ELSE NULL END AS salary
    FROM employees""")

rows = con.execute("SELECT * FROM revenue_filtered").fetchall()
print(f"行过滤结果 (us-team): {rows}")
rows = con.execute("SELECT * FROM employees_masked").fetchall()
print(f"列脱敏结果 (非hr): {rows}")
con.close()
```

## 核心概念速览（中英对照）

| 中文 | English | 一句话 |
| --- | --- | --- |
| 特权 | Privilege | 对 securable 的授权动作（SELECT/MODIFY/...） |
| 所有权 | Ownership | securable 的拥有者，拥有全部特权 |
| 行过滤 | Row Filter | 基于函数的动态行级访问控制 |
| 列脱敏 | Column Mask | 基于函数的动态列值隐藏 |
| 服务主体 | Service Principal | 用于自动化的非人类身份 |
| SCIM 同步 | SCIM Provisioning | 从外部 IdP 同步用户和组 |

## 最新演进与工业实践

- **Lakeguard**（2025）：Databricks 推出 Lakeguard 作为 UC 的 FGAC（Fine-Grained
  Access Control）增强层，支持多用户共享集群下的安全隔离。⚠️ 转述自掘金书评。
- **动态特权评估**：UC 的行/列过滤在 Serverless SQL 下性能优化显著，
  因为过滤谓词可被下推到 Parquet 读取层。✅ docs.databricks.com。
- **对标**：Snowflake 的 Row Access Policy + Masking Policy 与 UC 的
  Row Filter + Column Mask 机制高度相似，反映了行业共识。
- **趋势**：ABAC（Attribute-Based Access Control）正在替代传统 RBAC，
  UC 的函数式过滤/脱敏本质上是 ABAC 的实现形式。
