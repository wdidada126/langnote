## 2. 系统表：UC 的"治理元数据"（§1）

Unity Catalog 提供一组 **system tables**（系统表），存储在 `system` catalog 中：

| 系统表 | 内容 | 用途 |
| --- | --- | --- |
| `system.access.audit` | 审计事件（登录、GRANT、查询等） | 合规审计 |
| `system.access.table_lineage` | 表级血缘 | 影响分析 |
| `system.access.column_lineage` | 列级血缘 | 精确影响分析 |
| `system.billing.usage` | 计算资源使用 | 成本分析 |
| `system.compute.environments` | 集群环境配置 | 安全审查 |
| `system.information_schema.tables` | 所有表的元数据 | 资产盘点 |
| `system.information_schema.columns` | 所有列的元数据 | 数据字典 |

✅ 关键事实（docs.databricks.com）：
- 系统表只读，不可修改
- 查询系统表需要 `system` catalog 的 USE 特权
- 系统表数据有保留期（通常 1 年，可配置）
- 可通过 SQL 直接查询（与查询普通表相同语法）

```sql
-- 查询最近 7 天的审计事件
SELECT * FROM system.access.audit
WHERE event_date >= CURRENT_DATE - INTERVAL 7 DAYS
ORDER BY event_time DESC;

-- 查询谁访问了特定表
SELECT * FROM system.access.audit
WHERE action_name = 'select'
  AND request_metadata LIKE '%analytics.finance.revenue%';
```

## 3. 审计日志（§2）

审计日志记录 UC 中的所有治理操作：

| 事件类型 | 示例 | 审计价值 |
| --- | --- | --- |
| **认证事件** | 登录、Token 创建 | 谁进入了系统 |
| **授权事件** | GRANT、REVOKE、CREATE | 权限变更追踪 |
| **数据访问** | SELECT、INSERT、EXPORT | 数据消费追踪 |
| **共享事件** | CREATE SHARE、ADD RECIPIENT | 跨组织数据流动 |
| **系统事件** | Metastore 创建、工作区绑定 | 基础设施变更 |

⚠️ 转述：审计日志是合规的基础——GDPR、SOX、HIPAA 等法规均要求
可追溯的数据访问记录。UC 的系统表使审计从"手动收集"变为"SQL 查询"。

## 4. 数据分类（§3）

Unity Catalog 支持自动和手动数据分类：

**自动分类**：
- 基于列名模式检测（如 `email`、`ssn`、`credit_card`）
- 基于内容采样检测（正则匹配 + 统计特征）
- 分类结果写入表的 `data_classification` 标签

**分类标签体系**（⚠️ 转述，具体标签可自定义）：
| 分类 | 含义 | 示例 |
| --- | --- | --- |
| `PII` | 个人身份信息 | 姓名、邮箱、SSN |
| `PHI` | 受保护健康信息 | 病历、诊断 |
| `PCI` | 支付卡信息 | 信用卡号 |
| `FINANCIAL` | 金融数据 | 账户余额、交易 |
| `PUBLIC` | 公开数据 | 产品目录 |
| `INTERNAL` | 内部数据 | 运营报告 |
| `CONFIDENTIAL` | 机密数据 | 战略规划 |

**手动分类**：
```sql
-- 为表添加分类标签
ALTER TABLE analytics.hr.employees
    SET TAGS ('data_classification' = 'PII');

-- 为列添加分类标签
ALTER TABLE analytics.hr.employees
    ALTER COLUMN ssn SET TAGS ('data_classification' = 'PII');
```

## 5. 质量监控（Lakeguard）（§4）

Lakeguard 是 Databricks 的数据质量监控框架（⚠️ 转述自 Databricks 博客）。
工作流程：定义质量期望（如 NOT NULL、amount > 0）→ 执行检查 → 输出 PASS/WARN/FAIL
→ 触发动作（告警/阻断/记录）。

质量期望可在以下场景使用：
1. **Delta Live Tables (DLT)**：管道中定义期望，违反时自动处理
2. **Lakeflow Pipelines**：摄入管道中定义质量门控
3. **独立质量监控**：对已有表定期运行质量检查

⚠️ 转述：Lakeguard 的定位是"治理的质量维度"——与访问控制（安全维度）、
血缘（可追溯维度）共同构成 UC 的治理三角。

## 6. 🔧 SQLite 模拟审计日志（§5）

> ⚠️ **非本书引擎/平台行为**：以下演示用 Python sqlite3（3.45.3）模拟
> Unity Catalog 的审计日志存储与查询，仅做机制类比。

```python
import sqlite3
from datetime import datetime

con = sqlite3.connect(":memory:")

# 创建审计日志表（模拟 system.access.audit）
con.execute("""
    CREATE TABLE audit_log (
        event_id INTEGER PRIMARY KEY AUTOINCREMENT,
        event_time TEXT,
        user_identity TEXT,
        action_name TEXT,
        target_object TEXT,
        target_type TEXT,
        result TEXT,
        ip_address TEXT
    )
""")

# 模拟审计事件写入
events = [
    ("2025-01-15 09:00:00", "alice@company.com", "login", None, None, "SUCCEEDED", "10.0.0.1"),
    ("2025-01-15 09:01:00", "alice@company.com", "select", "analytics.finance.revenue", "TABLE", "SUCCEEDED", "10.0.0.1"),
    ("2025-01-15 09:05:00", "bob@company.com", "grant", "analytics.finance.revenue", "TABLE", "SUCCEEDED", "10.0.0.2"),
    ("2025-01-15 09:10:00", "carol@company.com", "select", "analytics.hr.employees", "TABLE", "DENIED", "10.0.0.3"),
    ("2025-01-15 09:15:00", "alice@company.com", "create_table", "analytics.finance.budget", "TABLE", "SUCCEEDED", "10.0.0.1"),
    ("2025-01-15 10:00:00", "etl-svc@company.com", "insert", "analytics.finance.revenue", "TABLE", "SUCCEEDED", "10.0.1.1"),
]
con.executemany("""
    INSERT INTO audit_log (event_time, user_identity, action_name,
        target_object, target_type, result, ip_address)
    VALUES (?, ?, ?, ?, ?, ?, ?)
""", events)

# 查询 1: 最近的安全事件（DENIED）
denied = con.execute("""
    SELECT event_time, user_identity, target_object
    FROM audit_log WHERE result = 'DENIED'
    ORDER BY event_time DESC
""").fetchall()
print(f"拒绝访问事件: {denied}")

# 查询 2: 特定表的访问历史
history = con.execute("""
    SELECT event_time, user_identity, action_name, result
    FROM audit_log
    WHERE target_object = 'analytics.finance.revenue'
    ORDER BY event_time
""").fetchall()
print(f"revenue 表访问历史: {history}")

# 查询 3: 用户活动摘要
summary = con.execute("""
    SELECT user_identity, COUNT(*) as event_count,
           GROUP_CONCAT(DISTINCT action_name) as actions
    FROM audit_log
    GROUP BY user_identity
    ORDER BY event_count DESC
""").fetchall()
print(f"用户活动摘要: {summary}")

con.close()
```

## 最新演进与工业实践

- **2025**：Lakeguard 与 UC 深度集成，质量检查结果自动写入系统表，
  可通过 SQL 查询质量趋势。⚠️ 转述自 Databricks Data+AI Summit 发布。
- **自动分类增强**：UC 的自动分类现在支持自定义检测规则（正则+ML 模型），
  不仅限于内置的 PII/PHI 检测。✅ docs.databricks.com。
- **对标**：AWS Lake Formation 的 Data Catalog + Glue Classifiers 是
  类似方案；Azure Purview 提供跨平台的分类与扫描能力。
- **趋势**：审计从"事后追溯"转向"实时告警"——异常访问模式（如非工作时间
  大批量导出）可触发自动告警/阻断。
