## 三、本书在数据库系列中的定位

一句话：**这是写给"用 MySQL 的软件工程师"的中层读物**——上不及《高性能 MySQL》的运维广度，
下不及 InnoDB 源码深度，正好处在最缺人的那一档：**把查询响应时间当成唯一北极星，用 performance_schema + sys 把它量化、归因、改进**。
作者自述的写作动机（✅ 官方简介）："讲基础的和讲高级的书都有，中间没有；因为不讲复杂性就讲不清性能。本书填这个中间层。"

### 辨析登记（防并档）

- **本书 ≠ 《高性能 MySQL》**（Schwartz/Zaitsev/Tkachenko，[../高性能mysql.md](../高性能mysql.md)）：后者是 DBA 全书（复制拓扑、硬件、备份、云），
  本书明确放弃 DBA 视角（✅ 作者站："no … deep internals required by DBAs and experts"）。两书对"索引"深度差一个量级。
- **本书 ≠ 《千金良方：MySQL 性能优化金字塔法则》**（[../千金良方_MySQL性能优化金字塔法则.md](../千金良方_MySQL性能优化金字塔法则.md)）：
  千金良方按"金字塔"自顶向下组织方法论与案例，本书按"查询响应时间 → 索引 → 数据 → 访问模式 → 分片"单线推进。
- **本书 ≠ 《MySQL 8 查询性能优化》**（Jesper Krogh，[../MySQL8查询性能优化.md](../MySQL8查询性能优化.md)）：同一 MySQL 8 观测底座，
  Krogh 偏 sys schema 与工具细节，本书偏决策与"红鲱鱼"取舍。
- **本书中译本已存在**（《高效能MySQL》，机工 2023-11，ISBN 9787111737933）——repo 内**没有**该中译本的独立笔记，
  故本目录按规范**只建英文原版一份**，中译本信息在本表登记并作为小节标题的实抓来源；后续若补中译本笔记，须回链本 00。
- **易混人物**：Daniël van Eeden（GitHub `dveeden`，Percona→Vettabase→PingCAP，MySQL 社区名人）**不是**本书作者；
  本册任务书原记其名为勘误项（实证过程见第一节）。两人同为 Percona 系、同写 MySQL 性能内容，故易混。

## 五、本目录的取证与实测纪律

- **不安装 MySQL、不追 Docker**：本机没有可用的 MySQL 8 实例，故凡 `performance_schema` / `sys` / 状态变量的

- **🔧 实测只允许"机制类比"**：用 Python 内置 `sqlite3` / 线程 / 计时器复现本书的**思想**（digest 聚合与分位数、
  索引杠杆、最少数据、N+1、分片扇出、原子计数器、单线程 applier 瓶颈、长读事务阻塞回收、漂移分块校验、fsync 成本）。
  每处 🔧 都写明**这不是 MySQL**，数字只用于说明机制方向，不可当作 MySQL 性能结论引用。
- 复现脚本与数据：`D:\develops\tmp\dbwave_emp\exp.py`、`followup.py`、`results.json`、`results2.json`（repo 内零构建产物）。
- 每章文末固定两节：**核心概念速览（中英对照）** 与 **最新演进与工业实践**（2024–2026 现状；论文 DOI 均过 Crossref 200 校验）。
