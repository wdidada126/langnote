## 6.1 被动→主动：元数据的控制论位移

学术判断 ⚠️：主动元数据的本质是**把元数据从观测平面移入控制平面**——用控制论术语：

| 模式 | 控制论角色 | 反馈类型 |
|---|---|---|
| 被动元数据 | 传感器（sensor） | 开环（无反馈） |
| 主动元数据 | 控制器（controller） | 闭环（负反馈调节） |
| 智能元数据 | 自适应控制器 | 闭环 + 学习（模型预测控制） |

形式化：设系统状态为 x(t)，元数据观测为 y(t) = h(x(t))，控制输入为 u(t)。
- 被动：只记录 y(t)，不产生 u(t)
- 主动：u(t) = K·(y_ref - y(t))，经典负反馈
- 智能：u(t) = π_θ(y(t))，策略函数由 ML 学习

## 6.2 主动元数据的五类回路（学术分类）

| 回路类型 | 输入 | 输出 | 学术模型 |
|---|---|---|---|
| 推荐回路 | 用户行为 + 图谱 | 数据资产推荐 | 协同过滤 + 图嵌入 |
| 物化决策回路 | 查询频率 + 成本 | 物化/去物化决策 | 在线优化（bandit） |
| 质量修复回路 | 质量指标 + 血缘 | 自动修复/告警 | 规则引擎 + 异常检测 |
| 策略下发回路 | 合规要求 + 标签 | 访问控制策略 | 策略编译（Datalog） |
| 编排调整回路 | 新鲜度 + SLA | 管道重排/触发 | 事件驱动（05 章） |

学术判断 ⚠️：五类回路的**闭环延迟**决定了 fabric 的"智能"等级——推荐/物化可容忍秒级延迟，质量/策略需亚秒级，编排调整需分钟级。

## 6.3 🔧 G3（复用）：血缘闭包作为推荐回路的输入

场景：999 条血缘边，求节点 999 的上游闭包——模拟"推荐与当前资产相关的数据集"。

- 实测：上游闭包 = 7 节点；0.102ms（SQLite 3.45.3；**⚠️ 非本书引擎行为**）。
- 学术读数：推荐回路的**候选集生成**是图遍历，毫秒级；但推荐的**排序**需要用户行为数据（协同过滤）——元数据图谱提供候选，行为数据提供排序。

## 6.4 🔧 G5（复用）：新鲜度扫描作为物化决策回路的输入

场景：24 万行元数据新鲜度扫描——模拟"哪些数据集需要刷新物化视图"。

- 实测：24 万行 46.99ms（DuckDB 1.5.5；**⚠️ 非本书引擎行为**）。
- 学术读数：物化决策回路的**输入侧**是新鲜度扫描（O(log n) 级别），**决策侧**是成本优化（物化收益 vs 存储成本）——后者是 online optimization 问题。

## 6.5 🔧 G6（新增）：策略下发回路的 Datalog 类比

场景：基于元数据标签自动生成访问控制策略——"密级=机密的数据集只允许 role=analyst_L3+ 访问"。

```python
# 模拟 Datalog 策略编译（Python 实现简化版）
metadata = [
    {"dataset": "sales_pii", "label": "confidential", "owner": "sales_dept"},
    {"dataset": "public_metrics", "label": "public", "owner": "analytics"},
]
policies = []
for m in metadata:
    if m["label"] == "confidential":
        policies.append({
            "resource": m["dataset"],
            "allow": "role:analyst_L3+",
            "deny": "role:external"
        })
print(f"generated {len(policies)} policies from {len(metadata)} datasets")
# generated 1 policies from 2 datasets
# ⚠️ 非本书引擎行为，Python 类比 Datalog 编译
```

学术读数：策略下发回路的**编译过程**是把元数据标签（B 元数据）翻译为可执行策略——学术上对应**策略即代码**（Policy-as-Code）和 Datalog/Rego 等声明式策略语言。

## 6.6 主动元数据的学术谱系

| 代际 | 技术 | 在 fabric 中的角色 |
|---|---|---|
| 被动记录 | 传统元数据管理 | 只记录"是什么" |
| 规则驱动 | 主动元数据 v1（硬编码规则） | "如果 X 则 Y" |
| ML 驱动 | 主动元数据 v2（模型预测） | "预测最佳行动并执行" |
| LLM 增强 | 主动元数据 v3（自然语言交互） | 10 章展开 |

学术判断 ⚠️：从 v1→v2 的跃迁需要**训练数据**——主动元数据的 ML 模型需要历史回路执行记录作为训练集，这是冷启动难题。

## 6.7 反模式清单

1. **回路无护栏**：自动物化决策无成本上限 → 存储爆炸。学术对策：约束优化（bounded optimization）。
2. **推荐无反馈**：推荐结果不回流 → 模型不更新。学术对策：在线学习 + 探索-利用平衡。
3. **策略无版本**：策略变更不追踪 → 合规审计失败。学术对策：策略版本化 + 回滚。
4. **回路无幂等**：同一事件触发多次 → 重复执行。学术对策：事件去重 + 幂等键。

## 6.9 自检补充：回路的可观测性要求

主动元数据的五类回路（6.2）每一条都必须满足**可观测性约束**——回路执行轨迹必须可审计（02 章铁律 3）。具体而言：
- 推荐回路：推荐结果 + 用户反馈必须落库，供模型迭代
- 物化决策回路：每次物化/去物化决策必须记录原因（成本/频率/SLA）
- 质量修复回路：自动修复操作必须可回滚（undo log）
- 策略下发回路：策略变更必须版本化（Git 化）
- 编排调整回路：管道重排必须通知下游属主

五条约束的**联合违反**将导致 fabric 的"智能"不可信——这是学术形式化必须包含的"安全阀"设计。

## 6.9 🔧 G7（新增）：质量修复回路的异常检测（DuckDB 类比）

场景：模拟元数据质量指标的时间序列——用简单 z-score 检测异常并触发修复。

```python
import duckdb
# 模拟 30 天质量指标（完整性%）
quality = [98.5, 97.2, 99.1, 98.8, 97.5, 98.0, 96.5, 97.8, 98.2, 97.9,
           98.1, 97.6, 98.4, 97.3, 98.7, 98.0, 97.4, 98.2, 97.8, 98.5,
           97.9, 98.1, 97.7, 98.3, 97.5, 98.0, 97.8, 98.2, 85.0, 97.9]
# z-score 异常检测
mean_q = sum(quality) / len(quality)
std_q = (sum((x - mean_q)**2 for x in quality) / len(quality)) ** 0.5
anomalies = [(i, v) for i, v in enumerate(quality) if abs(v - mean_q) / std_q > 2]
print(f"detected {len(anomalies)} anomalies: {anomalies}")
# detected 1 anomalies: [(28, 85.0)]（⚠️ 非本书引擎行为，DuckDB+Python 异常检测模拟）
```

学术读数：质量修复回路的**检测侧**是统计异常检测（O(n) 扫描），**修复侧**是规则引擎（基于血缘定位根因）——两者组合构成 6.2 质量修复回路的完整闭环。
