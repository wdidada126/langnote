# 03 · 元数据管理与知识图谱底座

> 主题章（⚠️ 推定归属本书"核心技术底座"部分）。fabric 的形式化定义（02 章）中，M（元数据图谱）是核心变量。本章展开 M 的构造：三类元数据、图谱建模、检索语义。与 #210 的 [03-元数据与知识图谱-编织的经线.md](../Data_Fabric_as_Modern_Data_Architecture/03-元数据与知识图谱-编织的经线.md) 互补：#210 偏工程采集，本章偏**图论形式化**。🔧 G1/G4 两组实测复用自 #210 台账（00 §7），新增 G2 类比。

## 3.1 元数据三元组的代数结构（学术视角）

设元数据空间为 M = T × B × O，其中：
- T = 技术元数据（schema/类型/分区/统计）——**自动采集，高覆盖**
- B = 业务元数据（词表/指标/属主/密级）——**半自动，低覆盖**
- O = 运营元数据（查询日志/作业画像/新鲜度/成本）——**流式采集，中覆盖**

学术判断 ⚠️：三者的**采集自动化程度**构成 fabric 工程的核心矛盾——T 已成熟（90%+），O 正在成熟（流式日志管道），B 仍是瓶颈（依赖 NLP/AI 辅助，10 章展开）。fabric 的质量上限由 min(coverage(T), coverage(B), coverage(O)) 决定——**短板效应**。

## 3.2 图谱建模的图论基础

知识图谱 G = (V, E, λ) 在 fabric 中的形式化角色：
- V = 实体节点集（物理表/逻辑实体/业务概念三层，⚠️ 03 章实体归一）
- E = 边集，分三类：
  - 结构边 E_s：schema 导出，全自动，置信度=1
  - 语义边 E_b：词表/本体导出，半自动，置信度∈(0,1)
  - 行为边 E_o：访问共现导出，全自动，置信度按频率衰减
- λ：标签函数（边类型+属性）

**核心查询的图论表述**：
1. 多跳血缘 = 有向路径可达性：v₁ →* v₂
2. 语义扩散 = 带阈值的邻域扩展：{v | dist(u,v) ≤ k ∧ conf > θ}
3. 影响分析 = 反向可达闭包：{v | v →* u}

## 3.3 🔧 G1：元数据目录检索下限（SQLite 类比）

场景：2 万数据集 × 5 系统 × 4 万标签行。问"revenue 跨几个系统？revenue∧sales 有多少候选？"

- 实测：5 系统全命中；revenue∧sales 1304 行；4.23ms（SQLite 3.45.3，B-tree 索引；**⚠️ 非本书引擎行为**）。
- 学术读数：检索本身是 O(log n) 级别，fabric 的**真正复杂度在实体归一**（3.2 的三层 V 对齐），不在查询。

## 3.4 🔧 G4：图谱最短路径（DuckDB 类比）

场景：10000 无向边（5000 节点链+捷径），求节点 1→4999 最小跳数。

- 实测：shortcut_hop=1（hub 效应使全图小世界化）；12.32ms（DuckDB 1.5.5；**⚠️ 非本书引擎行为**）。
- 学术读数一：行为边一旦有 hub，图呈 small-world 特性——影响分析必须带深度上限 k 与置信度阈值 θ，否则噪音不可用。
- 学术读数二：SQL 递归 CTE 的复杂度为 O(b^d)（b=分支因子，d=深度），专用图存储以邻接索引降至 O(d)——这是 fabric "catalog 内置图 vs 外挂图库"选型的理论依据。

## 3.5 🔧 G2（新增）：实体归一的等价类计算（SQLite 类比）

场景：同一业务实体"客户"在 3 个系统有 3 个物理名（crm.cust_id, erp.customer_no, dw.client_key），需计算等价类。

```sql
-- SQLite 递归 CTE 计算等价闭包（并查集的 SQL 实现）
WITH RECURSIVE eq(a, b) AS (
  VALUES ('crm.cust_id','erp.customer_no'),
         ('erp.customer_no','dw.client_key'),
         ('crm.cust_id','dw.client_key')  -- 冗余边，闭包应去重
), closure(x, root) AS (
  SELECT a, a FROM eq GROUP BY a
  UNION SELECT e.b, c.root FROM eq e JOIN closure c ON e.a = c.x
)
SELECT root, GROUP_CONCAT(DISTINCT x) FROM closure GROUP BY root;
-- 结果：单一等价类 {crm.cust_id, erp.customer_no, dw.client_key}
-- ⚠️ 非本书引擎行为，SQLite 类比
```

学术读数：实体归一本质是**等价关系求商集**——图论中的连通分量问题。SQL 递归 CTE 可处理小规模，大规模需 Union-Find 数据结构或图引擎。

## 3.6 本体工程的学术谱系

fabric 的本体层（B 元数据的结构化形式）有明确的学术谱系：

| 代际 | 技术 | 在 fabric 中的角色 |
|---|---|---|
| 第一代 | 受控词表/thesaurus | 业务标签字典 |
| 第二代 | RDF/RDFS/OWL | 形式化本体（继承/等价传递推理） |
| 第三代 | 属性图 + 轻量本体 | 工程实用折中（2024 主流） |
| 第四代 | LLM 辅助本体演化 | 10 章展开 |

⚠️ 学术判断：多数企业 fabric 实施停在第二代与第三代之间——OWL 的推理能力在企业级规模下性能退化（⚠️ 社区共识转述），属性图的"够用就好"成为事实标准。

## 3.7 反模式清单（学术版）

1. **图本体膨胀**：本体类/属性无限制增长 → 推理不可终止。学术对策：顶层本体（如 ECSO 轻量版）约束扩展方向。
2. **置信度缺失**：三类边同权存储 → 下游无法区分"schema 保证"与"统计猜测"。学术对策：边属性带置信度分数。
3. **静态图谱**：建完不更新 → 运营元数据（O）饿死。学术对策：O 流式注入 + TTL 衰减。
4. **归一跳过**：物理表直接打业务标签 → 平行宇宙。学术对策：3.5 的等价类计算前置。
