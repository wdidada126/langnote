## 5.2 核心精讲（历史语境）

- **变量即代码**：书中展示一个系统变量在 5.0 树里的完整足迹——C 全局变量 + sysvar 描述结构（名字、类型、上下界、默认值、flags）+ 可选的 `on_check/on_update/on_update_block` 回调；`SET` 语句与选项文件解析最终汇到同一套 setter。这个「声明式变量框架」是 MySQL 配置系统三十年不变的骨架。
- **作用域的朴素规则**：GLOBAL/SESSION 两档（书中还有局部变量议题）；会话变量在连接建立时从全局拷贝进 THD——所以「改全局不救活连接」的行为从 5.0 到今天一字未改，是 DBA 面试经典题的原点。
- **动态 vs 静态**：静态变量只在启动读取；动态变量可 `SET GLOBAL`，但书中提醒不少动态变量「改了要重启才全量生效」（缓冲池类尤甚）。5.0 时代 buffer pool 还不能在线伸缩（5.5+ 支持），这类「当年坑今天填」的清单是本章对位表主体。
- **教学示意**（不参与构建）：`SHOW VARIABLES LIKE 'xxx'`、`SELECT * FROM information_schema.SESSION_VARIABLES` 在 2007 与 2026 语义一致。

## 5.6 三问三答（本章高频疑问卡）

- **Q1：为什么不直接读 my.cnf 而是「四层优先级」？**
  A：编译默认 < 选项文件 < 命令行 < SET，层层覆写让打包、部署、运行时调试各有落点；今天再加 persist 层（文件里最优先的最后一层）。
- **Q2：书中为什么花篇幅讲 on_update 回调？**
  A：因为 MySQL 大量变量「改值有副作用」（重开日志、调整缓冲池实例、刷新表缓存）——回调就是把副作用集中到 setter 的事务边界里，这是「配置即代码」的工程样板。
- **Q3：8.x 还有「隐藏变量」吗？**
  A：有（带 PLUGIN 前缀或 EXPERIMENTAL/DEPRECATED 标记）；P_S 的 variables_info 给可见性与来源，比书中时代的「翻源码找变量」文明得多。

## 5.7 一个变量在代码里的四种存在（实测文件对照）

| 存在形式 | 作用 | 书中时代（5.0） | 今天（8.4，✅ 路径实测 200） |
| --- | --- | --- | --- |
| C 全局变量 | 承载全局值 | 一个 `extern` 全局量 | 仍有一批（收敛进 `system_variables` 与模块内静态量） |
| 描述结构 | 名字、类型、上下界、默认值、flags、回调 | `sys_var` 派生族（⚠️ 类名为书内口径，未逐行核验） | `sql/sys_vars.cc` 逐项 `Sys_var_*` 声明；头文件 `sql/set_var.h` |
| 会话副本 | 每连接一份可覆写值 | THD 上的 `variables` 结构 | `sql/system_variables.h` 里的结构体（同名概念仍在） |
| 展示与元数据 | 让人能查 | `SHOW VARIABLES` / I_S | I_S + `performance_schema.variables_info`（来源/可见性/历史）+ `SET PERSIST` 的 JSON 文件 |

- **一句话记忆**：**「值 + 描述 + 副本 + 视图」**。四种存在里只有「值」会被人误以为重要，排障时真正用的是后三者（这个变量属于哪个作用域、被谁改过、改动会触发什么回调）。

## 5.8 解剖四类代表变量（把「副作用」讲清楚）

| 类别 | 代表变量 | 改动的真实代价 | 书中口径 vs 今天 |
| --- | --- | --- | --- |
| 缓冲尺寸类 | `sort_buffer_size`、`join_buffer_size`、`read_buffer_size` | **按使用次数分配**，不是按连接一次性占满；会话级生效 | 概念未变；乘错系数仍是容量规划第一坑（转述 ⚠️） |
| 全局池类 | `innodb_buffer_pool_size` | 5.0 时代只能重启；后来支持在线分块扩容（⚠️ 版本点转述） | 今值以 GB 计，调整要配合实例数与块大小 |
| 表/对象缓存类 | `table_open_cache`、`table_definition_cache` | 影响打开表与结构缓存命中率；改小会立刻显形为打开等待 | 8.0 后与 DD 绑定（见 [03-核心类结构与变量.md](03-核心类结构与变量.md)） |
| 行为开关类 | `sql_mode`、`autocommit`、`tx_isolation`/`transaction_isolation`（后者为现名，转述 ⚠️） | 语义变化而非资源变化，风险最高 | 默认严格化是 5.7/8.0 的著名变更（5.3 表已登记） |
| 路径与开关类 | `datadir`、`log_bin`、`max_allowed_packet` | 多数静态；`max_allowed_packet` 全局/会话双档且决定 4.7 章的包上限 | 概念同构，见 [04-客户端与服务器通信.md](04-客户端与服务器通信.md) |

## 5.9 「改了谁会看见」决策表

- `SET GLOBAL x=…`：只影响**此后新建**的会话；正在跑的会话继续用它连接时拷贝的副本（5.2 已述，这条规则 2007→2026 一字未改）。
- `SET SESSION x=…`（或裸 `SET x=…`）：只影响当前会话，且**不回写全局**。
- `SET PERSIST x=…`（8.0.13+，转述 ⚠️）：立刻改全局 + 落 `mysqld-auto.cnf`，重启仍在；`SET PERSIST_ONLY` 只落文件不生效。
- 选项文件：只在启动时被读；容器化部署里它常由 ConfigMap/entrypoint 生成——**「文件里有、变量里没有」**的错位是这一层的新形态（转述 ⚠️）。
- 判据口诀：**先问作用域，再问动态性，最后问副作用回调**；三问齐了，任何「参数改了没效果」的工单都能自己关掉。

## 5.10 选项文件与工具链（历史语境）

- 书中给的是一条**从上到下的读取链**（形如 `/etc/my.cnf` → `/etc/mysql/my.cnf` → `$DATADIR/my.cnf` → `~/.my.cnf` → 命令行；⚠️ 精确顺序属转述，本目录不把它当实测结论）。
- `[group]` 与 `[group-suffix]`、`!include`/`!includedir` 的用法是当年「打包 + 本地覆盖」的标准做法；今天仍在用（`conf.d` 目录形态）。
- 调试工具：`my_print_defaults`（打印解析结果）与 `--validate-config`（启动前体检，5.3 已标 ⚠️）是两类「不启动服务器也能验配置」的手段；书时代只有前者这一半。
- **和 02 章的关系**：变量声明文件（今天 `sql/sys_vars.cc`）就是「一个变量的权威定义处」——书中「翻源码找变量」的方法在 8.x 依然有效，只是文件更好找了（见 [02-MySQL源代码基础.md](02-MySQL源代码基础.md) 的 2.9 对照表）。

## 5.12 阅读手记

- 本章最该被记住的不是任何变量名，而是**「配置即代码」**：变量有类型、有校验、有回调、有作用域、有生命周期——把它当对象模型读，而不是当运维口诀背。有了这个模型，`SET PERSIST`、`variables_info`、`--validate-config` 这些新长相都只是同一模型的增补视图。
- 与相邻章的接缝：变量值挂在 THD 的会话副本上 → [03-核心类结构与变量.md](03-核心类结构与变量.md)；会话副本在连接建立时拷贝 → [06-基于线程的请求处理.md](06-基于线程的请求处理.md)；`max_allowed_packet` 决定包上限 → [04-客户端与服务器通信.md](04-客户端与服务器通信.md)；缓冲类变量与引擎的关系 → [10-存储引擎掠影.md](10-存储引擎掠影.md)。

- 三个常见事故形态（跨两代都成立）：①**「文件里有、变量里没有」**——选项文件分组写错（`[mysqld]` 写成 `[mysql]`）或读取链前置项覆盖；②**「改了没生效」**——作用域或动态性判断错（先查 5.9 决策表）；③**「生效了但只在部分连接上」**——会话副本导致新旧连接行为不一致，连接池里表现为「同一 SQL 时对时错」。
- 与 03 章的接缝再强调一次：**会话变量表是 THD 的成员**，所以「变量」问题的可观测单位是连接，不是进程；这是本章与线程模型（[06-基于线程的请求处理.md](06-基于线程的请求处理.md)）合起来才能给出的判断。

## 核心概念速览（中英对照）

1. **系统变量** — system variable：以名字暴露的全局/会话可调参数。
2. **会话变量表** — session variable array：连接建立时从全局拷贝的 THD 副本。
3. **动态变量** — dynamic variable：可 SET GLOBAL 即时（或部分即时）生效者。
4. **静态变量** — read-only variable：仅启动时读取，改动需重启。
5. **on_update 回调** — update callback：变量变更时执行副作用钩子。
6. **选项文件** — option file（my.cnf）：分组 [mysqld]/[client] 的持久配置。
7. **优先级链** — option precedence：编译默认→文件→命令行→运行时 SET。
8. **SET PERSIST** — 持久化 SET：8.0.13+ 写入 mysqld-auto.cnf 的语法。
9. **sql_mode** — SQL 模式开关：严格程度与兼容行为的历史主战场。
10. **validate-config** — 启动前配置体检模式（8.0.16+ ⚠️）。
11. **variables_info** — P_S 元数据视图：变量来源、可见性、历史。
12. **作用域** — scope：GLOBAL/SESSION/PERSIST 三种生命域。

## 最新演进与工业实践

- **PERSIST 体系（转述）**：`SET PERSIST`/`SET PERSIST_ONLY`（8.0.13+）+ `mysqld-auto.cnf`（JSON）让「调了没写进文件」的经典事故成为历史；官方文档域 403 ⚠️，机制可在源码树核验：✅ https://github.com/mysql/mysql-server （`sql/set_var.cc` 等）。
- **配置治理实践（2024–2026）**：基础设施即代码潮流下，社区主流是「参数模板 + diff 审计」（云厂商参数组、Percona Config Generator 一类工具）；本书的「变量三件套」心智模型仍是排查参数漂移的地基。✅ 实测可达：https://docs.percona.com/percona-server/8.0/ （Percona 参数文档索引）。
- **8.4/9.x 升级注意（转述 ⚠️）**：8.4 移除/改名一批历史变量（MASTER_*→SOURCE_* 系列收尾、若干弃用插件默认关闭），升级前用 `performance_schema.variables_info` + 官方 Release Notes 做差集——这正是本章「变量即代码」观的运维红利。
- **观测侧**：information_schema.SESSION_VARIABLES 与 P_S 双视图、以及 `EXPLAIN` 可解释参数效果的实践，已在 repo 内 [../mysql/15-EXPLAIN详解.md](../mysql/15-EXPLAIN详解.md) 一侧展开。
