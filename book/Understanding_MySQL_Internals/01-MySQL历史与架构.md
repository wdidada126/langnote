## 1.2 核心精讲（历史语境）

- **二分架构是全书的坐标系**。此后 11 章全部在回答同一个问题：某个能力究竟在 Server 层还是引擎层？解析/优化/权限/复制日志在 Server 层；索引结构/行格式/锁粒度/崩溃恢复在引擎层。当年这套二分让 MySQL 吃下了 Web 早期爆发，也让「选错引擎=换数据库」成为 DBA 的核心课题。
- **模块图的当年画法**：连接线程 → 查询缓存（query cache）→ 分析器/优化器 → 记录接口（handler）→ 引擎。注意查询缓存是**正式构件**而非边缘特性；书中还有专节教存储引擎「使用查询高速缓存」（第 11 章事务语境下）。今天读这张图必须打三个补丁：QC 已删（8.0）、记录接口之上多了数据字典与插件框架（8.0）、连接认证多了 caching_sha2 体系（8.0.4 起默认）。
- **可插拔引擎的动机与副作用**：日志归档选 Archive、只读报表选 MyISAM、OLTP 选 InnoDB——引擎能力靠 handlerton 上的标志位声明（第 11 章展开），Server 层据此降级功能（例如没有崩溃恢复的引擎要靠 `myisam-recover` 这类补丁机制）。副作用：优化器无法假设任何引擎语义，代价模型长期保守（第 9 章的伏笔）。
- **一线的复制观**：所有 Server 级变更写进二进制日志，从库以「重放语句」为同步手段——这个 2007 年的设计至今仍是 MySQL 复制的地基（第 12 章展开），但重放单位与并行度已彻底换代。
- 教学示意（不构成运行环境）：当年观察「服务器由哪些构件编译而来」的入口 `SHOW ENGINES`、`SHOW VARIABLES LIKE 'have_%'` 思路今天仍可用来体检编译期裁剪。

## 1.7 阅读手记：这一章的正确用法

- **不要用它记参数**：本章没有任何今天仍可直接抄的配置；它的全部价值是给你后续 11 章提供「层次归位」的坐标系。
- **每读一个现代特性，反查它属于哪一层**：例如 8.0 的 hash join 属 Server 层优化器、instant DDL 属引擎层、SET PERSIST 属 Server 层配置系统——这个反射动作就是本章训练的目标。
- **把它当「反事实训练」**：设想没有可插拔引擎，MySQL 会怎样？答案写在它的竞争对手身上（PostgreSQL 单引擎路线），对照能加深对第 7 章接口设计的敬意。

## 1.10 三问三答（本章高频疑问卡）

- **Q1：2007 年图上的查询缓存，为什么当年值得单列一节？**
  A：因为读写比高的 Web 负载下命中率极高，且它对引擎透明——这是「Server 层做通用优化」路线的胜利样本，也是后来被证明「全局共享缓存在多核写热点下反规模」的失败样本。一个构件同时教给你优化的边界条件。
- **Q2：书中反复强调「多引擎」，为什么今天几乎听不到了？**
  A：不是接口死了，而是需求收敛：崩溃恢复 + 行级锁 + 事务成为 OLTP 底线，InnoDB 全部满足；其余引擎退到归档（Archive）、测试（blackhole）、调试（CSV）等窄岗位。可插拔性转为「保险丝」价值——云厂商魔改与 fork（MariaDB）都靠它活着。
- **Q3：这章和 Monty/Sunset 的公司史有什么关系？**
  A：书的公司叙事在出版后一年内整体失效，但架构结论不依赖公司：**接口稳定 > 实现聪明** 是 MySQL 活过被两次收购的真正原因，这层教训只有带着「历史语境」标记读本章才拿得到。

## 1.11 「层归属」速查表（本章训练的目标动作）

| 概念 | 2007 年归层 | 8.4/9.x 归层 | 判据（怎么自己查） |
| --- | --- | --- | --- |
| 解析与语法 | Server 层（`sql/sql_yacc.yy`） | 同层，文件同名（✅ 8.4 树实测存在） | 语法能力与所选引擎无关 |
| 优化与代价 | Server 层 | 同层，但统计来源多了直方图与 DD | 计划不因引擎换而换算法族 |
| 权限与认证 | Server 层（当年仅 SHA1 双散列） | Server 层 + 插件化认证框架 | 认证与表存储无关 |
| 查询缓存 | **Server 层正式构件** | **不存在**（8.0 移除） | 唯一整块消失的 Server 层模块 |
| 表锁 | Server 层（THR_LOCK） | 同层仍在（`mysys/thr_lock.cc` ✅ 实测存在），但只对非事务型引擎是终局并发度 | 引擎不同，锁粒度后果不同 |
| 元数据锁 | 无 | Server 层（5.5+，`sql/mdl.h` ✅ 实测存在） | 本书缺位项 |
| 索引结构 | 引擎层 | 引擎层 | `SHOW INDEX` 可见但实现在引擎 |
| 行格式 | 引擎层 | 引擎层（InnoDB 多形态） | 与 `.frm`/DD 一起构成元信息 |
| 事务与 ACID | 引擎层能力 + Server 层编排 | 同结构，编排升级为内部 XA/原子 DDL | handlerton 槽位是否非空 |
| 二进制日志 | Server 层 | Server 层（事件结构扩展） | 与引擎无关的提交顺序记录 |
| 表定义来源 | `.frm` 文件 | 事务性数据字典（InnoDB 内） | 8.0.16 起 `.frm` 消失 |
| 复制的重放 | Server 层（SQL 线程） | Server 层（并行工作者） | 从库侧永远是 Server 层行为 |

## 1.12 三层图的三种画法（文字版）

- **画法 A（本书原图）**：连接线程 → 查询缓存 → 解析/优化 → 记录接口（handler）→ 引擎。适合记住「SQL 能力在哪、数据能力在哪」。
- **画法 B（去掉化石）**：同图删掉查询缓存，在「解析/优化」与「引擎」之间插入 **MDL + 数据字典 + 插件框架** 三块挡板。适合今天的排障定位。
- **画法 C（按数据流）**：字节包（NET/VIO，见 [04-客户端与服务器通信.md](04-客户端与服务器通信.md)）→ THD 上下文（见 [03-核心类结构与变量.md](03-核心类结构与变量.md)）→ LEX/Item 树 → JOIN 计划（见 [09-解析器与优化器.md](09-解析器与优化器.md)）→ handler 跨界（见 [07-存储引擎接口.md](07-存储引擎接口.md)）→ 引擎日志与页。适合追一条 SQL。
- 三种画法共用同一结论：**MySQL 的架构问题首先是「归层问题」**。本章之后所有章节都在给这张图加细节，而不是换图。

## 核心概念速览（中英对照）

1. **服务器内核** — server kernel：协议、解析、优化、权限与缓存所在层，与引擎解耦。
2. **可插拔存储引擎** — pluggable storage engine：以统一 handler 接口挂接的存取后端。
3. **查询缓存** — query cache：按 SQL 文本缓存结果集的共享缓存（历史构件，8.0 已删）。
4. **一线程一连接** — one-thread-per-connection：每客户端连接绑定一个工作线程的模型。
5. **二进制日志** — binary log：服务器级变更日志，复制与 PITR 的原料。
6. **能力位图** — capability flags：handlerton 上声明事务/外键等能力的标志集。
7. **表级锁粒度** — table-level locking：MyISAM 时代 Server 层的主要并发控制面。
8. **mSQL 渊源** — mSQL lineage：MySQL 名称与早期 API 兼容取向的历史来源。
9. **引擎参差** — engine asymmetry：功能依所选引擎而变的时代特征。
10. **多主环形复制** — circular multi-master：2007 年口径的高可用形态之一。
11. **连接层协议** — client/server protocol：连接线程与客户端通信的字节层（第 4 章展开）。
12. **务实演化** — pragmatic evolution：本书解释 MySQL 设计选择的总叙事词。
13. **历史语境** — historical context：本目录对 2007 口径内容的强制标注纪律。
