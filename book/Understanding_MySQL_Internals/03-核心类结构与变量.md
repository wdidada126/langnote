## 3.2 核心精讲（历史语境）

- **THD：一切状态的挂点**。当年一个 THD 同时装着：线程与栈边界、`mem_root`（请求级内存池）、当前 DB 与权限快照、当前 SELECT 的 LEX/JOIN、事务与 handler 实例清单、诊断区（条件列表）。书中反复提醒：**看任何内核函数，先问它动了 THD 的哪个成员**——这是读 5.x 代码最重要的单点技巧。
- **NET：协议抽象不换车**。`net_read_packet/net_write_packet` 把「包」语义（3 字节长 + 1 字节序号 + payload）从业务里剥出，vio 层再把它剥出传输（TCP/Unix socket/SSL 槽位）。这套双层抽象（NET over VIO over TLS）从 4.1 一直活到 8.x，是本书结构图里**折旧率最低**的部分。
- **TABLE/Field 的两层皮**：Server 层用 TABLE+Field 描述「表应该长什么样」，引擎内部另有行格式与索引结构；两者的胶水是 handler（第 7 章）。书中强调 TABLE 缓存与「每语句打开/关闭」的代价，这是当年 Table Cache 粗放的写照。
- **my_alloc/MEM_ROOT**：MySQL 大量使用「带内存池的分配器 + 语句结束统一释放」的模式；书中给了 MEM_ROOT 的用法守则。该模式今天仍在（`sql/mem_root_allocator.h` 把它接入了 STL 分配器接口）——2007 的「处理器宏」里 DBUG 家族则大幅退位（8.x 用编译器 sanitizer + ut_ad/DBUG_TRACE 残存），一升一降很有时代感。
- 教学示意（不参与构建）：`thd->get_protocol()`、`thd->security_context()`、`table->file->...` 这类取成员路径，就是当年到今天的「导航主干道」。

## 3.6 三问三答（本章高频疑问卡）

- **Q1：为什么「实用程序 API 调用」单独成节？**
  A：因为 mysys 层等价于 MySQL 的第二 libc：跨平台文件/字符集/线程原语都包在这里；不认它，后面八章的工具调用全是黑盒。
- **Q2：「处理器宏」值不值得精读？**
  A：宏的**思想**（运行期可开关的调试、断言、跟踪）值得；具体 DBUG 语法不必背——现代替代品是 sanitizer + 编译器内建 + performance_schema 观测点。
- **Q3：全局变量清单还有效吗？**
  A：清单本身早已失效，但「系统变量=全局 C 变量 + 描述表 + 会话覆盖」的三件套模型仍是 8.x 的实现（外加 P_S 可见性），这是本章最耐用的抽象。

## 3.7 THD 成员分层：一张「挂点地图」

书中读码口诀是「先看函数动了 THD 的哪个成员」。把当年散在 THD 上的成员按今天的归属重排，就得到这张地图：

| 关注面 | 5.0 里 THD 上的形态 | 今天（8.4）的归属 | 备注 |
| --- | --- | --- | --- |
| 线程与栈 | 线程句柄 + 栈边界（用于溢出检测） | 仍在连接线程对象里 | 见 [06-基于线程的请求处理.md](06-基于线程的请求处理.md) |
| 请求级内存 | `mem_root`（MEM_ROOT） | 仍在 + `MEM_ROOT`/`Mem_root_allocator` 生态 | 语句结束统一释放 |
| 当前库与权限 | `db`、权限位图 | `Security_context` 对象 | 下放到 `sql/auth/` |
| 协议与缓冲 | `net`（NET 结构体直接嵌在 THD 里） | NET + `Protocol` 抽象（文本/二进制两套） | 见 04 章 |
| 当前语句 | `query`、`lex`、`select_lex`、`join` | LEX + `Query_block`/`Query_expression`（命名换代 ⚠️ 转述） | 官方示例 `dump_explain()` 用的正是 `lex->select_lex.where/join`（✅ 实测代码） |
| 事务状态 | 引擎句柄清单（`tran_list` 一类） | `Transaction_ctx`/`Ha_data` | 见 [11-事务.md](11-事务.md) |
| 诊断信息 | `net.error`、告警计数 | `Diagnostics_area`（条件列表 + 状态） | 术语已 SQL 标准化 |
| 会话变量副本 | `struct system_variables variables` | 同名结构族仍在（✅ `sql/system_variables.h` 实测存在） | 见 [05-配置变量.md](05-配置变量.md) |
| 打开的表 | `open_tables`（TABLE 链表） | 同结构概念 + MDL 票据 | 见 [08-并发访问与锁定.md](08-并发访问与锁定.md) |

- **读法**：THD 从「大杂物袋」演进为「挂点集合」——成员被包进子对象，但**每个关注面都能找到一个唯一的子对象负责**。今天排查问题仍按这张表定位：权限类看 Security_context，计划类看 LEX，事务类看 Transaction_ctx，回包类看 Protocol/NET。

## 3.8 记录缓冲（record buffer）的字节观：用官方示例反推

`ha_csv` 的 `fetch_line()` 是本章 Field/TABLE 的最佳实证（✅ 逐字读过官方示例）：

- **列序即指针序**：`Field** field = table->field;` 然后每解析出一个字段就 `(*field)->store(field_buf.ptr(), field_buf.length(), system_charset_info); field++;`——**Server 层的记录是一块扁平字节数组，Field 对象只负责「我的偏移在哪 + 怎么把外部字节写进去」**。
- **NULL 位图是固定区**：读完一行后 `memset(buf, 0, table->s->null_bytes);`——空值标记占缓冲开头的 `null_bytes` 字节；这也解释了为什么「加一个可空列」会改变记录布局。
- **缺列走默认值**：CSV 行比表列少时 `for (;*field;field++) (*field)->set_default();`——引擎不猜，显式补默认。
- **两处小坑（书时代的真实接口变化）**：4.1 示例写 `table->null_bytes`，5.1 示例写 `table->s->null_bytes`——**同一含义，换了宿主**（TABLE → TABLE_SHARE）。这类「成员搬家」正是本目录判断代码年代的指纹。
- 教学补记（⚠️ 转述，未逐行核验）：Server 层比较新旧行时用 `table->record[0]` 与 `record[1]` 两块缓冲，引擎的 `update_row` 语义即建立在「谁是新值谁是旧值」的约定上。

## 3.9 mysys：MySQL 的「第二 libc」（示例代码里真实出现的调用）

| API | 作用 | 在示例/8.4 里的出现位置 |
| --- | --- | --- |
| `my_malloc` / `my_free` | 带错误上报的分配（`MYF(MY_WME)` 标志） | `ha_csv::open()` 分配 `CSV_INFO` |
| `fn_format(..., ".csv", MY_REPLACE_EXT\|MY_UNPACK_FILENAME)` | 把表名拼成数据文件名 | `ha_csv::open()` |
| `my_open` / `my_close` / `my_pread` | 跨平台文件 I/O（`my_pread` 按块读） | 示例 512 字节块读；8.4 CSV 同类用法 |
| `my_errno` | 取最近 mysys 错误号 | `ha_csv::open()` 失败分支 |
| `String` + `append()`/`length(0)` | 带缓冲的字符串（字段值缓冲） | 示例 `field_buf` |
| `my_store_ptr` / `my_get_ptr` | 把行位置编进定长 `ref` | 示例 `position()`/`rnd_pos()` |
| `system_charset_info` | 默认字符集对象（传给 `Field::store`） | 示例字段解析 |
| `thr_lock_init` / `thr_lock_data_init` / `thr_lock_delete` | 表锁管理器的初始化与销毁 | 示例 `open()`/`close()`；见 [08-并发访问与锁定.md](08-并发访问与锁定.md) |
| `my_error(ER_xxx, MYF(0), ...)` | 把引擎错误变成 SQL 条件 | 8.4 `ha_tina::create()` 拒绝可空列（✅ 实测文件内） |

- 这条清单的实际用处：**读任何引擎源码时，把 mysys 调用当「 libc 语义」直接跳过**，注意力留给 handler 方法；反之在 8.x 里看到 `Mem_root_...`、`std::string` 混入，说明这一层正在被现代 C++ 逐步替换（转述 ⚠️）。

## 3.10 处理器宏与全局量：DBUG 时代的读码负担

- 示例文件头两行就很有年代感：`.cc` 里 `#ifdef __GNUC__ #pragma implementation`，`.h` 里 `#ifdef __GNUCC__ #pragma interface`（✅ 实测原文，头文件里宏名**多写了一个 C**，条件永不成立——一个留在官方示例里的真实小 bug，也说明当年这类编译指令已属装饰）。
- `DBUG_*` 家族的三件事：断言（`DBUG_ASSERT`）、跟踪（`DBUG_PRINT`）、运行期开关（`DBUG_SET`）。书中把它当「调试源码的入口」讲；今天仍在用但已退化：8.4 `ha_tina.cc` 里能看到 `DBUG_TRACE`（✅ 实测文件内），而断言与内存正确性交给 sanitizer（见本章 3.3 表）。
- 全局变量一族的读法：书里列的那些「C 全局 + sysvar 描述表」在 8.4 仍可对照实物——`sql/sys_vars.cc`、`sql/set_var.h`、`sql/system_variables.h`（三者在 8.4 树实测 200），只是声明形态更规整。

## 核心概念速览（中英对照）

1. **THD** — thread descriptor：一线程一请求的总上下文对象。
2. **NET** — 协议网络缓冲：包级读写抽象，屏蔽传输层差异。
3. **VIO** — virtual I/O：NET 之下的 socket/SSL 传输封装。
4. **TABLE** — Server 层表句柄：字段数组与 handler 实例的宿主。
5. **Field** — 列对象：类型、空值位与编解码的 Server 层表示。
6. **MEM_ROOT** — 内存池分配器：语句级统一释放的 my_alloc 家族核心。
7. **Item** — 表达式节点：与 Field 并列的求值树元素（查询期临时结果）。
8. **handler** — 引擎接口对象：TABLE 之下的每表一个引擎句柄。
9. **DBUG_*** — 调试宏家族：2007 时代的断言/跟踪/运行期开关机制。
10. **系统变量描述表** — sysvar table：全局 C 变量与会话变量的元数据桥。
11. **诊断区** — diagnostics area：SQL 条件/告警的存放处（THD 内）。
12. **两层皮** — two-layer table model：Server 层表结构与引擎层存储结构分离。
13. **security_context** — 权限快照：THD 上承载当前用户与库级权限的对象。
