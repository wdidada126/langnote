> 原书章：第 10 章（中文正版目录实抓：「存储引擎」）。二级小节实抓：架构的相同之处 / InnoDB / Memory（Heap）/ MyISAM / Merge / NDB / Archive / Federated。
> 语境基线：4.1/5.0 的「多引擎并存且能力参差」年代——InnoDB 还不是默认引擎，NDB 刚进主线（5.1），Archive/Federated/Merge 都还是「日常选项」。

## 10.1 本章地图

| 节 | 内容 | 2007 年口径的结论 |
| --- | --- | --- |
| 架构的相同之处 | 所有引擎共用 handler/handlerton；文件命名与 `.frm` 表定义；能力标志决定 Server 层降级面 | 引擎的差别只在「实现 + 声明的能力」 |
| InnoDB | 表空间、缓冲池、聚簇索引、行锁、崩溃恢复 | 功能最强但最重，配置项最多 |
| Memory（Heap） | 内存表、HASH/扫描索引、进程重启即空 | 内部临时表与映射表的底座 |
| MyISAM | `.MYD`/`.MYI`、表锁、索引存文件偏移、无崩溃恢复 | 当年的默认选择，全文索引在这里 |
| Merge | 把同构 MyISAM 表当一张表用（`.MRG`） | 手工分区的前身 |
| NDB | 分享无（shared-nothing）内存数据节点 + SQL 节点 | 高可用路线，与单机 MySQL 是两个世界 |
| Archive | 追加写 + zlib 压缩、无二级索引、顺序扫描 | 归档与日志流水 |
| Federated | 把远端 MySQL 表当本地表（走客户端协议） | 早期「跨实例查询」的穷人方案 |

## 10.2 「架构的相同之处」——本章最该记住的一节

- **同一套接口的三种「个性表达方式」**：能力声明在三个不同位置（7.4 表已列）——`table_flags()`（表级）、`index_flags()`（索引级）、handlerton flags（引擎级）。示例引擎 `ha_csv` 的写法最有教学味：`table_flags()` 返回 `HA_NOT_EXACT_COUNT`（不许拿 `records` 当 COUNT(*) 答案）、`index_flags()` 返回 0（我没有键）、handlerton 的事务槽全 NULL（我不参与事务）。**读三个返回值就知道这个引擎的性格**。
- **文件层约定**：`.frm` 存表定义（8.0.16 起被数据字典取代）、数据/索引文件按引擎各自扩展名（MyISAM `.MYD`/`.MYI`、InnoDB `.ibd`/ibdata、MERGE `.MRG`、ARCHIVE `.ARZ`、CSV `.csv`）。示例引擎用 `bas_ext()` 交出 `(".csv", 0)`，8.4 里同一信息改由 `hton->file_extensions` 提供（✅ 实测 8.4 `ha_tina.cc` 有 `tina_hton->file_extensions = ha_tina_exts;`）。
- **锁的相同与不同**：Server 层一律走 `store_lock()`→`thr_multi_lock()`→`external_lock()`（[08-并发访问与锁定.md](08-并发访问与锁定.md)）；区别在于 MyISAM/MEMORY/CSV 的表锁就是最终并发度，而 InnoDB 在 `external_lock` 之后自己接管行级并发。
- **优化器对所有引擎一视同仁地「不敢信」**：`info()` 必须给出不至于误导计划器的 `records` 下限（示例里抬到 2）——这条约定适用于所有引擎，也是本章与第 9 章的接缝。

## 10.3 引擎逐个小传（书中口径 → 今天）

### InnoDB
- **书中要点**：表空间（共享 `ibdata` 或独立 `.ibd`）、缓冲池 + LRU、聚簇索引即表、二级索引回表、行锁 + MVCC、重做日志与崩溃恢复、自动增长与外键。5.0 时代它还是「外挂」，功能靠 `innodb_*` 一堆参数打开。
- **今天**：5.5 起默认引擎，8.0 起系统表也在里面，还多出即时 DDL、数据字典、双写/（8.0.20+ 的）`dblwrite` 演进、并行扫描等（⚠️ 小版本点未逐条重抓）。深度展开在 repo 内另两本：[../mysql/02-Buffer-Pool.md](../mysql/02-Buffer-Pool.md)、[../MySQL技术内幕_InnoDB存储引擎2.md](../MySQL技术内幕_InnoDB存储引擎2.md)。

### Memory（HEAP）
- **书中要点**：全部在内存、索引在内存（HASH 或 BTREE 形态取决于版本与用法）、容量受 `max_heap_table_size`；重启即空、`GROUP BY` 溢出会报错；被大量内部用途使用。
- **今天**：仍是 MEMORY 引擎（✅ 8.4 专页实测 200），但内部临时表的默认早已转向 TempTables 引擎路线（`internal_tmp_mem_storage_engine`，⚠️ 转述），现代口径见 https://dev.mysql.com/doc/refman/8.4/en/internal-temporary-tables.html 。

### MyISAM
- **书中要点**：索引 B+ 树节点存的是**文件偏移**（所以行可以随意搬）、表锁 + 并发插入、`myisam-recover` 兜底、无事务无崩溃恢复、行数免费计数器、全文索引。
- **今天**：8.4 文档仍有专页（✅ https://dev.mysql.com/doc/refman/8.4/en/myisam-storage-engine.html ），但生产角色已收缩为「系统库以外的兼容保留 + 只读静态数据」；8.0 里「表必须 InnoDB」是官方迁移建议（⚠️ 转述，未逐页抓）。

### Merge（MRG_MyISAM）
- **书中要点**：把若干**同构** MyISAM 表拼成一张逻辑表，键与锁都在成员表上；当年用来做「按时间分片」的手工分区。
- **今天**：8.4 专页仍存（✅ https://dev.mysql.com/doc/refman/8.4/en/merge-storage-engine.html ），但真实需求早被分区表接走：https://dev.mysql.com/doc/refman/8.4/en/partitioning.html （本章判读：**Merge 是分区表的用户态前身**，两者不能混为一谈）。

### NDB（NDBCluster）
- **书中要点**：数据节点（内存 + 磁盘检查点）+ SQL 节点 + 管理节点；无共享架构；SQL 层可下推扫描条件；事务在数据节点内完成；与单机 MySQL 的锁/复制模型是两个世界。
- **今天**：NDB 已从 MySQL Server 文档域分离，走 MySQL Cluster 专文档（✅ 本轮实测：`refman/8.4/en/ndb-storage-engine.html` 为 **404**，而 `refman/8.4/en/mysql-cluster.html` 为 **200**，即 8.4 手册只留 Cluster 章节入口）；生态续命在 Percona XtraDB Cluster 的 wsrep 路线（✅ https://github.com/percona/percona-xtradb-cluster ，注意它是 InnoDB+复制协议，不是 NDB）。

### Archive
- **书中要点**：只追加、按块压缩（zlib）、无二级索引（只有行位置）、顺序扫描为主；日志/审计流水的最佳归宿；`COUNT(*)` 需要额外维护。
- **今天**：8.4 专页实测存在（✅ https://dev.mysql.com/doc/refman/8.4/en/archive-storage-engine.html ）；现实使用面被列式与对象存储归档挤压（⚠️ 趋势判断为转述）。

### Federated
- **书中要点**：本地只存「指向远端表的定义」，读写通过标准客户端协议转发给远端 mysqld；无本地存储、无跨端事务保证、性能受网络往返支配；`FEDERATED` 默认不启用。
- **今天**：8.4 专页实测存在（✅ https://dev.mysql.com/doc/refman/8.4/en/federated-storage-engine.html ）；同类需求现在由 MySQL Shell、Clone/Group Replication 与外部表/CDC 生态（如 Debezium ✅ https://github.com/debezium/debezium ）承担。

### CSV / BLACKHOLE（本书示例的两位亲属）
- CSV 引擎是示例引擎的原型（`storage/csv/ha_tina.cc`，8.4 实测 200）：无索引、行位置即 `ref`、`check()` 做一致性体检、`HTON_SUPPORT_LOG_TABLES` 允许 `general_log`/`slow_log` 用它。
- BLACKHOLE 只接收不保存，是压测与「只看日志」场景的插座（✅ https://dev.mysql.com/doc/refman/8.4/en/blackhole-storage-engine.html ）。
- **本章判读**：示例 `ha_csv` 与生产 `ha_tina` 的 `store_lock()` 函数体逐字同构（见 [07-存储引擎接口.md](07-存储引擎接口.md) 的 7.4 表）——**教学代码与生产代码在同一条演化线上**，这是本书最好的合法性证明。

## 10.4 「历史语境」清单

| 书中描述 | 今天（8.4/9.x） |
| --- | --- |
| 选引擎是 DBA 的核心决策 | 默认唯一（InnoDB）；其余引擎退到特化岗位（CSV 日志表、BLACKHOLE 压测、MEMORY 临时、ARCHIVE 归档） |
| 每表一个 `.frm` | 事务性数据字典 + SDI，8.0.16 起 `.frm` 消失（✅ https://dev.mysql.com/doc/refman/8.4/en/data-dictionary.html ） |
| MyISAM 全文索引是卖点之一 | 全文索引 InnoDB 也有（5.6+），MyISAM 优势再消一层（⚠️ 转述） |
| NDB 与单机 MySQL 同书并列 | NDB 走独立 Cluster 文档线（实测见 10.3） |
| 分区要靠 Merge 手工做 | 原生分区（LIST/RANGE/HASH/KEY）成熟，且部分引擎不参与（`HTON_NO_PARTITION` ✅ 实测 8.4 CSV 声明之） |

## 10.5 常见误区与修正

| 误区 | 修正 |
| --- | --- |
| 「引擎多=可任意替换」 | 事务/崩溃恢复/锁粒度不可跨引擎借，换引擎=换行为合同 |
| 「MEMORY 表可以当缓存层长期用」 | 进程重启即空、容量上限硬；作为缓存需要外部持久层（这是它和 Redis 类系统的根本差别） |
| 「MERGE 就是分区表」 | MERGE 是用户态拼表、成员可各不相同；分区是引擎/Server 层协议且约束同构 |
| 「Archive 慢」 | 它只是没有索引；顺序扫描 + 压缩在归档负载上恰恰是优点 |
| 「Federated 能当跨库事务用」 | 无两阶段保证，远端失败即数据不一致——今天没人这么用它 |

## 10.6 三问三答（本章高频疑问卡）

- **Q1：这一章为什么值得读？**
  A：不是为了选引擎（今天的选择题已经做完），而是为了理解「同一个 handler 接口能装下多不同的性格」——这是第 7 章接口设计的意义所在。
- **Q2：怎么判断一个引擎「够不够格」承担 OLTP？**
  A：查 handlerton 的三件事：事务槽是否非空、是否支持崩溃恢复（`recover`/redo）、锁粒度声明；这三问在 2007 与今天一样有效。
- **Q3：本章的引擎今天还剩几个能在新版本里真跑？**
  A：官方文档仍给专页的：InnoDB、MEMORY、MyISAM、MERGE、CSV、Archive、Federated、BLACKHOLE（✅ 实测 200，见文末）；NDB 走 Cluster 文档。真实生产里只有 InnoDB + 少量 MEMORY/CSV。

## 核心概念速览（中英对照）

1. **可插拔存储引擎** — pluggable storage engine：以 handler 接口挂接的存取后端。
2. **能力声明** — capability flags：`table_flags`/`index_flags`/handlerton flags 三层自我描述。
3. **表空间** — tablespace：InnoDB 的逻辑存储容器（共享/独立文件）。
4. **聚簇索引** — clustered index：叶子即行数据的索引，InnoDB 表的物理组织。
5. **回表** — row lookup：二级索引命中后按主键取整行的代价。
6. **内存表** — MEMORY (HEAP) engine：进程内存中的表，重启即空。
7. **文件偏移指针** — file position in index：MyISAM 索引叶子存的是位置而非主键。
8. **并发插入** — concurrent insert：MyISAM 读插混行的能力。
9. **合并表** — MERGE engine：同构成员表组成的逻辑大表（分区前身）。
10. **NDB 数据节点** — NDB data node：内存 + 检查点磁盘的分享无存储单元。
11. **归档压缩** — ARCHIVE engine：zlib 压缩追加写、无二级索引。
12. **联邦表** — FEDERATED engine：把远端表映射为本地表的转发型引擎。
13. **黑洞引擎** — BLACKHOLE：接收但不存储，用于压测与日志型场景。
14. **`.frm`** — 表定义文件：8.0.16 前每表一份，已被数据字典取代。
15. **文件扩展名声明** — `bas_ext()` / `file_extensions`：引擎告诉 Server 层自己用哪些后缀。
