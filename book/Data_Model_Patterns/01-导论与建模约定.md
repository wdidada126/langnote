# 01 导论与建模约定（原书 Ch1 Introduction + Ch2 Data Modeling Conventions，页 1–22）

## 章定位

Ch1 是全书的"檄文"：数据建模的承诺与失败（Data Modeling's Promise–And Failure）；Ch2 给出本书的方法论基座——把建模共识拆成**句法（Syntactic）/位置（Positional）/语义（Semantic）三层约定**。读懂这两章，后面 10 个领域模式章都是同一套约定在具体行业里的展开。

## Ch1 转述要点

### 1.1 承诺与失败

- 承诺：数据模型是组织内关于"业务事实长什么样"的**最稳定共识**——流程会变、系统会换，实体与关系的变化慢一个数量级。
- Hay 诊断的失败模式（转述）：
  1. **重复发明**：每个新项目、每个建模者都从零画一遍"订单-订单明细"，且每人画法不同；
  2. **约定缺失**：同样一张图，两个人读出两种基数含义（见 1.2 位置约定）；
  3. **与实现脱钩**：模型被当作交付物装饰，评审者只看表数量不看语义；
  4. **行业词汇不守恒**：同一个"当事人"在 CRM 叫 Party、在 HR 叫 Person、在财务叫 Customer，合并主数据时才发现是同一模式。
- 处方：把"见过一次就永远正确"的解法沉淀为**模式（Pattern）**，像软件界采纳 GoF 那样采纳数据建模模式，用命名+约定降低模型沟通成本。

### 1.2 About Modeling Conventions

Hay 强调：模式的价值不在图形，而在**被团队共同执行的约定**。他给出三种"读模"纪律：先说清关系的名词（如"被记录于"），再谈基数，最后谈可选性；顺序颠倒的评审会退化成图形纠错。

### 1.3 These Models and Your Organization / Who Should Read This Book?

- 模式不是宪法：允许"有记录的偏离"——偏离必须在模型注释里显式命名，否则视为错误。
- 目标读者（转述）：做逻辑设计的数据建模师、需要与建模师谈判的分析人员、以及"想看懂模型为什么这样画"的开发负责人。

## Ch2 转述要点：三层约定

### 2.1 Syntactic Conventions（句法约定）

- 实体=业务名词的单数（Person 而非 People）；关系=动词短语（"is assigned to"）；
- 主键的显示纪律：每实体标注标识符，但**代理键与业务键要区分命名**（Hay 反对无语义 id 泛滥，⚠️ 转述其一贯立场）；
- 一图一实体多次出现时须标注引用符号，避免"同名不同实体"。

### 2.2 Positional Conventions（位置约定）

- Hay 特色：把"一"侧与"多"侧与**图面位置**绑定——父在左/上、子在右/下；同一行内相关实体相邻摆放；
- 理由（转述）：评审者扫图的顺序即读句顺序，位置即语法的一部分；基数符号可能漏画，位置不会沉默；
- 与 ER 箭头流派（Crow's foot 等）的接口：任何记法都能映射到这三层约定，记法之争是句法层，本书故意停在约定层。ER 记法谱系见 [../Database_Modeling_and_Design_5e/02-实体联系模型ER.md](../Database_Modeling_and_Design_5e/02-实体联系模型ER.md)。

### 2.3 Semantic Conventions（语义约定）

- 关系的**读法模板**："每一个 X 关联 {零或一/恰一/零或多/一或多} 个 Y"，双向都写全；
- 三个高频语义陷阱（转述）：
  1. 把"类型-个体"画成父子（Ch4 专治，见 03 文件）；
  2. 把"角色"当成实体的属性列（Ch3/Ch6/Ch11 反复出现，见 02/04/07 文件）；
  3. 用一张表同时表达"事实"与"对该事实的承诺"（Work Order 模式的核心切分，见 04 文件）；
- 时间语义：未标注的时间区间一律按"左闭右开、以日粒度"读（Hay 的位置/语义约定在 Ch12 有回环修订）。

## 常见误读

1. "模式=模板，抄就行"——Hay 反对无脑套：偏离约定必须显式记录（Ch1.2 纪律）。
2. "位置约定是形式主义"——实为低成本评审机制，解决"同一图两人读出两义"。
3. 把本书当物理设计书：所有模式停留在逻辑层，索引/分区问题去 [../Physical_Database_Design/00-总览与阅读地图.md](../Physical_Database_Design/00-总览与阅读地图.md)。

## 🔧 类比演示（本章：约定的机器可检性）

逻辑约定到 schema 层的最低落点是命名与标识完整性：SQLite 3.45.3 实测（方法：`CREATE TABLE party_role(... REFERENCES party)` 后插入悬空外键值，得 `FOREIGN KEY constraint failed`；完整数据见 02 文件 T1）。演示语义——"每行必须属于一个已登记当事人"这类句法约定是**可被引擎强制**的，而位置约定永远只能靠人。非本书引擎行为，仅示意"约定→约束"的映射边界。

## 三层约定应用清单（评审会自用）

| # | 检查项 | 层 | 典型违例形态 |
|---|---|---|---|
| 1 | 实体名是单数业务名词 | 句法 | People/Orders 复数集合名词 |
| 2 | 关系是受控动词短语 | 句法/语义 | "has""rel" 等含糊动词 |
| 3 | "一"侧在左/上、"多"侧在右/下 | 位置 | 摆放颠倒使基数扫读失效 |
| 4 | 同族实体同行相邻 | 位置 | 无关实体散落全图 |
| 5 | 双向基数读法都写全 | 语义 | 只写单向，另一向靠猜 |
| 6 | 时间区间左闭右开、日粒度 | 语义 | 闭区间/秒粒度混用 |
| 7 | 业务键与代理键命名可辨 | 句法 | id 泛滥掩盖主外键链 |
| 8 | 偏离模式之处有显式注释 | 语义 | 静默破例，共识瓦解 |
| 9 | 类型关系与分类关系分画 | 语义 | instance-of 与 category-of 混一自关联 |
| 10 | 同一实体跨图同名 | 句法 | 同一 Party 三系统三名 |

## 建模练习（读后自测）

1. **练习 1**："每份合同设一至两名见证人"——按 2.3 读法模板写出双向读法并判层。参考要点：合同:见证人=1:0..2；反向"每见证人参与零或多合同"；"一至两"是语义约束，句法层不得退化为 0..N 了事。
2. **练习 2**：现有图中员工职务画成 `employee.position_str` 列——用 Ch1/Ch2 批注其违例。参考要点：职务=角色事实（02 文件 Party Role）；字符串列把语义约定压成句法装饰；历史维度直接丢失。
3. **练习 3**：队友一个用 Crow's foot、一个用 IDEF1X 画"同一模型"，图面冲突。按 Hay 观点先对齐哪层？参考要点：记法之争只在句法层；若语义读法不一致那是约定违规而非记法问题；位置冲突按 2.2 重摆。
4. **练习 4**：给"评审先看基数符号画得对不对"的做法开药方。参考要点：违反 1.2 读模纪律——先名词、再基数、后可选性；基数优先的评审退化为图形纠错。

## 译名对照说明

- Pattern 全书作"模式"，与 GoF 设计模式区隔：Hay 的模式是**逻辑建模约定**，无"面向对象的解法"含义；
- Conventions of Thought（副题）宜译"思维约定"：指训练成习惯的共同读法，不是"思考规范指南"式规章；
- Entity 一律"实体"，但 Hay 常与 thing/object 混用——按上下文判别，03/08 文件的三分法是唯一硬标准。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
|---|---|---|
| 模式 | Pattern | 被反复验证、可命名复用的建模解法 |
| 句法约定 | Syntactic Convention | 实体/关系命名与记号的纪律 |
| 位置约定 | Positional Convention | 父左子右等图面位置承载语义 |
| 语义约定 | Semantic Convention | 基数读法模板与时间区间读法 |
| 重复发明 | Reinventing the Model | 无模式库时各团队重画同构模型 |
| 有记录的偏离 | Documented Deviation | 允许破例但必须显式注释 |
| 业务键/代理键 | Business Key / Surrogate Key | 标识符两种血统，命名须可区分 |
| 承诺与事实分离 | Promise vs Fact Split | 订单（承诺）与履行记录（事实）分实体 |
| 模式库 | Pattern Library | GoF 之于软件的数据建模对应物 |
| 评审顺序 | Review Discipline | 先名词、再基数、后可选性 |

## 最新演进与工业实践

- **模式库的开源化**：数据建模社区模式（Hay 主持的 Community Data Model 系列）在 2020s 多以讲义/仓库形式流通；正式出版物仍是本书与 Morgan Kaufmann 姊妹册（⚠️ 未见可实证 URL 的官方开源仓库，诚实登记）。
- **约定→CI 检查**：现代 dbt/数据契约实践把"命名纪律、语义版本"写成 lint 规则（如 schema 测试、命名快照评审），与 Hay 2013 年"约定即质量"主张同向（⚠️ 转述，未逐家实测）。
- **理论根基仍有效**：Codd 关系模型原文 *A relational model of data for large shared data banks*, CACM 1970, DOI: [10.1145/362384.362685](https://api.crossref.org/works/10.1145/362384.362685)（✅ Crossref 200 校验）仍是"语义约定"的形式化后盾。
- **工业采用**：银行/电信主数据项目中的 Party 模型（本书 Ch3）与 FIBO 本体（OMG 业务词汇标准，⚠️ fibo.org 本机网络不可达未能验证 URL）在"当事人-角色"抽象上高度同构，可作为模式→本体的迁移路径。
