# 07 文档（原书 Ch11 Documents，页 205–234）

## 章定位

Ch11 是全书模式密度最高的一章（12 个二级节、30 页）：把"文档"从文件夹里的文件还原为**一等实体**——有身份、有结构、有角色、有版本、有收讫记录，并能承载临床观测与化学品安全说明等结构化内容。本章同时是 02（Party 角色）与 05（观测三元组）在"信息资产"方向的会师。

## 模式逐条转述

### 11.1 The Document / 11.2 Structure

- `Document` 实体三要件：**类型（Document Type，如 MSDS/合同/图纸）+ 内容身份（Document ID）+ 载体（一次具体表现/文件对象）**；
- 文档结构：`Document → Component Document` 递归（图纸套件、附件树）——Structure 模式第三次现身（02 组织、03 部件之后），读者此时应完成"递归结构=万能件"的归纳。

### 11.3 Roles / 11.4 Authorship / 11.5 Receipt of Documents / 11.6 Other Roles

- 文档-当事人一律经 **Document Role** 事实连接：作者、签署人、审核人、收件人、保管人……角色名是数据不是列名；
- Authorship 单独立节：作者可以是人也可以是组织（法人著作），且署名与版权角色可分离；
- **Receipt（收讫）**：向某 Party 送达并被确认的事件——时间戳+签收人+方式；合同催告、法规送达场景里"发出≠收到"，两事实分行（04 文件"承诺/事实分离"的文档版）。

### 11.7 Subject and Contents

- 文档**关于**什么（Subject）与文档**包含**什么（Contents）是两条不同的关系：
  - Subject：Document ↔ 任意业务实体（设备/合同/当事人），多对多——"关于这台泵的合格证"；
  - Contents：文档与另一文档的信息引用（"本规程引用标准 XX 第 5 条"），带引用条款粒度；
- 反模式：只有 `doc.tag` 字符串列——Subject 与 Contents 混成一锅，检索与影响分析双盲。

### 11.8 Versions

- 版本模式：**文档身份（Document）不变，表现（Revision/Version）逐版追加**；"当前版"是 Document 上恰一外键或角色事实，**不是布尔列的放任**——一文档多"当前"是完整性事故（🔧T6 用引擎强制之）；
- 生效/废止/被替代三种版本状态各自时间化；替代链（supersedes）是版本行间的自关联。

### 11.9 Variable Format Forms（可变格式表单）

- 表单=**表单模板（类型层：字段清单/布局/版本）× 表单实例（事实层：字段值）**；字段值纵表（Form Field Value: 实例×字段定义×值）容纳"不同年季模板字段增减"——EAV 的正当使用场景与其代价（Hay 明示要克制，08 文件 Ch12 再议）；
- 模板版本与实例填充版本必须分离：旧实例按旧模板解释。

### 11.10 Clinical Trials Observations / 11.11 Material Safety Data Sheets

- 两个"文档里长出结构"的压轴案例：
  - 临床观察报告：文档 Subject=受试者/研究（02 Party），Contents 挂 **观测三元组**（05 Ch8）——文档模式与实验室模式在监管数据里合体；
  - MSDS（现 GHS 下的 SDS）：同一文档类型在不同国家语言/法规版本下**结构同构**（成分×危害×防护小节），证明"文档=载体，小节=结构实体"的分层能扛住法规漂移。

### References（页 234）

## 🔧 T6 / T6b 实测：版本唯一性约束的双引擎对照（SQLite 3.45.3 / DuckDB 1.5.5，非本书引擎行为）

方法（脚本 `sqlite_tests.py`/`duck_tests.py`，输出 `sqlite_out.txt`/`duck_out.txt`）：`doc_version(doc, ver, is_current)`，复合主键 (doc,ver) 之外建**部分唯一索引** `CREATE UNIQUE INDEX uq_cur ON doc_version(doc) WHERE is_current=1`。

- **SQLite 3.45.3**：插入第二条 current → `second current intercepted: UNIQUE constraint failed: doc_version.doc`；随后"先降级 v2 再晋升 v3"（UPDATE+INSERT 同事务）成功，终态 `current rows: [(7, 3)]` —— "有且仅有一个当前版"被引擎声明式守住；
- **DuckDB 1.5.5**：同一 DDL 直接 `NotImplementedException: Creating partial indexes is not supported currently`（🔧 实测发现）——分析引擎不承载这类写入完整性，"当前版"约束须回到事务型库或批校验作业。
- 工程结论：模式不变式落在哪一层由引擎能力表决定（SQLite 偏索引型约束见 ✅ https://sqlite.org/partialindex.html ；DuckDB 面向分析写入路径），这正是"逻辑模式 vs 物理/引擎"分层教学案例。

## 常见误读

1. 用文件系统目录当文档模型——Subject/Version/Receipt 全部失踪；
2. `is_current` 布尔列无约束——多"当前版"静默发生（🔧T6 演示了补救）；
3. 表单直接宽表化——模板加一列=线上 DDL+历史实例错位（11.9 两害相权）。

## 建模练习

1. **练习 1**：政务"一件事集成办"——立项批文既关于本项目又互引条款。参考要点：Subject 与 Contents 两张多对多事实表分立；"清单里哪些材料"走 Subject，"改一处标准影响哪些文件"遍历 Contents。
2. **练习 2**：合同文档的"签署版/生效版/现行版"三概念。参考要点：三个独立指针（或角色事实）指向版本行，各自恰一约束按 🔧T6 同法实施；三布尔列混用=语义塌缩。
3. **练习 3**：电子签厂商回传签名事件流。参考要点：签名人=Document Role 事实，签署动作=Receipt 式事件行，文档哈希=版本内容指纹（11.1 身份/表现二分）；事件流不覆盖签署态。
4. **练习 4**：临床 CSR（研究报告）既含观测数据又引用方案版本号。参考要点：观测行归 05 章三元组，引用关系归 Contents——文档章与实验室章的分工试金石（11.10）。

## 版本状态机（据 11.8 转述示意）

```
草稿 draft ──签发──> 已发布 issued ──被新版替代──> 已替代 superseded
     │                    │──废止（无后继）──> 已退役 retired
     └──作废──> 废弃 abandoned
Document.current ──恰一指针──> 某一个 issued 版本
```

迁移全部落成事件行（谁/何时/依据哪条审批文档——自引用，Subject 关系的用武之地）；"生效日期 ≠ 发布日期 ≠ 签署日期"三时钟分行存储，混列即语义塌缩。

## 最新演进与工业实践

- **版本语义标准化**：Git 的 blob/commit 分离与 Hay"身份/表现"二分同型；企业内容管理（Alfresco/SharePoint）的 version label + major/minor 仍是 11.8 模式的产品化（⚠️ 转述）。
- **监管文档结构化**：CDISC ODM 承载临床观测链（✅ https://www.cdisc.org 200，2026-09-27）；GHS/SDS 16 节格式全球统一印证 MSDS 模式（⚠️ UNECE 页本机未验链）。
- **AI 检索语境（2024–2026）**：RAG 把文档切块（chunk）进向量库——Hay 提醒的"Subject vs Contents"在嵌入检索里重现为"元数据过滤 vs 语义相似"两条正交链路，结构化元数据（11.x 全套）成为检索质量的先决条件（⚠️ 方向性转述）。
- **EAV 争议现状**：宽表+列式引擎（DuckDB/BigQuery）时代，表单类数据倾向"模板 JSON+投影宽表"双轨，11.9 的克制原则仍被引用（⚠️ 转述）。
