# 06 制造计划与流程制造（原书 Ch9 Material Requirements Planning + Ch10 Process Manufacturing，页 173–204）

## 章定位

Ch9/Ch10 是 03 文件 Structure 模式的两大工业下游：**离散制造**（按 BOM 展开件数）与**流程制造**（沿流体路径追物料）。Hay 用两章示范同一方法论：先立"计划世界"（类型层+未来事实），再立"执行世界"（过去事实），两世界靠工单/批次咬合。

## Ch9 转述要点（MRP）

### 9.1 Planning Finished Products（成品计划）

- 计划三源：**预测（Forecast）+ 订单承诺（Ch6 合同行）+ 当前库存/在途（Ch4 库存三态）** → 净需求（Net Requirements）；
- 时间桶（Time Bucket）约定：计划按桶（日/周）记录，桶是实体不是字符串列；"冻结期内的计划不可再生成"是治理约定。

### 9.2 Determining Component Requirements（部件需求推演）

- BOM 逐层展开+提前期倒排=MRP 的教科书算法，Hay 关心的是**模型**：需求行（Requirement）= 类型 × 桶 × 来源（父项炸开/独立需求），每行须能回指父需求行——**需求树是可查询事实**，跑完即弃的中间表是黑箱反模式。

### 9.3 Firm Planned Orders / 9.4-9.5 The Manufacturing Planning Model / The Planning Model

- 计划单（Planned Order）→ 确认（Firm）→ 变工单（Ch5 Work Order）→ 变实际（领料/产出）——**四段式生命链**，段段留痕；
- 计划模型总图：类型层（BOM/提前期/批量规则）+ 时间层（桶）+ 事实层（需求/计划单/工单）三层解耦；换 MPS/MRP-II/APS 算法**不动表结构**——这是逻辑模型稳定性的展示窗。

## Ch10 转述要点（流程制造）

### 10.1 More about Assets / Structure and Fluid Paths

- 流程工业的"结构"不是装配树而是**连接拓扑**：设备（Asset）经 Pipe/Conduit 相连，流体路径（Fluid Path）= 拓扑上的通路；同一设备图，"装配视角"与"流体视角"两张结构表，别混。

### 10.2 Flows / Processes / 10.4 Monitoring Processes

- `Flow` 事实：物料（批次/流股）× 路径 × 时间段 × 量（带单位，多为质量/体积）——连续世界里没有"件"，数量语义换成**流**；
- `Process Segment`（过程段）：一批物料在某设备上的一段加工（开始/结束时间），是流程版的 Work Order；
- 监控：`Monitoring Point`（测点定义，类型层）× `Measurement`（读数事实）——延续 Ch8 观测模式。

### 10.5-10.6 The Laboratory / Tags and Measuring Points / Translation of Tag Values

- **Tag（位号）**：DCS/SCADA 世界的数据源地址，与业务测点是**两套命名空间**；`Tag → Measuring Point` 的映射表带生效区间——工厂改造改的是映射，不是历史读数；
- Tag 值翻译：原始刻度（0-4095 counts / 4-20mA）→ 工程量（℃/kPa）的换算规则也是版本化数据（10.6 标题点题）；
- 流程实验室：在线检验=对流的抽样（Sample 取自 Flow 而非个体），与 Ch8 三元组无缝衔接。

## 🔧 T5 实测：测点读数的分析侧（DuckDB 1.5.5，非本书引擎行为）

方法：`tag_value(tag, ts, val)` 5 行（T1 三点 10/20/30，T2 两点 5/7）；(a) 窗口 `AVG(...) ROWS BETWEEN 1 PRECEDING AND CURRENT ROW` + `LAST_VALUE`：实测 T1 移动均值 10→15→25（逐字输出含 `(T1,00:01,20.00,15.0)`、`(T1,00:02,30.00,25.0)`）；(b) **PIVOT 位号转列**：`PIVOT (SELECT date_trunc('minute',ts) AS m, tag, val FROM tag_value) ON tag USING avg(val) GROUP BY m` → `[(00:00, 10.0, 5.0), (00:01, 20.0, 7.0), (00:02, 30.0, None)]`——"tag 长表→宽表"即 10.6 Tag 翻译/对齐诉求的最小实现；注意首次尝试 `PIVOT ... ORDER BY 1` 直接 `ParserException`（DuckDB PIVOT 子句不接受裸 ORDER BY，实测发现，写法须 PIVOT 子查询包裹）。

## 常见误读

1. MRP 结果不落需求行只落"建议订单"——炸开过程不可审计（9.2）；
2. 把 tag 名当业务测点名存进读数表——DCS 改名=历史数据断层（10.5 映射层缺失）；
3. 流程工业强用"件数"列——流的累积量应是另一事实（9.x/10.2 数量语义分裂）。

## 离散 vs 流程世界对照表（Ch9/Ch10 总图）

| 维度 | Ch9 离散（MRP） | Ch10 流程 |
|---|---|---|
| 结构形态 | 装配 BOM（部件树） | 流体路径（设备拓扑） |
| 计划粒度 | 件 × 时间桶 | 流段 × 起止时间 |
| 执行单元 | Work Order | Process Segment |
| 追踪对象 | 个体/批次（03 章三层） | 批次/流股（物料平衡） |
| 取样对象 | 个体或批 | Flow 上取 Sample（接 05 章） |
| 数量语义 | 整数件 + 单位 | 质量/体积 + 单位（无"件"） |
| 命名空间 | 物料/型号码 | 型号码 + 位号（两套，须映射） |

## 建模练习

1. **练习 1**：油漆厂连续产线终端灌装成罐装 SKU——指出模型切换点。参考要点：灌装=最后一个 Process Segment；此点完成 Lot→Product 个体创生（03 章三层链），此后库存/订单全部走 Ch4/Ch6/Ch9 离散语义。
2. **练习 2**：100 台成品已生成未 Firm 的计划单，BOM 工程变更生效。需求树怎么重算？参考要点：结构新旧两行带生效区间（4.3）；未确认计划行按新结构再生成，需求行的父链 lineage 保留两代（9.2）；已执行工单不追改。
3. **练习 3**：DCS 升级后全部位号改名，历史读数如何保住？参考要点：只新增映射表行（新 tag→同一测点，生效区间切段，10.5）；UPDATE 历史 tag 列=灾难（常见误读 2）。
4. **练习 4**：混线车间"既按台套又按批次追溯"。参考要点：Ch9/Ch10 双结构表并存+交叠点显式建桥（灌装/装配段），正是两章并读的用武之地。

## 与算法层的边界

- MRP 批量规则、净需求算法归生产管理教科书，Hay 只保证**模型层可重算可审计**（需求树=可查询事实）；
- 计划公式的"表达式一等化"在 08 文件 12.8 收口；
- 流程侧的物料平衡（input=output±stock）是 Ch10 各事实表之间的跨表不变式，与 05 文件复式恒等同类（🔧T4 经验直接迁移）。

## 计划四段生命链（9.3 口令化速记）

| 段 | 实体状态 | 可再生成? | 可审计对象 |
|---|---|---|---|
| 生成（Generate） | Planned Order（虚拟） | 是（全量重跑） | 需求行父链 |
| 确认（Firm） | Firm Planned Order | 否（冻结期锁） | 确认人×桶 |
| 下达（Release） | Work Order（04 章） | 否 | 承诺回指（合同/预测） |
| 实绩（Actual） | 领料/产出/工时事实 | 永不（只追加） | 活动五元组 |

四段式=04 文件"承诺-事实链"在制造语境的专列；换算法（MRP→APS）只动段 1。

## 最新演进与工业实践

- **MRP→云 APS**：SAP IBP/Kinaxis 等把 9.x 的"三层解耦"云化，但逻辑模型仍是 类型+时间桶+需求事实 三件套（⚠️ 转述，未实测商业系统）；
- **ISA-95/IEC 62264**：企业-车间-控制分层与"工单=作业计划(Job Order)"的对象定义与 Ch9/Ch10 模式高度对齐，MES 集成时的字段映射可按本文件两套模式对照（⚠️ 标准页未能本机验链）；
- **时序分析栈**：tag/测点长表→特征宽表已是 DuckDB/ClickHouse 类引擎的一等公民（🔧T5 的 PIVOT 即缩影）；PI System/Aveva 生态仍维持"位号≠资产测点"双命名空间（⚠️ 转述）；
- **单元/批次混线（blend-and-batch）**：2020s 流程+离散混合制造让 Ch9/Ch10 双章并读的价值上升，社区讲义常以"同一工厂两套结构表"举例（⚠️ 方向性）。
