# 05 会计与实验室（原书 Ch7 Accounting + Ch8 The Laboratory，页 117–172）

## 章定位

两章是同一种建模范式的两面：**都用"账本"记录世界**——会计用借/贷双分录记价值流，实验室用"样本-检验-观测"三元组记事实流。Hay 在两章都演示了"类型层规则 × 事实层记录"的严格分层，且都处理"汇总数从哪来"（Summarization）这一对模型最不友好的问题。

## Ch7 转述要点

### 7.1 Basic Bookkeeping（基础记账）

- 四要素模式：`Account`（科目，递归树：父科目=汇总节点，又一次 Structure）、`Journal Entry`（分录头：时间/来源凭证）、`Posting/Entry Line`（行：科目×方向×金额）、规则表（什么业务事件生成什么分录模板——**规则是数据不是代码**的 Hay 式主张）；
- 复式恒等：每个 Journal Entry 的 Σ借=Σ贷——约束跨越同一分录的**多行**，是"行级 CHECK 表达不了的业务不变式"的经典案例（见 🔧T4 实测）；
- 币种纪律：金额必带币种（事实列，不是表名后缀），本位币汇总是派生；
- 冲销/更正=反向分录，禁止改历史行（时间切片在财务的强化版：法律义务）。

### 7.2 Summarization（汇总）

- **汇总层级模式**：`Account Hierarchy（明细→总账）× Period（日/月/年）→ Account Summary(余额, 借/贷发生额)`；
- 关键约定：汇总行必须由明细行**可重演**推导（re-computable），任何手工写进汇总列的"调整数"都必须同时落成明细分录——否则报表与明细断链；
- 未达账/在途：会计时间（关账期）与业务时间（交易发生）双时钟并存，`Period` 实体带开闭状态。

## Ch8 转述要点

### 8.1 Samples, Tests, and Observations（样本-检验-观测）

- 实验室母模式三元组：
  - `Sample`：从物（Ch4 个体/批次）中取的受检部分——**取样本身是活动**（Ch5），有日期与取样人（Party）；
  - `Test Type`：检验规程（类型层，含方法与限度），实例化为 `Test`（对样本的一次执行，=Work Order 子型）；
  - `Observation`：观测结果事实（值/单位/时间/由哪个 Test 产生）——Hay 刻意避开"结果"一词：**观测是被记录的读数，判合格与否是另一层规则**。
- 观测值的三形态：数值（连续）、类别（枚举）、文本（自由）——各有下游统计语义，混列是 QC 系统常见病。

### 8.2 Derived Observations（派生观测）

- 由其他观测计算出的观测（如 BOD 由两组稀释读数推出）：派生行必须回链其**父观测集+公式版本**——公式变了旧派生不追改（历史可重演原则，与 7.2 同构）。

### 8.3 Test Types / 8.4 Sample Methods

- 检验类型带规格限（上下限、目标值），限本身版本化；取样方法（Sample Method）是"如何取样"的类型层规程；两者都拒绝硬编码进事实行。

### 8.5 Testing for Material Composition / 8.6 Tests as Activities

- 成分分析=Observation 挂"成分（材料分类）×值×单位"的纵表——宽表一元素一列在周期表面前必然失败；
- 收尾把 Test 明确并入 Ch5 活动体系（检验单=Kinds of Work Orders 的一族）：全书动词统一。

## 🔧 T4 实测：复式恒等式的引擎表达力边界（SQLite 3.45.3，非本书引擎行为）

方法（脚本 `D:\develops\tmp\dbwave_w5_dmpatt\sqlite_tests.py`，输出 `sqlite_out.txt`）：`posting(txn, account, side D|C, amount)`；
1. 天真方案——`AFTER INSERT` 触发器要求"本 txn Σ借-Σ贷=0"：**实测发现连合法分录的第一条腿都被拦**（逐字：`finding: per-row trigger aborts the FIRST leg of a valid balanced entry: unbalanced entry`）。根因：SQLite 触发器**逐行**执行，而复式约束跨行；
2. 可行方案——事务内 `BEGIN; executemany(两腿); 提交前 SELECT ... GROUP BY txn HAVING Σ<>0;`：实测输出 `pre-commit check found unbalanced txns: []`（合法分录放行）→ 再插不合法 txn2 后检查得 `[(2,)]` → `ROLLBACK` → `postings after rollback: []`（全部或无，事务原子性实测可见）。
结论：跨行不变式在最小引擎上=「事务边界+提交前校验」；声明式方案（PG 延迟约束/EXCLUDE、SQL 标准 ASSERTION）本机不可测 ⚠️ 转述。

## 常见误读

1. 余额直接存 `account.balance` 并 UPDATE——违反可重演原则，审计噩梦（7.2）；
2. 检验结果写"合格/不合格"单列——把观测与判定焊死，限度改版后历史全废（8.1/8.3）；
3. 派生指标不回链父数据——数字出处不可考（8.2）。

## 账本式范式对照（两章公因式）

| 维度 | 会计（Ch7） | 实验室（Ch8） |
|---|---|---|
| 类型层 | 科目树、过账规则表 | Test Type、规格限、取样方法 |
| 事实层 | Journal Entry + Posting | Sample / Test / Observation |
| 派生层 | Account Summary（层级×期间） | Derived Observation（父观测+公式版本） |
| 不变式 | Σ借=Σ贷（跨行） | 观测必由某次 Test 执行产生 |
| 版本纪律 | 冲销更正，不改历史行 | 规格限版本化，派生不追改 |
| 可重演 | 报表可由明细重算 | 结论可由观测重算 |

一句话：**两章都在教"规则即数据 + 事实只追加 + 派生可重演"三件套**，行业外壳不同而已。

## 建模练习

1. **练习 1**：预付房租 12 个月摊销。参考要点：摊销规则=规则表数据（7.1），每月摊销=正式分录事实；合同表塞"剩余待摊"列违反可重演（7.2）。
2. **练习 2**：同一样本复测出旧值/复测 1/复测 2 三观测，报表要"当前值"。参考要点：三行全留；"当前"是判定规则+视图的产物（12.7 语义），不是 Observation 上的可覆写列。
3. **练习 3**：双准则（IFRS+本地）平行账。参考要点：Ledger 作为独立维度与 Account 树正交（7.2 变体），同一 Posting 多账映射规则化；禁止"科目码.后缀"字符串魔法。
4. **练习 4**：水质化验 BOD 由两稀释读数推得，方法换版。参考要点：派生观测回链父观测+公式版本（8.2）；旧结论不改，新批用新版——与 7.x 期间关账同构。

## 引擎边界备注（对应 🔧T4）

- 跨行不变式：SQLite 3.45.3 无延迟约束/statement 触发器 → 事务+提交前校验（🔧 实测口径）；
- PG 类引擎的 DEFERRABLE 约束可声明化（⚠️ 本机无 PG，转述）；
- 汇总可重演的工程形态=物化视图/增量聚合（见下节演进）；
- 无论引擎：**"不改历史行"是逻辑层铁律**。

## 过账规则三例（规则即数据的样表，转述示意）

| 业务事件（触发事实） | 规则行：借 | 规则行：贷 | 派生分录 |
|---|---|---|---|
| 收货（Delivery 入库，04 章） | 原材料库存 | 应付-在途 | JE + 2 Posting |
| 领料（Activity 消耗，04 章） | 生产成本 | 原材料库存 | JE + 2 Posting |
| 折旧桶到期（Period 事件） | 成本-制造费用 | 累计折旧 | JE + N Posting（按资产簇） |

要点：规则行本身是**类型层实体**（带生效区间），新增业务事件=插规则，不改代码——7.1 "规则表"的直观形态；样表数值仅为转述示意，非实测。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
|---|---|---|
| 科目 | Account | 价值分类节点，递归树 |
| 分录头 | Journal Entry | 一次记账事件的头（时间/凭证） |
| 过账行 | Posting | 分录中科目×方向×金额的行 |
| 复式恒等 | Double-Entry Balance | Σ借=Σ贷的跨行不变式 |
| 过账规则 | Posting Rules | 业务事件→分录模板，规则即数据 |
| 汇总 | Summarization | 科目层级×期间的派生余额 |
| 可重演 | Re-computable | 汇总必由明细推导，禁止手填 |
| 样本 | Sample | 受检部分，取样是活动 |
| 检验 | Test | 检验规程的一次执行（工单子型） |
| 观测 | Observation | 被记录的读数，判定另设一层 |
| 派生观测 | Derived Observation | 回链父观测与公式版本的计算值 |

## 最新演进与工业实践

- **账本→事件溯源**：双分录"只追加、冲销不修改"与 Event Sourcing/CQRS 的日志范式同构，现代财务中台（含开源账务引擎）普遍采用（⚠️ 方向性转述）；
- **实时汇总层**：物化视图/流式增量聚合（增量计算框架、数仓 MV 刷新）替代手工余额表，正是 7.2"可重演汇总"的工程化（⚠️ 未逐家实测）；
- **实验室信息学**：CDISC（临床试验数据标准，✅ https://www.cdisc.org 验证 200，2026-09-27）把 Sample-Test-Observation 三元组标准化为 ODM/SDTM 结构；LIMS 开源实现（SELAB、Senaite，⚠️ 未逐一验链）仍按该三元组建模，Hay 模式在 2024–2026 的 QC 数字化中持续在线；
- **SQLite 侧**：3.45.3 仍无 statement 级触发器与 DEFERRABLE 约束（🔧 本演示实测口径），跨行不变式首选"事务+提交前校验"或应用框架钩子。
