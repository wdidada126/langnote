# 08 · 数据字典、权限清单与工具语法速查（⚠️ 主题重构章）

> 本章按出版社文案参考单元"the SQL statements commonly used by DBAs, the data dictionary tables, the system privileges and roles, and the SQL*Plus, Export, Import, and SQL*Loader syntax"与"resource summary"重构。小节划分本目录自拟（[00-总览与阅读地图.md](00-总览与阅读地图.md) §二）；Oracle 行为 ⚠️ 文档转述；🔧G6 为 SQLite/DuckDB 字典类比实验、**非本书引擎行为**。

## 8.1 数据字典三层塔（⚠️）

```
X$  内核固定表（内存结构，裸真相）          ← 只有 SYS 可直查，文档不承诺
 └─ V$  动态性能视图（实例运行态快照）       ← 07 章 V$PARAMETER、06 章 V$SESSION 都在这层
     └─ DBA_/ALL_/USER_ 静态字典视图（持久对象元数据）← 本章主场
          前缀语义：DBA_=全库 | ALL_=我可见 | USER_=我名下（授权视角的三格抽屉，
          安全解读在 [../Oracle_Security/04-数据字典视图与虚拟关系.md](../Oracle_Security/04-数据字典视图与虚拟关系.md)）
```

- 自描述入口：`DICT`（可查字典表清单+说明）与 `DICT_COLUMNS`——本书"字典章"的第一页就是教你用 `DICT` 查 `DICT`，递归自指的入门仪式；
- 存储大户三连：`DBA_SEGMENTS`→`DBA_EXTENTS`→`DBA_FREE_SPACE`（02 章空间问题的三把钥匙）；
- 依赖与失效：`DBA_DEPENDENCIES`/`DBA_OBJECTS.STATUS='INVALID'`+`@?/rdbms/admin/utlrp.sql` 重编译（9i 起流行，8.0 时代手工 ALTER ... COMPILE）。

## 8.2 DBA 常用 SQL 语句卡（⚠️ 复刻本书"常用语句"单元）

| 任务 | 语句骨架 |
|---|---|
| 用户/会话清点 | `SELECT username,status FROM DBA_USERS;` `SELECT sid,serial# FROM V$SESSION;` |
| 杀会话 | `ALTER SYSTEM KILL SESSION 'sid,serial#' [IMMEDIATE];` |
| 表空间体检 | `SELECT tablespace_name,bytes/1048576 FROM DBA_DATA_FILES;` + `DBA_FREE_SPACE` 对账 |
| 对象重建空间 | `ALTER TABLE t MOVE TABLESPACE newts;`（8i 起在线 MOVE 尚属幻想，需锁表） |
| 索引维护 | `ALTER INDEX i REBUILD [TABLESPACE ts] [PARALLEL];` |
| 统计收集 | `ANALYZE TABLE t COMPUTE STATISTICS;`（8.0 姿势；`DBMS_STATS` 属 8.1.x） |
| 追踪开关 | `ALTER SESSION SET SQL_TRACE=TRUE;`（6.2 三件套的会话侧） |
| 控制文件转储 | `ALTER DATABASE BACKUP CONTROLFILE TO TRACE [RESETLOGS];`（03 章剧本的取材） |

## 8.3 系统权限与角色清单的读法（⚠️）

本书参考单元收录 8.0 全量系统权限表（数百条）与预定义角色成员表——速查书的硬核页。读法三条（本目录归纳）：
1. `DBA_SYS_PRIVS`/`ROLE_SYS_PRIVS`/`ROLE_ROLE_PRIVS` 三视图=权限/角色/角色套角色三层账，`CONNECT BY` 递归展开角色树是当时面试手艺；
2. 权限名构词法：`CREATE ANY TABLE`/`ALTER ANY INDEX`/`DROP ROLLBACK SEGMENT`——动词×对象×ANY 的矩阵，背矩阵不背清单；
3. `SYSTEM_PRIVILEGE_MAP`：把权限编码成负数（审计记录里的 `action#` 反查表）——5.4 审计流水的字典钥匙。

## 8.4 工具语法四联卡（⚠️）

**SQL*Plus**（DBA 的瑞士军刀，命令不带分号、以 `;` 结尾的是 SQL）：
`SET LINESIZE/PAUSE/FEEDBACK`、`SPOOL out.log`、`DEFINE &1`、`WHENEVER SQLERROR EXIT`、`@脚本`——批处理骨架；`SET AUTOTRACE`（6.2）、`COPY FROM`（跨库搬表，DBLINK 之前的穷人方案）。

**Export/Import**（03 章逻辑备份的语法面）：
`exp userid=file= full|owner=(a,b)|tables=(t1,t2) rows=y buffer= commit=n file/ log/`；
`imp userid=file= full|fromuser= touser= ignore=y show=y commit=y`——`ignore=y` 在"先建表后灌数"流程里的必要性、`show=y` 的只读侦察用法，是当年恢复剧本的高频两行。

**SQL*Loader**（装载三件套：控制文件+数据文件+bad/disc 文件）：
```
LOAD DATA INFILE 'x.dat' INTO TABLE t
  FIELDS TERMINATED BY ',' (col1 POSITION(1:10), col2)
```
直接路径 `direct=true`（跳 SQL 层直写块——02 章高水位联动）与常规路径之别、`bad` 拒载行/`disc` 预过滤行的文件语义，今天 Data Pump/外部表仍在用同一套词汇。

## 8.5.1 字典域五连查卡（⚠️ 本目录自拟，复刻"字典表速查"单元）

| 体检项 | 查询入口 | 异常信号 |
|---|---|---|
| 对象健康 | `DBA_OBJECTS WHERE STATUS!='VALID'` | 失效堆积=上游 DDL 未重编译 |
| 空间趋势 | `DBA_SEGMENTS` 按日快照差分 | 单段日增>阈值=作业失控候选 |
| 统计新鲜 | `DBA_TABLES.LAST_ANALYZED` | NULL 或月级陈旧=6.1 CHOOSE 漂移温床 |
| 授权蔓延 | `DBA_SYS_PRIVS WHERE GRANTEE='PUBLIC'` | ANY 类条目=5.2 雷区现形 |
| 审计水位 | `SELECT COUNT(*) FROM SYS.AUD$`（或 DBA_AUDIT_TRAIL） | 只增不清=SYSTEM 表空间慢性膨胀（5.4） |

五连查的输出全部是**普通 SELECT**——这就是 8.6 🔧G6 所说的"字典让治理可 SQL 化"：Oracle 把监控面做成可 JOIN 的关系，DBA 脚本因此可组合；SQLite/DuckDB 的元数据面太薄，撑不起这种体检单（非本书引擎行为的反向对照）。

## 8.6 🔧G6 实验：字典的三种密度（非本书引擎行为）

```
G6 sqlite_master: [('table','big','big'), ('index','ix_big','big'), ('table','t1','t1')]
G6 duckdb info_schema: [('main','e')]
G6 duckdb columns sample: [('i','INTEGER')]
```

（SQLite 3.45.3 / DuckDB 1.5.5。）三点对照（均**非本书引擎行为**）：
1. SQLite 的字典=`sqlite_master` 一张表（type/name/tbl_name/sql 四列，存 DDL 原文）——Oracle 字典是**数百张视图的关系网**（元数据被规范化成可 JOIN 的结构），DuckDB 走 SQL 标准 `information_schema` 中间路线；字典密度≈产品需要的治理面宽度；
2. `sqlite_master` 里索引与表平铺同层（`ix_big` 的 tbl_name 指回 big）≈ Oracle `USER_OBJECTS` 的 OBJECT_TYPE 列思维——"对象目录"的最小可行形态；
3. Oracle 字典独有而两实验库皆无的：**运行态层（V$）**——SQLite/DuckDB 无实例常驻态可观测，`PRAGMA` 的少量运行态（journal_mode）不构成层——8.1 三层塔在嵌入式世界塌成一层，这正是"DBA 这个职业为什么存在"的字典学答案。

## 最新演进与工业实践

- **字典扩张与命名遗产**（⚠️）：`DBA_*` 视图族持续扩张（`DBA_HIST_*` AWR 层 10g 起、统一审计视图 12c 起），三层塔变四层；`DICT` 仍可查（✅ SQL 参考主干实抓 200：https://docs.oracle.com/en/database/oracle/oracle-database/23/refrn/ ，经重定向至 /26/refrn/）。
- **工具链换代**（⚠️）：exp/imp→Data Pump（10g，服务器端作业/并行/网络导出）；SQL*Loader→外部表与 Data Pump 外表访问分担大批量装载（SQL*Loader 本体语法遗产仍在装载脚本存活）；SQL*Plus→SQLcl（Java 新 CLI，脚本语法兼容）——✅ SQL*Plus/SQLcl 手册实抓 200：https://docs.oracle.com/en/database/oracle/oracle-database/23/sqpug/ 。
- **元数据治理**（⚠️ 通说）：字典的现代角色从"DBA 查询面板"扩展为血缘/编目系统的原料（`DBA_DEPENDENCIES`→自动化影响分析）；information_schema 标准化让跨库元数据工具（如 DataHub）用同一 API 面吃 Oracle/DuckDB——8.6 的"字典密度"差异正在被治理层中间件抹平。
- **工业实践**（⚠️ 通说）：生产库巡检脚本的骨架仍是 8.2 卡的变体（会话/空间/失效对象/统计新鲜度四模块）；"先查字典再动手"的 DBA 反射，是速查书体裁留给职业文化的最深刻痕。
- **类比锚点**（🔧G6，非本书引擎行为）：sqlite_master/information_schema/Oracle 字典的三级密度对照，量化了"可治理性"这一抽象概念——字典越像关系网，越能被 SQL 本身治理。
