## 5.1 认证：连进来的第一道门（⚠️）

Oracle7/8 的登录路径速查：

| 路径 | 凭据存放 | 典型场景 |
|---|---|---|
| 字典口令 | `SYS.USER$`（8.0 口令哈希可逆性弱、DES 混淆） | 应用账户主流 |
| OS 认证 | `OPS$USER` 模式+`OS_AUTHENT_PREFIX`/`REMOTE_OS_AUTHENT` | 单机批处理、NT 域 |
| 口令文件 | `orapw<SID>` | 远程 SYSDBA/SYSOPER（01 章装机必做第 4 件） |
| 网络层 | SQL*Net 加密/认证（ASO 选件，收费） | 8i 时代的"零信任"预算题 |

`CONNECT scott/tiger`、`CONNECT / AS SYSDBA`、`CONNECT sys/change_on_install`——默认口令未改是本书"装机后 1 小时必做清单"第一条的候选（⚠️ 通说），也是 #61 册审计检查单的头号红牌。

## 5.2 授权三层：系统权限/对象权限/角色（⚠️）

```
系统权限: CREATE SESSION / CREATE TABLE / DROP ANY TABLE ...（GRANT ... [WITH ADMIN OPTION]）
对象权限: SELECT/INSERT/UPDATE/DELETE/EXECUTE ON 某对象（GRANT ... [WITH GRANT OPTION]）
角色:     CREATE ROLE r [IDENTIFIED BY/WAYS/CERTIFICATE]；CONNECT/RESOURCE/DBA 预定义
PUBLIC:   隐式全员角色——给 PUBLIC 的授权=给所有未来账户（速查书反复敲打的坑）
```

ADMIN OPTION 与 GRANT OPTION 的差别（回收是否级联）是 08 章语法速查的姊妹条目。`ANY` 家族权限（SELECT ANY TABLE 等）是"省事的灾难"——与 #61 册 03 章同一措辞，两册在盘后此话题构成互证。

## 5.3 资源概要文件与配额（⚠️）

Oracle8 的 `CREATE PROFILE` 管两件事：
- 资源：`SESSIONS_PER_USER`、`CPU_PER_SESSION`、`PRIVATE_SGA`（共享服务器下才有意义——4.5 的联动点）；
- 口令策略（8.1.x 才加入 `FAILED_LOGIN_ATTEMPTS`/`PASSWORD_LIFE_TIME`/`PASSWORD_VERIFY_FUNCTION`，本书成稿停在资源侧——⚠️ 时代注脚：口令复杂度函数时代在本书出版后开启）；
- 表空间配额：`ALTER USER u QUOTA 100M ON ts1`——没有配额的 SYSTEM 表空间滥用是 1999 年容量事故常客（联动 02 章）。

## 5.4 审计：AUDIT 命令与 AUDIT_TRAIL（⚠️）

```
AUDIT TABLE BY access WHENEVER NOT SUCCESSFUL;      -- 语句审计
AUDIT DELETE ON scott.emp;                           -- 权限/对象审计
NOAUDIT ...;                                         -- 关闸
SELECT * FROM DBA_AUDIT_TRAIL;                       -- 去向：SYS.AUD$（字典表本体）
```

- 出厂默认 `AUDIT_TRAIL=NONE`——"出厂失明"（#61 册 05 章同词，两册互证）；
- `AUDIT_TRAIL=OS` 的动机：防 DBA 改库内账本——审计独立性问题的 1999 年解法；
- `AUDIT SYSDBA` 类操作默认不留痕（口令文件路径绕过字典审计）——本书时代已知盲区（⚠️ 通说）；
- 清理纪律：`SYS.AUD$` 无人清理撑爆 SYSTEM 表空间是速查书标准事故条目。

## 5.5 监控：V$ 视图的 DBA 面板（⚠️）

| 面板 | 视图 | 一眼看什么 |
|---|---|---|
| 会话 | `V$SESSION` | 谁在连、等什么（`WAIT_CLASS` 前身列）、什么机器 |
| 锁 | `V$LOCK` | `BLOCK=1` 的头锁会话（阻塞链起点） |
| 长事务 | `V$TRANSACTION`/`V$ROLLSTAT` | 未提交事务挂住的 undo |
| 缓存 | `V$SYSSTAT`/`V$SESSTAT` | 命中率类统计的原始流水（06 章主场） |
| 资源 | `V$RESOURCE_LIMIT`（8i 起） | 会话/锁/时间模型峰值 |

监控与 06 章调优共用同一批视图，差别在问题："有人在干什么"（安全）vs"库为什么慢"（性能）——速查书把两章视图清单分开印，正是本书"同一对象、两个抽屉"的编排术。

## 5.6 🔧G4 实验：authorizer 回调——"库内没有用户"的对照实验（非本书引擎行为）

SQLite 无库内用户/权限体系；其"授权"是宿主注入的回调：

```python
def deny(action, a1, a2, dbn, trigger):
    return sqlite3.SQLITE_DENY if action in (sqlite3.SQLITE_DROP_TABLE,
                                             sqlite3.SQLITE_ATTACH) else sqlite3.SQLITE_OK
c.set_authorizer(deny)
```

实测（Python 3.13.2 + SQLite 3.45.3）：

```
G4 drop denied: not authorized
G4 attach denied: not authorized
G4 select still ok: (1,)
```

三点对照（均**非本书引擎行为**）：
1. SQLite 的 DENY 发生在**每次语句解析时**、由宿主代码决定——Oracle 的权限检查发生在库内安全模型中（字典里的授权记录），换宿主程序也照样拦：授权账本在库内 vs 在库外，是嵌入式与多租户服务器的结构分岔；
2. `attach` 被拦演示"连接层能力也能被授权面裁剪"——Oracle 无 ATTACH 对应物，最接近的是 04 章 `SQL.EXCLUDE` 进程门：都在"能力入口"设闸；
3. "select still ok"证明 authorizer 是语句级细闸而非连接级封禁——近似 Oracle 对象权限粒度，但没有任何持久化与审计联动（SQLite 侧无 AUDIT 对应物，审计要靠 `set_trace_callback`，#61 册 G3 已做）。

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| 系统权限 | system privilege | 干某类事的权利（CREATE TABLE），ANY 家族为雷区 |
| 对象权限 | object privilege | 对具体对象的 SELECT/EXECUTE 等 |
| 角色 | role | 权限打包+可激活开关，CONNECT/RESOURCE 为遗产 |
| 全员角色 | PUBLIC | 隐式授予所有账户的抽屉，宽授权事故源 |
| 管理选项 | WITH ADMIN OPTION | 转授系统权限的标记，回收不级联（对 GRANT OPTION） |
| 概要文件 | profile | 资源限制+（8.1.x 起）口令策略载体 |
| 语句/对象审计 | statement / object auditing | AUDIT 的两类靶 |
| 审计轨迹 | audit trail (SYS.AUD$ / OS 文件) | 库内账本 vs 库外账本，防 DBA 篡改之争 |
| 出厂失明 | AUDIT_TRAIL=NONE 默认 | 未配置=未审计的合规表述 |
| 会话监视 | V$SESSION/V$LOCK | "谁在干什么"的实时面板 |

## 最新演进与工业实践

- **口令与认证现代化**（⚠️）：11g 口令哈希改 SHA-1（10g 的 DES 哈希离线爆破工具链正是本书时代欠账）、12c 大小写敏感默认翻转、案例式认证（Kerberos/RADIUS/PAM）在 8i 起步、今天接 OIDC/OCI Vault；SYSDBA 审计盲区由统一审计+口令文件独立审计（12.2 起 `Audit sys operations`）补上。
- **审计体系换代**（⚠️）：12c Unified Auditing（策略化、`UNIFIED_AUDIT_TRAIL`）合并语句/权限/对象/FGA/监听器/OS 账本；FGA（9i `DBMS_FGA`）作为本书后一代的条件审计在 12c 并入统一策略——5.4 整节语法进入考古区。✅ 现行安全指南 slug `dbsec` 在 /23/→/26/ 重定向下实抓 404（⚠️ 已登记，2026-10-02），以 https://docs.oracle.com/en/database/oracle/oracle-database/23/ 首页检索 "Security" 为准。
- **最小权限工程化**（⚠️ 通说）：12c 起 DBA 角色拆分（SYSDBA/SYSOPER/SYSBACKUP/SYSKM）、预定义角色瘦身（CONNECT 只剩 CREATE SESSION 的清算在 11g 后完成）——5.2 的 ANY/PUBLIC 坑今天以"权限分析器+数据库 Vault  Realm"工具化防守。
- **工业实践**（⚠️ 通说）：CISO 检查单（默认账户锁定、口令策略、审计开启且外发 SIEM、PUBLIC 权限基线比对）逐条都能回放到本章 5.1-5.4——1999 年速查清单是当代合规基线（CIS Benchmark 等）的骨架原型。
- **类比锚点**（🔧G4，非本书引擎行为）：authorizer 实验证明"权限可以完全在引擎外实现"——反过来凸显 Oracle 模型的本质选择：安全状态是**库内持久数据**（可复制、可审计、跨工具一致），这是共享服务器数据库与嵌入式库的根本身份差。
