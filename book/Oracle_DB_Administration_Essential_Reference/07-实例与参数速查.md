# 07 · 实例与 INIT.ORA 参数速查（⚠️ 主题重构章）

> 本章按出版社文案参考单元"quick reference to the Oracle instance and database, the initialization (INIT.ORA) parameters"重构，是全书"参考抽屉"的心脏。小节划分本目录自拟（[00-总览与阅读地图.md](00-总览与阅读地图.md) §二）；Oracle 行为 ⚠️ 文档转述；🔧G1 为 SQLite/DuckDB 参数体系类比实验、**非本书引擎行为**。

## 7.1 实例解剖一页纸（⚠️）

```
实例 = SGA + 后台进程组（+ 服务器进程组属于会话，严格说不属实例本体）
SGA：  共享池(library/data dictionary cache) | 缓冲区缓存(buffer cache)
        | 重做日志缓冲(log buffer) | 大池/Java池(8i 起)
进程： DBWR(写脏块) LGWR(提交即写日志) SMON(实例恢复/清理) PMON(进程清理/注册)
        CKPT(检查点) ARCH(归档) RECO(分布式回滚) [MTS: dispatcher/QS](8.0)
```

记忆锚（本书体裁）：**LGWR 管承诺（提交）、DBWR 管家务（脏块）**——两者解耦是 WAL 家族的通用设计，🔧G1 对照实验里 DuckDB 的 `wal_autocheckpoint` 参数就是同一分工的嵌入式回声（非本书引擎行为）。

## 7.2 参数文件的物理性（⚠️）

- 位置：`$ORACLE_HOME/dbs/init<SID>.ora`（UNIX）/ `ORACLE_HOME\database\init<SID>.ora`（NT）——01 章目录地形的复用；
- 加载顺序：`spfile<SID>.ora → spfile.ora → init<SID>.ora`（9i 后话；8.0 只有 pfile 一档）；
- 多实例一台机：靠文件名里的 SID 区分，`ORACLE_SID` 环境变量选号（1.5 联动）；
- 改参数工作流（8.0）：`ALTER SYSTEM SET x=y SCOPE=MEMORY`（内存态试值，重启即忘）或编辑 pfile 后重启——`SCOPE` 三态里 SPFILE 档在本书时代不存在（⚠️ 时代注脚）。

## 7.3 参数家族速查卡（⚠️ 本目录自拟骨架，复刻本书编排）

| 家族 | 代表参数 | 一句话语义 | 联动 |
|---|---|---|---|
| 标识 | `db_name`、`instance_name`(8.0 新)、`db_domain`、`service_names` | 谁是谁：库名/实例名/域/服务 | 04 章 GLOBAL_DBNAME |
| 内存 | `db_block_size`、`db_block_buffers`、`shared_pool_size`、`sort_area_size`、`log_buffer` | SGA/PGA 各池配额（8.0 手工时代，无 SGA_TARGET） | 02 章块、06 章排序 |

| 持久性 | `control_files`、`db_files`、`log_checkpoint_*`、`fast_start_io_target`(8.0)、`log_archive_*` | 检查点节奏与归档去向 | 03 章恢复剧本 |
| 优化器 | `optimizer_mode`(RULE/CHOOSE/COST)、`sort_area_retained_size`、`hash_multiblock_io_count` | 6.1 双轨制的开关位 | 06 章 |

阅读法：速查书对每个参数给"类型（静态/动态）、默认值、平台相关性、与谁联动"四列——本卡是其压缩影子；参数四列法本身是 2026 年读任何数据库配置手册的通用姿势。

## 7.4 动态 vs 静态与"改错了怎么办"（⚠️）

- 动态参数：`ALTER SYSTEM` 即生效（多数带 `DEFERRED` 语义的例外）；静态参数：只能改文件重启——速查表用一列 `Dynamic?` 标注，本书最被翻烂的一页；
- 事故剧本：改错 pfile 起不来 → `STARTUP PFILE='/u01/app/init.good.ora'` 引导回滚版——"每次改前先 cp 一份带日期的 pfile"是 1999 与 2026 通用的纪律（今天叫配置管理）；
- `V$PARAMETER`/`V$SYSTEM_PARAMETER`：内存态 vs 文件态对照，`ISDEFAULT` 列揪出"没写进文件但生效"的漂移。

## 7.5 8.0 时代 SGA 手工配比速算（⚠️ 本目录自拟，复刻本书参数章的计算卡）

共享内存三段式的 1999 年算法（`sga_max_size`/`SGA_TARGET` 都不存在的世界里）：

```
SGA ≈ shared_pool_size
    + db_block_buffers × db_block_size
    + log_buffer
    + (固定开销：按 processes/sessions/open_cursors 派生，平台相关)
```

| 步骤 | 动作 | 判据/视图 |
|---|---|---|
| 1 定块 | `db_block_size` 建库定死，OLTP 小块/数仓大块 | 02 章 2.5（多块缓存属 9i） |
| 2 试缓冲 | `db_block_buffers` 逐步上调 | `V$SYSSTAT` 逻辑读/物理读比趋稳 |
| 3 试共享池 | `shared_pool_size`：字面量 SQL 多的库要异常大 | 6.5 绑定变量改写可反向省此处 |
| 4 留余量 | OS 与其他进程（PGA×会话数）不吃穿物理内存 | `sessions×sort_area_size` 最坏和 |
| 5 固化 | 改 pfile 重启验证（7.4 工作流） | `V$SGA` 组件清单对账 |

这张卡的当代价值不是数值（自动内存管理已接管），而是**"内存预算=组件×单位×并发"的乘法表思维**——今天给容器里的数据库配 `memory_limit`（DuckDB 默认 25.0 GiB 的由来，🔧G1 实测输出）用的仍是同一张乘法表（非本书引擎行为）。

## 7.6 🔧G1 实验：参数体系的三种存在论（非本书引擎行为）

同机实测两库的参数面（SQLite 3.45.3 / DuckDB 1.5.5，Python 3.13.2）：

```
G1 duckdb_settings count: 160
G1 sample: [('memory_limit','25.0 GiB'), ('threads','16'), ('wal_autocheckpoint','16.0 MiB')]
G1 sqlite pragmas: journal_mode=('memory',) page_size=(4096,) cache_size=(-2000,)
G1 sqlite compile opts sample: ['ATOMIC_INTRINSICS=0', 'COMPILER=msvc-1942', 'DEFAULT_AUTOVACUUM']
```

三点对照（均**非本书引擎行为**）：
1. **可查询性**：DuckDB 把 160 个参数做成一张可 SELECT 的表（`duckdb_settings()`）≈ Oracle `V$PARAMETER`；SQLite 用 `PRAGMA xxx` 逐问逐答 ≈ 8.0 时代 `SHOW PARAMETER` 之前的朴素；
2. **生命周期**：SQLite 编译期选项（`pragma_compile_options`）=不可改的"参数"，对应 Oracle 里 `db_block_size` 这类建库定死项——三种引擎各自划了不同的"可改边界"，边界位置就是产品哲学的 X 光片；
3. `cache_size=-2000`（负数=KB 语义）与 Oracle `db_block_buffers`（单位=块数）的**单位陷阱**跨引擎复现：7.3 速查卡"单位"列的存在理由——参数速查的第一价值不是值本身，是把单位钉死。

## 7.8 章前自测与本章边界

- 自测三题：①提交时先落盘的日志是谁写的、脏块延后写是谁负责的？（LGWR/DBWR，7.1 记忆锚）②`ALTER SYSTEM SET ... SCOPE=MEMORY` 之后重启，值还在吗？（8.0 不在——pfile 才是持久态；9i 后才有 SPFILE 档）③实例起不来、报错指向参数文件，第一动作是什么？（7.4：带日期备份的 pfile 引导回滚）。
- 本章边界：参数如何影响性能在 06 章（优化器族）、影响安全在 05 章（认证族）、影响备份在 03 章（归档/检查点族）——本章只回答"参数本身是什么、在哪、能不能热改"。
- 🔧G1 的边界声明：实验只对照"参数体系的可查询性/生命周期/单位"三个横断面，不涉及 Oracle 自动内存管理行为——后者全部 ⚠️ 文档转述。
- 与 #74 册分工：同一 SGA 对象，Adams 从闩锁与等待切入解剖运行时，本章从配置面切入登记配额（00 §4.2）。
- 证据锚点：`SCOPE` 三态与 SPFILE 为 9i 引入（⚠️）；11g 存档参考手册 https://docs.oracle.com/cd/E11882_01/server.112/e41084/toc.htm（00 §六实抓 200 ✅）可回查 11.2 参数四列原文——7.3 卡里每个"联动"都可在该手册参数条目找到交叉引用，读者复放路径明确。
- 一句话收束：参数速查的终点不是背下参数，而是建立"标识/内存/并发/持久/优化/安全/诊断"七个抽屉的分类直觉——换任何数据库产品，抽屉名都可以复用，只是里面的条目要重新领一遍。
- 阅读提醒：7.5 速算卡的数值步骤在自动内存管理时代已无操作必要，但作为"内存预算乘法表"的思维训练仍建议手推一遍（对照 🔧G1 的 DuckDB memory_limit 默认值即其当代回声）。
- 判卷标准：能不看表说出 7.3 七个家族名、并各举一个代表参数，即达到本书对"参数速查"一章设定的及格线（⚠️ 及格线为本目录自拟，非原书断言）。

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| 实例 | instance | SGA+后台进程；库=磁盘文件，实例=内存+进程 |
| 参数文件 | INIT.ORA / pfile | 8.0 唯一形态，文本、按 SID 命名 |
| 服务器参数文件 | SPFILE | 9i 起的库内二进制参数（本书时代不存在） |
| 动态/静态参数 | dynamic / static parameter | ALTER SYSTEM 即效 vs 必须重启 |
| 生效范围 | SCOPE=MEMORY/SPFILE/BOTH | 试值与固化的两档（后两档属 9i 语法） |
| 检查点 | checkpoint | LGWR/DBWR 节奏的同步点，恢复时间旋钮 |
| 转储目的地 | dump_dest 三件套 | 后台/用户/core 三类诊断文件的路标 |
| 内存池 | shared pool / buffer cache / log buffer | SGA 三大件+8i 大池/Java 池 |
| 并发闸门 | processes/sessions/transactions | 三层连接-会话-事务配额 |
| 参数漂移 | ISDEFAULT 差异 | 生效值≠文件值的隐性状态 |

## 最新演进与工业实践

- **自动内存管理三部曲**（⚠️）：9i 自动回滚段、10g `SGA_TARGET`（自动划 SGA）、11g `MEMORY_TARGET`/AMM（SGA+PGA 一把抓）——7.3 内存家族的逐池手调整体退役，但云/大页场景仍推荐 `lock sga`+手工配比，自动参数时代"懂手工"仍是兜底能力。
- **参数即服务**（⚠️）：23ai 文档主干实抓验证（经重定向 200）：管理手册 https://docs.oracle.com/en/database/oracle/oracle-database/23/admin/ 、参考手册（参数/等待事件字典）https://docs.oracle.com/en/database/oracle/oracle-database/23/refrn/ ——7.3 的"四列卡"今天就是 Ref 手册的在线交互版；11g 存档入口 https://docs.oracle.com/cd/E11882_01/server.112/e41084/toc.htm（实抓 200 ✅）仍可查 11.2 参数原文，考古链路完整。
- **可观测参数族扩张**（⚠️）：`control_management_pack_access`（诊断选件的许可证开关，11g 起）——速查书"参数=许可合规"的新维度，1999 年无此负担。
- **工业实践**（⚠️ 通说）：参数治理=配置管理：基线文件进 Git、变更走审批、`V$PARAMETER` 差异巡检自动化；"改错参数起不来"的剧本今天以 SPFILE 备份+PFILE 引导原样上演——工具在变，纪律不变。
- **类比锚点**（🔧G1，非本书引擎行为）：三引擎参数可查询性/可改边界/单位陷阱的对照，是"读配置手册"这项元技能的跨引擎练习场。
