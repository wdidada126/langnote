# 第 8 章 终止检测（Termination Detection，原书 pp.268–306）

> 一句话定位：一个计算已经「事实上全部结束」了，但没有任何单点知道——设计一个**不干扰原计算**的观测者，
> 在正确时刻宣布终止。这是 Spark/Flink「作业何时算完成」的理论原型。

## 核心精讲

（以下伪代码与复杂度表均为**教学示意，不参与构建**。）

### 1. 问题为什么难（8.1）

- **终止定义**：所有进程 passive 且**所有在途消息都已送达并被吸收**。第二条常被初学者漏掉——
  只看「大家都闲着」是不够的，可能还有消息在路上，收到后进程会再次激活。
- 困难性：异步系统没有全局视图，**「此刻无人活动」的判断瞬间就可能失效**（一条消息正在飞行）。
  检测算法必须给出**不误报（安全）且终将报告（活性）**的答案。
- 区分两类任务：**扩散计算**（diffusing computation，由一个 initiator 触发，如 GHS）与**通用计算**。

### 2. 计算树/森林：Dijkstra–Scholten 框架（8.2）

- 思想：让每个被激活的进程在「激活树」里有一个父亲；**消息激活 = 建父子边，回 ack = 断边**；
  initiator 的孩子全部断开后，树空 → 终止。
- **DEF（Dijkstra–Feijen–van Gasteren）版本**：每条消息带计数（信号量式 ack）：
  - 每个进程维护欠账数 `deficit`：发消息 +1，收到 ack −1；
  - 叶子进程 deficit 归零后向父节点发 ack；initiator 的 deficit 归零即**全局终止**。
- 复杂度：每条应用消息恰对应一条 ack——**消息复杂度 O(M)**（M 为计算消息数），无额外消息，代价只是带宽加倍。

```
发送方: send(data); deficit += 1
接收方: 收到 data → 激活自己, 记父亲（首次激活时）
叶子完成: send(ack); deficit -= 1
initiator: deficit == 0 → announce(terminated)
```

### 3. 基于波的检测（8.3 前半）

- 思想：反复跑 [05-波与遍历算法.md](05-波与遍历算法.md) 的波，检查「波期间是否有人活动」；
  若一波期间**没有任何本地计算事件**且无消息越过波前，则终止。
- 需要处理「消息跨越波边界」的竞态——通常给消息涂色/计数（彩虹式或着色波算法），波失败则重试。
- 优点：可与任意波算法组合（KKM 式设计哲学再次出现）；缺点：可能要多跑几轮。

### 4. 信用/权重算法（credit/recovery，Mattern）（8.3 后半）

- 思想：initiator 手持总权重 1；每条消息携带一部分权重传递，进程激活时把权重记账；进程变 passive 时
  把权重**汇总回 initiator**；initiator 累计收回权重 = 1 → 终止。
- 🔧 实现要点：权重是浮点数会耗尽精度，实用版用**计数对（Mattern 的 credit with counters）**代替权重除法。
- 复杂度：O(N + M) 级消息（视实现），且支持**多个 initiator 的森林版**（8.2 的森林结构）。

### 5. 终止谓词的正式定义与两类易混概念

- **全局终止谓词** T：`T ⟺ ∀p: passive(p) ∧ ∀通道 c: empty(c)`。
- 三个易混概念对照：

| 概念 | 含义 | 与终止的关系 |
| --- | --- | --- |
| 静止（quiescence） | 没有任何使能的迁移可发生 | 终止的一种（原书 Ch8 术语「静止检测」） |
| 停止（halt） | 每个进程都进入 final 状态 | 程序语义的终止，检测目标是它 |
| 死锁 | 有使能迁移但形成循环等待 | 「系统没死但不动」——**不是终止**，检测方法不同（见 [09 章] 10.4） |

- 🔧 教学提醒：死锁是「想动不能动」，终止是「无事可做」；用快照看等待图有环的是死锁，
  「全 passive + 全通道空」的才是终止——两者在工程日志里经常被混为一谈。

### 6. DEF 欠账计数的逐步推演（自查用）

进程链 A→B→C（**教学示意，不参与构建**）：

```
A 发 m1 给 B (A.deficit=1)
B 发 m2 给 C (B.deficit=1)
C 完成 → ack 给 B (B.deficit=0)
B 完成 → ack 给 A (A.deficit=0)
A.deficit=0 → announce(终止)     ✓ 此时确无在途消息（每条消息恰一张"欠条"）
```

- 反例核查：若 B 在 m2 在途时就向 A 回 ack（违规），A 会提前宣布终止，随后 m2 到达复活 C——
  说明「ack 必须在**本进程吸收完欠账后**才发」是安全性的全部来源。
- 消息账：每条应用消息恰配一条 ack → O(M)，无额外控制消息；代价是延迟翻倍（ack 关键路径）。

### 7. 信用算法的最小推演

- initiator W=1.0；A 激活自留 0.5、发消息携 0.5；B 收 0.5、自留 0.25、再传 0.25；
  所有进程 passive 后把自留额**汇总回 initiator**：0.5+0.25+…=1.0 → 终止（**教学示意，不参与构建**）。
- 浮点版耗尽精度 → Mattern 计数版：权重改为「消息携带正整数 credit，聚合只加不除」，
  initiator 持目标总数；工程上还有人把 credit 压进消息头的 1 字节计数器（上限即最大传播深度）。
- 与 DEF 对比：credit 版**无需 ack**（不与应用消息一一配对），适合 ack 难以落地的场景（如多播、
  消息可能被合并的流式系统），但 initiator 单点记账是可用性短板 → 森林版把记账分散到多 initiator。

### 8. 检测与快照的关系（一张表说清）

| 维度 | 终止检测（本章） | 快照（[09 章]） |
| --- | --- | --- |
| 目标 | 在线等待谓词**变真**的瞬间 | 拍下某一致瞬间的完整状态 |
| 开销 | 持续少量消息（欠账/credit） | 一次性 O(E) marker |
| 适用谓词 | 稳定谓词（终止、静止） | 任意可读谓词（稳定谓词拍照即可断言未来） |
| 工业形态 | Spark/Flink 的完成汇聚 | Flink checkpoint barrier |

### 9. 多 initiator 的森林版（8.2 后半的实际用法）

- 现实计算常有**多个发起者**（分布式任务提交、多客户端触发）；Dijkstra–Scholten 框架自然推广为
  **计算森林**：每个 initiator 是一棵计算树的根；节点被动化时向**自己所属树的父亲**回 ack；
  **每棵树独立归零**（各 initiator 各自宣布「自己发起的那部分终止」），或加一个全局汇合点等待所有树归零。
- 消息账不变：每条应用消息一张欠条，O(M)。
- 工业对照：Spark 多 job 并发时 DAGScheduler 按 job 各自维护完成计数——就是森林按树归零。

### 10. 着色波（检测的另一种实现）骨架

```
给应用消息标色: 白(波前之前) / 红(波前之后)
波推进时: 进程记录"本波期间是否变红(收到红消息或发生本地事件)"
一波结束无人变红且无红消息未清算 → 终止; 否则重跑一波
```

- 关键技巧：红消息必须**在下一波前被「追认」**（着色波允许有限次重跑），保证不误报。
- 与欠账法取舍：着色波**不要求每条消息配对 ack**（省带宽），代价是可能多跑几轮——
  与 [05 章] 「消息 vs 时间」的权衡一脉相承。

## 近年研究与工业界开源实践（2015–2026）

- **Spark 任务完成检测**（`apache/spark`，44.0k★）：DAGScheduler 的 stage 完成事件沿 driver 树汇聚，
  「所有 child 完成 → parent 完成」正是 Dijkstra–Scholten 计算树的工程实现（外加超时兜底）。
- **Flink**（`apache/flink`，26.4k★）：checkpoint 协调器等待**所有算子**确认 barrier → 作业级终止判断，
  与波的「汇齐再决策」同构。
- **etcd/Lease 与 Kubernetes Job**（`kubernetes/kubernetes`，128.0k★）：Job 完成判定用
  「所有 pod 到 Succeeded」——中心化查询替代分布式检测，因为**检测的观测者本来就是中心化的 driver**，
  这也是 2026 年工业界的主流取舍：能中心化就不做纯分布式检测。
- 🔧 分布式垃圾回收：语言运行时（Erlang 的引用追踪、.NET 的分布式 GC 研究线）仍在用欠账计数思想。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「大家 passive 就是终止」 | 还须**无在途消息**；漏掉第二条会误报，收到迟到的消息后计算复活 |
| 2 | 「检测算法可以随时插一脚」 | 检测必须**不干扰**原计算（不改变其可见行为）；检测消息与应用消息要分开计数 |
| 3 | 「权重用浮点除一半就行」 | 浮点精度耗尽后权重会丢失 → 永远检测不到；工程用计数器版本（Mattern） |
| 4 | 🔧 本书假设**无故障** | 节点崩溃时欠账永远收不回，检测失效；现代系统用超时 + 故障检测者（原书 Ch16，见 [10-同步网络与时间.md](10-同步网络与时间.md)）兜底，或干脆中心化（Spark driver） |
| 5 | 🔧 原书模型中消息必达且有限延迟 | 现实消息系统（Kafka 重试、at-least-once）会产生**重复消息**，欠账计数需配幂等去重，否则 deficit 永不为零 |
