# 第 5 章 无死锁包交换（Deadlock-free Packet Switching，原书 pp.155–178）

> 一句话定位：给「缓冲区资源」建一个**有向无环图**，让包只能沿 DAG 占资源——用秩序消灭循环等待。
> 这是全书中「操作系统死锁理论 → 网络协议」迁移最漂亮的一章。
> 延伸对照：RDMA/InfiniBand 的无损网络、NoC（片上网络）路由都建立在同一理论上。

## 核心精讲

（以下伪代码与图示均为**教学示意，不参与构建**。）

### 1. 死锁如何在网络里发生

- 存储转发网络中，包在每跳要占用**缓冲区**；若一组节点各自持有缓冲区并等待下一个空闲缓冲区，
  形成**循环等待**，即网络死锁——与操作系统死锁的四条件（互斥、持有并等待、不可剥夺、循环等待）逐一对应。
- 经典场景：两个环上相邻节点同时向对方发包，各自占满入口缓冲，互相等待，永不出队。

### 2. 结构化解法：有向无环缓冲图（5.2，DAGcb）

- 核心构造（Gunther 1981 的形式化）：把**缓冲区**（而非包）排成偏序，为每条通道的缓冲区分配等级，
  保证「包从缓冲区 b 移到下一跳缓冲区 b'」时**等级严格递增**——于是资源等待图天然无环，死锁不可能。
- 结论：**只要每个通道至少有一个「可达顶层」的缓冲区，网络就不会死锁**；寻找这样一个缓冲区分配 =
  给每条通道找一个**环律（cycle-free）等级函数**。
- 特例（后来成为行业标准）：
  - **虚拟通道分层**：同一条物理链路切出多条虚拟通道（VC），按 VC 等级排序即可打破循环等待；
  - **dimension-order routing**（Dally–Seitz 1987）：在 mesh/torus 上规定先走 x 再走 y，
    通道等级按维度递增——天然满足 DAG 条件，这是 wormhole 路由器（InfiniBand/NoC）的标准答案。

### 3. 非结构化解法（5.3）

- 不做全局等级设计，而是：检测死锁（超时）→ **牺牲/回退**（丢包或绕行）。代价是 packets 可能被丢弃，
  依赖上层（Ch3 的滑动窗口！）重传——**「有损 + 重传」与「无损 + 死锁避免」是一对架构分岔**。
- 🔧 原书的洞察（2026 年依然成立）：因特网选择了「有损 + 端到端重传」，
  数据中心互连（RDMA/IB、部分 RoCE 配置）选择了「无损 + 基于信用/缓冲图」——两条路线都是本章的方案。

### 4. 正确性证明的结构

- 证明模板 = 反证法：假设死锁发生 → 存在包集合互相等待 → 沿缓冲图构造严格递增等级链 → 与有界矛盾。
  这是 Ch2 不变量法的又一次应用（「无死锁」是安全性质）。

### 5. 操作系统死锁四条件 → 网络方案的映射表

| 死锁必要条件 | 网络中的形态 | 本章方案的破坏点 |
| --- | --- | --- |
| 互斥 | 缓冲区一次只装一个包 | 不破坏（资源本性如此） |
| 持有并等待 | 包占本跳缓冲、等下一跳缓冲 | **破坏**：等级递增使「等待」只能向上，无回头路 |
| 不可剥夺 | 包不能被中途踢出缓冲 | 非结构化解法破坏它（丢弃/回退） |
| 循环等待 | 节点环互相等缓冲 | **破坏**：DAGcb 使资源图无环 |

- 教学要点：结构化解法（5.2）同时破坏「持有并等待」与「循环等待」；非结构化解法（5.3）破坏「不可剥夺」。
  这张表可直接迁移回操作系统的死锁预防（[../数据库系统概念6/15-并发控制.md](../数据库系统概念6/15-并发控制.md) 的死锁预防节同构）。

### 6. DAGcb 的最小构造示例

- 目标：让 2×2 网格（4 节点）无死锁。用**维度序**：东西向通道等级 1、南北向通道等级 2；
  每条通道 2 个缓冲：低级 b1、高级 b2。
- 检验：任何包的路径形如「先东西后南北」，缓冲等级序列单调不减且每跳至少持平——
  「等待下一缓冲」永远发生在等级 ≥ 当前的资源上 → 等待图无环 → 无死锁（**教学示意，不参与构建**）。
- 若允许「先南北后东西」的自由选择，则存在等级回跳的环 → 必须再加 VC 层（等级 3、4）才能恢复 DAG 条件——
  这就是自适应路由需要更多虚拟通道的原因（Duato 理论的直觉版）。

### 7. 存储转发 vs wormhole/cut-through：死锁形态的差异

| 维度 | 存储转发（原书主模型） | wormhole / cut-through |
| --- | --- | --- |
| 缓冲粒度 | 整包 | flit（流片），包切条占用多跳 |
| 死锁对象 | 逐跳整包缓冲 | 跨多跳被同一包的 flit 链占住 |
| 分析工具 | 缓冲等级函数 | **通道依赖图**（Dally–Seitz）：通道为节点、占用依赖为边，要求无环 |
| 解法 | DAGcb | VC 分层 + 维度序/escape 通道 |

- 🔧 读原书时注意：5.2 的等级函数在 wormhole 下要「逐通道」而非「逐缓冲」论证；
  原书只作为扩展提示，深入以 Dally–Seitz 1987 为准。

### 8. escape 通道（Duato）的直觉

- 允许包自由选择「自适应通道」（可能形成依赖环），但**每对源目都保留一条无环的逃生通道**；
  死锁边缘时包可退回 escape 通道走完全程。现代 NoC/RDMA 网卡的路由表普遍是
  「自适应子网 + 确定性逃生路」的二元结构——比「全网严格排序」换取了自适应性与更低平均延迟。

### 9. 「有损」与「无损」两条路线的现代对峙（架构视角）

| 维度 | 因特网路线（有损 + 重传） | 数据中心互连路线（无损 + 结构防死锁） |
| --- | --- | --- |
| 拥塞应对 | 丢包/ECN 信号 → 端点降速 | PFC 不丢帧 → 依赖显式流控 |
| 死锁策略 | 允许死锁瞬态（重传兜底） | 必须结构性排除（本章 5.2） |
| 典型技术 | TCP/QUIC + BBR | InfiniBand、RoCEv2 + PFC/ECN + 信用 |
| 风险 | 队尾阻塞小、延迟抖动大 | **PFC 死锁**（流控环互相停水）、HOL 阻塞放大 |

- 🔧 RoCE 部署事故高发点恰是「PFC 打开了无损、却忘了 5.2 的等级论证」——跨优先级依赖仍可能成环。
  工业实践（各类数据中心网络论文与厂商部署指南，非同行评审为主）：优先级隔离 + 跳数上限 + 拓扑内单调性三件套，
  正是把本章「等级函数」手工补回配置里。

### 10. 缓冲图论证模板的通用化

- 本章证明套路可以抽成模板：**资源有偏序 + 获取只沿偏序上行 ⟹ 等待图无环**。
  复用清单：
  1. 锁的排序加锁（数据库死锁预防，[../数据库系统概念6/15-并发控制.md](../数据库系统概念6/15-并发控制.md)）；
  2. 文件锁/分布式锁按 key 排序获取；
  3. 多资源事务（2PC 锁序）；
  4. 部署变更顺序（先扩后缩、按依赖图推进）。
- 看到任何「按固定顺序拿资源」的守则，背后都是本章这条定理。

### 11. 环上死锁的最小推演（自查用）

- 节点 0、1 相向发包（**教学示意，不参与构建**）：
  ```
  0→1 的包占满 1 的入口缓冲; 1→0 的包占满 0 的入口缓冲
  ⇒ 两包各自等待对方入口腾出空位 ⇒ 循环等待成立, 无外部事件可打破
  ```
- 用等级函数修复：给「右行通道」等级 1、「左行通道」等级 2，并规定包只能**先右行后左行**
  （或加一条等级 0 的绕行 VC）；等待序列 1→2 单调 → 无环 → 死锁不可能。
- 与原书 5.2 的关系：这就是 DAGcb 在 2 节点上的退化版；维度序路由是它在网格上的推广
  （「先 x 后 y」=「先右后左」的多维版）。

- **RDMA 无损网络的死锁再回归**：RoCEv2 跑在以太网上后，PFC（优先级流控）造成的**头部阻塞与 PFC 死锁**
  成为数据中心热门问题（各类 SIGCOMM/NSDI 论文，如 HPCC、NSDI 2019《Understanding and Mitigating Hardware Glitches》一类工作——同行评审，具体篇目按需检索）。
- **P4 可编程交换机**（`p4lang/p4c`，839★）：缓冲管理逻辑首次可编程，「5.2 的等级函数」可写成数据面程序。

  工业界事实上的立场是「等级函数 + 拥塞控制 + 有损兜底」三者并用，而非任选其一。
- 🔧 死锁检测的算法层（终止检测、快照）见 [07-终止检测.md](07-终止检测.md) 与 [09-快照与方向.md](09-快照与方向.md)：

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「死锁是包的问题，重传就好」 | 重传会**加剧**缓冲占用；无损网络里死锁要靠缓冲图等级从结构上排除，不能靠重试 |
| 2 | 「只要路由无环就无死锁」 | 路由无环 ≠ 资源等待无环；死锁的对象是**缓冲区**，必须对缓冲区排序（DAGcb 的本意） |
| 3 | 「虚拟通道只是提性能」 | VC 的首要历史作用是**打破循环等待**（Dally–Seitz），性能是副产品 |
| 4 | 🔧 原书限定存储转发模型 | wormhole/cut-through 交换（包未收完即转发）死锁形态不同，需要 Dally–Seitz 的通道依赖图分析，原书只作引子 |
| 5 | 🔧 原书无拥塞控制视角 | 现代无损网络中「死锁避免 + 拥塞控制（ECN/PFC 水位）」必须联合设计（DCQCN 等），单靠缓冲图不够 |
