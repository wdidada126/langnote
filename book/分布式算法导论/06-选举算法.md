## 核心精讲

（以下伪代码与复杂度表均为**教学示意，不参与构建**。）

### 1. 问题定义（7.1）

- 进程带唯一 ID；发起方（或故障检测后）通过消息交换让**所有进程知道同一胜者**（ID 最大的进程）。
- 复杂度目标：**消息数**。这是一个「比较 + 泛洪」的分布式最大值问题，下界 Ω(N log N)（比较类，一般网络）。
- 🔧 与共识的边界：无故障选举只是最大值寻找；**故障下的领导者选举与共识等价难度**（原书 Part III 才谈）。

### 2. 环上选举（7.2）

| 算法 | 模型 | 最坏消息复杂度 | 要点 |
| --- | --- | --- | --- |
| Chang–Roberts（1979） | 单向环，ID 随机分布 | O(N²)（期望 N log N 量级，依分布） | 令牌携带 ID，遇更大 ID 即**自灭** |
| Hirschberg–Sinclair（1980） | 双向环 | O(N log N) | 令牌按**倍增半径**（1,2,4,…）双向扩散，两令牌相遇则消亡 |
| Dolev–Klawe–Rodeh / Peterson（1982） | 单向环 | O(N log N) | 倍增思想的单向化，两两「决斗」淘汰 |

- **Chang–Roberts**（教学示意，不参与构建）：

```
进程 i 想发起选举: 向右邻发 <id=i>
收到 <id=j>: if j > i: 转发 <j>; else: 丢弃（j 小于自己，令牌自灭）
            if j < i 且自己是发起者: 不转发
收到 <id=i>（自己的 ID 绕回）: 当选，广播 <leader=i>
```

- **Hirschberg–Sinclair** 的倍增：第 k 阶段每个「幸存者」令牌走 2^k 步再比较；幸存者数每阶段至少减半，
  故共 O(log N) 阶段，总消息 O(N log N)。**结论：双向 + 倍增能把 O(N²) 压到 O(N log N)**，
  这是本章最重要的复杂度教训。

### 3. 一般网络选举（7.3）

- 思路：先**构造生成树**（见 [05-波与遍历算法.md](05-波与遍历算法.md)），树上回声汇齐 max 即得胜者，再广播。
- 消息复杂度 = 生成树构造（如 GHS：O(|E| + N log N)）+ 树上两趟（O(N)）。
- 原书也讨论「bully 算法」式的直接泛洪版本：O(|E|·N) 级，简单但贵。

### 4. Korach–Kutten–Moran（KKM，7.4）

- **组合技术**：把「选举」分解为「波 + 局部胜者升级」——
  每个簇用波选出局部胜者，局部胜者再进入下一层选举；递归进行。
- 意义：任何波算法都能被 KKM 包装成选举算法，复杂度 = O(波复杂度 · log 层数) 量级；
  这是**算法设计模式**（模块化组合）的示范，也是 [05 章] 「波是积木」论断的最强注脚。

### 5. Chang–Roberts 五节点推演（自查用）

单向环 1→2→3→4→5→1，发起者 2（**教学示意，不参与构建**）：

```
2 发 <2> → 3 发 <3>（2 的令牌被 3 消灭）→ 4 发 <4> → 5 发 <5> → 1 丢弃 <5>（5>1），转发 <5>
→ 2 收到自己没有发的 <5>? 不对——2 收到 <5>，5>2，转发 → …… → 5 收到 <5>（自己的 ID）当选
```

- 观察：每张令牌遇到「更大的仍在环上的 ID」即死，胜者 5 的令牌恰好绕环一周；
  最坏情形（ID 逆序排列）人人起步、人人被灭一次 → Ω(N²) 消息；期望情形 O(N log N)（依 ID 分布）。
- 与 HS 对比的关键：CR 的令牌「生死」由比较决定且每进程只发一次起步令牌；HS 用**半径倍增**控制谁有资格继续发令牌。

### 6. Hirschberg–Sinclair 的阶段结构（教学示意）

```
阶段 k: 每个幸存者向两个方向各派令牌走 2^k 步:
        - 途中遇到更小 ID 的幸存者 → 令牌被吞
        - 两令牌正面相遇 → 小者出局
        阶段结束: 幸存者数 ≤ 原来的 1/2
结论: ≤ log N 阶段; 每阶段每幸存者 O(2^k) 消息; 求和 O(N log N)
```

- 直觉：把「全环比较」拆成「局部决斗」，规模指数收缩——与快速归并、倍增搜索同一家族的分治直觉。

### 7. Bully 算法：一般网络的朴素方案（Garcia-Molina 1982）

- 规则：进程 p 疑似 leader 死亡 → 向所有 **ID 更大**者发选举消息；
  若无响应则自封 leader 并广播；若有响应则等待更大者宣布。ID 越大越「横」——故称 bully。
- 消息复杂度最坏 O(N²) 量级，但**实现极简、语义直观**，至今仍是不少系统「故障切换」的默认直觉
  （改进方向：pre-vote 防抖、随机化，见下文工业节）。
- 🔧 与共识的衔接：bully 在分区下会产生两个 leader（各分区各自称王）——正是脑裂；
  无故障模型（本章）不处理，共识层（多数派仲裁）处理。

### 8. KKM 的一层展开示例

- 以「回声波」为积木：initiator 群发启动波 → 每个进程在波中上报自己的 ID → 波在「树根」处决出局部胜者；
  局部胜者集合进入下一层（若不止一个），重复直到唯一胜者 → 广播。
- 消息账：一层 = 一个波（2(N−1)）；层数 ≤ log(初始 initiators)；这就是「波是积木」在选举上的完整兑现。

### 9. 「ID 最大」vs「日志最新」：选举目标的两代变迁（对照表）

| 维度 | 教科书选举（本章） | Raft 式选举（2014–） |
| --- | --- | --- |
| 胜者判据 | ID 最大 | **日志最新**（term、 lastIndex 大者优先），ID 只作唯一化 |
| 破对称手段 | ID 比较 | 随机化选举超时 + term 单调 |
| 消息复杂度视角 | 渐近最优是目标 | 每轮 O(N) 足矣，重吞吐与稳定 |
| 故障语义 | 无故障 | 承认崩溃、分区，多数派仲裁 |
| 分票处理 | 算法保证唯一 | 允许分票发生，随机重试快速收敛 |

- 结论：工业界**放弃了渐近最优**，换来「可理解性 + 容错 + 可观测」；本章的价值在于告诉你
  没有故障时问题本来多简单，从而看清 Raft 多出来的每一条规则都是在买「故障下的正确」。

### 10. 环上选举算法的期望 vs 最坏（选型提示）

- Chang–Roberts：最坏 Ω(N²)（ID 逆序）、期望 O(N log N)（随机均匀分布假设下）——
  「期望好看」依赖**ID 分布假设**，攻击者可控 ID 时不可依赖；
- Hirschberg–Sinclair / DKR：最坏 O(N log N)，无分布假设——代价是双向通道/更复杂状态机；
- 现代系统里环拓扑罕见（gossip、p2p DHT 除外），一般网络直接「生成树 + 回声 + max」或上共识层更实际。

### 11. 环选举、生成树选举、共识：三层难度的定位

1. **环上 max**（本章 7.2）：拓扑固定、无故障 → 纯组合优化（比较结构设计）；
2. **一般网络选举**（7.3/7.4）：需先造生成树 → 组合设计（树 + 波）；
3. **故障下选举**（原书 Part III）：与共识等价难度 → 需多数派/随机化/故障检测，本章算法全部失效。
- 三层之间没有「免费升级」：从 1 到 2 买的是拓扑通用性，从 2 到 3 买的是容错——每层都要重付设计成本。

## 版本演进

| 阶段 | 变化 | 影响 |
| --- | --- | --- |
| 1979–1982 | Chang–Roberts → Hirschberg–Sinclair → Dolev–Klawe–Rodeh/Peterson | 环上选举复杂度从 O(N²) 优化到 O(N log N)（最优） |
| 1990 | Korach–Kutten–Moran（TOPLAS） | 组合式选举设计定型 |
| 🔴 1999 / 2014 | PBFT / **Raft**（USENIX ATC 2014） | 选举进入**容错时代**：任期（term）+ 多数派投票替代「最大 ID 获胜」；Chang–Roberts 式比较逻辑被随机超时（randomized timeout）替代 |
| 2015–今 | 分批/分层选举（如一致性哈希环上的分片 leader）、预投票（pre-vote）防抖 | 工业界在经典结构上加防风暴补丁 |

## 近年研究与工业界开源实践（2015–2026）

- **Raft 选举中的经典影子**：随机化选举超时（防分票）≈ 破对称；term 单调 ≈ ID 比较；多数派 ack ≈ 波的「汇齐」。
  与本章的差别在于：Raft 要容忍故障与脑裂，胜者未必是「最大 ID」，而是**日志最新者**——选举目标从 extrema 变成「最新数据」。
- **pre-vote / check-quorum**（etcd、hashicorp/raft 都实现）：防「网络抖动 → 疯狂换主」的选举风暴，工业补丁。
- 开源实践（star 数 2026-09-26 `gh api` 实测）：
  - `etcd-io/etcd`（52.3k★）：Raft 选举的参考实现，`raft.go` 状态机含 pre-vote。
  - `hashicorp/raft`（9.1k★）：Go 生态用得最多的 Raft 库，Consul/Nomad 的选主底座。
  - `kubernetes/kubernetes`（128.0k★）：kube-controller-manager / scheduler 的 leader election
    建在 etcd（或 lease 对象）上——「先选主再干活」是 Ch7 抽象在编排系统的直接应用。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「选 ID 最大的就是对的」 | 无故障时如此；有故障/分区时**必须改选多数派承认的候选**（日志最新），最大 ID 可能恰好是过时节点 |
| 2 | 「选举 = 共识」 | 无故障时选举比共识简单（只是 max）；**崩溃故障下两者等价难度**，Chang–Roberts 那套不能直接当共识用 |
| 3 | 「O(N log N) 已是最优，没有改进空间」 | 渐近最优 ≠ 工程最优：常数因子、期望 vs 最坏、带宽占用在现代实现里更重要；Raft 甚至放弃最优性换可理解性 |
| 4 | 🔧 原书假设进程**永不宕机** | 现实选举的触发器恰恰是「疑似宕机」；故障检测器（原书 Ch16）与选举必须一起设计，本目录在 [10-同步网络与时间.md](10-同步网络与时间.md) 带出 |
| 5 | 🔧 原书无随机化破对称（除匿名章外） | 2015 后的主流做法是**随机超时破对称**（Raft、Bully 修补版），比确定性 ID 比较更抗分票 |
