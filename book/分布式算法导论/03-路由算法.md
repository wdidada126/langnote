# 第 4 章 路由算法（Routing Algorithms，原书 pp.103–154）

> 一句话定位：把「全网最短路」变成每台路由器里**可收敛的分布式计算**——距离向量与链路状态的前身与证明。

## 核心精讲

（以下伪代码与复杂度表均为**教学示意，不参与构建**。）

### 1. 基于目的地址的路由（4.1）

- 每个节点维护**路由表**：对每个目的地址 d，记录下一跳。合法路由表要求：按表转发形成**到达目的地的路径**
  （原书用「路由表不变量」证明，即每个非目的地节点的下一跳到目的地的距离严格递减）。
- 路由算法要解决的不是「查表」（O(1)），而是**分布式地维护这张表在拓扑变化时的一致性**。

### 2. 全对最短路：分布式 Bellman-Ford（4.2）

- 每个节点对每个目的地维护估计距离 `D[w]`；周期性（或变化时）向邻居广播 `D`；
  收到邻居 v 的表后：`D[w] = min(len(u,v) + D_v[w], D[w])`，若变化则再次广播。
- 正确性论证：以「真实最短路长度」为不变量，估计值单调下降收敛（异步下也成立——这是 Bellman-Ford 对异步友好的关键性质）。
- 🔧 消息复杂度（原书口径）：静态网络 O(N·|E|) 条消息（N 为节点数，E 为边数）；拓扑变化会触发**重新收敛**，
  最坏情况消息数不可控——这正是「计数到无穷」（count-to-infinity）问题的根源。

### 3. Netchange 算法（4.3）

- 对分布式 Bellman-Ford 打补丁以应对链路增删：
  - 每个节点维护对每个邻居的**第二最小距离**（through-which-neighbor 的次优选择）；
  - 链路断开时，若当前下一跳失效，**立即切换到次优邻居**而不必全网重新扩散——限制坏消息传播范围。
- 原书证明 Netchange 在「单一链路变化」下消息复杂度受控，且路由表始终满足「无环」不变量（除收敛瞬间）。
- 🔧 与 RIP 的关系：Netchange 本质上是**RIP + 毒性逆转思想的理论化**；count-to-infinity 在真实 RIP 中仍会发生，
  工业界最终用「最大跳数（16 跳 = 无穷）」这种工程补丁而非算法修复。

### 4. 紧凑路由表与分层路由（4.4/4.5）

- **紧凑路由（compact routing）**问题：路由表必须 O(N) 甚至 O(log N) 位时，路径还能不能接近最短路？
  原书给出「间隔路由（interval routing）」式方案：把线性序的目的地打包成区间，一张表项服务一段目的地。
- 🔧 后续理论定论（原书之后）：**Thorup–Zwick (STOC 2001)** 给出 stretch 3、表大小 Õ(√N) 的紧凑路由方案，
  并证明 stretch < 3 时表大小下界为 Ω(√N)（girth 猜想，后来被证实为不可达）——把 4.4 的问题变成了有下界的科学问题。
- **分层路由（4.5）**：把网络划成区域，区域间只记「区域级」路由——这就是今天**自治系统（AS）与 BGP 的教科书原型**。

### 5. count-to-infinity 的逐步推演（自查用）

三点线型网络 A—B—C（C 到目的网 X 的真值 1，经 B 中转，A 经 B，B 经 C）（**教学示意，不参与构建**）：

```
初始: dist(B→X)=1, dist(A→X)=2
B—C 链路断开:
  B 丢失直连 → 听 A 说 2 → 猜 dist=3   ← 坏消息没有立刻死掉
  A 听 B 说 3 → 更新为 4；B 又听 A 说 4 → 5 ……
  ⇒ 距离以每轮 +1 的速度爬向「无穷」，期间环持续
```

- 修复手段对照：
  - **水平分割**：从 X 方向学来的路由不再向该方向宣告——堵掉 B 从 A 听回 X 这条假路径；
  - **毒性逆转**：反向宣告为无穷——立刻打死假路径，收敛更快、消息更多；
  - **触发更新**：变化立即广播，不等周期计时。
- RIP 的「16 跳 = 无穷」是把 count-to-infinity 限制在 16 轮内的工程补丁；OSPF（链路状态）直接
  让每个节点掌握全网拓扑、自己算 Dijkstra，从根上消掉该问题——原书 4.2/4.3 的对比落到工业界就是 RIP vs OSPF。

### 6. 链路状态的分布式实现要点（4.2 的另一半）

- 链路状态 = 三步：**发现邻居**（Hello）→ **泛洪 LSDB**（每条链路状态通告 LSA 向全网扩散，靠序号+年龄去重）
  → **各自本地跑 Dijkstra**。
- 泛洪正是 [05-波与遍历算法.md](05-波与遍历算法.md) 中「可靠的扩散波」：LSA 的序号机制保证每条通告
  每邻居至多转发一次；原书 4.2 的「泛洪 + 本地计算」即此结构的理论形态。
- 🔧 一致性陷阱：各节点 LSDB 同步存在短暂窗口，收敛期内不同节点可能算出**不一致的最短路**（瞬态微环），
  与原书 4.3 的「除收敛瞬间外无环」结论对读。

### 7. 三大路由协议复杂度/特性对照

| 维度 | RIP（距离向量） | OSPF（链路状态） | BGP（路径向量） |
| --- | --- | --- | --- |
| 信息范围 | 邻居的距离表 | 全网拓扑（域内） | 完整 AS 路径 |
| 收敛速度 | 慢（逐轮跳变） | 快（触发泛洪） | 慢但可控（策略优先） |
| 防环机制 | 跳数上限 + 水平分割 | Dijkstra 本身无环 | AS-Path 检查自身 AS |
| 规模 | 小网络 | 单个自治域 | 全球域间 |
| 对应原书 | 4.2/4.3 | 4.2 泛洪 + 本地计算 | 4.5 分层路由 |

### 8. 紧凑路由的一个最小示例（interval routing）

- 给节点 0…N−1 线性编号，环上每条边的路由表只存一个**区间**：节点 i 的边负责
  「目的地落在 [i+1, i+k]」的一段。查表 = 判断目的编号落在哪个区间 → O(1) 表项级的判断。
- 教学意义：证明「表不必按目的地逐项存」；Thorup–Zwick 的 Õ(√N) 方案是其规模化后继（见下文经典论文表）。

### 9. 分层路由的 OSPF 区域化实例（4.5 落地）

- OSPF 把一个 AS 切成区域：区域内跑链路状态泛洪（区域内部拓扑全知）；区域边界路由器（ABR）
  把区域拓扑**摘要**成「网段 + 代价」注入骨干区（Area 0）；外部路由由 ASBR 重分发。
- 信息量对照：区域内节点不必知道其他区域的内部链路——**路由表从「全网规模」降到「区域规模 + 摘要规模」**，
  正是 4.5「分层 = 用路径次优换表与消息」的工业实现。
- BGP 把同一思想再抬一层：AS 间只交换「可达性 + AS 路径」，路径细节完全封在域内。

### 10. SDN 场景下本章问题的新提法

- 传统（4.1–4.3）：每个路由器**自己**维护一致路由表；SDN：控制器集中计算、下发流表。
  4.2 的「分布式收敛」变成「**一致性更新**」——旧表新表切换期间如何不出现环/黑洞
  （Reitblatt et al. SIGCOMM 2012 的两阶段提交式更新：每跳新旧两组规则 + 版本标签，切换原子生效）。
- 呼应关系：版本标签方案与 Ch3 的「序号去重」、Ch6 的「两相波」共享同一直觉——
  **先铺新路径、再原子切流**；集中化改变的是计算位置，不消灭一致性本身。

### 11. BGP 路径选择的五条常识（读 4.5 的现代注脚）

1. BGP 不是最短路协议：选路优先级是**策略**（本地偏好、AS-PATH 长度、MED……），代价是「商业关系」不是拓扑距离；
2. AS-Path 防环是**逐项检查**而非距离比较——路径向量比距离向量多带的正是「历史」；
3. 收敛慢是特性不是缺陷：全局可达性信息宁可慢也要稳（RAIJ 系列研究关注的就是收敛冲击）；
4. Route Reflector 让 IBGP 全连接的 O(N²) 会话树化——4.5 分层思想在协议内部的再应用；
5. RPKI 起源验证补的是「节点可信」假设——原书模型缺的正是这一层。

## 近年研究与工业界开源实践（2015–2026）

- **SDN 控制面**：OpenFlow 把「路由表」变成控制器下发的小工具；原书 4.1 的「路由表不变量」在 SDN 里变成
  「控制面与数据面视图一致性」问题（一致性更新，SIGCOMM 2012 Reitblatt et al.《Abstractions for Network Update》——同行评审）。
- **BGP 在数据中心**：RFC 7938（2016，Google Jupiter）确立「数据中心内用 eBGP 而非 IGP」的实践，
  是分层路由（4.5）在叶脊拓扑上的现代翻版。
- **Consistent Hashing 与负载均衡**：与「路由」呼应——数据面用一致性哈希决定「去哪台」，路由决定「怎么过去」；
  原书不含此主题，属于 2026 视角必须补的缺口（Karger et al. STOC 1997 为原始文献）。
- 开源实践（star 数 2026-09-26 `gh api` 实测）：
  - `FRRouting/frr`（4.3k★）：Linux 上的 OSPF/BGP/IS-IS 套件，`bgpd`/`ospfd` 是本章算法的直接工业实现。
  - `openvswitch/ovs`（4.0k★）与 `opennetworkinglab/onos`（1.3k★）：SDN 数据面与控制面代表，
    把 4.2 的「分布式收敛」改为「集中计算 + 一致性下发」。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「距离向量与链路状态只是实现细节差异」 | 本质差异是**信息范围**：距离向量只知邻居的表（易 count-to-infinity），链路状态全网泛洪拓扑自己算——RIP vs OSPF 的差距 |
| 2 | 「Netchange 已解决路由环」 | 只保证**除收敛瞬间外**无环；瞬时不一致仍可能造成短环，BGP 用 AS-Path 防环是更强的机制 |
| 3 | 「路由表必须每目的地一项」 | 紧凑路由（4.4）证明可以远小于此；现代 FIB 的 LPM 前缀聚合是工程版的 interval routing |
| 4 | 🔧 本书假设节点可信、拓扑已知 | 域间路由（BGP）的现实是**策略 + 互信缺失**：路由安全（RPKI）是 2026 年的持续工程议题，原书完全未涉及 |
| 5 | 🔧 原书控制面完全分布式的立场已被部分颠覆 | SDN/集中式控制（ONOS、OVSDB）+ P4 可编程数据面（`p4lang/p4c`，839★）是新的主流叙述，应作为补充视角 |
