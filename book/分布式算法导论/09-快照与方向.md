# 第 10–11 章 快照 与 方向感（Snapshots / Sense of Direction and Orientation，原书 pp.335–395）

> 一句话定位：Chandy–Lamport 快照是分布式系统史上**被工业引用最多**的算法——Flink checkpoint 直接是其实现；
> 方向感（Ch11）则说明「知道邻居的拓扑方位」能把多种算法复杂度打下来。

## 核心精讲

（以下伪代码与复杂度表均为**教学示意，不参与构建**。）

### 1. 一致全局状态（10.1）

- **快照 = 一致切分**：记录的进程状态集合 + 通道消息集合，满足「不包含因果倒置的『收到未发出』消息」。
- 理论工具仍是 [01 章] 的 happened-before：快照**等价于某次合法的串行执行中的一个瞬时状态**
  （不必是真实发生的时刻，但与真实执行不可区分——这是它合法性的全部来源）。
- 难点：没有全局时钟，各进程「同时」不可定义；必须靠**消息携带标记**把切割面「缝」出来。

### 2. Chandy–Lamport 算法（10.2）

```
发起进程:   记录自身状态; 向每条出通道发 <marker>
进程 p:     首次收到某 <marker>（来自通道 c）:
              记录自身状态; c 置为空; 向其余出通道发 <marker>
后续收到 <marker>（来自通道 c'）: c' 置为空
非 marker 消息（c' 已记录后到达）: 记入 c' 的通道快照
```

- 性质：**冻结无关、消息不丢**；FIFO 是必要假设（marker 不许超车）——这是原书强调且工程上常被忽略的前提。
- **Lai–Yang 式变体**（原书第二算法）：不用 marker 阻塞通道，靠给消息**着色**（红/白）区分切割面两侧，
  代价是要离线推断通道消息——无 FIFO 假设时的替代方案。
- 消息复杂度 O(|E|)，额外开销为每通道一条 marker。

### 3. 快照的使用（10.3）与死锁检测应用（10.4）

- 快照得到一致状态后，可在其上**任意评估全局谓词**：是否死锁（等待图有环）、终止（见
  [07-终止检测.md](07-终止检测.md) 的对照）、负载均衡决策、稳定性质检测（稳定性：一旦真则永远真，如死锁）。
- **稳定性是关键豁口**：不稳定谓词（如「此刻活着」）拍完照就失效；稳定谓词（死锁、终止）拍照即断言未来——
  原书 10.4 用快照检测死锁正是利用死锁的稳定性。

### 4. 方向感与定向（Ch11）

- **方向感（sense of direction）**：给每条边标注「拓扑方位」（环上顺/逆时针、网格上的东西南北、超立方的维度），
  使每个进程能回答「往那个方向走 k 步到哪里」这类问题。
- 收益（原书 11.2–11.4）：
  - **弦环选举**：有方向感时可沿「跳距」组合信息，消息复杂度从 [06 章] 的 O(N log N) 进一步改善；
  - **超立方计算**：维度编号使「按维度归并」成为可能，波/广播算法的时间可压到 O(log N)（与维度同阶）；
  - 定性结论：**拓扑知识是一种算法资源**——信息越多，消息越省。
- 🔧 对应的负面结果：无方向感的匿名结构上，一些加速不可能实现——与 [08-匿名网络与对称破缺.md](08-匿名网络与对称破缺.md) 的不可能性互为表里。

### 5. 为什么必须 FIFO：一个反例推演（自查用）

通道 P→Q 非 FIFO，P 依次发 m1、marker（**教学示意，不参与构建**）：

```
网络把 marker 先送到 Q: Q 记录状态, 认为"P→Q 通道为空"
随后 m1 才到: m1 属于"切割面前发出、后到达"——应记入通道快照, 但 Q 已封口
⇒ 快照里丢了一条在途消息 → 不再是一致状态(可能违反"收到未发出"判据的对偶)
```

- 修复谱系：Chandy–Lamport（要求 FIFO）→ Lai–Yang（着色，去 FIFO 假设，通道消息离线推断）
  → Mattern（计数/向量版，容忍非 FIFO 且可多 initiator）。
- 工程对应：Flink 的 barrier 依赖算子间**严格 FIFO**（数据流按 partition 有序）；
  若上游 channel 乱序（如部分 batch 系统重排队），barrier 对齐前必须先做本地重排序——原书 FIFO 假设的工业影子。

### 6. 一致切分的判据（形式一句话版）

- 切分面把每个事件归「记录侧 FG（forward/green）」或「未记录侧」；一致 ⟺
  **不存在「记录了 receive 而未记录对应 send」的消息**。等价说法：FG 对因果序封闭。
- Chandy–Lamport 的正确性一句话：marker 保证每个通道的记录内容恰为「send 在 FG、receive 在 BG」的消息集合——
  收录了「发出但未送达」的，绝不会收录「未发出却收到」的。建议把这个判据与 [01 章] happened-before 对照记忆。

### 7. 快照检测死锁的工作示例（原书 10.4 落地）

- 进程 A 等资源（由 C 持有）、C 等（由 A 持有）——等待图 A→C→A（**教学示意，不参与构建**）：
  1. 任意节点发起快照，marker 沿等待关系传播；
  2. 拍出的全局状态里重建等待图（每进程快照含「我在等谁」）；
  3. 在快照上跑环检测（本地/汇聚到 initiator 均可），有环 → 死锁成立；
  4. **死锁是稳定性质**：一旦为真，除非有 abort 行为否则永真 → 快照结论可放心使用。
- 对照 [04-无死锁交换.md](04-无死锁交换.md)：网络缓冲死锁靠**预防**（等级），数据库/进程死锁靠**检测+回滚**——
  稳定性判定（本章快照）是后者的算法内核；[../数据库系统概念6/15-并发控制.md](../数据库系统概念6/15-并发控制.md)
  的等待图检测是同一逻辑的单机版。

### 8. 方向感的最小示例：弦环选举为什么更快

- 普通环：邻居只有「顺/逆」两个身份，信息只能一跳一跳扩散 → 选举 O(N log N)（[06 章]）。
- 弦环 + 方向感：每条弦标注「跳距 d」；进程可**按跳距组合**——
  「d 跳内的最大 ID」可以由「d/2 跳内的最大值」两两合并得到 → 比较次数按归并树下降，常数与轮次均改善。
- 超立方（11.3）：维度编号让「按维度归并」精确可执行，广播/聚合时间 O(log N)=维度数——
  「知道自己是几号维度」这一个信息，把全网计算压缩了一个数量级。

### 9. 快照的四个工业应用位（10.3 的现代展开）

| 应用 | 用到的快照性质 | 工业实例 |
| --- | --- | --- |
| 流计算 checkpoint | 一致切分 + 可恢复 | Flink ABS（见上文开源节） |
| 死锁/终止判定 | 稳定谓词 | 数据库等待图、分布式 GC |
| 全局调试与监控 | 「某时刻系统全体状态可对齐」 | 分布式追踪的因果对齐、微服务一致性视图（非同行评审实践居多） |
| 一致性备份/组快照 | 切割面语义 | 云盘一致组快照（厂商文档） |

- 共同点：都需要「**各局部状态 + 通道在途消息**」二者齐备才叫一致——只拷贝各节点内存（漏通道）
  是工程上最常见的半吊子快照，恢复时会丢消息。

### 10. 方向感章与现代「拓扑标签」的对照（11 章的 2026 读法）

- 原书 11 章的方向感：环/弦环/超立方上给边标注拓扑方位 → 算法消息复杂度下降；
- 现代等价物：云环境给节点打 **rack / zone / region 标签**，副本放置、读路由、故障域计算全部消费这些标签；
- 两者共享同一论断：**拓扑知识是算法资源**——「知道自己相对别人在哪」能把泛洪型算法（O(E) 级）
  换成定向型算法（O(D) 或 O(半径) 级）。读 11 章时请把「超立方维度」自动翻译成「可用区编号」。

## 近年研究与工业界开源实践（2015–2026）

- **Flink checkpoint（工业标准实现）**（`apache/flink`，26.4k★）：coordinator 周期注入 barrier，
  算子对齐 barrier 后把状态快照到远端存储——**Chandy–Lamport 的 marker 就是 barrier**；
  其后续演进 unaligned checkpoint（FLIP-76，非同行评审设计文档）为解决背压下对齐延迟而生。
- **Chandy–Lamport 云快照**：Azure/AWS 的「一致组快照」与 Spanner 等系统的备份一致性，
  本质是「切割面语义」在不同存储层的再实现（厂商文档，非同行评审）。
- 开源实践（star 数 2026-09-26 `gh api` 实测）：
  - `apache/flink`（26.4k★）：`checkpoint` 模块，ABS 算法的生产实现。
  - `apache/spark`（44.0k★）：structured streaming 的 watermark/barrier 机制与快照语义互补（完成判定见 [07 章]）。
- **方向感的现代影子**：数据中心拓扑感知调度（拓扑 key、rack-aware 副本放置）把「知道自己在拓扑中的方位」
  变成调度与复制的输入——与 Ch11「拓扑知识是资源」的结论一致。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「快照记录的就是『现在』」 | 记录的是**某个等价串行执行中的状态**，不必对应真实时间轴上的任何一刻——这正是其正确性的来源而非缺陷 |
| 2 | 「快照算法不需要 FIFO」 | Chandy–Lamport 依赖 marker 不超车；非 FIFO 用 Lai–Yang 着色或 Mattern 计数，各有代价 |
| 3 | 「拍完快照就能检测一切谓词」 | 只有**稳定谓词**（死锁、终止）拍完即可断言；不稳定谓词需要反复快照或专门算法（详见 Lynch） |
| 4 | 🔧 原书快照假设**无故障** | 生产 checkpoint 必须容忍算子崩溃后从上一个 checkpoint 恢复（exactly-once 语义靠快照+重放合力达成），故障恢复层原书缺位 |
| 5 | 🔧 方向感章的现代价值被低估 | 拓扑感知（rack/zone/region 标签）已是复制与调度的标配输入；Ch11 是其理论先声，读时应关联云多可用区场景 |
