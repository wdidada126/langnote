## 核心精讲

（以下均为**教学示意，不参与构建**。）

### 1. 系统模型：迁移系统

- 一个分布式系统建模为**迁移系统**：状态集合 + 迁移关系（transitions）。每个进程有局部状态，
  唯一交互方式是消息传递；一条消息的发送/接收是两个不同进程上的两个事件。
- **系统性质分两类**：
  - **安全性质**（safety）：「坏事永不发生」（如消息不丢失、不变量不破坏）；
  - **活性性质**（liveness）：「好事终将发生」（如终止、进度）。
- **证明工具**：**迁移不变性**（invariant）——找出一个谓词，含初始状态、且对每个迁移保持成立；
  它是全书证明「算法正确」的标准手法。这个思想今天原样活在 TLA+/PlusCal 的 invariant checking 里。

### 2. 因果序与逻辑时钟（Lamport 1978）

- 事件上的** happened-before 关系** `a → b`：同进程先后，或「send 事件 → 对应的 receive 事件」，或传递闭包。
- **逻辑时钟**：每个进程一个计数器，事件时自增，发送时携带时间戳，接收时取 `max(local, stamp) + 1`。

```python
# Lamport 逻辑时钟（教学示意，不参与构建）
def local_event():        p.clock += 1
def send(m):
    p.clock += 1
    m.stamp = p.clock
def receive(m):
    p.clock = max(p.clock, m.stamp) + 1
```

- 关键性质：`a → b ⟹ C(a) < C(b)`；**逆命题不成立**——C(a) < C(b) 推不出因果（并发事件时钟序是任意的）。
  正因为如此才需要后文（Ch10）的快照算法：**逻辑时钟打不出来的「全局状态」，要用通道消息做出来**。

### 3. 复杂度度量（2.4）

- 全书统一度量：**消息复杂度**（消息条数）与**时间复杂度**（异步下按「一步」计，同步下按轮计）。
- 模型假设谱系：异步（无时钟、任意延迟）vs 同步（轮推进）；可靠通道 vs 可丢失通道；
  唯一 ID vs 匿名（后者见 [08-匿名网络与对称破缺.md](08-匿名网络与对称破缺.md)）。
- 🔧 原书对消息大小的假设是「含 O(log n) 位本地信息即合法」；现代讨论常把消息大小也算进复杂度
  （CONGEST 模型），读第 4 章紧凑路由时要记住这点。

### 4. 全书记号约定（原书附录 A/B 的导读）

- **附录 A（伪代码约定）**：每个算法写作若干「按进程实例化」的模块，事件类型只有三种——
  内部事件、`send <msg>`、`receive <msg>`；消息接收是**原子**的，进程状态更新只发生在事件内。
  本目录各章伪代码沿用这一风格（简化为 Python 风格），语义等价。
- **附录 B（图与网络）**：网络 = 无向连通图 G=(V,E)，N=|V|、E 为边集、D 为直径；
  「通道」默认 FIFO 且可靠；「邻居」指共享一条边的进程。所有复杂度都是 N、E、D 的函数。
- 🔧 阅读提示：原书把「消息复杂度」与「时间复杂度」分列，但中译排版里两列容易被略读——
  本目录每章的核心精讲都用表格并列给出，避免混淆。

### 5. 不变量证明的完整小例（2.2 方法论演示）

以「环上令牌」为例演示迁移不变性的标准写法（**教学示意，不参与构建**）：

- 系统不变量（候选）：「任意时刻环上**至多一枚**令牌，且持有者唯一」。
- 验证三步：
  1. **初始成立**：只有 initiator 持令牌；
  2. **保持成立**：枚举每个迁移——发送令牌时发送方交出、接收方获得，令牌总数不变；
  3. **结论**：不变量恒真 → 任何时刻不会出现两枚令牌（安全性质），令牌不会凭空产生/消失。
- 这套「候选不变量 → 初始 + 保持 → 结论」的三段式，就是全书证明章法的全部骨架；
  第 3 章（协议正确性）、第 5 章（无死锁）、第 6 章（波终止）全部照此办理。

### 6. 矢量时钟：把「逆命题」补回来（原书未覆盖的延伸）

- Lamport 时钟丢信息（并发被强行定序）；**矢量时钟**让每个进程维护全 N 维计数器：

```python
# 矢量时钟（教学示意，不参与构建）
def local_event():        p.v[p.id] += 1
def send(m):
    p.v[p.id] += 1
    m.v = p.v.copy()
def receive(m):
    p.v = [max(a, b) for a, b in zip(p.v, m.v)]
    p.v[p.id] += 1
# a -> b  ⟺  V(a) <= V(b) 且 V(a) != V(b)   （双向刻画，Lamport 时钟只有单向）
```

- 代价：消息携带 O(N) 状态，N 大时不可行——工程上出现**区间内省（interval tree clock）**、
  仅追踪相关子集等折中。理解「Lamport → 矢量」这一步，就能理解 Ch10 快照为什么必须用「通道消息」而非「时钟读数」来定义一致性。

### 7. 复杂度度量补充：消息大小也算钱

- 原书 2.4 只数消息条数；现代分布式算法文献（CONGEST 模型）规定**每条消息 O(log N) 位**，
  「把整张表塞进一条消息」不算一跳。读第 3 章（协议头部）、第 4 章（路由表内容）、第 6 章（DFS 携带访问列表）
  时都应自问：这条消息几位？——复杂度结论可能因此改变（如紧凑路由的下界正是对消息大小敏感的）。

### 8. happened-before 判定练习（自查用）

设进程 A、B、C；事件序列（**教学示意，不参与构建**）：
- A1（A 发给 B 消息 m1）→ B1（B 收 m1）→ B2（B 发给 C 消息 m2）→ C1（C 收 m2）；
- 同时 A 独立发生 A2（本地事件），C 发生 C2（本地事件）。

判定表：

| 事件对 | 因果关系 | Lamport 时钟能判定吗 |
| --- | --- | --- |
| A1 与 C1 | A1 → C1（经 B1、B2 传递） | 能（C1 时间戳更大） |
| A2 与 C2 | 并发 | **不能**（时钟大小任意，可能「假序」） |
| B1 与 B2 | 同进程顺序 → B1 → B2 | 能 |

- 结论复述：Lamport 时钟给出「因果 ⟹ 时钟序」，反向不成立；并发对的次序在时钟上纯属巧合。
  这一限制贯穿全书：第 10 章快照、第 12 章时钟同步都是对「时间读数不可靠」的不同补救。

### 9. 本章的教学立场

第 1 章是动机章（举例：文件系统、支付网络等），真正必须吃透的是 2.2 的不变量证明法和 2.3 的因果序——
后面每一章的「正确性」都是本章方法论的重复应用。建议第一遍通读 1 章、精读 2.2–2.4；
各章笔记的「核心精讲」遇到「按不变量可证」字样时，都应能回想起本节第 5 小节的三段式。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「Lamport 时钟相等 = 并发」 | 相等意味着同一进程内顺序发生；**并发事件时钟可以不等也可能「看起来有序」**——逆命题不成立，要用矢量时钟 |
| 2 | 「逻辑时钟可以代替物理时间」 | 只能定序，不能回答「延迟了多久」；超时类算法（Ch3、故障检测）必须引入物理时钟或额外假设 |
| 3 | 「安全性质比活性重要」 | 二者正交；分布式系统的可用性常是活性问题（进度），正确性常是安全问题（不变量） |
| 4 | 🔧 本书模型假定**可靠 FIFO 通道**且无故障 | 现实网络会重排/丢失；TCP 在传输层补回 FIFO+可靠（见 [02-通信协议.md](02-通信协议.md)），Part III 才处理故障 |
| 5 | 🔧 原书复杂度只数消息条数 | 现代还须计消息大小（CONGEST）、带宽与延迟乘积；阅读紧凑路由（Ch4）时尤其要警惕 |
