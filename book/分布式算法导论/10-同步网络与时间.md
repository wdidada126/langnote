## 核心精讲

（以下伪代码与复杂度表均为**教学示意，不参与构建**。）

### 1. 同步模型（12.1）

- **同步网络**：时间切成轮；每轮内所有进程「同时」收上一轮消息 → 本地计算 → 发出本轮消息。
  消息一**轮**内必达（延迟上界 = 1 轮）。
- 收益：消息复杂度不变时，**时间复杂度可大幅下降**；且可以「按轮分阶段」设计算法（每轮做一件事）。

### 2. 同步选举（12.2）与 BFS（12.4）

- 环上选举：同步化让「每轮一个阶段」成为可能，Dolev 等 O(N log N) 的单向环算法在同步模型下可更自然地推导，
  某些变体可再省常数因子；一般网络的选举同样先造生成树再回声（结构同 [06 章]，只是时间被压到 O(D) 级）。
- **同步 BFS（12.4）**：initiator 每轮向邻居扩一层——
  轮数 = 网络直径 D；消息复杂度 O(|E|·D)。这就是**链路状态泛洪求最短路的同步模型版本**（呼应 [03-路由算法.md](03-路由算法.md)）。
- 定性结论：同步模型下「时间 = 拓扑距离」，这让所有「扩散类」算法的时间上界一目了然。

### 3. 同步器 α / β / γ（12.3）

- **问题**：异步网络上能否安全地运行同步算法？**Awerbuch（JACM 1985）回答：能——加一层同步器**。
- 三个经典同步器（教学示意）：
  - **α 同步器**：每轮向所有邻居发「我已就绪」；收到所有邻居的就绪即进入下一轮。
    时间 O(D)、每轮消息 O(|E|)。适合密集图。
  - **β 同步器**：先构造**生成树**，就绪消息沿树上/下传播。每轮消息 O(N)、时间 O(D_tree)。
    适合稀疏通信、树已存在的场景（与 [05-波与遍历算法.md](05-波与遍历算法.md) 的树直接复用）。
  - **γ 同步器**：在簇划分上组合 α（簇内）与 β（簇间），在消息与时间之间**插值**——参数可调的通用方案。
- 本质：同步器把「同步算法」当作**纯逻辑程序**复用，只替它仿真出「轮」的心跳——
  与 [01 章] 「模型只是假设、可以分层」的立场一脉相承，也是**仿真（simulation）作为算法技术**的范例。

### 4. 阿基米德假设（12.5）

- 原书用来指「进程对时间流逝有共同度量」这类理想化假设（时钟读数可比较、流逝速率一致）。
- 🔧 2026 视角：真实系统里这条假设恰恰是**要花钱买**的——15.3 的时钟同步与下文的 NTP/PTP/TrueTime 就是买法。

### 5. 补充精讲：容错时钟同步（原书 15.3 摘要）

- 有故障时的时钟同步：拜占庭故障下需 **交互一致性（interactive consistency）**——把时钟值经多轮投票/中值聚合，
  Lamport–Melliar-Smith 的容错时钟同步（SRI 报告/TOCS 系列）给出收敛路径；同步轮数与故障数 f 满足
  「轮次 ≥ f+1」的直觉（细节属原书 Part III，本目录不展开证明）。
- 工程对应：**NTP 用多数/分层选择、PTP 用 BMCA（最佳主时钟算法）选主**——「选举（[06 章]）」与「时钟同步」在协议层直接合流。

### 6. 三个同步器的伪代码与账本（教学示意，不参与构建）

```
α 同步器（每轮全邻居握手）:
  进入第 r+1 轮的条件: 收到所有邻居的 <ready r>   → 每轮消息 O(|E|), 时间 O(D)

β 同步器（树上报下达）:
  叶→根: 收齐孩子的 <ready> 后向父亲报 <ready>
  根→叶: 沿树回发 <go r>                          → 每轮消息 O(N), 时间 O(树深)

γ 同步器（簇内 α + 簇间 β）:
  预先划分簇; 簇内按 α、簇间沿簇生成树按 β
  → 每轮消息 O(Σ簇内边 + 簇树边), 参数化插值于 α 与 β
```

- 选择直觉：通信贵的网络选 β（消息省）；延迟贵、边密的环境选 α（时间省）；两者都贵时调 γ 的簇参数。
- 复用纪律：**同步算法一个字不用改**——同步器在其下仿真出「轮」，这正是 Ch2 「模型是可分层的假设」的最好示范。

### 7. 同步 BFS 的轮次推导（12.4）

```
r=0: initiator 标记自己(层 0)
r+1 轮: 层 r 的节点向未标记邻居发 <probe>; 收到者标层 r+1
结束: 轮数 = D(直径); 消息 = Σ每个节点向每个邻居发一轮 → O(E·D)
```

- 与 [03-路由算法.md](03-路由算法.md) 链路状态泛洪对读：LSA 泛洪 + 本地 Dijkstra 得到**同款最短路树**，
  但把「时间 = D 轮」换成了「每节点独立计算」——同步扩散与本地计算是求 BFS 的两条等价路线。

### 8. NTP/PTP/TrueTime/HLC 的机制速览（2026 视角的时钟同步）

| 体系 | 原理 | 精度 | 关键机制 |
| --- | --- | --- | --- |
| NTP（RFC 5905） | 分层（stratum）树状授时 + 往返时延估计 + 过滤/选择/聚类 | 毫秒级（互联网） | 8 层 stratum、防环路用「层号只降不升」（选举的影子） |
| PTP（IEEE 1588） | 主时钟选举（BMCA）+ 硬件时间戳 + 延迟测量 | 亚微秒 | BMCA = 时钟质量上的比较选举；交换机需支持透明时钟 |
| TrueTime（Spanner） | GPS + 原子钟给出**误差区间** [earliest, latest] | 区间毫秒级内 | 提交前 **wait_until(earliest) 过区**，用等待换外部一致性 |
| HLC | 物理时间 + Lamport 计数的混合 | 跟随本地物理钟 | `l' = max(l, pt, l_msg)`，`c'` 处理同物理时刻并发——无需专用硬件 |

- 一条主线：**误差不可消除，只能「度量并暴露」（区间）或「用等待/逻辑计数消化」**。
  HLC 公式与 [01 章] Lamport 时钟的「发送携带、取 max」结构一一对应——1978 年的算法仍是 2015 年数据库的内核件。

### 9. 阿基米德假设的工程成本清单（12.5 的 2026 补充）

- 跨 region 数据库为「让 12.5 的假设近似成立」实际支付的成本：
  1. 专用授时设施（GPS 天线 + 原子钟冗余，TrueTime）；
  2. 机房 PTP 化（交换机硬件时间戳改造）；
  3. 提交延迟预算（Spanner 的 wait，典型 7ms 量级写入延迟）；
  4. 逻辑时钟兜底（HLC/HybridTime 的维护与溢出处理）。
- 读原书时把这条清单放在 12.5 旁边，就能明白为什么原书可以一笔带过、而 2026 年的系统无法绕开。

### 10. 容错时钟同步的最小框架（原书 15.3 摘要与 2026 对读）

- 问题：f 个进程时钟**漂移或撒谎**（拜占庭），其余进程要收敛到彼此时钟差 ≤ Δ 内（agreement），
  且与真实时间偏移有界（validity）。
- 框架（教学示意）：多轮交换时钟读数 → 每进程对收到的读数做**容错中值/修剪均值**聚合 →
  迭代 f+1 轮内收敛；轮数下界与故障数绑定（同步模型的优势：轮次即时间上界）。
- 与普通时钟同步（NTP）的分工：NTP 只防**意外故障**（宕机、漂移），不做拜占庭防护——
  其分层选择（stratum）已是「多数/权威优先」的弱化版聚合；对恶意源需 NTS（RFC 8915，NTP 的认证扩展）补课。
- 一句话总结：**无故障 → Ch12 同步模型；崩溃故障 → 15.3 收敛聚合；拜占庭 → 聚合 + 认证（NTS/签名时间戳）**。

### 11. 闰秒与 leap smear（工程边角，2026 视角）

- 闰秒使「物理时间严格单调」失效一次；NTP 的 leap indicator 提前播报，leap smear（Google 实践，非同行评审博客）
  把 1 秒摊到 24 小时内缓慢消化，避免客户端时间回跳。
- 与本章的关系：这正是「阿基米德假设（12.5）」在现实中的裂缝——连「时间均匀流逝」都要协议维护，
  算法层面必须容忍时间回退（HLC 的 c 计数、TrueTime 区间对回跳天然免疫）。

## 近年研究与工业界开源实践（2015–2026）

- **NTP → PTP/TrueTime 的演进主线**：NTP（毫秒级，互联网）→ PTP（亚微秒，机房内）→ TrueTime（GPS+原子钟，
  给出**误差区间 [earliest, latest]**，Spanner 靠「等待区间过去」实现外部一致）。HLC（Kulkarni et al., 2014）
  把物理时间与逻辑计数拼成混合时钟，避免 TrueTime 的专用硬件（CockroachDB 采用）。
- 开源实践（star 数 2026-09-26 `gh api` 实测）：
  - `pendulum-project/ntpd-rs`（1.1k★）：Rust 写的现代 NTP 客户端/服务器（Pendulum 项目）。
  - `aws/clock-bound`（350★）：AWS Clock Bound 服务，把「误差区间」作为 API 暴露——TrueTime 思想的商品化。
  - `FRRouting/frr`（4.3k★）：域内路由与时间无关，但其 PTP/硬件时间戳生态（linuxptp）常与它同机部署，
    linuxptp 官方托管在 SourceForge（GitHub 无权威镜像，star 未核验）。
- **同步器的现代影子**：微批处理（Spark streaming 的批间隔）、Flink watermark 周期、
  分布式训练的同步 SGD step——都是「仿真轮次」的工业形态；而**逻辑仿真轮**与**物理时钟**的结合点是 HLC
  （见 [09-快照与方向.md](09-快照与方向.md) 末节及 [01 章] 逻辑时钟）。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「同步网络是更自然的假设」 | 恰相反：异步更基本；同步是**可以仿真的上层结构**（同步器的意义），别把轮次当物理事实 |
| 2 | 「有了 NTP 时间就能直接排序事件」 | NTP 误差可达几十毫秒且可为负偏移；直接用墙钟定序会翻转因果。要么误差区间（TrueTime/clock-bound），要么逻辑成分（HLC） |
| 3 | 「同步器能免费获得同步」 | 代价是真金白银的消息开销（α 每轮 O(|E|)）；γ 的参数权衡正是为此存在 |
| 4 | 🔧 原书 12.5 的阿基米德假设当作理想化一笔带过 | 2026 年它是**核心工程问题**：跨 region 数据库的一致性预算几乎全花在「缩短时间不确定性」上（TrueTime/PTP/HLC 三条路线） |
| 5 | 🔧 原书时钟同步（15.3）在容错篇、与本章脱节 | 读时应与本章合流：容错时钟同步是「拜占庭 Agrement 思想 + 中值聚合」，普通时钟同步（NTP）则是它的无故障退化版 |
