# 《代码整洁之道》总览与阅读地图

> **一句话**：Clean Code 不是在教你「怎么写代码」，而是在教你**怎么为别人（包括一年后的自己）降低阅读成本**——代码的生命周期里，读的时间远多于写的时间。
> 原书 *Clean Code: A Handbook of Agile Software Craftsmanship*，Robert C. Martin（**Bob 大叔**），Prentice Hall，**2008**（ISBN 978-0-13-235088-4；版权页亦见 2009 印次）。
> 中译本：《代码整洁之道》，韩磊 译，人民邮电出版社，**2010-01**（CIP：据 Pearson Education 英文版译出；ISBN **978-7-115-21687-8**，388 页）。

**大纲版在此**：仓库中**没有** `book/代码整洁之道.md` 这一整本的单文件大纲，但有一个**同主题的大纲单文件** `book/C++代码整洁之道.md`（它记录的是**另一本书**、偏 C++ 语言的整洁写法笔记，本仓库保留不删不改，两者互链）。本目录是**按章节的深度重写版**，与原大纲单文件并存。
**目录命名说明**：定名 `代码整洁之道`（不带空格），以匹配中译本书名。

## 1. 元数据与作者背景

| 项 | 内容 |
| --- | --- |
| 原书 | *Clean Code: A Handbook of Agile Software Craftsmanship*，Prentice Hall（Pearson），2008 |
| 作者 | Robert C. Martin（**Uncle Bob**）：20 世纪 70 年代初成为职业程序员，Object Mentor 公司总裁；敏捷联盟首任主席；《C++ Report》前主编；SOLID 的提出者；*Agile Software Development, Principles, Patterns, and Practices*（2002）作者 |
| 中译 | 韩磊 译（IT 社区与出版人，译有《梦断代码》《C# 编程风格》）；人民邮电出版社 2010-01；ISBN 978-7-115-21687-8；388 页 |
| 英文影印版 | 《代码整洁之道（英文版）》，人民邮电出版社 2011-01，ISBN 978-7-115-244901-7（另有 2015 印次 ISBN 978-7-115-557582-2 的英文版），可与中译对照 |
| 第 2 版 | 2020-02 人民邮电出版社出了新版（ISBN 978-7-115-524133-3，387 页），英文原版正文并未因它改写，属重排/重印；本目录以 **2008 英文原版 + 2010 中译本**为准 |
| 篇幅结构 | 17 章 + 附录 A/B/C。第 1–6 章「通则」，第 7–12 章「案例研究」，第 13–16 章「并发与实例」，第 17 章「味道与启发」（附录 C 是它的交叉索引） |
| 示例语言 | 几乎全是 **Java**（JUnit、FitNesse、`org.jfree.date.SerialDate`），少量 C# 与 C++；**没有 Python、Go、Rust、C++ 现代写法** |
| 配套 | Bob 大叔的 Clean Coder 博客 https://blog.cleancoder.com ；附录 A「并发编程 II」是他早期并发文章的合集 |

> 读本书的正确姿势：把它当作**一份可执行的「职业习惯清单」**，而不是设计理论。它的方法论密度高于理论性，且**带着强烈的个人色彩**（书中反复出现「我们」「作者身份」这类修辞）。把它当规范逐条打卡会僵化，当清单偶尔翻查才有效。

## 3. 版本演进时间轴（2008 ⟶ 2026）

| 年份 | 事件 |
| --- | --- |
| 2000 | XP / 极限编程流行，「代码整洁」以口头传统存在，没有成文规范 |
| **2002** | Martin，*Agile Software Development, Principles, Patterns, and Practices*（Addison-Wesley），SOLID 成形 —— Clean Code 的**前置原则集** |
| 2005–2006 | Bob 大叔在博客/会议上陆续发表「The SOLID Principle」「Boundaries」「Decoupling」等文章，本书的骨架基本来自这些演讲稿 |
| **2008-08** | **Clean Code 出版**（Prentice Hall，464 页），一时成为「代码风格」的通用词汇来源 |
| 2008–2009 | Clean Code 系列演讲（Clean Code Talks、Agile 2009 等）把书里的规则视频化传播 |
| 2010-01 | 中译本出版（韩磊 译，人民邮电；CIP 记录显示据 2009 英文版译出） |
| 2011 | 英文影印版引入中文市场，「Clean Code 风格」进入国内团队的日常讨论 |
| 2012 | 社区关于「**Clean Code 不可执行 / 教条**」的批评开始出现；测试金字塔被系统性地重新表述 |
| **2017-09** | 《架构整洁之道》（*Clean Architecture*，Robert C. Martin，Pearson）出版，把 SOLID 从「类设计」上推到「系统边界」（中文版 2023） |
| 2017–2019 | Clean Code 衍生作品出现：*Clean Code in Python*（Mikael Fangel，2018）、*Clean Code in C++*（社区写作/翻译实践，并非 Bob 大叔本人所写）、*Clean Architectures in Python*（Leonard 等，2021） |
| 2019–2021 | 《代码整洁之道：程序员的职业素养》（*The Clean Coder*，中译 2020）补上「职业人的纪律」这一缺环；*Clean Code* 被列入大量团队的 New Hire 必读书单 |
| 2020-02 | 中译第 2 版重排出版（ISBN 978-7-115-524133-3） |
| 2021–2023 | **批评意见成型**：命名与格式的过度强调、对短函数的机械追求、对遗留系统与团队政治的忽视被反复讨论；与《重构》《代码大全》的分工被重新厘定 |
| 2023–2026 | **AI 辅助编码**：Copilot / Codex / 各类 Agent 进入日常开发，代码审查的重心从「命名与格式」迁移到「**意图是否一致、边界是否清晰、测试是否真的在守卫**」；本书的规则部分仍有效，但**执行主体发生了变化**——格式与命名的机械检查已交给格式化器与 linter |

## 4. 本书刻意规避 / 未覆盖的缺口（重要）

| 缺口 | 说明 | 补到哪里 |
| --- | --- | --- |
| **几乎不讲并发** | 第 13 章只有约 6 页正文（附录 A 也不长），且例子是 Java 老式 `synchronized`/`wait/notify`，对内存模型、无锁、结构化并发基本不提 | `book/Java并发编程实战/`（本书）、`book/C++并发编程实战2/`、`book/多处理器编程的艺术2/` |
| **不讲性能** | 第 15 章标题是「让 JUnit 跑起来，让它跑得快」，但正文讲的是重构顺序，**没有性能剖析、复杂度、缓存、I/O 成本** | `book/Java性能权威指南.md`、`book/C++标准库.md` 的性能章节 |
| **不讲架构边界的落地** | 「单一职责」「依赖倒置」点到为止，没有组件图、模块图、依赖方向的具体做法 | `book/架构整洁之道*`（*Clean Architecture* 2023 中译）、`book/软件架构设计/`、`book/Fundamentals_of_Software_Architecture.md` |
| **Java 中心** | 全书示例代码 95% 是 Java（含 JUnit 3/4、FitNesse），且用的是 **Java 5 之前的写法**（无泛型、无注解），对其他语言读者有翻译成本 | 各章「版本演进」小节给出 Python/Go/C++/Rust 的对应写法 |
| **假定「绿野仙踪」的新项目** | 全部案例都是从零开始、有人陪你结对、有 TDD 权力、没有历史包袱的理想状况；对**遗留系统**几乎无着墨 | `book/重构*`、*Working Effectively with Legacy Code*、《重构（第 2 版）》 |
| **假定「你有决定权」** | 书里大量「你必须」「应该」，但对团队规范制定者、上下游耦合、deadline 压力给出的方法极少 | `book/打造敏捷开发模式/`、*The Clean Coder* 的职业观部分 |
| **不做量化** | 全书以「读起来顺不顺」为主观判断，没有给出可度量的指标（圈复杂度、扇入扇出、review 时长等） | 第 16 章后补：SonarQube / CodeQL / `gofmt` 这类可自动化工具 |

## 6. 跨书对照表（分工）

| 书 | 关注点 | 与 Clean Code 的关系 | 本仓库对应文件 |
| --- | --- | --- | --- |
| *Clean Architecture*（《架构整洁之道》） | 系统级边界、依赖方向、SOLID 的架构层应用 | **Clean Code 是它的「微观层」**：一本管函数/类，一本管组件与系统；本书 Ch10/Ch11 就是它的.java 底子 | 仓库中暂无 `book/架构整洁之道*`，最接近的是 `book/软件架构设计/`、`book/Fundamentals_of_Software_Architecture.md`、`book/Software Architecture.md` |
| *Refactoring*（《重构》） | **如何在不破坏行为的前提下**把脏代码改成干净代码 | 本书讲的是「目标形态」，重构讲的是「**路径与手法**」，以及「什么时候值得改、改不下去怎么办」 | 仓库中暂无 `book/重构*`，最接近的是 `book/大话重构.md` |
| *Code Complete 2e*（《代码大全 第 2 版》） | 软件构建的全局：语言细节、贯穿设计、编码习惯、调试、集成 | 覆盖面远大于 Clean Code（Clean Code 只管「代码本身的读写体验」）；《代码大全》讲「**怎么做**」，Clean Code 讲「**做到多干净**」 | 仓库中暂无 `book/代码大全（第2版）*` |
| *Design Patterns*（GoF） | 命名好的设计结构（模式名即最高级的命名） | Clean Code 的命名章讲「给类/方法取好名」，GoF 提供「标准化的好名字」；GOF 不谈代码整洁 | `book/设计模式GoF/`、`book/C++20设计模式.md` |
| *The Clean Coder* | 职业纪律、时间管理、学习、与他人的协作 | Clean Code 讲「代码」，Clean Coder 讲「人」，是本书的**前置素养篇** | 仓库中暂无单独条目 |
| *Working Effectively with Legacy Code* | 给没有测试的遗留代码「上保险」 | 本书假定你有 TDD 自由，本书对此几乎无解；这是补上本书最大缺口的那本 | 仓库中暂无单独条目 |

## 7. 阅读顺序与写作约定

| 文件 | 对应章节 | 核心主题 |
| --- | --- | --- |
| `00` | — | 元数据、全书结构、时间轴、缺口、工具链、跨书分工 |
| `01`–`06` | Ch1–Ch6 | 「通则」六章：整洁、命名、函数、注释、格式、对象与数据 |
| `07`–`12` | Ch7–Ch12 | 「案例研究」六章：错误处理、边界、测试、类、系统、迭进 |
| `13` | Ch13 + 附录 A | 并发（本书最小、最过时的章节，需要外部补课） |
| `14` | Ch14 | 案例研究：SerialDate 的逐步改进 |
| `15` | Ch15 + Ch16 | JUnit 内幕；第二轮与第三轮重构 |
| `16` | Ch17 + 附录 B/C | 味道与启发全表 + 启发式交叉索引 |

> 时间紧迫者的最小路径：`01` ⟶ `02` ⟶ `03` ⟶ `09` ⟶ `17`。命名与函数这两章的性价比最高；Ch5/Ch6 争议最大可以略读；Ch13 直接跳过去看并发专书。

每个章节文件的固定结构：

1. `# 第 N 章 标题` ⟶ `> **一句话**：...`
2. `## 本章地图`（表格：节 | 内容 | 结论）
3. `## 核心精讲`（含教学示意代码，**不编译、不运行、不参与构建**）
4. `## 版本演进`
5. `## 经典论文与原始文献`（表格，全部真实可查）
6. `## 近年研究与工业界开源实践（2015–2026）`（star 由 `gh api repos/OWNER/REPO --jq '.stargazers_count'` 实测）
7. `## 常见误区与本书需修正之处`（表格 ≥5 行，🔧 标记需修正处）
8. `## 与其他章 / 其他书的联系`

> 校验结论：全部文件已用 Python 逐文件校验 `content.count('\ufffd') == 0`，无乱码；文中代码均为教学示意，不编译、不运行、不参与构建。本目录未执行任何 git 命令。
