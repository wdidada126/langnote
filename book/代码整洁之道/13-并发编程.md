# 第 13 章 并发编程

> **一句话**：并发是本书里**最短、最过时的一章**；它告诉你「同步区域要小、别让线程互相依赖」，但真正的并发知识需要专门的著作——**这恰恰是本书最大的缺口**。

## 核心精讲

> **教学示意，不参与构建、不编译、不运行。**

示例一：保持同步区域微小（13.7）。

```java
// 教学示意，不参与构建：反例 —— 锁里做 I/O，锁持有时间被外部拖长
public synchronized void process(List<Record> records) {
    for (Record r : records) {
        appendAuditLog(r);      // 慢 I/O 在锁里
        store(r);
    }
}

// 正例：临界区只包住「真正要保护的共享状态」
public void process(List<Record> records) {
    for (Record r : records) {
        AuditEntry entry = auditOf(r);        // 与锁无关的事放到锁外
        synchronized (this) { auditLog.add(entry); }
        store(r);                             // 不共享的部分不必加锁
    }
}
```

示例二：警惕同步方法之间的依赖（13.6）——两个「都安全」的方法凑起来死锁。

```text
# 教学示意，不参与构建：经典死锁的两个同步方法
方法 A：synchronized(lockA) { ... synchronized(lockB) { ... } }
方法 B：synchronized(lockB) { ... synchronized(lockA) { ... } }
```

修正：确定锁的**固定获取顺序**，或干脆让所有权单一（只在一个地方加锁）。

示例三：别用 sleep 测试并发（13.9）。

| 做法 | 评价 |
| --- | --- |
| `Thread.sleep(100)` 后断言结果 | 脆弱：CI 变慢、机器忙时偶发失败 |
| 循环重试若干次再断言 | 仍然是概率性的 |
| 用显式等待/条件变量/超时 API | 正确 |
| 用并发检测工具（TSan / ASan 类） | 正确且可复现 |

```python
# 教学示意，不参与构建：正确的等待姿势（显式等待而非睡一觉）
with Condition() as cv:
    cv.wait_for(lambda: not queue.empty(), timeout=5)
```

示例四：并发防御原则的可执行版本（13.3）。

| 原则 | 落地方式 |
| --- | --- |
| 先正确，后性能 | 先用最笨的加锁实现，通过测试后再考虑无锁 |
| 同步区域最小 | 只包住共享状态的读写 |
| 单一权威 | 一个资源只有一个管理者，别各处都加锁 |
| 别共享可变数据 | 优先用不可变数据与消息传递 |

## 常见误区与本书需修正之处

| # | 误区 / 需修正处 | 说明 | 修正建议 |
| --- | --- | --- | --- |
| 1 | 🔧 **把这一章当成本书的并发结论** | 它只有约 6 页正文，示例是 Java 5 之前的 `synchronized`/`wait/notify`，对内存模型、无锁、协程几乎不提 | 直接读并发专书（`book/C++并发编程实战2/`、`book/Java并发编程实战/`） |
| 2 | 🔧 **「先做正确的再优化」缺少可操作路径** | 没说「如何证明它正确」 | 用 TSan/ASan 检测 + 形式化推理 + 并发专书的正确性和算法 |
| 3 | 🔧 **13.9「用多种平台、多次运行」的测试建议不可靠** | 概率性测试不能证明正确性 | 用显式等待工具与竞争检测器，别靠多跑几次 |
| 4 | 🔧 **附录 A 的内容已严重过时** | 早期文章里对 JDK 内部行为的假设已不成立 | 只当作「并发直觉」的历史材料读，按现代版本重新验证 |
| 5 | 🔧 **几乎没提并发与代码整洁的关系** | 「锁住一片代码」会让 `03-函数.md` 的短函数与 `10-类.md` 的小类难以成立 | 优先设计成无状态/不可变数据，让并发只在明确边界内存在 |
| 6 | 🔧 **AI 生成并发代码是 bug 的重灾区** | LLM 常写出 `Thread.sleep`、锁里有 I/O、线程池未关闭的代码 | CI 挂竞争检测；禁止在业务代码里手写锁 |
