# 12 安全与权限

> 单元性质：⚠️ 主题重构。对应教材通行"Database Security & Authorization"单元。深度对照：[../数据库系统概念6/09-应用设计和开发.md](../数据库系统概念6/09-应用设计和开发.md)（其安全节散于建模/开发章）与 4.6 授权叙述；中文应试正源：../数据库系统概论.md 第 4 章（安全性）与第 5 章（完整性）——王珊册此二章是国内教材最系统的表述；工程威胁面另册：../The_Database_Hackers_Handbook（本波同批在建，未验名前不链）。

## 1. 安全目标与威胁面

CIA 三性（机密/完整/可用）落到数据库：未授权读（拖库）、未授权写（篡改）、拒绝服务（锁风暴/超大查询）。资产分级（个人数据/商业秘密/公开）+ 威胁建模（STRIDE 思路 ⚠️ 转述）先行——教材式立场：**安全是约束问题，完整性（03 章）是其友军**。

## 2. 自主访问控制（DAC）：GRANT/REVOKE 语用学

- **授权图（authorization graph）**决定权限流通：只有带 `WITH GRANT OPTION` 的授予才转发权力；REVOKE ... GRANT OPTION FOR / CASCADE 的撤环语义是教材必考细节。
- 粒度阶梯：系统权限（CREATE TABLE）→ 库/表 → 列 → 行（RLS）；视图作为"列+行裁剪"的古典手段（05 章视图的安全第二人格）。
- 🔧 现实对照：SQLite/DuckDB 均**无内建 GRANT 体系**（嵌入式引擎以文件权限为访问控制）——教材的 DCL 只能在服务器引擎演示；本目录用 SQLite 能实测的是"边界外移"：应用层按角色生成 SQL+视图，权限表自建模（`CREATE TABLE role_perm(...)` 即 03 章模型元话术的自反使用）。

## 3. 强制访问控制（MAC）与 RBAC

Bell-LaPadula（不上读/不下写，密级格）、Biba（完整性对偶）、**RBAC**（角色=权限集绑定，最小特权/职责分离——工业事实标准）；行级安全（PostgreSQL RLS 策略）是 DAC 的当代补票 ⚠️ 转述。教材价值：给"为什么视图不够"的形式答案。

## 4. SQL 注入：教材最长存的漏洞

成因=**把数据面语法混进控制面**（字符串拼接 SQL）；防线优先级：参数绑定（DB-API placeholder，🔧 exp1–exp5 全程示范的 executemany/占位写法是"结构免疫"的最小样本）> 存储过程/白名单校验 > 转义（易漏）。二阶注入（污染源入库后再拼接）、ORM 原生 SQL 片段拼接是现代复发点。王珊册不展开注入史，本段以工程口径补全（威胁全谱见同波安全册，待其落盘互链）。

## 5. 数据即资产：加密/脱敏/审计

- **传输** TLS、**存储** TDE/列级加密（🔧 SQLite 类比：community encryption extension/sqlcipher 为外挂加密页；标准库无加密——教材"DBMS 应有加密"在嵌入式默认缺席，恰证功能矩阵差异 ⚠️ 非本书引擎行为）。
- **脱敏**：动态掩码 vs 静态去标识（GDPR 匿名化 vs 假名化之辨 ⚠️ 法规细节不作断言）。
- **审计**：登录/对象访问/SQL 文本入审计日志；SQLite 类比可用触发器+审计表手工实现（`CREATE TRIGGER ... INSERT INTO audit`——🔧 机制可用，非产品级审计）。
- **推断控制**：统计数据库的合计泄露问题（小格泄露），教材保留的经典子题。

## 6. 完整性双翼（王珊第 5 章口径）

域/参照/用户自定义三类约束（03 章）即**数据完整性**的安全学名；触发器承担复杂业务约束（CHECK 跨表不能，触发器能——SQLite 触发器语法实测可用 ⚠️ 本目录未做专项脚本，属已知实验缺口）。安全性防"人害"，完整性防"错害"，两章合并读最省脑。

## 8. 常见错误清单

1. 给应用账号 DBA 权限（最小特权失守的头号形态）。
2. 用转义库"包打天下"防注入而不参数化。
3. REVOKE 忘记级联对授权图的断链后果。
4. 视图当安全墙却无定义者权限校验（DEFINER/INVOKER 语义混）。
5. 审计日志自身不设访问控制——灯下黑。

## 9. 小结

安全章是全书"责任三角"的第三角：03 约束保正确、09–11 保时间与故障、本章保**访问者**。权限语法会忘，授权图与最小特权不会过时；13 章将把"谁可看什么"升格为"跨节点一致的策略"。

## 10. 补充：注入实验的"正解/病解"对照组（🔧 SQLite 可跑）

病解演示（勿在生产模仿）：

```python
pw = "' OR 1=1 --"
cur.execute("SELECT * FROM users WHERE pass='" + pw + "'")   # 拼接：口令框变永真式+注释吞尾
```

正解同题：

```python
cur.execute("SELECT * FROM users WHERE pass=?", (pw,))       # 参数面与语法面物理隔离
```

- 观测点：拼接版返回全表（注入成功），绑定版返回 0 行——**同一恶意字符串，两种命运**。
- 二阶变体：把恶意片段先存入库（注册名带 `'`），再被另一条拼接语句读出——"数据面回杀控制面"，参数化同样免疫。
- 🔧 方法一句话：users 表+两行代码即可课堂复现；exp1 脚本的 executemany 占位写法就是"安全姿势"的日常形态（本目录已全程示范，非专项实验）。

## 11. 补充：授权图撤销推演（纸面 5 分钟）

初始：Alice --(SELECT, GRANT OPTION)--> Bob --(SELECT)--> Carol。
- `REVOKE SELECT ON r FROM Bob CASCADE;` → Bob 失权，其授予的 Carol 一并断（级联遍历授权图边）。
- `REVOKE GRANT OPTION FOR SELECT ON r FROM Bob;` → Bob 保留 SELECT 但失去转发权；Carol 的既有权**不回撤**（撤销不溯及，ARb 树剪枝只删"未来边"——各引擎语法支持不一 ⚠️ MySQL 家族有近似实现，转述）。
考点：任何 REVOKE 先画授权图再答级联集，空想必漏。

## 12. 补充讨论：完整性与安全的分界线（王珊双章口径）

| 维度 | 完整性（第 5 章） | 安全性（第 4 章） |
|---|---|---|
| 防的对象 | 差错/违规录入（意外） | 恶意访问（故意） |
| 机制 | 约束/触发器/断言 | 授权/视图/审计/加密 |
| 违约语义 | 状态不合法 | 访问不合法 |
| 共同地基 | 03 章"约束=可执行契约" | 授权=对操作的约束 |

两章合并的心法一句话：**完整性管"写进去的必须对"，安全性管"能写的必须是该写的"**。工程上二者在"谁有权改约束"处交汇（12 章权限×DDL 权限=治理顶点）。

## 13. 自测四问

1. 视图保护列的机制名称与前提？（列裁剪+定义者权限校验；前提是不再暴露底层表直连口。）
2. `GRANT ALL` 在托管云的隐性风险？（含 DROP/授权转发，违背最小特权；云 IAM 与库内权限双层都要收口。）
3. 为什么 ORM 不能自动免疫注入？（原生 SQL 片段/order_by/表名拼接仍在语法面——参数面只覆盖值绑定。）
4. 审计日志"该记什么"三要素？（主体×对象×动作+结果；加时间线与来源；日志本体需独立访问控制。）

## 核心概念速览（中英对照）

- **CIA triad** — 机密/完整/可用：安全目标三轴
- **DAC / GRANT / REVOKE** — 自主访问控制/授权/回收
- **WITH GRANT OPTION / 授权图** — 转授权权与权限流通拓扑
- **privilege** — 权限：对象×动作×传播位
- **MAC / Bell-LaPadula / Biba** — 强制访问控制：密级格与完整性对偶
- **RBAC** — 基于角色的访问控制：工业事实标准
- **row-level security (RLS)** — 行级安全：策略化视图
- **least privilege / separation of duties** — 最小特权/职责分离
- **SQL injection** — SQL 注入：数据面污染控制面的经典漏洞
- **parameterized query / prepared statement** — 参数绑定/预语句：注入的头号解药（🔧 exp1–5 姿势）
- **TDE / encryption at rest / in transit** — 透明数据加密/存储加密/传输加密
- **data masking / anonymization** — 脱敏/匿名化
- **audit trail** — 审计轨迹
- **inference control** — 推断控制：统计库泄露防线
- **integrity constraints as security** — 完整性即安全友军：CHECK/FK 的第二用途

## 最新演进与工业实践

- **权限即代码**：2024–2026 主流团队把 GRANT 迁入版本库（Terraform/grantctl 类），审计从"翻手册"变"读 diff"；概念教材的"DBA 手工授权"叙事正在退役。
- **RLS 平民化**：PostgreSQL RLS、Supabase 把行策略塞进应用脚手架；SQL:2023 前后"安全策略"语言元素持续增补 ⚠️ 细节以标准目录为准。
- **密钥外置化**：KMS/HSM 与"BYOK"成云默认，DBMS 内算法让位密钥治理——教材"DBMS 支持加密"一句已被重写成架构题。
- **注入面变迁**：LLM 生成 SQL 的提示注入（prompt injection）是经典注入的镜像变体，参数绑定纪律仍是唯一可教基线；SQLite 参数化 API 作入门演练场成本最低（🔧 本目录 exp 脚本可当"安全写法样板"）。
- **合规牵引**：个人信息保护法规把"访问日志留存/去标识"写成硬性工程件——教材审计小节的现实权重翻倍 ⚠️ 法规不作断言。
