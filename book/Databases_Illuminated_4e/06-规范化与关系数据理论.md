# 06 规范化与关系数据理论

> 单元性质：⚠️ 主题重构。对应教材通行"Relational Database Design / Normalization"单元。深度对照：[../数据库系统概念6/08-关系数据库设计.md](../数据库系统概念6/08-关系数据库设计.md)；中文应试口径：../数据库系统概论.md 第 6 章（关系数据理论）；理论全谱纵深：[../Database_Design_and_Relational_Theory/00-总览与阅读地图.md](../Database_Design_and_Relational_Theory/00-总览与阅读地图.md)；工程直觉版：[../Database_Design_for_Mere_Mortals_3e/00-总览与阅读地图.md](../Database_Design_for_Mere_Mortals_3e/00-总览与阅读地图.md)。

## 1. 坏设计的三种病：冗余派更新异常

教材开场病例：把"系地址"塞进教师表——插入异常（无教师则系无处登记）、删除异常（删最后教师丢系信息）、修改异常（改地址要扫全表冗余行）。规范化的目标不是省空间，是**让每个事实只落一处**（single source of truth）。

## 2. 函数依赖（FD）：形式化的尺子

X→Y：X 等值则 Y 必等值。术语装备：闭包 X⁺（推理的可达集）、覆盖（canonical cover，去冗余 FD 与多余属性）、平凡/非平凡、传递依赖、多值依赖（MVD，4NF 的钥匙）。Armstrong 公理（自反/增广/传递） SOUND 且完备——教材通常给证明梗概，Date 册给全程。

🔧 课堂可测法（本目录补位）：FD 判定纯数据可验——给实例找反例只要 `SELECT X, COUNT(DISTINCT Y)>1`；例如 exp1 库中 dept_id→dept_name 若在 `department(dept_id,dept_name)` 上聚合计数无违例即"该实例满足"，但**FD 是意图约束，不是数据巧合**——这一步恰好演示"约束（schema 级）≠ 实例性质（data 级）"（03 章契约观再落地）。

## 3. 范式阶梯

- **1NF**：属性原子（02 章多值属性的正解是拆表）。
- **2NF**：非主属性完全依赖候选键（防部分依赖，只对复合键有意义）。
- **3NF**：消除非主属性的传递依赖；等价定义"每个 FD 的左部是超键**或**右部是主属性"。
- **BCNF**：每个非平凡 FD 左部必超键——比 3NF 更严；3NF 合成保依赖、BCNF 分解可能丢依赖（教材必讲的取舍定理）。
- **4NF/5NF**：MVD 与连接依赖——教材常点到为止，考试重点在 BCNF。

记忆主轴：**左超键则 BCNF；右主属性可豁免成 3NF**。

## 4. 分解的两大正确性判据

- **无损连接（lossless join）**：R1∩R2 → R1 或 R2（ chase 测试/直接判据）。丢了这个，重新 JOIN 会造出幽灵元组。
- **依赖保持（dependency preserving）**：π(FD 集) 的覆盖并集等价原集。丢了这个，违约检测要跨表全连接。
- 算法装备：BCNF 分解（可能不保依赖）→ 补救加回丢的依赖所在投影；3NF 合成（无损+保依赖，一次到位）。

## 5. 反规范化：工程对理论的赎买

读多写少的报表/分析场景刻意冗余（预 JOIN、缓存列、物化视图），代价是 0 节的三种病回归+同步维护（触发器/应用/ETL 三选一）。教材立场通常是"先规范化到位，再按测量证据定点反规范"（与 07/08 章的性能动机衔接）。OLAP 星型模式天然反规范（13 章）——规范化理论在数仓的"失效"是有意为之。

## 6. 教学病例演练（可跑）

经典病例：SC(学号,课程号,成绩,教师名,教材)，{学号,课程号}→成绩、课程号→教师名、课程号→教材——教师名对键部分依赖+传递依赖。分解：SC1(学号,课程号,成绩)+Crs(课程号,教师名,教材)，无损且保依赖，达 BCNF。此结构与 exp1 三表（学生选课场景的教师-系版）同构，改表名即可用 SQLite 复算；约束执法（PK/FK）由 🔧 exp1 语料背书。

## 7. 与两本主线教材的口径差

- 概念6：以"坏设计剖析→FD→BCNF/3NF 算法"为主干，强调 BCNF 分解丢依赖的构造例。
- 王珊：术语"最小依赖集 Fmin"、判定 3NF 用"每个依赖左超键或右全主属性"的 3NF 定义定理形式，考研按它写。
- 本册（教材向美式）：病例驱动+大量练习，理论深度低于前两者——本目录以 🔧 数据验 FD 补其"形式化练习不足"。

## 8. 常见错误清单

1. 拿单个数据实例"证明"FD 成立（巧合 vs 意图）。
2. 3NF 判定漏"右部主属性"豁免支。
3. BCNF 分解后忘检查依赖保持，约束退化成应用自查。
4. 把"多值依赖"理解为"多列依赖"（MVD 是对称的 X→→Y|Z 互补结构）。
5. 无证据反规范（先测再冗余，08 章优化器视角）。

## 9. 小结

规范化=用依赖语言把"设计好坏"变可判定；分解算法给构造性出路；工程以反规范化赎买理论。设计三章（02 建模→03 模型→06 理论）闭环后，转入"跑起来"的物理篇（07/08）。

## 10. 补充：FD 验证的 SQL 化（🔧 可在 exp1/exp4 库上跑）

给定 X→Y 意图，违例探测模板：

```sql
SELECT X, COUNT(DISTINCT Y) c FROM R GROUP BY X HAVING c > 1;   -- 空结果=该实例暂不违例
```

- 在 exp1 `department` 上跑 dept_id→dept_name：空结果（键依赖天然成立）。
- 在 exp4 `sales` 上跑 region→product：非空（一个 region 多 product），故 region→product **不成立**——学生由此亲手得到"哪些 FD 是巧合、哪些真被违反"的分寸感。
- 再验"巧合 vs 意图"：手动改一行制造违例，体会约束应上移 schema（04 章执法对象）。

## 11. 补充：范式判定速查（考试口径统一）

| 目标 | 一句话判据 | 常见翻车 |
|---|---|---|
| 2NF | 非主属性不部分依赖任一候选键 | 单键表自动满足（无部分可言） |
| 3NF | 每个 FD：左超键 或 右主属性 | 忘"或"支，误把 3NF 表判 BCNF 违例 |
| BCNF | 每个非平凡 FD 左必超键 | 多候选键循环依赖表（经典 3NF≠BCNF 例）要逐个验证 |
| 4NF | 无非平凡 MVD 除非左超键 | 把"一对多"当 MVD；MVD 的互补对称性要先画 |

王珊册的 Fmin 三步（右部单属性化→去左冗余→去冗余 FD）与概念6 的 canonical cover 同术异名，考研写 Fmin、读论文认 cover，本目录两词并注。

## 12. 补充讨论：规范化的边界案例三则

1. **历史表/审计表**：天然冗余（快照即目的）——规范化假设"事实唯一"被业务显式弃权。
2. **树形结构**：闭包表（closure table）以"多行路径事实"换无递归查询，路径表冗余是设计而非失误。
3. **多语言内容**：`article(id,lang,title)` 主键 (id,lang)——同一实体的不同语言版本是不同事实，规范化会保住它，反规范（JSON 列存翻译）则属 14 章契约再谈判。

## 核心概念速览（中英对照）

- **functional dependency (FD)** — 函数依赖：X→Y 的意图约束
- **closure (X⁺) / canonical cover** — 属性闭包/正则覆盖：推理可达集/去冗余等价集
- **transitive dependency** — 传递依赖：3NF 要消灭的对象
- **multivalued dependency (MVD)** — 多值依赖：4NF 的尺子
- **1NF/2NF/3NF/BCNF/4NF** — 范式阶梯：左超键收紧链
- **lossless join decomposition** — 无损连接分解：不造幽灵元组
- **dependency preserving** — 依赖保持：违约可局部检测
- **BCNF decomposition** — BCNF 分解：无损但可能丢依赖
- **3NF synthesis** — 3NF 合成：无损+保依赖的覆盖算法
- **decomposition rule X→Y: R1(XY), R2(R−Y∪X)** — 标准二分式：交集即决定性
- **denormalization** — 反规范化：以测量为赎买凭证的性能冗余
- **update anomaly（插入/删除/修改异常）** — 更新异常三兄弟：坏设计的病征
- **schema-level vs data-level** — 模式约束 vs 实例巧合：FD 判定的分界线

## 最新演进与工业实践

- **规范化在分析域的退场与返场**：2024–2026 数据仓库主流仍是星型/宽表（反规范化），但"数据契约+dbt 分层"把规范化重构成 staging→intermediate→marts 的**层级依赖**（[../Analytics_Engineering_with_SQL_and_dbt 目录](../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md) 有同题讨论）。
- **函数依赖自动发现**：元数据工具（Metanome 等 FD 挖掘器）用于逆向工程遗留库——把本单元的"给 FD"变成"从数据挖 FD 候选再人审"，学界活跃、工业零星 ⚠️ 工具现状以项目仓库为准。
- **键约束的工程执法**：SQL:202x 讨论中的 KEY 声明（声明性键不强制）与 PG 的 NOT ENFORCED FK 同源——理论约束与物理执法分离化，正呼应本单元"约束=意图"的立场。
- **教材互参**：3NF/BCNF 判定例题以王珊第 6 章口径应考最稳；Date 册给出完备性与希思（Heath）定理证明（其 05 章"函数依赖与 BCNF 正式与希思定理"）。
