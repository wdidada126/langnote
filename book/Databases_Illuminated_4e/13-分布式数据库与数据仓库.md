# 13 分布式数据库与数据仓库

> 单元性质：⚠️ 主题重构。对应教材通行"Distributed Databases / Parallel Databases / Data Warehousing"三章的合并单元。深度对照：[../数据库系统概念6/17-数据库系统体系结构.md](../数据库系统概念6/17-数据库系统体系结构.md)、[../数据库系统概念6/18-并行数据库.md](../数据库系统概念6/18-并行数据库.md)、[../数据库系统概念6/19-分布式数据库.md](../数据库系统概念6/19-分布式数据库.md)、[../数据库系统概念6/20-数据仓库与数据挖掘.md](../数据库系统概念6/20-数据仓库与数据挖掘.md)；中文对照：../数据库系统概论.md 第四篇；分布式总纲：[../分布式系列·总索引.md](../分布式系列·总索引.md)。

## 1. 为什么分布：三动机两代价

动机：地理就近（延迟）、规模分担（容量/吞吐）、可用性冗余（容灾）。代价：分布式事务协调、异构与目录管理、部分故障的语义噩梦。教材式定义：分布式数据库=**地理分散、逻辑统一**的数据库系统——"逻辑统一"是它与"一堆数据库"的分界。

## 2. 透明性阶梯与体系结构

分片透明>位置透明>局部映射透明（三级透明度）；客户端/中间件/服务器分层：两阶段（远程数据模型：把 SQL 搬到数据处）→三阶段（SQL 服务器架构：查询执行上移中间件）→目录服务（全局视图维护）。异构（联邦 database）与同构之别，中介（middleware/wrapper）为异构解药——⚠️ 教材传统在此停留较多，工业已被"云托管同构分片"替代大半。

## 3. 分片与复制（fragmentation & replication）

分片：水平（谓词切行）、垂直（投影切列）、混合；分片正确性三条件：完备/不交/可重构（第 06 章分解判据的分布式孪生）。复制：全复制/部分复制；读写权衡——**写放大换读局部性**；复制引发的更新传播（快照/更新段协议）是旧派协议，现代对应：主从复制+延迟（14 章 Dynamo 线）。

## 4. 分布式事务：2PC 与其伤

全局事务=跨分片事务；**两阶段提交（2PC）**：prepare（投票）+commit（决定），协调者单点+阻塞窗口（参与者永久等待）为两大罪；3PC 试图解阻塞但依赖故障模型假设，工业罕见。可用性视角：Quorum（N,R,W 且 R+W>N）给复制读写的一致性参数化；失败模型谱（崩溃/拜占庭）点到。🔧 类比锚（非分布式实现）：exp3 实测的 SQLite 库级写锁是"单协调者"直觉的极限简化——写者排队、无 prepare 阶段；真正的"提交结果未知"问题（09 章幂等重试的动机）在分布式才全面爆发。

## 5. 并行数据库（教材 18 章浓缩）

共享内存/共享磁盘/无共享（SN）三架构；数据分区（轮转/范围/哈希）+算子内/算子间并行；**倾斜（skew）**是并行杀手；Gather/分发原语。DuckDB 单进程 morsel 并行（🔧 exp5 百万行聚合 3.8ms 属该世代单机并行样本）——"单机的并行"与"分布的并行"在此接吻。

## 6. 数据仓库：面向分析的重构

特征：面向主题/集成/非易失/时变（Inmon 口径）；OLTP vs OLAP 差异表（粒度/模式/更新/用户/度量）；**星型/雪花/星型串**：维表反规范化（06 章的有意赎买）、事实表挂度量键；**OLAP 操作**：上卷/下钻/切片/切块；物化视图立方体与"查询改写"（8 章预计算的规模版）。ETL：抽取（异构源）/清洗（完整性回归）/变换（一致性维度）/加载（增量/全量）——现代演化 ELT（先加载后变换，仓内 SQL 做清洗，dbt 是旗手：../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md）。

## 7. 数据挖掘与衍生物

关联规则（Apriori，支持度/置信度）、分类聚类回归基础、文本/图挖掘概览——教材此节在 2024–2026 已被 ML 平台吸收（特征仓/向量检索），本目录保留概念词表不展开算法。

## 8. 常见错误清单

1. 把分片当备份（分片不增可用性，复制才增）。
2. 以为 2PC 保证原子性就顺带保证可用性（阻塞窗口=可用性洞）。
3. Quorum 条件写成 R+W≥N（应为 >N 的严格式；等号允许不一致）。
4. 星型模型硬塞多对多桥接事实却不声明粒度。
5. 数仓时变性误解为"不许 UPDATE"——实为版本/追加语义（SCD1/2 概念 ⚠️ 教材有、术语口径各异）。

## 9. 小结

分布式答"数据放多处"，数仓答"数据换形状"；两者共享一条元律：**一致性是可调预算，不是布尔开关**——14 章 NoSQL 把这条律推到极致。

## 10. 补充：2PC 最坏时刻的逐帧推演

```
T: 协调者 → 参与者A/B: prepare?
   A: 写日志"承诺" 回 YES      （A 已无法反悔，锁不放）
   B: 写日志"否定" 回 NO
   协调者决定 abort → 通知 A/B
故障窗口①：协调者在"决定后、发送前"崩溃 → A 持 prepared 悬案，
   恢复后协调者从日志找回决定再补发（决定必须落盘=2PC 的 11 章依存）。
故障窗口②：网络分区致 A 收不到 → A 永久阻塞（既不能提交也不能放弃）
   ——这就是"2PC 牺牲可用性"的全部内涵；3PC 用超时+多数决缓解，
   但其安全成立依赖"消息丢失率有界"假设，工业基本弃用 ⚠️ 转述。
```

自测：数出"参与者已写承诺但未收到决定"的秒数=你的 RPO 谈判筹码。

## 11. 补充：分片正确性三条件的 SQL 验法

完备（每条元组至少入一片）/不交（至多一片）/可重构（并/JOIN 回原像）。水平分片 `day<20230101 | >=20230101`：不交显然、完备显然、可重构=UNION ALL；垂直分片在"重复主键列"处才可重构（06 章 Heath 定理的分布式投影）。🔧 单机演练法：把 exp4 的 sales 按 day 二分导出两张表，`UNION ALL` 后与全表做 EXCEPT 双向对拍=可重构的实证（分钟级，可入课堂）。

## 12. 补充：星型 vs 规范化的决策表

| 判据 | 星型胜出 | 规范化胜出 |
|---|---|---|
| 读/写比 | 极高 | 均衡 |
| 查询形态 | 聚合+切片 | 点查+事务 |
| 一致性责任 | ETL 批次 | 引擎约束 |
| 演化成本 | 加度量易/加维慎 | 加表易 |
| 代表栈 | 仓+BI | OLTP 应用库 |

一句话收束 06 章与本单元的张力：**规范化是 OLTP 的语法课，星型是 OLAP 的修辞术**。

## 13. 自测四问

1. 位置透明与分片透明的用户可见差异？（前者只见"库名"、后者连"片"都不知道；分片透明最高。）
2. 全复制读扩展但写代价？（写放大=N，且同步等待收敛=提交延迟上界；异步则回到 14 章最终一致。）
3. Quorum N=5,R=3,W=3 容几台失效？（最多 2 台仍读写可用；W+R=6>5 交集非空——参数化的容灾数学。）
4. 雪花是"数仓里的 3NF"吗？（形似而神异：雪花的规范化是为维复用与一致性，不是为更新异常——06 章目标函数整体换掉。）

## 核心概念速览（中英对照）

- **fragmentation (horizontal/vertical)** — 分片：切行/切列，完备-不交-可重构
- **replication / full vs partial** — 复制：写放大换读局部性
- **transparency levels** — 透明性阶梯：分片/位置/局部映射
- **SQL-server architecture** — 三阶段架构：查询执行上移中间件
- **federated database** — 联邦库：松散自治+中介集成
- **two-phase commit (2PC)** — 两阶段提交：prepare 投票+commit 决定
- **coordinator blocking** — 协调者阻塞：2PC 的可用性原罪
- **quorum (R+W>N)** — 法定数：复制一致性的算术
- **shared-nothing (SN)** — 无共享架构：并行主流底座
- **intra-/inter-operator parallelism** — 算子内/间并行
- **data skew** — 数据倾斜：并行长尾病根
- **OLAP vs OLTP** — 分析/事务双形态：粒度与度量之别
- **star / snowflake schema** — 星型/雪花：维表反规范化骨架
- **roll-up / drill-down / slice / dice** — 上卷/下钻/切片/切块
- **ETL / ELT** — 数据加载两范式：仓外/仓内变换
- **SCD** — 缓变维：时维度的工程化 ⚠️ 口径以厂牌为准

## 最新演进与工业实践

- **湖仓（Lakehouse）吃仓**：Delta/Iceberg/Hudi 表格式把数仓语义（ACID、模式演进）叠到对象存储；"星型还是宽表"之争在 2024–2026 被"表格式+变长 schema"改写（盘上专册：Delta_Lake_Definitive_Guide、Apache_Hudi_Definitive_Guide、Apache_Iceberg活用入門 等，见总索引）。
- **存算分离为云默认**：Snowflake/BigQuery/Redshift 的分离架构让 18 章"三架构"叙事进入第四格——共享存储+弹性计算 ⚠️ 转述。
- **NewSQL 接 2PC 班**：CockroachDB/TiDB 用 Raft-group 复制+跨分片事务协议取代经典 2PC 单协调者——本单元概念仍是最短理解路径。
- **dbt/分析工程**：ETL 的"清洗/变换"以版本化 SQL 模型落地（[../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md](../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md)）；治理线（Data Mesh）把"数仓团队"解构为域自治（[../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md)）。
- **DuckDB 现象**：单机列式并行+对象存储直读（httpfs）让"教材级并行数据库实验"零集群成本可跑——🔧 exp5 即证。
