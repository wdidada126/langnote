# 08 查询处理与优化

> 单元性质：⚠️ 主题重构。对应教材通行"Query Processing & Optimization"单元。深度对照：[../数据库系统概念6/12-查询处理.md](../数据库系统概念6/12-查询处理.md)、[../数据库系统概念6/13-查询优化.md](../数据库系统概念6/13-查询优化.md)；中文对照：../数据库系统概论.md 第 15 章（查询处理与优化）；专册纵深：../数据库查询优化器的艺术.md。

## 1. 查询处理流水线

解析（词法/语法→语法树）→ 翻译（→代数表达式）→ **重写**（恒等变换：谓词下推、投影下推、常量折叠）→ **优化**（代价模型选物理算子与顺序）→ 执行（火山模型 iterator：open/next/close）。教材把"逻辑等价变换的合法性"当第一原理：JOIN 可交换/可结合、σ 可下推可串接、π 可合并——重写的每一步都必须保语义。

## 2. 物理算子选择

- **选择**：全扫（小表/高命中率）、索引扫（07 章 exp4 的 SEARCH）、位图交。
- **连接**：嵌套循环（NL）/块嵌套、**索引嵌套循环**（一侧小+另一侧有索引时近乎最优）、排序归并（SMJ，两侧预排后线性）、**哈希连接**（HJ，建小侧哈希桶再探测）。选择律：结果规模×内存×是否需保序。
- **聚合**：哈希聚合 vs 排序聚合；外排序（多路归并，页数/缓冲块数决定路数）是"内存溢出算法"的原型教材案例。

## 3. 代价模型：统计→基数→成本

统计摘要（N、块数、不同值 V(A)、直方图）→ 中间结果基数估计 → 代价=I/O 主导+CPU 项。等值选择按 1/V、范围按比例（教材简化线性假设）。**经典失效现场：单表多谓词独立性与相关列冲突**——exp4 的 `region='R3' AND amount>450` 若两列相关，独立假设就偏；这也是 07 章复合索引列序"先等值后范围"的代价论理由。基数误差沿 JOIN 树指数放大，是"计划突变（plan flip）"的病根。

## 4. 连接顺序搜索

动态规划（System R 下行线性链优先的子集枚举）/贪婪（一阶启发式：贪心选最便宜对）/随机+搜索剪枝；子查询去相关（unnesting：把相关子查询翻成 JOIN/半连接）是教材"优化器改写力"的招牌案例。

## 5. 🔧 用 EXPLAIN 把本章读"实"

SQLite 的 `EXPLAIN QUERY PLAN` 是教材级简化窗（exp4 实录：SCAN/SEARCH 与 USING COVERING INDEX、(region=? AND amount>?) 括号即索引列使用序）。自测实验建议（可加进 exp4 脚本）：

- 对两表 JOIN `teach⋈department`：有 PK/FK 索引时计划呈现 `SEARCH department USING ... (dept_id=?)` 驱动的嵌套——观察 SQLite 把小表放外侧；
- DuckDB `EXPLAIN` 输出可见 ORDER BY/LIMIT 下推与哈希聚合选择 ⚠️ 本目录对 DuckDB 计划仅定性转述，未做逐算子计时。

**工程戒律**：永远以 EXPLAIN 为准，不以"加了索引就快了"为信仰——07 章 exp4 中非前缀列 product 谓词"索引在手仍全扫"即为证。

## 6. 物化视图与预计算

把"每次算"换成"存着+维护"：物化视图/汇总表/缓存层；维护时机（即时 vs 批量刷新）与一致性（读到的可能旧）是权衡三角。教材传统一笔带过；现代对应：数仓汇总层与增量刷新（13 章衔接，dbt 物化模型同思想）。SQLite/DuckDB 均无原生物化视图 ⚠️——用生成列+表+触发器手工模拟，恰是"机制缺失暴露概念边界"的好练习。

## 7. 查询计划缓存与参数化

PREPARE/参数绑定防注入且促计划复用（12 章安全联动）；计划缓存失效与统计更新联动（"ANALYZE 后再看计划"的工程日常）。🔧 exp1–exp5 全部使用参数绑定写法——顺带演示 DB-API 的正确姿势。

## 8. 常见错误清单

1. `WHERE f(col)=常数` 杀索引（改写为逆运算或用表达式索引）。
2. `SELECT *` 阻碍覆盖索引（投影列没进索引就得回表）。
3. 左前缀违规：把范围条件列放在复合索引前部（exp4 实测 product 教训）。
4. 大 OFFSET 分页（`LIMIT 10 OFFSET 100000` 线性代价，改键集分页）。
5. 信"提示（hint）"不信统计——先修统计再谈 hint。

## 9. 小结

本章是"用户声明式 SQL→引擎过程式执行"的翻译官视角；与 07 章构成"结构×调度"对偶：索引是给优化器的词汇表，优化器是把词汇排成句法的作者。下章换维度：时间中的正确性（09/10/11 三部曲）。

## 10. 补充：一条查询的全程解剖（把本章读薄）

`SELECT s.name, AVG(g) FROM enroll e JOIN student s ON e.sid=s.id WHERE e.course='C101' GROUP BY s.name HAVING AVG(g)>80 ORDER BY 2 DESC LIMIT 5;`

- 重写：course 谓词下推到 enroll 扫描；投影砍列（学号/成绩之外不留）。
- 物理选择：enroll 有 (course) 索引则 SEARCH+索引嵌套连接；无索引则小表哈希连接。
- 聚合：哈希聚合为主；ORDER BY+LIMIT 可"Top-N 堆"消解全排序（比较次数 n·log5 级别）。
- 计划核对（🔧 方法）：同题在 SQLite 跑 `EXPLAIN QUERY PLAN` 看 USE TEMP B-TREE FOR ORDER BY 是否出现（出现=尚未 Top-N 化）；在 DuckDB `EXPLAIN` 看 HASH_GROUP_BY 与 TOP_N 节点名——**两引擎计划词汇不同但算子族一一对应**，这正是本章"物理算子选择"的活体双语教材。

## 11. 补充：统计信息实验设计（exp4 延伸，可跑）

1. 建表灌 30 万行但**不跑 ANALYZE**：观察 SQLite 默认估算（无统计时按常数猜）对计划选择的影响；
2. `ANALYZE` 后再看：直方图/`sqlite_stat1` 出现，等值估基数变为 N/V；
3. 改数据 10 万行不更新统计：计划仍用旧 V——"统计过期"现场。
   🔧 这三步只需在 exp4 脚本上追加 `ANALYZE`/重插/对比 `SELECT * FROM sqlite_stat1`，10 分钟内完成；结论一句话：**索引是枪，统计是瞄准镜**（⚠️ DuckDB 侧统计为自动采样维护，实验仅 SQLite 可做完整对照）。

## 12. 自测四问

1. 谓词下推为何永远语义安全而连接交换有时不？（σ 可交换可串接；外连接不满足交换律——把 LEFT JOIN 换序前先问保留侧变没变。）
2. 索引嵌套连接何时劣于纯嵌套循环？（内表索引命中率低/结果集大时，随机 I/O 税反超顺序扫——exp4 的 1/10 选择率临界感。）
3. 半连接（EXISTS）为何通常无需全投影？（找到一行即停，短路语义；计划里体现为 "USING EXISTS" 早停节点 ⚠️ 各引擎措辞异。）
4. 基数估 10 倍偏差在三层 JOIN 树上意味着什么？（错误沿路径相乘：10→100→1000，计划从"最优"翻到"最劣"可能只差一个 JOIN 序——plan flip 的算术。）

## 核心概念速览（中英对照）

- **query pipeline** — 查询流水线：解析→重写→优化→执行
- **volcano / iterator model** — 火山模型：open/next/close 拉式执行
- **predicate pushdown** — 谓词下推：最早过滤原理
- **nested-loop / index-nested-loop join** — 嵌套循环/索引嵌套连接
- **sort-merge join (SMJ)** — 排序归并连接：预排+线性合并
- **hash join (HJ)** — 哈希连接：建桶+探测，分析引擎主力
- **external sort** — 外排序：多路归并溢出内存原型
- **cardinality estimation** — 基数估计：代价模型的心跳
- **statistics / histogram / V(A)** — 统计/直方图/不同值数：估计的原料
- **independence assumption** — 独立性假设：多谓词连乘的隐含赌注
- **join order enumeration (DP/greedy)** — 连接序枚举：DP 与贪婪
- **query unnesting** — 子查询去相关：相关子查询→连接改写
- **EXPLAIN QUERY PLAN (SCAN/SEARCH)** — 执行计划：🔧 exp4 的判读指纹
- **materialized view** — 物化视图：预计算与维护权衡
- **plan cache / prepared statement** — 计划缓存/预备语句：绑定参数的复用面

## 最新演进与工业实践

- **学习型基数估计与自适应计划**（2024–2026）：Lero/Kairos 系学术线与云仓"adaptive query execution"（运行时重优化）并进；经典代价模型仍是教材唯一可教基线 ⚠️ 论文细节以原刊为准。
- **向量化与 Morsel 并行**：DuckDB 的 morsel-driven 执行（🔧 exp5 百万行 GROUP BY 3.8ms 属该世代产物，作为"每行迭代模型"的对照标本再合适不过）。
- **LLM+SQL**：Text-to-SQL 把"会优化"降级为"会核对"，EXPLAIN 判读成为数据工程师新的日常素养；教材此章价值从"写得快"转向"审得准"。
- **计划固定（plan freezing/hint 表）**：Oracle SQL Plan Management、PG pg_hint_plan 等工业手段应对 plan flip——教材未写的运维侧，可与 [../数据库系统概念6/13-查询优化.md](../数据库系统概念6/13-查询优化.md) 互补阅读。
