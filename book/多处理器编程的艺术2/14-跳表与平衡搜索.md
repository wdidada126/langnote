# 第 14 章 跳表与平衡搜索

> **一句话**：跳表是唯一能被又快又优雅地做成**线性一致并发版本**的平衡搜索结构——因为它的局部性只依赖相邻节点，不需要像红黑树那样做全局旋转。

## 14.1 核心精讲：跳表的并发友好性

### 串行跳表（Pugh 1990）

节点高度按几何分布随机生成：第 i 层的节点数以 `1/p` 递减（常用 `p = 1/2` 或 `1/4`），查找从顶层从左向右、必要时降级。期望查找/插入/删除 `O(log n)`，**无需再平衡**。

```java
// 教学示意：高度随机生成（p = 1/2），不参与构建
int randomHeight(Random r) {
    int h = 1;
    while (r.nextInt() < 0x4000_0000 && h < MAX_LEVEL) h++;  // p = 1/4 的一种写法
    return h;
}
```

### 为什么它比红黑树更适合并发

红黑树插入后要旋转/变色，涉及的祖先路径可能一直到根；并发化必须锁住整条路径或用 MCAS。而**跳表的插入只改动每层一个前驱指针**，且层级之间互相独立 → 天然适合逐层 CAS 地做成无锁版本。

| 结构 | 并发化的难点 | 常见做法 |
| --- | --- | --- |
| AVL/红黑树 | 再平衡波及祖先 | 路径加锁；或用 relaxed AVL 树放松平衡约束 |
| B+ 树 | 节点分裂/合并向上传递 | B-link 树（加 right-link）+ 乐观下降；现代代表是 Bw-tree（Delta 更新，ICDE 2013） |
| **跳表** | 只需要改前驱单指针 | 惰性删除 + 乐观/无锁 CAS |

### 删除必须三元组：`marked` + `fullyLinked`

并发跳表复用 Ch9 惰性链表的模式，但**多了一个状态**，因为插入要先把 `k` 层指针逐个 CAS 完成：

```
节点状态：
  fullyLinked=true ∧ marked=false  → 有效节点，可服务于查找
  fullyLinked=false              → 插入尚在进行中的「部分链接」中间态
  marked=true                     → 已逻辑删除，等待解链
```

`find()` 返回三元组 `(preds, succs, nodeIsOK)`：

```java
// 教学示意：抽自 ConcurrentSkipListMap 思路的伪码
int find(T key, Node[] preds, Node[] succs) {
  retry:
    Node pred = head, curr = null, succ = null;
    for (int level = MAX; level >= 0; level--) {
        curr = pred.next[level];
        while (true) {
            succ = curr.next[level];
            while (curr.marked) {                    // 跳过被删除节点
                curr = curr.next[level];             // （真实实现中还需要截断/解链）
                succ = curr.next[level];
            }
            if (curr.key < key) { pred = curr; curr = succ; }
            else break;
        }
        preds[level] = pred; succs[level] = curr;
    }
    return (curr.key == key) ? 1 : 0;                // 找到与否
}
```

**线性化点**：
- `add` → `fullyLinked = true` 那一步（此前 CAS 去的指针只是「部分可见」但不参与查找语义）；
- `remove` → 成功的 `marked = true`；
- `contains` → 读到一个未被标记且已完全链接的节点。

## 14.2 版本演进

| 阶段 | 代表 | 特点 |
| --- | --- | --- |
| 1990 | Pugh 串行跳表 | 单线程；队列/ MemTable 的经典选择 |
| 2000s | 惰性跳表（本书 Ch14） | `marked` + `fullyLinked`，阻塞式 write 锁但查找无锁 |
| 2004 | Fomitchev & Ruppert **无锁跳表**（PODC 2004） | 第一次给出完全 lock-free 的版本，但算法复杂（带 Hipp 'back-link'） |
| 2007 | Fraser & Harris（TOCS 2007） | 用 **MCAS（多位置 CAS）** 统一处理，代码干净、可投产 |
| 2011+ | Herlihy-Lev-Lychkina-Shavit 可证明正确的可扩展跳表 | 直接进本书第 2 版；给出线性一致性形式化证明 |

## 14.4 近年研究与工业界开源实践（2015–2026）

**研究侧**：

- **放宽线性一致性换取吞吐**：SprayList（PPoPP 2015，Alistarh / Kopinsky / Li / Shavit）把跳表用作优先队列的前端并允许「不完全最优先」；这是下一章的主角。
- **分布线性化（Distributional Linearizability）**：PODC 2018，允许 `deleteMin` 返回近似最小但保证随机分布，用于 Relaxed 结构。
- **持久内存（PMEM）上的跳表**：相关工作把 CAS 换成 `libpmemobj` 的事务式持久化，需要额外处理**flush 顺序**（`CLWB` + `SFENCE`）与崩溃后的恢复；可参考 PMDK 生态与持久索引（如 *RECIPE*，SOSP 2019）的工作。
- **形式化验证常态化**：近年 VerCors / Iris / RC11 相关工作把本书 Ch14 的惰性跳表当作 «标准测试题» 反复验证（无锁结构 ⇒ model checking 不可行，改用具型分离逻辑）。

**工业实现**：

- `openjdk/jdk`（≈**23.4k★**）：`ConcurrentSkipListMap` / `ConcurrentSkipListSet`，Doug Lea 的实现。**index 头节点 → 顶层 head circles**，查找永远无锁，插入用 CAS 加前行，删除标记后延迟解链。
- `facebook/rocksdb`（≈**32.1k★**）：MemTable 的默认结构是跳表，` db/skiplist.h` 里同时维护**三种变体**：普通、支持并发写插入、以及 **Hash SkipList**（先哈希再排序，降低高度）。近版本还支持 `ConcurrentHash MemTableRep`。
- `redis/redis`（≈**76.5k★**）：有序集合（zset）的 ` zskiplist`；单线程执行，因此不需要并发版本，但它的**随机层数分配 / span 字段**（支持 O(log n) rank 查询）是学习串行实现的优秀读物。
- `efficient/libcuckoo`（≈**1.7k★**）、`rust-lang/hashbrown`（≈**3.0k★**）：虽然不是跳表，代表了另一条路线——哈希表 + SwissTable 的 SIMD 探测；工业界往往是「是否需要有序」决定跳表 vs 哈希表。

## 14.5 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「跳表一定比平衡树快」 | 查找上跳表指针追逐（pointer chasing）多、缓存命中差；**红黑树/B-tree 在纯读场景下常常更优**。优势在于实现简单 + 并发化成本低 |
| 2 | 「`ConcurrentSkipListMap` 是无锁的」 | 其插入路径并不是 wait-free；它只是**查找无锁**，CAS 失败会回到 trying 从头重试 |
| 3 | 「删除只标 marked 就结束了」 | 还必须**解链/截断**（unlink），否则被删节点的 index 层会残留在结构里，长时间运行后退化成链表 |
| 4 | 「高度随机就不需要边界」 | 必须给 `MAX_LEVEL` 设上限且与 `log1/p(N)` 匹配，否则长尾节点既浪费内存又拖慢查找 |
| 5 | 🔧 本书未覆盖持久内存 | 在 NVM 上，`CAS 成功` ≠ `已持久化`；还需要 flush + fence，且复用节点需跨崩溃一致（参见 Dozens 2020s 的 pmem skip list 工作） |
