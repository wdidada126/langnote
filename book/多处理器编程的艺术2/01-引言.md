# 第 1 章 引言

> **本章地图**：为什么本书是必然产物（时钟频率停滞 → 多核成为唯一出路）→ 线程/锁/原子对象的抽象 → **一个可跑份额的度量方法**（提速比 vs 可扩展性）→ 并行素数筛与并行 Fibonacci 两个「反例」（说明并行≠更简单）→ Amdahl 定律与 Gustafson 定律 → 全书共存的两个主题：**正确性**与**可扩展性**。

## 二、核心精讲

### 1.1 本书的动机：多核时代的必然产物
- 单核性能增长停滞（功耗墙 / 指令级并行的收益耗尽），**所有性能收益都要靠并行**。
- 🔧 2026 视角补充：如今连**单核**都在靠 SIMD/推测执行提升，但真正的量级提升来自 **GPU / DSA / 众核**；本书的共享内存模型依然是 CPU 侧多线程的标准语汇。

### 1.2 Fork/Join 式线程模型与共享对象
- 线程共享地址空间，通过**对象（object）**协调。并发对象 ≠ 单纯加锁：需要根据竞争强度选择阻塞（blocking）或非阻塞（nonblocking）实现。
- 本书追求：**既正确（correct）又可扩展（scalable）**。
  - **正确性**： quiescent consistency / sequential consistency / **linearizability**（Ch3）
  - **可扩展性**：吞吐量随线程数增长的能力（Ch7 争用 + Ch12 组合 + Ch19 内存回收）

### 1.3 提速比度量 — 三个版本的质量差异
一个 **counting all 2/3 the primes up to 10^7** 的 benchmark，本书用三个版本诠释「并行很容易，也容易并行得糟糕」：

```java
// （教学片段，不参与构建）
// 版本一：串行 — 慢，但是 baseline
public static boolean isPrime(int x) {           // 判定素数的串行实现
    if (x <= 1) return false;
    for (int i = 2; i * i <= x; i++) if (x % i == 0) return false;
    return true;
}

// 版本二：所谓「并行」 — 共享一个 static 计数器，即使它 AtomicInteger 也会把 → 性能搞塌
static AtomicInteger counter = new AtomicInteger(0);   // ← 所有线程打同一个热点

// 版本三：正确并行 — 每个线程持有自己的本地计数，最后合并（典型 map-reduce 局部化思想）
static class LocalCounter {
    private int[] counts;                    // 每个线程一个 slot
    public LocalCounter(int nThreads) { counts = new int[nThreads]; }
    public void increment() { counts[ThreadId.get()]++; }        // 无争用
    public int get() { return Arrays.stream(counts).sum(); }     // 最后合并
}
```

- 🔧 这段代码的现代版就是 JDK8 的 **`LongAdder` / `Striped64`**：用分段 cells 消除热点。
- 🔧 **最朴素的教训**：并行化之前先清除共享热点，否则 N 个线程会为同一个 cacheline 反复争抢（cache line ping-pong）。

### 1.4 Amdahl 定律 vs Gustafson 定律
- **Amdahl**：固定问题规模，$S = \frac{1}{(1-P) + P/N}$。即使 $P = 0.9$，理论上限也只有 10 倍。
- **Gustafson**：固定时间、规模随核数放大，$S = N - (1-P)(N-1)$ —— 为「弱扩展」辩护（现代 big data workload 更符合它）。
- 🔧 本书引入 Amdahl 是为了告诉你**串行瓶颈决定了上限**；再多的核心也无法拯救一个序列化（不可并行）的部分。

### 1.5 并发的两个难度：正确性 + 可扩展性
- **正确性缺陷类别**：竞态（race）、原子性违反、死锁、活锁、饥饿、（这篇略）UB due to memory model。
- **可扩展性缺陷类别**：**锁争用、伪共享（false sharing）、缓存一致性流量、malloc/free 争用**，这些问题不会在小并发下暴露。
- 🔧 本书贯穿的一致性：**先算法正确性（Ch2-6），再工程扩展性（Ch7-20）**。

## 四、近年研究与工业界开源实践

- **近年研究**：**Amdahl/Gustafson 之外的新视角** —— Universal Scalability Law（USL，Gunther 2007）把**一致性开销（coherence/contention crosstalk）**建模成二次项：$C(N) = \frac{N}{1 + \sigma(N-1) + \kappa N(N-1)}$，能拟合「加到一定程度吞吐反而下降」；
  - **为什么多线程变慢**的实测综述：**Scalability! But at what COST?**（Wentzlaff & Agarwal, HotCloud 2020/2018）——8020 critique of systems research benchmarking。
- **工业界开源**（star 数 2026-09 实测）：
  - `openjdk/jdk`（≈23.4k★）：JDK 的 Thread/Executor/ForkJoin 是本章模型的最直接实现（`java.util.concurrent` 包）。
  - `JCTools/JCTools`（≈3.9k★）：高性能无锁队列，书中众多例子的工业版。
  - `google/benchmark` / `openjdk/jmh`（≈4.5k★）：**测提速比的正确工具**（JMH 防止 JVM 对 micro-benchmark 的死代码消除、循环展开等优化污染结果）。
  - `openjdk/jcstress`（≈2.1k★）：验证**内存模型**行为是否符合 JMM 的工具；任何涉及"可见性"的断言都该用它验一遍。

## 五、常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "多线程一定更快" | 争用与伪共享可以让 N 线程 **比单线程更慢** |
| 2 | "提速比测不出来做正��微调即可" | 没有 JMH +  warmed up pressure tests，数据基本是噪声 |
| 3 | "Amdahl 定律意味着多核无用" | Gustafson 视角下弱扩展几乎线性；取决于 workload |
| 4 | "the leave it to the compiler" | **编译器只保证单线程语义**；可见性/有序性要显式处理（Ch4） |
| 5 | 🔧 本书视角 | 本书着力于共享内存多线程；**多进程 + 消息传递**（Erlang/OTP，见 `book/高伸缩性系统/`）、actor 模型是另一条**避开**共享内存的路线，本书基本不谈 |
