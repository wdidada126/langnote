# 第 17 章 数据并行

> **一句话**：数据并行的全部秘密只有两个字——**结合律**。只要运算符满足结合律（不必可交换），归约和前缀和就能在 `O(n/P + log P)` 内完成，而这恰好是 work stealing 能承载的工作形态。

## 17.1 核心精讲：归约

```
归约 reduce(⊕, [a0, a1, ..., a_{n-1}]) = a0 ⊕ a1 ⊕ ... ⊕ a_{n-1}
```

只要 `⊕` **可结合**（`(a⊕b)⊕c = a⊕(b⊕c)`），就可以把线性链改成二叉树：

```
T₁ = O(n)        T∞ = O(log n)        并行度 = O(n / log n)
```

注意：**归约不要求可交换**。例如矩阵链乘 `(AB)C = A(BC)` 结合但不可交换，仍然可以并行归约；这一点常被误记。

```java
// 教学示意：JDK ForkJoin 归约（不参与构建）
static class Sum extends RecursiveTask<Long> {
    static final int CUTOFF = 10_000;
    final long[] a; final int lo, hi;
    protected Long compute() {
        if (hi - lo <= CUTOFF) { long s = 0; for (int i = lo; i < hi; i++) s += a[i]; return s; }
        int mid = (lo + hi) >>> 1;
        Sum left = new Sum(a, lo, mid), right = new Sum(a, mid, hi);
        left.fork();
        return right.compute() + left.join();      // 注意顺序：先 compute 再 join
    }
}
```

## 17.2 前缀和 / Scan：`O(n)` work，`O(log n)` span

**Scan** 定义为：`[a0, a0⊕a1, ..., a0⊕a1⊕...⊕a_{n-1}]`（**exclusive scan** 是 `[0, a0, a0⊕a1, ...]`，两者差一位，工业上 exclusive 更常用）。

串行版只要一个循环、`T₁ = O(n)`。并行版若用「每个 i 独立做一次归约」，则 `T₁ = O(n²)` —— 教训：**直接算术并行化会让 work 爆炸**。

### Blelloch 两遍扫描（1989/1990）

数组视为一棵树：

```
Phase 1  up-sweep（归约到根）：
    for d = 0 to log n - 1:
        for all k:        a[n-1 - k·2^(d+1)]  ⊕=  a[n-1 - k·2^(d+1) - 2^d]

Phase 2  down-sweep（从根分散下来）：
    root = 0
    for d = log n - 1 down to 0:
        for all k:
            tmp            = a[左孩子]
            a[左孩子]       = a[父]              // 父下传
            a[右孩子]       = tmp ⊕ a[父]        // 父 ⊗ 左兄弟下传给右孩子
```

- **work `W = O(n)`**（每个元素被访问常数次），
- **span `D = O(log n)`**，
- **只需要结合律**（树形推导对不可交换运算也成立），
- 也是唯一在实际 GPU/CPU 上被大规模部署的版本。

```java
// 教学示意：Blelloch up-sweep / down-sweep 的数组版本（inclusive scan）
static void blellochScan(long[] x) {
    int n = x.length;                       // 假设是 2 的幂
    for (int d = 0; (1 << d) < n; d++) {                       // up-sweep
        int step = 1 << (d + 1), half = 1 << d;
        for (int i = half - 1; i >= 0 - 1 && i < n; i += step) if (i + half < n && i >= 0)
            x[i + half] = x[i] + x[i + half];                   // 归约到 stride 位置
    }
    // 实际实现里 up-sweep 的下标是 «右孩子 += 左孩子»，并需要把根置 0；此处省略边界处理
    for (int d = (int) (Math.log(n) / Math.log(2)) - 1; d >= 0; d--) {   // down-sweep
        int step = 1 << (d + 1), half = 1 << d;
        for (int i = half - 1; i < n; i += step) {
            long left = x[i];
            x[i] = x[i + half];
            x[i + half] = left + x[i + half];
        }
    }
}
```

> ⚠️ 上面的代码是**教学示意**（下标边界未完整处理），生产实现请使用结构性更强的写法或直接用并行框架提供的 API。

### 三种 Scan 的对比

| 算法 | work | span | 特点 |
| --- | --- | --- | --- |
| **Hillis-Steele**（1986） | `O(n log n)` | `O(log n)` | 简单；work 多一个对数，适合 n 小、P 大的 GPU 场景 |
| **Blelloch**（1989） | **`O(n)`** | `O(log n)` | work 最优，加入内存，工程默认 |
| **Ladner-Fischer**（1980） | `O(n)` | `O(log n)` | 理论与 Blelloch 同级，常量略差 |

## 17.3 组合树（Combining Tree）与 Ch12 的呼应

第 12 章的计数/组合树本质上就是「归约 + 分布式 aggregation」：

| 应用 | 归约运算符 |
| --- | --- |
| 软件 barrier | 计数求和（`+`） |
| Fetch-and-φ 组合（fetch-and-op） | 运算符由调用决定 |
| 全局计数器 | `+`（浮点注意：浮点 `+` **不可结合**！） |

**浮点陷阱**：`sum(double)` 因为浮点加法**不满足结合律**，串行结果 ≠ 并行结果。这是数据并行最常见的「看似 bug」的现象，生产系统需要用 **Kahan / Neumaier 补偿求和**，或者接受重新统计。

## 17.5 近年研究与工业界开源实践（2015–2026）

**研究侧**：

- **Roofline / 带宽受限认知**（Williams, Waterman, Patterson, CACM 2009）：现代 scan/reduction 已经**不是算力受限而是带宽受限**；近年工作转向 cache-aware / blocked scan、以及如何在每次访存里做更多 work（如 vectorized aggregation）。
- **向量化 + 多核混合**：2020 年代的标准做法是 tiered parallelism（SIMD lane 内 / warp 内做小 scan，warp 间用 shared memory + decoupled look-back，块间用 multi-block 归约）。
- **可重复性（determinism）**：因为浮点不可结合，近年 reproducible reduction 的相关工作试图保证「相同输入 ⇒ 相同结果」，这对科学计算的可复现性很重要。

**工业实现**：

| 实现 | star | 说明 |
| --- | --- | --- |
| `NVIDIA/cub`（≈**1.8k★**） | GPU | `DeviceScan::InclusiveSum` / `ExclusiveSum` 使用 decoupled look-back scan + warp-level primitives（`__shfl_up_sync`），是今天 GPU 上最快的公开实现 |
| `NVIDIA/cuda-samples`（≈**9.7k★**） | GPU | 教学级 scan/recursive reduce 样例 |
| `openjdk/jdk`（≈**23.4k★**） | Java | `Arrays.parallelPrefix` 就是 Blelloch scan 的实现；`parallelSort` 内部用了 parallel merge；JDK 22+（JEP 460）的 **Vector API** 提供 SIMD 层 tiered parallelism |
| `apache/spark`（≈**44.0k★**） | 分布式 | RDD/DataFrame 的 reduce/aggregate；groupBy + shuffle 是「分布式分组归约」的工程化 |
| `apache/arrow`（≈**17.2k★**） | 内存格式 | 列式内存布局 + SIMD decode 是让 aggregate 走到带宽极限的前提 |
| `rayon-rs/rayon`（≈**13.3k★**） | Rust | `par_iter().map().sum()` / `.fold().reduce()` 就是本章 ⟨map-reduce⟩ 范式的安全抽象（类型系统保证归约运算符纯粹） |
| `ray-project/ray`（≈**43.9k★**） | 分布式 | 把 MapReduce 下沉到 Python 任务级别，其 map-reduce 语义源自同一套数据并行思想 |

## 17.6 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「并行 reduce 需要可交换」 | 只需要**结合**；不可交换（如矩阵乘、字符串拼接）也能归约 |
| 2 | 「浮点结果应该和串行一致」 | 浮点加法不可结合 → 每次运行结果可能不同；这是**正常现象**，需要 deterministic 就要用补偿求和 |
| 3 | 「scan 比串行快 P 倍」 | scan 是 bandwidth-bound，通常只能吃到内存带宽上限，与 P 无关 |
| 4 | 「ForkJoin 的 `join()` 前后不要做别的事」 | 正确的写法是 `left.fork(); right = right.compute(); left.join()` —— **先干活再等**，否则白白丢一个 worker |
| 5 | 🔧 本书未讨论 SIMD | 今天的数据并行第一层是 **SIMD lane**（AVX-512 / SVE / warp），多核只是第二层；只谈多核会显著高估收益 |
| 6 | 🔧 cutoff 必须实测 | `CUTOFF` 太小 ⇒ fork 开销主导；太大 ⇒ 尾部空闲。真实系统（Stream `parallelPrefix`）会按数组长度自动选择 |
