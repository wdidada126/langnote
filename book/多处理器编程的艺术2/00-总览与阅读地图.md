## 与并发系列的关系（各书总览已互链）

- **本书 = 算法与正确性的一面**；`Java并发编程之美/`、`Java并发编程实战/`(Goetz)、`Java并发实现原理/`(冷血)、`Java高并发核心编程/`(尼恩) = **Java 工程与 JDK 源码的一面**。建议顺序：**先用本书建立正确性定义（线性一致性、进展条件、内存模型）**，再回 JDK 看"为什么那样实现"。
- 本书 Ch2 的 **CLH/MCS 队列锁** → 就是 JUC `AQS` 与 `ReentrantLock` 的血脉。
- 本书 Ch9 Lazy list、Ch14 Lazy skiplist → 就是 `ConcurrentHashMap`(JDK8 桶级) 与 `ConcurrentSkipListMap`。
- 本书 Ch10 MS-queue → 就是 `ConcurrentLinkedQueue`；Ch11 Treiber 栈 → `ConcurrentLinkedDeque` 系。
- 本书 Ch16 work-stealing → 就是 `ForkJoinPool`；Ch12 计数 → 就是 `LongAdder`（ albeit 是 cell 分段而非纯粹的树)。
- 本书 Ch4/Ch5 的形式化是 **Java 内存模型（JSR-133）与 C++11 memory model** 的理论源头。

## 本书没覆盖的缺口（2026 视角）

- **语言/运行时**：Java 虚拟线程（JEP 444）、结构化并发（JEP 505）、ScopedValue（JEP 506）、C++20 `atomic_ref` / `jthread` / `atomic::wait`、Rust `Send/Sync` 所有权型并发。
- **弱内存模型的具体 formality**：x86-TSO（Sewell et al., CACM 2010）、ARMv8 公理模型（2017+）、Linux Kernel Memory Model（LKMM）、persistent memory 上 failures。
- **HTM 商业现实**：Intel TSX 在多数服务端 SKU 被微码禁用/删除；本书 Ch20 的 HTM 讨论需对照硬件可用性（见第 20 章修正）。
- **非阻塞内存回收的工程化**：folly `hazptr`、crossbeam（`crossbeam-epoch`）、以及 JVM 侧 GC 与显式回收混用的取舍（详见第 19 章）。
