# 第 6 章 容器的功能扩展

> `ApplicationContext` 在 `BeanFactory` 之上的增强：`refresh()` 十二步、`BeanFactoryPostProcessor`（`PropertyPlaceholderConfigurer`/`ConfigurationClassPostProcessor`）、`BeanPostProcessor`、事件机制（`ApplicationEventMulticaster`）、国际化 `MessageSource`、环境 `Environment`/`Profile`。

## 一、核心精讲

### 6.1 🔧 refresh() 主线
- `prepareRefresh` → `obtainFreshBeanFactory` → `prepareBeanFactory` → `postProcessBeanFactory` → **`invokeBeanFactoryPostProcessors`** → `registerBeanPostProcessors` → `initMessageSource` → `initApplicationEventMulticaster` → `onRefresh`（子容器如 Web）→ `registerListeners` → **`finishBeanFactoryInitialization`**（实例化所有非懒加载单例）→ `finishRefresh`（🔧 这是 Spring 容器的「总流程」，背下来对排障极有帮助）。

### 6.2 两类后处理器
- `BeanFactoryPostProcessor`：改**BeanDefinition 定义**（如 `${}` 占位符替换、`@Configuration` 解析）；`BeanPostProcessor`：改**bean 实例**（如 AOP 代理、`@Autowired` 注入）（🔧 时机不同：前者在实例化前，后者在初始化前后）。

### 6.3 事件机制
- `ApplicationEvent` + `ApplicationListener`；`ApplicationEventMulticaster` 广播（🔧 默认同步；需异步用 `@Async` 或自定义 multicaster；Spring 4.2+ 支持 `@EventListener`）。

## 三、常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "BeanFactoryPostProcessor 改实例" | 改定义；改实例用 BeanPostProcessor |
| 2 | "事件默认异步" | 同步；异步需配置 |
| 3 | "refresh 可重复" | 一般一次，重复会重建单例 |
