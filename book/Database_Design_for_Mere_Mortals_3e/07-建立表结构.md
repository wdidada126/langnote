## 三、表清单的三段生成法（p176–192）

1. **Preliminary Table List（176）**：问"我们在跟踪哪些**主题（subject）**？"——名词清单（客户、自行车、订单、零件、技师…）；
2. **Identifying Implied Subjects（176–181）**：关系里挖隐含主题——"客户**订购**了车"的"订购"若需要存自己的属性/被别的东西引用，就该有自己的表（本书式 M:N 识别术，第 10 章回收）；
3. **Using the Mission Objectives（182）**：逐条使命目标核对主题覆盖，防"表有了但问题答不了"；
4. **Final Table List（184–198）**三件套：表名精修（集合名词、单数、业务词汇，准则汇编见附录 C ✅p548）、**Indicating the Table Types（192）**——业务表之外承认**工具表**（校验表/桥表：10/11 章的 junction 与 validation 在此立项）、**Composing the Table Descriptions（192）**——逐表写"本表跟踪……每一行是一个……"（写作准则附录 C ✅p547）。

## 四、Ideal Field：字段归表的裁决刀（p199–218）

**理想字段判据**（Elements of the Ideal Field 汇编于附录 C ✅p545）：

- **原子**：一个字段只装一个事实——拆 multipart（199→210：地址→街道/市/邮编）与 multivalued（212：逗号串→新表+FK）两大手术；
- **非派生**：字段值不可由别的字段算出（计算字段回 06 章清册）；
- **完全依赖主键**：字段必须描述"这一行这个主题"，不能只描述部分或传递（这就是 FD/2NF/3NF 的白话化，附录 G ✅p572 明说此对应）；
- **命名无歧义**：Improving the Field Names（202）给命名纪律（单数、业务词汇、防缩写黑话，准则附录 C ✅p548）。

## 八、常见误区

1. 表名用缩写黑话（cust_ord_ln）：命名纪律专治，且表描述=给未来考古者的注释；
2. 拆多值时把新表建成"无主键影子表"：拆出的表也要过理想表判据（08 章补键）；
3. Subset table 当"可选优化"：Hernandez 用它替代 NULL 泛滥的宽表（互斥属性拆子表而非留空列）；
4. 隐含主题只找一次：p176 与 p178 两节是"清单→复核"双遍工序；
5. 表描述写成字段罗列："本表跟踪……每行是一个……"句式的价值在**主题排他性**——写不出这句的表就是杂牌表；
6. 把工具表当私搭乱建：校验表/联结表有正式编制（Table Types 节），与业务表同权登记进表清单；
7. 拆复合字段时过度原子化：把"省份"再拆成"战区+经济带"属于自嗨字段——原子性判据的边界是业务语义，不是拆分快感。

## 核心概念速览（中英对照）

1. **主题** — subject：表存在的唯一理由；一表一主题。
2. **隐含主题** — implied subject：关系/交互需要自己的属性时升格为表。
3. **理想字段** — ideal field：原子、非派生、完全依赖主键、命名无歧义。
4. **理想表** — ideal table：单一主题+可唯一标识行+无冗余事实。
5. **复合字段** — multipart field：一格多义（全名/整地址），拆列对象。
6. **多值字段** — multivalued field：一格多值（逗号串），拆表对象。
7. **表描述** — table description："本表跟踪……每行是一个……"强制句式。
8. **子类表** — subset table：特化属性的垂直拆分承接表。
9. **工具表** — table types：联结/校验等非业务表的正式编制。
10. **白话规范化** — normalization without jargon：理想字段/表=FD 判据的工程马甲。

## 最新演进与工业实践

- **1NF 的现代松动**：半结构化时代（JSON 列合法化）"一格多值"是否该拆重新成为权衡——SQLite JSON1 扩展（https://www.sqlite.org/json1.html ✅ 200 实抓 2026-09-27）与 DuckDB JSON 类型（https://duckdb.org/docs/stable/data/json/overview ✅ 200）让数组可存可查（json_each/UNNEST），但**被查询/被约束的多值仍应拆表**的判据未变：数组上外键与跨行唯一性依旧缺位 ⚠️ 判据为工程共识转述。
- **dbt 语义层的表清单**：sources.yml/模型描述字段=本书"表描述"的 YAML 化 ⚠️ 行业实践转述（文档站存在性常识级）。
- **建模工具**：联结表/子类表在 ERD 工具中一键生成（dbdiagram.io/drawsql，URL 已于 03 章验证 200），但"隐含主题"的发现仍是访谈+清单手艺 ⚠️。
