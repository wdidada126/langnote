## 一、本章定位

七步流程第 6 步：视图在本书不是查询便利贴，而是**使命目标的验收装置**——每条使命目标应能指认到回答它的视图（数据/聚合类），每条业务规则应能指认到执行它的校验视图。三分法（Data/Aggregate/Validation）是本章骨架，也是与所有教科书"VIEW=虚表"讲法分道扬镳的地方。

## 三、三类视图（p437–448）

| 类 | 用途 | 规格单要素（转述） |
|---|---|---|
| **Data View（437）** | 多表行级事实的组合呈现（明细清单） | 来源表、选择条件、字段去向 |
| **Aggregate View（442）** | 分组统计（销售月报/库存余量） | 分组列、聚合函数、**口径**（与 06 章计算字段清册勾连） |
| **Validation View（446）** | 输出**违规行清单**（11 章跨表规则的执法探针） | 断言的反向查询：查出来的每一行都是一次违例 |

**Validation View 是本书对"规则即数据"的最后一块拼图**：引擎不执法的第③层楼（见 11 章 🔧 三层楼），用"定时跑反查询、结果非空即报警"补位——2026 年的名字叫 data tests。

## 五、🔧 类比实测：视图可更性红线（非本书引擎行为）

实验 G 组（`D:\develops\tmp\dbwave_w5_mmortals\exp_out.txt`）：

- **G1** SQLite 3.45.3：`CREATE VIEW v_bike_products AS SELECT ... JOIN ...` 查询正常返回 `(1,'Helmet','Acme Bikes')`；
- **G2** 对连接视图 `UPDATE v_bike_products SET vendor_name='X'` → `OperationalError: cannot modify ... because it is a view`——SQLite 视图**只读**一刀切；
- **G3/G4 DuckDB 1.5.5**：视图查询正常；`UPDATE vv SET answer=1` → `Binder Error: Can only update base table`——同样拒绝；
- **教学映射**：两引擎都倾向"视图=呈现层不是存储层"，恰好支持本书三类视图全部按**只读报告对象**管理的设定；单表可更新视图的引擎（PG/SQL Server/Oracle 各有权衡 ⚠️ 转述未实测）会让"改视图=改基表"的副作用重开冗余话题——设计文档必须显式声明视图的可写性，本书表单未细分此格，是 🔧 实验反哺书本之处。

## 七、常见误区

1. "目标清单没对应视图也收工"：第 4 章验收钩子断裂，第 13 章复查将补刀；
2. 聚合视图不写口径：同一个"月销售额"三种过滤条件=三种真相（06 章四类信息需求复查在此还账）；
3. 校验视图当"可有可无的巡检脚本"：它是第③层楼唯一系统化执法者，必须与规则单一一挂钩编号；
4. 把视图当权限边界：行级安全的视图方案属实施层话题，本书逻辑设计不背书 ⚠️ 划界说明；
5. 校验视图与规则单编号错位：查出违例却指认不出违了哪条规则=执法探针没接电；
6. 一视多口径：同视图既按"下单日"又按"发货日"统计——拆两个具名视图，口径进文档格而非注释行；
7. 只建 Data View 不建 Validation View：三类视图缺一族，第③层楼规则即无系统执法者（11 章三层楼结论的视图侧镜像）。

## 核心概念速览（中英对照）

1. **视图** — view：保存的查询=呈现层设计对象。
2. **数据视图** — data view：行级多表事实组合。
3. **聚合视图** — aggregate view：分组统计与口径载体。
4. **校验视图** — validation view：违例清单生成器，规则的反向断言。
5. **视图文档** — view documentation：描述+字段+逻辑的三件套规格。
6. **只读默认** — read-only by default：连接视图不可更新（🔧 两引擎一致执法）。
7. **口径** — measure definition：聚合业务语义的唯一化定义。
8. **目标-视图映射** — objective-to-view traceability：使命目标可答性证明。
9. **反查询** — reverse assertion：以"查出即违例"表达规则校验的视图技法。

## 最新演进与工业实践

- **语义层复兴（2024–2026）**：MetricFlow/dbt semantic layer、Cube 等产品把"聚合视图+口径"升格为一等资产（metrics 定义文件）——本书三类视图的 BI 后裔链：validation view→data tests、aggregate view→metrics、data view→模型 ⚠️ 行业实践转述。
- **引擎侧视图谱系** 🔧：SQLite 视图只读（G2 实测）；DuckDB 支持 VIEW+MACRO 双轨（文档域 https://duckdb.org/docs/stable/sql/constraints/ 同站导航 ✅ 200）；标准侧 `WITH CHECK OPTION` 的引擎支持面 ⚠️ 未逐一复核，仅登记特性名。
