## 主题机制讲解

### 词法：分号可选与"软关键词"

- 语句结尾分号可省；官方语法以换行做终结（✅ Kotlin grammar: 换行符作为终结符存在，
  与 Java 必须显式 `;` 不同）。
- 标识符可用反引号包裹以容纳空格/关键字：`val \`my val\` = 1`（✅ 官方词法文档；
  反引号标识符主要面向 Java 互操作，官方明确不建议常规使用）。
- Kotlin 无 `strictfp/const`（Java 意义）等冗余修饰；大量词是"软/上下文关键词"
  （`data`、`value`、`sealed`、`inner`、`enum`、`typealias`、`expect`、`actual`），
  只在特定语法位生效，仍可在其他位置作普通标识符（✅）。对照 C++：C++ 关键字全部
  保留、不可挪用；Kotlin 选择"语法位敏感"避免关键字膨胀。

```kotlin
// 🔧 示意：软关键词可作普通标识符
val data = 42          // data 在顶层声明处不是关键字
```

### 类型系统：可空性是类型层的一等公民

- 每个类型有可空变体 `T?`，即 `T ∪ null` 的并集类型；非空 `T` 的变量不可赋 null（✅）。
  这是与 Java（引用类型皆可 null、靠 `Optional`/注解补丁）的根本分野；也是与 C++
  指针/`std::optional` 的分野——C++ 的 nullness 不由编译器统一追踪，Kotlin 由类型
  检查器全程做数据流分析。
- 基本类型装箱按平台需要自动发生；数字类型间**不隐式转换**，`val x: Long = 1` 报错，
  必须 `1L` 或显式 `.toLong()`（✅；对照 C++/Java 的隐式 widening——Kotlin 有意拒绝，
  因为溢出与精度损失不该静默）。字面量类型取"能装下它的最小类型"（Int 起，超界升
  Long），后缀 `L/u/ul` 造 Long/UInt/ULong（✅ 无符号整型 UInt/ULong/UByte/UShort
  自 Kotlin 1.5 转正）。
- `Unit` ↔ Java `void` ↔ C++ `void`；`Nothing` 是**空类型**：没有任何实例，用作
  永不正常返回的函数返回类型（`throw` 的表达式类型即 Nothing），故可参与类型收窄
  （✅）。C++ 最接近 `[[noreturn]]`，但那是属性不是类型；`Nothing` 作为表达式类型
  可以让 `val x = if (c) compute() else error("boom")` 里 x 按非空分支类型推断。
- 智能转换（smart cast）：`if (x is String) x.length` 在 x 为**局部不可变**且期间
  未变更时自动收窄，免手写强转（✅）。失效条件是要害：`var` 属性跨模块可见、可被
  并发修改、被捕获进可变更闭包时不转换（✅）——对照 C++ `std::variant` 的
  `std::get` 无流敏感推理，对照 Java 16 的 pattern matching for instanceof
  （`if (o instanceof String s)`）只覆盖声明点、不覆盖已有变量复用。
- 平台类型：调用 Java 代码得到的类型记为 `T!`——可空性未知，编译器不设防，
  NPE 风险原样带过来（✅ 官方 nullness annotation 文档口径）。互操作章的伏笔，见
  [00 总览](00-总览与阅读地图.md)第三节。

### 控制流：表达式优先

- `if` 是表达式可赋值：`val max = if (a > b) a else b`（✅）；C++ 有 `?:` 与
  IIFE 勉强对位，Java 只有三元运算符。Kotlin 无三元 `? :`（官方 FAQ 口径：`if`
  已是表达式，避免两套语法）。
- `when`：无主语版=链式 if 的扁平化；有主语版=穷尽 switch。分支体是表达式，
  用作赋值时**必须穷尽**（`else` 或类型/密封层级全覆盖；对 Boolean/密封类/枚举的
  穷尽性自 Kotlin 1.7 起强制）（✅）。C++17 `std::visit` + overloaded 惯用法是
  variant 上的同位物，但书写成本高一截；Java `switch` 到 14 才有 yield 表达式与
  箭头穷尽分支。
- 区间/步进：`1..10`、`10 downTo 1 step 2`、`in` 判定都是操作符约定（`rangeTo`、
  `step`、`contains`——见 [05 高级类用法](05-高级类用法.md)）（✅）。`Range` 是
  一等对象，可 `5 in 1..10` 复用，Java/C++ 无对位。
- 循环：`for (x in iterable)` 走迭代器约定；标签化的 `break@loop` / `continue@loop`，
  函数返回可用 `return@runLambda` 形式从 lambda 早退（✅）。对照 C++ 只有 goto 才能
  多目标跳出；对照 Java 的标签是 1.0 遗产且罕用。

```kotlin
// 🔧 示意：穷尽 when + 区间 + 标签 return
fun describe(x: Int): String = when {
    x in 1..10 -> "small"
    x in 11..100 -> "medium"
    else -> error("out of range")   // error 返回 Nothing，整式类型仍 String
}

fun firstPositive(xs: List<List<Int>>): Int? = run loop@{
    xs.forEach { inner ->
        inner.forEach { v -> if (v > 0) return@loop v }
    }
    null
}
```

## 易错点

1. **`==` 与 `===`**：`==` 调 `equals`（结构相等），`===` 是引用相等（✅）。
   Java 老兵习惯性以为 `==` 即引用比较——装箱数 `Integer.valueOf(200)` 两次比较
   `==` 为 false 的经典坑在 Kotlin 里被 `==` 修掉，但数组的 `==` 仍是引用语义
   （要用 `contentEquals`，✅）。
2. **智能转换失效**：`var` 属性、`open` 类成员、被 lambda 捕获的可变局部量拿不到
   smart cast；需要局部 `val` 拷贝或 `!!`（后者运行期风险）。
3. **可空类型上的成员调用**：`s.length ?: 0` 是错的——`?:` 左边得是表达式整体，
   安全调用链应写 `s?.length ?: 0`；漏 `?` 直接编译失败而非静默通过（这是相对
   Java 的进步：把 NPE 前移到编译期）。
4. **`!!` 滥用**：非空断言把编译期保证兑换成运行期 NPE（`NullPointerException`），
   官方文档口径是最后手段；平台类型场景优先显式声明成 `T?`。
5. **数字类型字面量陷阱**：`0.1 + 0.2 != 0.3`（IEEE 754，✅ 与 Java/C++ 同）；
   `Int * Int` 溢出**环绕不报错**，防溢出要显式 `Math.multiplyExact` 或 `toLong`
   （Kotlin 标准库另有 `Int.times` 无溢出检查的口径，官方 FAQ）。
6. **when 用作语句可不穷尽**：赋值场景才强制穷尽；漏 else 的"语句 when"合法但
   静默吞分支——迁移 Java switch 时最常见的语义差。
7. **raw string 的换行与缩进**：`"""..."""` 内换行原样保留、不转义（`\n` 字面义失效），
   要配 `trimIndent()/trimMargin()` 收拾缩进（✅）。

## 🔧 kotlinc 微实验设计

```bash
# 单文件快验（1e/2e 前半程语言实验都不需要协程依赖）
kotlinc ch01.kt -include-runtime -d ch01.jar && java -jar ch01.jar
```

- 实验 A（smart cast 失效边界）：同一逻辑分别用 `val` / 本地 `var` / 顶层 `var`
  写 `is String` 检查，观察哪些编译通过、哪些报 "smart cast to 'String' is
  impossible"。预期：本地 var 在"检查与使用之间无变更"时仍可转换，跨模块属性不可。
- 实验 B（Nothing 参与推断）：`val x: Int = if (cond) 1 else throw IllegalStateException()`
  编译通过；再把 throw 换成返回 Unit 的 println，观察类型错误，体会"throw 是
  Nothing 表达式"。
- 实验 C（无隐式 widening）：`val l: Long = 1` 与 `val l: Long = 1L` 对照编译；
  再试 `fun f(x: Long) = x + 1` 里 `1` 为何不报错（字面量在期望类型下直接按 Long
  解析，✅ 官方字面量文档口径），厘清"变量赋值不隐转"与"字面量适配期望类型"的边界。
- 实验 D（穷尽 when）：对密封类 when 赋值删 else，看 1.7+ 报错信息；
  改成语句位置，看静默通过。

## 核心概念中英对照

- **可空类型** — nullable type (`T?`)：类型层显式并入 null 的并集类型。
- **智能转换** — smart cast：基于数据流分析的类型自动收窄。
- **平台类型** — platform type (`T!`)：来自 Java、可空性未知的类型。
- **空类型** — `Nothing`：零实例类型，标记永不正常返回。
- **表达式优先** — expression-oriented：if/when/try 皆有值。
- **穷尽性检查** — exhaustiveness：when 用作表达式须覆盖全部输入。
- **软/上下文关键词** — soft/contextual keyword：仅语法位生效的关键字。
- **区间/步进** — range/progression：`rangeTo`、`step`、`contains` 的对象化。
- **标签返回** — labeled return：`return@label` 从 lambda 早退外层调用。
