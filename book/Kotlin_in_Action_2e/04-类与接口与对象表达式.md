## 核心机制

### 类与属性：primary constructor 即声明位

- `class Person(val name: String)`：主构造器挂类名后，属性要 `val/var` 显式声明才升格成员（裸参数仅构造期可见，✅）——Java 字段+构造赋值+getter 三件套合成一步；C++ 对位成员初始化列表，但无 accessor 自动生成。
- backing field 规则（✅）：默认访问器有字段；自定义 getter 不再引用 `field` 则字段消失；接口属性永无字段。`lateinit` 仅限非空 `var`、原生类型受限（✅），Java 侧只能拿 Optional/包装类凑，C++ 用 std::optional 两段初始化。
- 次构造器 `constructor(...) : this(...)` 必须委托主构造器（✅），杜绝 Java `this(...)` 悬空链。init 块与属性初始化器**按声明顺序**执行（✅）——顺序类 bug 头号温床，见批判读法 1。
- 可见性：默认 public；`internal`=同 module（✅，Java 包私有/C++ 无对位的中间粒度）；`protected` 不含包语义（✅ 比 Java 收紧）。类默认 final、成员默认不可重写，`open` 显式授权（✅）——对照 Java 默认可继承、C++ 默认非 virtual，Kotlin 两头都关。

### 接口：默认方法无状态，冲突点名合并

- 接口可有实现体方法与带 getter 的属性，**不能存状态**（✅）——与 Java 1.8 default（仍无字段）同律，与 C++ 多重继承带数据分野。
- 两父接口同名默认方法：实现类必须显式重写并 `super<A>.f()` 逐个点名（✅），不自动线性化；对照 C++ 菱形是运行期布局问题，Kotlin 是编译期点名问题——吵但安全。
- `abstract` 类 vs 接口选择口径与 Java 同（共享状态+构造器→抽象类，✅）。

### object 与伴生：static 的正确替代

- `object Single {}` 声明即线程安全单例（✅），顶掉 Java DCL/Holder 与 C++ Meyers singleton。
- `companion object` 是挂在类上的匿名单例：有自身类型、可实现接口、可具名（✅），**不是** Java static；要 `@JvmStatic` 才生成 JVM 静态方法（✅）。心智转换：Kotlin 没有静态成员，一切皆对象。
- 对象表达式 `object : Runnable { ... }` ≈ Java 匿名内部类（✅），但可捕获可变局部量（✅，effectively-final 限制不存在）；TS 对照：JS 对象字面量是结构性值，object 表达式是名义类型+行为覆写，层次不同。
- 擦除逃生舱：`object : TypeReference<HashMap<String,Int>>() {}` 捕获泛型实参，Gson TypeToken 同款机器（✅ 机制可证，书中出处 ⚠️），详见 [06 册](06-泛型.md)。

## 批判读法（易错与存疑）

1. **init/属性顺序**：`val b = a + 1; val a = 2` 编译过但 b 拿零值（✅ 行为）；书中若只画 happy path 即缺口。
2. **自定义 setter 递归**：`set(value) { property = value }` 不写 `field` 即无限递归栈溢出（✅）——Java `this.x=x` 肌肉记忆会背叛你。
3. **open 的传染性**：Spring/JPA 要求非 final 时满屏 open（✅ 生态现实）；书中对 Java 生态妥协的讨论深浅是 2e 质量试金石 ⚠️。
4. **伴生≠static 的 ABI**：成员编译进 `Companion` 内部类，漏 `@JvmStatic/@JvmField` 时 Java 侧写出 `Person.Companion.parse()`，反射/序列化常踩（✅）。
5. data class 不可 open、sealed 层级另册（✅）——本章与 05 的切分在 2e 是否依旧 ⚠️。

## 核心概念中英对照

- **主构造器** — primary constructor：类名同行声明位，兼属性声明。
- **后备字段** — backing field（`field`）：属性自动存储槽。
- **延迟初始化** — `lateinit`：非空 var 的晚绑定豁免券。
- **伴生对象** — companion object：类级单例，非 JVM static。
- **对象声明** — object declaration：声明即线程安全单例。
- **对象表达式** — object expression：匿名对象，可捕获可变局部量。
- **开放类** — `open`：显式授权继承/重写（默认 final）。
- **模块内可见** — `internal`：module 粒度中间可见性。
