## 核心机制

### 声明处方差：in/out 一次写清

- `interface Source<out T> { fun next(): T }`：`out` 承诺 T 只在协变位（返回值），`Source<Dog>` 即 `Source<Animal>` 子类型（✅）。Java 对位是**使用处**通配符 `<? extends T>`——方差标在调用点、类作者不表态（✅）；Kotlin 首选声明处标注，使用处投影补位。
- `Sink<in T>` 逆变（只当参数，✅）。PECS 口诀映射：声明处 out≈producer、in≈consumer（✅）。C++ **无内建方差**：`std::vector<Dog>` 与 `std::vector<Animal>` 毫无亲缘且各自单态化——C++/Kotlin 泛型观第一分水岭。
- 数组陷阱同构：Java `Integer[]` 协变、运行时 ArrayStoreException 兜底（✅）；Kotlin `Array<T>` **不变**（✅），要协变得声明 `Array<out T>` 只读位使用（✅）。

### 擦除、reified 与逃生舱

- JVM 泛型擦除（✅ 与 Java 同底）：`is List<String>` 非法、运行时无痕。四家坐标：TS **全类型层擦除**（类型零残留，✅ 该专题档本机实测过 strip-types）；Java/Kotlin 擦类型参数留类元数据；C++ 不擦而是展开成真实代码——对照表见 ../TypeScript系列·Runtime_vs_Type_System专题.md 第二节。
- `inline fun <reified T>` 借内联具体化（✅，[02 册](02-函数与Lambda.md) 实验 B）；非 inline 场景逃生舱：`KClass<T>` 参数或匿名对象捕获实参 `object : TypeRef<HashMap<String,Int>>() {}`（✅，[04 册](04-类与接口与对象表达式.md) 已埋）。
- 约束：`T : Number`、`T : Any`（可空性也是约束维，✅）、where 多约束合取（✅）。对照 C++20 concepts：命名约束包可约束任意表达式合法性，Kotlin 上界只是继承约束——表达力落差整档展开于 ../C++20模板元编程/06-概念和约束.md（✅ 在盘）。

### 星投影与平台签名

- `Array<*>`="某未知元素类型的数组"（✅）：读出 `Any?`、写入被拒，Java `List<?>` 同款沉默；投影做参数够用，做返回类型常逼你 reified/重载。
- 声明处方差+使用处投影可叠加：`fun copy(src: Source<out Animal>, dest: Sink<in Animal>)`（✅）。"variance 与 projection 二分"的讲解线凭记忆 ⚠️。
- 互操作签名现实：Kotlin `List<out T>` 编译为 Java `List<? extends T>`（✅ 口径）；函数类型方差 `(Dog)->Unit` ≤ `(Animal)->Unit`（参数逆变返回协变，✅），过 Java SAM 时退化为接口不变——最易翻车处。

## 批判读法（易错与存疑）

1. **方差是契约非证明**：`Source<out T>` 内若私有字段存可变 T，编译器仍认协变——替换性靠作者自律（✅ 机理；书中案例 ⚠️）。
2. **reified 语法位霸权**：`T::class`/`is T` 只在 inline 体内（✅）；reified 参数往别的高阶函数一传就撞 noinline/擦除墙——DSL 滥用是设计味道。
3. **试探式标方差**：给 `MutableList<T>` 标 out 立即编译错（可变性与方差互斥）——"先标再删"说明没懂原理。
4. **泛型 vararg**：协变数组收 vararg 的 heap pollution 在 Kotlin 少一半，但平台方法照旧不设防（✅ 机理）。
5. **常见误读**：把 `out` 讲成"不可变"（那是 03 册的事）——方差管子类型关系，不管修改。
6. 2e 是否收编泛型展开/definite 约束细则 ⚠️ 未核。

## 核心概念中英对照

- **声明处方差** — declaration-site variance：`in/out` 标在类型参数上。
- **使用处投影** — use-site projection：`out T` 调用点标注，Java 通配符同位。
- **逆变** — contravariance (`in`)：参数位反转子类型。
- **星投影** — star projection (`<*>`)：未知实参的读窄写禁形态。
- **具体化类型** — reified type parameter：仅 inline 可逃擦除。
- **类型擦除** — type erasure：JVM 运行期删类型参数。
- **不变数组** — invariant `Array<T>`：无协变兜底，拒绝整段踩坑。
