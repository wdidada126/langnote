## 核心精讲

（以下为教学性梳理，代码均**教学示意，不参与构建**。）

### 13.2–13.3 超级块与 inode：文件系统的两张表

Minix FS 把磁盘划分为：引导块（可选）、**超级块**、**inode 位图**、**块位图**、
**inode 数组**、**数据块区**。超级块记全局信息（总块数、空闲计数、魔数），挂载时读入内存。
每个文件对应一个 **inode**，存元数据（权限、尺寸、时间戳）与**直接/间接块地址指针**——
文件内容通过这些指针找到数据块。这正是 [04-Linux存储基础.md](04-Linux存储基础.md) 4.2「inode 视角」的实例化。

### 13.4 位图：谁空闲一目了然

inode 位图与块位图各用 1 bit 表示一项是否占用。分配一个 inode/块 = 找第一个 0 位并置 1；
释放 = 清 0。简单、无碎片元数据，是教学级 FS 的典型设计（生产 FS 用更精巧的分配器）。

### 13.5 目录项：名字到 inode 的映射

Minix 的目录本身就是一个特殊文件，内容是一串「(inode 号, 文件名)」记录。解析 `/a/b`：
读根 inode → 在其数据块里找 `a` 的 inode 号 → 读 `a` 的 inode → 找 `b` ……逐级下钻。

### 13.6 读写路径串起第四章

一次 `read(path, off, len)` 在 Minix FS 上的落地，正是 04 章 VFS→文件系统层 的具象：
路径解析得 inode → 用 inode 的块指针把字节偏移翻译成盘块号 → 经块层/驱动读数据。

```text
# 教学示意，不参与构建：读 /a/b 的 Minix 路径
root inode -> 目录项找 "a" 的 inode# -> a inode -> 目录项找 "b" 的 inode#
  -> b inode 的块指针[off/块大小] -> 数据块号 -> 块层读盘
```

## 版本演进

- Minix FS 作为教学载体长期稳定（它本就是为教学而生的简单 FS），2024 年书出版时与当前一致。
- 🔧 **2026 视角补入**：现代生产文件系统（ext4 的 extent、XFS、Btrfs/ZFS 的 COW）远比 Minix
  复杂；若以 Minix 为唯一范本，应补一句「它只是教学切片，真实 FS 用 extent/COW/B-tree 管理块」，
  免得读者把简单设计当工业现状。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「Minix FS 和 ext 一样」 | Minix 是教学简化版；ext 用 inode 但加 extent/日志，差别大 |
| 2 | 「目录是特殊结构」 | 目录本质是个「名字→inode」的文件，Minix 暴露得很清楚 |
| 3 | 「文件=数据块」 | 文件=inode(元数据)+数据块(内容)，inode 才是身份 |
| 4 | 🔧 用 Minix 当工业现状 | 2026 年应补 extent/COW/B-tree 等真实 FS 管理块的方式 |
