## 核心精讲

（以下为教学性梳理，代码均**教学示意，不参与构建**。）

### 4.1.1 系统调用：用户态与内核态的边界

Go 的 `os.File.Write` 最终落到 `write(2)` / `pwrite(2)` 等系统调用。关键点：

- **用户态 ↔ 内核态切换有成本**（上下文保存、权限检查、可能的拷贝）；
- 频繁小写的性能杀手往往是「系统调用次数」而非「写入字节数」——这正是 `bufio` 存在的理由（见第 3、5 章）。

### 4.1.2 VFS 层：一切文件系统的统一门面

VFS（Virtual File System）用一套统一对象（`inode`、`dentry`、`file`、`super_block`）
屏蔽底层文件系统差异。无论 ext4、XFS 还是 FUSE（第 15 章），对上层都长一样。
VFS 还负责**页缓存（page cache）**的挂钩——这是第 8 章「缓存模式」的内核侧。

### 4.1.3 文件系统层：把逻辑偏移映射成块

具体文件系统（ext4/XFS/Btrfs）负责：维护目录树、把文件的字节偏移翻译成磁盘块号、
管理空闲空间与日志（journal，保证崩溃一致性，对应单机 redo 思想）。

### 4.1.4 块层：IO 调度与合并

块层（block layer）把上层来的 bio 请求做**合并与重排**（电梯算法 / 多队列 MQ），
把随机小请求合并成顺序大请求，并把请求派发到具体队列。现代多队列块层（blk-mq）
是 NVMe 高并发的底座。`/sys/block/*/queue/` 下的调度器（none/mq-deadline/bfq）在此可调。

### 4.1.5 设备驱动层：最终落到介质

驱动把块请求翻译成对 SSD/HDD 的命令（NVMe 命令 / SCSI 命令）。到这一层才真正碰介质，
延迟数量级（HDD ms 级、NVMe µs 级）在此决定。

### 4.2 文件的定义：inode 视角

内核里「文件」≈ **inode（元数据：权限、尺寸、数据块指针）+ 数据块**；文件名只是
目录项（dentry）到 inode 的映射。一个 inode 可被多个硬链接指向；删除只是去掉一个链接。

```text
# 教学示意，不参与构建：一次 write 的内核旅程
Go os.File.Write
  -> syscall write(2)            # 4.1.1 陷入内核
  -> VFS vfs_write               # 4.1.2 统一门面 + 页缓存
  -> ext4_file_write_iter        # 4.1.3 文件系统层：偏移->块
  -> submit_bio                  # 4.1.4 块层：合并/重排
  -> nvme_queue_rq              # 4.1.5 驱动层：下发到 SSD
```

## 版本演进

- 本章描述的存储栈分层（syscall→VFS→FS→block→driver）是 Linux 长期稳定的结构，2024 年书出版时与当前一致。
- 🔧 **2026 视角补入**：现代内核的 **io_uring**（2019 并入主线，5.x 持续增强）绕开传统
  `read/write` 系统调用、用共享环形队列大幅降低 I/O 上下文切换开销——这是第 6 章「高级 I/O 模式」
  在 2026 年最重要的新变量，书中若只讲 libaio 需补 io_uring。
- 🔧 **2026 视角补入**：NVMe 已成默认介质，块层多队列（blk-mq）与 NVMe 队列深度直接对应；
  4.1.4/4.1.5 的「HDD 寻道」口吻须按 NVMe µs 级更新（详见 [02-Go语言的数据结构.md](02-Go语言的数据结构.md) 的硬件说明）。

## 近年研究与工业界开源实践（2015–2026）

- **eBPF 观测存储栈**：`bpftrace` / `bcc` 可在不修改内核的情况下追踪 4.1 每一层的延迟，
  是 2026 年定位 I/O 瓶颈的标准工具（🔧 2026 视角，见 00-总览「实验工具链」）。
- **NVMe 与 ZNS**：ZNS（Zoned Namespace）SSD 把顺序写约束暴露给主机，利好 LSM 类引擎
  （见 [14-存储引擎LevelDB.md](14-存储引擎LevelDB.md)）；是 4.1.5 驱动层的新介质变量。
- **高性能存储项目都在吃透这五层**：`minio/minio`（61350★）、`seaweedfs/seaweedfs`（34989★）
  的写路径优化本质上是在 4.1.4 块层与 4.1.5 驱动层上做文章。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「write 返回就落盘了」 | 默认只写入**页缓存**，真正落盘由回写线程异步完成；要强持久需 fsync/O_SYNC/direct |
| 2 | 「文件慢就是磁盘慢」 | 多数情况是系统调用次数、页缓存命中率或块层合并效率的问题，不一定是介质 |
| 3 | 「所有文件系统一样」 | 日志/COW/Extent 等差异会显著改变 I/O 特征（ext4 vs XFS vs Btrfs） |
| 4 | 🔧 只讲 libaio 不讲 io_uring | 2026 年高并发异步 I/O 事实标准是 io_uring，libaio 已偏老 |
| 5 | 🔧 用 HDD 寻道口吻讲延迟 | NVMe 已是默认，µs 级；HDD 仅适用于冷归档 |
