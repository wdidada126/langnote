# 第 2 章　Go 语言的数据结构

> 原书第 2 章是为后续存储编程打底的「Go 数据类型速成」。它挑了存储编程最常用的一组类型：
> **字节、数组/切片、字符串、map、Channel、接口**。这些不是 Go 语法全集，而是
> 「写存储系统绕不开的那几个」。本章的小节标题取自当当目录原文。

## 核心精讲

（以下为教学性梳理，代码均**教学示意，不参与构建**。）

### 2.1–2.2 字节与切片：存储系统的「原子」

存储系统读写的终点是字节序列。Go 用 `[]byte` 表示，`slice` 的三元组（指针、长度、容量）决定了
它只是底层数组的一段**视图**——这恰是零拷贝的基础：

```go
// 教学示意，不参与构建：切片是视图，切分不产生拷贝
buf := make([]byte, 4096)        // 一次分配 4KB 底层数组
hdr := buf[:16]                  // hdr 与 buf 共享底层数组，无拷贝
// 扩容规则：append 超过 cap 才分配新数组；提前 make 到容量可避免反复分配
```

> 关键陷阱：**切片共享底层数组**——`hdr` 改了，`buf` 也会变。存储代码里做缓冲区复用
> （如 `sync.Pool` 借出的 buf）必须警惕别名导致的并发脏读。

### 2.3 字符串与 []byte 的互转成本

`string([]byte)` / `[]byte(str)` 在标准实现里**会拷贝**（为保证字符串不可变语义）。
高频路径（如每请求转一次）上这是隐性开销；可用 `unsafe` 绕过但有安全风险，生产更常用
`bytes.Buffer` / `strings.Builder` 避免中间转换。

### 2.4 map：内存索引的底座

存储引擎的内存索引（如 Bitcask 的 `key → 位置` 哈希表、缓存的 `key → value`）几乎都靠 map。
注意两点：

- map **不是并发安全**的，多 goroutine 读写需 `sync.RWMutex` 或 `sync.Map`（读多写少场景）；
- 遍历顺序**随机**，不能依赖顺序。

### 2.5 Channel：把并发串成管线

第 1 章提到的「一请求一 goroutine」需要用 Channel 收回结果；更典型的用法是**流水线**：

```go
// 教学示意，不参与构建：读写管线（reader -> transformer -> writer）
func pipeline(in <-chan []byte, out chan<- []byte) {
    for chunk := range in {           // for-range 消费关闭的 channel 会自动退出
        out <- transform(chunk)       // select 可与 timeout 结合做超时控制（2.5.3）
    }
}
```

### 2.6 接口与 nil 陷阱

Go 的 `io.Reader` / `io.Writer` / `fs.FS` 都是接口，存储标准库的「可组合」全靠它。
最著名的坑（2.6.3）：**「接口变量为 nil」与「接口内含的指针为 nil」不是一回事**：

```go
// 教学示意，不参与构建：接口 nil 判断陷阱
var p *bytes.Buffer = nil
var r io.Reader = p          // r != nil！因为接口含 (类型=*bytes.Buffer, 值=nil)
fmt.Println(r == nil)        // false —— 常见 bug 来源
```

## 版本演进

- 本章内容（切片/map/channel/接口）属于 Go 1.x 长期稳定的核心，2024 年书出版时与当前一致。
- 🔧 **2026 视角补入**：Go 1.24 引入**弱指针 `weak.Pointer`**（位于 `weak` 包），
  可用于缓存/对象池，避免强引用导致对象无法回收——这是 2.4 map 缓存与第 8 章缓存模式在
  2026 年的新工具，书出版时（2024-08）尚未稳定。
- 🔧 **2026 视角补入**：Go 1.23 的 `iter` 迭代器让 `for range` 可遍历自定义序列，
  第 2 章若重写遍历示例（2.4.3 map 遍历、2.5.4 channel 遍历）可补一段 iterator 写法。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「切片是独立数组」 | 切片是视图，共享底层数组；子切片可能拖住整块内存不被回收 |
| 2 | 「string↔[]byte 转换免费」 | 标准转换会拷贝；高频路径要用 Builder/Buffer 规避 |
| 3 | 「map 并发读安全」 | map 非并发安全；需 RWMutex 或 sync.Map |
| 4 | 「接口变量 == nil 就是空」 | 含 nil 指针的接口 != nil，2.6.3 的坑务必牢记 |
| 5 | 🔧 缓存只讲 map | 2026 年应补 `weak.Pointer`（Go 1.24）做弱引用缓存，避免内存泄漏 |
| 6 | 🔧 遍历示例只给 range | Go 1.23 起可补 `iter` 迭代器写法，更通用 |
