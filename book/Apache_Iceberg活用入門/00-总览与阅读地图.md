## 这本书大概会讲什么（一段话）

Iceberg 是「开放表格式（open table format / ターブルフォーマット）」：它用一层**基于文件的元数据树**（table metadata → snapshot → manifest list → manifest file）把「表的当前状态」描述清楚，让任意引擎都能以 ACID 方式读写对象存储上的 Parquet/ORC/Avro 数据。一本「活用入門」的主线通常是：**为什么需要表格式 → 元数据怎么组织 → 隐藏分区与两类演化 → 行级删除（v2 delete files）→ 乐观并发提交 → catalog（Hive/Glue/REST）→ 日常维护（compaction/expire/orphan）→ 在 Spark/Flink/Trino 里真正用起来**。本目录把这 9 块逐一展开成可核对到规范的笔记。

## 读完本目录应能回答的问题（自查清单）

1. 一次 `INSERT` 之后，对象存储上新增/修改了哪几类文件？为什么 `metadata/` 下的旧文件不能随便删？
2. 为什么改分区方式不需要重写历史数据？新旧两种分区规格如何在一次查询里同时生效？
3. `RENAME COLUMN` 为什么在 Iceberg 里是 O(1) 操作，而在 Hive 表里是危险操作？
4. v2 表上一次 `UPDATE` 会留下什么文件？什么时候该用 CoW、什么时候该用 MoR？delete 文件多了会怎样？
5. 两个引擎同时提交的「冲突」是怎么被发现的？重试时为什么不重写数据文件？
6. `expire_snapshots` 与 `remove_orphan_files` 各自可能「删坏」什么？安全窗口怎么定？
7. REST Catalog 的 `updateTable` 请求体里，`requirements` 起什么作用？
8. Flink 流式写入的 commit 时机由什么决定？Trino 读 v2 表为什么可能比读 v1 表慢？
