## 1.2 OLTP 与 OLAP：两套工作负载物理定律

- **OLTP**：短事务、点读写、高并发、强一致； schema 规范化，容量按行增长。
- **OLAP**：长查询、大范围扫描聚合、低并发高延迟容忍（交互 BI 除外）、吞吐优先； schema 反规范化或
  列式，容量按「行数×列宽×压缩率」评估 ⚠️（转述 learn `overview-terminology` ✅ 与
  `sql-data-warehouse/sql-data-warehouse-overview-what-is` ✅ 对分析系统的定性）。
- 关键推论：数仓引擎的三大件——**扫描（列存）、 shuffle（分布）、缓存（聚合层）**——都是为了对抗
  OLAP 的 I/O 放大。后面 04/05 章的 CCI/分布键/DWU 全部回指这里。

## 1.3 数据仓库、数据集市与维度建模三条路线

- 数仓定义沿用「面向主题、集成、非易失、随时间变化的决策支持数据集合」的经典表述 ⚠️；数据集市是
  面向单一部门/域的切片。
- **星型路线（Kimball 系）**：事实表+维度表、一致性维度、总线矩阵；盘上系统性专著见

  与其姊妹册（方法论纵深在盘可实链，波规点名）。
- **企业规范化路线（Inmon 系）**：先建原子级企业数仓再派生集市；与星型路线的论战在
  Building_the_Data_Warehouse 目录有对位整理 ⚠️ 转述。
- **Data Vault 路线**：Hub/Link/Sat 面向敏捷采集的第三选择，盘上
  [../Data_Vault_2_0/00-总览与阅读地图.md](../Data_Vault_2_0/00-总览与阅读地图.md) 为主参考；
  Synapse 专用池上 Data Vault 落库同样吃「分布键选择」这道物理题（05 章回收）。
- 本章不深入任一方法论，只建立「模型是查询与加载的折中」这一判断框架。

## 1.4 ETL 与 ELT：变换发生在哪一侧

- ETL：抽取→在独立变换引擎里清洗→装载；ELT：原始数据先落湖/仓，用目标引擎算力做变换。
- 书中语境 ⚠️ 推定：Synapse 同时供给两侧——Pipelines 侧是 ADF 血统的集成运行时（07 章），
  SQL/Spark 侧是 ELT 的执行体；湖上 Spark 变换层兴起后，「谁来做变换」变成成本问题而非能力问题
  （对照盘上 [../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md](../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md) 的 dbt 语境 ⚠️ 转述）。

## 1.5 数据湖与「湖的三种口音」

## 1.6 分析工作负载的四个度量

书中概念位 ⚠️ 推定，按工程惯例整理：

1. **延迟**：从提问到首字节结果（交互）或整批完成（管道）；
2. **吞吐**：单位时间处理的扫描量/装载量（与 DWU/Spark 节点数近似线性但有天花板，04/05 章）；
3. **并发**：同时驻留的查询数（受内存/工作负载管理类闸门约束，05 章 resource classes ✅）；
4. **新鲜度**：数据从产生到可查询的时滞——这条在 09 章 Synapse Link 被单独立为产品特性。

## 1.7 角色分工：一个工作区，三种人

- **数据工程师**：管道、湖表、作业编排（06/07 章主场）；
- **数据分析师**：SQL 查询、BI 数据集、语义层（05/08 章主场，Power BI 集成 ✅
  `get-started-visualize-power-bi`）；
- **数据科学家**： notebook、特征、模型训练/服务（06 章 SynapseML 面，✅
  `machine-learning/what-is-machine-learning`）。
- Synapse 的「统一」卖点正是让三种人共享一份存储与一套安全边界（04/08 章回收）。

## 1.8 常见误区（本章视角）

1. **「数据湖=更便宜的数仓」**——错。湖没有仓的扫描/并发语义，直接当仓用会退化成全表扫文件。
2. **「建模是数仓侧的事，湖不需要」**——错。湖上medallion/分层布局（02 章）承担同类职责。
3. **「ELT 让 ETL 工具过时」**——错。拷贝、增量捕获、跨源联邦仍要集成层（07 章），只是变换重心迁移。
4. **「概念章可跳过」**——本书 03 章之后默认你已内化 1.2/1.6 的判断框架，跳读者会在 05 章掉队。

## 核心概念速览（中英对照）

- **联机分析处理** — OLAP：大范围扫描聚合的分析负载形态，与 OLTP 短事务相对。
- **数据集市** — Data Mart：面向单一业务域的数仓切片，星型模型最常见载体。
- **星型模式** — Star Schema：事实表居中、维度表放射的模型；Kimball 系方法论核心工件。
- **一致性维度** — Conformed Dimension：跨集市可复用、口径统一的维度，总线矩阵的前提。
- **ETL / ELT** — Extract-Transform-Load / Extract-Load-Transform：变换发生在独立引擎 vs 目标引擎。
- **数据湖** — Data Lake：对象存储上的原始数据集合，schema-on-read。
- **开放表格式** — Open Table Format：Delta/Iceberg/Hudi 为裸文件补上事务与元数据层 ✅ 官网。
- **新鲜度** — Data Freshness/Latency：数据产生到可查询的时滞，09 章 Link 的产品化指标。
- **扫描吞吐** — Scan Throughput：分析引擎的第一物理量，列存与分布皆为其服务。
- **角色三分** — Engineer/Analyst/Scientist：数据工程师、数据分析师、数据科学家的分工视角。
