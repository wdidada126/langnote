## 2.5 湖仓的账本：性能从哪来——🔧E3 实验（非 Synapse 引擎/平台行为）

湖上裁剪的第一性原理是**文件/行组级 min-max 统计**。DuckDB 实测（DuckDB 1.5.5，非 Synapse，
仅机理类比；对照 Synapse Serverless 对 Parquet 谓词下推、专用池 CCI 段压缩的 min-max 剪枝 ⚠️ 转述
✅ `sql/query-parquet-files`、`sql-data-warehouse/performance-tuning-ordered-cci`）：

```text
> COPY (SELECT * FROM fact ORDER BY m) TO 'sorted.parquet' (ROW_GROUP_SIZE 120000)     -- 2,000,000 行
> COPY (SELECT * FROM fact ORDER BY random()) TO 'shuffled.parquet' (ROW_GROUP_SIZE 120000)
parquet_metadata('sorted.parquet')   列 m 前 3 行组:
  [('m', 0, '0', '6041'), ('m', 1, '6041', '12083'), ('m', 2, '12083', '18124')]
parquet_metadata('shuffled.parquet') 列 m 前 3 行组:
  [('m', 0, '1', '99998'), ('m', 1, '0', '99999'), ('m', 2, '0', '99995')]
count(*) WHERE m BETWEEN 5000 AND 5100:
  有序文件 count=(2020,) t=0.007s | 乱序文件 count=(2020,) t=0.009s
```

- 读法：有序文件的行组 min/max 互不重叠，谓词可**整段跳过**；乱序文件每个行组都覆盖全域
  (0..99998)，统计失效。本地小文件耗时差被缓存/规模压平，但**元数据形态的差异是架构级的**：
  这正是「聚簇/排序键」「CCI 段裁剪」「按日分区」共同依赖的机理——把选择性好的键排进物理布局。
- 工程处方（跨引擎通用）：落湖时按高频过滤列排序/分桶；仓内时把该列作为分布/排序键候选。

## 2.6 「过渡」的务实路径（副题的三层含义）

1. **装载过渡**：ETL 直灌仓 → 先落湖、仓做视图/外部表（05 章），再按 SLA 决定是否物化进专用池；
2. **算力过渡**：单一 SQL 引擎 → SQL+Spark 双引擎共享一份湖数据（04 章）；
3. **组织过渡**：DBA 独掌仓 → 数据工程/分析/科学共驻一个工作区（08 章角色面）。

每一步都可用 1.6 节四个度量（延迟/吞吐/并发/新鲜度）做「是否值得」的判定，而不是信仰驱动。

## 2.7 常见误区

1. **「湖仓=湖+仓两个都要」**——资源翻倍不是目标；合流判据是 2.5 的裁剪与事务语义能否在一处成立。
2. **「MPP 已过时」**——2026 年 Fabric data warehouse 仍保留分布+列存骨架 ⚠️（✅
  `fabric/data-warehouse/guidelines-warehouse-performance`），过时的是「无弹性预置」而非并行原理。
3. **「表格式选错就满盘皆输」**——多引擎可读写共存渐成常态，但迁移成本真实存在，选型见盘上四册 ⚠️。
4. **「按扫描量计费一定省钱」**——重复用、高并发的稳定负载下，预置型（DWU 类比）常反超；本章
  给出的账本框架正用于此类判定 ⚠️ 转述。

## 核心概念速览（中英对照）

- **共享无架构** — Share-nothing MPP：数据按分布键切片到多节点并行执行的数仓主干架构。
- **容量单位** — Data Warehouse Unit (DWU)：专用池预置算力的计费/伸缩单位 ✅ 文档存在（04 章展开）。
- **裸湖语义真空** — Schema-on-read Gap：对象存储原始文件缺 ACID/隔离/时间旅行的状态。
- **开放表格式** — Open Table Format：Delta/Iceberg/Hudi，为裸文件补事务与元数据 ✅ 官网。
- **湖仓** — Lakehouse：以湖成本提供仓语义的合流架构；定义出处 CIDR 2021 ✅ PDF。
- **Lambda/Kappa** — 批流双路对账 / 一切皆流：2011–2017 架构争论的两极，湖仓试图超越之。
- **行组统计裁剪** — Row-group Min/Max Pruning：🔧E3 演示的湖上第一性加速机理（非 Synapse）。
- **外部表** — External Table：仓/Serverless 引擎把湖文件当表读的桥接工件（05 章）。
- **Medallion 分层** — Bronze/Silver/Gold：湖仓工程惯例分层（盘上湖仓册有系统化整理 ⚠️）。
- **过渡三态** — Load/Compute/Organization Transition：副题「从仓到湖仓」的三条落地路径。
