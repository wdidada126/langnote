## 4.2 存储底座：工作区绑定 ADLS Gen2（2021 语境）

- 建工作区时必须绑定一个 Azure ADLS Gen2 存储账户作为**默认文件存储**：笔记本、外部表、Delta 目录、
  Spark 临时区共享同一账房 ⚠️（转述 ✅ `overview-what-is`、`get-started-create-workspace`）。
- 专用池的仓内数据是**另一套存储**（DMS 暂存区+列存段 ⚠️），不等同于湖——「湖仓一体」在 2021 是
  「一个平台两种存储」的务实拼接，真正单存储收敛发生在 Fabric OneLake 时代（演进节）。
- 读法提示：把「数据在哪」当作架构第一问——同表数据湖侧/仓侧各一份时，新鲜度与一致性都要单独记账。

## 4.3 MPP 专用池的解剖（承 02/03 章血统）

- 三层经典分解 ✅ `sql/overview-architecture`：
  1. **控制节点**（查询解析/计划/协调，SQL Server 系优化器语义在此层 ⚠️）；
  2. **计算节点**（分布数据的并行执行，DMS 移动数据）；
  3. **共享存储层**（列存 CCI 段 + 暂存区）。
- 这是 **share-nothing MPP 的托管化**：与 Redshift（RA3 解耦化）、Snowflake（存算分离）的取舍不同——
  Synapse 保留「数据驻节点、按分布键局部化」的经典形态，收益是 join 局部性（05 章 🔧E2 类比其机理）。

## 4.4 Serverless SQL 与 Spark：湖侧的两个引擎

- **Serverless SQL**：从 PolyBase/Cosmos 分析线演化而来的按需 TDS 端点 ✅
  `sql/on-demand-workspace-overview`；语义=「对湖文件的 SQL」，能力位=外部表/视图 + OPENROWSET +
  三段式命名 ✅ `sql/develop-storage-files-overview`。
- **Spark 池**：托管 Spark 运行时 + Synapse 存储绑定 ✅ `spark/apache-spark-overview`；语义=
  「湖上原生 DataFrame/Delta 工作负载」，与 SQL 面共享同一份 Parquet/Delta 目录是卖点也是陷阱
  （类型系统/时区/十六进制字面量差异 ⚠️，06 章回收）。
- 选型一句话：**交互 BI 与 SQL 资产复用走 Serverless；重变换、ML、复杂控制流走 Spark** ⚠️ 推定处方。

## 4.5 集成面与 Link 面（07/09 章的架构位）

- **Pipelines**：内置 ADF 服务实例（工作区自动创建一个免费 ADF 资源 ⚠️）✅ `get-started-pipelines`；
  架构位=「数据的进出与编排」，不是变换引擎本体。
- **Synapse Link**：源系统（Azure SQL DB/Cosmos/SQL Server 2022/Dataverse）到湖+仓的**旁路复制**
  通道 ✅ `synapse-link/sql-synapse-link-overview`；架构位=新鲜度轴的产品化（01 章 §1.6）。

## 4.8 架构速读五问（本章自检 ⚠️ 推定组织）

1. **数据此刻在哪一层？**——湖（ADLS Gen2 目录）/仓（DMS 分布+CCI 段）/中转（暂存区）三选一；
   答错则优化方向整体错位（02 章 §2.3 的语义真空教训）。
2. **谁在协调这条查询？**——控制节点（解析/计划）在专用池侧；Serverless 的协调者是其无状态端点层；
   Spark 则是 driver/executor 模型——同平台三套「大脑」，故障排查入口完全不同（✅
   `sql/overview-architecture`、`sql/on-demand-workspace-overview`、`spark/apache-spark-overview`）。
3. **移动的是数据还是代码？**——分布键命中=谓词下沉、结果上行；未命中=DMS shuffle 搬表（05 章 🔧E2
   的桶图景）；Spark 侧同理看分区键与文件布局。
4. **这条链路的账单挂在哪面？**——DWU 常驻时长/处理字节/核心时/管道活动数（4.6），架构评审要同页
   展示性能目标与计量面映射 ⚠️。
5. **横切层是否先于业务负载就绪？**——网络三态选型、RBAC 双层设计、监控接入、Git 发布线（08 章）；
   横切欠账会在容量爬坡时集中爆发（✅ `guidance/security-white-paper-introduction`）。

- 五问覆盖本章全部箱体；把答案写成架构评审模板即可复用（本册编者处方 ⚠️ 非书页逐字）。

## 核心概念速览（中英对照）

- **控制平面/数据平面** — Control/Data Plane：编排管理与执行/存储的分界，工作区形态的架构骨架 ⚠️。
- **默认存储绑定** — Default ADLS Gen2 Binding：工作区创建时绑定的湖账房（2021 语境）✅。
- **三层 MPP** — Control/Compute/Storage：专用池的控制节点-计算节点-共享存储分解 ✅ overview-architecture。
- **DMS** — Distributed Moving Services：跨分布节点搬数据的内部机制 ⚠️（谱系承 APS/PDW）。
- **两段式湖仓拼接** — Platform-not-convergence：湖与仓两套存储在一个平台并存，04 章核心诚实点。
- **引擎双岸** — SQL岸/Spark岸：Serverless（湖上 SQL）与 Spark（湖上原生）的选型对照，4.4 节。
- **旁路复制** — Side-car Replication：Link 不入侵源库的通道形态（09 章）✅。
- **Synapse RBAC** — 工作区级角色模型：覆盖 Spark/管道/监控/元数据的细粒度角色 ✅。
- **Monitoring Hub** — 监控中心：一个入口看 SQL/Spark/管道三类作业 ✅ get-started-monitor。
- **计费横切** — Per-plane Billing：DWU/按处理量/核心时/活动数四套计量并存（03 章 §3.4）⚠️。
