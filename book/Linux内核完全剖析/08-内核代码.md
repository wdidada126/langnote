# 第 8 章 内核代码

> **本章地图**：内核的**核心数据结构**（`task_struct` 的极简版、`system` 段、`GDT`、缓冲头）→ `sched.c`（调度、定时器中断、`schedule()`、`sleep_on/wake_up`、哲学家进餐式的经典同步）→ `fork.c`（`find_empty_process`、`copy_process`、写时复制）→ `signal.c`（信号发送/处理/默认动作）→ `sys.c`（系统调用表与常见 `sys_*`）→ `trap.c`（异常与系统调用的统一入口）→ `system_call.s`（从汇编码到 C 的桥）。
>
> 一句话结论：**这八千行代码就是 Linux 的「灵魂」**——进程、调度、信号、系统调用四条主线在此汇合。读懂 `sched.c` + `fork.c`，你就读懂了操作系统最核心的一半。

| 文件 | 内容 | 结论 |
| --- | --- | --- |
| 内核数据结构 | `task_struct`、`GDT`、`TSS`、缓冲头 | 所有子系统的内存布局在此之前定型 |
| `sched.c` | `do_timer()`、`schedule()`、`sleep_on/wake_up`、`sys_*` | 内核的「心跳」与「调度心脏」 |
| `fork.c` | `find_empty_process()`、`copy_process()`、`copy_mem()` | 写时复制的教科书实现 |
| `signal.c` | `send_sig()`、`do_signal()`、默认动作表 | sender / kernel / handler 三段式 |
| `sys.c` | `sys_fork/execve/open/close/read/write/lseek` 等 | 系统调用号 → 处理函数的映射表 |
| `trap.c` | 异常表与 `do_*` 处理函数、`page_fault` | 硬中断与异常的 C 侧入口 |
| `system_call.s` | `system_call` 汇编入口 | 「一条 `int 0x80` 如何变成一次函数调用」 |

## 核心精讲

> 以下代码均为**教学示意，不代表可编译运行**；变量名为 0.11 风格。

### 8.1 核心数据结构：`task_struct` 的极简形态

```c
/* 教学示意，不代表可编译运行：0.11 风格的 task_struct 骨架 */
struct task_struct {
    long state;              /* -1 不可运行, 0 可运行, >0 已停止 */
    long counter;            /* 剩余时间片 */
    long priority;           /* 静态优先级 */
    long signal;             /* 待处理信号位图 */
    long sigaction[32];      /* 每个信号的处理函数指针 */
    int exit_code;           /* 退出码，供 wait() 取回 */
    unsigned long start_code, end_code, end_data, brk;
    unsigned long esp0, eip;
    unsigned short ss0;                     /* 内核栈段 */
    struct ldt_struct ldt;                  /* 本进程的 LDT */
    struct tss_struct tss;                  /* 本进程的 TSS */
};
```

```text
; 教学示意：0.11 的 GDT 前几项（sched_init 中设置）
;   GDT[0] 0000000000000000h    占位（段选择子 0 不可用）
;   GDT[1] 00cf9a0000000fffh    _CS  内核代码段（0x08）
;   GDT[2] 00cf920000000fffh    _DS  内核数据段（0x10）
;   GDT[3] 00cf9a0000000fffh    系统段（0x18）
;   GDT[4] ----------------    TSS0（sched_init 中填）
;   GDT[5] ----------------    LDT0（sched_init 中填）
```

> **关键设计**：每个进程的 **TSS / LDT** 描述符放在 GDT 里，切换进程时 `TR` 指向新进程的 TSS；Linux 实际只用 TSS 存**内核栈指针 `SS:ESP`**，其余现场都是软件保存。

### 8.2 `sched.c`：内核的心跳与心脏

#### `do_timer()` —— 每 10 ms 一次

```c
/* 教学示意，不代表可编译运行 */
void do_timer(void)
{
    if (--current->counter <= 0) {
        current->counter = 0;
        need_resched = 1;          /* 只置「软」调度标志 */
    }
}
```

> 🔧 现代内核里 `do_timer()` 演进为 `tick_handle_periodic()` / `sched_tick()`，配合 **tickless (`CONFIG_NO_HZ`)** 与 CFS 的 `vruntime` 更新。

#### `schedule()` —— 从所有就绪进程中挑一个

```c
/* 教学示意，不代表可编译运行：0.11 的 schedule() 核心 */
void schedule(void)
{
    int i, next, c;
    struct task_struct **p;

    /* 遍历 task[1..NR_TASKS]，找 state==TASK_RUNNING 且 counter 最大者 */
    while (1) {
        c = -1; next = 0; p = &LAST_TASK;
        for (i = NR_TASKS; i > 0; i--, p++)
            if (*p && (*p)->state == TASK_RUNNING && (*p)->counter > c)
                c = (*p)->counter, next = *p;
        if (c) break;                 /* 找到了时间片最多的进程 */
        /* 本轮全部耗尽：counter 减半再加 priority，重新轮转 */
        for (p = &LAST_TASK; p > &FIRST_TASK; --p)
            if (*p) (*p)->counter = ((*p)->counter >> 1) + (*p)->priority;
    }
    if (next == current) return;
    switch_to(next);                 /* 真正的上下文切换 */
}
```

```c
/* 教学示意，不代表可编译运行：switch_to 的汇编侧（sched.s 形态） */
switch_to:
    movl %esp,%eax              ; eax = 旧内核栈指针
    movl current,%eax
    xchgl %eax,%edx             ; edx = 旧 current, eax = 新 current
    movl %edx,%esp              ; 抛出旧栈，切入新内核栈
    lret                        ; 跳到新进程在栈上预留的断点
```

> 理解要点：Linux 只用 TSS 存 **`SS:ESP`**（内核栈指针），通用寄存器靠软件在栈上保存，最后用一条 `lret` 跳到新进程断点。这是 Linux 调度快的关键。

#### `sleep_on` / `wake_up`：同步原语的原始形态

```c
/* 教学示意，不代表可编译运行：sleep_on 与 wake_up */
void sleep_on(struct task_struct **p)
{
    struct task_struct *tsk;
    if (!p || *p == current) return;
    tsk = *p; *p = current;
    current->state = TASK_UNINTERRUPTIBLE;   /* 不可打断睡眠 */
    schedule();                              /* 主动让出 CPU */
    current->state = TASK_RUNNING;           /* 被 wake_up 唤醒后 */
    if (tsk && tsk->state == TASK_UNINTERRUPTIBLE) wake_up(&tsk);
}

void wake_up(struct task_struct **p)
{
    if (p && *p) { (**p).state = TASK_RUNNING; *p = NULL; }
}
```

> ⚠️ **这是「哲学家进餐 / pv」问题的直接历史对应物**（原书页面留有该摘录，与 `book/多处理器编程的艺术.md`、`courses/操作系统/NJUOS/notes/outline.md` L11–L12 同源）。
> 断言：这个实现**不正确**——不保证唤醒队列的 LIFO 顺序，可能唤醒错进程；若被唤醒进程在 `wake_up` 前被抢占，链会断。
> 🔧 现代内核的对应物是 `wake_up_process()` + `try_to_wake_up()` + `ttwu_queue()`，以及 RCU 保护的等待队列。

### 8.3 `fork.c`：进程创建与写时复制

```c
/* 教学示意，不代表可编译运行：find_empty_process() */
int find_empty_process(void)
{
    int i;
    for (i = 1; i < NR_TASKS; i++)
        if (!task[i]) return i;      /* 找到空槽 */
    return -1;                       /* 已满，fork 失败 */
}
```

```c
/* 教学示意，不代表可编译运行：copy_process() 的核心动作 */
int copy_process(int nr, ...)
{
    p = (struct task_struct *) get_free_page();
    *p = *current;                   /* 1) 浅拷贝 task_struct */

    p->state  = TASK_UNINTERRUPTIBLE;
    p->father = current->pid;
    p->counter = p->priority;        /* 2) 子进程拿到完整时间片 */
    p->signal = 0;
    p->tss.esp0 = kernel_stack_top;  /*    并换用新内核栈 */
    p->tss.ss0 = _DS;

    copy_mem(nr, p);                 /* 3) 页表项共享并置只读 → CoW */
    set_ldt_desc(gdt + (nr << 1) + FIRST_LDT_ENTRY, &p->ldt, 2);  /* 4) LDT */
    task[nr] = p;                    /* 5) 入就绪队列 */
    return nr;
}
```

```text
; 教学示意：copy_mem 的写时复制核心（page.s 中 copy_page_tables 形态）
;   对父进程每个页表项：
;     if (page & 1) {                  ; P = 1
;         page &= ~2;                  ; 清 R/W → 变只读
;         母、子页表项同时指向该物理页  ; 共享
;     }
;   任一方写该页 → #PF(W/R=1) → do_wp_page() 分配新页并复制
```

> **写时复制三步**：①父子共享物理页；②页表项清 `R/W`；③写时 `#PF`，`do_wp_page()` 真正分配并拷贝。这是 CoW 最早的落地，也是今天 `mm/cow_*.c` 的思想源头。

### 8.4 `signal.c`：信号的 sender 侧

```c
/* 教学示意，不代表可编译运行 */
void send_sig(long sig, struct task_struct *to, int priv)
{
    if (to->signal & (1 << (sig - 1)))  return;   /* 已排队，不去重 */
    to->signal |= 1 << (sig - 1);                 /* 置位图 */
    if (!to->sigaction[sig - 1].sa_handler)
        to->state = TASK_RUNNING;                 /* 默认动作：可能直接杀 */
    else if (to->state == TASK_STOPPED) to->state = TASK_RUNNING;
}
```

```text
; 教学示意，不代表可编译运行：do_signal 在「返回用户态之前」被调用
;   handle_signal(sig, signr, regs):
;      若 handler 是 SIG_DFL/SIG_IGN → 走默认动作
;      否则在**用户栈**上伪造 pt_regs，把返回地址改成 handler 入口
;      之后 sigreturn 系统调用恢复现场
```

> 两条必须知道的规则：
> 1. 信号**不立刻执行**，而是在「从内核返回用户态之前」（`system_call` / 中断返回路径）才被处理；
> 2. handler 运行在**用户态**，所以异常/陷阱不会在 handler 里直接发生。

### 8.5 `sys.c` 与系统调用入口

```c
/* 教学示意，不代表可编译运行：系统调用号 → 处理函数表 */
long (*sys_call_table[])(void) = { sys_fork, sys_exit, sys_open, sys_close,
                                   sys_read, sys_write, sys_wait4, ... };
```

```asm
; 教学示意，不代表可编译运行：system_call 汇编入口（system_call.s 形态）
system_call:
    cmpl $(NR_SYSTEM_CALLS-1), %eax     ; syscall number 越界检查
    ja    bad_sys_call
    pushl %edx / %eax / %ecx / %ebx     ; 保存参数与号（供 restart 用）
    movl %fs, %ds                       ; FS 提供「用户数据段」视图
    call  *SYSCALL_DESCRIPTOR(%eax*4)   ; 表跳转
    add  $20, %esp                      ; 清参数
    ret                                 ; 返回用户态（顺便处理信号）
```

| 机制 | 0.11 | 🔧 现代 |
| --- | --- | --- |
| 指令 | `int 0x80`（软中断） | `syscall`，`int 0x80` 仅兼容保留 |
| 传参 | `eax`=号，`ebx/ecx/edx`=参 | `rax`=号，`rdi/rsi/rdx/…`=参 |
| 表 | 函数指针数组 | `arch/x86/entry/syscall_64.c` 的 `__SYSCALL` 宏表 + seccomp |
| 跳转 | 直接 call | `do_syscall_64` → `syscall_enter_from_user_mode` |

### 8.6 `trap.c`：异常的统一入口

```c
/* 教学示意，不代表可编译运行 */
void page_fault(unsigned long eax, unsigned long error_code, ...)
{
    unsigned long addr = current->address;   /* CR2 在 asm 侧已存到 task */
    if (error_code & 1)                      /* bit0: 0=内核, 1=用户 */
        do_wp_page(...);                     /* 写时复制 / 写保护 */
    else
        do_no_page(...);                     /* 真正的缺页 */
}
```

> 0.11 用**「异常表 + 地址检查」**的旧式保护：缺页靠 `current->address` 与异常表的地址范围判断合法性。🔧 现代是 `vm_area_struct`（VMA）体系与 `handle_mm_fault()`。

## 近年研究与工业界开源实践（2015–2026）

- **调度器的三次换代**：O(1)（2.6，2003）→ CFS（2.6.23，2007）→ **EEVDF（6.1，2023 起默认）**。可在 `torvalds/linux`（**250112★**）的 `kernel/sched/` 里逐级对照：`sched/sched.c`、`sched/fair.c`、`sched/rt.c`。
- **内核抢占**：现代内核有 `CONFIG_PREEMPT_DYNAMIC`，把「自愿/抢占」做成运行期可选，与 0.11 的「不可抢占」差异最大。
- **观测与调优的真实工具**：`brendangregg/FlameGraph`（**19773★**）+ perf；`iovisor/bpftrace`（**10343★**）与 `libbpf/libbpf`（**2758★**）可在生产环境里动态观察调度延迟与 `runqlat`，完全取代 `printk` 排错。
- **真实案例**：`cilium/cilium`（**25549★**）大量依赖 eBPF 做调度可见性与网络卸载；`systemd/systemd`（**16746★**）负责用户态 1 号进程与 signal 语义的落地。
- **学习用最小内核**：`mit-pdos/xv6-public`（**9646★**）的 `proc.c`、`trap.c`、`sysfile.c` 与本章同名文件可按行对照；`mit-pdos/xv6-riscv`（**10516★**）则可对比 RISC-V 上的重写。
- **Rust 视角**：`Rust-for-Linux/linux`（**4413★**）、`fishinabarrel/linux-kernel-module-rust`（**1336★**）展示了把进程管理代码用更安全语言重写的路径。

## 常见误区与本书需修正之处

| # | 说法/写法 | 修正与补充 |
| --- | --- | --- |
| 1 | 「`sleep_on/wake_up` 是安全的同步原语」 | **不安全**：不保证唤醒顺序、可能被抢占导致链断裂；🔧 现代用 `wake_up_process` + `wq` + RCU，且引入 `TASK_KILLABLE` |
| 2 | 「`do_timer` 里直接调用 `schedule()`」 | 只置 `need_resched` 标志，实际切换在返回用户态/内核态的出口处做 |
| 3 | 「调度是 O(n) 遍历，慢」 | 0.11 确实是 O(n)；🔧 O(1) → CFS（`rb-tree` + `vruntime`）→ EEVDF，复杂度与公平性都换了算法 |
| 4 | 「内核不可抢占」 | 🔧 现代内核可抢占；`CONFIG_PREEMPT_DYNAMIC` 让调度延迟进入毫秒级 |
| 5 | 「`fork` 是复制内存」 | 0.11 靠写时复制（页表项置只读）；今天连页表本身都是 RCU 保护的共享对象 |
| 6 | 「进程切换用 TSS 保存现场」 | Linux 只用 TSS 存 `SS:ESP`；通用寄存器靠软件保存；硬件任务切换在 x86 上已不常用 |
| 7 | 🔧 「信号在 `send_sig` 时立刻执行」 | 它在返回用户态前的 `do_signal` 才执行；`sigreturn` 负责恢复现场 |
| 8 | 🔧 「`int 0x80` 就是现在的系统调用」 | 现代用 `syscall`；且新增了 `seccomp`、restrict 与 LSM 钩子 |
| 9 | 🔧 「单 CPU 的假设仍成立」 | 多核 + NUMA 是默认；调度需考虑 smp 负载均衡、RCU 同步、per-CPU 变量 |
