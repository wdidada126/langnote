# 第 13 章 内存管理

> **本章地图**：物理内存记账（`mem_map[]` 字节数组 + `get_free_page`/`free_page`）→ 分页初始化 `paging_init` 与内核页表布局 → 写保护异常与 COW（0.11 的「**所有页面预先映射、只用 WP 位触发缺页**」这一关键技巧）→ `fork()` 的 `copy_page_tables` 页表复制 → 交换子系统 `swap.c`（`swap_map[]`、`swap_out/try_to_free_page`）→ 缓冲缓存与磁盘缓冲区共享页面。核心结论：0.11 的内存管理是一个 **「线性扫描位图 + 一阶分页 + 无 cgroup/无 NUMA/无 SLUB」** 的最小可用系统，它把「分页」这一 hardware feature 用到了极致，却完全没有现代内核的「可视化与策略」层次。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 13.1 `mem_map[]` 与页面计数 | `unsigned char mem_map[PAGING_PAGES]`，单字节引用计数 | 分配 = **线性扫描找一个 0**，无 per-cpu 缓存、无伙伴算法 |
| 13.2 分页初始化 | `paging_init()` 建立页目录、映射低端内存、载入 `cr3`、置 `cr0.WP` | 1:1 映射内核空间；第 0 个 4MB 用于 video/BIOS 保留区 |
| 13.3 `get_free_page` / `free_page` | 低位前缀扫描、`mem_map[i]--`、`clear_page` | 「页面清零」是分配时就做的，成本低 |
| 13.4 写保护与 COW | `do_wp_page()`：写保护异常 → `get_free_page` + `copy_page`；0.11 用它兼作「缺页」 | 0.11 **没有**独立的 do_no_page，需求分页靠 wp-fault 完成 |
| 13.5 页表复制与 fork | `copy_page_tables()`：复制低 4MB 页表，`MEM_SHARED` 位决定是否共享 | fork 的「写时复制」在**页表层面**手工完成，不利用 CPU 的 COW（因为 x86 没有 PTE 的 COW 位） |
| 13.6 进程地址空间布局 | 0–4MB 用户，4MB–（4MB+缓冲）内核缓存，更高为任务/缓冲 | 地址空间**整体一次性映射**，靠 PF 位区分是否真实存在 |
| 13.7 `swap.c` | `swap_map[]`、`swap_readpage/swap_write_page`、`try_to_free_page`、`swap_out` | 换出粒度是**整页**；swap 用磁盘上 4KB 页对应一页物理内存 |
| 13.8 缓冲与交换的耦合 | `fs/buffer.c` 与 `mm/swap.c` 共用 `mem_map` 与页面释放 | 文件系统要通过「标记可回收」参与内存回收，这正是 0.11 的粗糙处 |
| 13.9 缺失的现代层次 | SLUB/SLOB、kmemcg、THP、zRAM/zswap、MGLRU、folio、NUMA | 🔧 全部缺失（详见下节） |

## 核心精讲

> 以下均为**教学示意，不代表可编译运行**。

### 13.1 物理内存记账：一个字节代表一页

```c
/* mm/memory.c —— 教学示意，不代表可编译运行 */
#define PAGING_SIZE (1024*1024/4096)
#define PAGING_PAGES (PAGING_SIZE)
extern unsigned char mem_map [PAGING_PAGES] = {0,};

unsigned long get_free_page (void)
{
    unsigned long ret;
    int i;
again:
    for (i = 0; i < PAGING_PAGES; i++)
        if (!mem_map[i])
            break;
    if (i >= PAGING_PAGES)              /* 内存不足：这里只是「打到队的尾部」 */
        return 0;
    ...
}
```

- `mem_map[i]` 是**引用计数**（不是 0/1 标志），值为 3 表示「被 3 个地方引用」；归零才可被分配。
- 分配是 O(页面总数) 的线性扫描。16MB 机器有 4096 页，扫描一次还行；但如果系统里有 GB 级内存，这就是 O(n) 的热点。
- 🔧 现代内核：物理页记账是 `struct page` 的 `_refcount`/`_mapcount`（每页一个**结构**而不是一个字节），加上 **per-cpu pageset** 的快速路径（`rmqueue_bulk`），典型分配只需几条指令。

### 13.2 分页初始化与内核空间布局

```c
/* mm/memory.c —— 教学示意，不代表可编译运行 */
void paging_init(void)
{
    ...
    /* 1) 清空一页作为临时页表 */
    clear_page((unsigned long) &tmp_page);
    /* 2) 把 0–4MB 的页表填好，指向自身（自映射线性地址） */
    ...
    /* 3) 建立 0x00000000 起的页目录项 */
    page_dir[0] = low_1mb << 12;      /* 前 1MB 保持 identity 映射 */
    ...
    /* 4) 写入 cr3 并打开分页 */
    set_pg_dir(pg_dir);
}
```

- 0.11 的分页是**手工 1:1 映射**：内核虚拟地址 = 物理地址（在 i386 上默认 `0xC0000000` 以上，但 0.11 时代还没真正启用高端内存 helper）。
- 地址空间约定（来自 `boot/head.s` 的 `memory_map`）：
  - `0 ~ 640KB`：低内存（含 video、BIOS 数据区），不可全部分配；
  - `1MB ~ 4MB`：内核代码；
  - `4MB` 以上：用于**磁盘缓冲区**与**用户进程页表**；
  - `F0000000` 附近：任务数据结构。
- 🔧 现代内核：分页由 `paging_init()`（`arch/x86/mm/`）完成， **`CONFIG_HIGHMEM`** 引入高端内存与 `struct page` 的 `memblock` 早期分配器；**`set_memory_rw`/`set_memory_x`** 取代直接改页表；并且内核空间与用户空间的分界由 `PAGE_OFFSET`（`__PAGE_OFFSET = 0xC0000000` 在 32 位）决定。

### 13.3 页表项与 0.11 的「假缺页」技巧

```c
/* 教学示意，不代表可编译运行 —— 0.11 风格 */
/* 页目录项与页表项：存在位 P=1，但「用户可读」而不可写 */
#define PAGE_DIRTY  0x40
#define PAGE_PRESENT 0x7   /* P|R/W|U/S —— 注意：P 恒为 1，R/W 清 0 */
```

关键洞见（本书反复强调的一段）：

- 0.11 在进程创建时**把 4GB 地址空间中用户能到的范围都按「不可写、存在」填好**；
- 于是任何对不存在的页表的访问，都会触发 **「写保护异常」（而非 present=0）**，因为 P 位一直是 1；
- `do_wp_page()` 收到异常后判断 `write_fault`，这时才真正分配一页、填好页表项、并 `un_wp_page()` 打开写权限。

```c
/* mm/memory.c —— 教学示意，不代表可编译运行 */
void do_wp_page(unsigned long error_code, unsigned long address)
{
    ...
    if (!(error_code & 4)) {  ...
    if (write_fault && !(error_code & 1) ...) {
        ...
        page = get_free_page(GFP_HIGH);   /* 现分配 */
        copy_page(page, ...);             /* 复制父进程内容（fork 场景） */
        ...
        un_wp_page(address);              /* 把 PTE 改成可写 */
    }
}
```

- 这一步的技巧性极强：**用 WP 位代替 P 位**做缺页检测，省了大量页表项的「不存在」分支。
- 但它也意味着 0.11 的 COW 是**软件模拟的**（先复制再改权限），而不是 x86 硬件按 PTE 的 COW 语义自动  trap 一次再修复。
- 🔧 现代内核：`do_wp_page()` 仍在（处理真·写保护），但需求分页的入口是 `handle_mm_fault()` → `do_fault()`，配合 **FAULT_FLAG_WRITE / FAULT_FLAG_WP**、MAP_POPULATE、PMD 级别的 huge page fault（`pmd_fault`）、以及 `folio` 的批量映射。

### 13.4 `fork()` 与页表复制

```c
/* mm/memory.c —— 教学示意，不代表可编译运行 */
int copy_page_tables(struct task_struct *p)
{
    ...
    for (entry = 0; entry < 0x1000000 / 4096 / 4; entry++) {
        old_pg_table = *pg_table;
        if (!(old_pg_table & PG_PRESENT)) continue;   /* 尚未建立的页表跳过 */
        ...
        copy_mem = 1;
        if (!(1 & old_pg_table)) {          /* 该页表不共享 → 复制 */
            ...
            *pg_table = ...;                /* 子进程的页表项 */
            ...
        }
    }
}
```

- 复制的是**页表本身**，然后把所有复制出来的页表项**改为写保护**（`if (mem_map[i] ... )` 处调用 `mem_map_used`），最后 `share_pages` 让父子共享物理页。
- 因此 fork 的成本 ≈ 复制一整套页表（`NR` 个页表项），与今天「惰性复制页表（`copy_present_pte`/`alloc_pgt`）」思路一致，只是 0.11 不做惰性。
- 🔧 现代内核：`copy_process()` → `copy_mm()` → `dup_mm()`/`copy_present_pte()`，Fork 时会**只复制 present 的 PTE**（惰性建表），对 huge page 用 `copy_present_pte` 的 PMD 短路；还引入 **`idle` thread 的 `mm` 共享 / RCU 保护的 page table 释放**。

### 13.5 交换（`swap.c`）

```c
/* mm/swap.c —— 教学示意，不代表可编译运行 */
static unsigned char swap_map[16384] = {0,};   /* 每页物理内存对应磁盘的一页 */

void swap_out(int dev, unsigned long *swap_map, ...) { ... }
static void try_to_free_page(unsigned long d) { ... }
static unsigned long swap_readpage(unsigned char *buffer, unsigned long offset) { ... }
```

要点：

- 交换区在磁盘上是**每页 4KB 一个槽位**，`swap_map[]` 记录每个槽位的被引用次数（多个进程共享同一页面时 > 1）；
- `try_to_free_page()` 会「从 tail 找最老的页 → 若是脏页先写回 → 若是共享页只减计数 → 独占页才能释放」；
- 页表项在换出后被改成「**换出页标识符**（高 24 位 + swap type）」，再次访问时触发 `do_wp_page`/page fault 读到内存。
- 🔧 现代内核：交换机制演化为 **`swap_slots` + `swapcache` + `swap readahead` + `zswap/zram` 压缩后端**；`try_to_free_page()` 早已被 `shrink_folio_list()` 取代；并且**文件页也可以被「换出」（page cache 回收）**，不只有匿名页。

### 13.6 内存回收与页缓存的交界

0.11 里文件系统自己维护 `b_dirt`、`b_lock` 等标志，靠「谁先感觉内存紧张」来决定谁回收，属于**无统一回收框架**的设计。

- 这直接导致了后来的重构：2.4/2.5 时代建立了**统一的页缓存 + 交换一体化**的回收路径（`shrink_dirty_memory`、`balance_dirty_pages`）。
- 🔧 现代：`mm/vmscan.c` 的 `shrink_node()` 同时扫匿名页与文件页，用 `zone->lruvec`（`LRU_INACTIVE_ANON` 等 6 个链表）排序，还有 `kswapd` / `direct reclaim` / `memcg` 回收三层。

## 版本演进

| 时间 | 内核版本 | 事件 |
| --- | --- | --- |
| 1991–1994 | 0.11 | `mem_map` 字节数组 + 一阶分页 + WP 位假缺页 + 软交换；无 SLUB、无 NUMA 感知 |
| 2000–2002 | 2.3/2.4 | **O(1) 调度器时代**：页表锁定（`mmap_sem`）成为主要瓶颈；`buffermem` 回收与页缓存分离设计争论 |
| 2004 | 2.6 | **SLUB**（Christoph Lameter）取代 SLAB 成为分配器默认；**cgroup（v1）** 引入内存限组 |
| 2007 | 2.6.16 | **SLOB**（Matt Mackall）作为小系统选项；cgroup 内存子系统的雏形 |
| 2010–2014 | 2.6.32–3.14 | **内存 cgroup v1 成熟**；**zswap**（Seth Jennings, 2013）与 **zRAM**（Nitin Gupta）进入主线；**透明大页 THP** 默认开启 |
| 2016 | 4.8 | **`memdefer`/memcg 分层回收**；BFQ/THP 相关工程改进；`khugepaged` 改进 |
| 2019–2022 | 5.x | **zswap 默认启用**（2020 左右）；folio 化启动，**MGLRU** 由 Yu Zhao 提交（2020 起，6.1 合并） |
| 2023 | 6.1 | **MGLRU 进入主线**；folio 成为页缓存默认单元 |
| 2024–2026 | 6.x | folio 化推进到 `read_folio`；`mlock` 与 MGLRU 的交互、`idle page tracking` 等持续打磨；`shrinker` 框架改进（`shrinker->free_batch`） |

## 近年研究与工业界开源实践（2015–2026）

- **近年研究**：集中在 **页缓存与匿名页的统一回收**、**压缩内存（zswap/zRAM/交换压缩）**、**大页（THP 与 huge folio）**、**cgroup 分层回收与 memcg v2 的 page counter 设计**、**非易失内存（PMEM）的 DAX 与 libnvdimm**，以及 **AI 负载下的巨量匿名页回收**（MGLRU 的主要驱动力之一就是内存数据库与 Spark 类负载）。
- **工业界开源**（star 数 2026-09 实测）：
  - `torvalds/linux`（≈**250k★**）：页缓存/回收在 `mm/`（`mm/vmscan.c`、`mm/filemap.c`、`mm/truncate.c`）；SLUB 在 `mm/slub.c`；`Documentation/admin-guide/mm/` 是必读文档。
  - `jemalloc/jemalloc`（≈**11.2k★**）：用户态分配器的代表，其 `cached bin` / `tcache` 设计正好对照 0.11 缺失的「per-CPU 分配缓存」。
  - `openzfs/zfs`（≈**12.5k★**）：ARC 缓存与 ZIL，展示了「自适应替换缓存（ARC）」如何解决 LRU 的扫描污染问题。
  - `buildroot/buildroot`（≈**3.7k★**）：构建带 zRAM/compressed modules 的最小 rootfs，适合复现内存压力实验。
  - `iovisor/bcc`（≈**22.7k★**）：`memleak`、`mmpagesize` 等 eBPF 工具，用来观察 0.11 之外现代系统的页级行为。

## 常见误区与本书需修正之处

| # | 误区 / 本书局限 | 2026 年的修正与补充 |
| --- | --- | --- |
| 1 | 「内存分配就是从 `mem_map` 找一个空页」 | 缺了 per-cpu 缓存、伙伴分裂合并、SLUB/SLOB 的对象分配器三层；现代一次 `kmalloc` 多数走 SLUB 的 per-cpu 数组 |
| 2 | 「缺页就是 P 位为 0」 | 🔧 现代有 P（存在）、**npages**、swapped、MMIOTRAP、**WP** 等多种 fault reason，走 `handle_mm_fault()` 的多级分发 |
| 3 | 「COW 由硬件自动完成」 | 🔧 x86 PTE 没有 COW 位；现代靠 `write-protect` + `FAULT_FLAG_WRITE` 的**一次特例化**（`wp_page_copy`），随后写操作不再 trap，与 0.11 的逻辑相似但代码路径成熟得多 |
| 4 | 「交换就是匿名页专属」 | 🔧 页缓存脏页也可以被回收（等价于换出），现代回收路径统一处理 anon/file |
| 5 | 「swap 只能换到磁盘」 | 🔧 zswap（压缩内存后落盘）、**zRAM**（纯内存压缩设备）可完全不用磁盘做 swap |
| 6 | 「大页对应用没必要」 | 🔧 THP/huge folio 通过减少 TLB miss 显著提升内存密集应用性能，但也可能增加回收碎片 |
| 7 | 「内存管理只是内核内部细节」 | 🔧 有 **memory cgroup v2**（`memory.max`/`memory.high`）、**PSI（pressure stall information）**、`memory.charge` 与 **userfaultfd**，已是可观测的运维接口 |
| 8 | 「页缓存回收用 LRU 就够」 | 🔧 经典 LRU 的扫描污染问题由 **MGLRU（6.1 合并）、ARC（ZFS）或 2Q** 等应对 |
