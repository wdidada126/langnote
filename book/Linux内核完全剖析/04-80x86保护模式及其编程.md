### 4.1/4.2 进入保护模式的最小步骤

```asm
; 教学示意，不代表可编译运行（与 06 章 head.s 同构）
    lgdt    gdt_48          ; 1. 装载 GDTR（6 字节：限长16 + 基址32）
    lidt    idt_48          ; 2. 装载 IDTR
    mov     eax, cr0
    or      eax, 0x1        ; 3. CR0.PE = 1，切换到保护模式（同一条指令）
    mov     cr0, eax
    jmp     8:0             ; 4. 长跳刷新 CS 流水线（段缓存必须重灌）
```

> **最容易漏掉的第 4 步**：`CR0.PE=1` 后 CPU 仍在执行 16 位代码流，必须有一条跨段跳转让 CS 的高速缓冲段描述符失效。

### 4.3 段选择符与段描述符

```text
; 教学示意：16 位段选择符
;   +---------------+--------+------+
;   |  Index (13b)  | TI(1b) | RPL  |
;   +---------------+--------+------+
;    TI=0  → GDT ;  TI=1  → LDT

; 教学示意：8 字节段描述符（后 32 位）
;   31..24 base | flags/P/DPL/S/type | 19..16 limit | 15..8 base | 7..0 base | limit 15..0

; 教学示意：把描述符地址 → GDTR（伪代码）
;   gdt_48: .word 0x8000    ; limit = 8*256-1 = 32767
;           .long gdt_0     ; base  = &gdt_0
```

| 51–56 | 类型字段要点（最常见值） |
| --- | --- |
| `0x08` | 未使用/保留 |
| `0x09`/`0x0B` | 只读 / 只读已访问（代码段） |
| `0x0A` | 可执行非可读 |
| `0x0F` | 可执行可读可非一致可写 |
| `0x92` | 可读写数据段（0.11 的 DS） |
| `0x9A` | 可执行可读代码段（0.11 的 CS，DPL=0） |
| `0x8A` | 调用门 |
| `0x86` | 中断门 |
| `0x87` | 陷阱门 |

> **必记结论**：Linux 只用 **4 个段**（内核代码/数据 0x08，用户代码/数据 0x0F 附近），且它们**基址为 0、限长为 4 GB**，即「平坦模型（flat model）」。分段在 Linux 里几乎无作用，剩下的只有「分段为分页提供权限与边界的硬件检查点」。

### 4.3.6 门与 `int 0x80`

```text
; 教学示意：中断门/陷阱门（64 位代码段时 16 字节，32 位时为 8 字节）
;   偏移 31..16 | 段选择子 | 属性(DPL/P/type) | 偏移 15..0

; 0.11 的 IDT 设置（sched_init / trap_init 做的事，07 章实现）：
;   set_trap_gate(0x00, &divide_error)   ; 除零
;   set_system_gate(0x80, &system_call)  ; int 0x80 → 系统调用
```

> 中断门 (`type=0x86`) 在入/出时会**自动清/置 EFLAGS.IF**（即关中断），陷阱门 (`type=0x87`) 不会。这就是「系统调用用陷阱门，断点异常用陷阱门」的原因。

### 4.4 分页：两级页表

```text
; 教学示意，不代表可编译运行：x86 32 位两级分页（4 KB 页）
;   CR3 → 页目录（4 KB，1024 项）
;   页目录项 P=1 且 PS=0  → 指向一个页表（4 KB，1024 项）
;   页表项 P=1 且 R/W=1  → 指向一个 4 KB 物理页帧
;   线性地址 = [31..22] 页目录索引 | [21..12] 页表索引 | [11..0] 页内偏移

; 页目录/页表项（32 位）：
;   bit0 P    存在
;   bit1 R/W  可写（0.11 的写时复制靠它清零）
;   bit2 U/S  用户可访问
;   bit3 PWT  cache 写透
;   bit4 PCD  cache 禁止
;   bit11/12 自映射、AVL 位
;   bit31..12 = 物理地址>>12
```

```c
/* 教学示意，不代表可编译运行：0.11 风格的分页填充（setup_paging）核心片段 */
static void setup_paging(void)
{
    /* 前 4 MB 直接一一映射：页目录第 0 项 → 第 0 个页表 → 低 4 MB */
    *((unsigned *) &tmp_page[0]) = 0;            /* 页表项先清零 */
    ...
    fill 0..4MB: entry = (i << 12) | 7;         /* P|R/W|U/S */
    ...
    cr3 = page_directory;                         /* 写 CR3 触发 TLB 失效 */
}
```

> **两个必记结论**：
> 1. 页表项 `R/W` 位为 0 时，写操作触发 `#PF`，错误码 `bit1(W/R)=1`；Linux 的 `copy_page_tables()` 正是把父子进程的页表项**设为只读**来实现写时复制。
> 2. TLB 不通过「刷新页表」自动更新，必须 `invlpg`（单页）或重装 CR3（全清）——0.11 的 `free_page_tables()` 里就有 `invlpg` 循环。

### 4.5 特权级检查的三条线

| 场景 | 检查内容 | 违规结果 |
| --- | --- | --- |
| 访问数据段 | `max(CPL, RPL) <= DPL`，且 `TYPE` 的 W 位 | `#GP(0)` |
|  jumps/calls 到代码段 | 一致码段允许同特权跳转；非一致需 **调用门** | `#GP` |
| 访问页 | `U/S`（CPL=3 需 U/S=1）与 `R/W` | `#PF` 且错误码 `bit0(U/S)`/`bit1(W/R)` |

```text
; 教学示意：#PF 错误码（CR2 保存出错的线性地址）
;   bit0 = 0 用户态 / 1 内核态
;   bit1 = 0 读 / 1 写
;   bit2 = 0 取指 / 1 其他
; 缺页异常原型：error_code 由 CPU 压栈，do_page_fault(page_table, error_code, addr)
```

## 版本演进

| 年份 | 变化 |
| --- | --- |
| 1986 | 80386 引入保护模式、分段 + 分页 |
| 1992 | Linux 0.12 目标：386，两级分页，4 GB 线性空间 |
| 2003–2005 | 🔧 **PAE**（`CR4.PAE`）让物理地址到 36 位+；2.6 起默认启用 |
| 2007+ | 🔧 x86_64 引入**四级分页 + 4 MB/2 MB 大页 + 长模式**（`EFER.LME`） |
| 2012+ | 🔧 **`fxsave`/`xsave`/`XSAVE` 状态管理**取代旧的任务切换段保存；`xgetbv` |
| 2016+ | 🔧 **KAISER / KPTI 页表隔离**（Meltdown 缓解，用户/内核页表分离）与 5 级分页支持 |
| 2020 | 🔧 **5 级页表**在 x86_64 主线可用；`LA57` |
| 2023+ | 🔧 影子栈/IBT（CET）影响返回地址与段选择子兼容性 |

## 近年研究与工业界开源实践（2015–2026）

- **内核侧的真实分页代码**：`torvalds/linux` 的 `arch/x86/mm/`（`pgtable.c`、`fault.c`、`page_64.c`），`mm/memory.c` 里的 `handle_mm_fault()` 是 `do_page_fault` 的正式后继。

- **形式化内存模型正在进内核**：`x86-TSO`（CACM 2010）与 Maurice 的 2020 修正，配合 herd7 / cppmem 等工具，被用来验证 C11 与 Linux 内核的内存序假设；内核里 `barrier()`、`smp_rmb()` 的实现方式也随这些研究被反复审视。
- **真实仓储 star 实测（2026-09-25）**：`torvalds/linux` **250112★**、`qemu/qemu` **13761★**（QEMU 的 `target/i386/tcg/sysemu/excp_helper.c` 就是保护模式的软件实现，读它比读文字快）。

## 常见误区与本书需修正之处

| # | 说法/写法 | 修正与补充 |
| --- | --- | --- |
| 1 | **「讲保护模式那节太罗嗦，还是看《Intel 开发人员手册》」**（原书页面第一条评语） | 同意。本章建议**以 SDM Vol.3A §3–§6 为主**，本书当索引；仓库内已有 `book/Intel开发人员手册.md` |
| 2 | 「分段和分页都很重要，都要认真学」 | Linux **只用平坦分段**（`__KERNEL_CS=0x08`、`__USER_CS=0x0F`，基址 0、限长 4 GB），分段等于形式；重点应放在**分页** |
| 3 | 「CR0.PE=1 之后就是 32 位了」 | 还要 `CS.E/L`、GDT 已装载、以及一条跨段跳转刷流水线 |
| 4 | 「GDT 越大越好」 | 🔧 真实内核的 GDT 有固定表项 + `percpu` 段 + 安全间隙（`TLS` 段、`vsyscall`/`geode` 保留位），不是随意放 |
| 5 | 「分页只有两级」 | 🔧 x86_64 是**四级（最多五级）**；PAE 让物理地址超 32 位；`5-level paging` 在 5.x 主线 |
| 6 | 「TLB 会自动同步」 | 必须 `invlpg` 或重装 CR3；这也是 `copy_page_tables` / `free_page_tables` 里那些循环的意义 |
| 7 | 🔧 「4 KB 页够用」 | 现代系统普遍开 **透明巨页（THP）** 与 `hugetlb`；内核用 `pmd` 级别映射 |
| 8 | 🔧 「保护好就万事大吉」 | 现代威胁面（KASLR/CET/页表隔离/SMAP/SMEP）才是关键；本书成书 2006，完全没有这些 |
| 9 | 🔧 「x86 就是全部」 | 内核主体与 `arch/` 分离后，arm64/riscv 才是移动与未来的大头；学习时可用 `mit-pdos/xv6-riscv`（**10516★**）对照 |
