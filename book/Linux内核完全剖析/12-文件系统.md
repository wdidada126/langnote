# 第 12 章 文件系统

> **本章地图**：缓冲区层 `buffer.c`（`buffer_head`、哈希队列、块读写）→ 位图与块分配 `bitmap.c` → 超级块 `super.c`（`mount_root`、`get_super`、`sv_rename` 等）→ 路径解析 `namei.c`（`namei`、`find_entry`、`add_entry`）→ 索引节点 `inode.c`（`iget`、`bmap`、`map_dirty`）→ 文件内容读写 `file_dev.c`（`file_read`/`file_write`）→ ext2 的 in-core 与磁盘 inodes 转换 `ext2.c`。核心结论：0.11 的文件系统把「**盘上数据结构**」和「**内存侧缓存**」压在同一个 `struct m_inode` 里，靠 14 字节固定文件名与 13 项块指针换来极简实现——这正是 ext2 与我今天所有现代文件系统差距的原点。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 12.1 `buffer.c` | `struct buffer_head`、b_hash 哈希、`bread/breada/bwrite`、`block_read/block_write` | 缓冲缓存是**块层唯一入口**，哈希以 (dev,blocknr) 为键 |
| 12.2 `bitmap.c` | `new_block`/`free_block`/`new_inode`/`free_inode`、块组 | 只有**一层间接**的位图分配，无 extent、无多块预分配 |
| 12.3 `super.c` | `struct super_block`、`mount_root()`、`get_super`、`put_super`、`s_isup` | 只能挂 8 个（`NR_SUPER`），root 在启动时硬性 mount |
| 12.4 `namei.c` | `namei()` 路径解析、`find_entry`、`add_entry`、`get_dir` | 路径解析用 `struct inode`，「目录项」不单独缓存 |
| 12.5 `inode.c` | `struct m_inode`、`iget/igrab/iput`、`bmap()`、`map_dirty()` | `i_zone[13]` = 7 直接 + 1 间接 + 1 双重间接 + 1 三重间接 |
| 12.6 `file_dev.c` | `file_read`/`file_write`、`MINIX/`EXT2` 分支 | 读写直接走 `bread`→块层，无 page cache、无 mmap 路径 |
| 12.7 `file_table.c`/`fcntl.c` | `struct file`、`get_empty_filp`、`open_namei`、`do_open` | 文件描述符表是静态数组，最多 `NR_OPEN=20` |
| 12.8 `ext2.c` | `ext2_read_inode`/`ext2_write_inode`、`ext2_statfs` | 负责 in-core inode ↔ 磁盘 inode（含 `i_zone` 转换） |
| 12.9 目录项固定 14 字节 | `struct dir_entry { char name[NAME_LEN]; int inode; }` | 🔧 这是 ext2/3 时代的核心限制，ext4 才改成可变长 |
| 12.10 缺失的现代层次 | 无 VFS 的 `dentry` 缓存、无 page cache、无 mmap 文件系统接口 | 🔧 现代文件系统是「inode_operations + file_operations + address_space_operations + dentry」四件套 |

## 核心精讲

> 以下均为**教学示意，不代表可编译运行**。

### 12.1 缓冲缓存：`struct buffer_head`

```c
/* include/linux/fs.h（0.11）—— 教学示意，不代表可编译运行 */
struct buffer_head {
    struct buffer_head *b_next;   /* 哈希冲突链 */
    unsigned long b_rsector;      /* 设备上的扇区号 */
    unsigned short b_dev;         /* 设备号 */
    unsigned char b_count;        /* 引用计数 */
    unsigned char b_dirt;         /* 脏 */
    unsigned char b_lock;         /* 被锁定（I/O 进行中） */
    unsigned char b_uptodate;     /* 数据已是最新 */
    unsigned char b_flushe;       /* 需要被刷新 */
    unsigned char b_repeat;       /* 读改写：缓存后释放 */
    unsigned char b_async;        /* 写回时异步 */
    unsigned long b_blocknr;      /* 逻辑块号 */
    char *b_data;                 /* 指向数据区（块内偏移 512 字节） */
    struct buffer_head *b_prev;
    struct buffer_head *b_next_free;   /* LRU/空闲链 */
};
```

- 缓冲区是 **512 字节 = 一个扇区 = 一个块**，`bread(dev, blocknr)` 找不到就分配一个 buffer、下发给块层、睡眠等待 `b_uptodate`。
- 🔧 现代 Linux 已经**把这块「缓冲缓存」整体换掉**：page cache 以**页（4KB）**为单位，通过 `struct address_space` + `radix_tree/xarray` 索引，还有 `folio` 概念（6.x 起全面 folio 化）；`buffer_head` 只在 `buffer_mapped()` 那类少数路径上残留。
- 也就是说，本章所有的 `bread()` 调用点，在 2026 年的内核里大多是 `->readpage()` / `filemap_read()`。

### 12.2 内存侧 inode：`struct m_inode`

```c
/* include/linux/fs.h（0.11）—— 教学示意，不代表可编译运行 */
struct m_inode {
    unsigned short i_mode;        /* 文件类型和权限 */
    unsigned short i_nlink;       /* 硬链接数 */
    unsigned short i_uid;
    unsigned short i_gid;
    unsigned short i_size;
    unsigned short i_mtime;
    unsigned short i_zone[9];     /* 前面 7 项是 0.11 实际用的 */
    /* 0.11 里 i_zone 实际是 13 项；
       7 直接 + 1 间接 + 1 双重间接 + 1 三重间接 */
    struct m_inode *i_next, *i_prev;   /* inode 哈希表链 */
    struct inode_operations *i_op;
    ...
    unsigned short i_count;       /* 引用计数 */
    unsigned char i_nlink_;       /* 链接计数 */
    unsigned char i_dev;
    unsigned char i_flags;
    unsigned char i_lock;
    unsigned char i_dirt;
    unsigned char i_pipe;         /* 0 = 非管道 */
    ...
};
```

- `i_count` 与 `i_nlink` 是两个不同的东西：`i_count` 是内核引用（打开/挂载/目录项），归零即丢弃；`i_nlink` 是磁盘链接数（盘上元数据），归零则该文件应被删除。
- `i_zone[13]` 的间接块模型，最终在ext2/3 里完全保留，**ext4 才用 extents 取代**（一组成员连续的物理块）。

### 12.3 块指针与 `bmap()`

```c
/* fs/inode.c —— 教学示意，不代表可编译运行 */
static inline int bmap(struct m_inode *inode, unsigned block)
{
    if (block < 7)                     /* 直接块 */
        return inode->i_zone[block];
    if (block < 512 + 7) {             /* 一次间接 */
        int i = block - 7;
        ...
        bh = bread(inode->i_dev, inode->i_zone[7]);
        ...
        return ((unsigned *) bh->b_data)[i];   /* 从中间块取出物理块号 */
    }
    ...
}
```

- 一个 512 字节的「间接块」里放的是物理块号，最多可以映射到 **512 × 512 × …** 个块；0.11 用 1KB 块时_MAX 约 2GB。
- 因为块是 512 字节而文件系统块可以是 1KB/2KB/4KB，所以 `bmap` 与上层对「块」的计数需要换算（`i_zone[0]` 存的是**文件系统的块号**而非扇区号）。

### 12.4 路径解析：`namei()` 与目录项

```c
/* fs/namei.c —— 教学示意，不代表可编译运行 */
struct m_inode *namei(const char *pathname)
{
    const char *basename;
    struct m_inode *dir;
    ...
    if ((dir = get_dir(pathname)) != NULL)
        return dir;
    ...
    /* 逐级 get_dir：每个 '/' 分隔一段，用 find_entry 找 inode 号 */
}

static struct buffer_head *find_entry(struct m_inode *dir, ...)
{
    /* 在目录文件里线性遍历：每块按 dir_entry 逐个比对名字 */
}
```

- 目录在 0.11 里是**普通文件**：目录项是一个个 `dir_entry`，文件名区固定 `NAME_LEN=14` 字节，`\0` 结尾，最多 14 个可见字符（第 15 字节是长度元数据的空间）。
- 因此：**最长文件名 14 字符**，这是所有Linux老教程里最常被引用的限制。
- 目录检索是**线性扫描**，目录一大就 O(n)；ext2 用**哈希树目录（htree）**在 2.6 补齐，ext4 直接支持可变长名字 + htree。

### 12.5 目录项的物理布局

```c
/* include/linux/fs.h（0.11）—— 教学示意，不代表可编译运行 */
struct dir_entry {
    char name[NAME_LEN];   /* 14 字节固定 */
    int inode;             /* 0 = 空项 */
};
```

- 「固定长度目录项」是 0.11/ext2 的设计选择：**读取可以完全顺序化、无需解析长度字段**，代价是名字短、目录项浪费（一个 512 字节块能存 17 个目录项）。
- 🔧 ext4 的 `struct ext4_dir_entry_2` 有 `name_len` 与 `rec_len`，支持**可回收的哈希树目录与可变长文件名**；XFS/btrfs 更进一步用 B+ 树/B-树索引目录。

### 12.6 文件内容读写：`file_read/file_write`

```c
/* fs/file_dev.c —— 教学示意，不代表可编译运行 */
int file_read(struct m_inode *inode, char *buffer, int count, off_t *ppos)
{
    int bh_size = BLOCK_SIZE;                  /* 1024 */
    ...
    while (count) {
        block = bmap(inode, *ppos / bh_size);  /* 文件偏移 → 物理块 */
        bh = bread(inode->i_dev, block);
        ...
        copy_to_user(buffer, bh->b_data + pos_in_block, chars);
        ...
        read_more: if (block == 0)  /* 前导空洞，用全零缓冲 */
    }
}
```

- 读写路径极短：**偏移 → bmap → bread → 用户拷贝**，没有页缓存、没有预读、没有写回线程、没有 `mmap` 映射。
- 🔧 现代路径是 `filemap_read()`：`page cache` 查找/建立 → 调用 `->readpage`（或 `->map_blocks` 提交 bio）→ `copy_to_user`；写路径还要考虑 `dirty` 标记、`writeback` 节流、`fallocate`、O_DIRECT 的对齐要求等。

### 12.7 文件打开：`open_namei` 与 `do_open`

```c
/* fs/open.c —— 教学示意，不代表可编译运行 */
int do_open(const char *filename, int flags, ...)
{
    struct m_inode *inode = namei(filename);
    ...
    for (i = 0; i < NR_OPEN; i++)          /* 静态 fd 数组 */
        if (!curr->files->fd[i])
            break;
    ...
    fd = i;
    file = get_empty_filp();               /* 静态 file 数组 */
    file->f_inode = inode;
    file->f_pos = 0;
    ...
    inode->i_count++;
    if (S_ISREG(inode->i_mode) && !(file->f_flags & O_TRUNC))
        file->f_pos = inode->i_size;       /* 注意：进程 0 的特例在此处 */
}
```

- `NR_OPEN = 20`（0.11 默认），`NR_FILE = 64`——这些静态上限是当年「小内核」的直接体现。
- 🔧 现代内核没有 `NR_OPEN` 硬上限（受 `RLIMIT_NOFILE` 限制），`struct file` 动态分配；并且有 `get_unused_fd_flags`、`fdget` 与 `rcu` 保护的 fdtable（ historic `files_struct` 分配）。

### 12.8 文件操作函数表：VFS 的种子

```c
/* include/linux/fs.h（0.11）—— 教学示意，不代表可编译运行 */
struct file_operations {
    int (*lseek)(struct inode *, struct file *, off_t, int);
    int (*read)(struct inode *, struct file *, char *, int);
    int (*write)(struct inode *, struct file *, char *, int);
    int (*readdir)(struct inode *, struct file *, struct dirent *, unsigned int);
    int (*select)(struct inode *, struct file *, int, select_table *);
    int (*ioctl)(struct inode *, struct file *, unsigned int, unsigned long);
    int (*open)(struct inode *, struct file *);
    int (*release)(struct inode *, struct file *);
    int (*fsync)(struct inode *, struct file *);
    int (*fstat)(struct inode *, struct file *, struct stat *);
    int (*check_media_change)(dev_t dev);
    int (*revalidate)(dev_t dev);
    int (*lock)(struct file *, int, struct file_lock *);
};
```

- 这个表格已经是 **VFS 的雏形**：`struct m_inode.i_op` 指向 `inode_operations`，`struct file.f_op` 指向 `file_operations`，`struct m_inode.i_op->default_file_ops` 也在 0.11 里被用起来。
- 🔧 但 0.11 缺了三样决定性的东西：**`struct dentry`（目录项缓存）**、**`struct address_space_operations`（页缓存与 mmap）**、**`struct super_operations` 的 `alloc_inode`/`destroy_inode`**。现代文件系统的完整接口是 `inode_operations + file_operations + address_space_operations + dentry_operations + super_operations + xattr + project_quota`。

## 版本演进

| 时间 | 内核/项目 | 事件 |
| --- | --- | --- |
| 1991–1994 | Linux 0.11 | minix 1.0 语义 + ext2：`dir_entry` 14 字节名、`NAME_LEN`、`i_zone[13]`、`NR_SUPER=8`、`NR_OPEN=20`、`NR_FILE=64` |
| 1994–1996 | 2.0 | ext2 走向成熟；VFS 抽象成形（`dentry` 在 2.x 才出现） |
| 2000 | 2.4 | ext3（日志化，2001 起）把 ext2 变成可在线升级的有日志版本 |
| 2006 | 2.6.19 | **ext4** 首次进入主线（当时仍叫 ext4dev）；extents、多块分配、延迟分配、htree 目录 |
| 2008 | 2.6.28 | **overlayfs** 首次进入主线（实验性）；**FUSE** 早已可用 |
| 2008 | 2.6.28 | ext4 稳定化（2008-12）；btrfs（2007 起开发）逐步成型 |
| 2014 | 3.12 | **btrfs** 稳定；XFS 支持 64 位与多 MD 镜像 |
| 2019–2023 | 5.x | `statx` 成熟；**io_uring 支持更多文件操作**（open/statx/fadvise/sync）；`fsmount/fspick/fsopen`（5.2/6.6） |
| 2020–2026 | 5.x/6.x | 文件系统**全面 folio 化**（`->readpage` → `read_folio`、MGLRU 感知）；`fsverity`、`erofs`、`f2fs` 各自成熟；`statmount/mountapi` 取代老的 `statfs` 路径 |

## 近年研究与工业界开源实践（2015–2026）

- **近年研究**：文件系统研究集中在 **flock/fcnl 扩展性**、**可观测性（`statx`、`statmount/mountapi`）**、**压缩与去重（btrfs/zstd、erofs、`fscrypt`）**、**持久内存（PMEM/NVM 的 DAX 路径）**、**写放大与 SSD 友好（延迟分配、discard、zone-aware 分配）**，以及 **AI 负载下的小文件与元数据性能**。
- **工业界开源**（star 数 2026-09 实测）：
  - `torvalds/linux`（≈**250k★**）：ext4 在 `fs/ext4/`，页缓存与文件映射在 `mm/filemap.c`，VFS 在 `fs/namei.c`、`fs/libfs.c`；`statx`/`io_uring` 相关接口在 `include/uapi/linux/stat.h` 与 `io_uring`。
  - `tytso/e2fsprogs`（≈**478★**）：e2fsck/tune2fs 的用户态配套，读 `lib/ext2fs/` 能反向印证本章讲的那套盘上结构。
  - `openzfs/zfs`（≈**12.5k★**）：完整实现了本章概念的现代版本——**COW、块指针（MPL/DVA）、zil 日志、可变长目录**，把 `i_zone[13]` 的思路推到极致。
  - `libfuse/libfuse`（≈**6.1k★**）：用户态文件系统框架，`giov` 与 `fuse` 让「文件系统不需要在内核里」成为现实；对本章是最好的对照实验。
  - `axboe/liburing`（≈**3.8k★**）：2023 年起大量存储/数据库应用改用 io_uring + O_DIRECT 绕开页缓存，正好对应本章「没有页缓存」的 0.11 路径的性能回归。

## 常见误区与本书需修正之处

| # | 误区 / 本书局限 | 2026 年的修正与补充 |
| --- | --- | --- |
| 1 | 「文件名最长 14 字符」是 Linux 的限制 | 只是 0.11/ext2 的 `NAME_LEN`；现代 ext4/XFS 最长 255 字节（ext4 可变长），btrfs 也无长度限制 |
| 2 | 「目录项 = 一个带名字的结构体」 | 🔧 现代有独立的 **`struct dentry` 缓存层**，与磁盘结构解耦（本章完全没有这一层） |
| 3 | 读写走 `bread` 就等于「页缓存」 | 🔧 0.11 只有**扇区/块级缓冲缓存**，没有以页为单位、没有 `address_space`、没有 mmap 映射 |
| 4 | 「文件描述符是静态数组下标」 | 🔧 `NR_OPEN=20` / `NR_FILE=64` 早已取消，由 `RLIMIT_NOFILE` 与动态 `struct file` 接管 |
| 5 | 「文件系统只需要在内核里实现」 | 🔧 **FUSE/libfuse** 让你在用户态写文件系统；overlayfs 更是专门为「内核里叠一层」设计的 |
| 6 | 「大小写敏感、14 字节名、目录数 ≤ 32000」是 ext2 的锅 | 🔧 ext2 本身可配；ext3 支持 32000 子目录上限（ext4 取消），这些限制多源于 0.11 的简化实现而非 ext2 规范 |
| 7 | 「读文件就是 read()」 | 🔧 `mmap` 文件映射（缺页映射 page cache）、**`io_uring`** 的批量提交、`statx` 获取纳秒时间戳与 `STATX_*` 扩展属性、O_DIRECT 的对齐约束，都是今天必须理解的部分 |
| 8 | 「一次 read 就一次块 I/O」 | 现代内核有**读预读（readahead）**、fadvise/madvise 提示、writeback 后台回写，与 0.11 的 `breada` 思想相同但机制复杂得多 |
