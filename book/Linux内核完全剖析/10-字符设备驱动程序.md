# 第 10 章 字符设备驱动程序

> **本章地图**：字符设备注册与通用读写 `char_dev.c`（`chr_tbl[]` + `rw_chr`）→ TTY 核心 `tty_io.c`（读写缓冲、节流、规范模式）→ 上下层接口 `ll_rw_tty.c` → 具体驱动：`console.c`（VGA 文本控制台）、`rs.c`（16550 串口）、`KEYB.S`（键盘扫描码汇编）。核心结论：0.11 的字符设备框架是「**静态表 + 函数指针 + 轮询**」的组合，TTY 既承担终端语义又承担「慢设备的读写缓冲」职责，两者被硬塞进同一个 `struct tty_struct`。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 10.1 `char_dev.c` | `chr_tbl[]`、`chr_dev_init()`、`rw_chr()` | 字符设备靠**数组下标 = 设备号**索引，最多 128 个 |
| 10.2 `tty_io.c` 的 `struct tty_struct` | `read_q`/`write_q` 环形缓冲、`throttle`、`reading`/`writing` 等待任务 | TTY 是一个**内核内的生产者-消费者队列**，不只是硬件抽象 |
| 10.3 读写路径 | `tty_read()` / `tty_write()`：唤醒等待者、规范模式转换、`copy_to_cooked` | 规范模式（canonical）把行编辑放在内核里，是后世 n_tty 的直接祖先 |
| 10.4 `ll_rw_tty.c` | `tty_write` 函数指针 → `console_write` / `rs_write` | 上下层解耦点只有**两个函数指针**，vFS 还没进入内核 |
| 10.5 `console.c` | VGA 文本模式：`con_write`、`scr_out`、`crt_*` 端口 | 控制台是**直接写_video 显存**的，与显卡驱动没有层次关系 🔧 |
| 10.6 `rs.c` | 8250/16550 串口：`rs_init`、`rs_write`、`rs_interrupt` | 轮询 + 简单中断，无 FIFO 深度控制、无 RTS/CTS 自动流控 |
| 10.7 `KEYB.S` | 8042/8255 PPI 扫描码读取、按键状态机 | 纯汇编键盘驱动，直接把扫描码塞进环形缓冲 |
| 10.8 字符设备的 `select` / `poll` | `ttyl_ok` 在字符设备上的实现 | 早期 `select` 的语义细节，在 TTY 上有一整套特判 |
| 10.9 缺失的现代层次 | 没有 input 子系统、没有 DRM、没有 evdev/uinput | 🔧 0.11 的字符设备抽象无法表达现代输入/显示设备 |

## 核心精讲

> 以下均为**教学示意，不代表可编译运行**；现代内核的 `struct tty_struct` 同名而不同形。

### 10.1 字符设备表：`chr_tbl[]`

```c
/* drivers/char/char_dev.c —— 教学示意，不代表可编译运行 */
static struct file_operations *chr_tbl[] = {
    &tty_fops,      /* 0 = tty   : 终端 */
    &console_fops,  /* 1 = console */
    &rs_fops,       /* 4 = ttyS0 */
    &rs_fops,       /* 5 = ttyS1 */
    &con_fops,      /* 21 = 控制台特殊文件 */
    &keyboard_fops, /* 22 = 键盘 */
    &mouse_fops,    /* 13 = 鼠标 */
    ...
};

int rw_chr(int minor, unsigned char *buf, int count, int write)
{
    static int last_call = 0;   /* 用来打破死锁的粗糙启发式 */
    ...
    if (chr_tbl[minor])
        return chr_tbl[minor]->read/write(...);
    return -ENODEV;
}
```

- 字符设备号在 0.11 是**编译期固定**的：`MAJOR(device_number)` 直接当下标，真正的文件操作结构体（`struct file_operations`）要到 0.12/1.0 才成为统一抽象。
- `last_call` 那类「上次调用主体」的启发式，是当年为了防止 **TTY 写阻塞 → 调度器死锁** 的土办法，读来令人唏嘘。

### 10.2 TTY 核心：`struct tty_struct`

```c
/* include/linux/tty.h（0.11）—— 教学示意，不代表可编译运行 */
struct tty_struct {
    struct termios termios;           /* 行规程设置（部分字段在 0.11 未实现） */
    struct task_struct *reading;      /* 等待读取的进程 */
    struct task_struct *writing;      /* 等待写入的进程 */
    unsigned long can;                /* 规范模式下可读字符数 */
    unsigned long throttle;           /* 上游被节流 */
    ...
    void (*write)(struct tty_struct *tty);          /* 底层写函数 */
    void (*put_char)(struct tty_struct *tty, char c);
    void (*flush_char)(struct tty_struct *tty);
    ...
    unsigned char read_q[TTY_BUFFER_SIZE];  /* 规范模式输入队列 */
    unsigned char write_q[TTY_BUFFER_SIZE]; /* 写入队列 */
    unsigned char secondary;                       /* 备用（用于 Cut/SIG 字符） */
    ...
};
```

三个要点：

1. `reading`/`writing` 是**单进程**等待者（不是 waitqueue），意味着一个 tty 同时只能有一个读者/写者被阻塞——这是后来 `wait_queue_head_t` 全面替换的动力。
2. `read_q` 的「规范模式」（canonical / cooked）把行编辑（退格、行删除、`^D`、信号字符）放在内核，用户在 `read()` 里读到的永远是「一行」。
3. `throttle` 与 `secondary` 是流式设备的流控遗迹，现代内核里被 `n_tty` 的 `icanon`/`opost` 与 tty 层的 `ldata->read_tail` 取代。

### 10.3 读写路径（`tty_io.c`）

```c
/* drivers/char/tty_io.c —— 教学示意，不代表可编译运行 */
int tty_write(struct tty_struct *tty, const unsigned char *buf, int nr)
{
    ...
    add_wait_queue(&tty->write_wait, &wait);     /* 现代版本 */
    while (nr > 0) {
        if (tty->write_q[head] 满) {             /* 队列满 → 阻塞 */
            schedule();
            continue;
        }
        c = get_user_char(buf);                  /* 从用户空间取一个字符 */
        if (tty->stopped || tty->throttle)
            ...
        else
            tty_insert_flip_string(...);          /* 塞进 write_q */
        buffer = ...;
    }
    wake_up(&tty->write_wait);
    return written;
}
```

- `tty_read` 侧则相反：先检查 `can`（可读数），不够就 `schedule()` 睡进去，被 `isig`/`wake_up_interruptible` 唤醒后 `copy_from_read_q` 取走。
- 🔧 今天的内核：`struct tty_struct` 在 `include/linux/tty.h`，行规程被拆成 **`n_tty`**（`drivers/tty/n_pty.c`/`n_tty.c`）与 **pty 对端**；`wait_queue_head_t`、按 cpu 分片的 flip 缓冲（`tty_insert_flip_string_flags` → `flip_push`）取代了单缓冲环。

### 10.4 上下层解耦：`ll_rw_tty.c`

```c
/* drivers/char/ll_rw_tty.c —— 教学示意，不代表可编译运行 */
void tty_write(struct tty_struct *tty)     /* 由 tty_struct.write 调用 */
{
    if (tty->write_chars ...)
        ...
}
int tty_read(...)  ...
/* console 侧 */
void con_write(struct tty_struct *tty) { ... 直接写显存 ... }
int rs_write(struct tty_struct *tty)   { ... 逐字符写 0x3f8 ... }
```

只有两个函数指针（`write` / 相关辅助），却要同时支撑控制台、两个串口、伪终端——这是 0.11 能压缩编译体积的代价。

### 10.5 VGA 控制台（`console.c`）

```c
/* drivers/char/console.c —— 教学示意，不代表可编译运行 */
static void scr_out(unsigned char c, unsigned char attr)
{
    unsigned short *read_pos = (unsigned short *) video_mem_start;
    ...
    read_pos[offset] = c | (attr << 8);   /* 直接写 VGA 文本显存 */
    ...
}
void con_write(struct tty_struct *tty) { /* 从 write_q 取出字符逐个 scr_out */ }
```

- 0.11 的控制台是 **BIOS 文本模式**的延续：`video_mem_start = 0xB800`，只支持 80×25 文本，光标靠 `0x3D4/0x3D5`（CRT 控制器寄存器）编程。
- 图形模式（VESA/VBE）下的控制台要等到 2.6 的 `fbdev`，**再到 5.x/6.x 的 `drm_fbdev`**。
- 🔧 现代层次：`drivers/tty/`（tty 核心 + n_tty）→ `drivers/video/console/`（fbcon 走 framebuffer）→ `drivers/gpu/drm/`（KMS 模式设置 + `drm_fbdev`）。console 只是在最上层的观察者之一，**X11/Wayland 与 DRM 直接抢模式设置权**，控制台再也不是唯一图形终端。

### 10.6 16550 串口（`rs.c`）

```c
/* drivers/char/rs.c —— 教学示意，不代表可编译运行 */
static void rs_write(struct tty_struct *tty)
{
    cli();
    while (nr && (inb(rs_port[tty->minor] + 5) & 0x20)) {  /* LSR->THRE */
        outb(c, rs_port[tty->minor]);                        /* 写一个字节 */
        nr--;
    }
    sti();
}
void rs_interrupt(int irq) { /* 读 IIR 判断来源，处理接收/出错/调制解调器状态 */ }
```

- 波特率靠 `outb(baud, port + 3)`（LCR）设置；`outb(...)` 前必须把 LCR 最高位置 1 才能写除数锁存器。
- 没有 FIFO 深度检测（`LSR` 的 `LSR_FIFO_DATA_READY` 位）、没有自动 XON/XOFF、没有 RTS/CTS 硬件流控自动切换。
- 🔧 现代串口驱动（`drivers/tty/serial/8250/8250_port.c`）用 **DMA（8250 的 DMA mode / 16550A 的 FCR 触发阈值）**、多端口共享 IRQ、devicetree/ACPI 资源获取，且 fifo 深度可按 `port->fifosize` 动态调整。

### 10.7 键盘（`KEYB.S`）

```asm
; drivers/char/KEYB.S —— 教学示意，不代表可编译运行
kb_wait:                       ; 等 8042 输入缓冲区空
    in  al, $0x64
    test al, $2
    jnz  kb_wait
    ret
...
keyboard_interrupt:            ; 8259 IRQ1
    in al, $0x60               ; 读扫描码
    ; 存入环形缓冲，处理 ALT/CTL/SHIFT 状态
```

- 0.11 的键盘扫描码处理是**纯汇编**，且不识别 E0/E1 扩展序列（所以 Function Keys 与某些按键在 0.11 上不可用）。
- 🔧 现代内核：`drivers/input/keyboard/atkbd.c`（AT/PS2，走 I8042）与 `hid-core`/`hid_generic`（USB/蓝牙 HID），扫描码 → 键值由 **input 子系统**统一（`input_event()` + `evdev` 暴露 `/dev/input/eventN`），用户态（libinput/ewmh）负责键位映射。

## 版本演进

| 时间 | 内核版本 | 事件 |
| --- | --- | --- |
| 1991–1994 | 0.11 | 静态 `chr_tbl[]` + `struct tty_struct`（单等待者、双字节缓冲）+ 轮询串口 |
| 2001 | 2.4 | `waitqueue` 成熟，tty 的等待者转向 `wait_queue_head_t` |
| 2007 | 2.6.24 | **TTY 层引入 `struct tty_ldisc` 线路规程机制**，把行编辑与硬件解耦 |
| 2012 前后 | 3.x | `n_gsm`、`n_hsi` 等各种 ldisc 齐备；pty 重构（`pty.c` 统一 master/slave） |
| 2018 | 4.17–4.19 | **Ilpo Järvinen 主导的 TTY 子系统重构**：按 CPU 分片 flip 缓冲、去掉 `put_char/flush_char`、统一 `tty_insert_flip_string` |
| 2019 前后 | 5.x | `n_tty` 单独成文件并从 tty 核心剥离；`tty_port` 进一步抽象 |
| 2020–2026 | 5.x/6.x | 控制台转向 DRM 模式的 `drm_fbdev`；input 子系统支持多点触控、笔、游戏手柄；`libinput`/`wlroots` 生态成熟 |

## 近年研究与工业界开源实践（2015–2026）

- **近年研究**：TTY 侧的研究/工程工作基本集中在**减少上下文切换与延迟**（flip buffer 分片、`n_tty` 的 read_req 优化）、**高分辨率终端的丢字符问题**；输入侧则集中在**多点触控与手势语义**、**输入延迟（input latency）测量**；显示侧集中在 **DRM  unifying kernel mode setting（uKMS）** 与 **Wayland 下的取代表面**。
- **工业界开源**（star 数 2026-09 实测）：
  - `torvalds/linux`（≈**250k★**）：tty 核心在 `drivers/tty/`，串口在 `drivers/tty/serial/`，输入在 `drivers/input/`，图形在 `drivers/gpu/drm/`。
  - `qemu/qemu`（≈**13.8k★**）：实验环境里提供 `virtio-gpu`、`PS/2` 键盘/鼠标、`isa-serial` 设备，让 0.11 的字符设备实验能跑在虚拟机中。
  - `tianocore/edk2`（≈**6.3k★**）：固件侧的 Console/Input 实现，是理解「BIOS 文本模式从哪来」的最佳参照。
  - `llvm/llvm-project`（≈**40.7k★**）：`KEYB.S` 那种纯汇编写法，今天只剩 `arch/*/` 下少量代码，主流是 C + 内联汇编。
  - `gcc-mirror/gcc`（≈**11.3k★**）：内核历来必须用 GCC 扩展（statement expression、asm），这也是书第 14 章「头文件与宏」的根源。

## 常见误区与本书需修正之处

| # | 误区 / 本书局限 | 2026 年的修正与补充 |
| --- | --- | --- |
| 1 | 「TTY 就是终端驱动」 | 🔧 TTY 核心 + `n_tty` 行规程 + pty + 串口 + 各种 ldisc 共同构成 `drivers/tty/`，行编辑逻辑与硬件无关 |
| 2 | 「控制台 = 显卡驱动」 | 🔧 控制台（`fbcon`/`drm_fbdev`）只是 framebuffer 的一个消费者；模式设置归 DRM，控制台是被动适配者 |
| 3 | 「键盘就是读扫描码」 | 🔧 现代输入链：HID 报告 → `input_event` → `evdev(/dev/input/eventN)` → libinput →  Wayland/X11；扫描码翻译在 `input-keymap` 层 |
| 4 | 「一个 tty 只能有一个写者」 | 🔧 从 `wait_queue_head_t` + `tty_port` 起，阻塞语义与等待者数量都已解除单点限制 |
| 5 | 「串口只能 115200」 | 🔧 16550 以上支持 FIFO、自动流控、可达数 Mbps；多串口共享 IRQ 也已成标准 |
| 6 | 「字符设备接口就是 read/write」 | 🔧 现代字符设备还有 `poll/select/epoll`、`mmap`（如 GPU、framebuffer）、`ioctl` 长尾（evdev/`UINPUT`）、以及 `io_uring` 的部分支持 |
| 7 | 本章 `chr_tbl[]` 的下标即设备号 | 🔧 现代内核用 `struct cdev` + `dev_t(makedev/MAJOR/MINOR)` + `register_chrdev_region`，并支持动态分配设备号 |
