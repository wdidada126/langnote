# 第 7 章 初始化程序

> **本章地图**：`init/main.c` 的 `main()` 从左到右、从上到下依次做——确定 `memory_end` / `buffer_size` → 中断门与 IDT（`trap_init()`）→ 定时器与 8259A（`time_init()`）→ 缓冲区与虚拟盘（`buffer_init()` / `rd_init()`）→ isting 控制台与 tty（`tty_init()`）→ `sched_init()`（GDT/TSS/LDT 的最后一道）→ `buffer_init` 之后的缓冲 → `sti()` 开中断 → 建进程 0 与 `fork` 出进程 1 → 挂载根文件系统 → 运行 `/sbin/init`。
>
> 一句话结论：**`main()` 是「内核自己变成操作系统」的那一公里**：前面所有汇编只是把 CPU 和内存摆好，`main()` 之后的每一步才真正造出「进程、文件、设备、调度」这些概念。

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 7.1 概述 | `main()` 的整体流程 | 从「裸机」到「可 fork/可 mount/可 exec」 |
| 7.2 技术要点 | 驱动全局数据结构、栈布局、`buffer` 初始化 | 内核数据结构必须在这一步定型 |
| 7.3 `main()` 逐段 | `trap_init` / `time_init` / `buffer_init` / `rd_init` / `tty_init` / `sched_init` / `sti` / `move_to_user_mode` / `fork` / `mount_root` | 顺序不可随意：分页已开，GDT/IDT 已就绪，才能开中断 |

## 核心精讲

> 以下代码均为**教学示意，不代表可编译运行**。

### 7.1 `main()` 骨架

```c
/* 教学示意，不代表可编译运行：init/main.c 的 main() 主干 */
volatile int jiffies = 0;      /* 由 timer 中断更新的 intrinsic 计数 */

void main(void)
{
    /* 1) 内存布局：从 BIOS 的 ext.bean 与 memory_map 得到可用内存 */
    memory_end = ...;          /* 例：8 MB 或 16 MB */
    buffer_size = ...;         /* 缓冲块数：0.11 里按内存比例算 */

    /* 2) 中断与异常：填 IDT 前 32 项，陷阱门/中断门 */
    trap_init();               /* 填 IDT，set_trap_gate(0, &divide_error) … */

    /* 3) 时钟与 8259A：读 CMOS 得到启动时刻，设置 PIT 频率 */
    time_init();               /* xtime 初值 = from_cmos */
    tms = ...;

    /* 4) 缓冲区与虚拟盘 */
    buffer_init();             /* 把内存尾部切成 1 KB 的缓冲块，链入 free_list */
    rd_init();                 /* 虚拟盘（ramdisk） */

    /* 5) 终端与控制台 */
    tty_init();                /* 串口 + 控制台 + tty 缓冲 */

    /* 6) 调度器与内核地址空间最后一步 */
    sched_init();              /* 建 TSS0/GDT 项、加载 TR、清 NT 位 */
    buffer_init();             /*（部分版本顺序在此） */

    /* 7) 全部就绪，开中断 */
    sti();

    /* 8) 切到用户态（特权级 3） */
    move_to_user_mode();       /* 用 iret 前的最后一次特权级切换 */

    /* 9) 建立进程，fork 出 init */
    fork(0);                   /* 创建进程 1（init） */
    ...
    /* 10) 挂载根文件系统并 exec /sbin/init */
    mount_root();
    ...
    while (1) pause();
}
```

### 7.3 各段的关键点

#### `trap_init()`：IDT 的第一次完整布局

```c
/* 教学示意，不代表可编译运行 */
void trap_init(void)
{
    int i;
    set_trap_gate(0,  &divide_error);
    set_trap_gate(1,  &debug);
    set_trap_gate(2,  &nmi);
    set_trap_gate(3,  &int3);           /* 断点：陷阱门，不关 IF */
    ...
    set_trap_gate(14, &page_fault);     /* #PF：error_code + CR2 */
    set_trap_gate(15, &reserved);
    ...
    set_system_gate(0x80, &system_call);/* int 0x80 → syscall 入口 */
    /* 例外：8259A 的向量在 IDT[0x20] 起；这里只掩蔽，不填处理函数 */
    outb(0x21, 0xFF);                   /* 主片全部掩蔽，稍后逐步打开 */
    outb(0xA1, 0xFF);                   /* 从片全部掩蔽 */
}
```

| IDT 槽 | 内容 |
| --- | --- |
| `0x00–0x1F` | CPU 异常（除零/调试/NMI/断点/溢出/BP/GP/PF/SIMD…） |
| `0x20–0x2F` | 8259A 的 IRQ 向量（0x20 定时、0x21 键盘、0x24 软盘、0x2E IDE） |
| `0x80` | `system_call`（陷阱门） |

#### `sched_init()`：GDT 的收尾与 TSS

```c
/* 教学示意，不代表可编译运行 */
void sched_init(void)
{
    /* 设置 GDT 的第 4、5 项：TSS0 与 LDT0（进程 0 的内核态） */
    set_tss_desc(gdt + 4, _TSS0);
    set_ldt_desc(gdt + 5, _LDT0, 128);

    /* 清 NT（Nested Task）位，防止 iret 时的任务切换陷阱 */
    __asm__ __volatile__("pushfl ; pop eax; andl $0xffffbfff,(%esp); pushl eax");

    ltr(0);          /* 加载任务寄存器 TR = GDT[4] * 8 */
    lldt(0);         /* 加载 LDT = GDT[5] * 8 */

    /* 设置初始调度状态 */
    task[0] = &init_task.task;     /* 进程 0 的任务结构 */
    current = &init_task.task;
    ...
    /* 启动定时器：每秒 100 次 tick */
    outb(0x43, 0x36);              /* 8253 通道 0，方波模式 */
    outb(0x40, LATCH & 0xff);
    outb(0x40, LATCH >> 8);        /* LATCH = 1193182 / 100 */
}
```

> **为什么要 `ltr`/`lldt`？** x86 的任务切换依赖 TSS；Linux 只在**内核初始化时**用它，此后所有进程切换都是「软件保存现场 + 换栈」，不再经过硬件任务切换。这是 Linux 高性能调度的一个重要前提。

#### `buffer_init()`：把内存切成 1 KB 缓冲块

```c
/* 教学示意，不代表可编译运行：缓冲池布局 */
struct buffer_head {
    unsigned long b_data;      /* 指向 1 KB 数据区 */
    unsigned short b_size;
    unsigned char  b_free;     /* 是否在空闲链表 */
    ...
};

/* 内存尾部：N 个 1 KB 缓冲块，头尾相接，链成 LRU 的 free_list */
#define BLOCK_SIZE 1024
buffer_end = ...;
for (b = (struct buffer_head *) (buffer_end - BLOCK_SIZE);
     b > (struct buffer_head *) (BLOCK_SIZE + &end); ...)
    b->b_free = 1;   /* 放入 free_list */
```

#### `move_to_user_mode()`：从内核态落到用户态

```c
/* 教学示意，不代表可编译运行：iret 前的特权级切换 */
__asm__ __volatile__(
    "movl $0x17, %%eax      \n\t"  /* 用户数据段选择子 */
    "mov %%eax, %%ds        \n\t"
    "mov %%eax, %%es        \n\t"
    "mov %%eax, %%fs        \n\t"
    "mov %%eax, %%gs        \n\t"
    "movl $0x0f, %%eax     \n\t"   /* 用户代码段选择子 */
    "pushl %%eax            \n\t"  /* 模拟 iret 的 SS:SP + EFLAGS + CS:IP */
    "pushfl                 \n\t"
    "pushl %%eax            \n\t"
    "movl $1f, %%eax       \n\t"
    "pushl %%eax            \n\t"
    "iret                   \n\t"
    "1:"
);
```

> **原理**：`iret` 会从栈上弹出 CS、EFLAGS、SS:ESP。构造好这三个值再 `iret`，CPU 就认为「这是从用户态陷入内核的返回」，于是把 CPL 从 0 变成 3。这是 0.11 里唯一的「内核→用户」切换点，也是后面 `fork` 返回用户态的模板。

### 7.3 顺序为什么不能乱

| 步骤 | 依赖什么 | 如果提前会怎样 |
| --- | --- | --- |
| `trap_init`（填 IDT） | 分段与 GDT 已就绪 | 无中断表格，开中断即 `#GP` |
| `time_init` | IDT 有 IRQ 槽 | 定时器中断会跑飞 |
| `buffer_init` | 分页已开、线性地址可用 | 缓冲头指针计算错误 |
| `tty_init` | 缓冲已就绪 | 打印时找不到缓冲区 |
| `sched_init` | GDT 可写 | `ltr/lldt` 装载无效选择子 |
| `sti()` | 上面全部完成 | 中断向量未填 → 直接崩溃 |
| `move_to_user_mode` | GDT 有用户段 | CPL=3 但段不可访问 → `#GP` |
| `fork/mount_root` | 中断已开 | 无法等待 I/O |

| 年份 | 初始化环节的变化 |
| --- | --- |
| 1992 | 0.11/0.12：`main()` 手工顺序初始化，全部编译进内核 |

| 2020+ | 🔧 `start_kernel()` 里的 `x86_init`、`init_call` 与 `rust_init` 并行存在 |

## 近年研究与工业界开源实践（2015–2026）

- **`start_kernel()` 是现代的 `main()`**：`torvalds/linux` 的 `init/main.c` 第一件事是 `early_boot` 检查（SMP/`!smp`）、`setup_arch()`、`sched_init()`、`mm_init()`、`rest_init()`，最后 `kernel_thread(kernel_init, ...)` 起用户态 1 号进程——与本书的 `fork/init` 一脉相承，只是被 initcall 与设备模型复杂化了。
- **早期打印是排错第一工具**：现代内核用 `early_printk()`、`DEBUG_HPET`、`printk()` 的 `KERN_DEBUG`；`cirosantilli/linux-kernel-module-cheat`（**4515★**）直接用 QEMU + GDB 单步这条路径。
- **固件与设备树的冲击**：x86 的 `setup_arch()` 需要 e820 映射；arm64 需要 Device Tree；这取代了 0.11 里「硬编码 `memory_end`」的做法。
- **真实工具**：`qemu/qemu`（**13761★**）的 `-d int -D /tmp/int.log` 可记录所有中断，是观察 `main()` 前后中断行为的利器；`brendangregg/FlameGraph`（**19773★**）用于事后分析内核启动的耗时分布。
- **教学对照**：`mit-pdos/xv6-public`（**9646★**）的 `main()`（位于 `kernl/main.c`…实际是 `proc.c` 前的 `smp` 初始化）与 `init.c`，比 0.11 更短，可作为本书的最小对照本。

## 常见误区与本书需修正之处

| # | 说法/写法 | 修正与补充 |
| --- | --- | --- |
| 1 | 「`main()` 就是内核入口」 | 0.x 是 `main()`；🔧 现代是 `start_kernel()`，`main()` 早已不存在于主线 |
| 2 | 「`init()` 里 `fork()` 出进程 1 是标准做法」 | 标准做法，但 0.11 的 `fork(0)` 参数与今天的内核线程语义不同（今天用 `kernel_thread`） |
| 3 | 「初始化顺序无所谓，能跑就行」 | 顺序硬依赖：IDT → 时钟 → 缓冲 → tty → 调度 → `sti` → 用户态 |
| 4 | 「`sti()` 只是开中断」 | 它是「假定前面所有中断处理都装好了」的一步；提前 `sti` 会直接跑飞 |
| 5 | 「`move_to_user_mode` 是 hack」 | 它依赖 `iret` 的栈帧布局，是 x86 特权级切换的标准技巧；🔧 现代内核在 `arch/x86/entry/` 里用 `swapgs` + `sysret/iret` 组合替代 |
| 6 | 🔧 「`buffer_init` 的做法今天还在用」 | 1 KB 手工缓冲池已被 `PAGE_SIZE` 的 `folio`/`biovec` 体系取代 |
| 7 | 🔧 「CMOS 取时间的方式通用」 | 现代用 RTC/HPET/TSC 与 `timekeeping` 子系统；`settimeofday` 与 `CONFIG_HPET_EMULATE` 才是今天的配置项 |
| 8 | 🔧 缺现代内容 | 建议补：`start_kernel()` 全链路、initcall 等级、设备模型、`request_mem_region`、early console |
