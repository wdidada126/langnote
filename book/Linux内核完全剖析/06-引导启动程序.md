# 第 6 章 引导启动程序

> **本章地图**：`bootsect.s`（BIOS 载入，把自己搬到 `0x07C00`，再把 `setup`、`system` 搬到 `0x10000` 起）→ `setup.s`（进入保护模式的准备：装载 GDTR/IDTR、重新分段、把 system 搬到 `0x0000`）→ `head.s`（32 位入口：设段寄存器、重设 GDT/IDT、分页、跳进 `main()`）。
>
> 一句话结论：**「实模式 → 保护模式」的三维切换全部发生在这 3 个不到 1 KB 的汇编文件里**，这是全书最有「戏剧性」的一章：BIOS 在 20 分钟前刚把这段代码读进内存，现在它要把整个内核重新排布一遍。

| 节 | 文件 | 内容 | 结论 |
| --- | --- | --- | --- |
| 6.1 工作原理 | 三段式引导流程 | BIOS → bootsect → setup → head → main | 每一段只负责「把代码放到该放的位置」 |
| 6.2 `bootsect.s` | 16 位汇编（`as86`） | 搬自己、`int 0x13` 读 `setup`/`system`、加载 `root_dev` | 512 字节硬约束，必须最后放魔数 `0xAA55` |
| 6.3 `setup.s` | 16 位汇编 | `cli`、`lgdt/lidt`、置 `CR0.PE`、远跳 8:0 | 「**进保护模式只差一条 `cr0` 写和一条远跳**」 |
| 6.4 `head.s` | 32 位汇编（GNU as） | 设 DS/ES/FS/GS、重设 IDT/GDT、分页、跳 `main()` | 分页在 `main()` 之前，所以 `main()` 看到的线性地址 = 物理地址 |

## 核心精讲

> 所有代码均为**教学示意，不代表可编译运行**。

### 6.2 `bootsect.s`：在 512 字节内做四件事

```asm
; 教学示意，不代表可编译运行：bootsect.s 的主干
    org 0x7C00                ; BIOS 把引导扇区载入此处（实模式段 0x07C0:0x0000）

start:
    mov ax, 0x7C00
    mov ds, ax
    mov ax, cs
    mov es, ax                ; ES = CS，准备搬自己

    ; 1) 把自己整体搬到 0x0600（避开 0x7C00 附近的中断向量区）
    call copy_self

    ; 2) 用 BIOS int 0x13 把 setup.s 读到 0x10000（SETUPSEG=0x1000）
    ;    再用 int 0x13 把 system 模块读到 0x10000 之后
    load_setup:
        mov cx, 0x0004        ; 扇区数
        mov dx, 0x0000        ; 驱动器 0
        mov bx, 0x0200        ; ES:BX = 0x1000:0x0200
        mov ax, 0x0200+0x0004 ; AH=02 读盘, AL=4 个扇区
        int 0x13
        jnc load_ok
        jmp load_setup        ; 反复重试（软盘的读错是常态）

    ; 3) 关闭中断、搬 system 到 0x0000 之前准备
    cli
    ; 4) 跳到 setup（段 0x1000）
    jmpi go, 0x1000
```

**四个必须记住的硬约束：**

| 约束 | 数值 | 为什么 |
| --- | --- | --- |
| 引导扇区大小 | 512 字节 | 磁盘扇区固定；末尾 2 字节必须是 `0x55 0xAA` |
| 载入地址 | `0x7C00` | IBM PC 的 BIOS 约定 |
| 自己搬走 | 到 `0x0600` | 让出 `0x7C00` 附近给 BIOS 数据区 |
| `setup`/`system` 目标 | `0x10000`（实模式段 0x1000） | 常规内存 `0xA000–0xFFFF` 要留给 BIOS/显存 |

### 6.3 `setup.s`：保护模式的「入场券」

```asm
; 教学示意，不代表可编译运行：setup.s 的关键序列
    cli                       ; 1. 先关中断（后面要动 GDTR/IDTR）
    lgdt gdt_48               ; 2. 装载 GDT（限长+基址）
    lidt idt_48               ; 3. 装载 IDT（暂时是 16 位的临时 IDT）

    mov eax, cr0
    or  al, 0x01              ; 4. CR0.PE = 1，进入保护模式
    mov cr0, eax

    jmpi 0, 8                 ; 5. 远跳到段选择子 8（GDT[1]=CS，基址 0）
                              ;    这一步同时刷新 CS 的段描述符高速缓存
```

> **这一段是本章的心脏**。三条要点：
> 1. 顺序不可交换：`cli` 必须最先，`lgdt/lidt` 必须在 `cr0.PE=1` 之前，远跳必须在 `cr0` 写之后；
> 2. `jmpi 0, 8` 里的 `8` 是**段选择子**（`GDT[1]`），不是段基址；
> 3. setup 还要顺便把 system 从 `0x10000` 搬回/重排到 `0x0000` 开始的连续区域，并重新设置 IDT 与临时 GDT 的 selectors。

### 6.4 `head.s`：32 位世界的第一段代码

```asm
; 教学示意，不代表可编译运行：head.s 的主干
    .section .text
.globl startup_32
startup_32:
    mov ax, 0x10             ; 内核数据段
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    lss stack_start, %esp    ; 设置内核栈（SS:ESP）

    call setup_idt           ; 重设 IDT（256 项，全指向 ignore_int）
    call setup_gdt           ; 重设 GDT（4 项：0/CS/DS/系统）

    ; 分页：把低 4 MB 一一映射，然后写 CR3 打开 CR0.PG
    call setup_paging
    lgdt gdt_48              ; 分页后段描述符已失效，需要重装
    lidt idt_48

    push $0                  ; 参数：无（0.11 的 main 无参）
    call main                ; 跳进 C
```

```text
; 教学示意：0.11 的 GDT（4 项），全部基址 0、限长 0xFFFFFFFF（平坦模型）
;   GDT[0] = 0000000000000000h    （占位，必须为空）
;   GDT[1] = 00cf9a0000000fffh    （CS: 可执行、可读、DPL=0、4 GB）
;   GDT[2] = 00cf920000000fffh    （DS: 可写、DPL=0、4 GB）
;   GDT[3] = 00cf9a0000000fffh    （系统段 / TSS 相关占位）
```

```c
/* 教学示意，不代表可编译运行：分页填充（head.s 里 setup_paging 的 C 部分） */
static unsigned long tmp_page[1024];   /* 页目录 */
static unsigned long page[1024];       /* 页表 */

static void setup_paging(void)
{
    int i;
    for (i = 0; i < 1024; i++) { page[i] = 0; tmp_page[i] = 0; }
    /* 低 4 MB：物理页 i → 线性页 i，属性 P|R/W|U/S = 7 */
    for (i = 0; i < 1024; i++) page[i] = (i << 12) | 7;
    /* 页目录第 0 项指向页表；第 1 项也指向自己（自映射，方便内核修改页表） */
    tmp_page[0] = 0x1000 | 7;
    tmp_page[1] = (unsigned long)tmp_page | 7;
    ...
    __asm__ __volatile__("movl %0, %%cr3" :: "r"(tmp_page));   /* 刷新 TLB */
    __asm__ __volatile__("movl %%cr0, %%eax; orl $0x8000, %%eax; movl %%eax, %%cr0");
}
```

> **自映射（self-mapping）是本章最精彩的技巧**：把页目录项指向页目录自身所在的物理页，使得内核可以通过「线性地址 = 页目录虚拟地址」直接改写页表，无需 `invlpg`。

### 6.5 从 `main()` 之前的完整时序

```text
; 教学示意：加电到 main() 的时间线
;  T0  CPU reset → CS:IP = FFFF:0000 →  BIOS 自检
;  T1  BIOS 读引导扇区 → 0x7C00
;  T2  bootsect 搬自己 → 0x0600；读 setup(0x10000) 与 system(0x10000+)
;  T3  setup 段：lgdt/lidt/cr0.PE/jmpi 8:0        ← 进入保护模式
;  T4  head 段（startup_32）：设段寄存器 → 重设 GDT/IDT → 分页 → 
;  T5  call main  →  init/main.c 的 main()
```

> 结论：**分页在进入 `main()` 之前已经打开**，所以 `main()` 里所有全局符号的地址都是「= 物理地址」的线性地址，直到 `07-初始化程序.md` 里 `memory_map` 把它重新划分。

## 版本演进

| 年份 | 引导环节的变化 |
| --- | --- |
| 1992 | 0.11/0.12：BIOS + 软盘 + `cat` 拼 Image |
| 1994 | 1.0：开始支持 `ELF` 作为 Image 格式（后续） |
| 1999+ | 2.x：LILO / GRUB；`bootsect` 逻辑被 `arch/i386/boot/` 取代 |
| 2000 | 🔧 **Multiboot** 成为主流引导协议（GRUB 提供 multiboot header） |
| 2008+ | 🔧 EFI/UEFI 普及；`efistub`、`systemd-boot` |
| 2012+ | 🔧 **systemd**（**16746★**）的 `bootctl` 与 `u-boot/u-boot`（**5253★**）承担现代启动 |
| 2018+ | 🔧 x86_64 主线默认 UEFI；legacy BIOS 支持逐步弱化 |
| 2020+ | 🔧 **`initrd`/`initramfs` 成为标配**：早期用户态在挂载真实根文件系统前运行 |

## 近年研究与工业界开源实践（2015–2026）

- **现代引导链**：固件（UEFI）→ bootloader（GRUB / systemd-boot / `u-boot/u-boot`，**5253★**）→ `bzImage` → initramfs → systemd（**16746★**）。本书的 `bootsect → setup → head` 只对应最前面那一小截。
- **QEMU 是最佳实验台**：`qemu/qemu`（**13761★**）的 `hw/isa/`、`fw/`（ SeaBIOS / EFI）可以直接观察「BIOS 干了什么」；`-d int` 能打印所有中断，**「看 0x13 的每次调用」比读代码直观**。
- **自写内核的现成模板**：`dreamportdev/Osdev-Notes`（**1158★**）与 `Minep/lunaix-os`（**525★**）用现代工具链重走本章这条路；`cirosantilli/linux-kernel-module-cheat`（**4515★**）给出可单步调试的 x86-64 引导。
- **内核调试的起点**：加 `serial console`（`0x3F8`）与 early printk，是替代「在 bootsect 里点亮 LED」的现代做法。
- **xv6 对照**：`mit-pdos/xv6-public`（**9646★**）的 `bootasm.S` + `bootmain.c` 是「另一份更短的 bootsect/setup」，可逐行对照本书。

## 常见误区与本书需修正之处

| # | 说法/写法 | 修正与补充 |
| --- | --- | --- |
| 1 | 「bootsect 就是一段小程序」 | 它有**硬约束**：512 字节、末尾 `0xAA55`、载入地址 `0x7C00`，且必须在软盘/磁盘的**第一个扇区** |
| 2 | 「CR0.PE=1 就是进保护模式了」 | 还需 `lgdt` 已执行、CS 缓存已通过远跳刷新；且此时分页（`CR0.PG`）仍然关闭 |
| 3 | 「setup.s 做了分段切换」 | 严格讲 setup 做的是「装载 GDTR/IDTR + 置 PE + 远跳」，**重新分段是 head 段做的** |
| 4 | 「`head.s` 里分页后才跳 main」 | 正确，但要注意 `lgdt/lidt` 在分页之后**必须重装**，因为段描述符高速缓存与页表无关但 GDT 本身所在线性地址变了 |
| 5 | 「引导扇区可以直接跳进 32 位代码」 | 不行：`jmpi` 后仍执行 16 位代码流，必须先切 PE 再跳 |
| 6 | 🔧 「软盘 + BIOS 就是今天的事」 | 2026 年基本没有软驱；真实环境是 UEFI + initramfs |
| 7 | 🔧 「`main()` 就是现代内核的入口」 | 现代入口是 `init/main.c: start_kernel()`；`main()` 只在 0.x 时期存在 |
| 8 | 🔧 缺现代引导内容 | 建议补：Multiboot / EFI stub、initramfs、`initcall` 机制、early console |
