# 《Linux内核完全剖析》总览与阅读地图

> 赵炯 编著，机械工业出版社。第 1 版 2006-01（ISBN 9787111180326，882 页，**基于 Linux 0.11 内核**）；
> 修订版《Linux 内核完全剖析——基于 0.12 内核》2009-01（ISBN 978-7-111-25047-0，945 页）；
> 第 2 版「15 周年版」2024（ISBN 978-7-111-74419-1，精装，定价 299.00 元）。
> 配套资源站点：**www.oldlinux.org**。豆瓣条目 https://book.douban.com/subject/3229243/

**大纲版单文件在此**：`book/Linux内核完全剖析.md`（含原书完整中译目录与本仓库原始摘录）。
**本目录是深度重写版**：按原书 17 章逐章展开，每章统一「地图 → 核心精讲 → 版本演进 → 经典文献 → 近年实践 → 误区与补正 → 跨章跨书联系」。两版并存、互链，不互相覆盖。

## 1. 这本书到底是什么（先建立正确预期）

| 维度 | 实际内容 |
| --- | --- |
| 研究对象 | Linux **0.11 / 0.12** 内核源码树（约 1 万行量级的可编译、可运行的小内核） |
| 写作方式 | 对源码文件**逐行加注**，而不是抽象原理讲解 |
| 代码规模 | 0.11 内核解压后约 1.4 MB、百余个 `.c/.s` 文件；现代内核超过 4000 万行，无法同法处理 |
| 历史定位 | 2004 年《Linux 内核完全注释》（436 页）的「完全剖析」续作，前者基于 0.11，后者第一版仍基于 0.11、修订版改 0.12 |
| 真实价值 | 提供一条**能跑通的完整链路**：BIOS → bootsect → setup → head → main() → 进程/内存/文件系统/驱动 |
| 主要短板 | ①成书 2006 年，内核主流早已是 6.x；②对 80x86 保护模式的讲解偏繁琐，细节不如厂商手册；③部分代码注释有翻译/勘误问题 |

> **一句话使用建议**：把它当「**可运行的最小内核全景贴图**」来读，而不是当现代内核教程。想看现代内核，先读本书建立骨架，再用 `torvalds/linux` + `Documentation/` 往下钻。

## 5. 从 0.11 到 2026：必须补的 12 个现代差距

本书的可贵在于「小」，代价是「旧」。以下 12 点是读本书时应当同步补上的（各章会挑 2–4 条展开）：

| # | 主题 | 0.11/0.12 的样子 | 现在的样子 |
| --- | --- | --- | --- |
| 1 | **调度器** | 单 CPU、非抢占、时间片轮转 + 启发式优先级 | 抢占式、CFS（2.6.23 起）、多核负载均衡、RT 组 |
| 2 | **内核抢占** | 无；`schedule()` 只能由主动调用或 timer 触发 | `CONFIG_PREEMPT_DYNAMIC`，从 2.6 到 6.x 逐步引入抢占 |
| 3 | **内存分配器** | 手工 `get_free_page` + 少量 `kmalloc` 池 | SLUB（`SLAB` 的继任者，7.x 起 SLUB 默认）、memblock 早期分配器 |
| 4 | **I/O 模型** | `read/write` on fd，select/poll 基本可用 | **epoll**（2.5.44）、io_uring（5.1 起）、`sendfile`/`splice` |
| 5 | **设备与 sysfs** | 无统一对象模型，字符/块设备手工注册 | **kobject/kset/sysfs**、device model、uevent、udev |
| 6 | **模块机制** | 无（0.11 内核整体编译） | **可加载模块 `.ko`**、modpost、模块签名、BTF |
| 7 | **分页扩展** | 32 位、非 PAE、4 KB 页、单页目录 | **PAE**（2.6 起，36 位物理地址）、4 MB 大页、X86_64 五级页表 |
| 8 | **体系架构** | 仅 i386 | arm64 / riscv64 / powerpc / loongarch 等；`arch/` 与通用代码分离 |
| 9 | **可观测性** | 只能 printk、看空闲死循环 | **eBPF**、ftrace、perf、BPF CO-RE |
| 10 | **可观测性（内核态）** | 手动加 `printk` | `trace_printk`、`tracepoints`、`BPF_PROG` |
| 11 | **安全** | 无 | SELinux/ apparmor、KASLR、CFI、影子栈、签名模块 |
| 12 | **语言与工具链** | GCC 老语法、内嵌汇编、`as86` | rust-for-linux、clang 支持、KASAN/UBSAN、`objtool` |

## 7. 术语速查（0.11 术语 → 现代内核术语）

读旧代码时最大的障碍不是逻辑，而是**名字变了**。这张表能省下大量搜索时间。

| 0.11/0.12 的说法 | 出处 | 🔧 现代内核里的对应物 |
| --- | --- | --- |
| `main()` | `init/main.c` | `start_kernel()`（同一个位置的「名字」） |
| `task_struct` 的 `counter/priority` | `sched.c` | CFS 的 `se->vruntime`，优先级是 `nice`/`sched_prio` |
| `need_resched` | `sched.c` | `TIF_NEED_RESCHED` 线程标志 + `preempt` 点 |
| `sleep_on/wake_up` | `sched.c` | `wake_up_process()` / `waitqueue` + RCU |
| `buffer_head` 的 1 KB 缓冲 | `fs/buffer.c` | `folio` / `bio` / `bvec` |
| `do_timer()` | `sched.c` | `tick_handle_periodic()` / `sched_tick()` |
| `int 0x80` 系统调用 | `system_call.s` | `syscall` 指令 + `do_syscall_64` |
| `copy_page_tables` | `mm/page.s` | `copy_page_tables()`（C 版）+ RCU 页表 |
| `TSS0`/`LDT0` | `sched.c` | 每 CPU 的 `tss_struct`（`force_ttss`） |
| `kernel/blk_drv/`、`chr_drv/` | 0.11 目录 | `block/` 与 `drivers/tty/`、`drivers/char/` |
| `root_dev` / `mount_root()` | `super.c` | `initramfs` + `fs/namespace.c` 的 mount 树 |
| `math-emu`（387 仿真） | `kernel/math/` | 已弱化；新架构靠 `CONFIG_FPU`/`kernel/fpu/` |

## 9. 实验与可复现环境（替代原书第 15–17 章的最小方案）

原书最后一章教你用 Bochs 装 0.12 并跑实验。2026 年的等价方案（**不编译、只观察**）：

| 需求 | 方案 | 备注 |
| --- | --- | --- |
| 看引导阶段在做什么 | QEMU + `-d int -D int.log` | 能打印每一次 `int`，包括 BIOS 的 |
| 单步跟踪 bootsect | `qemu-system-i386 -s -S` + GDB `target remote :1234` | 逐条执行 16 位代码 |
| 看 x86 芯片行为 | QEMU 的 `hw/isa/`、`hw/block/`（8259A/8237/8254/IDE 的软件实现） | 比 datasheet 快 |
| 看现代内核 | 在宿主上跑 perf/ftrace，`torvalds/linux` 自带文档 | 与本书对照的「另一半」 |
| 不想装 Linux | WSL2 / 容器里同样可用 QEMU + GDB | 学习路线不受操作系统限制 |

## 10. 三条阅读承诺

1. **先小后大**：0.11 的 1 万行先读完一遍，再去摸 4000 万行的主线，否则会迷路。
