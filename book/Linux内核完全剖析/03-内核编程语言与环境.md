# 第 3 章 内核编程语言和环境

> **本章地图**：`as86`（16 位汇编器，用于 bootsect/setup）与 `ld86` 的用法 → GNU `as`（32 位汇编，用于 head.s 与部分 arch 代码）语法、区（section）与重定位、符号、16 位代码编写 → C 语言程序：编译链接结果、内嵌汇编（`asm volatile`）、括号组合语句、寄存器变量、内联函数 → C 与汇编互相调用（AT&T 调用约定）→ **目标文件格式**（ELF、`a.out`、`.o`、System.map）→ **Make 与 Makefile**（规则、变量、自动变量、隐含规则）。
>
> 一句话结论：**这一章是「0.11 内核能不能编译」的全部答案**。0.11 用 16 位工具链（`as86/ld86`）编 3 个 16 位启动文件，用 `gcc` 编其余、用 `ld` 链接；理解目标文件格式，才能理解为什么 `head.s` 之后所有地址都从 `0x0000` 重新开始。

## 核心精讲

### 3.1/3.2 两套汇编器的分工

0.11 的编译是**双工具链**的：

| 文件 | 汇编器 | 位宽 | 说明 |
| --- | --- | --- | --- |
| `boot/bootsect.s`、`boot/setup.s` | `as86/ld86` | 16 位 | 实模式，最大 1 MB 地址，无 32 位指令 |
| `boot/head.s`、`kernel/*.s`、`mm/*.s` | GNU `as` | 32 位 | 保护模式，平坦分段，平铺线性地址 |

```asm
; 教学示意，不代表可编译运行：as86 与 GNU as 的写法差异（同一逻辑两种风格）

; ---- as86（Intel 风格，注意操作数方向相反、无 % 前缀）----
! as86 里注释是 !，立即数是符号后跟数字
    mov ax, 0x10
    mov ds, ax

; ---- GNU as（AT&T 风格）----
    .code32
    mov $0x10, %ax
    mov %ax, %ds
```

> 易错点：as86 用 Intel 语法（目标在前），GNU as 用 AT&T 语法（源在前、寄存器带 `%`、立即数带 `$`）。**混写是最常见的编译失败原因**。

### 3.3 内嵌汇编：内核的「贴身硬件操作」手段

```c
/* 教学示意，不代表可编译运行：gcc 内嵌汇编的典型形态 */
#define cli()       __asm__ __volatile__ ("cli")
#define sti()       __asm__ __volatile__ ("sti")
#define iret()      __asm__ __volatile__ ("iret")

/* 带操作数的版本：把 eax 的值传给 port，port 用 cl 指定 */
static inline unsigned char inb(unsigned short port)
{
    unsigned char _v;
    __asm__ __volatile__ ("inb %1, %0" : "=a" (_v) : "d" (port));
    return _v;
}

/* 「延时代替内存屏障」的经典技巧（io.h 中的 outb_p） */
#define outb_p(value, port) \
    __asm__ __volatile__ ("outb %0, %1\n\t" \
                          "jmp 1f\n\t" "1:" : : "a" (value), "d" (port))
```

> 三个必须懂的点：
> 1. `__volatile__` 禁止 GCC 把这段代码移出循环或删除；
> 2. 约束 `"=a"` 表示「输出到 `eax`」，`"d"` 表示「从 `edx` 输入」——这是 AT&T 寄存器约束写法；
> 3. 内核里大量用「跳转指令做耗时空转」来匹配慢速外设，现代代码改用 `barrier()`/`readl()` 的 `rmw` 语义。

### 3.3 括号中的组合语句与内联函数

```c
/* 教学示意，不代表可编译运行：把多个语句塞进一个表达式 */
#define __pack(x) ({ (x); })     /* GNU C 的语句表达式：值为最后一个表达式 */
```

> 0.11 的 `include/linux/kernel.h` 里这类宏很多；现代内核改用 `({ ... })` 语句表达式同样常见，但更推荐用 `static inline` 函数 + 编译检查。

### 3.4 C 与汇编的互相调用

0.11 用 GCC 的 **寄存器参数约定**：前几个参数依次进 `eax/ecx/edx`，返回值放 `eax`。

```c
/* 教学示意，不代表可编译运行：C 侧声明（extern 汇编符号） */
extern void _start(void);                 /* head.s 的入口 */
extern long _get_hi(void);                /* 汇编实现的辅助函数 */
extern void _set_tss_desc(unsigned int n, unsigned long addr);
```

```asm
; 教学示意，不代表可编译运行：汇编侧，向 C 传入返回值
;   _get_hi: 读入 cr3 并返回
_get_hi:
    movl %cr3, %eax     ; 返回 eax
    ret
```

> 注意：0.11 里真正关键的是**入口约定**——`head.s` 把 GDT/IDT 指针等准备好后，`ret` 回 `0x0000` 处的 `main()`，这就是「汇编跳进 C」的教科书例子。

### 3.5 目标格式与 `System.map`

```text
# 教学示意，不代表可编译运行：System.map 的典型内容（地址 → 符号）
c00f0000 T _start
c00f0100 T main
c00f1000 T schedule
c00f2000 T do_timer
00000000 A startup_32
```

| 概念 | 含义 |
| --- | --- |
| `.text / .data / .bss` | 代码 / 已初始化数据 / 未初始化数据（只占大小不占空间） |
| 重定位条目 | 记录「某节某偏移处需要填某个符号的地址」 |
| 符号表 | 名字 ↔ 地址；链接后成为 `System.map` |
| `vmlinux.lds` | 链接脚本，决定各节如何映射到最终虚拟地址 |

> 🔧 现代内核的 vmlinux 是 **vmlinux.lds + `scripts/link-vmlinux.sh`**，并用 `objtool` 校验；`System.map` 依旧生成，但位置为 `System.map`。

### 3.6 Makefile

```make
# 教学示意，不代表可编译运行：0.11 顶层 Makefile 的骨架形态
CC      = gcc
AS      = as
CFLAGS  = -m32 -O2 -fno-strength-reduce -fomit-frame-pointer -fno-common

boot/bootsect: boot/bootsect.s
    as86 -o boot/bootsect.o boot/bootsect.s
    ld86 -s -o boot/bootsect boot/bootsect.o

Image: boot/bootsect boot/setup system
    cat boot/bootsect boot/setup system > Image
```

> 结论：0.11 的构建是**「手工拼接镜像」**——`cat bootsect + setup + system > Image`。
> 🔧 现代内核是 `Kbuild`：`.config` → `autoconf.h` → 递归 `obj-y/obj-m` → `vmlinux` → `bzImage`；`buildroot/buildroot`（**3656★**）与 `cirosantilli/linux-kernel-module-cheat`（**4515★**）给出了最小可复现的现代构建链。

## 版本演进

| 年份 | 变化 |
| --- | --- |
| 1991 | 0.11：`as86/ld86` + `gcc -m68000?` 都不对，**实际是 80386 交叉编译**，Image 用 `cat` 拼接 |
| 1994 | 1.0：Makefile 开始有 `dep` 依赖生成（`ramdisk`、`nramdisk`） |
| 2001 | 2.4：Makefile 引入 `ifneq ($(CONFIG_X),y)` 条件与 `linuxsubdirs` |
| 2002 | 2.5：**Kbuild 引入**（Linux Kernel Makefile 重构），`obj-m/obj-y` 体系形成 |
| 2018+ | 🔧 LLVM/clang 支持成熟；`HOSTCC` 与 `CC` 分离；`make LLVM=1` |
| 2021+ | 🔧 Rust 工具链进入内核构建（`Rust-for-Linux/linux`，**4413★**）；`rustfmt`/`clippy` 参与 CI |
| 2023+ | 🔧 内核要求 GCC >= 5.1 / clang >= 14（逐步提高），老交叉链不再可用 |

## 近年研究与工业界开源实践（2015–2026）

- **汇编在内核里的占比已降到个位数**：`torvalds/linux`（**250112★**）里 `.S` 文件的比例远低于 2006 年，绝大多数硬件交互改用 C + 内嵌 `asm()`。
- **工具链仓库实测**：`gcc-mirror/gcc`（**11261★**）、`llvm/llvm-project`（**40652★**）是本章「编译器行为」的一手实现；`netwide-assembler/nasm`（**3315★**）虽然主要用于 DOS/固件教学，但仍是 16 位汇编写作的最佳靶子。
- **内联汇编正在被替代**：现代内核用 `READ_ONCE`/`WRITE_ONCE`、`<asm/barrier.h>`、`READL()` 与编译器屏障做 memory ordering，减少手写 `asm volatile`。
- **`dreamportdev/Osdev-Notes`（1158★）** 与 **`fishinabarrel/linux-kernel-module-rust`（1336★）** 提供了「用现代 clang + QEMU 重走 0.11 构建路径」的实操记录。

## 常见误区与本书需修正之处

| # | 说法/写法 | 修正与补充 |
| --- | --- | --- |
| 1 | 「IN OUT 指令可以随便用」 | 🔧 保护模式下 I/O 受 **IOPL** 与 TSS 的 I/O 位图限制；内核能用，用户态需 `ioperm()`/`iopl()` |
| 2 | 「as86 和 GNU as 只是语法不同」 | 二者位数、重定位方式、段模型都不同；0.11 的双工具链是历史产物，现代内核只有一套 |
| 3 | 「AT&T 语法就是把操作数反过来」 | 不止顺序：`%` 前缀、`$` 立即数、`size` 后缀（`l/w/b`）、跳转/调用的 `*` 间接前缀，都要记牢 |
| 4 | 「`System.map` 只在调试时用」 | 它是 `kallsyms` 的输入之一，也是 `System.map` 用于 `klogd`/`ksymoops` 的历史角色 |
| 5 | 「Makefile 规则写一遍就行」 | 🔧 现代内核用 Kbuild，`.config` 驱动条件编译，手写 Makefile 只在少数子目录（如 `tools/`）保留 |
| 6 | 🔧 「C 语言就是标准 C」 | 内核代码大量依赖 GNU **扩展**：语句表达式、零长数组、`__attribute__((noreturn))`、函数属性；不符合 ISO C |
| 7 | 🔧 「汇编学完就够」 | 2026 年内核里 Rust 已成一线语言（`Rust-for-Linux/linux`，**4413★**），C 之外的选择是现实存在的 |
| 8 | 🔧 缺现代工具链材料 | 建议补：`Documentation/process/building.html`、`clang/` 支持、BTF/`pahole`、KASAN |
