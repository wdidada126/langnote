# 第 17 章 实验环境设置与使用方法

> **本章地图**：实验机器的最低要求（80386、≥4MB RAM、软驱/IDE、minix 根文件系统）→ 工具链（`gcc`/`as86`/`ld86`/`make`/`tools/build.c`）→ **实验 0：编译出 Image 并在模拟器里启动** → 实验 1（时间片轮转与 `ps`）、实验 2（root 进程与 shell）、实验 3（新增系统调用）、实验 4/5（服务与文件相关）、实验 6（内存管理）→ 常见故障排查 → 🔧 2026 年的现代替代方案（QEMU + busybox/buildroot、eBPF/ftrace/perf 动态追踪）。核心结论：这十几个实验是「**把整本书的代码读懂之后，用最短路径亲手改一遍 0.11 内核**」，其价值主要在建立「改内核 → 重新构建 → 重新启动 → 观察」的完整闭环直觉。

## 核心精讲

> 以下均为**教学示意，不代表可编译运行**。

### 17.1 最小可行环境

```text
CPU         : 80386 以上（实模式 → 保护模式 → 分页三步走）
内存        : ≥ 4MB（0.11 把 4MB 以上留给磁盘缓冲区）
启动设备    : 1.44MB 软盘（Image 大小）或 IDE 硬盘
根文件系统  : minix 1.0 文件系统（mkfs.minix 制作）
显示        : VGA 文本模式（80×25）
```

- 0.11 的 `Image` 并不是一个可调大小的内核镜像，**它就是一张标准 1.44MB 软盘的字节镜像**：起始 512 字节是引导扇区，其后是 `setup`，再后是 `system`。
- 所以「把内核装进机器」等价于「把一块软盘的内容写出去」——`dd if=Image of=/dev/fd0 bs=512 count=1` 或者其他等价方式。

### 17.2 工具链与疑难杂症

```make
# 0.11 的 boot/Makefile（简化示意）—— 教学示意，不代表可编译运行
AS86FLAGS = -30 -0 -a        # as86：16 位汇编
LDFLAGS86 = -0
CC        = gcc -m386
CFLAGS    = -Wall -O2 -fomit-frame-pointer
```

常见不兼容：

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| `as86: command not found` | 缺少 `bin86` 包 | `apt install bin86`（Debian/Ubuntu 系列） |
| 编译报 `error: ... ` 在 `kernel/` | GCC 3.x 之后对内联汇编与 `__attribute__` 更严格 | 找一个 2.95/3.2 的老 GCC，或用社区整理过的 0.11 补丁集 |
| `make` 成功但 QEMU 里黑屏 | 软盘镜像没有写全 / 引导签名错误 | 检查 Image 大小是否为 1.44MB、`boot/bootsect.s` 末的 `0x55 0xAA` |
| 「No working init found」 | 根文件系统坏了或 `init/main.c` 的 `init()` 里 fork 失败 | 这是 0.11 的经典报错，见 `07-初始化程序.md` |

### 17.3 实验 0：把内核跑起来

```bash
# 1) 编译
make                  # 生成 Image（约 1.44MB）
# 2) 准备软盘镜像（宿主机为空盘）
dd if=/dev/zero of=a.img bs=512 count=2880
dd if=Image of=a.img conv=notrunc
# 3) 用模拟器启动
qemu-system-i386 -drive file=a.img,format=raw,if=floppy -m 16
# 或（Bochs 时代写法）
bochs -f bochsrc.txt      # bochsrc 里 floppya: 1_44=a.img, status=inserted
```

- 成功标志：终端上打印出类似 `Current process is "init"`（不同版本提示略有差异）、出现 shell 提示符、能敲 `ps` 看到 2–3 个任务。
- 这一步的**价值远大于它看起来有多简单**：它把前面 16 章的所有静态阅读变成了一个可交互的实验对象。
- 🔧 今天更省事的做法：直接把仓库 tag 切到 `v0.11`（`git checkout v0.11`）后用现代工具链编译，或用社区维护的补丁集；模拟器统一用 QEMU（`-nographic` 可把输出直接打到终端）。

### 17.4 实验 1：时间片轮转

```c
/* kernel/sched.c（0.11 关键片段）—— 教学示意，不代表可编译运行 */
if (--p->counter > 0) { ... }          /* 每次时钟中断递减 */
if (!current->counter)                /* 用尽则让出 CPU */
    current->counter = 0;
    ...
```

- 只需调整 `init_task.task.counter` 的初始值与调度公式里的系数，就能观察「长任务 vs 交互式任务」的相对吞吐——这是理解 O(1) 调度器之前时代设计取舍的最小实验。
- 🔧 对照：现代内核 `sched/`、`CFS` 的 `sched_slice()` 用虚拟运行时间（`vruntime`），并且有 `CONFIG_HZ`、per-CPU 运行队列与负载平衡；这个实验的结论仍然成立，只是「时间片」的含义从固定毫秒变成了权重分配。

### 17.5 实验 2：增加 root 进程与简单 shell

```c
/* init/main.c（0.11 关键片段）—— 教学示意，不代表可编译运行 */
void init(void)
{
    ...
    if (!(pid = fork())) {              /* 第一个子进程：shell */
        ...
        execve("/bin/sh", argv, envp);
    }
    ...
    while (1) { ... wait(); ... }       /* 父进程回收 */
}
```

- 实验要求通常包含「让 `shell` 在没有用户输入时自动退出并重建」，也就是要理解 `wait()` 与 `exit()` 的配对。
- 🔧 现代对照：`init/main.c` 里已经是 `kernel_thread(init, ...)` + `run_init_process("/sbin/init")`；init 进程不再手工 fork 第二进程。

### 17.6 实验 3：新增一个系统调用

需要同时改四处，缺一不可：

```c
/* ① 内核侧：kernel/sys_call.c */
extern int my_syscall(int arg);          /* 与 sys_call_table[NR] 对应 */
/* ② 系统调用表：kernel/system_call.s 的 res 表 */
    .long sys_ni_syscall ... .long my_syscall
/* ③ 用户态封装：lib/ 里写一个同名函数或直接 int 0x80 */
/* ④ 头文件：include/unistd.h 里增加 NR_mycall 与宏 */
```

- 走通之后，你就能从用户程序调用内核里自己写的函数——这一步是理解 **API → ABI → INT 0x80 → 系统调用表 → 内核函数** 全链路的最小实验。
- 🔧 现代对照：这些细节被 `syscalls/` 表（ARM/RISC-V 各有自己的 syscall 表）、`seccomp`、`系统调用号固定分配`与 `restart_block` 接管；今天写内核功能更多用 `static int __init xxx_init(void)` 内核模块，而不是改系统调用表。

### 17.7 实验 4/5：服务与文件相关

- 实验 4 常见要求：实现一个**简单 shell**（读入命令行 → `fork` + `execve`/`exit`），或实现一个「后台服务进程」；
- 实验 5 常见要求：打通文件路径解析，或实现/扩展一个文件系统调用（如 `my_ls`、`my_cat` 之类）。
- 两者都会反复用到第 12 章的 `namei()`/`bread()` 路径，是全书理论与实践的交汇点。

### 17.8 实验 6：内存管理观察

- 常见做法：打印当前进程的地址空间、统计 `mem_map` 里空闲页数量、观察 fork 前后页表项的变化。
- 这一实验需要你在启动参数里打开更详细的输出，并理解 `mm/memory.c` 里的 `get_free_page` 与 `do_wp_page`。

### 17.9 🔧 2026 年的等价升级路径

| 老实验 | 现代替代 |
| --- | --- |
| Bochs + 1.44MB 软盘 | `qemu/qemu`（≈**13.8k★**）的 `qemu-system-i386/-x86_64`；`-drive if=floppy` 或 `-hda` + `-boot c` |
| 自己写最小 rootfs | `mirror/busybox`（≈**2.2k★**）提供 `sh/ls/cat/ps`；`buildroot/buildroot`（≈**3.7k★**）一键生成 rootfs 的内核镜像 |
| 用 `printk` 调试 | `ftrace`（`tracefs`）、`perf`、`crash`、`kgdb`：静态插桩 → 动态插桩 |
| 在 0.11 上追系统调用 | `strace`/`ltrace` 追用户态；**eBPF**（`iovisor/bcc` ≈**22.7k★**，`libbpf`）可无侵入地挂到内核的 tracepoint/kprobe 上 |
| 看 CPU 火焰图 | `brendangregg/FlameGraph`（≈**19.8k★**）与 `perf script`，比在 0.11 上插 `printk` 高效多个数量级 |
| 「改内核 → 重启 → 看效果」的闭环 | 依然成立，且可用 `torvalds/linux`（≈**250k★**）的 git 历史与 LKML 邮件列表、`get_maintainer.pl` 找到正确的 reviewer |

## 版本演进

| 时间 | 主题 | 变化 |
| --- | --- | --- |
| 1994 | 原书实验体系 | 基于真机（含软驱、真 VGA），围绕 0.11 的六个实验 |
| 2006 | 本书出版时 | 建议改用 Bochs；软盘镜像与 `-fda` 参数成为标准做法 |
| 2010 前后 | QEMU 流行 | 替代 Bochs：启动快、可 `-snapshot`、`-nographic` 直连终端 |
| 2013 | 动态追踪成熟 | SystemTap/eBPF/perf：`printk` 之外的动态观测手段 |
| 2020 前后 | 模拟器语义化 | VMX/VT-x 嵌套、 perf 事件、PMU 在虚拟机中的可用性改善 |
| 2023–2026 | 老代码的可及性 | 用 git tag `v0.11` 直接获取原始源码；社区维护的编译补丁让 GCC/Clang 新版本可编译 |

## 近年研究与工业界开源实践（2015–2026）

- **近年研究**：模拟器方向集中在 **TCG 的多线程/多核重编译（MTTCG）**、**硬件辅助的虚拟化（KVM/VMX）**、**可重现实验（快照、确定性回放）**，以及 **将操作系统课程实验容器化**；追踪方向集中在 **eBPF 的安全性与验证器**、**PMU 在云环境的可用性与性能计数**、**内核追踪框架与 RCU 的交互**。
- **工业界开源**（star 数 2026-09 实测）：
  - `qemu/qemu`（≈**13.8k★**）：默认模拟器，几乎每一个内核开发者都用它跑过一次内核；`qemu-system-i386` 可精确复现 0.11 需要的 386 语义。
  - `buildroot/buildroot`（≈**3.7k★**）：为实验准备最小 rootfs（busybox + init），把「跑到 shell」这件事压缩成一条 `make` 。
  - `mirror/busybox`（≈**2.2k★**）：单个二进制提供 `sh/ls/cat/ps/mkfs` 等，是 0.11 实验里 `/bin/sh` 的现代等价物。
  - `iovisor/bcc`（≈**22.7k★**）：eBPF 工具集，可以在不重启内核的前提下观测块 I/O、调度延迟、页错误等（这些正是原书实验想让人「看见」的东西）。
  - `brendangregg/FlameGraph`（≈**19.8k★**）：`perf` 数据的可视化，实验报告从「截图终端」升级为火焰图。
  - `torvalds/linux`（≈**250k★**）：用 `git checkout v0.11` 拿原始源码、`git log --oneline v0.11..v2.6` 看二十年演进，是「实验后继续追进现代内核」的自然路径。

## 常见误区与本书需修正之处

| # | 误区 / 本书局限 | 2026 年的修正与补充 |
| --- | --- | --- |
| 1 | 「必须有一台能跑 80386 的真机」 | 真机早已绝迹；QEMU/Bochs 完全够用，且可 `-snapshot`、`-nographic` |
| 2 | 「必须用 GCC 2.95/3.2 才能编」 | 老版本 GCC 仍可装（或用社区补丁集）；现代工具链编 0.11 会遇到内联汇编与属性问题 |
| 3 | 「实验只能靠 `printk`」 | 🔧 有 `ftrace`、`perf`、`bpftrace`、`SystemTap`、`kprobe`；`printk` 依然是第一手段，但不必是唯一 |
| 4 | 「0.11 的实验只对 0.11 有意义」 | 实验训练的是「改 → 构建 → 启动 → 观察」闭环；同样的技能可直接迁移到现代内核的模块开发 |
| 5 | 「1.44MB 软盘是唯一载体」 | 可用 `-hda` 挂 IDE 镜像、可把根文件系统放在 `-hdb`，甚至用 `-kernel` + `-initrd` 直接引导 |
| 6 | 「编译失败就没办法」 | 先试着 `make V=1` 看真实命令、再用 `git bisect` 思想定位；多数失败是工具链差异而非代码错误 |
| 7 | 原书实验的「可选题目」范围 | 具体实验要求以原书为准；本笔记只补充环境、工具与观测手段，不替代原题 |
| 8 | 「跑 0.11 就是学内核」 | 0.11 只是**最小样本**；真正理解现代内核需要在 `torvalds/linux` 上读 `mm/`、`fs/`、`kernel/sched/` 并与 LKML 对照 |
