# 第 2 章 微型计算机组成结构

> **本章地图**：PC 总线结构与 I/O 端口编址（8086 的 64 KB I/O 空间）→ 接口访问控制（程序查询 / 中断 / DMA）→ 主存储器（RAM 容量与地址线约束）→ BIOS（INT 中断服务、实模式下的启动与引导）→ CMOS（64 字节实时时钟/配置信息，由 `CMOS.Setup` 暴露）→ 控制卡（8259A 中断控制器、8237 DMA 控制器、8253 定时计数器、键盘、串行、显示、软/硬盘控制器）。
>
> 一句话结论：**这一章是理解 `06-引导启动程序.md` 里 `int 0x13`、`cli/sti`、以及 `07` 里 `time_init()` 的唯一前提。**

## 核心精讲

### 2.2.1 I/O 端口：x86 的特殊空间

x86 用**独立编址（isolated I/O）**：`in/out` 走 IOPL 允许的地址空间，与内存地址空间不重叠。这是本书反复出现的 `outb_p()/inb_p()` 的根据。

```asm
; 教学示意，不代表可编译运行
; 从 0x3F8（COM1 数据寄存器）读一个字节
mov     dx, 0x3F8
in      al, dx          ; 读入 al
; 写 CRT 控制寄存器（0x3B4）再写数据（0x3B5）
mov     dx, 0x3B4
out     dx, al
inc     dx
out     dx, al
```

> 精华点在 `io.h` 里的 `outb_p/inb_p`：它们在 `outb` 之后插一条 `jmp 1f` 之类的**延时/扇出指令**，因为 8086 的外设比 CPU 慢，某些控制寄存器必须等待。

### 2.2.2 三种访问控制方式的取舍

| 方式 | 硬件成本 | CPU 占用 | 发生时机 | 内核对应 |
| --- | --- | --- | --- | --- |
| 程序查询（polling） | 最低 | 高（死等） | 软件主动 | `floppy.c` 早期、部分 console 初始化 |
| 中断驱动 | 中 | 低 | 硬件主动 | `request_irq()`、`do_IRQ` |
| DMA | 高（需 DMAC） | 最低 | 硬件主动 + 完成中断 | `hd.c`/`floppy.c` 的 `do_hd_request` |

### 2.3.2 BIOS 的启动角色

BIOS 在实模式下准备中断向量表（IVT）并做自检，然后把**引导扇区**加载到 `0x7C00`：

```asm
; 教学示意，不代表可编译运行：bootsect 用 BIOS 读盘（大致形态）
;   ds:si -> es:di，扇区数 cx，驱动号 dx
mov     cx, 0x0001        ; 扇区 1
mov     dx, 0x0000        ; 驱动器 0（软 A:）
mov     bx, 0x0200        ; ES:BX 目标缓冲
mov     ax, 0x0201        ; AH=02（读盘）, AL=1（1 个扇区）
int     0x13              ; BIOS 磁盘服务
```

> 关键认知：**内核镜像不是「被加载程序」加载的，而是被 BIOS 用 `int 0x13` 一块一块读进内存的**。所以 0.11 的 `system` 段必须放在 `0x10000` 之上的连续区域（`0x10000–0x8FFFF` 是常规内存之上的扩展区），这正是 `06` 章「把 system 移到 0x0000」的原因。

### 2.4.1 8259A 与中断向量分配

0.11/0.12 的 IDT 布局（下详于 `04-80x86保护模式及其编程.md`）：

```
IDT 0x00–0x1F   : CPU 异常（除零、调试、NMI、断点、GP、PF…）
IDT 0x20–0x2F   : 8259A 的 16 个 IRQ（0x20=定时器, 0x21=键盘, 0x24=软盘, 0x2E=IDE…）
IDT 0x30–0x3F   : 系统调用门（int 0x80）
IDT 0x80 起     : 一些仿真异常
```

```c
/* 教学示意，不代表可编译运行：8259 掩蔽字的典型编程顺序 */
#define PIC_MASTER_IMR  0x21
#define PIC_MASTER_ICW1 0x20

outb(PIC_MASTER_ICW1, 0x11);   /* 边沿触发、级联、要 IVR */
outb(PIC_MASTER_IMR + 1, 0x20);/* 主片起始向量 = 0x20 */
```

> 注意：0.11 里用的是**固定向量**方式的简化实现（直接 `outb` 到 `0x21` 掩蔽 IRQ），现代内核则依赖 `ioapic` 可编程重定向（见「版本演进」）。

### 2.3.3 CMOS 与时间

```c
/* 教学示意，不代表可编译运行：从 CMOS 读年月日时间 */
#define CMOS_PORT 0x70        /* 地址端口 */
#define CMOS_DATA 0x71        /* 数据端口 */

static unsigned char cmos_read(unsigned char addr)
{
    outb(CMOS_PORT, addr);
    return inb(CMOS_DATA);
}

/* 0.11 的 time_init() 大致如此：读 CMOS 的 0x00(秒) 0x02(分) 0x04(时)
   0x06(星期) 0x07(日) 0x08(月) 0x09(年)，拼出 xtime.tv_sec */
```

> 这正是 `07-初始化程序.md` 里 `time_init()` 与 `08` 里 `do_timer()` 用到的底层支持。

### 2.1 微型计算机组成原理：内核看到的「三件套」

从内核视角看，一台 PC 只有三方需要打交道：

```text
; 教学示意：内核与硬件的三类接触面
;   CPU ──► 内存（RAM）：通过分段/分页，地址空间由内核软件定义
;   CPU ──► I/O 端口 ：in/out，64 KB 独立空间（x86 特色）
;   CPU ◄── 中断     ：INTR 引脚 → 8259A → 中断控制器 → IDT
```

| 接触面 | 内核里的入口 | 对应本章节 |
| --- | --- | --- |
| 内存 | `memory_end`、`buffer_init()` 的布局 | 2.3.1 |
| I/O 端口 | `inb/outb` 与 `request_region` | 2.2.1 |
| 中断 | `do_IRQ` / `do_timer` | 2.4.1、2.4.3 |

### 2.2.2 三种方式的代价量化（为什么内核最终都选中断）

| 场景 | 轮询的代价 | 中断的代价 | DMA 的代价 |
| --- | --- | --- | --- |
| 每秒 100 次外部事件 | CPU 空转 100% | 每次约几百纳秒 | 加一次 DMAC 编程 |
| 大块数据传输（软盘 512 B） | 大量等待指令 | 中断频度高，开销显著 | 最优 |
| 键鼠输入 | 用户感觉卡顿 | 标准做法 | 不适用 |
| 结论 | 只在硬件极慢或初始化阶段用 | 内核中断驱动的默认 | 块设备的既定方案 |

> 这就是为什么 0.11 的 `floppy.c` 同时存在三种痕迹：`request_irq()` 注册中断，但传输过程仍靠轮询读取状态寄存器——因为 386 上的 DMAC  usability 有限，且软盘控制器要求「读状态 → 决定下一步」的紧密时序。

## 版本演进

| 年份 | 硬件/内核变化 | 对本章内容的冲击 |
| --- | --- | --- |
| 1981 | PC/XT，8088，10 MB 硬盘 | 本书的硬件基线 |
| 1985 | PS/2，80286，BIOS 扩展 | 保护模式与 AT 总线 |
| 1992 | Linux 0.12 目标环境：386 + 8–16 MB | `memory_end` 静态编译进内核 |
| 2001 | 2.4 起支持 ACPI、`apic` 通用中断层 | 🔧 8259A 只是「legacy 中断」之一 |
| 2008 | HPET 标准化 | 🔧 定时器不再只有 8253 PIT |
| 2010+ | x86 普遍无 PS/2 键盘、无软驱 | 🔧 `floppy.c`/`hd.c` 已无人维护 |
| 2016+ | ARM64 服务器与虚拟平台 | 🔧 ARM 用 GIC，本章整章只在 x86 成立 |
| 2020+ | `iomem` 驱动模型、devres、Linux 6.x 移除部分 legacy ISA 驱动 | 🔧 直接访问端口的写法被 `devm_` 系列取代 |

## 近年研究与工业界开源实践（2015–2026）

- **I/O 模型并未消失，只是被抽象了**：现代内核用 `request_region()`、`devm_ioremap()`、MMIO 替代裸 `in/out`，但 x86 的端口空间仍是驱动兼容层的一部分。
- **真实仓储与工具**：`qemu/qemu`（**13761★**）保留了最完整的 legacy x86 设备模拟，`hw/ide/`、`hw/block/floppy.c`、`hw/isa/` 就是本章所有芯片的软件等价物——**读 QEMU 源码比读 20 年前的 datasheet 更快**。
- **固件生态迁移**：Linux 6.x 起对 legacy BIOS 依赖减弱，UEFI + `efistub` 成为主线；`systemd/systemd`（**16746★**）的 `bootctl` 与 `u-boot/u-boot`（**5253★**）承担了现代引导入口。
- **教学设备模拟器**：`brendangregg/FlameGraph` 不相关，但同作者的 perf 生态与 `dreamportdev/Osdev-Notes`（**1158★**）提供了「用 QEMU + GDB 调试自写内核」的流程，正好替代本书第 17 章的实验环境。

## 常见误区与本书需修正之处

| # | 说法/写法 | 修正与补充 |
| --- | --- | --- |
| 1 | 「I/O 端口和内存统一编址」 | x86 是**独立编址**，`in/out` 与 `mov` 走不同空间；只有 ARM/RISC-V 常见统一编址 |
| 2 | 「8259A 就是全部中断」 | 🔧 现代 x86 主流是 **APIC/IOAPIC + MSI**，8259A 仅 legacy 兼容路径 |
| 3 | 「PIT 的 100 Hz 是硬件事实」 | 🔧 `CONFIG_HZ` 可配（250/1000），且 HPET/TSC 与现代 tickless 已让固定节拍过时 |
| 4 | 「BIOS 还在照老样子工作」 | 🔧 服务器与新型机器基本 UEFI；bootloader 走 `EFI_BOOT`/multiboot |
| 5 | 「CMOS 只有 64 字节」 | 准确说法：RTC 的 64 字节 CMOS RAM，其中仅约 10 字节给终端用户，`0x0D`/`0x0F` 等还含状态位 |
| 6 | 🔧 「DMA 现在也该学」 | 许多 0.12 驱动（如 `hd.c`）的 DMA 代码在现代内核里被 `blk-mq` + `scsi-mq` 取代，学习价值下降，可读性仍高 |
| 7 | 🔧 缺现代内容 | 建议补：`Documentation/driver-api/`、`devm_` 资源模型、`irq-domain`/`irqchip` 抽象 |
| 8 | 「软件驱动能直接使用硬件控制权」 | 🔧 内核需申请资源：`request_region()`/`request_irq()`/`request_mem_region()`，且现代内核有 devm 自动释放 |
| 9 | 「语言有点罗嗦」（原书页面评语，本章尤其明显） | 硬件细节建议直接查 datasheet 与 QEMU 源码，本书的文字描述可当索引用 |
| 10 | 🔧 缺现代中断体系 | 建议补：`Documentation/driver-api/irq/`（irq-domain、irqchip、MSI）、`struct device` 与 PNP/ACPI 资源获取 |
