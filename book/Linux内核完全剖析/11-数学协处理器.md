# 第 11 章 数学协处理器

> **本章地图**：`kernel/math_emulate.c` 的由来（80387 缺失/故障）→ `math_emulate()` 如何拦截协处理器指令 → **8087 栈式寄存器模型**（`TOP` + 8 个 80 位寄存器）与状态字 → 浮点异常通过 `SIGFPE` 上报用户进程 → `init_math()` 与 CR0 的 `EM`/`MP` 位。核心结论：这是一段**为兼容极早期 x86 机器而存在的软件层**，它定义了内核「**在中断/异常上下文中代表用户进程执行指令**」这一范式，是理解现代 FPU 状态保存的活化石。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 11.1 为什么需要仿真 | 部分 x86 机器无 387、或 CR0.EM=1 时 387 指令会 `#MF` | 内核必须能**代替用户进程执行浮点指令** |
| 11.2 `math_emulate()` 入口 | 缺协处理器中断 → `do_exception` → `math_emulate()` | 内核在**异常上下文**里解释指令，再向用户进程报 `SIGFPE` |
| 11.3 8087 的状态与寄存器 | `SW`（状态字）、`CW`（控制字）、`TOP` 与 8 层寄存器栈 | 浮点寄存器是**栈**不是数组，`TOP` 决定 `st(i)` 实际指向 |
| 11.4 `MAX_INT_REG` 与指令译码 | `struct i387_soft_struct`、操作码表、`fld/fstp/fadd` 等仿真 | 仿真只覆盖常用子集，**未实现的指令一律 `SIGFPE`** |
| 11.5 异常与 `SIGFPE` | 无效操作、除零、溢出/下溢、精度错误 | 0.11 只做「结果取绝对值最大」的粗糙近似，不做可重现的精确舍入 |
| 11.6 `init_math()` 与 CR0 | `CR0_EM`（仿真）、`CR0_MP`（监控协处理器） | 复位时禁用协处理器，由软件接管 |
| 11.7 仿真效率与历史 | 逐指令解释、每条 `inb/outb` 读状态、无 SIMD 概念 | 🔧 这段代码在 2.4/2.6 仍存在，直到 SSE 时代才真正失去意义 |
| 11.8 从 x87 到现代 FPU | XSAVE、XCR0、xsaveopt、`kernel_fpu_begin/end` | 🔧 核心问题从「要不要仿真」变成「**何时保存/恢复哪些状态**」 |

## 核心精讲

> 以下均为**教学示意，不代表可编译运行**。

### 11.1 触发路径：一次浮点指令如何进内核

```c
/* kernel/math_emulate.c —— 教学示意，不代表可编译运行 */
asmlinkage void math_emulate(long ___eax, long ___edx)
{
    ...
    /* 这里模拟的 387 状态 */
    struct i387_soft_struct *math_state = &current->thread.t_regs.fp_soft;
    ...
    switch (opcode) {                    /* 首字节 */
    case 0xd8:                           /* ESC 0 = 浮点指令组 0 */
        ...
    case 0xdb:  case 0xdc: case 0xdd:
    case 0xde:  case 0xdf:
        ...
    }
    ...
}
```

- x87 的浮点指令全部以 **ESC（0xD8~0xDF）** 开头。CPU 遇到 ESC 且 `CR0.EM=1` 或有协处理器缺失时，会抛出**协处理器缺失异常（#MF）**，内核据此进入仿真。
- 也就是说：**不是用户进程调用什么「浮点库」，而是用户进程执行了 `fldz` 这类指令本身**——内核通过异常拦截取指、译码、模拟。
- 这也是 x87 全部指令都是「**0xD8~0xDF + ModRM**」这种奇怪编码的原因：老的 8087 通过 ESC 转义让协处理器自己译码。

### 11.2 软件状态下的 387（`struct i387_soft_struct`）

```c
/* include/linux/sched.h（0.11）—— 教学示意，不代表可编译运行 */
typedef struct {
    long cwd;      /* 控制字 Control Word   */
    long swd;      /* 状态字 Status Word    */
    long ftw;      /* 标签字 Tag Word       */
    long fip;      /* 指令指针              */
    long fcs;      /* 代码段选择子          */
    long fdp;      /* 数据指针              */
    long fds;      /* 数据段选择子          */
    long st_space[64];  /* 8 个 80 位扩展精度寄存器（各 8 字节） */
} i387_soft_struct;
```

三个字段值得单独记住：

- `swd` 的 **位 8–10 是 `TOP`**，这是 8087 状态字里最反直觉的部分：浮点「寄存器」只有 8 个，但指令里写的 `st(0) ~ st(7)` 是**相对栈顶的偏移**。例如 `fadd st(1)` 实际操作的物理寄存器是 `(TOP+1) mod 8`。
- `ftw`（Tag Word）用 2 比特/寄存器标记该栈项是否空闲/为零/特殊——这正是「为何某些操作会产生无效操作异常」的判据。
- 🔧 现代 x86 的 XSAVE（`XCR0` 位）把**用户态与内核态的 FP 状态彻底分离**：`FPREG_X87 / SSE / AVX(256) / MPK / PKRU / ...` 各自独立保存，避免「保存了用不到的 AVX-512 状态」带来的巨大开销（这就是 `xsaveopt` 的动机）。

### 11.3 指令仿真片段

```c
/* kernel/math_emulate.c —— 教学示意，不代表可编译运行 */
/* fld st(i) —— 装入 */
else if (opcode == 0xdd && modrm_mod == 0xb0) {   /* 0xDD /4 = fld st(i) */
    unsigned long *st = &math_state->st_space[...];
    ...
    /* fstp st(i) —— 存回 */
}
```

- `math_emulate` 的译码逻辑基本是「**首字节 → ModRM → 寄存器字段（reg field）**」的二维开关表，与今天 CPU 里的微码 ROM 功能类似，只是慢了几个数量级。
- 每条指令仿真完还要**根据结果更新 `swd` 的异常位**——这一步让上层以为真的协处理器在工作。

### 11.4 从异常到 `SIGFPE`

```c
/* kernel/math_emulate.c —— 教学示意，不代表可编译运行 */
static void math_emulate_queue_exception(...)
{
    /* 0.11 的做法：算出结果后，直接给 current 记一个 SIGFPE */
    current->signal |= (1 << (SIGFPE - 1));
}
```

- 关键设计：**仿真不是给内核自己用的，是给用户进程用的**。内核必须在异常处理里判断「`#MF` 来自用户进程」，处理完后返回用户空间时**从异常返回指令处重新执行**（`iret` + 恢复 `eip`），让用户的 `fldz` 指令「假装执行成功」。
- 硬件异常 → 内核替代执行 → 向进程发信号，这一整套流程是后来**系统调用内嵌指令模拟**（如 `sysenter` 后的指令重启）、**`uprobes` 的 xol（execute out of line）**、以及今天 **「指令级仿真 / 硬件断点改写」** 的原型。

### 11.5 `init_math()` 与 CR0

```c
/* kernel/sched.c —— 教学示意，不代表可编译运行 */
void init_math(void)
{
    __asm__("fninit");                 /* 清空 FPU 状态 */
    if (cpu_has_fpu) { ... }          /* 若 CPU 有硬件则打开 CR0.EM / MP */
    else
        math_state...                  /* 否则用软件仿真 */
}
```

- `CR0_EM`（EMulation bit）：置位则所有协处理器指令触发 #MF，由软件接管；
- `CR0_MP`（Monitor Coprocessor bit）：配合 `CR0_NE`（Numeric Error）让 387 的**带内错误报告**生效。
- 🔧 现代内核启动时用 `boot_cpu_has(X86_FEATURE_FPU)` 等特性位判断能力，FPU 初始化在 `arch/x86/kernel/fpu/`，早期 `init_math` 那样直接 `outb` 改 CR0 的做法早已消失。

### 11.6 指令译码：ESC 转义 + ModRM 的 reg 字段

x87 的每条指令都由「**ESC 字节（0xD8–0xDF）** + ModRM」构成，制定位在哪一组里靠的是 ModRM 的 **reg 字段**：

```text
指令编码示意（不是可运行代码，仅表达编码结构）
  0xD8 ~ 0xDF   ESC（4 位组）
  0x00 ~ 0xBD   主操作码
  0xC0 ~ 0xFF   无内存操作数的浮点指令（st(i) 直接编码在 ModRM 的 rm 字段）
  ModRM:  mod=11 → 寄存器操作数，reg 字段决定指令语义，rm 字段决定 st(i) 编号
```

- 所以 `math_emulate` 的分支结构是「**先按 ESC 分组，再看 ModRM.reg**」的两级 switch——今天 CPU 里「微码 ROM 的 opcode 译码」在这一层上逻辑完全一致，只是快了几万倍。
- 判别「这次是读还是写」靠后缀：`fild`/`fistp` 这类「以 st 为源/目的」的指令必须严格区分操作数方向，0.11 的实现里到处是 `if (opcode == 0xdb && ...)` 这类判断。

### 11.7 为什么这段「死代码」仍值得逐行读

- 它演示了**内核如何在异常上下文中代表用户进程执行指令并修改返回地址**；
- 它演示了 **IEEE 754 的异常分类如何被映射成进程信号**；
- 它也解释了「浮点ABI」与「寄存器栈」的耦合：x87 的 8 个寄存器 + `TOP` 字段，让「计算过程」变成了一个**栈上的有向图**，这正是后来 SSE 用纯寄存器模型替代它的原因。

## 版本演进

| 时间 | 事件 |
| --- | --- |
| 1980 | Intel 8087 推出，与 8086 配套的浮点协处理器 |
| 1982/1986 | 80287 / 80387，80 位扩展精度成为事实标准 |
| 1990 前后 | 386DX 机型大量不带 387 → Linux 0.x 的 `math_emulate.c` 出生 |
| 1992–2000 | Linux 0.x～2.x 均保留协处理器仿真；2.0 时代已极少被触发 |
| 1999 | Intel 发布 **SSE**（MMX 之后的第一条 SIMD 扩展，与 x87 共用状态但独立异常处理） |
| 2008 | **AVX**（VEX 编码，256 位），逐步与 x87 三分天下 |
| 2013 | **AVX-512**，512 位向量 + 掩码，保存状态开销剧增 |
| 2011 | **XSAVE** 进入 x86，替代 `fxsave/fxrstor` 的固定格式保存 |
| 2016 前后 | **kernel_fpu_begin/end** 成熟：内核自身日益依赖 SIMD 与向量化加密（SHA-NI、AES-NI） |
| 2018 | x86 上 `math_emulate` 彻底退出历史舞台；FPU 代码集中在 `arch/x86/kernel/fpu/` |
| 2021–2023 | 6.x 内核推行 `fpu_state` 抽象与 per-cpu 惰性恢复，减少保存开销；XCR0 位图随新扩展继续增长 |

## 近年研究与工业界开源实践（2015–2026）

- **近年研究**：浮点侧的研究早已不在 CPU 仿真，而在 **FPU 状态切换开销**（XSAVE 的按需保存、per-task 惰性恢复）、**内核态使用 SIMD 的安全性**（禁止在 `atomic` 上下文/中断里用 FPU，避免栈溢出）、**可复现浮点（REPL/FMA 收缩）**以及 **异构加速器（GPU/NPU）与 x87/SIMD 的精度一致性**。
- **工业界开源**（star 数 2026-09 实测）：
  - `torvalds/linux`（≈**250k★**）：现代 FPU 代码在 `arch/x86/kernel/fpu/`，`kernel_fpu_begin/end` 声明于 `arch/x86/include/asm/fpu/api.h`；内核加密库使用 AVX2/SHA-NI（`crypto/sha256_ssse3` 等），这正是「内核也要开 FPU」的动机。
  - `llvm/llvm-project`（≈**40.7k★**）：`-march=x86-64-v3` 一类的「微架构级别」指令集分层，与内核 XSAVE 的 XCR0 位图思路同源。
  - `qemu/qemu`（≈**13.8k★**）：`qemu-x86_64 -cpu q35 -machine accel:tcg` 下可以模拟无 FPU 的 CPU，仍能复现书里的 `#MF` 异常场景。
  - `gcc-mirror/gcc`（≈**11.3k★**）：`math_emulate` 依赖 gcc 的 `long double` 80 位扩展与内联汇编，是「编译器行为决定内核实现」的典型。

## 常见误区与本书需修正之处

| # | 误区 / 本书局限 | 2026 年的修正与补充 |
| --- | --- | --- |
| 1 | 「浮点运算由 CPU 自动完成」 | 🔧 是否直接执行取决于 `CR0.EM`、CPU 是否真有 FPU；历史上有整整一个时代的机器需要内核仿真 |
| 2 | 「8 个浮点寄存器是数组下标」 | 始终是**栈**：状态字 `TOP` 决定物理映射，`st(i) = (TOP+i) mod 8` |
| 3 | 「`math_emulate` 精确实现了 IEEE 754」 | 0.11 的近似只在多数情况下「像真的」，精度异常与舍入模式基本不可复现 |
| 4 | 「仿真是内核为自己算数学用的」 | 恰恰相反：仿真是**为用户进程的指令**服务，内核只是代劳 |
| 5 | 「x87 至今仍是浮点主力」 | 🔧 x87 已成历史遗迹。通用浮点由 SSE（标量/128 位）→ AVX/AVX-512（256/512 位）接棒；x87 只剩老二进制兼容 |
| 6 | 「保存浮点状态就是 `fxsave` 一下」 | 🔧 现代是 **XSAVE + XCR0 位掩码 + `xsaveopt`**，只保存真正用到的组件；内核态还有 `kernel_fpu_begin/end` 约定（含 `in_interrupt` 时的 `__kernel_fpu_begin` 禁用路径） |
| 7 | 「中断上下文可以随便用浮点」 | 🔧 内核中**默认禁止**在中断/原子上下文使用 FPU/SIMD；必须显式 `kernel_fpu_begin()`/`kernel_fpu_end()`（它们若在原子上下文被调用会拒绝或直接崩溃） |
