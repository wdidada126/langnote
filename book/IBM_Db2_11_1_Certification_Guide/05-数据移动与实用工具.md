# 05 · 数据移动与实用工具（对齐考试域：Working with Data / Utilities ⚠️ 推定）

> 章名 ⚠️ 推定（主题重构，见 00 降级声明）。DB2 命令行为一律 ⚠️ 转述自 IBM 11.1 公开文档与社区笔记；本机不可装 DB2，无 🔧 实测组（SQL 标准对照组集中在 04/07 章）。

## 一、章定位

"三件套+两打包件"的配对与后果题：EXPORT/IMPORT/LOAD 各自的方向、格式、是否走 SQL 引擎、对日志与完整性的影响；db2move/db2look 的迁移脚手架角色。考试常以"执行 X 后表空间为何挂起"形式考 LOAD 的非常规路径。

## 二、EXPORT / IMPORT / LOAD 总对比（⚠️ 转述）

| 维度 | EXPORT | IMPORT | LOAD |
|---|---|---|---|
| 方向 | 库→文件 | 文件→库 | 文件→库 |
| 引擎路径 | 读，产出 IXF 等 | 走 SQL 引擎 INSERT | 旁路引擎直写页 |
| 约束/触发器 | 不适用 | 全生效 | 阶段化（可 DEFERRED） |
| 日志 | 读锁类影响 | 全量记日志 | 可少记/不记（COPY/NONRECOVERABLE） |
| 统计信息 | — | 装载后易失→须 RUNSTATS | 同左 |
| 速度量级 | 中 | 慢 | 快（并行/分区表友好） |
| 风险 | 低 | 低 | 挂起态/完整性 pending |

- 格式：IXF（跨平台首选）、DEL/CWS（人读与再加工）、WS?（冷门）；字符集与 DECIMAL POINT 参数是"导入数字变形"事故源 ⚠️。

## 三、IMPORT 细节（⚠️ 转述）

- 语法面：`db2 import from data.ixf of ixf replace/insert/insert_update into t`；INSERT_UPDATE=存在则更、不存在则插（upsert 的文件版——04 章 🔧B MERGE/UPSERT 家族考点的 utility 化身）。
- commitcount 与消息文件；IMPORT 完成即约束态，可恢复性不受影响（循环日志库也可用）。
- 统计丢失问题：大批 IMPORT 后 RUNSTATS 必跑（10 章回收）；考试问"查询变慢先查什么"。

## 四、LOAD 四阶段与后果（高频）

1. 阶段链：LOAD（解析+装行）→ BUILD（生成/暂存索引数据）→ INDEX（构索引）→ CLEAN（清暂存）；`ANALYZE? DISK?` 附加选项 ⚠️ 冷门不背。
2. 模式：INSERT/REPLACE/REPLACE_CREATE/MODIFIED?；`NONRECOVERABLE` 令目标表空间进备份挂起（必须补一次表空间级备份否则恢复被拒）——"为什么备份策略突然报错"类题眼（08 章联动）。
3. 完整性：装载违例行进 dump 文件（`DUMPFILE ... LIMIT n`）；超 LIMIT 整个装载失败回滚；`SET INTEGRITY` 处理约束挂起的表。
4. 并行与分区表：多智能体、分区表分片并行装是 LOAD 的性能卖点；`CPU_PARALLELISM/READ_BUFSIZE` 参数谱 ⚠️ 配对级记忆。
5. 远程装载与 `REMOTE`/命令行一致性细节不展开（⚠️）。

## 五、db2move / db2look 脚手架（⚠️ 转述）

- db2move：EXPORT/IMPORT/LOAD 三动作 × 全库表清单，生成 ACTION/MODES/DATA 文件族；跨库搬运"表+数据"的批处理位；`-l 路径 -u 用户 -p 密码` 形态。
- db2look：抽 DDL（-e）、统计（-m）、对象定义（-d）与授权语句，把"结构+RUNSTATS 脚本"打包成可重建库的文本；迁移三件套=结构（db2look -e）+统计（-m）+数据（db2move）。
- 与导出文件的关系：db2look 不搬数据、db2move 不搬索引定义（依赖目标库先建表）——顺序题。
- 冷门但考：`db2dart` 库损坏诊断（页级体检），与 ADMIN_ 前缀系列函数（如表空间/容器操作 ⚠️）同属"工具谱"域。

## 六、LOAD/IMPORT 与日志恢复的联动（考点链）

- 循环日志库：IMPORT 安全；LOAD 因少记日志存在恢复断裂风险（非可恢复装载后只能靠新备份恢复 ⚠️）。
- 归档日志库：LOAD 的 COPY YES（复制数据到备份）或 COPY NO+及时表空间备份，保住时间点恢复链（08 章主线）。
- 典型排错题：`SQL0668N? reason 1/3/7`（表挂起类，错误号示意 ⚠️）→ 按原因码分流：recover/ set integrity/ reorg 三类处方（10 章回收）。

## 七、常见陷阱（例题库向）

1. DEL 文件用默认分隔符导入含逗号数据——列错位；改修饰符（codepage/decpt/delim）组合。
2. LOAD 完不 RUNSTATS，优化器按空表出计划——性能断崖题的标准答案之一。
3. NONRECOVERABLE 后忘记补备份，恢复演练时全链失败（08 章联动）。
4. 大装载期间触发锁升级/日志满——预扩容参数与窗口规划（07 章）。
5. 把 IMPORT 当 LOAD 用做千万行迁移——性能与索引重建时机全错配。

## 八、考点自查清单

- 默写三件套方向×引擎×日志×风险四列对比。
- LOAD 四阶段名+各阶段失败后果（哪个阶段失败进 pending）。
- db2look/db2move 在"整库搬迁"里的分工顺序。
- NONRECOVERABLE 的两步补救（表空间备份+恢复策略确认）。

## 九·五、自测题（本目录自编，非原书题 ⚠️）

**Q1** 排错：IMPORT 千万行成功，次日报表 SQL 从索引扫描退化为全表扫描，第一步？
**答**：RUNSTATS（IMPORT 清统计+优化器按失真基数出计划，05→10 章联动；不是先重建索引）。

**Q2** 配对：把"走 SQL 引擎/旁路引擎""受约束/可延迟""全量日志/可少记""挂起风险低/高"四对特征分给 IMPORT 与 LOAD。
**答**：前四项均 IMPORT→LOAD 迁移方向（第二节表；LOAD 的约束可 DEFERRED 态收进 dump/完整性挂起 ⚠️）。

**Q3** 时序题：LOAD 四阶段名序+各一次典型失败后果。
**答**：LOAD（行/格式错→dump 超限整体失败）→BUILD（暂存构建异常→回滚）→INDEX（索引构建失败→表进需重建/挂起态）→CLEAN（收尾失败→完整性 pending 需 SET INTEGRITY）（第四节；阶段-后果配对为高频题 ⚠️ 口径转述）。

**Q4** 场景：整库从 A 实例迁 B 实例（同版本），三件套顺序。
**答**：目标库先建结构 `db2look -e`（+授权）→ 统计脚本 `db2look -m` 或到位后 RUNSTATS → 数据 `db2move load`（或 export+load），最后校验行数/统计/计划（第五节脚手架分工；顺序题）。

**Q5** 判断："db2move 能顺带把索引与触发器定义一起搬走。"
**答**：错。db2move 只管数据（+表清单），结构靠 db2look——"搬数据不搬定义"是两件套的分界（第五节）。

## 九·七、本域场景表达两句话

1. 速度句："千万行进库只有两条正路：LOAD 换速度但买'挂起+统计失效+恢复链断裂'三张账单；IMPORT 走引擎付慢的学费但账目干净——先问恢复窗口再选工具。"
2. 迁移句："结构靠 look、数据靠 move、统计靠 runstats——三句话覆盖 90% 的同构搬迁题。"

## 九·九、本域一句话索引（复述练习用）

- 三件套：EXPORT 出、IMPORT 慢而干净、LOAD 快而欠账（日志/统计/挂起三笔）。
- 格式：IXF 跨平台、DEL 人读；codepage/decpt 修饰符管字符与小数点事故。
- LOAD 四阶段：Load→Build→Index→Clean；失败阶段决定挂起形态。
- 两打包件：db2look 搬定义与统计脚本、db2move 搬数据，都不越界。
- 决策一问：恢复窗口能否容忍补备份——能则 LOAD，不能则 IMPORT 或 COPY YES。

## 核心概念速览（中英对照）

- **EXPORT** — 导出：库→IXF/DEL 文件
- **IMPORT** — 导入：文件→库，走 SQL 引擎、全约束全日志
- **LOAD** — 装载：旁路引擎高速装数据，四阶段（Load/Build/Index/Clean）
- **IXF/DEL** — 集成交换格式/定界文本：跨平台与可读性两路线
- **INSERT_UPDATE** — IMPORT 模式：存在则改（文件版 upsert）
- **NONRECOVERABLE** — LOAD 选项：不留备份副本→表空间备份挂起
- **DUMPFILE** — 违例行文件：装载约束违例的出口
- **SET INTEGRITY** — 完整性重置：约束挂起表的恢复动作
- **db2move** — 批量数据搬运器：全库 EXPORT/LOAD 脚手架
- **db2look** — DDL 抽取器：结构+统计+授权文本化
- **db2dart** — 库体检工具：页级损坏诊断
- **pending state** — 挂起态：表/表空间被工具流程中断后置锁的状态

## 最新演进与工业实践

- 工具谱延续：IMPORT/LOAD/db2move/db2look 在 11.5/12 文档族仍在册（✅ https://www.ibm.com/docs/en/db2 ），但新一代迁移更多走 CDC/复制与云管道（Db2 Warehouse、datastage? 生态 ⚠️ 转述）。
- 与 SQL 路线合流：04 章 🔧B 显示 2024–2026 年"MERGE 可移植性"仍是分水岭；大批量入仓场景行业普遍以"旁路装载+事后统计重建"替代行级 upsert——Db2 LOAD 的教义与湖仓 ingest 模式同构（可对照 [../DuckDB_in_Action/00-总览与阅读地图.md](../DuckDB_in_Action/00-总览与阅读地图.md) 数据管道章的"批量优先"心智）。
- 统计自动化：装载后 RUNSTATS 的"必跑"属性被自动维护吸收（10 章），工业脚本仍常显式执行以保证计划稳定。
- 格式遗产：IXF 作为跨平台载体的地位被 CSV/Parquet 侵蚀；Db2 侧读写外部格式能力在后续版本增强 ⚠️（以官方文档为准），考试史题目仍以 IXF/DEL 为主。
- 教训迁移：LOAD 的"旁路=快但破坏恢复链"是存储引擎通用权衡（PG 的 COPY FREEZE、MySQL 批量导入关日志同理）——面试可跨引擎串讲。
