# 10 · 维护与自动运行（对齐考试域：Maintaining the Database ⚠️ 推定）

> 章名 ⚠️ 推定（主题重构，见 00 降级声明）。DB2 行为一律 ⚠️ 转述自 IBM 11.1 公开文档与社区笔记；本机不可装 DB2。碎片/统计类 SQLite 类比（VACUUM、ANALYZE）已由 #77 的 00 第七节 C/E 组实测登记（非 DB2 行为），本章只引其口径不重复跑。

## 一、章定位

维护域三件套：**RUNSTATS（统计）、REORG（物理重组）、自动维护（调度器）**，外加"何时做哪个"的处方题。REORGCHK 是判据来源、AUTO MAINT 是偷懒开关——考试爱在两者间设陷阱（自动开着≠不用理解原理）。

## 二、RUNSTATS 细节（⚠️ 转述）

- 产物谱：表基数（CARD）、列统计（NGROUPS/频次直方?）、列组（COLGROUP）、分布统计（WITH DISTRIBUTION）——计划质量的原料（09 章回收）。
- 档位：FOR ALL COLUMNS / FOR COLUMNS 指定 / 采样（SAMPLE ... PERCENT / STATISTIC USING SYSTEM? 采样方法 ⚠️ 冷门名不背）；SUMMARY ONLY vs DETAILED? 影响成本与收益。
- 时机铁律：大批装载/删除后、表重建后、计划突变后；装载工具本身会清统计（05 章联动）。
- 11.1 增量：列组织表的实时/准实时统计倾向（BLU 路线 ⚠️ 细节存疑）、profile 统计（RUNSTATS ... TYPE? PROFILE 的轻量保持法 ⚠️ 口径谨慎）。
- 挂起态联动：LOAD 后 SET INTEGRITY 与统计先后的正确顺序（先完整性后统计 ⚠️ 常错点）。

## 三、REORG 与 REORGCHK（⚠️ 转述）

1. 为什么重组：行迁移/页碎片/聚簇度衰减→IO 放大；与 SQLite VACUUM 的"整库重写"不同，Db2 可按表/表空间/索引分粒度（#77 🔧C 口径：VACUUM 后页数量骤降=碎片存在的旁证，非 DB2 行为）。
2. REORGCHK 判据：F1..I6? 公式族输出（统计时效+碎片率），N/U? 列的 OK/星号读图题；"先 REORGCHK 再 REORG"是标准流程叙事。
3. 在线重组（offline vs online reorg ⚠️ 术语）：非独占重组+重组索引并行；暂停/恢复/中止控制（PAUSE/RESUME/ABORT ⚠️ 配对题）。
4. 分区表重组：可分区级增量；聚簇保持（REORG DATA ... WITH USE? 语句形 ⚠️ 冷门）。
5. 后续动作：重组后 RUNSTATS +（聚簇索引）重建计划校验（09 章闭环）。

## 四、自动维护调度器（⚠️ 转述）

- 总闸：DB CFG `AUTO_MAINT=ON` 分启 `AUTO_RUNSTATS/AUTO_REORG/AUTO_BACKUP` 三作业族；触发窗口/间隔参数（STATS?/AUTC? 类命名 ⚠️ 细节以文档）。
- 采集器：活动数据变化量越过阈值→自动入队；与 db2evmon? 无关，别混（事件监控器=观测，调度器=动作）。
- 运维纪律：生产常"半自动"（runstats 自动、reorg 人工窗口）——判断题偏好："全自动可高枕无忧"是错项。
- 备份自动化归 08 章（AUTO_BACKUP 依赖归档模式）。

## 五、健康巡检脚本位（工作流模板，⚠️ 示意非原书代码）

```text
db2 "get snapshot for databases on demo"      # 吞吐/日志/锁概览
db2 "select * from table(mon_get_bufferpool(null,-1))"  # 池级热点
db2 "reorgchk current statistics on table db2inst1.t"   # 判据
db2 "runstats on table db2inst1.t and indexes all"      # 处方
db2 "admin_check_db? ..."（冷门体检不背 ⚠️）
```

- 巡检节奏模板：日（日志/空间）→ 周（统计时效）→ 月（碎片+重组窗口）→ 季（恢复演练，08 章）。

## 六、常见陷阱（例题库向）

1. 刚 IMPORT 完直接看计划——统计未重建，结论无效（05/09 章连环题）。
2. REORGCHK 全星号就全库 REORG——先看统计时效列，多数"碎片"是统计陈旧假象。
3. 自动维护开着却从不验证执行历史（作业日志/HISTORY）——"自动=放任"错项原型。
4. 大表在线重组未预留足够 TEMP/日志空间→中途膨胀事故（03 章容量题联动）。
5. 重组窗口与备份窗口打架（表空间挂起连锁）——排程纪律判断题。

## 八·五、自测题（本目录自编，非原书题 ⚠️）

**Q1** 处方题：REORGCHK 输出某表多列带星号，但其中"统计时效"行的时间戳是上周——先做什么再判是否重组？
**答**：先 RUNSTATS 刷新后复跑 REORGCHK；多数"碎片星号"是统计陈旧的假象（第六节陷阱 2；机制：判据公式同时吃统计与物理指标，第二节 2）。

**Q2** 排序题：LOAD(NONRECOVERABLE) 完成后的动作序列：备份/SET INTEGRITY/RUNSTATS/计划校验。
**答**：解除挂起链先行——表空间备份（05/08）→ SET INTEGRITY（约束校验）→ RUNSTATS（统计重建）→ EXPLAIN 校验收尾（第八节动作链）。

**Q3** 判断："AUTO_MAINT=ON 后 AUTO_BACKUP 在循环日志库也能工作。"
**答**：错。自动备份子作业同受在线备份前提约束（归档模式，03 章矩阵），开关开着也只是排队失败叙事（第四节依赖关系）。

**Q4** 场景：在线 REORG 大表至一半业务高峰已到，两个合规选项。
**答**：PAUSE（暂停待窗口恢复 RESUME）或按预案 ABORT 回退（第三节 3——可暂停/恢复/中止正是 Db2 在线重组的差异化卖点，勿选"杀进程"）。

**Q5** 论述两句：为什么"重组后 RUNSTATS"不可省。
**答**：重组改变了物理序与页分布，聚簇度/行数指标已变，旧统计会误导新计划（第三节 5 + 第二节燃料论）；顺带索引若同窗重建，更需一并入统计。

## 八·七、本域场景表达两句话

1. 因果句："维护三件套是一条因果链的三段：数据变了→统计过期→计划劣化；REORG 治的是物理衰减——先分清'燃料坏了'还是'路坏了'。"
2. 自动化句："自动维护=有阈值的排队系统，不是保险箱；验证执行历史与窗口冲突，才是'敢开着 AUTO_MAINT'的前提（第四节纪律）。"

## 八·九、本域一句话索引（复述练习用）

- 统计四种产物：CARD/列/列组/分布——各喂一个优化器判断（09 章燃料）。
- 时机四律：装载后、大批删改后、重建后、计划突变后。
- 重组三粒度：表/索引/表空间；在线三态控制：PAUSE/RESUME/ABORT。
- 判据一表：REORGCHK 星号先问统计新鲜度，再问碎片。
- 自动三子闸：RUNSTATS/REORG/BACKUP，各自有前置依赖（备份闸依赖归档模式）。
- 动作链口诀：解挂起→补备份→重建统计→校验计划。

## 核心概念速览（中英对照）

- **RUNSTATS** — 统计收集：CARD/列/列组/分布产物族
- **采样统计** — Sampling：大表低代价估计（SAMPLE/PERCENT）
- **列组** — Column Group：联合谓词基数校正原料
- **REORG** — 重组：回收碎片/重排聚簇
- **在线重组** — Online Reorg：非独占可暂停/恢复/中止
- **REORGCHK** — 重组体检：公式族判据输出
- **聚簇度** — Clustering:数据物理序与聚簇索引一致性
- **AUTO_MAINT** — 自动维护总闸：调度器开关
- **AUTO_RUNSTATS/AUTO_REORG/AUTO_BACKUP** — 三自动化作业族
- **阈值触发** — Activity-based Trigger：变化量越限入队
- **SET INTEGRITY** — 完整性重置：装载后统计前的前置（05 章）
- **挂起窗口** — Maintenance Window：重组/备份排程纪律
- **巡检节奏** — Health Check Cadence：日/周/月/季分层模板

- 自调深化：11.5/12 继续吸收手工维护（自适应统计、查询管理、STMM 演化 ⚠️ 转述）；但"统计→计划→性能"因果链教学价值不减，Db2 认证卷仍以本章为机制理解载体（✅ 文档谱 https://www.ibm.com/docs/en/db2 ）。
