# 09 · 监控与性能调优（对齐考试域：Monitoring & Tuning ⚠️ 推定）

> 章名 ⚠️ 推定（主题重构，见 00 降级声明）。DB2 行为一律 ⚠️ 转述自 IBM 11.1 公开文档与社区笔记；本机不可装 DB2，无本章专属 🔧 组（监控读图直觉可用兄弟册 #77 的 🔧E ANALYZE→RUNSTATS 类比口径，非 DB2 行为）。

## 一、章定位

本域两张考卷：**工具选型**（什么场景用快照/事件监控器/表函数/db2pd/db2top）与**调优判据**（缓冲池命中、锁等待、排序溢出、访问计划形态）。命令输出片段读题是 Db2 卷特色，本章给"读图三问"：谁慢、慢在哪个资源、下一步取证命令。

## 二、监控体系全景（⚠️ 转述）

1. 快照监控器（Snapshot）：`UPDATE MONITOR SWITCHES`（LOCK/BUFFERPOOL/SORT/STATEMENT? 等开关，DBM CFG）+ `GET SNAPSHOT FOR ...`；轻量但离散，适合定点取证。
2. 事件监控器（Event Monitor）：事件流（缓冲池/排序/锁/语句）写表或文件，START/STOP 控制；`db2evmon` 解读二进制输出（05 章工具谱邻居）；重负载慎用。
3. 表函数监控（MON_GET 家族）：`MON_GET_DATABASE/MON_GET_BUFFERPOOL/MON_GET_LOCKS/MON_GET_ACTIVITY`（10.5 起主力 ⚠️），随查随得、可编程——现代主线。
4. db2pd：直读引擎内存结构（-locks -bufferpools -containers -agent?），无需建连，事故现场首选（07 章联动）。
5. db2top：TUI 仪表盘，会话级看等待/排序/IO；交互式排障叙事题。
6. 活动监控与语句集中：STMT_CONC（LITERALS?）把同形语句聚合进包缓存/语句监控视图（MON_GET_ACTIVITY 的 TOP 排序=抓"头号 SQL"套路）。

## 三、优化器与访问计划（⚠️ 转述）

- 统计输入=RUNSTATS 产物（基数/频率/列组/分布，10 章），计划输出=EXPLAIN 产物。
- 取证链：`db2expln -dynamic`（快速解释）/ `EXPLAIN PLAN FOR` + `db2exfmt`（全量格式化）；读计划认五要素：访问方法（IXSCAN/TABLESCAN/INDEX ANDING?）、连接方法（NLJOIN/MSJOIN/MERGEJOIN/FALSE?）、聚集/排序位置、基数估计 vs 实际、预估成本。
- 基数失真信号：估计行数与 RUNSTATS 时间错位（装载后未统计，05 章回收）→ 优化器盲选 TABLESCAN——"为什么突然不走索引"题的标准链条。
- 连接方法直觉：小驱动大+索引→NL；无序大表等值→MS（哈希）；已排序流→MERGE；跨引擎可迁移，对照 SQL Server 线 00 同题。
- 优化级别与提示面：优化器配置参数（数值级别谱系 ⚠️ 版本敏感不背数字）、后续版本的 hint/优化 profile 叙事（11.x 演进 ⚠️，答题以文档）。

## 四、资源热点判读表（⚠️ 转述）

| 症状 | 首要指标 | 处置参数/动作 |
|---|---|---|
| 物理读高 | 缓冲池 hitratio、read queue | BPSIZE、NUM_POOL?、预取（03 章） |
| 排序溢出 | 排序溢写计数、SORT? 类等待 | SHEAPTHRES_SHR、APPLHEAPSZ、SQL 改写 |
| 锁等待 | 锁等待时间、-911 出现率 | 07 章参数+事务瘦身 |
| 日志瓶颈 | 日志缓冲区等待、满日志 | LOGBUFSZ/LOGPRIMARY 扩容（03 章） |
| CPU 高 | 语句级计时、包缓存未命中率 | PKGCACHESZ、语句集中、准备复用 |
| IO 倾斜 | 容器使用与响应分布 | 容器重布、extentsize/prefetch 校准（03 章） |

- 读图纪律：Db2 指标多在 SYSPROC/表函数返回列里，题目给的就是这些列名——先认列再判断。

## 五、索引域考点（⚠️ 转述，纵深转理论线）

- 索引类型谱：常规（B 树）、唯一、聚簇（CLUSTER 提示性 ⚠️）、XML 索引、包含列 INCLUDE?（宽覆盖）、扩展索引（⚠️ 冷门）。
- 覆盖索引与"仅索引扫描"：SELECT 列全入索引→免回表；高频判断题。
- 建什么索引：db2advis（索引/MQT 顾问）以工作负载喂统计出建议——"自动推荐 vs 手工克制"讨论位；纵深读 repo 索引双书（见互链）。
- 索引维护代价面：LOAD 后重建（05 章）、REORG 后重建时机（10 章）、非叶页统计。

## 六、内存与并行小考点（⚠️ 转述）

- 度并行（intra-partition parallelism）：DB2_DEGREE_DISTRIBUTION?/MAX_DEGREE，大查询多进程/线程分段扫描（SMP 内并行，DPF 上再叠间并行 ⚠️）。
- 预取校准：`db2 "call admin_get_p?..."` 不背；口径=按容器条带数×读单元估 prefetchsize（03 章参数回收）。
- 包缓存/编目缓存膨胀：`flush package cache all` 的时机与代价（清后首批语句重新准备尖峰——运维题眼）。

## 七、常见陷阱（例题库向）

1. 事件监控器常开不关——自身成为负载；选型题答案优先表函数快照式随查。
2. 只看 hitratio 不看绝对物理读量——大池命中率 99% 仍可能海量 IO。
3. 拿 db2exfmt 的"成本数字"跨版本比大小——成本单位不可比，比形状（方法/顺序/基数）。
4. 装载后未 RUNSTATS 就调索引——计划失真的根因在统计不在索引（10 章回收）。
5. 并行度拉满做小 OLTP——上下文切换+锁面扩大；并行是给大扫描的处方。

## 八、考点自查清单

- 六类监控工具各配一个"唯一优势场景"（现场保全=表函数；无连环境=db2pd；趋势采集=事件监控器落表…）。
- db2expln vs EXPLAIN+db2exfmt 的取证深度差。
- 覆盖索引/仅索引扫描的定义一句话。
- 排序溢出链：估算→内存分配→溢出→临时表空间 IO→调参位置。

## 九·五、自测题（本目录自编，非原书题 ⚠️）

**Q1** 选型：库正在崩溃恢复中无法建连，需要立刻看锁与容器状态，用什么？为什么不用表函数？
**答**：db2pd——直读引擎内存不需连接（第二节 4）；MON_GET_* 需连库查询，恢复期连不上（"无连环境"是其唯一优势场景）。

**Q2** 读图：db2exfmt 输出某步 ROWS=500000 而 RUNSTATS 后同谓词实际 500，判读+处方。
**答**：基数估计严重失真（统计陈旧或采样偏差，第三节）；处方=重跑 RUNSTATS（可加列组/分布档）再验证计划（第六节排序/索引前先查统计——10 章联动）。

**Q3** 判断："排序溢出的唯一解是加大 SHEAPTHRES。"
**答**：错。先判估算与 SQL 形态（无索引排序/大宽行 ORDER BY），内存只是处方之一；溢出证据看排序监控计数与临时表空间 IO（第四节表行 2）。

**Q4** 配对：抓"当前最耗时 TOP SQL"与"某历史时段锁事件全记录"各用哪路。
**答**：前者 MON_GET_ACTIVITY/语句集中视图（STMT_CONC 归并字面量后排序）；后者事件监控器落表（历史流，第二节 3/6；快照是"现在"，事件是"过去"）。

**Q5** 场景：装载后查询不走索引，三个候选根因按序排查。
**答**：统计失效（05/10）→ 谓词形态（函数包裹/隐式转换使索引不可用）→ 索引本身状态（LOAD 后重建失败/挂起）——"先燃料后道路"排查律（第五/六节综合）。

## 九·七、本域场景表达两句话

1. 选型句："随问随答用表函数、事故现场用 db2pd、长期取证用事件监控器落表、人机仪表盘用 db2top——四个场景不互换是本章的全部考点。"
2. 计划句："跨版本比成本数字是外行，比方法/顺序/基数三形状才是读计划的正确姿势（第三节）。"

## 核心概念速览（中英对照）

- **快照监控器** — Snapshot Monitor：开关式定点采集（UPDATE MONITOR SWITCHES）
- **事件监控器** — Event Monitor：事件流落表/文件，db2evmon 解读
- **表函数** — MON_GET 家族：可编程即时监控主力
- **db2pd** — 引擎内存直读：无连接现场取证
- **db2top** — TUI 仪表盘：交互排障
- **STMT_CONC** — 语句集中：字面量归并看 TOP SQL
- **EXPLAIN/db2exfmt** — 访问计划产物与格式化器
- **db2expln** — 快速解释器：免落表读计划
- **IXSCAN/TABLESCAN** — 索引/全表扫描访问方法
- **NLJOIN/MSJOIN/MERGEJOIN** — 嵌套循环/哈希/归并连接方法
- **覆盖索引** — Covering Index：免回表的列包含
- **仅索引扫描** — Index-ONLY：计划理想形态判据
- **db2advis** — 设计顾问：索引/MQT 推荐器
- **度并行** — Intra-Partition Parallelism：单分区内并行扫描
- **包缓存** — Package Cache：准备产物复用层

## 最新演进与工业实践

- 监控面换代：11.5/12 文档把 MON_GET_* 系与监控视图（MON_GET_ACTIVITY/TOP-SQL 类）定为主线，快照监控器退兼容位 ⚠️ 转述（✅ https://www.ibm.com/docs/en/db2/12.1.x ）；Db2 自带 Web 控制台/DSM（Data Server Manager）承担图形化 TOP-SQL 与等待分析（⚠️ 工具名谱以文档为准）。
- AIQ 方向：Db2 11.5.x 起官方"自适应/自解释查询"叙事（自动重优化、查询管理 ⚠️），把 11.1 时代的静态调优考点推向"引擎自调+人管边界"。
- 观测融合：工业实践把表函数轮询接入 Prometheus/Grafana 栈，"事件监控器落表→指标库"成为 Db2 可观测性主流管道；跨引擎等待事件方法论可互鉴（Oracle/SQL Server 线 00 均登记同类）。
- 索引顾问生态：db2advis 之外，云 DBA 服务与设计模式库互补；覆盖索引/仅索引扫描仍是所有 B 树引擎的通用面试语言。
- 读题提醒：本域输出类题目里的列名（如 LOCK_WAIT、ROWS_READ）多年稳定，值得按表函数返回列清单记忆而非截图背诵。
