# 08 · 备份恢复与高可用（对齐考试域：Backup, Recovery and Availability ⚠️ 推定）

> 章名 ⚠️ 推定（主题重构，见 00 降级声明）。DB2 行为一律 ⚠️ 转述自 IBM 11.1 公开文档与社区笔记；本机不可装 DB2。备份/日志类 SQLite 类比实验已由兄弟册 #77 的 00 第七节 A/B 组登记（备份 API 拷库、journal_mode/checkpoint），本册不重复跑、只引其结论口径（均为非 DB2 行为）。

## 一、章定位

恢复域是 DBA 卷的"半壁分值"：备份类型×日志模式的可行性矩阵、RESTORE+ROLLFORWARD 的两段式时序、表空间级恢复与 LOAD 挂起的联动（05 章），加 HADR/pureScale 概念位选择题。

## 二、备份类型与前提矩阵（⚠️ 转述）

| 形态 | 前提 | 特征 |
|---|---|---|
| 全量离线备（OFFLINE） | 无活动连接（force 应用） | 循环日志库唯一选项 |
| 全量在线备（ONLINE） | 归档日志模式 | 需读锁+日志前滚保一致 |
| 增量（INCREMENTAL/CUMULATIVE） | 全备基线 + TRACKMOD=ON（03 章） | 页级变更图（bitmap）记脏区 |
| 表空间级备 | 归档模式 | 局部恢复配套（含 SYSTEM/USER 区分） |
| load 备份（loadcopy） | LOAD 且 COPY YES（05 章） | 装载一致性快照 |

- 备份介质：DISK/目录、TSM?（磁带服务 ⚠️）、V backup?（冷门）；`db2ckbkp` 校验备份头——"备份能不能用"的先验题。
- 备份历史目录：HISTORY 文件记录全链，`LIST BACKUP INCREMENTAL` 的恢复对象视图（09 章监控面联动）。

## 三、崩溃恢复与连接期恢复（⚠️ 转述）

1. 实例重启=各库崩溃恢复：日志前滚已提交+回滚未提交（WAL 教义，Gray 谱系同源）。
2. 连接期恢复（Connect-Time Recovery）：单应用故障时后台自动回滚其事务，其他连接不陪绑——Db2 特色参数/行为（题目爱考"谁触发了它"）。
3. QUIESCE TABLESPACES：多表空间写序一致性工具（跨表空间完整性场景，冷门配对位）。

## 四、灾难恢复两段式：RESTORE + ROLLFORWARD（高频主线）

```text
db2 restore db demo from /bak into /dbpath
db2 rollforward db demo to 2018-06-29-12.00.00.000000 and stop return
db2 rollforward db demo complete   （或 incremental 用于备份滚动期）
```

- 时序心智：RESTORE 把库拉回备份点（不一致态，连不上），ROLLFORWARD 沿归档日志推进到目标点（时间点 PIT/最尾 complete），`and stop` 打开使用。
- 三种前滚形态：`to 时间戳`（PIT）、`complete`（追尾）、`incremental`（增量备份级联滚动 ⚠️ 用途口径）。
- 链完整性检查：恢复对象图（LIST BACKUP INCREMENTAL FOR OBJECT ... DATABASE）判断"备份+哪些日志段"够不够——排错题眼（缺归档→只能回到最近可用点）。
- 表空间级：`restore ... tablespace` + `rollforward ... tablespace X,Y to ...`；配合 05 章 pending 表空间处置（load 非可恢复后的"先补备再恢复"纪律）。

## 五、HADR 与 pureScale 概念位（⚠️ 转述）

- HADR：主库日志流实时发给备库重放；角色主/备；三种日志写保护级别（SYNC/NEARSYNC?/ASYNC?——名字与丢数据窗口取舍是配对题）；TAKEOVER（手动/自动故障转移 ⚠️ 数据安全语义）、备库可读（standby read）在 11.1 可用、多备库形态（11.x 谱系 ⚠️ 版本归属存疑）。
- pureScale：共享存储+集群缓存设施（CF）+全局锁结构的"多写"扩展，AIX/Linux 金融核心叙事；考试只考概念定位（与 DPF/HADR 三分辨析）。
- 复制家族位：SQL Replication/Q Replication（CDC）属数据集成域，本册仅在 05 章"装载替代路线"提及。

## 六、恢复策略设计题套路

1. RPO/RTO 需求→ 组合"全备频率+增量+归档保留+HADR 级别"。
2. 归档日志保留：`LOGRETAIN/LOGARCHMETH` + 备份后是否删除归档（ROLLFORWARD RECOVERY? 的 HISTORY 联动）——"日志满了"事故（03 章联动）。
3. 演练：恢复验证=ROLLFORWARD 到时间点后只读检查；生产变更前后各留校验备份。
4. 与 #77 第 13 章"三板斧"（restore/rollforward/recover）同题，11.1 增加：自动存储路径还原细节与增量位图管理（⚠️ 转述深度不越界）。

## 七、常见陷阱（例题库向）

1. 循环日志库上想在线备→报"不允许多用户备份"类（示意 SQL1059N）；先归档化再操作（03 章决策回收）。
2. TRACKMOD=OFF 却排增量备份计划→从未生效（页修改图不记录）。
3. RESTORE 后直接连库→"需要前滚"挂起态；忘了 `rollforward ... complete`。
4. 前滚目标点在归档缺失段→链断；用 LIST BACKUP 的日志范围列定位。
5. HADR 备库 TAKEOVER 时忽略日志保护级别与未达日志→数据丢失窗口（"高可用≠零丢失"判断题眼）。

## 九·五、自测题（本目录自编，非原书题 ⚠️）

**Q1** 矩阵题：循环日志库 + 需要把库恢复到昨天 15:00，可能吗？给出唯一正路。
**答**：不可能——循环日志无前滚材料（第二节矩阵）；正路=先归档化+新全备基线，此后 PIT 才成立（"从现在起可恢复"是这类题的正确表述，非"救回昨天"）。

**Q2** 时序题：排序 restore→在线全备→归档截断→rollforward complete→确认打开使用 五事件的两轮周期。
**答**：备→（日志续写）→截断旧归档须以"备份已覆盖"为界→事故时 restore→rollforward→stop/open——口诀"备份圈起点、日志续尾巴、前滚接终点"（第四节链完整性口径 ⚠️）。

**Q3** 排错：restore 完成但 `connect` 报需要前滚类挂起，一步处方。
**答**：`rollforward ... complete`（或到目标 PIT）`and stop`；"连不上"是恢复中间态的预期行为不是损坏（第七节陷阱 3）。

**Q4** 配对：SYNC/ASYNC 类写保护档各答哪个需求——零丢失 vs 低延迟。
**答**：强同步=RPO≈0 牺牲提交延迟；异步=性能优先容忍故障丢窗口（第五节 HADR；"高可用≠零丢失"判断题原型）。

**Q5** 论述三句：pureScale 与 HADR 的定位差异。
**答**：HADR=异地容灾（日志重放、主备角色、读备库分流）；pureScale=本域扩展（共享存储+CF+多写高可用叠加）；前者防"站没了"，后者防"跑不动+单点重启"，可组合但预算与复杂度迥异（第五节 ⚠️ 概念位）。

## 九·七、本域场景表达两句话

1. 策略句："备份方案=（全备频率×增量×归档保留）对 RPO，（restore×前滚×接管）对 RTO——四个乘法两个除法覆盖全卷策略题。"
2. 演练句："没做过的恢复不算备份：定期 PIT 回放到隔离环境+db2ckbkp 先验，把'能恢复'从信念变成记录（第六节纪律）。"

## 核心概念速览（中英对照）

- **离线/在线备份** — Offline/Online Backup：停用全备 vs 归档模式热备
- **增量备份** — Incremental/Cumulative Delta：页修改位图（TRACKMOD）驱动
- **db2ckbkp** — Backup 校验：备份头可读性先验
- **HISTORY 文件** — 备份历史：恢复对象图数据源
- **崩溃恢复** — Crash Recovery：重启时前滚+回滚
- **连接期恢复** — Connect-Time Recovery：单应用故障后台自动回滚
- **RESTORE** — 还原：把库拉回备份点（后处挂起态）
- **ROLLFORWARD** — 前滚：沿归档日志到 PIT/complete/incremental
- **PIT** — Point-in-Time Recovery：时间戳定点恢复
- **表空间恢复** — Tablespace Restore/Pending：局部处置链
- **QUIESCE** — 表空间静默：跨空间写序一致工具
- **HADR** — 日志流复制高可用：SYNC/ASYNC 写保护与 TAKEOVER
- **pureScale** — 共享存储多写集群：CF+全局锁架构
- **RPO/RTO** — 丢数据窗口/恢复时长：策略设计双轴

## 最新演进与工业实践

- 11.5/12 延续：restore/rollforward 教义未变；Db2 12 文档谱把归档目的地扩展到对象存储（S3 兼容等）叙事 ⚠️ 转述（✅ https://www.ibm.com/docs/en/db2/12.1.x ）。
- HADR 现状：备库可读+多备库+`AUTO RESEND`/压缩传输等参数族在 11.5 成熟（⚠️），行业把 HADR 定位为"同城双活前身"；跨引擎对照=PG 流复制/MySQL Group Replication/SQL Server AG（repo 内三者 00 均有专章）。
- 快照备份崛起：存储层快照+Db2 `BACKUP ... USE SNAPSHOT`? 路线（11.x 支持面 ⚠️ 存疑处只提概念）改变大库 RTO；备份软件生态（CommVault 等）对 Db2 代理的支持延续——工业实践中"引擎日志链+介质快照"双轨。
- 演练常态化：2024–2026 合规框架（金融灾备年检）要求周期性 PIT 回放验证，本域"恢复对象图读法"成为 DBA 求职硬技能。
