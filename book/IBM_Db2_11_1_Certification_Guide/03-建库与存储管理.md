# 03 · 建库与存储管理（对齐考试域：Creating and Managing the Database ⚠️ 推定）

> 章名 ⚠️ 推定（主题重构，见 00 降级声明）。DB2 不可本机实测，命令语义一律 ⚠️ 转述自 IBM 11.1 公开文档与社区笔记。

## 一、章定位

本域是 DBA 考试的"地基工程题"：CREATE DATABASE 关键参数建库即定死的代价、表空间三问（类型/容器/页尺寸）、日志两模式（循环/归档）对备份能力的决定性影响。配对与排错题混合出现。

## 二、CREATE DATABASE 决策面（⚠️ 转述）

```text
db2 create database demo on /dbpath automatic storage yes \
  pagesize 16 codepage 1208 collate using identity \
  with 16 bufferpools? （形态示意，非可抄命令）
```

- 建库即定、后改极贵：页尺寸集合（决定可建表空间的页尺寸）、代码页/地区码（collate，排序语义）、自动存储开关与路径池。
- 模板库法：先建 TEMPLATE 库调好 bufferpool/表空间再 `CREATE DATABASE ... USING TEMPLATE`——考试爱考的"批量一致建库"路子。
- 默认对象清点：建库自动生成 IBMDEFAULTBP、SYSCATSPACE、TEMPSPACE1、USERSPACE1 等，11.1 下均以 DMS/自动存储形态出现（⚠️）。
- DIR/PATH/TEMPPATH 路径组参数控制库目录、缓冲池?、临时文件落点（⚠️ 转述）。

## 三、表空间与容器（⚠️ 转述）

1. 三类型收缩史：SMS（目录即容器，逐页建文件）在 11.1 时代新库不推荐、趋向淘汰 ⚠️；DMS 文件/目录容器（ extents 预分配）；V storage?（z 系概念，LUW 不考）。主线=DMS+自动存储。
2. 自动存储语义：路径池托管容器自动扩展/再平衡；`ALTER DATABASE ... ADD STORAGE ON ...` 扩路径；表空间级 RESIZE/AUTOEXTEND 参数细调。
3. 容器/条带/extentsize/prefetchsize：物理读放大控制链（09 章性能视角）；"prefetch 未设对"是调优题常客。
4. 每表空间页尺寸须匹配其中表的页尺寸；表→表空间绑定在 CREATE TABLE ... IN（放置策略考点）。
5. 监控入口：`MON_GET_TABLESPACE` 表函数看使用率/挂起态（09 章工具谱），快照面 GET SNAPSHOT FOR TABLESPACES。

## 四、缓冲池与内存参数（⚠️ 转述）

- 一页尺寸一池；多池共存按工作负载分表入池；池参数 BPSIZE（页为单位）/NUMBLOCKS?（块缓冲 ⚠️ 冷门）。
- 命中与物理读在快照/表函数中的配对（hitratio 判读在 09 章）。
- STMM 接管时手工 ALTER BUFFERPOOL ... IMMEDIATE 仍可干预；`db2 "alter bufferpool ibmdefaultbp size 10000"` 形态（⚠️）。

## 五、日志体系：循环 vs 归档（决定备份能力，高频）

- 日志构成：日志缓冲（LOGBUFSZ）→ 活动日志文件（LOGPRIMARY 个 × LOGFILSIZ 页）→ 按需扩展 LOGSECOND；V9.7+ 的 `LOGARCHMETH1/2` 与 `LOGRETAIN` 双开关决定归档去向。
- 循环日志（默认态）：日志复用覆盖；只允许离线（_quiesce_后）全备；崩溃恢复只能回退未提交、不能前滚（⚠️ 转述）。
- 归档日志（RECOVERY 模式）：日志归档到 DISK/TSM? 目的地；解锁在线备份与前滚恢复（08 章主线）；归档目录爆满是运维事故常客。
- 新日志文件名规则 V9+（S0000xxx.LOG 计数）替代老 C2xxxxx 习惯（⚠️ 代差注记，配 #77 第 13 章）。
- 一级考点：`LOGINDEXBUILD=DELAYED` 类装载相关参数（05 章伏笔）、`TRACKMOD`（页修改跟踪→增量备份，08 章）。

## 六、临时空间与排序落盘

- TEMPSPACE1/用户临时表空间（UT? 11.1 已倾向用自动存储 DMS 临时表空间 ⚠️）承载排序/物化溢出；排序内存不足溢出到临时表空间是"SQL0901C?/排序类"调优题的信号（09 章回收）。
- `db2 "values stmt_mem?"` 类探查不背；理解"内存排序→溢出→临时 I/O"因果即可。

## 七、常见陷阱（例题库向）

1. 建库页尺寸选单一 16K，日后想放 4K 索引密集小表——无 4K 池可用，重建代价高。
2. 循环日志库上执行 `BACKUP ... ONLINE` 直接报 SQL1059N?（不允许多用户备份类）——先切归档日志（⚠️ 错误号仅示意）。
3. 自动存储路径全删光→新对象分配失败；ADD STORAGE ON 补救。
4. 表空间挂起（PENDING）态来源：非可恢复 LOAD、脱机操作中断、备份? 冲突——先查 `db2 "get snapshot for tablespaces"` 再定处置（05/08 交界高频）。
5. collate 选错导致索引/比较语义诡异：地区敏感排序集（identity vs UCA?）差异 ⚠️ 转述，建库题眼。

## 九·五、自测题（本目录自编，非原书题 ⚠️）

**Q1** 场景题：生产库要支持热备+PIT 恢复+增量备份，列出必须为 ON 的三组参数。
**答**：LOGARCHMETH1（归档目的地）/LOGRETAIN（保留 RECOVERY 语义，二者共同脱离循环日志）+ TRACKMOD（页修改跟踪→增量备份前提）（第五节；在线备份本身依赖归档态，08 章矩阵回收）。

**Q2** 排错：`BACKUP DB ... ONLINE` 报"不允许多用户备份"类错误，一句话根因与处方。
**答**：根因=库仍在循环日志模式；处方=配归档参数后重连/按文档要求完成一次全备基线再在线操作（⚠️ 转述，错误号仅示意）。

**Q3** 选择：USERSPACE1 表空间报"空间不足"但文件系统明明有余量，两个方向性检查？
**答**：容器 AUTOEXTEND/最大尺寸设置与自动存储路径池是否耗尽可分配路径；再看 extent 内碎片与表 FCM? 参数（后项冷门 ⚠️ 不展开）。

**Q4** 判断："页尺寸 8K 的表可以放进 16K 缓冲池，所以建库给一个 32K 池就够了。"
**答**：错。缓冲池按页尺寸一一配表空间（第四节），单一大池无法服务其它页尺寸的池；建库页尺寸集合是难逆决策（第二节清单）。

**Q5** 论述两句：模板库法 vs 逐库手工调参的取舍。
**答**：模板保证跨库一致性、适合多库复制拓扑与合规基线；手工灵活适合单库极致调优——生产惯例是"模板起步、例外登记"（第二节 ⚠️ 社区口径）。

## 九·七、本域场景表达两句话

1. 建库评审句："先问三件不可逆的事——页尺寸集合、代码页/排序集、自动存储路径基线；日志模式虽可后改，但改的那一刻决定备份能力表。"
2. 空间句："Db2 的空间是三层弹性：路径池—容器—表空间，哪层封顶就在哪层扩容，报错文本会告诉你封顶层。"（⚠️ 转述拟人口径）

## 九·九、本域一句话索引（复述练习用）

- 建库五决策：页尺寸/代码页/collate/自动存储/模板——前三个近乎不可逆。
- 表空间主线：DMS+自动存储；SMS 进只读兼容通道 ⚠️。
- 日志二分：循环=冷备+不可前滚；归档=热备+PIT+链式恢复的门票。
- 弹性三层：路径池→容器→表空间；prefetch/extentsize 是读放大旋钮。
- 挂起三源：非可恢复装载、脱机中断、备份冲突——先 snapshot 后处方。
- 联动预告：TRACKMOD↔增量备、LOGARCHMETH↔在线备、pending↔05 章 LOAD。

## 核心概念速览（中英对照）

- **自动存储** — Automatic Storage：路径池托管容器自动扩展机制
- **表空间** — Tablespace：表数据到容器的中间管理层（SYSCATSPACE 等）
- **DMS/SMS** — Database/Disk Managed Space：预分配容器型 vs 目录自扩型表空间（SMS 退场中 ⚠️）
- **容器** — Container：表空间的物理承载（文件或目录）
- **EXTENTSIZE/PREFETCHSIZE** — 盘条带与预读粒度参数
- **缓冲池** — Bufferpool：按页尺寸划分的缓存池
- **循环日志** — Circular Logging：日志复用，仅冷备能力
- **归档日志** — Archive Logging：LOGARCHMETH1/LOGRETAIN 开启，解锁在线备份+前滚
- **LOGPRIMARY/LOGSECOND** — 日志文件数：预建数与按需扩展数
- **TRACKMOD** — 页修改跟踪：增量备份前置开关
- **PENDING 态** — 表空间挂起：LOAD/操作中断造成的封锁状态
- **模板库** — Template Database：USING TEMPLATE 一致性建库法
- **collate** — 排序集：建库期定死的字符串比较规则

## 最新演进与工业实践

- 11.5/12 延续：自动存储成为事实默认；SMS 在现行版已进"只读兼容"通道 ⚠️（新库不建 SMS 是多年官方口径）。✅ 文档谱 https://www.ibm.com/docs/en/db2/11.5.x 与 https://www.ibm.com/docs/en/db2/12.1.x（curl -sI 200）。
- 日志域增量：Db2 12 文档中在线日志扩容与归档目的地选项继续演进（DISK 之外对象存储归档等云化路线 ⚠️ 转述）；11.1 的"循环/归档二分"心智模型仍是所有引擎通用的最小充分理解。
- 跨引擎同题：PG 表空间 vs Db2 表空间粒度差异、InnoDB redo 组 vs Db2 日志文件组的对照读法，repo 内两本 PG/MySQL 管理册的 00 均已登记同类辨析。
- 工业实践：核心库建设规程中"建库参数评审清单"（页尺寸/collate/日志模式/路径分盘）至今沿用；本域是 DBA 面试"问三层"高频取材点。
- 🔧 锚点提醒：本域不依赖 SQLite/DuckDB 对照（其无实例/表空间层级，文件即库；概念映射差异已在 00 第七节纪律声明中处理，勿把"SQLite 文件=表空间"当严谨类比）。
