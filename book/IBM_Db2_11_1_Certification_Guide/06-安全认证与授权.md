# 06 · 安全认证与授权（对齐考试域：Security and Authorization ⚠️ 推定）

> 章名 ⚠️ 推定（主题重构，见 00 降级声明）。DB2 行为一律 ⚠️ 转述自 IBM 11.1 公开文档与社区笔记；本机不可装 DB2，无本章专属 🔧 组（类比锚集中在 04/07 章）。

## 一、章定位

Db2 安全域的两根轴：**认证**（你是谁：Authentication）与**授权**（你能干什么：Authorization）。考试以"层级归属"配对题为主：哪些是实例级权限、哪些是库级、哪些是对象级；再加 LBAC/RCAC/审计三个特色块。

## 二、认证谱系（⚠️ 转述）

1. 本地 OS 认证：CLIENT/Server 同机或域内，DB2 把 OS 凭证交 `db2ckpwd` 守护进程校验。
2. 远程客户端认证 CLIENT：用户名口令走 TCP 通道（明文风险→TLS 加固，GSKit 密钥库）。
3. DCS 服务器端认证 SERVER/SERVER_ENCRYPT：由服务器实例代客认证，客户端免本地账号——多客户端集中部署考点（与 11 章目录/编目连读）。
4. 插件认证：11.1 支持认证插件扩展（Kerberos/LDAP? 经 GSKit/第三方插件接入 ⚠️ 细节），企业单点登录路线。
5. 口令策略：OS 侧策略为主（插件可接管复杂度校验 ⚠️）。

## 三、权限层级总图（高频考区，⚠️ 转述）

- 实例级三权限（DBM CFG 组参数指定）：**SYSADM**（总管）、**SYSCTRL**（实例/库管理不含数据授权与安全面?）、**SYSMAINT**（维护操作如备份/重组不含读数据?）——"最小够用"分解题的原料。
- 数据库级：**DBADM**（库内总管）、**SECADM**（授权权，9.7 起从 SYSADM 拆出的关键设计 ⚠️ 版本归属注记）、DATAACCESS/ACCESSCTRL 等带 OPTION 的细分权限（GRANT DBADM WITH DATAACCESS）。
- 对象级：CONTROL、ALTER、SELECT/INSERT/UPDATE/DELETE、REFERENCES、INDEX、EXECUTE（例程）等；GRANT ... TO 用户/组/角色。
- 隐式主体：PUBLIC 组人人在册——"新对象默认 PUBLIC 有 SELECT?"类题按 DB CFG 的 SYSADM_REVOKE? 与对象类型分流（⚠️ 谨慎口径）。
- 角色：CREATE ROLE + GRANT ROLE；角色不含层级权限替代? 细节以文档为准。

## 四、LBAC 与 RCAC（⚠️ 转述）

- LBAC（基于标签的访问控制，Enterprise 线特性）：安全策略（Policy）→ 标签构件（Element）→ 标签（Label，含比较规则）→ 表的 SECLABEL 列 + 用户/行标签绑定；"无权限者连行都不可见"的行级安全重武器，配置面大。
- RCAC（行/列访问控制，11.1 新）：ROW ACCESS CONTROL（谓词式行过滤）+ COLUMN ACCESS CONTROL（掩码/豁免）——轻量替代 LBAC 的路线，考试新宠 ⚠️（与 04 章对象域交叉）。
- 对比考点：LBAC 标签格状模型 vs RCAC 谓词模型；何时选谁（治理复杂度/性能/粒度需求）。

## 五、审计与合规面（⚠️ 转述）

- DB CFG 审计参数（AUDIT... 类 ⚠️ 开关名以文档为准）记录登录失败?/权限违例等事件；审计日志落 OS 文件由 db2audit 工具族读解（11.1 工具面 ⚠️）。
- 与"审计需求四问"对应：谁、何时、对什么对象、做了什么——DB2 的答案分布在：目录触发器?、事件监控器（09 章）、RCAC 掩码（遮蔽非审计）三类方案辨析题。
- 最小权限实操路线：建组→分级授权→角色封装→PUBLIC 收权（例题库常以"纠正过度授权"命题）。

## 六、授权语句形态速记（⚠️ 转述）

```text
db2 grant dbadm without dataaccess on database to role dba_light
db2 grant select, update(col_a) on table emp to user alice
db2 revoke control on table t from group devs
db2 "create role auditor"  db2 "grant role auditor to user bob"
```

- 表级列粒度 UPDATE/REFERENCES 是 Db2 语法细节考点；GRANT ... WITH GRANT OPTION 传递链回收的级联语义（与关系理论线同源讨论）。

## 七、常见陷阱（例题库向）

1. 把 SYSCTRL 当"能看数据"——三实例级权限的数据可见性区分是送分/送命题。
2. 只有 SYSADM 组概念、忘了 Windows 下组=本地组+域组的解析差异（⚠️ 平台注记）。
3. LBAC 上线忘配例外/策略管理员，把自己锁在表外（SECADM 与策略所有权纠缠 ⚠️）。
4. 新库 PUBLIC 默认权限面在脚本迁移环境中引发越权——回查 GRANTS 用 db2look -e（05 章工具）。
5. DCS 认证配错导致"客户端装了全量 client 却连不上"——认证方式与客户端形态的匹配题（11 章回收）。

## 九·五、自测题（本目录自编，非原书题 ⚠️）

**Q1** 层级归属：把 SYSADM、DBADM、SECADM、CONTROL、SELECT 按"实例级/库级/对象级"归类。
**答**：实例级=SYSADM（同族还有 SYSCTRL/SYSMAINT）；库级=DBADM、SECADM；对象级=CONTROL、SELECT（第三节金字塔；带 OPTION 的 DATAACCESS/ACCESSCTRL 属库级细分 ⚠️）。

**Q2** 场景：审计部要"只能看本部门行、且手机号列脱敏"，选 LBAC 还是 RCAC？理由两句。
**答**：RCAC——行过滤用 ROW ACCESS CONTROL 谓词、列脱敏用 COLUMN ACCESS CONTROL 掩码即够；LBAC 标签格模型治理成本高，留给分级保密强合规场景（第四节，11.1 新特性考点）。

**Q3** 排错：用户被加入 SYSADM_GROUP 仍管不了实例，两个常见原因。
**答**：组解析问题（Windows 本地组/域组层级 ⚠️；UNIX 组生效需重新登录会话）+ DBM CFG 的 SYSADM_GROUP 是否显式设置且实例重启生效（第三节/02 章双轨口诀）。

**Q4** 判断："PUBLIC 默认权限面在多应用共享库上是安全的省事做法。"
**答**：错。PUBLIC 全员在册导致新对象默认暴露，最小权限路线要"收 PUBLIC 权+角色封装+db2look 复查授权"（第三节隐式主体+第五节实操链）。

**Q5** 配对：CLIENT/SERVER(DCS)/插件 三种认证各配一句部署画像。
**答**：CLIENT=客户端自带凭证直传；SERVER/DCS=服务端代客集中认证（客户端瘦）；插件=接企业目录/单点（Kerberos/LDAP 类 ⚠️）。与 11 章客户端形态组合出"最瘦客户端"方案题。

## 九·七、本域场景表达两句话

1. 模型句："Db2 安全问两层：门（认证：你是谁）与权（授权：你能碰什么）——90% 的权限排错其实是门没开对，不是权没给对。"
2. 治理句："角色封装+PUBLIC 收权+SECADM 分权，是从'人人 SYSADM'到可审计基线的最短路径（SECADM 拆分是 9.7 以降制度设计的题眼 ⚠️）。"

## 九·九、本域一句话索引（复述练习用）

- 两轴：认证=门（OS/CLIENT/DCS/插件四路），授权=权（实例三级/库级/对象级金字塔）。
- 三实例权限都不带读业务数据是设计不是缺陷；SECADM 拆权是 9.7 以降制度题眼。
- LBAC 重（标签格模型）、RCAC 轻（谓词+掩码）——11.1 新宠答"行级过滤+列脱敏"。
- PUBLIC 是默认暴露面，收权+角色化+db2look 复查=治理三件套。
- 审计闭环四问（谁/何时/对象/动作）分别落在：目录授权、事件监控（09）、RCAC 遮蔽≠审计。

## 核心概念速览（中英对照）

- **认证** — Authentication：确认连接者身份（OS/CLIENT/DCS/插件四路）
- **授权** — Authorization：确认主体可对客体做什么
- **SYSADM/SYSCTRL/SYSMAINT** — 实例级三权限：管理/控制/维护分层
- **DBADM** — Database Administrator 权限：库级总管
- **SECADM** — Security Administrator：专司授权链的库级权限
- **CONTROL** — 对象级最高权：含改删与再授权
- **PUBLIC** — 隐式全员组：默认权限面的风险源
- **角色** — Role：权限集合的再封装单位
- **LBAC** — Label-Based Access Control：标签策略行级安全
- **RCAC** — Row and Column Access Control：11.1 轻量行列控制
- **SECLABEL** — 安全标签列：LBAC 的表内载体
- **审计** — Auditing：违例/事件记录合规面
- **WITH GRANT OPTION** — 授权传递：级联回收语义的来源

## 最新演进与工业实践

- 11.5/12 延续：RCAC、认证插件体系在册并扩容（✅ 文档谱 https://www.ibm.com/docs/en/db2 ）；行列控制从"11.1 新面孔"变为默认答题面，LBAC 退守强合规细分场景 ⚠️ 转述。
- 加密面补全：本域 11.1 时代不含 TDE（透明数据加密）类静态加密，Db2 以备份加密（Backup Encryption，10.5/11 谱系 ⚠️）+ TLS 链路加密组合回应；2024–2026 行业把"静态加密"视为缺省项，跨引擎对比时注意 Db2 的实现命名与密钥管理对接方式差异 ⚠️（以官方安全文档为准）。
- 云化：Db2 on Cloud/Cloud Pak 把认证让渡给平台 IAM/企业 SSO，考试语境的 OS 组模型在托管服务中弱化——概念迁移题。
- 行业实践：金融核心库的最小权限治理（角色化+PUBLIC 收权+审计闭环）与本域自查清单一一对应；PG RLS/SQL Server 始终加密与 RCAC 的同构讨论是近年 DBA 面试常客。
