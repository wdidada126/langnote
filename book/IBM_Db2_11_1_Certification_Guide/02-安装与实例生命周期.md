# 02 · 安装与实例生命周期（对齐考试域：Installation ⚠️ 推定）

> 章名 ⚠️ 推定（主题重构，见 00 降级声明）。DB2 不可本机实测，命令语义一律 ⚠️ 转述自 IBM 11.1 公开文档与社区笔记。

## 一、章定位

本域考"装与起停的秩序感"：先装代码后建实例、先停实例再打补丁、实例归属与端口规划。题型多为命令配对（哪个命令完成哪个动作）与前置条件判断（报 X 错先查什么）。对 9.x 读者：概念与 #77 第 2 章几乎同构，差异在 11.1 的安装器形态与补丁谱。

## 二、安装形态与版本介质（⚠️ 转述）

1. 介质谱：服务器版（实例+引擎）、客户端版分"Client"（含 CLP/目录工具）与"Runtime Client"（仅驱动库，应用部署用）——考试高频："最小连接方案选哪个"→ Runtime/IBM Data Server Driver（见 11 章）。
2. 平台：Linux（rpm/tar 图形与字符向导）、AIX（smit/installp 习惯）、Windows（MSI 向导 + 服务账户设置）。
3. 静默安装：响应文件驱动（向导生成样例→改键值→无人值守），大规模部署与考试的"部署脚本"话题（⚠️ 参数名不背）。
4. 预检清单：OS 版本/内核参数（SHMMAX 等共享内存项）、磁盘空间（代码副本+实例目录+日志目录分盘习惯）、编译器/库依赖、svcname 端口注册。
5. 11.1 特性项：安装期即可选的 Feature 清单（如 IBM Data Server Driver、样本件）随介质捆绑，装完用 db2isetup/db2ilist? 视角查副本（⚠️ 命令名以文档为准）。

## 三、实例生命周期命令族

```text
db2icrt -a server -p tcp 50000 inst1     # 建实例（指定认证/端口）
db2ilist                                  # 列本机实例
db2start / db2stop [force]                # 启停实例
db2ichkrc? / ipclean（UNIX 残留 IPC 清理，习惯动作 ⚠️）
db2iupdt inst1                            # 补丁后升级实例代码链接
db2idd -r / db2deinstall?                 # 删除实例与卸载（顺序：先 db2stop）
```

- 一实例一所有者；多实例共存靠 DB2INSTANCE 环境变量路由（装错的头号事故源，与 #77 辨析 1/2 条同题）。
- Windows：实例=服务串"DB2 - DB2COPY1 - INST1"，服务账户密码轮换属运维规程。
- 实例目录（sqllib 等）与节点拓扑文件 db2nodes.cfg 只在 DPF 场景有意义（01 章伏笔回收）。

## 四、配置双轨：CFG 参数与注册表变量（⚠️ 转述）

- DBM CFG（实例级）：`db2 update dbm cfg using ...`，含 SYSADM_GROUP、DAS?、监控开关（MON_*）——09 章的开关多在此。
- DB CFG（库级）：`update db cfg for dbname using ...`，建库参数大半可后改（03 章展开）。
- 注册表变量：`db2set -g` 读、`db2set DB2Xxx=...` 写，实例级或全局；经典开关：DB2INSTANCE 路由、DB2_COMPATIBILITY_VECTOR（方言兼容向量，Oracle/MySQL 语法兼容入口，04 章呼应）、DB2_EVALUNCOMMITTED/DB2_SKIPDELETED 等并发行为开关（07 章）。
- 变量作用域优先级：全局 vs 实例 vs 用户注册表文件——配对题常客。

## 五、补丁与升级谱（⚠️ 转述）

1. 11.1 修正规律：FP（fix pack）新代码副本安装 → 停实例 → `db2iupdt` 更新既有实例 → 起实例；多实例机器逐个更新，`db2iidb? `不存在，别混。
2. 版本命名：11.1.0.0（GA，2016-11 ⚠️ 年代）→ 11.1.1.x/11.1.2.x/11.1.3.x/11.1.4.x 各 FP（⚠️ 具体能力差异以官方文档为准）。
3. 数据库升级：老库（如 9.x/10.x 备份或就地）升 11.1 走版本链约束（不可跳代细节 ⚠️）；SP/补丁级别与目录视图不匹配会产生 SQLP? 类症状，查 LEVELINFO（⚠️ 命令名从文档）。
4. 卸载次序题：停实例→删实例→卸代码；Windows 先停服务。

## 六、常见事故与排除路径（例题库向）

1. `db2start` 报共享内存/权限错：核对实例所有者身份与残留 IPC（ipclean 习惯，⚠️）。
2. 打补丁后 `db2 => `报 SQL1027N? 实例无效：忘跑 db2iupdt。
3. 用 root 直接建实例：必须实例所有者（或 Windows 管理员凭证走服务）。
4. 端口冲突建实例失败：先查 svcname/services 注册与 firewall。
5. 多实例机器上命令"没效果"：九成是 DB2INSTANCE 指向错实例——先 `db2 get instance`。
6. 装完找不到图形管理件：11.1 已无 Control Center ⚠️，转 CLPPlus/Data Studio（11 章）。

## 七、考点自查清单

- 说出服务器版/客户端版/Runtime 版三选一的理由与产物差异。

## 八·五、自测题（本目录自编，非原书题 ⚠️）

**Q1** 排错题：打完 FP 起实例报"实例配置与代码不匹配"类症状，缺哪步？
**答**：`db2iupdt inst`——补丁只更新了代码副本，实例链接未升级（第五节流程第 1 条；症状描述为社区口径转述 ⚠️）。

**Q2** 选择：20 台应用服务器要连库跑 JDBC，最小安装形态？
**答**：Runtime Client/Data Server Driver（不含 CLP/编目工具），配 DSN 自包含连接串或 DCS 下发（11 章联动）。

**Q3** 判断："DB2_COMPATIBILITY_VECTOR 写在 DB CFG 里。"
**答**：错。它是注册表变量（db2set 面，第四节双轨口诀"db2set=引擎的脾气"），放错层的选项是配对题常客。

**Q4** 排序：Windows 单机升级 11.1 FP 的操作序。
**答**：停应用连接 → 停实例（服务停止）→ 装新副本 → db2iupdt → 起实例 → 验证 `db2level` 类输出版本号（命令名 ⚠️ 以文档为准）。

**Q5** 论述一句：为什么 DB2 把"装代码"和"建实例"拆成两步？
**答**：多实例共享代码副本、补丁按副本统一升级、实例是轻量可增删的运行容器——大机传统的容量治理纪律（与 #77 第 2 章同源答案，MySQL 单进程初始化模型的反衬题）。

## 八·七、本域场景表达两句话

1. 运维句："Db2 升级不是覆盖安装：新副本并行落位，实例逐个 db2iupdt 切换链接，回退=把实例指回旧副本（口径 ⚠️ 转述）。"
2. 排错句："命令没反应先问三件：DB2INSTANCE 指哪、实例起没起、我是不是那个门（SYSADM 组）里的人。"

## 八·九、本域一句话索引（复述练习用）

- 介质：服务器/Client/Runtime 三形态，特性与体积三角。
- 次序：装码→建实例→（建库）；补丁：停→装副本→db2iupdt→起。
- 路由：DB2INSTANCE 是命令的"总闸开关"，多实例事故第一怀疑对象。
- 双轨：CFG 管资源（update dbm/db cfg），db2set 管脾气（行为开关）。
- 平台：Windows=服务+账户，UNIX=进程+IPC+ipclean 习惯。
- 退场：Control Center 不再随 11.1 提供 ⚠️，图形面转 Data Studio/Web 控制台。

## 核心概念速览（中英对照）

- **代码副本** — Install Copy：安装介质落盘的产品二进制目录，实例的供体
- **db2icrt** — Create Instance：建实例命令（认证类型+端口+名）
- **db2start/db2stop** — Instance Lifecycle：实例起停
- **db2iupdt** — Update Instance：补丁后把新代码链接进实例
- **db2ilist** — List Instances：枚举本机实例
- **DB2INSTANCE** — Env Variable：路由 db2 命令到目标实例
- **DBM CFG** — Database Manager Configuration：实例级参数集
- **注册表变量** — Registry Variable：db2set 管的引擎行为开关
- **兼容性向量** — DB2_COMPATIBILITY_VECTOR：开启方言兼容（ORA 等）
- **Fix Pack** — FP：11.1 时代的主要补丁形态（FPn）
- **Runtime Client** — 运行时客户端：只含驱动库的最小连接形态
- **ipclean** — IPC Cleanup：UNIX 残留共享内存清理习惯动作（⚠️）
- **SYSADM_GROUP** — DBM 参数：指定实例管理员 OS 组

## 最新演进与工业实践

- 安装面演进：11.5/12 延续"装码→建实例→建库"三级秩序（✅ 文档入口 https://www.ibm.com/docs/en/db2 ）；云托管形态（Db2 on Cloud 等）把前两级交给平台，DBA 直接面对建库与参数——本域的"命令谱"降维为"平台操作"，但考试级理解仍需本地装免费件走一遍（本目录未实测 ⚠️）。
- 补丁形态变化：FP 之外，11.5.x 起引入连续交付式版本轨（年更叙事 ⚠️ 转述），11.1 的"四代 FP"记忆法到 2024–2026 已过时；备考现行认证请重新对表。
- 容器化：官方与社区提供 Db2 容器镜像用于开发学习（docker 渠道以 IBM 发布物为准 ⚠️），安装域在 CI 时代变成"镜像选择+许可证确认"。
- 工业惯例：多实例隔离（应用/库分组）、补丁窗口与回退预案仍是 DB2 运维纪律核心；跨引擎同题可参照 PG/MySQL 的 00 中"参数分层"讨论。
- 工具替代史：Control Center 之死（11.1）→ Data Studio/DSM 接管图形面（⚠️ 转述）；CLPPlus 到 2024–2026 也进入收缩叙事，CLI 脚本 + 云平台控制台是当下主流。
