## 核心精讲

（以下为教学性梳理，伪代码/配置均**教学示意，不参与构建**。）

### 1.1 分布式系统：从「一台机器」到「一群机器」

- **白话定义**：原本在一台机器上跑的应用，因为**单机性能天花板**（CPU/内存/磁盘/连接数）
  或**可用性要求**（一台挂了全挂），被拆到多台机器上协同工作，对外仍像一个系统。
- **发展历程（教学示意）**：

```text
# 教学示意，不参与构建：系统形态演进
单机应用  ->  单机 + 数据库  ->  应用集群 + 负载均衡  ->  服务拆分(微服务) + 中间件
  (一台)      (读写分离/主从)     (无状态横向扩展)          (缓存/消息/协调解耦)
```

- **四大典型特性与取舍**：

| 特性 | 含义 | 典型取舍 |
| --- | --- | --- |
| 高并发 | 单位时间内处理大量请求 | 加机器（横向扩展）但带来一致性难题 |
| 高可用 | 部分节点故障仍对外服务 | 冗余副本，但副本间要同步 |
| 可扩展 | 加机器能线性提升能力 | 要求无状态/数据可分片 |
| 一致性 | 多副本看到相同的数据 | CAP：一致性、可用性、分区容错不可兼得 |

- **常见问题**：网络分区/延迟、节点宕机、消息丢失/重复、数据不一致、时钟不同步、
  分布式事务难做。这些恰恰不是业务代码该操心的，而是**中间件**该兜底的。

### 1.2 分布式中间件：把共性难题「产品化」

- **白话中间件**：夹在「业务应用」和「底层 OS/网络/存储」之间的一层**通用、可复用、独立部署**
  的基础软件。业务方不用自己手搓一套一致性协议，直接调中间件的 API 即可。
- **本书主线四款**：

| 中间件 | 类别 | 解决的核心问题 | 原书对应章 |
| --- | --- | --- | --- |
| Redis | 缓存中间件 | 高频读加速、热点数据共享 | 第 3–4 章 |
| RabbitMQ | 消息中间件 | 异步解耦、流量削峰、可靠投递 | 第 5–6 章 |
| ZooKeeper | 协调中间件（书中仅作锁实现） | 分布式协调、选主、配置 | 第 7.4 章 |
| Redisson | 综合中间件（基于 Redis） | 分布式锁、并发集合、限流等高级语义 | 第 8–9 章 |

### 1.3–1.4 本书要点与实战建议

- 核心要点：**Spring Boot 为基座 + 四款中间件 + 真实业务场景（抢红包/订单超时/书籍抢购/点赞排行榜）**。
- 实战建议：JDK 8 + Maven + IDE（IntelliJ IDEA 本书默认）；强调**动手跑代码**，
  因为分布式效果（并发、一致性）只有真跑起来才能体会。

## 版本演进

- **本书无第二版**；本节写 2020 年口径 → 2026 年视角的变化。
- **「分布式系统发展历程」到 2026 已走过云原生阶段**：2020 年本书讲的是「裸机/虚拟机 + 中间件」，
  2026 年主流已是**容器（K8s）+ Service Mesh + Serverless**，中间件多半以**托管服务**形态存在
  （不再自己装机架 ZK 集群，而是用云厂商的托管 Redis/RabbitMQ/ZK）。
- **CAP/BASE 的讲法没变，但工程落地更成熟**：2026 年「最终一致」已被事件溯源、CDC（Debezium）、
  Saga 等模式系统化，不再是「知道 BASE 这个词」就够。
- **中间件的「产品化」边界在扩张**：Redisson 这类「基于 Redis 的分布式对象」正是 2020 年后的趋势——
  把锁、信号量、限流器等并发原语直接做进客户端。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「分布式系统就是加机器」 | 加机器带来一致性、时钟、故障等新难题；不是无脑堆硬件 |
| 2 | 「CAP 三选二，随时可牺牲一致性」 | 分区容错 P 在分布式下基本必须保；实际是在 C 与 A 之间按场景取舍 |
| 3 | 「中间件能解决所有分布式问题」 | 中间件屏蔽共性难题，但分布式事务、幂等、边界用例仍需业务层兜底 |
| 4 | 「学中间件就是背 API」 | 必须理解它解决的是 1.1.4 的哪类问题，否则选型会错 |
| 5 | 🔧 本书把 ZooKeeper 归为「统一协调管理中间件」 | 真实目录里 ZK **只在第 7 章作锁实现**，未讲 znode/Watcher/集群；系统学 ZK 需另读 `../ZooKeeper-分布式过程协同技术详解.md` |
| 6 | 🔧 本书环境教学偏「本地裸装」 | 2026 年主流是 Docker Compose + 云托管，本地裸装仅适合学习 |
| 7 | 🔧 本书未提云原生/Service Mesh | 2026 年中间件多运行在 K8s 之上，Operator 模式接管了部署与运维 |
