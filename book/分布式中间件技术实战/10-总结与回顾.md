### 全书主线回顾（教学示意）

```text
# 教学示意，不参与构建：本书一条龙
Spring Boot 基座(第2章)
   ├─ Redis      缓存/计数/原子操作         (第3-4章: 抢红包)
   ├─ RabbitMQ   异步解耦/可靠投递/延迟      (第5-6章: 登录日志/订单超时)
   ├─ ZooKeeper  仅作分布式锁的一种实现      (第7.4章: 书籍抢购)
   └─ Redisson   基于Redis的分布式对象/锁    (第8-9章: 点赞排行榜)
```

- **认知闭环**：第 1 章讲「分布式系统有什么问题」→ 第 2 章搭基座 → 第 3–9 章逐个中间件「理论+项目」
  → 第 10 章收口。每款中间件都对应 1.1.4 里的一类分布式难题。
- **最重要的工程教训**（贯穿全书）：缓存要防穿透/击穿/雪崩、消息要 Confirm+ACK+幂等、
  锁要原子加锁+防误删+续期、高并发要用原子操作+异步落库。

- **2026 年中间件格局小结**：Redis 从缓存扩为数据平台、RabbitMQ 在复杂路由仍占优但高吞吐场景让位
  Kafka/RocketMQ/Pulsar、ZK 更多退居「Kafka/Hadoop 的协调底座」而非业务首选锁、Redisson 成为
  Java 侧「Redis 即并发框架」事实标准。本书 2020 年选的四款，到 2026 仍是健康且主流的选择，
  只是要把上述演进与缺口补上。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「学完本书就会用所有中间件」 | 本书只覆盖 Redis/RabbitMQ/ZK(锁)/Redisson；Kafka/ES/配置中心等未讲 |
| 2 | 「中间件能解决全部分布式问题」 | 分布式事务、限流、可观测仍需额外体系（见 00-缺口） |
| 3 | 「照书代码可直接上生产」 | 书代码是教学基准；生产需补高可用、安全、监控、容错 |
| 4 | 🔧 本书 ZooKeeper 仅作锁 | 系统学 ZK 需另读 `../ZooKeeper-分布式过程协同技术详解.md` |
| 5 | 🔧 本书只讲 RabbitMQ | 2026 应补 Kafka/RocketMQ/Pulsar 选型对照 |
| 6 | 🔧 本书锁定 Spring Boot 2 / Java 8 | 2026 迁移需注意 Jakarta 命名空间与 Java 17 |
| 7 | 🔧 缺分布式事务/限流/可观测 | 生产三大必备，本书未专章覆盖 |
