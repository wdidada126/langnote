## 核心精讲

教学示意，不参与构建：

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

v = Vector(1, 2) + Vector(3, 4)
print(v)                          # Vector(4, 6)
print(v == Vector(4, 6))         # True
```

鸭子类型（duck typing）：Python 不靠继承判定"能否用"，而看对象有没有对应方法。`__add__` 存在即可被 `+` 调用。

## 版本演进

- 3.7（2018）：`dataclasses` 自动生成 `__eq__`/`__repr__`（PEP 557）。
- 3.12（2023）：`override` 装饰器标记重写父类方法（PEP 698），减少误改名。
- 3.8（2019）：`Protocol`（PEP 544）正式描述结构化子类型（静态检查层面）。

## 经典论文与原始文献

- PEP 544（2018）https://peps.python.org/pep-0544/ 静态协议 `typing.Protocol`。
- PEP 698（2022）https://peps.python.org/pep-0698/ `typing.override`。

## 近年研究与工业界开源实践（2015–2026）

- `Protocol` + `mypy`/`pyright` 把鸭子类型纳入静态检查（🔧 非同行评审）。
- `@dataclass` 几乎取代手写值对象方法（见 [15-类和对象.md](15-类和对象.md)）。

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
|---|---|---|
| 手写 `__eq__`/`__repr__` | 样板 | `@dataclass` |
| 未提 `Protocol` | 鸭子类型无静态保障 | `typing.Protocol` |
| 重写方法无标记 | 父类改名静默失效 | `@override`（3.12+） |
