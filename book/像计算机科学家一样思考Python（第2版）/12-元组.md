## 核心精讲

教学示意，不参与构建：

```python
# 打包与解包（函数多返回值本质就是返回元组）
def min_max(xs):
    return min(xs), max(xs)

lo, hi = min_max([3, 1, 4, 1, 5])
print(lo, hi)                # 1 5

# 元组作字典键
pos = {}
pos[(0, 0)] = "origin"
print(pos[(0, 0)])           # origin

# 命名字段（替代下标，提升可读性）
from collections import namedtuple
Point = namedtuple("Point", ["x", "y"])
p = Point(1, 2)
print(p.x, p.y)              # 1 2
```

## 版本演进

- `namedtuple` 自 2.6 起在 `collections`（🔧 非 PEP 提案，直接实现）。3.6+ 推荐 `typing.NamedTuple`（可加类型注解）。
- 3.7（2018）：`dataclasses`（PEP 557）作为可变的 `namedtuple` 替代，更灵活。
- 3.11（2022）：`Self` 类型、更清晰的 `tuple[int, int]` 注解（PEP 585）。

## 经典论文与原始文献

- PEP 557（2017）https://peps.python.org/pep-0557/ 数据类 `dataclasses`。
- PEP 585（2019）https://peps.python.org/pep-0585/ `tuple[int, str]` 注解。

## 近年研究与工业界开源实践（2015–2026）

- 需要不可变+可哈希+命名字段：`typing.NamedTuple`；需要可变：`@dataclass`（🔧 非同行评审）。
- 现代轻量结构化数据也可用 `pydantic`（运行时校验，🔧 非同行评审）。

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
|---|---|---|
| 用下标 `t[0]` | 可读性差 | `namedtuple` / `NamedTuple` |
| 未提 `dataclasses` | 可变记录需求 | `@dataclass` |
| 含 list 的 tuple 仍"不可变" | 元素可变 | 区分容器不可变/元素可变 |
