## 核心精讲

教学示意，不参与构建：

```python
class Card:
    def __init__(self, suit, rank):
        self.suit = suit
        self.rank = rank
    def __repr__(self):
        return f"{self.rank}{self.suit}"

class Deck(Card):                 # 仅为示意：实际 Deck 含多张牌，此处演示 super
    def __init__(self, trump):
        super().__init__("♠", "A")   # 调父类初始化
        self.trump = trump

print(Deck("♥"))                 # A♠（演示用）
```

更贴近原书：用 `list` 组合（has-a）存 52 张牌，比"Deck 继承 Card"更符合组合优于继承。

## 版本演进

- 3.0：`super()` 无条件参数写法 `super().__init__()`（Python 2 需 `super(Deck, self)`）。
- 3.5（2015）：协变/类型系统中子类关系可注解（PEP 484）。
- 3.12（2023）：`@override` 标记（PEP 698）。

## 经典论文与原始文献

- Gamma 等《设计模式：可复用面向对象软件的基础》（GoF，1994）提出"组合优于继承"（🔧 以版次为准）。
- PEP 3135（2007）https://peps.python.org/pep-3135/ 无参 `super()`。

## 近年研究与工业界开源实践（2015–2026）

- 现代更常用组合/`dataclass`/`Protocol` 而非深继承树（🔧 非同行评审，社区共识）。
- 多重继承用 `super()` 按 MRO 顺序调用；`@dataclass` 支持多父类字段合并。

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
|---|---|---|
| `super(Sub, self)` | 冗余/易错 | 无参 `super()` |
| 深继承树 | 脆弱、紧耦合 | 组合/has-a |
| 未提 `@override` | 误改父类方法静默 | `@override`（3.12+） |
