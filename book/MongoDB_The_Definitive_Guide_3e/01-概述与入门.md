## 精读笔记

### 1. 为什么是 MongoDB（2013 叙事）

书开篇的四个卖点——易用（文档模型贴近对象语言）、可扩展（分片是一等公民）、功能丰富（索引/聚合/固定集合）、性能（内存映射存储 + 自然顺序）——是 2010 年代 NoSQL 运动的通用话术。注意其技术底色：

- **文档 = BSON**：类 JSON 但带类型（日期、二进制、ObjectId、正则、minKey/maxKey），单文档上限 **16MB**（由早期 4MB 放宽而来，书中作为容量教训讲解；放宽的精确版本 ⚠️ 未核验）。
- **集合无强制 schema（dynamic schema）**：同集合内文档结构可不同——书的立场是"模式在应用层"，此立场在第 8 章展开为整套设计方法（见 05 文件）。
- **数据库 = 物理隔离单元**：书中数据库到文件目录一对一映射（每库若干 .ns/.1 数据文件）——这是 MMapv1 的地形学，WT 下已重写但"库=资源边界"语义保留。
- **`_id` 唯一索引不可删**：默认 ObjectId（12 字节：时间戳+机器+进程+计数器），隐含时序性——它是后文 TTL、oplog、change streams 排序语义与键集分页的地基。

### 2. shell 与上手体验

- 第 2 章把 `mongo` 交互式 shell 当作主要教学工具：`use db`、集合即写即建、`db.coll.find().pretty()`、写 JS 脚本给服务器执行。
- `.mongorc.js` 启动钩子与提示符定制：作者借此引出"shell 是 JS 运行时"的本质——这句话在 mongosh 时代以 npm 生态的形式兑现。
- 书中"客户端列表"（各语言驱动雏形）在 2013 年参差严重，这段抱怨是理解驱动换代（见 14 文件）的伏笔。
- shell 断代小纪（⚠️ 年代以 14 文件与官方 shell 页为准）：`mongo`（SpiderMonkey 内嵌、全局锁时代的胶水）→ 5.0 宣布弃用 → 6.0 移除 → `mongosh`（Node 运行时、`--nodb` 模式可当高级计算器、可 `npm install` 库）——工具换代本身就是"shell 从玩具到工程件"的十年。
- ⚠️ 未实测：本机无 mongod，一切 shell 会话体验不可复现；现代等价物见对位表。

### 3. 数据类型（2.4 时代清单）

- 基本类型 + 日期（毫秒精度、UTC 存储）+ 数组（多键索引基础）+ 内嵌文档 + `Code`（JS 函数存库——后成安全隐患）+ minKey/maxKey（分片边界哨兵，与第 14 章 chunk 范围呼应）。
- **本书时代没有的**：Decimal128（3.4）、驱动层统一 UUID（3.9/4.x）、向量 embedding 的 `Double[]` 惯用法（2023+，Atlas Vector Search 时代）。

### 4. ObjectId 解剖（2.6 节的重点，全书地基之一）

12 字节布局：4 字节 Unix 时间戳（秒）+ 5 字节随机值（机器+进程标识的混合）+ 3 字节自增计数器。由此推出三条书中反复使用的性质：

1. **大致时间有序**而非严格有序——同秒内顺序取决于计数器与随机值，不能当精确排序键用（⚠️ 未实测，语义为官方长期文档事实）。
2. **可不连库生成**——客户端即可造 `_id`，这是批量插入与"先定 ID 后写文档"模式的前提。
3. **可反解时间**——取前 4 字节即生成时刻；运维上手艺"从 `_id` 估数据年龄"（`_id.getTimestamp()`）至今在 mongosh 可用 ✅（mongosh 页实抓）。

现代注脚：ObjectId 依然是默认 `_id` 策略，但业务键/时间有序 UUID/ULID 等方案在分区与索引局部性讨论中已成并列选项（09 文件片键语境）。

### 5. "集合即写即建"的账与债

第 2 章演示的惰性建库建表（写第一条才真正创建命名空间）是 MMapv1 文件时代的轻量操作，WT 下依旧成立；但书中未及警告的两笔债在 2026 年由平台补齐：

- **命名债**：集合/库名混用大小写与分隔符导致迁移与权限脚本雪崩——Atlas 与官方建模文档都建议显式命名规范（⚠️ 通识性表述）。
- **幽灵库债**：空库不落盘、`show dbs` 不可见曾让初学者困惑；`db.createCollection()` 显式创建（可带校验器/TTL 选项）是现代标准动作。

## 常见误区（书中显式纠正的）

1. "无模式 = 没有模式"——错，是"模式在应用与约定"，作者反复示范版本字段纪律。
2. "集合/库名随便起"——书中给出命名陷阱（点号、空串、`system.` 前缀保留）。
3. "文档越大越省"——16MB 上限 + 更新搬移成本教做人（05 文件继续展开）。
4. "MongoDB 是 ORM 替代品"——文档模型贴近对象不等于对象持久化；关系完整性仍归你管。
5. "日期类型本地时区"——存的是 UTC 毫秒，显示层才有时区——第 2 章已演示，至今仍是新手头号事故源。
6. "ObjectId 严格有序"——只有**大致**时间序（秒级前缀+计数器），同秒内顺序不保证跨分片/重启单调；当精确排序键用是 09 文件"单调热点"的同族错误（语义见精读第 4 节）。
7. "`show dbs` 看不到我建的库=失败"——空库/空集合不落盘是惰性建库的另一面；显式 `createCollection` 是现代标准动作（精读第 5 节"幽灵库债"）。
8. "副本集默认就是强一致"——默认写关注 `w:1` + 主节点读，故障切换可丢已确认写；线性化要显式 `writeConcern: majority` + `readConcern: majority`（机制账在 06/07/11 三个文件）。

## 核心概念速览（中英对照）

- **文档型数据库** — Document Database：以自描述 BSON 文档为存储与访问单元，模式由应用定义。
- **BSON** — Binary JSON：带类型扩展（日期/ObjectId/二进制/正则）的二进制文档编码。
- **集合** — Collection：同一数据库中的文档容器，不强制统一 schema。
- **动态模式** — Dynamic Schema：同集合文档可有不同字段与类型。
- **`_id` / ObjectId** — 12 字节全局唯一标识，含生成时间；默认唯一索引不可删。
- **MongoDB shell（mongo）** — 旧 JS shell：2013 教学主力，2026 已被 mongosh 取代。
- **mongosh** — 现代官方 shell：Node 运行时 + npm 生态 + Promise API。✅
- **内嵌文档** — Embedded/Sub-document：文档树内层级，表达 1:1/少量 1:N。
- **数组字段** — Array Field：被多键索引逐元素索引的 BSON 数组。
- **16MB 文档上限** — Max BSON Object Size：单文档硬上限，大文件走 GridFS。
- **Atlas** — 官方多云托管平台（2016 上线）：2026 年多数新用户的默认起点。⚠️（上线年份为公开史料）
- **minKey/maxKey** — 分片边界哨兵类型：与 chunk 范围元数据配套。
- **驱动（Driver）** — 各语言客户端：本书处 legacy 世代，2026 为统一新驱动世代。
- **`.mongorc.js` / mongoshrc** — shell 启动钩子两代：从玩具到工程件的十年注脚。
- **惰性建库建集合** — Lazy Namespace Creation：首写才落盘命名空间——"集合即写即建"的机制名。
- **时间有序 ID** — Time-ordered Identifier：ObjectId/UUIDv7/ULID 同族；分片与索引局部性讨论的地基（09 文件）。
