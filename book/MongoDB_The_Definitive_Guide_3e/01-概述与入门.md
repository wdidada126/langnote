## 精读笔记

### 1. 为什么是 MongoDB（2013 叙事）

书开篇的四个卖点——易用（文档模型贴近对象语言）、可扩展（分片是一等公民）、功能丰富（索引/聚合/ capped 集合）、性能（内存映射存储 + 自然顺序）——是 2010 年代 NoSQL 运动的通用话术。注意其技术底色：

- **文档 = BSON**：类 JSON 但带类型（日期、二进制、ObjectId、正则、minKey/maxKey 等），单文档默认上限 **16MB**（2.3.7 前的 4MB 教训被写成专节）。
- **集合无强制 schema（dynamic schema）**：同集合内文档结构可不同——书的立场是"模式在应用层"，这一立场后来在第 8 章展开为设计方法。
- **`_id` 唯一索引不可删**：默认 ObjectId（12 字节：时间戳+机器+进程+计数器），隐含时序性。这是后文 TTL、oplog、change streams 排序语义的地基。

### 2. shell 与上手

第 2 章把 `mongo` 交互式 shell 当作主要教学工具：连库、`use`、集合即建即写、`db.coll.find().pretty()`、JS 脚本文件、`.mongorc.js` 启动配置、shell 助手函数（`rs.status()`、`sh.status()` 其实第 9/13 章才用得上）。⚠️ 未实测说明：本机无 mongod，一切 shell 会话类体验均不可复现；现代等价物见下文。

### 3. 数据类型（2.4 时代清单）

基本类型、日期（毫秒精度 UTC）、数组（多键索引的基础）、内嵌文档、`_id`/ObjectId、Code（JS 函数存库——后成安全隐患）、minKey/maxKey。**本书时代没有的**：Decimal128（3.4）、UUID 类型标准化（3.9 驱动层）、矢量字段惯用法（2023+ 用 `Double[]` 存 embedding）。

## 2013 基线 → 2026 现状对位勘误

| 本书说法（2013） | 2026 现状 | 依据 |
|---|---|---|
| `mongo` 交互式 shell 是标准入口 | 旧 shell 5.0 弃用、6.0 移除；**mongosh**（JS 运行时、可 npm 装包、Promise API）是唯一官方 shell | ✅ https://www.mongodb.com/docs/mongodb-shell/ |
| 从 mongodb.org 下 tar 包跑 mongod | 官方不再提供 Windows 服务器二进制（5.0 起）；主流路径是 Docker 镜像或 **Atlas** 云托管；社区版下载页现行为 8.x 线 | ✅ https://www.mongodb.com/try/download/community （current 为 8.x）；https://www.mongodb.com/docs/manual/administration/install-community/ |
| BSON 文档类型清单（无 Decimal128/UUID 语义） | 类型扩展：Decimal128、UUID（驱动 3.9+ 统一）、`Date` 仍是毫秒 UTC；16MB 文档上限不变 | ⚠️ 版本细节推定，上限为官方长期文档事实 |
| Code 类型可存 JS | 仍存在但被 `$where`/mapReduce 一道被视为安全与性能反模式，现代教程不再教 | ⚠️ 未实测 |
| 概念地图："集合无模式，随便写" | 3.6+ **JSON Schema 校验器**（`validator`/`validationLevel`）可强制模式；Atlas 有 schema 分析 | ✅ https://www.mongodb.com/docs/manual/data-modeling/ |
| ObjectId 手工生成惯例 | 不变；但驱动默认 `_id` 生成、以及新增的有序 UUID 策略（如 Atlas 应用层）并存 | ⚠️ |

## 核心概念速览（中英对照）

- **文档型数据库** — Document Database：以自描述 BSON 文档为存储与访问单元，模式由应用定义。
- **BSON** — Binary JSON：带类型扩展（日期/ObjectId/二进制/正则）的二进制文档编码。
- **集合** — Collection：同一数据库中的文档容器，不强制统一 schema。
- **动态模式** — Dynamic Schema：同集合文档可有不同字段与类型。
- **`_id` / ObjectId** — 12 字节全局唯一标识，含生成时间，默认唯一索引不可删。
- **MongoDB shell** — 旧版 `mongo` JS shell；2013 教学主力，2026 已被 mongosh 取代。
- **mongosh** — 现代 Node/JS 官方 shell，支持 npm 包、Promise API、语法检查。✅ 官方页实抓
- **内嵌文档** — Embedded/Sub-document：文档树内层级表达一对一/少量一对多。
- **数组字段** — Array Field：BSON 数组，被多键索引（multikey index）逐元素索引。
- **16MB 文档上限** — Max BSON Object Size：单文档/BSON 载荷硬上限，大文件走 GridFS。
- **Atlas** — 官方托管云平台（2016 上线），2026 年多数新用户的默认起点。⚠️ 上线年份为公开史料
- **工作集** — Working Set：被频繁访问的内存数据+索引集（第 21 章深化）。

## 最新演进与工业实践

- **入口变更是最大勘误**：2013 年"装 mongod + 开 mongo shell"的三步上手，2026 年工业实践通常换成 `atlas local`（官方 CLI，早期版本曾名 mongodb-atlas）或 Docker `mongod:8.x` + mongosh；下载页与安装文档见 ✅ https://www.mongodb.com/docs/manual/administration/install-community/
- **API 形状本地可验，行为需服务端** 🔧：`python -m pip install pymongo`（4.18.2）成功，`from pymongo import MongoClient` 可导入；无 mongod ⇒ 所有"连接/建库/建集合"体验性结论 ⚠️ 未实测。PyMongo 官方文档：✅ https://www.mongodb.com/docs/drivers/pymongo/
- **驱动世代断层**：本书使用 legacy driver API（`safe=True` 等）。2018–2020 官方重写全套驱动（统一 CRUD API、retryable writes 默认开、connection string `retryWrites=true` 语义变化），旧 API 在 PyMongo 4.x 中大面积移除——读本书示例代码时"能对应上"是常见坑。⚠️ 细节以驱动官方迁移指南为准
- **许可前提已变**：本书假设"MongoDB 是开源（AGPL）"；2018-10-16 起服务器核心改 **SSPL v1**（4.2 起），OSI 不认可为开源；商业托管与开源替代生态因此重构（详见本目录 14 与 00 谱系节）。SSPL 原文页 ✅ https://www.mongodb.com/licensing/server-side-public-license
- **2026 版本线**：官方下载页 current 标注 8.x（"our fastest version ever" 宣传语指 8.0）；本书 2.4 基线与 8.x 之间隔着 WT 接管、事务、change streams、聚合扩张、Atlas Search/Vector Search 五大断层，各章文件尾部逐条对位。
