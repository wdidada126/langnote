## 精读笔记

### 1. 进程与配置（第 20 章）

- `mongod` 命令行/配置文件（`mongod.conf` YAML 前身）、`fork` 守护化、`--shutdown` 命令（书中标准停机，后由信号/systemd 取代）、`--dbpath` 与"别用 kill -9"的告诫。
- **安全观（2013 相当原始）**：默认无认证；作者给的清单 = 防火墙隔离 + 不暴露 27017 + `--auth` + keyFile；**静态数据加密缺位**（书中寄望 OS/文件系统级）；SSL 社区版可用但性能有顾虑。⚠️ 这一节是"当年粗粝"的最好标本。
- 日志：`--logpath/logappend/syslog`，"别把日志放数据库同盘"。

### 2. 内存与性能（第 21 章：MMapv1 的心电图）

- 世界观："**工作集必须装进 RAM**"——虚拟内存 + mmap 让 OS 页缓存即数据库缓存：读 `res/virtual`、缺页率（`mongostat` 的 `page_faults`）、`index miss`、后台刷新时间构成仪表盘。
- `db.serverStatus().mem` + `extra_info`（page_faults）+ OS 工具（vmstat/free）双向对账；工作集估算法 = 活跃索引 + 热文档大小。
- 21.3 性能：`mongoperf`?（保守：书中用文件系统基准与 `db.stats` 联查）+ "锁定百分比"是 MMapv1 全局锁时代的头号 SLI。
- 21.4 复制监控衔接 12.4（oplog 滞后、成员健康）。

### 3. 启停机制剧本（20.1–20.2 的"干净停机三步判据"）

书中停机教条 = `db.shutdownServer()`（旧 `--shutdown`），其"干净"判据三条件至今成立（⚠️ 文档转述）：

1. **最后一条日记已刷盘**——WT 时代对应"最后一次 checkpoint 完成 + journal 关闭"，否则重启走恢复流程、慢且有窗口损失（11 文件的断电剧本反向播放）；
2. **无进行中操作**——`currentOp` 可见活跃读写（10 文件），强杀=客户端孤儿游标 + 复制断流；
3. **网络仍可达**——供其他成员的心跳确认它"体面退场"而非被判死（06 文件选举语境：干净关闭的成员不触发紧急选举）。

   启动侧同理：书中"起不来先看日志最后一行"的手艺 2026 依旧——`mongod.log` 首屏是配置解析错误（YAML 缩进/非法选项），中段是存储引擎恢复（WT 文件锁、日志重放进度），尾屏才是网络绑定失败（`--bind_ip_all` 安全默认与防火墙）。三层各自的抢救路径在官方安装/配置文档有对位页（⚠️ 未实测）。

### 4. 内存监控判读详解（21.1–21.2：从 OS 页缓存到 WT 自管缓存）

- **书时代三层读法**：`free`（OS 空闲）→ `res`（mongod 驻留）→ `page_faults`（mmap 工作集溢出）——作者给的告警公式是"缺页率持续>0 且 free≈0 ⇒ 工作集超内存"。
- **WT 时代对位三层**（⚠️ 文档转述）：`wiredTiger.cache` 的 `bytes currently in the cache` vs `maximum bytes configured`（配额水位）；`tracked dirty bytes in the cache`（脏页比，checkpoint 压力的先导）；evgression 计数——现代告警公式是"脏页比持续顶阈值 ⇒ 磁盘写跟不上 ⇒ 前台延迟抖动"。
- **工作集估算法原样存活**（官方词汇仍是 working set）：活跃索引体积 + 热文档体积；WT 的块压缩 + 缓存自管把"装得下"的门槛实际抬高 2–4 倍（书里 MMapv1 数字直接换 WT 数字必错）。
- 书中"减少索引树脱靶（index miss）"手艺的现代化身：索引覆盖度与前缀复用（03 文件），配合 `wiredTiger.index` 的访问计数判冷热。⚠️

### 5. 20.3 安全六层部署次序（2026 重排版）

1. **网络隔离**：bind_ip/私有子网/安全组——书中"别暴露 27017"仍是第一层，且默认更保守（bind 到 localhost）；
2. **内部认证**：keyFile → x.509 互信（副本集/分片成员间），书中 keyFile 三件套的遗产；
3. **传输加密**：TLS（书里"SSL 性能顾虑"早成历史，TLS1.2 起步）；
4. **访问控制**：RBAC + 最小角色 + 项目级权限（书中 addUser 的现代化）；
5. **审计**：企业版/Atlas 合规刚需，2013 无此层；
6. **数据加密**：At-rest（企业版）+ 字段级 FLE + Queryable Encryption（7.0+）——书中"指望文件系统"的空白被三层产品填上。⚠️（次序为通行实践归纳，功能名以官方安全文档为准）

## 2013 基线 → 2026 现状对位勘误

| 本书说法（2013） | 2026 现状 | 依据 |
|---|---|---|
| `--shutdown` 停机 | 命令移除；**SIGTERM + systemd**（`TimeoutStopSec` 给足 flush 时间）是标准姿势 | ⚠️（长期文档事实）|
| 默认裸奔 + 防火墙兜底 | 默认安全趋势：绑定 localhost、`--bind_ip` 显式化；认证/TLS 成生产准入项；**动态/静态加密**：At-rest encryption（企业版 AES-CBC/256）、**Queryable Encryption（7.0 GA，客户端加密+可查询）**、字段级 FLE | ✅ https://www.mongodb.com/docs/manual/release-notes/8.0/（同域实抓；7.0 项 ⚠️ 未核 release 页）|
| SSL 可选、性能存疑 | TLS 1.2+ 强制化（6.0 起禁用 TLS1.0/1.1——⚠️ 细节见 6.0 notes），证书管理进平台 | ✅ https://www.mongodb.com/docs/manual/release-notes/6.0/（实抓）|
| OS 页缓存当数据库缓存（mmap） | **WT 自管缓存**（`cacheSizeGB`），缺页/`page_faults` 指标成历史；监控转 `wiredTiger.cache` 命中/脏比/checkpoint 时长 | ✅ WT 页实抓 |
| 工作集 = RAM 硬约束 | 约束精神仍在（"working set" 官方词汇保留），但 WT 压缩（snappy）+ 块缓存使可比数据量放大数倍 | ✅ WT 页 |
| serverStatus/mongostat 手工拉 | 指标仍在但结构化：FTDC、Prometheus 生态 exporter、Atlas 仪表板/Ops Manager；`currentOp` 聚合化（10 文件） | ⚠️ |
| 日志 = 纯文本轮转 | 支持 **JSON 结构化日志**（`logFormat: JSON`）+ 可配置组件 verbosity；ELK/Loki 直接摄取 | ⚠️ |

## 监控指标→症状→处置对照表（21 章的"看缺页吃药"现代化）

| 头排指标（2026） | 异常形态 | 最可能症状 | 第一处置 |
|---|---|---|---|
| `wiredTiger.cache` 脏页比 | 持续顶阈值 | 前台写延迟抖动（checkpoint 抢 IOPS） | 加大磁盘预算/降写入峰/扩 cacheSizeGB（11 文件） |
| eviction 耗时 | 突发飙升 | 查询被"帮忙逐出"拖慢 | 检查扫描量暴涨的查询（10 文件 currentOp） |
| `connections.current/available` | 逼近 max | 新连接超时、驱动池排队 | 先查连接放大（mongos×池，09 文件）再调上限 |
| oplog 窗口（optimeDate 差推算） | 短于修复时长 | 成员掉线即全量初始同步雪崩 | 扩 oplog（`replSetResizeOplog`，07 文件算法） |
| `asserts`/`metrics.errors` 增量 | 持续非零 | 隐性数据/内部错误积累 | 存证 + FTDC 包上报（官方监控文档） |
| page_faults（书时代） | 持续>0 | 工作集溢出、延迟毛刺 | 加 RAM 或减热数据——WT 下此列不存在，对位上两行 |
| `logicalSessionTimeoutMinutes` 相关会话堆积 | 高并发短连接 | 会话表膨胀、认证开销 | 连接池复用（驱动统一池模型，07 文件） |

⚠️ 全表为文档通识归纳，无本机实测；阈值语义各版本有出入，判读以对应版本文档为准。

## 常见坑（本目录归纳，书中多有其原型）

1. **"kill -9 救急"**——书中已警告：脏关闭让下次启动进恢复流程（journal/日志重放），恢复期间不可服务；勒索/断电之外，运维强杀是人为制造恢复窗口。
2. **"res 高=内存泄漏"**——WT `cacheSizeGB` 就是设计来"吃满配额"的，驻留高不等于漏；看书用 page_faults 交叉、看 WT 用脏页比交叉（21.1 的"计算机内存常识"节正是教这个）。
3. **"日志和数据同盘省钱"**——书中 20.4 告诫；checkpoint 刷盘与日志写互相踩踏，fsync 延迟放大成全局抖动。
4. **"服务器时间漂移无所谓"**——副本集心跳/选举超时与 oplog 时序对时钟敏感（23 章 ntp 纪律在 13 文件），Kerberos 更是直接拒签漂移票。
5. **"swap 开着当保险"**——书中主张关 swap 或 swappiness=0：数据库页被换出的一次访问=毫秒级页空洞；现代容器化部署改以"内存 limit+无 swap"实现同一意图。⚠️
6. **"监控=装个面板"**——21 章真正教的是**指标间的因果链**（缺页→延迟→队列→断连）；面板只会显示数字，判读模型还得回书里学。

## 核心概念速览（中英对照）

- **mongod.conf** — 配置文件：YAML 结构（3.x 起标准化），书中为命令行时代。
- **SIGTERM 停机** — 优雅关闭：flush + 释放锁，替代 `--shutdown`。
- **工作集** — Working Set：热数据 + 索引；容量规划第一单位（书与现在同词）。
- **缺页中断** — Page Fault：MMapv1 时代的头号性能信号。
- **后台刷新** — Background Flush（书中 fsync 周期指标）：WT 下变成 checkpoint。
- **serverStatus** — 综合健康快照命令：`mem/locks/wiredTiger.*` 分层。
- **keyFile / x.509** — 集群内部认证两代方案。
- **Queryable Encryption** — 可查询加密（7.0+）：密文上匹配/范围查询的现代答案。⚠️
- **审计日志** — Audit Log（企业版）：合规刚需，书中无此概念。
- **FTDC** — 全时诊断采集（3.2+）：服务端自动指标录像带。
- **mongos 连接治理** — maxConnecting/pool：书中"20000 连接 myth"之后的驱动统一池模型。⚠️
- **干净停机三步判据** — Clean Shutdown：日记刷尽+无进行中操作+网络仍可确认——2013/2026 同构。
- **cacheSizeGB** — WT 自管缓存配额（"物理内存一半"经验式）：现代内存判读的原点。⚠️
- **脏页比（dirty cache）** — checkpoint 压力的先导指标：WT 时代的"缺页率"。⚠️
- **TLS/X.509 互信** — 传输加密+内部认证的现代底座：书中 keyFile/SSL 顾虑的终点。

## 最新演进与工业实践

- **启动方式的三世代**：裸金属 init 脚本（书）→ systemd/docker-compose（自建主流）→ Atlas/K8s Operator（新部署默认）。配置面从 `mongod` 参数清单迁到 YAML + 平台 API。
- **安全清单重写**：2026 上线检查 = 网络隔离（VPC/PrivateLink）+ TLS + SCRAM/X.509 + RBAC 最小权限 + 审计 + At-rest/QE 加密 + 备份加密——书中 20.3 的三行清单扩展了一个数量级。⚠️（条目来自官方安全文档通识）
- **监控栈**：`mongostat/mongotop` 仍在官方 "MongoDB Database Tools" 包里，但生产角色降级；现代指标面 = 命令快照（serverStatus/currentOp）+ 结构化日志 + agent（exporter/Ops Manager/Atlas）三路采集（书中 `--rest/httpinterface` 那页早已移除）。⚠️
- **NUMA 与内存**：书中"禁用 NUMA/透明大页"建议（23 章，13 文件）在 WT 时代由 `numactl`/`zone_reclaim` 调优传统延续；`disableTransparentPageSwapping`? 保守：THP 关闭建议至今常见于安装文档。✅ install-community 页实抓
