## 精读笔记

### 1. 聚合框架：书内最"新"的东西

- 框架仅一年历史（2.2 引入），作者定位："声明式流水线，SQL 的 GROUP BY 家族 + 文档加工"。
- 编排纪律：**`$match` 前置吃索引**；`$project` 瘦身；`$unwind` 摊平数组（书中反复演示 unwind→group 即"数组元素计数"万能式）；`$sort/$limit/$skip` 的组合顺序影响性能。
- `$group` 累加器（`$sum/$avg/$push/$addToSet/$first/$last`）+ 表达式操作符（`$cond/$ifNull/$concat/日期函数`）——作者提醒这是"另一门要背的小语言"。
- **时代硬限制**：内存小配额后落临时文件、结果不能写回集合（16MB 内联封顶）→ 书中给出"管道输出手工写回"的 workaround，正是后来 `$out/$merge` 要填的洞。

### 2. MapReduce：被偏爱的过渡方案

- map/reduce/finalize + JS 作用域变量 + query 过滤 + inline/output 集合；`{reduce: "merge"}` 增量归约是本章技术含量最高点。
- 两个示例刻意选"管道做不到/别扭"的场景（全键统计、按域名分组的网页分类）——2013 年合理，2026 年看是路标错误：MapReduce 的全部席位被管道后续 stage 接管（见对位表）。

### 3. 聚合命令三件套

- `count`：与索引交互的计数语义（带查询时走不走索引）。
- `distinct`：数组摊平去重；书中已建议大数据量改管道。
- `group`：带 finalize 的 JS 分组，10 万文档/不可分片限制——本书时代就被劝退，随后整个命令消失。

### 4. Stage 族谱：书中八件套与后来者（⚠️ 引入版本按通识标注）

| 时代层 | 成员 | 一句话 |
|---|---|---|
| 2013 首发（本书） | `$match/$project/$group/$unwind/$sort/$limit/$skip`（+`$LIMITH/$SKIPH` 类内部优化器把戏，书中已提"可交换律优化"） | 管道骨架 |
| 2.4–2.6 | `$redact`（文档级权限过滤）、`$out`（写回）、`$sample` | 补"输出"与"抽样" |
| 3.2–3.4 | `$lookup`（左外连接）、`$facet`（并行多路子聚合）、`$graphLookup`（图遍历）、`$bucket`、`$addFields/$replaceRoot` | join 与分面补课 |
| 4.x | `$unionWith`（前身 `$unionWith` 6.1，4.4 试验 ⚠️）、`$merge`（upsert 语义写回）、`$set/$unset` 别名 | 物化视图引擎成型 |
| 5.0+ | **`$setWindowFields`（窗口函数）**、`$rank/$denseRank` 累加器家族 | SQL 窗口族整体迁入 |
| Atlas 专属 | **`$search` / `$vectorSearch`** | 搜索/向量并入管道 ✅（stage 页实抓） |

结论：7.2 的八件套今天仍是"管道语法完整性的 80%"——**骨架 13 年没改，长出了肌肉**，这是本章最值得自豪的判词。

### 5. 管道优化纪律（书中 7.1.2"限制"+ 7.2.8 组合技的现代版）

1. `$match` 尽量前置且带索引——唯一能"下推到集合扫描"的形态（分片上还能触发 targeted 路由）。
2. `$sort` 在 `$skip` 前？顺序即语义也是成本；`$limit` 前置可让后续 stage 早停。
3. `$unwind` 是放大器：先 `$match` 缩小文档集再摊平；unwind 后再 group 回来是最常见浪费模式。
4. `$project` 瘦身传下游，但**别在 `$lookup` 前删掉连接键**——书里同类警告（字段丢进不出）。
5. 超内存：`allowDiskUse:true` 是第一反应；反复溢盘是 schema/片键问题（回到 09 文件）。
6. 结果集大：`$out/$merge` 落集合再消费，别再指望 16MB 内联——书中 workaround 的正式化。
7. 索引联动判读（explain 聚合视角）：`$match` 前置才能把谓词下推给集合扫描器吃索引；紧随其后的 `$sort` 若与索引前缀同序可被"吸收"成顺扫（避免 32MB 内存排序）；`$group` 及其后的 stage 一律不吃索引——管道优化的本质是**把索引能干的活尽量留在管道门口**。⚠️（机制转述，未实测）
8. 两段式下推的账（分片语境）：含 `$group/$sum` 的管道会被 mongos 自动改写为"shard 初聚合 → mongos 终聚合"，初段选择性越好、跨线传输越小；group key 与片键无关时每个 shard 都要出全场数据——这是"聚合跑不动先查片键"的机制版本（09 文件）。⚠️

## 常见误区（书中显式纠正的）

1. "管道 stage 顺序无所谓"——`$match/$sort` 与 `$unwind` 的先后可以差一个数量级。
2. "MapReduce 一定比管道快"——作者用数据反驳：多数场景管道更快且省内存。
3. "聚合结果能超 16MB"——内联返回封顶，落盘/写回需另行安排。
4. "`$group` 的 `_id` 只能是字段"——可以是任何表达式/复合文档。
5. "`$unwind` 只配数组"——非数组字段直接透传或按 includeArrayIndex 补 null（现代选项）；书中"先 `$size` 过滤再 unwind"的手法仍有效。
6. "聚合跑不动就上分片"——单机内存纪律没做，分片只是把浪费乘以 N；两段式改写还会给 mongos 攒最终结果。
7. "`$limit` 只是语义截断"——它同时是性能杠杆：前置换 early termination、后置等于白算（7.2.8 组合技的现代表述）。
8. "`$out` 写分片集合自动续命"——目标集合须已在同一集群存在/分片就绪，管道输出不是免检搬家；跨库写回受权限与副本集拓扑约束。⚠️

## 2013 基线 → 2026 现状对位勘误

| 本书说法（2013） | 2026 现状 | 依据 |
|---|---|---|
| 管道只能返回游标/16MB 内联 | `$out`（2.6+）/`$merge`（4.2+，upsert/保留未匹配等模式）把管道变成**写回与物化视图引擎** | ⚠️（版本为官方文档通识） |
| 内存超限落盘不可调 | `allowDiskUse(true)` 驱动选项 + 6.x `allowDiskUseByDefault` + 分片侧分阶段预算 | ⚠️ |
| MapReduce 与管道并列两大入口 | **MapReduce 于 6.2 移除**；官方立场"管道替代 mapReduce"；需求分流到 `$group/$bucket/$facet/$unionWith(6.1+)/$setWindowFields(5.0+)` | ✅ https://www.mongodb.com/docs/manual/release-notes/6.0/（同系 6.x 记载；6.2 细节 ⚠️） |
| `group` 命令可用（受限） | 已移除；`distinct` 官方改推 `$group` 管道 | ⚠️ |
| 无 join（聚合不能关联集合） | **`$lookup`（3.2+）左外连接**、`$graphLookup` 递归、`$unionWith` 并流——教义部分推翻，设计哲学仍优先内嵌 | ⚠️ |
| 分析只能单机/手工轮询分片 | 管道原生下推分片集群（$group 两段式自动改写）；Atlas SQL/BI Connector 补 OLAP 门面 | ⚠️ |
| 文本/模糊分析靠 `$text`/自写 | 管道内挂 **`$search`（Atlas Search）与 `$vectorSearch`（向量近邻，ANN/ENN 两模式）**——聚合成为搜索的统一入口 | ✅ https://www.mongodb.com/docs/atlas/atlas-vector-search/vector-search-stage/（实抓） |
| explain 是查询专利 | 聚合 explain 提供 stage 下推/游标视角 | ⚠️ |

## 核心概念速览（中英对照）

- **聚合管道** — Aggregation Pipeline：stage 序列上的文档流变换。
- **`$unwind`** — 数组摊平器：数组内聚合的前置步。
- **累加器** — Accumulators：`$group` 内折叠函数族。
- **表达式操作符** — Expression Operators：管道内纯函数小语言。
- **`$out` / `$merge`** — 写回 stage：物化视图/幂等 upsert（书后时代）。
- **`$lookup`** — 左外连接 stage（3.2+）：join 补课。
- **`$facet`** — 分面聚合：一个管道多路子聚合。
- **`$bucket`** — 直方计分桶：书中手工分桶的官方化。
- **`$setWindowFields`** — 窗口函数（5.0+）：ROW_NUMBER/移动平均入 Mongo。⚠️
- **MapReduce** — map/reduce/finalize JS 方案：本书仍主推，6.2 已从服务器移除。⚠️
- **`allowDiskUse`** — 管道溢盘许可：替代书中"内存限制"告诫。
- **`$vectorSearch`** — Atlas 向量近邻 stage（ANN/ENN）：RAG 检索入口。✅
- **两段式下推** — Pipeline 在分片上的拆分改写（shard 初聚合 + mongos 终聚合）。
- **explain（聚合）** — stage 级计划分析。
- **early termination** — 早停：`$limit` 前置让管道"够用即止"的性能学名。
- **谓词下推** — Pushdown：`$match` 把过滤交给底层扫描/索引的资格认证（管道门口的活）。

## 最新演进与工业实践

- **管道 = 统一语言**：2026 年 `$search/$vectorSearch/$lookup/$merge` 把搜索、关联、物化全部挂进同一条管道；书 7.1 的"框架 vs MapReduce 之争"以管道通吃落幕。✅（两个 Atlas 页实抓）
- **RAG 标准件**：`[$vectorSearch(...), $project(score)]` + 元数据 `filter` 的混合检索——"7.2.8 使用管道"的 AI 续集；索引侧对应 Atlas Vector Search Index（03 文件）。⚠️ 性能未实测。
- **迁移检查单（读 7.3 前）**：全键统计 → `distinct`/`$group`（或 wildcard 索引 + schema 分析）；网页分类 → `$bucket/$facet` 或外部批处理；增量归约 → `$merge` 定时物化。
- **驱动形状（🔧）**：`Collection.aggregate` 在 pymongo 4.18.2 带 `allowDiskUse/batchSize` 语义（签名以官方文档为准）；`watch()` 承担"聚合之外流向外部系统"的 CDC 消费（07 文件）。
- **OLAP 边界仍清晰**：重报表场景 2026 年仍建议湖仓/Flink 阵营（见仓库 big-data 线目录）；官方 BI Connector/Atlas SQL 只覆盖轻量对接——书 8.6"不适合场景"里的报表红线至今有效（05 文件呼应）。
