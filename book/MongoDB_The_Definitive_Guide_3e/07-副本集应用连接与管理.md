# 07 副本集：应用连接与运维管理（原书第 11–12 章）

> 书目：《MongoDB: The Definitive Guide, 3rd Edition》（Kristina Chodorow, O'Reilly, 2013）。精读重构笔记，非原书文本；取证见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。
> 实测环境：pymongo 4.18.2 🔧 import 级（`Collection.watch`、`read_concern/write_concern` 模块可导入）；无 mongod ⇒ 连接路由/选举干预行为 ⚠️ 未实测。

## 阅读目标

- 理解驱动如何"自动发现拓扑"并做读写分离路由——2013 各家驱动参差的背景。
- 掌握写保证的表达（w/j/fsync 前身）与读扩展工具链（tags/延迟/隐藏）。
- 学会 12 章的"状态机干预"与 oplog 窗口容量思维，并知道哪些 API 已换代。

## 章骨架（中文小节 ✅ 实抓自人邮第 2 版目录）

- 第 11 章 从应用程序连接副本集：11.1 客户端到副本集的连接 / 11.2 等待写入复制（可能导致的错误、`w` 的其他值）/ 11.3 自定义复制保证规则（每数据中心一台可见节点、写复制到可见节点的"大多数"、创建其他规则）/ 11.4 将读请求发送到备份节点（一致性考虑、负载考虑、何时可以从备份节点读取数据）
- 第 12 章 管理：12.1 以单机模式启动成员 / 12.2 副本集配置（创建、改成员、较大副本集、强制重新配置）/ 12.3 修改成员状态（主变备、阻止选举、维护模式）/ 12.4 监控复制（获取状态、复制图谱、复制循环、禁用复制链、计算延迟、调整 oplog 大小、从延迟备份恢复、创建索引、预算有限的复制、主如何跟踪延迟）/ 12.5 主从模式（切换、模仿）

## 精读笔记

### 1. 应用侧连接与保证（第 11 章）

- 拓扑发现：给驱动任一成员地址 → `ismaster`（今 `hello`）握手 → 得到全景 + 角色 → 故障重路由。作者逐个语言点评实现质量，附"测试你的驱动"清单（拔主看行为）。
- 写保证三种语言：① `w=n`（n 个成员落地确认）② `w=majority`（书时代尚未定型为关键字，用自定义 write modes 表达）③ `fsync/j`（日记级别）。
- **11.3 自定义规则**（`getLastErrorModes`）：如"每数据中心至少一可见节点确认"——特性后来被整体移除（对位表）。
- 读扩展：`slaveOk/readPreference` 把读甩给备份节点；**一致性 vs 负载**的权衡：报表/延迟节点、缓存预热/隐藏节点、就近/机房 tags——本章 11.4 三小节是当年读写分离的标准教材。

### 2. 运维侧状态机干预（第 12 章）

- **以单机模式启动成员**（不带 `--replSet` 起 mongod）抢救数据文件/修配置——危险手艺。
- `rs.stepDown()`（计划内让位）、`rs.freeze()`（阻止选举窗口）、维护模式（书中经 `db.adminCommand` 旧式，后由 reconfig 表达）。
- 大副本集限制（投票成员上限、心跳开销）；`force` 重配"赌一致性"警告。
- 监控：`rs.status()/printReplicationInfo()`、成员 lag、**oplog 窗口（可回放时长）估算**——"oplog 太短 → 故障成员只能全量初始同步 → 打爆主"的容量因果链是本节精髓（12.4.6 调整 oplog 大小）。
- 12.5 主从模式两小节：从旧架构迁移 + "让副本集装出主从行为"的兼容技法——2026 已无对象。

### 3. 连接字符串即策略（第 11 章的现代汇总面）

| 参数（URI） | 归属章 | 2026 语义 |
|---|---|---|
| `replicaSet=` / 种子列表 | 11.1 | 任一成员均可引导全拓扑发现；种子多点更稳 |
| `readPreference=secondaryPreferred&maxStalenessSeconds=10` | 11.4 | 读扩展 + 陈旧保险丝（书中 `slaveOk` 土法的官方化 ⚠️） |
| `writeConcern=majority&journal=true` | 11.2 | 3.4 的 getLastError 方言的现代拼写 |
| `retryWrites=true&retryReads=true` | —（书后） | 幂等重试补"网络错≠失败"的洞（3.6+ 驱动） |
| `readConcernLevel=majority` | 11.4 一致性小节 | 替代"手工挑节点保一致" |
| `appSessionName/wTimeoutMS/connectTimeoutMS` | 11.1 超时话题 | 超时预算工程化 |

### 4. 计划内切换 runbook（12.3 的仪式化）

1. 目标主预热：确认其 `optimeDate` 追平（lag≈0）且优先级已 `rs.reconfig` 调高。
2. 现主 `rs.stepDown(秒)`（冻结期防旧主立刻抢回——书中 `freeze` 的用途）。
3. 驱动侧：拓扑更新 +（现代）`retryWrites` 兜住切换瞬间的写失败。
4. 验证：`hello` 的 `isWritablePrimary` 迁移、`rs.status()` 全员健康、oplog 无 ROLLBACK 记录。
5. 全程用 12.4 的 lag 监控护航——这套五步在 Atlas"Failover"按钮下原样存在。⚠️ 步骤为文档通识，未实测

### 5. oplog 窗口估算法（12.4.6 的可执行版）

- 窗口 ≈ `oplog 体积 ÷ 写入速率`。书中手工法：取 `rs.printReplicationInfo()` 首尾时间差；或用 `local.oplog.rs.stats()` 体积与 `serverStatus.oplog` 速率对算。
- 运维判据（至今 runbook 原文级可用）：**窗口 > 最坏修复时长**（全量同步 + 索引重建）；备份场景：窗口 > 备份耗时 + 缓冲，否则 PITR 断链（13 文件）。
- 改大小： capped 集合重定义的惊险流程（书中逐字节演示）→ 现代 `replSetResizeOplog` 在线热调（4.4+ ⚠️），是本章最解压的勘误。

### 6. 复制监控命令速查（12.4 的现代命令面，⚠️ 字段以官方 rs.*/serverStatus 文档为准）

| 命令/字段 | 回答的问题 | 判读要点 |
|---|---|---|
| `rs.status()` 成员表 | 谁活着、谁什么角色 | `state`/`health`/`lastHeartbeatMessage`（06 文件状态机） |
| `optimeDate` 差 | 从库滞后多少秒 | 复制滞后唯一硬口径；告警按它设 |
| `rs.printReplicationInfo()` | oplog 窗口有多长 | "可回放时长"= 修复容忍线（上节算法） |
| `rs.printSecondaryReplicationInfo()` | 谁拖后腿 | 含"落后 Xs (Y MB)"——带宽视角 |
| `db.getReplicationInfo()` | 同上（shell 无关版） | 脚本/巡检采集用它 |
| `serverStatus().metrics.repl` | 拉取/应用/网络各段耗时 | 滞后归因：是拉不动还是追不动（转述 ⚠️） |
| `replSetGetStatus` 的 syncSourceHost（5.0+） | 现在从谁复制 | 链式复制复活后的拓扑透视（06 文件对位表） |

官方复制方法文档（2026-09 curl 200）：https://www.mongodb.com/docs/manual/core/replica-set-elections/（选举行为权威页）与部署教程 https://www.mongodb.com/docs/manual/tutorial/deploy-replica-set/ ——12 章的干预动作先在这两页对号再上手。

## 常见误区

1. "加了索引和从库，读就线性扩"——每个从库要独立拉 oplog + 独立建索引；写主不受益。
2. "`w:3` 就是多数派"——成员数变化后语义漂移；majority 是票池概念。
3. "从节点读到旧数据 = bug"——异步复制的定义使然；要因果一致须上会话。
4. "延迟节点是备份"——它防误删，不防磁盘坏（仍要真备份）。
5. "stepDown 会均衡负载"——它只触发一次选举，新主还常是原主（优先级未变时）；负载均衡靠拓扑设计。
6. "readPreference 设了 nearest 就高枕无忧"——跨地域 nearest 读到什么取决于复制滞后，必须配 maxStalenessSeconds。

## 核心概念速览（中英对照）

- **拓扑发现** — Topology Discovery（ismaster/hello）：驱动自动感知成员与角色。
- **写保证** — Write Concern（w/j/wtimeout）：确认强度 = 副本数 + 持久化级。
- **`w:majority`** — 多数派确认：防回滚丢失的最低标准。
- **自定义写模式** — getLastErrorModes（书中特性）：已移除，无直接等价。
- **读偏好** — Read Preference（primary/secondary/nearest + tags）：读写分离路由核心。
- **成员标签** — Tags：机房/角色坐标，11.3 遗产、2026 仍用。
- **maxStalenessSeconds** — 最大陈旧容忍：读路由的现代保险丝。
- **stepDown / freeze** — 让位/冻结选举：计划内切换。
- **oplog 窗口** — Oplog Window：历史可回放时长 = 故障容忍边界。
- **复制图谱/复制链** — Replication Graph/Chain：12.4 观测对象（链已随禁用/复活两度变迁，见 06）。
- **Change Streams** — 变更流 + resume token：官方 CDC 接口。✅
- **retryable writes** — 可重试写（3.6+）：驱动幂等重试。
- **linearizable read** — 线性化读（4.0+）：牺牲吞吐换单分片强一致读。
- **syncSourceHost** — 复制来源透视（5.0+）：链式复制复活后"谁从谁拉"的观测字段。⚠️
- **standalone 抢救启动** — 12.1 手艺：不带 --replSet 直连成员修数据/修配置，危险但唯一后门。

## 最新演进与工业实践

- **Change Streams 接管 11 章读侧花活**：`cluster.watch()`/`coll.watch(pipeline)`（🔧 pymongo 4.18.2 `Collection.watch` 可导入，含 `resume_after/full_document` 参数；⚠️ 未连服务端）。以前"轮询 capped + 记游标"整类消失。✅ changeStreams 页。
- **连接字符串即策略**：`retryWrites/retryReads/readPreference/maxStaleness/writeConcern` 全在 URI——工程评审直接读串定级，这是书中分散章节的平台化终点。
- **运维面换代**：`rs.status` 人肉巡检 → Compass 拓扑图 / Prometheus exporter / Atlas 告警（Cloud Manager 2023 并入 Ops Manager ⚠️ 年份按公开公告）。
- **多区域容灾**：书中"跨数据中心写规则"在 2026 = Atlas Global/多区域集群 + zone 感知多数派；自建仍是 tags + writeConcern 组合拳。⚠️
- **延迟预算文化**：12.4"预算有限的复制"一节精神被云产品化（PITR 保留期 ↔ oplog 窗口成本），自建集群仍需本章估算公式——它是少数"可直接抄进 runbook"的 2013 内容。
