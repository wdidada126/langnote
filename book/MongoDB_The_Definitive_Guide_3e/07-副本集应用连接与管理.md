## 精读笔记

### 1. 应用侧：连接与保证（第 11 章）

- 驱动"自动发现"拓扑：给任一成员地址，驱动拉 `hello`（书中称 `ismaster`）得到全景，故障时重连并路由读写——2013 的驱动实现远不统一，作者因此写了一整章"驱动如何正确连副本集"，并给出"测试你的驱动"的清单。
- **写保证的三种语言**：① `w=n`（N 个成员确认）② `w=majority`（可配 `w: {majority: true}` 尚未定型的年代，书里用自定义 write modes）③ `fsync/j`。作者展示"自定义规则"（`getLastErrorMode`——**该特性后来被整体移除**），如"每个数据中心至少一台可见节点确认"。
- 读扩展：`slaveOk/readPreference`；**延迟节点 + 隐藏节点 + tags** 三件套把"报表读"和"备份读"分流——这是本章最有生命力的部分（tags 路由原样存活至今）。

### 2. 运维侧：状态机干预（第 12 章）

- `--replSet ... --noReplSet? no:` 单机启动成员做"抢救式维护"；`rs.stepDown()`、`electionTimeout`、维护模式（`rs.freeze()`）三工具防误切换。
- 大副本集限制（最多 12 投票/7 数据?记为"投票成员上限与网络开销"）、`force` 重配在失去多数派时"赌上一致性"的警告。
- 监控：`rs.status()/printReplicationInfo()`、复制延迟、oplog 窗口（保留时长）估算与"oplog 太短 → 初始同步风暴"的容量因果链——这是 12.4 的精髓。

## 2013 基线 → 2026 现状对位勘误

| 本书说法（2013） | 2026 现状 | 依据 |
|---|---|---|
| `ismaster` 握手 + 各家驱动参差 | 命令更名 `hello`（5.0+/驱动监控命令）；驱动重写统一拓扑发现，legacy 驱动退出维护 | ⚠️（驱动生命周期公告为公开事实）|
| `getLastErrorModes` 自定义写规则 | **已移除**；等价能力 = read/write concern + 标签化写关注（后由 **`w:-majority` + tag 只能表达约束子集**，复杂规则上移应用层）| ⚠️ |
| `safe=True` / `fsync` 选项 | 现代为 `WriteConcern(w=..., j=...)` 对象，`w:1,j:false` 是默认；**retryable writes** 补了"网络错误≠失败"的洞 | ⚠️ 默认值为驱动文档长期事实 |
| 手工尾随 oplog 做 CDC | **Change Streams（3.6+）**：聚合式管道 + 断点续传（resume token），取代"读 oplog 库"土法 | ✅ https://www.mongodb.com/docs/manual/changeStreams/（实抓）|
| 主从模式章节（12.5） | 无对应物（已移除）；跨数据中心容灾改由 zone/tags + 多数派读写 + Atlas 多区域集群承担 | ⚠️ |
| 一致性读 = "从主读或等 slave 追上" | Read Concern（`majority/snapshot/linearizable`）+ 因果一致性会话 + 事务快照读；`readConcern majority` 成默认（4.0+/6.0 移除开关） | ✅ https://www.mongodb.com/docs/manual/core/transactions/（实抓）|

## 核心概念速览（中英对照）

- **拓扑发现** — Topology Discovery（ismaster/hello）：驱动自动感知副本集成员与角色。
- **写保证** — Write Concern（w/j/wtimeout）：写确认的成员数与持久化级别。
- **`w:majority`** — 多数派确认：防回滚丢失的最低标准写法。
- **自定义写模式** — getLastErrorModes（书中特性）：已移除，现代无直接等价。
- **读偏好** — Read Preference（primary/secondary/nearest + tags）：读写分离路由核心。
- **成员标签** — Tags：机房/角色路由坐标，11.3 的遗产、2026 仍用。
- **stepDown / freeze** — 人工让位/选举冻结：计划内切换工具。
- **维护模式** — Maintenance Mode：让成员不触发选举的旧手法（`rs.reconfig` 替代）。
- **oplog 窗口** — Oplog Window：可回放历史时长，决定故障容忍边界。
- **Change Streams** — 变更流：订阅集合级变更的聚合 API，含 resume token。✅
- **retryable writes** — 可重试写：驱动层幂等重试（3.6+）。
- **linearizable read** — 线性化读（4.0+）：牺牲性能换单分片强读。

## 最新演进与工业实践

- **Change Streams 对位书 11 章全部"读侧花活"**：以前要"读 backup + 轮询 + 自记游标"，现在 `with cluster.watch(...) as stream: for change in stream:`（🔧 pymongo 4.18.2 中 `Collection.watch` 方法可导入，签名含 `resume_after/full_document` 选项；未连服务端 ⇒ ⚠️ 行为未实测；`full_document: updateLookup` 可拿更新后全貌）。
- **连接字符串即策略**：`retryWrites/retryReads/readPreference/maxStaleness` 全在 URI——`maxStalenessSeconds`（4.0 驱动统一特性）是书中"何时可以从备份节点读取数据"一节的工程答案。
- **运维自动化**：`rs.status` 的 `optimeDurableDate`/拓扑视图由 Compass/Cloud Manager（后并入 Ops Manager/TM；Cloud Manager 2023 退役——⚠️ 退役年份按公开公告）替代书中手工 `printReplicationInfo` 巡检。
- **多区域容灾**：书中"跨数据中心写规则"在 2026 = Atlas Global Clusters/Zone Sharding + 多数派写 + 就近读；自建仍用 tags + 自定义 writeConcern 子集。⚠️
