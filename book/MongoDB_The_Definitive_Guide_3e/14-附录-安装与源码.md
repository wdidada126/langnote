## 精读笔记

### 1. 附录 A：2013 的安装学

书中按 Ubuntu/OS X/Windows 分路：APT 仓库（10gen key）、tar 包、DMG/zip；强调 32 位限制、`ulimit` 前置、从包管理器起服务的路径差异。⚠️ 未实测。其"版本 × 平台 × 安装介质"矩阵当时已显过时——MongoDB 的发版节奏（书中一年两三个特性版本）决定了安装说明是全书保质期最短的部分。

### 2. 附录 B：源码地图

作者给出 `mongod` 源码树导览（`db/`、`bson/`、`client/`、`util/` 等目录）、构建方法（书中为 SCons 时代）与贡献流程。对读者的真实价值不在编译，而在**把第 11/12 文件所述黑盒降维**：按图索骥读当时代码，可以印证"全局锁 + mmap + journal"三件套的实现位置。⚠️ 现代源码树已大幅重构（本环境 GitHub 不可达，未核验目录细节）。

### 3. 生态与许可的换代（本文件兼论，2013→2026）

- **驱动**：书中 C++/Java legacy driver → 统一新驱动世代（CRUD API 规范、retryable writes、连接池标准化）；PyMongo 4.x 移除全部 legacy 别名（`insert/update/remove`）。✅ 驱动文档实抓：https://www.mongodb.com/docs/drivers/pymongo/
- **shell**：`mongo` → `mongosh`（JS 运行时、npm 生态、Promise API）。✅ https://www.mongodb.com/docs/mongodb-shell/
- **许可地震（2018，必须记住的一年）**：服务器核心从 AGPLv3 改为自写 **SSPL v1（2018-10-16，自 4.2 起）**；OSI 拒认其为开源，"开源软件"标签退场。✅ SSPL 原文页实抓：https://www.mongodb.com/licensing/server-side-public-license（页内标题即 "Server Side Public License (SSPL) | MongoDB"，版本行 "VERSION 1, OCTOBER 16, 2018"）
- **衍生替代（可验证链接）**：
  - **Amazon DocumentDB**——AWS 托管、MongoDB API 兼容的自有存储引擎："serverless, fully managed, MongoDB API-compatible"（官方产品页实抓 ✅ https://aws.amazon.com/documentdb/ ）；2021 起兼容 5.0 API、后续版本扩兼容（细节 ⚠️）。
  - **FerretDB**——Apache-2.0 开源、构建于 PostgreSQL 之上的 Mongo 兼容代理（官方文档实抓 ✅ https://docs.ferretdb.io/ ；源码仓库 https://github.com/FerretDB/FerretDB ⚠️ 本环境 GitHub 不可达未能核验）。
  - 另注：MongoDB 社区版仍在（SSPL 下源码公开可自布），但"云厂商白嫖托管"通道被立法式关闭——这是阅读一切 2018 后资料都要代入的背景。
- **公司/产品线**：10gen → MongoDB Inc.（2013 当年更名！）；Atlas（2016）成为营收主线；Realm/App Services 起落（Device Sync 于 2024 宣布日落 ⚠️ 日期未核验）。

### 5. mongod 启动机制推演（附录 A 的现代内核版，⚠️ 全节文档转述）

书中附录 A 只教"怎么装"；值得补的是装完之后进程做了什么——这是 11/12 文件所有机制的总装线：

1. 解析配置（mongod.conf YAML / 命令行）→ 权限与 ulimit 预检（23 章清单的第一次考试）；
2. 打开 `dbpath`：**WT 文件族锁定**（`WiredTiger.wt/turtle` + 独占锁文件防双开——书中 mongod.lock 的 WT 化身）；
3. 恢复阶段：校验和打开 → **重放 WT journal 到最后 checkpoint** → 打开 oplog（副本集成员先以 STARTUP2/RECOVERING 入列，06 文件状态机在此接棒）；
4. 绑定网络（bind_ip 默认纪律、TLS 证书加载）→ 认证表载入 → `ready to accept connections` 是 12 文件所有监控的起点；
5. 副本集成员加入后：心跳/选举资格评估/必要时初始同步——**"起一个 mongod"从来不是单机事件，是拓扑事件**（分片集群再叠加 config 版本对账，08 文件第 7 节）。

这条流水线的价值：出问题时你知道卡在哪一格——配置解析错（日志首行）、锁被占（上次没干净退出）、journal 重放慢（11 文件断电剧本）、选不到主（06/07 网络/时钟话题）——书中各章的病，在总装线上都有位置。

## 常见误区（本目录归纳）

1. "装最新版总是对的"——2026 是 LTS/Current 双轨 + 驱动/工具/服务器三张兼容矩阵的年代；附录 A 的"下载即用"须升级为"查矩阵再动"（演进节有锚点 URL）。
2. "SSPL=不可商用"——错得离谱：自部署/内部服务/咨询交付全部合法，被立法式关闭的只是**"把托管服务本身闭源售卖"**一条路（SSPL §13 机制，14 文件精读第 3 节）。
3. "开源替代品是 Mongo 的 fork"——DocumentDB 是自研引擎+API 子集、FerretDB 是 PG 之上的协议翻译——两者都不含 mongod 代码，兼容性以各自矩阵为准（⚠️ 细节页已实抓）。
4. "源码附录可跳过"——附录 B 的真正价值是"降维读法"：读过 2.4 的锁/日记实现位置，才懂 11 文件每条告诫背后的实现约束；现代源码树结构虽变，调用链读法原样有效。
5. "社区版与企业版只差功能"——还差发行渠道与生命周期承诺（企业版 LTS 更长、Windows 停发亦分轨）；选型时把 EOL 日历当硬约束。⚠️
6. "驱动随便选个语言的就行"——统一驱动世代（CRUD/读路由/重试规范）之前后的同名 API 语义差异巨大；书中 legacy 示例上现代驱动=静默行为漂移，比报错更危险（01/07 文件呼应）。

## 核心概念速览（中英对照）

- **SSPL** — Server Side Public License：MongoDB 自写 copyleft 许可，v1 发布于 2018-10-16；OSI 未认可。✅
- **AGPLv3** — 本书时代的服务器许可：2018 年被 SSPL 接替。
- **DocumentDB** — AWS 的 Mongo API 兼容托管库（自有引擎，非 Mongo 代码）。✅
- **FerretDB** — Apache-2.0 的开源 Mongo 兼容层（PostgreSQL 后端）。✅
- **legacy driver** — 书世代驱动 API：被统一新驱动全量替换。
- **mongosh** — 现代官方 shell：`mongo` 的继任者。✅
- **SCons** — 书中构建工具：已被新构建体系迭代。⚠️
- **NamespaceString** — 命名空间表示：源码阅读时连接"库.集合"概念的钉子。⚠️
- **Atlas** — 官方多云托管平台：本书出版同年公司更名、三年后产品上线。⚠️
- **10gen → MongoDB Inc.** — 2013 年公司更名：本书恰在更名前后写就。⚠️
- **LTS/Current 双轨** — 现代发行节奏：本书"一年两三版"的 rapid release 已被支持策略取代。⚠️
- **兼容矩阵** — Compatibility Matrix：驱动×服务器×工具的三元验收表——"装哪个"的现代答案。⚠️
- **WT 恢复流水线** — checkpoint + journal 重放 + oplog 追赶：附录 A"起进程"动作的内核真相（第 5 节推演）。⚠️

## 最新演进与工业实践

- **安装决策树（2026）**：托管（Atlas 各层）> 容器化自建（Operator/Helm）> 裸金属自建（包管理器/二进制）；每层的"版本支持矩阵"都要单独核对——书中"装最新即可"让位于 LTS/Current 双轨与 EOL 日历。✅ 下载页实抓（current 线为 8.x）
