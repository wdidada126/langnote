# 10 应用动态与数据管理（原书第 17–18 章）

> 书目：《MongoDB: The Definitive Guide, 3rd Edition》（Kristina Chodorow, O'Reilly, 2013）。精读重构笔记，非原书文本；取证见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。
> 实测环境：无 mongod ⇒ profiler/空间统计行为 ⚠️ 未实测；骨架来自目录实抓。

## 阅读目标

- 把 currentOp / profiler / mongostat-mongotop 三件套读成一套"运行现场取证"体系，掌握"受害者 vs 元凶"的判读手感。
- 掌握索引构建机制编年（foreground→background→hybrid）与认证体系（keyFile→RBAC）两条运维主线。
- 辨认 MMapv1 手艺（touch/预分配/padding"压缩"）的成批退役清单及其 WT 时代的对位物。
- 把 18.2 的"接力建索引"与 18.1 的认证雏形映射到 2026 的混合构建与六层安全体系（与 06/12 文件合读）。

## 章骨架（中文小节 ✅ 实抓自人邮第 2 版目录）

- 第 17 章 了解应用的动态：17.1 了解正在进行的操作（找有问题的操作、终止执行、假象、避免幽灵操作）/ 17.2 系统分析器 / 17.3 计算空间消耗（文档、集合、数据库）/ 17.4 mongotop 与 mongostat
- 第 18 章 数据管理：18.1 配置身份验证（原理、配置、工作方式）/ 18.2 建立和删除索引（独立/副本集/分片集群上建索引、删索引、注意内存溢出杀手）/ 18.3 预热数据（库入内存、集合入内存、自定义预热）/ 18.4 压缩数据 / 18.5 移动集合 / 18.6 预分配数据文件

## 精读笔记

### 1. 运行时观测三件套（第 17 章）

- `db.currentOp()`/`$currentOp`：看 `waitingForLock/nsecs/qty`；`db.killOp()` 止损。作者用大量篇幅讲"假象"：长操作可能是**等锁的受害者而非元凶**；"幽灵操作"（客户端断连后仍跑的操作，`maxTimeMS` 尚未诞生的时代）——给出的解法是 `opTimeLimit`/kill 循环。
- **系统分析器（profiler）**：`--profile 0/1/2 + slowms`，查 `system.profile` capped 集合；书中提醒"profiler 本身有开销、别常开"。
- 空间账本：`db.coll.stats()` 的 `storageSize/freeSize/objectSize/indexSizes（书中 avgObjSize、padding）`；"文档占多少"用 `Object.bsonsize()`——MMapv1 时代这些数字直接对应磁盘文件。
- **mongotop（按集合读写热点）/ mongostat（全局速率与锁占比计数）**——书中把它俩当作"没有 APM 时的一双眼睛"。

### 2. 数据管理手艺（第 18 章）

- 认证：2013 时代只有**库内用户 + `keyFile` 集群内认证**（`addUser`/内部 userSource 体系；RBAC 的 `admin` 角色表是 2.6 的，本书尚未见）。SSL 在第 20 章（12 文件）。
- 建索引：独立机 `ensureIndex` 阻塞；副本集"从节点逐个建 →  stepDown → 主最后建"的接力流程；分片集群每 shard 重复——"索引内存溢出杀手"指 `background` 失败/大索引爆 RAM 的经典事故。
- 预热：`touch` 命令把数据页钉进内存（MMapv1 特性）——重启后"冷读雪崩"的解药。
- 压缩/移动：MMapv1 的"压缩"实为空间回收手艺（`compact`/`repairDatabase`、索引与记录的空洞整理）；移动集合 = 复制+改元数据（分片环境则走 `moveChunk` 语义，两码事）。

### 3. currentOp 字段判读解剖（17.1 的"假象"诊断学）

- 书中阅读面：`op/ns/query` 看形状，`nsecs/microsecs_running` 看时长，`waitingForLock + locking.timeWaitingMicros` 看受害程度——作者立下的判读第一律：**最长的那个往往是等锁的受害者而非元凶**，元凶要去同屏找"锁的持有者"（可能是后台索引构建或一次大写）。
- 幽灵操作：客户端断连后服务端照跑（`maxTimeMS` 未诞生的书时代），解法是 `opTimeLimit` 参数或周期 kill 脚本——现代三件套：`maxTimeMS`（驱动逐请求）+ `maxExecutionTimeMS`（服务端默认上限）+ `killOp`（应急）。⚠️ 转述
- killOp 的语义全貌：**协作式终止**，多数执行阶段无检查点——杀到一半=白跑+回滚成本（书中警告，⚠️ 转述）。
- 现代 `$currentOp` 已聚合化（`db.aggregate([{$currentOp: {...}}])`），可按 `allActiveConnections` 全域采集并与会话/事务并排——"看运行现场"从 shell 助手升级为可过滤可 join 的数据面（⚠️ 转述）。

### 4. profiler 三级与空间账本（17.2–17.3 机制注记）

- `--profile 0|1|2` + `slowms` 阈值决定什么进 `system.profile`——它本身是 capped 集合，容量自我限制，作者两条告诫"别常开""定期清空否则挤爆"都由此来。
- collStats 账本的书时代读法：`n/objectSize/avgObjSize` 看形状、`storageSize/freeSize` 看空洞（MMapv1 碎片）、`paddingFactor` 看增长预留——三类字段只有前两族活到 WT 侧（05 文件 padding 对位）。
- `Object.bsonsize(doc)`：量单文档的唯一可靠尺——2026 语境下它量的是 **16MB 红线余量与内嵌数组膨胀预测**（05 文件）。
- mongotop 回答"热的是谁"（按集合的读写时间占比），mongostat 回答"整体多忙"（速率+队列+连接）——书中这对工具实为 USE 方法的土法实施，命名学见 [../性能之巅.md](../性能之巅.md)。

### 5. mongostat 列判读对照（17.4：书时代 vs WT 时代同表，⚠️ 现代列名以工具文档为准）

| 列 | MMapv1 时代读法（书） | 2026 读法 |
|---|---|---|
| insert/query/update/delete | 每秒操作速率 | 保留；getmore 列单列，游标风暴看它 |
| locked | 全局写锁占用%——头号 SLI | **消失**（WT 无全局写锁）；锁压力转 queue/唤醒类字段 |
| page_faults | mmap 缺页率——工作集告警 | 退役；WT 对位 = cache 脏比 + eviction（12 文件对照表） |
| dirty used | journal 未刷脏量 | WT checkpoint/journal 节奏替代 |
| qr/qw | 读写锁排队 | 现代对应执行队列/事务排队 |
| conn | 连接总数 | 保留且仍是头排指标（书中 20000 上限 myth 已被证伪） |

### 6. 索引构建机制编年（18.2："内存溢出杀手"的运维主线）

- 三代形态：**foreground**（书默认，阻塞写）→ **`background: true`**（并发但慢、易碎片化）→ **hybrid 混合构建**（4.2+ 默认：排序+批量加载，几乎不锁——机制转述 ⚠️）。
- 副本集场景：书时代主上构建无法及时传导到从，"从节点还在建 → 切主即瘫"是连锁事故源头，于是有 18.2 的接力仪式（从逐个建 → stepDown → 主最后建）；现代版：主构建+从自动继承 + `commitQuorum` 多数派确认才提交（4.4+），接力退役。⚠️ 转述
- 官方索引构建页可直查（2026-09 curl 200）：https://www.mongodb.com/docs/manual/core/index-creation/ ——18.2 整节手册在该页有现代重写。
- 删索引廉价，但空间归还（尤其 WT 时代的 `freeSize`）要 `compact`——书中"索引杀手"清单实为构建/碎片/归还三件事（11 文件对位）。

### 7. 18.3–18.6 手艺终局（预热/压缩/移动/预分配）

- **预热**：`touch` 把页钉进 OS 缓存（MMapv1 专属）——随引擎退役；WT 时代等价物 = `cacheSizeGB` 配额 + 上线前预热查询，冷启动雪崩的概念还在（12 文件）。⚠️
- **压缩**：书中"压缩数据"= 空洞整理（compact/repair）；WT 的 snappy 块压缩默认开启、`compact` 降级为空间归还工具。
- **移动集合**：书中手工"复制+改命名空间元数据"；现代有 `moveCollection`/`movePrimary` 官方原语，但历史上出过元数据不一致事故，官方口径**谨慎使用、先备份**（⚠️ 转述）——这是 18.5 最好的现代注脚。
- **预分配数据文件**：`--nssize/--prealloc` 是 MMapv1 文件系统时代的家什；WT 无对应概念，18.6 退役最彻底。

## 2013 基线 → 2026 现状对位勘误

| 本书说法（2013） | 2026 现状 | 依据 |
|---|---|---|
| `opTimeLimit`/手工 kill 治幽灵操作 | 3.2+ **`maxTimeMS`**（含服务端默认 `maxExecutionTimeMS` 查询上限）；killOp 仍在，但超时体系已内置 | ⚠️ |
| profiler 是慢查询唯一入口 | 仍在（`system.profile`）；平台层多 **Atlas Performance Advisor、Query Profiler API、FTDC 诊断包** | ⚠️ |
| `ensureIndex` 阻塞/接力建索引 | 4.2+ **混合构建默认化**，副本集自动级联（primary 建 → 从复制构建），无需手工接力 | ⚠️ 机制为长期文档事实 |
| `touch` 预热 | **MMapv1 专属，随引擎移除而消失**；WT 的等价物 = 预热缓存（`cacheSizeGB` 调优 + 应用侧预热查询），Atlas 有 cluster warm-up 工具 | ⚠️ |
| 认证 = keyFile + addUser | 完整体系：**X.509 集群内部认证、SCRAM-SHA-256、LDAP/Kerberos、RBAC、网络隔离/VPC peering、审计日志（企业版）** | ⚠️（功能清单为官方安全文档通识）|
| mongostat 看 `locked` 指标 | WT 无全局写锁——mongostat 的锁列语义整个换代（`total/reads/writes` 仍在，`locked_myt` 成历史文物） | ⚠️ |

## 常见误区（本目录归纳）

1. "最慢的操作就是元凶"——17.1"假象"专节的头号纠正：先找锁持有者，再谈凶手。
2. "profiler 常开在 2 才安心"——采样有成本，`system.profile` 容量自限；标准姿势 = slowms 阈值 + 事故时临时开到 2 + 用完关回。
3. "killOp 是免费的"——协作式终止无检查点，杀掉大操作=重做一次的成本（书中警告 ⚠️）。
4. "mongostat 速率低=还能扛"——不看工作集与内存水位（21 章/12 文件）就是只看时速表不看油表。
5. "touch/`--noprealloc`/padding 调参还要学"——三件全是 MMapv1 化石；WT 时代的等价作业是 cache 配额与 compaction（12 文件）。
6. "在主上建索引=副本集自动安全"——接力手艺已被 4.2+ 混合构建+commitQuorum 官方化，但"建索引=磁盘峰值"的风险预算永远有效。⚠️
7. "movePrimary 随便用"——跨 shard 搬库的元数据原语，历史上需专门修复脚本伺候；安全立场仍是"不搬，导出重灌"（⚠️ 转述）。

## 核心概念速览（中英对照）

- **currentOp** — 当前操作快照：`$currentOp`/`db.currentOp()`，锁等待与长查询入口。
- **killOp** — 终止操作：按 opid 打断失控查询。
- **Profiler** — 系统分析器：0/1/2 三级 + slowms 阈值，写 system.profile。
- **maxTimeMS** — 操作超时（3.2+）：书中"假象/幽灵"话题的现代解法。
- **mongotop** — 集合级读写热点采样工具。
- **mongostat** — 集群级速率/锁/复制滞后概览工具。
- **FTDC** — Full-Time Data Collector（3.2+）：官方诊断数据环形采集，书后时代。
- **collStats/dbStats** — 空间账本：storageSize/freeSize/indexSizes。
- **Object.bsonsize** — shell 内 BSON 尺寸计量。
- **touch** — MMapv1 预热命令：已随引擎退役。⚠️
- **keyFile 认证** — 集群内部共享密钥认证：被 X.509/SCRAM 体系迭代。
- **RBAC** — 基于角色访问控制（2.6+，书中尚未成体系）：内置角色 + 自定义角色。
- **$currentOp（聚合）** — 操作快照的数据面化（3.4+）：可过滤、可 join 的运行现场。⚠️
- **hybrid 索引构建** — 4.2+ 默认构建法：排序+批量加载，终结 foreground/background 二选一。⚠️
- **commitQuorum** — 索引提交法定人数（4.4+）：副本集接力仪式的官方化。⚠️
- **movePrimary/moveCollection** — 元数据搬迁原语：历史事故多，官方劝"先备份再动"。⚠️

## 最新演进与工业实践

- **从"手工三件套"到"平台可观测"**：自建集群标准姿势 = mongod/mongos 指标（Prometheus exporter；⚠️ 旧版官方 exporter 已由 MongoDB Helm/Operator 生态接管，细节以官方为准）+ FTDC 存档 + profiler 按需；Atlas 用户默认拿到 Performance Advisor/实时仪表板。
- **`$jsonSchema` + Atlas 模式分析**替代了 17.3"人肉估空间"的一部分场景；**schema suggestions**（未bounded 数组等）直接给出可执行整改项。✅（同域文档体系，05 文件引过）
- **索引运维自动化**：书中"副本集接力建索引"整节在 4.2+ 可删——混合构建 + 从节点自动继承；`commitQuorum`（4.4+）进一步防索引半途构建。⚠️ 未实测
- **认证现代化**：生产手册第一行从"开 auth"变成"开 auth + TLS + SCRAM/X.509 + 最小角色 + 审计"；keyFile 仅存于小环境。⚠️
- **幽灵操作叙事的平台化**：K8s/负载均衡时代的 liveness/readiness 探针与连接排空接管了"杀谁、何时杀"的决策，currentOp 退居取证——但 17.1"假象/幽灵"三源对账的方法论不变。⚠️
- **空间账本的现代问题域**：书中"算空间"的对象从 .1/.ns 文件变成 WT 压缩后尺寸 + 备份窗口成本；16MB/片键基数/热文档三大设计约束让 17.3 的手艺换了用处（05/09 文件）。
- **索引运维的官方页可直查**（2026-09 curl 200）：https://www.mongodb.com/docs/manual/core/index-creation/ 与监控总览 https://www.mongodb.com/docs/manual/administration/monitoring/ ——17/18 章的手感在现代文档里逐条有对位。
