## 核心概念速览（中英对照）

- **静态多态** — static polymorphism：分派发生在编译期（类型已知），零间接开销；对立面是虚表。
- **CRTP** — Curiously Recurring Template Pattern：`struct Dog : Counter<Dog>`——基类以派生类为模板实参，获得"向下转型无需虚表"的通道。
- **混入** — mixin：以"继承模板参数"叠加正交功能的小类（`Timestamped<Signed<Core>>`）。
- **类型擦除** — type erasure：接口层只见 `void*`/概念基类，具体类型藏进堆上的包装（function/any/string_view 的取舍）。
- **标签派发** — tag dispatch：用类型标签重载选实现（迭代器类别是最著名用户）。
- **表达式模板** — expression templates：运算符重载返回"表达式描述对象"而非结果，消费端一次循环融合整棵树。
- **临时量消除** — temporary elision：`a+b+c` 从两个中间向量变成零个——表达式模板的第一收益。
- **类型列表** — type list：编译期"元素的元素是类型"的序列；C++11 后的实体是 `std::tuple`。
- **索引序列** — `std::index_sequence`：把"对包逐位操作"翻译成"对下标 0..N-1 操作"的桥。
- **多态性光谱** — polymorphism spectrum：模板（0 开销/封闭集）↔ 虚函数（1 跳/开放集）↔ `std::function`（堆+间接）↔ `std::any`（完全动态）。

## 动机

前六章的零件（实例化/特化/包/traits/概念）到这里回答终极问题：**接口什么时候该是类型
参数，什么时候该是对象参数？** 选错方向的代价都实打实：过度模板化=编译时间+诊断地狱；
过度虚化=性能+对象模型扭曲（"脆弱基类问题"）。本章给的是判据与三件常用武器
（CRTP/类型擦除/表达式模板）的构造原理。

## 机制

**CRTP 的机器层**：`Dog` 在定义处就把自己的类型喂给基类 ⇒ 基类成员里
`static_cast<const Derived*>(this)` 是**编译期已知偏移的指针调整**，无 RTTI、无 vptr；
每个 `Counter<Dog>`/`Counter<Cat>` 是**不同的基类子对象类型**，所以
`static inline long instances` 天然按派生类各存一份——7.2.1 的"限制实例化计数"与
"单例基"都靠这一点。🔧（已实测 g++ 15.2：`{Dog a,b; Dog c=a;}` 后 `Dog::count()==3`）：

```cpp
template <typename Derived> class Counter {
    static inline long instances = 0;                    // C++17 内联静态：每特化一份
public:
    Counter() { ++instances; }
    static long count() { return instances; }
    void identify() const { static_cast<const Derived*>(this)->name(); } // 静态回溯
};
class Dog : public Counter<Dog> {
    friend Counter<Dog>;                                 // 私有钩子：只有基类能碰
    const char* name() const { return "Dog"; }
};
```

限制实例化次数（7.2.1）= 私有构造 + `friend Singleton<Derived>`：外界无法构造、
基类可以——`App : Singleton<App>` 的"编译期封死多实例"配方（🔧 实测通过）。
标准库中的 CRTP（7.2.4）：`std::enable_shared_from_this`、`std::iterator`（已弃用）、
`std::ios_base 继承链`、`std::view_base`（09 章再会）。

**混入**：`using Message = Timestamped<Signed<MsgCore>>;`——每层 `template<class Base>
struct X : Base`，功能是叠加的正交小类，组合在**类型别名处**完成（🔧 实测 `m.stamp()`
与 `m.sig` 同时可用）。与继承体系的区别：混入无 is-a 语义、按需拼装、彼此不知晓。

**类型擦除的构造原理**（与 CRTP 正面对撞）🔧（已实测）：

```cpp
class AnyCallable {
    struct Concept { virtual void call() const = 0; virtual ~Concept() = default; };
    template <typename F> struct Model : Concept {
        F f; explicit Model(F g) : f(std::move(g)) {}
        void call() const override { f(); }
    };
    std::unique_ptr<Concept> p;
public:
    template <typename F> AnyCallable(F f) : p(new Model<F>(std::move(f))) {}
    void operator()() const { p->call(); }
};
```

小对象优化（SBO）、可移动性、异常规格透传是工程细节；骨架就这 12 行。
**判据**：调用点需要"存下来、跨编译单元、集合里混装"→ 类型擦除；
"同调用点类型可模板化"→ 模板参数/CRTP。`std::function` vs 模板回调参数的
选择账（一次堆分配+虚跳 vs 每 lambda 一份代码）在 EMC Item 21 有对译
（[../Effective_Modern_C++.md](../Effective_Modern_C++.md)）。

**标签派发**：`count_to(a, b, cat{})`——把"决策依据"做成第一等类型参数进重载。
存在理由（constexpr if 之前它是唯一分叉器）+ 现职（多标签正交组合、SFINAE 时代 API
门面）；本目录 🔧 实测与 05 章 `if constexpr` 版并行存在。**三者总对照**：

| 手法 | 决策位置 | 可扩展点 | 诊断友好度 |
| --- | --- | --- | --- |
| 标签派发 | 重载决议（参数类型） | 新标签=新重载 | 中（no matching） |
| `if constexpr` | 函数体内 | 新分支改函数体 | 高（错误定位准） |
| `requires` 重载 | 候选资格（约束） | 新重载零侵入 | 最高（约束名入诊断） |

**表达式模板（7.6）**：`x + y` 返回 `Add<V,V>`（持两个引用/值，不计算）；
`Add` 又给 `+` 供操作数 ⇒ 编译期长成树；消费端 `for i: out[i]=e.at(i)` 一次循环
**融合**整棵树。🔧 实测 `x+y` 逐元素得 11/22/33 且**零临时向量**。代价账：
引用悬挂（操作数必须是惰性可重取的，环形缓冲就不行——08 章呼应）、
调试时"看到的不是数据是树"、`auto t = a+b; t = c+d;` 语义漂移。
现代竞品是**协程/向量化**与 `std::experimental::simd`、及编译器 RVO 的进步
——表达式模板在通用代码里退位，在数值/张量库里仍是正典（Eigen 的
`product.h` 评审文档明确讨论过 ET 取舍 ⚠️ 未直连）。

**类型列表（7.7）**：`tuple<int,char,double>` 为载体，`sizeof...` 出长度、
`std::tuple_element_t<I, ...>` 取第 I 个、`constexpr bool m[] = {is_same_v<Ts,U>...}`
折叠出查找表（🔧 实测 `indexOf<double>()==2`）。MPL 册的 `mpl::vector` 代数到此
全部可以用 tuple+折叠+index_sequence 重写——这是 00 篇"TMP 三册分工"的最实操注脚。

## 权衡

模式选择的总账：**CRTP=编译期封闭类型集 + 零开销 + 无法存进基类容器**；
**类型擦除=可存储可混装 + 一次间接 + 接口要预先想全**；**表达式模板=融合收益巨大但
只在"逐元素、可随机索引、生命周期受控"时值得**。三者没有胜负，只有调用点形状。

## 相邻概念对比

- **CRTP vs 虚函数**：对照 [../C++20设计模式/00-总览与阅读地图.md](../C++20设计模式/00-总览与阅读地图.md)
  的策略/模板方法章——Nesteruk 用 CRTP 重写策略模式与 7.2.3"组合设计模式"同题。
- **混入 vs 多重继承 vs 委托**：混入无虚继承菱形风险（每层单继承链）、状态自带。
- **类型列表 vs `std::variant`**：同一原料两种用途——variant 把列表变成"运行期可判别联合"，
  是类型列表最成功的商业化（07 的玩具在 08/09 的消费者视角里就是 variant 的孪生兄弟）。

## 最新演进与工业实践

- **CRTP 的 C++20 安全网**：`requires std::derived_from<Derived, Base<Derived>>` 一行
  校验"参数确实是继承自我方的特化"，治 CRTP 误用（`struct Cat : Counter<Dog>`）——
  Alexandrescu 时代做不到，本书 6 章语法直接用。
- **P2996 反射对模式的冲击排序**（提案实测见 [00 总览](00-总览与阅读地图.md)）：
  traits 类手工件最先生成器化，其次"枚举名字符串化"这类 mixin；CRTP 本身是结构性的，不受影响。
- **表达式模板工业现场**：Eigen（抽象表达树+求值融合）、Blitz++（Veldhuizen 本尊，
  1994 技术报告《Expression Templates》⚠️ 编号本次未核实到官方页面）、
  MetaNN（[../C++模板元编程实战.md](../C++模板元编程实战.md) 全书主线，编译期张量形状）。
- **类型擦除的现代成本学**：`std::function` 的堆分配在延迟敏感路径被 `absl::FunctionRef`
  （abseil 仓库，非拥有、要求可拷贝实参）替代——"先模板参数、必须存才 function"
  已是 Google 风格级共识；C++26 若 reflection+contracts 成势，擦除层还会更薄 ⚠️ 展望。
- **simdjson** 的对照启示：它选了**非模板**路线（运行期 SIMD dispatch + 查表），
  说明"零开销"的另一面是"零复杂度"——与 01 章"反方立场"呼应。
