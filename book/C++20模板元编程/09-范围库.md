## 核心概念速览（中英对照）

- **范围** — range：满足 `std::ranges::range` 的任何东西：有 `begin`/`end`，end 是哨兵即可。
- **视图** — view：`ranges::view` = range + movable + 可拷贝 + **不拥有**元素 + 操作是 O(1) amortized。
- **`view_base`** —  opting-in 基类：公开继承 `std::ranges::view_base` 即申报 `enable_view`（07 章 CRTP 的标准库现身）。
- **范围适配器** — range adaptor：接受范围返回视图的可调用对象（`views::filter` 一家）。
- **管道语法** — pipe `|`：`ranges::views` 对象带 `operator|` 伴生声明，`rng | views::f` 等价函数调用。
- **可视图范围** — viewable_range：range 且（已是 view 或左值）——"prvalue 容器不能直接进管道"的守门概念。
- **受约束算法** — constrained algorithms：`std::ranges::` 版本：range 入参、概念前置、哨兵定界。
- **投影** — projection：算法的可选"取值透镜"（`ranges::sort(v, {}, &Person::age)`）；本书目录未单列，std 版算法标配（补注 ⚠️ 非原书小节）。
- **`ref_view`/`owning_view`/`all`** — 三种"进管道资格"适配器：引用左值/拥有 rvalue 物化/统一入口。
- **适配器闭包** — `range_adaptor_closure`（C++23）：把自己的适配器挂进 `|` 生态的标准基座。

## 动机

08 章证明了"协议"（概念约束的范围接口）本身值得设计；本章回答"标准库给了什么现成货、

## 机制

**从抽象到库（9.1）**：C++11/14 的"范围"只存在于文档字里行间（begin/end 约定）；
range-v3 用探测+traits 造出概念近似物；C++20 收编为具名概念层。机制断代表述：
`std::ranges::range<R> = 有 begin/end 且 end 对 iterator 建模 sentinel_for`——
**全部检查都发生在实例化/约束求值层**，没有一行运行期代码。

**视图的惰性（9.2）** 🔧（已实测 g++ 15.2，输出 `pipeline=120`）：

```cpp
auto data = make_data();
auto even_squares = data
    | std::views::filter([](int x) { return x % 2 == 0; })
    | std::views::transform([](int x) { return x * x; });
static_assert(std::ranges::view<decltype(even_squares)>);
```

`filter_view` 不预筛、不缓存——`begin()` 才现场推进底层迭代器找首个满足谓词者，
每次 `++` 继续"找到下一个"；`transform_view` 的 `operator*` 现场调用投影函数。
**管道的全部值是"描述即执行"**：构造 `even_squares` 是 O(1)，遍历才 O(n)。
这解释了两条使用铁律：视图可重入但**每次重遍历都重算**（filter 谓词被重复调用——
纯函数要求来自 `std::regular_invocable` 约束）；视图不保活源——所以 prvalue 容器
直接进管道在 C++20 被 `viewable_range` 拦下（`auto data = ...` 那行的原因）。

**受约束算法（9.3）**：`std::ranges::find(v, 9)` vs `std::find(v.begin(), v.end(), 9)`
——除了少写一半字符，语义差异是**边界由概念保证一致**（同一视图 begin/end 两次调用
必须相容：`common_range` 管这件事）。🔧 实测 `find ok=1`。算法族与迭代器设施概念
（`indirect_unary_predicate`、`projectable`）共同构成"可组合乘法"：
算法 × N 个容器 × M 种元素访问方式 = N+M 份代码，不是 N×M。

**自定义范围适配器（9.4，本目录的工程核心）** 🔧（已实测 g++ 15.2，输出 `every nth: 1 3 5`）：

```cpp
template <std::ranges::common_range V>
    requires std::ranges::view<V> && std::ranges::forward_range<V>
class every_nth_view : public std::ranges::view_base {           // ① 申报 view 身份
    V base_{}; std::size_t n_ = 1;
public:
    every_nth_view() = default;                                  // ② view 要求 default/copy/move
    every_nth_view(V b, std::size_t n) : base_(std::move(b)), n_(n) {}
    class iterator {
        std::ranges::iterator_t<V> cur_{}, last_{}; std::size_t n_ = 1;
        friend class every_nth_view;
        iterator(std::ranges::iterator_t<V> c, std::ranges::iterator_t<V> l, std::size_t n);
    public:
        iterator() = default;                                    // ③ sentinel_for 要 semiregular——
                                                                 //    漏了这一行，整视图 range 概念不满足（实测踩坑）
        using value_type = std::iter_value_t<std::ranges::iterator_t<V>>;
        using difference_type = std::iter_difference_t<std::ranges::iterator_t<V>>;
        decltype(auto) operator*() const { return *cur_; }
        iterator& operator++() { std::ranges::advance(cur_, difference_type(n_), last_); return *this; }
        bool operator==(const iterator& o) const { return cur_ == o.cur_; }
    };
    iterator begin(); iterator end();
};
template <std::ranges::range R>
every_nth_view(R&&, std::size_t) -> every_nth_view<std::views::all_t<R>>;  // ④ 推导指南接住一切 range
```

四个教学点各对应前章一节：① `view_base` 是 07 章 CRTP 家族的标准库户口；②/③ 是
02 章"隐式实例化按需"与 06 章"概念是接口"的现场（**GCC 诊断直说**
"`is_constructible_v<iterator> is false`"——SFINAE 时代这里是黑盒，05 章实测对照的续篇）；
④ 是 04 章 CTAD 指南的实战。步长视图的关键细节：`advance(it, n, lim)` 带限推进，
防止尾部跨过 end 造成"永不等于哨兵"——**迭代器协议不是类型，是行为合同**。

## 权衡

- **手写视图 vs `range_adaptor_closure`（C++23）**：本书按 C++20 讲 begin/end 手工件；
  C++23 的闭包基类 + `views::stride`（本书 every_nth 的官方化 ⚠️ 提案号未实测）让
  90% 自定义适配器降级为一行组合——学手工件的价值在调试与库内行。
- **视图链的诊断债**：`filter_view<transform_view<...>>` 错误信息长；概念具名化后
  可读性已优于前 C++20 时代一个数量级（05/06 章实测结论的复利），但源视图约束错误
  仍在最外层爆出——**逐段 static_assert 是 ranges 的调试礼仪**。
- **`views::all` 物化策略**：`ref_view`（左值，零成本）vs `owning_view`（rvalue，物化并持有）
  ——选错寿命管理方式（管道里塞临时容器又存下视图）是 ranges 第一悬垂源。

## 相邻概念对比

- **08 vs 09**：08 自定义"协议实现"（容器+迭代器+算法），09 复用"协议消费者"（视图+
  受约束算法）；两章代码可拼成同一个 RingView 的两副面孔——08 版是输入迭代器+哨兵，
  若想在 09 进 `views::filter` 管道则必须升级能力等级（forward），**协议升级的成本**
  就是"输入序列可重入性"的定价。
- **ranges 管道 vs Eigen 表达式模板（07 章）**：同一"惰性求值+组合"哲学两种域：
  管道逐元素拉取，ET 整树融合展开；ranges 不做算术融合是刻意的（保持 O(1) 视图承诺）。
- **`std::ranges` vs range-v3**：同源不同代——概念严格度、`to()` 收集、`join` 修复等
  差异；用 v3 过渡再迁 std 是工业标准路径（对应 [../C++20设计模式/00-总览与阅读地图.md](../C++20设计模式/00-总览与阅读地图.md)
  管道章的载体选择讨论）。

## 最新演进与工业实践

- **C++23 的补票清单**（与本章直接相关）：`std::ranges::to`（容器化收集）、
  `zip`/`enumerate`/`fold`（`views::stride`、`chunks` 的寸取修正）⚠️ 各提案号未实测，
  特性名属实；本书 every_nth 练习在 C++23 下就是 `views::stride`——**教学件退役为
  标准件**，恰好证明 9.4 学的机制是对的。
- **std::generator（C++23）**：协程版"自产范围"，让 08 章 RingView 这类"有状态遍历"
  可以写成 `co_yield` 循环——视图协议与协程的汇流点（本目录在 06 概念约束的推广场景）。
- **P2300 std::execution 的"管道同构"**（实测 wg21.link/P2300R4 → 2022 文档，
  标题 `std::execution`，Niebler 等署名）：异步计算组合子复用 ranges 的管道语法思想——
  ranges 的概念设计正在输出到并发领域；本书读者读执行库源码不会有陌生感。
- **工业仓库对照**：range-v3（ericniebler/range-v3）读概念定义史；
  fmtlib 的 `formatter` 对 ranges 的适配（`fmt::join` 即"不可拷贝元素的视图"特例）；
  abseil 的 `c_*` → 原生 ranges 的迁移曲线在 2020s 的真实代码库中同步发生
  （Google 内源 OSS mirror 口径 ⚠️ 未逐仓核实）。
