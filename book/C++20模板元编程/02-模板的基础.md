## 核心概念速览（中英对照）

- **函数模板** — function template：签名含模板形参的函数族；只能**全**特化，不能部分特化。
- **类模板** — class template：生成类型的模板；支持显式与**部分**特化。
- **成员函数模板** — member template：类内的模板（容器/智能指针的转换构造标配）。
- **非类型模板形参** — NTTP, non-type template parameter：以值为参数；C++20 扩到"结构化类型"。
- **模板模板形参** — template template parameter：以类模板为参数，如 allocator 槽位。
- **隐式实例化** — implicit instantiation：用到才生成，且**只生成用到过的成员定义**。
- **显式实例化** — explicit instantiation：`template class X<int>;` 定义式强制生成 / `extern` 式抑制生成。
- **显式特化** — explicit (full) specialization：全部实参给定的定制版本，可省略 `template<>` 实参表改写行为。
- **部分特化** — partial specialization：更特化的模式匹配，类/变量模板专属；靠偏序决胜。
- **变量模板** — variable template：按模板实参索引的常量/变量族（`_v` traits 与内联策略对象的载体）。
- **别名模板** — alias template：可参数化的类型别名；typedef 无法模板化。
- **泛型 lambda** — generic lambda：形参写 `auto`；脱糖为带成员模板 `operator()` 的闭包类。

## 动机

本书的"元机制"全部寄生在本章语法之上：traits 是类模板+部分特化，`_v` 是变量模板，
折叠是形参包运算，CRTP 是类模板互操作。**把"定义"和"实例化"分开**是本章真正的认知门槛：
模板是图纸，实例是楼；特化是对某块地皮的定制图纸。

## 机制（到实例化/重载决议层面）

**隐式实例化的粒度**。函数模板只在被"用到且需要定义"时实例化定义体；
类模板只实例化被用到的**成员的声明**，其定义再单独按需实例化。这解释了 🔧（已实测 g++ 15.2）：

```cpp
template <typename T> struct Holder {
    T v;
    void need() { static_assert(false_v<T>, "boom"); }  // 不调用 need() 永不报错
};
template <typename T> constexpr bool false_v = false;
Holder<int> h{1};            // OK：need 未用，其定义不实例化
// h.need();                 // 若调用：static_assert 失败——"惰性诊断"是模板错误延迟爆发的根因
```

（注意裸 `static_assert(false)` 在 C++20 是**定义模板时**就非法的，必须挂靠依赖条件——
这正是 2020 年 CWG 裁决"never-constexpr"行为后的写法，见本章演进节。）

**特化选择算法**（部分特化是本章最难的一块）。对 `X<A>` 的实例化：
① 依次把实参序列代入每个偏特化模式做**模板实参推导**，推出矛盾者淘汰；
② 在存活者中按"更特化"偏序两两比较：若 `P1` 可作为 `P2` 的实参而反之不可，
`P1` 更特化；存在唯一极大者则选之，**两两不可比（歧义）直接编译错误**。
🔧（已实测）偏序生效的最小例：

```cpp
template <typename T> struct K { static constexpr int v = 0; };       // 主模板
template <typename T> struct K<T*>  { static constexpr int v = 1; };  // 指针
template <typename T> struct K<T**> { static constexpr int v = 2; };  // 双指针更特化
static_assert(K<int>::v == 0 && K<int*>::v == 1 && K<int**>::v == 2);
```

**函数模板没有部分特化**（语言规定，动机是它曾与重载混淆出无数坑），替代手法是把"特化"
转成**标签/形参间接层**：定义一个未特化的类模板、对它做部分特化，再让函数转发进去——
这是 05 章 traits 的骨架，也是"重载优先、特化收尾"的惯用法。

**NTTP 的 C++20 放宽**。旧规则：整数/枚举/指针/左值引用。C++20：字面类型、可复制，
且其隐式/默认 `operator==` 在约束上下文中可用——🔧（已实测 g++ 15.2 `-std=gnu++20`）：

```cpp
struct Fraction { int num, den; };                    // 隐式成员 operator==
template <Fraction F> constexpr double fv() { return double(F.num) / F.den; }
static_assert(fv<Fraction{3, 4}>() == 0.75);
```

⚠️ 细节：C++20 初版把 `operator==` 写成 explicit 或返回非 bool 的 NTTP 在相等性判定上
有限制（C++23 修，见演进节）。

**变量模板+别名模板的"两件套"惯式**：trait 本体是类模板（`is_pointer<T>`），
`_v` 是变量模板（`is_pointer_v`），`_t` 是别名模板（`remove_pointer_t`）。
变量模板特化🔧（已实测）：

```cpp
template <typename T> constexpr const char* typeName = "other";
template <> constexpr const char* typeName<int> = "int";      // 变量模板显式特化
static_assert(typeName<int>[0] == 'i');
```

**泛型 lambda = 成员模板**：`auto f = [](auto a, auto b){ return a+b; };` 脱糖为闭包类的
`template<typename A, typename B> auto operator()(A,B) const`。因此**不能**把泛型 lambda
赋给固定签名的函数指针，但可以传给 `std::invoke` 风格模板——07 章类型擦除节会用到这条边界。

## 权衡

- **隐式 vs 显式实例化**：隐式零维护但每 TU 重复解析（编译时间），且实现必须进头文件；
  显式实例化（`extern template` + 集中定义）把常用实参表钉死在库边界，换来头文件干净、
  增量编译快、ABI 可控——std::vector 的 libstdc++ `_GLIBCXX_EXTERN_TEMPLATE` 即此手法。
- **特化 vs 重载**：函数模板特化不参与重载决议的推导阶段（特化不是新函数名，
  是"给定实参下的另一份体"），极易写出"以为在特化其实在加重载"的错配；
  社区共识（含本书立场，与 [../Effective_Modern_C++/00-总览与阅读地图.md](../Effective_Modern_C++/00-总览与阅读地图.md)
  口径一致）：**优先重载（含参数标签/traits 间接层），慎用函数特化**。
- **部分特化 vs `if constexpr`**：能力有重叠时选后者（可读、错误信息好）；
  但"从类型上匹配模式"（如 `T*`、`std::pair<A,B>`）仍是偏特化独占的能力，constexpr if 做不到。

## 相邻概念对比

- **别名模板 vs typedef**：`template<class T> using Ptr = T*;` typedef 无此能力；
  别名模板**不能**被特化（想定制走 traits 类模板），这造成"模板模板形参收不下别名模板"
  的经典坑（`template<template<class> class> struct S` 对 `Ptr<T, Alloc>` 带默认实参时的匹配问题）。
- **成员模板 vs 虚函数**：成员模板不可虚（vtable 需在编译期定型）；CRTP 的静态分派
  正好补这个洞（[07 章](07-模式和惯用法.md)）。
- **变量模板 vs 内联全局**：C++17 内联变量让"头文件定义一次"不再靠函数包装的旧技巧
  （Meyers singleton 的 `static X& instance()` 写法退役），对照 [../Effective_Modern_C++.md](../Effective_Modern_C++.md) 的 Item 4 口径。

## 最新演进与工业实践

- **P2996 反射**（实测 wg21.link → 2025 年 R13，"Reflection for C++26"）会把"为每个类型
  手写 trait 特化"变成"从类型元数据自动生成"——`typeName` 这类手工表是反射最典型的靶子。
- **C++23 对 NTTP 的补丁**：允许显式 `operator==`/非字面类形参等限制被放宽
  （P2096R3 "Explicitly defaulted comparison operators and literal classes" 与
  P2124R1 "Correct NTTP spelling" ⚠️ 编号未逐一实测，特性方向属实）。
- **never-constexpr static_assert(false) 的裁决**：CWG 曾讨论把"依赖外 false"直接判非法
  （P2593 系列语境 ⚠️ 不展开），本书 C++20 写法（`false_v<T>`）仍是安全模式。
- **工业对照**：abseil 的 `absl::optional`/`flat_hash_map` 头文件里大量使用
  "主模板+偏特化萃取"（`TypeTraits` 风格）与 extern template 控制实例化；
  Boost.Hana 把"变量模板做编译期值、别名模板做类型函子"推到极致
  （仓库 boostorg/hana，其 `hana::type` 系列是本 02 章语法密度上限的试炼场）。
