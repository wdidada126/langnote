## 核心概念速览（中英对照）

- **输入序列边界** — input sequence boundary：把"一段可遍历的东西"抽象为 起点+终点 的配对；STL 设计的第一原语。
- **半开区间** — half-open range `[first, last)`：end 是哨位不是元素；空区间与指针算术的自洽选择。
- **迭代器** — iterator：对"指针"的概念抽象：解引用 + 自增 + 可比较（按类别逐级加码）。
- **迭代器类别** — iterator categories：input → forward → bidirectional → random → contiguous，能力包含链，也是 tag dispatch 的标签族。
- **哨兵** — sentinel（C++20）：与迭代器不同类型但可 `==` 的终点描述；`[it, sent)` 推广了"end 不一定是位置，可以是条件"。
- **环形缓冲** — ring buffer / circular buffer：定容覆盖式容器，STL 兼容性实验田（非连续 ⇒ 无缘 contiguous/random）。
- **泛型算法** — generic algorithm：以迭代器/范围为输入、以概念为前置条件的纯函数式操作。
- **算法的可组合性** — composability：count_if/transform 等以谓词/投影为一等参数的乘法性质。
- **代理式解引用** — proxy dereference：`operator*` 按值返回（环形缓冲覆盖语义下引用会悬垂），输入迭代器的合法姿势。

## 机制

**8.1 的设计三角**：容器负责"元素 + 如何取得边界"，迭代器负责"移动与访问的能力等级"，
算法负责"以最低够用能力完成操作"。机制层要点：算法通过 `std::iterator_traits<It>` 的
**五个 typedef**（category/value/difference/pointer/reference）获知能力——traits 在这里
不是工具而是**协议**。

**环形缓冲的迭代器设计**（8.2 的全部张力所在）。环是逻辑序、物理不连续 ⇒
① 不能给 `T&`（覆盖随时发生）⇒ 输入迭代器按值代理返回 `T`；
② 不能给 `++` 的算术跳跃 ⇒ random access 无望；
③ `begin == end` 在"满"时撞车 ⇒ 用**剩余计数**或哨兵区分空满。🔧（已实测 g++ 15.2）
用 C++20 哨兵协议把三件事全解决：

```cpp
template <typename T, std::size_t N>
class RingView {
    std::array<T, N> buf_{}; std::size_t head_ = 0, count_ = 0;
public:
    void push(const T& v) { buf_[head_] = v; head_ = (head_ + 1) % N; if (count_ < N) ++count_; }
    struct sentinel {};                      // end 不再是一个位置，而是一个"判断"
    class iterator {
        const RingView* rv_ = nullptr; std::size_t idx_ = 0, left_ = 0;
        friend class RingView;
        iterator(const RingView* rv, std::size_t i, std::size_t l) : rv_(rv), idx_(i), left_(l) {}
    public:
        using iterator_category = std::input_iterator_tag;   // 诚实申报能力上限
        using value_type = T; using difference_type = std::ptrdiff_t;
        using pointer = void; using reference = void;        // 代理输入：按值解引用
        T operator*() const { return rv_->buf_[idx_]; }
        iterator& operator++() { idx_ = (idx_ + 1) % N; --left_; return *this; }
        bool operator==(const iterator&) const;              // 全等比较（概念要求）
        bool operator==(sentinel) const { return left_ == 0; }
    };
    iterator begin() const { return iterator(this, (head_ + N - count_) % N, count_); }
    sentinel end() const { return {}; }
};
static_assert(std::input_iterator<RingView<int, 4>::iterator>);
static_assert(std::ranges::range<RingView<int, 4>>);   // 两条实测通过：协议合规自证
```

写入 1..6 到容量 4 的环，遍历得 3,4,5,6，`sum=18`——**覆盖式容器 + 输入迭代器 + 哨兵**
的最小完备样本。对照 SGI STL 时代（`../STL源码剖析/` 03 篇）实现同一件事要写多少
`iterator_traits` 特化手工件：这就是"协议从 traits 到概念"迁移的实物证据。

**8.3 自定义算法的约束书写**。双入口（迭代器对 + 范围）各一版，前置条件全部用概念
（🔧 实测，含 `std::predicate` 检查谓词对 `iter_value_t` 合法）：

```cpp
template <std::input_iterator It, std::sentinel_for<It> Sent, typename Pred>
    requires std::predicate<Pred, std::iter_value_t<It>>
int count_if_it(It a, Sent b, Pred p);

template <std::ranges::input_range R, typename Pred>
    requires std::predicate<Pred, std::ranges::range_value_t<R>>
int count_if_range(R&& r, Pred p) { return count_if_it(std::ranges::begin(r), std::ranges::end(r), p); }
```

机制层注意：`range_value_t<R>` 走的是 `iterator_t` 的 traits 链——**概念背后仍是 05 章
的探测器机器**；`R&&` + 不转发（只取 begin/end）避免悬垂的转发歧义。算法组合的示范
`sum_of_squares`（手写 fold，C++20 无 `std::accumulate` 的 ranges 版）显示：
"算法 = 范围协议 + 可调用件概念"两条正交轴。

## 权衡

- **迭代器 vs 索引**：环上索引 `(head_+i)%N` 也自洽，为何选迭代器？因为算法层只依赖
  协议不依赖容器形状——索引路线把算法钉死在 `operator[]` 语义上（连续假设）。
- **按值代理 vs 引用**：代理输入迭代器合法但**不可再入**（两次 `*it` 比较的是临时量）；
  想给 forward 及以上就必须解决覆盖问题（快照/双缓冲），成本立涨——诚实申报
  input 类别是性能与正确性的帕累托点。
- **C++20 概念 vs 手写 SFINAE 约束**：本章代码用概念版；等价的 05 章探测器版冗长
  一倍且零诊断优势。"协议时代"的选型已经没有悬念，需要会写的只有 traits 兼容层。

## 相邻概念对比

- **本章"范围"（抽象概念）vs 09 章"范围库"（std::ranges）**：8.1 标题的"范围"是
  Steele 式的输入序列边界概念；09 章才是 C++20 实体。作者分两章正是"抽象→机制"的台阶。
- **自定义算法 vs `std::ranges` 管道**：单用途算法（count_if_range）可写成闭包以进管道，
  那属于 09 章适配器的技术；本章先立"受约束函数"的地基。
- **迭代器协议 vs Java/C# Iterator/enumerator**：后者是对象方法（hasNext/next），
  STL 把"移动/访问/比较"拆成自由函数+traits ⇒ 非 intrusive（任何类型零侵入接入）——
  C++ 迭代器史上最重要的设计差异。

## 最新演进与工业实践

- **哨兵的现实用例**：`std::views::istream<T>` 的结束判定、零终止串（`std::ranges::
  c_str` ⚠️ 未核实该工具是否随 C++26 落地）、"读到分隔符为止"——end 从位置升级为谓词
  后，I/O 流容器第一次原生进 STL。
- **ranges 设计争议回望**：C++20 合并 ranges 时牺牲了 range-v3 的部分概念精度
  （间接投影 `indirect_unary_predicate` 的简化等 ⚠️ 具体条目不展开）；Niebler 的
  失望与 range-v3 持续演进是当代泛型库治理的名场面——读
  [../C++标准库/00-总览与阅读地图.md](../C++标准库/00-总览与阅读地图.md) 各章演进节可见同一争议在
  库侧的回响。
- **abseil 的对照实践**：`absl::c_*` 系列算法（对老 C++11 代码库的"伪 ranges"）证明
  范围接口的价值不依赖 C++20 机制——**接口先行**，概念是后来的正名。
- **fmt 的"容器协议"时刻**：fmt 的 `formatter<T>` 特化点就是"自定义类型接入标准遍历
  协议"的镜像案例：ranges 管读，formatter 管印；09 章管道 + 本章协议在格式化场景合流。
