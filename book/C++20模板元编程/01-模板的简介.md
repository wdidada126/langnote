## 核心概念速览（中英对照）

- **模板** — template：以类型/值/模板为形参的编译期代码生成器，C++ 泛型的语法根基。
- **泛型编程** — generic programming：算法面向"满足某概念的类型"而非具体类型书写（Steele & Levitt 提出，Stroustrup 引入 C++）。
- **参数化多态** — parametric polymorphism：同一份定义对任意类型实参成立，与子类型多态（虚函数）正交。
- **模板元编程** — template metaprogramming (TMP)：在编译期对类型求值、生成类型的图灵完备子语言（1990s 发现，Veldhuizen 等推动数值库应用）。
- **代码膨胀** — code bloat：每个实例化生成独立副本的代价；被"单份手写代码+运行期分派"的反面（脆弱基类、性能损耗）抵消一部分。
- **编译期多态** — static (compile-time) polymorphism：分派发生在重载决议/实例化期，运行期零开销。
- **实例化点** — point of instantiation：模板体到那里才真正"落地"，两阶段查找的第二阶段挂靠其上（详见 [04 章](04-高级模板的概念.md)）。

## 动机：这一章在书里的位置

本书是"先语法、再机制、后应用"的三段式（见 00 的映射表），第 1 章承担**建立心智模型**：
为什么 C++ 不用"一个函数存一份、类型运行期检查"的路线（Java/C# 泛型的类型擦除或具化），
而选择了"编译期按实参各生成一份"。这个选择决定了全书一切机制的成本模型——
**零开销抽象**：不用的不生成，用了的和手写的一样快，代价是错误信息（本目录在
[05](05-类型特征和条件编译.md)/[06](06-概念和约束.md) 章用实测诊断直面对比）、
编译时间与代码体积。

1.2 的"第一个模板"🔧 最小形态（已实测 g++ 15.2）：

```cpp
template <typename T>
constexpr T maxv(T a, T b) { return a < b ? b : a; }
static_assert(maxv(3, 7) == 7);   // 编译期即完成 int 版实例化与求值
```

机制层面此刻只需要知道：`maxv(3,7)` 触发**隐式实例化**，编译器用实参 `{int}` 代入，
生成一个 ordinary 函数 `int maxv<int>(int,int)`；若写 `maxv(3.5, 2)`，推导会因
`T` 同时来自 `double` 与 `int` 而失败（同位形参推得矛盾实参）——这是第一个"模板≠宏"
的实证：推导是**带规则的语义过程**，不是文本替换。

1.4 简史的锚点（通行记载，非逐字引书 ⚠️）：Templates 1990 进入 ARM/标准化（Stroustrup
《The Design and Evolution of C++》第 15 章）；1993 Unruh 意外发现模板可计算，
Veldhuizen 1994 技术报告把表达式模板带进数值计算（报告编号未核实 ⚠️，见 07 章）；
2003 Alexandrescu《Modern C++ Design》把 TMP 工程化；2005 Abrahams & Gurtovoy 的 MPL
册是前 C++11 时代集大成（库内 [../C++模板元编程.md](../C++模板元编程.md)）；C++11 起
语言用内置设施（变参/`constexpr`/`decltype`）逐步收编黑魔法，C++20 concepts 给接口侧收尾
——本书正站在这条线的"当代"位置上。

## 权衡：1.5 "优缺点"的机制化重述

- **优点**：类型安全（编译期即错）、零运行开销、跨类型复用、表达能力直达类型层
  （`is_copy_constructible_v<T>` 这种"对类型编程"没有任何运行期语言做得到）。
- **缺点**：诊断学灾难（本书 05→06 章的主线就是治它）、编译时间、错误位置远离根因
  （实例化点与出错点分离）、接口约束隐式化（concepts 之前调用者无法从签名读出要求）。
- **反方立场也要会答**：虚函数/`std::function` 以一次间接调用换单份代码与开放扩展。
  选型判据不是"现代偏好"，而是：类型集是否封闭于编译期、每调用开销是否敏感、
  是否需要以类型为输入做决策（这三条都指回 07 章 CRTP vs 类型擦除的正面对决）。

## 相邻概念对比

- **模板 vs 宏**：宏在预处理期做文本替换、无类型检查无作用域；模板参与重载决议与
  名称查找（04 章两阶段查找是本质区别）。
- **模板 vs `std::any`/继承**：参数化多态在类型层展开，子类型多态在对象层隐藏类型；
  对比表见 [07 章](07-模式和惯用法.md)"动态多态和静态多态"。
- **C++ 模板 vs Java 泛型**：Java 类型擦除使 `T.class` 不存在、无法按实参特化生成；
  C++ 每个 `X<int>`/`X<double>` 是不同完整类型——02 章显式特化的存在理由。
- **侯捷视角**：STL 源码剖析用 trait 把"迭代器背后是什么"讲成运行期效率的根，
  与本书 05 章 traits 是同一枚硬币两面，见 [../STL源码剖析/00-总览与阅读地图.md](../STL源码剖析/00-总览与阅读地图.md)。

## 心智模型：模板是编译期的纯函数

把本章 1.1/1.3 的信息压成一条可长期使用的模型：**模板 = 编译期纯函数，
实参 = 类型/值/模板，返回值 = 生成的实体（函数/类），异常 = 编译错误**。
四个推论都能在后文找到落点：

1. 纯函数不缓存：同一实参在多 TU 各生成一份，靠链接器 COMDAT 折叠——
   显式实例化（02 章 2.5.2）就是手工加缓存。
2. 参数空间是"类型 ∪ 常量 ∪ 模板"三族——NTTP/模板模板形参（02 章 2.4）各自解锁一族。
3. "函数重载"与"偏特化"是两套选路算法：前者走重载决议+推导（04 章），
   后者走模式匹配+偏序（02 章 2.6）；混用是新手第一大坑，本书第 2 章就立此存照。
4. 异常信息差是因为**错误发生在"调用点"而非"定义点"**（两阶段查找，04 章 4.1）；
   concepts（06 章）本质是给函数加"参数类型注解"，让校验前置。

## 最新演进与工业实践

- **C++20 不是终点**：concepts 只是"接口侧"落地，"生成侧"的大招（静态反射）仍在路上——
  P2996（Reflection for C++26，已实测 `wg21.link/P2996` 解析至 2025 年 R13）若最终落地，
  本书 02/05 章手写的 traits 家族大半可自动生成 ⚠️ 尚为提案。
- **工业侧的"零开销"证词**：fmtlib 的 `FMT_COMPILE`/`std::format` 编译期格式串解析、
  simdjson 的表生成，都是"模板生成代码 ≈ 手写代码"路线的当代旗舰（对应点分散在
  [03](03-变参模板.md)/[05](05-类型特征和条件编译.md)/[07](07-模式和惯用法.md) 各章演进节）。
- **反面证词同样重要**：Google C++ Style 长期限制模板复杂度（"friendliness to readers
  over cleverness"），abseil 大量采用运行期确定类型的 `string_view`/`fixed_map` 方案；
  本书立场是"懂机制、克制使用"，与两种立场都能对话。
