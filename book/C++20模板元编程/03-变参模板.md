## 核心概念速览（中英对照）

- **形参包** — parameter pack：`typename... Ts` 声明的零或多个实参序列；只能在"展开上下文"中出现。
- **包展开** — pack expansion：`Ts...` 形式；`...` 在**声明侧属类型、展开侧属模式**。
- **折叠表达式** — fold expression（C++17）：把二元运算符注入整个包的四形态缩写。
- **一元右/左折叠** — unary right/left fold：`(pack op ...)` / `(... op pack)`；空包时各有恒等式。
- **二元右/左折叠** — binary right/left fold：`(pack op ... op init)` / `(init op ... op pack)`。
- **sizeof...** — 包长度的编译期常量，空包合法返回 0。
- **递归消解** — recursive unpacking：`f(head, tail...) → f(tail...)` 的 C++11 祖传展开。
- **初始化列表展开技巧** — expansion via initializer list：`int a[] = {0, (expr(xs),0)...}` 借花括号**保证从左到右**的求值序。
- **同质包约束** — homogeneous pack constraint：C++20 写法 `requires (convertible_to<Ts, double> && ...)` 给整个包立规矩。
- **元组间接层** — tuple as pack stand-in：包不能当成员/模板实参传递的地方，一律换 `std::tuple`（3.4/5.6 的官方逃生门）。

## 动机

变参之前，"任意个实参"只有两个坏选项：手动 `f(a,b)`/`f(a,b,c)` 阶梯（组合爆炸）或
`va_arg`（类型不安全、无析构、无推导）。`std::tuple`、`make_unique`、`emplace_back`、
`print/format` 全都要靠一个能**原样转发任意签名**的机制——这就是形参包存在的唯一理由。
理解这一点，就知道为什么变参总是和引用折叠（04 章）、完美转发绑在一起讲。

## 机制

**四形态折叠与空包语义**（本目录实测核心）🔧（已实测 g++ 15.2）：

```cpp
template <typename... Ts> auto sum (Ts... xs) { return (xs + ...); }  // 一元右折叠
template <typename... Ts> auto sumL(Ts... xs) { return ((... + xs)); }// 一元左折叠
template <typename... Ts> void printAll(Ts&&... xs) { (std::cout << ... << xs) << '\n'; } // 二元注入
template <typename... Ts> bool allPositive(Ts... xs) { return ((0 < xs) && ...); }
// 实测运行输出：sum=6 sumL=6 allPositive=1
```

空包规则必须背：`(&& pack)` 返回 `true`、`(|| pack)` 返回 `false`、
`(pack + ...)` 返回 `int()`（0）——即逻辑恒等式，这让 `((cond(xs) && ...) && ...)`
式"全包谓词"在空包时**真**（vacuous truth），写约束时是特性不是坑。

**展开次序：本章的深水区**。`f(a...)` 的实参求值次序是 **unspecified**（每个实参表达式
内部可以交错），而花括号初始化列表**保证从左到右**。所以"我要按序展开"的标准技巧：

```cpp
std::vector<int> log_;
int tick(int x) { log_.push_back(x); return x; }
template <typename... Ts> void expandLeftToRight(Ts... xs) {
    int dummy[] = {0, (tick(xs), 0)...};  // braced-init：次序有保证
    (void)dummy;
}
```
实测输出 `order: 1 2 3`（同一程序里对比函数调用形态则次序随实现而定）。
C++17 的 `std::initializer_list` 与逗号展开至今仍是"按序遍历包"的正典；
`printAll` 里 `(std::cout << ... << xs)` 是折叠自带从左到右的结合，不受实参次序问题影响
——**这是"用折叠而不是手搓展开"最硬的理由**。

**变参类模板与包的存放**。包不能做数据成员；`struct Box<Ts...>` 里想存下来，
惯用法是继承/成员的 `std::tuple<Ts...>`（3.4 的思路），配合 07 章的
`std::index_sequence` 按下标展开。变参别名模板（3.6）如
`template<class... Cs> using Tuple = std::tuple<Cs...>;`；变参变量模板（3.7）如
`template<class... Ts> constexpr bool all_integral = (std::is_integral_v<Ts> && ...);`
——两者是 06 章"约束整个包"的原料。

**递归消解的活化石地位**：`void rsum(long&)` 递归基 + `rsum(long&, T, Rest...)`
两重载。折叠出现前的一切变参库（MPL 册第 8 章、`std::tuple` 早期实现）都用它；
今天只在"需要按索引区间分治"时才写。**每个折叠都能改写成递归，反之不显然**——
非结合运算（如函数复合、减法链）用右折叠保语义、左折叠结果不同——🔧 实测 `sum(1,2,3)`
与 `sumL(1,2,3)` 对可结合的 `+` 同为 6；对 `-` 则左折叠 `((1-2)-3) = -4`，
一元右折叠 `1-(2-3) = 2`（结合性差异，非实现差异）。

**空包行为速查表**（背下来能省一次调试）：

| 形态 | 例子 | 空包结果 |
| --- | --- | --- |
| 一元右 `(pack op ...)` | `(xs + ...)` | `int()` → 0；`&&` → true；`||` → false |
| 一元左 `(... op pack)` | `((... + xs))` | 同上恒等式 |
| 二元右 `(pack op ... op init)` | `(xs + ... + 0)` | `init`（0） |
| 二元左 `(init op ... op pack)` | `(0 + ... + xs)` | `init`（0） |
| `sizeof...(pack)` | — | `0`（唯一恒合法的零查询） |

## 权衡

- **折叠 vs 展开成初始化列表**：折叠表达的是"运算"，列表技巧表达的是"副作用序列"；
  前者可读、后者可控次序，多数场景 `(f(xs), ...),` 组合即可两者兼得。
- **变参模板 vs 容器参数**：`f(std::vector<int>)` 运行期长度、类型同质；
  变参是编译期长度、类型可异——只有需要**逐实参类型**做事（打印、构造、按类型分派）
  时才有存在资格，否则用容器（更短的错误信息、更少的代码膨胀）。
- **包约束 vs `static_assert`**：C++20 的 `(trait<Ts> && ...)` 进 requires 子句，
  失败时**约束不满足**（06 章诊断）；进 body 的 static_assert 则所有候选都参战后才炸，
  重载决议场景下语义也不同（SFINAE vs 硬错误）。

## 相邻概念对比

- **变参模板 vs `std::function` 包装**：后者类型擦除、长度运行期，变参保持具型；
  工厂/转发场景选变参模板，回调存储场景选 function（[07 章](07-模式和惯用法.md)类型擦除）。
- **`...` 三种身份**：C 风格省略号（类型不安全遗物）、模板形参声明、展开操作符——
  3.3 的术语澄清专治这个符号重载。
- **与 04 章的分工**：本章解决"多个"，04 解决"每个怎么推、怎么转发"——
  `void printAll(Ts&&... xs)` 里 `Ts&&` 是转发引用 + 包，两者叠加才有"完美转发任意实参"。

## 最新演进与工业实践

- **P2662 "Pack Indexing"**（已实测 wg21.link/P2662 → 2023 年 R3，Jabot & Halpern）：
  提案给包加 `T...[0]` 式下标访问。本书时代取包中第 i 个类型仍要靠
  `std::tuple_element_t<i, std::tuple<Ts...>>` 间接层——这正是提案的靶子。⚠️ 未合入。
- **C++23/26 的变参增量**：`if consteval`、`std::generator` 与变参无直接关系，不展开；
  与本章最近的仍是 lambda 初始化捕获里的包展开限制（`[...xs = xs]`）——C++20 非法，
  GCC15 仍未放行 ⚠️ 对应提案未逐一实测。
- **fmt/ranges**（fmtlib 仓库）：`fmt::format` 的 `format_args...` 就是把变参打包成
  `basic_format_args` 的教科书工程——"包不能存 → 元组/动态视图存"（3.4 思路的工业版），
  编译期由模板展开做逐实参类型检查，运行期只留类型码字。
- **std::print**（C++23）：本书 3.2 的 `printAll` 玩具对应标准里的 `print(args...)`，
  其签名 `template<class... Args> void print(format_string<Args...>, Args&&...)`
  是"变参 + 概念 + 编译期字符串"三合一的当代范本。
