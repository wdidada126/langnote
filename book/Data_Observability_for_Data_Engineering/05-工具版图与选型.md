## 5.1 工具版图概览（⚠️ 全部厂商口径，转述登记）

数据可观测性工具可分为三类（⚠️ 编者归纳）：

| 类别 | 代表工具 | 特征 |
|---|---|---|
| 商业平台 | Monte Carlo, BigEye, Datadog Data Observability, Soda | 全栈：采集+推断+行动 |
| 开源框架 | Elementary, Soda Core, Great Expectations, dbt tests | 信号采集+部分推断 |
| 自建最小栈 | SQL 规则 + cron + 通知 API | 完全定制，维护成本高 |

> ⚠️ 以上分类与功能描述均为品类通识级转述，非本书原书表述。各平台官方文档为第一手依据。

## 5.2 选型四问（⚠️ 编者归纳）

1. **规模**：你的关键表有多少张？< 100 张用开源/自建足够；> 1000 张考虑商业平台。
2. **栈复杂度**：你的数据栈有几层？层数越多，血缘自动化越重要。
3. **团队成熟度**：你的团队有 SRE/运维经验吗？有则自建门槛低；无则商业平台的开箱即用更合适。
4. **预算**：商业平台按表/按行数计费，大表多表场景成本可能超预期。

## 5.3 自建最小栈的 SQL 骨架 🔧 综合

02–04 章的四组 🔧 实验（G1 时效/G2 模式/G3 血缘/G4 体量）组合起来，恰好构成一个**自建最小观测栈**的计算骨架：

| 层 | 对应 🔧 组 | 功能 |
|---|---|---|
| 信号采集 | G1 freshness_sla + daily_volume | 时效/体量的持续快照 |
| 推断引擎 | G2 EXCEPT diff + G4 MAD z-score | 模式/体量的异常检测 |
| 影响分析 | G3 WITH RECURSIVE | 血缘递归遍历 |
| 行动路由 | alert_routing（04 章） | 告警路由 + 冷却 |

这个最小栈用 SQLite 即可运行——当然，生产环境需要替换为能支撑并发与数据量的引擎（⚠️ 推定）。

## 5.5 开源 vs 商业的决策树（⚠️ 编者归纳）

```
关键表 < 50 且团队有 SQL 能力？
  → 是：dbt tests + Elementary + Slack webhook
  → 否：评估商业平台
关键表 > 500 且需要自动血缘？
  → 是：商业平台（自动血缘是核心差异化）
  → 否：开源 + 手工血缘登记
需要合规审计台账？
  → 是：商业平台（内建审计日志）
  → 否：自建 + 自定义台账表
```

## 5.6 成本模型（⚠️ 推定）

商业平台的典型计费维度：
- **按监控表数**：每月每表 $X。
- **按扫描行数**：每月每百万行 $Y。
- **按用户数**：每月每用户 $Z。

自建的成本主要在**工程维护**：
- 监控规则的维护与更新。
- 快照基础设施的运维。
- 告警通道的集成。

## 核心概念速览（中英对照）

- **商业平台** — Commercial Platform：Monte Carlo/BigEye/Datadog 等全栈观测产品。
- **开源框架** — Open Source Framework：Elementary/Soda Core/Great Expectations 等。
- **自建最小栈** — DIY Minimum Stack：SQL 规则 + cron + 通知 API 的最小可运行观测系统。
- **选型四问** — Four Selection Questions：规模/栈复杂度/团队成熟度/预算。
- **自动血缘** — Automated Lineage：从 ETL 引擎自动采集血缘事件的能力。
- **按表计费** — Per-Table Pricing：商业平台的典型计费模式之一。
- **工程维护成本** — Maintenance Cost：自建方案的人力成本主体。
- **开箱即用** — Out-of-the-Box：商业平台的核心卖点。
- **OpenLineage** — OpenLineage：开放血缘事件标准，开源工具互通基础。
- **决策树** — Decision Tree：选型的结构化判断流程。

## 最新演进与工业实践

- **平台整合趋势**：Datadog 等传统 APM 厂商进入数据观测赛道，与原生数据观测平台竞争（⚠️ 品类观察）。
- **开源生态成熟**：Elementary 从 dbt 生态起步，已支持多引擎；Soda Core 支持多数据源——开源方案的覆盖面在扩大（⚠️）。
- **云仓内建化**：Snowflake/BigQuery 开始内建基础观测功能（freshness/volume），压缩了自建最小栈的存在空间（⚠️）。
- **工业实践口径**：选型不是一次性决策——从开源起步、随规模增长升级商业平台是常见路径（⚠️）。
