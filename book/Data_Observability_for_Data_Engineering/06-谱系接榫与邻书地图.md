## 6.1 数据可观测性在数据管理谱系中的位置

数据可观测性不是孤立品类——它与治理、网格、主动元数据、数据目录构成互补平面（⚠️ 编者归纳）：

| 品类 | 核心问题 | 与观测的关系 |
|---|---|---|
| 数据治理 | 谁有权做什么？ | 治理定制度，观测供运行信号验证制度 |
| 数据网格 | 数据即产品的 SLA 谁来兑现？ | 观测是 SLA 的运行态兑现器 |
| 主动元数据 | 元数据能否驱动自动化？ | 观测信号是主动元数据的输入源 |
| 数据目录 | 有哪些数据资产？ | 目录是登记簿，观测是运行态信号流 |

## 6.2 与数据治理的接榫

治理制度（政策、权责、标准）若无运行信号支撑则停留在文档层——这是 [../Understanding_Data_Governance/00-总览与阅读地图.md](../Understanding_Data_Governance/00-总览与阅读地图.md) 的核心论点之一。

观测对治理的贡献（⚠️ 推定）：
1. **权责验证**：告警路由的 owner 字段是否有人认领？——治理的「数据所有者」角色是否真实运作。
2. **标准验证**：SLA 达成率是否达标？——治理的「数据质量标准」是否被满足。
3. **合规验证**：数据血缘是否完整？——治理的「数据溯源要求」是否被满足。

反向：治理对观测的贡献是**提供组织合同**——没有治理制度，观测的告警路由和升级机制无处锚定。

与 Ladley 治理规程的实链：[../Data_Governance_Elsevier/00-总览与阅读地图.md](../Data_Governance_Elsevier/00-总览与阅读地图.md)。

## 6.3 与数据网格的接榫

数据网格的核心原则是「数据即产品」——每个域团队对自己的数据产品负全责，包括 SLA。

观测在网格中的角色（⚠️ 推定，实链 [../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md)）：
- **SLA/SLO 的运行态兑现**：网格的数据产品合同需要观测体系来持续验证。
- **自助平台的内建能力**：网格的自助数据平台需要提供观测能力给域团队。
- **联邦治理的度量基础**：网格的联邦治理需要跨域的观测度量来评估一致性。

## 6.4 与主动元数据的接榫

主动元数据（Active Metadata）的核心思想是：元数据不仅被查询，还驱动自动化动作。

观测信号是主动元数据的关键输入（⚠️ 推定，实链 [../Data_Fabric_as_Modern_Data_Architecture/00-总览与阅读地图.md](../Data_Fabric_as_Modern_Data_Architecture/00-总览与阅读地图.md)）：
- 时效违约 → 自动暂停下游管道。
- 模式漂移 → 自动触发 schema 审查工作流。
- 体量异常 → 自动标记数据资产为「待验证」。

## 6.5 与数据目录的接榫

数据目录是**设计态**的元数据存储（资产登记、口径说明、负责人）；观测是**运行态**的信号流（时效、体量、模式、分布）。

两者在「可发现性」处汇合（⚠️ 推定，实链 [../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md](../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md)）：
- 目录让观测信号有归属（这张表的告警发给谁）。
- 观测让目录条目有生命信号（这张表还活着吗、健康吗）。

## 6.6 与血缘纵深的接榫

血缘分析的技术纵深（图算法、影响分析、变更追溯）在 [../数据血缘分析原理与实践.md](../数据血缘分析原理与实践.md) 中展开。本册 02 章 G3 只做了最基本的递归遍历——生产环境需要更成熟的血缘基础设施。

## 6.7 四品类成熟度对照（⚠️ 编者归纳）

治理/网格/目录/观测四品类的成熟度在不同组织中差异显著（⚠️ 推定）：

| 品类 | 起步门槛 | 成熟标志 | 常见瓶颈 |
|---|---|---|---|
| 数据治理 | 制度文档 + 权责分配 | 运行信号可验证制度有效性 | 制度停留在纸面 |
| 数据网格 | 域团队划分 + 数据产品合同 | SLA 由观测持续兑现 | 域团队能力参差 |
| 数据目录 | 资产登记 + 口径说明 | 运行态信号反灌目录 | 目录条目无人维护 |
| 数据观测 | SQL 规则 + 通知 | 自动基线 + 因果闭环 | 告警疲劳、组织不响应 |

关键洞察：**四品类的成熟度必须同步推进**——治理领先但观测落后，制度无法验证；观测领先但治理落后，告警路由无处锚定。这是组织级数据能力建设的系统论约束（⚠️ 编者判断）。

与盘上四册的对应：治理双册（#186 Data_Governance_Elsevier / #189 Understanding_Data_Governance）提供制度面；网格（Data_Mesh）提供产品面；目录（EDC 2e）提供登记面；本册提供运行面。四册合读 = 数据管理全景。

**实践启示**（⚠️ 编者建议）：如果你的组织正在同时推进治理和观测项目，建议先完成治理的「权责分配」模块（确保每张关键表有 owner），再部署观测的告警路由——否则告警发出后无人认领，比没有告警更糟。这是从多次品类实践中归纳的先后关系（⚠️ 转述）。

**盘上四册阅读顺序建议**（⚠️ 编者建议）：对于想系统理解数据管理全景的读者，建议按以下顺序阅读盘上四册——① [../Understanding_Data_Governance/00-总览与阅读地图.md](../Understanding_Data_Governance/00-总览与阅读地图.md)（治理框架入门）→ ② [../Data_Governance_Elsevier/00-总览与阅读地图.md](../Data_Governance_Elsevier/00-总览与阅读地图.md)（治理规程纵深）→ ③ [../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md](../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md)（目录实施）→ ④ 本册 06 章（观测↔治理接榫）。网格册（Data_Mesh）可作为并行阅读件——它的「数据即产品」原则贯穿四册。

**四品类工具栈的交集与差异**（⚠️ 编者归纳）：

| 能力 | 治理工具 | 网格工具 | 目录工具 | 观测工具 |
|---|---|---|---|---|
| 权责登记 | ✅ 核心 | ✅ 域团队 | ✅ 资产 owner | ⚠️ 消费（路由依据） |
| SLA 管理 | ✅ 定义 | ✅ 合同 | ⚠️ 登记 | ✅ 运行态验证 |
| 血缘 | ⚠️ 合规需求 | ⚠️ 域间接口 | ✅ 登记 | ✅ 运行态采集 |
| 变更管理 | ✅ 审批流 | ✅ 产品版本 | ✅ 版本登记 | ✅ 漂移检测 |

四品类工具栈正在走向融合——但现阶段的融合度仍低，多数组织需要分别部署并在接口处做集成（⚠️ 品类观察）。

## 核心概念速览（中英对照）

- **设计态 vs 运行态** — Design-time vs Runtime：目录/治理是设计态，观测是运行态。
- **主动元数据** — Active Metadata：元数据驱动自动化动作，观测信号是其输入。
- **数据即产品** — Data as a Product：数据网格核心原则，SLA 由观测兑现。
- **联邦治理** — Federated Governance：数据网格的跨域治理模式，观测提供度量。
- **组织合同** — Organizational Contract：治理制度为观测提供的路由/升级/认领框架。
- **元数据覆盖率** — Metadata Coverage：治理制度在观测面的验证指标。
- **谱系接榫** — Spectrum Articulation：观测与治理/网格/目录/主动元数据的接口关系。
- **修复闭环** — Remediation Loop：观测发现→清洗修复→验证恢复的完整循环。
- **互补平面** — Complementary Planes：治理/网格/目录/观测各占不同平面，互不可替。
- **运行信号** — Runtime Signals：观测品类产出的动态数据健康信号。

## 最新演进与工业实践

- **治理+观测融合**：部分商业平台开始内建治理功能（数据所有权、SLA 管理），模糊了治理工具与观测工具的边界（⚠️ 品类观察）。
- **网格配套成熟**：数据网格的落地推动了对观测能力的需求——域团队需要开箱即用的观测（⚠️）。
- **主动元数据标准化**：OpenLineage + 各云仓的元数据 API 使观测信号回灌元数据层的成本降低（⚠️）。
- **工业实践口径**：观测不是替代治理，而是让治理「可被验证」——这是品类共识（⚠️）。
- **盘上互链**：治理（#186/UDG）、网格（Data_Mesh）、目录（EDC 2e）、Fabric（Data_Fabric）四册均在盘可链——本册 06 章是接榫枢纽。
