## 1.1 为什么数据工程需要「可观测性」（⚠️ 品类通识重构）

现代数据栈的三条演化线把「数据出问题」从偶发事故变成结构性风险（⚠️ 转述归纳，与 #226 01 章同向）：

1. **链路变长**：源系统 → CDC/事件流 → 湖仓 → 转换层 → 集市 → BI/AI。任何一环的时间语义、模式语义都可能与下游假设脱节。
2. **写入者变多**：分析工程师、数据科学家、平台工程、业务自建报表并行写入同一链路——「谁动了我的数据」从玩笑变成审计需求。
3. **消费者变成机器**：特征库、推荐系统、LLM 检索直接吃数据——坏数据不再只是「报表难看」，而是自动化决策被污染。

副题「Proactive strategies for ensuring data accuracy and addressing broken data pipelines」的两个动词——**ensuring**（ proactive 保障）与 **addressing**（reactive 修复）——恰好对应本册的两条主线（⚠️ 编者归纳）。

## 1.2 核心定义与可核锚点

- **可核锚（✅）**：Ben Moses, *The Rise of Data Observability*, WSDM '22 Companion, DOI `10.1145/3488560.3510007`——Crossref 200 实测。定义：让数据用户能够**自行发现、诊断、解决**数据问题的新兴方向。
- **工程册的增量（⚠️ 推定）**：在「发现-诊断-解决」三动词之上，本书副题强调 **proactive**（主动）——不止于事后感知，而要求把检测嵌入管道内部，使「作业成功 ≠ 数据正确」的鸿沟被运行时信号覆盖。
- **与 #226 五支柱的关系**：#226 给出 Freshness/Monitoring/Lineage/Documentation/Alerting 的分析框架（✅ 母体在盘可查，其 00 七之二）；本册推定为把这五支柱翻译成工程实施清单——监控配置、检测算法、告警路由、事件响应（⚠️ 推定）。

## 1.3 数据停机（Data Downtime）的工程定价

- **DDT 公式**（⚠️ 厂商口径转述）：DDT = N × (TTD + TTR)，事件数 ×（检测时长 + 修复时长）。
- **工程册的切入角度**（⚠️ 推定）：把 TTD 的压缩交给监控与检测算法（02/03 章），把 TTR 的压缩交给告警路由与修复工作流（04 章）——这是全册的组织骨架。
- 🔧 预告：02 章 G1 组用 SQLite 把「5 表 ×30 天滞后台账 → SLA 达成率」真实算出来，把修辞变成算术。

## 1.4 数据可观测性不是什么（防误读三则）

1. **不是数据质量工具的改名**：质量规则枚举「已知该查什么」；观测要求覆盖「没想到的坏法」。修复侧纵深见 [../数据清洗.md](../数据清洗.md)。
2. **不是端到端监控仪表盘**：仪表盘是呈现层；只有信号采集没有推断模型，仍是监控而非观测。
3. **不是血缘图谱的又一代销**：血缘服务于「定位与止损」，图谱本身不是目的。血缘技术纵深实链 [../数据血缘分析原理与实践.md](../数据血缘分析原理与实践.md)。

## 1.5 工程实施的最小构件表

把「可观测性」落到管道内，需要三类构件同时在场（⚠️ 按 #226 信号-推断-行动三构件框架推定）：

| 构件 | 工程落地物 | 缺位后果 |
|---|---|---|
| 信号面 | 时效/量/分布/模式/血缘事件的持续采集 | 只能靠人肉对账 |
| 推断面 | 阈值/基线/统计算法对信号做健康判定 | 有告警没诊断 |
| 行动面 | 通知到对的人、带上下文（影响范围、负责人） | 告警疲劳、甩票 |

## 1.7 案例推演：一张高管周报为什么会错

时间线（周一 09:30，管理层看到 GMV 周环比骤降 40%）：

1. **T-26h**：上游支付库做分库迁移，采集作业指向旧分片——作业没报错。
2. **T-2h**：`mart.order_daily` 停更。传统监控全绿。
3. **T+0**：分析师手工对账 40 分钟定位到 mart 层。
4. **T+3h**：跨团队拉群考古，追到迁移工单。

观测框架下的同一时间线（⚠️ 按五支柱推演）：
- **Freshness**：滞后突破 SLA 即告警，压缩检测段 26h→<1h。
- **Lineage**：从 mart 一跳反查上游，压缩定位段 3h→分钟级。
- **Alerting**：带影响面的通知直达 owner，压缩协作段。

结论：观测体系的价值在于把 **MTTD/MTTR** 系统性压缩。

## 核心概念速览（中英对照）

- **数据可观测性** — Data Observability：从数据资产输出推断其内部健康状态的能力（✅ Moses 锚）。
- **主动策略** — Proactive Strategies：副题核心词，要求在管道内嵌入检测而非仅事后感知。
- **数据停机** — Data Downtime：数据不可信/不可用时段，DDT = N×(TTD+TTR)。
- **检测时延** — Time to Detect (TTD)：故障发生到被发现的时长。
- **修复时延** — Time to Resolve (TTR)：发现到恢复可信的时长。
- **作业成功 ≠ 数据正确** — Green Pipeline, Bad Data：控制平面与数据平面信号不重合。
- **信号-推断-行动** — Signal / Inference / Action：观测系统的三构件框架。
- **数据质量 vs 观测** — Data Quality vs Observability：规则枚举 vs 运行推断，互补不互替。
- **三册三角** — Three-Book Triangle：#223 谈资 / #226 框架 / #224 工单。
- **档⓪书目** — Tier-Zero Bibliography：存在性可证、内容面不可达的取证分级。

## 最新演进与工业实践

- **品类主流化（2022–2026）**：数据可观测性从创业公司营销词进入分析平台词典；Gartner 系规划指南类文章在中文技术社区转引（⚠️ 未取一手报告）。
- **与 LLM 的双向交汇**：观测信号成为上下文喂给生成式助手做「自然语言排障」；同时 LLM 应用催生出「LLM 可观测性」新品类，与本书谱系平行不混同。
- **开源工程基线**：OpenLineage 等开放血缘标准、dbt 测试生态使信号采集层门槛大幅下降；商业平台竞争重心移到推断与协作层（⚠️ 工具版图见 05 章）。
- **工业实践口径**：数据产品 SLA/SLO 化是数据网格谱系的配套件——实链 [../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md)。
