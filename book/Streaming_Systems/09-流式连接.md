# 第 9 章 流式连接（Streaming Joins）

> 对应原书 Part II 第 9 章（英文原题 *Streaming Joins*；中译「流式连接」）。
> 小节目录 ✅ oreilly.com.cn 实抓：9.1 所有连接都是流式连接 / 9.2 非开窗连接 / 9.3 开窗连接 / 9.4 小结。
> 本文件为精读重构。章题倒装即宣言：**不是"流怎么做 join"，而是"join 本来就是流的特例"**。

## 章定位与中心论题

把第 6 章对偶性用到连接上：批 join = 两个 changelog 前缀的折叠乘积；
流 join = 持续维护同一乘积。全部差异收敛为一个问题：**两边状态各记多久、
按什么时间对齐**。本章由此把"连接"从 SQL 语法降维成一组第 2~4 章参数的组合，
并与第 7 章（状态成本）、第 8 章（语法表达）双线咬合。

## 逐节精读重构

### 9.1 所有连接都是流式连接

- 归约论证（重构表述）：INNER JOIN 对带符号输入 = 对每侧 changelog 做"增量物化维护"——
  新到 +I 与对面当前表求积，新到 -D 需回撤旧积。**批 join 只是"输入恰好终止"的流 join**。
- 推论一：**连接语义由输入种类决定**（append-only × append-only，changelog × changelog，
  表 × 流……），不同组合正确性规则不同——SQL 语法把它们藏进了引擎实现 ⚠️（Flink 对
  append-only×append-only 之外组合的撤回要求，转述自其文档，见姊妹书 13 补编）。
- 推论二：outer join 在流上比 inner 难得多——"找不到对家"这件事**永远不能被证明**，
  只能靠水位线近似宣布；没有水位线的 outer join 输出是投机性的（第 3 章复用）。

### 9.2 非开窗连接

- 全量状态连接：两侧（或一侧）记忆无期限 → 语义上就是"对动态表求 join"，
  结果完备性随水位线推进逐步收敛。三种经济形态：
  1. **双流 join**：双边都要全记忆，状态最大，慎用；
  2. **维表/流表 join**：一侧是有界表（配置、元数据），另一侧是流——
     状态只记小表（或外置查询），工业占比最高 ⚠️（"lookup join"词源见 9.3 演进节）;
  3. **时态（版本化表）join**：`FOR SYSTEM_TIME AS OF`——表带版本轴，
     流按事件时间取"当时的那版表"（第 8 章时态语法在此兑现；⚠️ 转述）。
- 删除的传染：changelog 侧一行被删，所有由它产出的连接结果必须回撤——
  回撤链深度 = 下游对状态的依赖深度（与 5.4 的重放等价、7.3 的状态 TTL 直接冲突，
  **本章是"想省状态就先改语义"说教最密集的地方**）。

### 9.3 开窗连接

- 给两侧记忆加期限即开窗 join，四种家族（按 Where 的选择划分）：
  1. **同窗连接（window join）**：双流各自按相同窗（滚动/滑动）切分，窗内互连，
     窗关即清状态——状态有界、迟到可容（第 3~4 章全套适用）；
  2. **会话合并连接**：join 本身参与定义会话（如"同会话内的点击×订单"），
     窗合并 → pane 身份漂移 → 第 5 章去重键变难（4.2 伏笔回收）；
  3. **区间连接（interval join）**：等值键 + `|t1−t2| < Δ` 的滑动相关，
     状态按 Δ 滚动释放；
  4. **迟到重发**：开窗 join 的修正同样走 firing panes（第 2 章三模式）。
- ⚠️ 转述：原书以球赛/运动数据类例贯穿本章（play-by-play 与比分表的开窗连接），
  演示"同一查询在窗内完备、跨窗不可完备"的边界；示例细节不作为引用依据。

### 9.4 小结

join 没有新数学，只有新记账：**每一格状态都是你为'将来可能匹配'买的保险**。
选错期限 → 结果错（太短）或成本爆（太长），与水位线定参（3.4）同构。

## 🔧 概念演示：开窗连接与"表版本轴"（DuckDB，非真流引擎）

点击流 join 会话表、每点击只在"会话开始后 30 分钟内"匹配（等值键 + 区间谓词 = 9.2/9.3 的混合）：

```sql
with sessions(k, sid, begin) as (values
 ('u1',1,timestamptz '2024-01-01 10:00'),('u1',2,timestamptz '2024-01-01 12:30')),
clicks(k, cid, ts, item) as (values
 ('u1',11,timestamptz '2024-01-01 10:02','book'),
 ('u1',12,timestamptz '2024-01-01 10:40','lamp'),
 ('u1',13,timestamptz '2024-01-01 12:31','pen'))
select sid, cid, item
from sessions s join clicks c using (k)
where c.ts >= s.begin and c.ts < s.begin + interval '30' minute
order by sid, cid;
```

🔧 实测：`sid=1↔cid=11(book)`、`sid=2↔cid=13(pen)`；`cid=12` 落在两窗之间被正确排除。
批语义下 `where ts ∈ [begin, begin+Δ)` 就是 interval join 的全部；流式实现需要的
"按 Δ 释放状态、按水位线宣布窗关"在 SQL 中不可见——**语法无损、记账有价**（9.4 的批式显影）。
时态版本轴同理可模拟（把 sessions 换成带 `valid_from/valid_to` 的版本表做区间条件），
读者可自行改写（🔧 方法说明：仅演示语义，不演示引擎）。

## 核心概念速览（中英对照）

- **流式连接** — streaming join：对 changelog 的增量物化维护
- **回撤传染** — retraction propagation：输入删除必须传导至派生输出
- **同窗连接** — window join：两流按相同窗切分后窗内互连
- **区间连接** — interval join：等值键 + 时间差 ≤ Δ，状态随 Δ 滚动释放
- **维表连接** — lookup/stream-table join：一侧为有界表的工业主形态
- **时态表连接** — temporal join：按事件时间取"当时版本"的表侧记忆
- **版本轴** — versioned table：表 + 有效期 = 被折叠的时间
- **outer 不可判定** — unprovable absence："没匹配"只能由水位线近似宣布
- **pane 漂移** — identity drift：会话合并致连接结果身份不稳定（5.4 难点）
- **状态=保险** — state as insurance：记忆期限与错算/成本的守恒交换
