## 章定位与中心论题

**流表相对性（stream-table duality）**：任何表都可以看作产生它的变更流（changelog），
任何流都可以在任意时刻凝固成表（快照）。批处理偏爱表、流处理偏爱流，
但二者只是同一数据的**两种取向（orientation）**——正如狭义相对性中"同时性取决于观察者"，
"这是流还是表"取决于你从时间轴的哪一点观察。Part I 的四问框架在此获得第二坐标轴，
数据世界从一维（有界/无界）升维为二维（**有界性 × 取向**）。

## 逐节精读重构

### 6.1 特殊理论：流表相对性的基础

- 定义两原语：
  **to-stream（表→流）**：表的变更流 = 快照序列的差分（c(t2) − c(t1)），元素带 +插入/−删除符号；
  **to-table（流→表）**：流在时刻 t 的表 = 截至 t 已到达元素构成的集合/包（含窗口化折叠）。
- changelog 表示：一行数据的演化 = 一串带符号记录（+I、-U/+U、-D）；
  **无符号（append-only）流只能表达"插入"世界**，关系数据的全部更新语义需要带符号流。
- "特殊理论"限于：**变更流 ↔ 当前表** 这一对；处理时间视角下成立（快照有明确"现在"）。

### 6.2 批处理与流和表

- 批处理 = 把流凝固成表再操作：MapReduce/SQL 批的输入输出都是表；
  第 2 章"全局窗"在这里显形为"**对完整 changelog 前缀的一次快照**"。
- 批的世界观缺陷重述：它看不见"表如何变成现在这样"（丢失中间态），
  也回答不了"此刻世界什么样"（等全量）——分别交给流的世界（6.1）与第 8 章 SQL。

### 6.3 流和表世界的 What/Where/When/How

- 在表上重述四问：What = 主键；Where = 表版本/快照（或按分区/窗折叠）；
  When = 提交/物化时点；How = 合并策略（upsert/append/版本追加）。
- 结论（重构表述）：**批流统一不是新框架发明，而是认识到四问在两种取向下同构**；
  "流上的窗口聚合 = 表快照的增量维护 = 物化视图"三者是同一对象的三种画法。

### 6.4 通用理论：流表相对性的推广

- 升维图（本章招牌，⚠️ 画法转述）：横轴"数据取向（行流 ←→ 列表）"、
  纵轴"有界性（有界 ↑ 无界）"，**四象限 = {批 SQL、流式、微批、交互查询} 的语义家园**；
  有界+表 = 经典 SQL；无界+流 = 流处理；沿对角线移动 = 换存储或换假设。
- "通用"还指：**任意数据集都可沿两个方向自由转换**，因此算子应声明"我工作在流上还是表上"，
  翻译责任交给引擎（这正是后来 Flink 动态表、湖仓 changelog 的模型先声）。

### 6.5 小结

流表二元对偶 = 本书给"批流之争"的终结答案：**没有批流之争，只有取向选择**。

## 🔧 概念演示：changelog ⇄ 快照表（DuckDB，非真流引擎）

带符号变更流（+I/+U/-U/-D 折叠为带符号增量），任意时刻 t 的表 = 前缀增量之和；
反过来，两张快照之差即一条可派生的"变更流"：

```sql
with changelog(op, ts, k, v) as (values
 ('+I',1,'a',10),('+I',2,'b',20),('-U',3,'a',10),('+U',3,'a',15),
 ('+I',5,'c',30),('-D',6,'b',20)),
delta as (select ts, k, case when op in ('+I','+U') then v else -v end d from changelog),
snap as (select 4 as t, k, sum(d) as v from delta where ts<=4 group by k
         union all select 6, k, sum(d) from delta where ts<=6 group by k)
select * from snap order by t, k;
```

🔧 实测输出：

```text
t=4: a=15, b=20          （a 的 -U/+U 在 ts=3 完成一次"改值不改行"的折叠）
t=6: a=15, b=0, c=30     （b 被 -D 删除后"和为 0"）
```

解读：① `b=0` 而非消失，暴露了**代数折叠对删除的粗糙表达**——真实流表系统需要
带"行数符号"的第二分量（或 -D 物化墓碑），这正是 6.1 强调带符号流的工程理由（🔧 演示结论）；
② 从 t=4 快照到 t=6 快照做差，即得一条新的等价 changelog——**两向转换无损**，对偶性成立。

## 核心概念速览（中英对照）

- **流表相对性** — stream-table duality：流与表可无损互转的对偶原理
- **特殊理论** — special theory：变更流 ↔ 当前表（处理时间快照）
- **通用理论** — general theory：有界性 × 取向的二维升维
- **变更流** — changelog：带 +I/-U/+U/-D 符号的记录流
- **带符号流** — retract stream：能表达删除/修正的流（append-only 之不足）
- **快照** — snapshot：流在时刻 t 凝固成的表
- **差分** — diff：两快照之差 = 一段等价 changelog
- **折叠/合并** — compaction：changelog 前缀 → 表状态的聚合过程
- **动态表** — dynamic table：流表统一的操作对象形态（Flink 术语同源于此思想）
- **物化视图** — materialized view：流上窗口聚合 = 表的增量维护
- **四象限** — boundedness × orientation：批 SQL/流式/微批/交互查询的语义地图
