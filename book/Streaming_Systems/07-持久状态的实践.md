# 第 7 章 持久状态的实践（Practicalities of Persistent State）

> 对应原书 Part II 第 7 章（英文原题 *Practicalities of Persistent State*；中译「持久状态的实践」）。
> 小节目录 ✅ oreilly.com.cn 实抓：7.1 动机 / 7.2 隐式状态 / 7.3 通用状态 / 7.4 小结。
> 本文件为精读重构。前六章回答"算什么、何时算对"，本章回答"**状态放哪、谁维护、崩了怎么办**"。

## 章定位与中心论题

流处理的一切高级语义（水位线、pane、触发、去重）都建立在**跨元素的记忆**之上。
本章用贯穿的"动物园刷卡计数"教学例（⚠️ 细节转述：闸机 turnstile 数据流的访客计数与报表，
原书以它演示从隐式状态到通用状态的演进）论证两级台阶：
**隐式状态**（框架替你记，容量与访问模式受限）→ **通用状态**（你显式声明并管理，获得全部自由），
并给出"持久"二字在流系统里的真实成本：状态后端、检查点、重放三选二的工程权衡。

## 逐节精读重构

### 7.1 动机

- 为什么需要状态：迟到数据的修正窗口、会话合并、去重簿记、第 5 章的 pane 幂等——
  全都要求"记住已经算到哪、算出过什么"。
- **状态必须持久且可恢复**：内存态在失败重放时会把"第 4 章的触发历史"弄丢，
  导致输出与不失败时不等价（重放等价，见 5.4）——本章对"持久"二字负责。
- 原书方法论（重构表述）：先问"**这段记忆能删吗、该多大、谁有权读**"，再选机制；
  绝大多数"状态爆炸"事故源于第一问问得太晚。

### 7.2 隐式状态

- GroupByKey/窗口聚合内部替你记的**缓冲袋（bag）**：元素按 (key, window) 暂存直到可触发。
  优点：零 API、语义安全；缺点：**只能整窗重放**、体积不可控、算完即弃无法跨窗复用。
- "重算代替状态"（reprocessing）的适用边界（本章重要论证）：
  源可重放 + 逻辑确定 + 成本可接受 ⇒ 可以不存状态（批处理天然如此）；
  三条任何一条不成立（无界源不可全重放！），隐式状态就撑不住。
- 动物园案例第一幕 ⚠️：只数"每分钟入园人数"用隐式状态足够；一旦要"跨天累计在场人数/游客画像"
  （需要**跨窗记忆**），必须进入 7.3。

### 7.3 通用状态

- 关键抽象：**每键状态（keyed state）+ 每键定时器（timer）**——
  在 ProcessFunction 级的低层算子里，开发者亲手读写 ValueState/ListState/合并型状态，
  并注册"事件时间到点回调"（⚠️ API 名词为 Flink/Beam 转述，本书只给模型）。
- 设计清单（精读重构为五条纪律）：
  1. 状态即窗口：**能由"窗"表达的记忆不要手写**（隐式优先）；
  2. 状态必带 TTL：无界流上的无界记忆 = 必然事故（会话状态清理是 4.2 的另一面）；
  3. 合并语义：跨窗修正要求状态存"可合并中间态"而非最终值（与 5.4 呼应）；
  4. 分区局部性：状态只属于该键——全局状态要么广播要么外部存储（引出第 9 章维表）；
  5. 容量规划：状态大小 × 访问延迟决定后端选型（内存/RocksDB 型 LSM/远程），
     细节主战场在姊妹书 [../Stream_Processing_with_Apache_Flink/07-有状态函数与状态管理.md](../Stream_Processing_with_Apache_Flink/07-有状态函数与状态管理.md)。
- 与第 5 章咬合：去重簿记本身就是通用状态的工业最大用户（"精确一次的税单"落在这里支付）。

### 7.4 小结

隐式状态给安全，通用状态给自由，**持久化给生存权**；
三者张力是流系统日常工程的全部，模型层（本书）只规定"你必须显式回答"。

## 状态反模式清单（精读重构：7.1–7.3 各条纪律的负面镜像）

| 反模式 | 症状 | 违反的纪律 |
| --- | --- | --- |
| 全局字典塞 keyed state | 每键重复存全量元数据，状态×键数爆炸 | 局部性（清单 4） |
| "先不设 TTL 以后再说" | 数月后 checkpoint 时长陡增、恢复超时 | TTL（清单 2） |
| 用状态存最终报表值 | 迟到修正无处合并，只能整值覆盖出错 | 可合并中间态（清单 3） |
| 把去重键做成随机数 | 重放时键漂移，第 5 章幂等全盘失效 | 重放等价（5.4 咬合） |
| 用外部 KV 逃避所有状态 | 网络往返进热路径，延迟/可用性双输 | 7.1"先问该不该记" |
| 会话状态永不清理空转键 | 冷键占位，窗口合并概率随状态集增大 | 定时器+水位线联动 |

## 🔧 概念演示：用"可合并中间态 + 迟到修正"重放 7.3 清单第 3 条（DuckDB，非真流引擎）

不存最终值、只存可合并中间态（count/sum），任何迟到修正只需并入再投影，
演示"状态换一种存法，迟到就不再可怕"：

```sql
with mid(k, pane, cnt, tot) as (values ('a',1,2,30),('a',2,1,15)),        -- 正常 pane
     late(k, pane, dcnt, dtot) as (values ('a',1,1,10)),                   -- 迟到修正(+1人/+10秒)
     state as (select k, pane, sum(cnt) cnt, sum(tot) tot
               from (select k,pane,cnt,tot from mid
                     union all select k,pane,dcnt,dtot from late) group by k,pane)
select k, sum(cnt) as visitors, sum(tot)/nullif(sum(cnt),0) as avg_sec,
       count(distinct pane) as panes_held
from state group by k;
```

🔧 实测：`k=a | visitors=4 | avg_sec=13.75 | panes_held=2`——
修正以"并入中间态"而非"重算全窗"生效；`panes_held` 一列即"记忆体积"的最小监视器
（纪律 2/3 的度量原型）。批引擎里没有定时器与状态后端，**此演示只证"可合并状态吸收迟到"这一代数性质**，
不证任何引擎的 checkpoint 行为（🔧 限定声明）。

## 核心概念速览（中英对照）

- **隐式状态** — implicit state：框架在 group-by-window 内自动维护的缓冲袋
- **通用状态** — general/keyed state：用户显式声明、按键隔离的持久记忆
- **定时器** — timer：事件/处理时间到点回调，触发逻辑的执行机构
- **重放代替状态** — reprocessing：源可重放时以重算换记忆，三前提缺一不可
- **状态 TTL** — state expiration：无界流上记忆的强制退役期限
- **可合并中间态** — mergeable intermediate state：以代数结构换迟到吸收力
- **状态后端** — state backend：内存/LSM/远程的存取实现层（⚠️ 运行时细节）
- **检查点** — checkpoint：状态+进度的一致性快照（Flink 路线，见姊妹书 12 补编）
- **局部性纪律** — key-locality：跨键记忆须广播或外置
- **动物园闸机** — turnstile/zoo example：本章贯穿教学例（⚠️ 转述）
- **重放等价的状态观** — replay-equivalence for state：失败恢复正确性的判据
