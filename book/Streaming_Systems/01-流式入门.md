# 第 1 章 流式入门（Streaming 101）

> 对应原书 Part I 第 1 章（英文原题 *Streaming 101*；中译章名「流式入门」）。
> 目录取证：✅ O'Reilly 中文网书页实抓小节（1.1 术语：什么是流式 / 1.2 数据处理模式 / 1.3 小结）；

## 章定位与中心论题

这是全书的"词汇表章"：把「流式（streaming）」从一个引擎特性还原为一种**数据处理模式**，
并埋下全书四问（What/Where/When/How，第 2 章展开）的种子。作者由官方博客系列
《The World Beyond Batch: Streaming 101》《Streaming 102》（O'Reilly Radar，URL 见本章末；403 不作内容依据）
扩写本章，核心句式有三：

1. **批与流是同一件事的两种模式**：批处理是"有界数据集上的流处理"的特例——这个视角是全书的立足点；
2. **流式≠低延迟**：流式的本质是**对无界数据的持续处理**，低延迟只是常见副产品；
3. **语言先行**：在谈任何引擎之前，先约定无界/有界、新鲜度/完备性、pipeline 等术语，
   后面所有引擎的文档都能翻译回这门语言。

## 逐节精读重构

### 1.1 术语：什么是流式

- **数据集按"有没有终点"二分**：无界（unbounded，理论上永不到来终点）/有界（bounded，能说完"我说完了"）。
  无界数据的**唯一现实呈现方式就是流**：你只能看见已经到达的部分。
- **流处理 = 对无界数据的持续处理**；与之相对，"把无界数据攒成小段再批处理"是**微批（micro-batch）**，
  它是"模拟流式的批"，两者的差别在语义而非外观 ⚠️（Spark 微批/连续模式等运行时细节转述，
  参见 [../bigdata/02-Spark核心与RDD模型.md](../bigdata/02-Spark核心与RDD模型.md)）。
- **新鲜度（freshness）与完备性（completeness）是独立两轴**：
  批处理在"数据到齐后"才产出（完备但不新鲜）；朴素流式"来一条处理一条"（新鲜但不完备）。
  本书后面所有机制——事件时间、水位线、触发、累积模式——都是在**同时逼近这两轴**，
  这是全书最重要的一句预告。
- 处理 pipeline 三件套：**源（source）→ 变换（transform）→ 汇（sink）**；
  map/filter/group-by/distinct/join 等术语沿用关系/函数式语义，不重新发明。
- 作者提醒：**"流式"不是新事物**——电话交换机、实时风控、在线系统早已在流式；
  大数据圈把"批"当默认、把"流"当补丁，只是 Hadoop 时代的历史偶然。

### 1.2 数据处理模式

- 按"数据有界/无界 × 处理是持续/一次性"可以排出一个 2×2：
  **批（bounded+batch）、微批（unbounded 切段+batch）、连续流（unbounded+continuous）**；
  同一份逻辑应当能跨模式复用——这正是后来 Apache Beam"一个模型多种运行时"的口号的语义版 ⚠️（转述）。
- 选择模式的判据不是技术站队，而是三问（⚠️ 重构表述）：结果要**多新鲜**？要**多完备**？
  为完备性多等 X 分钟的**代价**谁付？——第 2 章会把它形式化成 What/Where/When/How。
- 常见误区清单（精读重构，逐条对应社区常见混淆）：
  1. 把流式当"低延迟专用件"——忽略其"表达无界数据"的本体意义；
  2. 把 at-least-once/exactly-once 当引擎私有属性——其实它是第 5 章那样可分解的语义承诺；
  3. 认为"事件时间 = 加个时间戳列"——没有水位线配合的事件时间是半成品（第 3 章）；
  4. 用处理时间偷渡正确性——测试环境一切正常，生产乱序全崩（第 4 章 4.1）。

### 1.3 小结

本章交付一门"方言"：**有界/无界、新鲜/完备、source-transform-sink**。
带着这门方言，第 2 章把处理任务拆成四个正交问题；后面八章是四问的展开史。

## 🔧 概念演示：DuckDB 里"批是流的特例"意味着什么

DuckDB **不是真流引擎**（🔧 演示仅为概念模拟，临时脚本 `D:\develops\tmp\dbwave_ss\demos.py`）。
把 10 条事件按到达顺序灌入，用"运行到第 N 条为止的前缀聚合"模拟"流式边到边输出"，
与"全量批聚合"对照，可以精确复现新鲜度/完备性权衡：

```sql
with events(i, k, v) as (values (1,'a',10),(2,'b',7),(3,'a',5),(4,'b',3),(5,'a',-10)),
running as (select i, k, v, sum(v) over (partition by k order by i) as partial from events),
batch as (select k, sum(v) as batch_result from events group by k)
select i as seen_rows, k, v, partial as stream_partial, batch_result
from running join batch using (k) order by k, i;
```

🔧 实测输出（DuckDB 1.5.5）：

```text
seen_rows  k   v  stream_partial  batch_result
1          a  10            10.0           5.0
3          a   5            15.0           5.0
5          a -10             5.0           5.0
2          b   7             7.0          10.0
4          b   3            10.0          10.0
```

要点：对每个前缀（seen_rows），"流式部分结果"与"批终值"之差就是**新鲜但不完备**的量化形态
（如 a 在 seen=1 时报 10，终值却是 5）；前缀推满后两列收敛——**批 = 水位线推到 +∞ 的流**。
这一句是第 2、3 章的伏笔。

## 核心概念速览（中英对照）

- **流处理** — stream processing：对无界数据的持续处理；批是其有界特例
- **无界/有界数据集** — unbounded/bounded dataset：是否存在"说完"的时刻
- **微批** — micro-batch：把无界流切段后用批处理模拟流式
- **新鲜度** — freshness：结果距"反映当前"有多远
- **完备性** — completeness：结果距"包含所有该含数据"有多远
- **管道** — pipeline：source → transform → sink 的处理拓扑
- **事件时间/处理时间** — event time / processing time：数据自带时间 vs 机器时钟（第 3 章展开）
- **乱序** — out-of-order arrival：到达顺序 ≠ 事件时间顺序，无界数据的固有属性
- **数据驱动分析** — data-driven analysis：一切触发以数据（含隐式"数据到齐"信号）为条件，而非墙钟
- **模式选择三问** — freshness/completeness/cost：多新鲜、多完备、等待的代价
- **引擎无关模型** — engine-agnostic model：先有模型语言，后有引擎翻译（Beam 的立身之本）
