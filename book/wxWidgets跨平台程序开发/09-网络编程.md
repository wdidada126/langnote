# 第10章 wxWidgets 网络编程 —— wxSocket 的薄封装与它的 2026 替代版图

> **本章 2012 口径 → 2026 现状**：2012 年讲 2.8 的 wxSocketBase/Client/Server 与 wxURL/wxHTTP（BSD 套接字的 OOP 壳 + 内置 HTTP/FTP 客户端雏形）；2026 年 **wxSocket 处于"能用但基本无人推荐新增使用"的维护态**（官方长期建议 Boost.Asio 等替代，转述 ⚠️），wxHTTP/wxURL 老实现更早已淡出，而"访问因特网"（10.4）在 wx 内部的现代答案变成了 wxWebView。本章是"薄抽象在快速演进协议栈上失效"的第二例证（第一例见 [07](07-多媒体与打印.md)）。

### 事件驱动 socket 骨架（10.3.1 的机制重述；阅读性示例，未实测 ⚠️）

```cpp
// 监听: owner 窗口模式 —— socket 把网络就绪翻译成 GUI 事件, 与按键同泵排队
wxSocketBase* sock = listener->Accept(false);
sock->SetOwner(frame, wxID_ANY);            // 此后数据到达 => wxEVT_SOCKET
frame->Bind(wxEVT_SOCKET, &MyFrame::OnNet, this);
void MyFrame::OnNet(wxSocketEvent& ev) {
    switch (ev.GetSocketEvent()) {
      case wxSOCKET_INPUT:  sock->Read(buf, sizeof buf); render(buf); break;
      case wxSOCKET_OUTPUT: sock->Discard(); break;         // 写完成
      case wxSOCKET_CONNECTION: handshake(); break;
    }
}
// 2026 同构翻译: asio::post(ioc, handler) + UI 侧 CallAfter/timer 抽干
//   —— "网络事件泵"与"UI 事件泵"两个队列在 owner 模式下合一, 这正是本章精髓
```

### 2012→2026 协议栈差异预算（读 10.2/10.4 时挂的"过时税"清单）

| 主题 | 2012 书中默认 | 2026 现实 | 迁移动作 |
|---|---|---|---|
| 传输 | 明文 TCP | TLS 默认、证书钉扎可选 | 交给 OpenSSL/SChannel 层 |
| HTTP | 1.1, GET 轮询 | 2/3、长连接、SSE/WebSocket | 换 Beast/ixwebsocket 等 |
| IP | v4 单栈 | 双栈必备 | 地址抽象升级 |
| 身份 | 密码+服务器 | OAuth2/OIDC+系统浏览器 | 走 wxWebView/系统浏览器 |
| 更新 | exe 下载替换 | 包管理/差量/代码签名 | Authenticode/公证成硬门槛 |

## 一、动机：GUI 程序为什么要自己碰 TCP

2012 的桌面软件：自动更新、许可证服务器、内网设备通信（串口/以太网工控）、简单 P2P。当时"引一个网络库"在 Windows 上意味着再背一个 DLL 或和 Winsock 裸 API 肉搏，而 **wx 已经自带了**（wxNet 库：wxSocket+协议客户端），零新增依赖是决定性卖点。这个"顺带就有"正是本章存在的人类学原因——2026 年依赖管理（vcpkg/Conan）抹平了成本，卖点对消失，wxSocket 的技术短板随即裸露。

## 二、机制（10.1–10.3）

- **客户端-服务器模型（10.1）**与**套接字基础（10.2）**：`wxSocketBase`≈一个 BSD socket 的对象化（`Connect/Accept/Read/Write`，地址用 `wxSockAddress/wxIPaddress`——`sockaddr_in` 的壳），流/数据报（10.2.1 接口/10.2.3 地址）。所有 2012 年的 POSIX/Winsock 差异（初始化 `wxSocketManager::Init`、`closesocket vs close`、`SOCKET` 是 UINT 还是 int）都封装在这里。2026 提醒：**IPv6 支持在老 wxSocket 上残缺**（`wxIPaddress` 只有 v4 形状；3.x 有 `wxIPaddress` 扩展但 sockaddr 抽象未彻底现代化——转述 ⚠️），双栈网络环境是老代码的隐形债。
- **两种驱动模式（10.3）**——本章概念上最有生命力的部分：
  1. **阻塞式 + 工作线程（10.3.2）**：循环 Read，UI 更新靠第 8 章的投递（2012：wxPostEvent；2026：CallAfter）。
  2. **非阻塞 + 事件驱动（10.3.1）**：`SetOwner(window)` 后 socket 把 `wxEVT_SOCKET` 打进 GUI 事件循环——**这就是"把网络 fd 并入 UI 事件泵"**，与 libevent/muduo 的 reactor 同构（对 GUI 程序这是唯一不卡界面的正解；书中两处示例正好对照）。
- **10.4 访问因特网**：wxURL/wxFTP/wxTextWrapper 简易 HTTP 客户端（2.8 wxNet 的一部分）——HTTPS 时代（证书链、SNI、TLS1.3）这些手写客户端全部作废（转述：wxNet 老协议客户端在 3.x 中边缘化/移除 ⚠️）。

## 三、权衡与相邻概念对比：2026 桌面联网选型表

| 层 | wx 2012 | 2026 推荐 | 理由 |
|---|---|---|---|
| 裸传输 | wxSocket | **Boost.Asio**（独立 Asio） | 异步模型、TLS(OpenSSL)、标准执行器 |
| HTTP | wxURL | **cpp-httplib / cpr(libcurl) / Beast** | TLS、连接池、代理、HTTP/2 |
| WebSocket | 无 | Beast / libwebsockets / ixwebsocket | 实时更新、云端 API 常需 |
| 浏览器呈现 | 无 | **wxWebView(Chromium 后端，3.3 实测在载)** | OAuth/支付等复杂交互外包 |
| 串口/工控 | 书中未讲 | libserialport / asio serial | wxSerialConfig 系也存在 |

与服务器端的分野：[C++服务器开发精髓·网络编程](../C++服务器开发精髓/04-网络编程重难点.md) 的世界是"一台机几万个连接"（epoll/io_uring/reactor），GUI 客户端的世界是"几十个连接 + 必须与 UI 事件泵共生"。同一套 BSD API 两种工程学；读本章时记住**客户端网络代码的第一约束是"永远不阻塞 UI 线程"**，第二才是协议。

### 线程模式骨架（10.3.2 的 2026 等价：阻塞 I/O 搬出 UI 线程）

```cpp
// worker 线程持裸 socket 阻塞读写, 结果经 CallAfter 回 UI —— 两章机制的合体
std::thread t([win = wxWeakRef<wxWindow>(&frame), req]{
    auto resp = blocking_http(req);                    // 可与第三方库同线程栈
    if (auto* f = win.get()) f->CallAfter(&Frame::OnResult, resp);
});                                    // 2026: jthread/受管线程, detach 是本章坏味道
t.join();                              // 退出协议: 关 socket 唤醒阻塞 Read 再 join
// 判据: 连接数少且吞吐低 => 线程模式简单可靠;
//       长连接/推送风暴 => 回事件模式或 Asio, 别给"每连接一线程"找借口(链服务器篇)
```

**客户端网络自检三问**：会阻塞 UI 吗（三秒白窗定律）？断线重连有指数退避吗？证书错误是"默认拒绝+人话解释"吗？——2012 书的示例三问全不及格，恰是 2026 教程的正文。

## 核心概念速览（中英对照）

- **套接字封装** — wxSocketBase：BSD socket 的面向对象壳
- **所有者窗口模式** — SetOwner/event-driven socket：就绪即发 wxEVT_SOCKET 进 UI 循环
- **反应堆同构** — reactor equivalence：socket 事件并入 GUI 消息泵
- **wxSocketManager** — 全局初始化/清理（Winsock WSAStartup 的藏处）
- **阻塞+线程模式** — blocking socket in worker thread：更新经 CallAfter 投递
- **地址抽象** — wxIPaddress：IPv4 时代的 sockaddr 壳（IPv6 残缺 ⚠️）
- **wxURL/wxHTTP** — 内置简易 HTTP 客户端：TLS 时代作废的封装
- **双栈** — dual-stack IPv4/IPv6：老代码隐形债
- **TLS 外包** — offload TLS to OpenSSL/curl：客户端联网的事实标准
- **Beast/Asio** — Boost 网络栈：2026 wx 应用的常见外配搭档
- **wxWebView** — 嵌入式浏览器：wx 生态内"访问因特网"的现代答案

## 最新演进与工业实践

- **wxSocket 现状**：类系仍在 3.2/3.3 编译目标中（存在性），但官方文档对 wxNet 的"维护态"定性为社区长期共识（转述 ⚠️，本次未逐页抓取）；GitHub 上 wxSocket 相关 issue 的低优先级处理节奏与"建议改用 Asio"的回复模式是维护态旁证（口径转述 ⚠️，未逐条取证）。
- **std::execution 与网络**：P2300（实测 302，C++26）定型的 senders/receivers 是"异步网络→UI 回调"链条的语言化终点——`then/post/schedule_on` 组合恰好覆盖 10.3 两种模式的表达需求（2026 视角：本章的 if-else 手写状态机可整体升级为任务流水线）。
- **协议栈演进清单（2012→2026 的差异即本章的"过时预算"）**：HTTP/1.1→HTTP/2/3(QUIC)、裸 TCP→TLS 默认、IPv4→双栈、下载轮询→WebSocket/SSE。任何"照书中 wxSocket 写更新器"的 2026 教程代码都无法过企业网络/证书审查——用本节表格替换书中示例。
- **工业组合**：KiCad/Audacity 等 wx 大户的联网部分（更新检查、插件仓库）都走"专用 HTTP 库或系统 API"而非 wxSocket——wx 只当壳（对其公开 issue/代码的常识性转述 ⚠️ 未逐文件核）。

## 本章小结

1. wxSocket 的历史意义="零新增依赖"；该理由消亡后其抽象短板（阻塞模型笨重、IPv6/TLS 残缺）裸露。
2. 10.3"socket 事件进 UI 泵"的模式永不过时——2026 用 Asio+CallAfter 或 std::execution 重演。
3. 10.4 的现实替代：wxWebView（协议交互外包）+ 专业 HTTP 客户端库（数据交互）。
