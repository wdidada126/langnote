# 第7+8章合并 多媒体与打印 —— 两章"技术考古 + 管道残存"的合并读法

> **本章 2012 口径 → 2026 现状**：原书第 7 章（多媒体：wxMediaPlayer/wxSound/wxMediaCtrl）与第 8 章（打印：wxPrinterDC/打印框架/CUPS）在 2026 年命运分岔——**多媒体抽象层几乎全线枯死**（后端 QuickTime/DirectShow/GStreamer-0.10 全部退役，wxMediaCtrl 名存实亡，转述 ⚠️），**打印管道则活着且被 3.x 重构过**（原生打印对话框、DPI 正确的后台绘制）。两章合为一个文件：都是"OS 多媒体/文档输出服务的最薄封装"，也都面临"被 Web/专用引擎取代"的同一结局，合并读省时间且不损失任何机制。

### 打印骨架两代（阅读性示例，GUI 未实测 ⚠️）

```cpp
// 8.2.1 "实现打印框架"的 2012 形状：分页回调协议
class MyPrintout : public wxPrintout {
    bool OnPrintPage(int page) override {
        wxDC& dc = *GetDC();               // 屏幕预览时是屏 DC，打印时是打印机 DC
        dc.SetMapMode(MM_TEXT);
        DrawPageContent(dc, page);         // 同一函数画屏/画纸 —— 抽象的全部红利
        return true;
    }
    bool GetPageInfo(int* min, int* max, int* cur, int* tot) override { /* 页号协议 */ }
};
wxPrintDialogData dd; MyPrintout po("doc");
wxPrintDialog dlg(&frame, &dd);
if (dlg.ShowModal() == wxID_OK) dlg.Print(&frame, &po);   // 8.2.2 应用
// 2026 增量: GetDC 前按 printerDC.GetPPI/GetLogicalScale 校 DPI;
//            "打文件"优先走 PDF: 目标选 Microsoft Print to PDF / CUPS PDF / pdfium 预览
```

## 一、动机：框架该不该管"放电影"和"出纸"

wx 的答案是"管，但只薄管"。第 7 章的接口（7.1 多媒体编程接口）本质是把 Windows MME/DirectShow、SGI/其他 Unix 的音频服务各包一层；第 8 章则是把 GDI 打印 DC、PostScript/CUPS 输出各包一层。两个共同点：① **输出通道而非内容引擎**——解码、排版、光栅化全在外部；② 平台的废弃动作会直接打穿抽象层（QuickTime for Windows 2016 退役、XP 打印栈更替）。因此这两章是全库"2012→2026 落差"最刺眼的地方，处理方式也最考验诚实：**机制照学，API 名单全换**。

## 二、机制：多媒体（原书第7章）

- **7.2 音频**：`wxSound`（播放 WAV，一次性、非混音——2.8 的真实能力上限）；"音频抽象/播放音频文件/播放 CD"三节的 CD 部分已是纯考古（光驱消亡）。2026：wxSound 在 3.x 仍在（wxMSW 后端），但任何像样的声音需求走 miniaudio/SDL2_audio/RtAudio，或系统命令兜底（机制判断）。
- **7.3 视频 / 7.4 多媒体控件**：书讲 2.8 的 `wxMediaPlayer`（SGI 血统的抽象）——**3.0 起已删除**（转述 ⚠️）；替代物 `wxMediaCtrl`（2.9.0 引入，后端 DirectShow/GStreamer/QuickTime 插件式）。到 3.x：QuickTime 后端随苹果退役、GStreamer 0.10 后端被 1.0  ABI 冲掉，wxMediaCtrl 只剩 DirectShow/WMF 级别支持且文档长期标注"experimental 倾向"（口径转述 ⚠️）。**2026 结论：wx 应用内放视频=嵌 WebView（<video>）或外挂 mpv/VLC 子进程**——第 6 章 wxWebView 演进在此合流。
- **多媒体控件（7.4.1）**：播放/暂停/进度条三件套 UI 手写即可，框架不值得再包。

## 三、机制：打印（原书第8章）

- **8.1 打印 DC 直绘**：`wxPrinterDC` 就是一个"以页为画布的 wxDC"，把第 6 章绘图指令重放到纸上；`wxPrinter` 弹进度框。机制在 3.x 完全保留——**这是第 6 章 DC 抽象的红利**：绘图代码平台无关，输出目标（屏/纸/PDF）只换 DC 具体类。
- **8.2 打印框架**：`wxPrintFramework` 系——书中指 `wxPrintout` + `wxPrintDialog` + `wxPageSetupDialog` + `wxPrintPreview` 组合：实现 `OnPrintPage/GetPageInfo` 分页回调，预览即"把打印 DC 换成屏幕 DC 重放"。3.x 仍活；`wxPrintPreview` 体验老旧但可用（转述 ⚠️）。
- **8.3 类 UNIX 打印**：2012 年讲 lp/lpr 管线与 PostScript 直写。2026：CUPS 仍是 Linux 打印中枢，但 PostScript 直写路径被 **PDF-first（CUPS 内部 pdftops/驱动转 Raster）**取代；wxMSW 侧"Microsoft Print to PDF"使打印通道天然通 PDF（系统级事实，具体到 wx 版本细节 ⚠️）。
- **跨页文本/富内容排版**书中交给 wxHtmlWindow::Printing（第 4/8 章交叉）；2026 的正解是排版外包：wxWebView + 浏览器打印、或 Qt 式 QTextDocument→PDF（wx 无等价物，缺口如实记）。

## 四、权衡与相邻概念对比

| 需求 | 2012 书答案 | 2026 推荐 |
|---|---|---|
| 播放音频 | wxSound/wxMediaPlayer | miniaudio/SDL/RtAudio/系统 API |
| 播放视频 | wxMediaPlayer→wxMediaCtrl | WebView `<video>` / 外挂机 mpv |
| 出纸 | wxPrinterDC 直绘 | 不变 + PDF 中间格式优先 |
| 富文档排版 | wxHtmlWindow 打印 | wxWebView 浏览器打印管线 |
| 预览 | wxPrintPreview | 同上，或自绘 PDF 查看（pdfium） |

共同哲学：**"薄抽象层"在输出服务领域的失效模式=后端生命周期比抽象层短**。对照第 9 章网络（wxSocket 同病）与 [C++API设计·版本控制与ABI](../C++API设计/09-版本控制与ABI.md)（"依赖平台私有 API 的封装层随平台漂移"论点）。

### 2026 版"本章练习"（对应书末习题的外包化重做；均为机制口径 ⚠️ 未实测）

1. 声音反馈：miniaudio 单头文件嵌入，异步回调线程里只碰原子量，UI 提示经 `CallAfter`（链 08 章）。
2. 视频欢迎页：`wxWebView::LoadURL("file:///…/intro.html")` + `<video autoplay>`，零媒体抽象债。
3. 报表输出：应用内部生成 PDF（排版库/服务端渲染），打印仅剩"交给系统打印队列"一步——`wxGetApp().Print` 或直接 `ShellExecuteEx`(Win)/`lp`(Unix)。
4. 打印机枚举：`wxPrinter::GetPrinters()` 仍在（3.x 存活件），用它而不要重新发明注册表/`lpstat` 解析。
5. 打印进度：长任务打印的进度对话框在 3.x 要放主线程事件驱动，绝不在 `OnPrintPage` 里睡（UI 线程规矩的打印版）。

## 核心概念速览（中英对照）

- **媒体播放器抽象** — wxMediaPlayer（已删）：2.8 的视频封装，SGI 起源
- **wxMediaCtrl** — 3.x 媒体控件：GStreamer/DirectShow 插件后端，趋于弃用
- **wxSound** — 轻量音频播放：WAV 直放，无混音无流式
- **打印设备上下文** — wxPrinterDC：以页为画布的可绘制表面
- **打印回调框架** — wxPrintout 协议：OnPrintPage/GetPageInfo 分页模型
- **打印预览** — print preview：同代码重放到屏幕 DC 的复用技巧
- **页面设置对话框** — wxPageSetupDialog：纸张/边距/方向的 OS 原生面板
- **CUPS** — Common UNIX Printing System：类 Unix 打印中枢
- **PDF-first 输出** — PDF as intermediate：现代打印管线的中间通货
- **WMF/DirectShow 后端** — legacy media backends：QuickTime/DShow 时代残骸
- **外挂播放器策略** — out-of-process media：mpv/VLC 子进程集成模式

## 最新演进与工业实践

- **wxMediaCtrl 的 3.3 近况**：仍在编译目标内但社区长期呼吁"要么修好要么正式弃用"（Issue 存在为常态，未逐条核 ⚠️）；本笔记口径：**新项目多媒体一律绕开 wx 抽象**。
- **打印的现代正确姿势**：应用先生成 PDF（排版引擎自选：libharu、pdfgen 类、浏览器打印），再把 PDF 交系统打印通道（Win 的 IPrintDialog/Windows.Data.Pdf、macOS CorePrint、Linux CUPS/`lp`）；wx 在 3.x 提供打印 DC/对话框但**不提供 PDF 生成**——缺口要么 wxWebView 打印、要么引第三方库（机制判断 ⚠️ 细节）。
- **音频后端 OS 侧大事记**：Windows XP 时代的 MME/DirectSound 仍兼容但延迟差，Windows 侧主流已转向 WASAPI 一系；macOS 自 10.14 起弃用 OpenAL、推荐 AVAudioEngine 路线——当年 wxSound 依赖的简单通路在苹果端已换轨，佐证"薄抽象失效"论（OS 事实为业界周知，未逐条核 URL ⚠️）。
- **工业残存场景**：Kiosk/工控上位机（wxWidgets 存量最大的行业之一）仍需"响铃+出小票"——这类 ESC/POS 出纸根本绕开 OS 打印栈直写串口/USB，第 8 章框架在此类场景=用不上（诚实的产业切片观察，未做样本核证 ⚠️）。

## 本章小结

1. 第 7 章按"API 已枯、模式尚存"读：音频视频外包，wx 只当窗口壳。
2. 第 8 章按"管道活着、姿势变了"读：DC 重放模型不变，上游加一层 PDF。
3. 两章共同的教训：薄抽象层的生死=其后端服务的生死，选型时先查后端未来十年。
4. 自查三题：为什么"预览=换个 DC 重放"能成立（wxDC 的输出侧多态）？OnPrintPage 里弹进度框为什么死锁（打印框已有模态循环）？wxMediaCtrl 换成外挂播放器后，进度同步怎么做（子进程 IPC 事件回推，链 [08](08-并发编程.md) 9.2 路）？
5. 关联件：DC 家族来自 [06](06-图像与绘图.md)；"框架弃层生态认领"定律第三例见 [10](10-数据库编程.md)。
6. 一句话版本：媒体区读成"尸检报告"，打印区读成"仍值班的管道工"——两章合读正好一遍"抽象层新陈代谢"教程。
