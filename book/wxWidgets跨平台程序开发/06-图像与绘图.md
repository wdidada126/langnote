# 第6章 图像与绘图 —— 位图家族、DC 分层与 wxGraphicsContext

> **本章 2012 口径 → 2026 现状**：2012 年以 2.8 的 wxBitmap/wxImage + wxPaintDC/wxMemoryDC 双轨自绘为主轴，wxGraphicsContext 刚转正；2026 年 3.x 的口径是**能用控件不自绘、能走 GraphicsContext 不碰裸 DC**，并且整章缺一个 2012 不存在的大前提：高 DPI 缩放下的位图倍率（@2x/@1.5x）管理。

## 一、动机：GUI 里"画东西"的两条世界线

一条是**位图世界**（6.1）：像素资产的加载、缩放、格式转换；一条是**绘图世界**（6.2）：在某个可绘制表面（DC）上即时出图。wx 把它们分成两套 API 是 Windows GDI 血统——`wxDC` 几乎就是 HDC 的薄壳。理解这条世界线分裂，才能理解为什么本章 6.2.4 的示例要"内存画一次、屏幕上贴一次"。

## 二、机制（6.1 图像）

- **wxBitmap（6.1.1）**：与**特定 DC 关联**的显示器格式位图，构造/绑定贵、绘制快——GDI 兼容性时代的"上传显存对象"。
- **wxImage（6.1.2）**：与设备无关的 RGB+Alpha 字节缓冲，PNG/JPEG/GIF/BMP/TIFF/PCX 装卸载（handler 插件式，`wxImage::AddHandler`），`Rescale` 是 2.8 唯一的缩放选项（质量一般，插值可选项极少——当年被骂的点）。
- **wxIcon/wxCursor（6.1.3/6.1.4）**：平台资产类型，Icon 多尺寸族、Cursor 热点概念。**跨平台陷阱**：.ico 只在 Windows 全功能，GTK 用 PNG+XPM，书中已提醒打包策略要双轨。
- **图像容器（6.1.5）**：wxImageList（工具栏/列表图标册）与 wxAnimatedIcon（3.x 新增，转述 ⚠️）。

## 三、机制（6.2 绘图）

- **wxColour/wxFont（6.2.1）**：颜色 sRGB 分量对；字体按"家族/点大小"抽象——**wx 字体单位是磅，2026 依旧**，但点→像素换算在 DPI 缩放下的行为 3.x 已按逻辑 DPI 修正（转述 ⚠️）。
- **wxPen/wxBrush（6.2.2)**：轮廓与填充的样式对象；2.8 的 GDI 对象生命周期（每选入 DC 未换出即泄漏）是当年句柄泄漏事故之王，3.x MSW 后端做了内部池化缓解（转述 ⚠️）。
- **wxDC 家族（6.2.3）**：PaintDC（响应 EVT_PAINT，BeginPaint 语义）/ClientDC（即时）/MemoryDC（离屏）/ScreenDC/PrinterDC（第 8 章）；`wxBufferedPaintDC`/`wxAutoBufferedPaintDC` **是 2.9/3.0 对"双缓冲全靠手写"的官方救赎**——书中 2.8 式手写 MemoryDC 双缓冲模板代码，2026 一律替换为这两类。
- **绘图应用（6.2.4）**：画笔路径、文字度量（GetTextExtent 与 DPI 纠葛）、区域裁剪 `wxRegion`/`wxGCDC`。
- **wxGraphicsContext**：3.0 起的现代路径——抗锯齿、alpha 合成、渐变，后端 GDI+/Cairo/Quartz；2.9 时代性能与可靠性尚被诟病，3.x 已是默认推荐（转述 ⚠️）。
- **三维图形（6.2.5）**：wx 本体**没有 3D 抽象**，书接的是 wxGLCanvas 上挂 OpenGL 固定管线（glBegin 时代）。2026 该节整体视为考古（见演进节）。

## 四、权衡：DC 分层的历史包袱与替代

自绘控件（wxControl 派生 + OnPaint）换来像素级自由，代价是三平台渲染差异（字体 hinting、抗锯齿、Clear 背景闪烁）。2026 的减痛次序：优先原生控件 → 组合控件 → wxGraphicsContext 自绘 → 裸 DC 仅在维护 2.x 代码时出现 → 复杂 2D 场景改嵌 wxWebView（Chromium 后端，3.3 实测 changes 有载）或上游戏栈。与第 4 章"能 sizer 不绝对坐标"同为一条哲学：**wx 的应用现代化=把命令式绘图换成声明式组件**。

### 双缓冲两代模板（阅读性示例，GUI 未实测 ⚠️）

```cpp
// 2012 书式（2.8）：手写离屏合成——每个自绘控件重复这段样板
void DrawPanel::OnPaint(wxPaintEvent&) {
    wxPaintDC dc(this);                    // 必须构造于 EVT_PAINT 处理内
    int w, h; dc.GetSize(&w, &h);
    wxBitmap buf(w, h);                    // 离屏位图
    { wxMemoryDC mdc(buf);
      mdc.SetBackground(*wxWHITE_BRUSH); mdc.Clear();
      DrawContent(mdc); }                  // 真正画到内存
    dc.DrawBitmap(buf, 0, 0);              // 一次贴屏 => 无闪烁
}

// 2026 式（3.x）：样板被框架吸收
void DrawPanel::OnPaint(wxPaintEvent&) {
    wxBufferedPaintDC dc(this);            // 双缓冲内置
    dc.SetBackground(wxBrush(GetBackgroundColour()));
    dc.Clear();                            // 框架负责"先清后画"时序
    DrawContent(dc);                       // 同一函数签名: 拿到的都是 wxDC&
}
// 要矢量质感(抗锯齿/alpha/渐变): wxGCDC dc(bufed) 或 wxGraphicsContext::New()
// 尺寸单位口径: 全部按"逻辑像素"给, 位图资产按 GetContentScaleFactor 备好倍率图
```

绘图三对象的义务清单（当年句柄泄漏之王，读 6.2.2 时贴在手边）：
- 循环里 `new wxPen` 每帧分配 → 提升为成员或用 `wxPenInfo` 缓存；
- `SelectObject` 进 DC 的 GDI 对象在 DC 析构前不得析构（2.8 崩溃名场面）；3.x 后端内部处理，习惯仍值得留；
- 自绘控件必须响应 `EVT_ERASE_BACKGROUND` 空实现或 `SetBackgroundStyle(wxBG_STYLE_PAINT)`（3.x 写法），否则双缓冲白闪。

### 图像加载一张卡（6.1 的 2026 操作模型；阅读性示例，未实测 ⚠️）

```cpp
// 资产->上屏的标准流水线(带 DPI 纪律):
wxImage img;
img.LoadFile("art/logo.png", wxBITMAP_TYPE_PNG);   // handler 插件式解码(6.1.2)
img.SetOption(wxIMAGE_OPTION_SCALE, ...);          // 3.x: 按内容倍率语义(转述 ⚠️)
wxBitmap bmp(img, scale);                           // 绑定 DC 属性的"上传"一步
// 图标多尺寸族: wxIconBundle 收 16/24/32/48/256, 平台各取所需(6.1.3)
// GIF 动图: wxImage 不解帧动画, 需第三方或 wxAnimationCtrl(3.x)——书中未提的缺口
// 安全提醒: 老版 libpng/libjpeg 是 CVE 常客, 发行版打包(vcpkg/系统包)而非自带源码树
```

**读法提示**：6.1.1/6.1.2 的分界在 2026 仍是理解一切性能问题的钥匙——`wxImage` 操作是 CPU 端随便来，`wxBitmap` 的创建/尺寸变更是"重资产"，缩放循环里 `wxBitmap(wxImage.Rescale(...))` 每帧一次就是当年卡顿主因（今天仍成立）。

## 核心概念速览（中英对照）

- **设备上下文** — device context (wxDC)：可绘制表面的统一句柄抽象
- **离屏绘制/双缓冲** — off-screen rendering / double buffering：MemoryDC 合成后一次贴屏
- **wxBufferedPaintDC** — built-in buffering：3.x 内置双缓冲绘图画布
- **显示器无关图像** — wxImage：CPU 端像素缓冲，可加载/缩放/存取
- **显示器相关位图** — wxBitmap：GPU/GDI 亲和的绘制资产
- **图像处理器插件** — image handler：按格式插拔的解码器注册机制
- **Alpha 合成** — alpha compositing：带透明通道的混合绘制
- **wxGraphicsContext** — 2D 矢量绘制抽象层：抗锯齿/渐变/变换矩阵
- **画笔与画刷** — wxPen / wxBrush：轮廓与填充样式对象
- **区域** — wxRegion：非矩形裁剪/命中掩码
- **wxGLCanvas** — OpenGL 画布：3D 唯一官方入口（搭配外部 GL 栈）
- **HiDPI 倍率图** — @2x assets / scale-aware bitmap：现代位图资产管理关键词（wx 3.1+ 的 FromBitmap/scale 因子，转述 ⚠️）

## 最新演进与工业实践

- **固定管线 OpenGL 已死**：6.2.5 的 glBegin/glEnd 教学在 GL 3.3+/core profile、Vulkan、Metal（macOS GL 自 10.14 起弃用——业界周知）三重判决下不可编译运行于现代驱动语境；2026 在 wx 里做 3D 的现实路径：wxGLCanvas + **glad/OpenGL 3.3 core**、或 **Vulkan 表面（wxGLCanvas 支持 GLX/WGL 属性直取 vulkan surface，转述 ⚠️）**、或直接换引擎（bgfx、filament、Qt Quick/RHI）。
- **图像 I/O 的第三方替代**：stb_image、lodepng、turbojpeg 已成小项目首选——wxImage 保留的价值是与 wxBitmap/wxColourData 的管道畅通；解码器安全（libjpeg-turbo/zlib 跟随发行版补丁）是 2026 新论点。
- **字体与文本排版**：wx 2D 文本度量仍是"逐行量字"模型；复杂文种（阿拉伯连字、CJK 换行）需要 Pango/HarfBuzz 级排版引擎，wx 不提供——这是它与 Qt（自带文本引擎）的真实差距（机制判断）。
- **HiDPI 工程化**：3.1+ 的缩放感知（wxBitmap::Scale 的 scaleFactor、wxGCDC 与 backing scale）+ macOS 主屏倍率——2012 书中零出现；2026 任何"截图/标尺/像素画"类功能在 2.8 口径下必错，重读本章时要主动给每个坐标加"逻辑像素"前缀（转述 ⚠️）。
- **工业对照**：Audacity 的波形画布（高频重绘+缩放）正是"MemoryDC 手写双缓冲 → 现代滚动窗口重构"的活案例（其 GitHub 演进史周知，细节未核 ⚠️）；游戏编辑器一类工具则多数已迁 Dear ImGui。

## 本章小结

1. 位图（资产）与 DC（即时绘图）两套 API 源自 GDI 时代，理解分裂才能选对工具。
2. 3.x 三件套替换 2.8 手写模板：wxBufferedPaintDC、wxGraphicsContext、缩放感知位图。
3. 6.2.5 三维图形一节按"2012 考古"处理；现代 3D 不在 wx 抽象层内解决。
4. 自查三题：EVT_PAINT 里为什么必须构造 wxPaintDC 而非 wxClientDC（BeginPaint 的验证语义）？wxImage→wxBitmap 何时做才不卡交互？字体度量在高 DPI 下哪一步换算？
5. 关联件：打印 DC 是本抽象的第二个输出靶（[07](07-多媒体与打印.md)）；位图资产与 [04](04-图形用户界面.md) 的控件绑定共用 DPI 纪律。
6. 一句话版本：wxDC 的"一个接口多个靶"设计是 2012 章节里最抗老的抽象，代价全在 DPI 时代补票。
