# 第11章 wxWidgets 数据库编程 —— ODBC 时代与 wxDatabase 的短命，SQLite 的长赢

### wxDatabase 死亡复盘（机制转述 ⚠️，API 名以书中口径为据）

```text
wxDBFactory::Create("ODBC")   → 工厂选驱动: 抽象层第一座山(方言)
wxDBConnection / wxDBRowSet   → 游标对象化: 每列一个 wxDBColumn, 性能与特性双输
SQLWCHAR ↔ wxString ↔ 各 DB 驱动字符集 → 抽象层第二座山(字符), 与第5章 wxString 史同题
3.0 整体移除: 维护成本 > 用户量 —— "框架内置 ORM"命题作废
```

### 2026 版"本章该写的代码"（阅读性示例；SQLite C API 纯 C++ 部分本机可测但无 sqlite  amalgamation 在案，未实测 ⚠️）

```cpp
sqlite3* db; sqlite3_open("app.db", &db);
sqlite3_exec(db, "BEGIN", 0,0,0);                    // 批量写必包事务: 差距千倍级
auto* st = prep("INSERT INTO t(name,score) VALUES(?,?)");
sqlite3_bind_text(st, 1, name.data(), -1, SQLITE_TRANSIENT);  // 参数化=注入防线
sqlite3_step(st);
sqlite3_exec(db, "COMMIT", 0,0,0);
// schema 版本化: PRAGMA user_version + 增量 ALTER 迁移脚本, 启动时校验升级
// 线程: 连接不跨线程共享 —— worker 各开连接, 结果 CallAfter 回 UI (链 08)
```

## 一、动机（11.1 数据库简介）：桌面软件为什么 2012 年集体"接入数据库"

书中用一章的十分之一篇幅讲发展史/主流数据库/ODBC——反映当年的行业情绪：Access/FoxPro 世代的桌面软件要升级成"有数据库的严肃应用"，路径有二：**直连（ODBC/JDBC 时代统一抽象梦）**或**内嵌（Firebird Embedded/SQLite 初兴）**。14 年后复盘：直连路线在桌面端基本输给"本地 SQLite 做缓存/主存 + 云 API 做同步"，统一抽象梦（JDBC/ODBC）活成企业集成边角料。

## 二、机制（11.2 数据库编程）：书中路线与它的结局

- **准备工作（11.2.1）**：ODBC 数据源配置（DSN）、驱动安装；wx 侧 `wxDatabase` 的工厂（`wxDBFactory::Create("ODBC")`）。2026：DSN 配置仍是 Windows 老工业环境的日常，但对新代码是**负资产**（驱动分发、字符集 SQLWCHAR 泥潭）。
- **操作数据库（11.2.2）**：wxDatabase 的对象关系层——`wxDBConnection/wxDBRowSet/wxDBColumn`，**以游标+列对象取数**（2.8 API 名单，转述口径）。它的死因清单（用现代眼光）：抽象层同时背着"跨 DBMS 方言"与"跨平台字符串"两座山；性能（逐列对象化）与特性（方言特性一律抹平）双输；Qt SQL 的同期存在也没让它活下来——**"在 GUI 框架里内置数据库抽象"这个想法本身被证伪**（本节是全章核心判词）。
- **书中未展开、2012 已在上升期的另一路**：直接嵌 SQLite C API；wx 生态的社区胶水层 **wxSQLite3（utelle）**——本次实测其 GitHub 仓库 `pushed_at=2026-08-16`、stars 652（api.github.com 实测），**至今活跃**，就是"路线之争"的裁判结果。

## 三、权衡：GUI 框架该不该碰数据库？与相邻概念对比

| 层 | 代表 | 2026 判定 |
|---|---|---|
| 框架内置抽象（wxDatabase） | 已删 | 证伪：抽象成本>收益 |
| ODBC/JDBC 统一接口 | unixODBC/Win ODBC | 遗留集成、BI 工具用 |
| 单驱动薄封装 | **wxSQLite3**、SOCI、sqlpp11 | 主流：只抽"连接与语句"，SQL 自己写 |
| 嵌入式引擎直用 | sqlite3 C API | 小依赖大回报，桌面默认 |
| ORM/类型安全查询 | sqlite_orm、drogon 系（服务端） | 按团队口味 |
| 对象存储/文件 | JSON/parquet + mmap | 桌面新宠（配置与分析两用） |

对照 [C++API设计](../C++API设计/00-总览与阅读地图.md)：wxDatabase 是"**大而全抽象层**"失败样本——与第 1/9 章反复出现的"薄封装保命、厚抽象早逝"形成有趣的同一条定律的两个侧面：wx 对 socket 薄（活，但边缘）；对 DB 厚（死）。而 wxSQLite3 的长赢证明：**框架外、单后端、贴近 SQL** 的胶水才是 GUI 生态数据库层的稳态。

## 四、可迁移的正解（2026 版"本章应该教什么"）

1. 桌面持久化默认 SQLite：单文件、零服务、ACID；`BEGIN/COMMIT` 手工批处理事务（性能第一课）。
2. 线程规矩回链第 8 章：SQLite 连接**不跨线程共享**（serialized 模式除外但慢）；worker 线程各开连接 + CallAfter 回报。
3. UI 绑定走数据视图：`wxListCtrl`/`wxDataViewModel` + 分页查询（`LIMIT/OFFSET`→键集分页），别把游标直连控件。
4. 云同步=HTTP API（回链第 9 章选型表），本地 SQLite 做离线缓存——"直连中心数据库"架构在企业内网外基本退役。
5. 迁移与版本化：schema_version + 增量迁移脚本（当年书完全没有，是 2026 桌面应用的必修项）。

### 2026 桌面数据组件货架（把"正解"落到依赖清单上；项目名以官网为准，本次未逐一探活 ⚠️）

| 需求 | 首选 | 备注 |
|---|---|---|
| 本地存储引擎 | SQLite | 公版域，随发行版补丁 |
| wx 粘合层 | wxSQLite3 | 本次实测仓库 2026-08 活跃；附加密扩展 |
| 静态加密 | SQLCipher / wxSQLite3-crypt | GDPR/等保刚需，2012 书零覆盖 |
| 本地分析/报表 | DuckDB | parquet 直查，嵌入式 OLAP |
| 类型安全 SQL | sqlite_orm/sqlpp11(可选) | 收益随项目规模上升 |
| 迁移工具 | 手写 user_version 或 sqitch 类 | 关键是"有"而不是"用什么" |
| 云同步 | REST/GraphQL(链 [09](09-网络编程.md)) | 冲突解决自研 CRDT/最后写入 |

### 一句话版本（给只读一节的人）

本章唯一值得 2026 照抄的是 11.1.3 的概念栈（驱动-连接-语句-结果集四件套），其余全部替换：ODBC→SQLite、wxDatabase→wxSQLite3、游标直连网格→分页+视图模型、无迁移→user_version 迁移脚本。

## 核心概念速览（中英对照）

- **开放数据库互连** — ODBC (Open Database Connectivity)：SQL 方言与驱动的统一 C API
- **数据源名** — DSN (Data Source Name)：Windows 侧驱动配置载体
- **wxDatabase** — 2.8 内置 ORM 尝试：3.0 移除（转述 ⚠️）
- **游标行集** — wxDBRowSet：逐行逐列对象化取数模型
- **嵌入式数据库** — embedded DB (SQLite)：无服务进程、随应用分发的引擎
- **wxSQLite3** — 社区胶水层：wxString 接口 + 加密扩展，2026 仍活跃（实测）
- **键集分页** — keyset pagination：深分页的正解
- **数据视图模型** — wxDataViewModel：控件与数据源的 MVC 缓冲层
- **模式迁移** — schema migration：桌面软件升级的数据兼容层
- **离线优先** — local-first：SQLite 缓存 + 云同步的 2026 桌面范式
- **SQL 注入** — injection：拼接 SQL 的原罪，DSN/驱动时代遗留坏习惯

## 最新演进与工业实践

- **语言层的虹吸**：C++20/23 没有并入 SQL——数据库层生态停在库级（SQLite、DuckDB、sqlpp11），故本章的"框架内置抽象之争"在语言标准里看不到回声；反例是 std::execution（P2300 实测 302）这类"薄机制"入标——厚抽象不可标准化的教训与第 3 章"moc vs 宏"形成互文。
- **DuckDB 变量**：2026 桌面"数据分析面板"类需求（本地 OLAP、parquet 直查）已由 DuckDB 承接——嵌入式、单文件依赖、SQL 方言近 PostgreSQL；wx + DuckDB 是"报表型桌面工具"的现实新栈（趋势判断，无 wx 绑定层则走 C API）。
- **加密与合规**：SQLite 社区版无加密（SQLCipher/wxSQLite3 的加密扩展提供）；桌面应用 GDPR/等保语境下"本地库静态加密"成了 2012 教材完全缺失的一节。
- **wx 官方姿态**：3.x 起不再内置任何数据库层（删除即表态，转述 ⚠️）；官方 sample 无 DB 样例——社区层（wxSQLite3）补位是"框架放弃的层由生态认领"的标准案例，与第 7 章媒体外包同构。

## 本章小结

1. wxDatabase 之死 + wxSQLite3 之活 = "GUI 框架内置厚数据抽象被证伪、薄胶水长赢"的完整实验，本章最大遗产是这个判词。
2. ODBC 读成遗留学生；2026 桌面持久化三件套：SQLite、迁移脚本、离线优先。
3. 数据与 UI 的中间层（wxDataViewModel/键集分页）是书中 11.2 真正该展开而未展开的部分。
