## 0. 本章主线

2e 敢把"升级"写成独立一章，是因为 Spark 近十年的版本史就是一部**默认值与语义的翻案史**：

- 不改一行代码、只换版本——作业可能更快（AQE 接管）、更慢（新语义更保守）、或者直接报错（ANSI 化）；
- 升级工程学的本质＝把"版本差异清单"变成"可执行的迁移验证计划"；
- 谱系补位：#215 TDG 讲当下 API、#193 停在 2.x 时代（登记不链），"版本之间"的坑只有本册这一章在填。

## 3.1 升级的三条断层线（⚠️ 主题重建）

1. **二进制断层**
   - 跨大版本（2.4→3.x→4.x）所有第三方 jar（datasource、UDF、序列化器）必须重编译重验；
   - Scala 2.12→2.13 的交叉编译窗口是常见暗礁；
   - Hadoop 发行版依赖矩阵随版本漂移——官方兼容清单为唯一权威。⚠️＋ https://spark.apache.org/downloads.html ✅
2. **语义断层**
   - ANSI SQL 合规从 opt-in（3.x）到 **4.0 默认开**：整数除法、溢出、类型强转的报错行为翻转；
   - 这是静默数据正确性风险最高的一条——比性能回归更可怕；⚠️
   - 时区/日期解析策略收紧（`spark.sql.legacy.timeParserPolicy` 一族开关）是 2.4→3.0 的第一坑。⚠️＋ https://spark.apache.org/docs/latest/sql-migration-guide.html ✅
3. **默认值断层**
   - AQE 引入后逐步默认开、shuffle 并行度自适应、序列化与压缩选项收敛；
   - "升级后什么都没改但都变快了/变慢了"的元凶库；⚠️＋ https://spark.apache.org/docs/latest/configuration.html ✅

## 3.2 迁移工程方法（⚠️ 主题重建）

**差分验证三件套**（同输入双版本并跑）：

| 验什么 | 手段 | 抓哪类断层 |
|---|---|---|
| 数据没变错 | 行数＋聚合校验和逐分区比对 | 语义断层 |
| 计划没变坏 | 物理计划 diff（explain 文本归档） | 默认值断层 |
| 账单没变贵 | shuffle bytes/spill 量/task 时长分布 | 二进制＋默认值 |

- 回归重点名单：日期时区、CSV/JSON 边角、Hive 元数据兼容、外部 catalog 行为、UDF 空值语义。⚠️
- 灰度路径：影子跑 → 按作业分批切流 → 保留回退窗口（legacy 开关只当降落伞不当交通工具）；SQL 行为差异逐条对照官方迁移清单。✅ 入口 https://spark.apache.org/docs/latest/sql-migration-guide.html
- 不可迁移清单：依赖 `*.internal` 私有件的代码、以 RDD 路线写死的 ML 工程（4.x 的 MLlib 退场，见 [11-MLlib与机器学习管道](11-MLlib与机器学习管道.md)）。⚠️

## 3.3 为什么"2.4"是锚点（⚠️ 转述＋取证）

- 终版第 4 章标题直接写 **"What's New in Spark 4.2 Since 2.4"**：作者团把 2.4 视为"仍大量在产的最低水位线"。
- 2.4→4.2 之间发生了整整一代范式：DataFrame 统治、Catalyst/AQE 自动化、K8s GA 化、Connect、Python 生态崛起（细目见 [04-Spark4.2相对2.4的新特性](04-Spark4.2相对2.4的新特性.md)）。
- 升级叙事以 2.4 起算，等于承认：**存量系统的重心迁移成本才是调优市场的主体**。
- 中文互证：../bigdata/10-计算引擎的演进.md 的"存量视角"同构；2.x 时代基线册 #193 登记不链。

## 3.4 跳变风险清单（⚠️ 方向性骨架，逐条细目以官方 release notes 为准，不臆写）

| 跳变 | 高风险翻转 | 建议动作 |
|---|---|---|
| 2.4→3.0 | 时区解析收紧；AQE 引入（默认关）；Hive 依赖升级；Python/Scala 门槛上移 | 先解析策略、后开 AQE 影子对比 |
| 3.0→3.x | AQE 转默认、若干 deprecation 到期、datasource v2 语义微调 | 计划 diff 常态化 |
| 3.x→4.0 | ANSI 默认、JDK/Scala 基线再抬、Connect/新 ML 面、old mllib 退场 | 正确性回归优先于性能回归 |
| 4.x 内小步 | 行为修复与性能跟版为主 | 常规回归即可 |

- 诚实边界：上表是"迁移文档主题的分类骨架"，**不是逐条 changelog**；每条细项请以官方迁移指南族（sql-migration-guide ✅ 等）为准。

## 3.5 升级决策树（实践版 ⚠️）

```
在产 2.4? ──否──▶ 小步跟版(3.x内) ─▶ 常规回归
   │是
   ├─ 有湖仓迁移计划? ──有──▶ 与表格式升级合并窗口(一次阵痛)
   ├─ 有 Hive 深度绑定?    ──是──▶ 先做 catalog 兼容层试点
   └─ 都无 ──▶ 直上当前 stable(取证时 4.2.0 ✅), 留 legacy 开关回退
```

三问定节奏：业务窗口有几周？数据正确性可自动比对吗（三件套第一件）？团队 Python 栈多深（决定 ANSI/UDF 回归量）？

## 核心概念速览（中英对照）

- **迁移断层线** — Compatibility fault line：二进制/语义/默认值三类版本断裂的统称，升级风险地图的横轴。
- **ANSI 合规模式** — ANSI mode：溢出/除零/类型强转按标准语义报错，4.0 起默认，正确性风险第一位。
- **计划差分** — Plan diff：新旧版本物理计划逐项对比，升级回归的核心工件。
- **影子运行** — Shadow run：双集群同输入并跑比对，灰度切流前的最后防线。
- **遗留策略参数** — Legacy policy flags：`spark.sql.legacy.*` 一族，用行为开关买迁移时间的官方逃生舱。
- **二进制不兼容** — Binary incompatibility：跨大版本插件/UDF 必须重编译的约束线。
- **deprecation 周期** — 弃用窗口：API 从公告到移除的多版本承诺，盘点存量依赖的第一张表。
- **AQE 默认翻转** — AQE on-by-default：3.0 引入、后续版本默认开启的重规划机制开关史。
- **catalog 兼容** — Hive/catalog compatibility：外部元数据对接层是 2.4→3.x 最易踩的边角雷区。
- **版本锚点** — Baseline version：本书选 2.4 作存量参照系的叙事决策。
- **回退窗口** — Rollback window：legacy 开关＋双跑数据支撑的撤销余地。

## 最新演进与工业实践

- **取证现状（2026-10）**：官方 `docs/latest`＝ **Spark 4.2.0**（✅ 实抓页头）；SQL 行为变更权威入口 https://spark.apache.org/docs/latest/sql-migration-guide.html ✅；参数默认值权威入口 https://spark.apache.org/docs/latest/configuration.html ✅。本书终版以"4.2 对齐 2.4 存量"立意，升级章因此长红。⚠️
- **工业现状**：在产集群大量停在 3.x 中后期，2.4 存量仍是教材级市场——第 3/4 章立意的注脚（⚠️ 行业观察口径，不引未验证统计）。
- **湖仓解耦趋势**：表格式（Iceberg/Delta）把"引擎升级"与"数据格式升级"部分解耦后，**元数据层成为新断层线**——catalog 版本×引擎版本兼容矩阵先行，见 ../Use_Iceberg_with_Spark/02-Catalog配置与接入.md。
- **Connect 的缓和作用**：客户端 jar 与集群版本配对的老痛，在 Spark Connect（4.0+）协议化解耦下有望减负，但协议版本成为新兼容轴。⚠️
- **兄弟册对位（登记不链）**：#193（2.x 册）停在升级叙事起点、#150/#152 覆盖 3.x 教学面——与本册构成"版本断层四色图"，检索时注意各册成书年份。
