# 07 高效转换算子（Ch7: Effective Transformations）

> 章题取证 ✅（终版第 7 章＝草案第 5 章"高效的转换"对位）；草案节级结构 ✅ 实抓：窄/宽转换（性能与容错影响、coalesce 特例）/ 返回何种 RDD / 最小化对象创建（重用对象、更小结构）/ mapPartitions 迭代器到迭代器 / 集合操作 / 降低初始化开销（共享变量、广播、累加器）/ 重用 RDD（划算判定、缓存·持久化·检查点·shuffle 文件、Alluxio、LRU、繁忙集群、与累加器交互）。⚠️ 终版或有瘦身/改序。

## 0. 本章主线

这一章是 2e 里"RDD 手工技艺"的最大存量，全部围绕一个物理事实：**JVM 里每个对象都不便宜，每个 shuffle 边界都不免费**。SQL 时代的正确姿势：把这些知识用来**读懂引擎在替你做什么**，而不是手写回去。

## 7.1 窄与宽：算子的第一分类（草案 5.1 ✅）

- 窄转换近零成本：流水线内联进 codegen 循环，无落盘无网络。
- 宽转换＝shuffle 全家桶：写盘、网络、合并三笔账一次付清。⚠️＋ https://spark.apache.org/docs/latest/rdd-programming-guide.html ✅
- 第一性原则：**减少宽转换的次数与通过量**——次数看计划形状，通过量看数据形状（列裁剪/预聚合）。
- 性能影响（草案 5.1.1）：宽边界两侧还有"并行度突变"副作用——上下游分区数不匹配时产生放大或收缩。
- 容错影响（草案 5.1.2）：窄链断了就地重算便宜；宽边界断了要回放大段血缘——检查点与 persist 是"买断点"的保险（02 章阶梯的运维化）。
- coalesce 特例（草案 5.1.3）：只缩不增、可走窄路径免 shuffle；repartition 必 shuffle；**最常见误用是"缩在聚合之前"**把并行度永久锁死。中文互证 ../bigdata/02-Spark核心与RDD模型.md。

## 7.2 转换返回什么 RDD（草案 5.2 ✅）

- 分区器是否保留、是否可管道化（pipelined）、能否预聚合——三个属性决定下一算子的价格。
- 读 API 文档的正确姿势：不看"功能描述"，看"依赖声明"（OneToOne/Hash/Shuffle）。⚠️

## 7.3 对象经济学（草案 5.3 ✅）

- **重用现有对象**：分区内复用可变累加器/缓冲，避免逐行 new——GC 压力的直接开关；
- **更小的数据结构**：元组/包装类的字节账（装箱、引用头、对齐）；能 int 不 Integer、能平行数组不对象数组。⚠️
- 🔧 概念锚：E4（列存 0.01s vs 行存 0.16s，≈24 倍，**非 Spark**，详 [05-DataFrame与SparkSQL](05-DataFrame与SparkSQL.md)）——分布式 JVM 里逐对象税只会更重。
- "引擎替你做了什么"：UnsafeRow/向量化读＝"重用对象＋更小结构"的制度化；手写的价值只剩解释计划。⚠️

## 7.4 mapPartitions：迭代器到迭代器（草案 5.4 ✅）

- 定义（5.4.1）：函数收到分区**迭代器**、必须返回迭代器；逐元素 `map` 把两侧拍平成单对象流，`mapPartitions` 保住批的边界。
- 时空优势（5.4.2）：
  1. 初始化成本按分区摊薄（连接/句柄/字典加载一次即可）；
  2. 流式产出可不在内存物化整分区；
  3. 适配天然批式的外部系统（JDBC batch、批量 HTTP）。
- 案例（5.4.3）：数据库批读批写、富化调用、分区内归并。
- 红线：迭代器内偷偷 `toList` ＝ 把 mapPartitions 变成 OOM 制造机。⚠️

## 7.5 集合操作与初始化开销（草案 5.5/5.6 ✅）

- 分区内集合选择表：查重用 Set、紧凑遍历用数组/值类、链式追加是反模式（复制成本二次方）。
- 共享变量陷阱：闭包捕获大对象＝每任务重发一份序列化字节——导论 1.4.3 的伏笔在此兑付。
- 广播变量：块式增量分发，只读小表/字典的家；与 06 章 BHJ 同源不同用（一个是 join 策略，一个是变量通道）。
- 累加器：任务→driver 的单向汇报旁路；注意 action 语义下的可见性与重试重复累加。⚠️＋ https://spark.apache.org/docs/latest/rdd-programming-guide.html ✅

## 7.6 重用 RDD：缓存的会计学（草案 5.7 ✅）

- 划算判定（5.7.1/5.7.2）：`重算成本 × 复用次数` vs `缓存内存税 + 序列化税`——血缘长、复用多、重算贵三条件齐才 persist。
- 重用类型谱（5.7.3）：
  - cache/persist：级别谱系（内存/磁盘/序列化/副本）；
  - checkpoint：血缘截断，恢复有界但要多写一遍盘；
  - shuffle 文件：同 Stage 消费者天然复用，免费午餐。
- Alluxio（5.7.4）：内存级中间结果外置层——**演进取向**：到 2026 多被"湖仓表＋对象存储＋本地 NVMe 缓存"生态替代，读作历史方案。⚠️
- LRU 与繁忙集群（5.7.5/5.7.6）：存储内存被执行内存挤出的日常（02 章 E1 阶梯的运维语言，**类比非 Spark**）；多租户下 cache 命中率是最先崩的 SLA。⚠️＋ https://spark.apache.org/docs/latest/configuration.html ✅（memory 族）
- 与累加器交互（5.7.7）：缓存块重放会**静默丢累计**——副作用计数与容错模型天然冲突，改"数据即证据"。⚠️

## 核心概念速览（中英对照）

- **窄转换** — Narrow transformation：不触 shuffle 的流水线算子，codegen 的食粮。
- **宽转换** — Wide transformation：跨节点重分布，一切分布式成本的计量单位。
- **coalesce** — 缩分区：可走窄路径的并行度削减，repartition 的省钱替身。
- **mapPartitions** — 分区迭代器转换：摊薄初始化、保持流式边界的批式手柄。
- **迭代器到迭代器** — Iterator-to-iterator：不物化中间集的转换纪律。
- **闭包捕获** — Closure capture：大对象随任务广播的隐形开销源。
- **广播变量** — Broadcast variable：一次分发只读副本，富化与查表的家。
- **累加器** — Accumulator：任务向 driver 单向汇报的旁路计数器。
- **StorageLevel** — 持久化级别：内存/磁盘/序列化谱系的取舍开关。
- **checkpoint** — 检查点：血缘截断换恢复有界，代价双写盘。
- **LRU eviction** — 缓存挤出：存储内存给执行内存让路的机制。
- **Alluxio** — 内存分布式缓存层：中间结果外置的历史方案。
- **装箱税** — Boxing overhead：值类型对象化的字节与 GC 双重成本。

## 最新演进与工业实践

- **手工技艺的制度化**：mapPartitions≈向量化批读、广播复用≈AQE BHJ、对象复用≈UnsafeRow——本章价值从"照做"转为"能解释"。⚠️
- **AQE 默认后仍需人工的角落**：极端倾斜、缓存策略（新并行度模型下哪些中间结果值得 persist 变了）——参数口径以官方调优页为唯一权威（✅ https://spark.apache.org/docs/latest/sql-performance-tuning.html）。
- **缓存层生态**：Alluxio 路线在云上多被对象存储＋本地缓存/湖仓元数据层替代；跨引擎缓存一致性成为新命题（../Use_Iceberg_with_Spark/06-维护过程与流式写入.md 的维护视角；⚠️ 趋势观察）。
- **工业复盘高频**：coalesce 缩在聚合前→并行度锁死、闭包带大字典→任务字节膨胀——两条机制解释均在本章。
