## 0. 本章主线

ML 章在"性能书"里的身份是**约束清单**而非算法教材：训练与推理的分布式形态（数据并行 vs 模型并行、迭代算法的 shuffle 模式、特征流水线的物化点）决定前面各章的调优结论哪些能直接用、哪些会翻车。新旧 API 抉择（9.1）在 2026 已是历史问题——RDD 路线退场，Pipeline/DataFrame 路线是唯一活路（回看 [03-Spark升级与迁移](03-Spark升级与迁移.md)）。⚠️

ML 负载的执行形状速写：

```
特征流水线（宽转换密集区）──> 物化点选择（persist?）──> fit 迭代（血缘重放 × N 轮）
                                                      │
评估（可 combine 聚合，便宜）<── 预测（广播模型＋分区内批推断，吞吐主体）<──┘
```

## 11.1 MLlib（旧）与 ML（新）的选择（草案 9.1 ✅）

- 判据史：`mllib`＝RDD 裸接口，性能旋钮多但一切重造（特征工程、流水线序列化、参数管理全部手写）；`ml`＝DataFrame 管道，吃 Catalyst 优化红利＋Pipeline 整体可保存可组合。终版口径 ⚠️ 推定：ml 默认，mllib 只余存量维护与内部实现。
- 官方权威：https://spark.apache.org/docs/latest/ml-guide.html ✅（含 "ml → mllib 迁移说明" 族条目）。
- 谱系分工：算法配方本体（ALS 推荐/决策树/聚类/特征工程食谱）在 ../Advanced_Analytics_with_Spark_2e/00-总览与阅读地图.md 那条线，本章只记**性能形状**——谁在 shuffle、谁在迭代、谁该物化。
- 判读：为什么 ML 章必须活在调优书里——迭代算法是**血缘重放放大器**：fit 每轮都从最源头重算特征的话，前面各章所有"昂贵转换"的成本会被乘上轮数，persist 决策的杠杆在此最大。⚠️

## 11.2 特征流水线的性能解剖（草案 9.2.2/9.2.3、9.3.4/9.3.5 ✅）

- VectorAssembler/StandardScaler/OneHotEncoder 链：每步都是宽转换候选（跨分区统计量）——Scaler 要全局均值方差（一次聚合＋广播回）、Encoder 要全局频次表（一次 countByValue 型 shuffle）；**一条流水线的隐性 shuffle 次数比看上去多**。⚠️＋ml-guide ✅
- 高基数 one-hot＝内存爆炸经典点：稀疏向量（SparseVector 只存非零）＋频率截断（minWeightsOnColumn 类阈值，低频并入"其他"）为双解——本质是 [08-键值对数据与Shuffle](08-键值对数据与Shuffle.md) 预聚合母题的 ML 实例。⚠️
- 管道训练＝多次 action 风险：fit 遍历数据 N 轮 ⇒ 若不物化，血缘每轮重放；persist 特征表与否的划算判定即 [07-高效转换算子](07-高效转换算子.md) 重放成本公式的 ML 特化：`重放成本 × 轮数 vs 存储成本 × 分区生命周期`。⚠️＋ml-guide ✅
- 清洗阶段（Imputer/重命名/类型规整）多为窄转换，但**与宽转换交错排布**会白白多切 stage——流水线排序即 DAG 排序（接 [02-Spark运行原理](02-Spark运行原理.md)）。⚠️
- 🔧 概念锚回 [02-Spark运行原理](02-Spark运行原理.md) 的 E1：迭代算法每轮内存峰值与"挤出阶梯"同源——E1 实测 DuckDB 12M 行聚合在 120MB 限内存＋temp_directory 下 0.77s、4GB 下 0.89s，spill 文件实际生成：**内存不够时执行计划自己找地板**，迭代训练只是把这事重复 N 轮（**类比非 Spark**）。

## 11.3 训练、预测与评估的形状（草案 9.2.4–9.2.7、9.3.6–9.3.9 ✅）

- 训练算子的 shuffle 指纹分两族：
  - 树模型（决策树/随机森林/GBD）：多次排序＋分位数直方图扫描——RangePartitioner 的工业级用户（接 [08-键值对数据与Shuffle](08-键值对数据与Shuffle.md)），分裂点候选的采样与聚合是每轮固定税；森林＝树间并行、树内迭代。⚠️
  - 线性模型（SGD/LinearRegression/Logistic）：窄链＋小聚合（梯度是 per-partition 局部量，全局合并便宜）——天然近于流式，扩并行收益平滑。⚠️
- 预测阶段是吞吐主体：模型尺寸小 ⇒ 广播（接 [07-高效转换算子](07-高效转换算子.md) 广播变量纪律）＋分区内批式推断，免 join 免 shuffle；大模型（深度类）分区内加载/外置服务另议（11.4）。⚠️＋ml-guide ✅
- 评估指标（areaUnderROC/accuracy/rmse）多为可 combine 聚合——成本低到常被忽略；评估集误用训练集这类统计学错误不在本册范围（归 ../Advanced_Analytics_with_Spark_2e/00-总览与阅读地图.md 配方线）。⚠️

## 11.4 自定义算法、持久化与服务（草案 9.3.11/9.3.12/9.4 ✅）

- Transformer/Estimator 契约：写自定义阶段＝实现 fit/transform 签名＋接入参数系统（Param 声明可 grid search）＋序列化——换来的红利是 pipeline 可组合、可保存、可被 [10-测试与验证](10-测试与验证.md) 的计划断言覆盖。⚠️
- 模型持久化：原生 save/load（管道整体含元数据）为主；PMML/导出交换格式为跨引擎路线，草案年代工具位——2026 判读：交换更多走 ONNX 类推理格式（⚠️ 趋势观察，未验链不点名）。
- 模型序列化＝版本断层线：管道模型跨大版本加载的兼容性回到 [03-Spark升级与迁移](03-Spark升级与迁移.md) 的差分验证清单——模型是数据，按数据迁移纪律对待。⚠️
- "一般服务考量"节：离线批量打分 vs 低延迟在线服务的架构分叉——批量打分是 Spark 稳态主场；低延迟服务把模型搬出引擎。2026 判读：**批量特征＋外部模型服务**渐成主流，Spark 退守特征与批量层（⚠️ 趋势观察口径）。

## 11.5 误区清单

| # | 误区 | 正解 | 出处 |
|---|------|------|------|
| 1 | 一条 pipeline 只有一次 shuffle | 每阶段的全局统计量各带一次聚合税 | 11.2 |
| 2 | one-hot 高基数直接稠密向量化 | 稀疏＋频截断，否则内存爆炸 | 11.2 |
| 3 | 迭代训练不重算特征 | 不 persist 则每轮血缘重放，杠杆 ×N | 11.2 |
| 4 | 树模型慢在算力 | 慢在排序/分位数 shuffle，指纹不同族 | 11.3 |
| 5 | 低延迟推理用流式 Spark 硬扛 | 模型出库到专用推理面，Spark 管特征与批量 | 11.4 |
| 6 | 模型保存与引擎版本无关 | 跨大版本加载是断层线，按迁移纪律验证 | 11.4 |

## 11.9 ML 性能 FAQ（快查）

- Q：pipeline 训练特别慢？——先查每轮重放：persist 特征表再看损耗曲线，顺序不能反。⚠️＋ https://spark.apache.org/docs/latest/ml-guide.html ✅
- Q：高基数特征直接 OOM？——稀疏向量＋频率截断，再考虑 hashing trick（08 章预聚合母题的变体）。⚠️
- Q：随机森林加机器不涨速？——树内迭代税（shuffle）是地板；树间并行扩得好，树内扩不动。⚠️
- Q：想用 Spark 做在线推理？——低延迟不该在引擎里硬扛：批量打分出表、模型出库服务层。⚠️
- Q：模型存了加载报错？——跨大版本序列化兼容是断层线，按 03 章三件套对待模型工件。⚠️

## 核心概念速览（中英对照）

- **Pipeline/Estimator** — 管道与估计器：fit 产出 Transformer 的可组合 ML 抽象。
- **Transformer** — 变换器：transform 无参进有参出的流水线阶段基元。
- **特征流水线** — Feature pipeline：编码/缩放/装配链，宽转换密度最高的地段。
- **稀疏向量** — Sparse vector：高维特征的内存解药，one-hot 爆炸的防线。
- **迭代收敛** — Iterative convergence：多轮遍历数据的训练范式，血缘重放风险源。
- **血缘重放** — Lineage recompute：fit 每轮从源头重算的隐性成本，persist 的对价对象。
- **模型广播** — Model broadcast：小模型上发换分区内自给推断。
- **分位数直方图** — Quantile histogram：树算法分裂点的全局统计成本。
- **Param 系统** — 参数声明：自定义阶段接入网格搜索与序列化的契约面。
- **ML 迁移** — MLlib old → ml：RDD 路线到 DataFrame 路线的历史单行道。
- **批式打分** — Batch scoring：Spark 最稳的 ML 服务形态。
- **模型序列化** — Model save/load：管道持久化与跨版本兼容（回到断层线）。

## 最新演进与工业实践

- **RDD API 退场落地**：Spark 4.x 推进 old mllib 的移除线（⚠️ 具体版本节点以官方 ml 迁移文档为准，https://spark.apache.org/docs/latest/ml-guide.html ✅ 为权威入口），本章 9.1 的"新旧抉择节"已成历史脚注——读作"迁移如何完成"的社会学样本。
