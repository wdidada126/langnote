## 12.1 流处理：从 DStream 到 Structured Streaming（草案 10.1 ✅）

- 草案如实保留了双时代的张力：批间隔/checkpoint 间隔/Source-Sink 语义多为 **DStream 词汇**（receiver 常驻、以 RDD 序列为时间轴切片）；Structured Streaming 小节则是**增量查询＋watermark**的新范式：流＝无界表，每次触发对增量做一遍微批查询。权威：https://spark.apache.org/docs/latest/structured-streaming-programming-guide.html ✅。⚠️
- 调优要点迁移（都是前面各章的时间轴投影）：
  - 微批大小＝[02-Spark运行原理](02-Spark运行原理.md) 的任务粒度经验值搬到时间维度——批太小则调度开销占比爆炸，太大则延迟 SLA 失守；
  - 状态体积＝E1 内存阶梯的流式版——键状态聚合超内存即走 state store 落盘，恢复与读取都付盘税（**类比非 Spark**，机制转述 ⚠️）；
  - 乱序与迟到＝watermark 换内存：水位线调大→迟到容忍↑但状态保留期↑，两笔税永远对冲；
  - Source/Sink 形状：读侧并行度对齐分区、写侧小文件问题回 [05-DataFrame与SparkSQL](05-DataFrame与SparkSQL.md)（E3 反向：24 分区裁剪 0.00s vs 全扫 0.01s——分区是双刃，流式写出最容易切出过量小分区）。🔧
- DStream 注意事项节（草案 10.1.4）：块大小/序列化器/内存级接收等运维细节——2026 读作文物，但其"每批都要重新问一遍资源"的心智模型正是微批范式的病灶，Continuous/表级增量执行是后话。⚠️
- 高可用小节（草案 10.1.6）：checkpoint 落 HDFS 元数据、Driver 故障重启续算的语义边界（at-least-once 现实 vs exactly-once 需幂等 Sink）；判读：K8s 化后由"对象存储＋表格式事务"接手——恢复不再依赖引擎私有 checkpoint 而依赖表的快照一致性（回看 ../Use_Iceberg_with_Spark/06-维护过程与流式写入.md）。⚠️＋ https://spark.apache.org/docs/latest/running-on-kubernetes.html ✅
- 谱系分工：流式 API 教学在 ../Spark_The_Definitive_Guide/09-结构化流处理.md；流批一体架构叙事线（波 8 兄弟 #156/#157 等）只登记不链，挂点即本节。

## 12.2 GraphX 与社区包（草案 10.2/10.3 ✅）

- GraphX＝双 RDD（顶点表/边表）＋Pregel 迭代：性能指纹是"每超步一次 join＋消息聚合"——图算法的"迭代收敛"税与 11 章 ML 的"fit 重放"税同族，且**每轮都shuffle**（消息沿边路由）；顶点/边 RDD 的 co-partitioning 纪律直接决定超步成本（接 [08-键值对数据与Shuffle](08-键值对数据与Shuffle.md)）。⚠️＋ https://spark.apache.org/docs/latest/graphx-programming-guide.html ✅
- 图存储侧的现实：属性图/Neo4j 线（../../db/db.md 书目线，波 5 兄弟）与 GraphX 的内存图是两种世界——GraphX 强在"图是一次计算的输入"，弱在"图是常驻服务"；判读 ⚠️ 趋势观察。
- 社区包（spark-packages 生态，草案 10.3）：草案年代的弹性数据集/CSV-JSON IO/外部数据源连接器类库，多数已被 **DataSource V2＋湖仓格式**吸收——判读同 [04-Spark4.2相对2.4的新特性](04-Spark4.2相对2.4的新特性.md)：第三方的功能下沉为引擎内建，是 Spark 生态的标准消化路径。⚠️＋ https://spark.apache.org/docs/latest/sql-performance-tuning.html ✅

## 12.3 打包工程学（草案 10 章题第二义＋社区共识 ⚠️）

- 依赖谱系三坑：
  1. **版本三角**：Spark/Hadoop/连接器互斥矩阵——连接器声明的 Spark 主版本必须与集群严格配对；
  2. **shade 冲突**：同一库两个版本进 classpath（guava/jackson 是惯犯），重定位（relocation）是预防性手术但会切断与引擎共享类的路径；
  3. **provided vs assembly**：引擎自带的（Spark core）标 provided 减体积、启动快；缺的打 fat-jar 保自包含——体积-兼容-启动三角没有全赢解。⚠️＋ https://spark.apache.org/docs/latest/configuration.html ✅（classLoader 顺序族 spark.sql.executor/coordinator... 前缀开关）
- 提交面：`spark-submit` 参数族（主类/资源/配置优先级：命令行>properties 文件>默认）、动态分配与队列礼貌（流作业闲置伸缩，接 [11-调度资源与运维](../bigdata/11-调度资源与运维.md) 口径）；K8s 化后打包终局＝**容器镜像**：依赖冲突在镜像构建期暴露而非运行期（K8s 页 ✅）。
- 排错面：driver 日志与 eventLog 先行（接 [10-测试与验证](10-测试与验证.md) 指标法）；ClassNotFoundException/LinkageError 族按"谁带的、谁赢的"两问定位类加载路径。⚠️
- Python 作业打包：conda 环境分发/archives 上传＋`--py-files`——语言税（09 章）之外的**分发税**，镜像化同样消解大半。⚠️

## 核心概念速览（中英对照）

- **微批** — Micro-batch：Structured Streaming 的时间切片执行形态。
- **Watermark** — 水位线：迟到容忍与状态清理的交换汇率。
- **状态后端** — State store：流式聚合的键状态存储，内存-盘阶梯用户。
- **checkpoint 间隔** — Checkpoint interval：元数据落盘频率，恢复税与写放大权衡。
- **幂等 Sink** — Idempotent sink：exactly-once 语义的外部契约条件。
- **Pregel 模型** — 超步迭代：GraphX 的计算范式，每步 join＋消息聚合。
- **co-partitioning（图侧）** — 顶点/边 RDD 同分区布局：超步成本的先决条件。
- **shade/relocation** — 依赖重打包：类冲突的预防性手术，带共享类断链副作用。
- **provided 部署** — 作用域取舍：引擎自带与 fat-jar 的体积-兼容权衡。
- **classLoader 策略** — 加载顺序开关：冲突排错的旋钮。⚠️
- **动态分配** — Dynamic allocation：流作业闲置伸缩的队列礼貌。
- **推测执行** — Speculation：掉队长尾的重复任务对冲。
- **Event Log** — 事件日志：历史回放与指标采集的证据链。
- **容器镜像化** — Image-based packaging：把依赖冲突前移到构建期的打包终局形态。

## 最新演进与工业实践

- **DStream 退场完成度**：官方指南仍以 Structured Streaming 为唯一推荐面（✅ structured-streaming-programming-guide 页），草案的 DStream 注意事项到 2026 读作文物；流式 SQL 化与增量执行模式（非微批的连续/表增量方向）持续演进，口径以官方页为准 ⚠️。
- **流的落点=湖仓表**：流式写入与表维护（compaction/孤儿文件/元数据膨胀）解耦成专职工程面，见 ../Use_Iceberg_with_Spark/06-维护过程与流式写入.md——本册流章节的"高可用"在 2026 更多是"表事务＋对象存储"问题而非引擎 checkpoint 问题。
- **GraphX 热度**：开源侧维护性演进，重图分析负载部分迁移到专门引擎/湖仓图格式（⚠️ 趋势观察，本轮未对替代方案验链，不点名给链接）；图+ML 的特征迭代（11 章）仍是其存续理由。
- **打包终局**：镜像化（K8s 页 ✅）＋连接器官方二进制矩阵替代手工 shade；Connect 架构（4.0+）把"客户端 jar 与集群版本配对"的老税再削一层——打包矛盾从"运行时 classpath"上移到"镜像构建期"。⚠️＋ https://spark.apache.org/docs/latest/sql-migration-guide.html ✅（版本配对口径）
- **全册收官互证**：本目录 12 章与 ../Spark_The_Definitive_Guide/10-生产部署与性能调优.md、../bigdata/05-Spark性能优化.md 构成"部署-优化-调优"三角的最后钉脚；谱系分工与阅读地图详见 [00-总览与阅读地图](00-总览与阅读地图.md)。
