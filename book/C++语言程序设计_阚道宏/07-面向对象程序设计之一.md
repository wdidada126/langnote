## 核心概念速览（中英对照）

- **分类** — classification：OOP 第一支柱（教材口径）：把数据+操作归为「同一类事物」
- **封装** — encapsulation：第二支柱：`private` 藏表示、`public` 立契约——信息隐藏的语法化
- **类与对象** — class / object：类型 vs 该类型的存储实例；「类是图纸，对象是零件」的教材版
- **对象指针** — pointer to object（§7.3.2）：`Circle* p = &c; p->r()`，`->` 是 `(*p).` 的糖
- **类与对象的编译原理** — compilation of classes（§7.3.3/1 版 7.3.3）：成员函数不复制进对象、对象只存数据——本教材的机器观延续
- **构造函数** — constructor：与类同名、无返回类型、初始化专用；重载多家可
- **析构函数** — destructor：`~T()` 收尾；栈对象离开作用域自动调、`delete` 指针时调
- **拷贝构造函数** — copy constructor：`T(const T&)`；按值传参/返回/显式复制三触发点（§7.4.3 语境）
- **深拷贝与浅拷贝** — deep / shallow copy：默认逐成员复制=浅；指针成员裸奔=双倍释放/悬垂——本章头号事故点
- **对象数组** — array of objects（§7.5.1）：每个元素各自构造/析构
- **对象的动态分配** — dynamic objects（§7.5.2）：`new Circle(1)`/`delete`，与自由存储区（5.4.2）会师
- **常成员** — const member function/data（§7.6.1）：`int area() const;` 承诺不改对象——编译器强制的契约
- **静态成员** — static member（§7.6.2）：类级共享的数据/函数，不属于任何单个对象
- **友元** — friend function/class（§7.7）：开侧门给特定外部函数访问私有——封装的**受控破口**

## 动机：为什么从「结构体+函数」必须走到「类」

2 版 §7.1 的新增两小节就是论证本身：结构化给了**函数**（操作）和**结构体**（数据）两堆零件，
但两者的结合靠程序员自觉——全局结构体配一堆函数，数据被任何函数随意改写。
类的革命性不在语法，而在**把「谁能碰数据」写进类型定义**：`private` 是编译器执法的边界，
`public` 接口是模块四要素（5.1.3）里「接口」的最终形态。7.2「分析→抽象→组装」把 OOP 设计过程
升格为与结构化并列的方法论，这正是阚书「按方法组织知识点」纲领的第二幕。

## 机制拆解（按已核实小节）

- **§7.3 语法细则**：`class` 默认私有/`struct` 默认公有之别；成员访问；对象内存=数据成员之和（+对齐，7 章不深讲 ⚠️）；
  编译原理小节明确「成员函数表由类共享，对象只带数据」——为 8 章虚表留了认知接口。
- **§7.4 构造与析构**：默认构造器的合成规则；初始化列表 vs 构造体内赋值的区别（const/引用成员**只能**列表初始化）；
  析构顺序与构造相反；§7.4.3 深浅拷贝：默认拷贝=按位复制指针成员 → 两个对象持有同一裸指针 → double free。
  解法=自定义拷贝构造深复制资源（+三法则的 98 表达：析构/拷贝构造/赋值要一起写 ⚠️ 教材未用「三法则」名词，按主题通行口径）。
- **§7.5 应用**：对象数组的默认构造要求；`new T[n]` 对每元素调构造、`delete[]` 逆序调析构；
  对象作形参=触发拷贝构造（不传 `const&` 就是性能与深拷贝的双重考试）。
- **§7.6 常与静**：`const` 成员函数的 `this` 为 `const T*`；const 对象只能调 const 成员；
  静态数据成员类外定义（98 仪式）、静态成员函数无 this——全局状态的**合法**藏身处（对 5.3 的回应）。
- **§7.7 友元**：运算符重载前奏（`operator<<` 必须友元/非成员，9 章兑现）；友元类——慎用，教材亦以「讨论」笔调处理 ⚠️ 推定。

## 权衡与相邻概念对比

- **class vs struct**：仅默认权限之差——阚书 6.5.4→7.3 的连续叙事把它讲成演化而非对立。
- **成员函数 vs 友元 vs 非成员非友元**：优先级恰好反向于特权——能用第三种不用第二种，是 98 时代已有、
  现代更被强调的设计纪律。
- **构造重载 vs 默认参**：`Circle()` 与 `Circle(double r=1)` 同时存在会二义——教材练习的高频改错点 ⚠️ 按主题推定。
- **浅拷贝的「快」vs 深拷贝的「安全」**：引用计数（COW）是 98 时代的第三条路（侯捷《STL 源码剖析》有 String 实现），
  现代由 move 语义取代「想共享又怕复制」的两难（EMC++ item 23 方向）。

## 最新演进与工业实践

三态实测（g++ 15.2；✅/❌/⚠️ 同 01 章口径）：

| 教学主题 | 当年写法 | 现代写法 | 实测结论 |
| --- | --- | --- | --- |
| 成员默认值 | 构造重载铺满各组合 | 类内默认成员初始化 `int r = 1.0;`（C++11） | 🔧 NSDMI：c++98 ⚠️（GCC 向后放行＋警告）、c++23 ✅——**标准年≠编译器放行年**，VC6 时代真不行 |
| 禁止拷贝 | 声明 `private` 拷贝构造不实现 | `T(const T&) = delete;`（C++11） | 🔧 `=delete`：c++98 ⚠️、c++23 ✅；private-未定义是**运行时**才暴露的防御，`=delete` 前移到编译期且对友元也生效——教学应双讲 |
| 资源成员 | 裸指针+手写析构释放 | `std::unique_ptr` 成员＋零法则（C++11） | 🔧 `std::unique_ptr`：c++98 ❌（"does not name a template type"）、c++23 ✅；含 `unique_ptr` 成员的类**自动**不可拷贝——三法则被「资源即成员」蒸发了 |
| 显式单参构造 | 不强调 `explicit`（98 教学通病） | 单参构造一律 `explicit` | 双标准语法均 ✅——但隐式转换事故（`Circle c = 5;`）是两代编译器都不管的语义坑，教材 ⚠️ 未设专节（目录无 explicit），自学必补 |
| const 正确性 | `const` 成员函数（98 原生） | 同左＋`constexpr` 成员（C++11） | ✅✅/constexpr ❌→✅；const 是本章**永不过时**的硬核 |
| 对象数组初始化 | `T arr[3];` 要求默认构造 | `std::array<T,3>`/`vector<T>(3, init)`＋列表初始化 | 🔧 `vector{a,b,c}` 列表式：c++98 ❌、c++23 ✅（02 章同测结论复用） |

**滞后点小结**：①三法则的现代升级（五法则：+移动构造/移动赋值）教材口径必然缺席，本目录在
[../Effective_Modern_C++/05-右值移动完美转发.md](../Effective_Modern_C++/05-右值移动完美转发.md) 补完；
②成员初始化列表顺序=声明顺序（非列表顺序）的 `-Wreorder` 陷阱，多数 98 教材不点，自学须知（文档口径，

## 易错点与迷思速查

- 构造无返回类型：`Circle()` 写成 `int Circle()` 就退化成了**同名成员函数**——对象出生时它不会自动调。
- 默认构造依赖：对象数组 `Circle cs[3];` 要求 `Circle()` 存在——一旦你写了带参构造，编译器就不再送默认构造。
- 深浅拷贝双雷：①不写拷贝构造→默认浅拷→double free；②写了拷贝构造忘写赋值 `operator=`——
  两半都要落锁（三法则的 98 表述 ⚠️ 名词非书中原语）。
- 析构不成对：`new T[n]` 配 `delete[]`、单对象配 `delete`；构造函数里抛异常→已构造成员的析构纪律 ⚠️ 教材是否触及未核实。
- const 成员函数误用：非 const 对象可调用 const 成员，反之不可；在 const 函数里改成员（除非 `mutable`）编译即拒——
  这是**特性**不是障碍。
- 静态成员链接仪式：类内声明、类外定义（不写 static）——98 忘定义是链接错误而非编译错误，6.1 的知识在此回收。
- 友元迷思：「友元破坏封装所以邪恶」——它破坏的是**对外**封装、服务的是**运算符/流接口**的内聚；
  `<<` 不能做成员函数（左操作数是流），友元是 98 的正解之一（另一解：非成员非友元+公共接口）。
- this 迷思：成员函数「访问对象数据」的真相是编译器偷偷传 `T* const this`——7.3.3 编译原理节与 5.4 栈帧的会师点。
