## 核心概念速览（中英对照）

- **数组** — array：同类型元素的连续存储；下标从 0 源于「偏移即指针算术」
- **数组退化** — array-to-pointer decay：数组在多数表达式中化为指向首元素的指针，长度信息丢失
- **指针运算** — pointer arithmetic：`p+1` 前进的是**一个元素**而非一个字节（§4.2.1）
- **动态内存分配** — dynamic allocation：`new T[n]`/`delete[]`（§4.2.2），自由存储与数组的结合部
- **指针数组** — array of pointers：§4.2.3，元素全是指针的数组（与「数组指针」相对）
- **字符与转义序列** — character literal / escape sequence：`'a'`、`'\n'`、`'\0'`（§4.3.1）
- **空字符结尾字符串** — null-terminated string：`char[]` + 末尾 `\0`（§4.4.2），C 系文字处理的全部麻烦与全部自由之源
- **文字处理算法** — string algorithms：§4.4.3，统计/反转/查找/回文一类（⚠️ 题型按节名推定）
- **字符编码标准** — character encoding：§4.5.1，ASCII→扩展 ASCII→中文多字节码的历史线
- **ANSI 编码 vs Unicode** — ANSI code page (GBK 等) vs Unicode (UTF-16/UTF-8)：§4.5.2/4.5.3 的双轨中文处理程序
- **程序设计方法简介** — programming methodology（§4.6，2 版新增）：面向过程→面向对象的过渡导言，为 5 章起势

## 动机：一章同时解决「多数据」与「文本」两件事

数组讲「同型批量」，文字处理讲「最重要的批量实例——字符序列」，中文编码则是**中国教材的特色战场**：
按字节还是按字符处理，在 GBK 里「一个汉字可能撞 ASCII 码值」，直接把 §4.2 的指针算术变成生死题。
阚书把它放进第 4 章而非附录，等于宣布：**编码不是边角料，是数据表示核心课**。这也是它比
一般入门书「指针讲得实」的原因——2 版补 4.6 后，本章成为全书方法论枢纽。

## 机制拆解（按已核实小节）

- **§4.1 数组**：定义时长度须为常量表达式（98 口径）；初始化列表；越界无检查——「自己数边界」是 98 教学契约。
  常用处理算法（求和/最值/遍历骨架）在此首次规模化使用 3 章循环。
- **§4.2 指针与数组**：`a[i] == *(a+i)` 的等价定义；指针差值类型 `ptrdiff_t` 语境；
  `new int[m]` 运行期变长数组（98 正统做法，对比 C99 VLA——C++ 从未采纳 ⚠️ 文档口径）；
  释放必须配对 `delete[]`，写成 `delete` 是未定义行为。
- **§4.3 字符类型**：`char` 即小整数——参与算术、比较、映射表的技术前提；转义与多字符常量。
- **§4.4 字符数组与字符串**：`char s[] = "abc";` 隐含 `\0`；strlen/strcpy/strcat 族的使用与手动重实现。
- **§4.5 中文处理**：ANSI 码页下**按双字节探测**（首字节高位为 1 则吞两字节 ⚠️ 通行做法推定）数汉字/截断；
  Windows「W 系 API + `wchar_t`（UTF-16）」路线；两版此处口径基于 VC6/Win32 双字节char时代（2016/2017 的 Windows 现状）。
- **§4.6 方法简介（2 版）**：结构化「自顶向下逐步求精」到 OOP「对象交互」的叙事桥（⚠️ 正文未读，按节名概括）。

## 权衡与相邻概念对比

- **数组 vs 指针**：数组是存储，指针是值；数组拷贝=逐元素，指针拷贝=复制地址；`sizeof(数组)`≠`sizeof(指针)`
  ——4.1/4.2 的边界正是 5.6「函数间传数组」退化问题的前置。
- **指针数组 vs 数组指针**：`int* a[10]` 与 `int (*p)[10]` 的声明语法对比，本章传统保留节目。
- **静态数组 vs 动态分配**：栈上快且自动回收但尺寸编译期定/容量小；`new` 灵活但要记账——
  教材明摆着让学生先疼一遍，10 章 vector 与智能指针才有解药（现代工业：几乎从不裸 `new[]`）。
- **char[] vs string 类**：本章用 char[] 手工管理，9.4 才交 `std::string`——**故意延迟**，让手工之痛成为库之价值的论据。

## 最新演进与工业实践

三态实测（g++ 15.2；✅/❌/⚠️ 同 01 章口径）：

| 教学主题 | 当年写法 | 现代写法 | 实测结论 |
| --- | --- | --- | --- |
| 定长缓冲 | `char buf[4]; strcpy(buf, src);` | `std::string`/`std::span` 边界自理 | 🔧 小缓冲 `strcpy` 溢出在 `-Wall -O1` 下 **c++98 与 c++23 都静默通过**——编译器不兜底，「能过编译」与「安全」无关；现代防线是 ASan/静态分析（文档口径） |
| 只读字符串参数 | `void f(const char* s)` | `void f(std::string_view s)`（C++17） | 🔧 `std::string_view`/`std::span`：c++98 ❌、c++23 ✅ |
| 宽字符 Unicode | `wchar_t`/`std::wstring`/`wofstream`（§4.5.3 路线） | UTF-8 为默认执行字符集；`char8_t`（C++20，[wg21.link/p0482r6](https://wg21.link/p0482r6) 实测 302 可达） | 🔧 宽字符三件套 c++98 ✅/c++23 ✅（语法未死，但 Win 专属感在 Linux 语境尴尬）；`const char8_t* p = u8"…"` c++98 ❌、c++23 ✅；`std::u8view` 在 GCC 15.2 的 gnu++23 下 **FAIL**（u8string_view 为 C++23 提案 P2530 系列，libstdc++ 未落地 ⚠️ 文档口径） |
| 变长批量 | `int* a = new int[n]; … delete[] a;` | `std::vector<int> a(n);`（RAII 自动） | 两种写法双标准均 ✅——区别在**异常/早退路径上裸 new 会漏**（教材未讲异常时的合理妥协，10 章回看） |
| 中文按字数截断 | GBK 双字节探测循环 | UTF-8 序列边界解析（`std::ranges` 或 ICU 类库） | 无法用编译对照衡量；结论：§4.5 的**「字节≠字符」世界观完全不过时**，只是码页战争换成了 UTF-8 一统后的变体问题 |
| 数组字面量初始化 | `int a[] = {1,2,3};` | 同左＋`std::array<int,3>{1,2,3}`（C++11） | 🔧 `std::array`：c++98 ❌、c++23 ✅；C 数组写法永不过期但丢失长度/拷贝语义 |

**教材滞后点小结**：①全章无 `std::string`（延迟到 9 章是编排选择，自学时建议 4.4 学完立刻并读 9.4）；
②`new[]/delete[]` 未预告异常安全问题；③GBK 码页语境在 2020s 的 Windows（UTF-8 Beta 码页）与跨平台语境下需要重学为 UTF-8。

## 易错点与迷思速查

- 越界无报错：`a[100] = 1;`（数组只有 10 项）两标准都放行——98 契约是「自己数边界」，现代契约才轮到
  `at()`/span/ASan；把「编译过了」当「没越界」是本章第一迷思（本目录实测：连 `-Wall -O1` 都不告警）。
- `sizeof` 陷阱：函数形参 `void f(int a[])` 里 `sizeof(a)` 是指针宽不是数组宽——退化规则的照妖镜。
- `new int[n]` 配 `delete[]`：写成 `delete` 是 UB；数组元素含对象时漏 `[]` 等于只析构一个 ⚠️ 后果按 7 章回收理解。
- 字符串三坑：漏 `\0` 手放、`strcpy` 目标不够大、`==` 比 char[] 比的是地址——三条全是 9.4 string 的存在理由。
- 指针数组 vs 数组指针：`int* p[4]` 与 `int (*p)[4]` 一字之差；口诀「[] 优先级高于 *，括号改变一切」。
- GBK 截断半字节：按 byte 数「截 5 个汉字」的循环若不看高位，会把双字节字劈成两个乱码——§4.5.2 的实战核心。
- 迷思：「Unicode 就是双字节」——UTF-16 是双**码元**且代理对占两格、UTF-8 变长；教材语境是 Windows `wchar_t`
  的 UTF-16，现代语境是 UTF-8，读时要换坐标系。

## 编码源流一分钟卡片（§4.5 的前史后史）

- 1960s ASCII（7 位）→ 各国扩展 8 位码页（西文 Latin-1、中文 GB2312→GBK→GB18030）。
- 1991 Unicode 码点表发布；实现编码 UTF-8（1992， Unix 系）/UTF-16（Windows NT 系）/UTF-32 三分。
- 教材年代（2016/17）：Windows 宽 API=UTF-16、控制台默认 GBK 码页——所以书讲「ANSI/Unicode 双轨」是**当时**的真实世界。
- 2026 现状：UTF-8 事实一统（Web/源码/文件默认；Windows 10+ 提供 UTF-8 码页 Beta 与机器级选项）——
  双轨叙事读法要从「并存战争」更新为「UTF-8 内部表示 vs 遗留码页互转」。
