## 核心概念速览（中英对照）

- **流** — stream：字节/字符的顺序抽象；把设备、文件、内存串成同一套 `>>` `<<` 接口
- **流类库** — iostream library（§9.1）：`ios` 基类+`istream`/`ostream` 派生的类图——**教材首次用真实类库复盘 7/8 章机制**
- **标准输入输出对象** — `cin`/`cout`（§9.2）：`istream`/`ostream` 的预置对象（不是类型，是实例）
- **提取/插入运算符** — `>>` / `<<`：被重载成流语义的成员/非成员运算符（7.7 友元的正式兑现）
- **格式化输出** — manipulators（`setw`/`setfill`/`hex`…）：链式插入的状态机式排版
- **文件输出流** — `ofstream`（§9.3.2）：关联磁盘文件的 ostream；打开模式 `ios::out|app|binary`
- **文件输入流** — `ifstream`（§9.3.3）：读端；`while (in >> x)` 以流对象布尔语义控循环 ⚠️ 惯用法推定
- **双向文件流** — `fstream`（§9.3.4）：读写同身
- **字符串类** — `std::string`（§9.4）：动态长度+值语义的字符容器——4 章 char[] 之苦的总解药
- **Unicode 流** — wide streams（§9.5）：`wcout`/`wofstream`+`wchar_t`（Windows UTF-16 语境）
- **文件与文本/二进制模式** — text vs binary mode：换行翻译与字节原样之差

## 动机：为什么流单独成章、且放在 OOP 之后

2/7 章两处 `cout <<` 都是「先用后证」；到学生学完类与继承（7/8 章），第 9 章才揭盖：
**`operator<<` 是重载的非成员（友元）函数、`ios` 类图是组合+继承+虚函数的合成示范**——
本章实为全书机制部分的「期末实践题」，也是 10 章模板（标准库的另一半）前的类库侧收官。
§9.5 收编 Unicode 流，呼应 4.5 的中文处理双轨——教材的编码叙事到此闭环。

## 机制拆解（按 1 版已核实小节）

- **§9.1 类图**：`ios` ← `istream`/`ostream` ← `ifstream`/`ofstream`/`fstream`；`cin`/`cout`/`cerr` 是全局对象。
  流的可组合性（`<<` 返回 `ostream&` 实现链式）是 8 章「返回自身引用」惯用法的标准案例。
- **§9.2 标准 I/O**：`>>` 跳过空白、按类型解析、失败置状态位；`cout` 的格式化三层次——
  成员函数（`width()`）、操纵符（`setw()`）、手工填充（`setfill('*')`）。
- **§9.3 文件 I/O**：构造即开/`open()` 后开、关闭时机（析构自动关——RAII 的教学首发点）；
  文本逐行 `getline`；二进制 `read()/write()` 配合 4 章的结构体打包读写（教材常见串联 ⚠️ 按主题推定）。
- **§9.4 string**：`length/substr/find/+=/compare`；`cin >> string` 遇空白断 vs `getline(cin, s)` 整行——
  与 char[] 对照：赋值即深拷贝、自动扩容、`= 0` 是事故（空指针构造 UB）。
- **§9.5 Unicode 流**：`wchar_t`/宽字符串 `L"…"`/`wcout`；VC6/Windows 语境下 `wchar_t`=UTF-16，
  4 章的码页问题在流侧的对应物是宽窄两套 API（`_T()` 宏传统 ⚠️ 是否讲至宏级未核实）。

## 权衡与相邻概念对比

- **流 vs `printf/scanf`**：类型安全（编译期重载决议）+可扩展（自定义类型的 `<<`）vs 格式串运行期解析；
  代价是啰嗦与格式化粒度弱——现代由 `std::format` 终结争论（实测见下）。
- **`endl` vs `"\n"`**：endl 附 flush，循环里逐行 endl 有可观开销（文档口径）；教材两用法并存。
- **string vs char[]**：除非与 C 库边界相接（`c_str()`），无理由手选后者；教材把 string 放 9.4 而非 4 章，
  是「先痛后药」的教学法，自学建议 4.4 与 9.4 连读。
- **文件流 vs C 文件 API（`FILE*`）**：流有状态对象+异常位+RAII；`FILE*`+`fopen` 仍是 C 互操作现实——两制式在
  真实项目并存，教材只讲流侧（98 教学口径合理）。

## 最新演进与工业实践

三态实测（g++ 15.2；✅/❌/⚠️ 同 01 章口径；自写示意 🔧）：

| 教学主题 | 当年写法 | 现代写法 | 实测结论 |
| --- | --- | --- | --- |
| 基本流读写 | `cin >> x; cout << setw(8) << setfill('*') << v;` | 原样有效 | 🔧 `<iostream>`+`<iomanip>` 经典用法 **c++98/c++23 双标准通过**——本章主体是全书「保鲜度」最高的机制章 |
| 文本行读取 | `char line[256]; cin.getline(...)` | `std::string line; std::getline(cin, line);` | 两标准均 ✅；string 版免除截断风险 |
| 数值排版 | `<<` 操纵符串 | `std::format("{:>8}", v)`（C++20，[wg21.link/p0645r10](https://wg21.link/p0645r10) 实测 302 可达） | 🔧 `std::format`：c++98 ❌（"only available from C++20"）、c++23 ✅——printf 风格与 iostream 风格的百年拉锯由它收口 |
| 文件存在/路径 | `ifstream f(name); if (!f)` 试探 | `std::filesystem::exists/path`（C++17） | 🔧 `<filesystem>`：c++98 ❌、c++23 ✅（实测含 `path / "d.txt"` 拼接运算符）；文件名跨平台语义自此有了标准答案 |
| 宽流 | `wcout << L"中文"` | 执行字符集转 UTF-8 为主线；宽字符退居 Win32 边界 | 🔧 宽流双标准 ✅✅——语法没死，但 2020s 教学应补 UTF-8 默认化趋势（04 章 char8_t 实测互见） |
| 错误处理 | 检查流状态位 `fail()`/`clear()` | 同左＋`exceptions()` 让流抛异常（衔接 10 章） | 双标准 ✅；教材 ⚠️ 是否讲 `clear()` 复位细节未核实 |

**滞后点小结**：①无 `std::filesystem` 时代，列目录/探测路径全靠平台 API——9.3 的工程边界实际是 17 章作业；
②`strstream`（若 9 章提及 ⚠️ 未知）早被 `sstream`（C++98 即有！）取代——「98 就有的现代工具没讲」是本年代教材通病；
③二进制读入结构体的字节序/对齐可移植性问题，教材口径不展开（现代答案：显式逐字段序列化）。

## 易错点与迷思速查

- `operator<<` 返回类型：必须 `ostream&` 才接得住链式；返回 `void` 的「作业版」重载一拼 `a << b << c` 就断——
  9.1 类图讲可组合性的真正考点。
- `cin >>` 与 `getline` 混用：前者留下换行符，后者空读一行——中间要 `cin.ignore()`（⚠️ 教材是否给解药未核实，事故必遇）。
- 文件流忘检查打开：`ifstream f("没有.txt"); f >> x;` 静默失败——`if (!f) …` 或（现代）`f.exceptions()`。
- 读完再读的经典死循环：`while (!f.eof())` 会**多跑一轮**（eofbit 在读取失败后才置位）；
  正道是 `while (f >> x)`——以流对象布尔语义做门闩。
- 文本/二进制模式混用：Windows 下 `\r\n` 翻译让 `tellg` 字节数≠磁盘数——结构体批量读写必须 `ios::binary`。
- string 空指针事故：`std::string s = 0;`/`const char* p = nullptr; std::string s(p);` 两标准都编译通过、
  运行即 UB——4 章「`\0` 纪律」换了件马甲回来。
- 迷思：「wcout 输出宽字符=支持 Unicode」——控制台码页/字体/流缓存三方都可能截和转义；
  9.5 的理想世界在 VC6 与今天的 Windows 控制台都要打折 ⚠️（文档口径）。
