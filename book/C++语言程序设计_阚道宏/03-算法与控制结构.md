## 核心概念速览（中英对照）

- **算法** — algorithm：有穷性/确定性/可行性三性质的操作步骤序列（教材按此三性质立论）
- **布尔类型** — `bool`：`true`/`false` 两值类型；阚书把布尔单列一节再进控制结构，编排少见
- **关系/逻辑运算符** — relational / logical operators：`== != < <= > >=` 与 `&& || !`，短路求值（short-circuit）
- **选择结构** — selection：`if-else` 与 `switch-case`（§3.3.1/3.3.2），后者受控于「整型常量表达式+穿透」纪律
- **循环结构** — iteration：`while` / `do-while` / `for`（§3.4.1–3.4.3）＋ `break`/`continue`（§3.4.4）
- **计算复杂度** — computational complexity：§3.5.1，语句频度的增长阶记号（O 记号，教学口径不区分紧界）
- **内存占用量** — memory footprint：§3.5.2，与时间并列的第二评价轴——教材在此埋下 4 章数组与 5 章存储的动机
- **算法设计举例** — worked examples：§3.5.3，累加/递推/枚举/迭代类问题（⚠️ 具体题型未核实，按节名概括）

## 动机：为什么这是「方法论」的第一块基石

阚书的全书主轴是程序设计方法（结构化→OOP），而结构化方法的前提是
**Bohm–Jacopini 定理的工程化表述：任何流程都能用顺序/选择/循环三结构组合**。
本章把三结构与布尔代数绑定（先有能判真伪的表达式，才有可控的结构），
再用 §3.5 把「写完」升格为「写好」（时间+空间双评价）——这三段式直接为
5 章模块四大要素、8 章代码重用提供了评价语言。

## 机制拆解（按已核实小节）

- **§3.1 算法**：算法五种描述方式中的伪码/流程图传统；「程序是算法的用某语言书写」的等式。
- **§3.2 布尔类型**：关系表达式产出 `bool`；`&& || !` 的短路语义——教材用它讲安全判空的经典形态
  （`p != 0 && *p > 0` ⚠️ 示意，非书中原文）。C++98 语境下 `bool` 与整型的隐式转换边界亦在此交代。
- **§3.3 选择**：`if-else` 嵌套与悬挂 else；`switch` 的 case 常量标签、`break` 防穿透、`default` 兜底。
- **§3.4 循环**：先测后验（while）/先验后测（do-while）/计数三件套（for 初始化;条件;迭代）。
  `for(;;)` 与 `while(1)` 的主循环惯用法；break/continue 的「逃生舱口」定位。
- **§3.5 评价**：以语句执行次数估时间阶（O(1)/O(n)/O(n²) 的教学级定义）；空间上「原地 vs 复制」的取舍；
  举例多半是累加、阶乘、斐波那契、素数筛一类（⚠️ 推定，未读书中正文）。

## 权衡与相邻概念对比

- **`switch` vs  elseif 链**：离散整型值+分支多→`switch`（跳转表倾向）；区间/布尔条件→`if`。
  现代口径补充：`switch` 的漏 `break` 类 bug 可由 `-Wimplicit-fallthrough` 或 C++17 `[[fallthrough]]` 显式化治住（实测见下）。
- **短路求值 vs 按位运算**：`&&`/`||` 与 `&`/`|` 的误用在布尔语境里语义不同（无短路），是选择/循环的高发改错题点 ⚠️ 教学推断。
- **`do-while` 的当代地位**：菜单循环/至少执行一次的读取是其正统场景；工业代码因「先执行后审查」不利评审而少用——
  教材保留它更多是完备性。
- **三结构 vs `goto`**：本章隐含论敌是 goto；结构化=消除跳转入/出口。下游对照见 5.1 节与 [../C++编程惯用法/11-全书综审与方法论补编.md](../C++编程惯用法/11-全书综审与方法论补编.md)（1993 年同一论题的工业证词）。

## 最新演进与工业实践

三态实测（g++ 15.2；✅/❌/⚠️ 同 01 章口径）：

| 教学主题 | 当年写法 | 现代写法 | 实测结论 |
| --- | --- | --- | --- |
| 遍历容器 | `for (int i=0;i<n;i++) v[i]…` | 范围 for `for (int& x : v)`（C++11） | 🔧 范围 for：c++98 ❌、gnu++98 ⚠️（GCC 扩展放行＋警告）、c++23 ✅——「旧标准能编」是编译器宽容，不是年代合法 |
| 条件内定义 | 先声明后赋值再用 | `if (int x = f(); x > 0)`（C++17，[wg21.link/p0305r1](https://wg21.link/p0305r1) 实测 302 可达） | 🔧 if-init：c++98 ⚠️、gnu++98 ⚠️、c++23 ✅（同样被 GCC 向后放行，判年代靠标准） |
| 显式穿透 | `// no break 注释` | `[[fallthrough]];`（C++17 属性） | 🔧 与 if-init 同测：gnu++98 ⚠️ 接受；现代编译器对**未标注**的穿透默认告警（`-Wimplicit-fallthrough` 文档口径） |
| 布尔类型 | `bool`/`true`/`false` | 同左；`if (ptr)` 惯用法稳定 | ✅✅ 两标准无差异——本章主体是**不过时的核心**，学它不亏 |
| 算法库 | 手写选择/冒泡排序 | `std::sort`（算法头，98 即有；C++20 起 `std::ranges::sort`） | 🔧 `std::sort` 双标准 ✅；`ranges::sort` c++98 ❌/c++23 ✅。教学手写排序的价值在复杂度直观，不在生产可用 |
| 循环并行 | 手写计数器 | 并行策略属执行模型话题（教材语境没有） | 不展开——入门阶段先保证单线程正确 |

**现代教学运动对照**：isocpp FAQ 对「为什么不用 goto」「循环何时用哪种」的建议与本章结论一致；
cppreference 的 control flow 页可作本章术语的英文对照表。复杂度一节在教材 98 口径里不碰
缓存与分支预测；工业级性能直觉（O 记号相同、常数差百倍）留给
[../提高C++性能的编程技术.md](../提高C++性能的编程技术.md) 一类书补位。
