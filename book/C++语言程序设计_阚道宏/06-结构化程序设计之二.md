## 核心概念速览（中英对照）

- **编译单元** — translation unit：一个 `.cpp` + 其预处理包络 = 独立编译产物；多文件结构的原子
- **文件包含** — `#include`：文本级复制；`<>` 查系统路径、`""` 先查当前目录
- **头文件防护** — include guard：`#ifndef X/#define X/#endif` 防重复包含
- **宏定义** — macro (`#define`)：对象宏与函数宏；带参宏的括号纪律
- **条件编译** — conditional compilation (`#ifdef/#if/#endif`)：一套源码多平台/多配置的 98 答案
- **默认形参值** — default arguments：调用点缺省补全；声明处指定、只允许尾部连续缺省
- **重载函数** — overloaded functions：同名词表按实参类型/个数分派，编译期决议
- **内联函数** — inline function：向编译器提出的展开建议，替代带参宏的类型安全方案
- **递归函数** — recursion：自相似分解＋终止条件；§6.3.5 与 3 章循环互为孪生
- **命名空间** — namespace：具名作用域容器；C 库头进全局、C++ 头进 `std` 的历史由来（§6.4.2）
- **类型定义** — `typedef`：给类型起别名（§6.5.1），改善声明可读性
- **枚举/联合体/结构体** — enum / union / struct：自定义聚合类型三件套（§6.5.2–6.5.4）
- **Windows GUI 编程** — Win32 GUI（§6.6.1，2 版新增）：窗口过程回调式编程初体验（⚠️ 按节名概括）

## 机制拆解（按已核实小节）

- **§6.1 多文件**：分离编译→链接器汇合；`static` 函数/变量把符号锁在本编译单元（§6.1.2，
  文件级私有 = 98 的正统封装前身）；头文件放声明、源文件放定义（§6.1.3）。
- **§6.2 预处理**：包含展开、宏替换、条件编译三连；宏无类型无作用域之害与 `inline`/`const` 的解法配对讲解。
- **§6.3 特殊函数**：默认参（调用点展开）→重载（决议规则：完全匹配>提升>转换）→内联（Debug 不展开、
  Release 才可能）→`main(argc, argv)`（§6.3.4，命令行参数）→递归（§6.3.5 汉诺塔/阶乘类经典 ⚠️ 推定）。
- **§6.4 系统函数**：C 标准库函数（§6.4.1）与 C++ 库（§6.4.3）并陈，命名空间（§6.4.2）解释

- **§6.5 自定义类型**：`typedef` 简化声明；`enum` 整型常量组；`union` 共享存储省空间（与 struct 对比）；
  `struct` 数据打包——末尾直连 7 章「结构体+函数=类」的叙事。
- **§6.6（2 版）**：先给 Windows GUI 应用实例（§6.6.1 ⚠️ 正文未读：按节名与教材平台应为 Win32 SDK 消息循环），

## 权衡与相邻概念对比

- **宏 vs 内联/const**：函数宏求值次数/优先级三坑（副作用、`a&b` 优先级、类型不加检查）；
  98 的正解是「能 inline 不宏、能 const 不 define」——教材立场与之一致（6.3.3 单列内联即宣言）。
- **`typedef` vs 继承式复用**：typedef 只改名不换类型（重载决议视同原类型）；对比 7 章 typedef 成员别名场景。
- **`union` 的地位**：省空间的显式重叠，但「当前活的是哪个成员」全靠程序自己记账——
  现代由带活动状态跟踪的 `std::variant`（C++17）接管；教学保留 union 是因为它是理解对象内存重叠的最小模型。
- **头文件 vs 模块（历史对照）**：`#include` 的重复解析与脆弱性催生了 C++20 modules——
  本目录不展开（教材口径外），在 10 章演进节与 [../C++20模板元编程.md](../C++20模板元编程.md) 有跳转点。

## 最新演进与工业实践

三态实测（g++ 15.2；✅/❌/⚠️ 同 01 章口径）：

| 教学主题 | 当年写法 | 现代写法 | 实测结论 |
| --- | --- | --- | --- |
| 符号常量宏 | `#define MAX 100` | `constexpr int MAX = 100;` | 🔧 宏双标准 ✅；`constexpr` c++98 ❌/c++23 ✅——「宏退居条件编译与日志胶水」是 20 年最大口径变化 |
| 头文件防护 | `#ifndef/#define/#endif` | 同左＋`#pragma once`（非标准但各编译器支持） | 🔧 `#pragma once` 在 g++ 两标准 ✅（主文件使用仅告警）；跨工具链稳妥仍是 include guard |
| 类型别名 | `typedef int* IntP;` | `using IntP = int*;`（C++11）＋别名模板 | 🔧 `using` 别名：c++98 ❌、c++23 ✅；`typedef` ✅✅ 永动 |
| 枚举 | `enum Color {RED};` 值泄漏到外围 | `enum class Color : uint8_t {Red};`（C++11） | 🔧 域枚举：c++98 ❌、gnu++98 ❌、c++23 ✅——**强类型+指定底数**双升级；旧 enum 现代仍合法（`-Wuse-old-…` 之类偏好提醒是 lint 口径） |
| 编译期断言 | 无数（靠运行时 if） | `static_assert(…, "…")`（C++11） | 🔧 c++98 ❌、c++23 ✅——预处理条件编译的「类型版」补位 |
| 默认参+重载 | 98 原生语法 | 语法原样；新增陷阱维度=与 `override`/完美转发组合 | ✅✅ 双标准通过（教材 ⚠️ 未讲「虚函数默认参不参与覆写」之坑，见 08 章补位） |
| Win32 GUI（§6.6.1） | `WNDCLASS`/窗口过程回调 | Win32 仍是一等公民；跨平台交给 Qt/WinUI 层 | 无法编译对照（需 Windows SDK 头，MinGW 语境下样例 ⚠️ 未实测）；结论按「回调=函数指针的工业级应用」回连 5.4.3 |

**滞后点小结**：①`using namespace std;` 在教学代码里省字，工业口径限于 `.cpp` 且禁入头文件（文档口径）；
②多文件工程在 VC6 时代靠 `.dsp` 手工维护，今天是 CMake/IDE 生成——概念（声明/定义/链接）不变，仪式全变；
③`char* argv[]` 的命令行处理现代由参数解析库接管——机制仍有效。

## 易错点与迷思速查

- 宏的括号纪律：`#define SQR(x) x*x` 遇 `SQR(a+b)` 与 `SQR(i++)` 双翻车——正解 `#define SQR(x) ((x)*(x))`
  仍不如 `inline`；副作用问题括号救不了。
- 头文件循环包含：a.h↔b.h 互相 include，防护宏各自有效但整体白屏——前向声明（→7 章 8.2.5 回收）与
  「依赖单向化」才是结构解。
- 默认参三规矩：只能在声明处给、只能从右往左连续缺省、后文不得重复给同参默认值——违反其一必报错，
  教材习题的高频改错点 ⚠️ 按主题推定。
- 重载二义：`f(int)` 与 `f(double)` 遇 `f(1.0f)`、`f(0)` 遇 `f(int)`/`f(bool)`——决议阶梯（完全匹配>提升>转换）
  背不熟就会在练习里撞墙。
- 内联迷思：`inline` 是**建议**不是命令；类内定义隐式 inline；递归函数名义 inline 实际多半不展——
  它是链接语义（ODR 豁免）与优化提示的混合体，98 教材普遍讲糊 ⚠️ 本目录补刀。
- `static` 一词三义：函数内静态局部（生存期）、文件级静态（内部链接）、7 章类静态成员（共享）——
  6.1.2 只涉及前两义，读 7 章前先自查别串线。
- typedef 读法：从变量名向右圈读；`typedef int* P; P a, b;` 两个都是指针——这正是它相对 `#define int* P` 的存在理由。
