## 核心概念速览（中英对照）

- **代码重用** — code reuse（§8.1）：结构化靠函数库重用「操作」，OOP 靠继承/组合重用「设计」——教材的重用两级论
- **类的组合** — composition（§8.2）：成员是别的类的对象；「has-a」关系的语法化
- **前向引用声明** — forward declaration（§8.2.5）：`class B;` 破循环依赖——6 章头文件问题的类版
- **派生类/基类** — derived / base class（§8.3）：`: public Base` 复用并扩展；「is-a」的语法化
- **三种继承权限** — public/protected/private inheritance（§8.3.3）：一张 3×3 可见性矩阵；`protected` 专为派生而生
- **派生对象的构造与析构** — construction order（§8.3.4）：基先派后构造、派先基后析构
- **运行时多态** — runtime polymorphism（§8.4.2）：基类指针/引用指向派生对象，调用按**对象真实类型**分派
- **虚函数** — virtual function（§8.4.3）：`virtual` 开启动态分派；vtable/vptr 的教材版叙述（7 章编译原理的兑现）
- **抽象类** — abstract class（§8.4.4）：含纯虚函数 `= 0`，不可实例化——接口之种
- **运算符重载** — operator overloading（§8.4.1）：编译期多态的另一副面孔（与 §8.4.3 对照教学）
- **菱形继承** — diamond inheritance（§8.5.2 重复继承）：两份基类子对象→二义与浪费
- **虚基类** — virtual base class（§8.5.3）：`virtual public Base` 合二为一；构造责任上收最派生类

## 动机：多态是本章存在的唯一理由

组合（8.2）与继承（8.3）都能重用代码，但只有**虚函数**（8.4）能让「同一调用语句在不同对象上表现不同」，
从而写出**对扩展开放**的程序：新增派生类不改使用代码。8.5 反过来摊开多继承的账单（重名/重复继承/虚基类）——
本章的叙事弧是「能力→机制→代价」，阚书把多继承单列「讨论」而非「应用」，立场已经是防守的。

## 机制拆解（按 1 版已核实小节）

- **§8.1 重用对比**：函数库重用要「找到/改造可调用单位」，类库重用连数据结构带操作打包——为 9/10 章标准库铺动机。
- **§8.2 组合**：组合对象构造=成员对象逐个构造（声明顺序）；§8.2.4「类的聚合」处理数组/含对象的对象 ⚠️ 名词按目录。
- **§8.3 继承派生**：派生类不继承构造/析构（98 口径；C++11 的 `using Base::Base;` 教材时代不存在）；
  名字查找「派生→基」逐层上溯，隐藏（hiding）与重载的区分是 §8.3.2 访问规则的核心考点。
- **§8.4 多态**：三条件（基类指针/引用、virtual、覆写）；抽象类逼派生类兑现契约；
  §8.4.1 与 §8.4.3 并置讲「同一名词两种多态」——运算符重载=编译期按类型签名选函数，虚函数=运行期按对象类型查表。
- **§8.5 多继承**：重名需作用域限定符 `B1::f()` 消歧（§8.5.1）；无虚基的菱形=两份子对象、有虚基=一份+
  构造责任上收；本目录实测对象尺寸（🔧 g++ 15.2 x64，普通成员非虚继承 `D(nonvirtual)=20B`、虚继承 `vD=40B`，
  数值随对齐/指针宽变化，量级关系稳定：**虚基类用空间与间接寻址换唯一性**）。

## 权衡与相邻概念对比

- **组合 vs 继承**：继承耦合基类实现（"is-a" 稍有偏差即错），组合保持类型独立+可换实现——
  「优先组合」在 Effective C++ item 35 成文，教材 8.2 置于 8.3 之前，编排立场一致。
- **重载 vs 覆写 vs 隐藏**：同作用域按签名=重载；跨继承层同签名同 virtual=覆写（动态分派）；
  跨层不同签名=隐藏（派生名字抹掉基类名字）——三者是 8.3/8.4 边界上的高频错题区 ⚠️ 教学推断。
- **虚函数 vs 函数指针成员**：都能定制行为；虚函数绑定在类型格子上、函数指针绑定在对象上——
  现代视角：前者是静态类型多态、后者接近 `std::function` 成员的策略模式（对照 05 章回调）。
- **多继承 vs 单继承+接口**：Java/C# 因此只给「单类继承+多接口」；C++ 保留全套但工程口径（Google Style 等）
  基本禁实现级多继承——8.5 的「讨论」姿态与工业共识同向。

## 最新演进与工业实践

三态实测（g++ 15.2；✅/❌/⚠️ 同 01 章口径；代码为本目录自写示意 🔧）：

| 教学主题 | 当年写法 | 现代写法 | 实测结论 |
| --- | --- | --- | --- |
| 覆写声明 | 裸写同名函数，对不对全靠眼神 | `override`/`final`（C++11） | 🔧 签名错位的「假覆写」在两标准**都静默编译**；实测运行时 `B* pb=new D; pb->f(1)` 打到 `B::f`（改到 `D::f` 的意图落空）。同代码加 `override` → 两标准均编译错误（"marked 'override', but does not override"）——**编译器只在你授权时代为检查** |
| 隐藏陷阱 | `void f(int, int=0)` 遮蔽基类 `f(int)` | `-Woverloaded-virtual` 告警＋always-use-override | 实测：`pb->f(1)` 调 B 版、`d.f(1)`（对象直接调）经默认参调 D 版——同一表达式两种对象路径结果不同，98 至今未变 |
| 析构多态 | 基类析构不写 virtual（省字） | 做多态基类必 `virtual ~Base()`（或 `protected` 非虚封死） | 双标准语法 ✅；`delete` 基类指针指向派生对象而基类析构非虚 = UB（文档口径，各教材一致）——本章第一大暗坑，教材 ⚠️ 是否强调未知 |
| 抽象类 | `virtual void f() = 0;` | 同左；纯虚析构也合法（需定义） | ✅✅ 语法零演化——接口思想直贯 Java/C# 的 `interface` |
| 继承规格 | —（无对应工具） | `final` 类/函数封死继承树；编译器去虚化 | 🔧 `final`：gnu++98 ⚠️（扩展放行＋警告）、c++23 ✅；配合 LTO/whole-program 可把虚调用变直调（详见 [../C++新经典/04-多重继承下的虚函数表.md](../C++新经典/04-多重继承下的虚函数表.md) 实测） |
| 对象布局 | 「对象只存数据」一笔带过 | 直接读 ABI 文档/vs 调试器 | 🔧 本目录菱形尺寸实测（上文）；Itanium/MSVC 布局差异深读见 [../深度探索C++对象模型/08-专题-现代编译器视角Itanium与MSVC.md](../深度探索C++对象模型/08-专题-现代编译器视角Itanium与MSVC.md) |

**滞后点小结**：①`override/final` 缺席是 98 教材的结构性局限——本章所有「假覆写」例题在 2026 年的正确姿势
是**默认写 override**；②无移动语义时代「继承+资源管理」的复杂度被低估（现代零法则建议：**多态基类持
智能指针成员**）；③CRTP/策略模式等替代静态多态的路径教材口径不可达，留给
[../C++模板元编程/00-总览与阅读地图.md](../C++模板元编程/00-总览与阅读地图.md) 与 [../C++20设计模式.md](../C++20设计模式.md)。

## 易错点与迷思速查

- 忘了 virtual 的「覆写」：签名对了、`virtual` 漏了→静态绑定，基类指针调用打到基类版本——
  本目录实测的 `B::f` vs `D::f` 就是这个事故的复现器；现代解药 always-override。
- 基类析构非虚：`delete` 基类指针销毁派生对象→UB、派生资源漏放——多态基类的第一军规（文档口径）。
- 构造/析构里调虚函数：不会多态到派生版本（对象还没/已经不完整）——教材 ⚠️ 是否点破未核实，务必自补。
- 上转型随便、下转型危险：`Base* pb = new Derived;` 合法；`Derived* pd = pb;` 编译过但类型不符即事故——
  `dynamic_cast` 是 98 的正解（RTTI 底层见 Lippman 第 4 章/新经典 07 卷）。
- 私有继承伪装 is-a：`class D : private B` 实为「用 B 实现」且断多态通道——这种场合请用成员（组合）。
- 菱形二义：`d.B::x` 限定符是止血带，虚基类才是手术——但虚基类带来构造责任上收与尺寸/寻址开销
  （本目录实测 20B→40B）。
- 迷思：「继承=重用」——继承首先是**类型契约**（is-a 才能多态替换），代码搭便车只是副产品；
  这个错位正是 Java 时代之后「组合优先」共识的病灶。
