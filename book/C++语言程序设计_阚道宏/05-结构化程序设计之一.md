## 核心概念速览（中英对照）

- **结构化程序设计** — structured programming：自顶向下、逐步求精；函数=可命名可复用的步骤封装
- **模块四大要素** — module四要素（§5.1.3）：入口/出口、功能、接口（参数）、内部数据——教材自创的概括框架
- **团队分工开发** — team-based modular development（§5.1.2）：模块边界即人与人的协作边界，本章的「为什么要函数」
- **函数声明/定义/调用** — declaration / definition / call：原型（prototype）先行，实参形参按值结合
- **函数的执行** — function activation：栈帧（activation record）压栈弹栈——§5.4 的机器侧叙事
- **作用域** — scope：局部/全局/文件作用域；§5.3.3 用可见性管住数据
- **数据管理策略** — data management strategy：§5.3.1 分散按需传递 vs §5.3.2 集中全局共享——**本章最有方法价值的一对概念**
- **程序副本与变量** — program image vs variables（§5.4.1）：代码区/静态区/栈区三分的入门版存储模型
- **函数指针** — pointer to function（§5.4.3）：可存储的入口地址，回调机制之种
- **值/引用/指针传递** — pass by value / reference / pointer（§5.5）：三种参数结合方式与各自的读写契约

## 动机：把「写对」升级为「协作写出」

前两章默认单文件单人程序；第 5 章的问题意识换成**团队**：大程序拆零件（§5.1.2 明言「基于模块的团队分工协作开发」），
函数就是零件标准。阚书在此章显式抛出「数据怎么管」的问题（分散传参 vs 全局共享），
把作用域/存储区讲成**数据管理策略的技术底座**而非语法规则清单——这是它区别于逐条罗列语法教材的核心差异点。

## 机制拆解（按已核实小节）

- **§5.1 方法**：设计举例→分工协作→模块四要素。四要素里「接口」被提到与功能平级，为 7 章「封装」预埋。
- **§5.2 函数**：返回值+参数表+体；调用即复制实参；**声明**（原型）解决跨文件与前置引用；
  2 版新增「程序员与函数」（§5.2.6 ⚠️ 正文未读，按节名应是函数库/复用意识导言）。
- **§5.3 数据管理**：全局变量省事但制造隐式耦合（可测试性/可维护性代价）；按需传递显式但啰嗦；
  作用域与 `static` 全局（文件局部）是折中手段（`static` 细节在 6.1.2）。
- **§5.4 存储原理**：代码副本只读共享；全局/静态变量整个运行期存活；栈对象随块进出——
  **函数指针**（§5.4.3）把「代码也有地址」补上最后一块。
- **§5.5 三种传参**：值=只读副本；引用=别名直改；指针=可换可空的地址；2 版新增 §5.5.4「函数参数的设计」
  （⚠️ 按节名概括：只读入参/修改出参/返回值的选择纪律——现代教科书口径）。
- **§5.6 传数组**：形参 `int a[]` 即 `int* a`，长度须另行传递（§5.6.2 首地址视角）；
  二维数组传参必须补齐列数——退化规则（4 章）在本章兑现成约束。

## 权衡与相邻概念对比

- **全局共享 vs 参数传递**：教材给的是道德题（少用全局），工程上是**依赖显式化**问题——
  下游解法依次是：结构体打包（6.5.4）→类封装（7 章）→依赖注入（设计模式卷）。
- **引用传 vs 指针传**：都能改实参；引用契约更强（不可空、不可重指向），指针保留「可能没有对象」的语义。
  现代默认：**输出用返回值，只读大对象用 `const&`，「可空」才用裸指针**——§5.5.4 的设计直觉与之一脉。
- **返回多个值**：98 时代=引用/指针出参；现代=返回值打包（结构体/`std::pair`/tuple）优先——
  出参是当年无奈，今天多为次选（EMC++ item 论证拷贝消除后按值返回几乎免费）。
- **函数指针 vs switch 派发**：查表回调干掉一长串 if；但可读写性差，98 时代的「高级技巧」在
  现代被 `std::function`+lambda 平替（10 章与 EMC++ 6 章）。

## 最新演进与工业实践

三态实测（g++ 15.2；✅/❌/⚠️ 同 01 章口径）：

| 教学主题 | 当年写法 | 现代写法 | 实测结论 |
| --- | --- | --- | --- |
| 可空指针参数 | `f(int* p)`，调用传 `0`/`NULL` | `f(int* p)`＋`nullptr` | 🔧 `nullptr`：c++98 ❌、gnu++98 ❌、c++23 ✅——它**必须**是 C++11 产物，没有向后宽容 |
| 局部初始化 | `int a[3]; a[0]=…` | 统一初始化 `std::vector<int> v{3,1,2};` | 🔧 花括号列表初始化：c++98 ❌（「must be initialized by constructor」实测报错）、c++23 ✅ |
| 出参取结果 | `bool find(..., int& out)` | `std::optional<int> find(...)`（C++17） | 🔧 `std::optional`：c++98 ❌、c++23 ✅；「optional 可空语义 vs bool+出参」正是 §5.5.4 参数设计题的现代答案 |
| 回调 | `qsort(base,nmemb,size,cmp)` 函数指针 | lambda→`std::function`（C++11） | 🔧 裸函数指针双标准 ✅；捕获式 lambda 赋给函数指针 ❌（不可转换，两标准同报错——机制差异非年代差异） |
| 按值返回大对象 | 为避免拷贝改传引用出参 | 直接按值返回（RVO/保证拷贝消除，C++17 [wg21.link/p0135r1](https://wg21.link/p0135r1) 实测 302 可达） | 拷贝消除的 -std=gnu++14 vs 17 编译对照在本仓库 [../C++新经典/00-总览与阅读地图.md](../C++新经典/00-总览与阅读地图.md) 已实测（14 下返回禁拷贝对象失败、17 起通过），本目录引用其结论 |
| 递归/默认参 | 98 原生语法 | 语法原样保留，另得默认成员初始化器等增益 | ✅✅ 双标准通过——本章语法主体**零淘汰** |

**滞后点小结**：①全章无任何「返回值优先」论述（时代使然，98 无移动语义，按值返回大对象确实贵）；
②`static` 文件作用域在匿名命名空间（C++98 即有！）面前已过时——多数 98 教材不提匿名 namespace，本章亦然 ⚠️（目录无此小节）；
③线程话题缺席（教材口径合理，现代 `std::async`/并行算法见 [../C++并发编程实战2/00-总览与阅读地图.md](../C++并发编程实战2/00-总览与阅读地图.md) 入口）。

## 易错点与迷思速查

- 声明当定义：`int f();` 有了再 `int f(int a){}` 之前调用会错型；「先声明后定义」与「只声明不定义」的边界要画清。
- 数组形参的长度错觉：`void f(int a[10])` 里 10 是注释——长度必须另传，且函数内 `sizeof(a)` 是指针宽。
- 返回局部变量地址/引用：栈帧弹开后指针悬垂——5.4 存储原理的正确打开方式就是给这条坑配的说明书。
- 全局变量三宗罪（教材口径归纳）：耦合不可见、测试不可隔离、名字冲突——§5.3.2 的「集中管理」是让学生先体验再戒断。
- 静态局部变量：只初始化一次、存活到程序末、**98 下非线程安全**（C++11 起魔法静态才安全 ⚠️ 文档口径）——
  5.3.3/5.4.2 交界处的隐形考点。
- 函数指针语法：`int (*cmp)(int,int)` 的括号一个都不能省；调用可 `(*cmp)(a,b)` 亦可 `cmp(a,b)`——后者是正统糖。
- 迷思：「引用传参比指针快」——同一条机器路径（传地址），差异只在契约表达力，不在性能。

## 为什么函数指针没被淘汰（§5.4.3 的工业续命史）

C API 回调（qsort/Windows 消息/线程入口）至今仍是函数指针的世袭领地——因为「无捕获 lambda 可隐式转
函数指针」这一条让它在现代标准里也活得很好（本目录实测：无捕获 lambda 赋函数指针两标准语法均通过；
**有捕获**则不可转换，需 `std::function` 接管）。教材在 5.4.3 只讲语法，工业语境补一句：
函数指针=ABI 边界货币，`std::function`=堆分配的类型擦除，两者选型看**是否跨语言/跨库边界**。
