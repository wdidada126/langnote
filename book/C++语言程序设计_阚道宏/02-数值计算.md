## 核心概念速览（中英对照）

- **变量定义与访问** — variable definition / access：先声明类型再使用；访问即按类型解释存储
- **字面量** — literal：代码中的常量记号，`012`（八进制！）与 `1.5e3` 各有坑
- **常量** — constant (`const`)：只读名字；现代补 `constexpr`（编译期求值）
- **算术运算符** — arithmetic operators：`+ - * / %`，整数 `/` 截断、`%` 的符号跟随实现（C++11 起规定向零取整）
- **位运算符** — bitwise operators：`& | ^ ~ << >>`，掩码/移位/打包的教学主场
- **赋值与初始化** — assignment vs initialization：`=` 的两种身份，教材未细分处恰是现代 C++ 的改进点
- **流式输入输出** — stream I/O：`cin >>` / `cout <<`，把 I/O 当运算符重载讲（伏笔 9 章）
- **引用** — reference：对象的别名，§2.7.1 提前引入是为 5 章「引用传递」铺路
- **指针** — pointer：§2.7.2 存地址的变量；本教材在「数值计算」章就讲指针，强度高于一般入门书

## 动机：为什么「数值计算」单独成章

多数入门教材把运算符散在第二章叙述里；阚书把**算术、位、赋值、输入输出**四组操作立成一章完整的
「数据加工工具箱」，且在第 2 章就引入引用与指针——它的排序逻辑是：**先给全「处理单个数据」的武器，
再进第 3 章「组织处理步骤」（控制结构）、第 4 章「组织多个数据」（数组）**。这是按「数据→算法→组织」
的计算机口径，而非按语言特性清单。

## 机制拆解（按已核实小节）

- **§2.1 变量**：定义（分配存储）与访问（左值/右值两种角色，教材用「取值/存值」表述 ⚠️ 措辞未核实）；
  命名规则；类型决定解释方式——呼应 1 章「数据=比特+规则」。
- **§2.2 常量**：字面量、`const` 定义符号常量。VC6 时代惯用 `#define N 10`，教材倾向 `const`（2 版语境）。
- **§2.3 算术**：`/` 的整除语义、`%` 的应用（分离数位/回文判断是教材常见题型 ⚠️ 推定）、自增自减的前后置差异。
- **§2.4 位运算**：取指定位、清零、置一、左右移乘除、异或交换（三行无临时变量交换）——教学五件套。
- **§2.5 赋值**：复合赋值、赋值作为表达式及其可链式性。
- **§2.6 输入输出**：`cin >> x; cout << y;` 与提示语配合；换行 `endl` vs `"\n"`。
- **§2.7 引用与指针**：引用=必须初始化、不可改指的别名；指针=可空可换的地址变量；`&`/`*` 两种语境（取地址/解引用 vs 声明）的辨析是本章难点。

## 权衡与相邻概念对比

- **引用 vs 指针**（教材立小节的对照，也是面试常青题）：引用安全（无空引用、无算术）但能力弱；
  指针灵活但把「可空」责任推给程序员。现代口径：**默认用引用/值，需要「可重指向或可为空」才用裸指针**。
- **`const` vs `#define`**：前者进类型系统、受作用域管辖；后者只是文本替换。教材已站 `const` 一边。
- **位运算 vs 除法取模**：`x>>1`、`x&1` 曾是「快」的代名词；现代优化器会自动改写，位技巧的教学价值
  转移到**掩码语义**（协议解析、标志位）而非速度。

## 最新演进与工业实践

三态实测（g++ 15.2；✅/❌/⚠️ 同 01 章口径；临时件在仓库外 `D:\develops\tmp\cppsnippets_kan\`）：

| 教学主题 | 当年写法 | 现代写法 | 实测结论 |
| --- | --- | --- | --- |
| 声明类型 | `int i = 42;` 逐处写类型 | `auto i = 42;`（C++11） | 🔧 `auto`/`nullptr`：c++98 ❌、gnu++98 ❌（GCC 不给这俩面子）、c++23 ✅ |
| 符号常量 | `const int N = 4;` | `constexpr int N = 4;`（C++11） | 🔧 `constexpr`：c++98 ❌、c++23 ✅——`const` 当年写法**两个标准都合法**，是「不过时的好写法」典型 |
| 数字字面量 | 八进制陷阱 `012`=10 | 撇号分组 `1'000'000`（C++14） | 🔧 八进制两标准均 ✅（陷阱不因年代消失，须靠 `-Woctal-literal` 类告警/评审）；撇号 c++98 ❌、c++23 ✅ |
| 位运算 | 手写循环数 1 的个数 | `std::popcount`（C++20，[wg21.link/p0553r4](https://wg21.link/p0553r4) 实测 302 可达） | 🔧 `<bit>`/`popcount`：c++98 ❌（无此库）、c++23 ✅ |
| 交换 | 三行异或交换 | `std::swap(a,b)` | 两种写法在两个标准均 ✅；结论是**可读性问题不是标准问题**——异或交换在优化器面前无收益 |
| I/O | `cin >> x` | `cin >> x` 依旧；格式化需求交给 `std::format`（C++20） | 🔧 教材的流读写双标准 ✅✅（见 [09-流类库与文件IO.md](09-流类库与文件IO.md) 的深挖） |

**工业口径**：现代代码以初始化优先（统一初始化 `{}`）、`nullptr` 代替 `0/NULL`、位操作走 `<bit>`，
每条在 [../Effective_Modern_C++/01-类型推导.md](../Effective_Modern_C++/01-类型推导.md)（auto 规则）与
cppreference「Floating-point environment/bit manipulation」页都有出处；`%` 负数语义 C++11 起规定向零取整，
当年「-7%2 因编译器而异」的担忧已成历史（文档口径）。
