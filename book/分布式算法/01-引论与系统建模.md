## 核心精讲（教学示意，不参与构建）

### 1.1 I/O 自动机（I/O Automata）

I/O 自动机是 Lynch 与 Tuttle 提出的建模框架。一个 I/O 自动机 $A$ 由以下成分构成（教学示意）：

- $\text{states}(A)$：状态集合，含初始状态子集 $\text{start}(A)$；
- $\text{sig}(A)$：动作签名，划分为 **输入动作 $\text{in}$、输出动作 $\text{out}$、内部动作 $\text{int}$**；
- $\text{trans}(A)$：转移关系 $\to$，即 $(s, \pi, s')$ 三元组；
- **输入使能**（input-enabled）：任何状态下任何输入动作都可使能——这是 I/O 自动机区别于
  一般标记转移系统的关键，它保证环境随时可以「打扰」自动机，天然贴合分布式系统的开放性。

执行（execution）是形如 $s_0, \pi_1, s_1, \pi_2, s_2, \dots$ 的交替序列；执行片段（execution fragment）
是不要求从初始状态开始的执行「截段」。调度（schedule）只保留动作序列，状态序列去掉后即为调度。

### 1.2 组合（composition）

多个 I/O 自动机可以组合成一个复合自动机：共享同名的输入/输出动作（外部动作），
复合执行中这些动作同步发生。两条关键性质：

- **组合封闭性**：I/O 自动机的组合仍是 I/O 自动机（含输入使能性）；
- **层次化建模**：一个复合自动机又可以作为一个组件参与更高层的组合，
  于是「进程 + 信道 + 环境」可以自底向上搭出整个系统。

这套组合方法把「算法」与「环境/故障」解耦：故障模式（崩溃、拜占庭）被建模为另一个自动机
（故障环境自动机）与算法自动机组合，而不是写死在算法里——这正是全书能把同一算法
在不同故障假设下反复分析的语法基础。

### 1.3 公平性（fairness）

异步模型里「消息最终会被处理」不是时间假设，而是**公平性条件**：每个任务（task）
对应的动作不能永远被跳过。公平执行（fair execution）指每个任务都被无穷多次使能或无穷多次
发生的执行。FLP 一类不可能性结果（见 03 章笔记）正是要**在公平执行的集合内**构造出坏执行；
反过来，算法的正确性证明也要对一切公平执行成立。

### 1.4 问题规约与证明方法

问题规约为**输入/输出自动机的迹（trace）性质集合**：合法的输出迹集合刻画「解」。
两种典型证明手法（教学示意）：

- **不变式 + 良基排序**（invariant assertions）：先证所有可达状态满足不变式，再证关键测度递减；
- **模拟（simulation）/ 不变式映射**：证明具体自动机的执行在抽象自动机的意义上「可实现」，
  即通过映射 $\phi$ 把具体状态映到抽象状态——这是后续第 17 章「共享内存与网络相互模拟」
  与第 19 章快照算法证明的通用引擎。

### 1.5 不可分辨性（indistinguishability）

两个执行对一个进程**不可分辨**，若该进程看到的状态与动作历史完全相同。这是全书不可能性
证明的手术刀：FLP 的核心就是把两个「从决定 0 与决定 1 的执行」逐步黏合成一个合法执行，
使某个进程在两种未来中处境不可分辨，从而无法安全决定（详见 03 章笔记）。

### 1.7 环境自动机与故障建模示例

把「环境」与「故障」写成独立自动机再组合，是 I/O 自动机方法的招牌动作。教学示意
（崩溃故障环境，与算法自动机 $A$ 组合）：

```
自动机 FaultyEnv（崩溃故障环境）：
  状态：alive[p] : bool，初始全真
  输入动作：deliver(m, p)      // 当 alive[p] 时使能
  输出动作：crash(p)           // 使能条件：alive[p]；效果：alive[p] := false
  内部动作：tick               // 使能：恒真；效果：无（模拟任意慢）

系统 = A 组合 FaultyEnv（与信道自动机 C 一起）
性质规约：Safety = trace 集 ⊆ 合法输出迹集；Liveness = 对公平执行的要求
```

要点：**算法正确性证明对「一切与 FaultyEnv 组合出的公平执行」成立**——
故障假设不是口头描述，而是参与组合的一个自动机，可被替换（换成拜占庭环境
即得 08 章的问题设定），这正是全书复用同一套证明框架的机关。

### 1.8 复杂度度量速查（第 8.6 节）

| 度量 | 定义 | 适用模型 |
| --- | --- | --- |
| 步数复杂度 | 最长（公平）执行中某进程的内部/总步数 | 异步共享内存 |
| 消息复杂度 | 总发送消息条数 | 网络（同步/异步） |
| 时间复杂度 | 理想计时执行中的最大延迟单位 | 网络模型（异步下附加理想计时） |
| 轮数 | 同步执行的轮数 | 同步网络 |
| 位复杂度 | 总发送比特数 | 消息不等长的网络 |

注意异步模型的时间复杂度要**额外声明理想计时假设**（如「每步一单位时间」），
否则无定义——这是读第 15 章时间界时常被忽略的前提。

## 版本演进

- I/O 自动机最初用于异步系统（第 8 章）；同步网络章（第 2 章）沿用同一语言但加上「轮」结构；
  部分同步章（第 23 章）再引入时间界参数。三版建模是同一框架的逐步弱化假设。
- Lynch 后续与 Attiya、Guerraoui 等人的工作把 I/O 自动机思想延伸到定时自动机与
  TLA/形式化验证生态；她的 2023 年著作《Introduction to Reliable and Secure Distributed
  Programming》并非其作品（那是 Cachin/Guerraoui/Rodrigues），注意不要混淆——
  与 Lynch 直接相关的是教材 Attiya & Welch《Distributed Computing: Fundamentals, Simulations
  and Advanced Topics》，两者常被并列为「模型派」教材。
- 中译本（2004）基于 1996 英文版，无第二版更新；后续进展（随机化共识、失败检测器、
  部分同步工程化）见本目录各章 🔧 2026 视角节。

## 近年研究与工业界开源实践（2015–2026）

- **形式化验证工业化的源头活水**：I/O 自动机的「自动机 + 迹 + 模拟」方法直接滋养了
  TLA+ 生态。Lamport 的 TLA+ 与 PlusCal 已在 AWS（S3/DynamoDB 案例）、Azure Cosmos DB
  等生产系统用于共识协议验证；Lamport 本人与 Lynch 在 MIT 长期同域工作，
  两条建模传统（TLA 与 I/O automata）在「规约即性质集合」这一点上同源。
- **Jepsen（Kyle Kingsbury）黑盒测试**：把「对一切公平执行成立」的验证思想以
  故障注入 + 线性一致性检查器落地，是工程界最接近本章「问题规约为迹性质」的实践。
- **模型检查器 P（Microsoft Research）与 Ivy（VeriDI 链路）**：P 语言以状态机 + 事件驱动
  建模分布式系统并做系统性探索，Ivy 则用归纳证明验证共识协议，都可视为
  「I/O 自动机 + 自动化证明」路线的 2015–2026 延续。
- **开源参照**：`etcd-io/raft`（2026-09 现查 1.1k★，作为库被 etcd/TiDB 等嵌入）的
  状态机接口设计与本章「自动机组合」思想同构：把 raft 算法核心做成与传输/存储无关的
  纯状态机，测试与组合都因此变容易。
- **状态机复制（replicated state machine）的模型论基础**：把服务规约为「确定性自动机 +
  相同输入序 ⟹ 相同输出序」，第 10 章笔记会看到 raft 日志正是给这个自动机供应
  相同输入序的机制——本书的自动机语言是理解日志复制范式的零成本前置。
- **仿真环境即自动机组合**：现代分布式测试框架（deterministic simulation 一线）
  把时间、网络、磁盘都抽象成可插拔组件，与「算法 + 信道 + 故障环境」的组合结构
  一一对应；写仿真器前先读懂本章的组合封闭性，能少走弯路。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「I/O 自动机是 Lamport 发明的」 | 是 Lynch 与 Tuttle 提出；Herlihy-Wing 的可线性化定义借用了该框架（见 04 章） |
| 2 | 「异步模型里算法不可能有性能界」 | 复杂度以动作数/消息数度量，与时间无关；时间界只影响「轮数/延迟」类度量 |
| 3 | 「公平性等于活性假设很强」 | 公平性只要求任务不被永久饿死，这是异步系统证明的**下限**假设，FLP 在此假设下仍成立 |
| 4 | 「输入使能只是实现细节」 | 它保证环境任意输入不破坏组合封闭性，是分层证明可行的语法基础 |
| 5 | 🔧 本书未覆盖 | 2015 后工业界的**契约测试与故障注入**（Jepsen/Chaos 工具链）、**TLA+/Ivy 的机器辅助证明**；本书证明全为手工数学，工程上应优先学习机器可检查的规约 |
| 6 | 「执行 = 历史 = 调度」三者可互换 | 严格区分：执行含状态序列；调度只含动作序列；历史是调度去掉内部动作后的外部可见部分——三个对象的证明用途不同 |
| 7 | 「故障模型写死在算法里」 | I/O 自动机方法把故障建模为可替换的环境自动机；同一算法换故障环境即换问题，这是全书结构性的省钱设计 |
