# 第 04 章 共享内存互斥与原子对象（原书第 13 章，回接第 10 章）

> **本章地图**：从寄存器到原子对象（第 13 章：实现与规约）→ 可线性化语义 →
> 原子快照对象（atomic snapshot）→ 共享内存共识的强原语阶梯 → **一致性数（consensus number）**
> 与 Herlihy 定理 → 普适构造（universal construction）→ 回接第 10 章：FCFS 与线性化点的对应。

## 本章地图

原书第 13 章《Atomic Objects》是 Part IIA 的收官章，把第 9 章的「寄存器类型」推广为
「任意抽象数据类型的原子实现」，并回答第 12 章（FLP）留下的悬念：**什么强原语能突破
异步共识不可能性**。答案是一致性数 + 普适构造（Herlihy 理论）。本章是
[../多处理器编程的艺术2/](../多处理器编程的艺术2/00-总览与阅读地图.md) 系列笔记的
理论源头，两处按「理论 ↔ 实现」分工对读。

标题中「互斥」指本章与第 10 章互斥内容的接口（FCFS、可线性化点），互斥算法本体见 02 章笔记。

## 核心精讲（教学示意，不参与构建）

### 4.1 原子对象（atomic object）的定义

对象类型 $T$ 有状态集与操作集；原子对象实现要求操作表现**如同瞬间串行执行**
（可线性化）：存在所有操作的全序，每个操作落在其调用与响应时刻之间，
且该序与对象语义一致（每一步是该类型上的合法转移）。可线性化的两个关键性质：

- **局部性**（locality）：各对象分别可线性化 ⟹ 合在一起可线性化（Herlihy & Wing 1990）；
- **组合封闭**：可线性化对象串行组合仍是可线性化——这是第 8 章组合思想在数据结构层的对应。

> 与顺序一致性的差别：线性化是**实时序**（real-time）约束，更强；
> Lamport 顺序一致性只要求「某个合理的串行序」，不要求尊重实时。辨析详见
> [../多处理器编程的艺术2/03-并发对象与可线性化.md](../多处理器编程的艺术2/03-并发对象与可线性化.md)。

### 4.2 原子快照（atomic snapshot）对象

问题：$n$ 个槽位的 MRMW 寄存器组，要求一个 **snapshot()** 操作原子地读到全部槽位
的一致视图（如同瞬间定格）。难点：单槽逐个读不原子，读到一半别人还在写。

教科书构造（教学示意，双重集合扫描）：

```
共享：reg[i] : (ts, data)   // 写者 i 写自己的槽，ts 单调递增

写 write_i(v)：  reg[i] := (ts_i+1, v)

读 snapshot()：
  repeat
    a1 := 逐个读 reg[1..n]          // 第一次扫描
    a2 := 逐个读 reg[1..n]          // 第二次扫描
  until 两次扫描中「除自己外所有槽的 ts 相同」
  return a1（或 a2）
```

正确性直觉：若两次扫描间没有任何槽变化，两视图一致，直接返回；若某槽变了，
写者至少完整写了一次——利用「写者写前先读全场、发现重复写则收集对方值代替自己写」
（收集-帮助机制），可证明返回值构成某个合法的线性化点。原书 13 章给出证明并讨论
$O(n)$ 空间与无等待（wait-free）性质；快照的无等待下界与空间优化是后续十年
理论社区的活跃方向（Inoue/Chen 等构造，条目存疑不展开）。

### 4.3 一致性数（consensus number）★

类型 $T$ 的一致性数 $CN(T)$ = 用任意多个 $T$ 对象 + 读写寄存器能解出的
wait-free 共识的最大进程数（可解 $n$ 进程则 $CN \ge n$）。经典取值：

| 类型 | $CN$ | 关键操作 |
| --- | --- | --- |
| 读写寄存器 | 1 | read/write（FLP 的另一种读法：1 容错都不行） |
| test-and-set / fetch-and-add | 2 | 竞争双方只有一个胜者，天然 2-裁定 |
| 队列 / 栈（带并发语义假设） | 2 | 出队者胜 |
| compare-and-swap（CAS）/ LL-SC | ∞ | 直接写出共识三段（胜者值当决定值） |

证明模板（以 TAS 的 $CN=2$ 为例，教学示意）：两进程并发调 TAS，胜者读到的
返回值是 0、败者读到 1——返回值本身携带「谁先」的信息，把 init 与 propose
编码进被交换的值即可裁定。寄存器 $CN=1$ 的证明即 FLP（第 12 章）。
$CN=\infty$ 的 CAS 共识（教学示意）：

```
共享：R : 64 位字, 初值 ⊥
propose_i(v)： v1 := CAS(R, ⊥, v)
              if v1 = ⊥ then v1 := v end if   // 我赢或读走赢家
              return v1                        // 所有进程最终读到同一个 v1
```

（严格证明需处理 CAS 竞争失败后的重读与有效性校验，此处示意。）

### 4.4 Herlihy 定理与普适构造

**Herlihy 1991（ACM TOPLAS, Wait-Free Synchronization）** 三段论：

1. 层级定理：$CN$ 把同步原语分成严格递增的类，且类间**不可模拟**——
   低类对象无法 wait-free 实现高类对象（带共识数不变量证明）；
2. $CN=\infty$ 的类型（CAS、LL-SC、带共识数据的内存一致对象）是**普适**的；
3. **普适构造**：给定任意顺序对象规格 + 无限个 CAS，可 wait-free 实现该对象的并发版本
   ——核心是一个「共识指针链表」：每次操作先建新节点，再 CAS 把头指针从旧状态
   推进到包含自己操作的新状态；失败者读头链并**帮助**完成他人操作（helping）。

普适构造的直接推论：**wait-free 线性化 ≈ 「有 CAS 就有一切」**。
代价是构造出的对象吞吐极差（每次操作一次 CAS 串行化 + 帮助链），因此工程上
普适构造是正确性基准而非生产实现——这个「理论基准 ↔ 工程取舍」的落差，
正是 [../多处理器编程的艺术2/06-共识的普适性.md](../多处理器编程的艺术2/06-共识的普适性.md)
的主题。

### 4.5 回接第 10 章：互斥与原子对象的关系

- 第 10 章互斥的 FCFS 条件 ≈ 把「进临界区」建模为对象操作时的**线性化点排序**；
- 互斥锁本身的一致性数：持锁/释放锁协议若用读写寄存器实现（面包店），
  进度只能到 lockout-free；用 CAS 实现（test-and-set 锁），进度可到无死锁但
  **锁不是 wait-free 的**（等待者被持锁者卡住）——一致性数理论解释了
  「锁永远不是 wait-free 原语」这一根本差异。

### 4.6 快照对象与「读一致视图」家族对照

| 抽象 | 层次 | 一致性承诺 | 出处 |
| --- | --- | --- | --- |
| 原子快照（第 13 章） | 共享内存原语 | 全槽位存在共同线性化点 | 本章 |
| 全局快照（Chandy–Lamport） | 网络 | 等价执行的一致切面（因果一致） | 06 章 |
| MVCC 快照 / 快照隔离 | 数据库 | 事务开始时已提交数据的一致视图 | [../数据库系统概念6/15-并发控制.md](../数据库系统概念6/15-并发控制.md) |
| etcd linearizable 读 | KV 服务 | 读操作线性化于写历史 | 10 章笔记 |

四者是同一需求（「原子地看全貌」）在四层抽象的实现；区别在**是否存在共同线性化点**
与**读的是哪个版本**。数据库的快照隔离不要求与实时序对齐，因此弱于原子快照——
写偏斜（write skew）正是弱化的代价。

## 版本演进

- 1985–1990：Lamport 对寄存器原子性的形式化（《On Interprocess Communication》,
  Distributed Computing 1986 期刊版，卷页未核实，存疑）奠定 safe/regular/atomic 谱系；
- 1990：Herlihy & Wing《Linearizability: A Correctness Condition for Concurrent Objects》
  （ACM TOPLAS 1990, 12(3)）确立可线性化为标准正确性条件；
- 1991：Herlihy《Wait-Free Synchronization》完成一致性数与普适构造（TOPLAS 1991, 13(1)）；
- 1993+: 原子快照的空间/时间下界与更优构造（理论社区持续到 2000s）；
- 2000s–2026：可线性化检查工具工业化（linearizability checker：Knossos/Jepsen、
  Porcupine、Stateright 等），把「线性化点是否存在」变成 CI 可跑的判题器。

## 近年研究与工业界开源实践（2015–2026）

- 🔧 **CAS 普及后一致性数的实际意义**：x86 `lock cmpxchg`、ARM `LDXR/STXR`（后 LSE `CAS`）
  让 $CN=\infty$ 原语无处不在；一致性数从「稀有资源排序」变成「进度保证的审计工具」——
  现代并发库文档声明 lock-free/wait-free 时，本质是在声明其依赖原语的 $CN$。
- **可线性化检查进入 CI**：Jepsen 的 Knossos、开源 `anishathalye/porcupine`（Go 线性化
  检查器，star 未核验）、`stateright`（Rust 模型检查器，star 未核验）把第 13 章的
  语义变成测试断言；etcd（`etcd-io/etcd`，现查 52.3k★）的线性一致性读
  （ReadIndex/lease read）是其 KV 语义对「原子对象」概念的产品级对应物。
- **持久内存与原子快照**：PMEM 时代「跨缓存行原子快照」由 undo/redo 日志承担，
  与 4.2 节双重扫描思想同源；PMEM 硬件退潮后该思想转入 WAL + MVCC 的通用实现。
- 🔧 **共识数在 RDMA/DPDK 场景的再讨论**：远程 CAS 可用后，一致性数阶梯
  在「网络内存」上重演（远端对象的一致性数决定 wait-free 复制状态机能否成立），
  这是 2015–2026 理论-系统交叉的活跃点（代表工作条目未核实，存疑不点名）。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「可线性化 = 顺序一致性」 | 线性化尊重实时序且逐对象可组合（局部性）；顺序一致性两者都不保证 |
| 2 | 「CAS 能把锁做成 wait-free」 | 锁的语义（持有期间阻塞他人）决定了它不可能是 wait-free 的；CAS 普适的是**对象**，不是锁 |
| 3 | 「一致性数高的原语必然更快」 | 层级定理只讲**可模拟性**，不讲性能；生产系统为吞吐反而选低 CN 原语 + 更细粒度结构 |
| 4 | 「原子快照双重扫描总返回最新值」 | 它只承诺**一致**（存在线性化点），不承诺最新——快照隔离（数据库）同样如此 |
| 5 | 🔧 本书 1996 截稿 | 未覆盖 C++/Java/Rust 内存模型与 acquire-release 序；快照的现代实现走 MVCC 版本链而非帮助机制 |
| 6 | 🔧 现代视角 | 原子快照概念在分布式数据库以「快照隔离 + 时间戳读」重生（见 [../分布式数据库入门进阶与实战/09-共识算法.md](../分布式数据库入门进阶与实战/09-共识算法.md) 与其事务章） |
| 7 | 「帮助机制（helping）只是性能优化」 | 在普适构造里，helping 是 **wait-free 进度证明的必要部件**：没有它，被延迟进程可能永远等不到自己操作完成 |
