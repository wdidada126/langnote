# 第 02 章 共享内存异步算法基础：互斥与资源分配（原书第 9、10、11 章）

> **本章地图**：异步共享内存模型（第 9 章：寄存器类型、可区分状态、故障与随机化）→
> 互斥问题（第 10 章：性质定义、下界直觉）→ Dijkstra 互斥算法 → 更强条件（无饿死/无死锁）→
> 无锁出（lockout-free）算法 → 单写者寄存器算法 → **Lamport 面包店算法**（10.7）→
> 资源分配（第 11 章： dining philosophers、 drinker philosophers、死锁与饿死）。

## 本章地图

Part IIA 的入口三章。第 9 章把第 8 章的 I/O 自动机实例化到共享内存：进程通过**共享寄存器**
交互，寄存器按「读写能力」（单读单写/多读多写）、按「写者数量」（单写/多写）分类。
第 10 章给出全书第一个完整算法族——互斥，从 Dijkstra 的初始解到 Lamport 面包店算法，
展示了「模型越弱（寄存器越简单、故障越多）算法越精巧」的教科书式递进。
第 11 章资源分配把互斥推广到多资源并发请求（哲学家就餐是特例）。

## 核心精讲（教学示意，不参与构建）

### 2.1 共享内存模型的构件：寄存器类型谱系

第 9 章按两个维度给寄存器分类：

- **读写能力**：SRSW（单读单写）→ MRSW（多读单写）→ MRMW（多读多写）；
- **返回语义**：safe（并发读写时读到任意值）→ regular（并发读返回旧值或新值）→
  atomic（原子性，可线性化）。

关键基础事实（教学示意）：MRSW 原子寄存器可由 SRSW 原子寄存器构造
（每读者一份副本 + 读时归并时间戳）；MRMW 又可由 MRSW 构造（每写者一份 + 读时取最大）。
这套「由弱类型构造强类型」的手法是 04 章原子对象与 Herlihy 普适构造的垫脚石，
在 [../多处理器编程的艺术2/04-共享内存基础.md](../多处理器编程的艺术2/04-共享内存基础.md)
有实现向展开。

### 2.2 互斥问题定义（第 10.2 节）

$n$ 个进程循环执行「入口区 → 临界区 → 出口区 → 剩余区」，要求：

- **互斥性**（safety）：任意时刻至多一个进程在临界区；
- **无死锁**（progress / deadlock-free）：临界区空闲时，想进的进程终能进（某进程）；
- **无饿死 / 无锁出**（starvation-freedom / lockout-freedom）：每个想进的进程终能进；
- **先来先服务**（FCFS，可选强化）：入口顺序与到达顺序一致（10.4 节引入，为面包店算法铺垫）。

### 2.3 Dijkstra 互斥算法（10.3 节）

原书记述的 Dijkstra 型解法为每个进程维护标志位（教学示意，n 进程版本）：

```
共享：flag[i] ∈ {out, want, in}  （i = 1..n）

进程 i 入口区：
  repeat
    flag[i] := want
    while ∃ j < i: flag[j] ≠ out do   // 让小编号者优先
      if flag[i] = in then flag[i] := want end if   // 礼让回退
      while ∃ j < i: flag[j] ≠ out do skip end while
    end while
    flag[i] := in
  until ∀ j ≠ i: flag[j] ≠ in
```

该解保证互斥与无死锁，但一般不保证无饿死；且依赖对共享变量读写的原子顺序假设。
教科书价值在于**首次形式化互斥并给出可证明正确的算法**（Dijkstra 1965 手稿/1968 CACM）。

### 2.4 无锁出算法与单写者寄存器（10.5–10.6 节）

10.5 节给出仅用普通读写寄存器即可达到无锁出的构造思想：进程竞争一个逻辑「票据」排序，
败者回退重试。10.6 节把假设压到极限——**每对进程只用一个单写者寄存器**
（进程 $i$ 只写 $R_{ij}$，对方读），配合「记录最后说话者」的思想完成握手，
证明互斥甚至不共享变量也可以解，只要读写事件可排序。

### 2.5 Lamport 面包店算法（10.7 节）★

面包店算法是本章皇冠，三重意义：只用**安全（safe）读写寄存器**即可正确；
满足 FCFS；天然容忍读到的「中间态」值（取号动作不原子也不破坏正确性）。

```
共享：choosing[i] : bool；number[i] : 整数   （i = 1..n）

进程 i 入口区：
  choosing[i] := true
  number[i] := 1 + max(number[1..n])
  choosing[i] := false
  for j = 1..n do
    while choosing[j] do skip end while                    // 等对方取号完毕
    while number[j] ≠ 0 ∧ (number[j], j) ≺ (number[i], i) do skip end while
  end for

进程 i 出口区：
  number[i] := 0

// 字典序 ≺: (a,b) ≺ (c,d)  iff  a < c ∨ (a = c ∧ b < d)
```

- 证明要点：互斥——若 $i,j$ 同在临界区，则 $(number[i],i)$ 与 $(number[j],j)$
  互不相先；由取号与等待逻辑推出矛盾（利用 safe 寄存器「读到的旧值必有完整写入」性质）。
- FCFS：入口的取号完成时刻定序，字典序先到先进。
- 🔧 代价：共享数组 $O(n)$ 空间、入口 $O(n)$ 次自旋——正因为不实用，
  它的**正确性证明技术**（时间戳 + 字典序 + 不变量）才是遗产，
  后来成为 Lamport 逻辑时间（第 18 章）与 Lamport 时钟思想的前身。

### 2.6 资源分配与哲学家就餐（第 11 章）

把「临界区」推广为「一组资源请求」：进程提出资源请求向量，调度需保证
冲突请求不并发授予、无死锁、无饿死。经典实例：

- **dining philosophers**（Dijkstra）：相邻进程争同一叉子，第 11 章给出共享内存版解法
  （中心调度器 = 退化成互斥的解；分布式解 = 给叉子编号 + 资源分层申请）；
- **drinking philosophers**（Chandy-Misra）：任意子集冲突的一般化，
  请求图上用「破对称的局部规则」保证无死锁——这是 07 章对称破缺思想在共享内存的对应物。

死锁的四种对策在此定型：**一次性申请全部、资源有序分层、回退重试（带随机化）、
超时/死锁检测**——与数据库锁管理器（[../数据库系统概念6/15-并发控制.md](../数据库系统概念6/15-并发控制.md)
15.2 节）的 wait-die/wound-wait 与等待图检测完全同构。

## 版本演进

- 互斥谱系：Dijkstra 1965（首次形式化）→ Knuth 1966 / Eisenberg-McGuire 1972
  （改进无饿死）→ Lamport 1974 面包店（safe 寄存器 + FCFS）→ Peterson 1981
  两进程算法（教材最爱的极简解）→ Burns/Lamport 1980s 空间下界 $n$ 寄存器。
- 第 10 章未展开的方向：基于强同步原语（test-and-set、compare-and-swap）的自旋锁
  在 [../多处理器编程的艺术2/07-自旋锁与争用.md](../多处理器编程的艺术2/07-自旋锁与争用.md)
  有完整展开（TAS/TTAS/Anderson 队列锁/MCS 锁）——那是真实硬件上的「第 10 章续集」。
- 部分同步下的互斥（读/写故障恢复、timing-based 算法）留给原书第 24 章，见 10 章笔记。

## 近年研究与工业界开源实践（2015–2026）

- **面包店思想的三次工程转世**：
  1. **逻辑时间戳**：分布式数据库的事务时间戳排序（Spanner/Percolator 一脉）用
     时间戳字典序替代「物理时刻」，证明思路与面包店一致；
  2. **公平票据锁**：Linux 内核 `qspinlock`/ticket spinlock 的「取号—等号」结构与面包店同构；
  3. **FAIR 排队**：etcd 的公平配额（fair quota，写请求队列按到达序授予配额）
     是无饿死原则在 KV 存储里的直接落地。
- **互斥即租约**：现代系统几乎不再用纯共享内存互斥解决跨节点互斥，而是**租约（lease）+
  共识**：`etcd-io/etcd`（2026-09 现查 52.3k★）的 lease 机制、ZooKeeper/Chubby 的
  会话租约，都可读作「第 10 章问题在网络故障模型下的工程解」。
- **rust 的 atomics 与 wait-free 进度**：`crossbeam` 等库把进度条件（wait-free/lock-free/
  obstruction-free）作为 API 文档的一等公民，呼应第 9.6 节对故障与进度条件的建模。
- 对应开源自旋锁与争用的实测数据（缓存行弹跳、NUMA 扩展性）见
  [../多处理器编程的艺术2/07-自旋锁与争用.md](../多处理器编程的艺术2/07-自旋锁与争用.md)，
  该书笔记含 benchmark 口径，本目录不重复。
- **互斥理论 × 数据库锁管理器**：wait-die/wound-wait 时间戳法（防死锁）
  与面包店取号同属「时间戳排序破对称」家族；死锁检测的等待图在数据库侧的
  工程实现（InnoDB `lock0lock.cc`）见 [../数据库系统概念6/15-并发控制.md](../数据库系统概念6/15-并发控制.md) 15.2 节。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「面包店算法在实际系统里直接使用」 | 它只用 safe 寄存器，为证明最优性服务；工程上用 CAS/自旋锁/租约，本章价值在证明技术 |
| 2 | 「无死锁就够」 | 无死锁允许饿死个别进程；分布式存储（etcd 配额、锁服务）必须另加公平策略达到无饿死 |
| 3 | 「Peterson 算法依赖 test-and-set」 | 纯读写寄存器即可；CAS 只是让算法更短，不是必要条件 |
| 4 | 「共享寄存器天然原子」 | 第 9 章的 safe/regular/atomic 三分法说明原子性本身是**被构造出来的性质**（见 04 章） |
| 5 | 🔧 本书 1996 年截稿 | 未覆盖真实 CPU 内存模型（TSO/ARM 弱序、acquire-release 语义）；现代结论：无数据竞争需配内存栅栏，纯算法层面正确 ≠ 芯片上正确，须与《多处理器编程的艺术2》18 章（栅栏）对读 |
| 6 | 🔧 现代替代 | 跨节点互斥的主流是租约 + 共识 + fencing token，纯「锁」语义已让位于「租约 + 令牌校验」 |
