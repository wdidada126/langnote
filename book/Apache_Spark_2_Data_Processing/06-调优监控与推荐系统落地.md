## 1. 调优三杠杆（2.x 教义的正典表述）

- **序列化与内存布局** ⚠️：优先 `MEMORY_AND_DISK_SER` 系列级别；Kryo 注册自定义类（Spark 内建类型已内置注册）；避免在闭包里捕获大对象——`sc.parallelize(...)` 后 `map(大表.value)` 的 2.x 事故范本。
- **Shuffle 治理** ⚠️：`spark.sql.shuffle.partitions`（默认 200）按聚合基数调档；大表 join 走 broadcast hint（01 §3 广播通道的 SQL 面）；`repartition/coalesce` 的手动再分区是「AQE 之前时代」的日常体操。
- **内存模型** ⚠️：统一内存管理（unified memory model）下 execution/storage 互借，`spark.memory.fraction` 是 2.x 教参标配旋钮。
- **GC 姿势**：G1 取代 CMS 的教学转向发生在 2.x 年代 ⚠️（转述）——本册读者被引导在提交脚本里显式挂 JVM 选项。

## 3. 推荐系统：ALS 撑起副题的工程样板

```scala
import org.apache.spark.ml.recommendation.ALS
val als = new ALS()
  .setMaxIter(10).setRegParam(0.01).setRank(10)
  .setUserCol("userId").setItemCol("movieId").setRatingCol("rating")
val model = als.fit(ratings)              // 显式反馈基线
model.setColdStartStrategy("drop")        // 2.x 教义：未登录用户先丢弃
val recs = model.recommendForAllUsers(10) // 批量 top-K
```

- **显式 vs 隐式**：`ALS.train(ratingsDF, rank, iter, lambda, alpha)` 的隐式反馈变体（置信加权）是 2.x 推荐教程的保留节目 ⚠️；
- **评估口径**：`RankingMetrics` 的 MAP/NDCG 在 ml 包内可用但**全局指标聚合有近似教义** ⚠️——2.x 文档对推荐指标的分片近似有著名告诫；
- 与 04 管道体系同构：推荐是「Pipeline + 特征（用户/物品画像）+ 在线导出」的复合工程，Spark 只负责批式训练与批量打分。

## 4. 工程收束清单（本书年代最佳实践 → 复盘）

1. 输入侧：分区数≈数据形态对齐（小文件治理的前史姿势）⚠️；
2. 变换侧：谓词早进 SQL（02 的下推教义在管道层的回声）⚠️；
3. 动作侧：`foreachPartition` 复用 sink 连接（01 §3）⚠️；
4. 观测侧：UI 四页 + 事件日志常开（§2）；
5. 复现侧：seed 固定 + 管道模型版本化存档（04 §1 的跨版本警告回声）⚠️。

## 4.5 四类高频事故与定位动线（现场手册）

| 事故 | 信号（UI/日志） | 2.x 定位动线 ⚠️ |
|---|---|---|
| 数据倾斜 | 单 stage task 时长 max/median 比悬殊、个别 spill 爆表 | 热点 key 加盐两阶段聚合（01 §2 键重分布语义+🔧 E3 可组合性）、小侧改 broadcast join；AQE 未登场时代的手动体操 |
| Driver OOM | `collect()`/`toPandas()` 悬崖（02 §5）、超长链无 checkpoint 元数据膨胀（01 §4.5） | 动作侧先 filter 再 collect；链条侧 checkpoint 截断——两者都不改结果只改形状 |
| 小文件风暴 | task 数爆炸、NameNode 报警、`spark.sql.files.*` 相关读慢 | 源头 `repartition(n)`/写入前合并——输出侧 `coalesce` 收尾（06 §4 清单第 1 条） |
| Shuffle fetch failed | executor 失联→祖先 stage 重放 avalanche（01 §4.5） | 判外因（抢占/机器）与内因（executor 内存超载、`memory.fraction` 挤压）两条审计路 |

**动线总纪律**：先观测（§2 监控栈）→ 再定位（上表）→ 最后调参；「参数没变而性能崩了」优先查数据形态与集群环境，不查自己的代码直觉。

## 4.6 容量与成本：教参公式 → 审计清单

- 2.x 容量直觉：`executor 数 × (每 executor 核数 × 并发 task + 堆外开销比例)`——调度余量与 spill 余量都要预算，那个时代没有 AQE 兜底 ⚠️；
- 升级审计三清单（本书年代脚本 → 4.x 集群）：**失效参数**（手工档位被自适应接管）、**弃用参数**（改名/换义）、**聋参数**（键位仍在语义已迁）——逐参对照官方迁移文档再上线 ⚠️ 转述；
- 成本模型换代：标题页的 Hadoop 沙箱「自有集群摊折旧」姿势，已被存算分离+按需计费的托管形态整体替换（00 §4 史册定位的经济学收口）⚠️；
- 🔧 收尾呼应 E1/E5：下游能吃重发就用 append/update 的窄带宽，重放昂贵就诚实地 persist/checkpoint——**微批语义与存储决策在成本表上会师**，这是六章合读的最终视图（两实验数值均为单机类比，非 Spark 集群账单）。

## 4.7 时代差问答与自测（本章四问）

- **问：本册调优章节还能直接照做吗？** 答：不能——参数档位级教义（200 分区、G1 旗标）半衰期已过；「观测→定位→调参」元纪律仍成立（§4.5/演进表）。
- **问：ALS 还要不要学？** 答：作为「矩阵分解+交替优化」的最小可读实现仍值一读；作为生产推荐主干已是基线模型（演进表），学习预算应放在评估口径与批量导出工程上。
- **问：冷启动 drop 策略的隐患？** 答：它把「新用户占比」从指标里静音了——上线评审要单独问覆盖率（§3 教义的反面运用 ⚠️）。
- **问：🔧 数字在成本章能信几分？** 答：E1/E3/E5 只证语义与权衡方向，不证量级——集群账单必须回到 A/B 实测，本册网络面下 Spark 不可装这一事实贯穿始终（00 §7）。

自测四题：① 倾斜的 UI 指纹是什么、两种拆解各自改变结果吗；② History Server 与 eventLog 的开关依赖链；③ 隐式反馈的 alpha 在成本表上买的是什么；④ 升级 4.x 前三参数清单（失效/弃用/聋）各举一例并说明审计动线（§4.6）。

## 4.8 一分钟带走（本册原声五句）

- 承诺原声：`Understand tuning, debugging, and monitoring of big data applications` 与 `Build scalable recommendation engines`（✅ 官方 README 实抓）——本章两句全接住，也全标了半衰期。
- 调优一句断：参数是旧地图、动线是新大陆——先观测后调参的元纪律穿越 2.x→4.x（§4.5）。
- 监控一句断：`eventLog` 常开是一切事后诊断的先决条件，History Server 只是它的播放器（§2）。
- 推荐一句断：ALS 教的是矩阵分解的思维方式，不是 2026 年的生产选型（§3/演进表）。
- 合订一句断：调优词汇的「缝合感」最强——三本单品书各带自家年代参数表，本目录以三清单审计收编（§4.6）。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
|---|---|---|
| 统一内存管理 | Unified Memory Model | 执行与存储区互相借调的堆内分配制度（2.x 默认） |
| 混洗分区数 | shuffle.partitions | SQL 聚合/join 后重分布的 reducer 档位，2.x 手工调优核心旋钮 |
| 广播连接提示 | Broadcast Hint | 强制小表复制进任务以避免 shuffle join 的 SQL 杠杆 |
| 倾斜比 | Skew Ratio | task 时长 max/median 偏离诊断，倾斜长尾的 UI 信号 |
| 历史服务器 | History Server | 事件日志回放的事后诊断服务 |
| 事件日志 | Event Log | `spark.eventLog.enabled` 产出的应用时间线存档 |
| 交替最小二乘 | ALS (Alternating Least Squares) | 矩阵分解推荐主干：固定一侧解另一侧的迭代 |
| 隐式反馈 | Implicit Feedback | 置信加权的浏览/点击信号训练形态（alpha 权重） |
| 冷启动策略 | Cold Start Strategy | drop/scale 等未登录用户处理教义（2.x 起显式参数） |
| 排序评估 | Ranking Metrics | MAP/NDCG 等 top-K 质量度量（分片近似的告诫对象） |
| 分区级写出 | foreachPartition | 以分区为粒度建连接写出，推荐批量打分落库的工程件 |
| 序列化级别 | MEMORY_AND_DISK_SER | 磁盘换内存压力的持久化档位，调优三杠杆之首 |
| 参数审计三清单 | 失效/弃用/聋 参数 | 升级迁移的逐参对照纪律（§4.6），以官方 release notes 为准绳 |
| 容量直觉 | executor × (cores, memoryOverhead) | 教参时代的规划公式，调度与 spill 双余量预算（§4.6） |
| 存算分离 | Storage-Compute Decoupling | 托管计费对「自有集群摊折旧」的模型更替（§4.6，⚠️ 判语） |
