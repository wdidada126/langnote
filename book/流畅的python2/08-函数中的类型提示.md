# 第 8 章 函数中的类型提示（原书 pp.192–228）

> 一句话定位：本章是全书类型系统的入口——从「渐进式类型」的哲学讲到 `Any`/`Optional`/`TypeVar`/`Protocol`/`Callable`/`NoReturn` 的逐个用法，并明确「类型提示不能替代测试」。
> 基线：原书 Python 3.10；本目录按 3.12+ 校验。**这是本组 6 章中最需要按 2026 年口径重写的一章**：PEP 695（3.12）、PEP 673（3.11）、PEP 649（3.14）三项变化直接改写了本章的写法。

## 核心精讲

### 一、渐进式类型的三条底线

1. **可选**：不写注解的代码照样运行，解释器不检查。
2. **局部**：可以只给关键函数加注解，逐模块推进。
3. **工具驱动**：语义由静态检查器（mypy / pyright）定义，凡与官方文档冲突以 typing 规范站点为准。

```python
# 教学示意，不参与构建；本机 Python 3.13 可运行
# 静态检查：mypy --strict ch8_demo.py
from collections.abc import Iterable

def show_count(count: int, word: str) -> str:
    if count == 1:
        return f'1 {word}'
    return f'{count} {word}s'

def total(items: Iterable[float]) -> float:
    return sum(items)

print(show_count(3, 'bird'), total([1, 2, 3.5]))
```

`total` 收 `Iterable[float]` 而不是 `list[float]`：调用方可以传列表、元组、生成器、集合。这是「放宽入参、收紧出参」的典型体现（型变问题见第 15 章）。

### 二、🔴 PEP 695 新旧语法对照（本章最大修正点，3.12）

| 场景 | 旧写法（原书 3.10） | 3.12+ 新写法（PEP 695） |
| --- | --- | --- |
| 泛型函数 | `T = TypeVar('T')` <br> `def first(xs: list[T]) -> T: ...` | `def first[T](xs: list[T]) -> T: ...` |
| 有上界的类型变量 | `T = TypeVar('T', bound=float)` | `def f[T: float](x: T) -> T: ...` |
| 泛型类 | `class Stack(Generic[T]): ...` | `class Stack[T]: ...` |
| 泛型类型别名 | `Alias = List[T]` | `type Alias[T] = list[T]` |
| 非泛型类型别名 | `Alias = list[int]`（PEP 613：`Alias: TypeAlias = list[int]`） | `type Alias = list[int]` |
| 约束列表 | `T = TypeVar('T', str, bytes)` | 🔧 PEP 695 只支持上界，无「约束列表」等价语法；需要时用重载，`以官方文档为准` |

```python
# 教学示意，不参与构建；语法要求 Python 3.12+，本机 3.13 验证通过
# 静态检查：mypy --strict
from typing import Protocol

class SupportsLessThan(Protocol):
    def __lt__(self, other: 'SupportsLessThan') -> bool: ...

def first[T](xs: list[T]) -> T:          # 类型参数写在函数名后的方括号里
    return xs[0]

def maximum[T: SupportsLessThan](xs: Iterable[T]) -> T: ...   # 上界写法

class Stack[T]:
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, item: T) -> None:
        self._items.append(item)
    def pop(self) -> T:
        return self._items.pop()

type IntList = list[int]                 # 惰性求值的类型别名
type Pair[T] = tuple[T, T]               # 泛型别名，旧写法无法表达

s = Stack[int]()
s.push(3)
print(s.pop(), IntList, Pair[int])
```

新旧写法的本质差异：**旧 `TypeVar` 是模块级对象**（要命名、要对齐、易被复用串味）；**PEP 695 的类型参数有独立作用域**，由编译器管理，且惰性求值，天然支持前向引用。迁移时，`T = TypeVar('T')` 仍可用（未被移除），但新代码一律用新语法。

### 三、`Self`（PEP 673，3.11）：备选构造与链式返回的正确注解

```python
# 教学示意，不参与构建；Python 3.13 验证通过
from typing import Self

class Shape:
    def set_scale(self, scale: float) -> Self:   # 子类调用也返回子类类型
        self.scale = scale
        return self
    @classmethod
    def from_json(cls, data: str) -> Self: return cls()

class Circle(Shape): ...
print(Circle().set_scale(2.0).__class__.__name__)   # Circle
```

旧写法只能写 `-> 'Shape'`（字符串前向引用）或引入额外的 `TypeVar` 绑定，子类链式调用会退化成父类类型；`Self` 直接解决。

### 四、`Any`、`Optional`、联合与泛化容器

```python
# 教学示意，不参与构建
from typing import Any, NoReturn
from collections.abc import Mapping

def parse(raw: bytes) -> Any: ...                    # 逃逸阀：关闭后续检查
def find(name: str) -> str | None: ...               # PEP 604，等价 Optional[str]
def scores() -> Mapping[str, float]: ...             # 只读映射，不承诺可变
def fail(msg: str) -> NoReturn:                      # 永不返回
    raise RuntimeError(msg)
```

要点：`Any` 会**静默传染**——`Any` 参与的表达式结果仍是 `Any`，一处 `Any` 可能让整条调用链失去检查。返回值用 `Mapping` / `Iterable` / `Sequence` 而非具体类，是给未来的实现留余地。

### 五、静态协议（PEP 544，3.8）

```python
# 教学示意，不参与构建
from typing import Protocol, runtime_checkable

class SupportsClose(Protocol):
    def close(self) -> None: ...

def shutdown(res: SupportsClose) -> None:
    res.close()

class Connection:                     # 不继承 SupportsClose，照样通过检查
    def close(self) -> None:
        print('closed')

shutdown(Connection())
```

`@runtime_checkable` 让协议可用于 `isinstance`，但**只检查方法名是否存在，不检查签名**；含非方法成员（数据属性）的协议用 `issubclass` 会抛异常。协议里声明 `@staticmethod` / 类属性时的静态与运行时行为存在已知边界，🔧 **以 typing 规范（typing.readthedocs.io）为准**；实用建议是：协议成员优先声明为实例方法。

### 六、`Annotated`（PEP 593，3.9）：给注解挂元数据

```python
# 教学示意，不参与构建；Python 3.13 可运行
from typing import Annotated

Meters = Annotated[float, 'unit: meter']
Seconds = Annotated[float, 'unit: second']

def speed(distance: Meters, time: Seconds) -> Annotated[float, 'unit: m/s']:
    return distance / time
```

`Annotated` 的第二个及后续参数是任意对象，静态检查器忽略它们，但**运行时框架会读**：FastAPI 用它声明校验规则，pydantic / attrs 用它挂约束，各类依赖注入容器用它标记注入键。这是「类型提示从检查器走向运行时框架」的关键接口。

### 七、🔴 PEP 649（3.14）：注解延迟求值改变了运行时取注解的写法

3.14 起，函数/类/模块的注解**默认不再在定义时求值**，而是编译成 `__annotate__` 函数按需调用；读取注解的官方入口变成新增的 `annotationlib` 模块。

```python
# 仅 Python 3.14+ 示意，不在本机 3.13 上执行
import annotationlib

def f(x: undefined_name) -> None: ...        # 3.14 起定义时不再报错

print(annotationlib.get_annotations(f))              # 求值失败会抛 NameError
print(annotationlib.get_annotations(
    f, format=annotationlib.Format.FORWARDREF))      # 未定义的名字保留为 ForwardRef
```

影响面：任何在运行时读 `__annotations__` 做序列化/校验/依赖注入的库（pydantic、FastAPI、attrs、SQLAlchemy 2.x）都要随之调整；`typing.get_type_hints()` 依旧是「把注解解析成类型对象」的稳定入口。🔧 `from __future__ import annotations`（PEP 563）在 3.14 中的具体实现与保留语义**以官方文档为准**。

### 八、仅限位置参数、变长参数与 `Callable`

```python
# 教学示意，不参与构建；Python 3.13 可运行
from collections.abc import Callable

def query(sql: str, /, *params: float, timeout: float = 1.0, **opts: str) -> None:
    """`/` 前只能按位置传；`*params` 注解的是『单项』类型；`**opts` 同理。"""

Callback = Callable[[int, str], None]     # 参数类型列表 + 返回类型
AnySig = Callable[..., None]              # 省略号 = 任意签名（慎用）
```

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 🔧 8.5.9 全部用 `T = TypeVar('T')` + `Generic[T]` | 3.12 起已有官方新语法，旧写法冗长且类型参数作用域混乱 | `def first[T](...)`、`class Stack[T]`、`type Pair[T] = tuple[T, T]`（PEP 695） |
| 🔧 备选构造注解为 `-> 'Vector2d'` 或绑 `TypeVar` | 子类会退化成父类类型 | `-> Self`（PEP 673，3.11）；跨版本用 `typing_extensions.Self` |
| 🔧 只介绍 Mypy 一个检查器 | 2026 年是双检查器格局 | 同时用 mypy 与 pyright，二者互补 |
| 🔧 靠 `from __future__ import annotations` 实现延迟求值 | 3.14 起语言层面默认延迟求值（PEP 649） | 3.14 用 `annotationlib.get_annotations()`；解析成类型对象仍用 `typing.get_type_hints()`；🔧 细节以官方文档为准 |
| 用 `typing.List` / `typing.Dict` | 3.9（PEP 585）起为废弃别名 | `list[int]`、`dict[str, float]` |
| 写 `Optional[str]` / `Union[int, str]` | 3.10 起有更短的写法 | `str \| None`、`int \| str`（PEP 604） |
| 🔧 `TypeVar('T', str, bytes)` 约束列表 | PEP 695 未提供等价的「约束列表」语法，只保留上界 | 用重载签名表达有限选择；🔧 以官方文档为准 |
| 注解 `abc.Sequence` 等具体容器 | 过度约束调用方 | 入参尽量 `Iterable[T]` / `Sequence[T]`，出参可具体 |
| 🔧 协议中声明 `@staticmethod` 的行为 | 静态检查与 `runtime_checkable` 下的行为存在边界差异 | 协议成员优先写实例方法；🔧 以 typing 规范为准 |
| 认为类型提示能替代测试（8.7 节的反面） | 类型管不了逻辑、边界值与集成 | 类型 + 测试双轨，`pytest` 仍是主力 |
| `NoReturn` 与 `None` 混用 | 语义完全不同：`NoReturn` 表示「控制流不会回来」 | 只用于 `sys.exit`、纯抛异常的辅助函数 |
