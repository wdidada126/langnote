## 核心精讲

### 21.5 `httpx` 异步下载（现代写法）

```python
# 教学示意，不参与构建 —— 需 pip install httpx
import asyncio, httpx

async def fetch(url):
    async with httpx.AsyncClient() as client:
        r = await client.get(url, timeout=5)
        return url, len(r.content)

async def main():
    urls = [f"https://example.com/{i}" for i in range(20)]
    results = await asyncio.gather(*(fetch(u) for u in urls))
    print(len(results))

asyncio.run(main())
```

### 21.7 信号量限制并发 + 结构化并发（3.11+）

```python
# 教学示意，不参与构建 —— Python 3.11+
import asyncio, httpx

async def fetch_all(urls, limit=10):
    sem = asyncio.Semaphore(limit)
    async with httpx.AsyncClient() as client:
        async def one(u):
            async with sem:
                r = await client.get(u, timeout=5)
                return u, len(r.content)
        # 🔴 TaskGroup：任一任务抛异常，其余被取消（结构化并发）
        async with asyncio.TaskGroup() as tg:
            tasks = [tg.create_task(one(u)) for u in urls]
        return [t.result() for t in tasks]

asyncio.run(fetch_all([f"https://example.com/{i}" for i in range(20)]))
```

## 版本演进

- 🔴 **3.11 `asyncio.TaskGroup` 与 `asyncio.timeout`**：结构化并发进标准库，取代原书用 `gather`/`wait` + 手动 `try` 的脆弱写法。本章 21.7 必须补 `TaskGroup`：任一子任务失败会取消整组，符合「结构化并发」直觉。
- 🔴 **PEP 654 — `ExceptionGroup`/`except*`（3.11）**：`TaskGroup` 取消时把多个异常聚合成 `ExceptionGroup`，配合 `except*` 分别处理（见 [18-with、match和else块.md](18-with、match和else块.md)）。
- **PEP 492 — `async`/`await`（3.5）**：原生协程基础，3.12+ 不变。
- **PEP 525 — Asynchronous Generators（3.6）**：`async for`/`async yield`，本章 21.10 的基础。
- **PEP 530 — Asynchronous Comprehensions（3.6）**：`[x async for x in ag]` 异步推导。
- **PEP 703 — free-threaded（3.13+）**：free-threaded 下 `asyncio` 仍受事件循环单线程约束，但底层 C 扩展可在持有锁外并行（🔧 以官方为准）。
- 🔴 原书 `aiohttp` 示例：2026 年 `httpx`（同步/异步统一 API）更主流，建议优先 `httpx`。
- 🔧 异步类型提示 `Awaitable`/`AsyncIterator` 在 PEP 695 下的泛型写法，以官方为准。

## 近年研究与工业界开源实践（2015–2026）

- **FastAPI 是 `asyncio` 的工业标杆**：依赖注入 + `async def` 路由，默认跑在 `uvicorn` 事件循环（非同行评审，框架文档）。
- **`httpx` 统一同步/异步客户端**：取代 `requests`（同步）与 `aiohttp`（异步）分裂，团队协作成本更低（非同行评审）。
- **Trio 的「nursery」影响官方 `TaskGroup`**：结构化并发理念从 Trio 进入 `asyncio`（3.11）（非同行评审，社区演进）。
- **`anyio` 做「asyncio/Trio 后端无关」抽象**：跨事件循环代码用 `anyio`（非同行评审）。
- **`py-spy`/`scalene` 定位「事件循环被阻塞」**：异步服务卡顿时先查是否有同步阻塞调用混进循环（非同行评审）。

## 常见误区与本书需修正之处

| 原书说法 / 习惯 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 用 `gather` + 手写 `try` 管理并发 | 一个任务失败不能自动取消其余 | 🔴 用 `asyncio.TaskGroup`（3.11）做结构化并发 |
| `aiohttp` 当默认异步客户端 | `httpx` 同步/异步统一 API 更主流 | 优先 `httpx.AsyncClient` |
| 在 `async` 函数里调阻塞 I/O | 阻塞调用卡住整个事件循环 | 用 `loop.run_in_executor` 桥接，或彻底异步库 |
| 把 CPU 密集塞进 `asyncio` | 单线程事件循环下 CPU 密集仍串行 | CPU 密集用进程/`run_in_executor`，或 free-threaded |
| 忽略 `TaskGroup` 取消语义 | 异常触发整组取消，可能误伤 | 明确「结构化并发」边界：`try/except*` 收尾 |
| 🔧 `asyncio` 与 free-threaded 的关系 | free-threaded 不消除事件循环单线程约束 | 以官方文档为准，区分「循环内并发」与「循环外并行」 |
