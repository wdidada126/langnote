# 第 10 章 使用一等函数实现设计模式（原书 pp.261–274）

> 一句话定位：本章用「函数是一等对象」消融《设计模式》里的类层级——策略模式下每个策略退化成一个函数，命令模式下每个命令退化成一个可调用物，抽象基类被函数签名取代。
> 基线：原书 Python 3.10；本目录按 3.12+ 校验。

## 核心精讲

### 一、经典策略模式：用抽象基类定义接口

```python
# 教学示意，不参与构建；本机 Python 3.13 验证通过
from dataclasses import dataclass

@dataclass
class Customer:
    name: str
    fidelity: int = 0

@dataclass(frozen=True)
class LineItem:
    product: str
    quantity: int
    price: float
    def total(self) -> float:
        return self.quantity * self.price

class Order:                       # 上下文对象
    def __init__(self, customer: Customer, cart, promotion=None):
        self.customer = customer
        self.cart = list(cart)
        self.promotion = promotion
        self._total: float | None = None

    def total(self) -> float:
        if self._total is None:
            self._total = sum(item.total() for item in self.cart)
        return self._total

    def due(self) -> float:
        discount = self.promotion(self) if self.promotion else 0.0
        return self.total() - discount

    def __repr__(self) -> str:
        return f'<Order total: {self.total():.2f} due: {self.due():.2f}>'
```

原书先用 `abc.ABC` + `@abstractmethod` 定义 `Promotion`，再为每种折扣写一个子类。这个结构的问题很直白：**每个策略只有一个方法、没有状态**，类只带来了样板代码。

### 二、用函数 + `Protocol` 实现策略（2026 年写法）

```python
# 教学示意，不参与构建；Python 3.13 验证通过；静态检查：mypy --strict
from typing import Protocol

class Promotion(Protocol):            # PEP 544：结构类型，不要求继承
    def __call__(self, order: Order) -> float: ...

def fidelity_promo(order: Order) -> float:
    """积分满 1000 的客户享 5% 折扣。"""
    return order.total() * 0.05 if order.customer.fidelity >= 1000 else 0.0

def bulk_item_promo(order: Order) -> float:
    """单个商品数量 ≥ 20 时该商品享 10% 折扣。"""
    return sum(item.total() * 0.10 for item in order.cart if item.quantity >= 20)

def large_order_promo(order: Order) -> float:
    """不同商品 ≥ 10 种时订单享 7% 折扣。"""
    return order.total() * 0.07 if len({item.product for item in order.cart}) >= 10 else 0.0

promos: list[Promotion] = [fidelity_promo, bulk_item_promo, large_order_promo]

def best_promo(order: Order) -> float:
    """选择最佳策略：只是对策略结果取最大值。"""
    return max(promo(order) for promo in promos)

joe = Customer('John Doe', 0)
ann = Customer('Ann Smith', 1100)
cart = [LineItem('banana', 4, 0.5), LineItem('apple', 10, 1.5), LineItem('watermelon', 5, 5.0)]
print(Order(joe, cart, fidelity_promo))     # <Order total: 42.00 due: 42.00>
print(Order(ann, cart, fidelity_promo))     # <Order total: 42.00 due: 39.90>
print(Order(joe, cart, best_promo))
```

`Protocol` 在这里承担了原书抽象基类的角色，但不要求策略「继承」任何东西：任何 `(Order) -> float` 的可调用物都满足契约，静态检查器会验证签名。这比 `abc.ABC` 更松（无需继承）、比 `Callable[[Order], float]` 更清晰（有名字、可复用、可写文档）。

### 三、收集策略：内省 vs 显式注册

```python
# 教学示意，不参与构建；Python 3.13 验证通过
import inspect

def all_strategies(module) -> list[Promotion]:
    """按命名约定内省模块，收集全部策略函数。"""
    return [obj for _, obj in inspect.getmembers(module, inspect.isfunction)
            if obj.__name__.endswith('_promo') and obj.__name__ != 'best_promo']

promo_registry: list[Promotion] = []

def promotion(fn: Promotion) -> Promotion:
    """注册装饰器：新增策略不必改动任何既有列表。"""
    promo_registry.append(fn)
    return fn

@promotion
def weekend_promo(order: Order) -> float:
    return order.total() * 0.03

print([f.__name__ for f in promo_registry])     # ['weekend_promo']
```

原书演示了用 `globals()` 找出所有以 `_promo` 结尾的函数。**2026 年的建议是优先用显式注册装饰器**：内省依赖命名约定，一旦策略被重命名、被 `functools.wraps` 包装或被延迟导入，就会静默漏掉；装饰器注册表则把「有哪些策略」变成了可测试的显式事实。内省方案的合理用途是插件发现（`importlib` + `pkgutil` 扫描包）。

### 四、需要配置或状态时：回到类或单分派

「用函数代替类」有明确边界，三种情况不该硬套函数：

| 情形 | 表现 | 建议 |
| --- | --- | --- |
| 策略需要配置参数 | 阈值、汇率、权重随实例变化 | 用数据类承载配置，再用 `singledispatch` 按配置类型分派 |
| 策略需要跨调用状态 | 累计用量、限流窗口、缓存 | 用 `__call__` 类，或闭包（第 9 章） |
| 策略需要多个方法 | 除 `discount()` 外还要 `describe()`、`is_applicable()` | 用类；接口仍可用 `Protocol` 描述 |

```python
# 教学示意，不参与构建；Python 3.13 验证通过
from dataclasses import dataclass
from functools import singledispatch

@dataclass(frozen=True)
class BulkSpec:
    threshold: int
    rate: float

@dataclass(frozen=True)
class FidelitySpec:
    min_points: int
    rate: float

@singledispatch
def discount(spec, order: Order) -> float:
    raise NotImplementedError(spec)

@discount.register
def _(spec: BulkSpec, order: Order) -> float:
    return sum(i.total() * spec.rate for i in order.cart if i.quantity >= spec.threshold)

@discount.register
def _(spec: FidelitySpec, order: Order) -> float:
    return order.total() * spec.rate if order.customer.fidelity >= spec.min_points else 0.0

print(discount(BulkSpec(20, 0.1), Order(joe, cart)))        # 0（该订单无单品 ≥ 20）
print(discount(FidelitySpec(1000, 0.05), Order(ann, cart))) # 2.1
```

这样既保留了「策略是可插拔数据」的配置能力，又不需要为每种配置写一个子类。另一个可选分派手段是 `match` 语句（PEP 634–636，3.10）：当分支依据是**值的结构**而不是类型时，`match` 更直接。

### 五、命令模式

```python
# 教学示意，不参与构建；Python 3.13 验证通过
class MacroCommand:
    """把一组命令攒起来一次执行；需要 undo/redo 时给每个命令加对应方法。"""
    def __init__(self, commands):
        self.commands = list(commands)

    def __call__(self) -> None:
        for command in self.commands:
            command()

log: list[str] = []
MacroCommand([lambda: log.append('open'), lambda: log.append('save')])()
print(log)      # ['open', 'save']
```

命令对象在 Python 里通常就是可调用物：无状态命令用函数，需要撤销/重做/日志等附加行为时用带 `__call__` 的类。原书借的是《设计模式》里的 MacroCommand/菜单场景，落到 Python 上就是「把函数放进列表」。

## 近年研究与工业界开源实践（2015–2026）

| 主题 | 现状 | 实践建议 |
| --- | --- | --- |
| 策略接口的表述方式 | `Protocol`（PEP 544）已成为库作者描述「回调契约」的首选，ABC 退居需要运行时 `isinstance` 注册的场景 | 新代码优先 `Protocol`；需要虚拟子类注册时才用 `abc.ABC`（第 13 章） |
| 依赖注入与策略注册 | FastAPI/Django/pytest 等用装饰器 + 类型注解做注册与注入 | 显式注册表 + 类型注解，比 `globals()` 内省可测可查 |
| 分派手段的三分天下 | `singledispatch`（按类型、跨模块可扩展）、`match`（按结构、集中）、字典/映射（运行时可配置） | 按「分派依据」选型，而不是统一用一种 |
| 配置化策略 | 数据类（PEP 557）+ `frozen=True` 承载策略参数，配合 pydantic 做外部校验 | 把策略参数做成不可变数据对象，便于序列化与对比 |
| 无状态化的收益 | 无状态函数天然可并行、可缓存（`functools.cache`） | 能写成纯函数的策略就别写成类 |
| 🔧 基于注解的插件发现 | 3.14 起注解延迟求值，`__annotations__` 需经 `annotationlib` 读取 | 🔧 迁移方案以官方文档与所用框架 release note 为准 |

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 用 `abc.ABC` + `@abstractmethod` 定义策略接口 | 需要显式继承，对第三方函数不友好 | 用 `Protocol`（PEP 544）；仅当需运行时注册虚拟子类时保留 ABC |
| `Callable[[Order], float]` 足以描述策略 | 无名字、无文档、无法在错误信息里指代 | 具名 `Protocol` + `__call__`，可读性与复用性都更好 |
| 用 `globals()` 内省收集策略 | 依赖命名约定，包装/延迟导入时会漏 | 用注册装饰器 + 显式列表；插件发现场景再考虑 `inspect.getmembers` |
| 「函数能替代一切类」 | 有配置、有状态、多方法的策略用函数会失控 | 配置 → 数据类 + `singledispatch`；状态 → `__call__` 类；多方法 → 类 |
| 认为 `singledispatch` 可按任意参数分派 | 只按第一个参数 | 把配置对象放第一个参数，或用 `match` / 映射分派 |
| 折扣示例用可变 dataclass 承载策略配置 | 配置被意外修改导致结果不可复现 | `@dataclass(frozen=True)`（PEP 557），必要时 `slots=True` |
| 🔧 3.14 后基于 `__annotations__` 做策略发现 | PEP 649 改变注解求值时机 | 改用 `annotationlib.get_annotations()` / `typing.get_type_hints()`；🔧 以官方文档为准 |
| 命令对象必须实现 `execute()` 方法 | Python 中「可调用」就是命令 | 无状态用函数；需 undo 时用带 `__call__` 与 `undo()` 的类 |
