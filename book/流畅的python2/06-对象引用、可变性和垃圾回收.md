## 核心精讲

### 6.3 `==` 与 `is`：值相等 vs 身份相等

```python
# 教学示意，不参与构建 —— Python 3.13 可直接运行
a = [1, 2, 3]
b = [1, 2, 3]
print(a == b)   # True：值相等
print(a is b)   # False：不是同一个对象，id(a) != id(b)

c = a
print(a is c)   # True：c 是 a 的别名

# 🔧 唯一应该使用 is 的场景：与单例比较
x = None
print(x is None)   # 正确写法；写成 x == None 会被 __eq__ 重载误导
```

`==` 调用 `__eq__`，可被用户类重写；`is` 直接比 `id()`，不可重载。因此判断「是不是那个唯一的 `None`」必须用 `is`。

### 6.5.1 可变默认值陷阱（全站最高频面试题）

```python
# 教学示意，不参与构建
def add_item(item, bucket=[]):      # ⚠️ 默认值在 def 时只创建一次
    bucket.append(item)
    return bucket

print(add_item(1))   # [1]
print(add_item(2))   # [1, 2]  —— 上一次调用的副作用泄露了！
print(add_item(3))   # [1, 2, 3]

# 正确写法：用 None 哨兵
def add_item_ok(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

### 6.4 浅拷贝：嵌套结构仍是同一个对象

```python
# 教学示意，不参与构建
import copy
a = [1, [2, 3]]
b = a[:]                       # 切片=浅拷贝
b[0] = 9                       # 外层元素独立
b[1].append(4)                 # 内层列表仍共享！
print(a)                       # [1, [2, 3, 4]]  —— a 被意外修改
c = copy.deepcopy(a)           # 深拷贝才彻底断开
```

## 版本演进

- **3.12 `immortal objects`**（🔧 以官方文档为准，详见 PEP 683）：解释器内部的一些不可变单例（如 `None`、`True`、`False`、小整数）被标为「永生」，引用计数不再变化。这让多解释器（PEP 684）共享这些对象时无需原子操作，但**不改变用户可见语义**，只影响性能与引用计数观察（`sys.getrefcount` 看不到变化）。
- **3.13 free-threading（PEP 703，实验性）**：在 `--disable-gil` 构建（`python3.13t`）中，对象回收不再依赖 GIL 保护的引用计数，改用更细的锁或原子计数。本章关于「`del` 立即回收」的结论在 free-threaded 下**不保证**实时发生，并发释放要显式同步。
- 3.7+ 的字典保序（PEP 520，🔧 编号以官方为准）让 `==` 对 dict 的比较既比内容也比顺序——但自 3.7 顺序已是语言保证，故「无序字典相等」的情形已不存在。
- 小整数驻留范围、字符串驻留策略在不同 CPython 版本间有微调，属实现细节，跨版本/跨实现（PyPy、GraalPy）**不可依赖**。

## 经典论文与原始文献

- PEP 8 — Style Guide for Python Code（2001）。规范文档，非同行评审论文。要求与 `None` 比较一律用 `is`/`is not`。
- PEP 20 — The Zen of Python。规范文档。「Explicit is better than implicit」直接支撑「默认值用 `None` 哨兵」的写法。
- PEP 683 — Immortal Objects（🔧 以官方文档为准，3.12 引入）。规范文档，解释永生对象的引用计数豁免。
- PEP 703 — Making the Global Interpreter Lock Optional in CPython（3.13 实验性）。https://peps.python.org/pep-0703/ 。规范文档，free-threaded 构建对对象生命周期的影响来源。
- Python 语言参考「Data model」章节（3.1 节「Objects, values and types」「id()」「is」）。官方文档，本章身份/相等语义的权威口径。
- `gc` — Python 标准库 `gc` 模块文档，处理循环引用的垃圾回收。https://docs.python.org/3/library/gc.html

## 近年研究与工业界开源实践（2015–2026）

- **`weakref` 在缓存中的使用**：`weakref.WeakValueDictionary` 让缓存不阻止值对象被回收，是避免「内存泄漏式驻留」的工业界标准做法（非同行评审，标准库实践）。
- **mypy/pyright 的 `MutableDefault` / `UnspecifiedValue` 检查**：现代类型检查器能静态捕获「可变默认值」与「未标注返回类型」，把 6.5.1 的坑前移到编辑期。
- **3.11 Faster CPython 的对象头瘦身**：每个对象的内存头从 8 字节约简，使 6.7 提到的「不可变类型把戏」对小对象更省内存；但 `sys.getsizeof` 的观测值随之变化（非同行评审，speed.python.org 基准）。
- **free-threaded 生态**：NumPy、pyarrow 等已陆续发布 `--disable-gil` 兼容构建；本章关于引用计数的结论在它们内部已切换为原子计数（工业界公告，以官方为准）。

## 常见误区与本书需修正之处

| 原书说法 / 习惯 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 「`is` 比 `==` 快」所以能用 `is` 比较值 | `is` 只比身份，值相等的两个对象可能不是同一对象 | `is` 仅用于 `None`/单例/枚举成员；值比较一律 `==` |
| 默认参数 `bucket=[]` 当成「每次调用新建列表」 | 默认值在 def 时求值一次，跨调用共享 | 用 `bucket=None` 哨兵，函数体内部 `if bucket is None: bucket = []` |
| 认为 `tuple` 完全不可变 | 元组内的可变元素仍可改 | 区分「容器不可变」与「元素不可变」；「相对不可变性」 |
| `copy.copy` 能断开所有共享 | 浅拷贝只复制顶层 | 嵌套结构用 `copy.deepcopy` |
| `del x` 会「销毁对象」 | `del` 只删除名字绑定，对象可能因其他引用仍存在 | 对象回收取决于引用计数归零或 GC 回收循环引用 |
| 依赖小整数/短字符串驻留优化 | 驻留是 CPython 实现细节 | 不要用 `is` 比较整数/字符串；跨实现（PyPy/GraalPy）不可靠 |
| 🔧「3.12 起 `is` 对 `None` 不变」之外的身份语义 | immortal objects 改变了内部计数但不改变用户语义 | 用户层结论不变；仅性能/观察层面变化，以官方为准 |
