## 核心精讲

### 23.2 一个简单描述符（覆盖型）

```python
# 教学示意，不参与构建
class Quantity:                 # 覆盖型描述符：实现 __set__
    def __init__(self, storage_name):
        self.storage_name = storage_name
    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError("必须为正")
        instance.__dict__[self.storage_name] = value   # 直接落实例 __dict__

class LineItem:
    weight = Quantity("weight")     # 类属性是描述符实例
    price = Quantity("price")
    def __init__(self, weight, price):
        self.weight = weight         # 触发 Quantity.__set__
        self.price = price

# LineItem(1, 2) 合法；LineItem(-1, 2) 抛 ValueError
```

### 23.3 覆盖型 vs 非覆盖型

```python
# 教学示意，不参与构建 —— 展示优先级差异
class Overriding:         # 有 __set__：覆盖型
    def __get__(self, obj, cls): return "覆盖型读"
    def __set__(self, obj, val): obj.__dict__["x"] = val

class NonOverriding:      # 只有 __get__：非覆盖型
    def __get__(self, obj, cls): return "非覆盖型读"

# 覆盖型描述符压过实例同名字段；非覆盖型会被实例属性遮蔽
```

### 23.4 方法是描述符

```python
# 教学示意，不参与构建
class Demo:
    def method(self): ...

d = Demo()
# d.method 等价于 Demo.__dict__['method'].__get__(d, Demo)
# 即：函数.__get__ 把「函数」绑成「绑定方法」，自动塞入 self
import types
print(isinstance(Demo.method, types.FunctionType))   # True：函数是描述符
```

## 版本演进

- **PEP 487 — `__set_name__`（3.6）**：描述符在类创建时自动收到属性名，省去 23.2 手传 `storage_name`（如 `Quantity("weight")`）。本章示例可简化为 `weight = Quantity()`，名字由 `__set_name__` 注入。
- **PEP 557 — `dataclasses`（3.7）**：`@dataclass` 的字段校验可视为「描述符的声明式封装」，与 23.2 呼应（见 [05-数据类构建器.md](05-数据类构建器.md)）。
- **PEP 552 / `cached_property`**：`functools.cached_property` 本身是个描述符（非覆盖型 + 缓存），是 23.5 用法建议的现代补充（见 [22-动态属性和特性.md](22-动态属性和特性.md)）。
- 3.12 `immortal objects`（PEP 683，🔧 以官方为准）：对描述符协议语义无影响，仅影响内部单例性能。
- 🔧 关于 PEP 695 是否影响描述符泛型（`class Validated[T]` 风格校验器），以官方文档为准。

## 近年研究与工业界开源实践（2015–2026）

- **`pydantic` 的 `Field`/`validator` 是描述符的工业封装**：模型字段校验本质用描述符实现，比手写 `Quantity` 更完整（非同行评审，框架文档）。
- **`sqlalchemy` 的 `Column` 描述符**：ORM 列即描述符，把「类属性访问」映射到「行数据读写」（非同行评审）。
- **`cached_property`/`classmethod`/`staticmethod` 全是标准库描述符**：本章「方法是描述符」是理解它们的钥匙（非同行评审）。
- **`__set_name__` 让校验器免手传字段名**：工业校验库普遍依赖它（非同行评审）。

## 常见误区与本书需修正之处

| 原书说法 / 习惯 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 描述符手传 `storage_name` | 重复、易拼错 | 3.6+ 用 `__set_name__` 自动拿名字 |
| 混淆覆盖型/非覆盖型 | 优先级错导致属性「读不到/写不进」 | 记住：有 `__set__` = 覆盖型，压过实例属性 |
| 以为 `property` 是特例 | `property` 就是个描述符 | 理解协议后 `property`/`classmethod`/`staticmethod` 一通百通 |
| 为每个字段写专属描述符类 | 重复代码 | 用通用描述符 + `__set_name__`，或上 `pydantic`/`attrs` |
| 在描述符里存状态到错误地方 | 存到类属性会跨实例共享 | 描述符应把值存到 `instance.__dict__[name]` |
| 🔧 描述符与 `__slots__` 共存 | 槽对象没有 `__dict__`，覆盖型描述符存值要换键 | 以官方文档为准；通常描述符管理的属性不进 `__slots__` |
