# 第 12 章 序列的特殊方法（原书 pp.305–328）

## 核心精讲

### 一、协议与鸭子类型：不继承也是序列

```python
# 教学示意，不参与构建；本机 Python 3.13 验证通过
from collections.abc import Iterable, Sequence

class Seq:                                   # 只实现三个方法的最小「序列」
    def __init__(self, items): self._items = list(items)
    def __len__(self): return len(self._items)
    def __getitem__(self, index): return self._items[index]
    def __iter__(self): return iter(self._items)

v = Seq([3, 4, 5])                           # 本章的 Vector 同理
print(len(v), v[0], 5.0 in v, list(reversed(v)))   # 协议带来的能力
print(isinstance(v, Iterable))               # True：Iterable/Sized 做结构检查
print(isinstance(v, Sequence))               # False：Sequence 不做结构检查，需显式继承或注册
```

这正是本章的核心结论：**「是不是序列」由行为决定，不由继承决定**。`for`、`in`、`len()`、拆包、切片语法都只依赖 `__len__`/`__getitem__`/`__iter__` 这几个方法的存在。注意一处落差：只实现 `__len__` + `__getitem__` 时，`in` 与 `reversed()` 依然可用（走旧式迭代协议），但 `isinstance(v, Iterable)` 会是 `False`——`Iterable` 的结构检查要求显式有 `__iter__`。需要 `isinstance` 判定时有两个选择：继承 `collections.abc.Sequence`（PEP 3119）拿 mixin 方法并接受名义子类型约束；或用静态协议 `Sequence[T]` 只做静态检查（PEP 544）。原书的 `Vector` 两者都不做——这是刻意的设计取舍。

### 二、切片原理（12.5.1）

```python
# 教学示意，不参与构建；Python 3.13 验证输出
class Probe:
    def __getitem__(self, index):
        return index            # 原样返回，看解释器到底传了什么

p = Probe()
print(p[1:3])                   # slice(1, 3, None)
print(p[1:4:2])                 # slice(1, 4, 2)
print(p[1:3, 5:7])              # (slice(1, 3, None), slice(5, 7, None)) 多维切片变成元组
print(slice(None, 10, 2).indices(5))            # (0, 5, 2)
print(list(range(*slice(None, 10, 2).indices(5))))   # [0, 2, 4]
print(slice(-3, None, None).indices(5))         # (2, 5, 1)
```

`slice.indices(len)` 是切片实现的关键工具：它把 `None`、负数、越界都**规范化**成适配长度的 `(start, stop, stride)` 三元组，再交给 `range(*...)` 展开成具体下标。自己实现切片语义时永远先用它，别手算边界。

### 三、能处理切片的 `__getitem__`

```python
# 教学示意，不参与构建；Python 3.13 验证通过
import numbers

def __getitem__(self, index):
    cls = type(self)
    if isinstance(index, slice):                 # 切片 → 返回同类新实例
        return cls(self._components[index])
    elif isinstance(index, numbers.Integral):    # 整数 → 返回标量
        return self._components[index]
    else:
        raise TypeError(f'{cls.__name__} indices must be integers or slices')
```

两条约定：切片**返回同类型的新对象**（保持 `type(self)` 以便子类正确工作），整数索引**返回元素**。用 `numbers.Integral` 而非 `int`，可容纳 `numpy.int64` 等第三方整数类型。

### 四、动态存取属性：`__getattr__`（12.6）

```python
# 教学示意，不参与构建；Python 3.13 验证通过
class Vector:
    typecode = 'd'
    shortcut_names = 'xyzt'

    def __getattr__(self, name):
        cls = type(self)
        if len(name) == 1:                       # 只处理单字母，避免误吞 dunder 查找
            pos = cls.shortcut_names.find(name)
            if 0 <= pos < len(self._components):
                return self._components[pos]
        raise AttributeError(f'{cls.__name__!r} object has no attribute {name!r}')

    def __setattr__(self, name, value):
        cls = type(self)
        if len(name) == 1 and name in cls.shortcut_names:
            raise AttributeError(f'readonly attribute {name!r}')
        super().__setattr__(name, value)

v = Vector([3, 4, 5])
print(v.x, v.y, v.z)            # 3.0 4.0 5.0
```

三条铁律：
1. `__getattr__` **只在常规属性查找失败后**被调用，因此它比 `__getattribute__` 安全得多——需要拦全部属性访问时才用后者（第 22 章）。
2. 一律用 `type(self)` 而不是硬编码类名，子类才能继承行为。
3. 找不到就抛 `AttributeError`（带明确信息），否则 `hasattr()`、`copy`、`pickle` 这类靠 dunder 探测的代码会拿到错误结果。

### 五、哈希与快速等值测试（12.7）

```python
# 教学示意，不参与构建；Python 3.13 验证通过
import operator
from functools import reduce

def __hash__(self):
    return reduce(operator.xor, (hash(x) for x in self), 0)   # 逐元素异或归约

def __eq__(self, other):
    if isinstance(other, Vector):
        return len(self) == len(other) and all(a == b for a, b in zip(self, other))
    return NotImplemented
```

`zip` 会在较短一方结束时静默停止，所以**必须先比长度**——否则 `Vector([3,4]) == Vector([3,4,5])` 会得出错误的 `True`。哈希用 `reduce(operator.xor, ...)` 而非 `hash(tuple(self))`：前者是惰性生成器，对大向量不必先构造整个元组；语义上与「对分量哈希做异或」等价且可交换顺序。

### 六、格式化：自定义格式规范（12.8）

```python
# 教学示意，不参与构建；Python 3.13 验证通过
import itertools, math

def angle(self, n: int) -> float:
    r = math.sqrt(sum(x * x for x in self[n:]))
    a = math.atan2(r, self[n - 1])
    if (n == len(self) - 1) and (self[-1] < 0):
        return math.pi * 2 - a
    return a

def angles(self):
    return (self.angle(n) for n in range(1, len(self)))

def __format__(self, fmt_spec: str = '') -> str:
    if fmt_spec.endswith('h'):                    # 'h' = 超球坐标（模长 + 各角度）
        fmt_spec = fmt_spec[:-1]
        coords = itertools.chain([abs(self)], self.angles())
        outer_fmt = '<{}>'
    else:
        coords, outer_fmt = self, '({})'
    return outer_fmt.format(', '.join(format(c, fmt_spec) for c in coords))

print(format(Vector([3, 4, 5]), '.3eh'))   # <7.071e+00, 1.133e+00, 8.961e-01>
print(f'{Vector([3, 4, 5]):.2f}')          # (3.00, 4.00, 5.00)：f-string 同样走 __format__
```

要点：`__format__` 收到的只是冒号后的格式规范；用 `itertools.chain` 把标量与生成器串起来，避免在内存里拼出中间列表。

### 七、五版演进体现的协议设计原则

| 版本 | 新增能力 | 背后的方法 |
| --- | --- | --- |
| 第 1 版 | 可迭代、可索引、可拆包 | `__iter__` / `__len__` / `__getitem__` |
| 第 2 版 | 切片 | `__getitem__` 处理 `slice` |
| 第 3 版 | `v.x` 这类动态属性 | `__getattr__` / `__setattr__` |
| 第 4 版 | 可哈希、等值快速失败 | `__hash__` / `__eq__` |
| 第 5 版 | 自定义格式化 | `__format__` |

原则：**一类能力对应一组方法，按需实现**；不要为了「看起来完整」而实现不相关的方法，也不要靠继承来「自动获得」自己没实现的行为。

## 近年研究与工业界开源实践（2015–2026）

| 主题 | 现状 | 实践建议 |
| --- | --- | --- |
| 序列协议的实现方式 | 静态协议（PEP 544）渐成主流：注解写 `Sequence[float]`，实现方不必继承 | 新代码用 `Sequence[T]` 做静态约束，只在需要 mixin 时继承 `abc.Sequence` |
| 惰性求值 | 3.11 Faster CPython 后，生成器表达式与 `iter()` 的开销进一步下降 | 大向量/大数据集坚持惰性；`__iter__` 直接 `return iter(self._components)` |
| 科学计算生态 | `numpy`/`pandas` 用 `__array__`、`__dataframe__` 等协议互操作（第三方约定，非 PEP） | 自定义序列要对接生态时，实现对应的互操作协议而非继承它们的类 |
| 动态属性的风险 | `__getattr__` 被广泛用于 ORM、配置对象、JSON 包装器（第 22 章有完整案例） | 严格限制接受的属性名，找不到必须抛 `AttributeError` |
| 哈希与不可变性 | 现代实践是「可哈希即不可变」：需要哈希就用 `frozen` 数据类或只读 property | 可变的 `Vector` 不该实现 `__hash__`；本章因只读属性才可哈希 |
| 格式化新动向 | 3.14 的 t-string（PEP 750）把「插值」与「转义」解耦 | 🔧 语法与 API 以官方文档为准，暂不在生产代码依赖 |

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 「是序列」就要继承 `collections.abc.Sequence` | 继承会带入 mixin 与名义类型约束，多数场景不需要 | 实现 `__len__` + `__getitem__` 即可；静态检查用 `Sequence[T]`（PEP 544） |
| `isinstance(v, Sequence)` 能测出「像序列」 | `Sequence` 不做结构检查，结果为 `False` | 用 `iter(v)` / `len(v)` 这类行为测试；或用 `runtime_checkable` 的自定义协议 |
| 自己算切片边界 | 负数、`None`、越界情况极易出错 | 一律 `slice.indices(len)` + `range(*...)` |
| `__getitem__` 用 `isinstance(index, int)` | 排除第三方整数类型 | `isinstance(index, numbers.Integral)` |
| 切片返回列表 | 破坏类型一致性，`type(self)` 的子类会退化 | 切片返回 `type(self)(...)` 新实例 |
| `__getattr__` 里返回默认值 | `hasattr`、`copy`、`pickle` 会拿到错误结果 | 只接受约定的属性名，其余抛 `AttributeError` |
| `__eq__` 直接 `zip` 比较 | 长度不同会被静默截断成 `True` | 先比 `len` 再 `zip` |
| 可变对象实现 `__hash__` | 作为字典键后会因状态变化而「丢失」 | 只在不可变（只读属性 / frozen）时实现 |
| 🔧 3.14 后靠 `__annotations__` 推断元素类型 | PEP 649 改变求值时机 | 用 `annotationlib.get_annotations()` / `typing.get_type_hints()`；🔧 以官方文档为准 |
| 🔧 t-string 与 `__format__` 的关系 | 3.14 才引入，本章写作时不存在 | 🔧 t-string 语法与 API 以官方文档为准 |
