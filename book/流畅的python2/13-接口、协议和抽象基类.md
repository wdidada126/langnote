# 第 13 章 接口、协议和抽象基类（原书 pp.332–370）

> 一句话定位本章：Python 里「接口」有两条路——运行时鸭子类型（协议靠「有没有这个方法」判定）与静态大鹅类型（`abc`/`Protocol`），本章把二者讲透并给出取舍。
> 基线：原书 Python 3.10；本目录按 3.12+ 校验。

## 核心精讲

### 13.4 鸭子类型：不继承也能当序列

```python
# 教学示意，不参与构建
class Foo:
    def __getitem__(self, index):
        return range(10)[index]

f = Foo()
print(list(f))          # [0, 1, 2, ..., 9] —— 因实现了 __getitem__ 就「可迭代」
print(2 in f)           # True
# 注意：Foo 从不继承 Sequence / Iterable，却能被 for 当成序列用
```

### 13.5 大鹅类型：用 `abc` 显式声明

```python
# 教学示意，不参与构建
import abc

class Tombola(abc.ABC):
    @abc.abstractmethod
    def load(self, iterable): ...
    @abc.abstractmethod
    def pick(self): ...

class BingoCage(Tombola):
    def load(self, iterable): self._items = list(iterable)
    def pick(self): return self._items.pop()

print(isinstance(BingoCage([1, 2]), Tombola))   # True
```

### 13.6 静态协议：结构子类型，无需继承

```python
# 教学示意，不参与构建 —— 需 mypy / pyright 静态检查
from typing import Protocol

class Sized(Protocol):
    def __len__(self) -> int: ...

def print_len(obj: Sized) -> None:
    print(len(obj))

print_len([1, 2, 3])     # list 满足协议，无需继承 Sized
print_len("abc")         # str 也满足
```

## 版本演进

- **PEP 544 — Protocols（3.8）**：静态协议进入标准库（`typing.Protocol`）。本章 13.6 的核心，也是原书第 2 版相对第 1 版最大的新增。2026 年仍是定义「接口形状」的首选静态手段。
- **PEP 612 — ParamSpec（3.10）**：让回调协议能精确传递参数，配合 `Protocol` 描述高阶函数式接口（🔧 原书未强调，以官方为准）。
- **PEP 673 — Self（3.11）**：在协议/接口里描述「返回自身类型」更顺手，`def clone(self) -> Self`。
- **PEP 698 — `@override`（3.12）**：配合 ABC 时，可用 `@override` 标注「我确实覆盖了抽象方法」，静态检查器据此发现漏写。
- 3.12 `typing.Protocol` 的成员检测边界：非 `runtime_checkable` 的协议对 `isinstance` 会抛 `TypeError`，本章 13.6.3 已讲，3.12 后行为一致。

## 近年研究与工业界开源实践（2015–2026）

- **`typing.Protocol` 在 FastAPI / pydantic 中的使用**：用结构子类型描述「可注入的依赖长什么样」，取代繁琐的 ABC 继承（非同行评审，框架文档）。
- **`runtime_checkable` 的工业实践边界**：如 `pytest`、SQLAlchemy 用协议做静态提示，但运行时仍靠鸭子类型探测，避免 `isinstance` 开销（非同行评审）。
- **`zope.interface` 仍在重型框架（Twisted、Pyramid）中使用**：它是「显式接口 + 适配注册」的工业级方案，`abc` 只覆盖其一部分（非同行评审）。
- **类型检查器现状**：mypy 与 pyright 对 `Protocol` 的「显式声明 vs 隐式结构匹配」有细微差异；复杂协议建议以 pyright 为准交叉验证（非同行评审）。

## 常见误区与本书需修正之处

| 原书说法 / 习惯 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 认为鸭子类型「无需任何声明」 | 全靠运行时方法探测，重构时接口悄悄失效 | 需要文档化/静态保证时改用 `Protocol` |
| `Protocol` 子类能 `isinstance` 检查 | 非 `runtime_checkable` 的协议对 `isinstance` 抛 `TypeError` | 仅用 `@runtime_checkable` 标注的协议支持 `isinstance`，且只检查显式方法 |
| ABC 能替代一切接口 | ABC 是名义类型，需显式继承/注册，耦合更重 | 轻接口用 `Protocol`；需 `isinstance`/混入默认实现再用 ABC |
| `register` 虚拟子类会检查方法实现 | `register` 只是「声明」，不验证是否真实现方法 | `register` 是信任声明，漏实现会在调用时才炸 |
| 🔧「Protocol 的静态方法限制」 | 早期 mypy 对协议里 `@staticmethod` 行为有争议 | 以 typing 规范/pyright 当前行为为准，不要凭旧经验下笔 |
| 把 `numbers.Number` 当万能数值协议 | 数值塔分 `Complex/Real/Integral` 多层 | 按精度需求选 `numbers.Real` 等，而非笼统 `Number` |
