## 核心精讲

### 15.2 `@overload`：静态分派，非运行时

```python
# 教学示意，不参与构建 —— 用 mypy/pyright 静态检查
from typing import overload

@overload
def process(x: int) -> int: ...
@overload
def process(x: str) -> str: ...
def process(x):
    return x            # 真实实现只有一个，overload 仅为检查器

reveal_type(process(1))     # int
reveal_type(process("a"))   # str
```

### 15.6 泛型类：旧写法 vs PEP 695 新写法

```python
# 教学示意，不参与构建
from typing import Generic, TypeVar

T = TypeVar("T")            # ⚠️ 旧写法（原书 3.10 基线）

class Stack(Generic[T]):
    def push(self, item: T) -> None: ...
    def pop(self) -> T: ...

# ✅ 3.12+ PEP 695 写法：更简洁、作用域更干净
type Stack[T] = ...         # 类型别名新写法（仅示例，完整见下）
# class Stack[T]:           # PEP 695：直接在类头声明泛型参数
#     def push(self, item: T) -> None: ...
```

## 版本演进

- 🔴 **PEP 695 — Type Parameter Syntax（3.12）**：`def f[T](...)`、`class C[T]`、`type Alias[T] = ...` 取代 `TypeVar`/`TypeVarTuple`/`ParamSpec` 旧写法。这是本章最重大的修正——原书全用旧写法，2026 年应双轨呈现并优先新写法。
- **PEP 673 — Self（3.11）**：`def clone(self) -> Self` 替代 `TypeVar("S", bound="MyClass")` 的笨拙写法。
- **PEP 647 — User-Defined Type Guards（🔧 以官方为准）**：`TypeGuard` 让 `isinstance` 式收窄可类型化；`TypeIs`（3.13，🔧 以官方为准）进一步细化。
- 🔴 **PEP 649 — Deferred Evaluation of Annotations（3.14）**：注解默认延迟求值，改变 15.5 节「运行时会立即求值/字符串化」的结论；`get_type_hints` 与新语义的差异必须重写。
- **PEP 563 — 延迟注解（`from __future__ import annotations`，3.7）**：在 3.14 之前是「让注解不立即求值」的主要手段；3.14 注解延迟求值成为默认后，`from __future__ import annotations` 的定位变为「与未来对齐的兼容写法」（🔧 以官方 What's New 为准）。
- **PEP 692 — `Unpack` for `**kwargs` typing（🔧 以官方为准，3.12）**：给 `**kwargs` 加 `TypedDict` 型提示，是现代补充。
- **PEP 698 — `@override`（3.12）**：见 14 章，类型层也能标覆盖。

## 近年研究与工业界开源实践（2015–2026）

- **mypy 与 pyright 双主导**：mypy（PSF 官方）偏严格、pyright（Microsoft）偏快且对 PEP 695 支持积极；工业项目常按团队选其一进 CI（非同行评审）。
- **`pydantic` / `attrs` / `dataclasses` 在 `TypedDict` 生态的分工**：配置用 `pydantic`（运行时校验），纯类型标注用 `TypedDict`，见 [05-数据类构建器.md](05-数据类构建器.md)。
- **`typing_extensions` 作为前沿试验田**：PEP 695/649/673 等新特性先落 `typing_extensions`，再进标准库，跨版本兼容靠它（非同行评审）。
- **泛型在 FastAPI/SQLAlchemy 的工业实践**：`Page[T]`、`Repository[T]` 等泛型接口已成标配（非同行评审，框架文档）。

## 常见误区与本书需修正之处

| 原书说法 / 习惯 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 全用 `T = TypeVar('T')` 旧写法 | 3.12 起有更简洁的 `class C[T]` | 改用 PEP 695 语法；旧写法仍可用但属遗留 |
| 15.5 认为注解「运行时会立即求值」 | 3.14 PEP 649 默认延迟求值 | 3.14 起注解默认惰性；`get_type_hints` 行为随之调整，🔧 以官方为准 |
| `from __future__ import annotations` 当「终局方案」 | 3.14 后延迟求值是默认，该 import 变为兼容态 | 理解为「提前对齐未来语义」，非必须 |
| `TypeGuard` 与 `TypeIs` 混用 | `TypeIs` 是更精确的「双向收窄」（3.13） | 🔧 以官方为准选 `TypeIs` 做严格收窄 |
| 重载靠运行时 `if isinstance` 分支 | `@overload` 只是给检查器的声明，运行时只一个实现 | 不要指望 `overload` 做运行时分派 |
| 🔧 PEP 692 `Unpack[**kwargs]` 的 `TypedDict` | 原书未涉及 kwargs 定型 | 以官方文档为准补充 `**kwargs` 结构化提示 |
