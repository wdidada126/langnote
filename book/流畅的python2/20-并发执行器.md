# 第 20 章 并发执行器（原书 pp.572–594）

> 一句话定位本章：`concurrent.futures` 用「执行器 + future」把线程池/进程池统一成一套 API，让并发下载这类任务从「手写线程」退化成「提交 callable + 收结果」。

## 核心精讲

### 20.2.2 线程池并发下载

```python
# 教学示意，不参与构建 —— 需 pip install requests
import concurrent.futures, requests

URLS = [f"https://example.com/{i}" for i in range(20)]

def get(url):
    return url, len(requests.get(url, timeout=5).content)

with concurrent.futures.ThreadPoolExecutor(max_workers=8) as ex:
    futures = [ex.submit(get, u) for u in URLS]
    for fut in concurrent.futures.as_completed(futures):
        url, size = fut.result()       # 按完成顺序拿到结果
        print(url, size)
```

### 20.5 `as_completed` 与错误隔离

```python
# 教学示意，不参与构建
with concurrent.futures.ThreadPoolExecutor() as ex:
    futures = {ex.submit(get, u): u for u in URLS}
    for fut in concurrent.futures.as_completed(futures):
        try:
            fut.result()               # 异常在这里重新抛出，可被单独捕获
        except requests.RequestException as e:
            print("失败:", futures[fut], e)
```

## 版本演进

- **PEP 654 — ExceptionGroup 与 `except*`（3.11）**：当多个 future 同时失败，`as_completed` 循环里逐个 `try/except` 仍可用，但 3.11+ 也支持把一批异常聚合成 `ExceptionGroup` 用 `except*` 处理——是并发错误聚合的现代写法。
- **PEP 3148 — `concurrent.futures`（3.2）**：执行器抽象源头，3.12+ 不变。
- **PEP 703 — free-threaded（3.13+）**：free-threaded 构建下，`ThreadPoolExecutor` 跑 CPU 密集任务也能真正并行，模糊了「线程 vs 进程」的边界，但 `ProcessPoolExecutor` 的隔离性（崩溃不影响主进程）仍是优势。
- 🔧 关于 `ProcessPoolExecutor` 在 free-threaded 下的 pickling 要求是否放宽，以官方文档为准（仍是「可 pickle 的 callable + 参数」）。
- 3.9 `concurrent.futures` 已有 `ThreadPoolExecutor` 的 `initializer`/`initargs`，3.12+ 行为一致。

## 近年研究与工业界开源实践（2015–2026）

- **`requests` + 线程池是「并发下载」的工业基线**：简单可靠，仍是许多脚本首选（非同行评审）。
- **`httpx` 的「线程池 + 异步」双模式**：`httpx` 既支持同步（配 `ThreadPoolExecutor`）也支持异步（配 `asyncio`），与 21 章衔接（非同行评审）。
- **`tqdm` + `as_completed` 做进度条**：工业脚本标配（非同行评审）。
- **`ray`/`dask` 取代手写进程池做大规模 CPU 计算**：任务图调度比手动 `ProcessPoolExecutor` 更易扩展（非同行评审）。
- **`ProcessPoolExecutor` 的 `mp_context` 与 `fork` 弃用**：3.14 macOS 默认不再 `fork`，多进程启动方式要显式指定（🔧 以官方为准）。

## 常见误区与本书需修正之处

| 原书说法 / 习惯 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 用线程池跑 CPU 密集任务 | GIL 下 CPU 密集仍串行 | CPU 密集用 `ProcessPoolExecutor`（或 free-threaded） |
| 认为 `Future` 就是结果 | `Future` 是「未完成结果的句柄」 | 用 `.result()` 取，且会重抛异常 |
| `executor.map` 按完成顺序返回 | `map` 严格按输入顺序，慢任务阻塞快任务 | 要按完成顺序用 `as_completed` |
| 忽略 future 异常 | 异常藏在 future 里被吞 | `result()` 会重抛，必须 `try/except` |
| 多 future 异常用单个 `except` | 多个失败应分别处理 | 3.11+ 用 `ExceptionGroup`/`except*`，或循环 `as_completed` 隔离 |
| 🔧 多进程启动方式 | 3.14 macOS 弃 `fork` | 显式 `mp_context`，以官方文档为准 |
