# 第 7 章 函数是一等对象（原书 pp.175–189）

> 一句话定位：本章把「函数」从语法结构降格为普通对象——能赋值、能传参、能返回、能放进容器，由此打开第二部分「函数即对象」的全部技术（高阶函数、可调用对象、`operator`、`partial`）。
> 基线：原书 Python 3.10；本目录按 3.12+ 校验。

## 核心精讲

### 一、函数是对象：可赋值、可传参、可返回、可入容器

```python
# 教学示意，不参与构建；本机 Python 3.13 验证通过
def factorial(n: int) -> int:
    """返回 n 的阶乘。"""
    return 1 if n < 2 else n * factorial(n - 1)

fact = factorial              # 1. 赋值给新名字
print(fact(5))                # 120
print(type(fact))             # <class 'function'>
print(fact.__name__, fact.__doc__)
print([f.__name__ for f in (len, str, factorial)])   # 函数可以放进容器
print(sorted(map(str, [1, 2, 3]), key=len))          # 函数可以当参数
```

`__doc__` 与 `__name__` 是函数对象的普通属性；`help()`、装饰器和测试框架正是靠它们做内省，这也是第 9 章 `functools.wraps` 必须存在的原因。

### 二、高阶函数与「行为参数化」

`sorted(key=...)` 是 Python 中最成功的高阶函数设计：调用方传入一段**策略**，而不是给 `sorted` 增加一堆选项。

```python
# 教学示意，不参与构建
fruits = ['strawberry', 'fig', 'apple', 'cherry', 'raspberry', 'banana']
print(sorted(fruits, key=len))                       # 按长度
print(sorted(fruits, key=lambda w: (len(w), w)))     # 先长度后字典序
```

`map`/`filter` 在有了列表推导式之后基本退居二线：同样的工作，推导式更易读，且 `filter` 里的 `lambda` 往往可以直接搬进推导式的 `if` 子句。真正仍需 `map` 的场景是「函数已经存在」且语义就是逐元素变换。

### 三、九种可调用对象（原书 p.180）

`callable()` 是唯一能统一判定「能不能加括号调用」的方法。九类如下：

| # | 可调用对象 | 例子 | 判定要点 |
| --- | --- | --- | --- |
| 1 | 用户定义的函数 | `def f()` / `lambda x: x` | `type()` 为 `function` |
| 2 | 内置函数 | `len`、`time.strftime` | C 实现，`builtin_function_or_method` |
| 3 | 内置方法 | `dict.get`、`str.upper` | 方法的 C 版本 |
| 4 | 方法（类中定义的函数） | `obj.method` | 通过描述符绑定为 `method` |
| 5 | 类 | `int`、`Fraction` | 调用类触发 `__new__` + `__init__` |
| 6 | 类的实例 | 实现了 `__call__` 的对象 | 见 7.6 |
| 7 | 生成器函数 | 含 `yield` 的 `def` | 调用返回生成器，不执行函数体 |
| 8 | 原生协程函数 | `async def` | 调用返回 coroutine，须 `await` |
| 9 | 异步生成器函数 | `async def` + `yield` | 须 `async for` |

```python
# 教学示意，不参与构建
import random

class BingoCage:
    """带状态的可调用对象：调用一次，弹出一个球。"""
    def __init__(self, items):
        self._items = list(items)
        random.shuffle(self._items)

    def pick(self):
        return self._items.pop()

    def __call__(self):
        return self.pick()

cage = BingoCage(range(3))
print(callable(cage), cage(), cage())
```

`__call__` 的价值在于**跨调用保留状态**：闭包（第 9 章）也能保留状态，但一旦状态变多、需要额外方法，类就更合适。

### 四、仅限关键字参数与仅限位置参数

```python
# 教学示意，不参与构建
def tag(name, /, *content, cls=None, **attrs):
    """`/` 前只能按位置传；`*` 后只能按关键字传。"""
    if cls is not None:
        attrs['class'] = cls
    pairs = ' '.join(f'{k}="{v}"' for k, v in attrs.items())
    return f'<{name}{" " + pairs if pairs else ""}>{ "".join(content) }</{name}>'

print(tag('br'))
print(tag('p', 'hello', cls='sidebar'))
```

`/` 是 Python 3.8（PEP 570）引入的，用来给库作者留出「改参数名不影响调用方」的自由度；`*` 后的仅限关键字参数则强制调用方写出参数名，是 API 可读性的第一道防线。

### 五、`operator` 与 `functools.partial`

```python
# 教学示意，不参与构建
from operator import mul, itemgetter, attrgetter, methodcaller
from functools import partial, reduce

print(reduce(mul, range(1, 6)))            # 120，比写 lambda a, b: a * b 快且清晰
rows = [('a', 3), ('b', 1), ('c', 2)]
print(sorted(rows, key=itemgetter(1)))     # 按元组第 1 项排序
print(sorted(rows, key=attrgetter('__class__.__name__')))   # attrgetter 支持点号路径
print(methodcaller('replace', ' ', '-')('a b c'))           # 'a-b-c'

# partial：把两参数函数冻结成单参数回调
triple = partial(mul, 3)
print(triple(7), list(map(partial(mul, 10), range(1, 4))))
```

`itemgetter` / `attrgetter` 的可读性优势在多层结构下最明显：`attrgetter('coord.x')` 比 `lambda o: o.coord.x` 更短，且由 C 实现。`partial` 则是把函数「适配」成第三方 API 要求的回调形状的利器。

### 六、`Callable` 注解（2026 年写法）

```python
# 教学示意，不参与构建；类型检查用 mypy --strict / pyright
from collections.abc import Callable
from typing import ParamSpec, Concatenate, TypeVar

T = TypeVar('T')
P = ParamSpec('P')                       # PEP 612（3.10）

def apply_twice(fn: Callable[[int], int], x: int) -> int:
    return fn(fn(x))

# 装饰器要「透传被装饰函数的签名」，必须用 ParamSpec，否则签名退化为 (*args, **kwargs)
def logged(fn: Callable[P, T]) -> Callable[P, T]: ...
def inject_first(fn: Callable[Concatenate[int, P], T]) -> Callable[P, T]: ...
```

要点：`Callable[[int], int]` 只描述「参数类型列表 + 返回类型」，无法表达关键字参数、默认值与变长签名。凡是要包装另一个函数并保留其签名的场合（装饰器、`functools.wraps` 场景），一律用 `ParamSpec`（PEP 612）；`typing.Callable` 已废弃，统一用 `collections.abc.Callable`（PEP 585，3.9）。PEP 695（3.12）之后能否用 `def f[T]` 直接写出「泛型可调用」？——🔧 目前仍以 `Protocol.__call__` 或 `ParamSpec` 表达，`Callable` 的类型参数语法以官方文档为准。

## 版本演进

| 版本 | 与本章相关的变化 | 影响 |
| --- | --- | --- |
| 3.10（基线） | `X \| Y`（PEP 604）、`ParamSpec`（PEP 612）、`match` | 原书写法，`Callable` 注解全面可用 |
| 3.11 | Faster CPython 让纯 Python 函数调用与属性访问明显变快；`Self`（PEP 673） | 高阶函数/回调的性能顾虑下降；备选构造的注解可用 `Self` |

| 3.13 | free-threaded 实验构建（PEP 703）；新 REPL 便于试验函数对象 | 函数语义不变；交互式实验体验改善 |
| 3.14 | **PEP 649 注解延迟求值**；PEP 750 模板字符串 | 运行时读取 `__annotations__` 的旧写法需改；`annotationlib` 成为新的官方入口 |

| 主题 | 现状 | 实践建议 |
| --- | --- | --- |

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 用 `typing.Callable` 做注解 | 自 3.9（PEP 585）起 `typing.Callable` 属于废弃别名 | 用 `collections.abc.Callable[[int], int]` |
| `Callable[[int], int]` 能描述任意回调 | 关键字参数、默认值、变长签名一律丢失 | 装饰器/包装场景改 `ParamSpec` + `Concatenate`（PEP 612, 3.10） |
| 🔧 PEP 695 之后 `Callable` 可用新类型参数语法 | 尚无定论，本书未涉及 3.12 语法 | 🔧 以官方文档为准；泛型可调用目前用 `Protocol.__call__` 或 `ParamSpec` |
| `map`/`filter` 是「函数式」首选 | 多数场景推导式更清晰；`reduce` 多半有 `sum`/`any`/`all` 可替 | 仅在函数已存在、且语义就是逐元素变换时用 `map` |
| 九种可调用对象可用 `type()` 区分 | 判定「能否调用」不能靠 `type` | 一律 `callable(obj)`；类型检查用 `Callable` / `Protocol` |
| 3.14 后仍直接读 `func.__annotations__` | PEP 649 起注解延迟求值，`__annotations__` 不再总是「已求值的对象字典」 | 3.14 用 `annotationlib.get_annotations()`；🔧 精确格式参数以官方文档为准 |
| 原书按 3.10 基线，未提 `Self` | 备选构造、链式返回的注解在 3.10 只能写类型名字符串或 `TypeVar` | 3.11 起用 `typing.Self`（PEP 673） |
