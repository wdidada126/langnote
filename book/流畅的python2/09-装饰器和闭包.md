# 第 9 章 装饰器和闭包（原书 pp.232–258）

> 一句话定位：本章解释「函数如何被包装」——装饰器在导入时执行、闭包保存自由变量、`nonlocal` 让闭包可写，最终落到 `functools` 提供的备忘与单分派两件利器上。
> 基线：原书 Python 3.10；本目录按 3.12+ 校验。

## 核心精讲

### 一、装饰器在导入时执行

```python
# 教学示意，不参与构建；本机 Python 3.13 验证通过
registry: list = []

def register(func):
    print(f'running register({func.__name__})')
    registry.append(func)
    return func          # 原样返回：不改变行为，只做登记

@register
def f1(): pass

@register
def f2(): pass

print('registry =', [f.__name__ for f in registry])   # 调用 f1() 时不会再打印
```

关键点：装饰器代码在**模块导入时**跑一次；被装饰函数的调用发生在运行时，两者互不干扰。所有「注册式」框架（Flask 路由、`pytest` 的 fixture、CLI 子命令）都建立在这一条上。类场景下，注册也可改用 `__init_subclass__`（PEP 487，3.6）或元类（PEP 3115，3.0），见第 24 章。

### 二、作用域、闭包与 `nonlocal`

```python
# 教学示意，不参与构建
def make_averager():
    count, total = 0, 0.0
    def averager(new_value):
        nonlocal count, total      # 没有这行就是 UnboundLocalError
        count += 1
        total += new_value
        return total / count
    return averager

avg = make_averager()
print(avg(10), avg(11), avg(12))                  # 10.0 10.5 11.0
print(avg.__code__.co_freevars, [c.cell_contents for c in avg.__closure__])   # ('count','total') [3, 33.0]
```

三条规则：
1. 函数体中出现对某名字的**赋值**，该名字就是局部变量（除非声明 `global`/`nonlocal`）。
2. 局部变量在编译期确定，存在 `__code__.co_varnames`；自由变量存在 `co_freevars`，值存在 `__closure__` 的 cell 里。
3. `nonlocal` 只向**外层函数作用域**查找，不会一路找到全局。

### 三、`functools.wraps` 为什么是必需品

```python
# 教学示意，不参与构建；Python 3.13 验证通过
import time, functools

def clock(func):
    @functools.wraps(func)      # 拷贝 __name__/__doc__/__module__/__qualname__/__annotations__，设置 __wrapped__
    def clocked(*args, **kwargs):
        t0 = time.perf_counter()
        result = func(*args, **kwargs)
        print(f'[{time.perf_counter() - t0:0.8f}s] {func.__name__}{args} -> {result!r}')
        return result
    return clocked

@clock
def snooze(seconds: float) -> None:
    """睡一会儿。"""
    time.sleep(seconds)

snooze(0.01)
print(snooze.__name__, snooze.__doc__, snooze.__wrapped__)
```

没有 `wraps`，被装饰函数会「改名」为 `clocked`，文档消失，`help()`、`inspect.signature()`、测试报告、Web 框架的函数名路由全都受影响。`functools.wraps` 还会同步 `__dict__`，因此自定义属性也能保留。

### 四、`functools.cache` 与 `lru_cache` 的取舍

```python
# 教学示意，不参与构建；Python 3.13 验证通过
import functools

@functools.cache                     # 无界：等价于 lru_cache(maxsize=None)，但没有 LRU 链表开销
def fib_cache(n: int) -> int:
    return n if n < 2 else fib_cache(n - 1) + fib_cache(n - 2)
@functools.lru_cache(maxsize=128)    # 有界：超过上限淘汰最久未用项
def fib_lru(n: int) -> int:
    return n if n < 2 else fib_lru(n - 1) + fib_lru(n - 2)

print(fib_cache(30), fib_lru(30), fib_lru.cache_parameters())
fib_lru.cache_clear()
```

| 维度 | `functools.cache`（3.9+） | `lru_cache(maxsize=...)` |
| --- | --- | --- |
| 容量 | 无限，永不淘汰 | 有上限，LRU 淘汰 |
| 开销 | 更省内存、命中略快（无链表维护） | 需维护访问顺序 |
| 适用 | 参数空间有限、纯函数、可长驻 | 参数空间无界或需控制内存 |
| 工具方法 | `cache_info()` / `cache_clear()` / `cache_parameters()` 同样可用 | 同左 |

风险：无界缓存本质是有计划的**内存泄漏**，键还会强引用参数对象（含 `self`，可能阻止实例被回收）。方法上做备忘时优先考虑 `@cached_property`（第 22 章）或显式 `lru_cache(maxsize=...)`。

### 五、单分派泛化函数

```python
# 教学示意，不参与构建；Python 3.13 验证通过
from functools import singledispatch
from collections.abc import Sequence
import numbers, html

@singledispatch
def htmlize(obj) -> str:
    return html.escape(repr(obj))

@htmlize.register                      # 用注解里的类型注册
def _(obj: numbers.Integral) -> str:
    return f'<pre>{obj} (0x{obj:x})</pre>'

@htmlize.register(str)                 # str 本身也是 Sequence，必须显式注册作为递归出口
def _(text: str) -> str:
    return html.escape(text)

@htmlize.register(Sequence)            # 显式注册
def _(obj) -> str:
    return f'<ul>{"".join(f"<li>{htmlize(x)}</li>" for x in obj)}</ul>'
```

`singledispatch` 只按**第一个参数**分派，但支持按 MRO 与抽象基类（`numbers.Integral` 这类虚拟子类）匹配；递归时务必为 `str` 这类「既是标量又是序列」的类型显式注册，否则会无限递归。现版本可直接注册 `int | str` 形式的联合（PEP 604），🔧 该功能引入的具体版本**以官方文档为准**。类方法用 `singledispatchmethod`。分派依据若想换成「第二个参数」或「值的形状」，就得回到 `match` 语句（第 2、18 章）或策略字典（第 10 章）。

### 六、参数化装饰器与基于类的装饰器

```python
# 教学示意，不参与构建；Python 3.13 验证通过
import time, functools

def clock(fmt: str = '[{elapsed:0.8f}s] {name}{args} -> {result!r}'):
    """装饰器工厂：接受参数，返回真正的装饰器。"""
    def decorate(func):
        @functools.wraps(func)
        def clocked(*args, **kwargs):
            t0 = time.perf_counter()
            result = func(*args, **kwargs)
            elapsed = time.perf_counter() - t0
            print(fmt.format(elapsed=elapsed, name=func.__name__, args=args, result=result))
            return result
        return clocked
    return decorate

@clock()                       # 注意：参数化装饰器必须「调用」一次
def snooze(seconds): time.sleep(seconds)

class Clock:                   # 等价的类实现：__init__ 接参数，__call__ 接函数
    def __init__(self, fmt: str = '[{elapsed:0.8f}s] {name}'): self.fmt = fmt
    def __call__(self, func):
        @functools.wraps(func)
        def clocked(*args, **kwargs):
            t0 = time.perf_counter()
            result = func(*args, **kwargs)
            print(self.fmt.format(elapsed=time.perf_counter() - t0, name=func.__name__))
            return result
        return clocked

@Clock()
def other(): pass
snooze(0.01); other()
```

三层嵌套可读性差时，改成类实现往往更清楚：`__init__` 拿配置，`__call__` 拿函数。选择依据很简单——**需要维护状态就用类，纯包装就用函数**。

### 七、2026 年装饰器生态的新成员：`@override`（PEP 698，3.12）

```python
# 教学示意，不参与构建；需 Python 3.12+
from typing import override
class Base:
    def method(self) -> int: return 1
class Child(Base):
    @override                 # 静态检查器会验证签名是否真能覆盖；拼错方法名会被抓出
    def method(self) -> int: return 2
```

`@override` 运行时只是把函数标记为「覆盖」，真正的校验由 mypy / pyright 完成。它与 `@abstractmethod`、`@dataclass` 一起构成了「标准库 + typing 提供的官方装饰器族」。

## 近年研究与工业界开源实践（2015–2026）

| 主题 | 现状 | 实践建议 |
| --- | --- | --- |
| 装饰器的类型化 | `ParamSpec` + `Concatenate`（PEP 612）是 2020 年代的标准答案；`typing.override`（PEP 698）补齐了「覆盖校验」 | 写库时给每个装饰器加 `Callable[P, T] -> Callable[P, T]` 签名 |
| 备忘的内存风险 | 无界 `functools.cache` 在生产服务中造成过真实的内存事故 | 长生命周期服务优先 `lru_cache(maxsize=n)`；方法场景用 `cached_property` |
| 分派机制的竞争 | `singledispatch` 适合「按类型分支、实现分散在多模块」；`match` 语句适合「按结构分支、集中在一处」；生态惯例上 `functools.wraps` 已被 `ruff` 等 linter 视为强制项 | 跨模块可扩展 → `singledispatch`；单一函数内的形状判断 → `match`；自定义装饰器一律加 `@wraps` |

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 装饰器「在函数调用时生效」 | 装饰器在**定义/导入时**执行一次 | 把副作用（注册、打印）放装饰器体，把每次行为放 wrapper |
| 用 `global` 代替 `nonlocal` 做累加器 | 污染模块命名空间，且不可重入 | 用 `nonlocal` + 闭包，或改成类/`__call__` |
| 认为闭包变量「读不到」 | 能读到，只是不能重新绑定 | 需要写就 `nonlocal`；只写容器内容（如 `list.append`）不需声明 |
| 备忘一律用 `lru_cache(maxsize=None)` | 无界增长且带 LRU 链表开销 | 无界场景用 `functools.cache`；需限制用 `lru_cache(maxsize=n)` |
| 无界缓存没有代价 | 强引用键与值，阻止对象回收 | 服务里限定容量并定期 `cache_clear()`；方法上改用 `cached_property` |
| 🔧 3.14 后仍在装饰器里读 `func.__annotations__` | PEP 649 起注解延迟求值 | 用 `annotationlib.get_annotations()` 或 `typing.get_type_hints()`；🔧 以官方文档为准 |
| 覆盖父类方法无需声明 | 改名/签名漂移不会被发现 | 3.12 起加 `@override`（PEP 698），由 mypy/pyright 校验 |
| 认为 `singledispatch` 可按任意参数分派 | 只按第一个参数 | 需要别的分派维度时用 `match`、策略字典或多分派库 |
| 装饰器的类型注解写成 `Callable[..., Any]` | 调用方签名丢失 | `Callable[P, T]`（`ParamSpec`，PEP 612） |
| 🔧 `singledispatch` 注册 `int \| str` 的版本 | 现版本可用 | 🔧 引入版本以官方文档为准 |
