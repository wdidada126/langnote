# 第 16 章 运算符重载（原书 pp.431–451）

> 一句话定位本章：运算符重载让自定义对象「长出」`+`、`*`、`@`、`==` 等原生语法；本章讲清每个运算符背后该实现哪些特殊方法，以及边界在哪。

## 核心精讲

### 16.4 `+=` 与反向运算符 `__radd__`

```python
# 教学示意，不参与构建
class Vector:
    def __init__(self, xs): self.xs = list(xs)
    def __add__(self, other):
        if isinstance(other, Vector):
            return Vector([a + b for a, b in zip(self.xs, other.xs)])
        return NotImplemented
    def __radd__(self, other):        # 当 other.__add__(self) 返回 NotImplemented 时调用
        return self.__add__(other)
    def __repr__(self): return f"Vector({self.xs})"

print(Vector([1, 2]) + Vector([3, 4]))   # Vector([4, 6])
print([10, 20] + Vector([1, 2]))         # Vector([11, 22]) —— 走 __radd__
```

### 16.8 `@total_ordering` 省去重复比较

```python
# 教学示意，不参与构建
from functools import total_ordering

@total_ordering
class Item:
    def __init__(self, weight): self.weight = weight
    def __eq__(self, other): return self.weight == other.weight
    def __lt__(self, other): return self.weight < other.weight
    # 只需定义 __eq__ + 一个排序运算，其余 < <= > >= 自动生成
```

## 版本演进

- **PEP 465 — `@` 矩阵乘运算符（3.5）**：本章 16.6 的基础，3.12+ 不变；NumPy、`torch` 等用 `__matmul__` 实现矩阵乘法。
- **3.12 `immortal objects`（PEP 683，🔧 以官方为准）**：与运算符无关但影响不可变单例的 `+=` 行为观察——不可变对象（如 `tuple`）`+=` 实际生成新对象，`id` 会变。
- 3.10 `match` 模式匹配与运算符：`__eq__` 的语义直接影响 `case x if x == y` 的匹配，与 [18-with、match和else块.md](18-with、match和else块.md) 关联。
- 3.8 `functools.total_ordering` 行为一致；`@total_ordering` 的「必须定义至少一个排序运算」约束未变。

## 近年研究与工业界开源实践（2015–2026）

- **NumPy / `torch` 的 `__matmul__` 工业实践**：`@` 已成为科学计算与深度学习的标准点积/矩阵乘语法（非同行评审，框架文档）。
- **`@total_ordering` 在 `dataclass(order=True)` 中的内建支持**：`@dataclass(order=True)` 自动生成比较运算，取代手写 `@total_ordering`（见 [05-数据类构建器.md](05-数据类构建器.md)）。
- **运营商重载的安全边界讨论**：社区共识「只为语义自明的类型重载运算符，避免 `<<` 当位移以外的黑魔法」（非同行评审，Daniel Pope 等演讲）。
- **3.11 更快的属性访问**让 `self.xs` 这类读取在 `+=` 热路径上更快，间接利好运算符重载性能（非同行评审，speed.python.org）。

## 常见误区与本书需修正之处

| 原书说法 / 习惯 | 问题 | 2026 正确写法 |
| --- | --- | --- |
| 重载 `+` 不处理类型回退 | 遇到 `int + Vector` 会 `TypeError` | 不支持的组合返回 `NotImplemented`，让 Python 走反向运算符 |
| 认为 `+=` 总在原地改 | 不可变对象（如 tuple/`Vector` 新版）`+=` 生成新对象 | 不可变类型用 `__add__` 回退，`id` 会变 |
| 手写全部六个比较运算 | 重复且易错 | `@total_ordering` + `__eq__` + 一个排序运算；或 `@dataclass(order=True)` |
| 想重载 `and`/`or` | Python  deliberately 不允许（`and`/`or`/`not` 不能被重载） | 用方法名（如 `.all()`/`.any()`）替代，或返回 `NotImplemented` 之外的语义 |
| `@` 当普通乘法用 | `@` 语义是矩阵乘，滥用会误导 | 仅在确有「线性代数乘」语义时用 `__matmul__` |
