## 核心精讲

### 序列的分类：二维表格一句话说清

| 维度 | 容器序列（装引用） | 扁平序列（装值） |
| --- | --- | --- |
| 可变 | `list`、`bytearray`、`array.array` | — |
| 不可变 | `tuple`、`str`、`collections.deque`（可pop两端） | `bytes` |

容器序列里放的是对象的引用，所以 `list` 可以装异构数据；扁平序列在自己的连续内存里装紧凑的值（字符/字节/数值），
省空间但**只能装一种 C 类型**。这是 2.10 节所有讨论的起点。

### 推导式与生成器表达式

```python
# 教学示意，不参与构建
symbols = '$¢£¥€¤'
codes = [ord(s) for s in symbols]
print(codes)
beyond_ascii = [(s, ord(s)) for s in symbols if ord(s) > 127]   # 只用一次 ≈ 推导式的优势区间
print(beyond_ascii)

# 生成器表达式：逐个产出，不建中间列表
import array
arr = array.array('I', (ord(s) for s in symbols))     # array 构造函数接受可迭代对象，不需要先 list
print(arr.tolist())

# 推导式的变量不会泄漏到外层作用域（Python 3 已修复 Python 2 的行为）
x = 'outer'
print([x for x in 'abc'], x)        # ['a', 'b', 'c'] outer
```

可读性判断标准：**推导式的长度超过两屏、或里面嵌了 `if...else` 之外的复杂逻辑，就拆成生成器函数**。
`map`/`filter` 只有在第一个参数是**已存在的内置函数**（如 `map(len, seq)`、`map(str.strip, lines)`）时才值得考虑，
一旦要写 `lambda` 就是推导式更好读。

### 元组的双重身份与相对不可变性

```python
# 教学示意，不参与构建
traveler_ids = [('USA', '31195855'), ('BRA', 'CE342567'), ('ESP', 'XDA205856')]
for passport in sorted(traveler_ids):
    print('%s/%s' % passport)       # 拆包直接进格式化：元组当「记录」用

a = (10, 'alpha', [1, 2])
print(a[-1])
a[-1].append(99)        # 元素自己可变 —— 「不可变」说的是 tuple 持有的引用不可替换
print(a)

t = (1, 2, [30, 40])
try:
    t[2] += [50, 60]    # 对列表就地 += 成功，随后给 tuple 赋值 → TypeError
except TypeError as exc:
    print('TypeError:', exc)
print(t)                # (1, 2, [30, 40, 50, 60]) —— 改动已经发生了
```

`+=` 谜题的标准答案是：这一步等价于 `t[2] = t[2].__iadd__([50, 60])`，
`list.__iadd__` 就地完成并返回自身，**之后**对 tuple 做赋值才抛出 `TypeError`。
教训：不要在元组里放可变对象；也不要以为抛异常就意味着「没改动」。

### 拆包：`*`、`**`、嵌套

```python
# 教学示意，不参与构建
a, b, *rest = range(5)
print(a, b, rest)                       # 0 1 [2, 3, 4]
a, *body, c, d = range(5)
print(a, body, c, d)                    # 0 [1, 2] 3 4
metro = ('Tokyo', 'JP', 36.933, (35.68, 139.69))
name, cc, pop, (lat, lon) = metro       # 嵌套拆包
print(name, cc, lat, lon)
print(divmod(20, 8), t := (20 // 8, 20 % 8))   # 海象运算符只在需要复用表达式时才用（PEP 572）
try:
    a, b = range(3)                     # 数量不匹配 → ValueError
except ValueError as exc:
    print('ValueError:', exc)
```

### 序列模式匹配（本节为原书第 2 版新增）

```python
# 教学示意，不参与构建
def handle_command(command):
    match command.split():
        case ['q'] | ['quit']:                       # OR 模式
            return 'bye'
        case ['go', direction] if direction in 'nesw':   # 守卫
            return f'go {direction}'
        case ['go', *rest]:
            return f'bad direction: {rest!r}'
        case ['load', str() as name, *_] as whole:   # 类型模式 + 捕获（*_ 丢弃余项）
            return f'load {name} from {whole!r}'
        case []:
            return 'empty'
        case _:
            return 'unknown'

for c in ['quit', 'go n', 'go up', 'load map.txt extra', '']:
    print(c or '<blank>', '->', handle_command(c))
```

序列模式的三条现代经验：

- 它能同时完成「长度检查 + 结构拆包 + 类型/值过滤」，比 `if len(args) == 2 and args[0] == 'go'` 清晰得多。
- `case [*_]` 与 `case [*rest]` 语义不同：前者是「至少一项」，后者把余项绑定到 `rest`。
- 在 `case` 里写 `a`, `b` 这类**裸名会被捕获**而不是比较；要比较必须用点号
  （如 `case [Coord.x]`）或值/类型模式。这是新手最常见的 bug。

### 切片、`+`、`*`、`sort`

```python
# 教学示意，不参与构建
l = list(range(10))
print(l[::-1], l[-3:], l[:0])                 # 反转、末三项、空列表
l[2:5] = [20, 30]                             # 给切片赋值的长度不必相同
print(l)
s = 'biryani'
print(slice(None, 3), s.__getitem__(slice(None, 3)))
print('biryani'[:3], 'biryani'[slice(1, 8, 2)])

board = [['_'] * 3 for _ in range(3)]         # ✅ 正确的 3x3
weird = [['_'] * 3] * 3                       # ❌ 三行是同一个列表对象
board[1][2] = 'X'
print(board)
weird[0][0] = 'O'
print(weird)                                  # [['O', '_', '_'], ['O', '_', '_'], ['O', '_', '_']]
```

排序：`list.sort()` 就地返回 `None`，`sorted()` 返回新列表。**两者都是稳定排序**，
因此多关键字排序用「先次要键、后主要键」两趟实现，比构造 `key=lambda x: (-x.a, x.b)` 更好维护。

### 当列表不适用时：`array` / `memoryview` / NumPy 2.x / `deque`

```python
# 教学示意，不参与构建
from array import array
from collections import deque

nums = array('h', [-2, -1, 0, 1, 2])
memv = memoryview(nums)
octets = memv.cast('B')          # 同一块内存，按字节重新解释
print(octets.tolist())
octets[5] = 4
print(nums)                      # array('h', [-2, -1, 1024, 1, 2]) —— 通过一个视图改了底层数组

dq = deque(range(5), maxlen=10)
dq.rotate(3); print(dq)
dq.appendleft(-1); dq.append(5); print(dq)
```

```python
# 教学示意，不参与构建 —— 需 numpy（pip install "numpy>=2"）；本机实测 numpy 2.4.2
import numpy as np
from array import array

a = np.arange(12, dtype=np.int8).reshape(3, 4)
print(a[:, ::2])            # NumPy 切片是视图，写它等于写原数组
print(a[0, 0], type(a[0, 0]))
w = np.frombuffer(memoryview(array('d', [1.0, 2.0, 3.0])), dtype='d')
print(w, w.flags.writeable)
```

四类工具的 2026 年定位：

| 工具 | 适用 | 不适用 |
| --- | --- | --- |
| `array.array` | 需要与 C/`struct` 交换紧凑数值数组、又不想引入 numpy 依赖 | 任何需要算术、广播、线性代数的场景 |
| `memoryview` | 零拷贝读写缓冲区（网络/文件映射/共享内存），`.cast()` 重解释类型 | 通用数据结构；它自身不是容器替代品 |
| NumPy 2.x | 数值计算的事实标准；`@` 矩阵乘、广播、`np.frombuffer` 接 `memoryview` | 存异质对象（会退化成 `dtype=object`，性能反而更差） |
| `collections.deque` | 需要 `appendleft`/`popleft` 的队列、滑动窗口（`maxlen`） | 随机访问中间元素（`O(n)`）；需要切片就回到 `list` |

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 年的正确写法 |
| --- | --- | --- |
| 2.2 把 `array` 当作「数值 list」的常规替代 | 今天几乎总是 NumPy 更好 | `array` 保留给「需要紧凑 C 数组 + 不能引 numpy」的窄场景；有算术就用 `numpy.ndarray` |
| 2.10.3 NumPy 段基于 NumPy 1.x | 部分 API/标量表示已变 | 按 NumPy 2.x 复核；矩阵一律 `ndarray` + `@`，不用 `np.matrix` |
| 2.3.4「生成器表达式省内存」被读成「更快」 | 混淆空间与时间 | 它省的是**中间列表的内存**；单趟遍历的纯 Python 开销通常不会更 |
| 2.3.2 对 `map`/`filter` 的对比结论偏旧 | 具体倍数随版本漂移 | 保留「推导式更易读」的结论；性能数字一律实测，🔧 以本机基准为准 |
| 2.4.2「元组不可变」的表述容易被字面理解 | 未强调「相对不可变」 | 元素可变时 `+=` 仍能成功；做 dict 键/集合元素前请先 Frozen 化（见 [第 6 章](06-对象引用、可变性和垃圾回收.md)） |
| 2.8.2 只演示了「可变/不可变序列下 `+=` 的差别」 | 未点明「异常之后改动已生效」 | 明确：`t[2] += [50, 60]` 先 `__iadd__` 成功、后赋值失败，`t` 已被**部分修改** |
| 2.6 序列模式的 `case [a, b]` | 裸名会捕获，读者常误以为在比较值 | 要比较值用字面量/点名；守卫用 `if`，类型过滤用 `str()` / `int()` 等类模式 |
| 2.7 未讨论「切片是视图还是副本」 | NumPy / `memoryview` 上写切片会写回原数据 | list/str/tuple → 副本；NumPy → 视图；`memoryview` → 视图。不确定就 `copy()` |
| 🔧 2.10.1 关于 `array` 各 typecode 的细节 | 跨版本有清理动作 | 具体 typecode 支持范围**以官方 What's New / 库文档为准**，不要硬背 |
