## 核心精讲

### 5.2–5.4 五种构建器怎么选

| 构建器 | 不可变 | 可哈希 | 类型检查 | 校验 | 何时用 |
| --- | --- | --- | --- | --- | --- |
| `collections.namedtuple` | 是 | 是 | 否 | 无 | 一次性临时记录、对接旧 API |
| `typing.NamedTuple` | 是 | 是 | 好 | 无 | **具名元组的默认选择** |
| `dataclasses.dataclass` | `frozen=True` 可选 | frozen 时是 | 最好 | 自己写 `__post_init__` | 内部数据结构的默认选择 |
| `attrs`（第三方） | `frozen=True` | 可选 | 好（靠 PEP 681） | 验证器/转换器 | 比数据类多一点、又不想吵闹依赖时 |
| `pydantic`（第三方） | `frozen=True` | 可选 | 好 | **内建，且做类型转换** | 解析外部输入（HTTP/JSON/配置） |

```python
# 教学示意，不参与构建
from collections import namedtuple
from dataclasses import dataclass, field
from typing import NamedTuple

City = namedtuple('City', 'name country population coordinates')   # ① 无类型的临时记录
tokyo = City('Tokyo', 'JP', 36.933, (35.68, 139.69))
print(tokyo.country, tokyo._fields)


class GeoCoordinate(NamedTuple):                                   # ② 带类型、可加方法
    lat: float
    lon: float

    def __str__(self) -> str:
        return f'{abs(self.lat)}{"N" if self.lat >= 0 else "S"} {abs(self.lon)}{"E" if self.lon >= 0 else "W"}'



@dataclass(slots=True, kw_only=True)                               # ③ 标准库数据类
class CityRecord:
    name: str
    country: str
    population: float
    tags: list[str] = field(default_factory=list)


print(str(GeoCoordinate(35.68, 139.69)), CityRecord(name='Tokyo', country='JP', population=36.933))
```

### 🔴 PEP 695 类型参数语法：新旧对照（3.12 起必须会写）

| 场景 | 旧写法（书中所用） | 3.12+ 新写法（PEP 695） |
| --- | --- | --- |
| 泛型数据类 | `T = TypeVar('T')` + `class Stack(Generic[T])` | `class Stack[T]:` |
| 泛型具名元组 | `T = TypeVar('T')` + `class Pair(NamedTuple, Generic[T])` | `class Pair[T](NamedTuple):` |
| 受限类型参数 | `T = TypeVar('T', bound=SupportsLessThan)` | `class BinTree[T: SupportsLessThan]:` |
| 类型别名 | `Coordinates = tuple[float, float]` | `type Coordinates = tuple[float, float]` |
| 泛型函数 | 只能用 `TypeVar` 表达 | `def first[T](items: Iterable[T]) -> T \| None:` |

```python
# 教学示意，不参与构建 —— 本机 Python 3.13 实测通过
from collections.abc import Iterable
from dataclasses import dataclass, field
from typing import NamedTuple


@dataclass(slots=True)
class Stack[T]:
    items: list[T] = field(default_factory=list)

    def push(self, item: T) -> None:
        self.items.append(item)


class Pair[T](NamedTuple):
    first: T
    second: T


def first[T](items: Iterable[T]) -> T | None:
    return next(iter(items), None)


s: Stack[int] = Stack()
s.push(3)
print(s, Pair(1, 2), Pair[str]('a', 'b'), first([4, 5, 6]))
```

迁移建议：**新代码一律写新语法**；要兼容 3.11 及更早版本才保留 `TypeVar`，且**同一个类上不要混用两种写法**。
静态检查器对新语法的支持情况以各工具发布说明为准 🔧。

### 5.6 `@dataclass` 详解：字段选项、`__post_init__`、`ClassVar` / `InitVar`

```python
# 教学示意，不参与构建
from dataclasses import InitVar, dataclass, field, fields, replace
from typing import ClassVar


@dataclass
class Resource:
    schema: ClassVar[str] = 'dublin-core'               # 类常量：不进 __init__
    identifier: str
    title: list[str] = field(default_factory=list)      # 可变默认值必须走 factory
    db: InitVar[object | None] = None                   # 只传给 __post_init__
    created: str = field(default='', metadata={'format': 'ISO8601'})

    def __post_init__(self, db: object | None) -> None:
        if not self.title:
            self.title = [self.identifier]
        if db is not None:
            self.title = [t.upper() for t in self.title]


r = Resource('rs:1', created='2026-10-02')
print(r, [f.name for f in fields(r)], replace(r, identifier='rs:2').identifier)
print(fields(r)[2].metadata, Resource.schema)
```

`field()` 的四个常用参数：`default`（不可变默认值）、`default_factory`（每次新建，list/set/dict 必用）、
`repr` / `compare`（敏感字段设 `False` 以避开 `__repr__` 泄漏与比较）、`init=False`（派生字段，在 `__post_init__` 里算出来）。

### 5.6.1 `slots=True` / `kw_only=True`：今天应当默认开启吗

```python
# 教学示意，不参与构建 —— 本机 3.13 实测
from dataclasses import dataclass


@dataclass(slots=True)
class Slotted:
    x: int = 0


obj = Slotted(1)
print('有 __dict__？', hasattr(obj, '__dict__'))
```

实测三条：**① 没有 `__dict__`（不能随便加属性，既是目的也是约束）；② 体积更小；③ 默认不支持弱引用**。
建议：纯值对象开 `slots=True`；要动态属性、要弱引用、要依赖 `__dict__` 的第三方库，就关掉它。

### 5.8 类实例的模式匹配

```python
# 教学示意，不参与构建
from dataclasses import dataclass


@dataclass(slots=True)
class Point:
    x: float
    y: float


for shape in [Point(0, 0), Point(1, 2), ('not-a-point',)]:
    match shape:                                      # 位置模式靠 __match_args__
        case Point(x=0, y=0):                         # 关键字类模式
            print('origin')
        case Point(x, y):                             # 位置类模式
            print(f'point ({x}, {y})')
```

`@dataclass` 会自动生成 `__match_args__`，所以位置类模式开箱可用；自定义类要么显式写 `__match_args__`，
要么只用关键字模式。注意字段顺序从此变成**公共 API**——改顺序会破坏调用方写好的 `case`。

### `attrs` vs `pydantic`：取舍边界

```python
# 教学示意，不参与构建 —— 需 attrs / pydantic；本机实测 attrs 25.4.0、pydantic 2.12.5
import attrs
import pydantic


@attrs.define(frozen=True, slots=True)     # 快、小、可挂验证器，但**不做类型转换**
class AttrsPoint:
    x: float
    y: float


class Model(pydantic.BaseModel):           # 会**尝试把输入转成声明的类型**：'1.5' -> 1.5
    x: float
    y: float


print(AttrsPoint(1, 2), Model(x='1.5', y=2), Model(x=1, y=2).model_dump())
```

原则：**内部用 dataclass / attrs，边界用 pydantic**；pydantic 的类型转换既是核心价值也是风险，想要严格类型就得显式收紧（🔧 方式以 pydantic 官方文档为准）。

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 年的正确写法 |
| --- | --- | --- |
| 5.5.1「注解在运行时没有作用」 | 🔧 已经不成立 | `@dataclass`、`typing.NamedTuple`、`TypedDict`、pydantic 都**在运行时读注解**；正确表述是「解释器不为注解提供类型检查」 |
| 原书全部用 `TypeVar` + `Generic[T]` | 3.12 起有新语法 | 改 `class Stack[T]:` / `class Pair[T](NamedTuple):`；需要兼容旧版本才保留 `TypeVar`，且**不可混写** |
| 5.6 示例用 `Optional[X]` | typing 别名已废弃 | 写 `X \| None`（PEP 604）；容器写 `list[T]`（PEP 585），不用 `typing.List` |
| 5.6.1 里 `default_factory` 只是「一个选项」 | 它其实是**唯一正确答案** | 可变默认值写 `= list()` 会直接报错 `(ValueError: mutable default ... is not allowed)`；写 `= []` 会被 dataclass 拒绝，手写 `__init__` 时则会踩共享默认值的坑，详见 [第 6 章](06-对象引用、可变性和垃圾回收.md) |
| 5.6.5 都柏林核心示例用大量空默认值 | 容易被理解成「数据类适合任意动态字段」 | 动态/半结构化字段用 `TypedDict`（PEP 589）或 `dict`，数据类只用于**字段确定**的结构 |
| 未强调 `slots=True` 的代价 | 默认为真会三连翻车 | 实测：无 `__dict__`、体积小、**不支持弱引用**；需要弱引用就手工 `__slots__` 或关掉该选项 |
| 未强调 `frozen=True` 只是浅冻结 | 成员可变时仍可变 | `frozen=True` 只阻止**重新绑定属性**；字段是 list/dict 时内容仍可改，真正不可变需用不可变容器 |
| 5.8 认为类模式「天然可用」 | 只有 dataclass 自动有 `__match_args__` | 自定义类要显式写 `__match_args__` 才能用位置模式；改字段顺序会破坏外部 `case` |
| 🔧 全书不涉及运行时读注解的新语义 | 3.14 变了 | PEP 649 之后 `__annotations__` 默认延迟求值；依赖它的元编程（含本书第 24 章的 Checked）需按官方 What's New 复核 |
