## A.1 查询机制（⚠️ 转述）

- 元数据表是**目录内虚拟表**：经 catalog 暴露，用标准 SQL 查（Spark/Trino/Flink 各自语法），
  命名两族：`表$snapshots` 后缀式或 `系统库.表_snapshots`（各引擎形态不一）；
- 时间旅行可作用于元数据表本身（`FOR SYSTEM_VERSION AS OF` 查历史清单）——审计取证的杀手锏；
- "当前快照视图"（history/snapshots/manifests/partitions/files/position_deletes/refs）与
  "全历史视图"（all_* 四张）的**分界是排障关键**：rewrite/expire 之后 all_* 里仍见旧文件，
  普通视图已隐身——数据"从查询消失"与"从桶消失"是两件事（10 章 🔧 演示四的表侧镜像）。

## A.14 健康监控三例（书内示例的语义重构，SQL 为教学示意不参与构建 🔧概念演示边界内）

1. **A.14.1 按文件指标触发 compaction**：`SELECT count(*) FROM 表$files WHERE file_size_in_bytes <
   阈值` 占比越界→调度定向 rewrite（scope 参数取自 `partitions` 热区）——11.1.2 指标触发的原料。
2. **A.14.2 监控快照频率**：`snapshots` 按 commit 时间差分位——发现"某表分钟级提交却没配小文件政策"
   类的裸奔写入方（承 06 章快照节拍税）。
3. **A.14.3 洞察自动化**：把两例的查询做成巡检作业，输出"表×病×建议动作"三列工单。

### 🔧 演示五：手搓"迷你元数据表"体验 all_* 分界（DuckDB 1.5.5 实跑）

02 章演示脚本的两张表（manifest_entry/manifest_list）即 `manifests`+`files`+`position_deletes`
三表的合并化身：`snapshot_id<=S AND status<>'DELETED'` 过滤=**当前快照视图**；不带过滤=**all_entries
全历史视图**。实测（demo_out.txt）：读 1003 时当前视图见 2 文件、001 与 pos-del-1002 仍活在 all_
视图——正是 A.9–A.12 存在的意义。**"文件在元数据里退役两次"**：先在普通视图（被 DELETED 记账）、
再在快照过期后连记录一起消失——中间地带归 `all_*` 管。

## 排障手册（按症状路由到表；⚠️ 经验性整理）

| 症状 | 先查 | 看什么 |
| --- | --- | --- |
| 查询变慢、task 数暴涨 | `files`+`partitions` | 小文件比与分区字节分布 |
| loadTable/规划变重 | `manifests` | 清单条目数与每清单文件量（膨胀→rewrite_manifests） |
| 删改多的表读不动 | `position_deletes`（或 v3 DV ⚠️ 名目随 spec） | delete 台账与数据文件比 |
| "报表数字不对要回看当时定义" | `metadata_log_entries`+`history` | 按时间点取元数据版本 |
| 合规要"证明某行曾在/已删" | `all_data_files`/`all_delete_files`/`all_entries` | 历史可见性取证链 |
| 分支/标签不显示或漂移 | `refs` | 各 ref 指向快照与保留设置 |
| 想清孤儿/校准过期 | `snapshots`（committed_at 分布） | retain_last 与 older_than 的安全窗口 |

## 常见误区

| 误区 | 纠偏 |
| --- | --- |
| "元数据表=运维彩蛋，业务分析用不上" | 报表基线核对（当时的文件集）与 SLA 归因都靠它——11 章审计的地基 |
| "`files` 列出的就是桶里全部文件" | 它只列**当前快照可见数据文件**；孤儿/其他快照文件不在（对照桶清单才见全貌） |
| "all_* 能查回被 expire 的内容" | expire 删的是引用；记录保留到何时由元数据自身保留政策决定 ⚠️——别把 all_* 当时间胶囊 |
| "min/max 列统计骗不了人" | 统计可信度依赖写入秩序——10.1.2 错位数据就是"min/max 全重叠"的账（02 章 🔧 剪枝演示的对偶） |
| 拿一张引擎的元数据表语法当通用 | 表名形态/函数族因引擎而异（Spark $后缀、Flink 选项式）→ 语法回 Use_Iceberg_with_Spark 04 与活用入門 09 |

## 本章速查卡

- 视图两族：当前快照视图（可见性现状）vs all_*（跨快照取证）——排障第一分叉。
- 诊断路由串：慢/小文件→files+partitions；规划重→manifests；MoR 成本→position_deletes；

- 元数据表自身也能时间旅行——审计的套娃能力。
- 语法提醒：$后缀/系统库两形态因引擎而异，列名随 format-version 演进 ⚠️ 以当期文档为准。
- 自动化三例（A.14）：文件指标触发、提交频率监控、工单化巡检——11.1.2 的原料车间。

## 核心概念速览（中英对照）

- **元数据表** — Metadata Tables：把表的内脏（快照/清单/文件）以 SQL 可查虚拟表形式暴露的接口。
- **当前快照视图** — Current-snapshot Views：history/snapshots/manifests/partitions/files/refs 族——只报可见性现状。
- **全历史视图** — All-* Tables：all_data_files/all_delete_files/all_entries/all_manifests——跨快照取证族。
- **history** — 提交摘要表：时间、操作者、kind（append/replace/overwrite）的第一问话面。
- **metadata_log_entries** — 元数据文件日志：表定义自身的版本链（灾难取证用）。
- **position_deletes** — Position 删除台账：MoR 删除文件的账目（v3 下演进为 DV ⚠️）。
- **refs** — 分支/标签注册表：命名快照引用的治理面。
- **文件健康指标** — File Metrics：大小分布/清单规模/提交频率——A.14 自动化的三类传感器。
- **可见性≠物理性** — Visibility vs Existence：查询消失与桶消失的两个时刻——all_* 与孤儿清理的分界哲学。
- **虚拟表** — Virtual Table：不落盘、由 catalog+元数据文件即时合成的查询面。
- **时间旅行到元数据** — Traveling the Metadata：对元数据表再做版本查询——审计的套娃能力。
