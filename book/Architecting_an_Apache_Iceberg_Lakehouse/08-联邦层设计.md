## 8.1–8.2 联邦层的定位（五层模型里最"工程审美"的一层）

- 联邦=**查询时整合**：跨 Iceberg 湖、存量 Hive/RDB、SaaS API 的统一 SQL 面——04 章"共存期"的技术解。
- 三要求（8.2 实抓）各自的暗礁：
  1. **不复制**：直查（zero-copy）省存储但受源端性能上限——引出加速件（缓存/reflection/materialized view）
     与"复制换时延"的灰色地带；
  2. **一致语义**：业务定义（指标口径/命名）落进哪一层——视图？语义层？BI 端？——8.3.9 的语义层讨论；
  3. **BI 无缝**：对下游只暴露 JDBC/ODBC/Flight SQL 标准接口（承 09 章）。

## 8.3 双雄对照解剖（⚠️ 特性名以当期文档为准；两产品均不本机安装）

| 维度 | Dremio（8.3.1–8.3.4） | Trino（8.3.5–8.3.9） |
| --- | --- | --- |
| 出身与心智 | "湖仓引擎"：Iceberg 一等公民、围绕数据湖做加速与自助 | "分布式 SQL 查询引擎"：连接器广度 + ANSI SQL 社区标准 |
| 架构 | 规划/执行分离（coordinator+engine），历史/元数据由目录或内建库承载 ⚠️ | coordinator + workers 模块化；connector 插件 SPI 决定可扩性 |
| Iceberg 姿态 | **Iceberg-centric**：原生写路径/优化器针对 Iceberg 深度调教（reflection、列式缓存引擎 ⚠️ 名目随版本变） | 头号 read 连接器之一：谓词/limit 下推良好，写/维护能力子集 ⚠️ |
| 连接器面 | 湖仓向为主（对象存储/主流 DB/SaaS 精简集） | 数百连接器谱系（从 MySQL 到系统元数据）——8.5.1 的主轴 |
| 性能增强 | 自动副本/reflection、结果缓存、查询重写到最优物化 | 依赖正确统计/分区剪枝/物化视图（社区特性线快速演进 ⚠️） |
| 语义与自助 | 数据集/分支模型面向业务自助（UI 厚） | 语义层靠外置工具（8.3.9 的开放讨论） |
| 生态绑定 | 作者供职方（✅ 00 章元数据），叙事权重留意 | Dremio 条目带厂商视角，判词仍以你的约束为准（编者注） |
| 部署（8.4） | Docker/集群/Dremio Cloud 三轨 | 裸集群/K8s operator/多家托管发行 |

- 本章可携带结论（承 8.5）：**联邦层选型=问三件事**——源面广度（Trino 胜）、湖原生深度与自助语义
 （Dremio 胜）、治理贯通（catalog 集成质量定，见 07）。

- **OneLake shortcuts（8.6.1）**：微软"以快捷方式把外部桶注册进 OneLake"的虚拟化——PowerBI/ Fabric

  shortcuts，AI agent 优先看 Spice 面）。

## 常见误区

| 误区 | 纠偏 |
| --- | --- |
| "联邦层=可选装饰" | 04 章共存期没有它，迁移就变成大爆炸重写；它同时是消费层的统一接口宿主（09 章 JDBC/Flight 由它暴露） |
| "直查永远不复制" | reflection/缓存/物化视图本质是**受管理的复制**——承认成本模型（新鲜度×存储×运维）才谈优化 |
| "Trino 写 Iceberg 与 Spark 等价" | 写/DML/维护能力是子集，重摄入与 compaction 仍归引擎层（06/10 章分工）⚠️ |
| "Dremio 替代 catalog" | 它可内建/外接目录，但 Iceberg 治理真相在 REST catalog 侧——混用两套目录=07 章双真相陷阱 |
| 语义层悬空 | 指标口径没人认领时联邦层只是"更贵的查询代理"——8.2.2 的一致语义要落到具体对象（视图/语义层工具） |

## 核心概念速览（中英对照）

- **数据联邦** — Data Federation：不移动数据、查询时统一多源的架构层（8.1）。
- **零拷贝直查** — Zero-copy Querying：联邦的第一承诺——性能受源端上限约束。
- **Reflection/加速副本** — Dremio 对源表自动维护的轻量物化 ⚠️ 名目以当期文档为准。
- **物化视图** — Materialized View：查询结果的管理式复制——Trino/Dremio 皆有快速演进线 ⚠️。
- **Connector SPI** — Trino 连接器接口：数百数据源接入的模块化根因（8.3.6）。
- **谓词下推** — Predicate Pushdown：把过滤推进源端/文件统计——湖上读性能第一杠杆（02 章剪枝的引擎侧）。
- **语义层** — Semantic Layer：指标口径的独立载体——8.3.9 留给生态的开放题。
- **Iceberg-centric** — 以 Iceberg 为原生一等对象的设计姿态（Dremio 的 8.3.3 自我定位）。
- **OneLake shortcuts** — 微软生态的注册式虚拟化：快捷路径接入外部湖。
- **AI-native 虚拟化** — Spice.ai 路线（8.6.2）：为 LLM/agent 消费重新设计的数据接口层。
- **自助数据集** — Self-service Datasets：面向分析用户的治理化发布单元。
