## 3.1 第 4 章：MBA 到底难在哪（⚠️ 重构为五难）

1. **组合爆炸**：n 个商品 → 2^n 子集；Apriori 靠支持度剪枝，但低支持度阈值下仍指数级。
   数仓侧的后果：**共现矩阵不能全量预计算**，「先定规则族再算」成为架构约束（04 章的表清单
   由此而来）。
2. **粒度陷阱**：篮的定义（一次 POS 结账？一张订单？一个购物车会话？）改变全部统计量。
   外卖平台「一单多件」与超市「一人多单」的篮语义相反——**粒度声明必须先于任何 lift 读数**
   （Ralph Kimball 四步法第二步的 MBA 化用 ⚠️）。
3. **流行度伪装**：高渗透商品（面包/牛奶）与万物共现，裸共现表被「基本盘对」霸屏——
   必须上 lift/余弦等**归一化测度**（🔧E3 的 bread&milk：conf 0.5 但 lift 0.83，即伪装样本）。
4. **时间混杂**：促销季共现 ≠ 结构共现（黄油打折周里 bread&butter 规则虚胖）；不解耦价格
   事件，规则刷新会把促销当相关性——这是 Part I 与 Part II 在全书层面**互相需要**的技术原因
   （09 融合章 ✅ 章题 `-14/-15` 的动机 ⚠️ 推定）。
5. **可执行鸿沟**：千条规则无人执行；难点从统计转向治理——规则必须带**负责人/动作/复核周期**
   才进集市（05 章规则回写表的列设计动机 ⚠️）。

## 3.2 第 5 章：Solution Definition 的冻结清单（⚠️ 重构）

「解法定义」章在难点之后、架构之前——本书六步中承上启下的一步。对 MBA 而言应冻结：

| 冻结项 | 决策空间 | 对下游的强制力 |
| --- | --- | --- |
| 篮粒度 | 事务/会话/日聚合 | fact 表主键与 ETL 切分 |
| 目标规则族 | 商品对/品类对/k-项集 | 共现预计算范围（防爆炸） |
| 测度集 | support+confidence+lift 至少两项 | 结果表列清单 |
| 阈值与 Top-N | 每店/每品类取前 N 对 | 算法引擎参数与集市行数 |
| 刷新周期 | 日/周/月 | 05 章 ETL 调度 |
| 消费方式 | BI 报表/回写促销系统 | 权限与接口设计 |

**编者按 ⚠️**：这张表是本册对「模式六步」最有操作价值的一步的重构——2012 年它对抗的是
「先建大宽表再想找用法」的惯性；2026 年它对抗的是「先上 ML 管道再问业务要不要」的惯性，
同构。

## 3.3 难点→设计决策的推导链（本章与 04 章的接缝）

```text
组合爆炸   → 规则族冻结（3.2）→ 集市只存 Top-N 结果 + 篮原子事实
粒度陷阱   → 篮键生成规则写进 ETL 规约（05 章）
流行度伪装 → 结果表同时落三项测度，BI 层禁裸排序
时间混杂   → 促销/价格事件作为维度保留（→ Part II 时变维的技术伏笔）
可执行鸿沟 → 规则表带 owner/action/review_date 治理列（⚠️ 2026 回看为「数据产品」先声）
```

「时间混杂」一行的伏笔值得全书级阅读：第 4 章的 MBA 难点清单里，**只有这一条**无法在
Part I 内部解决（需要商品价的时变历史），而全书 Part II 恰好讲时变——14/15 章的融合
（✅ 章题「Market Basket Analysis in a Time Variant Data Warehouse」）在目录结构上即呼应
这一缺口 ⚠️ 推定。

## 3.5 反模式清单（⚠️ 编者归纳，供读码时对号）

- **全矩阵预计算**：不加规则族冻结直接物化 n×n 共现——行数爆炸且随 SKU 变更作废；
- **裸置信度排行榜**：bread→milk conf 高居榜首毫无新增信息（流行度伪装，3.1-3）；
- **篮定义漂移**：ETL 改版后「会话篮」被偷偷换成「日篮」，所有历史 lift 不可比（粒度陷阱，
  需 05 章装载断言防御）；
- **无刷新 SLA 的规则表**：BI 端把陈旧规则当现行策略——「持续 ROI」退化为一次性报告（2.3 反命题）。

2. 为「品类对」规则族重写冻结清单：粒度上抬后，哪一条难点被缓解、哪一条被加剧？（组合爆炸缓解，流行度伪装加剧 ⚠️）

## 3.7 案例推演：便利店「品类对」规则族的一次完整冻结（⚠️ 编者增补演练）

把 3.2 合同表落到一件最小业务——社区便利店想用规则指导鲜食柜补货：

```text
① 篮粒度   : POS 单笔小票（会话键沿用收银流水号；外卖单另立渠道列，不并篮）
② 规则族   : 仅品类对（饮料×鲜食 等 5×5 上三角），不做商品对——SKU 600 个的爆炸面直接砍掉一个量级
③ 测度集   : support + lift（confidence 由 BI 端现算，不落列）
④ 阈值     : support ≥ 0.5% 且每品类对按 lift 取前 10 店
⑤ 刷新     : 周一凌晨跑上周数据；促销日历当日快照随批写入（时间混杂的对治）
⑥ 消费     : 补货系统 API 读当期视图；周报 PDF 走邮件（两条消费路径口径同源）
```

- 推演暴露的三处「难点→条款」映射：②对应组合爆炸、⑤对应时间混杂、⑥对应可执行鸿沟——
  **难点清单不是抱怨列表，每一条都会在某处合同行留下强制条款**，这正是本书把 Solution
  Definition 单独成章的理由（✅ 章题级结构证据）。
- 若跳过 ②直接全量跑商品对：600 SKU → 179,700 对/周，其中 support≥0.5% 的约 2,000 对
  再按 lift 排序——算力账与噪声账同时爆掉（手推即懂 ⚠️）。
- 与 🔧E3 的接合：本演练把「bread/butter」换成品类代号后，SQL 一字不用改——规则族的
  抽象层级只改维表 JOIN 深度（04 章雪花教训在此复用：品类层级务必一致性）。

## 核心概念速览（中英对照）

- **组合爆炸** — Subset Explosion：MBA 全枚举不可行，规则族必须先冻结（3.1-1）。
- **篮粒度声明** — Basket Grain Declaration：会话/事务/日聚合的选定先于一切统计（3.1-2）。
- **流行度伪装** — Popularity Confounding：高渗透单品制造虚假强共现（3.1-3，🔧E3 实证）。
- **归一化测度** — Normalized Measure：lift/余弦剥离单品流行度的测度族。
- **时间混杂** — Temporal Confounding：促销事件与共现结构互相污染（3.1-4，Part II 伏笔）。
- **解法定义** — Solution Definition：架构开工前的查询/粒度/测度/阈值/周期六项冻结（✅ 章题）。
- **Top-N 规则表** — Top-N Rule Mart：集市只存头部规则行，不存全矩阵（3.2）。
- **治理列** — Owner/Action/Review Columns：规则表内嵌执行责任字段（3.1-5 ⚠️）。
- **裸桥表** — Unallocated Bridge：篮事实不做金额分摊，聚合止于篮层（3.4）。
- **反模式** — Anti-Pattern：全矩阵/裸排行/漂移/无 SLA 四件套（3.5）。

## 最新演进与工业实践

2012→2026（✅ URL 均 2026-10-02 `curl -L` 200；机制 ⚠️ 转述）：

- **阈值学习的自动化**：Apriori 支持度剪枝让位于 FP-Growth/Eclat 系与深度嵌入召回——「组合
  爆炸」难点在算法侧被工程化解决，但**数仓侧的冻结清单纪律**（3.2）反而更重要：管道越自动，
  未声明的粒度漂移越隐蔽 ⚠️。
- **指标层治理**：Solution Definition 的 2026 对应物是 metrics/semantic layer——规则族、测度、
  阈值以配置入库、随代码评审（盘上 `Analytics_Engineering_with_SQL_and_dbt/`，ls ✅，波尾对位登记）。
- **因果化升级**：「时间混杂」的现代解法是 uplift/因果推断——促销与基线用实验分离，共现只做
  召回不做结论；零售媒体（retail media）定价团队普遍配了 holdout 流水 ⚠️。
- **Data Vault 的桥表答案**：Bridge FDE（factor dimension element）模式把分摊因子做成一等公民，
  与本册「篮层不摊钱」互证——详见 [../Data_Vault_2_0/06-高级建模PIT与Bridge.md](../Data_Vault_2_0/06-高级建模PIT与Bridge.md)（✅ 在盘）。
- **在线推理回写**：规则/模型输出回写集市 → 今日特征库（feature store）双写模式；本册 3.1-5
  的治理列在 2026 由特征平台元数据托管，人工纪律降为兜底 ⚠️（✅ https://www.kimballgroup.com/ 首页
  的当代归档说明与目录线交叉印证）。
