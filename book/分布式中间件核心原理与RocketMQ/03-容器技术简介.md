## 核心精讲

（以下为教学性梳理，代码均**教学示意，不参与构建**。）本章偏操作，核心是「把第 2 章的 Boot 工程容器化」。

### 3.1.5–3.1.6 多阶段构建 Spring Boot 镜像（教学示意）

```dockerfile
# 教学示意，不参与构建：多阶段构建，最终镜像只含运行期
FROM maven:3.9 AS build
WORKDIR /app
COPY . .
RUN mvn -q package -DskipTests

FROM eclipse-temurin:17-jre
COPY --from=build /app/target/order-service.jar app.jar
ENTRYPOINT ["java","-jar","/app.jar"]
```

### 3.2.3 用 K8s 部署（教学示意）

```yaml
# 教学示意，不参与构建：Deployment + Service
apiVersion: apps/v1
kind: Deployment
metadata: { name: order-service }
spec:
  replicas: 3
  selector: { matchLabels: { app: order-service } }
  template:
    metadata: { labels: { app: order-service } }
    spec:
      containers:
        - name: app
          image: registry/order-service:1.0
          ports: [{ containerPort: 8080 }]
---
apiVersion: v1
kind: Service
metadata: { name: order-service }
spec:
  selector: { app: order-service }
  ports: [{ port: 80, targetPort: 8080 }]
```

> 关键认知：**镜像解决「环境一致性」，K8s 解决「多实例编排与自愈」**；RocketMQ 这类有状态组件
> 在 K8s 上通常借助 Operator（如 RocketMQ Operator）或用 StatefulSet 管理，第 6 章的集群部署可与之衔接。

## 版本演进

- **本书基于 Docker 20.x 系、Kubernetes 1.2x 系**（具体小版本以纸书为准，未能逐字核实）。
- **🔧 2026 视角：Docker 桌面版许可变化**。2021 年起 Docker Desktop 在大公司需付费，
  催生 **Podman / nerdctl / Rancher Desktop** 等替代；但 Docker 镜像格式（OCI）仍是事实标准。
- **🔧 2026 视角：K8s 生态成熟但变复杂**。Helm、Operator、CRD 普及；同时出现
  **K3s（边缘轻量）、Kubernetes 批处理（Kueue）、eBPF 可观测（Cilium）** 等方向。
- **🔧 2026 视角：Serverless 容器**（AWS Fargate、阿里云 ECI、Knative）让「部署」进一步托管化，
  与第 6 章「生产环境调优」的复杂度形成对照——部分团队不再自建 K8s 集群。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「容器 = 轻量虚拟机」 | 容器共享内核、隔离在进程级，不是完整 Guest OS |
| 2 | 「镜像越小越好，忽视可调试」 | 太精简镜像难排障；用 `eclipse-temurin` 等带工具链的基础镜像折中 |
| 3 | 「K8s 能解决一切部署问题」 | 有状态（如 RocketMQ Broker）需 StatefulSet/Operator，不能当无状态随意调度 |
| 4 | 🔧 本书未提 OCI 标准与 Docker 许可变化 | 2026 应说明镜像格式标准化与桌面版许可影响 |
| 5 | 🔧 本书未提 Serverless 容器 | 2026 部分场景用 Fargate/ECI/Knative 替代自建 K8s |
