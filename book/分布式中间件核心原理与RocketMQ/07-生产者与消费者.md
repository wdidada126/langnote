## 核心精讲

（以下为教学性梳理，代码均**教学示意，不参与构建**。）本章是 RocketMQ 的「数据平面」主线。

### 7.1 发送模式（教学示意）

```java
// 教学示意，不参与构建：三种发送
producer.send(msg);                       // 同步：等结果，最可靠
producer.send(msg, new SendCallback() {   // 异步：回调拿结果，高吞吐
    public void onSuccess(SendResult r) {}
    public void onException(Throwable e) {}
});
producer.sendOneway(msg);                 // 单向：发了不等，最快但不可靠
```

### 7.2 MessageQueue 与路由

- 一个 **Topic** 拆分为多个 **MessageQueue**（逻辑分片），分散在不同 Broker。
- 生产者按策略（轮询/哈希）选 queue，实现发送端负载均衡。
- Broker 故障：客户端路由表剔除故障 Broker，重试发往其他 queue（配合 5.2 路由刷新）。

### 7.3 Broker 持久化（核心机制）

| 机制 | 说明 |
| --- | --- |
| CommitLog | 所有消息顺序追加写入的物理日志，保证高吞吐 |
| ConsumeQueue | 每个 queue 的索引（offset/长度/tag），消费时按索引定位 |
| IndexFile | 按 key/时间查消息的哈希索引 |
| 同步刷盘 | 消息落盘后才返回，不丢但慢 |
| 异步刷盘 | 写 page cache 即返回，批量落盘，快但宕机可能丢 |

> 关键认知：**顺序写 CommitLog + 消费端零拷贝（mmap）** 是 RocketMQ 高吞吐的底层原理（呼应 4.4.1）。

### 7.4 消费：集群 vs 广播、Push vs Pull

| 维度 | 说明 |
| --- | --- |
| 集群模式 | 同一消费组内 queue 均分给成员，一条消息只被组内一个消费者处理 |
| 广播模式 | 组内每个消费者都收到全量消息 |
| Push | 长轮询，Broker 有消息主动推（体验好） |
| Pull | 消费者主动拉，控制力强（5.x PopConsumer 改进拉模型） |

### 7.5 Spring Boot 整合（教学示意）

```java
// 教学示意，不参与构建：Spring Boot 发/收
@Resource RocketMQTemplate tpl;
tpl.convertAndSend("order-topic", order);          // 发

@RocketMQMessageListener(topic = "order-topic", consumerGroup = "order-cg")
public class OrderListener implements RocketMQListener<Order> {
    public void onMessage(Order o) { /* 业务处理 */ }
}
```

## 版本演进

- **本书基于 RocketMQ 4.x 的 Pull/Push 与集群/广播消费、原生 + Spring Boot 整合**。
- **🔧 2026 视角：5.x PopConsumer**。5.x 引入 **Pop 消费（弹幕消费）**，解决长轮询与 rebalance
  抖动、消费进度（offset）由服务端管理，更适合多语言与弹性消费。原书 7.4 的 Push/Pull 模型在 5.x 下
  多了 Pop 这一现代选项。
- **🔧 2026 视角：Spring Cloud Stream 绑定器**。除原生与 `RocketMQTemplate` 外，2026 常用
  **Spring Cloud Stream + RocketMQ Binder** 做声明式绑定（见 00-总览与第 12 章）。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「异步发送一定丢」 | 异步只是不等返回，仍有 ack，配合重试可可靠 |
| 2 | 「单向发送能可靠」 | 单向发了不等，失败无感知，仅适合可丢日志 |
| 3 | 「消费组 = 广播」 | 集群模式一条消息只被组内一人消费；广播才人人都收 |
| 4 | 「Pull 比 Push 先进」 | 二者互补，Push 长轮询体验好，Pull 控制强；5.x Pop 统一改进 |
| 5 | 🔧 本书未提 5.x PopConsumer | 2026 应补服务端托管 offset 的现代消费模型 |
| 6 | 🔧 本书未提 Spring Cloud Stream Binder | 2026 Java 整合可声明式绑定 RocketMQ |
