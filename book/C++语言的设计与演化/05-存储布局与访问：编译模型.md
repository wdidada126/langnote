# 05 存储布局与访问：编译模型

> 对应原版 **第二部分第 10 章（存储管理/存储布局与访问）**——"语言分册"（Part II）的 opener。
> C++ 与机器之间的那份契约：对象在内存里长什么样、名字怎么绑到地址、
> cfront 如何靠"转译为 C"兑现零开销承诺。
> ⚠️ 小节归属未逐条核实，按主题重写。

## 核心概念速览（中英对照）

- **存储布局** — storage layout：对象的字节镜像是语言契约的一部分（可跨编译单元直接访问）。
- **布局兼容** — layout compatibility：C 结构体在 C++ 里镜像不变——cfront 策略的几何表达（✅ 术语后来在标准中定形）。
- **翻译实现** — translation to C（cfront）：C++ → C + 运行时库，1985–1991 的主流实现路线。
- **直接访问 vs 查表** — direct member access vs table lookup：非虚成员偏移编译期定死；虚调用一次表跳转——"pay only for what you use"的地址版。
- **虚函数表** — vtable：多态的代价载体，每（多态）对象一个指针。
- **名字改写** — name mangling：把重载/作用域信息编码进链接符号；C++ ABI 的头号非标准发明。
- **this 调整** — `this` adjustment：成员函数入口/调用点修正指针——MI 下 thunk 机制的前奏（`07` 章）。
- **静态存储期对象** — static/global objects：构造在 `main` 前、析构在 `main` 后——跨翻译单元次序问题（`11` 章主场）。
- **成员指针** — pointer to member：带"偏移 or 槽位"二义性的昂贵类型——D&E 坦承"为完整性付的税"。
- **独立编译** — separate compilation：以 TU 为单位、文本包含供上下文——`10` 章预处理器批判的靶子。
- **vague linkage** — 弱符号与"多处实例化合并一处"（模板/inline 函数的链接前提 ⚠️ 平台词，本目录不展开）。
- **常量折叠进布局** — `const`/枚举对代码生成的贡献：编译期可见性作为性能资产（`06` 章的转换阶梯共享之）。

## 本章地图

| 问题 | C++ 的答案 | 付出的代价 |
| --- | --- | --- |
| 对象放哪 | 值语义：栈/嵌入/堆全由使用者定；语言不管"所有权" | 悬垂引用、浅拷贝陷阱（所有权语言化见 `11`/`12` 章） |
| 名字→地址 | 编译期符号 + 链接期解析；类作用域靠改名编码 | 链接错误晦涩；跨厂商 ABI 长期不通（Itanium ABI 后收敛 ⚠️ 年份） |
| 多态寻址 | 虚表间接一次；非虚零开销 | 忘写 virtual → slicing；教育成本永久化 |
| 编译模型 | 独立编译 + 文本包含（`#include`） | 宏污染、编译放大（`10` 章主场） |

## 问题空间：布局到底是实现细节还是语言契约

- 备选 A（Simula/Smalltalk 式）：对象住堆里、句柄访问、GC 管理。
  一切皆引用 → 与 C 的值镜像不兼容，且为不用多态的人强制付费——违反 `01`/`02` 章两条硬约束，否决。
- 备选 B（C 式）：函数第一参数显式传 struct 指针。零开销但没有作用域/访问控制/构造纪律——不够用。
- 胜出 C（**静态布局 + 编译器合成偏移**）：
  `struct` 加函数成员但**不改布局**——非虚情况下与 C 逐字节同形；
  成员函数只是"自动带 `this` 参数的函数"，数据成员才是对象的全部——
  这条"函数不进对象"的坚持，同时解释了 sizeof 不含方法、链接器对布局透明、
  以及"给 C 回调传 this 指针"这类桥接代码为何可行。🔧

```cpp
struct Point { int x, y; int sum() const { return x + y; } };
static_assert(sizeof(Point) == 2 * sizeof(int));
// ^ 非虚 → 与 C struct 同形。C++11 起可用 static_assert 把这一"布局直觉"写成可编译契约 ✅
```

## 机制精讲：三件"档案级"细节

**1. 虚表不是语言概念，是实现契约。**
D&E 论证为何"每类一表、对象头一指针、调用 = 头指针 + 固定槽位"是零开销下唯一可行分发：
逐对象方法查找表（Smalltalk 式）为每个对象每个调用付费；
类型开关 + 直调（手工去虚化）不可扩展。vtable 方案的账本：
每对象 +1 指针（仅多态类）、每次虚调用 +1 间接跳转——**仅此而已**，其余照旧直调。

**2. 名字改写的三段妥协。**
C 链接器只认不透明符号 → 必须把类作用域/重载签名塞进符号名；
塞法无标准 → 1990s 各厂商 ABI 互不兼容（同名库不可互换、`new` 的符号语义各异）；
Unix 世界靠 Itanium/psABI 系列收敛（2000s 初 ⚠️ 年份），MSVC 自成一系至今——
`05` 章的"链接器问题"以 ABI 文档的形式活到今天（✅ cxxabi.com 与微软文档公开可查）。

**3. 成员指针的两难。**
指向成员函数的指针必须同时容纳"非虚直调地址"与"虚槽位/偏移 + this 调整"两种世界，
故在 MI/虚基类平台上膨胀为多字宽并带运行期判别——
D&E 直白承认这是"为完备性支付的昂贵税"，并给出忠告：热路径与接口层避免成员函数指针（✅ 该告诫在 cppreference"不可移植"提示中仍是标准建议）。

## 著名案例：`offsetof`、位域与"可移植布局"的长期悬案

本章的布局契约在两个角落始终没完全兑现：
- 位域（bit-field）的排列顺序与填充是 implementation-defined——"与 C 兼容"在这里变成"与各家 C 实现兼容"；
- 非 standard-layout 类上 `offsetof` 曾长期是 UB——直到 C++11 把"标准布局"定义为正式术语后逐步放宽（✅ ISO 锚点，细则 ⚠️ 以条文为准）。
教训：**凡把底层细节写进契约的语言，契约没覆盖的角落就成了不可移植性的雷区**——
这正是后来 reflection/序列化方向（`12` 章）要还的旧账。

## 最新演进与工业实践

- **契约的标准化补票**：C++11 定义 standard-layout/trivially-copyable 术语族、`alignas`/`alignof` 语言化、
  `[[gnu::packed]]` 之类厂商现实倒逼标准侧回应——"布局即契约"从惯例变成条文（✅ ISO 锚点）。
- **新抽象不碰布局**：C++20 协程把帧生命周期交给可定制的 promise_type/分配器（值语义的胜利）；
  modules 只改**前端输入方式**（编译时），不动**对象布局**（运行时）——
  对照 `10` 章：越接近编译模型的改动兑现越慢，越远离布局的改动越容易成功。
- **性能工程正吃红利**：游戏 ECS、网络零拷贝解析、序列化器直接按布局读字节——
  全靠本章契约；反例教育同样活跃：`vector<bool>` 代理引用、`reinterpret_cast` 跨类型 punning
  与严格别名（strict aliasing）的冲突是"布局自由"的灰色账单（✅ cppreference；个案行为 ⚠️ 复核）。
- **厂商 ABI 文档 = 本章的 2020s 实现章**：Itanium C++ ABI、MSVC ABI、各 psABI 补充——
  研究 vcall/vbase offset 机制的读者可直接把它们当"第 10 章续篇"读。

## 常见误区

- 误区：「虚函数很慢所以 C++ 慢」。虚调用 ≈ 一次难内联的间接跳转；
  贵的是它阻止的优化。编译器正用去虚化收回代价（Clang/GCC 的基于 vtable 的推断与 WPA 优化 ✅ 公开特性），
  这是"不输手写"承诺的当代兑现方式。
- 误区：「sizeof 含 vptr 是语言规定」。标准不规定；vptr 方案赢在实现简单与 ABI 可互操作——
  属"实现契约"层（见上机制 1）。
- 误区：「成员函数指针和普通函数指针同宽」。只在"非虚、无 this 调整"子集成立（`07` 章 MI 会拆穿）。

## 自查三题

1. 为什么"成员函数不占对象空间"能同时导出 sizeof 行为、C 布局兼容与回调桥接三件事？
2. vtable 方案对照"逐对象方法表"，在两本账（内存/调用）上各赢在哪里？
3. 举一例"布局契约未覆盖的不可移植角落"，并说明它为何成为后续语言特性（反射）的动因。

## 布局决策的"账本"（零开销原则的地址版结算）

| 机制 | 不使用者付什么 | 使用者付什么 | 账本依据（D&E 大意） |
| --- | --- | --- | --- |
| 成员函数 | 零（不进对象） | 传 `this` 一次（多为寄存器） | "函数不是数据" |
| 虚函数 | 非虚类零（无 vptr、直调） | 每对象一指针 + 每调用一次间接 | vtable 档案（机制 1） |
| 重载 | 不用重载者符号不变长？——不，改名全量生效 | 链接错误信息更可读 | 改名是全有全无的税，✅ 书中承认的少数"人人付一点"例外 ⚠️ 措辞 |
| RTTI | 无多态类零元数据 | `dynamic_cast` 才拉完整类型表 | `03` 章妥协案的落地形态 |
| 成员指针 | 不用者零 | MI/虚基类场景胖化 + 判别开销 | "为完备性付的税" |

这张表是本章最值得背下来的东西：**C++ 的每个抽象都有一行明确的价目表**——
"零开销"不是口号，是逐机制结算的会计制度（`12` 章将看到新特性继续按此格式报账）。
