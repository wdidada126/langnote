# 01 C++ 的设计目标与约束：从史前到诞生

> 对应原版 **第一部分第 1–3 章**（C++ 的史前时代 / C with Classes / C++ 的诞生）。
> 这三章是全书的"地质层"：先讲 Simula 与 C 各自的贡献与缺口，再讲 1979–1985 年
> 从"带类的 C"到 Release 1.0 的三次形态跃迁。
> ⚠️ 各章小节划分未逐条核实，本文按主题重写；凡逐月细节以原书第 5 章年表为准。

## 核心概念速览（中英对照）

- **带类的 C** — C with Classes：1979 年 Stroustrup 在 C 编译器上做的第一个原型，"classes" 一词的来历。
- **增量演化** — incremental evolution：不做全新语言，而是在 C 上一版一层地加机制，每步都保持可编译。
- **两个源头** — Simula + C：前者给类/继承/动态分发，后者给值语义/布局控制/可移植的编译模型。
- **仿真驱动的需求** — simulation-driven requirements：分布式系统仿真论文（写于剑桥时期）是"为什么需要新语言"的问题陈述。
- **名字改写** — name mangling/encoding：为让 C 链接器容忍重载而给函数名编码类型信息的最早妥协之一。
- **虚拟函数** — virtual function：Simula 式动态分发的显式化——调用点写 `virtual` 才进分派表。
- **构造/析构** — constructor/destructor：初始化与清理的不可绕过入口，后来 RAII 的地基。
- **自由存储** — free store：`new`/`delete` 管理的堆，区别于 C 自动存储期对象的"值在哪"问题。
- **引用** — reference：1982 年前后加入的别名机制，动机是 I/O 流参数与避免拷贝语义泄漏。
- **常量** — const：1985 年前后成型，把 `#define` 常量拉进类型系统（`10` 章名字空间与 `06` 章强制还会再遇它）。
- **cfront** — C++ 翻译器前端：把 C++ 译成可编译的 C 代码，1985 年 Release 1.0 的实现形态。
- **新 C++** — New C++：书中第 3 章的自称——1983 改名到 1985 发布之间成型的重载/常量/引用版本。

## 问题空间：1979 年的那道选择题

- 场景：贝尔实验室的分布式/网络设备仿真研究，需要"既建模又落地"的语言。
- Simula 67 一侧：类、继承、虚机制、GC——抽象天花板；但运行时按对象/按任务收费，
  且拿不到 Unix/C 的系统编程生态与可移植性。
- C 一侧：便宜、快、硬件可预测、随 Unix 扩散——但 `struct` 没有不变式、没有名字隔离、
  没有抽象类型；大规模程序靠命名约定与纪律裸奔。
- 需求画像（D&E 大意）：**编译期纪律 + 运行期克制 + 与既有世界互操作**，三者一个不能少。

## 备选方案全景（1970s 末–1980s 初）

- Ada：军工级强类型与任务模型——重量、编译链成本、与 Unix 文化错位；
- Modula-2/3：模块与强类型漂亮——生态与系统编程纵深不足；
- Smalltalk-80：纯对象 + 消息派发 + GC——值语义与布局控制为零，嵌入式/系统场景出局；
- Objective-C（1983 公开）：单继承 + 运行时消息——保留了 C，但动态运行时与静态检查两头不到岸；
- "等下一代硬件"论：认为 PDP-11 级机器就该用汇编——被 VAX/工作站浪潮证伪。

**否决逻辑**（全部撞在同一对硬约束上）：
1. 必须从 C 出发做**超集式演化**——存量代码、存量程序员、存量链接器是入口条件不是历史包袱；
2. 每个抽象机制必须能翻译成"本来手写的 C"——翻译不出来就砍或改设计（`05` 章 cfront 契约的种子）；
3. 语言机制优先于库约定——`class` 关键字而非"大家自觉的 struct 规范"，因为纪律不可编译期检查。

## 取舍之后的三件定盘事（1979–1985 时间线，⚠️ 月粒度未逐条核实）

- 1979–1981：C with Classes——类、成员作用域、派生与显式 virtual、`inline` 式成员函数；
  构造/析构、名字改写为链接器服务。
- 1982–1983：引用、重载成型；改名 **C++**（通常归功于 Rick Mascitti，1983 年末 ⚠️ 细节）；
  操作符 `new`/`delete`、`const` 进入语言边缘。
- 1984–1985：静态成员、枚举、更完整的类型检查；1985-10 Release 1.0（cfront），
  1985-12 TCPL 第 1 版出版（✅ 通行记载）——语言第一次同时拥有"可买的实现 + 可查的书"。

🔧 示意：Release 1.0 时代能编译的"现代"代码（教学示意，不参与构建）——

```cpp
struct Vector {            // 当时 class/struct 区分尚未完全定型 ⚠️
    double* p; int n;
    Vector(int);           // 构造：不变式的唯一入口
    ~Vector();             // 析构：清理不可逃逸
    double& operator[](int i) { return p[i]; }  // 重载 → 链接符号必须携带签名（名字改写）
    virtual double norm() const;                // 显式 virtual：代价在调用点可见
};
```

三个细节对应三件当年的"新"：值语义容器（拷贝要自己写——没有移动、没有 Rule of Zero）、
显式虚分派、以及要求链接器容忍改名符号的重载体系。

## 著名案例：为什么不是"更好的那门语言"

D&E 前史最常被忽略的论证：**C++ 赢在迁移成本曲线**。
1980 年代同时存在更优雅的面向对象语言，但它们要求组织级"改换门庭"；
C with Classes 允许一个 C 程序员带着一箱子存量代码、以周为单位渐进迁移。
后果双面：(a) C 的裂缝（数组退化、隐式转换、头文件）被全盘继承（`06`/`10` 章持续付税）；
(b) "演化而非革命"从成功路径升格为宪法原则（`02` 章）。

## 最新演进与工业实践

- **增量演化成为语言品牌**：C++11/14/17/20/23 全部延续"每版超集"节奏；
  WG21 至今以提案→工作组投票→工作稿的管线运转（isocpp.org 公开流程）。
- **两个源头的当代回响**：C 兼容继续松动但从未放弃——WG21 与 WG14（C）自 2020 年代设 liaison
  专门协调公共子集（✅ 机制存在为公开信息）；Simula 遗产（虚函数、类层次）在 C++20 concepts
  的静态多态面前退居二线，但运行时多态无标准替代——"两套多态都要"的判断长期兑现。
- **GC 从未进入 Core Language**：本章把 Simula 式默认 GC 列为"不可接受代价"，
  此后四十年回收问题一直在库/扩展层处理（详见 `11`、`12` 章）。
- **工业界**：游戏/嵌入式/高频交易等"值语义 + 布局控制"用户群是本章取舍的直接后裔；
  clang 与 MSVC 的改名方案（Itanium ABI 与 MSVC 系）至今是 ABI 级契约——
  1979 年的"链接器怎么办"从未退场（✅ 两套 ABI 文档公开可查）。

## 常见误区

- 误区：「C++ 一开始就是一门完整的面向对象语言」。实际：C with Classes 连构造/析构、
  重载都没有（分别到 1982 年前后才逐步出现 ⚠️ 逐年细节以第 5 章年表为准）。
- 误区：「兼容 C 是历史包袱所以是失算」。D&E 的论证相反：兼容性是用户基数与生态的来源，
  代价以"每件事论证两遍"的形式持续支付——是权衡不是疏忽。
- 误区：「`virtual` 默认开更安全」。见 `07` 章 virtual 默认代价争议——1980 年代这是真实的备选，
  被零开销原则与布局兼容双票否决。
