## 核心概念速览（中英对照）

- **自由存储** — free store：`new`/`delete` 的世界；与 C 堆同源，但带构造/析构契约。
- **placement new** — 在指定地址构造对象：把"分配"与"初始化"解耦的语言级出口（内存池/自定义分配器的地基）。
- **可替换分配** — replaceable operator new/delete：全局或按类接管分配策略——C++ 比所有 GC 语言都早给"分配器注入"留门（✅ C++98 起为标准行为）。
- **所有权** — ownership：D&E 时代靠注释与惯用法；C++11 后语言化（unique/shared/weak_ptr ✅；Rule of Three/Five/Zero ⚠️ 术语年代）。
- **保守式垃圾回收** — conservative GC（Boehm 式）：不区分指针与整数的"宁可信其有"标记——C++ 布局自由度的直接产物（`05` 章的债）。
- **精确 GC 与句柄** — precise collection & handles：把可移动对象关进指针笼子；与值语义正面冲突是 D&E 反对钦定 GC 的核心理由。
- **终结器之痛** — finalizers：回收期回调的次序/重入/复活难题——邻国（Java `finalize` 弃用史 ⚠️ 措辞）为鉴。
- **静态初始化次序灾难** — static initialization order fiasco：跨 TU 构造无序、析构后仍被引用的长期隐疾。
- **Meyers 单例** — 函数局部静态的惰性初始化惯用法；其线程安全性后来直接进标准（"magic statics"，C++11 ✅）。
- **内存模型** — memory model：多线程可见性公理化（happens-before 体系）——C++11 才有的标准语义（✅ ISO 锚点）。
- **指针不可枚举** — pointer safety 规则：标准既不要求 GC、也不允许实现"捏造"位模式——D&E 立场的条文化平衡态（⚠️ 条文细节复核）。
- **数据竞争即 UB** — data race → undefined behavior：C++ 内存模型的立法原点，把并发正确性转为可推理命题。

## GC 线：四种回收方案与 C++ 的结构性选择

问题：堆对象回收需要知道"谁还指着它"。备选全景：

- **A. 引用计数**：零暂停、可预测；循环泄漏 + 原子计数税。
  C++ 的半官方答案 `shared_ptr` 选了它，再用 `weak_ptr` 补循环账（✅ TR1/C++11）——
  D&E 对计数协议脆弱性的演示（继承类切片进计数壳、多线程重赋值竞态）至今仍是面试常客。
- **B. 保守式标记-清除**（Boehm-Demers-Weiser，✅ 项目现存且维护中）：
  不改分配即接管 `new`，把"字长且像合法地址的值"全当指针。
  代价：浮动垃圾、扫描暂停、严格意义不可移动对象（不压缩）。
  D&E 视之为"C++ 生态可共存的务实方案"——事实证明它是唯一活下来的全自动回收形态。
- **C. 精确式 + 句柄/指针反转**（Java 路线）：要求所有堆引用可枚举、可更新——
  与栈值语义、`reinterpret_cast`、C 库回调持指针（`05`/`06` 章的资产）正面相撞。
  在 C++ 里做精确 GC ≈ 废除 C++ 的指针自由度。这是"不钦定 GC"的第一原理。
- **D. 最小标准接口**（"哪些指针可能有效"的语言级声明；Boehm/Hirschfeld 在 C++0x 时代再提案 ⚠️ 结果：未进入）。

D&E 结论（大意）：语言只承诺**可共存性**，回收策略留给实现与库多选——
此后三十年的现实：bdwgc 服务遗留长尾、`unique_ptr` 独占/移交模型成为手工 GC、
"智能指针即垃圾回收的库实现"（Sutter 语 ⚠️ 出处措辞）成为社区俗谚。

## 静态对象线：并发章先解决了"最小并发问题"

跨 TU 全局对象构造次序未定义 + 析构后仍被引用 = 两大老雷（`10` 章 module 提案失败的注脚：
次序问题当时无人能给出可辩护语义）。语言化进度条：

- Meyers 单例（函数局部静态，90s 惯用法）：首次调用时构造、`main` 后逆序析构；
- **C++11：局部静态初始化必须线程安全**（"magic statics" ✅ ISO 锚点）——
  委员会顺带消灭了"初始化竞争"这个最小并发问题，成本为零（不用者不付费的名字版）；
- `std::atomic` + `call_once`（C++11 ✅）把剩余场景变成可验证代码。

🔧 惯用法对读（教学示意，不参与构建）：

```cpp
struct Logger { ~Logger() { flush(); } };
Logger g_log;              // 危险：另一 TU 的静态对象晚于它析构 → 写已关闭的资源 🔧

struct Logger2 {           // Meyers 单例：C++11 起隐式线程安全初始化（magic statics ✅）
    static Logger2& inst() { static Logger2 l; return l; }
};
// 当代正解：显式生命周期管理（启动期构造、关停期先于依赖方析构）——"库承担策略"的 D&E 路线 🔧
```

## 并发线：第 21 章的预言与其实现方式

第 21 章（⚠️ 推定章号）的诚实之处：承认"多线程需要语言帮忙"，同时拒绝"为并发重造类型系统"。
当时的争论点与 C++11 的落点对照：

- 共享内存 vs 消息传递：标准选了共享内存 + 原子操作作地基（机器现实），
  消息/任务模型留给库（channel/actor 至今民间）——与"机制进语言、策略进库"完全一致；
- 内存模型之争：是否钦定强顺序？最终采纳 Boehm 等推动的**弱序 + happens-before** 公理
  （与 C11 同步定稿 ✅ 两标准同年；人名与过程细节 ⚠️ 从简）——
  因为它同时满足硬件现实（x86/ARM 顺序差异）与优化器合法行为；
- `volatile` 的期望管理：D&E 时代的"volatile 做同步"幻觉被明确否决——
  C++11 规定 `volatile` 不承诺原子性/顺序（✅ 标准语义），这一课以"文档重写"方式收场。

## 最新演进与工业实践

- **所有权语言化（2011–2026 主线）**：unique/shared/weak（C++11 ✅）→ `make_unique`（C++14 ✅）→
  多态分配器（C++17 ✅）→ C++26 周期的 lifetime safety profile 与 `owner<T>` 方向
  （⚠️ 状态流动中，不点名结论）。
- **回收的现实光谱**：bdwgc 仍是保守式独苗（✅ GitHub ivmai/bdwgc 持续维护）；
  WASM 混合 GC 给精确式带来新场景（Emscripten 与 Boehm 组合史 ⚠️ 现状查其文档）；
  CHERI 等能力硬件研究让"可追踪内存"重新上桌——布局自由（`05` 章资产）与安全需求的新一轮对冲。
- **并发/异步长尾**：C++11 线程库 → C++20 `jthread`/`latch`/`barrier`/`stop_token`（✅ ISO 锚点）→
  sender-receiver 执行框架（C++26 方向 ⚠️ 措辞）——"任务与调度"至今走库层，与第 21 章预判一致。
- **协程**：C++20 协程（✅）为"每任务一小帧"提供无阻塞栈的语言语法——
  与 D&E 并发章"任务隔离"设想的隔代握手（有栈/无栈取舍见 `12` 章）。
- **工业界**：内存安全监管压力（美 ONCD 2022 报告点名内存不安全语言 ⚠️ 引用对原文）下，
  C++ 的答复是把第 19–21 章的答案产品化：sanitizers（ASan/TSan，LLVM 项目 ✅）、
  智能指针审查规则、hardening profile 方向（⚠️ 状态以 WG21 为准）。

## 常见误区

- 误区：「C++ 没有 GC 是缺陷」。准确说法：C++ 把"指针不可枚举"当作自由、用 RAII/所有权当作偿还——
  代价（UAF/泄漏）与收益（零暂停、布局控制、C 混编）自 1994 年起汇率未变，变的只是监管环境。
- 误区：「智能指针 = 所有权已入类型系统」。`T*` 在类型层仍无主；`owner<T>`/profile 方向补的正是这一刀（⚠️ 进行时）。
- 误区：「静态析构是 GC 问题」。它是**生命周期编排**问题——magic statics 与显式关停次序先于任何回收策略起作用。
