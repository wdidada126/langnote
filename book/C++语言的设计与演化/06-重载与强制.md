# 06 重载与强制

> 对应原版 **第二部分第 11 章（重载）与第 14 章（强制/转换）**。
> 两章被同一个矛盾串起来：**静态类型系统要给运算符/转换留出表达力，
> 又不能让隐式规则咬人**——重载是"让名字承载多种签名"，强制是"让类型之间的桥可审计"。
> ⚠️ 小节归属未逐条核实，按主题重写。

## 核心概念速览（中英对照）

- **重载** — overloading：同一名字在不同签名下共存；函数、运算符、构造函数皆入口。
- **签名参与身份** — signature as identity：C++ 的函数身份 = 名字 + 参数类型（链接器侧靠改名编码，见 `05` 章）。
- **决议三拍** — candidates → viable → best viable：重载决议的静态流程；歧义交还给程序员消解。
- **运算符重载** — operator overloading：语言只开放符号、不开放语法——保留结合律/优先级的"内建待遇"，禁止发明新中缀。
- **隐式用户转换** — user-defined implicit conversion：单参构造/转换运算符开启的便利之门，也是事故之门。
- **explicit** — 把"可否隐式"的决定权交还类型作者（D&E 记录了它作为折中的诞生；✅ C++98 起）。
- **具名强制** — named casts：`static_cast`/`const_cast`/`reinterpret_cast`/`dynamic_cast`——"危险要可 grep"（✅ C++98 定案）。
- **usual arithmetic conversions** — 继承自 C 的整型提升/算术转换规则：兼容性最贵的遗产之一。
- **bool 的迟到** — `bool` 到 1990s 中才进语言（早先用 `int`/位域模拟）：第 14 章围绕它讲透"隐式转换的连锁反应"。
- **安全布尔惯用法** — safe_bool：库层等语言补课的十年期民间方案（`if (x)` 可行、`x << 3` 不可行的指针技巧 ⚠️ 措辞）。
- **上下文到 bool** — contextual conversion to bool（C++11 ✅）：`explicit operator bool` 把惯用法语言化。
- **决议 vs 分派** — overload resolution is static, dispatch is dynamic：与虚函数的分工（`02` 章两套多态正交论的机制版）。

| 问题 | 备选 | C++ 取舍 |

## 重载线：问题空间与取舍

**问题空间**：`-` 有减法与取负两义、`+` 对内建类型已重载（字符串连接在别的语言里），
凭什么用户类型不许？但重载一旦与**默认实参、隐式转换、模板**相遇，决议就变成搜索问题。

- 备选 A：最佳匹配失败即错、程序员全量命名区分（`cmp_i_i` 式）——被否，违反 `02` 章规则 3（自定义类型待遇）。
- 备选 B：让子类型序参与"谁更特殊"的判定——D&E 立场鲜明地反对：
  **重载处理"不同类型同名操作"，虚函数处理"同一抽象的不同实现"**；
  两轴混合会让"加一个派生类"改变远处调用的决议结果（不可组合性，`02` 章规则 5 的直接应用）。
- 胜出 C：决议纯静态三段式（候选→可行→最优），子类型转换只作为"一次标准转换序列"计分；
  配合 `explicit` 收窄隐式门。代价：决议规则文本复杂度暴涨，1990s 各编译器实现在边角案例上互异，
  DR（缺陷报告）连年——**规则的可实现性是设计的一部分**，这是第 11 章给后世委员会的最大警示。

🔧 决议与隐式转换的互动标本（教学示意）：

```cpp
struct Ratio { Ratio(int n, int d); };
void f(Ratio);
f(42);          // 危险：int → Ratio 的隐式用户转换让这行编译通过 ⚠️ 依 ctor 非 explicit
struct Flag { explicit Flag(bool); };
void g(Flag);
g(0);           // ❌：explicit 掐断 0→bool→Flag 连环隐式转换（bool 迟到时代的坑，✅ C++98 语义）
g(Flag{true});  // ✅：直接初始化合法——"显式"只关隐式那扇门
```

## 强制线：从 `(T)e` 到四种门

C 的单一 cast 语法同时承担"去 const、换指针家族、截断数值"，审计不可能。
1990s 的新 cast 语法由委员会定案（Stroustrup 本人对"再发明一层语法"的态度在 D&E 中有保留记载 ⚠️ 细节）。
逐门的"何时正当"（第 14 章教材化内容的大意转述）：

- `static_cast`：编译期可证的桥——上行、显式下行（自担风险）、数值收窄；
- `const_cast`：唯一改 cv 限定者的门；对"真 const 对象"写回是 UB——诚实标注了"解除承诺 ≠ 解除事实"；
- `reinterpret_cast`：机器层重释——"便携性归零声明"（`05` 章布局契约的灰色通道）；
- `dynamic_cast`：多态界内的安全下行，失败可测（指针给 null、引用抛 `bad_cast`，✅ C++98）——RTTI 争议的正面资产。

老语法 `(T)e` 的保留是**兼容性铁律的执行现场**：C++ 宁可两套语法并存，
也不制造"合法代码迁移税"——风格迁移交给 lint/指南（Google style、C++ Core Guidelines）。

## 著名案例：`if (ptr)` 背后的六层阶梯

D&E 第 14 章的看家段落：要让 `if (p)` 在 `p` 为指针、整型、IO 流、后来还有
`unique_ptr`/`optional` 时都说真话，需要一条**从具体类型到"可条件"的正规化阶梯**
（指针→bool、整型→bool、算术→bool 的上下文转换）。完整后果链：

1. 老流对象为支持 `while (cin >> x)` 提供到"类指针"的转换，给 `x << 3` 式误用大开方便之门；
2. 库作者发明 safe_bool 在用户层自救（十年期）；
3. **C++11 用 `explicit operator bool` 把惯用法语言化**（✅ ISO 锚点）——
   `unique_ptr`/`optional` 的 `if (up)` 皆其果实。
这是 `04` 章"库孵化语言"论在类型系统侧的最干净闭环：语言最后追认的，正是库被迫发明的。

## 最新演进与工业实践

- **概念改写重载集**：C++20 concepts 让 `requires` 子句参与"谁更优"的半序判定（subsumption）——
  当年"重载轴"与"模板轴"两套排序第一次并入同一理论（✅ ISO 锚点，机制细节以条文为准 ⚠️）。
- **列表初始化的新护栏**：`{}` 窄化检查（C++11 ✅）+ `explicit` 列表构造，成为隐式转换审计的第二战场；
  `std::initializer_list` 让"像内建容器一样初始化"成为自定义类型的标准权利（`02` 章规则 3 续）。
- **转换的性能侧面**：stringstream 做数字↔字符串转换的巨额开销是 2010s 的共识，
  催生 `std::from_chars/to_chars`（C++17 ✅ 无 locale、可预测快）——"转换即性能问题"被工程界接棒。
- **类型诚实的还债清单**：`std::byte`（C++17 ✅）拒绝隐式当整数用；`gsl::not_null`/`owner<T>` 方向
  （`11` 章）继续给裸转换套概念笼头。
- **静态反思方向**：转换族"可枚举/可查询"仍是空缺，反射提案族在 C++26 周期推进
  （⚠️ 具体提案与状态请以 WG21 会议记录为准）。

## 常见误区

- 误区：「重载决议运行时参与」。全静态；虚分派才动态——两者拼写相似、分工正交（`02` 章规则）。
- 误区：「`explicit operator bool` 之后不能再转 bool」。它只禁隐式；`if`/`!`/三目等布尔上下文仍合法（✅ cppreference）。
- 误区：「`static_cast` 下行不检查所以都该 `dynamic_cast`」。`final`/可证类型场景里
  `static_cast` 是零开销正解；D&E 的两机制分工（编译期可证 vs 运行期须判）在 2020s 依旧成立。

## 隐式转换的"责任分配表"（第 14 章纪律大意）

- 类型作者的责任：凡"从整数/布尔/指针来的隐式入口"要么不存在、要么 `explicit`——
  `02` 章"不给人虚假安全感"的落地：语言允许门，作者必须装锁；
- 调用者的责任：跨越类型世界的每一步都应可被 grep 到（具名 cast 的"可审计"承诺）；
- 库设计者的责任：`optional`/`expected` 一类"值容器"绝不提供到 bool 的隐式转换，
  只开 `explicit operator bool`（✅ 现行标准库的统一姿势，cppreference 逐个可核）；
- 工具链的责任：窄化/符号性/丢失限定符的告警（`-Wconversion`、`-Wsign-conversion` ✅ 主流编译器选项）
  是语言"允许但标注"策略的执行伙伴——D&E 时代已确立"诊断是语言的一部分"。
