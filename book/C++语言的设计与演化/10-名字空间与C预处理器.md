# 10 名字空间与 C 预处理器

> 对应原版 **第二部分第 17 章（名字空间）与第 18 章（C 语言预处理器）**。
> 两章共享同一主题：**大规模程序的名字卫生**。
> 一个讲语言怎么给名字分房子（namespace），一个讲老强盗还在拆墙（`#include`/宏的文本本质）。
> 第 18 章末的"模块化编译"愿望，正是 C++20 modules 的直系前身叙事。
> ⚠️ 小节归属未逐条核实，按主题重写。

## 核心概念速览（中英对照）

- **名字空间** — namespaces：把全局作用域分区管理；为"多个独立演化的库共处一链"而生（✅ C++98 定案）。
- **匿名名字空间** — anonymous namespace：每个翻译单元独有的名字空间——`static` 全局的现代替代。
- **using 声明/指令** — using-declaration / using-directive：逐名引入 vs 整层倾倒；后者在头文件里是污染源。
- **ADL** — argument-dependent lookup（依参数查找）：自由函数经实参所属名字空间被找到——运算符非成员化的配套机制（Koenig 推动 ⚠️ 措辞）。
- **链接名与名字空间** — mangled linkage：namespace 不改运行期实体、只改改名方案——纯编译期机制的零开销示范（`05` 章）。
- **宏** — macros：文本替换型"预语言"；D&E 第 18 章控诉三罪：无作用域、无类型、调试盲区。
- **条件编译** — `#ifdef` 家族：不可检查的平行语法；"永远编译不到的分支"是 ODR 地雷。
- **文本包含** — textual inclusion：`#include` = 把文件贴进来——编译放大与传递依赖爆炸的共同根源。
- **头文件卫士** — include guards vs `#pragma once`：90 年代"预处理器缺模块"的民间补丁史。
- **前缀命名法** — 名字空间之前的黑暗时代：`XtWidget_`（X11 toolkit）式手工纪律——防撞名的纯约定方案。
- **module 关键字提案（1990s 版）** — 带链接段与初始化次序语义的重方案——被轻量 namespace 击败（`11` 章静态初始化纠缠是其失败注脚）。
- **modules（C++20）** — 语义级编译单元：一次编译、显式导出、宏不传染（✅ 载体论文 P1103R3 实测 200）。

## 本章地图

| 问题 | 1994 答案 | 2024 答案 |
| --- | --- | --- |
| 库名字冲突 | namespace（当时刚进草案） | namespace 普及 + inline namespace（C++11 ✅）做版本化 ABI |
| 常量宏 | 劝退到 const/enum | `constexpr`（C++11 ✅）终结"编译期常量必须是宏"的最后理由 |
| 特性开关 | `#ifdef` 是唯一可移植手段 | `if constexpr`（C++17 ✅）接管代码级分支；`#ifdef` 退守平台层 |
| 包含模型 | 文本包含 + PCH 止痛 | modules + 头单元过渡（✅ C++20；生态覆盖率 ⚠️ 复核） |

## 名字空间线：三种防撞名方案的比武

- 备选 A：`module` 重关键字——一次解决名字 + 构造次序 + 可见性。
  被否：范围蔓延导致语义欠账（构造次序问题本身无解，`11` 章主场），委员会"先解决名字"；
- 备选 B：只靠类套静态成员 + 文件级 `static`——跨 TU 的自由函数集合无处安放，
  且"把类当名字空间用"污染了类的语义定位（`07` 章刚精炼完的"类概念"不能当垃圾桶）；
- 胜出 C：轻量、纯编译期的 **namespace** + `using` 可见性控制 + ADL 补偿自由函数。
  D&E 第 17 章同时给出警告清单：名字空间**不提供**可见性强制（人人可 using 你的内部层）——
  它是命名纪律的辅助轮，不是访问控制；内部层要靠 `-fvisibility=hidden`/导出宏等工具层继续裸奔多年（✅ 工程通识）。

**ADL 的设计动机**（第 17 章的低调彩蛋）：为了让 `==`、`<<`、`swap` 这类**非成员**运算符/通用函数
在用户类型所属名字空间里被自动找到——它把 `06` 章"自定义类型与内建类型同权"的承诺
落实到了名字查找层；代价是查找规则复杂度上升与"意外捕获"类事故（设计权衡的常客）。

## 预处理器线：一份来自语言发明者的控诉状

第 18 章立场罕见地诚实——**承认自家地基烂**：

- `#include`/`#define` 是"类型系统之外的平行语言"（继承自 C）；
- 文本替换在模板时代后果更重：宏吃进尖括号、与 `::`/模板实参列表互咬；
- 条件编译块不参与语法检查：一个 `#ifdef` 拼写错 → 静默编译出两套不兼容的类定义 → ODR 违规且诊断不可达；
- 包含的传递闭包让编译时间与依赖面积超线性增长（"n 个头文件互含 = n² 编译工作量"的经验律 ⚠️ 措辞）。

**当年的处方**：能语言化的都语言化——const/enum 替常量宏、inline 替宏函数、模板替类型生成宏、
名字空间替前缀；预处理器只留 `#include` 与平台层 `#if`。
处方之外还欠一块拼图：**语义级导入**——第 9 章与第 18 章都望过的"模块化"（到 C++20 才交货）。

🔧 惯用法对读（教学示意，不参与构建）：

```cpp
#define MAX_SIZE 1024            // 无类型、不可调试、污染所有下游 TU
constexpr int kMaxSize = 1024;   // ✅ C++11：同款能力，进类型系统
#define SQR(x) ((x)*(x))         // 经典暗器：SQR(i++) 求值两次
inline int sqr(int x) { return x * x; }

#ifdef USE_FAST_PATH             // 特性开关：另一 TU 忘了同步定义 → 两套 ODR 静默发生
void config();
#endif                           // if constexpr 也救不了"跨 TU 的配置不一致"——modules 至今未全收此账 ⚠️
```

## 著名案例：`std` 必须裸写——名字空间战争的余波

委员会曾争"标准库是否全体入 `std`"（反方：输入负担与 C 兼容）。定案：全体入 `std` + ADL 补偿。
后果链至今清晰：

1. 教学中 `using namespace std;` 泛滥 → 2010s 起风格指南集体禁止（✅ 行业共识）——
   "名字空间不提供强制"的预言兑现；
2. inline namespace（C++11 ✅）把"名字空间"升级为 **ABI 版本容器**：
   abseil 的 `lts_2022_06_23` 式版本标签用它在同一 SO 内共存多 ABI 世代（✅ abseil 公开文档）——
   命名纪律直接变成发布工程；
3. 模块时代：命名模块/分区与 `std` 层次一脉相承，`std` 自身开始提供模块形态（`import std;`，
   C++23 图书馆路径，⚠️ 编译器/标准库覆盖现状需复核）。

## 常见误区

- 误区：「名字空间是访问控制」。它是**组织**机制；封装的牙齿仍在 `private`/匿名空间内部链接/可见性工具链。
- 误区：「modules 只是更快的 `#include`」。它改的是**语义单元**的定义（一次编译、显式导出、宏不传染），
  速度是副产品；真正难点在全局模块碎片与新旧模型共存的 ODR 边界。
- 误区：「constexpr 之后宏就没用了」。字符串化、拼接、X-macro 等"语法级生成"仍在少数库与
  反射缺位期（`12` 章）承担不可替代的角色——控诉状 ≠ 判决书。
