## 8.1 官方摘要：切流策略先行，搬家技术后置

摘要逐拆（✅）：

- "the next phase in migrating to MariaDB (**from Oracle in particular**)" —— 全书最后一次明示迁移源是
  Oracle（呼应 00 第一节主题勘误：这不是 MySQL→MariaDB 手册）；
- "**All new customers** coming into the program would go **straight to the new database**" ——
  增量直接落新库（Ch.1 埋的"增量切流"原则在此执行）；
- "they needed to **get an existing customer out there and running** as a proof of concept" ——
  存量搬家从**一个**标杆客户开始（07 章模板 G4 试点门的书内原型 ✅）；
- "this was the part of the migration that was **very important** for FWP to get right **for the
  existing customers and their corresponding production data**" —— 风险浓度最高的段落给了生产数据。

## 8.2 搬家流水线的重构（⚠️ 阶段划分 + 各段官方件取证）

```
[Oracle] --(1)抽取--> [中间态文件] --(2)转换--> [目标DDL/装载格式] --(3)装载--> [MariaDB]
                                                                    --(4)校验/回滚门-->
```

- **(1) 抽取**：Oracle 侧导出为分隔文本（SQL*Loader 控制文件反向用作生成器是常见做法 ⚠️ 转述）；
  章内 38 页的体量分配未放出（⚠️ 缺口），按叙事重心推断本段+装载段占大头；
- **(3) 装载**：MariaDB 侧文本装载官方件：kb "Loading Data From a Text File"（✅ 200 可达，
  `LOAD DATA INFILE` 族语义与其一致 ⚠️ 句级未抓）；大表装载的通识要点——
  先建表后建索引、关唯一性/外键检查的窗口管理、按分区切批（⚠️ 通用工程，非书内文字）；
- 与 MySQL 谱系的工具衔接点：`mariadb-dump`（MySQL 系 mysqldump 的分叉同名件，✅ kb 200 可达）
  适用于**MySQL→MariaDB** 的简单场景——本书 Oracle 源用不上它，2019 年很多"迁移 MariaDB"文章
  把两条流水线混谈，本册的 Ch.8 恰好划清了边界 ⚠️ 评论；
- **(4) 校验**：三级对账（行数→校验和→抽样深比对）是 07 章"横切层"的执行体；
  字符集对齐单列（✅ kb character-sets 200 可达 ⚠️ 句级；Oracle 库到 utf8mb4 的转码丢字符是经典暗坑 ⚠️）。

## 8.3 认证与连接层：搬家最后一公里的分叉雷区（✅ 取证最密的一段）

应用连不上≠数据没搬对，但客户视角两者同罪。分叉证据链：

- **认证协议史**（✅ mariadb.org 官方博客 Sergei Golubchik 2017-03-22 实抓）：从 MySQL 3.20
  的 32 位哈希挑战-应答，到 mysql_native_password，再到 MariaDB 侧独立的插件化认证
  （ed25519 等）——两侧口令哈希/握手已不同族；
- **连接器**（✅ 官方兼容性页原话）："All MySQL connectors (PHP, Perl, Python, Java, .NET,
  MyODBC, Ruby, MySQL C connector etc) work unchanged with MariaDB"——但同页提示
  legacy PHP5 的库校验 bug（✅），**"unchanged" 是官方口径不是免检证明**，
  02 章 2.2 表第 5 行的实测义务在此执行；
- 混合拓扑的认证矩阵测试（旧应用栈×新驱动×新旧口令哈希三因子的用例表）应作为 G4 门禁附件 ⚠️ 方法论。

## 8.4 切换与回退：把"搬家窗口"写成可演练的脚本（⚠️ 重构）

- 标杆客户切换的推荐时序：冻结写入→末轮增量→对账绿→DNS/连接串切换→观察窗→解冻——
  每步配独立回退点（07 章 G4/G5 回退波次的实例化）；
- 观察窗指标直接复用 #45 体系：查询响应时间回归 + 复制延迟 + 错误率
  （对位 [../Efficient_MySQL_Performance/01-查询响应时间.md](../Efficient_MySQL_Performance/01-查询响应时间.md)、
  [../Efficient_MySQL_Performance/07-复制延迟.md](../Efficient_MySQL_Performance/07-复制延迟.md)）；
- **回迁假设的时效性**：切换后若产生新数据，回到 Oracle 需要反向管道——
  07 章 7.4"退路变窄"论断在搬家窗内的具体形态（⚠️）；
- 增量先行红利的收口：新客早已在新库（8.1 ✅），批量存量波次完成之日即双轨成本清零之时
  （Ch.4 CBA 经常性项的兑现点，全书商业叙事在此闭环 ⚠️ 结构推断）。

## 8.5 类型级陷阱清单（本章与 Ch.3 的呼应对，⚠️/✅）

| 陷阱 | 机理 | 探针 |
| --- | --- | --- |
| JSON 列内容退化 | MariaDB JSON=LONGTEXT 别名（✅ 官方原话），旧脏数据可入列 | 03 章 🔧 A：装载期强制 `json_valid()` 过滤并计数 |
| 空串/NULL 语义 | 双库各与 Oracle 不同（Oracle 曾空串=NULL ⚠️） | 逐列抽样比对 `''`/NULL 计数 |
| 日期精度 | Oracle DATE 带时分秒 vs MySQL 系 DATE 不带；DATETIME(6) 精度对齐 | min/max/精度位比对 |
| 字符集转码 | Oracle 非 Unicode 集→utf8mb4 的不可逆映射 | 装载期告警行计数（8.2-4） |
| 数字标度 | NUMBER 无标度列 vs DECIMAL 定标 | 溢出/截断双零计数 |
| 序列当前值 | 数据搬完 `SETVAL` 忘了设——首写即主键冲突 | 切换检查表固定一行（✅ 03 章 §3.4 函数件） |

这张表的用法本身就是 Ch.8 的精神：**每条陷阱要能在流水线里变成一个计数器**，
而不是停在一页"注意事项"上 ⚠️。

## 8.6 本章检查清单（重构提炼 ⚠️）

1. 标杆客户选择标准是否明确（体量中位、业务可观察、客户配合度高）；
2. 抽取-转换-装载-对账四段是否各自有断点续跑能力；
3. 认证矩阵用例是否覆盖全部应用栈组合（8.3 三因子）；
4. 8.5 陷阱表是否逐行有计数器落点；
5. 切换脚本是否做过**带真实数据量的**全量演练（非演练不可进 G5 波次）；
6. 观察窗指标阈值与回退触发人是否在窗口开始前签字（06 章值班形态的落地检验）。

## 8.7 本章在全书权重下的读法（⚠️ 编辑观察）

38 页里摘要可确认的叙事锚只有三个：新客先行、一个标杆存量客户、生产数据不可出错。
据此推测章内大量篇幅给了**过程细节**（脚本、表结构样例、逐客户清单一类），
这类内容在 2019 年有教学价值、在 2026 年已基本工具化（见演进节）——
本目录因此把重构重心放在**不过期的部分**：8.3 认证取证链与 8.5 类型陷阱表。
若你只有一小时读本章的执行版：25 分钟读 8.3/8.5，35 分钟按 8.6 清单反向检查自己项目的搬家方案。

## 核心概念速览（中英对照）

- **增量先行** — Greenfield-First：新客户直落新库、存量后搬（✅ 摘要原句）
- **标杆客户** — Lighthouse Customer：首个存量搬家对象兼 PoC（✅ 摘要原句）
- **文本装载** — Bulk Text Load：`LOAD DATA INFILE` 族的分隔文本高速装载（✅ kb 可达 ⚠️ 句级）
- **三级对账** — Tiered Reconciliation：行数/校验和/抽样深比对（07 章横切层的执行体 ⚠️）
- **挑战-应答认证** — Challenge-Response Auth：MySQL 3.20 起口令不上线（✅ Sergei 博客实抓）
- **认证插件分叉** — Auth Plugin Divergence：MariaDB 侧 ed25519 等独立演进（✅ 博客语境 ⚠️ 细节）
- **连接器免检悖论** — Connector "Unchanged" Caveat：官方 unchanged 声明≠你的栈免测（✅ 原话+同页 bug 提示）
- **切换窗口** — Cutover Window：冻结→末轮增量→对账→切流→观察的脚本化时序 ⚠️
- **反向管道** — Reverse Pipeline：回退所需的新库→旧库数据回流（⚠️ 07 章 7.4 具象）
- **计数器化** — Counter-ization：每条类型陷阱落为流水线内一个可监控计数（8.5 方法论）
