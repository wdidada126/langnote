## 本书没覆盖的缺口

- **没有「业务系统架构」章节**：任务描述误以为有交易/会员/营销/商品/库存，实际上本书完全不讲
  具体业务域的架构设计，只讲支撑这些业务的技术底座。
- **没有「架构演化 / 设计误区 / 核心要素（性能·可用·伸缩·扩展·安全）」这一体系**：那是李智慧
  《大型网站技术架构》的主线，不是本书。本书以技术域而非能力域组织。
- **没有云原生视角**：本书成书时容器/K8s/Service Mesh 尚未普及，全书的「部署/扩缩容/服务治理」
  都是传统虚拟机 + 手工方案，缺「声明式编排」「不可变基础设施」视角。
- **没有一致性/共识算法的系统讲解**：本书把分布式问题当作「用 ZooKeeper 协调」的工程经验，
  没有 Paxos/Raft/CAP/BASE 的形式化；想补这块请看仓库里的
  [../深入理解分布式共识算法/00-总览与阅读地图.md](../深入理解分布式共识算法/00-总览与阅读地图.md)。
- **消息系统只讲 ActiveMQ/JMS**：缺 Kafka、缺「日志即事实源」的流处理范式。
- **搜索引擎只讲 Lucene/Solr**：缺 Elasticsearch 生态与倒排/向量混合检索。
- **数据分析只讲 Hadoop/MapReduce/Hive/Storm/Chukwa**：缺 Spark、Flink、Iceberg/Delta 等
  现代批流一体与湖仓表格式。
- **可观测性缺位**：本书第 4 章的「监控」是传统指标 + 心跳，缺 traces/metrics/logs 三位一体的
  OpenTelemetry 范式，也缺全链路压测、混沌工程。

## 跨语言对照

> 本书示例语言为 **Java**；下表对照同一概念在「本书 Java 生态」与「2026 云原生主流（Go 为主）生态」
> 的实现差异，帮助非 Java 背景读者迁移理解。

| 概念 | 本书（Java 生态，2014） | 2026 云原生主流（Go/多语言） | 差异要点 |
| --- | --- | --- | --- |
| RPC 框架 | 自研基于 TCP/HTTP 的 RPC、Hessian/JSON 序列化 | `grpc/grpc`（Protobuf）+ `google/protobuf` | 协议标准化、IDL 先行、跨语言友好 |
| 服务注册发现 | ZooKeeper + 自写路由 | `alibaba/nacos` / K8s Service + CoreDNS | 从「中间件」下沉为「平台能力」 |
| 服务治理 | 网关 + 配置规则手工下发 | `istio/istio` + `envoyproxy/envoy`（边车） | 治理逻辑与业务代码解耦 |
| 缓存 | memcache / Redis（Java 客户端） | Redis（任意语言客户端，go-redis 等） | 客户端生态跨语言成熟 |
| 消息 | ActiveMQ（JMS） | `apache/kafka`（多语言 producer/consumer） | 流处理范式，不只解耦 |

| 追踪 | 无 | `open-telemetry/opentelemetry-collector`（多语言） | 跨服务链路统一 |
