## 核心精讲（转述 + ⚠️）

### 执行模型：任务、调度器与饥饿
书把 SQL Server 执行模型画成三层（转述 ⚠️）：会话（连接）挂请求（request），请求变任务（task）排到调度器（每 CPU 芯一个），任务占工作线程（worker）跑。并行查询吃多个 worker（Coordinator+Workers）；max worker threads 默认自适应；**THREADPOOL 等待=没有空闲 worker**，几乎都是上游阻塞链让任务不肯离场。书给的急救链：DAC→查 blocking→kill 头目 ⚠️。

### 等待统计的正确用法
三条纪律（书中方法论 ⚠️ 转述）：① 差值采样（两次快照相减）而非累计值；② 排除无害等待（SLEEP_BPOOL_FLUSH、BROKER_*、DIRTY PAGE 睡眠族 ⚠️ 清单以书为准）；③ 等待要落到资源：PAGEIOLATCH 带 database_id/file_id/page_id，PAGELATCH on 2:1:1 就是 tempdb PFS。书逐类给"等待→机制→动作"三段式（本章地图即骨架），核心思想：**等待画像把'慢'切给 IO/CPU/内存/并发四个嫌疑人**。

### XEvent 相对 Profiler 的代际差
转述书中对比 ⚠️：SQL Trace/Profiler 缓冲+外部消费、高负载下丢事件且开销大；XE 事件产生点即过滤（谓词在引擎内），动作附加上下文（session_id/sql_handle），目标决定去向（内存环/文件/计数）。局限同样明说：XE 无 Profiler 的图形回放生态（2014 时点 ⚠️）、ring_buffer 容量有限、文件解析靠 XML。书给的最小可用三模板：昂贵查询、死锁取证（其实 system_health 免费）、latch 争用 pair_matching ⚠️。

### 基线与"不响应"手册
第 27 章收尾两节是运维剧本：基线=定时采集 waits/tasks/资源使用入表（书给脚本骨架 ⚠️），异常判定靠环比；"服务器不响应"走 DAC（仅一条、轻量、不排队），取"头阻塞任务+其语句"后手术式 kill。两者合起来把"排障"从玄学变成流程——本章的方法论价值大于任何单个等待类型的细节 ⚠️。

### 等待三段判读法（书中方法论收口 ⚠️）
拿到等待样本后的判读分三段（转述 ⚠️）：一是**归因**——等待名前缀即科室（PAGEIOLATCH→磁盘 IO，LCK→并发，RESOURCE_SEMAPHORE→授予，CX→并行，WRITELOG→日志盘）；二是**落资源**——用等待附带的 database_id/file_id/page_id 与 resource_description 打到具体对象、具体闩锁页；三是**对语句**——切到持有该类等待的会话的当前 SQL 与计划（dm_exec_requests 联查）。三段缺一，就会把"数字最大"误当"凶手最大"；书给的处方顺序始终是**先修查询与索引，再动服务器参数** ⚠️。

## 本章结论速记

- 先分层归因（HW/OS/配置）再看等待，等待再落到资源。
- 等待三段：归因→落资源→对语句，缺一即误诊。
- DAC 是留给诊断的，不是留给作业的。
- PAGEIOLATCH=等盘，PAGELATCH=内存页抢闩，一字之差两个科室。
- CXPACKET/RESOURCE_SEMAPHORE/THREADPOOL 多是查询与并发的次生症状。
- XE=引擎内低开销事件流；system_health 是免费行车记录仪。
- DAC 与基线是"进得去"和"看得出"的两条保险绳。

## 工程模式与常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "CXPACKET 高就把 MAXDOP 设 1" | 数仓大查询被误伤；书按 OLTP/DW 分场景 ⚠️（后来 Wilson 学派的 MAXDOP 建议属时代更新） |
| "等待 TOP 1 就是病因" | 无害等待常占头名；先洗清单再排序 ⚠️ |
| "开 Pro 版默认跟踪就够" | 默认 trace 信息面窄且非结构化；XE+Query Store 才是正解（26 章之后代 ⚠️） |
| "XE 会话多多益善" | 每会话有成本；书提醒谓词收窄+生产环境按需停 ⚠️ |
| "内存高=泄漏" | BP 按设计吃满目标内存；看自由内存/页生命期而非占用率 ⚠️ |
| "服务器挂了的直觉是重启" | DAC+查头阻塞+定点 kill 可保现场与数据（书中剧本 ⚠️） |
| "dm_os_wait_stats 要先清零再观察" | 累计值是设计而非缺陷：正确姿势是差值采样+落库基线，清零反而丢掉区间对比的参照系（书纪律 ⚠️） |
| "XE 没抓到=没发生" | 谓词（duration>阈值）天然滤掉高频短语句；聚合类问题要用 pair_matching/计数直方图目标，不是抓单案（书模板提醒 ⚠️） |
| "内存压力=缓冲池不够" | 授予排队（RESOURCE_SEMAPHORE）是单查询贪吃不是 BP 小；加内存不治坏计划 ⚠️ |
| "DAC 也能跑重诊断查询" | DAC 单 worker、禁并行；一条重查询能把后门自己堵死（书中警告 ⚠️） |

## 机制链条

```
请求 ──▶ 任务入队 ──▶ 调度器 ──▶ worker 执行 ──┬─ 让位（SCHEDULER_YIELD）
                                               ├─ 等锁（LCK_M_*）→ 链→ 饥饿（THREADPOOL）
                                               ├─ 读盘（PAGEIOLATCH）→ IO 栈
                                               ├─ 闩热点（PAGELATCH 2:1:PFS）
                                               └─ 等授予（RESOURCE_SEMAPHORE）
每一次等待进 dm_os_wait_stats ──▶ 差值采样+清洗 ──▶ 归因 ──▶ XE 现场取证
XE 目标选型：ring_buffer（现场）/ event_file（回放取证）/ pairing（闩热点差值）
```

## 核心概念速览（中英对照）

1. **执行模型** — Execution Model：会话/请求/任务/调度器/worker 五层。
2. **调度器** — Scheduler：每芯一个的 worker 时间片出租方。
3. **等待统计** — Wait Statistics：需求=运行+等待的记账本。
4. **PAGEIOLATCH / PAGELATCH** — 读盘等待 / 内存页闩争用。
5. **RESOURCE_SEMAPHORE** — 内存授予排队等待。
6. **CXPACKET / CXCONSUMER** — 并行协调 / 流控（2016+ 拆分 ⚠️ 后时代）。
7. **THREADPOOL** — worker 饥饿信号。
8. **ASYNC_NETWORK_IO** — 等客户端消费。
9. **DAC** — 专用管理员连接：不响应时的后门。
10. **基线** — Baseline：定时采样的健康参照系。
11. **Extended Events** — 引擎内轻量事件基础设施。
12. **谓词/动作/目标** — Predicate/Action/Target：XE 三段管道。
13. **pair_matching** — 成对事件差值聚合目标。
14. **system_health** — 默认常驻 XE 会话。
15. **差值采样** — Delta Sampling：两次快照相减还原区间等待，避开累计均值错觉。

## 最新演进与工业实践

- **XE 全面接班**：Profiler 已官宣弃用，SSMS 内建 XE 会话向导；system_health 扩展保留死锁/错误面（[Extended Events](https://learn.microsoft.com/en-us/sql/relational-databases/extended-events/extended-events) ✅）。
