## 核心精讲（转述 + ⚠️）

### 列存快的两本账
第 34 章把收益拆成存储账与执行账（转述 ⚠️）：存储侧——同列同类型相邻，字典+RLE+位压缩叠出 3–5 倍甚至更高的压缩比（书载范围 ⚠️），段级 min/max 元数据让谓词整段裁剪；执行侧——批模式把火山模型每行的虚函数开销摊薄到每千行一批，SIMD 与列指针顺序访问同时赢缓存。两账相加才是"数量级"，单讲其一会低估。

### NCCI 与 CCI：同一引擎的两代身体
NCCI（2012）=行存基表+只读列存镜像：写走行存、读走列存，同步由引擎完成；这决定了它"表仍要建聚集索引、维护成本双倍"。CCI（2014）=删掉行存本体：列存即表，可更新可插入，于是出现 delta store（缓冲未成组行，行存压缩形态）与 delete bitmap（删改=标记旧行+插新行 ⚠️）。书中演示：CCI 的 UPDATE=DELETE+INSERT 的位图/行组账——这正是"逐行 OLTP 上 CCI 会退化"的机制根源 ⚠️。

### 段、字典与统计的三层元数据
行组≈100 万行（书载量级 ⚠️）、列段×每列；段内有列局部字典，跨段有全局字典（2014 行为细节 ⚠️ 以书为准）；列存统计（DMV spine 里 sample 比例特殊、粒度按段）影响优化器对"返回行组数"的判断。书的排查口诀：查询慢先看 system colstore 视图里 segment 的 state（质量、压缩状态、删除数），90% 的退化能在那里找到 ⚠️。

### 维护剧本：让写入模式与行组对齐
小批量高频写→半空行组+delta 堆积→查询吃"未压缩段扫描+位图过滤"双重惩罚。书给的剧本（转述 ⚠️）：① 装载尽量批量（≥百万行成组）；② 后台定时 REORGANIZE 压缩 delta/清位图（2014 起 ⚠️），REBUILD 处理碎片化行组（分区表可单分区重建，接 10）；③ 冷分区上 ARCHIVE 压缩。这些建议的后半段已被产品内置（自动趋势：见下节）。

### 列存的两笔隐性账（书中工程视角 ⚠️）
看得见的收益背后书另点两笔账（转述 ⚠️）：一是**全局序丢失**——B+ 树顺路提供 ORDER BY/GROUP BY 的有序性，列存按段切分后段内有序≠全局有序，排序与流聚合需求统统要用真 Sort/Hash 还；二是**行重构成本**——跨列谓词与更新要在批内把多列 zip 回行形态，删除位图+delta 追加使"改一行"成为两次附加动作。34 章设计四诀（减行宽、多喂列、养统计、整型化）本质就是把这两笔账前移到设计侧结清 ⚠️。

### NCCI 时代的手工 HTAP 形态（34 章史观 ⚠️）
2012–2014 的"行存基表+NCCI 只读镜像"就是 CCI 出现前的手工 HTAP：写走行存 B+ 树、分析走列存段扫，优化器按查询形态分流（书以基准演示 ⚠️）。双写代价（两份额外存储+两套维护）最终被 CCI"单表双形态（列段+delta）"收编，但**热行存×冷列存**的分层心智存活到今天——分区表上"热分区行存/冷分区 CCI+ARCHIVE"的 runbook，正是这套 2012 思路的正规化 ⚠️。

## 本章结论速记

- 列存=存储账（压缩+裁剪）×执行账（批向量化），缺一账就不是那个数量级。
- 列存有两笔隐性账：全局序丢失与行重构；设计四诀就是还账清单。
- NCCI 手工 HTAP 被 CCI 收编，但冷热分层心智活到今天。
- NCCI 只读镜像、CCI 可写本体；CCI 的写=缓冲+标记删除。
- 行组要满、delta 要压、位图要清——列存运维三件小事。
- 事实表用整数代理键、列多喂给查询：设计侧决定压缩比。
- 列存不是 OLTP 解药，它是分析加速与"HTAP 第一块砖"（书 2014 语感 ⚠️）。

## 工程模式与常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "CCI 让任何查询都快" | 点查/高选择性单行读反被段扫描+元数据查找惩罚；书明确按负载分表 ⚠️ |
| "逐行 UPDATE 无所谓，反正能写" | 每次=位图+新行，堆积后退化；批量改写才划算 ⚠️ |
| "列存不用维护索引" | 行组质量/delta/位图就是新的"索引维护"面 ⚠️ |
| "字典压缩自动搞定字符串" | 高基数字符串字典爆炸；代理键/字典化建模仍是正解（34 章四诀之一 ⚠️） |
| "SELECT * 在列存也一样" | 列存按列取才省钱；宽投影直接抹掉列裁剪红利 ⚠️ |
| "NCCI 和 CCI 同义词" | 形态/读写性/维护模型全不同；书以两章分述 ⚠️ |
| "段裁剪对任何谓词都生效" | min/max 只跳"区间不可能"的段；高基数等值、列上套函数、字符串比较边界都能让裁剪退化近全扫（书诊断口径 ⚠️） |
| "列存统计与行存统计一回事" | 列存统计按 column_group 独立存储采样，缺了会让 JOIN 估歪；书中给 UPDATE STATISTICS 与目录联查骨架 ⚠️ |
| "CCI 之后不用留任何行存索引" | 2014 的 CCI 与非聚集行存索引共存受限（书列升级限制 ⚠️）；点查混合负载要重算账，后版放宽以官方文档为准 |

## 机制链条

```
批量 INSERT ──▶ 直接建列段（行组成型）──┐
小事务 INSERT ──▶ delta store（行压缩）─┴─▶ tuple-generator/后台压缩 ⚠️ 书载口径
UPDATE/DELETE ──▶ delete bitmap 标记 + 新行入 delta
查询 ──▶ 段 min/max+字典过滤 ──跳过/仅读所需列──▶ 批模式算子（~1000 行/批）
维护 ──▶ REORGANIZE（压 delta/清位图）/ REBUILD（合并半空行组、分区级可选）
```

## 核心概念速览（中英对照）

1. **列存储索引** — Columnstore Index：按列切段压缩存储的索引形态。
2. **行组** — Row Group：≈百万行的列段容器（书载量级 ⚠️）。
3. **列段** — Column Segment：一列在一行组内的压缩单元。
4. **字典压缩** — Dictionary/RLE：段内值表+游程/位编码组合。
5. **段裁剪** — Segment Elimination：min/max 元数据整段跳过。
6. **批处理模式** — Batch Mode：每批约千行的向量化执行。
7. **NCCI** — 非聚簇列存（2012）：只读列存镜像。
8. **CCI** — 聚簇列存（2014）：列存即表、可写。
9. **增量存储** — Delta Store：未成组行缓冲（压缩行存形态）。
10. **删除位图** — Delete Bitmap：逻辑删除标记，扫描时过滤。
11. **归档压缩** — COLUMNSTORE_ARCHIVE：冷段二档高压缩。
12. **REORGANIZE/REBUILD** — 列存维护两档：压 delta / 重建行组。
13. **代理键** — Surrogate Key：事实表整型化以喂好字典。
14. **全局/局部字典** — Global/Local Dictionary：跨段共享与段内私有的两层编码表（2014 行为口径 ⚠️ 以书为准）。
15. **列存统计** — Columnstore Statistics：按 column_group 独立存储采样的估算依据（书给 DMV 骨架 ⚠️）。

## 最新演进与工业实践

- **CCI 成为默认分析面**：2016+ 支持实时更新细节完善、2017 列存索引可直接建在分区/压缩组合上；"批量+列存"成为微软 DW 与 HTAP（内存行存×列存热冷分层）双线底座（[列存索引概述](https://learn.microsoft.com/en-us/sql/relational-databases/indexes/columnstore-indexes-overview) ✅）。
- **运维内置化**：后台压缩/行组质量治理由引擎接管，本书"三件小事"多数场景不再手工排程；Delta Store 的 tuple-mover 线程行为持续改进（版本注记 ⚠️ 以官方页为准）（[设计指南](https://learn.microsoft.com/en-us/sql/relational-databases/indexes/columnstore-indexes-design-guidance) ✅）。
- **IQP 补批模式账**：批处理模式内存授予反馈（BMOQG）、批模式扩展到行存（2016 自适应 ⚠️ 兼容级相关）——35 章最后一节正是其起点（[IQP](https://learn.microsoft.com/en-us/sql/relational-databases/performance/intelligent-query-processing) ✅）。
- **2022 自动索引/2025 向量**：列存自动维护进 Automatic Indexing 家族；2025 向量检索把"扫描+过滤"的批模式红利引向 AI 负载——本章引擎路线与 2020s 的向量时代接上了轨（[2022](https://learn.microsoft.com/en-us/sql/sql-server/what-s-new-in-sql-server-2022) ✅、[2025 新特性](https://learn.microsoft.com/en-us/sql/sql-server/what-s-new-in-sql-server-2025) ✅、[向量概述](https://learn.microsoft.com/en-us/sql/sql-server/vectors/vectors-sql-server) ✅）。
- **统计新篇**：列存统计与 RESILIENT 统计（2025）改进采样与升级漂移（[统计信息](https://learn.microsoft.com/en-us/sql/relational-databases/statistics/statistics) ✅）。
- **ALTER INDEX 官方页（二轮核验）**: 列存 REORGANIZE（含 COMPRESS_ALL_ROW_GROUPS 类选项 ⚠️ 版本注记以该页为准）与分区级单独重建的现行语法面见 [ALTER INDEX](https://learn.microsoft.com/en-us/sql/t-sql/statements/alter-index-transact-sql) ✅（curl 200，2026-09）——本章"维护=对齐写入模式"的权威语法对照。
- **批模式出圈续史**：2016+ 行存批模式与批处理模式内存授予反馈已归入 IQP 家族统一管理（复用已验证页 [IQP](https://learn.microsoft.com/en-us/sql/relational-databases/performance/intelligent-query-processing) ✅）——35 章最后一节是其起点，IQP 是其后续卷。
- **HTAP 的官方化**：书中"热行存×冷列存"手工组合已进官方设计指南推荐形态（内存优化表×列存混布等，逐项 ⚠️ 以版本页为准；总纲复用已验证 [设计指南](https://learn.microsoft.com/en-us/sql/relational-databases/indexes/columnstore-indexes-design-guidance) ✅）。
