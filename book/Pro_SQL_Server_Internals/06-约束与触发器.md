## 核心精讲（转述 + ⚠️）

### FK 的两侧成本不对称
书中给了一张"操作 × 索引需求"的账：
- 子表 INSERT/UPDATE FK 列：对父键做一次定位读——父 PK 索引天然覆盖，便宜；
- 父表 DELETE/UPDATE 键：要在子表找引用行——**若子 FK 列无索引，则子表全扫 + 更重的锁**，这是"删一行卡全库"的经典现场 ⚠️；
- 级联（ON DELETE CASCADE）放大上述两侧成本，且触发器与级联的交互复杂 ⚠️。

### 触发器的性能画像
DML 触发器在语句事务内运行，代价=（虚表物化 + 触发器查询 + 额外日志）。书中演示：带触发器的表其 INSERT 的日志量与 CPU 显著上升（定量 ⚠️ 无本机复现）；INSTEAD OF 可把宽表写"编译"到多表，但牺牲了引擎对声明式约束的可见性 ⚠️。

### 触发器 vs 约束 vs 应用层
选型顺序（书的立场，转述 ⚠️）：声明式约束能表达就用约束；约束表达不了（跨表审计、防误改）再 AFTER 触发器；业务规则放应用/存储过程。DDL/Logon 触发器属于治理域，不属于 OLTP 热路径。

### 虚表的物理去处（转述 ⚠️）
inserted/deleted 不是"免费视图"：语句影响行数多时它们是真实的工作表（tempdb 语境 ⚠️，与 08 章临时对象共用分配热点），触发器内再 join/聚合它们等于第二次访问。书的推论：触发器越"读"虚表越深，写路径越像"语句+小型 ETL"——热表触发器只应做轻校验与审计追加 ⚠️。

### 约束与并发的隐藏接口（转述 ⚠️）
FK 的"父侧操作查子表"不仅带来扫描，还带来锁的连锁：父行删除要在子表范围加锁防新引用插入——子 FK 无索引时锁面从"命中行"扩到"全表/全范围"，这就是 12 章某些"莫名死锁"的伏笔（书中两个案例分别落在 FK 传播与级联顺序上 ⚠️）。

## 本章结论速记

- 四种约束里 FK 是唯一"不建索引就有第二重成本"的。
- PK/唯一都是"索引合同"，聚簇与否另议（接 02/05 键选择）。
- 触发器是隐藏的事务参与者：回滚它等于回滚语句。
- CONTEXT_INFO 审计有时代码路径（ORM 批处理 ⚠️）会丢——现代对位见"最新演进"。
- 约束同时是完整性文档与优化器线索（CHECK/分区视图共振，接 07/10）。

## 工程模式与常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "建了 FK 自动快" | 子表 FK 列无索引时父侧删除可能全扫 + 锁升级 ⚠️ |
| "触发器=审计万能" | 热路径表上触发器是写放大源；审计可走变更捕获路线 ⚠️ |
| "INSTEAD OF 触发器只存在于视图" | 表上也可建，用于多态写入但要自担完整性 ⚠️ |
| "CHECK 约束有查询优化器魔法" | 书中记录的简化能力有限且有版本缺陷（⚠️ 转述），不要依赖其做分区裁剪 ⚠️ |
| "Logon 触发器写错没事" | 可能连 DAC 之外的会话全灭；需预留救援（DAC/单用户）⚠️ |
| "INSTEAD OF 触发器免检插入" | 它替引擎执行完整性——你手写缺失的校验一个都不会自动补 ⚠️ |
| "触发器里的 ROLLBACK 只回滚触发器" | 语句/事务同一性：默认整条上游语句一起倒（书给 SAVE TRAN 精细控制路线 ⚠️） |

## 机制链条

```
DML 语句 ──▶ 约束校验（PK/唯一=索引命中；CHECK=行级谓词）
        └──▶ FK：子→父 定位读（父键索引）；父→子 引用搜索（子 FK 列无索引 ⇒ 全扫+宽锁）
        └──▶ AFTER 触发器：虚表(inserted/deleted) 物化 → 触发器查询 → 同事务日志放大
        └──▶ INSTEAD OF：原语句不执行，全凭触发器代码重建语义
嵌套链：表A触发器→写表B→B触发器…深度上限 32；同表递归需双开关 ⚠️
```

## 延伸转述：书中判断力小题（转述 + ⚠️，非原书逐字）

1. **问**：为什么 FK 约束不自动给子表列建索引？
   **答**：引擎只自动实现 PK/唯一的索引；FK 子列索引留给设计者——这是"最贵的一步默认省略" ⚠️。
2. **问**：PK 能不能建成非聚簇？
   **答**：能（唯一索引承载，聚簇给别的键）；书中以"代理聚簇键+自然 PK 非聚簇"演示过该形态 ⚠️。
3. **问**：唯一约束列允许几个 NULL？
   **答**：SQL Server 传统唯一索引语义=仅容一个 NULL（书载 ⚠️；后时代 filtered unique 是通用解法）。
4. **问**：级联删除和触发器谁先执行？
   **答**：级联动作以内部 DML 形态参与，与 AFTER 触发器交织的顺序坑书中专门点名（细节 ⚠️ 以官方顺序文档为准）。
5. **问**：AFTER 触发器里为什么强调集合处理？
   **答**：虚表是语句级集合；游标式逐行=把一次 DML 放大成 N 次往返成本（书的反例 ⚠️）。
6. **问**：COLUMNS_UPDATED() 返回什么？
   **答**：列位图（每列一 bit，按列序分字节），要用位运算/UPDATE() 组合判变更——比逐列 IF 廉价但难读 ⚠️。
7. **问**：DDL 触发器能防 DROP TABLE 吗？
   **答**：能拦截并回滚（书给白名单审计+防误删双剧本 ⚠️）；但防不住先 ALTER 掉触发器的路径——治理是组合拳。
8. **问**：CONTEXT_INFO 和 SESSION_CONTEXT 的区别？
   **答**：后者是 2016+ 的类型化、可权限控制的升级形态（后时代对位 ⚠️，本章当时只有 128 字节土办法）。
9. **问**：触发器会阻止批量最小日志吗？
   **答**：带触发器的装载日志形态改变、成本上升——书中"装载前禁用触发器事后校验"路线（危险但时代常见 ⚠️）。
10. **问**：为什么"first/last"之外别指望顺序？
    **答**：同表同动作的其余触发器无序且可随版本变；依赖顺序=隐性耦合 ⚠️。
11. **问**：约束失效（NOCHECK）后新数据怎样？
    **答**：可写入违例数据；再 CHECK 需 WITH VALUES 类重验——书中列为"审计断档"典型 ⚠️。

## 核心概念速览（中英对照）

1. **主键约束** — Primary Key：唯一+非空的实体标识合同。
2. **唯一约束** — Unique Constraint：含单 NULL 语义的唯一索引合同。
3. **外键约束** — Foreign Key：引用完整性；两侧成本不对称。
4. **检查约束** — Check Constraint：行级谓词守门。
5. **级联动作** — Cascade：删除/更新沿 FK 传播。
6. **DML 触发器** — DML Trigger：AFTER/INSTEAD OF 语句钩子。
7. **虚表** — inserted / deleted：触发器内的新旧行集合。
8. **DDL 触发器** — DDL Trigger：模式事件审计与拦截。
9. **登录触发器** — Logon Trigger：会话建立时的闸门。
10. **嵌套触发器** — Nested Triggers：跨表级联触发（深度 32 ⚠️）。
11. **递归触发器** — Recursive Triggers：同表自触发，双开关控制。
12. **首末触发器** — First/Last Triggers：执行顺序的显式钉位。
13. **上下文信息** — CONTEXT_INFO：128 字节会话随行审计桥。
14. **NOCHECK 失效** — 约束暂停：新违例可入、重验需自付代价。
15. **触发器顺序** — sp_settriggerorder：仅能钉 first/last，中间无序。

## 最新演进与工业实践

- **变更捕获谱系替代部分触发器**：SQL Server CDC/Change Tracking 成熟，2017+ 时态表（Temporal Tables，2 版书已收录）成为"行级审计历史"的声明式主流方案——本书写作时刚发布，2024–2026 已是默认选项 ⚠️（时态表文档口径以微软官方为准）。
- **Ledger 表（SQL Server 2022+）**：append-only + 稀疏 Merkle 树验证的防篡改账本，覆盖"触发器审计"的合规场景（[Ledger 概览](https://learn.microsoft.com/en-us/sql/relational-databases/security/ledger/ledger-overview) ✅）。
- **约束与优化器**：2019+/2022 的 CE 与分区切换仍依赖 CHECK（分区视图时代遗产），但约束推导能力边界 ⚠️ 逐版核实，勿照书搬。
- **FK 索引自动检查**：主流巡检工具/Schema 比对（Flyway/Liquibase 流程）把"孤儿 FK 索引"列为默认审计项——本章经验的工程化（实践共识，量化 ⚠️）。
- **Azure SQL 对位**：Managed Instance 兼容多数约束/触发器能力，Azure SQL DB 对 DDL/Logon 触发器与 CLR 有功能裁剪（逐特性差异 ⚠️ 以官方特性矩阵为准，本目录不杜撰矩阵）。
