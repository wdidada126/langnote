# 第 2 章 · 表与索引：内部结构与访问方法（Tables and Indexes: Internal Structure and Access Methods）

> 原书位置：Part 1 · Chapter 2，页 29–52（✅ Crossref 子 DOI ..._2）。小节标题逐字官方（✅ front-matter 实抓）。
> 正文为精读重构转述；SQL Server 不可本机实测，机制结论一律 ⚠️。

## 本章地图

| 官方小节（✅） | 转述要点 | 一句话结论 |
| --- | --- | --- |
| Heap Tables | 无聚簇结构的行集合；全读/全改都走 IAM 或槽数组；更新超长行→转发指针（forwarding pointer），堆表更新可引发扫描路径改道 | 堆不是"更简单的表"，而是"另一种访问方法" ⚠️ |
| Clustered Indexes | B+ 树：叶层双向链表、行数据本体；中间层每页 (键+页号)；树深=定位成本；范围扫描按序读叶 | 聚簇键的选择=物理排序承诺，改不轻易 ⚠️ |
| Composite Indexes | 复合键按最左前缀有序；跳过中间列的谓词用不上排序；键列序影响查找与范围 | "最左前缀"是从 B+ 树定义直接推出的几何事实 ⚠️ |
| Nonclustered Indexes | 二级索引叶=键+行定位器（堆=RID，有 CI=聚簇键），非唯一时加 4 字节唯一化器（书中给出 -1..368 之类取值细节 ⚠️ 转述）；查找→回表（Key Lookup）；覆盖查询免回表 | 每个二级索引都是一笔"写时税" ⚠️ |

## 核心精讲（转述 + ⚠️）

### 堆的三宗罪（书的教学线索）
1. **无序**：范围/排序查询必须外部 SORT；IAM 扫描顺序不代表页号顺序（接第 1 章）。
2. **转发指针**：行更新变大时整行搬家、原槽留指针，之后所有定位该行都要"一跳"——书中用演示显示堆表上更新可把 Index Scan 变成分区式跳读 ⚠️。
3. **并发放大**：同页行更新互相锁阻塞（页锁粒度下），堆比 B+ 树更容易出现"随机行被物理聚一起"的冲突 ⚠️。
> 作者立场（转述）：堆表只在"批量装载 + 快速清空（TRUNCATE）"的暂存场景才划算 ⚠️。

### B+ 树的成本模型
定位一行 ≈ 树深次 I/O（根/中间层通常常驻缓冲池，真实成本≈叶 1-2 读 ⚠️）；范围扫 = 起点定位 + 叶层链表顺序走。聚簇键"窄、稳、递增"三原则在第 6 章展开，本章只把"插入即物理归位"讲透：非递增键（GUID）让每次 INSERT 落在随机叶 → 分裂 → 碎片（接第 5 章）⚠️。

### 二级索引与回表
书里反复演示同一查询的两种形态：非覆盖（Seek + Key Lookup + 可能的 Sort）与覆盖（纯 Seek）。INCLUDE 列把回表变成本索引扫描（第 4 章专节）；嵌套循环下 Lookup 次数=驱动行数，I/O 放大公式化 ⚠️。

### 唯一化器与重复键
二级索引非唯一时，SQL Server 在键后追加内部 4 字节列保证"每行可定位"（书中给出取值区间等细节 ⚠️ 转述待核验）；工程含义：非唯一索引比看起来更宽，选择性差的键值会产生"键+唯一化器+定位器"长尾 ⚠️。

### 定位器的两种命运用（转述 ⚠️）
二级索引叶里的"行定位器"不是抽象指针：堆表上是 **RID（文件:页:槽）**，槽数组一动（行搬家/转发）RID 就要重登记；聚簇表上是**聚簇键值**，于是"改聚簇键=全表二级索引集体改写"。书用这一点解释了为什么聚簇键一旦上线几乎不可改（只能新建+迁移），也是"堆表加索引 vs 重建为聚簇"决策的物理依据 ⚠️。

### 覆盖判断三步法（书中方法论转述 ⚠️）
① 列出查询引用的所有基表列；② 对候选索引核对"键列+INCLUDE 列"是否全覆盖；③ 未覆盖部分越小（列少、窄），回表的嵌套循环代价越可接受——当驱动行数大到临界点，优化器反而选全表扫+哈希。这三步在第 4 章 INCLUDE、第 6 章索引整合中反复使用，是本书"设计→计划"闭环的最小单元 ⚠️。

## 本章结论速记

- 堆/CI 是两种访问方法，不是"有无索引"的差别。
- B+ 树把"有序"承诺给范围与排序，把"随机插入税"转嫁给分裂与碎片。
- 二级索引的每次增删改，都是对定位器一致性的维护费。
- 覆盖索引消灭回表；INCLUDE 决定"键窄、叶宽"的折中（第 4 章）。
- GUID 上树要三思：默认 NEWID 是碎片的头号供应商（第 5/6 章）。
- 定位器是 RID 还是聚簇键，决定整座二级索引林的更新与迁移代价。

## 工程模式与常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "堆表插入快所以建堆" | 插入快的是"顺序写"；CI 递增键插入同样顺序；堆省的是分裂，亏的是读与更新 ⚠️ |
| "有索引就不会慢" | 不匹配最左前缀、隐式转换、回表风暴都会让索引名存实亡 ⚠️ |
| "二级索引越多读越快" | 每多一条索引，写路径多一份树维护；书中演示多索引表的 UPDATE 放大 ⚠️ |
| "唯一列建堆表也行" | 唯一约束在堆上仍建唯一索引，绕不开树的成本 ⚠️ |
| "聚簇键随便选" | 聚簇键被所有二级索引叶复制一遍——宽键=全表索引集体变宽 ⚠️ |
| "索引越多越好" | 每棵二级索引都是一条写放大通道+一个统计对象+一次优化器备选；书中给"用 sys.dm_db_index_usage_stats 找闲置索引"的退役法 ⚠️ |
| "覆盖索引没有代价" | 叶变宽挤占每页行数、增宽缓冲池足迹；INCLUDE 也进索引——只是不进"键的有序比较" ⚠️ |
| "二级索引叶里的定位器是地址" | 聚簇表的定位器是**键值**：改聚簇键=全索引逻辑重挂（书以演示说明写放大 ⚠️） |
| "扫描/查找由 DBA 决定" | 由优化器按统计报价决定，索引只是把选项摆上桌（接 03/14 ⚠️） |

## 延伸转述：书中判断力小题（转述 + ⚠️，非原书逐字）

1. **问**：为什么"每表必建聚簇索引"在书里不是教条？
   **答**：暂存/批量装载/TRUNCATE 生命周期表走堆更划算；有热点二级索引+窄回表时堆+索引也行——关键在访问方法匹配 ⚠️。
2. **问**：非覆盖 Seek 一定比 Scan 好吗？
   **答**：Lookup 次数×每跳成本随驱动行数线性涨；到阈值优化器改选 Scan+排序/哈希，"索引存在"不等于"索引被用" ⚠️。
3. **问**：聚集索引键重复会怎样？
   **答**：非唯一聚簇同样追加内部唯一化器（书载 4 字节 ⚠️），键宽与比较层级都变贵；"自然键当聚簇"要先算重复率账 ⚠️。
4. **问**：复合索引 (a,b) 能服务 `WHERE b=@x` 吗？
   **答**：不能 Seek（跳过前导列破坏有序前提），至多扫描/索引快照+残留谓词；要么建 (b,a) 要么 INCLUDE 思路重排 ⚠️。
5. **问**：为什么 GUID 主键被书反复点名？
   **答**：NEWID 随机→插入随机叶→分裂+缓存局部性差；NEWSEQUENTIALID/有序生成或 bigint 代理键是三条出路（第 6 章展开 ⚠️）。
6. **问**：索引视图/计算列上索引和本章模型什么关系？
   **答**：仍是同一套 B+ 树+定位器规则的特例——索引视图要求聚簇唯一索引打头（第 9 章 ⚠️）。
7. **问**：堆表转发指针何时消失？
   **答**：行缩回原页或全表重建时归位（书中机制 ⚠️）；UPDATE 后行宽剧烈波动是转发指针的温床。
8. **问**：如何判断"该给查询加 INCLUDE 还是扩键"？
   **答**：谓词列/排序列进键，纯输出列进 INCLUDE——键宽伤害所有 Seek，叶宽只伤害存储 ⚠️（第 4 章量化）。
9. **问**：堆转聚簇（把 heap 建成有 CI 的表）在索引侧动的是什么账？
   **答**：所有二级索引叶里的 RID 定位器要整体改写成聚簇键——等于一次性重建整座二级索引林（书中机制转述 ⚠️）；"先堆后聚簇"并不免费，只是把搬家费从日常更新挪到了一次性重建。

## 核心概念速览（中英对照）

1. **堆表** — Heap：无聚簇索引的表，行位置由分配器随手安置。
2. **转发指针** — Forwarding Pointer：堆行搬家后原槽的跳板。
3. **聚簇索引** — Clustered Index：叶节点即数据行的 B+ 树，一表一棵。
4. **叶层链表** — Leaf-level Linked List：范围扫描的顺序通道。
5. **树深** — Index Depth：根到叶的层数，定位 I/O 的上界。
6. **最左前缀** — Leftmost Prefix：复合键可用的前提条件。
7. **行定位器** — Row Locator：二级索引指向行的指针（RID 或聚簇键）。
8. **唯一化器** — Uniqueifier：非唯一索引内部补齐的 4 字节判别列。
9. **键查找** — Key Lookup：非覆盖查询的回表动作。
10. **覆盖索引** — Covering Index：查询所需列全在索引内、免回表。
11. **索引扫描/查找** — Index Scan / Seek：全序读取 vs 定位读取。
12. **查找谓词** — Seek Predicate / 残留谓词 — Residual Predicate：谓词进不进键的分界 ⚠️（术语为计划算子通用叫法）。
13. **槽数组** — Slot Array：页尾的行偏移目录，RID 第三段坐标的来源（接第 1 章物理层 ⚠️）。
