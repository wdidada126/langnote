## 核心精讲（转述 + ⚠️）

### 直方图的几何
DBCC SHOW_STATISTICS 的三块输出（标题/密度/直方图）是本章的操作面。直方图等深分档让"区间内行数≈均匀分布"成为可算假设；等值谓词命中某档时用 equal_rows，跨档时用 selectivity 比例——书中演示过"统计即剧本"：同样的数据，不同采样得到不同档边界，计划随之翻转 ⚠️ 转述。

### 采样率的两本账（转述 ⚠️）
统计构建读的行越少越便宜、但档边界与异常值越失真。书给 DBA 的口径：小表 FULLSCAN 无痛；大表先默认采样，凡"估算离谱"的列（倾斜、冷启动新值、递增键）单独加餐——要么 FULLSCAN 该统计、要么建过滤统计把人群拆开。2016+ 的"持久化采样百分比"（自动更新沿用上次采样率而非退回 20%）正是这条经验的产品化 ⚠️（后时代对位见末节）。

### 采样与自动维护的现实
- 自动统计默认按表大小抽样；千万行表上默认采样可能只抽几千行，异常值被平滑 ⚠️。
- 2012+ 的自动更新触发阈值改为阶梯式（小表保留旧公式、大表按移动行数递减，精确公式 ⚠️ 待核验，以微软官方统计文档为准：[Statistics](https://learn.microsoft.com/en-us/sql/relational-databases/statistics/statistics)）。
- 重查询前手动 `UPDATE STATISTICS WITH FULLSCAN`、或为倾斜列建过滤统计（第 4 章）是书给 DBA 的三板斧 ⚠️。

### CE 2014 的三条"性格改造"
旧 CE（70）：充满启发式猜测（OR 用"不完全独立"、猜测未知谓词相关性、外键无推导）。新 CE（120）：原则化——外键约束下推导范围、OR 用反转概率、多谓词坚持独立。书中逐案例对比行数：同一 SQL 在两 CE 下从 Nested Loop 翻转为 Hash Match 等计划剧变 ⚠️。工程结论：升级兼容级前，用 Query Store/基线比对计划（15 章与第 26 章呼应）。

## 本章结论速记

- 统计对象≠索引：没有索引的列也有统计；索引键统计随索引名存在。
- 估算影响三件事：访问方法、Join 算法、内存授予。
- 自动统计"会更新"不等于"更新得勤"：大表默认迟钝。
- 新 CE 更乐观≠更安全：低估行数是内存溢出的头号原因。
- 递增键、倾斜数据、过期统计是估算三大件，各有专项对策（过滤统计/手动 FULLSCAN/查询提示）。

## 工程模式与常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "重建索引统计就新了" | 索引重建只重算该索引键统计；其他列统计不动，且重建本身按采样 ⚠️ |
| "自动更新会救场" | 触发阈值高 + 编译用旧统计，形成"旧→慢→改→更旧"死循环 ⚠️ |
| "升级就切兼容级" | CE 变更可致计划大面积回退，应先基线回归再切 ⚠️ |
| "多列统计=多列索引" | 列级统计可含多列组合（CREATE STATISTICS (a,b)），密度向量覆盖前缀 ⚠️ |
| "直方图 201 档足够" | 档数封顶使高基数列的长尾估算粗糙；对策是过滤统计拆人群 ⚠️ |
| "移动行计数=修改行数" | 大量小事务、触发器二次修改都计入移动计数（书对 rowmodctr 语义的提醒 ⚠️） |
| "统计坏了重编存储过程就好" | 不改统计只改编译时机；坏图照样坏报价——先修数据侧 ⚠️ |
| "统计和索引是一回事" | 统计可独立于索引存在（列级自动统计），一份统计可服务多个共享前导列的索引（书中行为 ⚠️） |

## 机制链条

```
数据变更 ──▶ 移动行计数涨 ──过阈值──▶ 自动更新（采样）──▶ 直方图/密度刷新
                                                          │
优化器编译 ──▶ 谓词落档/密度换算 ──▶ 估算行数 ──┬─▶ 访问方法与 JOIN 报价
                                                └─▶ 内存授予（Sort/Hash）
估算失真 ──▶ 计划翻转/授予不足 ──▶ 溢出 tempdb / RESOURCE_SEMAPHORE（接 14/15）
```

## 延伸转述：书中判断力小题（转述 + ⚠️，非原书逐字）

1. **问**：为什么"索引重建后统计仍可能旧"？
   **答**：重建只刷新该索引键统计（且按采样），其余列级统计与修改计数不动 ⚠️。
2. **问**：`WHERE status=1`（只占 0.1% 的倾斜值）为何总被低估？
   **答**：等值命中档外或密度平均化；过滤统计把 status=1 单独立档是对策（第 4 章 ⚠️）。
3. **问**：新插入的"明天的日期"为什么估算为 0 行？
   **答**：直方图右边界停在采样时刻；递增键外推两代 CE 行为不同（本章官方对比小节 ⚠️）——主动 UPDATE 或谓词改写缓解。
4. **问**：低估与高估哪个更危险？
   **答**：低估→授予不足→溢出/迭代重跑；高估→授予排队挤占并发。书中案例显示低估在升级场景更常见也更致命 ⚠️。
5. **问**：CE 反馈（后时代）能替代统计维护吗？
   **答**：它修"重复查询的估算偏差"，不修"单次编译的数据现实"——新鲜统计仍是地基 ⚠️。
6. **问**：多列连接选择性怎么估？
   **答**：默认独立性相乘；有 FK/约束时可推导（2014 CE 卖点之一），否则靠组合统计纠偏 ⚠️。
7. **问**：AUTO_UPDATE_STATISTICS_ASYNC 的代价？
   **答**：编译不等新统计=计划继续按旧图跑一轮（书载权衡 ⚠️）；吞吐与新鲜度的交换。
8. **问**：怎么"看见"统计误导了计划？
   **答**：SHOWPLAN 的 ESTIMATE vs ACTUAL 对比 + DBCC SHOW_STATISTICS 手工对账（书中排查路径 ⚠️）。

## 核心概念速览（中英对照）

1. **统计对象** — Statistics Object：表/索引上若干列的分布元信息。
2. **直方图** — Histogram：≤201 档等深分桶，含 range_hi_key、等值/区间行数。
3. **密度向量** — Density Vector：单列与多列前缀的 1/不同值数。
4. **自动创建/更新** — Auto Create / Auto Update：优化器驱动的统计生命周期。
5. **采样率** — Sample Size：统计构建时读取行的比例，FULLSCAN=100%。
6. **基数估计器** — Cardinality Estimator (CE)：70（旧）与 120（2014 新）两代。
7. **兼容性级别** — Compatibility Level：CE 选择的开关载体。
8. **内存授予** — Memory Grant：按估算行数配额 Sort/Hash 内存。
9. **溢出** — Spill：授予不足时算子落 tempdb 继续。
10. **过滤统计** — Filtered Statistics：只覆盖谓词子集的统计。
11. **移动行计数** — Row Modification Counter：自动更新触发的分子。
12. **独立性假设** — Independence Assumption：多谓词联合选择率相乘。
13. **外连接退化** — Outer Join Simplification：约束/统计参与的重写规则之一（书涉 ⚠️）。
14. **统计新鲜度** — Statistics Freshness：last_updated 与移动计数的联合判断。

## 最新演进与工业实践

- **CE 又走了三代**：140（2017）、150（2019）、160（2022）逐代加入基数估计反馈（CE Feedback, 2017+）、Per-Aggregate 参数嗅探等；SQL Server 2022 起 Query Store 可驱动"自动计划修正"（[IQP](https://learn.microsoft.com/en-us/sql/relational-databases/performance/intelligent-query-processing) ✅；[2022 新特性](https://learn.microsoft.com/en-us/sql/sql-server/what-s-new-in-sql-server-2022) ✅）。
- **持久化统计上对象存储**：外部表/数据仓库场景下统计可持久化到对象存储侧，跨计算节点共享（机制细节 ⚠️ 未逐条核实）。
- **自动调优**：Azure SQL 与 SQL Server 2022 的 Automatic Tuning 强制计划可视为"统计驱动的回归自动回滚"（[Automatic tuning](https://learn.microsoft.com/en-us/sql/relational-databases/automatic-tuning/automatic-tuning) ✅）。
- **2025 对位**：SQL Server 2025 引入 vector 数据类型与 AI 场景，高维向量的选择率估算仍是开放问题 ⚠️（[2025 新特性](https://learn.microsoft.com/en-us/sql/sql-server/what-s-new-in-sql-server-2025) ✅）。
- **运维常态**：大表"定期手动 UPDATE STATISTICS … WITH FULLSCAN/固定采样"的巡检清单在 2024–2026 仍是工业实践（模式性共识；具体阈值因系统而异 ⚠️）。
- **2025 的 RESILIENT 统计**：统计携带升级期兼容信息、减少"兼容级切换=全员盲飞"的断崖——本章 CE 对比小节的问题被制度化缓解（条目名 ⚠️ 以 2025 官方发布页逐字为准：[2025 新特性](https://learn.microsoft.com/en-us/sql/sql-server/what-s-new-in-sql-server-2025) ✅）。
