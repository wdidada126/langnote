## 核心概念速览（中英对照）

- **运算符重载** — operator overloading：给自定义类型赋予 `+ < ()[]` 等语法身份，须守交换性与副作用纪律
- **自定义字面量** — user-defined literals：`operator""_km` 后缀函数，强类型物理量/单位的语法入口
- **四种类转换** — `static_cast` / `reinterpret_cast` / `const_cast` / `dynamic_cast`：意图命名的转换工具箱，C 风格强转是其合体遮羞布
- **转换函数与隐式转换** — conversion functions / implicit conversions：单参构造即隐式转换钩子，`explicit` 是默认防线
- **常量表达式** — constant expression：`constexpr` 变量/函数在编译期可求值；C++20 后 constexpr 函数可虚（语言线已入标准）
- **`volatile`** — volatile qualifier：承诺「每次访问都真读写内存」（MMIO/信号处理），**不是**原子、更不是并发工具
- **语句族** — statement grammar：表达式语句/复合语句(块)/声明语句/选择(if-switch)/迭代(for/while/do)/跳转(break-continue-return-goto)
- **范围 for** — range-based for：以 `begin/end` 协议遍历，`auto&`/`const auto&` 的 `02` 章推断规则在此高频使用
- **三路比较** — spaceship `<=>`：一次 `= default` 生成全比较族（C++20，语言 [P0515R3](https://wg21.link/p0515)＋库 [P0768R1](https://wg21.link/p0768)，实测可达）
- **初始化即声明** — brace-init everywhere：`{}` 统一初始化、窄化检查与「最令人生恼的解析」的解药
- **求值顺序** — order of evaluation：C++17 定向补票（赋值右侧先算、嵌套名字限定符左先于右），其余未定序仍是 UB 高发区
- **隐藏朋友** — hidden friend：把 `operator<<`/对称二元运算定义在类内，仅靠 ADL 可见，friend 纪律的工业默认
- **带初始化器的 `if`/`switch`** — if with initializer：`if (auto x = f(); cond)` 把生命周期压进分支（C++17）
- **窄化转换** — narrowing conversion：`(T)` 与 `=` 初始化放行 `double→int`，花括号初始化直接编译报错——最便宜的防错
- **条件 `explicit`** — `explicit(bool)`：C++20 起可按模板参数决定构造是否隐式（`02` 章转发场景的解药）

## 1. 动机：语法骨架是报错与优化的原材料

第 7–8 章没有「新能力」，却决定两件事：**编译器能否帮你**（声明的作用域、`explicit`、窄化检查）与**优化器能否看懂你**（volatile 语义、求值顺序、运算符副作用）。原书在模板章之后插入这两章，是把「表达式的代数」与「语句的控制流」从背景知识提到台面：7.3 类型转换直接为 7.4 常量表达式让路，7.5 volatile 则是全书唯一的「标准给你的裸机逃生舱」说明，与第 19 章 atomics 构成「别用错工具」的双子星。

## 2. 机制：三条主干

**运算符与转换的「意图显式化」。** 重载规则（成员 vs 非成员、对称二元走非成员+friend）之外，本章的实战核心是四 cast 的分工：`static_cast` 编译期已验证的转换、`const_cast` 唯一能剥 const 之处（用错即 UB 引信）、`reinterpret_cast` 指针↔整数的「我知道我在干什么」区、`dynamic_cast` 多态降级（`03` 章 RTTI 回收）。隐式转换的闸门只有一个词：`explicit`。

**自定义字面量（7.2）。** `long double operator""_km(long double) { return ...; }` 让 `5.0_km` 在语法层携带单位——`chrono` 字面量（第 12 章）即此机制的标准化成品；C++23 的 `std::print` 格式化族（见 `11`）延续了「后缀即类型」的美学。

**常量表达式（7.4）。** `constexpr` 变量编译期可初始化容器尺寸、模板实参；`constexpr` 函数在 C++14 放宽（多语句/循环）、C++17 加 `if constexpr`（[P0292R2](https://wg21.link/p0292)，实测可达；⚠️ 注意常被讹传的 P0296 实为 forward-progress 文档，本会话实测证伪）、C++20 默认捕获式 lambda constexpr、C++23 `if consteval`。求值顺序侧：C++17 已把右侧先算（赋值）、函数实参列表相对次序等规则化，本章只需给出「别依赖未规定项」判据。

**语句即作用域（8.x）。** 复合语句是 RAII 的兑现单元（析构在块尾），选择/迭代语句的「初始化语句」变体（`if (auto x = f(); x > 0)`，C++17 [P0305R1](https://wg21.link/p0305) 实测可达）把声明压进条件内——作用域纪律从习惯变成语法。跳转语句里 `goto` 的合法保留地只有错误清理的 C 式惯用法（教学上应指向 scope guard 与异常，`07`/`08` 章回收）。

## 3. 权衡：语法糖的还债时刻

- **重载运算符的克制**：`operator&&`/逗号重载几乎永远错（短路语义丢失）；转换函数+隐式转换组合会造出「意想不到的可行转换序列」（重载解析爆炸，`06` 章）。
- **`volatile` vs `std::atomic`**：atomic 才是跨线程可见性工具（`13` 章），volatile 只保「不被优化掉的单次访问」；MMIO 之外误用 volatile 是并发代码的经典病灶。
- **`= default` 比较 vs 手写字段序**：三路比较默认逐成员字典序——当业务序≠成员声明序，声明顺序就是语义（字段重排的隐性破坏面，本章教完 `<=>` 后必须讲）。

## 4. 相邻概念对比

| 概念 A | 概念 B | 分界线 |
| --- | --- | --- |
| `static_cast` | C 风格 `(T)x` | 前者意图可检索、不做 const 剥除/多步组合；后者是前四者的打包盲盒 |
| `constexpr` | `const` | const=不可改；constexpr=编译期可求值，两者正交（`constexpr` 形参可再 `const`） |
| `volatile` | `std::atomic` | 优化屏障 vs 内存序+原子性；并发只认后者 |
| `operator<=>` 默认 | 手写 `==`+`<` | 默认=成员声明序全序；自定义序/部分序（浮点、三态）需手写或自定义 cat |
| 范围 for | 索引 for | 前者不暴露下标（防越界，容器/视图友好）；计数器语义、跨步、多序列仍归索引式 |

## 典型误区与修正视角

| 误区 | 症状 | 修正视角 |
| --- | --- | --- |
| 「重载运算符能改优先级/元数」 | 想让 `operator+` 变三元 | 优先级、结合律、元数是锁死的语法契约，只能换语义不能换句法 |
| 「`volatile` 能当多线程开关」 | 用 volatile bool 做停止标志 | 无原子性无内存序；`13` 章 `std::atomic` 才是工具，编译器实测会重组 volatile 之外的访问 |
| 「C 风格转换是省事写法」 | `(T*)p` 一路畅通 | 它可能是 `const_cast`+`reinterpret_cast` 的静默组合拳；四 cast 各管一段，报错可 grep |
| 「`f(i++, i++)` 只是顺序未定」 | 两个副作用同表达式 | 两个修改间是**未序列化（unsequenced）** → UB，不是「哪种顺序都行」 |
| 「constexpr 函数就是编译期算」 | 运行期调用也期待常量 | 双人格：操作数是常量表达式才走编译期，否则正常运行期求值 |
| 「`==` 会跟着 `<=>` 全自定义」 | 写了自定义 `<=>` 却惊讶于 `==` 行为 | `==` 由 `<=>` **或**独立 `operator==` 合成，后者存在则优先（浮点 NaN 场景必写） |
| 「花括号永远更安全」 | `vector<int> v{10}` 与 `(10)` 混用 | 花括号防窄化、防解析陷阱，但对 initializer_list 重载有「抢匹配」新坑 |
| 「`explicit` 只防单参构造」 | 转换函数/多参忘防 | C++20 `explicit(bool)` 可按条件开闸；转换函数同样需要 `explicit operator bool` 惯例 |

## 🔧 实测对照：C++17 手写比较族 vs C++20 默认三路比较（已实测 g++ 15.2）

```cpp
// 原书第 7 章口径（C++17）：每个关系手写
struct Entry17 {
    std::string user; int amount;
    bool operator==(const Entry17& o) const { return user == o.user && amount == o.amount; }
    bool operator<(const Entry17& o) const  { return user < o.user || (user == o.user && amount < o.amount); }
};
// C++20：一行
struct Entry20 { std::string user; int amount; auto operator<=>(const Entry20&) const = default; };
int main() {
    Entry20 a{"bob", 1}, b{"alice", 2};
    auto c = a <=> b;
    std::printf("lt=%d eq=%d cat=%d\n", (int)std::is_lt(c), (int)(a == b), (int)(c == std::strong_ordering::greater));
}
```

- gnu++17 版真实输出 `0 0`；gnu++20 版真实输出 `lt=0 eq=0 cat=1`（"bob" > "alice"，故 is_lt 假、分类为 greater，而 `==` 由 `<=>` 合成）。
- 机制账：`= default` 的 `<=>` 逐成员取**最强**类别（int→strong、string→weak、double→partial），`==` 自动合成——「六运算符 × N 类型」的样板在 `03` 章的接口实现、第 13 章的关联容器键类型里同时蒸发。
- 库配套 `<compare>` 设施即 [P0768R1](https://wg21.link/p0768)（本会话实测，标题逐字为 Library Support for the Spaceship (Comparison) Operator）。

## 最新演进与工业实践

- **C++20/23/26 对位清单**：三路比较（C++20）；`if consteval`（C++23，[P1938](https://wg21.link/p1938) 实测可达）；聚合圆括号 [P0960R3](https://wg21.link/p0960)（`01` 章已实测）；字面量运算符模板与 `std::to_underlying` 类小件陆续入库；「指定初始化器进标准」属 C++26 线 ⚠️ 本会话未核提案号，引用时只写主题名。
- **`std::bit_cast`（C++20）**：`reinterpret_cast` 在「值位模式转换」场景的安全替代（`<bit>` 线 [P0553R4](https://wg21.link/p0553) 实测可达），IEEE754 双关、SIMD 加载全靠它。
- **工业仓库**：[`fmtlib/fmt`](https://github.com/fmtlib/fmt) 的 formatter 重载即自定义运算符/字面量纪律的工业范本；[`google/googletest`](https://github.com/google/googletest) matchers 大量复用 `<=>` 派生比较（`07` 章联动）。
- **求值顺序的考古层**：C++17 把「赋值右侧先算」「新序列号左侧先算」等写成明文，但函数实参间、`<<` 链式调用间仍未定序——「同一个 `cout` 链里别塞副作用」的军规比标准更保守；编译器求值顺序可视化可用 cppinsights 对照。
- **练习/拓展接点**：本章练习在 2026 的验收点应从「会不会重载」升级为「敢不敢删重载」——给一个手写比较+手写 cast 的旧模块，列出可用 `= default`、`std::bit_cast`、`explicit` 三件套删除的代码行。
