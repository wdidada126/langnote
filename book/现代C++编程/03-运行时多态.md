## 核心概念速览（中英对照）

- **运行时多态** — runtime (dynamic) polymorphism：以基类引用/指针调用，按对象**实际类型**在运行期选实现
- **虚函数** — virtual function：经 vtable/Thunk 间接跳转的可覆盖成员函数，`override` 显式声明覆盖意图
- **抽象基类 / 接口** — abstract base class / interface：含纯虚函数的类，只定义「能问什么」不定义「怎么答」
- **虚析构函数** — virtual destructor：经基类指针 `delete` 多态对象的前提，否则未定义行为
- **动态向下转型** — `dynamic_cast`：沿类型信息（RTTI）验证的降级转换，失败返回空指针/抛 `bad_cast`
- **共变返回类型** — covariant return type：覆盖函数可返回派生类的指针/引用
- **虚拟继承** — virtual inheritance：菱形继承去重，代价是对象布局与访问间接层加深
- **vtable 开销** — vtable overhead：每对象一个隐藏指针 + 每调用一次间接跳转，虚调用内联受限
- **静态多态对照** — static polymorphism (CRTP/templates)：同题在编译期解决——第 6 章与本章互为镜像
- **对象切片** — object slicing：派生对象按值进基类槽时「多态身份」被剥掉
- **非虚接口（NVI）** — non-virtual interface：公开非虚函数包私有虚实现，前置/后置钩子有了安放处
- **类型擦除** — type erasure：以单一接口容纳异构实现（`std::function` 即样本），与虚表同族但更轻
- **去虚化** — devirtualization：类型唯一性可证明（`final`/Whole-Program/内联可见）时虚调用改直调——vtable 开销的纠正阀，不是传说
- **protected 非虚析构** — protected non-virtual destructor：禁「经基类指针 delete」的第三条路：析构设 `protected`（非虚），只能经由具体类型销毁——与虚析构二选一，别选「public 非虚」
- **`typeid` 与 `type_info`** — RTTI 查询面：运行期类型身份证；`-fno-rtti` 一键关停后 `dynamic_cast`/`typeid` 同废——嵌入式视角看多态的真实依赖

## 1. 动机：行为要可替换，装配要推迟到运行期

第 4 章末尾银行示例已经出现「同一接口、多种记录器」的需求：日志器可能要换（文件/网络/加密），而调用方不应重编译。虚函数是唯一能把「选哪个实现」的决定权**交给运行时对象**的语言机制。本章的启发性例子（5.2）刻意用一个「看似多态实为切片/漏虚析构」的反例开路，再在 5.3 给出干净的接口定义流程，最后 5.4 把银行日志记录器改造成「接口 + 两三个实现 + 工厂」的组合体。

## 2. 机制：vtable 到底怎么找到你的函数

- 每个含虚函数的类带一张编译期生成的**虚表**（函数指针数组，按声明序）；每个对象带一个隐藏 **vptr** 指向其类的虚表。
- 调用 `p->log()` 被编译为「取 vptr→按固定偏移取指针→间接调用」；构造函数执行期间 vptr 逐阶段改写，所以**构造/析构中虚调用不「多态」**（只到当前层）。
- `dynamic_cast`/`typeid` 依赖 RTTI：类信息（`type_info`）与虚表并行存放；关掉 RTTI（`-fno-rtti`）后二者皆废——嵌入式常用开关，本章是理解其代价的最低成本位置。
- 接口定义三条纪律（5.3 的展开）：**纯虚 + 虚析构（`= default`）+ 实现侧一律 `override`**；所有权语义（返回 `unique_ptr` 还是借用引用）在接口注释里写死，与第 11 章智能指针联动。

## 3. 权衡：动态 vs 静态多态——原书 6.13 的结论先行

| 判据 | 虚函数 | 模板/概念（第 6 章） |
| --- | --- | --- |
| 集合异构（运行期才知道类型） | ✅ 唯一解 | ❌ `variant` 只能封闭集合 |
| 热路径开销敏感 | ❌ 间接跳转+内联受限 | ✅ 单态化后可完全内联 |
| 编译时间与代码膨胀 | ✅ 一处定义 | ❌ 每个实例化复制一份 |
| ABI 稳定（插件边界） | ✅ 虚表即稳定协议 | ❌ 模板必须暴露源码 |
| 可测性（mock 注入） | ✅ 第 10 章的模拟框架靠它 | 需接口萃取或概念级替身 |

**工厂+抽象基类是本章的交付形态**：5.4 的日志记录器即「接口 `Logger`、实现若干、配置选择实例」。这段设计在 2026 年教材口径不变，但现代笔记会补两条：返回 `std::unique_ptr<Logger>` 表达转移所有权；接口若只读，考虑 `std::function`/`function_ref` 作为「轻量单方法接口」替代（避免为一个函数养一套 vtable）。

## 4. 相邻概念对比

- **切片** — object slicing：派生对象按值进基类槽，多态身份当场死亡——本章最重要的事故模型（参数按值、返回按值、容器存对象非指针时皆触发）。
- **`override` vs `final`**：前者防签名漂移，后者封锁再覆盖并给编译器去虚化线索。
- **接口 vs `std::function`**：一个 vtable 承载多方法+状态，一个 vtable 承载一个闭包；方法数 ==1 且状态可进捕获时，后者更省样板（第 9 章回收）。
- **虚函数 vs `std::variant` 访问**：开放集合（可不断加实现）走虚函数；封闭集合（编译期已知全部备选）走 `variant + visit`——第 12 章工具库处对照。

## 典型误区与修正视角

| 误区 | 事实 |
| --- | --- |
| 「析构不写 virtual 只是小漏」 | 经基类指针 delete 非虚析构=**未定义行为**，不是泄漏那么简单 |
| 「override 可选」 | 漏写=签名漂移（参数/const/引用）静默变新重载；所有覆盖必须 `override` |
| 「多态容器存对象」 | 存 `T` 即切片；存 `shared_ptr<T>` 即所有权稀释——正解多为 `vector<unique_ptr<T>>`+移动入 |
| 「虚函数每次必走 vtable」 | 编译器可去虚化（类型唯一/`final`/devirtualization pass）；**接口边界**才是虚的必然成本 |
| 「`dynamic_cast` 是常规工具」 | 频繁降级=设计失配信号；优先回到虚接口或 `variant` 的封闭访问 |
| 「构造/析构里调虚函数能多态」 | 此刻 vptr 停在当前层，**只**多态到当前类——经典静默陷阱 |
| 「`final` 只是禁止继承」 | 两个位置两种语义：类名后禁继承、成员函数后禁覆盖——后者还给去虚化递线索，性能与纪律一石二鸟 |
| 「接口类就得全纯虚」 | 先分清「接口」与「带默认实现的基类」：全纯虚是接口纪律，基类携共用实现+个别纯虚同样合法——混了才会生出「为了 virtual 而 virtual」 |
| 「虚函数成本可忽略」 | 间接跳转挡内联、坏分支预测、链式小调用放大——接口边界该虚，热路径内层该直：devirtualization 能救多少取决于你暴露多少 |

## 练习检查点（对应原书「练习/拓展阅读」栏）

- 检查点 1：把 5.4 银行日志器改造成「纯虚+虚析构+全 `override`」三纪律版，再用 `-Wall` 验证漏写 override 能否被编译器点名。
- 检查点 2：写一个切片复现例（按值入基类槽），打印派生成员变化——用 sizeof/调试器双取证。
- 检查点 3：给同一需求做虚函数版与 `std::variant` 版各 30 行，比较「新增实现」与「新增操作」两边的改动成本（开放/封闭集合对偶题）。
- 检查点 4：给日志器最常用实现标 `final`，在 `-O2` 下对照汇编（或 `-fopt-info`）确认虚调用变直调——把「去虚化」从名词变成动词。
- 检查点 5：用 `-fno-rtti` 重编本章例：`dynamic_cast` 当场编译失败、`typeid` 行为改变——量一遍 RTTI 在设计里的真实依赖面。
- 检查点 6：把「经基类指针 delete 非虚析构」写成最小标本跑 ASan/MSVC 调试器（本平台限制见 `13` 章注脚），记录报错形态而非只记结论。
- 拓展落点：`[[nodiscard]]` 工厂（[P0189R1](https://wg21.link/p0189)）与协程擦除方向见「最新演进」；CRTP 现代替代（deducing this）已实测在上。

## 🔧 实测对照：虚函数接口 vs C++23 显式对象参数（已实测 g++ 15.2）

第 5 章的接口写法（`virtual void log(...) = 0;`）依旧是对的；但「按对象**实际类型**定制行为而**不想进 vtable**」这一半需求，C++23 的 deducing this（[P0847R7](https://wg21.link/p0847)，实测可达）给出了第三条路——显式对象参数既是「非静态成员函数」又是「普通可重载参数」：

```cpp
#include <cstdio>
struct Logger {
    int calls = 0;
    void log(this Logger& self, const char* m) { ++self.calls; std::printf("[log] %s\n", m); }
    int get_calls(this const Logger& self) { return self.calls; }
};
int main() { Logger l; l.log("txn 1"); l.log("txn 2"); std::printf("calls=%d\n", l.get_calls()); }
```

- `-std=gnu++23` 真实输出：`[log] txn 1` / `[log] txn 2` / `calls=2`。
- `-std=gnu++20`：GCC 15.2 以**扩展放行**并逐字警告 `warning: explicit object member function only available with '-std=c++23'`——标准身份是 C++23，别按 C++20 部署。
- `-std=gnu++17`（原书口径）：直接编译错误（`this` 作参数非法）。
- 对第 5 章的修正含义：过去只能在「虚函数（运行时）」与「CRTP（编译期）」二选一的分派，如今可在**同一类**里用 `this D&` 按 const/派生类型重载，CRTP 的「基类里 `static_cast<D*>(this)`」仪式可退役大半。

## 最新演进与工业实践

- **C++23 deducing this**：见上实测；同时是 `this` 捕获式 lambda 之外「按引用安全绑定成员回调」的新选项（与 `bind_front`，`06` 章联动）。
- **去虚化与 PGO**：现代编译器的 devirtualization（GCC `-O2` 起可证明类型唯一时直调）+ `-fprofile-guided-optimization`，使「虚函数=每次都贵」的老结论要带条件引用；但接口边界（插件/测试替身）仍是虚函数主场——判据见 [`../C++20设计模式/13-状态与策略.md`](../C++20设计模式/13-状态与策略.md) 的策略选择讨论。
- **协程擦除（C++20/23）**：日志/IO 接口异步化后，虚函数返回「可等待类型」的工业模式见 Boost.Asio 与 [`facebook/folly`](https://github.com/facebook/folly)（`folly::coro`）；std 侧 `generator` [P2502R2](https://wg21.link/p2502)（实测可达）为「多态迭代器」提供了协程式新答案。
- **契约与多态**：接口方法加 `[[nodiscard]]`/前置条件检查是 Google/Abseil 风格审查项（`[[nodiscard]]` 线 [P0189R1](https://wg21.link/p0189) 实测可达）。
- **稳定 ABI 的词汇**：「跨库边界只走 C ABI 或冻结接口类」是插件系统的工业铁律——本章 vtable 正是「冻结接口类」协议的原始形态（COM 式 `com_ptr` 与 Google 风格指南的「避免多级继承」同族）；链接侧细节在 `14` 章与本库 [`../C++API设计`](../C++API设计/00-总览与阅读地图.md) 一系。
- **练习/拓展接点**：5.x 的银行日志器练习，2026 版验收标准建议：①接口只含纯虚+虚析构；②工厂返回 `unique_ptr`；③给测试章（`07`）留好 mock 位——三步正好接上原书第二部分第一章的「模拟框架依赖接口注入」论点。
