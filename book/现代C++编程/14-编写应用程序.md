## 核心概念速览（中英对照）

- **`assert`** — 断言宏：`NDEBUG` 下整体消失；表达「程序员不变量」而非「用户输入校验」——两者混用是本章头号纠偏点
- **错误码三件套** — `errno`/`std::error_code`/`error_category`：C 的全局整数遗产 → C++11 的类型化目录（`system_error` 体系）
- **`std::system_error`** — 异常化错误码：`throw std::system_error(ec, "what")` 把 OS 错误带进异常路径（`02` 章栈展开回收）
- **数值_limits** — `std::numeric_limits`：类型边界的编译期自述（`max_lowest/epsilon/has_infinity`），从 `<climits>` 宏迁移而来
- **程序选项** — program options：命令行 flag/positionals+配置文件统一建模，`variables_map` 为查询中枢（Boost.ProgramOptions）
- **翻译单元与链接** — TU / linkage：内部链接（`static`/匿名命名空间）vs 外部链接；ODR 与符号可见性（`__declspec(dllexport)`/`__attribute__((visibility))`）
- **静态库 vs 动态库** — static / dynamic linking：链接期复制归档 vs 加载期符号解析（插件/OS ABI 边界只有后者）
- **头文件-only 与编译防火墙** — header-only / PIMPL：模板被迫全公开（`04` 章）与「减少重编译扇出」（Lakos 物理设计线）
- **`inline` 变量** — inline variables（C++17，[P0386R2](https://wg21.link/p0386) 本会话实测，标题逐字）：头文件里定义全局常量不再违规
- **`to_chars/from_chars`** — 无 locale 零分配转换（C++17，[P0067R5](https://wg21.link/p0067) 实测可达）：CLI 参数数值解析的现代默认
- **静态初始化顺序灾难** — static initialization order fiasco：跨 TU 的全局初始化次序标准不保证；解法=函数内局部 static（首次使用才初始化）或显式 init 函数
- **名字修饰** — name mangling：重载支持向符号表的代价；`extern "C"` 与导出宏是跨编译器 ABI 的两座桥
- **ODR** — one definition rule：同名符号跨 TU/跨库出现不一致定义=静默 UB；重复符号与「两个版本库同链」是其两大案发现场
- **可见性方言** — visibility：`__declspec(dllexport/dllimport)`（MSVC）vs `-fvisibility=hidden`+`__attribute__((visibility("default")))`（GCC/Clang）——同一件事两套笔
- **诊断输出分工** — `cerr` vs `clog`：前者不缓冲即时可见（错误），后者走缓冲（进度）；与 `11` 章流缓冲机制直接对表

## 1. 动机：最后一章补的是「程序」而非「特性」

21.1 罗列程序支持设施（`<cassert>/<cerrno>/<limits>/<system_error>`），21.2 用 Boost.ProgramOptions 把 `main(argc,argv)`（`06` 章 9.12 埋的线）升级为真正的 CLI，21.3 收「编译中的特别话题」（链接器、库形态、编译器方言）。三节合读是一个工程闭环：**校验（assert/limits）→ 报告（error_code/异常）→ 装配（options）→ 交付（link）**。

## 2. 机制：四条支撑线

**断言与错误的分界。** `assert(x > 0)` 在 `NDEBUG` 发布版消失——所以它**只能**表达内部不变量（违反=程序有 bug），用户输入校验必须用返回值/错误码/异常（`09` 章 expected 线、`11` 章 filesystem 双签名，全书在此汇拢）。`<system_error>` 的设计点：`error_code` 是「值+目录」（category），目录可自定义（POSIX/Windows/WinRT 三家 errno 空间被统一建模）——`ec == std::errc::no_such_file_or_directory` 的比较由 category 协议保证跨目录正确。

**数值自述。** `std::numeric_limits<T>::max()` 等 `constexpr` 静态成员替换宏时代（`INT_MAX`）；`lowest()` 管补码不对称、`epsilon()` 管浮点比较（`05` 章转换税的续集）。C++20 起多数成员 `constexpr` 化完毕，可进 `static_assert`。

**ProgramOptions 建模。** `options_description`（声明+help 生成）→ `store(parse_result, vm)` → `variables_map["port"].as<int>()`（查询+类型化）。配置文件语法（INI 风格/`--file` 混载）与「命令行覆盖配置文件」的层叠语义是其超出 getopt 的价值；`notify` 钩子做取值校验——把 `07` 章「接缝」思想用在配置装配上。

**链接与库形态。** 静态库=归档的 `.o`，链接期拷进最终产物（符号膨胀、但零运行期依赖）；动态库=加载期解析（`extern "C"` 边界、导出宏、`__declspec/dllexport` vs `-fvisibility` 方言）。原书点到的「编译特别话题」（名字修饰、静态初始化顺序）在 2026 年的工业口径：初始化顺序用 Meyers singleton/显式 init 函数规避，名字修饰用 C ABI 或模块封装。

**交付形态小账本。** 一个可执行程序=语言特性（`01`–`08`）+库（`09`–`13`）+链接方案。三条实务线各有一票否决权：**依赖线**（vcpkg/conan 锁定第三方版本，静态链接把「库版本地狱」变成「体积地狱」）、**ABI 线**（跨 .so/.dll 边界只走 `extern "C"` 或冻结接口类，`08` 章删除器与本章错误码同条军规）、**符号线**（默认隐藏+白名单导出，冲突在链接期终结而不是运行期）。21.3 只有三段，工程生涯里这一节占的官司最多。

## 3. 权衡：ProgramOptions 的当代位置

- **选项解析已非 Boost 独占**：`CLI11`（header-only、现代 C++、子命令体验）、`args`/`lyra` 等轻库涌现；Boost.ProgramOptions 的长板是**配置文件+命令行双源层叠**与 Boost 生态一致性，短板是链接依赖与老派 API。判据：与 Boost 栈（Asio/Graph，`13`/`09`）同仓项目留用；独立 CLI 工具用 CLI11。
- **`errno` 的线程现实**：现代 libc 把 `errno` 做成线程局部宏，但「调 API 后立即存码」的纪律仍不可省——中间任何标准库调用都可能覆写。
- **动态库的 ABI 税**：导出 C++ 类型跨库=编译器/标准库版本耦合——`08` 章 `unique_ptr` 删除器、`14` 章错误码边界，全指向同一条军规：**跨库边界只走 C 兼容 ABI 或冻结的接口类**。

## 4. 相邻概念对比

| 概念 A | 概念 B | 分界线 |
| --- | --- | --- |
| `assert` | 错误码/异常/expected | 内部不变量 vs 可预期失败；「assert 里写业务校验」按 UB 处理 |
| `error_code` | `error_condition` | 前者「哪个目录里的几号」原样记账；后者跨目录语义等价类（generic_category 归一） |
| 静态链接 | 动态链接 | 部署简单/体积累加 vs 可替换/多进程共享/加载器错误面 |
| ProgramOptions `variables_map` | `getopt` 手工循环 | 声明式（先描述后解析）vs 命令式；help/校验/层叠免费得来 |
| `inline constexpr` 全局 | 宏常量/`.cpp` 内 static | 类型安全+作用域+头文件可定义三全 |

## 典型误区与修正视角

| 误区 | 症状 | 修正视角 |
| --- | --- | --- |
| 「`assert` 里校验用户输入」 | Release 版校验集体蒸发 | `NDEBUG` 删除一切；发布路径的安全检查必须是错误码/异常/expected——assert 只写「若为假则程序有 bug」 |
| 「assert 表达式可以带副作用」 | Debug/Release 行为分叉 | `assert(i++ == 3)` 里 `i++` 在 Release 不执行——断言表达式必须无副作用（副作用移出，例如 `i += 1; assert(i == 3);`） |
| 「`stoi` 失败一定有异常」 | 空串/越界抛异常但「12abc」静默返回 12 | `stoi` 系列**部分解析也算成功**，越界才 `out_of_range`；要「整串即数字」的合同用 `from_chars`（本章 🔧 实测 `4x` 案） |
| 「`errno` 存下来以后随时能用」 | 隔两个库调用后值被覆写 | 现代 libc 是线程局部，但**任何库调用都可能覆写**；API 返回后立即转存/转 `error_code` |
| 「全局对象构造顺序无所谓」 | 跨 TU 依赖用到未初始化单例 | 链接顺序决定初始化顺序且不可移植；首次使用才构造（函数局部 static）是唯一稳的姿势 |
| 「动态库导出越多越方便」 | 符号冲突/初始化时序/安全面全开 | 默认可见性关掉+导出宏白名单；跨边界传 C 兼容类型或冻结接口（`03` 章纯虚接口在此复用） |
| 「静态链接=部署万能药」 | 体积膨胀+同一库两份状态 | 静态化把符号与全局状态拷进每个产物；混链（一个 .so 一个 exe 各带一份 libstdc++ 状态）是玄学崩溃产地 |
| 「`numeric_limits<double>::epsilon()` 是「最小正数」」 | 浮点比较写错基准 | epsilon=1.0 与次一个可表示值之差；「最小正」是 `min()`，「比较容差」要按量级缩放 |
| 「`variables_map["x"].as<int>()` 没值也安全」 | `bad_optional_access` 式异常 | 查询前 `count(vm)`/`vm.contains`（新版）；默认值用 `value_or` 语义声明，别拿异常当默认分支 |

## 练习检查点（对应原书「练习/拓展阅读」栏）

- 21.1a：写 assert 正反例各一（内部不变量版通过、用户输入校验版故意 Release 失效复现），用 `-DNDEBUG` 构建两遍对照输出。
- 21.1b：`errno` 样本：`fopen` 失败后立即转存 `errno`，中间插一次无关库调用，打印覆写前后值——给「立即存」写证据。
- 21.1c：`numeric_limits` 自述表：对 `int8_t/int/long double` 各打印 `lowest/max/epsilon(仅浮点)`，并与 `<climits>` 宏对比——本章「从宏到类型」的微观史。
- 21.1d：`system_error` 双世界：同一次「文件不存在」分别用 `std::filesystem::exists`（返回版）与 `ifstream::open`+`errno` 版捕获，再统一转 `std::errc` 比较——错误目录协议一次跑通。
- 21.2a：给自己的示例程序加 ProgramOptions（或 CLI11）三选项：`--port/--config/--verbose`，实现「命令行覆盖配置文件」层叠并打印最终生效值。
- 21.2b：所有数值入口换 `from_chars`+expected（`09` 章实测件）返回错误对象，异常路径只留给「程序 bug」——完成全书错误处理光谱的落地。
- 21.3a：造一个静态初始化顺序事故：两个 TU 的全局对象互用，交换链接顺序观察崩溃；Meyers singleton 修复。
- 21.3b：把同一程序分别静态/动态链一个自制小库：对比产物体积、启动依赖（`ldd`/依赖查看器）、改动库后重编译范围——三种链接形态各交一份体检表。

## 🔧 实测对照：`atoi/stoi` 时代 vs `from_chars`+`inline` 变量装配 CLI（已实测 g++ 15.2）

```cpp
#include <charconv>
#include <cstdio>
#include <string_view>
inline constexpr int kMaxAccounts = 10; // C++17 内联变量：头文件里定义常量（[P0386R2] 实测可达）
int to_num(std::string_view s) {
    int v = 0; auto [p, ec] = std::from_chars(s.data(), s.data() + s.size(), v);
    if (ec != std::errc{} || p != s.data() + s.size()) return -1; // 尾杂字符也判失败
    return v;
}
int main() { std::printf("%d %d %d\n", to_num("123"), to_num("4x"), kMaxAccounts); }
```

- `-std=gnu++17` 真实输出：`123 -1 10`。
- 对照原书 `main(argc, argv)` + 手工解析的 21.2 入门例：`stoi("4x")` 会**静默返回 4**（部分解析仍成功）——`from_chars` 用返回的指针+错误码显式暴露这一点，「解析整参数」的正确姿势自此有了可审计的合同。
- `inline constexpr` 行是为 21.3「编译特别话题」配的显微镜：C++98 时代「头文件里 const 数组/全局」意味着每 TU 一份拷贝与链接器仲裁，`inline` 变量（[P0386R2](https://wg21.link/p0386)，本会话实测标题逐字）把「头文件级单一定义」变成一等公民——与 constexpr 合并后即是工业配置头的默认形态。
- Boost.ProgramOptions 本身本机未装 Boost ⚠️ 其示例以「API 形态描述」呈现，不标实测。

## 最新演进与工业实践

- **C++23/26 补位**：`std::expected` 用于 CLI 参数校验返回（`09` 章实测）；`std::print` 的终端输出（`11` 章 MinGW 链接残缺实测在案，Linux 正常）；C++26 `std::execution`（[P2300](https://wg21.link/p2300)）对「应用装配=组件+执行器」的抽象化——程序入口从 `main` 手写线程转向声明式调度。
- **`<system_error>` 家族延伸**：`std::error_code` 在 C++20 起全面 `constexpr` 化（错误码进编译期字典）；`std::filesystem::path` 抛 `filesystem_error`（`11` 章）是该体系最常用样本；Windows 侧 WinRT/NTSTATUS 目录由实现补充。
- **工业仓库**：[`CLIUtils/CLI11`](https://github.com/CLIUtils/CLI11)（现代选项解析事实标准之一）、[`google/glog`](https://github.com/google/glog)/[`gabime/spdlog`](https://github.com/gabime/spdlog)（程序支持设施中「日志」这一课）、[`microsoft/vcpkg`](https://github.com/microsoft/vcpkg)/[`conan-io/conan`](https://github.com/conan-io/conan)（21.3 库链接话题的当代答案：依赖交付工具接管）。
- **练习/拓展接点**：21.2 的「给自己程序加配置」练习 2026 版三件套：①CLI11/ProgramOptions 定义 `--config` 层叠；②所有数值入口走 `from_chars`+expected 报错；③给配置对象加 `static_assert(inline constexpr 默认值)` 的边界自述——正好把 21 章三节拧成一次提交。
