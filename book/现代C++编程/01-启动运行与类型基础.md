## 核心概念速览（中英对照）

- **翻译单元** — translation unit：预处理后的单个源文件及其头文件闭包，是编译的基本粒度
- **工具链** — toolchain：预处理器→编译器→汇编器→链接器四段流水线（GCC/Clang/MSVC 三家方言）
- **入口点** — `main` entry point：程序唯一规定入口，返回值交给操作系统作退出码
- **调试器断点** — breakpoints / stepping：gdb/lldb 在符号表中用「断点—单步—回溯」观察未优化的可执行体
- **窄化与整型提升** — narrowing / integral promotion：`int→short` 有损、`char→int` 无处不在；花括号初始化在编译期拦截窄化（`05` 章规则全表）
- **固定宽度整型** — fixed-width integer types：`<cstdint>` 的 `int32_t/uint64_t`，跨平台位数承诺
- **原生数组的退化** — decay of raw arrays：数组作函数实参退化为指针，长度信息丢失
- **`nullptr`** — 类型安全的空指针字面量：`std::nullptr_t` 不与整数互相渗透，`0/NULL` 历史暧昧（`06` 章重载事故）的第一支疫苗
- **`const` 正确性** — const correctness：成员函数/形参的 `const` 是接口合同的一部分，非注释
- **头文件包含模型** — `#include` textual inclusion：文本插入式依赖，头文件闭包≠可见源码
- **`std::array`** — fixed-size contiguous container：带大小与迭代器接口的栈上数组，替代原生数组的默认选择
- **枚举类** — scoped enumeration (`enum class`)：不泄漏枚举量、不隐式转整数的强类型枚举
- **聚合初始化次序** — aggregate initialization：花括号严格按**成员声明序**初始化；指定初始化器让次序显式（GNU 方言早放行，标准化线属 C++26 ⚠️）
- **退出码与诊断旁路** — exit status / `stderr`：`main` 返回值是操作系统的收据；`cerr` 不缓冲，是诊断的紧急出口（`11`/`14` 章对表）
- **聚合类型** — aggregate：无用户构造函数的 `struct`/数组族，可用花括号（C++20 起可圆括号）初始化
- **联合体** — union：多成员共享存储、需手工纪律活动成员——现代替代是 `std::variant`
- **类的成员函数与访问控制** — member functions / access control：`public/protected/private` 与 `const` 成员限定构成封装语法

## 1. 动机：为什么「先跑起来，再懂语言」

多数 C++ 教材先讲类型系统再让程序开口说话；本书第 1 章反其道而行——**先把 `main`、编译命令、断点摆上桌**，让读者在第二章讲类型时已有「可调试的程序」作锚点。这个顺序隐含一个工程判断：C++ 的学习曲线主要不是语法曲线，而是**工具链与心智模型的错位曲线**（头文件闭包≠你看到的文件、优化改变可调试性、链接错误信息比语法错误更劝退）。原书第 1 章因此同时是「环境章」和「防坑疫苗章」。

## 2. 机制：工具链四段与类型的三层结构

**编译流水线。** `g++ a.cpp -o a` 一行背后：①预处理器展开 `#include`/宏得到翻译单元；②编译器产出汇编；③汇编器产出目标文件；④链接器合并目标文件与库、解析符号。三家编译器方言差异（`-Wall` vs `/W4`、`__declspec` vs 属性语法）在第 1 章点到，在本书第 21 章「编译中的特别话题」（本目录 `14`）回收。

**调试。** 原书用 gdb/lldb 演示断点、单步、变量检视；关键提醒是「`-O0 -g` 的调试视图与 `-O2` 的真实行为可能不一致」——这是后来 `volatile`（第 7 章）与优化假设讨论的伏笔。

**类型三层。** 第 2 章把类型切成：内置（算术/布尔/指针/`nullptr_t`）→ 复合（数组、函数）→ 用户自定义（`enum`/`struct`/`class`/`union`）。教学落点有三处现代替换，原书全部给出：
1. 原生数组 → `std::array`（带 `size()`、可拷贝、不衰减）；
2. 裸 `enum` → `enum class`（作用域与转换纪律）；
3. `union`+tag 手工判别 → 预告第 12 章的 `std::variant`（2.3 处先给方向）。

**全功能的类。** 2.4 用银行例子把「成员布局、构造/析构、访问控制、`const` 正确性」一次讲完，并埋下第 4 章「三/五/零法则」的引子——这是全书贯穿式造轮子（SimpleString、SimpleUniquePointer）的第一站。

## 3. 权衡：快节奏的代价与补偿

- **广 vs 深**：一章塞完工具链，意味着链接器脚本、ABI、符号修饰这些「为什么链接错误这么难读」只做现象级交代。补偿办法：把「编译中的特别话题」（第 21 章→本目录 `14`）当作本书自己的回填。
- **`std::array` 优先的代价**：栈上定长简单可靠，但动态场景仍要回到 `std::vector`（第 13 章），第 2 章读者需要忍住「现在就想要通用容器」的冲动。
- **C 味道的残留**：本章仍允许 `char*`、`int a[10]` 出现于示例（配合「致 C 语言程序员」前言），但作者的替换清单很明确——见下节辨析。

## 4. 相邻概念对比

| 概念 A | 概念 B | 分界线 |
| --- | --- | --- |
| 原生数组 `T[n]` | `std::array<T,n>` | 后者是真正的类型（拷贝=逐元素、知道 `size()`、不自动衰减） |
| `std::array` | `std::vector` | 定长/栈 vs 变长/堆；本章只碰前者，容量增长语义在第 13 章 |
| `enum` | `enum class` | 隐式转 int 与枚举量泄漏两个坑同时关掉 |
| `union {int i; float f;} + tag` | `std::variant` | 活动成员查询交给类型系统（第 12 章展开） |
| `.h` 头文件 | `.hpp`/PIMPL 等惯例 | 语言无差别，工程语义在头文件闭包与编译防火墙（互链大规模 C++ 笔记） |

## 典型误区与修正视角（2026 回看本书口径）

| 误区 | 事实 |
| --- | --- |
| 「编译是一步到位」 | 四段流水线，多数怪病在链接与预处理（宏卫生），报错文本按段定位 |
| 「换编译器只换命令」 | 方言（`__declspec`/属性）、三家标准库实现进度都不同——同代码≠同行为 |
| 「`std::array` 只是包装数组」 | 换来值语义、`size()`、`.at` 越界检查与算法适配，零运行期开销 |
| 「`enum` 当整型常量用无妨」 | 隐式转换+枚举量泄漏两个洞一起开；`enum class` 一次堵死 |
| 「`union` 是省内存技巧」 | 活动成员靠人肉记账=UB 温床；类型双关也应走 `std::bit_cast` 的正门 |
| 「入门书不必学调试」 | `-O0 -g` 的视图不是真相——这个心智模型是理解 `volatile`/优化假设（`05`）的前提 |
| 「`const` 成员函数=对象不可变」 | 它只约束**经此接口**的修改：`mutable` 成员、别名路径、内部可变状态照改——完整账本在 `02` 章生命周期与 `06` 章 const 重载 |
| 「`int` 就是 32 位」 | 标准只承诺 `short≤int≤long` 的相对次序与二进制补码（C++20 起）；跨边界数据/共享内存/序列化一律用 `<cstdint>` 定宽类型 |

## 练习检查点（对应原书「练习/拓展阅读」栏）

- 检查点 1：用 GCC/Clang/MSVC 各编译同一翻译单元，记录三条警告文案差异——工具链章的验收标准。
- 检查点 2：把旧工程一段原生数组全部换 `std::array`，数一数哪些接口签名被迫改（衰减问题现场取证）。
- 检查点 3：把第 2 章银行类改写成「聚合+自由函数」与「全功能类」两版，比较成员函数可删减的边界。
- 检查点 4：三级退出码实验（成功 0/用法错 2/内部错 3）：`main` 按 `argv` 校验返回，`cerr` 打诊断，shell 里核对 `$?`/`ERRORLEVEL`——第 1 章「入口即 OS 合同」的验收。
- 检查点 5：给同一 `struct` 成员分别用声明序/乱序花括号初始化，观察 GCC 对乱序指定初始化器的放行（GNU 方言）与 `-pedantic-errors -std=c++20` 下的脸色——区分「编译器给了你什么」和「标准给了你什么」。
- 拓展落点：初始化规则全表（cppreference 的 initialization 族）＋上面实测的 [P0960R3](https://wg21.link/p0960)/[P0457R2](https://wg21.link/p0457) 提案原文。

## 🔧 实测对照：C++17 教法定位 vs C++20/23 写法（已实测 g++ 15.2）

```cpp
#include <cstdio>
#include <string_view>
struct Point { int x, y; };
int main() {
    std::string_view name = "bank_logger.cpp";
    Point p(1, 2);                     // P0960：聚合圆括号初始化（C++20）
    Point q = Point{ .x = 1, .y = 2 }; // 指定初始化器：GNU 方言扩展（标准线在 C++26）
    std::printf("starts=%d ends=%d p=(%d,%d) q.y=%d\n",
        (int)name.starts_with("bank"), (int)name.ends_with(".cpp"), p.x, p.y, q.y);
}
```

- `-std=gnu++17`：**编译失败**（exit 1）——`starts_with/ends_with` 无、聚合圆括号初始化无。
- `-std=gnu++20` 真实输出：`starts=1 ends=1 p=(1,2) q.y=2`（exit 0）。
- 注：指定初始化器在 `gnu++20` 由 GCC 以扩展放行，**不属于 C++20 正式特性**（标准化线属 C++26 议题 ⚠️ 本会话未核其提案号），迁移旧 C 风格代码时别把它当跨编译器保证。
- `starts_with/ends_with` 的提案 [P0457R2](https://wg21.link/p0457) 本会话实测可达。

## 最新演进与工业实践

- **库函数补语法糖（C++20）**：字符串前后缀检查 [P0457R2](https://wg21.link/p0457)；`<=>` 让「六个比较运算符的样板」在类型章就消失（详见 `05`，语言侧 [P0515R3](https://wg21.link/p0515)＋库侧 [P0768R1](https://wg21.link/p0768)，实测可达）。
- **入口的现代写法（C++23）**：`std::print/println` [P2093R14](https://wg21.link/p2093) 正在取代「第一章 Hello World 的 `std::cout <<`」。⚠️ 本会话在同工具链实测：`<print>` 在本 MinGW 编译可行但链接缺符号（见 `11` 章的逐字报错），教学时以 `std::format`+`puts` 为稳态替代。
- **模块（C++20，[P1103R3](https://wg21.link/p1103)）**：第 1 章「头文件闭包」这一心智负担的根治方向；工业界 GCC/Clang 支持度参差，2026 年教程仍按 include 教（同判断见 [`../c++之旅3/02-模块化与错误处理.md`](../c++之旅3/02-模块化与错误处理.md)）。
- **工业仓库**：`llvm/llvm-project`（clang-tidy/clang-format 是本章工具链的现代延伸）、`martinmoene/…` 与 [`microsoft/GSL`](https://github.com/microsoft/GSL)（`gsl::span` 是 `std::array`→`span` 教学线的前身）、[`google/styleguide`](https://google.github.io/styleguide/cppguide.html)（`enum class`、固定宽度整型的强制场合）。
- **`enum class` 的后续账本（C++23/26）**：强类型枚举换来「回整数要 `static_cast`」的繁琐，C++23 `std::to_underlying` 是官方出口票；枚举反射线（P2996 系，本库他册已实测可达）属 C++26 前瞻，`magic_enum` 类第三方库是今天的过渡形态。
- **练习/拓展接点**：原书「拓展阅读」栏在本章通常指向编译器文档与 C++ reference；2026 年更实用的替代动线——拿本章银行类型在 [`andreasfertig/cppinsights`](https://github.com/AndreasFertig-Institute/cppinsights) 里看展开。
