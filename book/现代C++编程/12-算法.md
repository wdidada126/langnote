## 核心概念速览（中英对照）

- **算法族** — algorithm taxonomy：非修改（观察）/可变（改写元素）/排序族/二分/分区/归并/极值/数值八组，命名即语义合同
- **区间接口** — `[first, last)`：半开区间协议，空区间天然合法——标准算法的第一公理
- **比较与投影** — comparator / projection：`comp(a,b)` 定「严格弱序」；C++20 ranges 再分离出「取值函数 proj」
- **严格弱序** — strict weak ordering：`comp(a,b)&&comp(b,a)` 恒假+传递性；违反则 `sort` 未定义——「`<=` 传给 sort」事故之源
- **稳定性** — stable vs unstable：相等元素保序与否；`stable_sort/stable_partition` 用 O(n) 额外缓冲买保序
- **复杂度合同** — Big-O per algorithm：`sort` O(n log n)、`equal` O(min(n,m))、`search` 朴素 O(nm)——18.1 教你「读算法如读合同」
- **执行策略** — execution policies：`seq/par/par_unseq`（C++17 `<execution>`）把并行意图写进调用点
- **`std::erase`/`erase_if`** — 容器级擦除（C++20）：终结 erase-remove 惯用法的两步舞
- **二分族** — `binary_search/lower_bound/upper_bound/equal_range`：有序前提下的 log n 查询与插入点定位
- **分区族** — `partition/partition_point/is_partitioned`：`stable_partition` 之外，快排的心跳即此
- **归并族** — `merge/inplace_merge/set_intersection…`：有序区间集合代数与外排基石
- **极值/数值族** — `min/max/clamp/midpoint`＋`iota/reduce/transform_reduce`：从逐元素到可并行化归约的阶梯
- **`subrange`** — first/last 升格为 Range：`equal_range`/`mismatch` 的现代返回型，也是视图管道的「装配件」（`10` 章接口语义的物化）
- **堆算法族** — `push_heap/pop_heap/sort_heap/is_heap_until`：`priority_queue` 的幕后协议；「部分有序」是排序与查找之外的第三态
- **`nth_element`** — 快速选择：平均 O(n) 取第 k 小/中位数——比「全排序再取下标」便宜一整个 log
- **搜索器适配器** — `boyer_moore_searcher`/`default_searcher`（C++17）：`search` 的子序列算法可换引擎，10MB 文本扫描的正解入口
- **`views::common`** — 哨兵补平适配器：把「first 与 end 异类型」的区间转回老式算法要求的 common 区间——新旧两个时代的转接头

## 1. 动机：把「手写循环」换成「有合同的函数」

第 18 章是《C++ 标准库》三章（容器/迭代器/算法）的收官：算法把 `10` 的迭代器协议与 `09` 的容器失效规则组合成**可声明意图的动词**。原书按标准库的官方分组（非修改/可变/排序/…）走一遍，每组给「签名+复杂度+典型调用」，并用 18.1 的复杂度表把「为什么不用手写冒泡」的争论一次终结。

## 2. 机制：命名合同、比较代数与并行入口

**合同阅读法。** `std::sort(first,last,comp)` 的四行合同：区间要求（随机访问迭代器）、comp 语义（严格弱序）、效果（重排）、复杂度（比较/移动 ~n log n）。本章训练的核心动作不是背函数名，而是**在 cppreference 表格里读合同**——`find_if`（线性）vs 有序容器上 `binary_search`（log）vs `unordered` 桶查询（均摊 O(1)）的选型即合同比对。

**比较器与投影的分离。** `sort(begin,end,[](auto&a,auto&b){return a.age<b.age;})` 在 C++20 写成 `std::ranges::sort(v, {}, &Person::age)`——比较（怎么排）与投影（拿什么排）解耦后，"按成员排序" 不再逼你写 lambda 样板（`views`/`sorted` 生态的入口知识，`10` 章联动）。

**数值运算的并行化阶梯。** `accumulate`→`reduce`（重结合合法：浮点数序变则结果微变，这是**允许并行**的语义授权）→`transform_reduce`（内积/归约+映射二合一）。18.2 执行策略正是把这条「语义上可并行」变成「调度上真并行」的入口：`std::reduce(std::execution::par, ...)`。C++17 入库（TS 谱系），GCC 需 TBB 后端支持（见实测注脚）。

**Boost.Algorithm（18.11）**：`string` 搜索系列（Knuth-Morris-Pratt/Boyer-Moore）、`minmax_element` 补件、`mismatch` 家族——标准朴素 `search` 为 O(nm) 时，专用搜索器/Boost 算法是工程答案。

## 3. 权衡：并行不是免费的 n 倍

- **`par` 的门槛**：区间够大 + 谓词无副作用 + 元素可独立访问；小数组上 `par` 的任务调度开销直接吃掉收益——执行策略的正确用法是「**基准测试驱动的选择**」，不是「越并行越好」。
- **`par_unseq` 的额外承诺**：元素访问可交错（向量化前提），谓词里碰共享状态即 UB——两层并行意图（任务级/指令级）的区分是 18.2 的真正考点。
- **稳定性税**：`stable_sort` 需要额外缓冲（分配失败则抛出）；「相等元素顺序是否重要」要先问业务再选函数。

## 4. 相邻概念对比

| 概念 A | 概念 B | 分界线 |
| --- | --- | --- |
| `for` 手写循环 | 标准算法 | 算法带复杂度/失效/并行三合同；手写循环三样都要自己兜 |
| `std::find` | `ranges::find` | 后者传容器、可投影、返回 subrange；语义一致、接口现代化 |
| `lower_bound` | `unordered_map::find` | 有序+区间查询用前者；点查用哈希；两者不可互相替代 |
| `accumulate` | `reduce` | 前者强制左折叠（顺序敏感），后者声明可重结合——并行许可的语义学 |
| `unique` | `set`/`flat_set` | `unique` 只看**相邻**重复——「先 sort 再 unique」的连招（本目录 `09` set 替代案） |

## 典型误区与修正视角

| 误区 | 症状 | 修正视角 |
| --- | --- | --- |
| 「`sort` 传 `a<=b` 也等价」 | 大数据偶发段错误 | 比较器必须是**严格弱序**：`<=` 让 `comp(a,a)` 为真，直接撕碎算法前提（libstdc++ debug 模式有专门断言） |
| 「`unique` 能全局去重」 | 去重后仍然一堆重复 | 它只看**相邻**重复：要么先 `sort`，要么换 `set`/`flat_set`（`09` 章对比表最后一行的另一面） |
| 「`binary_search` 没排序也能用，只是慢」 | 结果时对时错 | 不是慢是**错**：前置条件是已排序/已分区——运行时没人替你检查，debug 迭代器模式也救不了 |
| 「erase-remove 两步舞是仪式」 | 见 C++20 直写觉得不正宗 | `std::erase(v, x)`/`erase_if`（C++20）就是把惯用法收编成动词；`list` 另有成员 `remove`（不失效其余迭代器）——**成员版 vs 算法版**的选择才是重点 |
| 「传了 `execution::par` 就并行了」 | CPU 占用纹丝不动 | 执行策略只是**意图声明**：libstdc++ 需 TBB 后端才真并行，本章 🔧 实测「编过跑对但未证并行」正是教材本身 |
| 「`par` 永远快过 `seq`」 | 小数组反而变慢 | 任务调度有固定开销；区间小于某阈值时策略收益为负——并行选型=基准测试，不是信仰 |
| 「`for_each` 就是 `for`」 | 往谓词里塞累加器 | `for_each` 无短路、无投影红利；C++20 后「每个元素做一次」优先 `ranges::for_each` 或直接管道；要累加请上 `reduce` |
| 「算法改容器大小也能行」 | `transform` 写越界 | 算法只动**元素**不动**分配**：写入端要预留（`back_inserter` 或 `reserve`）——`10` 章插入迭代器就是为这一刻准备的 |

## 练习检查点（对应原书「练习/拓展阅读」栏）

- 18.1：给比较器挂全局计数器，实测 `sort` vs `stable_sort` 在 1 万随机数上的比较次数，与 O(n log n) 曲线对表。
- 18.3：把三段手写循环（统计/查找/打印）改 `ranges::count_if/find/for_each`，再用投影删掉两个 lambda——体会「`_if` 退役潮」。
- 18.4：`transform` 原地与写新容器（`back_inserter`）两版各写一次，故意不 `reserve` 观察越界或重分配。
- 18.5/18.6：`Person{name,age}` 按年龄排序三写法（lambda 比较器 / `ranges::sort`+投影 / 先 `sort` 后 `equal_range` 查区间），统计三版行数。
- 18.7：用 `partition_point` 找「及格线分割点」替代手写二分——同一需求两种合同，哪个更难写错？
- 18.9：`clamp`/`midpoint` 各治一个旧事故（`(a+b)/2` 溢出的 `midpoint` 解；指针钳位的 `clamp` 解）。
- 18.10：`transform_reduce` 一行写加权内积；再加 `execution::par` 计时对照 `seq`，记录你机器上的阈值曲线。
- 18.11：`boyer_moore_searcher` vs 朴素 `search` 在 10MB 文本×长模式串的耗时比。

## 🔧 实测对照：erase-remove 惯用法 vs C++20 直写 + 并行探针（已实测 g++ 15.2）

```cpp
#include <algorithm>
#include <vector>
#include <numeric>
#include <cstdio>
int main() {
    std::vector<int> v{5,3,5,1,3,2,2};
    std::ranges::sort(v);
    std::erase(v, 5);            // C++20：终结 v.erase(std::remove(...), v.end())
    int lt3 = std::ranges::count_if(v, [](int x){ return x < 3; });
    bool found = std::ranges::binary_search(v, 2);
    std::printf("rest=[%d,%d,%d,%d] lt3=%d found=%d mid=%d\n", v[0], v[1], v[2], v[3], lt3, (int)found, std::midpoint(1, 8));
}
```

- `-std=gnu++20` 真实输出：`rest=[1,2,2,3] lt3=3 found=1 mid=4`。
- **执行策略探针（如实记录）**：另写 `std::reduce(std::execution::par, ...)`（10 万元素）在本 MinGW g++ 15.2 `-std=gnu++17` 下**编译通过且运行**，输出 `sum=100000`；未显式链接 `-ltbb`，故**不能断言其真并行**——libstdc++ 无 TBB 后端时可能回退串行执行（⚠️ 并行度未实测验证；判并行请上 [`uxlfoundation/oneTBB`](https://github.com/uxlfoundation/oneTBB) 或 MSVC `/std:c++17` + TBB）。这正是本章「执行策略=意图声明，兑现看实现」的最佳教材注脚。
- `std::midpoint`/`lerp` 属 C++20 数值小件（`<numeric>`）；二分/归并族复杂度表建议直接对照原书 18.1 与 cppreference 双读。

## 最新演进与工业实践

- **ranges 算法族（C++20，[P0896R4](https://wg21.link/p0896)/[P1716R3](https://wg21.link/p1716) 实测可达）**：全套算法进 `std::ranges::`＋约束（`sortable`）＋投影；C++23 再收编 `ranges::for_each/is_permutation/move`（[P1209](https://wg21.link/p1209) 同库笔记已核可达）；「`_if` 变体」在投影时代大量退役——`count(v, x)` 取代 `count_if(v, eq(x))`。
- **C++26 并行续命**：`std::execution` [P2300R8](https://wg21.link/p2300)（本会话实测，标题逐字 std::execution）把「算法的并行调度」升级为通用发送者/接收者模型——`par` 策略的下一代表达；Parallelism TS v2 谱系（N4620，同库 Effective_Modern_C++ 笔记已核存在）是其前史。
- **工业仓库**：[`oneapi-src/oneDPL`](https://github.com/oneapi-src/oneDPL)（Intel 并行算法库，execution policy 的工业实现样本）、[`uxlfoundation/oneTBB`](https://github.com/uxlfoundation/oneTBB)（libstdc++ 并行后端的本体）、[`boostorg/algorithm`](https://github.com/boostorg/algorithm)。
- **练习/拓展接点**：18.2 的练习在 2026 的正确姿势是给「par 与 seq」加计时对照（[`google/benchmark`](https://github.com/google/benchmark)），并故意在谓词里共享一个计数器——观察 `par_unseq` 下 TSan 的指控（配合 `13` 章并发工具），把「策略即承诺」演成可见的竞态。
