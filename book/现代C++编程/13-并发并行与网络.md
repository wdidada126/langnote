## 核心概念速览（中英对照）

- **线程与句柄管理** — `std::thread` / joinable：不 join 的线程对象析构即 `terminate`——第 19 章第一警报
- **`std::jthread`** — joining thread（C++20）：析构自动请求停止+join，配 `stop_token` 实现可取消线程
- **互斥与锁守卫** — mutex + `lock_guard/unique_lock/scoped_lock`：RAII 把锁寿命并入作用域（`02`/`08` 章模式在同步域复刻）
- **死锁三要件** — 互斥持有+循环等待+不可抢占：`std::scoped_lock`（多锁一次性按内部序加锁）是最便宜的防法
- **条件变量** — `condition_variable`：等待必须「谓词循环」包裹（防虚假唤醒/丢失唤醒），与 `stop_token` 版 `condition_variable_any` 互通
- **内存模型与原子** — memory model / `std::atomic`：`relaxed/acquire/release/seq_cst` 四档序；`atomic::wait/notify`（C++20）把自旋等待队列进标准库
- **future/promise** — 异步结果管道：`async`+`future::get` 是「一次任务一个结果」的最小异步模型；`when_all` 属 C++20
- **任务窃取与并行模式** — task graph / parallelism：并行算法（`12` 章）与线程池（`19.1` 的工程延伸）的关系
- **io_context 事件循环** — Asio reactor：异步操作的**调度中枢**；`run()` 单线程串行执行处理器
- **异步完成模型** — async completion：`async_write(soc, buf, handler)` 的「发起+回调」两段式；缓冲区生命周期=Asio 第一杀手
- **strand** — 串行执行域：同一 strand 上的处理器互斥运行——「免锁并发」的官方配方（19.1 与 20.3 的桥）
- **协议对象** — `ip::tcp::endpoint/resolver/acceptor`：DNS 解析、监听、连接建立的类型化管道
- **happens-before** — 先行发生关系：release 写与 acquire 读配对建立跨线程可见性——19.1 内存序讨论的坐标系本体
- **伪共享** — false sharing：相邻 atomic 落在同一缓存行互相踢脸；`alignas(hardware_destructive_interference_size)` 是标准解药（各实现对线宽支持不一 ⚠️）
- **读写锁** — `shared_mutex`：读多写少的并行化武器；`shared_lock`/`unique_lock` 两副面孔——升级死锁是它的经典坑
- **双检锁** — double-checked locking：裸指针版百年陷阱；正确版=`atomic`+acquire/release 或干脆 Meyers singleton（并发书卷一专题）
- **完成处理器签名** — completion handler signature：Asio 的 `(error_code, bytes_transferred)` 参数约定——异步回调侧的「类型合同」，`async_initiate` 时代仍有效

## 1. 动机：两个世界共用一套「异步词汇」

19 章教「多线程共享内存」的纪律（锁/原子/future），20 章教「不共享内存的并发」——事件驱动网络。原书把 Asio 提升为独立一章，是其「工程全覆盖」立场最硬的体现：真实 C++ 后端里，网络等待才是并发的主要来源，而 **Asio 的完成模型（队列+处理器）恰好是第 9 章 `std::function`/lambda 的工业大考**（回调即闭包，闭包即捕获纪律）。

## 2. 机制：共享内存侧与消息侧

**线程管理。** `std::thread` 的所有权问题（detach 失控/join 忘）由 C++20 `jthread` 收口；停止请求是**协作式**——线程自己查 `stop_token`，语言不保证抢占。锁的层级：数据不变量→临界区→锁粒度→`shared_mutex` 读写分离→无锁（原子/等待），19.1 的「先锁对了，再谈快」与并发书第 2 版完全同轨（互链见文末）。

**原子与等待通知。** `atomic<int>` 的 `store/load` 默认 `seq_cst`——本章判据：先 `seq_cst` 写对，基准测试证明瓶颈后再降档。C++20 同步库 [P1135R6](https://wg21.link/p1135)（本会话实测，标题逐字 "The C++20 Synchronization Library"）把 `wait/notify`（内核无关的等待队列）、`latch/barrier/semaphore` 一次入库——生产者消费者样例从此可以**不碰 mutex**。

**Asio 模型（20.1）。** 三层：①`io_context`（任务队列）；②`Socket/Timer/Resolver` 等异步对象（发起+投递处理器）；③`strand`（可选串行化）。单线程 `io.run()` 即完成「并发但不并行」的事件循环——多数服务器逻辑的正确起点；20.3 扩到多线程 = `io_context::run()` 起 N 线程 + strand 保护共享状态，这正是「无锁并发靠串行域」的设计学。

**并行算法（19.2）与 `12` 章互认**：`execution policies` 属并发章的另一半——`par_unseq` 对元素访问的交错承诺在 Asio/原子语境下等价于「别碰共享可变状态」的同一条纪律。

**缓冲区保活谱系（Asio 第一杀手的病历本）。** 异步操作持有的是「裸地址+长度」，从发起到完成回调之间原对象若析构即悬垂。四代解法：①`shared_ptr<session>` 捕获进处理器（本目录 `08` 章方案，原书 20.2 姿势）；②`bind_handler`/`post` 把对象生命周期绑到队列；③协程栈帧由 promise 接管，局部缓冲天然活到 `co_await` 恢复；④`static_buffer`/`use_vector` 等完成令牌让 Asio 自己管分配。判据一句话：**发起异步操作时，必须能指出缓冲区此刻被谁持有**。

## 3. 权衡：线程、循环与未来

- **线程每连接 vs 事件循环**：C10K 视角下阻塞线程模型按连接计费（栈+调度），Asio 把成本摊到每操作；代价是回调碎片化——现代解法：协程化 Asio（`co_await async_read(...)`，C++20 后 Asio 官方支持）或 `std::execution`（[P2300R8](https://wg21.link/p2300) 实测可达，C++26）统一「可组合的异步任务」。
- **锁 vs 无锁**：`atomic` 的 wait/notify 已能替代大部分手写条件变量，但无锁数据结构（队列/栈）的正确性依赖内存序功力——判据：先无锁容器库（`boost.lockfree`），别徒手造。
- **缓冲区所有权**：Asio 异步写期间缓冲区必须活着——`shared_ptr` 捕获（`08` 章）或协程栈对象（promise 生命周期接管）是两代答案。

## 4. 相邻概念对比

| 概念 A | 概念 B | 分界线 |
| --- | --- | --- |
| `mutex`+`condition_variable` | `atomic::wait/notify` | 前者守不变量（多字段）；后者守**单值**观察——等待值变 |
| `thread` | `jthread` | 后者=自动 join+stop_token；新代码默认后者（C++20 起） |
| `async(f)` | 真·线程池 | `async` 是「启动策略可选的一次任务」，非池；长期订阅模型请上池/执行器 |
| Asio strand | `mutex` | strand 串行化「任务间」，不保证同任务原子性；粒度=处理器 |
| 回调（handler） | 协程（`co_await`） | 同样异步，协程把栈续体交编译器，可读性胜；栈开销与生命周期要学明白 |

## 典型误区与修正视角

| 误区 | 症状 | 修正视角 |
| --- | --- | --- |
| 「创建了 `thread` 不 join 也没事」 | 程序随机 `terminate` | 可 join 的线程对象析构=终止进程；C++20 默认 `jthread`，老代码用 `join`/`detach` 二选一写进 RAII |
| 「加了锁就线程安全」 | 复合操作仍翻车 | 锁保护的是**临界区**不是调用点：check-then-act 两段各拿一次锁等于没锁；不变量跨字段就整段进同一把锁 |
| 「条件变量 `wait` 不用判条件」 | 偶发丢唤醒/虚假唤醒假通过 | `wait` 醒来看谓词，谓词必须**循环**（或谓词版 `wait(lk, pred)`）——`atomic::wait` 同理，醒来要复核 |
| 「默认 `seq_cst` 太贵要精打细算」 | 一上手就 relaxed | 先 seq_cst 写对，再基准测试证明瓶颈后降档——「优化下来的内存序」是最后五公里不是第一公里 |
| 「`atomic` 什么都能原子」 | 对多字段复合状态束手无策 | 单值观察用 atomic，复合不变量用锁；「无锁全家桶」的叙事在标准容器/复合状态面前普遍失灵 |
| 「Asio 单线程 `run` 就不需要同步」 | 定时器与 socket 共享状态照崩 | `run()` 单线程确实串行安全——但一开多线程（哪怕池），共享状态立刻回到 19 章纪律；strand 是免锁解之一 |
| 「异步回调里缓冲区肯定活着」 | 半包/乱码/ASan 悬垂报告 | 发起时回答「谁持有这块内存」；四代保活谱系见机制节——这是 Asio 事故榜断层第一 |
| 「`async` 就是线程池」 | 高频小任务调度爆炸 | `async` 是一次一结果+启动策略（可能新线程/可能推迟）；长期订阅模型要池/执行器/`std::execution` |
| 「Windows 并发程序行为怪异是标准库 bug」 | 多线程 cv「挂死」、入口点缺失 | 本目录 🔧 实录：PATH 上旧 `libstdc++-6.dll`（Git for Windows）遮蔽 g++ 15.2 运行时——**先查 DLL 加载路径再查代码** |

## 练习检查点（对应原书「练习/拓展阅读」栏）

- 19.1a：把「不 join 的 `std::thread`」写成最小复现，确认 terminate；再分别用 `jthread`/显式 `join`/`detach` 三种改法收口，写三句话对比语义差异。
- 19.1b：`mutex+condition_variable` 生产者消费者改 `atomic::wait/notify` 版（本章 🔧 已给骨架），比较两版的等待路径谁更少上下文切换（计时代理即可）。
- 19.1c：故意制造死锁（两线程反序拿两把锁），换 `std::scoped_lock` 修复；再用 `std::try_lock` 写一个「拿不到就退避」的第三种方案。
- 19.1d：给 `std::async` 的 future 挂 `wait_for(50ms)` 超时分支，体会「一次任务一个结果」模型对「长期订阅」的不适配。
- 19.2：把 `transform_reduce` 分别以 `seq/par/par_unseq` 跑同一区间，记录耗时表；再在 `par_unseq` 版谓词里碰共享计数器，TSan 跑一遍看指控（`07` 章 sanitizer 联动）。
- 20.1：给一个 `io_context` 手工投递三层处理器（`post`/`dispatch`/`defer`），单线程 `run()` 打印执行序——理解「并发不并行」的最小实验。
- 20.2：同步 HTTP 客户端改 Asio 异步版，两版对照：发起-完成两段式代码行数、缓冲区持有者注释。
- 20.3：单 `io_context`+多线程 `run`+`strand` 版聊天回音室：证明去掉 strand 后 TSan 立刻指控（`09` 章 unordered_map 共享写事故的网络重演）。

## 🔧 实测对照：mutex+条件变量时代 vs C++20 `atomic::wait` + `jthread`（已实测 g++ 15.2）

```cpp
#include <atomic>
#include <thread>
#include <cstdio>
std::atomic<int> item{-1};
void producer() { item.store(42); item.notify_one(); }
int main() {
    std::jthread t(producer);                       // C++20：自动 join
    int v = item.load();
    while (v == -1) { item.wait(v); v = item.load(); } // 无锁等待队列，无 mutex
    std::printf("got=%d\n", v);
}
```

- `-std=gnu++20` 真实输出：`got=42`。
- **工具链事故实录（重要，已实测定位）**：本 MinGW 环境下直接运行含 `jthread` 的可执行体曾得 `STATUS_ENTRYPOINT_NOT_FOUND`（PowerShell 退出码 `-1073741511`，即 `0xC0000139`）——根因：PATH 上 **Git for Windows 自带的旧 `libstdc++-6.dll`**（`C:\Program Files\Git\mingw64\bin`）遮蔽了 g++ 15.2 运行时；把 `D:\develops\tools\mingw64\bin` 前插后同程序正常输出。与本项目 [`../C++服务器开发精髓`](../C++服务器开发精髓/00-总览与阅读地图.md) 系记录的「msys2 运行时遮蔽致 cv 挂死」同族——**Windows MinGW 多线程调试第一守则：先查 DLL 加载路径**。
- 对照原书 19.1 的 `mutex+condition_variable` 生产者消费者：三行 `wait/notify` 换掉整段锁+谓词循环（谓词循环的精神仍在——`wait(v)` 只保证「不等于 v 时醒」，复核循环不能省）。

## 最新演进与工业实践

- **C++20 同步库全表**：`jthread/stop_token/latch/barrier/counting_semaphore/atomic::wait`——教学级细节与陷阱（`stop_callback` 死锁窗口等）以 [`../C++并发编程实战2/02-线程管控.md`](../C++并发编程实战2/02-线程管控.md)、[`../C++并发编程实战2/05-Cpp内存模型与原子操作.md`](../C++并发编程实战2/05-Cpp内存模型与原子操作.md) 为准，本目录不重复。
- **C++23/26**：并行算法补齐（ranges 版 `parlay` 线）；`std::execution`（P2300）入 C++26 后，Asio 的执行器模型与标准发送者/接收者正在收敛（Asio 作者已做 `std::execution` 适配实验 ⚠️ 收敛进度以 Asio 官方文档为准）；协程生态：`std::generator` [P2502R2](https://wg21.link/p2502)（实测可达）适合「异步生产者→同步消费者」桥接。
- **执行器（executors）的退役与转世**：C++17 曾把 `std::executor_ts` 送进标准前的最后一轮公共评审，随后提案组撤回、改以「执行函数（`std::execution`）」姿态重来——20 章读到的 Asio `executor`/`execution_context` 词汇与这条标准线同名不同命；今天写 Asio 用它的 strand/context 体系，写标准侧等 P2300 落地，两边别混词。
- **工业仓库**：[`boostorg/asio`](https://github.com/boostorg/asio)（独立 Asio 即 chriskohlhoff/asio 本体）、[`facebook/folly`](https://github.com/facebook/folly)（`folly::coro`/`CPUThreadPoolExecutor`：工业异步的对照组）、[`abseil/abseil-cpp`](https://github.com/abseil/abseil-cpp)（`Mutex` 注解与 `SCOPED_CLEANUP`：锁纪律的编译期协助）。
- **练习/拓展接点**：20.2 的 HTTP 客户端练习在 2026 做两版：①回调版（原书姿势，`shared_ptr` 保活缓冲区）；②`co_spawn`+`use_awaitable` 版（同逻辑改协程）——两版对读即得「回调地狱消灭术」的体感，并与 `06` 章 lambda 捕获纪律、`08` 章所有权互锁验收。
