## 核心概念速览（中英对照）

- **函数模板 / 类模板** — function / class template：以类型为参数的编译期代码生成器
- **模板实参推断** — template argument deduction：由调用现场反推 `T`，`auto` 的规则内核（`02` 章）
- **类型转换函数** — conversion function：`operator T()` 让类「参与」目标类型上下文，模板场景要警惕歧义
- **类型检查（traits 式）** — type checking in templates：`std::is_arithmetic` 等编译期谓词 + SFINAE 筛选重载
- **概念** — concepts：对模板参数的**具名布尔约束**，书中为 TS 讲解、C++20 转正（[P0734R0](https://wg21.link/p0734) 实测可达）
- **`static_assert`** — static assertion：concept 之前「把约束写成编译期断言」的权宜之计（6.8 章题原话）
- **非类型模板参数** — non-type template parameters (NTTP)：`template<int N>`，字面量/`constexpr` 对象/`auto` 参数逐代放宽
- **可变参数模板** — variadic templates：`template<typename... Ts>` + 折叠表达式 + `sizeof...`
- **SFINAE** — substitution failure is not an error：候选替换失败仅出局不报错，是高级模板分派的引擎
- **CRTP** — curiously recurring template pattern：派生类把自己作为模板参数交给基类，编译期「静态接口」
- **两阶段名字查找** — two-phase name lookup：依赖名推迟到实例化查，模板源码组织（6.12）一切规矩之源
- **推导指南** — deduction guides：为类模板补「从构造函数反推」的官方说明书（CTAD 配件，[P0091R3](https://wg21.link/p0091)）
- **模板特化** — specialization：全特化换整套实现，偏特化只收窄一类；函数模板**没有**偏特化（用重载代替）
- **显式实例化** — explicit instantiation：`template class Foo<int>;` 把单态化产物钉死在一个 TU，编译防火墙第一件
- **变量模板** — variable template：`template<typename T> inline constexpr bool is_x_v`，traits 家族的书写糖（[P0386R2](https://wg21.link/p0386) 实测可达，inline 变量同批）
- **requires 表达式** — requires expression：`requires { t.x(); }` 成员/表达式约束语法，concept 定义体的核心零件

## 1. 动机：把「类型错误」从运行期提前到编译期

第 5 章的 vtable 把决定交给运行时；第 6 章的整章是一次「反机动」：**所有能在编译期判定的，都不留给运行期**。mean 函数（6.4）演示了朴素模板「什么都能塞、报错在天书里」，随后 6.6–6.8 给出三代约束武器：手工 traits + SFINAE → `static_assert`（能点名，但晚了、糙了）→ concept（正式语言设施，书中是 TS）。SimpleUniquePointer（6.5）则是模板类侧的完整标本：NTTP 管容量、类型参数管元素、推导指南管入口体验。

## 2. 机制：约束、分派与实例化

**约束三代。**
1. `enable_if` 时代（6.6）：`typename std::enable_if<std::is_arithmetic<T>::value, T>::type` ——约束藏在返回类型里，报错在重载解析结束后；
2. `static_assert` 时代（6.8）：函数体/体内先断言，报错在实例化时——信息带人话，但函数已被选中；
3. concept 时代（6.7）：`template<Number T>` 或 `requires std::integral<T> || std::floating_point<T>`，报错**在候选收集阶段**落点，且「不满足」本身参与重载排序（requires 子句更特化者胜）。

**变参三件套（6.10）**：`pack... ` 展开、折叠表达式（基稿 [N4295](https://wg21.link/n4295)，空包补全由 [P0036R0](https://wg21.link/p0036) 定「一元折叠恒真」，均实测可达）、`sizeof...` 计数。`SimpleUniquePointer` 的工厂与 `mean` 的「传任意多个值」在变参会师，第 9 章 `invoke`/`apply` 再回收一次。

**源码组织（6.12）**：模板定义必须对实例化点可见 → header-only（或 `export template` 遗骨、显式实例化白名单）；工程代价：编译时间膨胀。方向性解法即 C++20 模块 [P1103R3](https://wg21.link/p1103)（实测可达，标题逐字未复核 ⚠️ 以「modules 采纳稿」口径引用）。

## 3. 权衡：编译期图灵的账单

- **报错质量**曾是 concept 唯一动机；实测结论（同库 [`../C++编程惯用法`](../C++编程惯用法/00-总览与阅读地图.md) 一系验证过方向）：concepts 红利更多在**判决落点提前**，报错长度不必然缩短。
- **代码膨胀 vs 内联收益**：模板每实例一份；热循环里赚到的内联，可能在下一次全量构建时以编译时间+二进制尺寸偿还。工业界对策：显式实例化收口常见类型、`std::function` 类型擦除封顶实例数（`06`/`09` 章联动）。
- **SFINAE 的遗产地位**：concepts 可用处一律 `requires`；但「探测式约束」（检测 `t.x()` 是否存在，`std::void_t` 惯用法）仍需底层 SFINAE——`std::detected_or_t`（[P0515R3](https://wg21.link/p0515) 同代库件，实测可达的是其比较侧，detectors 属库 TS 线 ⚠️ 不引编号）作为标准化的探测器未全面落地前，手写 `void_t` 仍是工业默认。

## 4. 相邻概念对比

| 概念 A | 概念 B | 分界线 |
| --- | --- | --- |
| 模板 | 宏 | 模板进类型系统（可检查、可推断）；宏是文本替换无作用域 |
| concept | `static_assert`+traits | 前者约束**参与重载排序**，后者只在选中后审判 |
| `typename...` | `template auto`（NTTP 泛化） | 类型参数 vs 值参数；C++20 起 `auto` NTTP 可收结构化类型 |
| CRTP | 虚函数 | 静态接口 vs 动态接口；CRTP 不能做异构容器（`03` 的表回看） |
| 显式实例化 | 隐式实例化 | 前者把单态化收敛到一个 TU（编译防火墙），后者按需膨胀 |

## 典型误区与修正视角

| 误区 | 症状 | 修正视角 |
| --- | --- | --- |
| 「模板就是带类型的宏」 | 用宏的思路预判替换时机 | 模板进类型系统：两阶段查找下非依赖名在**定义点**就要合法，宏没有这个契约 |
| 「`static_assert` 和 concept 二选一」 | 混用后报错两头找 | 分工不同层：concept 拦在**候选收集**，`static_assert` 审在**实例化之后**；前者管重载，后者管体内不变量 |
| 「concepts 让报错一定变短」 | 实测复杂约束下 gcc 仍吐长报告 |红利是**落点提前 + 可命名**（`Number` 直接出现在报错里），长度不必然缩短（本章 🔧 与同库惯用法笔记双向验证过方向） |
| 「函数模板可以偏特化」 | 写 `template<> T* pick(T*)` 报「partial specialization」 | 函数模板无偏特化，改用**重载**；会「吃掉」重载集意外命中的坑由显式 `<>` 定住 |
| 「header-only 是天条」 | 大工程全量构建爆炸 | 显式实例化白名单、`extern template`、以及 C++20 模块 [P1103R3](https://wg21.link/p1103) 是三条正门逃生通道 |
| 「变参模板=printf 的 `...`」 | 以为类型会被擦除 | `typename...` 每个参数类型信息全程保留，配合折叠表达式无需 sentinel |
| 「特化越多越灵活」 | 实例化行为随 include 顺序变 | 过度特化破坏「声明点可见性」心智模型；优先用 tag dispatch / `if constexpr`（[P0292R2](https://wg21.link/p0292)）表达分层 |
| 「CRTP 是设计模式刚需」 | 到处套 CRTP | 它只是「编译期静态接口」的一种投影；需要异构容器时立刻换回虚函数（`03` 章对比表） |

## 练习检查点（对应原书「练习/拓展阅读」栏）

- 6.4 mean 改造：先加 `static_assert(std::is_arithmetic_v<T>)`，再改写成 `template<Number T>`，对比两次「传字符串」的报错落点（函数体 vs 候选集）。
- 6.5 SimpleUniquePointer 三连（本章主作业）：`requires std::is_pointer_v<T>` → 标准概念重写 → 补推导指南使 `SimpleUniquePointer p(new int{3});` 免写模板实参。
- 6.10 变参：手写 `sum(Ts... vs)` 分别用递归展开与一元折叠 `(... + vs)` 实现，验证空包时两版行为（折叠补全规则见 P0036）。
- 6.11 CRTP 标本：给 `Base<D>` 加 `derived()`（`static_cast<D&>(*this)`），体会「为什么这里不能用虚函数」。
- 6.12 源码组织：把模板定义挪进 `.cpp` 观察链接错误，再用显式实例化救回，记录编译时间差。
- 拓展阅读指针：tcmalloc/abseil 仓库里 `if constexpr` 与 tag dispatch 并存的中继期代码，是 6.11「高级主题」的工程注脚。

## 🔧 实测对照：`enable_if` 时代 vs concept 时代（已实测 g++ 15.2）

```cpp
// C++17 教法定位（原书 6.6/6.8）
template<typename T>
typename std::enable_if<std::is_arithmetic<T>::value, T>::type mean17(const T* a, int n) {
    T s{}; for (int i = 0; i < n; ++i) s += a[i]; return s / n;
}
// C++20 现代写法（6.7 转正后）
template<typename T> concept Number = std::integral<T> || std::floating_point<T>;
template<Number T> T mean20(const T* a, int n) {
    T s{}; for (int i = 0; i < n; ++i) s += a[i]; return s / n;
}
int main() {
    int xs[] = {1,2,3,4}; double ys[] = {1.5,2.5,3.5};
    std::printf("%d %.2f\n", mean20(xs, 4), mean20(ys, 3));
    // mean20("abc", 1); // 取消注释：约束不满足，报错直接点名 Number
}
```

- `-std=gnu++17` 编 `mean17` 版：真实输出 `2`；-std=gnu++20 编 `mean20` 版：真实输出 `2 2.50`。两者行为等价，**差异全在接口可读性与报错落点**（取消注释后 gcc20 报 `declaration of 'mean20' ... does not match any constraint`/约束不满足类信息，且 `"abc"` 根本进不了候选集）。
- 概念侧标准库件：`std::integral/std::floating_point` 出自标准库 concepts [P0898R3](https://wg21.link/p0898)（实测可达）；ranges 全套约束（`sortable`/`projected`）见 `10` 章。

## 最新演进与工业实践

- **C++23/26 模板补票**：折叠式模板参数展开 `...`（C++26 pack 索引线，[P2662](https://wg21.link/p2662) 同库笔记已核为 Pack Indexing——只在此处转述，不逐字引）；`if consteval` [P1938](https://wg21.link/p1938)（实测可达）给「双人格」模板函数补了第四分支语法。
- **ranges 是 concepts 的最大甲方**：`std::ranges::sort` 的约束族（`random_access_range + sortable`）即 concept 在标准库的首次全量应用；学习曲线建议：本章 concepts → `10` 章 ranges 二连（本项目 [`../C++20模板元编程/00-总览与阅读地图.md`](../C++20模板元编程/00-总览与阅读地图.md) 用整本书走同一条线）。
- **工业仓库**：[`fmtlib/fmt`](https://github.com/fmtlib/fmt)（`FMT_CONSTEXPR` 到 C++20 concepts 重写的公开演进样本）、[`google/consoledrawer`](https://github.com/google/consoledrawer) 之类示例仓不宜硬凑——更实名的对照是 [`ericniebler/range-v3`](https://github.com/ericniebler/range-v3)（约束设计的前置实验室）与 [`abseil/abseil-cpp`](https://github.com/abseil/abseil-cpp) 的 `type_traits` 替代件（其「少模板魔法」宣言与本章构成张力，值得让学生辩论）。
- **练习/拓展接点**：6.5 SimpleUniquePointer 的 2026 版作业：给指针类型形参加 `requires std::is_pointer_v<T>` 约束→ 再改用 `std::default_initializable` 等标准概念重写 → 最后写推导指南使 `SimpleUniquePointer p(new int{3});` 免写 `<int>`。三步依次命中 concepts、标准概念库、CTAD 三个时代件。
