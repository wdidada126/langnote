## 核心概念速览（中英对照）

- **流类库骨架** — iostream class hierarchy：`ios_base → basic_ios → istream/ostream → iostream`，`cin/cout/cerr` 是 `istream/ostream` 的 `char` 特化全局对象
- **格式化抽取** — formatted input/output：`<<`/`>>` 运算符族+操纵符（`setw/fixed/setprecision`），`locale` 注入决定数字/排序外观（`10` 章合流点）
- **流状态位** — `goodbit/eofbit/failbit/badbit`：`if (is >> x)` 的真相是检查状态位；`exceptions()` 可把流错误升级为抛异常
- **文件流** — `ifstream/ofstream/fstream`：`open(mode)` 的文本/二进制（`ate/app/trunc/in/out`）模式代数
- **字符串流** — `stringstream`：内存内的流——格式化调试字符串、`str()/clear()` 复用是本章隐藏考点
- **`filesystem::path`** — 路径对象：原生分隔符+泛化分隔符双轨，`/=` 拼接运算符、`filename/extension/parent_path` 分解
- **文件与目录操作** — free operations：`exists/is_directory/copy/remove/create_directories/size/last_write_time`（错误码与抛异常双签名，`14` 章错误谱系回收）
- **目录迭代器** — `directory_iterator`/`recursive_directory_iterator`：目录即区间（`10` 章协议在 OS 树上的兑现）
- **路径↔流互操作** — path→fstream：C++17 起 `fstream` 直接收 `path`（POSIX 时代先转字符串的补丁线）
- **`std::format`** — text formatting：`{}` 槽位+类型检查的格式化统一语言（C++20，[P0645R3](https://wg21.link/p0645) 实测可达）
- **`std::print`** — formatted output（C++23，[P2093R14](https://wg21.link/p2093) 实测可达）：面向终端的格式化输出直达
- **流缓冲区** — `streambuf`：字节真正搬运层；`rdbuf()` 对接两块流（把 `cin` 缓冲直接灌给 `cout`），自定义设备（socket/内存映射）全靠派生它
- **stdio 同步开关** — `sync_with_stdio(false)`：默认 iostream 与 C stdio 同步保互换但拖速度——「cin 慢」传闻的第一看门人；关闭后禁止混用 `printf` 与 `cout`
- **tie 耦合** — `iostream::tie`：读 `cin` 前自动 flush 绑定的流；提示语只露半句事故的病灶与解药
- **粘性 vs 一次性操纵符** — sticky vs one-shot：`fixed/setw/setprecision` 里只有 `setw` 一次性用完即复位——表格错位事故的头号嫌疑人
- **路径谓词与分解** — `absolute`/`proximate`/`lexically_normal`：path 三件套不做 IO 的纯字符串代数；与「不做隐式规范化」的教训配伍食用
- **`file_status` 与权限** — `status(p)`/`perms`：POSIX 权限位模型经 `filesystem::perms` 暴露；Windows 侧部分语义降级 ⚠️ 平台差以实测为准

## 1. 动机：IO 是语言与操作系统的焊缝

第 16 章极短（原书自陈：流类库是「历史包袱最重的 API」），第 17 章是 C++17 的新宠。两章合并正好拼出完整叙事：**怎么把字节搬进/搬出程序（16），搬的对象长什么样、怎么组织（17）**。原书的教学取舍清晰：流类库只讲骨干与惯用法（不纠缠 `sync_with_stdio` 的性能玄学全谱），`<filesystem>` 按「path→操作→迭代→对接流」四步走。

## 2. 机制：从状态位到路径代数

**流的正确性语义在状态位。** `is >> x` 失败时 `failbit` 置位、`x` 不变（C++11 后）；文本模式的 `>>` 会吃掉空白——「逐行读」的惯用式是 `getline`，「逐个词」才是 `>>`。`stringstream` 的复用必须 `str(新)/clear()`：忘 clear 状态位，循环里第二次抽取静默失败是本章最经典的事故。

**path 的类型学。** `path` 内部持原生字符串但提供泛化访问（`generic_string()` 统一 `/`）；`operator/=` 智能插分隔符但**不做路径规范化**——`a/./b` 拼接即字面结果。Windows 的盘符/UNC 与 POSIX 的同名不同义，本章的工程提醒：跨平台代码里 path 只当「部件容器」用，别拿字符串比较路径。

**文件系统 API 的双签名。** 每个操作有 `f(p)`（抛 `filesystem_error`）与 `f(p, error_code&)` 两版——**批量遍历用错误码版**（单文件权限失败不该中断全盘扫描），用户命令用异常版。这与 `14` 章「错误处理光谱」结论完全同构。

**目录迭代器=文件系统版的 ranges 前端。** `directory_iterator` 满足输入迭代器要求：可直接喂 `std::count_if`/`find_if`（`12` 章算法区的 OS 应用）；`recursive` 版的 `depth/pop` 控制可剪枝——磁盘用量统计的教学例即此。

**缓冲、刷新与三块全局流。** `cout` 是带缓冲的：`endl`=换行+flush、`'\n'` 只换行；程序正常终止时全局流自动 flush，异常/`abort` 路径则可能丢尾行——「日志少最后一行」的第一现场。`cerr` 默认不缓冲且 `unitbuf` 置位，`clog` 走缓冲：三兄弟的分工是一句「紧急程度」而非类型差异。块作用域（`05` 章）结束时局部 `fstream` 析构自动 close+flush——RAII 在 IO 界的默认兑现，不需要你手写 `close()`（除非你要检查 close 的错误码版返回值）。

## 3. 权衡：`<<` 链、printf、format 的三方债

| 方案 | 长板 | 欠账 |
| --- | --- | --- |
| iostream `<<` | 类型可扩展（重载在类侧）、locale 感知 | 格式控制啰嗦（`setw+setfill+fixed`）、性能中下、与 C 生态不亲和 |
| `printf` 族 | 快、格式串即文档 | 类型不安全（`%d` vs `long` UB）、locale 粗糙 |
| `std::format`/`print` | 编译期检查格式串（字面量时）、性能第一梯队、`{}` 槽位可读 | 自定义类型需特化 formatter；工具链成熟度参差（见下实测） |

原书 16.1 教 iostream 在 2026 年仍完全成立（它是**流语义**：文件、socket、字符串三界的统一抽象），但**格式化**这件事已迁往 `std::format`——两件事拆开教才不误伤。

## 典型误区与修正视角

| 误区 | 症状 | 修正视角 |
| --- | --- | --- |
| 「iostream 天生比 printf 慢」 | 未调优就整体弃用 | 慢的第一根因是**默认与 stdio 同步**；`sync_with_stdio(false)`+`cin.tie(nullptr)` 后差距大缩小（本目录练习题量给你自己的数字） |
| 「一行 `<<` 串完格式就稳」 | 表格第二列起全部错位 | `setw` 一次性、`fixed/setprecision` 粘性；状态机式操纵符要在每列前重设宽度 |
| 「提示语没显示是 cout 坏了」 | `cout << "输入: "; cin >> x;` 半句消失 | 缓冲+`tie` 机制：要么 `flush`/`endl`，要么理解默认 tie 为什么救了你 |
| 「`path` 就是字符串，`==` 随便比」 | 跨平台判等翻车 | 大小写敏感性与分隔符随 OS；先 `weakly_canonical`/`lexically_normal` 再比，或比 `file_status` 的设备/节号 |
| 「`exists()==false` 就是文件不存在」 | 权限受限目录里误报「无此文件」 | `exists` 分不清「没有」与「没权限看」；错误码版 `status(p, ec)` 里 `ec==permission_denied` 是第三种真相 |
| 「符号链接会自动被处理好」 | 递归遍历成环/体积重复计 | `recursive_directory_iterator` 默认**不**追随符号链接（`follow_directory_symlink` 显式开）；`file_size` 的语义随 OS——两处都要显式决策 |
| 「异常版 API 更优雅所以全用它」 | 全盘扫描被单个权限文件打断 | 双签名纪律：遍历/批量用 `error_code` 版，用户指令用异常版（`14` 章光谱的同一条） |
| 「`getline` 读二进制也行」 | `\r` 残留、长度对不上 | 文本模式做换行翻译；二进制走 `read/write`+`streamsize` 循环，别拿格式化设施当搬运工 |
| 「`stringstream` 换个 `str()` 就能复用」 | 循环第二轮起静默失败 | 状态位不清零，抽取永远失败；复用语义=`str(新)+clear()` 两连，或者干脆重建对象 |
| 「`std::format` 全面替代 iostream」 | 想往 socket 上流式写时抓瞎 | format 管「字符串怎么拼」，iostream 管「字节往哪流」；自定义设备仍需 `streambuf` 派生——两者是互补不是换代 |
| 「文件写完靠析构自动收尾就稳」 | 磁盘满/权限变更时静默丢尾 | 析构不报错：落盘保证要在**显式** `flush()`/`close()` 后查 `good()`（或给流 `exceptions()` 上闸）——`08` 章 RAII 兜住句柄，兜不住「写成功」三个字 |

## 练习检查点（对应原书「练习/拓展阅读」栏）

- 16.1a：同一文本文件分别用 `>>`（逐词）与 `getline`（逐行）各读一遍输出行数；再混用一次 `>> x` 后 `getline`，解释为什么后者吃到空串（换行残留）。
- 16.1b：写 `setw/setfill` 三列表格，先按直觉写、再按「一次性 vs 粘性」修正；随后 `cin.tie(nullptr)` 复现提示截断并给出 `flush` 版修复。
- 16.1c：`sync_with_stdio(false)` 前后各测一次 10 万行 `cin>>` 回放（管道喂文件），报告你自己的倍数。
- 16.1d：`stringstream` 循环复用两版（清/不清 `clear()`），用状态位打印 `fail()` 证明静默失败。
- 17.2：对一个 Windows UNC 串与一个 POSIX 串各打印 `filename/stem/extension/parent_path` 四件套；用 `lexically_normal` 处理 `a/./b/../c`，观察「纯字符串、不碰磁盘」。
- 17.3：同一「统计目录树体积」需求写异常版与 `error_code` 版各一遍，在含无权限子目录的树里对比存活输出。
- 17.4：`recursive_directory_iterator` 区间直接喂 `ranges::count_if(extension()==".cpp")`；再加 `depth()` 限制剪枝 `.git`。
- 17.5：把 `path` 直接传 `ofstream`（C++17）并与「先 `.string()`」旧写法对拍，顺带验证中文路径在 UTF-8 代码页下的行为差异 ⚠️ 平台相关。

## 🔧 实测对照：`ostringstream` 手工拼装 vs `std::format`（已实测 g++ 15.2）

```cpp
#include <format>
#include <filesystem>
#include <cstdio>
int main() {
    auto line = std::format("{:<8}|{:>8.2f}|{:04x}", "robot", 3.14159, 255); // 左对齐/右对齐宽度/十六进制
    std::puts(line.c_str());
    std::printf("temp exists=%d\n", (int)std::filesystem::exists(std::filesystem::temp_directory_path()));
}
```

- `-std=gnu++20` 真实输出：`robot   |    3.14|00ff` ＋ `temp exists=1`。
- **工具链注脚（逐字报错，已实测）**：同工具链试 `<print>`（C++23）——编译到链接阶段失败：`undefined reference to 'std::__open_terminal(_iobuf*)'` ＋ `undefined reference to 'std::__write_to_terminal(void*, std::span<char, ...>)'`（ld.exe, collect2 退出码 1）。即 **libstdc++ 15 的 `std::print` 在本 MinGW win32 线程模型下链接残缺**——本项目 [`../C++语言程序设计5`](../C++语言程序设计5/00-总览与阅读地图.md) 系笔记曾独立记录同一坑，互证成立。格式化教学请用 `std::format`+`puts/cout`，`std::print` 留作 Linux/MSVC 演示。
- 提案账：format 语言-库措辞 [P0645R3](https://wg21.link/p0645)（本会话实测，标题 "Text Formatting"）；print [P2093R14](https://wg21.link/p2093)（实测可达）。

## 最新演进与工业实践

- **C++20/23 对位**：`path` 的 `u8string()` 返回 `std::filesystem::path` 的 UTF-8 视图线（C++20 `char8_t` [P0482R6](https://wg21.link/p0482) 实测可达）；`std::format` 的 ranges 格式化（`{:}` 集合输出，[P2286](https://wg21.link/p2286) 同库笔记已核可达）；C++23 `std::filesystem::path` 对 `u8string_view` 的接受度仍以 libstdc++/MSVC STL 支持矩阵为准 ⚠️。
- **文件系统实操增强**：`std::filesystem::file_time_type::clock` 一致性、`copy_options` 细粒度（C++20 起 `directory_iterator` 支持 `file_time_type` 缓存）——工程侧更实名的动作是把「文件监听」交给 OS 事件（inotify/ReadDirectoryChangesW），标准库无监听 API（至今缺口 ⚠️ C++26 亦无在案提案）。
- **工业仓库**：[`fmtlib/fmt`](https://github.com/fmtlib/fmt)（std::format 的前身与超集，formatter 自定义的活文档）、[`microsoft/STL`](https://github.com/microsoft/STL)（iostream/format 实现演进）、[`gabime/spdlog`](https://github.com/gabime/spdlog)（基于 fmt 的日志层——「流的现代替身」论据；课程版对照见 [`../现代C++实战30讲/14-单元测试与日志库.md`](../现代C++实战30讲/14-单元测试与日志库.md)）。
- **练习/拓展接点**：17.x 的目录统计练习加一个 2026 断言：`recursive_directory_iterator` + `fs::file_size(ec)` 错误码版，在含符号链接的树里必须显式 `follow_directory_symlink` 决策（否则成环风险）——把第 21 章的「错误处理」与本章的「遍历」焊死验收。
- **`<fstream>` 收 `path` 之外**：C++23 的 `std::file` 输入文件句柄线与 `std::filesystem::u8path` 退役线继续修补 IO/路径接口（⚠️ 均属主题名引用，本会话未逐字核提案号）；教学侧影响有限——`fstream`+`path`+`error_code` 三件套仍是 2026 教材稳态。
