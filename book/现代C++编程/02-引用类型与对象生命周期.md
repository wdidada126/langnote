## 核心概念速览（中英对照）

- **指针** — pointer：持地址的对象，可空、可重指、算术运算按元素步进
- **引用** — reference：必须初始化、不可重绑的「别名」，`T&&` 在特定上下文是右值引用而非引用引用
- **悬垂引用** — dangling reference：所指对象亡而引用名存，第 4 章全部灾难的总根源
- **`auto` 类型推断** — type deduction with `auto`：按模板实参推断规则剥引用与 `const`，`auto&` 才保留引用
- **存储期** — storage duration：静态/线程/自动/自由（dynamic）四族，决定析构时机
- **RAII** — Resource Acquisition Is Initialization：资源寿命绑定对象寿命，异常安全的骨架
- **栈展开** — stack unwinding：异常沿调用栈上行、逐对象析构，`noexcept` 是其边界条件
- **复制语义** — copy semantics：复制构造/赋值=深拷贝纪律，SimpleString 逐字节演示
- **移动语义** — move semantics：窃取堆资源换取廉价转手，`std::move` 只负责「命名为右值」
- **异常规格** — `noexcept`：承诺「不抛」，违约即 `terminate`；移动/析构的默认防线
- **自赋值防护** — self-assignment：拷贝赋值里 `this == &rhs` 检查在深拷贝手写实现中不可省
- **三/五/零法则** — rule of three/five/zero：有了析构/拷贝/移动其一，就要对整套负责，最好一套都不要（委托给成员）
- **保证的拷贝消除** — guaranteed copy elision：C++17 起 `return T{...}` 不承诺「省掉的移动」而是不发生移动（[P0135R1](https://wg21.link/p0135)）
- **值分类地图** — value categories：lvalue/xvalue/glvalue 三族六类，`std::move`/`forward`/重载决议全部以此为裁判（`06` 章正面展开）
- **万能引用** — universal reference：`T&&` 在推导上下文的别名身份，与右值引用形似神异（EMC++ Item 24 的百年纠偏点）
- **线程存储期** — thread storage duration：`thread_local` 对象每线程一份、随线程退出析构——4.1 四族里最常被跳过的一族
- **移动后的有效状态** — moved-from validity：被移动对象仍是合法可析构的对象，但内容只剩「合同可查」——别假设也别乱用
- **`std::exchange` 惯用法** — 移动赋值的安全零件：`exchange(ptr, nullptr)` 原子地「取走+置空」，写移动赋值少一对 if/delete
- **拷贝-交换（copy-and-swap）** — 异常安全构造术：按值收副本 → `swap` → 副本带旧资源死去；强保证一行 `T(other).swap(*this)` 换三态分支

## 1. 动机：指针/引用是语法，生命周期才是问题

第 3 章表面讲「怎么声明」，实际在回答：*一个值如何不拷贝地抵达函数*。第 4 章立刻把问题升级——值到了，**它依赖的东西还活着吗**。两章合并阅读的价值正在这条因果链：`auto` 推导错一个 `&`，就得到悬垂引用；异常路径漏一层析构，SimpleString 就漏内存。原书用同一个字符串类把两条线拧在一起，这是全书前半程技术密度最高的连击。

## 2. 机制：三条主线

**引用 vs 指针的选点。** 参数方向：可能缺席用指针（可空语义），必然存在用引用；返回方向：视图类返回引用/`string_view`，所有权转移返回值（或 `unique_ptr`）。3.3 的「使用」节实为一份决策表雏形。

**`auto` 的规则内核。** `auto x = expr;` 走模板实参推断（拷掉引用、顶层 `const`）；`auto&`/`const auto&` 保留引用；初始化列表 `auto x{3}` 得 `std::initializer_list`——4 条规则覆盖 95% 场景。结构化绑定（第 9 章回用）即该推断的推广（[P0217R3](https://wg21.link/p0217) 实测可达）。

**生命周期四联。** ① 存储期决定析构点：自动对象离开块、动态对象等 `delete`；② 异常路径**仍**按构造逆序析构栈对象——这是「为什么用 RAII 而不是 goto cleanup」的论证；③ SimpleString 手写三/五法则，暴露浅拷贝 double-free 的全部细节；④ 移动语义（4.6）把「廉价转手」从特例变成默认：`std::move` 是 `static_cast<T&&>` 的命名仪式，不产生任何机器行为。

## 3. 权衡：显式 vs 自动、拷贝 vs 移动

- **裸 `new/delete`（4.1 教学期出现）与 RAII**：先手写所有权，第 11 章智能指针才有「解药对病」的体感；代价是中间章节代码在 2026 年必须挂「仅教学」警示。
- **移动构造「 noexcept 才进容器」**：移动操作若可抛，`vector` 扩容宁可退回放慢拷贝——写移动时默认 `noexcept`，这是第 4 章埋给第 11 章（`unique_ptr` 迁移）的钩子。
- **`auto` 的可读税**：推断越顺手，类型漂移越隐蔽（`auto` 吞引用、`auto` 按值拷贝智能指针导致原子计数增）。现代指南的口径：短作用域+表达式类型显然才裸 `auto`。

## 4. 相邻概念对比

| 概念 A | 概念 B | 分界线 |
| --- | --- | --- |
| `T*` | `T&` | 可空/可重指 vs 必非空/不重绑；跨 API 边界传所有权走前者，函数内借用走后者 |
| 值返回 | 输出引用形参 | C++17 后「按值+移动/保证消除」几乎全胜；出参只在需要多次返回时保留 |
| `std::move` | `std::forward` | 移动是**转手**（源确定被弃用），转发是**透传**（值分类不变），详见 `06` |
| 深拷贝 | 浅拷贝 | 默认成员拷贝在裸指针成员上=浅拷贝=double-free 之源（SimpleString 的主案发现场） |
| 异常 + 析构 | 错误码返回 | 资源清理场景异常几乎不输；但错误码在「可预期失败」上保留胜场（第 10 章 expected 线，见 `07`/`09`） |

## 典型误区与修正视角

| 误区 | 事实 |
| --- | --- |
| 「`auto` 就是按引用」 | 裸 `auto` 按值且剥 `const/&`；`auto&`/`const auto&` 才是引用——推断规则背错方向就悬垂 |
| 「`std::move` 会移动」 | 它只是 `static_cast<T&&>`；移动发生在被选中的**移动构造/赋值**里 |
| 「析构顺序靠直觉」 | 同一作用域内严格构造逆序；成员按**声明序**逆序——声明顺序就是析构合同（`05` 章 `<=>` 同款纪律） |
| 「异常=更体面的 goto」 | 栈展开有真实成本（查表/析构链/缓存污染）；可预期失败走错误值（expected），异常留给「不该发生」 |
| 「返回局部变量的引用是快」 | 直接悬垂。按值返回+移动/保证消除才是快（实测样本站在 C++17 一边） |
| 「拷贝赋值不用管自赋值」 | `a = a` 走「先释放再接管」路径即自毁——手写五法则的必答题 |
| 「移动后的对象随便用」 | 处于合法但未指定内容状态 | 它仍须可安全析构、可再赋值得对——但读它等于问「空盒子里剩什么」：只许用合同承诺可查的操作（如 `unique_ptr` 判空后 reset） |
| 「`const` 就是只读」 | 拿 `const` 当线程安全/当编译期 | `const` 管接口不改，不管别名可见性（mutable/`const_cast` 都在门口），也不保证初始化时机；编译期要 `constexpr`（`05` 章表） |
| 「析构函数抛异常再包一层 try」 | 展开中二次异常直接 `terminate` | 清理失败的正确姿势=吞掉并记日志，或提前用 RAII 把失败关在构造期；析构的 `noexcept` 默认不是建议，是合同 |

## 练习检查点（对应原书「练习/拓展阅读」栏）

- 检查点 1：给 SimpleString 补全五法则，每个函数加自赋值/空指针/`noexcept` 三查——用 `-Wall` 看编译器点名漏掉了哪条隐式移动。
- 检查点 2：构造一个「返回 `string_view` 指向局部」的函数，开 `-Wdangling-reference`（GCC13+）观察告警——把悬垂变成可见。
- 检查点 3：把 mean/std 双输出改写三版：出参版→`pair`+结构化绑定版→自定义 `Stats` 聚合版，比较可读性与可演进性。
- 检查点 4：把 SimpleString 改造为「禁拷贝+可移动」版，在 C++14 与 C++17 下分别编译工厂函数 `make()`，复现本章 🔧 的删除函数红字与通过两态——同一份代码跨一个标准版本的生死对比。
- 检查点 5：写一个 `thread_local` 累积计数器跨三线程演示「每线程一份+随线程析构」，输出各线程终值——把 4.1 四族存储期的第四族变成可见。
- 拓展落点：[P0135R1](https://wg21.link/p0135) 与 [P0848R3](https://wg21.link/p0848) 原文（均实测可达）；异常成本的现代测量在 `07` 章基准线工具。

## 🔧 实测对照：C++14 的「至少一次移动」vs C++17 保证消除（已实测 g++ 15.2）

```cpp
#include <cstdio>
struct MoveOnly {
    int v;
    MoveOnly(int v) : v(v) {}
    MoveOnly(const MoveOnly&) = delete;
    MoveOnly& operator=(const MoveOnly&) = delete;
    MoveOnly(MoveOnly&&) = delete;      // 连移动都删
};
MoveOnly make() { return MoveOnly{42}; } // 直接返回临时量
int main() { auto m = make(); std::printf("v=%d\n", m.v); }
```

- `-std=gnu++14`：**编译失败**，逐字诊断：`error: use of deleted function 'MoveOnly::MoveOnly(MoveOnly&&)'`。
- `-std=gnu++17`：编译通过，真实输出 `v=42`。
- 机制账：C++14 允许消除但**要求**存在可用拷贝/移动构造函数；C++17（[P0135R1](https://wg21.link/p0135)，实测可达）把「返回纯右值初始化同类对象」改写成**不产生任何构造调用**——「按值返回」的成本论从「省不省」变成「本不存在」。
- 4.4–4.6 的 SimpleString 若用禁拷贝+自写移动实现，在 C++14 工厂函数处正是上面这条红字；这是本书两处章节（4 与 6/9 的返回语义讨论）在 2026 年唯一需要「重做实验」的判例。

## 最新演进与工业实践

- **条件平凡特殊成员（C++20，[P0848R3](https://wg21.link/p0848) 实测可达）**：三/五法则的编译器自动化延伸——`constexpr` 析构等能力让聚合类在编译期也能「持资源」。
- **CTAD 与 `auto` 合流（C++17，[P0091R3](https://wg21.link/p0091) 实测可达）**：`std::complex z{1.0, 2.0};`——第 3 章推断规则的最后一块拼图；本目录在 `04` 章 SimpleUniquePointer 处回收推导指南。
- **移动操作的条件 `noexcept`**：「`vector` 只搬 `noexcept` 的移动」的现代解是 `noexcept(条件)` 规格——手写移动时把承诺写成 `std::is_nothrow_move_constructible_v<成员>...` 的合取，让容器替你选移动还是拷贝（标准库自身即此写法最大样本）。
- **生命周期工具化**：编译器侧 `-Wdangling-reference`（GCC13+/Clang19+）把 3.3 的「悬垂引用」从人肉纪律变告警；静态侧 clang-tidy `bugprone-dangling-handle`、微软 C++ Core Guidelines `[ Lifetime profile ]`（见 [`../C++CoreGuidelines解析.md`](../C++CoreGuidelines解析.md)）同题。Sanitizer 侧：ASan 的 container-overflow 与本节内存模型直接相关（本项目 [`../C++代码调试的艺术.md`](../C++代码调试的艺术.md) 有平台实测注脚：MinGW 无 libasan，Windows 走 MSVC/WSL）。
- **工业仓库**：[`facebook/folly`](https://github.com/facebook/folly)（`folly::Expected`、移动重武器库）、[`abseil/abseil-cpp`](https://github.com/abseil/abseil-cpp)（`absl::string_view`/`StatusOr`：借用 vs 所有权二分的工业范本）。
- **练习/拓展接点**：4.x 练习的经典「手写 SimpleString 全套五法则」在 2026 年的正确打开方式：写完后再用 `-Wall -Wextra` 让编译器点名「隐式移动被禁用」的项——与 [`../Effective_Modern_C++/05-右值移动完美转发.md`](../Effective_Modern_C++/05-右值移动完美转发.md) 的 Item 29「移动要无条件 noexcept」互为练习题与教条。
