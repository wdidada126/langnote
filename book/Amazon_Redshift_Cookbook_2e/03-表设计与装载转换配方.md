## 3. 深潜一：三要素心智（⚠️ 转述+✅ 锚）

- **DISTSTYLE/DISTKEY**：事实表与大维表同键 HASH 分布可把 JOIN 变"节点本地"（ALL/KEY/EVEN 四式；AUTO 为现代默认）——分布键专页已 302（§2 表登记），语义锚走 r_CREATE_TABLE_NEW（✅）。
- **SORTKEY**：COMPOSITE(≤8 列) vs INTERLEAVE（多过滤列交叉剪裁）；1MB 块+区域元数据（zone map）是剪裁粒度（⚠️ 转述；✅ t_Sorting_data）。ATO 自动排序（auto sort）自 RA3 起在多数场景替代手工选择（⚠️）。
- **ENCODE AUTO**：列存自动选码（ZSTD/Delta/RLE…），装载后再 ANALYZE/VACUUM 生效（⚠️；✅ VACUUM/ANALYZE 锚 https://docs.aws.amazon.com/redshift/latest/dg/r_VACUUM_command.html 、https://docs.aws.amazon.com/redshift/latest/dg/r_ANALYZE.html 均同址 200）。
- 建模学理源头（星型/雪花之争）在盘上教典：[../Building_the_Data_Warehouse/11-关系模型与多维模型.md](../Building_the_Data_Warehouse/11-关系模型与多维模型.md)。

## 4. 深潜二：COPY 家族与"装载即转换起点"

- COPY 并行多文件+gzip/parquet/csv/manifest；`JSON 'auto'` 自动推型；`SERIALIZESTAGE`/`STATUPDATE` 调档（⚠️ 转述；✅ r_COPY https://docs.aws.amazon.com/redshift/latest/dg/r_COPY.html 同址 200，copy-parameters 锚 ✅ 同上）。
- AUTO COPY（把装载排队交给系统，替代手工"夜里批量白天流"）：2023+ 默认化（⚠️ 转述）。
- 装载后反模式：**直接 UPDATE 大表**——Redshift 的 UPDATE=标记删除+尾部插入，产生 unsorted 区放大 VACUUM 压力；本章 ch3 的暂存表合并法正是官方推荐替代（⚠️ 转述+✅ r_VACUUM_command）。
- DynamoDB 源：小表 scan 转 SQL、大表走 Export→S3→COPY（或 Zero-ETL，见本册 10）（⚠️；✅ CreateAndLoad_dynamodb.py 实抓为小表姿势）。

## 5. 🔧 实测：COPY vs 逐条 INSERT（3 个数量级）与合并两法

脚本 demo.py（D1/D3），DuckDB 1.5.5——**非 Redshift 行为，方言已按 DuckDB 改写**（Redshift 无 `ON CONFLICT` 语法，该路数仅为对比教学）：
1. 5e6 行 csv：`COPY l FROM 'lineitem.csv'` **1103ms**；同表逐条参数化 `INSERT ... VALUES(?,...)` 2e4 行 **19947ms**→外推 5e6 ≈ **4987s（约 83 分钟）**——**批量 COPY 与逐条 INSERT 相差约 4500×**，Redshift 同向结论（⚠️ 转述其"COPY 并行、INSERT 慢"官方口径）。
2. 10 万行增量并入 5e6 基表：仓内 ch3 式 **delete+insert（事务包）** **1072ms** vs DuckDB `INSERT ... ON CONFLICT DO UPDATE` **99ms**——证明"暂存合并法"正确但笨重；Redshift 至今无原生 UPSERT，社区以 merge 宏/存储过程薄封装（⚠️ 转述），此差异是本章最值得带走的一条。

## 6. 常见坑与最佳实践（⚠️ 转述+✅ 锚）

1. `STATUPDATE OFF` 只在反复试装用，正式装载后必补 ANALYZE（统计缺失→坏计划）。
2. gzip csv 装载 CPU 受限：列存格式（Parquet）+投影裁剪常胜过解压大 csv（§5 尺寸账见本册 04；✅ r_COPY 格式族）。
3. DISTKEY 选低基数列=分布倾斜单节点热点；先 `SELECT count(distinct)` 体检（⚠️ 工程惯例）。
4. 事务内 `DELETE USING + INSERT` 两语句同规模时，DELETE 的锁与 VACUUM 尾巴比 INSERT 更疼——小频率大批、避开查询高峰（⚠️）。
5. etl/ 分区目录的 dt 路径若被 `manifest` 与"通配+日期目录"两种方式混用，会双算行数——COPY 前后 `SELECT count(*)` 对账进配方模板（⚠️ 重构自文件摆位 ✅）。

## 5b 配方演绎一：SSB 星型五表 DDL 要点（⚠️ 转述重构——✅ Ssb_Table_Ddl.sql 文件名实抓、终版 0B 占位，细节以语法锚复核）

```sql
-- Redshift 方言示意（⚠️ 非原书文本；✅ r_CREATE_TABLE_NEW 锚同址 200）
CREATE TABLE part (
  p_partkey     BIGINT       DISTKEY,       -- 与 lineorder 同键：JOIN 本地化
  p_name        VARCHAR(55),
  p_mfgr        VARCHAR(25)  ENCODE TEXT255,
  p_retailprice DECIMAL(18,4)
) SORTKEY (p_partkey);
CREATE TABLE lineorder (
  lo_orderkey   BIGINT DISTKEY,             -- 事实表分布键=与最大 JOIN 对象对齐
  lo_partkey    BIGINT,
  lo_custkey    BIGINT,
  lo_orderdate  INTEGER,
  lo_quantity   DECIMAL(12,2),
  lo_extendedprice DECIMAL(12,2)
) INTERLEAVE SORTKEY (lo_orderdate, lo_partkey);  -- 多过滤列交叉剪裁
```
读法：事实表 DISTKEY 跟"谁 JOIN 我最多"走；维度表小则考虑 `DISTSTYLE ALL`；日期+高选择性列进 INTERLEAVE（⚠️ 现代默认 AUTO，例外才手写 →§3）。

## 5c 配方演绎二：暂存表合并五步（✅ 仓内 Insert_Update_Lineitem.sql 骨架 + ⚠️ 全步转述）

```sql
BEGIN TRANSACTION;                              -- ✅ 实抓首行同款
DROP TABLE IF EXISTS stg_lineitem;
CREATE TABLE stg_lineitem (LIKE fact_lineitem); -- 影子结构：列漂移防线（⚠️）
COPY stg_lineitem FROM 's3://.../etl/lineitem/' -- 分区目录/manifest（✅ etl 树实抓
  IAM_ROLE 'arn:aws:iam::...:role/redshift-cdk-load'  --  2020-08-15 dt= 路径族）
  REGION 'us-west-2' GZIP TRIMBLANKS ACCEPTINVCHARS;  -- 脏流三件套 ⚠️
DELETE FROM fact_lineitem USING stg_lineitem s
 WHERE fact_lineitem.orderkey = s.orderkey
   AND fact_lineitem.linenumber = s.linenumber;       -- 主键对：先删旧
INSERT INTO fact_lineitem SELECT * FROM stg_lineitem; -- 再插新：即 upsert
COMMIT;
-- （可选收尾）ANALYZE fact_lineitem; VACUUM fact_lineitem;  -- 统计与碎片（✅ r_ANALYZE/r_VACUUM）
```
坑位标注：DELETE 的 WHERE 必须有 DISTKEY 对齐的键，否则全节点广播删除（⚠️）；`LIKE` 复制表不带走编码/排序声明——影子表要 `LIKE ... INCLUDING DEFAULTS` 级别的心查（⚠️）。

## 核心概念速览（中英对照）

- 分布键 — DISTKEY：哈希分布对齐 JOIN 键、消灭跨节点重分布的手段
- 分布样式 — DISTSTYLE（KEY/ALL/EVEN/AUTO）：表级分布策略四式
- 排序键 — SORTKEY（COMPOSITE/INTERLEAVE）：1MB 块级剪裁的物化顺序
- 列编码 — column encoding（ENCODE AUTO）：列存压缩算法自动选择
- COPY 命令 — COPY：S3/DynamoDB 并行批量装载主通道
- 清单文件 — manifest：显式枚举 COPY 输入文件清单
- 暂存表合并 — staging table merge（delete+insert）：Redshift 式 upsert 正统
- 未排序区 — unsorted region：UPDATE/DELETE 后的碎片，VACUUM 对象
- AUTO COPY — AUTO COPY：装载队列化/并行化的系统托管模式
- SSB 基准 — Star Schema Benchmark：本章 DDL 所用星型负载
- Hive 风格分区 — `dt=` 分区路径：etl/ 样例的目录布局
- ANALYZE — ANALYZE：列统计/直方图采样供优化器
