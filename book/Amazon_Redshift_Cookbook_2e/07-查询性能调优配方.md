## 3. 深潜一：两类"慢"的分诊（⚠️ 转述）

- **等出来的慢**：查询在 WLM 队列排队（slot 满/优先级压制）→ 症状=开始时间晚、执行段不慢 → 处方在 08（队列/并发扩展）；
- **跑出来的慢**：进入执行后久——三大元凶：①重分布（DISTKEY 没对齐 JOIN 键，X1/X2/NONE 计划节点里现形）；②全扫+低剪枝（SORTKEY 错位/块统计失效）；③坏统计（歪曲的行数估计连锁错选 JOIN 序）→ 处方=本册 03 三要素+本节 ANALYZE/VACUUM 链；
- 自动时代的改口：RA3+ATO 下①②大量自动化（自动重排 sort、auto copy 编码），DBA 的新动作=**读 ATO 日志与 advisor 记录，而不是深夜手跑 VACUUM**（⚠️ 转述）。

## 4. 深潜二：MV 与 AutoMV（⚠️ 转述+✅ 锚）

- 手工 MV：`CREATE MATERIALIZED VIEW ... AUTO REFRESH YES`——刷新时机/成本要算"读放大 vs 重算成本"账（✅ MV 两锚同址 200）；
- AutoMV：系统观察重复子计划自动建/改写命中（2023+ 默认线；专页 302 登记 ⚠️）；
- 限制心法：MV 不保"新鲜度"——BI 口径要 SLA 时用编排显式刷新（→ 05 D4 节点），AUTO REFRESH 的触发时机文档口径为"负载合适时"（⚠️）。

## 5. 🔧 实测：预聚合 5× 与窗口去重 1.6×（本机真实跑过）

脚本 demo.py（D4/D5），DuckDB 1.5.5——**非 Redshift 行为，方言已按 DuckDB 改写**：
1. **D4（MV 账本，05 复用）**：5e6 基表聚合 14ms；2500 行日汇总读 0.76ms vs 基表滤段现算 4ms ≈ **5×**——"MV 值不值"=查询重复度函数，本例重复口径下一目了然；
2. **D5（去重两法）**：166.7 万行、按(orderkey,partkey,shipdate) 保 extendedprice 最大行——`row_number() OVER(...) rn=1` 子查询 **69ms** vs 历史惯用 max+自联 **113ms**（1.6×），**且后者语义不等价**（同组并列最大会翻倍，需再收敛一步）——Redshift 无 QUALIFY 语法，写法即前者（⚠️ 转述其窗口函数支持线）；
3. 诚实登记：Redshift 上两法的胜负手在计划是否触发重分布/落盘，数字不可平移，仅迁移"去重选窗口"的排序直觉。

## 6. 常见坑与最佳实践（⚠️ 转述+✅ 锚）

1. `EXPLAIN` 与 `EXPLAIN ANALYZE` 混用：前者不执行（估计可骗人），后者真跑（线上慎点）——先 STV/STL 找 Top-N 再 ANALYZE；
2. 谓词写列上函数（`date_trunc(col)=...`）废剪枝——改写为区间（✅ r_COPY 时代经典，Spectrum 同理 ✅ c-spectrum-considerations）；
3. `SELECT *` 在列存=放弃投影裁剪之利（TDG 04 的晚物化账本互证：[../Amazon_Redshift_TDG/04-数据转换策略.md](../Amazon_Redshift_TDG/04-数据转换策略.md) 🔧 4.5×）；
4. ANALYZE 时机：大批装载后立即（AUTO ANALYZE 兜底但有窗口期）——统计新鲜度=计划质量（✅ r_ANALYZE）；
5. 倾斜先体检：`SVL_QUERY_REPORT` 系看段间 skew（专页 302 登记 ⚠️；锚 r_STL_QUERY 同址 200 族内可检索）。

## 核心概念速览（中英对照）

- 查询计划 — query plan（EXPLAIN）：算子树与分布动作的说明书
- 重分布 — X1/X2/NONE：跨节点换行代价的三档记号
- 队列等待 — queue wait：WLM 排队时间（"等出来的慢"）
- 系统表账本 — STL_/SVL_/STV_：查询历史与瞬时状态的仓内日志
- AUTO ANALYZE — 自动统计：采样建直方图喂优化器
- VACUUM — VACUUM：回收未排序区、恢复排序键秩序
- 物化视图 — materialized view（AUTO REFRESH）：以写换读的预聚合
- AutoMV — 自动 MV：重复子计划的系统自建平替
- 谓词下推 — predicate pushdown：过滤进扫描端
- 投影裁剪 — projection/column pruning：列存只读所需列
- 倾斜 — skew：节点/段间数据量失衡
- 结果缓存 — result cache：同文查询直取上次结果（→08）
