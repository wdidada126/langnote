## 3. 配方一：Serverless 起步（⚠️ 转述 + ✅ 锚）

要点（Redshift Serverless，2024 语境）：
- 两个新对象取代"集群"心智：**namespace**（数据库与权限的容器）+ **workgroup**（算力入口），RPU（Redshift Processing Unit）计费，64 RPU 基步、按秒计费、闲置自动暂停（⚠️ 转述；✅ 语义锚 https://docs.aws.amazon.com/redshift/latest/mgmt/serverless-capacity.html 200）。
- CFN 模板关键参数：子网/安全组进入 VPC、workgroup 名、namespace 默认管理员——与预置集群"cluster+subnet group"一一对应但**不再选节点类型**（⚠️ 转述自官方入门线；✅ 入口 https://docs.aws.amazon.com/redshift/latest/mgmt/welcome.html 200）。
- 预置集群对照：RA3 节点 + managed storage（2019-12 起解耦存储与计算；DC2 本地盘族仍服务特定低延迟场景）（⚠️ 转述；✅ 版本/节点面 https://docs.aws.amazon.com/redshift/latest/mgmt/cluster-versions.html 200）。
- 选型口诀（重构自全章叙事）：突发/间歇负载→Serverless；稳定 7×24 大负载+预留折扣→预置 RA3（⚠️ 口径转述，两形态计费对比以官方页为准）。

## 5. 🔧 类比：psycopg2 兼容层与 sysdate 探针（本机真实跑过）

Redshift 驱动生态自称"PG 协议兼容"，本机以 DuckDB 1.5.5 演示"连接即探针"配方骨架（**非 Redshift 行为，方言已按 DuckDB 改写**）：DuckDB 无 sysdate，等价探针 `SELECT current_timestamp`；Python API `duckdb.connect()`→`execute(...).fetchone()` 五步即通——与 nb 中 6 行 psycopg2 样板一一对照可讲清"连接对象/游标/取密/探活/关断"五段式，唯一差异是 Redshift 需 `sslmode` 与 IAM 层（⚠️）。此骨架在本系列单机参照册 [../The_Definitive_Guide_to_SQLite_2e/00-总览与阅读地图.md](../The_Definitive_Guide_to_SQLite_2e/00-总览与阅读地图.md) 的 DB-API 节同构。

## 6. 常见坑与最佳实践（⚠️ 转述+✅ 锚）

1. **VPC 连通性**：Serverless workgroup 的子网须关联安全组+（私有子网时）NAT/端点，否则 Data API 之外一切直连超时——本系列通用网络常识（⚠️）。
2. **publicly-accessible ≠ 公网可连**：还需安全组入站放行 5439（⚠️ 转述）。
3. **凭据轮转**：Secrets Manager 托管 DB 密码后，应用侧取密要加缓存/重试，避免每查询一次 GetSecretValue（配额与延迟双坑）（⚠️ 工程惯例转述）。
4. **时区**：`SELECT sysdate` 返回 UTC；会话 `TIMEZONE` 可改，BI 端对账先统一 UTC（⚠️ 转述）。
5. CloudFormation 栈输出的 endpoint/port 是字符串拼接产物，跨栈引用用 `!Sub`——仓内 ch1/chapter_N 双 CFN 即示范此姿势（✅ 文件实抓）。

## 4d 配方演绎二：取密连接五段式（✅ 依仓内 notebook 实抓结构重构，非原书文本）

```python
# Redshift/psycopg2 姿势（⚠️ 转述示例；仓内 notebook 同款骨架 ✅）
import boto3, json, psycopg2
sec = boto3.session.Session().client("secretsmanager")
cred = json.loads(sec.get_secret_value(SecretId=secret_arn)["SecretString"])
con = psycopg2.connect(host=cred["host"], port=cred["port"], dbname=cred["dbname"],
                       user=cred["username"], password=cred["password"], sslmode="require")
cur = con.cursor()
cur.execute("SELECT sysdate")          # 探活：返回 UTC 当前时刻
print(cur.fetchall())
cur.close(); con.close()
```
五段=**取密→建连→开游标→探活→关断**；把 `sysdate` 换成 `SELECT 1` 亦通，选 sysdate 是 Redshift 方言指纹（PG 无此函数——一行代码同时验证"连通+是 Redshift"两件事，⚠️ 点评）。

## 核心概念速览（中英对照）

- 预置集群 — provisioned cluster：自选节点类型/数量的经典 Redshift 形态（RA3/DC2）
- 无服务器工作群 — Redshift Serverless workgroup：RPU 计费的弹性算力入口，与 namespace 配对
- 命名空间 — namespace：Serverless 下数据库、用户与权限的逻辑容器
- RPU — Redshift Processing Unit：Serverless 算力单位（4 vCPU+16GB 内存口径 ⚠️），按秒计量
- 密钥托管 — AWS Secrets Manager integration：把 DB 口令放密管服务、SDK 取密连接
- 临时凭据 — temporary credentials (GetClusterCredentials)：IAM 身份换取限时数据库用户凭据
- Data API — Data API：免 VPC 直连的 HTTPS JSON 查询接口，Lambda 友好
- JDBC/ODBC 驱动 — Redshift ODBC/JDBC drivers：BI 与应用侧标准接入层
- 参数模板 — parameter group：集群级会话变量集合（如启用/禁用结果缓存）
- 子网组 — subnet group：预置集群的 VPC 落点声明
- SSL 模式 — sslmode（require/verify-full）：驱动侧加密档位，verify-full 需 CA bundle
- CloudFormation 栈 — CFN stack：本册全部实验的资源编排载体（chapter_N_CFN.yaml）
