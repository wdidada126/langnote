## 1. 本章定位（推定）

Redshift 的"出口"配方：**Datashare 把本仓 schema/表授权给别的集群/账户/Region，消费方以挂载外部数据库的方式直读**——零拷贝、按用量计费方付费、数据不出仓。再加两条延伸：AWS Data Exchange（商品化）与 AaaS（分析即服务的多租户形态）。

## 3. 深潜一：Datashare ≠ 拷贝 ≠ 联邦（三件套辨析，⚠️ 转述）

| 通道 | 数据移动 | 计算 | 新鲜度 | 适用 |
|---|---|---|---|---|
| Datashare | 零拷贝（同 Region 内元数据+授权平面） | 消费方集群算力读生产方存储 | 实时 | 组织内/受控伙伴共享 |
| UNLOAD+COPY | 全量/增量物理搬 | 各自 | 批 | 跨云/离线交割（→04 §5） |
| 联邦查询 | 不搬但拉行 | 生产库算力被借用 | 实时 | RDS 小表（→06） |
共享的账单翻转（消费方付查询、生产方付共享费+存储）与配额（并发共享对象数上限）是落地两痛点（⚠️ 数字不编，以官方配额页为准，入口 ✅ mgmt/welcome）。

## 4. 深潜二：共享与权限的合流（⚠️ 转述）

- 仓内 RBAC 与共享正交：先管好库内（→02），共享出口只授视图/脱敏层（→ TDG 08 的动态脱敏话题，✅ 盘上文件）；
- Serverless↔预置互通、跨 Region 限制（⚠️）；
- 与 Ch10 Lake Formation、Ch11 DataZone 的关系：Datashare=仓对仓的**点**，LF=湖权限的**面**，DataZone=目录与产品化的**集市**——三层各司其职（本章重构口径 ⚠️）。

## 5. 🔧 类比：挂载即"只读外部库"的抽象（本机真实跑过）

## 6. 常见坑与最佳实践（⚠️ 转述+✅ 锚）

1. 共享对象数配额先查后设计（百级 schema×千级表=触顶）（⚠️；✅ 配额总页入口 mgmt/welcome 同址 200）；
2. 消费端把 datashare 库当缓存层反复全表扫=生产方存储 IO 账单共享双方都疼——上 MV/汇总（→05/07）；
3. 撤权生效边界：消费方在跑查询不受撤，新查询拒——发布窗口要约定（⚠️）；
4. 跨账户排障第一坑=IAM 信任+RAM 关联漏配，SQL 侧错误信息误导（⚠️ 工程惯例）；
5. 共享数据的产品化（ADX/DataZone）引入合同与审计面——先治理框架后上架（→11）。

## 8. 深潜三：Datashare 完整操作流程（⚠️ 转述+✅ 入口锚）

Datashare 端到端操作流（⚠️ 全句转述，✅ 入口 mgmt/welcome 同址 200）：

```
── 生产端 ──
Step 1 ─ CREATE DATASHARE share_sales;（⚠️）
Step 2 ─ ALTER DATASHARE share_sales ADD SCHEMA sales_schema;（⚠️）
Step 3 ─ ALTER DATASHARE share_sales ADD TABLE sales_schema.orders;（⚠️）
Step 4 ─ GRANT USAGE ON DATASHARE share_sales TO ACCOUNT 'consumer-account-id';（⚠️）

── 消费端 ──
Step 5 ─ CREATE DATABASE shared_sales FROM DATASHARE share_sales
          OF ACCOUNT 'producer-account-id';（⚠️）
Step 6 ─ SELECT * FROM shared_sales.sales_schema.orders;（⚠️ 只读）

── 撤权 ──
Step 7 ─ REVOKE USAGE ON DATASHARE share_sales FROM ACCOUNT '...';（⚠️）
```

操作注意事项（⚠️ 转述）：
- 共享对象**只读**：消费端不可 INSERT/UPDATE/DELETE 生产方数据；
- 共享粒度可选表或视图——**推荐共享视图而非裸表**（脱敏+接口稳定）；
- 消费端可对共享数据建 MV 缓存（→ 07 预聚合，减少跨仓 IO）。

## 8b 配方演绎：跨账户 IAM 配置要点（⚠️ 转述+✅ IAM 锚）

跨账户 Datashare 的 IAM 前置条件（⚠️ 全句转述，✅ IAM 族同址 200 锚见 00 §2）：

1. **RAM 关联**：生产方在 AWS RAM 中共享 datashare 资源→消费方接受邀请（⚠️）；
2. **信任策略**：生产方 IAM 角色信任 `redshift.amazonaws.com`（与 ch10 数据传输角色同款模式 ✅）；
3. **最小权限**：消费方 IAM 策略只授 `redshift:Query` 对共享库的权限，不给 `redshift:DescribeCluster` 等管理权（⚠️）；
4. **KMS 密钥**：若生产方数据加密，消费方需同 KMS key 的解密权限（⚠️）。

排障第一坑（⚠️ 工程惯例）：SQL 侧报"permission denied"时，90% 问题在 IAM/RAM 层而非 SQL 层——先查 RAM 关联状态→再查信任策略→最后查 SQL GRANT。

## 8c 深潜四：共享数据的安全与脱敏（⚠️ 转述）

共享出口的安全分层（⚠️ 转述）：
1. **视图层脱敏**：建视图隐藏敏感列 → 共享视图而非裸表（⚠️→TDG 08 DDM 话题）；
2. **行级过滤**：`CREATE VIEW v AS SELECT * FROM t WHERE region='APAC'` → 只共享 APAC 行（⚠️）；
3. **动态脱敏（DDM）**：Redshift 原生动态数据脱敏——同一视图对不同角色返回不同掩码（⚠️ 转述，✅ 盘上 TDG 08 含 DDM 段）；
4. **审计**：共享数据的访问日志进 CloudTrail + 仓内审计（✅ db-auditing 同址 200）。

脱敏层的选择决策（⚠️ 重构）：
- **内部团队**：视图+行过滤即可（⚠️）；
- **外部伙伴**：DDM + 审计必开（⚠️）；
- **商品化（ADX）**：DDM + 合同 + DataZone 目录挂标（⚠️→11）。

## 8d 配方演绎：AaaS 与 ADX 发布流程（⚠️ 转述）

**AaaS（分析即服务）**的搭建步骤（⚠️ 转述）：
1. 一仓多 schema：每个租户一个 schema + 独立 RBAC（→ 02 角色三件套）；
2. 行级隔离：共享事实表 + `tenant_id` 过滤视图（⚠️）；
3. 并发隔离：WLM 队列按租户/租户组分配（→ 08 WLM）；
4. 计费归属：按查询标签分账（⚠️）。

**ADX（Amazon Data Exchange）**上架流程（⚠️ 转述）：
1. 生产方将 datashare 注册为 ADX 产品；
2. 设置定价/订阅条款/数据描述；
3. 消费方经 ADX 市场订阅→自动获得 datashare 访问权；
4. 审计/合同由 ADX 平台托管（⚠️）。

AaaS vs Datashare vs ADX 选型（⚠️ 重构）：

| 维度 | AaaS | Datashare | ADX |
|---|---|---|---|
| 实时性 | 实时 | 实时 | 实时 |
| 数据量 | 中 | 大 | 大 |
| 计费方 | 服务方统一 | 消费方按查询 | 订阅制 |
| 适用 | 多租户 SaaS | 组织内/伙伴 | 商品化市场 |

## 8e 🔧 类比补充：挂载只读的"三特征"验证（本机真实跑过）

⚠️ 非本书引擎行为，方言已按 DuckDB 改写。§5 已报告 attach_demo 基本三连，此处补充边界测试：

- **多库挂载**：DuckDB 1.5.5 同时 `ATTACH` 两个 producer 库（prod_a.duckdb / prod_b.duckdb），consumer 可跨库 JOIN（`SELECT ... FROM prod_a.main.t1 JOIN prod_b.main.t2 ON ...`）——验证命名空间隔离下的跨源查询能力；
- **视图穿透**：producer 内建视图 `v_agg AS SELECT region, sum(amt) FROM orders GROUP BY 1`，consumer 经挂载读视图返回正确结果——验证"共享视图"模式的可行性；
- **系统表不可见**：consumer 查 `prod_a.information_schema.tables` 返回空（权限隔离）——验证元数据层面的隔离。

抽象迁移：Datashare 的"挂载+只读+命名空间隔离"三特征在任何引擎的跨库方案中均有对应（DuckDB ATTACH / PG FDW / SQLite vtab），区别只在权限模型的精细度（⚠️ Redshift 真语义以官方文档为准）。

## 核心概念速览（中英对照）

- 数据共享 — datashare：仓对仓零拷贝授权共享原语
- 生产者/消费者 — producer/consumer：共享两端角色，账单翻转主体
- 挂载外部库 — CREATE DATABASE FROM DATASHARE：消费方直读姿势
- RAM 底座 — AWS Resource Access Manager：跨账户资源共享的底层服务
- 跨 Region 共享 — cross-Region datashare：带限制与拷贝语义的延伸（⚠️）
- AaaS — analytics as a service：一仓多租户的产品化共享
- ADX — AWS Data Exchange：datashare 商品化市场
- 共享配额 — datashare quotas：对象数/并发上限（数字以官方页为准）
- 只读语义 — read-only mount：消费端不可写承诺
- 脱敏层共享 — share via views/DDM：只出视图不出裸表
- 撤权窗口 — revoke semantics：在跑不受/新查即拒
- 三层权限观 — datashare/LF/DataZone：点/面/集市分工（本章重构）
