## 2. 向量索引：2025-26 的最大增量 ✅ 实抓

- 官方文档新页 VectorSearch.html（HTTP 200，2026-09-27）：条目属性存向量→建**向量索引**→ `SearchVectors` API 做 **ANN** 检索；距离函数页内见 COSINE/EUCLIDEAN（另有 dot product 口径 ⚠️ 未逐一摘录）。
- API 面：APIReference `SearchVectors` 页 200 ✅——检索是独立动词，**不占 RCU 口径的旧计费叙事** ⚠️ 计费细则未取页证，谨慎转述。
- 定位辨析：DynamoDB 向量索引=「KV 表顺手做相似检索」，替代不了专用向量库的召回率/索引工程调优——对位盘上 [../Vector_Databases/00-总览与阅读地图.md](../Vector_Databases/00-总览与阅读地图.md)（ANN 索引结构与其 04 章哈希/量化域正是 Dynamo 黑盒掉的那部分）与 [../Elasticsearch_The_Definitive_Guide/00-总览与阅读地图.md](../Elasticsearch_The_Definitive_Guide/00-总览与阅读地图.md)（检索生态位对照）。
- 建模新张力 ⚠️：向量把「非键自由查询」合法化回来——02 章「没建键≈全扫」的铁律出现官方豁免口；单表叙事（06 章）需为嵌入属性划新边界。

## 8. 全册 🔧 类比复跑指南（本目录的「可执行附录」）

前提：Python 3.13.2（内置 sqlite3 3.45.3）+ pip 环境装 DuckDB 1.5.5；工作目录 `D:\develops\tmp\dbwave_w4_dyn\`（repo 外，工程纪律）。

- 类比一（02 章聚类）：建 `forum` WITHOUT ROWID 复合主键表 → 灌 200k → 跑「PK 前缀范围 ×200」与「仅 SK 定位」对照计时 + EXPLAIN QUERY PLAN。
- 类比二（04 章 GSI/SQLite）：`forum` → 同表全量 INSERT 灌 `gsi_sk_first(sk,pk)` → SK 前缀范围 ×200 扇出计时。
- 类比三（04 章 DuckDB）：`ev` 200k 行主表 + `ev_gsi` 投影表 → 基表键范围查 vs 索引表定值探测。
- 类比四（05 章计费算术）：抽样平均条目字节 → `math.ceil(size/4096)` 出 RCU 颗粒表（226B→1、400KB→100）。
- 类比五（06 章宽行税）：`items` 表 400KB vs 极小行，逐新连接 PK 点查 20 次取中位（0.06ms vs 0.36ms）。
- 统一声明：五组实验只证「键布局→访问代价」因果方向，与 DynamoDB 的哈希分区/计费/复制语义无实现关系——引用时必须带「非 DynamoDB 行为」尾缀。
