# 09 · 安全、加密与运维：托管不等于免责（⚠️ 重构章题）

> 章定位：全托管取消的是 SRE 工时，不是责任边界——IAM 键策略、加密选项、备份恢复、TTL、指标告警仍归你。取证锚：TTL.html ✅200、BackupRestore/ContinuousBackups/encryption/access-control 页 302 版本跳转 ⚠️ 存目可引。

## 1. IAM：DynamoDB 的权限是「键空间的艺术」⚠️ 转述（✅ access-control 主题域）

- 资源粒度：表与 GSI/LSI 同为可授权资源；condition 可锁到分区键值（如 `dynamodb:LeadingKeys` 实现「租户只见自己」）⚠️ 通识转述。
- 数据面与控制面分离：`dynamodb:GetItem` vs `dynamodb:DescribeTable` 两组动词，网关与运维角色分开设计 ⚠️。
- 常见事故：通配符放开 `dynamodb:*`、条件写遗漏导致越权覆盖（03 章乐观锁的另一面）⚠️。

## 2. 加密：默认开、密钥选谁 ⚠️ 转述（✅ 302 主题页存目）

- 静态加密默认开启；AWS-owned 密钥免管、客户管理 KMS 密钥（CMK）带来审计与吊销控制、成本按 API 计 ⚠️。
- 传输 TLS 强制策略（`aws:SecureTransport` condition）为社区基线 ⚠️。
- VPC Endpoint（网关终端节点）让 Lambda/子网访问 DynamoDB 不出私网 ⚠️ 转述。

## 3. 备份家族：快照、PITR、导出/导入

- **按需备份（on-demand backup）**：全表即时快照，保留至手动删除，恢复=还原新表（命名快照不阻塞写）⚠️ 转述（✅ BackupRestore 域）。
- **PITR 连续备份**：默认 35 天内任意秒级恢复 ⚠️（数字为社区通识，页 302 未静态证）；与按需备份互补：PITR 防手滑、快照防灾难。
- **Data Export / Data Import**：表→S3（Parquet 类）直连导出、S3 批量导入——数仓落地与冷归档的官方管道 ⚠️ 格式细节转述。
- 恢复语义陷阱：跨区域/PITR 恢复后 Global Tables 拓扑需重建，Streams 位点归零 ⚠️（07/08 章衔接）。

## 4. TTL：最便宜的容量管理

- 属性列存 Unix 秒时戳、服务后台扫描删除、过期不可逆、删除不计 WCU 口径 ⚠️/✅ 混合（✅ TTL 页 200 在架，细则转述）。
- 用途：会话/令牌/时序临时态；**不是备份替代**——TTL 删除与 PITR 恢复窗口冲突时以 PITR 为准 ⚠️。
- 监控点：TTL 状态（ENABLED/DISABLED）与待过期计数 ⚠️。

## 5. 可观测性清单 ⚠️ 方法论

- CloudWatch：ConsumedRCU/WCU、ThrottledRequests、SystemErrors、GlobalTables 复制滞后（05/08 章指标在此收口）。
- Contributor Insights：热点键 top-N（表/索引维度）⚠️。
- 告警基线：Throttled>0 即容量或布局有问题（05 章）；Consumed 逼近 80% 配额触发伸缩审查 ⚠️。
- 数据审计：CloudTrail 管 API 面、Streams 管数据面（07 章）——两轨并记才算全 ⚠️。

## 7. 合规与数据驻留 ⚠️ 转述

- 表级区域选择=数据驻留第一道墙；KMS 区域隔离与跨区复制的驻留冲突（Global Tables 数据全域可见）需在方案评审显式声明 ⚠️（08 章联动）。
- 个人数据删除义务 vs TTL/PITR 交互：PITR 窗口内的「删除」可被恢复复活——合规删除要按官方流程（恢复+删除+再快照）⚠️ 通识。

## 8. 最小权限策略草图（概念 JSON，非可部署文本 ⚠️）

```json
{
  "Effect": "Allow",
  "Action": ["dynamodb:GetItem", "dynamodb:Query", "dynamodb:UpdateItem"],
  "Resource": [
    "arn:aws:dynamodb:REGION:ACCT:table/AppSession",
    "arn:aws:dynamodb:REGION:ACCT:table/AppSession/index/*"
  ],
  "Condition": {
    "ForAllValues:StringEquals": {
      "dynamodb:LeadingKeys": ["${aws:PrincipalTag/tenantId}"]
    }
  }
}
```
- 要点逐行：数据面动词白名单；表与索引同批授权（GSI 漏授=隐性断流 ⚠️）；LeadingKeys 把「租户隔离」写进 IAM 而非应用 if（02 章「键即权限边界」的落点）。
- 反例登记 ⚠️：`dynamodb:*` + `Resource:"*"` 的教学文与脚手架默认值，是渗透测试报告常客。

## 9. 巡检与演练清单 ⚠️ 方法论

- 周检：ThrottledRequests 非零项归因（05 章四问）；TTL 表过期堆积曲线；索引 INDEX_STATUS 异常。
- 月检：备份可达性抽验（快照还原到隔离账户跑 diff ⚠️）；KMS key 轮换状态；IAM 策略 diff 审计。
- 季演：区域摘除（08 章回切剧本）；误删恢复（PITR 窗口实跑）；限流风暴（压测触发 400 退避验证）。
- 变更闸：新表进生产前需带「访问模式-键-索引-费用」四栏表（06 §8-10）+ 告警阈值 PR——没有表的 SLO 就没有表的运维。

## 11. 一句话记忆卡

- 托管取消的是 SRE 工时，不是责任边界——IAM/备份/驻留仍签名在你名下 ⚠️。
- 键即权限边界：LeadingKeys 是 DynamoDB 送的多租户最小权限快车道 ⚠️。
- 快照防天灾、PITR 防手滑、TTL 防膨胀——三件套各管一段时光 ⚠️✅。
- 删除的合规难点不在删，在「备份让死者复活」（§7）。
- 指标的三分法：消耗（花钱）、限流（撞墙）、滞后（跨区欠债）（05/08 联动）。
- 没带四栏表的表不许进生产；没做过恢复演练的备份不算备份（§9 收口）。

## 12. 记忆卡补三行

- 表、索引、区域、密钥四级资源都要名字：权限、成本、恢复的粒度全同构（04/08/09 联动）。
- 备份的价值=上次演练通过的还原；此句应印在恢复预案首页 ⚠️。
- 托管服务的「默认安全」只到加密为止：到「合规」还差你写的策略、演练、台账。

## 核心概念速览（中英对照）

1. **LeadingKeys 条件** — partition-key scoping：租户级最小权限的原生杠杆 ⚠️。
2. **控制面/数据面动词** — control/data plane actions：Describe 与 Get/Put 分权 ⚠️。
3. **CMK** — customer master key：客户管理密钥，审计与吊销自主 ⚠️。
4. **VPC 终端节点** — gateway endpoint：私网直连 DynamoDB ⚠️。
5. **按需备份** — on-demand backup：全表快照、手动删 ⚠️（✅ 主题域）。
6. **PITR** — point-in-time recovery：窗口内秒级回放 ⚠️。
7. **Data Export/Import** — S3 双向批量管道 ⚠️。
8. **TTL** — time to live：按秒时戳后台清除 ✅ 页 200。
9. **贡献者洞察** — Contributor Insights：热点键排行 ⚠️。
10. **ConsumedRCU** — 消耗读容量：容量与布局双线告警主指标 ⚠️。
11. **数据驻留** — data residency：区域选择即合规边界 ⚠️。
