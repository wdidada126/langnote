# 第 15 章 亿级高并发 IM 架构与实战（卷1）

> 把前 14 章升到「亿级」：长连接网关（接入层）、逻辑层、路由层（用户→连接所在网关）、消息可靠投递（ACK/重投/去重）、离线消息、读扩散/写扩散、水平扩展。本书收尾，是从「单体 IM」到「分布式 IM」的跃迁。

## 一、本章地图

| 层 | 职责 |
| --- | --- |
| 接入层 | 长连接网关（Netty/WebSocket），持 fd |
| 路由层 | userId→网关节点 映射（Redis） |
| 逻辑层 | 消息处理/群/好友 |
| 存储 | 消息落库 + 离线 |
| 可靠投递 | ACK + 重投 + 去重 |

## 二、核心精讲

### 2.1 🔧 连接与逻辑分离
- 网关只管长连接（海量 fd），消息经 MQ 发到逻辑层（🔧 网关无状态可水平扩；用户重连可能落不同网关，靠路由层 Redis 定位）。

### 2.2 可靠投递（至少一次）
- 发送→服务端落库→推+ACK；未 ACK 定时重投；接收端按 `msgId` 去重（🔧 至少一次 + 去重 ≈ 精确一次；seq 防乱序）。

### 2.3 写扩散 vs 读扩散
- **读扩散**（收件箱模式）：群发写一份，成员读时拉（🔧 大群友好，存少）；**写扩散**：群发每人一份（🔧 小群实时好，大群写爆）；超大群用「写扩散+读扩散混合」。

- 论文/文献：Lamport 逻辑时钟（1978，消息排序）；CAP（Brewer 2000）；IM 架构多参考微信/钉钉公开分享。
