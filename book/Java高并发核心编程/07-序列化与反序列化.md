# 第 7 章 序列化与反序列化：JSON 和 Protobuf（卷1）

> 序列化选型：JSON（可读但慢大）、Protobuf（紧凑高效、跨语言）、Hessian（Java RPC 友好）、Kryo（快但需注册）、Serialization（JDK 原生，慢且安全差）。本书独有「Protobuf 编解码 + 跨语言」实战。

## 一、本章地图

| 格式 | 特点 |
| --- | --- |
| JSON | 可读、跨语言、体积大、慢 |
| Protobuf | 二进制、schema、紧凑快、跨语言 |
| Hessian | Java RPC 常用、二进制 |
| Kryo | 极快、需注册、非跨语言 |
| JDK Serial | 慢、安全漏洞多、别用 |

## 二、核心精讲

### 2.1 🔧 选型建议
- **跨服务/跨语言**：Protobuf/FlatBuffers（🔧 gRPC 默认 Protobuf；FlatBuffers 零拷贝读取，游戏/高频用）。
- **Java 内部 RPC**：Hessian/Kryo（Dubbo 默认 Hessian2，可换 Kryo/Fastjson 危险）。
- **禁用 JDK `Serializable`**：攻击面大（🔧 反序列化 gadget chain：CommonsCollections 等）。

### 2.2 Protobuf 原理
- `.proto` 定义 schema，varint + tag 编码，字段可缺省向后兼容（🔧 比 JSON 体积小 3-10×、序列化快 5-20×）。
