# 第 10 章 协作开发（原书 pp.约 329–370）

> 条目 82–90。模块发现、虚拟环境、docstring、包结构、根异常、打破循环依赖、warnings、typing 静态分析。

## 本章地图

| 条 | 标题 | 结论 |
|---|---|---|
| 82 | 学会寻找他人构建的模块 | PyPI / 先搜后造 |
| 83 | 用虚拟环境隔离项目、重建依赖 | venv + 锁定文件 |
| 84 | 每个函数/类/模块都写 docstring | 文档即契约 |
| 85 | 用包安排模块，提供稳定 API | `__init__.py`/`__all__` 控制导出 |
| 86 | 用模块级代码配置部署环境 | 配置按环境切换，别散落常量 |
| 87 | 为模块定义根异常 | 调用者可专门捕获 API 异常 |
| 88 | 用适当方式打破循环依赖 | 重排导入/延迟导入/依赖注入 |
| 89 | 重构时用 warnings 提醒 API 变化 | `DeprecationWarning` 平滑迁移 |
| 90 | 用 typing 做静态分析消除 bug | `mypy`/`pyright` 抓类型错 |

## 核心精讲

```python
# 教学示意，不参与构建
# 条目 83：venv
#   python -m venv .venv && source .venv/bin/activate
#   pip install -r requirements.lock

# 条目 85：包与 __all__
# mypkg/__init__.py
__all__ = ["PublicApi"]
class PublicApi: ...

# 条目 87：根异常
class MyApiError(Exception):
    """本模块所有异常的基类。"""
class NetworkError(MyApiError): ...

# 条目 88：打破循环依赖——延迟导入
def handler():
    from .models import User      # 函数内导入，避免顶层循环
    ...

# 条目 89：DeprecationWarning
import warnings
def old_api():
    warnings.warn("old_api 已废弃，改用 new_api",
                  DeprecationWarning, stacklevel=2)

# 条目 90：typing
from typing import Optional
def process(x: int) -> Optional[str]:
    ...
```

## 版本演进

- 3.6：变量注解（PEP 526）、`typing` 模块成型（条目 90）。
- 3.8：`typing.Protocol`（PEP 544）结构化子类型；`typing.get_args` 等。
- 3.10：`X | Y` 联合类型（PEP 604），取代 `Optional[X]` 写 `X | None`。
- 3.12：PEP 695 类型参数语法（`type T = ...` 声明类型别名，函数可在 `def` 头部写独立类型形参）；PEP 649 注解延迟求值。
- 🔧 3.13+：`typing` 仍在演进，`TypeVarTuple`/`ParamSpec` 已稳定。

## 经典论文与原始文献

- PEP 8 — docstring 规范（条目 84）；`numpy`/`Google` docstring 风格流行。
- PEP 404 — 不再支持 `python -m ensurepip` 旧路径（🔧 以文档为准）。
- PEP 544 — Protocol（条目 90 结构化子类型）。
- PEP 604/695 — 联合类型/类型参数语法（条目 90 现代注解）。
- `warnings` 文档（条目 89）。

## 近年研究与工业界开源实践（2015–2026）

- `uv`（2024，Astral）取代 `pip`/`venv`/`pip-tools`/`poetry` 部分职责，极快；条目 83 的现代工具。
- `pyproject.toml`（PEP 518/621）取代 `setup.py`，统一构建与依赖声明。
- `mypy`/`pyright`/`ruff` 构成「类型 + lint」静态防线，条目 90 已成工程标配。
- 依赖锁定：`pip-tools`/`uv lock`/`poetry.lock`。

## 常见误区与本书需修正之处

| 误区 | 修正 |
|---|---|
| 把依赖写进全局 site-packages | 条目 83：每个项目独立 venv，提交锁定文件 |
| 顶层循环导入 | 条目 88：优先重构为依赖注入，其次延迟导入 |
| typing 全用 `Any` | 条目 90：失去静态检查意义，逐步收窄类型 |
| 用 `print` 做废弃提示 | 条目 89：用 `warnings.warn(DeprecationWarning, stacklevel=2)` |
| docstring 只写「做什么」 | 条目 84：写清参数/返回/异常/副作用 |
