# 第 9 章 测试与调试（原书 pp.约 300–328）

> 条目 75–81。repr 调试、unittest 组织、Mock 隔离依赖、pdb 交互、tracemalloc 内存。

## 本章地图

| 条 | 标题 | 结论 |
|---|---|---|
| 75 | 通过 repr 字符串输出调试信息 | 类实现 `__repr__`，日志更易读 |
| 76 | 在 TestCase 子类里验证相关行为 | 按行为而非函数组织测试 |
| 77 | 用 setUp/tearDown 等防用例互相干扰 | 准备/清理逻辑集中，隔离状态 |
| 78 | 用 Mock 模拟复杂依赖 | 隔离外部服务/慢调用 |
| 79 | 把依赖系统封装起来便于 Mock | 依赖注入让测试可替换 |
| 80 | 用 pdb 做交互调试 | `breakpoint()`（3.7+）断点 |
| 81 | 用 tracemalloc 掌握内存使用与泄漏 | 追踪分配来源，定位泄漏 |

## 核心精讲

```python
# 教学示意，不参与构建
# 条目 75：__repr__
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __repr__(self):
        return f"Point(x={self.x}, y={self.y})"

# 条目 76/77：unittest
import unittest
class TestCalc(unittest.TestCase):
    def setUp(self):
        self.calc = Calculator()
    def test_add(self):
        self.assertEqual(self.calc.add(1, 2), 3)

# 条目 78：Mock
from unittest.mock import Mock, patch
api = Mock(return_value={"ok": True})
with patch("module.api_call", api):
    result = do_work()

# 条目 80：breakpoint（3.7+）
def buggy(x):
    breakpoint()           # 进入 pdb
    return x + 1

# 条目 81：tracemalloc
import tracemalloc
tracemalloc.start()
# ... 运行 ...
snapshot = tracemalloc.take_snapshot()
top = snapshot.statistics("lineno")
```

## 版本演进

- 3.7：`breakpoint()` 内建（PEP 553），条目 80 不再手写 `import pdb; pdb.set_trace()`。
- 3.8：`unittest.mock.AsyncMock`（PEP 570 相关）支持异步 Mock。
- 3.0+：`__repr__` 仍是最佳调试实践（条目 75）。

## 近年研究与工业界开源实践（2015–2026）

- pytest 已成事实标准，替代手写 unittest 样板（fixture/parametrize 比 setUp/tearDown 更灵活）。
- `pytest-mock`/`freezegun`（时间）/ `responses`（HTTP）成测试三件套。
- 覆盖率：`coverage.py` + `pytest-cov`；类型检查 `mypy` 补静态测试缺口。

## 常见误区与本书需修正之处

| 误区 | 修正 |
|---|---|
| 手写 `pdb.set_trace()` | 条目 80：用 `breakpoint()`，可经 `PYTHONBREAKPOINT` 禁用 |
| 测试间共享状态 | 条目 77：用 setUp/tearDown 或 fixture 隔离，避免顺序依赖 |
| Mock 整个模块 | 条目 79：只 Mock 依赖边界，别 Mock 被测逻辑 |
| `__repr__` 返回非求值形式 | 条目 75：理想 `__repr__` 应能被 `eval` 重建（除非不可行） |
