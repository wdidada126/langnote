# 概念专篇：赋值表达式与推导优化（条目 10、29）

> 海象运算符 `:=`（PEP 572，3.8）在推导与循环里的取舍。本篇独立于章节正文，深入条目 10（减少重复代码）与条目 29（消除推导重复）。

## 一、为什么需要 `:=`

推导与 `while` 里常需「先算一个值，再判断，再用它」三步。没有 `:=` 时只能重复计算或抽成辅助函数：

```python
# 教学示意，不参与构建
# 没有 :=：重复调用昂贵的 get_data
results = [get_data(x) for x in xs if get_data(x) is not None]
# 缺陷：get_data 被调两次

# 有 :=：只算一次
results = [d for x in xs if (d := get_data(x)) is not None]
```

## 二、在 while 循环里包住条件

```python
# 逐行读，直到空行
while (line := f.readline()):
    process(line)
```

## 三、可读性边界（重要）

条目 10 强调「仅当同一子表达式需复用两次才值得」。反例：

```python
# 可读性差：把本该拆函数的一行塞进 :=
return [(y := f(x)) + g(y) for x in xs if (y := f(x)) > 0]   # 不推荐
# 更好：抽函数
def step(x):
    y = f(x)
    return (y + g(y)) if y > 0 else None
```

## 四、与生成器/itertools 的协作

当推导里 `:=` 超过两层，条目 28（[../04-推导与生成.md](../04-推导与生成.md)）建议改用生成器函数 + `itertools`。`itertools` 本身不需要 `:=`，例如 `itertools.chain` 拼接、`itertools.takewhile` 等价于「带条件的惰性切片」。

## 五、3.12+ 的 f-string 关联

PEP 701（3.12）放宽 f-string 后，调试可写 `f"{d=}"` 直接输出「d=<值>」，与 `:=` 配合：`f"{(d := get_data(x))=}"`。

## 六、常见误区

| 误区 | 修正 |
|---|---|
| 用 `:=` 偷懒压行 | 可读性优先；压行换来维护成本是亏的 |
| 在推导里 `:=` 同时改外部可变状态 | 副作用难追踪，违背推导「纯变换」直觉 |
| 忘了 3.8 以下不支持 | 目标环境 <3.8 时退回辅助函数（🔧 以运行环境为准） |
