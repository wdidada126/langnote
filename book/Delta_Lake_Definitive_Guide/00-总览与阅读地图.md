## 阅读路径建议

- **主线 A（机制派，推荐）**：01 → 02 → 04 → 07 → 09。
  从「事务日志怎么提交」走到「DV/CDF 改变了什么」，最后落到性能。
  读 02 时对照 [../mysql/19-redo日志.md](../mysql/19-redo日志.md)：Delta 的 commit 文件承担的角色很像 redo + 元数据 binlog 的合体，但恢复策略完全不同（无 WAL，靠日志重放元数据）。
- **主线 B（管道派）**：01 → 02 → 06 → 08 → 10 → 12。
  适合做流式湖仓的工程师：写入 → 流读流写 → medallion 分层 → CDC/SCD → 共享。
- **主线 C（治理派）**：03 → 11 → 12。
  生态与 catalog 在前，UC 治理与血缘居中，Delta Sharing 收尾。
- **进阶**：05（Kernel/delta-rs）适合要给非 JVM 引擎接 Delta 的人，可跳读。
