## 核心概念速览（中英对照）

- **常规操作集** — conventional operations：拷贝/移动/析构/比较/swap 的"全家福"
- **浅拷贝 vs 深拷贝** — shallow / deep copy：按位复制 vs 连资源一起复制，默认是前者
- **拷贝赋值自清理** — self-assignment safety：`x=x` 不能毁灭对象（先取副本再换）
- **转换构造与 explicit** — conversion constructor / explicit：单参构造=隐式转换，`explicit` 上锁
- **成员初始值设定项** — in-class initializer / NSDMI：类内默认值，构造列表可覆盖
- **移动语义** — move semantics：窃取资源而非复制，源对象进入"可析构的空平衡态"
- **右值引用** — rvalue reference（`T&&`）：绑定将亡值的通道，移动的语法入口
- **移动操作不得抛** — move noexcept：不抛则 vector 扩容敢移动，否则退回头拷贝
- **Rule of Zero/Five** — 零法则/五法则：能用标准组件就不手写；手写就凑齐五件
- **资源管理即所有权** — ownership：谁 new/开/锁，谁负责释放——"new 后不 delete 是 bug"
- **比较运算与全序** — total ordering / `<=>` 前身：导学要求每个类型有 `==` 与序关系
- **哈希与 equal 的一致性** — hash / std::hash：`a==b` 则 `hash(a)==hash(b)`，unordered 容器铁律
- **swap 免费化** — swap：移动语义落地后"三行模板全类型通吃"
- **用户自定义字面值** — user-defined literals：`operator""_km` 式的量纲/领域字面量（书例含单位换算风格）

## 动机：类型的"社会契约"

第 2、4 章造类型，第 5 章讲**类型的社交礼仪**：一个值要能被拷贝、被移动、被比较、被换出、
被安全地埋葬。Stroustrup 的叙事顺序值得玩味——先讲"每个操作怎么写对"，
再告诉你"最好一个都别写"（零法则），因为**默认值的正确性来自成员的默认值**：
vector 里装 `unique_ptr` 自动得到"移动容器"。

## 机制：从拷贝到移动的三级台阶

1. **拷贝**（§5.2.1）：陷阱集中在两处——自赋值（`Matrix& operator=(const Matrix& m)`
   的"先抢后删"顺序会自杀，正解是先拷到局部再 swap）与**浅拷贝默认值**
   （裸指针成员的默认拷贝 = 两个对象管一块内存 = double free）。
2. **移动**（§5.2.2）：`Vector(Vector&& v) : p{v.p}, sz{v.sz} { v.p=nullptr; v.sz=0; }`——
   移动=资源过户+原主"挂空"。导学强调移动操作**必须 noexcept**，否则标准库宁可用拷贝；
   这与第 13 章 `vector` 扩容行为直接挂钩。
3. **资源管理**（§5.3）：本节是第 13 章智能指针的"问题申报书"——
   "new 出来的东西在异常路径上谁来 delete？"答案：让对象替你 delete（RAII）。

🔧 实测（g++ 15.2，三档 `-std=c++17/20/23`）：本会话反复用于校准的
`Pair`/`Vector` 式移动构造与 CTAD 示例在三档均通过（移动是 C++11 常数）；
而 **constexpr 里的 `new/delete`**（"移动进编译期"的延伸）：
`constexpr int f(){ int* p=new int(3); int v=*p; delete p; return v; } static_assert(f()==3);`
在 c++17 **失败**、c++20/23 **通过**——P0784R7《More constexpr containers》
（[wg21.link/p0784](https://wg21.link/p0784) 实测可跳转）的字节级实证。

## 课堂问答（自读后对答案）

1. **问：** 为什么"移动操作不得抛"几乎是硬规矩而不只是建议？
   **答：** 移动常被塞进强保证的容器操作（扩容/swap）里：一旦可抛，异常安全契约
   要求回滚，而"已搬走一半"没法回滚——标准库的直接反应是退回拷贝（成本×N），
   或者你收获一个 terminate 路径。
2. **问：** 单例式 `T& operator=(T&&)` 里为什么必须 `if (this != &rhs)`？
   **答：** 自移动：先 `delete[] p` 再 `p = rhs.p` 时 rhs.p 已被自己释放——
   经典的"自己拆自己"。移动赋值和拷贝赋值共享同一条自清理纪律（§5.2.1）。
3. **问：** `std::hash<MyType>` 不特化会怎样？
   **答：** 编译期报错（unordered 容器找不到 hash），这算"幸运失败"；
   不幸的是特化了却与 `operator==` 不一致——编译运行都绿灯，只是桶里永远找不到人。
4. **问：** 自定义字面值后缀到底该不该带 `_`？
   **答：** 生态里两派并存：标准库 chrono 用无下划线（`1000ms`，C++17），
   而社区/CWG 导向建议**用户代码加 `_`**——为的是不与未来标准库扩展撞名。
   导学真正示范的是"把量纲编进字面量"这一库设计手法（科学计算领域库的地基），
   前缀之争只是它的代价条款。
5. **问：** 语言为什么不把窄化转换检查直接焊死（像 GSL 的 `narrow` 那样）？
   **答：** 兼容性铁律：存量代码里隐式窄化遍地，当场硬化=全量编译红。C++11 已把
   **字面量**经花括号初始化的窄化变成编译错误，运行期变量间的截断则交给工具层
   （-Wconversion/准则库）——"能焊的焊在语言，剩下的写成库"是本书反复出现的分界。

## 权衡：explicit 与转换的光谱

§5.1.2 类型转换一笔带过 C 风格转换的四合一风险，给出 `static_cast`（明确意图）
与 `narrow_cast`（GSL 的"我就是要截断"）两把小锤。单文件笔记的 "explicit 禁止隐式转换"
在此落地：**能显式就显式，但拷贝构造别加 explicit（标准容器要用），
move-only 的包装构造该加**——规则的边界由"这次转换是不是意图"决定。

§5.4 常规操作清单（比较/容器操作/IO/字面值/swap/hash）其实是给第 11–13 章标准库
"入乡随俗"的移民指南：自定义类型想进 `unordered_map`，`std::hash` 特化是入场券；
想被算法伺候，比较与迭代器协议要先对齐。

## 最新演进与工业实践

- **第 3 版（C++20）改了什么**：本章升为第 6 章并**新增 §6.4 操作符重载总表**、
  §6.5.3 迭代器及智能指针条目；"比较"小节升级为 **spaceship `<=>` 与三路比较**
  （三e §6.5.1），`= default` 一次生成六个比较运算符；成员初始值一节并入指定初始化器
  （C++20 聚合，`Point{.x=1,.y=2}`）。
- **C++23/26 又推进了什么**：`std::generator` 式惰性序列进 `std::format`
  （P2418R2，[wg21.link/p2418](https://wg21.link/p2418) 实测可跳转）；
  三路比较在标准库的补齐是 P1614R2《The Mothership has Landed》
  （[wg21.link/p1614](https://wg21.link/p1614) 实测可跳转，标题本次核实）。
- **实测时间线（本会话直证）**：指定初始化器 `P p{.x=1,.y=2}` 在 g++ 15.2
  `-std=c++17`（含 gnu++17）**-pedantic-errors 下拒绝**、`-std=c++20` 通过——
  与"第 3 版才出现该语法"完全同步；spaceship `a<=>b` 同档复测 fail/OK/OK。
- **工业实践**：Abseil/RE2 等库的"移动必须 noexcept、可移动对象保持合法"仍是硬规矩；
  序列化框架（如 reflection 方向 P2996）试图把 §5.4 的手写常规操作整段自动化。
