## 核心概念速览（中英对照）

- **组件容器算法函数四分** — components/algorithms/containers/functions：§8.2 的标准库分类学
- **头文件即模块碎片** — headers：`<vector>` 式无扩展名头 + `std::` 名字空间
- **string 的 SSO** — small string optimization：短串就地存放的透明优化（§9.2）
- **string_view** — string view：`{ptr,len}` 非拥有视图，C++17 的"读参数通用货币"
- **视图悬垂** — view dangling：`string_view` 不续命，返回局部串的视图是头号新坑
- **正则 ECMAScript 方言** — std::regex：默认 ECMAScript 语法，`smatch` 结果族
- **正则性能税** — regex performance：std::regex 以慢著称，海量场景请换引擎
- **流与缓冲区** — iostream / streambuf：`cin/cout` 之上的格式化管线
- **IO 状态位** — eofbit/failbit/badbit：流是"带状态机的迭代器"，循环条件即 good()
- **操纵算子** — manipulators：`setprecision/w/hex` 内联改流状态
- **格式化的断层** — formatting gap：2nd 版只有流式格式化——`std::format` 尚在门外（§10.6）
- **文件流与字符串流** — ifstream/ostringstream：设备无关的同一套 `<<`/`>>`
- **C 风格 I/O 共存** — printf/scanf：快但无类型安全，`sync_with_stdio` 开关的两难
- **filesystem 库** — std::filesystem：路径/目录迭代/状态，C++17 并入的 FS TS

## 动机：从"语言导学"切到"库导学"的铰链三章

第 8 章只有 3 页，功能是把前 7 章的"为什么标准库长这样"收口：
**库组件全部用语言设施本身写成**（§6 的模板、§5 的常规操作约定在库里兑现），
所以学库=复习语言。第 9、10 章则各抓一门"日用基础设施"：文本与 IO——
Stroustrup 特意在正则一节花 5 页讲语法而非 API，因为那是读者真正的盲区。

## 机制：三个值得刻住的判据

1. **参数怎么收字符串**（§9.3）：只读入参用 `string_view`，需存副本用 `string`（值传或 const&），
   构造新文本返回 `string`。实测：`std::string_view sv = "lit";`+ variant/any 组合在
   g++ 15.2 `-std=c++17` 即编译运行通过——C++17 是"文本 API 现代形态"的基线年。
2. **IO 循环的正确骨架**（§10.3/10.4）：`while (cin >> x)` 依赖"流到 bool"的显式转换协议；
   `bad()` 与 `fail()` 的区别=设备错 vs 格式错，恢复用 `clear()+ignore()`。
3. **filesystem 的路径代数**（§10.10）：`path` 是字符串+分隔符语义学，
   `directory_iterator` 是"懒的容器"；错误码版重载（`error_code&`）与异常版双轨——
   第 3 章"异常 vs 错误值"光谱在库里的样板答案。

## 课堂问答（自读后对答案）

1. **问：** `string_view` 相比 `const string&` 到底多买了什么？
   **答：** 多买"来源自由"：`const string&` 要求对方必须先有 string（字面量入参=造一个临时串），
   `string_view` 直接 `{ptr,len}` 接受字面量/C 串/string 切片——只读形参的通用插座；
   代价是它不拥有数据，返回局部串的视图即悬垂。
2. **问：** `regex_match` 与 `regex_search` 选哪个？
   **答：** 校验整串（日期/邮箱）用 match——它要求**全串吻合**；在文本中找子串用 search。
   拿 match 找子串是新手第一大坑（明明该中却不中：因为两侧还有剩余字符）。
3. **问：** `while (cin >> x)` 为什么就是正确的读文件骨架？
   **答：** `>>` 失败即置 failbit，流对象经 `operator bool`（显式转换，第 5 章语法位）
   报告状态——循环条件天然覆盖" EOF 与格式错"两种终局；换 `getline` 同理，只是"词粒度"变"行粒度"。
4. **问：** `std::format` 与 `printf` 都对标点占位符，差别在哪？
   **答：** format 的 `"{:03}"` 语法在**编译期校验**且类型安全（第 5 章重载+可变参数模板共同兑现），
   printf 的 `%03d` 错一位就是 UB；这也是"2nd 版只有流式格式化"断层的最早补法（第 3 版 §11.6.2）。

## 权衡：三章各自的"别用"清单

- 别用 `std::regex` 打高吞吐日志：libstdc++ 的实现以慢闻名（工业共识），
  RE2/Boost.Regex/simdjson 才是生产件（⚠️ 慢的量化数字因语料而异，不给假数据）；
- 别拿 `printf` 打自定义类型：`<<` 重载与 ADL 才接进类型系统（§10.5 的
  "给 Point 写 operator<<" 是小而全的练习）；
- 别在头文件 `using namespace std;`：§8.3 点名这是把整个名字空间灌进全工程。
- 2nd 版 §10.6 的格式化只讲流式操纵算子——`std::format`（P2093 系 2019 才起步）
  对它是"未来"，对今天的我们是"默认"；第 3 版已补（见下）。

## 最新演进与工业实践

- **第 3 版（C++20）改了什么**：字符串与正则升第 10 章（新增 §10.2.1 "string 的实现"——
  SSO 从脚注转正）；IO 升第 11 章并**大改三处**：§11.6.2 新增 printf 风格之后的
  `std::format` 一节（`format("{}-{:03}",2018,8)`）；流家族补 **内存流（std::basic_stringbuf→
  basic_memory_buffer 语境）与同步流 `std::basic_syncbuf`**；文件系统补 path 比较细节。
  库概览（第 9 章）新增 **ranges 名字空间**与模块组织（std 模块）。
- **C++23/26 又推进了什么**：`std::print`（P2093R14《Formatted output》一支的下游，
  [wg21.link/p2093](https://wg21.link/p2093) 实测可跳转）、格式化范围 P2286
  （[wg21.link/p2286](https://wg21.link/p2286) 实测可跳转，标题本次核实）、
  `ranges` 型 formatter（P2418R2，[wg21.link/p2418](https://wg21.link/p2418) 实测可跳转）。
  **实测（g++ 15.2）**：`std::format` 在 c++20/23 通过并运行正确、c++17 无此头；
  但 `#include <print>` + `std::print` 在 **c++23 亦失败**——libstdc++ 15 未收 print，
  需 MSVC 19.29+/gcc-trunk（⚠️ 具体版本未逐一复核）——"标准定了≠库有了"的现场教材。
- **工业实践**：跨平台路径一律 `std::filesystem`+UTF-8 约定；日志热路径用
  fmt/spdlog（fmt 即 std::format 的孵化器：[github.com/fmtlib/fmt](https://github.com/fmtlib/fmt)
  实测 200）。正则替代：Google RE2（线性时间保证）——导学未讲，本笔记补位。
