## 核心概念速览（中英对照）

- **函数定义** — function definition：C++ 程序的执行单位，`main` 是入口
- **返回类型与参数** — return type / parameter：签名先于函数体，是类型安全的第一道闸
- **左值/右值** — lvalue / rvalue：可寻址的持久对象 vs 临时的"值"，赋值箭头方向的依据
- **变量与初始化** — variable / initialization：`int x{2}` 统一初始化，收窄需 `=` 放行
- **窄化转换** — narrowing conversion：`double→int` 之类的信息丢失转换，花括号初始化会拒绝
- **算术类型** — arithmetic type：整型/浮点/字符/bool，各自有界、各有回绕行为
- **作用域** — scope：名字可见的文本区域；块作用域是最小的资源管理单元
- **生命周期** — lifetime / duration：局部变量随块存亡，是析构与 RAII 的时间基础
- **const/constexpr** — const / constexpr：运行期不可改 vs 编译期可求值，二者正交
- **指针** — pointer：持地址、可空（`nullptr`）、不做边界与生命周期检查
- **数组** — array：连续存储、退化为指针、不携带长度——三宗罪
- **引用** — reference：别名而非对象，必须绑定到有效存储、不可 reseating
- **断言与前置条件** — assertion / precondition：`Expects()` 式的契约雏形（§1.8）
- **字节与字** — byte / word：内存编号单位与 CPU 一次处理的单位
- **内存模型** — memory model：程序=一组字节 + 有类型的访问视图（§1.9）

## 动机：为什么要"先看全部"

Stroustrup 在导学式写作上一贯的赌注：**读者需要一张完整但简笔的地图，而不是画到第一页就停的工笔画**。
第 1 章因此在 17 页里塞进程序、函数、类型、变量、作用域、常量、指针/数组/引用、检验、硬件映射——
每样只讲"够用的一口"，并刻意用**硬件视角**收束（§1.9）：C++ 的世界观是"内存是一串字节，
指针是字节编号，赋值的类型决定怎么解读"。这不是顺带一提，而是全书反复使用的解释装置：
后面讲移动语义、`string_view` 悬垂、对象布局时，兜底的答案都是"字节上发生了什么"。

## 机制：三条主线拧在一起

1. **函数是类型系统的第一现场**（§1.3）：返回值/参数按值、按指针、按引用三种通道，
   各自的代价（拷贝/可空/别名风险）从第 3 章参数传递一路用到尾。
2. **初始化而非赋值**（§1.4.2）：`=`、`()`、`{}` 三种记号里，`{}` 拒绝窄化——
   这是 Stroustrup 用语言机制替程序员挡住的第一个经典 bug（`int i{d}` 编译报错，`int i(d)` 静默截断）。
3. **作用域=资源边界**（§1.5）：变量在右花括号处"死掉"，这一时间规则是第 5 章 RAII、
   第 15 章锁守卫、乃至整个"析构即清理"体系的钟摆。

🔧 实测（g++ 15.2，`-std=c++17/20/23 -pedantic-errors`，均三档同行为）：
`int d=3; int v{d}` OK，`double x=3.7; int i{x}` 在**三档标准下都报错**——窄化检查是 C++11 起的
"跨版本常数"，导学书 §1.4/§1.6 的建议今天照抄不误。

## 权衡：指针、数组、引用为何"三败俱伤"还要全讲

§1.7 的笔调是坦率的：数组"既不携带大小也不检查索引"；裸指针"可以空、可以悬垂、可以指错类型"；
引用"安全些，但它不是对象，没有可重绑定"。Stroustrup 的权衡不在三者里选一个，
而是**给出升级路径**：能不用指针就不用（第 13 章 `span`/第 15 章智能指针接管），
必须用时用引用表意图、用指针表可空。这一节是后面所有"资源章节"的伏笔。

§1.8 检验：`assert()`、 GSL 的 `Expects/Ensures`——注意 2nd 版这里只是**预告**，
正式的"契约设施"要等第 3 版独立成章（约束条件，见辨析节），C++26 才有关键词级别的合约。

## §1.9 细读：赋值与初始化的"硬件账"

§1.9.1/1.9.2 是全章最"离经叛道"的部分：Stroustrup 直接按**赋值=把值写进目标对象占用的字节、
初始化=从零状态构造**来解释，甚至坦承"编译器可以把 `x=i` 优化成寄存器改名"。
两点实用推论（本笔记复述其逻辑，非原书字句）：

1. 赋值要求左操作数**已经活着**（构造过），否则写进的是未构造存储——UB 的字节解释；
2. 初始化没有"旧值"这个中间人，因此 `const`/引用成员只能在初始化列表里安置——
   这条硬件账直通第 5 章的成员初始化与移动赋值自清理。

🔧 单文件笔记遗留疑问 "`= == 的区别？`" 用本节语言回答：`=` 是**存储搬运指令**（可改变世界），
`==` 是**谓词表达式**（产生 bool 值）；重载 `operator==` 之所以安全，正因为它默认应当无副作用——
第 3 版把这条纪律升格为"比较运算应与 `==`/`<=>` 一致"的建议（3e §6.5.1）。

## 建议节（§1.10）精读三条

- "**用抽象设施**"：优先标准库容器/算法而非裸数组指针——本章末尾的"预告式建议"贯穿全书；
- "**避免未初始化变量、宏、void\*、union 滥用、隐含转换**"：四条"避免"全是 C 遗留，
  与第 16 章 C/C++ 兼容性遥相呼应；
- "**变量尽量晚定义、尽量靠近作用域末端**"：把生命周期缩到最短，是最便宜的例外安全。

| 概念对 | 分界线 | 本册去处 |

## 最新演进与工业实践

- **第 3 版（C++20）改了什么**：§1.7 单拆出"空指针"小节——`nullptr` 一统江湖的收尾叙述；
  §1.8 检验拆给新的第 4 章"错误处理"（`assert`/`static_assert`/`noexcept` 聚拢）；
  新增 C++20 语言特性年表（§19.2.4）。单文件笔记里的 `= == 的区别？`疑问，
  在第 3 版的答案更明确：比较链 `<=>`（3e §6.5.1）把"判等与判序"合流。
- **C++23/26 又推进了什么**：`std::bytes`（C++26 方向）给"字节"一个无符号整数身份类型；
  契约（contracts）在 C++26 落地关键词级 `pre`/`post`（⚠️ 以 P2900 系推进为准，
  [wg21.link/p2900](https://wg21.link/p2900) 实测可跳转，最终措辞轮次未复核）。
- **实现史节点**：初始化收窄检查自 GCC 4.8/Clang 3.x 稳定；`nullptr` 为 C++11 常数。
  GCC 的 C++ 支持矩阵见 [gcc.gnu.org/projects/cxx-status.html](https://gcc.gnu.org/projects/cxx-status.html)
  （实测 HTTP 200）。
