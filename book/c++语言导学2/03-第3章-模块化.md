## 核心概念速览（中英对照）

- **头文件与包含** — header / #include：文本级复制，是"模拟模块化"的历史方案
- **分别编译** — separate compilation：.cpp/.h 分工，链接期缝合
- **ODR（单一定义规则）** — One Definition Rule：inline 函数可"多头定义"的合法性来源
- **前向声明与循环包含** — forward declaration：#include 保护不了的双向依赖
- **外部 C 链接** — extern "C"：与 C ABI 互操作的改名开关
- **宏滥用三宗罪** — macros：类型检查失明、作用域失明、调试失明
- **模块（C++20 预告）** — modules：编译一次、导出接口，替换文本包含的正规军
- **名字空间** — namespace：组织逻辑接口、防名字爆炸
- **异常与传播** — exception / propagation：错误沿调用栈上抛，栈展开顺带析构
- **不变式与 RAII** — invariant / RAII：异常安全的地基（§3.5.2 回扣第 2 章）
- **错误码/expected 式返回** — error codes / result types：异常的四条替代路线（§3.5.3）
- **合约（TS 预告）** — contracts：pre/post/invariant 谓词，当时仍在 C++20 门口
- **静态断言** — static_assert：编译期断言，模板时代的哨兵
- **传值/传引用/传指针** — pass by value / reference / pointer：参数三通道及其 const 变体
- **移动出参** — move semantics：`x = std::move(y)` 与"取空"式返回
- **结构化绑定** — structured bindings：`auto [a,b] = p;` 拆解 pair/tuple/聚合

## 动机：语言特性解决不了工程问题

导学把"模块化"放在前三章，因为真正拦路的问题是**编译时间、链接错误与依赖蔓延**，
而非语法。§3.2 冷峻地指出头文件机制的账：include 是文本复制→重复解析→宏泄漏→
循环包含"用语法糖掩盖架构问题"。§3.3 顺势预告 modules（当时标 C++20）：
"**模块=把 .h/.cpp 的意图直接做成语言设施**"。这一节也是理解第 16 章演化史最好的样片。

## 机制：错误处理是一条光谱而非三选一

§3.5 把错误处理拆成五层，每层有自己的"客户"：

1. **异常**（3.5.1）：适合"调用方处理不了"的罕见错误；栈展开自动调析构→与 RAII 咬合；
   代价是控制流隐式、`noexcept` 边界要人划。
2. **不变式**（3.5.2）：对象级的小宪法——构造函数、赋值、修改方法共同维护一条规则；
   "先构造新对象再提交"（copy-and-swap）是保规则的通用招。
3. **替代方案**（3.5.3）：错误码（会被忽略）、optional/variant 返回（第 13 章兑现）、
   "返回函数"续接式（当时未成库设施）、终止（fail-fast）。Stroustrup 的裁决：
   **异常与错误值互补——构造失败用异常，日常可恢复错误用值**。
4. **合约**（3.5.4）：pre/post/invariant 谓词标注在签名上，违约是"程序员错误"而非
   运行期异常——C++20 未赶上，2nd 版只能预告；这正是第 3 版改写最狠的一节。
5. **static_assert**（3.5.5）：把"模板参数不对"从几百行报错里提前拦下。

## 机制（下）：参数与返回值的四种姿势

§3.6 是全章可操作密度最高处，值得压成口诀：**小值传值、大入参 `const&`、
出参用返回值（可移动）或 `&`、可空/多态才用指针**。结构化绑定（3.6.3）给了
"返回多值"第三种体面：`for (auto& [name, val] : m)`——它统一拆解
pair/tuple/聚合，C++17 三件套之一，三档编译实测通过（本会话 `std::map` 遍历式）。

🔧 实测注记（g++ 15.2）：本会话反复验证的"三档标准矩阵"里，本章主题涉及
**modules**：`-std=gnu++20 -fmodules` 在 GCC 15.2 下编译 `export module M; / import M;`
两 TU 成功运行（exit 0），且模块缓存会校验语言方言（用 C++17 复用 C++20 的 .gcm
被拒：`language dialect differs`）；而 `import <vector>;` 头单元因缺预编译 .gcm 失败——
"标准库模块"仍是 P2465（[wg21.link/p2465](https://wg21.link/p2465) 实测可跳转）路线上未完的活。

## 课堂问答（自读后对答案）

1. **问：** 为什么 `inline` 函数可以在多个 TU 里"重复定义"？
   **答：** ODR 允许——只要每份定义 token 级相同；这是分别编译体系为头文件开的后门，
   也是宏/内联纠缠的根源。模块的意义就是把这种"复制粘贴的同一"升级成"编译一次的同一"。
2. **问：** `using namespace std;` 为什么在头文件里是重罪、源文件里勉强可恕？
   **答：** 头文件的 using-directive 会强灌给所有包含者——你替全工程做了决定；
   源文件只影响本 TU（§8.4 建议有专条呼应）。
3. **问：** 异常穿过 `noexcept` 函数会发生什么？为什么移动构造要标它？
   **答：** `std::terminate`。vector 扩容只在移动构造 `noexcept` 时才敢移动——
   否则退回头拷贝（第 12 章扩容行为的开关，第 5 章已埋伏笔）。
4. **问：** 结构化绑定能拆裸数组吗？
   **答：** 能拆 `std::array`/tuple/pair/聚合（公有无基类成员），C++17 范围即此；
   它引入的是"伪名字"（hidden structured binding members），在 lambda 捕获里当年有坑（C++20 修复）。
5. **问：** modules 既然治编译时间，为什么 2nd 版 §3.3 仍写得像"观望中"？
   **答：** 写作时点 Modules TS 语法未定、工具链（BMI 缓存/构建系统联动）未熟，
   书只能讲"具名接口取代文本包含"的意图；宏不随模块导出这类边角也只有预告位能留——
   本笔记用 g++ 15.2 `-fmodules` 实测"能用但须锁方言"，恰好补上这段历史中间态。

## 最新演进与工业实践

- **第 3 版（C++20）改了什么**：本章被**劈成两章**——错误处理独立为第 4 章
  （异常/约束条件/替代/断言/`noexcept` 系统重讲），模块化（3e 第 3 章）新增
  头文件卫生、**模块正式上位**（§3.2.2，去掉"C++20 预告"字样）、返回类型推导/后置；
  结构化绑定留在参数一节。目录对读见 [00-总览](00-总览与阅读地图.md)辨析节。
- **C++23/26 又推进了什么**：模块侧 P2633（标准库头单元语法，
  [wg21.link/p2633](https://wg21.link/p2633) 实测可跳转）→ C++23 `import std;` 由
  P2465R3 推动；合约最终在 **C++26** 以 `pre/post` 谓词落地（P2900 系，
  [wg21.link/p2900](https://wg21.link/p2900) 实测可跳转；⚠️ 采纳轮次未逐会期复核）。
- **实现史**：GCC 模块（本实测）需显式 `-fmodules`（GCC 14+ 从 TS 旗标转正过渡中，
  ⚠️ 版本细节以 cxx-status 为准）；Clang 需 `-fmodules -Xclang -experimental-...`（历史旗标，
  ⚠️ 未本机验证）。工业上 modules 落地最深的仍是 MSVC（⚠️ 凭公开博客印象）。
