## 核心概念速览（中英对照）

- **结构体** — struct：公开数据成员的聚合，C 血统的"记录"
- **类与封装** — class / encapsulation：默认私有，不变式（invariant）由成员函数守住
- **不变式** — invariant：对象构造后恒真的规则，异常安全与接口的共同前提
- **成员函数与 this** — member function / this：以对象为隐藏第一参数的函数
- **getter/setter 批判** — access function：无约束的存取器等于没封装
- **构造函数** — constructor：建立不变式的第一次机会；默认构造的代价
- **联合** — union：共享存储的"多选一"，无类型标签，活动成员需自行追踪
- **带标签联合** — tagged union / discriminated union：外加枚举标签=手工 variant
- **匿名联合** — anonymous union：省略名字直接用成员的语法糖
- **枚举** — enum：无作用域、可隐式转整数的常量集（C 遗产）
- **强类型枚举** — enum class：有作用域、不隐式转换、可指定底层类型
- **位域** — bit-field：struct 内按位声明（2e §2.2 提及，导学刻意薄讲）
- **_plain-old-data_** — POD/trivial 类型：可 memcpy 的类型层级底层（术语后移到第 5/16 章语境）
- **值语义** — value semantics：自定义类型也能像 int 一样拷贝/赋值/比较

## 动机：类型是程序的最小防御单位

Stroustrup 把"用户自定义类型"放在语言设施的第二章，位置本身就是论点：
**C++ 的核心不是"面向对象"，而是"像内置类型一样定义新类型"**（值语义+抽象）。
本章用 `Matrix`/`Vector` 式的极简例子说明：struct 加个不变式就是 class；
class 一旦需要"表达多种形态"，你就滑向 union 或 enum——而这两者都危险，
于是第 13 章的 `variant/optional` 才是本章真正的"续集"。

## 机制：四个工具的递进

1. **struct→class**（§2.2–2.3）：唯一区别是默认访问权；真正的区别在**纪律**——
   公开不变式注释、构造即校验、getter/setter 若是裸转发则是"假封装"。
2. **联合**（§2.4）：`union Value { int i; double d; }` 省空间但**不知道当前存的是谁**；
   Stroustrup 给出补救模板：struct 里放 `enum Tag + union`，即 tagged union——
   这就是 `std::variant`（第 13 章）的手动变速箱体。
3. **枚举**（§2.5）：`enum` 的三个坑（名字泄漏到外层作用域、隐式整数转换、无底层类型约束）
   各由 `enum class` 一一堵上。单文件笔记的两处疑问，本节直接回答：

🔧 `enum class Color { red, green };` vs `enum Color { red, green };`——实测（g++ 15.2）：
`int c = Color::red;` 在 `enum`（非限定）下**三档标准都编译通过**（隐式转 int，坑）；
在 `enum class` 下**三档都报错**（必须 `static_cast<int>`）。而 `Color::red` 写法在
非限定 enum 下 C++11 起也合法——所以 `enum class` 赢在**约束**而非语法。

4. **标签/值分离的硬件账**：union 成员共享起始地址，`sizeof(union)=最大成员+对齐`；
   tagged union 的额外 tag 字段正是 variant 体积的构成（对照
   [../深度探索C++对象模型/03-Data语意学.md](../深度探索C++对象模型/03-Data语意学.md)）。

## §2.2–2.3 细读：struct 的三件小工具

导学在这一节顺手塞进了后来被滥用的三个语法点（转述其主题，非原书字句）：

1. **成员默认初始化器**（`struct S { int x = 0; }`）——C++11 起可用，配合"NSDMI"
   让每个构造函数不再重复写零；第 5 章 §5.1.3"成员初始值"正式接管这个话题；
2. **位域**（`unsigned int bs : 7;`）——只为映射硬件/协议报文而存在，
   布局实现定义、`&` 取不到其地址，Stroustrup 的态度是"知道有这回事"；
3. **结构体作为"无成员函数的数据"**——函数式风格里 struct+自由函数优于类方法
   （开放扩展 vs 封闭类），这一立场在《C++ 核心准则》里升格为 P 条目。

## enum 三坑逐条演示

🔧 实测（g++ 15.2，`-std=gnu++17`，20/23 同行为）：

```cpp
enum Type { normal = 1, discrete };      // 坑1：normal 直接泄入外层作用域
Type t1 = normal;                          // C++11 起也接受 Type::normal（写法可统一）
int x = normal + 1;                        // 坑2：隐式转 int，静默通过
enum Flag : unsigned char { a=1,b=2 };     // 坑3 的半个修复：传统 enum 也能指定底层类型（C++11）
enum class Color { red, green };
int y = Color::red;                        // 报错——这正是 enum class 的全部意义
```

单文件笔记问"`enum class` 与传统 `enum` 区别"——上表即最小答案；其"前置声明省编译依赖"
一条对两者都成立（底层类型已知即可），真正差异集中在**作用域与隐式转换**。

## 课堂问答（自读后对答案）

1. **问：** struct 与 class 语法上只差默认访问权，为什么说"改选哪个"是设计行为？
   **答：** 默认私有=宣告"这里有不变式、由成员函数守"；用 struct=承认"纯数据、人人可改"。
   差别写进意图，编译器只是执行——§2.6 建议"数据成员默认 private"由此而来。
2. **问：** 裸 union 怎么知道当前成员是谁？tagged union 补了什么？
   **答：** 它不知道——这是 union 的核心危险。§2.4 的补救是 struct 里外加 `enum Tag`
   手工维持"标签-值一致"；`std::variant`（第 13 章）的贡献是把这个一致性交还类型系统。
3. **问：** `enum class` 不隐式转整数，取个数还得 `static_cast`，不是添麻烦吗？
   **答：** 那一行 cast 恰是"意图显式化"的站点：进入数值域必须写出来（或交给 C++23 的
   `std::to_underlying`），否则就会重演 C 里 `if (color == 3)` 的无界混用。
4. **问：** 本章为什么不讲拷贝/移动/析构？
   **答：** 那是 §5.1"基本操作"的全图（Rule of Zero/Five 的语境）；本章先立"类型形状"
   （字段+不变式+成员函数），第 5 章再谈"类型生命周期"——形状与运动分家讲授。

## 权衡：什么时候停在这里，什么时候上第 4 章

本章刻意不讲虚函数——"具体类型优先"是全书战略：**数据结构尽量 concrete（值语义、可栈上、
可拷贝移动），只有确实需要"同接口不同行为"时才付抽象类+堆分配+指针语义的三重税**（第 4 章）。
tagged union 的权衡也同构：手工 tag 快但散落在人脑里，`variant + visit` 把合法性交给类型系统。

## 最新演进与工业实践

- **第 3 版（C++20）改了什么**：联合与枚举**对调顺序**（3e §2.4 枚举、§2.5 联合），
  联合被降格为"最后手段"；并新增建议"**尽量用 variant 代替 union**"的明文化；
  结构体绑定后的聚合初始化在 3e 语境下讨论更多。术语仍为"联合/枚举"。
- **C++23/26 又推进了什么**：`std::to_underlying`（把枚举安全转回底层整数，
  C++23 进库；⚠️ 具体提案号本会话未在 wg21.link 核到对应条目，不写号）；
  反射方向（P2996，[wg21.link/p2996](https://wg21.link/p2996) 实测可跳转）长期目标之一
  正是"枚举→字符串"这类样板代码的消灭；实验实现见
  [github.com/yusufemresamur/docker-clang-p2996](https://github.com/yusufemresamur/docker-clang-p2996)
  （API 实测存在）。
- **工业实践**：Google Style Guide 强制 `enum class`；协议解析层的"带标签联合"今天多半写作
  `std::variant`+`matches`（C++26 提案方向）或反射生成的 visit。
