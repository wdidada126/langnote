## 核心概念速览（中英对照）

- **参数化类型** — parameterized type：用类型作参数造类型（`Vector<T>`）
- **成员模板** — member template：模板类里的模板函数，为转换/构造开小灶
- **类模板参数推导（CTAD）** — class template argument deduction：`pair p{1,2.0}` 不写尖括号
- **值模板参数** — non-type template parameter：`array<T, N>` 把编译期常量编进类型
- **auto 值参数** — `template<auto v>`：类型+值一体的参数（C++17）
- **函数模板** — function template：参数化"做什么"而非"对什么"
- **函数对象** — function object / functor：带 `operator()` 的类，可携带状态
- **lambda 表达式** — lambda：就地匿名函数对象，`[捕获](形参){体}`
- **泛化 lambda** — generic lambda（`auto` 形参，C++14）：微型函数模板
- **可变参数模板** — variadic template：`Ts...` 零到任意个参数
- **别名模板** — alias template：`template<typename T> using V = Vector<T>;`
- **编译期 if** — `if constexpr`：按模板实参裁剪代码路径，替代 tag 分发特化
- **模板实参推导** — template argument deduction：调用点反推参数的机制
- **转发（预告）** — forwarding：`T&&`+`std::forward` 保值类别穿透（第 7/13 章展开）
- **两阶段名字查找** — two-phase lookup：定义期查依赖外名字、实例化期查依赖名（§6.4 阴影下）

## 动机：第 2 次"泛化"，对象从数据变成操作

第 6 章开头回顾第 2 章：具体类型→抽象类型解决"行为复用"；模板解决的是
**"同一套代码服务不同数据类型"且不付虚函数税**。Stroustrup 特别把"参数化操作"
（函数模板→函数对象→lambda）排成三级台阶——这是 C++ 泛型编程的**功能语言内核**：
算法的高阶性靠"把计算当类型参数传递"。

## 机制：四组要点

1. **约束缺位时代的接口**（§6.2）：2nd 版明说模板参数只有"使用即要求"的隐式接口——
   报错延迟到实例化、错误信息震怒初学者。§6.2.1 预告 concepts（C++20），
   把第 7 章的"主角预告片"插在这里。
2. **值参数把不变量搬进类型**（§6.2.2）：`array<T, N>`、`span<T, Extent>`；
   `template<auto>`（实测 c++17 起三档可用）让"256 这个字节数"可推导。
3. **lambda 是语法糖，捕获列表是所有权声明**（§6.3.3）：`[&]` 悬垂是头号事故——
   导学警告"别把局部 lambda 存进长期对象而不捕获生命周期"。
4. **`if constexpr` 的分水岭意义**（§6.4.3）：递归模板终止从"特化接力"变成
   `if constexpr (sizeof...(Ts)==0)`；它是 constexpr 家族在**语句**层的投影。

🔧 实测（g++ 15.2 三档 c++17/20/23）：本会话矩阵中
`if constexpr`、变量模板、CTAD、别名模板、折叠表达式在 **c++17 即全绿**——
第 6 章内容 90% 是 C++11/14/17 存量，与"2nd=基线 C++17"的口径一致；
而 `template<typename T> concept ...`（§6.2.1 预告位）在 c++17 **拒绝**
（`'concept' does not name a type`）、c++20 起通过——预告与正片的分界用编译器量了出来。

## 课堂问答（自读后对答案）

1. **问：** 类模板里的"成员模板构造函数"解决什么普通构造解决不了的？
   **答：** `Vector<T>` 从 `Vector<U>` 转换（U 可转 T 即放行）——一个模板罩住无穷多
   源类型；这正是 shared_ptr 协变转换、Any 式包装的地基语法。
2. **问：** CTAD 会替 `Vector v{1,2,3}` 推出 `Vector<int>`，那想推 `Vector<double>` 怎么办？
   **答：** deduction guide（推导指南）或干脆写尖括号；C++20 起还有"聚合的 CTAD"补齐。
   导学只讲隐式路径，指南细节在标准库册。
3. **问：** lambda 和"就地定义的函数对象"性能有差别吗？
   **答：** 没有——lambda 就是编译器手写的闭包类+`operator()`；差别在人的层面：
   `[&]` 悬垂捕获是 lambda 独有的新失血点，具名 functor 反而被构造函数拦一道。
4. **问：** `if constexpr` 能替代全部 SFINAE/特化吗？
   **答：** 只能替代"分选实现"那一半；"约束合法性/参与重载集"仍需 concepts
   （或土法 enable_if）——这正是第 7 章存在的理由。
5. **问：** 函数模板为什么"传数组退化成指针、传 `int&` 推出 `T=int`"？
   **答：** 按值形参的推导默认剥顶层引用、数组/函数 decay——想留住类型就得用
   转发引用 `T&&`（左值实参推成 `int&`）。CTAD 与 `auto` 走的正是同一套推导机器，
   这也是 §6.2.3 与 §7 概念推导能接上的底层原因。
6. **问：** "别名模板不能特化"这个限制在实践中疼在哪？
   **答：** 写不出带条件分支的类型别名，TMP 元函数只好绕道类模板+`::type`
   （实战册的元函数全长成那样就是历史成因）；导学 §6.4.2 只给能力清单，
   这条"未列举"恰是它建议读者去翻标准库册的理由。

## 权衡：模板的账单一向是"编译期+代码膨胀"

与第 4 章抽象类型对照：**虚函数=运行期一次间接+零重复代码；模板=零间接+N 份实例**。
导学的建议是性能敏感处用模板、跨边界稳定接口用抽象类；两条线在第 7 章 concepts
处合流（concepts 是给模板补"接口文档+早报错"，不是第三种运行时分派）。
另注意 §6.4.2 别名模板**不能特化**的著名限制（当年 CWG 挂账），
TMP 实战册第 1 章的元函数写法就是围着它绕的。

## 最新演进与工业实践

- **第 3 版（C++20）改了什么**：模板升第 7 章，**变参模板挪去第 8 章**与 concepts 同堂；
  新增"模板变量"小节（§7.4.1，`template<typename T> constexpr T zero{};`——
  2nd 只在类型函数角落露脸）；§6.2.1 的"约束预告"转正为正式概念语法讲解；
  模板参数推导全面强化（`template auto`、`template<int N = 20'000'000'000>` 分隔符示例）。
- **C++23/26 又推进了什么**：lambda 模板参数（C++20 已可 `[](auto x)`）、
  `template` 关键字进 lambda（C++23）；`#embed` 把二进制资源纳入预处理（C++23）
  缓解"变参初始化器"场景（⚠️ 未实测 GCC 15 支持档）；反射 P2996 的近期目标即
  "模板元编程的样板终结者"。
- **实现史节点**：GCC 的 concepts TS 曾需 `-fconcepts` 旗标（GCC 6–9 时代），
  GCC 10 转正——与本次 gnu++17 默认拒绝 `concept` 的实测互为印证；
  CTG（CTAD）为 C++17 常数（GCC 6 起）。cxx-status 表：
  [gcc.gnu.org/projects/cxx-status.html](https://gcc.gnu.org/projects/cxx-status.html)（实测 200）。
