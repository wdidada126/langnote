## 核心概念速览（中英对照）

- **具体类型** — concrete type：布局与操作编译期定死，值语义、栈友好、可内联
- **抽象类型** — abstract type：接口与实现分离，基类只留纯虚函数
- **多态** — polymorphism：基类指针/引用在运行期分派到派生实现
- **虚函数与重写** — virtual function / override：动态接口的动词位
- **纯虚函数** — pure virtual（`= 0`）：把"必须被实现"写进类型
- **final 与 override 标注** — final / override：封死重写点、让漏写签名变成编译错误
- **虚析构函数** — virtual destructor：经基类指针 delete 时正确展开析构链
- **抽象基类（接口）** — interface class：无状态、全纯虚，跨库边界的稳定协议
- **类层次** — class hierarchy：Shape→Line/Circle 式的开放分类学
- **访问者（预告）** — visitor：层次漫游的双分派（§4.5.2 以 dynamic_cast 先演示）
- **动态转换** — dynamic_cast / RTTI：运行期探测"你到底是谁"，昂贵且不闭集
- **资源泄漏** — resource leak：层次+裸 `new/delete` 组合的经典事故
- **RAII 句柄** — handle / scope guard：用第 2 章的"具体类型"替层次管资源
- **语义相等 vs 指针相等** — equality of value vs identity：层次里 "=" 到底比谁？

## 动机：一个词——"表示"

导学第 4 章的隐含问题是：**同一问题该用哪种表示？** Stroustrup 给两条答案并排：
`Matrix`（具体类型：double*+维度，快、可值拷贝）与 `Shape` 层次（抽象类型：
可无限扩展的新图形）。他的立场毫不含糊——**默认用具体类型；抽象是税，
只有"要跨编译/团队边界扩展行为"时才付**。这是全书与 OO 教材分道扬镳的一段。

## 机制：两线的关键咬合点

1. **容器型具体类型**（§4.2.2–4.2.3）：`Vector` 三件套（ptr/sz/space）+ 五种常规操作；
   `initializer_list` 让 `Vector v{1,2,3}` 走通用路径而非字符串特例——标准库风格的新类型
   就该接入标准设施。
2. **抽象类型三章法**（§4.3–4.5）：基类声明接口→派生类 `override`→调用方只握 `Shape&`。
   注意导学刻意用**引用**示范多态；"切片"（按值传基类丢掉派生身份）被归为事故而非特性。
3. **层次漫游的诱惑**（§4.5.2）：`for (Shape* p : v) { if (auto c = dynamic_cast<Circle*>(p)) ... }`
   ——Stroustrup 明写这是"坏代码的磁铁"：每加一个派生类就要改所有 if 链。
   出路两条：把公共操作提升进接口（多态本身），或访问者模式（第 14 章的
   [../C++20设计模式/14-模板方法与访问者.md](../C++20设计模式/14-模板方法与访问者.md) 展开双分派谱系）。
4. **资源防漏**（§4.5.3）：单文件笔记摘录的"记住所有分支都要 delete p"正是本节恐惧的
   人话版；解药=让 `unique_ptr<Shape>` 住进容器（第 13 章），delete 从源码里消失。

## 课堂问答（自读后对答案）

1. **问：** 为什么基类析构必须 `virtual`？
   **答：** 经 `Shape*` delete 派生对象时，非虚析构=只跑 `~Shape`，派生部分泄漏——
   且这是 UB。接口类没有数据也要为析构付一个 vptr，正是"抽象税"的固定成本。
2. **问：** `Circle c; Shape s = c;` 为什么是事故不是便利？
   **答：** 切片：s 只拷了 Circle 的 Shape 子对象，`s.area()` 调到 `Shape::area`——
   多态要求指针/引用，值语义要求拷贝构造，两者在此互斥。对策：基类拷贝构造设 protected
   或干脆 delete（第 5 章 Rule-of-X 话题）。
3. **问：** 为什么导学说"dynamic_cast 链是坏代码磁铁"却仍演示它？
   **答：** 教学目的=让你认出"每种类型都要 if 一遍"是**接口设计失败**的信号；
   正解要么提升进虚接口，要么封闭化换 variant+visit（§13.5.1 兑现）。
4. **问：** `unique_ptr<Shape>` 装进 vector 后，`push_back` 需要额外注意什么？
   **答：** vector 只存 move-only 元素时全部增删路径必须可移动——这就是第 5 章
   "移动 noexcept 决定扩容成本"在真实容器里的验收单（本笔记实测：CTAD+move 三档通过）。
5. **问：** 为什么说"具体类型免费给你栈、值语义和拷贝，抽象类型三者全没收"？
   **答：** 层次上的值语义不可行（基类不知道派生尺寸），只能指针+堆；§4.5.3"避免资源泄漏"
   一节本质是承认层次里混进了 new——这笔账由第 13 章智能指针来清。
6. **问：** §4.5 对多重继承几乎不着墨，是疏漏吗？
   **答：** 是导学的页预算选择：MI 的菱形、虚基类、名字查找规则一段讲不清，
   半吊子讲法反而教出坏设计——本书立场是"具体优先+单接口"，MI 的深水区留给
   专册（本笔记推断 ⚠️，非原书字句）。

## 权衡：虚表税、拷贝税与封闭性

抽象层次的三笔账：**空间**（每对象一个 vptr、每类一张 vtable）、**时间**（一次间接跳转、
内联断链）、**拷贝**（基类不知派生尺寸，"按值多态"只能克隆或句柄）。对照
[../深度探索C++对象模型/06-执行期语意学.md](../深度探索C++对象模型/06-执行期语意学.md)
可看到同一机制的字节级解剖。若层次封闭（编译期已知全部类型），
variant+visit 是更快更安全的替身（第 13 章兑现）——
"开放用虚函数、封闭用 variant"是本册最重要的二择口诀。

## 最新演进与工业实践

- **第 3 版（C++20）改了什么**：类仍在第 5 章，新增"类的概述"小节；§4.5.2 层次漫游改口
  **推荐访问者/std::variant 替代 dynamic_cast** 的措辞更强；`explicit b(true)` 式
  基类构造调用、聚合初始化与多态构造的新语法（C++20 指定初始化器）进入示例。
- **C++23/26 又推进了什么**：`this` 显式对象参数（deducing this，P0847R7，
  [wg21.link/p0847](https://wg21.link/p0847) 实测可跳转）被寄予"CRTP 与多态混合体"的期望——
  派生类可捕获自身静态类型而保留虚分派；本会话实测 GCC 15.2 `void inc(this auto&& self)`
  在 `-std=c++23`（扩展放行）与 `-std=c++2c` 通过、`c++20` 拒绝——**实现进度跑在标准档位前**。
  它也是"按值多态/克隆"样板代码的减刑者（⚠️ 与 P0847 的关系为社区共识而非提案原文）。
- **工业实践**：游戏引擎 ECS 对"类层次虚分派缓存不友好"的批评与"组件=variant 化"的
  回潮，正是本节权衡的工业版（⚠️ 通识表述，不引具体论文）。接口类+工厂在 ABI 边界
  仍不可替代——`std::format` 的 formatter 注册就是"编译期具体类型"路线的胜利（第 10 章呼应）。
