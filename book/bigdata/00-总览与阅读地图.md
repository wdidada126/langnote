# 大数据：两本书的深度笔记总览与阅读地图

> **本章地图**：本目录**不是一本书，而是两本书的深度重写版**。左边是《Spark 大数据实时计算：基于 Scala 开发实战》（杨力，人民邮电出版社，2022-10，ISBN 9787115597038），右边是《离线和实时大数据开发实战》（朱松岭，机械工业出版社，2018-05，ISBN 9787111596783，大数据技术丛书）。前者是「**Scala 语言 + Spark 框架**」这条**技术纵线**，后者是「**离线数据平台 + 实时数据开发**」这条**工程横线**。两本合起来才是一张完整的现代大数据地图：一个告诉你引擎怎么用，一个告诉你平台怎么搭、坑在哪。

- **大纲版在此（浅读入口，本目录是深度重写版）**：
  - `Spark大数据实时计算.md` —— 只存了书名/ISBN 一句话大纲，本目录的 `01–06、09` 章是它的展开。
  - `离线和实时大数据开发实战.md` —— 只存了出版年/ISBN 一句话大纲，本目录的 `07、08、10–12` 章是它的展开。
- **为什么必须两本一起读**：2018 年之前，行业共识是「离线批处理 + 实时流式」两套 pipeline 并存（Lambda）。两本书恰好是这两种视角的产物：《离线和实时大数据开发实战》写于 2018 年，是**平台视角**的样本；《Spark 大数据实时计算》写于 2022 年，是**框架视角**的样本。2026 年的现实是——**Lambda 已被 CDC + 流处理 + 湖仓一体部分取代**，因此本目录在每一章都补了「两书未覆盖的 2026 现实」。

## 三、阅读路径建议

### 3.1 三条主线

1. **引擎线（技术纵深）**：`02` → `03` → `04` → `05` → `11`。适合已经有了 Spark 使用经验、想搞明白「为什么这么慢」的工程师。这条线几乎完全由《Spark 大数据实时计算》第 6、7、9 章支撑。
2. **平台线（工程横向）**：`01` → `07` → `08` → `09` → `12`。适合做数据平台/实时数仓的架构与开发。这条线几乎完全由《离线和实时大数据开发实战》第二、三篇支撑。
3. **语言线（地基）**：`06` → `02`。想把 Spark API 用得顺手，先把 Scala 的不可变集合与高阶函数想清楚，否则读 Spark 源码会处处碰壁。

### 3.2 推荐顺序

- **第一次读（建立地图）**：`00` → `01` → `06` → `02` → `07`。
- **第二次读（补现代）**：`04` → `10` → `09` → `12`。这三章是两书共同的缺口所在，也是 2026 年最值钱的部分。
- **按需**：`03`、`05`（性能问题排查时再读）；`08`（接消息队列时再读）；`11`（上线运维时再读）。

## 四、2026 视角：两本书共同的四个时代缺口

两本书加起来覆盖了「Spark 怎么用」与「平台怎么搭」，但对下列主题几乎没有着墨。每一章至少补 2–4 条相关内容，下面这张表是总纲：

| 缺口 | 为什么 2026 年绕不开 | 分散在哪些章 |
| --- | --- | --- |
| **Spark 3.x 的新语义**：ANSI 模式（ Crawford 等，SIGMOD 2022）、动态分区裁剪 DPP、Adaptive Query Execution(AQE)、SPIP（SPark Improvement Proposal）；Spark 4.0 的 SI / ANSI-by-default 走向 | 两书写于 Spark 2.x 时代，`spark.sql.ansi.enabled=false` 是 2022 年前的行为；不补会读不懂其报错 | `01`、`04`、`05`、`10` |

| **成本与治理**：对象存储（S3/OSS）上的存算分离、向量化与编译执行（Arrow / Velox / DuckDB）、数据血缘与成本归因 | 两书的假设是「集群在本地 HDFS 上」 | `09`、`10`、`11`、`12` |

## 六、术语对照与高频说法的 2026 更正索引

两本书各自使用了不少「成书即成立、今天需要加限定」的说法。下表把它们集中索引，正文里在对应章节的误区表中展开：

| 高频说法 | 出处 | 2026 年的更正 | 正文位置 |
| --- | --- | --- | --- |
| 「实时计算 / 流计算的鼻祖是 Storm」 | 《离线》第 8.1 节 | 方向对（Storm 确实是流处理的先驱），但 2026 年新项目**不应**再选 Storm（社区已基本停更） | **`01`** 误区 1、`07` 误区 4 |
| 「Spark Streaming 是实时计算的主力」 | 《离线》第 9 章；《Spark》第 10 章 | 微批（默认 500ms）不是事件级；新项目首选 Flink，Spark 侧用 Structured Streaming | **`01`** 误区 4、`07` 误区 3 |
| 「Spark 是最流行的大数据计算引擎」 | 两书共同的隐含前提 | 批处理与 SQL 仍是 Spark 主场，但**流处理默认选择是 Flink** | **`10`** 误区 1 |
| 「数据湖 = 对象存储上放文件」 | 《离线》第 7.5 节 | 缺了**表格式**（ACID、时间旅行、schema 演进）就不算湖仓 | **`09`** 误区 1、`10` 误区 5 |
| 「把数据搬到消息队列就解耦了」 | 《离线》第 1.2.1 节 | 解耦的前提是**可重放 + 正确提交 offset + 幂等消费**，否则只是换了一个丢数据的姿势 | **`08`** 误区 1–2 |
| 「开了 checkpoint 就是 exactly-once」 | 《离线》第 8.4 节语境 | exactly-once 只覆盖算子状态；输出侧必须幂等或事务 | **`07`** 误区 1 |
| 「Hive 上的优化就是倾斜治理」 | 《离线》第 5 章 | 倾斜仍是核心，但还要补：统计信息、小文件、列裁剪、DPP | **`03`、`05`、`09`** |
| 「Scala 写 Spark 只能用 RDD 那样的方式」 | 《Spark》第 6 章 | Spark 2.x 之后的推荐写法是 Dataset/DataFrame | **`02`** 误区 5、`04` |
| 「并发问题用 Akka Actor 解决」 | 《Spark》第 3 章 | 数据并行领域「不可变 + 局部性」更优；Actor 只适合状态机场景 | **`06`** 误区 5、7 |
| 「升级只是换个 jar 包」 | 两书的隐含假设 | Spark 3.x→4.x 的 ANSI/SI 会改变语义；升级需要清单化管理 | **`04`、`10`** |
