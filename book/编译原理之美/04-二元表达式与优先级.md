# 第 4 章 二元表达式中的难点：优先级、结合性与回溯（讲 04）

> **一句话**：`1 + 2 * 3` 这种「一串运算符挤在一起」的东西，是语法分析里第一个真正难的地方——难在**优先级、结合性、左递归和回溯**这四件事会同时冒出来。

## 核心精讲

### 4.1 优先级第一件事：分层

处理二元表达式最干净的办法是**按优先级把文法分成若干层**，一层只认一种运算符：

```text
expr    : addExpr
addExpr : mulExpr (('+'|'-') mulExpr)*      {最低优先级：加和减}
mulExpr : unaryExpr (('*'|'/') unaryExpr)*   {高一级：乘和除}
unaryExpr: '-' unaryExpr | primary            {再高一级：一元}
primary : NUM | ID | '(' expr ')'             {最高级：原子}
```

**为什么分层能同时解决优先级？** 因为在递归下降里，`expr()` 调用 `addExpr()`，后者调用 `mulExpr()`……**调用的深度就是优先级的深度**。*优先级越高，递归越深、越早被绑定到叶子上。*

```
1 + 2 * 3
   expr
     addExpr
       mulExpr ── 2 * 3 在这一层就被乘号绑住了
       1
```

### 4.2 结合性：靠「左结果」还是「右结果」

```text
左结合（left-assoc）：(1-2)-3   文法用「左边的expr + 右边的新项」
右结合（right-assoc）：1-(2-3)  文法用「1 + 右边的表达式」

赋值是右结合：   a = b = c   ==>  a = (b = c)
加减是左结合：   1-2-3       ==>  (1-2)-3
幂运算常右结合：  2^3^2       ==>  2^(3^2)
```

对照写法：

```java
// 教学示意：左结合靠 while 循环，右结合靠递归（不参与构建）
AstNode leftAssoc() {                 // expr : expr ('+'|'-') term   -> 循环
    AstNode left = term();
    while (isAddOrSub(peek())) {
        Op op = toOp(next());
        left = new BinOp(op, left, term());   // 不断把新结果挂到左边
    }
    return left;
}

AstNode rightAssoc() {                // expr : term ('^' expr)?     -> 递归
    AstNode left = term();
    if (peek().type == POW) { next(); return new BinOp(POW, left, rightAssoc()); }
    return left;
}
```

### 4.3 左递归：递归下降的死穴

课程原话点到了名：**左递归**。

```text
expr -> expr ADD term | term        {左递归：expr 的定义里又出现 expr}
```

用递归下降直接写就是**无限递归**：

```java
// 教学示意：错误示范（不参与构建，会 StackOverflowError）
AstNode expr() {
    if (peek().type == ADD) {        // 又看到了 ADD？
        next();
        return new BinOp(ADD, expr(), term());   // 又一次调用 expr() -> 死循环
    }
    return term();
}
```

### 4.4 消除左递归：把「递归」换成「循环」

通用的左递归消除公式（右结合化）：

```text
A -> A α | β       ==>    A -> β A'         A' -> α A' | ε
```

对本例：

```text
expr  -> expr ADD term | term
      ==> expr  -> term rest
          rest  -> ADD term rest | ε
```

于是代码变成：

```java
// 教学示意：消除左递归后的循环写法（不参与构建）
AstNode expr() {
    AstNode left = term();
    while (peek().type == ADD || peek().type == SUB) {   // 循环代替左递归
        Op op = toOp(next());
        left = new BinOp(op, left, term());
    }
    return left;
}
```

> **ANTLR 4 的特例**：ANTLR 4 支持**直接左递归**（`expr : expr '*' term | term;` 合法），它在内部自动做左递归消除。**但间接左递归依然不支持**，且**两个二元运算符的优先级关系必须由分层文法表达**。这一点课程没有点破，是很多 `.g4` 写不出来的根本原因。

### 4.5 两种流派：隐式优先级 vs 显式优先级

| 流派 | 代表 | 写法 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| **隐式（分层文法）** | ANTLR、递归下降 | 一层一个产生式 | 优先级与结合性**从语法文件里一眼可读** | 文法文件会变长 |
| **显式（优先级表）** | yacc/bison、算符优先 | `%left ADD SUB`、`%prec` | 加一个运算符只改一行 | 优先级关系与语法分离，容易改错 |

```yacc
/* 教学示意：yacc 的%（不参与构建） */
%left LOW
%left '+' '-'
%left '*' '/'
%right POW
```

课程里对 yacc 的整体判断（原摘录已有）：

> yacc 类工具的共同特点就是，通过编写 `.y` 格式的说明文件定义语法，然后使用 yacc 命令行工具生成对应语言的源代码。

### 4.6 回溯：本课程的定义与真实代价

用户原摘录：

> 尝试一个规则不成功之后，恢复到原样，再去尝试另外的规则，这个现象就叫做「**回溯 backtracking**」。
> 在编译器编译 Java 代码时，「回溯」常常出现在语法解析阶段，特别是在处理复杂的表达式或嵌套结构时。回溯是解析器的一种策略，用来在遇到解析错误时，撤销某些步骤，回到之前的状态并尝试其他可能的解析路径。

这段话**作为定义是对的**（它就是 PEG/回溯式 LL 解析器的语义），但要补三点：

**代价一：时间**。回溯解析器最坏情况下是指数时间。

```java
// 教学示意：指数级回溯的教科书例子（不参与构建）
// 文法：  S -> A A
//     A -> 'a' A | 'a'
// 输入：  aaaaa...a（n 个 a）
// 匹配 S 的代价约为 O(2^n)
```

**代价二：代码膨胀**。每多一个可回溯的选择，就要多一份「保存现场—失败—恢复」的代码。

**代价三：错误信息变差**。因为失败太多，真正的错误点被淹没在重试里。

现代做法：**用前看（lookahead）换掉回溯**。ANTLR 4 的 `adaptivePredict()` 会按需扩展前看符号数来决定走哪条分支；LL(k) 用 k 个 Token 做决定；LR 用「移进/规约」决策略做无回溯的确定性选择。

### 4.7 讲 19 的经典疑问：为什么推导不是左递归的？

课程讲 19 的答疑标题是「对于左递归的语法，为什么我的推导不是左递归的？」。这个问题的核心在于**区分两件不同的事**：

| 概念 | 含义 |
| --- | --- |
| **左递归的文法** | 产生式形如 `A → Aα | β` 的**语法形式** |
| **左递归的推导/分析过程** | 分析器实际**从左往右、把新符号挂到左边**的行为 |

消除左递归后：

```text
文法不再是左递归：  expr -> term rest ;  rest -> ADD term rest | ε
但分析行为仍是「左结合」：  解析器仍然产生 (1-2)-3 这样的左倾树
```

**结论**：消除的是**文法里的左递归**（为了递归下降能停机），**保留的是语义上的左结合性**（为了算出正确的树）。这两者经常混为一谈，正是讲 19 答疑想澄清的。

## 版本演进

| 年份 | 事件 |
| --- | --- |
| 1960 | ALGOL 60 用 BNF 描述表达式，分层文法成为主流写法 |
| 1963 | Dijkstra 的「递归下降」思想成熟，优先级靠调用深度表达 |
| 1965 | Knuth 提出**算符优先文法**，用优先级表直接分析（比分层文法更紧凑） |
| 1971 | Wirth 的 Oberon 编译器用「项/因子两层 + 优先级循环」写表达式 |
| 1975 | yacc 的 `%left`/`%right`/`%prec` 让优先级关系**显式化** |
| 1980s | 算符优先分析在 EDSL（表达式DSL）场景广泛落地 |
| 1991 | Emer/Hook/Gschwind，*An Empirical Study of Instruction Selection*，开始量化「分层文法 vs 优先级表」的差异 |
| 2004 | PEG 用「有序选择 + 记忆化」重新解决回溯 |
| 2013 | **ANTLR 4 支持直接左递归**，内部自动消除；`adaptivePredict()` 按需扩展前看 |
| 2017 | Chevrotain 出现，主打「可 debug 的手写式 LL(k)」，明确反对隐式回溯 |
| 2019 | 本专栏上线，讲 04 与讲 19 分别覆盖「怎么消左递归」和「为什么推导仍左结合」 |
| 2022+ | Rust 的 `chumsky`/`nom` 用组合子重新表达优先级，类型系统保证不会漏 case |
| 2025–2026 | LLM 生成表达式文法时最常见的三类错误：左递归未消、优先级层次错、把右结合写成左结合 |

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「左递归 = 坏语法」 | 左递归在**文法层面**很自然、在 yacc/Earley/ANTLR4 里都能处理；只有**手写递归下降**必须消掉它 |
| 2 | 「消掉左递归后就变成右结合」 | 消的是文法形式，树形与结合性不变；见本章 4.7 |
| 3 | 「优先级靠优先级表就行」 | 显式表（yacc `%left`）与隐式分层（ANTLR）各有代价；分层文法的**可读性**是它的最大优势 |
| 4 | 「回溯只是慢一点」 | 最坏指数时间，且错误信息会被淹没；现代解析器用**前看**而非回溯 |
| 5 | 「Java 编译 `if/else if` 时大量回溯」 | javac 用前看 + 递归下降，**正常路径不回溯**；回溯主要出现在错误恢复 |
| 6 | 🔧 本课程未提 **ANTLR 4 的直接左递归** | `.g4` 里可以直接写 `expr : expr '*' term | term`，但**间接左递归仍需手工消除**，优先级仍靠分层 |
| 7 | 🔧 未提 **PEG 的「有序选择」= 把优先级写进语法顺序** | 这与 yacc 的优先级表、ANTLR 的分层是**三条不同的世界观**，见 `12` |
| 8 | 🔧 未提 **Earley 解析器天然处理左递归**（无需消除） | 讲 16–18 之外的一条备选路线 |
| 9 | 🔧 未提 **LLM 写表达式文法的高频错误** | 分层顺序写反、右结合写成左结合、漏掉一元运算符层级 |
| 10 | 🔧 未提 **Chevrotain / chumsky / nom 这类「可 debug 的手写解析器」** | 2020 年代手写 parser 的主流选择，正好是本讲「手写递归下降」思路的延续 |
