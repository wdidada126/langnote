## 核心精讲

### 5.1 先设计语言，再写编译器

设计一门小语言时，最有价值的能力是**知道该砍掉什么**：

| 该有 | 可以没有 |
| --- | --- |
| 变量、赋值、表达式 | 指针、手动内存管理 |
| if / while / for | goto |
| 函数、递归 | 并发、异常处理 |
| 基础类型（int / string / bool） | 面向对象、泛型 |
| print 作为副作用出口 | 模块系统、包管理 |

课程选的语言就是上面这一栏：够写小工具，又不至于让实现变成第二个 C++。

### 5.2 语句文法（这门语言的骨架）

```text
program   : statement*
statement : assignment | ifStmt | whileStmt | forStmt
          | returnStmt | breakStmt | continueStmt | printStmt | block
block     : '{' statement* '}'
assignment: ID '=' expr ';'
ifStmt    : 'if' '(' expr ')' block ('else' block)?
whileStmt : 'while' '(' expr ')' block
forStmt   : 'for' '(' ID '=' expr ';' expr ';' expr ')' block
returnStmt: 'return' expr? ';'
printStmt : 'print' expr ';'
```

`block` 的存在让「语句是否允许嵌套」这件事有了一个统一出口，也是后面讲 07（作用域）的种子。

### 5.3 表达式：直接复用讲 04 的分层

```text
expr       : addExpr
addExpr    : mulExpr (('+'|'-') mulExpr)*
mulExpr    : unaryExpr (('*'|'/') unaryExpr)*
unaryExpr  : '-' unaryExpr | primary
primary    : NUM | STRING | BOOL | ID | '(' expr ')' | funcCall
funcCall   : ID '(' expr? (',' expr)* ')'
```

### 5.4 AST 节点：一定要带位置信息

```java
// 教学示意：AST 节点的公共基类（不参与构建）

        this.op = op; this.left = l; this.right = r; this.line = line; this.column = col;
```

### 5.5 求值器：树遍历解释器

```java
// 教学示意：求值器骨架（不参与构建）
class Interpreter {
    Environment env = new Environment();     // 变量表，见讲 08

    Object eval(AstNode node) {
        if (node instanceof NumLit) return ((NumLit) node).value;
        if (node instanceof StrLit) return ((StrLit) node).value;
        if (node instanceof IdRef)  return env.get(((IdRef) node).name);
        if (node instanceof Binary) {         // 短路与逻辑运算在讲 09 再细化
            Binary b = (Binary) node;
            switch (b.op) {
                case ADD: return (Integer) eval(b.left) + (Integer) eval(b.right);
                case IF:  return truthy(eval(b.left)) ? eval(b.right) : 0;
                // ...
            }
        }
        if (node instanceof IfStmt) { /* 条件 + 分支 */ }
        if (node instanceof WhileStmt) { /* while (truthy(cond)) eval(body) */ }
        // ...
        throw new RuntimeError("无法求值：" + node.getClass().getSimpleName(), node);
    }
}
```

课程给出的「分析词法、语法、进行计算」这个总结，就是上面这段代码做的事情。

### 5.6 REPL：把 loop 包一层

用户原摘录里也记了这个：

> 这个输入、执行、打印的循环过程就叫做 **REPL（Read-Eval-Print Loop）**

```java
// 教学示意：REPL（不参与构建）
public static void main(String[] args) throws Exception {
    Interpreter ip = new Interpreter();
    BufferedReader in = new BufferedReader(new InputStreamReader(System.in));
    String prompt = "> ";
    while (true) {
        System.out.print(prompt);
        String line = in.readLine();
        if (line == null || line.equals(".exit")) break;
        try {
            Object v = ip.eval(new Parser(new Lexer(line)).parseProgram());
            if (v != null) System.out.println(render(v));
        } catch (CompileError | RuntimeError e) {
            System.out.println("错误：" + e.getMessage());     // 关键：不崩
        }
        prompt = "    ";                                      // 续行提示
    }
}
```

### 5.7 错误处理：分三类，不要混在一起

| 类型 | 例子 | 谁负责 |
| --- | --- | --- |
| **词法错误** | 非法字符 `@` | Lexer |
| **语法错误** | `if (x) {` 少了右括号 | Parser |
| **语义/运行时错误** | 未定义的变量、除零、类型不匹配 | Interpreter / 后续讲 09 的类型检查 |

课程讲 04 提到的「处理语法错误，让脚本解释器不会因为输入错误而崩溃」，落点就在这里的 `try/catch`。

### 5.8 这门小语言的边界（刻意的）

- **没有类型声明**：变量类型靠运行时值决定（弱类型）。
- **没有函数**：函数要在讲 07（作用域与生存期）才出现。
- **没有面向对象**：讲 09 才开始。
- **没有垃圾收集**：因为「什么都不 new  long-lived」就不存在 GC 问题，讲 33 才正面处理。

**理解边界比理解实现更重要**：一门语言的实现成本 ≈ 它的语义复杂度，而不是它的语法复杂度。

| 年份 | 事件 |
| --- | --- |

| 方案 | 速度 | 调试难度 | 课程讲次 |

| 树遍历解释 | 慢（10×~50× C） | 最易 | 讲 05 |

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「先学完整语言设计，再动手写」 | 应该反过来：**先写一个能跑的最小版本，再长它** |
| 2 | 「AST 节点不需要位置信息」 | 没有行列号，后面所有诊断信息都无从谈起；**第一版就加** |
| 3 | 「REPL 就是个循环」 | 真正的难点是**增量解析**与**跨行输入**；Tree-sitter 的增量能力对 REPL 尤其重要 |
| 4 | 「语法错误让程序崩溃没关系」 | 课程明确要求「不会因为输入错误而崩溃」；错误必须分类、必须带位置 |
| 5 | 「这门小语言是最终产物」 | 它是跳板：讲 07 加函数、讲 09 加类型、讲 23/26 加编译执行 |
| 6 | 🔧 本课程 2019 年上线，未提 **JIT 与字节码两条演进路线** | 讲 32（字节码）、讲 34（JIT）已在课程内，但**树遍历 → 字节码 → JIT 的对比表**应在本章就给出 |
| 7 | 🔧 未提 **Tree-sitter 做 REPL 的增量解析** | 现代 REPL 的实时高亮/补全依赖增量 parser，而不是每次从头解析 |
| 8 | 🔧 未提 **LLM 作为「语言语义的求值器」** | Agent 的循环结构本质就是 REPL；语言设计者要开始考虑「模型怎么读懂我的 DSL」 |
| 9 | 🔧 未提 **错误恢复（error recovery）** 的具体策略 | 课程只在讲 05 提了「不崩溃」，缺少系统方法：phrase-level recovery、token deletion/insertion、panic mode |
| 10 | 🔧 未提 **Error Message 的「建议」功能** | 2026 年的标准是错误提示要给出「你是不是想写 X」，这是编译技术里最被低估的竞争力 |
