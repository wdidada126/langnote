# 第 3 章 语法分析入门：纯手工打造公式计算器（讲 03）

> **一句话**：语法分析要回答「这串 Token 是不是合法的句子、它长成一棵什么树」；答案由**上下文无关文法（CFG）**给出，写法叫 **BNF/EBNF**，产出物叫**抽象语法树**。

## 核心精讲

### 3.1 语法规则 = 一组替换规则（产生式）

课程这句话把整件事说透了：**语法规则是由上下文无关文法表示的，而上下文无关文法是由一组替换规则（又叫产生式）组成的。**

```text
expr  -> term | expr ADD term        {产生式}
term  -> factor | term MUL factor
factor-> NUM | LPAREN expr RPAREN
```

### 3.2 BNF：Antlr 和 Yacc 都用的写法

用户原摘录里的这句话是本章最实用的知识点之一：

> **「巴科斯范式」，简称 BNF。Antlr 和 Yacc 这两个工具都用这种写法。**

BNF 的原始记法（Backus 1959 / Naur 1960）：

```text
<expr>  ::= <term> | <expr> <op> <term>
<term>  ::= <factor> | <term> <op> <factor>
```

课程配的 EBNF 更紧凑（去掉了等价递归）：

```text
expr   : term ( (ADD | SUB) term )* ;      // 注意这里已经是 ANTLR 风格了
term   : factor ( (MUL | DIV) factor )* ;
factor : NUM | '(' expr ')' ;
```

> **注意一个容易混的点**：课程上面用 `expr -> term | expr ADD term` 这种**带左递归**的写法讲概念（因为它和 BNF 课本写法一致），而 ANTLR 4 的 `.g4` 里允许**直接左递归**。这两种写法在第 04 讲会正面冲突，是本课程的一个著名「坑」。

### 3.3 终结符与非终结符

| 概念 | 定义 | 在语法树里 |
| --- | --- | --- |
| **终结符（Terminal）** | 不能再被替换的符号，对应一个 Token | 叶子节点 |
| **非终结符（Non-terminal）** | 可以进一步替换成若干终结符/非终结符 | 内部节点 |

```text
非终结符（可继续展开）   expr / term / factor
终结符（已经是 Token）   NUM  ADD  MUL  LPAREN  RPAREN
```

### 3.4 从产生式到推导

```java
// 教学示意：公式计算器的文法（不参与构建）
// 文法：
//   expr   : term (('+'|'-') term)*
//   term   : factor (('*'|'/') factor)*
//   factor : NUM | '(' expr ')'
```

对输入 `1 + 2 * 3` 的**最左推导**：

```text
expr
=> term (('+'|'-') term)*
=> 1 (+ term)*
=> 1 + term (('*'|'/') factor)*
=> 1 + 2 (('*'|'/') factor)*
=> 1 + 2 * factor
=> 1 + 2 * 3
```

### 3.5 语法树与抽象语法树

**语法树（parse tree / concrete syntax tree）** 保留每一个终结符，**抽象语法树（AST）** 只保留语义骨架：

```text
具体语法树（有括号节点）
            expr
        /    |    \
    expr    '+'   term
     |           /   |  \
    NUM        factor  '*'  term
     |          |      /  |   \
     1         NUM    '(' expr ')'
                       |   |
                      2    NUM
                            |
                            3

抽象语法树（括号消失了）
        BinOp(+)
       /       \
   Num(1)    BinOp(*)
             /      \
        Num(2)    Num(3)
```

课程在讲 03 里给的 AST 可视化链接就是看这个的：

- **AST 可视化 Demo**：`https://resources.jointjs.com/demos/javascript-ast`
- 用法：把一棵手写 AST 贴进去，直接看树形渲染结果。做语法分析时**强烈建议先把 AST 打印出来**（本课程在 PlayWithCompiler 里就是这么干的）。

> 课程提到的 https://gitee.com/richard-gong/PlayWithCompiler 是配套的交互式工程。

### 3.6 递归下降：一个非终结符一个函数

```java
// 教学示意：递归下降的骨架（不参与构建）
class Parser {
    TokenStream ts; int p = 0;

    AstNode expr() {                       // expr : term (('+'|'-') term)*
        AstNode left = term();
        while (peek().type == ADD || peek().type == SUB) {
            Op op = toOp(next());
            AstNode right = term();
            left = new BinOp(op, left, right);   // 注意：左结合靠「循环 + 左结果」
        }
        return left;
    }
    AstNode term() { /* 同理，* / */ }
    AstNode factor() {
        if (peek().type == NUM) return new Num(next().text);
        match(LPAREN); AstNode e = expr(); match(RPAREN); return e;
    }
}
```

**这个骨架同时解决了第 03 讲的两个副产品**：「计算」= 遍历这棵树；「处理语法错误」= `match()` 失败时抛异常而不是崩掉。

### 3.7 回溯 backtracking：本课程的定义

用户原摘录里写得很清楚：

> 尝试一个规则不成功之后，恢复到原样，再去尝试另外的规则，这个现象就叫做「**回溯 backtracking**」。

课程随后用 Java 的 `if / else if / else` 举例子（这段摘录也收在这里）：

```java
// 教学示意：课程用来解释回溯的例子（不参与构建）
void example() {
    if (condition) {
        expression;              // 步骤 3：尝试解析 expression
    } else if (otherCondition) {
        otherExpression;
    } else {
        defaultAction();
    }
}
```

课程描述的解析步骤是：识别方法声明 → 识别 `if` 语句 → 尝试解析 `expression;` → **失败则回溯到 `if (condition) {` 之前** → 尝试解析成别的语句类型。

**这里要给出一个更准确的技术判断**（见「常见误区」）：

- 这段摘录描述的是**通用解析器的「试错 + 恢复现场」语义**，它确实叫回溯。
- 但**现代 Java 编译器（javac）实现的并不是回溯式parser**。javac 用「递归下降 + 前看若干 Token」来**先判断、后进入**，正常路径上不回溯；「回溯」在 javac 里主要出现在**错误恢复**与**注解/注解处理器**等少数场景，而不是 `if/else` 分析的日常路径。
- 换句话说：**回溯是「通用 PEG/LL(k) 解析器」的特征，不是所有编译器的特征。** 这正是本课程讲 17/18（LL 与 LR）要解决的问题。

## 版本演进

| 年份 | 事件 |
| --- | --- |
| 1959 | Backus 在 ALGOL 58 报告中引入**巴科斯范式** |
| 1960 | Naur 主持的 ALGOL 60 修订报告正式采用 BNF |
| 1963 | 上下文无关文法被用于描述编程语言语法（而非自然语言的语言学传统） |
| 1966 | Landin 提出「the next 700 programming languages」，语法抽象被推向极致 |
| 1970 | Earley 提出**通用、任意文法、多项式时间**的 Earley 解析器 |
| 1975 | Johnson 发布 **yacc**，LALR(1) 成为工业标准 |
| 1980 | Wirth 用「递归下降 + 运算符优先级」重述表达式处理（Oberon 编译器） |
| 2004 | Ford 提出 **PEG**：有序选择 + 无回溯，从另一头解决了回溯问题 |
| 2013 | **ANTLR 4** 的 ALL(\*) 让「自适应前看」取代手工语法谓词 |
| 2016 | Chevrotain、Tree-sitter 等「可调试的手写式解析器」出现 |
| 2018 | Tree-sitter 论文（ICSE 2018）确立增量 + 容错解析 |
| 2019 | 本专栏上线，讲 03 用公式计算器把 CFG 讲成一件有手感的事 |
| 2022+ | Rust 生态的 `chumsky`、`nom` 让「组合子式 parser」成为主流选择之一 |
| 2025–2026 | LLM 能写出正确的 `.g4`，但**左递归/优先级/二义性**三类错误仍是它最常犯的 |

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「语法分析会大量回溯」 | 这是**回溯式解析器（PEG / 早期 LL(k)）**的特征；javac、Go 编译器、ANTLR 4 都尽量**前看来避免回溯** |
| 2 | 「`if/else if/else` 一定会触发回溯」 | 真实编译器用的是**前看判断 + 递归下降**，正常路径不回溯；回溯主要出现在**错误恢复** |
| 3 | 「BNF 就是 ANTLR 语法」 | BNF 是元语言 notation；ANTLR 用的是**EBNF 扩展**（`? * + ()`），Google 的 `lark` 又换了一套 |
| 4 | 「语法树 = 抽象语法树」 | 具体语法树含括号等终结符，AST 不含；课程讲 03 的图正是这个区分 |
| 5 | 「产生式左边可以是终结符」 | 产生式左部**必须是非终结符**，否则就不是上下文无关文法 |
| 6 | 🔧 本课程 2019 年上线，未提 **Earley / GLR / PEG** 三条 LR 之外的路线 | 2026 年必须补： Earley（任意文法）、GLR（Tomita）、PEG（无回溯）都应作为「LR 之外」的选择写进来，见 `12` |
| 7 | 🔧 未提 **Tree-sitter** 对「语法分析 = 一棵树」这一心智模型的冲击 | 增量解析 + 容错解析意味着「坏输入也能出树」，是 IDE 时代的新默认 |
| 8 | 🔧 未提 **ANTLR 的监听器/访问器双模式** | 本章手写 AST，讲 07 用 ANTLR 时会有两套完全不同的做法，见 `06` |
| 9 | 🔧 未提 **LLM 写语法的常见错误** | 大模型写 `.g4` 最常犯三类错：左递归未消除、优先级层次错、二义性未消解 |
