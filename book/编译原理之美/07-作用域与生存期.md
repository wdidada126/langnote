# 第 7 章 作用域和生存期：实现块作用域和函数（讲 08）

> **一句话**：「这个名字指的是哪个东西」和「这个东西活多久」是两件不同的事——前者叫**作用域（Scope）**，后者叫**生存期（Lifetime）**；编译器的活就是把这两件事同时管住。

## 核心精讲

### 7.1 三个概念先分清

| 概念 | 定义 | 例子 |
| --- | --- | --- |
| **绑定（Binding）** | 一个名字和一个实体之间的对应关系 | `x` 绑定到地址 `0x7ff0` |
| **作用域（Scope）** | 绑定**在源码中可见的范围** | `x` 只在某个 `{}` 里可见 |
| **生存期（Lifetime）** | 绑定所指向的**存储存在的时间** | 局部变量活到函数返回 |

> 一个常见错误：把「作用域」理解成「存储什么时候销毁」。**作用域是静态的、源码结构决定的；生存期是动态的、运行时间决定的。** 课程标题把这两个词放在一起，正是为了强调它们是两回事。

### 7.2 静态作用域（词法作用域）

用户原摘录里有这两个术语：

> **静态作用域（Static Scope）**
> **动态作用域（Dynamic Scope）**

```java
// 教学示意：静态作用域（不参与构建）
int x = 1;
void f() { int x = 2; print(x); }   // 打印 2
void g() { print(x); }              // 打印 1（外层 x）
void h() { f(); print(x); }         // 打印 2，再打印 1
```

规则：**名字解析沿着「定义处的词法嵌套链」向外找**，与调用者是谁完全无关。这是 C/Java/C++/Rust/Go 的共同选择。

### 7.3 动态作用域

```java
// 教学示意：动态作用域（不参与构建）
int x = 1;
void f() { print(x); }               // f 自己没有 x
void g() { int x = 99; f(); }        // 动态作用域下打印 99
void h() { g(); }                    // 打印 99
```

规则：**名字解析沿着「当前的调用链」向外找**。这是 LISP 1.5、早期 BASIC 的选择，今天只剩少数脚本（如部分 Unix shell 变量语义）还保留它。

| | 静态作用域 | 动态作用域 |
| --- | --- | --- |
| 解析依据 | 源码嵌套 | 调用链 |
| 可静态推理 | **能**（编译期就能确定） | 不能 |
| 名字冲突风险 | 低（靠块嵌套） | 高（靠调用时序） |
| 典型语言 | C、Java、Rust、Go | 早期 LISP、部分 shell |

### 7.4 符号表：作用域栈

```java
// 教学示意：基于作用域栈的符号表（不参与构建）
class SymbolTable {
    // 外层到内层：索引 0 是全局
    private List<Map<String, Symbol>> scopes = new ArrayList<>();

    SymbolTable() { scopes.add(new HashMap<>()); }   // 全局作用域在栈底

    void enterScope() { scopes.add(new HashMap<>()); }
    void exitScope()  { scopes.remove(scopes.size() - 1); }

    boolean declare(String name, Symbol s) {
        return scopes.get(scopes.size() - 1).put(name, s) == null;
    }
    Symbol lookup(String name) {                       // 内层 -> 外层
        for (int i = scopes.size() - 1; i >= 0; i--) {
            Symbol s = scopes.get(i).get(name);
            if (s != null) return s;
        }
        return null;                                   // 未声明
    }
}
```

**要点**：

- `enterScope/exitScope` 与 `{` `}` **必须在语法分析/语义分析时成对触发**，丢一次就会内存泄漏式的符号污染。
- 符号里除了名字，还要记**类型、偏移、行号**（到讲 09 才补齐类型，到讲 13 才补齐偏移）。

### 7.5 环境变量与全局环境

```java
// 教学示意：全局环境 + 函数环境（不参与构建）
class Environment {
    Map<String, Object> globals = new HashMap<>();     // 全局变量，长期存在
    Map<String, Object> locals  = new HashMap<>();     // 局部变量，函数返回即失效

    Environment parent;                                 // 静态作用域链
    Object get(String name) {
        Environment e = this;
        while (e != null) { if (e.locals.containsKey(name)) return e.locals.get(name); e = e.parent; }
        if (globals.containsKey(name)) return globals.get(name);
        throw new RuntimeError("未定义的变量：" + name);
    }
    void set(String name, Object v) { /* 找到最近的定义处再写 */ }
}
```

> 课程提到的**自举（bootstrapping）**正是这一章的产物：函数一旦被实现了「用自己写的语言写自己」，就说明语言已经能表达「名字 → 行为」这一层抽象了。Rust 的 `rustc`、Zig 的 `zig build zig`、V 语言的 V 编译器，都是走这条路的现代样本。

### 7.6 函数的实现骨架

```java
// 教学示意：函数调用（不参与构建）
class Function implements Callable {
    AstNode body;  Environment closureEnv;   // 闭包要记住定义处的环境

    Object call(Interpreter ip, List<Object> args) {
        Environment env = new Environment(closureEnv);   // 新环境，父 = 定义处
        for (int i = 0; i < params.size(); i++)
            env.locals.put(params.get(i), args.get(i));  // 绑定实参
        return ip.executeBlock(body, env);               // 执行，返回 return 值
    }
}
```

### 7.7 生存期与栈帧

```
调用 f(1,2) 时：
  +-----------------------+
  | 返回地址（ caller 的下一条指令） |
  | 参数 2                |   <- 调用者压栈
  | 参数 1                |
  +-----------------------+
  | 局部区：x, y           |   <- f 栈帧从这里开始
  | 临时区：表达式中间结果  |
  +-----------------------+
        ^ 栈指针 SP 在这里移动，f 返回时 SP 复位
```

**关键洞察**：**生存期可以用「栈指针移出作用域」一次性结束**——不需要任何显式的销毁代码，也不需要 GC。这就是「栈上分配」的美妙之处，也是 C 语言能那么快的原因之一。

### 7.8 自举

```
用 C 写编译器 v1 ──编译──> 编译器 v1（可执行）
用编译器 v1 编译「编译器自身的源码」 ──> 编译器 v2
用编译器 v2 编译「编译器 v2 的源码」 ──> 编译器 v3（与 v2 行为一致 => 自举完成）
```

自举的好处：语言特性的每一次扩展，都先要用自己来表达，逼着你把语义想清楚。Rust 用它保证了「Rust 写出来的 Rust 编译器」与「预编译的 rustc」行为一致。

## 版本演进

| 年份 | 事件 |
| --- | --- |
| 1958 | ALGOL 引入 **begin/end 块**，词法作用域的第一个大规模样板 |
| 1960 | ALGOL 60 明确采用**静态作用域** |
| 1966 | Landin 提出闭包（函数 + 引用环境），`the next 700 programming languages` 里给出形式化 |
| 1968 | Lisp 1.5 的动态作用域传统（与 ALGOL 的静态作用域分道扬镳） |
| 1970s | Pascal 的嵌套过程 + `forward` 让静态作用域的实现变得具体 |
| 1975 | **Scheme** 采用词法作用域，并给出「过程 = 代码 + 环境」的清晰定义 |
| 1977 | Unix System V shell 保留部分动态作用域语义 |
| 1983 | C 的 `extern`/`static`/块作用域定型，成为今天绝大多数 C 系语言的模板 |
| 1991 | Python 采用**函数内赋值即局部**的规则（LEGB 查找顺序） |
| 2003 | Python 2 引入嵌套函数与 `closure` 语义 |
| 2014 | Java 8 的 lambda 与** effectively final** 局部捕获规则 |
| 2019 | 本专栏上线，讲 08 用块 + 函数把符号表讲透 |
| 2019 | Python 3.8 的海象运算符 `(:=)` 在赋值与表达式之间加了一层微妙的作用域规则 |
| 2022 | Rust 的模块/路径系统把「作用域」推进到包级 |
| 2025–2026 | **LLM 在「生成带作用域语义的 DSL」时最容易出错的地方**：变量捕获与遮蔽 |

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「作用域和生存期是一回事」 | 作用域是**静态的、源码嵌套决定**；生存期是**动态的、运行时间决定**；课程标题并列二者正是为了强调这个区别 |
| 2 | 「局部变量离开作用域就销毁了」 | 语义上「不可访问」，但内存是否立即回收是实现细节；栈上分配才是「离开即回收」 |
| 3 | 「符号表就是一张哈希表」 | 必须支持**嵌套 + 遮蔽 + 退出回滚**；单层 Map 做不了 |
| 4 | 「动态作用域只是历史包袱」 | 它在**宏系统、调试器、DSL 求值**里仍有实用价值 |
| 5 | 「自举这件事只发生在 1970 年代」 | 至今活跃：`rustc` 自举、`zig` 自举、V 编译 V |
| 6 | 🔧 本课程未提 **闭包捕获的具体规则** | 闭包在第 10 讲才正面讲，但函数实现（`closureEnv`）在本章就会出现；建议提前埋线 |
| 7 | 🔧 未提 **作用域分析与借用检查的关联** | Rust 的借用检查器是「作用域分析」最现代、最严格的形式，值得对照 |
| 8 | 🔧 未提 **符号表与数据库名解析的同构性** | 建议把讲 14 的 SQL 列绑定与本章对照讲，理解成本会大幅下降 |
| 9 | 🔧 未提 **增量解析下的符号解析** | Tree-sitter 有 query 但没有符号表；IDE 的「跳转定义」需要另一套增量符号解析 |
| 10 | 🔧 未提 **名字遮蔽（shadowing）的策略选择** | 有的语言报错（Rust），有的语言静默遮蔽（C++ 块内）；这是语言设计决策，不是实现细节 |
