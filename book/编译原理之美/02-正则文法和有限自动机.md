# 第 2 章 正则文法与有限自动机（讲 02：纯手工打造词法分析器）

> **一句话**：词法分析只做一件事——**从字符流里切出 Token**；而这件事可以用一套完全形式化的机器（**有限自动机**）做对，且**时间复杂度是线性的**。

## 核心精讲

### 2.1 模式、词素、记号（务必分清）

```text
模式 Pattern  =  "标识符由字母开头，后跟若干字母数字"   <- 规则
词素 Lexeme   =  "count1"                              <- 匹配到的一段字符
记号 Token    =  <IDENT, "count1">                     <- 类型 + 值
```

### 2.2 正则文法、正则式与正则定义

词法层用的是 **3 型文法（正则文法）**：产生式的右部最多只有一个非终结符。等价工具是**正则式**（RE）。

```text
标识符:  letter ( letter | digit )*          {规则}
integer: digit+                               {规则}
letter:  [A-Za-z_]
digit:   [0-9]
```

课程里说的「正则文法」和「有限自动机」是同一件事的两面：**正则式 → NFA → DFA → 最小化 DFA**，这就是讲 02 的主线。

### 2.3 状态转换图（手画图纸）

```text
        letter
   +-------------------+
   |                   v
->(0) ---letter---> (1) --letter|digit--> (1)
   |
   +----digit----> (2)  (integer 的接受态)
```

### 2.4 NFA 与 DFA 的形式定义

```python
# 教学示意：NFA 与 DFA 的数据结构（不参与构建、不编译、不运行）
NFA = {
    "states":   {0, 1, 2},
    "alphabet": {"letter", "digit"},
    "start":    0,
    "accept":   {2},
    # 同一个 (状态, 字符) 可以映射到多个下一状态 —— 这就是 "不确定"
    "trans":    {0: {"letter": {1}},
                 1: {"letter": {1}, "digit": {1, 2}}}
}

DFA = {
    "states":   {0, 1, 2},          # DFA 的状态其实是 NFA 状态集合的子集
    "alphabet": {"letter", "digit"},
    "start":    0,
    "accept":   {2},
    # DFA 的转移是单值的
    "trans":    {0: {"letter": 1, "digit": 2},
                 1: {"letter": 1, "digit": 2},
                 2: {"letter": None, "digit": None}}
}
```

关键区别只有一条：**NFA 一个状态遇到一个字符可以走多条边，DFA 只能走一条**。所以 DFA 可以「一步确定」，NFA 需要「试」。

### 2.5 子集构造（ε-closure + move）

```python
# 教学示意：NFA -> DFA 的子集构造（不参与构建、不编译、不运行）
def epsilon_closure(states, nfa):
    """反复加 ε 边可达的状态"""
    stack, seen = list(states), set(states)
    while stack:
        s = stack.pop()
        for t in nfa["trans"].get(s, {}).get("eps", ()):
            if t not in seen:
                seen.add(t); stack.append(t)
    return frozenset(seen)

def move(states, sym, nfa):
    out = set()
    for s in states:
        out |= nfa["trans"].get(s, {}).get(sym, set())
    return out

def subset_construction(nfa):
    start = epsilon_closure({nfa["start"]}, nfa)
    worklist, dfa_states = [start], {start}
    trans = {}
    while worklist:
        S = worklist.pop()
        for sym in nfa["alphabet"]:
            T = epsilon_closure(move(S, sym, nfa), nfa)
            if T and T not in dfa_states:
                dfa_states.add(T); worklist.append(T)
            if T:
                trans[(S, sym)] = T
    return dfa_states, trans
```

**复杂度直觉**：子集构造最坏是指数（NFA 有 n 个状态时，DFA 状态可能达 2ⁿ），但对**词法分析用的正则式来说几乎从不发生**，这就是为什么工程上可以放心自动构造 DFA。

### 2.6 DFA 最小化（划分法）

```python
# 教学示意：按「接受态 vs 非接受态」反复划分（不参与构建、不编译、不运行）
def minimize(dfa):
    # 初始把状态分成 "接受组" 和 "非接受组"
    groups = [frozenset(dfa["accept"]),
              frozenset(dfa["states"] - dfa["accept"])]
    changed = True
    while changed:                       # 不动点：直到不再分裂
        changed = False
        new = []
        for g in groups:
            buckets = {}
            for s in g:
                key = tuple(sorted((sym, dfa["trans"][s][sym]) for sym in dfa["alphabet"]))
                buckets.setdefault(key, []).append(s)
            if len(buckets) > 1:
                changed = True
                new += list(buckets.values())
            else:
                new.append(g)
        groups = new
    return groups
```

### 2.7 用 DFA 驱动的手写词法分析器

```java
// 教学示意：DFA 驱动的 nextToken（不参与构建）
Token nextToken() {
    int cur = dfaStart;
    int lastAccept = -1, lastPos = pos;
    while (pos < src.length()) {
        char c = src.charAt(pos);
        int next = dfaTrans[cur][charClass(c)];
        if (next < 0) break;                 // 无路可走
        cur = next; pos++;
        if (isAccept(cur)) {                 // 记录最后一个接受态
            lastAccept = cur; lastPos = pos;
        }
    }
    if (lastAccept < 0) throw new LexError("非法字符 @ " + pos);
    pos = lastPos;                           // 回退到最长匹配之后
    return makeToken(lastAccept, src.substring(...));
}
```

### 2.8 最长匹配与关键字

- **maximal munch（最长匹配）**：`123abc` 应该整体当成标识符还是 `123` + `abc`？按最长匹配原则，它是一个标识符。
- **关键字**：课程建议**不要**在语法里为 `if`/`while` 单独造 DFA 分支，而是全部当标识符，再查一张**保留字表**：

```java
// 教学示意：保留字后处理（不参与构建）
Token t = nextToken();
if (t.type == IDENT) {
    switch (t.text) {
        case "if":  return new Token(TokenType.IF, t.text);
        case "while": return new Token(TokenType.WHILE, t.text);
        default:    return t;
    }
}
```

## 近年研究与工业界开源实践（2015–2026）

**「词法分析在 2026 年长什么样」**：手写 DFA 的时代基本结束，但「词法规则」本身反而变多了——因为日志解析、SQL、配置、契约文件都在用正则描述。

| 项目 | star（2026-09-25 实测） | 场景 |
| --- | --- | --- |
| `antlr/antlr4` | **19,015★** | 我们的 `.g4` 里就内含 lexer 规则；讲 06 直接用 |
| `rust-lang/rust` | **119,157★** | 其 `regex` crate 坚持无回溯、线性时间 |
| `intel/hyperscan` | star 未核验 | 多模式匹配，SQL 注入检测的核心组件 |
| `google/re2` | star 未核验 | 线性时间正则，被 protobuf、`git` 等大量使用 |
| `alibaba/druid` | **28,178★** | Java 版 SQL 解析：词法层的复杂之处全在标识符/字符串/注释 |
| `apache/shardingsphere` | **20,804★** | 分库分表要求零误判，词法容错要求极高 |
| `tree-sitter/tree-sitter` | **27,046★** | 词法用 LR(1) 而非 DFA，但对外接口仍是「切 Token」 |

**值得记的一个工程事实**：ANTLR 的 lexer 规则与 parser 规则写在同一个 `.g4` 里时，**lexer 规则自动获得更高的优先级**——这解决了关键字与标识符的冲突。这是本课程没展开、但非常实用的一个点。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「正则式就是所有正则引擎用的那套」 | PCRE 等**回溯型**引擎的最坏时间复杂度是指数级；RE2 / Rust `regex` / hyperscan 是**自动机型**，线性时间。词法分析选自动机型 |
| 2 | 「NFA 一定比 DFA 慢，所以直接用 DFA」 | 手写 DFA 是体力活；先用 NFA 描述、子集构造自动生成，工程上更划算 |
| 3 | 「词法分析要处理上下文」 | 正则语言**无法**匹配嵌套括号（这不是正则能表达的语言），上下文相关的一律交给语法层 |
| 4 | 「关键字要在词法层消除」 | 课程推荐：先一律当标识符，再查保留字表，减少 DFA 膨胀 |
| 5 | 🔧 本课程未提 **Unicode 与词法分析** | 2026 年的现实：`emoji`、CJK 标识符、`\u{1F600}` 这类扩展码点都要求「码点」而非「char」作为字母表元素；ANTLR 4 对此有专门的 code point 支持 |
| 6 | 🔧 未提 **Unicode 与词法分析**的第二个坑 | 源码编码（UTF-8/BOM/CRLF）必须在词法之前解决，否则第一个 Token 就是坏的 |
| 7 | 🔧 未提 **ANTLR 的 StringTemplate / 监听器 / 访问器** | 它们不在本讲范围内，但直接决定讲 07「重构脚本语言」的做法，见 `06` |
| 8 | 🔧 未提 **RE2 / hyperscan / Rust regex** 的存在 | 讲 16 自己实现一个正则工具时，正好可以和这两个「工业级正则」对照 |
| 9 | 🔧 未提 **LLM 时代正则的新用途** | 日志在线解析（`Drain` 类算法 + 正则模板）是当前很活跃的工程方向 |
