尝试一个规则不成功之后，恢复到原样，再去尝试另外的规则，这个现象就叫做“回溯 backtracking”。

在编译器编译Java代码时，“回溯”常常出现在语法解析阶段，特别是在处理复杂的表达式或嵌套结构时。回溯是解析器的一种策略，用来在遇到解析错误时，撤销某些步骤，回到之前的状态并尝试其他可能的解析路径。

下面是一个具体的例子，展示了Java代码的解析过程中可能需要回溯的情况：

```java
void example() {
    if (condition) {
        // 可能是一个复杂的表达式
        expression;
    } else if (otherCondition) {
        // 可能是另一个复杂的表达式
        otherExpression;
    } else {
        // 默认情况
        defaultAction();
    }
}
```

在解析上面的代码时，编译器会按照如下步骤进行解析：

1. 解析 `void example() {`，识别到这是一个方法声明的开始。
2. 解析 `if (condition) {`，识别到这是一个 `if` 语句的开始。
3. 尝试解析 `expression;`，如果 `expression` 非法，编译器可能会回溯到 `if (condition) {` 之前的状态。
4. 尝试解析 `else if (otherCondition) {`，识别到这是一个 `else if` 语句的开始。
5. 尝试解析 `otherExpression;`，如果 `otherExpression` 非法，编译器可能会回溯到 `else if (otherCondition) {` 之前的状态。
6. 解析 `else {`，识别到这是一个 `else` 语句的开始。
7. 解析 `defaultAction();`，如果 `defaultAction` 非法，编译器可能会回溯到 `else {` 之前的状态。
8. 最后解析到 `}`，识别到这是方法结束。

在上面的解析过程中，如果编译器在任何步骤中遇到错误（例如，`expression`或`otherExpression`非法），它会回溯到之前的状态，并尝试解析其他可能的语法结构。例如，如果在解析`expression;`时失败，编译器可能会回溯并尝试解析为其他类型的语句或表达式。
通过这种回溯机制，编译器可以更灵活地处理复杂和嵌套的语法结构，确保正确的语法分析和错误处理。
这个输入、执行、打印的循环过程就叫做REPL(Read-Eval-Print Loop)
