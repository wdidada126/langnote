# 《编译原理之美》总览与阅读地图

> **一句话**：这是一门**动手课**——用 35 讲带你从零写出一个脚本语言解释器（前端），再用 10 讲写出一个能编译成可执行文件的编译型语言（后端），共 45 讲。它不讲「编译原理考试」，讲「编译原理怎么变成你手里的工具」。

## 0. 原摘录在此，本目录是系统化重写版

- **原摘录单文件**：`book/编译原理之美/编译原理之美.md`（用户自己的摘录，含 GPL/DSL、`.y`/`.g4`/`.proto` 类比、回溯 backtracking、AST 可视化链接、PlayWithCompiler 仓库链接等要点）。
- **本目录承担全部深度笔记内容**；原摘录**不删不改**，两者并存、互相链接。
- 原摘录中已有的要点已全部吸收到对应章节，见下面的「原摘录要点归属表」。

## 5. 阅读路线建议

- **完整路线（跟着课程走）**：`01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10 → 12 → 13 → 14`，`11` 按需，`12` 中的 16/17/18 三讲建议在第 04 讲之后先粗看一遍再回来精读。

- **只想学后端/优化**：`13 → 14`，并从 `06` 借一句「IR 是分界线」作为前置。
- **时间紧的最小路径**：`01`、`03`、`04`、`06`、`14`。这五章覆盖「编译技术在业务里最常见的一Half 用法」。

## 6. 版本演进时间轴（2019 年专栏 → 2026 年现状）

| 年份 | 事件 |
| --- | --- |
| 1956 | Chomsky 建立**形式语言分层**（0 型到 3 型），今天讲「上下文无关文法」的地基 |
| 1960 | Backus 在 ALGOL 58 报告中使用**巴科斯范式（BNF）**；Naur 修订的 ALGOL 60 报告正式采用 |
| 1966 | Landin 提出 **the next 700 programming languages**，闭包（闭包 = 函数 + 环境）的概念雏形成型 |
| 1970 | Earley 发表 **Earley 解析器**（CACM 1970），是 LR 之外最重要的通用解析算法 |
| 1972–1973 | Aho 与 Ullman 出版 *The Theory of Parsing, Translation, and Compiling*，把编译理论系统化 |
| 1975 | Johnson 发布 **yacc**；Lesk 发布 **lex**，Unix 世界的编译器生成器定型 |
| 1978 | Kildall 提出**不动点法**求数据流不动点，全局优化的起点 |
| 1982 | DeRemer 与 Pennello 提出高效计算 **LALR(1) 前看集**（TOPLAS），LR 工程化难题被解决 |
| 1982 | Damas 与 Milner 给出 **Hindley-Milner 类型推断**算法 |
| 1986 | 龙书 *Compilers: Principles, Techniques, and Tools*（Aho / Sethi / Ullman）出版 |
| 1988 | Appel 出版 *Modern Compiler Implementation*，把「用经典理论写出能跑的编译器」变成可能 |
| 1989 | Chaitin 等提出**基于图着色的寄存器分配与溢出**（PLDI 1989） |
| 1992 | ANTLR 1 随 PCCTS 发布（LL(k) + 语法谓词） |
| 2004 | Ford 提出 **PEG**（解析表达式文法），「有序选择 + 无歧义」的解析世界观 |
| 2006 | 龙书第二版（紫色封面）出版，新增面向对象与垃圾回收章节 |
| 2009 | Terence Parr 出版 *Language Implementation Patterns*，与本书同为「动手派」代表作 |
| 2013 | **ANTLR 4** 发布，**ALL(\*) 自适应 LL(\*)** + 直接左递归支持 |
| 2016 | Kotlin、Swift 进入稳定期；Java 的 `invokedynamic` 让 JVM 上的动态语言实现成本骤降 |
| 2017 | 字节码联盟成立；Haas 等发表 **WebAssembly** 论文（PLDI 2017）；GraalVM .starts |
| 2018 | **TVM** 发表（OSDI 2018）；Tree-sitter 论文（ICSE 2018）确立「增量解析 + 容错解析」的 IDE 路线 |
| 2019 | 本专栏上线；**Triton** 发表（MAPL 2019）；Zig 1.0 还远，但**自举编译器**讨论升温 |
| 2020 | **MLIR** 白皮书发布（arXiv 2020.02），「多层 IR」成为编译器架构主流范式；LLVM 从 Apache 迁到 **LLVM Foundation** |
| 2021 | MLIR 正式进入 `llvm-project`（CGO 2021 论文）；ANGLE/WASM 后端持续演进 |
| 2022 | **GraalVM 22.x** 系列把多语言互操作做成生产可用；Rust 1.6x 之后 `rustc` 自举比例进一步提升 |
| 2023 | PyTorch 2.0 引入 **TorchInductor**，用 Triton 做 GPU 代码生成，「AI 编译器」正式进入主流框架 |
| 2024 | ANTLR 4.13.x 为最新稳定版；Tree-sitter 成为大量语言官方高亮/解析的默认值 |
| 2025–2026 | **大模型改变的是「写语法的人是谁」**：`.g4`/`grammar.js` 反而成了人与模型共享的机器可读契约；但**歧义消解、诊断质量、IDE 体验**这三个本书关心的老问题依然没变 |

> 一句话概括：**ANTLR 解决了「怎么写语法」，Tree-sitter 解决了「怎么让语法在编辑器里毫秒级可用」，MLIR 解决了「怎么让多个 IR 层各司其职」，而大模型改变了「为什么需要一门 DSL」的论证方式。**
