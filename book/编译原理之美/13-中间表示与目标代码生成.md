## 核心精讲

### 13.1 讲 20：后端技术全景

后端常被拆成四件事，每件事都很难：

| 任务 | 做什么 | 难度 |
| --- | --- | --- |
| **指令选择（Instruction Selection）** | IR 操作 → 目标机器的指令 | 中 |
| **寄存器分配（Register Allocation）** | 把「虚拟寄存器」映射到有限的物理寄存器 | 高（NP-hard） |
| **指令调度（Instruction Scheduling）** | 重排指令填满流水线 | 高（依赖具体微架构） |
| **窥孔优化 / 局部优化** | 局部的模式替换 | 低 |

课程的原摘录里把优化分成两类，这个划分非常好用：

> 优化工作又分为「**独立于机器的优化**」和「**依赖于机器的优化**」两种。
> 独立于机器的优化 —— 不依赖硬件特征，在 IR 上做；
> 依赖于机器的优化 —— 依赖硬件特征：寄存器优化、充分利用高速缓存、并行性、流水线、指令选择。

### 13.2 讲 21：运行时机制

「透过语法看运行时」——一段代码在运行时到底发生了什么：

```text
源代码  ->  编译  ->  目标文件（.o）
                        |
                        +-- 被链接器拼成可执行文件
                        |
                        v
                  装载进内存：
        +---------------------------+
        | 代码段 .text   (只读, 可执行) |
        | 数据段 .data   (可写)        |
        | BSS            (未初始化数据) |
        | 堆 heap        <- malloc / new |
        | 栈 stack       <- 函数帧       |
        +---------------------------+
               ^ SP 在这里生长
```

**三个必须知道的事实**：

1. **局部变量在栈上**，生存期 = 栈帧存在期间（见讲 07）。
2. **动态分配在堆上**，生存期要你自己管或交给 GC（讲 33）。
3. **全局变量在数据段/BSS**，程序启动即存在。

### 13.3 讲 22：汇编语言其实不难学

x86-64 的三种基本语句：

```asm
; 教学示意：x86-64 汇编的最小集合（不参与构建）
; 1) 数据传送
mov rax, 1              ; 立即数 -> 寄存器
mov rbx, [rsp+8]        ; 内存 -> 寄存器（偏移寻址）
mov [rsp+8], rax        ; 寄存器 -> 内存

; 2) 算术与逻辑
add rax, rbx
imul rax, rbx
cmp rax, rbx            ; 只设标志位，不存结果

; 3) 控制流
jne .L1                 ; 不相等则跳
jmp .L2
.L1:
.L2:
```

一个重要认知：**汇编「不难学，难在别处」**——难在寄存器很少、难在调用约定（Calling Convention）、难在栈帧对齐。

### 13.4 讲 23 + 加餐：栈帧

```asm
; 教学示意：一个典型的栈帧（不参与构建）
push   rbp              ; 保存旧的帧指针
mov    rbp, rsp         ; 帧指针指向当前栈顶
sub    rsp, 16          ; 为局部变量留出空间
mov    QWORD PTR [rbp-8], 42   ; 局部变量
...
pop    rbp
ret                     ; 弹出返回地址并跳转
```

函数调用完整流程：

```text
调用方                          被调用方
------                          --------
1. 传参（按调用约定：寄存器 + 栈）
2. call func
     └─ 压入返回地址，跳转到 func
3.                              3. push rbp; mov rbp,rsp   (建立栈帧)
4.                              4. sub rsp, N               (留局部变量空间)
5.                              5. ...执行...
6.                              6. mov rsp,rbp; pop rbp     (撤销栈帧)
7.                              7. ret                      (回到返回地址)
8. 清理参数（或由被调用方清理，取决于调用约定）
9. 结果放在约定的寄存器里（如 x86-64 的 rax）
```

### 13.5 讲 24：中间代码——兼容不同的语言和硬件

用户原摘录里记了这个，以及三地址码 / SSA：

> 三地址代码、静态单赋值码等不同的 IR

课程原摘录还给了「优化工作分为独立于机器 / 依赖于机器两类」，这里给三地址码的样例：

```text
; 教学示意：三地址码（Three-Address Code）（不参与构建）
t0 = 1
t1 = 2
t2 = t0 + t1        ; 每个指令最多三个操作数
t3 = t2 * 3
t4 = t0 - t3
if t4 > 0 goto L1   ; 控制流也用三地址码表达
t5 = t4
t5 = t4 + 1
L1: t6 = t5
```

**三地址码与控制流图（CFG）**：把三地址码按基本块（Basic Block）切分，块之间的边就是控制流：

```text
      t0=1; t1=2; t2=t0+t1; t3=t2*3; t4=t0-t3
         |                                  |
         |  if t4 > 0 goto L1               |  (fall-through)
         v                                  v
   L1: t6 = t5                    t5=t4; t5=t4+1
```

### 13.6 讲 25：LLVM 不仅仅让你高效

```java
// 教学示意：前端只需要会「生成 IR」（不参与构建）
Module m = new Module("my_lang");
IRBuilder b = new IRBuilder(m);
Function f = m.addFunction("fib", i32, List.of(i32));
Value arg = f.arg(0);
BasicBlock entry = b.appendBasicBlock(f, "entry");
b.positionAtStart(entry);
Value base = b.createICmpULT(arg, b.getInt32(2), "is_base");
Value ret = b.createSelect(base, arg, computeFib(m, arg));
b.createRet(ret);
m.verify();            // 生成完一定要 verify
```

**LLVM 带来的三件事**：

| 收益 | 说明 |
| --- | --- |
| **后端白拿** | 寄存器分配、指令选择、SSE/AVX 自动向量化都免费 |
| **多语言复用** | Clang（C/C++）、rustc（Rust）、SwiftC、DragonE 全部输出到 LLVM IR |
| **多目标复用** | 同一个 IR 编译到 x86 / ARM / RISC-V / WASM |

### 13.7 讲 26：生成 IR——实现静态编译的语言

从 AST 到 IR 的模式，本质上是**对 AST 做一遍遍历，每个节点生成一个（或几个）IR 指令**：

```java
// 教学示意：AST -> IR（不参与构建）
Value gen(Binary b) {
    Value l = gen(b.left), r = gen(b.right);
    switch (b.op) {
        case ADD: return builder.createAdd(l, r);
        case MUL: return builder.createMul(l, r);
    }
}
Value gen(IfStmt s) {
    Value cond = gen(s.cond);
    BasicBlock thenB = appendBB("then"), elseB = appendBB("else"), endB = appendBB("end");
    builder.createCondBr(cond, thenB, elseB);
    builder.positionAtStart(thenB); gen(s.then); builder.createBr(endB);
    builder.positionAtStart(elseB); if (s.els != null) gen(s.els); builder.createBr(endB);
    builder.positionAtStart(endB);
    return null;
}
```

**LLVM IR 的类型系统**（课程 2020-11 的摘录里提到过「介绍 LLVM IR 类型」）：

| 类型 | 含义 |
| --- | --- |
| `i1 / i32 / i64` | 整数位宽 |
| `float / double` | 浮点 |
| `ptr` | 指针（ opaque pointer，LLVM 15+ 默认） |
| `[n x T]` / `T*` | 数组与数组指针 |
| `{T1, T2}` | 结构体 |
| `T (@params)` | 函数类型 |

> **LLVM IR 是强类型的**：没有类型就没法生成正确代码，这一点与玩具语言的动态类型形成鲜明对照。

### 13.8 讲 29/30：目标代码生成与优化

```text
IR  ->  [指令选择]  ->  线性/树重写 IR  ->  [寄存器分配]  ->  物理寄存器 IR
                                              |
                                          [指令调度]  ->  最终汇编
```

**指令选择**：把 IR 的抽象操作映射到目标指令。经典算法有 tree rewriting（重排 IR 树，用动态规划选最优覆盖）与 peephole（局部模式匹配）。

**寄存器分配**：

```python
# 教学示意：线性扫描分配器的核心（不参与构建）
# 1. 给每个值算生命周期区间（liveness interval）：def 到最后一次 use
# 2. 按起始位置排序
# 3. 遍历，尽量复用已结束的寄存器；没有可复用的就 spill 到栈
```

| 算法 | 特点 |
| --- | --- |
| **图着色**（Chaitin 等） | 经典，把冲突图着色；K 个寄存器 = K-着色 |
| **线性扫描**（Poletto & Sarkar） | 快，编译速度优先，LLVM 早期用 |
| **PBQP** | 分区基于图划分，LLVM 现在默认（Ryzen 上的结果常更好） |

### 13.9 讲 32：字节码生成——为什么 Spring 技术很强大

```text
.java  ->  javac  ->  .class（字节码 + 常量池）  ->  JVM 解释 + JIT
```

字节码是 IR 的一种：**平台无关、稳定、可验证、可被 JIT 二次编译**。Spring 技术栈里大量的「运行时生成字节码」（AOP 动态代理、MyBatis 的 Mapper 代理、CGLIB）都是「生成 IR」思维的直接体现——**用字节码当 IR，就能免费获得跨平台与 JIT 优化**。

### 13.10 讲 33：垃圾收集

```java
// 教学示意：可达性分析（不参与构建）
Set<Object> live = new HashSet<>();
Deque<Object> worklist = new ArrayDeque<>();
rootSet().forEach(o -> { if (live.add(o)) worklist.add(o); });   // 根集合：栈、全局、寄存器
while (!worklist.isEmpty())
    for (Object ref : referencesOf(worklist.remove()))           // 遍历字段/数组元素
        if (live.add(ref)) worklist.add(ref);
// 剩下不在 live 里的对象就是垃圾
```

| 方案 | 代表 | 特点 |
| --- | --- | --- |
| **引用计数** | CPython（部分）、Objective-C ARC | 即时回收，但不能处理循环引用 |
| **标记-清除 / 压缩** | JVM 的 Serial/Mark-Sweep | 经典 |
| **分代（Generational）** | JVM 的 G1/ZGC、HotSpot | 大多数对象死得早 |
| **拷贝（Copying）** | JVM 的新生代、Go 的部分场景 | 无碎片，需双倍空间 |
| **增量 / 并发** | ZGC、Shenandoah、Go GC | 停顿时间可控 |

**2026 年必须补的一条**：**MLIR**——本章 13.6 若只讲「单层 IR」已经过时。真实编译器（尤其是 AI 与异构计算）用的是**多层 IR**：

```text
TensorFlow/PyTorch 计算图  ->  MLIR Dialect（高层语义）
                          ->  linalg / tensor  Dialect
                          ->  memref  Dialect（内存视图）
                          ->  llvm Dialect（LLVM IR）
                          ->  目标机器码
```

「每一层只做该层的事，下层只认下层的抽象」——这是 2020 年之后编译器架构最重要的变化。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「中间表示就是三地址码」 | 三地址码是**一种** IR；还有栈式（Java 字节码）、SSA（LLVM IR）、树（AST）、图（计算图）。 |
| 2 | 「SSA 就是给变量起新名字」 | SSA 的核心约束是「**每个变量只被赋值一次**」，它让数据流分析变得可以直接读 |
| 3 | 「寄存器分配随便排」 | 它是 NP-hard；实践中用图着色、线性扫描、PBQP 三种算法 |
| 4 | 「GC 就是标记-清除」 | 还有分代、拷贝、增量、ZGC 的读屏障等；讲 33 只讲了概念层面 |
| 5 | 「LLVM 只是个 C++ 编译器」 | 它是**一套 IR + 一套 pass + 多语言/多目标的基础设施** |
| 6 | 🔧 本课程 2019 年上线，对 **MLIR** 完全空白 | 2026 年必须补：多层 IR 是本章最大的过时点，见 13.6 |
| 7 | 🔧 未把「**自举编译器**」作为工程范本 | 建议补：`rustc` 用 Rust 自举、`zig` 用 Zig 自举，是「现代小型编译器」最值得照抄的架构 |
| 8 | 🔧 未提 **Rust 的借用检查器 = 编译期内存管理** | 它把本章 13.10 的 GC 问题提到了编译期，是运行时机制的重要对照 |
| 9 | 🔧 未提 **eBPF 编译器**（LLVM BPF 后端 + `libbpf`） | 本章的 IR/代码生成在 2026 年最活跃的落点之一 |
| 10 | 🔧 未提 **WASM 作为 IR 的目标格式** | 讲 32 的字节码思路在 WASM 上更彻底：栈式 IR + 沙箱 + JIT |
| 11 | 🔧 未提 **LLVM 的 opaque pointer**（LLVM 15+ 默认） | 类型指针被统一成 `ptr`，是所有 IR 教程都需要更新的一处 |
