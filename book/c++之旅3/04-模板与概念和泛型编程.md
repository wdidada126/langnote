## 核心概念速览（中英对照）

- **类模板** — class template：类型参数化的类型生成器；使用即实例化。
- **函数模板** — function template：实参推导（deduction）决定模板参数；`template` 关键字可省（CTAD 语境）。
- **模板实参推导** — template argument deduction：含引用坍缩（reference collapsing）与转发规则。
- **受限模板参数** — constrained template parameter（书中旧机制：`typename`/SFINAE 时代过渡写法）。
- **变量模板** — variable templates：`template<class T> constexpr T pi = ...;`。
- **别名模板** — alias templates：`template<class T> using Vec = std::vector<T, My_alloc<T>>;`。
- **编译期 if** — `if constexpr`（C++17）：未选中分支**不求值不实例化**，模板元编程的分水岭。
- **Lambda/闭包** — lambda expression：匿名函数对象，捕获列表按值/按引用/init-capture。
- **概念** — concept（C++20）：对模板参数的具名编译期谓词，`requires` 表达式书写约束。
- **约束蕴含** — subsumption：重载决议比较约束的逻辑强弱，而非"签名谁更特化"。
- **变参模板** — variadic templates：`Ts...` 参数包；`sizeof...` 计数。
- **折叠表达式** — fold expressions（C++17）：`(args + ...)` 四种形态替代递归展开样板。
- **完美转发** — perfect forwarding：`T&&`（转发引用）+ `std::forward<T>` 保值类别穿透。
- **模板编译模型** — inclusion model：定义须在实例化点可见（头文件放定义），`export` 关键字已死。

## 设计视角：动机 → 机制 → 权衡 → 相邻对比

**动机：模板报错为什么是"灾难"以及 concepts 修了什么。**（书之大意）SFINAE 时代，未满足约束的实参
让编译器"试着编译每种可能"，错误从实例化深处喷涌。concepts 的三重目的被 Stroustrup 反复强调：
①接口即文档（约束写在签名上）；②报错前置（"不满足 std::integral"一行说清）；
③**基于约束的重载**——这是以前 `enable_if` hack 在做的事，现在有了语义内核（subsumption 比较约束强弱）。
权衡：concept 是编译期谓词而非类型，**它不进重载的名字查找、不参与偏序的全部**——书中 8.2.6
"类型与概念"专门辨析：`SomeConcept auto x` 与 `x : SomeConcept` 的推导差异。这段是全书密度最高的
语言条款之一，深读请直接跳 [../C++20模板元编程/04-高级模板的概念.md](../C++20模板元编程/04-高级模板的概念.md)
（Bancila 给了标准库概念树全图）——本目录视其为 concepts 的"地形册"。

**机制：参数化操作三阶梯。** 函数模板（编译期单态化，内联到极致）→ 函数对象（可携带状态、可传型参）→
lambda（就地匿名函数对象，捕获替代状态）→ `std::function`（类型擦除的运行期代价，书归第 16 章"函数适配"）。
设计视角：C++ 泛型的**零开销**靠的是"早绑定"——模板在编译期生成专型代码，与虚表的"晚绑定"互补；
第 5-6 章用虚函数处理"类型集合开放"，第 7-8 章用模板处理"操作集合开放"，
这就是 Stroustrup 的"两种多态各管一头"（对照 [../C++语言的设计与演化/08-模板：泛型的前史.md](../C++语言的设计与演化/08-模板：泛型的前史.md)）。

**机制：`if constexpr` 与折叠表达式的定位。** 前者终结"标签分发/偏特化模拟分支"时代
（对比 2005 年的 MPL 递归展开，见 [../C++模板元编程.md](../C++模板元编程.md) 的世界），
后者终结"递归实例化求和"样板（`void print(Ts... ts)` 旧写法 vs `((cout << ts << ' '), ...)`）。
🔧 本机基线实测（g++ 15.2 `-std=gnu++20`）：`template<std::integral T> constexpr T gcd(T,T)` 编译期断言通过、
lambda 捕获/折叠组合通过——书 ch7-8 全部示例可在该配置复现。
🔧 同一实验的"两个时代"写法对照（t16，`-std=gnu++20` 编译运行，输出 `5 5 1.25`）：

```cpp
// SFINAE 时代：约束藏在签名噪声里，报错从深处喷涌
template <class T, std::enable_if_t<std::is_integral_v<T>, int> = 0>
T half(T v){ return v / 2; }
// concepts 时代：接口即文档，且约束可直接参与基于约束的重载
template <std::integral T>        T half2(T v){ return v / 2; }
template <std::floating_point T>  T half2(T v){ return v * T(0.5); }
```

传 `std::string` 给 `half2` 时，调用点报 `no matching function for call to 'half2(std::string)'`，
候选行直接显示 `requires integral<T>`——归因从"模板体内部第 200 行"提前到"签名这一行"（8.1 三重目的②的实感）。

**权衡：模板编译模型（8.5）为什么仍要求"定义进头文件"。** 包含模型（inclusion model）把实例化推迟到
使用点，因此定义必须可见；C++20 modules 从根上换了答案（编译器为模板存"已编译语义"），
`export` 关键字（C++98/11 的失败尝试，D&E 的活化石）已移除。书的坦白与附录 A 的"过渡期"口径一致：
现阶段模板工程仍活在头文件世界里，modules 是还债路线。

**相邻对比：** 与 Rust 泛型（trait bound 从诞生就有约束语义）、与 Java 泛型（类型擦除+通配符）相比，
concepts 的独特处是**约束是普通 constexpr 布尔表达式**——可以任意组合、由库作者自造概念，
无需语言级"接口"仪式；代价是概念不进入链接层，两个 TU 可合法地用不同概念约束同一函数签名
（ODR 灰色地带，概念等价性检查 ⚠️ 标准至今未完成）。

## 最新演进与工业实践（第 3 版止于 C++20，本节补 C++23/26）

- **pack indexing（C++26，P2662R3 ✅标题 "Pack Indexing"）**：`Ts...[0]` 直接取参数包第 N 项，
  终结"为了取一个元素先包 tuple 再 get"的仪式——本目录 03 章 tuple 例子的现代改写。
- **static reflection 进发 C++26（P2996R3 → R13，标题 "Reflection for C++26" ✅wg21.link+索引双实测）**：
  `^struct S`、`std::meta::annotations` 等；一旦定稿，本章的"约束文档化"将升级为"结构可枚举"——
  序列化/ORM 样板（书中只能靠概念约束）改由编译器生成。GCC 现状：P2996 系列未完整实现（⚠️ 跟踪版本号未核）。
- **`std::generator`（C++23，P2502R2 ✅）** 用协程给"惰性等差数列"，函数模板作者第一次不必手写 promise_type
  （机制详解见 [08 章](08-范围与指针容器.md)、协程见 [10 章](10-并发.md) 18.6）。
- **概念基础设施的库化**：range-v3 的作者 Eric Niebler 主导的 std::ranges 概念树已成标准库骨架；
  abseil 以 `Requires` 注释+static_assert 自造约束层（C++17 兼容包袱）；folly 的 `FOLLY_REQUIRES` 系宏
  在 C++20 模式下多数退化为 concepts 包装 ⚠️（细节未逐条核，方向如上）。
- **支持矩阵**：GCC 10 起 concepts/ranges 齐备、11+ 修复推导角坑；本机 GCC 15.2 对本书 ch7-8 语法零障碍
  （-std=gnu++20 全过，见上实测）；clang 15+/MSVC 17.4+ 同等可用（未本机实测，⚠️ 转述矩阵页）。

## 常见误区

1. "concept 就是带检查的 typename"：它不限制实例化次数（同约束不同实参照样 N 份代码），也不产生类型——
   约束失败在调用点报"不满足"，而非在定义处报"找不到类型"。
2. 用 `requires` 写只有实现可见的谓词，再在重载里依赖强弱判定：subsumption 是**语法级蕴含**比较，
   两个逻辑等价但写法不同的 concept 不可比较强弱（书 8.2.2 的警告；深坑，见 Bancila 册）。
3. `template<> auto f(auto x)` 混用缩写模板与显式约束：二者可互相转换但语义细节（推导时机）不同——
   书 8.2.5 用"abbreviated function template"正名。
4. 把 `std::forward<T>` 用在非推导模板参数上："完美"前提是 `T&&` 是转发引用；写成 `T& &&` 只是右值引用。
5. 给模板参数加约束后删掉全部防御：`static_assert` 依然值得保留在概念定义内部（报错归因更快）。
6. 以为 concepts"治好了"两阶段名字查找：约束管的是"能不能实例化"，非依赖名仍在定义点查找、
   `typename T::size_type` 一个都省不掉——那是模板编译模型（8.5）的另一层债。
7. 把约束全写成体内 `static_assert`：它在重载**选定之后**才报错，等于放弃 8.2.2 的基于约束重载；
   约束要出现在签名上才参与强弱比较。
