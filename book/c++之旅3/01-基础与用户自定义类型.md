## 核心概念速览（中英对照）

- **直接映射到硬件** — direct mapping to hardware：指针即地址、对象即内存布局，语言不隔层虚拟机。
- **统一初始化** — uniform (list) initialization：`{}` 通用于标量/聚合/ initializer_list，收窄需显式。
- **收窄转换** — narrowing conversion：`int d{i}` 若丢信息则编译错误，替代 C 的隐式截断。
- **编译期常量** — `constexpr` / C++20 `consteval`：constexpr 编译期或运行期均可，consteval 只能编译期。
- **空指针字面量** — `nullptr`（C++11）取代 `NULL`/`0`：类型安全，不与整数重载歧义。
- **数组退化** — array-to-pointer decay：数组传给函数丢失长度，故书中导向 `span`/`array`。
- **原始数组** — C-style array（`int a[10]`）：仍是别的容器的实现底座，不直接用作接口。
- **结构** — `struct`：公有的数据成员打包，"plain old data" 的 C++ 表达。
- **联合** — `union`：共享存储的互斥成员，无类型标签，安全性靠手工纪律。
- **具名枚举** — scoped `enum class`：不隐式转整数、不泄漏枚举量到外层作用域。
- **位域** — bit-field：`unsigned int flags : 8;` 用位宽换紧凑，代价是取不了成员地址。
- **字段代理** — field proxy：bit_field 类用 `operator=`/隐式转换伪造"可引用的位"。
- **值语义** — value semantics：UDT 像 int 一样可拷贝、可放栈、可赋值的默认能力。

## 设计视角：动机 → 机制 → 权衡 → 相邻对比

**动机：为什么第 1 章就讲指针？**（书之大意）C++ 的世界观是"你能看见机器的样子"。
指针/数组/引用不是历史包袱，而是与硬件的契约：`int*` 就是地址，对象就是可按字节检视的内存。
Stroustrup 的写法很诚实——先承认 C 风格数组"不做范围检查、会退化成指针"这些坑（1.7），
再立刻给出当代答案：能不用裸数组就不用，接口用 `std::span`（第 15 章），持有用 `vector/array`。
这是 Tour 全书通用的"先兼容现实、再指向理想"叙事。

**机制：初始化是一等公民。**（1.4.2）`{}` 初始化 2012 年后被反复"扶正"，本书口径：
默认用 `{}`，因为它杜绝默认初始化漏写、并把收窄转换变成编译错误：

```cpp
// 🔧 书之大意复现（g++ -std=gnu++20 实测可编）
int i1;          // 不确定值(局部)——危险写法,书中点名
int i2{};        // 0
int i3{999.9};   // ❌ 编译错误: double→int 收窄
int i4 = 999.9;  // 静默截断为 999——C 的旧罪,合法保留
```

权衡：`{}` 与 `initializer_list` 构造函数存在著名的"花括号劫持"（`vector v{10}` 是 1 个元素而非 10 个），
本书把这一坑留到第 12 章再爆——导览书的节奏感，此处先建立习惯。

**机制：constexpr/consteval——把计算搬到编译期。**（1.6，第 3 版重写节）
`const` 只管"不可改"，`constexpr` 管"能在编译期算"；C++20 的 `consteval` 再收紧一档：只许编译期算。
这条线正是第 7-8 章模板计算、第 17 章数值优化的地基。设计视角：C++ 不另发明"编译期语言"，
而是让**同一套子集语法**在两个阶段都合法（constexpr 函数是"阶段多态"），代价是子集规则复杂——
复杂规则本身就归模板章和 [../C++20模板元编程/](../C++20模板元编程/) 深读。

**机制：union 为什么存在了 40 年还这么原始？**（2.5）union 给的是"存储重叠"这一硬件事实，
但把"当前存的是哪个成员"的类型标签义务留给了程序员——unsafe by design，因为加标签=加开销，
违反零开销原则（详见 [../C++语言的设计与演化/02-语言设计规则与演化方法论.md](../C++语言的设计与演化/02-语言设计规则与演化方法论.md)）。
书的处方很干脆：现实代码里 **enum class + switch 手工配对**是最低成本的安全网；
真正的答案（带标签、带值语义的判别式联合 `std::variant`）押后到第 15 章——
对比 `variant` 之后你会理解"语言不加、库来补"是 C++ 演化的主路径。

**相邻概念对比：struct vs class vs enum class vs union vs bit-field。**
五者是一张"数据布局菜单"：struct=全公有 class 只是默认访问不同（2.2）；enum class 是"受限整数+类型隔离"
（2.4，隐式转 int 被禁是刻意的——C 的 enum 是类型系统的特洛伊木马）；union 放弃类型安全换空间；
位域换紧凑但失去取址与原子操作友好性（代理类技巧 2.5 末是给进阶读者的钩子）。
第 3 版在这里的新增口径：**优先 enum class，永远别用无标签 union 传接口**。

## 最新演进与工业实践（第 3 版止于 C++20，本节补 C++23/26）

- **`std::bytes`（C++23）→ `std::text_encoding`（C++26）**：为"字节序列≠字符串"正名。提案号本次未核到定稿号，
  ⚠️ 只述方向。**本机实测**：g++ 15.2 libstdc++ 无 `__cpp_lib_stdbytes` 宏（`-std=gnu++23`），即该特性未实现。
- **deducing this（C++23, P0847R7 ✅wg21.link+标题实测）**：成员函数第一参数可写 `this Self&&`，
  一个模板同时接住 lvalue/rvalue/const 四象限——直接替代第 2 章"字段代理"和第 6 章"setter 族"的手写组合爆炸。
  🔧 实测（`-std=gnu++23` 编译运行通过）：

  ```cpp
  struct Widget {
    template <class Self> void build(this Self&& self) {
      std::printf("value kind: %s\n",
        std::is_lvalue_reference_v<Self> ? "lvalue" : "rvalue");
    }
  };   // w.build() → lvalue；std::move(w).build() → rvalue；-std=gnu++20 下报"仅 c++23"
  ```
- **`static operator()`（C++23, P1169R4 ✅）**：`static constexpr int operator()(int,int)` 合法，
  无状态函数对象终成"全静态"——与本章 1.6 constexpr 一脉相承（对照实验见 [03 章](03-类与基本操作.md)）。
- **GCC/Clang 支持矩阵现状**：上两特性 GCC 12/13 起可用（本机 GCC 15.2 全部通过）；
  abseil/folly 等库仍以 C++17/20 为基线（abseil 官方声明支持到 C++20；C++23 采纳进展 ⚠️ 未逐一核实，
  此处只给方向：新库代码的 baseline 正从 17 迁到 20/23）。
- **cppreference 对照**：本章每小节在 cppreference 均有对应"语言支持矩阵"页（Feature-test macros），
  用 `__cpp_constexpr >= 201907L/202110L` 可脚本化检测 consteval/if constexpr 支持度——导览书不讲的工程落地细节。

## 常见误区

1. `int x;` 后"忘了初始化"：语言不提供"默认毒值"，靠的是工具链兜底——`-Wall` 的 `-Wuninitialized`、
   MSVC `/W4`、clang-tidy `bugprone-*` 检查族；标准侧 C++23 只改了属性可忽略性
   （P2552R3 "On the ignorability of standard attributes" ✅标题实测），初始化纪律仍属工程约定。
2. 以为 `{}` 一律更安全：它有 initializer_list 劫持与 `explicit` 交互的暗坑（第 12 章 vector 处回收此债）。
3. enum 当位标志用 `|` 混型：应写 `enum class` + 显式位运算重载（或 C++23 `std::to_underlying` 一把梭，见 [09 章](09-实用工具与数值计算.md)）。
4. 把 union 当"轻量 variant"直接跨线程读：无标签+无同步，UB 双杀；要共享可变判别对象请用 [10 章](10-并发.md) 的原子/锁纪律。
5. 以为"传数组给了函数整个数组"：`void f(int a[10])` 收到的是退化的 `int*`，`sizeof(a)` 是指针不是数组；
   长度必须另传，或直接换成 1.7 建议的 `span`/`array` 接口。
6. 头文件顶层 `using namespace std;`：把上百个名字灌进全局命名空间，污染下游所有包含者（1.x/3.x 反复
   叮嘱的旧坑，附录 A 的 `import std;` 讨论里它换了个马甲仍然存在——名字可见性永远是被设计出来的）。
7. 拿 `constexpr` 当"强制编译期计算"：它是"允许编译期算"，实参不定时仍生成运行期版本；要"只许编译期"
   用 `consteval`——这也是 1.6 把两个关键词并列讲的原因。
