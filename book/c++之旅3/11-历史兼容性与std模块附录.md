## 核心概念速览（中英对照）

- **大事年表** — chronology of C++：B(1970s)→C→"C with Classes"(1979)→C++(1983)→C++98→C++11→…→C++20 的坐标系。
- **带类的 C** — C with Classes：C++ 的前身形态；本书用它警示"把 C++ 当 C 用"是过时方言。
- **方言与子集** — dialects / subsets：每个标准添一种方言，项目应显式选定一致的子集与风格。
- **渐进演化** — gradual evolution：不破坏既有代码的演化纪律，代价是历史包袱与 ABI 稳定承诺。
- **二进制接口** — ABI（application binary interface）：标准不规定，源码兼容 ≠ 目标文件兼容。
- **特性测试宏** — feature test macros：`__cplusplus` 与 `__cpp_lib_*`/`__cpp_*`，跨版本兼容文化的正规工具。
- **兄弟语言** — sibling languages：19.3.1 的定位——C 与 C++ 同根分治，不是父子，更不是超集关系。
- **`extern "C"`** — 链接规格：两语言互操作的正门，只保函数签名与平凡数据布局。
- **移除与弃用** — removed/deprecated：register、动态异常规范、`random_shuffle`、trigraphs 等的墓志铭（19.2.9）。
- **std 模块** — `import std;` / `module std;`：附录 A 主题——标准库作为模块导入（本书写作时未定稿）。
- **头单元** — header unit：`import <vector>;` 式过渡形态，与聚合模块包装（A.4）配套出现。

## 设计视角：动机 → 机制 → 权衡 → 相邻对比

**动机：导览书为什么用 47 页历史收尾？**（书之大意）Stroustrup 的判断是：C++ 使用者最大的坐标迷失，
是把"我用的编译器支持的"误当"C++ 支持的"、把"我部门风格的"误当"C++ 风格的"。最后一章给出三件坐标系：
年表（特性属于哪一代）、方言论（风格是选型不是对错）、C/C++ 关系（兄弟不是父子）。这也是全书
"zero overhead + 渐进演化"设计哲学的自白页：19.1.6 的模型与 [../C++语言的设计与演化/01-C++的设计目标与约束：从史前到诞生.md](../C++语言的设计与演化/01-C++的设计目标与约束：从史前到诞生.md) 互为摘要与全文。

**机制：年表与特性表的正确读法。** 年表主干（通行史实）：B（1969-1973，贝尔实验室）→ C（约 1970-1973，
K&R）→ "C with Classes"（1979，Stroustrup 为模拟软件分布式化而造）→ 更名 C++、virtual/引用/`const`/
`operator new`（1983-1984）→ 首本专著与 Cfront 发布（1985）→ ARM（1989，语言史实上的"预标准"）→
委员会标准化（1990s 初，与 C 同根分道）→ C++98 → C++03（缺陷修复）→ C++11（"新基线"，近乎新语言）→
此后每 3 年一版：C++14/17/20/23。19.2 的八张表（语言×库各四代）教的是查表法：**遇到任何特性先问
"哪年进的标准"，再问"我的实现矩阵哪天给的"**——这两个日期可能相差十年以上（见下节实测）。

**权衡：兼容是资产也是税负。** 源码级向后兼容承诺让 30 年代码仍可编译，代价是：语言里永远留着
"能跑但别写"的层（裸数组、`union` 的手工标签、动态异常规范移除前的怪胎，呼应
[01 章](01-基础与用户自定义类型.md)的 union 弱点论）；ABI 不在标准内意味着跨厂商二进制混用没有
承诺，"兼容"在工程上退化为"同一工具链内重编译"。19.2.9 的移除清单（register、`auto` 存储类、
trigraphs、动态异常规范、`random_shuffle`、`gets`、`std::iterator` 基类等；各项归属版本细节以
原书表为准 ⚠️ 本次未逐条核对）说明委员会其实在slowly还债——但每笔债都拖了 9-19 年。

**相邻对比：兄弟而非父子。** 19.3.1 的核心论点：C1999/C11/C17/C23 与 C++1998/11/14/17/20 是各自
独立演化的两门语言，交集（块结构、值语义、`struct` 的平凡布局、`extern "C"` 函数签名）才是可安全
共享的地带。常见误读是把"C++ 是 C 的超集"（只在 1985 年前后近似成立）当永恒真理。19.3.2 的
兼容性问题（书之大意归纳）：枚举尺寸与不完整枚举、`const` 在两个语言里的链接性差异、柔性数组成员、
VLA（C 有 C++ 无）、 designated initializer 语义差异、复合字面量——清单以原书为准 ⚠️。工程结论
只有一条：**跨界只传平凡可布局数据与纯函数指针，其余各写各的**。

### 🔧 实测：`__cplusplus` 与特性测试宏是"年表×实现矩阵"的最佳教具

g++ 15.2（`-std=gnu++23`，本机临时目录，t13/t14 实录输出节选）：

```text
__cplusplus = 202302
__cpp_lib_expected 0x315E3   __cpp_lib_generator 0x315DF   __cpp_lib_flat_map 0x315DF
__cpp_lib_to_underlying 0x31576   __cpp_lib_print 0x315E3   __cpp_static_call_operator 0x315DF
__cpp_if_consteval 0x3157A   __cpp_lib_is_scoped_enum 0x3151B
__cpp_lib_mdspan (absent)    __cpp_lib_stdbytes (absent)   __cpp_lib_hazard_pointer (absent)
__cpp_implicit_copy_elision (absent)   __cpp_deduce_this/__cpp_deducing_this (absent)
```

三个诚实结论：① `__cpp_lib_print` 已定义但本机 `std::print` **链接失败**（MinGW 运行时缺口，见
[00 章实测表](00-总览与阅读地图.md)）——特性宏测的是"头文件声称有"，不测"运行时真能跑"；
② deducing this 编译可用但 GCC 15 不发对应特性宏——**GNU 扩展式提前实现可以不守宏纪律**；
③ mdspan/bytes/hazard_pointer 缺席——同一年份标准，同一版本号编译器，矩阵进度各不相同。
这正是 19.2 八张表教的方法论：查标准表定"哪年"，查实现矩阵（libc++/libstdc++/MSVC STL 支持表）定"哪天"。

### `import std;` 现状（附录 A 的 2026 后日谈）

- 附录 A 的立场（书之大意）：A.2 **先用实现提供的**（写作时部分编译器已有实验性 `import std`）；
  A.3 用头文件永远合法，不是落后标志；A.4 自制聚合 `module std`（把常用头包成头单元再
  `export import`）是等得起之前的过渡桥；A.5 建议：模块化的首要收益在**你自己的代码**
  （编译防火墙 + 显式导出），不必为 `import std` 阻塞采纳 modules。
- 2026 现状 ⚠️ 本次未逐一核厂商文档：MSVC STL 已正式提供 `std`/`std.compat` 模块（VS 2022 系）；
  GCC/libstdc++ 本次未验证到可用 `import std;`；Clang/libc++ 进展中。P2465R3 标题里的
  "std.compat"（导入时同时暴露全局名以兼容 `<C 头>` 混用）说明：**std 模块的难点不在快，
  在与 40 年头文件文化的共存**——这是 19.3 兄弟论在模块时代的翻版。

## 常见误区

1. "C++ 是 C 的超集"：1985 年前后近似成立，此后是分家兄弟；用 C 惯用法写 C++（typedef struct、
   手工标签 union、`malloc` 配析构）= 活在被 19.2.9 移除的方言里。
2. 把"标准年份"当"可用年份"：C++20 的 modules 至今没有全厂商一致的 `import std`（见上节 ⚠️）；
   选型看实现矩阵，不看发布会 PPT。
3. 以为源码兼容 = 可混链：ABI 不在标准内；跨编译器/跨大版本混 .o/.lib 从来不是 C++ 的承诺。
4. 用 `#if __cplusplus >= 202002L` 硬编码一切：库特性宏（`__cpp_lib_*`）与语言特性宏
   （`__cpp_*`）要分开测，且像本机 print 案例那样**宏过也可能链接失败**——CI 里要真链真跑。
5. 追新即正义：19.1.4 的书之大意是"每代方言都还活着"，维护中的 C++98 风格系统仍在运转；
   升级的货币是 ABI 断裂与审查成本，不是特性数量。
6. `import std;` 之前先等"官方统一方案"：附录 A 三建议的顺序（实现提供→头文件→自制包装）
   本身就是答案——过渡态可持续十年，别把模块化整章冻结。
