# 06 输入输出与文件系统（原书第 11 章）

> 总览：[00-总览与阅读地图.md](00-总览与阅读地图.md)｜索引：[../C++系列·总索引.md](../C++系列·总索引.md)

## 核心概念速览（中英对照）

- **流抽取/插入** — stream insertion/extraction（`<<`/`>>`）：类型化 IO 的双向箭头。
- **流状态** — I/O state：`goodbit/eofbit/failbit/badbit` 四位 + `bool` 测试；失败不抛是默认文化。
- **格式化操纵符** — manipulators：`hex`、`setw`、`setprecision`、`fixed` 等"流内小命令"。
- **区域设置** — locale：千分位/货币/字符集的可替换层；默认 `"C"` locale（性能与行为的起点）。
- **文件流/字符串流** — `ifstream/ofstream` / `istringstream/ostringstream`：同 API 换后端。
- **内存流** — stringbuf 直挂（11.7.4）：免拷贝的流式缓冲复用。
- **同步流** — sync_with_stdio：iostream 与 C stdio 的步调开关，关掉换吞吐。
- **printf 风格格式化** — `snprintf` 系：书中定位为"知道它存在，但用 format/iostream"。
- **文件系统路径** — `std::filesystem::path`：跨平台的字符串代数（generic/native、`/` 拼接）。
- **目录遍历** — `directory_iterator` / `recursive_directory_iterator`：11.9.2 的列目录利器。
- **文件状态** — `file_status` / `exists` / `is_regular_file`：stat 的类型化包装。

## 设计视角：动机 → 机制 → 权衡 → 相邻对比

**动机：为什么 iostream 长得这么怪？**（书之大意）`<<`/`>>` 重载、状态位而非异常、locale 钩子——
三件套都来自 1980s 的设计选择：类型安全（对比 printf 的格式串/参数不检查）+ 可扩展（UDT 自定义
operator<< 即融入）+ 可换环境（locale/codecvt）。代价是 Stroustrup 自己也承认的**慢**：
每个 `<<` 是虚函数+sentry 对象+locale 查询，且与 C stdio 默认同步（11.7.5）。
书的处方分三档：一般代码用 iostream 没问题；吞吐敏感先 `sync_with_stdio(false)`；
再不够换 printf/fmt/新 std::format 直写缓冲。这是导览书最"成人"的一章——它不辩护，只告诉你边界在哪。
🔧 本机实测这个"边界"（t17，g++ 15.2 `-O2 -std=gnu++20`，向 `nul` 写一百万行，单次运行只看量级）：
`cout` 默认同步 **77ms** → `sync_with_stdio(false)` 后 **41ms**（约省一半，坐实 11.7.5 的同步税）；
但 `snprintf+fputs` 反而 **366ms**——"printf 一定快"是都市传说，**刷新与缓冲策略比 API 选型更决定吞吐**。

**机制：错误文化——状态位优先。** 11.4 的惯例代码是 `while (is >> x)` 而非 try/catch：
流的失败是**数据驱动的常态**（EOF、类型不符），与第 4 章"异常管程序员的错"分工一致；
需要异常时 `is.exceptions(ios::failbit)` 一键切换（书演示了这个开关）。
相邻对比：Rust `Read` trait 返回 `Result`、Go error 随行——三家都同意"IO 错误是值"，
只有 C++ 的历史包袱让它以"静默状态位"形式呈现，`bool` 测试要记得写。
📋 编辑整理的状态位速查（归拢 11.4 口径）：

| 状态位 | 典型触发 | 恢复手段 |
| --- | --- | --- |
| `goodbit` | 一切正常 | — |
| `eofbit` | 读取碰到末尾 | `clear()`（常与 failbit 同时置位） |
| `failbit` | 格式不符/抽取失败/参数非法 | `clear()` 后还要丢弃坏字符，否则死循环 |
| `badbit` | 底层不可恢复错误（write 失败等） | 基本只能弃用流重开 |

**机制：UDT 的 IO 协议。** 11.5 确立惯例：`operator<<` 自由函数（常为 friend，输出最小信息集）、
`operator>>` 负责错误恢复（`setstate(failbit)`），**序列化格式与调试格式分离**（书未用此词，
但"输出只给必要成员"就是该原则的雏形；C++23 后 std::print 的 formatter 特化接管了这条路线）。

**机制：filesystem 是"类型化的路径代数"。** path 的关键设计（11.9.1）：
分隔符感知（`/` 追加自动适配）、generic/native 双视图、`path` 即字符串又非字符串（隐式转换被故意限制）。
11.9.2 的目录遍历示例强调 `directory_iterator` 返回 `directory_entry`——缓存了状态，遍历时
重复 stat 是新手性能坑（书用 "avoid multiple calls to status" 口径 ⚠️ 原句未逐字核）。
权衡：`<filesystem>` 是标准库里少数"以库形式补操作系统差异"的组件，因此语义只能取交集（权限模型、
符号链接处理都点到为止）。🔧 本机实测（t18，g++ 15.2 `-std=gnu++20 -static`，运行输出 `files=66 dirs=0`）：

```cpp
std::error_code ec;
fs::recursive_directory_iterator it{root, fs::directory_options::skip_permission_denied, ec};
for (fs::directory_entry e : it)          // entry 自带缓存的 status——
  if (e.is_regular_file()) ++n_files;     // 再调 fs::is_regular_file(e.path()) 就是二次 stat
```

## 最新演进与工业实践（第 3 版止于 C++20，本节补 C++23/26）

- **`std::print`/`std::println`（C++23，P2093R14 ✅）本章正主**：`print(stdout)` 免同步直写、
  终端色码检测、格式串编译期检查（`constexpr` 校验，fmt 的招牌进标准）。
  🔧 本机实测（MinGW g++ 15.2）：编译通过；链接失败（`std::__open_terminal/__write_to_terminal` 未定义，
  MinGW 运行时缺口），`std::format` 正常——本地写 IO 代码验证时建议 format+puts 兜底（见 [05 章](05-标准库概览与字符串正则.md)）。
- **`std::printbuf`/`printable`（C++26）**：给 `std::to_string` 的"官方替身"（按流直写不中转 string）；
  提案号未采到定稿 ⚠️ 仅述方向（P2846 系 ⚠️）。
- **print 与本章的关系**：`print` 是"格式化+直写"，**绕过**流状态位（错误以异常/中止呈现）——
  它不取代 iostream 的文件流/字符串流/宽字符转换，11 章的"输出一族"在 C++23 后从两族变三族。
- **`std::format` 的场景扩张（C++23）**：容器格式化 `{:~}`、user-defined formatter 简化
  （P2418/P2689 线 ⚠️ 编号未逐一核）；C++26 将把 chrono 日历格式补齐（P2726 ⚠️）。
- **filesystem 的 C++26 增量**：`u8path` 弃用后的 `path(char8_t*)` 支持、`absolute(p, base)` 重载
  （P2696R2 ⚠️ 未核标题，方向性描述）。
- **工业现状**：日志/格式化事实标准 fmtlib（`fmt::print` 是 std::print 的直接上游）已进
  std::format 后新项目迁 std 的窗口期正在打开；abseil `StrCat/StrJoin` 仍是高性能拼接首选之一 ⚠️ 转述。
  GCC/Clang 矩阵：`<format>` GCC 13+/clang 17+（libc++ 18），本机实测 GCC 15.2 ✅。

## 常见误区

1. 每个 `endl`：它是"换行+flush"——循环里等于每行刷一次盘，用 `'\n'`（书 11.2 点名）。
2. 忘测 `>>` 失败直接消费变量：failbit 下 x 值未定义（C++11 后置零，旧版保留原值），先测再用。
3. 以为关同步后 `printf` 和 `cout` 还能混用：11.7.5——混用需 `std::ios::sync_with_stdio` 语义自觉，否则输出交错。
4. locale 的"隐藏开销"：构造 `std::locale("")` 每次查询环境变量；流的全局 locale 切换是重操作（11.6.1 警告）。
5. `path` 当字符串到处隐式传：`path` 与 `string` 的编码假设不同（Windows 宽字符内部表示），边界处显式 `.string()/.u8string()`。
6. 把"读写整个文件"写成 stringstream 大中转：11.7.4 的 stringbuf 挂接或直接 `istreambuf_iterator` 进容器。
7. `ifstream is{name};` 后不测开没开就 stream >>：打开失败置的是 failbit（部分实现 badbit），
   错误表现是"文件内容恰好抽不出来"而不是崩溃——C++11 后构造即 open，必须紧跟状态测试。
8. 指望 `directory_iterator` 给出稳定顺序：顺序实现相关（NTFS/ext4 不同），可复现的遍历要先收集再 `sort`。
9. 混用 `setw/setprecision` 后忘了它们是"一次性/粘性的"两种操纵符：`setw` 只对下一次输出生效，
   `fixed` 会一直粘着——调试"为什么这行之后全变了"先查这里（11.6 的坑位）。
