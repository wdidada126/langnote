## 三条阅读路线

1. **纵贯线（默认）**：`01 → 11` 顺序读。原书即按"基础 → 抽象机制 → 库与专题"递进，目录版保持章序。
2. **现代特性线（用过 C++11/14，补到 C++20/23）**：`02`（模块化+expected）→ `04`（concepts）→
   `07/08`（ranges/flat_map/generator）→ `10`（jthread/协程/std::execution 展望）→ `11`（特性年表 + C++23/26 总表）。
   每章《最新演进与工业实践》即本线站点。
3. **设计视角线（配合 D&E 读）**：`01` ↔ D&E05、`03` ↔ D&E07、`04` ↔ D&E08、`02` ↔ D&E09/10、`11` ↔ D&E12。
   Tour 讲"特性是什么"，D&E 讲"当年为什么吵成这样"；两本同作者，互为横纵剖面。

**最短路径**：只关心"这本书比第 2 版/比 C++20 多了什么" → `11` 的 C++23/26 总表 + `02`（expected/contracts）+
`04`（concepts 定稿形态）+ `08`（ranges/generator/mdspan）+ `10`（std::execution）。

### 本次编译实测速览（第 3 版 C++20 写法 vs C++23 新写法）

| 对照实验 | 结果 |
| --- | --- |
| deducing this `void build(this Self&&)` | ✅ gnu++23 编译运行通过；gnu++20 下报"only available with -std=c++23"（GNU 扩展警告） |
| `static constexpr int operator()` + `static_assert` | ✅ gnu++23 通过；gnu++20 警告 |
| `if consteval { } else { }` + 编译期分支 static_assert | ✅ gnu++23 通过（另一侧不求值） |
| `std::expected<int,string>` + `transform/and_then` 链 | ✅ 运行输出 `ok=0 err=div by zero fallback=-1`；**`-std=c++20` 下硬错误**（`std::expected` 不存在）——库特性与语言特性回退行为不同 |
| `std::generator<int>` 斐波那契协程 | ✅ 运行输出 `0 1 1 2 3 5 8 13` |
| `std::print/std::println` | ⚠️ 本 MinGW 组合下**编译通过但链接失败**（`undefined reference to std::__open_terminal/__write_to_terminal`，MinGW 运行时缺口），改用 printf 兜底——诚实记录，非特性本身问题 |
| `std::flat_map` / `std::to_underlying` / `ranges::to` | ✅ gnu++23 编译通过；gnu++20 下 `flat_map is not a member of std` |
| `<mdspan>` | ❌ libstdc++ 15 无该头（P0009R18 在 libstdc++ 未实现；libc++/msvc 已实现） |
| `std::bytes`（C++23） | ❌ 本环境无 `__cpp_lib_stdbytes`（该特性后又在 C++26 改名 text_encoding ⚠️） |
| C++20 基线：concepts / `operator<=>` / `std::views` / constexpr 递归 gcd | ✅ `-std=gnu++20` 编译运行全通过 |
| `std::jthread` + `stop_token`（书中 ch18 新增内容） | ✅ gnu++20 编译通过（运行需 `-static` 兜底，本机 DLL 路径问题） |
