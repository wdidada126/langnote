## 核心概念速览（中英对照）

- **vector** — 动态连续数组：默认容器；`size/capacity` 分离，增长翻倍策略摊还 O(1)。
- **指针可互换性** — pointer-interchangeable：元素永远连续存放，可当 C 数组接口用（data()）。
- **list / forward_list** — 双向/单向链表：稳定迭代器 + O(1) 任意位置插删，缓存不友好。
- **map** — 有序关联容器（红黑树）：O(log n) + 中序遍历有序。
- **unordered_map** — 哈希表：平均 O(1)，桶+链，`max_load_factor/rehash` 可调。
- **分配器** — allocator：容器内存申请的钩子层；书中结论"std::allocator 之外基本用不到，要定制看 pmr"。
- **迭代器** — iterator：容器与算法之间的解耦接口（`begin/end` 半开区间惯例）。
- **迭代器类别** — iterator categories：input/forward/bidirectional/random（+C++20 contiguous）。
- **流迭代器** — `istream_iterator/ostream_iterator`：把 IO 流伪装成序列，接算法。
- **谓词** — predicate：算法的可插拔判断件（函数对象/lambda/函数指针三形态）。
- **算法家族** — non-modifying / modifying / sorting / set 操作：约 80 个官方零件。
- **执行策略** — execution policy（C++17）：`seq/par/par_unseq/unordered` 首参开启并行。
- **erase 惯用法** — erase / erase_if（C++20）：容器成员删除 vs 算法删除的收编史。

## 设计视角：动机 → 机制 → 权衡 → 相邻对比

**动机：STL 的中心思想一句话。**（书之大意）容器提供"对元素的访问"（迭代器），算法定义"对值的操作"，
两侧解耦后 **M 个容器 × N 个算法 = M+N 份代码**。导览书给的是这个乘法表的目录（13.5 概览表），
深读全部地形请转 [../C++标准库/03-STL总览.md](../C++标准库/03-STL总览.md)（逐件讲）与
[../STL源码剖析.md](../STL源码剖析.md)（实现讲）。本章只抓 Stroustrup 的三个"为什么"：
为什么 vector 是默认（连续内存+摊销增长+与 C 接口可互操作，缓存时代的最优解）；
为什么 list 没死（splice、稳定引用、`std::list::sort` 的 O(n log n) 指针重排——链表独有红利清单）；
为什么 map 与 unordered_map 都要（前者要有序遍历/范围查询，后者要纯查表；键可比较吗、哈希均匀吗，两个问题决定选择）。

**机制：迭代器类别=算法的"电源接口"。** 13.3 的等级表（input→output→forward→bidirectional→random）
决定哪些算法能用哪些迭代器：`std::sort` 要随机访问（list 迭代器进不去，所以 list 自带成员 sort）；
`std::advance` 按类别选 O(1) 或 O(n)。📋 编辑整理速查（据 13.3 归拢，非原表）：

| 类别 | 能做什么 | 代表载体 | 解锁的代表算法 |
| --- | --- | --- | --- |
| input | 单向读一次 | `istream_iterator` | `find/copy` |
| output | 单向写 | `ostream_iterator` | `transform` 的输出侧 |
| forward | 单向可重复 | `forward_list`、`unordered_map` | `equal/count` 双趟 |
| bidirectional | 可倒退 | `list`、`map` | `reverse`、`inplace_merge` |
| random(+contiguous C++20) | 跳跃+`[i]`+指针算术 | `vector`/`deque`/`span` | `sort/binary_search/nth_element` |

C++20 把这套"标签类+traits"换成了 concepts 阶梯
（`random_access_iterator` 等，见 [08 章](08-范围与指针容器.md) 14.5 与
[../C++20模板元编程/04-高级模板的概念.md](../C++20模板元编程/04-高级模板的概念.md)），
书中 13.3.1 流迭代器一节同时展示了旧式 `iterator_traits` 与新式 `iterator` 概念共存。

**机制：谓词是 STL 的"策略注入点"。** 13.4 演示传 lambda 做自定义比较/判断——
`find_if/sort/count_if` 的第三/四参让同一算法长出无限行为；这正是"基于参数化的设计"
（policy 思想的可运行期版），与第 5-6 章的虚函数（行为参数化）互补：
一个在类型层，一个在调用层（对照 [../C++模板元编程实战/02-异类词典与policy模板.md](../C++模板元编程实战/02-异类词典与policy模板.md) 的编译期 policy）。

**机制：执行策略——最保守的并行标准化。** 13.6：给算法首参加 `std::execution::par`，
实现可并行；`par_unseq` 再允许向量化（元素间不得相互依赖）。权衡讲透：并行是**优化**不是语义
（标准允许实现忽略策略退化为 seq），且谓词回调必须线程安全——这条边界直接把话题推给第 18 章，
也把"并行算法的未来形态"推给 std::execution（见最新节）。

**权衡：分配器（12.7）的坦白书。** 书中态度罕见地直白：默认 `std::allocator` 全局 new 足够绝大多数场景；
想定制内存（池/共享内存/跟踪器）走 PMR（`pmr::polymorphic_allocator` + `memory_resource`，运行期多态）
而不是老的模板参数分配器——后者污染类型、组合爆炸的教训被官方承认（概览表 12.8 里 allocator 列被淡化）。

## 最新演进与工业实践（第 3 版止于 C++20，本节补 C++23/26）

- **`std::flat_map` / `std::flat_set`（C++23）**：有序 `vector<pair>` + 二分查找——中小规模、读多写少时
  对红黑树 map 的缓存碾压；接口与 map 近似（异构查找受限 ⚠️ 细节以 cppreference 为准）。
  定稿号本次未采到 ✅ 标题，⚠️ 不写编号。**本机实测**（g++ 15.2，t06 编译运行通过）：

  ```cpp
  std::flat_map<int, std::string> fm{{2,"b"},{1,"a"}};            // 插入即保持有序
  auto v = std::views::iota(1,4) | std::ranges::to<std::vector>(); // C++23 一行收集
  // -std=gnu++20 下第一行即报 'flat_map' is not a member of 'std'
  ```
- **`std::ranges::to`（C++23）**：`auto v = rng | std::ranges::to<std::vector>();` 一行收集，终结
  `std::vector<int>(rng.begin(), rng.end())` 样板——实测与 flat_map 同文件通过（[08 章](08-范围与指针容器.md) 是其主场）。
- **`views::zip`（C++23，P2321R2 ✅标题 "zip"）**：多序列并行遍历入标准（此前 range-v3 独享）；
  adjacent/chunked 同期（编号 ⚠️ 未采）。
- **并行算法 → std::execution（C++26，P2300R10 ✅标题 "std::execution"）**：执行策略被普遍认为
  是"试验性接口"，sender/receiver 模型（可组合、可异步、可 backpressure）才是终局——
  详解见 [10 章](10-并发.md)。C++23 未给执行策略新增成员函数版 `erase_if`（那是 C++20，13 章已含）。
- **工业现状**：abseil 的 `absl::flat_hash_map`（SwissTable 开址哈希）早于且优于标准 unordered_map 一代，
  C++23 后 flat_map 分走了"小表有序"场景；folly `F14` 系列同理 ⚠️ 转述自各库文档。
  编译器支持矩阵：GCC 13 起 flat_map/ranges::to 完备（本机 GCC 15.2 实测 ✅）。

## 常见误区

1. 在 vector 中间 `insert/erase`：O(n) 搬移+迭代器全失效——链表才给稳定性（12.3 的对比意图）。
2. `map["k"]` 当只读查询：operator[] 缺键会**插入默认值**——只读用 `find`/`at`（12.5 点名）。
3. `unordered_map` 键类型随手写：需要 `hash<K>` + `operator==` 齐备；指针键默认哈希=地址值，语义常错（12.6）。
4. `vector<bool>` 当普通容器：它是位压缩特化，`&v[0]+i` 不成立、代理引用让 `auto&` 陷阱频发（12.8 表注）。
5. 在 `par_unseq` 算法的谓词里碰共享状态/加锁：直接 UB（13.6 明确警告；深水区见
   [../C++并发编程实战2/04-并发操作的同步.md](../C++并发编程实战2/04-并发操作的同步.md)）。
6. 算法写容器时混用"成员函数版"与"算法版"：优先算法+迭代器；仅 `list::sort/merge/splice/reverse`
   这类"结构操作"用成员版（12.8/13.5 的取舍表）。
7. 拿 `reserve` 当 `resize`：`reserve` 只动 capacity，元素仍是 0 个——`v[3]=x` 越界 UB；
   先 `resize` 或用 `push_back`（12.2 的 size/capacity 分离正为此设）。
8. `unordered_map` 迭代中途 `insert` 后继续用旧迭代器：重哈希使全部迭代器失效（erase 只废被删那个，
   `extract` 保节点）——桶结构的失效规则与 vector 完全不同（12.6）。
9. 见 `map` 就用、见大数据就 `unordered`：先问两题（要有序遍历吗？哈希可信吗？）——
   12.8 概览表的存在意义就是逼你先答题再选型。
