## 核心概念速览（中英对照）

- **具体类型** — concrete type：布局与操作编译期全知，值语义，无虚表（Shape 反例见 5.3）。
- **抽象类型/接口** — abstract type / interface：含纯虚函数的基类，运行期多态的握手点。
- **虚函数** — virtual function：经 vtable 间接分派；`override`/`final` 让重写可检查可封死。
- **对象切片** — slicing：按值传/存派生类只留下基类"切面"，多态静默失效。
- **类层次导航** — navigating a hierarchy：`dynamic_cast` 探测 + 虚函数回访（Visitor 前奏）。
- **拷贝/移动构造** — copy/move constructor：深拷贝 vs 偷资源，`const T&&` 右值引用是移动的信使。
- **五法则** — rule of five：析构/拷贝构/拷贝赋/移动构/移动赋要么全想清楚要么全交给默认。
- **RAII** — resource acquisition is initialization：资源寿命=对象寿命，异常安全的地基。
- **操作符重载纪律** — operator overloading：重载的是"数学/惯用直觉"，不惯用（`&&`、逗号）就别重载。
- **三路比较** — three-way comparison（`operator<=>`, C++20）：一个运算符生成六个关系运算。
- **swap** — `std::swap` 特化：移动时代的资源交换原语，"不抛"是它的强需求。
- **用户自定义字面量** — UDL：`2.5km`、`12'000'ms` 式后缀，把单位/域编码进字面量。

## 设计视角：动机 → 机制 → 权衡 → 相邻对比

**动机：为什么 Stroustrup 花两章写"一个 Vector"？** 因为 Vector 是 C++ 类型设计的**完备演练场**：
5.2 给"有不变式、需要管理内存"的具体类型画像（构造即正确、析构即清算），6.2 再把它拷一遍移动版——
同一类型两次演化，读者被迫直面"拷贝语义 O(n) 的隐性成本"。设计视角的核心句（书之大意）：
**具体类型是默认选择，继承是最后选择**——虚函数意味着每次调用一跳间接、对象头上挂 vptr、
拷贝语义破产（派生类拷贝派生类要 dynamic_cast 到最派生）。Java/C# 的"万物皆引用"没有这个成本问题，
也没有值语义的紧凑与可组合；C++ 把选择权（和账单）都交给你。

**编辑整理的"行为随类型变"四选一（本书 5.3/7/15.4 散点归拢，非原表）：**

| 方案 | 分派时机 | 成本 | 出处 |
| --- | --- | --- | --- |
| 虚函数基类 | 运行期，对象自带 vptr | 一次间接跳转 + 禁止值拷贝 | 5.3-5.4 |
| 模板参数 | 编译期，每种类型一份代码 | 编译期膨胀，无运行期成本 | 第 7 章 |
| `variant` + `visit` | 运行期，封闭集合 | 无 vptr，类型清单写死在声明里 | 15.4 |
| 函数指针/`function` | 运行期，行为对象化 | 策略模式最小件；`function` 有堆成本 | 6.4/16 |

**机制：移动 = 把"偷资源"变成合法动作。** 右值引用的语义不是"临时对象"而是"可以被掏空的东西"。
6.2.2 的移动 Vector：拷贝构造分配新内存逐元素复制；移动构造只搬指针+置空源。
五法则是这套机制的记账表：一旦手写析构，编译器就"不再自动给移动"（Rule of Zero 的建议由此而来：
成员全是值语义 RAII 类型时，五个都不用写——见 [../Effective_Modern_C++/05-右值移动完美转发.md](../Effective_Modern_C++/05-右值移动完美转发.md) item 14 同款论证）。
相邻对比：Rust 用 move 语义+借用检查强制"掏空后不可再用"；C++ 允许用（掏空对象处于"有效但未指定"状态），
相邻对比：Rust 用 move 语义+借用检查强制"掏空后不可再用"；C++ 允许用（掏空对象处于"有效但未指定"状态），
代价是心智模型，换来的是"移动失败可回退拷贝"的库自由。
🔧 本机实测（g++ 15.2 `-std=gnu++20`，输出 `bad.n=2 good.n=3` + 五行析构轨迹）：五法则手写 vs Rule of Zero——

```cpp
struct BadVec {                       // 一旦写析构，就得连带想清四件
  Resource* p; size_t n;
  ~BadVec(){ delete[] p; }
  BadVec(const BadVec&) = delete;  BadVec& operator=(const BadVec&) = delete;
  BadVec(BadVec&& o) noexcept : p(o.p), n(o.n) { o.p = nullptr; o.n = 0; }
  BadVec& operator=(BadVec&& o) noexcept { /* 先释放再偷 */ return *this; }
};
struct GoodVec {                      // 成员全 RAII ⇒ 五个特殊成员一个不写
  std::unique_ptr<Resource[]> p; size_t n;
};
```

**机制：`operator<=>` 是"少写错"工程。** C++20 前比较六件套（==,!=,<,<=,>,>=）手写易漏且互相矛盾。
spaceship 返回"序类别"（less/equal/greater/unordered），编译器按对称性派生其余五张表；
`= default` 逐成员聚合比较。设计取舍：三向比较可**短路**（比完 x 就不比 y），
所以"字典序 vs 集合序"在默认实现里由成员声明顺序决定——书在 6.5.1 特意提醒别滥用 `is_eq(cmp)` 反推 ==。
🔧 本机实测基线（g++ 15.2 `-std=gnu++20`）：`struct Point{int x,y; auto operator<=>(const Point&)const=default;};`
+ `static_assert(Point{1,2} < Point{1,3});` 编译期通过。

**权衡：UDL 为什么克制？** 6.6 演示 `2.5km` 后立刻降温：字面量算子改变语法外观、易与已有后缀冲突，
书中定位是"库作者的工具"而非日常件（对比 Rust traits 无此语法、Go 干脆无运算符重载——
C++ 给能力但用"社会规范"限用，这是其演化方法论的常态，参见
[../C++语言的设计与演化/02-语言设计规则与演化方法论.md](../C++语言的设计与演化/02-语言设计规则与演化方法论.md)）。

  左值/右值 × const/非 const 四份；"CRTP 手写静态多态"（[../More%20Effective%20C++.md](../More%20Effective%20C++.md)

- **static operator() / static operator[]（C++23，P1169R4 ✅ / P2589R1 ✅）**：无状态仿函数可全静态；

  6.4 的"函数对象"从此可与自由函数在成本上彻底平齐。
- **隐式 constexpr 扩张（C++23）**：非虚成员函数在常量求值下自动 constexpr 化（"constexpr for more agility"

- **C++26 观察项**：`operator|` 风格比较链（P2472 系）未入标准 ⚠️；contracts（P2900 系列，见 [02 章](02-模块化与错误处理.md)）

  自动生成 6.5 的样板（比较/哈希/IO 全可由字段清单派生）——这正是附录/11 章所述"样板债的终极还款人"。

  能看清"值语义理想"在百万行代码库里的折价。

## 常见误区

1. 按值传派生类还期待多态（切片）：接口层要么 `T&`/智能指针，要么设计成"值语义就不许继承"——书 5.5.1 二选一。
2. 析构里调用虚函数：此时动态类型已"降级"为本层，虚分派静默失效（5.5.3 资源话题的暗礁）。
3. 给 `operator&&`/`operator,` 重载语义：短路/求值序在模板语境连锁反应，标准库自己都不干（6.4 明言）。
4. 移动后当"空对象"用又当"零值对象"用：标准只保证"有效但未指定"；自定义类型应把"移后态"定义成可析活（书建议 move 后回到默认态）。
5. `= default` 与 `= delete` 混作"注释"：delete 是硬约束（阻止继承/阻止转换），默认是"按语义生成"，别用 bool 参数伪重载。
6. 默认 `operator<=>` 当"业务排序"：它按成员**声明顺序**逐字段字典序——改一行字段顺序=改全库排序语义；
   业务主序要显式比较函数（6.5.1），而且默认 spaceship 不送 `std::hash` 特化（6.5.6 还得自己写）。
7. 有虚函数还按值拷基类"应该没事"：5.5.1 的防切片处方是用 `clone()`/值语义包装（如 `std::function`
   式类型擦除）接管，或干脆把接口类的数据成员清零——"接口无状态"是两条正路之一。
