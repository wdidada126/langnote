# 04-关系数据模型（Ch5 The Relational Data Model, pp.89–105 ✅）

## 二、主题深读

### 2.1 「行序无关」与「无重复元组」——两条最常被违反的教学纪律
2026 现场仍大量可见 ORDER BY 依赖与重复行入库。本目录 🔧 提供两面证据：
- E3（demos.txt）：在 FD 集上机械求闭包，得「5 属性 16 个超码、唯一候选码 {ENO}」——**主码选择是定理不是心情**；SQLite/DuckDB 的 PRIMARY KEY 声明只是把选定结果固化（并自动加 UNIQUE 索引，见 E5 计划差异）。
- E6：反例数据行 (3,36.5,'NY') 两次——普通表不拦（无键时重复行合法），一旦 `id INT PRIMARY KEY`，第二次插入即 `UNIQUE constraint failed: dq.id`。两条纪律的可执行形态=「PK/UNIQUE 声明 + 排序只在输出层」。

### 2.2 与 Date 的温差：同一章的三档写法
- 本书 Ch5（17 页，通俗）↔ [../Relational_Theory_for_Computer_Professionals/01-数据库基本概念.md](../Relational_Theory_for_Computer_Professionals/01-数据库基本概念.md)（关系/关系变量严格区分，会追问「表≠关系」）↔ [../SQL_and_Relational_Theory/00-总览与阅读地图.md](../SQL_and_Relational_Theory/00-总览与阅读地图.md)（拿 SQL 方言的违约行为开刀）。
- Harrington 的立场是教学实用主义：接受「表≈关系」的松散类比换取入门速度；Date 立场是这类比正是 SQL 腐化源头。两种立场无对错，但**读者要知道自己站在哪一层**。

### 2.3 外键=联系的「唯一通货」
ER 里一对多/多对多（Ch4）到关系模型全部塌缩为「列的相等约束」。E2 实测强制矩阵（demos.txt）：
```
SQLite: FK pragma=OFF 孤儿行 1 行不拦；事务中开 PRAGMA 是 no-op（陷阱实录）；提交后 ON → FOREIGN KEY constraint failed
DuckDB 1.5.5: Violates foreign key constraint ... —— 与「分析库不强制 FK」通说相反，实测为准
```
「声明≠强制」在两引擎呈相反形态：SQLite 默认不强制（哲学：嵌入式信任开发者），DuckDB 强制（哲学：ETL 现场的守门人）。工程结论：**FK 语义是标准，强制矩阵是方言**——Codd Rule 11/完整性独立（Ch9）在方言层只能部分兑现。

### 2.4 A Bit of History 的 2026 再注释
教材的 Codd→关系胜利叙事在 2026 需要补上：文档/列族/图三模型在特定负载分走市场（Ch28 专章承接，见 [18-XML对象关系与NoSQL](18-XML对象关系与NoSQL.md)），但「二维表+键+约束」成为一切模型的**互译底层**（Parquet/Iceberg schema 即表的列化投影——盘上 Apache_Hudi_Definitive_Guide / Apache_Iceberg活用入門 在册 ✅）。历史叙事从「替代论」改写成「底层方言论」。

### 2.5 Primary Keys 小节的操作化：键选型的五个追问
Ch5 的 Primary Keys（✅ 节题）给出唯一/最小/稳定/非空的要求（措辞 ⚠️ 通识提炼）。操作化清单（本册综合）：①同一键值可能对应两个业务对象吗（唯一性）；②这个键会因业务动作而变吗（改手机号/合同续签——稳定性）；③键由外部系统生成吗（第三方 ID 的漂移风险）；④键会进报表与对外接口吗（自然键暴露面）；⑤复合键的两列都会单独查询吗（索引复用）。任何一问卡壳即退回代理键方案——与 02 §2.3/2.6 的论战闭环。🔧 E2 标本（非本书示范行为）：DuckDB 复合 PK 违例报错原文 `duplicate key "1, 1"`——复合键唯一性有 DB 执法，但「稳定」一栏的责任全在应用。

### 2.6 Views 小节：读接口的「一等公民」认证
Ch5 把 Views（✅ 节题）列进**模型**部件而非查询糖——这是对偶义务：Ch21（14 文件）负责实现语义，Ch9 Rule 6（07）负责合规判据。🔧 E5 实录（非本书示范行为）：SQLite 直接 UPDATE 普通视图得到 `cannot modify v_a because it is a view`——Codd「一切视图可更新」愿望在现实方言里是负样本（demos 台账），本小节因此带上双重读法：模型层的正典 + 引擎层的负债。2026 后裔：BI 语义层的指标定义、数据目录里的逻辑视图、权限视图（16 §2.5 对位）。

### 2.7 The Data Dictionary 小节：元数据原点与目录工业
一节之隔，2016→2026 从「教材零件」长成「产业」：数据字典=Rule 4（动态在线目录，✅ 规则题在 07）的正文化身，也是 Ch12 CASE 工具「数据字典报告」功能的对象（09）。现代承接：技术目录/血缘/术语治理三件套（盘上 [../Fundamentals_of_Data_Observability/00-总览与阅读地图.md](../Fundamentals_of_Data_Observability/00-总览与阅读地图.md) 与 Data_Mesh 线在册 ✅，00 §七账）。教材不变论点仍锋利：**不可查询的元数据等于没有元数据**——A Bit of History（✅ 末节，§2.4 已注）与本节的合读结论：目录是关系模型的自我描述能力，自我描述弱的系统靠文档活着，文档比表先过期。
