# 06-规范化（Ch7 Normalization, pp.141–161 ✅）

> 三态：✅ 书页 TOC/Crossref 页码实抓 · ⚠️ 转述/推定展开 · 🔧 本机 SQLite/DuckDB 实测（**非本书示范行为**）。
> 21 页走完 ER→关系翻译+1NF 到 6NF 全部范式——本书密度最高的一章，也是与 Date《Database Design & Relational Theory》温差最大的一章：Harrington 给「识别与修复」的操作手册，Date 给「依赖与投影」的证明体系。

## 一、精读札记（官方二级小节 ✅ 逐条）

- **Translating an ER Diagram into Relations** —— 先行手术：实体→表、1:N→外键、M:N→交叉表（Ch4 的机械化收口）。
- **Normal Forms** —— 总起：范式=「坏依赖」的逐层清剿令。
- **First Normal Form** —— 禁重复组/多值列（Ch14 时代靠逗号串、2016 靠 JSON 列——本章未及 JSON ⚠️）。
- **Second Normal Form** —— 消灭部分依赖（复合键上的半截依赖）。
- **Third Normal Form** —— 消灭传递依赖（非主属性→非主属性）。
- **Boyce–Codd Normal Form** —— 「每一个决定因子都是超码」；3NF 容忍的边角病在 BCNF 清零。
- **Fourth Normal Form** —— 多值依赖（MVD）与「两个独立多值事实同居一表」的病。
- **Fifth Normal Form** —— 连接依赖（JD）：无冗余重构为投影之连接 ⚠️（页内例不可达）。
- **Sixth Normal Form** —— 6NF：一属性一关系的时间轴拆解（Date 偏爱，教材点到即止）。

## 二、主题深读

### 2.1 🔧 E3 实测：把「决定因子」变成可计算对象（非本书示范行为）
对教材标准例 R(ENO,ENAME,DEPT,DNAME,MGR)，FD 集 {ENO→ENAME,DEPT; DEPT→DNAME,MGR; DNAME→DEPT,MGR}，demos.txt：
```
属性数=5 超码数=16 候选码=[['ENO']]
{DNAME,ENO}⁺ = 全集R ; {DEPT}⁺ = [DEPT,DNAME,MGR]
```
机械判据一行话：**X 是超码 ⇔ X⁺=R；候选码=超码的 ⊆-极小元**。BCNF 违规检测=对每个非平凡 FD X→A，验 X⁺=R——本 FD 集里 DEPT→DNAME 的 DEPT⁺≠R（缺 ENO/ENAME）→ DEPT 侧独立成表。Armstrong 公理的饱和过程即闭包循环，与 Date 册第 3-4 章的正式叙述完全同构（对读位：[../Database_Design_and_Relational_Theory/04-函数依赖与BCNF非正式.md](../Database_Design_and_Relational_Theory/04-函数依赖与BCNF非正式.md) 与 [../Database_Design_and_Relational_Theory/05-函数依赖与BCNF正式与希思定理.md](../Database_Design_and_Relational_Theory/05-函数依赖与BCNF正式与希思定理.md)）。

### 2.2 🔧 E2 实测：范式的「执法面」——约束在两引擎的落地（非本书示范行为）
规范化把依赖「拆干净」，约束让依赖「守得住」。E2 矩阵（demos.txt）：
```
SQLite: FK pragma OFF 孤儿 1 行不拦; 事务内 PRAGMA foreign_keys=ON 是 no-op（陷阱实录）; 提交后 ON → FOREIGN KEY constraint failed; UNIQUE 强制
DuckDB 1.5.5: FK/UNIQUE/CHECK/复合PK 全部即插即拦（"Violates foreign key constraint..."）
```
2NF/3NF 的「部分/传递依赖禁止」在 SQL 里无直接对应约束——**只能靠分解+FK 间接执法**；这正是本章（拆）与 Ch11（守）必须连读的理由。

### 2.3 4NF/5NF/6NF 的教学纵深差
Harrington 对 4NF 的处理是「双多值同居」口诀+一例（⚠️ 转述级）；5NF 给连接依赖直觉；6NF 一段点到。对照物：Date 册用整书论证 4NF/5NF 并附追逐算法与连接依赖正式定义（[../Database_Design_and_Relational_Theory/12-多值依赖与4NF.md](../Database_Design_and_Relational_Theory/12-多值依赖与4NF.md)、[../Database_Design_and_Relational_Theory/10-连接依赖与5NF正式.md](../Database_Design_and_Relational_Theory/10-连接依赖与5NF正式.md)）；Elmasri 走中间路线（其 06 章 ✅）。三档深浅读者各取所需——本目录把 Harrington 定为**工作层**、Date 定为**证明层**。

### 2.4 1NF 的 2026 再战场：JSON 与数组列
2016 教材的重复组例子（item1/item2 列位）在 2026 的等价物是多值塞进 JSON/ARRAY。🔧 方言对照：DuckDB 原生 `INTEGER[]`/STRUCT 列可持多值（关系纯度让步给扫描性能，1NF 灰色地带 ⚠️ 工程口径）；SQLite 3.45.3 无原生数组、JSON1 扩展以 TEXT 存半结构（官方文档页 ✅ https://www.sqlite.org/json1.html 实查）——「要不要为 1NF 拆表」在列存/文档混龄栈里重新成为开放题，呼应 Ch28 NoSQL 章。

### 2.5 反规范化的合法出口（接 Ch8）
E1 实测（demos.txt）：3NF 五表后删除订单 102 不伤目录（2 件商品/2 家客户俱在）——规范化的收益；但报表侧「每单必须 JOIN 四表」的代价在 Ch8 用索引/反规范缓解。Date 册的「反规范化」专章（[../Database_Design_and_Relational_Theory/08-反规范化.md](../Database_Design_and_Relational_Theory/08-反规范化.md)）与本书 Ch8 同题；本册特色是把性能决策收进「先规范、后按访问路径调优」的顺序律。

### 2.6 ER→关系的翻译细则清单（Ch7 首节 ✅，与 03 的分工线）
Translating an ER Diagram into Relations（✅ 节题）是本章的隐藏主线：1:1→FK 落强制侧（03 §2.7 矩阵）；1:N→N 端 FK；M:N→中间表+双 FK 复合 PK（§2.1 定理的正式兑现）；多值属性→独立表（=1NF 的表级执法）；子类/超类→三合一/两立（表合并/表分离/混合——教材未展开，⚠️ 通例补）。E1 的反模式宽表→3NF 拆分实录（demos ✅）就是「M:N+冗余」双病灶的最小翻译案例；03 §2.5 🔧 最小翻译与本节互为上下游：03 给概念动作，06 给判定程序。

### 2.7 各范式的判定程序（FD 理论一屏通）
逐级判定句+反例锚（综合 ⚠️+🔧 E3）：1NF=每列原子（2.4 的 JSON 战场）；2NF=无部分依赖（复合键的前置问题；E3 🔧 样本 ENO 单候选键下 2NF 自动成立——「空转判定」的教学标本）；3NF=无传递依赖（E1 的 city 依赖链即反例）；BCNF=每个决定因子都含候选键（E3 闭包机械化：{DNAME,ENO}+ 五属性全收、{DEPT}+ 停在三属性——demos 原文）；4NF=无非平凡多值依赖（§2.3 纵深差所在）；5NF=连接依赖无损；6NF=不可再分解。超码 16 个 vs 候选键唯一（E3）给出全书最锋利的一句：**范式判定=在决定因子上找候选键**。

### 2.8 分解的两个正确性判据（⚠️ 本册补件）
教材小节清单（✅）未给「无损连接/依赖保持」形式判据——这是同题材研究生教材（Elmasri&Navathe 盘上线，00 §七实链）的标配件。本册补最小认知框架：分解合格线=①拼回原关系不丢信息（lossless join），②原函数依赖全部仍可执法（dependency preserving）；BCNF 分解可能牺牲②，3NF  synthesis 保②——工程口径：**牺牲②就把那部分规则搬进应用/断言层**（接 17 质量断言线）。读者带着这两把尺重走 §2.7 判定链，本章 21 页（✅ 141–161）即闭合。

## 最新演进与工业实践
- 约束执法矩阵 2026-10-02 实测刷新认知：DuckDB 1.5.5 已全量强制 PK/UNIQUE/CHECK/**FK**（demos.txt E2 实录），与旧文档印象相反——依赖发现/校验管道可把 FK 作为第一道闸门而非事后对账；SQLite 的 foreign_keys 开关文档 ✅ https://www.sqlite.org/foreignkeys.html 仍是「声明 vs 强制」教学的最佳标本。
- 1NF 边界的工业再谈判：开放表格式（Iceberg/Parquet 嵌套列）+ 分析引擎（DuckDB LIST/STRUCT）让「规范形+受控嵌套」成为 OLAP 默认；OLTP 仍是全分解阵地（盘上 Apache_Hudi_Definitive_Guide 在册 ✅ 有嵌套 schema 演进章）。
- 教材互认：Elmasri《数据库系统基础教程/模型与设计》各版、Ricardo《Databases Illuminated》均把「依赖→范式→分解」定为数据库核心课程单元（ABET 口径 ⚠️），本书 Ch7 页数配置（21 页）与之相当。
- 两判据工程名=迁移评审：无损靠双向可拼测试、依赖靠断言兜底（§2.8 ⚠️）。
- FD 机械化（E3 🔧）：闭包两式原文在 demos——「找候选键」可跑脚本（非本书示范）。
- 工业使用序：3NF 保底、按需 BCNF、4NF+罕见——OLTP 经验律（⚠️）。
- 1NF 再战场（§2.4）与 18 双录：JSON/数组列=原子性重新谈判。
- 反规范化出口（§2.5）当代形态=物化/宽表/语义层缓存——合法出口四字仍准。
- OLAP 免范式迷思：星型本身是刻意反 3NF 的读优化设计——06/17 合读（⚠️）。
- 教学纵深差（§2.3）：4/5/6NF 书内一页、Date 深论——盘上分流（00 §七）。
