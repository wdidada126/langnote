# 16-数据库安全（Ch23 Database Security, pp.471–495 ✅）

> 三态：✅ 书页 TOC/Crossref 页码实抓 · ⚠️ 转述/推定展开 · 🔧 本机 SQLite/DuckDB 实测（**非本书引擎/示范行为**）。
> 25 页安全章走「威胁→对策」双线（外部/内部各一对），收口于备份恢复与「多少安全才够」的成本问。2016 教材把 SQL 注入与最小权限写进正文属于清醒行列；本章与 Codd Rule 12（不可颠覆）互为表里。

## 一、精读札记（官方二级小节 ✅ 逐条）

- **Sources of External Security Threats** —— 渗透者/注入/社会工程；DBMS 暴露面盘点。
- **Sources of Internal Threats** —— 越权 DBA/特权应用账号/离职残留；内部人威胁建模。
- **External Remedies** —— 网络隔离、补丁管理、账户锁定策略。
- **Internal Solutions** —— GRANT/REVOKE 授权格、视图收窄面（Ch14 安全壳回收）、行级/列级控制的商业形态 ⚠️。
- **Backup and Recovery** —— 全量/增量/事务日志三条恢复线；恢复目标（RPO/RTR 语汇 ⚠️ 书内措辞推定）。
- **The Bottom Line: How Much Security Do You Need?** —— 安全=风险定价题，不是合规打卡题。

## 二、主题深读

### 2.1 SQL 注入：本章技术含量最高的一节，2026 仍未过时
书内立场（参数化查询/最小权限/纵深防御 ⚠️ 通说转述）在 2026 的验证：OWASP 榜单上注入仍在，但形态向 ORM 拼接/二阶注入/提示注入（LLM 生成 SQL 通道）迁移——**最后一种恰好是「用自然语言写 SQL」教学线的意外后果**（本目录 11–14 文件教的 SELECT，2026 由模型代笔，注入审计从人转移到生成器+参数模板）。
### 2.2 🔧 载体现实：SQLite/DuckDB 的安全面几乎为零配（非本书示范行为）
两载体均无 GRANT/REVOKE、无用户体系（文件权限=唯一 ACL；URI 只读模式 `mode=ro`/`file:...?immutable=1` 是 SQLite 能给的全部 ⚠️ 官方文档族转述）。工程启示反更清楚：**授权格是 DBMS 的功能，不是 SQL 的功能**——书内 Internal Solutions 的商用清单（角色/列掩码/审计）在嵌入式与分析引擎里要向上层（应用/网关/目录平台）找宿主；盘上 [../The_Database_Hackers_Handbook/00-总览与阅读地图.md](../The_Database_Hackers_Handbook/00-总览与阅读地图.md) 与本波在盘册 [../Oracle_Security/00-总览与阅读地图.md](../Oracle_Security/00-总览与阅读地图.md)（波7在册 ✅）提供攻防纵深对照。
### 2.3 备份恢复的教材-现场温差
书内三线（全量/增量/日志）在 SQLite 的极简对应：文件复制/`VACUUM INTO`（在线一致快照）/WAL 检查点纪律（E4 同库可演示 ⚠️ 本目录未单测，盘上 Using_SQLite 与 SQLite TDG2e 两册有 VACUUM INTO 与备份 API 实测 ✅ 在册纵读）。RPO 思维在 2026 云线的化身= PITR（时点恢复）默认开——恢复目标从「计划」变「滑条」。
### 2.4 Rule 12 的内部威胁学
Codd 第 12 规则「低层通路不得绕过完整性」正是「内部威胁」的形式化：任何绕过授权/约束直达存储的通道都使前 11 条失效。E2 的 SQLite FK-OFF 是 Rule 12 精神的日常微型违规（默认关约束=官方留的后门）；安全章与约束章在 2026 的合流读物即「完整性即安全」的数据契约叙事（../Data_Observability_for_Data_Engineering 在册 ✅）。

### 2.5 DCL 与授权模型：书内语法在载体上的空缺（⚠️+🔧 对照）
书内 Internal Solutions（✅ 节题）走 GRANT/REVOKE+角色的标准 DCL 线；🔧 载体对照（非本书示范行为）：SQLite/DuckDB **均无库内 DCL**——单机引擎把「谁能连文件」交给文件系统与连接串，授权模型整体外置。这不是缺陷而是分层提醒：**DCL 是多用户服务器的特性**；嵌入式场景的安全预算应全额投向输入面（参数化）与出口面（脱敏）。2026 的对应演化：托管库把 GRANT 语言升格为策略即代码（row-level security/列掩码/动态脱敏，⚠️ 通识）——视图作为授权接口的教义在 14 §2.7 已埋伏笔，两处合读。

### 2.6 威胁-对策总账：按书内六节对 2026 判词（⚠️ 综合）

| 书内节（✅） | 2026 现状 |
|---|---|
| Sources of External Security Threats | 攻击面从端口转向供应链与凭证（库外防线扩大） |
| Sources of Internal Threats | 云 IAM 让「内鬼」可审计——最小权限即默认工单流 |
| External Remedies | 边界防护平台化；SQL 注入仍需应用侧参数化（§2.1） |
| Internal Solutions | DCL→策略即代码；视图/RLS 承担列行裁剪 |
| Backup and Recovery | 快照对象存储化；§2.3 的教材-现场温差缩小，验证仍是稀缺纪律 |
| The Bottom Line | 答案从「买多少」变成「分层预算：入口>存储>出口」 |

六节账合起来：本章的技术件一半升级、一半外包给平台——**唯独「注入」和「备份验证」两节至今无法外包给人之外的任何东西**（判词 ⚠️）。

### 2.7 出口侧与输入侧的镜像纪律（评注 ⚠️）
书内叙事重心在输入侧（防写入恶意 SQL），2026 的事故分布已移一半到**出口侧**：越权读、导出脱敏失败、日志/错误信息泄露、报表权限视图旁路。输入侧标准件（参数化、白名单标识符、最小 DDL 权）与出口侧标准件（RLS/掩码、导出审批、错误面收敛）互为镜像——都以 Rule 12（Nonsubversion，07 §2.5 判定行）为教义出处。The Bottom Line 的问句「你需要多少安全」在 2026 的可操作回答：**先把两侧镜像清单各打一遍勾，再谈预算**。

## 最新演进与工业实践
- 生成式通道的注入面：LLM 产 SQL 的落地防线=只读账号+视图层+语句模板校验三件套（与 11–14 教学线的 SQL 生成能力恰成镜像——**会写才审得住**）。⚠️ 通说。
- SQLite 官方 WAL/文档族实查在线 ✅（https://www.sqlite.org/wal.html ）是嵌入式「文件即攻击面」威胁模型的最简权威文本；URI 只读/不可变模式的 ✅ 级 URL 留待补验，登记于完工报告。
- 行列级安全与动态掩码成为云数据平台标配（Fabric/Snowflake 线），教材版图的空白点恰是本波云仓五册的覆盖区——00 §七分工表口径下，本册守「关系模型内的安全原语」，平台级授权矩阵交棒云册与 Oracle_Security（在册 ✅）。
- 2026 事故分布位移：注入仍在、重心增「库外一件」——数据湖桶位错配=新 SQL 注入（文末注在册）。
- 载体分层判词（§2.2）：DCL 是多用户服务器特性；单机引擎预算全投输入面+出口面（🔧 对照）。
- RLS/掩码/目录三件套（§2.5）接管书内 Internal Solutions 语义——授权即代码、策略即评审（⚠️）。
- 备份三角的现代件：快照对象存储化+不可变备份对抗勒索——§2.3 温差线拉长为产业线（⚠️）。
- 本章毕业判据：§2.6 总账表每行能补一个当代产品名。
- Rule 12 锚（§2.4）给安全章宪法位：绕过权限的每条后门都是关系模型的违宪立法（07 联动）。
- 盘上纵深三分（§2.8）：Hackers=攻击面、Oracle_Security=服务器 DCL、DRE=可靠性工程——全在册 ✅。
- 视图授权接口（14 §2.7 伏笔）在本章兑现为行/列裁剪最小方案——两章互指账。
- 输入侧三件（参数化/白名单/最小 DDL 权）与出口侧三件（RLS/审批/错误面收敛）互为镜像（§2.7）。
- 「注入与备份验证无法外包」判词（§2.6）在 LLM 生码时代加倍适用——生成 SQL 仍是注入面（⚠️）。
