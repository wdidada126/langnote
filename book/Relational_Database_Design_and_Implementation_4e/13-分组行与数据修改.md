## 二、主题深读

### 2.1 窗口函数是本章的 2026 前卫线
2016 教科书把 windowing 写进正文（✅ TOC 实证）值得点名：彼时 SQLite 尚未支持（3.25/2017 才补 ⚠️ 通说），MySQL 8.0（2018）才有——本书读者若在书内环境学窗口，到 2026 已无方言墙。🔧 本机对照：DuckDB 1.5.5 窗口全族原生；SQLite 3.45.3 含 RANK/LAG/帧语法（波2 DuckDB_Up_and_Running 实测集在册 ✅ 有同类样张）。教学顺序建议：聚合分组（折叠）→窗口（不折叠）——两章一字之差语义相反。
### 2.2 MERGE 的方言众生相
| 载体 | upsert 形态 |
|---|---|
| SQL 标准 (2003) | MERGE INTO...USING...WHEN MATCHED |
| SQLite | INSERT...ON CONFLICT DO UPDATE（冲突目标=PK/UNIQUE，E2 执法件） |
| DuckDB | INSERT OR REPLACE / 标准 MERGE 支持面 ⚠️ 未逐一实测 |
| 湖仓 | Iceberg/Hudi MERGE 系 CDC 管道的主动脉（三册在册 ✅） |
E1 五表骨架的 qty 更新场景（重复到达同一 (order,item)）正好演示 upsert 必要性（🔧 非本书示范）。
### 2.3 UPDATE 无 WHERE：用 🔧 演示制度性防线
demos.txt E4 语境可复用的三层防线：事务（BEGIN→改→看行数→COMMIT/ROLLBACK）、busy_timeout 下的锁纪律、SQLite `changes()` 行数回读。教材 Ch20 的「小心 UPDATE」在 2026 的等价教条是**一切写操作进事务+行数断言**（E4 的回滚重试成功样本：`回滚+锁释放后重试成功, g.v=2`）。
### 2.4 聚合 NULL 纪律×三值逻辑=管道事故矩阵
Ch16 三值+Ch19 NULL 聚合+E2 约束缺位，三件凑齐 2026 数据管道最常见的静默失真路径：LEFT JOIN 产 NULL→AVG 跳空虚高→报表「均值正常」；反连接 NOT IN 恒假→分母缺失。本章应配「NULL 审计清单」小页（书未给 ⚠️，本目录 17 文件 E6 给最小件）。

### 2.5 CAST 与类型系统：SQLite 亲和性 vs DuckDB 强类型（⚠️ 综合+🔧 载体注）
Ch19 专设 Changing Data Types: CAST（✅ 节题），因为两型系统分居两侧：**SQLite 动态类型+列亲和**（值类型与列声明可以分家，文档面在 SQLite 官方数据类型页 ⚠️ 未逐页重验者自律）；**DuckDB 静态强类型**（隐式收窄即报错）。同一句 CAST 在两家语义不同——亲和性引擎里它改的是解释，强类型引擎里它改的是值。教学价值：本章把「类型转换不是免费的」讲成了语法（🔧 非本书示范行为的载体对照：本波 demos 全程两栈并置，类型歧义零发生正是因为每步显式转换——纪律即副产品）。

### 2.6 集合函数与 GROUP BY 的机器化自验（🔧 复用法）
用 🔧 E5 素材（非本书示范行为）把本章讲成三道可跑题：①5200 行分组在 SCAN 全表计划下的耗时基线=索引前世界（demos 原文 1.64ms）；②DuckDB CTE 对 200 万行按组流式聚合，三组均值 2449.9987/2450.0013/2450.0（demos 原文）——**组间差在浮点尾数**，分组聚合的确定性课在百万行尺度才有肉眼可见教具；③E6 的 AVG=-41.0 vs SUM/5=-32.8（NULL 跳过 vs 按 0 计）给「分组后取什么口径」的账单。三题覆盖 Set Functions/Grouping Queries 两节（✅）全部考点。

### 2.7 MERGE 的源侧粒度与幂等（§2.2 的操作面）
MERGE 语义=「按源行匹配目标行，命中则改、未中则插（书内小节 ✅ on a Condition）」；生产事故率最高的不是语法而是**源行粒度**：源侧同一键出现两行时，标准语义各家不一（报错/任选其一），2026 平台纪律是**先按键去重再 MERGE**（⚠️ 综合判词）。幂等写法三件：稳定键、单调谓词（只前进不回退）、可重放源——本章 8 页（✅ 429–436 Ch20）的 Data Modification 四节（Insert/Update/Delete/MERGE ✅）+这三件，即 DML 管道的最小安全规格。
