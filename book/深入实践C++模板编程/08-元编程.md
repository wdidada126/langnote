## 核心概念速览（中英对照）

- **元编程** — metaprogramming：以「程序的另一部分」为数据的编程；C++ 的载体是模板实例化引擎
- **元函数** — metafunction：输入类型/整型常量、输出类型/整型常量的编译期函数；形态=类模板+嵌套成员
- **元函数调用** — metafunction invocation：实例化 `F<Args...>::type/::value` 即「求值」
- **元容器** — metacontainer：装类型的编译期容器（本书的 5 槽容器/MPL 的 vector_c 谱系）
- **元算法** — metaalgorithm：作用在元容器上的 transform/filter/find 族
- **类型过滤** — type filtering：按谓词元函数拆分类型列表——TMP 版的 `copy_if`
- **实例化即求值** — instantiation-as-evaluation：递归实例化链=函数调用栈；偏特化=模式匹配子句
- **枚举传值** — enum-value channel：C++98 元函数的「返回值」靠 `enum { value = ... }` 常量成员
- **constexpr 元编程** — constexpr metaprogramming：C++11 起值级 TMP 的正统继任者
- **consteval** — immediate function（C++20）：只准编译期调用的函数——元函数的语法糖终态

## 动机：一台没人打算编程的计算机

书中 13.1 的定调（机制转述）：模板实例化引擎**碰巧**图灵完备——它其实是一台
无副作用、纯惰性、以类型为内存的**函数式抽象机**。与 07 章伪变参一脉相承，但第 13 章
把视角从「技巧」升到「语言」：`template <class...> class` 是 lambda 的残废版、
偏特化是 `match`、继承 `std::integral_constant` 是返回、没有赋值只有绑定。

**元函数的两代实现姿态**（13.2，实测对照）：

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++98（f98_oldstyle.cpp）：C++98 的全部家当
template <int N> struct Fib { enum { value = Fib<N-1>::value + Fib<N-2>::value }; };
template <> struct Fib<0> { enum { value = 0 }; };   // 递归基=偏特化
template <> struct Fib<1> { enum { value = 1 }; };
char arr[Fib<10>::value];                             // 编译期值当数组维数：55,实测通过
```

「实现」= 类模板 + 嵌套常量/类型成员；「调用」= 强制实例化（用作维数、static_assert、
模板实参）。C++98 的憋屈细节：**没有 constexpr**，整数只能走 `enum`（位宽受限、不能取
地址）；没有变参，arity 靠 `List<H,T>` 手工搭；无 `_v` 后缀，写全称 `Fib<10>::value`。

## 机制：元容器与类型过滤的编译期数据流

13.3–13.4 的实例（机制转述）：先做定长 5 槽元容器（`types<T1..T5, null_t>` 形态，
`null_type` 做哨兵——Loki 谱系的标准做法），再写**类型过滤**：谓词元函数
（如 `is_pointer`）× 过滤元算法 → 输出「是指针的类型」子列表。

```cpp
// 🔧 复现骨架（哨兵+默认参形态，与本章其余代码同批实测编译）
struct NullType {};                                        // 哨兵:「到此为止」
template <class T1 = NullType, class T2 = NullType, class T3 = NullType,
          class T4 = NullType, class T5 = NullType>
struct Types { using head = T1; using tail = Types<T2, T3, T4, T5>; };
// 过滤=两条偏特化: head 满足谓词→保留 head 再递归 tail;否则直接递归 tail
```

定长 5 槽 + 默认参数 + 哨兵终止——每个设计决定都是 C++98 语法真空的补丁
（无变参→槽数封顶；无 `requires`→默认值全铺；无折叠→尾递归手工化）。C++11 之后
它的合法形态就是 `template <class... Ts> struct Types { ... };` 一行。

用 C++11 变参重演同款算法（本书第 15 章发布时点的前沿，今天看恰好是过渡层）：

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17（f_metaprogram.cpp 节选）
template <class T> struct IsPtr : std::false_type {};
template <class T> struct IsPtr<T*> : std::true_type {};        // 谓词:偏特化即分支
template <class... Ts> struct CountPtr;
template <> struct CountPtr<> { static const int value = 0; };   // 递归基
template <class H, class... R> struct CountPtr<H, R...> {
    static const int value = (IsPtr<H>::value ? 1 : 0) + CountPtr<R...>::value;
};
static_assert(CountPtr<int, char*, void, double*>::value == 2, "filter"); // 实测通过
```

到编译器行为层面数成本：`CountPtr` 每元素实例化一层（N 层递归对编译器有
`ftemplate-depth` 默认 ~1000+ 的深度上限；MSVC 历史 128 代），`IsPtr<T>` 的 true/false
分支零成本（`integral_constant` 无对象）。**这就是元编程的「空间换时间」全在编译期
付账、运行期分文不收**——与 06 章代码膨胀是同一枚硬币。

## 权衡：三种图灵机的分工（2026 年账本）

| 层 | 2013 年工具 | 今天首选 | 判据 |
| --- | --- | --- | --- |
| 值计算 | `Fib<N>::value` | `constexpr`/`consteval` 函数 | 报错可读、可调试、可运行期回退 |
| 类型计算 | `List/At/Filter` 手工 | `std::tuple + std::variant` + mp11 / 折叠 | 类型列表操作仍有残余需求 |
| 选型分派 | 特化阶梯 | concepts + `if constexpr` | 见 06 章诊断实测 |

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17：同一算法的 constexpr 重写
constexpr int fib_rt(int n) { int a = 0, b = 1;
    for (int i = 0; i < n; ++i) { int t = a + b; a = b; b = t; } return a; }
static_assert(fib_rt(10) == 55, "");   // 循环版,编译期照算
```

C++14 放开 constexpr 循环后，**值级 TMP 已全线亡故**；本书 13 章真正不朽的是
「类型是一等数据」的世界观——它活到 std::tuple/std::variant/mp11 里。

## 最新演进与工业实践

- **constexpr 泛型化（C++20/23）**：constexpr 虚函数/多态分配器（P1073R3 线，
  ⚠️ 提案状态未逐一核实）、容器进 constexpr——当年「编译期不能 new」的边界持续外移。
- **`<concepts>` 的元编程副产物**：`std::same_as/std::derived_from` 等本身就是
  「返回布尔的元函数」，`requires` 的求值语义（constexpr bool 转换）把元函数
  输出并进了语言值类别。
- **mp11 一行版**：`mp_count_if(mp_list<int,char*,void,double*>, is_pointer)`
  （boost::mp11，header-only）——类型过滤的最终工业形态；教学实现对照读
  [../C++模板元编程/05-序列与迭代器.md](../C++模板元编程/05-序列与迭代器.md) 与
  [../C++模板元编程/10-附录与从MPL到现代C++的替代.md](../C++模板元编程/10-附录与从MPL到现代C++的替代.md)。
- **工业级验收场**：[../C++模板元编程实战.md](../C++模板元编程实战.md)（MetaNN，
  github.com/bluealert/MetaNN-book）用类型列表做神经网络层的编译期 shape 检查——
  13 章玩具的千倍当量。
- **表达式模板（邻章预告）**：值级+类型级合体输出零临时矩阵表达式的技法，正统叙述在
  [../C++模板元编程/09-DSEL与表达式模板.md](../C++模板元编程/09-DSEL与表达式模板.md)；
  经典文献 Veldhuizen, *Expression Templates*, C++ Report 1995（经 Wikipedia 词条互证）。

## 自查

- 为什么 C++98 元函数用 `enum` 而不是 `static const int`？（后者 ODR-used 时需类外定义，
  当引用传参就链接失败——本书 1 章静态成员的镜像问题）
- `CountPtr` 递归与 `std::index_sequence` 构造同构吗？（同：线性实例化链 + 累加器可换折叠）
- 类型过滤今天还非用模板不可吗？（值的过滤 constexpr 即可；**类型**列表操作仍是
  tuple/variant 时代刚需，如 `variant` 构造去重）
