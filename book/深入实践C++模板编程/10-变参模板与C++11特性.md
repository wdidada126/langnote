## 核心概念速览（中英对照）

- **参数包** — template/function parameter pack（`class... Ts` / `Ts... args`）：零或多个元素的编译期序列
- **展开模式** — pack expansion pattern：`f(args...)` 中的 `args` 所在子式，逗号处繁殖
- **`sizeof...`** — 包的大小：编译期元素计数，旧时代靠元容器 Length（07/08 章）
- **递归展开** — recursion via overload：`print(H, R...)` 剥头递归 + 空包重载做基例（C++11 唯一姿势）
- **折叠表达式** — fold expression（C++17, N4295）：`(args + ...)` 一元/`(init + ... + args)` 二元，递归展开的正名
- **外部模板** — extern template（N1987）：01 章老话题的 C++11 语法化——抑制隐式实例化
- **模板别名** — alias template（`template<class U> using My = X<U, int>;`）：可参数化的 typedef，补齐 C++98 缺口
- **`>>` 连续右尖括号**：C++11 起 `vector<vector<int>>` 不拆字——词法级体验修复
- **后置返回类型** — trailing return type（`auto f() -> decltype(x)`）：依赖推导结果当返回类型的前置解
- **标准 tuple** — `std::tuple` + `get<I>`/`make_tuple`/`tie`：02/07 章手工元组的官方收编

## 机制：参数包的三种遍历法

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17（e_old_vs_variadic.cpp + h_modern_replacements.cpp）
template <class... Ts> struct Tup { static const int size = sizeof...(Ts); };
// ① 递归展开(C++11 唯一直写方式):剥头 + 空包基例
void print_all() { std::printf("\n"); }
template <class H, class... R>
void print_all(H h, R... r) { std::printf("%d ", (int)h); print_all(r...); }
// ② 折叠(C++17):一行终结 ①
template <class... Ts> int sum17(Ts... ts) { return (ts + ...); }
// ③ 数组初始化列表展开(C++11 时代的"伪折叠"惯用法):
//    int dummy[] = {0, ((void)std::printf("%d ", ts), 0)...};
show(1, 2.5, "s");                      // 实测:折叠打印包内元素
std::apply([](auto&&... xs) { ((std::printf("t:%d ", (int)xs)), ...); },
           std::tuple{7, 8, 9});        // 实测: tuple→pack 桥
```

机制层三点：① 包**不能单独存在**，必须嵌在展开模式里（模板实参、函数实参、
using-declaration 的 `T... = D...` 各有语法位）；② 多重包展开要求**等长**（`Pair<Ts...> ... `
zip 语义由编译器检查）；③ 递归展开的终止靠**重载决议**选中空包版本——03 章的
候选淘汰机制在变参语境复用。`sizeof...` 与 `static_assert(sizeof...(Ts) >= 2)` 让
arithmetic 校验第一次可以写进函数内部（当年 MPL 要 `assert_` 元算法）。

**推导扩展三件套**（15.2）：`auto` 变量=按初始化器走一遍模板实参推导；
`decltype(expr)` 取表达式**类型与值类别**（这是 09 章转发的观察窗）；后置返回类型
解决「返回类型里要用形参名」的顺序悖论。`std::make_unique` 缺席 C++11、C++14 补票是
书中「拾遗」时段后的公案 ⚠️（原书未提，本目录补记，机制核过）。

**lambda 的机制定位**（16.1，编译器视角）：闭包=编译器合成的匿名类，捕获列表=成员、
`operator()` const 化=默认；可转函数指针的无捕获 lambda 在模板实参位上等价于函数指针
NTTP（02 章的伏笔，C++20 起有捕获的 lambda 也进入 NTTP 世界）。书中「foreach 三种写法」
的第一写法（裸 for）今天让位给 range-for + views 管道。

第 16 章组件的现代合订本（🔧 已实测 g++ 15.2 -std=gnu++17；`make_unique` 一行按史实
需 C++14）：

```cpp
template <class T> using IntAllocVec = std::vector<T, std::allocator<T>>; // 别名模板:
// 对位 04 章 rebind 仪式——旧时代要写 struct rebind{typedef ...;},今天一行 using
int isum(std::initializer_list<int> xs) { int s = 0; for (int x : xs) s += x; return s; }
IntAllocVec<int> v{1, 2, 3};                       // isum({10,20,30})=60 实测
int a, b2; std::tie(a, b2) = std::make_tuple(2, 1);// tie=「左值打包」反向 unpack
std::unique_ptr<int> p = std::make_unique<int>(7);
std::unique_ptr<int> q = std::move(p);             // 独占所有权:拷贝被编译期处死
// 实测输出 v=3 isum=60 tie=(2,1) *q=7 p==nullptr ——全部通过
```

`initializer_list` 的机制一句话：花括号列表物化为 `const T(&)[N]` 数组 +
{指针,长度} 视图，**元素仍是拷贝**——书中 16.2 的「初值封装类模板」正是 std 侧的
同款设计；而 unique_ptr 的「删除拷贝 + 移动构造」组合是 09 章移动语义的所有权化应用：
把「资源单一主人」写进类型系统，运行期双释放从「纪律问题」变成「编译不过」。

**别名模板 vs 02 章 rebind 的正面对账**：`allocator_traits` 的 rebind 在 C++11 头文件里
就是一行 `template <class T, class U> using rebind_alloc_t = typename rebind_alloc<T, U>::type;`
——当年手写嵌套模板干的事，现在是语言原语的组合。`>>` 修复则纯属词法：编译器把
`> >` 贪婪合并再拆分，从此嵌套闭括号不用带空格（书中 15.3.3 的欣慰一句话）。

## 权衡：新语法吃不掉的东西

- 变参模板**没有包索引**：`args[i]` 不可写，按位取元素仍需 `std::get<I>(tuple)` 或
  递归——C++26 的 pack indexing `args...[i]` 才补上（⚠️ 提案状态未核实，仅作方向注记）。
- lambda 闭包类型匿名不可命名：返回 lambda 要靠 `auto`（C++14）+ 移动（09 章）合奏。
- `unique_ptr` 拷贝禁死：一切「存进容器再分享」的需求都逼出 `shared_ptr`——所有权
  语义务必在设计期裁决（条款化论述在
  [../Effective_Modern_C++/04-智能指针.md](../Effective_Modern_C++/04-智能指针.md)）。

## 最新演进与工业实践

- **变参三件套后续**：折叠 N4295（C++17）、CTAD P0091R3（C++17，
  `std::pair p{1, 2.0};` 实测 g++ 15.2，聚合版 C++20）、`std::type_identity`
  P0887R1 "The identity metafunction"（C++20，实测：非推导上下文
  `append(vec, type_identity_t<T> item)` 一子句终结当年 `::type` 阻断推导的仪式）。
- **lambda 的四次长大**：C++14 泛型 lambda（`auto` 形参）与初始化捕获、C++17
  `*this` 捕获、C++20 **模板参数 lambda + constexpr lambda**——书中 9.2.1「foreach
  三种写法」今天的答案是「range-for + lambda + views 管道」。
- **tuple 生态**：`std::apply/invoke/make_from_tuple`（C++17）、
  `std::to_tuple`（C++23 图书馆，⚠️ 提案号未核）；`std::tuple_size` 特化成为
  结构化绑定的定制点——02 章嵌套元组的完全反转（协议向类型要信息）。
- **工业样板**：abseil `absl::StrCat(args...)` 用变参+类型擦除 `AlphaNum` 实现
  零分配两趟拼接——「递归展开 vs 数组展开 vs 折叠」三代写法的活化石对比
  （github.com/abseil/abseil-cpp `strings/str_cat.h`）；fmt `make_format_args`
  以 `format_args`（类型擦除包视图）承载异构参数包，是 15 章语法的性能工程课。
- **别名模板的终验**：`allocator_traits<A>::rebind_alloc`（04 章）、ranges 的
  `views::transform_t` 之类缩写族、`std::pmr::vector<T> = vector<T, polymorphic_allocator<T>>`
  ——C++98 内嵌 `rebind` 模板彻底让位给一行 `using`。
