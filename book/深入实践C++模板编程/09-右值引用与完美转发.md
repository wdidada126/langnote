## 核心概念速览（中英对照）

- **左值/右值** — lvalue / rvalue：可取地址、有身份的 vs 将死的临时物；本书按「非左值即广义右值」推进
- **右值引用** — rvalue reference（`T&&`）：绑定将死对象、授权**搬走**其资源的新引用类型
- **返回值优化** — RVO/NRVO：编译器直接在目标存储上构造返回值；当年**非强制**，移动是它的兜底
- **移动构造/移动赋值** — move ctor/assignment：偷指针、留空壳——深拷贝 O(n) 降为 O(1) 交换
- **左值强制转义成右值** — `std::move`：其实是 `static_cast<T&&>`，**不搬任何东西**，只是改判值类别
- **右值引用变量是左值** — named rvalue ref is lvalue：具名即有身份——函数体内转发链的头号陷阱
- **引用折叠** — reference collapsing：`& &→&`，`&&` 出现在 `&` 旁一律降级；成员模板与转发的地基
- **转发引用** — forwarding reference（旧称 universal reference）：仅存在于 `T&&` 推导形参与 `auto&&`
- **完美转发** — perfect forwarding：`std::forward<T>` 按推导记忆原样还原值类别再传参
- **noexcept 与移动** — 强保证的筹码：vector 扩容只肯用不抛的移动，否则退回拷贝

## 动机：临时物的一生之耻

14.1 的历史账（机制转述）：C++98 里 `string t = f() + g() + h()` 每次临时物落地都要
深拷贝资源；RVO 能省则省，但**NRVO 失败（多返回路径）与嵌套临时物**无计可施。
右值引用的解法不是「延长临时物」（const 引用早就会），而是**给它一个合法的死后处理窗口**：
绑定 `T&&` 即宣告「此对象将死，资源可征用」。

值类别体系的编译期投影：重载决议把 `T&&` 形参排在 `const T&` 之后仍可胜——
**非 const 精确绑定右值优于 const 绑定**；这就是 `string` 同时挂移动/拷贝两版赋值、
按实参值类别自动选路的机制。

## 机制：折叠规则与转发的信息流

「引用声明符消去规则」（书用词，即 reference collapsing）：

```text
T&  &   → T&        T&  &&  → T&
T&& &   → T&        T&& &&  → T&&
```

它**不是为转发设计的**，而是成员模板绑定引用时的无歧义要求（02 章「通用拷贝构造」
`X<T>(T&&)` 收 lvalue 推出 `X&`——没有折叠规则就构造出「引用的引用」这种非法类型）；
折叠是地基，转发引用是盖出来的楼。推导规则一句话：**实参是左值 → `T` 推成 `X&` →
`T&&` 折叠成 `X&`（保住 lvalue 身份）；实参是右值 → `T` 推成 `X` → `X&&`**。

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17（g_move_forward.cpp 节选）
template <class T> struct is_lref : std::false_type {};
template <class T> struct is_lref<T&> : std::true_type {};
template <class T> void take(T&&) {
    std::printf("take: T deduced as lvalue-ref=%d\n", (int)is_lref<T>::value); }
int n = 7; take(n);             // lvalue-ref=1  (T=int&)
take(std::move(n));             // lvalue-ref=0  (T=int)

template <class F, class... Args>
auto logged(F&& f, Args&&... args)
    -> decltype(std::forward<F>(f)(std::forward<Args>(args)...)) {
    std::printf("[before]\n");
    return std::forward<F>(f)(std::forward<Args>(args)...);
}
```

`forward<T>` 的实现就是查表：`T` 是 lvalue-ref 则返回 lvalue，否则 `static_cast<T&&>`——
**move 是无条件改判，forward 是还原性改判**，一字之差决定转发链是否「完美」。
14.3.2 的「智能 min」实例即此理：min 要把实参**原值类别地**返回并转给下游——

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17：智能 min(节选)
template <class T>
constexpr T&& min_ref(T&& a, std::remove_reference_t<T>& b)   // a 右值路径
    noexcept { return static_cast<T&&>(a); }
template <class T>
constexpr T& min_ref(T& a, T& b) noexcept { return b < a ? b : a; }  // 双左值路径
// 语义:两个左值→返回较者的左值引用;任一右值→返回右值引用(不许悬垂)
// 关键约束:第二形参写成「非推导的 lvalue 引用」阻止 a 为右值时 b 也绑右值
```

## 移动与异常：14.4 的硬核实测

「迁移数据的风险」：移动构造抛异常=源对象半搬走，容器强保证（要么成功要么原样）瞬间破产。
C++11 的裁决写进 `vector` 扩容逻辑——**搬移用 `move_if_noexcept`**：移动构造不 `noexcept`
就宁可拷贝。实测对照（🔧 已实测 g++ 15.2）：

```cpp
struct BlobNoMoveThrow {          // 移动构造标了 noexcept
    std::string data;
    BlobNoMoveThrow(std::string s) : data(std::move(s)) {}
    BlobNoMoveThrow(const BlobNoMoveThrow&) { std::printf("copy\n"); }
    BlobNoMoveThrow(BlobNoMoveThrow&&) noexcept { std::printf("move-noexcept\n"); }
};
std::vector<BlobNoMoveThrow> v;
for (int i = 0; i < 3; ++i) v.emplace_back("xxx...");
// 实测输出: move-noexcept × 3 —— 无一次 copy
```

把 `noexcept` 删掉再跑同一循环，扩容路径立刻转为 copy（书中 14.4.4「移动的效率问题」
的另一半：`swap` 走 move 还是三次拷贝也看它）。「转义函数模板」（14.4.3，机制转述）
提醒 move-only 资源（文件句柄）穿过绑定/存储层时的逃逸审计——今天对应
`std::unique_ptr` 作参数按值+移动的标准姿势。

## 权衡：三件反制完美转发的旧事

- `T&&` 贪吃一切：`f(7)` 与 `f(x)` 同签名——接口自述能力为零（C++20 概念约束是解药）。
- 初始化列表的转发陷阱：`vector<T> v{a, b}` 里 a 是 lvalue 会被 copy_list 截走，
  移动语义失踪——书中时代正发生，C++11 至今无解（`emplace_back` 绕道）。
- 折叠让 `forward<T>(x)` 的 `T` 不能手写类型名：一旦写死 `forward<int>` 就把 lvalue
  强转成 xvalue——「完美」破产。

## 最新演进与工业实践

- **C++17 保证性拷贝消除**：纯 prvalue 直接就地构造，传参返回不再产生临时物——
  当年「为省一次拷贝写移动」的场景少了一半（`std::pair p{a, b}` 传参即 prvalue）。
- **术语修正**：「通用引用」（Meyers 造词）被标准术语 **forwarding reference** 取代
  （C++14 决议，⚠️ 提案号未核），[../Effective_Modern_C++/05-右值移动完美转发.md](../Effective_Modern_C++/05-右值移动完美转发.md)
  第 24–27 条是本章的英文世界的镜像章。
- **`noexcept` 的库化**：C++17 起 `noexcept` 进**函数类型**（`void()noexcept` 与
  `void()` 是两个类型），重载/特化可区分——14.4.2 的标注从此参与类型系统（⚠️ 提案号未核，机制已核）。
- **工业对照**：abseil 用 `absl::string_view` 显式「按值+不转发明针」的载荷类，提醒
  转发引用不该贪 view 类型；fmt 的 `append_to`/out-iters 按值收 `appender`（移动
  友好 trivially copyable）避开了转发的生命周期黑洞（github.com/abseil/abseil-cpp、
  github.com/fmtlib/fmt）。
