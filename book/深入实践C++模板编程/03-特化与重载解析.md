## 核心概念速览（中英对照）

- **全特化** — full/explicit specialization：`template <> class X<int*> {...}`，实参形状完全钉死
- **偏特化** — partial specialization：`template <class T> class X<T*> {...}`，只约束实参形状——**类模板特权**
- **主模板** — primary template：偏特化的锚；没有它，特化无处派生
- **最特殊化优先** — most specialized wins：多个部分匹配时取「偏序最大」的特化，平手即歧义错误
- **特化优先级阶梯** — 主模板 < 偏特化 < 全特化：越具体越先被选中
- **函数模板无偏特化** — no partial specialization for functions：只能全特化，且不参与重载偏序
- **模板实参偏序** — partial ordering of function templates：两个候选函数模板比「谁更受约束」
- **编译期条件判断** — compile-time branching：2013 年的解法是特化选型，今天的解法是 `if constexpr`
- **SFINAE** — Substitution Failure Is Not An Error：替换失败只淘汰候选，不产生诊断（详见 06 章展开）

## 动机：`vector<bool>`——一句「特例改变语义」的活教材

书中从 `vector` 谈起（机制转述）：`vector<bool>` 全特化成**位压缩代理**——`operator[]`
返回的不是 `bool&` 而是代理对象，`size()` 数的是位组。教训有两层：

1. 特化不只是「换个更快的实现」，它**可以合法地改变接口语义**（`vector<bool>` 至今
   是标准库最著名的设计事故，[../C++标准库/04-容器.md](../C++标准库/04-容器.md) 有现代处置）；
2. 反过来，接口不变、只优化存储的特化才是常态：`hash<T*>`、traits 的指针特化全是这一类。

## 机制：类模板特化的匹配与优先级

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17
template <class T> struct name { static const char* get() { return "primary"; } };
template <class T> struct name<T*>            { static const char* get() { return "ptr-partial"; } };
template <class T> struct name<const T*>      { static const char* get() { return "constT*-partial"; } };
template <>       struct name<int*>           { static const char* get() { return "int*-full"; } };
// name<int>        → "primary"
// name<int*>       → "int*-full"      （全特化压过两条偏特化）
// name<double*>    → "ptr-partial"    （const T* 不匹配 non-const double*）
```

编译器行为层面的两步：**(a) 候选收集**——把所有能「覆盖」本次实参向量的偏特化
（含主模板、含全特化）摆上桌；**(b) 取最特殊者**——对候选两两做**偏序**：把甲的实参
模式拿去推乙的形式参数，若乙能推出而甲推不出乙，则甲更受约束。全特化实参全是具体
类型，必然压过任何偏特化；两条偏特化互相推不出对方时为**歧义**，编译错误。

函数模板这边规矩完全不同（书中 4.4 节核心）：

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17
template <class T> T pick(T a, T b)  { return a; }
template <class T> T pick(T* a, T* b) { return *a; }   // 合法:这是重载,不是偏特化
// template <class T> T pick<T*>(T* a, T* b) {...}     // 非法:函数模板没有偏特化
```

「重载而非偏特化」有一条暗坑：两个函数模板的**全特化**不生成新重载，只特化已有模板——
`template <> int pick<int>(int, int)` 合法，而期待它像偏特化一样吃掉指针版就错了。
当年的标准绕行是**实现类惯用法**（🔧 已实测 g++ 15.2）：

```cpp
template <class T> struct pick_impl;                      // 主模板:类这边有偏特化特权
template <class T> struct pick_impl<T*> {
    static T go(T* a, T*) { return *a; }
};
template <> struct pick_impl<int> {
    static int go(int a, int) { return a; }
};
template <class T>
auto pick2(T a, T b) -> decltype(pick_impl<T>::go(a, b))   // 返回类型交给选型层
{ return pick_impl<T>::go(a, b); }
// 实测: pick2(x,y)=1(走 int 版), pick2(&x,&y)=1(走 T* 偏特化版)
```

即「函数模板收推导、类模板做选型」——把语言欠的偏特化在两个模板家族间挪用。

**为什么函数模板没有偏特化**（标准侧的设计决断）：函数模板的选型走**重载决议 +
模板实参偏序**，再叠加一层偏特化会与重载规则打架（`f(int*)` 全特化版本还隐式生成
函数模板的怪诞交互是历史包袱）。工程替代三件套，按年代排列：
| 年代 | 惯用法 | 今天状态 |
| --- | --- | --- |
| C++98 | 转发到**类模板的偏特化**（`detail::pick_impl<T>` 静态函数） | 仍可用，叫 implementation-class idiom |
| C++98 | 手写**重载**吃掉更具体的形状 | 可用，但要记得重载不吃隐式转换 |
| C++11 | `enable_if` SFINAE 互斥重载 | 被 C++20 约束取代（见下） |
| C++17 | `if constexpr` 单函数内分叉 | 首选（P0292R2，wg21.link 实测可达） |

**「分辨重载」一节**（书中 4.4.1，机制转述）的要点：`f(T)` 与 `f(T*)` 同时可行时，
`f(p)`（p 为指针）选 `f(T*)`——偏序认定指针版更受约束；但 `f(int*)` 的**非模板**普通
函数优先于一切函数模板特化/实例（重载决议：非模板 exact match 先赢）。

**「编译期的条件判断逻辑」（4.4.2）**：用特化选型当 if——`selector<cond>::type`、
`if (traits<T>::is_ptr)` 这种「运行期写 if、条件却是编译期常量」的形态在 2013 年
只能靠特化 + 死代码仍须可编译的隐忍；C++17 `if constexpr` 之后被丢弃分支**不实例化**，
正名替代。实测对比（🔧 已实测 g++ 15.2）：

```cpp
template <class T> auto describe(const T& v) {
    if constexpr (std::is_integral_v<T>) return std::string("int:") + std::to_string(v);
    else if constexpr (std::is_pointer_v<T>) return std::string("ptr");
    else return std::string("other");
}
```

旧写法下 `std::to_string(&v)` 这种「错误分支里的合法代码」会在实例化时炸；
`if constexpr` 下该分支根本不出实体。

## 权衡：特化是权力，也是无政府

特化**不可被访问控制约束、不做接口兼容性检查**（成员可以完全不同），全特化后
声明与定义可以天各一方（ODR 区）。所以现代库设计的口径（Bancila 与 boost 风格一致）：
- 数据萃取类模板（traits）：**欢迎**特化——它就是为此而生（[07 章](07-高级模板编程技巧.md) traits 主题）；
- 行为容器类：尽量**禁止派生式特化**，用 `static_assert` 拦路或 `final` 设计；
- 接口收窄型特化（`vector<bool>` 式）：教科书级反例，C++20 用 `container` 概念
  （P0898R3 族，实测可达）把「`operator[]` 必须返回引用」写进要求——
  **特化不再能悄悄违约，违约即不满足概念**。

## 最新演进与工业实践

- **约束重载取代 enable_if 选型**：`template <std::integral T>` 直接表达「这条重载只在
  整数时可行」，重叠约束靠 subsumption 判优先（06 章有 SFINAE vs concepts **诊断对比实测**）。
- **`std::type_identity_t` 拆推导**（P0887R1 "The identity metafunction"，wg21.link 实测可达）：
  想把「推导冲突」变成「以第一参数为准」的合法重载，把第二参数包进
  `type_identity_t<T>` 变非推导上下文——2013 年用嵌套 `::type` 手工实现的同款效果。
- **fmt 的选型**：`fmt::formatter` 为基本类型预置特化（`formatter<char>` 等），且用
  `static_assert` 拒绝未定义 `formatter` 的特化滥用——特化权力 + 概念式验收的现代样板。
- **`vector<bool>` 的遗产**：range-v3/abseil 文档圈普遍建议需要位压缩时显式选
  `std::vector<char>`/`absl::...`/`boost::dynamic_bitset`（github.com/ericniebler/range-v3、
  github.com/abseil/abseil-cpp），_proxy 容器必须走 `ranges::range` 的 proxy 规则_。
