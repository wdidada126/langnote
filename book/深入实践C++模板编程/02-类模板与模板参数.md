> 主题：类型无关数据结构、栈类模板及其子类化、异质链表、嵌套实现元组、成员/友元

## 核心概念速览（中英对照）

- **类模板** — class template：数据结构骨架 + 类型参数；每个实参组合一个独立类型
- **模板参数推导在类上的缺席** — 2013 年现状：类模板使用点必须写全 `< >`（C++17 CTAD 改变）
- **异质链表** — heterogeneous list：每节点持不同类型，`List<Head, Tail>` 嵌套的雏形
- **嵌套实现元组** — tuple via nesting：`tuple<A, tuple<B, tuple<C, empty>>>`，变参前夜的正解
- **成员函数模板** — member function template：类已有参数之外再开一层模板参数
- **友元函数模板** — friend function template：类内声明注入非成员 `operator<<`/`operator==`
- **类模板静态成员** — static member of class template：每个 `X<T>` 一份，跨实例计数器的载体
- **非类型模板参数** — non-type template parameter (NTTP)：整数、指针、引用、成员指针——值进入类型系统
- **成员函数指针模板参数** — pointer-to-member as template argument：对象+成员指针打包泛型访问器
- **模板型模板参数** — template template parameter：形参是「模板」而非类型/值，容器适配器骨架

## 动机：从「一个栈」到「一族栈」，再到「类型当数据流」

书中第 2 章以栈为教具（机制转述）：`Stack<T>` 内含数组与顶指针；派生类 `SubStack<T>`
继承类模板时**自己也要带模板参数并转发实参**（`class Sub : public Base<T>`），因为
基类模板不是类型，`Base<T>` 才是——这句话就是「类模板是造类型的机器」的最直白表述。

更精彩的是两件「类型组装术」：

- **异质链表**：C++98 没有 `std::tuple`，把「一串未知类型」塞进编译期的办法是
  递归嵌套节点 `struct node { H head; tail_node next; }`——类型信息进类型系统，
  运行期只留数据。这是 07 章「伪变参模板」和 Abrahams 书 MPL 列表的同源技法。
- **嵌套元组**：`tuple<A,B,C>` = `A × (B × (C × ()))`，取值 `get<0>` 沿嵌套层级编译期递归。
  🔧 本目录在 [07-高级模板编程技巧.md](07-高级模板编程技巧.md) 用
  `List<int, List<double, List<char, Nil>>>` + `At<I>` 复现并**已实测 g++ 15.2**，
  与 C++11 `sizeof...` 版并排对照。

**成员函数模板**的杀手应用是「通用拷贝构造」：`template <class U> shared(const smart_ptr<U>&)`
让 `shared_ptr<Derived>` 转 `shared_ptr<Base>` 而不误触普通拷贝重载；书中还演示了它与
重载决议的互动——**成员模板比普通成员函数在偏序里更不受约束**，能匹配的一律让位非模板版。

**友元函数模板**解决 `operator<<` 找不到门内私物的两难：类内一行
`template<class W> friend int peek(const X<W>&) { return ...; }`
把「非成员 + 能看私有 + 类型随宿主推」三件事同时办成；注意它属于**注入式名字
（friend-injected name）**：编译器侧的落点是**不进入外层名字空间的普通可查找集**，
只有当实参类型恰在该类所在名字空间时，ADL（实参相关查找）才把它捞出来——
「为什么这个 `<<` 不写 using 也能找到」的唯一答案。🔧 已实测 g++ 15.2 -std=gnu++17：
`main` 里裸调 `peek(x)` 纯靠 ADL 命中；而**只在类内声明、类外定义**会得到
「声明可找到、链接期 undefined reference」的半瘫状态（实测踩坑）——友元模板要么
类内定义，要么改用「类外具名模板 + 前置声明 + friend 引用」的标准三件套。

**类模板静态成员（2.6）**：`template <class T> struct Counter { static int n; };`
的 `n` 属于 `Counter<T>` 每一个实例各一份，定义仍须类外（C++17 前）：

```cpp
// 🔧 教学示意（成员定义规则已实测 g++ 15.2 -std=gnu++17）
template <class T> struct Counter { static int n; };
template <class T> int Counter<T>::n = 0;   // 每个模板一份「定义模板」
Counter<int>::n++;   // 与 Counter<char> 的 n 互不相干（呼应 01 章函数模板静态变量）
```

这条规则在编译器的落点：静态成员的定义本身是个模板，**只有被使用才实例化出对象**；
滥用它会得到「链接期才发现某 TU 没带定义」的经典错误——与 01 章 HPP/CPP 链接失败
同源同治（显式实例化或定义进头）。

## 机制：五种模板参数的编译器视角

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17（NTTP 四连）
template <int N> struct Fixed { int arr[N]; };            // 整数：值→维度→类型系统
int twice(int x) { return 2 * x; }
template <int (*F)(int)> int applyT(int x) { return F(x); } // 函数指针：行为参数化
struct A { int v; };
template <class C, class M> struct Wrapper {               // 成员指针：数据成员泛型访问
    C obj; M mem;
    auto call() -> decltype(obj.*mem) { return obj.*mem; }
};
template <template <class, class> class Container, class T> // 模板型模板参数
size_t count_of(const Container<T, std::allocator<T>>& c) { return c.size(); }
```

逐条到编译器行为层面：

1. **整数 NTTP**：实参必须是常量表达式；值参与类型同一性判断（`Fixed<8>` 与 `Fixed<9>`
   是两个类型，各自实例化 static 成员）——这就是「用类型系统记编译期状态」的入口。
2. **函数指针/引用 NTTP**：要求链接期有实体或具内链接，调用点变成间接但可内联
   （编译器看到具体 `F` 后直调）。C++20 起函数指针可用**无捕获 lambda** 现场提供，
   当年「先定义全局函数再传名」的仪式被免除 ⚠️（提案号未核，机制已核）。
3. **成员函数指针 NTTP**：难点在其**类型本身**——`int (A::*)() const` 里的 cv/ref 限定
   都是类型的一部分；对象模型层面成员指针不是裸地址（可能带虚表偏移修正），
   详见 [../深度探索C++对象模型.md](../深度探索C++对象模型.md) 第 4 章。
4. **模板型模板参数**：形参的「形状」（参数个数/种类）必须与实参模板匹配；C++98 时代
   `Container<T, Alloc>` 写法把带分配器的容器锁死，C++11 变参形参
   `template <class...> class` 才解套（[../C++20模板元编程.md](../C++20模板元编程.md) 视角）。

## 权衡：嵌套手工账 vs 语言原生

异质链表/嵌套元组的一切优雅都记在编译期，代价同样记在编译期：
诊断信息不可读（`List<A, List<B, ...>>` 报错滚雪球）、实例数量随深度线性增长、
手工 `At<I>` 每层一个类。这是「用 1998 年语言写 2011 年库」的普遍形态——
**技巧本身不是目标，它是语法真空期的代偿**。

相邻概念对比：Java 泛型用擦除把类型信息**扔掉**（运行期无 `List<A,B>` 可问）；
C++ 模板把类型信息**留在编译期当数据用**——本书第 2 章的元组构造与第 13 章元编程
是同一枚硬币的两面。

## 最新演进与工业实践

- **元组线**：C++11 `std::tuple` + 变参模板直接吸收 2.4 节全部手工活；`std::apply`（C++17）
  把「沿嵌套层级递归」换成折叠。实测：`std::apply([](auto&&... xs){...}, std::tuple{7,8,9})`
  展开打印，g++ 15.2 通过（见 [10-变参模板与C++11特性.md](10-变参模板与C++11特性.md)）。
- **CTAD**：类模板使用点免写 `< >`（P0091R3，wg21.link 实测可达），
  `std::pair p{1, 2.0};`、`std::lock_guard g(m);`——2013 年「使用点必须全类型」的戒律成为历史。
- **成员指针线**：C++17 `std::invoke` 统一「可调用物 + 对象」调用形式，成员指针 NTTP
  的包装价值转移到 `std::function`/`mem_fn` 场景（对比见 [../Effective_Modern_C++/08-微调与全书收束.md](../Effective_Modern_C++/08-微调与全书收束.md)）。
- **模板型模板参数的工业面**：abseil 容器族、range-v3 的 `viewable_range` 约束里
  「以模板为参数做萃取」仍常见（github.com/abseil/abseil-cpp、github.com/ericniebler/range-v3）。
- **NTTP 解放（C++20）**：允许「结构性类型」——字面量聚合类、`std::string_view`、
  甚至指定数组作非类型参数（⚠️ 提案号本次未核实；机制：编译器以对象表示做类型同一性
  哈希），「整数与指针专属」的 2013 教条正式过期。
