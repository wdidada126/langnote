## 核心概念速览（中英对照）

- **三权分立** — container/iterator/algorithm decoupling：N 容器 × M 算法靠迭代器做中介，复杂度从 N×M 降到 N+M
- **序列容器** — sequence container：vector/list/deque，位置语义由存储布局决定
- **容器适配器** — container adaptor：stack/queue/priority_queue 只改接口不改存储
- **关联容器** — associative container：树家族 set/map/multiset/multimap，序由比较策略供给
- **散列容器** — hash containers：本书成书时是 TR1 扩展（`unordered_*` 于 C++11 转正）
- **分配器** — allocator：把「内存从哪来」从容器实现里剥离出来的可替换组件
- **分配器等价性** — allocator equality：`a1 == a2` 则内存可跨对象互释——无态/有态的分水岭
- **rebind** — allocator rebind：`A<int>` 换 `A<Node>` 的模板型模板通道；C++11 起由 traits 自动推导
- **池分配器** — pool allocator：定长块回收复用，小对象高频分配的工程正解
- **定位构造** — placement new / in-place construction：分配与构造彻底解耦的会师点

## 动机：Java 擦除 vs C++ 模板——同一目标的两条路

书中第 5 章的对照（机制转述）极有价值：Java 用**继承 Object + 运行期向下转型**（或
擦除泛型）实现「一个容器装万物」，代价是类型安全后移到运行期、整数装箱；C++ 用
**编译期参数化**实现同一目标，类型信息全程保留，还能让迭代器做「容器能力」与
「算法需求」之间的**唯一契约**。这套契约的三份合同：

- 容器合同：提供 `begin/end`、元素类型 `value_type`、（可选）分配器参数；
- 迭代器合同：五档能力标签 + 五个 typedef（05 章展开）；
- 算法合同：只吃迭代器区间 + 函数对象，绝不 `dynamic_cast` 回容器。

第 6 章按此骨架过容器家族（vector 翻倍扩容、deque 分块、红黑树 map、堆做
priority_queue、TR1 散列表），与 [../STL源码剖析/04-序列式容器.md](../STL源码剖析/04-序列式容器.md)、
[../STL源码剖析/05-关联式容器.md](../STL源码剖析/05-关联式容器.md) 完全互文——本书讲「用」，
侯捷书讲「造」，此处不重复源码细节。

容器适配器是 02 章「模板型模板参数」的官方用武之地（机制转述，签名按现行标准核对）：

```cpp
template <class T, class Container = std::deque<T>,
          class Compare = std::less<typename Container::value_type>>
class priority_queue;   // 元素类型/宿主容器/比较策略:三个注入点三层决策
std::priority_queue<int, std::vector<int>, std::greater<int>> min_heap;
```

stack/queue 各两参（容器可换）、priority_queue 三参（还要换序策略）；bitset（6.4.6）
则是「整数 NTTP 定容量」的反例——**不走分配器、不走迭代器**，用 `unsigned long`
数组硬怼位运算，提醒读者容器家族从来没有一个大一统模板骨架。交换语义（7.2 专节）
埋着分配器的第一个雷：容器 swap 时分配器不等则**禁搬内存**、只能退化为逐元素移动
（C++11 起有 scoped 传播规则前更是雷区，见下文权衡节）。

## 机制：分配器——模板版依赖注入的最早标准化样本

第 7 章是本书工程含金量最高的入门章之一。书中列分配器基本要求（机制转述）：
`value_type`、`allocate/deallocate`、`construct/destroy`（定位构造/显式析构）、
`rebind` 成员模板、相等性判断。实践是一个**池分配器**：一块大 arena 切成等长子块，
`allocate` 摘空闲链、`deallocate` 头插归还——构造与析构仍归容器管。

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17（节选自 c_iter_alloc.cpp，满足最小 allocator 要求）
template <class T, std::size_t Chunk = 64>
struct pool_alloc {
    using value_type = T;
    template <class U> struct rebind { using other = pool_alloc<U, Chunk>; };
    pool_alloc() = default;
    template <class U> pool_alloc(const pool_alloc<U>&) {}      // 转换构造：跨类型复用
    T* allocate(std::size_t n) { return static_cast<T*>(::operator new(n * sizeof(T))); }
    void deallocate(T* p, std::size_t) { ::operator delete(p); }
    template <class U> bool operator==(const pool_alloc<U>&) const { return true; } // 无态:一切实例等价
    template <class U> bool operator!=(const pool_alloc<U>&) const { return false; }
};
std::vector<int, pool_alloc<int>> pv{5, 6, 7};  // 实测可用
```

编译器行为层面的三个关键点：

1. **等价性决定代码共享**：无态分配器（本例）所有 `pool_alloc<T,64>` 互通——节点
   内存可被任意类型的同配置实例释放，容器实现可以把 `deallocate` 折叠成一份函数；
   有态分配器（真内存池句柄）则每个 `T` 各持状态，**等价性判断错一次就是堆破坏**。
2. **rebind 的动机**：`vector<T, A>` 内部要分配的是**节点**不是 T，`A<int>` 必须能变
   `A<Node>`；2013 年靠嵌套 `rebind`，C++11 起 `std::allocator_traits<A>::rebind_alloc`
   自动从模板头部拆参（拆不出来仍回落 `rebind`）——**实测：给带非类型参数的
   `pool_alloc<int>` 加 `rebind` 前 libstdc++ 15 直接报 no type named 'type'**，
   老式分配器在新库上的适配成本当场可见。
3. **分配 ≠ 构造**：`allocate` 给裸内存、`construct` 走 placement new——
   这条解耦让 vector 能实现「容量与大小分离」，也是 09 章 move/emplace 的前提。

## 权衡：分配器参数的成败账

- 收益：池化、跨进程共享内存（boost::interprocess 全靠它）、统计与调试
  （`-D_GLIBCXX_DEBUG` 风格的 tracking allocator）。
- 成本：接口污染（每个容器多一个模板参数→实例数量翻倍）、传播规则复杂
  （嵌套容器的 rebind 链）、多数用户根本不该碰。
- 标准的裁决史：C++11 `allocator_traits` 把「必须实现的成员」缩到 `value_type +
  allocate + deallocate`；C++17 加 scoped allocator 与容器递归传播；**C++20 删除
  `construct/destroy` 与 hint 版 allocate**（成员模板吃不进 concepts 化的接口，改由
  `std::construct_at/destroy_at` 承担）——本机 g++ 15.2 实测已按新口径（互证：
  [../STL源码剖析/07-专题-SGI_STL到现代标准库.md](../STL源码剖析/07-专题-SGI_STL到现代标准库.md)）。

## 最新演进与工业实践

- **std::pmr（C++17）**：`polymorphic_allocator` + `memory_resource` 把「换内存策略」
  从类型参数降到运行期对象——池分配器的精神转世，签名里不再有第三个模板参数。
- **abseil**：`absl::Allocator` 全局接管（`absl::SetGlobalAllocator`）走的是「根本不
  做容器模板参数」的另一条路线（github.com/abseil/abseil-cpp）。
- **fmt**：`fmt::detail::buffer` / `basic_memory_buffer` 用 `allocator_traits` 兼容的
  分配回调做增长缓冲区，是「分配器参数只在需要的层出现」的现代示范（github.com/fmtlib/fmt）。
- **C++20 容器概念**：`std::container`（P0448/P1006 线，⚠️ 提案号未逐一核实）
  正式规定：分配器**必须**能默认构造/拷贝/移动/交换/相等判断——第 7 章的基本要求
  如今是编译器可检查的合同。
- **`vector<bool>` 呼应 03 章**：其「代理引用」在 C++20 ranges 里是钦定的 proxy
  reference 模型（`iterator_traits` 时代它连 iterator category 都难自述）。
