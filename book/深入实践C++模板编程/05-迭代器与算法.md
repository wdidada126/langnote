# 05 · 标准库中的迭代器与算法（对应原书第 8–9 章）

> 原书位置：第 8 章「标准库中的迭代器」（P132–144）/ 第 9 章「标准库中的算法」
> （P145–178，含「矩阵操作消除循环语句」实践：跨跃/累计/组合迭代器）。
> 单文件大纲：[../深入实践C++模板编程.md](../深入实践C++模板编程.md)。

## 核心概念速览（中英对照）

- **迭代器五档** — iterator categories：input / output / forward / bidirectional / random_access，能力子集格
- **迭代器特性萃取** — iterator_traits：从任意迭代器（含裸指针）抽 value/difference/reference/category 五元组
- **基类自述** — inheriting `std::iterator<...>`：自定义迭代器继承基类即自带 typedef（C++17 起废弃、C++20 移除）
- **标签分派** — tag dispatch：拿类别标签当虚拟「函数重载键」，为同一算法选最优实现
- **迭代器适配器** — iterator adaptors：reverse/insert(_back/front)/stream，不改容器改「走法」
- **流迭代器** — istream/ostream_iterator：把 IO 流接入算法管线的胶水
- **函数对象** — functor：重载 `operator()` 的类；可带 typedef 供 traits 萃取（第 9.3 节）
- **参数绑定** — binder1st/bind2nd：把二元函数对象化约成一元；后被 `std::bind` 与 lambda 双杀
- **跨跃迭代器** — strided/zip 雏形：书中矩阵实践的自造迭代器，range-v3 的 `stride`/`zip` 祖先形态
- **算法即策略管道** — algorithms as policies：sort 吃什么序、transform 做什么映，全由函数对象供给

## 动机：迭代器是「抽象的指针」，更是**能力证书**

第 8 章的要点（机制转述）：算法不该问「你是什么容器」，只该问「你能走多快、能走几次」。
五档类别就是五张能力证书：单向一次（input）、单向可重复（forward）、可倒退（bidirectional）、
可随机跳转（random_access）。`std::advance` 的教学价值在于它是**同一个接口、两种实现**：

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17（c_iter_alloc.cpp 节选）
template <class It> void advance_impl(It& it, int n, std::input_iterator_tag) {
    while (n > 0) { ++it; --n; }          // list 路线：O(n)
}
template <class It> void advance_impl(It& it, int n, std::random_access_iterator_tag) {
    it += n;                               // vector 路线：O(1)
}
template <class It> void my_advance(It& it, int n) {
    advance_impl(it, n, typename std::iterator_traits<It>::iterator_category());
}
// 实测输出：[step-by-step] list -> 3 / [O(1) jump] vector -> 3
```

编译器行为层面：类别标签是**空类型**，按值传形参零成本；重载决议在编译期完成选择，
内联后不存在分派残留。traits 的兜底链是三层：自定义迭代器继承 `iterator<>` 基类自报
typedef → 类内手写 typedef → **裸指针 `T*` 的偏特化萃取**（`iterator_traits<T*>` 偏特化
直接给 random_access——呼应 [03-特化与重载解析.md](03-特化与重载解析.md) 的「偏特化为萃取而生」）。

## 机制：适配器谱系与第 9 章算法流水线

迭代器侧四类适配器（8.3/8.4 节）：`reverse_iterator`（++ 翻译成 --，端点偏移一位的
`base()` 语义要背）、`back_insert_iterator` 等（解引用即 push，**把覆写型算法
`copy/remove_copy` 变成追加型**）、`istream_iterator`/`ostream_iterator`（流→序列界面）。

`base()` 偏移机制值得在编译器层面说透：`rbegin()` 包的是 `end()`，其 `operator*`
定义为先回退再解引用（`*(--base_copy)`）——**为什么不能构造时就 -1？** 因为
`list::end()` 是不可自减的哨兵、而「减一再存」对 input 档不合法；把偏移推迟到
解引用瞬间是唯一对所有类别都成立的做法。`r.base()` 因此指向「正序下一次会越过的
位置」，`copy(v.rbegin(), v.rend(), out)` 的区间边界换算全依赖这条不变式。

算法侧（第 9 章）按功能族过：搜索（find/search）、计数比较、复制交换删除、排序、
二分、集合运算、堆操作；foreach 的三种写法（for 循环/`for_each`/range-for 前夜）
是书中时代感的可爱注脚。**函数对象是算法的第二输入**：`less<T>` 给序、`plus<>` 给
合并、谓词给筛选；9.3 的参数绑定（`bind2nd`）在 2013 年已显老态（书中亦有微词，
机制转述）。

第 9.4 节矩阵实践值得单独致敬（机制转述）：自造**跨跃迭代器**（步长跳行的
counting/strided 组合）、**累计迭代器**、**组合迭代器**，让矩阵乘法/ LU 分解
「没有一行循环语句」——本质是把循环结构编码进迭代器的 `operator++`，让通用
`transform_reduce` 驱动。这正是 **Veldhuizen 表达式模板**（*Expression Templates*,
C++ Report 1995，经 Wikipedia 词条互证）的同族思想：用模板把「循环的形状」提前到
类型层展开（表达式模板专章在 [../C++模板元编程/09-DSEL与表达式模板.md](../C++模板元编程/09-DSEL与表达式模板.md)）。

最小复现（🔧 已实测 g++ 15.2 -std=gnu++17，无循环取 3×3 矩阵第 2 列之和 = 15）：

```cpp
template <class It> struct strided {                       // 循环形状=类型
    using iterator_category = std::forward_iterator_tag;   // 能力证书手填
    using value_type = typename std::iterator_traits<It>::value_type;
    using difference_type = std::ptrdiff_t;
    using pointer = value_type*; using reference = const value_type&;
    It p; std::size_t step;
    strided& operator++() { std::advance(p, step); return *this; }  // ++ 即跨行
    bool operator==(const strided& o) const { return p == o.p; }
    bool operator!=(const strided& o) const { return !(*this == o); }
    reference operator*() const { return *p; }
};
int s = std::accumulate(col(1), col(10), 0);   // 2+5+8,零循环体
```

这个玩具同时讲清两件事：迭代器适配的全部秘密只有 `++/*//==` 三件事；而「五个
typedef 必须自报」的仪式——当年可继承 `std::iterator<>` 偷懒——正是下文「演进」里
被判废弃的那一个。

## 权衡：五档格子的得与失

- 得到：`sort` 只声明吃 random_access，编译器+重载决议替你挡住 list（运行期异常
  变成编译期不可行）；库作者与容器作者互不认识即可对接。
- 失去：能力是**离散档位**，真实需求是连续谱——「能前进但引用失效」（vector<bool>
  代理）、「可合并不可回退」之类的形状在旧体系里只能勉强归类。这正是 C++20 ranges
  重做迭代器概念格的原因（见下）。
- 代价峰值：`std::iterator` 基类惯例让「萃取」与「声明能力」耦合——后来发现继承
  基类只是**给 traits 喂 typedef** 的手段而非能力本身，于是基类被废弃（下表）。

## 最新演进与工业实践

- **ranges（C++20, P0896R4 "The One Ranges Proposal"，wg21.link 实测可达）**：
  类别标签升级为**概念格**（`std::input_iterator` → `std::ranges::range` 一族），
  能力用 requires 表达式声明式刻画，`std::advance` 的分派从「重载技巧」变成
  「概念约束的正规军」。`views::stride`/`views::reverse` 正是 9.4 自造迭代器的官方化。
- **`std::iterator` 之死**：C++17 废弃、C++20 移除；今天自定义迭代器**手写五个 typedef**
  或直接特化 `std::iterator_traits`（⚠️ 精确移除版本次按通行记载核对为 C++20，未查标准原文）。
- **bind 之死**：[../Effective_Modern_C++/06-lambda表达式.md](../Effective_Modern_C++/06-lambda表达式.md)
  第 30/31 条口径——lambda + `function_ref` 全面替代 `bind1st/std::bind`；`bind` 残存
  价值只有 `std::function` 构造与转发占位。
- **工业对照**：range-v3（github.com/ericniebler/range-v3，ranges 的试验田）里
  `stride_view`/`zip_view` 的头文件就是「跨跃/组合迭代器」的现代教材；fmt 的
  `fmt::appender`/`counted_output_iterator` 把输出迭代器做成了零类型擦除的
  `std::output_iterator` 实证（github.com/fmtlib/fmt）。
- **算法并行的接口回声**：C++17 并行执行策略（`std::execution::par`）给 sort 再加
  「第二输入」，与函数对象策略位一脉相承 ⚠️（提案号未核，接口已核：
  `sort(std::execution::par, v.begin(), v.end())`）。
