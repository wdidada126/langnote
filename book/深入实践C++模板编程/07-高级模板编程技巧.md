## 核心概念速览（中英对照）

- **标签** — tag：以空类型/枚举常量在编译期携带「该走哪条路」的信息（迭代器类别是最著名官方标签）
- **特性** — traits：类型信息的编译期查询接口；默认定义 + 按类型特化供货（`numeric_limits` 为范句）
- **编译期多态** — compile-time polymorphism：分派发生在实例化期，零 vptr 零虚表间接
- **虚基类模板启发** — 12.2 的解剖：vtable 机制=「按类型索引的函数指针表」，模板可在**类型层**直接复刻同构物
- **策略（政策设计）** — policy-based design：把行为决策点做成模板参数（ Alexandrescu 体系在 [../C++模板元编程.md](../C++模板元编程.md) 的邻近书目语境处理，本书此处为轻量版）
- **存储策略** — storage policy：vector 的「内存从哪来、怎么长」注入点——分配器参数化的教学变体
- **伪变长参数模板** — pseudo-variadic templates：`List<Head, Tail>` 嵌套类型链模拟任意长度参数表
- **编译期递归** — compile-time recursion：以模板实例化链代替 while/for，`At<I>` 逐层剥列表
- **元组访问** — tuple access via nesting：`get<I>` 沿 `head/tail` 递归下行，返回类型逐层精化

## 动机：1998 年的语言只给了「一个」多态

书中 12.2 的推理链（机制转述）很有教学史价值：虚函数=运行期按对象实际类型选实现；
但**模板参数本身就是类型**，选型可以整体搬到编译期。「全覆盖函数模板」指用重载+特化
把「所有情况」枚举完毕、不留运行期悬空；「虚基类模板」则是看穿 vtable 的实现——
每类一张表、按偏移取指针——然后用模板**手工造一张编译期的表**（成员函数指针数组 +
整数 NTTP 索引）。到编译器行为层面：这条路得到的分派在 -O2 下是直调或完全消除，
而虚分派永远隔一次间接（对象模型底座见
[../深度探索C++对象模型.md](../深度探索C++对象模型.md) 第 4 章）。

## 机制：四件技巧各自的实现骨架

**traits（12.1）**：`numeric_limits<T>` 主模板全体返回 0/false（「不是数值类型」的自述），
每个内置类型全特化供货 `min/max/lowest/has_infinity`。设计模式的三个要件：
① 统一查询接口；② 默认值让未知类型**可编译但自报不支持**；③ 特化即扩展点。
矩阵×向量乘法的实例用它按元素类型选精度路径。深读：
[../C++模板元编程/02-Traits与类型操纵.md](../C++模板元编程/02-Traits与类型操纵.md)。

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17：traits 的「默认自述」骨架
template <class T> struct my_limits {            // 主模板:什么都不知道
    static constexpr bool is_specialized = false;
    static constexpr T max() { return T(); }
};
template <> struct my_limits<char> {             // 特化:供货
    static constexpr bool is_specialized = true;
    static constexpr char max() { return 127; }
};
static_assert(my_limits<char>::is_specialized && my_limits<char>::max() == 127, "supplied");
static_assert(!my_limits<double*>::is_specialized && my_limits<double*>::max() == nullptr,
              "default self-report: unknown type still compiles");
```

（示意骨架，实际 `numeric_limits` 用继承统一实现；重点是「主模板兜底 → 使用点
永不硬错，只拿到 is_specialized=false 的自报」这条设计律。）

**策略（12.3）**：书中给 vector 加「存储策略」——把 allocate/deallocate/grow 三个决策
点做成模板参数，再让容器继承策略（继承即组合的模板版）。它正是第 7 章分配器的
抽象化复盘：**策略=可替换的编译期依赖注入**。

**伪变参（12.4）——本章的编译期图灵机**：

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17（e_old_vs_variadic.cpp 节选）
struct Nil {};
template <class H, class T> struct List { using head = H; using tail = T; };

template <class L> struct Length;                                  // 元函数:列表长度
template <> struct Length<Nil> { static const int value = 0; };
template <class H, class T> struct Length<List<H, T>> {
    static const int value = 1 + Length<T>::value;
};
template <int I, class L> struct At;                               // 元函数:第 I 个类型
template <int I, class H, class T> struct At<I, List<H, T>> {
    using type = typename At<I - 1, T>::type;
};
template <class H, class T> struct At<0, List<H, T>> { using type = H; };

using L = List<int, List<double, List<char, Nil>>>;   // hetero_node 的直系后代
static_assert(Length<L>::value == 3, "old-style length");
static_assert(std::is_same<At<1, L>::type, double>::value, "old-style at");  // 实测通过
```

机制三层：类型进模板实参（数据）→ 偏特化做模式匹配（分支）→ 实例化链做递归
（循环）。这就是「模板图灵完备」的最小演示，也是 08 章元编程的前奏。

## 权衡：技巧税单（逐条对 2026 年报销）

| 2013 年技巧 | 隐藏成本 | 现代替身 |
| --- | --- | --- |
| 标签分派选路 | 每个路标一套空重载 | `if constexpr`（P0292R2，实测可达） |
| traits 手工查询 | `typename X<T>::type` 啰嗦 | `<type_traits>` 全家 + `_v`/`_t` 后缀（C++14/17） |
| 虚表复刻成编译期表 | 手工维护、诊断差 | CRTP + `std::array<Fn, N>` 表；或直接 `std::variant` + `overload`/`visit` |
| 策略模板参数 | 接口多参、组合爆炸 | 库设计收敛到少数点：分配器→pmr，格式化→`std::format` 的 formatter 定制点 |
| 伪变参列表 | 每操作一个元函数、报错雪崩 | 变参模板（N2242，实测可达）+ 折叠（N4295，实测可达）+ `std::tuple` |

诚实注脚：策略设计在 Alexandrescu 原教（2001）里以「继承+空基优化」承载多决策点；
本书 12.3 的 vector 存储策略是同一思想的单点演示——组合爆炸的批评两边都躲不开。

## 最新演进与工业实践

- **CRTP 的现役样板**：fmt 的定制点 `template <class T> struct formatter` 要求用户
  **继承** `fmt::formatter<T, char>`（CRTP），`parse`/`format` 由基类供给默认实现——
  12.2「编译期表」思想在产品级库里的今天形态（github.com/fmtlib/fmt `fmt/base.h`）。
- **variant 取代手工分派表**：C++17 `std::variant + std::visit` 给「按类型选实现」
  提供带穷尽性检查的官方答案（漏分支=编译期可诊断），比虚函数复刻更省内存。
- **策略→概念约束的闭环**：C++20 里「合法策略」从文档约定变成 `std::invocable`
  之类可验证约束；范围 for 的 `range` 协议、ranges 的 `view` 协议是策略思想的
  概念化终态（[../C++20模板元编程.md](../C++20模板元编程.md) 视角）。
- **开源对照**：folly::Function 用「小对象缓冲 + 手工 vtable 结构体」做运行期可
  移动调用对象——正是 12.2 思路的性能工程版（github.com/facebook/folly）；
  模式语言重述见 [../C++20设计模式/](../C++20设计模式/)。
- **伪变参的最后凭据**：理解 `List<H,T>` 仍是读旧 MPL 代码的门票——
  Boost.MPL 全部容器都是这个形状（[../C++模板元编程/05-序列与迭代器.md](../C++模板元编程/05-序列与迭代器.md)）。
