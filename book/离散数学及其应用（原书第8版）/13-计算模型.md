## 核心精讲

```python
# 教学示意，不参与构建（不编译、不运行）
# 13.1 / 13.4：用「子集构造」把 NFA 转成 DFA，并用泵引理检验非正则性。

def nfa_to_dfa(nfa_trans, start, accept, alphabet):
    """子集构造：NFA 的 ε-free 子集构造。返回 (迁移字典, 接受状态集合)。"""
    def closure(states):
        stack, seen = list(states), set(states)
        while stack:
            s = stack.pop()
            for t in nfa_trans.get(s, {}).get("", []):
                if t not in seen:
                    seen.add(t)
                    stack.append(t)
        return frozenset(seen)

    def move(states, sym):
        return frozenset(t for s in states for t in nfa_trans.get(s, {}).get(sym, []))

    start_set = closure({start})
    dfa_trans, worklist, dfa_accept = {}, [start_set], set()
    if start_set in accept:
        dfa_accept.add(start_set)
    while worklist:
        S = worklist.pop()
        for sym in alphabet:
            T = move(S, sym)
            if not T:
                dfa_trans[(S, sym)] = frozenset()
                continue
            T = closure(T)
            dfa_trans[(S, sym)] = T
            if T not in dfa_trans.values() and T not in dfa_accept:
                worklist.append(T)
                if T in accept:
                    dfa_accept.add(T)
    return dfa_trans, dfa_accept
```

```python
# 教学示意，不参与构建（不编译、不运行）
# 13.4 泵引理：若 L 是正则语言，则存在泵长度 p，使 L 中长度 ≥ p 的任意字符串
# 都能被分成 xyz，满足 |xy| ≤ p、|y| ≥ 1、且 xy^0..xy^k 仍在 L 中。
# 用反证法：挑一个「构造上必然有重复状态」的字符串即可。

def pumping_lemma_check(L, n):
    """对给定语言 L 与泵长度 n，检查泵条件是否成立（教学示意，不参与构建）。"""
    for s in L:
        if len(s) < n:
            continue
        violation = None
        for i in range(len(s) + 1):
            for j in range(i + 1, len(s) + 1):
                x, y, z = s[:i], s[i:j], s[j:]
                if not all((x + y * k + z) in L for k in range(3)):
                    violation = (s, x, y, z)
                    break
            if violation:
                break
        if violation:
            return False, violation
    return True, None

# 经典应用：L = {0^n 1^n | n ≥ 0} 不是正则语言
# 若它是正则的，泵长度 p 下取 s = 0^p 1^p，泵环会破坏 0 与 1 的数量平衡
```

```python
# 教学示意，不参与构建（不编译、不运行）
# 13.5 图灵机：一条带、一个读写头、一组状态； accept / reject / loop 三态。

class TuringMachine:
    def __init__(self, transition, start, accept, reject, blank=" "):
        self.transition = transition      # (state, symbol) -> (state, symbol, move)
        self.start, self.accept, self.reject = start, accept, reject
        self.tape, self.head, self.state = [""] * 64, 0, start

    def run(self, max_steps=10 ** 4):
        for _ in range(max_steps):
            sym = self.tape[self.head] or self.blank
            key = (self.state, sym)
            if key not in self.transition:
                return "reject"
            nxt, write, move = self.transition[key]
            self.tape[self.head] = write
            self.state = nxt
            self.head += 1 if move == "R" else (-1 if move == "L" else 0)
            if nxt in self.accept:
                return "accept"
            if nxt in self.reject:
                return "reject"
        return "loop"                      # 超过步数上限 → 视为未停机

# 例：识别 0^n 1^n 的图灵机骨架（教学示意，不参与构建）
tm = TuringMachine({
    ("q0", "0"): ("q0", "0", "R"),
    ("q0", "1"): ("q1", "1", "L"),
    ("q1", "1"): ("q1", "1", "L"),
    ("q1", "0"): ("q2", "X", "R"),       # 遇到 0 说明计数失败
    ("q2", "1"): ("q2", "1", "R"),
    ("q2", ""):  ("accept", "", "N"),
}, "q0", "accept", "reject")
```

**Myhill–Nerode 的直觉（13.3）**：把字符串按「加上它后从某个状态出发会不会进入接受态」分类，得到有限多个「右语言」等价类；等价类个数就是最小 DFA 的状态数。这也解释了为什么「0^n 1^n」需要无限多个状态——它的右语言等价类无限多。

## 外扩：P vs NP 与 NP 完全（第 8 版未覆盖，非本书正文）

第 8 版第 13 章止于图灵机，中译本正文不含复杂度类。为补齐知识结构，这里给出必要的外扩：

- **复杂度类**：`P` 是多项式时间可判定的问题类；`NP` 是「多项式时间可验证（存在简短 certificate）」的问题类；显然 `P ⊆ NP`，而 `P = NP` 是否成立是**尚未解决**的问题。Clay Mathematics Institute 把它列为千年悬赏问题之一。
- **NP 完全**：若 `L ∈ NP` 且对所有 `L' ∈ NP` 有 `L' ≤_p L`，则 `L` 是 NP 完全的。Cook 1971 证明了 SAT 的 NP 完全性，Karp 1972 用 21 个归约把这张图谱铺开。
- **经典 NP 完全问题**：SAT（布尔可满足性）、顶点覆盖（vertex cover）、子集和（subset sum）、背包（knapsack）、TSP（旅行商问题）、图着色、哈密顿回路、3-SAT。
- **重要澄清**：NP 完全 ≠ 「算不出来」。这些问题都有有效的启发式与近似算法，工业界（SAT solver、CP-SAT、整数规划）每天都在求到近似最优解。

| 问题 | 归约自 | 典型应用 |
| --- | --- | --- |
| SAT / 3-SAT | 直接由 Cook 定理得到 | EDA 验证、配置、计划生成 |
| 顶点覆盖 | Karp 1972 | 网络监控、特征选择 |
| 子集和 / 背包 | Karp 1972 | 资源分配、投资组合 |
| TSP | Karp 1972 | 物流、芯片布线 |
| 图着色 | Karp 1972 | 频率分配、调度冲突 |

## 常见误区与本书需修正之处

| 误区 / 需修正 | 说明 |
| --- | --- |
| 🔧 **把「图灵机」当成一个具体的程序** | 图灵机是一个**族**（带 + 状态 + 转移表）；通用图灵机只是其中一个成员，正是它确立了「可计算 = 图灵可计算」 |
| 🔧 **混淆「可识别」与「可判定」** | TM **可识别**（ recognize）的语言是递归可枚举语言；只有**可判定**（decide）的才是递归语言。停机问题的语言可识别但不可判定 |
| 🔧 **P vs NP 被当成「已被证明」的伪科学传闻** | 网络上流传的若干「P = NP 证明」（包括 2019 年那次著名的 5 小时视频）都被指出有错误；Clay 千禧年奖金至今无人获得。以权威综述与官方问题说明为准 |
| **泵引理只用来「证明是正则」** | 泵引理是**必要**条件，只能用来「证明不是正则」；想证明一个语言是正则，必须构造 DFA 或用 Myhill–Nerode 论证 |
| 🔧 **NFA 与 DFA 的等价性被当成「NFA 更弱」** | NFA 与 DFA 识别同样的语言类（正则语言）；NFA 的价值在构造容易，DFA 的价值在实现容易 |
| **把 Church–Turing 论题当成定理** | 它是一个**论题**（convention/假设），不是可证明的定理——它的地位在于「至今没有反例」 |
| 🔧 **回归约时把方向搞反** | 归约是 `L' ≤_p L`（把 L' 归约到 L）；若方向反了，结论的语义就完全颠倒了 |
| **「NP 完全」当成「无法求解」** | 见外扩小节的澄清；NP 完全只意味着「除非 P = NP，否则不存在多项式算法」，启发式与近似在实践中很有效 |
| 🔧 **停机问题的表述被简化过头** | 「停机问题不可判定」指的是**给定 TM 与输入的一般性问题**不可判定；对特定具体程序，停下来完全可判定 |
