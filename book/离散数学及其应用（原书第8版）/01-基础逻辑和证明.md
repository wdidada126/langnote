# 第 1 章 基础：逻辑和证明

> **一句话**：命题逻辑给「可判真的表达式」一套代数，谓词逻辑给它变量与量词，而证明论给出从前提走到结论的合法推理序列——这三层是全书其余 12 章唯一的通用语言。

## 核心精讲

本章的「代码」不是算法，而是**把推理过程变成可检查的形式**。下面给出逻辑等价判定与命题推理骨架的教学示意，全部为**教学示意，不参与构建**，且不编译、不运行。

```python
# 教学示意，不参与构建（不编译、不运行）
# 目标：用朴素枚举验证第 1.3 节的逻辑等价式，而不是背书式记忆。
# 真值表：一个只有 2 个变量的命题公式就是一个 f: {0,1}^2 -> {0,1}。

from itertools import product

def truth_table(n):
    """返回 {0,1}^n 的所有赋值行（1 为真，0 为假）。"""
    return list(product([0, 1], repeat=n))

def p_implies_q(p, q):
    """p -> q，与 p <=> (not q or p) 一致。"""
    return (0 if (p and not q) else 1)

def logical_equivalent(f, g, n):
    """判断两个 n 元真值函数是否逻辑等价。"""
    for row in truth_table(n):
        if f(*row) != g(*row):
            return False, row
    return True, None

# 待验证的等价式（p, q 取 0/1）
eq1 = lambda p, q: p_implies_q(p, q)                    # p -> q
eq2 = lambda p, q: ((not p) or q) and 1 or 0            # ¬p ∨ q
print(logical_equivalent(eq1, eq2, 2))                  # 应等价

# 德·摩根律：¬(p ∧ q) ≡ ¬p ∨ ¬q
dm1 = lambda p, q: not (p and q)
dm2 = lambda p, q: (not p) or (not q)
print(logical_equivalent(dm1, dm2, 2))

# 第 1.6 节的消解律（resolution）：(p ∨ q) ∧ (¬p ∨ r) ⟹ (q ∨ r)
# 把「子句」表示为变量到布尔值的函数，消解只做一次布尔运算。
def clause_or(f, g):
    """两个子句的合取，返回其真值函数（教学示意，不参与构建）。"""
    def h(**assign):
        return f(**assign) and g(**assign)
    return h

def resolve(p, q, r):
    """对子句 (p ∨ q) 与 (¬p ∨ r) 做消解，得到子句 (q ∨ r)。"""
    a = lambda **kw: kw.get("p", 0) or kw.get("q", 0)   # p ∨ q
    b = lambda **kw: (0 if kw.get("p", 0) else 1) or kw.get("r", 0)  # ¬p ∨ r
    c = lambda **kw: kw.get("q", 0) or kw.get("r", 0)   # q ∨ r（消解结果）
    _ = clause_or(a, b)
    return c(p=1, q=0, r=0)                              # 仅演示调用形式
```

**消解律为什么重要**：它只有一条规则 `((p ∨ q) ∧ (¬p ∨ r)) ⟹ (q ∨ r)`，却足够证明任何命题逻辑的定理，因此是 SAT 求解器与 Prolog 一类自动推理系统的推理核心。第 8 版在 1.3 节把「可满足性」与「可满足性问题求解」单独列出，正是由此通向工程实践的接口。

**直接证明 / 反证法的模板**：

```python
# 教学示意，不参与构建（不编译、不运行）
# 这不是可执行代码，而是「证明骨架」的可执行化写法：
# 把需要穷举或分情形的对象显式列表化，避免「分情形漏分支」。

def prove_by_cases(cases, case_pred, conclusion):
    """cases: 候选对象列表；case_pred: 每个对象是否属于某个分支；
       conclusion: 分支上的结论谓词。要求每个 case 至少命中一个分支。"""
    seen = set()
    for c in cases:
        hit = False
        for i, pred in enumerate(case_pred):
            if pred(c):
                hit = True
                seen.add(i)
                if not conclusion[i](c):
                    return False, c, i      # 分支上结论不成立，证伪
        if not hit:
            return False, c, None           # 未被任何分支覆盖 → 漏情形
    # 未被覆盖的分支若 cases 穷举了全集，则分情形证明成立
    return True, None, None
```

- **直接证明**：假定前件为真，用定义与前已证定理逐步推出后件。
- **反证法**：假定结论 `q` 为假，与前提矛盾。注意要否定**结论的整体**，不是否定某一支。
- **归谬证明**：与反证法同源，只是把「矛盾」钉在一个具体的已知事实（如 √2 是无理数）上。

## 常见误区与本书需修正之处

| 误区 / 需修正 | 说明 |
| --- | --- |
| 🔧 **用等号表示蕴含** | 写下 `p = q` 表示「p 蕴含 q」是错的；`=` 是**对象之间的相等**，而 `→` / `⟺` 是**公式之间的等价/蕴涵**。正确写法是 `p → q`（蕴涵）与 `p ⟺ q`（等值） |
| 🔧 **归纳法边界缺失** | 第 1.8 节的证明策略常被跳过基础步；写「显然对 n=1 成立」而不验证，或把归纳假设表述成「对任意 n 都成立」，都是结构性错误（详见第 5 章） |
| 🔧 **`¬∀x P(x)` 与 `∀x ¬P(x)` 混用** | 前者等价于 `∃x ¬P(x)`，不是 `∀x ¬P(x)`；第 1.4/1.5 节的否定式是本章最高频错误点 |
| **混淆「重言式」与「定理」** | 重言式是**命题逻辑**里对所有赋值都为真的公式；定理是**对象层面**的命题。二者层次不同，第 1.3 节的小节标题容易让人混 |
| **把「可满足」当成「可判定」** | 可满足性（SAT）本身不是「求解」，是「是否存在赋值」；NP 完全性指的是**判定版本**的困难度。第 8 版新增的 1.3.6/1.3.7 小节也未给这一区分下结论 |
| 🔧 **分情形证明漏分支** | 用 `p → q` 的四种真值组合做分情形时，`p` 为假的两个分支必须一并处理；只消掉 `p` 为真而忽略其余，证明并不完整 |
| **量词顺序随手交换** | `∀x ∃y Likes(x,y)`（每个人都喜欢某人）与 `∃y ∀x Likes(x,y)`（存在一个人被所有人喜欢）不等价；1.5 节反复强调，但做题时仍最常出错 |
| 🔧 **中文标点与逻辑符号混排** | 命题公式中混用全角逗号、括号会破坏可读性；建议统一 `,` 与 `( )` 的半角写法，并在符号表中先行声明 |
