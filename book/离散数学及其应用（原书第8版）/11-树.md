# 第 11 章 树

> **一句话**：树是「无环连通图」的别称，也是工程中唯一能把 log 级复杂度变成现实的结构——从 BST 到 Huffman 编码，本章讲的都是「用分层换取局部性」。

## 核心精讲

```python
# 教学示意，不参与构建（不编译、不运行）
# 11.1 / 11.2：树的高度性质和 BST 的插入与查找。

class BSTNode:
    def __init__(self, key, left=None, right=None):
        self.key, self.left, self.right = key, left, right

def bst_insert(root, key):
    """二叉搜索树插入：递归地沿左/右子树下降；正确做法应保持 BST 性质。"""
    if root is None:
        return BSTNode(key)
    if key < root.key:
        root.left = bst_insert(root.left, key)
    else:
        root.right = bst_insert(root.right, key)
    return root

def bst_search(root, key):
    cur = root
    while cur:
        if key == cur.key:
            return cur
        cur = cur.left if key < cur.key else cur.right
    return None

def tree_height(node):
    """树高：空树 0，递归式 height = 1 + max(height(left), height(right))。"""
    if node is None:
        return 0
    return 1 + max(tree_height(node.left), tree_height(node.right))

# 11.1 的性质：深度为 h 的二叉树至多有 2^h 个节点（归纳法直接可得）
# 因此 n 个节点的 BST 在最坏情况下树高为 n（退化成链表），最好为 ⌈log n⌉
```

```python
# 教学示意，不参与构建（不编译、不运行）
# 11.3 树的四种遍历：递归写法与「栈/队列」的显式等价写法。

def preorder(node, out):
    if node:
        out.append(node.key)
        preorder(node.left, out)
        preorder(node.right, out)

def inorder(node, out):
    if node:
        inorder(node.left, out)
        out.append(node.key)
        inorder(node.right, out)

def postorder(node, out):
    if node:
        postorder(node.left, out)
        postorder(node.right, out)
        out.append(node.key)

def level_order(root):
    """层次遍历：用队列（即 11.3 的 BFS 视角）。"""
    from collections import deque
    result, q = [], deque([root])
    while q:
        node = q.popleft()
        if node:
            result.append(node.key)
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
    return result
```

```python
# 教学示意，不参与构建（不编译、不运行）
# 11.5：Kruskal + 并查集；并查集同时是 11.2 决策树与 9.5 等价类的工具。

class UnionFind:
    """并查集：带按秩合并与路径压缩；n 次操作摊还 O(α(n))。"""
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])   # 路径压缩
        return self.parent[x]

    def union(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False                                  # 已在同一个集合
        if self.rank[rx] < self.rank[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx
        if self.rank[rx] == self.rank[ry]:
            self.rank[rx] += 1                            # 按秩合并
        return True

def kruskal_mst(vertices, edges):
    """最小生成树：按权排序后加边，用并查集判环。O(E log E)。"""
    parent = UnionFind(vertices)
    mst, total = [], 0
    for u, v, w in sorted(edges, key=lambda e: e[2]):
        if parent.union(u, v):
            mst.append((u, v, w))
            total += w
    return mst, total
```

```cpp
// 教学示意，不参与构建（不编译、不运行）
// 11.2 决策树与前缀码的二叉树视角：C++ 侧给出一个带权路径长度的结构体。
// Huffman 算法：每次取两个最小权合并，代价即带权路径长度 Σ w_i · depth_i。

#include <vector>
#include <queue>
#include <functional>

struct HuffmanNode {
    long long weight;
    int left = -1, right = -1;
};

std::vector<HuffmanNode> build_huffman(const std::vector<long long>& freq) {
    // 小顶堆比较器：先比权，再按节点下标稳定排序，保证结果可复现
    auto cmp = [](const HuffmanNode& a, const HuffmanNode& b) {
        if (a.weight != b.weight) return a.weight > b.weight;
        return a.left < b.left;
    };
    std::priority_queue<HuffmanNode, std::vector<HuffmanNode>, decltype(cmp)> pq(cmp);
    for (long long f : freq) {
        HuffmanNode n; n.weight = f; pq.push(n);
    }
    while (pq.size() > 1) {
        HuffmanNode a = pq.top(); pq.pop();
        HuffmanNode b = pq.top(); pq.pop();
        HuffmanNode merged;
        merged.weight = a.weight + b.weight;
        merged.left = 0; merged.right = 1;   // 仅示意结构，不代表真实下标
        pq.push(merged);
    }
    return {};  // 教学示意：此处不生成真实森林
}
```

**11.1 的两条基本性质**（本书与后续都用）：

1. 有 `n` 个节点、连通无向的图恰有 `n − 1` 条边（反证：每加一条边产生一个环，每去一条边断开连通性）。
2. 深度为 `h` 的二叉树至多 `2^h` 个节点，因此满二叉树 `n` 个节点时 `h = ⌈log₂(n+1)⌉ − 1`。

## 外扩：AVL、B 树 / B+ 树与并查集（第 8 版未完整覆盖）

第 11 章正文把「树」当作图论的一个分支来讲，但工程上真正撑起系统的树结构是下面这些。它们在本书中只有零散提及，因此集中补在这里。

| 结构 | 平衡判据 | 查找复杂度 | 典型用途 |
| --- | --- | --- | --- |
| BST（11.2 已讲） | 无 | 最坏 `O(n)` | 教学与小规模场景 |
| AVL | 左右子树高差 ≤ 1 | `O(log n)` | 内存中的有序索引 |
| 红黑树 | 黑高平衡（最长 ≤ 2×最短） | `O(log n)` | C++ `map/set`、Java `TreeMap` |
| B 树 | 所有叶同层，节点度数有上下界 | `O(log_t n)` | 数据库（缓冲友好，磁盘 I/O 最少） |
| B+ 树 | 同 B 树，数据只在叶子且叶子成链 | `O(log_t n)` + 范围扫描 `O(t)` | InnoDB / PostgreSQL 的索引 |

并查集（`union-find`）在第 9.5 节已作为等价类的工具出现，这里补上它的**摊销分析**：按秩合并 + 路径压缩后，`n` 次操作的摊还代价是 `O(α(n))`，其中 `α` 是 Ackermann 函数的反函数（`α(n) < 5` 对任何实际规模的 `n`）。这也是 11.5 的 Kruskal 能跑到 `O(E log E)` 的原因。

## 常见误区与本书需修正之处

| 误区 / 需修正 | 说明 |
| --- | --- |
| 🔧 **生成树的边数记成 `n`** | `n` 个节点的连通无向图，任意生成树恰有 **`n − 1`** 条边；记成 `n` 会与「树的节点数−1」混淆 |
| 🔧 **BST 的查找复杂度当成 `O(log n)`** | 只有**平衡** BST 才是 `O(log n)`；普通 BST 退化时是 `O(n)`（词表按字母序插入就会退化） |
| 🔧 **并查集里的环检测用「visited 集合」** | 正确做法是并查集或染色标记；用 visited 集合会退化成 `O(V)` 每次，且无法支持跨边的合并 |
| **Kruskal 与 Prim 的适用差异被忽略** | Kruskal 用边排序，适合稀疏图且天然支持并行；Prim 用优先队列，适合稠密图；二者都依赖 MST 的循环性质 |
| 🔧 **Huffman 编码当成「最优」而不加前提** | 它给出的是**最优前缀码**（在给定符号频率下）；若允许定长或需要错误容忍，结论不同 |
| **前缀码与「编码表」混同** | 无歧义解码依赖「没有任何码字是另一个码字的前缀」这一特性，这正是二叉树叶子的性质 |
| 🔧 **树的高度定义不一致** | 「空树高度 = 0」与「空树高度 = −1」两种约定并存；做递归或计算复杂度时必须先固定约定 |
| **把 B 树 / B+ 树当成第 11 章的内容** | 本书 11 章只到生成树与最小生成树；B/B+ 树属于数据库索引（见「外扩」与该缺口说明） |
| 🔧 **把「树高 O(log n)」当成存储代价** | 树结构带来的是**比较次数**的 `O(log n)`，实际内存访问可能是树高的若干倍（缓存缺失），工程上常数可能更差 |
