## 核心精讲

本章要求动手实现三个东西：伪代码、**复杂度分析**、以及「别写错渐进记号」。下面给出 Karatsuba 乘法与渐进关系判定的教学示意，均为**教学示意，不参与构建**，不编译、不运行。

```python
# 教学示意，不参与构建（不编译、不运行）
# 3.3 分治乘法：Karatsuba 把两个 n 位数的乘法从 O(n^2) 降到 O(n^{log2 3}) ≈ O(n^1.585)。
# 递推式 T(n) = 3T(n/2) + O(n)，第 8 章 8.3 节会给出主定理解法。

def karatsuba(x, y):
    """分治乘法骨架（教学示意，不参与构建；未做负数与边界的完整处理）。"""
    if x < 10 or y < 10:
        return x * y

    m = max(len(str(x)), len(str(y)))
    n = m // 2
    high1, low1 = divmod(x, 10 ** n)
    high2, low2 = divmod(y, 10 ** n)

    z0 = karatsuba(low1, low2)
    z2 = karatsuba(high1, high2)
    # (high1 + low1)(high2 + low2) − z2 − z0 = 交叉项，只需再乘一次
    z1 = karatsuba(high1 + low1, high2 + low2) - z2 - z0

    return z2 * 10 ** (2 * n) + z1 * 10 ** n + z0

# 复杂度：T(1) = Θ(1)，T(n) = 3T(⌈n/2⌉) + Θ(n) = Θ(n^{log_2 3}) ≈ Θ(n^1.585)
# 而小学竖式乘法是 T(n) = T(n−1) + Θ(n) = Θ(n^2)
```

```python
# 教学示意，不参与构建（不编译、不运行）
# 3.2 渐进记号：与其死记公式，不如把「比较增长量级」写成可判定的流程。

import math

def omega_is_big_o(f, g, n0=1, c=None):
    """判定 f(n) = O(g(n))：是否存在常数 c > 0 与 n0，使 |f(n)| ≤ c|g(n)| 对所有 n ≥ n0 成立。

    f = O(g) 当且仅当 limsup_{n→∞} |f(n)/g(n)| < ∞。
    """
    if c is None:
        # 先取 c = 1，若失败再按比值放大（教学演示用）
        c = 1.0
    for n in range(max(n0, 1), 10 ** 6):
        if abs(f(n)) > c * abs(g(n)):
            # 比值已经发散，放大 c 也救不回来
            return False
    return True

def growth_rank(names, funcs):
    """按增长率从小到大排序（教学示意，不参与构建）。"""
    return sorted(names, key=lambda name: funcs[name])

_n = [1_000_000]

_of = lambda n: math.log(n)
_n2 = lambda n: n * math.log(n)
_n2_37 = lambda n: n ** 2.37
_n3 = lambda n: n ** 3
_two_n = lambda n: 2 ** n

print(growth_rank(
    ["log n", "n log n", "n^2.37", "n^3", "2^n"],
    {"log n": _of, "n log n": _n2, "n^2.37": _n2_37, "n^3": _n3, "2^n": _two_n},
))
```

**必须记住的三条性质**（3.2 的核心）：

1. `f(n) = O(g(n))` 表示 `f` 的**上界**，不表示「f 等于 g」；`f(n) = Θ(g(n))` 才是「同一量级」。
2. 常数因子与低阶项在渐进记号下消失：`1000n` 与 `n` 同阶，`n² + 100n` 与 `n²` 同阶。
3. `O(1)` 指的是**有界**，不是「运算数为 1」。

第 3.3 节的复杂度表（背下这张表比背算法重要）：

| 问题 | 典型复杂度 |
| --- | --- |
| 查找有序数组（二分） | `O(log n)` |
| 查找无序数组（线性） | `O(n)` |
| 排序（比较排序下界） | `Θ(n log n)` |
| 图的邻接矩阵 / 邻接表遍历 | `O(V²)` / `O(V + E)` |
| 最短路（Dijkstra + 堆） | `O((V + E) log V)` |
| 全源最短路（Floyd–Warshall） | `Θ(V³)` |
| n 位整数乘法（Karatsuba） | `Θ(n^1.585)` |

## 常见误区与本书需修正之处

| 误区 / 需修正 | 说明 |
| --- | --- |
| 🔧 **把「大 O」说成「等于」** | `f(n) = O(g(n))` 应读作「`f(n)` 是 `O(g(n))` 的」；写成「f 等于 g」会让人误以为 `n = O(n²)` 与 `n² = O(n)` 同时成立。正确写法：`f(n) ∈ O(g(n))`、`f(n) = Θ(g(n))` |
| 🔧 **忽略底数：Σ log k = O(log n)** | 「log」必须写清底数；`log₂ n` 与 `ln n` 只差常数因子（故同阶），但把「Σ log k = O(n)」写错则指 `n log n − log n! = O(log n)` 是错的，正确是 `Θ(n log n)` |
| 🔧 **复杂度只记最坏情况** | 3.3 节要求区分最坏/平均/最好；二叉搜索树的「平均 O(log n)」与「最坏 O(n)」差别很大，只记一个会误导 |
| **假设乘法是 O(1)** | 位运算的代价随整数位数增长；密码学场景里 `a·b mod N` 的代价是 `O(n²)` 甚至更多，不是常数时间 |
| 🔧 **把算法「一定终止」当成定理** | 算法定义中的有限性有前提；随机化算法、在线算法、以及含循环终止性未被证明的程序都不在满足该前提 |
| **渐进记号里的常数被当成不存在** | `1000n log n` 与 `n log n` 同阶，但在 n = 10⁵ 时前者可能更慢；工程上必须看常数 |
| 🔧 **误以为「O(n^1.585) 的 Karatsuba 已是最优」** | 大整数乘法的最优复杂度至今未定；已知有更好的多分歧分治方案（如 Toom–Cook、`n^{log 3}` 的进一步改进），不要把本书的 `O(n^{log₂3})` 当成终点 |
| **复杂度模型的边界被忽略** | 排序的 `Θ(n log n)` 下界只在**比较模型**下成立；计数排序、基数排序在非比较模型下可到 `O(n)` |
