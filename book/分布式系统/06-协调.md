# 第 6 章 Coordination（协调）

> **本章地图**：分散的节点如何对「时间」「顺序」「谁说了算」达成一致
> → **物理时钟**：时钟漂移、Cristian 算法、**NTP**、GPS 授时
> → **逻辑时钟**：**Lamport 时钟**与 happens-before、**向量时钟**
> → **互斥（mutual exclusion）**：集中式、令牌环、Ricart-Agrawala
> → **选举（election）**：Bully 算法、环选举
> → **Gossip 协调与聚合**（3rd ed 特色）：信息扩散、聚合计算
> → **组播与容错协调**（方框：可靠多播的排序语义）。

## 本章地图

## 核心精讲

（以下伪代码均为**教学示意，不参与构建**。）

### 6.1 物理时钟与时钟同步

- **时钟漂移（clock drift）**：
  - 每台晶振走速不同（典型 ~10⁻⁵ 量级）；
  - 任其发展，机器间秒级发散。
- **Cristian 算法**：
  - 向时间服务器询问，`T = T_server + (T1+T2)/2`；
  - 误差界 ±(RTT/2 + 最小单向延迟)。
- **NTP**（Mills）：
  - 分层 stratum 拓扑（顶层接 GPS/原子钟）；
  - 多轮采样 + Marzullo 算法过滤离群时延；
  - 互联网上做到毫秒~几十毫秒级；
  - 书强调 NTP 三目标：同步到 UTC、容忍丢包、可扩展。
- 🔧 关键提醒：
  - 物理时钟同步的**误差下限由网络延迟决定**，软件再聪明也压不到零；
  - 这是 TrueTime（见近年段）必须「等待不确定性区间」的根因。

### 6.2 逻辑时钟：顺序比时刻更重要

- **happens-before（→）**：
  - 同一进程内事件序 + 消息发送先于接收。
- **Lamport 时钟**：
  - 每事件本机计数 +1；
  - 消息携带时间戳，接收方取 max 后再 +1；
  - 性质：`a → b ⟹ C(a) < C(b)`；
  - **反推不成立**——Lamport 时钟无法区分并发与因果；
  - **全序化**：加节点 ID 打破平手 `(ts, id)`——工程中「用逻辑序给写定序」的通用技巧。
- **向量时钟**：
  - 每节点维护全员的计数向量，消息携带全量；
  - `a → b ⟺ V(a) < V(b)`（逐分量 ≤ 且至少一个 <）；
  - **能识别并发**。

```python
# 教学示意：Lamport 时钟（上）vs 向量时钟（下）
def local_event():  lc += 1;  return lc
def send(msg):      lc += 1;  msg.stamp = lc
def recv(m):        lc = max(lc, m.stamp) + 1
# 向量版：recv 时 V = elementwise_max(V, m.V); V[self] += 1
# 判断：V(a) < V(b) → a→b；不可比 → 并发 → 冲突检测（Dynamo/版本向量）
```

- 🔧 工程对应：
  - Lamport 时钟 → 给写事件定全序（现代 KV 的 sequencer）；
  - 向量时钟 → Dynamo/Riak 的版本向量（检测兄弟版本）。

### 6.3 互斥（mutual exclusion）

| 方案 | 消息数/次 | 容错性 | 要点 |
| --- | --- | --- | --- |
| **集中式协调者** | 3（请求/授权/释放） | 协调者单点 | 最简单；协调者崩溃需选举（引出 6.4） |
| **令牌环** | 1（令牌自带流转） | 丢令牌需重选 | 令牌即「持有权」的物化 |
| **Ricart-Agrawala** | 2(N−1) | 任一节点崩溃阻塞全组 | Lamport 时钟排序请求 + 「迟到的 REPLY 攒着发」优化 |

- Ricart-Agrawala 直觉：
  - 想进临界区就广播带时间戳的 REQUEST；
  - 收到所有人的 REPLY 才进；
  - 别人比你早申请就先让他；
  - **是「Lamport 全序 + 确认」的直接应用**——也是 Ch8 共识的雏形。

### 6.4 选举（election）

- **Bully 算法**：
  - 节点发现协调者失联 → 广播「我还在」；
  - 比 it ID 大的都回应 → 小 ID 退选；
  - 最终最大 ID 胜出；
  - 简单，但消息风暴 O(N²)。
- **环选举**：
  - 沿逻辑环传「参选消息」，回到起点时最大 ID 当选，再绕环通知。
- 🔧 工程视角：
  - 书里算法是**容错原语教学**；
  - 真实系统用**租约 + 随机退避 + 共识协议内置领导选举**
    （Raft 的 leader election、ZooKeeper 的 ZAB 快选）；
  - Bully/环在消息丢失与网络分区下表现脆弱——需配合故障检测器（接 Ch8）。

### 6.5 Gossip 协调（3rd ed 特色）

- **机制**：
  - 每轮随机挑 b 个同伴，交换/合并视图（push / pull / push-pull）；
  - 信息以流行病方式指数扩散，O(log N) 轮覆盖全网。
- **用途三件**：
  1. 信息传播：成员列表、配置；
  2. **聚合（aggregation）**：估计均值/负载/计数——交换后取平均即可收敛；
  3. 故障检测（Phi Accrual 类，见 Cassandra/Hazelcast 实践）。
- 🔧 Gossip 的本质是**用最终一致换无中心**：
  - 无单点、自愈（Ch2 自组织的算法化）；
  - 但视图是「概率意义上最新」——绝不能拿它做需要强序的事。

## 近年研究与工业界开源实践（2015–2026）

- 🔧 **混合逻辑时钟 HLC**（Kulkarni et al., 2014；CockroachDB 采用）：
  - `hlc = (物理最大值, 逻辑计数)`；
  - 物理部分保证「与 NTP 时间单调不离谱」；
  - 逻辑部分保证 happens-before 全序；
  - `cockroachdb/cockroach`（≈32.5k★，2026-09 实测）用 HLC 给事务定快照时间戳——
    「Lamport 思想 + 物理可读性」的当代合成。
- 🔧 **Google TrueTime（Spanner, OSDI 2012）**：
  - GPS + 原子钟硬件把不确定性压到毫秒级（典型 ±1~7ms）；
  - 事务提交**显式等待**不确定性区间（commit-wait）换取外部一致性；
  - 本书未收录；是「物理时钟误差必须被算法尊重」的终极工程形态。
- **NTP 的当代对手**：
  - PTP（IEEE 1588，数据中心亚毫秒）与 chrony 取代 ntpd 成为 Linux 默认；
  - Mills 的分层与过滤思想原封未动。
- **Gossip 工业化**：
  - Cassandra（成员与负载 gossip）；
  - `hashicorp/consul`（≈30.1k★，实测，LAN/WAN gossip 池）；
  - SWIM 协议（2018 年 Hashicorp 员工论文，`hashicorp/memberlist`，star 未核验）——把 6.5 的机制做成可复用库。
- **互斥的归宿**：
  - 分布式互斥几乎全部收编进**共识协议的领导权**；
  - `etcd-io/etcd`（≈52.3k★，实测）用 Raft 选主后本地互斥；
  - `apache/zookeeper`（≈12.8k★，实测）用 ZAB——
    6.3 表格里的「集中式协调者」以高可用形态复活。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「NTP 同步好了就能用本地时间戳定序」 | NTP 毫秒级误差 > 多数事务窗口；跨机排序要么逻辑时钟（HLC/Raft log 序），要么 TrueTime 硬件 + commit-wait |
| 2 | 「Lamport 时钟能判断因果」 | 只能单向（a→b 则时间戳小）；并发事件时间戳可能一样，需向量时钟才能识别并发 |
| 3 | 「Ricart-Agrawala 是生产可用的互斥」 | N−1 确认消息 + 任一节点失联即阻塞；工程上已让位于共识选主，学它为了理解 Lamport 序的用法 |
| 4 | 「Gossip 收敛了就是最新视图」 | 概率收敛，且无全局序；只能做成员/配置/指标，不能做需要线性一致的决定 |
| 5 | 🔧 本书需 2026 补丁 | 书未讲 HLC 与 TrueTime：物理时钟章节的 2026 标准答案是「HLC 做默认、硬件时钟做可选加强」 |
| 6 | 🔧 本书需 2026 补丁 | 书的选举算法不涉及**优先级成员集与 epoch/term**（Raft term、ZAB epoch）：现代选举必须把「任期号」写进协议，防止旧主复辟（脑裂双主） |
