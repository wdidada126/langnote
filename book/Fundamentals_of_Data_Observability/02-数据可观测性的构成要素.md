## 2.1 组件学总览

五支柱不是五个产品功能，而是五个**职责**：一个数据资产的运行时自证能力，可以且应该被拆为这五件事（⚠️ 转述归纳）。

| 支柱 | 职责一句话 | 主要输入 | 主要输出 |
|---|---|---|---|
| Freshness 时效 | 数据抵达性与时新度 | 时间戳、调度完成事件 | 滞后指标、SLA 判定 |
| Monitoring 监控 | 数据体自身的持续体检 | 行数、分布、模式、值域 | 异常信号流 |
| Lineage 血缘 | 链路登记与影响分析 | 作业元数据、SQL/管道解析 | 依赖图、影响面 |
| Documentation 文档 | 语义与责任的机器可读登记 | 元数据、人写描述 | 可发现性、可信上下文 |
| Alerting 告警 | 把信号翻译成对的人的可行动通知 | 前四支柱的信号 | 事件、工单、升级 |

## 2.2 Freshness：时效支柱

**定义问题**：给定承诺（SLA：每 2 小时更新 / 每日 06:00 前），当前时刻数据是否兑现？两路信号可交叉验证（⚠️ 转述）：

1. **调度面**：作业成功完成事件（便宜，但「成功的空转」骗人——1.7 案例即此）。
2. **数据面**：表内业务时间戳的最大值（`max(updated_at)`）或行数增速——数据自己说话，但要求表里有可信时间字段。

**滞后度量**：`lag = now − max_updated`，对 SLA 判定。🔧 **G1 原型（SQLite 3.45.3，本机真实跑过；非生产观测平台）**：

- 登记 6 张表（orders/users/events_hourly/dim_product/fx_rates/audit_log），SLA 从 2h 到 168h 不等；14 天 × 小时级快照，生成 2016 行 `snaps` 元数据；对其中 `events_hourly`、`audit_log` 注入「停更」（max_updated 冻结）。
- 判定 SQL 核心：`(julianday(snap_ts) − julianday(max_updated)) * 24 > sla_hours`。
- 结果：**185 行违约**（events_hourly 94 / audit_log 91），两表最大滞后均爬至 **95.0 小时**。真实系统里这不是 185 个告警，而是 2 个持续违约事件——去重问题交给 2.6/04 章。
- 复现：`python D:\develops\tmp\dbwave_w5_obs\proto.py`（G1 段）。

**边界情形**（⚠️ 归纳）：慢变维表（dim_product 型）不适合短 SLA，应转「心跳表/水位表」模式；多时区与迟到数据（流式场景）使 `max_updated` 本身需要水位语义——对位 [../Streaming_Systems/00-总览与阅读地图.md](../Streaming_Systems/00-总览与阅读地图.md) 的水位线章节。

两条工程提醒：
- 时间戳来源要登记进 `tables_reg`（业务时间 vs 落库时间 vs 快照时间三种 `max_updated` 语义混用是 freshness 误报第一来源，⚠️ 实践句）；
- G1 的小时级快照节奏即 MTTD 下限——判定周期与 SLA 量级同阶，不要给 24h SLA 的表配秒级轮询（成本侧自律，⚠️ 归纳）。

## 2.3 Monitoring：监控支柱（数据体的体检套餐）

四类常规体检项（⚠️ 转述；各厂商标题近似，如 Monte Carlo 五维度「freshness/volume/schema/distribution/lineage」是**厂商版**分类，与本书五支柱不同一层——montecarlo.ai 官网 ✅ 可达 200，具体口径以其站方为准）：

- **量（volume）**：行数/字节数的滚动基线偏离。🔧 G4 原型：90 天日行数、14 天基线、z-score 阈值 3，5 个人为注入异常全部命中（+3.6/−3.6/+3.4/+3.4/−3.7σ）。
- **分布（distribution）**：关键列的零值率、唯一率、分位数漂移——比逐值规则更会抓「没想到的坏法」。
- **模式（schema）**：列增删改类型。🔧 G2 原型：两期列元数据快照 `EXCEPT` 差集 + 同名列 join 比对，11 列 → 13 列窗口内检出 **3 起漂移**（`orders.coupon_code`、`users.phone` 新增；`orders.amount` REAL→DOUBLE）。
- **内容/枚举**：新类别值（新品类、新状态码）出现即信号——「unknown category」是经典未知未知探针。

## 2.4 Lineage：血缘支柱

观测语境下血缘是**运行时资产**而非一次性图纸（⚠️ 转述）：

- **登记粒度**：表级够用（影响面粗筛），列级才能支撑口径传染分析——成本陡增，按需分层。
- **采集方式**：作业元数据登记（便宜）⇄ SQL/运行时解析（准）。开放标准线（OpenLineage 等）使「运行时事件 → 血缘边」流水线化（⚠️ 详见 06 章）。
- **影响分析**：从变更点沿图正向可达 = 受影响消费方；从故障点反向可达 = 候选根因集。

🔧 **G3 原型（SQLite 3.45.3；非生产观测平台）**：9 条边的迷你链路（raw→stg→mart→app→ext + ml 支线），`WITH RECURSIVE down(t) AS (...)` 自 `stg.orders` 正向展开，得 **6 个下游节点**（mart.order_daily、mart.churn_features、app.revenue_dash、app.finance_export、ml.churn_model、ext.board_metrics），查询亚毫秒。这就是 1.7 案例「告警带影响面」的数据结构本体。技术纵深（中文）实链 [../数据血缘分析原理与实践.md](../数据血缘分析原理与实践.md)。

## 2.5 Documentation：文档支柱

文档支柱的观测视角三件套（⚠️ 归纳）：

1. **登记簿即真相**：表/列/指标的语义、负责人、SLA、消费方清单必须以机器可读形式存在（元数据表），否则其余四支柱无处挂上下文。
2. **文档也要新鲜**：描述最后更新日期本身是 freshness 信号——过期文档是负资产。
3. **与目录谱系分工**：企业数据目录（metadata 平台、检索发现、协作）是文档支柱的「仓库级实现」——实链 [../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md](../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md)；本书不重复平台选型，只立「运行信号回灌登记簿」的闭环要求（主动元数据口径，⚠️ 转述）。

## 2.6 Alerting：告警支柱

信号不变成「对的人 + 可行动上下文 + 不炸群」的通知即白采（⚠️ 归纳）：

- **路由**：按血缘找负责人与受影响方（G3 结构）分级通知；
- **降噪**：同源去重、冷却窗口、风暴聚合——🔧 G4 原型的规则表 `alert_rule(rule, tbl, op, thr, cooldown_h)` + 24h 冷却判定：5 个触发点彼此间隔 >24h，冷却后仍为 5 条告警（原型验证的是「不漏」；「不多」需依赖 2.3-2.4 的相关性聚合，真实系统主战场在此）；
- **升级**：SLA 分钟级 → 小时级未认领则升级——与 DBRE 的错误预算/值班制同构，实链 [../Database_Reliability_Engineering/00-总览与阅读地图.md](../Database_Reliability_Engineering/00-总览与阅读地图.md)。
- **对照软件面**：Grafana/Loki 栈的告警通道语义可直接类比（✅ 官方文档站可达：grafana.com/docs/loki/latest/、/docs/grafana/latest/fundamentals/，访问 2026-09-27）；差异在告警对象是「一张表的健康声明」。

## 2.7-bis 支柱间的最小信号契约（⚠️ 笔者设计件，供 04 章工程化索引）

五支柱不是并列清单而是流水线：每两根之间有明确的数据契约。

| 上游 → 下游 | 传递物 | 在 04 章的表结构落点 |
|---|---|---|
| Freshness → Alerting | 违约快照行 + SLA 引用 | `snaps` × `alert_rule` join |
| Monitoring → Alerting | 带基线上下文的异常点（z 值） | G4 规则表 `thr` 列 |
| Lineage → Alerting | 影响面节点集（路由收件人） | `lineage` 递归展开结果注入 payload |
| Documentation → 全体 | 负责人、承诺、语义口径 | `tables_reg`（登记簿即文档子集） |
| Alerting → Documentation | 事故史、认领记录回写 | `snaps` 追加即审计史（4.0 设计要点） |
| Monitoring → Lineage | 漂移事件标注到边上（何时变的） | `cols.snap` 与边表时间轴对齐 |

契约意识的作用：防「支柱孤岛」——五个产品各自为政时，跨栏信息（比如「这条告警的根因表也是漂移表」）必然丢失，退回到人工考古（对位 1.7 案例的 T+3h 段）。

## 2.7 五支柱的耦合关系

- Freshness 与 Monitoring 共享基线统计；Lineage 为 Alerting 提供路由与影响面；Documentation 是其余四者的上下文外存（⚠️ 归纳）。
- 反模式：先上 Alerting 后补登记簿——没有负责人与语义登记的告警必然转人工考古（1.7 案例复现）。
- 与「数据即产品」的接榫：五支柱齐了，数据产品才敢对客户承诺 SLO——实链 [../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md)。
- 支柱成熟度不均的工程含义：Freshness/Monitoring 有统计件可买可抄，Lineage/Documentation 只有登记纪律——预算应二八开在「信号采集」与「登记维护」两侧，多数失败项目把预算全押前者（⚠️ 判断句，与本目录 3.9 反序列警告互印）。
- 一句话记忆版：**时效问「到没到」，监控问「像不像」，血缘问「连着谁」，文档问「说是谁」，告警问「喊给谁」**（⚠️ 笔者口诀）。

## 核心概念速览（中英对照）

- **五支柱** — Five Pillars：本书框架：Freshness/Monitoring/Lineage/Documentation/Alerting（⚠️ 官方表述未一手核实）。
- **时效性** — Freshness：数据时新度对 SLA 的兑现程度；`lag = now − max_updated`。
- **停更/滞后** — Staleness / Lag：更新节奏违约的运行态故障及其度量。
- **心跳表** — Heartbeat Table：慢变场景下用独立小表自证「管道还活着」的模式。
- **模式漂移** — Schema Drift：列增删改类型的未声明变更，快照 diff 可检。
- **分布漂移** — Distribution Drift：值分布（零值率/分位数/唯一率）随时间的偏移。
- **数据血缘** — Data Lineage：数据从源到消费点的依赖边集合；观测语境下的路由与影响分析底座。
- **影响分析** — Impact Analysis：沿血缘正向可达集计算（🔧 G3：6 下游节点）。
- **根因追溯** — Root-Cause Tracing：沿血缘反向可达集筛候选根因。
- **元数据登记簿** — Metadata Registry：语义/负责人/SLA 的机器可读外存，文档支柱底座。
- **告警疲劳** — Alert Fatigue：无降噪的告警洪水导致认领率崩塌的组织病症。
- **冷却窗口** — Cooldown Window：同源信号在窗口内不再重复成告警的去重参数（🔧 G4：24h）。
- **MTTD / MTTR** — Mean Time To Detect / Resolve：检测与止损平均时长，观测体系的母度量。
- **主动元数据** — Active Metadata：运行信号驱动元数据层更新的工程口径（⚠️ 转述）。

## 最新演进与工业实践

- **检测层平权**：行数/分布基线异常检测曾是商业平台卖点，2024 后 dbt tests、开源统计库（⚠️ 具体项目版本未逐一取证，不列名）与平台内建监控使其商品化；竞争上移至误报控制与协作工作流。
- **血缘标准收敛**：OpenLineage 类开放事件标准把「采集作业 → 血缘边」做成流水线件（⚠️ 转述，官网未逐一可达性验证故不附 URL）；列级血缘仍是成本瓶颈，中文纵深见 [../数据血缘分析原理与实践.md](../数据血缘分析原理与实践.md)。
- **观测 ↔ 目录合流**：企业目录产品普遍长出运行监控，观测平台长出文档登记——两条产品线互为对方缺失的一半，与 [../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md](../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md) 的「主动元数据」演进节同一观察。
- **LLM 辅助排障**：把五支柱信号作为上下文供生成式助手归纳「坏在哪、影响谁、找谁」是 2024–2026 各家演示的共同方向（⚠️ 转述，厂商演示不作性能背书）。
- **软件侧镜像**：Grafana 云 / Loki 等对「metrics/logs/traces」三支柱的告警、SLO 功能持续演进（✅ 文档站 200 可达，2026-09-27），数据侧五支柱工程仍处「规则+基线」为主的时代——本目录 🔧 原型即该现状的最小快照。
