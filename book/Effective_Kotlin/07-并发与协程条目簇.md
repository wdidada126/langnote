## 本簇条目地图（⚠️ 推定 8 条）

| 编号 | 条旨（本仓自概括） | 一句话裁决 |
| --- | --- | --- |
| ⚠️55 | 协程是可挂起计算，不是线程 | ✅ suspend 编译成状态机（CPS），挂起时释放线程；1 线程可跑万协程 |
| ⚠️56 | 结构化并发：作用域即生命周期 | ✅ 在 `coroutineScope { launch ... }` 内启动，失败/取消沿父子树传播；裸 `GlobalScope.launch` 是孤儿源 |
| ⚠️57 | Dispatcher 是调度器选型，不解决数据竞争 | ✅ Main/Default/IO 只管"在哪个池跑"；串行化 ≠ 线程安全，共享态仍要 ⚠️60 |
| ⚠️58 | 取消要协作：长循环埋检查点 | ✅ `isActive`/`ensureActive()`；不挂起也不查取消的循环杀不掉（`NonCancellable` 例外要显式） |
| ⚠️59 | async 为"先起跑后收账"，不是装饰 | ✅ 并发扇出再 `awaitAll`；顺序 `async().await()` 等于白起一个协程还吞了异常语义 |
| ⚠️60 | 可变共享态三档：禁 > Mutex > 原子 | ✅ 首选消息/挂起安全容器（Channel、`MutableStateFlow.update`）；✅ Mutex 可挂起等待，`synchronized` 块内不可挂起 |
| ⚠️61 | runBlocking 只许出现在 main 与测试胶水 | ✅ 它是"阻塞当前线程直到完成"的桥，生产协程里用=自毁挂起模型 |
| ⚠️62 | 异常走 Job 树，别让 supervisor 变万能胶 | ✅ `SupervisorJob` 让子失败不株连兄弟，但代价是每条支路要自设兜底；catch 协程异常优先 `childCancelled` 语义想清楚 |

## 条目特写

### ⚠️56/59｜作用域与扇出

🔧 坏味道：
```kotlin
GlobalScope.launch { loadData() }        // 孤儿：宿主销毁它照跑
val a = async { f() }; val b = async { g() }; a.await(); b.await() // 串行 await 无并发收益？✅ 有起跑但异常半路悬空
```
🔧 修正：
```kotlin
coroutineScope {
    val (x, y) = async { f() } to async { g() }
    handle(x.await(), y.await())          // 两个都已并发起跑，这里才收账
}
```

### ⚠️55｜与 Java/C++ 并发条目的判词差

✅ Kotlin 协程是"用户态可挂起函数 + 编译器状态机"，对照：Java 线程/虚拟线程是
调度器层方案（Loom ⚠️ 书成后发展，不在本簇口径），C++ 无语言级协程标准语义
（`std::execution`/协程 TS 是库与提案位）——判词见
[../Effective_Modern_C++/07-并发API.md](../Effective_Modern_C++/07-并发API.md)（EMC++ 的
"别用线程做默认并发单位"与协程教义同源）。Effective Java 第 81 条附近"executor
框架优先于裸线程"（⚠️ 编号凭记忆，本仓无 EJ 档互链）是同一工程直觉的 2006 版。

## 🔧 微实验（全部未实测，本机无 kotlinc）

1. 裸 `GlobalScope.launch` + `cancel()` 父作用域，观察子协程存活（孤儿复现）。
2. CPU 忙循环不查 `isActive` 的 `cancel` 失败案例，再补 `ensureActive()` 修复对照。
3. `synchronized` 块内调 suspend 函数 → 预期编译错（阻塞 API 里挂起），文案归档。
