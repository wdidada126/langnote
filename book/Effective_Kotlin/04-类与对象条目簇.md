## 条目特写

### ⚠️34｜value class（本簇重点档）

🔧 坏味道：`fun charge(user: String, amount: Double)`——userId/钱数/欧元美分全是裸类型。
🔧 修正：
```kotlin
@JvmInline value class UserId(val raw: String)
@JvmInline value class EuroCents(val cents: Long)
fun charge(user: UserId, amount: EuroCents) { /* amount.cents */ }
```
理由：✅ value class 编译后底层类型直接现形（参数在字节码里仍常是原始类型+名字改签），
零包装对象；代价是可见性受限（仅一个 `val` 主构造属性）、可空时会装箱。
**跨语言裁决**：C++ 没有语言级对应概念位——最接近的是手写 newtype 包装 struct
（样板+构造函数全透传）或类型别名（零保护），两边都不免费；✅ Kotlin 把"包装的
运行时成本"这一最大阻力直接消掉，等于宣布 newtype 无借口。Java 侧同一愿景是
JEP 值类（Valhalla，⚠️截至本档写作时未 GA），书成时点上也只能望 Kotlin 兴叹。

### ⚠️31/32｜data class 的边界

```kotlin
data class Row(val id: Long, val tags: Array<String>) // ❌ tags 按引用比
```
✅ 修正：不用 Array（用 `List`+拷贝），或手写 equals 覆盖；✅ "带行为的协作者"
（Service/Repository）不配 data——equals 按字段全等对身份对象是错误语义。
对照：Effective Java Item 10/11"equals/hashCode 成对、别自造脆弱等式"（⚠️ 编号凭
记忆推定；本仓暂无 EJ 分章档可互链）；data class 是"编译器代写 EJ 仪式"，但代写
不等于代判——**要不要等式、哪些字段进等式**仍是人的决定。

- **Effective TypeScript 2e**：TS 结构化类型下 `type UserId = string` 零保护、brand
  类型才能近似 value class 的语义区分（⚠️ 判例口径见
  [../Effective_TypeScript_2e/01-类型基础条目簇.md](../Effective_TypeScript_2e/01-类型基础条目簇.md)
  与 [../TypeScript系列·总索引.md](../TypeScript系列·总索引.md)）；Kotlin 名义类型+
  value class 是"结构化的便利、名义的纪律"折中。sealed ↔ 判别式联合：
  [../Effective_TypeScript_2e/03-对象与结构关系条目簇.md](../Effective_TypeScript_2e/03-对象与结构关系条目簇.md)。

## 中英对照

| 中文 | 英文 | 一句定义 |
| --- | --- | --- |
| 数据类 | data class | 构造参数自动进 equals/hashCode/toString/copy/componentN。 |
| 值类 | value class (`@JvmInline`) | 单属性零成本包装，运行期以底层类型现形。 |
| 密封类 | sealed class/interface | 子类集合编译期可知，解锁 when 穷尽检查。 |
| 类委托 | class delegation `by` | 接口实现转发给被委托对象，编译器生成样板。 |
| 属性委托 | property delegation | get/set 逻辑外包给 `getValue/setValue` 提供者。 |
| 伴生对象 | companion object | 类作用域单例，静态成员的 Kotlin 形态。 |
