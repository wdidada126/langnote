## 条目特写

### ⚠️68｜ABI 兴趣线在工具簇的落点

✅ 分工：binary-compatibility-validator 管**签名**（public API 列表 diff），
.api 文件即契约快照；但它照不到 inline 函数体（改动不进签名）与序列化格式。
裁决：库的 public 面越小，工具越省力——把"能进 ABI 的东西"先在设计层砍小
（`internal` + ⚠️44 的 `@PublishedApi` 纪律）。对照：TS 侧工具链判例（tsconfig
strict 全家桶/linter 裁决风格）见
[../Effective_TypeScript_2e/06-工程配置与2e新增条目簇.md](../Effective_TypeScript_2e/06-工程配置与2e新增条目簇.md)，
系列索引 [../TypeScript系列·总索引.md](../TypeScript系列·总索引.md)。

### ⚠️69｜"少 mock"的 Kotlin 理由

🔧 坏味道：为 `UserDto` 写三个 stub getter 喂 Mockito。
🔧 修正：
```kotlin
val user = User(id = 1, name = "a", tags = listOf("x")) // 真对象，构造免费
assertEquals(expectedUser, user)                        // ✅ data class 等式直接可用
```
对照 Effective Java equals 条目族（⚠️ 编号凭记忆，本仓无 EJ 档互链）：EJ 教你
"把 equals 写对很难"，Kotlin 的判词是"让编译器替你写对，然后人只裁决语义"；
泛型/mock 框架选择（mockk vs Mockito-Kotlin）⚠️ 凭记忆且不在本簇硬断言。

## 中英对照

| 中文 | 英文 | 一句定义 |
| --- | --- | --- |
| 警告即错误 | warnings-as-errors (`-Werror`) | CI 把编译器警告升级为构建失败。 |
