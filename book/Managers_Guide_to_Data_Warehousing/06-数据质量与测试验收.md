## 6.1 质量在管理语言里的位置：不是 bug 率，是信任率

数仓的独特性在于**错误的延迟显形**：装载时的一次静默错值，三个月后在董事会材料里引爆（⚠️）。
因此管理者视角的质量定义是：**「用户敢在多大范围内不复核就引用」**——信任率。工程指标（空值率/
重复率/对账差）是信任率的代理变量，代理变量必须能追溯到被信任的具体报表与决策（03 章驱动表反向
索引）。

✅ "collaborative" 推论：信任率只能由业务侧测量（引用行为、复核率），由 IT 侧改善（管道与规则）
——两列都要进质量月报，缺前者是本章反对的第一反模式。

## 6.2 质量维度表与「一次体检」（🔧 E5 锚）

经典六维（完整性/准确性/一致性/及时性/唯一性/有效性，⚠️ 通识口径）落地为可执行 SQL 集。
🔧 E5 实抓（SQLite，1M 行订单式样本，0.33s 一次全表体检）：

| 检查项 | 实抓读数 | 管理读数 |
| --- | --- | --- |
| email 空值 | 58,824（5.88%） | 空≠错：先问业务「这个字段用于分析吗」，再定严重级 |
| email 格式坏 | 40,921（4.09%） | 与空值并列即 9.9% 不可联email 触达——营销域据此降级数据源 |
| region 空值 | 9,901（0.99%） | 1% 空值在按 region 分组时会从「其他」桶冒出——口径会议必争论点 |
| 主键重复 | 0 | 唯一性绿的代价：补建索引 0.56s（体检本身也要成本入账） |

**三条纪律**（⚠️）：①体检进装载流水线而非事后运动；②每维度阈值由数据 Owner 签字（02 章矩阵
质量行的验收物）；③**修复预算与告警同权重**——只报警不修数=制度化地把脏数据搬运到用户大脑里。

## 6.3 质量责任的拓扑：谁的签字覆盖哪段链路

```
源系统录入 ──(源属主团队)──▶ 抽取 ──(ETL 团队)──▶ 仓库 ──(模型属主)──▶ 报表 ──(报表 Owner=业务)
      │                        │                      │                    │
   规则前置拦截             对账+行数/金额双校验     一致性维度校验        UAT 抽样+引用审计
```

- 越靠左修复越便宜（⚠️ 通识：成本随链路右移数量级增长）——但**管辖权越靠左越难**（源系统属主
  不在数仓项目编制内）。2009 管理解法：借治理委员会的跨部门仲裁权（02 章 2.3）把「靠左」变成
  政治可行；2026 解法见 §6.6 演进。
- **对账双校验**（行数+业务金额合计）是财务血统规则的最低配置——单数行数会放过「行数对、金额错」
  的静默事故（⚠️）。

## 6.4 测试验收的三层结构与「带病上线」豁免

⚠️ 重构（阶段坐标系=L4，门禁规则回链 4.3）：

1. **工程层**：单元/管道回归/性能窗口（🔧E2 方法复核：夜间窗口约束是否仍成立）；
2. **口径层**：抽样对数——每张首发报表抽 3 个切片与业务手工数对表，差值入容差表；
3. **采纳层**：种子用户 2 周并行期（新旧双跑），引用行为记录（6.1 信任率的原始数据）。

**容差表**（质量豁免的法律文本，⚠️）：每个指标「可接受误差带+有效期+到期复测人」三元组；
带病上线=业务 Owner 在容差表签字而非口头默许——✅ "decision points for success" 在此的硬形态是：
**豁免必须是有期限的资产，不是无痕的让步**。

## 6.5 反模式巡诊（⚠️ 管理症状学）

- **质量仪表盘自嗨**：绿条满屏但没有一个指标能映射到某张被引用的报表（6.1 代理失效）。
- **脏数据考古队**：每次事故都人工回溯血缘（02 章 2.4-2）而不沉淀规则——团队编制被历史债吃掉。
- **完美主义锁死**：「数据 100% 干净才上线」——在分析需求侧这等于宣布项目无终止态；处方=容差表
  把「够好」显式化（6.4）。✅ collaborative 推论：「够好」的定义权在业务，这正是它必须双人签字的原因。
- **测试数据真空**：用生产脱敏前样例测试，上线即面对真实脏度（🔧E5 式体检应跑在**全量镜像**上，
  样本会给假绿——本机 1M 行实验换 100M 行时问题率漂移是常态）。

## 6.7 容差表字段定义与一条填好的样例（⚠️ 重构）

字段：指标名 / 口径版本（字典 v#）/ 误差带（绝对或相对）/ 测量方法（🔧E5 式 SQL 编号）/
复测频率 / 有效期 / 到期动作（复测→重签或降级下架）/ 业务属主签字 / IT 属主签字。

```
指标: 月活跃客户数
口径版本: 字典 v3（剔除内部测试账号条款已并入）
误差带: 与CRM对账相对差 ≤0.5%
测量: QC-17（对账双校验：行数+去重客户数，SQL 存规则库）
复测: 每月1日 07:00 自动 / 有效期: 6 个月
到期: 自动生成重签工单，逾期该指标看板角标变灰（引用可见性惩罚）
签字: 市场总监＿＿（业务Owner） / 数据平台经理＿＿（IT）
```

**设计要点**（⚠️）：到期动作把「有期限的豁免」自动化——豁免的终点不是续签而是**重新测量**；
角标变灰是 6.1 信任率的制度杠杆：让用户看得见「这个数字的担保何时到期」。对应 5.4 幽灵预算二：
每条容差带背后都站着一条修复工单与它的报价。

## 核心概念速览（中英对照）

- **信任率** — Trust Rate：用户不复核即引用的范围占比，质量的管理学定义（6.1）。
- **代理变量纪律** — Proxy Discipline：工程指标须可追溯到被引用的报表/决策（6.1）。
- **一次体检** — One-shot Health Scan：六维 SQL 全表测量（🔧E5：5.9%/4.1%/1%/0）。
- **修复预算** — Remediation Budget：告警与修数编制同权重（6.2-③）。
- **责任拓扑** — Accountability Topology：链路四段各自的属主与校验物（6.3 图）。
- **对账双校验** — Dual Reconciliation：行数+金额合计同验，防静默事故（6.3）。
- **三层验收** — Three-tier Acceptance：工程/口径/采纳层各一套证据（6.4）。
- **容差表** — Tolerance Register：误差带+有效期+复测人三元组=豁免法律文本（6.4）。
- **有期限的豁免** — Time-boxed Waiver：带病上线的合法形态，✅ 决策点论硬投影。
- **仪表盘自嗨** — Dashboard Vanity：绿条与引用行为脱钩的反模式（6.5）。
