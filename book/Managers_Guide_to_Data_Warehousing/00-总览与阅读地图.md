## 6. 🔧 类比实验总表（本机 SQLite/DuckDB，**非本书引擎/平台行为**——本书无引擎，实验服务于管理指标）

管理视角册的实验口径：**成本、容量、吞吐、质量度量**四类管理弹药。脚本
`D:\develops\tmp\dbwave_w9_mgdw\exp.py`（DuckDB 1.5.5 / SQLite 3.45.3，零新装），数字为 2026-10-02 实抓。

| # | 实验（管理问题） | 实抓结果 | 类比对象 → 落点章 |
| --- | --- | --- | --- |
| E1 | 3 年现金流的回本期与净现值敏感性（SQLite 窗口函数滚动累计） | Y1 净流出 1050；**回本期=第 4 年**（未折现累计 -700；折现 10% 亦第 4 年，NPV -348.95）；5 年累计未折现 -1600/折现后 -963.66 | 商业论证的「回本期+折现」双口径 → 01/07 章 |
| E2 | ETL 装载吞吐→夜间窗口容量规划（DuckDB read_csv 2M 行） | 42MB CSV 0.18s 入库 ≈ **1110 万行/秒、0.235GB/s**；线性外推 1TB≈1.2h、5TB≈5.9h（单线程本地） | 装载窗口=容量-人手换算器 → 05 章 |
| E3 | 同一数据的四种存放形态字节/行（CSV/SQLite 行存/DuckDB/Parquet） | 21.1 / 15.8 / **3.2** / 4.2 字节每行（列存省 5–6.6×） | 存储 TCO 量级差 → 05 章 |
| E4 | 增量交付 vs 大爆炸重建（DuckDB 12M 行分季聚合） | 逐季增量 0.17s vs 每次全量重建 0.25s（1.5×；本地小样本，**收益随数据量与重建频次放大**的定性结论保留） | 迭代交付的经济学论据 → 04 章 |
| E5 | 数据质量门的一次全表体检成本（SQLite 1M 行） | 0.33s 测得 email 空值 58,824（5.9%）、格式坏 40,921（4.1%）、region 空值 0.99%、主键重复 0；补建索引 0.56s | 质量度量=一条 SQL 的事，贵在「没人负责测」 → 06 章 |
