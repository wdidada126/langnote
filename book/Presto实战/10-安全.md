## 精讲

### 1. 安全边界的"三段式"心智
```text
[客户端/BI] --10.1/10.5--> [协调器] --10.3.3 集群内TLS--> [worker 群]
                              |
                              +--10.7/10.8--> [数据源: Hive metastore/HDFS/RDBMS/...]
```
- 每段独立认证手段（LDAP ↔ mTLS ↔ Kerberos），**弱段即全链短板**；
- Presto 自身不做数据加密存储（它无数据），其安全责任=**访问路径治理**——与数据库的静态加密语境不同（对照
  [../数据安全架构设计与实战.md](../数据安全架构设计与实战.md)）。

### 2. 授权的真实粒度（10.2）
- 系统访问控制：`access-control.properties` 指定实现（file-based 规则：按用户/组 × catalog × schema × 操作放行）；
- 连接器访问控制：把权限判定下沉到源（如 Ranger 集成 ⚠️ 书中以开源 file/规则实现示范，Ranger 属 Starburst/生态件）；
- **没有列级/行级安全的通用机制**——书中明确此局限；当代解法要么靠源系统（Hive+Ranger/Iceberg+权限层），
  要么靠产品化（Starburst 的 Open Access Control/数据屏蔽）。

### 3. Kerberos 双通路（10.6 + 10.8）
- 客户端→协调器：HTTP SPNEGO（`presto.` principal + keytab，服务票据换取）；
- 协调器/worker→Hive/HDFS：代理用户 impersonation（doAs），需要 Hadoop 侧 `hadoop.proxy.user.*` 配置；
- 排障口诀：**先 kinit 验票据，再看 keytab 时钟偏移（5 分钟窗口），最后查 impersonation 白名单**。
国内 Hadoop 集群接入的第一杀手即此处（与 06 章 Hive 连接器联动）。

### 4. 集群分离的场景账（10.9）
两把尺子：
- **用户群体隔离**：探索型流量 vs 报表 SLA 型流量分集群（资源组 12.8 是集群内的软隔离，集群分离是硬隔离）；
- **数据敏感度隔离**：授权粒度不足时，物理拆集群=最粗但最硬的 ACL。
这与 B 站/美团的"多集群+路由"架构互为因果（路由层=集群分离的用户侧门面）。

## 常见误区

| 误区 | 现实 |
| --- | --- |
| "LDAP 认证过了就有权限" | 认证≠授权；默认无 access-control 配置时，通过认证者可查一切放行 catalog |
| "加密全开不影响性能" | 集群内 TLS 加解密吃掉 CPU，交互式吞吐需实测校准 ⚠️（转述社区经验，非本书数据） |
| "Presto 能替代源库权限体系" | 连接器凭据是服务账号——它能看到什么，决定你能越权看到什么 |
| "自签名证书内网随便用" | 证书轮转失控=生产停机事故温床；10.4 的手艺只配救急 |

## 本章小结与行动清单

三句话带走：
1. 安全是**链式属性**：三段链（客户端-协调器 / 集群内 / 协调器-数据源）取最弱段定级，加固要从最弱段做审计；
2. 引擎侧授权是钩子不是体系——把"细粒度"期望要么交给源系统/Ranger 类外置件，要么交给商业发行版，
   要么交给湖 catalog 层（2024–2026 的正确答案越来越倾向最后一项）；
3. Kerberos 类故障 90% 是运维三件套问题：票据有效期、时钟偏移、代理白名单——先把这三样做成巡检项再谈加密体系。

安全基线评审单（上线前逐条签字）：
- [ ] 默认无认证配置（HTTP 裸奔）在公网/内网边界是否已用网络策略封堵（TLS 未就绪时的过渡底线）；
- [ ] 所有连接器凭据集中托管（Vault/KMS 类），catalog 文件不落明文密码——06/07 章遗留示例逐个改造；
- [ ] `SHOW GRANTS`/访问控制规则与实际用户群对表，最小权限从 admin 自己开始；
- [ ] 事件监听器落审计流（谁/何时/何查询/结果行数）并有保留期策略（12 章监控与合规共用此件）；
- [ ] 证书/keytab 轮转演练过至少一次，含轮换后回归。
- [ ] TLS 未就绪阶段的网络封堵有书面豁免与到期日（"临时裸奔"必须是有期限的决策）。

自测：
- [ ] "LDAP 通过即可查一切"在什么配置下成立？如何证伪？（认证≠授权，10.2 缺省钩子）
- [ ] 集群分离与资源组的分工？什么时候软隔离必须升级成硬隔离？（10.9×12.8 合题）

一句话总结：安全章没有新架构，只有**清单纪律**——三段链、两本账（凭据托管、权限对表）、一次轮转演练，
做到即及格，缺一即裸奔。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 认证 | Authentication | 确认调用者身份（LDAP/Kerberos/证书） |
| 授权 | Authorization | 判定已认证主体可执行的操作 |
| 系统访问控制 | System Access Control | 引擎级权限钩子（file 规则起步） |
| 连接器访问控制 | Connector Access Control | 权限判定下沉到数据源侧 |
| SPNEGO | SPNEGO | HTTP 上的 Kerberos 协商认证 |
| keytab | Keytab | 服务长期凭据文件（免交互取票） |
| 代理用户 | Impersonation (doAs) | 引擎以第一方身份代终端用户访问 Hadoop |
| mTLS | Mutual TLS | 双向证书认证的集群内通信 |
| keystore/truststore | Java Key Store | JVM 证书与信任链容器 |
| TLS 终结 | TLS Termination | 负载均衡上卸载加密的部署法 |
| JWT 认证 | JWT Authentication | 书中未含；其后版本引入的令牌认证 ⚠️ |
| 事件监听器 | Event Listener | 查询审计事件的 SPI 钩子 |
| 集群分离 | Cluster Segregation | 按人群/敏感度硬拆物理集群 |
