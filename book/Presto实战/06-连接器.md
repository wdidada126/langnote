## 精讲

### 1. 连接器 SPI 的最小完备面（6.1 + 4.5 回顾）
一个连接器要回答四类问题：
- **元数据**：有哪些 catalog/schema/表/列？（接 Hive Metastore/JDBC 自省/自实现）
- **切分**：表怎么切成 Split 派给 worker？（文件/HBase region/ES shard/TPCH 桶）
- **读取**：给定 Split 产出 Page（列式解码、类型映射）；
- **写回与 DML**：建表/CTAS/INSERT/DELETE 各支持到哪一步——**支持面差异是跨源迁移最大的坑**（8.6.6 专节）。

### 2. RDBMS 样板：把压力还给源库（6.2）
- **查询下推**：Presto 把可翻译的谓词/投影/聚合编译成源库 SQL 发出——
  下推边界之外的部分回到 Presto 再算，因此 `WHERE` 写在不索引列上照样全表拉；
- **并行与并发**：单连接按 `connection-url` 池化、分区列切 Split 并行读（JDBC 连接器参数 ⚠️ 版本核对）；
  对源库它是"又一个重客户端"，生产必须评估源库连接/IO 配额与只读副本（6.2.4 安全性同此意）；
- **类型映射表**是第一个 bug 高发区（源库 DECIMAL/时区处理与 Presto 语义差 ⚠️ 逐版本核对）。

### 3. Hive 连接器细读（6.4，全书数据面重心）
- 概念分层：HDFS/S3（字节）→ 文件格式 ORC/Parquet/RC/文本（编码）→ **Hive 表格式**（分区目录约定 + metastore 模式）；
- **分区**：`day=YYYY-MM-DD` 目录即列，谓词含分区列才有剪裁——书中反复强调"忘写分区谓词=扫全库"；
- **内部表 vs 外部表**：Presto DROP 谁不动数据、ALTER 谁能生效，取决于 metastore 所有权语义（8.6.5/8.6.6 联动）；
- **文件格式与压缩**：ORC/Parquet 列式+谓词索引是交互式性能底线；文本+snappy gzip 是负优化；
- **MinIO 示例**：S3 兼容对象存储挂 Hive 的最小云原生闭环——2021 年的前瞻，2026 年已被
  **Iceberg 表格式**取代为默认主战场（文末）。

### 4. 三个"非数据"连接器的正确用法（6.6–6.8）
- `jmx`：`SELECT * FROM jmx.current."presto.metadata:name=*" ...`——排障时先查引擎自己；
  与 Web UI（12.1）互为宏/微观两视图；
- `blackhole`：`INSERT INTO blackhole...` 压上游链路，剥离真实写侧变量；
- `memory`：语义试验+小维表缓存；**上限受节点内存约束，重启即失，不是缓存方案**。

## 常见误区

| 误区 | 现实 |
| --- | --- |
| "Presto 查 MySQL 不影响 MySQL" | 下推失败部分会把源库当扫描器用；高峰联查拖垮业务库是常见事故（用只读副本+限并发） |
| "分区表自动快" | 只有分区列进入谓词才剪裁；函数包裹分区列（`substr(day,..)=`）当场失效 |
| "Hive 连接器=支持 Hive 事务/ACID 表" | 对 ACID Hive/湖格式的事务支持按版本与格式有限 ⚠️；湖上 ACID 交给表格式层（互链 09/存储文件格式笔记） |
| "连接器性能都差不多" | 下推深度差一个数量级：JDBC/ORC 剪裁 vs ES 全文 vs Kafka 无索引 |

## 本章小结与行动清单

三句话带走：
1. 连接器四问（元数据/Split/读取/写回）是接到任何新数据源时的第一张问卷——答不全就不要承诺 SLA；
2. **下推边界=性能天花板**：同一张表，谓词写法不同可以在"源内完成"与"拉回全表"之间切换，EXPLAIN 是唯一公证人；
3. Hive 连接器一节（6.4）表面上过时（主场转向 Iceberg），实质是湖表语义的地基：分区/格式/所有权概念被表格式层原样继承。

接入新源的评估模板（抄进工单系统用）：
- [ ] 元数据：表结构从哪来？变更感知吗？缓存 TTL？
- [ ] Split：粒度/数量/倾斜预期；并行读上限？
- [ ] 读取：支持哪些谓词/投影/聚合下推？类型映射表逐列过；
- [ ] 写回：CREATE/INSERT/DELETE 支持到哪步？（8.6.6 清单）
- [ ] 运维：凭据轮转、连接配额、源侧监控（对源库它是个坏邻居还是好邻居？）

自测：
- [ ] 为什么 JDBC 连接器要默认走只读副本？（6.2.4 安全性的资源侧含义）
- [ ] blackhole 与 memory 连接器各自"不该用在哪"？（压测件≠缓存、内存表≠持久化）

一句话总结：连接器章的终点认知是——**引擎只认识"表"这个形状**，
把任何源映射成表时丢掉的语义（索引/事务/新鲜度/顺序），都要在设计文档里写明由谁来补。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 连接器 SPI | Connector SPI | 元数据/Split/读写/DDL 的插件接口契约 |
| 查询下推 | Query Pushdown | 谓词/投影/聚合翻译给源系统先行执行 |
| Split | Split | 并行读取的最小数据切片单位 |
| Hive 表格式 | Hive Table Format | 目录分区约定 + metastore 模式的表组织 |
| 分区剪裁 | Partition Pruning | 依分区列谓词跳过无关目录 |
| 内部表/外部表 | Managed/External Table | metastore 对数据生命周期所有权的划分 |
| ORC/Parquet | Columnar File Formats | 列式文件+索引，交互式扫描的底座 |
| RC 文件 | RCF (Deprecated) | 早期列式格式，书中仅作历史介绍 |
| JMX 连接器 | JMX Connector | 引擎指标以 SQL 暴露的自省源 |
| 黑洞连接器 | Blackhole Connector | 接收并丢弃数据的压测汇 |
| 内存连接器 | Memory Connector | 内存驻留、重启即失的试验表 |
| MinIO/S3 兼容 | S3-compatible Storage | 对象存储接 Hive 表的云原生桥（书中示例） |
| 类型映射 | Type Mapping | 源类型与 Presto 类型的转换表 |
