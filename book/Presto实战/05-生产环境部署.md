## 精讲

### 1. 内存配额联立方程（5.5 的当代读法）
一个 worker 的内存至少四份账：
```text
-Xmx(堆) ≥ query.max-memory-per-node(引擎池) + 操作缓存 + Exchange 缓冲 + JVM 自身(native/codecache/GC)
整机 RAM ≥ -Xmx + 页缓存需求(HDFS/S3 本地缓冲 ⚠️ 版本相关) + OS 余量
```
- `query.max-memory`（集群级）与 `query.max-memory-per-node`（节点级）构成第一道熔断；
- 溢出（spilling）在书中时代可选且性能悬崖深（12.3 深究）；
- G1 的 `-XX:InitiatingHeapOccupancyPercent`、`G1HeapRegionSize` 等参数书中给了模板——
  模板值随 Java 17/G1 演进已需重校（⚠️ 照抄 2021 模板是事故源）。

### 2. "同包差分配置"部署模型（5.7）
所有节点装同一发行包，仅 `etc/` 差分：
- 协调器：`coordinator=true`，去掉 `node-scheduler.include-coordinator`（生产不让大脑兼苦力）；
- worker：`coordinator=false` + `discovery.uri=http://coord:8080`；
- `catalog/*.properties` 全集群一致（否则 `Table Not Found` 类幽灵故障——某 worker 缺 catalog 文件）。
**纪律**：配置即代码（Git 管理 + 发布比对），否则"节点漂移"无 debug 价值。这与 K8s ConfigMap 思路同构。

### 3. 部署形态的三种世代（书中给了前两种）
| 形态 | 书中 | 2026 |
| --- | --- | --- |
| 裸机/虚机 tar.gz + launcher | ✅ 主流 | 存量 |
| RPM 包 | ✅ 提及（含第三方打包 ⚠️） | 边缘化 |
| 容器 + Operator/K8s | 5.9 云上雏形 | 主流：弹性伸缩、滚动升级、拓扑自动发现 |
K8s 化的语义代价：worker 频繁重生→发现抖动；协调器有状态（查询生命周期）→不适合随意驱逐（⚠️ 各家 Operator 对策不同）。

### 4. 规模考量三条线（5.10 展开）
1. **协调器规划带宽**：SQL 规划/调度是单点协调活，高并发 ad-hoc 下协调器 CPU 与 GC 先饱和——对策是拆分多集群（10.9 集群分离）；
2. **worker 数量 × 每查询分片数**：Stage 碎片过多调度开销超收益；
3. **存储侧并发上限**：HDFS NameNode/S3 前缀限流常比计算先到顶——湖仓时代由表格式+缓存层缓解（见 06/11 章与 Iceberg 笔记互链）。

## 常见误区

| 误区 | 现实 |
| --- | --- |
| 让协调器兼 worker 省事 | 小拓扑教学可以；生产规划抖动与执行挤兑互相放大，书中明确建议分离 |
| `query.max-memory` 调大=更快 | 只是抬高熔断线，OOM 概率与 GC 停顿同步上升 |
| 配置热改即生效 | 多数参数需重启；会话级可改的参数面窄且版本相关 ⚠️ |
| 集群规模线性扩 | 广播 Join、协调器带宽、元数据访问都会非线性恶化 |

## 本章小结与行动清单

三句话带走：
1. 部署的产物不是一组机器，而是**一份可复现的配置仓库**：同包+角色差分+版本控制，三者缺一就等着幽灵故障；
2. 内存账是联立方程（-Xmx/引擎池/Exchange 缓冲/OS 余量），抄模板前先按 Java 版本与 GC 重解一遍；
3. 规模上限先看协调器，再看 Exchange 与元数据服务，最后才看 worker CPU——顺序反了就是钱白花。

上线前检查单（书中时代的 tar.gz 路线与当代 K8s 路线通用的部分）：
- [ ] 协调器/worker 配置 diff 审阅通过；catalog 文件全节点一致并有校验（和比对）；
- [ ] `node.id` 与环境标签纳入 CMDB，故障时可按 id 定位；
- [ ] JVM 参数表记录"为什么是这个值"（每个值一个理由，12.7 有对照组）；
- [ ] 滚动重启演练：先重启 worker 再重启协调器，各观察在途查询行为；
- [ ] 时钟同步（Kerberos/TLS 证书校验的前提，10 章预埋）。
- [ ] 磁盘与网络基线压测过一轮（blackhole+tpch 即可，06 章工具的部署侧应用）。

自测：
- [ ] 为什么"热改配置"多数不生效？哪些参数是会话级例外？（参数分层心智）
- [ ] K8s 上协调器为什么不适合随意驱逐/HPA？（有状态查询生命周期，4.2）

一句话总结：部署章的产出物不是"跑起来的集群"，而是**可复现、可审计、可滚动**的三份资产：配置仓库、参数决策表、演练记录。
