## 精讲

### 1. 每接一个源，先回答"它把 Split 切成什么"
| 源 | Split 形态 | 下推红利来源 |
| --- | --- | --- |
| Accumulo | tablet 范围 | 有序行键前缀过滤（7.2.2：谓词→扫描范围） |
| Cassandra | token 范围/vnode | 分区键等值→定向分片 |
| Kafka | 分区×偏移段 | 无谓词红利，全量解码——只配小窗口探索 |
| Elasticsearch | shard | 查询 DSL 翻译（含全文 match），Lucene 层裁剪 |
| HBase(Phoenix) | region | 经 Phoenix 元数据映射，谓词翻译深度受限 ⚠️ |
**读表法**：第 6 章的"下推边界=性能天花板"在具体源上的投影。任何源上写 `WHERE` 前，先想这条谓词能否改写为源的原生定位手段。

### 2. Kafka 连接器的设计味道（7.4）
- 表 = topic + 行 decoder + 数据 schema 的**静态映射**（JSON/CSV/Avro/Protobuf decoder ⚠️ 支持面按版本）；
- 无主键、无更新语义、消费偏移由 Presto 会话管理——它是"批式快照读流"，不是流计算；
- 生产用法边界：探索样本、联查维表、对账瞬时窗口；长流消费请交给真正的流引擎（互链
  [../Apache_Paimon_Streaming_Lakehouse/11-Flink集成与CDC入湖实践.md](../Apache_Paimon_Streaming_Lakehouse/11-Flink集成与CDC入湖实践.md)：当代解法是 CDC 入湖后统一查）。

### 3. 联邦查询实操解剖（7.6）
书中流程的骨架（以概念复述，非原文）：
```sql
SELECT o.id, c.name, e.event_time
FROM mysql.sales.orders o
JOIN hive.dwd.customers c ON o.cid = c.id
LEFT JOIN kafka.events.e ON e.key = o.id       -- 三源联查示意
WHERE o.day >= '2021-01-01' AND c.tier = 'gold';
```
- **计划形态**：每源一个子 Stage，Exchange 处做分布式 Join；小表广播（4.11.7）决定成败；
- **物理化是终态**：联邦结果若要复用/加速 BI，用 7.7 的 CTAS 落 Hive/Iceberg 表，把一次性联查固化为湖内单源查询——
  这正是后来"湖仓吞掉联邦"的路线预演；
- **成本护栏**：跨源大 Join 前先在两侧各自 LIMIT/聚合收敛（12.2 的调优信条在此源场景的具象）。

### 4. ES 双路执行（7.5）
可翻译谓词（term/range/通配）进 Lucene，不可翻译的（函数包裹、相关子查询）回 Presto 全量拉——
"混合执行"的样板：看 `EXPLAIN` 输出里 `TableScan[es ... pushdown=...]` 行判断红利（⚠️ 计划文本形态按版本核对）。

## 常见误区

| 误区 | 现实 |
| --- | --- |
| 联邦查询是常态架构 | 它是**胶水/探索/迁移期**形态；稳态应物化到湖（7.7）或源侧建模，否则每次联查都付全网搬运费 |
| Kafka 连接器能做实时看板 | 无增量视图、全 topic 扫描，看板应走流引擎+OLAP 物化（互见 [../bigdata/07-实时计算与流式架构.md](../bigdata/07-实时计算与流式架构.md)）|
| ES 有 match 谓词就快了 | 只有映射到 DSL 的部分快；解析失败静默回退全扫，必须 EXPLAIN 复核 |
| Cassandra 加个 WHERE 就有索引效果 | 无分区键的过滤=全集群扫；连接器不创造源所没有的能力 |

## 本章小结与行动清单

三句话带走：
1. 五个非关系源的接入示范其实在反复讲同一件事：**源没有的能力（索引/谓词/更新），连接器不会凭空造**；
2. 联邦查询的经济学=一次性联查成本 vs 物化到湖的存储/新鲜度成本——高频复用必物化，低频探索可裸联；
3. Kafka/ES 等"流与弱结构源"在 2026 年多被湖格式吸收（CDC 入湖/variant 类型），本章因此更像"源生态博物馆"，
   但**下推判定方法**（EXPLAIN 复核 TableScan 行）永生不灭。

联邦查询上线前检查单：
- [ ] 每个源的输入量级估算（行数×字节）已写在 SQL 注释头，评审者据此判断 Exchange 风险；
- [ ] 小表侧确认广播阈值内（4.11.7），大表侧确认分区/索引谓词命中；
- [ ] 结果集有 TTL 或已决定 CTAS 落表（7.7）；
- [ ] 源侧限流/只读副本配置完成（06 章 JDBC 纪律的跨源版）。

自测：
- [ ] 为什么"ES 上加了 WHERE"仍可能全扫？给出两个成因与一个证据手段；
- [ ] Kafka 直查与"CDC 入湖后查湖表"的分水岭是什么？（新鲜度×复用率）

一句话总结：高级连接器=五个"源的物理性"课例；记住**Split 形态决定并行上限、下推边界决定扫描下限**这两把尺，
遇到任何新源都能自行完成本章式推演。

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 翻译代理模式 | Proxy Translation | 经 Phoenix 等中间层间接接源 |
| 行解码器 | Row Decoder | Kafka 记录→行的编解码插件（JSON/Avro…） |
| 表映射 | Table Mapping | 非关系对象（topic/索引/宽表）与表的静态对应 |
| 谓词下推边界 | Pushdown Boundary | 源原生可执行的谓词子集 |
| DSL 翻译 | DSL Translation | Presto 谓词→ES Query DSL 的编译 |
| 全文搜索 | Full-text Search | 经 ES 连接器进入的 match/短语检索 |
| 联邦查询 | Federated Query | 跨 catalog 单 SQL 联查 |
| 混合执行 | Hybrid Execution | 下推段+回 Presto 段并存的计划形态 |
| EXPLAIN 复核 | EXPLAIN Verification | 以计划文本确认下推是否生效的手法 |
| 物化固化 | Materialization | 联邦结果 CTAS 落湖为单源表 |
| 轻量 ETL | Light ETL | INSERT/CTAS 驱动的 SQL 转换，非作业编排 |
| Token 范围 | Token Range | Cassandra 分片定位的哈希区间 |
| Shard 级并行 | Shard Parallelism | ES 分片即 Split 的并行读 |
