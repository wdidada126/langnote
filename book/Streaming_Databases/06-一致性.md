## 章定位与中心论题

流式数据库把"一致性"从口号拆成四层问题：**传输层**（消息会重放/乱序/丢吗）、
**状态层**（故障后状态与源流的可恢复对齐）、**视图层**（读者会不会看到半更新）、
**服务层**（pull/push 读者各自读到的新鲜度上界）。⚠️ 推定本章以"exactly-once 是营销词还是定理"
为轴，把 #228 的重放等价（replay equivalence）翻译成数据库用户的验收清单。

## 逐节精读重构（⚠️ 章级）

### 6.1 传输层：日志语义先于一切

- Kafka 型日志给出的是**至少一次 + 可重放**；"恰好一次"靠消费者幂等/事务 API 组装
  （⚠️ 转述，未装引擎）；#228 05 章的结论在此复用：**结果等效而非传输等效**；
- 源→视图的映射必须可**确定性地**从 (源前缀, 视图算法) 重放出来——否则 6.3 的修复无从谈起。

### 6.2 状态层：故障恢复的三种姿势

1. **从源重放**（Materialize/早期 ksqlDB 路线）：状态=纯函数(源, offset)，崩溃后重放到水位；
   恢复时间∝历史长度 → 用快照+压缩日志（compacted topic）摊薄；
2. **检查点快照**（Flink Chandy-Lamport 系，见 Flink 书 12 章）：状态周期落盘，重放从快照起点；
3. **共享存储**（云原生货架：RisingWave/Materialize v2 路线）：状态放 S3 型对象存储，
   计算重启即读——"一致性"与"恢复时间"解耦（⚠️ 各家实现细节文档转述，本册一律不评性能）。
- 内核视角对照：[../Database_Internals/07-日志结构存储.md](../Database_Internals/07-日志结构存储.md)
  的 WAL+快照就是同一条谱系的单机版。

### 6.3 视图层：更新原子性与读一致性

- 一条输入可能触发跨多索引/多视图的连锁维护（第 4 章 delta 传播）——
  **要么全可见要么全不可见**，否则 pull 读者看到"和不等账"的中间态；
- 🔧 演示（本章末）：sqlite 触发器天然继承事务原子性，回滚即视图无痕——
  "视图维护挂在写事务上"的最小说明；
- 分布式下同一命题升级为**两难**：源提交、状态落盘、索引更新、push 送达四者横跨多节点，
  需要事务/共识机制背书（对照 DBI [10-分布式事务](../Database_Internals/10-分布式事务.md)、
  [11-共识算法](../Database_Internals/11-共识算法.md)；本册不展开协议细节）。

### 6.4 服务层：读者视角的新鲜度合同

- pull 读者：可能读到"落后 N 毫秒"的副本（存算分离/多副本时 N 是配置项）；
- push 读者：至少一次送达 + 游标重放 ⇒ 消费端仍需幂等（回到 6.1）；
- ⚠️ 推定本书金句式结论：**流式数据库卖的不是"绝不重复"，而是"重复可识别、乱序可折叠、
  故障可重放"**（本目录认同，并提醒用 #228 05 章的副作用清单验收出站端）。

### 6.5 副作用与出站端（承 #228 05 章）

外部系统（邮件、支付、写回非事务存储）不在"结果等效"保护伞下：
幂等键、两阶段、变更数据捕获式"意图表"是仅有的三件工具；⚠️ 推定本章有对应告诫。

## 🔧 演示：回滚原子性——视图与基表同生共死（sqlite3 3.45.3，非流引擎）

接第 4 章演示 A 的 mv_region_rev：开事务→插入一条引用不存在客户的订单→人为报错→ROLLBACK，
检查视图是否被"半途触发器"污染：

🔧 实测输出（原样，`demos.py`）：

```text
A4 mv after rolled-back txn (atomicity): [('east', 195, 2)] => unchanged: True
```

解读：触发器执行在事务内，回滚把**基表写入与视图增量一并撤销**——6.3 的"全可见或全不可见"
在单机上免费；分布式引擎要为同一性质付出事务/共识成本（这正是 6.2 三种姿势的动机）（🔧 演示结论）。

## 核心概念速览（中英对照）

- **至少一次/恰好一次** — at-least-once / exactly-once：传输语义与结果语义的经典错位（#228）
- **重放等价** — replay equivalence：故障重放后输出不可区分（6.1）
- **可折叠乱序** — order-tolerant folding：按主键/水位把乱序流折成确定状态（6.4）
- **快照+压缩日志** — snapshot + compacted log：从源重放的两大摊薄手段（6.2-1）
- **检查点** — checkpoint：状态周期性一致性落盘（6.2-2，Flink 路线）
- **共享状态存储** — disaggregated/shared state：状态外置对象存储（6.2-3，云原生路线）
- **更新原子性** — atomic view update：连锁维护的全可见/全不可见（6.3）
- **读偏斜** — read skew：pull 读者撞上半更新中间态的病（6.3）
- **新鲜度上界** — staleness bound：服务层合同的可测版本（6.4）
- **幂等键** — idempotency key：出站副作用去重的最后防线（6.5）
- **意图表** — outbox pattern：先写"打算做的副作用"再异步执行（6.5）
- **数据库待遇验收** — database-ness audit：以四层清单验收流式数据库宣称
