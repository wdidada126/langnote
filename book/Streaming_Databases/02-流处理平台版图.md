## 逐节精读重构（⚠️ 章级）

### 2.1 平台的三个抽象层

- **底层日志**：Kafka/Pulsar——只做 durable stream（带 offset 的重放日志），计算外挂；
- **计算引擎**：Flink/Spark Structured Streaming/Kafka Streams/Herons 遗珠/Beam(运行时中立)——
  给"流上的函数/关系算子"，结果送回外部存储；
- **查询层**：ksqlDB/Flink SQL(动态表)/Materialize/RisingWave/Dataflow 等——
  以 SQL + 物化视图为一等公民，"算完直接就是可查的表"。
- ⚠️ 本书推定立场：三层的边界正在溶解，最终收敛于"查询层吞并计算层、日志层退为存储附件"。
  这个论点在第 5/9 章放大为主张。

### 2.2 代表平台速写（以 2024 为锚，现状见文末实查）

| 平台 | 形态 | 状态/时间语义要点 | 与 #228 关系 |

### 2.3 选型的四条轴线（⚠️ 重构组织）

1. **语义完整度**：事件时间/乱序/迟到谁兜底（→ 用 #228 四问打分：
   [02 章](../Streaming_Systems/02-数据处理的来龙去脉.md)）；
2. **状态规模**：GB（内存/嵌入式）→ TB（RocksDB/Flink）→ 存算分离（云货架）；
3. **交付形态**：库 < 自管集群 < 托管服务（第 10 章展开）；
4. **查询面向**：只有 API/算子，还是有 SQL+可订阅的结果表（本书分水岭）。

### 2.4 版图上的"数据库味"

- 只有少数货架成员提供：声明式 schema、主键、二级索引、事务边界、权限模型——
  即"数据库待遇"（第 5/6 章的伏笔）。⚠️ 推定本书在此埋下"流处理平台 ≠ 流式数据库"的判据：
  **前者交付作业，后者交付一张永远新鲜的表**。

## 🔧 概念对照演示（sqlite3 3.45.3，批式库模拟"货架语义"，非任何流引擎）

把 2.1 三层的**接口差异**用同一份数据演出来：底层日志=只追加带序号的表；
计算引擎=对表做 GROUP BY 后写回；查询层=视图即时读（pull）：

```sql
CREATE TABLE journal(off INTEGER PRIMARY KEY AUTOINCREMENT, k TEXT, v INT);  -- 日志层
INSERT INTO journal(k,v) VALUES ('a',1),('b',2),('a',3);
-- 计算层：一次性物化"结果表"（微批味）
CREATE TABLE agg AS SELECT k, sum(v) s FROM journal GROUP BY k;
-- 查询层：不物化，读时现算（ksqlDB pull query / Materialize 的直觉等价物）
SELECT k, sum(v) s FROM journal GROUP BY k;
```

🔧 实测：journal 3 行，agg 与即时 GROUP BY 均返回 a=4, b=2（三种"平台姿态"同语义不同成本
——物化一次/读时全算/持续维护，为第 3、4 章的 push vs pull、IVW 埋点）。

## 核心概念速览（中英对照）

- **三层抽象** — log/compute/query tiers：日志、引擎、查询层的货架分层
- **durable log** — 持久重放日志：Kafka 型底座，offset 即时间轴
- **动态表** — dynamic tables：Flink SQL 的流表统一对象（#228 06 章思想的产品化）
- **KTable** — Kafka Streams 的表抽象：压缩日志=快照语义
- **微批** — micro-batch：Spark 式"以批仿流"，连续性有下限
- **模型中立** — model-neutral（Beam）：一份图多引擎跑，与"平台绑定"对立
- **SQL 面** — SQL surface：是否有声明式查询+可订阅结果，本书判据
- **数据库待遇** — database-ness：schema/主键/索引/事务/权限的完整度
- **交付作业 vs 交付表** — pipeline vs fresh table：流处理与流式数据库的分水岭
- **存算分离** — disaggregated state/compute：云原生货架的共同骨架（第 10 章）
- **CHANGES FOR PARTITION** — Kafka 原生表读接口：ksqlDB 特色，"流即表"的 API 证据
- **版图贬值率** — landscape half-life：平台章的通病，须靠带日期取证续命
