## 章定位与中心论题

本章为全书铺设"流式地基"：批处理与流处理不是两种工具，而是对**同一份随时间变化的数据**
的两种交付节奏；实时化的根本动机是"数据的价值随时间衰减"。⚠️ 按内容简介（✅ 实抓），
本书的三段式世界观在此定型：**源端实时数据 → 在途流处理 → 低延迟服务**，
后面所有章节都是这三段中某一段的放大。

## 逐节精读重构（⚠️ 章级）

### 1.1 数据新鲜度的需求侧

- 业务侧三股压力（⚠️ 重构组织）：风控/欺诈检测要"事发即知"；运营仪表盘要"现在"而非"昨天";
  面向客户的推荐/状态推送要毫秒级。批处理 T+1 的根因是**全量重算**：每次把历史全部重扫。
- 新鲜度谱系（与 #228 [01 章](../Streaming_Systems/01-流式入门.md)"完美/近似/务实"三分对应）：
  天级批 → 微批（分钟）→ 真流（秒/亚秒）→ 交互查询（毫秒 pull）。
  ⚠️ 本书立场推定：多数"实时需求"其实要的是**结果随时可查**，而非"每条秒到"，
  这正是流式数据库（第 5 章）的切入点。

### 1.2 流处理的最小模型

- 数据流 = 无界、随时间追加的记录序列；算子 = 对流的**持续函数**；
  状态 = 算子为算出下一个输出而记住的东西。
- 与 #228 的术语对齐：那里的 What/Where/When/How 四问（
  [02 章](../Streaming_Systems/02-数据处理的来龙去脉.md)）是**语义层**；
  本章只给"来料加工"的直觉流水线（source → transform → sink），
  故意推迟乱序/水位线等深水问题（⚠️ 推定本书把时间语义并入第 2/5/6 章消化）。
- 关键分叉：**流计算输出什么**？（a）聚合结果写回外部库（经典流处理）；
  （b）输出本身就是一张持续保鲜的表（流式数据库）。(b) 是本书主战场。

### 1.3 为什么"再加一个流系统"不解决问题

- 经典实时数仓三跳（⚠️ 重构，参考 [../bigdata/07-实时计算与流式架构.md](../bigdata/07-实时计算与流式架构.md) 的
  Lambda 描述）：Kafka 进 → Flink/Spark 算 → MySQL/Redis/Cassandra 出。
  每跳都带一份**独立存储与独立语义**（各自的 SQL 方言、各自的一致性承诺、各自的运维面）。
- 本书的批判点（按内容简介"降低实时方案的基础设施"✅ 措辞推定）：
  流式数据库要把"算完存哪、怎么查、何时保鲜"三件事收进**一个系统**——
  用物化视图（第 4 章）替代"算→存→查"三跳。
- 反方观点也要摆上（本目录平衡）：三跳架构换来各层可独立扩容/独立故障域；
  合一系统则换来开发速度。这是第 7/10 章反复出现的钟摆。

## 🔧 直觉演示：批重算 vs 增量一行（python 内置 sqlite3 / SQLite 3.45.3，非流引擎）

同一道聚合题，批节奏与流节奏的成本差来自**结构**而非调优（内联脚本，输出存盘 ch1_demo.txt）：

```sql
-- t 表 200000 行、50 个分组；mv(k,s,c) 由 AFTER INSERT 触发器增量维护
SELECT k, sum(v), count(*) FROM t GROUP BY k;      -- 批节奏：全表重扫
INSERT INTO t VALUES (7,42);                        -- 流节奏：触发器只碰 1 个分组行
```

🔧 实测输出（原样）：

```text
rows: 200000 | groups: 50 | full recompute: 49.2 ms
insert 1 row w/ trigger: 0.076 ms | mv[k=7]: (2076042, 4001) | full[k=7]: (2076042, 4001) | match: True
full touches: 200001 rows; incremental touches: 1 row + 1 mv row
```

解读：增量路径成本 ≈ O(组数变化)，与历史规模解耦——"持续查询"的全部经济学就在这里；
但注意这是**单机触发器**，无分布式 shuffle、无乱序、无故障恢复——那才是第 4~6 章的主题（🔧 演示结论）。

## 核心概念速览（中英对照）

- **数据新鲜度** — data freshness：结果与真实世界的时滞，实时架构的第一 KPI
- **无界数据集** — unbounded dataset：只会追加、永不"结束"的数据，流处理的对象
- **持续函数** — continuous function：对每条输入即时产出/更新输出的算子语义
- **全量重算** — full recomputation：批处理保鲜方式，成本 O(历史全量)
- **增量维护** — incremental maintenance：只处理 delta 的保鲜方式，成本 O(变化量)
- **三跳架构** — ingest/process/serve pipeline：Kafka→Flink→在线库的经典实时链路
- **流式数据库** — streaming database：把"算完存哪怎么查"合一的持续查询引擎（本书主题）
- **新鲜度谱系** — freshness spectrum：天级批→微批→真流→交互查询的连续统
- **价值衰减** — value decay：数据价值随时延下降，实时化的经济学动机
- **价值双重性** — value of streams：流既是"消息"又是"未落地的表"（第 9 章伏笔）
- **push 需求** — push-based serving：结果主动到达消费者，区别于 pull 现问现查
- **语义分层** — semantics vs plumbing：#228 管语义正确，本册管产品与架构
