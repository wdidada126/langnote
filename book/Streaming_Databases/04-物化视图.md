## 章定位与中心论题

物化视图 = **把查询结果存下来并随基表变化保持正确**的数据库技术；
流式数据库的本质就是"所有视图都是物化视图、所有维护都是增量的、维护节奏是逐条的"。
⚠️ 推定本章论证链：定义与历史（批式 MV 的刷新困境）→ 增量视图维护 IVW（只算 delta）→
各代数算子的 delta 规则 → 从任意多条流构造 MV（→ 第 5 章）。

## 逐节精读重构（⚠️ 章级）

### 4.1 批式 MV 的两难

- 传统 RDBMS 的 MV：`REFRESH` 全量重算（Oracle/SQL Server 路径 ⚠️ 文档转述）或
  受限的 fast-refresh（物化视图日志 + 增量刷，条件苛刻：聚合可分解、无外连接等）；
- 刷新周期=新鲜度下限、全量成本=规模上限：**批式 MV 永远在新鲜度与成本间折中**；
- 出路：把"刷新"从周期动作改成**写入路径上的同步动作**——这就是 IVW，
  也是本目录 🔧 触发器演示的骨架。

### 4.2 IVW 的算子代数（本目录整理成表）

设 delta(·) 为基表变更的多重集，视图维护规则（⚠️ 通识组织，细节见 DBSP/经典综述）：

| 算子 | delta 规则 | 难点 |
| --- | --- | --- |
| 选择 σ | delta 过滤即可 | 无 |
| 投影 π | 去重需计数支撑（count 随行） | 删除后何时撤行（计数归零） |
| 并 ∪ | 分配律 | 重复计数 |
| 连接 ⋈ | delta(R⋈S)=δR⋈S + R⋈δS + δR⋈δS | 三项都要算；自连接防重 |
| 分组聚合 | 可分解聚合(SUM/COUNT/MIN+多重集)好办；AVG=count+sum 合成 | **非可分解聚合**（MEDIAN/百分位）代价高 |
| 外连接 | 删除侧要**补 NULL 行**、插入侧要**撤 NULL 行** | 见 🔧 演示 B：最容易写错 |
| 递归/不动点 | 迭代直至 delta 为空 | 收敛与循环依赖（→ 7 章演示 D） |

- 核心数据结构：**带符号多重集**（每行带 +1/-1 或行数计数）——#228 06 章的 changelog 在此
  露出代数真身；DBSP 论文把它形式化为"流的微积分"（✅ DOI 见文末）。

### 4.3 从流构造 MV

- 流→MV=按主键把 changelog 折叠成表（to-table，#228 语言）；MV→流=把维护产生的行差
  再发布出去（to-stream）；**双向都免费**是流式数据库的卖点（→ 第 5/9 章）。
- ⚠️ 内容简介原句（✅ 实抓）"construct materialized views from any number of streams"：
  多流拼接=以主键为 What 的跨流连接维护。

### 4.4 工程税

维护者状态要持久化（→ 第 6 章一致性）、增量算错一处则视图永远错下去（无"全量重刷"退路时
更危险）、schema 演化时 MV 重建昂贵、以及"视图级权限"问题。⚠️ 推定本章末尾有运维忠告。

## 🔧 演示 A：手写 IVW（sqlite3 3.45.3 触发器，非流引擎）

`orders ×(join customers)→ mv_region_rev(region,total,cnt)`，INSERT/DELETE/UPDATE 三个触发器
按 4.2 的连接+聚合规则增量维护；变更序列 = 插 3 单、删 1 单、改 1 单金额：

🔧 实测输出（原样，`demos.py`）：

```text
A2 trigger-maintained mv : [('east', 195, 2)]
A3 on-the-fly full recomp: [('east', 195, 2)] => identical: True
```

解读：west 组被删单后 cnt=0 触发**墓碑清理**（`DELETE ... WHERE cnt<=0`）——
演示了 4.2 表"删除后何时撤行"与"count 支撑"两难点的最小正确实现。

## 🔧 演示 B：朴素触发器栽在外连接（同环境）

只维护"stock 插入"一侧的 `products LEFT JOIN stock` 视图：

🔧 实测输出（原样）：

```text
B1 naive trigger MV (misses 补空 rows): [(1, 'a', 5)]
B2 correct LEFT JOIN recompute        : [(1, 'a', 5), (2, 'b', 0), (3, 'c', 0)]
```

解读：naive==correct 为 **False**——LEFT JOIN 的"补空行"要求触发器同时挂在**保留侧的插入**
与**可空侧的删除**上，并处理 NULL 占位；这正是 4.2 表最后一行与 IVW 文献中 outer join 维护
最难写对的经验性复现（🔧 演示结论；真实流引擎同样要在优化器里做这件事，不是人肉触发器）。

## 核心概念速览（中英对照）

- **物化视图** — materialized view：存储查询结果并随基表保鲜的数据库对象
- **增量视图维护** — IVW, incremental view maintenance：只处理 delta 的维护策略
- **全量刷新** — full refresh：重算整视图，批式 MV 的保底手段
- **带符号多重集** — signed multiset：行带 +1/-1/计数，IVW 的通用货币（#228 changelog 之代数化）
- **delta 规则** — delta propagation：算子对输入变化的响应公式（σ/π/⋈/γ 各不同）
- **自连接三项式** — δ(R⋈S)=δR⋈S+R⋈δS+δR⋈δS：连接维护的分配律
- **可分解聚合** — decomposable aggregate：SUM/COUNT/MIN(+计数) 可增量；MEDIAN 难
- **补空行** — NULL-completion：外连接删除侧维护特有的正确性义务
- **墓碑/计数归零** — tombstone cleanup：投影去重与组消失的撤销机制（🔧 演示 A）
- **视图日志** — materialized view log：Oracle 式变更捕获，IVW 的前身工程
- **持续物化视图** — continuously maintained MV：流式数据库里 MV 的存在方式（第 5 章）
- **DBSP** — 流上的数据库微积分：自动 IVW 的形式化理论（文末 ✅ DOI）
