# 第 1 章 基本技巧——元函数、控制流与 CRTP

> 原书：李伟《C++模板元编程实战：一个深度学习框架的初步实现》第 1 章（P3–27），
> 人民邮电出版社 2018-11。目录取自既有大纲 [../C++模板元编程实战.md](../C++模板元编程实战.md)（豆瓣 30394402 口径）。
> 总览与阅读地图见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

本章是全书"元编程基础技术"部分（第一部分）的起点：把模板实例化当作函数调用、
把特化匹配当作分支、把递归实例化当作循环——为第二部分（MetaNN 深度学习框架，
第 3–8 章）的富类型体系、表达式模板与 policy 组件打好语法底座。

## 核心概念速览（中英对照）

- **元函数** — metafunction：以类型为参数、以类型或编译期常量为结果的"函数"，实体是类模板
- **类型萃取** — type traits：从类型中提取成员类型/属性的模板族（书中 `::type` 风格 + `<type_traits>`）
- **类型别名** — type alias (`using`)：C++11 起替代 `typedef`，可与变参模板组合
- **模板型模板参数** — template template parameter：以"模板本身"（而非已实例化类型）为参数
- **容器模板/类型列表** — container template / type list：`TypeList<Ts...>` 式的编译期聚合容器
- **顺序/分支/循环** — sequential / branch / loop in TMP：实例化序列、特化选择、递归实例化
- **实例化爆炸** — instantiation explosion：朴素递归元函数在深层实例化时模板实例数组合式膨胀，甚至撑爆编译器
- **短路逻辑** — short-circuit logic：`And_/Or_` 借特化在第一个 false 处停止递归，避免无谓展开
- **奇特的递归模板式** — CRTP (Curiously Recurring Template Pattern)：派生类把自己作为基类模板实参，编译期"向上转型"
- **命名约定** — `Xxx_` 尾下划线：本书元函数命名规范（区别于类型与算法模板）

## 动机：为什么"先练剑法再看阵图"

作者把全书切成两部分是有用意的：第 1、2 章的技术（元函数、控制流、CRTP、policy）
在第二部分被**反复组合使用**——第 4 章的标签体系靠"类型作模板参数"，第 5 章的
OperOrganizer 靠变参与特化分派，第 7 章的 ComposeTopology 靠容器模板与递归元函数。
如果直接读框架章，会同时面对"模板语法"与"神经网络架构"两座山。因此本章的每个
技法都要回答一个问题：**它在 MetaNN 里最终落在了哪里**（下文各节末以"→ 框架落点"标注）。

## 机制精讲

### 1.1 元函数与 type_traits

元函数的最小形态：

```cpp
// 🔧 示意：类型元函数（书中 Xxx_ 命名口径的等价改写，非原书源码）
template <class T> struct RemoveConst_ { using type = T; };
template <class T> struct RemoveConst_<const T> { using type = T; };  // 偏特化=模式匹配
template <class T> using RemoveConst = typename RemoveConst_<T>::type; // 别名收尾
```

机制三要素：**主模板=默认分支，偏特化=模式匹配，`::type`/`value`=返回值**。
标准库 `<type_traits>` 提供工业级同款（`std::remove_const_t`），作者仍自建是因为
框架需要**对自定义类型做域内萃取**（第 4 章 `OperElementType_` 等）——标准 traits
只认识标准世界。命名约定 `Xxx_`（元函数）+ `Xxx`（别名）是本书自订风格，读
MetaNN 源码（[github.com/bluealert/MetaNN-book](https://github.com/bluealert/MetaNN-book)，实测 200）
时随处可见，如 `RemConstRef`、`OperCateCal`。→ 框架落点：第 4/5 章所有 `traits.h`。

### 1.2 模板型模板参数与容器模板

```cpp
// 🔧 已实测 g++ 15.2：模板作为输入（F 是"未定身的模板"）与容器模板
template <class T> struct Box { using type = T; };
template <template <class> class F, class T> struct Apply { using type = F<T>; };
static_assert(std::is_same_v<Apply<Box, int>::type, Box<int>>);
```

模板可以**作为未实例化的函数传入**（输入），也可以被元函数**生成后返回**（输出，
经由 `::type`），两头都是模板就有"高阶元函数"。把 `TypeList<Ts...>` 当作编译期
数组，就是书中"容器模板"：C++98 时代要写定长包装（`TypeList5<T1..T5>` +
`NullParameter` 哨兵），变参模板（C++11）后用 `Ts...` 一步到位。本书成书于
2018，正文实际已按变参风格写（如 `MetaNN/facilities/var_type_dict.h` 里的
`Create_<N, TCont, T...>` 用递归把 `Cont` 填到 N 个槽位——正是"容器模板输出"的活例）。
→ 框架落点：第 2 章异类词典、第 7 章 SubLayer 描述子句列表。

### 1.3 顺序、分支与循环

- **顺序**：嵌套实例化即顺序求值，`A<B<C>>` 先内后外；或用继承把多步结果串起来。
- **分支**：特化选择 + 全特化终止递归；`If_` 的问题在于**两个分支都会被实例化**，
  需要惰性求值包装（把类型包进 `::type` 延迟到选中分支才展开）。
- **循环**：递归实例化 + 全特化出口。典型如"对类型列表求长度/取第 N 个"：

```cpp
// 🔧 已实测 g++ 15.2（-std=gnu++23）：递归"循环"取第 N 个类型
template <class... Ts> struct TypeList { static constexpr std::size_t size = sizeof...(Ts); };
template <std::size_t I, class L> struct At;
template <std::size_t I, class T, class... Ts>
struct At<I, TypeList<T, Ts...>> : At<I - 1, TypeList<Ts...>> {};  // 递归=步进
template <class T, class... Ts>
struct At<0, TypeList<T, Ts...>> { using type = T; };              // 全特化=出口
static_assert(std::is_same_v<At<1, TypeList<int, char, double>>::type, char>);
```

- **实例化爆炸与编译崩溃**（§1.3.4）：递归元函数若在"每层都做集合运算"
  （如并集/去重），实例数随输入组合式增长；MSVC/GCC 各有递归深度上限
  （`-ftemplate-depth`，默认 900 上下）。**这是本书与 Abrahams 书都郑重提醒的头号性能陷阱**，
  第 7 章拓扑排序的元函数设计直接受它约束。
- **短路与惰性**（§1.3.5）：`And_<true, L...>` 递归到第一个 false 即停，
  避免展开剩余分支——等价于运行期的 `&&` 短路；实现靠"多一层的特化"而非求值顺序。
→ 框架落点：`OperSeq_`（第 5 章运算序列）、`PolicySelector`（第 2/7 章 policy 查找）。

### 1.4 奇特的递归模板式（CRTP）

```cpp
// 🔧 已实测 g++ 15.2：CRTP 基类静态下转派生类型，零虚表
template <class D> struct Shape { double area() const { return static_cast<const D*>(this)->area_impl(); } };
struct Circle : Shape<Circle> { double r = 1; double area_impl() const { return 3.14159 * r * r; } };
static_assert(sizeof(Shape<int>) == 1);  // 无 vptr
```

CRTP 的本质：**构造期就知道最终类型**，把运行期虚分派提前为编译期名字查找。
书中定位是"静态多态的第一块基石"。注意 MetaNN 框架章里几乎不写裸 CRTP，
而是用它的推广形态——policy 基链（第 2 章）与 `OperOrganizer` 按类别特化（第 5 章），
思路上是"把'派生类作为参数'推广成'行为/标签作为参数'"。

## 权衡

| 维度 | 模板元函数路线 | 运行期路线（虚函数/std::function） |
| --- | --- | --- |
| 求值时机 | 编译期，结果烙进类型 | 运行期，可配置 |
| 错误报告 | 实例化错误（2018 年很刺耳；concepts 后好转） | 断言/异常，友好 |
| 编译成本 | 实例化爆炸风险（§1.3.4） | 无 |
| 产物 | 零开销抽象，可内联 | vptr/堆分配成本 |

## 最新演进与工业实践

- **if constexpr（C++17）** 让 §1.3 的"分支"多数不再需要特化：`if constexpr (std::is_integral_v<T>) ... else ...`，未选中分支不实例化，天然解决"两分支都被展开"问题。提案 [P0292R2](https://wg21.link/P0292R2)（wg21.link 实测 302）。书中"惰性求值包装"技巧在现代只在需要**类型级**分支（`using type = ...`）时仍不可替代。
- **折叠表达式（C++17）** 消灭 §1.3 的简单递归：`((Ts::value && ...) && true)` 一行就是带短路的 `And_`（短路是语言规定行为）。提案 [N3681](https://wg21.link/N3681)（实测 302）。
- **变量模板与 `_v`/`_t` 别名**（C++14/17）：书中 `Xxx_::value` 风格今天一律写作 `std::xxx_v`/`std::xxx_t`，GCC libstdc++ 全面提供。
- **concepts（C++20）** 取代 SFINAE 做"类型谓词"：约束子句就是布尔元函数的语言化，错误信息根治。谱系对照见 [../C++20模板元编程.md](../C++20模板元编程.md) 与 [../Effective_Modern_C++.md](../Effective_Modern_C++.md)。
- **工业实例**：fmt 库（[github.com/fmtlib/fmt](https://github.com/fmtlib/fmt)）核心分派即 `if constexpr` 链 + traits 萃取；Abseil/folly 的 `type_traits.h` 扩展（如 `absl::disjunction`）正是书中短路逻辑的工业同名物。Boost.Hana 证明了类型列表路线在 C++14 后完全可被 `constexpr` 数据结构取代。
- **本章复现**：类型列表 `TypeList` 的 Length/At/Append/transform 四个元函数在本机 `-std=gnu++23` 下编译运行通过，`transformL<AddCV>` 输出 `const int* const char* const double*`（g++ 15.2 实测）。
