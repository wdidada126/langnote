# 第 4 章 类型体系与基本数据类型——富类型的第一块地基

> 原书第 4 章（P76–118）。目录口径见 [../C++模板元编程实战.md](../C++模板元编程实战.md)。
> 总览见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

框架实现的第一章：**用标签把"是什么、在哪算"编码进类型**。
Scalar/Matrix/Batch 这些名字听起来平凡，但 MetaNN 的每个数据类都携带
类别标签（CategoryTags）、设备标签（DeviceTags）、元素类型三张"类型护照"，
后续章节的运算分派（第 5 章）、层装配（第 6/7 章）、求值优化（第 8 章）
全靠在这三张护照上做编译期查找。

## 核心概念速览（中英对照）

- **类型体系** — type taxonomy：以标签组织类型间的" isa/可转换/可运算"关系， STL 迭代器分类是其范本
- **标签** — tag：无成员的空类，纯类型身份（`CategoryTags::Matrix`、`DeviceTags::CPU`）
- **标签作模板参数** — tags as template arguments：把分类信息变成可分派的类型参数（tag dispatch 的推广）
- **类别标签** — CategoryTags：MetaNN 实测含 `Scalar/Matrix/BatchScalar/BatchMatrix` 四标签
- **设备标签** — DeviceTags：实测仅 `CPU`（GPU 为预留扩展点，见 §4.2.1）
- **标量** — Scalar：0 阶张量；类模板 + 按设备特化的双层结构（§4.3）
- **平凡矩阵** — trivial matrix（源码 `trival_matrix.h`，含单位矩阵）：对角占优的特殊存储矩阵
- **全零矩阵 / 独热向量** — zero matrix / one-hot vector：不占数据的"形状即信息"矩阵
- **批** — Batch：样本维打包（BatchScalar/BatchMatrix），§4.5.1
- **数组/重复** — Array / Repeating / Duplicate：批的生成与变换工具（`batch/array.h`、`batch/duplicate.h`）
- **浅拷贝与写操作检测** — shallow copy + write detection：数据句柄共享 + 写前独占检查（§4.2.3）
- **底层访问** — lower access（`lower_access.h`）：把任意矩阵降为"连续内存+步长"的统一视图

## 动机：STL 的_iterator_分类教会框架的事

§4.1.2 回顾 STL 迭代器五级分类（输入/输出/前向/双向/随机访问）：算法按**类别标签**
选实现（`advance` 对随机访问迭代器 O(1)、对前向 O(n)）。MetaNN 复刻这套语法：
`add(A, B)` 的维度检查、求值路径，按 `CategoryTags` 特化到 Scalar/Matrix/BatchMatrix
各走各的。与运行期 `if (dtype == ...)` 相比，标签方案把分发成本清零，且把
"不支持的组合"直接变成编译错误——这是"富类型"（把信息放进类型）的全部动机。

## 机制精讲

### 4.1 标签体系与配套元函数

实测源码 `MetaNN/data/facilities/tags.h` 全文只有两个结构体：

```cpp
// 🔧 摘自公开仓库 MetaNN-book（实测 200），标签=空类的嵌套声明
struct CategoryTags { struct Scalar; struct Matrix;
                      struct BatchScalar; struct BatchMatrix; };
struct DeviceTags   { struct CPU; };
```

配套的元函数在 `data/facilities/traits.h`：`CategoryOf_`/`DeviceOf_` 之类的萃取
（具体名以仓库为准 ⚠️ 本笔记按 §4.1.5 目录"与类型体系相关的元函数"转述），
约定是**每个数据类型自带 typedef**，萃取器只做转发——比自己写 `is_matrix` 特化快一个数量级的维护性。
§4.1.3 的"将标签作为模板参数"还有一层用意：标签是**开放的**，加 GPU 只需加
`struct GPU;` + 新特化，不动既有类型（开闭原则的类型层版本）。

### 4.2 六大设计理念（§4.2.1–4.2.6）

1. **设备/单元解耦**：数据只说"我在 CPU"，运算说"我支持 CPU"，匹配由 traits 做——为多设备留缝。
2. **存储分配**：`allocators.h` + `continuous_memory.h`，内存归"连续块+形状视图"，为 SIMD/缓存友好。
3. **浅拷贝+写检测**：拷贝构造只复制句柄（矩阵间大量共享底层块，如 Duplicate 生成的批）；
   写操作前检查引用计数/独占标志，非独占则先物化（copy-on-write 的框架内变体）。
   ⚠️ 具体检测机制（计数在哪层）未逐行读源码，此处按节题转述。
4. **底层接口扩展**：`LowerAccess`（实测 `lower_access.h` 存在，第 5 章 sigmoid 源码直接调用它拿
   `RawMemory()/RowLen()`）——所有 CPU 矩阵统一降维成"行主序块"，运算只写一次。
5. **类型转换与求值**（§4.2.5）：表达式→数据的转换挂接第 8 章求值模型。
6. **数据接口规范**：`RowNum()/ColNum()/BatchNum()` 等按类别提供，不同类别接口集不同——由标签保证不误用。

### 4.3–4.5 具体类型

- **Scalar**（§4.3）：`Scalar<T, Device>` 主模板 + CPU 特化"外壳/内核"两层——
  外壳管接口，特化管存储（实测 `data/scalar.h` 与 `data/matrices/cpu_matrix.h` 分文件）。
  等价骨架（机制转述，我的教学版）：

```cpp
// 🔧 示意（教学重写，非原书源码；结构对应实测文件分层）
template <class Elem, class Device> class Scalar;          // 主模板：只声明，误用即错
template <class Elem> class Scalar<Elem, DeviceTags::CPU>  // CPU 特化：真正的壳
    : ScalarStorageCPU<Elem> { public: /* RowNum 恒 1、Eval 等接口 */ };
```

  主模板**故意不给定义**：任何未实现设备的使用在实例化处编译失败——
  "接口在模板、实现在特化"的扩展点纪律贯穿全框架（矩阵/Batch 同构）。
- **Matrix**（§4.4）：`Matrix<T, Device>` 通用矩阵；**特殊矩阵是富类型的精彩处**：
  `TrivalMatrix`（单位/对角，O(n) 存储）、`ZeroMatrix`（只有形状）、`OneHotVector`
  （只有索引，交叉熵损失的标签就该这么存——第 6 章 NLL 层直接消费）。
  §4.4.3"引入新的矩阵类"演示加一个类需要动哪些扩展点（traits + LowerAccess + 运算特化）。
- **Batch**（§4.5）：`Batch<T, Device>` 给矩阵/标量加样本维；`Array` 是批的定长异构容器，
  `Repeating` 把单样本"虚拟复制"成批（零内存），`Duplicate` 做实际复制——
  三个模板把"训练时 batch 从哪来"讲透（实测 `batch/array.h`、`batch/duplicate.h`）。

## 权衡

富类型的税单：**类型爆炸**（类别×设备×元素类型每加一维，特化面翻一倍——所以
DeviceTags 只留 CPU 也是一种诚实）与**错误信息刺耳**（标签不匹配报的是几十层模板栈）。
收益是第 5–8 章的所有分派都变成"查类型"而不是"查对象"。与 [../STL源码剖析/03-迭代器与traits.md](../STL源码剖析/03-迭代器与traits.md)
同构：侯捷讲 traits 时说"萃取代替继承"，本章是同一课时的框架级作业。

## 相邻概念对比

- 标签体系 vs [../C++模板元编程/04-整型外覆器与布尔元编程.md](../C++模板元编程/04-整型外覆器与布尔元编程.md)：Abrahams 用外覆器携带整数值；MetaNN 用空类携带"身份"，两者共同构成"类型即数据"的两面。
- Batch/Duplicate vs PyTorch 广播（broadcasting）：torch 运行期推形状，MetaNN 把"有没有批维"编进类型（BatchMatrix vs Matrix 是两个类型，混用编译不过）。
- OneHotVector vs 现代 `nn.CrossEntropyLoss` 的整数标签张量：同一思想的两种存储方案。

## 最新演进与工业实践

- **C++26 `std::mdspan`（[P0009](https://wg21.link/P0009)，实测 302，C++23 收录）**
  与本章的"连续内存+形状视图"完全同题：mdspan 用**布局映射**（layout_right/layout_left/
  layout_stride）在类型层编码内存布局，`LowerAccess` 的"RawMemory+RowLen"可视为手写 layout_stride。
  读本章时请并行对照 mdspan：MetaNN 的标签体系解决"是什么布局"，mdspan 解决"怎么索引布局"。
- **类型体系 vs concepts**：MetaNN 的"每个类型自带 Category typedef"契约在 C++20 可写成
  `concept MatrixLike = requires { typename T::Category; ... }`，编译器直接验证扩展点（§4.4.3）是否齐全；
  2018 年只能靠"用到才报错"。
- **独热与稀疏**：`OneHotVector/ZeroMatrix` 是**编译期稀疏类型**，工业对应是 cuSPARSE、
  PyTorch `torch.sparse`（运行期稀疏）——富类型路线的优势是稀疏性参与重载决议，
  专属运算（如只读 one_hot 的 NLL 导数）可零分支特化。
- **xtensor**（[github.com/xtensor-stack/xtensor](https://github.com/xtensor-stack/xtensor)，实测存在）
  与本章最像的工业库：表达式模板 + 广播在类型层的 C++ 多维数组，`xexpression` 基类
  就是 CRTP 富类型。⚠️ 原书正文/后记是否点名 xtensor/Eigen 作对照未逐页核实，本条为笔记作者的横向补充。
