# 第 6 章 基本层——从"无状态运算"到"有状态可训练单元"

> 原书第 6 章（P148–184）。目录口径见 [../C++模板元编程实战.md](../C++模板元编程实战.md)。
> 总览见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

运算是纯函数，**层（Layer）是带参数、带梯度协议、带生命周期的训练单元**。
本章定义层的统一接口（构造→初始化→正向→反向→更新），把第 2 章的
policy/异类词典、第 4 章的 DynamicData 雏形组装成层的配置系统，
再用 AddLayer/ElementMulLayer/BiasLayer 三个具体层把接口"跑"给读者看。

## 核心概念速览（中英对照）

- **层** — layer：框架中"一次可复用计算+其参数/梯度"的封装单位（`layers/` 目录）
- **层对象构造** — layer construction：以 policy 容器 + 具名参数装配层类型（第 2 章技术的全量兑现）
- **参数矩阵** — parameter matrix：层内持久、参与训练的数据（区别于激活值）
- **参数初始化/加载** — parameter initialization / loading：filler 家族（constant/gaussian/uniform/var_scale，实测 `model_rel/param_initializer/`）
- **正向传播** — forward pass：层把输入表达式算成输出并缓存必要中间量
- **反向传播** — backward pass：层接收输出梯度、产出输入梯度与参数梯度
- **中间结果存储** — intermediate caching：正向存下反向要用的激活（如 sigmoid 的输出）
- **梯度收集** — gradient collection（实测 `model_rel/grad_col/grad_collector.h`）：多路径梯度汇聚
- **中性检测** — neutrality check：层"未起作用"（输入恒直通）时的跳过优化（§6.1.9）
- **DynamicData** — 动态数据壳（实测 `data/dynamic.h`）：类型擦除的矩阵持有器，参数/梯度的运行期容器
- **InjectPolicy** — 策略注入：外层 policy 灌入子层构造（`policies/inject_policy.h`）
- **通用 I/O 结构** — common I/O（实测 `layers/facilities/common_io.h`）：层间数据流通的标准端口类型
- **bias 层** — bias layer：按行广播加偏置，第一个"带参数"的完整层示例

## 动机：运算不够，层才够

`sigmoid(W*X+b)` 用第 5 章表达式写完就没了：W 存在哪？谁负责把 W 从文件读进来？
反向时 `dL/dW` 沿哪条路回到 W？这些问题的共同点是**跨越一次以上训练迭代**——
纯函数表达式没有"身份"和"记忆"，所以需要新抽象：层=**参数所有权的单元 + 梯度路由的节点**。
同时层必须能被第 7 章复合层无差别组合，于是接口（§6.1 的 9 个小节）先于实现被设计出来。

## 机制精讲

### 6.1 层的设计理念（九问式接口）

§6.1.1–6.1.9 实际是给层立"九个问题的标准答案"：怎么构造（具名参数+policy）、
参数怎么初始化/加载（filler 由 policy 选择）、正向怎么算（输出=表达式求值或 DynamicData）、
中间结果存不存、反向怎么给（输入梯度/参数梯度两路输出）、参数怎么更新（外部优化器写回）、
参数怎么获取（供保存/共享）、中性怎么检测（跳过整层的编译期+运行期优化）。
**每个答案都是一个扩展点**——第 7 章复合层把同样的九问答一遍，粒度换成"子层图"。

### 6.2 辅助机制四件套

1. **初始化模块**（§6.2.1）：`ParamInitrait`/filler 体系，policy 决定用哪个分布
   （var_scale filler 按 fan-in 缩放——Glorot 初始化的框架内名字，⚠️ 原书是否点名 Glorot 未核实）。
2. **DynamicData**（§6.2.2）：为什么需要类型擦除？因为**参数、梯度、优化器状态要放进
   同构容器**（vector），而它们的表达式类型各不相同。DynamicData 提供
   "求值并持有为具体 Matrix"的异步句柄语义（`data/dynamic.h` 实测存在）。
   这是全书"编译期世界↔运行期世界"的正式关口，另一半在第 8 章 eval 子系统。
3. **层的常用 policy 对象 + InjectPolicy**（§6.2.3–6.2.4）：预定义 policy 组合
   （训练性、共享名等）；InjectPolicy 让复合层的 policy 自动流到子层——
   第 2 章 PolicySelector 的复用。
4. **通用 I/O 结构与操作函数**（§6.2.5–6.2.6）：`LayerIO`（实测 compose 源码用到）、
   `Input/Output/Weight/Grad` 等端口标签 + 自由函数门面，层间连接全部说这门"普通话"。

### 6.3 三个具体层（机制转述 + 等价要点）

- **AddLayer**（§6.3.1）：两输入逐元素加，无参数——"中性"路径最多，展示反向的梯度直通。
- **ElementMulLayer**（§6.3.2）：逐元素乘，反向需要**缓存另一操作数**（中间结果存储的典型用例）。
- **BiasLayer**（§6.3.3）：第一个真参数层——`Input + Weight 广播`；反向中权重梯度是
  对样本维求和（折叠运算跨维归约的第 5 章伏笔在此兑现）。

三层的代码形态（据实测 `elementary/add_layer.h、bias_layer.h` 的接口签名转述）：
统一继承自带 policy 容器参数的模板基类，正向/反向各是一个模板成员函数，
对输入的具体类型全泛型——**层的实现只依赖端口的 traits 契约，不依赖第 4 章具体类**。
"九问"压成一份接口草图（教学重写，非原书源码）：

```cpp
// 🔧 示意：层协议的最小形状（对应 §6.1.1–6.1.9 的九问）
template <typename TPolicies>
struct BasicLayer {                            // 构造：policy 容器 + 具名参数（问1）
  template <class... Args> BasicLayer(Args&&...);
  auto EvalForward(In&& in);                   // 正向：输出=表达式/DynamicData（问4/5）
  auto EvalBackward(OutGrad&& g);              // 反向：输入梯度+参数梯度（问6）
  void LoadParams(Stream&);                    // 参数 I/O（问2/3/8）
  void UpdateGrad(DynamicData&& p_grad);       // 梯度归并到参数（问7）
  static constexpr bool IsNeutral(...) {...}   // 中性检测（问9）
};
// 注意成员全是模板：层不可当基类指针用——异质存放的缺口由第 7 章拓扑描述补上
```

### 6.4 已实现的基本层一览（§6.4）

实测 `layers/elementary/` 共九个：Abs/Add/Bias/ElementMul/Interpolate/Sigmoid/
Softmax/Tanh/Weight——前八个对应第 5 章同名运算的"有状态马甲"，
WeightLayer 是唯一"只产参数不做算术"的源层（filler 在此挂接）。
一个合理的读法：把这张表与 `operators/facilities/tags.h` 的运算表并排，
**每个可训练的点都是一个源层，每个计算点都自带导数马甲**（Sigmoid→SigmoidDerivative），
框架的"可微性"就是这两张表的乘积。

## 权衡

层接口用**模板成员函数**（编译期多态）而非虚函数，代价是层类型不可异质存放
（第 7 章复合层靠拓扑描述在编译期知道全部子层，绕开了这个问题）；
收益是正向图与反向图中的运算全部内联。DynamicData 的类型擦除则承认了
"有些边界必须运行期"——纯编译期方案在参数存储上没有收益（对象数量少、尺寸大，
虚一层无所谓），这是**按需选择静态/动态**的示范判断。

## 相邻概念对比

- 层 vs 运算：层有**身份**（名字/参数持久/可共享），运算表达式是匿名临时值。
- `Layer::operator()` 风格 vs PyTorch `Module.forward`：同为"callable 单元"，
  MetaNN 的层构造即定死类型（policy+描述），torch 的 Module 运行期 add 子模块。
- policy 选 filler vs 配置字典选 filler（yaml→运行期查表）：前者错填编译不过，后者可热换。

## 最新演进与工业实践

- **PyTorch ATen 代码生成对照**：torch 用 `derivatives.yaml` **声明**每个算子的导数，
  构建期 `tools/autograd/gen_variable_*` 生成 C++ 反向函数（VariableType 层）——
  与 MetaNN"每层手写反向"是同一工程的两种时点选择：**编译期手写 vs 构建期生成**。
  生成物本质仍是"把梯度路由写死进代码"，方向上验证了 MetaNN 的静态立场；
  而 pytorch 的 `TensorIterator`（`aten/src/ATen/native/TensorIterator.*`）解决广播
  混合精度分块，对位本章 bias 广播+第 5 章折叠的运算内核层（仓库实测存在）。
- **`register_backward_hook` / `torch.autograd.Function`** 是运行期版的"层协议九问"：
  forward/backward 成对、save_for_backward 存中间量（对位 §6.1.5）——概念可直接互译。
- **C++20/23 语境重述**：层的"端口契约"今天应写成 concepts（`ForwardLayer`/
  `BackwardLayer` 约束模板成员签名），把 §6.1 的接口纪律从文档搬进编译器；
  `std::expected`（C++23 标准库组件，提案链以 cppreference 记载为准）适合 DynamicData 求值失败的错误传播 ⚠️（书中用异常与否未核实）。
- **中性检测的现代对应**：torch.compile/Dynamo 的图简化会删掉恒等节点，XLA 有
  HLO 级 dead-code elimination——§6.1.9 的朴素想法在今天由图编译器代劳。
