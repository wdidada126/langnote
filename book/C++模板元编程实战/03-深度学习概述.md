# 第 3 章 深度学习概述——领域地图与 MetaNN 的定位

> 原书第 3 章（P63–75，第二部分开篇）。目录口径见 [../C++模板元编程实战.md](../C++模板元编程实战.md)。
> 总览见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

这是一章"领域补课"：作者假定读者熟悉 C++ 但未必熟悉深度学习，于是用一章篇幅
把神经网络、训练循环和深度学习系统的组织方式讲清，再引出本书的靶子——
**MetaNN：一个以模板元编程/编译期计算为主轴的深度学习框架原型**，
并明确声明本书"不会涉及的主题"（CUDA 内核、分布式训练等）。

## 核心概念速览（中英对照）

- **机器学习到深度学习** — from ML to DL：以表示学习取代人工特征工程的范式迁移
- **人工神经网络** — artificial neural network (ANN)：分层堆叠的"线性变换+非线性激活"可微函数族
- **前向传播** — forward propagation：输入沿层序计算出预测值
- **反向传播** — backward propagation / backprop：依链式法则从损失回传各参数梯度
- **梯度下降** — gradient descent：沿负梯度更新参数；SGD/Adam 等变体
- **损失函数** — loss function：如交叉熵负对数似然（NLL），MetaNN 有专层实现
- **计算图** — computation graph：把模型表达为张量运算的有向图；静态图/动态图两流派
- **张量** — tensor：框架中的多维数组抽象；MetaNN 以 Scalar/Matrix/Batch 三级实现
- **富类型** — rich types：把设备/类别/元素类型等信息编码进类型系统的类型设计风格（第 4 章展开）
- **编译期计算** — compile-time computation：本书框架区别于主流（面向对象运行期）框架的立身点

## 动机：为什么用"元编程"做深度学习框架

2018 年的主流框架（TF 1.x/PyTorch/Caffe2/Theano）共同点是：**运行期对象模型**——
Layer 是虚基类、Tensor 是带 dtype/device 枚举的堆对象、autograd 是运行期建 tape。
这套抽象灵活，但每层付出虚分派、动态类型检查、运行期维度检查的代价，
且"模型结构"要到运行期才成形。作者的赌注是：**神经网络在训练开始前就完全已知**
（结构、类型、连接），既然如此，为什么不让它在编译期成形？模板元编程提供
"类型级编程"能力，表达式模板提供"运算延迟/融合"能力——这正是前两章技术储备的用武之地。
这个立场在 §3.2.4"本书不会涉及的主题"里被刻意收窄：MetaNN 是**研究性原型**，
不追 GPU kernel、分布式与成熟 API，只回答"元编程路线能把静态架构做到什么程度"。

## 机制精讲（领域部分转述 + 框架定位）

### 3.1 深度学习三部曲

§3.1.1–3.1.2 的脉络（按公开共识转述）：特征工程 → 表示学习（深度信念网络 2006 破局）→
GPU 时代的 CNN/RNN/LSTM；激活函数（sigmoid/tanh/ReLU）、Softmax 分类头、
交叉熵损失——**本书第 5 章的每个运算模板、第 6 章的每层，都能在此找到对应物**：
Sigmoid/Tanh/Softmax/Abs 是一元运算，Add/ElementMul/Dot 是二元运算，
NLL 是损失层，GRU 是循环层。数学细节（如 softmax 数值稳定化）原书从简，
本笔记也不复述；关键是记住：**训练 = 前向 + 反向 + 更新** 的循环，
框架的全部复杂度都来自"如何组织这张可微计算图"。

把训练循环展开成伪代码，框架要承包的环节一目了然：

```text
for epoch in epochs:
  for batch in data:                      # 第 4 章 Batch/Array 的地盘
    pred = forward(model, batch)          # 第 5 章表达式 + 第 6/7 章层
    loss = NLL(pred, onehot(label))       # 第 4 章 OneHotVector 的用武地
    backward(loss)                        # 第 6/7 章反向协议/梯度收集
    optimizer.update(params, grads)       # 第 6 章参数获取/更新接口
```

MetaNN 的每个模块都在为这张五行循环的**某一格**提供编译期实现——
读第 4–8 章时随时回来对照这五行的哪一格。

§3.1.3"深度学习系统的组织与训练"还立了一个分类坐标：**按计算图确定的时机**
分静态图（先建图后喂数，TF 1.x/Theano 路线）与动态图（边算边建，PyTorch 路线）。
MetaNN 把这条线推到极限，成为第三类：**图在建对象之前就已确定——在编译期**；
"训练一次"对应"编译一次程序 + 运行期只换数据"。这个定位是理解全书
一切设计（拓扑排序是元函数、运算是特化、连接是模板参数）的钥匙。

### 3.2 MetaNN 的切片

- **从矩阵工具到框架**（§3.2.1）：MetaNN 由作者早年更小的矩阵库演化而来（仓库
  [liwei-cpp/MetaNN](https://github.com/liwei-cpp/MetaNN) 实测存在，最后提交 2021-01），
  所以它的类型体系（第 4 章）带着"矩阵库血统"：数据先行，层与图后置。
- **五层模块**（据 §3.2.2 + 公开源码目录实测）：`data/`（标量/矩阵/Batch）、
  `operators/`（表达式模板运算）、`layers/`（elementary/compose/recurrent）、
  `model_rel/`（参数初始化 filler、梯度收集）、`evaluate/`（求值子系统）。
  目录树逐文件核实于 MetaNN-book 分支，与本笔记第 4–8 章一一对应。
- **边界声明**（§3.2.4）：不讨论反向传播数学推导的完备性、不做 GPU 代码、
  API 不求易用——读第 4–8 章时请把这当作"实验条件"。

## 权衡

| 维度 | MetaNN（编译期静态架构） | 主流框架（运行期对象架构） |
| --- | --- | --- |
| 结构定义时机 | 类型声明即模型，编译完成模型已"跑通"于类型层 | 运行期 add() 拼装，可随时改 |
| 错误发现 | 维度/类型错配尽量编译期拦截 | 运行期异常，报错栈深 |
| 灵活性 | 换结构=重编译；调试看模板错误 | 交互式、可热改 |
| 优化空间 | 编译期可见全图→融合/去冗余（第 8 章） | 需 trace/graph 捕获（今天的 torch.compile 才补上） |
| 团队规模适配 | 元编程门槛高，2018 时点错误信息可读性差 | 工程主流 |

作者的诚实之处在于 §5.8"运算的折衷与局限性"与本章的"不涉及"清单——
它没有声称元编程路线全面优于面向对象路线，而是给出了一个**可对照的样本**。

## 最新演进与工业实践

- **自动微分四形态的权威分类**出自 Baydin 等的综述（A. G. Baydin, B. A. Pearlmutter,
  A. A. Radul, J. M. Siskind, *Automatic Differentiation in Machine Learning: a Survey*，
  JMLR 18(153):1–41, 2018；通行引文口径）。**DOI 核实结果**：Crossref 未收录该文 DOI
  （JMLR 不在 Crossref 注册 ⚠️，其官方页面 v18/16-465.html 本次实测 404 ⚠️）；
  arXiv 副本可核：[10.48550/arXiv.1502.05767](https://doi.org/10.48550/arXiv.1502.05767)
  （doi.org 实测解析至 arxiv.org/abs/1502.05767）。综述区分**源到源变换、前向模式、
  反向模式、操作符重载**四类——MetaNN 属"操作符重载 + 编译期图"混合体。
- **操作符重载式 AD 的现代旗舰是 JAX**（[github.com/jax-ml/jax](https://github.com/jax-ml/jax)，
  实测存在；原 google/jax 已重定向）：`jax.grad` 用追踪(tracing)+函数变换实现前向/反向，
  可微分地层层叠加、vmap 自动并行——与 MetaNN"每个运算都参与编译期组合"的哲学同源，
  只是发生在 Python 追踪层而非 C++ 类型层。
- **源到源 AD 的工业代表是 Enzyme**（[github.com/EnzymeAD/Enzyme](https://github.com/EnzymeAD/Enzyme)，
  实测存在）：直接在 LLVM IR 上生成梯度代码，无需重写框架——这是对"用模板手工内联
  导数"（MetaNN 为每个运算手写 `SigmoidDerivative`）的最强反命题：编译器替你求导。
- **"编译期已知全图"的当代胜利**：TF2 的 XLA、`torch.compile`(TorchDynamo+Inductor) 走的
  正是"先捕获/追踪图、再编译融合"路线——MetaNN 第 8 章的"避免重复计算/同类合并"
  在工业界以图编译器形态复活。差异在捕获手段：MetaNN 用类型系统，工业界用 trace + JIT。
- **经典论文之外**：GRU（Chung et al., *Empirical Evaluation of Gated Recurrent Neural
  Networks on Sequence Modeling*, 2014）与 LSTM 是第 7 章 RecurrentLayer 的领域蓝本；
  引文年份以 arXiv 1412.3555 口径记 ⚠️（本次未做 Crossref 实测）。
