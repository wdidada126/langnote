## 核心精讲
设计原则：能用组合就不用继承；「包装/代理」类把操作转发给内含对象，扩展行为而不改其类。

```
教学示意，不参与构建
class Wrapper:
    def __init__(self, obj):
        self._obj = obj
    def __getattr__(self, name):     # 未定义属性转发给内含对象
        return getattr(self._obj, name)
```

- 多继承适合「mixin」：小而无状态的横切能力（如日志、序列化）；深层继承树脆弱。
- 3.x 方法统一是「绑定函数对象」，少了很多 2.x 的 `unbound method` 区分。

## 版本演进
- 3.x 删除「未绑定方法」概念，方法就是函数（`isinstance(f, types.FunctionType)`）。
- 3.8 `Protocol`（PEP 544）做结构化子类，弱化显式继承。

## 经典论文与原始文献
- *Design Patterns*（GoF）：组合、代理、装饰器模式（工程共识）。
- PEP 544 *Protocols*（3.8）。

## 近年研究与工业界开源实践（2015–2026）
- `typing.Protocol` 让「鸭子类型」可被类型检查器验证；`abc` 定义抽象基类。
- `dataclass` + 组合替代大量手写包装类。

## 常见误区与本书需修正之处
| 误区 | 修正 |
| --- | --- |
| 深层继承复用代码 | 改组合/mixin，避免 MRO 陷阱 |
| 用 `__getattr__` 做日常属性 | 仅用于转发/兜底；常规用普通属性，否则影响性能与清晰度 |
| 多继承随意 | 仅 mixin 横切；主关系用单继承 |
