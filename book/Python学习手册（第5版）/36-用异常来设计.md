## 核心精讲
设计原则：错误尽早抛（靠近源头、带上下文），在能处理的地方捕；顶层做兜底日志。3.11 `except*` 可一次处理「多个异常」的异常组。

```
教学示意，不参与构建
# 3.11：并发任务可能各自失败
def run_all(tasks):
    errors = []
    for t in tasks:
        try:
            t()
        except Exception as e:
            errors.append(e)
    if errors:
        raise ExceptionGroup("task failures", errors)
try:
    run_all([a, b, c])
except* ValueError as eg:        # 只处理其中的 ValueError
    print(eg.exceptions)
```

- 顶层不应让异常直接冒泡到用户；记录日志后转成友好提示。
- 不要为「可预期的正常分支」滥用异常（见 [33-异常基础](33-异常基础.md)）。

## 版本演进
- 3.11 `ExceptionGroup` + `except*`（PEP 654）适配并发/批量场景。
- 3.x `contextlib.suppress` 简洁忽略已知异常。

## 常见误区与本书需修正之处
| 误区 | 修正 |
| --- | --- |
| 顶层不处理异常 | 至少顶层 `try` 记录日志并转友好信息 |
| 用异常做返回值 | 异常是异常路径；常规结果用返回值/Optional |
| 忽略 `ExceptionGroup` | 3.11+ 并发多错用 `except*` 分别处理 |
