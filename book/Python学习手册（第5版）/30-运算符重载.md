## 核心精讲
定义 `__add__` 等方法让自定义对象支持 `+`、索引、比较等原生语法。

```
教学示意，不参与构建
class Vec:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __add__(self, o):
        return Vec(self.x + o.x, self.y + o.y)
    def __eq__(self, o):
        return (self.x, self.y) == (o.x, o.y)
    def __repr__(self):
        return f"Vec({self.x},{self.y})"
```

- 容器类实现 `__getitem__`/`__len__`/`__iter__`（见 [09-元组文件及其他](09-元组文件及其他.md)）。
- 比较可用 `functools.total_ordering`（定义少量方法自动补其余）。

## 版本演进
- 3.x 删除 2.x 的 `__cmp__`；靠富比较 `__lt__`/`__eq__` 等。
- 3.4 `@functools.total_ordering` 稳定。
- 3.x 矩阵乘法 `__matmul__`（PEP 465，3.5）供 NumPy 类使用。

## 近年研究与工业界开源实践（2015–2026）
- NumPy/Pandas 大量重载运算符与 `[]` 切片；`__eq__` 与 `@dataclass(eq=True)` 自动生成。
- `typing` 对重载返回类型（如 `__add__` 返回 `Self`）支持（`Self` 3.11）。

## 常见误区与本书需修正之处
| 误区 | 修正 |
| --- | --- |
| 用 `__cmp__` | 3.x 已删；用富比较或 `@total_ordering` |
| 重载所有运算符 | 只重载语义自然者；否则显式方法更清晰 |
| 忘记 `__eq__` 影响哈希 | 定义 `__eq__` 后默认 `__hash__` 失效（实例不可再哈希），需显式定义或设 `unsafe_hash` |
