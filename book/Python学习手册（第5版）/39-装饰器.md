## 核心精讲
装饰器 `@deco` 等价于 `f = deco(f)`，在不改原函数代码的前提下增强其行为。务必用 `functools.wraps` 保留元信息。

```
教学示意，不参与构建
import functools, time
def timing(f):
    @functools.wraps(f)
    def wrapper(*args, **kw):
        t = time.perf_counter()
        r = f(*args, **kw)
        print(f"{f.__name__}: {time.perf_counter()-t:.4f}s")
        return r
    return wrapper
@timing
def slow():
    time.sleep(0.1)
```

- 类装饰器返回新类，常用于注册/增强（如 `@dataclass` 本身就是类装饰器）。
- 3.9 `functools.cache` 比 `lru_cache(maxsize=None)` 更直白（见 [19-函数的高级话题](19-函数的高级话题.md)）。

## 常见误区与本书需修正之处
| 误区 | 修正 |
| --- | --- |
| 装饰器不写 `@wraps` | 会丢失 `__name__`/`__doc__`，破坏日志/类型/测试 |
| 装饰器做重活 | 装饰发生在 import 时，避免耗时/副作用 |
| 过度嵌套装饰器 | 多层包裹难调试；必要时拆为显式包装 |
