## 核心精讲
包是含 `__init__.py` 的目录；`from . import sibling` 做相对导入，避免硬编码顶层名。

```
教学示意，不参与构建
# mypkg/__init__.py, mypkg/a.py, mypkg/b.py
# 在 b.py 中：
from .a import helper          # 相对导入同包
from . import a                # 导入同包模块
```

- 3.3 命名空间包（PEP 420）：可跨多目录合并、无需 `__init__.py`，利于大项目/分发。
- 隐式相对导入（`import sibling`）在 3.x 已删除，必须显式 `from . import`。

## 版本演进
- 3.3 命名空间包（PEP 420）。
- 3.4 删除隐式相对导入，统一绝对/显式相对。
- 3.x `pkgutil.iter_modules`/`importlib` 遍历包内模块。

## 经典论文与原始文献
- PEP 420 *Implicit Namespace Packages*（3.3）。
- 官方 *Reference*「The import system — Packages」。

## 近年研究与工业界开源实践（2015–2026）
- 现代打包用 `src/` 布局 + `pyproject.toml`（PEP 517/518），避免意外导入工作区副本。
- `importlib.resources` 访问包数据。

## 常见误区与本书需修正之处
| 误区 | 修正 |
| --- | --- |
| 用隐式相对导入 `import a` | 3.x 语法错误；写 `from . import a` |
| 命名空间包需 `__init__.py` | PEP 420 下可不用，但显式 `__init__` 仍有导出控制价值 |
| 工作区文件被误当作包 | 用 `src/` 布局隔离，避免 `pip install -e .` 装到源码目录 |
