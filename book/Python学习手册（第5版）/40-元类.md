## 核心精讲
元类是「创建类的类」：默认 `type`；自定义元类在类创建时介入（如注册、强制接口、改写属性）。

```
教学示意，不参与构建
class RegMeta(type):
    registry = {}
    def __new__(mcs, name, bases, ns):
        cls = super().__new__(mcs, name, bases, ns)
        RegMeta.registry[name] = cls
        return cls
class Plugin(metaclass=RegMeta):
    pass
```

- 3.6 `__init_subclass__`（PEP 487）让基类在子类定义时收到钩子，多数「轻量元类」场景可免元类。
- 业务代码几乎不需要元类；框架（ORM、序列化、DI）才用。

## 版本演进
- 3.6 `__init_subclass__`（PEP 487）大幅减少元类需求。
- 3.x `type(name, bases, ns)` 仍是动态建类底层；`types.new_class` 辅助。
- 3.12 PEP 695 `type` 参数语法不影响元类本质。

## 近年研究与工业界开源实践（2015–2026）
- `pydantic`/`attrs`/`SQLAlchemy` 用 `__init_subclass__`/描述符而非裸元类。
- ABC（`abc.ABCMeta`）是最常见元类用途：定义抽象基类。

## 常见误区与本书需修正之处
| 误区 | 修正 |
| --- | --- |
| 一上来用元类 | 先用 `@dataclass`/`__init_subclass__`/装饰器，万不得已才元类 |
| 元类做运行期逻辑 | 元类作用于「类定义时」，运行期逻辑应放实例/方法 |
| 忽视 `super().__new__` | 自定义元类必须正确委托，否则类创建失败 |
