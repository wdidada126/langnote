# 概念专篇：描述符与属性管理

> 第 38 章延伸。描述符是 Python 属性访问的底层协议，是 `@property`、`dataclasses`、ORM 的基石。

## 描述符协议
一个类只要实现 `__get__`（及可选 `__set__`/`__delete__`），其实例作为**类属性**时即成为描述符，拦截对该属性的访问。

```
教学示意，不参与构建
class Validated:
    def __init__(self, name):
        self.name = name
    def __get__(self, obj, owner):
        return obj.__dict__[self.name]
    def __set__(self, obj, value):
        if value < 0:
            raise ValueError("需非负")
        obj.__dict__[self.name] = value

class C:
    x = Validated("x")     # 类属性是描述符实例
```

## 优先级（数据/非数据描述符）
- **数据描述符**（定义了 `__set__`）优先于实例字典。
- **非数据描述符**（只有 `__get__`，如函数/方法）在被实例字典遮蔽时退居其后。
- 这与 [29-类代码细节](../29-类代码细节.md) 的属性查找层级一致。

## 与 `@property` 的关系
`@property` 本质是用描述符实现的便捷语法（读/写/删三个方法包装成属性）。需要**跨多个属性复用同一逻辑**时，直接写描述符类更合适。

## 现代替代
- 3.7 `@dataclass` + `field`/`__post_init__`（PEP 557）覆盖大多数「带校验的字段」。
- `pydantic`/`attrs` 内部用描述符做声明式校验与默认值。
- 3.8 `functools.cached_property` 缓存首次访问结果。

## 版本演进
- 3.6 `__set_name__`（PEP 487）让描述符在类体执行时拿到自己的名字（无需手动传 `name`）。
- 3.7 `dataclasses`（PEP 557）；3.9 `functools.cache_property`。
