## 核心精讲（一）：四个 Lab 的设计要点

> ⚠️ **本目录不提供任何可抄的 Lab 源码，也不链接公开解答仓库。**
> 下面只给**设计要点、状态机形状、失败模式**——这是课程本身也强调的学术诚信前提。
> 网上有大量解答仓库（这是公开的事实），但抄写代码会让你失去这门课唯一不可替代的收获：
> **亲手把「不确定」变成「确定」的过程**。

### 13.1 Lab 1：MapReduce

| 维度 | 要点 |
| --- | --- |
| 核心难点 | **任务状态机 + 超时重做 + 输出原子发布** |
| 状态机 | `Idle → InProgress → Completed`；只有 `Completed` 是终态，`InProgress` 超时则回退到 `Idle` |
| 并发纪律 | 所有共享状态由**单一保护者**（一把锁或一个 goroutine 串行化处理）持有；参考 [05-Go线程与Raft导论.md](05-Go线程与Raft导论.md) |
| 原子发布 | worker 先写临时文件，完成后 `rename`（重命名在同一文件系统内是原子的）→ 半成品不可见 |
| 常见坑 | 重做的前提是 map/reduce **确定性**；worker 领取任务与标记完成之间不能有窗口 |

### 13.2 Lab 2：Raft（2A 选举 / 2B 日志 / 2C 持久化）

| 维度 | 要点 |
| --- | --- |
| 核心难点 | **任期 + 投票 + 一致性检查 + 提交规则 + 持久化时机** |
| 2A | 选举超时随机化；收到更高 term 立即退回 follower；心跳压制选举 |
| 2B | `AppendEntries` 的 `prevLogIndex/prevLogTerm` 一致性检查；冲突回退；**提交必须要求 `entry.Term == currentTerm`**（见 [06-容错Raft一.md](06-容错Raft一.md) 的 Figure 8） |
| 2C | `currentTerm`、`votedFor`、`log[]` **在回复 RPC 前落盘** |
| 常见坑 | 持锁期间发 RPC（死锁/吞吐崩）；提交条件漏掉任期检查；选举限制写成「只看 index 不看 term」 |
| 调试顺序 | 2A 单测 → 2B 无故障 → 2B 加故障 → 2C 加崩溃重启（**按这个顺序，不要跳**） |

### 13.3 Lab 3：KV Raft

| 维度 | 要点 |
| --- | --- |
| 核心难点 | **重复请求去重（session + 序号）+ 读的线性一致性** |
| 去重表 | 必须**在状态机里**（随日志复制），否则 leader 切换后失效；参考 [08-ZooKeeper.md](08-ZooKeeper.md) |
| 写路径 | 客户端请求 → Raft 提交 → 应用状态机时才真正执行 → 回复（**只有 leader 能回复**） |
| 读路径 | 不能「直接读本地状态机」，否则被隔离的旧 leader 会返回陈旧数据；至少要做 ReadIndex（[07-容错Raft二.md](07-容错Raft二.md)） |
| 常见坑 | 应用到状态机与回复客户端的顺序；去重表未按序号单调推进；leader 变更后客户端的重试风暴 |

### 13.4 Lab 4：Sharded KV

| 维度 | 要点 |
| --- | --- |
| 核心难点 | **分片迁移的原子性与幂等性**（本质是成员变更的工程版） |
| 权威来源 | 「谁服务哪个分片」必须有**唯一权威**（配置 + 配置版本），任何时刻只有一个 group 服务一个分片 |
| 幂等 | 迁移数据、删除旧分片、更新配置三步都要能重复执行而不改变结果 |
| 客户端 | 收到「我不服务这个分片」时必须**按配置重试**，而不是一直重试同一台 |
| 常见坑 | 配置版本回退（旧配置消息迟到）；迁移中又发生新配置变更；垃圾分片残留 |

### 13.5 调试方法论（比答案更重要）

| 手段 | 解决什么 | 出处 |
| --- | --- | --- |
| `go test -race` | 数据竞争 | [05-Go线程与Raft导论.md](05-Go线程与Raft导论.md) |
| **大量重复运行**（如 `-count=100`） | 低概率时序 bug；`-race` 只发现「本次真的发生过」的竞争 | 课程实践 |
| 确定性仿真（固定随机种子 / 模拟时钟网络） | 让「偶发失败」可复现 | `madsim` 一类工具的思想 |
| 缩小范围（二分注释 / 减小集群规模） | 定位是哪一轮交互出错 | 通用 |
| 打日志要有 term/index/角色/时间 | 否则日志看不出因果 | 课程建议 |
| Jepsen 式的一致性检验 | 验证「你声称的一致性是否真的成立」 | `jepsen-io/jepsen` |

### 13.6 自查清单（每个 Lab 交付前过一遍）

| # | 检查项 | 不通过时的典型症状 |
| --- | --- | --- |
| 1 | 所有共享状态是否只有一个明确的保护者？ | `-race` 报错 / 偶发结果错乱 |
| 2 | 「判断 + 修改」是否在同一次持锁内完成？ | 极低频的重复执行 |
| 3 | 是否在持锁期间做了 RPC 或磁盘 I/O？ | 吞吐崩塌、偶发死锁 |
| 4 | 对外可见的效果是否发生在「确定之后」？ | 崩溃后出现「主说有、备说没有」 |
| 5 | 所有会改变持久状态的操作是否「先落盘再回复」？ | 重启后状态回退 |
| 6 | 提交/应用的条件是否包含必要的任期或版本检查？ | 已提交数据被覆盖 |
| 7 | 每条消息/每次迁移是否可重复执行而不改变结果？ | 重复请求造成数据翻倍 |
| 8 | 是否跑过 `-race` + 至少上百次重复 + 故障注入？ | 「本地能过、CI 挂」 |

## 版本演进：6.824 → 6.5840

- **编号变更**：MIT EECS 自 **2022 年秋**起启用四位编号（6.xxx → 6.xxx0），
  官方 "Subject numbering" 页有完整说明；分布式系统课因此由 **6.824** 变为 **6.5840**。
  这也解释了为什么 2020 的旧链接与「6.824」标题仍到处可见。
- **Lab 数量**：2020 是 4 个（MapReduce / Raft / KV Raft / Sharded KV）；
  6.5840 2026 是 **5 个**（新增 **Lab 2: Key/Value server**，Raft 顺延为 Lab 3）。
- **Raft 内容的实验编号错位**：2020 的 Raft 是 Lab 2（2A/2B/2C），2026 是 Lab 3（3A–3D）。
  **按 2020 资料做 2026 的实验（或反过来）时，务必先确认编号与子任务划分**。
- **讲次轮换**（以 2026 官方页为准，官方自述为 tentative）：
  - 新增：**Paxos** 独立讲、**Chain Replication (CR 2004)**、**IronFleet 形式化验证**、**Ray**、**AWS Lambda / 按需容器加载**、**BFT/PBFT**；
  - 2020 有而 2026 未见：**Aurora**、**Frangipani**、**COPS**、**Blockstack**、**Spark**、**AnalogicFS**（可能年度轮换）。
- **不变的部分**：GFS、Raft（两讲）、ZooKeeper、Spanner、FaRM、Memcached、Bitcoin、SUNDR 仍在；
  四个（五个）Lab 的骨架精神不变。

## 近年研究与工业界开源实践（2015–2026）

- **验证与测试成为一等公民**：共识/事务实现只靠单测远远不够；
  2026 的门槛是 **`-race` + 确定性仿真 + 一致性检验（Jepsen 式）** 三件套。
- **确定性仿真**：把时钟、网络、磁盘变成可控输入，让「跑一万次才出现一次」的 bug 变得可复现。
- **形式化方法走向实用**：TLA+ 用于设计阶段、Dafny/Coq 用于实现级证明，
  已不只是学术演示（IronFleet 是标志，6.5840 已把它纳入课程）。
- **工业界开源（star 数 2026-09-26 `gh api` 实测）**：
  - `jepsen-io/jepsen`（**7504★**）：一致性检验框架，测过几乎所有主流数据库。
  - `madsim-rs/madsim`（**1161★**）：Rust 确定性仿真器（模拟网络/时钟/磁盘），
    把分布式系统跑成可复现测试。
  - `apple/foundationdb`（**16731★**）：确定性模拟测试的工业标杆。
  - `etcd-io/etcd`（**52310★**）、`tikv/tikv`（**16878★**）：生产级共识实现，
    它们的测试套件（含故障注入）本身就是学习材料。
  - `apache/zookeeper`（**12811★**）：L8 的实现本体。

## 常见误区与本课程需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「抄一份网上解答就能过 Lab」 | 能过测试，但学不到东西；且不同年份的 Lab 接口与子任务划分已变化 |
| 2 | 「测试通过 = 实现正确」 | 分布式 bug 多为低概率时序问题；必须 `-race` + 大量重复 + 故障注入 |
| 3 | 「-race 没报就没有竞争」 | 只覆盖本次执行的路径（[05-Go线程与Raft导论.md](05-Go线程与Raft导论.md)） |
| 4 | 「Raft 论文读完就能实现」 | 论文没写清的部分（成员变更、PreVote、learner、快照工程）恰恰是实现的全部难点 |
| 5 | 「6.824 的 Lab 编号一直没变」 | 6.5840 已把 Raft 从 Lab 2 挪到 Lab 3，并新增 Key/Value server（Lab 2） |
| 6 | 🔧 2020 课程未覆盖 | **确定性仿真测试**：2020 只强调 `-race` 与重复跑；2026 应把它作为标准手段 |
| 7 | 🔧 2020 课程未覆盖 | **形式化验证**（TLA+/Dafny）：课程在 2020 不讲，6.5840 2026 已单列 IronFleet 一讲 |
| 8 | 🔧 2020 课程未覆盖 | **一致性检验（Jepsen 式）**：2020 未出现，2026 是「声称强一致」系统的入场券 |
| 9 | 🔧 2020 课程未覆盖 | **讲次轮换带来的资料错配**：网上大量「6.824 笔记」对应不同年份；读之前先核对 schedule 年份与 Lab 编号 |
