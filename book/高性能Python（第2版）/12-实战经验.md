## 核心精讲

本章是案例集，提炼可复用原则：

**1. 先有基准，再谈优化。** 没有可复现基准的「优化」迟早翻车；用第 2 章工具链建立 CI 基准回归。

**2. 瓶颈常在边界。** 多数性能问题不在算法，而在序列化、IPC、网络往返、内存拷贝（第 2/6/11 章）。先用剖析定位，再动手。

**3. 分层加速。** 用 Python 写编排与业务逻辑，把 5% 热点交编译扩展（第 7 章）/向量化（第 6 章）/多进程（第 9 章）。不要为了 5% 把 95% 代码写成 C。

**4. 生产化纪律。** Docker 固化环境、监控真实 P99（非平均）、保留回滚。性能优化的价值由线上指标定义。

**5. 何时不优化。** 「过早优化是万恶之源」——先保证正确与可维护，热点出现再针对性处理（80/20）。

## 版本演进

- 原书 2020 案例偏「单服务 + Celery」。2026 主流是「云原生 + 弹性 + 可观测」：OpenTelemetry 追踪、KEDA 弹性、向量化/编译内核。原则不变，工具升级。
- 3.11+「Faster CPython」让「纯 Python 热点」自动变快，部分旧优化可删除（保持代码简单）。

## 近年研究与工业界开源实践（2015–2026）

- 性能工程融入 SRE：SLO/P99 驱动优化，而非微基准。

## 常见误区与本书需修正之处

- 误：照搬书中某公司的参数/配置——硬件与依赖已变，参数需本地重测。
- 误：把「单核微基准」的结论直接外推到分布式系统；并行有阿姆达尔/古斯塔夫森定律上限。
- 🔧 原书未覆盖 OpenTelemetry / 弹性伸缩等现代生产性能工程，应补到「版本演进/工具」。
