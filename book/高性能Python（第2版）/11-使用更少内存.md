# 11 使用更少内存

> 原书 pp. 341–392（英文 2e；中文版页码以实体书为准 🔧）

## 本章地图

| 节 | 内容 | 结论 |
|---|---|---|
| 对象开销 | PyObject 头 | 每个对象都有固定成本 |
| __slots__ | 去 __dict__ | 类实例省大内存 |
| array / 定长类型 | 紧凑数组 | 同类型用 array 省 |
| memoryview / buffer | 零拷贝 | 切片不复制 |
| 稀疏结构 | 只存非零 | 稀疏数据别用稠密 |
| 生成器 | 惰性 | 不物化整序列（见第 5 章） |

## 核心精讲

**1. 对象头开销。** CPython 每个对象带引用计数、类型指针、大小字段（通常 16–24 字节 + GC 跟踪）。百万级小对象（如大量小 dict/对象）内存爆炸的主因。

**2. `__slots__`。** 默认实例用 `__dict__`（又是哈希表）；声明 `__slots__` 后实例用固定元组存属性，去掉 `__dict__` 与 `__weakref__`，内存与访问双收益（对象多时显著）。

```python
# 教学示意，不参与构建
class Point:
    __slots__ = ("x", "y")   # 不再有 __dict__
    def __init__(self, x, y):
        self.x, self.y = x, y
```

**3. array 模块 / 定长类型。** `array.array("i", ...)` 是同类型连续定长数组，比 `list[int]` 省很多；`struct` 做二进制布局。

**4. memoryview / buffer protocol。** 视图不拷贝底层缓冲，对大字节串/NumPy 数组做「切片」零拷贝，避免复制整个 blob。

**5. 稀疏结构。** 稀疏矩阵/图用字典或专用库（scipy.sparse）只存非零，远省于稠密 `list`/`ndarray`。

## 版本演进

- 3.3 起 `memoryview` 支持 `cast` 重塑；buffer protocol 持续演进。
- 3.4 起 `enum`、3.7 起 `dataclasses`（`@dataclass(slots=True)` 在 3.10 起可生成 `__slots__`，3.11+ 更完善）成为「省内存 + 可读」的现代替代。
- 3.11 起「更紧凑对象」：`dict` 小字典、 frame 对象更小；3.12 起子解释器隔离更省跨解释器复制。
- 标准库 `sys.getsizeof` + `tracemalloc`（第 2 章）做内存剖析。

## 近年研究与工业界开源实践（2015–2026）

- 工业界大数据用 Arrow 格式（零拷贝跨语言）、Polars/DataFrame 列式存储天然紧凑。
- `msgspec` / `orjson` 等用 `__slots__`/slots 思想做高性能（反）序列化。
- 大实例集（如 Web 请求对象池）广泛用 `@dataclass(slots=True)`。

## 常见误区与本书需修正之处

- 🔧 误：原书写 `__slots__` 时 dataclass(slots=True) 尚未出现；2026 应优先用 `@dataclass(slots=True)` 兼得可读与省内存。
- 误：`__slots__` 不能动态加属性，且继承链每个类都要声明，否则部分实例仍有 `__dict__`。
- 误：以为「小对象用 tuple 就够」——tuple 不可变，频繁改状态的对象仍需 slots 类。
- 误：memoryview 比拷贝「快」——主要省内存，复制避免与否取决于是否真走 buffer。
