## 本章地图

| 节 | 内容 | 结论 |

| 无限序列 | 迭代器惰性 | 用迭代器表达「永不停」的流 |

## 核心精讲

**1. 迭代器 vs 可迭代。** 可迭代（`__iter__`）产生迭代器（`__next__`）；`for` 循环底层就是反复调 `__next__` 直到 `StopIteration`。

**2. 生成器 `yield`。** 每次 `yield` 暂停并保留栈帧，下次从断点继续。适合「生产者—消费者」流式管线，避免把整个序列塞进内存。

```python
# 教学示意，不参与构建
def evens(limit):
    n = 0
    while n < limit:
        yield n
        n += 2

# 惰性：从不物化整个序列
total = sum(x * x for x in evens(10_000_000))   # 生成器表达式
```

**3. 生成器表达式 vs 列表推导。** `(f(x) for x in it)` 惰性、省内存；`[f(x) for x in it]` 立即物化。大数据务必用前者。

## 版本演进

- 3.3 起 `yield from`（委托子生成器）；3.5 起 `async def` / `await` 与异步生成器 `async def gen(): yield`。
- 3.7 起生成器可加 `return value` 作为 `StopIteration.value`（PEP 380 已落地于 yield from）。
- 3.10 起 `match`/`case` 可在迭代解构上做模式匹配；3.11 `aiter`/`anext` 内置异步迭代入口。
- `itertools`（标准库）提供 `islice`、`tee`、`chain` 等惰性积木。

## 常见误区与本书需修正之处

- 误：生成器「快」——它往往不比列表推导快，优势在内存与惰性，不是速度。
- 误：`itertools.tee` 会缓存已消费部分到内存，多消费者场景可能被它悄悄吃光内存。
- 误：生成器只能遍历一次；复用需重新调用工厂函数或 `itertools.tee`。
- 🔧 原书未覆盖异步生成器（2016+ 才普及），应在「版本演进」补 `async for`/`async def gen`。
