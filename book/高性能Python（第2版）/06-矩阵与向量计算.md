## 核心精讲

**1. 为什么 list 慢。** `list of lists` 是「指针数组的数组」，元素非连续、每行独立分配，CPU 缓存命中率低；且每个元素都是 `PyObject*`，解释器逐元素开销巨大。

**2. NumPy 连续数组。** `np.ndarray` 是单块连续内存 + dtype + stride。向量化（`a + b`）在 C 层循环，无解释器逐元素开销，且对缓存友好。

```python
# 教学示意，不参与构建
import numpy as np
n = 4_000_000
a = np.linspace(0, 1, n)
b = np.linspace(0, 2, n)
# 向量化：一次 C 调用
c = a * a + b * b
# 原地：避免临时数组
np.add(a * a, b * b, out=c)
```

**3. 原地与广播。** `+=`、`.sum(axis=...)`、`out=` 参数避免反复分配临时数组；广播（broadcasting）让不同形状自动对齐，省显式 tile。

**4. numexpr。** 对长表达式（`a*b + c*d - e`）做惰性求值 + 多线程，避开 NumPy 逐个算子产生临时数组的开销。

**5. 警惕「伪优化」。** 原书用 scipy 某例说明：有时引入「更高级」库反而更慢，务必用第 2 章剖析验证。

**6. Pandas 内部。** DataFrame 按列存（`BlockManager` → 现代 Arrow-backed），整列运算走 NumPy；**不要**在循环里 `pd.concat`（每次复制），应预分配或用 `.loc`/批量构造。

## 版本演进

- 原书基于 NumPy 1.x。2024 起 **NumPy 2.0** 发布（ABI 清理、dtype 系统升级、`np.float64` 等别名规范化、移除大量 NumPy 1.x 废弃 API）。代码里应丢掉 `np.float`/`np.int` 等别名。
- NEP 50（NumPy 2.0 的类型提升规则）、NEP 42（dtype 协议）。
- Pandas 2.x 默认用 PyArrow 后端（字符串、缺失值更高效），`copy-on-write` 默认开启，避免隐式别名 bug。
- `numpy.typing.NDArray`（3.9+ 泛型）做类型标注。

## 常见误区与本书需修正之处

- 🔧 误：原书示例按 NumPy 1.x 写（`np.float`/`np.int` 别名），NumPy 2.0 已移除，需改 `np.float64` 等。
- 误：认为「向量化一定快」——小数组上 ufunc 调用开销可能盖过收益；超大数组又受内存带宽限制。
- 误：盲目 `np.array(list_of_lists)` 不指定 dtype，得到 `object` 数组，毫无性能优势。
- 误：Pandas 循环 `concat` 是性能灾难；应向量化或预分配。
