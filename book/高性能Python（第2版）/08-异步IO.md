## 核心精讲

**1. 异步解决什么。** 当程序大部分时间在等网络/磁盘（I/O 密集），多线程会被 GIL 与上下文切换拖慢；`asyncio` 用单线程事件循环 + 协程，在「等」的时候切去跑别的协程，性价比极高。

**2. 协程与事件循环。** `async def` 定义协程，`await` 让出控制权；`asyncio.run(main())` 启动事件循环。

```python
# 教学示意，不参与构建（需 Python 3.11+ 用 TaskGroup）
import asyncio

async def fetch(url):
    # 伪代码：await 一个非阻塞 I/O
    return f"done:{url}"

async def main():
    async with asyncio.TaskGroup() as tg:   # PEP 654 结构化并发
        t1 = tg.create_task(fetch("a"))
        t2 = tg.create_task(fetch("b"))
    # t1.result() / t2.result() 此时已完成
```

**3. 结构化并发 TaskGroup（PEP 654，3.11）。** 取代手抖的 `asyncio.gather` 错误处理：任一组内任务抛异常，其余被取消，并以 `ExceptionGroup` 汇总——比「gather 吞异常」安全得多。

**4. 与多进程/多线程边界。** 异步只在单线程内并发 I/O；遇 CPU 密集要 `loop.run_in_executor` 丢进进程池，或用 `asyncio.to_thread`（3.9）。

## 版本演进

- 原书（2020）基于 `asyncio` 早期 API（`loop.create_task`、`gather`）。3.7+ 已有高层 `asyncio.run`/`asyncio.create_task`；3.11 加 `TaskGroup` + `ExceptionGroup`（PEP 654）；3.11 加 `asyncio.Runner` 上下文管理。
- 3.9 起 `asyncio.to_thread`、`asyncio.timeout`（3.11）。
- 生态：`anyio`（统一 asyncio/trio 后端）、`trio`（结构化并发先驱）、`aiohttp`/`httpx`(async)。

- FastAPI（基于 `anyio`）把 async 推向 Web 主流；ASGI 取代 WSGI 处理并发连接。

## 常见误区与本书需修正之处

- 🔧 误：原书错误处理以 `gather(return_exceptions=...)` 为主；2026 应首选 `TaskGroup`（异常不丢、自动取消兄弟任务）。
- 误：以为 `async` 函数「自动并发」——必须被 `await`/`create_task` 调度，否则只是定义。
- 误：在协程里调同步阻塞 I/O（如 `requests.get`）会卡住整个事件循环；要用异步库或 `to_thread`。
- 误：asyncio 不能绕过 GIL 做 CPU 并行，CPU 热点仍靠多进程（第 9 章）。
