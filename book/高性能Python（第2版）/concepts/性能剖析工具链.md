# 概念专篇：性能剖析工具链

> 跨章概念：与第 2 章（性能分析定位瓶颈）强相关，并支撑全书的「先测再优」纪律。
> 校准到 2026。

## 1. 按目标选工具

| 目标 | 工具 | 侵入 | 备注 |
|---|---|---|---|
| CPU 耗时概览 | `cProfile` + `pstats` | 低（2–10× 慢） | 标准库；`python -m cProfile -s cumtime` |
| 可视化火焰图 | `snakeviz` / `tuna` | 低 | 渲染 cProfile 输出 |
| 逐行 CPU | `line_profiler`（`kernprof -l -v`） | 中（需 `@profile`） | 精确到行；配 no-op 兜底 |
| 内存 | `memory_profiler` / `tracemalloc` | 低 | 标准库 tracemalloc 抓峰值/泄漏 |
| 线上进程 | `py-spy`（`top`/`dump`） | 零（采样） | 生产安全，不改代码 |
| 全栈（CPU+内存+GPU） | `Scalene` | 低 | 行级三线剖析，带 AI 建议 |
| 时间线/并发 | `viztracer` → perfetto | 低 | 看异步/多进程交错 |
| 字节码 | `dis` | 零 | 看 CPython 真实指令 |

## 2. 标准库可观测性（3.12+）

- **`sys.monitoring`（PEP 669，3.12）**：低开销的底层剖析/跟踪钩子，取代旧式 `sys.setprofile`/`sys.settrace`，自写剖析器应优先用它。
- `tracemalloc` 自 3.4 起即用，适合 CI 里抓内存回归。

## 3. 推荐工作流

1. 先 `py-spy top` 粗看线上/本地热点（无侵入）。
2. 用 `cProfile` + `snakeviz` 定位耗时函数。
3. 用 `line_profiler` 下钻到行。
4. 内存问题切 `memory_profiler` / `tracemalloc`。
5. 并发/异步时序用 `viztracer`。
6. 全程跑单元测试 + 基准（pytest-benchmark / asv），防止「越优化越错」。

## 4. 常见误区

- 误：cProfile 结果当真实耗时——它有显著开销，只能定位，定位后要去掉剖析器测端到端。
- 误：line_profiler 的 `@profile` 未装包时报 `NameError`——务必 `try/except ImportError` 给 no-op 装饰器。
- 误：py-spy 在 no-GIL 构建（3.13t/3.14t）下采样语义不同，结论需结合构建类型解读。
