## 核心精讲

**1. 类型信息为何加速。** CPython 每次运算都要拆 `PyObject*`、查类型、装箱/拆箱。编译型方案（Cython/Numba/mypyc）拿到静态类型后，可直接生成原生机器码，去掉这层开销。

**2. Cython（AOT）。** 把 `.py` 渐进改成 `.pyx`：先 `cythonize` 编译跑通，再给热点变量加 `cdef int` 等类型注解，用 `cython -a` 看「黄得越少越快」。`pyximport` 可免构建直接 import。

```python
# 教学示意，不参与构建（Cython .pyx 片段）
def integrate(double a, double b, int n):
    cdef double s = 0.0
    cdef double dx = (b - a) / n
    cdef int i
    for i in range(n):
        s += (a + i * dx) ** 2
    return s * dx
```

**3. Numba（JIT）。** `@njit` 装饰纯数值函数，首次调用编译并缓存；`parallel=True` + `prange` 自动多核；`numba.vectorize` 生成 ufunc。上手最快，限制：只认纯 Python + NumPy 子集。

**4. PyPy。** 换带 JIT 的解释器，零代码改动即可加速（动态类型也能 JIT）；但**仍带 GIL**，且 C 扩展生态（许多库依赖 CPython API）兼容性有坑。2026 年 PyPy 支持至 3.10 语法。

**5. FFI。** `ctypes`（标准库，调动态库）、`cffi`（CFFI 项目，声明式）、`f2py`（Fortran）。适合调已有高性能库而非从零写。

**6. CPython C 扩展 / HPy。** 最底层控制，但开发成本最高；现代可走 HPy（可移植 C API，兼容 CPython/PyPy/GraalPy）。

**7. GPU。** 海量并行（矩阵、深度学习）用 CUDA/ROCm；PyTorch/JAX/CuPy 封装了底层。动态图（PyTorch）利于研究，静态图（XLA）利于部署。

## 版本演进

- 原书提 mypyc 较少；现 **mypyc**（Mypy 自带 AOT）可将带类型注解的纯 Python 编译为 C 扩展，是「零 DSL」方案。
- Cython 3.x（2023+）默认行为变更（更严格的 `cpdef`、更好的类型推断、Python 3 语法）。
- Numba 持续支持到较新 NumPy；注意 NumPy 2.0 ABI 兼容性。
- 3.13+ free-threading 构建（PEP 703）下，编译扩展需用「受限 C API」或标记线程安全，见 [concepts/GIL与free-threading.md](concepts/GIL与free-threading.md)。

## 常见误区与本书需修正之处

- 🔧 误：原书称 PyPy「无 GIL」或暗示并行自由——PyPy 同样有 GIL，多线程 CPU 并行仍需多进程。
- 误：以为「加了 Numba 就一定快」——`@njit` 不支持的代码会退化为对象模式甚至报错；先剖析确认是数值热点。
- 误：在 free-threading（3.13t/3.14t）下用老式 C 扩展会触发 GIL 假设冲突，需受限 API。
- 误：Cython 不加类型注解几乎不加速，必须显式标注热点。
