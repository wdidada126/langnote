## 核心精讲

**1. 哈希表结构。** `dict` 与 `set` 都是开放寻址的哈希表（3.6 起 `dict` 用更紧凑的「紧凑字典」布局，插入顺序被保留）。查找先算 `hash(key)`，再定位桶，冲突用线性/二次探测。

**2. 扩容。** 负载因子（已用/总桶）超阈值（约 2/3）时整体搬迁到约 2 倍大的表。预分配可用 `{k: v for ...}` 或先估算大小减少搬迁。

**3. 命名空间即字典。** 局部变量在 `co_varnames` 数组里（按索引，O(1)）；全局/属性访问走字典查找（更慢）。所以「局部变量快于全局」本质是数组索引 vs 哈希查找。

```python
# 教学示意，不参与构建
d = {}
for i in range(10_000):
    d[i] = i           # 多次 resize；可先 d = dict.fromkeys(range(10_000)) 预建
```

## 近年研究与工业界开源实践（2015–2026）

- 3.7 后「OrderedDict 不再必需」成为常识，但 `OrderedDict.move_to_end` 等专属能力仍保留。
- 工业界用 `os.environ`/`sys.modules` 等全局字典时警惕锁竞争；热路径尽量本地化。
- 不可变映射 `types.MappingProxyType`（3.3+）用于暴露只读配置。

## 常见误区与本书需修正之处

- 🔧 误：原书部分表述把 dict 顺序当「未定义」——3.7+ 已是语言保证，现代代码可依赖插入序。
- 误：用可变对象（list、dict）当键——不可哈希，`TypeError`。
- 误：认为 set 去重「免费」——去重要算 hash + 比较，超大 set 仍吃内存；可评估 `array`/位图替代。
- 误：`dict.copy()` 是浅拷贝，嵌套结构共享引用。
