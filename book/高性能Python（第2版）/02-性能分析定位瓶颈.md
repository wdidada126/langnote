## 核心精讲

本章用「Julia 集」算图作为贯穿基准，演示从粗到细的剖析梯度。

**1. 简单计时。** 玩具级可用 `time.perf_counter()`；装饰器版用 `functools.wraps` 包好。

```python
# 教学示意，不参与构建
import time, functools

def timeit(func):
    @functools.wraps(func)
    def wrapper(*a, **k):
        t0 = time.perf_counter()
        r = func(*a, **k)
        print(f"{func.__name__}: {time.perf_counter()-t0:.4f}s")
        return r
    return wrapper
```

**2. cProfile（标准库）。** `python -m cProfile -s cumulative script.py`，或用 `pstats` 在代码内聚合。输出看 `ncalls`（调用次数）与 `cumtime`（累计）。

**3. 可视化。** `snakeviz` 把 cProfile 输出渲染成交互火焰图；`tuna` 是更轻量的替代。

**4. 逐行 line_profiler。** 用 `@profile` 装饰目标函数，`kernprof -l -v script.py` 出逐行耗时。注意 `@profile` 在普通运行下未定义——用「no-op 装饰器」兜底：
```python
# 教学示意，不参与构建
try:
    from line_profiler import profile
except ImportError:
    def profile(f): return f   # no-op，保证未装包时也能跑
```

**5. 内存 memory_profiler。** `@profile` + `mprof run`，看每行内存增量；`tracemalloc`（标准库）适合抓峰值与泄漏。

**6. 线上 py-spy。** `py-spy top --pid <pid>` / `py-spy dump`，采样栈，不修改被测进程，生产安全。

**7. dis 看字节码。** `import dis; dis.dis(func)` 看 CPython 实际执行的指令，理解「为什么这行慢」。

## 版本演进

- 原书聚焦 py-spy / line_profiler / memory_profiler / cProfile。2020 后新增：

## 近年研究与工业界开源实践（2015–2026）

- Scalene（Emery Berger 等）将「行级内存 vs CPU」分离剖析做成标配思路。
- viztracer + perfetto 成为看并发/异步时间线的主流。
- 工业界「CI 里跑基准回归」（如 pytest-benchmark / airspeed velocity）把剖析前置到提交阶段。

## 常见误区与本书需修正之处

- 🔧 误：原书未提 `sys.monitoring`（3.12），自写剖析钩子现在应优先用它而非猴补 `sys.setprofile`。
- 误：cProfile 会显著拖慢（2–10×），只能用于定位，不能代表真实耗时；定位后要去掉剖析器再测端到端。
- 误：line_profiler 的 `@profile` 在未装包时报 NameError——务必配 no-op 兜底（原书其实也提了，但易被忽略）。
- 误：py-spy 在 free-threading 构建下采样语义与带 GIL 时不同，需留意。
