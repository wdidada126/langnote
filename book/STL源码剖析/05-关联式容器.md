# 第 5 章 关联式容器（Associative Containers）

> 覆盖原书第 5 章：树与二叉搜索树复习、红黑树性质与 `rb_tree` 实现、set/multiset/map/multimap 四层皮、

> 本章回答一个问题：**「按键查找」的两条底盘路线——有序用树、无序用哈希——各自怎样长到源码结构。**
> 源码引用镜像 [karottc/sgi-stl](https://github.com/karottc/sgi-stl)（stl_tree.h / stl_hashtable.h /
> stl_hash_map.h / stl_hash_fun.h，写作时逐文件可达）；对原书为机制转述。

## 核心概念速览（中英对照）

- **关联式容器** — associative container：以「键」组织而非以「位置」组织；分有序（红黑树）与无序（哈希）两族（后者是 SGI 扩展）。
- **键值对** — pair / value_type vs key_type：set 的 value 即 key；map 的 value 是 `pair<const Key, T>`，靠萃取器区分两族。
- **红黑树** — red-black tree：五性质近似平衡 BST（根黑、红不连续、黑高相等…），换 O(log n) 查找 + 低旋转次数。
- **树节点基** — `_Rb_tree_node_base`：`color + parent + left + right` 四字段（stl_tree.h:71-76），值域挂在派生模板节点上——通用手术代码不碰值。
- **哨兵头节点** — header：`_M_parent` 指根、`_M_left` 指最左（begin）、`_M_right` 指最右（最大元素），end() 即 header 自身。
- **树迭代器 ++** — in-order successor：有右子→找右子树最左；否则沿 parent 上爬直到「从左边下来」——双向迭代器档。
- **lower_bound / upper_bound** — 下/上确界：树上二分找 `≥key` / `>key`；`equal_range` 一对答案。
- **插入双模式** — insert_unique / insert_equal：前者返回 `pair<iterator,bool>`（set/map 用），后者直接返回位置（multi 系用）。
- **开链哈希** — chained (open) hash table：桶向量 `vector<slist>`，每桶一条单链表处理冲突（SGI 称 open hash，⚠️ 与文献「开放寻址」同名不同义，见误区表）。
- **质数桶数** — prime bucket counts：28 级质数表 `__stl_prime_list`（stl_hashtable.h:148-160），`next_prime` 选桶；避免 2 幂桶数放大劣质哈希的低位偏差。
- **再哈希** — rehash：元素数超过桶数即 `resize` 到 `max(2*旧桶, next_prime(元素数))`，全表逐桶重新链接。
- **取值萃取** — `select1st / select2nd`：从 `pair` 拿 key（建树/建桶用）或 value（map 视图用），`_Select1st`  functor 见 06 篇谱系。
- **哈希函数对象** — `struct hash`（stl_hash_fun.h）：整数族恒等映射；字符串 `5*h + c`（BKR 系变体，:40-46）；自定义类型需特化。
- **等价 vs 相等** — equivalence by comparator：树上「互不比对方小」即等价，multi 系同键相邻；哈希上「同桶 + 键相等」。

## 动机：有序不是免费，无序不是万能

序列容器查找 O(n)。关联容器要 O(log n) 或 O(1)，但两种「秩序」买法不同：

- **树**：始终全序 → 支持区间查询（lower_bound/equal_range/双向遍历），但每元素一节点、比较代价高；
- **哈希**：只保证桶内局部无序 + 键相等 → 单点查询 O(1)，但区间/前缀/有序遍历不可能。

SGI 用**同一套部件语言**把两族都搭起来：底盘（rb_tree / hashtable）+ 萃取器（identity / select1st）+
比较器/哈希器（less / hash）——四个上层容器只是模板参数不同的皮。

## 机制 A：rb_tree 到手术刀级别

### 1. 节点与哨兵

```cpp
// stl_tree.h:71-76（实测镜像行号）
struct _Rb_tree_node_base {
  _Color_type _M_color;               // 红/黑
  _Rb_tree_node_base* _M_parent;
  _Rb_tree_node_base* _M_left;
  _Rb_tree_node_base* _M_right;
};
template <class V> struct _Rb_tree_node : public _Rb_tree_node_base { V _M_value_field; };
```

`_Rb_tree_impl` 里只有一个 header + 节点计数器。header 的妙用：`_M_left` 永远是最小节点、
`_M_right` 永远是最大节点、`begin()==header._M_left`、`end()==&header`——
**空树与满树共用一套端点逻辑**，`front()/back()` O(1)。

### 2. 迭代器 ++（03 篇双向档的活教材）

```text
if (x._M_node->_M_right)      → 进入右子树，返回其最左下（_S_minimum）
else                          → 沿 parent 上爬，直到当前节点是其父的左子；
                                爬到「从左边下来」的那个父即后继；
                                从右边爬到顶 = 没有后继（返回 end()）
```

### 3. 插入手术：先 BST，再修色

新节点**必染红**（stl_tree.h:266 `__x->_M_color = _S_rb_tree_red`——染红只可能违反「红不连续」，
不会违反黑高性质），然后按叔父颜色分 Case 重着色/旋转（`_M_rebalance_insert`）。
删除更复杂（双黑修复），书以插图带过——机制与 CLRS 一致，SGI 用 parent 指针免哨兵 nil 节点。

### 4. 四层皮

```text
set     = rb_tree<Key, select1st, Compare, alloc>   insert_unique
multiset= 同上                                        insert_equal
map     = rb_tree<pair<const K,T>, select1st, Compare, alloc>  insert_unique
multimap= 同上                                        insert_equal
```

`map::operator[]` 在 SGI 中：`lower_bound` 找到即返回引用；找不到则 `insert` 再 `operator[]`
（⚠️ 具体绕行写法各版本有别，机制以镜像 `map.h` 为准，此处只陈述语义：默认构造插入）。
这就是「`operator[]` 会悄悄插元素、const 地图不可用 []」的根源。

## 机制 B：hashtable 链与搬家

```cpp
// stl_hashtable.h 骨架（转述）
template <class Val, class Key, class HashFcn, class ExtractKey, class EqualKey, class Alloc>
struct hashtable {
  vector<slist<Val>> buckets;        // 桶向量：每桶一条单链表（开链）
  size_type num_elements;
  // 关键行（实测）：:148-160 28 级质数表；:351 max_bucket_count = 表尾；
  //                 :516 round_for_bucket = next_prime(n)
};
```

- **桶数为何是质数**：`hash(x) % buckets`；若桶数为 2^n，劣质哈希（低位无变化）会让高位信息全丢，
  质数强制模运算「搅动」所有位。注意：整数键的 `hash<int>` 是恒等函数（stl_hash_fun.h:70 附近），
  **键值本身的高度偏斜会直通桶分布**——这是书中「hash(100) 对 100 桶表」的警告。
- **插入**：`b = hash(key) % n`；unique 版先在本桶线性找重复，头插；equal 版直接头插。
- **rehash 触发**：SGI 策略是**元素数 > 桶数即翻倍重建**（比「装填因子 0.75」激进，链短、省内存、费搬家）。
  搬家时按「旧桶顺序」把每个节点 splice 到新桶——不重新分配节点，只改链。
- **迭代器**：桶间跳跃找非空（`find_next_bucket`），前向档——**哈希天然不需要双向**，与树的对比点。

## 权衡

| 维度 | rb_tree 族 | hashtable 族 |
| --- | --- | --- |
| 单点查找 | O(log n) 比较 | 均摊 O(1)，最坏 O(n)（全冲突） |
| 区间/有序遍历 | 原生能力 | 不可（只能全表） |
| 迭代器失效 | 插入几乎不失效（节点制）| rehash 全失效（桶结构变了） |
| 内存 | 每节点色+3 指针 | 桶向量 + 每节点 next |
| 定制成本 | 比较器 `less<T>` | 哈希函数 + 相等判据，双件套 |
| 标准地位 | C++98 起入标 | SGI 扩展，C++11 以 unordered_* 重新发明 |

## 相邻概念对比

- **set vs map**：同一棵树，`select1st` vs `select2nd` 与 value 类型不同——**萃取器是唯一实质差异**。
- **hash_map vs unordered_map**：SGI 版无 `allocator` 全模板化、桶是 slist、rehash 策略不同；
  标准版要求 `Hash`/`Key_eq` 可调用对象而非 `struct hash` 特化，接口语义（`operator[]`、`at`）也更严。
  **迁移只需换名字+自定义哈希写法，但别指望 O(1) 保证同前**（标准同样是均摊）。
- **树 vs 跳表**：SGI 无跳表；工程上 LevelDB/RocksDB 用跳表做 memtable（本仓库
  [../Redis设计与实现.md](../Redis设计与实现.md) 的 zset 亦是跳表），随机化换平衡，实现难度低于红黑——现代视角值得对照。
- **等价（!a<b && !b<a）vs 相等**：树上同键靠等价、哈希上靠 `EqualKey`；自定义比较器若与
  哈希判据不一致，两族行为会分裂——这是「比较器必须是严格弱序」在关联容器侧的镜像。

## 最新演进与工业实践

- **unordered_*（C++11）血统**：由 C++03 TR1 从 SGI hash_* 演化而来（⚠️ TR1 具体文档编号未核实）；
  实现普遍仍是「桶 + 前向链（带缓存哈希值的单向节点）」，即 SGI 开链法的直系后代。
- **工业界抛弃链式哈希**：
  - [absl::flat_hash_map](https://github.com/abseil/abseil-cpp)（开放寻址 + SIMD 控制字节，元数据 1 字节/槽）——
    把「桶向量 + 节点」压进**一块连续内存**，缓存局部性碾压开链；rehash 时元数据比较即可筛候选。
  - [martinus/unordered_dense](https://github.com/martinus/unordered_dense)：Robin Hood + 倒置索引（bucket→ FIFO stacks），
    标准兼容接口，作者原 robin_hood 仓库现已不可访问（实测 404），由 unordered_dense 继任。
  - [Tessil/robin-map](https://github.com/Tessil/robin-map)：Robin Hood 迁移，Redis `dict` 的增量 rehash 亦同族。
  共同点：**整数哈希扰动（splitmix/murmur finalizer）取代「质数模」**——现代共识是「2 幂桶 + 强哈希」优于
  「质数桶 + 弱哈希」，SGI 的 28 级质数表是为 `hash<int>` 恒等这种弱哈希兜底的组合拳（见上节警告）。
- **PMR 进入哈希容器**：`std::pmr::unordered_map` 一次整池分配桶 + 节点（`uses_allocator` 经
  `polymorphic_allocator` 自动传递；🔧 本机 g++ 15.2 以自定义 `memory_resource` 计数验证过 1000 元素
  vector 仅 11 次分配——同机制适用于 pmr 容器，见 07 篇实测附注）。
- **B-tree 反向渗透**：工业 KV 常用「排序容器 + 批量扫描」思路（F14/BTree 混合体，⚠️ 具体库名不展开）；
  区间查询需求 = 红黑树路线的现代存活证明。

## 常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | SGI「open hash（开哈希）」= 开放寻址 | SGI 早期版本（2.x，本书剖析对象之一）把链地址哈希表类命名为 `open_hash`（后续版本改名为 `hashtable`；⚠️ 本次核实的 4.x 系镜像中已无 open_hash 类名，实测只见 `hashtable`/`hash_map`），其含义始终是**链地址法**（桶挂链表），与现代文献的 open addressing（探测序列）名同实异 |
| 2 | unordered_map 是标准版 hash_map | 接口与要求都重写过（可调用对象、`at`、节点句柄 C++17）；只是同一思想 |
| 3 | 树插入会使迭代器失效 | 节点制容器插入不失效（begin/end 位置不变，值序不变）；**哈希 rehash 才全灭** |
| 4 | 红黑树 = AVL 更矮 | 红黑比 AVL 更高（≤2log），但旋转次数 O(1)/插入——写多读少选红黑正是此权衡 |
| 5 | 键可以随便改 | map 的 key 是 const 正是防「改键坏树」；set 给 mutable 元素改坏自己，全靠「实现自由」豁免（std::set 的 value_type 实际 non-const 是著名历史事故 ⚠️  LWG 编号未核实） |
