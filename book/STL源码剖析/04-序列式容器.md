# 第 4 章 序列式容器（Sequence Containers）

> 覆盖原书第 4 章：vector、list、deque（双头队列）、heap、priority_queue、stack/queue 适配器、
> SGI 扩展 slist、rope（长字符串）、bit_vector（位图）。
> 本章回答一个结构问题：**每个容器的底层数据形状长什么样，为什么形状决定操作代价。**
> 源码引用镜像 [karottc/sgi-stl](https://github.com/karottc/sgi-stl)（stl_vector.h / stl_deque.h /
> stl_list.h / stl_heap.h / stl_rope.h / stl_bvector.h，写作时逐文件可达）；对原书为机制转述。

## 核心概念速览（中英对照）

- **向量** — vector：三指针 `start / finish / end_of_storage` 管理的连续动态数组，空间预备量翻倍成长。
- **容量** — capacity：`end_of_storage - start`；`size ≤ capacity` 的差值就是「免重分配配额」。
- **链表** — list：循环双向链表 + 哨兵节点 `_M_node`，节点 `prev/next + data`，迭代器只包一个指针。
- **双端队列** — deque：`map`（指针数组）指向若干**定长缓冲块**，块数 × 块内元素数构成二维布局。
- **块大小 512** — `__deque_buf_size(sizeof(T)) = 512 < size ? 1 : 512/size`（stl_deque.h:80）：小元素一块几百个，大元素独占一块。
- **堆** — heap：数组表达的完全二叉树，`parent=(i-1)/2`、`left=2i+1`，max-heap 序。
- **堆手术** — push_heap / pop_heap / make_heap / sort_heap：upheap/downheap（`adjust_heap`）维持序。
- **容器适配器** — container adaptor：stack/queue/priority_queue 不改数据、只改接口——「以容器为基座戴上面具」。
- **单链表** — slist（SGI 扩展）：前向迭代器档；**头部插入 O(1)、中间插入需前驱**，节点池按「一次一整档」配置。
- **绳子** — rope（SGI 扩展）：引用计数 + 二叉拼接树表达的长字符序列，O(log n) 拼接/切片，写时复制。
- **位向量** — vector\<bool\>：以 32 位 word 打包布尔（`__WORD_BIT = CHAR_BIT*sizeof(unsigned int)`，stl_bvector.h:36），迭代器是带位偏移的 proxy。
- **迭代器失效** — iterator invalidation：vector 重分配全灭、list/deque 端插稳定（deque 端插不失效迭代器但使位置引用失效）。

## 动机：三种「线性」的不可调和

线性访问有三种刚需：**随机下标**（要连续）、**任意点廉价插删**（要离散节点）、
**两头伸缩 + 稳定地址**（连续和离散各做一半）。一种内存布局三者不可兼得，于是：

```text
vector : 连续数组            —— 下标 O(1)，中间插删 O(n)，端插摊还 O(1)
list   : 离散双向节点        —— 已知位置插删 O(1)，下标 O(n)，每节点 +16B 指针
deque  : 分块连续 + 索引表    —— 两头摊还 O(1)，下标 O(1)(两级)，整体重分配几乎不发生
```

SGI 把「堆」也做成一族**自由函数**（`stl_heap.h`）而非容器——`priority_queue` 只是
vector + heap 算法的门面。这个分层（数据形状 / 算法 / 门面）正是第 1 章部件论的落实。

## 机制：逐容器到源码结构

### 1. vector：三指针与翻倍

```cpp
// stl_vector.h 骨架（转述）
template <class T, class Alloc = alloc>
class vector {
protected:
  iterator start, finish, end_of_storage;   // 三个 T*
  // 空间不足时：新容量 = max(2*旧容量, 需要量)（_M_range_check 路径，
  // 例如 assign/insert 的 __len > capacity() 分支 stl_vector.h:611 起：
  //   先 _M_allocate_and_copy 新块 → destroy 旧元素 → deallocate 旧块 → 换三指针
};
```

要点：扩容是**整块搬家**（新分配 + uninitialized_copy + 析构旧的），所以引用/迭代器全失效；
「翻倍」使 n 次 push_back 的重分配次数是 O(log n)、搬移总量 O(2n)——摊还 O(1) 的来源。
`insert` 在容量够时只是尾段搬移。swap-erase 惯用法之所以有效，正因为它复用这套搬家逻辑收缩容量。

### 2. list / slist：哨兵统一端条件

```cpp
// stl_list.h（转述）：__list_node_base{ next, prev }；节点继承它再挂 data
_List_node_base _M_node;      // 头哨兵：begin()=next, end()=&_M_node, empty()=next==&_M_node
```

双向环 + 哨兵让 `insert_before/erase` 无分支；`list::sort` 是**归并排序**（链表上快排无优势，
merge 不需随机访问），`merge/splice/reverse/unique` 全部只动指针不动数据。
slist 反向需要前驱，所以它的接口刻意只给 `insert_after/erase_after` 风格（SGI 用「以 x 前驱的迭代器」表达），
其迭代器 category 是 forward——**03 篇标签分派的活教材**：`advanced` 之类算法对 slist 自动降级。

### 3. deque：map-of-buffers 与跨块迭代器

```cpp
// stl_deque.h（转述）
protected:
  iterator start, finish;        // iterator 内含 {cur, first, last, node}
  map_pointer map;               // T** —— 指向「块指针数组」
  size_type map_size;
// 块内元素数 = 512/sizeof(T)（至少 1，stl_deque.h:80 实测于镜像）
// 迭代器 ++：cur 到 last 则 node++ 换块、cur 重置为该块 first —— 03 篇 __deque_inc 的由来
```

deque 的随机访问迭代器「看起来连续、走起来换块」，`operator-` 要算跨块距离：
`(node 差) * 块容量 + 块内偏移差`。`push_front/push_back` 只在**整张 map 用尽**时才
`reallocate_map`（重排指针数组，**不搬元素**），且默认在两端各留一块余量——
这就是「两端生长几乎免费」的机关。代价：中间插删退化为搬移整段（搬指针不能跨块，只能逐元素）。

### 4. heap 与 priority_queue

`push_heap`：新元素先放尾，再 `upheap` 逐层与父比较交换。
`pop_heap`：堆顶与尾互换、`adjust_heap`（先下沉留洞、再上浮回填）在缩小后的区间恢复序。
`sort_heap`：反复 pop_heap——**堆排序原地 O(n log n)**，是 06 篇 `partial_sort` 的零件。
`priority_queue` 默认用 `vector` + `less`（max-heap），换 `greater` 即 min-heap。

### 5. rope 与 bit_vector（两枚偏门样本）

- **rope**：`_Rope_char_ptr_proxy` 等 proxy 满天飞；节点带 `_M_ref_count`（stl_rope.h:545 附近可见归零才 `_M_free_tree`），
  大文本的「切片共享 + 拼接成树」适合编辑器 buffer 场景。⚠️ 现代三家实现均未收录，标准也无——它是「SGI 扩展」的标本。
- **vector\<bool\>**：`bit_vector` 以 32 位 word 存位（`__WORD_BIT`），`reference` 是
  `{word* , mask}` 的位域代理——**第一个把「迭代器不必是裸指针」推到极限的标准容器**，
  C++20 的 `std::ranges` 为此专门引入了「proxy 引用」概念（呼应 03 篇演进节）。

## 权衡

| 容器 | 内存税 | 缓存 | 伸缩 | 典型误用 |
| --- | --- | --- | --- | --- |
| vector | 0（连续） | 最优 | 搬家式 | 当队列头删（O(n)） |
| deque | map + 两端余块 | 块内好 | 不搬家 | 中间插删 |
| list | 每节点 2 指针 + 分配 | 最差 | 任意点 O(1) | 高频小节点导致池压力（02 篇正是它的续命丸） |
| slist | 1 指针 | 差 | 头插 O(1) | 想回退（做不到） |
| rope | 树 + 引用计数 | 差 | 拼接 O(log n) | 短字符串（纯亏） |
| vector\<bool\> | 1/32 | 优 | 同 vector | 取 `&v[i]`（拿不到，proxy） |

## 相邻概念对比

- **deque vs vector**：同样要「表观随机访问」，一个赌「两头生长」（SGI/现代 libstdc++ 都是 512B 块），
  一个赌「整体搬家」。`sizeof(deque)==sizeof(vector)` 的错觉来自都只有几个指针成员。
- **list vs slist**：多一根 prev 换来回退与 `splice` 任意点；slist 是「forward 档迭代器的容器化身」。
- **heap 算法 vs 树容器**：堆序弱于 BST 全序——只保证「顶点即极值」，所以取极值 O(1)、
  但找任意元素 O(n)；第 5 章的红黑树正是反方向的选择。
- **stack/queue**：默认基座 deque（SGI/现代 libstdc++），`stack<vector>` 换底一行模板参数——
  适配器不造数据只限接口，与 06 篇函数适配器同族不同用。

## 最新演进与工业实践

- **deque 块尺寸的现代走向**：libstdc++ 至今 512 字节（本机 g++ 15.2 头文件 `bits/stl_deque.h`
  `_GLIBCXX_DEQUE_BUF_SIZE 512`，实测）；MSVC STL 采用 16 字节块策略（⚠️ 细节未在本机核对，以 microsoft/STL 源码为准）；
  libc++ 长期沿用 3 指针 + map 结构并持续重写迭代器层（llvm/llvm-project `libcxx/include/deque`）。
  🔧 本机实验（g++ 15.2，已实测）：vector 首末元素地址差恰为 `4999*4`（连续），deque 为 145708 字节
  （分块离散），且 `push_front` 5000 次后既有元素地址与值纹丝不动——分块 + map 的直接证据。
- **vector\<bool\> 的存废**：libc++ 另起炉灶实现 `std::vector_bool`（P2956R3 提案路线 ⚠️ 编号未核实），
  用「真容器 + 引用代理」替代旧 proxy 怪胎（仅 C++26 范围讨论，三家尚未统一；此条写作时以 libc++ release 说明为据 ⚠️）。
- **slist/rope 的后裔**：`std::forward_list`（C++11）是 slist 转正；rope 没有转正，
  工业界由片段式字符串自建（LLVM `Support`、编辑器/文本库如Xi/Gap buffer 系）——SGI rope 源码仍是最好的教材。
- **工业选型共识**：默认 vector；「队列」用 `deque` 或 folly producer/consumer 队列；
  「大量小对象 + 稳定地址」交给 arena + `std::list` 或 slab 池（02 篇思想的工业复活）；
  文本 buffer 用 rope 思想自建或现成 CRDT/片段库。
- **rope 引用计数的现代替代**： intrusive_ptr / COW 字符串已被标准禁绝
  （C++11 起 SSO 与移动语义取代短字符串 COW；MSVC 的 COW 字符串是历史包袱 ⚠️ 未核细节）——
  移动语义视角见 [../Effective_Modern_C++.md](../Effective_Modern_C++.md)。

## 常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | vector 每次 push_back 都可能搬家 | 只在 `size==capacity` 时；翻倍策略使搬家摊还可忽略 |
| 2 | deque 是「双段数组」 | 是「块指针数组 + 多块」；下标是两级查表 |
| 3 | `deque::iterator` 不是随机访问 | 是（SGI 与现实现皆然）——只是差值计算跨块 |
| 4 | list.sort 是快排 | 归并：链表无随机访问，快排的分区优势不存在 |
| 5 | priority_queue 有堆容器类 | 它是 vector + `stl_heap.h` 自由函数的适配器，堆就是数组 |
| 6 | `&vb[i]` 能拿 `bool*` | vector\<bool\> 无 `bool&`，只有位代理；要真 bool 用 `std::bitset`/`vector<uint8_t>` |
