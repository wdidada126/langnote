## 核心概念速览（中英对照）

- **算法分类学** — algorithm taxonomy：非变动型（find/count/search）、变动型（copy/transform/replace）、
  排序与二分（sort/binary_search）、置乱（shuffle/rotate）、集合运算（set_union/merge）、极值（min/max 族）。
- **in-place vs out-of-place**：同族算法以「有无输出迭代器」分对，如 `replace` 覆写原区间、
  `replace_copy` 写到别处且原区间只读。
- **函数对象** — functor / function object：重载 `operator()` 的类；比函数指针快（可内联）、可携带状态。
- **仿函数基类** — `unary_function` / `binary_function`（stl_function.h:37,43）：只提供 typedef 证书，使配接器可萃取参数类型。
- **算术/关系/逻辑仿函数** — plus/minus/multiplies、less/greater/equal_to、logical_and/not：`sort(v.begin(), v.end(), greater<int>())` 的弹药库。
- **一元化配接** — `unary_negate/binary_negate` + `not1/not2`（:158）：把谓词 p 变成 !p。
- **函数组合** — `compose1/compose2`（:257）：f(g(x))、f(g1(x),g2(x))。
- **参数绑定** — `binder1st/binder2nd` + `bind1st/bind2nd`（:187-205）：二元降一元，把常数焊死在一侧。
- **函数指针配接** — `ptr_fun`（:290-321）：给普通函数补 typedef 证书，使其可进配接流水线。
- **成员函数配接** — `mem_fun/mem_fun_ref` 家族（:512 起）：把 `p->size()` 改造成 `f(p)` 的一元函数，容器元素为「指针 + 成员函数」时的桥梁。
- **反向迭代器** — `reverse_iterator`：包裹任意双向迭代器，`++` 译为 `--`；`rbegin() == reverse_iterator(end())`。
- **插入迭代器** — `back/front/insert_iterator`：解引用+赋值被改写为 `push_back/push_front/insert`，
  使 `transform/copy` 从覆写变追加；category 为 output。
- **流迭代器** — `istream/ostream_iterator`：把 IO 流伪装成输入/输出迭代器，算法直通终端/文件。
- **auto_ptr**：拷贝即转走的「引用语义智能指针」（定义在 `memory` 头，非 stl_tempbuf；析构 delete）——
  C++11 弃用、C++17 移除的史前 RAII。
- **temporary_buffer** — `_Temporary_buffer` + `get_temporary_buffer`：`malloc` 失败就**对半砍**再试
  （stl_tempbuf.h `_M_allocate_buffer` while 循环实测），拿多少用多少；归还走 `free`。

## 动机：策略注入的三种语法

算法要「因人而异」：比较、变换、谓词。98 年代表达策略有三条路：

1. **函数指针**：简单但不可内联（间接调用）、不能带状态；
2. **仿函数**：类型即策略，编译期完全特化，可内联可存参数——SGI 主力；
3. **配接器**：已有前两者但**接口不匹配**时的转接头——算法要一元你有二元（bind），
   要函数对象你有成员函数（mem_fun），要写你有只读（insert_iterator）。

三件套加上 traits 证书（03 篇），构成 C++98 泛型编程的全部日常语法。

## 机制：三条线各到源码层

### 1. 算法线：按迭代器档位选路

`stl_algo.h`（镜像实测 3297 行）的组织法：每个公开算法是「 traits 查档 → 转发给 `__algo` 私有实现」：

```cpp
// 转述：sort 的分派（stl_algo.h）
template <class RandomIt, class Compare>
void sort(RandomIt first, RandomIt last, Compare comp) {
  __sort(first, last, comp,
         iterator_traits<RandomIt>::iterator_category());   // 非随机访问 → 编译期报错（重载兜底）
}
// __sort: 区间小时插值排序（SGI 阈值 __stl_threshold=16）、
//         否则 introsort 形态：选枢(中位三者) → 递归左段 → while 循环尾递归右段（限制递归深度）
// merge/sort 的稳定版：__merge_buffer_type = temporary_buffer（见第 3 节）
```

`lower_bound` 在随机访问档用 `half = len/2; advance(first, half)`，双向档则「距离一半数过去」——
**同一算法，两份实现，全靠 03 篇标签分派**；`unique/copy/transform` 只要求 input/forward。

### 2. 仿函数线：证书 + 配接的矩阵

`mem_fun` 是本章最陡的坡。成员函数指针 `size_t (String::*)() const` 不能像自由函数那样调用，
`for_each(v.begin(), v.end(), &String::size)` 编译不过——因为容器里是 `String*`（指针语义）时
需要「取出对象、在对象上发射调用」这一转接层。SGI 用 2×2×(0/1 参数) 的矩阵铺路
（stl_function.h:512 起实测）：

```text
             非 const / const      返回值非 void / 是 void（偏特化）   参数 0 个 / 1 个
mem_fun   ：对象在容器中是指针 → 适配器体内 (p->*f)()
mem_fun_ref：对象在容器中是值   → 适配器体内 (x.*f)()
—— 2(非/const) × 2(void/非void 特化) × 2(0/1 参) × 2(ref/ptr) = 16 个模板类的「人肉重载」。
```

为什么函数指针时代只能这样：没有 `decltype`/泛型 lambda，无法写一个万能适配器统一 16 种形态。
`bind1st(op, value)` 造 `binder1st`：存下 op 与 value，`operator()(x)` → `op(value, x)`——
C++11 的 `std::bind` 与 lambda 用变参模板把这门手艺工业化后又淘汰了它（见演进节）。

### 3. 空间管理线：auto_ptr 与 temporary_buffer

```cpp
// auto_ptr（memory 头，SGI 以 operator=(auto_ptr_ref) 实现「拷贝即转走」）
template <class T> class auto_ptr {
  T* ptr;
public:
  T* release();                 // 放弃所有权不销毁 —— 转手的机关
  void reset(T* p = 0);
  ~auto_ptr() { delete ptr; }   // 唯一兑现 RAII 的地方
};
// ⚠️ 拷贝构造签名各版本不同（mutable 引用 vs auto_ptr_ref），细节以镜像 memory 为准，勿背。
```

auto_ptr 的三个死穴：① 可拷贝 → 源对象变 null，放进 vector 后 sort 一来所有权乱飞；
② `delete`（数组要 `delete[]`）不适配；③ 不能表达「借用」。C++11 用 `unique_ptr`（禁拷贝、
带删除器、数组特化）处决了它，C++17 移除。

```cpp
// temporary_buffer：「能拿多少算多少」的暂存带（stl_tempbuf.h 实测）
while (_M_len > 0) {
  _M_buffer = (Tp*) malloc(_M_len * sizeof(Tp));
  if (_M_buffer) break;
  _M_len = _M_len / 2;            // 拿不到就腰斩再试
}
// 析构：_Destroy_n(buffer, length) 析构已构造段；return_temporary_buffer → free
// 用途：unstable_partition/unstable_sort（SGI 的 merge 系）拿不到全量缓冲时，
//       退化为「带小缓冲的多轮归并」——永远比退回 O(n^2) 选择排序强。
```

**异常安全协议在这里闭环**：配置失败/构造抛出时，临时缓冲自己析构已构造元素——
02 篇 uninitialized 家族的调用方就是这里。

## 权衡

| 表达策略的载体 | 内联 | 带状态 | 可读性(当年) | 遗产 |
| --- | --- | --- | --- | --- |
| 函数指针 | ✗ | ✗ | 高 | `qsort` 式 API |
| 仿函数 + 配接器 | ✓ | ✓ | 低（16 个 mem_fun）| 算术/比较仿函数沿用至今 |
| lambda（C++11+） | ✓ | ✓（捕获） | 高 | 全面替代 |

temporary_buffer 的「腰斩」策略换来**永不失败**（malloc 一次比一次小）：稳定排序最坏退化为
多轮外部归并而非抛异常——「优雅降级」在标准库里的稀有样本。⚠️ SGI merge 是否真用满此降级路径
未逐行核实，此处按公开注释与函数签名陈述。

## 相邻概念对比

- **配接器 vs 容器适配器**：同名不同族——`stack` 改的是「容器接口」，`bind1st` 改的是「函数/迭代器接口」；
  书第 8 章讲后者为主，04 篇的 stack/queue 是前者的近亲。
- **`not1` vs `not_fn`**：C++17 用变参 `std::not_fn` 一个模板顶掉 not1/not2 两件，也宣告
  「靠 typedef 证书萃取」路线的死刑（不需要类型信息了）。
- **`bind1st` vs 偏函数**：绑定顺序（1st 焊左、2nd 焊右）是语义学坑——对 `less` 而言
  `bind2nd(less(), 5)` 是 `x<5`，`bind1st` 才是 `5<x`；工业代码因此更信 lambda。
- **reverse_iterator 的「负偏移」**：`base()` 与 `operator*` 差一格（`&*rit.rbegin() + 1 == &*begin`）——
  与 `upper_bound` 返回值配对的 `insert(ub.base(), x)` 惯用法即建立在这个错位上（机制转述）。

## 最新演进与工业实践

- **退役名单（C++17 移除 / C++11 弃用）**：`ptr_fun`、`bind1st/2nd`、`not1/not2`、`mem_fun(_ref)` 系、
  `unary_function/binary_function`（C++11 起弃用 ⚠️ 提案编号未核实，此为标准与三家实现公认年表；
  libstdc++ 出于 ABI 兼容仍保留部分定义——本机 g++ 15.2 `<bits/stl_function.h>` 可见）。
  替代品：**lambda + `std::function`/`bind`（慎用）**；理由与代价见 [../Effective_Modern_C++.md](../Effective_Modern_C++.md) 30/31 条。
- **ranges view（C++20）吃掉迭代器适配器**：`v | views::reverse | views::filter(pred) | views::take(3)`
  取代 reverse_iterator + 手写谓词组合；`views::transform(f)` 即 compose 的语言化。
  `iota_view` 补上「生成型 input 迭代器」的标准化。参考实现 [ericniebler/range-v3](https://github.com/ericniebler/range-v3)。
- **auto_ptr → unique_ptr/shared_ptr**：所有权语义显式化（move 转手、禁拷贝）；
  `std::default_delete` 对应 auto_ptr 的 `delete`，删除器则补上「池归还」缺口（02 篇 pmr 视角）。
  对象模型里成员函数指针的真实宽度（虚/非虚/多重继承各异）见 [../深度探索C++对象模型.md](../深度探索C++对象模型.md)——
  那正是 mem_fun 矩阵存在的底层原因。
- **temporary_buffer 的后裔**：`std::get_temporary_buffer` 在 C++17 弃用、C++20 移除
  （三家实现一致；⚠️ 提案号未核实）——因为算法改由 `allocator` 取临时内存（`uninitialized` 家族换防），
  概念上正呼应 SGI「临时缓冲必须可失败降级」的设计被更严格的分配协议取代。
- **工业实践**：新代码写策略参数直接用「可调用对象 + `auto` 形参」（C++20 模板简写），
  不再要 typedef 证书；fmt（[fmtlib/fmt](https://github.com/fmtlib/fmt)）演示了「编译期格式串」如何替代
  ostream_iterator 系在日志/输出场景的角色（编译期检查、性能更好）。

## 常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | `for_each(v.begin(),v.end(), &String::size)` 可行 | 元素是指针时必须 `mem_fun`；C++11 后 lambda `[](String* s){return s->size();}` 最直白 |
| 2 | bind1st 把值绑在「第一个实参位」 | 语义正确但方向反直觉：`bind1st(op, v)` → `op(v, x)`，v 占左位——x 是第二个参数；`<functional>` 文档多年被读反 |
| 3 | auto_ptr 放进容器没问题 | 拷贝转所有权 → sort/swap 一来对象失踪；C++98 时代戒律「auto_ptr 不得入容器」 |
| 4 | stable_sort 失败会抛异常 | SGI 用临时缓冲降级为多轮归并；**拿不到内存照样稳定**，只是慢（见机制节 ⚠️ 注） |
| 5 | 算法不改变容器大小 | `copy(v.begin(),v.end(), back_inserter(w))` 里 w 在长——插入迭代器解除了「输出区间必须预先足够大」的约束 |
