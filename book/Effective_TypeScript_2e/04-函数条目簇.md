## 本簇条目地图（⚠️ 凭记忆条旨，非逐字）

- **条旨1**｜重载签名是「给编译器看的目录」，实现签名才是唯一真身——能 union/交叉表达的不要重载。
- **条旨2**｜优先联合参数而非多重载：`(x: A | B) => R` 一个签名收敛全部现实。
- **条旨3**｜回调参数别写全：JS 实参按位置喂，多余的「被忽略参数」是协议的一部分 ⚠️。
- **条旨4**｜函数类型的参数逆变检查挂在 `strictFunctionTypes`；方法简写形式逃逸该检查 ⚠️。
- **条旨5**｜`this` 三条路：方法 shorthand、`this: void` 标注斩乱麻、箭头函数固捕获 ⚠️。
- **条旨6**｜`void` 返回的回调可以被任何返回值类型顶替（assignability 特例），别指望拿它约束。
- **条旨7**｜剩余参数 + 元组类型表达函数签名形状（`(...args: [A, B])`），2e 应有专条 ⚠️。

## 跨语言裁决

**裁决1｜TS 重载 ≈ Java 重载的「假亲戚」。**
Java 重载在字节码里是不同签名的真实方法（运行时按签名分派）；Kotlin 同理且默认参数是**真语法**
（对照 [../Effective_Kotlin/01-命名与注释.md](../Effective_Kotlin/01-命名与注释.md) Item ⚠️4
命名参数——JVM 上有真载体）。TS 重载声明**一条都不产**：实测 E6——`fmt` 两个重载声明 + 一个实现，
运行时 `(fmt as Function).length = 1`（只剩实现签名的 arity），`fmt(1, 2)` 多传参数**不报错**，
返回 `"1"` ✅。分派逻辑若不写在实现的 if/switch 里，就是薛定谔的分派。公理落点：重载表是
纯编译期文档，运行时世界是单函数 + JS arguments 混沌。

**裁决2｜EJ Item ⚠️「limit overload 使用」（本仓无 Effective Java 档，推定）在 TS 反向放大。**
Java 里 overload 至少运行时真实存在、坑在装箱/协变返回；TS 里正确姿势几乎总是
「单签名 + 判别式参数 + 体内收窄」（簇 02 联动）——因为参数联合类型在编译期被检查、
在运行时由手写分支兑现，两头都有抓手；重载声明两头都虚。

## 🔧 成对反例

坏味道（把声明当行为）：
```ts
function fmt(x: number): string;
function fmt(x: string): string;
function fmt(x: number | string): string { return String(x); }
// 调用方以为有两个世界，运行时只有一个：
// E6 实测：fmt.length=1；fmt(1, 2 as any) 照常执行 ✅
```
修正（一个签名 + 显式判别 + 元组约束调用形状）：
```ts
type Log = (...args: [level: "info" | "error", msg: string]) => void;
const log: Log = (level, msg) => console.log(`[${level}] ${msg}`);
// 联合参数：编译期收窄在体内做；元组标签参数=自文档化签名
```
`this` 反例（借来的方法丢 this）⚠️ 凭记忆：解构/`const f = obj.m; f()` 运行必炸 undefined——
这不是类型层能救的，是公理主场（`this` 是 JS 运行时机制，TS 只是事后标注）。

## 中英对照

| 中文 | 英文 | 一句定义 |
| --- | --- | --- |
| 重载签名 | overload signature | 编译期目录，运行时零存在 ✅ |
| 实现签名 | implementation signature | 唯一被 JS 执行的真身 |
| 参数逆变 | parameter contravariance | 函数子类型对参数方向反转的检查 ⚠️ |
| 回调协议 | callback protocol | 忽略多余实参的 JS 传统约定 |
| 元组类型 | tuple type | 定长带位签名的数组形状 |
| 标签元组参数 | labeled tuple elements | 函数签名的自文档位 ⚠️ |
| this 标注 | `this: void` | 声明「我不吃 this」的隔离条 |
