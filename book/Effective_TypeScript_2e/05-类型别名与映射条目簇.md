## 本簇条目地图（⚠️ 凭记忆条旨，非逐字）

- **条旨1**｜类型别名是**透明别名**不是新类型：`type Meters = number` 挡不住把秒当米传——对照 nominal 语言（Java 类、Kotlin value class）。
- **条旨2**｜用具名别名把「意图」写进类型（文档化类型），但别误以为获得了名义安全 ⚠️。
- **条旨3**｜交叉类型合并形状、联合类型选择形状：先定代数方向再动手 ⚠️。
- **条旨4**｜映射类型 = 类型层的 for 循环：`{ [K in Keys]: V }` 机械变换形状。
- **条旨5**｜条件类型 + `infer` 提取内部类型（函数参数、Promise 包裹层、数组元素）。
- **条旨6**｜模板字面量类型把字符串语法升格为类型代数（`` `${T}_id` ``）——2e 增补带 ⚠️。
- **条旨7**｜`satisfies` 双向检查：值满足类型的同时保留更窄推断——2e 增补带 ⚠️。
- **条旨8**｜类型级计算要设止损线：递归深度、报错可读性、工具链兼容都是成本 ⚠️。

## 跨语言裁决

**裁决1｜C++ 模板单态化「消灭类型层并变出真代码」，TS 映射类型「消灭类型层并变出零」。**
专题档对照表第四列：C++ 模板编译期直接变成机器码形状，运行时全是真函数；TS 的映射/条件/模板
字面量类型同样只在编译期运转，但**不产一行代码**。实测 E7：`type Mapped = { [K in Keys]: Templ<K> }`、
`InferEx` 条件推断、`satisfies` 标注混写一文件，strip-types 直跑 exit=0，运行时零痕迹
（`Object.getOwnPropertyNames(globalThis)` 不含 Mapped，✅）。对照
[../Effective_Modern_C++/01-类型推导.md](../Effective_Modern_C++/01-类型推导.md) 与
[../C++20模板元编程/](../C++20模板元编程/) 世界观：C++ 的 `concept`/SFINAE 报错是编译期灾难同族，
但产出物真实；TS 类型级迷宫的代价是**纯机会成本**——算得再深，运行时仍是一层裸 JS。

**裁决2｜Kotlin `typealias` 同样透明，但 Kotlin 备有逃逸舱（value class / `reified T`），TS 的名义化要自己造。**
TS 想要「Meters 不等于 Seconds」只有品牌化 hack（`number & { __brand: "m" }` ⚠️ 惯用法非逐字）
或把值编码进对象（公理推论3）。EJ/EK 教义「包装类/内联类优于裸标量」在 TS 全部降级为运行时
分配决策：要么付对象开销，要么放弃名义安全——这是四语言对照表（专题档第二节）在别名带的投影。

## 🔧 成对反例

坏味道（类型级过度工程 + 误信别名有名义性）：
```ts
type Deep<T> = T extends (infer U)[] ? Deep<U>[number][] : T;  // 迷宫示例
function drive(m: Meters, s: Seconds) {}   // type Meters = number; type Seconds = number
drive(5, 10);                              // 传反了也「安全」——别名透明，检查无处落脚
```
修正（透明别名诚实标注 + 需要名义时用品牌/编码进值）：
```ts
type Brand<T, B extends string> = T & { readonly __brand: B };  // ⚠️ 社区惯用法
type Meters = Brand<number, "m">;
const m = 5 as Meters;                     // 转换点集中，混用当场红波浪线（仍仅编译期 ✅E7 机理）
```
