## 本簇条目地图（⚠️ 凭记忆条旨，非逐字）

- **条旨1**｜理解结构类型的本质：形状兼容即类型兼容，与「名字相同才兼容」的名义语言决裂。
- **条旨2**｜interface 与 type 对象的选法：多数场景等价，扩展/交叉需求决定顺位 ⚠️。
- **条旨3**｜可选属性 `?` ≠「键可能缺失」：它允许 `a: undefined` 显式占位，两态在运行时并存。
- **条旨4**｜`readonly` 是编译期礼貌，运行时不冻结（与 `Object.freeze` 分账）。
- **条旨5**｜TS `private` ≠ JS `#`：前者纯类型层访问标记，后者运行时硬墙——类设计重灾区。
- **条旨6**｜子类型与可替代性：多余属性通过结构检查（宽对象可顶窄对象），别指望名义隔离。
- **条旨7**｜对象字面量的多余属性检查只针对「新鲜字面量」，绕道变量即失效 ⚠️。
- **条旨8**｜索引签名/`Record` 表达开放形状，与精确形状之间用映射衔接（深入见簇 05）⚠️。

## 跨语言裁决

**裁决1｜Kotlin `data class` 真生成 equals/hashCode，TS 的「形状相同即相等」只活在类型层。**
公理落点（Runtime vs Type System 专题推论5）：TS 运行时**无相等协议**——两个类型互相兼容的
对象做 `===` 比的是引用，`deepEqual` 要手写或借库。EK 侧对应操盘是
[../Effective_Kotlin/03-集合与解构.md](../Effective_Kotlin/03-集合与解构.md) Item ⚠️25
「Pair 超两个升级 data class」——Kotlin 的结构相等是编译器产的**真代码**，TS 的等价物永远是
类型幻觉。故 TS 裁决：需要值语义时显式编码（手写 equals 或序列化后比对），不要假设结构类型带来结构相等。

**裁决2｜EJ「minimize mutability」（⚠️ Item 15 推定，本仓无 Effective Java 档）在 TS 降级为「双重合同」。**
Java 的 final 字段 + unmodifiable 视图有运行时背书；TS 的 `readonly`/`Readonly<T>` 全部擦除。
实测 E4（簇 02 同脚本）：`as const` 对象运行时照样改写字段、`Object.isFrozen=false` ✅。
所以 TS 侧的不可变裁决必须拆两行写：编译期防误用（readonly）+ 运行时防篡改（freeze），缺一即裸奔。

## 🔧 成对反例

坏味道（把可选属性当「键不存在」协议——以下为 E9 原样实测脚本）：
```ts
interface Opt { a?: number; b: number }
const o: Opt = { b: 1 };
o.a = undefined;                 // 类型层完全合法
console.log("a" in o);           // true —— 「有 a 键」！
JSON.stringify(o);               // "{"b":1}" —— undefined 值在序列化世界蒸发
delete (o as any).a;             // 想回到「缺键」只能手动删
```
实测 E9：`"a" in o = true`、`Object.keys` 含该键、`JSON.stringify` 丢键、`delete` 后 `in` 才 false ✅。
「可选」在运行时是**三态**（缺键/undefined 键/有值键），`in`、`for...in`、JSON 轮询各看不同面。
修正（把「缺键 vs undefined」的裁决写回结构层）：
```ts
function send(o: Opt) {
  if ("a" in o) { /* 键在（哪怕值是 undefined）走这条 */ }
  else { /* 真缺键走这条 —— in 是运行时真判别，不违反公理 */ }
}
```
另引专题档基线：`private` 字段运行时 `Object.getOwnPropertyNames` 全露、`#` 才隐藏 ✅
（[../TypeScript系列·Runtime_vs_Type_System专题.md](../TypeScript系列·Runtime_vs_Type_System专题.md) 实验 A）。

## 中英对照

| 中文 | 英文 | 一句定义 |
| --- | --- | --- |
| 结构类型 | structural typing | 按形状而非名字判定兼容 |
| 名义类型 | nominal typing | 名字不同即不兼容（对照面） |
| 可选属性 | optional property (`?`) | 允许 undefined 的宽授权，非缺键承诺 ✅ |
| 只读属性 | readonly property | 编译期写保护，运行时零动作 ✅ |
| 私有字段 | `private` vs `#` | 类型层礼貌 vs 运行时硬墙 ✅ |
| 多余属性检查 | excess property check | 仅新鲜字面量享受的一次性严格 ⚠️ |
| 索引签名 | index signature | 开放形状的兜底描述 |
