## 1. `_delta_log` 文件家族（⚠️ 文档转述）

```text
表根/_delta_log/
  00000000000000000000.json  ← 每提交一个，20 位零填充 = 版本号
  00000000000000000009.checkpoint.parquet ← 每 10 提交重放物化
  000...10checkpoint.d.json  ← 增量 checkpoint
  last_checkpoint / _commitInfo-*.parquet（侧车，统计）
```

读表的定义性动作：取 `last_checkpoint` → 加载其后所有 commit JSON → 得当前版本
**活动文件列表**。日志是真相，parquet 只是载体（DG 00 与
[../Engineering_Lakehouses_with_Open_Table_Formats/05-DeltaLake表格式机制.md](../Engineering_Lakehouses_with_Open_Table_Formats/05-DeltaLake表格式机制.md) 同款强调）。

## 2. 一次提交的 JSON 动作集（⚠️ 转述 PROTOCOL.md）

commitInfo（时间/操作者/指标）、txn（幂等：流式提交用 appId+version 去重）、
add / remove（文件进/出，带 partitionValues、stats min/max、dataChange 标志）、
metaData（schema/分区/属性）、protocol（读写特性版本）。**更新一行的物理真相**：
add 重写后的新文件 + remove 旧文件（COW）；开 Deletion Vectors 后变 add 一个 DV 位图
（05 章，对照 Iceberg 的 MOW 删除文件
[../Apache_Iceberg活用入門/05-行级删除与删除文件.md](../Apache_Iceberg活用入門/05-行级删除与删除文件.md)）。

## 3. 提交协议：对象存储上的乐观并发（⚠️ 转述）

写者流程：并发生成数据文件 → 尝试把 `version=N.json` 以**条件 put**
（"仅当不存在"）写入 → 成功即提交；失败则：

1. 若 N 已被别人填上 → 读该 commit，做**冲突检查**；无冲突则基于新状态
   重算本提交的 add/remove，N++ 再试（可循环多次）；
2. 有冲突 → 抛 `ConcurrentAppendException` 类错误，作业失败。

没有锁、没有协调服务——与 MySQL 的意向锁/两阶段锁完全不同谱系
（对照 [../mysql/19-redo日志.md](../mysql/19-redo日志.md)：redo 管"介质故障恢复"，
Delta 日志管"逻辑版本即恢复"，见 [../数据库系统概念6/16-恢复系统.md](../数据库系统概念6/16-恢复系统.md)）。
跨文件引擎对比在 [../Engineering_Lakehouses_with_Open_Table_Formats/06-事务与并发写.md](../Engineering_Lakehouses_with_Open_Table_Formats/06-事务与并发写.md)。

## 4. 隔离级：默认可串行化，RC 可选（⚠️ 转述 + 🔧 演示对照）

- 读侧：单查询固定读一个版本快照 = **快照隔离**（不脏读、不可重复读被消灭）。
- 写写侧：协议保证可串行化（冲突即败）。
- 可选 Read Committed 外部 API（流式微批消费场景，05 章的 txnAction 基础）。
教科书对表：[../数据库系统概念6/15-并发控制.md](../数据库系统概念6/15-并发控制.md) 的
序列化图论在"以文件为粒度、以日志为调度器"下重演。

## 5. 🔧 实测：sqlite3 手写迷你"版本表 + 快照读"（本机真实跑过）

**方法**：Python 内置 sqlite3（**3.45.3**，Windows），库文件 16 KB；
两张表模拟日志与数据：`commits(version,ts,op)` + `data(file_id,row_id,val,added_v,removed_v)`；
快照读谓词：`added_v<=V AND (removed_v IS NULL OR removed_v>V)`；
每提交包一层 `BEGIN IMMEDIATE…COMMIT`。全过程 5.46 s（fsync 主导），关键读数：

| 动作 | 版本 | 快照读结果（实测逐值） |
| --- | --- | --- |
| WRITE 3 行 | v1 | `[(1,a),(2,b),(3,c)]` |
| UPDATE 行2（COW：旧行 removed_v=2 + 新行 b2） | v2 | `[(1,a),(2,b2),(3,c)]` |
| DELETE 行1 | v3 | `[(2,b2),(3,c)]` |
| MERGE（行3→c3 + 插入行4，单提交两动作） | v4 | `[(2,b2),(3,c3),(4,d)]` |
| VACUUM（清 removed_v<5 的死版本 3 行） | v5 | v4 不受影响；**v2/v3 时间旅行被毁**：同谓词回看只剩 `[(2,b2)]` |
| CHECKPOINT（v4 物化为 cp 表） | — | 3 行，"日志重放"换"直读" |

三点结论（🔧）：① "版本表 + 有效区间 + 谓词读"最小 20 行代码就复现了 Delta 的
逻辑视图语义；② VACUUM 毁历史不是比喻——保留窗口外旧版本**静默给错数据**而非报错
（Delta 用 `delta.deletedFileRetentionDuration` 默认 7 天约束这件事，04 章）；
③ 双连接并发：持写事务时第二连接 `BEGIN IMMEDIATE` **立刻 `database is locked`**——
SQLite 是悲观锁，Delta 是"先干活后比对、版本名互斥"的乐观协议，**语义等价、机制相反**。
脚本与输出存 `D:\develops\tmp\dbwave_w3_delta\demo_out.txt`（repo 外）。

## 6. ducklake 对照（复用姊妹目录实测，注明来源）

[../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md](../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md)
的 🔧 实测（本册**不复跑**）给出同语义第三坐标：

- 提交 = `ducklake_*` 元数据库里的快照递增（其 CTAS 581 万行 0.20 s、`ducklake_snapshots()` 列 (0,t0)/(1,t1)）；
- 时间旅行只认 `AT (VERSION => n)` 语法（其实测四种写法三败）；
- **"提交即落文件"是错觉**：DuckLake 数据可长期内联在元数据库、DATA_PATH 空目录
  ——对照 Delta"日志是真相、文件列表只是投影"，方向恰好相反：DuckLake 把真相收进
  数据库（=回到单写者锁世界，其跨源写陷阱自注），Delta 把真相摊在存储上（=换来多引擎）。
- 21 个 `ducklake_*` 维护函数（flush/expire/cleanup/snapshots 分层）≈ Delta 的
  VACUUM/OPTIMIZE/RESTORE/DESCRIBE HISTORY 家族。
选型含义：**要协议开放与多写引擎 → Delta 式日志；要单机零运维 → DuckLake 式目录内化**
（四格式三角的谱系位置参见 06 章）。

## 7. 常见误区

| 误区 | 修正 |
| --- | --- |
| "_delta_log 是 WAL，恢复时重放数据" | 它是**元数据版本史**，数据文件从不重放；恢复=挑版本 |
| "文件名有版本号就防冲突了" | 版本号防"双双自称 N"；数据冲突仍靠可串行化比对（§5 演示的谓词即比对物） |
| "乐观并发=永不失败" | 热分区上两写者必有一方重试或抛错；写放大随重试涨 |
| "checkpoint 只是缓存可删" | 删了功能不坏但读放大爆炸：每次开表重放全部 JSON |

## 核心概念速览（中英对照）

- **事务日志** — Transaction Log：`_delta_log` 下按版本号排列的提交序列。
- **提交文件** — Commit File：`N.json`，一次 ACID 提交的原子单位（条件 put 写入）。
- **动作** — Action：commit 内条目类型（commitInfo/txn/add/remove/metaData/protocol）。
- **活动文件集** — Active Files：某版本下 add 未 remove 的文件闭包，= 快照内容。
- **检查点** — Checkpoint：每 10 版物化日志，读放大 O(1) 化。
- **侧车文件** — Sidecar：commit 统计信息外置，保持 JSON 轻小。
- **乐观并发控制** — OCC：先写后比对，版本名互斥裁决，冲突者重试或败。
- **可串行化** — Serializable：默认写写保证；读为快照隔离。
- **读已提交 API** — ReadCommitted 外部流：以 txn 幂等消费提交序列。
- **条件写** — Conditional Put：对象存储"不存在才写"的原语，日志的地基。
- **有效区间谓词** — added_v≤V<removed_v：🔧 迷你实现快照读的 WHERE 形状。
- **内联数据** — Inline Data（DuckLake 实测③）：真相暂存元数据库的相反取舍。
