## 1. medallion 的工程账（⚠️ 转述）

bronze（不可变原始，1:1 落地）、silver（清洗/去重/MERGE 对齐，业务实体）、
gold（聚合 mart）。每层是同一事务日志家族里的不同表（02 章协议复用），
层间用流推进（05 章）。三条工程账：

- **新鲜度**：每层加一跳提交节拍，端到端延迟累加；
- **重放半径**：silver 逻辑错 → bronze 重放；bronze 脏 → 上游重抽——分层即隔离爆炸半径；
- **成本**：三层存储 × VACUUM 窗口（04 章）= 静态账单主体。
重放机制首选 availableNow + 幂等 MERGE（05 章 §2/§3），不是"改数据手改"。
medallion 的完整参考纵深 → [../Delta_Lake_Definitive_Guide/08-湖仓架构-Medallion.md](../Delta_Lake_Definitive_Guide/08-湖仓架构-Medallion.md)。

## 2. 参考架构一页图（教学示意）

```text
Debezium/Kafka ─┐
API/DB 快照    ─┼→ ingest(微批/availableNow) → bronze ─MERGE→ silver ─聚合→ gold → BI/ML/Feature
文件/IoT       ─┘        （_delta_log 全链路版本化，CDF 再分发）
治理面：Unity Catalog（或 Polaris/LakeFS 生态位）→ 权限/血缘/共享
```

"表格式之下、平台之上"的空档（谁管运维小账）由 04 章维护三件套 + 02 章冲突治理填。

## 3. 治理面：格式管不了的事交给 catalog

Delta 表原生只承诺：ACID/旅行/schema 承诺（03 章"半硬约束"的兑现方也多是治理层）。
行级权限、脱敏、血缘、发现——Unity Catalog（Databricks 系，2024-06 OSS 化 ⚠️）或
Iceberg REST 阵营（Polaris/Gravitino 等）。DG 用两章讲 UC 治理与血缘
（[../Delta_Lake_Definitive_Guide/11-治理安全与数据血缘.md](../Delta_Lake_Definitive_Guide/11-治理安全与数据血缘.md)），
本册只立坐标：2026 年 delta.io 官方"Kernel+UC Delta APIs"与 catalog-managed tables
两篇博文（✅ URL 见 §6 末）标志**提交协议开始上移 catalog**——02 章"对象存储抢版本号"
的经典图景在托管形态下让位于"catalog 裁决"。治理谱系的元数据目录学另见
[../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md)（联邦治理一翼）。

## 核心概念速览（中英对照）

- **medallion** — 奖牌分层：bronze/silver/gold 的精炼流水线。
- **重放半径** — Replay Blast Radius：分层隔离错误传播的工程账。
- **新鲜度预算** — Freshness Budget：逐跳提交节拍的延迟累加。
- **catalog 裁决** — Catalog-managed Commit：提交协议从对象存储上移到 catalog 服务。
- **Unity Catalog** — Databricks 发起的治理层（OSS 化中）：权限/血缘/发现。
- **Delta Sharing** — 开放跨组织共享协议：预签名文件面。
- **格式中立** — Format Neutrality：Iceberg REST 生态的核心卖点。
- **DV 同型收敛** — Deletion Vector Convergence：三格式不约而同的位图删除。
- **选型三问** — 主写引擎/新鲜度/中立性：矩阵之外的判据。
- **入门实操 vs 全面参考** — 本册与 DG 的分工一句话版。
- **单机湖仓** — DuckLake 位（🔧 引注）：概念同款、体量最小的对照系。
