## 1. 流读：把提交序列当日志消费（⚠️ 转述）

```python
(spark.readStream.format("delta")
      .option("ignoreChanges", "true")   # 语义取舍见 §6 误区
      .load("/mnt/silver/orders"))
```

机制：流引擎每轮轮询 `_delta_log` 的新版本，把"新 add 文件"作为本轮增量（02 章
txn 动作保证重启幂等）。新鲜度 = 触发间隔 × 提交节拍——**Delta 流的粒度是提交，
不是行**；要秒级以下就得问 Kafka/Paimon 式 changelog（§6 表，
[../Apache_Paimon_Streaming_Lakehouse/07-Changelog生成机制.md](../Apache_Paimon_Streaming_Lakehouse/07-Changelog生成机制.md)）。

## 2. 流写：mergeStream + foreachBatch MERGE（⚠️ 转述）

```python
def upsert(batch_df, batch_id):
    (batch_df.createOrReplaceTempView("b")
     or spark.sql("""
       MERGE INTO orders t USING (SELECT * FROM b) s
       ON t.id=s.id WHEN MATCHED THEN UPDATE SET *
       WHEN NOT MATCHED THEN INSERT *"""))
df.writeStream.format("delta").foreachBatch(upsert).option("checkpointLocation", ck).start()
```

幂等三保险：checkpoint（查询进度）+ txn 动作（提交去重）+ MERGE（内容对齐）。
"精确一次"在这里 = **端到端效果一次**（外部效果靠幂等，不是靠分布式事务）。
同题 Iceberg 工程在 [../Architecting_an_Apache_Iceberg_Lakehouse/06-摄入层架构.md](../Architecting_an_Apache_Iceberg_Lakehouse/06-摄入层架构.md)（波内兄弟实链）。

## 3. availableNow：批与增量的统一节拍（⚠️ 转述）

`Trigger.AvailableNow()`（Spark 3.3+/Delta 2.x 配套）：把"全部历史"当有限流一次性
消费完即停——回填(replay)与追平(catchup)同一段代码。medallion 重放场景（06 章）的
工程支点。旧写法 `.trigger(once=True)` 的"单轮"语义与之有别（⚠️ 精确差异以当期文档为准）。

## 4. CDF：表自己吐出变更流（⚠️ 转述）

```python
spark.read.format("delta").option("readChangeFeed", "true")
  .versionAsOf(10).versionAsOf(20).load(path)   # 区间内 _change_type/_commit_version/_commit_timestamp
```

- 写侧 `tableUpdates` 流式 CDF；`_change_type ∈ {insert, update_preimage, update_postimage, delete}`
  ——即 Flink 口径的 +I/-U/+U/-D 四件套（对照
  [../Apache_Paimon_Streaming_Lakehouse/07-Changelog生成机制.md](../Apache_Paimon_Streaming_Lakehouse/07-Changelog生成机制.md) 的
  原生 changelog：Delta 靠"读时比对前后镜像"补，Paimon 靠 LSM 合并时"顺手生成"，两种世界观）。
- 保留窗口独立于 VACUUM（`delta.tableFeature.updateChangesEnabled` 类参数 ⚠️）；
  下游位点管理薄——消费慢于窗口即断供（§6）。

## 5. Deletion Vectors：把删除从重写变成旁路（⚠️ 转述 + 格式对表）

`delta.enableDeletionVectors`（3.0+，writer feature）：DELETE/UPDATE/MERGE 不再
COW 整文件，而是给旧文件配位图标记死行；读时过滤，OPTIMIZE 时物理消化。
收益：高频 MERGE 表写放大骤降（03 章 §4 的成本模型被改写）；
代价：DV 文件增殖需清理、非 DV-aware 的旧引擎读不了（protocol 动作拒绝——02 章
特性声明的用武之地）。跨格式对照：Iceberg MOW position-delete（
[../Apache_Iceberg活用入門/05-行级删除与删除文件.md](../Apache_Iceberg活用入門/05-行级删除与删除文件.md)）、
Paimon DV（[../Apache_Paimon_Streaming_Lakehouse/09-Compaction与删除向量.md](../Apache_Paimon_Streaming_Lakehouse/09-Compaction与删除向量.md)）——
**三格式在 2024–2026 不约而同走向"base 文件 + 删除位图"**，收敛即定论。

## 7. 常见误区

| 误区 | 修正 |
| --- | --- |
| "ignoreChanges=true 白拿幂等" | 它静默吞掉上游删除——正确性交给 MERGE 重刷时才配 |
| "流读延迟 = Kafka 级" | 受提交节拍钳制；高频写与新鲜度互相踩踏（02 章冲突 + 小文件） |
| "CDF 想读多远读多远" | 超保留窗口即断供；位点与窗口的协同同 04 章 VACUUM 教训（🔧 迷你版直觉可迁） |
| "开了 DV 就永远不用 OPTIMIZE" | DV 只是延迟重写；位图攒厚照样吃读性能与清理配额 |
| "checkpoint 目录随便指" | 换目录=换查询身份：txn 幂等链断，轻则重放重、丢则位点乱 |

## 核心概念速览（中英对照）

- **增量读** — Incremental Read：按版本枚举新文件的流式源。
- **触发器** — Trigger：processing-time/availableNow/once 的节拍定义。
- **foreachBatch** — 微批 sink 钩子：每批跑一次 MERGE 的挂点。
- **端到端一次** — Effectively-once：checkpoint+txn+幂等写的合成语义。
- **CDF** — Change Data Feed：表级变更流（含 pre/post image）。
- **_change_type** — 变更类型列：insert/update_preimage/update_postimage/delete。
- **Deletion Vector** — 删除向量：文件级位图旁路死行，MOW 的 Delta 形态。
- **writer feature** — 写特性：protocol 声明的兼容性门禁（DV/CDF 等）。
- **ignoreChanges** — 读端吞删除选项：用正确性换鲁棒性的双刃剑。
- **image 语义** — pre/post image：retract 流在湖侧的替身。
- **提交粒度** — Commit Granularity：Delta 流新鲜度的物理下限。
- **位点** — Offsets/Checkpoint：流查询的进度身份，目录即人格。

- **Flink/多引擎流式**：flink-delta 连接器支持流读流写（✅ 仓库族在 delta-io 名下，
  https://github.com/delta-io/delta 200 已验）；与 Flink 原生 changelog 的分工：
  Delta 管"提交即版本"，changelog 语义靠 CDF 补齐（对照 Paimon 原生路线）。

  方案（选型三角见 [06-湖仓架构与格式选型.md](06-湖仓架构与格式选型.md)）。
