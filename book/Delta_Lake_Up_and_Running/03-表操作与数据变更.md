## 1. 建表与写入模式（⚠️ 文档转述）

```sql
-- 教学示意，非书中原文
CREATE TABLE delta.`/mnt/bronze/events` (id LONG, ts TIMESTAMP, payload STRING)
  USING DELTA PARTITIONED BY (days(ts));
CREATE TABLE IF NOT EXISTS t AS SELECT * FROM src;      -- CTAS
CREATE OR REPLACE TABLE t AS SELECT * FROM src2;        -- 换内容不丢历史(旧版本仍在日志)
```

DataFrameWriter 的 `append/overwrite` + `partitionBy` + `.option("mergeSchema")` 组合，
以及 DeltaTable builder API，SQL/DataFrame 双入口等价（⚠️ 转述）。`overwrite` 的
`partitionOverwriteMode=static|dynamic` 决定"覆盖整表还是只覆盖来犯分区"——
幂等回刷作业的第一开关（🔧 迷你版语义：02 章 `UPDATE data SET removed_v=? WHERE 谓词`
后只 add 同分区新行，即可复现"分区级替换"）。

## 2. 约束与默认值：从"无"到"半硬"

| 机制 | 强度 | 备注 |
| --- | --- | --- |
| NOT NULL | 硬（默认全列可空性受控） | schema enforcement 的一部分 |
| CHECK | 硬（写入侧拒绝） | Delta 3.0+ 转正（✅ 3.0 博 URL 见 02 章） |
| GENERATED ALWAYS（identity/表达式） | 半硬 | 生成列不可手填；identity 做代理主键 |
| PRIMARY KEY / FOREIGN KEY | **声明性**（ENFORCED NOT VALIDATED） | 给优化器/血缘看的注解，不校验存量——与真数据库的约束差一个时代（对照 [../Relational_Theory_for_Computer_Professionals/00-总览与阅读地图.md](../Relational_Theory_for_Computer_Professionals/00-总览与阅读地图.md) 一系的约束世界观） |

"约束是元数据承诺、不是引擎执法"是湖仓表与 OLTP 库最容易踩穿的一层认知差。

## 3. 分区与生成分区（⚠️ 转述）

- 传统：`PARTITIONED BY (dt STRING)` 手工塞日期字符串——分区爆炸与类型丢失的老坑。
- 演进：生成列分区 `PARTITIONED BY (days(ts))` / `months(ts)`（Delta 2.0+）：
  用户不再手填，读端谓词带 `ts` 即可裁剪到分区——隐藏分区的 Iceberg 版本见
  [../Apache_Iceberg活用入門/03-隐藏分区与分区演化.md](../Apache_Iceberg活用入門/03-隐藏分区与分区演化.md)。
- 布局与裁剪的物理层账：文件 min/max stats + data skipping（[../bigdata/09-存储与文件格式.md](../bigdata/09-存储与文件格式.md)）。

## 4. CRUD：每条"行级"语句背后都是文件重写

```sql
DELETE FROM t WHERE id = 42;                    -- 读旧文件→写新文件→日志 remove/add
UPDATE t SET score = score + 1 WHERE uid = 7;   -- 同上，谓词内全体重写
```

⚠️ 转述：未开 DV 时 `UPDATE/DELETE/MERGE` 的写放大 = 谓词命中的**文件**总大小，
不是行数——"改一行重写一文件"。Deletion Vectors 把删除变成位图旁路（05 章），
写放大与读性能同时改善；Iceberg 的 MOW position-delete 是同题异卷
（[../Apache_Iceberg活用入門/05-行级删除与删除文件.md](../Apache_Iceberg活用入門/05-行级删除与删除文件.md)），
Hudi/Paimon 则给 COW/MOR 与 LSM 两条岔路
（[../Apache_Paimon_Streaming_Lakehouse/02-核心数据结构LSM树与主键表.md](../Apache_Paimon_Streaming_Lakehouse/02-核心数据结构LSM树与主键表.md)）。

## 5. MERGE 全解（本章技术高峰）

```sql
-- 教学示意：经典 CDC 三拍
MERGE INTO silver AS t USING (
  SELECT * FROM cdc_staging WHERE __op <> 'R'          -- 排除读快照
) s ON t.id = s.id
WHEN MATCHED AND s.__op = 'D' THEN DELETE
WHEN MATCHED AND s.ts >= t.ts THEN UPDATE SET *        -- 乱序保护
WHEN NOT MATCHED AND s.__op <> 'D' THEN INSERT *;
```

- 三子句：`MATCHED`（可拆条件多支）、`NOT MATCHED`、`NOT MATCHED BY SOURCE`
  （源里消失的目标行——做"全量快照对齐"的杀手锏）。
- **确定性红线**：同一目标行被多源行命中且各支动作不一 → 报
  `Multiple_matched_rows`，作业失败而非悄悄任选（⚠️ 文档转述；🔧 迷你复现：
  02 章 `data` 表上 `UPDATE` 关联多行子查询即同款"一对多歧义"）。
- 幂等性：MERGE 单提交，重跑安全；`INSERT *` 与列级 `SET v=s.v` 的 schema 漂移差异
  在 03 节 enforcement 与 07 主题（schema 演进，本章 §7 摘要）交界处。
- 与 `INSERT OR REPLACE`/Hudi upsert 的语义差：MERGE 可以带任意 JOIN 谓词与多分支，
  "upsert"只是其退化形式。Paimon 的 merge-engine 是**声明式**替代（写时合并不问 SQL，
  [../Apache_Paimon_Streaming_Lakehouse/06-合并引擎.md](../Apache_Paimon_Streaming_Lakehouse/06-合并引擎.md)）。

## 8. 常见误区

| 误区 | 修正 |
| --- | --- |
| "MERGE 慢，不如 truncate+insert" | 小表全刷破坏历史且写放大更大；谓词对齐的 MERGE 才配得上日志 |
| "DELETE 完表就变小了" | 只是日志 remove；物理空间要等 VACUUM（04 章） |
| "分区列越多裁剪越准" | 分区爆炸先杀死列目录与 stats——先 data skipping 后分区 |
| "PK 声明了就能防重" | 不执法；防重靠 MERGE/写入方自律（§2 表） |
| "NOT MATCHED BY SOURCE 是方言" | 它是 Delta MERGE 相对标准 SQL:2003 的重要增强之一，做快照对齐刚需 |

## 核心概念速览（中英对照）

- **CTAS/RTAS** — Create/Replace Table As Select：以查询结果为表的建/换法。
- **分区覆盖模式** — partitionOverwriteMode：static 全表覆盖 vs dynamic 按来犯分区覆盖。
- **生成列** — Generated Column：`GENERATED ALWAYS AS` 表达式列，identity 与分区表达式的载体。
- **声明式约束** — Declarative PK/FK：只承诺不执法的键注解。
- **CHECK 约束** — Check Constraint：写入侧硬校验（3.0+）。
- **写放大** — Write Amplification：行级变更按文件粒度重写的代价。
- **MERGE** — Merge：USING 源 × ON 谓词 × 三子句的多分支同步语句，单提交原子。
- **Multiple Match** — 匹配歧义错误：一目标行被多源行命中即失败。
- **CDC** — Change Data Capture：INSERT/UPDATE/DELETE 事件流；入湖以 MERGE 收口。
- **SCD2** — 缓变维二型：拉链历史表，MERGE 双写（关旧开新）。
- **type widening** — 类型放宽：兼容性升级列类型不重写数据。
- **mergeSchema** — 选项：写入时自动并入新列的演进开关。

## 最新演进与工业实践

- **语法线**：MERGE 自 Delta 0.5 时代存在、`NOT MATCHED BY SOURCE` 于 1.x 加入；
  identity/生成列 2.x；CHECK/REPLACEWHERE 等 3.x（⚠️ 各条目精确版本以 docs.delta.io
  （✅ https://docs.delta.io/index.html）发布说明为准）。
- **DV 改变成本模型**：开 Deletion Vector 后 UPDATE/DELETE 写放大从"文件级"降到
  "位图级"，3.x 起成为高频修改表默认推荐（✅ https://delta.io/blog/delta-lake-3-0/）。
- **工业实践**：多引擎 MERGE 竞争格局——Trino/Spark/Flink 各自的 `MERGE INTO` 语义子集
  不完全一致，跨引擎管道要锁同一实现（定性 ⚠️）；dbt-delta/Fivetran 类工具默认姿势
  仍是"staging + MERGE"（转述）。选型对照可读
  [../Use_Iceberg_with_Spark/03-数据读写与MERGE-INTO.md](../Use_Iceberg_with_Spark/03-数据读写与MERGE-INTO.md)（Iceberg 侧同款工程）。
