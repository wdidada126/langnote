## 本书没覆盖的缺口（2026 视角）

- **客户端缓存（Client-side caching）**：Redis 6.0 tracking 机制；本书成书前该技术不存在。
- **Redis 多线程 I/O**：6.0 引入的网络层多线程，本书的「单线程」论断需修正为「单线程命令执行 + 多线程 IO」。
- **Valkey 与 Redis 分叉之争**：2024 年 Redis 许可证变更后的生态分裂；Valkey 已成为许多云厂商默认选择。
- **Dragonfly / KeyDB 等 Redis 兼容新内核**：线程级并行、内存效率的新实现。
- **云原生缓存服务**：AWS ElastiCache、阿里云 Tair（托管版）、腾讯云 Redis——本书讲自建，少谈托管。
- **缓存与一致性新范式**：write-behind + CDC（如 Debezium）保持缓存与 DB 一致，比书中的 Cache-Aside 更自动。
- **本地缓存新选择**：Caffeine（Java，取代 Guava Cache 的现代化方案，基于 Window TinyLfu）本书未出现。
- **跨语言对照**：Go 的 groupcache（Brad Fitzpatrick）、Go 生态 go-redis；Python 的 pylibmc / redis-py——本书偏 Java 生态。

## 实验工具链

- **压测**：`redis-benchmark`（Redis 自带）、`memtier-benchmark`（Redis Labs，可对比 Memcached/Redis）、`JMeter`（业务级压测）。
- **监控**：Redis `INFO` 命令 / `redis-cli --stat`、Memcached `stats` 命令、Prometheus + Grafana 采集缓存命中率/驱逐率/连接数。
- **本地验证缓存算法**：用 JUnit + 小型 LRU/LFU 实现跑命中率对照实验（代码均为**教学示意，不参与构建**）。
- **一致性验证**：用 `tc` / `iptables` 模拟网络分区，观察 Sentinel / Redis Cluster 的故障转移行为（仅本地沙箱，不连生产）。
