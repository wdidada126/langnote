## 1. 参数体系的 10g 地形（⚠️ 通说）

- 两类可见性：公开 `init.ora/spfile` 参数 vs 隐藏参（下划线族 `_latch_sleeps` 式）——隐藏参=厂商内部契约，本册体裁常抄录，2026 生产禁用未获 MOS 授权的隐藏参 ⚠️（红线）。
- 作用域三层：实例（`ALTER SYSTEM`）/会话（`ALTER SESSION`）/段对象（存储子句）——**能窄不宽**是本册反复出现的纪律 ⚠️。
- spfile（9i 末引入，10g 主流化 ⚠️）：`SCOPE=SPFILE/BOTH/MEMORY` 语义+`V$PARAMETER`（含 isdefault/ismodified 取证列）——"改了什么"第一次可由视图自证。
- 参数建议器：`V$_parameter`×ADDM 建议×`DBA_ADVISOR` 通道 ✅（B14211 Ch4/Ch6 域）——本册时代"参数贴士"正被产品化取代的起点。

## 2. 高频名录（本册时代×2026 状态两栏，⚠️ 名录+✅ 状态锚）

| 参数 | 10g 语境用途 | 2026 状态 |
|---|---|---|
| `db_cache_size`/`db_block_size` | 缓冲池/块制式 | 现役（ASMM 托管） |
| `shared_pool_size` | 池钉死 | 现役（多为下限语义） |
| `pga_aggregate_target`/`workarea_size_policy` | 自动 PGA | 现役（` PGA_AGGREGATE_LIMIT` 12c 加顶 ⚠️） |
| `memory_target`/`memory_max_target` | AMM | 现役但大机劝退（`03` 章） |
| `db_file_multiblock_read_count` | mbrc | 化石/不推荐手设 |
| `log_checkpoint_*`/`fast_start_mttr_target` | 检查点节拍 | MTTR 现役，interval 族淡出 |
| `sessions/processes` | 预算 | 现役 |
| `cursor_sharing` | 解析止血 | 现役（EXACT 为纲） |
| `session_cached_cursors` | 句柄缓存 | 现役 |
| `statistics_level` | 自动数据总闸 | 现役（TYPICAL） |
| `parallel_max_servers` | PX 预算 | 现役（配自动 DOP） |
| `undo_retention`/`db_undo_retention guar*` | CR 保障 | 现役（guarantee 慎用） |
| `db_writer_processes` | DBWn 分片 | 现役（默认自适应 ⚠️） |
| `optimizer_mode`/`optimizer_dynamic_sampling`(10g 名 `db_file_direct_io_count`? 不录) | 计划倾向 | 模式现役，动态采样 11g 起改参名口径 ⚠️ |
- 名录纪律：表中只收"跨代幸存率"信息，**不给建议值**——本册的"值感"来自 10g 内存/磁盘量级，今天照抄等于拿 2005 年油价导航 2026。

## 3. 症状→参数反查索引（⚠️ 收口地图，把九章钉成一页）

| 症状（`02` 事件/账本） | 首查章 | 常被冤枉的参数 |
|---|---|---|
| `db file sequential read` 爆量 | `06/05` | `db_cache_size`（真因常在 CF/统计） |
| `db file scattered read` 爆量 | `05/04` | mbrc（真因常在该走索引没走） |
| `log file sync` 高 | `04/09` | 日志参数（真因常在碎提交/盘） |
| `latch: shared pool` | `05/03` | `shared_pool_size`（真因常在硬解析） |
| `latch: cache buffers chains` | `08/03` | 分片隐藏参（真因常在热块设计） |
| `enq: TX` | `08/09` | 无（应用序列化点） |
| -1555 | `08` | `undo_retention`（真因常在提交节拍） |
| Est≠Actual 计划病 | `05` | 优化器隐藏参（先补统计） |
| 全扫突然弃索引 | `05/04` | mbrc/系统统计变更 |
| 夜批超时 | `09/03` | 并行度（先看 TEMP 溢出与 PGA） |
- 读法：**先章内证据链，后参数**；本表是"别先动参数"的防呆清单——本册所有贴士的公约数。

## 4. 脚本工具箱（⚠️ 体裁还原，文件名按 10g 通说）

- 报告类：`spreporta.sql`（Statspack）/`awrrpt.sql`/`ashrpt.sql`/`addmrpt.sql`；bottlenecks.sql 式自研切片。
- SQL 侧：`utlxplan.sql`+`utlxplp.sql`（解释计划表与美化）⚠️、autotrace 脚本 `utlxplan` 族、`@` 模板化会话脚本。
- 诊断事件：`oradebug setmypid; oradebug event 10046 trace name context forever, level 12;`——本册时代唯一"高级感"操作，trace 文件目录 `user_dump_dest` 族（11g 后改 `diagnostic_dest` 口径 ⚠️）。
- 统计/运维：`DBMS_STATS` 任务编排、`DBMS_SQLTUNE` 家族、锁堵链查询模板（`08` 视图账本）；每个模板在重组章内均已给出入口。
- **bstat/estat**：9i 时代"两份 V$ 快照打差"手工艺 ✅ 概念在册（`$ORACLE_HOME/rdbms/admin/bstat.sql`+差值脚本），本册时代与 Statspack 并用——Statspack/AWR 的"前史标本" ⚠️。

## 8. 升级回归验收清单（⚠️ 通说；SPA/Database Replay 产品化前的手工艺版）

任何大版本迁移（如本册时代的 9i→10g，或今天对照 19c→23ai 的同构流程）按十项过闸：

1. 基线留档：核心 SQL 的 `V$SQL_PLAN` 快照+autotrace 三件套（逻辑读/物理读/耗时）导出 ⚠️。
2. 统计随行：生产 `DBMS_STATS` 导出→新库导入再比计划（`05` 的跨库口供法）⚠️。
3. 参数瘦身：旧 init.ora 只带"必需偏差"进新 spfile，其余交默认+ASMM（`03/10` 纪律）⚠️。
4. hint 审计：全量代码 grep `/*+`，逐条在新版本验效（`07` §8 排查序）⚠️。
5. Outline/锁计划清点：本册时代遗产到新代际的迁移=SPM Baseline 装载（`07` §9 断代志的实操页）⚠️。
6. 特性开关对照：优化器新行为（变换/直方图默认值/动态采样度）以升级指南逐项核 ⚠️。
7. 工作负载回放：无 Replay 工具年代=影子库+采样重放脚本 ⚠️；11g+ 用 Database Replay/SPA ✅ 概念在册（10.2 目录 Ch21/22 已见雏形）。
8. 等待谱对比：新旧 AWR 的 Top events 结构变化>语义变化先看统计与参数 ⚠️。
9. 批窗口日历：夜批/维护窗/自动任务的时钟冲突表 ⚠️（`09/05` 联动）。
10. 回滚包：变更单附"退回旧参数/旧计划一键脚本"——本册时代就成立的运维美德 ⚠️。

## 最新演进与工业实践

- **参数治理现代化 ⚠️→✅**：19c/23ai 的默认策略是"少设参数"——内存族交给 ASMM/AMM 与自治层、检查点交给 MTTR 自适应、统计交给自动任务；文档口径明确"设了专用值=承担维护责任"（19c PTG/Reference 门户在册 ✅ 实抓存在性，逐页口径 ⚠️）。
- **观测面整合**：`oradebug event`/SQL Trace 体系在 19c 收敛为统一诊断接口 + **SQL Monitor/SQL Trace 云上传**；AWR 家族扩展 CDB/PDB 多层报告（多租户 12c+）⚠️——本册脚本的当代同名件几乎都在，但参数与路径换代。
- **自治终局**：Autonomous Database 把本章整章的工作（参数/统计/索引/SQL 画像）纳入自动流水线并**不对用户暴露调参面**（✅ 概念锚 docs.oracle.com Autonomous 线；本会话未实抓逐页 ⚠️）——"调优参数速查章"的终点是成为历史职业的记忆。
- **工业实践通识化**：症状→证据→处置、能窄不宽、隐藏参需授权——已进任何一线数据库团队的变更管理 SOP（跨引擎对读 ✅ [../SQL_Server_Advanced_Troubleshooting/10-扩展事件与持续监控体系.md](../SQL_Server_Advanced_Troubleshooting/10-扩展事件与持续监控体系.md)、[../Troubleshooting_Oracle_Performance_2e/05-不可复现问题的事后分析.md](../Troubleshooting_Oracle_Performance_2e/05-不可复现问题的事后分析.md)）。
