## 1. 锁（enqueue）：慢的艺术，也是病的标本（⚠️）

- 谱系 ⚠️：TM（DML 表锁护结构）/TX（行锁，锁在事务+itl 条目上）/ST（序列）/PW/…；`V$LOCK` 的 BLOCK 列+`V$SESSION.BLOCKING_SESSION`（10g 起直接暴露 ✅ B14211 Ch10 域）——"谁堵谁"第一次成为一行 SQL 的事。
- 行锁机理 ⚠️：锁不锁"行"本体而锁 ITL 槽+索引条目；两事务改同行→后来者挂 `enq: TX - row lock contention`；**序列化点设计**（热点账户行）是应用架构问题不是调参问题。
- 病理速诊 ⚠️：`enq: TX` 的 wait#2/3 编码区分 itl/行锁/事务表；`SELECT FOR UPDATE` 超时与 `NOWAIT` 的 ORA-00054；死锁 ORA-00060（trace 文件画环）——预防靠访问序一致+短事务，检测靠 `V$SESSION_EVENT` 的死锁计数。
- 贴士红线 ⚠️：`ALTER TABLE ... LOCK`/`DDL 阻塞等 TM` 类"清锁"操作在现代运维等于纵火；本册时代的"杀会话解 lock"配方 2026 先查 RAC 全局块属主再动。

## 2. 闩锁（latch）：内存结构的交通警（⚠️）

- 与锁分工 ⚠️：闩护**共享内存结构**（缓冲链、共享池、redo 分配 LSO）瞬时一致，持有=微秒级；锁护业务语义，持有=事务级。内幕级流程在盘上闩锁章 ✅（above 链接）。
- 三态获取 ⚠️：立即→自旋（`spincount`，CPU 换等待）→睡眠（`immediate/sleep` 代数）；`V$LATCH` 的 misses/spins、`V$LATCH_CHILDREN` 找子闩热点、`V$SESSION` 的 wait#1=子闩地址。
- 本册时代三大全网热点：`cache buffers chains`（热块：索引右枝/序列段头/循环缓冲小表）、`shared pool`（硬解析风暴，归 `03/05`）、`redo allocation`（高频小提交，归 `04/09`）。
- 处方谱 ⚠️：热块三件套（`_db_block_hash_buckets` 扩分片/表哈希分区分散/逻辑上撤热）；序列 `NOCACHE` 是事故不是优化（CACHE+高 step 才是）；**mutex（11g）接棒 library cache 类闩** 是本章话题的终章——演进节记。

## 3. 段头竞争：ITL 与 freelist 的世纪公案（⚠️）

- ITL（interested transaction list）槽不足 → 并发 INSERT/UPDATE 挂 `enq: TX - allocate ITL entry` ⚠️；`INITTRANS/MAXTRANS/PCTFREE` 是段级预算 ⚠️。
- freelist 链争用（多进程找同一空块链）→ `V$WAITSTAT` 的 `first free list` 行+`FREELISTS/FREELIST GROUPS`（RAC 分节点）⚠️；经典热表=批量装载与高并发小插。
- **ASSM（SEGMENT SPACE MANAGEMENT AUTO，9i 引入、10g 默认表空间级 ✅ 概念锚 10.2 Concepts）**：位图段头替 freelist 链——本册恰处手工段头向自动段头过渡期，两条腿贴士并存；2026 只剩兼容层读法。
- 判读入口 ⚠️：`V$SEGMENT_STATISTICS`（10g 新，row lock/data block 等待按段归因）——"哪个段在挨打"从此有表可查。

## 4. undo 一致性读与 ORA-01555（⚠️ 时代病一）

- 机理 ⚠️：读一致性=当前块+undo 回滚构造 CR 克隆；长查询+高并发改写=回滚链拉长；undo 被复用→**ORA-01555 snapshot too old**——本册时代三大悬案之首（长查询/批量提交交错/undo 空间不足三路病因）。
- 10g 新器 ✅ 概念在册：UNDO 保留时间窗（`undo_retention`）+ **RETENTION GUARANTEE**（10.1 表空间级承诺 ⚠️ 许可/空间代价）+ ADDM 的 undo 顾问（`V$UNDOSTAT` 账本：undostat 的 steals/maxcon 是饥饿证据）。
- 应用侧解法 ⚠️：批量作业**别边提交边继续扫**（提交即丢一致性锚点，回头读=重造 CR）；长报表走只读副本/物化视图（→ 盘上仓库章 ✅ [../Oracle_Essentials_5e/08-仓库实施分区物化视图与装载.md](../Oracle_Essentials_5e/08-仓库实施分区物化视图与装载.md)）。
- 现代对应：ORA-01555 在自动 undo 调优+Flashback 时代罕见 ⚠️，但 CR 克隆的 CPU 税（`consistent changes` 统计）仍每日上演——对读 TOP 物理设计章的 ITL/PCTFREE 账 ✅ [../Troubleshooting_Oracle_Performance_2e/16-优化物理设计.md](../Troubleshooting_Oracle_Performance_2e/16-优化物理设计.md)。

## 5. RAC 语境的并发加成（⚠️ 点到为止）

- 全局缓存融合：块在主/备实例间搬家（`gc current block` 族等待）；**缓存融合（cache fusion）** 让 RAC2 时代"锁≠慢"成为可能 ⚠️；序列/全局块属主（mastering）与 `gc` 闩。
- 本册基线若涉 RAC 贴士（⚠️ 推定），2026 一律以 19c/23ai RAC 文档+盘上 RAC 案例章为准：[../Oracle_Database_Problem_Solving/06-RAC故障诊断与SQL顾问.md](../Oracle_Database_Problem_Solving/06-RAC故障诊断与SQL顾问.md) ✅。

## 8. 热块现场工（⚠️ 五步流程，cache buffers chains 专项）

1. **认犯**：`V$LATCH_CHILDREN` 找争用最热的子闩地址（gets+misses+immediate_misses 加权）⚠️。
2. **找赃**：以该地址反查持有块——10g 手工艺 `V$SESSION.P1/P2`（file#/block#）聚合或 x$ 层解块表（⚠️ 高危，需指导；2026 首选 `V$SESSION` 等待行直接带 `CURRENT_FILE#/BLOCK#` 组合账）。
3. **定罪**：file#+block# → `V$SEGMENT_STATISTICS`/`DBA_EXTENTS` 映射到段+对象类型（表头/索引右枝/位图节点各归各案 ⚠️）。
4. **判刑阶梯**（先设计后参数）：应用散列键/批量合并 → 分区或哈希分布表 → `PCTFREE/ITL` 段级预算 → 缓冲分片参数（`_db_block_hash_buckets` 族，博物馆条目）⚠️。
5. **缓刑复核**：同窗口 ASH 按事件+对象再采样，确认 `buffer busy waits`/`read by other session` 曲线塌落 ⚠️。
- 索引右枝热点（序列主键最右叶）是本章与 `06` 反向键判例的合流案；位图更新热块（DML×位图）判例四的机理解释位 ⚠️。

## 9. 死锁与挂起取证小抄（⚠️ 通说）

- 死锁（ORA-00060）⚠️：服务端自动检测回滚一方，TRACE 文件画等待环——取证=捞 trace 的锁转换序，处置=统一访问序/`SELECT FOR UPDATE NOWAIT` 早败。
- 挂起（hang，无死锁码的互等）⚠️：本册时代靠 `V$SESSION` 堵链+`oradebug hanganalyze/systemstate`（⚠️ 需官方指导）；10g 起 DIAG 进程自动画像 ⚠️。
- 堵链一行 SQL（10g 新列 ✅ B14211 Ch10 域）：`SELECT sid, blocking_session, event FROM v$session WHERE blocking_session IS NOT NULL`——本册最"现代感"的贴士 ⚠️。
- RAC 语境：全局块属主与跨实例链（→ `08` §5，实例册/问题册对读）⚠️。
- 判读边界：锁等待≠锁泄漏；`V$LOCK` 长期大量 TM 行先看连接池是否"借而不还" ⚠️（`09` 会话管理联动）。

## 10. 并发度量小表（⚠️ 速记）

| 度量 | 账本 | 健康语感 |
|---|---|---|
| 闩命中率 | `V$LATCH` gets/misses | misses 增速与业务量同频 |
| 自旋效率 | spins/misses | 高自旋高睡=参数与负载不配 |
| 段争用密度 | `V$SEGMENT_STATISTICS` 等待行 | 单段独大=设计案 |
| 锁等待占比 | `V$SESSION_EVENT` enq 族 | 峰时可容忍，谷时不该在 |
| CR 构造成本 | `V$SYSSTAT` consistent changes/get | 长查询+热更新=高值双因 |
- 与 `02` 分诊表互扣：本表左列即事件族的"计数侧镜像"——等待说"多久"，计数说"几次"。

### 附记：并发轶事三句与判例索引（⚠️ 时代注脚）

- 一句："闩锁调参时代"（spin/sleep 手工党）在本册后十年落幕，mutex+分片化接管——今天仍调 `_latch_*` 的生产库=把博物馆搬到机房 ⚠️。
- 二句：freelist/PCTFREE 之争随 ASSM 强制化盖棺，但 ITL 预算（INITTRANS/MAXTRANS 仍活）是幸存者——段级并发预算的直觉要留 ⚠️（对读 ✅ [../Oracle编程艺术：深入理解数据库体系结构（第3版）.md](../Oracle编程艺术：深入理解数据库体系结构（第3版）.md) 事务块节）。
- 三句：ORA-01555 从"三大悬案"降到"边角案例"，靠的是 undo 自动调优+长查询治理——但 CR 克隆 CPU 账每天都在，读懂本判例的人对 `consistent changes` 永远敏感 ⚠️。
- 判例索引：判例四（位图×OLTP）见 `06` §8；序列热点见 `06` §8-5 与 §8 热块第 3 步；堵链一行 SQL 见 §9——本章与两章互为案例库 ⚠️。
- 教学收口：并发调优的真名字是"设计少争用的数据+写短持有时间的事务"，闩锁参数只是这场设计失败的止痛贴 ⚠️ 重组断言。

### 附记二：并发工单分级模板（⚠️ 体裁收口）

- P1 挂起/堵链成片：先取证（§9 堵链+hanganalyze 位）再处置，杀会话是最后选项 ⚠️。
- P2 单点热点行：序列化点判定→设计级散列（`06` 分区/键散列）→中期事务重构 ⚠️。
- P3 闩计数爬升：走 §8 热块五步；参数阶梯最后一级才见 ⚠️。
- P4 -1555/undo 报警：长查询与提交节拍下 undo 账——三处病因一处处方 ⚠️。
- 分级用途：本册并发贴士全部按 P1–P4 归位后，"何时抄哪条"不再有歧义 ⚠️ 重组断言。
### 附记三：并发取证时间线手法（⚠️）

- 三段采样：事发前 10 分钟 ASH（找起始会话）→ 事中 `V$SESSION` 现场（堵链快照）→ 事后 `V$LOCK`/trace（环与码）⚠️。
- 一把钥匙：`SQL_ID`+`ROW_WAIT_OBJ#`（行等待定位，10g 起 `V$SESSION` 直接带行地址三元组 ⚠️ 口径以文档为准）——锁案卷宗里唯一贯穿三段的字段。
- 收口：本章四段账（锁/闩/段头/undo）在时间线上是同一条剧情的四幕——先定幕，再查账 ⚠️ 重组断言。

## 最新演进与工业实践

- **化石与新钩 ✅/⚠️**：`_latch` 自旋调参与"杀会话解锁"是本册时代配方；11g **mutex** 替换库缓存类闩（cache locks 分片改进延续），12c+ 锁诊断产品化（`V$SESSION` 堵链字段→EM/ASH 原生堵链图），19c/23ai 的 PTG/Concurrency 章在册 ⚠️（19c 门户已实抓，逐页未验）。freelist/PCTFREE 手工贴士随 ASSM 强制化退出现役（12c 起非默认段空间选项不再可选 ⚠️）。
- **ORA-01555 的现代形态 ⚠️**：undo 饥饿变罕见；同族新面孔=闪回归档（11g Flashback Data Archive）与长查询的 ORA-04068/ORA-8177 类；CR 克隆 CPU 成本在 AWR 的 `consistent changes/get` 里仍是每日指标。
- **RAC 终局**：本册时代 RAC 是"高可用皇冠"，2026 云上高可用主流改走 DG/复制+多活应用层，RAC 仍在但装机占比降 ⚠️——本章 RAC 节按史料+特定架构双读。
- **工业实践平移**：堵链取证思想≈分布式系统的锁等待图/deadlock detector；跨引擎对照 ✅ [../SQL_Server_Advanced_Troubleshooting/09-阻塞死锁与并发故障排除.md](../SQL_Server_Advanced_Troubleshooting/09-阻塞死锁与并发故障排除.md)（blocking process 链+死锁图，同构度最高）、MySQL 侧 MDL/事务锁谱（✅ [../高性能mysql.md](../高性能mysql.md)）。
- **2026 姿势**：机理读本=内幕册闩锁/锁两章（✅ 在盘）+《Oracle 编程艺术》并发节（✅ 在盘）；手册读本=TOP 16 章物理设计+堵链处置；本册供 10g 现场感：那是 ASSM 铺开前"段头手工党"最后的文献。
