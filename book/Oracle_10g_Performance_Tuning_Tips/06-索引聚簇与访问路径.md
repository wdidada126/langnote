## 1. B 树索引的三行几何（⚠️ 通说；✅ 解剖在盘）

- 根/分支/叶：等值路径=根→枝→叶连续单块读（`INDEX RANGE/UNIQUE SCAN`），每层一次 `db file sequential read`；高度（`DBA_INDEXS.HEIGHT`/`BLEVEL`）即路径长度税。
- 叶内存序+rowid 回表：范围扫的代价函数=叶子块跨度+**回表次数×聚簇因子影响**（✅ 成本账全解剖 [../Cost_Based_Oracle_Fundamentals/04-B树索引基础访问.md](../Cost_Based_Oracle_Fundamentals/04-B树索引基础访问.md)）。
- 删除留空位（leaf block splitting/deleted entries）→ 本册时代贴士"索引重建频率"之争 ⚠️：空间回收 vs 建索引 IO 风暴；后续代际的"合并块复用"（11g `_advance` 类改进 ⚠️）改写结论。

## 2. 🔧 类比 D1：访问路径的三张计划照（SQLite 3.45.3，非 Oracle）

20 万行表 `big(id,a,b,pad)`，`a` 仅 20 值（等值命中 5%）、`b` 1000 值（0.1%）：`demo_out.txt`：

- `WHERE a=5` → `SEARCH ... USING COVERING INDEX ix_ab (a=?)`；
- `WHERE b=777` → `SEARCH ... USING COVERING INDEX ix_b (b=?)`；
- `WHERE pad='x5'`（无索引）→ `SCAN big`：**计时 0.059 ms vs 9.814 ms**（同库内存态，约 165 倍）。
- 对读 Oracle ⚠️：前两条≈`INDEX RANGE SCAN`（选择性足够时），第三条≈`TABLE ACCESS FULL`——"优化器先挑路径、路径决定等待事件名（sequential vs scattered read）"的因果链在轻引擎里同样成立，但**成本模型与阈值完全不同，不可拿倍数当 Oracle 预期**。
- **判定：非 Oracle 引擎行为**。

## 3. 🔧 类比 D2：覆盖索引=回表税清零（SQLite 3.45.3，非 Oracle）

同表同谓词 `a=5`（1 万行命中）对比取列：

- `SELECT a,b`（索引内自足）→ COVERING INDEX，**3.882 ms**；
- `SELECT pad`（须逐行回表）→ `USING INDEX`（非 covering），**7.379 ms**（约 1.9 倍）。
- 对读 Oracle ⚠️：覆盖索引=消灭 `TABLE ACCESS BY INDEX ROWID` 行——账本上从"回表单块读次数"直接消失；设计贴士"把高频查询所需列收进索引"在两个世界同义，但 Oracle 侧还要付**写放大与 CF 恶化**的 DML 税（本册与 `02` 章速诊表均指认）。
- **判定：非 Oracle 引擎行为**（SQLite 的 rowid 表回表更廉价，倍数不可外推）。

## 4. 🔧 类比 D3：复合索引前导列与谓词形状（SQLite 3.45.3，非 Oracle）

- `a>3 AND b=7`（范围吃掉 ix_ab 前导列）→ 优化器弃 ix_ab **改用 ix_b (b=?)**；
- `a=3 AND b>700`（等值在前）→ `ix_ab (a=? AND b>?)` 全段命中；
- 统计行 `sqlite_stat1(ix_ab)=200000 10000 200`（表行×前缀均值×全键均值）——只有键均值、无分布形态（D6 同题）。
- 对读 Oracle ⚠️：前导列纪律同源；Oracle 在此之上还有**跳跃扫描（skip scan，10g 起，前导列低 NDV 时可救 `a>3 AND b=7`）**与组合谓词的扩展表扫描——轻引擎无 skip scan 可类比，差异如实 ⚠️。索引列序设计正典对读：✅ [../数据库索引设计与优化.md](../数据库索引设计与优化.md)（Hargreaves 系中文单文件，"等值→范围→排序"列序律）。
- **判定：非 Oracle 引擎行为**。

## 5. 索引谱系全表（⚠️ 通说+✅ 文档锚）

| 型 | 场景 | 10g 时代要点 |
|---|---|---|
| B 树（复合/唯一） | OLTP 主力 | `COMPRESS` 前缀去重；并行建 `PARALLEL`+`NOLOGGING` 组合拳 |
| 位图 | 低 NDV 列/DSS | 更新即锁段 ⚠️ OLTP 禁区；✅ 解剖 [../Cost_Based_Oracle_Fundamentals/08-位图索引.md](../Cost_Based_Oracle_Fundamentals/08-位图索引.md) |

| IOT（索引组织表） | 主键访问全覆盖 | 溢出映射（PCT_THRESHOLD）；二级索引 ROWID 易腐 ⚠️ |

| 外部表索引 | — | 10g 新外部表世界无索引，走预聚合 |

## 6. 建/维护的操作贴士骨架（⚠️ 体裁还原）

- 建：夜窗 `CREATE INDEX ... PARALLEL NOLOGGING` → 立即 `LOGGING`；先大表后索引防锁等待；`DBA_INDEX_USAGE`/`V$OBJECT_USAGE`（monitored）查死索引 ⚠️——"删未用索引"是本册最可能收录的清理贴士。
- 判活三问 ⚠️：统计新不新（`05`）→ 谓词可索引吗（函数包裹/隐式转换是两大杀手）→ 选择性够吗（5% 法则只是口诀）。
- 病理对照：索引没被用≠索引没用——CBO 弃用通常是"回表账算不过来"（CF 高），处方在表重组（`MOVE`+索引重建）而非硬 hint。

## 8. 病理判例博物馆（⚠️ 通说判例五则，各留"当年处方+今鉴"）

1. **索引没被走（谓词被函数包裹）**：`WHERE TRUNC(order_date)=DATE'...'` 全表；当年处方=函数基索引或改写范围谓词；今鉴同左（可索引化纪律跨版本零迁移 ✅ 对读 [../Oracle查询优化改写技巧与案例.md](../Oracle查询优化改写技巧与案例.md)）。
2. **隐式转换弃索引**：VARCHAR2 主键配数字字面量；处方=改调用方类型；今鉴=ORM 参数绑定类型审计工具化。
3. **CF 虚高弃索引回表账**：统计新、谓词好但走全扫——`05` 章 CF 解剖后处方为表重组（`MOVE`+索引重建）或 clustering 设计；今鉴=12c+ 的 `INMEMORY`/19c 自动索引改变权衡 ⚠️。
4. **位图上 OLTP**：低基数列建位图，更新即 `enq: TX` 段锁连锁；处方=删位图；今鉴=本册时代最流传的"坏贴士"反面标本 ⚠️。
5. **反向键索引救序列**：写入热点右枝打散，报表范围扫失效新病；处方=按读写比决策+函数基索引补范围路；今鉴=11g 后序列缓存与间隔方案更优 ⚠️。
- 五判例共用第 6 节判活三问的因果链：**料（统计）→ 形（谓词形状）→ 账（选择性×回表）**。

## 9. 分区表上的索引抉择（⚠️ 10g 口径速记）

- 本地索引（LOCAL）：分区对齐、维护便宜（`DROP PARTITION` 不毁全局索引）；全局（GLOBAL）：唯一约束与非分区键高速路；**10g 全局索引可分区**（hash/range）打散单点 ⚠️。
- 裁剪（partition elimination）双条件 ⚠️：谓词带分区键 + 统计供 CBO 推得动；组合失效时本地索引全分区扫=隐藏成本账。
- 装载联动：分区交换（`EXCHANGE PARTITION`）+ 本地索引即时可用（→ `09` 搬山章；仓库姿势 ✅ [../Oracle_Essentials_5e/08-仓库实施分区物化视图与装载.md](../Oracle_Essentials_5e/08-仓库实施分区物化视图与装载.md)）。
- 索引维护窗口贴士 ⚠️：`ALTER INDEX REBUILD PARTITION`/`DROP STORAGE` 词表按子分区树形查；19c/23ai 的 Interval 分区+自动维护接管大半仪式（⚠️ 新口径先对文档）。
- 与盘上纵深对读：✅ CBOF 位图/B 树两章（`04/08`）+ 索引设计中文单文件（`../数据库索引设计与优化.md`）；本章只给"分区×索引"的 10g 现场词表。

### 附记：索引体检工单模板（⚠️ 体裁还原，巡检月历用）

1. **存在性**：`DBA_INDEXES` 状态（UNUSABLE 清单=事故在途）+ 分区索引的本地失效位 ⚠️。
2. **使用性**：监控窗口内的 USED/NOT USED（`V$OBJECT_USAGE`/后 10g 的 usage 视图 ⚠️）；"半年未用"候选删除清单先过约束/唯一性依赖检查 ⚠️。
3. **形态**：`BLEVEL/LEAF_BLOCKS` 同比漂移、`DISTINCT_KEYS`/NUM_ROWS 比率变化——比率突变处看装载与统计动作对表（`05` §9 十问联动）⚠️。
4. **碎度**：`INDEX_DROPPED_KEYS` 思路的手术决定（重建 vs 合并）——本册时代判例一争议的现代答案：多数场景不重建，扩容自动消化 ⚠️。
5. **热区**：右枝/段头等待计数（→ `08` 热块五步）⚠️。
6. **写放大**：DML 吞吐前后对比（覆盖收益 vs 维护成本的净账）⚠️。
- 模板用法：每月一跑、留档对比；索引问题的三大来源（设计/统计/负载漂移）各占其账 ⚠️。
- 与 `05` 十问、`08` 热块流程构成"月度巡检三件套"——本册体裁的系统性其实藏在单条贴士的合订处 ⚠️ 重组断言。

### 附记二：访问路径选择的四行因果链（⚠️ 本章收束）

- 料（统计新鲜+直方图到位）→ 形（谓词可索引化+类型对齐）→ 账（选择性×回表×CF）→ 证（计划+等待事件双确认）⚠️。
- 链上任一环缺失，"索引调优"都会退化为玄学——🔧 D1–D3 演示的正是"形与账"两环在轻引擎里的可见版本（**非 Oracle 行为**）。
- 与 `05` 的三板斧、`02` 的速诊表构成闭环：统计章喂料、索引章定形、事件章验货 ⚠️。
- 反查入口：本附记四行 = `10` 章反查索引表"全扫/索引病"两行的解决路径 ⚠️。
### 附记三：索引经济学一图流（⚠️ 本章终收敛）

- 读侧账：`选择率 → 叶块跨度 → 回表次数×CF 系数 → 等待事件名`——四段链条每一段都有视图可对（`02/05` 联动）⚠️。
- 写侧账：每次 DML=表块+索引块+undo+（10g 起）可能的 ITL 追加——索引数量是乘数，🔧 D2 的"覆盖省读"在写侧反向变成"多索引加税"（**非 Oracle 行为**，方向直觉成立）⚠️。
- 决策句 ⚠️：加不加索引，问的不是"能不能快"，而是"谁的账涨、谁的账跌、跌掉的能否用等待事件验证"——本册时代与 2026 同文。
- 收尾互扣：本图流是 `10` 章反查索引表两行（sequential/scattered 爆量）的求解总纲 ⚠️。

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| B 树索引 | B-tree index | 根枝叶几何的有序键→rowid 映射 |
| 覆盖索引 | Covering index | 所需列全在索引内免回表 |
| 回表 | Table access by index rowid | 索引命中后取行的单块读税 |

| 位图索引 | Bitmap index | 低基数列的压缩位向量谱 |
| 函数基索引 | Function-based index | 表达式求值结果的索引 |
| 反向键索引 | Reverse key index | 打散序列写入热点 |
| 索引组织表 | IOT (Index-Organized Table) | 数据即索引叶子 |
| 索引监控 | Index monitoring | 用不用一查便知 |

## 最新演进与工业实践

- **文档延续 ✅**：Indexes and Clusters 主题在 19c/23ai PTG 在册（✅ 门户实抓，00 §12.7）；B 树/位图/函数基/IOT 谱系全部现役，位图在 12c+ 的"重复值索引（duplicate bitmap）"与分区场景继续受限 ⚠️。
- **代际增量**：11g **不可见列索引**、安全文件索引（SECUREFILE 时代）；12c 部分索引/`IDENTITY` 配套；19c **自动索引（Auto-Index）**——创建/弃用/回滚整体自动化（19.11 起 GA ⚠️），本册"死索引清理"贴士的当代对应物是 `DBA_AUTO_INDEX_*` 账本；**In-Memory 列存储（12c+）**为低选择度分析列提供了 B 树/位图之外的第三条路 ⚠️。
- **重建之争的现代答案**：段移动（`ALTER TABLE MOVE ONLINE` 12c+）+ 在线索引重建让"夜窗重建"仪式基本退役 ⚠️；空间利用议题由 ASSM（自动段空间管理，9i 引入 10g 默认化 → 12c 起强制）接管，freelist/PCTFREE 贴士退居兼容层。
- **2026 姿势**：索引设计第一原则仍是"谓词形状×选择性×回表账"（🔧 D1–D3 亲验其跨引擎普适）；具体到 Oracle 的列序/压缩/监控口径以 19c/23ai 文档+TOP 2e `15/16` 章（✅ [../Troubleshooting_Oracle_Performance_2e/15-超越访问与连接优化.md](../Troubleshooting_Oracle_Performance_2e/15-超越访问与连接优化.md)/[16-优化物理设计.md](../Troubleshooting_Oracle_Performance_2e/16-优化物理设计.md)）为准；本册供 10g 现场感与判例，不提供处方。
