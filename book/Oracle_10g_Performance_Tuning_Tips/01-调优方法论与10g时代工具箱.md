## 1. 为什么 10g 是方法论的分水岭

- 9i 及以前：调优≈"调实例"——Statspack 快照、`init.ora` 参数、按部件（内存/IO/锁）分头配比；"自底向上"结构派的时代（同代 O'Reilly 册即此立场，见 [../Oracle_Performance_Tuning_2e/00-总览与阅读地图.md](../Oracle_Performance_Tuning_2e/00-总览与阅读地图.md)）。
- 10g 官方新增（✅ B14211 在线目录逐章可查：https://docs.oracle.com/cd/B19306_01/server.102/b14211/toc.htm ）：**AWR 自动负载资料库、ASH 活动会话历史、ADDM 诊断器、SQL Tuning Advisor/SQL Profile、SQL Access Advisor、计划稳定性（Plan Stability）**——Oracle 把"记账+诊断"做进了内核。本册成书正当其时：贴士册的价值=教你用新账本 ⚠️ 推定。
- 一句话立场：**10g 把"会调优的 DBA"从"会背参数的人"改写成"会读账本的人"**；这也是本册所有章的公共前提。

## 2. 目标函数：响应时间 vs 吞吐量

- 两问分离 ⚠️（10g 时代通说，B14211 Ch1 亦以"用户满意度=响应时间"开宗 ✅）：
  - OLTP：优化**单请求响应时间**——排队论意义上，减少 CPU 时间+非空闲等待；
  - DSS/批处理：优化**吞吐**——允许单查询变慢换整体完成时刻提前。
- Millsap 的"响应时间=服务时间+队列等待"分解法（`V$SESSION_EVENT` 逐等待建模）在 10g 期已成显学；贴士册风格通常不摆公式、直接给"先看哪个视图"的操作序 ⚠️。
- 与盘上主读本的分工：方法论纵深在 TOP 2e（✅ [../Troubleshooting_Oracle_Performance_2e/01-性能问题.md](../Troubleshooting_Oracle_Performance_2e/01-性能问题.md) 症状驱动二分法）；本册（重组口径）只给"贴士前置的三问"：**瓶颈在 CPU/IO/并发哪一层？账本证据是什么？改动可测吗？**

## 3. 调优流程的 10g 标准照（⚠️ 通说）

1. **立基线**：AWR 快照（`AWRRPT` 报告）或 Statspack 快照对；无基线=无调优，只有猜。
2. **找前台**：ADDM/`DBA_ADVISOR_*` 视图给"Top activity"清单；ash（`V$ACTIVE_SESSION_HISTORY`）给"此刻谁在等什么"。
3. **下钻**：按等待类进入专项视图（`V$SYSSTAT`/`V$SYSTEM_EVENT`/`V$LATCH`/`V$LOCK`）。
4. **动刀**：SQL 改写/索引/参数——一次一变量，可回滚。
5. **回表**：再取快照对比；把结论写进变更单。
- 纪律（跨代际不变 ✅）：**证据驱动 + 单变量 + 可回滚**。本目录后续每章都按此闭环组织材料。

## 9. 一次完整"贴士闭环"示例（⚠️ 通说情景剧）

情景：凌晨报表批处理超时告警（10g 生产，AWR 已购诊断包）。

1. 取事故窗口 AWR 报告：Top 5 waits 出现 `log file sync` 伴 `log file parallel write`，DB time 占比 18% ⚠️ 典型对。
2. ASH 切片定位：集中在一类高频小事务（非报表 SQL 本身）→ 并发写入者的重做提交在排队。
3. 下钻 `V$SYSSTAT` redo 相关项 + OS IO 特征：确认日志盘与数据盘同 spindle 组 ⚠️。
4. 动刀（单变量）：日志成员独立镜像到低延迟卷；**不是**先调 `log_checkpoint` 类参数。
5. 复测：同窗口 AWR 对比，等待对同降；变更单附两份报告截图。
- 这出情景剧用到的账本入口分布在 `02`（等待对读法）、`04`（redo 节拍）、`08`（并发提交）——贴士册的"抄答案"与本目录的"抄过程"，请以后者为准。
- 反面教材（⚠️ 通说的常见事故）：跳过第 1–3 步直接加大 `db_cache_size`——在等待账本不支持"缓冲饥饿"的场合，等于给没病的实例喂补药，还会挤占共享池引发硬解析抖动（`03/05` 章证据链）。

## 最新演进与工业实践

- **本书世代的调优工具时间线**（10g→2026 三步走，各条目文档锚点见 00 §12.7）：

| 世代 | 记账层 | 诊断层 | 处置层 |
|---|---|---|---|
| 本册（10.1/10.2，⚠️ 2005?/2007） | AWR/ASH 初代+Statspack 双轨 | ADDM/EM Grid | Advisor 手动触发 |
| 19c（✅ E96347-06） | AWR 强化（含实时 SQL Monitor 许可件） | ADDM+自动 SQL 调优任务 | Auto-Index/自动优化窗口 |
| 23ai/26ai（✅ 门户在册） | AWR+云观测栈（OCPD/基线库） | 自治数据库内诊断 | Autonomous 自动处置闭环 |

- **10g→23ai 落差实录**：AWR/ASH/ADDM 三件套自 10.2 至今仍是主干——✅ 19c《Database Performance Tuning Guide》（E96347-06）与 23ai 路径（现服务 26ai 文档 G43584-03，2026-07）均在册延续"Automatic Workload Repository/Active Session History/ADDM"章线：https://docs.oracle.com/en/database/oracle/oracle-database/19/tgdba/index.html （✅ 本会话实抓确认文档存在）。本册时代的"Statspack 双轨"在企业版主线已退轨 ⚠️。
- **工具接管面扩大**：SQL Tuning Advisor→11g SQL Adaptive Tuning→12c 自动优化任务→19c **Auto-Index/Auto-Task**、自治数据库（Autonomous DB）把"找瓶颈→动刀"闭环整体自动化 ⚠️（演进 URL：https://docs.oracle.com/en/database/oracle/oracle-database/23/newft/index.html ⚠️ 未实抓）。
- **EM Grid→云控制台**：本册时代的网格控制演化为企业云控制/OCI Observability 线 ⚠️。
- **2026 工业实践**：证据驱动三纪律（基线/单变量/可回滚）仍是性能工程面试与变更管理的通行标准；Millsap 响应时间方法论出书于 2003（"SQL Tuning" 谱系），其"先量化再动手"与本册时代合拍，今天读来依然是最省钱的调优课 ✅（对读：[../Troubleshooting_Oracle_Performance_2e/03-可复现问题的分析.md](../Troubleshooting_Oracle_Performance_2e/03-可复现问题的分析.md)）。
- **跨引擎回声**：等待记账思想被 MySQL performance_schema、SQL Server DMV 等待统计完整复刻（✅ 在盘同构：[../SQL_Server_Advanced_Troubleshooting/02-动态管理视图与等待统计.md](../SQL_Server_Advanced_Troubleshooting/02-动态管理视图与等待统计.md)、[../Efficient_MySQL_Performance/00-总览与阅读地图.md](../Efficient_MySQL_Performance/00-总览与阅读地图.md)）——读老 Oracle 账本的最快方式是先读你手里引擎的对应账本。
