# 05 优化器统计与执行计划 — Oracle Database 10g Performance Tuning Tips & Techniques（精读重构）

> ⚠️ 主题重组口径（章号非原书章号，降级声明见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §3）。本章=CBO 的"喂料—读口供—纠偏"三板斧；成本公式解剖请转盘上 CBOF（✅ [../Cost_Based_Oracle_Fundamentals/00-总览与阅读地图.md](../Cost_Based_Oracle_Fundamentals/00-总览与阅读地图.md)），本章只教开饭与查岗。
> Oracle 行为 ⚠️ 转述；官方锚点 ✅：B14211 Ch13/14/19（Query Optimizer/Managing Statistics/EXPLAIN PLAN，目录实抓在册）。🔧=本机 SQLite 3.45.3/DuckDB 1.5.5 类比（非 Oracle 引擎行为）。

## 1. 优化器模式与代际站位（⚠️ 通说）

- `optimizer_mode`：ALL_ROWS（总成本）/FIRST_ROWS_n（首 n 行快）/CHOOSE（旧遗产）；10g 起建库默认 ALL_ROWS ⚠️；DSS 会话偶用 FIRST_ROWS_10 救分页头屏是本册时代贴士。
- RBO 已宣判（9i 起不推荐、12c 移除 ⚠️ 演进记），但本册时代仍有存量库骑墙——贴士册的"RBO 迁 CBO 检查单"是历史文献价值所在。
- 10g 关键增量 ✅：**系统统计**（`DBMS_STATS.GATHER_SYSTEM_STATS`，CPU/IO 标定进成本单位）+ 夜间自动统计收集作业（`GATHER_STATS_JOB`，维护窗调度）——"统计饿死"问题被制度性缓解的开始。

## 2. 统计三层账（表/列/索引）+ 采集工具迁移

| 层 | 内容 | 载体 | 病理与纠偏 |
|---|---|---|---|
| 表 | 行数/块数/平均行宽 | `DBA_TABLES` | 陈旧→基数全歪；`DBMS_STATS` 重采 |
| 列 | NDV/空值/分布 | 直方图（FREQUENCY/TOP-N/HEIGHT-BALANCED） | 倾斜无图→选择度骗局（B14211 Ch14 口径 ✅） |
| 索引 | 层级/叶块/聚簇因子 | `DBA_INDEXES` | CF 虚高→弃索引（✅ 解剖在 [../Cost_Based_Oracle_Fundamentals/05-聚簇因子.md](../Cost_Based_Oracle_Fundamentals/05-聚簇因子.md)） |
- 工具迁移线 ⚠️：`ANALYZE`（列统计弱、CF 采样粗）→ **`DBMS_STATS`**（并行/可导出导入/可锁定/`METHOD_OPT` 按列定制）——本册时代正是劝迁高峰。
- 统计运维贴士 ⚠️：STT（statistics target）参数与自动收集窗口；导出导入统计支撑"生产采、测试用"；锁定静态参照表统计防夜间作业冲刷。

## 3. 取计划四路与判读纪律（⚠️ 通说）

1. `EXPLAIN PLAN FOR`+`DBMS_XPLAN.DISPLAY`：预估图（可能与共享池真身不一致——贴士警示 ✅ 官方文档专节）。
2. `V$SQL_PLAN`/`V$SQL_PLAN_STATISTICS`：共享池真身与行级计数（10g 起 `ALLSTATS` 采样线）。
3. autotrace：逻辑读/物理读/递归快速速览。
4. 10046 level 10/12 + TKPROF：执行实况金标准（服务/等待分解）。
- 两条铁律 ⚠️：**Est Rows ≠ A-Rows 处即统计案发现场**；从最深缩进自下而上读行源序。对读 TOP 2e 计划章（✅ [../Troubleshooting_Oracle_Performance_2e/10-执行计划.md](../Troubleshooting_Oracle_Performance_2e/10-执行计划.md)）——同一纪律的 2014 版教材化。

## 4. 🔧 类比 D5：连接算子的选择函数跨引擎不同（DuckDB 1.5.5，非 Oracle）

`demo_out.txt`（`D:\develops\tmp\dbwave_w10_ora10g\`，100 万×50 万表）：

- 等值大连接 `l.j=r.k` → EXPLAIN 出现 **HASH_JOIN**（建小侧哈希、大侧探路）；
- 不等式 theta 连接（缩表 2000×2000 防组合爆炸）→ **PIECEWISE_MERGE_JOIN**。
- 对读 Oracle 三连接谱（✅ 成本账在 CBOF：[11-嵌套循环连接](../Cost_Based_Oracle_Fundamentals/11-嵌套循环连接.md)/[12-哈希连接](../Cost_Based_Oracle_Fundamentals/12-哈希连接.md)/[13-排序与归并连接](../Cost_Based_Oracle_Fundamentals/13-排序与归并连接.md)）：小驱动集高选择性选 NL、等值大批选 HJ、双方已排序省 sort 层选 MJ——**算子谱系同构，选择逻辑各引擎自定**；DuckDB 无"按成本挑 NL 做等值"的可复现路径，如实 ⚠️。
- **判定：非 Oracle 引擎行为**；用于校准"计划=算子组合，算子各有账本"的通用直觉。

## 5. 🔧 类比 D6：直方图为什么存在——一个负结果示范（DuckDB 1.5.5，非 Oracle）

倾斜表（40 万行，`c=CASE i%10=0 THEN i ELSE i%37 END`，`c=13` 实际 9730 行）：

- 无统计首查：计划估算 **~28 rows**；`ANALYZE skew` 后：估算 **~10 rows**——不升反降，离实际 9730 差三个数量级。
- 病理剖析：优化器按"均匀分布/NDV 反推"估算等值选择度，`i%37` 生成的密集团被少数大值撑高 NDV 视野——**这正是 Oracle 直方图要救的场景**（频率/TOP-N 图把"哪个值有多少行"显式记账 ✅ B14211 Ch14 概念）。
- SQLite 侧同题（诚实边界）：`sqlite_stat1` 只有"表行×键均值"两数（`demo_out.txt` D3 行），无分布形态概念——Oracle 式"统计翻案计划"在轻量引擎不可复现（波5 #28 册 D3 负结果同型结论，✅ [../Oracle_Performance_Tuning_2e/06-优化器统计与SQL调优.md](../Oracle_Performance_Tuning_2e/06-优化器统计与SQL调优.md)）。
- **判定：非 Oracle 引擎行为**；教学价值=让你亲手看见"没直方图的优化器如何惨败"，回去读 10g `METHOD_OPT` 贴士会心。

## 6. 解析经济学与绑定变量（⚠️ 通说；应用账本见 `09`）

## 9. 统计值班十问（⚠️ 快查清单，收编本章各节）

1. 表统计最后何时采？`DBA_TABLES.LAST_ANALYZED` 与装载日历对表。
2. 自动收集作业在跑吗？窗口/停止原因/失败记录（`DBA_AUTOTASK_*` 族 ⚠️）。
3. 倾斜列有直方图吗？`DBA_HISTOGRAMS` 的桶形（FREQUENCY/TOP-N）与 `METHOD_OPT` 策略一致吗？
4. 统计会"新得可疑"吗？行数暴涨但 NDV/CF 不变=采样问题 ⚠️。
5. 静态参照表锁了统计吗？防夜间冲刷（`03` reload 连锁的元凶位）。
6. 系统统计采集了吗（10g 新，NOWORKLOAD vs WORKLOAD 差异 → `04` 章成本换算）。
7. 导出/导入统计通道用于发布回归了吗 ⚠️（测试库照生产口供说话）。
8. 动态采样在场吗（10g `OPTIMIZER_DYNAMIC_SAMPLING` 默认值口径 ⚠️ 按文档）。
9. 计划里 Est Rows 与 A-Rows 差几倍？>10 倍处先查 1–7 再谈 hint。
10. 上次计划突变对上了哪次统计动作？`V$SQL_PLAN` 的历史（AWR SQL 计划快照 `DBA_HIST_SQLPLAN` ⚠️）是时间线证据。
- 十问全部可由人答=统计值班合格；任何一问长期"不知道"=本册时代所谓"调优救火队"的病根 ⚠️。

## 10. V$SQL_PLAN 字段小卡（⚠️ 通说；判读双铁律的字典页）

| 字段 | 读法 |
|---|---|
| `ID/PARENT_ID` | 树形缩进=行源序，自最深读起 |
| `OPERATOR/OPTIONS` | 访问法×变体（FULL/RANGE/HASH/MERGE+BLOOM 等 ⚠️） |
| `OBJECT_NODE` | RAC 全局计划才见实例列（→ `08`） |
| `OPTIMIZER` | 语句当时模式（`01/05` 的 ALL_ROWS vs n 分诊） |
| `COST` | 相对量纲，跨版本/跨库不可比 ⚠️ |
| `CARDINALITY/BYTES/CPU/IO` | 预估三口供：行/字节/单位成本 |
| `OTHER_TAG/FILTER/STARTUP_COST` | 谓词下推与分布式碎片线索 |
- 与 `DBA_HIST_SQLPLAN` 连用做"计划考古" ⚠️：同 SQL_ID 的窗口间计划漂移，多数对应 `05` 的统计事件或 `07` 的 hint 注入。
- 深挖成本字段语义 → CBOF `01` 章（✅ [../Cost_Based_Oracle_Fundamentals/01-成本究竟指什么.md](../Cost_Based_Oracle_Fundamentals/01-成本究竟指什么.md)）；本章只负责"字段先长什么样"。

### 附记：统计误读三则（⚠️ 通说纠偏）

- 一则：`LAST_ANALYZED` 新≠口供真——装载 50% 时采的统计比三天前的旧统计更害人；对账要 `DBA_TAB_STATISTICS` 的 ROWS×实测 COUNT ⚠️。
- 二则：直方图不是万能药——等值均匀的列加图纯属计划噪声放大器；`METHOD_OPT` 的"按列定制"才是纪律 ⚠️（对读 ✅ [../Cost_Based_Oracle_Fundamentals/07-直方图.md](../Cost_Based_Oracle_Fundamentals/07-直方图.md)）。
- 三则：CF 高低不是绝对病——全扫型负载 CF 高无伤，OLTP 点查 CF 高才回表税爆；判据永远是"该对象的工作负载形状" ⚠️（✅ 解剖 [../Cost_Based_Oracle_Fundamentals/05-聚簇因子.md](../Cost_Based_Oracle_Fundamentals/05-聚簇因子.md)）。
- 三则共用心法：**统计的真假要拿业务实测对账，不与上一版对账** ⚠️。

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| 基于代价的优化器 | CBO (Cost-Based Optimizer) | 按统计估算成本选计划 |
| 系统统计 | System statistics (`CPU_IO_STATS`) | 把 CPU/IO 速度标进成本单位 |
| 直方图 | Histogram | 列值分布的显式记账 |
| 聚簇因子 | Clustering factor | 索引序与表物理序的一致度 |
| 执行计划 | Execution plan | 算子树+行源序 |
| 预估/真身计划 | Explain plan vs `V$SQL_PLAN` | 纸面答案 vs 共享池实物 |
| 行活动统计 | Row source statistics (10046/A-Rows) | 每算子实际行数与耗时 |
| 绑定变量窥视 | Bind peeking | 首值定计划的 10g 机制 |
| SQL Profile | SQL Profile | 不改语句喂修正系数 |
| 统计锁定/导出 | Lock/Export statistics | 防冲刷与跨库搬运 |

## 最新演进与工业实践

- **制度延续 ✅**：`DBMS_STATS`+直方图+系统统计全链在 19c/23ai 在册（✅ 门户实抓 00 §12.7；10.2 B14211 Ch13–14 为祖版）。
- **代际增量 ⚠️→现役**：11g **自适应游标共享（ACS）**终结 peeking 悖论主战场、SQL Plan Management（Baseline）接棒 Outlines、**动态采样**升格为默认（`OPTIMIZER_DYNAMIC_SAMPLING`）；12c 直方图增强与在线统计收集、**结果缓存**；19c **实时统计（Automatic Workload Repository 表监控/online stats）**与自动索引任务——本册的"喂料三板斧"今天由调度器代喂一半，**人判倾斜与回归** 仍归人 ✅（对读 [../Troubleshooting_Oracle_Performance_2e/07-系统统计信息.md](../Troubleshooting_Oracle_Performance_2e/07-系统统计信息.md)/[08-对象统计信息.md](../Troubleshooting_Oracle_Performance_2e/08-对象统计信息.md)）。
