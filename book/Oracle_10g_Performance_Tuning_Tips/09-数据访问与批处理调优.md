# 09 数据访问与批处理调优 — Oracle Database 10g Performance Tuning Tips & Techniques（精读重构）

> ⚠️ 主题重组口径（章号非原书章号，降级声明见 [00-总览与阅读地图.md](00-总览与阅读地图.md) §3）。本章=应用侧的"往返经济学"：连接、解析、行处理、事务边界与批量搬运；对应官方 B14211 Ch2《Designing and Developing for Performance》域（✅ 目录实抓在册）。
> Oracle 行为 ⚠️ 转述（引擎不可实测）；跨引擎直觉可回看 🔧 D2/D5（`06/05` 章，非 Oracle 行为）。

## 1. 一次 SQL 往返的成本解剖（⚠️ 通说）

应用→网络→服务器进程→（解析/执行/取行→网络→应用）循环。四个税种 ⚠️：
1. **解析税**：硬解析 CPU（`05` 章绑定变量纲）；
2. **往返税**：每 fetch 一轮网络握手——行处理型（逐行 `FETCH`）把税乘上行数；
3. **执行税**：计划与 IO（`02–07` 全链）；
4. **提交税**：每次 commit 一趟 redo 落盘等待对（`04` 章）。
- 本册立场（贴士体裁必然强调 ⚠️）：**实例调优到边际后，剩余大头都在应用侧**——这句 2005 年的话在 2026 仍是性能工程的铁律。

## 2. 连接与会话管理（⚠️）

- 专职服务器=一连接一进程（Unix）/一线程（Windows `SHARED_SERVERS` 场景另算）；连接风暴的三档解 ⚠️：应用连接池（首选）→ Bequeath 队列参数（`QUEUESIZE`）→ **共享服务器/池化**（`dispatchers`、`shared_servers`，高并发低 CPU 场合，代价=上下文切换与内存）。
- 监听器账本 ⚠️：`tnsnames` 的 `SDU`（会话数据单元）调大包减少往返分片；`TCP.NODELAY` 治 Nagle 延迟——本册时代最经典的"网络两贴士"。
- 空闲会话堆积：`SQL*Net message from client` 是空闲等待（`02` 分界）但占 PGA 与进程资源——池上限+超时回收是应用侧责任。

## 3. 数组接口：批量行搬运的艺术（⚠️ 本章王牌）

- 逐行 SQL 引擎（游标一开一合=往返×行数）vs **数组/集合接口**：OCI `OCIBandArray*`、Pro*C `ARRAY` 宿主、**PL/SQL `BULK COLLECT`+`FORALL`**（9i 引入，本册时代主推 ⚠️）。
- `FORALL` 三形态：默认/`SAVE EXCEPTIONS`/`INDICES OF`+`VALUES OF`（跳空洞数组）——批量 MERGE/UPSERT 配方（配 `07` 章 MERGE）。
- `BULK COLLECT LIMIT` 的内存/往返折中 ⚠️（默认全表吞进 PGA 是事故候选——PGA 账回看 `03`）。
- 跨引擎直觉：🔧 D2 覆盖索引省回表在轻引擎已演示"少一趟=少一半"（**非 Oracle**）；数组接口同构物=各引擎的 prepared statement 批量绑定/参数数组（对读盘上 ✅ [../数据库性能调优.md](../数据库性能调优.md) 的行协议节）。

## 4. 批量装载与搬山（⚠️ 通说；✅ B14211 Ch2 域）

- **SQL*Loader 直Path**（`DIRECT=TRUE`）：旁路缓冲缓存、按区写、`UNRECOVERABLE` 配套——"夜装载窗口减半"的本册时代标准姿势 ⚠️；约束/触发器限制清单照抄前逐条对文档。
- **外部表（9iR2 起）+ 并行**：文件即表；与 Data Pump（10g 新，`expdp/impdp` ✅ 概念在册）构成"库到库"快线——盘上案例证词 ✅ [../Oracle_Database_Problem_Solving/07-数据泵与快速迁移.md](../Oracle_Database_Problem_Solving/07-数据泵与快速迁移.md)。
- 索引后置律 ⚠️：先装数据后建索引（或 `PARALLEL NOLOGGING` 重建，`06` 章配方）；分区表 direct path insert（10g `INSERT /*+ APPEND */` 对分区本地/全局索引的维护代价差异是经典坑 ⚠️）。
- 装载统计闭环：装载后立即 `DBMS_STATS`（`05` 喂料纲），否则第一波查询用旧口供演灾难片 ⚠️。

## 5. 并行家族（⚠️ 10g 全盛期）

- 三入口：DOP 声明（`PARALLEL(t,4)`）/表属性/会话+系统参数（`PARALLEL_MAX_SERVERS` 预算）；查询并行（PX 进程组 QC+slaves）、DML 并行需 `ENABLE PARALLEL DML`、索引建/重扫并行（`06`）。
- 收益曲线诚实话 ⚠️：并行是"以总资源换墙钟"，单查询变快与吞吐变慢可以同真（`01` 章目标函数再教育）；SMP 超线程时代后"并行过度=闩锁烟花"（对读盘上现代案例 ✅ [../Oracle_Database_Problem_Solving/05-AWR分析优化.md](../Oracle_Database_Problem_Solving/05-AWR分析优化.md) 的 PX 病理）。
- 10g 新器 ✅ 概念在册：**并行自动度**（`parallel_adaptive_multi_user`，按需降 DOP ⚠️ 后被弃）与统计并行收集（`GATHER_STATS_JOB` 内并行）——后者活到今天。

## 6. 事务边界与提交节拍（⚠️ 收官常识）

- 短事务三理由：锁持有时间（`08`）、undo 链长（`08`）、redo 峰值（`04`）；**批内提交节拍**（每 N 行 commit）是装载吞吐与失败重做窗的折中 ⚠️——N 的本册时代经验值"万级"，2026 仍按 redo 预算定。
- 自治事务（`PRAGMA AUTONOMOUS_TRANSACTION`）在审计日志场景的诱惑与 undo/锁副作用 ⚠️——慎用贴士的代表。
- 只读路径的快照隔离期待：一致性读零阻塞是 Oracle 对读写混战的世纪答案（`08` CR 机理的应用面）——MySQL/PG 读者对读 ✅ [../高性能mysql.md](../高性能mysql.md)（MVCC 节）、[../Efficient_MySQL_Performance/00-总览与阅读地图.md](../Efficient_MySQL_Performance/00-总览与阅读地图.md)。

## 7. 应用调优体检单（⚠️ 重组收口）

| 检查项 | 证据 |
|---|---|
| 绑定变量覆盖率 | 硬解析率/`V$SYSSTAT` parse 族 |
| 逐行循环热点 | `SQL*Net` 往返计数/10046 |
| 提交粒度 | 每秒 redo 量/`log file sync` 次数 |
| 大结果集策略 | fetch 尺寸/BULK 化 |
| 装载链路 | 直Path/外部表/索引后置到位 |
| 并行使用 | DOP 预算 vs 批窗口日历 |
- 使用法：任何"实例侧无病灶但应用喊慢"的工单，先跑这张单——本册时代与 2026 的 DBA 分工共识几乎未变。

## 8. 会话级性能参数小名单（⚠️ 博物馆读法；全部以"能窄不宽"为纲）

| 参数（`ALTER SESSION` 域） | 当年用途 | 2026 备注 |
|---|---|---|
| `arraysize`（客户端预取组宽） | 减 fetch 往返 | 现役（驱动层同名思想） |
| `cursor_sharing` | 解析止血带 | 现役但 EXACT 为纲（`05`） |
| `sort_area_size`（POLICY=MANUAL） | 夜批大排序 | 化石面保留（`03`） |
| `db_file_multiblock_read_count` | 全扫吞吐 | 化石（`04`） |
| `parallel_max_servers` 会话护栏 | PX 预算 | 现役（自动 DOP 改语义 ⚠️） |
| `workarea_size_policy` | AUTO/MANUAL 切换 | 现役 |
| `optim_reshape_*` 类 hint 开关 | 试验变换行为 | 隐藏参红线（`05/10`） |
| `ALTER SESSION SET EVENTS '10046 …'` | 自跟踪 | 现役（oradebug 通道 `10`） |
| `NLS_LANG/字符集` | 转换 CPU 税 | 现役（UTF8 时代改形不改理 ⚠️） |
| `transaction_isolation/read only` | 报表防 1555 缓解 | 现役（→ `08` CR 账） |
- 纪律 ⚠️：会话级试验必须可回收（`ALTER SESSION` 随会话灭），把会话参数抄进 PROFILE/LOGON TRIGGER 前想清楚"要的是临时还是永久病"。

## 9. 应用侧与实例侧的责任分界表（⚠️ 收口，`01` 章三问的落地）

| 工单症状 | 第一责任侧 | 证据入口 |
|---|---|---|
| 偶发超时且 DB 无等待异常 | 应用（池/网络/GC） | AWR 正常+OS 指标 |
| 逻辑读随版本发布暴涨 | 应用 SQL 改写 | `V$SQL` 新旧 SQL_ID 对比（`05`） |
| 高峰 `latch: shared pool` | 应用绑定/解析 | 解析率（`05`） |
| `log file sync` 高 | 应用提交节拍 | redo/s 曲线（`04/09`） |
| 计划突变 | DBA+开发共判 | 统计时间线（`05` §10） |
| 装载窗口超时 | 平台共判 | TEMP/直Path/并行链（`04/09`） |
| 全链健康仍慢 | 应用行处理 | 10046 服务 vs 等待分解（`10`） |
- 使用法：先跑第 `07` 节的体检单与本表定位责任侧，再动对应章处方——本册最值钱的一页其实不是任何单条参数 ⚠️。

### 附记：批处理窗口日历模板（⚠️ 夜批组织学）

- 窗口分层：装载（外部源→暂存表）→ 校验（行数/聚合双账）→ 变换（批量 MERGE/INSERT APPEND）→ 索引/统计维护 → 汇总物化 → 报表分发 ⚠️。
- 资源分时：并行段（PX+直Path+TEMP 高峰）与串行段（校验/小 DML）错开；统计收集放装载尾（`09` §4 闭环）⚠️。
- 失败重做单元：以分区/批次为 checkpoint 粒度（每单元提交节拍对齐 `04` redo 预算与 `08` undo 链长）⚠️。
- 观测存档：每窗口留 AWR/`V$SYSSTAT` 对差+`gv$session_longops` 进度行——本册时代的"批处理可观测性"手工艺，思想即当代 pipeline SLA 表 ⚠️。
- 与 `01` 章目标函数呼应：夜批优化的是"完成时刻"与"总资源"两个账，单条 SQL 变快可能让两账同时变坏（过度并行挤占）⚠️（对读盘上仓库教材装载章 ✅ [../Oracle_Essentials_5e/08-仓库实施分区物化视图与装载.md](../Oracle_Essentials_5e/08-仓库实施分区物化视图与装载.md)）。

### 附记二：数组接口选型口诀（⚠️）

- 行多必数组、行大先瘦身、内存设 LIMIT、异常留 SAVE——四短语是本章第 3 节的口袋版 ⚠️。
- 与驱动层对应：JDBC batch/ODP.NET 数组参数即其当代方言，口诀不变、动词轮换。

## 最新演进与工业实践

- **现役主干 ✅/⚠️**：绑定变量、数组接口、短事务三律跨代际零迁移成本（19c/23ai 文档与驱动层默认支持 ⚠️，门户实抓见 00 §12.7）；Data Pump 至今是搬运正路（`impdp` 的并行/转换子句换代增强 ⚠️）；SQL*Loader 直Path 让位 **ODCI/外部表+SDK 化装载**（12c In-Database Archiving、19c 自动并行装载 ⚠️）。
- **接口层革命**：本册时代"OCI/Pro*C 数组"的姿势，2026 换成了 JDBC batch/各语言驱动 pre-fetch（`fetchBatch`/`stmt.setFetchSize`）——**协议思想未变，词汇表换了**；池化从"共享服务器参数"变成应用侧连接池工业标准（对读盘上应用侧性能 ✅ [../Java性能权威指南.md](../Java性能权威指南.md) 的 JDBC 节）。
- **并行自动度兴衰 ⚠️**：`parallel_adaptive_multi_user` 已被官方弃用路线清出（12c 后不再推荐），并行升级为"自动 DOP（12c `PARALLEL_MAX_SERVERS`+AUTO 度）+ 语句队列（PX 调度器）"——读 10g 并行贴士先查 19c/23ai 并行章差异。
- **工业实践对照**：批量 vs 逐行的往返经济学是所有客户端-服务端系统的通识（盘上登记在册目录 `../Database_Reliability_Engineering/`：N+1 查询防治是 SRE 常设科目；守"只链已验名文件"纪律故此处仅登记不直链）。
- **2026 姿势**：学现代应用侧数据访问，盘上首选 TOP 2e 的解析/数据访问组章（✅ [../Troubleshooting_Oracle_Performance_2e/12-解析.md](../Troubleshooting_Oracle_Performance_2e/12-解析.md)/[13-优化数据访问.md](../Troubleshooting_Oracle_Performance_2e/13-优化数据访问.md)）；本章价值=2005 年应用-实例责任划分的原始文本，凡参数名先过时校验。
