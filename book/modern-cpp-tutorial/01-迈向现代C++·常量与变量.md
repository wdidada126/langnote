## 一、动机：为什么第一章先讲"别用什么"

欧长坤的处理方式与商业书不同：开篇不列新特性清单，而是先立"负面清单"。C++ 的向后兼容承诺意味着旧写法不会被立刻删除，只会被"弃用"暗示——而新手最难判断的恰恰是哪些写法已被判了缓刑。第二段（§1.2）解决另一个认知偏差：大量从 C 转来的读者把 C++ 当"C 加类"，作者用一张韦恩图和一句结论（"**C++ 不是 C 的一个超集**"）提前拆掉这颗雷，再引出 `extern "C"` 这条与 C 互操作的唯一正道。§2.1/§2.2 则进入"编译期能确定的事别留给运行期"的主线：`nullptr` 修的是 `NULL` 的类型语义缺陷，`constexpr` 修的是 `const` 名不副实的"常量表达式"缺陷，初始化列表和结构化绑定修的是"同一种初始化有好几种互不兼容语法"的表达缺陷。

## 二、机制：逐条拆开

**被弃用清单的"现在时"状态**（原书列了 8 条，实测其现状）：`char* ← 字符串字面量` 在 C++11 起被禁止（编译器多数只给警告，加 `-pedantic-errors` 才报错，见 🔧b）；异常说明（`throw()`）与 `auto_ptr` 已在 C++17 **删除**而非仅弃用；`register` 在 C++17 移除了存储期含义，但 GCC 15 在 `-std=c++17` 乃至 `-std=c++26` 下仍拒绝把它用作标识符（实测，🔧c）——原书"作为保留关键字，目前不具备实际意义"的说法与编译器行为一致。

**nullptr 的真实对手是 `__null`**。原书 2026 修订版讲得很准：`NULL` 是实现定义的空指针常量；定义为 `0` 的实现（MSVC）会让 `foo(NULL)` 静默调用 `foo(int)`，定义为 Clang/GCC 内建 `__null` 的实现则让重载决议产生歧义。`nullptr` 的类型 `nullptr_t` 只能隐式转成指针/成员指针，把这两条歧路一次堵死。

**constexpr 与"const ≠ 常量表达式"**。数组长度必须是常量表达式：`const int len_2 = len + 1;`（len 为运行期值）产生的 `len_2` 是"常数"但不是"常量表达式"；GCC/Clang 默认开 C99 变长数组（VLA）扩展，让非法代码"能过"，这正是原书提醒加 `-pedantic-errors` 的原因。`constexpr` 把"我保证编译期可求值"变成编译器强制校验的契约；C++14 放宽函数体（局部变量、循环、分支），C++11 时代只能写三目递归。

**if/switch 初始化语句（C++17）** 把临时变量锁进 `if` 作用域（`if (auto itr = find(...); itr != end())`）；**`std::initializer_list`（C++11）** 统一了数组/POD/类对象的初始化语法，代价是带 IL 构造函数的类型在 `{}` 初始化时会被优先选中（隐式 `vector` 陷阱的根源）；**结构化绑定（C++17）** 则把 `std::tie` 的"先声明、类型全写对"降级为 `auto [x,y,z] = f()`。

### 🔧 实测 a：nullptr 与 `__null`（复现原书 §2.1 判别代码）

```cpp
#include <cstdio>
#include <type_traits>
void foo(char*) { std::puts("foo(char*)"); }
void foo(int)   { std::puts("foo(int)"); }
int main() {
    std::puts(std::is_same<decltype(NULL), std::nullptr_t>::value ? "NULL -> nullptr_t" : "NULL -> not nullptr_t");
    std::puts(std::is_same<decltype(NULL), decltype(0)>::value ? "NULL same as 0" : "NULL differs from 0");
    foo(0); foo(nullptr);
    // foo(NULL);  // 打开后见下
}
```

已实测 g++ 15.2（`-std=c++17`）输出：

```text
NULL -> not nullptr_t
NULL differs from 0
foo(int)
foo(char*)
```

打开 `foo(NULL)` 后：`error: call of overloaded 'foo(long long int)' is ambiguous`——g++ 的 `NULL` 是 `__null`，在重载决议里以 `long long` 身份参与，两条转换都可行 → 歧义。**原书"GCC/Clang 下歧义"的论断在 GCC 15 复现成功**；同时注意 `decltype(NULL)` 在 g++ 下既不是 `int(0)` 也不是 `nullptr_t`，原书示例程序里三个 `if` 全不打印，属教材省略，实测补充如上。

### 🔧 实测 b：字符串字面量→`char*` 的档位边界

```cpp
int main() { char *s = "hello world!"; return s[0] == 'h' ? 0 : 1; }
```

已实测 g++ 15.2 + `-pedantic-errors`：`-std=c++98` 仅警告（`deprecated conversion ... [-Wwrite-strings]`，仍可链接运行）；`-std=c++11/17/20` 一律 `error: ISO C++ forbids converting a string constant to 'char*'`。弃用→禁止的时间线在编译器上以 C++11 为界，与原书"C++11 起不再允许"吻合。

### 🔧 实测 c：constexpr 循环放宽（原书 §2.1 的 fail→OK 边界）

```cpp
constexpr long fib(int n) {
    long a = 1, b = 1;
    for (int i = 3; i <= n; ++i) { long c = a + b; a = b; b = c; }
    return b;
}
```

已实测 g++ 15.2：`-std=c++11` → `error: body of 'constexpr' function ... not a return-statement`；`-std=c++14` → 通过，`fib(30) = 832040`。同文件验证 VLA：`char bad_arr[m];`（m 为 const 但运行期初始化）在 `-std=c++14`（GNU 扩展默认开）下**编译通过**、加 `-pedantic-errors` 后 `error: ISO C++ forbids variable length array`——原书关于扩展"伪装合法"的警告属实。

### 🔧 实测 d：§1.2 的 `extern "C"` 分离编译（书内 code/1 的做法，MinGW 版）

```c
/* foo.h */
#ifdef __cplusplus
extern "C" {
#endif
int add(int x, int y);
#ifdef __cplusplus
}
#endif
```

```cpp
// main.cpp
#include "foo.h"
#include <cstdio>
int main() { std::printf("Result from C code: %d\n", add(1, 2)); }
```

已实测 g++ 15.2 / gcc 15.2（MinGW）：`gcc -c foo.c` → `g++ main.cpp foo.o -std=c++17 -o app`，输出 `Result from C code: 3`。书内示例用 `clang++ -std=c++2a` 与 Makefile 表述，机制与工具链无关；`extern "C"` 改变的是**链接名（name mangling）与调用约定**，不改变语言语法——这也是为什么头文件要用 `__cplusplus` 宏包夹：C 编译器不认识 `extern "C"` 语法。原书用一段"看不懂的花哨 lambda"（`[out = std::ref(...) ]{...}()`）做钩子引后续章节，是教程惯用的悬念手法，2026 修订版保留未动。

## 三、权衡与陷阱

- `nullptr` 零成本，但 `NULL` 的两种坏行为（静默选 `int` 重载 / 歧义）说明：坏的不是宏，是"整数冒充空指针"的类型系统漏洞。
- `constexpr` 是接口契约而非优化提示：函数只要有**一条**路径无法编译期求值，整体就不是 constexpr（C++11 更苛刻，见 🔧c）。滥用 `const` 冒充常量表达式会被 VLA 扩展掩盖，直到换了 `-pedantic-errors` 的 CI 才爆雷——🔧c 就是这个边界。
- `std::initializer_list` 的统一语法有暗面：`std::vector<int> v{5};` 是 1 个元素而非 5 个容量；`v5{}` 与 `{}` 重载歧义让"统一"打了折扣。原书没讲这一层，读 Effective Modern C++ item 7 补。
- 结构化绑定不生成真变量而是**别名**（对成员绑定时），所以不能对它取 `decltype` 得到成员类型以外的新东西，也不能给它加 `mutable`；`auto [x,y,z] = f()` 对 tuple 会引入移动，而 `auto& [x,y,z]` 才零开销。

## 四、与相邻概念对比

| 维度 | `NULL` | `0` | `nullptr` |
|---|---|---|---|
| 类型 | 实现定义（`__null`/int） | int | `std::nullptr_t` |
| 重载决议 | 歧义或抢 `int` 档 | 永远匹配整数档 | 只匹配指针档 |
| 判据 | 用 🔧a：g++ 下三者互不相同 | | |

| 维度 | `const T`（运行期常量） | `constexpr`（常量表达式） |
|---|---|---|
| 求值时点 | 可在运行期 | 编译期可验证 |
| 做数组长度 | 否（VLA 扩展会骗你） | 是 |
| 做模板实参 | 仅整型常量表达式 | 是（C++20 扩展到类类型） |

## 核心概念速览（中英对照）

- **弃用** — deprecation：标准明示未来会移除、当前仍可用的特性状态
- **空指针常量** — null pointer constant：能隐式转换为任意指针类型的特殊值
- **将亡值前置概念：常量表达式** — constant expression：仅依赖字面量/constexpr 实体、编译期可求值的表达式
- **变长数组（扩展）** — variable length array, VLA：C99 特性，GCC/Clang 以扩展形式在 C++ 中默认可用
- **初始化列表** — braced-init-list / `std::initializer_list`：`{...}` 语法与其轻量视图类型
- **统一初始化** — uniform initialization：C++11 让任意对象可用花括号语法初始化
- **POD 类型** — plain old data：无构造/析构/虚函数的平凡类型（C++20 后拆分为 trivial/standard-layout）
- **结构化绑定** — structured bindings：把 tuple/pair/数组/聚合体解包进一组具名变量（C++17）
- **if 初始化语句** — init-statement in if/switch：把临时变量限制在条件语句作用域内（C++17）

## 最新演进与工业实践

- **`__null` 已近失传**：VS 2017 起 MSVC 在 C++ 模式把 `NULL` 从 `0` 改为 `nullptr`（原书"定义为 0 例如 MSVC"指的是旧版行为，2026 修订版亦如此区分；本机未装 MSVC，⚠️ 文档性陈述未实测）；g++ 15 维持 `__null`（🔧a 实测）。工业 lint（clang-tidy `modernize-use-nullptr`）把"禁 NULL"作为默认检查项。
- **`auto_ptr` 的墓地**：C++11 弃用、C++17 删除。迁移目标不是 `shared_ptr` 而是 `unique_ptr`——它才是 `auto_ptr` 移动语义的正统后代（见本笔记 07 篇）。
- **`std::expected` 谱系**（见 12 篇）：错误码→异常→optional→expected 的钟摆，在本章"负面清单"精神的延长线上。
- **constexpr 的军备竞赛**：C++20 允许 `constexpr virtual`、`std::vector`、`new/delete`（P0784R7 *More constexpr containers*，wg21.link/P0784 实测 302）；C++23 放宽 `goto`/标签语句（原书 §11.1 末节有记）。工业上 Google/Bloomberg 的代码规范都把"能在编译期算"列为性能手册第一档。
- **社区重估**：本章的"弃用清单"在 2026 版仓库里仍保持原样，是全书被引用最多的页之一；Reddit r/cpp 多次把它作为"从 C++98 迁移的第一页"推荐。教程止步于清单，Core Guidelines（R.*/ES.* 条目）给出每条弃用的替代写法，两读互补。
