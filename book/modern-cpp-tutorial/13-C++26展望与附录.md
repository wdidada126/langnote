## 一、动机：一本"高速上手"的书如何处理"还没发生的事"

第 12 章是全书方法论的试炼场：教程如何讲一个**尚未定稿**的标准？作者的答案是三段式——只收"最终语法大概率不变+已有可编译子集"的特性（包索引/delete 原因/占位符/饱和算术），概念性预告反射与契约并明说"当前无法编译"，最后 §12.3 用一整节强调"标准-实现-时间"的三重不确定。这份克制恰是附录 1"进一步阅读"清单存在的意义：教程负责搭骨架，生长靠社区。

## 二、机制

**§12.1 语言侧五件**

- **静态反射（P2996R13）**：编译期把类型/成员/枚举项变成一等公民数据：`constexpr auto r = ^^int;` 取反射值，`typename [: r :] x = 42;` 用"拼接"语法把反射值变回代码。目标：序列化/注册表/DI 告别宏与外置代码生成器。书的边框警告"主流工具链尚不可用"（截至成文，Clang 有实验分支，GCC 未落地）。
- **契约（P2900R14）**：`pre(...)`/`post(r: ...)`/`contract_assert(...)` 三级前置/后置/语句断言，违约行为可全局配置（terminate/记录后继续）。11 篇里被辟谣的 Contracts 在这里复活——从"C++20 的弃婴"到"C++26 的头牌"，教科书级案例：**特性时间表会漂移，教材必须跟着改口**（本教程 2026 修订正是这么做的）。
- **形参包索引（P2662R3）**：`ts...[0]`、`ts...[sizeof...(ts)-1]` 直接索引包元素，终结"取首元素要 tuple 中转"的体操。
- **带原因的 = delete**：`= delete("pass a real buffer, not nullptr")`，删除理由进编译错误。
- **占位符 `_`（P2169R4）**：`_` 成为可重复声明的"不关心"名字，`auto _ = f();` 表达丢弃而非匿名块。

**§12.2 库侧**

- **std::execution（P2300R10）**：发送者/接收者模型——异步任务的组合代数（`schedule/starts_on/then` 等），std::async（09 篇）的十年换代品。书的诚实警告：不提供可运行示例，因为实现未落地。
- **饱和算术（P0543R3）**：`<numeric>` 的 `add_sat/sub_sat/mul_sat/div_sat/saturate_cast`，溢出钳制而非回绕——图像/音频/SIMD 累加的 UB 终结者。
- **其他库设施**：`inplace_vector`、`function_ref`、`<simd>`、`std::linalg`、`text_encoding`；书特别标注 **`std::hive` 是否纳入仍不确定**（⚠️ 作者自己挂的免死金牌，引用时留意）。
- **其他值得关注的提案**：结构化绑定进 `if/while`、平凡可重定位（trivially relocatable）、constexpr 结构化绑定、`submdspan`、加固标准库（hardened）、`std::breakpoint` 等。

**附录群**：附录 1 是一份精选书单/资料清单（与本书互补：cppreference、各原著）；附录 2 六节最佳实践——常用工具（clang-tidy/格式器/Sanitizers）、代码风格（RAII、const 正确性、按值 return+move）、整体性能（避免不必要拷贝、容器选型）、代码安全（智能指针、边界检查、`-fsanitize`）、可维护性（小函数、命名空间、头文件纪律）、可移植性（避免扩展、注意 UB 与实现定义行为）；附录 3 五张"特性→版本"索引表（C++11/14、17、20、23、26），是全书最好用的速查页——也是本系列 00 篇映射表的对照基准（其"默认模板参数"条目与正文有漂移，见勘误台账）。

### 🔧 实测：C++26 四件可编译子集 + 两个"教材没说的细节"（g++ 15.2，`-std=c++26`）

```cpp
template <typename... Ts> auto first(Ts... ts) { return ts...[0]; }   // 包索引
void use_span(int* p, int n);
void use_span(std::nullptr_t, int) = delete("pass a real buffer, not nullptr");
auto _ = compute();  auto _ = compute();      // 占位符重复声明
std::add_sat(std::numeric_limits<int>::max(), 1);                       // 饱和
```

已实测 g++ 15.2 输出：

```text
first=1 last=3
error: use of deleted function 'void use_span(std::nullptr_t, int)': pass a real buffer, not nullptr
a = 1, _ 被复用了三次
add_sat(INT_MAX,1) = 2147483647
wrap: hi+1 = -2147483648
sub_sat(0,1) = -1
```

四个书例档位全部与 §12.3 "当前能编译的是其中一小部分" 的说法吻合。**两个实测发现**：① 删除原因要在**同元数重载**里被选中才会打印——书例 `use_span(std::nullptr_t)`（1 参）配 `use_span(int*, int)`（2 参）时，`use_span(nullptr, 0)` 只会因元数不匹配报错，看不到自定义原因（本实测把两者都改成 2 参才复现）；② GCC 15 对 `_` 的实现有毛刺：**声明三次合法，但任何读取 `_` 的表达式（哪怕写 `(_)`）都报 `reference to '_' is ambiguous`**——书例"只声明不读取"恰好绕开，用时须知。附加实测：`-std=c++23 -pedantic-errors` 下占位符例报 `error: name-independent declarations only available with '-std=c++2c'`，档位边界钉死；`register` 关键字在 `-std=c++26 -pedantic-errors` 下仍保留（`int register = 5;` → `error: expected unqualified-id before '=' token`），原书"register 已弃用但未删除"的表述在 GCC 15 依旧成立。

## 三、权衡与陷阱

- 反射的"拼接语法 `[: :]`"与 `^^` 仍是 P2996 文档语法，ISO 投票前的任何教程示例都自带变质风险——本书的概念性示例配"目前无法编译"警告是正确姿势，读者不要拿它当可运行代码传抄。
- 契约违约处理级别（`contract_violation` 动作决定 terminate 还是继续）是**编译选项级**策略：把本应 terminate 的违约在生产环境调成"继续"是合规灾难，书未展开但必须意识到。
- 占位符 `_` 不延长生命周期：`auto _ = lock();` 立即析构（它是个有名字的对象，名字恰好可复用），与"未绑定的 `std::unique_lock` 临时量"是不同坑。
- 饱和算术用于"业务语义钳制"；需要精确检测溢出仍要用 `__builtin_add_overflow` 风格或检查前后值——`add_sat` 静默丢信息。
- std::execution 落地前，异步 C++ 的现实选项仍是：std::async（够用）、folly::coro（C++20 协程派）、asio（IO 派）。

## 四、与相邻概念对比

| C++26 件 | 前浪/替身 | 升级点 |
|---|---|---|
| 反射 | 宏/外部代码生成器 | 语言内建、constexpr 可用 |
| Contracts | assert/gsl::Expects | 标准化语义+可配置处置 |
| `pack...[N]` | tuple 展开取索引 | 一行 |
| `= delete("why")` | 匿名删除+脑补 | 错误信息携带设计意图 |
| `std::execution` | std::async/回调 | 可组合调度代数 |
| `add_sat` | 手写 clamp+UB 风险 | 标准原语 |

## 核心概念速览（中英对照）

- **静态反射** — static reflection：编译期检视/操作程序结构（`^^`、`[: :]`）
- **契约** — contracts：pre/post/contract_assert 的接口约定
- **形参包索引** — pack indexing：`pack...[N]`
- **带原因的删除** — deleted with reason：`= delete("...")`
- **占位符名** — placeholder `_`：表达"不关心"的可复用名字（P2169R4）
- **发送者/接收者** — senders/receivers：std::execution 的异步组合模型
- **饱和算术** — saturation arithmetic：溢出钳制原语
- **就地向量** — inplace_vector：无堆分配定容容器（展望）
- **函数引用** — function_ref：非拥有可调用引用（展望）
- **平凡可重定位** — trivially relocatable：移动=memcpy 的标准许可
- **加固标准库** — hardened library：边界/生命周期检查构建档

## 最新演进与工业实践

- **实现状态时间线（以 §12.3 口径）**：g++ 15.2 的 `-std=c++26` 已可玩包索引/delete 原因/占位符/饱和算术（本篇四项全部实测通过）；反射在 Clang 21 系实验分支（⚠️ 本机未验证）；contracts 的 GCC/Clang 前端支持仍在演进。std::execution 的参考实现 stdexec（NVIDIA/GodBold）早已工业可用，标准合流在 2026-2027 窗口。
- **社区重估**：C++26 被戏称"C++20 的延迟交付包"——ranges/concepts 收尾件+contracts+reflection 全是上一周期立项；教程第 12 章与附录 3 的对照阅读能把这张"跨版本工程图"看清。`std::hive` 的"不确定声明"也是教材处理争议提案的范本。
- **附录 2 的现实映射**：六节最佳实践对应的工业工具链 2026 已全部标准化——clang-tidy `modernize-*`/`bugprone-*`、Address/Thread/UB Sanitizer 三件套、Compile Explorer 反汇编纪律；"按值返回+移动"（附录 2 性能节）在 C++17 强制复制消除（05 篇）后有了更强的理论保证。
- **对照阅读**：`../Effective_Modern_C++/09-专题-书后演进时间线.md` 以 2014 年书面视角推演到 2026，与本篇恰好构成"预言/兑现"双联画；`../c++之旅3/11-历史兼容性与std模块附录.md` 则从 Bjarne 视角补了"标准怎么演化"的历史层。
