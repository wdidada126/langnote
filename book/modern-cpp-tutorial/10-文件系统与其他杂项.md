## 一、动机：把"操作系统边角"与"语言碎件"一次收编

第 8 章解决一个老牌痛点：跨平台文件操作长期没有标准答案（POSIX dirent vs Win32 FindNextFile），Boost.Filesystem v3 的广泛使用证明了需求，C++17 以 **v3 语义**收编进 `<filesystem>`（注意：不是 v2——SGI/POSIX 风格的路径分类学被保留）。第 9 章则是"够不上单独成章但必须记账"的散件：`long long` 终于转正、`noexcept` 从"可以不用"升为类型系统公民、字面量两则（原始串与自定义 UDL）、内存对齐三件套（`alignof/alignas/` 过对齐 new）、类型双关的合法通道（bit_cast）、以及 `<cmath>` 一次性补进 C 数学库欠了几十年的特殊函数。

## 二、机制

**§8.1 path**：路径是"字符串+通用路径文法"的对象，`/` 运算符拼接（`base / "sub"`），原生与通用两套表现形式（`native()` 反斜杠 vs `generic_string()` 正斜杠）分离是它最贴心的设计；`filename()/extension()/stem()/parent_path()` 做分解。**§8.2 状态查询**：`exists/is_regular_file/is_directory/file_size/last_write_time` 等以 `file_status` 或直接布尔/数值返回；错误处理双通道——返回 `bool`/抛异常、或 `error_code&` 版本（遍历不存在的目录时后者才可控）。**§8.3 遍历**：`directory_iterator`（单层）与 `recursive_directory_iterator`（深潜），后者可 `disable_recursion_pending()` 剪枝。**§8.4 建删**：`create_directories`（递归建）、`copy_file`（带 `copy_options`）、`rename`、`remove`/`remove_all`（整个目录树）。**§8.5** 给出综合小程序：建临时目录→写文件→查状态→遍历→复制改名→`remove_all` 收尾。

**§9.1** `long long int`：C++11 转正，至少 64 位；同章还点名 `_Align`/`thread_local` 等关键词扩编。**§9.2 noexcept**：既是声明修饰（`void f() noexcept`，违约即 `terminate`），也是**运算符**（`noexcept(f())` 编译期查询）；`throw()` 动态异常规范被它取代（C++17 起 `throw()` 等价 `noexcept` 并渐废）；函数指针的 noexcept **参与类型系统**（C++17）。**§9.3** 原始字面量 `R"( ... )"` 终结"字符串里写正则/HTML 的转义地狱"；自定义字面量 `operator"" _kmh` 让 `100.0_kmh` 进类型系统（书例：km/h 与 mph 换算），字面量运算符模板可收字符序列（二进制字面量 `0b1010'0001` 配 `operator"" _bin` 是经典玩法）。**§9.4 内存对齐**：`alignof(T)` 查、`alignas(N)` 提；过对齐类型（如 SIMD 的 64 字节对齐）在 C++17 前 `new` 不保证对齐——C++17 为此**重载了带对齐参数的 new/delete**，过对齐类型的动态分配才合法化。**§9.5 类型双关**：union 双关、`memcpy` 双关之外，C++20 的 `std::bit_cast<To>(from)` 给出编译期可用、语义最直的按位重解释（书例 float→uint32）。**§9.6** `<cmath>` 扩充：`riemann_zeta/assoc_laguerre/assoc_legendre/beta` 等特殊函数（C++17）。

### 🔧 实测：8.5 综合例 + 9.x 散件（g++ 15.2，`-std=c++20 -static`）

```cpp
const fs::path base = fs::temp_directory_path() / "modern-cpp-fs-demo";
fs::create_directories(base / "sub");
std::ofstream(base / "hello.txt") << "hello, filesystem";
p.filename() / fs::exists(p) / fs::file_size(p);          // 查询
for (const auto& e : fs::recursive_directory_iterator(base)) ...  // 遍历
fs::copy_file(p, base / "copy.txt"); fs::rename(...); fs::remove_all(base);
struct alignas(std::max_align_t) AlignasStorage { char a; int b; double c; long long d; };
std::bit_cast<std::uint32_t>(3.14f);   std::riemann_zeta(2.0);
```

已实测 g++ 15.2 输出（临时目录路径按本机展开）：

```text
filename: hello.txt | exists: 1 | size: 17
entry: C:\Users\wdidada\AppData\Local\Temp\modern-cpp-fs-demo\hello.txt
entry: C:\Users\wdidada\AppData\Local\Temp\modern-cpp-fs-demo\sub
after cleanup, exists: 0
alignof(Storage) = 8, alignof(AlignasStorage) = 16
noexcept(no_throw()) = 1
bit_cast: 1078523331
riemann_zeta(2) = 1.64493 (pi^2/6 = 1.64493)
```

`bit_cast: 1078523331` = 0x4048F5C3，正是 IEEE754 单精度 3.14 的位型——按位重解释实锤；`riemann_zeta(2)=π²/6` 到小数第五位吻合，特殊函数开箱可用。

**工具链勘误（实测发现）**：本机 MinGW（win32 线程模型）动态链接 `<filesystem>` 会在运行期崩 `0xC0000139 (STATUS_ENTRYPOINT_NOT_FOUND)`——即使最小到只调 `fs::temp_directory_path()` 也复现；加 `-static` 链接即恢复。属 MinGW 运行时与 libstdc++ 的符号错位，不是代码问题；CI 脚本里这是高频坑，值得记住。

## 三、权衡与陷阱

- `path` 拼接的 `/` 会重置绝对路径（`base / "C:/x"` 结果为后者），跨平台测试要同时断言 `generic_string()`。
- 状态查询在符号链接上有 follow/skip 两套（`symlink_status` vs `status`）；`file_size` 对目录是错误路径（error_code 版返回错，异常版抛出）。
- `noexcept` 的错误标注方向比漏标更危险：把会抛的函数标成 noexcept = 把异常变成 `terminate`；优先从 `noexcept(expr)` 运算符推导（`void f() noexcept(noexcept(g())))` 的模板味写法是书例原文）。
- UDL 用户后缀必须以下划线开头（标准保留无下划线命名空间；C++23 起 `_` 直接跟字母的裸后缀才被解禁，见 12 篇）。
- 自定义字面量三形态：普通函数（非模板、双参数）、字符串/字符版 `operator"" _x(const char*, size_t)`、模板版 `operator"" _x()`（编译期字面量解析）——书例只用了前两型。
- `bit_cast` 不是 `reinterpret_cast`：目标类型大小必须相等且都可平凡拷贝，否则编译失败——**这道编译期安检正是它的价值**。

## 四、与相邻概念对比

| 双关手段 | 类型安全 | constexpr 可用 | 档位 |
|---|---|---|---|
| `reinterpret_cast` 指针互转 | 否（严格别名 UB 雷区） | 部分 | C++98 |
| union 成员写入读出 | 实现定义/UB 边缘 | 否（C++20 起部分） | C |
| `memcpy` 到目标类型 | 合法但笨重 | 否（C++20 起是） | C++11 |
| `std::bit_cast` | 编译期校验大小/平凡性 | 是 | C++20 |

| 字符串字面量 | 转义处理 | 典型用途 |
|---|---|---|
| `"a\\nb"` | C++ 转义生效 | 常规 |
| `R"(a\nb)"` | 原样保留 | 正则/HTML/内嵌代码 |
| `100.0_kmh` | UDL 函数接管 | 单位/进制等领域类型 |

## 五、配套散件图谱：span、variant/any/optional 与 source_location（第三轮增补）

原书第 9 章只讲了"新类型/对齐/双关"，但与 C++17/20 同期到货的一批 `<xxx>` 小组件常被一起问到，本节补全图谱（提案号均经 `curl -sI wg21.link` 实测 302）：

- **`std::span<T>`（C++20，P0122R7，实测标题 "span: bounds-safe views for sequences of objects"）**：非拥有连续视图，`std::string_view`（随 P0220R1 进 C++17）的孪生。关键件：`size()/data()/subspan()/first<N>()`。它把 `(T*, size_t)` 参数对对象化，是 GSL 系"安全裸指针"的标准化——视图不拥有内存，存活期归调用方。
- **三兄弟定位**：`optional<T>`＝值或没有；`variant<Ts...>`＝类型安全联合（C++17，P0088R3，实测标题 "Variant: a type-safe union for C++17 (v8)"）；`any`＝可放任意可拷贝类型的运行时盒子。optional/any/string_view/byte 由 **P0220R1（实测标题 "C++17 Fundamentals"）**打包自 TS 收编进 C++17。对比表：

| 维度 | optional | variant | any |
|---|---|---|---|
| 类型集合 | 单一类型或无 | 编译期封闭集（N 选其一） | 运行时任意 |
| 取值方式 | value()/value_or() | get<I>/visit | any_cast<T>（错则抛） |
| 堆分配 | 无 | 无（内联缓冲） | 可能（SBO 实现定义） |
| 典型场景 | 可空查询/可选参数 | 代数数据类型、结果/错误 | 异构事件/UI 属性表 |

- **`std::source_location`（C++20，P1208R6，实测标题 "Adopt source_location for C++20"）**：默认参数魔法——`f(..., source_location loc = source_location::current())` 捕获**调用处**文件/行/函数名，替代 `__FILE__` 宏家族；13 篇 contracts 的违约报告正依赖它传递现场。
- **`std::assume_aligned`（C++20，P1007R3，实测 302）**：编译器对齐提示的标准化，与 §9.4 的 `alignas` 是因果近亲；`std::to_address`（C++20）给一切"类指针"统一取地址礼仪。

互链：06 篇（string_view/容器）、09 篇（并发设施）；跨书见 `../c++之旅3/06-输入输出与文件系统.md`（filesystem 的 C++20 全貌重讲）与 `../现代C++语言核心特性解析/13-对齐属性与预处理器.md`（对齐细节）。

### 🔧 实测 c：filesystem 错误三态 + 三兄弟 + source_location（g++ 15.2，`-std=gnu++20 -static`）

```cpp
auto st1 = fs::status(ghost);              // 无 ec：不存在 -> not_found，不抛
auto st2 = fs::status(ghost, ec);          // 带 ec：错误码通道
for (fs::directory_iterator it(ghost);;) … // 抛异常版：filesystem_error
std::span<int> s{arr}; auto mid = s.subspan(1, 3);
std::variant<int, std::string> v{42};  std::optional<int> o{std::nullopt};  std::any a = 3.5;
void log_me(..., std::source_location loc = std::source_location::current());  // 记调用点
```

已实测 g++ 15.2 输出：

```text
status(no-ec).type() == not_found: true
with-ec: ec=true msg=No such file or directory
throwing: caught filesystem_error what() starts with path: true
span size=6 mid=[2 3 4]
variant index=0 -> int:42
optional value_or(-1) = -1
any has_value=true, type.name nonempty=true
loc: 57:11 in int main()
```

三态语义各归位：无 ec 的状态查询把"不存在"编进 `file_status`（`not_found`）而非报错；ec 版设 `ec=true`（"No such file or directory"）；遍历不存在目录的异常版在 `what()` 里带全路径。**编译档位对照**：同一文件 `-std=c++17` 编译失败于 `error: 'std::source_location' has not been declared` 与 `std::format` 缺失——`<span>/<source_location>/<format>` 是 C++20 门限的活教材。

## 核心概念速览（中英对照）

- **路径对象** — std::filesystem::path：带通用文法的跨平台路径值类型
- **目录迭代** — directory_iterator / recursive_directory_iterator：单层/递归枚举
- **错误码通道** — error_code 重载：不抛异常的状态查询双胞胎
- **noexcept 运算符** — noexcept(expr)：编译期查询"会不会抛"
- **原始字符串字面量** — raw string literal：`R"(...)"` 零转义
- **自定义字面量** — user-defined literal：`operator"" _suffix` 领域类型入口
- **对齐说明符** — alignof / alignas：布局查询与对齐提升
- **过对齐动态分配** — over-aligned new（C++17）：`operator new(size, align_val_t)`
- **类型双关** — type punning：同一块内存换类型读
- **位重解释** — std::bit_cast：受编译期安检的类型双关（C++20）
- **黎曼ζ函数** — riemann_zeta：C++17 `<cmath>` 特殊函数代表
- **非拥有连续视图** — std::span：(指针,长度) 对的对象化（C++20）
- **和类型** — std::variant：编译期封闭集的类型安全联合
- **类型擦除容器** — std::any：运行时任意类型的值盒子
- **调用点捕获** — std::source_location：`__FILE__/__LINE__` 的现代替身（C++20）

## 最新演进与工业实践

- **档位澄清**：`<filesystem>` 的 path/status/iter 全家桶是 **C++17**；`std::bit_cast` 是 **C++20**；过对齐 new 是 **C++17**——原书第 9 章把这些混排，读时对照附录 3 索引表才不迷路（勘误台账已记其 8.x 节名与 toc.md 旧版不一致一处）。
- **C++20/23 对位**：`std::to_address`（指针样对象取地址的统一礼仪）、`std::assume_aligned`（GCC `__builtin_assume_aligned` 的标准化近亲，C++26 `[[assume]]` 见 12 篇）、`std::byteswap`（C++23，类型双关换到字节序战场）。UDL 裸后缀（`100ms` 不写下划线）随 `<chrono>` 用户字面量在 C++20 进入工业日常。
- **工业现状**：`<filesystem>` 在多数低延迟评审里仍被要求"冷路径可用、热路径进 error_code+缓存"；absl::FilePath、LLVM `sys::path` 等替代品证明 path 的跨平台边界用例（UNC、设备命名空间）标准库仍未穷尽。`std::format`（C++20）抢走了 UDL 之外的一部分"数字字面量格式化"需求。
- **社区重估**：第 9 章的"杂项"定位恰是本书诚实之处——这些是**标准委员会的收纳盒**而非特性主线；学习优先级显著低于 2–7 章，但 `bit_cast`/过对齐 new 两项在 SIMD/序列化岗位是刚需，面试权重被低估。
- **filesystem 的"售后"状态**：C++20/23/26 三轮给 `<filesystem>` 的增量近乎为零（委员会火力转向 contracts/execution），工业口径已经沉淀——path 规范化、UNC、设备命名空间仍是实现定义行为高发区；安全敏感场景应在 `canonical()` 之后再做白名单比对，absl::FilePath 等替代品正是为此存在。
- **P0220R1 与"TS 收编流程"**：optional/any/string_view/byte 全部来自 "Technical Specification for C++17 Extensions"（实测标题 "C++17 Fundamentals"）——先在 TS 里实地验证、再打包进 C++17。这条"TS→标准"流水线在 ranges（range-v3）、execution（stdexec，13 篇）上被反复复用，读第 9 章杂项可当标准化流程的显微镜标本。
- **对照阅读**：`../在拥挤和变化的世界中茁壮成长C++2006–2020/05-错误处理与C++17：大海迷航.md`（filesystem 收编年代的一手记录）与 `../C++语言的设计与演化/05-存储布局与访问：编译模型.md`（对齐与对象模型的历史纵深）可分别补上"库过程"与"内存布局"两个视角。
