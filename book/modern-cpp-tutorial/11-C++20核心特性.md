## 一、动机：C++20 是"四大件"级别的版本

自 C++11 以来改动量最大的一次。四个新大件各自瞄准一个积累了二十年的债：**概念（concepts）**还模板以可读的错误信息（SFINAE 咒语退役）；**模块（modules）**终结"头文件=文本复制"的编译模型（宏污染、重复解析、ODR 迷雾一起清算）；**范围（ranges）**把 STL 算法从"迭代器对"升格为"容器进容器出"的管道代数；**协程（coroutines）**给异步/生成器/惰性求值一个语言级的挂起-恢复原语。原书第 10 章的写法是"每件给一个最小可用例+一页动机"，并罕见地**主动辟谣**：合约与事务内存不属于 C++20——这是对中文圈以讹传讹的"20 大特性"清单（含 Contracts/TM）的定向纠偏（该澄清框是 2026 修订新增，见勘误台账"教材自我修正"条目）。

## 二、机制

**概念与约束（P0898R3 + P1102R2 语法收敛）**：模板错误的根源是"参数无约束，错了也要实例化到底"。原书的开场例是 `std::sort(l.begin(), l.end())` 对 `std::list`——不满足随机迭代器要求，旧世界吐几百行模板栈，概念世界一句约束不满足。三层写法渐进：`template <typename T> requires Sortable<T> void sort(T& c);` → 缩写 `template <Sortable T>` → 作为占位类型直接 `void sort(Sortable& c);`（概念即类型约束的"constrained auto"）。`requires` 表达式四层级（简单/类型/复合/全称）能表达"支持 `a+b` 且结果可转回 T"这类结构化约束；`std::convertible_to` 等标准概念库在 `<concepts>`。

**模块（P1135R6 家族的语言件）**：`export module foo;` / `export import` / `import foo;` 替换"`#include` 全家桶"。模块接口单元编译产物是"已解析的 AST 快照"，语义：一个声明只被编译一次、宏不再顺带传染、私有细节真的不可见。原书按"分区单元/接口/实现"的官方分类给了最小示例，同时明确警告：**工具链支持进度是全特性里最慢的**（这警告至今有效）。

**范围（P0896R4，吸收 Eric Niebler range-v3 设计）**：`range = 有 begin/end 的东西`；`view = 惰性、可组合、O(1) 拷贝的范围变换`。管道重载 `|` 让 filter/transform/drop/take 自由串联：`v | views::filter(偶数) | views::transform(平方)` 读起来就是需求文档。要点：view 不拥有元素、不保证缓存（重复迭代可能重复计算）——要固化就 `ranges::to<std::vector>()`（C++23，见 12 篇）。

**协程（P0912R5）**：函数体含 `co_await`/`co_yield`/`co_return` 即为协程，编译器把它改写成状态机+挂起点。C++20 **只给机制不给现成类型**：`promise_type`、`coroutine_handle`、`suspend_always/never` 是"用户态胶水三件套"。原书的最小惰性生成器（`Generator<T>` + `co_yield` 逐个产出 `range(1,5)` 输出 `1 2 3 4`）是全中文教材里少见的手写完整 promise_type 教学例——理解成本仍在，但例子把五钩子（get_return_object/initial_suspend/final_suspend/yield_value/return_void+unhandled_exception）全部过了一遍。

**关于合约与事务内存**：Contracts 曾进 C++20 工作草案、临发货被摘牌转攻 C++26（13 篇）；TM 从未成为标准，只有一份搁置的 TS。原书此框的存在感 > 其篇幅——它定义了本章的诚实边界。

### 🔧 实测：concepts + ranges 管道的 C++17→C++20 档位（g++ 15.2）

```cpp
template <typename T>
concept Addable = requires(T a, T b) { { a + b } -> std::convertible_to<T>; };
template <Addable T> T sum(T a, T b) { return a + b; }
auto result = v | std::views::filter([](int x) { return x % 2 == 0; })
                | std::views::transform([](int x) { return x * x; });
```

已实测 g++ 15.2：`-std=c++17` 编译失败——`error: 'concept' does not name a type; did you mean 'const'?`（第二行连带 `'Addable' has not been declared`）；`-std=c++20` 通过，输出：

```text
3
4
4 16 36 
```

`sum(1,2)/sum(1.5,2.5)` 证明概念约束不影响正确实例化；`4 16 36` 是偶数过滤+平方变换在 `{1..6}` 上的惰性结果。协程侧附带实测：原书 Generator 例在 `-std=c++20` 输出 `1 2 3 4`（惰性产出、析构自毁句柄）。

## 三、权衡与陷阱

- 概念的"收缩"语法 `Sortable auto` / 占位参数写法方便但会隐藏约束表达式，复杂约束仍建议 `requires` 子句后置——错误信息可读性来自约束**命名**，不是来自关键字数量。
- `<ranges>` 首迭代成本可能非 O(1)（filter 要找到第一个满足项），要求 `input_or_output_iterator` 的算法对单次前进假设成立——给 view 套"需要多遍稳定缓存"的算法前先想清楚（`ranges::ref_view`/`owning_view` 的边界）。
- 模块的现实部署成本：CMake/构建系统、头文件迁移的宏依赖清理、同名模块冲突——教程给了语法没给迁移策略，工程上普遍采用"新代码用模块、旧接口留 shim"长尾路线。
- 协程手写 promise_type 是"每三百行一个 UB"的高危作业：帧分配失败路径、resume-after-destroy、异常传播三处最容易翻车；生产代码请直接用库（见演进节）。
- 章节结构提醒：第 10 章小节**没有** 10.1–10.5 编号（toc.md 亦如此），本系列文件名里的"11-"只是笔记序号，与书内编号脱钩，读 00 篇映射表对齐。

## 四、与相邻概念对比

| C++20 大件 | 替代/前浪 | 胜负手 |
|---|---|---|
| concepts | SFINAE/`enable_if`（03 篇） | 错误信息 + 可读约束 |

## 核心概念速览（中英对照）

- **概念** — concept：对模板参数的编译期命名约束（requires 表达式）
- **约束** — constraint：概念作用于参数的布尔式子句
- **缩写语法** — abbreviated function template：`Sortable auto` 式占位参数
- **模块** — module：以已编译接口为单位的编译模型（export/import）
- **翻译单元** — translation unit：模块欲解决的"文本包含"基本单位
- **范围** — range：有 begin/end 的抽象；算法的容器级入口
- **视图** — view：惰性、可组合、O(1) 拷贝的范围变换
- **管道操作符** — range adaptor pipelines：`|` 串联视图
- **协程** — coroutine：可挂起/恢复的函数（co_await/yield/return）
- **promise_type** — 协程与外界约定的胶水协议（C++20 需手写）
- **协程句柄** — std::coroutine_handle：帧的遥控器（resume/destroy/done）

## 最新演进与工业实践

- **C++23 到货清单（12 篇展开）**：`std::generator`（P2502R2，协程终于开箱即用）、`ranges::to`（P0896R4 的收尾件）、zip/enumerate/chunk/slide（P2609R3 等）、`if consteval`。原书第 11 章与本章的衔接点几乎全在这里。
- **Modules 工业现状（⚠️ 无官方编译器支持时间表可引，此处只给可核实事实）**：GCC 14 起支持模块（源码级 import，不兼容 `#include` 混用）；MSVC 17.x 持续迭代但头文件标准化覆盖率仍不完整；Bazel/CMake 的模块依赖建模仍是最活跃的论文题目。教程"支持进度最慢"的警告在 2026 依然成立。
- **Ranges 的社区正名**：range-v3（Eric Niebler）→ C++20 标准采纳的路线被原书附录 3 标注；中文圈当年"ranges 是玩具"的论调随 `views::split/join_with` 在解析代码的普及已反转；Clang-tidy 出现 `modernize-*ranges` 检查族，等价于官方"请迁移"信号。
- **概念库的现实红利**：标准库算法签名的"概念化"（`std::sortable`、`std::invocable`、`std::predicate`）让 03 篇的 SFINAE 惯用法在 2026 新代码里基本绝迹——本笔记体系内 `../c++之旅3/04-模板与概念和泛型编程.md` 用概念重讲了整章模板，可与本篇互参。
- **Contracts 前瞻**：本章辟谣框指向的 P2900R14 已在 C++26 落地（13 篇实测 g++15 `-std=c++26` 的 contract 支持面），教程与标准的这场"时间差追逐战"本身就是活教材。
