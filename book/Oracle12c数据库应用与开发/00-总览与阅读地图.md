# 《Oracle 12c 数据库应用与开发》等 9 本 Oracle 主题书 · 总览与阅读地图

> **这里是什么**：不是一个作者的一本书，而是 `book/Oracle12c数据库应用与开发/` 目录下 **9 本 Oracle 中文技术书** 的**主题式重排笔记**。原目录里的 `.md`（9 个）与 `.zip`（2 个）只当作**原始素材**，一个字都不改；本目录下的 `NN-*.md` 是重排后的产出。
>
> **为什么重排**：这 9 本书的章节划分互相打架——《Oracle12c数据库应用与开发》按"教学章节"，《DBA攻坚指南》按"运维流程"，《SQL优化最佳实践》按"优化器原理"，《高并发Oracle数据库系统的架构与设计》按"扩展维度"。按书读会重复三遍、漏掉三处。所以这里按 **Oracle 知识主线** 重切成 15 个文件，每本书的贡献标在章节后面的「书目」列里。

## 四、原笔记批注的解读：「重点看第 7 章」

原笔记对《Oracle12c数据库应用与开发》留下四条批注：

> **重点看第 7 章** / 容器数据库 / 可插拔数据库 / `C##` 开头 / 导入数据

核实后的含义是：这本书 **共 16 章**，第 7 章是 **「数据查询」**（第 8 章才是 DML）。而这条批注被写在"容器数据库 / 可插拔数据库 / `C##` 开头 / 导入数据"这组关键词**之前**，说明原笔记作者的意思是：

1. 装好 12c 后，因为默认建的是 **CDB**，样例用户是 `C##` 前缀的**公共用户**，模板数据是**导入**进去的（笔记里留了 4 条 `sqlldr MYSHOP/...@host:1521/TEST control=...log=...bad=...` 命令行，对应 input_login / input_course / input_student / input_sc 四张表）；
2. 数据导入之后，**真正值得看的就是第 7 章「数据查询」**——也就是基于这套 `C##` 样例模式把 SELECT 的各种写法跑一遍；
3. 所以「重点看第 7 章」不是"跳过前面"，而是"**前面（CDB/PDB、`C##`、sqlldr 导入）只要知道怎么把环境跑起来，重点放在第 7 章的查询**"。
4. 笔记里还有一条。「是 user，同一个数据库，不同的 IT 项目访问，一个项目对应一个用户」「表在 scheme 下面」「user 和 scheme 同名」——这是把"一个项目 = 一个用户 = 一个 schema"的组织方式记下来了，第 7 章的查询就是在这个约定下写的。

这条指示已在 `01-Oracle12c体系结构与CDB-PDB.md` 和 `08-常见SQL误区与最佳实践.md` 两处落实，原文表述「重点看第 7 章」原样保留。

另外，第 1 章批注里出现了 `SELECT con_id, dbid, name, open_mode FROM v$pdbs;`，第 2 章标题是「CDB和PDB操作」，可确认原笔记重点抓的是 **CDB/PDB**。第 1 章还留了缩写表：ORAC（Oracle Real Application Cluster）、OASM（Oracle Automatic Storage Management，注：现写作 **Oracle Automatic Storage Management** 的官方缩写仍为 **ASM**，原笔记的 OASM 是笔记作者的记法）、ODI（Oracle 数据集成器）、OBDC（Oracle Big Data Connectors）。

## 七、同一概念在 9 本书里的不同说法

读这一套最容易困惑的不是"不懂"，而是"三本书三种说法"。下面这张表把高频冲突概念对齐，避免读者以为自己记错了：

| 概念 | 12c 教材的说法 | SQL 优化最佳实践的说法 | 性能优化方法论的说法 | RAC 书 / 其他书的说法 |
| --- | --- | --- | --- | --- |
| 优化器的"成本" | 笼统说"代价最小" | 明确拆成 CPU 成本 + I/O 成本，并说明 `optimizer_mode` 的影响 | 把"资源"单独抽出来（CPU/Memory/IO/Network/Lock/Buffer Lock/Latch/Mutex） | DBA 攻坚指南偏"实测各省" |
| 共享池内存被大量占用 | 笼统提醒"少用硬解析" | 用**游标与语句解析**一章打通：shared pool 命中率、`cursor_sharing`、绑定变量 | 归到 "Library Cache / Mutex" 资源体系 | —— |
| 等待事件 | 基本不提 | 只在案例里顺带提 | **全书核心**：按资源分类给出各自的衡量指标 | RAC 书讲 RAC 专属等待（GC buffer busy acquire 等） |

## 十、学习 Oracle 特有的"心智负担"（本套书默认你知道，但不写出来）

这 9 本书都是给"已经决定学 Oracle 的人"写的，不会解释为什么 Oracle 的学习曲线和 MySQL 不一样。补齐这段再读会顺很多：

| # | Oracle 特有 | 为什么别处少见 |
| --- | --- | --- |
| 1 | **一个"库"有两种含义**：CDB（容器库）里可以装多个 PDB（可插拔库）；而 MySQL 的"库"≈ Oracle 的"schema/用户"，PostgreSQL 的 `database` 也近似 schema 容器 | 藏得很深，只有 12c 教材第 2 章正面讲 |
| 2 | **schema ≈ user**：`user` 和 `schema` 同名，`GRANT` 的对象归到同名 schema 下；MySQL 里"库"和"用户"是两个正交概念 | 台湾/大陆教材都直接当常识用 |
| 3 | **默认不提交**：`SQL*Plus` 里 DML 后必须显式 `COMMIT`，退出时如果 `exit` 会隐式回滚（取决于设置） | MySQL 客户端默认 autocommit，差异第一天就踩 |
| 4 | **NULL 与空串等价**：Oracle 里 `'' IS NULL` 为真，`NULL = NULL` 未知；MySQL 里 `''` 和 `NULL` 不同 | SQL 应用及误区分析第 3–6 章有专门反例 |
| 5 | **排序时 NULL 最大**：`ORDER BY` 默认 NULLS LAST | 同上，第 14 章还专门对比了 SQL Server 的差异 |
| 6 | **隐式类型转换是安全陷阱**：`WHERE varchar_col = 123` 会让谓词变成 `TO_CHAR(varchar_col) = 123`，索引直接失效 | 本目录 `08` 章集中处理 |
| 7 | **字符串字面量用单引号，标识符默认大写**：不写引号的标识符会被折叠成大写，与 MySQL 的保留大小写行为不同 | 开发第一天就会遇到 |
| 8 | **同一句 SQL 两次执行可能计划不同**：绑定变量窥探、自适应游标共享（ACS）、统计信息变化都会影响 | SQL 优化最佳实践"游标"章专门讲 |
| 9 | **事务与会话强绑定**：`COMMIT/ROLLBACK` 是会话级，`DDL` 会隐式提交——这条连不少老 DBA 都会记错 | DBA 攻坚指南在故障处理里有实操提醒 |

> 这九条里，#1 对应 `01`，#4/#5 对应 `08`，#8 对应 `06`，#9 对应 `04`。
