## 核心精讲

> 教学示意，**不参与构建、不编译**。

### 通用算术与 `apply-generic`

```scheme
; 复用的分派骨架（2.4.3 的通用版）
(define (apply-generic op args)
  (let ((type-tags (map type-tag args)))
    (let ((proc (get op type-tags)))
      (if proc
          (apply proc args)
          (if (or (null? args) (null? (cdr args)))
              (error "No method for these types" op type-tags)
              (apply-generic op (list (coerce args type-tags)
                                      (car (cdr args)))))))))

; 注册两种复数的实现
(define (install-polar-package)
  (define (magnitude z) (car z))
  (define (angle z) (cdr z))
  (define (make-from-mag-ang r a) (cons r a))
  (put 'magnitude '(polar) magnitude)
  (put 'angle '(polar) angle)
  (put 'make-from-mag-ang 'polar make-from-mag-ang)
  'done)

(define (install-rectangular-package)
  (define (real-part z) (car z))
  (define (imag-part z) (cdr z))
  (define (make-from-real-imag x y) (cons x y))
  (put 'real-part '(rectangular) real-part)
  (put 'imag-part '(rectangular) imag-part)
  (put 'make-from-real-imag 'rectangular make-from-real-imag)
  'done)

; 用户视角：完全不知道实现
(define z (make-from-mag-ang 1.414 0.785))
(magnitude z)     ; ==> 1.4142135...
```

### 组合类型：标签的递归构造

```scheme
; 复合数据的标签由所有子数据的标签一起决定
(define (make-complex-from-real-imag x y)
  (tag (cons 'complex (cons 'rectangular (cons x y)))))

(define (make-complex-from-mag-ang r a)
  (tag (cons 'complex (cons 'polar (cons r a)))))

; 于是 type-tag 可以逐层拆开
(define (type-tag datum)
  (cond ((pair? datum) (caar datum))     ; 取 innermost 的 tag
        ((number? datum) 'scheme-number)
        (else 'primitive)))

(define (contents datum)
  (cond ((number? datum) datum)
        (else (cdar datum))))            ; 同上，逐层下剥
```

> 于是 `(add (make-scheme-number 1) x)` 可以 because 两个参数的标签都是 `scheme-number` / `complex`，查表命中。**这就是「类型 = 标签的复合」**，也是 2026 年泛型里「trait 由参数类型自动推导」的动态原型。

### 类型塔：把类型组织成层次

```scheme
; 方案 A：集合表示（SICP 的选择）
; types = (scheme-number complex)，复杂类型 = 子类型的集合
(define (equ? x y) (apply-generic 'equ? (list x y)))
(define (=? x y)   (apply-generic '= (list x y)))
(define (<? x y)   (apply-generic '< (list x y)))

; 方案 B：塔式分层（Scheme number 是 integer ⊂ rational ⊂ real ⊂ complex）
; 上升（raise）到更高层后统一处理
(define (raise x) (apply-generic 'raise (list x)))
```

> 2.5.4 的取舍是本章的核心，也是软件工程里最经典的争论：
> - **集合表示类型**（2.5.1 实际采用的方案）：灵活，但「查找表爆炸」——n 种类型两两组合就要 n² 个条目；
> - **塔式类型**：条目少，但要求所有类型都能排成一条链，遇到「矩形坐标的复数」这种无法归约的情况就崩。
> 现代语言的选择是第三条路：**类型类（type class）与约束求解**——既不必归约，也不需要 n² 条目。

### 一个泛型包的骨架

```scheme
; 用户只要安装一次，之后所有操作都可加
(define (install-scheme-number-package)
  (define (tag x) (attach-tag 'scheme-number x))
  (put 'add '(scheme-number scheme-number) (lambda (x y) (tag (+ x y))))
  (put 'sub '(scheme-number scheme-number) (lambda (x y) (tag (- x y))))
  (put 'mul '(scheme-number scheme-number) (lambda (x y) (tag (* x y))))
  (put 'div '(scheme-number scheme-number) (lambda (x y) (tag (/ x y))))
  (put 'equ? '(scheme-number scheme-number) =)
  (put '= '(scheme-number scheme-number) =)
  (put '< '(scheme-number scheme-number) <)
  (put 'make-scheme-number 'scheme-number (lambda (x) (tag x)))
  'done)
```

> 注意这一段代码的**自我相似性**：每个包都长得一模一样（tag + `put` + 返回 `'done`）。这种「都会绘制的形状」本身就是抽象——**下一步就是宏**。

## 版本演进

| 阶段 | 演进要点 |
| --- | --- |
| **1975–1978 Scheme 早期** | 只有手工 `cond` 分派（2.4.1 那种），泛型是靠 if-else 硬写 |
| **1980s CLOS** | 通用函数 + 类 + 多重分派；`defmethod` 在参数列表上匹配，等价于 `put` 的自动化版本 |
| **1998 R5RS** | `put`/`get` 未进入标准（各实现自己造）；这是 SICP 代码在 R5RS 下**不可移植的根因** |
| **1998 Haskell 类型类** | 用**编译期约束**替代运行期查表：`class Eq a where (==) :: a -> a -> Bool` |
| **2020 Rust trait** | trait + 关联类型 + 泛型约束，是「可加性」在静态语言里的完整答案 |
| **2022 C++20 Concept** | 编译期约束的约束，等价于类型塔的静态版 |
| **2022 Go 泛型（1.18）** | 补上了最后一环：接口 + 类型参数 |
| **2026 的趋势** | 「编译期可加性」几乎完胜：Rust 单态化后泛型代码与手写专用代码同速；运行期分派仅在跨 crate 的动态场景（如插件、脚本引擎、数据库驱动）保留 |

> **1996 → 2026 的一句话总结**：SICP 2.5 的 `put/get` 是**运行期可加性**的巅峰技术；今天主流工业语言提供的是**编译期可加性**。两者能力相当，**代价一个在运行期、一个在编译期**。

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **`put`/`get` 不是标准** | 本章的代码在 R5RS 下**无法运行**（`put`/`get` 不在标准里）。迁移到 Racket 必须自己实现或用 `make-hash` 的等价物——这是全书最实际的迁移障碍 |
| 🔧 **类型塔的过时之处** | 2.5.5 的「实/复塔式分层」要求类型可排序；2026 年 Rust/Haskell 的类型类允许**任意类型实现任意 trait**，不需要排序 |
| **把「可加性」当成免费的** | 每加一种类型就要往表里注册一遍，注册本身是新的 boilerplate；Rust 的 `impl` 简洁得多 |
| 🔧 **`apply-generic` 的错误处理偏弱** | 1996 年的写法遇到未定义操作只 `error`；现代写法应区分「未找到方法」与「类型不合法」，否则调试成本极高 |
| **章节顺序导致的误解** | 2.5 在 2.4 之后，但 2.4.3 的数据导向与 2.4.4 的消息传递是**并列方案**，很多读者误以为 2.5 是对它们的改进，其实 2.5 只是把 2.4.3 扩得更完整 |
| 🔧 **未提供宏方案** | 2.5 每个包都要重复 tag + `put`；今天的答案很明确：**用宏（Scheme/CL）或类型类（Haskell/Rust）消除 boilerplate**。本书生于宏还不成熟的时代 |
| **练习无官方答案** | 2.5 的练习 2.61–2.65（符号代数、级数）在中文版无答案，建议对照社区题解 |
