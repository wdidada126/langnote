# 第 2 章 构造数据抽象（2.1 数据抽象与区间算术）

> **一句话**：数据抽象的全部秘密只有一句——**让使用方只通过一组操作接口访问数据，构造方可以随便换实现**；这条线叫抽象屏障。

---

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 2.1.1 | 实例：有理数的算术运算 | 把「加减乘除」定义成一组操作，`add-rat/sub-rat` 只依赖构造器与选择器 |

## 核心精讲

> 教学示意，**不参与构建、不编译**。

### 有理数：抽象屏障的第一个例子

```scheme
; ---- 构造与选择（屏障之下）----
(define (make-rat n d)
  (let ((g (gcd n d)))
    (cons (/ n g) (/ d g))))   ; 内部用 cons 实现，外部不可见

(define (numer x) (car x))
(define (denom x) (cdr x))

; ---- 操作（屏障之上）----
(define (add-rat x y)
  (make-rat (+ (* (numer x) (denom y))
               (* (numer y) (denom x)))
            (* (denom x) (denom y))))

(define (mul-rat x y)
  (make-rat (* (numer x) (numer y))
            (* (denom x) (denom y))))

(define (print-rat x)
  (newline)
  (display (numer x))
  (display "/")
  (display (denom x)))

(define one-half (make-rat 1 2))
(define one-third (make-rat 1 3))
(print-rat (add-rat one-half one-third))   ; ==> 5/6
```

> 关键在 2.1.3 的宣言：**用户只需要知道 `make-rat/numer/denom` 三者约定一致，不需要知道内部用 `cons` 存**。这意味着「把有理数改成裸分数对 / 结构体 / 两个全局变量」都不影响上层——**抽象屏障就是这么生效的**。

### 泛化：把复合数据做成通用容器

```scheme
; 通用 pair：本书第 2 章给出，作为所有层次数据的底座
(define (cons x y)
  (lambda (m) (m x y)))

(define (car z) (z (lambda (p q) p)))
(define (cdr z) (z (lambda (p q) q)))

(car (cons 3 4))    ; ==> 3
(cdr (cons 3 4))    ; ==> 4
```

> 这一小段 code 正是 **Church encoding** 的 `true/false` 版本，也是 2.4.2「带标志数据」的先声。它证明了一件事：**数据就是行为，不是表示**。

### 区间算术：本书最著名的扩展练习

```scheme
; 区间 = 下界 + 上界
(define (make-interval a b) (cons a b))
(define (lower-bound i) (car i))
(define (upper-bound i) (cdr i))

; 加法：区间可以精确相加
(define (add-interval x y)
  (make-interval (+ (lower-bound x) (lower-bound y))
                 (+ (upper-bound x) (upper-bound y))))

; 乘法：四个乘积取极值
(define (mul-interval x y)
  (let ((p1 (* (lower-bound x) (lower-bound y)))
        (p2 (* (lower-bound x) (upper-bound y)))
        (p3 (* (upper-bound x) (lower-bound y)))
        (p4 (* (upper-bound x) (upper-bound y))))
    (make-interval (min p1 p2 p3 p4)
                   (max p1 p2 p3 p4))))

; 除法：乘上倒数区间（若区间跨 0 则无定义）
(define (div-interval x y)
  (mul-interval x
                (make-interval (/ 1.0 (upper-bound y))
                               (/ 1.0 (lower-bound y)))))

; 中心值与宽度：刻画误差传播
(define (center i) (/ (+ (lower-bound i) (upper-bound i)) 2))
(define (width i) (/ (- (upper-bound i) (lower-bound i)) 2))

; 区间乘加：带符号宽度
(define (make-center-width c w)
  (make-interval (- c w) (+ c w)))
(define (percent n) (/ (* n 0.01) 2))   ; 百分比 → 半宽
```

> 两个陷阱（练习 2.7/2.8/2.9/2.12 的精髓）：
> 1. **除法必须检查分母跨 0**，否则「无穷」会静默污染结果；
> 2. **误差不守恒**：区间乘法/pow 会让宽度按次数放大，所以并行电阻那道题（`par 1 2` 之类）会得到比直觉更宽的区间——这正是工程上「误差传播」的原型。

### 列表与闭包性质

```scheme
; 列表的构造器与选择器
(define (list x y z) (cons x (cons y (cons z '()))))
(define (null? x) (eq? x '()))
(define (list-ref lst n)
  (if (= n 0)
      (car lst)
      (list-ref (cdr lst) (- n 1))))
(define (length lst)
  (if (null? lst) 0 (+ 1 (length (cdr lst)))))

; 闭包性质：复合数据的任意部分仍可用已有选择器取回
(car (car (list 1 2 3)))       ; ==> 1：car 对任何 cons 都可用
```

> **闭包性质**（closure property）是 2.2 的核心命题：正因为 `car`/`cdr` 对任何由 `cons` 造出的东西都有效，我们才能用 `cons` 造树、造表、造任意层次结构而不需要新的语法。

### 用抽象层次重写列表操作

```scheme
; 只依赖 car/cdr 的通用操作（屏障之上）
(define (map proc lst)
  (if (null? lst)
      '()
      (cons (proc (car lst))
            (map proc (cdr lst)))))

(define (append l1 l2)
  (if (null? l1)
      l2
      (cons (car l1) (append (cdr l1) l2))))
```

## 版本演进

| 阶段 | 演进要点 |
| --- | --- |
| **LISP 1.5** | 只有 `cons/car/cdr` 与 S 表达式；数据抽象靠**约定**，没有语言层面的保护 |
| **ALGOL 60 / Pascal** | 引入 **record** 与显式作用域，抽象屏障第一次有语法（`program = 声明 + 语句` 的分块） |
| **Scheme 1975** | `cons` 成为唯一的复合数据构造器（closure property），2.2 的一切由此展开 |
| **R5RS (1998)** | 增加 `pair?`、`list` 字面量 `(list ...)`，但**没有记录类型** —— 数据抽象仍靠约定 |
| **R6RS / Racket（2007/2013）** | `define-struct`/`define-record-type` 提供**命名结构 + 自动选择器**；`match` 提供模式匹配；抽象屏障从约定升级为编译器检查 |
| **2026 生态** | Rust 的 struct + trait、Go 的 struct、Java 的 record 都在做同一件事；**主流语言已经把「复合数据」做成类型，把「层次结构」交给标准库** |
| **2026 的趋势** | 类型驱动设计（Type-Driven Development）与「不可变数据 + 穷尽性检查」（match exhaustiveness）取代了 SICP 的纯约定式抽象 |

> **1996 → 2026**：SICP 2.1 的 `make-rat` 今天在 Rust 里是 `struct Rational { n: i64, d: i64 }` 加 `impl`；思想没变，**代价从人的纪律变成了编译器的类型检查**。

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **方言与结构定义** | 2.1 用手写 `cons/car/cdr` 造有理数；现代 Racket/OCaml/Rust 有 `define-struct`/record，照抄本书代码在 Racket 里也能跑但**与教学意图相悖**（本书想让你体验「裸抽象」） |
| 🔧 **1996 年数值前提** | 2.1.4 的区间算术基于 IEEE 754 双精度；2026 年的 `+∞`/`NaN` 语义与除法陷阱比书中更复杂，区间跨 0 必须显式报错 |
| **把 `cons` 当成「分配内存」** | 2.1 的 `cons` 是纯粹的**闭包构造**，不分配堆对象；误解这一点会导致对 5.3 存储分配彻底看不懂 |
| 🔧 **抽象屏障被读者忽略** | 很多读者跳到 2.2 之后，忘了 2.1 反复强调「谁可以看见 `car`」；2.4.2 的带标志数据正是靠「屏障被故意打破」才成立 |
| **gcd 的负号问题** | `(make-rat -4 6)` 在本书的 `gcd` 实现下会得到 `-2/3` 之外的符号错误；R5RS 的 `gcd` 对负数行为不统一，需自行取绝对值 |
| 🔧 **误差传播结论过时** | 2.1.4 练习 2.9 的「宽度可加」结论只在加法成立；乘除法与百分比那几题的**数值稳定性**在 2026 年由区间算法库（如 Directed Roundings 标准）重新规范 |
| **练习缺口** | 2.1.4 的电阻并联、区间平方等练习在中文版没有提示；区间除法未定义的情况书里只在练习 2.7 出现，容易被跳过 |
