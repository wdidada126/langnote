# 专篇：惰性求值（从 SICP 3.5 到 2026 年的迭代器）

> **一句话**：惰性求值把「求值时机」变成了一个可选择的策略——**一旦承认时机可以推迟，「无穷」就成为一个可以写下来的值**。

---

## 1. 三种求值时机

| 策略 | 何时求值 | 典型语言 | 优点 | 代价 |
| --- | --- | --- | --- | --- |
| **及早求值**（eager / strict） | 绑定时立即算 | C/Java/Go/Python（默认） | 推理简单、无泄漏 | 写不出无穷序列；多余计算 |
| **惰性求值**（lazy / non-strict） | 第一次被强制时算 | Haskell（默认）、Racket 的 `delay` | 能表达「未定的无穷」 | 求值顺序不确定、空间泄漏 |
| **显式延迟**（explicit） | 程序员指定 | Rust `Iterator`、Python generator | 可控、可推理 | 需要写 `yield`/`collect` |

> SICP 3.5 讨论的是**第二种**；2026 年工业界绝大多数用的是**第三种**。这是本篇最重要的现实结论。

---

## 2. promise 的最小实现

```scheme
; delay 的本质：把「要做的事」和「当时的环境」打包
(define-syntax-rule (delay exp) (list 'promise '() exp))  ; 示意
(define (force-obj p)
  (cond ((eq? (car p) 'memoized) (cadr p))
        ((eq? (car p) 'promise)
         (set-car! p 'memoized)
         (set-car! (cdr p) (cadr p))
         (set-cdr! p ((cadr p)))  ; 示意，真实实现用 box
         (cadr p))
        (else (error "not a promise"))))
```

书里的教科书实现（SICP 3.5.2）用 `set-car!`/`set-cdr!` 改写 promise 为 `memoized` 态：

```scheme
(define (force promise)
  (cond ((eq? (car promise) 'function)   ; 未求值
         (let ((result ((cdr promise))))
           (set-car! promise 'memoized)
           (set-cdr! promise result)
           result))
        ((eq? (car promise) 'memoized)   ; 已求值
         (cdr promise))
        (else (error "not a promise"))))
```

> 🔧 迁移注意：`set-car!` 在 R6RS/Racket 里已弃用，改用 `box`/`unbox`，语义完全一致。

## 3. 惰性带来的模块化（SICP 的核心论点）

```scheme
; 自引用的惰性流：guesses 在定义自己时还没算出来
(define (sqrt-stream x)
  (define guesses
    (cons-stream 1.0
                 (stream-map (lambda (guess)
                               (average guess (/ x guess)))
                             guesses)))
  guesses)

(stream-ref (sqrt-stream 2) 5)   ; ==> 约 1.41421
```

> 在及早求值里，这段代码**无法书写**（无限递归）；在惰性求值里它是自然写法。
> 3.5 因此得出那个著名的结论：**求值时机是一种模块化手段**——因为「还没发生的步骤」也被允许出现在定义了。

## 4. 惰性最实用的价值：记忆化

```scheme
; delay 的记忆化版本：同一个 promise 只求值一次
(define (memo-delay exp)
  (let ((forced? #f) (value #f))
    (lambda ()
      (if (not forced?)
          (begin (set! value exp)   ; 示意：真实实现延迟到第一次调用
                 (set! forced? #t)
                 value)
          value))))

; 记忆化版斐波那契：子问题只算一次
(define (memo-fib n)
  (define (fib k)
    (cond ((< k 2) k)
          (else (+ (force (~ (fib (- k 1)))
                          (force (~ (fib (- k 2)))))))))
  ;; ~ 表示「记忆化的延迟」；核心差别：每个子问题只被求值一次
  (fib n))
```

> 教科书式的写法（SICP 3.5.4）是把 `delay` 换成 `memo-delay`，递归函数的代码一行都不用改，θ(φⁿ) 直接降到 θ(n)。**这是惰性求值最实用的价值：不用改算法结构就消掉重复子问题。**

> 这就是「**共享而非重复**」：惰性求值把「同一子问题算两次」这件事在语言层面消灭了，**不需要程序员手写 DP 状态数组**。

## 5. 惰性的代价（本书几乎没提）

| 代价 | 表现 | 2026 年的对策 |
| --- | --- | --- |
| **空间泄漏** | 未求值的 thunk 堆积（尤其出错时） | 强制策略、上限检查 |
| **求值顺序不确定** | 副作用顺序不再等于书写顺序 | 保留严格区域、monad 隔离 |
| **可推理性下降** | 调用栈不再是时间线 | 显式 `force`、不可变数据 |
| **缓存局部性差** | 惰性链表遍历 cache miss 更多 | 向量化、chunked 惰性 |
| **调试困难** | 栈里没有真实的调用链 | 强制求值、日志 |

## 6. 惰性在 2026 年的三个真实形态

```python
# 形态一：生成器（Python）
def primes():
    n = 2
    while True:
        if is_prime(n): yield n
        n += 1
```

```rust
// 形态二：Iterator（Rust）—— 零成本惰性
let v: Vec<i32> = (0..).filter(|x| x % 2 == 0).map(|x| x * x).take(5).collect();
```

```javascript
// 形态三：异步生成器 / 流
async function* fetchAll(urls) { for (const u of urls) yield await fetch(u); }
```

三者共同点：**惰性是可控的、显式的、拉式的**（pull-based），而不是 Haskell 那种全局隐式。这是工业界 20 年经验给出的答案。

## 7. 惰性 vs 约束传播：同一枚硬币

| 维度 | 惰性序列（3.5） | 约束传播（3.3） |
| --- | --- | --- |
| 描述方式 | 关系 + 拉式消费 | 关系 + 推式传播 |
| 顺序 | 由消费者决定 | 由传播网络决定 |
| 终止性 | 可能永远不终止（无限流） | 可能无限循环（约束环） |
| 时间因素 | 消除时间 | 也消除时间 |

> SICP 把这两章分开写，但它们是同一个想法：用「**关系**」替代「**步骤**」。差别只在谁去拉动计算。
