# 第 5 章 寄存器机器里的计算（5.1–5.5：从求值器到编译目标码）

## 核心精讲

> 教学示意，**不参与构建、不编译**。

### 寄存器机器：一台可编程的抽象机

```scheme
; 机器的指令以 Scheme 数据描述
(define ece-machine
  '(controller
    (assign val (op constant) (const 1))
    (assign continue (label after-square-root))
    (goto (label sqrt-loop))
    sqrt-loop
    ...
    after-square-root
    (perform (op print) (reg val))
    (goto (reg continue))))

; 用模拟器「运行」它：
(define machine (make-machine ece-machine))
(set-register! machine 'x 2)
(start machine)
```

> 一台寄存器机器由三样东西构成：**数据路径**（寄存器、数据操作、栈）与**控制器**（指令序列）。第 5 章的全部内容就是在两者之间反复搬砖。

### 求值器状态机：把递归拆成跳转

```scheme
; 4.1 的 eval 是递归的；5.4 把它拆成 6 个「入口」
; 每个入口处理一种表达式类型，并在需要时 (goto (label eval-dispatch))

(define (amachine)
  '(controller
    eval-dispatch
      (test (op self-evaluating?) (reg exp))
      (branch (label eval-self-evaluating))
      (test (op variable?) (reg exp))
      (branch (label eval-variable))
      (test (op quoted?) (reg exp))
      (branch (label eval-quoted))
      (test (op application?) (reg exp))
      (branch (label eval-application))
      ...
    eval-application
      (assign unev (op operands) (reg exp))
      (assign exp (op operator) (reg exp))
      (assign continue (label after-operator-evaluation))
      (goto (label eval-dispatch))
    after-operator-evaluation
      (assign unev (op operand-arguments) (reg exp))
      (test (op no-operands?) (reg unev))
      (branch (label apply-primitive-procedure))
      (assign argl (op empty-arglist))
      (goto (label collect-args))
      ...
    apply-primitive-procedure
      (assign val (op primitive-apply) (reg primitive) (reg argl))
      (goto (reg continue))
    ...))
```

> 关键观察：**`(goto (reg continue))` 取代了函数调用**；`continue`、`env`、`exp`、`argl`、`unev` 这些「隐含参数」变成了显式寄存器。
> 这正是 2020 年 CPU 与 JS 引擎里发生的事——**栈帧被寄存器变量替代，调用被跳转替代**。

### 编译规则：从表达式到指令序列

```scheme
; 编译一个表达式 = 生成「把值放进 val」的指令序列
(define (compile exp target linking)
  (cond ((self-evaluating? exp)
         (compile-self-evaluating exp target linking))
        ((variable? exp)
         (compile-variable exp target linking))
        ((quoted? exp)
         (compile-quoted exp target linking))
        ((if? exp)
         (compile-if exp target linking))
        ((lambda? exp)
         (compile-lambda exp target linking))
        ((application? exp)
         (compile-application exp target linking))
        (else (error "Unknown expression type -- COMPILE" exp))))

; 变量：把它从环境里装进目标寄存器
(define (compile-variable exp target linking)
  (let ((var-exp
         `(assign ,target (op lookup-variable-value) (const ,exp) (reg env))))
    (preserving linking (list 'env) var-exp)))

; 顺序与分支的组合子
(define (compile-sequence seq target linking)
  (define (compile-body body target linking)
    (cond ((last-expression? body)
           (compile (car body) target linking))
          (else
           (let ((first (compile (car body) target 'seq)))
             (preserving linking (list 'val)
               `(seq ,first (goto (label ,(compile-sequence (cdr body) target linking)))))))))
  (compile-body seq target linking))
```

> 编译器的核心抽象是三个组合子：`preserving`（保护寄存器）、`seq`（顺序）、`branch`（分支）。**有了它们，编译就只是「把每个语法规则翻译成指令树」**。

### 运行时系统：闭包与环境

```scheme
; 编译后的过程：一个 (code, env) 对
(define (make-compiled-procedure entry env) (list entry env))

; 进入编译时过程
(entry-point (make-compiled-procedure label env))
```

> 运行时系统的职责：**延续（continuation）、闭包对象、栈分配、垃圾回收**。5.3 的废料收集与 5.2 的栈管理，就是这一层的全部内容。

### 存储分配与废料收集

```scheme
; 三色标记清扫（示意）
(define (gc-root-set) '(stack-registered-obj))
(define (mark obj) ...)

```

> 5.3 讲了停止拷贝、标记清扫、引用计数三种策略。2026 年主流实现（V8、HotSpot、Go、JVM）都是**分代 + 增量 + 写屏障**的组合——思想还是那三种，工程复杂度高了两个数量级。

## 版本演进

| 阶段 | 要点 |
| --- | --- |
| **1960** | McCarthy 的 LISP 首次需要 GC（cons 无限分配） |
| **1963 Lisp 1.5 的 GC** | 停止拷贝（stop-and-copy）首次实现 |
| **1967 Deutsch & LISP 机器** | 寄存器机的早期形态；硬件化的 Lisp 机器（1980s） |
| **1980s** | 引用计数与标记清扫成为标配；TC（尾部调用）在寄存器机上自然成立 |
| **1983 Kildall / SRA 方法** | 数据流分析用于寄存器分配；「寄存器机」这一抽象终于有了系统理论 |
| **1996 SICP 第 2 章/第 5 章** | 用 Scheme 描述寄存器机，成为编译器教学的标准范式 |
| **2000s** | JIT 成熟；「树提升解释器 → JIT 编译」成为 JVM/V8 的标准两阶段 |
| **2010s LLVM** | IR 抽象让「机器描述」与「代码生成」解耦；SICP 5 章的指令序列成为教科书 |
| **2020s WASM / Cranelift** | 寄存器机思想在 WASM 与即时编译器里复活；Rust 生态大量用它做 JIT |
| **2026 趋势** | 编译器的产出目标从物理硬件转向**WASM 与 GPU**；同时「编译到 Python/R」这类多目标后端（Racket 的做法）说明指令序列是极好的中间表示 |

> **1996 → 2026**：第 5 章的机器在今天对应 **WASM 的指令集、LLVM 的 IR、Rust 的 Cranelift**。你不太可能再手写一个「Scheme 寄存器机模拟器」，但**读懂 5.1–5.5 依然是理解任何现代引擎的最短路径**。

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **5.x 在中文版的位置** | 中译本把第 5 章作为第 5 章，但**第 5 章与第 4 章内容联系紧密（4.1 的显式控制求值器直接引出 5.4）**，分开读容易断线 |
| 🔧 **1996 年硬件与性能叙述过时** | 5.1 讨论的「寄存器数量」「栈深度」在 2026 年的多核机器上需重新标定；但**寄存器机模型本身没有变** |
| 🔧 **GC 策略叙述简化** | 5.3 只讲三种教科书策略，没有提写屏障、分代假设、增量式并发；2026 年的 ZGC 有颜色指针 + 读屏障，是这些思想的复杂组合 |
| **模拟器代码过于冗长** | 5.2 的机器模拟器约 100 行；中文版缺少对「数据路径与控制器分离」的图示，建议自行画一张 |
| 🔧 **未讲 WASM 与 IR** | 第 5 章写到寄存器机就停了；2026 年应补上 LLVM IR 与 WASM 作为现代「寄存器机」的实例，否则读者难以迁移 |
| **编译规则的三个组合子被忽略** | `preserving`/`seq`/`branch` 是编译器的骨架，只言传不身教很容易漏掉；实际上**整个第 5 章就是围绕这三个 combinator 的组合** |
| 🔧 **`make-compiled-procedure` 的表示** | 编译后过程用 `(list entry env)` 表示；Racket 的 compiled-procedure 用更细的闭包结构，语义一致 |
