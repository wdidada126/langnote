# 第 2 章 构造数据抽象（2.2 层次性数据、闭包性质与序列操作）

> **一句话**：`cons` 造出一切，而 `map/filter/accumulate` 把「怎么遍历」彻底关进黑箱——**列表最美的性质不是它能存东西，而是它能被当成「一句话」来加工**。

## 核心精讲

> 教学示意，**不参与构建、不编译**。

### 列表作为约定界面

```scheme
; 构造器与选择器（屏障之下）
(define (cons x y) (lambda (m) (m x y)))
(define (car z) (z (lambda (p q) p)))
(define (cdr z) (z (lambda (p q) q)))

; 列表字面量只是「嵌套 cons」的糖
(define one-through-three (list 1 2 3))
(car one-through-three)     ; ==> 1 (car 取第一个元素)
(car (cdr one-through-three)) ; ==> 2
```

> **关键区别**：`car` 取的是**第一个组合项**，不是「列表的首元素」。这个细节是很多人啃 SICP 第 2 章时卡住的地方。

### 高阶操作三件套

```scheme
; 筛选
(define (filter predicate sequence)
  (cond ((null? sequence) '())
        ((predicate (car sequence))
         (cons (car sequence) (filter predicate (cdr sequence))))
        (else (filter predicate (cdr sequence)))))

; 映射
(define (map proc sequence)
  (if (null? sequence)
      '()
      (cons (proc (car sequence))
            (map proc (cdr sequence)))))

; 累加（also called fold-right）
(define (accumulate op initial sequence)
  (if (null? sequence)
      initial
      (op (car sequence)
          (accumulate op initial (cdr sequence)))))

; 组装
(define (both? p1 p2) (lambda (x) (and (p1 x) (p2 x))))
(define (both-not? p1 p2) (lambda (x) (not (both? p1 p2 x))))
```

> **为什么是 `accumulate` 而不是 `sum`**：因为 `op` 可以是 `+`、`cons`、`append`、``lambda ...`` 做任何事。**这就是 03 章 `sum` 的推广**，也是把「结构」与「策略」分离的关键动作。

### 嵌套循环的高阶写法（练习 2.36–2.38）

```scheme
; 传统嵌套循环：求和
(define (sum-odd-squares tree)
  (cond ((null? tree) 0)
        ((not (pair? tree)) (if (odd? tree) (square tree) 0))
        (else (+ (sum-odd-squares (car tree))
                 (sum-odd-squares (cdr tree))))))

; 用 accumulate 统一表达
(define (filter-except predicate sequence)
  (filter predicate sequence))

(define (map-accumulate proc sequence)
  (accumulate (lambda (x y) (cons (proc x) y)) '() sequence))

; 幂次求和
(define (sum-of-squares-primes tree)
  (accumulate + 0
              (map-except square (filter prime? (enumerate-tree tree)))))
```

> 练习 2.38 让 `accumulate` 支持 `append`、`cons` 与反序（`reverse`），它是**fold 家族的统一原型**：`fold-right` 对应 `accumulate`，`fold-left` 对应把 `op` 参数顺序翻转的版本。

### 表操作中的共享与别名

```scheme
; 尾递归版的 map（tail-recursive，常量栈空间）
(define (map-tr proc lst)
  (define (iter rest result)
    (if (null? rest)
        (reverse result)
        (iter (cdr rest) (cons (proc (car rest)) result))))
  (iter lst '()))

(reverse '(1 2 3))   ; ==> (3 2 1)

; append：因为 cons 共享结构，append 只复制第一段
(define (append l1 l2)
  (if (null? l1) l2 (cons (car l1) (append (cdr l1) l2))))
```

> **共享结构（sharing）**是 2.2 最容易被忽略的性质：`(cdr x)` 与原列表共享尾部，所以 `append` 不复制 `l2`。这是 5.3 存储分配与废料收集的前置知识，也是 1996 年那帮人反复讲的「空间 vs 时间」取舍。

### 树与层次数据

```scheme
; 树的遍历：只做模式匹配，不做结构假设
(define (count-leaves tree)
  (cond ((null? tree) 0)
        ((not (pair? tree)) 1)
        (else (+ (count-leaves (car tree))
                 (count-leaves (cdr tree))))))

; 用 accumulate 重写
(define (count-leaves-acc tree)
  (accumulate (lambda (x y) (+ x y)) 0
              (map (lambda (x) (if (pair? x) (count-leaves-acc x) 1))
                   tree)))
```

## 版本演进

| 阶段 | 演进要点 |
| --- | --- |
| **1960 LISP** | 列表是唯一数据结构，遍历靠递归；没有 `map`（早期用户自己写循环） |
| **1975 Scheme** | `cons/car/cdr` 的闭包性质确立；高阶遍历函数开始出现 |
| **R5RS (1998)** | `map` 进入标准（保证顺序），`append`/`filter` 有明确语义；`fold-left/fold-right` 命名在 SRFI-1 里定型 |
| **SRFI-1（2000）** | Lisp/Scheme 的**列表库标准提案**，把 `filter/reduce/remove-duplicates` 等统一命名，今天 Guile/Chibi/Racket 都实现它 |
| **Common Lisp** | `mapcar`/`remove-if`/`reduce` 是 1980 年代就有的成熟版本，直接影响了后来的 SRFI |
| **Python / JS（2026）** | `map`/`filter`/`reduce` 成为一等公民；**生成器（generator）让惰性版本（`filter` 返回迭代器）成为主流**，正是 10 章流思想的平民版 |
| **Rust（2026）** | `Iterator` trait + `fold` 把高阶操作做成零成本抽象；`into_iter().filter().map().collect()` 与 2.2.3 的写法几乎同构 |
| **Java（2026）** | Streams API 是一份「SICP 2.2 作业的官方实现」，但仍是拉式（pull）而非推式（push） |

> **1996 → 2026**：2.2.3 的 `accumulate` 今天叫 `fold`，进了 SRFI-1、Python `functools.reduce`、JS `Array.prototype.reduce`、Rust `Iterator::fold`。**思想被所有语言吸收，名字被各自本地化**。

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **`car` 的语义与 C 的 `head` 不同** | 本书 `car (list 1 2 3)` 得到 1，但 `(car (cdr (list 1 2 3)))` 得 2 而**不是**整个 `(2 3)`；很多读者从 C 的数组习惯迁移过来会在这里错 |
| 🔧 **递归深度受限** | 2.2 的 `filter`/`map` 递归版在 1996 年的解释器里受栈限制；改成尾递归/迭代版是必须做的改写（`map-tr` 示意） |
| **共享结构带来的别名 bug** | `(define y (cdr x))` 之后修改 `x` 的尾部会影响 `y`；这是 C/Java 程序员最常犯的 Lisp 式陷阱（Java 里表现为 `subList` 的著名 bug） |
| 🔧 **`append` 与 `cons` 的复杂度标注缺失** | 本书只说 `append` 是 O(n)，没强调**它不复制第二段**；在 2026 年写不可变数据结构时这是核心性质 |
| 🔧 **练习 2.36–2.38 的命名混乱** | 中文版把 `accumulate` 直译且练习要求用 `accumulate` 复现嵌套循环，缺乏提示；建议同时参考 SRFI-1 的 `fold-right`/`fold-left` 命名 |
| **练习难度断层** | 2.2 的练习 2.37（求幂序列）与 2.38（`accumulate` 变体）是整章的分水岭，卡在这里非常常见，建议配合题解 |
| **未讲惰性版本** | 2.2.3 只给及早求值的 `filter`；**惰性版本由 3.5 的流补齐**。如果先读 10 章再回头看 2.2，体会会完全不同 |
