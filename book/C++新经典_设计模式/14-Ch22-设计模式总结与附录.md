## 核心概念速览（中英对照）

- **静态初始化次序** — static initialization order：跨翻译单元的全局对象构造顺序未定义——
  A.1 的正题（Meyers 单件是工业解药）
- **拷贝构造/拷贝赋值** — copy constructor / copy assignment：A.2 全节主题；
  自我赋值（self-assignment）与继承链下的重复代码是其两个 C++ 特色坑
- **copy-and-swap**：自我赋值免疫 + 强异常保证的赋值书写惯用法（A.2.2 问题的现代答案）
- **规则零/规则五** — Rule of Zero / Rule of Five：2010 年代对「手写三件套」的清算口径
- **is-a 与 public 继承** — public inheritance as is-a：A.3 的主张；子类遮蔽父类函数
  （shadowing/`override` 缺失）是其列出的头号事故
- **纯虚函数的实现体** — body for pure virtual：A.3.4——「强制子类实现 + 提供默认素材」的
  C++ 冷门机制（链接期合并，LSP 语境）
- **组合与委托** — composition & delegation：A.4 收尾全书——「优先组合而非继承」的语言落地
- **模式目录** — pattern catalog：22 章总结的应有物（分类表/关系图）
- **模式消解** — pattern dissolution：语言设施吸收模式样板的历史过程（本文件的 2026 视角主题）
- **代码生成** — code generation：反射/宏/模板把「手写的模式」变成「生成的模式」

## 为什么总结章要连着附录讲：地基与楼层

本书的结构诚实值得记录：附录 A 用 4 大节回讲**类和对象的语言语意**——这不是凑页数。
24 个模式里有 19 个的机制建立在这些语意上：

| 附录小节（✅已核实） | 托底的模式 | 关系 |
| --- | --- | --- |
| A.1 静态对象/全局构造顺序 | 单件（7 章）、享元池 | 「实例唯一」的前提是「何时构造」可控 |
| A.2 拷贝构造/赋值/自我赋值 | 原型（3 章）、备忘录（18 章） | clone 与快照的**正确性**全在拷贝语意 |
| A.3 is-a 与重写规则 | 模板方法/状态/策略/访问者 | 虚函数契约是所有多态模式的接缝 |
| A.4 组合与委托 | 装饰/桥接/组合/中介者 | 「优先组合」一句话管四个模式 |

换句话说：**模式是设计层的词汇，附录是语言层的语法**——作者把语法单独附在书尾，
等于承认这本书的天花板受限于 C++11 的设施；把附录读完再回头看 24 式，
才知道哪些样板是「语言缺位税」（可被新设施退税），哪些是设计本身（永远要人写）。

## 机制：22 章总结的「一张关系图」补写

原书总结章明细 ⚠️未核实，这里按 24 式关系补一张教学图（模式间的引用是 GoF 原书本有的
网状关系，非本书原创）：

```
创建线： 简单工厂 → 工厂方法 → 抽象工厂
                    ↘ 原型（复制代替从零造）
        建造者（分步装配）——与工厂正交：管「怎么装配」不管「造哪个」
结构线： 适配器/桥接/装饰/外观/享元/代理/组合
          组合 ←—— 解释器/访问者（操作 AST/元素树的两副面孔）
          装饰 ←—— 职责链（环绕链兄弟）
行为线： 模板方法 ←(换序)→ 策略 ←(同构)→ 状态
        观察者 ←(星形化)→ 中介者
        命令 ←(状态可逆)→ 备忘录
语言税： 以上凡是「虚函数+类」写的样板 → 模板/lambda/variant/concepts 可部分退税
```

## 🔧 退税示范：模式被语言吸收的三个断面（已实测 g++ 15.2，`-std=gnu++23`）

```cpp
// 1) concepts 约束插件契约（策略/工厂的类型校验现代化）
template <class T> concept Saver = requires (const T& t, const std::string& s) {
    { t.serialize(s) } -> std::convertible_to<std::string>;
};
struct JsonSaver { std::string serialize(const std::string& d) const { return "{json:" + d + "}"; } };
template <Saver S> std::string saveWith(const S& s, const std::string& d){ return s.serialize(d); }

// 2) std::expected：工厂/链上「失败」的显式通道（代替返回 nullptr/静默传递）
std::expected<int, std::string> parseInt(const std::string& s){
    int v = 0;
    for (char c : s){
        if (c < '0' || c > '9') return std::unexpected(std::string{"bad char "} + c);
        v = v*10 + (c - '0');
    }
    return v;
}
```

实测输出：`{json:save} / 123 ok / err: bad char a`。注意：**被吸收的只有「样板」**——
`Saver` 概念省掉的是抽象基类三件套，不是「把序列化做成可换插件」这个设计决策；
设计决策才是模式的实体，样板只是它在旧语言里的影子。

## 权衡：总结章该有的诚实与本书的选择

GoF 式总结强调「何时不用」（对照 [../设计模式GoF/06-模式的代价与反模式.md](../设计模式GoF/06-模式的代价与反模式.md)）；
2026 年补充三条：
1. **模式数量早已不是 23**：POSOA、PoSA、游戏模式（Nystrom）各有一张表——「设计模式」
   作为商标的边界应当打开；
2. **模式教学的语言基线必须换代**：以 C++11 讲模式（本书基线）在今天会系统性多教一倍样板——
   补税单见各文件「最新演进」节；
3. **A.3 的「public 继承规则」在现代的对应物是 `final`/`override`/CRTP 纪律**——
   语法级建议应升级为工具级（clang-tidy 规则），这是中文模式书极少走的一步。

## 最新演进与工业实践

- **附录 A 诸题的最新语意**：A.2 的拷贝三件套在 C++11 后并入**五法则**（移动构造/移动赋值），
  A.3 的「遮蔽」有了 `override` 关键字的编译期执法，A.1 的构造顺序问题今天的推荐解是
  「依赖注入到显式启动序列，少用全局」——三条均可在
  [../Effective_Modern_C++.md](../Effective_Modern_C++.md) 找到对应条目（item 值域），
  底层机制的权威描述在 [../深度探索C++对象模型/05-构造析构拷贝语意学.md](../深度探索C++对象模型/05-构造析构拷贝语意学.md)
  与 [../深度探索C++对象模型/01-关于对象.md](../深度探索C++对象模型/01-关于对象.md)。
- **给「一周一模式」学习法的收尾评价**：OPAC 摘要口径的 24 周节奏适合建立**词汇表**；
  从词汇到判断力的下一步，是回到自己项目做一次「退税审计」：数一数哪些模式的类
  可以删成一行 lambda/一个 variant——本目录各文件的权衡节即审计底稿。
