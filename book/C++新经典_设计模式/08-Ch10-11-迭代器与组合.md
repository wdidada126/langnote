## 核心概念速览（中英对照）

- **迭代器** — Iterator：顺序访问聚合元素而不暴露其内部表示
- **聚合** — Aggregate：持有元素集合的对象（容器）
- **单一职责原则** — SRP（Single Responsibility Principle）：一个类只有一个变化的理由（10.2 专节）
- **内聚/耦合** — cohesion / coupling：职责内聚、依赖松耦合——SRP 的两个可测化身
- **范围 for** — range-based for：C++11 起「消费端迭代器」的语言内置
- **输入迭代器概念** — C++20 `std::input_or_output_iterator` 等 iterator concepts：迭代器的类型契约
- **哨兵** — sentinel：C++20 允许终点与起点类型不同（begin/end 异构）
- **组合** — Composite：树叶与树枝实现同一接口，递归构成树形结构
- **透明式组合** — transparent composite：加孩子操作放**基类**——客户端对树/叶一视同仁，但叶子背着假接口
- **安全式组合** — safe composite：加孩子只在**树枝**上——类型安全，客户端需区分树/叶（11.4 的正题）
- **场景图** — scene graph：Composite 在游戏引擎的标准形态（节点树+变换级联）
- **ECS** — entity-component-system：数据导向的后继者：实体=id，组件=纯数据，系统=批处理函数

## 动机一（迭代器）：遍历逻辑写三遍

10.1 的「容器和迭代器的简单范例」指向的老问题：背包、怪物表、任务列表……每个容器都要
手写 `for (int i=0; i<n; ++i)` 级别的遍历，容器换链表/哈希表，遍历代码全重写。
把「怎么走到下一个」抽成独立小对象后，**算法与表示解耦**——并且这段抽出的代码
恰好给 10.2 的 SRP 做了最佳教具：容器管「存」，迭代器管「走」，各一个变化理由。

本书 10.3.2 罕见地专设「现代C++中的迭代器」小节（✅标题）——作者的口径是：
STL 迭代器已经是默认答案，模式课仍讲它是为了**看懂 std 在替你做什么**。

## 动机二（组合）：11.1「目录内容遍历」

文件和目录共用一套「列内容」逻辑：目录里既有文件又有子目录，递归下去。
若用「文件类/目录类」两套类型，客户端要为二者写两份代码；
Composite 的答案：**让 Component 基类同时是文件和目录的接口**，客户端代码只写一遍
`print(node)`，递归自然涌现。11.5「其他场景探讨」在游戏语境最典型的落点就是场景树/UI 树。

## 机制：🔧 安全式组合 + 手写迭代器（已实测 g++ 15.2，`-std=gnu++20`）

```cpp
class SceneNode {
public:
    virtual ~SceneNode() = default;
    explicit SceneNode(std::string n):name_(std::move(n)){}
    virtual void draw(int depth) const { std::string p(depth*2,' '); std::cout << p << name_ << "\n"; }
protected: std::string name_;
};
class SceneLeaf final : public SceneNode { public: using SceneNode::SceneNode; };
class SceneGroup final : public SceneNode {
public:
    using SceneNode::SceneNode;
    void add(std::shared_ptr<SceneNode> n){ kids_.push_back(std::move(n)); }  // 只在树枝——安全式
    void draw(int depth) const override { SceneNode::draw(depth);
        for (auto& k : kids_) k->draw(depth+1); }
private: std::vector<std::shared_ptr<SceneNode>> kids_;
};

class Inventory {                                  // 手写输入迭代器：容器管存、It 管走
public:
    explicit Inventory(std::vector<std::string> items):items_(std::move(items)){}
    class It {
    public:
        using value_type = std::string;
        using difference_type = std::ptrdiff_t;
        using iterator_category = std::forward_iterator_tag;
        explicit It(const std::string* p):p_(p){}
        const std::string& operator*() const { return *p_; }
        It& operator++(){ ++p_; return *this; }
        bool operator==(const It& o) const { return p_ == o.p_; }
    private: const std::string* p_;
    };
    It begin() const { return It{items_.data()}; }
    It end()   const { return It{items_.data() + items_.size()}; }
private: std::vector<std::string> items_;
};
```

实测输出：缩进的树（root/player/fx/flame）+ `sword potion shield`——
手写 `It` 满足 C++20 iterator concept 的最小子集后，**范围 for 免费工作**。
组合侧的结构要点：`draw` 的多态递归 = 模板方法（骨架在基类）+ 组合（树形）的叠加，
GoF 明说 Composite 常与 Visitor 搭档（第 13 文件），原因在此。

## 权衡：11.4 的透明/安全之辨与组合的 ECS 危机

- **透明式**（`add/remove` 也放基类）：客户端一行 `node->add(child)` 不假思索，但叶子
  背了假接口（调 `SceneLeaf::add` 要么运行时异常要么静默——违反 ISP）。
- **安全式**（如上码）：编译期挡住对叶子的 add，代价是客户端拿 `SceneNode*` 时**不知道**
  能不能加孩子——要么 downcast（`SceneGroup* g = dynamic_cast<...>`），要么上 Visitor。
- **ECS 的冲击（2026 必读）**：场景树式 Composite 的三大痛——指针追逐缓存不友好、
  节点类型虚表膨胀、子对象生命周期管理复杂。数据导向方案（EnTT、Bevy 等公开库/文档）：
  实体只是 id，组件是 SoA 连续内存，「父子/变换级联」用**关系组件**表达，系统批处理。
  **树没有消失**（prefab 实例化、UI 布局、附件挂点仍是显式树），但「用继承树表达组合」
  这一 GoF 编码方式被「用数据表达组合」取代——这是本书 11.5 那个年代少见、
  而今天必须补的一课（实证可再读 [../Rust游戏开发实战.md](../Rust游戏开发实战.md) 的 Bevy 章）。

## 相邻概念对比

| 对比 | Iterator | Composite | Decorator | Adapter |
| --- | --- | --- | --- | --- |
| 管的问题 | 怎么**走**集合 | 树**同构** | 逐层**加料** | 接口**翻译** |
| 结构特征 | 持游标、可比较 | 自引用容器 | 持同接口内层 | 持异构内层 |
| 语言吸收度 | 高（范围 for/concepts/generator） | 低（运行时树仍手搓） | 中（ranges view 同构） | 低 |

## 最新演进与工业实践

- **C++20 iterator concepts + 哨兵**：迭代器从「五种 tag 的方言」变成可检查的契约；
  `std::counted_sentinel`/`std::as_const` 等 C++23 增补继续（均已核实入标准；
  基线描述见 [../C++17完全指南.md](../C++17完全指南.md) 语言侧与
  [../C++标准库.md](../C++标准库.md)）。
- **C++23 `std::generator`**：协程式「产出元素的迭代器」——树遍历可写成
  `generator<Node&> walk(node)`，递归 Composite 的显式栈样板消失（已核实入 C++23；
  姊妹册论证在 [../C++20设计模式/10-解释器与迭代器.md](../C++20设计模式/10-解释器与迭代器.md)）。
- **EnTT（公开仓库）**：`registry.group<T>`/view 的迭代是「批量迭代器」——
  遍历语义从「一步一对象」进化为「一步一 SoA 切片」，性能模型完全不同。
- **UE Blueprint/Widget 树**（公开文档）：UI 与预制体层级仍是正统 Composite——
  透明/安全之争在引擎里的裁决：**接口里只暴露 `AddChild` 给 Panel 类**（安全式路线），
  Leaf 控件根本不带 add——与 11.4 的结论一致。
