## 核心机制

### 导出链：从训练产物到推理工件

- 路径：`.pt` 权重 → ONNX（图+权重交换格式）→ TensorRT/OpenVINO/CoreML 等运行时
  engine ✅（各家格式的定义性事实）；Python 训练、C++/边缘设备执行的分工靠这条
  序列化鸿沟缝合 ⚠️（书的展开深度待核）。
- 经典语言工程锚：**ONNX 之于深度学习 ≈ LLVM IR 之于编译器**——前端多、后端多，
  靠中间表示把 M×N 适配降为 M+N；导出失败九成是算子表不支持（如动态 shape、
  自定义头），排错先查 IR 层再查运行时 ⚠️（工程共识）。
- 后处理归属决策：NMS 留在 Python 侧还是图内固化（torchvision NMS 算子导出兼容性
  ⚠️）——部署章的真实分水岭在这里，书若只演示 `model.export()` 一行即浅尝 ⚠️。

### 推理加速与精度损失谱

- FP32→FP16→INT8 的位宽阶梯 ✅ 概念；INT8 需校准集（PTQ）或量化感知训练（QAT）
  ⚠️ 术语口径通用。检测模型的量化雷区：回归分支对误差非线性敏感（框坐标）⚠️，
  这是「分类掉点少、检测掉点多」传闻的机制解释位——书若给数字必核其数据集口径（回 01 带）。
- 吞吐三件套：batch 大小、imgsz、运行时线程池；对照 C++ OpenCV dnn 模块 ✅ 存在性——
  OpenCV/ONNX Runtime/TensorRT 三条 Python 可触达的推理路径，书的选择不等于领域选择 ⚠️。
- 端侧锚：Jetson/RK 类 NPU 各有私有工具链 ⚠️（书覆盖度未知）；「模型文件格式」
  之外还有「算子库版本」双重耦合，嵌入式读者对本带要按半年时效重读。

### 服务化与监控（若书触及 ⚠️）

- 视频帧流水线：解码→前处理→推理→后处理→回写；瓶颈常不在模型而在解码/拷贝 ⚠️（工程
  共识）。Python 侧 GIL 与多进程 worker 的取舍，是书里最容易照抄即错的段落 ⚠️。

## 批判读法（易错与存疑）

1. **benchmark 条件不给全**：FPS 数字必须带 batch/imgsz/设备/精度/是否含前后处理，
   缺一即不可比（✅ 方法学）；书的性能表逐格盘点缺哪项。
2. **「导出即成功」叙事**：ONNX 导出成功≠TensorRT build 成功≠端侧库支持，三段
   成功率各自独立 ⚠️；书示例环境版本与读者版本差一个 release 就翻车。
3. **量化掉点归因**：掉点常来自校准集分布≠生产分布而非位宽本身 ⚠️；书若有
   「INT8 只掉 0.x」结论，查其校准集来源。
4. 部署章代码的**仓库 commit 锚定**：本仓无法核对 2026-04 对应哪个版本 ⚠️，读时
   自查 docs 版本号，勿把书当 API 手册。
5. 若书未讲「推理服务的时间预算与降级策略」（掉帧/降 imgsz），工程视角即为缺口 ⚠️。

## 核心概念中英对照

- **中间表示** — intermediate representation (IR)：ONNX 的生态位，LLVM IR 同类物 ✅。
- **导出** — export：训练工件到推理工件的序列化迁移。
- **训练后量化** — PTQ：用校准集定标度的位宽压缩 ⚠️ 术语通用。
- **量化感知训练** — QAT：训练中模拟量化噪声 ⚠️。
- **算子支持表** — opset support：导出失败的第一现场。
- **吞吐/延迟** — throughput / latency：部署双目标，互不可替 ✅ 概念。
- **端侧运行时** — edge runtime：TensorRT/OpenVINO/NPU SDK 一类的执行容器。
