## 11.1 「实时」的三档定义（⚠️ 重构标尺）

| 档 | 端到端延迟 | 典型链 | 代价 |
| --- | --- | --- | --- |
| 准实时 | 分钟 | 高频批（Firehose 小缓冲+微批转换，04/06） | 最低运维，口径同批 |
| 流式 | 秒 | KDS/MSK → Flink → 服务层 | 状态与正确性工程 |
| 交互流 | 亚秒+在线读 | 流 → KV/搜索/缓存面 | 双写一致性面 |

架构第一步是**给每个用例选档**——「仪表盘都要秒级」是需求通胀不是需求 ⚠️（重构判断）。

## 11.3 流处理正确性三件套（⚠️ 通识，Flink 语义面）

- **时间语义**：事件时间 vs 处理时间；水位线（watermark）=「迟到到此为止」的承诺 ⚠️——
  乱序预算与延迟目标互斥，选边站是架构决定。
- **状态与 exactly-once**：checkpoint 屏障一致性 + 两阶段提交汇 ⇒ 端到端 exactly-once
  **只在 sinks 配合时成立** ⚠️（S3 的「提交=最后清单写」与 03 章 §3.7 同构）。
- **保留期边界**：KDS 重放窗口（🔧E4：游标只能在保留段内回拨）⇒ 「补数能力」是流的
  03 章分层问题 ⚠️。

## 11.4 流批口径统一：Lambda/Kappa 之辨（⚠️ 通识史账）

Lambda（批层+加速层双实现，对账地狱）→ Kappa（流重放一统，受保留期物理限制 🔧E4）→
湖仓调和（流落湖+表格式 upsert，批读同一张表——12 章接棒）⚠️。成书 2022 语境：
「口径统一」口号大于落地；2026 复盘：真正终结争论的是**开放表格式吸收 CDC**（04 章演进
同链：[../Apache_Hudi_Definitive_Guide/00-总览与阅读地图.md](../Apache_Hudi_Definitive_Guide/00-总览与阅读地图.md) ✅）。

## 11.5 流上的维表与富化

事件只有事实，消费要成品：流侧 join 静态维（广播/缓存/异步 I/O 三法 ⚠️ Flink 语义）
与「维变化慢、事实到得快」的时间旅行 join ⚠️（表格式承接后移）。架构句：
**富化在哪层做，决定你为「重算历史」付多少钱**——流内做=历史难，落湖做=延迟税 ⚠️。

## 11.6 服务层：流结果怎么被读

秒级读需求 ⇒ 结果进可低延迟查的仓/引擎：Redshift 流式摄入面、OpenSearch、DynamoDB
（⚠️ 概念登记；DynamoDB 对位盘上 [../Amazon_DynamoDB_TDG/00-总览与阅读地图.md](../Amazon_DynamoDB_TDG/00-总览与阅读地图.md) ✅ 在盘）。
注意：**服务层是双写点**，一致性合同（11.3 两阶段提交 + 幂等键）在此签署 ⚠️。

## 11.7 🔧E4 回看：从游标到水位线（**非 AWS 行为**）

04 章实验（追加 10 万条 178ms；游标增量读 29,999 条 2.0ms）的镜像问题：本机没有
「事件时间」列也能玩游标，但一旦把 `body` 换成带延迟抖动的到达序，**没有水位线概念的
存储表就会把「未来」算进当前窗口**——课堂里给学生两分钟加一列 event_ts 再跑一次，
立刻体感 11.3 第一条为何值钱 ⚠️（教学重构，非 AWS 行为）。

## 11.8 成本与弹性的流式特殊性

按分片/RPU 常开计费 ⇒ **流的空闲也要钱**（与 Athena 按扫描「不用不付」镜像互补，13 章
合账）。弹性三问 ⚠️（重构）：峰值供给方式（手动扩分片 vs 自动）、缩容安全边界（游标
保留期）、以及「这条流值得 7×24 吗」——后一问最常砍预算 ⚠️。

## 11.9 档位决策示范（⚠️ 重构示例需求单，非书中案例）

- 需求单甲：「经营大屏要秒级」——拆穿后发现决策者每分钟看一次 ⇒ 准实时档
  （11.1 第一行：Firehose 30s 缓冲+分钟级聚合）省一整条 Flink 链 ⚠️。
- 需求单乙：「风控要拦这笔交易」——亚秒+在线读 ⇒ 交互流档（11.1 第三行），

## 11.10 流式层复盘五问（⚠️ 重构自测）

1. 你家每条流落在 11.1 哪档？「需求通胀档」（要秒级但没人秒级看）的有几条？
2. 水位线的迟到预算写在需求文档还是只写在代码注释里？（11.3 第一条的合同化）
3. exactly-once 声称链上，最后一个 sink 真的配合提交协议吗？（11.3 第二条的验收）
4. 重放窗口外的历史，你的「Kappa 兜底方案」是什么？（11.4：多半是湖，那就回到 12.1）
5. 流的常开费月度复盘做过「这条流值得 7×24 吗」的死刑问询吗？（11.8/13.4 ⚠️）

**一句话收束** ⚠️：流式架构的尊严建立在两件小事上：说得出
延迟的数字（11.1 档位）、说得出迟到的边界（11.3 水位线）——两者说不出，
架构图上的闪电符号就只是装饰 ⚠️（重构句）。

课堂加练 🔧：给 E4 的 seq 到达序打乱 10% 再跑同一游标语义，「至少一次+幂等」与
「恰好一次」的差别会在重复行里自己开口说话（本机无窗口无状态后端，非 AWS 行为）。

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
| --- | --- | --- |
| 水位线 | Watermark | 迟到数据的信任边界 |
| 事件时间 | Event Time | 以发生时刻而非到达时刻计 |
| 检查点 | Checkpoint | 状态一致性快照 |
| 两阶段提交 | Two-Phase Commit | 端到端 exactly-once 的汇侧协议 |
| 状态后端 | State Backend | 键控状态的存放引擎 |
| 广播流 | Broadcast State | 小维表进算子内存 |
| Lambda 架构 | Lambda Architecture | 批+加速层双路史前方案 |
| Kappa 架构 | Kappa Architecture | 一切皆可重放流 |
| 富化 | Enrichment | 事实流上挂维度 |
| 双写合同 | Dual-write Contract | 流结果与被读层的一致性承诺 |
