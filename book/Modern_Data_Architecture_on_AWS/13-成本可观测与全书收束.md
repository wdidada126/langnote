## 13.1 AWS 分析账单的四种形状

⚠️ 转述/通识归纳（各 ✅ what-is 页均含计量小节，本册不引具体费率）：

| 账形 | 代表 | 控制杠杆 | 前文章 |
| --- | --- | --- | --- |
| 按扫描量 | Athena | 分区/压缩/列裁剪三级火箭 | 05/08 |
| 按容量时长 | Redshift 预置、EMR、MSK | 右型+伸缩纪律+预留折扣权衡 | 07 |
| 按请求/时长细粒度 | Lambda、Glue(DPU)、SFN(状态转换) | 任务粒度与冷启动设计 | 06/10 |
| 常开流费 | KDS 分片、Firehose、Flink RPU | 11.8「值得 7×24 吗」 | 04/11 |

**第一公理**：分析成本的主体不是存储（03 分层后存储是小头），是**计算×频次×放大器
（坏查询/重跑/笛卡尔）**⚠️——账要往查询面管，不是往磁盘上管。

## 13.2 归因三件套：标签·工作组·账期对齐（⚠️ 通识）

- 资源标签（域/管线/团队/环境）打在**创建时**（10.7 标签、09 owner 同构）；
- Athena 工作组分账 ✅（`athena/latest/ug/what-is.html` 体系 ⚠️）、Redshift 工作组分账
  ✅（`redshift/latest/mgmt/welcome.html` 体系 ⚠️）——引擎侧原生分账优于事后按用量猜；
- 成本与用量数据的**粒度对齐**（小时级账单×分钟级运行）靠运行元数据回标 ⚠️（10.7 观测
  接口的成本侧用途）。

## 13.3 性能-成本联合调优（把全书旋钮摆上天平）

- 更快常更贵也常更省：Athena 加缓存/MV 省扫描费 ✅（08 章）；Redshift 升规格提并发税降
  等待税（07）；Glue 换 Python Shell 省 DPU 但限规模（06）。
- 排序键/聚簇类旋钮的**写放大换读税**交易（🔧E6 直觉，非 Redshift 行为）；
- 生命周期把「查得少」的数据搬离「算得贵」的层（🔧E1 直觉，非 S3 行为）；
- 万能先问：这个负载的**正确档位**是什么（02 四问/11.1 标尺）——档位错了，旋钮都是安慰剂 ⚠️。

## 13.4 可靠性定价（⚠️ Analytics Lens 支柱转述 + 重构账法）

✅ `wellarchitected/latest/analytics-lens/welcome.html` 的可靠性/运营支柱问句翻译成钱：
重放预算（04.8）=为补数保留的存储与窗口成本；DLQ 与隔离（10.6）=为瞬态错误付的
冗余；新鲜度 SLA（08.5）=物化与刷新的常开费。**给每个承诺标价**是架构师的预算语言，
「随时可用、秒级、永远正确」三者同要=账单无限 ⚠️（重构句）。
