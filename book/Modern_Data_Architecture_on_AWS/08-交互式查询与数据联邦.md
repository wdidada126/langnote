## 8.1 Athena 的账本模型（✅ `athena/latest/ug/what-is.html`，⚠️ 转述）

- serverless、ANSI SQL、直读 Glue 目录里的湖表；**计费面=你扫了什么**（按数据量档位，
  压缩/列式/分区三件套直接把账单乘除 ⚠️ 恒等式与 05 章 §5.3 同源）。
- 引擎选项（Athena 引擎版本/分布式增强 ⚠️ 概念登记，不引未验证页）；
  物化视图与结果复用面后补 ⚠️（演进节）。
- 架构位：Athena=湖的「读接口」，不承担写路径与重度并发服务（那归仓或服务化 API）⚠️。

## 8.2 谓词的三级火箭（⚠️ 通识 + ✅ partitions 页）

同一条 `WHERE`，收益排序：**分区裁剪（05 章 ✅）> 文件内 min/max/行组裁剪（Parquet 统计）>
列裁剪（列式格式）**。三者的旋钮分别在目录设计、写入 compaction（03/06）、投影表达式 ⚠️。
Athena 对「谓词是否真下推」的验证姿势：对比扫描量指标（workgroup 指标面 ⚠️，未验证页不引）。

## 8.3 联邦的三种形态

1. **湖内多格式联邦**：一引擎跨 Parquet/ORC/JSON 表（目录统一 ⇒ SQL 统一 ⚠️）。
2. **仓↔湖联邦**：Redshift Spectrum 从仓 SQL 触达湖表（07 章 §7.3 世代一 ✅ welcome 页体系）；
   镜像方向是 Athena 侧无仓表一等公民 ⇒ 语义层要小心「谁能查谁」⚠️。
3. **操作库直连联邦**：RDS/Lambda 连接器（Athena 联邦查询框架 ⚠️ 概念，未验证页不引 URL）——
   适合低频小查询，滥用即把生产库当数仓 ⚠️ 红线。

## 8.4 🔧E5：零搬运关联的本地直觉（**非 AWS 行为**）

SQLite ATTACH 双库：湖侧事实（冷库 44,446 行）× 仓侧维表直接 JOIN，**8.2ms、零物化复制**。
移植直觉：联邦的本质=**把「搬运决策」推迟到查询时**；代价直觉同样可测——本机无网络、
无序列化、无并发其他租户，所以 E5 只证「可行」不证「划算」。**划算的判据回 §8.5** ⚠️。

## 8.5 物化与否的决策表（⚠️ 重构框架）

| 判据 | 倾向联邦即时查 | 倾向物化/入仓 |
| --- | --- | --- |
| 复用频次 | 一次性探索 | 高频固定报表 |
| 延迟 SLO | 分钟可忍 | 秒级承诺 |
| 数据量斜率 | 稳定小 | 大且长尾 |
| 一致性要求 | 允许快照漂移 | 需时点一致发布 |
| 成本归属 | 谁查谁付可接受 | 需摊薄到产品账 |

物化视图（Athena/Redshift 均有面 ⚠️）是两列之间的桥：把「复用频次」判据自动化——
但 MV 的**新鲜度契约**（刷新管线、10 章）是新债不是免债 ⚠️。

## 8.8 查询治理的最小三件

①工作分组+扫描配额（账单护栏）；②目录授权前置（09 章，Athena 无权限即无扫描）；
③慢查询归因（扫描量/裁剪失效两张表）⚠️ 通识——交互层的自由度必须用这三件换，
否则「人人都能查湖」=「人人都能开账单」⚠️。

## 8.9 扫描量手算示范（⚠️ 重构算术，恒等式不给单价）

设：日增 40GB 压缩 Parquet，按 `dt` 分 365 区，全表 14.6TB。
- 查询 A（带 dt 谓词，7 天窗口，读 3 列/共 20 列）：扫描≈40GB×7×(3/20 列比例直觉，
  列裁剪生效前提=谓词与投影都下推)≈**42GB**；
- 查询 B（无分区谓词的探索全表聚合）：**14.6TB**——A 与 B 差 **~350 倍**；
- 结论恒等式（05 §5.3）再推一步：**一条坏 SQL 的价格=它跳过所有三级火箭的价格** ⚠️。
护栏三件回 §8.8：工作组配额挡 B、模板预检教 A、成本超限告警连 13.2 归因 ⚠️。

## 8.10 查询层复盘六问（⚠️ 重构自测）

1. 贵查询榜前五条，各卡在哪级火箭上？（8.2——三级全通的查询不该上榜）
2. 你的「谁查谁」矩阵能画成 8.3 三形态的并集吗？画不出的边=未声明的联邦 ⚠️。
3. 物化清单每张 MV 有新鲜度契约与下线条件吗？（8.5 的 MV 债条款）
4. BI 工具是直连还是穿透到引擎各自缓存？（8.6 手搓缓存红线）
5. Zero-ETL 上线后，旧 DMS 链路的退役评审排期了吗？（8.7——新默认不改旧账=双份成本 ⚠️）
6. 8.8 三件缺一，请把「人人能查湖」改写进风险登记册 ⚠️。

**一句话收束** ⚠️：交互层的文明程度，等于「自由的查询」与
「受管的成本」之间的明确汇率——8.8 三件套就是汇率表；没有汇率表的湖上查询自由，
是向财务未来的借款，利息按扫描量复利计 ⚠️（重构句）。

补一题课堂实验 🔧：E5 之后把两个 ATTACH 文件复制到另一目录、改名、重跑——学生
会立刻追问「生产上谁负责这个改名不炸」，联邦治理（09 章）的必要性从体感长出
（本机无鉴权无计费，非 AWS 行为）。

补一句归因：8.9 的手算数字全部来自 05 章恒等式的代入练习——**架构师要能在白板上
用一行算式否决一条查询，这是查询治理最小的可执行形式** ⚠️（重构句）。

## 最新演进与工业实践

2022→2026（✅ URL 200；⚠️ 转述）：

- **Athena 的「仓化」**：物化视图、托管 Iceberg 写路径（✅ `glue/latest/dg/iceberg-tables.html`
  302→200 体系）、ACID 表支持持续补齐——「只能读湖」的 2022 刻板印象过期 ⚠️。
- **Zero-ETL 普及后 §8.3 形态 3 收缩**：常规 RDS→仓不再走查询时联邦 ✅（8.7）；
  直连框架退守「跨账号/稀有源」长尾 ⚠️。
- **工业实践**：查询治理三件套（8.8）在 2026 已模板化为「工作组+标签+配额告警」三开关；
  反例长尾是 BI 工具绕开治理直挂引擎——评审关注点从「能不能查」变「经由什么身份查」
  （09 章身份面）⚠️ 通识。
- **本机互鉴重申** 🔧：E5 脚本（tmp `exp.py`）适合课堂 5 分钟演示「联邦=推迟搬运」，
  并当场追问「生产上为什么不能这么爽」——四差：网络、并发、计费、鉴权（非 AWS 行为）。
