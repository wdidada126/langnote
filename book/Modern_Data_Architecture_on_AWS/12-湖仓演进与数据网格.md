## 12.1 表格式：湖获得「表的教养」的元数据层（✅ 两页）

✅ `glue/latest/dg/iceberg-tables.html`（302→200）、✅
`prescriptive-guidance/latest/cloud-design-patterns/delta-lake.html`（302→200）（⚠️ 转述）：

- 家族共同点：Parquet 文件之上加**快照式元数据树** ⇒ ACID 写、模式演进、时间旅行、
  隐藏分区（05 章 §5.3 手工分区学的接管者）。
- 差异面（⚠️ 通识，不锁版本细节）：规范开放度/引擎联盟/维护工具链；选型跟着
  「你的消费引擎矩阵」走而非跟着博客走。
- 对 AWS 的关系双轨：**Glue 注册表格式表**（互操作面）与 **S3 Tables 原生托管**
  （产品面，12.2）——同一枚硬币的平台内外两面 ⚠️。

## 12.2 S3 Tables：湖仓的「出厂默认」（✅ `s3/latest/userguide/s3-tables.html`）

## 12.3 Zero-ETL：让「集成」从项目变配置（✅ `glue/latest/dg/glue-zero-etl.html` 302→200）

⚠️ 转述：RDS/DynamoDB→Redshift（及湖侧对偶面）托管 CDC 管线：预置/持续同步/

## 12.4 Data Mesh：从技术架构到组织架构（⚠️ 通识史账）

- 四原则（⚠️ 业界通识）：域所有权、数据即产品、联邦治理、自助平台。
- 对 09/10 章的改写：权限模型（9.2）不变，**授权主体从「中心团队」变「域团队」**；
  编排所有权（10.2 分工句）以域为墙切分 ⚠️。
- 实现中立：Mesh 不是服务清单，是「谁对哪个数据产品负责」的合同网——
  用 AWS 组件摆 Mesh 与用开源摆，差别在平台工程面不在原则面 ⚠️。

## 12.5 DataZone：Mesh 的 AWS 原生承载（✅ `datazone/latest/userguide/what-is-datazone.html`）

⚠️ 转述：域（domain）/项目（project）/数据产品三层抽象，跨账号资源订阅+治理钩子+
统一目录检索。与 Glue Catalog 的关系：DataZone 管「组织可见性与订阅流」，Glue 仍管
「引擎解释表所需的物理元数据」——**两本账别记成一本** ⚠️（架构师验收点）；
05 章 §5.6 血缘与 09 章 §9.5 owner 制在此汇合。

## 12.6 🔧E5 的 Mesh 读法（**非 AWS 行为**）

08 章 ATTACH 联邦（8.2ms 零搬运）在域视角下升级：两个 ATTACH 文件=两个域的资产，
查询时的 join=跨域订阅。本机模型缺的恰是 Mesh 的全部难点：**契约（schema 变更谁
通知谁）、发现（元目录）、结算（成本归因）**——把这三样加回 ATTACH 世界，就是
DataZone 想替你做的一切 ⚠️（教学重构）。

## 12.7 架构栈终态拼图（全书骨架回收）

源（04）→ 着陆 S3（03）→ 目录（05）→ 托管表格式/S3 Tables（12.2）→ 转换（06/10）→
仓/流双消费（07/11）→ 联邦与物化裁决（08）→ 权限与所有权（09/12.5）→ 成本账（13）。
「现代」二字的最终定义 ⚠️（重构）：**每层可独立演进、层间以契约相连**——
表格式、目录、事件模式、授权模型就是四份契约 ⚠️。

## 12.9 托管表 vs 自建表格式对照（⚠️ 重构决策表）

| 判据 | S3 Tables 托管 | Glue 注册自建表 |
| --- | --- | --- |
| 格式选择自由度 | Iceberg 单格式 ⚠️ | 三格式任选 ⚠️ |
| 维护运维 | 内置（12.2） | 你的日程（6.7） |
| 跨云可移植 | 规范可携、平台绑定 ⚠️ | 文件即自由 |
| 演进节奏 | 跟随产品发布 | 跟随社区版本 |
| 适合画像 | AWS 主站、少运维 | 多云/格式癖/存量 EMR |

补一句组织面 ⚠️：选托管=把 12.4「自助平台」四层里的存储维护外包给 AWS 自己——
平台团队省下的排班，应转投契约管理（12.7），这是「架构会自己变好」的唯一合法形式。

## 12.10 演进层复盘四问（⚠️ 重构自测）

1. 你的平台里「手工湖仓三件套」（键设计/分区学/compaction 日程）还剩几件没被
   12.2 托管收编？留着的理由能写成一行验收标准吗？
2. 表格式选型的判据，写的是「规范开放度」还是「你的引擎矩阵已支持谁」？（12.1 尾注）
3. 12.4 四原则里，你组织真正缺的是哪一条？（经验分布：缺①所有权与③契约的多，
   缺④货架的少 ⚠️ 通识判断）
4. DataZone 与 Glue「两本账」在你的平台各有表头吗？只有一本=组织面未上线 ⚠️（12.5）。

## 最新演进与工业实践

2022→2026（✅ URL 200；⚠️ 转述）：

- **表格式之战收敛为 Iceberg 公约数**：AWS 各托管面以 Iceberg 为原生（✅ s3-tables、
  ✅ iceberg-tables 两页），Delta 经开源连接器可达 ⚠️（✅ delta-lake 指导页体系）；
  成书时代「三格式并立」的选型题降级为「引擎兼容性验收题」。
- **DataZone 的成人礼**：从 2022 年预览叙事到 GA 产品线 ⚠️——但工业采纳呈「治理平台
  重、中台组织变更更重」的两八开：软件只解决 12.5 的「两本账」问题，不解决 12.4 的
  组织问题 ⚠️ 通识。
- **MLOps/生成式侧翼**：SageMaker（✅ `sagemaker/latest/dg/whatis.html`）对湖表作为
  特征/语料源的直接消费面扩大 ⚠️——12.7 拼图右上新增一格，不改四契约结构。
- **工业实践**：2026 的架构评审模板（Analytics Lens ✅ + 12.7 层契约句）已把
  「你的层间契约是什么」列为必答题；答「都是托管服务所以不需要契约」的，按风险项登记 ⚠️
  （重构判断）。
