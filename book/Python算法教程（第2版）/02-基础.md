## 二、核心精讲

### 2.1 渐近记号（详见 [concepts/渐近记号与复杂度分析.md](concepts/渐近记号与复杂度分析.md)）
- `f(n) = O(g(n))`：存在 `c, n0` 使 `n>n0` 时 `f(n) <= c·g(n)`（渐近上界）。
- `f(n) = Ω(g(n))`：渐近下界；`f(n) = Θ(g(n))`：上下界同阶。
- 还有 `o`（严格小于）、`ω`（严格大于）。

### 2.2 实验验证
原书用手写计时。今天用 `timeit` 更稳：

```python
# 教学示意，不参与构建
import timeit

def linear(n: int) -> int:
    return sum(range(n))

def quadratic(n: int) -> int:
    return sum(i * j for i in range(n) for j in range(n))

if __name__ == "__main__":
    for n in (1000, 2000, 4000):
        tl = timeit.timeit(lambda: linear(n), number=100)
        tq = timeit.timeit(lambda: quadratic(n), number=10)
        print(f"n={n:4d}  O(n)={tl:.4f}  O(n^2)={tq:.4f}")
```

### 2.3 Python 内置复杂度（必记）
`list.append` 均摊 O(1)；`list.insert(0, x)` / `list.pop(0)` 为 O(n)（这也是 BFS 必须用 `deque` 的原因，见 [05-遍历.md](05-遍历.md)）；`dict`/`set` 查找/插入均摊 O(1) 且 **3.7+ 保序（PEP 520）**；`dict` 合并 `|` 为 O(n)（PEP 584，3.9+）。

## 五、近年研究与工业界前沿（2020–2026）

- 🔧 关于「均摊 vs 最坏」在现代 CPU 缓存下的实际表现，工业界多用 `pytest-benchmark` / `hyperfine` 做经验对比（非同行评审）。
- PyPy 的 JIT 使同一段 `O(n^2)` 在常数上可能优于 CPython 的 `O(n log n)` 小输入——提醒「渐近」不等于「实测快」（见 [12-加速Python.md](12-加速Python.md)）。

## 六、常见误区与本书需修正之处

- 🔧 原书称「`list` 的 `in` 是 O(n)」没错，但没强调 `set`/`dict` 的 O(1) 仅在哈希均匀时成立；恶意哈希碰撞（哈希 DoS）在 3.4+ 已用哈希随机化缓解。
- 原书未提 `sys.getsizeof` 与「对象开销」——Python 列表每个元素是指针（8 字节）+ 对象头，海量小整数应优先 `array`/`numpy`（见 [12-加速Python.md](12-加速Python.md)）。

## 七、跨语言对照

- C++ `std::vector::push_back` 也是均摊 O(1)，但内存连续；Python `list` 是指针数组，缓存局部性更差——这是「同一复杂度、不同常数」的典型例子。
