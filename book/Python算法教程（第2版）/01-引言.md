## 二、核心精讲

### 2.1 本书的边界
原书明确：读者应已会 Python，目标是在「知道语法」之上建立算法思维——如何把新问题归约到已知问题、如何分析复杂度、如何实现并评估经典算法。它不替代语言入门书（见 [`Python基础教程（第3版）`](../Python基础教程_第3版_9787115474889/00-总览与阅读地图.md)）。

### 2.2 Python 工具链（按 3.12 校准）
原书用 `python3` + 手工 `time` 计时。今天的最小可复现环境：

```python
# 教学示意，不参与构建
from __future__ import annotations
import sys, timeit

def sanity() -> None:
    print("python", sys.version_info[:3])

if __name__ == "__main__":
    sanity()
    # 微基准：timeit 比手工 time 更稳
    t = timeit.timeit("sum(range(1000))", number=10000)
    print(f"sum(range(1000)) x10000 = {t:.4f}s")
```

### 2.3 算法即程序
本书的核心立场：算法不是伪代码，而是能跑、能测、能基准对比的真实 Python。后续每章都遵循「先分析、再实现、再基准」的闭环。

## 三、版本演进

- 原书（3.3）示例依赖当时语法；今天统一用 3.12+：
  - 用 `from __future__ import annotations` 让注解不参与运行时求值（3.7+）。
  - 用 `math.inf` 表示无穷，替代原书手写的超大整数哨兵。
  - 用 f-string 输出（3.6+），原书用 `%` / `str.format`。

## 五、近年研究与工业界前沿（2020–2026）

- CPython 在 3.11（专用于帧/调用提速约 25%）、3.12（每解释器 GIL，PEP 684）、3.13–3.14（实验性 free-threading，PEP 703）持续演进，直接改变「Python 慢」这一前提（详见 [12-加速Python.md](12-加速Python.md)）。
- 算法教学领域：Jupyter + `timeit` + `cProfile` 已成标准实验范式（非同行评审，社区共识）。

## 六、常见误区与本书需修正之处

- 🔧「Python 天生慢、算法书里的 Python 代码只能教学」：在 3.11+ 与 free-threading 下，这一判断需重写；数值/并行场景用 NumPy / 无 GIL 解释器可逼近编译型性能。
- 原书把「工具链」压得很薄；今天应补 `venv` + `pytest` + `cProfile` 三件套（见总览第六节）。

## 七、跨语言对照

- 与 C++ 算法书（如 *Introduction to Algorithms* 的伪代码版）相比，本书优势是示例可直接运行；代价是隐藏了内存布局细节，需配合 [`CPython设计与实现`](../CPython设计与实现.md) 理解性能来源。
