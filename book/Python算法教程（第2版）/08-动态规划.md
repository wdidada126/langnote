## 二、核心精讲

### 8.1 记忆化（按 3.9+ 校准）
原书用字典手存中间结果；今天用 `functools.cache`：

```python
# 教学示意，不参与构建
from functools import cache

@cache
def fib(n: int) -> int:
    return n if n < 2 else fib(n - 1) + fib(n - 2)

@cache
def edit_distance(a: str, b: str) -> int:
    if not a: return len(b)
    if not b: return len(a)
    cost = 0 if a[0] == b[0] else 1
    return min(
        edit_distance(a[1:], b) + 1,
        edit_distance(a, b[1:]) + 1,
        edit_distance(a[1:], b[1:]) + cost,
    )
```

### 8.2 自底向上填表
LIS 的 O(n^2) 填表、`numpy` 可把内层向量化；背包用二维表递推。

## 三、版本演进

- 🔴 Python 3.9 起 `functools.cache` 是无参版 `lru_cache(maxsize=None)`，写纯函数记忆化首选；原书手写的 `memo` 字典可整套删除。
- 原书用列表二维表；今天可标注 `list[list[int]]`，并对数值密集场景用 `numpy` 二维数组提速。

## 六、常见误区与本书需修正之处

- 🔧 原书手写记忆化字典在函数带可变/不可哈希参数时会失效；`@cache` 要求参数可哈希（用 `tuple` 而非 `list`）。
- 🔧 递归 DP 在长序列上仍会 `RecursionError`（见 [04-归纳递归与规约.md](04-归纳递归与规约.md)）；长输入用自底向上。
- 原书未提 `@cache` 的内存膨胀（无限缓存大输入可能 OOM），生产可设 `lru_cache(maxsize=...)`。

## 七、跨语言对照

- C++ 用 `std::unordered_map`/`std::vector` 二维表；Java 用 `int[][]`；Python 用 `list[list[int]]` + `@cache`，可读性与开发速度占优，常数略逊。
