## 二、核心精讲

### 4.1 结构归纳
对递归数据结构（链表、树）用「结构归纳」：基础情形（空）成立，假设对较小结构成立则对当前成立。

### 4.2 递归（按 3.12 校准，含重要修正）
原书用普通递归。Python **没有尾调用优化（TCO）**，深递归会 `RecursionError`：

```python
# 教学示意，不参与构建
import sys
from functools import lru_cache

def fact(n: int) -> int:
    return 1 if n <= 1 else n * fact(n - 1)   # 非尾递归，n 大需 sys.setrecursionlimit

@lru_cache(maxsize=None)
def fib(n: int) -> int:                        # 记忆化递归，避免指数爆炸
    return n if n < 2 else fib(n - 1) + fib(n - 2)

if __name__ == "__main__":
    print(fact(10), fib(50))
    print("递归深度上限:", sys.getrecursionlimit())
```

### 4.3 规约
把问题 A 转换为已解问题 B。例如「求最大子数组和」规约为「前缀和 + 单次扫描」；更一般的规约见第 11 章 NP 完全性。

## 三、版本演进

- 🔴 关键修正：**Python 永不自动做尾递归优化**（Cython/mypyc 也不保证），深递归必须用「显式栈」或改写为迭代。原书未强调这点，易让读者在树/图递归里踩 `RecursionError`。
- 原书用字典记忆化；今天用 `functools.cache`/`lru_cache`（见 [08-动态规划.md](08-动态规划.md)）。
- `sys.setrecursionlimit` 调高有栈溢出风险，生产代码优先迭代。

## 五、近年研究与工业界前沿（2020–2026）

- 递归→迭代的「 trampoline」模式在异步/栈受限环境仍有用；`asyncio` 本身即事件循环替代深递归。
- 类型层面：`TypeVar`/`ParamSpec`（PEP 612）让递归泛型更可标注（参见 [`Effective Python（第2版）`](../Effective Python（第2版）/00-总览与阅读地图.md)）。

## 六、常见误区与本书需修正之处

- 🔧「递归一定慢/一定优雅」：在 CPython 下递归函数调用开销大且无 TCO，热点路径应迭代或用 `@cache` 削枝；深递归务必警惕 `RecursionError`。
- 原书示例的 `sys.setrecursionlimit(10000)` 在默认线程栈下可能段错误，生产不推荐。

## 七、跨语言对照

- 函数式语言（Scheme/Haskell）有尾递归优化，可写「尾递归 = 循环」；Python 没有，写法需调整——这是跨语言最易踩的坑。
