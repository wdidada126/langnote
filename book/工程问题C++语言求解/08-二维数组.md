## 核心概念速览（中英对照）

- **二维数组** — two-dimensional array（8.1）：`double t[20][20];` 行优先连续存储的矩阵教学模型
- **行优先存储** — row-major storage：C/C++ 固定沿第二维连续，决定循环嵌套顺序与缓存命中
- **矩阵** — matrix（8.4）：矩形数表 + 其上运算（加/乘/转置/行列式）
- **行列式** — determinant（8.4.1）：方阵的标量函数，|A|=0 ⇔ 不可逆（联立有唯一解的前提）
- **转置** — transpose（8.4.2）：行列互换 Aᵀ
- **高斯消元法** — Gaussian elimination（8.5.2）：前向消元化成上三角 + 回代，O(n³) 的线性系统直接法
- **增广矩阵** — augmented matrix（8.5 机制）：系数矩阵拼右端向量的 [A|b] 组织方式
- **联立方程的图形分析** — graphical analysis（8.5.1）：二维方程组的直线交点直觉，解存在唯一性的可视化
- **高维数组** — higher-dimensional arrays（8.7）：三维以上（本书用到温度场/体数据例子）
- **选主元** — pivoting（8.5.2 缺失环节）：消元前交换行使主元最大化的稳定性补丁

## 1. 动机：从「一批数」到「一张网」

地形高度图、电路节点方程、三维温度场——工程数据的自然维度 ≥2。本章把第 7 章的「数组+循环+函数」组合升维，并第一次把**线性代数**带进教材：8.4 矩阵运算不是数学复习，而是为 8.5 高斯消元（全书最重的一节）铺路；8.6 电路分析（基尔霍夫方程组）则是「线性系统从哪来」的答案。

## 2. 机制：三件事决定本章成败

**(a) 行优先与缓存**（8.1 隐含）：`for i { for j { a[i][j] } }` 顺存储方向、命中缓存；内外层交换后在 N 大时慢数倍。这是「内存模型直觉」的教学富矿，书未点破，读者务必自己补做实验。

**(b) 数组传参仍带维度**（8.1.3）：`void f(double a[][20], int rows)`——第二维必须是编译期常量（退化规则），这正是 `vector<vector<double>>`（8.3）流行的历史原因，也是它「每行一次堆分配、不连续」缺陷的来源。

**(c) 高斯消元的组织**（8.5.2）：

```
for k in 0..n-1:                 # 主元列
    for i in k+1..n-1:           # 消去下方
        f = a[i][k]/a[k][k]
        a[i][k..n] -= f * a[k][k..n]
回代: x[i] = (b[i] - Σ_{j>i} a[i][j]x[j]) / a[i][i]
```

**书版致命简化**：无选主元（pivoting）。若 `a[k][k]` 接近 0（甚至=0 但矩阵可逆，如 [[0,1],[1,0]]），算法直接爆炸。这是本章「最新演进」要展开的第一点。

## 3. 权衡：手消元 vs 标准库 vs 专用库

- 手消元（本书）：教学价值在于看清 O(n³) 的三重循环与主元概念。
- `std::array<std::array<double,N>,N>`（C++11）：恢复值语义、可拷贝、可比较、`size()` 可信——8.3 节 vector-of-vector 的连续性问题它也不再有。
- 生产级：**Eigen**（表达式模板、SIMD 自动向量化、完整 LU/QR/Cholesky/稀疏）、**armadillo**（MATLAB 风格 API）、LAPACK（列主元/分块，数十年打磨）。工程代码 2×2/3×3 小系统手写闭式解（伴随矩阵、Cramer 法则）反而常见——分支预测与免堆分配收益。

## 4. 🔧 自编译样例（已实测 g++ 15.2）

书式 C++98：转置/行列式/高斯消元（无选主元）：

```cpp
// 编译：g++ -std=gnu++98 ch08_old.cpp
void transpose(double a[N][N], double b[N][N]);
double det2(double a[N][N]);
bool gauss_solve(double m[N][N + 1]);   // 增广矩阵原地消元
```

实际输出（解 4x+3y=10; 6x+3y=12）：

```text
A^T = [4.000 6.000; 3.000 3.000] det=-6.000
x=1.000 y=2.000
```

C++20 重写：维度进类型 + 按值返回（RVO）+ `std::optional` 表达「奇异无解」：

```cpp
// 编译：g++ -std=gnu++20 ch08_modern.cpp
using Mat = std::array<std::array<double, N>, N>;
std::optional<std::array<double, 2>> solve(Aug m);  // 失败返回 nullopt，不出错码
if (auto sol = solve(aug); sol) std::cout << std::format("x={:.3f} y={:.3f}\n", (*sol)[0], (*sol)[1]);
```

实际输出：

```text
A^T = [[4, 6], [3, 3]] det=-6
x=1.000 y=2.000
```

## 5. 最新演进与工业实践

- **std::mdspan（C++23）**：在连续存储上建立「逻辑多维视图」——`std::mdspan<double, std::dextents<int,2>>` 统一了「行优先、零拷贝、维度运行时可变」三件事，是本书 8.1/8.7 的终极现代形态；官方提案 P0009（ISO C++ 提案页可查编号，DOI 未经核实不附）。
- **数值稳定性补课**：列主元高斯消元（partial pivoting）是 8.5.2 的必要补丁；条件数（condition number）刻画「输入扰动→解放大」，MATLAB 的 `cond`、NumPy 的 `numpy.linalg.cond`、Eigen 的 `FullPivLU`。读本书样例时永远自问：若 `a[k][k]` 是 1e-16 会怎样。
- **库生态与选型**：Eigen https://eigen.tuxfamily.org（MPL2 许可证，自 3.2 起替代旧 LGPL 路线）、armadillo https://sourceforge.net/projects/arma/ （API 最接近 MATLAB）、LAPACK/BLAS（Netlib 参考实现或 OpenBLAS/MKL 优化实现）；SciPy 的 `numpy.linalg.solve` 底层即 LAPACK——工程原型验证阶段的默认路径。
- **稀疏与大规模**：n > 10⁴ 的网格方程（地形/CFD）换迭代法（共轭梯度、多重网格）+ 稀疏格式（CSR），入口库 Eigen Sparse、Trilinos、PETSc——8.7 高维数组背后的真实工业图景。
- **SIMD/自动向量化**：编译开关 `-O3 -march=native` 下现代编译器对「j 内层连续」的消元内循环能向量化；循环顺序错误直接断送（行优先知识在 2026 年依然是性能刚需）。

## 6. 相邻概念对比与易错点

- **`double a[20][20]` vs `vector<vector<double>>` vs `std::array<std::array<>>` vs 一维拉平+宏 `IDX(i,j)`**：连续性与值语义的四方博弈；生产首选 Eigen/`mdspan+vector`。
- **转置的隐藏成本**：大矩阵原地转置是缓存不友好的经典 benchmark（Stroustrup 的 «Programming: Principles and Practice» 练习亦有涉及），分块转置（tiling）是 HPC 常识——超出本书，但值得在「相邻概念」层面知道。
- **行列式判奇异的误区**：|A|≈0 不代表「接近奇异」（缩放即改变 |A|），判断用条件数/秩——8.4.1 的教学正确、工程上误导，必须标记。

## 7. 案例深潜：工程挑战「地形导航」（8.2）与 8.6 电路分析

**地形导航的机制**：`height[i][j]` 网格上求路径坡度/可视域——两个现代回响：(a) 这就是栅格地图（DEM），A*/Dijkstra 寻路的通行代价矩阵由此而来；(b) 邻域访问模式 `t[i±1][j±1]` 是 stencil 计算的最小样本，HPC 里 9 点模板与它同构。「行优先 + 沿行扫描」在本案例里第一次产生**可测量的性能差异**。

**电路分析（8.6）**：KCL/KVL 列方程 → 系数矩阵（电导/电阻拓扑的直接翻译）→ 高斯消元。读法建议：把方程组规模推到 3×3 再跑一遍手消，亲自感受「系数接近相关」时舍入误差如何放大——8.5.2 的无选主元缺陷在电路网表里是真实事故（良态方程组被近零主元炸掉）。

**8.7 高维数组**：`temp[4][20][20]` 式体数据——现代对应物是气象/医学影像的 3D 数组与 `mdspan`/xarray 视图；注意三维以上时「哪个维度做内层循环」直接决定性能。
