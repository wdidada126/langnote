## 核心概念速览（中英对照）

- **工程问题解决流程** — engineering problem-solving process：本书贯穿全书的「陈述问题 → 输入/输出描述 → 处理/算法 → 测试 → 结果」五步法
- **算法** — algorithm：有限的、无歧义的计算步骤描述，本书从第 3 章起用伪代码表达
- **伪代码** — pseudocode：介于自然语言与代码之间的设计语言，本书问题分解工具
- **自顶向下设计** — top-down design：把大问题分解为可独立求解的子问题，对应第 6 章模块化
- **数值数据类型** — numeric data type：int/double 等在计算机中的有限精度表示，为第 2 章的上溢/下溢埋伏笔
- **历史回顾** — historical review（1.1）：从算筹、ENIAC 到高级语言的计算史叙事线

## 1. 动机：工程师为什么需要一门「方法论」先于语法

普通 C++ 教材第 1 章讲「计算机是什么、程序是什么」，本书第 1 章的差异化定位是：把**工程问题的求解流程**当作正文主角，语法只是流程的执行载体。作者 Etter 是工程教育研究者（其「五步法」源自她早期著作 *Programming Techniques for Scientists and Engineers*），所以第 1 章实际给全书定了调：后面每一章都围绕一个「工程挑战」（第 2 章汽车性能、第 7 章海啸预警系统……）走一遍完整流程。

对读者的直接收益：读到任何一章都能回答「这段代码解决工程问题的哪一步」。

## 2. 机制：五步法在后续章节的落点

| 五步法的步骤 | 本书落点（已核实章节） |
|---|---|
| 1. 陈述问题（Problem Statement） | 每章章首「工程挑战」框 |
| 2. 输入/输出描述（I/O Description） | 第 2 章变量与 I/O、第 5 章数据文件 |
| 3. 数学公式/数据组织 | 第 3.5 节线性插值、第 7.3 统计表征数、第 8.4 矩阵 |
| 4. 算法（伪代码→代码） | 第 3–4 章控制结构、第 7.5 排序/搜索、第 10.4 递归 |
| 5. 测试与验证 | 各章「解决应用问题」小节 + 章末习题 |

这套结构是「机制」层面最值得学的部分——它比任何具体语法都长寿。

## 3. 权衡：工程教材 vs 计算机教材的第一分岔

- **工程视角**（本书）：正确性来自「与物理量纲对照 + 边界值测试」，性能与抽象层级是次要矛盾；所以第 2 章就引入类（object-based），第 9 章才补指针。
- **CS 视角**（如 C++ Primer）：正确性来自类型系统与语言规则，先讲语言再讲应用。
- 权衡结果：本书上手快、能立刻算东西，但语言模型深度止步于「用类封装数据」，第 10 章的高级主题（模板/继承/虚函数）只有一章的容量。这决定了它 2026 年的读法：**当问题解决框架书读，别当语言参考书读**。

## 4. 🔧 自编译样例（已实测 g++ 15.2）

书式 C++98 五步法演示（速率计算，2.8 节同款问题前置）：

```cpp
// 编译：g++ -std=gnu++98 ch01_old.cpp
const char* FORMULA = "rate = (d1+d2)/(t1+t2)";
double d1 = 2000.0, d2 = 3500.0;
double t1 = 2.5,   t2 = 4.1;
double rate = (d1 + d2) / (t1 + t2);   // STEP 4: 算法
cout << "Average rate = " << fixed << setprecision(3) << rate << " m/s" << endl;
```

实际输出：

```text
rate = (d1+d2)/(t1+t2)
Average rate = 833.333 m/s
Sanity: 0 < rate < max(d/t)? yes
```

同一问题在 C++20 下的现代写法：把「公式」做成 `constexpr` 纯函数，测试左移到编译期：

```cpp
// 编译：g++ -std=gnu++20 ch01_modern.cpp
constexpr double avg_rate(Leg a, Leg b) {
    return (a.dist + b.dist) / (a.time + b.time);
}
static_assert(avg_rate({100, 1}, {100, 1}) == 100.0);  // 第 5 步"测试"进编译期
int main() {
    std::cout << std::format("Average rate = {:.3f} m/s\n",
                             avg_rate({2000, 2.5}, {3500, 4.1}));
}
```

实际输出：

```text
Average rate = 833.333 m/s
```

## 5. 最新演进与工业实践

- **计算思维（Computational Thinking）**已成为与五步法同源的现代叙事：周以真 2006 年的Communications of the ACM 阐述文章是该概念的出处（未能经 ACM DL 核实 DOI，此处不附，⚠️）；今天各工程的「问题分解→模式识别→抽象→算法」四步与本书五步法几乎一一对应。
- **工程计算选型**：五步法的第 3、4 步今天多数 prototypes 用 Python/NumPy + SciPy（生态里插值/拟合/线性代数全有 `scipy.interpolate`、`numpy.linalg`），C++ 用于部署期性能与嵌入式约束。Jupyter 笔记本是「输入/输出描述+测试」的现代载体。
- **验证手段演进**：本书第 5 步靠手算对照；现代工程实践补充了 Catch2/GoogleTest 单测、CI 数值回归（对照基线解）、以及针对浮点的 interval arithmetic（如 Boost.Interval）。
- **Eigen**（https://eigen.tuxfamily.org）、**GSL**（https://www.gnu.org/software/gsl/）等开源数值库承接了本书第 3.5/6.9/6.11/8.5 各「数值方法」小节的生产级实现。
- 工具链注记：以上样例在 x64 Windows + MinGW g++ 15.2 实测；`-std=gnu++98` 可完整编译本书风格代码，这正是本书语言基线（ANSI C++/C++98）至今可移植性的证据。

## 6. 相邻概念对比与易错点

- **五步法 vs 迭代开发**：五步法是「一次走通、局部回填」的瀑布式，与真实工程「原型→修改」的迭代有张力；本书用大量小节（*5.6、*6.9 带星号选学）缓解，但读者应自觉补上「先跑通再改好」的习惯。
- **伪代码 vs 统一建模**：伪代码只到第 7 章前有效；数据规模变大后应直接跳到标准库容器语义（第 9.8 节）而非继续手绘流程。

## 7. 案例深潜：用五步法走一遍「汽车油耗」

本章没有独立工程挑战（已核实），但从第 2 章起每章都有；提前用「汽车性能」的骨架演示五步法，方便后文每章对照：

| 步骤 | 本例内容 | 常见事故 |
|---|---|---|
| 1 陈述问题 | 已知三次加油的里程差与油量，求平均油耗 | 把「市区/高速混合」的口径问题当数学问题 |
| 2 I/O 描述 | 输入：`d0..d3`（里程表读数）、`f1..f3`（升）；输出：L/100km 与 mpg | 单位不统一（加仑 vs 升） |
| 3 公式 | `L/100km = Σf / Σd × 100`；`mpg = (Σd/1.609) / (Σf×0.2642)` | 换算系数硬编码进表达式 |
| 4 算法 | 顺序累加即可；若油量逐次录入则一个计数循环 | 过早引入复杂度 |
| 5 测试 | 用「10L/100km ≈ 23.5mpg」的双向一致性自校验 | 只测理想值不测 0 里程/除零 |

五步法的关键纪律：**第 1、2 步不许碰键盘写代码**——这正是本书与前序 CS 教材最大的手感差异。
