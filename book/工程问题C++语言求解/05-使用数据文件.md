## 核心概念速览（中英对照）

- **文件流** — file stream（5.1）：`ifstream`/`ofstream`，把磁盘文件接进 iostream 体系
- **流的类层次** — stream class hierarchy（5.1.1）：`ios_base → ios → istream/ostream → ifstream/ofstream` 的继承树（第 10 章继承的先导案例）
- **eofbit / failbit / badbit** — stream state flags（5.2.2/5.5）：三种失败原因分开记录，`good()` 只查全绿
- **记录数约定** — specified number of records（5.2.1）：先读计数再读数据的自描述文件格式
- **标志信号** — flag signal（5.2.2）：用特殊值或状态标志驱动读循环
- **数据过滤器** — data filter（5.4）：读入→按规则改写→写出，本章的「实战项目」原型（HTML 修改）
- **线性建模** — linear modeling（5.6）：由数据点拟合直线并外推，最小二乘的入门版（数值方法支线第二级）
- **ASCII 文件** — ASCII file：文本模式文件，对应附录 C「MATLAB 从 ASCII 文件绘图」的桥梁格式

## 1. 动机：工程计算的输入输出从来不在键盘上

传感器、气象站、臭氧探针产生的是**文件**。本章把第 4 章的「数据终止循环」接到真实载体上，同时引入两个终身上位概念：(a) 流的**状态模型**——读失败不抛异常而是置标志位；(b) 文本/二进制数据格式的**契约**——记录数、字段序、终止符。5.4 的 HTML 数据过滤器更是第一次让读者写「会改写别人数据」的程序。

## 2. 机制：一次完整的文件读循环

```cpp
ifstream in("ozone.dat");
if (!in) { cerr << "cannot open" << endl; return 1; }   // 5.5 打开即检查
while (in >> day >> ppb) { ... }                         // 5.2.3 流作条件
// 循环退出后：in.eof() 与 in.fail() 告诉你死因
```

机制核心：`operator void*`/`explicit operator bool`（C++11 后为后者）返回 `!fail()`；提取运算在遇到 eof/格式错时**先失败再置位**，所以 eofbit 是滞后的——它总在一次「多余」的尝试之后出现。本笔记 ch05_old 实测证实：读完最后一条有效记录（0.47）时循环内 `in.eof()` 仍为 false，直到下一次提取失败才 yes/yes。

**状态查询的三种姿势**（5.5 的现代表述）：
1. 循环内防御：`if (!in) break;` 后查 `in.eof()` 区分「正常耗尽」与「格式坏数据」；
2. 读完后裁决：`in.eof()` 可原谅，`in.fail()/bad()` 必须报告；
3. C++ 风格异常：`in.exceptions(std::ifstream::failbit | std::ifstream::badbit)` 让流失败抛 `std::ios_base::failure`——本书完全不讲，但它是现代错误处理的主流之一（对应《现代C++实战30讲》第 5 讲的错误处理现代化讨论）。

## 3. 权衡：文本 vs 二进制；标志位 vs 异常

- **文本（ASCII）**：可读、可手改、跨平台（配合附录 C 还能喂给 MATLAB）；代价是格式化/解析开销与精度往返损失（double 文本化再读回可能差 1 ULP；`std::to_chars/from_chars` 才是精确往返的正解）。
- **二进制**：`ios::binary` + `read/write` 精确保存浮点位型，工程存档应选它；本书教学全选文本。
- **标志位**：C++98 流 API 的默认错误模式，适合「坏一行跳一行」的数据清洗；**异常**适合「读不出来就中止」的配置加载。工业代码两种都有，原则是**在构造后、首次使用前检查**。
- 5.4「修改 HTML 文件」暗含的输出安全问题今天升级为 OWASP 的注入防护：转义（escaping）与内容策略（CSP），本书只处理到「替换标签」的深度。

## 4. 🔧 自编译样例（已实测 g++ 15.2）

书式 C++98（写→关→读→查标志）：

```cpp
// 编译：g++ -std=gnu++98 ch05_old.cpp
while (in >> day >> ppb) { sum += ppb; ++n; if (in.eof()) cout << "(eof reached)" << endl; }
cout << "failbit? " << (in.fail() ? "yes" : "no") << " eofbit? " << (in.eof() ? "yes" : "no") << endl;
```

实际输出：

```text
records=5 mean=0.410
failbit? yes eofbit? yes
```

（注意：循环体内从未打印 "(eof reached)"——eofbit 在最后一次成功提取时仍是关的，它是被第 6 次失败的尝试置位的。这就是 5.2.3 「为什么不能 while(!eof())」的全部答案。）

同一任务的 C++20 写法：`<filesystem>` 查存在/大小 + RAII 作用域关文件 + `istream_iterator` 收集：

```cpp
// 编译：g++ -std=gnu++20 ch05_modern.cpp
{ std::ofstream out("ozone2.dat"); out << std::format("{} {:.2f}\n", i + 1, data[i]); } // 作用域结束自动 close
std::cout << std::format("exists={} size={}\n", fs::exists("ozone2.dat"), fs::file_size("ozone2.dat"));
std::vector<std::string> tokens(std::istream_iterator<std::string>{in}, {});
```

实际输出：

```text
exists=true size=40
tokens=10
mean=0.410
```

实测踩坑记录（真实工业经验）：Windows 上 `fs::remove` 一个仍被 `ifstream` 占用的文件会抛 `filesystem_error`（"另一个程序正在使用此文件"）——必须先 `in.close()`；Linux 则允许。跨平台代码里文件生命周期要按 Windows 的严格语义写。

## 5. 最新演进与工业实践

- **std::filesystem（C++17）**：路径拼接、存在性、大小、遍历目录全标准化，替代本书时代手搓的探测技巧；<filesystem> 在 GCC-8 前需 `-lstdc++fs`，属历史脚注。
- **std::format（C++20）**：写出格式化数据不再操纵符串状态（样例已示）。
- **二进制/归档格式的工业现状**：HDF5/NetCDF（气象学与海洋学——正好是本书「天气预报/臭氧」案例的现代直系后代）、Parquet/Arrow（列式数据）、以及 CSV 上的 `rapidcsv`/`csv2`。文本交换一律 UTF-8，行尾 `\n` 统一由工具链（git autocrlf/editorconfig）管理。
- **读整文件的现代惯用法**：`std::ifstream f(path, std::ios::in | std::ios::binary); std::string buf(std::filesystem::file_size(path), '\0'); f.read(buf.data(), buf.size());` 或 C++23 `std::expected` 包装「打不开」。
- **附录 C（MATLAB 绘图）**今天可由 matplotlib/plotly 直接吃 CSV 完成；「ASCII 文件作跨语言总线」的架构思想仍然成立。
- 参考文档：流状态标志的权威语义见 https://en.cppreference.com/w/cpp/io/basic_ios.rdstate （在线核实，2026）。

## 6. 相邻概念对比与易错点

- **`in >> x` vs `getline(in, s)`**：混用时行尾残留 `\n` 会让 getline 读到空行——先 `in.ignore()` 清行。
- **打开失败 ≠ 读到一半失败**：前者查 `is_open()/bool`，后者查状态标志；本书 5.5 的错误检查清单值得照抄进自己的 code review 清单。
- **相对路径依赖工作目录**：IDE 里「能跑，命令行不能跑」的头号原因；现代解法：`std::filesystem::current_path()` 显式化或资源路径注入配置。

## 7. 案例深潜：工程挑战「天气预报」与 5.4 数据过滤器（HTML）

**数据过滤器的管线模型**：`ifstream 输入 → 逐条规则改写 → ofstream 输出`，中间规则以「匹配→替换」表驱动。本章它用来给 HTML 文件批量加标签/改属性；抽象出来就是今天的 linter/代码生成器/ETL 单条流水线。两个工程注脚：

1. **原地修改是危险动作**——正确姿势永远是「写临时文件 + 原子重命名」（`std::filesystem::rename`，POSIX 原子）；书的时代用「另存新文件」土办法，思想一致。
2. **HTML 是注入面**——生成的标签内容若混入用户数据而未转义，就是存储型 XSS。现代等价物：Python `html.escape`、C++ 手写 `&→&amp;` 五件套、以及 Content-Security-Policy 兜底。这是「输出即攻击面」的最早一课。

**天气预报（工挑）/臭氧测量（5.7）**：观测站定时上传 ASCII 记录 → 程序端计数/均值/越阈告警——完整闭环把 4.5 的数据终止循环第一次接上真实文件。5.6 线性建模（选学）用臭氧数据拟合趋势线，是「数值方法支线」从插值（会算）到拟合（会猜）的升级。
