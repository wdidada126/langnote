## 核心概念速览（中英对照）

- **泛型编程** — generic programming（10.1）：以类型为参数写算法，类模板是其本书级载体
- **数据抽象** — data abstraction（10.2）：自定义类型 + 隐藏表示 + 受控接口（Pixel 案例）
- **操作符重载** — operator overloading（10.2.1/10.2.3）：给自定义类型赋予 `+ - <<` 等语法
- **友元函数** — friend function（10.2.4）：授权非成员函数访问私有数据，`operator<<` 的古典落点
- **验证对象** — validating objects（10.2.5）：构造/修改方法里检查数据合法性
- **递归** — recursion（10.4）：函数自调用；阶乘/斐波那契/二叉树三例覆盖线性与树形递归
- **类模板** — class template（10.5）：`template<class T> class Stack`，编译期按类型生成代码
- **继承** — inheritance（10.6）：Rectangle→Square→（类比）Cube 的 is-a 层级
- **虚方法 / 运行时多态** — virtual method / runtime polymorphism（10.7）：基类指针 + vtable 分派
- **可重复囚徒困境** — iterated prisoner's dilemma（10.8）：以策略类层次演示多态的综合案例

## 1. 动机：一章装下「现代 C++ 的三个入口」

本章是全书的收口：泛型（→模板/STL）、抽象（→类设计）、继承与多态（→OOP），外加递归（→算法思维）。容量只有一章，深度必然克制——它给的是**正确的路标**而非纵深。本笔记把它当三本专著的目录页来读：对象布局看 Lippman，容器实现看侯捷，类设计看 McGregor。

## 2. 机制：四条知识线的最小模型

**(a) 类与操作符**：Pixel 持 r/g/b 私有 + 友元 `operator<<`。机制要点：成员 `operator+` 的隐式左操作数、友元的「特权非成员」身份、返回 `ostream&` 以支持链式 `cout << a << b`。C++20 起成员 `operator<<` 甚至可行，而 `std::format` 让「格式化」彻底外接化（见样例）。

**(b) 递归与摊还成本**：阶乘→尾递归可迭代化；斐波那契指数爆炸→备忘录/迭代；BinaryTree 类（10.4.3）用 9.7 的节点指针重组为递归结构，插入/遍历天然递归。**本书没讲「递归深度→栈溢出」**，是必补的坑（10.4 之后所有递归实现都要问最大深度）。

**(c) 类模板**：Stack<T> 一份代码多类型实例化——「泛型=编译期代码生成」的最小样本；与 9.8 的标准容器衔接：为什么工程用 `std::stack` 而不是书里的 `items[8]` 定长数组（越界 UB！）。

**(d) 继承与虚方法**：`Shape* p = new Square(3); p->area();`——静态类型与动态类型分离，编译器改经 vtable 间接调用。Rectangle/Square/Cube 链条同时埋着著名的设计缺陷（见权衡）。

## 3. 权衡：Square 继承 Rectangle 是错的吗？——是的，且这是最好的教训

10.6 的 Square is-a Rectangle 在「面积计算」语境无害，但一旦 Rectangle 提供 `set_w/set_h`，Square 继承后「改宽不改高」破坏方形不变式——**LSP（里氏替换原则）**的标准反例，Barbara Liskov 1994 年 OPCDATA 技术报告提出（报告无 DOI，按标题核实）。现代结论：几何类型用公共基类/概念/组合，而不是让 Square 冒充 Rectangle 的可写版本。本书案例选型的这个暗雷，恰是它给读者的最好礼物。

**多态 vs 值语义**：虚函数=堆分配+指针+动态分派；`std::variant/visit`（C++17）给封闭类型集带来值语义+编译期分派（开集/闭集对偶）；策略模式可用模板参数静态化（CRTP）。囚徒困境策略集是**封闭小集合**，现代首选 variant。

## 4. 🔧 自编译样例（已实测 g++ 15.2）

书式 C++98：Pixel+friend、类模板 Stack、抽象基类+虚方法：

```cpp
// 编译：g++ -std=gnu++98 ch10_old.cpp
Pixel operator+(const Pixel& o) const;
friend ostream& operator<<(ostream& os, const Pixel& p);
template <class T> class Stack { T items[8]; ... };   // 定长隐患保留原样
class Shape { public: virtual double area() const = 0; };  // 纯虚=抽象基类
Shape* s = new Square(3);
```

实际输出：

```text
(10,20,30) + (5,5,5) = (15,25,35)
stack pop=9 then 7
square area=9.00
```

C++20 重写：`concepts` 约束模板、`std::formatter` 特化替代友元流重载、`override/final`、`unique_ptr` 管理多态对象：

```cpp
// 编译：g++ -std=gnu++20 ch10_modern.cpp
template<typename T> concept Stackable = std::copyable<T>;
template<Stackable T> class Stack { std::vector<T> v; ... };
double area() const override;            // 签名写错=编译错误
struct Square final : Rectangle { ... }; // 终结继承链
shapes.push_back(std::make_unique<Square>(3));
```

实际输出：

```text
(10,20,30) + (5,5,5) = (15,25,35)
pop=9 size=2
total area=19.00 pi=3.141593
```

实测注脚：`std::vector<std::unique_ptr<Shape>> shapes{ make_unique... , make_unique... };` 写法**编译失败**——initializer_list 会复制 unique_ptr。这个报错本身就是「独占所有权不可复制」教义最好的活教材。

## 5. 最新演进与工业实践

- **概念（C++20）**替代 SFINAE 约束（EMC 时代技法）：数值算法（第 8 章消元、第 6 章求根）今天应写成 `template<std::floating_point T>`；std 还提供 50+ 标准概念于 `<concepts>`。
- **三路比较（C++20）**：`auto operator<=>(const Pixel&) const = default;` 一行生成六个关系运算——本书 10.2 手定义操作符的动机大半消失。
- **协程（C++20）与递归**：深层递归的现代替代（迭代器化/协程化栈）在解析器与树遍历（10.4.3）中已是常规武器。
- **格式化**：`std::formatter` 特化（样例已示）取代「friend ostream<<」——数据类保持无 IO 依赖，序列化边界外置；这也是 Boost.JSON/nlohmann::json 的 ADL `to_json/from_json` 设计哲学。
- **对象模型底层**：vptr/vtable、虚继承菱形布局、构造期虚调用不解多态——本书 10.6/10.7 全部机制的机器真相在 Lippman 书中，务必配读（见延伸）。
- **经典文献**：Liskov 1994 *Behaviors Subtypes Beating a Subtyping*（OPDATA-TR-93-1，无 DOI，标题可检索）；Stroustrup 关于模板与多态取舍的论文未在此展开。
- **游戏/AI 策略的工业实践**：10.8 囚徒困境策略集的现代类比是行为树/状态机 + `std::function`/variant 策略注入；ML 部署侧则早已是 Python 训练 + C++（ONNX Runtime）推理的分工。

## 6. 相邻概念对比与易错点

- **友元：用还是不用**：仅两类正当场景——对称二元操作符与 `operator<<` 类外格式化（后者 C++20 起可被 formatter 取代）；「为了测试开友元」应改用 public 接缝。
- **模板 instantiate 失败信息**：无 concepts 时报错深埋栈中——本书 10.5 的 Stack<char> 照样能编译出灾难，因为 `T items[8]` 无边界检查（C++20 `.at()`/gsl::span）。
- **析构虚函数规则**：经基类指针 delete 而析构非 virtual = UB；书样例在 Shape 加了 `virtual ~Shape()`，这个细节读者必须内化（EMC Item 7）。
- **递归 vs 迭代成本**：尾递归（阶乘）编译器常优化；二叉树遍历在生产环境一律显式栈或 Morris——10.4 没告诉你「栈溢出也是工程事故」。

## 7. 案例深潜：工程挑战「人工智能」与 10.8 可重复囚徒困境

**10.8 的机制解剖**：策略类层次——`class Strategy { virtual move decide(...) }` 派生出 TFT（以牙还牙）、ALLD（总是背叛）、ALT（交替）等；仿真循环每回合抽两个策略对局、累计得分。这其实是**策略模式**的教材原型：算法族 + 运行时替换。三个现代追问：

1. 策略集合封闭（就 4–5 种）→ `std::variant<TFT, ALLD, ALT, ...>` + `std::visit` 更优：无堆分配、无 vtable 间接、加新策略会触发编译器「漏分支」告警（虚函数版不会）。
2. 仿真要可复现：策略内部若含随机（混合策略），必须注入 RNG 而非各自 `srand`——呼应 6.5 的 `<random>` 迁移。
3. 「AI」标题在今天名不副实：这是博弈论/多智能体最小样本；现代对应物从 AlphaGo 的蒙特卡洛树搜索到 RL 环境接口（gym 风格），但「策略=可替换决策单元」的抽象一脉相承。

**10.3 彩色图像处理**：Pixel 类 + 二维数组（8 章）+ 操作符重载的合奏——卷积核用 `operator*` 写起来几乎就是数学式；现代生产是 Eigen 张量/OpenCV，但「先给像素一个类型」的抽象动作不变。
