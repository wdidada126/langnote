## 核心概念速览（中英对照）

- **地址操作符** — address operator（9.1.1）：`&x` 取对象内存地址
- **解引用操作符** — dereference operator（9.1）：`*p` 访问指针所指对象
- **指针算术** — pointer arithmetic（9.1.3）：`p+1` 前进一个 `sizeof(T)`，与下标 `a[i] ≡ *(a+i)` 等价
- **动态内存分配** — dynamic memory allocation（9.4）：`new T`/`new T[n]` 运行期在自由store申请
- **自由存储 / 堆** — free store / heap：new 的分配域，与栈（自动存储）相对
- **悬挂指针** — dangling pointer（9.6）：delete 后仍指向已释放内存的指针
- **内存泄漏** — memory leak（9.6）：失去全部指针指向的动态内存再也无法释放
- **链表** — linked list（9.7.1）：节点+next 指针的动态序列，插入/删除 O(1)（已知位置）
- **栈 / 队列** — stack / queue（9.7.2/9.7.3）：LIFO/FIFO 抽象数据类型，本书用链表手造、9.8 用标准库接管
- **STL** — Standard Template Library（9.8）：`std::list/stack/queue` 所代表的容器/算法/迭代器体系入门窗口

## 1. 动机：为什么把指针压到第 9 章

多数教材第 5、6 章就讲指针，Etter 的选择是：**先在值语义世界里把问题解决能力建立起来，再打开底层**。到第 9 章时读者已经理解数组、函数、类，指针立刻有了用武之地——运行时大小的地震波数据（9.5）、链接出的文本索引（9.9）。这条「晚学但马上实战」的路线对工程师非常友好，对准备面试/读底层代码的人则意味着必须自己加深。

## 2. 机制：三层递进

**(a) 指针即地址 + 类型**。`double*` 与 `int*` 存的是同类数字，但 `+1` 的步长不同——类型是给算术用的。数组名在表达式里退化为指向首元素的指针（9.2），于是 `*(a+i)==a[i]` 不再是巧合而是定义。

**(b) 手动生命周期**。栈对象随作用域生灭；`new` 出生的对象**一直活着直到 `delete`**。9.6 的错误清单就是这条规则的反面教材清单：

| 错误 | 后果 | 现代解法 |
|---|---|---|
| 忘记 delete | 泄漏 | `vector`/`unique_ptr` |
| delete 后继续用 | 悬挂指针/UB | 同上 + ASan |
| delete 两次 | UB | 所有权类型系统 |
| `new T[]` 配 `delete`（不带[]） | UB（只析构首元素） | `std::array/vector` |
| 浅拷贝含指针的类 | double free | Rule of 0/3/5 |

**(c) 链式结构**。9.7 手造链表→栈→队列，是「用指针表达递归数据结构」的最小样本；紧接着 9.8 宣布：这一切标准库已有（`std::list/stack/queue`），自己写的唯一理由是学习。

## 3. 权衡：指针章节的长期争议

- **性能直觉**：链表「插入快」的说法要加前提——只有已持有迭代器且 n 大、又确实需要 O(1) 中间插入才划算；线性扫描时 `vector` 因连续内存+预取几乎总是更快（缓存墙时代「好布局 > 好复杂度」）。本书成书年代的教学口径未反映这一点。
- **所有权表达**：裸指针不表达所有权（C++ Core Guidelines I.11/F.7），本书时代没有 `unique_ptr/shared_ptr`，这是全书与现代工程脱节最严重的一章——恰因此它最值得一读：知道问题原始形状，才懂智能指针好在哪。

## 4. 🔧 自编译样例（已实测 g++ 15.2）

书式 C++98：指针算术 + new[]/delete[] + 手工链表：

```cpp
// 编译：g++ -std=gnu++98 ch09_old.cpp
double* arr = new double[n];
for (double* q = arr; q != arr + n; ++q) s += *q;   // 指针遍历
delete[] arr;
Node* head = 0;
for (int i = 3; i >= 1; --i) head = new Node(i * i, head);   // 头插建表
while (cur) { Node* t = cur; cur = cur->next; delete t; }    // 手工逐节释放
```

实际输出：

```text
x=3.5 *p=3.5
sum=11.0
1.0 4.0 9.0 
```

C++20 重写：vector/make_unique/forward_list——全程不出现 new/delete：

```cpp
// 编译：g++ -std=gnu++20 ch09_modern.cpp
std::vector<double> arr(5);                    // RAII 动态数组
auto owner = std::make_unique<std::vector<int>>(std::vector<int>{1, 4, 9});
std::forward_list<int> lst;                    // 标准库单向链表
for (int i = 1; i <= 3; ++i) lst.push_front(i * i);
```

实际输出：

```text
x=3.5 *p=3.5
sum=11.0 cap=5
owned size=3
9 4 1 
```

对照结论：现代版把 9.6「常见错误」整节从**语法问题**降维成**类型问题**——资源管理交给 RAII 后，错误类别（泄漏/双释放/算术错）在编译期即被封死。

## 5. 最新演进与工业实践

- **智能指针三件套（C++11）**：`unique_ptr`（独占，零开销，make_unique 防异常窗）、`shared_ptr`（引用计数，控制块线程安全但对象访问不保证）、`weak_ptr`（破环）。工程口径：**新代码里出现裸 `new/delete` 即评审红旗**（EMC Items 18–22、Core Guidelines R 系列）。
- **std::expected 与错误路径**（C++23）：分配失败现代不用 `nothrow new`，让 `vector` 抛 `bad_alloc` 或用内存池；本书 9.4 的 `if (p == 0)` 检查已是历史。
- **内存池/分配器**：高频小对象场景（9.7 节点）用 arena/pool——abseil 的 Allocator/`Slab`、`std::pmr`（C++17 多态分配器，`monotonic_buffer_resource` 即「只增不还」池，正对本书地震数据「申请→整批丢弃」的模式）。
- **验证工具**：AddressSanitizer（-fsanitize=address）是 9.6 全部错误的现代猎犬，CI 标配；Valgrind 在 Linux 仍是存量选择。
- **Rust 参照系**：所有权/借用系统在语言层解决了本章整节的纪律问题，这也是近年「用工程规范约束指针」讨论的对照组；转读 [../C++并发编程实战2/00-总览与阅读地图.md](../C++并发编程实战2/00-总览与阅读地图.md) 可见 C++ 内存模型侧的同一焦虑。
- **文档**：cppreference new/delete 页与 GSL 指南（https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#S-memory）是在线核实的权威口径。

## 6. 相邻概念对比与易错点

- **指针 vs 引用**：引用=永远有效、不可重绑的别名（接口首选）；指针=可空可算术（底层结构与旧 API 领域保留）。9.2.3 「指针作函数参数」在现代签名里大多改写为引用/span/迭代器。
- **`list` vs `vector`**（9.8.1 的选型）：除「迭代器失效语义不同」「O(1) splice」外，默认 vector——这条现代经验书里未给足。
- **栈队列的标准库门面**：`std::stack/queue` 是**容器适配器**（默认底层 deque），不是容器——面试常考，也是 10.1「泛型」的预告。

## 7. 案例深潜：工程挑战「天气模式」、9.3 ENSO 数据与 9.9 文本索引

**9.3 厄尔尼诺南方涛动（ENSO）**：海平面气压/海温异常序列按事件窗口动态截取——`new double[m]` 的第一个正当用例：窗口长度运行时才知道。现代等价：`vector` 切片 / `std::span` 子视图（零拷贝，且没有「谁负责 delete」的问题）。

**9.9 文本文件的索引**：词 → 出现位置列表——**倒排索引**的最小教学样本（搜索引擎的数据结构祖型）。书用「struct WordEntry + Node* 链表」手写；现代 5 行等价物：

```cpp
std::unordered_map<std::string, std::vector<std::size_t>> index;
for (std::size_t pos = 0; std::string w; in >> w) index[w].push_back(pos);
```

这个对照值得展开讲：手制版练的是指针纪律（9.6 错误清单全部命中），标准库版是生产唯一选项——两版都写一遍、各自 ASan 跑一遍，本章就算读值了。

**天气模式（工挑）**：第 8 章温度网格 + 本章动态尺寸（分辨率可变）+ 9.7 队列（逐日推进的调度）——前三章数据的「模式化」汇总。
