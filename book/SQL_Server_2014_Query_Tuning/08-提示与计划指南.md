## 8.1 提示分类总表（⚠️ 转述+官方页对读）

| 族 | 成员 | 作用半径 | 典型调优用途 | 主要风险 |
|---|---|---|---|---|
| 连接提示 | INNER/LEFT/RIGHT/FULL OUTER + LOOP/HASH/MERGE + {LEFT|RIGHT}_OUTER_JOIN_HINT | 单连接 | 固化算法救火、验证成本假设 | 剥夺自适应；数据漂移后烂死 |
| 表访问提示 | INDEX(...)、FORCESEEK[(列组)]、FORCESCAN、KEEPIDENTITY 等 | 单表引用 | 探索 Seek 键序、排除坏索引 | INDEX(0) 类「全禁索引」=扫描自残写法 |
| 查询级 OPTION | RECOMPILE、MAXDOP、HASH/MERGE UNION INTERSECTION EXCEPT JOIN、OPTIMIZE FOR、FAST n、USE PLAN、ROBUST、DISABLE_BATCH_MODE... | 整条语句 | 并行/授予/算法全家桶微调 | 组合爆炸，难审计 |
| 语义型 | NOEXPAND（视图/CTE）、KEEPFIXED PLAN（旧式表提示） | 对象 | 阻止展开以稳定计划 | 掩盖真正病因 |
| 旧时代残留 | READPAST/HOLDLOCK 族（并发语义，11 章归口）、UPDLOCK | 并发 | 队列模式 | 被误当性能提示 |
- 官方立场（✅ 文档原意转述）：提示「覆盖优化器决策」，仅在**其它手段验证无效后**、由**了解查询与数据者**施加——本章把这句话钉在墙上。
- 2014 语境要点：`OPTIMIZE FOR`/RECOMPILE 属 07 章处方，MAXDOP 提示配资源治理（12），`USE PLAN N'...'` 只作应急（8.3 详述其脆）。

## 8.2 提示的工程纪律（处方外的药柜管理）

1. **登记制**：每个生产提示记录：语句指纹（query_hash）、原因、施加日期、复审日期——「考古安全网」；工业上以表/仓库承载。
2. **验证对**：提示前后跑同一参数矩阵（07 §7.6 配方），留下计划与 P95 对比。
3. **熔断**：随版本/兼容级升级**全量重评**（重编译会尊重提示但代价假设已换代），提示是跨版本升级的头号「遗产债务」。
4. 提示不进 ORM 生成物：应用层拼接提示=把 DBA 决策塞进发版车；通道应在数据库侧（指南/视图）而非文本侧 ⚠️ 实践主张。

## 8.3 计划指南（Plan Guide）：冻结整棵计划树 ⚠️ 转述

- 三型：DATABASE/TEMPLATE/OBJECT 级；从缓存提取计划 XML 作 `@plan`，或仅指定优化模板与参数。
- 语义=「模板匹配的计划强制替换」，比提示更重：绑定的是**整个计划形态**，任何 schema/索引变动即失效（GUID 状态 `sys.plan_guides.is_enabled` 巡检）。
- USE PLAN 提示与指南同源；官方明示其脆弱（内部表示非公开契约 ✅ hints 页注记转述）：2014→现代升级剧本里「先解绑 USE PLAN 再谈兼容」。
- 适用白名单：供应商不可改 SQL 的黑盒应用、救火窗口、升级陪跑对照实验；其余场景 07/05 处方优先。
- 审计通道：`sys.fn_stmt_sql_handle_from_sql_plan` 反查、sp_create_plan_guide 的 REQUIRED_DB_SETTINGS 列表（ANSI 选项钉死，呼应 07 复用谓词）。

## 8.4 「先证明优化器错了」流程（本章方法论主件）

1. 记录现场：参数值、统计时间戳、兼容级、缓存内计划 XML。
2. 单变量实验：`OPTION (RECOMPILE)`（排除嗅探）→ `OPTIMIZE FOR UNKNOWN`（看密度基线）→ 逐提示（LOOP/HASH/MERGE、FORCESEEK）跑参数矩阵。
3. 归因四分：统计过期 / CE 模型差 / 索引缺失（09）/ 写法塌方（06）——**提示只应出现在归因结论之后**。
4. 结案文书：若最终采用提示/指南，写进 8.2 登记制并设复审；若改写可行，撤提示留改写。
- 🔬 对照组技巧：临时复制库改统计/索引做 A/B，生产零风险（基线纪律见 12）。

## 8.5 🔧 本机类比：提示=剥夺选择的最小演示（非本书引擎行为）

SQLite 3.45.3 的交叉类比物是索引提示变体：
```
SELECT ... FROM orders WHERE cust=1234 AND status='A'      → 自动 COVERING INDEX SEARCH
同句写 WHERE ... AND +0 BETWEEN 0 AND 0 等无害包裹不坏；
但把列包进函数（06 §6.6 写法 B）→ 退化残余过滤
——SQLite 没有 FORCE INDEX：优化器**拒绝被提示**，这恰好演示了「提示是打破默认最优
   选择的权力干预」这一概念本体；DuckDB 1.5.5 同理（无 per-query 索引提示，PRAGMA 级开关粗粒度）。
```
教学落点：在「无提示可用」的引擎上先理解默认选择为何正确，再回 SQL Server 理解何时值得打破它——比直接背提示语法更能防滥用 ⚠️ 教学法主张。

## 8.6 并发类提示的归位（与 11 章交界）

- `READCOMMITTED/READUNCOMMITTED/SNAPSHOT/SERIALIZABLE` 表提示改的是**隔离级别**不是访问路径；`READPAST` 跳忙行（队列消费模式）；`UPDLOCK`+`HOLDLOCK` 出队原子化——这些属 11 章处方表，本章仅登记「长得像性能提示的并发提示」以免误用（NOLOCK 神话判 11 §11.5）。

## 8.8 武器工坊：五类场景的「该不该提示」裁决

- 场景一 升级救火（供应商 SQL 不可改）→ 指南/USE PLAN 有期使用，登记+复审 ✅ 裁决。
- 场景二 嗅探已确诊且 RECOMPILE/OPTIMIZE FOR 无效 → 连接/访问提示可做归因实验，转正需 8.2 手续。
- 场景三 「感觉扫描不对」 → 不许提示，先走 05 §5.6 检查表。
- 场景四 并发等待（11 章病）→ 优化提示无效，禁止拿 MAXDOP/索引提示治锁。
- 场景五 DTA/DMV 建议与坏索引共存 → 先删坏再建建议（09 §9.3），不许用 INDEX 提示绕自家重叠。
裁决原则一句话：**提示改变形态，不改变病因；形态可提示，病因须处方**。

## 核心概念速览（中英对照）

- **查询提示** — Query Hint：OPTION 族，语句级覆盖优化器决策。
- **表提示** — Table Hint：INDEX/FORCESEEK/FORCESCAN 等，单表引用级。
- **连接提示** — Join Hint：固化连接类型与算法。
- **FORCESEEK** — 强制走索引查找（可指定键列组）。
- **FORCESCAN** — 强制扫描形态（探索/兜底用，行数大时危险）。
- **USE PLAN** — 以计划 XML 直接指定整棵执行树。
- **计划指南** — Plan Guide：数据库/模板/对象三级计划冻结。
- **is_enabled** — sys.plan_guides 的存活巡检字段。
- **RECOMPILE/OPTIMIZE FOR** — 嗅探处方双雄（07 归口）。
- **MAXDOP 提示** — 语句级并行度帽。
- **NOEXPAND** — 阻止视图/CTE 内联。
- **遗产债务** — Legacy Debt：升级时必须重评的提示/指南存量。

## 最新演进与工业实践

- **参数感知与提示的合流**：2017+ 自适应连接让「固化 NL↔Hash」类提示失去主要动机；工业上提示存量按版本递减是健康信号。✅ intelligent-query-processing 页。
- **查询存储时代**：「强制已知的良好计划」在 UI/自动调优中取代手写 USE PLAN 的 80% 场景（可审计、可回退）；QS 是计划指南思想的官方继任者。✅ monitoring-performance-by-using-the-query-store。
