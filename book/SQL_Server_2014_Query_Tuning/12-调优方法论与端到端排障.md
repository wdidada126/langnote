## 12.1 调优的第一定律与循环

- 第一定律（全目录贯穿）：**没有基线就没有调优**——任何「变慢」主张必须先回答「和什么比、哪一段比」。
- 标准循环：
  1. 定义业务级 SLO（P95/P99 墙钟、吞吐、错误率），换算为可测指标。
  2. 采集基线：语句级（query_stats/QS 前身的手工抽样）、资源级（waits/IO/内存授予）、形态级（计划哈希分布）。
  3. 定位：自上而下（SLO 破→哪类负载→哪条语句）与自下而上（热点等待→哪些语句贡献）双向对撞。
  4. 归因四分（08 §8.4）：统计/CE、索引、写法、并发。
  5. 单变量修复→复测→登记；失败回滚是默认权利。
- 反模式：跳级调优（未定位先加索引/提示）、多变量同改（改了三处「快了一点」=结案无据）。

## 12.3 度量入口清单（2014 时代的工具箱 ⚠️ 转述）

- 语句级：`sys.dm_exec_query_stats`（时长/CPU/逻辑读/授予/计划哈希族）、缓存计划文本、缺失索引视图（09）；无 QS 年代的痛：抽样窗口要自管。
- 等待级：`dm_os_wait_stats`（差值采样）、`dm_exec_session_wait_stats`、`wait_stats` 分桶排除法（SOS_SCHEDULER_YIELD/BLOCKING/PAGEIOLATCH/PAGELATCH/LCK_M_/WRITELOG 各族的判读一句话）。
- 事件级：扩展事件（2014 已成熟：`sp_server_diagnostics` 会话、system_health 默认包；Profiler 迹已属遗物，本目录不展开——机制在边②15 章）。
- 形貌级：每库「计划哈希散点图」（同 query_hash 的 plan 数与耗时双峰=07 漂移监视器）、存储过程执行统计（老而弥坚）。
- 纪律：所有 DMV 读数注明**采样间隔与重启基线**（缓存类视图重启清零=差值失真的头号来源）。

## 12.4 端到端剧本（三条高频急诊 ⚠️）

**剧本 A「昨晚开始变慢」**
1. 变更单核对（发布/索引/统计作业/配置）→ 无变更进 2。
2. query_stats 对比基线窗口：定位语句族。
3. 取其缓存计划+实际计划走 03 决策树。
4. 行数差大→02/07 通道（统计/嗅探）；行数正常但 IO/CPU 形态变→05/11；并发等待→11.4 取证。
5. 处方从温和谱系（07 §7.3）起手；登记复盘。

**剧本 B「升级/兼容级后变慢」**
- 按 02 §2.4+07 §7.6：双兼容级对跑参数矩阵→差异计划归到 CE 换代或嗅探重抽签→定点处方（禁整体回退当首选）。

**剧本 C「报表能忍应用不能忍」**
- 12.5 资源治理切读写通道（dop/内存帽/副本分流），11.2 的 RCSI 评估，09 建议按读写两本账分别裁决——**调优目标函数是业务 SLO 不是总耗时** 的落地版。

## 12.5 资源治理与容量边界 ⚠️

- 服务器级：最大内存（留 OS 余量）、`max degree of parallelism`（NUMA/核数经验线：OLTP 保守、DW 放宽，均转述口径）、`cost threshold for parallelism`、轻量池（线程压时的调度逃生门，边①机制）。
- 会话级：资源池为 SQL 资源 governor（企业版特性）的内存/dop/时间帽——把「单语句挤占」关进笼子（10 章批式授予互动）。
- tempdb：多文件消分配争用、版本 store（11.3）与 spill（04.3）三账合一规划——RCSI 立项时的隐藏前置。
- 容量与调优的边界句：**调优改善效率，治理保障公平，容量决定底线**；三层混用是排障论坛的最大噪音源。

## 12.6 🔧 本机类比：基线-差值法的最小示范（非本书引擎行为）

SQLite 3.45.3 复现「同一语句的计划/耗时基线漂移」观测流程：
```
步骤1 基线：orders 无新索引时记录 L= cust 谓词族 SCAN，耗时 ~21ms（05 G1）。
步骤2 变更：CREATE INDEX ix(cust,status) → 同语句 0.2ms（G1 复用）——
        「单变量+前后全量数字」即调优结案的最低证据标准。
步骤3 反例训练：只建 ix(ts) 时同语句仍 SCAN（索引没覆盖谓词形态）→
        演示「加了索引≠被选择」，逼读者走 05 §5.6 检查表而非许愿式建索引。
方法：perf_counter+EXPLAIN QUERY PLAN 文本存档 diff；脚本 tmp/dbwave_w5_sstune。
```
延伸：DuckDB 1.5.5 用 `EXPLAIN ANALYZE` 记录逐算子实际行数，等于免费拿到本时代最缺的「实际计划基线」——把 12.3 的度量入口清单在迷你引擎上完整演练一遍。

## 核心概念速览（中英对照）

- **基线** — Baseline:变更前后的同口径度量序列，一切对比的分母。
- **SLO** — Service Level Objective:业务级延迟/吞吐目标。
- **等待统计** — Wait Statistics:资源等待的累计账本（差值法解读）。
- **差值采样** — Delta Sampling:两次快照相减的观测纪律。
- **计划哈希散点** — Plan Hash Scatter:同语句族多计划共存的监视形态。
- **归因四分** — Four-Way Attribution:统计/索引/写法/并发归口法（08 §8.4）。
- **单变量修复** — One-Variable Fix:结案证据标准的最低要求。
- **资源调控器** — Resource Governor:会话级 CPU/内存/dop 笼子（企业版）。
- **轻量池** — Dedicated Admin/轻量连接：调度饥饿时的逃生门。
- **成本阈值并行** — cost threshold for parallelism：并行起算闸门。
- **端到端剧本** — End-to-End Runbook:急诊流程的固化为文。
- **回滚权利** — Rollback Right:处方无效即撤的调优伦理。
