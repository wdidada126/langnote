## 11.1 优化器看不见的成本：编译期代价模型不含等待（01 §1.5b 的回环）

- 同一「好计划」在零并发与 300 并发下墙钟可差一个量级：锁等待、版本链走查、闩锁争用都不在 EstimateIO/EstimateCPU 里。
- 症状谱：计划没变、统计没变、代码没变而 P95 恶化 → 并发通道，不是 CE 通道（02/07 排除法之后进本章）。
- 调优分工：并发问题的「写方处方」（索引减少锁范围、覆盖减少持锁时间）其实在 05；本章管「读方与协议方」。

## 11.2 隔离级别速览与默认语义（⚠️ 转述）

| 级别 | 读行为 | 写行为 | 调优含义 |
|---|---|---|---|
| READ UNCOMMITTED（含表提示） | 脏读 | 不申请共享锁 | 快但以正确性换时间（11.5 神话判） |
| READ COMMITTED（默认） | 语句级共享锁 | 排他至语句/事务边界 | 高读并发下锁争用主战场 |
| **READ COMMITTED SNAPSHOT（RCSI）** | 读走版本（tempdb） | 写正常加锁 | 数据库选项，2005 起；**读阻塞消解+tempdb 新账**（11.3） |
| SNAPSHOT | 事务级版本一致读 | 更新冲突抛错 | 需开启+长事务版本膨胀监视 |
| REPEATABLE READ/SERIALIZABLE | 范围/键共享锁持有至事务 | — | 计划稳定的代价=阻塞他人 |
- 2014 语境：Azure/新一代应用默认推动 RCSI；「锁噪音大」的库开 RCSI 是标准处方之一（变更需回归：语义从「语句级不脏读」保持，但幻读窗口行为有差异 ⚠️）。

## 11.3 版本链与 tempdb：RCSI 的双头账 ⚠️

- 行版本=被修改行的版本链（指向 tempdb 版本记录）；读侧沿链回溯到正确事务序列点——**链越长读越贵**：长事务/大更新未拆分=版本链失控=「明明加了索引读还是慢」的新病因。
- 版本 store 清理阈值（长期事务 pin）；tempdb 争用表现为 `PAGELATCH_EX/SH` on 版本页与分配对象（12 章等待线对读）。
- 处方线：拆分批处理（06 §6.5 第 5 条）、缩短事务、监视 `sys.dm_tran_active_snapshot_database_transactions` 老化。
- 内存 OLTP 对手机器（10.2）与 RSI 同源乐观思想但不同实现——并发章的「两个 MVCC 世界」差异归边②/10 章。

## 11.4 阻塞链取证：谁伪装成了慢查询（剧本 ⚠️ 转述）

1. 会话地图：`sys.dm_exec_requests` 的 blocking_session_id + `sys.dm_os_waiting_tasks`（LCK_M_* 类型/模式/资源 database_id+ hobt_id 定位对象）。
2. 锁归属：`sys.dm_tran_locks`（resource_type/assoc object_id）找**持有者**而非抱怨者——头阻塞会话的事务里那句 UPDATE/SELECT 才是调优对象。
3. 升级判据：锁升级阈值（约 5000 锁/语句，转述口径）→ 大范围 UPDATE 改分段（06 剧本）以避开表级升级。
4. 队列模式：应用层以 UPDLOCK+READPAST 出队（8.6 归位），当代更多将队列外移至专用消息层（见演进节）。
5. 死锁≠慢：死锁是吞吐损失+错误重试；图取证（system_health 的 deadlock graph 扩展事件包）在边②，本章只划界：调优语境区分「等得久」与「互相杀」。

## 11.5 NOLOCK 神话与其他暗器判词 ⚠️/社区共识

- **NOLOCK 不「更快」，只是不还价**：它免去共享锁申请，换来脏读/跳过/页断裂读（结构不一致读）风险；「报表全加 NOLOCK」= 用正确性给并发问题打止痛，判词与 [../Expert_Performance_Indexing_SQL_Server_2019/08-索引神话与最佳实践.md](../Expert_Performance_Indexing_SQL_Server_2019/08-索引神话与最佳实践.md) 的神话清算体例一致。
- 暗器清单：游标跨事务持锁、调用方超时未取消服务端（孤儿事务继续阻塞）、分布式事务/MSDT 拖长锁持有、SP 内嵌套事务忘记 COMMIT 计数、隔离级别与会话级 `SET` 漂移（连 07 复用谓词）。
- 「索引没变为何变慢」排查顺序：阻塞链→版本链→闩锁（tempdb/内存对象）→执行内存授予（04 §4.3）→再回 CE。

## 11.6 🔧 本机类比：读阻塞的有无对照（非本书引擎行为）

SQLite/DuckDB 作为「无共享锁读」参照系：
```
SQLite 3.45.3 默认 journal 模式：写者持排它锁，读者可继续读旧库快照；
WAL 模式：读写并发=版本化（RCSI 概念的最小可跑模型，单写多读）。
DuckDB 1.5.5 单写进程模型：无行锁概念，读侧只见已提交快照。
对照实验：连接 A BEGIN; UPDATE orders SET status='X' WHERE id=1（未提交）
  → SQLite 默认下连接 B 读同一行不等待（读到旧值）≈ 版本读语义原型；
     而 SQL Server READ COMMITTED 下 B 该语句会被锁住直至 A 提交——
     「同一句 SELECT 在不同并发协议下的等待矩阵」由此可体感。
```
方法：python sqlite3 双连接；差异标注：两引擎均**无 RCSI 的语句级粒度**，仅概念类比。

## 11.8 等待工坊：五张会话快照的诊断走向

- 快照一 `LCK_M_S` 长、头阻塞者是大 UPDATE → 拆分批（06.5-5）+装载窗口错峰。
- 快照二 `PAGELATCH_EX` 于 2:1:1（tempdb） → 版本链/ spill 双嫌疑（11.3 vs 04.3），先查事务老化。
- 快照三 `SOS_SCHEDULER_YIELD` 齐涨 + 计划未变 → 并行过配/CPU 压力，走 12.5 治理。
- 快照四 `WRITELOG` 高峰伴慢 → 日志/检查点侧（边①03 目录），非查询通道。
- 快照五 读会话等待 `LCK_M_S` 但库未开 RCSI → 11.2 立项评估+11.3 前置 tempdb 账。

## 核心概念速览（中英对照）

- **读已提交快照隔离** — RCSI：库级选项，读走版本链免共享锁。
- **行版本链** — Version Chain：tempdb 中同逻辑行的历史版本序列。
- **版本存储** — Version Store：tempdb 行版本仓库与清理线程域。
- **锁升级** — Lock Escalation：细锁堆量后升表级，阈值语境内转述。
- **LCK_M_*** — 锁请求等待类型族，模式编码在名中。
- **blocking_session_id** — 会话地图的头节点指针。
- **dm_tran_locks** — 锁归属视图，找持有者的钥匙。
- **SKIP LOCKED 语义** — 出队跳忙行模式（SQL Server 当年用 UPDLOCK+READPAST 模拟）。
- **闩锁** — Latch：内存结构短期轻量互斥，tempdb/分配页热点。
- **孤儿事务** — Orphaned Transaction：客户端超时后仍驻留服务端的锁源。
- **脏读** — Dirty Read：UNCOMMITTED 读到的回滚风险值。
- **头阻塞** — Head Blocker：链首单会话拖垮全链的形态。

## 最新演进与工业实践

- **RCSI 成为云默认叙事**：Azure SQL DB 推荐文档长期把「读不阻塞写」列为云上第一姿势；自建实例的迁移评估表里 RCSI 与 tempdb 容量必须同页出现 ⚠️ 生态转述。
- **原生 SKIP LOCKED/乐观队列**：Oracle/PG/MySQL(8.0+)已有 `SKIP LOCKED` 语法；SQL Server 截至本笔记 2026-09 核验时点未检索到等价 T-SQL 语法（⚠️ 以官方文档为准，未下绝对断言），社区以队列模式库/外部消息层替代——**2014 时代的 UPDLOCK 剧本在当代多被架构外移** ⚠️。
- **等待统计产品化**：`sp_BlitzWho`/`sp_WhoIsActive` 社区标准件把 11.4 剧本做成一行命令；Azure 智能事务/阻塞可视化监控（Query Store 时代的 wait stats）是托管面替代 ✅ 生态地位转述。
- **内存 OLTP 对照的退役风险**：10.2 的乐观无锁世界若弃用（演进节），「无锁并发」教学需回到 RCSI/XEP 组合讲——并发知识的载体在换 ⚠️。
