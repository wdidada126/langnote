## 10.1 为什么调优书在 2014 必须写这两章

SQL Server 2014 = 「Hekaton（内存优化表）GA 后的首个大版本 + 聚集列存储索引（CCI）可更新」：查询调优的对象空间第一次分裂成**行存/内存表/列存三个执行世界**，各自有独立的访问路径、并发模型与统计链路。本章只记「对调优决策的影响面」，实现细节归边②。

## 10.2 内存 OLTP 调优切片 ⚠️

- 访问路径重构：无 B 树——**索引即两条链表**（桶索引+范围索引并存于一表）；等值查询走哈希桶，范围/排序需非聚集（范围）索引；「一张表两种索引的取舍」替代旧的聚簇/非聚簇话术。
- 编译时代偿：natively compiled 存储过程把解释执行换成 C 编译（2014 支持 ALTER 重建、外键/检查约束、`SCHEMA_AND_DATA` 持久化）；**调优红利集中在高频率短事务**，分析型大扫描不配入内存表。
- 并发模型：乐观 MVCC 无锁表——冲突以重试处理；等待统计里看不到传统闩锁，**监控面板要换计数器**（边②有专章）。
- 2014 当年限制（影响设计即影响调优）：不支持 DBCC/backups 单独粒度到表、跨表事务出内存引擎即序列化失败族、`TOP`/`ORDER BY` 在编译查询的支持子集——调优先按「容量规划」而非「计划微调」思考。
- 判读红线：**内存表不参与传统计划缓存收益模型**（编译计划驻留内存对象），07 章处方对 natively compiled 过程大部分失配 ⚠️ 转述。

## 10.3 列存储（CCI）调优切片 ⚠️

- 数据组织：列组段（rowgroup≈百万行）+ 每列段压缩；**字典/压缩使扫描宽度=谓词列宽**，5.3 的 `%x` 无解与「大表全扫聚合」在此改账。
- 批量模式执行：向量化算子（Batch Mode）替代行式迭代器；授予模型不同（批式按段数），04 §4.3 的 spill 处方要重算。
- 状态机与可更新性：2014 CCI 可增量装载——delta rowgroup（列存化后台任务）+ 压缩段；**调优热点=碎片化的小压缩组与未压缩 delete 标志**，监控 `column_store_delta_store_tensors/row_groups` 的 trim/tuple 计数（转述口径），重组=重新压缩/Rebuild。
- 排序段（Order Key/后续版本 Order Spill）：2014 靠装载顺序+聚集主键侧排序习惯换段消除；段内 min/max（zonemap 前身）决定谓词裁剪率——**装载键序=列存时代的聚簇键序**。
- 统计差异：列存不依赖传统直方图走每列 min/max+字典（⚠️ 版本细节归边②），基数误差形态从「桶外推」变为「段跳过失败」；2.4 的 CE 换代对列存查询同样生效（兼容级开关不分引擎）。
- 混合工作负载：行存（OLTP 写+点查）+非聚集列存（读分析）同表共存自此成为标准架构；调优问题从「选索引」升级为「路由负载到正确副本形态」——注意 2014 只允许一表一列存且 CCI 即表本体，与后续「非聚集列存/嵌入式列存」（16 版+）形态差异大 ⚠️。

## 10.4 缓冲区池扩展 BPE：2014 的第三杠杆（⚠️ 转述）

- 定位：SSD 文件作为缓冲池二级扩展，压热页的读放大；**不扩内存对象、不救执行内存授予**（授予不足仍 spill tempdb）。
- 调优判读：适合「读多写少、内存墙下页生命周期偏冷」的库；等待类型 `PAGEIOLATCH_SH` 高位+文件延迟分布是候选证据（12 章等待线）。
- 2014 版本限定与后续弃用线见演进节（教训：平台级特性生命周期也进调优知识账本）。

## 10.6 🔧 本机类比：列存段跳过 vs 行存二分（非本书引擎行为）

DuckDB 1.5.5（列存向量化引擎替身）：
```
seg 表 200 万行、val 随 g 分段单调：EXPLAIN 显示 SEQ_SCAN + Filters、估计 ~400,000 行
  （实际 BETWEEN 900000 AND 900500 仅 501 行——估计仍走统计算术，
   但**执行侧靠 zonemap 跳段**把 IO 压到极少数 rowgroup：列存「段裁剪」的可见形态）
对照 SQLite 3.45.3 同规模：无段概念，靠 B 树 Seek 键序命中（05 G1 的 124×）
```

- 方法：range 建表+EXPLAIN+实测 count；脚本在 tmp/dbwave_w5_sstune。

## 10.8 世界工坊：五题「选错世界」判例

- 判例一 报表 SQL 全查内存表：列裁剪/扫描优势在内存侧不存在（链表世界），迁移非簇列存/行存副本方案。
- 判例二 高频点查用 CCI：段裁剪救不了行级锁语义需求，且 delete 标志膨胀——回行存+Seek。
- 判例三 装载乱序的 CCI：段 min/max 失效、跳段率趋零（🔧G5b 对照）——重排装载键。
- 判例四 大扫描放进 natively compiled 过程：编译红利在短事务，扫描照旧耗满 CPU——拆双引擎。
- 判例五 BPE 当「内存不够的解药」：授予与版本链问题原样保留（10.4）——先等认证据再买 SSD。

## 10.9 边界速查（2014 版语境的「还不能」清单 ⚠️）

- 一表一列存、CCI 即本体；非簇列存要等 2016（标准版受限另计）。
- 内存表：无跨引擎分布式事务红利、检查/外键刚 GA、DBCC 盲区。
- BPE：不扩执行内存、不救 tempdb 版本链。
- 批量模式仅由列存触发（170 前）——行存表「想要向量化」在 2014 是伪需求。
- QS 不存在（2016+）：本目录所有「事后取证」在当年要自建抽样。

## 10.10 一页口诀

> 短事务进内存、大扫描进列存、点查留在行存；
> 装载键序是列存的聚簇键、桶数是内存表的直方图；
> 三世界各有各的统计、各自的等待、各本的处方书。

## 核心概念速览（中英对照）

- **Hekaton/内存 OLTP** — In-Memory OLTP：本机内存引擎，索引即链表。
- **natively compiled** — 编译为机器码的存储过程形态。
- **bucket count** — 哈希索引桶数，90% 基数准则的容量参数。
- **SCHEMA_AND_DATA** — 内存表持久化级别（对照 SCHEMA_ONLY）。
- **CCI** — Clustered Columnstore Index：2014 起可更新的列存本体。
- **rowgroup/delta store** — 列组段与未压缩增量的装载状态机。
- **tuple mover** — 后台把 delta 压缩为列存段的系统线程。
- **Batch Mode** — 向量化批量执行形态。
- **Order Key** — 列存排序键（2014 形态原始，后置版本完善）。
- **Segment 裁剪** — 段级 min/max 谓词跳过（zonemap 家族）。
- **BPE** — Buffer Pool Extension：SSD 二级缓冲池。
- **混合副本形态** — 行列共存架构（2014 受限，16+ 非聚集列存放开）。

## 最新演进与工业实践

- **列存全面下沉**：2016 非聚集列存/聚类列存进所有 SKU、**2019 起批处理模式行存储（170+，2022/170 GA）让行存表也吃到向量化**——10.3「按引擎选世界」在当代收敛为「按语句选执行模式」。✅ columnstore-indexes-overview。
- **内存 OLTP 的轨道分化**：Azure SQL Hyperscale/托管实例持续支持但特性更新放缓，社区出现「以高版本行存+优化替代 Hekaton」的退坑实践线 ⚠️ 生态转述，读者决策要带 SKU/年代双标签。
- **BPE 已死**：微软官方宣布弃用（2016 引入废弃线，不推荐新负载），其教训固化进方法论：**平台特性寿命也是调优变量**——登记于本章 10.4 的历史框。⚠️ 转述。
- **自动管理列存储**：2019+ 的「自动索引/自动优化」在云端为热点表自动建/删列存索引（Azure 自动调优家族）——10.5 的路由问题被托管化 ⚠️。
- **跨引擎镜鉴**：本目录 🔧 用 DuckDB 演示列存直觉已成惯例；Parquet/Iceberg 时代的段跳过/谓词下推词汇与 CCI 同源，湖仓侧阅读可接 [../Advanced_Snowflake/00-总览与阅读地图.md](../Advanced_Snowflake/00-总览与阅读地图.md)（微列存+min/max 裁剪的商用范本，波4 已验收实链）。
