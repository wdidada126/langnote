## 3. 🔧 实测组五：schema 演化不是口号，是读侧模式开关（DuckDB 1.5.5）

**方法**：表 `emp(id, name)` 写 `emp_v1.parquet` → `ALTER TABLE emp ADD COLUMN salary`
并回填后写 `emp_v2.parquet`；随后**两代文件并读**：

| 读法 | 结果（原样摘录） | 语义 |
| --- | --- | --- |
| `union_by_name=1` | `(1,'a',NULL),(1,'a',100.0),(2,'b',NULL),(2,'b',100.0)` | 按列名对齐，旧文件缺列补 NULL——**演化安全** |
| 严格模式（默认） | 返回首页 `(1,'a')`，未报错 | 以首文件 schema 截断，**静默丢列**（危险形态） |

- 判读 1：**同一份物理文件，"schema 演化支持"完全由读端解释规则决定**——Iceberg 把
  该规则固化为"按字段 id 而非名字匹配"（✅ <https://iceberg.apache.org/spec/>），
  从根上消灭"改名即错配"事故；Delta 以 columnMapping 模式提供同款能力 ⚠️。
- 判读 2：严格模式**不报错只少列**是本组最有教育意义的输出——生产事故里它表现为
  "报表列悄悄消失"，比崩溃难发现一个数量级。
- 纵深：[../Engineering_Lakehouses_with_Open_Table_Formats/07-Schema与分区演化.md](../Engineering_Lakehouses_with_Open_Table_Formats/07-Schema与分区演化.md)
  （字段 id 机制全解）、[../Use_Iceberg_with_Spark/05-演化与隐藏分区.md](../Use_Iceberg_with_Spark/05-演化与隐藏分区.md)。

## 4. 🔧 实测组六：catalog = "文件 → schema 版本"间接层（SQLite 3.x 内存库）

**方法**：两张表最小复现元数据登记（60 行内可手敲）：

```sql
CREATE TABLE schemas(schema_id INTEGER PRIMARY KEY, ddl TEXT);
INSERT INTO schemas VALUES (1,'id INT, name VARCHAR'),
                           (2,'id INT, name VARCHAR, salary DOUBLE');
CREATE TABLE files(path TEXT, schema_id INT);
INSERT INTO files VALUES ('emp_v1.parquet',1),('emp_v2.parquet',2);
-- 查询：每个文件按哪个 schema 解释？
SELECT f.path, f.schema_id, sc.ddl FROM files f JOIN schemas sc USING(schema_id);
-- 实测输出: [('emp_v1.parquet',1,'id INT, name VARCHAR'),
--           ('emp_v2.parquet',2,'id INT, name VARCHAR, salary DOUBLE')]
```

- 结论：**表格式的 schema 演化 = 本组两张表的 JOIN**；差异只在规模（Avro 元数据文件
  承载）、原子发布（换快照指针）与并发（02 章 🔧）。理解到这一层，"schema registry"
  不再神秘。
- 与 DLUR 姊妹实验的错位：彼为"版本表+快照读"（时间维度），本组为"schema-id 间接层"
  （结构维度），互补不重复。

## 6. 质量闸门：分层各守一道（§6）

| 层 | 闸门 | 失败动作 |

## 8. 常见误区

| 误区 | 修正 |
| --- | --- |
| "有目录就有治理" | 目录给发现性；权限/质量/血缘是另外三件（§2 平面图） |
| "ALTER TABLE 加列即安全演化" | 跨版本旧文件的读侧规则才是安全所在（§3 🔧：静默丢列实证） |
| "血缘一次建成" | 采集是持续工程，新管道上线日即血缘漏点日（§5） |
| "质量规则越多越好" | 无分层职责的堆规则=告警噪音（§6 表） |
| "治理拖慢交付" | 无治理的湖仓在三年的审计/重刷成本更高（Inmon 与 Menon 罕见同向 ⚠️） |
| "元数据系统自建不难" | §4 的最小复现恰好说明：难的是原子发布与并发，不是两张表 |

## 核心概念速览（中英对照）

- **元数据平面** — Metadata Plane：技术/操作/业务三层元数据的总称（§2）。
- **数据目录** — Data Catalog：可发现性资产登记处；UC/Purview/Atlas 各占档位。
- **schema 演化** — Schema Evolution：加宽/改名/拆分不破旧读（🔧 §3 读侧决定论）。
- **字段 ID 匹配** — Column-ID Matching：Iceberg 消灭名字错配的规范机制 ✅ spec。
- **血缘** — Lineage：表/列级依赖图（§5 三采集策略）。
- **数据质量闸门** — Quality Gate：分层拦截规则集（§6）。
- **死信区** — Dead-letter/Quarantine：不合格数据的隔离留存。
- **数据契约** — Data Contract：生产者与消费者的口径承诺（§6 Gold 行）。
- **认证发布** — Certified Dataset：以治理背书换自助信任（§6/§8）。
- **schema registry** — 模式登记处：§4 两张表 JOIN 的工业化放大版。
