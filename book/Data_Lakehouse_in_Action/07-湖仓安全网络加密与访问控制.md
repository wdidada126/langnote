## 2. 责任分界与四道边界（§1/§2）

```
 用户/BI/应用
   │ ④语义边界: 行/列过滤·脱敏策略(引擎或catalog执行)
 引擎层(Spark/SQL端点)
   │ ③引擎边界: 表/列级 GRANT, 会话身份透传
 表格式/目录层(UC/Purview/HMS)
   │ ②存储边界: 容器级RBAC + ADLS POSIX ACL ✅(URL见§3)
 对象存储(ADLS Gen2)/网络(VNet/PrivateLink/防火墙)
   │ ①网络边界: 私有端点、受控出口
 加密底座(SSE/CMK/TLS) — 云商默认承担
```

- 反直觉要点：**表格式把"绕过引擎直读文件"变成现实威胁**——任何人拿到 SAS token
  就能 `read_parquet` 全湖裸文件。因此湖仓安全的重心从"数据库里子"移到
  **①②边界 + 凭证治理**，这与 2022 年前"仓库时代"的直觉相反。
- 与 Inmon 对位：他谈"让数据可信"偏质量，Menon 明确"secured"为独立动词——
  两者共同暴露旧数仓安全叙事的空白：湖上安全首先是**存储侧**安全。

## 3. 身份与授权栈（§3，✅ URL + ⚠️ 细节转述）

- **ADLS Gen2 双层授权**：Azure RBAC（数据平面角色如 Storage Blob Data Reader）
  + POSIX 风格 ACL（文件/目录属主、组、掩码），两套策略在同一命名空间叠加：
  ✅ <https://learn.microsoft.com/en-us/azure/storage/blobs/data-lake-storage-access-control>。
  工程难点在"effective permissions 的合取语义"——排障时先 `getAccessControl`/
  `setOwner` 谱系再查 RBAC ⚠️。
- **身份链**：Entra ID（原 AAD）为根身份 → Synapse/Databricks 映射到服务主体或
  个人身份 → 引擎内 GRANT → catalog 策略。跨层"身份透传"（查询者本人而非作业
  账号的权限生效）在 2022 是稀缺能力，2026 由 Unity Catalog 类集中式方案补齐 ✅
  <https://learn.microsoft.com/en-us/azure/databricks/data-governance/unity-catalog/>。
- **开源自对照系** ⚠️：Ranger（策略中心）+ Kerberos（认证）的 Hadoop 栈是本书
  非 Azure 章节的参照；四家表格式官方站（见 02 章链接）均不含授权方案——
  **安全从来是 catalog/引擎层的事**，这个分层判断 2026 仍成立。
- 纵深盘上：[../Delta_Lake_Definitive_Guide/11-治理安全与数据血缘.md](../Delta_Lake_Definitive_Guide/11-治理安全与数据血缘.md)
  的行/列过滤与脱敏机制章（Delta 侧最完整）。

## 4. 加密与密钥主权（§4，⚠️ 全转述）

| 层 | 默认 | 升级选项 | 主权含义 |
| --- | --- | --- | --- |
| 静态（存储） | 平台托管密钥 SSE | CMK（Key Vault 客户密钥） | CMK≈可一键"逻辑毁钥"，合规刚需 |
| 传输 | TLS | 私有端点内网化 | 出口收敛=审计面收敛 |
| 列级 | 无（需引擎/格式支持） | 信封加密/Parquet 列加密 ⚠️ | 细粒度但破坏裁剪，慎用 |
| 引擎内存 | 平台边界 | 机密计算 SKU | 高敏场景溢价 |

- 判读：**列级加密与谓词下推互斥**（密文无统计可用）——安全与性能在 04 章 🔧
  的框架里再次对撞；实务用"分级存储（敏感列独立表/独立容器）"替代列加密。

## 5. 隐私工程：不可变湖遇上删除权（§5）

GDPR "被遗忘权"在湖仓的三个结构性摩擦（⚠️ 通识+盘上治理册口径）：

1. **写时复制=旧文件还在**：DELETE 只是清单不引用，物理删除依赖 VACUUM/expire
   窗口（02 章 🔧"旧文件留存"的反面）——删除 SLA 实为清理策略 SLA。
2. **备份/副本放大**：Bronze 原样保留 + 分层复制使"同一 PII 七处存活"常态化，
   删除必须沿血缘传播（06 章 §5 血缘的隐私用途）。
3. **匿名化两难**：哈希不加盐≈可枚举反推；真删除又毁分析价值——实务收敛为
   "假名化 + 密钥隔离 + 政策化保留期"。
- 盘上制度层：[../Data_Governance_Elsevier/00-总览与阅读地图.md](../Data_Governance_Elsevier/00-总览与阅读地图.md)
  （政策到控制的翻译方法）、[../数据安全架构设计与实战.md](../数据安全架构设计与实战.md)

## 6. 审计与检测（§6）

- **表格式历史=天然取证日志**：`DESCRIBE HISTORY`/snapshots 表给出"谁在何时提交
  了什么"的不可篡改账本（⚠️ 各家实现；#148 册元数据表章有逐表清单 →

- 三源合流：平台活动日志（云）+ 引擎查询日志 + 表版本历史——缺一个就有抵赖面。

## 7. 常见误区

| 误区 | 修正 |
| --- | --- |
| "引擎里配好权限就安全了" | 直读裸文件绕过一切引擎授权（§2 反直觉要点） |
| "RBAC 配完不用看 ACL" | ADLS 双层合取语义，缺一层排查即卡死（§3 ✅ 页） |
| "SSE 开启=密钥在我" | 平台托管与 CMK 的主权差一个量级（§4 表） |
| "DELETE 即数据消失" | 物理清除=清理策略的函数（§5-1） |
| "加密列更合规" | 列加密摧毁下推与统计，且通常不是法规要求（§4 判读） |
| "审计=打开云日志" | 三源不合流，历史不可对质（§6） |

## 核心概念速览（中英对照）

- **共享责任模型** — Shared Responsibility：云管底座加密，客管身份策略。
- **私有端点** — Private Endpoint：PaaS 服务落入客户 VNet 的网络边界手段 ⚠️。
- **RBAC** — 基于角色的访问控制：数据平面角色（如 Blob Data Reader）✅ ADLS 页。
- **POSIX ACL** — 文件级授权：ADLS 分层命名空间的第二层 ✅ 同页。
- **CMK** — Customer-Managed Key：密钥主权与"毁钥即毁数据"的合规原语（§4）。
- **信封加密** — Envelope Encryption：数据密钥+主密钥两级体制（§4 ⚠️）。
- **假名化** — Pseudonymization：可逆脱敏，删除权的缓冲方案（§5）。
- **身份透传** — Pass-through Identity：查询以自然人权限在引擎内生效（§3）。
- **版本账本审计** — History as Audit Trail：表快照日志兼任取证源（§6）。
- **最小特权湖** — Least-Privilege Lakehouse：容器/表/行列三级递减授权纪律。

## 最新演进与工业实践

- **集中式策略平面胜出**：2022 年"引擎内 GRANT + 存储 ACL"的双轨拼接，2026 收敛到
  Unity Catalog 式"策略随治理对象、身份随企业目录"的单轨 ✅
  <https://learn.microsoft.com/en-us/azure/databricks/data-governance/unity-catalog/>；
  本书 §3 的翻译链大部分被平台内化。
- **行/列过滤 + 脱敏成为表格式上层标配**：Delta/Iceberg 社区与 catalog 联动推进
  ABAC/CLA（column & row level access）规范讨论 ⚠️ 转述（iceberg 官方站持续更新）。
- **密钥与合规产品化**：CMK、客户加密键撤销、保留/删除策略以订阅形态交付，
  §5 的删除权工程从自建脚本变成平台开关（⚠️ 各厂商文档口径）。
- **安全-性能权衡的新解法**：分级分桶（敏感区独立存储+独立策略）+ 04 章裁剪纪律，
  替代 2022 时代"列加密一把梭"的错误直觉——与 #148 册存储章的隔离分域建议合流。
