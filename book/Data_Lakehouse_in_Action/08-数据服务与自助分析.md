## 2. 服务全景（§1/§2）

```
              ┌─ BI 工具(Excel/PowerBI/Tableau) ── JDBC/ODBC ─┐
 认证数据集    ├─ 数据科学家(notebook) ── Arrow/pandas/Spark ─┤→ SQL分析端点
 (Gold层)     ├─ 运营应用(低代码/后端) ── REST/查询模板 ──────┤   + 缓存/并发层
              └─ 内部自助探索(ad-hoc) ── 笔记本/即时SQL ──────┘    (⚠️ 形态转述)
```

| 消费者 | 延迟期望 | 失败容忍 | 服务要点 |
| --- | --- | --- | --- |
| 高管看板 | 秒开 | 零 | 物化+缓存+早预热 |
| 分析师 ad-hoc | 秒-分 | 中 | 成本护栏（查询上限/自动取消） |
| 运营应用 | 毫秒-秒 | 低 | 预留端点+SLA 分区 |
| ML 特征读取 | 批量秒 | 中 | 列裁剪+谓词下推（04/05 章 🔧 的受益人） |

- 本书 2022 语境的 Azure 服务面：Synapse Serverless SQL（湖上按需计费 T-SQL 端点）、
  Synapse Dedicated SQL（仓化服务层）、Power BI 直连（⚠️ 转述）。
  ✅ 服务总口径：<https://learn.microsoft.com/en-us/azure/synapse-analytics/overview-what-is>。

## 3. BI 直连湖的原理（§3）

- 旧世界：湖→ETL→仓 cube→BI，因为"文件不可信、半写可见"。
- 湖仓的解锁：**快照原子发布**（02 章）让任意时刻的读落在一个完整版本上——
  JDBC 端点因此可以直连 Bronze 之外的层而不出"半份报表"。
- 读路径优化栈（服务侧视角）：
  1. catalog 统计与分区裁剪（04 🔧E1：5/1887 文件）；
  2. 行组跳过（05 🔧E2 族：布局 ×2.8）；
  3. 结果/元数据缓存（端点内建 ⚠️）；
  4. 物化聚合表兜高频重查询（回扣 02 §5 视图/物化决策）。
- 盘上同题纵深：[../Snowflake_The_Definitive_Guide/00-总览与阅读地图.md](../Snowflake_The_Definitive_Guide/00-总览与阅读地图.md)
  与 [../Advanced_Snowflake/00-总览与阅读地图.md](../Advanced_Snowflake/00-总览与阅读地图.md)
  的服务层章（warehouse 并发扩展/结果缓存是该三件套的最成熟商业实现）；
  [../Amazon_Redshift_TDG/00-总览与阅读地图.md](../Amazon_Redshift_TDG/00-总览与阅读地图.md)
  的联邦查湖（Spectrum/S3 外链）则是"仓服务湖数据"的另一路线。

## 4. 语义层与认证数据集（§4）

- 问题：自助=人人可查 ⇒ 同名指标多口径 ⇒ "自助"退化为"自乱"。
- 三件解药（⚠️ 2022 通识 + ✅ 2026 平台化）：
  1. **语义层**：指标定义集中（度量/维度表达式），BI 工具经它翻译而非各写 SQL；
  2. **认证数据集**：Gold 表打治理徽章（06 §6），未认证可查但显式告警；
  3. **发现入口**：目录搜索先行（06 §7），找不到=不会用，用了=乱用。
- Fabric 已将 OneLake+语义层+Direct Lake 做成一体化答案（盘上 #221 实链：
  [../Fundamentals_of_Microsoft_Fabric/00-总览与阅读地图.md](../Fundamentals_of_Microsoft_Fabric/00-总览与阅读地图.md)）——
  本书服务章的产品形态在微软系已被整体替代，**概念骨架仍然有效**。
- 对读大图案册：[../Data_Fabric_as_Modern_Data_Architecture/04-语义层与统一数据访问.md](../Data_Fabric_as_Modern_Data_Architecture/04-语义层与统一数据访问.md)

## 5. 性能与并发三件套（§5，⚠️）

| 手段 | 原理 | 代价 | 适用 |
| --- | --- | --- | --- |
| 缓存 | 热文件/结果驻留 | 一致性窗口 | 读多写少看板 |
| 物化/聚合表 | 预计算换扫描 | 维护与新鲜度 | 高复用指标 |
| 端点隔离 | 交互式与批互不踩 | 资源碎片 | 多租户湖 |

- 反模式三则：把 ad-hoc 高峰打到生产端点（并发风暴，05 §7）；用物化掩盖布局问题
  （04/05 🔧 的教训：先修排序再谈缓存）；为省存储关掉历史版本又抱怨"报表不可回放"
  （02 §4/11 章清理对冲）。

## 6. 数据共享与对外服务（§6）

- 本书时代（2022）：对外供数=开放 API 或复制一份；**开放共享协议刚起步** ⚠️。
- Delta Sharing 于 2021 年末开源、2022-2023 生态铺开：以协议让任意客户端读
  发布方表快照，无需复制与账号互信 ✅ <https://delta.io/blog/>（协议演进出口）；
  盘上纵深 [../Delta_Lake_Definitive_Guide/12-Delta-Sharing.md](../Delta_Lake_Definitive_Guide/12-Delta-Sharing.md)。
- 2026 视角：共享/交换能力并入 catalog 平面（UC 的 sharing 特性 ✅ UC 文档页），
  与 06 章"策略随对象"同流。
- 服务"产品化"的终点讨论是数据产品（Data Product）——mesh 语境下服务即契约：

## 7. 常见误区

| 误区 | 修正 |
| --- | --- |
| "湖上 BI 慢就得回仓" | 先查裁剪/布局/缓存三层（§3 优化栈），多数场景可救 |
| "自助=开放查询权限" | 无语义层与认证徽章的自助=口径战（§4） |
| "serverless 无限弹性" | 冷启动与并发配额是软上限（§5 ⚠️） |
| "物化越多越稳" | 每份物化都是新的一致性债（§3-4/02 §5） |
| "对外供数=开账号" | 协议化共享（免复制）已成熟（§6） |
| "缓存能救布局" | 缓存治标，行组/分区裁剪治本（05 🔧 §4 证据链） |

## 核心概念速览（中英对照）

- **数据服务** — Data Serving：以查询/接口形式向消费者兑现湖仓价值（§1）。
- **SQL 分析端点** — SQL Endpoint：湖上按需 JDBC/REST 查询门面（§2 ⚠️）。
- **快照一致读** — Snapshot-Consistent Read：BI 直连湖不出半份报表的根据（§3）。
- **语义层** — Semantic Layer：指标口径的集中定义与翻译层（§4）。
- **认证数据集** — Certified Dataset：治理徽章背书的 Gold 资产（§4）。
- **ad-hoc 查询** — 即席查询：探索式非预定分析，需成本护栏（§2/§5）。
- **结果缓存** — Result Cache：同查询免重算（§5）。
- **聚合表/物化** — Aggregated/Materialized Table：预计算服务层（§5）。
- **Delta Sharing** — 开放共享协议：跨组织免复制读表 ✅ delta.io 生态。
- **查询模板** — Query Template：把表变成应用可调用端点的最小封装（§2）。

## 最新演进与工业实践

- **Direct Lake 式"仓速湖价"服务成为微软系答案**：Fabric 把语义层直读 OneLake 做成
  默认路径，本书"抽取到 Dedicated 池再服务"的 2022 建议已被替代（盘上 #221 实链
  [../Fundamentals_of_Microsoft_Fabric/00-总览与阅读地图.md](../Fundamentals_of_Microsoft_Fabric/00-总览与阅读地图.md)）。
- **开放表格式+BI 的连接性收敛**：Iceberg REST catalog 使第三方 BI/查询引擎
  （Trino/ClickHouse/DuckDB 系）直连多引擎湖成为货架能力 ✅
  <https://iceberg.apache.org/docs/latest/>；服务不再绑定原厂商引擎——
  Menon "多模式组合"（✅ 简介原文）在消费侧的实现。
- **指标层独立产品化**：dbt Semantic Layer/Cube 等中间层在 2023-2026 壮大，
  §4 的语义层从"BI 工具属性"变成独立基础设施（⚠️ 转述；dbt 双册为波6兄弟——
  登记不链）。
- **服务侧可观测**：查询级 P95、并发、成本三大指标的端点内建仪表盘化，
  与 #226 册（实链，06 章 §6 处）共同构成服务运行面基线。
