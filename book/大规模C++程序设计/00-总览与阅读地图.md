## 三条阅读主线

1. **物理设计主线（全书脊柱）**：`02` → `03` → `04` → `05` → `06`。
   组件是原子、层级是骨架、破环是手术刀、防火墙是减重手段、包是治理单元。
2. **可测性暗线**：`03`（隔离测试/增量测试）→ `09`（组件测试驱动与 BDE 实践）→ `10`（卷一"为测试而设计组件"章）。
   Lakos 的立场是：**物理设计的质量用"可测性"来度量**，这是全书最常被忽略的主张。
3. **逻辑/物理分界主线**：`01`（问题域）→ `07`（逻辑设计三章）→ `08`（附录专题）。
   逻辑设计管"是什么"（is-a/契约/抽象），物理设计管"怎么摆"（include/链接/层次）。

**最短工程路径（要给项目落地用）**：`02` → `03` → `05` → `06`，再按痛点回读 `04`/`09`。
**纯现代视野路径（只想知道今天还有什么用）**：`01` → `10`，再选读 `05`/`04`。

## 本书定位与接续关系

- **定位**：C++ 大规模工程**物理设计**的奠基之作——第一次把"文件怎么切、头文件谁包含谁、
  依赖图不许有环、按层发布与回归"上升为与逻辑设计（类图/契约）平权的一等设计维度。
  侯捷系谱讲"对象模型"（见 [../深度探索C++对象模型.md](../深度探索C++对象模型.md)），Lakos 讲"包含模型"。
- **产业源头**：作者自 1987 年用 C++，长期在 Bloomberg 领导 **BDE（Bloomberg Development Environment）**
  基础库团队；书中规则即 BDE 工程规范的理论化。BDE 已开源（github.com/bloomberg/bde），
  是检验本书每条款的活样本（详见 `10`）。
- **接续**：2019《Large-Scale C++ Volume I: Process and Architecture》以 C++11/14/17 重写并扩展全书
  （新增"破除物理循环"专章、性能章、开源开发章）；作者另有《Upgrading C++》（O'Reilly，2021 ⚠️ 未逐字核实）。
  读法建议：1996 版练"思想手术"，卷一读"现代化定稿"。见 [10](10-2019卷一与新语言特性的接续.md)。

5. pimpl、值句柄、抽象接口、抽象工厂分别隔离了耦合的哪一层？代价是什么？（`05`）

| 逻辑设计 | logical design | 类、函数、数据结构及其契约与继承关系的设计 | 01、07 |
| 大 M 设计 | big-M design | 以千文件/百万行为量级思考设计后果的视角（对应小 m） | 01 |

| 翻译单元 | translation unit | 预处理输出+源文件的可编译整体；C++ 独立编译的最小物理单位 | 02 |
| 组件 | component | `.h`+`.cc`+测试驱动的闭包，重用、物理依赖与独立测试的最小合法单位 | 02、09 |
| 单元 | unit | 仅指文件层面的编译产物，比组件弱一层的历史概念 | 02 |
| 包含卫哨 | include guard | 防同一头文件在一个翻译单元内展开两遍的宏；须全局唯一 | 02 |
| 冗余包含卫哨 | redundant include guard | 90 年代为省预处理时间的每文件二次卫哨，现代视为反模式 | 02 |

| 物理依赖 | physical dependency | 编译/链接某文件前必须先把哪些文件纳入构建闭包，含"编译期复制类型布局"的隐式传递 | 02、03 |
| 逻辑依赖 | logical dependency | 概念使用关系（A 的接口提到 B），无 include 也可成立 | 02 |
| 隐含依赖 | hidden/implicit dependency | 由内联展开、默认实参、模板体等间接造成的 include 依赖 | 02 |
| 依赖提取 | dependency extraction | 删掉可换前置声明/可移动的 include，把物理依赖削到最小 | 02 |
| 物理层 | physical level | 组件的非负整数编号：其依赖全在更低层；层内互不依赖 | 03 |
| 层级化 | levelization | 把物理依赖图整理成有向无环图并编号的过程（动词化书名概念） | 03、04 |
| 累积组件依赖 | accumulated component dependencies | 底层组件被上层多少个组件间接依赖的计数，度量变更爆炸半径 | 03 |
| 隔离测试 | isolated testing | 只链接被测组件与其 .cc，不引入任何真实被测者，验证其自足性 | 03、09 |
| 增量测试 | incremental testing | 按层自底向上排测试日程：第 k 层开工前 0..k-1 层已测 | 03、09 |
| 基于使用的测试 | usage-based testing | 用"最小合法用法 + 最大合法用法"驱动测试用例设计 | 09 |
| 组件测试驱动主程序 | component test driver | 组件自带的可执行回归程序，是组件的第三份必备文件 | 02、09 |
| 聚合循环/累积循环 | accumulation cycle | 同层/近邻组件互相纠缠、依赖随版本持续累积的慢性病 | 03 |
