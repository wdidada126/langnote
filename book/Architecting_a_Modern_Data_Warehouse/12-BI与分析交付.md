## 12.1 BI 栈的分层：从仓库到「谁在何时看什么」

现代 BI 栈四件（⚠️ 通说重构，书中框架推定）：
- **连接/取数**：直连仓/湖仓表 vs 抽取到模型（导入模式）——两模式在 Power BI（✅
  https://learn.microsoft.com/en-us/power-bi/fundamentals/power-bi-overview）与
  QuickSight（✅ https://docs.aws.amazon.com/quicksight/latest/user/welcome.html）均有对位件 ⚠️；
- **语义层**：度量/口径/角色的定义处——Bill Inmon「集成」与 Ralph Kimball「一致性维度」的当代载体
  （上游实链：[../Building_the_Data_Warehouse/11-关系模型与多维模型.md](../Building_the_Data_Warehouse/11-关系模型与多维模型.md)）；
- **可视化/仪表板**：前台交互本体（摘要 ✅「front end of user interactions」）；
- **分发/嵌入式**：门户、订阅、embed——民主化的最后一公里（10 章「可达」件的工具化）。

多云 twist：两云 BI 各服务各云主场数据+跨云需求经 04 章联邦面/05 章产品出口取数——
**BI 不出跨云直连神话**（出云费+身份双账，11.5 最小切片原则的交付版）。

## 12.2 双云 BI 对位表（⚠️ 通说 + ✅ 双入口）

| 维度 | Power BI 族（Azure） | QuickSight 族（AWS） |
|---|---|---|
| 建模语言 | DAX/Power Query（⚠️ 名目） | 计算字段/SPICE（⚠️ 名目；✅AWS7） |
| 语义资产位置 | 数据集/语义模型（Fabric 化 ⚠️✅AZ7 域） | 分析/数据集分层（✅AWS7 域） |
| 仓直连 | Synapse/专用池直连系 ⚠️✅AZ8 | Redshift 直连+Data API 通道 ⚠️✅AWS1/AWS9 域 |
| 湖探查 | serverless 池⇄导入混合 ⚠️ | Athena 直连（联邦税=按扫描账单，🔧G1 复引） |
| 民主化接口 | 自助应用+治理租户指标 ⚠️✅AZ4 | 自助数据集+IAM 权限面板 ⚠️✅AWS7 |
| 成本心智 | 容量 SKU/许可族 ⚠️ | 按会话/容量 ⚠️ |

选型口径与 03 章同构：**按「身份与仓的主场」选 BI 主族，另一云留轻量出口**——
两族全部署=两套语义层漂移风险（10 章「单一事实」在 BI 侧的破窗 ⚠️）。

## 12.3 自助 BI 的治理闸门（摘要 ✅ 接缝的展开）

Ch7 摘要 ✅ 明言自助依赖 BI 工具赋能，10 章民主化的三幻觉在此配闸：
- 发现闸：已发布报表登记回目录中心（10.2 投影件），口径文档随产品合同走（06 章可供性）；
- 质量闸：报表数据源只允许指向 silver/gold 层与认证产品（🔧G3 分层纪律的出口版，
  直连 bronze=闸门一票否决项 ⚠️）；
- 安全闸：行级/列级策略在语义层执行一次、仪表板继承（11.2 RLS/DDM 的交付面投影），
  导出/下载白名单化（11.5 最小切片）。

## 12.4 从仪表板到决策闭环（⚠️ 通说）

- **动作化**：告警订阅/阈值回写编排（07 章事件触发端的反向使用 ⚠️）；
- **指标平台化**：企业指标清单（metrics store）出现于两云文档视野 ⚠️——语义层的再一次上移，
  12.1「定义处」从工具内挪到目录实体（10 章血缘的消费账在此补全）；
- **AI 前台**：自然语言问答/增强分析（⚠️ 转述通说；成书期两云均已有对话式问询件名目，
  专页未逐一验真——登记）：01 章「G6 对话式分析期」预言的兑现件。

## 12.5 🔧 复引 G1/G3：BI 查询的湖上成本形状（非平台行为）

- 仪表板刷新=同谓词高频重复查询——🔧G1 的 12.2× 联邦税若乘刷新频率即「直连湖的账单曲线」；
  处方=导入模式/物化视图/结果缓存三件（⚠️ 两云 BI 均有对位件，12.2 表）；
- 口径漂移=「同指标两名」——🔧G3 的 silver 唯一去重表作为语义层底座的类比：
  一份 truth 表供 N 个仪表板，N 份加工表必漂移（仓库「集成」特征的 BI 侧表述）。

## 12.6 本章学习检查点（⚠️ 推定）

1. 默写 BI 栈四件并指出多云下唯一不做跨云直连的一件（语义层须主场单源）；
2. 三闸门各配一个 10/11 章的承接实体（目录/契约/RLS）；
3. 用 🔧G1×刷新频率解释「直连党 vs 导入党」争论的成本真相与折中件（缓存/物化）。

## 12.7 BI 运维成本速查（⚠️ 通说重构）

| 成本项 | 控制杆 | 锚 |
|---|---|---|
| 直连扫描账单 | 刷新频率×谓词宽度（裁剪） | 🔧G1/G2 |
| 抽取存储 | 加速容量预算与 TTL | 12.2 |
| 闲置许可/容量 | 用量排序+季度退役 | 10.1 幻觉② |
| 跨云消费出云 | 产品粒度最小切片 | 11.5 |
| 语义双头维护 | 主族唯一语义层裁定 | 12.2 末 |

季度成本评审五项 owner 应不同人——行列分离是「治理平衡光谱两端」（摘要 ✅）的运营化。

## 12.8 语义层治理八规则（⚠️ 编者注，10 章闸门工具版）

1. 度量只在语义层定义，仪表板禁止重定义核心度量；
2. 每指标配 单位/时间粒度/维度白名单 三标注；
3. 语义模型变更走契约版本 bump，消费方订阅通知（06 章产品化）；
4. 角色级权限只开模型对象不开物理表（11.5 继承链）；
5. 跨云指标出口=产品合同+缓存双检（12.5 账单曲线）；
6. 指标清单单一源，目录投影承接（10.8 lineage_down 字段）；
7. 废弃走日落窗，禁静默删除；
8. 季度口径漂移抽检样本=新报表∪低使用报表（10.1 幻觉①的 BI 变体检测）。

八条即「单一事实来源」承诺（01 章速览十术语之一）在交付面的落地细则。

## 12.9 收束三问（全书出口章，自测 ⚠️）

1. 你司 BI 主族定了吗？两族并存的语义漂移预算是多少（12.2 末）；
2. 语义层八规则（12.8）现在跑通几条？不足四条，先别上对话式问询（12.4——AI 会把
   没有的治理放大成更快的错误）；
3. 从 01 章概念史到本章出口：把「单一事实来源」用你司一个真实指标讲成三分钟故事
   （定义在语义层/来自 gold 层/审计可回——01/05/11 三章合卷检验）。

BI 章即全书验收现场：前面十一节搭的每一层，都在这张仪表板上被用户看见或被用户绕开。

## 最新演进与工业实践

- **Fabric 语义模型成为微软侧新中心**（2023–2026 ⚠️；✅ https://learn.microsoft.com/en-us/fabric/get-started/microsoft-fabric-overview 与 https://learn.microsoft.com/en-us/power-bi/fundamentals/power-bi-overview 双现行页）：Power BI 的「数据集」升格为组织级语义模型并与仓/湖件同门面——12.1 语义层一行的当代形态；Fabric 专深归波内兄弟册（#218/#220/#191 登记不链，00 §5）。
- **QuickSight 的对话式与仪表板付费墙重构**（2023–2025 ⚠️ 转述；✅ https://docs.aws.amazon.com/quicksight/latest/user/welcome.html 现行能力叙述）：Q&A 自然语言件与按会话计费的弹性出口强化 12.4 两趋势——成本心智行（12.2）在 2026 比成书快照更细。
- **仓侧直连语义升级**（⚠️；✅ https://docs.aws.amazon.com/redshift/latest/mgmt/welcome.html 域含 BI 集成叙述）：Zero-ETL+Data API+共享让「仓⇄BI」通道托管化，12.5 账单曲线整体下移；湖侧仍以导入/缓存为主（🔧G1 税形不变）。
