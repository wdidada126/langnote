## 3.2 MPP 内核机制的通约（⚠️ 转述，三巨头对位表联动）

盘上 [../Amazon_Redshift_TDG/00-总览与阅读地图.md](../Amazon_Redshift_TDG/00-总览与阅读地图.md) §4
三巨头对位表已把「计算/存储、物理设计」两行写透——本册只补多云通约三条：

- **分发/聚簇是第一公民**：Redshift DISTKEY⇄Synapse 哈希分发列⇄Snowflake 聚簇键，同属
  「让 JOIN 键共置以消 Shuffle」一族；多云蓝图必须为每个重 JOIN 事实表记「双云两份布局方案」。
- **弹性模型不可平移**：RPU 自动扩缩 ⇄ DWU 手动档位 ⇄ Snowflake credit 秒计 ⇄ BQ slot——
  成本仿真工具要按云各配（Tuning 册 [../Tuning_the_Snowflake_Data_Cloud/06-虚拟仓库.md](../Tuning_the_Snowflake_Data_Cloud/06-虚拟仓库.md) 是 credit 侧最优读法；BigQuery 册 [../BigQuery_for_Data_Warehousing/02-数据盘点与成本管控.md](../BigQuery_for_Data_Warehousing/02-数据盘点与成本管控.md) 是 slot 侧）。
- **微分区/列存/zone map 是跨引擎公约数**：见 [../Tuning_the_Snowflake_Data_Cloud/04-微分区.md](../Tuning_the_Snowflake_Data_Cloud/04-微分区.md) 的有序/乱序 11× 对照——本册 🔧G2 用分片文件给出同方向的「裁剪税」侧写。

## 3.3 🔧 实测 E-G2：分片布局的裁剪收益（DuckDB 1.5.5，非本书引擎行为）

脚本 `D:\develops\tmp\dbwave_w9_amdware\demo2.py`。150 万行按 `k%6` 切成 6 个分片 Parquet 文件：

| 查询方式 | 用时 | 备注 |
|---|---|---|
| 谓词可证伪 5 片→只扫 1 片（文件名裁剪） | **3.3ms** | 等价 MPP 分发列 JOIN 共置后的「片内命中」 |
| 谓词不可裁剪，6 片全扫 | **5.2ms** | 裁剪收益 1.6×——小数据集上偏窄，规模放大后收益按片数增长 |
| 结果一致性 | rows-equal=True | 两种路径同行数同和值 |

解读 ⚠️：真实 MPP 的 shard 数（20–160 级）远大于 6，且带网络 Shuffle 项——分片对
「高选择率点查+共置 JOIN」的收益在云上通常数倍于此。本数字仅证**方向**，不可换算成
Synapse/Redshift 的任何 SLA；单机粒度、无网络、无并发的三重失真声明同盘上惯例 📐。

## 3.4 选型决策树（⚠️ 重构，书中立场推定）

```
已有 T-SQL 资产重? ──是──> Azure: Synapse 专用池(F1) 优先
      │否
双云已并存? ──否──> 单云深耕路线(让位三巨头册+盘上专册)
      │是
湖上 AI 负载占比高? ──是──> F3 双云各立(Databricks/AWS+Glue) + 表格式统一(05章)
      │否
报表出口统一诉求强? ──是──> F4 倾向(Fabric 化评估，登记波内兄弟册不链)
      │否
默认: F1 主仓 + F2 探索面 双形态并行
```

每个分支的暗题都是 2.3 的 D3 三难题：出云费模型、目录一致性、身份贯通——
选型时把三道暗题的答案写进同一页，才算完成多云选型（⚠️ 本书企业视角推定）。

## 3.5 「客户期望」侧的形态演化压力（摘要 ✅ 词句的展开 ⚠️）

Ch2 摘要 ✅「customer expectations increase with each passing year」三点通说展开：
①新鲜度从 T+1 到分钟级——形态压力=流式摄入进仓（09 章 Kinesis/DMS 路径）；
②交互从报表到自助——形态压力=语义层前移（12 章）；③可信从抽样审计到全链路血缘——
形态压力=治理内建（10/11 章）。**期望升级不改变仓库定义，只改变其交付界面**（01 章结论在此收口）。

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| MPP | Massively Parallel Processing | 多节点分片并行执行，F1 族的共同内核 |
| 存算分离 | Separation of Storage and Compute | 弹性扩容解耦——云仓一代主线 |
| 分发列/分布键 | Distribution Key | JOIN 键共置消 Shuffle 的布局原语（DISTKEY/哈希分发列） |
| 无服务器查询 | Serverless Query | 零供给按量计费探索面（Athena/serverless 池） |
| DWU / RPU | Data Warehouse Unit / Redshift Provisioning Unit | 两云各自的算力计费单位（对位表行「计费心智」） |
| 数据共享 | Data Sharing | 仓间实时互读原语（Snowflake Share/Redshift Datashare） |
| 形态选型 | Warehouse Archetype Selection | 本册 3.1 五形态按负载分层选择 |
| 出云费模型 | Egress Cost Model | 跨云搬运的月度账，选型暗题① |
| 语义层前移 | Semantic Layer Shift-Left | 口径定义离用户更近、离仓库更远（12 章） |
| 交付界面 | Delivery Interface | 期望压力作用的位置；仓库定义不变（3.5） |
