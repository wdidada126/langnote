## 核心精讲

### 1 系统形态（7.1）
Amoeba 的目标形态：用户面前只有哑终端，算力在**处理器池**（a rack of processors）里动态分配——
这正是 [03-进程与线程.md](03-进程与线程.md) 4.2 节处理器池模型的完全体。组成：
- **微内核**：每个机器上跑同一份 Amoeba 内核，只管线程调度、内存、IPC。
- **服务器**：文件、进程、目录、时钟、随机数等全部是用户态进程。
- **Shell 终端**：会话入口，进程在池中机器上被创建，用户无感。

Amoeba 的**进程服务器（process server）**值得一节笔记：任何客户端（只要权能允许）
都可以请求「在某台池内机器上运行这个可执行文件 + 这段进程描述符」——
创建进程本身是一个分布式系统调用。进程描述符（segment 段表、线程栈、权能集）
与 Mach 的任务/线程抽象（[08-案例-Mach与Chorus.md](08-案例-Mach与Chorus.md)）
是同一代「进程可序列化」思潮的两份答卷；2026 年回看，它就是容器
（可复制的运行时描述 + 镜像）的 1990 年代直系祖先。

### 2 权能：Amoeba 的灵魂（7.2）
客户端访问任何资源（文件、进程、信号量……）都必须持有 128 位**权能**：

```text
/* 教学示意，不参与构建：Amoeba 权能布局（128 位）。 */
+--------------+-------------+------------+----------------+
| Server port  | Object #    | Rights     | Check field    |
| （服务器定位）| （对象号）   | （权限位）  | （校验字段）    |
+--------------+-------------+------------+----------------+
```

- **创建**：服务器生成随机 **Check** 字段 C 并自己保存；权能里直接携带 C。
- **验证**：客户请求到达时，服务器比对权能内 C 与保存值。
- **缩权派生**：客户请求「给一个只读权能」，服务器发回 `f(C, 新权限掩码)`（f 为单向函数），
  服务器存原始 C；验证时对收到的字段再做一次 f 比对即可——**不需要任何密钥分发设施**。
- **定位**：Server port 广播定位服务器（LAN 内），或目录服务器查（WAN）。
  与 [04-命名.md](04-命名.md) 权能一节互为印证。

### 3 Bullet 服务器：不可变性换一致性
Bullet（子弹）服务器只提供**创建不可变文件**与**读取**：文件一旦写入不可修改，
修改即生成新文件并返回新权能。收益：
- 无需写锁与并发控制；副本可以随意复制（内容永不冲突）；
- 垃圾靠引用计数回收。
这与 2026 年的内容寻址存储（Git 对象库、容器镜像层、IPFS）是同一个设计决策——
「不可变 + 内容寻址」是分布式一致性最便宜的解法。

### 4 FLIP 与组通信
FLIP（Fast Local Internet Protocol）为「进程」而非「机器」寻址：进程迁移后连接不断；
同时支持不可靠组播与可靠组播，把 [02-分布式系统中的通信.md](02-分布式系统中的通信.md)
2.5 节的组通信直接做进网络层。Amoeba 的分布式编程课实验（基于组通信的并行棋类搜索等）
是 1990 年代分布式 OS 教学的名场面。

FLIP 的「按进程寻址」有两个直接收益，读时可以展开：

1. **迁移透明**：进程从池内机器 A 迁到 B，通信连接不断——TCP（按主机+端口）做不到；
2. **组播自然**：组是进程集合而非机器集合，可靠组播的成员管理跟着进程走。

代价是自建协议栈（要与当时所有现成 IP 软件共存）——Amoeba 团队选择
「FLIP 封在 IP 之下/之上均可」的务实设计。**为分布式 OS 专门造网络层**这件事
成也专精、败也生态：2026 年没有人为「自己的 OS」造传输层了，QUIC 是
「为整个互联网造传输层」的最后一次尝试。

### 5 务实层：Rand 服务器与 Unix 仿真
权能校验需要大量高质量随机数 → Rand 服务器专门生产；
存量 Unix 程序通过兼容库/仿真层迁移——这与后来 Windows 的 POSIX 子系统、
WSL 的思路如出一辙：**新系统要活，先得兼容旧生态**。

### 6 Amoeba 的目录服务器（第 7 章素材，接 [04-命名.md](04-命名.md)）
权能的获取与共享由目录服务器承担：目录是「名字 → 权能集」的表，
同样以权能保护（能读目录 = 持有目录权能）。跨目录共享、按位掩去权限派生
「弱化权能」、以及把目录复制到多站点（广域可用性）——这三件事让
目录服务器成为 Amoeba 内部「自身也要分布式化」的组件，
也暴露了元数据复制的一致性代价（[06-一致性复制与容错.md](06-一致性复制与容错.md)）。

### 7 Amoeba 的三条教训（原书 CACM 1990 经验论文的要点，本目录自拟归纳）
1. **用户态服务器没有想象中慢**：Amoeba 实测 RPC 往返在 LAN 内达亚毫秒级，
   「服务放内核才快」的直觉被推翻——这条经验直接喂养了后来的微内核阵营。
2. **权能好用但难撤销**：缩权派生优雅，作废已发权能笨拙；最终答案是
   「重新生成对象」级别的暴力手段——短时效凭证（2026）没有出现的原因是
   当年没有足够便宜的时钟同步（见 [05-同步.md](05-同步.md)）。
3. **应用才是生死线**：系统设计堪称优雅，但缺少杀手级应用与生态兼容，
   研究资金枯竭后项目即止。所有「优雅的新 OS」都要回答同一道题。

### 8 Amoeba 权能 vs 传统文件权限：一张完成对读的表

| 场景问题 | Unix（ACL 系） | Amoeba（权能系） |
| --- | --- | --- |
| 「我能不能读这个文件」 | 内核查 inode 权限位 + UID | 检查手上的权能是否含读位 |
| 「借给别人只读」 | 对方需要账号 + 改权限 | 直接给出缩权派生的权能副本 |
| 「对象搬了家」 | 路径失效 | 权能含服务器定位字段，广播/目录解析 |
| 「权限被冒用」 | 依赖账号系统 | 单向函数校验字段，无法伪造 |

读表时注意：权能系把「认证」从基础设施挪进了对象引用本身。
2026 年云存储的预签名 URL 之所以不用先建账号，正是这个思路。

## 版本演进

| 时期 | Amoeba 的状态 | 时代注脚 |
| --- | --- | --- |
| 1981–1990 | 设计与原型（VU），多伦多/阿姆斯特丹多站点部署 | 与 Mach/Chorus 并列的三大分布式 OS 原型 |
| 1990（CACM 论文） | 公布完整经验报告 | 教科书第 7 章的主体即此 |
| 1991–1995 | 研究停止，团队转向教材与后续项目（MINIX 3 的用户态驱动思想与其同源） | 商品化工作站 + TCP/IP 栈让「定制网络层」失去吸引力 |
| 1995（CACM 之后） | 研究停止，团队转向教材与后续项目（MINIX 3 的用户态驱动思想与其同源） | 商品化工作站 + TCP/IP 栈让「定制网络层」失去吸引力 |
| 2015–2026 | 无活跃主线；思想散落各处：权能→seL4/对象存储签名 URL；不可变存储→镜像层/内容寻址；组通信→共识组 | 「输了产品，赢了思想」 |

读本章的推荐姿势：**把第 7 章当「设计决策目录」读，不当系统介绍读**。
Amoeba 的每个机制都是一个「如果从零设计分布式 OS，X 应该怎么做」的参考答案：
- 资源访问怎么做？→ 权能
- 文件一致性怎么做？→ 不可变（Bullet）
- 网络层怎么做？→ 按进程寻址（FLIP）
- 计算资源怎么组织？→ 处理器池（[03-进程与线程.md](03-进程与线程.md) 4.2）

四问四答都拿到了，原书第 7 章的目的就达到了——它本来就不是让你去用 Amoeba 的。

## 近年研究与工业界开源实践（2015–2026）

- **微内核血统的现代直系**：seL4（`seL4/seL4`，5766★，2026-09-26 实测）以形式化验证的
  **权能访问控制**继承 Amoeba 的安全观；QNX（闭源，车载实时）延续微内核 + 消息传递路线；
  Google Fuchsia（GitHub 无主仓，**star 未核验**）在消费者设备上重试微内核 OS。
- **不可变存储的产品化**：容器镜像层（`containerd/containerd`，21335★）与 OCI 分发都是
  Bullet 式「只写不改 + 哈希寻址」；对象存储的预签名 URL 是「权能=可校验访问凭证」的
  无状态翻版。
- **广域权能的对照**：Macaroon（凭证派生/缩权）与 SPIFFE（服务身份）是「可派生、可缩小
  权限的凭证」谱系在现代安全栈中的延续。
- **Plan 9 的平行宇宙**：同为「资源全部网络化」的实验 OS，Plan 9 用 9P 协议把一切做成文件
  （`9fans/plan9port`，1958★）；与 Amoeba 的权能路线互为镜像，两者都没有赢，但 9P 活在
  虚拟化与容器挂载的角落里。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「Amoeba 是 Unix 的变体」 | 它是完全自研的分布式 OS，只有兼容层为了跑 Unix 程序 |
| 2 | 「权能就是指针」 | 权能同时完成命名、定位、授权三件事，且可验证、可缩权派生 |
| 3 | 「Bullet 服务器只是文件服务器」 | 它的不可变性是系统级一致性策略，不是存储特性 |
| 4 | 🔧 **原书对 Amoeba 的性能数字与机器规模已无意义** | 2026 年读法：只读架构决策与权衡；性能问题直接对照现代 RPC/存储基准 |
| 5 | 🔧 **「哑终端 + 处理器池」形态要重述** | 现代等价物是「浏览器 + 云算力池」；算力租借的单位从 Amoeba 进程变成容器/函数 |
| 6 | 🔧 **Amoeba「死了」≠ 白做了** | 其微内核、权能、组通信、不可变存储四条思想线在 seL4/Fuchsia、对象存储、共识组、镜像层全部有现役继承者 |
| 7 | 「Amoeba 的 RPC 语义与 TCP 一致」 | Amoeba 用 FLIP 自带可靠传输与组播语义，超时/重传策略面向「进程对」而非「连接」——读第 7 章时别套 TCP 直觉 |
