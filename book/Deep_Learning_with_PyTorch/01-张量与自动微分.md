## 核心机制

### Tensor = 带设备抽象的多维数组

- `torch.Tensor` 是类型化 n 维数组 + 设备位置（CPU/CUDA）双属性对象；dtype/device 显式建模，跨设备运算拒做隐式搬运（✅）。
- 对照 Java：JDK 无原生 n 维数组抽象（`int[][]` 是数组的数组、行不连续）；对照 numpy（库内 [../PythonDataScienceHandbook2e.md](../PythonDataScienceHandbook2e.md) 一线）：numpy 的 `ndarray` 有 stride 无 device 维度——PyTorch 等于「ndarray + 显存语义」的并集（✅ 概念口径）。
- 对照 d2l：[../DiveIntoDeepLearning.md](../DiveIntoDeepLearning.md) 张量章 API 常新，本书该节写法 2020 截点，读时对照（⚠️ 差异清单欠账）。

### 存储与视图：零拷贝的代价

- 多个 Tensor 可共享同一底层 Storage：切片、`view/reshape`、转置返回**视图**而非拷贝，原地写互相可见（✅）。
- 对照 C++：`std::span`/Eigen 表达式的不占有视图模型同构——视图是非 owning 引用，生命周期由 Storage 引用计数兜底；对照 Java：数组传引用同样共享，但 Java 老兵容易把 `t.clone()` 与 `view` 混淆，两者语义分别是深拷贝与别名（✅）。
- 视图的成立条件是 stride 兼容：不连续张量上 `view` 抛错、`reshape` 可能悄悄复制——静默复制是性能陷阱（✅）。

### autograd：运行期反向 tape

- 前向每个算子在 `requires_grad=True` 的叶子间织出动态 DAG，`.backward()` 沿 tape 反向累积梯度到 `.grad`（✅）。这是「动态图」的官方定义级机制，不是营销话术。
- 对照 C++ 表达式模板（Eigen 路线）：编译期把 `a+b*c` 融成单循环是**静态**组合；PyTorch 反其道在**运行期**记 tape，换来 Python 控制流自由——两家在「何时决定计算图」上分居光谱两端（✅ 概念口径）。对照 TF1 静态图（库内 [../ProgrammingTensorFlow2.md](../ProgrammingTensorFlow2.md)）：先建图后喂数据 vs 边跑边记。
- `Variable` 遗迹：0.4 起 Tensor 与 Variable 合一（✅ 官方文档），书中若仍写 `Variable` 包装即历史层，学概念可以、抄代码不行 ⚠️。

## 批判读法（易错与存疑）

1. **梯度累加不加清零**：`.grad` 默认累加而非覆盖，忘 `zero_grad` 是新手第一坑；书里节奏是否反复强调 ⚠️ 凭记忆待核。
2. **detach 与 no_grad 混讲**：前者切断视图谱系出图，后者关录制，语义不同；含糊即缺口。
3. **in-place 与 autograd 的冲突**：tape 上前向输出可能被反向复用，原地写会报「版本不符」错误（✅）——书中该警告的位置 ⚠️ 未核。
4. **`view`/`reshape` 不分**：见上「静默复制」，教学书此处必须给判别实验。
5. 花书（[../深度学习_花书.md](../深度学习_花书.md)）第 6 章给反向模式的数学，本书给工程实现——先读哪本都行，但别把两本的符号体系混抄。

## 核心概念中英对照

- **张量** — tensor：带 dtype/device 的类型化 n 维数组。
- **存储** — storage：底层一维连续内存，多张量可共享。
- **视图** — view：共享 storage 的零拷贝别名，非独立张量。
- **自动微分** — autograd：运行期录制前向 tape、反向传播梯度。
- **计算图** — computation graph：动态 DAG，随代码执行即时成形。
- **叶子节点** — leaf node：`requires_grad` 的源头张量，梯度落点。
- **梯度累加** — gradient accumulation：`.grad` 不清零即跨步相加。
