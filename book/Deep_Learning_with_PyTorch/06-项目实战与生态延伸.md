## 核心机制

### 项目三件套：数据、模型、检查点

- 书中项目模式 = 前面机制章的组合演习：数据管线（03/04）→ 训练循环（02）→ 调优（05），配检查点续训（✅ 概念口径）。
- 持久化定式：存 `state_dict()`（参数名→张量的有序字典）而非整个模型对象；整模型 pickle 连类定义拓扑一起序列化，重构性差且 ⚠️ 官方文档明确警告 pickle 反序列化任意代码的安全面（✅）。
- 对照 Java：`state_dict` 是「数据与代码分离」的序列化——类似只存字段值不存类字节码；整模型 pickle 则近似 ObjectInputStream 全对象图序列化，连带享受其反序列化 RCE 前科 ✅。Kotlin 侧 `kotlinx.serialization` 强制 schema 化，两家文化对「序列化即信任边界」的成熟度差异可作读书时的心灵对照（库内 [../Kotlin_in_Action_2e/00-总览与阅读地图.md](../Kotlin_in_Action_2e/00-总览与阅读地图.md) 一系，文本级对照）。

### 生态版图：官方家族与外围

- `torchvision/torchaudio/torchtext` 官方卫星包 + `Hub` 预训练权重分发 + ONNX 导出互操作（✅ 均为官方文档在盘件）；书中 2020 收 TorchScript 初介 ⚠️ 详略未核，其部署线（script/trace→Mobile）后续演化大。
- 对照库内他书：Chollet（[../DeepLearningWithPython2e.md](../DeepLearningWithPython2e.md)）站在 Keras 抽象上看生态，本书站在框架内部看生态——同一批包、两个纵深；TF 阵营对位见 [../ProgrammingTensorFlow2.md](../ProgrammingTensorFlow2.md)。
- 生态延伸判词（本仓裁决）：torchtext 边缘化、Transformer 接管 NLP 是 2020 后事实（✅ 社区共识级）；书中相关投资按历史读。
- 对照 C++：state_dict 的「权重与拓扑分离」近似序列化只存数据 + 注册工厂重建对象图，拒绝把类布局写进存档——两种语言在「不可信字节流能携带多少代码」上给出同构答案（文本级对照，不引原句）。

## 批判读法（易错与存疑）

1. **项目年代感**：书的项目体量（猫狗/文本分类级 ⚠️ 凭记忆）2026 已无工程含金量，价值在「完整走通机制链」的教学闭环，不在产出物。
2. **map_location 细节**：GPU 存的权重在 CPU 机器加载会炸，`torch.load(..., map_location=...)` 是该节必考知识点 ✅；书是否前置强调 ⚠️ 未核。
3. **state_dict 与 optimizer 成对存**：只存模型丢动量状态，续训不等于连续——检查点「全家桶」清单（model/optimizer/scheduler/rng/epoch ✅ 口径）书里点到哪层待核。
4. **ONNX 导出的动态维/算子覆盖坑**：书中演示级用法 ⚠️，真实导出务必对照现行 opset 文档。
5. 别把「生态巡礼章」读成生态现状：2026 版图为 torch.compile/PyTorch 2.x、Hub→torch.hub 与 ecosystem 重组 ⚠️，以 pytorch.org 为准逐件销账。
6. **fine-tune 与 from-scratch 的成本账**：书中项目偏爱小数据集全训练 ⚠️ 凭记忆；2026 口径是先问预训练权重能否直接换头，机制课练手之外的真实项目少从 zeros 起步。

## 🔧 微实验位（未实测：本机未装 torch，仅为设计）

- 实验 A：分别 `torch.save(model)` 与 `save(model.state_dict())`，跨类重构后加载，实证 state_dict 韧性。
- 实验 B：训练中途存「全家桶」检查点，重启进程续训，比对 loss 曲线无缝。
- 实验 C：小模型 `torch.onnx.export` 动态 batch 维导出，用 ONNX Runtime 对拍输出（需装环境，挂账）。
- 实验 D：GPU 训练存权重后在 CPU-only 机器 `torch.load` 不加/加 `map_location='cpu'`，复现加载报错与修复，坐实跨设备坑。

## 核心概念中英对照

- **状态字典** — `state_dict`：参数名到张量的映射，模型持久化正解。
- **检查点** — checkpoint：模型+优化器+调度器等训练态快照。
- **反序列化安全** — deserialization safety：pickle 加载不可信文件的代码执行面。
- **权重 hub** — torch.hub：预训练权重与函数的分发机制。
- **脚本化** — TorchScript：脱离 Python 解释器的模型表示与部署线。
- **交换格式** — ONNX：跨框架模型互导的中间表示。
- **续训** — resume training：从检查点接回训练态而非冷启动。
- **生态卫星包** — torchvision/audio/text：官方分域扩展库。
