## 核心机制

### nn.Module：一个会自注册的容器

- 子类化 `nn.Module`，赋值为 `nn.Parameter` 的属性被自动收进 `_parameters` 注册表，子模块收进 `_modules` 树；`.to(device)` 递归搬运全树、`parameters()` 供优化器（✅）。
- 对照 Java/Kotlin：这套「赋值即注册」靠 Python 属性协议拦截，语义近似 Kotlin 委托属性（库内 [../Kotlin_in_Action_2e/05-数据类与委托.md](../Kotlin_in_Action_2e/05-数据类与委托.md) 讲的 by delegate——同样是把 set/get 重定向进框架存储）；工程生态对照 Spring 的注解扫描注入：容器托管对象图、按图递归操作（初始化/搬运/序列化），只是 PyTorch 用协议代替了注解。
- `forward()` 不是被调用而是被 `__call__` 包装触发，以便挂 hook（✅）——直接调 `net.forward(x)` 绕过钩子链，是 Java 人最容易习得的坏习惯。

### 损失与优化器：解耦的三个角色

- 模型（造图）、损失函数（评判）、优化器（更新）三者正交：`SGD/Adam` 只认「参数组 + 梯度」，不认识模型（✅）。
- 对照 C++/Java：策略模式的标准三件套；Keras 的 `compile(loss=..., optimizer=...)` 把三角色焊进黑箱（[../DeepLearningWithPython2e.md](../DeepLearningWithPython2e.md)），本书刻意手工展开——这是「机制纵深」定位的核心教学动作。

### 训练循环五拍

- 定式：前向 `out=net(x)` → `loss=criterion(out,y)` → `opt.zero_grad()` → `loss.backward()` → `opt.step()`（✅ 官方教程同构）。
- 节拍可读可断是 eager 的优点：每拍都能 print/调试；对照静态图「整图编译后不可打断」的调试断点缺失（[../ProgrammingTensorFlow2.md](../ProgrammingTensorFlow2.md) 一代的痛点）。
- epoch/batch 双层循环 + `DataLoader` 迭代器抽象（✅）：Python 迭代器协议天然对接，对照 Java `Iterator` 拉取模式同构。

## 批判读法（易错与存疑）

1. **zero_grad 三写法**：`opt.zero_grad()` / 逐参数清 / 新版 `set_to_none` 默认化（✅ 后续版本事实），书止于 2020 ⚠️ 未涉——照抄即折旧。
2. **train/eval 模式**：`model.eval()` 与 `torch.no_grad()` 是两回事（前者切 BN/Dropout 行为，后者关录制 ✅）；书中是否讲透 ⚠️ 凭记忆，读 03 章 BN 时回查。
3. **模块注册陷阱**：普通 list 装子模块不会被 `_modules` 收录（`nn.ModuleList` 才行 ✅），属性循环里的静默丢参数是经典事故。
4. 「手工循环」的教学价值建立在读者真的手打上；只读不练等于没学——但本机无 torch，🔧 挂账。
5. 书中该部项目案例（MNIST 走向 ⚠️ 凭记忆）与 d2l（[../DiveIntoDeepLearning.md](../DiveIntoDeepLearning.md)）逐层实现章对照读，机制 + 数学两条腿。

## 核心概念中英对照

- **模块** — `nn.Module`：可注册参数、可组合、可搬运的计算单元。
- **参数注册** — parameter registration：赋值即入 `_parameters` 的协议魔法。
- **前向传播** — forward pass：`__call__` 包装下执行 `forward`。
- **损失函数** — loss/criterion：输出到标量惩罚的映射。
- **优化器** — optimizer：按梯度原地更新参数的策略对象。
- **训练循环** — training loop：五拍定式的外层 epoch/batch 嵌套。
- **评估模式** — eval mode：切 BN/Dropout 行为，与 no_grad 正交。
