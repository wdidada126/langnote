## 核心概念速览（中英对照）

- **IO 对象不可拷贝** — IO objects no copy/assignment：流持有缓冲区状态，按引用传递（`istream& is` 惯型的原理）
- **条件状态** — stream state：`rdstate` 返回 `iostate` 位掩码，`badbit/failbit/eofbit`；`setstate/clear(goodbit)` 复位
- **RAII 式流关闭**：`fstream` 析构自动 close——"离开作用域即释放资源"思想的第一次全面示范
- **输出缓冲** — buffering：endl=换行+flush；`unitbuf` 让每次写都 flush；程序崩溃前未 flush 会丢输出
- **string 流** — string stream：`istringstream` 在内存上复用 `>>`/getline 语法做字段解析；`ostringstream` 拼接格式化输出
- **顺序容器选型五问**：随机访问？头插？中间插？定长？唯一键？——9.1 的决策表是全库容器章总纲
- **`array`（C++11）与 `forward_list`（C++11）**：栈上定长数组的包装；仅单向且带 before_begin 的最省节点链表
- **`at()` vs `[]`**：at 带范围检查抛 `out_of_range`；[] 越界 UB——性能与安全的开关在选型手里
- **emplace vs push** — emplace：原位构造省一次临时对象拷贝/移动；⚠️ 见"定性标注"
- **迭代器失效规则（9.3.6）**：vector 增长全失效/不增长其后失效；deque 中间插两端失效；list/forward_list 永不失效（除被删元素）
- **capacity/size/reserve/shrink_to_fit**：9.4 增长策略三件套；`shrink_to_fit`（C++11）是"请求"非"命令"
- **几何翻倍增长** — geometric growth：均摊 O(1) push_back 的来源；libstdc++ 1.5x、MSVC 1.5x/1.x ⚠️（各实现不同）
- **swap 的线性时间**：容器交换只换内部指针/句柄；`noexcept` 语义（EMC++ 条款14 话题）
- **容器适配器** — adapter：stack/queue/priority_queue 是接口改造不是新容器，默认底层 deque（pq 默认 vector）
- **string 数值转换（9.5.5）** — to_string/stoi/stod（C++11）：stoi 系带异常语义，to_chars/from_chars 是其"无异常高性能"续作

## 小节细目（按原书小节号速记）

### 第8章

- **8.1.1 IO 对象无拷贝或赋值（页279）**：拷贝构造/赋值被 delete——函数形参只能 `istream&`；也解释了为什么"保存流对象进容器"必然失败，想存请用 string 流的内容或路径。
- **8.1.2 条件状态（页279）**：`cin.rdstate()` 三位组合；`cin.clear(file::badbit)` 恢复指定位；`if (cin >> val)` 失败后"清状态+丢垃圾"两拍修复循环（cin.sync() ⚠️5版未教，用 ignore 到换行）。
- **8.1.3 管理输出缓冲（页281）**：刷新时机四条（endl/flush、unitbuf、缓冲区满、另一流关联）；`cin` 与 `cout` 自动关联故读前必 flush——调试"没输出"先想到缓冲。
- **8.2.1 使用文件流（页284）**：`ifstream in(file)`；C++11 起文件名可 `std::string`/字符数组/字面量（新特性小节）；析构自动 close；重用流对象时先 close 再 open 否则失败状态残留。
- **8.2.2 文件模式（页286）**：`app` 追加、`ate` 打开即定位末尾、`in/out/trunc` 组合表；模式一旦设定不可改，只能 close→重开。
- **8.3.1 istringstream（页287）**：ReadPersonInfo 例子——先整行 getline 再字段 >>；str() 换绑新串。
- **8.3.2 ostringstream（页289）**：Person 信息编码成一行；与 8.3.1 配对实现"自定义单行格式"。

### 第9章

- **9.1 概述（页292）**：选型表：array（C++11 定长）/vector/deque/list/forward_list（C++11 单链）/string；"默认 vector"原则出处。
- **9.2.1-9.2.7 概览（页294-304）**：begin/end 家族（含 const 重载选择规则：对象是 const 则拿 const 迭代器）；容器构造/赋值矩阵（`vector<int> v2 = v1;` 列表例外：`{a,b}` 是值拷贝非大小）；`swap` 的 O(1) 与"迭代器跟着资源走"；`max_size/resize` 是"请求"语义。
- **9.3.1-9.3.6 操作（页305-316)**：push/emplace/insert 与"迭代器参数不能指向本容器"警告（v.insert(v.begin(), v) 类 UB）；访问 front/[]/at/back 与 list 无 `[]`；删除 pop/erase（返回下一位）/clear；forward_list 的 before_begin/insert_after 平行宇宙；失效总表+循环 erase 正确模板。
- **9.4 增长（页317）**：size/capacity/reserve/shrink_to_fit 的"请求"措辞；翻倍策略均摊 O(1)；循环 push 前先 reserve 是最便宜的优化。
- **9.5.1-9.5.5 string 补充（页320-327）**：substr/构造子串、insert/replace/`+=`、find 家族（rfind/find_first_of）、compare 与 `==` 的取舍、`to_string/stoi` 系列。
- **9.6 适配器（页329）**：stack（默认 deque）/queue（默认 deque）/priority_queue（默认 vector）；"适配器无迭代器"。

## 自查与面试高频

1. 为什么函数里按值传 `istringstream` 编不过？（IO 对象禁拷贝）
2. `vector<bool>` 的 `operator[]` 为什么不是 `bool&`？（位压缩代理，引用语义受限）
3. list 和 deque 谁支持随机访问？为什么 deque 支持但中间插入仍危险？（两端块+逻辑连续；失效规则）
4. `v.reserve(1000)` 后 `v.size()` 是多少？（0——capacity≠size）
5. map 的 `insert` 与 `operator[]` 在键已存在时的行为差异？（前者忽略、后者覆盖——见 11 章）
6. `splice` 为什么是 list 的"零拷贝搬家"？它对迭代器失效规则的例外是什么？（不搬元素只改链接，被搬元素的迭代器仍有效）
7. `deque` 中间 `insert` 复杂度和失效范围？迭代器为何"可存但一失效全家亡"？（块结构决定；对照 vector 失效仅搬迁点）
8. `vector<int> v{1,2,3}; v = {4,5};` 之后 `v.size()`？（2——列表赋值；`{}` 在赋值语境也是 initializer_list 通道，与 `=` 拷贝赋值区分）
9. `list` 的 `sort` 是成员函数而不是算法，为什么？（泛型 `std::sort` 要求随机访问迭代器；成员版借"链接可改"实现 nlogn 归并且不动元素）
10. `array<T,N>` 比 C 数组和 `vector` 各赢在哪？（零开销+带大小信息+可拷贝比较；栈上定长是性能敏感场景的默认容器）
11. `forward_list` 相对 `list` 省的那份内存具体省在哪？代价是什么？（单链每节点少一个指针；失去 backward 遍历与 insert(pos)——只能 before/after）
12. 为什么"容器内嵌对象 + 只读遍历"首选 `for (const auto& x : c)`，改元素才用 `auto&`？（值遍历静默拷贝+改不到本体，是 03 文件 toupper 事故的容器版）
13. `is >> ws` 和 `getline(is, s)` 组合读"可能空的一行"为什么仍会错？（`ws` 会吞掉换行把下一行提上来；空行语义要 `getline` 后自查 empty——08 文件词频统计的数据清洗细节）

## 8.x IO 库：从"对象"角度重看 cin

**动机**：第1章用了 cin/cout，第8章揭开它们是 `istream/cout` 全局对象、状态机与缓冲区的复合体。

**机制**：`while (cin >> word)` 的本质：`>>` 失败置 failbit → 流对象经 `explicit operator bool`（C++11，替代旧 `void*` 安全 bool 惯型）转 false。`getline(istream&, string&, delim)` 与成员 `getline(char*, n, delim)` 两套别混。文件流三步：定义 fstream、open（或直接构造）、像 cin/cout 用；app 模式写尾部、ate 定位尾部、trunc 清空——5版表格化呈现，记住"默认 out 会截断"这一条就防住 90% 事故。

**相邻概念对比**：`istringstream` 解析 vs 正则解析（17.3）：字段规整用前者、模式复杂用后者；C++11 起文件名可直接用 `std::string`（8.2.1 新特性小节），`filesystem::path` 更进一步（见演进节）。

## 9.x 顺序容器：一张决策表 + 一套失效纪律

**权衡主线**：
- **vector 默认优先**（书的原话精神："除非有明确理由否则用 vector"）；中间频繁插删才 list；头部频繁进出去 deque；定长小对象 array。
- 9.3.1 "添加元素"的三种视角：尾加（push/emplace）、中插（insert 返回新元素迭代器，C++11）、批量（insert 迭代器区间/`{il}`）。
- 失效纪律的实操形式：**循环里 erase 用返回值 `it = c.erase(it)`**；别在 range-for 里改大小。

**机制补充（9.4）**：capacity 翻倍 × size 增长曲线，reserve 预知大小时才用；1000 次 push_back 后 capacity=1024（见 🔧）——libstdc++ 按 2 的幂增长。

## 🔧 实测（已实测 g++ 15.2, -std=gnu++23）

`s07.cpp`：9.4 增长策略、C++20 `std::erase_if`、`std::format` 对 string 流式拼接的替代：

```cpp
for (int i = 0; i < 1000; ++i) grow.push_back(i);
std::erase_if(v, [](int x){ return x % 2 == 0; });   // 取代 erase(remove_if(...), end)
std::string line = std::format("{:->8}|{:08.3f}", "head", 3.14159);
```

```
push_back 1000次后 size=1000 capacity=1024
erase_if后奇数: 5 1 9
----head|0003.142
```

## 最新演进与工业实践（基线 C++11 → 现在）

- **`std::erase / std::erase_if` 自由函数（C++20）**：string/vector/deque 的"按值删除"一站完成（🔧 已实测），list/forward_list 的成员 `remove_if` 仍保留——两代惯用法并存期。⚠️ 对应提案编号未实测，不列号。
- **`std::format`（C++20）/ `std::print`（C++23，[P2093R14](https://wg21.link/p2093r14) 实测200）**：`ostringstream` 手工拼字符串的现代替身之一（本项目 MinGW 的 print 链接残缺已记录于 00）。
- **`std::filesystem`（C++17，[P0218R1](https://wg21.link/p0218r1) "Adopt File System TS for C++17" 实测200）**：路径拼接/存在判断/遍历目录，跨平台替代 Windows API 与 POSIX dirent；8.2 文件 IO 的最佳拍档。
- **`charconv`（C++17，[P0067R5](https://wg21.link/p0067r5) 实测200）**：`to_chars/from_chars` 无异常、无 locale、可查错误码，9.5.5 数值转换的高性能终解（浮点支持各编译器进度不一 ⚠️，本机 gcc 15 整型实测可用）。
- **`std::pmr` 多态分配器（C++17）**：同一容器换内存策略（monotonic_buffer_resource 等），9.2 容器 API 之上的"分配维度"扩展。
- **定性标注（emplace）**：9.3.1/13.x 的 emplace 卖点"永远更快"在 2020s 已被修正——传字面量/已构造对象时与 push 无差，且 emplace 绕过 explicit 检查可能选出意料外的构造（如 `emplace_back("a", "b")` 对 pair 的旧世界）。结论仍是"构造参数直接给就 emplace，别的用 push"。
- **clang-tidy**：`performance-inefficient-vector-operation`（循环 push 无 reserve）、`readability-container-data-pointer`、modernize-use-emplace 族。
- **工业对照**：abseil 提供 `absl::InlinedVector`（小 size 栈上）与 `absl::FixedArray`；folly 的 `fbvector`（自动 reserve 增长）/`F14` 系列代表"工业标准容器增强"流派——都建立在 9.4 的增长策略思想之上。

## 勘误与存疑

- ⚠️ 9.2.5 swap 一节"swap 后迭代器指向哪个容器"的精确承诺（容器对象交换则迭代器跟随内部存储）各容器细节略异，实操只记"跨 swap 用迭代器危险"。
- ⚠️ 5版未涉及 `std::inplace_vector`（C++26）与 `flat_map`/`flat_set`（C++23，提案号未实测故不给），选型表未来要加两行。
