本章覆盖：7.1 定义抽象数据类型（Sales_data 设计/改进/类相关非成员函数/构造函数/拷贝赋值析构）→ 7.2 访问控制与封装（private/友元）→ 7.3 类的其他特性（成员再探/返回 `*this`/类类型/友元再探：friend 函数与类、局部友元）→ 7.4 类作用域（名字查找与类作用域/两阶段查找）→ 7.5 构造函数再探（初始值列表/委托构造/默认构造函数作用/隐式类类型转换/聚合类/字面值常量类）→ 7.6 静态成员。

## 核心概念速览（中英对照）

- **抽象数据类型** — ADT：数据+操作绑定，接口与实现分离；Sales_data 是全书贯穿教具
- **接口设计三问**：哪些操作是成员、哪些是非成员友元、哪些既非成员也非友元
- **构造函数 constructor**：名字=类名、无返回类型；**默认构造函数**（无参或全默认参）决定 `Sales_data total;` 能否编译
- **`=default`（7.1.4，C++11）**：显式索要编译器合成版本；与"不提供任何构造"效果近似但意图不同
- **in-class initializer 类内初始值（C++11）**：成员声明处给默认值，构造统一回退点
- **初始化列表 member initializer list**：进入函数体前完成初始化；**const/引用成员唯一的赋值时机**；顺序=声明顺序非书写顺序
- **委托构造函数 delegating constructor（C++11）**：一个构造调用同类的另一个构造
- **explicit**：阻断"单参构造函数=隐式转换"；多参数版（C++11）用于列表初始化场景
- **拷贝/赋值/析构的隐式声明**：这里只需知道"编译器会合成"，规则细节是 13 章（三/五法则）主场
- **this**：指向本类对象的隐式常量指针；`return *this;` 支持 `a.combine(b).print()` 链式调用（7.3.2）
- **const 成员函数**：承诺不改对象；`mutable` 数据成员可绕过（7.3 尾）
- **友元 friend**：承认破坏封装换取接口对称（如 `<<`/`>>` 非成员重载）；声明不定义、定义放 .cpp 是书推荐工程法
- **类作用域与两阶段查找（7.4.1）**：成员体内名字先查类域再查文件域；成员函数体在"类完整后"编译——前向引用合法的原因
- **聚合类 aggregate（7.5.5）**：全 public、无构造、无基类——`Data d{"9-1", 2, 3.0}` 花括号按声明顺序初始化
- **字面值常量类 literal class（7.5.6，C++11）**：所有成员是字面值类型 + 有 constexpr 构造——constexpr 对象的类的准入条件
- **静态成员 static member**：属于类不属于对象；`inline static` 前的老规矩是类内声明+类外定义

## 小节细目（按原书小节号速记）

- **7.1.1 设计 Sales_data（页228）**：定义骨架=只有数据+校验 ISBN；把 read/add/print 做成非成员"类相关函数"——注意定义顺序（add 在 read 之后等，非成员也要先声明后使用）。
- **7.1.2 改进的 Sales_data（页230）**：把与状态强耦合的收回成员：`combine`（返回 `*this` 支持链式，7.3.2 再讲）、`valid`、成员版 read/print。
- **7.1.3 类相关的非成员函数（页234）**：非成员但"逻辑上属于接口"——放在类定义之后、保持与成员一致的形参约定。
- **7.1.4 构造函数（页235）**：初始值列表语法；`Sales_data& operator=` 之外的合成默认构造规则；`=default` 的四种写法差异（声明处/类外/替换定义）。
- **7.1.5 拷贝、赋值、析构（页239）**：本节只立"编译器自动合成"的存在性，规则在 13 章。
- **7.2.1 友元（页241）**：friend 声明位置自由（public/private 均可）；友元不是成员、声明不定义时注意链接。
- **7.3.1 类成员再探（页243）**：成员可被类内名字限用；返回 *this（7.3.2）；类类型作为成员（7.3.3）；友元再探（7.3.4：友元类、成员函数做友元、局部友元声明技巧——"定义放 .cpp 让接口只暴露必要信息"）。
- **7.4.1 名字查找与类作用域（页254）**：成员体内两阶段查找；内联定义在类内的函数体"视在类完整之后"——成员顺序随意的前提。
- **7.5.1 构造函数初始值列表（页258）**：声明序初始化 vs 书写序执行；"用未初始化成员做初始值=未定义"。
- **7.5.2 委托构造（页261）**：委托后自己的体内赋值会覆盖被委托者的初始化——"最后执行者说了算"。
- **7.5.3 默认构造函数作用（页262）**：决定 `Sales_data total;`、`vector<Sales_data>(10)` 能否编译；无默认构造时改用列表初始化传参。
- **7.5.4 隐式类类型转换（页263）**：单参构造=转换函数；转换链只允许一步用户定义转换；explicit。
- **7.5.5 聚合类（页266）**：无 private、无构造、无基类无虚函数；成员初始化表按声明序。
- **7.5.6 字面值常量类（页267）**：成员都是字面值类型+constexpr 构造（C++11 新特性小节）。
- **7.6 静态成员（页268）**：static 函数无 this→不能访问非静态成员；可作默认实参；类外定义一次规则。

## 自查与面试高频

1. `explicit Sales_data(const std::string& s);` 挡住了哪些调用？放开了 `Sales_data d(s)` 吗？
2. 成员 `i(j), j(1)` 顺序写反为何得到垃圾值？（声明序）
3. 为什么 `const Sales_data&` 成员函数不能调用 `combine()`？（底层 const 传染）
4. 静态成员函数为何不能碰非静态成员？用参数传对象行吗？（行，但此时考虑非成员）
5. 聚合类 `struct{int a; std::string b;}` 能用 `()` 初始化吗？（C++20 起能，之前不能）
6. 为什么把成员函数定义在类内等于给它加了 `inline`？对大型类意味着什么？（头文件膨胀+增量编译变差——Pimpl 惯用法的动机之一）
7. `mutable` 与 `const` 成员函数：缓存字段的合法逃生门边界在哪？（逻辑 const 可，物理可见状态改不得；多线程下 mutable 缓存要另行同步）
8. 友元为什么破坏封装 yet 仍是 IO 运算符的标准解？替代方案（public 访问器拼装）差在哪？
9. const 成员函数里 `this` 的类型是什么？为什么它调用非 const 成员函数编译不过？（`const Sales_data* const`；底层 const 传染=只读对象上不允许再开可写通道）
10. 构造函数里把 `this` 登记给回调/其他对象为什么危险？对象此刻处于什么状态？（半构造：成员未全部初始化、派生类未介入虚表——"不要在构造中调用可覆盖的成员函数"同源铁律）
11. `static const int size = 10;` 为什么可以类内初始化而 `static std::string` 不行？（整型/字面量类型的 constexpr 静态数据成员可用常量表达式类内初始化，仍需类外定义取地址场景）
12. C++17 的 `inline static` 成员与类外定义相比省了什么坑？（ODR 允许多 TU 同定义=不再需要"头声明+cpp 定义"成对维护；`std::mutex` 类成员共享的工业标准写法）
13. 没有默认构造的类为什么 `vector<Sales_data> v(10);` 编不过？两条出路？（默认构造是 vector 批量构造的协议；出路：给它默认构造，或 `vector<Sales_data> v{Sales_data{}, ...}` 列表初始化）
14. `const` 对象调用成员函数时，哪些函数必须存在重载对？（返回引用/指针的 getter 需要 const/非 const 双版本——底层 const 的接口镜像）
15. 为什么"先声明成员顺序=构造顺序"使得 `j(i), i(0)` 这种初始化列表顺序 bug 极难测？（编译警告 MSVC 默认不响；clang-tidy `misc-...` / `-Wreorder` 值得常开）
16. 类内默认成员初始化器与初始化列表谁优先？两者都没有时 POD 成员的初值？（列表赢；没有列表则默认初始化——读 `Sales_data d;` 里 bookNo 是垃圾值的根因）
17. `mutable` 计数器 + const 成员函数自增，多线程下这段代码的数据竞争在哪一行？（自增非原子；逻辑 const 不等于线程安全 const，要 `std::atomic` 或锁）
18. 同名字段 `size`：为什么"成员函数叫 size 返回容器元素数"是习惯法而非标准强制？仿写 STL 风格类时哪些名字有"协议义务"？（begin/end/size/empty 的语义契约；违反者范围 for/算法接不上）
19. `struct` 与 `class` 唯一的差别是什么？什么时候"用 struct"本身就是一条设计文档？（默认 public/默认继承 public；纯数据载体用 struct=宣告"无不变量可破坏"）

## 7.1 机制：Sales_data 的三段进化

第2章 struct（数据公开）→ 7.1 骨架（只定义数据+isbn 等访问器，操作做成非成员 `read/avg/add`）→ 7.3 成熟（把与对象状态强耦合的操作收回成员，`combine` 返回 `Sales_data&` 支持链式）。

**动机**："先非成员后成员"不是偷懒——**接口越薄越健壮**；只有必须访问私有状态或需要 this 的操作才升级为成员。这是 Lippman 想灌输的第一条设计品味。

**关键机制**：
- 构造函数初始值列表 vs 函数体内赋值：对类类型成员是"初始化 vs 默认构造+赋值"的性能差；对 const/引用成员是"唯一合法路径"。
- 隐式类类型转换（7.5.4）：`item + string("...")` 能编译，因为单参构造 `Sales_data(const string&)` 兼职转换函数——不想接受就 explicit；想只接受显式写法就 `explicit Sales_data(string, ...)` 多参版（C++11）。

**相邻概念对比**：`Sales_data` 的 combine（成员，改自己）vs add（非成员，产生新对象）——"动词属于谁"决定成员归属；`friend std::istream& operator>>` 与成员 `>>` 的取舍在 14.2 展开。

## 7.4-7.6 作用域、名字与静态

- 类内声明顺序无关（函数体两阶段查找），但**数据成员初始化顺序只认声明顺序**——初始值列表按书写顺序执行会埋雷（`i(j), j(1)` 反例）。
- 静态成员：共享存储、可用作默认参数、类内声明类外定义（整型/constexpr 例外可类内初始化）；现代替代：**`static` 成员函数当回调传递（C ABI 场景）**、无状态工具直接进命名空间。

## 🔧 实测（已实测 g++ 15.2, -std=gnu++20）

`s06.cpp`：类内初始值（C++11）+ explicit 阻断隐式转换 + C++20 聚合体圆括号初始化（P0960R3）：

```cpp
struct Sales_data { std::string bookNo{"-"}; unsigned units_sold = 0; double revenue = 0.0; ... };
struct Guard { int v; explicit Guard(int x = 0) : v(x) {} };
Guard g = 5;              // 被 explicit 拦下（改 g{5} 才过）
Sales_data c("9-1", 2, 3.0);  // C++20 才允许聚合体用 () 
```

```
combine=7
g=5 c: 9-1 units=2
```

## 最新演进与工业实践（基线 C++11 → 现在）

- **聚合体 `()` 初始化（C++20，[P0960R3](https://wg21.link/p0960r3) "Allow initializing aggregates from a parenthesized list of values" 实测200）**：7.5.5 花括号写法的圆括号平替，CTAD 友好。
- **`=delete` 语义扩张**：书中 7.1 已见"阻止拷贝"（=delete 的 C++11 原教用法）；现代还用它封掉"不许为右值准备的成员"——`void str() && = delete;`（13.6.3 呼应）。
- **`inline static` 数据成员（C++17）**：7.6 "类外定义"样板的终结——`struct C { inline static int n = 0; };`。
- ** defaulted 比较运算符（C++20，[P0515R3](https://wg21.link/p0515r3) 实测200）**：7.1 "要不要写 operator==" 的成本归零，详见 [11-操作重载与面向对象.md](11-操作重载与面向对象.md)。
- **clang-tidy**：`cppcoreguidelines-pro-type-member-init`（忘初始化）、`performance-implicit-conversion-in-loop`、`readability-redundant-member-init` 全部对位本章。
- **工业对照**：GSL `not_null`、absl `Status` 都以"单参构造 explicit + 类内初始值"为风格基线；Google C++ Style 的"能非成员就非成员、friend 慎用"就是 7.2 的工程化复读。
- **定性标注**：⚠️ "局部类不能当模板实参""友元声明必须在类内"等 7.x 边角规则在 C++11/17 已陆续放宽（局部/匿名类型可作模板实参等），旧书条条款款以编译器为准。

## 勘误与存疑

- ⚠️ "构造函数体内赋值 vs 初始值列表"的"默认构造+赋值两倍开销"论证对内置类型成员不成立——书 7.1.4 原文用词更精确，重构笔记易传丢，此处已限定为类类型成员。
