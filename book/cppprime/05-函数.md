## 核心概念速览（中英对照）

- **形参与实参** — parameter vs argument：形参是变量，实参是传入的值
- **传值/传引用** — pass by value / reference：要改就引用（现代补充：要观察就 `const&`，小对象按值）
- **const 形参不参与重载**：顶层 const 被忽略，底层 const 改变可匹配集合
- **数组实参退化** — array to pointer decay：`void f(int*)`、三种写 `int* / int[] / int[N]` 参数等价；传长度的三种套路（哨兵/双指针/`initializer_list`）
- **`initializer_list`（6.2.6，C++11）**：同类型可变形参的官方解；元素恒为 const
- **省略符形参** — varargs `...`：`va_start/va_arg/va_end`，只为兼容 C 而保留
- **局部静态对象** — local static：首次执行定义处初始化（C++11 起线程安全），退出才销毁
- **分离式编译** — separate compilation：声明进头文件、定义进 .cpp，链接器缝合
- **返回引用要慎重**：返回 `const string&` 省拷贝，但源对象生命周期必须更长
- **尾置返回类型** — trailing return（6.3.3，C++11）：`auto func(int i) -> int(*)[10];` 返回数组指针的可读写法
- **重载 overload**：同名字不同签名列；**重载不跨作用域**（内层遮蔽外层，含类的继承作用域）
- **默认实参 default argument**：只能从右往左省；声明处给值、定义处不再给
- **内联 inline / constexpr 函数（6.5.2）**：inline 是"建议+ODR豁免"，constexpr 才是编译期承诺
- **调试帮助** — assert/NDEBUG：`assert` 在 NDEBUG 下整个消失，副作用表达式禁入 assert；`__func__`
- **函数匹配 overload resolution**：候选→可行→最佳；隐式转换等级（精确匹配>提升>算术转换>…）决定胜负
- **函数指针** — function pointer：`int (*pf)(const int&, const int&)`；把函数当参数的唯一旧解

## 小节细目（按原书小节号速记）

- **6.1.1 局部对象（页184）**：四种生命周期——自动、静态（local static）、线程、动态；"定义时初始化 vs 每次进入重新定义"的区别决定计数器写法。
- **6.1.2 函数声明（页186）**：原型=返回类型+形参类型+名字；头文件放声明；递归调用合法正是"先声明后定义"的体现。
- **6.1.3 分离式编译（页186）**：每文件独立编译→链接；改动 .cpp 只重编该文件，改动头文件牵一发动全身——16.1.6 与 modules 话题在此埋线。
- **6.2.1-6.2.3 传值/传引用/const 形参（页187-192）**：实参初始化形参（拷贝发生在此）；引用别名无拷贝；"值传 const 形参等价于非 const"的顶层 const 推论；用 const 引用同时满足"读与写"实参的匹配表。
- **6.2.4 数组形参（页193）**：三写法归一为指针；`int (&arr)[10]` 保留大小的引用写法；`main(int argc, char** argv)`。
- **6.2.5 main 命令行（页196）**：argv[0] 是实现定义的程序名；选项解析无标准库。
- **6.2.6 可变形参（页197）**：initializer_list（同类型）/ 省略符（兼容 C）/ 可变参数模板（16.4，任意类型）。
- **6.3.1-6.3.3 返回（页199-206）**：无返回值函数隐式 return；返回引用=左值可被赋值（`f() = val` 合法但恶心——书有示例）；返回数组指针的 typedef/decltype/尾置三解。
- **6.4.1 重载与作用域（页210）**：内层遮蔽全部外层同名重载；补救=全名 `::f(...)`。
- **6.5.1-6.5.3（页211-216）**：默认实参只从右省、每次调用重新求值；inline 的 ODR 一致性要求；constexpr 函数（C++11 严格版）；assert 与 NDEBUG。
- **6.6 函数匹配（页217-221）**：可行函数四级转换（精确/提升/算术/类类型）；实参恰好两个最优候选即歧义。
- **6.7 函数指针（页221-225）**：赋值自动转指针、解引用可选；函数表（数组 of 函数指针）实现"switch 的替身"。

## 自查与面试高频

1. 形参 `const vector<int>&` 与 `vector<int>` 各在什么情况必须选？（改/大 vs 小/要复制一份）
2. 为什么"数组大小写进形参列表"是假象？（退化）
3. `static` 局部变量首次初始化线程安全吗？（C++11 起是）
4. 默认实参写进函数定义又写进声明会怎样？（重复指定，编译错）
5. 重载为什么不能只靠返回类型区分？（调用点不出现类型时无法决议）
6. `nullptr` 与 `NULL`/`0` 在 `f(int)`/`f(char*)` 重载面前行为差别？（后者的二义/意外选中正是 nullptr 的动机）
7. 内联函数为什么建议放头文件？声明期内联与 `inline` 关键字强制内联是一回事吗？（前者只是多次定义豁免+ODR 要求；是否真内联由编译器决定）
8. 什么时候输出参数该用指针而不是引用？（"可空/可选"要显式表达时——`nullptr` 是文档；引用永远假定有效）
9. `typedef int (*Cmp)(int,int);` 与 `using Cmp = int(*)(int,int);` 在模板里谁必须用？后者与 `std::function<int(int,int)>` 的成本差别？（模板成员 typedef 必须 `typename`；function 有类型擦除堆分配与调用间接层）
10. `__FILE__` 宏和 `std::source_location` 默认实参，为什么后者可以安全传给下游函数？（宏是字符串拼接进日志，位置信息随宏消失；source_location 在调用点取值、随参数下传）
11. `main` 能声明为 `void main()` 吗？返回值没写时等价于什么？（标准只认两种签名；C++11 起落到 `return;` 隐式 0）
12. 函数重载决议看到 `f(1)` 与候选 `f(long)`/`f(double)`，谁赢？（整型提升 long 胜浮点转换——"提升>转换>用户定义"档位表在模板之后仍要考）

## 6.1-6.2 机制：调用约定背后的对象生命周期

**动机**：函数是"接口 + 生命周期边界"双重角色。6.1.1 的局部对象四态（自动/静态/线程/动态）是理解后面 RAII、智能指针、Meyers 单例的地图。

**机制**：
- 传引用形参 vs const 引用 vs 值的选择树在 6.2.2-6.2.3 展开：**改→引用；不改且大→const&；小且可拷贝廉价→值**（书比此保守，倾向一律 const&）。
- 数组形参三写法（6.2.4）：`int*` + 长度、`int begin[], int end[]`、C 风格字符串终止符——三案都是"退化后自补信息"的补丁。现代答案：`span<int>`（见下节）。
- main 的 `int main(int argc, char* argv[])`：标准只保证这两形态。

**权衡**：书的"传引用优先"教义在标量上被现代性能观部分推翻（值传 `int` 走寄存器，`const int&` 反多一层间接）；EMC++ 第 1 条之后这类细化已成常识。

**相邻概念对比**：`initializer_list` vs 可变参数模板（6.2.6 的两种"不定参"——前者要求同类型，后者任意类型，16.4 见）；默认实参 vs 重载（默认实参更省 boilerplate，但每次调用都要重新求值默认值，**默认值不是编译期常量**这一点 6.5.1 特别警告）。

## 6.3-6.4 返回值与重载的坑区

- 不要返回局部对象的引用/指针（悬垂）；列表初始化返回值 `return {a, b};`（C++11）配合聚合返回类型很香。
- 返回数组指针（6.3.3）：`decltype(f(1))*` 或尾置返回——这节是 16.2 模板推断的预告。
- **重载与作用域（6.4.1）**：内层声明同名函数即遮蔽所有外层重载——"为什么我的 `f(2)` 调不到 `f(double)`"标准答案；继承里的对应物是 `using Base::f;`。

## 6.5-6.7 特性区

- **inline**：现代意义=头文件可定义函数的 ODR 豁免，不是性能开关（编译器自己决定内联）；隐式 inline 的类内定义成员函数已在 7 章用到。
- **constexpr 函数**（C++11 基线）：5 版教的是"return 单表达式"严格版；**C++14 放宽**为可含局部变量/循环/多 return——🔧 实测即按 C++14 编译。
- **assert 的正确用法**：防御"逻辑上不可能"而非"运行时可能错"（用户输入/IO 失败必须显式处理）。
- **函数指针**：6.7 的手写 `int (*pf)(int)` 已属考古必备、日用可弃——现代替身是 lambda（无捕获可转指针）、`std::function`（14.8.3）、模板参数（16.1）。

## 🔧 实测（已实测 g++ 15.2, -std=gnu++14）

`s05.cpp`：C++14 constexpr 递归 + C++17 结构化绑定代替"输出参数"：

```cpp
constexpr long fact(int n){ return n <= 1 ? 1 : n * fact(n-1); }  // C++14 允许循环/分支
auto [m, s] = compute();        // 多返回值：不再传指针"输出形参"
```

```
fact(10)=3628800  编译期就算出来
mean=2.5 sd=0.5
x=101
```

注：结构化绑定按扩展编译（gnu++14 带警告通过），标准姿势是 `-std=gnu++17`。

## 最新演进与工业实践（基线 C++11 → 现在）

- **constexpr 函数体放宽（C++14）→ if constexpr（C++17，[P0292R2](https://wg21.link/p0292r2) 实测200）→ if consteval（C++23，[P1938R3](https://wg21.link/p1938r3) "if consteval" 实测200）**：6.5.2 那条时间线一路推进到"编译期/运行期双人格函数"。
- **结构化绑定（C++17，[P0217R3](https://wg21.link/p0217r3) 实测200）**：`return {mean, sd}` + `auto [m,s]` 终结"输出形参"惯用法。
- **`std::span`（C++20，[P0122R7](https://wg21.link/p0122r7) 实测200）**：6.2.4 数组形参三写法的官方终结者——一个类型携带"指针+长度"。
- **[[nodiscard]]（C++17，[P0189R1](https://wg21.link/p0189r1) 实测200）**：给"返回值不接即 bug"的函数上锁；GSL 的 `gsl::not_null`、`GSL::Expect` 哲学同源。
- **clang-tidy**：`modernize-use-override`（15章）、`performance-unnecessary-value-param`、`readability-*` 直接对位本章抉择。
- **工业对照**：abseil Status/StatusOr 返回约定（"错误走返回值不走指针输出参"）、folly `Future`——6.3 返回类型讨论的现代工程放大版。
- **定性标注**：`...` 省略符形参在托管新代码中视为反模式（类型不安全）；函数指针作 API 参数已被 `std::function`/模板取代，但 C 回调 ABI 场景仍不可替代。
