## 核心概念速览（中英对照）

- **动态内存** — dynamic memory：生命周期不受作用域约束、手动或 RAII 管理的堆内存
- **shared_ptr**：引用计数共享所有权；拷贝+1、析构-1、归零释放
- **use_count/get/reset**：观测计数、裸指针取值、换绑释放
- **make_shared**：一次分配（对象+控制块）且**异常安全**——`f(shared_ptr<T>(new T), g())` 求值乱序可泄漏，`make_shared` 免疫
- **unique_ptr**：独占所有权、只移动不拷贝；`reset/release/get`，自定义删除子
- **release vs reset**：release 交出所有权不删除（交给裸指针接管者），reset 立即删除
- **weak_ptr**：不拥有、观测 shared_ptr；`expired()/lock()` 破环与缓存的经典双工具
- **循环引用** — cyclic reference：两个 shared_ptr 互指→计数永不归零→泄漏；weak_ptr 是标准解
- **new/delete**：分配+构造 / 析构+释放；`new T[]/delete[]` 数组版配对铁律
- **bad_alloc 与 nothrow**：`new (nothrow)` 返回 nullptr 而非抛异常
- **allocator 类**：分配与构造分离的两阶段原语（allocate/construct）——vector 背后的机制，13.5 实战
- **智能指针转换**：`static_pointer_cast/ dynamic_pointer_cast...`（⚠️ 5版未展开，工程常见）
- **RAII** — resource acquisition is initialization：资源寿命绑定对象寿命；本章是全书 RAII 宣言

6. `shared_ptr<T> sp(new T)` 用 `new T[]` 会怎样？（不匹配：数组要自定义删除器或改用 vector/unique_ptr<T[]>；make_shared 也不支持数组）
7. `enable_shared_from_this` 为什么在建 shared_ptr 之前调 `shared_from_this()` 会 bad_weak_ptr？对象生命周期内它内部持有什么？
8. RAII 视角下"内存泄漏只是资源泄漏的一种"——给出锁/句柄/套接字三个对应的守卫类型。
9. 为什么返回 `shared_ptr<T>` 按值、参数按 `const shared_ptr<T>&` 或 `T*`/引用，各有何代价？（拷贝计数原子操作=缓存行争用；按值返回是所有权分享的自然表达）
10. `shared_ptr` 指向数组为什么是坑？两种修法？（默认删除器不配 `delete[]`；自定义删除器 `shared_ptr<T[]>(p, default_delete<T[]>())`，或直接 `vector`）
11. "从 this 造 shared_ptr"为什么必须 `enable_shared_from_this`？裸 `shared_ptr<Derived>(this)` 错在哪两个层面？（两个独立控制块=双重释放；weak 引用计数通道缺失）
12. `weak_ptr` 的 `lock()` 与 `expired()`+构造，哪个有 TOCTOU 竞态？为什么？（后者两步之间对象可被释放；lock 一步原子完成——多线程下只认 lock）
13. shared_ptr 比较用 `*p` 还是 `p.get()` 做哈希键？放进 unordered_map 的指针键生命周期怎么保？（值语义哈希走 get 的地址；所有权要么容器要么 map 别两处都想要）
14. 智能指针放进数组/容器时"默认构造即空"对判空逻辑意味着什么？（`shared_ptr::operator bool` 是主判据；`unique_ptr` 解引用前同样必须查——空指针解引用不再是"指针没赋值"而是"默认构造的合法值"）
15. 三-way 所有权表达：`T*`（观察可空）/`T&`（观察非空）/`unique_ptr`（独占）/`shared_ptr`（共享）——函数签名该怎么选？（GSL 用 `not_null<T*>`/`owner<T*>` 把这套约定写进类型——12 章 unique_ptr 面试答案的标准库化）

## 12.1 机制：所有权是一种类型

**动机**：`new/delete` 四大错（泄漏、悬垂、双重释放、配对错）本质是"所有权隐式"。C++11 智能指针把所有权写进类型：shared=共享、unique=独占、weak=只看不管。

**机制要点**：
- `shared_ptr` 计数在**拷贝/赋值/析构**时变动；函数返回 `q` 时若 q 被移动则计数不变（12.1.1 用图讲透——移动语义的预热）。
- `unique_ptr` 默认删除子 `delete ptr`；数组特化 `unique_ptr<T[]>` 用 `delete[]`；自定义删除子处理 `fclose` 等 C 资源（`unique_ptr<FILE, int(*)(FILE*)>` 惯型，12.1.5 脚注级）。
- **weak_ptr**：不延长寿命；`lock()` 原子地"若活着给我 shared_ptr，否则空"——缓存与回调安全性的地基。
- 智能指针与异常（12.1.4）：栈展开保证 RAII 对象析构，这是"裸 new + 中途 throw 必泄漏"的结构性解药。

**权衡**：shared_ptr 的代价——控制块原子操作（线程安全仅指针本身，不保护元素）、`use_count` 调试可见性差、循环引用风险。**默认 unique_ptr，需要共享才 shared_ptr**（EMC++ 第18/19/21 条）在 2013 年已是苗头、今天已是共识。

**相邻概念对比**：`shared_ptr<T>(new T)` vs `make_shared`（两次分配 vs 一次；控制块先于对象释放的长尾持存 ⚠️）；`unique_ptr` 转移 `std::move(p)` 后 p 必为 nullptr（书用"移走"一词贯穿 9/12/13 章）；`weak_ptr` vs 裸指针（过期检测能力之别）。

## 🔧 实测（已实测 g++ 15.2, -std=gnu++14）

`s09.cpp`：make_shared 引用计数、make_unique（C++14 补位）、vector<unique_ptr> 移动入容器、weak_ptr 观测归零：

```cpp
auto sp = std::make_shared<X>(1);
{ auto sp2 = sp; /* count=2 */ }
owns.push_back(std::make_unique<X>(2));
owns.push_back(std::move(up));       // 转移后 up 为空
std::weak_ptr<X> wk = sp;  sp.reset(); // wk.expired() 变 true
```

```
count=2
count=1
owns=2 up=null(已被移走)
  ~X(1)
weak expired=1
  ~X(2)
  ~X(3)
```

析构顺序直观展示所有权归属：sp 归零即 `~X(1)`；容器里的 2、3 随 main 退出释放。

## 最新演进与工业实践（基线 C++11 → 现在）

- **`std::make_unique`（C++14，[N3656](https://wg21.link/n3656) "make_unique" 实测200）**：书中 12.1.5 用裸 `new` 构造 unique_ptr 的姿势已过时——make_unique 补齐异常安全+一致性；⚠️ 唯一限制：自定义删除子时 make_unique 不适用，直接 `unique_ptr<T, D>(new T, D())`。
- **`std::span`（C++20，[P0122R7](https://wg21.link/p0122r7) 实测200）**：动态数组的"不拥有视图"传参，替代"指针+长度/两个迭代器"；`new T[n]` 之后包成 span 再交给函数。
- **`std::pmr`（C++17）**：`std::pmr::vector` + `monotonic_buffer_resource` 在多数场景替代手搓 allocator 的 12.2.2/19.1 需求。
- **constexpr 分配（C++20，[P0784R7](https://wg21.link/p0784r7) "More constexpr containers" 实测200）**：编译期 `new/delete` 与 constexpr vector/string 的地基——"动态内存"第一次可存在于编译期。
- **多维数组现代解**：`new T*[n][m]` 类需求直接用 `std::mdspan`（C++23，[P0009R18](https://wg21.link/p0009r18) "MDSPAN" 实测200；子视图 [P2630R4](https://wg21.link/p2630r4) "Submdspan" 实测200）。
- **定性标注（auto_ptr）**：旧代码/4版教程的 `auto_ptr<T>`：拷贝即转移 + 析构 delete[] 错配风险，C++11 废弃、**C++17 已删除**；见到即等价替换 `unique_ptr`。
- **clang-tidy/GSL**：`cppcoreguidelines-owning-memory`（裸 new/delete 报警）、`modernize-make-unique/shared`、`modernize-use-unique-ptr`；GSL 的 `owner<T*>` 标注函数返回"裸的但应被接管"的指针。
- **工业对照**：abseil/Chromium 常见"句柄+代际索引"方案替代 weak_ptr 的场景（避免原子计数与悬垂检测开销）；游戏引擎普遍"对象池 + 自定义 deleter 的 unique_ptr"——都是本章所有权观的变体。

## 勘误与存疑

- ⚠️ `shared_ptr` 与数组：`shared_ptr<T[]>` 到 C++17 才正式支持（5版时期要自写删除子）——书中"shared_ptr 配合 new[] 麻烦"的叙述按现代写法已过时一半。
- ⚠️ make_shared 控制块合并导致"weak 残留持存大对象"的取舍，书未提，列为工程注意项即可。
