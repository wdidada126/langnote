## 核心概念速览（中英对照）

- **泛型算法** — generic algorithm：算法操作迭代器不依赖容器，"算法-迭代器-容器"三层解耦是 STL 的灵魂
- **只读/写元素/重排**三分类：10.2 的认知地图；写算法（fill/copy/transform）不分配存储，**必须配插入迭代器或预置大小**
- **谓词** — predicate：可调用的 bool 返回；一元/二元；谓词不得改自己的实参（纯函数约定）
- **lambda 表达式（C++11）**：`[捕获](参数)->返回类型{体}`；捕获默认值或引用，`mutable` 放开 const 限制
- **捕获列表纪律**：按引用捕获局部对象、lambda 活得比作用域长=悬垂；隐式捕获 `&`/`=` 起步
- **std::bind（C++11）**：占位符 `_1/_2` 部分绑定；现代判词见"定性标注"
- **插入迭代器** — insert iterator：`back_inserter/ front_inserter/ inserter`——把"写入"转成"插入"，解 10.2 越界问题
- **iostream 迭代器**：`istream_iterator<T>` 惰性读、`ostream_iterator<T>` 写出+分隔符——"IO 当序列"的胶水
- **反向迭代器**：`rbegin/rend`，`base()` 回退一格（erase 前调 `.base()` 的经典陷阱）
- **五类迭代器** — input/output/forward/bidirectional/random_access：算法按能力取最弱分类；C++20 改名 concept 体系
- **算法命名规范**：版本后缀 `_if/_copy/_n` 与 `stable_`——三正交维度
- **list 成员算法**：list/forward_list 的 sort/merge/splice 等禁用同名泛型版（O(n log n) vs O(n²) 教训）
- **关联容器** — associative container：set/map 红黑树（有序 O(log n)）、unordered_* 哈希（无序摊还 O(1)）
- **严格弱序** — strict weak ordering：`<` 必须满足的三性质； comparator 写错的后果是"随机丢元素/死循环"
- **pair 类型**：`make_pair`/花括号构造；map 元素就是 `pair<const K, V>`（`first/second`）
- **map 下标双刃**：`m[k]` 读会插入默认值——统计好用、查询危险；只读查找一律 `count/find`
- **多键查找四件套**：`lower_bound/upper_bound/equal_range` + `count`；无序容器只有 `count/find/equal_range`
- **无序容器的接口约束**：键需要 hash（`std::hash` 可特化）+ `==`；桶 bucket_* 接口为性能调优保留

## 自查与面试高频

1. `copy` 到 `vector` 中途为什么可能越界写？三种解法？（尺寸预置/resize/插入迭代器）
2. lambda 捕获 `&` 返回后调用为什么会崩？（闭包引用了亡魂）
3. `list::sort` 与 `std::sort(list)` 的复杂度差别根因？（双向 vs 随机访问）
4. map 的 `[]` 为什么不能给 `const map` 用？（可能插入）只读访问怎么办？（find/at 前检查）
5. unordered_map 平均 O(1) 的前提？hash 冲突极端退化怎么办？
6. `stable_sort` 与 `sort` 的代价差在哪？何时必须稳？（等值保持输入序；按多键分次排序/输出对齐场景）
7. 谓词为什么必须无副作用且对同一输入结果一致？（算法可任意次调用谓词、可复制；违反即未定义行为）
8. `transform` 与手写 for 循环谁该让路？（单值映射用 transform 表达意图；有分支/多语句时 for 更可读——算法优先不是教条 ⚠️ 业界两派并存）
9. `set_intersection` 忘记先排序会怎样？有报错吗？（无报错无保证——结果错误且未定义排序前提；这是"算法不检查输入"的典型）
10. `multiset` 的 `count` 与 `equal_range` 在 10 万个重复键下复杂度各是多少？（前者 O(log n + k) 全走一遍；后者给迭代器区间自行决定——统计热点用等值区间更省）

## 10.x 机制：为什么"算法在外面"

**动机**：若每个容器自带 find/sort，M 个容器 × N 个算法 = M×N 份代码；迭代器解耦后 M+N。理解了这句，10 章的所有函数名都好记。

**机制与陷阱**：
- `unique` 只去相邻重复——"sort 后 unique 再 erase"三步曲（10.2.3）是书给出的第一个算法组合拳；它正是 C++20 `std::erase_if`/ranges 要简化掉的样板。
- `accumulate` 起点类型决定结果类型（`0` 与 `0.0` 差一个截断故事，10.1 例子）。
- lambda 的捕获在编译期生成闭包类（14.8.1 呼应"lambda 是函数对象"）——捕获 `[&]` 出作用域即悬垂，异步场景必须 `[=]` 或显式拷贝。
- 反向迭代器的 `erase(--rend)` 类操作要先 `.base()` 调整：off-by-one 高发地。

**相邻概念对比**：`find`（线性）vs `binary_search`（要求已排序）vs map 的 `find`（树内 O(log n)）——同一个词三种数据结构路径；`transform` 的"输入区间+输出迭代器"形态 vs ranges 的"管道"形态（演进节）。

## 11.x 关联容器：选型 = 有序性需求 + 键类型能力

**权衡主线**：
- 需要**区间查询/有序遍历**→ map/set（红黑树 ⚠️ 标准只承诺复杂度不承诺实现，但业界如此）；纯查找→unordered（要求键可 hash）；
- 自定义键：有序版给比较器（函数对象/lambda 不行于模板参数场景要命名类型），无序版给 hash 特化 + `==`。
- `equal_range` 在多键 map 里替代 `[]`；单词转换 map（11.3.6）把"函数对象 map + 下标懒插入"两个惯用法合成一个可运行例子——Primer 全库最优雅的 10 页之一。

## 🔧 实测（已实测 g++ 15.2, -std=gnu++23）

`s08.cpp`：C++20 ranges 投影排序 + C++23 `ranges::to` 收集 + C++17 `try_emplace/insert_or_assign`（书中 insert 场景的现代细化）：

```cpp
std::ranges::sort(ps, std::ranges::less{}, &Person::age);      // 投影替代比较lambda
auto names = ps | views::filter(...) | views::transform(...)
                | std::ranges::to<std::vector>();               // P2602R0
m.try_emplace("k", 1);  m.insert_or_assign("k", 2);            // map 插入双补丁
```

## 最新演进与工业实践（基线 C++11 → 现在）

- **_ranges 算法与视图（C++20，[P0896R4](https://wg21.link/p0896r4) "The One Ranges Proposal" 实测200）**：`std::ranges::sort(v)` 直接传容器；谓词+投影分离让 `sort` 的"按成员排"不再写 lambda；`views::filter|transform` 惰性管道替代 copy-if-then-sort 的中间容器。
- **`ranges::to`（C++23，[P2602R0](https://wg21.link/p2602r0) "Poison Pills are Too Toxic" 实测200）**：管道末端收集成容器（🔧 已实测；注意 MSVC 把 `ranges::to` 归在 `<ranges>`、gcc 需 gnu++23 ⚠️）。
- **标准库 concepts（C++20，[P0898R3](https://wg21.link/p0898r3) "Standard Library Concepts" 实测200）**：10.5"五类迭代器"的正式后继体系（`input_iterator` 等概念）；报错从"天书模板实例化"变"不满足概念"。
- **unordered 异构查找（C++20，[P0919R3](https://wg21.link/p0919r3) 实测200）**：`unordered_map<string,K>` 可用 `string_view`/`const char*` 直查，终结"必须构造 string 再查"的临时分配。
- **abseil 对照**：在标准容器普及前，工业界用 `absl::flat_hash_map`（SwissTable，性能长期标杆）与 `absl::string_view` 键组合解决同类问题；folly 的 `F14` 系列同理。
- **clang-tidy**：`modernize-use-ranges`、`performance-*`、`readability-*` 大量针对旧算法样板；`abseil-*` 检查族可直接告废 `std::bind` 场景。
- **定性标注（std::bind，10.3.4）**：C++11 时代"参数绑定"的唯一答案已被**无捕获 lambda 全面取代**（EMC++ 第34条论证过）；bind 仅在"绑定成员函数指针给老式回调 ABI"时还有残值。
- **定性标注（unique 三步曲）**：`v.erase(std::unique(...), v.end())` 写法已被 `std::erase_if`/ranges 版本稀释，但排序去重思路不变。

## 勘误与存疑

- ⚠️ "红黑树"在标准中从未被指名——5版正文也仅说"平衡二叉树"；本笔记沿用业界实现事实。
- ⚠️ `try_emplace/insert_or_assign`（C++17）在书中不存在（第11章写作时只有 insert/emplace），🔧 输出即演示二者差异：前者不移动已存在键的值、后者强制覆盖。
