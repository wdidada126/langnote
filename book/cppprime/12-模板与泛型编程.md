## 核心概念速览（中英对照）

- **实例化** — instantiation：函数模板按调用、类模板按用到的成员分别生成代码（惰性实例化）
- **模板实参推断** — argument deduction：从实参类型反推模板参数；**推断期只做const/引用之外的极少量转换**，这是"为什么 `f(v)` 传 `vector<int>` 给 `T&` 却把 T推成 const vector"等困惑的答案
- **显式模板实参** — `max<int>(a, b)`：打断推断的唯一开关
- **尾置返回类型**：`template<typename It> auto f(It b, It e) -> decltype(*b)`——返回类型依赖参数的早期解法
- **引用折叠** — reference collapsing：`& &`、`&& &` 等四种组合只在类型别名/模板推断时发生，规则"有左引用则结果左引用"
- **万能引用/转发引用** — forwarding reference `T&&`：当 T 是推断类型时既收左值又收右值；`std::move` 的本质是 `static_cast<T&&>`（16.2.6 拆解）
- **std::forward**："条件 move"——实参是右值才转右值（16.2.7）
- **模板模板参数**：`template<typename T, template<typename...> class> struct`——容器适配器与 allocator 的通道
- **非类型模板参数**：`array<T, N>` 的 N；指针/引用参数需外部链接（5版规则），C++20 放宽到 constexpr 对象
- **显式实例化** — `template class X<int>;` + `extern template`：省编译时间与重复生成
- **可变参数模板** — variadic：`sizeof...`、包扩展的三种上下文、递归展开（C++11 唯一手段）
- **完美转发** — perfect forwarding：`template<typename... Ts> emplace(Ts&&... args){ ... std::forward<Ts>(args)... }`——值类别与 const 全程无损
- **全特例化/部分特例化**：函数模板**不能**部分特例化（用重载替代）；类模板可（`remove_reference<T&>` 家族）
- **SFINAE** — 替换失败不是错误：推断期非法替换只把该候选从列表移除；`enable_if` 是它的显式工具（16.5 + 附录）
- **hash 特化**：为自定义键打开 unordered 大门的唯一正门（`std::hash<MyType>` 特化）

## 小节细目（按原书小节号速记）

- **16.1 定义模板**
  - 16.1.1 函数模板：实例化=用实参替换模板参数的过程；`compare` 的 `T a=v[i]` 拷贝语义提醒（想避免拷贝传引用）。
  - 16.1.2 类模板：成员函数**惰性实例化**——没调用的成员永远不会生成代码，这是类模板可以含"对某些 T 非法"成员的原因。
  - 16.1.3 模板参数：类型参数（带默认参数，规则同函数默认实参）/非类型参数（整型/引用，`array<T,N>`）/模板模板参数（`T&` 形式参数与 `int` 形式参数不能互用）。
  - 16.1.4 类模板与成员模板：`Link<int>::next<int>` 两级参数各自独立；成员模板不能虚，可以被 `using Base::m` 继承。
  - 16.1.5 控制实例化：`template class X<int>;`（强制生成）+ `extern template X<int>;`（抑制重复生成），库作者工具。
  - 16.1.6 效率与灵活性：为何模板实现必须放头文件——实例化需要定义可见；inline/头文件膨胀/编译时间是同一枚硬币的反面。
- **16.2 模板实参推断**：16.2.1 类型转换的限制（只允许 const 与顶层/底层引用规则内的小转换）→ 16.2.2 显式实参覆盖推断 → 16.2.3 尾置返回 → 16.2.4 函数指针作实参（推断出 `T=int(*)(int,int)`，不能隐式转 `function`）→ 16.2.5 `T&`/`T&&` 三表 → 16.2.6 std::move 拆解 → 16.2.7 std::forward 拆解。
- **16.3 重载与模板**：非模板优先 → 可行函数中"转换序列最优"胜出 → 同等则更特化的模板胜出 → 仍平手则二义。
- **16.4 可变参数模板**：16.4.1 `sizeof...` 与参数包声明 → 16.4.2 包扩展的三种上下文（逗号/函数实参/模板参数列表）→ 16.4.3 递归展开终止条件 + `forward<Ts>(args)...` 转发包（`emplace` 的真实骨架）。
- **16.5 模板特例化**：16.5.1 函数模板只能全特化且特化**不参与**该函数名的重载决议基础版本选择（坑源，C++14 起普遍建议改用重载）→ 16.5.2 类模板部分特化（`remove_reference`、`tuple` 的递归定义骨架）→ 16.5.3 为 `Sales_data` 特化 `std::hash` 并喂给 unordered 的完整流程。

## 自查与面试高频

1. **`template<typename T> void f(T&&)` 收到左值 `a` 时 T 推成什么？** `T = A&`，引用折叠后形参是 `A&`——"万能引用"的名字来源；`std::forward<T>(a)` 此时转发为左值。
2. **为什么 `std::move` 不需要模板参数推断也能动？** 它只做 `static_cast<T&&>`，值类别运算是编译期的，运行期零指令。
3. **类模板成员函数为什么不立即实例化？** 惰性实例化允许成员对当前实参非法（如 `Blob<T>::iterator` 依赖 `vector<T>::iterator`），只用才生成。
4. **函数模板特例化为什么"慎用"？** `template<> int max<int>(int,int)` 不会自动优先于通用版参与重载比较——它只是重载集里的普通一员，行为反直觉；标准库自己的 `std::` 特化豁免是历史遗留。
5. **SFINAE 发生在哪个阶段？** 替换期：实参代入候选签名后若产生非法类型，该候选被**移除**而非报错——`enable_if`/`void_t` 家族全部建立在此；C++20 concepts 是它的"声明式前置过滤"。
6. **`sizeof...(Args)` 能用在运行期吗？** 否，编译期常量表达式。
8. **`template<template<typename...> class C> void f(C<int>&)` 收 `vector<int>` 行吗？收 `array<int,3>` 呢？** 前者行（可变参模板模板参数匹配任意 allocator）；后者不行——NTTP `N` 不是类型参数，形状不同。
9. **为什么两阶段名字查找（依赖名/非依赖名）书里几乎没展开，读老代码却处处撞见？** `typename T::value_type` 的 typename、`this->` 前缀、`template` 消歧符都源于此——附录外的公认教学缺口 ⚠️，现代 concepts 报错友好化后仍需会读。
10. **`explicit` 在构造函数只有单参时才需要，模板构造函数怎么办？** `template<typename It> X(It, It)` 两参模板 ctor 不隐式单参；判断标准仍是"是否允许从 It 隐式造 X"。
11. **`template` 消歧符（`p->template f<T>()`）解决什么问题？** 依赖名中 `<` 默认按"小于"解析，显式模板实参需要 `template` 关键字改判——面试常拿它考"你到底有没有手写过模板"。
12. **转发引用构造函数为什么会吃掉拷贝构造？** `X(U&&)` 对 `X&` 推出 `U = X&` 比 `const X&` 更精确匹配，若不加 `!std::is_same_v<std::decay_t<U>, X>` 约束则自递归爆栈——EMC++ 条目 26 的经典事故。
13. **类模板的 CTAD 为什么需要"推导指引"而函数模板不需要？** 函数从实参表唯一确定 T；构造函数的参数与类模板参数未必一一对应（如 `vector` 的分配器参数），需要 `template(Iter, Iter) -> vector<...>` 类指引补充映射。
14. **为什么 `extern template` 不能替代头文件里的定义？** 它只是"这个 TU 别再生成"的抑制指令，定义必须仍然存在于某个 TU——编译防火墙的正身是 modules，不是 extern template。
15. **`template<typename T = int> void f();` 的默认模板参数能写两遍吗？** 声明/定义各写一次=编译错（同默认实参规则）；且后续重声明只能追加参数不能改默认值。
16. **两个模板哪个"更特化"怎么判？** 假设存在万能实参使两者同时可行，通用版能接的实参集是另一个的真子集者胜出——16.3 决议最后一级，判不出来就是二义。
17. **`typename T::size_type x;` 的 typename 和 `T::template f<U>()` 的 template 各解决哪类歧义？** 前者"这个名字是类型"、后者"这个 < 是模板实参括号"——都只在依赖名上出现，读懂它们等于读懂模板语法的一半暗坑。
7. **CTAD 出现后 `std::pair p(1, 2.5);` 的类型是什么？** `pair<int, double>`——由隐式推导指引从构造实参反推类模板参数。

## 机制：一套"类型即参数"的函数语言

**动机**：16 章回答第 10 章遗留问题——算法为何能"一物走百容器"。模板=编译期代码生成器；泛型编程与 OOP 的分界（16.1.6）：**编译期换类型选模板，运行期换类型选虚函数**。

**推断三形态速记表**（16.2.5 的骨架，背这张表等于背本章一半）：

| 形参写法 | 实参为非常左值 `int a` | 实参为 const 左值 | 实参为右值 `int()` | T 推断结果 |
|---|---|---|---|---|
| `T`（值传） | `int`，拷贝 | `int`（丢 const） | `int`，拷贝 | 不含引用/const |
| `T&`（左值引用） | `int&`→`int&` | 只能绑 const：`const int&` | 不能绑（除非 const T&） | 左值语境专属 |
| `const T&` | `int` | `int` | `int` | 万能接收，值类别丢失 |
| `T&&`（转发引用） | `int&` 折叠成 `int&` | `const int&` | `int`（不加 &） | 唯一"记住值类别"的形态 |

配套两条铁律：① 引用折叠只发生在**推断/别名**时，写 `int& &&` 直接编译错；② `T&&` 只有当 T 正被推断时才是转发引用——`vector<int>&&`、显式 `f<int>(...)` 里它就是普通右值引用。

**机制主线**：
- 推断三形态（16.2.5）：形参 `T` 值传、`T&` 左值引用、`T&&` 转发引用——各自对 const/引用/值类别的处理表是本章心脏，背表不如吃透引用折叠。
- move/forward 拆穿（16.2.6/2.7）：`std::move` 与模板无关（任何 T&& 场景都能手写 cast）；`std::forward` 必须是模板（需要"知道原值类别"）。二者都是编译期戏法，零运行时成本。
- 可变参数三板斧（16.4）：`sizeof...(args)`、`(args, ...)` 逗号包扩展、递归展开 `print(head); print(tail...)`——C++11 没有折叠表达式，所以书里递归无处不在；读 C++17 后代码时对照折叠语法即可。
- 特例化的边界（16.5）：`hash` 例子给出"通用版本先声明、特化按需补"的标准姿势；⚠️ 函数模板特例化不参与重载决议第一阶段的坑，Modern C++ 共识是"用重载别用特例化"。

**权衡**：模板的代价=编译时间、错误信息、头文件暴露实现（16.1.6 的"效率与灵活性"）；收益=零成本抽象。书中"模板放头文件"正是权衡结果，modules 想改写它。

## 最新演进与工业实践（基线 C++11 → 现在）

- **concepts 与约束（C++20，[P0734R0](https://wg21.link/p0734r0) "Wording Paper, C++ extensions for Concepts" 实测200；标准库概念 [P0898R3](https://wg21.link/p0898r3) "Standard Library Concepts" 实测200）**：`requires std::integral<T>` / `template<std::integral T>` 取代 `enable_if` 教学——报错变人话、重载可约束强弱。
- **折叠表达式（C++17）**：`(args + ...)` 终结递归展开样板（🔧 已实测；编号未跑 wg21 故不给 ⚠️）。
- **constexpr if（C++17，[P0292R2](https://wg21.link/p0292r2) 实测200）**：模板内编译期分支，替掉一半 tag dispatch 与 if-constexpr-able SFINAE。
- **CTAD（C++17，[P0091R3](https://wg21.link/p0091r3) 实测200）**：`pair p{a,b};`、`vector v{1,2,3};`——16.1 类模板写实参的日常负担解除；推导指引可自定义。
- **ranges 即模板范例（C++20，[P0896R4](https://wg21.link/p0896r4) 实测200）**：视图管道是 concepts+成员模板+完美转发的工业级综合示范，读 ranges 源码是本章最佳习题续集。
- **反射（C++26 在途，[P2996R4](https://wg21.link/p2996r4) "Reflection for C++26" 实测200）**："为每个成员自动生成"一类元模板黑魔法有望被 `^` 反射原语替代；落地范围与时间 ⚠️ 未定。
- **clang-tidy**：`modernize-avoid-c-arrays` 之外，模板可读性检查 `readability-*` 有限——模板纪律主要靠 review：能 auto 别 decltype、能约束别 SFINAE。
- **工业对照**：abseil `absl::variant/optional/span` 与 folly `fc/small` 家族的模板实现都是本章概念的量产现场；`fmt` 库的 `format_to` 可变参数+`char` 包扩展是折叠表达式的教科书样本。
- **定性标注**：`std::enable_if_t<bool, T>` 作为返回类型的 SFINAE 惯型（16.2 时代）在 concepts 之后仅作考古知识；⚠️ `auto_ptr` 式的"拷贝即转移"在模板时代被 `move_ptr` 语义彻底取代（见 09 文件）。

## 勘误与存疑

- ⚠️ "非类型模板参数限制（指针需外部链接等）"自 C++11 起多轮放宽（C++20 class-type NTTP），书口径为 C++11——读新码遇到 `template<auto N>` 属正常进化。
- ⚠️ `extern template` 在 MSVC/MinGW 的导出语义细节各平台有差——书未区分，工程落地以链接结果为准。
