# 13 · 第17章 标准库特殊设施（对应原书第17章，页635-682）

> 导航：[返回总览](00-总览与阅读地图.md) ｜ 习题答案见 [../cppprime.md](../cppprime.md)（chap 17 段） ｜ 系列导航 [../C++系列·总索引.md](../C++系列·总索引.md)

本章覆盖：17.1 tuple 类型（定义初始化/get/index/作为多返回值/匹配函数返回 tuple）→ 17.2 bitset 类型（定义初始化/位运算与 count/any/none/flip/to_string）→ 17.3 正则表达式（`regex_match` 全匹配 vs `regex_search` 子匹配/`match_results` 与 `sub_match`/`regex_iterator`/`regex_replace`/ECMAScript 语法）→ 17.4 随机数（engine 与 distribution 分离设计/`uniform_int`·`uniform_real`·`bernoulli`·正态等/`seed_seq`·`random_device`）→ 17.5 IO 库再探（格式化：oct/hex/setw/setfill/setprecision 等 manipulator/未格式化：`get/put/peek/ignore/write`/流随机访问：seekg/seekp/tellg/tellp）。

## 核心概念速览（中英对照）

- **tuple**：定长异质"打包组"；`get<I>(t)` 编译期索引、`tuple_size/tuple_element` 元编程接口
- **`tie`**：造左值 tuple 做逐元素比较/解包——结构化绑定出现前的标准解法
- **bitset<N>**：编译期定长位向量；`count/test/set/flip/to_string(2)`；区别于运行时大小的 `vector<bool>`
- **正则四件套**：`regex_match`（整串）/`regex_search`（子串）/`regex_iterator`（遍历所有匹配）/`regex_replace`（格式替换 `$1` 引用子表达式）
- **`cmatch/smatch/sregex`**：字符类型 × 序列容器类型的命名矩阵——17.3.2 的"迭代器对决定匹配容器类型"规则
- **子表达式**：括号捕获，`m[1]` 是 `sub_match`（可当 string_view 的 pair 前身）
- **ECMAScript 语法**：标准钦定的唯一正则方言（`\d \s [[:digit:]]` 等），工程上各家 boost/PCRE/re2 有超集
- **随机数双层设计**：engine（生成位流：`mt19937/mt19937_64/minstd0/rand48`）× distribution（映射分布）——生成器不直接"造骰子"
- **`random_device`**：硬件熵源，**不可移植、可能循环出定值**——播种用它但要防其退化
- **IO manipulator 三类**：值格式（`hex/dec/oct`）、字段外观（`setw/setfill/setprecision`）、布尔外观（`boolalpha`）；`setw` 只对下一次输出有效
- **未格式化 IO**：`istream::get()/read()/peek()/ignore()` 与 `ostream::put()/write()`——字节级与二进制文件通道
- **流定位**：`seekg/seekp` + `beg/cur/end`；文件流可靠，管道/终端不可靠（书 17.5.3 提醒）

## 小节细目（按原书小节号速记）

- **17.1 tuple 类型**：定义与初始化（`make_tuple` 会 decay，`tuple<int&, int>` 与 `auto&` 可保住引用）→ `get<I>` / `get<T>`（类型须唯一）→ `tie` 绑左值做逐元素 `<` 比较 → tuple 作为多返回值：`return {v1, v2}` 的聚合初始化通道。
- **17.2 bitset 类型**：`bitset<N>` 的 N 编译期固定；构造来源 `unsigned long long` / string（任意进制字符自动识别 '0'/'1'）；操作全集 `<< >> & | ^ ~` + `count any none all flip test set reset to_string`；下标返回代理引用（可写单 bit）。
- **17.3 正则表达式**：
  - 17.3.1 `regex_match`（整串才真）vs `regex_search`（子串即真）——第一个必错点。
  - 17.3.2 `match_results`（`cmatch/smatch`）与 `sub_match`：`m[0]` 全匹配、`m[1]` 第一捕获组；`sub_match` 本身是 pair 形状，可 `.str()`。
  - 17.3.3 `regex_iterator` 区间遍历所有匹配 + `regex_replace` 的 `$1` 反向引用格式串。
  - 17.3.4 ECMAScript 语法表：`\d \w \s`、字符类、`* + ? {n,m}`、非贪婪 `*?`、断言 `^ $ \b`。
- **17.4 随机数**：engine 三种（`minstd0` 线性同余 / `mt19937` 梅森旋转 / `ranlux` 迟滞）× 两种绑定方式（直接传对象、`default_random_engine` 别名）；distribution 表（`uniform_int/uniform_real/bernoulli/binomial/negative_binomial/geometric/poisson/exponential/normal`）；同一 engine+同一 distribution 每次消耗状态数不同——**别假设"取走一个数=状态+1"**。
- **17.5 IO 库再探**：17.5.1 manipulator（`boolalpha/hexfloat/scientific/fixed/setprecision/setw/setfill` 与"一次性 setw"）→ 17.5.2 未格式化 `get/peek/read/ignore` 与 `put/write`（二进制读写文件的正门）→ 17.5.3 `tellg/tellp/seekg/seekp(beg|cur|end)`；文件流可随机，终端/管道 ⚠️ 不保证。

## 自查与面试高频

1. **`regex_match` 和 `regex_search` 对 `"abc123"` 用 `\d+` 结果分别是？** false / true——match 要求全串覆盖。
2. **`tuple<int, int> a{1,2}, b{1,3}; a < b` 合法吗？** 合法，逐元素字典序——`tie` 比较惯用法的原因。
3. **为什么 random 头文件不直接给 `randint(1,6)` 而是 engine+distribution？** 生成源与分布整形解耦：同一分布可换不同质量/可重现性的源；`uniform_int_distribution` 还修正了 `rand()%6` 的取模偏差。
4. **`setw(8)` 后两条输出都变 8 宽吗？** 否，只对紧随的一次输出有效；`setfill` 却是粘滞的。
5. **二进制文件读入 `std::string` 的正确姿势？** `ios::binary` + `seekg(end)` 求长或逐块 `read`，配合 `gcount()` 处理短读——文本模式换行翻译会破坏字节数。
6. **`vector<bool>` 与 `bitset<N>` 怎么选？** 编译期已知宽度→bitset（可作 NTTP、无代理引用坑）；运行期动态→考虑 `vector<char>`/`boost::dynamic_bitset`，`vector<bool>` 的代理引用与标准容器要求有兼容性差异。
8. **`make_tuple(42, "hi")` 得到的第二个元素类型？** `const char*`（decay 后存指针）——字面量跨线程/存 string 时先 `std::string{"hi"}` 显式造好再塞。
9. **`std::regex r; r.assign("[(", 2)` 会发生什么？** 抛 `regex_error`（模式非法）——std::regex 编译期校验但异常常被忽略；配置中心来的 pattern 要先 try-compile。
10. **`bitset<10> b("1010abc")` 的结果？** 抛 `std::invalid_argument`——string 构造逐字符检查只认 0/1；`b = 0xFFULL` 的赋值则是"从整数截断低 8 位进 10 位宽"，构造与赋值语义不对称。
11. **`default_random_engine` 在不同编译器下是不同引擎，为什么标准钦定这种"不一致"？** 它表达"平台默认档"而非具体算法；可复现实验必须点名 `mt19937`/`mt19937_64` 并固定种子——17.4 测试确定性的根因。
12. **`get<0>(t)` 忘了 `#include <tuple>` 会报什么错？** 模板找不到/ADL 失败的连锁错误——tuple 的函数与类型同头文件（`std::get` 非 ADL 可达，需显式包含）。
13. **`random_device` 能直接当 engine 传给 `shuffle` 吗？** 接口上它满足引擎概念但实现可能每次开熵源——性能塌方；标准姿势是用它播种 mt19937。
14. **`ss.put(c)` 与 `cout << c` 对 `char` 值 >127 时行为差别？** put 按无符号转 `streambuf::sputn` 原样写字节；`<<` 走 locale 的字符转换通道——二进制输出永远用 put/write。
15. **`std::to_string` 与 `std::format` 的精度控制能力差在哪？** to_string 固定 6 位小数式的 legacy 行为被诟病多年；format 的 `{:.3}`/`{:x}` 才是"格式化进 std"的终点（17.5 演进主线的另一端）。
16. **`m.prefix()`/`m.suffix()` 返回什么？** `sub_match`——正则匹配点前后残留文本，`regex_replace` 手搓版（find→拼 prefix→替换→继续）用它才不丢字。
7. **`std::expected<T, E>` 与 `optional<T>` 的本质差别？** expected 强制携带错误信息 E 并可携带值/错误两种状态，`value_or/and_then` 语义同族；optional 只回答"有没有"。

## 机制与权衡（按小节）

- **17.1 tuple**：动机是"函数返回多值不逼你造 struct"。`auto t = highestOccurrence(...)` 风格在 16.2 推断配合下确实简洁，但可读性被广泛诟病——**优先返回具名 struct** 是 2020s 共识。
- **17.2 bitset**：`N` 是编译期参数→`sizeof(bitset<80>)==10`，可作模板参数/成员；`vector<bool>` 是动态版但代理引用一堆限制（`&v[0]` 不合法等）。工业上位图超过几千 bit 直接上专用库（roaring 等）。
- **17.3 regex**：`std::regex` 的 ECMAScript 语法够用；**性能与栈安全是它的阿喀琉斯**——回溯爆炸（ReDoS）与深递归段错误在 libstdc++ 上都有名有姓。书未提，工程必修（见演进节）。
- **17.4 random**：engine/distribution 分离是"生成与整形解耦"的漂亮设计——`shuffle(v, g)` 接受的是 engine 不是"随机数"。默认 `mt19937` 32 位：别用 `rand()%6` 的旧习，书也反对。
- **17.5 IO 再探**：manipulator 矩阵（17.5.1 表格）查阅即可；真正记住三件事：`setw` 一次性、precision 对浮点语义（总位数 vs 小数位数，fixed 改变含义）、二进制文件要 `ios::binary` 打开。

## 速查两表（17.3 / 17.5 的查阅件）

**ECMAScript 正则常用语法（17.3.4）**：

| 写法 | 含义 | 备注 |
|---|---|---|
| `\d \w \s` | 数字/字母下划线/空白 | 反义 `\D \W \S` |
| `[abc] [^abc]` | 字符集/取反 | `-` 区间只在集内特殊 |
| `* + ? {n,m}` | 重复 | 全部默认贪婪，尾随 `?` 转非贪婪 |
| `^ $ \b` | 行首尾/词界 | `\B` 非词界 |
| `(...)` `(?:...)` | 捕获/只分组不捕获 | `$1` 只在 regex_replace 格式串引用捕获 |
| `a\|b` | 交替 | 优先级最低，常需外层括号 |

**manipulator 粘滞性（17.5.1）**：粘滞=`boolalpha showbase showpoint fixed scientific unitbuf` + `setfill/setbase/setw` 之外的 `set*`；一次性=`setw` 与 `endl`（附带 flush）；`setprecision` 的含义随 `fixed/scientific/hexfloat` 切换（小数位数 vs 总有效位数）。

## 🔧 实测（已实测 g++ 15.2, -std=gnu++23）

`s13.cpp`：17.1 tuple+结构化绑定、17.3 子表达式与 `regex_search`、17.4 固定种子骰子，外加 23 章级补位 `std::expected`（对位 17.1"返回可失败多值"的现代解）：

```cpp
std::regex phone{R"((\d{3})-(\d{4}))"};
auto [a,b] = std::tuple{1, 2.5};                    // C++17 tie 的继任者
std::expected<int, std::string> parse(std::string_view s){ ... }  // C++23 P0323R12
std::mt19937 g(42); std::uniform_int_distribution<int> d(1,6);
```

```
区号=555 号码=1234 整个匹配=555-1234
tuple: 1 2.5
expected有值: 42
expected错误: 非数字字符: x
骰子x5(固定种子): 3 5 6 2 5 
```

固定种子输出可复现——演示"确定性测试"这一 17.4 的工程用法。

## 最新演进与工业实践（基线 C++11 → 现在）

- **`std::optional`（C++17）/`std::expected`（C++23，[P0323R12](https://wg21.link/p0323r12) "std::expected" 实测200）**："可能失败的返回值"终结 tuple<bool,T> 黑话；optional 的单值版经 [P0798R8](https://wg21.link/p0798r8) "Monadic operations for std::optional"（实测200）获得 `and_then/or_else` 管道，expected 同样有 [P2505R5](https://wg21.link/p2505r5) "Monadic Functions for std::expected"（实测200）。
- **tuple → 结构化绑定 + 具名聚合（C++17，[P0217R3](https://wg21.link/p0217r3) 实测200）**：17.1 的 `get<0>` 阅读税被 `auto [mean, sd]` 归零；tuple 退居泛型库内部（apply/visit 的中转站）。
- **constexpr bitset（C++20/23，[P2417R2](https://wg21.link/p2417r2) "A more constexpr bitset" 实测200）**：17.2 全部操作进编译期，配置位图可在 `static_assert` 里验证。
- **`std::format`（C++20）/ `std::print`（C++23，[P2093R14](https://wg21.link/p2093r14) 实测200）**：17.5 整套 manipulator（`setw/setfill/setprecision`）被 `{:>8.3f}` 一行替代——格式化 IO 章节在 2025+ 的正确打开方式是 format 规范。
- **filesystem（C++17，[P0218R1](https://wg21.link/p0218r1) 实测200）**：17.5.3 手工 `seekg` 算文件大小的旧惯用法改用 `fs::file_size`。
- **工业对照（regex）**：`std::regex` 性能弱是行业共识——Google 用 RE2（线性时间、无回溯）、工业解析多用 simdjson/re2/boost::xpressive；**`std::regex` 进生产路径前先做 ReDoS 审计**。
- **random 工程细节**：密码学场景 std::random 全家不合格（非 CSPRNG），要 `RAND_bytes`/OS 熵；模拟/游戏用 `mt19937_64` + 良好播种（`seed_seq` 从 `random_device` 取 4×64bit）——5 版没写的"种子卫生"是现代必学。
- **clang-tidy**：`readability-magic-numbers`（位掩码建议 constexpr）、`modernize-use-std-print`（有实验性 print 检查）。

## 勘误与存疑

- ⚠️ 17.3 示例里 ECMAScript 语法对 `[:space:]` 等 POSIX 类的支持在 libstdc++ 长期缺位——书按标准表格讲，实测可能踩空，用 `\s` 即可。
- ⚠️ 17.4 `seed_seq` 小节标注（书中存在但部分版次页码不同）；细节按标准。
