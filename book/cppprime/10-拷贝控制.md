## 核心概念速览（中英对照）

- **拷贝构造函数** — copy constructor：第一参数是本类型引用（通常 const&）；触发时机清单比想象长（按值传参、按值返回、braced-init、vector 扩容……）
- **拷贝赋值运算符** — copy assignment：先备后换（copy-and-swap 是异常安全正道之一）
- **析构函数** — destructor：释放资源 + 成员逆序销毁；"拥有资源的类几乎总需要自定义析构"（法则一）
- **三法则 / 五法则** — Rule of Three/Five：需要自定义析构/拷贝/赋值之一，就五个全要显式处理（`=default/=delete` 也算处理）
- **`=default`（C++11）**：索要合成版；**`=delete`**：显式删除（阻止拷贝/阻止特定重载）
- **行为像值** — value-like：深拷贝，各副本独立（string 的写时复制 ⚠️ 已因线程安全被各实现抛弃，书 13.2 时代还留着讨论尾巴）
- **行为像指针** — pointer-like：引用计数共享，自定义析构减计数——shared_ptr 的手写原理（13.2.2）
- **swap**：不拷贝地交换状态；成员 swap 应 `noexcept`，非成员重载配合 ADL
- **右值引用** — rvalue reference `T&&`：只能绑右值；`std::move` 只是左值→右值的**强制转换**，本身不移动任何东西
- **移动构造/移动赋值**：窃取资源；必须让源对象进入可析构状态（置空）；**通常应标 noexcept**——vector 扩容只在可移动且 noexcept 时才用移动（13.6.2 关键机制）
- **移动迭代器** — move_iterator：`std::make_move_iterator`，把解引用变成右值——vector 搬迁的内部功臣
- **引用限定符** — ref-qualifier（C++11）：`void f() &;` `void f() &&;` 按对象值类别重载成员函数
- **合成移动**：只有用户没写拷贝相关成员时编译器才合成移动——"写了拷贝构造就丢了默认移动"的著名坑
- **完美转发预告**：`std::forward` 在 16.2.7 才展开；本章只立"右值引用+move"两块地基

## 小节细目（按原书小节号速记）

- **13.1.1 拷贝构造（页440）**：第一形参必须引用（否则无限递归）；触发时机全列表——按值传/返、`{...}` 聚合成员、`vector` 扩容、`make_pair` 模板实参……编译器还常"本该拷贝却直接初始化"的省略（copy elision，C++17 变强制，见演进节）。
- **13.1.2 拷贝赋值（页443）**：自赋值检查（`if (&rhs == this) return *this;` 或用局部副本规避）；返回 `*this` 引用；"先分配新再释放旧"的异常安全顺序。
- **13.1.3 析构（页444）**：函数体→成员逆声明序→基类逆序；"类有其它析构需求前，先确保 vector/string 成员自管"；显式调用析构=罕见双杀（见 19.1 定位 new 配对）。
- **13.1.4 三/五法则（页447）**：合成拷贝构造/赋值对智能指针成员"恰好正确"（计数共享）；对裸指针成员"恰好全错"；"用了 =default/自定义/删除之一就要五件套全表态"。
- **13.1.5-13.1.6（页449-451）**：`=default` 在类内=inline、类外=非 inline 的差别；阻止拷贝三工具：`=delete`（正解）、private 声明不定义（旧式）、定义但声明为 delete 的移动。
- **13.2.1 行为像值（页453）**：StrBlobPtr→Blob 深拷贝版；写时复制 COW 的历史与出局（线程安全成本）。
- **13.2.2 行为像指针（页455）**：引用计数四操作（拷贝+1/析构-1/赋值双向调整/共享数据独立）——shared_ptr 原理手推。
- **13.3 交换（页457）**：成员 `noexcept` swap + 非成员特化 std::swap 的 ADL 配合；`swap(Message&)` 必须重注册 Folder——"移动赋值=swap+销毁旧"的派生式实现。
- **13.4 Message/Folder（页460-463）**：save/remove/copy/move/析构五件套+swap，全书最完整的拷贝控制工程样本。
- **13.5 StrBlob/Query（页464-469）**：shared_ptr 包 vector 的"共享容器"；StrBlobPtr 用 weak_ptr；Query 反向指针 + allocator 版 BigSeg 手搓 vector 迷你实现（alloc_n_build）。
- **13.6.1 右值引用（页471）**：`T&&` 绑右值；函数返回/IO 读取结果天然右值；"函数返回左值可赋值，返回右值不可"的判据；`std::move` 的模板真身 `static_cast<T&&>`。
- **13.6.2 移动构造/赋值（页473-481）**：noexcept 与 vector 扩容契约；移动迭代器与 `uninitialized_copy/move`；"移动后源对象只能赋值/析构"的合同。
- **13.6.3（页481-485）**：`&&` 限定成员（`std::string str() &&;` 只对将亡值开放）；右值引用的成员重载矩阵。

## 自查与面试高频

1. 只写拷贝赋值不写拷贝构造，移动会发生什么？（按标准"五法则"连锁：移动被抑制）
2. 为什么移动构造忘标 `noexcept` 时 vector 扩容回退拷贝？怎么实测？（🔧 样例删 noexcept 重跑）
3. copy-and-swap 实现赋值运算符同时解决哪三件事？（自赋值/异常安全/代码复用）
4. `std::move(v)` 之后还能 `v.push_back` 吗？（标准只承诺可析构可赋值；具体容器行为看合同）
5. unique_ptr 的拷贝构造是"被 delete"还是"根本没声明"？差别？（声明+delete，重载决议期即报错且信息明确）
6. 为什么析构函数几乎不该抛异常？`noexcept` 从 C++11 起对它是默认吗？（栈展开中二次异常即 terminate；默认隐式 noexcept(true)）
7. Rule of zero 说"优先设计成无需手写五法则"——用 `vector`/`unique_ptr` 成员组合如何实现？还剩什么情况必须自己写？
8. 移动赋值里"先释放自己再接收对方"与"swap 后把旧资源留给对方析构"两种写法，异常安全等级差在哪？
## 五法则决策树（速记）

```
需要手工管理资源吗?
├─ 不需要 → Rule of Zero: 五个特殊成员一个都不写
│            (用 vector/unique_ptr/shared_ptr 组合出语义)
└─ 需要   → 值语义(可拷贝)还是引用语义(只移动)?
    ├─ 只移动 → 写 移动构造+移动赋值(都 noexcept) + 析构,
    │           显式 =delete 拷贝两件 (unique_ptr 模式)
    └─ 可拷贝 → 五件套全写; 拷贝用拷贝-赋值=交换惯用法;
                移动 noexcept 否则 vector 扩容退化为拷贝
```


## 机制：对象生命周期经济学

**动机**：拷贝控制=类作者决定"复制这个类值不值得、怎么复制"。C++ 的独特立场是默认按位/逐成员拷贝，代价自定义、收益显式。

**机制主线**：
- 析构次序：函数体 → 成员逆声明序 → 基类逆序；资源获取即初始化（第12章）+ 逆序销毁 = RAII 完整闭环。
- 五法则决策树：先问"要不要自定义析构？"要→五个全表态（哪怕 `=default`）；不要→大概率全别写（零法则 Rule of Zero）。
- 移动的操作合同：** noexcept 才能进 vector 增长快路**；移动后源必须自洽（可析构、可赋值），`std::move` 之后继续用源对象除了赋值/析构都是危险。

**权衡**：写时复制（COW）在 13.2.1 作为"值语义的优化版"出现——现代多线程环境里它的原子引用计数成本与可观测的共享语义使它出局；这是"5 版教法定性"的典型样本。

**相邻概念对比**：移动构造 vs 拷贝构造+swap 优化；`std::move` vs `std::forward`（前者无条件转右值、后者条件转——值类别系统两员，16 章再辩）；`&`/`&&` 引用限定与 const 重载正交。

## 13.4-13.5 两个经典大例

- **Message/Folder**：互相引用的所有权网状结构，拷贝=重建文件夹注册、移动=转移注册、析构=注销——"自定义拷贝控制处理间接资源"的完整示范；`swap` 先交换再重注册是 13.3 的活教材。
- **StrBlob/StrBlobPtr**：用 `shared_ptr` 把 vector 包成"行为像共享指针"；`weak_ptr` 版 StrBlobPtr 防悬垂（接 12.1.6）。13.5 的 `alloc_n_construct` 私有辅助 + allocator 复用是手写容器的前置戏。

## 🔧 实测（已实测 g++ 15.2, -std=gnu++11）

`s10.cpp`：移动构造标 noexcept 后，vector 扩容走移动而非拷贝（去掉 noexcept 立刻变一串 copy）：

```cpp
Blob(Blob&& o) noexcept : p(o.p), n(o.n) { o.p=nullptr; o.n=0; printf("move "); }
std::vector<Blob> v;
v.push_back(Blob(1)); v.push_back(Blob(1)); v.push_back(Blob(1));
```

```
move move move move move move 
move b.n(已移走)=0 c.n=2
```

6 次 move 中一半来自临时量入容器、一半来自扩容搬迁——对照 13.6.2"移动构造函数通常应该是 noexcept 的"（书中 C++11 新特性小节原文精神）。

## 最新演进与工业实践（基线 C++11 → 现在）

- **强制拷贝消除（C++17，[P0135R1](https://wg21.link/p0135r1) "guaranteed copy elision" 实测200）**：`T f() { return T(); }` 不再承诺"至少一次移动可省"而是**根本不发生**构造调用；13.2 的拷贝计数心智模型要更新。
- **条件 trivial 特殊成员（C++20，[P0848R3](https://wg21.link/p0848r3) "Conditionally Trivial Special Member Functions" 实测200）**：constexpr 析构等能力解锁，聚合/变体类在编译期可持有资源。
- **默认比较（C++20，[P0515R3](https://wg21.link/p0515r3) 实测200）**：13.1"要不要写 operator=="的问题变成 `= default` 一行（详 11 文件）。
- **ranges 的移动语义**：`std::ranges::to`（[P2602R0](https://wg21.link/p2602r0) 实测200）收集管道结果时全链移动无拷贝——13.6 的成果在库层的兑现。
- **clang-tidy**：`modernize-use-equals-default/delete`、`performance-move-const-arg`（对 const 对象 move 无意义）、`cppcoreguidelines-special-member-functions`（五法则巡检）；`noexcept` 漏标由 `misc-no-recursion` 之外另有 `performance-no-automatic-move` 提醒。
- **工业对照**：folly 的 `fbvector`/`F14` 把"扩容何时敢 move"做到极致（trivially moveable 概念），正是 13.6.2 机制的工业放大；GSL 的 `std::move` 纪律（核心准则 R.* 家族）以静态检查兜底。
- **定性标注**：⚠️ "移动后源对象处于但未指明有效状态"的 5 版措辞已被"可析构且可赋予新值"的精确合同替代（标准文本演进）；13.6.1 "左值变 xvalue 用 std::move" 在 C++23 的 `std::as_rvalue` 出现前仍是唯一工具——教学地位不变。
