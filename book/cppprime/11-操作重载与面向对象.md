## 核心概念速览（中英对照）

- **运算符重载** — operator overloading：保持"直觉含义+对称性"的接口设计；不能重载的：`:: .* -> ?:` 等
- **IO 运算符必须非成员**：左操作数是流；输出用 const 引用、输入返回 `istream&` 支持级联
- **对称运算符三件套**：成员 `+=` + 非成员 `+ = +=` 实现（14.3 的搭档模式，C++20 spaceship 前夜的标配）
- **前置/后置 ++**：后置用哑元 int 区分、返回旧值副本——迭代器类的高频日常
- **下标返回引用**：`T& operator[]` 可当左值；const 对象版返回 const（C++11 `at()` 补检查）
- **函数对象** — function object：重载 `operator()` 的类；lambda=编译器合成的函数对象（14.8.1 点破）
- **std::function**：类型擦除的可调用对象容器；`mem_fn/bind`（19.4.3）与它同族
- **类型转换运算符** — `operator T()`：隐式转换之源；**explicit operator bool**（C++11）——流与智能指针的安全 bool 惯型
- **二义性军规（14.9.2）**：不要两个类互转；不要既转算术类型又转 bool；不要重载 `&& || ,`（短路丢失）
- **多态** — polymorphism：基类引用/指针经虚函数分派；**虚函数只在通过引用/指针调用时才"虚"**
- **override / final（C++11）**：编译期核对覆盖意图/封死再覆盖
- **纯虚函数与 ABC**：`= 0`；抽象基类不可实例化、可定义（析构等）供派生调用
- **虚析构铁律**：可能按基类指针 delete 的类必须有虚析构（或删除析构走 `~Base() = delete`）
- **对象切片** — slicing：按值传/存派生对象丢失派生部分——多态场景必须指针/引用
- **容器与继承**：容器存 `shared_ptr<Base>`（15.8 Basket），不存基类值
- **句柄类** — handle class：Query 包 Query_base 引用计数——"接口稳定、实现可扩"的中间人（13.2.2 复用）
- **继承的构造函数（C++11）**：`using Base::Base;` 一行继承全部构造

## 自查与面试高频

1. 为什么 `operator<<` 不能做成成员？（左操作数是流）
2. `explicit operator bool` 与 `operator bool` 的调用点差异？（条件语境 vs 任意语境）
3. 基类析构非虚、`delete base_ptr` 会发生什么？为什么编译器常不报警？
4. 派生类只覆盖了 `f(int)`，调用 `d.f(double)` 为什么找不到基类 `f(double)`？（遮蔽；using 修复）
5. 构造/析构函数里虚调用解析到谁？（当前层——vptr 尚未/已切换）
6. 虚函数默认实参为什么"按静态类型取"？给出基类派生类默认值不同的事故样例。
7. `override` 关键字在重构中的价值？没有它时改名基类虚函数会发生什么？（派生静默变成新函数，多态断链）
8. `operator new` 重载在类级别合法、全局重载"合法但危险"的原因？（全局替换影响所有分配含第三方库；正确通道是类级/分配器策略）
9. 基类指针容器 `vector<shared_ptr<Query>>` 里放派生对象，`push_back` 之后对象被"切"了吗？为什么智能指针免疫？（切片只发生在按值；指针/引用持有多态身份）
10. 引用计数的 Query 体系为什么析构函数不递归 delete？（叶子为空、内部节点由 shared_ptr 自动归零——15.8 用所有权替掉手动树销毁）
11. `Query_base` 析构为什么可以非虚？如果改成 `unique_ptr<Query_base>` 持有会怎样？（shared_ptr 存的删除器记住了派生类型——非虚析构在智能指针下安全是"定制删除器"的副作用 ⚠️ 教学盲区）

## 第14章：接口设计学

**机制主线**：运算符重载的目的不是语法糖，而是让自定义类型**融入语言惯用法**——`==` 该对称、`[]` 该可当左值、`<<` 该可级联。三处深坑：
1. `>>` 的教科书实现要"读前判条件、失败擦回现场"（14.2.2 的 read 恢复故事，异常安全的前哨课）。
2. `operator bool` 的旧写法允许 `if (cout == 42)`，`explicit operator bool` 只允许条件语境——第1章 `while (cin >> v)` 的实现真相在此揭晓。
3. 二义性（14.9.3）：类类型转换参与重载决议，两个候选各赢一步即歧义——"少写转换运算符"是唯一防御。

## 第15章：运行期多态的成本与边界

**动机**：把 Query 例子从 12.3 的迭代器风格重写为策略模式家族——全书 OOP 高潮。

**机制要点**：
- 虚调用三层间接（对象 vptr → 类 vtable → 函数指针）：概念模型书只给示意，细节归侯捷/Inside the C++ Object Model（延伸链）。
- 名字查找（15.6）：派生类同名遮蔽基类版本——哪怕基类版本是虚函数、派生签名不同也会**遮蔽而非重载**；`using Base::name;` 拉回重载集。
- 构造/析构期间虚函数不"虚"（15.7：构造基类部分时派生 vptr 未就位）——**不要在构造析构里调虚函数**。
- `private` 继承=实现继承（is-implemented-in-terms-of），罕见正解；`protected` 数据成员是设计失误（书有同感），应 protected 函数。

**权衡**：多态 vs 模板（16 章）——运行期换类型（OOP）vs 编译期换类型（泛型）；多态的 vtable 成本、缓存不友好与可组合性收益需逐案评估。C++23 `std::polymorphic` ⚠️ 未进标准（该提案后续被撤回/搁置），动态多态主流仍是虚函数与 `std::function` 两轨。

## 🔧 实测（已实测 g++ 15.2, -std=gnu++20）

`s11.cpp`：C++20 默认 `<=>` 一行顶 14.3 六-operator 手工区；容器持 `unique_ptr` 的 ABC 多态：

```cpp
struct Point { int x, y; auto operator<=>(const Point&) const = default; };
struct Query { virtual ~Query() = default; virtual std::string rep() const = 0; };
std::unique_ptr<Query> q = std::make_unique<Word>("hello");
```

```
Point{1,2}=={1,2} -> true
(Point{1,2} < Point{1,3}) -> true
虚调用: Word(hello)  (基类指针析构必须虚析构)
```

## 最新演进与工业实践（基线 C++11 → 现在）

- **一致比较（C++20，[P0515R3](https://wg21.link/p0515r3) "Consistent comparison" 实测200）**：`operator<=>(const&,const&) = default;` 同时生成 `== < <= > >=` 全套；14.3 的"成对重载"教学基本成为历史负担（仍要懂，用于读旧码）。
- **`[[nodiscard]]`（C++17，[P0189R1](https://wg21.link/p0189r1) 实测200）**：给"不接返回值就是错"的重载运算符/工厂函数加锁。
- **lambda 时代（14.8 的正统续篇）**：14.8.3 的手写 `StrLong` 函数对象、`plus<int>` 现代一律 lambda/投影替代；`std::function` 在 C++23 获得 move-only 可调用对象支持（提案号未实测 ⚠️ 不给号）。
- **variant + overload 模式（C++17）**：封闭类型集（不随派生扩展）的静态多态替代虚函数：`std::visit(overload{...}, var)`——变体构造由 [P0608R3](https://wg21.link/p0608r3) "A sane variant converting constructor" 实测200 定型。
- **clang-tidy/GSL**：`cppcoreguidelines-virtual-class-destructor`、`modernize-use-override`、`google-explicit-constructor`（隐式转换军规的工具化）。
- **工业对照**：abseil 用 `absl::variant/Status`（值语义错误+多态）替代异常类层次——与 15 章"Query 树"相对的扁平设计流派；folly `Promise/Pipeline` 亦属"组合代替继承"阵营。
- **定性标注**：14.9 "implicit conversion 满天飞"年代的解法（explicit 化一切）已成默认；⚠️ 5 版对"重载 `new`/用户字面量 `operator""`"着墨极少，现代库（units/chrono literals）重度依赖后者。
