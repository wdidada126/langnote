## 核心概念速览（中英对照）

- **栈展开** — stack unwinding：throw 后逆序销毁局部对象直至匹配 catch；RAII 保证析构执行
- **catch 匹配顺序**：派生类在前、`catch(...)` 兜底；**按引用捕获**避免切片丢失派生信息
- **重抛出** — `throw;`：在原 catch 内重抛"原件"（保留派生类型），区别于 `throw e;` 的复制降级
- **function try block**：构造/析构初始化列表抛异常的唯一捕获点；捕获后仍隐含重抛
- **noexcept 说明/运算符（C++11）**：`void f() noexcept;` 违约即 `terminate`；`noexcept(expr)` 编译期查询——移动构造的 vector 契约依赖它
- **异常类层次**：`exception → logic_error/runtime_error` 两支 + `nested_exception`（C++11，`std::throw_with_nested`/`rethrow_nested`，书 18.1.5 点到）
- **命名空间** — namespace：全局名字冲突的结构化管理；匿名 namespace=文件静态
- **using 声明 vs using 指令**：声明引入单个名字（头文件可用），指令引入全部（仅源文件/函数内）
- **ADL** — argument-dependent lookup：实参类型所在命名空间的函数参与查找——`std::swap` 重载生效的机制（18.2.4/书在 13.3 呼应）
- **内联名字空间（C++11）**：版本管理——`ns::v2::f` 名字提升到 `ns::f` 可见，又可用全名精确调用
- **多重继承** — multiple inheritance：菱形问题+名字二义+构造顺序；**虚继承**共享间接基类子对象（代价：vtable 间接寻址、构造责任归最派生类）
- **`dynamic_cast`**：有符号/无符号/void*/跨继承四类转换语义；失败返回 nullptr（指针）/抛 bad_cast（引用）；RTTI 三工具之二
- **`typeid` 与 type_info**：多态类型才运行期识别；`hash_code`/`name` 均实现定义
- **enum class（C++11）**：作用域隔离 + 不隐式转整 + 可指定底层类型；普通 enum 保持旧兼容
- **成员指针** — pointer to member：`int X::*pd; void (X::*pf)(int);` 需要对象才能解引用；`mem_fn` 包装成可调用
- **嵌套类** — nested class：名字作用域限定 + 可访问外围私有（成员实现），StrBlobPtr 模式（13.5）
- **union**：共享内存的互斥成员组；C++11 起可有带非平凡构造成员（需手工生命周期）——`std::variant` 的裸体版
- **位域** — bit-field：`unsigned bf : 3;` 布局实现定义，跨平台序列化禁入
- **volatile**：禁止编译器缓存该内存（**不保证原子性/线程同步**——常被误用，18.1 后与 C++11 原子库划清边界）
- **`extern "C"`**：关名字改编与调用约定差异，C ABI 桥；也可包住函数与变量
- **附录A 定位**：头文件-名字对照表 + 算法十大类速查 + 随机数设施表，纯查阅件

## 机制与权衡

### 18.1 异常：错误传播的"第二通道"

机制：异常走类型匹配不走值返回；`terminate → unexpected → set_terminate` 的历史包袱（`unexpected` 在 C++11 已废 ⚠️，书如实标旧）。**noexcept 的算法意义**（18.1.4）：标准库用 `noexcept` 探测决定容器扩容可否移动（13.6 回环）；自定义移动构造忘标是性能事故。
权衡：异常 vs 错误码/expected——**构造失败与深层嵌套循环里异常有主场**；高频失败路径（解析器热循环）用 `std::expected` 更便宜。两种风格不可混用为"有的地方抛有的地方返回"——API 要一致。

### 18.2 命名空间与 ADL

机制：using 指令引入的候选在查找时**与本地候选共同决议**，同名冲突才报错——"接口膨胀"（接口污染）是 using 指令进头文件的经典病灶。ADL 正解：`swap` 定制点、`operator<<` 放类型所在 ns；滥用后果："unsuitable ADL"（gcc 有专名）使无关函数成为候选。
对比：匿名 namespace（内部链接，每个 TU 独立类型！）vs `static`（老式文件作用域）vs 模块内部链接——C++20 modules 后部分话题改写。

### 18.3 多继承与虚继承

机制：构造/析构按声明序→逆序；虚基类由**最派生类**直接构造（中间类都声明也不管）。虚继承布局（vbptr/虚基表）归对象模型书。
**定性标注**：接口类（纯虚）多继承是"现代 Java/Go 式多实现接口"的 C++ 原型，仍在用；带状态的多继承、菱形虚继承组合在 2020s 工业 review 里默认死刑，`std::variant` 值类型与组合优先。

### 19.x 特殊工具箱

- **重载 new/delete + 定位 new（19.1）**：池分配器/对齐控制/对象构造在预分配内存（`new (p) T(args)`）——现代用 pmr/`allocator` 替代手搓；定位 new 仍活在线程本地 arena 与 placement 容器实现里。
- **RTTI（19.2）**：dynamic_cast 的正当使用极少（Visitor 的 `cast` 逃生舱）——**能虚函数解决就别 typeid**；RTTI 成本（typeinfo 链接/跨 DLL 身份）书未展开 ⚠️。
- **成员指针（19.4）**：数据成员指针在反射式泛型（"把字段当参数传"）有独用——ranges 投影就是 `&Person::age`（🔧 08 文件演示过）；成员函数指针当回调的现代包装 `mem_fn/bind/lambda` 三选一。
- **union（19.6）**：手工判别联合体是 UB 温床；**std::variant（C++17）是默认答案**（构造约束由 P0608R3 实测200 定型）。
- **volatile（19.8.2）**：仅"MMIO/信号处理边界"正当；并发一律 `std::atomic`——书在 19 末给出 C++11 原子库指引（⚠️ 5版未讲多线程，线程设施见姊妹书）。

## 自查与面试高频

1. `catch (exception e)` 为什么是双重错误（切片+可能再抛）？正确姿势两个关键词？（`const&`+按派生在前排序）
2. 函数 try block 捕获构造初始化列表异常后"还要不要写 throw"？（不写也隐含重抛；对象已是半构造态，能做的只有记日志）
3. `noexcept(f())` 与 `noexcept` 作为说明符长得一样，怎么从上下文区分？（运算符进表达式求值为编译期 bool；说明符是函数类型的一部分，参与重载）
4. using 指令放进 .h 为什么被 review 一票否决？给一个它引发"下游某天突然编译不过"的机理。（引入的名字污染所有包含方，与新标准库名字相撞）
5. 虚继承下中间类都在初始化列表写了 `Base(...)`，最终用谁的和构造顺序？（最派生类的直接调用；其余全被忽略——"虚拟基类由最派生类负责"）
6. placement new 之后 delete 该指针错在哪？正确的两生命周期操作？（未经匹配的构造直接调删除器；须手工 `p->~T()` 且不 free 内存）
7. `dynamic_cast<Derived*>(base)` 返回 nullptr 与"转换失败抛 bad_cast"各发生在什么目标类型下？（指针形态/引用形态）
8. `extern "C"` 包住函数声明和包住整个头文件，链接指示到底改变了什么、没改变什么？（名字改编与调用约定；C++ 语义检查照旧）
9. 匿名 namespace 与 `static` 函数的差别只剩"类型身份"了吗？（每个 TU 中匿名 ns 的类型是不同类型——把它们放进头文件被两侧包含即 ODR 违规事故源）
10. `catch (const std::exception&)` 里再 `throw;` 与 `throw std::current_exception();` 的语义差别？（前者原样继续展开；后者把"当前异常"装箱可跨线程搬运——`exception_ptr` 家族）
11. 虚继承下 `typeid(Derived).name()` 跨 DLL 相等吗？为什么 RTTI 身份是"实现定义"？（typeinfo 按地址比身份，跨模块合并靠链接器/运行期支持；name 格式各厂商不同）
## 🔧 实测（已实测 g++ 15.2, -std=gnu++20）

`s14.cpp`：异常包装重抛、内联 namespace 版本管理、dynamic_cast、mem_fn、scoped enum：

```cpp
namespace lib { inline namespace v2 { int api(){ return 200; } } }
enum class Color : unsigned char { red = 1, green, blue };
try { ... throw std::runtime_error("wrapped: outer"); } catch (const std::exception& e) { ... }
auto fn = std::mem_fn(&Derived::who);  fn(d);
```

```
捕获: wrapped: outer
lib::api()=200 且 lib::v2::api()=200
dynamic_cast成功: derived 
derived 
Color::green底层值=2 (无隐式转int)
```

## 最新演进与工业实践（基线 C++11 → 现在）

- **`std::source_location`（C++20，[P1208R6](https://wg21.link/p1208r6) 实测200）**：`__FILE__`/19.5 断言样板的类型安全替身；默认实参 `std::source_location loc = std::source_location::current()` 是现代"记录调用点"标准式。
- **contracts（[P2900R6](https://wg21.link/p2900r6) "Contracts for C++" 实测200）**：`pre/post` 谓注释曾规划入 C++26，2024 后被移出 ⚠️ 状态反复——pre 的 `expects` 精神已由 Gsl Expects/`__builtin_assume` 类工具承担。
- **reflection（C++26 在途，[P2996R4](https://wg21.link/p2996r4) 实测200）**：19.2 RTTI 与成员指针的"编译期反射"将覆盖"用元数据操作类型"的大部分动机；`^typeof`/`^members` 会改写 19.4 一节的存在意义 ⚠️ 时间线未定。
- **`std::expected`（C++23，[P0323R12](https://wg21.link/p0323r12) 实测200）**+ 单轨错误处理：与 abseil `absl::StatusOr`、folly `Expected` 同流派——18.1 的"异常 or 返回值"天平在"预期内失败"一侧正式加了码。
- **variant 消灭 union（C++17）**：`std::variant<A,B>` 自带判别与访问；19.6 的手工 tag 代码 review 即改。
- **模块与命名空间（C++20，[P1103R3](https://wg21.link/p1103r3) "Merging Modules" 实测200）**：命名空间解决"名字冲突"，模块解决"名字+宏+包含泄漏"——18.2 的头文件战争从根上被换题。
- **clang-tidy/工业**：`bugprone-exception-escape`（线程里裸抛）、`modernize-use-noexcept`、`misc-unused-parameters` 对位 18.1；Google style 全局禁异常 → 错误码/Status 文化——Primer 的中立叙述在工业里要选边。
- **定性标注**：`register` 存储类（附录A语言支持表）C++17 废弃、C++20 语义保留给将来；`auto_ptr` 已死（见 09）；`std::unexpected()`（异常动态规范）C++11 已废、C++17 删除——读 18.1 时跳过其讨论。
