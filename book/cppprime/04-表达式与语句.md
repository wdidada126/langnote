## 核心概念速览（中英对照）

- **左值/右值（初步）** — lvalue/rvalue：4.1 给的是"能取地址=左值"的直觉定义，严格版到 13.6
- **求值顺序未定** — order of evaluation unspecified：`f() + f()` 调用次序不定；`&& || ,` 三个有短路/顺序保证
- **副作用冲突即 UB** — `i = i++ + 1` 一类"同一表达式多次改同一对象"未定序则未定义行为
- **复合赋值** — compound assignment `+= -= *= /= %=`：与等价展开在求值次数上有微妙差
- **条件运算符** — conditional `?:`：嵌套可读性差，现代替身是 `if-else`/`switch` 表达式化写法 ⚠️（无此语法）
- **位运算符** — bitwise `~ & | ^ << >>`：移位会整型提升；有符号 `>>` 实现定义（算术/逻辑）
- **sizeof**：编译期运算符；4.9 + `sizeof 类成员`（C++11 新特性）；`sizeof...(pack)`（16.4）的预告
- **static_cast / const_cast / reinterpret_cast / dynamic_cast**：4.11.3 显式转换四件套，dynamic_cast 19.2 细讲
- **隐式转换的雷区** — 4.11.2：数组转指针、类类型经构造函数/转换运算符、bool 参与算术
- **语句即作用域**：5.2 强调条件/循环语句初始化变量拥有各自作用域
- **悬垂 else** — dangling else：else 配最近的未匹配 if
- **switch 的 case 标签** — case label：不能声明初始化变量（除非加 `{}`）、`fallthrough` 要注释（C++17 前）
- **范围 for（5.4.3，C++11）**：`for (auto &i : v)`；不能改变容器大小
- **do while**：至少执行一次；现代 code review 的高频"改写点"
- **异常三件套（5.6）** — throw / try / catch：栈展开 stack unwinding；标准异常 `exception/runtime_error/...`

## 小节细目（按原书小节号速记）

### 第4章

- **4.1.1 基本概念（页120）**：表达式=操作数+运算符；左值右值的"可取地址"判别；优先级/结合律/求值顺序三维度各自独立。
- **4.1.2 优先级与结合律（页121）**：`*p++` 的拆解示范（后置 ++ 优先于解引用、结合律决定执行序）；口诀"先括号后一元再二元"。
- **4.1.3 求值顺序（页123）**：除 `&& || ,` 与赋值外无顺序保证；`f(*p, ++i)` 类组合 UB 判定流程——"同一表达式对同一对象多次无序副作用"。
- **4.2-4.5（页124-133）**：算术（除法向零截断、取模符号跟被除数 ⚠️C++11 定死）；逻辑短路；赋值返回左操作数引用、`=` 右优先；前后置 ++ 差异与循环首选前置。
- **4.6 成员访问（页133）**：`.`/`->`/`.*`/`->*`；指针解引用链 `(*p).mem` 与 `p->mem` 等价。
- **4.7-4.10（页134-141）**：`?:` 的嵌套反例；位运算 `& | ^ ~ << >>` 与掩码惯用法（4.8 用十六进制字面量拆颜色通道）；sizeof（不真正求值、结果 `size_t`）；逗号。
- **4.11-4.12（页141-147）**：转换阶梯、常量指针↔非常量不可隐式、显式 cast 四种写法各管一段。

### 第5章

- **5.1-5.2（页154-155）**：空语句做显式"无操作"（`;` 紧跟 for 是 bug 高发）；复合语句=新作用域。
- **5.3 条件（页156-164）**：悬垂 else；条件内定义变量作用域含 else；switch 的 case 标签是"语句跳转目标"故不能声明初始化（除非花括号块）。
- **5.4 迭代（页165-169）**：while/for/do-while 选择：条件先判还是后判、循环变量作用域；范围 for 的隐藏迭代器循环展开。
- **5.5 跳转（页170-172）**：break/continue 只作用于最近一层循环；goto 跳过定义即 UB 的规则。
- **5.6 异常（页172-177）**：throw 拷贝异常对象；catch 匹配"最似"者、按引用收；`exception` 家族 `what()`；书警告"异常不是万能控制流"。

## 自查与面试高频

1. `int i = 0; i = i++ + i;` 为什么 UB？`&&` 为什么不算？
2. `sizeof(x++)` 会让 x 加一吗？（不会——sizeof 操作数不求值，C++11 起对象实例外）
3. switch 里两个 case 共享代码的正确写法（C++11 靠注释 / C++17 靠属性）？
4. `catch (exception e)` 与 `catch (const exception& e)` 差别？哪个会切片？
5. 范围 for 遍历 `vector<bool>` 为什么 `auto` 逐元素是坑？
6. `int(*p)[10]` 与 `int* p[10]` 分别是什么？如何从内向外读声明？（右左法则；数组指针是 16 章模板传数组的底层形态）
7. `x = y = z` 能链式的原因是什么？赋值运算符返回什么？（返回左操作数引用；这是自定义 `=` 的签名依据）
8. 哪些运算符不能重载？（`.*` `::` `?:` `sizeof` 与 `new`/`delete` 的"能否重载"另有专门规则；还有字面量运算符的限制）
9. `i = v.size() - 1` 当 `v` 为空为什么会得到天文数字？两种现代修法？（无符号回绕；改用 `int(v.size())` 需证明非负，或 ranges 下 `std::ssize(v)`——C++20）
10. 复合初始化 `int a{v.size()}` 缩窄到 int 会怎样？（列表初始化拒绝丢失精度的隐式转换，编译错——这是 `{}` 相对 `()` 的核心增益）
11. `goto` 在 C++ 里合法吗？跨过变量初始化的跳转为什么被禁止？（合法但 review 禁；跳过带初始化的非 POD 声明进入其作用域=编译错）

## 第4章：优先级是表，求值顺序才是坑

**动机**：新手背 `<<` 高于 `&` 低于 `+` 没意义——真出事的是 `cout << a < b` 这种把优先级差异变成行为差异的写法。

**机制**：
- 4.1.3 是本章灵魂：除 `&& || ,` 与赋值外，**操作数求值顺序未规定**。`while (ia[cnt++] = ia[cnt])` 类习题全部源于此。
- 4.11 类型转换与 2.1.2 呼应：隐式转换出现在条件、算术、引用绑定三处；显式转换四种 cast 各有边界——`const_cast` 去 const 后改原 const 对象仍是 UB。
- 4.9 sizeof：返回 `size_t`；对类成员 `sizeof Sales_data::revenue`（C++11）允许不有对象。

**权衡**：书建议"不确定就加括号 + 一行别干两件事"；工业侧的更强约束来自工具（clang-tidy `bugprone-*`、覆盖率下的 sanitizer）。

**相邻概念对比**：`.*`/`->*` 成员指针运算符（4.6 一笔带过）在 19.4 才成为主角；逗号运算符（4.10）唯一正当用途是 for 循环头，其余场景应换行。

## 第5章：语句层的工程纪律

- **5.2 作用域纪律**：循环外声明、循环内复用旧值——书用反例（`while (cin >> val)` 计数错例）演示"变量活太久"的 bug 形态。
- **5.3.2 switch**：case 穿透是特性也是事故；每个 case 要么 break 要么注释（C++17 `[[fallthrough]]` 把它变成可编译检查的约定，见 🔧）。
- **5.4.3 范围 for**：等价于"用迭代器遍历且迭代器只前进一次"；`vector<bool>` 上 `auto` 逐元素拷贝代理值的坑（5版未提，现代必提）。
- **5.5.3 goto**：书的态度"不用它"；内核代码/错误清理宏是它仍存在的工业理由。
- **5.6 异常入门**：throw 复制异常对象、catch 按引用（5版原话级别建议 `catch (const exception& e)`）；`what()` 返回 `const char*`。完整语义在 18.1。

## 🔧 实测（已实测 g++ 15.2, -std=gnu++17）

`s04.cpp`：C++17 的 if 带初始化器 + `[[fallthrough]]` 属性——两者都不在第5版里（第5版只能在 if 外裸声明变量、只能靠 `// FALLTHRU` 注释）：

```cpp
if (size_t n = v.size(); n > 3)          // n 只在 if 内可见
    for (auto x : v) total += x;
switch (2) {
    case 2: [[fallthrough]];             // 编译器/静态检查器都认
    case 3: cnt = 42; break;
}
```

```
total=150
cnt=42
```

## 最新演进与工业实践（基线 C++11 → 现在）

- **`[[fallthrough]]`（C++17，[P0188R1](https://wg21.link/p0188r1) "Wording for [[fallthrough]] attribute" 实测200）**；配套 **`[[nodiscard]]`（P0189R1）** 与 **`[[maybe_unused]]`（P0212R1）**——三属性把 4/5 两章的"风格约定"升级为"编译期检查"。
- **if/switch 带初始化器（C++17，[P0292R2](https://wg21.link/p0292r2) "constexpr if: A slightly different syntax" 实测200，同一提案族）**：5.2 作用域纪律的类型级兑现。
- **求值顺序（C++17）**：`E1[E2]`、函数调用里"后缀表达式先求值"、`<<` 链——C++17 给了一批新顺序保证；书 4.1.3 的"全未定"叙述需要打补丁 ⚠️（细节以 P0145 系措辞为准，此处编号未实测故不给）。
- **constexpr if（C++17，P0292R2 实测200）**：5.3 条件语句进入编译期分支时代，16 章模板分派的现代主力。
- **GSL/clang-tidy 对照**：`CppCoreGuidelines ES.1-ES.*`（Expressions and Statements 整章）逐条覆盖 4 章；`bugprone-branch-clone`（if/else 分支雷同）对位 5.3。
- **定性标注**：4.7 `?:` 的多层嵌套在 2020s review 中会被要求换 `switch`/策略表；`do{...}while` 仅剩"至少一次 IO 泵"一类正当场景。
