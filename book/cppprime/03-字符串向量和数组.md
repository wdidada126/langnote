## 核心概念速览（中英对照）

- **using 声明** — using declaration：把命名空间成员引入当前作用域；头文件里全局 using 是污染，本书明令禁止
- **`string` 与 `vector` 的读入语义** — `>>` 跳过空白读至下一个空白；`getline` 读整行含空格
- **string 操作全集** — size/empty/`+`/`+=`/比较：比较按字典序；`s.size()` 返回 `size_t`（无符号陷阱回访）
- **字符分类函数** — cctype：`isalpha/isdigit/ispunct/isspace/isupper/toupper`；`isXXX` 传 char 前必须转 `unsigned char`（负值 UB）
- **范围 for（3.2.3 预告）** — range for statement：`for (auto &c : s)`；C++11 新特性，5版把它放在第5章正式讲
- **`vector` 只能 push_back** — 不能随机增长：`v[i]` 访问的下标必须已存在；用 size 或迭代器扩
- **迭代器** — iterator：`begin()/end()` 半开区间 `[b, e)`；`cbegin()/cend()`（C++11）返回 const 迭代器
- **迭代器运算** — `*it / it-> / ++ -- == != < > 迭代器相减/加整数`：只有随机访问迭代器全支持
- **指针即迭代器** — array-to-pointer decay：`int a[10]; 数组名在表达式里退化为首元素指针`
- **`std::begin/std::end`（C++11 新特性，3.5.3）**：对内置数组同样适用的通用取区间函数——泛型代码的第一块模板
- **C 风格字符串** — C-style string：`char[]` + `'\0'`;  `cstring` 的 `strlen/strcmp/strcat` 无边界检查，本书态度"知道但别用"
- **多维数组** — multidimensional array：`int ia[3][4]` 行优先；range for 外层要 `auto (&row)[4]` 否则退化

## 小节细目（按原书小节号速记）

- **3.1 命名空间的 using 声明（页74）**：`using std::string;` 只引入一个名字；函数内 vs 头文件的后果对比（后者名字污染整个包含者）。
- **3.2.1 定义和初始化 string（页76）**：拷贝初始化 `string s = "..."` 与直接初始化 `string s("...")`；`string(n, ch)` 重复构造；⚠️ 注意 `string s = 10, 'c'` 是逗号声明符的坑（实际得 `s=10` 编译错——书的经典反例题）。
- **3.2.2 string 操作（页77）**：`+` 两侧至少一个是 string（两个 `const char*` 相加非法）；`size()` 无符号；比较按字典序；`==` 值比较。
- **3.2.3 处理字符（页81）**：`isalpha` 等分类 + `toupper` 转换；范围 for 逐字符改写必须 `auto &c`；把 string 当容器遍历的第一视角。
- **3.3.1 vector 定义初始化（页87）**：列表初始化的歧义（`vector<int> v{10}` 是一个元素 10 而非十个 0——与 `vector<int> v(10)` 对照是 3.3.1 的保留节目）；`vector<vector<int>>`（C++11 起 `>>` 不必空格）。
- **3.3.2 添加元素（页90）**：`push_back` 是唯一正规增长姿势；下标只读已存在位置；"不能对 vector<bool> 用引用习惯"书在 13.2 补刀。
- **3.3.3 其他操作（页91）**：`==` 逐元素、`!=`；没有 `<`（vector 之间）；下标运算与 size 的配合。
- **3.4.1-3.4.2 迭代器（页95-99）**：`(*it).member` 必须括号或换 `it->`；迭代器算术 `+= -` 与差值类型 `difference_type`；`cbegin/cend`（C++11）。
- **3.5.1-3.5.5 数组（页101-112）**：定长、`sizeof` 求长、列表初始化；越界无检查；`std::begin/std::end`（C++11）统一容器与数组；char 数组 vs string 的 C 风格字符串、`strlen/strcmp/strcat/strcpy` 的无边界警告；与旧接口 `c_str()`。
- **3.6 多维数组（页112）**：`int a[3][4]` 每行是含 4 个 int 的数组；range for 正确三写法（外层引用+内层值）；指针数组 `int* p[10]` 与指向数组的指针 `int (*p)[10]` 之辨。

## 自查与面试高频

1. `string s = "abc"; s[10] = 'x';` 行为？`s.at(10)` 行为？
2. `vector<int> v1(10); vector<int> v2{10};` size 各是多少？
3. `for (auto c : s) c = toupper(c);` 为什么改不动 s？
4. `char ca[] = "hi"; sizeof(ca)` 与 `strlen(ca)` 各是多少？差在哪？
5. 函数里 `int a[10]` 传给 `void f(int a[])`，`sizeof(a)` 还能用吗？为什么？
6. `s.substr(2)` 与 `string_view(sv).substr(2)` 谁的返回值还依赖原串存活？（string_view——悬垂视图是本项目头号事故源）
7. `vector<int> v; v.reserve(10); v[5] = 1;` 合法吗？（越界：reserve 只给 capacity 不产生元素，`operator[]` 不检查，应用 push_back/resize）
8. `string_view` 为什么"只读却不保证底层不被别人改"？给出一个悬垂视图事故样例。（视图不持有内存，原串析构/移动后视图即断线风筝）
9. `cin >> s` 后紧跟 `getline(cin, t)` 为什么 t 是空的？标准清法是什么？（残留换行被 getline 先吃掉；`cin.ignore(numeric_limits<streamsize>::max(), '
')`——注意这是转义写法）
10. `vector<string> vs(3);` 与 `vector<int> vi(3);` 元素初值分别是什么？（空串与 0——类默认构造 vs 值初始化差异的入口）
11. 迭代器失效口诀"vector 扩容全灭、list 只灭被删、deque 两端各异"——用 `for (auto it = v.begin(); *it != x; ++it) if (flag) v.push_back(x);` 指出两处违规。

## 3.2-3.3 为什么 Primer 把 string/vector 放在数组之前

**动机**：这是 5 版对 4 版最大的教学顺序改动——先教**安全容器**再教裸数组，与"用抽象、少碰内存"的现代方针一致。

**机制要点**：
- `string`/`vector` 的 `size()` 是成员函数不是运算符；`==` 重载做值比较（数组的 `==` 是指针比较——对比项在此立起）。
- `vector` 不允许"用下标扩张"：`v[v.size()] = x` 越界 UB；只能 `push_back`。书反复敲这一条，对应的是它 9.4 的增长策略。
- 迭代器是**区间** `[begin, end)`：这个半开约定贯穿 10 章算法、17 章 regex、甚至 span。

**权衡**：书的迭代器教学用 `for (auto it = v.begin(); it != v.end(); ++it)` 形态；C++11 的 `for (auto& x : v)` 在很多场景直接替掉它——但"会写迭代器"仍是读 9-10 章的前置能力。

**相邻概念对比**：`string` vs `string_view`（C++17 补位，见下节）；`vector<T>` vs `array<T,N>`（大小可变 vs 编译期定长）；迭代器 vs 下标——越界检查都默认没有，差别在可读性与可迁移性。

## 3.4-3.5 迭代器与数组：旧世界的接口

- **迭代器失效的初印象**（3.4 提醒 + 9.3.6 展开）：`erase/insert` 后的 it 不可再用——书在此只给直觉。
- **指针与数组（3.5.3）**：`*(a+i) == a[i]` 的定义级等价；C 风格字符串以 `'\0'` 终止，`strlen` 是 O(n) 且不计终止符。
- **与旧代码接口（3.5.5）**：`const char* c = s.c_str();`——`string` 对象给 C API 的唯一正门；现代补一句：C++11 起 `&s[0]/s.data()` 也保证连续（⚠️ 5版正文只教 c_str）。
- **多维数组（3.6）**：真正的高价值是 `using int_array = int[4];` 配合 range for，和"外层 auto 必须带引用"的陷阱。

## 🔧 实测（已实测 g++ 15.2, -std=gnu++23）

`s03.cpp`：5 版教 `substr` 拷贝切分 vs 现代 `string_view` 零拷贝 + C++20 `starts_with/ends_with`：

```cpp
std::string s = "C++ Primer, 5th ed.";
std::string_view sv = s;
sv.starts_with("C++");            // C++20，P0457R2
std::string_view head = sv.substr(0, sv.find(','));   // 不分配
for (auto& e : v) e *= 2;         // 范围for + 引用改元素
```

```
starts_with = true  ends_with = true
head = C++ Primer (零拷贝视图, 长度 10)
v = [10, 6, 16, 2]
```

## 最新演进与工业实践（基线 C++11 → 现在）

- **`std::string_view`（C++17，[P0254R2](https://wg21.link/p0254r2) "Integrating std::string_view and std::string" 实测200）**：本章"切字符串"的现代默认——只读参数一律 `string_view`，不再传 `const string&`；注意悬挂陷阱（视图不拥有，源失效即悬垂）。
- **`starts_with/ends_with`（C++20，[P0457R2](https://wg21.link/p0457r2) "String Prefix and Suffix Checking" 实测200）**：取代 `compare(0,n,s)==0` 与 `rfind` 黑话。
- **`std::span`（C++20，[P0122R7](https://wg21.link/p0122r7) "span: bounds-safe views" 实测200）**：3.5"指针+长度" pair 的官方打包；给 C API 传数组用 `span<T>`，GSL 的 `gsl::span` 是其前身。
- **`std::to_chars/from_chars`（C++17，[P0067R5](https://wg21.link/p0067r5) "Elementary string conversions" 实测200）**：数值↔字符串的零分配快路，`to_string`（9.5.5 数值转换）的性能替代。
- **clang-tidy**：`bugprone-string-constructor`、`performance-avoid-endl`、modernize 系列把本章陷阱工具化。
- **工业对照**：folly 的 `fbstring`（SSO 极致化的 string）与 `F14` 无关但代表"标准容器之上仍有一层工业选型"；abseil 则提供 `absl::string_view/absl::Cord` 谱系。

## 概念边界一览表

| 易混对 | 分界一句话 |
|---|---|
| `string` vs `const char*` | 前者是带大小的对象，后者是"指针+约定终止"的视图；互转只走 `c_str()`/拷贝构造 |
| `vector::size()` vs 数组 `sizeof/sizeof` | 成员函数 vs 编译期常量除法，后者一进函数就失效 |
| 迭代器 vs 指针 | 迭代器是指针概念的超集：能力分级（10.5），数组指针=随机访问迭代器 |
| `[]` vs `at()` | 都返回引用；at 越界抛异常，`[]` 越界 UB |
| `auto&` vs `auto`（范围 for） | 带引用才能改元素；不带是拷贝，改不到容器 |
| `vector<T>` vs `array<T,N>` | 动态增长 vs 定长零开销；可转 `span` 统一接口（C++20） |

## 勘误与存疑

- ⚠️ 3.5.1 "定义和初始化内置数组"中 `int a[] = {1,2,3}` 后 `sizeof(a)/sizeof(a[0])` 求长度的惯用法，在函数传参（退化）后立刻失效——书 3.5.3/6.2.4 两处各说一次，容易记混：只有**同一作用域内的真数组**能量。
- 本节无独立 wg21 无法核实的硬事实；`data()` 的非 const 连续保证细节以标准文本为准。
