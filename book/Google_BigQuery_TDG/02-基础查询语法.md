## 核心精讲

### 1. 反引号与限定名（✅ 配套仓库）

BigQuery 的对象寻址是 `project.dataset.table`，**含连字符/保留字符的项目名要整体反引号**：

```sql
-- 配套仓库原例：backtick only around project
SELECT gender, tripduration
FROM `bigquery-public-data`.new_york_citibike.citibike_trips
LIMIT 5;
```

⚠️ 转述：反引号内不能跨层级写 `a.b`（除非整串加引号）；这与 ANSI 双引号标识符规则不同，是迁移第一坑。

### 2. SELECT \* EXCEPT / REPLACE（✅ 目录实抓小节）

```sql
-- 自拟教学示意（非原书文本）：列改写的极简姿势
SELECT * EXCEPT (tripduration), tripduration / 60.0 AS duration_min
FROM `bigquery-public-data`.new_york_citibike.citibike_trips;
```

⚠️ 官方参考：query-syntax 页（✅ docs.cloud.google.com/bigquery/docs/reference/standard-sql/query-syntax）。
🔧 **DuckDB 1.5.5 同族能力实测（非 BigQuery 行为）**：DuckDB 用 `EXCLUDE/REPLACE` 关键字达成同样语义，本机直跑：

```sql
-- python: duckdb.sql("SELECT * EXCLUDE (gender) REPLACE (dur*60 AS dur) FROM t4")  t4=('M',10)
[(600,)]   -- ✅ 输出：gender 被剔除，dur 被就地改写，其余列原位保留
```

对照结论：**"列剔除/原位改写"已是现代分析方言的趋同能力**（Trino/Presto 侧对照见
[../Trino_The_Definitive_Guide_2e/09-高级SQL特性.md](../Trino_The_Definitive_Guide_2e/09-高级SQL特性.md)），
但关键字拼写（EXCEPT/EXCLUDE）与优先级细节各家不同，迁移必查文档。

### 3. 聚合与 DISTINCT 的两个陷阱（✅ 配套仓库注释原话）

- `-- NOTE: Does not work`：配套仓库专门演示了**在 WHERE 里写聚合**是非法的，须改 HAVING。
- `-- distinct is on entire query` / `-- why empty?`：`SELECT DISTINCT a, b` 是**整行组合**去重而非按列去重；
  以及 `COUNT(DISTINCT x)` 在超大基数的近似诉求（⚠️ 原书指向 `COUNTIF`/近似函数，03/08 章展开）。
- 与教材口径对照：分组语义的形式化定义见 [../数据库系统概念6/03-SQL.md](../数据库系统概念6/03-SQL.md)。

### 4. 数组与结构体：BigQuery 的"第一公民"（✅ 目录实抓）

BigQuery 把半结构化嵌套做进标量同级的类型系统（`ARRAY<...>`/`STRUCT<...>`），
`ARRAY_AGG` 聚合出数组、`UNNEST` 把数组炸回行——这是原书区别于 MySQL 入门章的最大语法增量。

🔧 **DuckDB 1.5.5 类比实测（非 BigQuery 行为）**，复刻 citibike 式"分组→数组→再展平"闭环：

```sql
-- T1 配套仓库同款聚合语义
WITH src AS (SELECT * FROM (VALUES ('M',10),('F',20),('M',30)) t(gender,dur))
SELECT gender, ARRAY_AGG(dur) AS durs FROM src GROUP BY gender ORDER BY gender;
-- ✅ [('F', [20]), ('M', [10, 30])]

-- T2 结构体数组 + UNNEST 展平
SELECT s['gender'] AS g, s['dur'] AS d
FROM (SELECT UNNEST([{'gender':'M','dur':10},{'gender':'F','dur':20}]) AS s);
-- ✅ [('M', 10), ('F', 20)]
```

⚠️ 转述 BigQuery 侧差异：结构体字面量用 `STRUCT(1 AS a, 'x' AS b)`、取值用点号 `s.a`；
数组构造有 `[1,2,3]`、`ARRAY(SELECT ... )`、`ARRAY_AGG` 多门；官方 arrays 页
✅ https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/arrays 。
DuckDB 的 `{'k':v}` MAP 式字面量与点号/方括号双取值只是**语义近邻**，别当方言等价物。

### 5. UNNEST 与 JOIN 的合体（✅ 目录"元组/使用数组"小节）

⚠️ 转述：`FROM t, UNNEST(t.arr)` 是逗号交叉连接 + 表函数的组合，带 `WITH OFFSET` 可取下标；
作用域规则（关联/非关联）是原书"Join 释疑"小节的主题。对照 SQL 标准：

## 常见误区（⚠️ 转述 + 🔧 实测校准）

| 误区 | 事实 |
| --- | --- |
| `SELECT DISTINCT col` 只按该列去重 | DISTINCT 作用于**整行**（✅ 配套仓库注释原话）；按列去重取最值要 GROUP BY |
| 反引号可以包住 `a.b.c` 全名 | 分层限定名逐段处理，行为不同（⚠️ 官方 query-syntax） |
| UNNEST 必须配合 UNNEST 数组列同名 | 可用别名与 WITH OFFSET 重塑（⚠️ arrays 页） |
| DuckDB 能跑 = BigQuery 一样跑 | 🔧 本目录所有 DuckDB 结果仅证明语义可行，语法细节以 BQ 文档为准 |

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| 标准 SQL | Standard SQL | BigQuery 现行方言（vs 已弃用 Legacy SQL，08 章有迁移表） |
| 限定名 | qualified name | `project.dataset.table` 三级寻址，必要时反引号 |
| 通配选择改写 | SELECT \* EXCEPT/REPLACE | 剔除列/原位改写的列选择语法 |
| 公用表表达式 | CTE (WITH clause) | 命名子查询，本书主线分析全靠它 |
| 分组聚合 | GROUP BY / HAVING | 聚合后过滤只能在 HAVING |
| 整行去重 | DISTINCT | 作用于查询输出的完整行组合 |
| 数组 | ARRAY\<T\> | 有序可重复嵌套值，列级第一公民 |
| 结构体 | STRUCT\<T\> | 命名字段记录型值，可嵌数组 |
| 数组聚合 | ARRAY_AGG | 组内值收集为数组（可配 ORDER BY/LIMIT） |
| 展平 | UNNEST | 把数组元素变成行，可 WITH OFFSET 取下标 |
| 交叉连接 | CROSS JOIN | 笛卡尔积；`FROM a,b` 即其简写 |
| 结果缓存 | results cache | 同查询+数据未变时约 24h 内免费复用结果（⚠️ 时长以现文档为准） |
| 视图 | view | 保存的查询，共享与权限载体 |
