## 核心精讲

### 1. QUALIFY：窗口函数的"HAVING"（⚠️ 转述 + 🔧 DuckDB 1.5.5 实测，非 BigQuery 行为）

BigQuery 的 `QUALIFY` 子句让窗口函数的过滤像 HAVING 之于聚合一样简洁：

```sql
-- 自拟教学示意（非原书文本）：取每组最新一行
SELECT name, val, ROW_NUMBER() OVER (PARTITION BY name ORDER BY ts DESC) AS rn
FROM t
QUALIFY rn = 1;
```

🔧 **DuckDB 1.5.5 实测**：

```sql
-- python: duckdb.sql("SELECT name, val, ROW_NUMBER() OVER (PARTITION BY name ORDER BY val DESC) AS rn FROM t5 QUALIFY rn = 1")
-- t5 = [('A',10),('A',20),('B',30)]
-- ✅ [('A', 20, 1), ('B', 30, 1)]
```

结论（🔧）：QUALIFY 在 DuckDB 1.5.5 中已原生支持——这是分析 SQL 方言趋同的又一证据。
⚠️ 但命名窗口语法（`WINDOW w AS (...)`）在 DuckDB 同支持，BigQuery 侧细节以官方 query-syntax 页为准。

### 2. 脚本化：BigQuery 有了"控制流"（✅ 配套仓库 + ⚠️ 转述）

2019 后 BigQuery 引入脚本能力（⚠️ 版本年份以官方 scripting 页为准）：

```sql
-- 自拟教学示意（非原书文本）
DECLARE threshold INT64 DEFAULT 1000;
DECLARE cnt INT64;
SET cnt = (SELECT COUNT(*) FROM dataset.big_table);
IF cnt > threshold THEN
  SELECT 'Large table, proceed with caution' AS warning;
END IF;
```

✅ 配套仓库 `08_advqueries/` 含脚本化用例；⚠️ 脚本消耗槽位时间、可能阻断结果缓存（07 章）。
对读标准 SQL 的过程化扩展：[../数据库系统概念6/05-高级SQL.md](../数据库系统概念6/05-高级SQL.md)。

### 3. MERGE：事务性 DML 的瑞士军刀（⚠️ 转述）

```sql
-- 自拟教学示意（非原书文本）：增量同步
MERGE dataset.target AS T
USING dataset.source AS S
ON T.id = S.id
WHEN MATCHED AND S.updated_at > T.updated_at THEN UPDATE SET T.val = S.val
WHEN NOT MATCHED THEN INSERT (id, val) VALUES (S.id, S.val);
```

⚠️ MERGE 是原子操作——要么全成功要么全失败（04 章"装载不管去重"的修正入口）。
配套仓库的 queries.txt 中亦有 MERGE 式修正示例（✅ 实抓注释标题）。

### 4. Time Travel：快照读（⚠️ 转述）

```sql
-- 自拟教学示意（非原书文本）
SELECT * FROM dataset.my_table
FOR SYSTEM_TIME AS OF '2026-01-01 00:00:00 UTC';
```

⚠️ 默认窗口 7 天（可扩至 14 天 ⚠️ 以官方文档为准）；底层是列存版本链而非快照副本。
对读 Snowflake Time Travel [../Snowflake_The_Definitive_Guide/07-数据保护与恢复.md](../Snowflake_The_Definitive_Guide/07-数据保护与恢复.md)。

### 5. 参数化查询（✅ param_*.py 实抓）

配套仓库 `08_advqueries/param_*.py`（✅ 实抓）演示 Python 客户端的参数绑定：

```python
# 配套仓库风格示意（非原书文本）
from google.cloud import bigquery
client = bigquery.Client()
query = "SELECT name FROM dataset.t WHERE id = @target_id"
job_config = bigquery.QueryJobConfig(
    query_parameters=[bigquery.ScalarQueryParameter("target_id", "INT64", 42)]
)
result = client.query(query, job_config=job_config).to_dataframe()
```

⚠️ 参数化**防注入**且**利于缓存命中**（相同参数不同值→查询文本一致→可能命中结果缓存 07 章）。

### 6. UDF 深入（⚠️ 转述 + ✅ 配套仓库）

03 章已述 JS 标量 UDF 基础；本章展开：
- **表值 UDF**：`CREATE FUNCTION` 返回 TABLE→可 FROM 调用，类似视图但带参数；
- **模板 UDF**：`<T>` 类型参数→多态复用（⚠️ 配套仓库有模板 UDF 示例）；
- **性能注意**：JS UDF 有 V8 启动成本，高频调用场景慎用（⚠️ 07 章槽位视角）。

### 7. 动态 SQL（⚠️ 转述）

`EXECUTE IMMEDIATE` 支持运行时拼接 SQL：

```sql
-- 自拟教学示意（非原书文本）
DECLARE table_name STRING DEFAULT 'dataset.my_table';
EXECUTE IMMEDIATE "SELECT COUNT(*) FROM `" || table_name || "`";
```

⚠️ 动态 SQL 绕过编译期类型检查、不命中结果缓存——生产环境慎用。

## 常见误区（⚠️ 转述 + 🔧 实测校准）

| 误区 | 事实 |
| --- | --- |
| QUALIFY 是 BigQuery 独有 | 🔧 DuckDB 1.5.5 已支持——分析 SQL 趋同证据 |
| 脚本免费 | 脚本消耗槽位时间，长循环/大 DECLARE 有成本（07 章） |
| MERGE 可以替代 DELETE+INSERT | MERGE 是原子操作≠性能等价；大表 MERGE 可能比分区覆盖更贵 |
| Time Travel 无成本 | 版本链占用存储；超过窗口即不可恢复 |
| 参数化只防注入 | 还利于结果缓存命中（查询文本一致性） |
| UDF 无成本 | JS UDF 有 V8 启动成本；行级高频调用需谨慎 |

## 核心概念速览（中英对照）

| 术语 | English | 释义 |
| --- | --- | --- |
| QUALIFY | QUALIFY clause | 窗口函数过滤子句，分析 SQL 的 HAVING（🔧 DuckDB 同支持） |
| 命名窗口 | named window | WINDOW w AS (...) 复用窗口定义 |
| 脚本 | scripting | DECLARE/SET/IF/WHILE/BEGIN EXCEPTION 控制流 |
| 存储过程 | stored procedure | CREATE PROCEDURE 封装可复用逻辑 |
| MERGE | MERGE statement | INSERT+UPDATE+DELETE 原子合并（⚠️ 成本非等价） |
| Time Travel | time travel | FOR SYSTEM_TIME AS OF 快照读（默认 7 天 ⚠️） |
| 参数化查询 | parameterized query | @param 绑定，防注入+利缓存 |
| JS UDF | JavaScript UDF | V8 引擎执行的用户自定义函数 |
| 表值 UDF | table-valued UDF | 返回 TABLE 的参数化函数 |
| 模板 UDF | templated UDF | 多态类型参数 `<T>` 的 UDF |
| 动态 SQL | dynamic SQL | EXECUTE IMMEDIATE 运行时拼接（⚠️ 慎用） |
| 帧规范 | frame specification | ROWS/RANGE BETWEEN... 窗口帧定义 |
