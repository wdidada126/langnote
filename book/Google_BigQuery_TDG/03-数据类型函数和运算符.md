## 核心精讲

### 1. 一套"为分析而生"的类型系统（⚠️ 转述 + ✅ URL）

- 只有 `INT64/FLOAT64` 没有 INT32 家族——窄类型是运维负担，列存压缩交给引擎（对照 [../bigdata/09-存储与文件格式.md](../bigdata/09-存储与文件格式.md) 的 Parquet 编码观）。
- `NUMERIC` 定点（⚠️ 官方口径：固定精度 38、标度 9；BIGNUMERIC 精度 76/标度 38）处理金额；FLOAT64 严禁入钱庄。
- `TIMESTAMP` 存 UTC 微秒；`DATETIME` 无时区；跨时区报表必配 `PARSE_TIMESTAMP/FORMAT_*`（⚠️；函数寻址一律走官方 SQL 参考区，✅ 实抓可达页：docs.cloud.google.com/bigquery/docs/reference/standard-sql/query-syntax 与 .../arrays）。
- `GEOGRAPHY`（WKT/WKB + S2）+ 空间函数族是原书时代（2019）云仓独卖点，本章配套注释以"Geography"收尾 ✅。

配套仓库原例（✅ 实抓，注释即小节标题）：

```sql
-- numeric
SELECT CAST('123.45' AS NUMERIC) AS n, NUMERIC '678.90' AS typed_literal;
-- conditional expression / coalesce
SELECT IF(x > 0, 'pos', 'neg') AS sign, COALESCE(null_str, fallback) AS v FROM t;
-- CAST bool as int64
SELECT CAST(TRUE AS INT64) AS one, CAST('9' AS INT64) AS nine;
```

### 2. SAFE_\* 与"错误哲学"（🔧 类比实测，DuckDB 1.5.5，非 BigQuery 行为）

⚠️ BigQuery 约定：非法转换/越界默认**报错使作业失败**；`SAFE_CAST`、`SAFE.SUBSTR` 返回 NULL 代替报错。
DuckDB 的对应物是 `TRY_CAST` 族，本机实测：

```sql
SELECT IF(1<2,'yes','no') AS if_test, TRY_CAST('abc' AS INT) AS safe_int, CAST('9' AS INT) AS plain_int;
-- ✅ [('yes', None, 9)]  —— IF 谓词同形；TRY_CAST 失败→NULL；CAST 成功→9
```

结论（🔧）："条件表达式 + 失败转 NULL"在两个方言里都存在且形态几乎一致——但**哪些函数提供 SAFE_/try_ 变体清单不同**，迁移必须逐函数对照（BQ 类型与函数口径见 ✅ data-types/query-syntax 参考页）。

### 3. NUMERIC 标度行为（🔧 类比实测，DuckDB 1.5.5，非 BigQuery 行为）

```sql
SELECT CAST(1.234 AS DECIMAL(3,2));          -- ✅ Decimal('1.23')  —— 就地四舍五入到目标标度
SELECT CAST(123.4 AS DECIMAL(3,2));          -- ✅ Conversion Error: value is out of range!
```

- 🔧 本机证据：DECIMAL 转换**先舍入、溢出即抛错**（不是静默截断）。
- ⚠️ BigQuery 口径转述：NUMERIC 的 scale 固定 9（写入超标度会舍入/报错，语义细节以官方 data-types 文档为准）；
  两引擎同属"定点必守标度"阵营，与 FLOAT64 的"无限精度但不可信末位"形成教学对照。

### 5. UDF/模板函数（⚠️ 转述，08 章展开）

JS 标量 UDF（`CREATE FUNCTION ... RETURNS ... LANGUAGE js`）、带 ARRAY 参数的模板 UDF、
表值 UDF——配套仓库 `08_advqueries` 有脚本化用例 ✅；⚠️ UDF 消耗计算、可能阻断结果缓存，是性能章节常客。

### 6. 运算符优先级与 IN UNNEST（⚠️ 转述 + 🔧 类比）

BigQuery 的数组运算符 `IN UNNEST(arr)` 是 SQL 标准 `IN` 的数组扩展：

```sql
-- 自拟教学示意（非原书文本）
SELECT name FROM users
WHERE role IN UNNEST(['admin', 'editor', 'viewer']);
```

🔧 **DuckDB 1.5.5 类比（非 BigQuery 行为）**：DuckDB 用 `array_contains` 或 `IN (SELECT * FROM UNNEST(...))` 达成类似语义。
⚠️ 运算符优先级：`IN UNNEST` 的优先级低于比较运算符——复合条件务必加括号，避免 `a > 0 AND b IN UNNEST(arr)` 被误解析。
配套仓库注释标题虽未单独列"运算符"小节，但 `03_func/datatypes_functions.txt` 的查询示例中多处使用数组运算符（✅ 实抓）。

## 常见误区（⚠️ 转述 + 🔧 实测校准）

| 误区 | 事实 |
| --- | --- |
| STRING 与 BYTES 一样 | BQ 中 UTF-8 归 STRING，原始字节归 BYTES；`LENGTH` 语义按字符/字节分列（LENGTH vs BYTE_LENGTH） |
| `CAST('abc' AS INT64)` 返回 NULL | 🔧 默认**报错**（DuckDB 同为报错）；要 NULL 必须 SAFE_CAST/IF(安全变体) |
| FLOAT64 存金额够用 | 十进制循环小数即误差源；金额一律 NUMERIC（🔧 DECIMAL 实验佐证"精度是契约"） |
| TIMESTAMP 带时区 | TIMESTAMP 恒为绝对时刻；"当地时间"是查询时 FORMAT 的事 |
| 隐式转换处处有 | BQ 隐式转换矩阵比 MySQL 严格得多，建议全显式 CAST（⚠️ data-types 页） |

| 术语 | English | 释义 |

| 定点数 | NUMERIC / BIGNUMERIC | 十进制精确数值，钱与合规账专用（⚠️ 38/9 与 76/38 口径） |

| 地理类型 | GEOGRAPHY | WKT/WKB 球面几何 + S2 索引空间函数族 |
| 安全转换 | SAFE_CAST / SAFE.\* | 失败返 NULL 而非让作业报错的函数变体（🔧 DuckDB≈TRY_CAST） |
| 空值合并 | COALESCE | 首个非 NULL 值，✅ 配套注释小节 |
| 条件三元 | IF(cond, a, b) | 与 CASE 互补的行内条件（🔧 DuckDB 亦支持 IF） |
| 近似去重 | APPROX_COUNT_DISTINCT | 误差换扫描量，计费世界的省钱阀 |
| 分位数草图 | APPROX_QUANTILES | 大表分布分析的近似族函数 |
| 表采样 | TABLESAMPLE SYSTEM | 按比例取样试探成本/分布 |
| 用户定义函数 | UDF (JS) | 行级自定义逻辑；模板/表值 UDF 扩展参数形态 |
