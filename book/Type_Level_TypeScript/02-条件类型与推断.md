# 《Type-Level TypeScript》分章笔记 02 · 条件类型与推断

> 第Ⅱ段「条件与推断：条件类型、分发律、`infer`」（⚠️ 段名凭 [00-总览与阅读地图.md](00-总览与阅读地图.md) 骨架表机制清单记忆，非原书目录逐字）。本段是体操的**分支与反推**两员主将；03 映射、04 字面量、05 递归都要回落到这里的判定机器上。

## 核心机制

### 1. 条件类型：类型层的 if，假分支默认 never
`T extends U ? X : Y` 在类型位置求值。约定俗成的第一号用法是把「假」编码成 `never`：`Exclude<T, U> = T extends U ? never : T`——不是返回布尔，而是**用分支直接裁剪集合**。这比 C++ 的 `std::conditional_t`（二选一取值）多一层味：TS 的条件可以在「保留/湮灭」之间做集合差。典型热身：`type T1 = Exclude<"a" | "b", "a">` ⇒ `"b"`。

### 2. 分发律：裸类型参数对联合自动 map
条件类型的**隐藏事实**：当检查类型是*裸*类型参数（naked type parameter）且实参为联合时，条件被**逐个分发**再取并：`"a" | "b" extends "a" ? X : Y` 不是整体判（那会走假分支），而是 `("a" extends "a" ? X : Y) | ("b" extends "a" ? X : Y)` = `X | Y`。`Exclude` 能工作全靠分发。反分发技巧是给两边套元组：**`[T] extends [U]` 关掉分发**做整体比较——`type NotDistributed<T, U> = [T] extends [U] ? true : false`。忘套 `[T]` 是本号体操 bug 的头号产地（union 里混进 `never`/可选修饰时最阴）。

### 3. `infer`：模式位置的具名反推
`infer P` 把「从实参类型反推」的推导机器暴露成可命名槽位，只能出现在 `extends` 右操作数的**模式位置**：
- 函数返回位：`type Ret<T> = T extends (...args: any[]) => infer R ? R : never`
- 元组尾位：`type Last<T> = T extends [...unknown[], infer L] ? L : never`
- 参数字面量位（04 档主场）：`` S extends `${infer A}:${infer B}` ``
协变位置多候选推**联合**、函数参数位（逆变）多候选推**交叉**——细节规则以官方口径为准 ⚠️，书中习题基本只吃协变面。

### 4. `Equal`：双向可赋不是相等，同一性才是
`[A] extends [B]` 且 `[B] extends [A]` 对多数对象类型够用，但会被 `any`（双向可赋一切）与结构化等价骗过。社区/练习站惯用加强版即 01 档函数同一性 `Equal`。本号关键裁定：**判「类型相等」永远用 `Equal`，判「可赋值」才用裸 extends**——两条线混用会让 `Expect` 台假阳性。

### 5. 递归推断预告：`Awaited` 最小核
条件+分发+infer 三件合奏的样板（细节见 05 档）：
```ts
type Awaited<T> = T extends Promise<infer U> ? Awaited<U> : T;
```
每层剥一个 `Promise`，无 Promise 时落地——**递归基藏在假分支**，这是所有链式解包题的骨架。

## C++ 对偶裁定

| TS 机制 | C++20 对应物 | 裁定 |
|---|---|---|
| `T extends U ? X : Y` | `std::conditional_t` + 偏特化模式匹配（02/05 章） | 对偶成立；C++ 的「分支」=特化选择，TS 的「分支」=语言内建表达式 |
| 分发律（union 自动 map） | 参数包一元变换 `(Ts...)` 展开 / fold（03 章） | 形似神异：C++ 分发是**语法显式**（包），TS 是**语义隐式**（裸参数规则），漏看即翻车 |
| `[T] extends [U]` 反分发 | 无对偶（C++ 无「把整体包一层骗过展开」的同位手法） | 差集档 |
| `infer` 位置反推 | 模板实参推导 + CTAD 推导指南（04 章） | 强对偶：`infer` 就是把推导槽写进模式里 |
| 假分支塌成 `never` | SFINAE：替换失败从候选集**静默移除**（05 章探测器族） | 哲学同源（失败即不存在），载体不同（类型 vs 重载集） |
| `T extends U` 约束 | `requires`/概念约束（06 章） | 对偶成立，但 TS 约束可出现在任意类型位 |

互链裁定：本段与 [../C++20模板元编程/05-类型特征和条件编译.md](../C++20模板元编程/05-类型特征和条件编译.md)（traits+enable_if 时代）对读收益最高——`Exclude` 之于分发 ≈ `mpl::remove_if` 之于类型列表；`infer` 之于模式 ≈ `decltype`+`declval` 之于探测表达式。

## 批判读法

- **分发律是双刃剑**：它让 `Exclude/Extract` 一行写成，也让「我以为在判整体」的意图静默变形；生产代码里凡是入参可能为联合的条件类型，第一反应该是「这里要不要 `[T]`」。可读性代价不在长度而在**隐式语义**。
- 条件链超过 3 层（`A ? B ? C ? ...`）时 TS 的 hover 会把整个未求值表达式甩回给你，栈式阅读体验断崖——书的杂技题合法，工程 PR 不合法。
- 实例化爆炸前夜：分发意味着 **N 个 union 成员 × 递归深度** 的实例化乘法；`Awaited` 对深嵌套 Promise 的爆点与 05 档深度上限是同一条账。

## 🔧 微实验：分发/反分发断言台

```ts
type _t1 = Expect<Equal<Exclude<"a" | "b", "a">, "b">>;            // 分发在干活
type _t2 = Expect<Equal<[1 | 2] extends [1] ? true : false, false>>; // 反分发：整体不再是子集
type _t3 = Expect<Equal<Last<[1, 2, 3]>, 3>>;                       // infer 元组尾位
```
