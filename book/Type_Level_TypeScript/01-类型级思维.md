# 《Type-Level TypeScript》分章笔记 01 · 类型级思维

> 第Ⅰ段「类型级思维：类型=集合、函数=类型变换」（⚠️ 段名凭 [00-总览与阅读地图.md](00-总览与阅读地图.md) 骨架表前二行的机制清单记忆，非原书目录逐字）。本系列是全仓最重技术线：02–05 分章的每个机制都回指本章心法。

## 核心机制

### 1. 类型是集合，值是它的元素
每个类型圈住一组值：字面量类型 `3`、`"ab"` 是**单元素集**，联合是并集（`A | B`），交叉是交集，`never` 是空集、`unknown` 是全集。可赋值性判定被压成一条集合语言：**`T extends U` ⇔ 「T 的每个元素都在 U 里」⇔ T ⊆ U**——这就是 TS 结构子类型的代数面目。典型热身体操：`type T1 = 1 extends number ? 1 : 0`（单元素 ⊆ 无限集 ⇒ `1`），`type T2 = never extends string ? 1 : 0`（空集是任何集的子集 ⇒ `1`，空真）。

### 2. 泛型是类型级函数，具化是应用
`Partial<T>` 不「包含」T，而是**吃 T 吐新类型**的函数：`Partial<{a: string}>` 即函数应用。带类型形参的别名/接口一律按「纯函数」看待——同实参恒同结果、无副作用、**不生成任何运行期代码**。`type Foo<T> = T extends string ? "s" : "n"` 是函数，`Foo<number>` 是调用。这个视角是全书的总开关：后面条件类型（分支）、映射类型（遍历）、递归类型（循环）全是这台「类型函数虚拟机」的指令。

### 3. 「提升」到类型层的三块领地
把值语言搬进类型层的三条搬运带，各占后续一章：**条件类型**（if/else，见 02 档）、**映射类型**（for-in 遍历键，见 03 档）、**模板字面量类型**（字符串拼接与模式匹配，见 04 档）。元组（见 05 档）则提供「列表」这个数据结构。缺任何一块，类型层都只是注解语言；四块齐了，它是**非偏序完备的图灵气混合物理机**——「图灵完备」措辞为社区口径 ⚠️，精确定理不在此展开。

### 4. 擦除公理在体操里的重量
TS 类型运行时零留存（✅ 已由 [../TypeScript系列·Runtime_vs_Type_System专题.md](../TypeScript系列·Runtime_vs_Type_System专题.md) 实验 A 实测）：类型层算得再花哨，产物仍是等价 JS。推论两条：① 体操题的「测试即类型」——正确性用 `Expect<Equal<A, B>>` 断言在编译期表达，单元测试测不到类型；② 类型层错误**不产生任何运行时报警**，写错体操的代价是下游 `any` 化与假阳性，而不是崩溃。

### 5. C++ 背景读者的首号迁移陷阱：`any` 不是 `auto`
`any` 是**关掉检查的逃生舱**（双向可赋、成员随便点，soundness 破口），不是 C++ 的「由实参推导」。心智对照应钉在：`any` ≈ 中世纪 `void*` 纪律面，`unknown` ≈ 类型安全顶集（只能用、不能再加工），`infer` ≈ 模板实参推导（04 章 [../C++20模板元编程/04-高级模板的概念.md](../C++20模板元编程/04-高级模板的概念.md)）。把 `auto` 直觉带进 `any` 是类型体操作业的第一大 bug 源。

## C++ 对偶裁定

| TS 机制 | C++20 对应物 | 裁定 |
|---|---|---|
| 泛型=类型函数、具化=应用 | 模板具化（01/02 章「模板是编译期纯函数」心智） | **对偶成立**，总纲同构 |
| 类型=集合、`T extends U` 子集判定 | concepts 约束满足（隐式谓词，06 章） | 同哲学异机制：C++ 谓词在类型外，TS 集合即类型本身 |
| `never` / `unknown` 底顶元 | 无对偶（C++ 无类型格顶底；最近似：不可具化的 ill-formed） | 差集档 |
| `any` | `void*` 的纪律面（非语言地位） | 无对偶 |
| 结构化可赋值 | 名义子类型+隐式转换 | 异：判定算法根本不同 |

总裁定：第Ⅰ段是**双峰重合区**——C++ 模板背景读者迁移成本最低的一段；差异从 Ⅳ 段（字面量）才开始拉开（对读 [../C++20模板元编程/01-模板的简介.md](../C++20模板元编程/01-模板的简介.md) 的「模板是编译期纯函数」四推论，逐条可映射）。

## 批判读法

- **可读性代价从第一天就存在**：类型表达式即代码，但 hover 出来的类型常被格式化器折叠、别名丢失；体操解的「一行天才写法」在生产 PR 里通常要被 reviewer 打回。
- 集合隐喻有**断裂面**：`T extends U` 不是纯子集（函数参数逆变、`any` 双向、结构化比较的规则尾巴），书里把它讲成集合时留意「比喻当定义用」的滑坡。
- 「图灵气」的另一面是**无编译期停机保证**：递归类型靠深度上限硬刹车（05 档专讲），C++ 同样有具化深度事故——两边的成本模型一致，别指望 TS 更温和。

## 🔧 微实验：`Expect<Equal<..>>` 惯用法（本系列通用测试台）

```ts
type Equal<X, Y> = (<T>() => T extends X ? 1 : 2) extends
  (<T>() => T extends Y ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type _ = Expect<Equal<1 extends number ? 1 : 0, 1>>;   // 本章机制 1 的自测题断言化
```

`Equal` 用**函数类型同一性**（内部同一检查）做「双相反向可赋值」的加强版，是练习站/本书通用作答约定 ⚠️（书中具体版本以原文为准）。**🔧 未实测**：断言的通过/失败全在 `tsc` 报错面，本机无独立 tsc（PATH 探测无果），且铁律禁止以编译报错为「实测」——此台仅作阅读时手写对答案的骨架，待 tsc 销账。
