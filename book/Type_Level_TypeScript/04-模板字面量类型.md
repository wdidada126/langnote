## 核心机制

### 1. 字面量类型谱系与模板字面量语法
字符串字面量类型是单元素集（01 档），模板字面量类型把 JS 的 `` `a${b}c` `` 语法**提升到类型位置**：`` type Px = `${number}px` `` 圈住 `"0px" | "1px" | …`（无限集，`"8px"` 可赋、`"px8"` 不可）。槽位填联合即**笛卡尔展开**：`` type Pair = `${"a" | "b"}-${"x" | "y"}` `` ⇒ `"a-x" | "a-y" | "b-x" | "b-y"`——集合代数在第Ⅳ段的直译。4.1 起四个内建字符串函数 `Capitalize/Uncapitalize/Lowercase/Uppercase`（版本归属 ⚠️ 社区口径）是类型层的标准库，`as` 改名（03 档）全靠它们。

### 2. `infer` 在字面量槽：类型层的模式匹配
模板字面量 × `infer` = **字符串反解析**，本段的真正武器：
```ts
type FileExt<S extends string> = S extends `${string}.${infer Ext}` ? Ext : never;
```
匹配规则按**从左到右、惰性定界**理解（首个 `.` 切开 `A/B`）⚠️ 多槽歧义时的官方裁定细则未逐字对 spec。`ExtractParams` 真题骨架：`S extends \`${string}:${infer P}/${infer Rest}\` ? P | ExtractParams<Rest> : …` ——路由串 `"/users/:id/posts/:pid"` 在类型层被解析成 `"id" | "pid"`。

### 3. 典型体操一：`Split`（递归切串）
```ts
type Split<S extends string, D extends string> =
  S extends `${infer H}${D}${infer R}` ? [H, ...Split<R, D>] : [S];
```
一行里四件兵器齐发：模板模式（切点）、`infer` 双槽（头/尾）、递归（05 档主场）、元组累集。`Split<"a.b.c", ".">` ⇒ `["a", "b", "c"]`——「类型层字符串处理=切分+拼接的对偶」，本段所有解析题都从这两条原语长出来。

### 4. 典型体操二：类型级校验器（路由/单位/CSS）
`` type CSS<T extends `${number}${"px" | "rem" | "%"}> = T `` 这类**约束即校验**的写法是模板字面量最工程化的用法：把「合法字符串的形状」写进类型，非法值在 `tsc` 面被拒。松紧全看槽位材料：`` `${number}px` `` 拒 `"eight px"`，但 `` `${string}px` `` 只锚定后缀——`"not a px"` 照样溜进来；数字槽用 `number` 还是字面量联合 `"0" | "8"`、前缀槽留白还是收紧，这个**槽位松紧矩阵**是出题人最爱考的边角。

### 5. 运行面边界：它是唯一「有运行面对手」的类型机制
JS 本来就有模板字符串**表达式**，模板字面量类型只是它的类型层镜像——这给了别段没有的实证位：同一程序里值层 `` `${k}` `` 照跑、类型层 `` `get${K}` `` 全数剥除（✅ 见下节微实验）。

## C++ 对偶裁定

| TS 机制 | C++20 对应物 | 裁定 |
|---|---|---|
| `` `${A}${B}` `` 类型级拼接 | 无语言对偶；class-type NTTP（02 章）+ 自制 `fixed_string` 可**表示**串但不可算 | **无对偶 ★ 时代差主证** |
| `` `${infer A}.${infer B}` `` 模式反推 | 无——`constexpr` 手写逐位比较、`std::string_view::find` 只能在 constexpr 求值里做值层切 | 无对偶；fmtlib 编译期格式串解析是**库级**孤例 |
| 字面量联合笛卡尔展开 | 无对偶（参数包不做字符级笛卡尔） | 无对偶 |
| 内建 `Capitalize` 等 | 需自制 constexpr 函数表 | 弱对偶：载体从「语言内建」降到「库」 |
| 字符串字面量类型（4.1 前） | NTTP `char N[]` 时代遗留（07 章 `lit` 惯用法） | 历史对照，接 [../C++20模板元编程/02-模板的基础.md](../C++20模板元编程/02-模板的基础.md) |

总裁定：00 档「C++ 无对偶（constexpr 字符串时代差）」在本段**全表兑现**——第Ⅰ~Ⅲ段还能双峰对读，第Ⅳ段起 TS 单边行驶。互链结论可直接引向目标专题档「TypeScript 类型体操 ↔ C++ TMP 对照表」的差集页。

## 批判读法

- **无正则**是天花板：模板字面量的匹配能力≈字面分隔切分，复杂文法要靠 05 档递归手搓状态机——能写，但每加一个 token 类型都是实例化乘法（union 笛卡尔面尤其：三个 4 成员槽 = 64 个字面量，四个 5 成员 = 625，**指数是设计使然**）。
- 可读性代价：`` S extends `${infer A}${B}${infer C}` ? … `` 一行五个人造名字，无类型层调试器可单步；比嵌套条件更难 review，因为它**伪装成正则**。
- 工程止损：校验类用法（路由参数、CSS 单位、事件名）形状浅、收益真，可上生产；解析类用法（Split/JSON-ish）留在练习站与代码生成器前置检查，业务仓里出现即评审预警 ⚠️（仓内约定，非书载）。

## 🔧/✅ 微实验：strip-types 双跑（全系列唯一运行面实测）

脚本 `/tmp/tsexp/tlt04.ts` 与 `/tmp/tsexp/tlt04b.ts`（会话临时目录），**✅ node v22.14.0 `--experimental-strip-types` 真跑**：

```ts
type Px<T extends number> = `${T}px`;
type Route = "/users/:id/posts/:pid";
const route: Route = "/users/:id/posts/:pid";
const px: Px<8> = "8px";
console.log("rendered:", render(route, { id: "42", pid: "7" }));
console.log("px =", px, "| typeof:", typeof px, "| keys of holder:", Object.keys({ px }));
```

- 跑通 ✅ exit=0，原样输出：`rendered: /users/42/posts/7`；`px = 8px | typeof: string | keys of holder: [ 'px' ]` ——类型层的 `Px<8>`/`Route` 对值世界**零干预**：`typeof px` 是裸 `string`，模板字面量类型纯住编译期。
- 反号 ✅ `tlt04.ts` 曾把 `Route` 当**值**传给函数（`render(Route, …)`），strip-types 下直接 `ReferenceError: Route is not defined`（exit=1）——类型别名擦除后不存在；且 strip-types 删注解**不查类型**，此类误用在运行面才炸、在 tsc 面是另一种报错（接专题档实验 B 机理）。
- 类型面断言（`Expect<Equal<Split<"a.b", ".">, ["a", "b"]>>`）仍 🔧 未实测：本机无独立 tsc。
