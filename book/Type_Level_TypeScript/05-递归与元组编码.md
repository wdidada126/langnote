# 《Type-Level TypeScript》分章笔记 05 · 递归与元组编码

> 第Ⅴ段「类型级编程：递归、列表/元组编码、类型解析器」（⚠️ 段名凭 [00-总览与阅读地图.md](00-总览与阅读地图.md) 骨架表机制清单记忆，非原书目录逐字）。收官段=前三段兵器（条件/映射/字面量）的**组合运用场**；00 档点名的「TS 递归深度限制 vs C++ 模板深度限制双表」在本档落地。

## 核心机制

### 1. 递归条件类型：类型层的循环=分支+自调用
TS 没有类型层 for/while，**递归就是循环**：递归基藏在条件假分支，归纳步靠自调用剥掉一层结构。
```ts
type Flatten<T> = T extends Array<infer U> ? Flatten<U> : T;
type FlattenAll<T> = T extends [infer H, ...infer R] ? [H, ...FlattenAll<R>] : [];
```
第一支是「剥到非数组为止」的解包（`Awaited` 同族，接 02 档），第二支是「拆元组头、递归尾」的 cons 遍历。**递归基必须让问题规模必然收敛**：`Flatten<any[]>`、可选元素、交叉里的数组——都是收不敛的题面地雷。

### 2. 元组=类型层的列表；自然数=元组长度
```ts
type Length<T> = T extends unknown[] ? T["length"] : never;   // number 字面量
type Add<A extends unknown[], B extends unknown[]> = [...A, ...B]["length"];
type Five = Add<[,,,], [,,]>;                                 // 5
```
TS 4.0 起可变元组（`...infer R`）让「列表操作」有**原生载体**；算术全部借「长度」外包给字面量 number。老派 C++ 读者的另一编码是 cons 嵌套对 `[H, [H2, []]]`（TMP 时代 type list 的 TS 复刻，练习站题偶见 ⚠️ 未对书中原题）——两条编码路线的互转（`ToCons`/`ToList`）本身是本号经典体操。

### 3. 累集方向学：prepend 便宜、append 递归贵
`[A, ...T]` 头插直写；`[...T, A]` 尾插在**递归体内**时每层都要先把已有元组整份展开再拼——深度 n 时展开代价按平方级堆 ⚠️（社区成本口径，无官方复杂度承诺）。标准解式：**递归里反向 prepend 收集，出口处一次 `Reverse`**——`Split`（04 档版式是顺拆）若产物需保序追加，答案普遍写成 Acc 反积再翻元组。
```ts
type Reverse<T extends unknown[], Acc extends unknown[] = []> =
  T extends [infer H, ...infer R] ? Reverse<R, [H, ...Acc]> : Acc;
```

### 4. 尾递归形态与「尾递归消除」（4.1，⚠️ 版本归属社区口径）
`Reverse` 的 Acc 形不只是风格：TS 对**尾位置的递归条件类型**做消除，把「深度栈」折成循环，同样题面从爆栈变过关。判别口径：递归调用是否是条件的**直接结果**（尾位）——`Foo<...> extends X ? Y : Foo<...>` 可消；`[Foo<A>, Foo<B>]` 这种「结果里再套结果」不可消。写深递归体操题，**先设计成 Acc 尾形再调错**是练习站流传的正经工程法。

### 5. 深度上限与保险丝：`excessively deep` 两面孔
超限的报错面是 `Type instantiation is excessively deep and possibly infinite` ——注意它**两副面孔不分**：真无限（漏递归基）与 merely-too-deep（合法但超预算）同报一错 ⚠️ 报错面未经本机 tsc 实测，仅社区记载。主动保险丝（「燃料表」惯用法）：
```ts
type Foo<T, Fuel extends unknown[] = NewArray<64>> =
  Fuel extends [] ? never : T extends [infer H, ...infer R] ? [H, ...Foo<R, [...Fuel extends [unknown, ...infer F] ? F : []]>] : [];
```
（`NewArray` 本身又要一层递归/条件生成——「先有燃料还是先有递归」是本号元编程彩蛋。）与 C++ 侧对照的**双深度表**：

| 维度 | TypeScript | C++20 (GCC/Clang) |
|---|---|---|
| 限制者 | 检查器内置常数，**版本相关**（数十~数百量级 ⚠️ 具体数字各版本未实测，不敢写死） | `-ftemplate-depth`（GCC 默认 900 ⚠️ 待对官方文档复验；本仓 [../C++20模板元编程/00-总览与阅读地图.md](../C++20模板元编程/00-总览与阅读地图.md) 有诊断记录） |
| 可调性 | 不可调（用户侧只能 Acc 形/燃料表自救） | 命令行可调 |
| 撞限症状 | 上述双语报错 + 类型退化为报错点 | 实例化深度诊断（带实例化回溯链） |

## C++ 对偶裁定

| TS 机制 | C++20 对应物 | 裁定 |
|---|---|---|
| 递归条件类型 | 模板递归+特化递归基（`Fact<0>` 样板，[../C++20模板元编程/04-高级模板的概念.md](../C++20模板元编程/04-高级模板的概念.md) 4.2） | **强对偶**：两边同病（无出口=深度爆） |
| 元组/可变元组 | 参数包 `Ts...`、`std::tuple`（[../C++20模板元编程/03-变参模板.md](../C++20模板元编程/03-变参模板.md)） | 强对偶：`...infer R` ↔ 包展开 |
| cons 嵌套编码 | MPL 时代 type list（`hdl_list<T, Tail>` 链） | 同源古董（[../C++20模板元编程/07-模式和惯用法.md](../C++20模板元编程/07-模式和惯用法.md) 惯用法谱系） |
| 尾递归消除 | 无对偶：C++ 实例化深度是硬计数，无语言承诺的消除 | TS 单边优势 |
| 类型解析器（token→AST） | fmtlib `FMT_COMPILE` 编译期格式串解析、constexpr 求值（C++14/20 后走函数不走模板） | 时代差：C++ 用 **constexpr 函数**平替大半递归模板，TS 无类型层函数体只能递归条件硬搓 |

互链裁定：本档与 [../C++20模板元编程/04-高级模板的概念.md](../C++20模板元编程/04-高级模板的概念.md) 的模板递归小节是 00 档预告的主互链对；「constexpr 循环收编类型层循环」的 C++ 退路在 TS **不存在**（类型层没有 `for`），这是双峰对照的终点差异。

## 批判读法

- **30 行以上的递归类型=不可维护代码**：无断点、无栈回溯、报错只给两面孔一孔；体操题（深解析、JSON-ish parser）在练习站合法，进业务仓即评审红线 ⚠️（仓内约定口径）。
- 实例化爆炸的乘法在第五段到顶：深度 × 宽度 × union 分发（02 档）× 笛卡尔字面量（04 档）四个乘数同场开火；`Expect` 断言通过≠编译时间可接受，**大 fixture 上的类型检查耗时会进 CI 账**。
- 反方立场：类型级 JSON parser 的正当替代是 schema-first 库（值层 parser+泛型推导）——擦除公理下「类型层的确定性」换不来运行时保证（专题档戒律 3），本段杂技与工程的分界线要自己画。
