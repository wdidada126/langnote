## 核心精讲

### 1. 八个算子与"原始"二字

⚠️ 按作者一贯口径重构本节：Codd 1970 给出了 8 个算子（限制、投影、联接、乘积、并、差、改名、除），并指出**其中一部分可以互相表达**。因此要区分"语言里有的算子"与"必须作为原始算子的最小集合"（4.10.3「原始运算符」正是做这件事）。一个常见的极小集合是 `{限制, 投影, 乘积, 并, 差, 改名}`，其余派生：

```
交        r1 ∩ r2      ≡  r1 MINUS (r1 MINUS r2)
θ-联接    r1 ⋈_θ r2    ≡  (r1 × r2) WHERE θ
自然联接  r1 ⋈ r2      ≡  (r1 × r2) WHERE 公共属性上全部相等 ， 再投影去掉重复属性
除        r1 {A} ÷ r2  ≡  (r1 投影到 r1−r2 的头) MINUS ( ... 见 4.x/D5d 的双重否定 )
```

**闭包（closure）**是这一章真正的主题：每个算子的输入是关系、输出也是关系 ⇒ 表达式可以任意嵌套 ⇒ 语言是"关系上的代数"而不是"遍历行的过程"。这条性质决定了第 11 章里"SQL 子句是不是也保持闭包"的判据。

### 2. 投影的代价：重复元组

`π_{SNO}(SP)` 会 collapse 掉同一供应商的多条供应记录。**在关系里这不是问题**——集合自动去重；在 SQL 里它是静默的行为差异（🔧 D4 的第一段实测：本例里加不加 DISTINCT 恰好结果相同，因为数据没有制造重复；把条件放宽就能看到差异）。这就是作者把"投影"单独列一节的原因：它是**唯一会改变元组同一性判断的算子**。

### 3. 同头条件与改名（4.6 / 4.7）

`UNION/INTERSECT/MINUS` 要求两个关系**头相同**：属性名、类型一一对应（无序地对应）。因此实际书写里 `RENAME` 是配平工具：

```
-- ⚠️ 示意：把 S 和 P 的"城市"改同名后求并
(S RENAME CITY AS C ) UNION ( P RENAME CITY AS C )
```

🔧 反面实证（D2，第 2 章已列）：SQL 的 `UNION` 不看名字只看位置，所以 SQL 里的"同头"是假前提，写错不报错。

### 4. 联接、乘积与"再论交运算"（4.10）

作者在此处的三步走值得照抄进笔记：

1. **乘积** `r1 × r2`：所有元组对；度相加，基数相乘（🔧 D4b：`S CROSS JOIN SP` = 9 = 3×3）。
2. **θ-联接** = 乘积 + 限定（🔧 D4b：`JOIN ON S.SN = SP.SN` = 3）。
3. **自然联接** = θ-联接 + 投影（去掉重复的公共属性）。
4. **再论交**：`r1 ⋈ r2`（同名同型公共属性上的自然联接）与 `r1 ∩ r2` 的关系——当两者头相同且公共属性就是全部属性时退化成交；作者用这一小节说明**"交"和"联接"是同一件事的两个视角**（元组层面 vs 属性层面）。

工程提醒（⚠️ 转述）：自然联接在真实产品里是危险写法（列名一改语义就变），MySQL/PostgreSQL 都支持但普遍不推荐——本目录不实测性能，仅记录：代数上等价 ≠ 执行上等价（代价差异见 [../mysql/15-连接查询.md](../mysql/15-连接查询.md)）。

### 5. 除法：Codd 原始算子里最被低估的一个

`SP {SNO, PNO} ÷ P {PNO}` 读作"供应了所有零件的供应商号"。它是唯一带**全称量词**味道的代数算子（对照附录 D 的关系演算：除法 ↔ `∀`）。SQL 里没有除法运算符，唯一的标准写法是双重否定：

🔧 实测（D5d，SQLite 3.45.3；数据：SP 含 S1(P1,P2)、S2(P2)、S4(P1,P2,P3)，P = {P1,P2,P3}）

```sql
SELECT DISTINCT SN FROM SP AS x
WHERE NOT EXISTS (SELECT * FROM P AS p
                  WHERE p.PN NOT IN (SELECT PN FROM SP AS y WHERE y.SN = x.SN));
-- -> [('S4',)]
```

漏掉 `DISTINCT` 的后果（🔧 D5e）：`-> [('S4',), ('S4',), ('S4',)]`——除法是关系运算，返回袋就说明还没回到关系层次。

### 6. 关系比较（4.11）与修改运算符的扩充（4.12）

- 比较：`r1 = r2`（扩展相等）、`r1 ⊆ r2`、`IS_EMPTY(r)`（配合附录 B 的 TABLE_DUM/TABLE_DEE 可表达成关系层的等式）。这一小节是第 6 章"断言"的语法前提：断言的布尔值就是"某个关系是否为空"。
- 修改：`INSERT`/`DELETE`/`UPDATE` 是赋值缩写；`UPDATE` 在模型里等价于"删旧元组 + 插新元组"的一次整体替换，因此它**必须是一次原子操作**（否则码可能在中途被违反——这是第 8 章原子性的模型侧理由）。作者在此还讨论了"扩充"：一次修改涉及多个 relvar 的情形（例如同时改 SP 和派生统计），这在 SQL 里要靠事务表达。

🔧 关系比较在 SQL 里没有对应物（D10e 只能用双向 `EXCEPT` 绕）：

```sql
SELECT (SELECT COUNT(*) FROM (SELECT SN FROM S EXCEPT SELECT SN FROM S_copy)) = 0
   AND (SELECT COUNT(*) FROM (SELECT SN FROM S_copy EXCEPT SELECT SN FROM S)) = 0;
-- -> [(1,)]
```

## 常见误区

| 误区 | 纠正 |
| --- | --- |
| 「关系代数只是历史，实际用 SQL 就行」 | 代数是**判据**：SQL 的每个子句都可以拿去问"它是不是闭包内算子"；第 11 章就是这么用的 |
| 「投影不需要去重」 | 投影是集合上的投影，重复自动消失；SQL 必须显式 `DISTINCT` |
| 「UNION 会帮我对齐列名」 | 它按位置对齐（🔧 D2）；名字不同、顺序不同都能"成功"，然后给错答案 |
| 「NATURAL JOIN 最优雅所以最该用」 | 优雅但脆：属性集合一变，联接条件跟着变；且与模型的自然联接在 NULL 上并不等价（第 12 章） |
| 「UPDATE 是一行行的」 | 模型层是整体替换；把它想成一串单行改写会漏掉"中途状态可能违反约束"的问题（→ 🔧 D11e 的 ABORT 行为） |
| 「除法没什么用」 | 它是"全部/任意"类需求的唯一声明式表达，双重否定是它的 SQL 影子 |

## 核心概念速览（中英对照）

- **关系代数** — relational algebra：以关系为输入输出的算子代数，Codd 1970 提出
- **Codd 的原始代数** — Codd's original algebra：限制、投影、联接、乘积、并、差、改名、除（8 个，部分可派生）
- **限制** — restriction（σ）：按谓词筛元组，度不变
- **投影** — projection（π）：去属性；可能合并元组 ⇒ 关系语义下自动去重
- **同头 / 并兼容** — union-compatible：两关系头相同，是并/交/差的前提
- **并 / 交 / 差** — union / intersection / difference：集合算子，交可由差表达
- **改名** — rename（ρ）：改属性名（或元组变量名），用于凑同头
- **笛卡尔乘积** — product（×）：所有元组对；度相加、基数相乘
- **θ-联接 / 自然联接** — theta join / natural join（⋈）：乘积 + 限定（+ 去重复属性）
- **原始运算符** — primitive operators：不可由其他算子表达的最小算子集
- **除法** — division（÷）：带全称量词味道的算子；SQL 里写作双重 NOT EXISTS
- **闭包** — closure：算子输出仍是关系 ⇒ 表达式可任意嵌套
- **关系比较** — relation comparison：`=`、`⊆`、`IS_EMPTY`，作用在关系值上
- **修改运算符** — updating operators：INSERT/DELETE/UPDATE，赋值的派生缩写

## 最新演进与工业实践

- **代数在 2024–2026 年的工程形态**：查询优化器的中间表示仍是关系代数树/图——自愿式优化（Cascades 类）把"逻辑算子 → 物理算子"作为核心分工。⚠️ 转述，未在本目录实测。可读的入口：红宝书合集导航 [../Readings_in_Database_Systems/00-总览与阅读地图.md](../Readings_in_Database_Systems/00-总览与阅读地图.md)。
- **除法的现代替身**：分析引擎里"满足全部条件"的查询常用 `GROUP BY ... HAVING COUNT(DISTINCT x) = n` 代替双重否定（🔧 自拟，非书中原文）：

```sql
-- 🔧 与 D5d 等价的"计数式除法"，在 SQLite 3.45.3 上可跑
SELECT SN FROM SP WHERE PN IN (SELECT PN FROM P)
GROUP BY SN HAVING COUNT(DISTINCT PN) = (SELECT COUNT(*) FROM P);
```

（⚠️ 注意：计数式在存在 NULL 或部分缺失时需要额外保护；双重否定式对 NULL 更稳，第 12 章讨论。）
- **DuckDB 的算子支持**（🔧/文档口径）：`ANTI JOIN`、`SEMI JOIN`、`ASOF JOIN`、`PIVOT/UNPIVOT` 已成为一等语法（https://duckdb.org/docs/sql/query_syntax/select ✅），这恰好是"作者在第 5 章呼吁的 MATCHING/NOT MATCHING 被工业界补上了"的一个侧面证据。
- **关系比较的标准化进展**：SQL 标准至今没有"关系相等"运算符；最接近的是 `NOT EXISTS (r1 EXCEPT ALL r2) AND NOT EXISTS (r2 EXCEPT ALL r1)`（⚠️ 标准文本未逐字核）。这与本直 🔧 D10e 的绕法一致。
- **代码层对照**：Tutorial D 风格实现（关系值可直接 `=` 比较）可参考社区实现 `core.relational`：https://github.com/moerkb/core.relational ✅（Clojure，基于 Date 的 Tutorial D；2014 年后停更，仅作语言形态参考）。
