# 第 1 章 并发设计原理（First step: concurrency design principles）

> 并发设计的起点：衡量指标（吞吐量/响应时间/可伸缩性）、设计步骤、基础算法（矩阵乘/数据聚合的串行/并行对照）。本书独有的「先定指标再设计」方法论。

## 一、本章地图

| 主题 | 关键 |
| --- | --- |
| 衡量指标 | 吞吐量、响应时间、可伸缩性、公平性 |
| 设计步骤 | 分解任务 → 选执行器 → 度量 → 调优 |
| 基础并行 | 矩阵乘/数据聚合的并行化模板 |

## 二、核心精讲

### 2.1 🔧 先定指标
- 不要盲目并行：先量串行基线（🔧 用 JMH 微基准 / 业务链路埋点），确认瓶颈在 CPU 还是 IO。
- 可伸缩性 ≠ 越快越好：Amdahl 定律限定串行部分的加速上限（🔧 见 Goetz concepts/Amdahl定律与可伸缩性）。

### 2.2 任务分解模板
- 数据并行（同操作不同数据）→ `parallelStream` / ForkJoin；任务并行（不同操作）→ 线程池 + `CompletableFuture`（🔧 见葛一鸣 5 章并行模式）。

## 三、版本演进 / 论文 / 前沿

- 论文：Amdahl（1967）与 Gustafson（1988）定律；Gunther USL（Universal Scalability Law）。
- 前沿：JDK 21 虚拟线程让「任务并行」常退化成「每请求一虚拟线程」+ 结构化并发，省去手分解（JEP 444/453）。

## 四、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "并行一定快" | 先量串行基线，看 Amdahl 上限 |
| 2 | "线程越多吞吐越高" | 超核心数后上下文切换反噬 |
| 3 | "不度量就调优" | JMH/链路埋点先量化 |
