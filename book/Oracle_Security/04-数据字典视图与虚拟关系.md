## 4.1 数据字典：权限模型作用其上的"库内元数据库"

⚠️ 转述（8i/9i）：数据字典本体是 SYS 拥有的一组基表（`user$`、`tab$`、`col$`、`ts$`……存于 SYSTEM 表空间），其上有三层公开视图：

- **`V$`/`GV$` 动态性能视图**：实例运行态（会话、等待、锁）——直接封装固定表（fixed table，`X$`），授权走 `V_$xxx` 同义词+GRANT SELECT 路线；
- **`DBA_*`**：全库视角，如 `DBA_TAB_PRIVS`、`DBA_ROLE_PRIVS`——审计取证主力；
- **`ALL_*`/`USER_*`**：按当前用户可见性/属主收窄的镜像层。

安全视角的三行结论：①字典是**唯一完整的授权账本**，03 章的一切清算最终表现为几条 `DBA_*` 查询；②`SELECT_CATALOG_ROLE` 与 `O7_DICTIONARY_ACCESSIBILITY=TRUE`（8i 兼容开关：使 `ANY` 系统权限连字典基表一并覆盖）是两个"账本对全员开放"的历史阀门（⚠️ 参数语义为官方文档口径）；③字典可读面本身应进最小权限清单——能读 `DBA_USERS` 即拥有全库用户名与哈希（9i 的 `DBA_USERS.PASSWORD` 列仍展示哈希！11g 起移入 `user$` 需特权重读）——这是"元数据即机密"的教科书案例。

## 4.2 视图作为授权工具：封装、联查与 definer 语义

⚠️ 转述：视图是 2001 年（VPD 之前夜）实现细粒度可见性的**主武器**：

- 列裁剪/行过滤：`CREATE VIEW emp_secure AS SELECT id, name FROM emp` + 只授视图、不授基表；
- **definer 权利透传**：视图以定义者的对象权限读基表，访问者不需要基表权限——授权面从 N 张表收敛为 1 个视图；
- WITH CHECK OPTION 守写路径；
- 局限同样清楚：视图集合是**人工维护的策略物化**，策略变更=DDL 变更；VPD（9i，策略函数注入谓词）与 Label Security 是其自动化替代者（03 章演进节）。

### 🔧 G2 意外发现：SQLite 的视图**没有** definer 透传语义（非 Oracle 行为）

authorizer 回调实验（🔧 实测，脚本见 00 §五）：对基表 `emp` 的列读回调在**经视图访问时同样发生**——

```python
def auth2(action, arg1, arg2, dbname, trigger):
    if action == sqlite3.SQLITE_READ and arg1 == "emp" and arg2 == "ssn":
        return sqlite3.SQLITE_DENY       # 只封 ssn 列
    return sqlite3.SQLITE_OK
con2.set_authorizer(auth2)
con2.execute("SELECT * FROM emp_secure")   # OK：视图只引 id,name
con2.execute("SELECT ssn FROM emp")        # -> access to emp.ssn is prohibited
```

实测输出：`G2 via view OK: [(1,'alice'),(2,'bob')]`、`G2 ssn column read blocked -> access to emp.ssn is prohibited`。**解读**：SQLite 的授权回调工作在视图展开后的"物理读"层，无法区分经视图/直接读——因此 SQLite 语境下"用视图保护列"必须靠 authorizer 直接盯列，而不能指望视图本身产生权限边界。这恰好反衬 Oracle 视图安全模式的成立条件：**授权判定发生在名称解析层、按对象（视图）而非按展开后的基表列**——两引擎一个概念差，实验把差值钉死了（⚠️ Oracle 侧语义为文档转述）。

## 4.3 字典安全面的审计标准件

⚠️ 本册"第三方指南"体裁的检查动作（重构自同期通说）：

1. `DBA_TAB_PRIVS` 按 `GRANTEE='PUBLIC'` 切片——出厂 EXECUTE 包清点（03 章联动）；
2. `DBA_SYS_PRIVS` 中 `ANY` 家族 + `SELECT ANY DICTIONARY`（9i 引入，把字典访问从 `SELECT ANY TABLE` 里拆出来的关键粒度改进）；
3. `V$FIXED_TABLE` 可枚举面：哪些 X$/V$ 能被谁查；
4. `O7_DICTIONARY_ACCESSIBILITY`、`Restricted` 模式状态；
5. 导出工具（exp/imp）与 `EXP_FULL_TABLE` 类角色：字典权限的"侧门"——拖库在 2001 年是一个合法命令行工具（05 章：为何要审计它）。

## 4.4 🔧 G5：Virtual Table——"虚拟关系"机制的具象化（非 Oracle 行为）

SQLite 的 `CREATE VIRTUAL TABLE` 允许注册由模块实现的"表"：

```python
con5.execute("CREATE VIRTUAL TABLE docs USING fts5(body)")
con5.execute("SELECT rowid, highlight(docs,0,'[',']') FROM docs WHERE docs MATCH 'listener OR audit'")
# -> [(1,'[listener] password granted sysdba'), (2,'[audit] trail grows fast')]
```

实测（🔧）：FTS5 虚表在 `sqlite_master` 中登记为 `type='table'`，但内容存储与查询计划全部由 fts5 模块接管。

**类比落点**（⚠️ 侧为转述+本目录类比，非同一机制）：Oracle 世界里同样存在"看起来是表、行为由代码定义"的一族——外部表（external tables，9i 引入，数据在文件里）、物化视图（查询改写）、以及 VPD 加持下的普通表（谓词被策略函数偷偷注入）。G5 的教学价值：让"关系是接口、存储与语义可换引擎"这件抽象事在 5 行代码内可玩，从而理解 4.2 的视图与 VPD 为何能"不改应用而改行为"。注意边界：SQLite Virtual Table 是**扩展机制**，Oracle 外部表/VPD 是**安全与集成机制**，不可混为一谈（标非 Oracle 行为）。

## 核心概念速览（中英对照）

- **数据字典** — data dictionary：SYS 基表+公开视图层，授权模型的账本。
- **固定表** — fixed table（X$）：实例内存结构映射，V$ 的底座。
- **动态性能视图** — dynamic performance view（V$/GV$）：运行态取证面。
- **DBA_/ALL_/USER_ 三层** — dictionary view tiers：可见性收窄的镜像阶梯。
- **SELECT_CATALOG_ROLE** — catalog role：字典全读的捷径角色，基线审视对象。
- **O7_DICTIONARY_ACCESSIBILITY** — compat switch：让 ANY 权限覆盖字典的 8i 兼容阀门（⚠️）。
- **SELECT ANY DICTIONARY** — granular privilege：9i 拆出的字典专权。
- **视图封装** — view-based encapsulation：definer 透传下的授权收敛术。
- **WITH CHECK OPTION** — write guard：视图写路径谓词约束。
- **元数据即机密** — metadata confidentiality：DBA_USERS 含哈希的教训。
- **拖库侧门** — export backdoor：exp/imp 与导出权限的合法外衣。
- **Virtual Table** — 虚表（🔧）：模块接管存储与计划的"接口表"。
- **外部表** — external table：Oracle 侧"文件即表"，类比 G5 用。
- **VPD** — virtual private database：策略函数注入谓词的视图自动化（9i）。
- **三册分读** — one dictionary, three lenses：安全/优化/诊断共用字典。

## 最新演进与工业实践

- **哈希列事件**：11g 起 `DBA_USERS`/`ALL_USERS` 不再展示口令哈希（回归 `user$` 特权读），4.1③ 的教科书案例以厂商改默认面收尾（⚠️ 通说）。
- **字典层工程化**：12c 的 CDB 视图加 `CON_ID`、`CONTAINERS()` 子句统一跨租户字典查询；ADDM/AWR 把 `V$` 消费产品化——TOP2e 线的现代延伸（[../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md](../Troubleshooting_Oracle_Performance_2e/00-总览与阅读地图.md)）。
- **VPD 现状**：`DBMS_RLS` 仍是 23ai 内置能力，且演进出 `DBMS_REDACT`（动态脱敏，12c）与 SODA/JSON 关系视图；视图+VPD+Redact 三层与 4.2 的"人工物化策略→自动策略"叙事连成直线。
- **SQLite 侧（🔧 生态）**：Virtual Table 家族长成 FTS5/JSON1/RTREE/系列表等标准件，rqlite/DNS-over-SQLite 等项目把"宿主授权回调"用作真实安全边界——G1/G2 展示的模式在生产工具中存在（⚠️ 项目名通识，未附链）。
- **数据目录合流**：现代治理把"字典视图清点"升级为自动化数据目录+权限图谱，元数据采集/血缘/权限快照成为治理平台标配——工程语境见在盘 [../数据安全架构设计与实战.md](../数据安全架构设计与实战.md) 的元数据与分类分级章节。
