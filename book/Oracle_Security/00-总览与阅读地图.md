## 五、实测纪律声明（🔧 全览）

Oracle 不可本机实测 → 本目录**零条 Oracle 🔧 结论**。SQLite 类比实验共 5 组（≥4 组达标；加密/权限/Virtual Table 三类齐备），脚本与输出落盘于 `D:\develops\tmp\dbwave_w7_orasec\experiments.py`（repo 零构建产物），运行环境 Python 3.13.2 + SQLite 3.45.3（FTS5 已编译入）：

| 组 | 实验 | 类比对象 | 所在章 |
|---|---|---|---|
| G1 | `set_authorizer` 回调 DENY `DROP TABLE`/`ATTACH` | Oracle 系统权限裁剪 | 03 |
| G2 | 视图展开后按基表+列回调，DENY `emp.ssn` 列读 | 列级权限/视图封装（含语义差异发现） | 04 |
| G3 | `set_trace_callback` 捕获全部执行语句 | AUDIT 跟踪流 | 05 |
| G4 | 口令→PBKDF2→密钥流异或加密整个 DB 文件，头魔数 `SQLite format 3` 消失 | TDE 之前的带外加密/DBObfusc 思路 | 07 |
| G5 | FTS5 虚拟表 `CREATE VIRTUAL TABLE ... USING fts5` | 数据字典"虚拟关系"与 Virtual Table 机制 | 04 |

**每一组结论均标"非 Oracle 行为"**：SQLite 无库内用户体系，其"权限"是宿主应用回调注入的，恰与 Oracle 的库内授权模型形成结构性对照——这个对照本身就是本册最有价值的概念澄清。

## 七、2001 → 2026 时间轴锚点

- 1997–1998：Oracle8i 之前，共享责任边界开始文档化；DES-based 口令哈希可离线穷举，公开破解工具已有流通（⚠️ 通史转述）。
- 2001?（本书，⚠️ 年份待核验）：第三方/审计视角的 Oracle 安全书出现，正是 dot-com 后 DB 暴露面反思期。
- 2003–2005：Slammer 蠕虫（2003，打 SQL*Net/监听器栈）与 2005 年初 TNS 口令哈希公开爆破风暴；Oracle 2005-01 起改为**季度 Critical Patch Update**——本书出版后的世界首先被这两件事重塑（⚠️ 通史转述）。
- 2005–2007：10gR2 TDE、Data Vault/Label Security 商品化；#51 DBHH（2007）从攻方重述同一批主题。
- 2013–2019：12c 统一审计、口令大小写敏感默认翻转、Veridata 等；12.2 TLS 强化。
- 2020–2026：19c 长期支持 + 23ai/26ai：默认口令策略收紧、`SEC_CASE_SENSITIVE_LOGON` 退役、ZDK/QPS 列加密、DB 侧 mask/grant 体系（REST/Data Pump 侧），审计接入云可观测栈。各章演进节就近展开。

## 八、争议与辨析登记

1. **CONNECT 角色之辩**：预定义角色 RESOURCE 含 100+ 系统权限（11g 后收敛），CONNECT 实际仅需 CREATE SESSION——原书 ch05s02 专节讨论即因 8i/9i 时代 CONNECT 隐含 CREATE TABLE 等权限的旧语义。多一代 Oracle 安全文章反复清算此话题，本册 03 章以此为中心（✅ 锚点唯一实证，⚠️ 论证自拟）。
2. **审计写 OS 还是写 DB**：AUDIT_TRAIL=OS 在 9i 是"防 DBA 篡改审计"的答案，后被统一审计+审计策略集中化替代；05 章保留该历史逻辑。
3. **视图穿透问题**：SQLite authorizer 实验（G2）意外发现"视图展开后仍按基表+列回调"，与 Oracle definer-rights 视图语义相反——此差异为本目录自产澄清，两引擎行为分别标 ⚠️/🔧。
4. **中译混排**：检索中"Oracle 安全"同名中文书/词条多（如《Oracle安全实践》系中文原创），均非本书译本，防混。
