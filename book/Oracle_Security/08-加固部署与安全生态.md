## 8.1 出厂状态盘点：默认账户与样例世界

⚠️ 转述（8i/9i）：新建库附带数十个出厂账户——真实内部账户（SYS/SYSTEM/OUTLN/CTXSYS/ORDSYS...）与演示账户（SCOTT/TIGER、HR、PM、SH、OE）。2001 年的事故画像：**演示账户口令即用户名且从不锁定**（无 profile 时代），`SCOTT/TIGER` 成为互联网上 Oracle 的代名词级入口；DBSNMP 携带 `SELECT ANY TABLE` 类权限服务于 OEM 智能代理——"监控要权限"第一次以默认高权形态登场。9i 的 DBCA 开始询问口令并锁定未用账户，方向自此翻转（⚠️ 演进节续账）。

加固动作清单（本册体裁的标准件，逐条对应字典证据）：

1. `DBA_USERS` 全表过筛：`ACCOUNT_STATUS`、`LOCK_DATE`、`EXPIRY_DATE`、口令哈希为默认值者（`DBA_USERS.PASSWORD` 在 9i 可读！04 章哈希教训）；
2. 未用选项不装（Oracle Text/InterMedia/…各自带来一个 CTXSYS/MDSYS 面），已装不用的锁；
3. 样例 schema 在生产库删除或至少改口令+锁+撤 PUBLIC 依赖；
4. `DBA_ROLE_PRIVS WHERE GRANTEE IN (默认高权账户)` 回收链。

## 8.2 环境与文件层加固

⚠️ 转述：数据库安全的一半在 OS/网络（02 章"两个根"的部署面）：

- `$ORACLE_HOME` 可写性=攻击者改二进制/加库（extproc 通道，6.2）；oracle 属主账户的 shell 历史里存着 `connect sys/pass`——口令进 ps/历史是当年渗透报告常客；
- `init.ora` 参数敏感项：`sec_case_sensitive_logon`（9i 语义讨论）、`os_roles`、`remote_os_*` 三件套（远程 OS 认证=OS 轨外延到网络，默认值即危险样本）；`restricted` 模式运维纪律；
- 文件权限面：口令文件/orapw、监听日志、AUD$ 导出件、备份片（07 章："备份=明文全库"）；
- 最小安装原则：不启用的服务不注册（监听 SID_LIST 收缩，6.5 联动）。

## 8.3 补丁前时代：告警、CPU 与暴露窗口管理

⚠️ 转述史实：本书年代尚无季度补丁制度——厂商以"Security Alert"电邮通告 + 单点补丁（one-off patch）交付，暴露窗口以月计、且多数企业连告警邮件列表都没订阅。Slammer（2003-01，6 章）直接催生 2005-01 起的**季度 Critical Patch Update（CPU）**制度与其后的 Patch Set Advisor/`opatch lspatches` 台账化。审计者由此获得新检查单：`DBA_REGISTRY_SQLPATCH`（时代后件）/opatch 清单 vs 当季 CPU 的差额=账面暴露窗口；版本探针（6.1 的 banner）+补丁台账=攻击者的免费计算器。**补丁管理是安全生态里唯一由"时间"定价的防线**——这是 01 章威胁面表最后一行的落地形。

### 收束对照（🔧 概念收编，非新实验）

8.2 的"文件权限即最后防线"与 8.1 的"默认账户面"在 SQLite 世界有精确镜像：G1/G2 实验显示 SQLite 的访问控制**整个由宿主程序负责**——没有库内账户=没有默认口令雷，但宿主代码一旦可被替换（=8.2 的 ORACLE_HOME 可写），授权回调也形同虚设。**引擎负责机制、部署者负责策略、时间负责补丁**——01 章共享责任模型在三章收束处完成闭环。

## 8.6 最小加固脚本骨架（示意件，⚠️ 伪 SQL，勿直接投产）

本册体裁的终点形态是"可执行的检查单"。以下为八章知识压缩成的骨架示意（对象名/参数按 9i 语境 ⚠️ 转述，各版本必核对后改写）：

```sql
-- 02 章：认证面
select username, account_status, lock_date, profile from dba_users;
select * from dba_profiles where resource_name like 'PASSWORD%';
-- 03 章：授权面
select * from dba_sys_privs where privilege like '%ANY%';
select * from dba_tab_privs where grantee = 'PUBLIC';
select * from dba_role_privs where granted_role in ('DBA','RESOURCE');
-- 05 章：留痕面
show parameter audit;  select count(*) from sys.aud$ where ntimestamp# > sysdate-7;
-- 06 章：网络面（shell 侧）: lsnrctl status / 端口普查 / sqlnet.ora 三参数
-- 08 章：基线面：与 CIS/自建基线逐项 diff，输出红黄绿三态
```

**使用纪律**：脚本输出只是"证据导出件"（01 章），判红牌的是 7.6 式的问题框架与本章各清单；把"跑扫描器"当成"做加固"是生态建制化之后的新误区。

## 核心概念速览（中英对照）

- **默认账户审计** — default account review：SCOTT/TIGER 时代的标准红牌。
- **演示 schema** — sample schemas：生产库里的教学残留。
- **DBSNMP 悖论** — monitoring privilege：要监控就要权限，要权限就有面。
- **OS 轨加固** — home/binary trust：$ORACLE_HOME 可写性与口令进历史。
- **remote_os_* 三件套** — remote OS auth params：OS 信任外延到网络的默认危险样本。
- **Security Alert 时代** — pre-CPU era：月级暴露窗+无人订阅的告警。
- **CPU 季度补丁** — Critical Patch Update：Slammer 催生的时间定价防线。
- **opatch 台账** — inventory of applied patches：账面暴露窗口的算法。
- **一键体检** — SAT/DSAT：人肉清单的建制化终态。
- **数据安全中心** — data security command center：云上的发现-分类-脱敏-监控闭环。
- **宿主全责** — host-owner security（🔧）：SQLite 无库内账户的镜像教训。
- **时间定价** — security priced in time：补丁窗即风险敞口。
- **机制/策略/补丁三分** — mechanism/policy/patch：全书收束的责任坐标系。
- **攻守对位表** — offense-defense map：本册与 #51 的章章映射。
- **波内四读** — four Oracle lenses：Essentials/ProblemSolving/Internals/Security。

## 最新演进与工业实践

- **默认姿态翻转**：现代 DBCA 默认锁演示账户、口令策略内置、`SEC_CASE_SENSITIVE_LOGON` 退役为恒真；12c 起 SecureFiles 默认、`audit_trail` 在统一审计模式下的新语义（⚠️ 版本细节以官方基线文档为准）。
- **官方免费体检件**：Oracle Database Security Assessment Tool（DSAT，2021+，免费下载运行出报告）——8.4 谱系的当代终点；配套 My Oracle Support 的补丁顾问把 8.3 台账自动化（⚠️ 产品名通识，本环境未能逐一验链）。
- **发布节奏演化**：CPU→RUR/RU 半年大更+季度安全（18c/19c 时代）→23ai 延续；漏洞评级体系（CVSS 进公告）让 8.3 的"窗口"可计算。
- **生态与合规**：CIS Benchmark/等保数据库要求条目化后，8.1/8.2 清单在工业界由 IaC 镜像+策略即代码下发（与在盘治理线互参，如 [../Data_Governance_in_the_Era_of_AI_2e/00-总览与阅读地图.md](../Data_Governance_in_the_Era_of_AI_2e/00-总览与阅读地图.md) 的合规自动化语境——该链接已验证在盘）。
