# 06 网络、监听器与连接层安全（主题重构章）

> 本章为**主题重构**（原书 TOC 不可达，见 [00 降级声明](00-总览与阅读地图.md)）。Oracle 侧论述 ⚠️ 文档转述；本章无独立 🔧 组（网络层无 SQLite 对应物，类比仅在 6.4 以对照段给出）。

## 6.1 监听器：一切远程攻击的第一站

⚠️ 转述（8i/9i，产品名 Net8/Oracle Net）：监听器（`tnslsnr`，默认端口 1521）是独立于实例的进程，职责是"接电话并转接"——它自己维护**服务注册表**（实例 PMON 动态注册 + `listener.ora` 静态注册双轨）。安全后果：

1. **版本探针**：`tnsping`/nc 裸发连接请求即可回包 banner（含 Oracle 版本、补丁级别）——攻击侦察的免费午餐；当年建议 `ADMIN_RESTRICTIONS_<name>`（9i 引入，⚠️）与屏蔽 banner 的手段有限；
2. **status 泄密**：`lsnrctl status` 输出 DBID、日志/trace 文件路径、`ORACLE_HOME`——**无口令即可执行**（8i 默认无口令时代）；
3. **远程管理灾难链**：`lsnrctl set password` 是止血带而非城墙：口令以明文流过网络（后由口令 verifier 演进）、`SET CURRENT_LISTENER`+`save_config` 类操作可被滥用改写配置；监听器口令文件形态与 DB 口令文件（02 章）无关，是**第三个凭据库**——三轨（字典/orapw/口令）并立的说法由此而来；
4. **动态注册面**：服务名可被"猜"（`ORCL`/`XE`/`TEST` 字典爆破），静态注册的 `GLOBAL_DBNAME` 别名管理是资产清单问题。

## 6.2 客户端与命名解析：被忽视的一半

⚠️ 转述：`sqlnet.ora` 三件套：

- **命名方法** `NAMES.DIRECTORY_PATH`（TNSNAMES/EZCONNECT/HOSTS 顺序）：EZCONNECT（`host:port/service`）与 HOSTS 解析在 9i 让 `tnsnames.ora` 消失成为可能，同时把信任交给 DNS/hosts 文件——命名劫持面随之前移（联动 Slammer 史，见演进节）；
- **节点限制** `tcp.validnode_checking` + `invited_nodes`（8.1.3/9i 期引入，⚠️ 具体版本号不背）：IP 白名单，当年少数真正免费的城墙；
- **`SQLNET.EXPIRE`**（死连接探测）与 `TRACE`/`LOG` 目录权限（监听日志含 SQL*Net 元数据、trace 可含敏感串）。

外部过程 `extproc`（PL/SQL 调 C 库的通路）经独立监听服务派发 OS 进程执行库文件——`EXTPROCORACLPERM` 类权限配置与库文件目录可写性构成**从 DB 到 OS 代码执行**的历史通道，审计必查（⚠️ 通说转述）。

## 6.3 传输层：从明文焦虑到 ASO

⚠️ 转述：8i/9i 的 SQL*Net 默认**明文**：口令（认证期）、SQL 全文、结果集全程裸奔。对策分级：

| 层 | 手段 | 时代成本 |
|---|---|---|
| 网络分段 | DB 只监听内网接口、防火墙白名单 | 免费但依赖网工 |
| 节点检查 | invited_nodes | 免费，9i 起 |
| 完整性 | ASO crypto checksum（MD5/SHA） | 选件费+CPU |
| 加密 | ASO 加密（export 版 40 位/国内版分级，Triple-DES 起步） | 选件费+美国出口管制语境 |
| 身份 | 双向 SSL 证书认证（02 章合流） | PKI 基建 |

概念澄清（本目录提炼）：**传输加密≠数据加密**——ASO 解决"链路上不裸奔"，对 07 章的"盘上不裸奔"零贡献；当年两件事共用"encryption"一词导致大量方案错配，本书以整章篇幅切开这条缝。

## 6.4 对照段（非 🔧，概念类比）

SQLite 没有网络层——**"零监听器"是一种极端安全姿态**：攻击面收缩为"谁能读文件/谁能执行宿主进程"。工程后果的镜像对照：Oracle 的监听器加固问题（6.1-6.2）在 SQLite 世界变成"部署侧的文件权限与进程隔离"问题；而一旦把 SQLite 塞进 C/S 网关（rqlite HTTP 端点、基于它的嵌入式设备固件），6.1 的所有剧情（banner 泄露、未认证端点、默认开放）在 HTTP 层原样重播——网络中间层的信任债不会因为换引擎而消失，只会换协议还。

## 6.5 审计者检查单（本册体裁）

1. `lsnrctl services` 远程盲测：能拿到什么（应拿不到或仅经跳板）；
2. 端口普查：1521 之外的历史残留（多个监听/ORACLE_HOME 各自 listener.ora）、静态注册的 SID 与真实库对不上账；
3. `sqlnet.ora` 三参数现状（命名方法/validnode/expire）；
4. extproc 服务是否关闭（不用的监听不配 SID_LIST）；
5. ASO 是否启用及其覆盖链路清单（07 章密钥管理联动）；
6. 监听日志的时间戳与 AUD$ 会话交叉（05 章留痕三角的网络角）。

## 6.6 攻防第一幕：一次匿名侦察的转写（⚠️ 转述式重构，非实录）

攻击者在碰到 02 章任何认证防线之前，能白手拿到什么？——当年一次公开的 `lsnrctl` 会话即可（命令语义 ⚠️ 文档转述）：

```text
C:\> set ORACLE_HOME = D:\oracle\ora90          # 甚至不是必须的
C:\> lsnrctl status LISTENER
... Services Summary...
  "ORCL", status READY ...
    Instance "orcl", status READY ...
      Handler(s)... (DEDICATED) establish:0 accept:0 ...
    ... (含 DBID 类标识、trace 路径、ORACLE_HOME 真实路径) ...
```

三行结论：①服务名清单=口令爆破的字典输入（02 章）；②路径泄露=OS 侧攻击的地图（08 章文件层）；③`establish/accept` 计数=在线流量指纹（性能视角居然也能读——与 TOP2e 的"等待即信息"同构，⚠️ 类比声明）。所以 6.5① 的"远程盲测"检查项排在清单第一位：**先量化对方免费得到什么，再谈加固优先级**。

## 6.7 命名与拓扑的资产治理问题

⚠️ 转述+提炼：监听器安全的本质困难是**资产账本**问题而非密码问题——

1. 一台机 N 个 `ORACLE_HOME` × 每 HOME 默认一个监听 = 端口账实不符的温床（历史残留监听比现役监听更危险，因为无人记得其口令/配置）；
2. 静态 `SID_LIST` 里的别名（GLOBAL_DBNAME 玩法：一监听多别名做早期"读写分离路由"）让"服务名→库"映射失控，审计归因随之失效；
3. `tnsnames.ora` 集中分发 vs 广播注册（`.brd`，当年 Net8 的"自动发现"）是 2001 年的便利/泄露权衡题——广播后来被默认关闭，方向由历史裁定（⚠️）；
4. 治理动作：把"监听-端口-服务名-实例-主机"五元组当配置管理项维护，年度对账——这就是"数据库 CMDB"的最早形态之一。

2. invited_nodes 挡不住哪种对手？（6.2：能进入白名单网段的任何主机——它只收缩面不设身份）
3. "传输加密≠数据加密"各管盘面哪一角？（6.3 表+07 章开篇）。

**一句话口述版**：监听器是"没锁门的前台"——它不认人只认服务名，所以侦察免费、口令是后补的、真正的墙只有 invited_nodes 与分段两堵；ASO 买的是"通话加密"，不是"抽屉上锁"。

## 6.9 连接层三文件速记（⚠️ 9i 口径）

| 文件 | 归属 | 安全相关项 | 失守后果 |
|---|---|---|---|
| `listener.ora` | 监听器进程 | 端口/协议栈/口令/静态注册/ADMIN_RESTRICTIONS | 侦察自由+配置改写 |
| `sqlnet.ora` | 客户端+服务端双边 | 命名方法/validnode/expire/trace 级别 | 连接劫持与噪音留痕 |
| `tnsnames.ora` | 客户端资产 | 服务名→端点映射账本 | 应用侧"拓扑真相"泄露 |

配套三问（体检时自答）：三个文件各在谁的可写域内？版本管理与审计库对得上账吗？trace/log 的保留期与敏感度假设一致吗？——三文件纪律是 08 章"环境加固"在连接层的投影。

## 核心概念速览（中英对照）

- **监听器** — listener（tnslsnr）：独立于实例的转接进程，远程攻击第一站。
- **动态注册** — dynamic registration：PMON 向监听器上报服务，资产面自动化也是攻击面自动化。
- **banner 泄露** — version banner：探针回包即版本情报。
- **lsnrctl status 泄密** — listener info leak：DBID/路径无口令可见。
- **监听器口令** — listener password：明文过网的第三轨凭据，止血带不是城墙。
- **ADMIN_RESTRICTIONS** — listener lockdown：封杀运行时改配置的 9i 参数（⚠️）。
- **EZCONNECT** — easy connect：免 tnsnames 的 host:port/service 形态，信任移交 DNS。
- **validnode_checking** — node restriction：invited_nodes IP 白名单，当年免费的城墙。
- **extproc** — external procedure：DB→OS 代码执行的历史通道。
- **ASO** — Advanced Security Option：加密/完整性/企业认证选件（当年收费）。
- **传输加密** — data in transit encryption：链路不裸奔，与存储加密分属两题。
- **出口管制分级** — export crypto grades：40 位/强密版并存的时代褶皱。
- **零监听器姿态** — no-daemon surface（🔧 类比）：SQLite 文件即库的极端收缩面。
- **信任债迁移** — trust-debt migration：嵌入式网关把监听器剧情换成 HTTP 剧情。
- **留痕三角网络角** — net evidence corner：监听日志与 AUD$ 交叉归因。

## 最新演进与工业实践

- **Slammer 分水岭（2003-01）**：SQL*Net/监听器栈缓冲区溢出蠕虫在数小时内打瘫全球——6.1 的"第一站"论断以灾难方式获得工业共识；Oracle 事后把补丁模型推向季度 CPU（08 章），并将动态注册/默认配置持续收紧（⚠️ 事件为公开网络史通识）。
- **现代默认面**：当前版本监听器默认仅本机注册远程管理受限、`ADMIN_RESTRICTIONS` 方向成为出厂姿态、TLS 一体化（Native Network Encryption 免费并入企业版，ASO 时代结束——与 02 章演进同源，2017 许可调整，⚠️ 通说）；12.2+ 支持 TLS 强制与服务端口令文件退役路线。
- **零信任语境**：数据库连接网关/mTLS 服务网格化（云厂商 DB proxy、Oracle 自家 Database Security Service 类形态）把 6.2 的"客户端信任"问题升维成身份问题；extproc 一类通道在当代基线里是默认关闭项。
- **SQLite 侧（对照）**：嵌入式部署安全讨论集中于文件权限、预编译语句（注入面收缩到宿主代码）与 rqlite/sqlite-web 类网关的认证缺失——6.4 的镜像论断在社区事故报告中反复应验（⚠️ 通识，未附链）。
