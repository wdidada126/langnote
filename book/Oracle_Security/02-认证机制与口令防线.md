# 02 认证机制与口令防线（主题重构章）

> 本章为**主题重构**（原书 TOC 不可达，见 [00 降级声明](00-总览与阅读地图.md)）。Oracle 侧论述全部 ⚠️ 公开文档转述，不可实测；本章无 🔧 组（SQLite 无库内认证概念，该类比放在 [03 章](03-权限角色与CONNECT之辩.md)作结构性对照）。

## 2.1 认证在 Oracle 架构中的落点

⚠️ 转述：Oracle 的连接建立分两段——先经监听器（网络层，06 章）定位实例服务，再由实例完成**用户认证**。8i/9i 提供的认证通道：

1. **Oracle 口令认证**：用户名/口令，口令哈希存于字典（`user$` 表，DES-based 哈希——正是 2005 年前后离线爆破工具的靶子）；
2. **特权连接认证**：`SYSDBA`/`SYSOPER` 经口令文件（orapwSID）或 OS 组认证（operadmin 组映射），这是**绕过普通字典**的第二套凭据体系，审计时容易被漏；
3. **OS 外部认证**：`OS_AUTHENT_PREFIX=ops$` 约定，OS 登录身份直接映射库内 `ops$xxx` 用户——Windows 域或 UNIX 信任域的嫁接点；
4. **外部名称认证**：`GLOBAL_NAMES`/目录服务侧 x500 名字映射；
5. **Advanced Security 认证**：Kerberos/SSL/RADIUS 三道门（ASO 选件收费，00 §六表）。

设计要点：通道 2 与通道 1 的**双轨**是 Oracle 特有的复杂度来源——`startup restrict` 时代连口令文件都没有（OS 认证独占），9i 后口令文件让远程管理免密登录成为可能，也让"备份了 orapw 等于备份了 SYS"成为取证常识。对照在盘：口令文件的物理位置讨论挂在 [../Oracle12c数据库应用与开发/03-存储结构-表空间与段区块.md](../Oracle12c数据库应用与开发/03-存储结构-表空间与段区块.md) 之外的 $ORACLE_HOME 语境（该书未展开，⚠️ 注明）。

## 2.2 口令生命周期：从复杂度到哈希强度

⚠️ 转述（8i/9i）：

- 口令复杂度靠 **VERIFY_FUNCTION**（`profile` 挂 `password_verify_function`，`utlpwdmg.sql` 样例函数：长度≥旧版约定、含数字/字母、非用户名逆序等）——是"脚本自带但默认不启用"的典型：出厂仍是无复杂度校验；
- 账户锁定靠 profile 的 `FAILED_LOGIN_ATTEMPTS`（9i 起有 DEFAULT profile 值，8i 需手设）；
- 口令轮换/宽限期：`PASSWORD_LIFE_TIME`/`PASSWORD_GRACE_TIME`/`PASSWORD_REUSE_MAX`；
- 哈希弱点：DES-based 区分大小写但**用用户名做盐**的老式存储 → 同库内改用户名即可复用爆破表；这一缺陷 11g 换 SHA-1 10 位盐哈希才闭合（演进节）。

**审计者检查单**（本册体裁，重构自同期社区通说）：所有非人账户（schema owner）口令过期策略、`DBA_USERS.ACCOUNT_STATUS`/`LOCK_DATE` 全表、匿名/默认账户口令未改清单（与 08 章联动）。

## 2.3 双轨凭据体系与信任边界

口令文件 vs 字典的边界问题（⚠️）：

| 问题 | 字典认证 | 口令文件认证 |
|---|---|---|
| 谁能连 | 全部普通用户 | 仅 SYS/SYSDBA/SYSOPER 成员 |
| 审计去向 | 可进 AUD$ | 失败**不落常规审计**（OS 层 syslog/事件日志） |
| 介质 | 数据文件（可被备份泄露波及） | 明文文件（OS 权限即最后防线） |
| 绕过面 | 应用通道（注入=合法） | `OS_AUTHENT_PREFIX`+信任域=OS 侧沦陷即库内沦陷 |

结论句（本目录提炼）：Oracle 的安全模型有**两个根**——数据库字典与操作系统信任域，任何一侧的默认宽松都会让另一侧形同虚设。OS 认证把 DB 安全问题的 1/3 移交给了系统管理员，这是 2001 年本书反复提醒跨职能协作的原因。

## 2.4 SSL/Kerberos：当年"买得起才用"的方向

⚠️ 转述：ASO 的三种企业认证整合里，Kerberos 走"OS 层票据→Oracle 信任 KDC"，SSL 走"双向证书+映射 DN 到库用户"，RADIUS 走"一次一密"。三者的共同卖点不是加密而是**口令不落库、不复用、可集中吊销**——即把 2.2 的口令弱点整体外部化。2001 年落地率低的原因：KDC/证书基础设施成本高、ASO 授权费、且多数企业内网仍被当作信任域。今日现状见演进节。

## 2.5 外部认证的操作陷阱清单

⚠️ 重构：

1. `ops$` 前缀用户**不设口令**，OS 侧任何能"变成"该 OS 用户进程身份的人即成库内该用户——UNIX 上 `su`、Windows 上服务账户滥用都是通道；
2. 网络侧 OS 认证（NT LM 信任桥）在双网卡/域信任扩大后静默扩面；
3. 外部认证用户常被划入过大默认角色（与 03 章 CONNECT/RESOURCE 叠加成"免口令+大权限"组合雷——原书 ch05s02 讨论 CONNECT 的语境里这正是被清算的对象，✅ 锚点，⚠️ 关联推断）；
4. 审计盲区：OS 认证成功的会话在 AUD$ 里看不到失败前的口令尝试，责任追踪要回落到 OS 日志——05 章 AUDIT_TRAIL=OS 的动机之一。

## 2.6 审计者的认证侧字典查询件（⚠️ 重构清单）

对应 01 章"以视图为证据源"方法在认证层的标准件（列名以 9i 口径，⚠️ 现代版本列已增改）：

1. `DBA_USERS`：`USERNAME/ACCOUNT_STATUS/LOCK_DATE/EXPIRY_DATE/PROFILE`——全账户体检底表；
2. `DBA_PROFILES`：`FAILED_LOGIN_ATTEMPTS/PASSWORD_LIFE_TIME/PASSWORD_VERIFY_FUNCTION`——逐 profile 核对"锁没锁、换不换、验不验"；
3. `DBA_OS_SESSION_ENCLIST` 类外部映射（`V$SESSION` 的 USERNAME/OSUSER 交叉）——ops$ 用户的"两个身份"对账；
4. `V$PWFILE_USERS`——口令文件成员清单（第三轨的账本）；
5. `DBA_ROLE_PRIVS WHERE GRANTED_ROLE='DBA'`——认证过后的第一问："登进来是谁"（03 章接口）。

## 2.7 认证决策树（部署视角，⚠️ 本目录提炼）

```
有企业目录/KDC/PKI 基建吗？
├─ 有 → ASO 系（Kerberos/SSL）统一认证，库内少留口令账户
└─ 无 → 口令认证？
    ├─ 单人交互 → Oracle 口令 + profile 三件套（有效期/锁定/复杂度）
    ├─ 应用连接池 → 尽量仍用 Oracle 口令但入保险库（当年=人肉口令表）
    └─ OS 批量作业 → ops$ 仅限专用低权账户 + 该账户 OS 侧同权治理
特权管理（SYSDBA）→ 优先 OS 轨（堡垒机承接），远程轨口令文件仅应急，
                     并确认 AUDIT SYSDBA 已开（05 章 5.1）
```

决策要点：**每种认证通道都自带一条配套审计义务**——通道选择即审计面选择，这是 05 章"留痕三角"的认证侧投影。

## 2.8 本章自测（三问）

1. 备份了 `orapw<SID>` 意味着什么？（=备份了 SYS 远程登录能力；口令文件成员清单见 2.6④）
2. 为什么 `ops$` 免口令账户必须同时治理 OS 侧？（2.5①：OS 身份即库身份，信任域共享）
3. 9i 的口令哈希弱点是什么、被哪个版本线闭合？（2.2：用户名作盐的 DES 系；11g SHA-1 起，演进节）。

## 2.9 本章挂点

- 2.1 双轨 → 05 章 `AUDIT SYSDBA`（轨二补留痕）与 08 章 orapw 文件加固（轨二补介质防线）；
- 2.3 "两个根" → 06 章 extproc/OS 轨、08 章 $ORACLE_HOME 文件层，三处合看即"DB-OS 边界地图"；
- 2.4 ASO → 07 章钱包（认证与加密共用同一密钥/证书基建，当年一次采购两笔账）；

## 核心概念速览（中英对照）

- **口令认证** — password authentication：字典存储哈希，默认无复杂度校验。
- **口令文件** — password file（orapwSID）：SYSDBA/SYSOPER 第二套凭据体系，绕过字典。
- **OS 外部认证** — operating system authentication：`ops$` 前缀，OS 身份直映射库用户。
- **信任边界** — trust boundary：字典与 OS 两个根，任一侧宽松即全局失守。
- **VERIFY_FUNCTION** — password verify function：profile 挂载的口令复杂度函数，默认不启用。
- **账户锁定** — account lock（FAILED_LOGIN_ATTEMPTS）：在线爆破限速器。
- **DES 哈希弱点** — weak password hash：用户名作盐的老式存储，离线爆破靶子。
- **Kerberos 集成** — Kerberos authentication：票据替代口令，ASO 选件。
- **双向 SSL 认证** — mutual SSL authentication：证书 DN 映射库用户。
- **RADIUS 一次一密** — one-time password：动态口令网关。
- **Advanced Security Option** — ASO：当年收费的企业认证+传输加密选件。
- **免口令账户** — no-password schema：外部认证+大角色的组合雷。
- **审计回落** — fallback to OS logs：口令文件失败的审计不在 AUD$，在 OS 层。
- **双轨凭据** — dual credential stores：字典与口令文件的对称管理问题。
- **吊销集中化** — centralized revocation：外部认证相对口令库的核心运营红利。

## 最新演进与工业实践

- **哈希线**：11g SHA-1（10 位盐）→ 12c 引入 SHA-512（16 位盐，10G/23C 格式并存），配合 `DBUA_DEFAULT_TBLSPACE` 时代口令管理自动化；11g 起 `SEC_CASE_SENSITIVE_LOGON` 默认 TRUE 纠正了 8i/9i 不区分大小写的历史行为（⚠️ 通说，官方 Security Guide 可复核）。
- **默认策略翻转**：12c 起 DEFAULT profile 带失败锁定与口令有效期；Oracle 推荐脚本从"要不要启用"变成"敢不敢放宽"——方向与 2.2 节正好相反。
- **企业认证现状**：Kerberos/TLSm/统一目录（LDAP/AD、OIDC 经 REST/Data Gateway 网关）仍是主战场，但 ASO 认证功能已并入企业版免费层多年（2017 版价目调整，⚠️ 通说），当年"收费墙"论据已解除。
- **云侧**：Autonomous DB 直接消灭本地口令面（mTLS 钱包强制 + Service API），相当于把 2.4 节"口令不落库"变成唯一形态。
- **工具生态**：口令哈希审计工具（CheckPasswordStrengthForOracle、OAT 后裔、ncrack 在线爆破）把 2.2 的弱点教学变成持续红队服务；CIS Benchmark Oracle Database 的 2.x 节即口令与配置文件清单（⚠️ 名称通识，未附链）。
- **在盘互参**：等保/行业侧口令规范见 [../数据安全架构设计与实战.md](../数据安全架构设计与实战.md)；AAA 框架见 [../CISSP认证考试指南.md](../CISSP认证考试指南.md)。
