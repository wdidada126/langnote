# 07 加密、混淆与数据保护（主题重构章）

> 本章为**主题重构**（原书 TOC 不可达，见 [00 降级声明](00-总览与阅读地图.md)）。Oracle 侧论述 ⚠️ 文档转述；🔧 G4 为 SQLite 文件加密实验，**非 Oracle 行为**。

## 7.1 问题定义：盘上的明文

06 章切开了"链路上"与"盘面上"两题，本章只管后者。⚠️ 8i/9i 的盘面现实：

- 数据文件、重做日志、归档日志、导出转储（`.dmp`）**全部明文**——备份带出库即全库出库；
- 唯一"原生"遮蔽是 `DBMS_OBFUSCATION_TOOLKIT`（8.1.5+ PL/SQL 包，DES 算法）：应用开发者手调加解密列值，无密钥管理、无填充保护（ECB 类使用姿势的密文模式泄露，教科书级坑）；
- 第三方/免费生态：O'Reilly 生态位上的 **DB Obfuscation Tool（DBObfusc）** 类小工具（对指定列做固定密钥 DES 混淆，主打"测试环境脱敏"——本书时代的"masked data"前身）。William Heney 本人长期活跃于 Oracle 安全工具圈（✅ 作者检索旁证），本书的工具生态章由此格外厚。

一句话史观：**TDE（10gR2，2005）之前的世界，列级加密=应用代码的责任**。本章一半篇幅是"前 TDE 时代怎么活"，这决定了阅读时别把 7.2 的方案当今日推荐。

## 7.2 密钥管理：钱包的前世

⚠️ 转述：ASO/Native Encryption 的密钥来源：口令派生（`WALLET` 之前是 sqlnet 参数直给口令的蛮荒）→ Oracle Wallet（`ewallet.p12`，PKCS#12 容器，9i ASO 时代形态渐齐）。钱包承担三件事：本方私钥/证书（SSL 客户端身份）、信任锚（对端证书链）、以及各类秘密的集中存放。安全叙事上钱包与口令文件（02）、监听器口令（6.1）并列为**库外三秘密**——介质都是文件系统上的敏感文件，OS 权限+备份策略即其最后防线（联动 [../Oracle12c数据库应用与开发/03-存储结构-表空间与段区块.md](../Oracle12c数据库应用与开发/03-存储结构-表空间与段区块.md) 的物理层直觉）。

Auto-login wallet（明文伴生 `cwallet.sso`）后来引入"方便但摊开私钥"的取舍——2001 年的读者与 2024 年的读者在此面对的同样是"密钥托管给机器还是给人"的两难，该两难至今以 KMS/HSM 形态存在（演进节）。

## 7.3 🔧 G4：文件级加密实验——passphrase→密钥→密文链的具象化（非 Oracle 行为）

目标：复现"TDE 之前带外加密"的核心链路：口令→密钥派生→整库文件密文化→头魔数消失→凭口令还原。环境 Python 3.13.2 标准库（本网络 pip 超时，故用 `pbkdf2_hmac + HMAC-SHA256 计数器密钥流` 的教学级构造，**非产品级 AES**，诚实标注）：

```python
key  = hashlib.pbkdf2_hmac("sha256", "S3cretPass".encode(), salt, 200_000, dklen=32)
ks   = keystream(key, len(raw))            # HMAC(key, ctr) 串接截断
enc  = bytes(a ^ b for a, b in zip(raw, ks))
open("enc.db","wb").write(salt + enc)      # 盐前置，口令不落盘
```

实测输出（🔧，完整脚本 `D:\develops\tmp\dbwave_w7_orasec\experiments.py`）：

- 明文库直读泄露机密：`G4 plain file leaks secret: True`（`credit-card-4111` 字节可搜）；
- 头魔数 `SQLite format 3\x00` → 加密后 `26 41 2f aa ...`：`G4 encrypted first 16 bytes`；
- 密文文件内机密不可见：`G4 'credit-card-4111' visible in ciphertext file: False`；
- 还原闭环：`G4 roundtrip decrypt -> ('credit-card-4111',) | header restored: True`。

**映射到 Oracle 概念**（⚠️ 侧全部转述）：G4 演示的"口令→KDF→数据密钥→透明覆盖文件"即 10gR2 TDE 的主从表结构（表空间主密钥包裹列/表密钥）的裸形；"备份文件必须与库文件同等级别保护"的 7.1 结论被实验反向证明——未加密的 `.dmp`/备份片正是 `plain.db`。差异也要钉死：Oracle 实装为块级、密钥分层托管、支持 wallet/KSM/HSM 外置，G4 是单层口令、全文件粒度——**教学件不是方案**。

## 7.4 混淆、脱敏与"可用不可见"的三层谱

⚠️+🔧 综合段：按"数据还要不要用"排一个谱：

| 层 | 目标 | 2001 手段 | 现代对应 |
|---|---|---|---|
| 加密 | 授权后还原 | DBMS_OBFUSCATION_TOOLKIT/第三方列加密 | TDE+列加密（ZDK/查询保护） |
| 混淆 | 不可还原但格式可用 | DBObfusc 类固定密钥变形 | 测试数据管理/格式保留加密 FPE |
| 脱敏 | 展示面遮蔽 | 视图列裁剪（04 章即最早的脱敏器！） | DBMS_REDACT 动态掩码 |

视图=2001 年的动态脱敏，这个再诠释是本册与 04 章合读才看得到的点：同一张 `emp_secure` 视图，权限章叫"封装"，本章叫"masking"——机制同一、合规目标不同。

## 7.5 完整性与防篡改的另一半

盘面威胁的另一问是"改"不是"看"：备份被换页、存储层静默腐化。⚠️ 8i/9i 的答案只有块校验和（db_block_check 类参数的前身）与备份介质管理纪律——密码学完整性（HMAC 覆盖页）从未进入内核，直到近年校验/防篡改选件与外部可验证备份（Object Storage 侧签名）才补齐（⚠️ 演进节，勿与本书时代对号）。G4 的密钥流构造若加 `HMAC(salt, ct)` 尾签即是最小完整性演示，留给读者（repo 零产物纪律：写 D:\develops\tmp\）。

## 7.6 加密方案选型五问（本目录提炼的判断框架）

1. **保护谁免受谁？** 链路窃听→06 章传输加密；介质失窃/备份外流→本章盘面加密；DBA 直读敏感列→列级/掩码（7.4 谱）。答案不同层，方案不可互相顶替——方案错配是当年第一多发现象；
2. **性能预算多少？** ASO 全链路 DES/Triple-DES 的 CPU 代价在 2001 年硬件上以两位数百分比计（⚠️ 通说量级），列级只加密高价值列是本书时代的主流折中——7.3 实验里"整个文件一把梭"恰恰是当年做不起的形态，TDE 把它做成做得起的；
3. **密钥死在哪？** 密钥与数据同盘=没加密（G4 若把口令写进脚本即是此反例）；钱包/口令文件/KMS 的托管层级决定恢复演练方案；
4. **可恢复性验证过吗？** "加密的备份从未成功还原"是合规审计的经典尸体——恢复演练必须带密钥轮换后的新样本；
5. **合规勾稽哪条？** 等保/GDPR/PCI 对"存储加密"的条文映射到上面的"保护谁免受谁"，错一格就是审计底稿返工。

## 7.8 前 TDE 时代的四条"土办法"及其死因（⚠️ 史实重构）

1. **应用层列加密**（DBMS_OBFUSCATION_TOOLKIT/自研）——死于密钥进代码+ECB 姿势+索引失效（加密列无法范围查询）；
2. **视图脱敏+权限**（7.4 第三行）——"看"解决了，"备份里仍是明文"没解决；
3. **OS 卷加密**（当年第三方卷产品）——数据库性能塌方+密钥托管给存储管理员，责任三角（08 章）错位；
4. **导出后加密转储**——只治备份一支，盘上数据文件仍裸奔。
四条死因合起来正是 TDE 的产品定义：内核态、密钥分层、转储同密、性能可控。**理解死因比记住功能重要**——这是老书最增值的部分。

## 核心概念速览（中英对照）

- **盘上明文** — data at rest in clear：数据文件/备份/转储全明文的默认态。
- **DBMS_OBFUSCATION_TOOLKIT** — 前 TDE 加密包：PL/SQL 手调 DES，无密钥管理。
- **DBObfusc** — obfuscation utility：本书时代的免费列混淆/测试脱敏工具生态代表。
- **TDE** — transparent data encryption：10gR2 起内核化，主密钥包表密钥，本书未及。
- **KDF/PBKDF2** — key derivation（🔧）：口令拉伸成密钥，G4 实测 20 万次迭代。
- **头魔数** — magic header：`SQLite format 3` 消失=密文形态可验（🔧）。
- **带外加密** — out-of-band encryption：应用/工具层盖文件，TDE 之前的世界形态。
- **钱包** — Oracle Wallet（ewallet.p12）：证书+私钥+秘密的 PKCS#12 容器。
- **库外三秘密** — three file secrets：字典/orapw/钱包（+监听口令）都活在 OS 权限上。
- **FPE** — format-preserving encryption：混淆的现代正规军。
- **动态脱敏** — data redaction：视图列裁剪的合规再诠释（DBMS_REDACT）。
- **可用不可见** — usable-not-visible：脱敏谱的设计北极星。
- **块校验与签名备份** — integrity arms race：盘面"防改"线迟到的补课。
- **教学件不是方案** — lab not production（🔧）：G4 的诚实边界声明。
- **透明加密的"透明"** — transparency scope：仅指应用无感知，不含"免运维"承诺，勿扩大解释。

## 最新演进与工业实践

- **TDE 谱系**：10gR2 表空间加密→11g wallet 分离（`encryption_wallet`）→12c 的 128 位表空间算法与"密钥轮换免重写"→18/19c 大表在线加密迁移（`ALTER TABLE ... MOVEMENT` 式分片在线，⚠️ 特性名以官方文档为准）→23ai 的查询保护/数据最小化族（ZDK 零停机克隆密钥体系、机密计算方向）。
- **列加密与掩码**：`DBMS_REDACT`（12c）、Oracle Big Data 侧 masking 工具、行业 FPE 库（AFL 开源 libFPE 类，⚠️ 名称通识未附链）；测试数据管理（TDM）产品化 7.4 的"混淆"层。
- **KMS/HSM 合流**：钱包外置到 OCI KMS/外部 HSM、"密钥与数据分域"成为云默认（Autonomous DB 即此形态），7.2 的两难被架构消解而非纪律消解。
- **SQLite 侧（🔧 生态）**：SQLCipher 提供产品级页加密（Argon2 KDF+HMAC 完整性，恰为 G4 缺的两件）、Windows EFS/磁盘层加密对应"带外"路线；社区反复实测"备份文件明文外泄"类事故与 7.1 同构。
- **合规条文迁移**：存储加密从"选件决策"变为"默认预期"——审计问句从 7.6① 的"保护谁免受谁"进化为云服务商责任共担矩阵里的行选择；但"密钥死在哪"（7.6③）一问穿越 25 年一字不改。
- **完整性补课现状**：盘面防篡改由 checksum 段头演进到块级校验+签名备份试点（⚠️ 特性细节以官方文档为准），对应 7.5 的迟到线；SQL 注入拖库改密的经典叙事（../白帽子讲Web安全.md）在完整性语境获得第二重解释。
- **在盘互参**：分类分级与加密体系的中文工程语境 → [../数据安全架构设计与实战.md](../数据安全架构设计与实战.md)；物理层文件视角 → [../Oracle12c数据库应用与开发/03-存储结构-表空间与段区块.md](../Oracle12c数据库应用与开发/03-存储结构-表空间与段区块.md) 与其 [12-备份恢复容灾与DataGuard.md](../Oracle12c数据库应用与开发/12-备份恢复容灾与DataGuard.md)（备份=加密的第一客户）。
