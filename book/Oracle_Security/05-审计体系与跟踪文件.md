# 05 审计体系与跟踪文件（主题重构章）

> 本章为**主题重构**（原书 TOC 不可达，见 [00 降级声明](00-总览与阅读地图.md)）。Oracle 侧论述 ⚠️ 文档转述；🔧 G3 为 SQLite 类比实验，**非 Oracle 行为**。

## 5.1 标准审计：三粒度开关

⚠️ 转述（8i/9i）：`AUDIT_TRAIL` 初始化参数四态——`NONE`（出厂默认：零留痕）、`DB`（写 `SYS.AUD$`，需定期归档否则 SYSTEM 表空间撑爆）、`OS`（写操作系统文件，`audit_file_dest` 定位，文件名 `ora_<sid>_<spid>.aud` 式）、以及远古 `TRUE/FALSE` 别名。OS 模式的动机在 02 章已埋：**让 DBA 无法一边作案一边删自己的痕迹**——审计流与数据库写权限分离，是当时唯一的"分权"手段（统一审计+外置收集器出现前的替代解剖）。

三种审计粒度（标准审计模型的全部旋钮）：

1. **语句审计**：`AUDIT TABLE`/`AUDIT INSERT TABLE` 类——按 DDL/DML 语句类型全员记；
2. **权限审计**：`AUDIT ALTER ANY TABLE` 类——盯 03 章 ANY 家族的使用；
3. **对象审计**：`AUDIT SELECT ON hr.emp BY ACCESS`——精确到对象的存取。

修饰符决定体量与语义：`BY SESSION`（默认，会话内同语句折叠一行）vs `BY ACCESS`（逐次记录，取证要的就是它）；`WHENEVER NOT SUCCESSFUL`（只记失败=爆破探测位）。`NOAUDIT` 撤记。9i 新增 `AUDIT SYSDBA/SYSOPER`（把口令文件轨也拖进留痕，02 章双轨闭合）。

## 5.2 AUD$ 的取证解剖与它的天生死角

⚠️ 转述：`SYS.AUD$` 关键列（`USERNAME`/`USERHOST`/`TERMINAL`/`ACTION#`/`RETURNCODE`/`NTIMESTAMP#`/`SQLTEXT` 仅存首 5 字符+长度——**长 SQL 全文不留**是标准审计最被诟病的一点，配套动作是 `AUDIT_TRAIL`+`DBA_AUDIT_TRAIL` 视图族+`ACTION#` 到 `SYSTEM_ACTION_PRIVILEGES` 的编码翻译）。

死角清单（本册第三方视角的重点）：

- **谁来审计审计者**：SYS 的删改 AUD$ 不留痕——`audit_sys_operations=TRUE`（Windows 事件日志/UNIX 审计文件另流）是对该死角的半修：SYS 特权操作强制走 OS 审计流（OS 审计模式与统一审计之间的过渡形态）；
- 共用账户（连接池时代）：`USERNAME` 列只能记到"应用池身份"，自然人归因必须靠应用侧关联键/`CLIENT_IDENTIFIER`（9i 有 `DBMS_APPLICATION_INFO` 置模块名/动作名的雏形，10g 的 `CLIENT_ID` 列才进 AUD$——⚠️ 版本细节标推定）；
- 应用经中间件直连：数据库看到的全部来自一个 IP+一个用户，审计价值趋零；
- 保留与归档：`delete from sys.aud$` 是合规审计必查项，OS 模式/导出归档成为必需流程。

## 5.3 FGA 前夜：从"记流水"到"盯策略"

⚠️ 转述：9i 的 DBMS_FGA（8.1.5 试验性、9i 正式化）以**策略**为单位：`ADD_POLICY(object, policy, audit_condition, audit_column, enable_trigger)`——只有谓词命中的访问才留痕，且写 `FGA_LOG$`，能带 `audit_column` 精确到列。与标准审计的关系是"哨兵 vs 记录仪"：标准审计全量高噪、适合追责期回看；FGA 低噪、适合持续盯敏感对象（04 章的"元数据即机密"列位正是首批部署对象）。许可口径辨析：FGA 属企业版内建、非 ASO 式收费选件（此点各书评常混，⚠️ 以官方文档为准），本目录按内建口径转述。

### 🔧 G3：trace 回调——审计流的最小可玩模型（非 Oracle 行为）

```python
audit = []
con3.set_trace_callback(lambda s: audit.append(s))
con3.executescript("CREATE TABLE audit_demo(...); INSERT ...")
con3.execute("SELECT * FROM audit_demo")
# 实测：G3 trace captured 3 statements: ['CREATE TABLE audit_demo(u TEXT, act TEXT);',
#   " INSERT INTO audit_demo VALUES('app','update x');", 'SELECT * FROM audit_demo']
```

🔧 解读：SQLite 把"每条执行语句交一份给宿主"做成了一个回调——这就是 AUDIT 机制去持久化后的裸形态：无 BY SESSION/BY ACCESS 折叠问题（天然 BY ACCESS）、无保留策略（宿主说了算）、也**无防篡改**（进程内存里，杀进程即毁库外无痕）。对照 ⚠️ Oracle：AUD$/OS 文件/（现代）统一审计文件三层各自解决"折叠、体量、DBA 篡改"一个维度。G3 的教学点：**审计=语句流+持久化位置+信任根**，三者可分离设计——SQLite 只给了第一件，Oracle 三件全有但默认不装。

## 5.4 合规检查单（重构自本册体裁）

1. `SHOW PARAMETER audit` 三参数现状（trail/dest/flush）；`audit_trail=NONE` 直接红牌（01 章"出厂失明"）；
2. 登录成功/失败是否都记：`AUDIT SESSION`；系统权限使用：`AUDIT ALTER DATABASE` 等清单（CIS 2.x 风格基线，⚠️ 名称通识）；
3. 敏感对象对象审计 `BY ACCESS`；`AUDIT SYSDBA`；
4. 保留策略：定期 purge（11g 前手工 delete/truncate，之后 `DBMS_AUDIT_MGMT`——演进节）；
5. 时钟信任：AUD$ 时间戳来自实例 OS 时钟，取证链需 NTP 佐证（与 TOP2e 的事后分析方法共病，互链 [../Troubleshooting_Oracle_Performance_2e/05-不可复现问题的事后分析.md](../Troubleshooting_Oracle_Performance_2e/05-不可复现问题的事后分析.md)）。

## 5.5 网络与存储侧的"审计可见性"

⚠️ 联动预告：06 章（监听器日志 `listener.log` 记录了连接而不记录内容；命名方法影响可归因性）与 07 章（传输加密后中间设备失明→审计价值向 DB 端集中）。留痕三角：**DB 审计流 + OS/网络元数据 + 应用关联键**，缺一角则对应类别的事件不可归因——2001 年本书用整章工具箱强调此三角，至今仍是 SOC 建设的老话。

## 5.6 当年已知的"审计旁路"清单（⚠️ 转述+社区清算，攻方细节留给 #51）

| 旁路 | 原理 | 半修 |
|---|---|---|
| SYS 删 AUD$ | 审计数据与审计者同库同权 | OS 模式+audit_sys_operations |
| 直连共享池外通道 | 静态 SQL 之外的执行（DBMS_JOB 内跑）语句审计口径不一 | 权限审计盯 CREATE JOB |
| 字典即目标 | 改规则先改参数：把 pfile 里 `audit_trail` 改回 NONE（重启才全效，但窗口存在） | 审计 ALTER SYSTEM 与重启事件本身 |
| 应用池归因失效 | USERNAME 只有池身份 | DBMS_APPLICATION_INFO 约定（5.2） |
| 时间源污染 | 主机时钟改=整条时间线失真 | NTP+日志交叉（5.4⑤） |

读法：这张表就是"谁来审计审计者"的五种具体形态——统一审计+外置收集+不可变存储（WORM/对象锁定）三件现代武器分别压住前三行（演进节）。

## 5.7 一条审计记录的旅程（把参数表讲成时间线，⚠️ 重构）

1. **连接建立**：监听器日志记 IP/程序（06 章网角）→ 认证结果进/不进 AUD$（口令文件轨默认不进，02 章双轨；`AUDIT SYSDBA` 开启后才有）；
2. **登录审计**：`AUDIT SESSION` 产生 CONNECT/DISCONNECT 一对行，含 `USERHOST/TERMINAL/LOGON_PML`（失败带 RETURNCODE=1017——爆破画像的原料，`WHENEVER NOT SUCCESSFUL` 时只留这半对）；
3. **语句执行**：按三粒度开关逐条判定是否落行；`BY SESSION` 折叠让"改了一次工资"与"改了一百次"在账面上等价——取证必读列务必看此修饰符；
4. **DDL 特权面**：`AUDIT DATABASE`/权限审计盯 `ALTER SYSTEM` 等"改规则本身"的动作——审计体系自保的关键条目；
5. **断开与冲刷**：`audit_file_dest` 侧 OS 文件按服务器进程(spill)切分、`noaudit` 生效后历史仍在；DB 模式下 AUD$ 增长曲线=容量规划输入（SYSTEM 表空间字典回滚段邻居，性能册语境）。

把这条旅程读通，5.4 检查单上每个参数都能回答"它守的是旅程哪一站"。

## 5.9 审计参数速记卡（⚠️ 9i 口径，供 5.4 检查单配套）

- `audit_trail`：NONE|DB|OS（TRUE/FALSE 为远古别名）；改动需重启（pfile 时代）；
- `audit_file_dest`：OS 模式落点，OS 权限即审计权限（08 章文件层联动）；
- `audit_sys_operations`：TRUE 时 SYS 自身操作强制 OS 流——"半修"的主开关；
- 常用审计语句三连：`AUDIT SESSION;`、`AUDIT <敏感对象> BY ACCESS;`、`AUDIT ALTER ANY TABLE BY ACCESS;`
- 视图族：`DBA_AUDIT_TRAIL`（可读版 AUD$）、`DBA_AUDIT_EXISTS`（双查提示）、`DBA_FGA_AUDIT_TRAIL`（9i）；
- 体量直觉：`BY ACCESS` 全开的大流量库，AUD$ 日增可达百万行级（⚠️ 量级通说）——"该记的 BY ACCESS、不该记的不记"是策略核心。

## 5.10 五分钟口述版（电梯陈述，供复讲自校）

"Oracle 出厂不留任何痕迹（AUDIT_TRAIL=NONE）→ 打开后有三档粒度（语句/权限/对象）和两种落点（DB/OS），OS 落点专防 DBA 自己删账；SYS 轨要 audit_sys_operations 补洞；SQL 全文与池化归因是两个天生死角，当年用触发器和 FGA 硬凑，统一审计+外置 SIEM 之后才算闭合。"——能一口气说完这段，本章即过关（⚠️ 全段版本口径同正文）。

三个关键词的从属关系再钉一遍：**开关**（参数）→ **粒度**（三审计+修饰符）→ **落点**（信任根选择）。5.9 节速记卡是前两格的手册，5.6 旁路表是第三格的反面教材。

## 核心概念速览（中英对照）

- **AUDIT_TRAIL** — audit trail location：NONE/DB/OS（+远古 TRUE），默认 NONE=失明。
- **AUD$ / FGA_LOG$** — audit tables：留痕的两个落点，删改它们是必查项。
- **语句/权限/对象审计** — statement/privilege/object auditing：标准审计三粒度。
- **BY ACCESS / BY SESSION** — audit granularity modifier：逐次 vs 折叠。
- **WHENEVER NOT SUCCESSFUL** — failure-only audit：爆破与越权尝试探测器。
- **AUDIT SYSDBA** — privileged-session auditing：把口令文件轨拖入留痕（9i）。
- **audit_sys_operations** — SYS self-audit escape：SYS 操作强制走 OS 流，破"谁审计审计者"。
- **SQLTEXT 截断** — sql text truncation：AUD$ 不存全文的老缺陷。
- **DBMS_FGA** — fine-grained auditing：策略谓词命中的哨兵式审计（9i 正式化）。
- **trace 回调** — trace callback（🔧）：SQLite 语句流裸模型，审计三要素教学件。
- **关联键** — correlation key：池化连接下的自然人归因（CLIENT_IDENTIFIER 雏形）。
- **审计保留** — retention/purge：容量与合规的平衡，DBMS_AUDIT_MGMT 前史。
- **时钟信任根** — time trust：时间戳取证依赖 NTP 佐证。
- **留痕三角** — evidence triangle：DB 流+网络/OS 元数据+应用关联。
- **出厂失明** — blind by default：NONE 默认值在合规语境的红牌地位。

## 最新演进与工业实践

- **统一审计**：12c 引入 Unified Auditing（`ORA$BASE` 策略、QUARTZ/纯模式迁移期），AUD$/FGA/OS/RMAN/Data Pump 流合并入 `UNIFIED_AUDIT_TRAIL`；12.2/19c 纯统一审计成为默认方向（⚠️ 通说，官方升级指南可复核）——5.2 的"多落点"死角基本闭合。
- **云与集中化**：Oracle 侧 Audit Vault and Database Firewall（收购产品，2012+）与 OCI Audit Monitoring 把留痕外送到独立信任域；工业实践主流是 Filebeat/Fluent Bit→SIEM（Splunk/ELasticsearch 线），"DBA 删不了"从 OS 审计文件模式升级为网络分段问题（⚠️ 通说）。
- **全文 SQL 留存**：现代策略普遍在 DB 侧只留摘要+在外围（DB Firewall/代理，如 Query Monitor 类产品）留全文，回应 5.2 的 SQLTEXT 截断。
- **SQLite 侧（🔧 生态）**：`set_trace_callback`/`sqlite3_stmt_status` 是宿主审计标准件；加密+审计的组合在 sqlcipher 生态有实现；本目录 G3 脚本可直接改造为 SQLite 版"BY ACCESS 日志器"（repo 零构建产物纪律：改造件请写 D:\develops\tmp\）。
- **在盘互参**：事后取证方法论对照 [../Troubleshooting_Oracle_Performance_2e/05-不可复现问题的事后分析.md](../Troubleshooting_Oracle_Performance_2e/05-不可复现问题的事后分析.md)；合规框架底座 [../CISSP认证考试指南.md](../CISSP认证考试指南.md)；攻方视角的审计绕过（DBHH 对 AUD$ 篡改史）登记于 00 §四 #51 双线。
