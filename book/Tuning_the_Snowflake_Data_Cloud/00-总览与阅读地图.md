## 6. 实测纪律与 🔧 类比实验总表（本机，非 Snowflake 平台行为）

Snowflake 为云托管产品，**本机不可实测**：全部机制描述为官方文档转述 ⚠️（URL 逐条验证见第 8 节）。
概念类比用本机 **DuckDB 1.5.5（Python 包）/ SQLite 3.45.3（Python 内置）** 实测 🔧，脚本落盘
`D:\develops\tmp\dbwave_w8_snowtune\exp.py`（repo 零构建产物），结论一律标注**「非 Snowflake 平台行为」**。

| # | 实验 | 结果（实抓数字） | 类比对象 → 落点章 |
| --- | --- | --- | --- |
| E1 | 8M 行表按 k 排序 vs hash 打乱，窄区间谓词 `k BETWEEN` 读真实列（sum(v)+max(p)）×5 取最优 | 有序 **2.2ms**，乱序 **25.3ms**（≈11×），全表扫描 62.7ms | min/max zone-map 剪枝 ↔ 微分区裁剪/聚簇深度 → 04/05 章 |
| E2 | DuckDB `SET threads=1/8`，20M 行分组聚合 | 3.79s → **0.53s**（≈7.2×） | 仓库尺寸=并行分片数 ↔ Scaling Up → 06/08 章 |
| E3 | SQLite UPDATE 就地覆盖实证（`(1,100)`→`(1,150)` 旧值不可回查）；历史表 valid_from/valid_to 模拟 as-of 查询 | 原生**无**时间旅行，模拟可行 | Time Travel/Zero-Copy 元数据版本对照 → 01 章 |
| E4 | 200k 行点查：无索引 7.7ms → 建 `INDEX ix` 后 **0.05ms**（≈150×） | 二级索引加速点查 ↔ SOS 补 Snowflake「无索引」短板 → 07 章 |
| E5 | 同一随机谓词查询连续 3 次 | 7ms→6ms→4ms（本地缓存升温） | 仓库本地磁盘/结果缓存 ↔ warehouse cache → 06 章 |
