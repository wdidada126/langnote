## 核心精讲

### 12.1 工作量证明：把身份换成成本

```
教学示意，不参与构建
// 问题：开放网络里任何人都能造一堆身份（Sybil 攻击）
//       基于「一个身份一票」的共识（PBFT 的 3f+1 假设）立刻失效
// PoW 的解法：投票权 = 算力占比，伪造身份不能增加算力
//
// 形式化：给定区块头 H 与难度目标 target
//   找 nonce，使得  hash(H || nonce) < target
//   hash 无结构性 -> 只能暴力枚举 -> 期望尝试次数 ≈ 2^256 / target
//   验证却只需要一次 hash -> 求证昂贵、验证廉价（这就是「证明」的含义）
```

源头不在比特币：

- **Dwork & Naor《Pricing via Processing or Combatting Junk Mail》**（CRYPTO 1992，期刊版 Journal of Cryptology 1993）
  提出用**计算代价**抑制垃圾邮件，是 PoW 的最早文献；
- **Back《Hashcash - A Denial of Service Counter-Measure》**（2002）给出可用的 hashcash 方案；
- **Nakamoto《Bitcoin: A Peer-to-Peer Electronic Cash System》**（2008）把它变成**共识机制**。

### 12.2 区块链的 PoW 实现

```
教学示意，不参与构建
// 区块结构（简化）
block = {
    prevHash,        // 指向父区块 -> 形成链
    merkleRoot,      // 本区块交易的 Merkle 根
    timestamp, nonce,
    difficulty       // 编码进 bits，决定 target
}
// 挖矿循环
while true:
    if sha256d(blockHeader(nonce)) < target:
        broadcast(block); break
    nonce += 1            // 用完就改 coinbase 的 extraNonce 或时间戳
// 难度调整：每 2016 个区块（比特币约两周）按实际出块时间重新校准
//   目标：平均 10 分钟出一个块
// 链选择规则：最长（累计难度最大）的链为有效链
```

**为什么「最长链」规则是安全的**：

- 攻击者要改写某个已确认区块，必须**从它的父块开始重新挖一条更长的链**；
- 若诚实算力占多数，攻击者追上的概率随确认数**指数下降**；
- 这就是「6 个确认」惯例的由来——它是**概率性最终性**，不是确定性最终性。

**51% 攻击**（本书 12.2 的核心反例）：

```
教学示意，不参与构建
// 攻击者算力 > 50% 时可以：
//   1. 双花：给商家发一笔交易并拿到货，同时私下挖一条不含该交易的更长链并发布
//   2. 审查：拒绝打包特定交易
// 做不到的是：
//   - 伪造他人签名（密码学保证）
//   - 凭空造币（会被其他节点按规则拒绝）
// 代价：算力租赁成本 + 币价下跌带来的自损
```

### 12.2 补充：分叉与确认（为什么「等 6 个块」）

```
教学示意，不参与构建
// 两个矿工几乎同时找到合法 nonce -> 全网短暂存在两条同长链（分叉）
//   规则：节点各自在自己先看到的那条链上继续挖
//   一旦某条链先长出下一块，它变长 -> 另一条被丢弃（orphan）
//   被丢弃的块里的交易回到 mempool 等待重新打包
// 因此「一笔交易在最新块里」并不等于「已确定」：
//   它还可能被重组（reorg）掉
//   它上面每多一个块，被重组的概率就指数下降
//   -> 比特币社区的经验值：6 个确认
// 工程含义：交易所/钱包的入账确认数就是这么来的，它是一个**风险阈值**而非协议规则
```

### 12.2 补充：难度调整的作用

```
教学示意，不参与构建
// 若算力持续增长而难度不变 -> 出块越来越快 -> 分叉率上升、安全性下降
// 比特币：每 2016 个区块按实际耗时重新校准难度，目标平均 10 分钟/块
//   new_target = old_target * (actual_time / expected_time)
// 作用：让「出块速率」与「全网算力」解耦
// 这也是 PoW 与 PBFT 的一个根本差别：
//   PBFT 的吞吐由网络与节点数决定；PoW 的出块速率由**难度参数**人为钉住
```

### 12.3 PoW 的定位：与前面所有协议的对照

| 协议 | 故障模型 | 身份假设 | 最终性 | 成员规模 |
| --- | --- | --- | --- | --- |
| Paxos / Raft / ZAB | CFT | 已知、授权 | **确定性** | 数十 |
| PBFT | BFT | 已知、授权（许可） | **确定性** | 数十~百 |
| **PoW** | BFT | **开放、无许可** | **概率性** | 数万 |
| PoS | BFT | 开放（持有权益） | 确定性（有检查点） | 数千~万 |

PoW 真正解决的问题是：**在没有任何身份准入的开放网络里，也能就历史达成一致**。
这是前面所有协议都不处理的场景，因此它不是「更好或更差的 Paxos」，而是**另一类问题**。

## 版本演进

- **1992 / 1993**：Dwork & Naor 提出用计算代价抑制滥用（CRYPTO 1992 / Journal of Cryptology 1993）。
- **2002**：Adam Back 的 Hashcash。
- **2008**：中本聪白皮书《Bitcoin: A Peer-to-Peer Electronic Cash System》，把 PoW 变成共识机制。
- **2011 前后**：人们意识到**矿池集中化**与 **ASIC 专业化**会侵蚀 PoW 的去中心化假设。
- **2014 起**：**PoS（权益证明）**研究兴起；以太坊长期规划 Casper。
- **2022-09**：**以太坊完成 The Merge**，从 PoW 正式切换到 PoS——这是本书出版（2022-08）之后一个月发生的事，
  **本书不可能覆盖**，是本章最需要补的 2026 视角。
- **2022（本书）**：第 12 章（3 节）用「如何理解工作量证明 / 区块链如何实现 / 小结」讲清了挖矿原理与 51% 攻击，
  定位是科普而非工程（读者不会去实现 PoW）。
- **2026 视角**：
  - **比特币仍用 PoW**（`bitcoin/bitcoin`，**90251★**），能耗争议持续；
  - **以太坊已于 2022-09 转向 PoS**，PoW 不再是「区块链共识的默认答案」；
  - 能耗讨论从技术议题变成**政策议题**（部分司法辖区对 PoW 挖矿有监管限制）；
  - 企业场景几乎不用 PoW：许可链用 **Raft / PBFT / HotStuff 系**。

## 近年研究与工业界开源实践（2015–2026）

- **近年研究**：
  - **比特币主干协议的形式化**（Garay et al. EUROCRYPT 2015；Pass et al. EUROCRYPT 2017）把「51%」这一通俗说法变成可证明的定理；
  - ** selfish mining**（Eyal & Sirer, 2014 起）指出即使算力 < 50% 也可能获得超额收益，是 PoW 激励层的重要批判；
  - **PoS 的正式化与落地**（Ouroboros CRYPTO 2017；Casper FFG）在 2022 年以太坊合并后成为主流研究方向。
- **工业界开源**（star 数 2026-09 `gh api` 实测）：
  - `bitcoin/bitcoin`（**90251★**）：唯一仍在大规模使用 PoW 的主流公链参考实现；可作为本章 12.2 的源码对照。
  - `hyperledger/fabric`（**16732★**）：**企业场景的真实选择**——许可链 + Raft/PBFT 系，不用 PoW。
  - `etcd-io/etcd`（**52310★**）：企业内部业务的真实选择（CFT），提示 PoW 的适用面极窄。
  - `jepsen-io/jepsen`（**7504★**）：**不测试区块链共识**；区块链系统的评估应看其公开的形式化证明与审计，而非 Jepsen。
- **以太坊合并（2022-09）**：共识层从 PoW 切到 PoS，能耗下降幅度巨大；
  这是本章必须标注的**书外事实**——本书出版于 2022-08，早于合并一个月。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「PoW 是 PBFT 的改进版」 | 不是。PoW 解决的是**无许可**网络的共识（身份可自由伪造），PBFT 需要**许可**成员 |
| 2 | 「51% 算力能伪造交易」 | 不能伪造签名。51% 能做到的是**双花**与**审查**，不是凭空造币 |
| 3 | 「6 个确认 = 绝对安全」 | 是**概率性**最终性；比特币没有确定性最终性，PoS 系才有检查点最终性 |
| 4 | 「PoW 就是算 hash」 | 「算 hash」只是手段；本质是把**投票权绑定到不可伪造的外部成本** |
| 5 | 🔧 2026 补丁：以太坊已转 PoS | 本书 2022-08 出版，**2022-09 以太坊完成 The Merge**。2026 年的现实是：PoW 主要只剩比特币，公链新项目基本都走 PoS。本章的「区块链 = PoW」印象必须修正 |
| 6 | 🔧 2026 补丁：矿池集中化与 ASIC 的影响 | 本书 12.2 未讨论，但现实中算力集中在少数矿池，「51%」的威胁模型实际上是「少数矿池合谋」。这是评估 PoW 安全性的关键前提 |
| 7 | 🔧 2026 补丁：能耗议题已进入政策层面 | 本书未涉及。2026 年 PoW 的争议主要在**能耗与监管**而非技术正确性；企业在选择时应把合规成本计入 |
| 8 | 🔧 2026 补丁：企业场景不适用 PoW | 本章讲的是公链机制，读者若把它套到企业系统会造成严重过度设计。企业场景用 **Raft（CFT）**或 **PBFT/HotStuff 系（BFT）**，见 [09-PBFT算法](09-PBFT算法.md) |
