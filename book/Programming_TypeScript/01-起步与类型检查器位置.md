## 核心机制

- **一句话定位**：TS = JS + 一层只在编译期存在、emit 时全数剥除的类型注解。本章在全书中的真正贡献不是语法教学（Learning TS 已覆盖），而是**第一次点破「检查器位于何处」**：校验发生在 `tsc`/编辑器，产物落地运行时后检查器即死。
- 类型注解三态：初始可省（推断）、显式标注（`x: T`）、断言（`as T`）——断言是**向检查器撒谎**，不产生任何运行时转换或检查（专题公理 2，✅ 机制面见 02 章实验 as-lie）。
- 「编译」一词的戒律：TS 官方口径是 **transpile（转译）+ type-check（检查）两条独立工序**。转译器逐 token 删注解，不理解类型；检查器逐节点判 assignability，不产码。两工序各自可单独失败——这是理解后面一切「为什么运行时炸了编译没红」的钥匙。
- 作者谱系注记：Boris Cherny 是 ts-morph 作者——**AST 级工具视角**贯穿其后续写作（⚠️ 以版权页/自述为准）。

## 批判读法

- 本章叙事暗含「TS 是静态语言」的舒适错觉。反读法：把每段语法样例都在脑内跑一遍「删掉冒号后还剩什么 JS」，剩不下东西的都是纯检查器现象。
- 书中早期对 tsconfig `strict` 阶梯（`noImplicitAny`/`strictNullChecks`/`strictFunctionTypes`）着墨轻，但**00 总览判定本书一切后续章的语义都是 flag 依赖的**——不配 strict 读全书会得出错误的「类型系统规律」。
- 与 Tackling TS 的分工：那边讲「为什么该有类型」论述线，这边讲「检查器怎么运转」机制线；Ⅰ 部重叠面大，可 20 分钟速过（00 读法条已裁定）。

## 🔧 微实验

实验 1 ✅（node v22.14.0 `--experimental-strip-types`，`/tmp/tsexp/e1_erase.ts`，exit=0）：注解删除是**逐 token 语法行为**，非类型导向改写——`Function.toString()` 在运行时打印的构造函数体里注解已消失，但参数名、体结构原样保留：

```ts
class Box { value: number = 1; constructor(v: number) { this.value = v; }
  scale(f: number): number { return this.value * f; } }
console.log(Box.prototype.constructor.toString());
```

实测输出：`class Box { value = 1; constructor(v ) { this.value = v; } scale(f ) { ... } }` ——注意 `v` 后留有空格残迹：删的是 token，不是重排版。

实验 2 ✅（`/tmp/tsexp/e2_enum.ts`）：`enum Color { Red, Green }` 在 strip-only 模式直接 SyntaxError（`ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX: TypeScript enum is not supported in strip-only mode`，exit=1）——**enum 是「会产码的类型层语法」的界碑**，与纯擦除语法（type/interface/注解）分属两个物种。呼应专题第 4 条戒律，该条 ⚠️ 待补实测就此销账。

不可实测位 ⚠️：本章若谈「类型错误长什么样」需 `tsc`，本机无独立 tsc，禁引用其输出为实测。
