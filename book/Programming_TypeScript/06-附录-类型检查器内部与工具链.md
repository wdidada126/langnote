# 《Programming TypeScript》章笔记 06 · 附录：类型检查器内部与工具链

> 对照骨架部号：**Ⅵ Appendix**（⚠️ 部名/附录标题凭记忆；00 总览定位「类型检查器内部、编译器配置——实现线第一块砖」）。
> 书 2020 年止：其时编译器为 TS 4.0 世代；本档以书内口径为主，Node 原生 strip-types 属**超书范围**的当代实测载体（只证运行时边界，不代书立说）。

## 核心机制

- **编译器流水线**（通行口径 ⚠️ 非逐字引书）：`parse → bind → check → emit` 四段。parse 产 AST；bind 建符号表（Symbol/Node 双图）；check 跑 assignability 关系机器；emit 才轮到擦除+降级。**擦除发生在 emit，且 emit 不理解类型**——01 章「转译/检查两工序」的实现层展开。
- **assignability 机器**：`isTypeAssignableTo(S, T)` 递归下降；02 的 ⊆ 表、03 的逐属性判决、04 的 method 标志位豁免，最终都汇成这一个关系函数+其缓存。附录价值=把「语言规范读感」转成「实现可读感」：TS 语义的真相住在 checker 代码里，规范文档是判例集。
- **lib.d.ts 与 ambient 层**：标准库类型（含 05 章五件套）是**用同一语言写的声明文件**——`Partial<T>` 不是运行时对象，checker 眼里它只是普通类型级函数。三层世界：语法（checker 硬编码，如 `keyof`）/ 库级体操（lib.d.ts 编码）/ 值层（JS 本尊）。
- **工具链面**：`tsc` 命令行与 tsconfig（`include/exclude/types/paths` 决定 Program 的建图范围）；`declaration` 输出（.d.ts）=把结构子类型签名序列化，是跨包检查的货币。作者 ts-morph 背景注记：check 段 API 化后才有 AST 级重构工具——**checker 既是库也是产品** ⚠️ 谱系说法以版权页为准。

## 批判读法

- 附录通常薄（书中亦以鸟瞰为度 ⚠️ 页序未销）——正确用法是当**跳板**而非教材：每个附录名词（Program/Symbol/Type/Checker）到 TypeScript_Compiler_Notes 或官方 `compiler/` 源码找对应实体再回头。
- 2020→今的差集要显式记账：书出后业界剧变位——TS 5.x Go 原生重写编译器（提速面）、Node 22.6+ 原生类型剥除、装饰器标准化——**全部超书范围**；但「类型只在检查器存在、emit 只擦不查」的公理反而被 Node 时代实证得更狠（见实验）。
- 对 C++ 读者的镜像问题：「clang 的 Sema 阶段 vs TS checker」——同为独立于代码生成的语义层，差别在 clang 检查后仍要为留存类型信息付 AST/调试格式成本，TS 检查完信息全弃。擦除「彻底度」的两语言刻度，回链专题第二节。

## 🔧 微实验

实验 1 ✅（`/tmp/tsexp/e8_stack.ts`，node v22.14.0 `--experimental-strip-types`，exit=0）：类型层代码的运行时故障**精确回指 .ts 源位置**——剥除保持行列位，调试器看到的是你的文件：

```ts
type Cfg = { strict: boolean };
function check(c: Cfg): number { return (c as any).missingFn(); } // 第 2 行起算
try { check({ strict: true }); } catch (e) { console.log((e as Error).stack.split("\n")[1].trim()); }
```

实测输出帧：`at check (C:\Users\wdidada\AppData\Local\Temp\tsexp\e8_stack.ts:3:21)`——注解行号在栈里原样存活；「擦除≠位置丢失」的工具链证据。

实验 2 ✅（`/tmp/tsexp/e2_enum.ts` 双模式复演）：同一文件，`--experimental-strip-types` 报 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`（exit=1），`--experimental-transform-types` 正常跑出 `0`（exit=0）——**「产码语法 vs 纯擦语法」的分界线被 Node 两种模式物理化**；`--experimental-transform-types` 为超书范围机制，本条同时销专题第 5 节 ⚠️ 待补项。

不可实测位 ⚠️：checker 内部（关系缓存、符号表）无法经运行面观测，且本机无独立 tsc/无 npm 授权——一切「报错文本/诊断信息」类断言只登记预期。
