# 《Programming TypeScript》章笔记 03 · 对象、接口与结构子类型

> 对照骨架部号：**Ⅲ Objects and Interfaces**（⚠️ 章名凭记忆；本档题名为仓内切分）。
> 书 2020 年止：`#private`（JS 原生硬私有，3.8 前后）、template literal 键（4.1）等**超书范围**；接口 vs 类型别名的社区后续共识不回填本书口径。

## 核心机制

- **结构子类型判定流程**（本章心脏，可写成算法）：`S` 可赋给 `T` ⟺ `T` 的每个必选属性在 `S` 中有**可赋的子类型**对应物。没有名字参与判决——这是与 Java「看继承声明」的名义子类型的机制级分岔。
- **interface vs type alias**：书内分工≈「对象形状优先 interface（可声明合并、错误信息更友好），其他一律 type」。声明合并是双刃剑：库 augmentation 靠它，事故也靠它（同名意外合并 ⊥ 全局形状）。
- **可选属性 `?` 的真身**：`{ x?: number }` = `{ x: number | undefined }`（且叠加 `undefined` 可省略的读写不对称）——可选性是**属性级 ∪**，回链 02 代数表。
- **freshness（超额属性检查）**：仅对**新造对象字面量**直接赋给目标类型时生效；先存变量再赋即绕过。机制上是一条独立于结构子类型的「字面量新鲜度」规则——书中作为便利讲，反读法：这是**防止笔误的启发式**，不是类型系统定理，别指望它防住运行时脏属性。
- `readonly`：浅层只写守卫，数组/嵌套对象内部照改；`{ readonly [K in keyof T]: ... }` 深只读要手写（映射类型，05 章）。
- **class + `implements`**：`implements Named` 只是「让检查器按结构验收一遍类的形状」的**声明**，不给原型链加任何运行时关系。
- 泛型约束 `T extends U` 即把 02 的 ⊆ 谓词挂到形参上；C++20 概念约束 `requires C<T>` 是同位物，区别在 C++ 要先具名概念，TS 的「概念」就是匿名结构类型本身（鸭子类型的静态化）。

## 批判读法

- 「结构 = 集合」在对象层最真、也最脆：宽度子类型（多属性可以）与深度可变性（04 章方法双关）互相拆台。读书时自问：这条 assignability 是检查器哪条规则放的行——freshness？浅比较？递归到属性？
- 书中 class 一章的 Java/C++ 味道（讲继承层次）与本系列「prefer composition」后续共识相左——把 class 内容当「JS 原型桥的语法糖说明书」读，类型层价值只在 implements/泛型类两处。
- 与专题公理合读：`private`（TS）运行时字段照在、`#hard` 才是硬墙——类设计条目重灾区在擦除专题有实测记录，本章只需登记对偶。

## 🔧 微实验

实验 ✅（`/tmp/tsexp/e5_struct.ts`，node v22.14.0 `--experimental-strip-types`，exit=0）：三件事一屏看全——宽于接口的对象照常通过（结构子类型=运行时无关的检查器判决）；接口名在运行时命名空间**不存在**；`implements` 在原型上**零痕迹**：

```ts
interface Named { name: string }
const greet = (x: Named): string => "hi " + x.name;
const obj = { name: "a", age: 9, secret: true }; // 超额属性：变量间接路径
class C implements Named { name = "c"; }
console.log(greet(obj), "|", typeof Named, "|",
  Object.getOwnPropertyNames(C.prototype), C.prototype.constructor.name);
```

实测输出：`greet: hi a | interface-at-runtime: undefined | implements-trace: [ 'constructor' ] | proto: C`——`Named` 连个值都不曾存在，`undefined` 是字面意义。

不可实测位 ⚠️：freshness 对字面量直赋的报错、缺属性报错——检查器面，无 tsc 不引为实测；补配对表见专题第 5 节。
