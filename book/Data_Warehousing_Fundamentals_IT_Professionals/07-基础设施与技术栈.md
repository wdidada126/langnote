# 07 基础设施与技术栈（Infrastructure as the Foundation for Datawarehousing）

> 原书：Data Warehousing Fundamentals for IT Professionals, 2nd Edition（Ponniah，Wiley 2010，ISBN 9780470462072）
> 第 8 章，pp.163–192 ✅（Crossref `...ch8` + Wiley 目录）。精读重构：节题/页码 ✅，论述转述 ⚠️；
> 本章示例引擎面（Oracle/SQL Server/DB2 等商用 RDBMS）本机不可复现——一律 ⚠️，🔧 类比集中在建模/ETL 各章。

## 1. 章节定位

Part 3 第二章：把 06 文件的技术剖面落成**采购单**。硬件/OS/数据库软件/工具集/appliance 五节即 2010 年
数仓基础设施的完整货架。本章是全书"时代感最强"的一章（2026 货架整体换代），但其**选型维度**
（容量/吞吐/可用性/技能/成本五轴）一字未变——读法：货架当史料，维度当工具。

## 2. 逐节精读（✅ 节题源自 Wiley 目录）

### 2.1 Infrastructure Supporting Architecture（支撑架构的基础设施，p.164 ✅）

- 总纲 ⚠️：基础设施 sizing 由三个架构参数决定——装载吞吐窗口、查询并发画像、数据保有规模；
  三者分别回收 ch12（ETL 节奏）、ch14（交付矩阵）、ch6 的存储规格推导（本册 05 文件）。
- 教材的容量公式骨架 ⚠️：规模≈Σ(源行数×粒度×保留期×膨胀系数)+索引/临时/装载峰值余量——
  2010 年"×2~×3 拍脑袋系数"在云仓时代变成"按账单观测回填"。

### 2.2 Hardware and Operating Systems（硬件与操作系统，p.166 ✅）

- 2010 货架 ⚠️（转述）：对称多处理/早期多核、SAN/DAS 之争、RAID 条带与镜像换吞吐换可靠；
  64 位 OS 成为分析服务器标配；内存开始成为"列存/缓存"的第一瓶颈资源。
- 教材判词 ⚠️：数仓硬件三问——IO 带宽够不够装载窗口、内存够不够哈希聚合、扩展性够不够三年增长；
  三问在 2026 变成云仓选型三问（对象存储吞吐/Credit 规格/自动扩展），骨架同构。

### 2.3 Database Software（数据库软件，p.181 ✅）

- DBMS 选型维度表（回收 05 文件 DBMS Selection ✅）：SQL 完备性与扩展（分区/物化视图/OLAP 函数）、
  装载工具链、复制/高可用、平台与技能生态、许可成本 ⚠️。
- 行存 vs 列存之争正发生在此章年代 ⚠️：列存以压缩比+扫描谓词下推取胜于分析负载，行存保留于
  混合负载边缘场景——本章立场是"按查询画像选，别按信仰选"。
- ⚠️ 不可实测登记：教材示例多取自 Oracle/SQL Server 系商用引擎，本机零新装纪律下不复现其
  分区/物化语句；概念面以 🔧E1/E1b（星型 join 与预聚合）、🔧E2（雪花 vs 星型）代替演示（见 00 第 6 节）。

### 2.4 Collection of Tools（工具集，p.184 ✅）

教材八类工具货架（与 ch9 元数据/ch12 ETL/ch14 交付三章互为目录）⚠️：ETL 套件、质量剖析、元数据管理、
报表、 ad-hoc 查询、OLAP 客户端、挖掘工作台、门户调度。
- 集成度警告 ⚠️：工具越多→粘合剂代码越多→元数据总线越必需；本书倾向"少而衔接良"。

### 2.5 Data Warehouse Appliances（数仓一体机，p.188 ✅，第 2 版新增主题 ✅ Wiley 页）

- 一体机=列存引擎+专用硬件+调优捆绑的交钥匙形态（2008–2012 热潮）⚠️；教材给三评：上市快、
  单负载极致、但价格锁定与扩展天花板。
- **2026 判词** ⚠️：该赛道整体被云仓+开放表格式吞并——本章恰成 appliance 兴衰的一手史料（对位
  03 文件 2.4 节）。

## 7. 选型五轴评分卡模板（⚠️ 本册依 ch8 节题域编制，权重自调）

| 轴 | 评项示例 | 一票否决位 |
|---|---|---|
| 性能 | 装载吞吐窗/聚合延迟/并发画像 | 过不了夜间窗口 |
| 容量与增长 | 三年规模×膨胀系数 | 触扩展天花板 |
| 技能生态 | 团队存量/招聘市场/文档 | 无人会运维 |
| 工具链 | ETL/质量/BI 亲和与粘合成本 | 关键件缺位且不可插件 |
| 总拥有成本 | 许可+硬件+人力+培训 | 预算×1.5 仍不够 |

- 2026 增轴建议 ⚠️：账单可观测性（finops 友好）与开放格式支持度（不被锁定）——教材五轴直接扩为七轴。
- 行存/列存速判 ⚠️：谓词命中列数/总列数比值高→行存友好；比值低+重复值多→列存甜点（压缩+下推双收）。
- appliance 史料读法 ⚠️：把 2.5 当"技术经济学"案例：交钥匙省的是集成人力，付的是扩展与议价权——
  云厂商今日"托管全家桶"仍在同一权衡曲线上。


- 选型自查三问 ⚠️（本册归纳）：一问团队技能存量，二问数据体积与增速斜率，三问粘性成本（出栈费/迁移费/锁定年限）；三问皆平才谈性能分。
- 对读提示：基础设施"堆栈分层"叙述与 [../Building_the_Data_Warehouse/00-总览与阅读地图.md](../Building_the_Data_Warehouse/00-总览与阅读地图.md) 第 4 章硬件取舍互为 1995/2010 两代版本，差异点在云化摊销。
## 核心概念速览（中英对照）

| 英文 | 中文 | 一句话释义 |
|---|---|---|
| sizing | 容量定标 | 以装载/查询/保有三画像定硬件规格 |
| RAID striping/mirroring | RAID 条带/镜像 | 吞吐与可靠的互换手段 |
| row store / column store | 行存/列存 | 按行组织 vs 按列组织的存储布局 |
| materialized view | 物化视图 | 预计算结果的存储实体（预聚合的引擎替身） |
| partitioning | 分区 | 按键切块以便装载窗口与裁剪 |
| high availability | 高可用 | 故障不中断服务的部署形态 |
| ETL suite | ETL 套件 | 抽取-转换-装载的工程工具 |
| data warehouse appliance | 数仓一体机 | 软硬捆绑交钥匙分析设备（已并入云仓） |
| tool glue code | 工具粘合代码 | 工具间集成失控的隐性成本源 |

## 最新演进与工业实践

- **货架换代对照** ⚠️：2010 硬件/OS/DBMS 三节 → 2026 对象存储+云仓引擎+托管编排；"选型五轴"里
  新增两轴：**按量成本可观测性**与**开放格式支持度**——教材维度法直接续用。
- **列存全胜的注脚**：列存+zone-map/微分区已成为云仓默认布局；本机 🔧E1/E2 实验的聚合性能差
  （SQLite 20 万行星型 join 307.4ms vs 预聚合 90.8ms；DuckDB 雪花 17.1ms vs 星型 12.3ms）演示的正是
  "布局与预计算决定分析延迟"这一超越货架的原理（**非本书示例引擎**，见 00 第 6 节）。
- **appliance 的墓碑与遗产**：其"极致单负载"由云仓的专用 workload 集群（如盘上 Snowflake 册 06 章
  仓库尺寸/多集群 ⚠️ 转述+其 00 已验 URL）继承；采购话术从买盒子变成选算力档位。
- **工具集收敛为平台** ⚠️：八类工具货架被"现代数据栈"图谱（摄取/转换/编目/BI 四象限）重组，
  粘合成本问题升级为平台间 API 治理——盘上编目/治理两册承接（08/12 文件互链）。
