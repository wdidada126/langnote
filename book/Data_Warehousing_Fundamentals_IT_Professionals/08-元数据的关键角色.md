## 1. 章节定位

## 2. 逐节精读（✅ 节题源自 Wiley 目录）

### 2.1 Why Metadata Is Important（元数据为何重要，p.193 ✅）

- 教材五用 ⚠️：①口径可查（业务信任的地基，回收 05 信息包签字件）；②血缘可追（变更影响分析）；
  ③装载可管（映射规则即 ETL 的配置文件）；④合规可依（审计/留存政策的证据面）；⑤复用可行的目录。
- 名言式论断（转述 ⚠️）：**没有元数据，数仓只是大文件堆**——本章标题"Significant Role"的分量所在。

### 2.2 Metadata Types By Functional Areas（按功能域的元数据类型，p.203 ✅）

功能域分类学（教材矩阵 ⚠️）：

| 功能域 | 元数据样例 | 主要维护者 |
|---|---|---|
| 技术-结构 | 表/列/类型/约束/分区 | DBA/ETL |
| 技术-流程 | ETL 映射、作业调度、装载日志 | ETL 工程师 |
| 业务-定义 | 指标口径、术语表、合法值域 | 业务数据owner（回收 04 团队表） |
| 业务-使用 | 热门报表、用户画像、访问统计 | BI 管理员 |
| 管理-政策 | 保留期、安全分级、所有权 | 治理委员会（回收 12 MDM） |
- 登记：五域表即 2026 catalog 三大支柱（技术/业务/运营）的教材前身 ⚠️。

### 2.3 / 2.4 Business Metadata 与 Technical Metadata（pp.207/209 ✅）

- 二分法正名：business metadata 面向**消费者语言**（"毛利率=？口径是谁批的？"），technical metadata
  面向**机器与建造者**（"这列从哪张表哪个作业来？"）；两者必须经"映射桥"（指标→模型列）缝合 ⚠️。
- 缝合失败的两种病症 ⚠️：只有技术元数据=仓库无人敢用；只有业务词典=口径无法落到列。
- 🔧E7 实测类比（本机，非本书引擎）：DuckDB `information_schema.columns` 抓到 3 条列记录、SQLite
  `sqlite_master` 抓到 2 条表记录——演示"引擎自带的是纯技术元数据"这一事实；业务面（口径/owner/
  合法值）引擎给不了，恰证明本章"业务元数据须专门供给"的论断。

### 2.5 How To Provide Metadata（如何供给元数据，p.212 ✅）

- 三条采集路线 ⚠️：手工登记（全但衰减快）、工具自动捕获（血缘扫描/ETL 日志回流）、
  流程内嵌（变更必须带元数据更新才放行——教材最推）。
- 仓库形态 ⚠️：2010 语境为专用元数据库+报表接口；关键设计判词：**元数据本身也是时变数据**
  （版本/生效区间），别用覆盖式更新——与 10 文件 SCD 思想同构。

## 3. 关键概念辨析

## 7. 元数据健康自检表（⚠️ 本册依 ch9 节题域编制）

| 检查项 | 及格线 | 不及格的临床表征 |
|---|---|---|
| 口径可查 | 任一报表指标 5 分钟内查到定义与 owner | 群里问口径，三人口径不一 |
| 血缘可追 | 列级上游可反查+变更影响可评估 | "改了这列会炸什么？——不知道" |
| 规则在账 | ETL 业务规则有外置台账与版本 | 规则考古靠读脚本 if |
| 时变维护 | 元数据有历史版本（回收 SCD 思想） | 定义被覆盖，无从对账旧报表 |
| 更新内嵌 | 模型/规则变更必须带元数据变更同批 | 文档永远比代码旧半年 |

- 🔧E7 复盘（非本书引擎）：引擎原生只给"技术-结构"一格（DuckDB 3 列/SQLite 2 表记录）——
  矩阵其余四格**全是组织工程**，这正是 2.5 供给方案的着力点。
- 2026 一句话 ⚠️：目录产品接管了"存与查"，但"养"（更新纪律）仍然无替身——自检表年年填。


- 元数据三问自查 ⚠️（本册归纳）：一问"字段含义在哪查"（业务元数据入口），二问"这列从哪来"（血缘深度），三问"改了谁会坏"（影响分析广度）；三问答不上即元数据未闭环。
- 技术锚点：血缘抓取可先用目录册的 information_schema 扫描思路（[../The_Enterprise_Data_Catalog_2e/01-数据目录是什么与为什么.md](../The_Enterprise_Data_Catalog_2e/01-数据目录是什么与为什么.md)），本册 🔧E7 是其最小可行原型。
- 治理衔接：本章"元数据=基础设施"论断是治理册群的公理起点，深读 [../Understanding_Data_Governance/01-什么是数据治理.md](../Understanding_Data_Governance/01-什么是数据治理.md)。
## 核心概念速览（中英对照）

| 英文 | 中文 | 一句话释义 |
|---|---|---|
| metadata | 元数据 | 关于数据的数据：结构/流程/口径/使用/政策 |
| business metadata | 业务元数据 | 消费者语言的定义、口径、合法值、owner |
| technical metadata | 技术元数据 | 结构与流程的机器可读写描述 |
| lineage | 血缘 | 从源到交付列的变换路径记录 |
| impact analysis | 影响分析 | 变更沿血缘传导的风险评估 |
| metadata repository | 元数据仓库 | 集中存放与检索元数据的存储 |
| data dictionary | 数据字典 | 仅结构域的最小元数据集 |
| semantic layer | 语义层 | 业务元数据的可执行化（查询翻译） |
| catalog | 数据目录 | 面向发现与信任的元数据产品面 |
