## 2. 逐节精读（✅ 节题源自 Wiley 目录）

### 2.1 Demand For Online Analytical Processing / OLAP is The Answer（pp.374/379 ✅）

- 需求侧论证 ⚠️：关系查询擅长"取一行/取一组"，分析要的是"沿维度导航+任意聚合层级+秒级响应"；
  朴素 SQL 在三事上破产：聚合层级爆炸、维度组合直觉缺失、缓存语义缺失。
- OLAP 答案三件：多维立方抽象、聚合预计算、会话内缓存——每件都在后文找到工程载体。

### 2.2 OLAP Definitions and Rules（定义与规则，p.379 ✅）

- 术语立法 ⚠️：Codd 1993 论文给 OLAP 命名并立 12 规则（立方概念/稀疏处理/多维排布/一致报表/
  跨维度/多粒度/推测更新/信息驱动/维度数/无限制用户/非受限维度/异常可视）——教材按"概念六征 +
  操作十二规"转述（原书小节 ✅ 存在；逐条措辞以教材为准，本笔记不伪造引文）。
- 教材用法 ⚠️：12 规则当**采购评估表**用，不当宗教用——2026 无引擎满分，但稀疏立方与一致报表
  仍是验收题。
- 🔧E6 实测（DuckDB 1.5.5，非本书引擎）：4 行明细的 `GROUP BY ROLLUP(ch,reg)` 产出 **7 行**
  （2×2 明细+2 小计+1 总计），`CUBE` 产出 **9 行**（全边缘）——"任意聚合层级"规则的 SQL 最小化身；
  🔧E6b：SQLite 直接 **不支持** ROLLUP（OperationalError），需 UNION ALL 手工模拟——引擎能力差即
  教材"选对分析引擎"论断的本机注脚。

### 2.3 OLAP Characteristics / Major Features and Functions（pp.382/382 ✅）

- 特征清单 ⚠️：快（响应亚秒）、一致（跨层对账）、可导航（旋转/上卷/下钻/切片/切块）、多维直觉、
  稀疏容受、多用户、无限维（名义）、非受限聚合。
- 功能动词表 ⚠️：drill-down/roll-up/slice/dice/pivot/排名/同期比/构成比——每个动词在透视 UI
  找一只按钮，是本章的动手作业。

### 2.4 OLAP Models（三模型，p.393 ✅）

| 模型 | 载体 | 教材判词 ⚠️ |
|---|---|---|
| MOLAP | 专用多维立方存储 | 快、贵、容量墙；立方爆炸管理是手艺 |
| ROLAP | 关系星型+SQL 聚合 | 吃星型设计（回收 09/10）与聚合表；扩展便宜，响应靠工程 |
| HOLAP | 冷热分置混合 | 立方存汇总、关系存原子——10 文件聚合表的系统化 |
- 第 2 版在 OLAP 模型上有增补 ✅（Wiley "New to This Edition" 点名 OLAP models）。

### 2.5 OLAP Implementation Considerations（实施考量，p.398 ✅）

- 工程清单 ⚠️：立方规模预算（维成员笛卡尔×稀疏折扣）、刷新频率与锁读（回收 11 装载窗口）、
  工具与源星型的兼容矩阵（13 文件选型九问）、桌面立方 vs 服务器立方（安全面回收 16）。

## 3. 关键概念辨析

- **OLAP vs BI**：OLAP 是**导航引擎**，BI 是交付全集（13 文件谱中一格）⚠️。
- **立方爆炸 vs 稀疏红利** ⚠️：名义维度积恐怖，真实数据稀疏使压缩立方可行——MOLAP 续命的全凭据。
- **SQL OLAP 化**：ROLLUP/CUBE/GROUPING SETS+窗口函数让 ROLAP 吞并 MOLAP 语义——🔧E6 演示的正是
  2026 主流形态对 1993 规则的迟到兑现 ⚠️。

## 7. OLAP 采购评估表（按 Codd 12 规则的教材用法 ⚠️ 本册整理）

| 规则域 | 现场验收题 | 一票级别 |
|---|---|---|
| 概念（立方/多维/一致报表） | 同一指标换个钻取路径，数字还一致吗？ | 硬 |
| 操作（透视/旋转/上下钻） | 分析师改轴心，UI 与 SQL 谁兜底？ | 中 |
| 容量（稀疏/无限维/无限制用户） | 五维×高基数时延迟与账单曲线？ | 硬 |
| 修改（推测/信息驱动） | 加一个新维成员，重建窗口多久？ | 中 |
| 呈现（异常可视/非受限聚合） | 极值与缺格如何暴露而非掩盖？ | 低 |

- 判词 ⚠️：满分引擎不存在——按域给权重，比按宗教选阵营省钱得多。
- 🔧 复盘（非本书引擎）：E6 的 ROLLUP 7 行/CUBE 9 行+SQLite 无 ROLLUP（E6b）证明"规则域第一行"
  （一致报表+多聚合层级）如今主要由 SQL 方言承担——选型题已从"买哪种立方"变"吃哪家 SQL"。
- 立方预算速算 ⚠️：名义积=Π(维成员数)，实存=名义积×稀疏率×压缩系数——三数各测一次再谈容量。

## 核心概念速览（中英对照）

| 英文 | 中文 | 一句话释义 |
|---|---|---|
| online analytical processing (OLAP) | 联机分析处理 | 多维导航+预聚合的分析引擎形态 |
| multidimensional cube | 多维立方 | 度量沿维度层的抽象数据结构 |
| roll-up / drill-down | 上卷 / 下钻 | 沿粒度阶梯的聚合/展开导航 |

| MOLAP / ROLAP / HOLAP | 三种 OLAP 模型 | 专用立方 / 关系底座 / 混合 |

## 最新演进与工业实践

- **MOLAP 的解体与转世** ⚠️：专用立方产品大面积退场，其遗产被三件吸收：SQL ROLLUP/CUBE（语法）、
  云仓自动聚合/结果缓存（执行）、语义层指标定义（口径）——"立方"作为心智模型仍活在透视 UI。
- **列存+向量化=R 端翻身** ⚠️：2010 判词"ROLAP 响应靠工程"在列存引擎时代大幅兑现；本机 🔧E2 组
  （20 万行聚合毫秒级，**非本书引擎**）演示的下限，即是云仓的上限语法。盘上对位：
  [../DuckDB_in_Action/00-总览与阅读地图.md](../DuckDB_in_Action/00-总览与阅读地图.md)、
  [../Tuning_the_Snowflake_Data_Cloud/00-总览与阅读地图.md](../Tuning_the_Snowflake_Data_Cloud/00-总览与阅读地图.md)
  （查询引擎调优的 2026 完全体，实名 ls ✅）。
- **Codd 规则的现代等价** ⚠️：一致报表→指标平台单一定义源；跨维/多粒度→半结构化列存+变长数组；
  信息驱动→物化视图自动推荐；"无限制用户"被按量计费真正解决。
- **分析民主化的性能税** ⚠️：自助爆炸把立方预算题变成账单题——FinOps 与查询治理（超时/队列/仓库
  隔离）承接 15 文件实施考量的当代卷。
