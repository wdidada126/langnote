## 1. 章节定位

Part 2 的引擎章：**ch5 教"怎么把业务话翻成需求件"，ch6 教"需求件怎么反向决定全部技术选型"**。
两章连读即本书方法论的心脏——信息包（Information Packages）是需求原子，需求原子驱动数据设计/架构
/存储/DBMS/交付五大推导。

## 2. 逐节精读：第 5 章（✅ 节题源自 Wiley 目录）

### 2.1 Dimensional Analysis（维度分析，p.100 ✅）

- 需求采集的**提问框架** ⚠️：让业务方用"看什么（度量）× 按什么切（维度）× 到什么程度（粒度）×
  什么频率（刷新）"四问描述每个分析场景；此框架与 Kimball 四步法（选过程→定粒度→选维度→选事实）
  同构（对位 [../数据仓库工具箱3.md](../数据仓库工具箱3.md) 第 2 章 ✅ TOC 实见"4步骤维度设计过程"）。
- 教材提醒 ⚠️：维度分析发生在建模之前——它是**语言工具**不是设计工具，勿把访谈变成 schema 评审。

### 2.2 Information Packages—A Useful Concept（信息包：一个有用的概念，p.103 ✅）

- 定义 ⚠️：信息包 = 一组用户就一组度量/维度/粒度/频率/保留期的**签署需求件**，含样例数据与验收样例。
- 信息包模板要素（教材式清单 ⚠️）：业务问题陈述、度量定义（口径+公式）、维度清单与合法值、
  粒度声明、时间范围与刷新频率、期望交付形态（报表/OLAP/导出）、源系统指认、责任人签字。
- 为何是"本书最佳发明" ⚠️：它把易变的需求切成**可分期、可验收、可追溯**的单元——进度治理
  （ch4 阶段闸门）与优先级谈判都以此计价。

### 2.3 Requirements Gathering Methods（需求采集方法，p.109 ✅）

教材方法菜单 ⚠️：访谈（结构化/半结构）、问卷、焦点小组、文档与报表逆向工程（从存量报表反推口径）、
样例观察（shadowing）、**workshop**（与 Kimball 维度建模研讨会同源互通）。
- 第 2 版在此主题有增补 ✅（Wiley "New to This Edition"点名 requirements gathering techniques）。
- 组合拳建议 ⚠️：报表逆向工程打底 + 焦点小组定优先级 + 逐包访谈补细节；纯问卷在口径问题上不可靠。

### 2.4 Requirements Definition: Scope and Content（需求定义的范围与内容，p.116 ✅）

- 需求基线化 ⚠️：区分"项目级需求（ Why/成功度量）"与"包级需求（ How 的验收件）"；
  变更走登记而非口头；需求完备性检查=每包八要素齐备且签字。

## 3. 逐节精读：第 6 章（✅）——需求反向驱动五大推导

| 推导 ✅节题 | 需求输入 | 教材要点 ⚠️ |
|---|---|---|
| Data Design（p.122） | 包的度量/维度/粒度 | 粒度声明决定原子表设计；维度合法性即维度表内容——需求直接映射模型，先于任何"风格站队" |
| The Architectural Plan（p.125） | 用户分布/主题域数量 | 三架构型（回收 02）用需求画像打分选择；跨域一致性需求高→中央集成价值升 |
| Data Storage Specifications（p.131） | 时间范围/保留期/刷新 | 容量=行数×粒度×保留期方程；在线窗口与归档线由包定义决定 |
| DBMS Selection（p.132） | 规模/预算/技能栈 | 选型矩阵（性能/成本/工具生态/运维），教材立场：DBMS 中立、需求说话（本书示例多 Oracle/SQL Server 系属时代语境 ⚠️，非立场） |
| Information Delivery Strategy（p.133） | 包的交付形态字段 | 拉（报表/订阅）vs 推（门户/告警）vs 自助（OLAP/查询工具）三路分配；直连 ch14 |

## 4. 关键概念辨析

- **需求驱动 vs 架构驱动 vs 建模驱动**：Ponniah/ Inmon / Kimball 的三面旗帜在本章最硬——本书把架构与建模
  都降格为"需求方程的解"；三角深读：[../Building_the_Data_Warehouse/03-数据仓库与设计.md](../Building_the_Data_Warehouse/03-数据仓库与设计.md)
  （设计观对照）。
- **信息包 vs 用户故事**：2026 敏捷语汇可逐字替换——包=带验收样例与口径定义的用户故事+数据契约；
  本书的"验收样例"正是当年缺失、今日 dbt test 补上的那一件 ⚠️。
- 粒度（granularity）在此是需求词、在 ch4/Inmon 册是设计词——同一概念两处立法，对位
  [../Building_the_Data_Warehouse/04-数据仓库中的粒度.md](../Building_the_Data_Warehouse/04-数据仓库中的粒度.md)。

## 7. 信息包最小模板（⚠️ 本册依 ch5 节题域整理，非原书表格复刻）

| 字段位 | 内容 | 验收样例挂载点 |
|---|---|---|
| 业务问题 | 一句话+决策场景 | 样例：期望报表一帧截图/草图 |
| 度量定义 | 名称/公式/单位/可加性 | 样例：三行手算对账数 |
| 维度清单 | 维名/合法值域/层级 | 样例：钻取路径一步 |
| 粒度声明 | 事实行=什么事件 | 样例：一行明细数据 |
| 时间与频率 | 保留期/刷新窗 | 样例：延迟上限断言 |
| 交付形态 | 推/拉/嵌+工具档 | 样例：投递目标地址 |
| 源系统指认 | 表/接口/负责人 | 样例：源侧对账基准 |
| 签核 | 业务owner+技术owner | 双签生效，变更走登记 |

- 采集节奏建议 ⚠️：报表逆向打底（成本低）→ 焦点小组排优先级 → 逐包补细节；一次大问卷=一份大幻觉。
- 本章金句备忘（转述 ⚠️）：**需求不是记录下来的，是构造出来的**——信息包即构造现场。

## 核心概念速览（中英对照）

| 英文 | 中文 | 一句话释义 |
|---|---|---|
| dimensional analysis | 维度分析 | 度量×维度×粒度×频率的需求提问框架 |
| information package | 信息包 | 本书需求原子：可签署可验收的分析需求件 |
| requirements gathering | 需求采集 | 访谈/问卷/焦点组/报表逆向/workshop 方法族 |
| reverse engineering (reports) | 报表逆向工程 | 从存量报表反推口径与维度 |

| data storage specification | 数据存储规格 | 由保留期与粒度推出的容量/分层规格 |
| DBMS selection | 数据库选型 | 需求画像打分决定的中立选型 |
| information delivery strategy | 信息交付策略 | 推/拉/自助三路的交付分配 |
| granularity | 粒度 | 事实表原子行所代表的最小事件级别 |

  （dbt 测试、契约框架）；"签字"变成"合并请求评审+CI 通过"。盘上对位：
  [../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md](../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md)。
- **LLM 辅助需求工程** ⚠️：从存量报表/SQL 日志自动反推口径草稿（报表逆向工程的 AI 化）、text-to-SQL
  原型验证包可行性——教材方法菜单的 2026 增量。

  最实用的访谈剧本 ⚠️。
