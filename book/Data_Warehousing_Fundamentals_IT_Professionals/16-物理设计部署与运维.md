## 1. 章节定位

全书"落地三连"：**先算清物理账（18）→ 再安全上线（19）→ 再长期养活（20）**。也是项目生命周期
（04 文件）的最后两阶段——教材首尾同构，规划章承诺的运维预算在此兑现。

## 2. 逐节精读：第 18 章 物理设计（✅）

- **Physical Design Steps（p.464）** ⚠️：从逻辑模型到物理方案的推导序——容量重算（05 存储规格×
  物理开销系数）、布局（分区键/散列/索引清单）、装载窗口与并行度预算、备份/复制拓扑。
- **Physical Design Considerations（p.467）** ⚠️：读写争用的解法矩阵（分区轮换/双缓冲/错峰调度），
  恢复点目标（RPO/RTO 口径与装载窗口联动）。
- **Physical Storage（p.473）** ⚠️：条带/RAID 选型回收 07 货架；分级存储（在线/近线/归档）按
  02 文件存储分级层落位。
- **Indexing The Data Warehouse（p.477）** ⚠️：仓库索引三戒——少而准：位图索引吃低基数列（2010
  语境 ⚠️ 商用引擎特性，本机不复现）、聚合导航靠预聚不靠索引（回收 🔧E1b：307.4→90.8ms 的预聚合
  收益远胜调索引）、装载期建索引后置。
- **Performance Enhancement Techniques（p.483）** ⚠️：并行装载/分区裁剪/物化视图/统计刷新/慢查询
  回路（TOP SQL 例会）——2026 全部有云仓托管替身（微分区/自动聚簇/结果缓存，对位
  [../Tuning_the_Snowflake_Data_Cloud/](../Tuning_the_Snowflake_Data_Cloud/) 04-06 章谱系）。

## 3. 逐节精读：第 19 章 部署（✅）

- **Data Warehouse Testing（p.490，第 2 版新增主题 ✅ Wiley 页点名 data warehouse testing）** ⚠️：
  五层测试件——单元（规则/转换）、集成（管道）、**数据对账**（源/仓平衡，回收 11 三本账）、
  性能（装载窗+并发峰画像）、UAT（业务样例包验收，回收 05 信息包签字件）。
- **Major Deployment Activities（p.491）** ⚠️：切换策略（大爆炸 vs 并行运行 vs 分域渐进）、历史
  数据迁移分期（保留窗口先近后远）、回退剧本。
- **Considerations For A Pilot（p.497）** ⚠️：试点=选一个信息包最密、发起人最铁的主题域跑通全管道，
  以战报养动能——教材最务实的三页。
- **Security（p.502）** ⚠️：账号/角色/行列级过滤/导出管控/审计日志；与 13 文件权限矩阵、15 文件
  Web 安全面对表。
- **Backup and Recovery（p.504）** ⚠️：仓库可重建性思想——**备份"元数据+规则+水位"三件，数据可
  重放装载者从简**（相对 OLTP 的备份哲学反转，本章最精警 ⚠️）。

## 4. 逐节精读：第 20 章 增长与维护（✅）

- **Monitoring The Data Warehouse（p.512）** ⚠️：监控五面板——装载 SLA/查询性能/空间增长/作业

  规划、成本复盘、元数据卫生年检——"仓库是租来的，不是买来的"运营观 ⚠️。

## 6. 关键概念辨析与自查

- **物理设计 vs 逻辑设计**：前者答"怎么摆放与养活"，后者答"摆什么"（09/10 文件）⚠️。
- **可重建性思想**为何仓库独有：源数据仍在+规则版本化 ⇒ 仓库=可重放函数像 ⚠️——2026 dbt 式
  "转换即代码"把它做成行业默认。
- 自测三题：①给"分域渐进迁移"写一页切换剧本要点；②索引三戒在列存云仓哪戒失效、为什么；
  ③监控五面板各接哪个组织的例会（提示：装载 SLA→数据工程周会，使用统计→价值复盘季会）。

## 7. 上线彩演剧本要点（⚠️ 本册依 ch19 节题域编制）

彩演五幕（每幕留观测与回退点）⚠️：
1. 全量历史迁移演练：按分期窗口计时，核对三本账（回收 11）——超时即切分域渐进。
2. 夜间装载+白天查询并发压测：装载窗边缘的查询延迟曲线是真正的 SLA 证据（回收 06/07 sizing）。
3. 故障注入：作业失败/源缺文件/磁盘水位三剧本各演一次，验证"元数据三件套可重建"承诺。
4. 权限演练：行列级过滤+导出管控+审计抽盲测（回收 13 权限矩阵）。
5. 业务验收日：信息包样例件全量对账（回收 05 签核字段）——双签后窗口切换。

- 运维交接物清单 ⚠️：监控五面板配置+值班手册+例外队列 owner 表+变更三台账空壳——缺一件即"上线
  即裸奔"。
- 收官自检 ⚠️：全书论证链复述一遍——需求（05）决定架构（06），架构决定货架（07），货架养活管道
  （11），管道吐出可信（12），可信换来交付（13-15），交付压在运维（16）——教材三角的第三顶点
  （Ponniah 过程确定性）就此闭合。

## 核心概念速览（中英对照）

| 英文 | 中文 | 一句话释义 |
|---|---|---|
| physical design | 物理设计 | 布局/分区/索引/窗口的落地方案层 |
| partition switching | 分区轮换 | 装载与查询解耦的窗口魔术 |
| bitmap index | 位图索引 | 低基数列的压缩位阵索引（2010 商用引擎语境） |
| data reconciliation | 数据对账 | 源仓行数/金额平衡核验 |
| user acceptance testing (UAT) | 用户验收测试 | 业务样例包签收环节 |
| parallel run / cutover | 并行运行 / 切换 | 三类上线策略的两翼 |
| pilot | 试点 | 单主题域全管道先行的推广法 |
| recoverability (metadata+rules+watermark) | 可重建备份观 | 元数据三件套优先于数据本体 |
| SLA monitoring | 服务水平监控 | 装载/查询/可用的承诺仪表盘 |
| change control board | 变更控制委员会 | 模型/规则/口径三台账的闸口 |
