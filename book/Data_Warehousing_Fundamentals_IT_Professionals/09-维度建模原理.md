## 2. 逐节精读（✅ 节题源自 Wiley 目录）

### 2.1 From Requirements To Data Design（从需求到数据设计，p.225 ✅）

- 推导流水线 ⚠️：信息包（05 文件）→ 抽取"度量/维度/粒度/频率"四件套 → 候选事实表（一业务过程一事实）
  → 维度外提。本节等于把 Kimball 四步法翻译成需求语言——教材层的价值在**输入件明确**（不是从业务灵感
  起步，而是从签字件起步）。
- 与 3NF 的关系 ⚠️：EDW 原子层是否规范化不在本章裁决（02/06 文件的三型路线各自安放），星型被定位为
  **交付侧通用语**。

### 2.2 The Star Schema（星型模式，p.232 ✅）

- 结构定义：中央**事实表**（粒度声明 + 外键群 + 可加度量）围绕**维度表**（描述属性、低基数列、文本域）
  ⚠️；join 即"星芒"，查询形态=按维度属性过滤→按维度属性分组→对事实聚合。
- 设计三规 ⚠️：①粒度先行且全表统一；②度量注明可加性（additive/semi/non）；③维度退化（degenerate，
  订单号类）留在事实表不建维。
- 🔧E1 实测（SQLite 3.45.3，非本书引擎）：20 万行事实 × 3 维（日期/产品/门店）星型 join+双维分组聚合
  = **307.4ms**、产出 40 组——演示星型查询"事实大表 join 小维"的标准形态与代价基线。

### 2.3 Star Schema Keys（星型模式的键，p.239 ✅）

- 三类键 ⚠️：自然键（业务码，稳定性差）、**代理键**（surrogate，装载时发的整数票号，SCD 版本化载体）、
  组合键/退化键。代理键的三条理由：跨源统一命名空间、历史版本各行其键、整数 join 性能。
- 教材注脚：代理键是"装载器的副产品"——与 11 文件 ETL 序列生成器（sequence）衔接。

### 2.4 Advantages of The Star Schema（星型的优点，p.241 ✅）

- 五优 ⚠️：用户可理解（业务词直接是表列）、查询路径短（join 少）、聚合语义直白、装载简单、
  工具亲和（OLAP/透视天然吃星型）。
- 对称劣势预告（10 文件）：冗余换直观、维度爆炸性增长时规范化诉求回来（雪花）。

### 2.5 Star Schema: Examples（星型模式示例，p.244 ✅）

- 教材例域（销售/库存/服务类场景 ⚠️）：每例给"粒度声明→事实列→维度列"三件套表式——本册 🔧E1
  的数据形状（fact_sales(dk,pk,sk,qty,amt) × dim_date/dim_product/dim_store）即该范式的本机复刻。
- 阅读法 ⚠️：把每个例子的"为什么这个粒度"先遮住再自答，是 ch10-11（本册 09/10）最高效的过法。

## 核心概念速览（中英对照）

| 英文 | 中文 | 一句话释义 |
|---|---|---|
| star schema | 星型模式 | 事实表居中、维度表环绕的分析模型 |
| fact table | 事实表 | 业务过程的事件粒度度量行集合 |
| dimension table | 维度表 | 描述事实环境的属性集合 |
| grain / granularity | 粒度 | 事实表一行代表的最小事件级别 |
| additive measure | 可加度量 | 可沿任意维度求和的度量 |
| degenerate dimension | 退化维度 | 无独立维表、留在事实表的业务键 |
| surrogate key | 代理键 | 装载时发放的整型技术键 |
| natural key | 自然键 | 源系统的业务编码 |
| conformed dimension | 一致性维度 | 跨星共享同构定义的维度（总线基石） |

## 最新演进与工业实践

- **星型即物化视图层** ⚠️：云仓时代，手工维表被"事实直连+托管物化/自动聚簇"部分替代，但
  粒度/可加性/代理键三规仍是聚合建模公理；dbt 语义层把"维度属性分组"升格为指标定义——本章
  四件套推导在 2026 有直接工具化身。盘上：[../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md](../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md)。
- **列存让 join 变便宜、也让更多 join** ⚠️：本机 🔧E2 组对比（DuckDB 雪花 17.1ms vs 星型 12.3ms，
  20 万行）显示现代向量化引擎已把规范化税降到噪声级——但教材"join 少+可理解"的人类侧理由不过期。
- **事实表三型的当代扩容** ⚠️：无事实事实表/混合事实等在 Kimball 原典续章；实时场景再加"流式聚合表"
  新方言——交付语汇仍以星型为通用汇编目标。
- **工业实践锚点**：Snowflake/BigQuery 等对星型的官方建模建议与本章五优一脉 ⚠️（不引未验 URL；
  盘上对位 [../BigQuery_for_Data_Warehousing/00-总览与阅读地图.md](../BigQuery_for_Data_Warehousing/00-总览与阅读地图.md)）。
