## 1. 章节定位

Part 3「架构与基础设施」的总图章：把 ch2 的构件清单升级成**带层次与流的技术架构框架**，并给出三类
架构型（top-down/bottom-up/hybrid）的技术剖面。本章是全书"图最多"的一章，也是面试架构图的口试底本 ⚠️。

## 2. 逐节精读（✅ 节题源自 Wiley 目录）

### 2.1 Understanding Data Warehouse Architecture（理解数仓架构，p.141 ✅）

- 教材开宗 ⚠️：架构=组件+连接+约束的三件套；数仓架构的特殊约束来自 ch2 四特征（只读性、时变、
  集成），因此**数据流方向单一（源→仓→交付）**是拓扑第一原则。
- 逻辑架构与物理架构分离陈述：前者谈"层"（staging/integration/delivery），后者谈"机"（服务器/网络/存储）
  ——物理面在 ch18（本册 16 文件）。

### 2.2 Distinguishing Characteristics（区分性特征，p.143 ✅）

数仓架构 vs OLTP 架构的对照 ⚠️：单向数据流、批量节奏（哪怕准实时也是微批语义）、写读分离
（装载窗口 vs 查询高峰）、元数据枢纽位、历史累积（存储增长不可逆）。
- 教材点名的设计后果 ⚠️：装载与查询的**资源战争**决定了一切分层/隔离/调度机制的存在理由。

### 2.3 Architectural Framework（架构框架，p.146 ✅）

本书四层框架（与组件表 ch2 对齐后放大 ⚠️）：

| 层 | 组件 | 本册落点 |
|---|---|---|
| 源层 Source | 操作性系统/外部数据/遗留 | 11（抽取面） |
| 准备层 Staging/ETL | 暂存、清洗、转换、质检 | 11/12 |
| 存储层 Storage | EDW 原子/汇总/历史 + 集市 + 元数据仓库 | 02/08/09/10 |
| 交付层 Delivery | 查询/报表/OLAP/挖掘/门户/Web | 13/14/15 |
- 贯穿件：metadata 仓库与项目管理/治理不是"第五层"而是**纵向切四层的管理面**（回收 04/08）⚠️。

### 2.4 Technical Architecture（技术架构，p.148 ✅）

- 技术剖面 ⚠️：装载路径（全量/增量/实时微批三口）、查询路径（直连集市/OLAP 立方/门户缓存）、
  以及连接两者的**分区与轮换策略**（partition switching 雏形——教材置于 ch18 深讲，本章给拓扑位）。
- 接口形态：文件/ODBC-JDBC/消息/数据泵时代的复制技术（Text/Oracle Streams 一类属时代语境 ⚠️ 不逐一
  点名），教材只按"推送/拉取、同步/异步"分类学。

### 2.5 Architectural Types（架构类型，p.156 ✅）

三型技术剖面重画（回收 02 文件判词）⚠️：
1. **top-down**：EDW 为唯一真相源，集市=EDW 视图/物化派生（Inmon 立场）；治理强、周期长、交付慢。
2. **bottom-up**：集市网+总线/一致性维度即"逻辑仓库"（Kimball 立场）；交付快、总线纪律不可松。
3. **hybrid**：中央集成层(hub)供集市+旁路直供关键集市；教材称"现实多数为 hybrid 变体" ⚠️。
- 打分表建议 ⚠️：按需求画像（用户广度/口径风险/预算节奏/技能栈）为三型打分——05 文件五推导之一的
  落地现场。

## 3. 关键概念辨析

- **架构 vs 拓扑 vs 组件**：本章三词分层使用 ⚠️——组件（有什么）、拓扑（怎么连）、架构（+约束与理由）。
- **与 Inmon 册对位**：BDW 第 3 章「数据仓库与设计」从环境论起笔，本章从框架图起笔；教材层把 CIF 的
  "环形总线"降维成四层流水线——站队味更淡，可操作性更强（[../Building_the_Data_Warehouse/03-数据仓库与设计.md](../Building_the_Data_Warehouse/03-数据仓库与设计.md)）。
- **元数据的架构位**：为什么 metadata 值得单开一章（ch9）——因为它是四层框架里唯一**跨层**的组件；
  预读钩子设在本章 2.3 贯穿件。

## 7. 架构图验收清单（⚠️ 本册依 ch7 节题域编制）

审一张数仓架构图，五问递进 ⚠️：
1. 四层是否齐备且方向单一？（缺暂存=不可回放；逆向箭头=治理债）
2. 装载与查询的争用面标了吗？（窗口/隔离/错峰，三缺一即事故候补）
3. 元数据触点画了吗？（每个转换框应可回溯出规则出处——回收 08）
4. 集市与 EDW 的供给关系明确吗？（dependent/independent 混画=拓扑含糊）
5. 扩展路径在哪？（加源/加域/加用户各走哪条线，三年图与当日图同框）

- 三型打分表提示 ⚠️：hybrid 不是"和稀泥"——它的成本是中央层的双份纪律（模型+装载），
  没有治理预算的组织慎选。
- 面试位 ⚠️：本章四层框架+"为什么这样分层"是最常被考的原教旨架构图，胜过任何云厂商参考图。

## 核心概念速览（中英对照）

| 英文 | 中文 | 一句话释义 |
|---|---|---|
| architecture (components+connections+constraints) | 架构 | 组件+连接+约束三件套 |
| staging area | 暂存区 | 装载流水线的落地缓冲区 |
| single direction data flow | 单向数据流 | 源→仓→交付的拓扑第一原则 |
| load/query contention | 装载-查询竞争 | 数仓架构的根本约束来源 |
| partition switching | 分区轮换 | 装载窗口与查询窗口解耦的物理手段 |
| top-down architecture | 自顶向下架构 | EDW 唯一真相源路线（Inmon） |
| bottom-up architecture | 自底向上架构 | 集市+总线即仓库路线（Kimball） |
| hybrid architecture | 混合架构 | 中央集成层+旁路的现实主流 |
| bus architecture | 总线架构 | 一致性维度缝合各集市的纪律 |
