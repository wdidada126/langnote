## 核心精讲（教学示意，不参与构建）

### 1.1 定义与「连贯性」的含义
- 定义：**独立计算机的集合，对用户呈现为单一连贯系统**。两个关键词：
  - **独立计算机（independent computers）**：各自有自己的 CPU、内存、时钟，不做指令级共享；
  - **单一连贯（single coherent）**：中间件把差异藏起来，用户/程序员无需知道「有几台、在哪台」。
- 对比计算机网络：网络暴露机器与协议（用户知道 IP、会挑服务器）；分布式系统**隐藏**它们。
- 中间件（middleware）是「单一连贯」的承重墙：位于操作系统之上、应用之下，提供统一的进程/通信/命名/事务接口。

### 1.2 目标
- **使资源可访问**：资源共享（打印机、文件、计算能力）是最初动机；隐含需求是**控制访问**（谁能用、何时用）。
- **透明性**六种：
  | 类型 | 含义 |
  | --- | --- |
  | 访问透明 | 本地/远程资源操作方式一致 |
  | 位置透明 | 不必知道资源在哪 |
  | 迁移透明 | 资源移动不影响使用 |
  | 复制透明 | 多副本对用户不可见 |
  | 并发透明 | 多用户共享不被感知 |
  | 失效透明 | 失效被屏蔽、任务可继续 |
  - 🔧 原书强调：**完全透明不可取也不必要**。例：广域链路上假装「本地访问」只会掩盖延迟；
    感知到「副本在亚洲、我在欧洲」反而可以就近访问。透明性是手段不是目的。
- **开放性**：按**标准接口**写系统（如 OMG 的 IDL），用接口定义语言描述，允许跨厂商互操作；代价是接口成为攻击面。
- **可扩展性**三维度：
  1. 规模：用户/进程数量增加；
  2. 地理：节点跨地域分布，通信延迟无法忽略；
  3. 管理：跨越多个管理域。
  - **扩展技术**：① 隐藏通信延迟（异步通信、预取）；② **分布**（DNS 分区、把组件拆到子域）；
    ③ **复制与缓存**（复制提高读写能力，缓存把数据拉近用户）。
  - 复制的副作用：一致性难题——这正是本书 Ch7 的出发点；原书在此已埋下「复制 → 一致性 → 可扩展性」的因果链。
- **普适系统的陷阱**（fallacies）：网络可靠、延迟为零、带宽无限、网络安全、拓扑不变、管理员只有一个、传输代价为零、网络同质——每一条都被实际系统打脸过。

### 1.3 分布式系统的类型
- **分布式计算系统**：集群（同构、高内聚）、网格（跨组织共享资源）、云（按需付费，IaaS/PaaS/SaaS 雏形）。
- **分布式信息系统**：面向组织内应用集成——事务处理监视器（TP monitor）、企业应用集成（EAI）；
  它是本书范型部分「基于对象（Ch10）/基于 Web（Ch12）」的直接背景。
  - **分布式普适系统**：小型、移动、电池供电的设备嵌入物理环境（家庭、医疗、传感网）；
    特征：节点易失效、拓扑动态变化、通信不稳定——2007 年的「前沿」，今天即 IoT/边缘计算的前身。

### 透明性的「六种 × 程度」读法

- 原书按「隐藏了什么」给六种透明性命名，但实践中还要按**隐藏到什么程度**分级：
  1. **语法透明**：调用形式一样（RPC stub 即可做到）；
  2. **语义透明**：失败/延迟的语义也一样（几乎做不到，网络分区下无解）；
  3. **运维透明**：故障定位时仍能还原真实拓扑（可观测性补的正是这一层）。
- 这个分级解释了 2026 年的工程共识：**语法透明全都要，语义透明按需给，运维透明主动暴露**——
  「透明性是手段不是目的」在工程上就落在这三句话。

## 版本演进

- **前传（1990）**：Tanenbaum《Distributed Operating Systems》以操作系统为中心；本版把视角扩大到「中间件之上的系统」。
- **第 1 版（2002）《Distributed Systems: Principles and Paradigms》**：无独立架构章（架构内容并入进程/系统章）；
  类型学尚未成型。
- **第 2 版（2007，本书）**：新增独立的**第 2 章体系结构**；加入 P2P（DHT、gossip）与普适系统两大新内容；
  范型章改为「每章选一个代表性案例」而非罗列全部案例。
- **第 3 版（2017，van Steen & Tanenbaum，作者免费电子版，见 [分布式系统（van Steen 3rd）](../分布式系统/00-总览与阅读地图.md)）**：
  删去三大「范型章」（对象/文件/Web/协调案例章合并弱化），重组为原理章；
  云计算、大数据、微服务进入正文；透明性论述更克制（强调「有意的非透明」）。
- **2026 口径**：定义被扩展为「一组通过网络协作以达成共同目标的节点」；
  「单一连贯视图」在微服务/多云时代被有意放弃（显式服务边界 > 隐式透明），这是读本书时必须携带的修正。

## 近年研究与工业界开源实践（2015–2026）

- **定义的演化**：业界主流把分布式系统锚定在**微服务 + 云原生**：Kubernetes 的「声明式 API + 控制器循环」
  替代了原书的「中间件透明」路线——不追求藏起机器，而追求「机器可替换」。
- **可扩展性三技术在 2026 的对应物**：分布 → 分片/分区（sharding）；复制与缓存 → CDN + 多副本存储；
  隐藏延迟 → 异步化（消息队列、prefetch）。三者与原书表述几乎一一对应，只是实现换代。
- **开源实践**（star 数 2026-09 实测）：
  - `kubernetes/kubernetes`：控制平面自身就是分布式系统（etcd + leader 选举 + list/watch），是「开放性（声明式接口）」的最佳当代样本；
  - `apache/kafka`（≈33.8k★）：跨管理域可扩展的分布式日志，直接回应「地理与管理可扩展性」。
- **可扩展性三陷阱的 2026 复现清单**（原书 1.2.4 的 pitfalls 表在今天的对应物）：
  1. 「很多用户 = 一个应用」→ 微服务拆分不当造成雪崩式级联失败；
  2. 「网络是可靠的」→ 分布式锁/协调假设无分区，分区演练（混沌工程）必做；
  3. 「拓扑不变」→ 滚动发布/自动扩缩容让节点随时进出，成员管理协议（lease/watch）是标配；
  4. 「管理员只有一个」→ 多租户与多云导致配置漂移，GitOps（声明式 + 审计）成为治理手段。
- **普适系统的落点**：原书的传感网/家庭网络演化为 IoT 平台与**边缘计算**；
  「节点易失效 + 拓扑动态」的假设在车联网、工业边缘集群中仍然成立，本书的容错章（Ch8）仍是最适切的准备。
- **开放性的 2026 代价**：开放接口（OAuth2/OIDC、OpenAPI）在带来互操作的同时扩大攻击面——
  原书「接口成为攻击面」的提醒在零信任时代被放大（详见 [08-容错与安全.md](08-容错与安全.md)）。

### 延伸判读：两个定义之争（2026 补充）

- **原书定义**：「对用户呈现为单一连贯系统」——强调**幻觉**；
- **原书作者后续（van Steen 3rd / 演讲）**：「一组通过网络协作以达成共同目标的节点」——强调**合作**而非幻觉；
- 差异的根源：2007 年主流系统追求把机器藏起来（NFS、CORBA），2017 年后主流系统**主动暴露机器**
  （微服务声明依赖、K8s 显式调度）——「藏」的成本被可观测性与故障定位的需求反超。
- 判断一个系统是否「分布式」的新实用标准：
  1. 是否存在**部分失效**（一部分挂了整体还能用）；
  2. 是否存在**不可忽视的不可靠通信**；
  3. 是否需要**显式的协议**来达成一致。
  三者齐备即分布式系统——比「单一连贯视图」的旧定义更贴近工程。
