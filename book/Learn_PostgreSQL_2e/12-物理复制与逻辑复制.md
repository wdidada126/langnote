# 12 · 物理复制与逻辑复制（原书第 17–18 章合并）

> 对应原书 Ch17 *Physical Replication* + Ch18 *Logical Replication*（✅ 章题；复制双章合并，00 有映射）。实证 ✅：docker 镜像目录直接暴露教学设计——ch17 三拓扑 `chapter17_delayed / chapter17_streaming / chapter17_synchoronous`（原文拼写 synchoronous 如此）+ `code/chapter17.sql`；ch18 三场景 `chapter18_logical_clear / chapter18_logical_ready / chapter18_physical_logical` + `code/chapter18.sql`。勘误（✅ README）：p610 "wal_level 默认是 mininal" 错——现代 PG 默认 **replica**。

## 1. 物理复制：WAL 流的搬运工（Ch17 ⚠️+✅）

- 原理：standby 持续接收并回放 WAL ⇒ **字节级镜像、只读服务**（warm standby ✅ https://www.postgresql.org/docs/current/warm-standby.html ）；`pg_stat_replication`/`pg_stat_wal_receiver` 双侧观测 ✅ https://www.postgresql.org/docs/current/monitoring-stats.html 。
- 三种送达语义（docker 三镜像即三实验 ✅）：**async**（默认，可能丢已确认事务）、**同步 `synchronous_commit = on/local/remote_write/remote_apply`**（延迟换零丢失）、**延迟备库 `recovery_min_apply_delay`**（误删保险，chapter17_delayed 正是此场景）。
- 槽（replication slot）`wal_level=replica` 起 WAL 保留有底，但**失活槽=磁盘杀手**——监控 `pg_replication_slots` 是运维红线 ⚠️+✅（docs 口径 wal-internals 已链）。
- 拓扑词表 ⚠️+✅ https://www.postgresql.org/docs/current/high-availability.html ：级联/同步候选/仲裁；仲裁者（quorum）语义 PG 10+。
- 工具外脑：Patroni（HA 编排事实标准 ✅ https://api.github.com/repos/patroni/patroni 200）、repmgr/pglockrarian 谱系 ⚠️。

## 2. 逻辑复制：发布与订阅（Ch18 ⚠️+✅）

- 概念：从 WAL 里**解码行变更**→ 按 PUBLICATION/SUBSCRIPTION 路由，表级粒度、跨版本、目标可写 ✅ https://www.postgresql.org/docs/current/logical-replication.html 、https://www.postgresql.org/docs/current/sql-createpublication.html 。
- 限制清单（书与文档一致 ⚠️+✅ 同上页）：序列/DDL/大对象不同步；初始快照 `copy_data=true` 一次性搬运（**不保全局一致性快照跨多表时注意** ⚠️）；`origin` 防环、冲突不自动解（last-write-wins 也无 ⇒ 报错停摆）⚠️。
- docker 三场景读法（✅ 目录名）：`logical_clear`=从零发布订阅建立；`logical_ready`=已同步态的增量与观测（`pg_stat_subscription`）；`physical_logical`=**物理备库上开逻辑解码**为下游供流——作者刻意用容器组合讲混合拓扑。
- `wal_level=logical` 是前提 ⇒ 该集群 WAL 变肥（row 镜像开销 ⚠️）；两阶段解码 `two_phase`（PG 15+ ⚠️+✅ release 族）。
- 迁移双通路：pg_dump 走逻辑备份（Ch15）、逻辑复制走**在线迁移+零停机升级**——书把 18 章当"版本升级神器"收尾 ⚠️。

## 3. 🔧 类比实测：无服务器引擎如何"想象复制"（duck6.out / sq1.out 🔧）

- **多副本不存在**：SQLite/DuckDB 均无服务端复制协议；最接近的工程替代是文件级 rsync/对象存储快照（⚠️ 通例）。本机可验证的是**单写者约束**：

```text
SQLite WAL 模式：第二连接可并发读，但写者唯一（wal_checkpoint 返回 busy 位，🔧 实测 0|0|0）
DuckDB：同一文件二次读写连接即冲突（单进程内嵌模型）🔧 通例声明，未做双进程实验
```

- **对照 PG**：物理复制=把"重放日志"扩展到跨机；逻辑复制=把"读己之写"扩展成发布订阅网络。嵌入式引擎的读扩展答案在**文件副本**（如 DuckDB 直读对象存储上的 Parquet ⚠️，对位 [../DuckDB_in_Action/00-总览与阅读地图.md](../DuckDB_in_Action/00-总览与阅读地图.md) 的湖仓章）。
- **DuckDB→PG 的"反向复制"玩具 🔧**：`postgres_scanner` 扩展在本机为 `installed=True, loaded=False`（duck6.out 实抓）——装载后可把**活 PG 库当表读**（ATTACH TYPE postgres）；即分析引擎把"复制"简化为"直连扫描"，与 PG 侧 postgres_fdw 同思路（→ [13-常用工具与实用扩展.md](13-常用工具与实用扩展.md)）。本机无 PG 服务端可连，端到端未跑通，登记 ⚠️。**非 PostgreSQL 行为**声明如上。

## 核心概念速览（中英对照）

1. **流复制** — streaming replication：WAL 实时搬运；物理=字节镜像只读。
2. **热备** — warm/hot standby：回放中可服务只读查询（hot 为默认形态）。
3. **同步提交** — synchronous_commit：on/local/remote_write/remote_apply 四档耐久-延迟旋钮。
4. **延迟备库** — delayed standby：recovery_min_apply_delay 的人为时差保险（✅ docker 实证）。
5. **复制槽** — replication slot：WAL 保留承诺；失活即膨胀事故源。
6. **仲裁同步** — quorum sync：多候选中任意 N 个确认即提交 ⚠️+✅。
7. **发布/订阅** — publication/subscription：逻辑复制的两端对象。
8. **行解码** — row-based decoding：wal_level=logical 的额外 WAL 代价 ⚠️。
9. **copy_data** — 初始快照搬运：订阅建立时的表拷贝开关。
10. **origin 防环** — replication origin：双向/链式订阅的循环抑制。
11. **pg_stat_replication / pg_stat_subscription** — 两本观测账：发送端与接收端。
12. **Patroni** — HA 编排器：etcd/Consul DCS + REST 故障切换 ✅（API 200）。
13. **物理+逻辑混合** — 备库供逻辑流：chapter18_physical_logical 容器实证 ✅。

- **版本增量** ✅：PG 15 逻辑复制 `two_phase`；PG 16 将逻辑复制作为大版本升级推荐路线继续加固 ⚠️ 转述；PG 17 冲突处理改善预告；**PG 18 逻辑复制冲突日志落地、增量备份配套 pg_walsummary 等** ✅ https://www.postgresql.org/docs/release/18.0/ （以 release 页为准 ⚠️ 细节转述）。
