## 1. 日志与审计（Ch14 ⚠️+✅）

- 骨架参数（✅ https://www.postgresql.org/docs/current/runtime-config-logging.html ）：
  - `logging_collector=on` 起收集器进程，stderr 落 `log/`；
  - `log_destination`：stderr / **csvlog**（机器管道）/ eventlog / jsonlog（PG 16 新增 ⚠️+✅ 同页）；
  - `log_statement`：none/ddl/mod/all 四档；
  - `log_min_duration_statement`：-1 关、0 全记、N 记慢于 N ms；
  - 事件灯：`log_checkpoints`、`log_lock_waits`、`log_autovacuum_min_duration`。
- 日志行模板 `%p %u %d %x`：进程号/用户/库/事务号——**application_name 打标**让"哪个应用"进日志（本书惯用 ⚠️+✅ logging_collector 页 log_line_prefix 要素）。
- SQLSTATE 五位码：错误语言标准化，应用按码分流重试 ⚠️+✅（errcodes 附录，docs/current 族）。
- 审计合规：核心无列级审计；工业标准件 **pgAudit**（外部扩展——docs/current/pgaudit.html 实测 404，佐证"核心外"⚠️；以项目文档为准）。
- 闭环：csvlog → pgBadger 报表 → Top 慢 SQL → [10-查询调优索引与性能.md](10-查询调优索引与性能.md) 工作流第 3 步。

## 2. 备份与恢复（Ch15 ⚠️+✅）

三层地图（书结构 ⚠️；总纲 ✅ https://www.postgresql.org/docs/current/backup.html ）：

1. **逻辑层**：
   - `pg_dump -Fc`（custom 格式：压缩+并行+选择恢复 ✅ https://www.postgresql.org/docs/current/app-pgdump.html ）；
   - `pg_restore -j N`（并行重建 ⚠️+✅ 同页族）；
   - 单表通道 `COPY`（✅ https://www.postgresql.org/docs/current/sql-copy.html ）；
   - 跨版本/异构迁移走 pgLoader 与逻辑复制（→ [12-物理复制与逻辑复制.md](12-物理复制与逻辑复制.md)、[13-常用工具与实用扩展.md](13-常用工具与实用扩展.md)）。
2. **物理层（PITR）**：`pg_basebackup` + `archive_mode=on` + `restore_command` ⇒ 任意时间点 ✅ https://www.postgresql.org/docs/current/continuous-archiving.html ；低层 API `pg_backup_start()/pg_backup_stop()`（Ch11 伏笔回收，✅ backup-dump https://www.postgresql.org/docs/current/backup-dump.html ）。
3. **管理层**：Barman ✅（https://api.github.com/repos/EnterpriseDB/barman 200）、pgBackRest ✅（https://api.github.com/repos/pgbackrest/pgbackrest 200）——加密/增量/保留策略外置 ⚠️。

纪律 ⚠️：**没演练过的备份等于没有**——恢复演练+amcheck 体检 ✅ https://www.postgresql.org/docs/current/amcheck.html 入例行作业。

## 3. 配置与监控（Ch16 ⚠️+✅）

- 参数治理：四来源优先级与 context 分级（internal/postmaster/sighup/backend/superuser/user——决定"要不要重启" ✅ https://www.postgresql.org/docs/current/config-setting.html ）；自检句 ⚠️：

```sql
SELECT name, setting, unit, source FROM pg_settings WHERE source <> 'default';
```

- 内存三角 ⚠️+✅（runtime-config-resource 族口径 https://www.postgresql.org/docs/current/runtime-config-wal.html 同族文档，具体页未逐一验 ⚠️）：
  - `shared_buffers`≈RAM 1/4 起点；
  - `effective_cache_size`=优化器账面 OS 缓存预期；

- 生态面板：pgAdmin（✅ https://www.pgadmin.org/ 200）、Prometheus+postgres_exporter、Grafana ⚠️ 通例——管理册实操对位 [../Mastering_PostgreSQL_Administration/07-监控_pgAdmin与Grafana.md](../Mastering_PostgreSQL_Administration/07-监控_pgAdmin与Grafana.md)。

## 4. 🔧 类比实测：备份一致性责任的三种分配（sq1.out / duck.out 🔧，非 PostgreSQL 行为）

```text
SQLite(WAL):  在线写 + 边文件 sq1.db-wal；一致性折叠靠 wal_checkpoint（🔧 0|0|0）
              官方 .backup 命令/Backup API 处理"热备份读锁+增量拷贝"⚠️
DuckDB:       CHECKPOINT 语句实测通过（🔧 duck.out）→ 之后复制单文件即一致
PostgreSQL:   热数据集禁止裸 cp（页撕裂风险），必须 basebackup+WAL 链或逻辑导出 ⚠️+✅
              （continuous-archiving.html / backup.html）
```

- 导出格式对照 🔧/⚠️：SQLite `.dump` 重放 SQL；DuckDB `COPY TO 'x.parquet'` 列存文件；PG `COPY ... FORMAT csv/binary`（✅ sql-copy）+pg_dump 元数据与数据分道。
- 谱系一句话：**单写者引擎把一致性藏进文件锁，多进程服务器把一致性显式成 WAL 协议**——这就是 Ch15 需要三种备份法的原因。

## 7. 自动 vacuum 调优与膨胀监控（⚠️+✅）

- **autovacuum 参数族**（✅ https://www.postgresql.org/docs/current/routine-vacuuming.html ）：
  - `autovacuum_vacuum_scale_factor`（默认 0.2=20% 死元组触发 ⚠️）：大表 20% 可能=百万行——调低到 0.01 或更小；
  - `autovacuum_analyze_scale_factor`（默认 0.1 ⚠️）：统计更新触发阈值；
  - `autovacuum_vacuum_cost_delay`：限速器——调高保护在线查询但延长 vacuum 时间。
- **表级覆盖** ⚠️+✅：`ALTER TABLE big SET (autovacuum_vacuum_scale_factor = 0.01);`——大表独立调优。
- **膨胀观测** ⚠️：

```sql
SELECT relname, n_live_tup, n_dead_tup,
       last_autovacuum, last_autoanalyze,
       dead_ratio := n_dead_tup::float / GREATEST(n_live_tup,1)
FROM pg_stat_user_tables
ORDER BY n_dead_tup DESC LIMIT 20;
```

- **VACUUM FULL vs 在线 VACUUM** ⚠️+✅：`VACUUM FULL` 锁表重建（回收空间彻底但停写 ⚠️）；普通 `VACUUM` 不锁但空间只标可复用不归还 OS。
- 🔧 SQLite 的 `VACUUM` 命令（🔧 非 PostgreSQL 行为）=全库重建压缩（类似 PG 的 VACUUM FULL）；DuckDB `VACUUM` 实测通过但语义差异大 🔧。

## 8. pg_upgrade 与跨版本迁移（⚠️+✅）

- **pg_upgrade**（✅ https://www.postgresql.org/docs/current/pgupgrade.html ）：跨大版本就地升级——复制目录结构+迁移系统目录，比 dump/restore 快几个数量级。
- **前置检查** ⚠️：
  - 旧版扩展需在新版 PG 安装同版本二进制；
  - 不兼容的 `shared_preload_libraries` 需先移除；
  - `pg_upgrade --check` 预检模式不修改任何文件 ⚠️+✅。
- **逻辑复制做零停机迁移** ⚠️（工业通例）：旧版做发布端→新版做订阅端→追平后切换→回滚通道保留——对位 [12-物理复制与逻辑复制.md](12-物理复制与逻辑复制.md)。
- **回滚策略** ⚠️：pg_upgrade 保留旧目录（`--link` 模式除外）可回退；逻辑复制方案保留旧实例直到验证完成。
- 🔧 对照：SQLite 升级=换二进制文件（🔧 无目录迁移概念）；DuckDB 升级同 SQLite 模式（🔧 非 PostgreSQL 行为）。

## 9. 配置参数的诊断与调优工作流（⚠️+✅）

- **非默认参数一览** ⚠️+✅：

```sql
SELECT name, setting, unit, source, context
FROM pg_settings
WHERE source <> 'default'
ORDER BY source, name;
```

- **参数改错的紧急恢复** ⚠️：`postgresql.auto.conf`（`ALTER SYSTEM` 写入）优先级高于 `postgresql.conf`——误设可通过编辑此文件+reload/restart 恢复。
- **work_mem 实战调优** ⚠️：
  - 公式起点：`work_mem × max_connections × max_parallel_workers_per_gather` ≤ RAM × 0.25 ⚠️；
  - 观测：`pg_stat_activity` 中 `state='active'` 且 `wait_event_type='IO'` 的会话=可能在等排序落盘。
- 🔧 DuckDB 内存管理：`SET memory_limit='8GB'` 全局一刀（🔧 非 PostgreSQL 行为）；SQLite 无共享内存配置（🔧）。

## 核心概念速览（中英对照）

1. **logging_collector** — 日志收集器进程。
2. **jsonlog** — PG 16 新增目的地 ⚠️+✅。
3. **log_min_duration_statement** — 慢语句阈值闸。
4. **pgAudit** — 外置审计标准件（404 实证"非核心"⚠️）。
5. **pgBadger** — csvlog 报表器 ⚠️。
6. **pg_dump -Fc** — 自定义格式逻辑备份。
7. **pg_restore -j** — 并行恢复。
8. **pg_basebackup** — 物理基础备份。
9. **PITR** — 归档+WAL 时间点重放 ✅。
10. **Barman / pgBackRest** — 备份管理器双雄 ✅。
11. **context 分级** — 参数生效语境：重启/reload/会话 ✅。
12. **pg_stat_* 视图族** — 监控正门 ✅。
13. **track_io_timing** — IO 计时采样开关 ⚠️。
14. **amcheck** — 索引一致性体检 ✅。

## 最新演进与工业实践

- **备份面** ✅：PG 17 引入 `pg_combinebackup`（增量备份链合并），18 的 pg_upgrade 保留旧表空间等改进（✅ release 17.0/18.0 两页可达）；自建=pgBackRest/Barman 双雄（仓库 200 实抓），云=快照+PITR 一键。
- **监控面**：PG 16 的 `pg_stat_io` 统一 IO 计数正是本书基线红利（✅ monitoring-stats 族 ⚠️ 细节转述）；Prometheus/Grafana 栈成开源自监控默认 ⚠️。
- **日志演进** ⚠️：jsonlog（16）直喂现代可观测管道（OTLP/Loki）；PG 18 OAuth（✅ release 18.0）把认证审计推向外置身份面。
- **配置即代码**：参数模板（Tuning Web 类 ⚠️ 不引 URL）、迁移脚本化、灰度重载 `pg_reload_conf()` 是 2020s DBA 三件套；与 [../Mastering_PostgreSQL_Administration/06-例行维护.md](../Mastering_PostgreSQL_Administration/06-例行维护.md) 的运维日历互补。
