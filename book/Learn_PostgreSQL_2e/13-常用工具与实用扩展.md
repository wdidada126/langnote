## 1. 三容器主线（✅ 目录名+代码实证）

- **MySQL→PostgreSQL 迁移**：pgLoader（Common Lisp 实现的搬运工，✅ 仓库 https://api.github.com/repos/dimitri/pgloader 200）一把梭：schema+数据+类型映射+`AUTO_INCREMENT→serial/identity`，迁移后校验行数 ⚠️（书内流程转述）。配套视角：逻辑复制做在线迁移（→ [12-物理复制与逻辑复制.md](12-物理复制与逻辑复制.md)）与 oracle 线在管理册展开：[../Mastering_PostgreSQL_Administration/08-Oracle迁移_Ora2Pg.md](../Mastering_PostgreSQL_Administration/08-Oracle迁移_Ora2Pg.md)。
- **pg_trgm 模糊检索** ✅ https://www.postgresql.org/docs/current/pgtrgm.html ：三元组相似度+`similarity()/word_similarity()`、`%` 操作符、GIN/GiST 索引加速；典型场景=拼写容错搜索与"类 LIKE 索引化"（`LIKE '%x%'` 走 trigram 索引）⚠️+✅。
- **postgres_fdw 联邦** ✅ https://www.postgresql.org/docs/current/postgres-fdw.html ：`CREATE SERVER/USER MAPPING/FOREIGN TABLE` 三件套，远端表可查可写（pushdown 下推远程执行 ⚠️+✅ 同页）；本章代码即此三句骨架 ✅。

## 3. 🔧 类比实测 A：联邦查询——SQLite ATTACH 的"最小 fdw"（sq8.out 🔧）

用本书同名用户 luca/enrico 做跨库 JOIN：

```text
$ sqlite3 fa.db "ATTACH DATABASE 'fb.db' AS b;
   SELECT u.name, p.title FROM users u JOIN b.posts p ON p.uid=u.id;"
luca|Btree
enrico|WAL
```

- SQLite ATTACH：同构文件级"联邦"，本地多文件即多 schema（`main/b`），无远程、无凭据管理。
- DuckDB 🔧：`ATTACH ':memory:' AS m` 同款多目录（catalog）语义；跨引擎则靠**扫描器扩展**——本机 postgres_scanner `installed=True`（duck6.out 实抓），理论可 `ATTACH TYPE postgres` 直连活 PG；**本机无 PG 服务端，端到端未验证 ⚠️**。
- PG postgres_fdw ⚠️+✅：网络对端+USER MAPPING 凭据+计划下推，是三者中唯一"把远端当本地表优化"的方案。三层对照=文件联邦/进程联邦/网络联邦（非 PostgreSQL 行均为本机实验）。

## 4. 🔧 类比实测 B：模糊与全文的三种答案（回扣全文检索义务）

- 需求"拼写容错/子串命中"：PG=pg_trgm `%`+GiST（✅ 文档）；**SQLite 无 trgm 等价物**——内置只有 LIKE/GLOB，FTS5 需前缀/词干（本机 py_fts.out：`MATCH 'wal OR btree'` 命中 2 行、`highlight()` 返回 `[wal]` 🔧；Android 构建无 FTS5 的否证 🔧）。
- **DuckDB**：fts 扩展 BM25 打分实测（duck7.out：'wal checkpoint' 查询命中分数 0.18/0.70 🔧）。
- 概念迁移表 ⚠️：trigram≈字符级 n-gram 倒排；tsvector≈词级倒排；三者都能回答"搜什么"，但**更新代价与排序质量互斥**——PG 选 tsvector+GIN 保吞吐、pg_trgm 保灵活；SQLite FTS5 是影子表重灌；DuckDB 是批式重建索引。工业上"搜索下沉专用引擎（ES/Meilisearch ⚠️）"仍是大数据量默认解——对位盘上 [../Elasticsearch_The_Definitive_Guide/00-总览与阅读地图.md](../Elasticsearch_The_Definitive_Guide/00-总览与阅读地图.md)。

## 5. psql 高级技巧精选（⚠️+✅ 书外延伸）

- **\gset 变量赋值**（✅ app-psql 页）：`SELECT current_database() AS db \gset` → 后续 `\echo :db` 使用——脚本化运维利器。
- **\watch 实时监控** ⚠️：`SELECT count(*) FROM pg_stat_activity \watch 5`——每 5 秒刷新查询，轻量监控。
- **\copy vs COPY** ⚠️+✅：`\copy` 在客户端执行（无需超管权限）、`COPY` 在服务端执行（需文件在服务器文件系统）——迁移脚本首选 `\copy`。
- **条件执行** ⚠️：`\if ... \elif ... \else ... \endif`（PG 10+ ✅ app-psql 页）——psql 脚本支持条件逻辑。
- **\gexec** ⚠️+✅：执行查询结果中的每条结果作为 SQL——批量操作的元命令（如动态生成 VACUUM 语句）。
- 🔧 DuckDB CLI 也有 `.watch` 等元命令（🔧 非 PostgreSQL 行为）；SQLite `.dump` 导出全库 SQL 是独特优势（🔧）。

## 6. 全文检索工具链纵深（⚠️+✅）

- **PG 内置 FTS**（✅ https://www.postgresql.org/docs/current/textsearch.html ）：
  - `to_tsvector('english', body)` → 词位向量；`to_tsquery('english', 'index & btree')` → 查询；
  - `@@` 匹配操作符；`ts_rank` / `ts_rank_cd` 排序函数；
  - GIN 索引加速（`CREATE INDEX idx_fts ON docs USING gin(to_tsvector('english', body))`）⚠️+✅。
- **中文分词** ⚠️：`zhparser` 扩展（基于 SCWS 分词 ⚠️）——内置 FTS 默认按空格/标点分词不支持中文。
- **pg_trgm 补充**（✅ pgtrgm.html）：
  - `similarity('postgresql','postgre')` → 0.5+（⚠️ 具体值以实跑为准）；
  - `word_similarity` 适合短语搜索（子串相似度 ⚠️）；
  - GiST 索引适合 `ORDER BY similarity` 的 KNN 查询；GIN 索引适合 `%` 过滤 ⚠️+✅。
- 🔧 对照：SQLite FTS5 用 `MATCH` + `bm25()` 排序（🔧 py_fts.out 实测）；DuckDB fts 扩展 BM25（🔧 duck7.out 实测）——PG 的 FTS 优势在 GIN 索引+MVCC 并发读。

## 7. 迁移工具全景（⚠️ 书外整理）

| 源 → 目标 | 工具 | 特点 |
|---|---|---|
| MySQL → PG | pgLoader ✅ | schema+数据+类型映射一把梭 |
| Oracle → PG | Ora2Pg ⚠️ | Perl 实现，PL/SQL→PL/pgSQL 转换 |
| SQLite → PG | pgLoader / `.dump`+sed ⚠️ | 小库可直接 SQL 脚本适配 |
| CSV/JSON → PG | COPY / `\copy` ✅ | 高速装载（→ [03 号文件](03-基础语句_DDL与DML.md)） |
| PG → PG（跨版本） | pg_upgrade ✅ / 逻辑复制 ⚠️ | 停机 vs 零停机两档 |
| PG → 异构 | 逻辑复制 + CDC ⚠️ | Debezium/Kafka Connect 消费变更流 |

- 迁移后校验清单 ⚠️：
  1. 行数对齐（`SELECT count(*)` 逐表比对）；
  2. 序列值对齐（`SELECT last_value FROM sequence` ⚠️）；
  3. 约束/索引数量一致（`\d` 逐表核查）；
  4. 应用冒烟测试（关键查询结果集比对）。

## 8. FDW 生态扩展（⚠️ 书外延伸）

- **postgres_fdw** ✅（核心 contrib）：PG-to-PG 联邦，支持写操作下推。
- **file_fdw** ✅（核心 contrib）：把 CSV/文本文件当表读——`COPY` 的只读联邦版。
- **第三方 fdw** ⚠️ 通例：
  - `redis_fdw`：Redis KV 当表读写；
  - `tds_fdw`：SQL Server 联邦；
  - `mysql_fdw`：MySQL 联邦（⚠️ 维护状态需查仓库活跃度）；
  - `aws_s3` / `multicorn`：对象存储/S3 当表读——数据湖场景。
- **FDW 性能守则** ⚠️：
  - 下推（pushdown）是生死线——谓词/JOIN/聚合推到远端执行 vs 全量拉到本地过滤，性能差百倍 ⚠️+✅；
  - `IMPORT FOREIGN SCHEMA` 批量导入远端表定义（✅ postgres-fdw 页）；
  - 大表联邦查询加 `LIMIT` 或物化到本地临时表 ⚠️。
- 🔧 SQLite ATTACH（🔧 第 3 节已实测）=文件级联邦；DuckDB 扫描器扩展（🔧 postgres_scanner/parquet_scanner）=进程级联邦——PG postgres_fdw 是三者中唯一网络级+优化器感知的方案。

## 9. 运维观测工具补遗（⚠️ 书外整理）

- **pg_stat_kcache** ⚠️：扩展 pg_stat_statements，补充每查询的系统/CPU 时间+磁盘读——性能分析精细化。
- **pg_wait_sampling** ⚠️：采样等待事件分布——定位"时间花在哪种等待"（锁/IO/LWLock）。
- **pg_visibility** ✅（核心 contrib）：可见性映射观测——`pg_visibility_map_summary()` 查每表可见/冻结页数，配合 VACUUM 调优。
- **pg_buffercache** ✅（核心 contrib）：共享缓冲区内容透视——`SELECT c.relname, count(*) AS buffers FROM pg_buffercache b JOIN pg_class c ON b.relfilenode=c.relfilenode GROUP BY c.relname ORDER BY buffers DESC;` ⚠️。
- 🔧 DuckDB 有 `pragma_storage_info()` 系列（🔧 非 PostgreSQL 行为）；SQLite 有 `PRAGMA database_list` / `PRAGMA page_count`（🔧）——PG 的观测扩展族是服务器引擎中信息量最丰富的。

## 核心概念速览（中英对照）

1. **pgLoader** — MySQL/SQLite→PG 搬运工：schema+数据+类型映射一把梭 ✅（API 200）。
2. **三元组** — trigram：pg_trgm 的最小检索单元，`%` 相似度算符+索引化 LIKE。
3. **word_similarity** — 词级相似度：短语匹配的调优旋钮 ⚠️。
4. **FDW** — 外部数据包装器：把任意后端伪装成表的扩展协议。
5. **CREATE SERVER / USER MAPPING / FOREIGN TABLE** — 联邦三件套（✅ ch19 代码骨架）。
6. **下推** — pushdown：把谓词/JOIN 送到远端执行，fdw 性能生死线 ⚠️+✅。
7. **psql 元命令** — \d/\gset/\i：脚本化运维的正统工具。
8. **pgAdmin 4** — 官方 GUI ✅（pgadmin.org 200）。
9. **pgBadger** — 日志分析器：csvlog 的报表出口 ⚠️。
10. **amcheck** — B 树一致性体检 ✅（同 Ch15 演练闭环）。
11. **FTS5/BM25** — 对照系：SQLite 倒排影子表 🔧 / DuckDB BM25 打分 🔧 / PG tsvector+trgm ⚠️+✅。
12. **多目录** — catalog/ATTACH：SQLite/DuckDB 的轻量联邦 🔧。
