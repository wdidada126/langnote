# 09 · 扩展生态：给数据库装插件（原书第 12 章）

> 对应原书 Ch12 *Extending the Database – the Extension Ecosystem*（✅ 章题）。
> 实证 ✅：docker `chapter_12/init/080-extensions.sh`（批量装扩展）+ 自制扩展 **tagext**：`tagext--1.0.sql` 与升级脚本 `tagext--1.0--1.1.sql` 双文件实抓——本章既教"用生态"也教"造生态"，且专门演示了**版本升级路径**。

## 1. 扩展的对象学：CREATE EXTENSION 装了什么（⚠️+✅）

- 定义：扩展=**打包的 SQL 对象集 + 可选共享库**，三件套：
  - `name.control`：default_version/relocatable/superuser 等元数据；
  - `name--ver.sql`：安装脚本；
  - `name.so`：C 代码载荷（可选）
  （✅ https://www.postgresql.org/docs/current/extend-extensions.html ）。
- `CREATE EXTENSION name [WITH SCHEMA s]`：对象整体登记、可 `DROP EXTENSION` 整体卸载——数据库侧的"包管理" ⚠️+✅。
- 货架与账本：`pg_available_extensions`（可装）、`pg_extension`（已装）、`\dx` 元命令（⚠️+✅ 同页）。
- 升级链：`ALTER EXTENSION tagext UPDATE TO '1.1'` 沿 `tagext--1.0--1.1.sql` 迁移——本书用自制扩展把"扩展是**有版本谱系的软件**"钉成一等观念 ✅（树实证）。
- contrib=官方准扩展货架 ✅ https://www.postgresql.org/docs/current/contrib.html （hstore/citext/pg_trgm/bloom 等，后章反复取用）。
- 预载类扩展：需启动期挂钩（执行器钩子/后台 worker/统计采集）者必须进 `shared_preload_libraries` **且重启**——pg_stat_statements、auto_explain 是代表（⚠️+✅ https://www.postgresql.org/docs/current/pgstatstatements.html 、https://www.postgresql.org/docs/current/auto-explain.html ；参数机制 https://www.postgresql.org/docs/current/config-setting.html ）。

## 2. 自造扩展最小闭环（本章实操 ⚠️ 据实抓文件名重构）

1. 写 SQL 载荷：域/函数/操作符（tagext 教学对象=标签类型族 ⚠️ 推断自命名）；
2. 写控制文件（default_version='1.0'、relocatable=true…）；
3. 投放 `$SHAREDIR/extension/`（`pg_config --sharedir` 定位 ⚠️）；
4. `CREATE EXTENSION tagext;` 验证 → 加 1.1 脚本 → `ALTER EXTENSION ... UPDATE`；
5. C 语言扩展：`PG_MODULE_MAGIC`、`_PG_init`、`LANGUAGE c` 绑定（✅ https://www.postgresql.org/docs/current/xfunc-c.html 200 已验）。
- 依赖声明 `requires = 'hstore'`、`schema` 归属与权限位（超级用户限制 `superuser=false` 放行）⚠️+✅ extend-extensions 页。

## 4. 🔧 类比实测 A：扩展加载的三种世界（duck6.out / sq7.out / py_fts.out 🔧）

```text
DuckDB 1.5.5:
  SELECT extension_name, installed, loaded FROM duckdb_extensions();
  -> fts:(F,F)  icu:(T,T)  json:(T,T)  postgres_scanner:(T,F)
  INSTALL fts; LOAD fts;      # 两步制：自动下载 + 会话装载（实测成功）
SQLite (Android CLI 3.50.6):  .load -> "unknown command or invalid arguments"（构建裁掉装载器）
SQLite (python 3.45.3):       FTS5 已编入内核 -> CREATE VIRTUAL TABLE ft USING fts5(body) 成功
```

- 三种供给链 ⚠️：DuckDB=**中心仓库+会话级**（版本随引擎）；SQLite=**编译期特性开关**（同一版本两个构建一个有 FTS5 一个没有——本机实证，租户运维最痛点）；PG=**库级绑定+目录对象**（CREATE EXTENSION 一旦执行全库可见、可 GRANT、可升级回滚）。
- **非 PostgreSQL 行为**声明：前二为实跑；PG 行以 extend-extensions.html 为据 ✅。

## 5. 🔧 类比实测 B：拿 fts 扩展开刀——装完就能全文检索（duck7.out 🔧）

```text
> INSTALL fts; LOAD fts;
> PRAGMA create_fts_index('docs','id','body');
> SELECT id, fts_main_docs.match_bm25(id,'wal checkpoint') FROM docs;
  (1, 0.185...)  (2, NULL)  (3, 0.701...)      # BM25 实打分
> ... WHERE fts_main_docs.match_bm25(id,'wal') IS NOT NULL  -> [(3,)]
```

- 扩展=新表函数/新 PRAGMA 的注入——与 PG contrib"新类型/新索引/新操作符"同构（⚠️+✅ 文档口径）；
- 该实验同时预演了 Ch19 的 pg_trgm/全文话题（→ [13-常用工具与实用扩展.md](13-常用工具与实用扩展.md)）与 Ch12 的 GIN 底座概念（✅ https://www.postgresql.org/docs/current/textsearch.html ）；
- SQLite 侧对照：`MATCH 'wal OR btree'` + `highlight()` 返回 `[wal]`（py_fts.out 🔧）。

## 7. 本章自测（重构版；题目自拟 ⚠️）

1. **问**：扩展与裸 SQL 脚本的本质差别？**答**：目录登记+版本链+整体装卸=包管理。
2. **问**：pg_stat_statements 为何要预载？**答**：挂钩执行生命周期，需 shared_preload_libraries+重启 ⚠️。
3. **问**：`ALTER EXTENSION x UPDATE` 依据什么找脚本？**答**：version 脚本链（tagext--1.0--1.1.sql ✅）。
4. **问**：SQLite 的 FTS5 为何"有人有有人没有"？**答**：编译期开关，随发行构建（🔧 本机双构建实证）。
5. **问**：DROP EXTENSION CASCADE 危险在哪？**答**：连带删除其上用户对象 ⚠️。

## 8. 扩展的版本管理与升级路径（⚠️+✅）

- **版本脚本链**（✅ extend-extensions 页）：`name--1.0.sql`（基线）→ `name--1.0--1.1.sql`（增量）→ `name--1.1--2.0.sql`（大版本）——`ALTER EXTENSION x UPDATE TO '2.0'` 自动沿最短路径迁移。
- **default_version 与 auto-upgrade** ⚠️：`.control` 文件中 `default_version` 决定 `CREATE EXTENSION` 默认安装的版本；升级需显式 `ALTER EXTENSION`。
- **回滚策略** ⚠️：扩展升级失败=目录对象半新半旧——**先 pg_dump 再升级**是铁律；无 `ALTER EXTENSION ... DOWNGRADE` 原语（需手工执行反向脚本 ⚠️）。
- **relocatable** ⚠️+✅：`relocatable=true` 的扩展可 `ALTER EXTENSION x SET SCHEMA new_schema` 搬家；多数扩展 `relocatable=false`（对象间有跨模式依赖）。
- 🔧 DuckDB 扩展无版本升级链（🔧 非 PostgreSQL 行为）——`INSTALL fts` 永远拿当前引擎匹配版本；SQLite 扩展=编译期开关更无运行时升级概念。

## 9. 扩展安全与平台化（⚠️+✅）

- **trusted vs untrusted** ⚠️+✅（extend-extensions 页）：`trusted=true` 扩展（如 hstore/pg_trgm）允许非超管安装；`trusted=false`（如 plpython3u）需超管——"u"后缀=unrestricted ⚠️。
- **平台产品启示** ⚠️：Supabase/Neon 等多租户平台只开放 trusted 扩展给用户自助安装——这是 Ch12 扩展知识的产品化落地。
- **扩展依赖冲突** ⚠️：`requires = 'postgis, pg_trgm'` 声明——安装时自动检查依赖存在但**不自动安装依赖**（需手工先装 ⚠️）。
- 🔧 对照：DuckDB 扩展安装无权限分层（🔧 任何用户可 INSTALL/LOAD）；SQLite 加载扩展=文件系统访问（🔧 `.load` 受 OS 权限控制）。

## 核心概念速览（中英对照）

1. **扩展** — extension：SQL 对象包+控制文件+可选 .so。
2. **控制文件** — .control：版本/可重定位/权限元数据。
3. **升级脚本链** — extension version scripts：1.0→1.1 迁移路 ✅ 实证。
4. **contrib** — 官方附加模块货架 ✅。
5. **shared_preload_libraries** — 启动预载：钩子类扩展前置。
6. **pg_available_extensions** — 货架视图。
7. **LANGUAGE c** — C 扩展：PG_MODULE_MAGIC 起手 ✅。
8. **REQUIRES** — 依赖声明：包管理思想。
9. **BM25** — DuckDB fts 排序函数（🔧 实跑）；PG 对应 ts_rank 族 ⚠️。
10. **GIN** — 倒排通用索引：全文/数组/JSONB 公共底座 ⚠️+✅。
11. **pgvector** — 向量货架 ✅（API 200）。
12. **会话级 vs 库级装载** — INSTALL/LOAD(DuckDB) vs CREATE EXTENSION(PG) vs 编译期(SQLite) 🔧。

## 最新演进与工业实践

- **pgvector 线** ✅（仓库 200 实抓）：0.7+/0.8 的 halfvec/iterative scan 使 PG 成为廉价向量库主流；PG 18 文档站收录向量实践 ⚠️——Ch12 读毕请以 pgvector README 为最新教范。
