# 06 · The Core C API（核心 C 接口）

> 原书第 6 章（Crossref 章题 ✅：`..._6` "The Core C API"）。小节划分 ⚠️ 推定。
> 🔧 说明：本章不编 C 程序（避免 repo 内构建产物），而是用 Python 内置 sqlite3 作为
> **同一 C 接口的受控观察窗**——prepare/step/finalize、错误码、busy、authorizer、
> progress handler、backup 全部直达 C 层语义；无法经 Python 触达的部分（sqlite3_open_v2

## 1. 本章在 2010 年的语境

2010 年的"核心 C API 课"围绕三代接口的新旧交替展开：

1. **打开/关闭**：`sqlite3_open/_16/_ex`；`sqlite3_close` 在 3.6.x 时代**不能**在有未 finalize
   语句时调用（3.7.x 起允许并返回 SQLITE_BUSY ✅ changelog 通读所得 ⚠️ 未逐句核）。
2. **执行三形态**：`sqlite3_exec`（回调式一行流）、老式 `sqlite3_prepare`(遗留，书中已劝退)、
   **`sqlite3_prepare_v2`**（3.5.0 引入 ⚠️ 通识；书时代的主流正解：语义=完整 SQL 编译，
   schema 变更自动重备）。
3. **step/column 循环**：`sqlite3_step` → `SQLITE_ROW`/`SQLITE_DONE`；`column_text/int/double/blob`
   + 类型查询；**取列一律按索引，按名是性能陷阱**。
4. **错误双通道**：`sqlite3_errcode`(主码) vs `sqlite3_extended_errcode`(扩展码)——书中给了
   整页码表；`SQLITE_BUSY`/`SQLITE_LOCKED` 之辨。
5. **绑定参数**：`sqlite3_bind_*` 按 1 起始索引；`sqlite3_reset` 复用语句。
6. **备份 API（2010 新物种）**：`sqlite3_backup_init/step/finish`——热备正解，3.6.11 刚随
   changelog "Added the hot-backup interface" 登场 ✅（原句），本书 2e 恰好差一步没讲上。

## 2. 精读要点（重构）

- **"V2 的 schema 自愈"是本章的技术分水岭**：老 prepare 缓存的是 VDBE 程序，表结构一变即
  SQLITE_MISUSE 风险；v2 缓存 SQL 文本、失效自动重编译——书中所有"重备循环"样板代码的根因。
- `sqlite3_complete()` 判语句完整性：以**分号收尾**为必要（🔧 E6：`'SELECT 1;'`→True，
  `'SELECT 1'`→False）——2010 手写 REPL 的标准零件。
- **column_* 返回值的生命周期**：文本/二进制指针在语句步进前有效，留存必须拷贝——嵌入式
  内存受限场景的头号事故源（⚠️ 书叙述转述，✅ 官方 c3ref 页同源规则）。
- busy handler 与 `sqlite3_busy_timeout` 互斥设置、后者是前者的包装（✅ [c3ref/busy_timeout.html](https://www.sqlite.org/c3ref/busy_timeout.html) 200）。

## 3. 🔧 实测（E6）：经 Python 窗口的 C 语义

| C 概念 | 观察 | 数字 |
| --- | --- | --- |
| 扩展错误码 | Python 3.11+ 异常直挂 C 码 | `sqlite_errorcode=2067`, `sqlite_errorname='SQLITE_CONSTRAINT_UNIQUE'`（主码 19+子码，书时代要调 extended_errcode） |
| busy 协议 | 两连接对撞 | `busy_timeout=0`：0.000 s 即 `SQLITE_BUSY`；`=2000`：等对端提交，0.534 s 成功 |
| idle 事务的锁足迹 | 写失败仍持 SHARED → 对端 COMMIT 被挡 | 修法是显式 end 事务（🔧 两次失败的实验过程即证据 ⚠️ 详见 exp_all.py 注释） |
| authorizer 回调（sqlite3_set_authorizer） | Python `set_authorizer` 直通 | DROP TABLE 被 DENY → `DatabaseError: not authorized`；期间授权器观察到 **5 个动作事件** |
| progress handler（sqlite3_progress_handler） | 每 20 个 VM 指令回调 | 三路笛卡尔积查询中回调 **4 次**——首次实证"VDBE 按指令计步"（与 11 章 EXPLAIN 对读） |
| 在线备份 API | `Connection.backup(dst, pages=16)` | 12 KB 库 0.125 s、src=dst=3 行；pages 参数即 C 层 `sqlite3_backup_step(n)` 的页粒度 |
| sqlite3_complete | 模块级函数 | True/False 如上述 |
| total_changes | 语句级计数 | 1（受约束失败不计 ✅ 语义） |

## 5. 常见误区

1. **`sqlite3_prepare_v2` 的 BUSY 语义**：准备期 schema 失效返回 `SQLITE_SCHEMA`（v2 内部自动
   重试，老 API 才要手写循环）——书中"重备样板"在今天属于多余代码（⚠️ 转述官方 FAQ）。
2. 把 `SQLITE_BUSY`（跨连接文件锁）与 `SQLITE_LOCKED`（同连接表级闩锁，如本册 E5 的
   `wal_checkpoint` 在事务内踩的 `database table is locked` 🔧）混为一谈——E5/E6 两种子都抓到了。
3. 备份时假设 pages=全部 ⇒ 一次性锁读事务过长；默认 -1 全拷与分 16 页（🔧 E6）之间是
   写者停顿时间的取舍。
4. 以为 authorizer 只拦 DDL ⇒ 每个列访问都过回调（🔧 E6：3 行 SELECT 计 5 事件）。

## 8. 一次查询的 API 时序（把本章零件串成线）

```text
open ─(flags/URI)─► prepare_v2(sql) ─► [授权器回调：每个动作事件 🔧 5 次/3 行 SELECT]
                       │                    progress_handler 每 N 指令一哨 🔧 4×20
                       ▼
        bind_*(1..n) ─► step ─SQLITE_ROW─► column_*（指针即时拷贝！）
                       │
                       └─SQLITE_DONE─► reset（复用）─► finalize
提交点：busy 协议与 journal 协议在此接管（05 章矩阵）
备份旁路：backup_init ─► step(pages) 🔧 16 页粒度 ─► finish
```

## 9. 本章自检卡（一问一答）

1. Q：v2 相比老 prepare 的核心差异？ A：schema 失效自动重备（缓存 SQL 文本）。
2. Q：`sqlite3_close` 前必须？ A：finalize 所有 stmt（3.7+ 可 BUSY 返回，v2 式宽容）。
3. Q：区分 BUSY/LOCKED 的一句话？ A：别人挡我=BUSY，我挡我=LOCKED。
4. Q：complete() 的判定标准？ A：分号收尾的完整语句（🔧 True/False）。
5. Q：text 列指针何时失效？ A：下一次 step/reset；留存须拷贝。
6. Q：绑定位次从几开始？ A：1；列位次从 0。
7. Q：total_changes 计失败 DML 吗？ A：不计（🔧 约束失败后仍 1）。
8. Q：授权器能拦 SELECT 列级吗？ A：能（code=SQLITE_READ + 列名参数，🔧 事件计数佐证）。
9. Q：progress handler 返回非零会？ A：中断当前语句（Abort-on-N-onzero 语义 ⚠️ 页为准）。
10. Q：在线备份与拷贝文件的本质差别？ A：备份 API 在锁协议内逐页取一致快照（05 章教训的官方解）。

## 核心概念速览（中英对照）

- **prepare/step/finalize** — 预备-步进-终局：SQLite C API 的主循环三拍。
- **prepare_v2** — schema 自愈版预备接口：书时代的新主流。
- **扩展错误码** — extended error code：SQLITE_CONSTRAINT_UNIQUE=2067 这种主+子编码（🔧）。
- **busy handler / busy_timeout** — 文件锁重试策略（🔧 0 s 立败 vs 0.534 s 等到）。
- **SQLITE_BUSY vs SQLITE_LOCKED** — 跨连接锁忙 vs 同连接表闩锁（🔧 E5/E6 双例）。
- **authorizer** — 授权回调：五类动作事件、DENY 即 "not authorized"（🔧）。
- **progress handler** — VM 指令进度回调：每 N 步一哨，可中断长查询（🔧 4 次/20 步）。
- **在线备份接口** — hot-backup（3.6.11 ✅）：backup_init/step/finish 三段式。
- **sqlite3_complete** — 分号判全：REPL 零件（🔧 True/False）。
- **total_changes** — 成功 DML 计数器：约束失败不增（🔧）。
- **column_* 生命周期** — 指针随步进失效，留存须拷贝（⚠️ 书重点）。
- **绑定参数 1 起始** — bind index base 1：与列 0 起始相反。
- **close_v2** — 容忍未 finalize 语句的析构式关闭。
- **sqlite3_exec** — 回调式一步到位：小脚本便利贴。
- **受控观察窗** — 本册方法论：Python 绑定 = 同一 C 接口的可脚本化探针。
