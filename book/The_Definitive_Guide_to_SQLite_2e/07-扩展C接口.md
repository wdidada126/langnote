# 07 · The Extension C API（扩展 C 接口）

> 原书第 7 章（Crossref 章题 ✅：`..._7` "The Extension C API"）。小节划分 ⚠️ 推定。
> 🔧 方法同 06 章：以 Python `create_function/create_aggregate/create_collation` 为观察窗
> （它们就是 `sqlite3_create_function*` 的直译），虚表/可加载扩展给语义级对位 + 边界声明。

## 1. 本章在 2010 年的语境

SQLite 的哲学是"内核极小，能力外延"——第 7 章教读者亲手补能力：

1. **标量/聚合函数注册**：`sqlite3_create_function`（一次注册标量+聚合+析构角色）；
   参数个数/编码/`SQLITE_UTF8`/旗标（2010 尚无 `SQLITE_DETERMINISTIC`，3.8.3 起有 ⚠️ 通识）。
2. **自定义排序规则**：`sqlite3_create_collation`——书例是西语/拼音排序与"半自动 NOCASE"。
3. **可加载扩展**：`sqlite3_enable_load_extension` + `sqlite3_load_extension`，初始化函数
   `sqlite3_extension_init` 命名规约；**发行版默认不编译该能力**（安全考虑），书时代就强调
   "自己编译才玩"——2026 依然如此（🔧 E7 证据）。
4. **虚拟表框架**：`sqlite3_create_module` + `xConnect/xBestIndex/xFilter` 生命周期——本章的
   珠峰，FTS/RTREE 皆为其用户；2010 年 CSV 虚表（后期扩展）与 fileio 都还没进官方树 ⚠️。
5. **变更通知钩子**：`sqlite3_commit_hook/rollback_hook/update_hook`（3.6.x 时代已齐 ⚠️ 引入
   版本按 c3ref 页头"实验性→转正"叙事推定）与 `sqlite3_get_table` 便利（书中有专节，今日官方
   弃用推荐 stmt——⚠️ 转述）。

## 2. 精读要点（重构）

- **函数注册是连接级的**：同进程多连接要各注册一遍——书中"全局注册 helper"模式今天照用。
- 聚合函数的 `finalize` 只准调用一次、step 内不得再跑 SQL（回调重入陷阱，⚠️ 转述官方
  threadless 告诫）。
- `REGEXP` 是"预留插槽"教科书例：操作符内建、语义外包（🔧 E7 复现：先报错后注册即通过）。
- 虚拟表把"表"从存储概念变成**计算接口**：xBestIndex 决定谓词下推——2026 年扩展生态
  （sqlite-utils/DAV/加密层）仍按此框架说话。

## 3. 🔧 实测（E7）：扩展机制的行为与成本

| 观察 | 数字/结果 |
| --- | --- |
| 标量 UDF `cube(x)` 非确定版：`count(DISTINCT cube(v))`（9 个不同输入） | 回调 **9 次**（无缓存，逐输入一次） |
| 同名函数注册为 `deterministic=True` | 仍 **9 次**——该查询形态下未触发额外折叠；结论：**旗标是"许可"不是"保证"**（优化器自行取舍 ✅ 诚实记录） |
| 自定义聚合 `mymode`（众数） | `SELECT mymode(v%5)` → `(1,)`：step/finalize 协议直用 |
| 自定义 collation `REVERSED` | 排序输出 `'a4,a3,a2,a1'` ✅ |
| 可加载扩展 | `hasattr(conn,'enable_load_extension')=True`，但本发行版 compile_options **不含** `SQLITE_ENABLE_LOAD_EXTENSION`（🔧 `in opts → False`）——Python 内置版=不可装载，书的"要自己编"今天仍成立 |
| `REGEXP` | 未注册：`no such function: REGEXP`；注册 2 参 UDF 后 `SELECT 'abc' REGEXP 'a..'` → `(1,)` ✅ 十年一贯 |
| `PRAGMA module_list` | fts3/fts4/fts5/fts5vocab/fts4aux/fts3tokenize/rtree/rtree_i32/json_each/json_tree 共 10 模块——**当年"自己写扩展"的 FTS/RTREE 已是出厂件** |

## 4. 2010 语境 vs 2026 现状对位

| 本书设定（3.6.x） | 2026 现状 | 锚点 |
| --- | --- | --- |
| FTS3 是要自己编进来的扩展 | fts3/4/5 + rtree + json 全内置于常见发行（🔧 module_list）；FTS5 于 3.9.0 进 amalgamation ✅ changelog | — |
| 函数注册无确定性旗标 | `SQLITE_DETERMINISTIC`（3.8.3 ⚠️）；Python 3.8+ `deterministic=`（🔧 可传） | — |
| 虚表要 C 才能写 | 仍是 C 层的活（Python 无 create_module 面）✅ 边界声明；内置虚表种类大增：sequence/csv 类外部包、dbstat（🔧 姊妹册 CLI 证据 ⚠️ 版本未锚） | — |
| commit/update hook 是唯一变更通知 | 新增 pre-update hook（3.13.0 ⚠️ 转述）、session/crashtest 扩展面、WAL 下 changeset 系列 | — |
| 扩展安全=自己负责 | `SQLITE_DBCONFIG_TRUSTED_SCHEMA`（3.26+ ⚠️）应对注入式虚表劫持；官方把"扩展默认不可信"写进威胁模型（⚠️ 转述） | — |

## 5. 常见误区

1. 以为 `deterministic=True` 必有缓存红利 ⇒ 🔧 E7 同查询 9→9 次；它只是允许常量折叠/索引
   表达式使用的许可证。
2. 在发布版 Python/系统库里期待 `load_extension` ⇒ CPython 发行不带（🔧 证据）；需要时走
   `pysqlite3-binary`/`apsw` 一类自带装载能力的发行（⚠️ 生态名转述）。
3. 注册函数忘处理 NULL/类型分支 ⇒ C 层 `sqlite3_value_type` 分派缺失=崩溃；Python 包装帮你
   做了翻译，书中 C 教训在 2026 的 C 用户身上原样复发。
4. 把 collation 用在表达式索引上期待全表序 ⇒ 排序规则绑定在列/索引定义时点。

## 9. 本章自检卡（一问一答）

1. Q：`deterministic=True` 买到什么？ A：优化器使用权，不保证省调用（🔧 9→9）。
2. Q：CPython 能 load_extension 吗？ A：方法在、能力没编（🔧 options 无旗标）。
3. Q：REGEXP 报错的第一修复？ A：注册同名 2 参 UDF（🔧 全流程复现）。
4. Q：聚合 step 里能再执行 SQL 吗？ A：禁忌（重入），收集后 finalize 外做。
5. Q：连接 A 注册的函数 B 可见吗？ A：不可见——注册=连接级。
6. Q：FTS5 当年今天各要几步安装？ A：当年重编译；今天 `CREATE VIRTUAL TABLE`（🔧 一行成）。
7. Q：xBestIndex 输出影响什么？ A：谓词下推与是否 SCAN（对照 🔧 E9 `SCAN m`）。
8. Q：collation 能替代函数索引吗？ A：能改变 ORDER BY 走索引（03 章表达式索引对读）。
9. Q：虚表能进触发器吗？ A：高安全模式下需 INNOCUOUS 标记（✅ changelog 3.44 片段）。
10. Q：书里 2010 扩展与今日 SQLite 版本兼容？ A：ABI 稳定承诺在，但旗标/模块集差异需重估 ⚠️。

## 核心概念速览（中英对照）

- **UDF 注册** — scalar function registration：create_function 连接级生效（🔧 9 次回调）。
- **确定性旗标** — SQLITE_DETERMINISTIC：许可优化器折叠，非缓存承诺（🔧 9→9）。
- **自定义聚合** — aggregate UDF：step/finalize 两拍（🔧 mymode=(1,)）。
- **排序规则** — collation：比较函数外置（🔧 REVERSED 逆序）。
- **REGEXP 插槽** — 内置操作符+外包函数（🔧 报错→注册→通过）。
- **可加载扩展** — loadable extension：发行版默认封死（🔧 compile_options 无旗标）。
- **虚拟表** — virtual table：xConnect/xBestIndex/xFilter 计算式表接口。
- **module_list** — 本库虚表模块注册表（🔧 10 件出厂内置）。
- **变更钩子** — commit/rollback/update hooks：书时代的事件三件套（⚠️ 未本机复现）。
- **sqlite3_get_table** — 便利取表 API：官方弃用方向 ⚠️（转述），本册未用。
- **xBestIndex** — 谓词下推决策点：虚拟表的灵魂回调。
- **trusted_schema** — 3.26+ 威胁模型开关 ⚠️：扩展时代的安保补丁。
- **回调重入** — callback reentrancy：钩子内再跑 SQL 是经典炸点。
- **能力外延** — core minimal, extensions maximal：本章标题的哲学注脚。
