## 1. 本章在 2010 年的语境

收官章把引擎掀开给"会用的人"看：

1. **B 树存储**：每张表=一棵 rowid B 树、每个索引=一棵键 B 树；页型四件套
   （interior/leaf × table/index）；溢出页（overflow）与 defragment。
2. **VDBE（Virtual Database Engine）**：SQL→字节码→单指令一步的寄存器机；
   `sqlite3_stmt` 就是程序；`EXPLAIN` 看指令、`EXPLAIN QUERY PLAN` 看计划（2010 版 EQP 输出
   简陋：只有 "SCAN/SEARCH" 一行流——🔧 今天的 EQP 也是，见 E11）。
3. **pager/锁层复访**：05 章协议在源码层的归属（pager.c/os_*.c）。
4. **"New Features" 前瞻节**：2010 年的预告清单（WAL 首发即在 3.7.0 ✅、无行存储表、
   FTS4/RTREE 演进、视图/触发器增强 ⚠️ 具体小节清单推定）——这是全册最需要"对位验收"的地方。

## 2. 精读要点（重构）

- **VDBE 的诚实入门姿势是 `EXPLAIN`**：更新一行 rowid 表只需 26 条指令（🔧 E11），
  核心五连 `OpenWrite/SeekRowid/Column/Add/...New` 结构一目了然；06 章 progress handler
  的"每 20 指令回调 4 次"（🔧 E6）终于有了计量对象。
- **`Search versus Scan` 的全部世界观**：EQP 的 `SEARCH t USING INTEGER PRIMARY KEY (rowid>?)`
  与 `SEARCH t USING COVERING INDEX ix (b=?)`（🔧 E11）就是"rowid 即聚簇、索引自带回表/免回表"
  两条定律的现代打印体。
- **统计与启发**：ANALYZE 产 `sqlite_stat1`（🔧 E11：`('t','ix','3 1')`——3 行、每 b 值 1 重复）；
  2010 无直方图，选择性靠"均匀分布假设"（姊妹册 🔧 已证 stat1 单行格式原样）。
- 前瞻节的史学价值：读懂"当年的下一步"才知道本书印刷墨迹未干世界就转弯了（对位表下节）。

## 3. 🔧 实测（E11+E6/E5 汇总）：VDBE 与格式的显微镜

| 观察 | 数字/结果 |
| --- | --- |
| `EXPLAIN UPDATE t SET b=b+1 WHERE a=2`（a=INTEGER PRIMARY KEY） | **26 条指令**；头部序列 `Init,Null,Noop,OpenWrite,Integer,SeekRowid,Rowid,OpenWrite,IsNull,Null,Column,Add,...`（rowid 直达 + 索引双写结构清晰） |
| EQP（有索引 ix ON t(b)） | `SEARCH t USING COVERING INDEX ix (b=?)`（免回表） |
| EQP（rowid 范围） | `SEARCH t USING INTEGER PRIMARY KEY (rowid>?)`（聚簇定律） |
| 提交对文件头的原子影响 | file change counter +1/提交（🔧 delta=1；E1 的 2→3 独立复证）；version-valid-for=4 与提交计数同步（E11 末态） |
| ANALYZE | `sqlite_stat1 = [('t','ix','3 1')]`；表 t 行统计 '3 1' |
| `PRAGMA cache_size=-100` | 负值=KB 语义回显 `(-100,)`；page_size 4096 |
| `PRAGMA schema_version` | 三次模式操作后 =3（模式代际计数器活样本） |
| 指令计量互证 | progress_handler 每 20 指令回调 × 4 次（E6）≈ 笛卡尔积查询千级指令 ÷20 量级吻合 ✅ |

## 5. 常见误区

1. 把 EQP 当承诺：它是计划快照，ANALYZE 前后/参数值都会变计划（🔧 E11 两查询双计划）；
   上线判断要 `EXPLAIN` 级证据。
2. 以为 VDBE 指令≈CPU 指令：一步 VM 可能触发整页 I/O（SeekRowid 背后是 B 树下钻）——
   02 章 fsync 账单在微观层重演。
3. 把 `schema_version` 与 `schema cookie` 混用成一句：本质同一 PRAGMA 的今昔名（3.?.? 改名
   ⚠️ 版本未锚；🔧 E11 用新名可跑）。
4. 只读 2010 的"New Features"节就下结论：那半章是历史文件；对位表右列才是 2026 的现役特性。

## 7. VDBE 常见指令速查（对 🔧 E11 的 26 指令解剖台命名）

| 指令 | 职责 | 在 E11 UPDATE 程序中的角色 |
| --- | --- | --- |
| Init/End | 程序出入口 | 首条即 Init |
| OpenRead/OpenWrite | 开表/索引游标 | 两个 OpenWrite：数据树+ix 索引树 |
| Integer/SeekRowid/Rowid | rowid 直达定位 | `WHERE a=2` 的编译形态（聚簇定律） |
| Column/MakeRecord | 取列/组行 | 旧值读出与新行组装 |
| Add/Concat/... | 表达式求值 | `b+1` 即 Add |
| NewIdxRowid/IdxInsert/Delete | 索引维护 | ix 的旧键删+新键插 |
| Affinity/NotNull/IsNull | 类型与 NULL 防御 | 程序里的 IsNull=约束路径 |
| VOpen/VFilter... | 虚表一族 | 07 章回调的字节码化身 |
| Transaction/Commit | 事务节拍 | 触发 05 章锁协议升级 |

## 8. 优化器观察三动作（日常维护节拍，本册全 🔧）

1. **看**：`EXPLAIN QUERY PLAN`（🔧 SCAN↔SEARCH 一行判）；存疑再 `EXPLAIN` 数指令（🔧 26 条）。
2. **喂**：`ANALYZE` 产 stat1（🔧 '3 1'）；数据分布剧变后重喂。
3. **量**：progress handler 计步（🔧 E6 4×20）或 CLI `.timer`（🔧 E9 real 0.002 s）把直觉换成数。

## 9. 本章自检卡（一问一答）

1. Q：一条 UPDATE rowid 表动几棵树？ A：数据树+每受影响索引树（🔧 两 OpenWrite）。
2. Q：COVERING INDEX 为何快？ A：键里就有答案，免回表（🔧 E11 EQP 原话）。
3. Q：stat1 '3 1' 读法？ A：表 3 行、索引每首键平均 1 重复（✅ 格式通识）。
4. Q：rowid>? 计划行意味着？ A：B 树区间扫描，聚簇范围查询。
5. Q：change counter 和 WAL 兼容吗？ A：WAL 有自己代际机制，页 1 字段照写（🔧 E5/E11 语境 ⚠️ 细节以 fileformat 页为准）。
6. Q：VDBE 指令数≈性能？ A：只算 CPU 账，I/O 另算（05 章页账）。
7. Q：schema_version 何时 +1？ A：模式变更（🔧 3 次操作=3）。
8. Q：2010 "New Features" 节还值得读吗？ A：作为 roadmap 考古值得，作为依据不可——对位表先读。
9. Q：ANALYZE 需要常跑吗？ A：写多读分析场景定期；小库一次即可（🔧 E11 样本）。
10. Q：本册对"内部机制"的一贯读法？ A：协议（05）→ 接口（06/07）→ 指令（11），显微镜与账单互证。

## 核心概念速览（中英对照）

- **VDBE** — 虚拟数据库引擎：寄存器字节码机，stmt 即程序。
- **EXPLAIN** — 字节码反汇编（🔧 一次 UPDATE=26 指令）。
- **EXPLAIN QUERY PLAN** — 计划一行流：SEARCH/SCAN + 索引用法。
- **聚簇即 rowid** — INTEGER PRIMARY KEY 直达律（🔧 rowid>?）。
- **覆盖索引** — covering index：免回表（🔧 COVERING INDEX ix）。
- **sqlite_stat1** — ANALYZE 产物：'表行数 重复度' 朴素格式（🔧 '3 1'）。
- **溢出页** — overflow page：超长记录的溢出链（⚠️ 未实测）。
- **页四象限** — 内/叶 × 表/索引：B 树页型分类学。
- **file change counter** — 提交心跳（🔧 +1/commit）。
- **schema cookie/version** — 模式代际戳（🔧 =3）。
- **WITHOUT ROWID** — 键聚簇小表形态（🔧 E4 一例）。
- **pager** — 页缓存与锁的交接层（05 章协议主体）。
- **自动 checkpoint** — WAL 的 1000 页节拍（🔧 编译默认）。
- **前瞻节验收** — roadmap archaeology：2010 预告 vs 2026 现实的映射法。
- **指令≠I/O** — VM 一步背后可能是一棵树的下降。
