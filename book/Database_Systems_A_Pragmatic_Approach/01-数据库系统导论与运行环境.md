# 01 数据库系统导论与运行环境（原书第 1–2 章）

> 书目：《Database Systems: A Pragmatic Approach》，Elvis C. Foster & Shripad V. GodBole，Apress 2014，母 DOI `10.1007/978-1-4842-0877-9`。
> 证据级：章题/页区间/DOI ✅ Crossref 一手（_1: pp.3–11；_2: pp.13–27）；章首段 ✅ Springer 摘要逐字；小节展开 ⚠️ 据章题+首段+通行教学法重构；🔧 为 SQLite 3.45.3/DuckDB 1.5.5 类比实测，**非本书引擎（Oracle 10g 等）行为**。

## 1 本章定位

两章合成"开营仪式"：ch1 把学生迎进课程并画地图，ch2 拆开一台"数据库系统"看零件——人、软件、硬件、过程四件套。本书是教材不是专著，开篇即假定你先修过编程/数据结构/UI/软件工程（✅ 摘要原文），因此它花极少篇幅说服你"为什么要用 DBMS"，直接进入环境术语，为后面关系模型（ch3）与 Oracle 化 SQL（ch10–15）铺术语底。

## 2 ch1 内容主讲：Introduction to Database Systems

章首段逐字（✅ Springer 摘要）：

> "Welcome and congratulations on your entry to this course in database systems. The fact that you are in this course means that you have covered several fundamental topics in programming, data structures, user interface, and software engineering. Now you want to learn..."

可锚定的教学信号（⚠️ 截断后为重构）：

- **课程合同式开篇**：自学线（Self-Study）体例，作者向"学生与教学生的教授"双线说话（About 原文 ✅）。
- **数据库=软件系统的必需件+企业关键资源**（About 原文逐字锚点："It discusses the database as an essential component of a software system, as well as a valuable, mission critical corporate resource" ✅）——这句话是全书价值观：技术线（作为组件怎么建）与资产线（作为资源怎么管，呼应 ch21 管理、ch13 安全）并行。
- **理论实践平衡宣言**（About："mastery of the technique of combining and balancing theory with practice" ✅）：预告了本册 ch5/7/8 的数学面与 ch11–15、17 附录的工程面配比。
- 常见重构议题（⚠️）：数据与信息的区分、文件系统时代的痛点（冗余/不一致/程序-数据耦合）、数据库方法的好处、DBMS 一词的层次。

## 7 深挖与自测

### 概念辨析十问（自测，答案在上文）
1. 数据与信息差在哪一步？——差在"组织语境+加工"；DB 管数据，BI 管信息（ch24 回收）。
2. DBMS、Database、Database System 三层词各指什么？——软件、数据本体、软件+数据+人+规程的整体。
3. 文件系统翻身的四大战场？——冗余、不一致、程序-数据耦合、访问受限（即席查询/并发）。
4. 逻辑独立与物理独立各豁免哪类改动？——改概念模式豁免外视图；改存储豁免一切程序。
5. 三级模式两级映射谁维护？——映射存目录（ch14），DBMS 自动执行、DBA 授权改动。
6. Schema 会变、Instance 每秒都在变：哪个才是"库"的日常？——Instance；schema 是骨架。
7. 本书 ch20 说 Delphi 是"第二前端"，环境章的前端观是什么？——UI 属环境中的人机界面（ch6 展开）。
8. "关键任务资源"是技术论断还是管理论断？——后者；它决定全书把 ch21 管理列为专章。
9. 为什么先修假设数据结构？——索引实现（ch27）默认 B 树语言（✅ 摘要背书）。
10. 自学线教材的"课程合同"体现在哪句？——ch1 首段 welcome+先修清单（✅ 逐字）。

### 常见误区六条
- 把 DBMS 当"高级文件管理器"——忽略并发/恢复/授权三大件。
- 认为数据独立性自动成立——应用直连表结构即绕过映射，独立性当场失效。
- 把 schema 画完就冻结——业务演化要求变更管理流程（ch21）。
- 混淆 DBA 与开发者职责边界——视图/授权正是两界的合同纸（ch13）。
- 以为"上了云就不用管"——云只换运维主体，"资源必须被管理"的论断不变。
- 背三级抽象忘两级映射——抽象的全部价值在映射的自动化。

### 🔧 加餐：环境体检三步（SQLite 域，非本书行为）

- `sqlite_master` 行数对比模型评审记录（E6）——漂移=未走变更流程。
- 交付物标注"引擎+版本"水印：3.45.3/1.5.5 行为差异 E 组随时复现。

## 8 术语快卡与跨书对位

| 术语 | EN | 一句话定位 |
|---|---|---|
| 数据库 | Database | 按结构组织、可被多程序共享的持久数据集合 |
| DBMS | Database Management System | 在数据与用户之间居中：存储、安全、并发、恢复 |
| 数据独立性 | Data Independence | 应用不随存储结构/硬件变化而重写——本书卖点之一 |
| DDL | Data Definition Language | 描述"表长什么样"的语言（第 11 章正面展开） |
| DML | Data Manipulation Language | 描述"数据怎么查改"的语言（第 12 章正面展开） |
| 文件-记录-字段 | File/Record/Field | 本书导论用的最低层抽象台阶 |
| 数据字典 | Data Dictionary | "关于数据的数据"，第 14 章系统目录的前身 |
