## 2 重构模拟卷（七题，考点映射原章）

**Q1（ch3/4，概念）** 判别下列说法并改正："SQL 表就是关系；外键约束一经声明所有 DBMS 都会强制。"
**参考答案**：两错。SQL 表是 bag 且列有序（DISTINCT/EXCEPT 才回集合语义）；强制与否依引擎——🔧E1 实测 SQLite `PRAGMA foreign_keys` 默认 0、孤儿行 `(1,'ann',99,50.0)` 照收，而 DuckDB 默认执法（E2 `key "did: 99" does not exist`）。Oracle 系执法（⚠️ 本书口径）。

**Q2（ch4，规范化）** 平坦表 `enroll(sid, course_no, credit, prof_name, dept_name, dept_budget)`，FD：course_no→credit；(course_no,prof_name)→dept_name；dept_name→dept_budget。求 BCNF 分解。
**参考答案**：sid+course_no 为键；链式传递依赖→拆 `course(course_no,credit)`、`prof_course(course_no,prof_name)`、`profdept(prof_name,dept_name)`、`dept(dept_name,dept_budget)`、`enroll(sid,course_no,prof_name)`——dept_budget 两处传递即两刀。验证工具：E1/E2 把 dept_budget CHECK(>=0)+UNIQUE(dept_name) 落 DDL 跑通。

**Q3（ch7/8，代数⇄SQL）** 用代数与 SQL 各写"选修了'Eng'系全部课程的学生"。
**参考答案**：除法 `Enroll ÷ σdept='Eng'(Course)`；SQL 模板一 `GROUP BY sid HAVING COUNT(DISTINCT course_no)=(SELECT COUNT(*) …)`，模板二双 NOT EXISTS——🔧E3 的 `WITH t AS(…avg…) JOIN` 同构验证思路；实测域换成 emp/dept 后 CTE 版返回 `[(2, 110.0)]`。

**Q4（ch11，DDL 方言）** 写出 Oracle 10g 序列用法并给出 SQLite/DuckDB 等价物。
**参考答案**：`CREATE SEQUENCE s START WITH 10 INCREMENT BY 5`+`s.NEXTVAL`（⚠️ 本书方言口径）；🔧 等价：SQLite `INTEGER PRIMARY KEY AUTOINCREMENT`；DuckDB `CREATE SEQUENCE`+`nextval('s')`。差异点：SQLite 无独立序列对象（E1/E4 实测域均 ROWID 派生）。

**Q5（ch13，视图与安全）** `CREATE VIEW v_high AS SELECT name,salary FROM emp WHERE salary>10000;` 随后 `UPDATE v_high SET salary=salary-1;` 会发生什么（三引擎）？
**参考答案**：Oracle 简单视图可更（⚠️ 本书口径，key-preserved）；🔧SQLite 直接报错 `cannot modify v_high because it is a view`（E5——一切视图只读，须 INSTEAD OF 触发器；触发器改写实测成功 `(7,)`）；🔧DuckDB 报 `v2 is not an table`（E6d）。WITH CHECK OPTION 语义另需考试作答：改后行不得逃逸谓词。

**Q6（ch14/15，目录与局限）** 写查询列出"当前库所有表与视图及其 DDL 原文"（两引擎）。
**参考答案**：🔧SQLite `SELECT type,name,sql FROM sqlite_master WHERE name LIKE 'v%'`——视图定义原文逐字在册（E6）；DuckDB `SELECT table_name,column_count FROM duckdb_tables()`+`duckdb_views()`+`duckdb_columns()`（is_nullable 列；函数目录 `duckdb_functions()`=2948 个，E6/E6e）。

**Q7（ch22/24，综合案例）** 两部门各持一方言库，出"跨库联合报表"的最小方案与完整性风险。
**参考答案**：🔧E8b 双方案——SQLite 双 ATTACH 跨库 JOIN（`[('left','right')]`）或 DuckDB `ATTACH … (TYPE SQLITE)` 异构接入；风险：无全局原子提交/各自统计口径→回收 ch22 透明性清单与 ch24 清洗环节。案例展开 1 页，评分点=透明性×完整性×目录一致性。
