> 书目：《Database Systems: A Pragmatic Approach》，Elvis C. Foster & Shripad V. GodBole，Apress 2014，章 DOI `…_7`（pp.129–148）/ `…_8`（pp.149–162）。

## 1 本章定位

Division 一末段的"数学半场"：ch7 代数（怎么算）+ ch8 演算（算什么）。两章首段给出全书最硬的方法论表述（✅ 逐字）：

> ch7: "One of the reasons for the success and longevity of the relational model is that it is firmly grounded on mathematical principles (of linear algebra and set theory), which are well known and well documented. The (normalized) relational tables are by design, organized…"（截断）
> ch8: "This chapter discusses relational calculus as an alternate way of manipulating relations in a database. The partial college database, introduced in the previous chapter (figures 7-1 and 7-2) will be used as a frame or reference. It must be constantly borne in mind…"（截断）

信息量极大：**college database 图 7-1/7-2 是代数例库**；演算被定位为"另一条操纵关系的路"（过程式 vs 陈述式），且提醒"要始终铭记"某差异（⚠️ 截断处大概率是"演算结果仍是关系/安全表达式"）。

## 2 ch7 内容主讲（⚠️ 按标准代数八/九算子重构）

- 传统算子：并 ∪、差 −、交 ∩（可导）、笛卡尔积 ×。
- 专门算子：选择 σ、投影 π、重命名 ρ、连接 ⋉/⋈（自然/θ 连接）、除 ÷（"所有"类查询的代数表达）。
- **封闭性**：算子输入输出皆关系→可流水线索引化嵌套——ch10 会说"SQL 继承此性质"。
- 查询树与等价变换直觉（为 ch8/优化留钩）。

## 3 ch8 内容主讲（⚠️ 重构）

- **元组关系演算** `{ t | P(t) }`：谓词刻画行集合；∃/∀ 与连接/除法的对应。
- **域关系演算**：按列变量书写——表格演算/示例元素法（QBE 幽灵 ⚠️ 本册是否涉及无证据）。
- **安全表达式**：有限结果的谓词子集；代数=演算表达力等价（Codd 定理的课堂版，⚠️ 命名推测）。
- **映射到 SQL**：`{t | STUDENT(t) ∧ t.age>18}` → `SELECT * FROM student WHERE age>18`——这是本书"演算→SQL"叙事的最大实用动机（⚠️ 推断）。

## 4 🔧 代数算子的双引擎物化（非本书引擎）

把代数逐个翻译成可跑的 SQL（E3/E4 实测语料，college 域换 dept/emp 域）：

| 代数 | SQLite 3.45.3 / DuckDB 1.5.5 实现 | 实测读数 |
|---|---|---|
| σ 选择 | `WHERE did=10 AND salary>100` | EQP：无索引 `SCAN emp`→建索引后 `SEARCH … USING INDEX (did=? AND salary>?)`（E4） |
| π 投影 | `SELECT DISTINCT did` | bag→set 需显式 DISTINCT（两引擎都不自动去重——"表≠关系"再现） |
| ⋈ 连接 | `JOIN … USING(cid)` | 50万×5万 `o_norm JOIN c_norm` 157.26ms（E7） |
| − 差 | `EXCEPT`（SQLite 3.39+/DuckDB 均支持）（⚠️ 本工作区未单测，语法级陈述） | — |
| ÷ 除 | `GROUP BY + HAVING COUNT(*)=n` 或双 NOT EXISTS | 谓词演算 `∀` 的落地模板 |
| 流水线索引化 | CTE：`WITH t AS (SELECT did, avg(salary) av … ) SELECT … JOIN t WHERE salary>av` | E3 返回 `[(2, 110.0)]`——代数查询树的 SQL 同构 |

- ⚠️ Oracle 10g 的 `CONNECT BY`、MINUS（=差）是本册 SQL 章的方言预告——概览口径见 07/08 号文件。

## 6 教学与实操要点

1. "先画查询树，再写 SQL"：把代数当草稿纸用，SQL 是终稿——本书把 SQL 章排在代数后的深层原因。
2. 除法 ÷ 是面试分水岭：写得出双 NOT EXISTS 模板才算过。
3. 演算的价值一句话：**优化器的工作语言**（谓词下推=σ 提前），读任何引擎的 EXPLAIN 都需要它。

## 7 深挖与自测

### 概念辨析十问
1. 代数与演算的分野一句话？——过程式（怎么算：算子树）vs 陈述式（算什么：谓词）。
2. 封闭性为何值得单独强调？——"嵌套即流水线"的许可证；SQL 子查询继承此性。
3. θ 连接与自然连接差在哪？——θ 任意谓词+全列保留；自然=等值+合并去重复列。
4. 外连接"纯关系"吗？——否：NULL 填充行越出关系语义（ch15 局限回收）。
5. 除法到底算什么？——全称量词："包含全部"的键集——∀ 的代数化身。
6. 演算表达式何时"安全"？——每个量化变量被有限关系约束；否则答案无限。
7. 代数⇄演算等价给谁用？——给优化器：谓词下推=σ 提前、连接重排=× 结合的工程化。
8. HAVING 属哪个算子家族？——σ 的后置版（WHERE=前置 σ，分组后=HAVING）。
9. 投影后可能破键——暴露什么软肋？——键不随 π 遗传（ch4 依赖回收）。
10. ORDER BY 破坏代数吗？——破坏：代数输出集合，排序即列表化（bag/序之争）。

### 常见误区六条
- 把 SQL JOIN 当代数原生——它是"×+σ"的糖；自然连接才代数。
- 除法只会双 NOT EXISTS——GROUP BY/HAVING 计数版更贴优化器；两模板都练熟。
- 以为 EXISTS/IN 全等——NULL 让 NOT IN 恒空（三值逻辑）。
- 把视图当"存好的查询树"——存的是 SQL 文本（E6 sqlite_master 逐字证明）。
- DISTINCT 当开关无代价——bag→set=一次去重成本。
- 读不懂 EXPLAIN 怪物理——先用代数语言翻译：每个计划节点=一个算子。
