## 4 🔧 域与类型的实测反差（SQLite/DuckDB，非本书引擎）

- SQLite 3.45.3（E1）：**动态类型+存储类**，`CREATE TABLE weak(i INTEGER, t TEXT); INSERT INTO weak VALUES('abc',123)` 照样入库，`typeof` 返回 `('text','text')`；亲和性只做"尽力转换"（`'42'`→integer）。**域约束在 SQLite 是程序员的口头约定而非引擎合同。**
- DuckDB 1.5.5（E2/E8）：强类型近似域概念——`INSERT INTO emp VALUES(1,'x',100)` 直接把字符串塞 INT 列报 `Conversion Exception: Could not convert string 'x' to INT32`；`typeof(12::INTEGER)`、`DESCRIBE emp` 显示 `DECIMAL(10,2)` 精确到标度。
- 🔧 关系=集合的演示：DuckDB `SELECT count(*), count(DISTINCT did) FROM ...` 对比 bag 语义；`EXPLAIN emp`（E2）元数据列序仍固定——"属性有序"这条模型例外在两引擎都保留。
- ⚠️ Oracle 10g（本书主线）有真正的 `CREATE DOMAIN` 缺位但 `CHECK`+类型体系介于两者之间——概览章口径见 11 号文件。

## 7 深挖与自测

### 概念辨析十问
1. 关系是集合、表是 bag——差在哪两个补救运算？——DISTINCT（去重）与显式列序（投影固定）。
2. 域约束谁执行？——标准答 DBMS；现实从引擎（DuckDB E2）到程序员约定（SQLite E1）光谱分布。
3. 候选键与主键的选法差异属模型还是工程？——工程：模型只要求"存在极小超键"。
4. "属性不可重复"与"列可同名"——SQL 为何两者并存？——表非关系；`*` 展开/别名可造同名列。
5. 元组无序为什么重要？——优化器换序不改语义，是代数等价/并行化的地基（ch5/7）。
6. NULL 是域内合法值还是缺席标记？——三值逻辑把两者搅浑（ch15 回收）。
7. 度数不变、基数常变——哪个更像 schema？——度数属结构；基数属 instance。
8. "关系是谓词的外延"——本册何处呼应？——ch8 的 {t | P(t)} 即该思想的课堂版。
9. 属性有序破坏模型纯粹性吗？——破坏；但为 SELECT * 与 UI 可预期，SQL 选择保留。
10. "正规化表"一词何章兑现？——ch4（1NF=原子性定义在此）。

### 常见误区六条
- 把"表"当"关系"替 SQL 辩护——四差异（重复/序/域松弛/键无保证）一条不饶。
- 认为类型系统=域——域还含业务合法值集（CHECK/引用值域）。
- 主键随意换——外键引用一动全局震（参照完整性代价）。
- DISTINCT 随手加——掩盖 bag 病根，性能与正确性双代价。
- NULL 三义混装（不知道/不适用/零）——语义债迟早爆炸。
- 以为强类型就守域——类型≠完整性全部（E2 的 CHECK/ALTER 缺口）。

### 🔧 加餐：域纪律实验清单（非本书行为）
- SQLite：'abc' 入 INTEGER，typeof→'text'（E1）。
- DuckDB：同款直接 ConversionException（E2）——两引擎=域约束两极。
- DECIMAL(10,2) 在 DESCRIBE 原样保留（E2）——"域可声明且可见"。

## 8 术语快卡与跨书对位

| 术语 | EN | 一句话定位 |
|---|---|---|
| 关系 | Relation | 一张二维表的数学名：集合，不重复、无序 |
| 元组 | Tuple | 表中的一行，关系的元素 |
| 属性 | Attribute | 表中的一列，取值来自某域 |
| 域 | Domain | 属性取值的原子类型集合 |
| 目数/基数 | Degree/Cardinality | 列数/行数，关系的两把尺 |
| 候选码 | Candidate Key | 唯一标识元组的最小属性集 |

## 最新演进与工业实践

- **模型的当代代理**：SQL 标准至 SQL:2016/2023 仍以关系为核心；嵌套/对象扩展（SQL:1999）商业渗透率低——本册 ch23 的预言"对象关系共存"以 JSON 半结构化的形式兑现（🔧E8：SQLite `json_extract('{"addr":{"city":"CD"}}','$.addr.city')`→'CD'，DuckDB STRUCT 嵌套 `o.name/o.tags` 直查）。
