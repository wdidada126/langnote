# 05 持久化：RDB 与 AOF

> ⚠️ 结构声明：精读重构主题单元，非原书实抓章节（缺口申报见 [00-总览与阅读地图.md](00-总览与阅读地图.md)）。
> 前提纪律：**Redis 本机不装不跑 ⚠️**——持久化行为描述全部转述官方文档（其 persistence 页 ✅ 本轮实测 200：https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/ ）；🔧 演示用 DuckDB 1.5.5 复现「内存态→落盘→重启恢复」的概念形态，**非 Redis 行为**。

## 5.1 问题的本质：把 WAL/快照教科书重新发明一遍

- 内存数据库的耐久化只有两种原语（与 [../数据库系统概念6/16-恢复系统.md](../数据库系统概念6/16-恢复系统.md) 的分类学一一对应）：
  - **快照**：某时刻全量镜像 → RDB（dump.rdb，二进制紧凑格式）。
  - **日志**：写操作增量记录 → AOF（append-only file，命令追加）。
- 关系库用「WAL+checkpoint」两者合体且默认全开；Redis 的默认值却是「RDB 若干档+无 AOF」（⚠️ 各版本默认 save 策略有变，5.0/6.0/7.x 的默认档位不同，不逐条断言，部署时核对 redis.conf 现文）——默认值背后的身份之争：**缓存（丢了无所谓）vs 数据库（丢了要命）**。

## 5.2 RDB：fork 出来的全量时刻（⚠️ 转述）

- 触发：`SAVE`（阻塞，生产禁手⚠️）/`BGSAVE`（fork 子进程写临时文件，完成后原子 rename 替换）。
- **写时复制（COW）机制**：子进程持 fork 瞬间的视图继续写盘；父进程页被改写时内核复制页 → 大实例 BGSAVE 期间的内存放大与 fork 延迟（页表复制毫秒~秒级）是两个经典隐性成本（⚠️ 机制转述；正是 03 内存账的隐藏项）。
- 损坏语义：RDB 全文件损坏=丢整档；`redis-check-rdb` 工具族 ⚠️。
- 适用判断：主从复制的首传种子、备份到对象存储、以及「能容忍 N 分钟丢窗」的业务（丢窗=save 档位间隔 ⚠️）。

## 5.3 AOF：把写命令再走一遍（⚠️ 转述）

- 记录口径：**追加写命令**（协议格式文本），重启重放重建键空间。
- fsync 三档：`appendfsync always`（每命令刷盘≈同步耐久，吞吐塌方）/ `everysec`（默认折中：**丢 1~2 秒**）/ `no`（交给 OS，丢更多）。
- **AOF 重写**（rewrite）：文件单调膨胀 → `BGREWRITEAOF` 按当前键空间生成等价最小命令集替换；期间新写入进缓冲区，重写完成后拼接（⚠️ 机制转述；早期「rewrite 与阻塞」的坑随 6.0 多线程 aof write 有缓解 ⚠️ 不展开）。
- 损坏语义：日志天然可局部截尾（最后一条不完整命令丢弃，`redis-check-aof` ⚠️）——**日志的容损性优于快照**，这是分类学层面的必然，不必实测也成立。

## 5.4 混用与「谁赢」的加载次序（⚠️ 转述）

- 4.0+ 混合持久化：RDB 头+AOF 增量尾（`aof-use-rdb-preamble`，默认趋势 ⚠️），兼得重放速度与丢窗下界。
- 加载优先级：同时存在 AOF 与 RDB 时**以 AOF 为准**（AOF 被视为更完整账本 ⚠️）——备份演练要按这条口径设计校验，否则「有 RDB 备份」是幻觉。
- 与 03 的接口：`noeviction`+无持久化=「既不能丢也没有账」，配置上自相矛盾的 Redis 在生产大量存在（⚠️ 工程观察转述）。

### 🔧 概念复现（DuckDB 1.5.5 真跑，脚本 `D:\develops\tmp\dbwave_w3_lredis\demo.py`）

把「内存态→落盘→重开恢复」的最小闭环在 SQL 引擎上走一遍：

```
:memory: 库写入 100 万成员表（内存态）→ 不落盘即销毁 = 数据蒸发
文件库  : 建库→INSERT ('hello','world')→close()→重开→SELECT 恢复出 [('hello','world')]
          落盘文件 536,576 字节，重启后完整可读
```

- 类比映射：`:memory:` ≈ 无持久化 Redis；文件重开恢复 ≈ 启动加载 RDB/AOF 重放；**536KB 文件里含目录/元数据开销**，对应 RDB 的自描述二进制格式。
- 类比失真处（必须讲明）：DuckDB 文件是**实时可查询的存储本体**，Redis 落盘文件平时**不可查询**、只在启动时消费；DuckDB 无「命令重放」概念（它是页+ WAL 引擎）。恢复语义的这部分差异用 ⚠️ 文档口径补 ⚠️。

## 5.5 丢窗算术（本单元的「背锅题」）

| 配置 | 崩溃丢数据 | 依据 |
| --- | --- | --- |
| 纯 RDB（save 档 5m/1） | 最多 ~5 分钟 ⚠️ | 快照间隔语义 |
| AOF everysec | 1~2 秒 ⚠️ | fsync 节拍（官方页示例口径 ✅ 存在于 persistence 页） |
| AOF always | ~0，吞吐代价 | 同步刷 |
| 全关 | 实例全量 | 缓存型业务的正当选择 |

- 与主从复制的耐久化组合（「从库多副本≈备份」是个常见误区：异步复制不救已写坏的数据，06 呼应 ⚠️）留到下节问题清单。

## 5.6 面向 SQL 开发者的一句话收束

Redis 持久化=「在数据库之外手工重建一套 WAL/checkpoint 语义，并把 RTO/RPO 参数化暴露给运维」。你熟悉的 mysqldump/binlog 心智在这里全部映射得通，**唯一的落差是 Redis 没有「恢复到任意时间点」的事务连续性保证**（AOF 重放近似 PITR 但受重写边界 ⚠️）。

## 5.7 崩溃恢复时间线推演（⚠️ 全转述演练，无实测）

设 12:00:00 实例带着「最近一次 BGSAVE 完成于 11:55、AOF everysec 追到 11:59:58」崩溃：

| 时刻 | 事件 | 依据（⚠️） |
| --- | --- | --- |
| 12:00:0x | 进程亡，内存态蒸发 | 全内存本质 |
| 重启 t0 | 读配置决定真相源：AOF 在 → 重放 AOF（优先于 RDB，5.4） | 加载次序口径 |
| t0+Δ1 | 重放至文件尾，丢弃末条不完整命令 | 日志容损性 |
| t0+Δ1+ε | 服务就绪；**11:59:58→12:00 的 ≤2s 写为丢窗** | everysec 语义 |
| （若无 AOF） | 只能吃 11:55 的 RDB → 丢窗≈5 分钟 | 快照粒度 |

- Δ1 的教训句：**恢复时长与 AOF 体积成正比**——这正是 5.3 重写机制同时服务「省盘」与「省 RTO」的双重理由；RDB 恢复快（二进制直读）但丢窗粗，两档在时间轴上各自把守一头（⚠️ 定性）。
- 混合格式（5.4）在这条时间线上的位置：RDB 头承担 Δ1 的大头、AOF 尾只补增量——RTO 与 RPO 第一次被同一份文件同时优化 ⚠️。

## 5.8 备份与恢复演练清单（⚠️ 工程通识）

1. RDB 外送：`BGSAVE` 产物按 `dump.rdb.{时间戳}` 复制走，**永远不要在原文件上做**（rename 语义+竞态）。
2. 恢复演练必须验三件事：文件可加载（check 工具族）、加载后键空间抽检、**加载次序与预期一致**（AOF 覆盖 RDB 的默认真相源有没有坑到你）。
3. 从库当备份的再评估：[06](06-复制哨兵与集群.md) 6.5 的「异步复制≠备份」误区在此复用——备份至少满足 3-2-1 中的「离线一份」，在线副本不算 ⚠️。
4. 持久化关闭的实例（纯缓存档）要在配置注释里写明「丢了谁重建」——没有答案就别关。

## 核心概念速览（中英对照）

- **RDB** — Redis Database 快照：二进制全量镜像文件（dump.rdb）。
- **BGSAVE** — 后台保存：fork 子进程写临时文件后原子替换。
- **写时复制** — copy-on-write：fork 后页按需复制的内核机制，内存放大源。
- **AOF** — append-only file：写命令追加日志。
- **fsync 策略** — appendfsync always/everysec/no：耐久性与吞吐的旋钮。
- **AOF 重写** — log rewrite：按键空间重生成最小命令集以收缩日志。
- **混合持久化** — RDB preamble + AOF tail：4.0+ 的合体格式 ⚠️。
- **丢窗** — data loss window：崩溃时的最大数据损失时间。
- **重放恢复** — replay：启动时消费持久化文件重建内存态。
- **redis-check-aof/rdb** — 文件校验修复工具族 ⚠️。
- **原子 rename** — 快照发布手法：临时文件写完再替换，防半档。
- **加载优先级** — AOF over RDB：两档并存时的真相源选择 ⚠️。
- **PITR** — 任意时间点恢复：Redis 持久化模型给不出的关系库能力（近似而非等价 ⚠️）。
