## 8.3 Valkey 分裂：读本册必须带上的新前提

- 事件骨架（⚠️ 转述，两站 ✅ 实测 200）：2024-03 Redis Ltd. 弃用开源许可后，社区分叉 **Valkey**（Linux 基金会托管，接口兼容 Redis 协议），云厂商多路支持；「Redis 兼容」自此成为治理问题而非技术问题。
- 对读者的实际影响：**文档要按发行版读**——同一命令族行为差异、参数默认值、集群改进线在两个谱系各自演化；本册各单元引用的 redis.io 页 = Redis Ltd. 口径，Valkey 对位文档见 https://valkey.io/ （✅ 实测 200，页面级差异未逐条核对 ⚠️）。
- 兼容面判断（⚠️ 判断句）：RESP 协议与核心类型语义仍是公约数，本册 02/03/04/05 的概念骨架在两个谱系同样成立——**这正是把「语义单元」与「版本事实」分写的收益**。

- **折旧表** — deprecation map：书口径→现状口径的对位总账（8.2）。

- **ACL** — 访问控制列表：6.0 起的用户/权限体系（书基线只有 requirepass ⚠️）。
- **许可三连** — RSALv2/SSPLv1 → +AGPLv3：Redis 8 的多许可现实 ⚠️。
- **Valkey** — 社区分叉：Linux 基金会托管的协议兼容谱系 ✅。
- **文档按发行版读** — distro-aware docs：2026 的第一使用纪律。
- **多模型打包** — multi-model：Redis Stack 式 Module 整合路线 ⚠️。
- **WAIT** — 副本确认命令：异步默认的应用级补丁 ⚠️。
- **术语治理** — terminology migration：SLAVE→REPLICA 类更名的通称。
