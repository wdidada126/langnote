# 04 事务 MULTI 与服务器端脚本

> ⚠️ 结构声明：精读重构主题单元，非原书实抓章节（缺口申报见 [00-总览与阅读地图.md](00-总览与阅读地图.md)）。

## 4.1 SQL 开发者带进来的三件行李，逐件卸下

| 行李 | 关系库承诺 | Redis 现实（⚠️ 转述） |
| --- | --- | --- |
| 事务=ACID 全套 | 原子+一致+隔离+耐久 | MULTI/EXEC 只给「排队+连续执行」的弱原子；**无回滚**、隔离=单线程串行、耐久交给 05 |
| 约束=服务端兜底 | 唯一/外键/CHECK | 无。一致性责任全在应用与数据结构设计（01 1.3） |
| 存储过程/触发器 | 服务端批量逻辑 | 对应物是 Lua 脚本（2.6 起）与 Functions（7.0 起）⚠️ |

## 4.2 MULTI/EXEC 的机械结构（⚠️ 转述自官方事务页口径）

- 流程：`MULTI` 开队列 → 后续命令**不执行只入队**（返回 QUEUED）→ `EXEC` 原子地连续执行全队列（期间无其他客户端命令插队，因为单线程 ✅ 该页实证存在此论述框架）。
- 两类错误的分野（本单元最容易背错的点，按官方事务页 ⚠️ 转述）：
  1. **入队时错误**（语法/未知命令）：队列作废，EXEC 拒绝执行整批——「全有或全无」在这条线上成立。
  2. **执行时错误**（如对 string 键做 LPUSH 的运行时类型错）：出错命令失败，**其余命令照常执行，不回滚**。Redis 明确宣称这是可接受的：「只有 bug 才会触发」的立场（官方 FAQ 式论述 ⚠️）。
- 结论句：MULTI 给你的是**批处理+穿插隔离**，不是 SQL 意义上的原子事务。把 `BEGIN/COMMIT` 的心智直接平移=事故预定。
- WATCH 乐观锁：`WATCH k` 后若 k 在 EXEC 前被任何客户端改动 → EXEC 返回 nil（放弃），应用层重试——即 CAS 循环（⚠️ 转述）。这对应的是并发控制的「乐观/快照」一支，与 [../数据库系统概念6/15-并发控制.md](../数据库系统概念6/15-并发控制.md) 的两阶段锁谱系正相对照。

### 🔧 概念复现（sqlite3 3.45.3 真跑）

在 SQL 侧把「整批要么全做」跑到极致，用来**反衬** Redis 的不回滚：

```
正常 MULTI/EXEC 类比: BEGIN → UPDATE a:-70 → UPDATE b:+70 → COMMIT
  结果: [('a', 30), ('b', 120)]            —— 转账守恒 ✅
入队即语法错的类比:   BEGIN → UPDATE a:-70 → UPDATE ... WHERE nonexistent=1 → 异常
  ROLLBACK 后:        [('a', 100), ('b', 50)] —— 整批回滚，分毫不动
```

- 读数：sqlite 的事务在第二例把 -70 撤销了；**Redis 的 EXEC 若在执行期遇错则不会撤销**（⚠️ 分野在官方事务页，演示是 SQL 侧镜像）。
- 「原子连续执行」的另一种 SQL 类比：单连接内串行发整批语句但不回滚已执行部分——SQLite 无此模式，故 Redis 的半套原子只能靠 ⚠️ 文档转述定位，这正是「非 Redis 行为」声明的价值。

## 4.3 不用 MULTI 的原子性：单命令本身就是事务

- `INCR`/`LPUSH`/`SADD`/`ZINCRBY` 天然原子（单线程串行 ✅ 事务页框架）——2015 书隐含的实用主义：**大部分「需要事务」的场景其实只需要「把不变量压进一条命令」**。
- 例：限流=INCR+EXPIRE 两条命令的竞态（EXPIRE 丢失→计数器永生），正确解从 Lua（4.3）或 SET NX 模式来 ⚠️。
- `SET key val NX PX 30000` 一条命令完成「不存在才写+带 TTL」——2.6.12 前要靠 MULTI 模拟的历史（⚠️ 转述）说明参数化单命令是 Redis 的第一原子层。

## 4.4 Lua 脚本：原子性的第二层

- 语义（⚠️ 转述）：`EVAL script numkeys key... arg...` 整个脚本作为**一条命令**执行——运行期间绝不被插队，脚本内可「读-改-写」闭环。这才是 Redis 上能做「比较-交换」「多键搬运」的机制层。
- 约束（⚠️）：脚本应决定论（Cluster 下还要求键声明全部落同槽，见 06）；长脚本=全库卡顿（01 单线程的另一面）；脚本进 AOF whole-script 记法（⚠️ 持久化交互，05 展开）。
- 书时代语境：2015 年「复杂事务→写 Lua」已是社区共识，本书副题的 web solutions 里 CAS/计数类都靠它 ⚠️ 推定（章目未实抓）。

## 4.5 Functions（7.0）：从「传脚本正文」到「服务端代码库」

- `FUNCTION LOAD` 注册命名函数，`FCALL` 调用；库化、可复制、配 `REDIS_FUNCTION` 常量（⚠️ 转述；官方介绍页 ✅ 实测 200：https://redis.io/docs/latest/develop/interact/programmability/functions-intro/ ）。
- 对 SQL 心智的翻译：Lua 脚本≈ ad-hoc 批处理，Functions≈存储过程（持久化在服务端、按名调用）。Redis 8 进一步引入多语言函数运行时（⚠️ 见 08 的演进登记，具体语言支持面以官方现文为准）。

## 4.6 设计判断题（本单元收束）

1. 需要「多键同成同败」→ 接受不回滚现实：键设计让部分失败可被对账修复，或用 Lua 把判断压进执行前。
2. 需要「读-改-写并发正确」→ WATCH 重试环 或 Lua 原子的单循环；锁（SET NX）是第三选项，边界见 07。
3. 需要「隔离级别」这类词 → 换词汇表：Redis 只有「命令边界」，没有读快照、没有写偏斜讨论空间（⚠️ 与 [../数据库系统概念6/14-事务.md](../数据库系统概念6/14-事务.md) 的 ISO 谱系对照后自证）。

## 4.7 一段 MULTI 会话实录（⚠️ 转述示例，接口见 ✅ transactions 页）

```
CLIENT A                          CLIENT B
MULTI                             SET ctr 100
  -> QUEUED
INCR ctr      -> QUEUED           (ctr 被改动!)
LPUSH mylist x -> QUEUED
EXEC
  -> [101, [x], ...] 或 nil?
```

- 逐行判读：A 在 MULTI 后、EXEC 前，`ctr` 被 B 改动 → 若 A **没有** WATCH，EXEC 照常执行（INCR 结果 101）——MULTI 本身**不保证**你入队时读到的世界还在；若 A 先 `WATCH ctr`，EXEC 返回 **nil**（放弃整批）。
- 第二层判读：入队的 `LPUSH mylist x` 若 mylist 实为 string 类型，EXEC 仍执行队列——该条报错、其余命令照常（4.2 执行期不回滚的现场版）。
- 结论卡片：**WATCH 管「世界变了没」，MULTI 管「别被插队」，两件事互不替代**——SQL 开发者最容易把它们混背成一个 COMMIT。

## 4.8 WATCH 重试环骨架（语言无关伪码 ⚠️）

```
loop (预算 N 次):
  WATCH 键集
  读当前值(普通命令, 不在 MULTI 内)
  计算新值
  MULTI; 写命令入队; EXEC
  若 EXEC 非 nil → 成功退出
  否则继续 → 超预算则降级(排队串行化/换互斥带外锁并读 07 边界)
```

- 三个工程注脚：①读必须在 WATCH 之后（WATCH 只失效此后的 EXEC，不锁历史）⚠️；②预算次数与退避是**活性**参数，没有它们热点键上会活锁；③重试环吞吐随竞争平方级恶化——热点自增的正解从来不是 CAS 而是 **INCR 类单命令**（4.3）。

## 4.9 原子性金字塔（本单元背诵版）

| 层 | 机制 | 保证 | 失败形态 |
| --- | --- | --- | --- |
| 1 | 单命令（INCR/SET NX/LMOVE） | 原子+串行 | 表达力有限 |
| 2 | MULTI/EXEC | 批内无插队 | 执行期不回滚 |
| 3 | Lua/Functions | 读-改-写闭环原子 | 长脚本=全库卡；Cluster 键声明 |
| 4 | 带外锁（07） | 跨命令跨进程 | TTL 与停顿竞态 ⚠️ |

层数越高表达力越强、事故半径越大——「能停在哪层就停在哪层」是本单元唯一心法（⚠️ 判断句）。

## 核心概念速览（中英对照）

- **MULTI/EXEC** — 事务队列：入队-原子连发的批处理原语，非 ACID 事务。
- **QUEUED** — 入队回执：MULTI 期间命令延迟执行的标志语义。
- **无回滚** — no rollback：执行期出错后续照常，Redis 事务的著名取舍 ⚠️。
- **WATCH** — 乐观监视：键被改动则 EXEC 放弃的 CAS 前置。
- **重试环** — retry loop：应用层对 WATCH 失败的标准处置。
- **命令原子性** — command atomicity：单命令天然串行执行的一致性最小单元。
- **EVAL** — Lua 求值：脚本作为单命令原子的第二层。
- **键声明** — keys 参数：脚本对触达键的显式声明（Cluster 前提 ⚠️）。
- **Functions** — 7.0 服务端函数库：命名注册+FCALL 的存储过程化。
- **SET NX PX** — 参数化单命令：把「不存在才设+TTL」压进原子边界的样板。
- **READONLY 变体** — EVAL_RO/FCALL_RO：只读路由声明（7.0 ⚠️）。
- **whole-script 记法** — 脚本整体写 AOF 的持久化策略（⚠️，05 呼应）。
