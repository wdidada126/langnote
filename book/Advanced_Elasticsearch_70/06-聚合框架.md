# 聚合框架（原书 Ch8）

> ⚠️ 主题重构：Ch8 代码 `aggregation_framework`，含 ETF 历史价格 bulk 数据 + `Moving Average Chart.xlsx`——聚合结果在 Excel 中可视化，说明管道聚合（moving_avg）实操。

## 1. 聚合解剖：桶 × 指标 × 管道

ES 聚合 = **Bucket（分桶）→ Metric（计算）→ Pipeline（二次加工）** 三层。

```
aggs: {
  "by_category": {           ← Bucket Agg (terms)
    "terms": { "field": "category" },
    "aggs": {
      "avg_price": {         ← Metric Agg (nested inside bucket)
        "avg": { "field": "price" }
      },
      "max_moving_avg": {    ← Pipeline Agg (over siblings)
        "moving_avg": { "buckets_path": "avg_price" }
      }
    }
  }
}
```

## 4. Pipeline 聚合

## 5. 聚合执行模型

- 协调节点分发聚合请求到所有分片 → 分片局部聚合 → 返回 top N → 协调节点归并
- terms agg 默认 `shard_size = 1.5 * size + 10`——每分片多取候选，减少归并误差
- nested agg 本质 = 重新执行一次子查询——开销较大

## 6. 🔧 类比演示（非 ES 行为）

**G3：SQL GROUP BY vs ES terms agg**（SQLite 3.45.3 + DuckDB）

```python
# SQLite GROUP BY: 1000 行 sales, 5 buckets, COUNT/SUM/AVG
# 耗时 ~0.20ms
conn.execute("SELECT region, COUNT(*), SUM(amount), AVG(amount) FROM sales GROUP BY region ORDER BY COUNT(*) DESC")
```

| 维度 | ES terms agg | SQLite GROUP BY |
|---|---|---|
| 分桶键 | keyword/doc_values | 任意列（全扫或索引） |
| 子聚合 | 嵌套桶×指标 | 不支持（需多次查询） |
| 近似 | cardinality 用 HLL++ | COUNT(DISTINCT) 精确 |
| 截断 | size 参数（默认 top 10） | 无截断 |
| 管道 | moving_avg 等 | 窗口函数 `AVG() OVER(...)` |
| 分布式 | 分片并行 + 协调归并 | 单进程 |

DuckDB 窗口函数类比更贴切管道聚合：`AVG(price) OVER (ORDER BY date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)` ≈ `moving_avg(window=7)`。**均为非 ES 行为**。

## 7. 本章要点

- 聚合是 ES 从"搜索引擎"到"分析引擎"的关键能力——书中 EDA 场景（Ch10）即基于此
- 理解 terms 截断机制是仪表盘设计的基本功（`shard_size`、`doc_count_error_upper_bound`）
- Pipeline agg 是时间序列分析利器——Kibana 仪表盘大量使用
- TDG 聚合章（[../Elasticsearch_The_Definitive_Guide/03-聚合.md](../Elasticsearch_The_Definitive_Guide/03-聚合.md)）的 1.x 概念框架仍适用——本章给 7.0 实操

## 核心概念速览（中英对照）

1. **桶聚合** — Bucket Aggregation：按条件将文档分组，类比 GROUP BY
2. **指标聚合** — Metric Aggregation：对桶内文档计算统计值（AVG/SUM/MAX…）
3. **管道聚合** — Pipeline Aggregation：对已有聚合输出做二次计算
4. **terms 聚合** — 按 keyword 字段词频分 top N 桶
5. **date_histogram** — 按时间间隔分桶（1h/1d/1M），时序分析主力
6. **cardinality** — 基于 HyperLogLog++ 的近似 COUNT(DISTINCT)
7. **percentiles** — 百分位数聚合（tdigest 算法），延迟分析必备
8. **composite** — 分页遍历大量桶（替代 scroll + terms）
9. **significant_terms** — 统计学显著词项发现（JLH/normalization 算法）
10. **moving_avg** — 滑动平均管道聚合——书中标志性示例
11. **nested agg** — 进入 nested 子文档空间做聚合
12. **shard_size** — 每分片多取候选桶数以降低归并误差
13. **doc_count_error_upper_bound** — terms agg 截断的文档计数误差上界

## 最新演进与工业实践

- **ES 8.x/9.x 聚合演进**：聚合框架核心不变（bucket/metric/pipeline 三层）；新增 `rare_terms`（罕见词项）、`multi_terms`（多字段组合 terms agg）、`matrix_stats`（多元统计）
- **ES|QL 聚合**：`FROM idx | STATS count() BY bucket | SORT count DESC`（9.0 GA，https://www.elastic.co/docs/reference/query-languages/esql ✅ 200）——SQL-like 语法覆盖常见 GROUP BY 场景，但复杂管道聚合仍用 Agg DSL
- **Kibana Lens**（8.x 默认可视化编辑器）：拖拽式聚合组合——底层仍生成 Agg DSL
- **工业实践**：可观测性（logs/metrics/traces）场景 date_histogram + 子聚合是核心查询模式；terms agg 在电商类目/标签统计中高频；significant_terms 在异常检测/日志分析中不可替代
- **性能优化**：`aggs` + `size: 0`（不需要命中文档时）减少序列化开销——ES 7.x 起 `terminate_after` 可限制分片处理文档数
