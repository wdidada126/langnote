# 映射与分词分析（原书 Ch4–5）

> ⚠️ 主题重构：Ch4 代码 `mapping_api`（静态映射 JSON），Ch5 代码 `analyzer`（自定义分词器 + stopwords）。两章相邻同属"数据定义"主题，合并为本文件。

## 1. Mapping：ES 的 Schema 定义

ES 7.0 映射定义字段类型、索引策略和分析器。

### 核心类型（7.0 基线）

| 类型 | 用途 | 搜索方式 | 类比 |
|---|---|---|---|
| `text` | 全文检索 | 分词后倒排查 | TDG 的 analyzed string |
| `keyword` | 精确值/排序/聚合 | 不分词 term 查 | TDG 的 not_analyzed string |
| `date` | 日期/时间 | range/term | `@timestamp` 系统字段 |
| `long`/`double` | 数值 | range | doc_values 默认开 |
| `geo_point` | 经纬度 | 距离/地理形状查询 | 见 06 章 geo agg |
| `nested` | 对象数组 | 独立文档语义 | Ch7 详述 |
| `object` | 扁平对象 | 串味风险 | Ch7 辨析 |
| `join` | parent-child | 稀疏树 | Ch7 |
| `ip` | IPv4/IPv6 | CIDR 范围 | 7.0 新增 |
| `constant_keyword` | 固定值 | term | 多数据集分型 |

官方文档：https://www.elastic.co/guide/en/elasticsearch/reference/7.17/mapping-types.html ✅ 200

### 动态映射 vs 静态映射

- 动态映射（`dynamic: true` 默认）：自动检测类型，有陷阱（如 `1.0` → double、字符串日期误判）
- 静态映射：`PUT /idx` 时显式定义——生产推荐；书中示例 `create_cf_etf_index_with_static_mapping.json` 即此
- `dynamic: strict`（未定义字段报错）/ `dynamic: false`（未定义字段不索引但存 `_source`）

## 2. Analyzer 三件套

ES 文本分析 = **Tokenizer（必有）+ Token Filters（可选）+ Character Filters（可选）**。

```
"Running searches" → [standard tokenizer] → [lowercase] → [porter_stem] → "run search"
```

- 内置分析器：`standard`（Unicode 断词）、`simple`（非字母断）、`whitespace`、`keyword`（不切）、`pattern`（正则切）
- 自定义分析器：在 `settings.analysis.analyzer` 声明
- 书中代码 `define_custom_analyzer.json` + `stopwords/` 目录——创建含 stop filter 的自定义分析器

官方文档：https://www.elastic.co/guide/en/elasticsearch/reference/7.17/analyzer-anatomy.html（⚠️ 推定 URL）

## 3. 🔧 类比演示（非 ES 行为）

**G5：Porter 词干化（FTS5，SQLite 3.45.3）**

```python
conn.execute("CREATE VIRTUAL TABLE stem_test USING fts5(body, tokenize='porter unicode61')")
conn.execute("INSERT INTO stem_test VALUES('searching for distributed databases')")
conn.execute("INSERT INTO stem_test VALUES('searches are distributed system concerns')")
# MATCH 'search' → 2 rows (porter: searching→search, searches→search)
# MATCH 'searching' → 2 rows (同 stemmed 结果)
# MATCH 'distributed' → 2 rows
```

- FTS5 `porter unicode61` 分词器 ≈ ES `standard tokenizer + lowercase filter + porter_stem filter`——**类比而非等价，非 ES 行为**
- ES 独有：synonym_graph filter、stemmer override、ngram/edge_ngram 子词——FTS5 无直接对应
- ICU tokenizer / 中文 SmartCN / 日韩 Kuromoji——FTS5 unicode61 无法处理 CJK 分词

**G2：bm25() 字段权重排序（FTS5）**

```python
conn.execute("CREATE VIRTUAL TABLE docs USING fts5(title, content, tokenize='porter unicode61')")
# bm25(docs, 10.0, 1.0): title 权重 10x content — ES 类比 boost
rows = conn.execute("SELECT title, bm25(docs,10.0,1.0) FROM docs WHERE docs MATCH 'elasticsearch' ORDER BY score").fetchall()
```

## 4. Mapping 实战要点（书中 ETF 数据集）

```json
// create_cf_etf_index_with_static_mapping.json 核心结构 ⚠️ 转述
{
  "mappings": {
    "properties": {
      "symbol":    { "type": "keyword" },
      "name":      { "type": "text", "analyzer": "english" },
      "price":     { "type": "float" },
      "fund_family": { "type": "keyword" },
      "category":  { "type": "keyword" },
      "date":      { "type": "date", "format": "yyyy-MM-dd" }
    }
  }
}
```

- `keyword` 用于精确过滤（`term` 查询、聚合、排序）；`text` 用于全文搜索
- `norms: false`（keyword 默认无 norms）节省磁盘——TDG [../Elasticsearch_The_Definitive_Guide/11-映射与索引的本质.md](../Elasticsearch_The_Definitive_Guide/11-映射与索引的本质.md) 深入
- `doc_values: true`（默认，除 text 外）——排序/聚合依赖列存；TDG 大对位表 #16 行解释 fielddata→doc_values 演进

## 5. 本章要点

- Mapping 是"7.0 后最大的 schema 层"——types 删除后字段类型成为唯一分类手段
- Analyzer 三件套是相关性调优的入口——与 TDG [../Elasticsearch_The_Definitive_Guide/07-词项分析与语言处理.md](../Elasticsearch_The_Definitive_Guide/07-词项分析与语言处理.md) 对照
- 书中 `stopwords/` 目录含自定义停用词列表——`stop_path` vs `stopwords` 内联二选一
- 动态映射"方便但危险"——生产环境一律静态映射 + `dynamic: strict`

## 核心概念速览（中英对照）

1. **映射** — Mapping：字段类型与分析器的声明式定义，ES 的 schema 层
2. **动态映射** — Dynamic Mapping：ES 自动推断字段类型，生产慎用
3. **分词器** — Analyzer：tokenizer + filter 组合，将文本转为 token 流
4. **标准分词器** — Standard Tokenizer：基于 Unicode 文本分段（UAX#29）的分词器
5. **词干化** — Stemming：将词形还原为词根（running→run），降低词汇碎片化
6. **停用词** — Stop Words：高频无意义词（the/is/of），过滤以减小倒排体积
7. **keyword 类型** — 不分词的精确值字段，用于 term 查询/聚合/排序
8. **text 类型** — 分词的全文字段，用 match 查询搜索
9. **doc_values** — 列式正排索引，排序/聚合默认数据源，替代旧 fielddata
10. **norms** — 字段长度归一化因子，参与 BM25 打分；keyword 默认关闭
11. **copy_to** — `_all` 移除后的替代：将多字段内容复制到一个聚合 text 字段
12. **analyzer 三件套** — Tokenizer + Token Filter + Char Filter 组合的自定义分析器

## 最新演进与工业实践

- **2026 现状**：ES 9.x 字段类型体系大幅扩展——`semantic_text`（自动向量化，https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/semantic-text ✅ 200）、`match_only_text`（省 `_source` 空间）、`wildcard`（内置 n-gram 索引加速通配查询）。字段类型总览：https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/field-data-types ✅ 200
