# 自定义分析与搜索即输入（原书 Ch15–16）

> ⚠️ 主题重构：Ch15 代码含 `analysis plugin.pdf`（自定义 Analysis 插件文档）和 `mydictionary.dic`（自定义词典——CJK 分词场景）；Ch16 代码含 `cf_rfem_hist_price/`（前缀/补全搜索数据集）。两章合并——语言处理深度 + 搜索 UX 进阶。

## 1. Analysis Plugin 开发（Ch15）

ES 7.0 允许开发自定义 Analysis Plugin，注册新的 Tokenizer/TokenFilter/CharFilter。

### 插件结构

```
analysis-plugin/
├── plugin-descriptor.properties   # name/version/es.version
├── elasticsearch-analysis-mydict-7.0.0.jar
└── mydictionary.dic              # 自定义词典文件
```

### 核心 Java 类

1. **Plugin 入口**：继承 `Plugin`，实现 `getAnalysis()` 返回 `AnalysisModule.AnalysisProvider` Map
2. **自定义 TokenFilterFactory**：继承 `TokenFilterFactory`，实现 `create(TokenStream)` → 新 TokenFilter
3. **自定义 TokenizerFactory**：继承 `TokenizerFactory`，实现 `create(Reader)` → 新 Tokenizer
4. **注册到 ES**：`elasticsearch.yml` 或 `config/analysis-<name>/` 放置词典

### 词典文件 `mydictionary.dic`

书中示例为中文/自定义领域词典：
```
SPDR
S&P 500 ETF
道琼斯
纳斯达克100
```

`standard` tokenizer 按 Unicode 空白/标点断词——`SPDR` 若不在词典中可能被拆为 `S` + `P` + `D` + `R`；自定义词典确保领域术语完整性。

## 2. CJK 语言处理选项

ES 内置 CJK 分析器：
- `smart_cn`（SmartChineseAnalyzer）——IK 替代方案，Java 词典分词
- `kuromoji`——日文形态素分析
- `icu_transform`——Unicode 标准化/大小写/字符折叠（需 ICU 插件）
- `cjk_bigram`（内置）——中日韩双字符组合分词——无词典但召回高

⚠️ 书中 `mydictionary.dic` 暗示自定义词典分词插件——7.0 时代社区最活跃方案为 **IK Analyzer**（https://github.com/medcl/elasticsearch-analysis-ik ⚠️ 未验证 URL）。

## 3. Search as You Type（Ch16）

`cf_rfem_hist_price` 数据集——ETF 历史价格的补全/前缀搜索场景。

### 两条实现路线

| 方案 | mapping 要求 | 查询方式 | 优劣 |
|---|---|---|---|
| **Edge N-gram** | `text` 字段 + `edge_ngram` filter（索引时分词） | `match` 查询 | 搜索快/索引慢/占空间 |
| **Completion Suggester** | `completion` 类型字段 | `_search` + `suggest` | 前缀专用/FST 极快/不支持中间匹配 |

### Edge N-gram 示例

```json
// mapping ⚠️ 转述
{
  "settings": {
    "analysis": {
      "filter": {
        "edge_ngram_filter": {
          "type": "edge_ngram", "min_gram": 1, "max_gram": 20
        }
      },
      "analyzer": {
        "edge_ngram_analyzer": {
          "tokenizer": "standard",
          "filter": ["lowercase", "edge_ngram_filter"]
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "symbol": { "type": "text", "analyzer": "edge_ngram_analyzer",
                  "search_analyzer": "standard" }
    }
  }
}
```

**关键**：index analyzer 用 `edge_ngram`（生成所有前缀 token），search analyzer 用 `standard`（不分词）——避免搜索词被拆碎。

### Completion Suggester 示例

```json
// mapping
{ "suggest": { "type": "completion", "analyzer": "keyword" } }

// 查询
{ "suggest": { "autocomplete": { "text": "van", "completion": { "field": "suggest" } } } }
```

- FST 前缀树——毫秒级补全，支持 `weight` 按热度排序
- 7.0 起 `completion` 字段不支持跨字段——需 copy_to 或应用侧聚合多字段

## 4. 🔧 类比演示（非 ES 行为）

**G2：bm25() 字段权重 vs edge_ngram 打分差异**

FTS5 无 `edge_ngram`/`completion` 对应物——但 `trigram` tokenizer 可做子串搜索类比：

```python
# FTS5 trigram 子串搜索
conn.execute("CREATE VIRTUAL TABLE trigram_test USING fts5(body, tokenize='trigram')")
conn.execute("INSERT INTO trigram_test VALUES('elasticsearch distributed')")
r = conn.execute("SELECT * FROM trigram_test WHERE trigram_test MATCH 'lastre'").fetchall()
# 命中：trigram 索引允许子串匹配——edge_ngram 仅前缀，trigram 支持任意位置
```

- FTS5 trigram ≈ ES `ngram`（非 edge_ngram）——任意位置子串匹配；**非 ES 行为**
- ES completion suggester 基于 FST（Lucene 层）——SQLite 无对应物

**G5：自定义词典 vs FTS5 分词器**

FTS5 分词器仅 `unicode61`/`porter`/`trigram`——不支持自定义词典。ES 可通过 `synonym_filter` 或 `keyword_marker`（保护不词干化）实现部分词典效果。

## 5. 本章要点

- Analysis Plugin 是 ES 深度定制的语言处理入口——7.0 时代仍走 Java SPI 机制
- `edge_ngram` + 双 analyzer（index/search 分离）是 Search as You Type 最常用方案
- Completion Suggester 适合纯前缀补全——不支持多字段/中间匹配
- CJK 中文搜索 = IK/smartcn + 自定义词典——书中 `mydictionary.dic` 即此场景
- TDG [../Elasticsearch_The_Definitive_Guide/07-词项分析与语言处理.md](../Elasticsearch_The_Definitive_Guide/07-词项分析与语言处理.md) 给 analyzer 原理层细节

## 核心概念速览（中英对照）

1. **Analysis Plugin** — ES 扩展点：自定义 Tokenizer/Filter 打包为插件 jar
2. **plugin-descriptor.properties** — 插件元数据声明文件（name/version/es.version）
3. **Edge N-gram** — TokenFilter：从词首生成递增子串——前缀匹配
4. **Completion Suggester** — 基于 FST 的前缀补全器，mapping 类型 `completion`
5. **search_analyzer** — 查询时分析器——与 index_analyzer 分离实现精确前缀匹配
6. **词典（dictionary）** — 领域词汇表，保护专有名词不被分词/词干化
7. **IK Analyzer** — 中文分词插件，支持自定义词典+热更新（社区插件）
8. **SmartChinese** — ES 内置中文分词器（`smart_cn`），基于词典+统计
9. **CJK Bigram** — 中日韩双字组合分析器——无词典但高召回
10. **FST** — Finite State Transducer：Lucene 级压缩状态机——completion suggester 核心数据结构
11. **ngram** — 固定长度子串 token 生成器——部分匹配（不限前缀）
12. **keyword_marker** — TokenFilter：标记词典中的词不做词干化——部分词典效果
13. **synonym_graph** — 同义词展开 TokenFilter——搜索时扩展查询词

## 最新演进与工业实践

- **ES 8.x**：`search_as_you_type` 字段类型（8.0 GA）——内置多子字段（`_2gram`/`_3gram`/`_index_prefixes`）封装 edge_ngram 最佳实践，无需手动配 analyzer——书中手写方案被"一键字段类型"替代
- **IK/smartcn**：持续维护到 8.x/9.x——中文搜索场景仍是 IK + 自定义词典主导；Elastic 官方 `analysis-ik` 未进官方仓库（社区版 https://github.com/INRIA/elasticsearch-analysis-ik ⚠️ 未验证）
- **Elasticsearch Relevance Engine (ESRE)**（2023 宣布）：整合 ELSER + 向量 + BM25——"搜索即输入"扩展到语义补全：用户输入自然语言查询 → ELSER 展开 → RRF 混合 BM25+语义排序
- **Completion Suggester 在 9.x**：仍可用但 Elastic 推荐 `search_as_you_type` + kNN 混合方案
- **工业实践**：电商搜索框 = `search_as_you_type`（前缀匹配）+ ELSER（语义）+ RRF（融合排序）；日志场景（Elastic Observability）用 `searchAsYouType` 做字段名自动完成
