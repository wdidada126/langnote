## 三、JDK 版本演进时间轴（阅读本书必带）

| 版本 | 年份 | 与本书直接相关的变化 | 影响章节 |
| --- | --- | --- | --- |
| **JDK 8** | 2014 | 本书基线：`LongAdder`、`StampedLock`、`CompletableFuture`、`ConcurrentHashMap` 红黑树化、默认 G1 未开、移除 PermGen → **Metaspace** | 全书 |
| **JDK 9** | 2017 | `CompletableFuture` 增强（`orTimeout`/`completeOnTimeout`/`copy`/`failedFuture`）、VarHandle 引入、`getOrCreate`–`computeIfAbsent` 语义强化、JDK 9 的 `Flow`（Reactive Streams） | 4、11.9 |
| **JDK 11** | 2018(LTS) | `HttpClient` 异步化（CompletableFuture 风格）、Flight Recorder 开源、Epsilon/ ZGC 实验 | 11 |
| **JDK 14** | 2020 | **CMS 移除**（JEP 363）、JFR Event Streaming（JEP 349） | 1.8（GC 停顿影响线程） |
| **JDK 15** | 2020 | **偏向锁废弃并默认关闭**（JEP 374）、ZGC/Shenandoah 转正 | 2.5、2.12 |
| **JDK 17** | 2021(LTS) | 强封装 JDK 内部 API（JEP 403，`sun.misc.Unsafe` 访问开始受限）、Vector API 孵化 | 2.9（本书 Unsafe 用法已无法直接使用） |
| **JDK 19/20** | 2022-23 | **虚拟线程预览**（JEP 425/436）、结构化并发预览（JEP 428/437）、ScopedValue 孵化（JEP 429） | 1、6、8、10 |
| **JDK 21** | 2023(**LTS**) | 🔴 **虚拟线程 GA**（JEP 444）、**Generational ZGC**（JEP 439）、Sequenced Collections（JEP 431）、Key Encapsulation API、虚拟线程下的 `Executors.newVirtualThreadPerTaskExecutor()` | 1.2、6.3、8、10、11.7 |
| **JDK 22** | 2024 | 外部函数与内存 API GA（JEP 454）、G1 区域钉住（JEP 423，为虚拟线程铺垫） | 2.9 |
| **JDK 23** | 2024 | 🔴 **`sun.misc.Unsafe` 内存访问方法标记的废弃**（JEP 471，for removal） | 2.9 |
| **JDK 24** | 2025 | 🔴 **虚拟线程可在 `synchronized` 中不钉住**——JEP 491（VTD 去除 pinning 限制）、`Unsafe` 内存访问发出警告（JEP 498）、AOT Class Loading(JEP 483)、抑或用 java.lang.disableCache.. | 2.5、2.9、6 |
| **JDK 25** | 2025-09(**LTS**) | 🔴 **ScopedValue GA**（JEP 506）、Stable Value 预览（JEP 502）、紧凑对象头（JEP 519）、JFR CPU-time profiling（JEP 509）、Generational Shenandoah（JEP 521）、结构化并发第 5 预览（JEP 505） | 1.11、11.10 |

## 七、跨语言对照速查（本书每章都会用）

详细对比见 [concepts/并发模型跨语言对比.md](concepts/并发模型跨语言对比.md)，速查表：

| 语言 | 并发单元 | 同步原语 | 与本书 JUC 的对应 |
| --- | --- | --- | --- |
| Java | Thread（8）/ **VirtualThread（21+）** | `synchronized`、JUC Lock/ASCore + JMM(happens-before) | — |
| Go | goroutine | channel + `sync.Mutex`/`atomic`，CSP | Channel ≈ `BlockingQueue` + `SynchronousQueue` 组合；Go runtime 的 GMP 调度器 ≈ ForkJoin work-stealing |
| Rust | thread + async task | `Mutex`/`RwLock`/`Arc`/`Atomic`、`Send`/`Sync` **编译期检查** | Rust 的所有权把"数据竞争"变成**编译错误**——java 只能在运行期用 JMM/锁约束 |
| C++ | `std::thread`/coroutine | `std::mutex`、`std::atomic` + `memory_order` | C++ 的 memory_order 与 Java VarHandle 的 opaque/acquire/release/releaseAcquire 一一对应 |
| Erlang/Elixir | process（BEAM 轻量进程） | mailbox + **无共享内存** + OTP supervisor | Actor ≈ 每个 actor 单线程 + 消息 ≈ 本书「避免共享」终极答案 |
| Python | thread（受 GIL 限制）+ asyncio coroutine | `threading.Lock`、`asyncio` | GIL 让 Python 多线程 **不能并行 CPU**；近似 Java 早期"单线程 + 事件循环"模型 |
| Node/JS | 单线程 event loop + worker_threads | 无锁（无共享内存） | 与 virtual thread 前的异步写法（回调地狱）同样的动因产生了 CompletableFuture/Reactor |
