# 第 6 章 包含多个段的程序

> **一句话**：把数据、代码、栈分别放进各自的段，程序才第一次「像模像样」——本章讲清段的分工，以及为什么本书花了整整一章来讲这个看似琐碎的问题。

---

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 6.1 在代码段中使用数据 | 数据直接跟在 `start:` 后面 | 可行但不优雅：数据与指令混排，读代码困难 |
| 6.2 在代码段中使用栈 | 在代码段末尾开栈 | 可行但要手动设 `SS:SP`，且要防越界 |
| 6.3 将数据、代码、栈放入不同的段 | `data/stack/code` 三段 | **正解**：各自 `segment/ends`，各自设置段寄存器 |

## 核心精讲

> 以下均为**教学示意，不参与构建，不编译不运行**。

### 1) 在代码段中使用数据（6.1）

```asm
; 教学示意，不参与构建
code segment
start:
    mov cx, 5
    mov bx, 0
s:  mov ax, [bx]        ; 这些"数据"其实是代码段里的字节
    add ax, 1
    mov [bx], ax
    add bx, 2
    loop s

    mov ax, 4c00h
    int 21h
code ends
end start
```

问题：数据混在指令里，**`offset` 取地址会跟着代码一起搬**，调试时看到的也可能是同一块内存。所以只适合极小演示。

### 2) 在代码段中使用栈（6.2）

```asm
; 教学示意，不参与构建
code segment
    dw 0, 0, 0, 0, 0, 0, 0, 0     ; 手动留出 16 字节当栈
start:
    mov ax, cs
    mov ss, ax                    ; 栈建在代码段里
    mov sp, 16                    ; 栈顶 = 偏移 16（正好是上面 16 字节之后）

    push ax
    pop  bx
    ...
code ends
end start
```

> 注意：`dw 0 dup(0)` 之类必须保证**段里有足够的字节**。8086 的 `push` 从高向低生长，若 SP 已经指向代码起始处，第一条 push 就会覆盖代码——这属于「栈顶超界」（第 3 章 3.8 讲过）。

### 3) 三段分离的正解（6.3）——本章的最终范式

```asm
; 教学示意，不参与构建
    assume cs:code, ds:data, ss:stack

data segment
    dw 1234h, 5678h, 9abch, 0defh     ; 数据段
data ends

stack segment stack
    dw 0 dup(?)                        ; 栈段（至少 1 字节，实际留够）
stack ends

code segment
start:
    mov ax, data
    mov ds, ax                         ; ① 设 DS —— 数据段靠手动设置才生效

    mov ax, stack
    mov ss, ax                         ; ② 设 SS
    mov sp, 10h                        ;    再设 SP

    mov bx, 0
    mov cx, 4
s:  push [bx]                          ; ③ 用栈做临时保存
    add bx, 2
    loop s

    mov ax, 4c00h
    int 21h
code ends
end start
```

**三点纪律（全书由此定型）**

| 段 | 段寄存器 | 由谁设置 |
| --- | --- | --- |
| 数据段 | DS（必要时 ES） | 程序员：取段址 → `ax` → 段寄存器 |
| 栈段 | SS + SP | 程序员：设 SS 再设 SP（**顺序不能反**） |
| 代码段 | CS | 由装载器/入口设置；运行时不能靠 `mov` 改 |

> 为什么设 SS 必须先设 SS 后设 SP？因为给 SS 赋值的**下一条指令**会隐含使用 SP；若顺序反了，会在 SP 还是旧值时就触发栈操作。这一条在 x86  manuals 里被反复强调。

### 4) 为什么「段」是重要的组织手段

```text
data  段  → 可读写的静态数据；可被 linker 放到不同地址
stack 段  → 生命周期 LIFO 的临时变量区；给函数调用（Ch10）与中断（Ch12）用
code  段  → 指令序列；可被分页、可被映射到只读页
```

## 版本演进

| 年份 | 事件 | 关联 |
| --- | --- | --- |
| 1978 | 8086 的 `segment/ends` 伪指令（MASM 风格） | 本章写法 |
| 1982 | 80286 保护模式：段变成「选择子 → 描述符」 | 段的定义权从程序员手里交给系统 |
| 1985 | 80386：32 位段 + 页式管理 | 段大小的自由度提高，但实用上「扁平模型」流行（段基址=0） |
| 1990s | Win32 / Linux ELF：段（section）由链接器合并， conceptual 段被 section + 段寄存器抽象化 | `data/stack/code` 变成 ELF 的 `.data/.bss/.rodata/.text/.stack` |
| 2003 | x86-64：64 位模式默认忽略段基址（fs/gs 除外） | 段几乎退化为「CS/DS/SS/ES 各为 0」的兼容壳 |
| 2026 | 「段」在应用层的价值归零，在**安全**上重新重要（CFI、Shadow Stack、CET） | 段越界检查以更硬的形式回来了 |

> 一句大实话：今天写 x86-64 程序，你不会再手动 `mov ds, ax`；但「数据 / 栈 / 代码分开」这个思想被链接器和运行时完整保留了，而且它在内存安全议题上重新变得关键。

## 常见误区与本书需修正之处

| # | 误区 / 待修正 | 说明 |
| --- | --- | --- |
| 1 | 🔧 「`assume ds:data` 写了就不用管 DS 了」 | 再强调一次：**`assume` 是给编译器的提示，不是硬件动作**。不手动 `mov ax,data; mov ds,ax`，`[bx]` 会读到别的段。 |
| 2 | 🔧 「栈段可以留 0 字节」 | 8086 上至少要有空间。空栈段 + push 会直接覆盖相邻数据甚至代码。 |
| 3 | 🔧 「先设 SP 再设 SS 也没关系」 | 顺序应为 **SS → SP**。x86 规定给 SS 赋值后的第一条指令隐含使用 SP，顺序反了会立刻错。 |
| 4 | 🔧 「三段分离只是写法上的偏好」 | 它有实际意义：链接器可以分别放置、分别赋予权限（只读代码 / 可写数据），这是后来分页保护与 W^X 的前身。 |
| 5 | 🔧 「今天写代码还要这样分三段」 | x86-64 下你确实不需要。但 **OS 开发、bootloader、固件**依然严格按段/section 组织。 |
| 6 | 「栈段放在数据段里也行」 | 技术上可行（同一段内多处），但会让栈越界静默破坏数据——正是本章反对的做法。 |
| 7 | 🔧 「段越界在现代 CPU 上会被拦住」 | 保护模式有段界限检查，但**应用多用扁平段，等于放弃该保护**。真正的防线是页错误、canary 和 ASLR。 |
