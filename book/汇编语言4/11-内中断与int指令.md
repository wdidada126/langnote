# 第 12-13 章 内中断与 int 指令

> **一句话**：中断是「CPU 正在做的事被打断了，改去执行另一段代码，再回来」；本章把它拆成**四步**（查向量表 → 保护现场 → 执行例程 → `iret` 返回），再补上 `int` 指令与 BIOS/DOS 中断例程这一层「系统调用」。

## 核心精讲

### 1) 中断向量表（12.3）

```text
内存 00000h 开始，1 KB，共 256 个中断向量：
  0 号：地址 0000:0000  → 4 字节：偏移(2) + 段(2)
  1 号：地址 0000:0004
  n 号：地址 0000:(n × 4)      ← 记住这个公式
  FF 号：地址 0000:03FC

BIOS 占用 00–1F（含 int 13h 磁盘、int 16h 键盘、int 10h 显示）
DOS   占用 20–3F（int 21h 等）
```

> **关键洞察**：中断向量表只是一块普通内存。**你能写它，就能劫持中断**——这就是本书实验 12（改写 0 号向量）与实验 15（改写 `int 9`）的原理，也是现代 rootkit 的同一手法。

### 2) CPU 响应中断时自动做的事（12.4）

```asm
; 教学示意，不参与构建（CPU 硬件行为，不是你写的代码）
; 1) pushf           ; 标志寄存器入栈
; 2) push CS         ; 段寄存器入栈
; 3) push IP         ; 偏移入栈            ← 这 3 步是硬件自动完成
; 4) 取中断向量 n 的 4 字节：IP ← [n*4], CS ← [n*4+2]
; 5) 从新 CS:IP 开始执行中断处理程序
```

对应 `iret`（12.5）：

```asm
; 教学示意，不参与构建
iret                    ; ≡ pop IP ; pop CS ; popf
```

**与 `call/ret` 的对照**（呼应第 10 章）

| 项 | `call/ret` | 中断 |
| --- | --- | --- |
| 谁压返回地址 | `call` 指令 | **CPU 硬件自动** |
| 保护标志 | 不保护 | `pushf` 自动 |
| 返回指令 | `ret` | `iret` |
| 目标地址来源 | 指令中的操作数 | **中断向量表** |
| 可嵌套 | 可以（有返回地址） | 可以（IF 控制开关） |

### 3) 0 号中断：自己造出来的中断（12.6–12.10）

```asm
; 教学示意，不参与构建
; 实验 12 的核心：把自定义例程安装到 0 号向量
data segment
    dw 0, 0, 0                    ; 给中断处理程序留空间（数据段）
data ends

code segment
start:
    ; ① 把中断例程的代码复制到安全空间（本书用 0:200 起）
    mov ax, 0
    mov es, ax
    mov bx, 0200h
    mov si, offset do0
    mov cx, offset do0end - offset do0
copy_loop:
    mov al, [si]
    mov es:[bx], al
    inc si
    inc bx
    loop copy_loop

    ; ② 设置中断向量：0 号 → 段 0，偏移 0200h
    cli                             ; 关中断，避免安装过程中被打断
    mov ax, 0
    mov ds, ax
    mov word ptr [0*4],  0200h      ; IP
    mov word ptr [0*4+2], 0         ; CS
    sti                             ; 开中断

    mov ax, 4c00h
    int 21h

do0:
    ; ③ 中断例程体（打印提示）
    ;    注意：中断里所有用到的寄存器都要 push/pop 保护
do0end:
    nop
code ends
end start
```

> 三个必须记住的陷阱：**(a)** 例程要能「浮动」（所以要用相对寻址，不能写绝对地址）；**(b)** 设置向量前必须 `cli`，设完再 `sti`；**(c)** 例程内部改 DS 会破坏被中断程序的数据，务必保存。

### 4) BIOS / DOS 中断例程（13.4–13.7）

```asm
; 教学示意，不参与构建
; 直接写显存（80×25 文本模式，第 0 行第 0 列）
    mov ax, 0b800h
    mov es, ax
    mov byte ptr es:[0], 'H'    ; 字符
    mov byte ptr es:[1], 07h    ; 属性（灰底白字）

; 用 BIOS 中断例程（int 10h, AH=02h 置光标位置）
    mov ah, 02h
    mov bh, 0                   ; 页号
    mov dh, 10                  ; 行
    mov dl, 30                  ; 列
    int 10h                     ; BIOS 视频服务

; DOS 功能调用（int 21h, AH=09h 显示字符串，DS:DX 指向，$ 结尾）
    mov ax, data
    mov ds, ax
    mov dx, offset s
    mov ah, 09h
    int 21h
```

**常用中断速查**

| 中断 | 功能 | 常用寄存器 |
| --- | --- | --- |
| `int 10h` | BIOS 视频服务 | `AH`=子功能 |
| `int 13h` | BIOS 磁盘服务（**第 17 章主戏**） | `AH`=读/写, `AL`=扇区数, `CX`=柱面/扇区, `DS:BX`=缓冲区 |
| `int 16h` | BIOS 键盘服务（**第 17 章主戏**） | `AH=0` 读键（`AX` 返回） |
| `int 21h` | DOS 系统调用 | `AH`=功能号；`4Ch` 退出 |
| `int 9h` | **硬件**键盘中断（第 15 章） | — |

## 版本演进

| 年份 | 事件 | 关联 |
| --- | --- | --- |
| 1978 | 8086：中断向量表 + `int n`/`iret` | 本章主角 |
| 1982 | 80286/AT：8259 中断控制器两级级联，IRQ0–15 | 第 15 章的外中断 |
| 1985 | 80386：保护模式下的 IDT（门描述符）取代裸向量表 | 向量表从「4 字节偏移/段」变成「8 字节门」 |
| 1990s | 高级配置与电源接口（ACPI）；MP 规范让 APIC 成为可能 | `int n` 仍在，但分发者换成了 APIC |
| 2000s | x86-64：`syscall`/`sysenter` 提供**更快**的系统调用路径 | `int 80h` 被淘汰出快速路径（Linux 仍在保留兼容入口） |
| 2026 | 内核用 `entry_SYSCALL_64` / `entry_INT80_32` 双入口；seccomp 插在中间 | 「系统调用」的概念没变，只是入口更丰富 |

> 一个漂亮的演变：**`int n` → `syscall`**，替代的动机始终是「`int` 太慢」（要查表、要压栈）。但 `int` 的**语义模型**在 x86-64 上完整保留了下来。

## 常见误区与本书需修正之处

| # | 误区 / 待修正 | 说明 |
| --- | --- | --- |
| 1 | 🔧 「把中断例程直接用 `mov` 写在代码段里，把它的地址填进向量表就行」 | 通常不行：例程可能被装载到与你预想不同的段地址，内部若用了绝对地址就会飞。本书 12.8 的「安装」做法（复制到 0:200）正是为此。 |
| 2 | 🔧 「修改向量表前不用关中断」 | 必须 `cli` … `sti` 包住。否则安装过程中被中断，会用一个半写的向量直接跳到垃圾地址。 |
| 3 | 🔧 「`iret` 和 `retf` 一样」 | `iret` 是 `pop IP; pop CS; popf`，**还恢复标志**；`retf` 是 `pop IP; pop CS`。在中途错误使用会导致标志破坏。 |
| 4 | 🔧 「中断例程里随便用寄存器」 | 中断会打断任何代码，例程**必须**保护它用到的所有寄存器（除 `AX` 等由调用约定决定的）。这是本书反复强调的。 |
| 5 | 🔧 「`int 13h` 读盘能驱动现代硬盘」 | 只能访问到 8 GB 以内的 CHS 范围；大容量磁盘要用 `int 13h` 的扩展调用（LBA，`AH=42h`/`43h`），而 UEFI 下干脆用 `int 10h` 的 `UEFI BIOS` 接口或直接自己写 AHCI。 |
| 6 | 🔧 「`int 21h` 是今天的系统调用」 | 在 Linux 上应该是 `syscall`（`rax`=号，`rdi/rsi/rdx`），在 Windows 上走 NTDLL。`int 21h` 只在 DOS / 兼容层里存在。 |
| 7 | 🔧 「中断向量表 = 现代 x86 的中断机制」 | 从 80386 起，保护模式下用的是 **IDT 中的门描述符**（含特权级、类型）。本书讲的是实模式的极简版本，够用来理解原理，但不足以写内核。 |
| 8 | 🔧 「`div` 除零只会崩」 | 在装上自定义 0 号中断例程后，你可以**完全接住**它——这正是实验 12 的收获，也是理解异常的最好方式。 |
| 9 | 「单步中断（TF）已经没人用了」 | 硬件断点、调试器、逆向分析全都依赖它；`debug -t` 就是 TF 的直接应用。 |
