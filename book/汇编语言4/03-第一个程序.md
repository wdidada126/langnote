# 第 4 章 第一个程序

> **一句话**：这一章用 1 个小程序把「编辑 → 编译 → 连接 → 装载 → 执行 → 跟踪」整条链路走一遍，并回答那个被忽略的问题：**到底是谁把程序搬进内存并让它跑起来的？**

## 核心精讲

> 以下均为**教学示意，不参与构建，不编译不运行**。

### 1) 从写出到执行的五个阶段（4.1）

```
  编辑 (edit)    →  源程序 .asm      (伪指令 + 汇编指令 + 标号)
  编译 (masm)   →  目标文件 .obj     (机器码 + 重定位信息)
  连接 (link)   →  可执行文件 .exe   (多个 .obj 合并，解析外部地址)
  装载 (loader) →  内存中的进程映像 (command.com 完成)
  执行 (run)    →  CPU 从 CS:IP 开始逐条执行
```

### 2) 源程序的骨架（4.2）

```asm
; 教学示意，不参与构建
; 文件名: t.asm
    assume cs:code, ds:data, ss:stack

data segment
    db 1, 2, 3, 4, 5            ; 数据段：db/dw/dd 定义数据
data ends

stack segment stack
    dw 0 dup(?)                 ; 栈段：至少留出一个字节，否则栈可能出问题
stack ends

code segment
start:                          ; 入口标号：告诉编译器 'end start' 的 start 在哪
    mov ax, data
    mov ds, ax                  ; DS 指向数据段，才能用 [x] 取数据
                                ;
    mov ax, 4c00h
    int 21h                     ; DOS 功能 4Ch = 带返回码正常退出
code ends

end start                       ; 伪指令 end：源程序到此结束，入口 = start
```

**伪指令清单（编译器执行，不产生机器码）**

| 伪指令 | 作用 |
| --- | --- |
| `segment` / `ends` | 定义段，`segment` 与 `ends` 必须配对 |
| `assume` | 把「段名」与「段寄存器」的对应关系告诉编译器（**注意：assume 只影响编译期的语法检查，真正生效要靠你手动给段寄存器赋值**） |
| `end start` | 源程序结束，并指定入口地址标号 |
| `db / dw / dd` | 定义 1 / 2 / 4 字节数据 |
| `dup(n)` | 重复数据 |

### 3) 编译与连接（4.4 / 4.5）

```bash
masm t.asm t.obj        ; 汇编：检查语法，产生目标文件
link t.obj t.exe        ; 连接：合并段、解析符号、产生 exe 头（重定位表）
                        ; 简化：masm t.asm; link t.obj;
```

> `.exe` 文件里除了机器码，还有 **MZ 头 + 重定位表**，装载器靠它把映像搬到内存并修正段内偏移。

### 4) 谁装载了程序（4.8）

```text
开机 → BIOS 自检 → 读引导扇区到 0x7C00 →  bootloader
                                      ↓
                          加载 command.com（DOS 外壳）
                                      ↓
      用户在提示符下输入 t.exe → DOS 找到 .exe 头
                                      ↓
      command.com 分配内存块 (MCB 链)，把 .exe 读入内存，修正重定位
                                      ↓
                    设置 CS:IP 指向入口（.text 段 + 重定位后的偏移）
                                      ↓
                                  CPU 开始执行
```

> 结论：**「谁」是 DOS 的装载器（command.com 的一部分）；CPU 只提供 `CS:IP` 这个入口，不会自己去磁盘找程序。** 这与 Linux 下 `execve` 由内核装载、入口由 ELF 头的 `e_entry` 指定，是同一件事的两个版本。

### 5) 用 Debug 跟踪（4.9）

```bash
debug t.exe
-r          ; 看当前所有寄存器的值（CS/IP/DS/SS/SP 一眼全貌）
-u          ; 反汇编从 CS:IP 开始的若干条指令
-t          ; 单步（进入：会跟到 int 中断内部）
-p          ; 单步（跳过：把 int 21h 当成一条执行完）
-d  ds:0    ; 看数据段内容
-g =0 100   ; 从 0 跑到 100 地址处
```

## 版本演进

| 年份 | 事件 | 对「第一个程序」的影响 |
| --- | --- | --- |
| 1981 | MS-DOS 1.0（IBM PC DOS） | `.exe` 重定位表、MCB 内存链、`.com` 无头直接装载 |
| 1985 | 80386 / DOS 扩展器（DOS/4GW、Watcom） | 32 位 `.exe` 需要额外的 DOS 扩展格式 |
| 1994 | Win32 推出 | 「程序装载」交给 PE loader；`CS:IP` 不再是入口，入口是 PE 的 `AddressOfEntryPoint` |
| 1990s– | ELF / systemd | Linux 下同样是「loader 读文件头 → mmap → 设置寄存器入口」 |
| 2026 | — | 今天写「第一个程序」多半是 **C 的 `main`** 或 **`_start` + NASM**；裸机入口仍是 `jmp` 到自己的代码 |

> 不变的是：**入口地址总是一个寄存器值**。变的是谁来填它（DOS shell / PE loader / ELF loader / firmware）。

## 常见误区与本书需修正之处

| # | 误区 / 待修正 | 说明 |
| --- | --- | --- |
| 1 | 🔧 「`assume ds:data` 之后就可以直接用 `[x]` 了」 | **不能**。`assume` 只对编译器有意义，硬件不看它。你必须自己 `mov ax,data; mov ds,ax`，否则读到的是错误段。这是初学者第一大坑。 |
| 2 | 🔧 「`end start` 里的 `start` 是指令」 | `start` 是**标号**（地址），`end` 是伪指令，用来告诉 MASM「入口在这里」。漏写或写错会导致从错误地址开始执行。 |
| 3 | 🔧 「栈段可以一个字节都不定义」 | 至少要留出足够的栈空间。`dw 0 dup(?)` 之类是常见写法；有些环境下空栈段会直接崩。 |
| 4 | 「程序结束了 CPU 就停了」 | DOS 程序结束是「`int 21h/4Ch` 把控制权还给 command.com」。CPU 永远在执行某条指令，只是控制权换了人。 |
| 5 | 🔧 「本书的 `.exe` 流程 = 现代程序流程」 | 现代是 PE/ELF loader + mmap + 动态链接 + ASLR。`CS:IP` 入口已被 PE/ELF 的 entry point 取代，装载者从 command.com 变成内核。 |
| 6 | 🔧 「手写 `int 21h` 退出比 `return 0` 高级」 | 在 Linux 上正确写法是 `mov rax,60; xor rdi,rdi; syscall`（x86-64）或 `exit_group`；`int 21h` 只在 DOS 有意义。 |
| 7 | 「Debug 里的 `-t` 单步就是 CPU 单步」 | `-t` 遇到 `int` 会**进入中断例程内部**（跳到中断向量指向的代码），`-p` 才是执行完整条 `int`。区别在 4.9 与 Ch13。 |
