# 第 14-15 章 端口、CMOS RAM 与外中断

> **一句话**：凡是「CPU 不去取内存指令、而是去问某个芯片」的地方，都落在端口上——CMOS RAM 走 `70h/71h` 端口，键盘走 `60h/64h` 端口；而外中断的本质是「外部芯片拉高 INTR 线 → CPU 完成当前指令后查中断向量」。

## 核心精讲

### 1) 端口读写（14.1）

```asm
; 教学示意，不参与构建
; 端口地址在 8 位寄存器里时：
    in  al, 70h          ; 读端口 70h → al
    out 71h, al          ; 写端口 71h
; 端口地址超过 255 时，要先送 DX：
    mov dx, 3f8h         ; COM1 的数据端口
    in  al, dx
    out dx, al
```

| 指令 | 说明 |
| --- | --- |
| `in acc, port8` | 从 8 位端口输入到 AL/AX |
| `in acc, dx` | 从 DX 指定的端口输入 |
| `out port8, acc` | 输出到 8 位端口 |
| `out dx, acc` | 输出到 DX 指定端口 |

> 端口是 x86 上**独立于内存**的 64 KB 地址空间（`in`/`out` 与 `mov` 走不同的控制线）。这与 ARM/SoC 常见的内存映射 I/O 是两条设计路线。

### 2) CMOS RAM：用 `shl/shr` 解开 BCD（14.2–14.4）

```asm
; 教学示意，不参与构建
; CMOS 里存的是 BCD：一个字节高 4 位是十位，低 4 位是个位
; 读 "时"（CMOS 偏移 04h）
    mov al, 04h
    out 70h, al          ; 选寄存器
    in  al, 71h          ; 读出 BCD 字节，比如 0x93（= 93，BCD）
    mov ah, al
    and ah, 0fh          ; 个位 → 3
    shr al, 1
    shr al, 1
    shr al, 1
    shr al, 1            ; 高 4 位右移 4 位 → 9
    mov bl, ah           ; 十位
    mov bh, 0
    mov cx, 10
    mul cx               ; AX = 9 * 10 = 90
    add ax, bx           ; 90 + 3 = 93（二进制值）

; 更省事的写法：and 0Fh 取个位，shr 4 取十位
    mov ah, al
    and al, 0fh
    mov cl, 4
    shr ah, cl
```

**CMOS RAM 的常用偏移**

| 偏移 | 含义 |
| --- | --- |
| 00h | 秒 |
| 02h | 分 |
| 04h | 时 |
| 06h | 星期 |
| 07h | 日（月中的第几天） |
| 08h | 月 |
| 09h | 年 |
| 0Ah | 状态寄存器 A（时钟频率等） |
| 0Ch | 状态寄存器 B（24/12 小时制等） |
| 20h–7Fh | 通用 RAM（128 字节的后 96 字节） |

> 现代意义：CMOS 里的**时间信息**仍被 BIOS/UEFI 使用；「往 CMOS 里写 0x00 让机器忘记开机密码」只是历史段子，现代机器的密码存在 NV/TPM 里。

### 3) 外中断与 8259（15.1–15.2）

```text
可屏蔽中断（INTR）：
   IF = 1  → CPU 在完成当前指令后响应
   IF = 0  → CLI 后的指令序列不会再被外部中断打扰
   8259 主片端口 20h/21h，从片（AT 起）端口 A0h/A1h
   IRQ0=定时器  IRQ1=键盘  IRQ2=从片  IRQ8–15=级联来的外设

不可屏蔽中断（NMI）：
   内存校验错、ECC 错、温度告警等；不受 IF 影响
```

```asm
; 教学示意，不参与构建
    cli                  ; 关可屏蔽中断，进入临界区
    ...                  ; 读写 8259 端口、更新自己的数据
    sti                  ; 再开
```

### 4) 键盘的完整链路（15.3–15.5）

```text
按下按键
  ↓
8042/8048 键盘控制器识别按键 → 生成扫描码（scancode）
  ↓
写进 0x60 端口的数据寄存器；同时拉高 8259 的 IRQ1
  ↓
CPU 收到 IRQ1 → 查中断向量表的 9 号项 → 跳转到 int 9 例程
  ↓
int 9 例程：in al, 60h（读扫描码）→ 处理 → iret
```

安装新 `int 9`（保留旧例程，形成中断链）：

```asm
; 教学示意，不参与构建
    ; ① 把旧的 9 号向量保存起来
    cli
    push ds
    mov ax, 0
    mov ds, ax
    push word ptr [9*4]     ; 旧 IP
    push word ptr [9*4+2]   ; 旧 CS
    ; ② 安装自己的例程到 9 号向量（同 12 章的手法）
    ...
    pop ax                  ; 先恢复旧的 CS
    ...
    pop ds
    sti
```

> 「中断链」思想在今天的对应物就是内核里的 `notifier_block` / `kernel module` 钩子：谁都可以插一脚，但要**保留并调用原来的**。

## 版本演进

| 年份 | 事件 | 关联 |
| --- | --- | --- |
| 1978 | 8086 的 `in/out` 与端口空间 | 本章主角 |
| 1981 | IBM PC：8255 并行口、8259 单级中断控制器、MC146818 时钟 | 端口布局的原型 |
| 1984 | IBM PC/AT：8259 两级级联（IRQ2 级联从片），8042 键盘控制器 | IRQ8–15 的由来 |
| 1985 | 80386：MPS/MP 规范与 APIC 引入 | 中断分发从「8259 单级」走向「APIC 矢量」 |
| 1997 | ACPI 规范 | 传统 8259 与 APIC 的共存；` ACPI` 命名空间接管电源管理 |
| 2003 | x86-64：`syscfg`/LAPIC 成为主流 | 传统 IRQ 仅作兼容 |
| 2026 | 内核仍保留 `legacy PIC` 支持，但新平台默认 APIC/x2apic | 本书的 8259 世界观是「博物馆级的清晰模型」 |

> 值得强调：本书讲的 8259 模型在**结构上极其清晰**，至今仍是理解中断分发思想的最佳教材；只是真实硬件早已换成 APIC。

## 常见误区与本书需修正之处

| # | 误区 / 待修正 | 说明 |
| --- | --- | --- |
| 1 | 🔧 「`out 70h, al` 之后马上 `in al, 71h` 就能读到新值」 | CMOS 访问有一定建立时间；连发两次读同一寄存器有时会读到旧值。稳妥做法是读两次比对（本书有提到「为了保险读两次」）。 |
| 2 | 🔧 「CMOS 里存的是二进制数」 | 是 **BCD 码**（每 4 位存一位十进制数字），所以要 `and 0Fh` / `shr 4` 拆位。直接当二进制用会得到错误时间。 |
| 3 | 🔧 「端口和内存是同一块空间」 | x86 上端口**独立编址**（`in/out`，64 KB 个）；ARM/SoC 多用内存映射 I/O（`ldr` 读设备寄存器）。两条路线，别混。 |
| 4 | 🔧 「`cli` 之后就彻底不会被中断」 | `cli` 只关**可屏蔽**的 INTR。NMI（内存错误、温度告警）照样来。 |
| 5 | 🔧 「装 `int 9` 例程时可以直接覆盖旧的」 | 会丢掉原键盘驱动。正确做法是**保存旧向量并在自己处理完后调用它**——这就是中断链。 |
| 6 | 🔧 「`shl ax, 1` 等价于 `add ax, ax`，所以 `shr ax,1` 等价于 `div ax,2`」 | 对**无符号**成立。有符号要用 `sar`；且移位与除法在标志位影响、`CF` 语义上并不等价（尤其 `shl` 与 `mul` 对 CF 的处理不同）。 |
| 7 | 🔧 「今天的程序也能直接 `out 70h, al`」 | 从用户态访问固定 I/O 端口（`ioperm`/`iopl`）在 Linux 上受限，Windows 上更严格。内核驱动里才常见。 |
| 8 | 🔧 「8259 的现代机器还在用」 | 新平台默认 APIC/x2apic；8259 只作为兼容层存在。但**IRQ 编号与级连结构的思想**被完整继承。 |
| 9 | 「往 CMOS 写 0 就能清开机密码」 | 只适用于极老的 AMI/Award BIOS；现代机器密码存在 NV 存储或 TPM 里，且写 CMOS 常会触发启动密码校验而非清除密码。 |
