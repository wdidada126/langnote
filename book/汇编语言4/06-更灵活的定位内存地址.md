# 第 7 章 更灵活的定位内存地址的方法

> **一句话**：`and/or` 加上 `[bx+idata]`、`[bx+si]`、`[bx+si+idata]` 三类复合寻址，让汇编第一次可以「像数组一样」——用下标和增量表达「第 i 个元素」，而不是手算偏移。

## 核心精讲

### 1) `and` / `or` 与大小写转换（7.1–7.4）

```asm
; 教学示意，不参与构建
; ASCII：'A' = 41h，'a' = 61h，第 5 位（bit5, 值 20h）是区分大小写的一位
;
; 小写 → 大写：清 bit5
    mov al, 'a'            ; al = 61h
    and al, 0dfh           ; 61h and DFh = 41h → 'A'
; 0DFh = 1101 1111b，清掉 bit5

; 大写 → 小写：置 bit5
    mov al, 'A'            ; al = 41h
    or  al, 20h            ; 41h or 20h = 61h → 'a'

; 判断是否为字母（不跳转的写法，靠测试位）
    test al, 20h           ; 只关心 bit5，结果反映"是不是小写"
```

### 2) `[bx+idata]`：这是「数组访问」的经典形态（7.5 / 7.6）

```asm
; 教学示意，不参与构建
; 把 0 号字符串的第 3 个字符改成 'Z'
    mov ax, data
    mov ds, ax
    mov bx, 0              ; bx = 字符串下标
    mov cx, 5              ; 假设有 5 个字符串
s:
    mov dl, [bx+3]         ; 第 bx 个字符串的第 3 个字符
    or  dl, 20h            ; 转小写写回演示
    mov [bx+3], dl
    inc bx
    loop s
```

> **核心直觉**：`[bx+3]` 里 `bx` 是「行/记录」，`3` 是「字段偏移」。只要元素大小一致，就能写成 `[bx + sizeof(elem)]`。
> 常见错误：忘了乘元素大小——`dw` 数组要用 `[bx+2*i]`，写成 `[bx+i]` 会读错。

### 3) `[bx+si]` / `[bx+di]`：两个下标（7.7 / 7.8）

```asm
; 教学示意，不参与构建
; 二维数组 a[row][col]，按行优先
    mov bx, 0              ; 行下标
    mov si, 0              ; 列下标
    mov ax, a[bx][si]      ; MASM 语法；NASM 写作 [bx+si]
    ; 手工展开（64 位Talk：x86 只有二维偏移没有真正的多维）：
    ; 物理偏移 = bx * row_size + si
```

> 8086 只有 `base + index*1` 这一种比例因子（比例因子固定为 1，没有 `index*4`）。**这正是 x86 寻址方式在 80386 之后才加 `index*scale` 的原因**。做 `dw` 数组时你要自己乘 2。

### 4) `[bx+si+idata]`：完整形态（7.9）

```asm
; 教学示意，不参与构建
; 结构：table[i] 是一个 4 字节元素，第 2 个字段是名字
    mov ax, table
    mov ds, ax
    mov bx, 0              ; 元素下标
    mov si, 2              ; 字段偏移
    mov cx, 10
s:  mov ax, [bx+si+4]      ; 基址(bx) + 变址(si) + 常量偏移(4)
    add bx, 4              ; 元素大小 = 4
    loop s
```

### 5) 完整的寻址方式谱系（7.10）

| 分类 | 形式 | 8086 是否支持 |
| --- | --- | --- |
| 立即数 | `mov ax, 5`（不是内存寻址） | 支持 |
| 寄存器 | `mov ax, bx` | 支持 |
| 直接 | `[idata]` | 支持（`[0]`, `[1000h]`） |
| 基址 | `[bx]` / `[bp]` | 支持（bp 默认 SS） |
| 基址+偏移 | `[bx+3]` / `[bp+3]` | 支持（idata 为 8/16 位） |
| 变址 | `[si]` / `[di]` | 支持 |
| 基址+变址 | `[bx+si]` / `[bx+di]` | 支持 |
| 基址+变址+偏移 | `[bx+si+3]` | 支持 |
| **比例变址** | `[bx+si*4]` | **8086 不支持**（80386+ 才有） |

## 版本演进

| 年份 | 事件 | 关联 |
| --- | --- | --- |
| 1978 | 8086：最多 `base + index + disp`，比例因子恒为 1 | 本章主角 |
| 1982 | 80286：同上（16 位保护） | — |
| 1985 | **80386：`[base + index*scale + disp]`，scale ∈ {1,2,4,8}** | 数组访问终于可以由硬件算乘除 |
| 1993 | Pentium：寻址单元变多，2 个操作数可同时访问内存 | `mov [eax],[ebx]` 非法仍存在 |
| 2003 | x86-64：SIB 字节编码上述组合，64 位寻址 | 今天写的内联汇编里最常见 `[rbp-8]`、`[rax+rcx*4]` |
| 2013+ | AVX/AVX-512 引入地址寄存器压缩（1GB page、ISA 级不变） | 寻址能力继续膨胀，ISA 层面无新变化 |

> 从 8086 到 x86-64，寻址方式几乎没有本质变化，只是**位数从 16 扩到 64、多了比例因子**。这正说明：*寻址方式的形状在一开始就被定死了，后面四十年只是放大。*

## 常见误区与本书需修正之处

| # | 误区 / 待修正 | 说明 |
| --- | --- | --- |
| 1 | 🔧 「`[bx+si]` 里 si 可以是任意寄存器」 | 只能用 **bx/bp/si/di** 作基址，si/di/bx 作变址；**ax/cx/dx 不能做地址寄存器**。这是 8086 的硬性限制。 |
| 2 | 🔧 「`[bp]` 和 `[bx]` 一样默认 DS」 | **`[bp]` 默认段寄存器是 SS**。这是第 8 章要点，也是本书第 2 章埋下的伏笔，容易漏。 |
| 3 | 🔧 「8086 也能写 `[bx+si*4]`」 | 不能。比例因子是 8086 之后才有的。用 `dw` 数组必须自己 `add bx,2` / `shl bx,1`。 |
| 4 | 🔧 「`and al, 0dfh` 总是能转大写」 | 只适用于 A–Z 与 a–z。其它字符（数字、符号、汉字）会被破坏。要「判断后转换」得先 `cmp` 范围。 |
| 5 | 🔧 「字符常量 `'a'` 就是 1 字节」 | 在 MASM 里 `'a'` 是 1 字节立即数，但 `db 'ab'` 是 2 字节；`mov ax,'ab'` 这种写法会按小端拼成 0x6162，含义容易混淆。 |
| 6 | 🔧 「本章的寻址方式也就是现代汇编的全部」 | 现代还有 RIP 相对寻址（`[rip+disp32]`，位置无关代码的基础）、SIB 的 32/64 位形式，以及 AVX-512 的掩码寄存器寻址。 |
| 7 | 🔧 「手写用 `[bx+si]` 会更快」 | 现代 CPU 的 load/store 单元会**自动合并相邻访问**（宏融合/向量化）。手写循环的常见结果是更慢，而非更快。 |
