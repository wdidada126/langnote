# 第 8 章 数据处理的两个基本问题

> **一句话**：「数据在哪」（地址表达式）与「数据有多长」（8 位还是 16 位）——这两个问题决定了汇编指令能不能合法编译，也决定了本书后半段（转移、栈、中断）能否写对。

## 核心精讲

> 以下均为**教学示意，不参与构建，不编译不运行**。

### 1) 数据在哪：三类来源（8.2 / 8.3）

```asm
; 教学示意，不参与构建
mov ax, 1        ; ① 立即数 idata：1 就在指令里
mov ax, bx       ; ② 寄存器 reg：数据在 bx 里
mov ax, [bx]     ; ③ 内存 mem：数据在 ds:bx 指向的内存里
add [si], word ptr 10 ; 内存 ↔ 立即数（注意必须说明长度）
```

### 2) 数据有多长：本章最容易被忽略、也最容易出错的一点（8.5）

```asm
; 教学示意，不参与构建
mov ax, data
mov ds, ax

mov byte ptr [bx], 0        ; 写 1 个字节，目标 [bx] 处开始的 1 字节
mov word ptr [bx], 0        ; 写 2 个字节（16 位）

; 若省略 ptr：
mov [bx], 1                 ; MASM 会"猜"——碰到"1"通常按 1 字节处理
                             ; 但合到一起时可能变成 2 字节，静默错误
```

**规则**：只要有内存操作数，就明确写出 `byte ptr` 或 `word ptr`（NASM 里改写成 `byte [bx]` / `word [bx]`）。

### 3) `div` 与 `dd`（8.7 / 8.8）

```asm
; 教学示意，不参与构建
; 16 位除法：被除数隐含在 AX（或 DX:AX），除数是指令操作数
;   div byte ptr [bx]  →  AL = AX / op   ,  AH = AX % op
;   div word ptr [bx]  →  AX = DX:AX / op,  DX = DX:AX % op
; 注意：商为 16 位时，被除数必须是 DX:AX 形式

; 用 dd 定义 32 位数据，配合 16 位 div 做 32 位运算
data segment
    dd 100001h            ; 4 字节
data ends
...
    mov ax, 4c00h
    int 21h

; 更常见的技巧：把 32 位数拆成高 16 位 DX 与低 16 位 AX
    mov dx, high_word
    mov ax, low_word
    div cx                ; dx:ax ÷ cx → ax=商, dx=余数
```

> `div` 的除数为 0、或商溢出（如 `ax ÷ 1` 但 ax > 0FFFFh）都会触发 **0 号中断**（本书第 12 章的核心实验就是捕获它）。

### 4) `dup`（8.9）

```asm
; 教学示意，不参与构建
data segment
    db  200 dup(0)        ; 200 字节的缓冲区，全 0
    dw  10 dup(0)         ; 10 个字，全 0
    db  3 dup('ab')       ; 重复字符串
data ends
```

### 5) 结构化数据访问（8.6）

```text
假设数据布局（record 结构）：
    +0  dw  id
    +2  dw  score
    +4  db  name[8]
    +12 db  valid

取第 i 条记录的 score：
    mov ax, [bx + 2]        ; bx = i*12
取第 i 条记录的 name[3]：
    mov al, [bx + 4 + 3]    ; 即 [bx+7]
```

> 这是「结构体」在 8086 上的真实样子：**没有 `struct`，只有偏移量的算术。**

## 版本演进

| 年份 | 事件 | 关联 |
| --- | --- | --- |
| 1978 | 8086：无符号除法 `div`，有符号 `idiv`；`cwd/cbw` 做符号扩展 | 本章 8.7 |
| 1985 | 80386：`div` 支持 32 位；`movsx/movzx` 显式扩展 | 「数据有多长」变得可显式控制 |
| 1990s | SSE 之后的「数据类长度」扩展为 128/256/512 位 | 长度问题从 8/16 变成 8/16/32/64/128/256/512 |
| 2003 | x86-64：`movsx/movzx` 全套，`div` 支持 64/128 位 | `rdx:rax ÷ r/m64` |
| 2026 | 自动向量化与 mask 寄存器让「长度」由编译器决定 | 手写时常用 `vpcmpeqb` 等一次处理 64 字节 |

> 一个有趣的观察：**「数据有多长」这个问题从 8086 提出后，一直没有消失过，只是长度值从 8/16 变成了更宽的集合。**

## 常见误区与本书需修正之处

| # | 误区 / 待修正 | 说明 |
| --- | --- | --- |
| 1 | 🔧 「不写 `word ptr` 没关系，编译器会处理」 | **在内存操作数上省略长度修饰是最大的静默 bug 来源**。MASM 的推断规则在 `add [bx], 1` 和 `add [bx], word ptr 1` 之间可能给出完全不同的机器码。NASM 里则是 `byte [bx]` / `word [bx]`，语法换汤不换药。 |
| 2 | 🔧 「`div` 除数是 0 就返回一个特殊值」 | x86 上是**触发 0 号中断（#DE 异常）**。PC 机上若未安装自定义 0 号中断例程，会直接显示 `Divide error` 或死机。本书实验 12 就是捕获它。 |
| 3 | 🔧 「`div word ptr [bx]` 的被除数就是 AX」 | 16 位除法时被除数是 **DX:AX**（DX 存高 16 位，AX 存低 16 位）；8 位除法才是 AX。商超出目标寄存器同样触发 #DE。 |
| 4 | 🔧 「`bp` 和 `bx` 一样都是基址寄存器」 | `bp` **默认段寄存器是 SS**，这是栈帧访问（`[bp+...]`）能工作的根本原因（第 9 章栈帧）。 |
| 5 | 🔧 「ax/cx/dx 也能做地址寄存器」 | 不能。8086 的地址寄存器只有 bx/bp/si/di（32 位后是全部 8 个）。 |
| 6 | 🔧 「32 位除法用 x86-64 就简单了」 | x86-64 的 `div r/m64` 依然是 **rdx:rax ÷ r/m64**，且代价很高。现代代码多用乘法倒数或 FPU。 |
| 7 | 🔧 「本章的 `dd`/`dup` 在现代汇编里也有」 | 概念相同，语法不同：NASM 用 `dd`/`dq`/`dt` 与 `times 200 db 0`；GAS 用 `.long`、`.zero 200`。 |
