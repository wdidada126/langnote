# 第 5 章 [BX] 和 loop 指令

> **一句话**：`[BX]` 让「地址」变成可以程序计算的东西，`loop` 让「重复」变成一条指令——这两条合起来，第一次有了「会循环、会遍历数组」的汇编程序。

## 核心精讲

> 以下均为**教学示意，不参与构建，不编译不运行**。

### 1) `[BX]`：把偏移放进寄存器

```asm
; 教学示意，不参与构建
    mov ax, 1000h
    mov ds, ax           ; ds 指向 1000h 段
    mov bx, 0            ; bx 当"指针"

    mov ax, [bx]         ; (ax) = (ds:0)     第一个字
    add bx, 2            ; 指针后移一个字（不是 1 字节！）
    mov ax, [bx]         ; (ax) = (ds:2)     第二个字
```

> 关键点：`inc bx` 使偏移 +1，但对 16 位数据要 `add bx, 2`。**`bx` 是字节偏移，不是元素下标。** 这一点是数组遍历最容易写错的地方。

### 2) `loop` 指令的语义（严格）

```asm
; 教学示意，不参与构建
    mov cx, 5            ; 循环次数放进 CX
    mov bx, 0
    mov ax, 0            ; 累加器清零

s:  add ax, [bx]         ; 循环体（标号 s 在这里）
    add bx, 2            ; 前进一个字
    loop s               ; ① (cx) ← (cx) - 1  ② 若 (cx) ≠ 0 则 IP 回跳到 s

    ; 循环次数 = 初始值；cx 不能当普通寄存器在循环体中乱用
```

精确语义（本章最重要的一句）：

```
loop s:   cx ← cx - 1
          if cx ≠ 0 then IP ← 标号 s 处的偏移（相对位移）
          else 顺序执行下一条
```

即：**`loop` 先减，再判断，最后一次（cx=1 时）跳过跳转，直接退出循环。**

### 3) Debug 与 MASM 的差异（5.4）

```asm
; 教学示意，不参与构建
; 在 Debug 中用 -e 手工写入的代码：
;     mov ax,[0]      ← Debug 里 [0] = 读 ds:0 的内存
; 在 MASM 里写：
    mov ax, 0         ← 若误写成 "mov ax,[0]"，MASM 认为 0 是立即数或需要定义
```

常见原因：MASM 中 `[ ]` 有歧义，需要 `offset` 取地址；而 Debug 只能解释机器码，一切都按内存解释。**这是「手工机器指令」与「编译的汇编指令」之间真实的鸿沟。**

### 4) 段前缀（5.6 / 5.8）

```asm
; 教学示意，不参与构建
    mov ax, 0
    mov es, ax          ; ES 指向 0 段
    mov cx, 256
    mov bx, 0
s:  mov al, [bx]        ; 从 DS:bx 读
    mov es:[bx], al     ; 写到 ES:bx（段前缀）
    inc bx
    loop s
```

> `es:` 是**段前缀**：临时让 `[bx]` 的段寄存器从默认 DS 换成 ES。本书用这个手法把数据搬运到「安全空间」。

### 5) 一段安全的空间（5.7）

| 区间 | 用途 |
| --- | --- |
| `0:200` ~ `0:2FF`（512 字节） | 8086 PC 上公认的空闲 RAM，程序可自由读写而不破坏系统数据 |
| `0:400` 起 | 传统上给软盘驱动参数表，也常被程序借用 |

> 现代意义：这些约定在今天的机器上仍然有效（因为实模式兼容层被完整保留），但它们**不是 ABI**，换硬件/换 BIOS 就可能失效。

## 版本演进

| 年份 | 事件 | 关联 |
| --- | --- | --- |
| 1978 | 8086 的 `loop` 指令（8086 就有，非 80386 独有） | 本章主角 |
| 1982 | 80286 的 `rep` 前缀与 `lodsb/stosb` 组合 | 串操作才是「批量循环」的正解 |
| 1985 | 80386 的 `loop` 变体（`loope/loopne/loopz/loopnz`），以及 `ecx` | 32 位下循环同样用 CX 的低位 |
| 1990s | 编译器内自动向量化 / unrolling | 手写 `loop` 被 `-O3` 取代 |
| 2011 | SIMD（AVX）与自动向量化成熟 | `loop` 的 throughput 工作被向量指令替代 |
| 2026 | 手写循环汇编仍是 JIT / 加密 / memcpy 的保留地 | 与 `rep movsb` 一样，仍是底层代码常见元素 |

> 值得注意：`loop` 在微架构上其实**不快**（它要显式改 `cx`、要做分支预测），现代编译器常把 `loop` 展开成无条件跳转 + `sub`。但作为教学，它是最好的「循环 = 计数器 + 条件跳转」示范。

## 常见误区与本书需修正之处

| # | 误区 / 待修正 | 说明 |
| --- | --- | --- |
| 1 | 🔧 「`loop` 会先判断再减 CX」 | 顺序是**先减 CX 再判断**。因此把 CX 设为 N 时循环体执行 N 次；若把 CX 当别的用途，行为会出乎意料。 |
| 2 | 🔧 「循环体里可以随便用 CX」 | CX 被 `loop` 占用。循环体中改 CX 会让循环次数变形——本书 5.2 特别强调过。 |
| 3 | 🔧 「`[bx]` 的段一定是 DS」 | 默认才是 DS；加段前缀 `es:[bx]` / `cs:[bx]` / `ss:[bx]` 后可以换。另外 **`[bp]` 默认段是 `SS`**（本书第 8 章会讲），这是常见的隐性差异。 |
| 4 | 🔧 「`inc bx` 就走到下一个元素」 | 取决于元素大小：字节数组 +1，字数组 +2，双字数组 +4。混用是数组类 bug 的头号来源。 |
| 5 | 🔧 「`loop` = 现代 CPU 上最快的循环」 | 现代处理器里 `loop` 常比展开的 `jmp` 更慢（额外写寄存器 + 分支）。编译器通常不生成 `loop` 指令。 |
| 6 | 🔧 「0:200 这段空间可以放心用」 | 是 8086 PC 上的**实践约定**，不是标准。真实系统上写它可能与驱动/扩展 ROM 冲突。现代裸机代码应自己保留内存。 |
| 7 | 「Debug 与 MASM 的差异是 bug」 | 是刻意设计：Debug 直接解释机器码，`[0]` 只能是内存；MASM 有符号与类型系统，需要 `offset`。它恰好演示了「汇编语言是助记符」这一层。 |
