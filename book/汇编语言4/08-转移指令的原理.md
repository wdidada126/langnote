# 第 9 章 转移指令的原理

> **一句话**：转移指令的根本不是「跳到某个地址」，而是**修改 IP（必要时连同 CS）**；而 8086 只有 16 位 IP，所以「跳多远」这件事必须由编译器算清楚——这就是短/近/远转移与位移超界检测的由来。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 9.1 操作符 `offset` | 取标号的偏移地址 | `mov ax, offset s` 等价于一条 `mov ax, immm` |
| 9.2 `jmp` 指令 | 无条件转移的四种形式 | 段内/段间、直接/间接，共 4 类 |
| 9.3 依据位移转移的 `jmp` | `jmp short s` / `jmp near s` | **CPU 不知道目标地址，只知道「往后多少字节」** |
| 9.4 目的地址在指令中的 `jmp` | `jmp far ptr s` | 同时改 CS 与 IP |
| 9.5 目的地址在寄存器中的 `jmp` | `jmp ax` | 间接转移，引出 `call` 的实现 |
| 9.6 目的地址在内存中的 `jmp` | `jmp word ptr [bx]` / `jmp dword ptr [bx]` | 从内存里取一个/两个字作为 IP（或 CS:IP） |
| 9.7 `jcxz` 指令 | `jcxz s`：(cx)=0 则转移 | 条件转移，但只对 CX 一个条件 |
| 9.8 `loop` 指令 | 见第 5 章，此处给精确语义 | `loop` ≡ `jcxz` + 计数器 |
| 9.9 依据位移转移的意义 | 为什么用位移而不是绝对地址 | 代码可浮动（relocatable）、体积小 |
| 9.10 编译器对转移位移超界的检测 | 短转移超 -128~+127 报错 | **MASM 会自动把 short 升级为 near**，附 3 记录了细节 |

## 核心精讲

### 1) 转移的本质（9.1–9.2）

```asm
; 教学示意，不参与构建
code segment
start:
    mov ax, 0
s:  inc ax                 ; 标号 s 的偏移地址 = offset s 的值
    jmp short s            ; 无条件回到 s
    mov ax, 4c00h
    int 21h
code ends
end start
```

> **只有一个事实**：转移 = 修改 `IP`；跨段转移才连带修改 `CS`。
> **`offset s`** 是编译器在汇编期算出的常量，写入指令本身（立即数形式），运行时不需要查表。

### 2) 四种 `jmp`（9.2–9.6）

| 形式 | 语法 | 改什么 | 目标来源 |
| --- | --- | --- | --- |
| 短转移 | `jmp short s` | IP（8 位位移） | 指令里的位移量 |
| 近转移 | `jmp near s` / `jmp s` | IP（16 位位移） | 指令里的位移量 |
| 远转移 | `jmp far ptr s` | **CS + IP** | 指令里的段值与偏移 |
| 寄存器间接 | `jmp ax` | IP ← AX | 寄存器 |
| 内存间接 | `jmp word ptr [bx]` | IP ← (ds:bx) | 内存 |
| 内存远间接 | `jmp dword ptr [bx]` | CS ← (ds:bx+2), IP ← (ds:bx) | 内存 |

```asm
; 教学示意，不参与构建
    jmp ax                     ; IP ← ax
    jmp word ptr [bx]          ; IP ← ds:bx 处的 1 个字
    jmp dword ptr [bx]         ; CS ← 高字, IP ← 低字
```

### 3) 位移转移为什么重要（9.9）

```asm
; 教学示意，不参与构建
; 机器码层面：jmp 后面跟的是一个"相对位移"，不是绝对地址
;   8 位位移：EB xx   （jmp short）
;   16 位位移：E9 xxxx（jmp near）
;
; 若用绝对地址形式，代码就"钉死"在内存某一处，
; 现在整个程序可以被装载到任何段地址上运行 —— 这才是初步的可重定位性。
```

### 4) `jcxz` 与 `loop` 的等价关系（9.7 / 9.8）

```asm
; 教学示意，不参与构建
; loop s 的等价展开：
    dec cx                   ; ① cx ← cx - 1
    jnz s                    ; ② 若 cx ≠ 0 跳回 s

; jcxz s（若 cx = 0 则转移）：
    jcxz s                   ; 等价于
    jmp short done
s:  ...
done:
```

> 条件转移全部依赖标志寄存器（第 10 章讲）；`jcxz` 是唯一直接看 `cx` 而**不看标志位**的条件转移。

### 5) 位移超界与编译器的处理（9.10）

```asm
; 教学示意，不参与构建
s:  ...                      ; 循环体很大
    jmp short s              ; 若 s 到此处超过 127 字节 → 报错
                             ; MASM 会自动升级为 jmp near（附注 3 专门记录）
```

| 转移类型 | 位移范围 | 机器码 |
| --- | --- | --- |
| short | -128 ~ +127 字节 | `EB rel8` |
| near | -32768 ~ +32767 字节 | `E9 rel16` |
| far | 跨段，无位移限制 | `FF /5` 或 `EA seg:off` |

## 版本演进

| 年份 | 事件 | 关联 |
| --- | --- | --- |
| 1978 | 8086：`jmp short/near/far`，`jcxz` | 本章主角 |
| 1985 | 80386：`eip` 32 位，位移扩到 32 位；新增 `jecxz` | 位移范围从 16 位扩到 32 位 |
| 1990s | 分支预测器进入 x86（Pentium 的 BTB） | 转移代价从「10+ 周期」变成「预测成功近乎免费」 |
| 2003 | x86-64：**引入 RIP 相对寻址**，`jmp` 的直接形式以 RIP 为基准 | 位置无关代码（PIC）变得可行 |
| 2013+ | 分支预测器成为性能头号议题（Spectre 也在这条链上） | 「转移」在安全与性能上同时重要 |
| 2026 | CET（Endbranch/Shadow Stack）加固间接转移 | `jmp rax` 这类间接跳转被硬件监管 |

> 转折点是 **x86-64 的 RIP 相对寻址**：它让「位移转移」在 64 位模式下有了新生命，也让 PIC 与 PIE 成为可能。本书写的 `jmp s` 在 64 位下会自动变成 RIP 相对。

## 常见误区与本书需修正之处

| # | 误区 / 待修正 | 说明 |
| --- | --- | --- |
| 1 | 🔧 「`jmp` 跳到的是绝对地址」 | 短/近转移里**没有绝对地址**，只有「相对当前 IP 的位移」。这就是代码可重定位的根本，也是「位移超界」报错的原因。 |
| 2 | 🔧 「`jmp short s` 写了就一定是 8 位位移」 | 若位移超出 -128~+127，MASM 会**自动升级**为 near（附注 3 记录了 `jmp` 相关处理的细节）。写汇编时不要依赖这个隐式升级来控制机器码大小。 |
| 3 | 🔧 「`jmp far ptr s` 只在跨段时才用」 | 段内跳转也要写 `short`/`near` 来**明确意图**；跨段（改 CS）才必须 `far`。 |
| 4 | 🔧 「`jcxz` 是一个通用条件转移」 | 它只对 `cx` 判断，不看任何标志位。条件转移应该用 `jz/jnz/ja/jb...`（第 10 章）。 |
| 5 | 🔧 「`loop` 和 `jcxz` 完全等价」 | 不完全：`loop` 会**先减 cx 再判断**；`jcxz` 不修改 cx。混用会漏掉最后一次迭代。 |
| 6 | 🔧 「本书的 `jmp s` 在 64 位下也是位移转移」 | x86-64 下直接转移以 **RIP 相对**为基准（rel32/rel8），语义更接近本书的 short/near 思想，但**不再是段:偏移模型**。 |
| 7 | 🔧 「手写汇编写控制流就更快」 | 现代 CPU 的分支预测器对规整循环/switch 命中率极高。手写「特化控制流」收益很小，风险（预测失败 + 安全问题）却不小。 |
| 8 | 「`jmp` 到 `int 21h` 是没必要的」 | 有时确实用 `jmp` 复用已有代码；但常见误用是把 `jmp` 写在循环里制造无条件跳转风暴。 |
