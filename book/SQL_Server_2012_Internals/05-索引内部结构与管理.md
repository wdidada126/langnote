## 核心精讲（转述 + ⚠️）

### 1. 一棵树的两种人生：CI 与 NCI
CI 叶页装着整行，所以"点查走 CI=只碰一棵树"；NCI 叶只装键+定位器，命中后还要回表(CI 键再走一趟树，堆表则 RID 直达页槽)。书里的经典算账：非覆盖 NCI 点查=2×树高的随机 IO；回表行数比例超过约 1/4~1/3 后，直接全表扫更便宜——这个交叉比在 SSD 时代右移但仍存在 ⚠️。✅ 准绳：https://learn.microsoft.com/en-us/sql/relational-databases/indexes/clustered-and-nonclustered-indexes-described 。INCLUDE 列不复制进中间层，是"键窄+叶肥"的折中——与 InnoDB"二级索引叶藏主键、回表"的差异(主键即聚簇=InnoDB 只有一棵树 ⚠️)对照见 [../MySQL技术内幕_InnoDB存储引擎2.md](../MySQL技术内幕_InnoDB存储引擎2.md) ⚠️。

### 2. 键设计的三叉戟（转述 ⚠️）
(a) **选择性**：前导列唯一度决定树的上半程收敛速度；(b) **可定位性**：等值谓词列在前、范围列在后，否则范围列之后全废；(c) **写放大**：每个 NCI 都是每次 DML 的税，宽键+高基数=分裂流水线。书中给"少而精"的判据与大量案例(逐案细节 ⚠️ 未逐字复述，工程清单版另见 #36 [../Pro_SQL_Server_Internals/05-索引碎片与设计调优.md](../Pro_SQL_Server_Internals/05-索引碎片与设计调优.md))。通论对位 [../数据库索引设计与优化.md](../数据库索引设计与优化.md)。

### 3. 碎片的定量学
dm_db_index_physical_stats 三件套：avg_fragmentation_in_percent(外部)、avg_page_space_used_in_percent(内部)、page_count。经典阈值(<5 忽略/5–40 重组织/>40 重建)出自本书时代的最佳实践 ⚠️，作者同代人已警告"阈值不如工作负载画像" ⚠️。ONLINE 重建在 2012 已可用但锁阶段与版本堆叠有讲究(08 章)；2014+ 的 SE_REDO 日志瘦身 ⚠️ 见演进节。

### 4. 统计：索引的影子账本
索引创建=自动建键统计；UPDATE STATISTICS 与重建索引的关系(重建只刷新该索引统计 ⚠️)是高频误区源。2012 的自动更新阈值改为大表阶梯公式——细节与两代 CE 对比在 #36 统计专章讲得更全：[../Pro_SQL_Server_Internals/03-统计信息.md](../Pro_SQL_Server_Internals/03-统计信息.md) ✅(文件在盘，写前已验)。✅ https://learn.microsoft.com/en-us/sql/relational-databases/statistics/statistics 。

## 🔧 类比实验 E2 · 主键树 vs 二级索引树：一页一世界的页数对照（SQLite CLI 3.50.6 dbstat）

**非本书引擎行为，仅通用机制演示**：表 ci(id 主键, k 随机整数, payload≈200B×5000 行)，建二级索引 ix_k 后用 dbstat 分树清点：

```
ci   ：265 页 / 1,085,440 B   ← "聚簇"：键序即行序，载荷全在叶
ix_k ： 18 页 /    73,728 B   ← 二级：只有键+rowid，叶极瘦
range 查询 k BETWEEN 100..1000 命中 903 行(需回表 903 次)
```
实测 ✅。迁移到 SQL Server：NCI 的瘦叶正是"必须回表"的结构根源，INCLUDE 把回表行变成肥叶——SQLite 无 INCLUDE，回表税只能靠 rowid 直达(它的 rowid 表天然聚簇) ⚠️。两家共同教训：**二级索引的成本不在建，在每次查询要不要再爬一次主树** ⚠️。

## 本章结论速记

- CI 树=数据本身；NCI 树=键+定位器，覆盖与回表是一体两面。
- 树高是对数函数：百万行 3 层、十亿行 4 层——索引的价值与天花板都由扇出决定。
- 键顺序是谓词形状的函数；INCLUDE 是选择性换宽度；两者都在给 DML 税率做预算。
- 碎片分内外两账，度量视图给数、维护命令给动作、工作负载给阈值。
- 树不是静态化石：每次 DML 都在给键序、页密度与锁面同时记账(04/08 章)。
- 索引统计影子化：别把"重建索引"当统计维护的替身。

## 常见误区（转述 ⚠️）

| 误区 | 事实 |
| --- | --- |
| "多建索引保险" | 每写一次全树链都付费；无用索引比没有更贵 ⚠️ |
| "唯一索引不重复统计" | 唯一索引同样带统计；且唯一性检查也走锁/latch 路径 ⚠️ |
| "重建一定比重组划算" | 小表/低碎片时 REBUILD 白付事务日志与 IO ⚠️ |
| "GUID 主键必死" | 带种子的 sequential GUID 缓解；真正问题是随机性×宽键 ⚠️ |
| "INCLUDE 进键列也行" | 进键=参与排序+唯一性+变宽；INCLUDE 只落叶 ⚠️ |
| "筛选索引=小索引随便建" | 谓词不匹配或参数嗅探会让它形同虚设(06/07 章) ⚠️ |
| "碎片率 90% 查询就废了" | 读顺序型负载下外部碎片伤害有限；看 IO 模式再动手 ⚠️ |

## 转述扩写：树高算术与维护窗口剧本（⚠️ 转述）

### 树高怎么估
- 中间层一条目≈键宽+子页指针+开销，设每页可容 F 个键 ⇒ 深度≈log_F(行数)：int 键下百万行 3 层、十亿行 4 层量级(数量级口径 ⚠️，书含具体算例)；
- 键宽税：NCI 叶每行还要背完整 CI 键——int 身份列当聚集键，所有 NCI 跟着膨胀 ⚠️；
- 扇出红利：更瘦的键=更高的扇出=更浅的树，这是"窄聚集键"教条的全部数学。

### 一次"坏索引"的验尸清单
1. 看定位器类型(堆 RID? CI 键?) → 决定回表成本模型；
2. 看覆盖度(缺哪几列) → INCLUDE 候选；
3. 看选择性(直方图前导列) → 谓词收敛能力；
4. 看碎片两账 → 维护动作选择；
5. 看使用统计(sys.dm_db_index_usage_stats) → 该不该删 ⚠️✅(Learn 索引视图/DMV 页 ⚠️URL 未逐验)。

### 维护窗口剧本（⚠️ 转述）
- ONLINE REBUILD：建影子树+变更日志回放+短时锁阶段；2012 可用但版本叠加吃 tempdb(08 章握手) ⚠️；
- OFFLINE：独占但干净，适合窗口充裕的仓库(列存另有重造语义，06 章) ⚠️；
- REORGANIZE：轻量在线，日志友好；对内部碎片有效、对"逻辑乱序"无能为力 ⚠️；
- 决策输入：窗口长度、日志吞吐预算、版本存储水位、读局部性画像——"阈值表"只是起手式 ⚠️。

### 索引与分区/统计的三角账
- 分区表上非对齐索引=隐形全表大索引：SWITCH 被卡、维护失去分块粒度(06 章) ⚠️；
- 多列统计可独立于索引存在：无索引列的组合谓词靠它吃饭(#36 统计章对位) ⚠️✅statistics(Learn)。

## 核心概念速览（中英对照）

1. **B 树** — B-tree：平衡多路搜索树，SQL Server 索引的骨架 ⚠️✅(Learn)。
2. **聚集索引** — Clustered Index：键序=物理序，叶即数据 ⚠️✅(Learn)。
3. **非聚集索引** — Nonclustered Index：键+定位器的瘦树 ⚠️✅(Learn)。
4. **键查找** — Key Lookup：NCI 命中后回 CI 补行的第二次爬树 ⚠️。
5. **覆盖索引** — Covering Index / INCLUDE：把回表需要的列直接装进叶 ⚠️✅(Learn)。
6. **定位器** — Row Locator：RID(堆)或 CI 键(NCI 指回数据的地址) ⚠️。
7. **树高/层** — Index Depth：随机 IO 次数的对数预算 ⚠️。
8. **内部碎片** — Internal Fragmentation：页内空洞，avg_page_space_used_in_percent ⚠️。
9. **外部碎片** — External Fragmentation：叶链物理错位，avg_fragmentation_in_percent ⚠️。
10. **重建** — ALTER INDEX REBUILD：重造整树，2012 可 ONLINE ⚠️✅(Learn)。
11. **重组织** — REORGANIZE：叶层就地紧凑，日志友好 ⚠️✅(Learn)。
12. **填充因子** — Fillfactor/PAD_INDEX：预留分裂洞的建树参数 ⚠️。
13. **索引统计** — Index Statistics：键直方图+密度，优化器的眼睛 ⚠️✅(Learn)。
14. **逆向扫描** — Backward Scan：降序需求可用升序索引反着走 ⚠️。
