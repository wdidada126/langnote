## 核心精讲（转述 + ⚠️）

### 1. "特殊存储"的共同主题：行式引擎的三处漏点
稀疏列(列太多且多 NULL)、LOB(单值太大)、分区(表太大)——本章三件道具分别在**列宽、值宽、表宽**上给 8KB 行式世界观打补丁 ⚠️。FileTable 则干脆把文件语义(SQL 表⇄Windows 文件share)双向翻译，事务一致性靠 03 章日志兜底(细节 ⚠️ 转述)。对位阅读：现代湖仓表格式在"表太大"这条腿上走了更远——[../Apache_Iceberg活用入門/00-总览与阅读地图.md](../Apache_Iceberg活用入門/00-总览与阅读地图.md) 与 [../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md](../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md)(均 ✅盘上验名)可当 2012 分区章的"续命版"读。

### 2. 分区：从"多文件组"到"滑动窗口"
分区函数把键域切成 N 段，分区方案把段绑到文件组——与 02 章文件组、05 章"索引必须对齐"的账目在此汇合。SWITCH 的"元数据魔术"要求：目标表同构、约束 CHECK 在位、索引对齐 ⚠️。分区统计的双账本(全局+分区级直方图)是后来"分段统计"话题的前身 ⚠️，理论通识回扣 [../Physical_Database_Design/00-总览与阅读地图.md](../Physical_Database_Design/00-总览与阅读地图.md) ⚠️。

### 3. 特殊索引的分类学
- **谓词型**：筛选索引(带 WHERE 的小树)；
- **结构转换型**：XML(文档→节点表)、空间(几何→网格)；
- **检索型**：全文(倒排)、语义(统计扩展)；
- **物化型**：**列存储索引**——把表转置成按列切段的压缩块，配合批次扫描 ⚠️。
2012 的 NCCI 限制(表只读、每表 1 个、不可更新)是理解 2014 CCI 翻身的关键锚点 ⚠️。✅ https://learn.microsoft.com/en-us/sql/relational-databases/indexes/columnstore-indexes-overview 。

### 4. rowversion≠版本存储（书内辨析 ⚠️）
rowversion 是每行随事务递增的令牌(乐观并发的 If-Match)；行版本化隔离(RCSI)是版本指针+tempdb 链条(08 章)。两词同源异构，是面试经典陷阱 ⚠️。

## 🔧 类比实验 E6 呼应 · "段+元数据消元"的普适性（DuckDB 1.5.5；完整版见 [07-查询执行优化与计划缓存.md](07-查询执行优化与计划缓存.md)）

**非本书引擎行为，仅通用机制演示**：DuckDB 2,000,000 行列存表，`WHERE cat=42` 谓词仅 0.002s ✅——zone-map(min/max 段元数据)让绝大多数段根本不读。SQL Server 的列存段+字典压缩在 2012 已具备同型消元思想(段级统计⚠️ 转述)；两家都说明：**列存的读性能不在索引树，在"少读"**。对照 SQLite(行式+索引)同表谓词需爬树或全扫，差异即世界观差异 ⚠️。

## 本章结论速记

- 特殊存储=行式引擎在列宽/值宽/表宽三方向的补丁集。
- 分区是物理布局术：对齐则索引/统计/维护全链受益，错位则处处补税。
- 筛选索引赌数据分布；XML/空间索引是"另一种数据模型的关系化投影"。
- 全文是倒排、语义是统计；2012 列存是只读加速器，离"仓库默认布局"还差 2 年(2014 CCI)。
- rowversion 是行内计数器，版本存储是隔离级别机制——别混。

## 常见误区（转述 ⚠️）

| 误区 | 事实 |
| --- | --- |
| "Filestream 随便开" | 卷必须 NTFS+分配单元对齐、防病毒软件是经典杀手 ⚠️ |
| "FileTable=文件服务器替代" | 行级安全/备份粒度仍是表级，运维语义差很远 ⚠️ |
| "分区=自动并行加速" | 不裁剪(pruning 失效)的分区只会让每查询更贵 ⚠️ |
| "筛选索引谁都能用" | 查询谓词须被索引 WHERE 蕴含，参数化查询常不匹配(07 章) ⚠️ |
| "XML 索引建了查询就快" | 主索引三附属成本极高，文档级操作常仍全扫 ⚠️ |
| "2012 列存能替换所有索引" | NCCI 只读、每表一个、更新即禁用重造——定位是装载后分析 ⚠️ |
| "rowversion 保证行顺序唯一" | 数据库级计数器：回滚照样递增，只保证"变过"不保证"提交序" ⚠️ |

## 转述扩写：滑动窗口脚本骨架与道具选型（⚠️ 转述，伪 T-SQL 仅示意）

### 滑动窗口月度轮转（伪代码骨架，非可运行）
```
LOOP 每月：
  1. 预建未来边界：SPLIT RANGE(下界)        -- 新空分区
  2. 装载新数据进"隔离暂存表"(同构+同界+索引对齐)
  3. SWITCH 暂存 → 当月分区                  -- 元数据级秒切换
  4. SWITCH 最老分区 → 归档表(或冷文件组)     -- 出场
  5. MERGE RANGE(淘汰边界)                   -- 收编空分区
  6. UPDATE STATISTICS(全局/分区策略)         -- 账本跟进 ⚠️
```
坑位登记：切换要求"约束+索引+统计"三对齐；分区上的全局统计与分区统计双账(05 章呼应) ⚠️。

### 道具选型速查

| 数据形态 | 首选道具 | 次选 | 本章依据 ⚠️ |
| --- | --- | --- | --- |
| 超宽稀疏(EAV 味) | column set/稀疏列 | 拆表 | NULL 零占位 |
| 100KB–GB 单值 | Filestream/FileTable | LOB | 走 NTFS 流 |
| 亿行事实表(仓) | 列存(2012 只能 NCCI 只读) | 分区+归档 | 段消元 |
| 时间冷热分层 | 分区+文件组 | 快照/日志传送 | 物理布局术 |
| 布尔态偏斜(99% NULL) | 筛选索引 | 分区视图 | 谓词化小树 |
| 文档碎片查询 | XML 索引三附属 | 关系化拆表 | 树贵且挑形态 |

### 2012 列存的"只读契约"细目（⚠️ 转述）
- 建 NCCI 后基表不可 DML——要改就 DISABLE/DROP 再来；每表至多一个；列数 ≤1024、每列可入段 ⚠️；
- 段(segment)≈列块+压缩(字典/RLE)+段级统计——"段消元"已具雏形(E6 呼应，🔧 非本书)；
- 书的时代判断："先装载后分析"的工作流补丁——2014 CCI 用 delta store+tuple mover 把契约改写为默认布局(演进节) ⚠️。

## 核心概念速览（中英对照）

1. **稀疏列** — Sparse Column：NULL 零占位声明，配 column set 用 ⚠️。
2. **rowversion** — Rowversion(旧 timestamp)：行变更令牌，乐观并发基石 ⚠️。
3. **FILESTREAM** — FILESTREAM：NTFS 流承载 VARBINARY(MAX)，事务同域 ⚠️。
4. **FileTable** — FileTable：文件/目录语义的表投影 ⚠️。
5. **表分区** — Table Partitioning：一表多块，按分区函数切键域 ⚠️。
6. **滑动窗口** — Sliding Window：SPLIT/MERGE+SWITCH 的滚动维护术 ⚠️。
7. **对齐** — Partition Alignment：索引/分区落在同键同界，SWITCH 的入场券 ⚠️。
8. **筛选索引** — Filtered Index：带 WHERE 的部分索引 ⚠️✅(Learn)。
9. **主 XML 索引** — Primary XML Index：文档节点的 B 树投影(+路径/值/值主键三附属) ⚠️。
10. **空间索引** — Spatial Index：几何对象的网格 tessellation 索引 ⚠️。
11. **全文索引** — Full-Text Index：断词/词干后的倒排结构 ⚠️。
12. **语义搜索** — Semantic Search：2012 新，统计短语相关度 ⚠️。
13. **非聚集列存(NCCI)** — Nonclustered Columnstore：2012 只读加速器，段+列压缩 ⚠️✅(Learn)。
14. **段消元** — Segment/Rowgroup Elimination：凭段级元数据跳过整块 ⚠️(🔧 E6 呼应)。

## 最新演进与工业实践

- **2012→2016**：NCCI→**CCI(2014，可更新的聚集列存)**完成"仓库默认物理布局"翻身(✅ https://learn.microsoft.com/en-us/sql/relational-databases/indexes/columnstore-indexes-overview )；XML/空间/全文基本冻结在小版本迭代 ⚠️；FileTable 后继乏力 ⚠️ 观察性结论。
- **2017→2022**：列存吃到自适应 JOIN 反馈、持久化统计(✅ 演进细节未逐 URL 验 ⚠️)；PolyBase→大数据池(2019)把"外部表"接上 Hadoop/Parquet——分区章的"数据分层"叙事云化 ⚠️。
- **2025**：**自动分区(automatic partitioning)**——SQL Server 2025 预览路线把本章最重的"分区函数运维"自动化(✅ 总入口 what's new https://learn.microsoft.com/en-us/sql/sql-server/what-s-new-in-sql-server-2025 ，实现细节 ⚠️ 转述)；**向量类型+向量索引**成为"特殊索引"的新成员，语义上接 2012 全文/语义搜索的检索谱系 ⚠️。
- **工业实践**：热冷分层从"分区+文件组"迁移到"分区+对象存储备份(✅ https://learn.microsoft.com/en-us/sql/relational-databases/backup-restore/sql-server-backup-to-url )/湖仓导出"；列存+行存混合(HTAP)取代 NCCI 时代"单独建张只读镜像表"的土办法 ⚠️。
- **系列对位**：Iceberg/Delta 的隐藏分区与文件消元是本章分区+段消元的开源转世([../Apache_Iceberg活用入門/00-总览与阅读地图.md](../Apache_Iceberg活用入門/00-总览与阅读地图.md)、[../Delta_Lake_Up_and_Running/00-总览与阅读地图.md](../Delta_Lake_Up_and_Running/00-总览与阅读地图.md) ✅盘上验名)。
