## 核心精讲（转述 + ⚠️）

### 1. 一行的解剖学（转述 ⚠️）
SQL Server 记录 = 1 字节状态 + 状态位图(NULL 位/短列位) + 固定长度部分长度 + 列数 + 固定数据 + **变长列偏移数组(倒序)**。工程推论全部由此展开：加宽 varchar 不碰数组只改长度、把列改成稀疏 NULL 省字节、"列数惩罚"在 640 列表上夸张但不玄学 ✅(列数上限 1024 的现代文档可查 ⚠️ 未逐条验 URL)。对照阅读：InnoDB 行格式(头/空位图/变长长度列表)在 [../MySQL技术内幕_InnoDB存储引擎2.md](../MySQL技术内幕_InnoDB存储引擎2.md) 有几乎同构的一节，SQLite 记录头+serial type 则是第三种方言——三家都是"页内装箱问题" ⚠️。

### 2. 堆的经济学：免费入场与隐性税
堆写入便宜(哪里有空页哪里塞)、RID 扫描全表快(顺序读分配单元)、但：更新变长字段可能"搬家+留转发指针"，非聚集索引指向 RID 时搬家要改所有 NCI ⚠️。书中(推测口径 ⚠️)与 #36 一致的结论：**堆适合一次性装载+全量扫描的暂存表，不适合 OLTP 点查**。理论通识回扣 [../数据库索引设计与优化.md](../数据库索引设计与优化.md) 的"聚簇选择"章 ⚠️。

### 3. 大值对象的三条退路
- LOB(text/ntext 旧型 + max 新造型)→ LOB 分配单元，页内只留 16B 指针 ⚠️；
- 非 max 变长列挤爆 8060 → ROW_OVERFLOW 逐列外迁 ⚠️；
- Filestream/FileTable 直接落 NTFS 流(06 章主场) ⚠️。
"选哪条退路"的决策树是本章与运维的接缝：LOB 读放大、overflow 行的多分配单元一致性(08 章 DBCC 要三账合对) ⚠️。

### 4. Ghost、版本与清理线程
删除先标 ghost，后台清理线程回收——这解释了"删 1 亿行后扫描仍慢"的时间窗；开启 RCSI 时 ghost 清理还得等版本链读者散尽，tempdb 版本存储 GC 与它握手(08 章) ⚠️。机制叙事在 [../Understanding_MySQL_Internals/00-总览与阅读地图.md](../Understanding_MySQL_Internals/00-总览与阅读地图.md) 有 InnoDB purge 对位物 ⚠️。

## 🔧 类比实验 E3 · 插入顺序决定页密度：分裂税的量化（SQLite 3.45.3，5 万行）

**非本书引擎行为，仅通用机制演示**：同一数据集(1..50000 整型主键)，两种插入顺序，各建 4KB 页库。

```
顺序插入   → page_count=1357，耗时 0.05s
随机(种子42)插入 → page_count=1515，耗时 0.31s
```
实测：随机键多付 **11.6% 页数、6.2 倍时间** ✅。机制迁移：B+树在"随机到达的键"上必然做半空分裂，产生页内空洞(内部碎片)——SQL Server 对应概念是**填充因子 FILLFACTOR**与 avg_page_space_used_in_percent(05 章)；差异在 SQL Server 默认 100% 填充、且分裂策略是页分半，SQLite 默认每页留 1/16(1MB 以下)。数字不通用，**"写模式决定碎片形态"的规律通用** ⚠️。

## 本章结论速记

- 行=位图+固定段+变长倒序数组：一切宽度学从页字节预算推导。
- 堆不是"没有成本"，是把成本从插入挪到更新/二级索引维护/扫描定位。
- 三分配单元(ROW_OVERFLOW/LOB/IN_ROW)让"一行"变成"一组页"，一致性检查按三账做。
- 压缩=CPU 与 IO 的交换，页压缩带字典，行压缩只瘦变长——别拿压缩当备份瘦身用 ⚠️。
- 页分裂是预付未来插入的定金：顺序键少付、随机键多付(E3 演示)。

## 常见误区（转述 ⚠️）

| 误区 | 事实 |
| --- | --- |
| "NULL 也占一个字节" | 位图记账，NULL 列基本不占数据字节 ⚠️ |
| "varchar(8000) 能放 8000 字符" | 多字节字符集按字节折；且整行 8060 约束在场 ⚠️ |
| "nchar 存 unicode 更省" | 定宽双字节填充，比变长 nvarchar 贵 ⚠️ |
| "堆表更新就是原地改" | 放不下就搬家+转发指针，NCI 还得跟着改 RID ⚠️ |
| "删行=空间立刻回收" | ghost 清理是异步的，版本链还能拖着不放 ⚠️ |
| "压缩拖垮 CPU" | 默认行/页压缩的 CPU 代价在 IO 受限盘上常是赚的 ⚠️ |
| "max 列就是免费午餐" | 指针 indirection 让读放大翻倍，且不能进索引键 ⚠️ |

## 转述扩写：一页的字节账（⚠️ 转述，数字未本机验证）

### 页的固定开销
- 96B 页头(页类型/偏移/状态/对象 ID…) + 行尾槽数组(每行 2B) ⇒ 一行的净可用=8192−96−2×行数 ⚠️；
- 推论一：行数越多槽越吃空间，槽数组自身也能把页"撑满到不能再塞" ⚠️；
- 推论二：一行最小开销=1B 状态+列位图+长度字段们——"一行 int"远不止 4 字节 ⚠️。

### 压缩决策树（⚠️ 转述）
1. 变长列多/NULL 多 → ROW 压缩(类型瘦身、去定宽填充)；
2. 列重复度高(同一页内值成簇) → PAGE 压缩(前缀字典叠加)；
3. 已有列存需求 → 不走压缩走 06 章 CCI 路线(时代后见之明 ⚠️)；
4. 压缩使行变小 → 每页行数↑ → 扫描 IO↓ 但分裂频率与 CPU 编解码↑——评估必须成对看 IO 与 CPU 曲线 ⚠️；
5. 压缩改不了 LOB/overflow 的外账，LOB 压缩另有手段(页内 ⚠️ 细节存疑不写死)。

### 堆 vs 聚集：一张对照表

| 维度 | 堆 | 聚集索引表 |
| --- | --- | --- |
| 插入 | 找空页即塞(可能撞 PFS 热点) | 按键定位+可能分裂 |
| 点查(有 NCI) | NCI→RID 直达 | NCI→CI 两棵树 |
| 更新变长 | 搬家+转发指针 | 原页腾挪或行移动 |
| 全扫 | 分配单元顺序=物理顺序 | 叶链=键序 |
| 删除回收 | ghost 同右 | ghost 同右 |
| 适合 | 装载/暂存/一次性 | OLTP 常态 |

（表为两家书共同叙事的浓缩 ⚠️，逐格行为细节以 Learn 与实测环境为准。）

### 行锁的最小单位问题
- 锁可以锁 RID/KEY/页/extent——行式页组织决定了"锁粒度下限=行或键"，页锁时代(≤2000 行提示)是历史注脚 ⚠️(08 章主场)。

## 核心概念速览（中英对照）

1. **记录头** — Record Header：状态位+位图+长度+列数的行身份证 ⚠️。
2. **列偏移数组** — Column Offset Array：变长列倒序索引，"从后往前数" ⚠️。
3. **NULL 位图** — Null Bitmap：用 1 bit 记账"这列没值" ⚠️。
4. **堆** — Heap：无键序的表，RID=文件:页:槽 ⚠️。
5. **转发记录** — Forwarded/Redirecting Record：搬家后留在原页的指路牌 ⚠️。
6. **行溢出** — ROW_OVERFLOW_DATA：非 max 变长列的单间退路 ⚠️。
7. **LOB 分配单元** — LOB Allocation Unit：max/旧大对象的独立账本 ⚠️。
8. **幽灵记录** — Ghost Record：已删待回收的行，清理线程的猎物 ⚠️。
9. **行内 8060 上限** — Max Row Size：一页装两行的硬约束 ⚠️。
10. **行压缩** — ROW Compression：类型瘦身+变长去填充 ⚠️✅(Learn 数据压缩页 ⚠️URL 未验)。
11. **页压缩** — PAGE Compression：行压缩+列前缀字典 ⚠️。
12. **PFS 类别** — Page Free Space 记账：混合/单页/已分配/脏位 ⚠️✅Pages and Extents(Learn)。
13. **行版本指针** — Version Pointer：14 字节(事务序列+链地址)的隔离级别税 ⚠️。
14. **填充因子** — Fillfactor：建索引时预留给未来分裂的空洞 ⚠️。
