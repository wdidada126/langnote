# 02 数据库与数据库文件（原书 ch3 Databases and Database Files）

> 状态标注：⚠️ = SQL Server 引擎二手转述（本机不可实测）；✅ = Microsoft Learn 现行文档（写前 curl -sL 200）；🔧 = 本机 SQLite/DuckDB 类比，**非本书 SQL Server 引擎行为**。

## 一、本章地图

数据库不是"一个文件夹"，而是一套**层级账本**：数据库→文件组→文件→区（extent）→页（page）。本章把这套空间账本讲透，后面"表/索引"都是往页里摆东西。

- 2A 数据库的组成：数据文件（.mdf/.ndf）与日志文件（.ldf）
- 2B 文件组（Filegroup）：分配与放置的逻辑单元
- 2C 页（Page, 8KB）：IO 与分配的最小原子
- 2D 区（Extent）：8 页连续，分配的基本粒度
- 2E 系统数据库：master/model/msdb/tempdb

## 二、核心精讲（⚠️ 转述）

### 2.1 文件与文件组（⚠️）

一个数据库由**至少一个主数据文件（.mdf）+ 至少一个日志文件（.ldf）**构成，可追加次要数据文件（.ndf）。数据文件归属某个**文件组（Filegroup）**；PRIMARY 是默认组。文件组是"放置策略"的抓手：表/索引可指定建在特定组，从而把冷温热数据分布到不同物理盘（⚠️）。日志文件**不属于**任何文件组——它记的是"动作序列"而非"数据布局"。

✅ 官方口径：[Database Files and Filegroups](https://learn.microsoft.com/en-us/sql/relational-databases/databases/database-files-and-filegroups)。

### 2.2 页：8KB 的宪法（⚠️）

SQL Server 数据文件按 **8KB 页**切分，页是读写的**最小 IO 单位**，也是分配/空间管理的最小单位。页头有页类型（数据页、索引页、GAM/PAM/SGAM、IAM、/boot 等）、页校验、对象 ID、索引 ID 等元数据（⚠️）。数据页内还有行偏移数组（slot array），支持"逻辑顺序 ≠ 物理顺序"的行存取。

### 2.3 区（Extent）与混合分配（⚠️）

分配以 **extent = 8 个连续页 = 64KB** 为基本粒度。小对象先落在**混合区（mixed extent）**（一页一页地给，多个对象共享一个 extent），当增长超过阈值（约 8 页）转为**统一区（uniform extent）**（整个 extent 归一个对象）。谁"在用哪个区"由全局分配图 **GAM/SGAM** 与每对象 **IAM（Index Allocation Map）** 链记账（⚠️）。这正是 SQL Server 平衡"小对象省空间"与"大对象顺序 IO"的核心机制。

### 2.4 系统数据库（⚠️）

- **master**：登录名、配置、系统级元数据与实例"存在性"记录。
- **model**：新建数据库的模板（改它=改所有新库默认）。
- **msdb**：SQL Agent 作业、备份历史、维护计划。
- **tempdb**：临时表/表变量/内部工作区/版本存储（`READ COMMITTED` 快照与 MARS 都靠它），每次启动重建（⚠️；2008 尚无 2019 的多文件并行优化）。

## 三、🔧 类比实验 E1：页大小作为 IO/分配原子单位（非本书 SQL Server 引擎行为）

SQLite 允许把页大小设为 1024–65536 的 2 的幂，正好演示"页=IO/分配原子"这一通识（SQL Server 则固定 8KB，⚠️ 不可改）：

```text
# 本机 python sqlite3 3.45.3，读文件头偏移 16 的大端 2 字节=页大小
pragma page_size=1024 -> 文件头读回 1024, 三页库文件 3072 B
pragma page_size=4096 -> 文件头读回 4096, 文件 12288 B
pragma page_size=8192 -> 文件头读回 8192, 文件 24576 B
```

观察：页大小一旦写进库头就固化；换页大小需重建库。SQL Server 的 8KB 与之同属"以固定大小页作为 IO/分配原子"，但 SQL Server 在此之上还有 extent/IAM 两级分配图（⚠️，SQLite 无 extent 概念）。数字来自本机，不代表 SQL Server。

## 五、常见误区与要点（⚠️）

- "把日志文件放进某文件组"：错——日志不属于文件组（⚠️）。
- "自动增长当常态容量策略"：频繁 grow 制造碎片与延迟；应预配（⚠️）。
- "页大可调"：SQL Server 数据页恒 8KB（⚠️），不像 SQLite 🔧 可选页大小。
- "多 .ndf 一定更快"：要看是否落不同磁盘 LUN，同盘堆文件无并行收益（⚠️）。
- tempdb 争用（PFS/GAM 闩）是 2008 经典故障点：多文件 + 追踪标志 1118 缓解（⚠️，属运维，非引擎实测）。

## 六、数据页解剖（⚠️ 转述）

一张 8KB 数据页自上而下的结构（⚠️，依 Delaney 团队公开描述）：

- **页头（96 字节）**：页类型、分页级别、分配单元 ID、对象 ID、索引 ID、空闲字节偏移、行数、校验与"最小 LSN"（用于恢复时判断页新旧，见 [03-日志与恢复.md](03-日志与恢复.md)）。
- **行数据区**：紧跟页头向后增长，每行含状态位、长度、固定列与"列偏移数组"。
- **行偏移数组（slot array）**：在页尾向前增长，每项 2 字节指向行起点；删除行只清 slot，产生页内碎片（⚠️）。
- **空闲空间**：行区与 slot 区之间；`FILLFACTOR/PAD_INDEX` 控制索引页预留多少空闲以缓解放置时的页分裂。

## 七、分配推演：一张表如何长大（⚠️）

1. `INSERT` 需要空间 → 存储引擎在目标分区的**分配单元（allocation unit，IN_ROW / ROW_OVERFLOW / LOB_DATA 三单元之一）** 上找空闲页。
2. 小量数据 → 从 **SGAM 标记的混合区** 取单页，登记进对象 IAM 的"混合页位图"段。
3. 累积到 8 页 → 转为整块 **统一区**，IAM 链追加新区项，指向下一批 8 页（⚠️）。
4. 页写满 → B+ 树发生**页分裂**（见 [05-索引内部结构与管理.md](05-索引内部结构与管理.md)），一次分配新区或复用空闲。
5. 逻辑顺序靠 slot array + IAM 维持，物理页可散落多文件/多盘（⚠️）。

> 关键：SQL Server 用"混合区→统一区"的两段式，兼顾小表省空间与大表顺序 IO；这是它区别于"直接按页发号"的引擎的核心分配智慧。

## 八、🔧 补充实验（非本书 SQL Server 引擎行为）

```text
# 用 SQLite 观察"页随分配增长"的粗略账本（SQL Server 用 IAM/GAM，⚠️ 无对应 CLI）
PRAGMA page_size=4096;
CREATE TABLE demo(k INTEGER PRIMARY KEY, v TEXT);   -- 起始仅若干根页
INSERT INTO demo(v) VALUES('x'); ...                -- 每灌一批
SELECT * FROM pragma_page_count();                  -- 页数随数据单调上升
```

对照：本机 SQLite 3.45.3 用 `page_count` 粗看空间增长；SQL Server 对应可观测对象是 `sys.dm_db_database_page_allocations`（⚠️，逐页列出分配），二者皆"按页记账"，但 SQL Server 的三级分配单元与 IAM 链是 SQLite 没有的。数字不代表 SQL Server。

## 九、放置与容量规划检查清单（⚠️）

- 数据文件与日志文件**分盘**：日志顺序写、数据随机读，争用相互放大。
- 预配文件初值，autogrow 设固定 MB 步长而非百分比（⚠️）。
- 大表/索引按文件组放置到匹配 IO 画像的 LUN。
- 开启"即时文件初始化"（instant file initialization）避免 grow 时清零延迟（⚠️，需权限）。
- tempdb 文件数≈逻辑核数（≤8 起步）以摊薄 PFS 闩争用（⚠️）。

## 核心概念速览（中英对照）

- 主数据文件 — Primary data file (.mdf)：数据库起点，含系统表首与 PRIMARY 组。
- 次要数据文件 — Secondary data file (.ndf)：追加到某文件组的数据文件。
- 日志文件 — Log file (.ldf)：记录事务动作序列，不属于文件组。
- 文件组 — Filegroup：数据文件的逻辑分组，放置/分配单元。
- 页 — Page：8KB，IO 与分配最小原子，含行偏移数组。
- 区 — Extent：8 连续页（64KB），空间分配基本粒度。
- 混合区 — Mixed extent：多对象各占其页，供小对象省空间。
- 统一区 — Uniform extent：整区归单对象，供大对象顺序 IO。
- GAM/SGAM — Global/Shared Allocation Map：全局/共享区使用位图。
- IAM — Index Allocation Map：某对象持有区的链式位图。
- tempdb — tempdb：临时/内部/版本存储，重启重建。
- 行偏移数组 — Row offset (slot) array：页尾记录各行起始，支持逻辑≠物理顺序。
- 自动增长 — Autogrow：文件写满后的扩容动作，宜预配避免碎片。

- 页/区模型至今未变：SQL Server 2022/2025 仍 8KB 页 + 64KB extent + IAM/GAM 记账；✅ [Database Files and Filegroups](https://learn.microsoft.com/en-us/sql/relational-databases/databases/database-files-and-filegroups)。
