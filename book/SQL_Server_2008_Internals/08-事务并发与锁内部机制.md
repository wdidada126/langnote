# 08 事务并发与锁内部机制（原书 ch12 Transactions and Concurrency + ch13 Inside SQL Server Locking）

> 状态标注：⚠️ = SQL Server 引擎二手转述（本机不可实测）；✅ = Microsoft Learn 现行文档（写前 curl -sL 200）；🔧 = 本机 SQLite/DuckDB 类比，**非本书 SQL Server 引擎行为**。

## 一、本章地图

ACID 的"I（隔离）"和"C（一致性）"靠两样东西落地：**隔离级别**与**锁**。本章讲事务边界、五级隔离（含 2008 引入的快照隔离/RCSI）、锁模式/粒度/层级、锁升级与死锁。它建在 [03-日志与恢复.md](03-日志与恢复.md) 的原子性之上。

## 二、核心精讲：事务与隔离（⚠️）

### 2.1 事务属性与边界（⚠️）

`BEGIN TRAN / COMMIT / ROLLBACK` 划定原子工作单元；回滚依赖日志补偿记录（见 [03-日志与恢复.md](03-日志与恢复.md)）。事务可嵌套（`@@TRANCOUNT` 计数，内层 COMMIT 只递减、最外层才真提交，⚠️）。

### 2.2 隔离级别与三类读异常（⚠️）

ANSI 四隔离（READ UNCOMMITTED / READ COMMITTED / REPEATABLE READ / SERIALIZABLE）对应三种异常：**脏读**（读到未提交）、**不可重复读**（两次读同行动不同）、**幻读**（范围查询多出行）。2008 关键补充：

- **SNAPSHOT**（显式快照隔离）：事务读"提交时点的版本"，写冲突则失败——用版本控制替代锁读。
- **READ COMMITTED SNAPSHOT ISOLATION (RCSI)**：库级选项，把默认 READ COMMITTED 也改成"行版本读"，读不加共享锁（⚠️；靠 tempdb 存版本，回扣 [02-数据库与数据库文件.md](02-数据库与数据库文件.md)）。
- 版本控制（row versioning）：每行带版本指针链，快照/ RCSI 按 LSN 找回"我可见的版本"（⚠️）。

✅ 官方口径：[SET TRANSACTION ISOLATION LEVEL](https://learn.microsoft.com/en-us/sql/t-sql/statements/set-transaction-isolation-level-transact-sql)。

## 三、核心精讲：锁内部机制（⚠️）

### 3.1 锁模式与粒度（⚠️）

模式：S（共享）/ X（排他）/ U（更新，防"读后改"死锁）/ A（资源池关联）/ Sch-S/Sch-M（架构锁）/ IS/IX/IU/SI/UoW 等意图锁。粒度：**行/键 → 页 → extent → 表 → 数据库**，锁管理器（Lock Manager）统一记账，兼容矩阵决定 S/S 兼容、S/X 冲突（⚠️）。

### 3.2 锁层级与锁升级（⚠️）

**锁升级（Lock Escalation）**：当单对象细粒度锁数量越过阈值（2008 约 5000 锁，内部阈值），引擎把它们**换成更高层级**（通常表级 X/S），以省锁内存与匹配开销——代价是并发度骤降。2008 只有"锁数超阈值"这一触发；2014+ 才有 memory pressure / 单锁块阈值可配等（⚠️ 前向引用）。

### 3.3 阻塞与死锁（⚠️）

- **阻塞（Blocking）**：持锁者挡等待者，等待链进 `sys.dm_os_waiting_tasks`/`sp_who`。
- **死锁（Deadlock）**：循环等待，锁监视器周期性"死锁搜索"发现环，选代价小的**牺牲者（victim）**回滚，报 error 1205（⚠️）。追踪标志 1222/1204 输出死锁图（⚠️）；现代用 **扩展事件 `system_health`/`sp_server_diagnostics`**（2012+ 死锁 XML 更完善，⚠️ 前向）。

## 四、🔧 类比：隔离与版本（非本书 SQL Server 引擎行为）

SQL Server 锁/版本机不可本机测，但"读不加锁 vs 加锁、快照读"的通识可对照 SQLite/DuckDB：

```text
# 🔧-E4b SQLite：WAL 让"读不阻塞写、写不阻塞读"
PRAGMA journal_mode=WAL;          -- 多读单写；读看到一致性快照，不被写者挡住
# 🔧-E4c SQLite 默认 rollback-journal：读会因 -journal/锁被写者短暂阻塞
# 🔧-DuckDB：单写者、MVCC 快照隔离
CREATE TABLE t(a INT); INSERT INTO t VALUES(1);
BEGIN TRANSACTION; DELETE FROM t; ROLLBACK;   -- 版本回滚：ROLLBACK 后行复现(类比 undo)
SELECT count(*) FROM t;           -- 仍 1，体现事务原子+快照可见性
```

对照 SQL Server：WAL 的"读不阻塞写"精神近似 RCSI 用版本代替共享锁；DuckDB 的 MVCC/回滚与 SQL Server 行版本+CLR 回滚同属"多版本并发控制"家族（⚠️ 类比，SQL Server 版本存 tempdb、按 LSN 定位，机制更复杂）。数字来自本机，不代表 SQL Server。

## 六、要点与检查清单（⚠️）

- 默认 READ COMMITTED 用锁；开启 RCSI 用版本，减少读阻塞但增 tempdb 与版本链负担。
- SERIALIZABLE/宽范围易键范围锁，并发下死锁面大；能快照则快照。
- 长事务是万恶之源：挡日志截断（见 [03-日志与恢复.md](03-日志与恢复.md)）、挡版本清理、放大锁升级。
- 死锁要治"顺序"：统一多表访问顺序、缩小事务、加合理索引减少持锁时长。
- 锁升级非"越省越好"：它牺牲并发换内存，热点表常需追踪标志 1211/1224 权衡（⚠️）。

## 六、锁兼容矩阵与典型冲突（⚠️）

- **S–S 兼容**（可共存读），**S–X 冲突**，**X–任意 冲突**；**U–S 兼容、U–U 兼容、U–X 冲突**——更新锁专为"先读后改"设计，减少两个 U→X 转换死锁。
- 意图锁 **IS/IX/IU** 挂在高层（表/页）声明下层持锁，加速冲突检测——不必枚举每一行就能判定表级 X 是否与某行 S 冲突。
- **Range 锁族（RangeS-RangeX 等）**：SERIALIZABLE 下按索引键区间加锁，防"新键落进范围"= 防幻读（⚠️）。

## 七、锁内存与锁监视器（⚠️）

- 每个锁结构约 **96 字节**，从通用 lock memory clerk 申请；锁内存吃紧会强制升级甚至报错（"not enough lock memory"，⚠️）。
- **Lock Matcher** 是锁管理器的中央裁决者，所有请求过它——高频争用下 Lock Matcher 本身可能成瓶颈（⚠️）。
- 死锁搜索由**锁监视器周期任务**执行（默认约 5s），发现环后按"回滚代价"选 victim，报 1205（⚠️）。

## 八、常见阻塞/死锁成因（⚠️）

- 长事务：读或写把锁持有到 COMMIT 之后，挡后续（也挡日志截断/版本清理）。
- 缺失/低效索引：本应 seek 几行却扫全表加一堆锁，冲突面暴增。
- 加锁顺序不一致：A 会话按 表1→表2、B 会话按 表2→表1，天然死锁温床。
- 跨库/分布式事务（MSDTC）持锁久，锁资源跨节点协调成本上升（⚠️）。
- RCSI 关闭 + 读热点：经典"读把写挡在外面"，开 RCSI 通常立刻缓解（⚠️）。

## 九、常见问答（FAQ）

1. **问：加共享锁为什么还会被 X 锁挡？** 答：S 与 X 互斥；读要 S、写要 X，读写本就冲突（⚠️）。
2. **问：RCSI 开了就没有阻塞了吗？** 答：读不再被写挡，但写写仍冲突、且 schema 修改/建索引等仍需 Sch-M（⚠️）。
3. **问：更新值不改变数据还触发锁吗？** 答：仍写日志、仍加 X 锁；建议加 `WHERE col <> @new` 短路（⚠️）。
4. **问：死锁牺牲一定回滚全部吗？** 答：只回滚那一条批/语句级别的事务单元，视 `@@TRANCOUNT` 而定（⚠️）。

## 核心概念速览（中英对照）

- 隔离级别 — Isolation Level：定义并发事务间可见性规则的等级。
- 脏读 — Dirty Read：读到其他事务未提交的数据。
- 不可重复读 — Non-Repeatable Read：同事务两次读同一行结果不同。
- 幻读 — Phantom Read：范围查询两次出现新增/消失的行。
- 快照隔离 — Snapshot Isolation：读提交时点版本，写冲突即失败。
- RCSI — Read Committed Snapshot Isolation：库级把默认读改为版本读，免共享锁。
- 行版本链 — Row Version Chain：行历史版本按 LSN 串联供快照定位。
- 共享锁/排他锁 — S/X Lock：读锁/写锁，兼容矩阵决定冲突。
- 更新锁 — Update Lock (U)：读后改的中间锁，防转换死锁。
- 意图锁 — Intent Lock：表/页层级声明下层持锁意图。
- 架构锁 — Schema Lock（Sch-M/S）：改动对象定义时的排他/稳定锁。
- 锁升级 — Lock Escalation：细粒度锁过多时换高层级锁。
- 死锁牺牲者 — Deadlock Victim：被选回滚以破环的事务。

- 版本化成为主流默认取向：RCSI、2014+ 优化版本存储、AG 可读副本的一致性读（✅ [Always On AGs](https://learn.microsoft.com/en-us/sql/database-engine/availability-groups/windows/always-on-availability-groups-sql-server)）把"读不阻塞写"推向工程默认。
