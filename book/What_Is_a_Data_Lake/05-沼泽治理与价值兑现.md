# 05 沼泽治理与价值兑现路线

> 本章为**精读重构**（原书 TOC 不可实证，见 00 §2/§3），收束短册的"why should you care"：
> 湖的失败形态（沼泽）与成功形态（价值兑现）是同一枚硬币——治理是翻转手段。
> 云厂商治理件不可实测标 ⚠️；🔧 实验为 SQLite 3.45.3 类比，**非本书平台行为**。

## 1. 沼泽的定义学：不是"乱"，是"合同失效"

数据沼泽(data swamp)的通俗画像——找不到、不敢用、算不对——用本笔记的语言重述：
04 章三张职责合同（bronze 只追加/silver 口径一致/gold 可弃）中的任何一张被静默违约，
湖即开始沼泽化。**沼泽是治理状态，不是存储状态**：同一堆 S3 文件，合同在履行就是湖，
失守就是沼泽。这个定义让"我们的湖是不是沼泽"变成可测问题——🔧 E4 现场演示：

```
E4 swamp audit after uncontrolled writes: duplicate keys=100, null user_id rows=1
E4 dedup keep-min-rowid: 6.2ms -> rows=5001 distinct=5001
   (bronze untouched: 5101 rows retained as reprocess source)
```

无管制写入（重复投递+缺字段）灌进银层：100 个重复键、1 行空主键，全部**静默**。
去重修复只花 6.2ms，但前提是 bronze 的 5101 行原文完好——04 章的保险单在这里兑付：
**修复在银层做，真相在铜层留**。沼泽化的终点不是脏数据，而是失去"从 raw 重放"这条退路。

## 3. 治理的 SQL 化：E4 的可复用套路

把 §1 的审计-修复做成周报只需四段 SQL（SQLite 实测语法，任何引擎可移植）：

1. 重复键审计：`SELECT eid FROM silver GROUP BY eid HAVING count(*)>1`；
2. 必填空值审计：`SELECT count(*) FROM silver WHERE uid IS NULL`；
3. 保最早行的幂等去重：`DELETE FROM silver WHERE rowid NOT IN (SELECT MIN(rowid) FROM silver GROUP BY eid)`；
4. 层间对账：bronze 行数 ≥ silver 行数（缺口=丢数或违约清洗，04 章 §6 表的实例）。

原则：**治理规则用查询表达，不用 Wiki 表达**——能跑在 CI 里的才是治理。

## 4. 价值兑现：湖的三笔回报（⚠️ 主题重构）

1. **自助分析**：目录+权限就位后，分析师绕开排期自取数据——回报形态是需求周期，
   用 04 章水位日报同时度量"快"和"活"；
2. **ML 原料库**：训练集的可复现要求（04 章 payload 留存+时间旅行）使湖成为特征仓库的
   上游；特征仓/AI 侧叙事盘上有波10兄弟册 #197《Data Warehousing in the Age of AI》在建（同波只登记不链）；
3. **成本重分配**：把"每队一库"的重复存储折算成人力，投向治理与演练（§3/§7）——
   湖省下的钱要看得见地去买保险，否则三年后以沼泽形式连本带息归还。

## 5. 组织面：治理不是部门，是合同签署方

04 章三张合同的甲方乙方（⚠️ 通行讲法转述）：

| 合同 | 甲方（消费方） | 乙方（平台/生产方） | 违约信号 |
|---|---|---|---|
| bronze 只追加 | 重放演练负责人 | 采集与投递团队 | 有人直接改 raw 权限 |
| silver 口径一致 | 业务分析负责人 | 数据工程师 | 同名指标两处不同值 |
| gold 可弃可重建 | 报表所有者 | 加工作业 Owner | 金表成了"唯一真相源" |

湖失败案例的尸检报告几乎都指向同一条：**合同没有签署方，只有默认方（没人）**。

## 6. 演进路线：从短册读到的"下一步"

短册的收尾叙事是成熟度阶梯 ⚠️ 重构：

```
L0 文件堆 ──登记目录──► L1 可发现的湖
     ──分层合同+质量SQL──► L2 可信的湖
     ──表格式+统一权限──► L3 湖仓（多负载混载）
     ──域化产品+数据SLA──► L4 数据产品化（mesh 语言）
```

2021 年的本书能讲到 L2/L3 之间；L4 的词汇表（data product、契约、SLA）是出版窗口后
三年才铺开的 ⚠️——三册地图的分工恰在此：#137 架构世代、#170 运营化世代、本册定义世代
（同波兄弟只登记不链，见 00 §4）。

## 7. 一页行动清单（价值兑现的最后一公里）

- [ ] 目录登记率：出口表 100% 在目录，未登记不许上线；
- [ ] §3 四段 SQL 进周报，重复/空值/对账三警报；
- [ ] 季度重放演练（04 章 §7 第三步）留痕，输出"没收到的字段"清单；
- [ ] 权限双皮检查：BI 与 ML 是否共用同一套行级策略（03 章验收清单第 4 问）；
- [ ] 成本月报含"湖省下的钱去向"一行，防止治理预算被自然蒸发。

## 8. 本章小结

沼泽=合同静默违约，治理=用可执行的查询与签署方把合同钉住，价值=自助/ML/成本三笔回报。
E4 用 6.2ms 演示了修复之廉与退路之贵——这正是短册标题之问的最终答案：
**数据湖值得在意，不是因为它便宜，而是因为它是唯一能同时兑现"原始留存+多引擎读取"
两种承诺的形态——前提是你履行三张合同。**
