# 第 8 章 模式在现代语言中的演化（Rust / Java / Kotlin / Python / Go）

> **一句话**：同一个设计意图，在不同语言里会找到表达力成本最低的实现；**当语言直接给出了该构造，模式就退化成一行代码**——这是 2014 年之后最大的变化。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 判据：模式的必要性 = 语言表达力的缺口 | lambda / enum / record / trait 各自吃掉哪些模式 | 先问「语言有没有直接给」，再谈模式 |
| Rust：trait、enum、所有权如何替代部分模式 | Strategy/State/Visitor/Proxy/Decorator 的 Rust 形态 | 编译期穷尽检查 + 零成本抽象，双分派不再是唯一解 |
| Java：record / sealed interface / 变体如何替代 Builder 与 Visitor | 值类型与穷尽匹配 | Builder 变小、Visitor 变成 switch 模式匹配 |
| Kotlin / Python / Go 的实现差异 | `data class`、`dataclass`、`first-class function`、接口即鸭子类型 | 语法层缩短样板，类型层决定安全边界 |
| 跨语言对照总表 | 23 个模式在五种语言里的写法强度 | 有些模式在 Go 里几乎不出现（Decorator/Builder said 样板少） |
| 选择建议 | 什么情况下仍然要手写模式 | 「跨语言边界、需要命名与审查、需要横切控制」时模式仍有价值 |

## 核心精讲

### 1. 判据：先问语言有没有直接给

| 语言特性 | 直接替代的模式 | 例子 |
| --- | --- | --- |
| **一等函数 / lambda** | Command（一次性）、Strategy、Observer（轻量） | `auto job = [&]{ save(); };` |
| **判别联合 / sealed 类型** | Visitor、State（枚举态） | `std::variant` / Rust enum / Java sealed |
| **值类型（record/data class）** | Builder（少字段）、Memento（不可变快照） | `record Point(int x, int y)` |
| **标准算法与迭代协议** | Iterator、Visitor（遍历） | Ranges / Stream / `__iter__` |
| **智能指针 / 所有权** | Proxy 的「智能引用」、`RefCounted` | `Rc<T>`、`Arc<T>` |
| **模式匹配** | Visitor 的双分派 | Rust `match` 穷尽性检查 |
| **注解与 AOP/中间件** | Decorator（横切） | `@Transactional`、`app.use(mw)` |

**一句话原则**：**如果语言已经给了构造，就用语言；模式只留在语言做不到的地方。**

### 2. Rust：类型系统 + trait 如何替代部分模式

```rust
// 教学示意，不参与构建、不编译、不运行
// Strategy：trait 对象，无需继承层次
trait Compression { fn compress(&self, data: &[u8]) -> Vec<u8>; }
struct Lz4;
impl Compression for Lz4 { fn compress(&self, d: &[u8]) -> Vec<u8> { d.to_vec() } }

fn pack<T: Compression>(data: &[u8], codec: T) -> Vec<u8> { codec.compress(data) }  // 静态分发

// Visitor 的替代：enum + match（编译期穷尽检查，无双分派、无虚开销）
enum Expr { Add { lhs: Box<Expr>, rhs: Box<Expr> }, Num(i32) }
fn eval(e: &Expr) -> i32 {
    match e {
        Expr::Num(v) => *v,
        Expr::Add { lhs, rhs } => eval(lhs) + eval(rhs),
    }
}
```

- **State**：Rust 倾向「用类型表达状态」（`enum Order { Draft(Payload), Paid(Payload) }`），非法状态无法构造——比 GoF 的三个状态类更彻底。
- **Proxy / 智能引用**：`Rc<T>` / `Arc<T>` / `RefCell<T>` / `Mutex<T>` 就是语言级代理；写者锁语义由类型系统保证。
- **Decorator**：用 trait 组合与 `impl Trait` 返回适配器，避免类爆炸。
- **Singleton**：`std::sync::OnceLock<T>` / `LazyLock<T>` 保证「只初始化一次」且 `Send + Sync` 语义明确；但 Rust 的全局可变状态审查更严，多数项目仍选择注入。

### 3. Java：record / sealed interface 如何替代 Builder / Visitor 的一部分

```java
// 教学示意，不参与构建、不编译、不运行
// Builder 的一部分被 record 吃掉：值语义 + 紧凑构造器做校验
public record ServerConfig(String host, int port, int timeoutMs) {
    public ServerConfig {
        if (port <= 0 || port > 65535) throw new IllegalArgumentException("bad port");
        if (timeoutMs <= 0) throw new IllegalArgumentException("bad timeout");
    }
}

// Visitor 的一部分被 sealed interface + switch 模式匹配吃掉（穷尽检查）
sealed interface Expr permits Num, Add {}
record Num(int value) implements Expr {}
record Add(Expr lhs, Expr rhs) implements Expr {}

static int eval(Expr e) {
    return switch (e) {                       // 新增分支时编译期强制处理
        case Num n  -> n.value();
        case Add a  -> eval(a.lhs()) + eval(a.rhs());
    };
}
```

- **Builder 仍未完全消失**：当构造有**多步约束**（先设置 A 才能设置 B、字段之间有不变式）或需要**流式 API** 时，Builder 依然是最好的表达。
- **Singleton**：Java 5 起推荐 enum 单例（防反序列化与反射）；现代更常用框架 scope。
- **Observer**：`java.util.Observer` 已过时，现代写法是 `Publisher`/`Subscriber` 规范或框架事件。
- **Command/Strategy**：lambda 之后只剩「需要撤销/重做/可序列化/可重放」的情况。

### 4. Kotlin / Python / Go 的差异

| 语言 | 对模式的影响 |
| --- | --- |
| **Kotlin** | `data class` 自带 `copy()`（Prototype 的一行版）；默认 `val` 让不可变成为默认（State/Memento 变轻）；`object` 是语言级单例（Singleton）；扩展函数替代部分 Decorator/Utils |
| **Python** | 一等函数 + `functools.wraps` 的装饰器就是 Decorator 的标准形态（`@property`、`@contextmanager`）；`dataclass` + `dataclasses.replace` 是 Builder/Prototype 的轻量版；`iter`/`__iter__` 让 Iterator 变成默认写法；单例用模块级单例即可 |
| **Go** | 接口是隐式实现（「接受接口，返回结构体」），Adapter 常见但继承型模式（Template Method/Bridge）几乎不出现；struct 组合 + 方法值让 Decorator 更像函数包装；`sync.Once` 做初始化 |

```python
# 教学示意，不参与构建、不编译、不运行
# 装饰器 = Decorator 模式的母语形态
import functools
def retry(times: int):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*a, **kw):
            for i in range(times):
                try: return fn(*a, **kw)
                except Exception: continue
            raise RuntimeError("exhausted")
        return wrapper
    return deco
```

### 5. 跨语言对照总表（23 个模式的写法强度）

| 模式 | Rust | Java 17 | Kotlin | Python | Go |
| --- | --- | --- | --- | --- | --- |
| Singleton | `OnceLock`/模块（常用注入） | enum / 框架 scope | `object` | 模块级单例 | `sync.Once` |
| Builder | 结构或工厂 | **`record`+校验，复杂时 Builder** | `apply{}` DSL | `dataclass`+工厂 | 结构体字面量 |
| Abstract Factory | trait 集合 | 接口 + 实现 | 接口 | 类/工厂函数 | 接口 + 结构体 |
| Factory Method | 泛型函数 | `Supplier`/SPI | 工厂函数 | 工厂函数 | 构造函数/接口 |
| Prototype | 派生 `Clone` | 基本不用 | `copy()` | `dataclasses.replace` | 拷贝结构体 |
| Adapter | trait 实现 | 适配方法/接口 | 扩展 | 包装函数 | 接口隐式实现 |
| Bridge | 泛型参数 | 接口树 | 接口 | 组合 | 组合 |
| Composite | `enum` 递归 | sealed + `visit` | sealed | 递归 | 接口递归 |
| Decorator | trait 组合 | AOP/中间件 | 扩展/委托 | **装饰器（最自然）** | 函数包装 |
| Facade | 模块函数 | 服务门面 | 门面类 | 门面函数 | 包级函数 |
| Flyweight | 共享 `&'static` | 常量池/`record` | 值类 | 模块常量 | 结构体值传递 |
| Proxy | `Rc/Arc/Mutex` | 反射代理/Javassist | by delegation | `__getattr__` | 结构体嵌入 |
| Chain of Responsibility | 闭包链 | filter/middleware | 链式函数 | 中间件列表 | 中间件链 |
| Command | `Box<dyn Fn()>` | `Runnable` | lambda | 闭包 | `func()` |
| Interpreter | macro/match | ANTLR | ANTLR | 递归下降 | genny/parser gen |
| Iterator | `impl Iterator` | Stream/`Iterable` | 序列 | `__iter__` | 切片 + `for range` |
| Mediator | 事件/通道 | 事件总线 | 委托 | 事件循环 | channel |
| Memento | 不可变快照 | `record` 快照 | `copy()` | 序列化 | 值拷贝 |
| Observer | channel/`tokio::select` | `Publisher` | 委托 | 回调/信号 | channel |
| State | **enum 状态类型（最优）** | 状态机库/`enum` | sealed | 显式状态函数 | 状态函数组合 |
| Strategy | **trait（最优）** | `Function`/lambda | lambda | 函数参数 | 函数参数 |
| Template Method | 泛型静态版 | `default` 方法/模板 | 抽象成员 | 基类（少用） | 嵌入 + 覆写 |
| Visitor | **`match` 穷尽（最优）** | sealed + switch | sealed/when | `visit` 函数 | 接口双分派（少） |

### 6. 什么情况下仍然值得手写模式

1. **跨语言边界**：同一个设计要在 C++/Java/Rust/Go 里都成立时，抽象成模式便于团队一致。
2. **需要命名与审查**：模式的名字让 Code Review 有共同语言（「这里是 Adapter，它有一个替补实现」）。
3. **需要横切控制点**：事务、日志、权限、重试这些关注点，仍需明确的中间层。
4. **需求本身就是「可枚举的变化点」**：需要撤销栈、需要策略可配置、需要状态机有审计。

## 版本演进

| 语言 | 关键演进 | 对模式的影响 |
| --- | --- | --- |
| C++ | 98（无 lambda/无智能指针）→ 11（lambda、智能指针、`nullptr`）→ 17（`optional/variant/string_view`）→ 20（Concepts、Ranges、Modules、`jthread`） | 手写 Iterator/智能引用/Command 样板基本消失；Ranges 与 Concepts 替代大多数泛型包装 |
| Java | 5（泛型、注解）→ 8（lambda、Stream）→ 11（var、Holder 式单例）→ 17（`record`、`sealed`、switch 模式匹配） | Command/Strategy → lambda；Visitor → 穷尽匹配；Builder → 部分消失 |
| Rust | 2015（1.0）→ 2018（async/await）→ 2021（异步 trait、const generics） | trait 与所有权让 State/Strategy/Proxy 变成类型问题 |
| Kotlin | 2016 起（1.x 至今） | `data class`/`object`/扩展函数让 Builder/Singleton 变轻 |
| Python | 3.x（dataclass 3.7、类型提示 3.5+） | 装饰器 = 原生 Decorator；dataclass 简化值对象 |

## 近年研究与工业界开源实践（2015–2026）

**趋势**：（1）**类型系统继续吃模式**：Rust 的 trait + enum、Kotlin 的 sealed、Java 的 record + sealed + switch 模式匹配，都在把「需要类层次的问题」变成「需要类型构造的问题」；（2）**函数式语法普及**：管道、组合子、异步流让 Decorator/Observer/Chain 变成表达式；（3）**样板的减少带来代码评审焦点的转移**：从「类结构是否合理」转向「类型约束是否完备、错误是否可穷尽处理」；（4）**模式的存活空间收窄到「跨语言、跨团队、跨进程」的名字层**。

| 仓库 | star（实测） | 说明 |
| --- | --- | --- |
| `rust-lang/rust` | **119,149★** | enum + match 穷尽与 trait 对象，是「模式被类型系统替代」的最有力证据 |
| `microsoft/TypeScript` | **111,192★** | 判别联合与 `satisfies` 让「轻量 Visitor」在 JS 生态成立 |
| `swiftlang/swift` | **70,401★** | `protocol` + 关联类型 + `enum` 关联值，替代 Strategy/State/Visitor |
| `spring-projects/spring-framework` | **60,260★** | Java 生态里「模式仍被显式书写」的主场：Factory Bean、AOP 代理、事件发布 |
| `google/googletest` | **39,581★** | 跨语言测试模板，反射出各语言对 Template Method 的不同取舍 |
| `facebook/folly` | **30,545★** | C++ 工业库用少量原语覆盖多数 GoF 场景（`folly::Function` 替代 Command/Strategy） |
| `openjdk/jdk` | **23,379★** | `record`、`sealed`、switch 模式匹配的落地现场，标准库同时是模式标本与反例 |
| `dotnet/runtime` | **18,298★** | `record` / `init` / `required` 在语言层削减 Builder 与工厂；值语义成为默认 |

## 常见误区与本书需修正之处

| 误区 | 现象 | 修正 |
| --- | --- | --- |
| 🔧 **把 1994 的 C++ 实现当标准答案抄到 Rust/Go** | 用 `Box` 手搓「智能引用」，或写一堆 `.clone()` | 用语言原生机制（`Rc/Arc`、接口隐式实现、值语义） |
| 🔧 **以为模式是语言无关的强制结构** | 在非 OO 语言里硬套模板方法继承体系 | 模式的判据是「变化点」；Go/Python 里用组合与闭包即可 |
| 🔧 **Builder 被 record 取代就没有存在价值** | 多步约束与不变式校验仍需 Builder 表达 | 简单值类型用 record；多步约束保留 Builder，把校验放进 `build()` |
| 🔧 **Visitor 被 `match` 取代后仍手写 `accept`** | 无谓的双分派开销，新增元素还要改所有访问者 | 用 sealed/`variant`/穷尽匹配；只有「元素层级长期稳定」的手写场景才用 Visitor |
| 🔧 **Python 里什么都叫装饰器** | 把日志、鉴权、重试都用 `@` 堆起来，栈深难读 | 装饰器只做横切；事务与编排放到显式中间层或中间件管道 |
| 🔧 **Rust 里为了「不用模式」而放弃类型状态** | 用运行时判断状态合法性，丢失编译期保证 | 用 `enum` 类型状态表达非法构造为不可能 |
| 🔧 **跨语言复用时强求「同一个模式的同一份实现」** | 每门语言一份样板，维护成本翻 N 倍 | 在每门语言里找表达力最优解，用模式名保证沟通一致 |
| 🔧 **把「用了 language feature」当作省事** | 用 lambda 替代 Strategy 后丢失了可测试性与可替换性 | 只有一次性算法才退化；需要命名的算法仍保留接口 |
