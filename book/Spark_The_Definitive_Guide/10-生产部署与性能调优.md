## Ch 22 核心：生产部署

### 集群部署模式

| 模式 | 适用场景 | 优势 | 劣势 |
|------|----------|------|------|
| **Standalone** | 开发/小型集群 | 部署简单 | 无资源隔离 |
| **YARN** | 企业级 Hadoop 生态 | 资源共享、安全 | 依赖 Hadoop |
| **Kubernetes** | 云原生/弹性伸缩 | 容器化、弹性 | 部署复杂 |

⚠️ 本书出版时 Mesos 仍受支持；Spark 3.0 已移除 Mesos。

### 关键配置参数

```bash
# 提交应用
spark-submit \
  --master yarn \
  --deploy-mode cluster \
  --driver-memory 4g \
  --executor-memory 8g \
  --executor-cores 4 \
  --num-executors 10 \
  --conf spark.sql.shuffle.partitions=200 \
  --conf spark.sql.adaptive.enabled=true \
  my_app.py
```

| 参数 | 默认值 | 建议 |
|------|--------|------|
| `spark.executor.memory` | 1g | 4-16g（视数据量） |
| `spark.executor.cores` | 全部可用 | 4-5（避免过多线程） |
| `spark.sql.shuffle.partitions` | 200 | 视数据量调整（AQE 可自动） |
| `spark.serializer` | JavaSerializer | `KryoSerializer`（更快更小） |
| `spark.sql.adaptive.enabled` | false (2.x) / true (3.x) | ✅ 开启 AQE |

### 打包与依赖管理

✅ `--packages`：Maven 坐标自动下载依赖
✅ `--jars`：手动指定 jar 文件
⚠️ 集群模式下 Driver 和 Executor 都需要依赖

### 监控与日志

✅ **Spark History Server**：查看已完成应用的历史
✅ **Ganglia / Prometheus + Grafana**：集群级监控
✅ **Application UI**：实时查看 Job/Stage/Task 状态

## Ch 23 核心：性能调优与调试

### 性能调优策略

#### 1. 数据序列化

```scala
// 使用 Kryo 序列化（推荐）
spark.conf.set("spark.serializer", "org.apache.spark.serializer.KryoSerializer")
spark.conf.set("spark.kryo.registrationRequired", "false")
```

✅ Kryo 比 Java 序列化快 10x，体积小 3-5x

#### 2. 内存管理

```
Executor 总内存
├── 执行内存 (Execution) ← Shuffle/Join/Aggregate
├── 存储内存 (Storage)   ← Cache/Broadcast
└── 用户内存 (User)      ← UDF 对象
```

⚠️ `spark.memory.fraction` (0.6)：执行+存储占总内存比例
⚠️ OOM 排查：检查是否有大 Broadcast 变量或未释放的缓存

#### 3. 并行度调整

✅ `spark.sql.shuffle.partitions`：Shuffle 分区数（AQE 可自动调整）
✅ `spark.default.parallelism`：RDD 默认并行度
⚠️ 分区数过少→Task 过大；过多→调度开销大

#### 4. AQE (Adaptive Query Execution)

```python
spark.conf.set("spark.sql.adaptive.enabled", "true")
spark.conf.set("spark.sql.adaptive.coalescePartitions.enabled", "true")
spark.conf.set("spark.sql.adaptive.skewJoin.enabled", "true")
```

✅ AQE 三大能力：
1. **动态合并 Shuffle 分区**：小分区自动合并
2. **动态切换 Join 策略**：Broadcast ↔ SortMerge ↔ ShuffleHash
3. **动态优化数据倾斜**：自动拆分倾斜分区

#### 5. 缓存策略

```python
df.cache()                    # MEMORY_ONLY
df.persist(StorageLevel.MEMORY_AND_DISK)
# 使用后立即 unpersist
df.unpersist()
```

### 调试技巧

| 技巧 | 工具 | 用途 |
|------|------|------|
| 查看执行计划 | `df.explain()` | 分析 Catalyst 优化 |
| Spark UI - SQL 页 | Web UI | 查看物理计划和耗时 |
| Spark UI - Stages 页 | Web UI | 发现数据倾斜 |
| `spark.sql.adaptive.enabled` | 配置 | 开启 AQE 自动优化 |
| Event Log | 配置 | 记录完整执行历史 |
| `collect()` 小数据集 | 代码 | 调试小结果集 |

### 常见性能问题

| 问题 | 症状 | 解决方案 |
|------|------|----------|
| 数据倾斜 | 某些 Task 远慢于其他 | AQE 倾斜处理 / Salting |
| OOM | Executor 崩溃 | 增大内存 / 减少缓存 / 检查 Broadcast |
| Shuffle 过大 | 网络 I/O 瓶颈 | 减少 Shuffle / 预聚合 / 调整分区数 |
| 小文件问题 | 调度开销大 | `coalesce` 合并 / AQE 自动合并 |
| GC 停顿 | Executor 延迟高 | Kryo 序列化 / 减少对象创建 |

## 🔧 DuckDB / SQLite 类比

> 以下类比均为辅助理解，**非本书引擎行为**。

🔧 **类比 1：spark-submit ≈ DuckDB CLI / SQLite CLI**
- `spark-submit --master yarn app.py` ≈ `duckdb db.db < query.sql` ≈ `sqlite3 db.db < query.sql`
- 都是启动执行引擎运行脚本 · ⚠️ 非本书引擎行为

🔧 **类比 2：Shuffle 分区调优 ≈ DuckDB threads / SQLite 无**
- Spark `shuffle.partitions` 控制并行度
- DuckDB `PRAGMA threads=N` 控制并行线程数
- SQLite 单线程，无此概念 · ⚠️ 非本书引擎行为

🔧 **类比 3：Kryo 序列化 ≈ DuckDB 列式存储 / SQLite WAL**
- Kryo 压缩数据减少内存和网络开销
- DuckDB 列式存储天然紧凑
- SQLite WAL 模式优化写入性能 · ⚠️ 非本书引擎行为

🔧 **类比 4：AQE ≈ DuckDB 自适应优化 / SQLite 查询计划器**
- Spark AQE 运行时动态调整执行策略
- DuckDB 也有自适应执行（如自动选择 Hash/Sort Join）
- SQLite 的查询计划器相对简单 · ⚠️ 非本书引擎行为
