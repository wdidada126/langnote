## 2. 监控三层塔（⚠️ 转述重构）

| 层 | 载体 | 典型问题 |
|---|---|---|
| API/管理面 | CloudTrail + CloudWatch 事件 | 谁改了集群参数/WLM？ |
| 资源面 | CloudWatch 指标（CPU/健康/队列深度）+ 控制台 | 容量是否到顶、是否频繁 autoscale |
| 数据面 | 系统表/视图（STL/SVL/SV2/视图族）+ 查询编辑器 V2 | 哪条查询慢了、慢在哪个阶段 |
- 系统表三兄弟（⚠️ 名录转述）：STL_*（原始日志）、SVL_*（过滤视图）、SV2_*（维度/DDL 历史）、以及 SYS* 新视图族（Serverless 优先口径）；
- ✅ 分析入口：https://docs.aws.amazon.com/redshift/latest/dg/query-analytics-monitoring.html （200，"monitor your workload using system tables or CloudWatch"语义锚）；
- 控制台"查询监控选项卡 + 顶级查询 + 并发"三件套是 Ch5 排障方法论的 UI 化（✅ 结构标注）。

## 3. HA/DR 设计（⚠️ 转述）

- RTO/RPO 先行：业务定容忍度，架构选型随之——书中给"重建 vs 恢复 vs 切换"三档时间直觉（✅ 小节实抓）；
- **Multi-AZ**：预置集群可创建为多 AZ 或单 AZ 转多 AZ；故障时自动在健康 AZ 拉起（RTO 分钟级 ⚠️）；Serverless 天然跨 AZ ⚠️；
- 快照：自动（保留期/调度 ⚠️）+ 手动；**跨区域快照复制 = 地域级 DR 主路径**；恢复=从快照新建集群/命名空间；
- "简单重放"小节：用快照快速克隆环境做演练/回归（✅ 标题实抓）——DR 的价值一半在"敢练"。

## 5. 🔧 本机类比（**非 Redshift 行为**）

- 系统表直觉：SQLite `EXPLAIN QUERY PLAN` + `PRAGMA stats` 输出重定向到日志表，模拟"数据面可查询化"；DuckDB 的 `duckdb_logs`/profiling 表同理——"用 SQL 监控数据库"这一 Redshift 招牌范式，本机两件套均可零成本体验；
- 快照/回放直觉：SQLite `VACUUM INTO 'copy.db'` + 文件级复制 ≈ 手动快照+恢复；跨区域复制不可类比（诚实 ⚠️）；
- 并发监控直觉：跑两条长查询同时 `PRAGMA`/系统视图看活动语句——概念版"顶级查询"页。

## 9. 告警规则起步集（⚠️ 转述归纳，上线首日最小集）

- 队列等待：WLM 队列时长 p95 > 阈值（并发瓶颈第一信号）；
- 健康事件：集群/工作群 health 事件（自动恢复触发即通知，§3 Multi-AZ 联动）；
- 慢查询榜：单查询扫描行数 > N 亿 或耗时 > 预算（查询警报，✅ 概念页 200）；
- 存储水位：托管存储/已删除未 VACUUM 占比（Ch5 ATO 联动）；
- 成本曲线：日 RPU-小时环比 +15%（FinOps 周会入口）；
- 审计面：CloudTrail 中参数组/WLM/授权类 API 变更全广播（Ch8 联动）。

## 10. DR 演练清单（⚠️ 按本章快照/多 AZ 机制提炼）

1. 每季度：跨区域快照 → 目标区恢复新集群 → 抽 10 张核心表对账（RTO 实测记录）；
2. 每半年：手动快照"简单回放"克隆测试环境跑回归（✅ 10.6 小节用法）；
3. 故障注入：预置多 AZ 集群 kill 节点事件观察自动恢复；Serverless 观察挂起/恢复时延；
4. 权限演练：Snapshot 恢复出的库权限面核验（恢复≠继承全部 datashare ⚠️）；
5. 复盘：把演练耗时填回 RTO/RPO 表，超容忍即回到 §3 重选型。

## 核心概念速览（中英对照）

- CloudWatch 指标 — metrics：资源面遥测标准出口，可告警可大盘
- 系统表/视图 — system tables & views（STL/SVL/SV2/SYS 族）：数据面"用 SQL 查自身"
- 顶级查询 — top queries：按耗时/资源排序的查询榜（控制台+视图两式）
- 工作负载并发 — concurrent queries：实时并发画像，扩容信号之一
- CloudTrail：管理面 API 审计流水（谁在何时改了什么）
- RTO / RPO — 恢复时间/恢复点目标：DR 设计的双标尺
- Multi-AZ — 多可用区部署：AZ 级故障自动重拉（⚠️ 预置集群特性）
- 自动/手动快照 — automated/manual snapshots：备份双轨，保留期可调 ⚠️
- 跨区域快照复制 — cross-region snapshot copy：地域级 DR 主路径
- 快照回放 — snapshot replay：克隆环境做演练/回归的轻量用法
- Grafana 插件：仓监控第三方大盘官方通道（✅ 小节实抓）
- 查询监控选项卡 — query monitoring tab：控制台内置查询级观察窗
- 事件通知 — event notifications：CloudWatch 事件→SNS 的运维广播线（⚠️ 书内邻近主题）
- 指标命名空间 — metric namespace：AWS/Redshift 与 Serverless 维度差集所在（§7 缺口项）
- 健康事件 — health events：节点/AZ 级异常与自动恢复的发布面（⚠️ 转述）
- 大盘即代码 — dashboards as code：Grafana/QuickSight 监控盘的版本化管理实践（⚠️ 行业惯例）
- 首因分层 — first-cause triage：管理面/资源面/数据面三层各自为政的告警归属（§2 塔）
- 跨集群视图 — cross-cluster queries：一处看全农场查询的 Serverless 红利（✅ 10.2 小节实抓）
- 快照即环境 — snapshot-as-environment：备份资产复用为测试/演练环境的思路（§3 回放小节）
- 运维节律 — operational cadence：§11 表的本质——把遥测变肌肉记忆
