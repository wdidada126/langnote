## 2. datashare 机制本体（⚠️ 转述 + 概念卡）

- 对象模型：`CREATE DATASHARE` → `ALTER DATASHARE ADD SCHEMA/TABLE` → producer 授权 → consumer 集群 `CREATE DATABASE ... WITH DATASHARE` 挂载为**只读库**；
- 三条铁律（⚠️ 转述）：只读；消费方用自己集群的算力/缓存（不拖垮生产方）；跨账户靠 AWS 组织/账户白名单；
- Serverless↔预置互通、跨区限制、对象数上限配额——以官方页为准（✅ 概念主入口 https://docs.aws.amazon.com/redshift/latest/mgmt/ 根 200；专页改版 302，登记缺口 ⚠️）；
- 对位：Snowflake Secure Data Sharing（[../Snowflake_The_Definitive_Guide/10-安全数据共享.md](../Snowflake_The_Definitive_Guide/10-安全数据共享.md)）抽象更干净（share 直接挂 database）；Redshift 的 datashare 挂"schema 子集"且与 namespace 绑定，心智多一层（⚠️ 评价）。

## 3. 多租户 AaaS 三模式（本章精华，✅ 小节实抓 + ⚠️ 机制转述）

| 模式 | 布局 | 隔离/成本权衡 | datashare 的角色 |
|---|---|---|---|
| 池模型 pooled | 全租户共表（tenant_id 列） | 最省、隔离最弱 | 按租户视图共享 |
| 桥模型 bridged | 共享事实+租户分维度 | 中庸 | 多视图组合 |
| 筒仓模型 siloed | 每租户独立 schema/库 | 最强、成本爆炸 | **一 share 对一租户，算力归消费者** |
书中用教育 AaaS 商案例贯穿（✅ 承接 Ch3 学生模型）：SaaS 商把派生数据集卖给校方，同时不泄露他校数据。
这一节的实质是"**用共享代替复制**"：传统 ETL 分发 → 零拷贝订阅，与 [../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md) 的"数据产品"叙事同频。

## 4. ADX 与"仓连仓→仓连市"（⚠️ 转述）

- AWS Data Exchange：把 datashare 打包成商品上架/订阅，计量计费平台代办；
- 注意事项小节覆盖：刷新语义（生产方变更何时可见）、行数配额、支持对象矩阵 ⚠️；
- 对位 Snowflake Marketplace（生态先发且更厚，⚠️ 评价）；BigQuery 侧对应 Analytics Hub（⚠️ 待兄弟册 Google_BigQuery_TDG 定稿对回）。

## 5. 湖方向（7.7）与 Ch3/Ch4 的合流（⚠️ 转述）

- **查询湖**：Catalog Connect 挂 Glue/Iceberg 目录，把湖表当本地 schema 查（RA3/Serverless 上加速缓存 ⚠️）；
- **卸载回湖**：UNLOAD 出 Parquet/Iceberg（✅ https://docs.aws.amazon.com/redshift/latest/dg/r_UNLOAD.html 200）供其他引擎消费；
- 净效果：Redshift 从"仓"升级为"湖仓对等网关"——这正是 2024-2026 官方叙事（datalake/dwh 双向）的成书期雏形（⚠️ 评价）。

## 6. Amazon DataZone 小节（⚠️ 转述；2026 有重大变故，见演进节）

- 组件四件套：Business data catalog / Projects（生产者-消费者工作流）/ Governance & access（Lake Formation 引擎）/ Data portal；
- 八步入门=标准 data mesh 的 UI 化：发布→订阅→双边审批→消费；
- 与 Redshift 集成：把 datashare/湖表注册为数据产品，门户出目录（✅ 译文组件标题实抓）；
- 本章把 Data Mesh 理论（Ch1 一页纸）兑现为服务——全书结构上首尾呼应最重的一对（✅ 结构标注）。

## 7. 🔧 本机类比（SQLite，**非 Redshift 行为**）

- "只读挂载+算力归消费者"：本机 SQLite `ATTACH 'other.db' AS prod (READ_ONLY)`——查询用本进程资源、生产库零负载，与 datashare 的"消费方出算力"同构；权限粒度差异（attach 即全库可见 vs schema 子集授权）恰说明 Redshift 还要 grant 链的原因；
- 三模式玩具：单库内 tenant_id 表（池）/ 每租户一 .db 文件（筒仓）attach 聚合——本机可跑"共享 vs 复制"的 IO 直觉，但网络/计费维度不可类比（诚实 ⚠️）。

## 9. 共享操作序列（SQL 骨架复述，⚠️ 转述形态）

生产方：
```sql
CREATE DATASHARE teaching_ds;
ALTER DATASHARE teaching_ds ADD SCHEMA public;
ALTER DATASHARE teaching_ds ADD TABLE dim_students, TABLE fact_grades;
GRANT USAGE ON DATASHARE teaching_ds TO NAMESPACE '消费者ns';   -- 同账户/跨账户两式
```
消费方：
```sql
CREATE DATABASE prod_share FROM DATASHARE teaching_ds OF NAMESPACE '生产者ns';
SELECT * FROM prod_share.public.fact_grades LIMIT 10;  -- 只读
```
- 消费方权限仍要在本侧 GRANT 给内部用户（共享进门≠人人可读，Ch8 联动 ⚠️）；
- 增量可见性：新对象需再次 ALTER ADD（不是整 schema 自动漂移 ⚠️）；
- Serverless 与预置互为生产/消费方均支持（⚠️ 转述）。

## 核心概念速览（中英对照）

- 数据共享 — datashare：零拷贝只读跨集群/账户发布 schema 子集（⚠️ 转述）
- 生产者/消费者 — producer/consumer：共享关系两端的角色与账单归属
- 命名空间 — namespace：Serverless/共享场景下标识"库集合"的身份层
- 跨账户共享 — cross-account sharing：白名单/组织边界的对外发布
- 池/桥/筒仓 — pooled/bridged/siloed：多租户存储三模式（本章招牌表）
- 分析即服务 — AaaS, analytics as a service：把派生数据集当产品卖
- AWS Data Exchange（ADX）：数据商品市场，datashare 商业化通道
- 数据产品 — data product：mesh 语汇；ADX/DataZone 里的发布单元
- Amazon DataZone：目录+项目+门户+联邦治理的 mesh 服务化（⚠️ 2026 起并入 DataZone→线见演进）
- 商业数据目录 — business data portal/catalog：DataZone 四组件之门面
- Lake Formation 授权：DataZone 细粒度访问的底层引擎（Ch8 亦用）
- 只读挂载语义 — read-only attach：消费方建库即快照式挂载，权限仍要本地二次 GRANT（⚠️ 常见误区）
- 零拷贝 — zero-copy sharing：不复制数据换带宽/存储成本的共享本质（对位 SF 同概念）
- 数据商品化 — data as commodity：ADX 把 datashare 变成可计费订阅品
- 门户发现 — discovery portal：DataZone 目录的人机界面，mesh"产品"叙事的落地件

## 最新演进与工业实践

- 2024–2026 三条主线（⚠️ 转述自 AWS 公开材料，日期以官网为准）：
  ① Zero-ETL 与 datashare 互补：共享管"读别人加工好的"，Zero-ETL 管"自己持续拿源数据"；
