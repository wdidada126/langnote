## 2. 权限模型总览（⚠️ 转述重构）

Redshift 是 PostgreSQL 8.x 血统（⚠️ 史实）：GRANT/REVOKE、schema/table/view/column 级权限、角色继承——
在此之上叠云侧三层：
1. 集群/工作群入口：IAM 认证 + db user 映射（Ch2）；
2. 库内对象：PG 式 ACL + **默认特权 ALTER DEFAULT PRIVILEGES**（新对象不再逐个补授权）；
3. 湖/外部：Spectrum/IAM role 信任链 + **Lake Formation 数据级权限**（列/行粒度统一治理，Ch7 DataZone 同款底座）。
✅ 建表/授权语义锚：https://docs.aws.amazon.com/redshift/latest/dg/t_create-tables.html （200）。

## 3. 三个经典坑（⚠️ 转述 + 🔧 类比）

- **PUBLIC schema 与搜索路径**：PG 系历史坑——search_path 含攻击者可控目录时对象劫持；Redshift 语境多为"新手对象散落 public、权限失控"；
- **对象所有权**：owner 隐式全权，交付后必须转 owner（`ALTER ... OWNER TO`），否则人员流失即权限黑洞；
- **默认特权缺失**：新表不继承 GRANT → 组策略失效，需 ALTER DEFAULT PRIVILEGES 或角色化模板。
🔧 类比（**非 Redshift 行为**）：SQLite/DuckDB 进程内无 ACL——本机可用"文件名即权限"反证权限层存在的必要性；把同一 DB 交给两个 python 进程分别 ATTACH READ_ONLY/读写，可直觉演示"授权在挂载点生效"，与 datashare 挂载（Ch7）同构。权限劫持类坑无法单机演示，纯 ⚠️ 转述。

## 4. RLS 与动态脱敏（本章新特性双璧，⚠️ 转述）

- **RLS**：`CREATE ROW-ACCESS POLICY ... USING (expr)`——策略表达式在扫描期过滤，**对 ALL 用户生效**（含 owner，这点区别于视图方案）；
- 视图/谓词旧法 vs RLS 新法：集中策略、免改查询、与 DISTKEY/SORTKEY 的交互（谓词可下推则代价低 ⚠️）；
- **DDM**：`ALTER COLUMN ... MASKING POLICY`——按角色条件返回掩码值/NULL/部分遮蔽，敏感列"一列多相"；
- 考虑事项小节覆盖：性能回归、与 MV/Spectrum 表的组合限制、审计可见性 ⚠️ 细节未回核英文；
- 对位：Snowflake 的 Row Access Policy + Dynamic Data Masking 几乎同名同构（[../Snowflake_The_Definitive_Guide/05-访问控制.md](../Snowflake_The_Definitive_Guide/05-访问控制.md)）——两册本章可互为讲义。

## 5. 外部数据的权限统一（8.5，⚠️ 转述）

- Spectrum/IAM：集群角色 → 信任策略允许 Redshift 服务主体 AssumeRole → s3:GetObject 面收窄（最小权限）；
- Lake Formation 表/列/行三级权限接管湖侧，Redshift 用户组映射 LF 主体；
- 净效果：**仓内 PG ACL + 湖侧 LF 权限**拼成一张矩阵——2023 成书时的"统一治理"仍是双引擎缝合态（⚠️ 评价），2025+ 统一目录叙事见演进节。

## 6. 与合规场景的连接（⚠️ 转述归纳）

书中示例延续学生数据集：家长只见自己孩子（RLS）、教师见本班但遮 SSN 类字段（DDM）、外部研究员拿脱敏共享（Ch7 联动）——
"同一份物理表，四种可见性"是本章教学主线，也解释了它与 Ch7（共享）、Ch10（审计）的三角关系。

## 8. 授权矩阵模板（⚠️ 转述归纳，可直接抄进 runbook）

| 主体 | 范围 | 动作 | 落点 |
|---|---|---|---|
| bi_readers 组 | 集市 schema | USAGE+SELECT | GRANT 到视图层，不到基表 |
| etl_svc 角色 | staging schema | CREATE/INSERT/TRUNCATE | 专用 db user + 临时凭证策略 |
| analysts 角色 | 生产 schema | SELECT（RLS 过滤后） | ROW-ACCESS POLICY 按 team_id |
| 外部消费者 | datashare 子集 | 只读挂载 | 消费方侧再 GRANT（§9 铁律） |
| 湖侧主体 | LF 表/列 | SELECT/DESCRIBE | Lake Formation 覆盖默认宽松 |

三原则：授权给角色不给个人；对象归组库不归 public；默认特权先行（新表免逐张补票）。

| 反模式 | 症状 | 正解 |
|---|---|---|
| 人人 superuser | 审计无法归责 | 角色模板+组映射（§8 表） |
| GRANT 打到基表 | BI 直连拖垮 ETL 面 | 授权止于 mart 视图 |
| 手工补票新表 | 漏授=数据不可见事故 | ALTER DEFAULT PRIVILEGES |
| 湖仓两套人肉映射 | 权限漂移不可复现 | LF↔角色映射表版本化（8.5） |

## 9. 权限排障决策树（⚠️ 转述）

1. 连不上？——IAM/认证层（Ch2）：temp credentials 过期、SAML 映射缺 db user；
2. 连上看不见库？——datashare 消费侧 GRANT USAGE 缺失（跨库挂载最常见）；
3. 看得到表 403？——schema USAGE vs table SELECT 两级分开查；
4. 结果缺行/多行？——RLS 策略命中面（owner 也被过滤=正常，勿"提权看全量"）；
5. 列露馅？——DDM 策略按角色生效，确认登录主体映射对了组；
6. 湖表忽明忽暗？——IAM 信任链或 LF 联动过期（8.5 两小节合查）。

## 10. 自测五题（合书作答，⚠️ 依据本章要点）

1. owner 查询自己的 RLS 表，会被策略过滤吗？——会；视图方案才存在 owner 豁免问题；
2. 新入职分析师为何看不到上周建的表？——默认特权未配，GRANT 只覆盖既有对象；
3. search_path 为何是安全问题而不只是便利问题？——目录劫持/同名对象错位（§3 坑 1）；
4. Spectrum 表为何不能靠 GRANT SELECT 一劳永逸？——湖侧权限由 IAM 信任链+Lake Formation 决定，仓内 grant 只覆盖挂载点；
5. DDM 与 RLS 同开时排障顺序？——先看列值是否被掩码（策略角色映射），再看行是否被过滤（策略表达式），最后查登录主体映射。

## 11. 本章与 Ch2/Ch7 的三角关系（✅ 结构标注 + ⚠️ 评价）

Ch2 管"进门"（认证/网络/凭证）→ Ch8 管"进门后能碰什么"（ACL/RLS/DDM）→ Ch7 管"递给谁"（共享子集）；
三章各答一问：你是谁 → 你能看什么 → 你能给谁看。生产事故复盘按此顺序倒查最快；
SF 册把三者收进两章，AWS 因 IAM/LF 双引擎拆成三章——结构差异即治理栈差异。

## 12. 术语误用纠偏（⚠️ 帮读）

- "权限"与"认证"混用：连不上多是认证（Ch2），查不到才多是权限（本章）——工单分类第一步；
- "脱敏=加密"：DDM 是查询期策略变换，静态加密（KMS）另在数据面（✅ security-encryption.html 200），两者不可互替；
- "RLS=视图"：视图可被绕过（直查基表），策略绑表不可绕——这是新特性替代旧做法的全部意义；
- "给 PUBLIC 授权图省事"：等于全库裸奔，本章"默认特权"小节的存在就是为了体面地拒绝这个请求。

## 核心概念速览（中英对照）

- 对象所有权 — ownership：对象隐式全权归属，转 owner 是交付动作
- 默认特权 — default privileges：对将来对象预授权（ALTER DEFAULT PRIVILEGES）
- 搜索路径 — search path：名字解析目录序列，劫持与越权经典入口
- 数据库角色 — db role：权限载体，组→角色映射 IAM 身份（⚠️ 转述）
- 行级安全 — RLS (row-level security)：策略表达式扫描期过滤，owner 亦受限
- 动态数据脱敏 — dynamic data masking：按角色对列值实时遮蔽/置空/变换
- 掩码策略 — masking policy：列级绑定、条件表达式选相
- IAM 信任链 — assume role：集群经服务主体换取 S3/LF 访问的联邦桥
- 外部模式 — external schema：Spectrum 挂载 Glue Catalog 的库内代理
- Lake Formation：湖侧行/列级权限引擎，Redshift 组可映射其主体 ⚠️
- PG 血统 — PostgreSQL heritage：ACL 语法与系统目录的兼容性来源 ⚠️
- 最小权限 — least privilege：本章一切示例的默认姿态
- GRANT/REVOKE 两级 — schema USAGE vs table SELECT：缺一级就有"看得见库进不去表"
- 组到角色映射 — group-to-role：IAM 身份进库后的权限承载体，换人不换策
- 掩码列多相 — column per persona：同一列按角色呈现不同形态（DDM 本质）
- 审计闭环 — audit loop：变更（CloudTrail）×数据访问（系统表）双面对账（Ch10 联动）
