# 第 6 章 从客户端到云的并行处理器

> **一句话**：多核之所以难，不是「写不出并行代码」，而是**并行程序的加速比上限由不可并行的那部分决定（Amdahl），而不可并行的是数据依赖与共享资源**；本章把 SISD→MIMD→SIMD→SPMD→向量→GPU→集群→云这条谱系一次走完。

## 核心精讲

> 以下均为**教学示意，不参与构建、不编译、不运行**。

### Amdahl / Gustafson 与扩展性

```c
/* 教学示意，不参与构建、不编译不运行 */
/* Amdahl：固定工作量，串行部分 s 决定天花板 */
double amdahl(double s, int n) { return 1.0 / (s + (1.0 - s) / n); }

/* Gustafson：问题规模随核数增长，串行部分不随之增长 */
double gustafson(double s, int n) { return (1.0 - s) + s * n; }

/* amdahl(0.10, 16) = 5.9  gustafson(0.10, 16) = 15.6 */
/* 本书 6.2 也强调：串行部分的**定义**在不同并行模型下会漂移——I/O、内存带宽、串行段都是串行瓶颈 */
```

### 分类：Flynn 的分类与本书的扩展

```text
SISD  单指令流 单数据流     传统单核
SIMD  单指令流 多数据流     向量机、GPU 的 SIMT、SSE/AVX/RVV
MIMD  多指令流 多数据流     多核、SMP、集群（最常用的一类）
SPMD  单程序多数据         MPI/SYCL/TBB 等 SPMD 编程模型（MIMD 的编程视图）
向量  数据级并行           第 3 章的子字并行是 SIMD 的窄版本
```

### 硬件多线程：三种粒度（6.4）

```text
细粒度多线程（fine-grained）：每个时钟切换线程，靠密集切换掩盖指令延迟（吞吐优先，单线程延迟变差）
粗粒度多线程（coarse-grained）：只在遇到长停顿（如 cache 缺失）才换线程，保持线程延迟
同时多线程 SMT：同一周期同时发射**不同线程**的指令；Intel 的 Hyper-Threading 是其商品化形态
   代价：执行单元与缓存的实际吞吐被两个线程分摊
```

```asm
# 教学示意，不参与构建、不编译不运行
# SMT 的取舍：两条线程同时在流水线里跑，取指宽度与 L1 带宽是共享资源
#   -> 单线程IPC 可能下降，但总吞吐上升
# 与「乱序执行」的区别：SMT 是**线程级并行（TLP）**，乱序是**指令级并行（ILP）**，
#   Smith & Sohi (ISCA 1995) 把这两类并行分开，本章 6.4 正是 TLP 的硬件实现
```

### GPU 的并行模型（6.6）

```c
/* 教学示意，不参与构建、不编译不运行 */
/* 用「线程 = 数据的一个元素」的编程模型描述同一个内核 */
__global__ void saxpy(float *y, float a, float *x, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;   /* 一维线程网格 */
    if (i < n) y[i] = fmaf(a, x[i], y[i]);           /* 每个线程一次乘加 */
}
/* 隐藏在硬件后面的事实：
   - warp = 32 条 SIMT 线程，同一条指令同时作用在一整个 warp 上
   - 靠**极多线程 + 切换**隐藏延迟，而不是靠大缓存或深流水线
   - 访存必须合并（coalesced）：一次 warp 访问应尽量落在连续的 128B 上 */
```

> 与 CPU 的定位差异（本书 6.6 的要点）：
> CPU 追求「**一个线程跑多快**」（深流水线、大缓存、预测执行、强单线程）；
> GPU 追求「**同样吞吐下用多少面积**」（多核 + SIMT + 靠并行度掩盖延迟、缓存小、每个核能跑的线程数极大）。

### 互连拓扑：代价的对比（6.8）

| 拓扑 |度 |直径 | 特点 |
| --- | --- | --- | --- |
| 总线（bus） |1 |1 | 成本低，但广播不可扩展（多核下直接被一致性流量打满） |
| 环（ring） |2 |O(n) | 成本线性，直径随规模变差；商品 CPU 的片间互连常用它 |
| 网格（mesh） |2–4 |O(√n) | 二维 mesh 是片上网络（NoC）与超算的主流拓扑 |
| 环面（torus） |4 |O(√n) | 绕回边降低直径，拓扑等价但布线更绕 |
| 超立方（hypercube） |log₂n |log₂n | 直径最优，布线复杂 |
| crossbar |n |1 | 完全交换，面积 O(n²)，只在少量核之间可用 |
| omega / 多级交换 |2 |log | 用交换级折中，用于片上网络与集群 |

### 消息传递与共享内存（6.5 / 6.7）

```c
/* 教学示意，不参与构建、不编译不运行 */
/* 消息传递（MPI 风格）：显式 send/recv，程序员控制数据移动 */
MPI_Send(buf, count, MPI_FLOAT, dest, tag, MPI_COMM_WORLD);
MPI_Recv(buf, count, MPI_FLOAT, source, tag, MPI_COMM_WORLD, &status);

/* 共享内存（OpenMP 风格 / 线程）：隐式可见，靠同步保证正确性 */
#pragma omp parallel for schedule(static)
for (int i = 0; i < n; i++) y[i] = a * x[i] + y[i];
/* 共享内存下的两个核心问题：
   ① 竞争条件（data race）：无序写导致结果不确定
   ② false sharing（伪共享）：两个线程写同一 cache 行里的不同变量 */
```

### 矩阵乘的并行化收尾（6.12）

```c
/* 教学示意，不参与构建、不编译不运行 */
/* 前面 3 章已用子字并行 ×4、循环展开 ×2、cache 分块 ×2 改造过这段代码；
   本章加上线程级并行：把 i 方向切成 T 块，每块给一个线程/核 */
#define T 16
double C[T][N];
#pragma omp parallel for
for (int i0 = 0; i0 < T; i0++)
    for (int i = i0; i < N; i += T)          /* 相邻行分给同一线程 -> 提升局部性 */
        for (int j = 0; j < N; j++) {
            double sum = 0.0;
            for (int k = 0; k < N; k++)
                sum += A[i][k] * B[k][j];
            C[i0][j] = sum;                  /* 只写自己那一份，避免跨线程同步 */
        }
/* 本书报告的结论：16 个处理器上拿到 14× 加速——并行化本身不难，
   难的是让每一步优化都不把前一步的收益抵消掉 */
```

## 版本演进

| 阶段 | 与本章相关的关键变化 |
| --- | --- |
| **1960s–1970s** | CDC 7600、Cray 的向量机；ILLIAC IV；共享内存多处理机的早期形态 |
| **1980s–1990s 中** | 总线型 SMP 商品化；SPMD 编程模型流行；Flynn 的 SISD/SIMD/MIMD 分类成为通用术语 |
| **1990s 中后期 SMT 提出** | Tullsen、Sohi、Patterson、Ozer 等人提出同时多线程（SMT），论证「空闲执行单元可以用另一条线程填满」 |
| **1990s 集群时代** | Beowulf 与目标机；MPI 标准化；Internet 级并行取代「一个 Symmetric MP」的想象 |
| **2004–2006** | 功耗墙：多核成为唯一出路；GPU 从图形走向通用（GPGPU/CUDA 2006） |
| **2011 / 2015（本书第 5 版）** | **本章整章重写**：GPU（Fermi）、warehouse-scale computers、NIC 的软硬件接口被大量补充 |
| **2017–2019 第二黄金时代** | Hennessy & Patterson 提出「领域定制架构（DSA）」是下一个性能来源；TPU（2015–2017）开始量产 |
| **2019/2020 本书 RISC-V 版** | 本章保持「从客户端到云」的标题，但 GPU/DSA 例子更新，并补 RISC-V 侧的并行与线程扩展 |
| **2020–2023** | RISC-V 向量（RVV 1.0, 2022）把向量作为一等公民；CHIPS 计划与芯粒（chiplet）互连成为主流封装方式 |
| **2022–2026** | AI 加速器（稀疏、低精度、大片上 SRAM）成为 ISA 与微结构的主战场；GPU 与 CPU 的边界进一步模糊（GPU 开始支持标量通用核与缓存一致性） |
| **对照 x86 的微码化与 ARM 的 SVE2** | 商用 ISA 都在「保留生态 + 加可伸缩向量/领域扩展」，本书本章的四类并行（ILP/TLP/DLP/MLP）到 2026 年被全部重新受热 |

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **本章只到「多核 + GPU」的坐标** | 本书第 5 版写成于 2015/2016，之后 10 年的最大变化是 **DSA 与稀疏/低精度 AI 加速器**（TPU/自研 NPU），本章的 GPU 一节已不足以描述今天的加速器版图 |
| 🔧 **Cache 一致性只讲 MESI** | 6.5 的 SMP 讨论隐含「侦听可行」的前提；规模化之后必须用**目录式协议（MOESI/MESIF）**，本书完全没有这一层 |
| 🔧 **「性能 = 时钟频率 × 核数」的直觉在 2020 年代失效** | 单核主频停滞十几年，性能增长主要来自核数摊分、缓存与加速比；同时**每瓦性能与尾延迟**取代峰值成为主要指标 |
| 🔧 **Core i7 vs Fermi 的对比停留在 2015 年** | 今天的 GPU 算力是当年量级的几十倍，而且 CPU/GPU 的边界已被「GPU 上有通用与缓存一致性」改写 |
| 🔧 **RISC-V 向量扩展与商业 ISA 的差异未讲清** | 本书的 SIMD 是「定宽短向量」；RVV 是**可伸缩向量（vsetvli，长度不写死在指令里）**，与 SVE 同思路，与 AVX-512 不同，这个差异会影响第 3 章的结论 |
| **并行程序的困难只归因于 Amdahl** | 6.2 强调 Amdahl，但真正的现代痛点还有：竞争条件、伪共享、NUMA 上的远端访存、以及**并行开销本身**（同步、原子操作、分配） |
| 🔧 **未覆盖「冯诺依曼瓶颈」与数据密集型负载** | 本章按指令流组织；2017 年之后的负载是「数据搬运远超计算」（Patterson 关于数据密集型应用的讨论），用带宽而非吞吐衡量 |
| 🔧 **网络与互连只讲拓扑图** | 6.8 讲 ring/mesh/torus 的形状，未讲 2020 年代的重点：**chiplet 互连（UCIe）、CXL 内存扩展、RDMA/NIC 卸载**——这些才是集群性能的决定项 |
