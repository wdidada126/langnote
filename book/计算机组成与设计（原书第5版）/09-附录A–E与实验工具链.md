## 核心精讲

> 以下均为**教学示意，不参与构建、不编译、不运行**。

### 附录 A：从 `.s` 到可执行文件

```asm
# 教学示意，不参与构建、不编译不运行
# 汇编器（assembler）逐行把伪指令展开成真实指令，并建立符号表
        .data
array:  .word 1, 2, 3, 4
len     = 4
        .text
        .globl main
main:   li   t0, 0              # 伪指令 -> li t0, 0  →  addi t0, x0, 0
        la   t1, array          # 伪指令 -> lui + addi
        lw   t2, 0(t1)
        add  t0, t0, t2
        li   a7, 10             # 退出系统调用号
        ecall                   # 系统调用

# 汇编器的三件事：① 伪指令展开 ② 把标号变成地址 ③ 生成重定位信息
# 链接器（linker）的三件事：① 合并多个目标文件的段 ② 解析符号地址 ③ 为库函数定位
# 加载器（loader）的三件事：① 建立地址空间 ② 复制代码与数据 ③ 跳到入口 _start
```

### 附录 B：逻辑设计基础的三条约定

```text
① 组合逻辑：输出只由当前输入决定（无记忆）—— 比如 ALU、译码器、多路选择器
② 时序元件：状态元件（寄存器）保存信息—— 边沿触发（edge-triggered）是主流
③ 时钟：全局时钟驱动所有状态元件；组合逻辑必须能在下一个时钟到来前稳定
推论：一个时钟周期里，组合逻辑「跑完从输出到寄存器的整条路径」；
     所以流水线切得越碎，单段组合逻辑越短，就能跑越高的时钟频率——
     但也越多流水寄存器（面积与功耗代价）。
```

> 本书第 4 章反复用到的四个部件：**指令存储器（ROM）、寄存器堆、ALU、数据存储器**，
> 加上**四个多路选择器**（决定 ALU 操作数、写回值来源、写回寄存器、PC 来源）就搭出了整台机器。

### 附录 C：GPU 是一种「不同的处理器」

```c
/* 教学示意，不参与构建、不编译不运行 */
/* GPU 的三个结构性选择：
   ① 用**大量小核 + 多线程**代替少量大核：靠并行度掩盖延迟，而不是靠缓存/预测
   ② SIMT：32 条（或 64 条）线程同一条指令同时执行，分支要收敛（divergence 有代价）
   ③ 访存合并：一次 warp 的访问要尽量落在一个连续的 128B 段上 */

__global__ void dot(float *out, float *a, float *b, int n) {
    __shared__ float tile[256];              /* 片上共享内存（scratchpad） */
    int tid = threadIdx.x;
    tile[tid] = a[tid] * b[tid];
    __syncthreads();                          /* 块内同步 */
    if (tid == 0) {
        float s = 0.0f;
        for (int i = 0; i < 256; i++) s += tile[i];
        *out = s;
    }
}
/* 关键差异：CPU 上「一个线程跑多快」最重要；GPU 上「占用率（occupancy）」最重要 */
```

### 附录 D：控制通路为什么需要状态机

```text
单周期实现的控制信号 = 指令的操作码 -> 一组固定的 0/1（一张大真值表）
多周期/流水线的控制信号 = (操作码 × 当前状态) -> 0/1（有限状态机）

两种实现风格：
  微程序（microprogramming）：把控制信号序列存在 ROM 里，逐条执行 → 容易改，但慢
  硬布线（hardwired FSM）  ：用状态寄存器 + 组合逻辑直接生成 → 快，改起来要重新画电路
x86 是微程序的活化石：外部 CISC 指令在内部被拆成微操作（micro-op）交给 RISC 式流水线执行。
这也是第 3、8 章反复出现「CISC 在微码化」的原因。
```

### 附录 E：三种 RISC ISA 的横向对照

| 维度 | MIPS（本书前四版 + 原书第5版） | ARM（AArch64） | RISC-V |
| --- | --- | --- | --- |
| 通用寄存器 | 32（含 r0=0） | 31（x0 恒为 0）+ sp | 31（x0 恒为 0）+ sp |
| 指令长度 | 定长 32 位 | 定长 32 位（A64） | 基础定长 32 位 + 可选 16 位压缩（C） |
| 立即数 | 16 位 + lui | 19/16/12 位（各种形式） | 12 位 + lui 拼 32 位 |
| 内存访问 | load/store 架构 | load/store 架构 | load/store 架构 |
| 分支 | beq/bne + 少量 | b.cond / cbz / tbz + b.bl | beq/bne/blt/bge/bltu/bgeu |
| 条件码 | 无（比较用 slt 生成） | 有（NZCV 状态寄存器） | 无 |
| 向量 | 无标准扩展（历史上有 SIMD） | SVE/SVE2（可伸缩） | RVV（可伸缩，1.0 于 2022 年冻结） |
| 许可 | 专利 + 授权（已退出主流移动市场） | 专利 + 授权 | **完全开源、无授权费** |
| 本书中的角色 | 第 5 版正文的 ISA | Real stuff 实例（Cortex-A8） | 第 5 版 RISC-V 版的 ISA |

## 版本演进

| 阶段 | 与附录相关的关键变化 |
| --- | --- |
| **1980s SPIM 的出现** | 教学用 MIPS 汇编模拟器，至今仍是附录 A 的工具 |
| **1990s 教学附录体系定型** | 本书把「章 + 附录」写成一条可选路径，读者可按软件/硬件两路取用 |
| **2007 第 4 版** | 附录加厚：逻辑设计基础、Verilog、控制通路的硬件实现成为正式附录 |
| **2015/2016 第 5 版** | 附录 E 改写为「RISC 指令集体系结构」，把 ARM/x86 的 Real stuff 纳入 |
| **2019/2020 第5版 RISC-V 版** | 附录全部围绕 RISC-V 重写：附录 E 变成 RISC-V ISA 概览；课堂工具换成 RARS/Venus/Spike；Verilog 示例用来描述流水线控制（附录 D） |
| **2020s** | 附录 C（GPU）在 AI 时代重新变得重要；附录 D 的微码讨论对理解 x86 微操作仍有价值 |
| **2020s 工具的迁移** | 从 SPIM 到 RARS/Ripes：从「看寄存器」到「看数据通路」，教学重心从指令到微结构 |

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **附录 A 的 SPIM 已不是主流** | 第 5 版 RISC-V 版改用 RISC-V 工具链（RARS/Ripes/Spike）；SPIM 只对应 MIPS 版（原书第 5 版） |
| 🔧 **附录顺序按版次漂移** | MIPS 版与 RISC-V 版的附录编号与内容组织不同，引用时要指明版次，否则「附录 B」在两个版本里不是同一节 |
| 🔧 **附录 B 只到「时序元件」** | 没有覆盖 2020 年代硬件设计必备的**复位策略、跨时钟域（CDC）、异步 FIFO 与握手**，而这正是 FPGA/ASIC 入门最常见的坑 |
| 🔧 **附录 C 的 GPU 只到 Fermi** | 本附录写于 2015 年前后；今天的 GPU（ Hopper/Blackwell 一代）在访存层次、张量核心与编程模型上都已改变，需要补充 |
| 🔧 **附录 D 的微码讨论偏历史** | 微程序在现代通用核里几乎绝迹，只有 x86 这类兼容层还保留微码（microcode ROM）；教学时建议把它当作「理解 x86 微操作」的钥匙，而非实现范式 |
| **附录 E 忽略「向量」的当代形态** | 三种 ISA 都已有可伸缩向量（SVE2 / RVV），本书附录只讲标量与简单 SIMD |
| 🔧 **未提 Verilog 之外的现代工具链** | 附录 D 的示例用 Verilog；今天主流是 Chisel/SpinalHDL（因为参数化生成），这也是开源核生态的选择 |
| **把附录当可选读物而跳过** | 附录 B 与附录 D 是读第 4 章的真正前置；跳读会让「控制信号」一节只剩下背表 |
