# 第 2 章 指令：计算机的语言

> **一句话**：一条 RISC 指令只做**一件事**、只认**一个时钟周期**，因此「程序 = 数据 + 地址 + 分支 + 约定」四件套——而**寄存器怎么分配，本质上是编译器与 ISA 之间的一份契约**。

## 核心精讲

> 以下均为**教学示意，不参与构建、不编译、不运行**。

### 五种指令格式（RISC-V RV32I）

```asm
# 教学示意，不参与构建、不编译不运行
# R 型：寄存器-寄存器算术        add  rd, rs1, rs2
# I 型：立即数算术 / load       addi rd, rs1, imm ;  lw rd, imm(rs1)
# S 型：store                  sw   rs2, imm(rs1)
# B 型：分支                   beq  rs1, rs2, label
# U 型：立即数装入高位          lui  rd, imm[31:12]
# J 型：跳转                   jal  rd, label

addi t0, x0, 5          # t0 = 5          （x0 恒为 0，等价于 li t0, 5）
lw   t1, 0(sp)          # t1 = 栈顶的字
sw   t1, 0(sp)          # 存回去
lui  t2, %hi(symbol)    # 高 20 位
addi t2, t2, %lo(symbol)# 低 12 位拼出完整 32 位地址
```

> 定长 32 位、五格式是 RISC 与 CISC 最本质的分野：**所有格式加起来只占指令编码空间的一小部分**，译码逻辑因此极简——这正是 Hennessy & Patterson 1980 年论点的硬件落地。

### 函数调用的栈帧与寄存器约定

```asm
# 教学示意，不参与构建、不编译不运行
# 被调函数 f，RISC-V 约定：
#   a0–a7 = 参数/返回值（x10–x17）；t0–t6 = 调用者保存的临时量（x5,x6,x7,x28–x31）
#   s0–s11 = 被调用者保存（x8,x9,x18–x27）；sp = 栈指针（x2）；ra = 返回地址（x1）
f:
    addi sp, sp, -16        # 在栈上开 16 字节的帧
    sw   ra, 12(sp)         # 保存返回地址
    sw   s0, 8(sp)          # 保存旧的帧指针（s0 即 fp）
    addi s0, sp, 12         # s0 = 当前帧的底部（帧指针）
    ...
    lw   ra, 12(sp)         # 恢复
    lw   s0, 8(sp)
    addi sp, sp, 16         # 撤销帧
    jalr x0, 0(ra)          # 返回（ret 的展开形式）

main:
    li   a0, 3              # 第 1 个参数
    li   a1, 4              # 第 2 个参数
    jal  ra, f              # 调用；ra 被覆盖，所以 f 必须保存它
```

> 三条必须记住的约定：
> ① **调用者保存（caller-saved/temporary）**：`t*` 与 `a*` 由调用方负责在被调函数破坏前自行保存；
> ② **被调用者保存（callee-saved/saved register）**：`s*` 与 `sp` 若被用到，被调用函数必须**原样恢复**；
> ③ **栈生长向下**：`sp` 递减开空间；参数多于 8 个时多出来的走栈；局部大数组走栈或走堆。

### 数组与结构的访问：地址即偏移

```asm
# 教学示意，不参与构建、不编译不运行
# 假设 int A[100]，A 的基址在 t0；int 占 4 字节，所以下标 i 要 ×4
    slli t1, a0, 2          # t1 = i * 4（左移两位）
    add  t1, t0, t1         # t1 = &A[i]
    lw   t2, 0(t1)          # t2 = A[i]
    sw   t2, 0(t1)          # A[i] = A[i]（原地）

# 结构体成员：直接把「字段偏移」写成立即数
#   struct P { int x; short y; char c; };   x@0, y@4, c@6
    lw   t3, 0(a0)          # p->x
    lh   t4, 4(a0)          # p->y（半字，2 字节）
    lb   t5, 6(a0)          # p->c（字节）
```

> 对齐（alignment）：RISC-V 允许非对齐访问（硬件拆分），但 x86 与 ARM 也支持只是代价高；对齐字段能省掉拆装指令，是 2020 年代结构体设计的常识。

### 分支、循环与 switch

```asm
# 教学示意，不参与构建、不编译不运行
    li   t0, 0
loop:
    bge  t0, a0, done       # if (i >= n) goto done
    add  t1, t0, t0         # body …
    addi t0, t0, 1          # i++
    j    loop               # 无条件跳
done:
    # 分支指令只有 beq/bne/blt/bge（及有无符号变体），没有条件码

# switch → 跳转表（jump table）：CI 侧一次性比较，RISC 侧靠表
    la   t0, table
    slli t1, a0, 2          # 下标 ×4
    add  t1, t0, t1
    lw   t2, 0(t1)          # 取目标地址
    jalr x0, 0(t2)          # 间接跳转
```

### 原子性与同步（2.11）

```asm
# 教学示意，不参与构建、不编译不运行
# 保留集（reserved set）式原子读改写：lr.w 之后的空间保证不被别人插队
again:
    lr.w  t0, (a0)          # 读并声明保留
    addi  t0, t0, 1
    sc.w  t1, t0, (a0)      # 尝试写回；成功则 t1 = 0
    bnez  t1, again         # 失败就重试
    fence rw, rw            # 栅栏：保证前面的读写不被后面的重排
```

### 同一段逻辑的三种 ISA 写法

```asm
# 教学示意，不参与构建、不编译不运行
# x86-64（CISC，内存可作 ALU 操作数）
    mov eax, [rbx]      ; add eax, 1 ; mov [rbx], eax
# ARM64（load/store + 三地址）
    ldr w0, [x1]        ; add w0, w0, 1 ; str w0, [x1]
# RISC-V（必须先 load 到寄存器）
    lw t0, 0(a0)        ; addi t0, t0, 1 ; sw t0, 0(a0)
```

> 注意：**RISC-V 一次只碰一个内存操作数**，所以「内存 → 内存」的运输必须显式拆成两次寄存器中转，代码行数因此偏多——这是 2.10 之后所有 RISC 程序的固有形态。

## 版本演进

| 阶段 | 与本章相关的关键变化 |
| --- | --- |
| **1980 RISC 宣言** | Patterson & Ditzel（CACM 1980）：指令少而简单、编译期承担优化、寄存器是性能的支点 |
| **1981–1984 RISC-I/II** | 31 条指令、78 个寄存器（RISC-II 增至 138），寄存器窗口被 SPARC 采纳 |
| **1984–1990s MIPS / SPARC / Power** | 32 个通用寄存器的现代约定定型；MIPS 成为本书前四版的默认 ISA |
| **1990s ARM32** | 条件执行（`cond` 前缀）+ 寄存器少（16 个）换取**代码密度**，嵌入式时代的正确选择 |
| **2011 ARMv8 / AArch64** | 64 位、31 个通用寄存器、去掉条件执行、新增 `ldar/stlr` 供同步使用 |
| **2019/2020 本书 RISC-V 版** | 换成 RV32I/RV64I；立即数处理用 `lui+addi`，跳转用 `jal/jalr`，保留集用 `lr.w/sc.w`；大立即数与 PIC 的讨论全部按 RISC-V 重写 |
| **2020s** | C 扩展（压缩指令 16 位）让 RISC-V 追平 ARM 的代码密度；向量扩展把 SIMD 纳入标准 ISA；商业核开始支持 RV64 与 `Zicbo` 缓存操作 |
| **2017→今天（对照）** | 同期 x86 靠 `AVX-512/AVX10` 在向量宽度上追赶；ARM 用 SVE/SVE2 做可伸缩向量。**指令集之争从「简 vs 繁」变成「可伸缩向量与领域扩展」** |

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **寄存器约定只教到 32 个** | 第 5 版沿用早期约定；RISC-V 正式版 `x0–x31`，`x18–x27` 才是 s 系列，有些中文资料把 `s0/s1` 与 fp 混为一谈，需以 ISA 手册为准 |
| 🔧 **「RISC 指令数多 = 慢」的旧批评** | 2016 年之后的宏操作融合、C 扩展与微码化让这条批评基本失效（见 Celio/Patterson 2016） |
| 🔧 **缺「代码密度」维度** | 本章只讲时钟周期与指令数；在移动端 2020 年代，**16 位压缩指令（C 扩展）带来的取指与缓存收益**是 ARM 与 RISC-V 竞争的主战场 |
| **把 `beq` 理解成 `cmp + je`** | RISC-V 没有隐式标志位；`beq a0,a1,L` 是「一次比较 + 一次条件跳」，与 x86 的两条指令语义不同 |
| **栈帧只会画不会算** | 嵌套调用、叶子函数、`ra` 是否需要保存，取决于函数体是否调用别人；只记「每次都保存 ra」会白白多几条 store |
| 🔧 **同步一节太薄** | 2.11 只给出 `lr.w/sc.w` 与 fence；实际缓存一致性、内存模型（RVWMO）与 Acquire/Release 语义需要在《量化研究方法》与 RISC-V 内存模型书中补 |
| 🔧 **浮点与整数寄存器不分家** | 本章只讲整数寄存器；RISC-V 的 `f*` 浮点寄存器在 03 章与 RISCV-D/M 扩展中另有一套编号与约定 |
| **忽略零寄存器 x0 的妙用** | `addi t0, x0, 5` 即 `li`；很多「立即数」其实是「与 0 相加」。理解这一点才能读懂压缩后的机器码 |
