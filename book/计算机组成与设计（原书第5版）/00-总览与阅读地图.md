## 1. 元数据与作者背景

| 项 | 内容 |
| --- | --- |
| 作者 | David A. Patterson（UC Berkeley，RISC-I、RAID、RISC-V、TPU 的推动者）、John L. Hennessy（Stanford，MIPS/Sparc，2017 年 ACM 图灵奖） |
| 姊妹书 | 《计算机体系结构：量化研究方法》（*Computer Architecture: A Quantitative Approach*）——同一作者的**研究生级量化方法**，本书是**本科级硬件/软件接口** |
| 主线实例 | 第 5 版（MIPS）用 **MIPS32**；同版 RISC-V 版用 **RV32I/RV64I**。全书的贯穿例子是同一个矩阵乘法 `matrix multiply`，四个章各推一次性能上限 |
| 结构特色 | 每章都有 **Real stuff**（真实产品：Cortex-A8 / Core i7 / Fermi GPU）、**Go faster**（软件侧提速手法）、**Fallacies and pitfalls**（谬误与陷阱）、**Historical perspective** |
| 性能线索 | 第 3 章子字并行 ×4 → 第 4 章循环展开 ×2 → 第 5 章 cache 分块 ×2 → 第 6 章 16 处理器线程级并行 ×14；**全书只用 24 行 C 代码改动**跑完全程 |

> 与姊妹书的分工：**本书回答「硬件长什么样、程序怎么被它执行」**，量化方法回答「这么设计值不划算」。
> 想算 cache 缺失代价、想画 Roofline、想做真实微基准，必须回过头看 `book/计算机体系结构.md`。

## 3. 版本演进时间轴

**关键订正**：把指令集换成 RISC-V 的**不是**英文第 5 版（仍是 MIPS32），而是同版次的「第5版·RISC-V 版」（2019/2020）。
第 5 版真正的最大变化是**从单核叙事转向多核叙事**：新增功耗墙、后 PC 时代，第 6 章整章重写为「从客户端到云的并行处理器」。

| 年份 | 事件 | 与本书的关系 |
| --- | --- | --- |
| 1965 | Moore，《Cramming more components onto integrated circuits》 | 第 5 章「面向摩尔定律的设计」的由来 |
| 1967 | Amdahl 的「单处理器能否扛住大规模计算」 | 第 1 章、第 6 章反复引用的加速比上限 |
| 1980 | Patterson & Ditzel, *The Case for Reduced Instruction Set Computers*, CACM 23(9) | 命名并论证 RISC；本书第 2、3 章的立论基础 |
| 1981–1984 | Berkeley RISC I/II（31 条指令、78 个寄存器 → 138 个），Stanford MIPS | 第 2 章寄存器约定、第 4 章单周期实现的原型 |
| 1990 | 《量化研究方法》第 1 版 | 量化设计方法论；本书的量化结论都来自这套方法 |
| 1994 | 本书第 1 版（COD: H/S Interface） | 确立「章 + 附录 + Real stuff」结构 |
| 1998 / 2003 / 2007 | 第 2 / 3 / 4 版 | 第 4 版开始把 ARM 与 x86 的「Real stuff」写进正文 |
| **2015/2016** | **第 5 版（中译本 2015-07）** | **功耗墙 + 后 PC 时代 + 第 6 章整章重写（GPU/WSC/NIC）；实例换成 Core i7 / Cortex-A8 / Fermi** |
| 2017 | Patterson & Hennessy 获 ACM 图灵奖 | 同年 *A New Golden Age for Computer Architecture*（CACM 62(2)）提出「第二黄金时代」 |
| 2019/2020 | **第5版·RISC-V 版** | MIPS → RISC-V；附录 E 改为 RISC ISA 概览；补水坑式教学与调试器（RARS/Spike） |
| 2021–2023 | RISC-V 向量扩展 **RVV 1.0** 冻结、Arm **SVE2**（随 Armv9）、Intel **AVX10** 路线 | 本书第 3、8 章的 SIMD 内容需要按这一代重写（见 03/08 章的「版本演进」） |
| 2024–2026 | 数据中心走「每瓦性能」而非主频；稀疏化与低精度（INT8/FP8/FP4）成为 ISA 新战场 | 本书第 6 章的「从客户端到云」需要向 DSA / 加速器延伸（见 08 章） |

## 6. 跨语言对照：x86-64 / ARM64 / RISC-V 汇编

同一意图的三种写法，读本书第 2 章时的最佳对照表。

| 意图 | x86-64 | ARM64（AArch64） | RISC-V（RV64I） |
| --- | --- | --- | --- |
| 通用寄存器 | `rax rbx rcx rdx rsi rdi rbp rsp …`（xmm/ymm/zmm 为向量） | `x0–x30`（`x29` 帧指针、`x30` 链接寄存器、`sp` 为 x31） | `x0–x31`（`x0`=零、`x2`=sp、`x8`=s0/fp、`x10–x17`=a0–a7、`x5/x6/x7/x28–x31`=t0–t6） |
| 立即数加载 | `mov eax, 10`（32 位立即数入寄存器） | `mov x0, #10`（伪指令，展开为 `movz`） | `li a0, 10`（伪指令，展开为 `addi`/`lui`） |
| 加法 | `add eax, ebx` | `add x0, x1, x2` | `add a0, a1, a2` |
| 加立即数 | `add eax, 10` | `add x0, x1, #10` | `addi a0, a1, 10` |
| 取数（load） | `mov rax, qword [rbx]` | `ldr x0, [x1]` | `ld a0, 0(a1)` / 32 位 `lw a0, 0(a1)` |
| 存数（store） | `mov qword [rbx], rax` | `str x0, [x1]` | `sd a0, 0(a1)` / 32 位 `sw a0, 0(a1)` |
| 相等分支 | `cmp rax, rbx` / `je label`（靠标志位） | `cmp x0, x1` 或 `subs xz, x0, x1` / `b.eq label` | `beq a0, a1, label` |
| 不等/小于分支 | `jne` / `jl` | `b.ne` / `b.lt` | `bne` / `blt` |
| 函数调用 | `call f`（返回地址入栈，名字即符号） | `bl f`（返回地址入 `x30`） | `jal ra, f` 或 `jalr ra, 0(ra)` |
| 函数返回 | `ret`（= `jmp` 到栈上返回地址） | `ret`（= `br x30`） | `jalr x0, 0(ra)` |
| 参数 / 返回值 | `rdi rsi rdx rcx r8 r9` / `rax` | `x0–x7` / `x0` | `a0–a7` / `a0,a1` |
| 栈指针 / 帧指针 | `rsp` / `rbp` | `sp` / `fp`(x29) | `sp`(x2) / `s0`(x8) |
| 调用者保存（易失） | `rax rcx rdx rsi rdi r8–r11` | `x0–x18`（部分） | `t0–t6` |
| 被调用者保存（_callee_ 保存） | `rbx rbp r12–r15` | `x19–x28` | `s0–s11` |
| 系统调用 | `syscall`（Linux x86-64） | `svc #0`（Linux aarch64） | `ecall` |
| 内存屏障 | `mfence` | `dmb ish` / `dsb sy` | `fence iorw, iorw`；取指栅栏 `fence.i` |
| 原子读改写 | `lock xchg` / `lock cmpxchg` | `ldar` / `stlr` | `lr.w` / `sc.w` |
| 双精度浮点加 | `addsd xmm0, xmm0, xmm1` | `fadd d0, d1, d2` | `fadd.d ft0, ft1, ft2`（扩展 F/D） |

> 三条值得记住的**结构性差异**：
> 1. RISC-V 是**纯 load-store** 架构，只有 `lw/sw/lh/sh/lb/sb/ld/sd` 碰内存；x86 的 `add [mem], reg` 一类内存-内存运算在 RISC-V 里根本不存在。
> 2. ARM64 与 x86 双双把**标志位**藏在隐式状态里（`cmp` 不写目的寄存器）；RISC-V 为了分支预测与乱序友好，**没有隐式标志位**，比较直接生成 `slt/sltu` 或走 `beq`。
> 3. RISC-V 只有 `beq/bne/blt/bge` 四条分支、**无条件跳转** `jal/jalr`，没有 Condition Code，因此条件执行要靠**分支预测器**而不是靠标志位复用。

## 7. 阅读路径建议

- **软件方向**：1 → 2 → 3（3.1–3.5）→ 4.1/4.5/4.10 → 5.1–5.4 → 5.7 → 6.1–6.5，重点盯每章的 **Go faster** 小节。

- 每章的 **Fallacies and pitfalls** 是最容易漏掉、也最值钱的部分，务必逐条对照（见各章「常见误区」）。
