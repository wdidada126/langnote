# 第 1 章 计算机抽象及相关技术

> **一句话**：计算机体系结构的全部艺术，就是**在一层一层的抽象里只暴露恰好够用的接口**——「指令集架构」是软件看到的那一层，「微体系结构」是硬件真正实现的那一层，而**性能只能靠量化测出来，不能靠直觉猜出来**。

### 性能度量的三个层次（本书最常考的换算）

```text
响应时间（response time / latency）：单个任务从开始到结束的墙钟时间
吞吐率（throughput）              ：单位时间完成的任务数
CPU 时间                          ：CPU 真正花在**本程序**上的时间（不含 I/O、不含他人占用）

CPI（cycles per instruction）= 总时钟周期数 / 指令数（IC）
CPU time = IC × CPI × 时钟周期长度
MIPS     = 指令数 / (CPU time × 10^6)   ← CPU time 越小 MIPS 越大
```

> 三个陷阱，本书 1.10 逐条点名：
> ① **不要用 MIPS 比较不同指令集**：同样一句 C，`load-store` 架构的指令数天然更多，MIPS 反而更低（MIPS 在单周期内「指令数少」的优化下可以趋于无穷大）。
> ② **不要用 MIPS 比较同一处理器上不同编译优化**：优化减少了 IC，但 CPI 与时钟频率不变，MIPS 的变化不能说明墙钟时间的变化。
> ③ **不要用时钟频率代表性能**：核数、缓存、内存带宽全都能让低频机器更快。
> 唯一可信的度量是**墙钟响应时间**（以及数据中心语境下的**每瓦吞吐**）。

### 功耗墙：为什么频率涨不动了

```text
动态功耗 ≈ α × C × V² × f     （α=开关活动因子，C=负载电容，V=电压，f=时钟频率）
静态功耗 ≈ 漏电电流 × V       （尺寸不断缩小后不再可忽略）

结论：想提频率就要提 V，而 V 一提功耗就三次方级上涨、散热立刻崩。
Dennard 缩放（尺寸缩小 → 电压同比缩小 → 功率密度不变）在 2000 年代中期失效，
于是产业界改走两条路：多核（吞吐）+ 精填充（避免浪费）（能效）。
```

> 这也正是本书第 6 章整章重写、以及后来「第二黄金时代」（Hennessy & Patterson, CACM 2019）命题的起点：
> **性能不再来自单一时钟，而来自核数 × 能效 × 并行度。**

### 后 PC 时代与 Amdahl 定律

```c
/* 教学示意，不参与构建 */
/* Amdahl 定律：不可并行部分 s 决定加速比的天花板 */
double amdalh_speedup(double serial_fraction, int cores) {
    /* 串行部分占 s，其余可摊到 cores 个核；无限核时上限为 1/s */
    double parallel = 1.0 - serial_fraction;
    return 1.0 / (serial_fraction + parallel / cores);
}
/* serial_fraction = 0.10, cores = 16  ==> 上限 10×（16 核只拿到 5.9×） */
```

> 本书第 6 章反复用这个公式说明：**加核很容易，改掉串行部分很难**。

## 版本演进

| 阶段 | 与本章相关的关键变化 |
| --- | --- |
| **1980s** | 性能 = 时钟频率。RISC 论文论证「指令数多但每条简单」反而更快，逻辑上还没碰到功耗墙 |
| **2000s 中期** | Dennard 缩放失效，功耗墙显现；Intel 取消 Tejas/Jayhawk 转向多核 |
| **2015/2016（本书第 5 版）** | 把「功耗墙」与「从单核到多核的沧海巨变」写进第 1 章正文，实例换成 Core i7、Cortex-A8、Fermi GPU |
| **2019/2020（第5版 RISC-V 版）** | 章节名从「计算机概要与技术」改为「**计算机抽象及相关技术**」，突出抽象层次；后 PC 叙述改用平板与云基础设施 |
| **2021–2026** | 移动端进入「每瓦性能」竞争；数据中心关注尾延迟（tail latency）与 **Attack of the Killer Microseconds**（Barroso/Patterson/Ranganathan, CACM 2017）——性能度量从平均延迟转向 **P99/P999** |
| **2026 视角** | 单核主频在 2020 年代基本停滞（约 3–5 GHz 量级），CPU 侧的性能提升主要来自核数、缓存、SPEC 优化与**异构加速**；因此第 1 章的「性能」定义必须补上 **每瓦性能** 与 **尾延迟** 两个维度 |

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **「第 5 版改用 RISC-V」的常见误传** | 英文第 5 版（中译本 2015-07，ISBN 978-7-111-50482-5）**仍是 MIPS32**；改成 RISC-V 的是同版次的「第5版·RISC-V 版」（2019/2020）。买书或引用时要分清 |
| 🔧 **性能公式只覆盖单核** | `CPU time = IC × CPI × 时钟周期` 是单核模型；第 6 章讲多核时，墙钟时间还要除以有效并行度，否则会高估加速比 |
| 🔧 **功耗墙一节停在 2015 年** | 本书只讲动态功耗与 Dennard 缩放；2017 年之后的**电压墙（stackoverflow）**、**降频/省电的 DVFS 策略**、**Chiplet/3D 堆叠带来的热密度**都未覆盖 |
| **把 MIPS 当性能单位** | 本书 1.10 第 1 条谬误：MIPS 可以因「单周期指令优化」而趋近无穷，且跨指令集不可比 |
| **用时钟频率论英雄** | 1.10 第 4 条：核数、缓存容量、内存带宽都可能让低频机器胜出 |
| 🔧 **只讲平均延迟不讲尾延迟** | 1.9 用 SPEC 的平均值说话；数据中心语境下 P99 才是用户的真实体验（见 Barroso et al. 2017） |
| 🔧 **未覆盖 2020 年代的加速器叙事** | 1.8「从单核到多核」只讲到多核（multicore）；TPU 与稀疏加速器主导的推理负载，在本书里只有第 6.6 节 GPU 一小节 |
| **冯诺依曼瓶颈的缺席** | 本书通篇不质疑「指令驱动、取指-执行」的结构本身；想看反面论证见 Backus 1977（见 03 章） |
