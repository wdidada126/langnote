# 第 3 章 计算机的算术运算

> **一句话**：整数用**补码**表示「符号」而不占一位，加减法因此只有一套电路；浮点用「符号+指数+尾数」把小数塞进 32 位——**而浮点错误的常见来源不是精度不够，是指数跑飞**。

## 核心精讲

> 以下均为**教学示意，不参与构建、不编译、不运行**。

### 补码：加减只有一个电路

```c
/* 教学示意，不参与构建、不编译不运行 */
/* n 位补码：最高位为符号位，值为 -2^(n-1) + Σ b_i·2^i (i<n-1) */
/* 关键性质：加法直接按位加，溢出回绕后结果仍然正确 */
int8_t a = 100, b = 60;
int8_t s = (int8_t)(a + b);   /* 160 溢出：补码回绕成 -96 */
                              /* 用 8 位看：100+60=160=0xA0 -> -96（正确回绕） */

/* 减法 = 加上负数（补码取反加一） */
int8_t d = (int8_t)(a - b);   /* 40 */
```

**溢出检测**（本书 3.2 的判据）：

```text
设两个 n 位操作数 a、b，结果 sign = a[n-1] xor b[n-1]，carry_into_sign 为进入符号位的进位
有符号溢出溢出条件 = carry_into_sign xor carry_out_of_sign
也就是：同号相加却得到异号结果  ==> 有符号溢出（无符号看进位 C_n-1 即可）
```

> 与浮点不同：**有符号整数溢出在补码里不是错误**，C 语言只说它是未定义行为（UB），编译器可以据此做任意优化——这是 2020 年代「整数溢出是 UB」讨论（如 `fortify-source`、`_FORTIFY_SOURCE`）的根源。

### 乘法与除法：ALU 之外的迭代

```text
乘法（本章讲的低功耗形式）：
  乘法器 = 被乘数寄存器 + 累加器 + n 位加法器 + 乘数寄存器
  每一步：根据乘数的最低位决定是否把被乘数加到累加器，右移一位，共 n 步
  面积/时延与「每步加法」成正比；现代核用 Booth 编码 +进位保留加法器+ Wallace 树压缩

除法（恢复余数法）：
  remainder = 0; 逐位：remainder = remainder<<1 | 下一位
                若 remainder >= divisor 则 remainder -= divisor 且该位置 1
  不恢复余数的除法靠「上一步的小差」省掉一次减法
```

> 工程结论：**乘法在硬件里很贵**（面积与功耗），所以编译器从不手写乘法；而**除以常数**会被编译成乘以倒数（浮点）或移位合并（整数），这也是 3.3 之外最实用的一条。

### IEEE 754：把小数做成科学计数法

```text
单精度（32 位）： 1 位符号 | 8 位指数（偏置 127） | 23 位尾数（规格化后隐含前导 1，实际 24 位有效）
双精度（64 位）： 1 位符号 | 11 位指数（偏置 1023） | 52 位尾数（隐含前导 1，实际 53 位）

数值 = (-1)^s × 1.f × 2^(e - bias)
特殊值：e=0 且 f=0 → ±0；e=0 且 f≠0 → 非规格化数（没有隐含前导 1）；
        e=全 1 且 f=0 → ±∞；e=全 1 且 f≠0 → NaN（多种安静/ Signaling NaN）
舍入模式（默认）：向最近偶数（round-to-nearest-even）——同时是「对称」的，能抵消系统性偏差
```

```c
/* 教学示意，不参与构建、不编译不运行 */
#include <stdio.h>
int main(void) {
    float x = 1.0f;
    volatile float half = 0.1f;
    x += half;                 /* 0.1 在二进制里是无限循环小数 */
    printf("%.20f\n", x);      /* 结果不是 1.10000000000000000000，而是最接近的浮点数 */
    return 0;
}
/* 0.1f 的实际值 = 0.100000001490116119384765625 …… */
```

> 浮点加法的**五个步骤**：对阶（小指数向大指数对齐）→ 尾数相加 → 规格化与舍入 → 指数溢出/下溢检查 → 符号处理。
> 代价：一次浮点加法可能要几十个整数时钟周期；这就是为什么需要 `FMA`（融合乘加）与向量化。

### 子字并行：一条指令干四件事（3.6 / 3.8）

```c
/* 教学示意，不参与构建、不编译不运行 */
/* 朴素版：每个时钟周期做 8 个浮点乘加，但标量指令只算一个元素 */
void dgemm_scalar(float *C, float *A, float *B, int n) {
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) {
            float sum = 0.0f;
            for (int k = 0; k < n; k++)
                sum += A[i*n+k] * B[k*n+j];   /* 每次只用 1 个浮点通道 */
            C[i*n+j] = sum;
        }
}

/* SIMD 版：一次处理 4 个 float（单个 128 位寄存器装 4 个通道） */
void dgemm_simd4(float *C, float *A, float *B, int n) {
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j += 4) {
            float c[4] = {0,0,0,0};
            for (int k = 0; k < n; k++) {
                float a = A[i*n+k];
                c[0] += a * B[k*n+j+0];
                c[1] += a * B[k*n+j+1];
                c[2] += a * B[k*n+j+2];
                c[3] += a * B[k*n+j+3];   /* 4 条独立累加，正好喂满 4 个通道 */
            }
            C[i*n+j+0]=c[0]; C[i*n+j+1]=c[1]; C[i*n+j+2]=c[2]; C[i*n+j+3]=c[3];
        }
}
```

> 本书用这个例子论证：**矩阵乘不需要改算法，只要把「4 个通道的运算」叠到一条指令里，就能白拿 4 倍**——代价是需要处理尾部余数（`j+4 > n` 时的边界），这正是 3.8 「Go faster」小节的核心工程内容。

### 溢出与精度陷阱（3.9 谬误与陷阱）

| 谬误 | 事实 |
| --- | --- |
| 「浮点就是实数」 | 浮点数在**幅值很大时**相邻 두 数间隔固定（`eps`），在接近 0 时又极密——这是**离散且非均匀**的表示 |
| 「用 `==` 比较浮点结果」 | 舍入误差让「同一个数学结果」在不同计算顺序下给出不同位模式；应比较误差界或用相对误差 |
| 「溢出会抛异常终止程序」 | IEEE 754 默认**不**触发异常，而是给出 ±Infinity 并继续；`feenableexcept` 才可选地打开 |
| 「整数溢出会 wrap-around 所以安全」 | C 标准里**有符号**整数溢出是未定义行为，编译器可以假设它不发生并据此优化 |
| 「乘法慢所以少用」 | 硬件乘法器只要几个周期，且 Ivy Bridge 之后乘法**吞吐**已与加法同量级（延迟略高） |

## 版本演进

| 阶段 | 与本章相关的关键变化 |
| --- | --- |
| **1960s–1970s** | 各家浮点格式不兼容（x86 x87 用 80 位扩展精度，图形硬件格式各异） |
| **1985 IEEE 754 标准** | 统一二进制表示、舍入模式与异常；1990 年被 IEEE 754-1985 正式采纳，本章 3.5 就是这一标准 |
| **1989 x87 的 FSTP 与倒数** | 早期 x87 无 FMA，`sin/cos` 用查表+多项式 |
| **2000s SSE2（x86-64 起强制）** | 整数 SIMD 与双精度 SIMD 进入通用 CPU；本书 3.6 的子字并行即 SSE 形态 |
| **2011 AVX / 2016 AVX-512** | 256 位 → 512 位，掩码寄存器、融合域操作；代价是**降频**（热密度） |
| **2019/2020 本书 RISC-V 版** | 浮点与整数寄存器区分（`f*` 系列），`F/D/Q` 扩展与 `Zfh`（半精度）成为标准扩展；矩阵乘例子改用 RISC-V 向量指令描述 |
| **2021 SVE2 / 2023 AVX10** | ARM 用可伸缩向量（SVE/SVE2）解决「宽度写死在 ISA 里」的老问题；Intel 用 AVX10 把 512 位与 256 位域解耦 |
| **2020s 低精度浪潮** | BF16 / FP8 / FP4 进入 ISA 与数据通路：AI 训练与推理把「精度」当作可调旋钮，**本章 3.5 的固定格式模型正在被可配置格式挑战** |
| **2022 RVV 1.0** | RISC-V 向量扩展 1.0 冻结，`vsetvli` 让「一条指令处理任意长度」成为标准写法 |

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **只讲 32/64 位固定宽度浮点** | 2020 年代的主流是 **BF16/FP16/FP8/FP4** 与可伸缩向量，固定宽度的教学模型与工业实践脱节（见 ARM SVE2 / Intel AVX10 / RVV） |
| 🔧 **子字并行只讲「×4」** | 第 5 版用 128 位装 4 个 float 的示例；今天 256/512 位与 V 扩展的长向量把倍数推到 8–64，且需要**尾部掩码**处理 |
| **把「浮点异常」当成陷阱（trap）** | IEEE 754 默认**不** trap，产生 NaN/Inf 继续运行；只有显式打开异常_ENABLE 位才会 |
| **用 `x == y` 判断浮点相等** | 3.9 明确列为谬误；工程上的正确做法是比较绝对/相对误差，或做区间运算 |
| 🔧 **乘法器结构与今天不符** | 本书讲「n 步移位加法」；现代核是 Booth + Carry-save + Wallace 树，吞吐已接近加法器，但**面积与延迟**的教学结论仍然成立 |
| 🔧 **整数溢出与浮点下溢混为一谈** | 有符号整数溢出在 C 里是 UB（编译器可假设不发生），浮点下溢只是丢精度；二者的后果严重程度完全不同 |
| 🔧 **未覆盖 FMA 与融合运算** | 本章没有 `fma`（乘加融合）这一节，而 FMA 是 2015 年之后浮点性能的重要来源，且直接影响精度 |
| **忽略非规格化数与渐进下溢** | 3.5 提到非规格化数，但没解释它们为什么存在（避免下溢时的突然归零），也没提 flush-to-zero 的性能陷阱 |
