# 第 5 章 大容量和高速度：开发存储器层次结构（二）——虚拟内存与可靠存储

> **一句话**：虚拟内存同时是三样东西——**给进程的地址空间 illusion、给 OS 的访问控制手段、给硬件的「主存 cache」**；而 TLB 就是「页表的 cache」，它让这套体系在硬件上跑得动。

## 核心精讲

> 以下均为**教学示意，不参与构建、不编译、不运行**。

### 虚拟地址到物理地址：一次翻译的完整路径

```asm
# 教学示意，不参与构建、不编译不运行
# 一次 load 的硬件路径（简化）：
#   1) 用虚拟地址的 VPN（virtual page number）查 TLB
#   2) TLB 命中 -> 直接得到物理页帧号 PPN，拼上 offset 得到物理地址
#   3) TLB 缺失 -> 查页表（可能需要多级页表，一次访存）+ 更新 TLB + 重跑指令
#   4) 拿到物理地址后再查 cache
#
#   虚拟地址        页表/TLB               物理地址
#   | VPN | offset |  -> PPN | offset ->（cache 命中/缺失）
#   32 位中典型拆分：VPN = 20 位（4KB 页），offset = 12 位

lw   t0, 0(a0)      # a0 里是「虚拟地址」；硬件替你完成 VPN->PPN 的翻译
```

```c
/* 教学示意，不参与构建、不编译不运行 */
/* 多级页表（x86-64 的 4 级为例，概念上一致）：
   根目录 -> 上级目录 -> 中间目录 -> 页表 -> 得到物理页基址
   目的：稀疏使用地址空间时不必为整张表付代价（其实是树，不是数组） */
```

### TLB：页表的 cache

| 项 | 说明 |
| --- | --- |
| 为什么需要 | 每访问一次内存就要查一次页表 = 一次额外访存，性能上不可接受；TLB 把「翻译」本身也做成层次结构 |
| 放在哪 | 通常位于 cache 与 L1 之间（也可能在 L1 内），是**虚拟寻址**的唯一一套缓存 |
| 内容与结构 | VPN → PPN、有效位、脏位、权限位、ASID（地址空间 ID，避免每次切换进程都刷 TLB） |
| 缺失处理 | 硬件直接遍历页表（成本：多次访存）/ 操作系统通过「页错误」介入 |
| 与 cache 的关系 | **TLB 是虚拟寻址，cache 一般是物理寻址**（虚拟索引 + 物理标签是折中方案）；二者是串联关系，不是竞争关系 |

```asm
# 教学示意，不参与构建、不编译不运行
# 页错误（page fault）发生时，硬件做的是：
#   1) 把触发的虚拟地址与错误原因写入特定寄存器（如 RISC-V 的 stval/scause）
#   2) 关中断、跳到内核里的页错误处理例程
#   3) 内核决定：分配新页 / 换出到磁盘（swap）/ 拒绝访问（段错误）
#   4) 更新页表、刷 TLB（sfence.vma）、返回用户态重新执行那条指令
```

### 存储层次统一框架（5.8）

```text
每一层都回答同样三个问题：
  ① 这一层的「块」叫什么？      cache 叫 block/line，TLB 叫 entry，虚拟内存叫 page
  ② 缺失时去哪里找？            下一层（或下一级页表）
  ③ 命中/缺失的代价各是多少？    命中时间 + 缺失率 × 缺失惩罚

统一之后的关键洞察：**页表也是一层 cache**，
区别只是它的「缺失处理」由操作系统而不是硬件电路驱动。
```

### 可靠存储：用冗余换正确性（5.5）

```text
错误检测：
  奇偶位（parity）        ：1 bit 检 1 位错（无法纠错，且同时错两位会漏检）
  校验和（checksum）      ：传输层常用（如 TCP/IP 头校验和）
  CRC / ECC（SECDED）     ：内存用 SECDED（纠正 1 位、检测 2 位）足够

错误处理的三个层次：
  故障（fault）  ：可检测、可恢复（如页错误）
  错误（error）  ：检测到了但本层次没恢复（ECC 无法纠正则 panic）
  失效（failure）：服务中断
可靠性 = 累计危险故障的时间占比；可用性 = 提供服务的时间占比
（MTTF / MTTR 是这两个量的经典度量）

RAID 的几个Level（思想比编号重要）：
  RAID0 条带（无冗余，纯吞吐）
  RAID1 镜像（100% 冗余，读可并行、写要同步）
  RAID3/4 带校验盘     RAID5 分布式校验（重建 I/O 代价高）
  RAID6 双校验（容忍两块盘同时坏）
```

### 页表项与权限位

```asm
# 教学示意，不参与构建、不编译不运行
# 页表项（示意）字段：
#   V 有效位    R/W 读写权限    U 用户/内核
#   A 访问位（ Accessed，用于页面回收与老化）
#   D 脏位（ Dirty，写过的页换出时必须写回）
#   PPN 物理页帧号
# 权限检查发生在地址翻译的每一步：
#   用户态写只读页 -> 页错误 -> 内核决定是否 SIGSEGV
```

> 一句话总结这一章的软硬分工：**页表是软件维护的数据结构，TLB 是硬件维护的高速副本，而「页错误」是两者不一致时 OS 被叫醒的唯一通道。**

## 版本演进

| 阶段 | 与本章相关的关键变化 |
| --- | --- |
| **1960s** | Atlas / UNIVAC 的「每用户一个过渡区」是虚拟内存的雏形；分页机制随 multiprocessing 出现 |
| **1970s–1980** | VAX-11、x86 80386（1990 前后）把分页与保护位写进硬件；页表从软件链表走向多级页表 |
| **1990s** | TLB 成为标准部件；x86 加 PSE/PAE 支持更大物理内存 |
| **2000s 虚拟化** | 32 位 x86 的「影子页表」开销巨大 → Intel EPT / AMD NPT（二级页表）硬件化 |
| **2013–2019 大页与 THP** | 2MB/1GB 大页减少 TLB 缺失；透明大页在 Linux 上普及，也可能因「压缩/退填」导致延迟抖动 |
| **2019/2020 本书 RISC-V 版** | 虚拟内存一节改为 RV32/RV64 的 `satp`/`sv39` 页表格式，并配 `sfence.vma` 指令 |
| **2021–2026 RISC-V 特权规范** | 虚拟化扩展（H 扩展）把 `vsatp`/二级翻译（`hgatp`）标准化，呼应本书 5.6 的虚拟机讨论 |
| **2020s 内存配比变化** | 大内存机器让 TLB 覆盖率成为新问题；MLP/模型加载让「页错误 + 零页 + 就地分配」的开销被放大 |
| **2020s 持久化内存** | PMEM/非易失内存把「页既可以换出也可以直接持久化」的假设打通（Optane 之后热度回落，但语义仍在标准里） |

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **一致性只讲 MESI** | 本书只给侦听式协议；**目录式（directory）与 MOESI/MESIF** 才是多核商用与数据中心的主流方案，本书第 8 章只提 NUMA 而不展开 |
| 🔧 **缺失「内存墙/带宽」视角** | 本章讲的是延迟；2017 年之后数据中心的主要矛盾是带宽（HBM/Chiplet/跨域访存），Roofline 的斜率项主导 |
| 🔧 **TLB 的处理被简化为「很快」** | TLB 缺失一次可能要多走几级页表（真实机器上是多次访存），在指针密集程序上 TLB 缺失可以占到可观的执行时间 |
| **把 cache 与页表混为一谈** | 二者串联而非并列：**先 TLB 翻译、再 cache 查找**；把 TLB 当成「cache 的一种」会漏掉权限位与 ASID 的作用 |
| 🔧 **虚拟索引/物理标签未提** | 实际 L1 常做「虚拟索引 + 物理标签」，由此产生页别名问题，需页面着色缓解；本书 5.x 只用最简单的映射 |
| 🔧 **可靠存储只讲硬件冗余** | 5.5 之后缺少 2015 年后的实践：**ECC 内存是标配但仍有 row hammer / 微码/固件故障**这类新威胁维度 |
| 🔧 **页错误被讲成「慢但无害」** | 2.5 亿级页错误的（如 KSM、透明大页合并、swap 风暴）足以把整机拖垮；云上「页错误处理开销」是真实计费项 |
| 🔧 **未覆盖 2020 年代的安全性** | 页表权限位与 Meltdown 一类「推测执行绕过页表检查」的漏洞，说明**页表与推测执行必须一起设计**，本书完全没有这一层 |
