# 第 4 章 处理器（二）：流水线、冒险与异常

> **一句话**：流水线的本质是**「把组合逻辑切成 k 段并用寄存器隔开」**，代价是三类冒险——**结构冒险抢资源、数据冒险等结果、控制冒险等分支**；现代处理器的一切复杂度，都是为了压低这三类的代价。

## 核心精讲

> 以下均为**教学示意，不参与构建、不编译、不运行**。

### 为什么流水反而可能变慢：三类冒险

```asm
# 教学示意，不参与构建、不编译不运行
# ---------- 数据冒险：下一条指令要用上一条的结果 ----------
add  t0, t1, t2        # t0 在 EX 段末尾才形成
sub  t3, t0, t4        # 需要 t0 -> 必须转发（forwarding）
and  t5, t0, t6        # 更远的一拍，转发即可
xor  t7, t0, t8        # 再远一拍，转发即可
sw   t0, 0(a0)         # store 的数据来自最早那次运算

lw   t0, 0(a0)         # load 的结果在 MEM 段才出来
add  t1, t0, t2        # 只能停一个周期（load-use hazard），转发救不了

# ---------- 控制冒险：分支结果还没出来 ----------
    beq t0, t1, L      # 结果在 EX 段末尾出现
    addi t2, t2, 1     # 这一条可能不该执行
L:  addi t3, t3, 1

# ---------- 结构冒险（资源冲突，本书讲得最简） ----------
# 单存储器 + 单乘除单元时，「一条 lw 在 MEM 段」与「其它指令在 IF 段」抢同一个存储器
```

### 转发（forwarding）的四种路径

```text
EX  ->  EX   （下一条在 EX 段的指令立即用 EX 段结果）
EX  ->  MEM  （给访存/写回阶段的指令用）
MEM ->  EX   （给下一条 EX 段的指令用）
MEM ->  MEM  （store 需要）
规则要点：**只有「最近的那一份」才被转发**；同一寄存器同时有多份在流水线里时，靠「转发条件真值表」选最近的。

load-use 例外：load 的数据在 MEM 段末尾才可用，而下一条指令本来就进到 EX 段了，
             所以必须 stall 一个周期（或改用「加载立即使用」的多条策略：把 load 提前、把使用推后）。
```

### 分支预测：从「永远不跳」到两级自适应

```asm
# 教学示意，不参与构建、不编译不运行
# 循环里的分支 99% 命中「继续循环」；静态预测把这种行为「方向固定」
loop:
    addi t0, t0, -1
    bnez t0, loop       # 永远预测「跳转」-> 循环场景几乎零惩罚

# 硬件侧：BTB（分支目标缓冲）缓存目标地址，BHT/PHT 缓存方向历史
# 两级自适应预测器：用「全局/局部历史」查表得到预测位，错误时更新表
```

### 异常与流水线的冲突：精确异常

```text
理想：异常发生时，CPU 的状态必须等价于「那条指令单独执行时出错」
现实：后面几条指令可能已经算完并写回寄存器了
解决：把「写回」挪到提交（commit）时做，或清空流水线重来（flush）
代价：现代核用重排序缓冲（ROB）+ 重命名，正是为了在乱序执行下维持精确异常
```

### 循环展开：软件侧把冒险消掉（4.12）

```c
/* 教学示意，不参与构建、不编译不运行 */
/* 原版：单次迭代内 y += a*x，两条指令串行依赖 */
for (int i = 0; i < 100; i++)
    y[i] = y[i] + a * x[i];

/* 展开 4 次：多条 independent 的乘法可以并排发射，避开「等上一条乘法」的停顿 */
for (int i = 0; i < 100; i += 4) {
    float t0 = a * x[i+0];
    float t1 = a * x[i+1];
    float t2 = a * x[i+2];
    float t3 = a * x[i+3];
    y[i+0] += t0;  y[i+1] += t1;
    y[i+2] += t2;  y[i+3] += t3;
}
/* 本书用这个把矩阵乘的速度再翻一倍：唯一改动是不数地重复写了几行 C */
```

> 这里的分工值得记住：**编译器负责消掉数据冒险里的「无谓等待」，硬件负责处理消不掉的**（转发、预测、ROB）。

## 版本演进

| 阶段 | 与本章相关的关键变化 |
| --- | --- |
| **1964 IBM Stretch /  transistor 流水线概念** | 流水线的思想最早出现在大型机上 |
| **1981–1985 RISC-I / MIPS R2000** | 定长指令使「译码一段、执行一段」变得可行，流水线成为 RISC 的标志 |
| **1993–1995 Pentium / Pentium Pro** | 双流水线超标量 → 乱序执行 + 推测执行，控制冒险处理方式定型 |
| **1997–2000 Alpha 21264 / 21464** | 大窗口 + 精确异常，微结构复杂度达到峰值 |
| **2004 Pentium 4 Prescott / 2006 Core 2** | 流水线加深遭遇功耗墙 → 转向「能效优先」，长度不再一味加长 |
| **2011 Cortex-A8 / 2015 Core i7（本书 4.11 Real stuff）** | 本书用这两款产品讲「实际流水线有多长、分支预测多准」 |
| **2019/2020 本书 RISC-V 版** | 流水线例子改用 RV32I/RV64I；4.13 用 Verilog 描述流水线控制，把「控制」也纳入可综合的示例 |
| **2020s** | 开源超标量核（BOOM）、生成器（CHIPS Alliance）让「换一个微结构参数就重新综合」成为教学常规；**多发射 + 推测执行的复杂度从高校课程里下沉到开源项目** |
| **对照：x86 的微码化** | Pentium Pro 之后 x86 内部拆成微操作，用 RISC 式流水线执行；本章对所有「CISC 超标量」实现的描述同样适用 |

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **五段流水线的性能模型过于乐观** | 本书假设「IPC≈1」；真实超标量核靠多发射与乱序才拿到 IPC>1，五段模型无法解释乱序/重排序的收益 |
| 🔧 **结构冒险几乎不提** | 4.7 直接从数据冒险讲起；现实中**功能单元数量与端口争用**才是现代核的主要结构冒险（如浮点乘、除单元冲突） |
| 🔧 **分支预测只给「静态预测」** | 4.8 讲的是最简模型；2015 年后的商用核用 TAGE/ITTAGE 类多级自适应预测器，准确率 95%+，而本书的预测模型停留在「一位/两位计数器」 |
| **把流水线深度 ≈ 性能** | 4.14 列为谬误：深度增加会推高分支误预测的代价，2004–2006 年主频 wars 已经证明这一点 |
| 🔧 **精确异常的处理被一笔带过** | 4.9 只说「跳向量表」；流水线里的异常要「冲刷 + 回退 + 保持状态一致」，重排序缓冲是这一节缺失的关键概念 |
| 🔧 **未覆盖推测执行与 Spectre 的安全代价** | 本书讲预测执行而不谈** Spectre / 侧信道**——2020 年代最重大的架构级安全问题恰恰来自「推测执行必须可观测地不泄漏」 |
| **转发规则表当成全部** | 转发只解决「数据已产生」的情况；load-use 停顿、以及多周期乘法/除法产生的长延迟依赖，仍需其它机制 |
| 🔧 **缺能效维度** | 没有讨论「流水寄存器与重排序缓冲的功耗面积代价」，而这正是 2017 年后「不做那么深的流水」的真实理由 |
