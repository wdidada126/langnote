# 第 5 章 大容量和高速度：开发存储器层次结构（一）——Cache

> **一句话**：cache 的全部设计都在回答一个问题——**「用多少面积/功耗，把一个字节的平均访问时间从 200ns 压到 1ns 以内」**；而答案永远是同一个公式：`AMAT = 命中时间 + 缺失率 × 缺失惩罚`。

## 核心精讲

> 以下均为**教学示意，不参与构建、不编译、不运行**。

### 存储技术：为什么不能只做一种

```text
SRAM 单元（6 个晶体管）：两个反相器交叉耦合 + 两个访问管
  + 速度：与 CPU 同量级（1–2 个时钟周期访问）
  - 面积：一个 SRAM 单位约等于 6 个 DRAM 单位；容量做不大
DRAM 单元（1 个晶体管 + 1 个电容）
  + 密度高、便宜
  - 漏电与刷新（refresh）：电容会丢电荷，每若干毫秒要整行重写
  - 读后破坏（destructive read）：读出后要先回写（恢复）

因此：寄存器文件用触发器，L1/L2 用 SRAM，主存用 DRAM，磁盘/闪存更慢更便宜。
DRAM 的带宽（而非延迟）常常是数据中心的真正瓶颈——这决定了「带宽墙」一词在 2017 年后的流行。
```

### Cache 的组织：地址怎么被拆开

```text
地址 = tag | index | offset（字节偏移）
      （有些实现把 offset 写作 block offset / word select）

块 = 一行 = tag + valid(+dirty) + data

直接映射  ：块地址 % 组数 —— 每组只放一行
全相联    ：所有行都能放，替换要全局决策（贵）
组相联    ：块地址 % 组数 决定「这一组」，组内自由替换（n 路 = n 相联）

一个具体例子（32 位地址、32 位机器、块大小 16B、cache 大小 8KB、4 路组相联）：
  offset = log2(16B)      = 4 位
  组数    = 8KB/(4×16B)   = 128 组
  index   = log2(128)     = 7 位
  tag     = 32 - 4 - 7    = 21 位
```

> 计算步骤（本书 5.3 反复要求手算）：
> ① 拿到块地址（block address = 地址 / 块大小）；② `块地址 % 组数` 得到组；
> ③ 在该组里查 tag 是否命中且 valid；④ 用 offset 在 64 位宽的数据里取出需要的字节/字。

```asm
# 教学示意，不参与构建、不编译不运行
# 一条 lw 在 cache 命中时只花一个周期；一次缺失要把下面这些全做完：
#   1) tag 比较（可能多行同时比）-> 2) 未命中则替换选择 -> 3) 从下一级取整块
#   4) 把整块写进 cache -> 5) 再把需要的字交给执行阶段
lw   t0, 0(a0)      # a0 指向的地址若不在 cache 中 -> 走完整的缺失处理
```

### 平均访存时间（AMAT）

```
AMAT = 命中时间 + 缺失率 × 缺失惩罚
     = (命中时间) + (缺失率) × (缺失惩罚)
进一步展开成多级：
AMAT = L1命中 + L1缺失率 × (L2命中 + L2缺失率 × 主存惩罚)
```

```c
/* 教学示意，不参与构建、不编译不运行 */
/* 本书的经典算例：若 cache 缺失率 2%、主存访问 100ns、命中 1ns */
/* AMAT = 1 + 0.02 × 100 = 3ns；把缺失率降到 1% 只省 1ns */
/* 反例：命中时间从 1ns 涨到 2ns（更大的 cache）却可能让缺失惩罚变长 */
double amat(double hit_time, double miss_rate, double miss_penalty) {
    return hit_time + miss_rate * miss_penalty;
}
/* amat(1.0, 0.02, 100.0) = 3.0 ns */
```

> **最重要的一条工程直觉**：当缺失惩罚远大于命中时间时，**降低缺失率的空间比降低命中时间大得多**；
> 但两者存在权衡——把 cache 做大往往以提升命中时间为代价，这就是 5.15「谬误与陷阱」里「命中率提升一倍性能就翻倍」的反例。

### 提升命中率的四种手法

| 手法 | 说明 | 代价 |
| --- | --- | --- |
| 增大块大小 | 一次取回更多连续字节，空间局部性收益大 | 缺失惩罚上升；程序里若少顺序访问反而可能降低有效命中 |
| 提高相联度 | 减少冲突缺失（conflict miss，直接映射的主要痛点） | 查找延迟与面积上升 |
| 替换策略 | LRU 最直观；伪 LRU、随机、LRU 近似（在 L1 里被大量采用） | 硬件复杂度 |
| **多级 cache** | L2/L3 用更大容量换更低缺失率 | 面积与功耗；L1 命中时间必须保持很短 |

```c
/* 教学示意，不参与构建、不编译不运行 */
/* 5.14 的 cache 分块（blocking）：把 B 按块切分，让内层循环反复使用同一小块 */
void dgemm_blocked(float *C, float *A, float *B, int n, int bs) {
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j += bs)
            for (int k = 0; k < n; k += bs)
                for (int ii = i; ii < i+1;   ii++)
                for (int jj = j; jj < j+bs;  jj++) {
                    float sum = 0.0f;
                    for (int kk = k; kk < k+bs; kk++)
                        sum += A[ii*n+kk] * B[kk*n+jj];
                    C[ii*n+jj] += sum;   /* 复用次数上升，cache 未命中次数下降 */
                }
}
/* 结果：本书报告矩阵乘在这一步再快一倍——只改了循环结构，没改数学 */
```

### 写策略

```text
写穿透（write-through）：同时写 cache 与下一级；cache 里只放一份干净副本
                        - 一致性好、缺失处理简单；- 每次写都要访问内存，写带宽压力大
写回（write-back）    ：只在 cache 里改，换出时才写下一级；用 dirty 位标记
                        +  writes 被吸收，写带宽成本低；- 缺失时要先读回再写回（写分配策略）

写分配（write-allocate）  ：缺失时先把块取进来再改
不做写分配（no-write-allocate）：缺失时直接写下一级
典型组合：L1/L2 用 write-back + write-allocate；L2 到内存的写通常走 write-through 以简化一致性
```

### Cache 一致性：多核为什么要协议（5.10）

```asm
# 教学示意，不参与构建、不编译不运行
# 两个核缓存同一地址：核 0 写了，核 1 怎么看见？
# 侦听式（snooping）：每个核的 cache 监视总线，发现别人写自己缓存的行就失效或更新
    la   a0, shared_var
    li   t0, 1
    sw   t0, 0(a0)          # 核 0 写
    # 核 1 的 cache 通过总线侦听到这次写 -> 把自己那份置为 invalid（MESI 的 M->I）
    lw   t1, 0(a0)          # 核 1 重新读，必须去内存取
```

> MESI 的四种状态：**M**（已修改，独占可写）、**E**（独占干净）、**S**（共享干净）、**I**（失效）。
> 读缺失时按 M/E/S/I 决定取数与状态迁移；写缺失要先拿独占权（**RFO / read-for-ownership**），这在多核里是写带宽的主要消耗。

## 版本演进

| 阶段 | 与本章相关的关键变化 |
| --- | --- |
| **1960s–1970s** | 从「手工管理过渡区」到 IBM System/360 Model 67 的 cache 原型；cache 一度被视为「需要小心设计的黑魔法」 |
| **1980–1990** | 直接的映射 cache 进入微处理器；VAX-11/780 的 cache 是经典案例 |
| **1993 Pentium / 1995 Pentium Pro** | 两级 cache 成为 x86 标准；L2 从板级移到片内（Pentium Pro 首创） |
| **2000s** | 多核带来**一致性问题**；MESI 及其变体从研究进入商用实现 |
| **2011 Cortex-A8 / 2015 Core i7（本书 5.13 Real stuff）** | 本书的 Real stuff：Cortex-A8 的 8 路 L1，Core i7 的 32KB L1 + 256KB L2 + 共享 L3 |
| **2011–2017 3D XPoint / 非易失内存** | 试图缩短 DRAM 与 SSD 的鸿沟（Optane 是最后一款商用产品，2023 年退场） |
| **2019/2020 本书 RISC-V 版** | 5.x 全部围绕 RV32I 的字节寻址重新描述；cache 控制器的 Verilog 示例与可运行的开源核配合 |
| **2020s** | 片上存储成为 AI 芯片的第一设计约束：**SRAM 电容与带宽**决定大模型推理吞吐；chiplet 与 HBM 把「内存墙」推到封装层面 |
| **2020s 一致性扩展** | 本书只讲侦听式 MESI；目录式（directory）与 MOESI 在商用核与数据中心里更常见（见 07、08 章） |

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **只讲 MESI，不讲目录/MOESI** | 5.10 只给侦听式协议；数据中心规模的核数下**侦听会Broadcast 风暴**，实用方案是 directory-based（MOESI/MESIF），本书第 8 章只提一句「NUMA」而不展开 |
| 🔧 **「命中率提升 = 性能提升」的直觉被过度强化** | 5.15 列为谬误；命中率与命中时间是此消彼长的关系，且**计分卡的 cache 缺失次数**才是与真实工作量直接相关的量 |
| 🔧 **SRAM/DRAM 的数字停留在 2015 年** | 书中给的访问时间（DRAM ~100ns、L1 ~1ns）方向没错，但 2020 年代 HBM/DDR5/3D 堆叠让带宽与延迟的关系再次变化 |
| 🔧 **未覆盖「内存墙」与带宽瓶颈** | 本章讲的是延迟模型；2017 年后的主要矛盾是**带宽**（HBM/倍距），Roofline 模型里的斜率项才是主导 |
| **把「块」和「页」当成一回事** | 块是 cache 与内存之间的单位，页是虚拟内存的单位，通常页远大于块；混用会导致 TLB 与 cache 的关系讲不清（见 07 章） |
| 🔧 **写策略只给两种极端** | 真实实现还有写合并（write combining）、写缓冲区（store buffer）与「部分写」（byte-enable 与掩码写入）等中间形态 |
| 🔧 **未讨论虚拟索引 + 物理标签的坑** | 本书 5.x 用简单映射；实际 L1 常用「虚拟索引、物理标签」，带来别名（aliasing）问题，需要页面着色（page coloring）缓解 |
| 🔧 **cache 一致性一节缺少目录式与缓存一致性的实测** | 本节缺少「多核跑同一变量时写的代价」的可操作实验；可用开源核 + 一致性单元自行搭建（见 08 章） |
