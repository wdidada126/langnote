> 对应《Java并发编程实战》第 12 章。把"概率撞 bug"升级为"必然复现 + 形式化验证"的现代工具箱。

## 二、核心精讲

### 2.1 从"手写计时循环"到"工具化"
- 第 12 章已指出五类性能陷阱（GC/动态编译/不真实采样/不真实竞争/死代码消除）。现代统一答案是 **JMH**。
- 安全性测试的本质是**统计**：跑够久、交错够多才有置信度。但纯随机太慢 → 用**系统性交错探索**。

### 2.2 jcstress（JVM 内存模型模糊测试）
- OpenJDK 官方，**专门验证** happens-before / volatile / final / 原子类的真实行为。内置 `@Actor`/`@Outcome`/`@Ref` 注解描述"期望哪些结果、哪些结果算 bug"。
- 它会在**多架构（x86-TSO / ARM-弱内存）**上跑交错，把"x86 跑过、ARM 翻车"暴露出来（见 16 章）。

### 2.3 Lincheck（Kotlin 算法线性化测试）
- JetBrains，**模型检查式**并发算法测试：你写"顺序版正确实现"，Lincheck 自动探索交错并验证并发版是否满足**线性化性（linearizability）**。
- 思想可迁移 Java：把"并发结构的每步操作"和"顺序版"对照，自动找反例。

### 2.4 确定性调度 / 记录回放
- **`rr`**（Mozilla, 7.9k★）：给任意多线程程序录屏，回放**逐指令确定**，复现竞态的终极武器（C/C++/Rust；Java 层用字节码插桩近似）。
- **`Microsoft/Coyote`**（2.7k★）：系统化"调度探索"找出死锁/活锁/竞态并**给出确定性复现**——直接升级第 12 章的"注入 yield"思路。

### 2.5 模型检查与形式化
- **`herd7` + `diy7`**（Cambridge）：用 `.litmus` 文件形式化描述弱内存交错，Linux 内核 memory model 同款；Java/C/C++/Rust 通吃。
- **TLA+**（Lamport）：用形式化规约验证并发协议（死锁/活锁），工业界（AWS）用于分布式并发。

## 三、版本演进

- **2006 本书第 12 章**：手写 `PutTakeTest` + `yield` 注入。
- **JDK 8 JMH**：微基准标准化。
- **JDK 9 JFR 开源**：运行时观测平民化。
- **2014+ jcstress / 2018+ Lincheck / 2020+ Coyote**：系统性/模型检查式并发测试成熟。

## 六、常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "单测绿 = 并发对" | 必须用 jcstress/交织测试 |
| 2 | "自己写计时循环" | JMH，避开五类陷阱 |
| 3 | "x86 跑过就稳" | ARM 弱内存会翻车；多架构 CI |
| 4 | "撞不到 bug 就是没有" | 用确定性调度（Coyote/rr）主动制造交错 |
