## 二、核心精讲

### 2.1 锁的劣势（15.1）
- 锁是**悲观**的：假设会冲突，先独占再干。代价：等待线程被挂起/唤醒（上下文切换 μs 级）、优先级反转、死锁、饥饿。
- 高争用下，锁的吞吐量随线程数**先升后崩**（Amdahl + 切换开销，见 11 章）。

### 2.2 CAS（15.2）
- 语义：`CAS(addr, expect, new)` —— 若 `*addr == expect` 则写入 `new` 并返回成功，否则失败。**硬件级单条原子指令**（x86 `lock cmpxchg`）。
- 非阻塞：线程**不挂起**，失败就重试（自旋），不触发上下文切换 → 高争用下仍维持吞吐。
- JVM 通过 `Unsafe.compareAndSwapInt` 暴露；JDK 9+ 由 `VarHandle` 正式承接（JEP 193）。

### 2.3 原子变量类（15.3）
- `AtomicInteger/AtomicLong/AtomicReference/AtomicBoolean` + 数组版 + 字段更新器 `AtomicReferenceFieldUpdater`。
- JDK 8 新增 **`LongAdder`/`DoubleAdder`**——热点计数用**分段累加**，把单点 CAS 竞争打散（见 concepts/LongAdder）；高争用下远快于 `AtomicLong`。
- JDK 12+ **`Atomic` 类新增 `updateAndGet`/`accumulateAndGet` 等无分配 lambda 形式**；`VarHandle` 让自定义类也能有等价语义。

### 2.4 非阻塞算法（15.4）
- **非阻塞（non-blocking）**：某线程失败不会影响别人前进（无死锁/优先级反转）。
- **无锁（lock-free）**：总有一个线程能前进（无死锁/饥饿）。
- **等待无关（wait-free）**：每个线程都**有界步数**内完成（最强，最难写）。
- 经典实现：Treiber 栈（`AtomicReference<Node>` + CAS 头）、Michael-Scott 队列（见 concepts/Michael-Scott）、无锁计数器。
- 写法模板：`do { old = get(); nv = compute(old); } while (!CAS(old, nv));`

### 2.5 风险（15.5）
- **ABA**：值从 A→B→A，CAS 误以为没变。解法 `AtomicStampedReference`（版本号）/ `AtomicMarkableReference`。
- **活锁**：一直 CAS 失败一直重试，谁都过不去（加退避可缓解）。
- **正确性极难**：非阻塞算法是并发里**最容易写错**的一块，务必验证 + 用 jcstress 测。

## 三、版本演进

- **JDK 5**：`Atomic*` 类 + `Unsafe.CAS` 引入，非阻塞算法在 Java 落地。
- **JDK 8**：**`LongAdder`/`LongAccumulator`**（分段累加，并发计数神器）；`ConcurrentHashMap` 重写用 CAS + 桶级锁（见 concepts/ConcurrentHashMap）。
- **JDK 9**：**`VarHandle`**（JEP 193）正式替代 `Unsafe` 的字段 CAS/volatile 操作，提供 5 档内存语义（plain/opaque/acquire/release/volatile）。
- **JDK 12**：`Atomic` 类增强（无分配的函数式更新）。
- **JDK 21–25**：**`Unsafe` 进入废弃通道**（JEP 471/498），`memorySegment`/`VarHandle` 是未来；`Atomic` 内部已逐步迁离 `Unsafe`。

## 四、经典论文 / 原始文献

- **Herlihy, "Wait-Free Synchronization" (PODC 1991, Dijkstra 奖)**——**里程碑**：证明某些操作**无法用锁实现但可用 CAS 等待无关实现**；"共识数（consensus number）"层级。
- **Herlihy & Shavit, "The Art of Multiprocessor Programming"**——非阻塞算法的标准教材，Treiber 栈 / MS 队列 / 各种 wait-free 结构。
- **Michael & Scott, "Simple, Fast, and Practical Non-Blocking and Blocking Concurrent Queues" (PODC 1996)**——MS 队列（见 concepts）。
- **Doug Lea, J.U.C 原子包 + AQS 论文 (2004)**——Java 非阻塞基础设施的工程化。
- **Lamport, "Specifying Concurrent Systems with Sequential Consistency" (1993)**——无锁正确性的理论基底。

## 五、近年研究与工业界前沿

### 5.1 硬件原语的进化
- **`CAS2`/DCAS** 未普及；x86 引入 **`cmpxchg16b`**（128 位 CAS）支撑 `AtomicReference` 双字更新。
- **ARM/Linux 上 `LSE` 原子指令集**（ARMv8.1）让 CAS 不再靠 LL/SC 重试循环，Java 在 ARM 服务器上非阻塞性能大幅提升。
- **TSX / RTM**（Intel 事务内存）曾想给锁"隐式事务"，因 bug 被**废弃**——非阻塞路线反而更稳。

### 5.2 无锁数据结构的工业爆发
| 项目 | Stars | 关联 |
| --- | --- | --- |
| **JCTools/JCTools** | 3.9k | SPSC/MPSC/MPMC/SPSC 无锁队列，消息中间件标配 |
| **LMAX-Exchange/disruptor** | 18.5k | 无锁环形缓冲（Sequence + CAS），1M+ ops/s |
| **ben-manes/caffeine** | 17.9k | `ConcurrentHashMap` + `LongAdder` + 无锁读窗口，缓存教科书 |
| **crossbeam-rs/crossbeam** | 8.6k | Rust 无锁队列/MPMC/epoch GC，MS 队列的 Rust 实现 |
| **Rayon (rayon-rs/rayon)** | 12k | 基于 work-stealing 的无锁并行迭代器 |
| **facebook/folly** | 30.5k | `AtomicHashArray`、无锁结构、hazard pointer 实现 |

### 5.3 ABA 与现代内存回收
- **Hazard Pointers**（Michael, 2004）——无锁结构安全回收内存的工业标准，被 folly / crossbeam 采用。
- **Epoch-based reclamation**（Fraser）/ **Interval-based**（Wolper & Korland）——Rust `crossbeam` 的 `epoch` 模块即此。
- **Quiescent-State-Based Reclamation (QSBR)**——Linux 内核 RCU 思路，高性能无锁系统首选。

### 5.4 测试工具
- **`openjdk/jcstress`**（2.1k★）——**专门模糊测试**非阻塞算法在弱内存模型下的正确性（见 16 章）。
- **`vmlens`**——检测原子类误用、丢失更新。

## 六、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "无锁一定比锁快" | 低争用下 CAS 自旋开销反大于锁；只有**高争用热点**才显著胜出 |
| 2 | "CAS 不会有 ABA 问题" | 涉及**指针/引用复用**必有 ABA；用 `AtomicStampedReference` |
| 3 | "自己写个无锁 stack 就行" | 无锁算法极易错；用 J.U.C 现成的，或用 jcstress 验证 |
| 4 | "热点计数用 `AtomicLong`" | 高争用用 **`LongAdder`**（分段），避免全线程抢同一缓存行 |
| 5 | "直接用 `Unsafe`" | JDK 21+ `Unsafe` 被废弃；改用 `VarHandle` |
| 6 | "`volatile` 可以替代 CAS 做计数" | `volatile++` 非原子（读-改-写），必须用 `Atomic*` 或 `LongAdder` |
