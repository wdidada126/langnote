# 03 结构化、文本与物联网数据（原书第 6–8 章）

> 对应真实目录：第 6 章 结构化数据 / 第 7 章 文本数据 / 第 8 章 模拟/物联网数据。
> ⚠️ 章题来自豆瓣著录的真实目录；**章内小节与工程细节为依据 Inmon 公开著述及现代湖仓实践的重建**，非书中原文。标注 🔧 处为原书大概率没有、按 2026 年现状补的工程内容。

## 核心概念速览（中英对照）

- **结构化数据** — structured data：可完整映射到关系表、schema 先行的数据（业务库、事务流水）
- **文本数据** — text data：语义内嵌于自然语言字符串的数据（文档、邮件、日志文本）
- **模拟数据** — analog data：连续物理量（温度、振动、电压）的数据化形态
- **物联网数据** — IoT data：由传感器/设备持续产生的大规模事件流数据
- **实体抽取** — entity extraction：从文本中解析出结构化的实体、属性、关系 ⚠️ 术语按常规回译
- **事件模型** — event model：把 IoT 流落地为"实体 + 时间 + 度量"的窄事实结构 ⚠️ 教学命名
- **价值密度** — value density：单位字节中可用于决策的信息量；IoT 数据的典型特征是低价值密度
- **时序数据** — time-series data：以时间为主轴的度量序列，IoT 的常见近生产形态
- **CDC / 变更数据捕获** — change data capture：从结构化源系统连续捕获增删改的工程手段 🔧
- **参照完整性** — referential integrity：跨类数据汇入供应链时保持业务键一致性的约束

## 核心精讲

### 1. 结构化数据通道（第 6 章 ⚠️ 重建）

Inmon 处理结构化数据不需要发明新东西——那是他 1992 年以来的标准作业：

- **抽取**：源库按业务键与时间戳取增量或全量；
- **staging**：类型统一、码值映射、去重、参照完整性预检（01 章的质检口）；
- **集成装载**：写入基础数据层（近生产），再按口径生成生产层；
- 湖仓只改变了**底座**：仓库表换成对象存储上的表格式表。工程后果（🔧 补充，书中未必提）：小文件与 compaction、并发提交的冲突处理成为新工序——见 [../Apache_Hudi_Definitive_Guide/06-维护与优化Hudi表.md](../Apache_Hudi_Definitive_Guide/06-维护与优化Hudi表.md)。

### 2. 文本数据通道（第 7 章 ⚠️ 重建）

第 7 章在本书分类学里地位微妙：它是 Inmon 立场**松动最多**的一类。

```
合同/邮件/工单 ──原样──→ raw 层（不可变封存，供未来重解析）
      │
      ▼ 解析工序：版面分析 → 分句/分词 → 实体与关系抽取 → 置信度过滤
结构化事实（甲乙金额日期…）──→ 近生产层 → 汇入与第 6 章同一条供应链
      │
      └─(🔧 现代旁路)→ 全文索引 / embedding → RAG/检索消费线
```
（教学示意，不参与构建）

要点：

- **原文是证据，解析产物是数据**：raw 层封存原文保证"重解析权"（模型换代后旧成果可重做，呼应 01 章可重做性）；
- Inmon 式追问（⚠️ 推定）：解析置信度如何进入供应链质检？错误解析与错误类型转换在架构上同罪；
- **对撞点**：2023 年后主流（尤其 LLM 时代）主张"文本不必先结构化，检索增强直接消费"。Inmon 会反驳：无质检的直读使每个消费者各错各的；工程现实是两条线并存，前者适合决策供数、后者适合语义检索 🔧。此张力在副标题"data mesh 基石"语境下更尖锐（11 章）。

### 3. 模拟/物联网数据通道（第 8 章 ⚠️ 重建）

- **特征三连**：量大（单厂日产 TB 级不稀奇）、密（毫秒采样）、值低（99.9% 样本永不入报表）；
- 入库路径：设备原始流 → 解码（协议/量程/单位）→ 时间对齐（时钟漂移、乱序）→ 事件化（窄事实）→ 异常过滤/聚合 → 近生产/生产层；
- **Inmon 式提醒**（⚠️ 推定）：IoT 最容易诱导"直接看曲线"的降层直读；正确做法是把"当前值/告警态"物化为生产层属性，曲线留近生产层按需取；
- 设备主数据（台账、测点命名、量程表）是这类数据的参照骨架——**没有对齐的设备台账，遥测数据不可集成**，这把 15 章"软数据"与 17 章"目录"都提前牵了进来。

### 4. 三章合读：类型—层次对应表 ⚠️（教学归纳）

| 类型 | raw 层存什么 | 近生产层产物 | 生产层常见形态 |
| --- | --- | --- | --- |
| 结构化 | 快照/日志原样 | 清洗集成的原子事实 | 主题模型表/指标 |
| 文本 | 文档原件 | 抽取出的结构化事实、索引 🔧 | 实体/关系宽表、分类汇总 |
| 模拟/IoT | 原始帧/码流 | 对齐解码后的事件时序 | 聚合统计、告警态、设备属性 |

该表是本笔记对三章的压缩，用于 07 章"层次"与 12 章"对照"的桥梁。

### 5. 三类数据接入检查单（教学工具 ⚠️）

把三章的可判定要点浓缩为接入新数据源时的自查（对照原书若有出入，以原书为准）：

**结构化源接入**
- [ ] 抽取窗口与源系统备份窗口是否解耦？（不要让湖仓调度绑架生产库）
- [ ] 业务键与时间戳字段可辨识吗？不可辨识先补源端或映射表；
- [ ] 码值/字典拿到最新版了吗？（10 章描述性数据）

**文本/软数据接入**
- [ ] 原文是否原样入 raw 且不可变？（重解析权的物理保证）
- [ ] 抽取产物是否带置信度与回指原文的指针？
- [ ] 解析器版本是否登记？换版后能否圈定受影响产物？

**IoT 源接入**
- [ ] 设备台账/测点字典先于遥测接入对齐了吗？
- [ ] 时钟漂移与乱序窗口的容忍度定义了吗？
- [ ] 采样率与保留策略分层设定？（raw 全率长存、近生产降率）

三张单的共同点：**每一条都服务于"可溯源/可重做/口径一致"三要素（01 章）**——类型不同，质检项不同，不变量相同。

## 常见误区

| 误区 | Reality |
| --- | --- |
| "非结构化=不用 schema" | 近生产层必须给抽取产物显式 schema，否则只是把混乱推迟到查询端 |
| "IoT 数据太廉价，不值得进供应链" | 价值密度低≠无价值：聚合与异常检测的生产层价值恰恰建立在 raw 全存之上 |
| "文本解析一次就够" | 解析器/模型会换代；raw 封存原文=保留重做权（01 章可重做性的文本版） |
| "三条通道 = 三套架构" | 通道分头、供应链合一：到近生产层就共用同一套质检与集成工序 |
