## 核心概念速览（中英对照）

- **移动语义** — move semantics：窃取源对象内部资源；"源对象此后不可用"只是**实现者约定**，不是语言强制
- **万能引用** — forwarding/ universal reference `T&&`：模板参数与 `auto&&` 两处语境中可绑左/右值的引用
- **引用折叠** — reference collapsing：`& && → &`，万能引用与 forward 的语法底座
- **完美转发** — perfect forwarding：`std::forward<T>` = "按推导结果决定还原左/右值"的条件 static_cast
- **奇异递归模板模式** — CRTP：基类以派生类为模板参数，编译期多态零虚表；`enable_shared_from_this` 即 CRTP
- **类型萃取** — type traits：`is_same/enable_if/if constexpr` 一族的编译期反射
- **void_t 探测** — detection idiom：`void_t<decltype(expr)>` 让"有没有这个成员"成为可重载类型
- **指向实现的指针** — PIMPL：把私有成员从头部文件中拿走；sizeof 恒定；代价一次堆分配+指针追逐
- **不抛保证与移动回退** — noexcept / move_if_noexcept：移动构造不 noexcept，vector 扩容宁拷贝不移动
- **拷贝-交换** — Copy-and-Swap：值参拷贝 + noexcept swap，自赋值与强异常安全一石二鸟
- **内省排序** — introsort：快排递归超 2·log n 层切堆排，小区间切插入排序——std::sort 不是纯快排
- **闭包类型** — closure type：lambda = 编译器生成的匿名函数对象，捕获=成员，`()`=operator()
- **类型擦除** — type erasure：std::function 用 SBO 缓冲+虚调用包装任意可调用物，代价见实测
- **const 重载** — const overloading：隐式对象参数的 cv 限定参与重载决议，返回 `T&` vs `const T&`

## 机制：五条主线

### 1. 值类别流水线：move → forward → 完美转发

站文从源码切入：`std::move(x)` 恒等于 `static_cast<T&&>(x)`——**它不移动任何东西**，
只是把左值钉成右值引用以便选中移动构造/赋值。是否真移动取决于**你写的移动构造做了什么**；
站文演示了"移动构造内部仍拷贝"的反例：move 后源对象照常用。
这推翻了八股"std::move 之后不可再使用"的绝对化表述（正确表述：只能赋回或析构，除非实现者承诺）。
万能引用只有两个合法出生地（模板推导参数 `T&&`、`auto&&`），折叠表四行；
`std::forward<T>(u)` 是**条件**转换：T 推导为左值引用则还原左值，否则转右值——
"move 是无条件右转，forward 是按需还原"，两者的分工一句话钉死。
转发失效三案（站文列二）：默认参数、未转发而直接传具名 `T&&` 变量、嵌套模板断链。

### 2. 可调用物三形态与它们的账单

- **lambda**：`cpp-lambda-impl` 给出闭包展开——捕获列表变成员变量（按值捕获拷贝进来、
  按引用捕获存引用包装），函数体变 `operator()`，默认 const；空 lambda sizeof==1（C++20 起可为 0 ⚠️ 站文未及）。
- **std::function**：类型擦除容器，小对象（libstdc++：可nothrow复制+尺寸适配）存内联缓冲，
  否则堆分配；调用=间接调用+可能虚分派，**编译器无法内联**。`cpp-function-cost` 篇翻译并实测了
  那篇著名的 ns 级基准：创建/调用 function 比直接 lambda 慢一个量级，但绝对值纳秒级——
  结论与站方一致："开销真存在，恐慌不必要，热点回调才要换模板/函数指针"。
- **std::invoke**：统一"成员函数指针+对象"与普通函数的调用语法，是 `bind/引用包装器/algorithm` 的底层胶水。

### 3. 多态的两条路：虚表（动）vs CRTP（静）

CRTP 篇：`struct Derived : Base<Derived>`，基类 `static_cast<Derived&>(*this).impl()` 编译期分派——
零间接调用、可完全内联，代价是基类无法存指针（不是类型）、代码膨胀、派生类接口不被强制。
相邻两篇正好演示"替代继承"的第三种方案：`variant + visit`（07 章经验板块）——
**运行时多态三选一：虚表（开放层次）→ variant（封闭集合）→ CRTP（框架静态骨架）**。
const 重载篇给出底层视角：成员函数=首参为 `X*`/`const X*` 的自由函数，
cv 限定参与重载所以 `const string& s = str; s[0]` 调到 const 版——为 04 与 10 的 string COW 篇牵线。

### 4. 异常安全的两件武器

`noexcept` 篇：vector 扩容用 `move_if_noexcept`——元素的移动构造**只有标了 noexcept（或不可拷贝）
才敢用**，否则回退拷贝（移动抛异常=元素半搬走的中间态无法回滚）。所以标准姿势：
移动构造 `noexcept`，或 C++11 前的"swap 法"。
Copy-and-Swap 篇：`A& operator=(A other) noexcept { swap(*this, other); return *this; }`——
拷贝发生在提交前，天然强保证+自赋值安全；**站文未提的现代反驳**（本目录补）：值参版对
自赋值和"源即将报废"场景各多付一次拷贝，C++11 后的四步赋值（copy-and-move 或判等+move）
反而更常用——异常安全与性能的经典权衡，两说并存才是现状。

### 5. 模板即接口：定义必须可见

`cpp-template-define-header` 篇：模板是**按实例化点生成的蓝图**，包含模型下定义不可见=链接期
undefined reference；出路三条：定义进头文件（默认）、显式实例化、（module 时代）BMI 导出。
`type_traits`/`void_t` 两篇是 C++11–17 元编程工具箱的正经入门：`enable_if_t` 约束重载、
`void_t<decltype(x.f())>` 探测成员、`if constexpr`（外链 05 折叠表达式篇）终结标签分发。
`cpp-sort` 篇走读 libstdc++：区间>16 用快排（median-of-3 pivot），深度超 2·log2(n) 切堆排保底，
<16 切插入排序——"std::sort 是快排"的八股到此为止， introsort+小区间优化才是答案。

## 最新演进与工业实践

- **C++17/20/23 修正清单**：`if constexpr`（17）取代大部分 enable_if；CTAD（17）省模板实参；
  `[[nodiscard]]` 给工厂函数；C++20 concepts 取代 SFINAE 惯用法（报错可读性质变）；
  C++23 **deducing this（P0847R6，实测 302 ✅）**让 CRTP 手写样板退役（05 章实测）；
  move/forward 双件套至今无标准替代。
- **工业仓库对照**：folly 的 `Function`（更紧的 SBO）、`frozen`、absl::FunctionRef（非持有视图版
  function，回调参数的现代默认）；range-v3 把"转发+萃取"推成视图管道；fmt 的 `FMT_CONSTEXPR`
  分派演示了 type_traits 的工业级用法。CRTP 工业样本：std::enable_shared_from_this、
  fmt::format_string、Seastar 的 future/promise 链。
- **现代重估**：板块两篇"new 判空/拷贝构造为何带引用"是纯面试体操，工程价值≈0，
  但 const 重载、move_if_noexcept、function 开销三篇是真·日常决策依据。

## 实测样例（已实测 g++ 15.2）

复现 `cpp-function-cost` 的账单——5000 万次调用，std::function vs 直接 functor（-O2）：

```cpp
#include <functional>
#include <chrono>
#include <cstdio>
struct Add { int operator()(int a, int b) const { return a + b; } };
int main(){
  const int N = 50'000'000; int s = 0;
  auto t0 = std::chrono::steady_clock::now();
  std::function<int(int,int)> fn = Add{};
  for (int i = 0; i < N; i++) s += fn(1, 2);
  auto t1 = std::chrono::steady_clock::now();
  s = 0;
  for (int i = 0; i < N; i++) s += Add{}(1, 2);
  auto t2 = std::chrono::steady_clock::now();
  printf("std::function %.2fs  direct functor %.2fs (s=%d)\n",
         std::chrono::duration<double>(t1-t0).count(),
         std::chrono::duration<double>(t2-t1).count(), s);
}
```

```
$ g++ -O2 -std=c++17 s04.cpp && ./s04
std::function 0.05s  direct functor 0.00s (s=150000000)
```

解读：直接 functor 被内联成 `s += 3` 循环（≈0），std::function 的间接调用挡住一切优化——
"量级差"在 -O2 下被放大得比站文引用的基准更夸张，**结论方向一致**：热循环里的回调用
模板参数/函数指针，别用擦除类型。
