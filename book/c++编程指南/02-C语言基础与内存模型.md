# 02 C 语言基础——为 C++ 读者准备的内存地基

> 对应站点板块：主要内容第 2 板块 `/docs/c-basic/`（6 篇，2026-09-26 实抓 ✅）。
> 板块定位（站方一句话）："C 语言核心概念和基础语法，为学习 C++ 打下坚实基础"。
> 6 篇里没有一篇讲语法入门——全是**内存主题**：虚拟内存与 malloc、栈与堆、memcpy、
> C 实现面向对象、C 实现动态字符串、C 实现 future。**板块的真实名字应该是"C 语言内存模型"**。

## 核心概念速览（中英对照）

- **程序断点** — program break (brk)：堆区向高地址生长的边界，小块 malloc 靠推它拿内存
- **mmap 阈值** — mmap threshold（默认 128KB）：大块分配绕过堆管理器和匿名映射的分界
- **释放后复用** — free-then-reuse：free 的内存回 freelist，同一地址会被后续 malloc 命中
- **栈帧与堆块** — stack frame vs heap block：函数生命周期 O(1) 弹栈 vs 手工/碎片化的堆管理
- **字节复制到页复制** — memcpy implementation ladder：8B 字复制→SSE/AVX→大块的页表级技巧
- **重叠未定义** — overlapping copy is UB：memcpy 不保序读写，memmove 才有临时缓冲语义
- **C 式继承** — struct-prefix "inheritance"：首成员嵌入"基类"结构体 + void* 参数模拟 this
- **容器反查** — container_of 宏：由成员地址反推宿主结构体地址，Linux 链表的地基
- **动态字符串** — SDS (simple dynamic string)：len/alloc/free 三字段 + 预分配，均摊 O(1) 追加
- **原子状态机** — atomic CAS state machine：跨线程任务结果的无锁读 + 锁慢路径

## 动机：C++ 教程为什么要开一个 C 板块

站方视角：训练营学员"基础差"，C 是内存观的前置课。工程视角更实际——
C++ 工程师每天在三层夹缝里干活：**语言层（RAII）、运行时层（malloc/new）、系统层（虚拟内存）**，
后两层全是 C 的语义。6 篇文章里 4 篇直接服务这三层的对齐：`c-malloc` 讲"你 new 的内存从哪来"、
`heap-stack-memory` 讲"为什么成员放栈上更快"、`memcpy` 讲"标准库函数内部长什么样"、
`oop-in-c` 讲"C++ 面向对象在机器上本来就是结构体首成员+隐藏指针"。

## 机制：六篇各自的核心论证

### 虚拟内存与 malloc（`c-malloc`，板块最长篇）

站文图解 malloc 全流程，可核实的机制要点：
`malloc(n)` 小块走 **brk 推程序断点**、大块（>128KB 默认阈值）走 **mmap 匿名映射**；
free 并不归还内核，而是挂回 bins 等待复用——因此**"两次 malloc 同一指针"是合法现象**，
站文用它演示 double-free/释放后读（UAF）的攻击面。虚拟地址→物理页的翻译层
（页表/TLB）解释了为什么"malloc 一大块不碰它就不占物理内存"（惰性缺页）。
这些与 09 章 `build-debug/load-virtual` 篇、10 章 OS 板块 `memory-manager` 篇三处互证，
是站内少数"同一主题多板块重复建设"的例子。

### 栈内存 vs 堆内存（`heap-stack-memory`）

站文结论清单：栈分配=移动栈指针（纳秒级）、自动释放、连续性好缓存友好；堆=malloc 元数据开销、
碎片、需显式管理、可跨函数生命周期。**关键权衡被点破**："栈快"不是因为指令少，而是
(1) 栈内存大概率常驻 L1/L2、(2) 无分配器锁与搜索、(3) 释放 O(1) 且批量（多帧一次弹）。
反面约束：栈大小固定（Linux 默认 8MB，线程另设），大对象/可变长对象必须上堆——
这一条直通 04/05 章的 vector 实现与 07 章内存池。

### memcpy 原理（`memcpy`）

"从字节复制到页复制的优化"：小尺寸按字节→按 8B 字（寄存器宽度）→SSE/AVX 128/256 位搬运；
对齐检查决定能否走 SIMD；大尺寸考虑非临时存储（`movntdq` 跳缓存）与页复制。
站文最有价值的提醒：**memcpy 重叠是 UB**，glibc 的 memcpy 方向是实现私有决定，
同一份代码在不同 libc/ISA 上重叠拷贝结果不同——所以有 memmove（内部按方向选正/倒序复制）。

### C 实现面向对象（`oop-in-c`）

用 `struct Base { int v; void (*print)(struct Base*); }` + 函数指针表手写"虚表"，
派生=首成员嵌入+覆盖函数指针；this=首参数指针。这一篇是把 03 章引用/成员函数底层
（`obj.f(&obj)` 隐式对象参数，站文 `cpp-const-overload` 篇同款论证）钉死在 C 层的演练。
工业对应物：Linux kernel `container_of`/`list_head`、COM IUnknown、GLib GObject。

### C 实现动态字符串（`c-dynamic-string`）

手写 SDS：`{len, alloc, buf[]}`；追加时若 `free_space` 不足按 1:1（<1MB）或 1:1.5（≥1MB）
预分配 → **均摊 O(1)**；`sdscpy` 一次分配消灭 strcpy+malloc 两次拷贝。这正是 Redis SDS 的
论文级复刻，站文作者明说参考 Redis。它同时解释了 05 章 string_view 的另一半：
既然拷贝可以靠"预分配+一次复制"摊平，**视图类型省的就是那次复制本身**。

### C 实现 C++ 的 future（`c-future`）

跨线程任务调度：结果槽 + `_Atomic int state`（PENDING/READY/DONE 状态机），
读方 fast path 用 CAS 抢 DONE 态防重复取值，慢路径 mutex+cond 阻塞等待。
板块的收官篇把前 5 篇（内存、原子、锁、回调结构体）全用上了——这是站内少数
"板块内有课程大纲设计"的证据。

## 相邻概念对比

| 组 | A | B | 判据 |
| --- | --- | --- | --- |
| 分配 | brk/小 chunk | mmap/大 chunk | 128KB 阈值；归还是否回内核（MALLOC_TRIM） |
| 复制 | memcpy | memmove | 源目标是否重叠；重叠必 memmove |
| 生命周期 | 栈对象 | 堆对象 | 是否跨函数返回存活；大小是否编译期可定 |
| 字符串 | C 定长 char[] | SDS/string_view | 谁持有长度；谁负责终止符 |

## 最新演进与工业实践

- **C 标准侧**：C23 收了 `nullptr`、`typeof`、`constexpr`——本站"用 C 讲 C++ 概念"的写法在
  C23 里部分获得亲儿子语法；但 128KB mmap 阈值、freelist 复用等 glibc malloc 行为仍是实现细节。
- **C++ 层对应物**：`std::bit_cast`（C++20）把"POD 才能 memcpy"的教训变成类型安全的按位转换；
  `std::span` 把"指针+长度"视图推广到一切连续容器（SDS 的通用化）；
  `pmr::monotonic_buffer_resource`（C++17）是"栈式大分配器"的标准库化，对应 brk 直觉。
- **工业仓库**：分配器替代 jemalloc/tcmalloc/mimalloc 重写"free 不归还+线程缓存"；
  memcpy 现代演进看 glibc ifunc 分发与 ARM `DC ZVA`；SDS 思想在 Envoy/folly FBString 中延续。
- **训练营属性→真实使用频率**：malloc 行为与栈堆权衡是**内存类面试的前三高频**（双 freed 复用、
  128KB 阈值）；但工业现场你 90% 的时间在"用分配器"而非"懂分配器"——懂它的价值出现在
  性能事故（碎片/锁竞争）与嵌入式/池化场景。memcpy 页复制细节属低频深挖。

## 实测样例（已实测 g++ 15.2）

栈/堆地址关系 + memmove 重叠语义（对应 `heap-stack-memory` 与 `memcpy` 两篇）：

```cpp
#include <cstdio>
#include <cstdlib>
#include <cstring>
int main(){
  int local; void* h = malloc(16);
  printf("stack=%p heap=%p (stack < heap? %s)\n",
         (void*)&local, h, (void*)&local < h ? "yes" : "no");
  char buf[] = "abcdefgh";
  memmove(buf + 2, buf, 5);      // 重叠：memcpy 则是 UB
  printf("memmove overlap -> %s\n", buf);
  free(h);
}
```

```
$ g++ -O2 s02.cpp && ./s02
stack=0000007434fff9b0 heap=00000221657971a0 (stack < heap? yes)
memmove overlap -> ababcdeh
```

解读：Windows x64 栈地址高、堆地址低（与 Linux 进程布局同型但值域不同）；
`ababcdeh` 证明 memmove 按"往前拷贝会覆盖尚未读的数据"时正确改用倒序。
