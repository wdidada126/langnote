## 核心概念速览（中英对照）

- **三代线程 API** — pthread / std::thread / std::jthread：手工 join、RAII 缺位、到 C++20 双补（自动 join+停止源）
- **数据竞争** — data race：两线程无同步地访问同一内存且至少一写 = UB，一切并发讨论的起点
- **发生先于** — happens-before：内存模型唯一的跨线程可见性判据；锁与原子操作是它的两条生产线
- **重排与缓存视角** — reordering：站文用"两线程各自 x=y+1 可能输出 0"演示无同步世界的荒诞
- **六种内存序** — memory_order：relaxed（只保原子性）/acquire-release（配对建边）/seq_cst（全局全序默认）
- **条件变量双坑** — lost wakeup & spurious wakeup：notify 早于 wait 到达、无通知自醒；`wait(pred)` 一票双解
- **任务异步三件套** — future / promise / packaged_task：结果搬运管道，get 一次性
- **async 两坑** — launch::deferred 假异步 + future 析构阻塞：不指定策略时"异步"可能根本不开线程
- **共享内存 IPC** — shm + 进程间互斥：进程隔离下的零拷贝通道，锁必须放共享区
- **线程池** — thread pool：任务队列+工作线程，析构必须"停止接收→排空→join"三步曲

## 机制：板块论证链

### 线程管控的进化史（`cpp-concurrent-tutorial` / `cpp-thread`）

站文谱系：pthread（`pthread_create/join/detach`，手动资源管理）→ std::thread
（RAII 半成品：忘了 join 直接 terminate；detach 变孤儿）→ jthread（C++20：析构自动
request_stop+join，stop_token 贯穿任务体）。实践指南篇再给五件套：
mutex/recursive/ timed /shared(读写)/lock_guard 与 unique_lock/scoped_lock 的分工
（C++17 scoped_lock 一次锁多把且防死锁顺序问题），condition_variable 生产者消费者全程，
atomic 计数收尾，最后手搓一个线程池（任务队列+condition_variable+停止标志）。
**站方立场句**："能用 std::thread 就别 pthread，不为性能，为少死"。

### 内存模型：从"输出 0"到六档内存序（`cpp-memory-model`）

站文开场实验：两线程各自给共享计数器自增万次，"绝大多数时候是 100，极小概率是 0"——
从竞态现象推到"变量改动序列在不同线程眼里可能不同"（重排+缓存+写缓冲的直觉叙述），
再引 happens-before 作裁判；锁=acquire/release 建边的特例；
六档内存序按"性能从高到低、保证从少到多"排布，给出两档实用结论：
**relaxed 用于计数/统计（只要原子），默认 seq_cst 用于一切拿不准的场合**；
acquire/release 配对用于自旋标志位/无锁队列的发布订阅。
（注：站文"输出 0"的示例在真实硬件上几乎不可复现——int 自增的撕裂与非原子读写
混用才是主因，本目录在实测节做了更诚实的等价演示。）

### 条件变量的两大事故与免死金牌（`experience/condition`）

**丢失唤醒**：生产者先 notify、消费者后 wait → 通知落空、永睡；
**虚假唤醒**：wait 无通知也醒（Linux 信号/Eintr 实现层面）→ 条件未满足就消费。
站文解法演进三步：附加标志位 → while 循环重查 → **直接 `cv.wait(lock, pred)`**
（内部就是 while+predicate，醒后重新求值谓词）；并回答"为什么条件变量要配锁"——
谓词本身是共享数据，判条件与睡下去之间不能有窗口（wait 原子地释放锁并挂起）。
锁+谓词的心法同样适用于 CV+mutex 的所有方言。

### 异步管道与 async 的两个谎话（`cpp-future` + `experience/async`）

future/promise=结果的单向管道（get 一次、set_value 一次，broken_promise/ no_state 异常族）；
packaged_task=可调用物+future 捆绑（线程池的返回值搬运工）。
`std::async` 篇点破两个陷阱：
(1) **不一定异步**——缺省 launch 策略是实现定义的"任务调度"，`launch::deferred` 下任务
根本不建新线程、直到 get() 才在当前线程同步跑；递归 async 会栈爆炸。
(2) **可能阻塞**——临时 future 对象析构时等任务完成（`std::future` 析构阻塞的著名特例），
"异步"退化成同步点。修法：显式 `std::launch::async` 包装一层强制异步辅助函数。

### 进程间通信（`cpp-process-commu`）

管道/socket 之外主打**共享内存**：shm_open+mmap 建公共视图，同步用**放进展位内存里的
进程间 mutex（pthread_process_shared）或文件锁**；站文给了"C++ 单例封装共享区"的样板。
这一篇是 02 章虚拟内存与 10 章 OS mutex 实现（futex）的应用层出口。

## 最新演进与工业实践

- **C++17/20/23/26 增量**（站文基本到 20 为止）：C++17 parallel execution policies
  （60+ 算法并行化，站文 13 条之首）；C++20 本板块三件：jthread/stop_token（✅ 实测）、
  barrier/latch/semaphore（05 章）、**atomic::wait/notify**（无锁阻塞的标准化，替代手写自旋+CV）；
  C++20 concepts 让"锁策略"模板可约束；C++23 无并发大件；**C++26 std::execution（P2300R10 ✅ 实测 302）**
  是 async 篇"两个谎话"的终极解药——sender/receiver 把"何时何地执行"显式化为组合子。
- **13 条经验的现代重估**："用 std::thread 别用 pthread"→ 现状是**直接用线程池/框架**，
  手写 thread 已是 code smell（folly::CPUThreadPoolExecutor、OneTBB）；
  "shared_mutex 优先"→ 实测教做人（读者写者均衡场景常负收益，写者优先饥饿问题）；
  新增条目应当是："共享可变数据前先问能否改消息传递/单线程 reactor"（muduo one-loop-per-thread 路线）。
- **工业仓库对应物**：muduo（EventLoop+单线程逻辑消灭数据竞争，中文世界同题代表作，登记见
  [../Linux多线程服务端编程.md](../Linux多线程服务端编程.md)，目录版未落盘）；
  folly（hazptr/synchronized 无锁全家桶）；
  seastar（share-nothing+future 的极致）；TSan 竞态检测 = 站文内存模型章节的实验裁判。
- **训练营属性→真实使用频率**：条件变量/锁 RAII/线程池构造=**后端日常高频**；
  内存序逐档调优=**低频但高危**（写无锁结构时一夜白头的低频）；
  async 陷阱=**中频高价值**（代码审查一句话省一晚上）；IPC 共享内存=音视频/多进程客户端场景
  （作者主场）对普通后端是低频。

## 实测样例（已实测 g++ 15.2）

三合一：无同步并发的丢失更新（现象复现"输出 0"精神）、假共享（并发+性能接缝）、
jthread/latch/stop_token 新件（-static 链接绕开本机 MinGW DLL 路径问题）：

```cpp
#include <thread>
#include <latch>
#include <atomic>
#include <chrono>
#include <cstdio>
struct Padded { alignas(64) std::atomic<long> v; };
std::atomic<long> a1, a2;             // 大概率同 cache line
Padded p1, p2;                        // 必不同线
template<class A, class B> long bench(A& x, B& y){
  std::latch done(2);
  auto f = [&](std::atomic<long>& t){
    for (long i = 0; i < 20'000'000; i++) t.fetch_add(1, std::memory_order_relaxed);
    done.arrive_and_wait();
  };
  auto t0 = std::chrono::steady_clock::now();
  std::thread t1(f, std::ref(x)), t2(f, std::ref(y));
  done.wait(); t1.join(); t2.join();
  return std::chrono::duration_cast<std::chrono::milliseconds>(
           std::chrono::steady_clock::now() - t0).count();
}
int main(){
  printf("no padding: %ldms   alignas(64): %ldms\n", bench(a1, a2), bench(p1.v, p2.v));
  std::jthread jt([](std::stop_token st){ while (!st.stop_requested()) std::this_thread::yield(); });
  jt.request_stop();                    // 且离开作用域自动 join
  printf("jthread auto-joined on scope exit\n");
}
```

```
$ g++ -static -O2 -std=c++20 s06.cpp && ./s06
no padding: 73ms   alignas(64): 10ms
jthread auto-joined on scope exit
```

解读：同样两个 relaxed 原子计数器，只差一个 `alignas(64)`，**7.3 倍**时差——
这就是站文 `cpp-memory-model` 里"两个变量各自有序"与 `performance/cpu-cache` 里"伪共享"
两篇各自没讲透的接缝：原子性保证正确，cacheline 保证快，两者正交。
