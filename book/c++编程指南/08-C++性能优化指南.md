## 核心概念速览（中英对照）

- **缓存行** — cache line（64B）：CPU 与内存间最小搬运单位，一切"遍历顺序影响速度"的根因
- **时间/空间局部性** — temporal/spatial locality：行优先遍历命中预取器，列遍历次次 miss
- **伪共享** — false sharing：两线程各写各的变量，却在同一 cache line 上互相踢飞所有权
- **分支预测** — branch prediction：流水线押注未来，错一次赔十几周期；随机数据让 `if` 变成性能黑洞
- **间接调用 vs 内联失败** — devirtualization：站文实测虚表那次间接调用本身不贵，**挡住了内联和向量化才贵**
- **测量纪律** — measure first：板块首篇第一句"不要凭感觉优化"，13 年经验条同款（站方自洽的少数处）
- **SoA/AoS** — structure of arrays：面向缓存的数据布局设计，`performance/design` 篇主旨
- **SBO/类型擦除开销** — small buffer optimization：std::function 的堆分配阈值（04 章实测的机制面）
- **体积优化** — binary size reduction：-ffunction-sections、LTO、异常表瘦身、模板减肥十招
- **性能工具谱** — profiler/valgrind/perf/VTune：采样式 vs 插桩式，火焰图读法

## 动机：性能板块=全站"实测含量"最高的部分

站文性能篇的共同文体：**先给一对反直觉计时**（行/列遍历差数倍；排序与否影响 if-else 循环 3 倍；
虚函数两次实验一慢一快），再下探硬件解释。它不是系统性能教材（无roofline、无基准方法学），
但"机制直觉"建立得非常高效——正是训练营学员最短路径。

## 机制：三层解剖

### 硬件层：Cache 两篇 + 分支预测

`performance/cache`：局部性→预取器（顺序访问硬件自动流水）→行/列遍历实测对比；
`cpu-cache`：先演示"两个独立计数器多线程累加，加 alignas(64) 前后差数倍"（**本章 06 章实测同款**），
再讲 MESI 所有权迁移：写同一行的任何字节=整行失效重取。
`branch-predict` 是全板块招牌：经典实验——同一份"if (v>=128) sum+=v"循环，
**随机数组 7.9 秒、排序数组 2.4 秒（站文版本：注释掉排序行 24s vs 保留 7.9s，3 倍差）**；
解释链=流水线→乱序→推测执行→预测失败冲刷；给出 `__builtin_expect`/排序预处理/
分支化无分支（cmov、位技巧 `sum += (v>>7)*v` 类）三把武器。
站文数字来自作者老硬件；本目录在 2026 年硬件+GCC 15 复现时发现**信号已被编译器与更好的预测器抹平**
（见实测节——这个"负结果"本身就是最好的现代演进材料）。

### 代码层：虚函数、类型、STL、设计

`virtual-function` 篇是站板块最成熟的一篇：实验一，虚调用循环 vs 普通调用循环，
12.895s vs 12.706s——**"虚表间接调用本身几乎不要钱"**；实验二，往循环里塞一个
小而热的函数体，普通版 436ms、虚调用版数倍——差额来自**内联失败+迭代器失效式重复计算**，
不是那一次跳转。结论句值得引用式转述："虚函数的开销不在调用，在于它让编译器无法再优化"。
`code-state` 篇：整型（int32 与机器字对齐最快、除法贵）、浮点（FPU 管线、与整型互转代价）、
布尔（存 0/1 但按字节加载、位域慎用）——"数据类型性能指南"。
`stl` 篇：容器选型表（vector 默认、list 近乎全输、unordered 看哈希）、reserve 预分配、
`emplace_back` 省一次移动、按值移动进容器、算法替代手写循环。
`skill`+`advice` 两篇合并=代码手感清单：传 const 引用/值得拷贝的才值传、
避免临时对象（RVO/NRVO 讲透：多数情况按值返回**不要**改成传引用输出参数）、
预分配、字符串拼接攒总量、移动语义受益者名单（容器/句柄/大对象）。
`design` 篇：类结构层面性能（pimpl 的指针追逐税、继承层次对构造/析构顺序的约束、
把热点成员拆独立结构）。

### 工具与目标层

`opt-tools`：静态（cppcheck/clang-tidy/SonarQube/infer+圈复杂度等度量）与动态
（gprof/Valgrind callgrind/perf/VTune/heap profiler）两轨，附"何时用哪个"决策表；
`size-opt`：体积十招（`-ffunction/-fdata-sections` + `--gc-sections`、LTO、
异常表 `-fno-exceptions` 场景评估、模板外置、运行期多态换表驱动、字符串合并）。
`cpp-endl`（04 外链）归此层：`std::endl`=换行+flush，日志循环里它是真开销。

## 最新演进与工业实践

- **编译器时代修正**：本目录实测（见下）显示 GCC 15 -O2 把"预测不利的 if"直接**向量化为掩码加法**，
  随机/排序 3 倍差在现代默认优化下消失；-O0 也几乎测不出——分支预测税在 2026 年
  主要存在于**分支本身不可向量化**的真实代码里（查表分派、提前 return）。`[[likely]]/[[unlikely]]`
  （C++20）与 `__builtin_expect` 继续有效但收益点变少。
- **虚函数结论的工业呼应**：LLVM/Chromium 代码库大量用 `final`/`devirtualization` 注解
  找回内联——站文"开销在挡住优化"的判断与 `llvm-devirtualunit` 等论文方向一致 ⚠️（论文未核 DOI，只题方向）。
- **伪共享现代工具化**：perf c2c 专门定位 false sharing；folly `cachepadding`、abseil 的
  `ABSL_CACHELINE_SIZE` 注释已成开源惯例——站文 alignas 手工拳的标准化形态。
- **SoA 的当下**：simdjson、Entt、游戏引擎 ECS、ClickHouse 列式存储是"设计篇"思想的生产级证据；
  C++26 `std::execution` 不涉性能层，但 `std::mdspan`（C++23）提供多维布局抽象。
- **训练营属性→真实使用频率**：**测量纪律=最高频心法**（先 profile 再动手，一票否决玄学优化）；
  cache/伪共享=高频于性能敏感岗（音视频/交易/游戏，作者主场）；
  分支预测/类型性能=面试中频、现场低频（除非你写编解码器）；体积优化=客户端/embedded 刚需、后端少见。

## 实测样例（已实测 g++ 15.2）

**复现站文招牌实验的"现代翻案"**——分支预测税去哪了：

```cpp
#include <algorithm>
#include <random>
#include <chrono>
#include <cstdio>
int main(){
  const int N = 1<<14, R = 20000;
  int data[N];
  std::mt19937 rng(42);
  for (auto& v : data) v = rng() % 256;
  auto work = [&](const char* tag){
    auto t0 = std::chrono::steady_clock::now(); long sum = 0;
    for (int r = 0; r < R; r++) for (int v : data) if (v >= 128) sum += v;  // 站文原版循环
    auto t1 = std::chrono::steady_clock::now();
    for (int r = 0; r < R; r++) for (int v : data) sum += (v >= 128) ? v : 0; // 无分支版
    auto t2 = std::chrono::steady_clock::now();
    printf("%s branch:%.3fs branchless:%.3fs\n", tag,
      std::chrono::duration<double>(t1-t0).count(), std::chrono::duration<double>(t2-t1).count());
  };
  work("random  ");
  std::sort(data, data+N);
  work("sorted  ");
}
```

```
$ g++ -O0 -std=c++17 s08.cpp -o s08_O0 && ./s08_O0   # 先关掉一切优化
random   branch:0.31s branchless:0.36s
sorted   branch:0.32s branchless:0.36s

$ g++ -O2 -std=c++17 s08.cpp -o s08_O2 && ./s08_O2   # 默认优化
random   branch:0.00s branchless:0.00s                # 全部向量化，三组几乎同时归零
sorted   branch:0.00s branchless:0.00s
```

解读：站文"排序与否 3 倍差"在本机 **测不出来**——-O0 下现代 CPU 预测器已能吃掉
简单可模式化分支，-O2 下 GCC 把两个循环统一向量化（cmov/mask add）。
结论不是"站文错了"，而是其机制在 2010s 硬件+老 GCC 上显著、在 2026 工具链上
**只在分支不可向量化时才回来**；"先测量"因此永远是本章第一条。
