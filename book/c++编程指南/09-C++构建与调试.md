# 09 C++ 构建与调试——从 gcc 四条命令到 ELF 段布局的十三篇

> 对应站点板块：主要内容第 8 板块 `/docs/build-debug/`（13 篇，实抓 ✅）。
> 站方一句话："编译原理、调试技巧、CI/CD 等工程化主题"——**CI/CD 实际零篇 ⚠️**，
> 板块实体是 Linux 链接加载与调试工具的十三讲：
> gcc 编译四阶段、编译链接符号冲突、CMake 入门、动态链接详解、Debug/Release、GDB、
> 共享库版本控制（SONAME）、程序入口（main 之前）、函数调用栈帧、段管理（text/data/bss）、
> 虚拟内存页映射、Windows Dump 解析。

## 核心概念速览（中英对照）

- **四阶段流水线** — preprocessing → compilation → assembly → linking：`gcc -E/-S/-c/-o` 对应拆解
- **符号解析** — symbol resolution：未定义符号表+强弱势符号（`nm/objdump`）是链接期冲突的账本
- **可见性控制** — static / anonymous namespace / `-fvisibility=hidden`：把符号关进本翻译单元/DLL
- **位置无关代码** — PIC (`-fPIC`)：共享库以 GOT/PLT 间接寻址换重定位自由
- **SONAME 版本化** — shared object versioning：`libfoo.so.1.2.3` + SOVERSION 表达 ABI 兼容性承诺
- **程序的真入口** — `_start`/crt0：main 之前还有栈初始化、`.init_array` 全局构造、动态加载器
- **段布局** — text/data/bss/rodata：代码/已初始化全局/零初始化全局/只读常量四段+堆栈
- **调用约定与栈帧** — calling convention / stack frame：rbp/rsp 摆位、参数寄存器、返回地址藏身处
- **海森堡缺陷** — heisenbug：Debug 正常 Release 崩溃（UB 被优化放大/消失）与反之（生命周期被 debug 模式延长）
- **核心转储** — core dump / minidump：`ulimit -c`、`catchsegv`；Windows 侧 SetUnhandledExceptionFilter+dbghelp
- **gdb 三板斧** — backtrace/print/frame + 多线程 `info threads/thread apply all bt`：死锁现场读法

## 动机：为什么"构建调试"是训练营的临门一脚

01 章痛点清单里"不懂企业级工程化开发"落点就是本板块：会写代码与能让 500 个 .cpp 在
双平台出可复现产物、崩了能在 30 分钟内定位，中间隔着这 13 篇。站文特色是**把黑盒拆到
命令行级**：gcc 一条命令拆四步给你看中间产物；一个符号冲突例子从 multiple definition
讲到静态/动态两种库的可见性策略；ELF 用 `readelf/objdump` 现场解剖。

## 机制：四组主题

### 编译链路（gcc-progress / compile-link / debug-release）

`gcc helloworld.c -o out` 实为：cpp 展开宏与 include（`-E` 可看，体积暴涨数倍）→
cc1 生成汇编（`-S`，中间语言的证据）→ as 产 .o（`-c`，重定位表+未决符号）→
ld 链接（符号配对、段合并、入口设定）。**compile-link 篇主戏**是符号冲突：
两个 .o 同名全局函数 → ld 报 multiple definition；解法分级：`static`/匿名命名空间（TU 内私有）、
命名空间（工程级）、`-fvisibility=hidden`+显式导出（DSO 边界）、`extern "C"` 只管名字改编不管冲突。
debug-release 篇给 -O0..Ofast 全表并解释两案：**Release 崩 Debug 活**（UB：未初始化变量在
debug 栈残值恰好无害、strict aliasing 破坏、浮点重排）与 **Debug 崩 Release 活**
（迭代器调试宏/container debug 模式改了内存布局；或 `#define` 吞了 NDEBUG 分支）——
"海森堡"两向都有账。

### 链接与加载（dynamic-static-link / linux-version-control / link-segment / load-virtual / linux-main-start）

静态库=归档的 .o 集合，链接期**拷贝**进产物（体积换独立性）；动态库运行期**映射**共享
（PIC→GOT 数据重定位/PLT 函数跳板），`LD_PRELOAD` 劫持的原理即符号插入次序。
版本控制篇讲 SOVERSION 三级号（major=ABI 破坏、minor=兼容增量、patch）与 `libfoo.so→.so.1→.so.1.2`
符号链接阶梯。段管理篇用真实 ELF 演示 text（RX）/rodata（R）/data（RW，已初始化）/
bss（RW，占位不占盘）——"全局变量放哪了"一次讲透。
main-start 篇：`_start`（crt1.o）设栈与参数→`__libc_start_main`→`init_array` 跑全局构造→
才进 main；**自定义入口** `-nostartfiles` + `_start` 裸写 syscall 示例（嵌入式向）。
load-virtual 篇与 02 章 malloc 篇同源：页表/按需缺页/写时复制——加载 ELF 不等于读盘。

### 调试（gdb / dmp / linux-func-call + 跨板块 experience/gdb）

gdb 篇：断点家族（条件/硬件/watchpoint 看内存何地被改）、`print/r` 格式化、
backtrace+frame 切换读参数与局部；**函数调用篇是 gdb 的底层篇**：x86-64 传参寄存器
rdi/rsi/rdx/rcx/r8/r9、栈帧 rbp 链、返回地址——理解了它，`bt` 输出才不是天书。
多线程死锁调试在 `experience/gdb`（本章合并消费）：`thread apply all bt` 找
两线程互等对方已持有的 mutex。dmp 篇补 Windows 侧：minidump 三档生成
（`SetUnhandledExceptionFilter`/WER/dbgMakeMiniDump）、WinDbg `!analyze -v` 三板斧——
**站内少见的双平台视角**，与训练营"音视频客户端=Windows+Android"画像吻合。

### CMake（cmake 篇）

站方入门口径正确但保守：`add_executable/target_link_libraries` 现代签名、
`find_package`、构建目录分离。缺口：不讲 `target_include_directories(PUBLIC/PRIVATE/INTERFACE)`
的传播语义、不讲 FetchContent/工具链文件——以 [../ModernCMakeforC++.md](../ModernCMakeforC++.md) 登记书
为下一步是本章建议。

## 最新演进与工业实践

- **链接器与构建加速**：2026 年大仓标配是 **mold/lld** 替换 GNU ld（链接提速一个量级）+
  ccache/sccache + Bazel 远程缓存；CMake 侧 P0 仍是"目标制、禁全局变量"。
  站文 gcc 四阶段讲法不受影响，但 ld 那一环的"等 5 分钟"痛点已可治。
- **modules 对板块的重写预告**：C++20 header units 允许"只预处理不翻译"——
  站文 cpp 展开体积爆炸的痛点，标准答案正在从 `-fpch`/unity build 迁向 import；
  GCC/Clang 支持度见 05 章判断（试点级）。
- **调试信息**：DWARF5 普及（gcc 11+ 默认）、`-gsplit-dwarf`（.dwo 分离，大仓链接提速）；
  Linux 侧 **reverse debugging（rr）** 已成事实标准——
  站文未提，本章补：复现死锁事故，rr record/replay 强于 core dump 一档。
- **CI/CD 缺口指认**：站方承诺的 CI/CD 内容不存在 ⚠️——补位读物为各仓文档
  （GitHub Actions + vcpkg/conan 的 manifest 模式）。
- **训练营属性→真实使用频率**：**每日**：编译链接错误读法、CMake 目标语法、gdb bt 三板斧；
  **每周**：符号冲突治理、版本化、dump 分析；**低频但救急**：自定义入口、段手术。
  本板块是全站在"面试"与"上班"间失真最小的一个。

## 实测样例（已实测 g++ 15.2）

debug-release 篇论点的本机量化 + MinGW 现场：

```cpp
#include <cstdio>
#include <chrono>
long fib(int n){ return n < 2 ? n : fib(n-1) + fib(n-2); }
int main(){
  auto t0 = std::chrono::steady_clock::now();
  long r = fib(38);
  auto t1 = std::chrono::steady_clock::now();
  printf("fib(38)=%ld in %.3fs\n", r, std::chrono::duration<double>(t1-t0).count());
}
```

```
$ g++ -O0 -std=c++17 s09.cpp -o s09_O0 && ./s09_O0
fib(38)=39088169 in 0.151s
$ g++ -O2 -std=c++17 s09.cpp -o s09_O2 && ./s09_O2
fib(38)=39088169 in 0.043s
```

解读：3.5 倍纯优化差还只是"看得见的部分"；同一段代码在 -O2 下若含 UB，
行为差异可以不是快慢而是有无——站文"Debug/Release 双向翻车"的根。
环境注记（实测副产品）：本机 MinGW 动态 exe 直接执行返回 127（libwinpthread DLL 搜索路径问题），
`-static` 后正常——这本身就是 09 章动态链接一讲的活教材。
