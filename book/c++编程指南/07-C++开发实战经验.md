## 核心概念速览（中英对照）

- **无符号回绕** — unsigned wraparound：`for(size_t i=n-1; i>=0;)` 永真；`container.size() < -1` 恒假
- **迭代器失效** — iterator invalidation：erase 返回后继、遍历中扩容=全体作废，STL 头号悬垂源
- **虚析构缺失** — non-virtual base destructor：基类指针 delete 派生类=UB+泄漏
- **变参宏复用** — va_list reuse after vsnprintf：C11 §7.21.6.8 明文"值不确定"，必须 va_copy
- **JSON 精度天花板** — IEEE double 2^53−1：id 类 int64 走 JSON 必须转 string（Google 协议惯例）
- **值语义多态** — std::variant + visit：封闭类型集合上的多态，替代继承树的第二方案
- **组合优于继承** — composition over inheritance：站文版论证：耦合实现细节/脆弱基类/构造顺序绑架
- **对象池** — object pool：预分配+空闲链表复用，治"高频小对象 malloc 抖动"
- **内存泄漏钩子** — allocation hooking：接管 operator new/delete 记录栈回溯，定位泄漏现场
- **UTF-8 逐字节陷阱** — UTF-8 traversal：`string[i]` 是字节不是字符，中文截半即乱码
- **异常边界** — exception boundaries：跨线程/跨 API/跨模块三处必须拦截，异常不做控制流
- **RAII 高级技法** — RAII→CRTP 谱系：`coding-experience` 篇把 04 板块诸设施串成"高级写法"清单

## 动机：这个板块是"训练营"的产品本体

02–06 板块任何教程网站都有，experience 板块才是本站的差异化资产：几乎每篇都有**事故现场**

## 机制：四大簇精读

### 簇一：陷阱清单类——《24 个 C++ 开发陷阱》是板块目录

`experience/summary` 一篇顶半章：无符号循环、`size()` 比较、memcpy/memset 只适用 POD
（对含虚表对象 memcpy = 拷 vptr 进新世界）、list 必须用成员 sort（随机访问迭代器不存在）、
new/delete 配对（回链 03 章 cookie）、基类虚析构、**中文注释编码事故**（GB2312 乱码字节里
藏 `\` 续行符吞掉注释后的行——真实且罕见的经典）、成员变量必须手动初始化。
每坑一代码块，风格"考前重点"。相邻的 condition/async 两篇在 [06 章](06-C++并发编程实战.md)已深读；
`valist` 篇值得单独复述：**iOS 崩、Windows 不崩的根因**——第一次 `vsnprintf` 后原 va_list
进入 C11 定义的"不确定值"状态，Windows 实现恰好可复用、ARM 实现不行；正解 `va_copy` 再喂第二次格式化。
`json` 篇同理跨平台：JS 侧 `Number` 是 double，19 位雪花 ID 前端拿到已损坏——协议层 int64→string 是唯一稳解。
`chinese-string` 给 UTF-8 字节模式（1xxxxxxx/110xxxxx…）与手写解码器，顺带痛批
"GBK 时代遗留代码遇上 UTF-8 数据"的国内日常。

`sdk` 与 `chromium` 是双镜像：SDK 开发讲 ABI 稳定/符号隐藏/版本策略（与 09 章 SONAME 篇互链）；

### 簇三：设计抉择类——继承不再是默认答案

`derive-vs-combine`：站文结论罕见地不骑墙——默认组合，仅当"需要多态+稳定的 is-a+ protected
扩展点"才继承；给脆弱基类与构造顺序两案。`variant-override`：C++17 variant+visit
在**封闭类型集**（协议消息、GUI 控件种类）上全面优于继承树——无堆分配、无 vptr、穷尽检查

rule of 0/3/5）；`design-struct` 从内存对齐切入结构体设计（字段排序省 padding，回链 10 章 memory-align）。
`coding-experience` 篇名"从 RAII 到 CRTP"，实为 04 板块的浓缩串烧（站方自我引用，本目录不重复消费）。

## 最新演进与工业实践

- **现代语言特性对陷阱清单的"消坑"效应**：无符号回绕→`std::ssize`（C++20）与 ranges；
  memcpy POD 约束→`std::bit_cast`（C++20）；迭代器失效→ranges views 消灭中间容器与
  手写 erase 循环；空指针判定→`[[lifetimebound]]`/
  clang `-Wdangling-gsl` 让 string_view/引用参数悬垂在 CI 里爆炸；`nullptr` 与 `optional`
  替代"可能为空指针"。中文编码：C++20 曾为 UTF-8 推出 `char8_t`，C++23 认定设计失败、
  `u8string` 回退为 `std::string`——站文教训升级但没消失。
- **规范类的工业上游**：C++ Core Guidelines（Stroustrup/Ellis，本仓库有
  [../C++CoreGuidelines解析/01-简介.md](../C++CoreGuidelines解析/01-简介.md) 目录版）、
  Google Style、Chromium Style 原文；执行层=clang-tidy（本站 08 章 opt-tools 推荐 SonarQube/infer，

- **variant 多态的工业验证**：游戏引擎（EnTT、Godot 的 Variant 类型）与编译器

- **训练营属性→真实使用频率**：24 陷阱与编码规范=**code review 每日素材**（新人杀手 Top5：

## 实测样例（已实测 g++ 15.2）

手写 shared_ptr 篇的镜像验证——循环引用泄漏与 use_count 现场（站文只讲原理，此处上证据）：

```cpp
#include <memory>
#include <cstdio>
struct Node { std::shared_ptr<Node> self; ~Node(){ printf("~Node destroyed\n"); } };
int main(){
  auto n = std::make_shared<Node>();
  n->self = n;                       // parent↔child 环
  { auto m = n; printf("use_count after copy: %ld\n", m.use_count()); }
  n.reset();                         // 外部句柄全清，环仍自锁
  printf("after reset(): no destruction above => leak\n");
}
```

```
$ g++ -O2 -std=c++17 s07.cpp && ./s07
use_count after copy: 3
after reset(): no destruction above => leak
```

解读：计数 3（n、m、self 各一），m 出作用域-1、n.reset()-1，**self 那一票永不作废**——
输出里没有 `~Node destroyed`。修法即站文一笔带过的 weak_ptr：观测端用 `weak`，
所有权单向成环自然解（对照 05 章智能指针三件套）。
