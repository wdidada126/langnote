## 核心概念速览（中英对照）

- **日志库三明治** — logger = macro(现场采集) + format(拼接) + sink(落盘)：spdlog/glog/Boost.Log 三篇共用骨架
- **异步日志** — async logging：前端入队+后端线程批量写，`spdlog` 篇的"blocking vs async pool"
- **写时复制字符串** — COW string：引用计数+惰性复制的 string 旧实现，C++11 起被标准禁止（多线程事故）
- **局部缓冲** — SSO (small string optimization)：libstdc++ `basic_string` 的 `_M_local_buf` 16 字节短串不上堆
- **互斥锁的三层楼** — mutex = 硬件原子指令(x86 lock cmpxchg) → 内核 futex 休眠队列 → libc 语义封装
- **快速用户区互斥** — futex：无竞争时零系统调用，有竞争才进内核排队——站文"锁的代价在睡眠不在加锁"的正解
- **进程的一生** — process lifecycle/scheduler：fork-exec-wait、CFS 虚拟运行时长调度（OS 板块最大篇）
- **页面置换** — page replacement：LRU/WorkingSet/缺页中断，虚拟内存叙事的下半场
- **索引从 0** — zero-based indexing：Dijkstra 的区间论证 `[0, n)`——端点差即长度、相邻区间自然衔接
- **Duff 设备** — Duff's device：switch 的 fallthrough 跳进 8 路展开循环体，1983 年最凶残的 C 惯用法

## 机制：三块各自的核心论证

### 开源剖析组（spdlog / glog / Boost.Log / string / 读开源方法论 / debug 技巧 / 项目导航）

日志三连是站内最成体系的源码课：**通用架构**（Macro 采集 `__FILE__:__LINE__` →
Logger 组合 Format+Sink → 拼接器支持流式/printf/fmt 三风格 → Sink 轮转/控制台/文件）；
spdlog 篇亮点：锁与无锁环形队列二选一、异步模式=独立线程+批量 flush；glog 篇亮点：
`LOG_IF/LOG_EVERY_N/CHECK` 宏族与严重级落盘策略、Google 式符号化 stacktrace；
Boost.Log 篇展示"库设计 Modularized"的另一个极端（特性组合爆炸）。
**string 源码篇**回答自己列的 7 问：`basic_string` 深拷贝版（`_M_dataplus`+`_M_local_buf`
SSO 16B 缓冲）与 COW 版（`_Rep` 引用计数+`_S_empty_rep_storage` 共享空串）双轨对照，
并明确 C++11 废除 COW 的原因——多线程下"写时复制"的"写"检测本身需要原子操作，
省内存输给了正确性。**这一篇是全站与 [../C++标准库/08-特殊容器与字符串.md](../C++标准库/08-特殊容器与字符串.md) 衔接最好的一篇**。
"如何读开源：六步法"给方法论（跑 example→断点进主流程→画类图→改注释重编→追一个函数的一生→写文章）——
本站本身就是该方法的产物。
### OS 原理组（mutex / 进程管理 / 内存管理 / 文件系统）

mutex 篇的楼梯：软件解（Peterson）→ 硬件原子（test&set、x86 `lock` 前缀）→
OS 层"睡眠换 CPU"（自旋+阻塞混合、等待队列）→ **futex：乐观路径不进内核**；
并给"锁的三种实现代价谱"（自旋烧 CPU/系统调用税/无锁换复杂度）。
进程管理篇（板块最长）：task_struct、fork COW、execve 重建地址空间、
调度从 O(1) 到 CFS（vruntime 红黑树）、命名空间与容器关系一段。
内存管理篇：分页/多级页表/TLB/缺页处理/置换算法（FIFO 的 Belady 异常、LRU 工程近似 Clock）。
文件系统篇：VFS 四层抽象、inode/dentry 缓存、日志式文件系统的 WAL 思想——
与 07 章 sqlite3 WAL 篇同构互证（数据库 WAL 借的就是文件系统 WAL 的魂）。

### 计算机知识点组（duff-device / count_by_zero / system64 / memory-align）

Duff's device：8 路展开减判断次数，**余数用 switch  fallthrough 从中间跳进循环**
（`count%8` 进 case、`case 0` 补尾）；站文如实标注"现代编译器自动做，这是考古+读懂老代码"。
index 从 0：Dijkstra 论证 `[low, high)` 半开区间家族——长度=high−low、空区间 low==high、
相邻区间无缝衔接；文章坦承"这题超纲，靠查资料"，是站内文体自省的孤例。
system64：寄存器宽度/地址空间/指针大小/ABI（x32 vs x86-64）对比表；
memory-align：对齐三规则（成员 align 起点、总大小=最大 align 倍数、`#pragma pack` 危险）+
`alignas/alignof` 现代写法——与 08 章 struct 设计篇、07 章 design-struct 三处同一知识点。

## 最新演进与工业实践

- **日志**：std::format/std::print（P2093R14 ✅）把 spdlog 的格式化层标准化（01 章已实测其最小形态）；
  工业现状：spdlog 仍是事实默认，glog 在 Google 系；新趋势是结构化日志（JSON lines+零分配热路径）。
- **string**：COW 已死（libstdc++ 自 GCC5 `_GLIBCXX_USE_CXX11_ABI` 起只有 SSO 版）；
  现代演进是 FBString（ folly 小字符串优化 23B+外链）、rope（LLVM）、string_view 消费侧改造。
- **锁**：C++20 `atomic::wait`、`std:: counting_semaphore` 把 futex 语义部分标准化；
  工业轮子：absl::Mutex（属性化）、folly TFRC/SpinLock 系——测量结论与站文一致：**先降共享再挑锁**。
- **OS 组**：四篇内容属 C++11 时代以来最稳定知识（POSIX/CFS 细节除外 ⚠️ 内核版本未标注），
  可当 06/09 两章的"往下问一层"答案卷；升级读物=OSTEP 原书（站文自己推荐）。
- **训练营属性→真实使用频率**：读开源方法论=**转岗/进阶刚需**（面试"你读过什么源码"的答题模板）；
  string 源码=**面试高频、调试偶发**（SSO 解释"为什么短串快"）；mutex 三层楼=**并发岗必背、
  其余岗位背一次够用**；Duff/0 起点=纯面试冷知识（低频）。

## 实测样例（已实测 g++ 15.2）

Duff's device 正确性+性能考古，和对齐三规则的 sizeof 现场（duff-device + memory-align 两篇合体）：

```cpp
#include <cstdio>
#include <cstring>
#include <chrono>
void duff_copy(char* to, const char* from, size_t count){
  int n = (count + 7) / 8;
  switch (count % 8) {                 // 余数从中间跳进循环
    case 0: do { *to++ = *from++;
    case 7:      *to++ = *from++;
    case 6:      *to++ = *from++;
    case 5:      *to++ = *from++;
    case 4:      *to++ = *from++;
    case 3:      *to++ = *from++;
    case 2:      *to++ = *from++;
    case 1:      *to++ = *from++;
           } while (--n > 0);
  }
}
struct P1 { char c; long long x; };                       // 自然对齐
struct __attribute__((packed)) P2 { char c; long long x; }; // 强扭
struct alignas(16) P3 { char c; long long x; };           // 撑大对齐
int main(){
  char a[4096], b[4096]; for (auto& c : a) c = 1;
  auto t0 = std::chrono::steady_clock::now();
  for (int i = 0; i < 200000; i++) duff_copy(b, a, 4096);
  auto t1 = std::chrono::steady_clock::now();
  for (int i = 0; i < 200000; i++) memcpy(b, a, 4096);
  auto t2 = std::chrono::steady_clock::now();
  printf("Duff %.2fs  memcpy %.2fs  (b[0]=%d)\n",
    std::chrono::duration<double>(t1-t0).count(),
    std::chrono::duration<double>(t2-t1).count(), b[0]);
  printf("sizeof P1=%zu P2=%zu P3=%zu, alignof P1=%zu\n",
    sizeof(P1), sizeof(P2), sizeof(P3), alignof(P1));
}
```

```
$ g++ -O2 -std=c++17 s10.cpp && ./s10
Duff 0.18s  memcpy 0.00s  (b[0]=1)
sizeof P1=16 P2=9 P3=16, alignof P1=8
```

解读：手工 8 路展开在 -O2 + SIMD memcpy 面前**输了一个数量级**——站文"现代编译器自动做"
的判断量化成立；Duff 的今日价值=读懂老代码+面试。对齐三规则同样现场：
`{char,long long}` 16B、packed 9B（未对齐访问风险自负）、alignas(16) 撑到 16B——
P2 省的那 7 字节在 x86 上以每次访问的拆分代价偿还。
