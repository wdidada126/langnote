# 第 8 章 微调与全书收束（Tweaks，Items 41–42）

> 对应原书第 8 章（Items 41–42）。单文件大纲 [../Effective_Modern_C++.md](../Effective_Modern_C++.md)；
> 导航 [00-总览与阅读地图.md](00-总览与阅读地图.md)｜索引 [../C++系列·总索引.md](../C++系列·总索引.md)。
> 原书以最轻的两条收尾——按值传参与「insert 可能胜过 emplace」——但它们各自拖着
> 一整串前置机制（移动成本模型、节点分配器、异常保证）。本章末尾附全书 42 条的收束复盘。

## 核心概念速览（中英对照）

- **按值传参 + 移动** — pass by value + move：可复制、必复制、移动廉价三前提下，单重载方案替代
  「左值 const& + 右值 &&」双写。
- **最坏情况成本分析** — worst-case cost analysis：书的核心方法论——接口设计比较的是
  拷贝/移动/构造的**次数**，而不是「看起来快」。
- **emplace 族** — emplace family：就地完美转发构造元素；与 insert 的差异在「先造还是先比」。
- **节点白分配** — redundant node allocation：`std::list/set/map::emplace` 可能构造后才发现
  重复/异常，节点已分配即已付费。
- **强保证与 emplace** — strong guarantee interactions：emplace 参数求值抛异常时，
  容器状态不变的前提是「元素尚未构造」——转发实参越复杂越难满足。
- **有效未定状态** — valid but unspecified：被移动/被清空对象的可依赖边界（全书反复出现的底线概念）。

## 本章地图

| Item | 核心论点 |
| --- | --- |
| 41 | 对「可复制、一定会被复制、移动成本低」的形参，考虑按值：一份实现、签名诚实；但最坏情况多一次移动 + 按值禁止多态基类 |
| 42 | emplace 不总优于 insert：list 的无条件节点分配、set 的重复键白构造、vector 的 reserve 缺失、转发实参求值异常——四种场景 insert 更稳 |

## 机制一：按值 + move 的成本账（Item 41）

```cpp
// 🔧 双方案对照（成本表用 s4 的计数器思想实测验证过拷贝/移动计数）
// A. 重载对（C++11 直觉）
void setA(std::string n)  { name_ = std::move(n); }        // 实际是「按值版」见下
void setA(const std::string& n) { name_ = n; }             // 左值：1 拷贝
void setA(std::string&& n)      { name_ = std::move(n); }  // 右值：1 移动
// B. 转发引用（Item 26 警告过）
template<typename T> void setB(T&& n) { name_ = std::forward<T>(n); }
// C. 按值（Item 41 推荐候选）
void setC(std::string n) { name_ = std::move(n); }         // 左值：1 拷贝 + 1 移动；右值：2 移动
```

| 实参类别 | 重载对 A | 转发引用 B | 按值 C |
| --- | --- | --- | --- |
| 左值 string | 1 拷贝 | 1 拷贝 | 1 拷贝 + 1 移动 |
| 右值 string | 1 移动 | 1 移动 | 2 移动 |
| 可转换实参（`const char*`） | 1 构造 | 1 构造（在赋值点） | 1 构造 |
| 代码量/可维护 | 双份 + 未来每加形参翻倍 | 单份但吞重载 + 报错模板深渊 | 单份、可 .cpp 藏实现 |
| 多态类型 | 可 | 可 | **禁止**（按值切掉派生部分） |

结论程序：先问「类型是否可复制且移动廉价」——string/vector/智能指针是，
array/老类型/多态基类不是；再问「是否总是被复制（存进成员）」——条件构造就不值。
两问都过，按值；否则回到 const&/&& 重载对。这正是 Item 26/27「避开万能引用重载」的
**正面出口**。C++20 concepts 出现后，第四条路（约束模板按值）重新开张，见演进节。

## 机制二：emplace 的四张暗账（Item 42）

1. **节点容器先分配后判断**：`std::list<T>::emplace_back` 必分配节点——即使随后构造抛异常，
   或 `std::set<T>::emplace` 撞重复键。`insert` 对「重复」的判断在构造之前（比较键即可），
   白分配/白构造的概率更低。🔧 示意：循环里 `s.emplace(v)` 与 `s.insert(v)` 在 `v` 重复时
   构造计数不同——list 场景节点分配器计数可见差异（本目录未单独留脚本，机理在
   [../C++标准库/03-STL总览.md](../C++标准库/03-STL总览.md) 的节点模型一节）。
2. **vector 无 reserve 时 emplace 更亏**：扩容路径上二者同构；不扩容时 emplace 省的是
   「临时对象的构造+析构」，若实参本身要构造临时，红利归零。
3. **异常保证的错位**：`v.emplace_back(f(), g())`——f 成功 g 抛，元素未构造、容器不变
   （基本保证仍在）；但 `l.emplace` 节点分配器可能已消耗，「强保证」场景别拿 emplace 当默认。
4. **Item 30 的回声**：转发失败清单（裸 `{}`、`0`、`std::array`）在 emplace 面前十倍放大——
   `m.emplace(std::make_pair(k, v))` 与 `m.try_emplace(k, v)` 的差别是**是否构造 pair**。

判据浓缩成一句：**构造元素是意图吗？** 是（args 直通就地构造）→ emplace；
否（已有对象，插入是意图）→ insert。性能神话（"emplace 永远更快"）败给分配器现实。

（Item 29）与「不确定就别标 noexcept」（Item 14）是同一句话的两半。

## 最新演进与工业实践

- **concepts 改写 Item 41/26/27 终局**：`void setName(std::same_as<std::string> auto n)`
  约束模板按值——单实现 + 精确错误信息 + 保留类别，旧三难（重载对/转发引用/按值）出现
  第四解（[cppreference concepts 页](https://en.cppreference.com/w/cpp/language/constraints)）。
- **C++17 保证消除 + CTAD**：移动成本模型更新后，Item 41 的「右值 2 移动」在多数
  `return` 路径被 prvalue 直构造替代；账本要按 C++17 重算。
- **`std::string_view`/`std::span`（C++17/20）修订 Item 41 的适用面**：只读形参不该按值拷
  string——「必复制」三问的答案在只读场景直接为否，view 类参数（2–3 字节的按值）才是正解；
  Abseil Tips 明确 `string_view` 按值传（[abseil/tips](https://abseil.io/tips/)）。
- **try_emplace/insert_or_assign（C++17）**：Item 42 讨论的「map 重复键白构造 pair」被
  标准库直接补刀——`try_emplace` 仅在键不存在时才构造 mapped——本书「insert 有时更稳」的
  场景一半被库吸收。
- **[[maybe_unused]]（C++17）与 std::source_location（C++20）**：接口微调层的两枚迟到补丁
  （前者服务 constexpr 裁枝与模板调试参数，后者替代 `__FILE__/__LINE__` 宏默认参）。
  🔧 source_location 实测（脚本 s7：`s7 at s7_post_book.cpp:51`，默认实参在**调用点**求值——
  这正是它能替代宏的机制根因）。
- **工业体现**：[fmt](https://github.com/fmtlib/fmt)/[std::format](https://en.cppreference.com/w/cpp/utility/format/format)
  的 `format_args` 是「按值 view + 类型擦除」的当代教科书实现；
  [Folly](https://github.com/facebook/folly) 的 `fbstring` 与小对象优化展示了
  「移动不总是廉价」的反例（Item 41 三问的库级验证）。
- **对本书结论的修订**：Item 41 三前提不变、工具箱变大；Item 42 在 map 域被
  `try_emplace` 接管大半，list/set 域的「节点白分配」教训永不过时。

## 常见误区

1. 「emplace 更快是定律」——在 `std::list` 的构造失败/重复键路径上它**多付**一次分配。
2. 「按值参数不能接右值」——恰恰相反；错的是「按值会拷贝一切」：按值 + move 对右值是
   构造直入（🔧 s4 的移动计数实测）。
3. 「Item 41 可以用于基类引用形参」——按值切割派生身份；多态形参永远 const&。
4. 「reserve 之后 emplace 就没有异常问题」——元素构造本身仍可抛；容器不变性来自
   分配器与构造顺序契约，不来自「反正不扩容」。
5. 「书收束 = 42 条背完」——收束的正确形态是三条元规则（本章上文）；条款会过时，
   账本方法论不过时。
