# 第 4 章 智能指针（Smart Pointers，Items 18–22）

> 对应原书第 4 章（Items 18–22）。单文件大纲见 [../Effective_Modern_C++.md](../Effective_Modern_C++.md)；
> 导航 [00-总览与阅读地图.md](00-总览与阅读地图.md)｜索引 [../C++系列·总索引.md](../C++系列·总索引.md)。
> 本章把「谁拥有资源」从注释和纪律升级为**类型系统可检查的事实**：
> 独占（unique_ptr）、共享（shared_ptr）、观测（weak_ptr）、制造（make 函数）、隐藏（Pimpl）。

## 核心概念速览（中英对照）

- **独占所有权** — exclusive ownership：`std::unique_ptr` 的语义契约；move-only、零运行时开销、可数组特化。
- **共享所有权** — shared ownership：`std::shared_ptr` 引用计数；拷贝廉价但**写计数非线程安全**。
- **控制块** — control block：存强/弱计数、删除器、分配器、`enable_shared_from_this` 钥匙的堆结构。
- **自定义删除器** — custom deleter：删除动作进类型（unique_ptr 模板参数）或进对象（shared_ptr 类型擦除）——
  前者污染类型、后者只占空间。
- **悬垂安全观测者** — dangling-safe observer (`std::weak_ptr`)：不延长生命期、以 `lock()`/`expired()` 判活。
- **制作函数** — make functions (`make_unique`/`make_shared`)：一次分配、异常安全、防止 `new T` 裸奔。
- **别名构造** — aliasing constructor：`shared_ptr<Inner>(outer_sp, &outer_sp->inner)`——共享生命期、指向成员。
- **Pimpl 惯用法** — Pimpl idiom：指向不完全类型的 `unique_ptr` 实现指针；编译防火墙 + ABI 稳定。
- **不完全类型** — incomplete type：只有声明没有定义的类型；其析构点必须在定义可见的翻译单元。

## 本章地图

| Item | 核心论点 |
| --- | --- |
| 18 | unique_ptr：默认零开销；自定义删除器改其类型（`std::function` 可抹平但付运行时税）；可转 shared_ptr，反之不可 |
| 19 | shared_ptr：控制块三词开销、拷贝赋值可能腾出「最后持有者」的销毁、`enable_shared_from_this` 的前提与坑 |
| 20 | weak_ptr：观测者 + 缓存句柄；无 `->`/`*` 是故意设计（判活必须过 `lock()`） |
| 21 | 优先 make：异常安全（C++11 求值序下）+ 单次分配；两个反例：自定义删除器、刻意控制分配（大对象/内存池） |
| 22 | Pimpl 的特种成员函数定义必须离开头文件（析构在 Impl 完整处），否则 unique_ptr 删除器编译失败或 UB |

## 动机：裸指针的三种罪

裸指针不回答三个问题：**谁释放？何时释放？现在还有效吗？** 智能指针把三者编码进类型：
unique_ptr 答「我，离开作用域时，必有效」；shared_ptr 答「最后一个持有者，计数归零时，必有效」；
weak_ptr 答「没人，只观测，可能无效」。选错类型的代价从「偶发崩溃」变成「可审计的设计缺陷」，
这就是本章 5 条的立法精神。

## 机制：五层展开

### 1. unique_ptr：零开销的边界（Item 18）

`unique_ptr<T, D>` 的删除器 `D` 若为**无捕获 lambda/函数指针/空类型（EBO）**，
对象尺寸等于裸指针；一旦 `D = std::function<void(T*)>`，尺寸膨胀且每次删除多一跳间接调用。
接口上 `operator*`/`->` 无空检查、`reset()`/`release()` 语义分明：`release()` 把所有权
**卸给裸指针**，是全家族唯一鼓励泄漏风险的口子——用了 `release()` 就必须立刻找到新主人。
数组特化 `unique_ptr<T[]>` 配 `operator[]`，与默认 `delete[]` 绑定——别拿标量版管数组。

### 2. shared_ptr 的控制块经济学（Item 19）

- 拷贝只增**原子**强计数（一次 `lock xadd` 级别的代价）；**对同一个 shared_ptr 对象**的并发
  读安全，写（换指向）不安全——「线程安全」的正确范围是**每个控制块**而非每个指针变量。
- 拷贝赋值的隐藏剧情：`sp1 = sp2;` 先自增 sp2 计数、再自减 sp1 旧目标计数——旧目标若恰是
  最后持有者，析构在赋值表达式里发生（异常/重入敏感点）。
- **一个资源两个控制块 = UB**（从裸指针各构造一个 shared_ptr）；`enable_shared_from_this`
  在对象非 shared 持有期间调 `shared_from_this()` 也是 UB/抛异常（C++17 起标准区分两种）。
- 多态删除的正确前提：基类析构 **virtual**，或构造时把派生类型信息带进控制块删除器。

### 3. make_shared 的双刃（Item 21 + 19）

单次分配（对象与控制块同块）意味着：① 分配次数减半、缓存友好；② **对象内存被弱计数拖住**——
只要还有一个 weak_ptr 活着，整块内存（含对象原本该释放的部分）不能归还分配器。
大对象 + 长命 weak_ptr 的缓存场景，`shared_ptr<T>(new T)` 反而合理；
自定义删除器（`make_unique` 无删除器重载）与「构造实参需更多重载控制」同理。

🔧 实测补充（本书 Item 21 的异常安全论证已过时一半）：C++11 的求值序允许
`f(std::shared_ptr<T>(new T), g())` 中 `g()` 抛异常泄漏 `new T`——这正是书里力荐 make 的案例；
**C++17 起实参表达式被保证「各自完整求值、互不穿插」**，该泄漏通道关闭
（[cppreference 求值序页](https://en.cppreference.com/w/cpp/language/eval_order)）。
结论不变（make 仍是默认），但论据从「救命」降级为「更快更整洁」。

### 4. weak_ptr 的两种人生（Item 20）

- **破环**：shared 图里的回边（观察者→被观察者、树的孩子→父亲）用 weak 断开。
- **判活缓存**：`lock()` 返回 shared_ptr 拷贝（成功则对象在你使用期间不会死），
  C++17 起用 `shared_ptr::reset()` 配 aliasing 的场合减少。无 `->`/`*` 的「不便」
  正是它把竞态窗口显式化的设计——`expired()` 后裸用旧地址仍是你的锅。

### 5. Pimpl：把「实现不可见」坚持到底（Item 22）

```cpp
// 🔧 已实测（脚本 s5_pimpl.cpp，仓库外，g++ 15.2 -std=gnu++23，输出 s5 ok: pimpl）
class WidgetImpl;                       // 头文件只需要这句话
class Widget {
public:
    explicit Widget(std::string n);
    ~Widget();                          // 声明在类内、定义在实现文件
    Widget(Widget&&) noexcept;          // 同上；=default 也必须放实现文件
    Widget& operator=(Widget&&) noexcept;
private:
    std::unique_ptr<WidgetImpl> pImpl;  // 析构器需要 WidgetImpl 完整
};
// 实现文件里：
Widget::Widget(std::string n) : pImpl(std::make_unique<WidgetImpl>(std::move(n))) {}
Widget::~Widget() = default;
```

为什么不能把 `~Widget() = default;` 写进头文件：unique_ptr 析构要 `delete` 一个指针，
此处 `WidgetImpl` 不完整——**要么编译失败（多数实现），要么删除器在 UB 上空指针**。
默认构造/移动同理：它们都要在某点销毁「构造失败」的对象。三条规则合成一句：
**凡 pImpl 宿主类的特种成员函数，其定义一律住进实现文件。**
🔧 实测陷阱：移动后宿主对象处于「pImpl 为空」的有效未定状态——再调 `name()` 即解空指针
（本章脚本对此特意加了注释并验证「只访问新宿主」的安全路径）。

## 权衡：三指针选型表

| 场景 | 选 | 放弃的 | 得到的 |
| --- | --- | --- | --- |
| 单一所有者、转移频繁 | unique_ptr | 共享能力 | 零开销、move-only 纪律 |
| 真共享（引用计数语义清晰） | shared_ptr | 性能与确定性析构 | 生命周期共担 |
| 只观测、可能悬垂 | weak_ptr（或裸引用） | 直接访问 | 判活契约 |
| 所有权不明 | **别用指针，拷值或引用** | — | 接口诚实 |

「用不了 unique 也别急着上 shared」是本章的暗线：多数「共享」其实是「谁都拥有」的逃避设计。

## 相邻概念对比

- **unique_ptr vs auto_ptr**：后者可拷贝且拷贝即窃——C++11 已弃用、C++17 移除；unique_ptr 用
  move-only 把窃取显式化（对照 [../C++语言的设计与演化.md](../C++语言的设计与演化.md) 的演化观）。
- **shared_ptr 引用计数 vs 所有权图**：计数只是**一种**所有权策略实现；D 语言/JS 的 GC 是另一种——
  书不讨论的边界。
- **`make_shared` vs `shared_ptr<T>(new T)`**：两次分配 vs 一次分配、weak 拖住内存 vs 对象先析构。
- **Pimpl vs 继承隐藏**：Pimpl 换「编译依赖 + ABI」，虚基类换「扩展点」；成本结构完全不同
  （接口的 ABI 稳定性论证见 [../C++API设计.md](../C++API设计.md)）。

## 最新演进与工业实践

- **`std::make_unique`（C++14）补票**：Item 21 标题的「make_unique 缺席理由」——
  C++11 漏掉它是因为提案（make_unique 的讨论）赶在标准化会议截止前未及并入 ⚠️ 过程细节未逐字核实；
  结果是「C++11 用 `new` 兜底、C++14 全面 make」的两代代码长期共存。
- **C++17 求值序修订**：如上节，Item 21 的异常安全论据被语言本身补掉（版本差异点：C++14 下仍成立）。
- **`std::atomic<std::shared_ptr>`（C++20）**：把「对同一指针变量的并发读写」补进标准（此前
  libstdc++/libc++ 有非标准 `__atomic_*`  overload；更常见做法仍是 `std::mutex`/自旋锁包一层）。
- **`std::out_ptr`/`std::inout_ptr`（C++23）**：对接 C API 的「填指针」调用
  （`FILE**`、COM out 参数），把 unique_ptr 安全地递进出参——所有权语义在 C++23 的新疆场。
- **工业体现**：[Abseil](https://github.com/abseil/abseil-cpp) 大量用 `std::unique_ptr`
  做工厂返回与测试夹具；[Folly](https://github.com/facebook/folly) 的 `folly::atomic_shared_ptr`
  是 C++20 之前的工业答案；本仓库实测笔记
  [../../cpp/cpp11-shared-ptr-notes.md](../../cpp/cpp11-shared-ptr-notes.md)、
  [../../cpp/unique_ptr.md](../../cpp/unique_ptr.md)、[../../cpp/shared_ptr.md](../../cpp/shared_ptr.md)。
  手写一遍控制块：[../现代C++实战30讲/02-自己动手实现智能指针.md](../现代C++实战30讲/02-自己动手实现智能指针.md)。
- **标准库视角**：智能指针在库层的位置与组合用法见 [../C++标准库/02-通用工具与智能指针.md](../C++标准库/02-通用工具与智能指针.md)。

## 常见误区

1. 「shared_ptr 是线程安全的」——计数安全，**指针变量**与**被指对象**都不安全。
2. 「从 `this` 随手 `shared_from_this()`」——对象不是 shared_ptr 持有时即 UB；构造函数里调也是 UB。
3. 「weak_ptr 只是 shared 的附属品」——它的独立价值是把「判活」变成显式 API；
   `lock()` 失败的分支处理是设计的一部分。
4. 「Pimpl = 运行时多态」——不是，Pimpl 是编译防火墙；虚函数开销为 0 的代价是改布局即破 ABI。
5. 「`make_unique<T[]>` 没有数组版」——C++14 起有（`make_unique<T[]>(n)`），书时代无；
   读老代码时注意这条版本断层。
