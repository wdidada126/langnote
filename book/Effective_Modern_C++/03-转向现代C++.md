# 第 3 章 转向现代 C++（Moving to Modern C++，Items 7–17）

> 对应原书第 3 章（Items 7–17，全书最长的一章）。单文件大纲见 [../Effective_Modern_C++.md](../Effective_Modern_C++.md)；
> 导航 [00-总览与阅读地图.md](00-总览与阅读地图.md)｜索引 [../C++系列·总索引.md](../C++系列·总索引.md)。
> 这一章是「C++98 惯用法 → C++11/14 惯用法」的总清算：初始化语法、空指针、别名、枚举、
> 函数禁用、覆盖、迭代器、异常规格、编译期求值、const 的线程契约、特种成员函数生成矩阵。

## 核心概念速览（中英对照）

- **统一初始化** — uniform initialization：`{}` 可承担一切初始化角色，且禁止窄化转换。
- **窄化转换** — narrowing conversion：大括号初始化被明令禁止的丢失性转换（浮点→整、`long long`→`int` 等）。
- **最令人头疼的解析** — most vexing parse：`Widget w(Args());` 被解析为函数声明，`{}` 是语法解药。
- **initializer_list 重载怪癖** — braced-init overload quirk：`std::vector<int> v(10)` 是 10 个 0，`v{10}` 是 1 个元素。
- **空指针字面量** — `nullptr`：类型 `std::nullptr_t`，可隐式转一切指针，不与整数重载纠缠。
- **别名声明** — alias declaration (`using`)：相比 typedef 多出的能力是**别名模板**。
- **有作用域枚举** — scoped enumeration (`enum class`)：枚举数不泄入外围作用域、不隐式转整、可控制底层类型与前置声明。
- **删除函数** — deleted function：`= delete` 在重载决议层直接出局，优于 private 未定义（后者到链接期才失败且仅对成员可见）。
- **override 指明符** — `override` specifier：把「想覆盖却重载」变成编译错误，并自带「不许再派生覆盖」的语义。
- **const 迭代器优先** — prefer `const_iterator`：`cbegin` 前时代靠 `auto it = c.cbegin()`；迭代器不可隐式转 const。
- **noexcept** — `noexcept`：不抛承诺；违约即 `std::terminate`；条件规格 `noexcept(expr)` 服务泛型代码。
- **constexpr** — `constexpr`：变量=编译期常量保证；函数=至少存在一条编译期求值路径；类型=constexpr 构造。
- **const 的线程契约** — thread safety of `const`：并发调不同对象的 const 成员必须安全；缓存字段用 `mutable std::atomic` 修补。
- **特种成员函数生成** — special member function generation：五大件（默认构造/析构/拷贝构造/拷贝赋值/移动两件套）的隐式声明与删除矩阵。
- **五规则/零规则** — Rule of Five / Rule of Zero：要么五个全写，要么靠 RAII 成员一个不写。

## 动机：这些不是语法糖，是语义契约的再分配

C++98 时代的每条惯用法都建立在「编译器不会帮你」的假设上；C++11/14 把其中一部分
变成语言保证（override 检测、窄化禁止、特种成员自动合成），把另一部分变成陷阱
（`NULL` 撞整数重载、`{}` 撞重载决议、隐式移动被用户析构抑制）。本章 11 条的共同主题是：
**知道哪些旧习惯已经被接管、哪些新默认值会咬人**。

## 机制：三组关键展开

### 1. `()` vs `{}`：一场三方混战（Item 7）

大括号初始化有三副面孔：普通聚合/列表初始化、`std::initializer_list` 形参匹配、
空列表 `Widget w{};` 的值初始化。危险点在第二副面孔：**只要有一个重载吃
`std::initializer_list`，大括号实参优先走它**。`std::vector` 因此分裂出两种宇宙：

```cpp
// 🔧 已实测（对照 s4 与本章验证，g++ 15.2 -std=gnu++23）：
std::vector<int> a(10);   // 10 个元素，全 0
std::vector<int> b{10};   // 1 个元素：10
std::vector<int> c{10, 1}; // 2 个元素：10 和 1
std::vector<int> d(10, 1); // 10 个元素，全 1（无对应 initializer_list 语义时退回普通构造）
```

另两个边角：`Widget w1();` 是函数声明（most vexing parse 变体），`Widget w2{};` 才是对象；
`std::function` 形参接收 `{}` 时歧义到编译失败。结论：默认用 `{}`，两处例外——
① 明确要「构造实参转发」语义的容器 size 构造（写 `()` 或 `reserve+emplace`）；
② 数值变量愿意接受窄化时（`double d = 1.5; int i(d)` 的旧代码迁移）。

### 2. noexcept 的三段论（Item 14）

- **语义**：`noexcept` 参与类型系统（`f() noexcept` 与 `f()` 是不同类型，但可隐式互转，
  函数指针例外要写全）；违约不抛异常而是 `std::terminate`——所以「不确定别乱标」是诚实的默认。
- **算法**：STL 用 `std::move_if_noexcept` 在「移动」与「拷贝」之间做选择：容器扩容时，
  只有 noexcept 移动才能保证强异常保证。🔧 已实测（见 [05 章](05-右值移动完美转发.md)：noexcept 移动的
  自定义类型在 `vector` 扩容时 moves=15 copies=0；去掉 noexcept 后行为随实现，libstdc++ 退回拷贝）。
- **条件规格**：泛型代码写 `noexcept(noexcept(expr))`——内层是运算符，外层是规格；
  编译器在推导 noexcept 运算符时只看表达式是否会求值抛出（含函数自身的规格）。

### 3. 特种成员函数生成矩阵（Item 17）

C++11 的默认策略：**你没写，我就按需生成；但你声明了任何相关件，我就不越权**。

```text
写了析构函数          → 移动构造/移动赋值 不再隐式生成（拷贝仍生成，已废弃倾向）
写了拷贝构造或拷贝赋值  → 移动两件套 不再隐式生成
写了移动两件套任意一个  → 拷贝两件套 + 默认构造被删除（移动后拷贝不安全，必须显式）
任何成员不可拷贝/不可移动 → 对应特种函数被「删除」而非「未声明」
```

后果链：给类加一个**空的**析构函数，等于让它退出移动优化（退回拷贝）——
这正是「用户声明析构抑制移动」在 C++11 里的硬事实。五规则是 C++03 三规则在移动时代的补丁；
零规则（成员全是 RAII 类型 → 五大件全默认）才是 C++11+ 的正解。
🔧 已实测：`Legacy{ ~Legacy(){} }` 的 `vector` 扩容计数 copies=15/moves=0，
补 `noexcept` 移动后 moves=15/copies=0（脚本 `s4_special_members.cpp`，仓库外）。

### 4. const 的线程安全契约（Item 16）

「多个线程读同一对象」要求 `const` 成员函数之间零数据竞争。缓存字段（memoization）是经典违例：
逻辑 const、物理写。书的三级解药：① `const_cast` 加锁（丑）；② 用 `mutable std::atomic<T>`
包装缓存（无锁字段可用 `load/store` + `memory_order`，书中给出 `compare_exchange_strong` 版）；
③ 整个对象 `std::shared_mutex` 保护（并发读代价）。这为 [07 章](07-并发API.md) Item 40 的
atomic 讨论埋线：`mutable std::atomic` 不是并发设计，只是 const 正确性的补救。

## 权衡与相邻概念对比

- **enum class vs int 常量组**：前者类型安全 + 可前置声明，代价是没有隐式转整（需要 `std::to_underlying`
  或 C++14 的 `static_cast<std::underlying_type_t<E>>(e)`）——`constexpr auto` 常量对象是第三条路，
  但缺少枚举的「一组值」语义。
- **alias vs typedef**：等价于「能不能模板化 + 能不能少写一次名字」；调试器/报错文本里
  别名可读性更高（模板展开后 typedef 露出真实类型，别名保留 `using` 名，随实现而异 ⚠️）。
- **`=delete` vs private 未定义**：删除在**重载决议**阶段出局，任何调用者都收到清晰错误；
  private 未定义只对非成员出局，且失败在链接期。删除还有独门用法：禁止 `f(int)` 接 `bool`、
  禁止 `new`（删 `operator new`）/禁止栈对象（删构造+析构，需要 friend 的派生类豁免）。
- **`constexpr` vs `const`**：`const` 是「不可改」，`constexpr` 是「编译期可求值」——
  `const T x = f();` 里 f 可以运行期才返回；constexpr 变量保证进入只读段/模板实参可用。
- **`constexpr` 函数 vs 模板元编程**：C++14 放宽后（循环、分支、`auto` 返回、修改局部变量），
  大量 `std::integral_constant` 递归可以用普通 constexpr 函数替代，可读性碾压（本仓库
  [../C++模板元编程.md](../C++模板元编程.md) 时代的旧写法与本书对照阅读）。

## 最新演进与工业实践

- **if constexpr（C++17）** 终结了 Item 14/15 时代泛型代码的标签分派主流写法：
  `if constexpr (std::is_integral_v<T>)` 编译期裁掉不可行分支；语法定案文档
  [P0292R2「constexpr if: A slightly different syntax」](https://wg21.link/P0292R2)（Jens Maurer，
  经 wg21.link 解析核实存在）。当年口号「Tag Dispatching is out. If-constexpr is in!」
  出自 VC++ 团队博客（Billy O'Neal，2015）⚠️ 原 URL 本次未核实，观点本身已被标准采纳坐实。
- **[[maybe_unused]]（C++17）** 解决 `constexpr` 分支裁掉后「变量未使用」警告——Item 15
  「能用 constexpr 就用」在警告层面的配套补丁。
- **constexpr 的 C++20/23/26 连跳**：constexpr 虚函数？未发生 ⚠️；已落地：constexpr `new`/`std::string`
  操作、`std::vector` 的 constexpr 化（C++26 提案链）持续推进——书口径「函数能用就用」不变，
  但「constexpr 即更快」的误读（见常见误区）在 libc++/libstdc++ 的 constexpr 容器支持后更需警惕。
- **C++20 `constinit` / `std::source_location`**：前者把「静态初始化序」显式化，
  后者替代 `__FILE__/__LINE__` 宏在日志接口里打点（🔧 已实测，见 [09 篇](09-专题-书后演进时间线.md)）。
- **`std::to_underlying`（C++23）** 补上 enum class 的「取底」一步。
- **工业体现**：[GSL（Guidelines Support Library）](https://github.com/isocpp/CppCoreGuidelines)
  的 `not_null<T>` 把 Item 8 的 nullptr 讨论升级为「接口禁止空指针」；
  本仓库登记见 [../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md)。
  [fmt](https://github.com/fmtlib/fmt) 用 `FMT_COMPILE_STRING` 等技巧把「编译期格式串」做成生态标配
  ——constexpr 能力边界的工业推手。

## 常见误区

1. 「`{}` 永远安全」——`vector<int> v{10}` 与 `v(10)` 的语义分裂是本书点名的高频事故。
2. 「标了 noexcept 更快」——收益在**移动选择/终止路径**而非单次调用；`noexcept` 函数内抛异常
   不是「更快失败」而是直接 terminate。
3. 「写了析构函数只是习惯」——它会静默关掉整个类的移动通道（Item 17 矩阵）。
4. 「enum class 没有隐式转换，用着不方便，干脆别用」——不便正是安全；桥用
   `underlying_type_cast` 或 `to_underlying` 显式搭。
5. 「编译器生成的特种函数是 C++11 新语法」——生成规则是核心语言语义变更，不是库；
   与对象模型的关系可对照 [../深度探索C++对象模型.md](../深度探索C++对象模型.md)。
