## 三条阅读主线

1. **语义基座线（推导 → auto → 右值/转发）**：`01` → `02` → `05`。
   模板/auto/decltype 三套推导规则是全书一切「现代写法」的地基；移动与转发引用是它的消费端。
2. **资源与抽象线（智能指针 → lambda → Pimpl）**：`04` → `06`（+`03` 的 Item 22/17）。
   所有权显式化 + 闭包即对象，这两条改变了接口设计的成本结构。
3. **并发与性能线（并发 API → 微调）**：`07` → `08` → `09`。
   42 条里最「保值」的部分（任务 vs 线程、atomic vs volatile）恰是 C++17/20 改动最多的部分，
   必须配着第 09 篇的口径修订读。

**最短路径（老代码现代化改造者）**：`05` → `04` → `06` → `07`（Items 35–37）→ `08`。

## 为什么 2026 年仍然值得读

- **C++11/14 已是存量代码基线**：工业界主流 ABI 与代码规范（Google/Chromium/Unreal/各大厂内部风格）
  的最低门径仍是 C++14/17；本书 42 条针对的正是这块「已落地但未精通」的语料。
- **机制不变，口径演化**：引用折叠规则、转发引用的推导、控制块布局、noexcept 与 vector 强保证的
  关系，这些机制在 C++17/20/23/26 里一个字没改；改的只是「推荐写法」（CTAD、if constexpr、
  string_view/span、jthread、std::execution）。读本书读的是**为什么**，第 09 篇告诉你**现在怎么写**。
- **它预言了后十年的议程**：packages/tasks（Item 35 之延伸）→ P2300R10 `std::execution`（已核实存在，
  2024，见 [09 篇](09-专题-书后演进时间线.md)）；「基于任务而非线程」在 jthread/协程时代成为共识。
- **配套书目**：并发细节去 [../C++并发编程实战2/00-总览与阅读地图.md](../C++并发编程实战2/00-总览与阅读地图.md)，

## 读完应该能回答的十个问题

2. `auto x = expr;` 与 `auto x{expr};` 的推导差异从哪条规则来？（`01`、`02`）
3. 为什么 `std::move` 不移动任何东西？`std::forward` 与它的本质区别？（`05`）
4. `T&&` 何时是转发引用、何时是右值引用？判定程序是什么？（`05`）
5. make_shared 的「单次分配」在什么时候反而有害？（`04`）
6. Pimpl 里为什么析构函数必须「声明在类内、定义在实现文件」？（`03`、`04`）
7. `[=]` 捕获在成员函数里埋了什么悬垂雷？C++20 如何改口？（`06`）
8. deferred 任务会被谁「偷走执行」？void future 为什么能修好一次性事件通知的竞态？（`07`）
9. `std::atomic` 与 `volatile` 各自的不可替换场景？（`07`）
