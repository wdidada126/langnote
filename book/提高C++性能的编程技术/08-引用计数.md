# 08 · 引用计数：共享所有权的账本（原书第 12 章）

> 覆盖：12.1 实现细节、12.2 已存在的类、12.3 并发引用计数、12.4 要点。
> 大纲版见 [../提高C++性能的编程技术.md](../提高C++性能的编程技术.md)；总览见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

## 核心概念速览（中英对照）

- **引用计数** — Reference Counting：对象随附共享计数器，每引用 +1、每释放 -1、归零销毁——所有权协议最古老的一种。
- **计数句柄** — Handle/Ballot 分离：把计数放进独立的 Ballot（控制块），被计数对象与句柄解耦；12.1 的核心结构。
- **`op=` 的自赋值陷阱** — Self-Assignment：`x = x` 时先释放后拷贝会杀死自己——书中用"先加后减"顺序免疫，`shared_ptr::swap` 是制度化答案。
- **写时复制** — Copy on Write (COW)：计数 >1 时共享，真写才深拷——12.2"已存在的类"的标杆应用（当年 `std::string` 的主流实现）。
- **并发引用计数** — Concurrent Reference Counting：++/-- 必须原子，否则计数丢失→提前释放（use-after-free）或永不释放（泄漏）。
- **原子税** — Atomic RMW Tax：`lock xadd/cmpxchg` 抢缓存行所有权——计数本身成为跨核热点。
- **非原子快照** — Atomic Snapshot / Adorned Bits：把计数与标志位打包进单字，一次原子操作读改整包；"Scalable Objects Are Locally Adorned"（Harris et al. ⚠️ 无 DOI 核到，会议论文 2005 系）一脉。
- **循环引用** — Cyclic Reference：计数协议的结构性死穴：互相引用的对子永不归零。

## 动机：为什么"聪明的指针"是性能技术而不是语法糖

12 章开场场景（对照目录重写）：巨型对象（如 12.1 的 `String`/位图类）构造贵、拷贝更贵，
而程序里"同一份数据被 N 个持有者分享"普遍存在。深拷贝 = N 份内存 + N 份构造；
引用计数 = 1 份数据 + N 个指针字。它同时是**内存技术**（共享）与**时间技术**（拷贝变指针赋值）。
代价则全部压在两行 `++/--` 上——本章后半部分就是把这两行在不同线程假设下的价格标出来。

结构上 12.1 坚持三件套（这套骨架今天原样活在 libstdc++ 的 `__shared_ptr` 里）：

```cpp
// 🔧 12.1 骨架的极简重写
template <class T> class RC {
    struct Ballot { long refs; T* obj; };   // 控制块：计数与共享资源同生共死
    Ballot* b_;
public:
    RC(T* p) : b_(new Ballot{1, p}) {}
    RC(const RC& o) : b_(o.b_) { ++b_->refs; }                    // 拷贝=加一
    RC& operator=(RC o) { swap(o.b_, b_); return *this; }         // copy&swap：自赋值免疫
    ~RC() { if (--b_->refs == 0) { delete b_->obj; delete b_; } } // 归零=销毁
};
```

## 机制 → 实测：并发把一切变贵（00 总表 #5）

**先看不原子的坏消息**（12.3 的机制面）：`++refs` 编译成 load-add-store 三步；两个核同时做，
一个加值被另一个覆盖——计数偏小 → **提前 delete**（堆损坏）或偏大 → 泄漏。这不是理论洁癖，
是共享库多线程崩溃的头号成因之一。修法：`lock` 前缀原子。

已实测 g++ 15.2 -O2（1 亿次拷贝赋值循环，本机单次样本；手写 RefPtr 复制/析构路径，
`std::atomic<long>` vs `long` 计数）：

| 计数实现 | 耗时 | 反汇编证据 |
| --- | --- | --- |
| 普通 `long` | 51.2 ms | `inc/dec` 或 `addq $1`（寄存器/内存直读直写） |
| `std::atomic<long>` | **330.7 ms（6.5×）** | `lock addl $0x1,(%rbx)`、`lock subl $0x1,(%rax)` |

一次 `op=` 含两次原子 RMW（新 +1、旧 -1），每条约 20–30 ns 量级——**热点对象每传一次引用
付一次缓存行所有权迁移**。这就是今天 `shared_ptr` 按值传参进性能圈子被反复警告的物理原因
（✅ 通行实践：`const shared_ptr&` 或裸引用传参；只有要共享所有权时才 ++）。

## 权衡：12.2 "已存在的类"与 COW 的教训

书中 12.2 盘点可挂计数的宿主（String、大位图、解析树节点）；1990 年代末 `std::string` 的
主流实现正是 COW（Copy-On-Write），此后历史给出了反转判词（✅ 标准事实）：

- COW 让"读共享"便宜，但任何写触发分裂深拷——**`operator[]` 是否可免拷返回**成了语意噩梦，
  C++11 明令禁止 `std::string` 的 COW（非 const `operator[]` 必须可 `&s[0]` 改写后不影响副本）；
- 多线程下 COW 的检查-写回本身又需要原子/锁，收益被 [05 章](05-多线程内存池与锁定策略.md)式锁税吃光；
- SSO（短串本地缓冲）+ 移动语义提供了 COW 想解决的问题的更优解：小串零堆、大串转让所有权。
  见 [../Effective_Modern_C++/05-右值移动完美转发.md](../Effective_Modern_C++/05-右值移动完美转发.md)。

| 策略 | 拷贝成本 | 写成本 | 线程成本 | 循环引用 | 现代处境 |
| --- | --- | --- | --- | --- | --- |
| 深拷贝 | 高 | 无 | 零（各自私有） | 免疫 | 移动语义已大半救活 |
| 引用计数 | 一次 ++ | 无（人人可写=共写） | 原子税 | ❌ 需弱引用 | `shared_ptr`，慎用按值 |
| COW | 一次 ++ | 首次写深拷 | 原子税+语意坑 | ❌ | 标准禁用 |
| `unique_ptr`/所有权树 | 不可拷，移动=搬指针 | 无 | 零 | 结构上罕见 | 默认首选 ✅ |

## 相邻概念对比

- **vs [04 章](04-单线程内存池.md)内存池**：都在处理"对象生死的账"——池管**分配**路径，计数管**释放时机**；书中版本1 池 + RC 句柄是当年组合拳，今天对应 pmr arena + `unique_ptr`。
- **vs GC**：计数=确定性析构、O(1) 元数据、无停顿，但所有权成环即死；GC 处理环但牺牲时机确定性与停顿预算。12 章末与 Java 对照的论点今天仍是选型常识。
- **vs `weak_ptr`**：环的官方解药——观察不计数；控制块拆强/弱双计数正是 12.1 Ballot 设计的延伸（✅ libstdc++ 实现结构）。

## 最新演进与工业实践

- **`std::shared_ptr` 赢下标准战场，但输掉热路径**：控制块原子计数与本章完全同构；工业对策——
  Chromium `scoped_refptr`（要求类型自带 `AddRef/Release`，线程模型上很多只在单序列流转 ⚠️ 泛称）、
  Windows `Interlocked` 系、Rust `Arc`（同为原子计数，编译器保证不丢 `--`）。
- **非原子计数的合法化生存**：单线程/无所有权跨界场景显式换回非原子——`intrusive_ptr` 配
  非原子计数（Boost/Seastar 模式）、Folly 的 `RCURefPtr`（读侧几乎零开销，宽限期机制替代计数递减热点 ⚠️ 细节以 folly 文档为准）。
- **缓存行级优化**：现代分配器把控制块与对象**合并分配**（`make_shared` 同款效果：少一次分配、
  同缓存行——但延长对象内存占用至弱引用清零 ⚠️ 通行权衡），是 12.1 "Ballot 独立 new"的修正。
- **写时复制的转世**：数据库页/OS fork 的 COW 依然红火（页粒度+硬件支持），失败只在**语言级小对象**
  层面——粒度与竞争频率决定 COW 生死，这条判据比本书表述更普适（本目录观点）。
- **结论**：第 12 章的**结构知识（控制块三件套、自赋值顺序、环与弱引用）完全成立**；
  COW 应用层路线已死；"引用计数是免费的聪明"这个 90 年代幻想被 6.5× 原子税实测正式埋葬——
  今天的第一建议永远是**先 `unique_ptr`/借用，计数是最后手段**。

## 机制补充：环与弱引用的最小标本

```cpp
// 🔧 12.4 要点里"计数死穴"的示意
struct Node { std::shared_ptr<Node> next; };   // 只有强引用
Node* leak_demo() {
    auto a = std::make_shared<Node>(), b = std::make_shared<Node>();
    a->next = b; b->next = a;                  // a、b 计数各=2
    return nullptr;                            // 离开作用域各-1 → 仍=1，永不归零：整环泄漏
}
// 解法：所有权方向用 shared_ptr，反向观察用 weak_ptr（不计数，lock() 时原子地验尸）
```

`weak_ptr::lock()` 必须"检查未过期 + 临时加一"两步原子完成，否则对象可在两步之间被别的
线程复活销毁——这就是控制块要拆**强/弱双计数**的原因（✅ libstdc++/MSVC 结构一致）；
12.1 的单计数 Ballot 在这里欠了一笔债，`shared_ptr` 替它还了。

## 常见误区与自查

- **误区 1："shared_ptr 拷贝不安全因为计数会竞争"**——libstdc++/MSVC 的计数**是**原子的
  （就是实测那 6.5× 的来源）；真正不安全的是对**同一个 shared_ptr 对象**的并发读写
  （控制块原子≠指针变量原子）——[../C++并发编程实战2/03-线程间共享数据.md](../C++并发编程实战2/03-线程间共享数据.md) 有专节。
- **误区 2："用引用计数就能免费共享"**——析构线程可能与分配线程不同 → 跨线程释放（[05 章](05-多线程内存池与锁定策略.md)
  的归还问题）+ 最后一次 -1 触发的连锁析构出现在完全意想不到的调用点（延迟尖刺）。
- **误区 3："工厂返回 shared_ptr 是好默认"**——现代准则：只观察返回裸引用/指针，独占返回
  `unique_ptr`，**确需共享所有权**才 `shared_ptr`（Effective Modern C++ item 18–21 谱系）。
- **自查**：给最热的智能指针类型数一次"每事务 ++/-- 次数"；若它出现在 cache line 争用榜
  （perf c2c），考虑侵入式计数+线程局部分片，或干脆改用 RCU/生命周期借用。
