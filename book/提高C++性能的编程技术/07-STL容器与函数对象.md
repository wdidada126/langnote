> 大纲版见 [../提高C++性能的编程技术.md](../提高C++性能的编程技术.md)；总览见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

## 核心概念速览（中英对照）

- **渐近复杂度** — Asymptotic Complexity (Big-O)：选型第一关；本书开宗明义——Big-O 相同不代表常数相同，Big-O 更好也不代表小 n 时更快。
- **插入剖面** — Insertion Profiles：`vector` 中间插=搬尾巴 O(n) 但连续；`list` 插=O(1) 指针手术但造节点+断局部性。
- **重分配风暴** — Reallocation Storm：`vector` 扩容的几何增长（倍增策略摊还 O(1)），峰值翻倍内存与迭代器全体失效。
- **节点容器** — Node-based Container：`list`/`set`/`map`（前哈希时代）每元素一坨堆分配+指针跳转——本书火力集中处。
- **遍历成本** — Traversal Cost：`list` 遍历是指针追逐（每跳一次缓存未命中），`vector` 是预取流水线的乐园。
- **查找** — Lookup：有序 `vector`+`binary_search` 对 `set` 的树 Chase，n 大时反而常胜（对数×缓存惩罚 vs 线性×预取）。
- **函数对象** — Function Object (Functor)：以 operator() 携带比较/运算策略——**可内联、可携带状态、类型即策略**。
- **函数指针税** — Function Pointer Tax：`qsort` 式回调=间接调用+无法内联+参数强制擦除为 `void*`。
- **比 STL 更好？** — Better than STL?：11.7 讨论自带"知道得更多"的定制容器——天下没有白拿的通用性。

## 动机：1999 年的两场 STL 论战，本书站哪边

90 年代末"STL 慢"是工程界流行病（节点分配贵、模板编译痛、当年实现参差）。第 11 章的立场
罕见地平衡：**用机制分析代替站队**——先 11.1 立 Big-O 规矩，再把插入/删除/遍历/查找四个
动作逐容器解剖常数因子。它戳破的两个神话至今有效：

1. "`list` 插入 O(1) 所以插入多用它"——你没算每次 `new Node`（回到 [04 章](04-单线程内存池.md)的税单）和后续遍历的指针追逐；
2. "`vector` 中间插入 O(n) 所以绝对不能"——O(n) 个**连续字节搬移**常常快过 O(1) 次**冷内存指针跳转**，直到 n 大到惩罚显现。

## 机制：常数因子的三层来源

```text
容器操作真实成本 = 算法复杂度 × 内存布局常数 × 分配器常数
```

- **内存布局**：`vector` 元素间地址相邻，硬件预取器自动跟车；`list` 节点散落在堆各处
  （分配顺序决定，见 [10 章](10-可扩展性与系统体系结构.md)存储器层级），每 `it++` 都是一次
  数据 cache miss + 一次不可预测的跳转（`jmp` 到 `it->_Next`，分支预测器懵）。书中实测
  list 遍历比等规模 vector 慢一个量级级差 ⚠️ 具体数字未复核，机制方向无疑。
- **分配粒度**：`std::list`/树容器每元素 1 次节点分配（1999 年 malloc 是全局锁+搜索的贵货）；
  `vector` 整段连续分配——分配次数差 n 倍。这正是 [04 章](04-单线程内存池.md)池化后 STL 容器
  自动受益的通道（换分配器不改代码）。
- **函数对象 vs 指针**：`sort(v.begin(), v.end(), Cmp())` 里 Cmp 类型编译期已知，
  比较体直接内联进循环、无间接调用；`qsort` 的 `int(*)(const void*,const void*)` 每次比较
  三笔税：擦除进 `void*`（反强转）、间接 call、无法向量化。这是 [02 章](02-虚函数开销与模板继承.md)
  "间接调用阻断优化"论断在库层的翻版，也是侯捷《STL源码剖析》反复强调"函数对象第一等公民"的性能理由。

**删除/遍历/查找**（11.3–11.5）的要点浓缩：`list::erase(pos)` 本身 O(1) 但要 O(n) 找到 pos；
`vector` 区间 `erase` 是一次搬移（且**不缩容**——容量与大小分家）；有序 vector 二分查找的
对数趟数每次都是冷跳转，但趟数×惩罚常常仍小于无序线性的元素数×预取红利；关联式容器
（`set/map`）红黑树的中序遍历=节点指针追逐+缓存不友好，11.5 的批量查找建议"能预排序就预排序"。

## 权衡与相邻概念对比

| 需求 | 书中时代答案 | 机制理由 |
| --- | --- | --- |
| 大量尾部增删 | `vector`（摊还 O(1)，预留增长） | 连续+倍增；`list` 尾插每元素一节点 |
| 迭代器稳定的中间插 | `list`（仅当 n 大且真需稳定） | 指针手术不搬邻居 |
| 只读查找集 | 有序 `vector`+`binary_search` | 缓存税对数 vs 线性——大 n 反转 |
| 按键聚合 | `map`（当年无哈希） | 11.7 已预言"哈希表更优"的空白 |
| 小 n（<16） | 朴素线性扫描 | Big-O 交叉点未到达，常数统治 |

## 最新演进与工业实践

- **flat 容器时代**（✅ 标准事实，C++23）：`std::flat_map`/`flat_set` 把"有序 vector+二分"标准化
  ——当年 11.5 的民间智慧升格为接口；本仓库口径注意：[../C++标准库/04-容器.md](../C++标准库/04-容器.md)
  覆盖到 C++11，flat 容器超出之 ⚠️。
- **哈希进场**：C++11 `unordered_map` 补上 11.7 的空缺；但主流实现（abseil `flat_hash_map`、
  `folly::F14FastMap`）走的仍是"**连续内存 + SIMD 探测**"路线——abseil 用一组控制字节做
  16 路 SSE 匹配（Swiss Table，⚠️ 论文《Abseil Containers: flat_hash_map》设计说明以官方文档为准，
  本次未连通核验），Folly F14 用 SIMD 14 槽桶——**本书"布局>指针追逐"的判据在新战场全胜**。
- **`std::function` 反例**：类型擦除把函数对象的"可内联"红利没收（堆缓冲+间接调用）——
  热回调用模板参数或 `__attribute__((always_inline))` 手写跳板；详见 [../C++标准库/06-函数对象与Lambda.md](../C++标准库/06-函数对象与Lambda.md)。
- **emplace 与分配税**：C++11 `emplace_back` 就地构造省临时（接 [03 章](03-返回值优化RVO与临时对象.md)），
  但节点容器仍每元素一次分配；池化通道制度化：`std::pmr::vector/list` + `polymorphic_allocator`（C++17）。
  SGI 时代"给容器换 allocator 模板参数"的路已因非均匀内存上下文被标准废弃——新旧配置器对比精读见
  [../STL源码剖析/07-专题-SGI_STL到现代标准库.md](../STL源码剖析/07-专题-SGI_STL到现代标准库.md)。
- **游戏行业答案**：数据导向设计流派（Scott Turner《Data-Oriented Design》2012 及 GDC 相关演讲 ⚠️ 无 DOI，具体篇目本次未核验）把 11 章的直觉工程化为"紧凑数组 + 索引代指针"——节点容器代价论的产业化版本。
- **结论**：第 11 章是全书**保鲜度最高**的一章：Big-O 与常数因子的双层决策框架一字不用改，
  只是具体容器名单换代（list↓、flat↑、unordered 走 SIMD）；"比 STL 更好？"的答案也稳定——
  定制赢在知道得更多、输在维护税，2026 年依旧。

## 代码标本：同一排序的两种回调税

```cpp
// 🔧 教学示意：11.6 论点的现代最小样本
int cmp_qsort(const void* a, const void* b) {           // 税1: 参数擦成 void*
    return *(const double*)a - *(const double*)b ? 1 : -1;
}
qsort(data, n, sizeof(double), cmp_qsort);              // 税2: 每次比较一次间接 call，不可内联

struct Cmp { bool operator()(double a, double b) const { return a < b; } };
std::sort(data, data + n, Cmp());                       // 类型即策略：比较体直接内联进排序循环
// C++11 后：std::sort(begin, end, [](double a, double b){ return a < b; });  // 闭包=匿名函数对象，同权红利
```

一次都看不出差别（数据小、比较廉）？把比较换成"带字符串解引用"再测——差异就是
11.6 的全部论点。同理 `set::find` 与 `std::binary_search(vec)`：前者每层一次冷节点跳转，
后者对数趟但趟趟命中预取器（11.5 的实战结论）。

## 常见误区与自查

- **误区 1："Big-O 好就赢了"**——11.1 亲自立的反例框架：n=8 时 O(n²) 插入排序胜一切
  （introsort 的前身理由），常数是另一半真理。
- **误区 2："vector 中间插入要整体搬，太可怕"**——搬的是 memcpy 级连续字节；
  1MB 数据在 10GB/s+ 内存带宽前是 100μs 量级（⚠️ 依代际），真正常驻热区时反而快过 list 的冷节点。
- **误区 3："函数对象语法丑，用 std::function 统一"**——`std::function` 正是把 functor 的
  编译期类型退化成运行期擦除——11.6 赢下的税单原样付回去（见 [../C++标准库/06-函数对象与Lambda.md](../C++标准库/06-函数对象与Lambda.md)）。
- **自查**：容器选型三问——①尺寸是否编译期已知/稳定？②热点是遍历、查找还是插删？
  ③失效规则允许我缓存指针/迭代器吗？答不出③的人都会回炉 [../C++标准库/04-容器.md](../C++标准库/04-容器.md)。
