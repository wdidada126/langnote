# 05 · 多线程内存池与锁定策略（原书第 7 章）

> 覆盖：7.1 版本4（多线程内存池实现）、7.2 版本5（快速锁定 Fast Locking）、7.3 要点。
> 大纲版见 [../提高C++性能的编程技术.md](../提高C++性能的编程技术.md)；总览见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

## 核心概念速览（中英对照）

- **多线程内存池** — Multithreaded Memory Pool：版本 3 的单线程池加锁改造的产物（版本4）；本书并发分配器叙事的起点。
- **全局锁池** — Globally Locked Pool：整池一把锁——正确但把并行度压成串行，锁竞争即新瓶颈。
- **锁内嵌对象** — Lock-per-Pool-Manager：把锁嵌进池管理器，语义同全局锁，只是封装位置不同（书中对旧式 `Guard` 类的修正）。
- **快速锁定** — Fast Locking：版本5 的灵魂——先用原子操作"试探"（无竞争则不进真锁），竞争真发生才付互斥的成本。
- **自旋锁** — Spin Lock：以原子 test-and-set/exchange 忙等的锁；短临界区之王，长等待/优先级反转之敌。
- **每线程缓存（预告）** — Thread Caching：本书止步处，恰是现代分配器的分岔口——线程私有池命中即免锁。
- **伪共享（预告）** — False Sharing：多线程池相邻块被不同核频繁摸碰，缓存一致性协议空转——第 15/16 章正式展开。
- **锁粒度** — Lock Granularity：一池一锁 vs 一分箱一锁 vs 无锁；本书第 15 章 15.8 回扣本问题。

## 动机：一把锁如何毁掉 13 倍收益

[04 章](04-单线程内存池.md)实测单线程池比 new/delete 快 13 倍。把同样的池开 8 线程跑：
所有线程在**同一把锁**的排队上互相踩踏——临界区再小，锁本身是一次原子 RMW
（`lock cmpxchg`/`lock xchg`，实测见 [08 章](08-引用计数.md)的 lock 指令讨论），缓存行
在核间来回失效（MESI 的所有权迁移，几十~几百 ns ⚠️ 周期数依硬件）。分配器从"加速泵"
变成"串行沙漏"，多线程扩展性曲线在第 2~4 核就躺平——这正是本书第 15 章 Amdahl 叙事的
分配器特例。

## 机制：版本 4 → 版本 5 的两级台阶

**版本 4（7.1）**：把版本 3 的管理函数全部裹进 `Guard g(lock)` 的 RAII 作用域。
书里两个当时的洞见今天仍然值得默写：

1. 锁要**池持有**（对象成员），不要靠调用方记得加——"易错的协议要封装成不可错的类型"，
   RAII 锁管理（`std::lock_guard` 的前世）在 1999 年还得手写；
2. 即便单线程程序也在付锁税：多数 Unix 运行时"安全就算没人竞争也走一遍锁"——所以
   "我还没多线程"不构成豁免理由，锁的设计要面向**未来线程化**。

**版本 5（7.2 快速锁定）**：核心直觉——**绝大多数锁操作发生在无竞争时刻**，
为偶发的竞争为每次常态付互斥的系统调用/内核等待成本不值。实现骨架（🔧 教学示意重写）：

```cpp
// 🔧 版本5 思想的现代原子重写（原书用测试-并-设置原语）
class FastLock {
    std::atomic_flag f_ = ATOMIC_FLAG_INIT;
public:
    void lock()   { while (f_.test_and_set(std::memory_order_acquire)) { /* 自旋/退避 */ } }
    void unlock() { f_.clear(std::memory_order_release); }
};
// 分配快路径：FreeList::push_head 用一次 CAS 完成"无人抢则我拿"，
// 失败(=有竞争)才升级到真锁保护的慢路径。
```

权衡很直白：自旋烧 CPU（超线程/单核上是纯浪费），内核互斥可睡眠让出核；
现代做法是**混合**——先自旋 N 次再 futex 挂起（glibc/pthread 的默认策略即如此 ⚠️ 依实现）。

**本书停步之处**：版本 5 仍是一池（分箱）一锁。作者自己承认终极方案在"线程私有的空闲链"
方向上——这就是下一节的现代补完。

## 权衡与相邻概念对比

| 方案 | 无竞争成本 | 竞争成本 | 复杂度 | 对应 |
| --- | --- | --- | --- | --- |
| 全局锁池 | 一次原子锁 | 全序列化 | 低 | 版本4 |
| 分箱锁（size-class 一锁） | 一次原子锁 | 撞同箱才串 | 中 | 版本5 的方向 |
| **每线程缓存 + 慢路径中心堆** | **零**（TLS 命中） | 仅补货/归还时 | 高 | tcmalloc/jemalloc |
| 无锁自由链（CAS 头插） | ABA 与指针稳定难题 | —— | 陷阱级 ⚠️ | 教科书反面教材 |
| arena 不回收 | 零 | 无 | 低 | `pmr::monotonic_buffer_resource` |

与 [06 章](06-内联三讲：基础·性能·技巧.md)的接口：分配器热路径快慢的另一半在内联——
`tcache_hit → return obj` 这种两分支小函数若被函数调用边界卡住，ns 级优势直接蒸发。

## 最新演进与工业实践

- **tcmalloc**（线程缓存 malloc，Google；原始论文 "Dynamic Memory Allocation with Thread Caching" ⚠️ 常被记为 SIGMETRICS 1994 Wilson et al.，本次 Crossref 未核到确切 DOI，只写标题年份）：把版本 5 的"快速路径免锁"制度化为 **thread cache**——每线程每尺寸档一条私有自由链，命中全程无原子操作。gperftools 血脉至今在 Google 内部服务里跑。
- **jemalloc**（Jason Evans；相关论文 "A memory allocator/defragmenter via retention and reuse"（ISMM 2010）⚠️ Crossref 未核到 DOI，标题年份为通行记载）：tcache + 脏页回收策略，FreeBSD 默认、Rust std 曾长期默认；其**碎片自治疗**（retention/reuse）回答了版本 3 遗留的外部碎片问题。
- **mimalloc**（✅ 论文已实测 Crossref：Leijnse et al. "mimalloc: Free List Sharding in Action", APLS 2019, DOI [10.1007/978-3-030-34175-6_13](https://doi.org/10.1007/978-3-030-34175-6_13)）：页级分片 + 每线程局部页，宣称"local free list 无锁、跨线程归还走延迟队列"——与版本 5 的思想完全同构，多了对**跨线程释放**（对象在 A 线程分配、B 线程释放）的现代处理。
- **Hoard**（Berger et al.，✅ 论文已实测 Crossref：DOI [10.1145/378993.379232](https://doi.org/10.1145/378993.379232)，ASPLOS/SIGARCH 2000）：同代学术标杆，用"堆抽象"同时证明 O(1) 摊还与**竞争最坏界**——给本书的经验式优化补上了理论证明。
- **Rust/Go 语境**：Go runtime 的 mcache→mcentral→mspan 三级、Rust `crossbeam-epoch` 的并发回收，都是"每线程缓存 + 分级慢路径"路线的当代化身 ⚠️ 泛称，细节以各自文档为准。
- **结论**：第 7 章的具体实现（自旋 CAS 池）**已被淘汰**——生产分配器不再让应用自己写并发池；但它提炼的问题结构（常态无竞争、锁税在原子与缓存行、终极解法是私有化）**精确预言**了之后 25 年分配器的演化路径。作为"如何把一把锁从错误位置搬走"的推理教程，全章今天仍然值得读。

## 机制补充：为什么"无锁自由链"是教科书陷阱

顺手能想到的"更快方案"——CAS 头插头取、彻底无锁——会在两处翻车：

1. **ABA**：线程 1 读到头 A→B；取出 A、B 成为新头；线程 1 的 CAS"我以为头是 B"成功，
   但链表已被并发操作改写多轮，节点内存可能已还给 [04 章](04-单线程内存池.md)式池并复用——
   指针值相同、含义已变。解法（epoch/危险指针，即内存回收问题）复杂度反超锁。
2. **争用放大**：所有线程挤同一条链的头 = 把锁税换成缓存行 ping-pong 税，实测常更慢
   （mimalloc 论文 ✅ DOI 见演进节 对 local-free 的强调正是为此）。

自旋的退避策略（书中版本 5 的"快速"另一半）：指数退避 + `pause` 指令提示超线程伙伴
（x86 的 `pause` 从"防流水线冲刷"演化到含瞬态执行缓解语义 ⚠️ 依微架构），
以及"自旋 N 次未果转 futex 睡眠"的两级泵——1999 年这些原语还叫 test-and-set。

## 常见误区与自查

- **误区 1："加了锁才叫多线程设计"**——[04 章](04-单线程内存池.md)实测显示锁税在**无竞争**时
  也存在（每次一进一出各一次原子 RMW）；所以"快路径免锁"是并发数据结构通用律，不限于分配器。
- **误区 2："自旋锁高级，无脑用"**——临界区里可能阻塞（IO/缺页/被抢占）时自旋=把 CPU 烧成
  灰还引入优先级反转；自旋只配护住**几条指令级**的原语。
- **误区 3："线程数上去吞吐就上去"**——回扣 [10 章](10-可扩展性与系统体系结构.md)：全局锁处
  Amdahl 串行项=1，曲线直接躺平；先把共享点拆掉再加人。
- **自查**：给现有分配路径估个账——每分配动作几次原子操作？几次跨核行迁移？
  若是"每次 new 都碰共享状态"，答案永远在"私有化（线程缓存）或分级（分箱）"两个方向里选。

## 本章地图（30 秒版）

```text
版本3（单线程可变大小池，[04章]） 
   └─ 加锁 → 版本4：正确性到手，并行度归零（全局锁串行化）
        └─ 快速锁定 → 版本5：无竞争走原子捷径，有竞争进真锁慢路径
             └─ 本书止步；现代分配器续写：tcache（每线程私有链）+ 分级慢路径
                                  （tcmalloc/jemalloc/mimalloc，见演进节）
```

一句话总结本章：**并发的性能问题，最终都转化为"共享状态接触面积"问题**——
锁是把面积缩到零并排队，线程缓存是把面积缩到"仅补货时"，无锁结构是换一种面积形状
（CAS 头）但欠下回收债。三种答案在同一问题上轮流最优，取决于竞争频率。
