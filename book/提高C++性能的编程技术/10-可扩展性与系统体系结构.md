## 核心概念速览（中英对照）

- **可扩展性** — Scalability：加核数换来的吞吐增长率；本书把"性能"升维成"曲线的形状"。
- **对称多处理器** — Symmetric Multi-Processing (SMP)：共享内存的多核架构——1999 年的新鲜事，今天的默认世界。
- **Amdahl 定律** — Amdahl's Law：加速比 ≤ 1/(串行份额 + 并行份额/N)；串行 5% 时 100 核封顶 ~18×。
- **无共享 / 部分共享** — Shared-Nothing / Partial Sharing：15.6/15.7 的组织原则——能私有就私有，共享面缩到协议最小集。
- **锁粒度** — Lock Granularity：15.8——粗锁省同步次数、细锁省争用；存在与数据规模相关的最优区间。
- **伪共享** — False Sharing：15.9——不同核各写各的变量，却因同处一条缓存行被迫轮流夺行；性能杀手榜常客。
- **惊群现象** — Thundering Herd：15.10——一次事件唤醒 N 个等待者，1 个干活 N−1 个白付上下文切换税。
- **读/写锁** — Reader-Writer Lock：15.11——读多写少时放宽并发；当年实现笨重，见演进节的当代替代。
- **存储器层级** — Memory Hierarchy：16.1——寄存器→L1/L2/L3→DRAM→SSD/磁盘，每级慢 10~100 倍；全书一切"常数"的物理来源。
- **缓存行/缓存抖动** — Cache Line / Thrashing：16.4/16.5——工作集超级、访问模式周期性踢出热行。
- **上下文切换** — Context Switch：16.9——寄存器搬运 + 页表切换 + 两级缓存预热污染；微秒级但按次数计费。
- **内核交叉** — Kernel Crossing：16.10——系统调用的陷入/返回往返，13.9 批处理建议的机制依据。

## 动机：从"一次调用多快"到"N 个核多快"

前 14 章优化的是单流延迟；15 章换了坐标系：**吞吐随核数的曲线**。书中机制链完整：
SMP 共享总线/互连 → 争用缓存行所有权 → 锁与原子操作成为曲线拐点 → Amdahl 给上限。
1999 年的读者要说服老板买第二块 CPU；2026 年的读者面对 128 核——**曲线没变，拐点提前**。
15.2 的教训用最狠的方式重述：并行化 95% 的代码只值 20 倍，如果剩下 5% 是全局锁
（比如 [05 章](05-多线程内存池与锁定策略.md)没做好的分配器），100 核也榨不出第二份油。

## 机制：三条税路的指令/硬件层视图

**伪共享（15.9）**：核 A 写 `counters[0]`、核 B 写 `counters[1]`——若两变量同落一条 64B 行，
MESI 一致性协议以**行**为粒度：B 的写迫使 A 的行降级失效，A 再写又踢 B。每次"各写各的"
都付一次跨核行迁移（数十~数百 ns ⚠️ 依互连拓扑，本次未实测）。经典侦测：perf 的
`mem_load_retired.l3_hit`/`offcore_requests` 类事件 + 消除后对比（⚠️ 事件名依微架构）。
修法即 padding/对齐到行粒度（`alignas(64)`，或各大库的 cacheline 对齐宏/`std::hardware_destructive_interference_size`，⚠️ 具体宏名以所依库版本头文件为准）。

**缓存友好四连（16.4–16.7）**：循环体访问模式决定 L1/L2 命中率——按行遍历 vs 跨步跳跃差
一到两个数量级；16.5"抖动"是工作集刚好卡在级容量边界的病态；16.6 警告跳转打断
取指/预解码流水线；16.7 给出反直觉药方：**小而直的分支/无分支计算常胜过取分支预测的赌**
（三目、`min` 编译出的 cmov 即此理——本目录实测 [02 章](02-虚函数开销与模板继承.md)单态 295 vs 混合 1985 ms 是同一机制的极端样本）。

**惊群与上下文切换（15.10/16.9）**：`poll/select` 时代一个监听 fd 就绪唤醒全部等待线程，
只有 accept 成功者干活，其余白付一次切换（保存/恢复寄存器组 + TLB/缓存污染）；epoll/IOCP
用"只通知就绪集"在接口层消解了惊群，而**线程数≠并发数**的当代共识（每核一线程、
用户态调度器、async await）正是 16.8/16.11"线程化选择"的终极答案。

**内核交叉（16.10）**：syscall 的 `syscall/sysret` 往返 + 安全缓解（寄存器清洗、spectre 屏障）
使单次交叉成本在 2026 年反而比 1999 年更贵（⚠️ 量级通行记载，本次未实测）；解法谱系：
批处理（`writev`/io_uring 一次提交多请求）→ 共享内存环 → 内核旁路（DPDK/RDMA）。

## 权衡：共享拓扑的选择树（15.5–15.8 整理）

```text
任务能彻底切分？ ──是──> 无共享（15.6）：每核一份数据，合并结果。Amdahl 串行项→仅启动/IO。
      │否
共享数据读多写少？ ──是──> 缓存共享数据/只读快照（15.5）：读侧零锁（RCU/seqlock/atomic 指针切换）
      │否
按数据分区？ ──是──> 部分共享（15.7）：锁跟着分区走（粒度自动细化，伪共享风险转给布局设计）
      │否
全局可变单点 → 只剩锁粒度权衡（15.8）+ 期望争用计算——或重新设计以消灭该单点（14 章回魂）。
```

## 相邻概念对比

- **读/写锁（15.11）vs 快照式读**：当年 rwlock 的读者计数本身就是争用点；现代偏好 seqlock/RCU/引用计数共享指针（接 [08 章](08-引用计数.md)）——读侧真零原子，代价在无阻塞读的重试或宽限期。
- **伪共享 vs 真共享**：前者是**布局事故**（padding 可解），后者是**逻辑冲突**（只有分区/复制能解）——perf 上信号相似，处方相反，先证后治。
- **16 章 vs 13 章**：13 章让人少算，16 章告诉你"算的地方"（寄存器/缓存/内核）各自的价签；13.7/13.8 是两章的缝合线。
- **vs [../C++并发编程实战2/00-总览与阅读地图.md](../C++并发编程实战2/00-总览与阅读地图.md)**：本书给"为什么并发的钱难赚"的硬件账本，Williams 给"怎么花"的标准库工具箱。

## 最新演进与工业实践

- **NUMA 是本章的当代放大**：跨内存节点访问再乘 1.5~2 倍延迟（⚠️ 依平台），`numactl`/first-touch/
  每节点分配器分区成了新的"锁粒度"议题——15 章的共享拓扑决策树长出了内存维度。
- **工具链**：perf（Linux 内核自带， Gregg 生态）、Intel VTune 的 memory access 分析、
  ARM topdown/PMU 计数；`perf c2c` 直接把伪共享点名到 cache line（✅ 工具存在，细节以 man 页为准）。
- **Amdahl 的后日谈**：Gustafson 扩展律（问题规模随核数增长时串行份额可以不变）解释了超算吞吐
  神话，但**服务器延迟敏感路径仍归 Amdahl 管**——两定律并列讲才是完整世界观（本目录补语）。
- **epoll → io_uring**：惊群与内核交叉的终局方案是"批量提交 + 完成队列 + 可选轮询"，
  一次进入内核办 N 件事（✅ 内核机制事实）；用户态协议栈/DPDK 则是"根本不进内核"的极端。
- **无共享制度化**：Seastar/Scylla 的 shard-per-core、Actor/协程调度器（tokio、各类游戏引擎任务系统）
  都是 15.6 的产业实现；`thread_local` + 每线程统计再合并（现代版 15.5 缓存共享数据）已是遥测标配。
- **伪共享的永恒性**：行大小仍是 64B（x86/Arm 主流），`std::hardware_destructive_interference_size`
  （C++17）是标准对 15.9 的迟到致敬（✅ 标准事实；各实现默认值与告警 ⚠️ 依 libstdc++/MSVC 现状）。
- **结论**：第 15–16 章是全书**受时间侵蚀最少**的部分——机制在硅里，不在编译器里。Amdahl、
  锁粒度、伪共享、上下文切换、内核交叉五件套今天原样成立；变的只有清单：SMP→NUMA、
  rwlock→RCU/seqlock、多线程阻塞→事件循环/io_uring、手写线程池→结构化并发 ⚠️（C++26 进行时）。

## 代码标本：伪共享的药与惊群的路

```cpp
// 🔧 15.9：每核一个计数器
struct alignas(64) PerCore { long n; };   // 每对象独占一条缓存行
PerCore counters[N_CORES];                 // 朴素版 long counters[N] 在高频写争用下
                                           // 会让 8 核互踢同一行——padding 后云消雾散（⚠️ 依行大小）
// 🔧 15.10/16.11 惊群的接口层解法（当年 epoll 新事物，今天常识）：
listen(fd, ...); epoll_ctl(ep, EPOLL_CTL_ADD, fd, &ev);   // 边沿触发+accept4(SOCK_NONBLOCK)
// 一次事件只叫醒被"分发到"的任务，而非全体等待者；协程化后连"叫醒"都省了（用户态调度）
```

两个标本共同说明：15/16 章的病根都在**共享点的接触面积**——行粒度（伪共享）、
等待集合粒度（惊群）、地址空间粒度（上下文切换/TLB）。"缩小接触面积"六个字可通全书后两章。

## 常见误区与自查

- **误区 1："Amdahl 说明并行没用"**——它说明的是**串行份额**没用；正确用法是量出你的
  串行项（锁/初始化/全局 IO），它决定加核预算的天花板。
- **误区 2："读写锁解决读争用"**——reader count 本身是共享写点（回到 [08 章](08-引用计数.md)原子税）；
  读极热时 seqlock/RCU/每线程副本常更优（⚠️ 依读侧能否容忍重试/宽限期）。
- **误区 3："线程池越大越能吃到核"**——超出核数的 runnable 线程只是排队 + 切换税 + 缓存互相
  踩脏（16.8/16.9）；当代默认：每核一线程 + 工作窃取。
- **自查**：性能曲线上找到"不再上升"的核数点，问三题——争的是锁（15.8）、行（15.9）
  还是地址空间（16.9/16.10）？三选一，处方各不相同。
