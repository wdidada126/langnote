## 核心概念速览（中英对照）

- **按值返回机制** — Return-by-Value Mechanics：1999 年典型实现=函数内构造临时 + 拷贝构造到调用方隐藏/显式暂存 + 析构临时，一条 `return T(...)` 三次函数调用。
- **返回值优化** — Return Value Optimization (RVO)：编译器直接在调用方目标存储上构造，拷贝"从未发生"。
- **具名返回值优化** — Named RVO (NRVO)：返回具名局部变量时的 RVO 变体，条件性（多返回点/取地址即失效）。
- **计算性构造函数** — Computational Constructor：`Rational(int,int)` 承担约分等计算，让"构造即完成运算"，替代"构造函数 + set/计算函数"两步舞。
- **临时对象** — Temporary Object：编译器为表达式造的无名对象——传值实参、类型不匹配的隐式转换、返回链、异常对象。
- **临时对象产生点** — Temporary Generation Sites：本书 5.1–5.4 的清单：定义、隐式转换、按值传递、按值返回，四大泉眼。
- **复合法 op=()** — Compound Assignment Idiom：`x = a; x += b; x += c;` 手工替换 `x = a + b + c;`，本书 5.6 的招牌技巧。
- **拷贝消除** — Copy Elision：C++11 命名、C++17 对 prvalue 强制的合法省略，RVO 的制度化后代。
- **移动语义** — Move Semantics：省略失败时的廉价兜底——"偷资源"取代"深拷贝"。

## 动机：一条 `Rational r = a + b - c;` 的解剖图

第 4、5 章合起来回答一个问题：**表达式语法与机器动作之间隔着多少次构造/拷贝/析构？**
书中对 Rational/String 的枚举（5.1–5.4）至今是最好的临时对象教材，四类泉眼：

1. **定义即构造**（5.1）：`Rational r;` 不算临时，但 `Rational r = Rational(2,4);` 在 1999 年的
   编译器上是"临时 + 拷贝"（今天就地构造）。
2. **类型不匹配 → 隐式转换**（5.2）：`void f(const Rational&); f(5);` —— int 不在 Rational
   表达域，编译器造 `Rational(5)` 临时；单参构造/转换构造=临时对象自动贩卖机。`explicit`
   （Meyers《More Effective C++》第 8 条同款药方）是第一道闸。
3. **按值传递**（5.3）：形参本身就是"活到函数尾的临时对象"；`const T&` 是条件反射式修复。
4. **按值返回**（5.4，接第 4 章）：`return` 一个局部/临时——机制上"构造+拷贝+析构"三连，
   除非 RVO 命中。

链式表达式 `(a+b)+(c+e)` 里每个 `+` 至少一个临时；N 个操作数的折叠求和 = O(N²) 的元素搬运。
这就是 5.6 `op=()` 技巧的战场：

```cpp
// 🔧 原书 5.6 惯用法（复用法）
result = a; result += b; result += c; result += e;  // 零临时
result = (a + b) + (c + e);                          // 每个 + 一个临时（当年）
```

## 机制 → 实测：现代优化器自己就是"op=() 大师"（00 总表 #1、#2）

已实测 g++ 15.2（MinGW-w64 x86_64，-std=gnu++23，本机单次样本）：

**实验 1**（临时链 vs op= 复用，50M 次/循环携带）：

| 构建 | 临时链 | op= 复用 | 差距 |
| --- | --- | --- | --- |
| `-O0`（拷贝可观测，带计数器探针） | 630.9 ms | 461.6 ms | +37% |
| `-O0`（无探针） | 552.3 ms | 473.6 ms | +16% |
| `-O2`（两种都测） | ≈0 ms | ≈0 ms | **整个循环被闭式折叠**——连"每迭代 ++ 全局计数器"都被折成 `+= N` |

1999 年的 `+37%` 是真实账单；现代 `-O2` 在无观测副作用时对 POD 类型把两条路径归一——
`op=()` 从"性能必修"降级为"仅在拷贝构造不可省略（有副作用/堆资源且移动不可用）时仍有意义"。

**实验 2**（64B 载荷对象：按值返回 vs 出参，20M 次）：

| 构建 | return-by-value | out-param |
| --- | --- | --- |
| `-O2` NRVO 生效 | 566.9 ms | 556.7 ms（打平） |
| `-O2 -fno-elide-constructors`（模拟 RVO 失效） | **1112.0 ms** | 538.2 ms（按值贵 107%） |

`-fno-elide-constructors` 是本次最有力的教学开关：它让"拷贝从未发生"显形——剥掉省略后
按值返回多付近一倍成本。而 C++17 起 prvalue 的直接初始化是**语义规定**而非优化许可
（✅ 标准事实），编译器不再需要"聪明"才能兑现零开销；NRVO 未命中的多返回点场景由移动语义兜底。

## 权衡：当年技巧清单的现代残值

| 书中技巧 | 1999 收益 | 2026 收益 | 原因 |
| --- | --- | --- | --- |
| `const T&` 传参 | 大 | 仍有（引用 vs 值对大对象） | 小对象（≤2 寄存器）按值反而快 ⚠️ 未实测 |
| `op=()` 复用法 | 30%+（实测 -O0） | ≈0（POD/可内联时） | 闭式/向量化优化接管 |
| 出参代替返回值 | 大 | **反模式** | RVO 强制化 + 移动；出参破坏流水线写法、妨碍 `const auto x = f();` |
| 计算性构造函数 | 大 | 转化为"优先列表初始化 + `explicit`" | 约分类计算放构造里仍是好设计（语意理由） |
| 避免隐式转换 | 大 | 仍有（`explicit` 是默认美德） | 临时对象泉眼 2 从未被编译器堵死 |

## 相邻概念对比

- **RVO vs 移动**：RVO 消灭拷贝这个"事件"；移动接受事件但换廉价"动作"。优先级永远是先让省略命中，移动是 NRVO 失败（多 return 点、条件构造）时的保险。
- **临时对象 vs 表达式模板**：本书时代没有给出方案；Veldhuizen 1995 提出、Blaze/Eigen 实践的表达式模板把 `(a+b)+c` 变成惰性求值的模板表达式对象，逐元素一次融合循环（⚠️ 本书目录无表达式模板专章，此为本目录补编语境）。
- **vs [01 章](01-跟踪实例与构造析构的代价.md)跟踪实例**：拷贝计数器就是本章的诊断仪——`copies()` 非零即临时对象流量。

## 最新演进与工业实践

- **C++11/14/17 三部曲**（✅ 标准事实）：C++11 右值引用与移动语义 → C++14/17 把 prvalue 与拷贝消除逐步语义化 → C++17 强制省略。`std::string`/`vector` 的 `substr`/`operator+` 按值返回今天都是零/常数成本。
- **`std::optional<T>` 返回多态值**、结构化绑定 `auto [x,y] = f();`（C++17）让"返回多个值"不再需要出参与 tuple 堆分配。
- **fmt 库**：`fmt::format` 返回 `std::string` 值——按当年标准这是"临时对象灾难"，实际靠移动 + SSO + 编译期格式检查成为最快的格式化方案之一（⚠️ 具体基准数字未实测；通行结论来自 fmt 官方文档 charts）。
- **表达式模板的成败**：源头是 Veldhuizen 1995 年在 C++ Report 上的系列专栏（⚠️ 无 DOI 的杂志文章，本次未能连通核验具体篇名，只写年份与刊物）；成功者——**Eigen**（Guennebaud et al. T-RES 2010 技术报告，无 Crossref DOI ⚠️）、**Armadillo**（✅ Sanderson & Curtin, JOSS 2016, DOI [10.21105/joss.00026](https://doi.org/10.21105/joss.00026)，实测 Crossref 可达）、Blaze；失败者——`std::valarray`（接口设计未为模板表达式留门，基本弃用，见 [../C++标准库/10-国际化数值并发与分配器.md](../C++标准库/10-国际化数值并发与分配器.md)）。
- **结论**：第 4 章（RVO/计算性构造）的**机制叙述**今天读仍准确（加上"且已被标准部分强制"的补丁）；第 5 章的 op=() 技巧作为**手动优化**已死，作为**理解拷贝流量**的教学标本永生。

## 常见误区与自查

- **误区 1："按值返回一定产生一次多余拷贝"**——1999 年成立；今天 prvalue 强制直接初始化 +
  NRVO 高频命中 + 移动兜底，三连之后"按值返回"在 API 层面基本免费。**反过来了**：
  返回 `T&`/`T*` 才需要逐例辩护（生命周期！）。
- **误区 2："加了 `std::move` 才算移动优化"**——`return local;` 自动按移动处理（甚至优先于具名
  返回的 NRVO 失效场景），手写 `return std::move(local);` 反而**阻断 NRVO**——Meyers
  《Effective Modern C++》item 25 的经典告诫，正是本书时代的技巧反向演化的标本。
- **误区 3："临时对象只出现在算术表达式"**——四大泉眼里最阴的是 5.2 类型不匹配：
  带隐式转换构造的类，任何"少写一个类型"的调用点都在造临时。`explicit` + `-Wconversion`
  级别的自觉是唯一的闸。
- **自查**：拷一个"返回值小对象 + 链式表达式"的热点函数，用拷贝计数器（[01 章](01-跟踪实例与构造析构的代价.md)手法）
  数出每调用 copies；若 >0 且类持有堆资源 → 优先补移动构造（一条路救全家），
  而不是回到 op=() 复用法。

## NRVO 失效的常见形态（4.2 机制的当代清单）

```cpp
// 🔧 以下写法都会把"就地构造"降级为移动/拷贝（NRVO 不命中）
Big pick(bool cond) { Big a, b; return cond ? a : b; }  // 多候选对象
Big& leak()  { Big t; ... return t; }                    // 返回引用=悬垂，编译器拒绝是仁慈
Big lazy()   { static Big once; ... return once; }       // 具名 static 不可省略
template<class T> T make(auto&&... xs){ return T{xs...}; } // prvalue：C++17 直接初始化，零拷贝 ✅
```

规则可以背，更重要的是理解省略为何有条件性——具名对象可能被多个 return 点引用、
可能被取地址（逃逸出函数）、可能有非平凡析构语义；这些边界恰好也是
移动语义发挥兜底价值的地方。
