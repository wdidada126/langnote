## 🔧 REST Catalog 概念类比（DuckDB / SQLite 文件目录 ≥ 4 组）

> 以下类比用于帮助理解 REST Catalog 的抽象概念。**类比对象为 DuckDB/SQLite，非 Polaris 行为**——
> 差异点在每组后标注。

| # | DuckDB/SQLite 概念 | REST Catalog (Polaris) 对应 | 关键差异（🔧 非本书引擎行为） |
| --- | --- | --- | --- |
| 1 | `.duckdb` / `.db` 文件 = 一个 catalog | Polaris catalog = 一个 REST 端点管理的元数据集合 | 🔧 DuckDB/SQLite catalog 是本地单文件；REST catalog 是远程 HTTP 服务，多客户端并发访问 |
| 2 | SQLite `ATTACH DATABASE` / DuckDB schema = namespace | Polaris namespace = catalog 内的命名空间（如 `db1.schema1`） | 🔧 DuckDB/SQLite schema 是文件内逻辑分区；REST namespace 可跨存储位置、跨云 |
| 3 | SQLite 表文件 / DuckDB 表 = 数据实体 | Polaris 管理的 Iceberg 表 = 元数据指向的对象存储文件集 | 🔧 DuckDB/SQLite 表数据在本地文件内；REST catalog 表数据在远程对象存储（S3/GCS/ADLS） |
| 4 | SQLite 用户/角色 / DuckDB GRANT = 权限 | Polaris Principal + PrincipalRole + CatalogRole = 三层 RBAC | 🔧 DuckDB/SQLite 权限是文件级或库级；REST catalog 权限可细化到 namespace/表/列级 |
| 5 | `.db` 文件路径 = 数据位置 | Polaris storage credential = 指向对象存储的凭证配置 | 🔧 DuckDB/SQLite 数据路径是本地文件系统路径；REST catalog 的 storage location 是远程 URL + 临时凭证 |
| 6 | 单进程写锁 = 并发控制 | Iceberg 乐观并发 + REST catalog 原子提交 | 🔧 DuckDB/SQLite 用文件锁；REST catalog 用元数据原子切换实现无锁并发写 |
