## 核心精讲

**1. 编译流水线**。`tokenize` → 语法分析生成 AST → 符号表 → 控制流图（CFG）→ 字节码（`PyCodeObject`）。`compile(src, "", "exec")` 产出 code 对象；`dis.dis` 可看。

**2. 字节码定义（3.11+）**。指令在 `Python/bytecodes.c` 用 `inst()`/`op()`/`macro()` 声明式写，由 `Tools/cases_generator/` 生成 tier1/tier2 的 C 代码，取代手写 `opcode.h`。

**3. 解释器主循环**。`_PyEval_EvalFrameDefault`（`Python/ceval.c`）是栈式解释器：取指令、操作数栈、派发。`dis` 看到的 `LOAD_FAST`/`BINARY_OP` 等在此执行。

**4. 自适应解释器（PEP 659，3.11）**。热点指令被「特化」：`BINARY_OP` 根据实际类型变成 `BINARY_OP_ADD_INT` 等内联快速路径（quickening），显著提速。3.12/3.13 持续扩展特化种类。

**5. 实验 JIT（3.14）**。在 tier2 微操作（uop）之上做 copy-and-patch JIT，把热路径编译为机器码；3.14 实验性开启。

```python
# 教学示意，不参与构建
import dis
def f(a, b):
    return a + b
dis.dis(f)          # 看 LOAD_FAST / BINARY_OP / RETURN_VALUE
```

## 常见误区与本书需修正之处

- 🔧 误：原书（3.10 基线）的字节码机制基于旧 `opcode.h`；3.11+ 改为 `bytecodes.c` + cases generator，必须更新。
- 误：以为「字节码跨版本兼容」——字节码格式随版本变，`.pyc` 带版本号。
- 误：特化永远更快——冷路径首次特化有成本，且类型抖动会去特化。
