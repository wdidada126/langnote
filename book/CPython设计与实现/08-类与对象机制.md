## 核心精讲

**1. 类即对象**。`class` 语句在运行时创建一个 `type` 实例（类型对象）；实例的 `ob_type` 指向它。属性查找：先实例 `__dict__`，再沿 MRO 查类。

**2. 描述符（descriptor）**。对象定义了 `__get__`/`__set__` 即描述符，是 `property`、`classmethod`、`staticmethod`、`functools.cached_property` 的底层机制。数据描述符（有 `__set__`）优先于实例属性。

**3. 元类**。`type` 是自身的元类；自定义元类控制类的创建（属性校验、注册）。但多数需求可用 `__init_subclass__`（3.6）或类装饰器替代，更直观。

```python
# 教学示意，不参与构建
class Base:
    def __init_subclass__(cls, **kw):
        super().__init_subclass__(**kw)
        print("子类注册:", cls.__name__)   # 3.6+ 钩子

class Sub(Base):
    pass
```

## 版本演进

- 3.6 `__init_subclass__`（PEP 487）取代大量轻量元类需求。
- 3.7 `dataclasses`（PEP 557）用类装饰器生成样板；3.10 `@dataclass(slots=True)` 生成 `__slots__`。
- 3.12 `type` 相关内部更稳；`__class_getitem__` 支持泛型别名。

## 近年研究与工业界开源实践（2015–2026）

- `dataclass(slots=True)` 成为高性能数据类首选；`pydantic`/`attrs` 建基于描述符与 `__init_subclass__`。
- 元类在 ORM/序列化框架仍用，但新代码偏好描述符 + 装饰器。

## 常见误区与本书需修正之处

- 🔧 误：原书（3.10 基线）对 `dataclass(slots=True)` 与 `__init_subclass__` 覆盖不全；2026 应补。
- 误：以为「property 是语法魔法」——本质是非数据描述符（`__get__` 无 `__set__`）。
- 误：优先上元类——多数场景 `__init_subclass__`/类装饰器更可读。
