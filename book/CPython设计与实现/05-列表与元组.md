# 05 列表与元组

> 原书 pp. 第 5 章（具体页码以实体书为准 🔧）

## 本章地图

| 节 | 内容 | 结论 |
|---|---|---|
| list 内部 | 指针数组 + over-alloc | append 摊销 O(1) |
| 缓冲池 | 空列对象池 | 小对象复用 |
| tuple 内部 | 静态数组 | 不可变、更紧凑 |
| 选型 | 语义优先 | 不可变用 tuple |

## 核心精讲

**1. list = 动态指针数组**。`PyListObject` 含 `ob_item`（指针数组）与 `allocated`（容量）。`append` 摊销 O(1)，超容量时按公式整体搬迁扩容（over-allocation）。

**2. 对象缓冲池**。频繁创建/销毁的小 `list` 走空闲对象池，减少 malloc 压力。

**3. tuple = 静态数组**。长度固定、不可变，对象更紧凑（无 `allocated` 字段），可作 dict 键，且支持小元组缓存。

```python
# 教学示意，不参与构建
import sys
lst = [1, 2, 3]
tup = (1, 2, 3)
print(sys.getsizeof(lst), sys.getsizeof(tup))   # tuple 更小
```

## 版本演进

- 3.9 `list` 增 `copy()`；3.10 起 `list[int]` 泛型标注（PEP 585，3.9 起可用）。
- 3.11+「Faster CPython」对 list 索引/遍历有专门特化（`BINARY_SUBSCR_LIST_INT`）。
- 3.12 `list`/`tuple` 的小对象缓存更稳定。

## 经典论文与原始文献

- `Objects/listobject.c`、`Objects/tupleobject.c`。
- PEP 585（泛型内置类型标注，3.9）。

## 近年研究与工业界开源实践（2015–2026）

- 不可变记录多用 `tuple`/`NamedTuple`/`dataclass(frozen=True)`；高频路径省内存。
- 3.11 特化让 list 访问接近数组，但内存差（指针数组）仍在。

## 常见误区与本书需修正之处

- 🔧 误：原书未提 PEP 585 泛型标注；现代代码应写 `list[int]` 而非 `typing.List`。
- 误：把 list 当队列 `pop(0)` 是 O(n)；FIFO 用 `collections.deque`。
- 误：「tuple 更快」——访问速度与 list 接近，优势在内存与不可变语义。
