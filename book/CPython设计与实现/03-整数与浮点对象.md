# 03 整数与浮点对象

> 原书 pp. 第 3 章（具体页码以实体书为准 🔧）

## 本章地图

| 节 | 内容 | 结论 |
|---|---|---|
| 整数内部 | 定长 + 大整数数组 | 无溢出，成本在堆分配 |
| 小整数池 | [-5,256] 复用 | 常见小整数不重复分配 |
| 浮点 | 双精度 + 池 | 直接包 C double |
| immortal | PEP 683 | 常量不再变动计数 |

## 核心精讲

**1. 整数（任意精度）**。Python `int` 是小整数用单 `ob_digit`、大整数用 `ob_digit[]` 数组的「符号-幅值」表示，无溢出但有堆分配成本。`sys.getsizeof(10**100)` 随位数增长。

**2. 小整数池**。区间 `[-5, 256]` 的对象常驻、复用，比较 `is` 成立——但**不要依赖 `is` 比较整数**，用 `==`。

**3. 浮点**。直接包一个 C `double`（`ob_fval`），无特殊池，每次 `float(x)` 新建（小范围常量可能被驻留，但不保证）。

```python
# 教学示意，不参与构建
import sys
a = 256; b = 256
print(a is b)          # 小整数池：True（勿依赖）
x = 257; y = 257
print(x is y)          # 通常 False（实现细节）
print(sys.getsizeof(2**100))   # 大整数随位数吃内存
```

## 版本演进

- 3.12 immortal 对象（PEP 683）：`-1`/`0`/`1`/`None`/`True`/`False` 等成为永生对象，引用计数冻结，利于 no-GIL。
- 3.11+ 整数运算在自适应解释器下更快（特化 `BINARY_OP_ADD_INT` 等）。
- 早期 `int` 即「long」（3.0 起合并，无独立 `long` 类型）。

## 经典论文与原始文献

## 近年研究与工业界开源实践（2015–2026）

- immortal 对象减少常量的原子引用计数，是 free-threading 的关键使能。
- 大整数运算走 GMP 类路径（实现内建），远超 naive。

## 常见误区与本书需修正之处

- 🔧 误：原书未含 immortal 对象（PEP 683）；3.12+ 应补。
- 误：用 `is` 判断整数相等——永远用 `==`；`is` 仅用于单例（`None`）。
- 误：以为「Python 整数有上限」——任意精度，代价是性能与内存。
