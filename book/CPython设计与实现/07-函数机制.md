## 核心精讲

**1. 函数对象**。`PyFunctionObject` 持有 `__code__`（PyCodeObject，编译产物）、`__globals__`（定义处模块全局）、`__closure__`（闭包变量）。函数是头等对象，可传参/返回。

**2. 栈帧**。`PyFrameObject` 记录局部变量、常量、指令指针、异常状态。每次调用建新帧压栈；3.11+ 帧对象大幅瘦身（lazy 帧），速度快、内存低。

**3. 闭包**。嵌套函数捕获外层变量，用 `cell` 对象共享，多个闭包可共享同一 `cell`。

**4. 名字空间与查找**。LEGB：`Local → Enclosing → Global → Builtin`。局部变量在帧数组里按索引 O(1)，全局走 dict 查找更慢。

```python
# 教学示意，不参与构建
def outer():
    x = 1
    def inner():
        return x          # 闭包捕获 x（cell）
    return inner
```

## 版本演进

- 3.11「零开销栈帧」：`PyFrameObject` 拆成紧凑帧 + 解释器状态，调用更快（PEP 657 精确回溯也借力）。
- 3.10 `match`/`case` 模式匹配在函数内可用；3.11 `exceptiongroups`。
- 装饰器语法 `def f() @wrap` 始终等价于 `f = wrap(f)`。

## 近年研究与工业界开源实践（2015–2026）

- 3.11 帧瘦身让深递归与高频调用显著提速；`sys._getframe` 仍可拿帧（性能敏感场景慎用）。
- 闭包 + 装饰器是 Web 框架中间件的基础。

## 常见误区与本书需修正之处

- 🔧 误：原书（3.10 基线）未含 3.11 紧凑帧与提速；2026 谈函数调用成本必须带「Faster CPython」结论。
- 误：以为「闭包一定慢」——捕获是 cell 指针共享，成本极低；慢在动态查找。
- 误：`locals()` 修改能影响局部变量——CPython 中函数内 `locals()` 是快照，改它不影响帧（仅模块级有效）。
