# 概念专篇：字节码编译与执行流水线

> 跨章概念：与第 07 章（函数/帧）、第 11 章（编译与执行）、第 13 章（GIL）强相关。
> 校准到 2026（3.11+ 自适应解释器、3.14 实验 JIT）。

## 1. 流水线与关键文件

```
源码 .py → [tokenize] → AST → [符号表] → CFG → 字节码(PyCodeObject)
                                              ↓
                                      _PyEval_EvalFrameDefault（ceval.c）
                                              ↓
                              自适应特化(PEP 659) → 实验 JIT(3.14)
```

- `compile(src, "", "exec")` 产 `PyCodeObject`；`dis.dis` 看指令。
- 3.11+ 字节码指令定义在 `Python/bytecodes.c`（声明式 `inst()`/`op()`/`macro()`），由 `Tools/cases_generator/` 生成 tier1/tier2 的 C 代码，取代旧手写 `opcode.h`。

## 2. 解释器主循环

`_PyEval_EvalFrameDefault`（`Python/ceval.c`）是栈式解释器：取指令 → 操作数栈 → 派发。`LOAD_FAST` 读帧局部数组（O(1)），`BINARY_OP` 走类型特化。3.11 帧对象大幅瘦身（lazy frame），调用更快。

## 3. 自适应解释器（PEP 659，3.11+）

热点指令被「特化」：`BINARY_OP` 依实际类型变成 `BINARY_OP_ADD_INT` 等内联快速路径（quickening）。类型抖动会「去特化」回通用路径。3.12/3.13 持续扩展特化种类。累计纯 Python 约 1.6× 提速（3.11–3.14）。

## 4. 实验 JIT（3.14）

在 tier2 微操作（uop）之上做 **copy-and-patch** JIT，把热路径编译为机器码。3.14 实验性开启，是性能里程碑。源码见 `InternalDocs/jit.md`。

## 5. 常见误区

- 误：字节码跨版本兼容——格式随版本变，`.pyc` 带版本号，跨版本需重编译。
- 误：特化永远更快——冷路径首次特化有成本，类型抖动会去特化。
- 误：看字节码就能完全解释性能——内存布局（第 02/09 章）常比指令数更决定实测快慢。
