# 概念专篇：GIL 与 no-GIL 构建

> 跨章概念：与第 13 章（GIL 与线程）、第 14 章（异步与并发）强相关，并贯穿并发主题。
> 校准到 2026（PEP 703、3.13t/3.14t 实验）。

## 1. GIL 是什么

`_PyRuntimeState` 持有的进程级互斥锁，保证同一时刻只有一个线程执行 Python 字节码。它让引用计数与对象模型无需逐操作加锁，代价是同进程内多线程 CPU 并行受限。

## 2. 何时被阻塞 / 释放

- **阻塞（无法并行 CPU）**：纯 Python CPU 密集的多线程。
- **释放（可并发）**：I/O 等待（socket/磁盘）、调用释放 GIL 的 C 扩展（NumPy/OpenBLAS、Pillow）、多进程（各自独立 GIL）。

## 3. no-GIL 构建（PEP 703）

- 3.13（2024）起提供 `--disable-gil`（或 `PYTHON_GIL=0`）实验构建，常称 **3.13t**；3.14 延续并改进，默认仍带 GIL。
- 含义：同进程多线程可真正并行 Python 代码。但需：① 无数据竞争设计（原多线程代码可能暴露竞态）；② C 扩展用受限 C API（PEP 683 immortal、PEP 689 临时 API）或显式标线程安全。
- 前置依赖：immortal 对象（PEP 683，3.12），避免对常量做原子引用计数。

## 4. 其他并行路径

- **多进程**：`multiprocessing`/Ray/Dask，绕开 GIL，跨核（见 [`高性能Python（第2版）/00-总览与阅读地图.md`](../../高性能Python（第2版）/00-总览与阅读地图.md) 第 9 章）。
- **子解释器（PEP 554，3.12）**：`interpreters` 模块创建隔离解释器，各自 GIL 与状态，可多核并行且避免共享可变状态（见第 14 章）。

## 5. 决策表

| 场景 | 首选 | 原因 |
|---|---|---|
| I/O 密集 | asyncio / 多线程 | GIL 在等待时释放 |
| CPU 密集 + 向量化库 | 多线程（库内释放 GIL） | NumPy 等已并行 |
| CPU 密集 + 纯 Python | 多进程 / no-GIL / 编译 | 绕开或消除 GIL |
| 隔离多租户 | 子解释器（PEP 554） | 状态隔离 + 潜在并行 |

## 6. 常见误区

- 误：「Python 不能并行」——多进程、释放 GIL 的扩展、异步 I/O、子解释器都能并行/并发。
- 误：「no-GIL 让旧多线程代码自动变快」——还需无竞争设计 + 扩展兼容。
- 误：「PyPy 无 GIL」——PyPy 同样有 GIL，JIT 只加速单线程。
