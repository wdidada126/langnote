## 本章地图

| 节 | 内容 | 结论 |

## 核心精讲

**1. str 紧凑表示（PEP 393，3.3）**。一个 `str` 按最大字符宽度自动选 `latin1`(1B)/`UCS2`(2B)/`UCS4`(4B) 存储，避免总是 4 字节；`sys.getsizeof` 随内容宽度变。

**2. intern（驻留）**。标识符、字面量常量等会被 intern，使比较/字典查找用指针而非逐字符。手动 `sys.intern` 可用于高频键。

**3. 不可变与拼接**。`str` 不可变，`a += b` 在循环里反复分配新对象，是性能反模式；应用 `[]` + `"".join()` 或 `io.StringIO`。

**4. bytes / bytearray**。`bytes` 不可变原始字节；`bytearray` 可变。与 `str` 不混用（3.x 严格区分，无隐式互转）。

```python
# 教学示意，不参与构建
import sys
s = "hello"
print(sys.getsizeof(s))          # 含头部 + 字符数组
parts = ["a", "b", "c"]
big = "".join(parts)             # 优于循环 += 
```

## 版本演进

- `str` 紧凑存储（PEP 393，3.3）是 2.x→3.x 的重大内存改进。
- 3.12+ `string_interning` 有 `InternalDocs/string_interning.md` 文档。
- 3.14 实验性 **t-string（PEP 750）** 模板字符串（类似 f-string 但产出结构化模板），字符串处理新范式。

- 字符串处理在解析/模板场景是热点；3.14 t-string 面向安全 SQL/HTML 构造。
- 编码探测（CJK 等）在紧凑表示下仍按最大宽度，混合文本偏宽。

## 常见误区与本书需修正之处

- 🔧 误：原书未含 PEP 750 t-string；3.14 起字符串模板有官方方案，应补到「版本演进」。
- 误：循环 `+=` 拼接字符串「差不多」——大数据量下是 O(n²)，必须用 join。
- 误：`bytes` 与 `str` 可比较/互转——3.x 严格区分，混用抛 `TypeError`。
