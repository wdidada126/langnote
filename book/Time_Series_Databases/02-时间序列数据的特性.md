## 章定位与中心论题

## 逐节精读重构

### 2.1 特性一：写多读少、写后不改（append-dominant）

- 数据记录后几乎不再修改（✅ 译文回述："时间序列数据存入后就很少再需要修改了"）。
- 设计推论（⚠️ 转述重构）：
  1. 不需要通用 MVCC/回滚段为"改"付代价——LSM 类追加结构天然契合
     （盘上通识线：[../设计数据密集型应用.md](../设计数据密集型应用.md) 第 3 章）；
  2. 缓存策略可以极端：热数据 = 最近时间段，LRU 近似为"按时间截断"；
  3. 一致性需求降级：单点写入天然无冲突，分布式协调主要服务于副本而非写冲突。

### 2.2 特性二：查询以时间段为单位（range-dominant）

- ✅ 译文回述："查询时经常是查询一个连续时间段的数据，也可能查询汇总或者聚合后的数据"。
- 两个读形态：**原始段扫描**（画图/导出）与**聚合查询**（均值/最大/分位数）。
- 设计推论：物理布局应让"同一序列 + 相邻时间"的数据**物理相邻**（列式/宽列/按序列分组的
  blob 都服务于此）；聚合形态则催生降采样层（03 章 🔧D2 实测其收益）。

### 2.3 特性三：序列数量随标签组合爆炸（高基数）

- 度量 × 标签组合 = 序列 ID 空间；设备数 × 测点数 × 标签值可轻松到千万级。
- ⚠️ 转述重构：本书时代该问题的典型形态是"每主机每磁盘每度量一条序列"的监控清单；
  今天的加剧形态是云原生标签（pod/namespace/region）与 trace 属性组合。
- 设计推论：序列 ID 的**编码成本**进入一等公民位置——ID 映射表（metric/tag → 4 字节 ID）
  是 OpenTSDB 的核心机制之一（04 章展开）；高基数失守的直接表现是索引内存爆炸
  （Prometheus 社区所谓 high cardinality explosion，⚠️ 转述，见本章演进节）。

### 2.4 特性四：时间戳高度规律（可压缩性）

- 采样按固定周期（10s/1min），时间戳列的信息量趋近于零。
- 设计推论：delta-of-delta 编码（差分再差分 → 近零值密集 → 变长编码/位打包）。
- 🔧 **概念演示 D4（玩具实现，非任何时序引擎行为）**：Python 生成 10,000 个
  10s 周期 ±2s 抖动的时间戳，三种编码逐字节统计（脚本
  `D:\develops\tmp\dbwave_w3_timeseries\demo.py`，输出 `demo_out.txt`）：

  | 编码 | 字节数 |
  | --- | --- |
  | 全量 u64 | 80,000 |
  | delta + 6bit 组变长 | 10,005 |
  | delta-of-delta + 6bit 组变长 | 10,010 |

  🔧 实测：全量/dod 比 **8.0×**；本例抖动均匀（dod 众数 |1|~|4| 各约 1,500–2,000 个）
  使 dod 与一阶 delta 几乎持平——**恰是教训**：dod 的红利来自"周期极规律"的时钟，
  抖动大时收益转移到数值侧（浮点值 XOR 类压缩，Gorilla 谱系，✅ DOI 见演进节）。
  演示为纯 Python 位统计，注明玩具实现。

### 2.5 特性五：数值平滑、相邻强相关

- 物理量（温度/负载/价格）相邻采样高度相关，浮点尾数低位常不变。
- ⚠️ 转述重构：本书对此着墨有限（2014 年），显影它的是一手文献 Gorilla（见演进节）；
  设计推论：值侧 XOR + 掩码变长编码，与时戳侧 dod 构成时序压缩的两翼。
- 消费侧含义：平滑性让**降采样几乎无损**（03 章 🔧D2 的 28.6:1 压缩比在监控画图上肉眼难辨）。

### 2.6 特性六：数据价值随时间衰减（分层与 TTL）

- 昨天的原始点几乎不再被读；周/月尺度的决策只依赖聚合层。
- 设计推论：**多分辨率分层存储**（raw → 5min → 1h → 1d）是 TSDB 的标配信息架构；
  每层独立 TTL。本书的"汇总或聚合后的数据"表述（✅ 译文回述）即此机制的预告。
- 与流式计算的接口：分层聚合本质是"预计算的窗口聚合"——把 02 章特性交给
  [../Streaming_Systems/00-总览与阅读地图.md](../Streaming_Systems/00-总览与阅读地图.md)
  的 What/Where/When/How 框架重述，就是"按时间桶分组、允许迟到修正、增量累积"
  （04 章 🔧D3 演示"到达序不变性"正是该框架的批式投影）。

### 2.7 六条特性 → 设计约束对照表（重构小结）

| 特性 | 存储引擎约束 | 本书落点 |
| --- | --- | --- |
| append 为主 | 追加结构、轻事务 | 03 NoSQL 选型 |
| 时间段读 | 序列内物理相邻布局 | 03 rowkey/宽表 |

## 核心概念速览（中英对照）

- **追加主导剖面** — append-dominant profile：写后不改、删除以段为单位
- **时间段扫描** — time-range scan：读路径主形态，要求序列内物理相邻
- **聚合查询** — aggregate query：均值/极值/分位数的段上汇总，降采样服务的对象
- **基数爆炸** — cardinality explosion：标签组合使序列数失控，索引内存的头号杀手
- **序列 ID 编码** — compact ID mapping：度量/标签 → 定长整数的映射表机制
- **delta-of-delta** — dod 编码：时间戳差分再差分，规律时钟下近零值密集
- **变长编码** — variable-length coding：把小整数压进少量比特（本目录 🔧 玩具实现）
- **XOR 压缩** — XOR + bitmask：对平滑浮点序列的值侧编码（Gorilla 谱系，⚠️ 转述）
- **多分辨率分层** — multi-resolution retention：raw/粗粒度层并存、各带 TTL
- **价值衰减** — value decay：数据效用随龄期下降，分层与降采样的人类学理由
- **到达序不变性** — arrival-order invariance：全量重算结果与写入顺序无关（🔧D3 演示）
- **宽列布局** — wide-column layout：一行多列（时间偏移为列）的时序物理布局预告
