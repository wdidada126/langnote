## 逐节精读重构

### 5.1 访问接口层：HTTP + JSON 的薄客户端

- ⚠️ 文档转述（OpenTSDB HTTP API 口径，✅ http://opentsdb.net/docs/build/html/api_http/index.html
  登记，本会话未逐页抓取）：查询 = `GET /api/query`（start/end/metrics/aggregator/downsample），
  写入 = `PUT /api/put`；所谓"R/Go/Ruby 接口"皆是这层 JSON 的薄封装——
  **接口设计的本质是把 4.1 的聚合/降采样参数暴露为语言对象**。
- 重构要点：三语言选择反映 2014 年数据科学版图（R = 统计，Go = 运维工具，Ruby = Web 后端）；
  2026 回看该席位已被 Python/pandas 与 SQL 联邦查询取代（见演进节）。
- 与盘上通识的关系：这类"存储引擎 API 层"的取舍（REST 薄封装 vs 原生二进制协议）在
  [../Trino_The_Definitive_Guide_2e/00-总览与阅读地图.md](../Trino_The_Definitive_Guide_2e/00-总览与阅读地图.md)
  的连接器语境里是同一问题的另一端（查询引擎向下抽象存储）。

### 5.2 消费形态一：给眼睛的（图表与降采样选择）

- 绘图分辨率约束：屏幕像素数 ≪ 原始点数 → 降采样粒度应随时间窗自适应
  （1 小时窗用 10s 桶，1 年窗用 1d 桶）——3.4/🔧D2 的 rollup 层在此成为**性能刚需**
  而非省钱手段：查一年不降采样 = 扫千万点。
- ⚠️ 转述：本书倾向"查询时降采样"（引擎内 downsampler 现算），代价是重复计算；
  预物化多层 rollup 是另一极——🔧 **演示 D3b 续（DuckDB 1.5.5，非时序引擎）**：
  查询时聚合与物化 rollup 的等价性验证：对 2,000 点按 `i/100` 分桶（20 桶），
  `GROUP BY` 现算与预存 rollup 表逐桶比对，🔧 实测全等（02/04 章脚本
  `D:\develops\tmp\dbwave_w3_timeseries\demo.py` 同源）——
  "降采样正确性 = 聚合可分解性"的可检验陈述；真实引擎的差别全在增量维护成本（04 章 rollup 失效）。

### 5.3 消费形态二：给机器的（时序 → 特征）

- 封底 ✅ 实据："How time series databases contribute to practical machine learning projects"。
  ⚠️ 转述重构的论证骨架：
  1. ML 需要**对齐的多源特征矩阵**（温度 × 负载 × 价格 × …），TSDB 的
     （序列 × 时间段 × 聚合）三元查询天然产出"列 = 序列、行 = 时间桶"的宽表；
  2. 标签/时间泄漏（label leakage）是时序 ML 的头号正确性问题——训练特征必须只用
     预测时刻**已可观测**的桶（水位线思想的 ML 投影，对照
     [../Streaming_Systems/00-总览与阅读地图.md](../Streaming_Systems/00-总览与阅读地图.md)）；
  3. 异常检测 = TSDB 的"查询模式"而非"外挂系统"：对每条序列维护滚动均值/方差
     （或作者惯用的基线 + 残差分布），超界告警——两位作者的另一本短书
     *Practical Machine Learning: A New Look at Anomaly Detection*（✅ 封底文案明载同作者推荐）
     即该方案的展开。
- 🔧 **玩具异常检测（sqlite3，纯概念演示，脚本 `demo2.py`）**：对 🔧D 数据集（500 序列 ×
  400 点 @10s，正弦趋势 + 0.5σ 噪声）逐序列滚动 60 点窗口均值/标准差，标记 |z|>4 的点；
  随机注入 50 个 +25.0 尖峰。🔧 实测：200,000 点全量滑窗扫描 **2.90s**（Python 侧滑窗），
  **命中 43/50、漏报 7、误报 0**——漏报全部落在正弦波谷附近（窗口 σ 被趋势撑大，z 被稀释），
  这个"失败样本"恰是 5.3(3) 基线-残差框架的教科书注脚：**趋势不先扣，阈值必失真**
  （去趋势/季节性分解的动机由此可感；方法为玩具级，不代表任何检测引擎效果）。

| `start` / `end` | 时间段读（range-dominant） | 02/2.2 |

## 核心概念速览（中英对照）

- **薄客户端** — thin client：HTTP/JSON API 的语言封装（R/Go/Ruby 2014 三件套）
- **聚合器/降采样器参数化** — aggregator/downsampler as API：4.1 一等公民的消费侧镜像
- **分辨率自适应** — resolution matching：桶粒度随查询时间窗缩放，绘图刚需
- **查询时聚合 vs 物化 rollup** — on-the-fly vs materialized：降采样两极，等价性可验（🔧D3b）
- **特征矩阵** — feature matrix：列 = 序列、行 = 时间桶的 ML 输入宽表
- **标签泄漏** — label leakage：训练特征混入预测时刻不可观测的未来桶
- **滚动基线** — rolling baseline：均值/方差滑窗，TSDB 内置异常检测的最小形态
- **残差分布** — residual distribution：观测 - 基线的经验分布，超界即告警
- **水位线投影** — watermark projection：ML 特征截止 = 计算侧终点证据的存储侧使用
- **特征平台** — feature store：5.4 之争的产品化后代（演进节）
- **连续查询** — continuous query：滚动基线增量维护的流式名字

## 最新演进与工业实践

- **语言席位的更替**：R/Go/Ruby 组合已成时代标本；当代 TSDB 客户端事实三件套 =
  Python（pandas/parquet 直读）+ SQL 方言 + PromQL/Flux 类专用查询语言
  （⚠️ 转述；✅ https://docs.influxdata.com/influxdb/v2/ 200 实抓可见 Flux 口径）。

  PromQL→SQL 桥、DuckDB/Trino 直读对象存储上的指标导出件（⚠️ 转述；盘上
  [../Trino_The_Definitive_Guide_2e/00-总览与阅读地图.md](../Trino_The_Definitive_Guide_2e/00-总览与阅读地图.md)
