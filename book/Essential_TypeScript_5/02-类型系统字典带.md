## 二·五、擦除状态速判表（本带实测汇总，非书中内容）

「写法查得到，但它在运行时到底留不留东西」——本带把 Ⅱ 部机制按此二分，✅ 条目均有本会话真跑支撑：

| 类型层写法 | 运行时留痕 | 一手证据 |
|---|---|---|
| `type`/`interface`/`implements`/`declare` | 无 ✅ | `era.ts`（transform）→ `C keys: [ 'p','a','c' ]`、`C.prototype keys: [ 'constructor' ]` |
| 泛型形参与实参、`<const T>` | 无 ✅ | 同上：`f.length: 1`（元数不受类型影响） |
| 类型注解/交集/联合/字面量类型 | 无 ✅ | ../TypeScript系列·Runtime_vs_Type_System专题.md 三 实验 A |
| 类型谓词签名 `x is T` | 无（函数体照常跑） ✅ | `eo.ts` strip → `pure-erasable-ok: 1 true` |
| `satisfies` / `as const` | 无；且**不冻结对象** ✅ | `sat.ts` strip → `... false`（`Object.isFrozen(c)`=false） |
| `as` 断言 / `!` 非空断言 | 无（纯谎言通道） ✅ | `srv.mts` 用 `(...)[0]!` 直跑；专题档 四、推论 2 |
| 参数属性 `constructor(public p)` | **有** ✅（transform 产码；strip 拒） | `param.ts` → `ok P { q: 1 }` |
| `override` / `readonly` | 无 ✅（`override` 已跑）；`readonly` ⚠️ 未单测 | `ovr2.ts` strip → `override erased: 2` |
| 判别联合的判别字段（`kind`） | **有**（它是你手写的值，不是类型） ✅ | 专题档 四、推论 3 |

## 三、🔧 微实验（真跑记录，脚本 `/tmp/et5/`，会话临时未入库）

1. `sat.ts`：`node --experimental-strip-types sat.ts` → `satisfies/as-const/const-T param erased: {"a":1,"b":"x"} {"a":1} {"a":1} false` ✅ —— `satisfies`、`as const`、`<const T>` 三种现代「类型层强化」语法在运行时**零痕迹**，且 `as const` **不产生 `Object.freeze`**（`Object.isFrozen(c)`=false）：只读是类型层的，运行时对象仍可改。这条是本带对专题档公理的第 2 波补强。
2. `eo.ts`（`erasableSyntaxOnly` 纯擦除面）→ `pure-erasable-ok: 1 true` ✅ —— `import type { ... }`（含 runtime 模块 `node:readline` 的纯类型 import）、`type` 别名、类型谓词签名（`x is Box`）全数擦除后照跑；类型谓词的运行时身份就是普通函数（`g` 的 `return` 走的是手写的 `"v" in x`，**类型层什么都没替你做**）。
3. `era.ts`：strip 模式被**参数属性**挡住 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX: TypeScript parameter property is not supported in strip-only mode` ✅；`node --experimental-transform-types era.ts` → `C keys: [ 'p', 'a', 'c' ] | has p: true | f.length: 1 | C.prototype keys: [ 'constructor' ]` ✅ —— `implements`/`declare`/泛型形参运行时不留痕；泛型函数元数仍 1；参数属性是**少数会产码的类型层语法**（与专题档推论 4 对位，本波补上真跑证据 ✅）。
4. 盘外（**未实测 ⚠️**）：`strictNullChecks`/`noImplicitAny` 家族在同一组样例上的报错矩阵需独立 tsc——本机 `which tsc` 空，见 ../TypeScript系列·总索引.md 三、边界条。
