## 三、🔧 微实验（本机真跑，脚本在会话临时目录 `/tmp/et5/`，未入库）

1. `a.mts`（跨文件 import + 顶层 await）：`node --experimental-strip-types a.mts` → `esm-import-ok 7 ...` + `tla-ok`，exit=0 ✅ —— 多文件 `.mts` 直跑（显式扩展名 import）与 TLA 在 node 22.14 全可用；Ⅰ 部的 bundler 前置对本仓环境不必要。
2. `m1/s.ts`（目录含 `{"name":"m1","type":"module"}`）：`.ts` 被按 **ESM** 解释，`import.meta.url` 可用 ✅；同目录 `s2.ts` 写 `require("node:fs")` → `ReferenceError: require is not defined in ES module scope` ✅ —— 模块归属由 package.json/type 与 `.mts/.cts` 扩展名决定，**与 tsconfig 的 `module` 无关**（tsc 面本波未测 ⚠️）。
3. `c.cts`：`node --experimental-strip-types c.cts` → `cts-runs: 5 object string` ✅ —— `.cts` 下 `module`/`__filename` 存在，legacy 写法有专属逃生门。
4. `esfeat.ts`：static 初始化块、实例/静态 `#private`、解构、`Array.prototype.at`、`Object.hasOwn`、`structuredClone`、`fetch`、`WeakRef`、`Intl`、TLA **全部可用** ✅；同一文件放在无 package.json 的目录时报 `SyntaxError: Unexpected identifier 'Promise'` ✅（.ts 落 CJS 作用域 ⇒ TLA 非法）。裁决：**target/lib 该选哪一代，以 node 运行面实测为准**，书中「需降级」清单大面积失效。
5. `enum.ts`/`ns.ts`/`param.ts` 三件（环境带边界）：见 05 带 ✅ 实测（strip 全拒、transform 全跑）——本带只记「环境=Node 直跑；转译能力有限」结论，细节归 05。
