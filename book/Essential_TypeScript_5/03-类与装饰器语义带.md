## 二、本书独有价值点

1. **装饰器双语义并存期=本带最大坑位（⚠️ 版本对位一律不写死）**：TS 里同一段 `@decorator` 源码在两种语义下签名不同——**实验装饰器**（需 `experimentalDecorators: true`，参数 `(target, key, descriptor?)`、可配 `emitDecoratorMetadata` 反射元数据，Angular/NestJS 生态长期依赖）与 **Stage-3 标准装饰器**（TS 5.0 起原生路径，无元数据反射、context 对象形态不同）；**书中覆盖到哪一制、是否两制并讲，必须以目录销账 ⚠️**。本仓已有的一手证据只到运行面：见实验 7——两制在 node 22.14 **都跑不起来**，故本带任何装饰器结论只能来自 tsc/打包器侧，本波一律留欠账。
2. **Freeman 长例程对类的用法谱**：同一工程里「类→加访问修饰符→加参数属性→加装饰器」的连续重构步序是本仓独有可查表；主干书（Programming TS）讲语义不讲演进 ⚠️ 步序需目录销账。
3. 类设计裁决位：`private`（纯类型层）与 `#`（运行时硬墙）的取舍，本仓以专题档实测为准，本书只补「完整工程写法」样板。

## 二·五、装饰器双语义对照（⚠️ 语义列系公共面记忆，非书中原文；实测列=本会话真跑）

| 维度 | 实验装饰器（legacy 制） | Stage-3 标准装饰器 | 本仓实测 |
|---|---|---|---|
| 启用方式 | `experimentalDecorators: true`（TS 5.x 公共面上默认关 ⚠️） | 语言原生路径，不需该开关 ⚠️ | Node 侧两者**均需转译**，而 Node 不做 ✅ |
| 方法装饰器签名 | `(target, key, descriptor?)` | `(value, context)` 形态，context 带 kind/name ⚠️ | 两制源码在同一 node 22.14 上同报 V8 `Invalid or unexpected token` ✅（`legacy.ts`/`stage3.ts`，strip 与 transform 四组合） |
| 元数据反射 | 配 `emitDecoratorMetadata` 可发 `design:paramtypes` ⚠️ | 无对应机制 ⚠️ | 未实测（无 tsc）——本仓一切 DI 路线因此**不可复演** ⚠️ |
| 类装饰器返回值语义 | 可替换类 ⚠️ | 语义受限（constructor 装饰器另规） ⚠️ | 未实测 ⚠️ |
| 生态依赖 | Angular/NestJS 长期依赖 ⚠️ | 新库逐步采用 ⚠️ | 生态列属通识，书覆盖哪制=**销账第一优先** ⚠️ |

## 三、🔧 微实验（本机 2026-10-07 真跑，脚本在 `/tmp/et5/`，未入库）

1. `fieldkeys.ts`（`--experimental-transform-types`）→ `own keys order: [ 'b', 's', 'priv', 'b2' ] | has #hard: false | gx: 42 | static own: [ 'length','name','prototype','acc' ]` ✅ —— 字段初始化序=base 字段→derived 字段→ctor 体内赋值；`#hard` 不进 ownKeys、`priv`（无修饰符）进；类上静态 own 名含 `prototype`。
2. `ovr2.ts`（strip）→ `override erased: 2` ✅ —— `override` 纯类型层，产物里零痕迹（校验只发生在 tsc 面 ⚠️）。
3. `era.ts` 参数属性双面：strip 拒（`TypeScript parameter property is not supported in strip-only mode` ✅），transform 产码 `P { q: 1 }`（`param.ts` ✅）——类型层语法里**会产码**的那一小撮。
4. `ovr.ts` 的 `accessor z = 3`：strip 与 transform **均失败**，V8 `SyntaxError: Unexpected identifier 'z'` ✅ —— 自动访问器在 node 22.14 无转译支持；本仓用到它的例程必须走 tsc。
5. `enumshape.ts`（transform）→ `E: {"1":"A","2":"B","A":1,"B":2,"S":"str"} | destructure A: 1 | frozen: false | typeof E.A: number string str` ✅ —— 数字成员有反向映射、字符串成员没有；`enum` 对象**未冻结**（运行时可改，类型层毫无保护）；混合枚举 `typeof` 不统一。`const enum` 在 transform 下**未内联**（`ce2.ts` → `CE binding at runtime: {"5":"X","X":5}` ✅），与 tsc 非 isolatedModules 时的内联行为不同 ⚠️ 后者未实测（无 tsc）。
6. `ns.ts` namespace：strip 拒 ✅ / `--experimental-transform-types` 跑通输出 `1` ✅ —— `namespace` 属「产码语法」，与 05 带 `erasableSyntaxOnly` 代理面同构。
7. 装饰器双语义运行面判定（**本带核心实测**）：`legacy.ts`（类方法上的旧式装饰器）与 `stage3.ts`（标准语义装饰器）在 **strip 与 transform 四种组合全部 SyntaxError: Invalid or unexpected token** ✅；同目录放含 `experimentalDecorators: true` 的 `tsconfig.json` 后仍同样失败 ✅ —— 结论：**Node 的 TS 支持面完全不做装饰器转译，且 Node 直跑路径不读 tsconfig**；书中装饰器章的一切例程在本仓不可复演，需真 tsc/打包器（本波无）。
8. `mw.ts`（泛型类 + `private` 字段，strip）→ `chain: {"body":"HI!"} | hs erased? [ 'hs' ]` ✅ —— 泛型类 `Chain<Ctx>` 擦除后与普通类同形，而 **`private hs` 运行时照样出现在 ownKeys 里**：与 `#hard`（不入 ownKeys，实验 1）构成「礼貌私有 vs 硬墙私有」的双面实测，类设计第一条戒律。
9. 待补（依赖真 tsc ⚠️）：两制装饰器在同一份 `@log` 源码上的**产物 diff**（legacy 的 `__decorate` 帮助函数 vs 标准的原生 `@@metadata`）、`emitDecoratorMetadata` 的 `design:paramtypes` 是否随 `import type` 消失（Angular DI 地雷位）。
