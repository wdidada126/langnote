# 05 消息、事务与脚本

> 主题域：发布订阅、MULTI/EXEC/WATCH 事务、Lua 脚本原子性——「把多个命令拼成一个正确动作」的三条路线。
> Redis 命令全部为 redis.io 文档转述 ⚠️（不装不跑）；三路线的语义差异用对照表给逻辑判据，不做本机 Redis 验证。
> 主题归属声明见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

## 本章地图

| 配方 | 你能做到 | 关键命令 |
| --- | --- | --- |
| 广播通知 | 即时失效/在线状态推送 | `SUBSCRIBE/PUBLISH/P UNSUBSCRIBE` |
| 模式订阅 | 按前缀通配订阅 | `PSUBSCRIBE chan:*` |
| 命令打包 | 一串命令不被穿插（但不回滚） | `MULTI/EXEC/DISCARD` |
| 乐观并发 | 读-改-写不丢更新 | `WATCH + MULTI + EXEC( nil=冲突重试)` |
| 原子宏 | 多命令逻辑一把梭、服务端执行 | `EVAL/EVALSHA`、`SCRIPT LOAD/EXISTS` |
| 原子弹出 | 队列取走+入处理中等复合动作 | 脚本化 `ZRANGE+ZREM`、旧 `RPOPLPUSH` |

## 核心配方精讲

### 配方：pub/sub 是烟花不是信使 ⚠️

`PUBLISH chan msg` 只投递给**当前在线**订阅者，无持久化、无重放、离线即错过——2011 年至今一字未变
（文档：https://redis.io/docs/latest/develop/interact/pubsub/ ✅ curl 200）。适用三件套：缓存失效广播
（配 04 章 cache-aside）、在线状态/输入中指示、跨进程轻量通知。**不适用**：任务队列、事件溯源、任何「必须送达」——
那些场景在 5.0 后归 Streams（消费组+PEL），本书时代归外部 MQ ⚠️。`PSUBSCRIBE` 的模式匹配在订阅者多时
成本按订阅模式数乘积计，滥用会让一条 PUBLISH 变成扇出风暴。

### 配方：事务的真实语义——打包，不是一致性 ⚠️

`MULTI...EXEC` 保证**队列不被穿插**（期间其他客户端命令进不来），但：① 运行期某命令报错**不回滚**先前已执行的；
② 入队期语法错误整个事务拒收；③ 无回滚=无 ACID 的 R。别按关系库直觉理解「事务」二字 ⚠️
（文档：https://redis.io/docs/latest/develop/using-commands/transactions/ ✅ curl 200）。
真正的价值主张一句话：把「N 条命令」变「1 个执行单元」，省 N-1 个 RTT 且拿到执行不被打断。

### 配方：WATCH——乐观锁的标准姿势 ⚠️

读阶段（GET 或计算输入）→`WATCH` 相关键→`MULTI` 写事务→`EXEC`：返回 `nil` 表示监视期间键被动过，
**重试整个读-改-写循环**。这就是 04 章「更新缓存」写路径、07 章「读计数-判断-写回」类配方的并发护甲。
与悲观锁对照：WATCH 不阻塞任何人的读写（除 EXEC 的打包瞬间），冲突概率高时重试成本反超——
高冲突复合操作直接上脚本。

### 配方：EVAL——服务端原子宏的边界与代价 ⚠️

`EVAL script numkeys key.. arg..` 单命令完成「读→判→写→返回」全逻辑：脚本执行期间**整个实例为你让路**
（单线程语义），这是比 MULTI 更硬的原子性，也是 07 章「锁的 Lua 释放」的立足点
（文档：https://redis.io/docs/latest/commands/eval/ ✅ curl 200）。三条纪律：
① **键走 KEYS[]、常量走 ARGV[]**——集群/未来演进的正确性全押在这条约定上（2011 年弱约束、当代集群硬约束 ⚠️）；
② 脚本**确定性**要求（旧版）：随机命令（SRANDMEMBER/TIME）不可裸用，需 `redis.call('TIME')` 类写权宜或转函数；
③ 长脚本=全实例阻塞——`lua-time-limit 5` 默认，超时后可 `SCRIPT KILL`（未写时）或只能 `SHUTDOWN NOSAVE`（已写时）：
**评审期把脚本行数与循环规模当 P99 延迟预算看**。EVALSHA/SCRIPT LOAD 解决脚本体积与网络重复传输：
客户端缓存 SHA，先 EVALSHA、遇 `NOSCRIPT` 回退 EVAL/SCRIPT LOAD——库都封装了这手 ⚠️。

### 配方：原子弹出的前传 ⚠️

「取走并移到别处」类动作（可靠队列雏形）在 2011 年用 `RPOPLPUSH src dst`（单命令原子）或脚本
`ZRANGE+ZREM` 实现；6.2 起 `LMOVE` 补双向，7.0 时代更多场景已由 Streams 的 `XAUTOCLAIM` 接管 ⚠️。
判读口诀：**能用单命令就不要 MULTI，能用 MULTI 就不要 EVAL**——原子性够用即止，脚本是最后手段。

## 三条路线对照表（本章总判据）

| 维度 | pub/sub | MULTI/EXEC | WATCH 事务 | EVAL 脚本 |
| --- | --- | --- | --- | --- |
| 原子性 | 无（消息各自投递） | 执行不被穿插 | 同 MULTI+冲突检测 | 全实例让路，真原子 |
| 回滚 | 不适用 | **无** | 无（重试代替） | 单线程内天然「全或停」 |
| 读中间态可用 | 否（订阅非读） | 否（EXEC 前只有入队） | 事务外读 | **是**（脚本内先读后判） |
| 典型用途 | 失效广播/通知 | 批量写省 RTT | 低冲突读改写 | 锁释放/复合判定 |
| 失败模式 | 订阅者离线丢消息 | 运行期命令错继续执行 | 活锁/重试成本 | 脚本超时阻塞全实例 |
| 2026 归宿 | 客户端侧缓存/Streams 分流 | 保留（管道更常用） | 保留 | Functions(7.0) 工程化 |

一句话决策树：**只要送达→Streams/MQ；只要不穿插→MULTI；要看旧值写新值→WATCH；还要中间判断→EVAL**。

## 常见坑与判读

| 坑 | 症状 | 判读/规避 |
| --- | --- | --- |
| 拿 pub/sub 当队列 | 消息随订阅者离线蒸发 | 送达语义上 Streams/MQ |
| MULTI 当回滚 | 半途出错留下半套数据 | 需要真原子→脚本；需要回滚→外部存储 |
| 脚本死循环 | 全实例阻塞至杀 | 评审脚本复杂度；超时杀脚本 SOP |
| 裸 SRANDMEMBER 进脚本 | 主从/复制语义风险 | 确定性规则或转函数 ⚠️ |
| WATCH 重试不设上限 | 高冲突下活锁 | 指数退避+上限+降级悲观 |
| EVAL 拼参数进脚本体 | 注入与 NOSCRIPT 双坑 | 一切入参走 ARGV[] |

## 核心概念速览（中英对照）

- **发布订阅** — Pub/Sub — 即发即忘的频道广播，零持久化。
- **模式订阅** — PSUBSCRIBE — glob 通配订阅，扇出成本随模式数上升。
- **事务** — MULTI/EXEC — 命令打包不被穿插；无回滚。
- **监视重试** — WATCH CAS — 键版本变了 EXEC 返回 nil，重试读-改-写。
- **乐观并发控制** — OCC — 不锁资源、冲突了重来，与悲观锁相对。
- **Lua 脚本** — EVAL — 服务端原子宏，执行期独占实例。
- **EVALSHA/SCRIPT LOAD** — 脚本缓存 — 按摘要引用服务端脚本，省带宽防重复传输。
- **NOSCRIPT** — 脚本未缓存错 — 客户端回退整脚本重发的信号。
- **lua-time-limit** — 脚本超时线 — 默认 5s，越线后可 KILL（未写时）。
- **RPOPLPUSH/LMOVE** — 原子转移弹出 — 取走+落位一条命令完成（可靠处理中间态的原料）。
- **Streams 与消费组** — Streams/Consumer Groups — 5.0 起接棒「可靠消息」叙事的正式主角。
- **确定性约束** — Script Determinism — 旧版脚本可随机命令、主从各自执行的口径；7.0 函数时代弱化 ⚠️。

## 最新演进与工业实践

- **Functions（7.0，2021）**：EVAL 的工程化升级——服务端命名函数库（`FUNCTION LOAD/FCALL`），
  脚本不再每客户端各存一份、NOSCRIPT 问题根除；效果等价、治理更好 ⚠️（文档口径）。
- **脚本确定性放宽**：7.x 效果复制改为命令传播层面重定义，旧「随机命令黑名单」叙事在当代文档中淡出 ⚠️——
  2011 年读到的脚本规则多数已换代，迁移旧脚本先重读 protocol-spec 页（✅ curl 200，见 01 章引用）。
- **客户端侧缓存（6.0+）**：RESP3 + tracking 让「pub/sub 做失效广播」有了官方协议级形态（`CLIENT TRACKING`），
  本章的失效配方在 2024–2026 已是标准库特性而非手搓脚本 ⚠️。
- **工业实践**：高冲突复合操作（库存扣减、红包拆分）在社区共识里一律「脚本/函数 + 幂等键」，
  且把脚本超时列入事故库（全实例阻塞半径太大）⚠️；锁释放必须 Lua 比较删除的定论由 07 章展开，
  与 Kleppmann 论战的工程落点见其文（✅ 2026-09-27 curl 200：
  https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html）。
