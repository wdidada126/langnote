# 02 字符串、计数器与键管理

> 主题域：字符串命令族、原子计数、SETNX/SETEX 语义、键命名规范、键生命周期管理（EXISTS/TTL/RENAME/DEL/SCAN）。
> 取证口径：Redis 命令为 redis.io 文档转述 ⚠️；「计数器=INCR/SETNX 逻辑语义」有 sqlite3 真跑演示 🔧（**非 Redis 行为**）。
> 主题归属声明见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

## 本章地图

| 配方 | 你能做到 | 关键命令 |
| --- | --- | --- |
| 存取标量与序列化对象 | 字符串承载 JSON/blob/数字 | `SET/GET/APPEND/GETRANGE/STRLEN` |
| 原子计数器 | 页访/库存/限流数不丢不加 | `INCR/INCRBY/DECR/DECRBY/INCRBYFLOAT` |

| 带失效时间的写 | 会话/验证码一类短期值 | `SETEX/SET KEX`（TTL 随行） |
| 批量读写 | 少往返的 M 族 | `MSET/MGET/MSETNX` |
| 键命名与分类 | 可运维的键空间 | `命名规范`、`TYPE/TTL/EXISTS` |
| 安全遍历键 | 生产扫库不阻塞 | `SCAN` 游标（`KEYS` 禁用于生产） |
| 键迁移与删除 | 改名不换槽、删除不心疼 | `RENAME/RENAMENX/DEL/UNLINK` |

## 核心配方精讲

### 配方：字符串族的完整剖面 ⚠️

`SET key value [EX s] [PX ms] [NX|XX] [GET]`（文档：https://redis.io/docs/latest/commands/set/ ✅ curl 200）——
2011 年书里 SETNX+SETEX+EXPIRE 三条拼出来的语义，Redis 2.6.12 起被一条 SET 的选项收编；这是本册「版本基线提醒」
的第一个具体例：**旧配方合并、旧命令保留兼容**。`APPEND/GETRANGE/SETrange/STRLEN` 提供偏移量级读写，
可用于追加式日志；`INCRBYFLOAT` 面向浮点计数（分数/汇率聚合，哈希版见 `HINCRBYFLOAT`：
https://redis.io/docs/latest/commands/hincrbyfloat/ ✅ curl 200）。
大值对象（>10KB JSON）直接整读整写是常见起点，但热读场景应转哈希字段级读写（03 章），省序列化与带宽。

### 配方：计数器——Redis 最便宜的原子性 ⚠️+🔧

Redis 单线程执行模型下 `INCR` 对同键天然串行：读-改-写不可穿插，这就是 2011  Cookbook 式「页访问计数/日限额」
配方全部押在 INCR 上的原因。工程四细节：① 计数键要带时间粒度后缀（`hits:page:42:20260927`）配 `EXPIRE`，
否则无限堆积；② 粒度后缀同时是巡检与按族清理脚本可利用的信息（键命名=运维合同，见下文）；
③ `INCR` 于已存在非整数值上报错——**键空间复用要换前缀而不是清值**；④ 高并发单键计数是热点，
现代做法分片（`hits:{page}:shard{0..N}` 各自 INCR，读时求和，成本换均衡）。

🔧 **语义等价物演示**（sqlite3 3.45.3，Python 3.13；脚本 `D:\develops\tmp\dbwave_w3_rcook\demo.py`，
输出 `demo.out`；**演示的是 INCR/SETNX 的逻辑语义，非 Redis 性能**）：
- `SETNX` ⇔ `INSERT OR IGNORE`：首次插入返回 1（成功），键已存在返回 0——真跑两轮得 `1 → 0` 序列 ✓。
- `INCRBY 1000` ⇔ 单语句 `UPDATE kv SET val=val+1000 ... RETURNING val`：读-改-写收进一条语句即原子步长。
- 连续 1000 次「单语句 INCR+读回」真跑耗时 **4.8 ms**（内存库），终值精确 1000——验证的是「单语句=原子」
  这条协议逻辑在 SQL 世界的等价物；Redis 侧对应结论（单线程无穿插）只能引文档 ⚠️。

### 配方：键命名是运维合同 ⚠️

`类型:实体:限定` 冒号分层（`user:1001:profile`）不是风格洁癖：`--bigkeys`、SCAN 模式匹配、按前缀清理脚本、
监控聚合都吃这个约定。两条硬规则：① 键里不要放自由文本（用户昵称会造出不可管理的热键空间）；
② 前缀首段做「表名」，让 04 章的淘汰策略与巡检脚本可以按族处理。命名规范在 2011 至 2026 的官方文档中一以贯之 ⚠️。

### 配方：SCAN 而不是 KEYS ⚠️+🔧

`KEYS pattern` 一次性全库遍历，O(N) 且阻塞单线程——生产环境等于自 DoS。`SCAN cursor [MATCH pat] [COUNT n]`
给游标式增量遍历：不保证快照一致（两次游标间的写入可见性随意）、保证**遍历开始时已存在且未被删的键必被返回**。
客户端库的 `scan_iter` 即此封装（文档：https://redis.io/docs/latest/commands/scan/ ✅ curl 200）。
🔧 语义等价物：SQLite `SELECT name FROM sqlite_master WHERE name LIKE 'hits:%'` 的一次性快照 vs
「LIMIT/OFFSET 游标分页」的增量视图——SCAN 的「可能重复、不漏存量」契约相当于游标分页在可变集合上的弱化版
（本册演示集中在计数/排行/锁三例，SCAN 语义按此推读，未单独真跑 ⚠️）。

### 配方：键生命周期 ⚠️

`EXISTS` 判存在（多键版一次给计数）；`TYPE` 决定后续命令族；`TTL/-1/-2` 双含义：-1=存在但无过期、-2=键不存在——
**判「不存在」和「不过期」必须用两个命令或看返回值语义**，这是 04 章缓存三态（命中/未命中/陈旧）的地基。
`RENAME` 原子改名（同 db 内）；`DEL` 同步删除，大值（百万成员集合）删除的阻塞在 4.0 由 `UNLINK` 后台化 ⚠️。
`GETDEL`（6.2）一条命令完成读后删，收编了旧「GET+DEL 哨兵式」脚本配方：
https://redis.io/docs/latest/commands/getdel/ ✅ curl 200。

## 常见坑与判读

| 坑 | 症状 | 判读/规避 |
| --- | --- | --- |
| INCR 复用脏键 | `ERR value is not an integer` | 键空间隔离，别拿对象键当计数键 |
| SETNX 后崩溃没 EXPIRE | 锁/标志位永驻 | 一律 `SET NX EX` 单命令（旧两命令配方已废） |
| 生产 KEYS | 秒级延迟尖峰全实例遭殃 | SCAN；巡检用 `--bigkeys` |
| TTL 判存在 | -2 与 -1 混为一谈 | 三态：有值/有键无 TTL/无键 |
| 热单键计数 | CPU 集中在一个核对列 | 分片计数 + 读侧求和 |
| 大键 DEL 阻塞 | 删百万成员集合卡住主线程 | UNLINK（4.0+）或分批 SPOP |

## 核心概念速览（中英对照）

- **原子计数** — INCR/DECR — 单线程串行的读-改-写，Redis 最廉价的原子性。
- **计数分片** — Counter Sharding — 热点单键拆 N 片各自 INCR，读侧求和。
- **SETNX** — SET if Not eXists — 键不存在才写；现代写法并入 `SET ... NX`。
- **SETEX** — SET with EXpire — 带 TTL 的写；现代写法 `SET ... EX`。
- **键命名规范** — Key Naming Convention — `类型:实体:限定` 冒号分层，供巡检/清理/监控按族处理。
- **TTL 三态** — TTL Semantics — 返回值正数/`-1`(无期)/`-2`(不存在) 构成缓存判读三态。
- **SCAN 游标** — SCAN Cursor — 增量遍历：可重复、不漏存量、不快照一致。
- **MSET/MGET** — Multi-key 读写 — 多键单往返；跨槽时集群模式受限。
- **RENAME 原子改名** — RENAME — 同 db 内键更名，蓝绿换键的基础件。
- **UNLINK** — 异步删除 — 4.0 起把大键回收挪到后台线程。
- **GETDEL** — 读并删 — 6.2 起的原子「取走即销毁」，队列/一次性令牌常用。
- **MSETNX** — 批量仅不存在才写 — 多键「全有或全无」占位。
- **SET 选项面** — EX/PX/NX/XX/GET — 一个命令收编旧 SETNX/SETEX/GET+SET 全部拼装。
- **键族** — Key Family — 以首段前缀划同族的键集合，淘汰与巡检按族处理的前提。
