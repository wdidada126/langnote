# 06 持久化、复制与运维管理

> 主题域：RDB/AOF 两轨持久化、主从复制语义、配置与观测（CONFIG/SLOWLOG/INFO）、安全收编（requirepass→ACL）。
> 全部为 redis.io 文档转述 ⚠️（本机无 Redis，不做 Docker 尝试）；「RDB fork 内存峰值」类数字一律不引用本机。
> 主题归属声明见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

## 本章地图

| 配方 | 你能做到 | 关键命令/参数 |
| --- | --- | --- |

## 核心配方精讲

### 配方：RDB——快恢复、粗耐久 ⚠️

`save 900 1` 类规则触发 `BGSAVE`：fork 子进程写紧凑快照文件。两个 2011 年讲到今天仍有效的代价模型：
① fork 瞬间的**内存记账成本**与写时复制（COW）污染——快照期间高写入可让 RSS 冲到数倍 used_memory ⚠️，
「32GB 实例留一倍余量」是旧 Cookbook 的经典告诫；② 崩溃丢失窗口=距上次快照的全部写入，规则调多久丢多久。
手动 `BGSAVE`+`LASTSAVE` 巡检、`--rdb` 拉全量做异地备份，都是本书时代就成型的操作 ⚠️。
`SAVE`（同步阻塞版）在生产按下等于自杀，旧书特别警告过，今天依旧。

### 配方：AOF——细耐久、重放贵 ⚠️

`appendonly yes` 后每条写命令追加文本日志；`appendfsync everysec`（默认推荐，最多丢 1 秒）与
`always`（每次落盘，吞吐断崖）构成耐久/成本的两端 ⚠️。日志会无限肥——重写机制
（现代为 `auto-aof-rewrite-percentage/min-size`）用当前数据集生成等价短 AOF 替换。6.0 起默认
**混合持久化**：重写时以 RDB 二进制打底、尾部继续 AOF 增量——恢复速度与耐久窗口首次不再二选一。
判读口诀：RDB 管「灾难恢复的地板」，AOF 管「崩溃丢失的天花板」，两轨同时开着才是常态配置。

### 配方：复制语义——异步、两阶段、可断点 ⚠️

新从库 `replicaof host port`：全量同步（主 fork 发 RDB + 缓冲增量）→ 命令流持续复制；
断线后 5 字节历史环形缓冲（`repl-backlog-size`）允许**部分重同步**（PSYNC2 时代多从库链路亦支持）⚠️
（文档：https://redis.io/docs/latest/operate/oss_and_stack/management/replication/ ✅ curl 200）。
三条铁律级判读：① 复制**异步**——主确认写入后崩溃可能丢已确认写（07 章锁的失效场景之源）；
② 从库默认只读（`replica-read-only yes`），过期键以主发 DEL 传播（04 章两阶段的镜像面）；
③ `min-replicas-to-write/min-replicas-max-lag` 提供「无多数则拒写」的**弱化版**保护——不是共识，
是止血带（DDIA 对半同步家族的评价同此 ⚠️）。

### 配方：观测与在线运维 ⚠️

`INFO` 分节读法：`server`（运行时长/配置漂移）、`clients`（连接构成）、`memory`（04 章主战场）、
`persistence`（最近 BGSAVE/AOF 成功失败——**告警就挂这几个时间戳**）、`replication`（role/master_repl_offset/
slave_repl_offset 差值=延迟字节数）、`stats`（命中率/evicted_keys/expired_keys）、`commandstats`（每命令 QPS/延迟分布）。
`SLOWLOG` 只记「命令本身执行慢」（默认 10 微秒阈值 ⚠️），不含网络排队——它抓得出 `KEYS`/大 `SORT`，
抓不出慢客户端。`CONFIG GET/SET` 在线试参数、验证后 `CONFIG REWRITE` 固化——2011 年即标准流程，
注意并非所有参数可动态（文档按参数标注 mutable 性 ⚠️）。

### 配方：安全收编——从 requirepass 到 ACL ⚠️

旧配方三件：`bind` 内网 + `protected-mode yes` + `requirepass`，外加 `rename-command FLUSHALL ""` 封高危命令。
7.0 起 ACL 提供多用户、命令/键模式级授权与密码哈希（`ACL SETUSER`），`requirepass` 退化为 default 用户的兼容开关 ⚠️
（文档：https://redis.io/docs/latest/operate/oss_and_stack/management/security/acl/ ✅ curl 200）。
现代底线没有变的那一条：**Redis 协议本身不是为公网设计的**，暴露公网永远过隧道/TLS 层——本书时代的
「别裸奔」告诫在 CVE 史（2.x 时代未授权访问写 crontab/SSH key 的经典入侵链）之后已成铁律 ⚠️。

## 常见坑与判读

| 坑 | 症状 | 判读/规避 |
| --- | --- | --- |
| save 规则默认+大数据集 | fork 卡顿/磁盘疯写 | 关自动 save、以 AOF 或外部备份替代 |
| 误按同步 SAVE | 实例秒级全阻塞 | 只用 BGSAVE；脚本别名封死 SAVE |
| appendfsync always | 吞吐断崖、SSD 寿命 | everysec 起步，耐久分级讲场景 |
| 主崩丢已确认写 | 「写成功的数据没了」 | 异步复制的物理 limit；需要则上等待方案或换存储 |
| backlog 太小 | 频繁全量同步风暴 | 断线时长×写速率预算 repl-backlog-size |
| 从库做唯一备份 | 「备份=从库」幻觉 | 从库也会 RDB 复制错数据；快照独立外存 |
| 只盯命中率不盯 evicted | 淘汰在默默吃正确性 | keyspace_misses 与 evicted_keys 同屏 |

## 核心概念速览（中英对照）

- **RDB 快照** — RDB Snapshot — fork 子进程写的紧凑二进制全量，恢复快、窗口粗。
- **写时复制污染** — COW Dirtying — 快照期高写入令 RSS 远超数据集大小的机制。
- **AOF** — Append Only File — 写命令文本日志，everysec/always/no 三档落盘策略。
- **AOF 重写** — AOF Rewrite — 以当前数据生成等价短日志（6.0 后多为 RDB 打底混合式）。
- **混合持久化** — Mixed Persistence — RDB preamble + AOF 增量，恢复与耐久兼得。
- **全量/部分同步** — Full/Partial Resync — PSYNC 断点续传，受 repl-backlog-size 窗口约束。
- **复制偏移量** — Replication Offset — master/slave_repl_offset 差值=落后字节。
- **异步复制丢写** — Async Replication Loss — 已确认写在主崩后消失的固有窗口。
- **min-replicas-to-write** — 副本止血带 — 无合格从库则拒写，弱化保护而非共识。
- **SLOWLOG** — 慢命令日志 — 只记服务端执行超阈命令，不含网络/排队耗时。
- **protected-mode** — 保护模式 — 无配置无密码时拒绝公网裸连的出厂护栏。
- **lastsave 与告警** — LASTSAVE — 最近快照时间戳，持久化健康告警的挂载点。
- **磁盘化复制** — Diskless Replication — 5.0+ 经 socket 直发 RDB，免去主盘写读一跳。
- **命令改名** — rename-command — 旧时代高危命令封禁手段，现由 ACL 命令授权取代。
- **ACL 用户** — ACL User — 多用户+命令/键模式授权（7.0），替代单密码时代。

## 最新演进与工业实践

- **命令改名**：`SLAVEOF`→`REPLICAOF`（5.0 起并存、文档主推）；`appendonly` 参数家族在 7.x 文档中
  以 AOF 单开关收敛（多文件分片形态出现于 7.0 的 cluster 侧）⚠️。
- **AOF  fsync 组**与后台化：持久化路径逐步交给 IO 线程化/后台清理（UNLINK、lazyfree 家族参数
  `lazyfree-lazy-*`）——2011 年「fork 一切能后台的」的哲学延续 ⚠️（persistence 文档：
  https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/ ✅ curl 200）。
- **许可与分叉影响备份链**：Redis 8（AGPLv3 选项，见 https://redis.io/blog/ ✅）与 Valkey（
  https://valkey.io/ ✅）双线上，RDB/AOF 文件格式仍是共同底座，跨线迁移的备份兼容性成为 2025–2026 新问题 ⚠️
  （两项目文档口径）。
- **观测面演进**：`LATENCY` 命令族（2.8+）与 `MEMORY DOCTOR`（4.0+）把本章「INFO+SLOWLOG 两件套」扩展成
  四件套；当代托管服务的指标导出（redis_exporter 类）即在其上建 Prometheus 面板 ⚠️（文档/项目口径）。
- **工业实践**：2024–2026 生产栈里「关自动 save + AOF everysec + 外部快照备份」是托管与自建两域趋同的默认；
  ACL 多用户接入应用/运维/备份三条通道，`rename-command` 退居二线 ⚠️；「已确认写丢失」的评审问题
  统一导向应用层幂等与对账（与 07 章、DDCA 08 章连成一线）。
