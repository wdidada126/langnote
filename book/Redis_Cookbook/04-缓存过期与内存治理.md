# 04 缓存、过期与内存治理

> 主题域：缓存读写模式（cache-aside/击穿/雪崩）、TTL 机制内幕、maxmemory 与淘汰策略、内存优化手段。
> Redis 命令与策略行为全部为 redis.io 文档转述 ⚠️（本机不装不跑 Redis）；过期语义的逻辑演示给 SQL 等价口径但不单独真跑 ⚠️。
> 主题归属声明见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

## 本章地图

| 配方 | 你能做到 | 关键命令/参数 |
| --- | --- | --- |
| Cache-Aside | 读缓存未命中回源并回填 | `GET`→查库→`SET EX` |
| 防击穿（单飞） | 热 key 失效风暴只放一条回源 | `SET NX EX` 互斥 + 等待重读 |
| 防雪崩 | TTL 加抖动、分级过期 | `EX` 上加随机量 |
| 主动/惰性过期判读 | 理解「删了但内存没还」 | `EXPIRE/TTL`、过期键两阶段 |
| 设定内存上限 | 实例不再无限吃内存 | `maxmemory` |
| 选淘汰策略 | allkeys-lru / volatile-* / LFU / TTL | `maxmemory-policy` |
| 编码级省内存 | 小对象压缩存储吃满红利 | listpack/intset 阈值参数 |
| 观测内存 | 谁在吃、命中率多少 | `INFO memory/stats`、`MEMORY USAGE` |

## 核心配方精讲

### 配方：Cache-Aside 的完整闭环 ⚠️

读路径：`GET key` 命中返回；未命中→回源（DB/服务）→`SET key val EX ttl`→返回。写路径二选一：
**删缓存**（`DEL`，下次读自然回填，简单但窗口内可能读到旧值）或**更新缓存**（并发写需要 05 章 WATCH 或脚本护航）。
2011 书与当代文档在这一点上没有变化：Cache-Aside 的一致性上界就是 TTL，业务要求更强就得换写路径方案或放弃缓存 ⚠️。

### 配方：击穿互斥与抖动 ⚠️

热 key 到点群蜂回源——用 02 章的 SETNX 当「单飞锁」：抢到者回源重建，未抢到者短暂 sleep 后重读缓存。
注意这是**概率正确**（锁 TTL 短、回源慢于锁期时仍有群蜂），本质是 07 章分布式锁的最小用例。
雪崩对策是把 TTL 打散：`EX base + rand(0, base/5)`，避免整点同批键同时蒸发 ⚠️。

### 配方：TTL 机制的内幕（两阶段过期）⚠️

惰性删除：读时检查过期才删——正确性来源；定期删除：后台周期抽样删——摊平成本。两点工程推论：
① 过期键可能**逻辑上已死、物理上仍占内存**，`INFO keyspace` 的计数不可当精确值用；
② 从库不自主过期（以主为准，主发 DEL 传播）⚠️——这条在 06 章复制语义里再出现。
`EXPIRE/PEXPIRE/EXPIREAT/PERSIST` 全族 + TTL 三态返回（02 章）是键生命周期的命令面；
7.4 起哈希字段也能带 TTL（`HEXPIRE` 族）⚠️（厂商文档口径，本册未验该页 URL）。

### 配方：maxmemory 与淘汰策略 ⚠️

不设 `maxmemory` 的 Redis 是内存黑洞；设了不选策略等于默认 `noeviction`——写命令开始报错而不是变慢，
很多「缓存服务大面积 500」事故的根因。**策略选择表**（文档转述，
https://redis.io/docs/latest/operate/oss_and_stack/management/optimization/memory-optimization/ ✅ curl 200）：

| 场景 | 策略 | 理由 |
| --- | --- | --- |
| 纯缓存，键可随意丢 | `allkeys-lru`（默认直觉）或 `allkeys-lfu`(4.0) | 全键空间竞争，命中优先 |
| 缓存+少量必须常驻 | `volatile-lru/lfu` | 只动带 TTL 的键 |
| 有精确过期语义的任务键 | `volatile-ttl` | 先淘汰最快过期的 |
| 数据不能丢（队列/锁/计数） | `noeviction` + 容量告警 | 淘汰=数据损坏，宁报错 |
| 随机可容忍 | `allkeys-random` | 近似访问不可估时反而公平 |

LRU 是**近似采样**（`maxmemory-samples` 默认小样本）不是全量 LRU——采样数调大更接近理论但更耗 CPU ⚠️。
LFU（4.0）用计数器对「长期冷、瞬时热」更稳，适合缓存与批处理混布的实例 ⚠️。

### 配方：编码阈值是隐形预算 ⚠️

`hash-max-listpack-entries/value`、`list-max-listpack-*`、`set-max-intset-entries`、`zset-max-listpack-*` 四组阈值决定
小对象走紧凑编码还是通用结构。设计键时把「单哈希字段数 < 128、单值 < 64B」当默认预算（2.x 时代为 ziplist 阈值，
7.2 起 listpack 取代 ziplist——命名换代、思想不变 ⚠️）。**超过阈值的那一次写入不会立刻转化**（读侧惰性重建），
所以阈值调大后内存不会自动涨、调小后也不会立刻缩 ⚠️。

### 配方：观测三件套 ⚠️

`INFO memory`（used_memory / maxmemory_human / 各编码占比）、`INFO stats` 的
`keyspace_hits/misses`（命中率=缓存健康度主指标，注意 `expired_keys` 同屏看）、
`MEMORY USAGE key`（4.0，单键精确记账）。2011 年只有前两件，MEMORY 族是后补的——读旧配方时把「估算」升级为「实测命令」 ⚠️。

## 常见坑与判读

| 坑 | 症状 | 判读/规避 |
| --- | --- | --- |
| maxmemory 满 + noeviction | SET 直接 OOM command 报错 | 缓存实例必设淘汰策略 |
| 把 KEYS 当监控 | 巡检脚本打挂生产 | `--bigkeys`/SCAN（02 章） |
| 过期≠释放 误判 | 「TTL 到了内存没降」报警 | 两阶段+惰性重建，看 INFO 曲线趋势 |
| TTL 相同批量导入 | 整点雪崩 | 抖动（本章配方） |
| 击穿锁永不过期 | 回源崩溃后全键锁死 | 锁必带短 EX（NX+EX 单命令） |
| 大哈希贴阈值边缘 | 内存账与编码红利剧烈波动 | 键设计期就按 128/64B 预算拆 |

## 核心概念速览（中英对照）

- **Cache-Aside** — 旁路缓存 — 读未命中回源回填；一致性上界=TTL。
- **缓存击穿** — Hot-Key Breakdown — 单热键失效引发回源风暴；互斥单飞缓解。
- **缓存雪崩** — Cache Avalanche — 批量键同期失效；TTL 抖动缓解。
- **惰性删除** — Lazy Expiration — 读时判过期才删，正确性来源。
- **定期抽样删除** — Active/Sampled Expiration — 后台周期抽样清理，成本摊平。
- **maxmemory** — 内存上限 — 实例容量合同；不写=黑洞。
- **淘汰策略** — Eviction Policy — noeviction/LRU/LFU/TTL/random × allkeys/volatile 矩阵。
- **近似 LRU** — Approximated LRU — 采样 N 候选择旧，非全量精确。
- **LFU 计数器** — LFU Decay Counter — 4.0 引入的对数概率计数器频率估计。
- **listpack 编码** — Listpack（旧称 ziplist）— 小复合对象的紧凑连续内存表示。
- **命中率** — Hit Rate — keyspace_hits/(hits+misses)，缓存主 KPI。
- **MEMORY USAGE** — 单键记账 — 4.0+ 的按键含开销精确统计。
- **碎片率** — Mem Fragmentation Ratio — used_memory_rss/used_memory，>1.5 值得警觉 ⚠️。
