# 03 哈希、列表、集合与有序集

> 主题域：四大复合数据类型的配方——对象存储（哈希）、队列与窗口（列表）、标签与去重（集合）、
> 排行榜（有序集）。Redis 命令为文档转述 ⚠️；排行榜配方附 DuckDB/sqlite3 **语义等价物**真跑 🔧（非 Redis 行为）。
> 主题归属声明见 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

## 核心配方精讲

### 配方：哈希存对象——字段级更新是灵魂 ⚠️

`HSET user:1001 name bob age 30`；只改年龄用 `HSET ... age 31` 或 `HINCRBY`，不动其他字段、不整取整存——
对 02 章「字符串整存 JSON」的优势在热更新场景直接兑现为带宽与序列化节省（文档：
https://redis.io/docs/latest/develop/data-types/hashes/ ✅ curl 200）。
`HINCRBYFLOAT` 支撑分数类字段原子更新（✅ curl 200 见 02 章引用）。小哈希在内部以 listpack 编码存为单键
连续内存（省内存的主因），**字段或值过大即转哈希表编码**、红利消失——「一个大 JSON 塞一个字段」等于退化回字符串，
这是 Cookbook 时代就有的告诫 ⚠️。

### 配方：列表当队列与时间线 ⚠️

`LPUSH`+`BRPOP` 组 FIFO（阻塞端天然做 worker 挂起）；注意：裸 list 队列**无 ACK、无重投**，消费者崩溃即丢消息——
当代可靠队列走 Streams（5.0）或外部 MQ，本书配方只适用于「丢了也无所谓」的轻任务 ⚠️。
定长窗口是列表最优雅的一招：`LPUSH recent:search:u1 kw` 紧跟 `LTRIM recent:search:u1 0 9`——
每键恒存最近 10 条，用户搜索历史/浏览足迹零清理成本。

### 配方：集合做标签、关系与去重判定 ⚠️

`SADD tags:post:7 redis perf` + `SINTER tags:post:7 tags:post:9` 出共同标签；「共同好友」即两用户好友集求交。
去重判定用 `SISMEMBER` O(1)（限重场景的正解，计数场景见 07 章 HLL）。随机类：`SRANDMEMBER`（看）与
`SPOP`（取走）分开——抽奖、随机出题一对命令解决。集合无「顺序」概念，别拿它做窗口（那是 LTRIM 的活）。

### 配方：排行榜=有序集（本章主菜）⚠️+🔧

有序集=「成员→双精度分数」映射+按分数与字典序双键排序（分数并列时**成员名按字典序**定名次，全局无歧义）。
文档：https://redis.io/docs/latest/develop/data-types/sorted-sets/ ✅ curl 200。

Redis 侧配方（⚠️ 文档转述）：
```
ZINCRBY board:2026 250 alice          # 加分（不存在自动入榜）
ZREVRANGE board:2026 0 4 WITHSCORES   # Top5，高分在前
ZREVRANK board:2026 bob               # bob 的名次（0 基）
ZCOUNT board:2026 3000 4200           # 分数段人数
ZREMRANGEBYSCORE board:2026 -inf 1000 # 清榜（淘汰线以下）
```

🔧 **语义等价物真跑**（同一份种子数据，双引擎验证「有序集语义」= 分数降序+同分名字典序的排序关系）：

- sqlite3 3.45.3 版（Python 3.13 内置）：建表 `z(member PRIMARY KEY, score)`，
  `ZINCRBY` ⇔ `INSERT ... ON CONFLICT(member) DO UPDATE SET score=score+250 RETURNING score` →
  alice 3350→**3600.0**；`ZCARD`=6；`ZSCORE`=3600.0；
  `ZREVRANGE 0 4` ⇔ `ORDER BY score DESC, member ASC LIMIT 5` 实跑输出：
  `erin 5010 → bob 4120 → carol 4120 → alice 3600 → dave 2870`（**bob 排在 carol 前**，正是同分字典序 tie-break 的体现）；
  `ZREVRANK bob`=1；`ZCOUNT 3000..4200`=3；`ZREMRANGEBYSCORE -inf..1000` 删 1（frank 610）。
- DuckDB 1.5.5（输出 `D:\develops\tmp\dbwave_w3_rcook\duck.out`）：`ROW_NUMBER() OVER (ORDER BY score DESC, member ASC)-1`
  一次性给出全员 0 基名次（erin 0/bob 1/carol 2/alice 3/dave 4/frank 5）；
  分段翻页 ⇔ `WHERE score BETWEEN 1000 AND 5000 ORDER BY score, member LIMIT 2 OFFSET 1` → `[(alice,3350),(bob,4120)]`。
- **边界声明**：以上证明的是排序语义等价（含 tie-break、名次 0 基、按分删除三契约），与 ZSET 的 O(log N) 跳表实现、
  并发原子性无关——那两层只能引文档与内核笔记 ⚠️。

### 配方：有序集的第二人格：优先级队列与延时队列 ⚠️

分数当优先级：`ZPOPMAX`（5.0）原子弹出最高分=任务调度出口；旧版用 `ZRANGE k -1 -1 + ZREM` 包进脚本保原子
（05 章）。分数当「到期时间戳」即延时队列雏形：`ZRANGEBYSCORE delay 0 now LIMIT 10` + 逐个 `ZREM` 摘取到期项——
两个命令拼出「到时触发」，本书时代的招牌配方之一 ⚠️。

## 常见坑与判读

| 坑 | 症状 | 判读/规避 |
| --- | --- | --- |
| BRPOP 当可靠队列 | worker 崩、任务蒸发 | 上 Streams/带 ACK 队列；或处理前先移 pending 键 |
| 大哈希单字段塞 JSON | listpack 红利没了、整取整存 | 字段拆细；热字段与冷字段分键 |
| ZSET 分数用整数外类型 | 排序按 double 精度意外并列 | 分数别用 float 存高精度 ID；名字段要短（同分排序键） |
| SMEMBERS 取百万成员 | 单命令回包打满带宽 | SSCAN 分批 |
| ZRANK/ZREVRANK 混用 | 名次方向反了 | 0 基；方向看命令名 R |
| 集合做顺序窗口 | 顺序丢失 | 那是 LTRIM 的活 |

## 核心概念速览（中英对照）

- **哈希** — Hash — 字段→值映射，字段级原子更新；小哈希 listpack 编码省内存。
- **listpack 编码** — Listpack/ZipList(旧) — 复合类型小数据时的紧凑内存表示，超过阈值转通用结构。
- **阻塞弹出** — BRPOP/BLPOP — 空列表时挂起消费者的出队原语。
- **定长窗口** — Capped List — LPUSH+LTRIM 每键恒定 N 条的滚动窗口。
- **集合** — Set — 无序去重；SINTER 把「关系」变成一行命令。
- **有序集** — Sorted Set/ZSET — 成员+双精度分数、分数与字典序双键排序。
- **同分字典序** — Lexicographic Tie-Break — 分数并列按成员名升序，名次全局确定。
- **ZREVRANGE/ZREVRANK** — 逆序区间/逆序名次 — Top-N 与「我排第几」两条主查询。
- **ZPOPMAX/MIN** — 原子弹出极值 — 优先级队列出口（5.0+）。
- **延时队列雏形** — Scored Delay Queue — 分数=到期时间戳 + ZRANGEBYSCORE 摘取。
- **SPOP/SRANDMEMBER** — 取走/查看随机元 — 抽奖与采样的命令分工。
- **跳表** — Skip List — ZSET 有序性的底层结构（文档/内核笔记口径 ⚠️）。

- **命令增量**：`ZRANK/ZREVRANK` 语义延续至今；6.2 补齐 `ZADD GT/LT`（分数只增不减的守卫，游戏榜直接受益）；
  7.x 文档把「sorted-set 双键排序」契约写得更明白（✅ 引用同上文 sorted-sets 页）。

  产品文案里明示（「并列按昵称」），否则运营侧永远当 bug 报 ⚠️（工程社区共识）。
