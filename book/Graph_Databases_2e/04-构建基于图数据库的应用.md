## 4.1 数据建模的工程化展开

第 3 章给了模型与陷阱，4.1 是“操作手册”：
- **按需描述模型（4.1.1）**：模型文档=问题清单+图草图，不做“全集 schema”设计。
- **节点表事物、联系表结构（4.1.2）**：“结构/事件/交互”倾向作关系；被多方共享、需独立生命周期的作节点。
- **细粒度联系 vs 通用联系（4.1.3）**：在“语义可查询”与“类型数可控”之间取平衡——类型是查询语言的一部分，不是注释。
- **把事实建模为节点（4.1.4）**：一次“点击”“转账”是事实，参与方≥2 时把事实升格节点、各方指向它（星型事实即图化的 reification）。
- **复杂值类型作节点（4.1.5）**：地址/坐标等结构化值，若需共享与跨值查询（“同址的人”）就建节点。
- **时间（4.1.6）**：书给三种方案——关系属性存时间戳（最简单，推荐起点）、把“时期”建成节点串联、事件流式建模（事实节点 + 前后关系）。**先属性、后结构，别为未来需求预付建模成本。**
- **迭代与增量（4.1.7）**：模型随验收查询演化，迁移成本靠标签/类型的向后兼容策略压住。

## 4.2 应用程序架构：嵌入式 vs 服务器（含 REST）

本章是全书“Neo4j 实践”的主战场：

- **嵌入式（embedded）**：应用 JVM 内直接持有图——最快（无网络无序列化）、可参加外部 XA 事务；代价：语言绑定 JVM、进程级故障域共享、版本与应用锁死。
- **服务器（server / REST 时代）**：Neo4j Server 独立进程，两种接入：
  - **HTTP REST API**：资源风格端点（节点/关系/事务端点），跨语言、可缓存、防火墙友好；书中事务走 `tx` 端点批处理（begin/commit），并讨论 REST 轮询 vs 流式。
  - **Bolt（2015 前后新引入）**：二进制、连接复用、官方 driver 生态（Java/.NET/Python/JS/Ruby/Go）——本书第 2 版正好处在 REST→Bolt 换代口，工程上今天默认 Bolt。
- **集群（4.2.2）**：书中形态为高可用集群（当时基于 Paxos 的 CA cluster）与读副本；目标是读扩展与故障转移，**写仍单主**。
- **负载均衡（4.2.3）**：读请求分流副本、写回主；客户端负载均衡 vs 网关层的取舍。

重构者按：4.2 的框架至今未变——“嵌入式（性能/事务集成）vs 服务器（异构/隔离）”仍是第一问，只是选项扩成“托管云（Aura）”；REST 仍活着（HTTP JSON 端点），但生产应用接入层已是 Bolt + driver。

嵌入式 vs 服务器决策表（按书意重构）：

| 决策问题 | 倾向嵌入式 | 倾向服务器 |
|---|---|---|
| 语言栈 | 纯 JVM | 多语言/非 JVM |
| 故障域 | 与应用共存亡可接受 | 必须隔离 |
| 事务集成 | 需加入外部 XA/JTA | 图库内事务即可 |
| 版本治理 | 应用与库同发布节奏 | 独立升级 |
| 性能 | 极致本地（无序列化） | 网络往返可接受 |
| 典型形态 | 单体内嵌分析组件 | Web 服务/微服务后端 |

REST 端点最小走查（书中 HTTP 时代口径，重构示例）：

```text
POST /db/data/transaction/commit
{ "statements": [
  { "statement": "MATCH (p:Person {id:$id}) RETURN p",
    "parameters": { "id": 12 } } ] }
→ 200 { "results": [...], "errors": [] }   // 声明式事务一步提交
```

要点（重构）：事务端点=begin/commit 两段或一步 commit；响应体内嵌资源 URI（HTTP 可缓存、防火墙友好）；批量语句共享一个事务是其与“每请求一事务”的关键差别。今天的等价物是 driver 的 `execute_query`/`session.run`，语义一一对应。

### 导入方式决策表（4.5 展开）

| 数据量 | 形态 | 书中/今日工具 |
|---|---|---|
| < 10 万点 | 在线写 | Cypher `UNWIND` 批 + driver 事务 |
| 百万级、可停机 | 离线全量 | 旧 `neo4j-import` → 今 `neo4j-admin database import full` |
| 百万级、不可停机 | 在线渐进 | 分批事务 + 后台索引补建 |
| 持续增量 | 流式 | Kafka/connect 生态（超出原书） |

### 本章自测问答

1. 嵌入式最快，为什么大多数生产不用？——故障域/语言绑定/版本锁死三问多数答“不可接受”。
2. REST 与 Bolt 的代际关系？——同一服务器两代协议：Bolt 用连接复用+二进制换吞吐，REST 保留给轻量集成与运维。
3. 集群里写为什么仍单主？——图上多跳事务需要一致的邻接视图；多主冲突检测在邻接结构上极贵（6.4.4 的根源）。
4. 性能测试为何先测扇出分布？——遍历代价公式的输入就是度数；先找上帝节点再谈 QPS。
5. 容量第一问是什么？——热集能否驻留内存（页缓存/堆外），决定磁盘 I/O 放大率。
6. 批量导入为什么要求空库+离线？——避免边在线构图（索引/事务/检查开销），改“构造后加载”。

## 4.3 测试

- **测试驱动的数据模型开发（4.3.1）**：以小型“代表性图”（几百点）建 fixture，验收查询写成断言；模型变更=增删用例。这是 3.4.3 方法论的工程化。
- **性能测试（4.3.2）**：书中方法（大意）——用随机生成器放大到百万点/千万边，跑同一批查询看时延曲线随度数的增长；重点盯**上帝节点与热点扇出**；结论是“图查询性能测试 = 度数分布测试”，先测扇出分布再测 QPS。

## 4.4 容量规划

4.4 的清单（优化条件/性能/冗余/负载）浓缩成可操作四条：
1. 内存优先：**热集（working set）进页缓存/堆外**是 Neo4j 类引擎第一性能前提；
2. 磁盘预算：记录文件 + 索引 + 事务日志三者分别估；
3. 冗余：副本拓扑决定可用性目标（对照 4.2 集群）；
4. 负载画像：读扩散型（遍历）与写密集型分开压测。

## 4.5 导入和批量加载

- **初始导入（4.5.1）**：小数据走 Cypher `CREATE`（配 `UNWIND` 批）或 REST/Bolt 事务批提交。
- **批量导入（4.5.2）**：书中 `neo4j-import` 工具离线并行装载 CSV（3.5 莎士比亚 CSV 在此复用）；关键约束：空库、字段映射文件、分片并行。
- 通用经验（书中大意）：**先建模关系再灌属性、按标签/类型分片、导入期关索引自动创建**——与数仓 ETL 的“bulk load 后建索引”同构。

## 核心概念速览（中英对照）

- **嵌入式模式** — embedded mode：图库作为库进程内运行，共享 JVM 与事务上下文。
- **服务器模式** — server mode：独立进程、网络协议访问（HTTP/Bolt），语言无关。
- **REST API** — REST API：以 HTTP 资源端点操作图（节点/关系/索引/事务端点）。
- **Bolt** — Bolt：Neo4j 二进制线协议，驱动（driver）生态的底座。
- **事务端点** — transactional endpoint：HTTP 上 begin/commit 的批式事务入口。
- **高可用集群** — HA cluster：基于共识协议的多副本写单主集群。
- **读副本** — read replica：异步复制的只读节点，分流读负载。
- **验收查询 fixture** — representative graph fixture：小型代表性图 + 断言的模型测试法。
- **扇出分布测试** — fan-out profiling：以度数分布预测遍历性能的测试思路。
- **热集** — working set：常访问点/关系/索引集合，内存规划对象。
- **批量导入器** — bulk importer：离线并行装载 CSV 的工具（neo4j-import 血统）。
- **分片并行** — sharded parallel load：多文件多核同时写入、后接关系。

## 最新演进与工业实践

- **接入层收敛到 Bolt + 官方 driver**：多语言 driver（Python/JS/Java/.NET/Go/Rust）文档：https://neo4j.com/docs/api/python-driver/current/ （curl 200 ✅）。REST HTTP 端点仍保留于运维与轻量集成，但新应用默认 driver；第 1 版“REST Blue Prints”章的遗产今天≈教程示例。
- **批量导入工具换代**：`neo4j-import` 已废弃，由 **`neo4j-admin database import full`**（CSV 并行离线装载，单库）与 incremental import（增量）取代：https://neo4j.com/docs/operations-manual/current/tools/neo4j-admin/neo4j-admin-import/ （curl 200 ✅）。Memgraph（CSV 导入工具链，见其 docs：https://memgraph.com/docs ，curl 200 ✅）、AWS Neptune（bulk loader）提供同构能力——本书 4.5 的方法论未过时。
- **集群与“去嵌入式”方向**：Neo4j 5.x/2025.x 把企业版集群形态持续向云编排收敛（Aura 托管多租户、K8s operator），书中 2.x 时代的因果集群/读副本拓扑细节与今天差异较大（⚠️ 本版细节以官方运维手册为准，不在此展开）。运维手册现行版：https://neo4j.com/docs/operations-manual/current/ （curl 200 ✅）。4.2 的“嵌入式”选项在新版本基本只剩官方内嵌测试用途（口径 ⚠️ 以发布说明为准）。
- **云托管成为默认答案**：Neo4j Aura（DB 即服务，含免费档）：https://neo4j.com/cloud/aura/ （curl 200 ✅）。容量规划（4.4）被“选实例规格 + 计费模型”替代，但“热集进内存”的第一性原理不变。
- **测试的当代形态**：Testcontainers + `neo4j/neo4j` 镜像跑验收查询成为 CI 惯例（方法论即 4.3.1 落地）；性能测试直接跑 LDBC SNB：https://ldbcouncil.org/ （curl 200 ✅）。
- **版本口径**：书中 Neo4j 2.x → 5.26（5.x 末代 LTS）→ 2025.x 年份版：https://neo4j.com/docs/upgrade-migration-guide/current/ （curl 200 ✅）。
