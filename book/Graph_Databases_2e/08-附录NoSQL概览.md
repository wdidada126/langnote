## 附录内容线（重构）

使用方式：本文件是全书的“对照系”——先读 `./02-关联数据的存储选择.md` 的批判，再用本文件把批判放回全景，避免把图当成万能存储。

### A. NoSQL 分类学

书中沿用业界四分类（与 Sadalage & Fowler《NoSQL 精粹》同源口径）：

1. **键值（key-value）**：不透明值 + 哈希键；伸缩性极好，查询能力=键设计能力。代表（2015 语境）：Redis、Voldemort、Dynamo 系。
2. **文档（document）**：半结构化自描述文档 + 域查询；聚合一致性边界。代表：MongoDB、CouchDB。
3. **列族/宽列（column family / wide-column）**：按列族稀疏排序存储；为“列裁剪 + 写吞吐”优化。代表：Cassandra、HBase。
4. **聚合/事件溯源（aggregate/event sourcing）**：不可变事件流重建状态；时间维度的“关系”。

本书的独特动作：在第四类之外把**图数据库单列**为第五类（或者说“关系范式”的独立代表），并用第 2 章论证为什么前四类没有把“联系”当一等公民。

四分类总表（与《NoSQL 精粹》口径互证）：

| 类别 | 数据形态 | 强项 | 关联能力 | 2015 代表 |
|---|---|---|---|---|
| 键值 | key→opaque value | 极简伸缩 | 无（键约定） | Redis/Dynamo |
| 文档 | 半结构化聚合 | 领域对象贴合 | ID 引用，需应用层拼 | MongoDB/CouchDB |
| 宽列 | 列族稀疏表 | 写吞吐/列裁剪 | 预建物化（table-per-query） | Cassandra/HBase |
| 聚合/事件 | 不可变事件流 | 时间审计/状态重建 | 时间维“关系” | ES 系 |
| **图（本书）** | 点边+属性 | 邻域扩散查询 | **原生** | Neo4j |

各范式的“关联能力”细看（附录论证的展开，重构表述）：

- **键值**：关联若必须表达，只能编码进键（`user:42:friends` 约定）——无类型、无属性、无查询语言，键约定腐化是运维债。
- **文档**：内嵌=拥有（所有权树），引用=松耦合；跨聚合遍历=应用层 N+1 查询循环；反范式化冗余让“关系变更”变成多文档写问题。
- **宽列**：行键决定唯一访问路径；“列”是属性布局的自由度，不是实体间关系；关系支持靠 secondary index/物化（SAI 之前长期是痛）。
- **事件溯源**：实体间关系被投影为“事件流的时间线”；空间关系仍然要外挂读模型（CQRS 视图）——恰证明读模型层需要一个能表达关系的存储。
- **图**：把上述四类都在“应用层或约定层”承担的关系职责，下沉回存储层——附录以此收束第 2 章。

### B. CAP 与 BASE

- **CAP**：分区容错在分布式里近乎必选，工程选择发生在 C/A 之间；书中提醒——“选择”只在**分区发生时**才被迫二选一，正常期两者可兼得（这一辨析至今常被误读）。
- **BASE**（Basically Available / Soft state / Eventually consistent）：对 ACID 的松绑； Dynamo/Cassandra 血统的最终一致读（读写向量、读修复、读己之写的补丁手段）。
- 本书立场：图数据库（Neo4j 代表）明确站 ACID 一侧——第 6 章 6.4 的“事务/可恢复性”与此呼应；附录承认代价是**扩展性形态受限**（当时无通用分片）。

论证链拆解（重构表述）：
1. 最终一致的本质交易：用“收敛延迟”买“写可用/分区存活”；
2. 图上多跳写（建边即改两端结构）若跨副本异步，会出现“半边存在”的悬挂邻接——遍历语义难以容忍；
3. 所以本书选 ACID+复制（而非分片）作为一致性策略——这是**模型驱动的架构选择**，不是阵营偏好；
4. 推论（重构者补）：读多写少的关联查询可以把副本读做到极致（4.2 读副本），多数 OLTP 图负载并不需要分区级写扩展——书用架构回避了它论证不过的东西。
5. 对照今天：NewSQL（分布式 SQL 事务引擎）走了相反路线——保住 ACID 同时做写扩展；图库与 NewSQL 的边界问题（谁做关系密集 OLTP）是 2024–2026 多模融合叙事的真正张力所在。

### C. 选型判定表（附录方法论化）

| 你的负载 | 首选形态 | 理由 |
|---|---|---|
| 键取回/缓存 | 键值 | 无关系需求 |
| 领域对象整体读写 | 文档 | 聚合边界即对象 |
| 高写吞吐时序/宽表 | 宽列 | 列裁剪+LSM |
| 审计/状态可重放 | 事件溯源 | 时间线真相 |
| 多跳/路径/共同邻居 | **图** | 邻接原生 |
| 全表聚合报表 | 列存 OLAP/数仓 | 扫描压缩最优 |

### 本章自测问答

1. “选择 C 还是 A”为什么只在分区时成立？——无分区时两者并得，CAP 讨论的是退化期的保法。
2. 悬挂邻接是什么、为何威胁最终一致图？——“半边”跨副本未收敛，多跳读可能踩空。
3. table-per-query 与物化视图的关系？——同一思想的两种叫法，宽列生态里由写方显式维护。
4. 多语言持久化的集成成本落在哪？——一致性胶水（双写/变更捕获），4 章服务器模式只是解决了“连得上”。
5. 多模数据库是否推翻四分类？——推翻“引擎=类别”，保留“结构=类别”；查询形态判据不变。
6. GQL 标准化改变了分类学的什么？——图从 NoSQL 分支升为与 SQL 并列的标准语言位。

### D. 与图数据库的关系收束

- 多语言持久化（polyglot persistence）：图负责关联查询，其他引擎负责各自最擅长的形态；集成方式回到第 4 章（REST/Bolt 服务器模式天然适合异构栈）。
- 分类学不是选型终点：**查询形态（沿关系扩散 vs 聚合扫描 vs 键取回）才是**——附录把第 2 章的批判升格为一般方法。
- 收束三句话（重构）：模型各异、负载互斥、胶水在执行层——所以“选哪个 NoSQL”是伪问题，“每个查询走哪个引擎”才是真问题；这也是本书把自己放进“NoSQL 全景中的一格”而非“替代者”的谦逊位置。

## 核心概念速览（中英对照）

- **键值存储** — key-value store：不透明值 + 键哈希，伸缩优先。
- **文档存储** — document store：自描述半结构化文档，聚合边界。
- **聚合** — aggregate：一致性/事务边界的领域单元。
- **列族** — column family：稀疏有序列簇，宽列存储的核心结构。
- **事件溯源** — event sourcing：以不可变事件流为真相源的状态重建。
- **多语言持久化** — polyglot persistence：按负载选存储的架构观。
- **CAP** — CAP：一致性/可用性在分区时的取舍定理。
- **BASE** — BASE：基本可用 + 软状态 + 最终一致的松绑纲领。
- **最终一致** — eventual consistency：无全局时序的收敛保证。
- **读修复/反熵** — read repair / anti-entropy：副本收敛机制两形态。
- **ACID 立场** — ACID stance：本书/Neo4j 的 OLTP 承诺。
- **多模数据库** — multi-model database：单引擎内置多种数据模型（分类学的当代融合）。
