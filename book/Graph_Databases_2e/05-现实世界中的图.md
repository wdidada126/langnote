## 5.1 为什么选择图（判据复述）

书中给的选型判据（重构表述）：当你的查询模式**以“沿关系扩散”为主**（几跳内的可达性、路径、共同邻居），且**关系本身携带业务语义**（类型/属性/方向有意义）时，图是正确存储；反之：全量聚合统计、浅关联、键值取回，各有更专的引擎。5.2 的六类用例全部满足“深度关联 + 关系语义”两个条件。

## 5.3 三个实际示例（端到端演练）

### 5.3.1 社交推荐（专业社交网络，页 97 起）

书中主线（重构）：以“职业社交网络”为背景——
1. 建模：`(:Person)-[:KNOWS]-(:Person)`、`(:Person)-[:WORKED_AT]->(:Company)`、`(:Person)-[:HAS_SKILL]->(:Skill)`；
2. 推荐查询族：**共同邻居数**做“认识可能性”打分（`MATCH (a)-[:KNOWS]->(mutual)<-[:KNOWS]-(b) … count(mutual)`）、同公司+同技能加权；
3. 工程要点：推荐类查询天然是“聚合遍历”（先扩散再收敛），务必**限制跳数与类型**防扇出爆炸；为高频起点建复合索引；把打分逻辑放应用层还是查询层，书中给了 Cypher 与遍历 API 两种写法——这正是“遍历 vs 查询语言”取舍的实例（详见 `./06-图数据库的内部结构.md`）。

### 5.3.2 授权与访问控制（页 107 起）

- 模型：`(:User)-[:MEMBER_OF]->(:Group)-[:GRANTED]->(:Permission)-[:APPLIES_TO]->(:Resource)`，继承用可变长路径表达。
- 核心查询：权限判定=模式存在性（存在任意一条 GRANTED 路径 ⇒ 允许）；治理查询=反向遍历（“某资源当前对谁可见”“禁用某角色会撤掉谁的访问”）。
- 书中强调的洞察：**访问控制的本质是图的可达性问题**——把策略表翻译成 ACL 服务后，"谁能访问"从多表 JOIN 应用层拼凑变成单条声明式查询。

### 5.3.3 地理空间与物流（页 115 起）

- 模型：路网 `(:Junction)-[:ROAD {distance, speed}]->(:Junction)`，配送点挂到最近路口。
- 查询：最短路径（Dijkstra 加权，衔接第 7 章 7.2）、区间可达（“30 分钟车程内所有客户”= 带权重半径遍历）。
- 工程注意（书中大意）：纯图不擅长“几何包含”类查询，需属性/外部几何索引配合——2015 年的诚实边界，今天由**空间索引/图层混合**补齐（见下“最新演进”）。

## 5.4 小结

案例章的方法论收束：**用例 = 模型（3 章）+ 接入架构（4 章）+ 查询族 + 边界**。六类用例的共同指纹是“关系即业务”，三例的差别是扩散方向（社交=无向共邻、权限=继承链、地理=加权路径）。

## 核心概念速览（中英对照）

- **共同邻居** — common neighbors：两节点邻居交集，社交推荐打分基元。
- **扩散-收敛** — expand-and-converge：先沿关系扩散候选、再聚合打分的查询形态。
- **影响域** — blast radius / reachability set：沿依赖边可达的资产集合，故障分析对象。
- **黄金记录** — golden record：MDM 中跨源对齐后的权威实体，图里表现为合并节点+溯源边。
- **继承链** — inheritance chain：权限/组织模型中的可变长路径语义。
- **可达性查询** — reachability query：判定两节点间是否存在（满足约束的）路径。
- **反向遍历** — reverse traversal：从资源回追主体（“谁能访问我”）。
- **加权路径** — weighted path：边带成本属性的路径，物流/路由的核心结构。
- **等时圈** — isochrone：从起点按权重扩展固定成本的可达区域。
- **模式存在性** — pattern existence：以匹配是否存在为结果的查询，权限判定的形式化。
- **爆炸半径** — blast radius：变更/故障沿依赖图传播的规模。
- **邻域抓取** — neighborhood retrieval：以给定起点收集 k-hop 子图的检索形态（GraphRAG 前身概念）。

## 最新演进与工业实践

- **GraphRAG 成为第七类用例（2024–2026 热潮）**：微软论文 *From Local to Global: A Graph RAG Approach to Query-Focused Summarization*（arXiv:2404.16130，2024）——先用 LLM 从语料抽实体关系建知识图，再做社区检测+分层摘要回答“全局性问题”：论文页 https://arxiv.org/abs/2404.16130 （curl 200 ✅；DOI 为 DataCite `10.48550/arXiv.2404.16130`，**未经 Crossref 收录校验 ⚠️** 故以 arXiv 链接为准）；官方实现 https://github.com/microsoft/graphrag （curl 200 ✅，README 自述 2024-07 首发、定位为研究型项目）。Neo4j 官方 GraphRAG Python 库（检索器/构建器）：https://neo4j.com/docs/neo4j-graphrag-python/current/ （curl 200 ✅）。本章 5.3.1 的“推荐打分”与 GraphRAG 的“子图检索”在工程栈上是同一族查询。
- **推荐 = 图 + 向量的混合检索成主流**：向量近邻召回（语义相似）+ 图关系扩圈（协同证据）双向融合；Neo4j 向量索引文档 https://neo4j.com/docs/cypher-manual/current/indexes/semantic-indexes/vector-indexes/ （curl 200 ✅）。书 5.3.1 纯共同邻居打分，今天通常作为向量召回后的重排特征。
- **云图服务把案例工程化**：AWS **Neptune + Neptune Analytics**（托管图 + 图数据科学/Gremlin/openCypher）：文档 https://docs.aws.amazon.com/neptune/latest/userguide/analytics-feature.html （curl 200 ✅）；Neptune 官方把“欺诈检测/推荐/知识图”列为头部用例（与 5.2 清单高度重合）。
- **访问控制的图实践**：云厂商 IAM 策略图分析（可达性=权限判定）已是成熟产品形态；开源侧类似思路见权限建模工具（具体项目更迭快 ⚠️ 不点名，以“用图做策略可达性验证”为关键词检索）。
- **地理空间用例的当代补全**：Neo4j 2025.x 起提供空间点类型 + 空间索引（`POINT` 属性/`db.index.spatial`），书 5.3.3 需外挂几何索引的限制已部分解除（细节以 https://neo4j.com/docs/cypher-manual/current/ 为准 ✅ 可达；条目级变化 ⚠️ 未逐项抓）。
