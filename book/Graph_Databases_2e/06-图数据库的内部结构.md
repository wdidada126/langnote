## 6.1 原生图处理：遍历是一等执行模型

书中核心对比（重构表述）：

- **关系执行器**：查询计划 = 算子树，邻接靠 JOIN 算子重算；优化器世界围绕“连接顺序/物化中间结果”。
- **图执行器**：查询计划 = **遍历（traversal）**——从入口索引定位起点，沿某类型的邻接指针前进；原语是 `expand(node, type, direction)` +  evaluator/过滤器 + 唯一性约束。
- **遍历的两个经典策略**：深度优先（DFS）与广度优先（BFS）在此被放到执行引擎层讨论（数学性质见第 7 章 7.1）；引擎按查询形态选策略（存在性判定→DFS 常早停；层级扩散计数→BFS 分层）。
- **声明式查询语言（Cypher）与命令式遍历 API 的关系**：语言层把“意图”交给引擎规划；遍历框架把“路径控制”交还开发者（剪枝、记忆化、自定义展开规则）。**两者不是替代而是分层**——这正是本章 6.3 的 API 三件套存在的理由。

免索引邻接的代价公式（书的主张，实测形态见 `./02-关联数据的存储选择.md` 🔧 节）：k 跳查询代价 ~ Σ(访问节点的出度)，与全图规模无关。

## 6.2 原生图存储

以 Neo4j 存储为例（2015 年语境，store 文件层）：

- 三类记录文件：**节点记录 / 关系记录 / 属性记录**（node/store、rel/store、prop/store），定长记录 + 34-bit 记录 ID 作为“物理指针”；标签索引、属性索引独立目录（只服务入口定位）。
- **关系记录是双向链表环**：每条关系同时挂在两端节点的邻接链表上（`firstRel` + `nextForP1/nextForP2`），因此“从任一端展开”都是 O(1) 指针追逐——免索引邻接的物理形态。
- 记录删除用空位记录 + 高水位，文件内存映射（page cache 即“热集在内存”的实现层，呼应 4.4 容量规划）。
- ⚠️ 版本口径：上述 store 布局是 1.x–2.x 时代的实现描述；Neo4j 后续版本存储格式多轮重构（记录格式/压缩/对齐均有变化），读本章时把它当**原理示意**而非现行实现。

## 6.3 用于编程的 API：三件套

1. **内核 API（Kernel API）**：最底层（`Node`/`Relationship` 记录级操作），性能控制力最强，牺牲抽象与安全——书中定位是“扩展/内库开发用”。
2. **核心 API（Core API）**：事务化、通用编程界面（嵌入式形态的主 API；服务器 driver 是其远程等价物）。
3. **遍历框架（Traversal Framework / Traversal API）**：命令式遍历 DSL——`expand(type, dir) + evaluator + uniqueness`，开发者可编程剪枝、防爆内存（uniqueness 的 NODE/RELATIONSHIP/PATH 三种模式）。
   - 书中立场（重构）：**查询语言解决“多数意图可声明”的查询，遍历框架解决“需要控制遍历过程”的查询**（自定义打分、深度自适应剪枝、环路处理）。今天这个分工由“Cypher + 过程/UDF + GDS 算法库”承接。

## 6.4 非功能型特性

- **事务（6.4.1）**：OLTP 图库坚持 ACID（对照第 8 章附录 BASE）——书中强调“图上的多跳写”需要事务保证局部一致性；Neo4j 当时为单写锁 + MVCC 读（口径 ⚠️ 具体并发控制细节以版本手册为准）。
- **可恢复性（6.4.2）**：事务日志 + 记录文件崩溃恢复；备份形态为在线备份/文件拷贝组合。
- **可用性（6.4.3）**：主从复制 + 共识的 HA 集群（书中 Paxos 集群）、故障转移、读副本；目标是运维可用性而非分区容错优先。
- **可扩展性（6.4.4）**：读扩展=加副本；写扩展当时受限（单主）；分片（sharding）是图数据库的长期难点——**跨分片遍历**破坏免索引邻接的 O(1) 前提，书中明确不看好自动分片。这一判断 2024–2026 仍大体成立：工业界用“业务分库 + Fabric 查询联邦”绕开，而非通用自动分片。

## 精读札记

- 本章是全书与《Database Internals》最同构的一章：6.2 讲“文件格式/记录管理/崩溃恢复”，只是把 B 树换成了邻接链表。两者并读能得到一个更稳的结论：**图库的性能优势不在“文件更聪明”，而在“执行模型省掉了重算邻接”**——存储层只是让指针追逐便宜。
- 6.4.4 对分片的保守是作者立场鲜明处：图模型的分区问题是学术难题（边分割/点分割的通信代价），书中“宁可复制不要分片”在 Neo4j 架构上兑现为 multi-tenant + Fabric 路线。

## 核心概念速览（中英对照）

- **原生图处理** — native graph processing：以邻接遍历为执行模型的查询处理。
- **免索引邻接** — index-free adjacency：沿物理指针访问邻居，不经索引。
- **expand 原语** — expand primitive：按类型/方向从节点取邻接边的引擎操作。
- **遍历策略** — traversal strategy：DFS/BFS 在执行层的形态与适用查询。
- **求值器** — evaluator：控制单步访问/停止/剪枝的遍历回调。
- **唯一性约束** — uniqueness：遍历中节点/关系/路径去重模式。
- **内核 API** — kernel API：记录级最低层编程界面。
- **核心 API** — core API：事务化的通用嵌入界面。
- **遍历框架** — traversal framework：命令式遍历 DSL（expand+evaluator+uniqueness）。
- **MVCC** — multiversion concurrency control：图上读的并发控制手段之一。
- **崩溃恢复** — crash recovery：事务日志重放保证持久性。
- **高可用集群** — HA cluster：共识驱动多副本自动故障转移。
- **读副本** — read replica：异步只读复制节点。
- **图分片难题** — graph partitioning problem：跨分片遍历使邻接 O(1) 前提失效的扩展瓶颈。
