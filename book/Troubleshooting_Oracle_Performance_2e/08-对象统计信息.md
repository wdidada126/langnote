## 本章定位

- 基数估计的原料章。目录即教学：有什么（8.2）→ 怎么采（8.3–8.4）→ 特殊对象（GTT/分区/pending，8.5–8.7）→ 全套管理（8.8–8.13）→ 保鲜策略（8.14）。
- 作者立场：**绝大多数坏计划的第一根因是统计过期或缺维度**；排障先问"统计什么时候采的、按什么选项采的"。

## 8.1–8.2 包与统计清单（p.207–232）

- 8.2 六类统计（官方 ✅）：
  - **Table Statistics（210）**：num_rows、blocks、avg_row_len、chain/average row chaining、（12c 增列存/内存行存相关字段）。
  - **Column Statistics（211）**：num_distinct（NDV）、num_nulls、num_buckets、density、low/high value——**density 与直方图的联动**是理解"倾斜列必须直方图"的关键。
  - **Histograms（213）**：频率型 vs 等深型；`SIZE SKEWONLY/AUTO/REPEAT/n`；桶数与采样率权衡；著名警告：**删统计→默认值（假设均匀）常比错直方图更接近真相——"没有统计比错统计更糟"是反命题，"错统计比没统计更糟"才是本书立场**。
  - **Extended Statistics（226）**：column group（11g）修补列间相关导致的 NDV 连乘低估——**"选择度=各谓词乘积"的独立性假设是坏估计的头号理论缺陷**，扩展统计是官方补丁。
  - **Index Statistics（230）**：lvls（blevel）、leaf_blocks、distinct_keys；与表统计侧的 CLUSTERING_FACTOR 共同决定索引范围扫描成本。
  - **Partitioned Objects（232）**：分区级+全局级双层，global/partial 聚合规则。

## 8.3–8.4 采集与配置（p.233–246）

- **Target Objects（235）**：GATHER / GATHER_SCHEMA / GATHER_DATABASE / GATHER_TABLE（`CASCADE=TRUE` 联动列与索引）。
- **Gathering Options（239）**：`estimate_percent`（AUTO_SAMPLE_SIZE 的近优采样）、`degree`、`granularity`（AUTO/GLOBAL AND PARTITION…）、`method_opt`、`no_invalidate`（统计变更后游标失效时机——**"改统计炸计划"的直接旋钮**）。
- **Backup Table（244）**：GATHER_* 的 `statown`+备份表路数（与 Ch7 同一套）。
- **Configuring the Package（245）**：The Legacy Way（245，import_parameter 老表）vs The Contemporary Way（246，`SET_GATHER_TABLE_STATS_PREFS` 族 + `DBA_OPTSTAT_PREFS` 全局默认）。

## 8.5–8.7 三类特殊对象（p.248–256）

- **Global Temporary Tables（248）**：会话私有数据 vs 全局一份统计的错配；作者示范"装载后采一次+锁统计"的保守法 ⚠️ 转述。
- **Pending Object Statistics（250）**：`PUBLISH` 开关——先采后验再发布，统计变更的灰度通道。
- **Partitioned Objects（251）**
  - Challenges（251）：全局统计聚合的近似误差；
  - **Incremental Statistics（254）**：11g synopsis 机制——只采改动分区、`APPROX_GLOBAL AND PARTITION` 合成全局，大表统计的架构级改进；
  - Copying Statistics（256）：`COPY_TABLE_STATS`——造历史/影子表做计划仿真的手段。

## 8.8–8.14 管理与保鲜（p.257–270）

- **Scheduling（257）**：The 10g Way（257，DBMS_SCHEDULER 手工作业）vs The 11g and 12c Way（259，自动维护任务 `automatic statistics gathering job`——夜窗口、不可跳、`DBA_AUTOTASK_*` 可观测；含"自动任务干扰批处理窗口"的运维权衡）。
- **Restoring（261）**：`RESTORE_TABLE_STATS` + 保留期（默认 31 天）——**"昨天计划还好好的"标准解法：把时间拨回去**。
- **Locking（262）**：`LOCK_TABLE_STATS` 护住静态参照表，自动任务绕道。
- **Comparing（265）**：`DIFF_TABLE_STATS`（12c）输出两份统计的计划影响差异——统计界的 A/B。
- **Deleting（267）/ Exporting, Importing, Getting, Setting（268）**：清理与跨环境传输（生产→测试标准件）。
- **Logging（269）**：优化器操作日志审计一切统计动作。
- **Strategies（270）**：全书统计侧结论清单——变更率驱动采样、大表增量、静态表锁定、升级前备份、变更走 pending+diff。

## 🔧 统计影响计划——sqlite3 类比实测（非 Oracle）

- `demo.py`（200k 行磁盘库）：`ANALYZE` 后 `sqlite_stat1` 得 `('t','ix_kind','200000 400')`；建 `ix_v` 后范围查询计划由 `SCAN t`（≈10.3 ms）翻为 `SEARCH t USING COVERING INDEX ix_v`（<0.05 ms）。
- 演示三层：**统计喂成本模型→计划可见翻转→覆盖索引免回表收益**。SQLite 只有最原始统计，类比止于结构层，数值与 Oracle 不可互推。

## 易混点与补记

- 直方图管"分布"不管"相关性"：列间相关交给扩展统计，别指望加直方图救组合谓词（⚠️ 转述）。
- 频率直方图与高度平衡直方图的适用边界是 NDV：NDV>254 后只剩后者，桶的语义也随之改变。
- 12c 自动直方图（SIZE AUTO）按负载感知是否需要，但"自动"不等于"永远对"——数据模式剧变后要复查。
- 增量统计的 synopsis 在分区维护后可能陈旧：行数对了、聚合歪了，是本章经典疑难。
- pending 统计不自动生效：SET_TABLE_STATS 的 PUBLISH 语义与 gather 的 no_invalidate 是两个独立开关。
- DIFF/RESTORE 配表是统计的"版本控制"：升级前备份、事故时回退，与 Ch7 管理三面同构。
- 统计过期阈值（%_changed_rows）只盯 DML 量：大批量删后再插可能行数没变分布全变。

## 核心概念速览（中英对照）

- **对象统计** — Object Statistics：表/列/索引/分区四层统计族
- **NDV** — Number of Distinct Values：列去重值数
- **密度** — Density：无直方图时的选择度代理
- **直方图** — Histogram：频率型/等深型
- **SIZE SKEWONLY / AUTO / REPEAT** — 直方图策略三档
- **扩展统计** — Extended Statistics：列组/表达式相关性补丁
- **聚类因子** — Clustering Factor：索引键序与行序的错位度
- **AUTO_SAMPLE_SIZE** — 自动采样：近优样本量策略
- **CASCADE=TRUE** — 级联采集：表统计带动列/索引
- **no_invalidate** — 游标失效时机：变更爆炸半径旋钮
- **增量统计** — Incremental Statistics：synopsis 合成全局
- **pending 统计** — Pending Statistics：先采后发布
- **DIFF / RESTORE** — 统计差异报告与时间机器
- **自动收集任务** — Automatic Statistics Job：11g+ 维护窗口作业
