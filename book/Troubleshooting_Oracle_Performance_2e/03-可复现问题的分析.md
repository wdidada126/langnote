# Ch3 Analysis of Reproducible Problems（可复现问题分析）— 原书 p.51–101 · Part II Identification

> ⚠️ 文档转述。本章工具（10046/TKPROF/DBMS_HPROF）为 Oracle 专有，不实测；文末 🔧 为 sqlite3+Python 方法论类比（非 Oracle）。

## 本章定位

- 三分法第一类：**能稳定复现的问题**——排障的奢侈品，允许"埋点→复现→读报告"完整闭环。
- 本章只讲一件事：把一次数据库调用（含其下所有递归 SQL 与 PL/SQL）**按时间逐行拆开**。
- 全书方法论的操作核心：Ch4/Ch5 只是同一数据源在不同可得性下的降级形态。

## 3.1 Tracing Database Calls（追踪数据库调用，p.51）

- **SQL Trace（p.52）**
  - 核心是 10046 事件：level 0/1 标准、4 加绑定值、8 加等待与 WO、12 两者全开（2e 推荐 12）。
  - 开启途径：ALTER SESSION / DBMS_SESSION / **DBMS_MONITOR**（按 sid/serial、service、module、action 粒度，11g 后主推）。
  - trace 文件位置由 diagnostic_dest（ADR 基目录）决定，命名 `<sid>_ora_<pid>.trc`。
  - 作者纪律：**trace 开销决定它只配开在复现窗口，不配常开**。
- **Structure of the Trace Files（p.65）**
  - 按 parse/execute/fetch 三段 + WAIT + STAT 行组织。
  - `PARSING IN CURSOR #…` 条目含 sql_id（10.2+）与文本；时序行给出 cpu/elapsed/queryrd/pivorwr——**响应时间分解的原子记录**。
  - 多 trace（并行从属、后台进程）需合并后再读。
- **Using TRCSESS（p.67）**：trcsess 按 session/service/filename 归并散碎 .trc——多模块应用与并行执行的必备第一步。
- **Profilers（p.67）**：术语区分——trace 是记录，profiler 是聚合报表；TKPROF 是事实标准。
- **Using TKPROF（p.68–79）**
  - 核心开关逐项精读：`explain=file`+`table=`（出计划，注意权限噪声）、`aggregate`（递归 SQL 合并）、`sysyes/no`（作者建议先 sysyes 看系统语句再 sysno 看负载本体）、`wait=yes`（剔 latch 噪声）、`sort=ela/exe/fch/prs`、`grp=`（按前缀分组）、`insert=`（结果落表供 SQL 分析——Ch5 仓储思想的第一次亮相）。
  - 读法纲领：**先看每次调用多少毫秒、再看总次数**——平均与总量双视角，回扣 Ch2"响应时间为纲"。
- **Using TVD$XTAT（p.79–89）**
  - 作者出品的免费分析器：调用树视图（父 SQL→递归 SQL→PL/SQL 行级）、按模块/动作的响应时间瀑布、两次 trace 的 A/B 差异报告。
  - 论证要点：**分析 trace 的正确姿势是按调用层次聚合，而非平铺列表**。

## 3.2 Profiling PL/SQL Code（PL/SQL 剖析，p.89）

- **DBMS_HPROF（层级剖析器，11g+，p.89）**
  - trace_enable/trace_disable → hp 工具或 DBMS_HPROF.ANALYZE 入库 → DBMSHP_FUNCTION_INFO/CALLS/VERSIONS/SYMBOLS。
  - 输出：函数调用层级、**自身时间（self）vs 传播时间（propagated）**、两次运行 diff。
  - 回答的问题："到底是哪个包哪个函数在花时间"。
- **DBMS_PROFILER（p.96）**
  - 行级覆盖（DBMSPLSQL_LINEID 族表），回答"哪些行从未执行/各行耗时"。
  - 与 HPROF 互补：HPROF 看时间结构，PROFILER 看行覆盖。
- **Triggering the Profilers（p.101）**
  - 多层应用/作业/远程会话里如何正确启停，避免污染样本或漏采窗口。

## 症状→取证工具速查

| 症状 | 第一步取证 | 第二步聚合 | 依据节 |
|---|---|---|---|
| 某报表稳定跑 30 秒 | 10046 level 12 复现一次 | TKPROF sort=ela / XTAT 树 | 3.1 |
| 看不出时间花在 SQL 还是 PL/SQL | DBMS_HPROF 开层级剖析 | hpackprof 看 self/propagated | 3.2 |
| 并行作业 trace 碎成一片 | trcsess 按 service 归并 | 再进 TKPROF | 3.1 TRCSESS |
| 递归 SQL 淹没主语句 | TKPROF aggregate + sysno | 单独跑一轮 sysyes 审计 | 3.1 |
| 想知道"哪行 PL/SQL 没跑过" | DBMS_PROFILER | 覆盖表按行号聚合 | 3.2 |

| trace 里等待与 latch 混杂 | TKPROF wait=yes | 只留真实等待 | 3.1 |

## 常用命令速查（⚠️ 书内口径转述）

- `EXEC DBMS_MONITOR.SERV_MOD_ACT_TRACE_ENABLE(service=>..., module=>..., waits=>TRUE, binds=>TRUE)`
- `trcsess session=<sid>,<serial> *.trc -o merged.trc`
- `tkprof merged.trc out.txt explain=app/pwd aggregate=y wait=yes sort=(ela,exe) insert=prof_table`
- `EXEC DBMS_HPROF.START_PROFILING('run_dir','run_name')` → `STOP_PROFILING` → `DBMS_HPROF.ANALYZE(...)`
- 查剖析结果：`DBMSHP_RUNS / DBMSHP_FUNCTION_INFO / DBMSHP_CALLS`

## 易混点与补记

- 10046 等级 8 与等级 12 的取舍：wait=True 的开销在高频小语句上可能被放大，采集前先想清楚要哪一层。
- TKPROF 的 `total` 与 `elapsed` 两栏读法不同：递归调用折叠口径会掩盖真实消耗点（⚠️ 转述）。
- trcsess 解决的是"多进程/共享服务器下轨迹散落成多文件"，不是解决"找不到慢 SQL"——定位仍靠 SQL trace 触发。
- TVD$XTAT 汇总表与明细表分工：先按模块聚合找大头，再下钻明细，与 Ch2 分层排除法同构。
- DBMS_HPROF 给 PL/SQL 函数级 self/propagated 时间，DBMS_PROFILER 给行级命中——两者互补不是互斥。
- 可复现是本章全部工具的前提；一旦复现不了，就该切换到 Ch4/Ch5 的武器库。

## 核心概念速览（中英对照）

- **SQL Trace** — SQL Trace (10046)：会话级数据库调用逐行计时
- **跟踪等级** — Trace Level：4=绑定值，8=等待，12=两者
- **DBMS_MONITOR** — 按 service/module/action 粒度的官方开关
- **trcsess** — 多 trace 文件归并器
- **TKPROF** — trace 后处理与排序报表工具
- **aggregate / grp** — 递归 SQL 合并 / 前缀分组
- **wait=yes** — 剔除 latch 类噪声的开关
- **TVD$XTAT** — 调用树式 trace 分析与 A/B 工具（作者出品）
- **层级剖析** — Hierarchical Profiling (DBMS_HPROF)：函数级调用树计时
- **行级剖析** — Line Profiler (DBMS_PROFILER)：行覆盖与行耗时
- **自时/传时** — Self vs Propagated Time
- **可复现问题** — Reproducible Problem：可主动触发、允许埋点的问题类
