# Ch4 Real-Time Analysis of Irreproducible Problems（不可复现问题的实时分析）— 原书 p.103–149 · Part II Identification

> ⚠️ 文档转述。V$ 视图/ASH 为 Oracle 专有，不实测；"分层排除法"文末以 sqlite3 类比 🔧（非 Oracle）。

## 本章定位

- 三分法第二类：**问题正在发生但无法主动复现**（偶发慢、会话挂起、批卡住）。
- 不能埋 10046 等它犯病，只能**趁病在时采样内存中的实时状态**——动态性能视图是唯一的"活体切片"。
- 本章同时是全书"等待事件方法论"的正章。

## 4.1 Analysis Roadmap（分析路线图，p.104）

- 自上而下分层排除四层：
  1. 数据库服务器负载：整机是否饱和（OS 统计 + Time Model）；
  2. 系统级分析：哪类等待主导（wait classes/events 分布）；
  3. 会话级分析：哪些会话在制造负载（V$SESSION 快照 + ASH）；
  4. SQL 语句级：定位 sql_id 与计划。
- 口诀：**由面到点、先系统后会话后语句**；每层要有"证据行"才允许下钻。
- 该路线图与 4.3/4.4 两条工具路径（有包/无包）正交复用。

## 4.2 Dynamic Performance Views（动态性能视图，p.105）

官方列九类（✅），逐类要点：

- **OS Statistics（V$OSSTAT，p.106）**：CPU 忙碌/空闲、换页——先排除"数据库外的资源饥饿"。
- **Time Model（V$SYS_TIME_MODEL，p.107）**：DB time 为根的可加分解（sql execute elapsed、parse、plan…）；**DB time / OS 时间之比是判断"问题在不在数据库内"的第一道闸**。
- **Wait Classes & Wait Events（V$SYSTEM_WAIT_CLASS / V$SYSTEM_EVENT，p.109）**
  - 八大类：User I/O、System I/O、Concurrency、Application、Configuration、Administrative、Network、Other。
  - 典型事件与含义（⚠️ 转述书内口径）：`db file sequential read`=索引式单块读（量大未必坏）；`log file sync`=提交等待；`enq: TX - row lock contention`=业务锁。
  - **等待≠病因；Configuration 类等待指向参数而非缺陷**。
- **System/Session Statistics（V$SYSSTAT/V$SESSTAT，p.113）**：计数器差分法（latch、解析、排序）——与等待事件交叉验证。
- **Metrics（V$SYSMETRIC*，p.114）**：带阈值的比率指标，建立"正常带"参照系。
- **Current Sessions Status（V$SESSION，p.115）**：ROW_WAIT_*、BLOCKING_SESSION、SQL_ID、事件现场字段。
- **Active Session History（V$ACTIVE_SESSION_HISTORY，p.117）**
  - **2e 重点升级节**（1e 未展开）：每秒对活跃会话采样，环形缓冲（内存约 10 万样本；每 10 分钟抽 1% 落 DBA_HIST_ACTIVE_SESS_HISTORY）。
  - 用法：按 `session_state='WAITING'+event`、`delta_time`、`sql_id/module/plsql_*` 聚合，还原任意历史窗口的响应时间构成——**AWR 的 1 秒分辨率补充**。
  - 书内给经典分桶 SQL 范式（按分钟 × 事件/模块/语句分组）。
- **SQL Statement Statistics（V$SQL/V$SQLAREA，p.126）**：按 elapsed/executions 排重语句；**警告：平均值骗人，双峰耗时必须回 ASH/trace 再分层**。
- **Real-time Monitoring（p.126）**：`V$SQL_PLAN_MONITOR` + `DBMS_SQLTUNE.REPORT_SQL_MONITOR`——并行或超 5 秒语句自动行源级采样；作者言："现场只配看一个报告，选 SQL Monitor"。

## 4.4 Analysis Without Diagnostics Pack（p.142）

- 无包时的等价手写件（官方四段同名）：
  - Database Server Load（142）：V$OSSTAT 差分；
  - System Level（143）：V$SYSTEM_EVENT/V$SYSTEM_WAIT_CLASS 差分；
  - Session Level（147）：V$SESSION 定时采样环——**手搓微型 ASH**；
  - SQL Information（147）：V$SQL 聚合。
- **这套"差分采样"是本章可移植性最强的资产，对任何数据库成立**。

## 🔧 分层排除法类比（sqlite3，非 Oracle）

- 数据集同 `demo.py`（200k 行磁盘库）：
  - 第 1 层：`time.perf_counter` 包整批查询，确认时间落在语句内而非连接/解析；
  - 第 2 层（等待类类比）：同一语句内拆 I/O 型（`SCAN` 型 count ≈0.2 ms）与 CPU 型（GROUP BY kind ≈8.5 ms）——**"主导成分分流"与等待类分流同理**；
  - 第 3 层：`EXPLAIN QUERY PLAN` 的 SCAN vs SEARCH 即"下钻到计划行"。
- 仅为 SQLite 行为，演示排除结构，不映射 Oracle 数值。

| 症状 | 先看 | 再看 | 依据节 |
|---|---|---|---|
| 整机卡但说不清哪层 | V$OSSTAT + V$SYS_TIME_MODEL | DB time 是否同步飙升 | 4.2 |

## 核心概念速览（中英对照）

- **分析路线图** — Analysis Roadmap：负载→系统→会话→语句四层下钻
- **时间模型** — Time Model：DB time 可加分解
- **等待类** — Wait Class：等待事件八大类
- **等待事件** — Wait Event：会话耗时事件粒度记录
- **V$OSSTAT** — 主机 CPU/内存压力视图
- **差分采样** — Statistics Diff Sampling：两次快照计数差
- **ASH** — Active Session History：每秒活跃会话采样环
- **delta_time** — 相邻采样点会话耗时
- **V$SQL_PLAN_MONITOR** — 行源级实时执行监控（11g+）
- **SQL Monitor** — 单条 SQL 现场报告
- **Diagnostics Pack** — AWR/ASH 查询的许可门槛
- **微型 ASH 手搓** — Session Sampling Loop：无包等价件

## 最新演进与工业实践

- **ASH 云端放大**：OCI **ASH Analytics** 把 ASH 升为全量保留+高级透视；19c/23ai 的 V$ACTIVE_SESSION_HISTORY/DBA_HIST_* 仍是本章脚本直接续用对象 ⚠️ 转述。
- **许可现实**：Diagnostics Pack 限制依旧，多数中小站点主方案就是 4.4 手搓路；社区成品：Tanel Poder snapper（github.com/TanelPoder/snapper）、`ash_wait_chains`、eDB360 免费报告 ⚠️ 转述。
- **SQL Monitor → SQL Insight**：ADW/自治库把单语句现场报告产品化为免费页 ⚠️ 转述。
- **等待范式外溢**：PostgreSQL 9.6+ 引入 wait_event_type/wait_event（`pg_stat_activity`）、MySQL performance_schema 等待模型——均沿 Oracle 方法论建模，本章读法可直接平移 ⚠️ 转述。
