# Ch10 Execution Plans（执行计划）— 原书 p.299–356 · Part III Query Optimizer

> ⚠️ 文档转述。文末 🔧 为 sqlite3 类比（EXPLAIN QUERY PLAN，非 Oracle 计划格式）。本章是"排障日常动作文法"章。

## 本章定位

- 计划是优化器的"口供"。本章三段式：**怎么取（10.1–10.2）→ 怎么读（10.3）→ 怎么判（10.4）**。
- 第一记耳光：EXPLAIN PLAN 与游标计划不等价——前者模拟、后者真实。取计划不难，难在取到"当时真正执行的"计划。

## 10.1 Obtaining Execution Plans（取计划四法，p.299）

- **The EXPLAIN PLAN Statement（p.299）**：模拟产物；绑定变量时看不到 peeking 效应；当前环境≠执行时环境。定位：新语句预览可用，现场取证禁用。
- **Dynamic Performance Views（p.303）**：`V$SQL_PLAN`/`V$SQL_PLAN_STATISTICS(_ALL)`——游标缓存中的真实计划；plan_hash_value 配对；行源级实际计数需 `statistics_level=ALL` 或 `/*+ gather_plan_statistics */` 口径（⚠️ 转述）。
- **AWR and Statspack（p.305）**：`DBA_HIST_SQLPLAN`（默认不采，需调采集模式）——历史计划入仓储（Ch5 接口）。
- **Tracing Facilities（p.307）**：10046 level 16 + plan statistics——**trace 是唯一能把计划、实际行数、时间三者同帧对齐的手段**。

## 10.2 The dbms_xplan Package（p.311）

- **Output（p.311）**：PLAN_TABLE_OUTPUT 分段——计划主体、**Predicate Information（access/filter/start 三语义是解读钥匙）**、绑定段、**Outline Data（hint 的唯一可靠来源：永远从 outline 抄 hint，别背名字——Ch11 接口）**。
- **The display Function（p.316）**：读 PLAN_TABLE（即 10.1 模拟件）。
- **The display_cursor Function（p.322）**：读游标缓存；`format1=>'ALLSTATS LAST'` 出"估计 vs 实际行数/时间"对照——**定位错误基数的一等工具**。
- **The display_awr Function（p.323）**：读历史计划。

## 10.3 Interpreting Execution Plans（解读，p.325）

- **Parent-Child Relationship（p.325）**：缩进即数据流；ROWS/BYTES/COST/TIME 列含义与"子行成本已计入父行"的累计陷阱。
- **Types of Operations（p.328）——官方五型分类（✅）**
  - Stand-Alone Operations（328）：一进一出叶算子（TABLE ACCESS FULL、INDEX UNIQUE SCAN…）；
  - Iterative Operations（331）：NESTED LOOPS——子行源每父行重复一次，**看 Starts 计数**；
  - Unrelated-Combine（331）：各子行源独立消费（UNION-ALL、CONCATENATION）；
  - Related-Combine（333）：需全量子行源（HASH JOIN、SORT/MERGE、GROUP BY、HASH UNIQUE）；
  - Divide and Conquer（342）：PX 并行族与分段操作。
- **Special Cases（p.345）**：FILTER 子查询的执行时机（每父行 vs 一次）、INLIST 展开、`Starts` 放大陷阱、视图边界。
- **Adaptive Execution Plans（p.348，12c）**：计划树中的 `STATISTICS COLLECTOR` 节点——执行中按实际行数在 NL↔HJ 间切换；display_cursor 标注最终执行的子树。**解读自适应计划必须看"实际发生的那棵树"，否则错怪优化器**。

## 10.4 Recognizing Inefficient Execution Plans（判优，p.353）

- **Wrong Estimations（p.353）**：估计/实际偏离 10x 即嫌疑、>100x 基本定罪；追因走 Ch8 清单（直方图？扩展统计？采样率？动态采样缺位？）。
- **Restriction Not Recognized（p.355）**：谓词未被识别成访问路径（函数包裹列、隐式类型转换、`LIKE '%x'`、视图边界）——本该下推的过滤退化为全量 FILTER；**改写对策回扣 ../Oracle查询优化改写技巧与案例.md 的中文化案例谱系**。
- 判优总纲：**没有绝对坏计划，只有与目标（响应时间/吞吐）错配的计划**——先定优化模式，再看结构。

## 易混点与补记

- 执行计划是"承诺的施工图"不是"实际流水账"：行源统计（gather_plan_statistics）才能对质（⚠️ 转述）。
- 五类操作（数据获取/数据修改/标量/连接/视图处理）先分类再读树，读树速度立刻翻倍。
- 缩进即依赖：同级操作按序执行、父操作消费子操作输出，把"表连接"当并列就错了。
- STARTS、ACTUAL ROWS、LAST OUTPUT 三列对质时缺一不可：只看 ROWS 会漏掉并行切片与重启动。
- `ROWS *COST` 排序是找"病灶"不是找"最大表"：全扫大表可能便宜，小表嵌套循环驱动侧才致命。
- Note 段的 STATISTICS MANUALLY 与 dynamic sampling 提示说明统计环境， Predicate/Column Usage 段才是谓词真相。
- XPLAN 与 DBMS_XPLAN.DISPLAY_CURSOR 的差别在"预测"与"游标缓存中实际"：两者都读，不要只读一个。
- 10053 追踪读法：先搜 Best Cost 行定胜者，再看落选者的计算差异，不要逐行硬啃。
- ADAPTIVE 计划在游标缓存里的显示可能只反映最终分支：并行/串行的切换在运行时已发生。
- 计划里出现未申请的转换（如视图合并）不要慌：那是合法转换在起作用，见 Ch11 清单。
- "索引没被用"不等于"索引坏了"：谓词不可达、选择性差、成本翻转三类原因要分开证。
- AWR 抓来的历史计划与当前可复现计划版本不同时，先对齐统计与参数环境再比较。
- 绑定变量窥视下同一游标可能展示多个子游标：V$SQL 的 IS_BIND_SENSITIVE 行要顺手看。
- 计划稳定性工具箱（SPM/Profile/Outline）在 Ch9 已配置，本章负责读出结果。
- 读计划的终极问题是三件：数据从哪来、每步多少行、谁在驱动谁。
- 并行计划里 DFO/TQ 列的读法在 12c 文档有专章，书内以 RX/RW 标识示意外勿深读。
- 本章方法论完全可迁移：EXPLAIN QUERY PLAN 的 SCAN/SEARCH 二分化是它的极简版（见上文 🔧）。

## 核心概念速览（中英对照）

- **执行计划** — Execution Plan：优化器生成的行源算法树
- **计划哈希** — plan_hash_value：计划形态指纹
- **EXPLAIN PLAN** — 模拟计划（非现场证据）
- **V$SQL_PLAN** — 游标缓存真实计划
- **gather_plan_statistics** — 行源实际计数采集开关（hint 级）
- **dbms_xplan.display_cursor** — 现场计划+估计/实际对照
- **ALLSTATS LAST** — E-Rows/A-Rows/E-Time/A-Time 输出格式
- **Predicate Information** — access/filter/start 谓词三分
- **Outline Data** — 计划蓝图（hint 唯一可靠来源）
- **迭代算子** — Iterative Operations：NL 子树重复执行（Starts）
- **STATISTICS COLLECTOR** — 自适应运行时改道节点
- **基数误估** — Wrong Estimations：数量级偏离定罪线
