## 13.1 Identifying Suboptimal Access Paths（识别，p.449）

- **Identification（449）**：判据=估计行数 vs 实际行数 × 单次访问成本；工具=Ch10 的 ALLSTATS 对照与 V$SQL_PLAN_MONITOR。
- **Pitfalls（452）**：两大认知陷阱——
  - "全表扫描一定坏"：大表+低选择度下 FTS（常配并行）是最优；
  - "索引一定好"：低聚簇因子的索引范围扫描退化为随机单块读风暴（`db file sequential read` 暴涨）。
- **Causes（454）**：统计失真、谓词不可达形态（函数包裹/隐式转换）、聚簇劣化。
- **Solutions（454）**：对症回 Ch8（统计）、Ch16（聚簇/物理设计）或改写（Ch11.2）。

## 13.2 SQL Statements with Weak Selectivity（弱选择度语句，p.459）

- **Full Table Scans（459）**：成本构成（表块数×多块读折算 vs 索引路径）；`TABLE ACCESS FULL` 的合理与不合理边界；缓存与预取行为（11g 的 serial direct read 拐点、12c 的 table pipelining，⚠️ 转述）。
- **Full Partition Scans（461）**：**分区裁剪是本章技术核心**——
  - 静态裁剪：谓词含分区键常量，编译期即裁；
  - 动态裁剪：JOIN FILTER/子查询驱动（运行时裁）；
  - 裁剪失效经典形态：分区键被函数包裹、隐式类型转换、绑定列非分区键。
- **Range Partitioning（461）**：开区间/闭区间谓词与可裁粒度的对应表。
- **Hash and List Partitioning（474）**：hash 仅等值裁剪；list 依赖枚举值显式命中。
- **Composite Partitioning（475）**：one-key/two-key（11g 引入）语义与裁剪层级。
- **Design Considerations（477）**：分区数上限效应、本地索引粒度、分区维护与统计联动（Ch8 接口）。
- **Full Index Scans（479）**：按序取全索引的合法场景（ORDER BY 消除、MIN/MAX、覆盖聚合）；与 FTS 的取舍=索引块数×有效密度 vs 表块数。

## 13.3 SQL Statements with Strong Selectivity（强选择度语句，p.482）

- **Rowid Access（482）**：`TABLE ACCESS BY USER ROWID/INDEX ROWID` 极限形态——cluster key 命中即单块读；多行 rowid 的批量/预取读路径。
- **Index Access（484–525，本章最长节）**：访问路径全家福，逐算子给"触发谓词形态/成本构成/失效条件"：
  - INDEX UNIQUE SCAN / **I2SCAN**（IOT 上以主键范围模拟唯一）；
  - INDEX RANGE SCAN（升/降、DESCENDING）、**INDEX SKIP SCAN**（前导列低 NDV 补救——作者主张优先改索引列序而非依赖它）；
  - INDEX LIST SCAN（IN 列表展开）；
  - **INDEX FAST/FULL/COMPLETE SCAN**（聚合与覆盖三形态的成本差异）；
  - **INDEX JOIN / INDEX JOIN E / BITMAP version**（多单列索引位图合并）；
  - **BITMAP / BITMAP INDEX RANGE SCAN**（低基数列位图代数：AND/OR/EQUAL_MINUS，OLAP 语境）；
  - IOT 的存储直达与二级索引回表。
- **Single-table Hash Cluster Access（526）**：hash cluster 点查圣杯（一次哈希=一块）；代价在装载与簇大小旋钮——2e 明言该对象罕见但值得认识。

## 🔧 访问路径对照——sqlite3 类比实测（非 Oracle）

- 200k 行库：`SELECT id FROM t WHERE v BETWEEN 0.5 AND 0.5001`（返回 15 行）无 `ix_v` 时 `SCAN t` ≈9.9–10.3 ms；`CREATE INDEX ix_v` 后 `SEARCH t USING COVERING INDEX ix_v (v>? AND v<?)` <0.05 ms。
- 演示：**强选择度+索引=数量级收益**（方向与 Oracle 同向）；谓词落入索引键=SEARCH，否则退化 SCAN 过滤（≈access/filter 之分）。
- SQLite 无聚簇因子/直方图概念，量级不可迁移——非 Oracle 结论。

## 谓词形态→可达路径速查

| 谓词形态 | 理想路径 | 常见坏味道 | 依据节 |
|---|---|---|---|
| 主键/唯一键等值 | INDEX UNIQUE SCAN / rowid | 仍走 FTS：统计或 hint 遗留 | 13.3 |
| `col=?`（高聚簇索引） | RANGE SCAN | 低聚簇→顺序随机单块读风暴 | 13.1/13.3 |
| `substr(col)=?` / `col+0=?` | （不可达）改写裸列 | FTS+FILTER | 13.1/Ch10.4 |
| 前导列低 NDV 组合键 | 可 SKIP SCAN，但优先改列序 | 依赖 skip scan 的脆弱计划 | 13.3 |
| `col IN (大量值)` | INDEX LIST SCAN | 列表过长→版本爆炸（Ch12） | 13.3 |
| 分区键范围/等值 | 分区裁剪+本地索引 | 函数包裹→全分区扫 | 13.2 |
| 低基数列 `=?` | 位图索引（DWH） | OLTP 位图=锁灾难 | 13.3 |
| 聚合无 GROUP BY | FAST FULL SCAN（覆盖） | 回表全扫 | 13.2 |

## 易混点与补记

- 访问路径优化的第一性账是"块数"：行、列、谓词三要素共同决定，换索引不换行长等于白跑（⚠️ 转述）。
- index skip scan 的"前导列低基数"要拿直方图证实，凭感觉开等于碰运气。
- 函数索引的可达条件是谓词写成同一表达式：列上加函数、索引列裸奔，两边都不沾。
- 覆盖索引（index fast full scan 可用）与回表成本的取舍，先确认 distinct 键值是否真的稀疏。
- LOB 外置（STORE AS SECUREFILE/enable storage in row）改变的是"每行多少块"这笔总账。
- 聚类因子（clustering factor）是索引路径的隐形税率：同样 NDV，CF 不同结论相反。
- 12c 的 index fast full reverse scan 等能力扩展要记入口，具体行为以文档为准。
- rownum 分页的"先排序后截断"陷阱：STOPKEY 只在有序索引对齐时省时间。
- 批量回写用 FORALL+SAVE EXCEPTIONS 时，失败行的索引/触发器副作用仍可能发生，测试口径要含回滚。
- prefetch 参数在 JDBC/ODP.NET/OCCI 名字不同但账相同：网络往返×行数。
- "索引提示没生效"先查统计与参数环境，再怀疑 hint 语法。
- 本章所有招数共享一个前提：计划稳定——否则优化的是噪声（接 Ch9/Ch10）。

## 核心概念速览（中英对照）

- **弱/强选择度** — Weak/Strong Selectivity：以选择度定策略的总纲
- **全表扫描** — Full Table Scan：合理时的多块读+并行利器
- **分区裁剪** — Partition Pruning：静态/动态两级，谓词须裸含分区键
- **JOIN FILTER** — 动态裁剪运行时过滤器
- **跳过扫描** — Index Skip Scan：前导列低 NDV 补救
- **覆盖扫描三型** — Index Fast/Full/Complete Scan：免回表聚合
- **索引连接** — Index Join：多单列索引位图合并
- **位图索引** — Bitmap Index：低基数列位串与位图代数
- **IOT** — Index-Organized Table：按键有序存储的表
- **聚类因子** — Clustering Factor：键序与行序错位度
- **Hash Cluster** — 哈希簇表：点查一步直达
- **rowid 访问** — Access by Rowid：最小读单元
