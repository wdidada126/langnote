## 6.1 Fundamentals（基本盘，p.169）

- 优化器职责链：语法/语义校验 → **查询变换** → 搜索空间生成（连接序 × 访问路径 × 连接方法）→ 用统计估成本 → 选最优。
- 目标函数随优化模式变形：FIRST_ROWS_n（OLTP 交互）vs ALL_ROWS（批量/并行）——同一语句两个宇宙（Ch9/Ch14 反复回扣）。
- 版本口径：RBO 在 11g 后仅为遗留兼容物；成本单位是**时间（秒）**（10g 起，依赖系统统计——为 Ch7 埋线）。

## 6.2 Architecture（架构，p.172）

- 组件素描：解析器、变换引擎、成本引擎、行源生成器；SQL trace 里可观察各阶段产物（变换后的语句会回显在 trace 中——Ch3 工具的下游呼应）。
- 12c 新住户预告：**自适应查询优化**两件套——计划期（optimization statistics 反馈）与执行期（adaptive plans，见 Ch10）；SQL Plan Directives（自适应统计的"需求单"，书在 12.1 口径内提及）。

## 6.3 Query Transformations（查询变换，p.173–189）——本章主体，官方列 21 种

按等价重写家族分组记忆（页码 ✅ 官方目录）：

1. **谓词/投影族**
   - Predicate Push Down（178）：过滤条件推入行源内部；
   - Predicate Move Around（180）：谓词在等价类间挪移；
   - Select List Pruning（177）：不需要的列不进投影；
   - View Merging（176）：内联视图并入宿主——合并（可下推）vs 不合并（先聚合再连接）的取舍是 2e 例题密度最高处。
2. **去重/聚合族**
   - Count Transformation（174）、Distinct Elimination（181）、Distinct Placement（181：连接+去重下推到维表侧）、Group-by Placement（181）、Order-By Elimination（182）。
3. **布尔结构族**
   - Common Sub-expression Elimination（174）、OR Expansion（175：展开为 CONCATENATION/UNION-ALL，各支用最佳索引）、Join Factorization（185：提取公共维表前缀）。
4. **子查询族**
   - Subquery Unnesting（183：IN→SEMI）、Subquery Coalescing（183：多子查询归并一次扫描）、Subquery Removal Using Window Functions（184：Top-N per group 经 ROW_NUMBER 消解——**本章最可移植的改写技巧**）。
5. **连接族**
   - Join Elimination（185：外键可证存在性时直接删表——**约束即性能的实证**）、Outer Join to Inner Join（186：谓词使外连接退化）、Full Outer Join（187）、Table Expansion（187：MV 重写驱动的表替换）、Set to Join Conversion（188）、Star Transformation（189：详见 Ch14）。
6. **物化视图族**
   - Query Rewrite with Materialized Views（189：声明式重写，详见 Ch15）。

- 本目录读法建议：每种变换问三件事——触发条件？计划里的算子签名？hint 如何关/开？三问答案可在 10053 trace 与重写视图里验证（⚠️ 转述）。

## 计划特征→变换反查速查

| 计划里看到 | 背后是哪类变换 | 想关掉/逼出用哪族 hint |
|---|---|---|
| CONCATENATION + UNION-ALL | OR Expansion | `USE_CONCAT` / `NO_EXPAND` |
| 视图名消失、谓词进基表 | View Merging | `MERGE` / `NO_MERGE` |
| VIEW + FILTER 每父行执行 | 未解嵌套（Unnesting 失败） | `UNNEST` / `NO_UNNEST` |
| SEMI / Anti 连接 | Subquery Unnesting 成功 | 同上 |
| 行内 WINDOW SORT 替代子查询 | Subquery Removal Using Window Functions | `NO_SUWF_BY_WINFUNC` |
| JOIN 消除（表消失） | Join Elimination（依赖外键+NOT NULL） | `ELIMINATE_JOIN` |
| 事实表位图 AND | Star Transformation | `STAR_TRANSFORMATION` |
| MV 替身出现 | Query Rewrite with MV | `REWRITE` / `NO_REWRITE` |
| 谓词进了内联视图 | Predicate Push Down | `PUSH_PRED` |

## 易混点与补记

- CBO 与 RBO 的历史切换：10g/11g/12c 逐步清退 RBO 痕迹，书内以 12.1.0.2 口径叙述（⚠️ 转述）。
- 成本单位是"秒"不是"块"：这个 10g 起的改变，把系统统计（Ch7）变成成本模型的地基。
- join order 搜索与 transform 展开是两个正交维度：空间大小分别受 `_optimizer_...` 族参数与转换开关控制。
- "CBO 选了坏计划"常常是"统计信息骗了 CBO"：第 III 部分三章（7/8/9）都是为这句话服务。
- 多因素成本（CPU+IO+并行）叠加后，解释计划不再能靠单条公式手算——要看 Note 段与 Predicate 段。
- 转换（transformation）在代价评估之前发生：同一 SQL 的不同等价形态才是真正在竞争计划的候选。
- 优化器追踪事件（10053）是本章方法论的钩子：它把"为什么选这个计划"的内部决策摊成文本（接 Ch10）。
- 12c 的统计驱动特性（SQL Plan Directives、dynamic sampling 增强）是 CBO 自我修复的第一步，书内埋线、2026 已成主角。
- 本章定位是"地图"不是"教程"：每一小节都是后续 Ch7–Ch10 的入口。

## 核心概念速览（中英对照）

- **查询优化器** — Query Optimizer (CBO)：成本导向计划生成器
- **查询变换** — Query Transformation：不改结果、改可优化性的逻辑重写
- **视图合并** — View Merging：内联视图并入宿主查询
- **谓词下推** — Predicate Push Down：过滤条件推入行源
- **OR 展开** — Or Expansion：OR 拆 UNION-ALL 各支配索引
- **子查询解嵌套** — Subquery Unnesting：子查询改连接
- **窗口函数消解** — Subquery Removal Using Window Functions：Top-N per group
- **连接消除** — Join Elimination：可证等价时删外连接表
- **连接因子分解** — Join Factorization：提取公共维表前缀
- **表扩展** — Table Expansion：MV 驱动的表替换
- **星型变换** — Star Transformation：位图代数重构星型访问
- **物化视图重写** — Query Rewrite with MVs：声明式答案复用
- **自适应查询优化** — Adaptive Query Optimization (12c)：计划期+执行期双自适应
- **优化模式** — Optimizer Mode：FIRST_ROWS_n vs ALL_ROWS
