# Ch9 Configuring the Query Optimizer（配置查询优化器）— 原书 p.273–297 · Part III Query Optimizer

> ⚠️ 文档转述。参数行为不实测；参数清单以官方目录节次为骨架，逐参数语义按书内+文档口径转述。

## 本章定位

- 反"调参玄学"的一章。目录第一句即立场：**To Configure or Not to Configure…（p.273）**。
- 作者答案：优化器默认配置在绝大多数场景是对的；配置的合法动机只有两个——
  1. 已证明的工作负载特征与默认假设冲突；
  2. 你有可回归的验证手段。
- 本章给路线图而非参数大全：先诊断（Ch3–5）、再确认统计（Ch7–8）、最后才动参数，且**每次只动一个**。

## 9.1 To Configure or Not to Configure（p.273）

- 参数是"改变优化器假设"的杠杆，也是"掩盖真实问题"的遮羞布。
- 合法变更的三特征：有证据、有回滚、有台账（回扣 Ch1 问题台账）。

## 9.2 Configuration Road Map（p.274）

- 官方六步骨架（转述大意 ⚠️）：
  1. 明确目标：哪条/哪类语句、什么指标（响应时间/吞吐）；
  2. 确认系统统计与对象统计健康（否则一切参数都是空中楼阁）；
  3. 从优化器参数族中挑与症状直接相关者；
  4. 测试环境同统计+同基线做 A/B；
  5. 变更入操作日志与配置台账；
  6. 生产变更配回滚方案（spfile/scope 语义 + 统计回滚配套）。

## 9.3 Set the Right Parameter!（p.276）

- **Query Optimizer Parameters（p.276–291）**：书内逐参数给"默认/合法值/何时动/危险度"。主干清单（⚠️ 转述）：
  - `optimizer_mode`：FIRST_ROWS_n/ALL_ROWS 总目标——混合负载站点的经典陷阱；
  - `optimizer_features_enable`：**版本降级旋钮**，升级后计划翻转的第一止血阀；代价是冻结新变换——短期救火、长期要还；
  - `optimizer_index_cost_adj` 与 `db_file_multiblock_read_count`：**I/O 成本扭曲对**——10g 时代的调优圣水、workload 统计普及后的危险玩具（多数场景应留在默认）；
  - `optimizer_index_caching`：聚簇近似估计的补充旋钮；
  - `statistics_level`（TYPICAL/ALL）：决定 ASH/plan monitor/工作负载采集是否在场——**排障站点常年 TYPICAL 是失策**；
  - `cursor_sharing`（EXACT/FORCE/SIMILAR）：**本章唯一被建议谨慎使用的"急救参数"**——FORCE 可止血字面量风暴但喂坏计划，治本在应用侧绑定（Ch12 展开）；
  - I/O 体系族（`filesystemio_options`、`db_writer_*`、`_file_io_slaves*`）：与优化器间接相关，多数站点不动；
  - 隐参数（`_optimizer_*`、`_nlj_batching_enabled` 等）：**必须拿到 Oracle 支持背书再动**——作者的红线。
- **PGA Management（p.291–297）**
  - `workarea_size_policy`（AUTO/MANUAL）、`pga_aggregate_target`（12c 前软目标）与 `pga_aggregate_limit`（12c 新硬顶语义）；
  - 排序/哈希连接/位图合并的工作区大小分摊逻辑（`V$SQL_WORKAREA*` 观测，Ch14 工作区节互引）；
  - 因果链：**PGA 不足 → 磁盘排序/两遍哈希 → 响应时间翻倍**——参数不改计划形状但改成本兑现。

## 症状→参数判定速查

| 症状 | 先排除 | 才考虑的参数 | 危险度（书内态度） |
|---|---|---|---|
| 升级后计划集体翻转 | 统计兼容性 | optimizer_features_enable（临时） | 中：救火可、要还 |
| 字面量风暴拖垮 CPU | 应用改不了？ | cursor_sharing=FORCE（临时） | 高：急救阀 |
| 索引路径系统性吃亏 | workload 统计缺失 | optimizer_index_cost_adj | 高：先补统计 |
| 交互页首行慢、批量慢不分 | 目标混淆 | optimizer_mode 会话级 | 低：scoped |
| 大排序落盘/两遍哈希 | PGA 配置 | pga_aggregate_target/limit | 低：容量问题 |
| 无诊断数据可看 | — | statistics_level=ALL（窗口期） | 中：开销换可见性 |
| 优化时间超过执行时间 | 统计与动态采样 | 搜索策略类隐参数 | 极高：须 SR 背书 |

## 易混点与补记

- init.ora 参数、优化器开关、隐参数是三层不同的控制面，作用域与会话级覆盖关系要分清（⚠️ 转述）。
- OPTimizer_ADAPTIVE_FEATURES 之类的 SQL 补丁是"带版本语义的开关"，比改 init 参数更可回退。
- 动态采样从 0 到 11 的档位不是越贵越好：10053 里能看到它在缺统计时如何顶上，先证缺失再加档。
- 结果缓存与计划缓存是两回事：SQL 级与数据级失效策略不同，别把 V$RESULT_CACHE 当 V$SQL 看。
- `CURSOR_SHARING` 从 EXACT 到 SIMILAR 的语义在 12c 已被 FORCE+扩展游标共享取代，旧手册结论要更新。
- 绑定变量窥视只发生在硬解析时刻：游标已在内存、负载分布已漂移时它救不了你。
- 自适应游标共享是"运行时反馈"，绑定窥视是"编译时快照"——同带 cursor 字样，方向相反。
- SQL Plan Baseline 接受新计划是 evolve 过程不是即时生效：FEASIBLE/ACCEPTED 状态机要看清。
- SQL Profile 修的是"这条语句的成本环境"，Outline 钉的是"这棵形状树"——一个补数据一个封结构。
- 12c 的 SQL Trace 与 XPLAN 是取证工具不属于配置面，但 Ch10 会把它们接上。
- 优化器特性开关族（_optimizer_...）每次升级都可能变化：把隐参数清单当易耗品维护。
- 文档口径：本节的参数名以 12.1.0.2 书内为准，26 文档里部分条目已更名或移除 ⚠️。
- 改配置的验证闭环 = 对比执行计划 + 对比 AWR 负载画像，缺一半都等于没验证。
- 全局配置与对象级配置（如 no_invalidate、opt_estimate）互相纠缠时，先用最窄作用域试错。
- 本章一切参数的最终目的：让 Ch7/Ch8 的统计输入与 Ch6 的成本模型按设计运转。

## 核心概念速览（中英对照）

- **配置路线图** — Configuration Road Map：诊断→统计→单参数→A/B→台账→回滚
- **优化器模式** — optimizer_mode：全局目标函数选择
- **特性降级** — optimizer_features_enable：版本行为回退阀
- **索引成本系数** — optimizer_index_cost_adj：索引路径整体缩放（高危）
- **多块读计数** — db_file_multiblock_read_count：全扫成本旋钮（过时）
- **统计级别** — statistics_level：TYPICAL/ALL 决定诊断设施在场性
- **游标共享** — cursor_sharing：EXACT/FORCE/SIMILAR 急救语义
- **PGA 策略** — workarea_size_policy：AUTO/MANUAL
- **PGA 硬顶** — pga_aggregate_limit（12c）：防 OOM 上限
- **工作区** — Work Area：排序/哈希内存配额单元
- **隐参数** — Hidden Parameters：下划线族，需 SR 背书
- **spfile/scope** — 变更持久化与生效域：可逆性设计

## 最新演进与工业实践

- **2026 对位**：19c/23ai 参数面继续膨胀（自适应特性各自带母开关）；官方支持口径未变——**升级后计划问题第一止血阀仍是 optimizer_features_enable** ⚠️ 转述。
- **Autonomous DB 极端化**：几乎全部优化器参数被托管锁定——"不许调参"从本章立场变成平台事实；运维转译动作=向自动机制提供反馈（SPM/SQL 画像页）而非手改 ⚠️ 转述。
- **跨引擎**：MySQL 8 `optimizer_switch` 误用仍是事故高发区；PostgreSQL `random_page_cost`（SSD 时代 4.0→1.1–2.0 的调优潮流）恰是"缺系统统计时手工等效"的活案例——回扣 Ch7。
