## 本章定位

- Part IV 的"重武器"章：前面解决"一条语句怎么跑"，这里解决"**换个执行范式**"——预计算（MV）、缓存（结果缓存）、以资源换时间（并行）、以格式换时间（DPI）、以批量换往返（预取/数组接口）。
- 共同哲学：**收益都建立在"消除重复工作"上，误用则制造新的重复工作**。

## 15.1 Materialized Views（物化视图，p.575–596）

- **How It Works（576）**
  - MV=物化查询结果+刷新机制+重写入口。
  - 定义选项：WITH ROWID/PRIMARY KEY、`ENABLE/DISABLE QUERY REWRITE`。
  - 刷新方式：COMPLETE/FAST（物化视图日志 `MLOG$_`、可读一致/可更新快照）；时机：ON COMMIT/ON DEMAND/NEXT；执行器 `DBMS_MVIEW.REFRESH`（嵌套、分区变更刷新）。
  - 重写开关：`query_rewrite_enabled` 与 `query_rewrite_integrity`（ENFORCED/TRUSTED/STALE_TOLERATED 三档）。
- **When to Use（596）**：多报表共享的聚合、滚动窗口汇总、跨库维度复制；与星型变换（14.8）分工。
- **Pitfalls（596）**：ON COMMIT 刷新风暴、基表变更与 MV 失配、重写选错 MV 的反噬、企业版选件许可与运维成本。

## 15.2 Result Caching（结果缓存，p.597–604）

- **How（597）**：11g 两层——服务器端 RESULT_CACHE（语句结果级，`V$RESULT_CACHE_*`，失效依赖基表 DML）与客户端（OCI 注释）；`RESULT_CACHE_MODE=MANUAL/FORCE`；PL/SQL 函数级 `RESULT_CACHE`/`RELIES_ON`。
- **When（604）**：小而热、读多写少的维度查询与查找函数；**结果集大小是硬门槛**（缓存大结果=负收益）。
- **Pitfalls（604）**：高吞吐下缓存本身成争用点（`rescache: mutex` 类等待 ⚠️ 转述）、FORCE 无差别缓存、命中率被绑定变量形态掩盖。

## 15.3 Parallel Processing（并行，p.605–636，本章半壁）

- **How It Works（605）**
  - 架构：QC+slave 集（`V$PX_SESSION`）；
  - 粒度：表级（分区/子分区/块区间）、操作级（计划分段：`PX PARTITION RANGE/JOIN FILTER`）、语句级（DOP）；
  - 分布方法：BROADCAST/HASH/随机/PARTITION（14.6 接口）；
  - DOP 来源：表 DEGREE→hint→自动 DOP（`parallel_min_time_threshold`、`parallel_threads_per_cpu`、`parallel_servers_target`）；
  - **12c 三件套**：intermediate result spilling（溢出临时表空间）、statement queueing（队列等待 `PX longque` 类）、DOP 自动降级（资源不足时降并行而非挂起）——书按 12.1 口径 ✅。
  - DDL/DML 并行（`ENABLE PARALLEL DML`）；串行化检测：`PX COORDINATOR` 之下无并行子操作=被降级。
- **When to Use（636）**：批处理窗口、大扫描/大连接；判据=**时间收益是否抵得上资源挤占**——并行把响应时间换成吞吐，OLTP 误用=全场灾难。
- **Pitfalls（636–641）**：倾斜（热分区独扛 slave）、并行属选件的许可现实、统计口径（并行 trace 需 TRCSESS 合并——Ch3 回扣）、计划串行点（函数/序列/UNION 导致的单线程段）。

## 15.4 Direct-Path Insert（旁路插入，p.641–644）

- **How（641）**：`INSERT /*+ APPEND */` 与 `/*+ APPEND_VALUES */`（PL/SQL 绑定批量，11.2 起）：绕过缓存直接格式化新 HWM 区。
- **When（644）**：批量装载窗口；与并行组合。
- **Pitfalls（644）**：**段排他锁与读一致性窗口**（未提交不可见）、块不可复用直至 HWM 清理、索引树碎片（对策：装载后重建索引）、与压缩路径的耦合（HCC 仅 DPI 激活，16.5 接口）。

## 15.5 Row Prefetching（行预取，p.645–650）

- **How（645）**：fetch 间驱动侧批量预取：OCI prefetch（11g 后默认 20 行）、JDBC `defaultRowPrefetch`、ODP.NET `FetchSize`。
- **When（650）**：大结果集消费端；配合 `bytes sent via SQL*Net to client` 观察。
- **Pitfalls（650）**：预取掩盖"慢在往返/驱动"的真相；`SQL*Net message from client` 的等待学名是"客户端在思考"（回扣 Ch4 等待观）。

## 15.6 Array Interface（数组接口，p.650–654）

- **How（650）**：PL/SQL `FORALL`（SAVE EXCEPTIONS、INDICES OF）、JDBC `addBatch/executeBatch`、OCI array binds/dml。
- **When（654）**：任何行数>百级的往返型 DML/查询。
- **Pitfalls（654）**：批量内行级触发器放大、异常定位困难、游标侧数组内存。
- 作者警句（转述大意 ⚠️）：**"数组接口消灭往返，绑定变量消灭解析——两剂药不可互替"**。

## 易混点与补记

- 物化视图重写要求查询与 MV 定义在语义上可对齐：基表直查未必命中 MV，先查 REWRITE 能力列（⚠️ 转述）。
- 刷新方式（COMPLETE/FAST/FORCE）与查询重写开关是两个维度，刷新失败时重写会静默失效。
- 结果缓存的失效粒度是"表级"：任何一次 DML 都会让该表相关缓存整体作废，高频写表上收益归零。
- 12c 自动 DOP 按语句 IO 阈值触发：小语句被并行化通常是阈值配错而非特性错。
- 并行度不是越高越好：排队（parallel servers queued）与降级（downgrade）在 AWR 里各有签名。
- DPI 省的是"每行往返"，prefetch 省的是"每批往返"：两种网络税，药不一样。
- 客户端侧的"慢"要先拆成 DB 时间/网络时间/应用处理时间三段再谈优化。
- 本章机制全部在 SQL 之外：诊断时先确认 SQL 侧已无油水（Ch13/Ch14），否则是错药。

## 核心概念速览（中英对照）

- **物化视图** — Materialized View：预计算+可重写的答案表
- **MV 日志/快速刷新** — Materialized View Log / FAST Refresh
- **重写完整性** — query_rewrite_integrity：ENFORCED/TRUSTED/STALE_TOLERATED
- **结果缓存** — Result Cache：语句/函数结果级缓存（11g）
- **并行执行** — Parallel Query/DML：QC+slave 分片协作
- **自动 DOP / 语句队列 / 溢出** — Automatic DOP / Statement Queuing / Spilling（12c）
- **PX 串行化** — Serialized PX：名义并行实际串行
- **旁路插入** — Direct-Path Insert（APPEND/APPEND_VALUES）
- **行预取** — Row Prefetch：fetch 侧批量拉取
- **数组接口** — Array Interface（FORALL/addBatch）
- **SQL*Net message from client** — "客户端在思考"型等待
- **rescache: mutex** — 结果缓存争用等待

## 最新演进与工业实践

- **MV 线**：19c/23ai 的**自动物化视图（Automatic MVs）与 ADW 自动 MV 建议**把"发现聚合模式→建→重写→刷新"整链产品化——本章三段论仍是评审自动决策的框架 ⚠️ 转述。
- **并行线**：19c 默认 `parallel_degree_policy=AUTO`（门控+计划缓存）普及；Exadata/ADWC 的弹性 DOP 让"并行恐惧症"退场，但倾斜与串行点检测仍归本章方法论 ⚠️ 转述。
- **DPI/批量线**：23ai 的 AI Vector Search 与 JSON 批量装载大量复用 APPEND_VALUES+FORALL；跨引擎同构答案：PostgreSQL `COPY`、MySQL `LOAD DATA`、DuckDB appender API（可实测：pip duckdb）⚠️ 转述。
- 工具位：15.5/15.6 的往返治理效果最适合用 TVD$XTAT 模块瀑布（Ch3）审计 ⚠️ 转述。
