## 2.1 Selectivity and Cardinality（选择度与基数，p.19）

- **选择度**：谓词过滤后剩余行占表行的比例（0–1）；是列与谓词的属性。
- **基数**：某行源（表/视图/连接/分组）结果集的行数估计；是行源的属性。
- 关系式：带谓词行源的基数 = 无谓词基数 × 选择度。
- 优化器一切成本比较建立在这两个量上；**贯穿全书的诊断观：坏计划十有八九坏在基数估计**（Ch10 Wrong Estimations、Ch8 直方图均回扣此节）。
- 社区长期混用二词，作者特意分辨——本目录全稿遵循此定义。

## 2.2–2.3 What Is a Cursor? / Life Cycle of a Cursor（游标与生命周期，p.21–24）

- 游标 = 会话 PGA 中的句柄，指向共享池中的**可共享游标**（parent + 若干 child）与执行堆（执行环境、绑定元数据、结果缓冲）。
- 生命周期：Open → Parse（软/硬）→ Bind → Define → Execute → Fetch → Close。
- 硬解析发生在共享池找不到可复用 parent/child 时；child 因优化器环境、统计版本、绑定元数据不匹配而增殖（伏笔 Ch12 版本爆炸）。
- 会话侧游标不开不关 → open_cursors 耗尽与 PGA 泄漏；作者区分"游标数量问题"与"游标内存问题"两类症状。

## 2.4 How Parsing Works（解析如何工作，p.24）

- **Shareable Cursors（p.25）**
  - parent cursor 以 SQL 文本哈希定位；child 以环境+统计+绑定签名定位。
  - 文本不同 = 不同 parent；环境漂移 = child 爆炸。字面量 SQL 是"共享"的反面教材。
- **Bind Variables（p.29）**
  - 客户端/OCI/JDBC/PL/SQL 的绑定路径逐一说明。
  - Bind Peeking（11g+）：首次解析采样绑定值入 child 元数据，与直方图联动决定基数（伏笔 Ch8）。
  - 作者明确"什么时候不该绑定"：数据倾斜列 + 无直方图时。
  - ACS（Adaptive Cursor Sharing，11.2/12c）：按绑定区间生成多计划；2e 相比 1e 在此大幅扩充。

## 2.5 Reading and Writing Blocks（块读写，p.40）

- 一切物理读经 buffer cache；两种模式：
  - Consistent Read（CR 克隆，undo 构造前镜像）——查询路径；
  - Current Read（加锁块）——DML 路径。
- 直接读绕过缓存（并行/全扫的 direct path read、Ch15 的 direct-path insert）。
- 写路径：dirty block 由 DBWn 异步落盘，redo 由 LGWR 同步保证——**"提交不等于数据块落盘"**。
- 此节为 Ch1.2.9（不必要提交）与 Ch4 等待事件（db file sequential/scattered read、log file sync）提供机理底座。
- 与 ../Oracle编程艺术：深入理解数据库体系结构（第3版）.md 严格互补：那本讲块/ITL 结构，这本讲"读写一次块花哪些时间"。

## 2.6 Instrumentation（仪器化，p.42）

- 总论："没有测量就没有排障"。两类仪器（官方子节 ✅）：
  - **Application Code（p.43）**：应用自带计时/日志；作者提醒——以数据库调用为边界的计时才可比。
  - **Database Calls（p.44）**：内核自带计数：时间模型统计、等待事件、会话统计（V$SYS_TIME_MODEL、V$SESSION_EVENT 等）。
- 每个数据库调用被拆为 elapsed = CPU + 各类等待（可加分解）——**Ch3 trace 与 Ch4 V$ 视图的共同底座**。
- 本节立起全书时间观：**响应时间是唯一真目标；一切统计都是响应时间的可加分解**。

## 易混点与补记

- 响应时间 ≠ 服务时间：排队段归响应、不归服务——DB time 里两者混在一起，先分层再下结论（⚠️ 转述）。
- DB time 与 OS CPU 利用率可以 simultaneously 一个高一个低：并行与并行度会扭曲单机视角。
- 等待事件名相同含义可不同：`db file sequential read` 是索引式单块读，快慢全看上下文，不能见名定罪。
- 事务级与语句级指标别混用：一条 SQL 的耗时可能远小于它所在事务的总耗时。
- 分层排除法（OS→实例→会话→SQL）是本章方法论骨架，Ch3–Ch5 全部复用。

## 核心概念速览（中英对照）

- **选择度** — Selectivity：谓词过滤比例（0–1）
- **基数** — Cardinality：行源结果行数估计，"坏计划之母"
- **游标** — Cursor：会话句柄 + 共享池可共享游标合称
- **可共享游标** — Shareable Cursor：parent（文本哈希）+ children（签名）
- **软解析/硬解析** — Soft/Hard Parse：有无完整优化阶段之分
- **绑定变量** — Bind Variables：文本规范化换游标复用
- **绑定值捕获** — Bind Peeking：首解析采样影响基数估计
- **自适应游标** — Adaptive Cursor Sharing：按绑定区间多计划
- **一致性读/当前读** — Consistent/Current Read：CR 克隆 vs 加锁读
- **直接路径读写** — Direct-Path Read/Write：绕过缓存的批量通道
- **时间模型统计** — Time Model Statistics：DB time 可加分解
- **等待事件** — Wait Events：会话耗时事件级切分
- **仪器化** — Instrumentation：应用与数据库两侧耗时测量总称

## 最新演进与工业实践

- **诊断产品化**：12c+ 的 V$SQL_CS_*（ACS 观测视图）、19c/23ai 的 V$SQL_SHARED_CURSOR 原因位持续扩充；云上 ADI 直接告警"游标版本爆炸" ⚠️ 转述。
- **绑定 vs 字面量的当代折衷**：ORM 默认绑定；PostgreSQL 12+/17 的 plan cache generic/custom 切换（`plan_cache_mode`）、MySQL 8 无 ACS 只能 hint——跨引擎同题，作者"倾斜列慎用通用计划"结论仍成立 ⚠️ 转述。
- **Instrumentation 的现代等价物**：OpenTelemetry 数据库 span 约定（db.statement/db.system）正是"以数据库调用为计时边界"的工业实现；Oracle 23ai 引入 DBMS_OBSERVABILITY 统一导出 ⚠️ 转述。
- 参考文档：Oracle 26 版 Reference/Concepts 文档族可达（docs.oracle.com/en/database/oracle/oracle-database/26/ ✅ curl 200）；MOS 关于 bind peeking/ACS 的说明文档（Doc 616317.1）长期被引 ⚠️ 编号转述。
