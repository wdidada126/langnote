## 16.1 Optimal Column Order（最优列序，p.655）

- 行式存储下列的物理顺序影响行长进而影响块行数（NULL 尾部列省存储、变长列头开销）。
- 经验方向：宽列与常变列的位置权衡（"常读列前置"以省行内解析与块数）。
- 重要纠偏：**CBO 时代列序不影响路径选择，只影响空间与块密度**——RBO 时代的"连接列前置"迷信被作者点名清除。
- 限定：IOT 与列存（IMC 时代）下规则变形。

## 16.2 Optimal Datatype（最优类型，p.657）

- **Pitfalls（657）**：
  - VARCHAR2 字符语义与 NLS 下最大长度陷阱；CHAR 定长补空格致 join 失配；
  - DATE 被当纯日期用（实际含时间）；TIMESTAMP 与精度滥用；
  - NUMBER 泛用→宽度浪费与隐式转换→谓词不可达（Ch13 访问路径灾难的类型学根源）。
- **Best Practices（660）**：能小则小（INTEGER/NUMBER(p,s)/精确到微秒才用 TIMESTAMP）、字符列按真实分布定长、连接键类型全链统一、ROWID 不持久化。
- 每条都回扣"块行数×谓词可达性"双账。

## 16.3 Row Migration and Row Chaining（行迁移与行链接，p.662）

- **Migration vs Chaining（662）**：迁移=UPDATE 增宽后原块放不下，旧位留**转发指针**；链接=一行天然跨多块（大行/块小）。
- **Problem Description（664）**：迁移使每次读=2 次块访问——索引扫描的单块读放大；链接使行读碎片化。
- **Problem Identification（664）**：`ANALYZE TABLE ... LIST CHAINED ROWS` + CHAINED_ROWS 表、`V$SYSSTAT` 的 table fetch continued row、12c 统计侧 chain 计数（⚠️ 转述）。
- **Solutions（665）**：`ALTER TABLE ... MOVE`（段重建；12.2+ MOVE ONLINE 预告）、pctfree 预防（接 16.4）、ASSM、大行拆分/LOB 外置。

## 16.4 Block Contention（块竞争，p.665）

- **Problem Description（666）**：热块家族——
  - 索引右侧生长（序列索引最右叶热点）；
  - 表侧 ITL 不足（initrans/pctfree）与 freelists 时代的 P1/P2…；
  - 现场等待：`enq: HW - contention`（高水位）、`buffer busy waits`、RAC 下 `gc cr block busy`。
- **Problem Identification（666）**：ASH 按 current_obj#/file#/block# 三维聚合定位热块；`V$SEGMENT_STATISTICS` 的 buffer busy waits；等待事件 p1/p2 直读文件号/块号（Ch4 方法论落地）。
- **Solutions（670)**：hash 分区打散索引热点、序列 CACHE 与 12c `SCALE EXTEND`、ASSM 取代 freelists、initrans/pctfree 调块内并发槽、反向键索引的利弊（解热点、毒区间扫描）。

## 16.5 Data Compression（数据压缩，p.673）

- **Concept（673）**：符号表压缩（块内前缀码），按"列值重复度"吃红利。
- **Requirements（675）**：2014 许可地图（⚠️ 书内口径）——OLTP Table Compression 属 Advanced Compression 选件；BASIC 较宽；HCC 绑 Hybrid Columnar 组织与特定存储（Exadata/ZFS）。
- **Methods（675）**：COMPRESS BASIC（仅 DPI 路径生效的陷阱！）、OLTP COMPRESS（普通 DML 维持压缩）、**HCC 四级（QUERY LOW/HIGH、ARCHIVE LOW/HIGH，12c 口径）**与 DML 触发重压机制、索引压缩（叶节点 nocompress 例外）、IOT 溢出段。
- 收益账：块数下降→缓存命中率↑→扫描 IO↓——全书成本模型的物理分母。

## 易混点与补记

- 迁移留转发指针、链接天然跨块：诊断口径都是 `table fetch continued row`，处置方案却相反（MOVE vs 拆行）（⚠️ 转述）。
- pctfree 是"给未来 UPDATE 买的保险"：只读表设 0、高频增宽表设高，一刀切必错。
- ASSM 解决 freelists 竞争，不解决 ITL 不足与右侧热点——三个时代三种病。
- 反向键索引治标：区间扫描与聚类属性全受损，12c SCALE EXTEND 是更对路的解。
- 列序不影响 CBO 路径选择，影响行长与块密度——RBO 时代迷信要在账本上清除。
- BASIC 压缩只在 direct path 写入生效是 12c 经典陷阱：普通 DML 维持压缩要 OLTP COMPRESS。
- HCC 绑组织方式与存储平台（书内 2014 许可地图），选它先过许可关再谈收益。
- 压缩改变全书成本模型的分母：块数降、缓存升，统计与标定都要重采才可比。
- 本章是 Ch1.2"缺物理设计"反模式的解药卷，也是全书收束：运行时的债多是设计时的赊。

## 核心概念速览（中英对照）

- **行迁移/行链接** — Row Migration / Row Chaining：转发指针 vs 跨块行
- **table fetch continued row** — 迁移读取的统计签名
- **pctfree / initrans** — 预留更新空间 / 块内事务槽
- **ASSM / freelists** — 自动段管理取代 freelist 组
- **ITL 竞争** — Interested Transaction List shortage
- **右侧热点** — Right-Hand Index Growth
- **SCALE EXTEND 序列** — 12c 序列键打散
- **反向键索引** — Reverse Key Index：热点解药、区间毒药
- **buffer busy waits / enq: HW** — 热块/高水位等待族
- **OLTP/HCC 压缩** — Advanced Row Compression / Hybrid Columnar Compression
- **DPI-BASIC 耦合** — 压缩激活路径的陷阱
- **行长账** — 列序×类型→块密度：物理设计的第一性

## 最新演进与工业实践

- **19c/23ai 对位**：`MOVE ONLINE`（12.2+）让迁移治理无停机常态化；**IMC（In-Memory Column Store）事实上接管扫描侧收益**（行存压缩+列存副本双轨）；自动索引/自动统计对物理设计的反馈仍在起步 ⚠️ 转述。
- **许可现实**：OLTP 压缩多版本仍属 Advanced Compression 选件，**ADW 等托管服务默认开启（含 HCC）**——许可地图从静态表变成平台属性 ⚠️ 转述。
- **块大小退场**：16/32k 大块试验在 SSD 时代收益萎缩，社区共识"块大小几乎不该动"——本章 16.1/16.2"行长才是杠杆"得到延续 ⚠️ 转述。
- 🔧 类比注（sqlite3，非 Oracle）：`demo.py` 的 `sqlite_stat1 ('t','ix_kind','200000 400')` 显示每键均 400 行——**"低基数键=高重复=符号表压缩红利"** 的直觉在 SQLite 页上同样成立（未做压缩实验，止于直觉）。
- 跨引擎：PostgreSQL HOT update（同页更新免索引写）是"行迁移控制"的 MVCC 变体；MySQL InnoDB purge 滞后对应块密度恶化——同一物理问题的三种文明解。
