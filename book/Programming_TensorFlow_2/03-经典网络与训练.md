## 一、核心机制

### 1. 三件套：loss / optimizer / metrics
- `model.compile(loss='sparse_categorical_crossentropy', optimizer='adam', metrics=['accuracy'])` ⚠️ 字符串简写凭通行口径。
- 损失选择纪律：**整数标签→sparse_*，one-hot→categorical_*，二分类→binary_crossentropy**——教学册的高频翻车点就是标签形状与损失不配对。
- PyTorch 对照（本档主锚）：Keras `compile` 三件套 ≈ PyTorch 循环里手写 `criterion = nn.CrossEntropyLoss()` + `optim.Adam(model.parameters())` + 每步手动累计 accuracy。关键语义差：**PyTorch `CrossEntropyLoss` 内嵌 softmax 吃 logits，而 Keras 要求模型末层自带 softmax 再配 categorical 损失**——两边对「数值稳定化谁负责」的分工相反，从任一边迁移者必踩。
- 其他语言锚：优化器字符串注册表（`'adam'`→类）近似 IoC 容器按名注入——便利但掩盖了学习率调度等构造参数，工业代码宜显式 `tf.keras.optimizers.Adam(learning_rate=...)` ⚠️ 默认 lr 数值属版本敏感，不写死。

### 2. 过拟合控制
- Dropout 层（训练态随机丢、推理态缩放补偿）、L2 核正则（`kernel_regularizer=l2(1e-4)`）、早停（EarlyStopping + 验证指标）、数据增广。⚠️ 带段内容按通行教学结构推定。
- 对照 PyTorch：`nn.Dropout` 语义相同，但 Keras 的 `training` 参数把模式显式传到每一层，PyTorch 靠模块全局 `train()/eval()` 状态——后者忘记切换是经典事故，前者写自定义循环时漏传 `training=True` 同样经典。**两侧各留了一个坑，只是坑位不同**。

### 3. Estimator 迁移（时代特产）
- 1.x 的 `tf.estimator.Estimator` + `model_fn` 是「图时代训练协议」；本书成书期正处 Estimator 冻结、官方推纯 Keras 的换代点，迁移带段大概率存在 ⚠️ 推定（单文件档主线脉络点名）。
- 2026 读法：当作**框架 API 生命周期标本**读——`model_fn(features, labels, mode)` 手工分 TRAIN/EVAL/PREDICT 三模式 ≈ 把所有 if 写在训练循环里；Keras 用方法拆分（fit/evaluate/predict）吸收了这个复杂度。

## 二、批判读法
- 教学密度与工业口径的落差：`metrics=['accuracy']` 在分类外的任务（回归/多输出）会静默不适配 ⚠️；书中自定义指标（`tf.keras.metrics.Metric` 子类）讲多深未知 ⚠️，目录销账时确认。
- 「调参玄学」风险：Adam 默认值全包打天下是 2021 教学册常态，2026 已知 Adam 在部分 CV 任务泛化劣于 SGD+momentum——书中若给结论「Adam 优先」，按当年共识而非定论读 ⚠️。
- Estimator 带段跳读判据：若你无 1.x 遗留代码，该带段整节可跳，概念价值本档已浓缩。

## 三、🔧 微实验位（未实测：本机未装 tensorflow）
- E1：同一小数据集（如 iris/titanic 级），分别用 sparse/one-hot 标签 × categorical/sparse 损失做 2×2 矩阵，记录哪些组合报错、哪些静默给错结果。
- E2：Dropout rate 0 / 0.2 / 0.8 三条 train/val 曲线，验证「推理态补偿」——关掉 `training=False` 路径观察 logits 尺度漂移。
- E3：`EarlyStopping(patience=3, restore_best_weights=True)` 开与关的末轮权重差异，坐实回调对最终模型的干预。
