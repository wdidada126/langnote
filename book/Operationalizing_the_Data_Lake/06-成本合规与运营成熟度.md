# 06 · 成本、合规与运营成熟度

> 🔻 降级册主题重建章（⚠️ 非原书目录），全册收束章：账单与法条如何变成日常巡检对象。
> 三态：✅=文档实链预检 200；⚠️=平台不可实测；🔧=SQLite/DuckDB 类比，**非本书平台行为**。

## 6.1 论点：湖的账单是运营仪表盘，不是财务附件

对象存储成本结构（存储费/请求费/读流量费）每一项都直接映射一个运营信号：

- 请求费异常增长 → 小文件或过度 LIST（回 [02 章](02-可运营面·存储表格式与计算栈.md) §2.2/§2.3）；
- 存储费增速>>业务数据增速 → 快照过期与孤儿清理失守（§2.3 手术没做）；
- 读流量费集中爆发 → ad-hoc 与管线未隔离（§2.4 第 1 题）。

制度含义：**成本异常检测应进值班流程**（周巡检项），费用标签（按域/按 owner 打标）
则是把账单变成治理问责数据（回 [05 章](05-元数据目录与治理的运营衔接.md) §5.1 owner 路由）。

## 6.2 合规面：留存、删除与"可证明执行"

合规要求翻译成湖运营只有三种动作：

| 要求 | 运营动作 | 证据物 |
|---|---|---|
| 留存期（retain N 年） | 生命周期策略+定期删除作业 | 删除日志（条数/时点/规则版本） |
| 被遗忘权 | 点删+下游传播 | 血缘闭包（05 章组1）证明删全了 |
| 驻留边界 | 桶区域策略+摄取白名单 | 清单报告（02 章 §2.2） |

关键认识：⚠️ 生命周期规则是异步最终一致的（02 章），因此合规删除的**验收证据**
只能是"到期时刻清单里确实没有"，而非"我设置了策略"。

## 6.3 运营成熟度五级（本册自建量表，通识拼装，无书目背书）

```
L1 能跑   有调度、手动救火
L2 可见   产出账本+新鲜度巡检 SQL（01 章组1/组3 级）
L3 有闸   DQ 规则即代码+隔离台账（04 章闭环）
L4 有约   SLO/错误预算绑定变更节奏（01 章 §1.4、03 章 §3.5）
L5 有账   成本与合规进入周巡检，血缘支撑免审删除（本章）
```

每级判据都是"查哪张表"，不是"有没有制度文件"——运营化的成色只体现在台账里。

## 6.4 🔧 本机类比（4 组，全部**非本书平台行为**）

**🔧组1 分区级成本台账**。SQLite `part_cost(tbl,part,bytes,class,accessed)` 五分区样本，
按 hot/warm/cold 单价（示例 0.023/0.0125/0.004 $/GB·月，数值仅演示）×字节聚合月费，
实测逐分区出账（样本字节过小，金额≈0，**方法>数值**）。
→ "成本按分区归属到 owner"这一动作与引擎无关，一张 GROUP BY 即制度。

**🔧组2 冷热度分档**。同一台账按访问数分档，实测 `[('hot',1),('warm',2),('ice',2)]`；
降级建议查询命中 `bronze/2026-07→warm`（访问 220 低于热档线）。
→ 转储策略的评审材料就是这张两列表；反向核对见组4。

**🔧组3 留存期执行的边界语义**。以 2 年线对四条 2025/2026 分区跑
`(julianday(now)-julianday(ds))/365>2`，实测**删=0、存=4（含 PII 行 3）**——
最老分区 2025-01-01 距基准点仅 1.75 年，线未咬合。
→ 这正是合规演示的价值：**到期判定必须可复算**，"删不动"与"忘了删"在证据上泾渭分明。

**🔧组4 压实的成本收益**。复用 [01 章](01-从建设到运营·数据湖运营化的问题域.md) 组4 素材实测：
分片 4×13,276B=53,104B → zstd 合并 32,302B，**省 39%**、文件数 4→1。
→ 维护作业的 ROI 可以用（字节节省×存储单价 + 请求数减少×请求单价）周度复核——
02 章四手术里唯一每期都该算账的就是 rewrite/compact。

## 6.5 把 05 章的验收题升一级

05 章 §5.5 四题（治理运行验收）之上，本章加三题（成熟度 L5 验收）：
5. 上周成本环比 >20% 的分区是谁的、原因标签是什么；
6. 随机抽一条"已删除"合规请求，五分钟内出示删除日志+血缘免审证明；
7. 压实作业的字节节省报表最近一期数字是多少（组4 同款，真实规模）。
七题全过者，可以不再需要"数据湖运营"这个岗位称谓——产品自己会运营自己（理想态 ⚠️）。
