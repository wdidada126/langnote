# 02 · 可运营面 · 存储、表格式与计算栈

> 🔻 降级册主题重建章（⚠️ 非原书目录）。本章回答：湖的三层栈上，运维动作各自落在哪里。
> 三态标注：✅=文档实链预检 200；⚠️=不可实测面；🔧=SQLite/DuckDB 类比，**非本书平台行为**。

## 2.1 三层栈与"运营重心"的下移

```
 计算栈   Spark/Trino/DuckDB/引擎作业  —— 运营面: 队列、并发、失败重试
 表格式   Iceberg / Delta / Hudi / Paimon —— 运营面: 快照、模式、小文件、孤儿文件   ← 重心
 存储层   S3/ADLS/OSS 对象桶            —— 运营面: 分层、生命周期、清单、请求费
```

2016–2020 的湖运营重心在计算栈（把作业跑完）；2021 之后公认下移到**表格式层**——
因为可回退（快照）、可干预（维护作业）、可观测（元数据统计）三个动作接口只有表格式层同时提供。
文档面：Iceberg 规格与维护 ✅ https://iceberg.apache.org/docs/latest/ ；
Delta 维护命令（OPTIMIZE/Z-VACUUM）✅ https://docs.delta.io/latest/index.html 。

## 2.2 存储层：桶是账本不是硬盘

对象存储给运营的三个"账单级"事实：① 请求费按**列出/读取次数**计——小文件星云首先打在
请求费上，其次才是扫描延迟；② 生命周期规则（转储/过期）是**异步最终一致**的，不能当业务删除器用；
③ 清单报告（inventory）是湖资产盘点唯一的**全量真相源**，与任何目录系统的统计核对是例行运营动作。
AWS 侧目录+脚本面可参考 Glue ✅ https://docs.aws.amazon.com/glue/latest/dg/welcome.html ；
Lake Formation 旧根路径预检 404（00 §6），本章不引用其内容。

## 2.3 表格式层：四种维护手术

| 手术 | 目的 | 触发判据（示意） | 破线风险 |
|---|---|---|---|
| rewrite/compact | 文件颗粒度恢复 | 平均文件 < 目标 MB 连续 N 天 | 低（只增快照） |
| expire snapshots | 元数据与存储回收 | 快照保留期外 | 中（回退窗口缩短） |
| delete orphan | 孤儿文件清理 | 清单 vs 元数据差集非空 | **高**（必须 dry-run 先行） |
| analyze/statistics | 计划质量 | 画像过期 | 低 |

⚠️ 各平台对四手术的命令名/默认参数不同，以 §2.1 两条 ✅ 文档为准，本册不背具体参数。

## 2.4 计算栈：运营视角只问三件事

1. **隔离**：ad-hoc 查询与管线作业是否互相饿死（资源组/队列）；
2. **节拍**：调度频率是否小于数据到齐周期（空转）或大于 SLO（破线）；
3. **写入并发**：同分区并发写是否有序合并策略（冲突解决协议，表格式层兜底与否是选型分水岭）。
DuckDB/SQLite 单机上无此三题——恰说明"运营问题密度与共享度成正比"（类比语境，见 §2.5）。

## 2.5 🔧 本机类比（4 组，全部**非本书平台行为**）

**🔧组1 事务层开销可测但本机不敏感**。SQLite 连写 3000 行，`journal_mode=DELETE` 与 `WAL`
两轮耗时均为 0.01s（噪声地板内，本机测不出差异）。诚实结论：**类比演示的是测量姿势**——
"开销归因实验"要求工作负载大于噪声，湖平台压测同理（先证负载够大，再谈归因）。

**🔧组2 copy-on-write 快照对比**。用两个 parquet 文件手工扮演 v1/v2 快照（v2 改前 50 行值），
DuckDB JOIN 对比实测变更行=50。→ 演示"快照=不可变文件集+差分读取"的最小机制；
真实表格式在此之上补的是**原子发布**（新快照指针切换）与**孤儿记账**，两者恰是运营事故来源 ⚠️。

**🔧组3 schema 演进的双向门**。SQLite 查询未登记列直接 `no such column: b`（拒读）；
`ALTER TABLE bronze ADD COLUMN b TEXT DEFAULT 'late'` 后旧行立即可读 `(1,'late')`。
→ 湖上的"read schema / write schema"之争在这个 5 行实验里两面都出现了：
引擎默认保守（拒读未知列），演进必须由**写侧登记**驱动——这正是 05 章 schema 注册的伏笔。

**🔧组4 统一目录面雏形**。DuckDB `ATTACH ':memory:' AS lake_gold` 后建跨库视图，
`information_schema`/`SHOW TABLES` 面把两"层"（parts/*.parquet 4000 行 + gold 1 行）并在一张
结果里：`[('lake_silver',4000),('lake_gold',1)]`。→ "目录=跨栈的联合视图"在单机五分钟可演示；
Unity Catalog 把它产品化的部分 ✅ https://docs.databricks.com/en/data-governance/unity-catalog/index.html 。

## 2.6 选型速判：哪层坏过决定听谁的

运营者对栈的信任来自事故史而非发布会。经验判据（通识，⚠️ 无具体厂商背书）：
表格式层必须选**维护动作有审计回执**的（每次 rewrite/expire 产出可查的 plan 文件）；
存储层必须开**清单导出**（§2.2 的真相源前提）；计算栈可换，前提是写入全部经表格式层收口。
湖仓两册盘上读物对此展开更深：
[Data_Lakehouse_in_Action](../Data_Lakehouse_in_Action/00-总览与阅读地图.md)、
[Practical_Lakehouse_Architecture](../Practical_Lakehouse_Architecture/00-总览与阅读地图.md)。

## 2.7 运维动作的归属表：自己做、托管做、不做

三层栈的可运营面并非都该由数据团队持有。归属判据一句话：**动作有审计回执且回滚代价可控→自己做；
参数空间大且故障史丰富→交给托管面；纯省钱类→排进 [06 章](06-成本合规与运营成熟度.md) 季审而不是日常**。

| 动作 | 建议归属 | 理由 |
|---|---|---|
| 小文件压实窗口设定 | 自己做 | 与 SLO 强耦合（03 章节拍） |
| 快照保留期 | 自己做（并登记在 05 章） | 决定回退窗口=业务承诺 |
| 孤儿文件删除执行 | 托管/双人复核 | 不可回滚手术，必须 dry-run+审批 |
| 存储转储生命周期 | 托管+周核对 | 异步最终一致，核对清单即可 |
| 统计信息刷新 | 自己做（低频） | 计划质量归因需要自家基线 |
| 桶策略变更 | 合规共管 | 06 章驻留边界联动 |

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| 可运营面 | operable surface | 三层栈上可观测/可干预/可回退的接口总和 |
| 表格式 | table format | 在对象存储上伪造表语义的元数据协议 |
| 快照过期 | snapshot expiration | 缩短回退窗口换存储回收的手术 |
| 孤儿文件 | orphan files | 不被任何有效快照引用的文件 |
| copy-on-write | 写时复制 | 改一行=重写整文件换不可变读 |
| 清单报告 | bucket inventory | 对象存储侧的全量真相源 |
| 生命周期规则 | lifecycle rule | 异步的转储/过期策略，非业务删除器 |
| 读/写模式 | read/write schema | 演进之争的两个方向 |
| 统一目录 | unified catalog | 跨栈联合视图即控制面 |
| 维护节拍 | maintenance cadence | 手术频率与触发判据的制度化 |

## 最新演进与工业实践

- 2023–2026 生态主线是**表格式整合战**：Iceberg 成为跨厂商默认元数据面的趋势明显，
  Delta 亦提供面向 Iceberg 元数据兼容的转换层（UniForm 方向，⚠️ 以各家 ✅ 文档现状为准）。
- 云厂商出现"托管表格式+桶即表"产品化（对象存储层原生内建 Iceberg 维护面 ⚠️ 演进性表述），
  本册 §2.3 的"四手术"有从用户职责下沉为服务商职责的趋势——运营化对象不变，责任边界移动。
- 目录统一面（Unity Catalog 类，✅ §2.5 组4 链接）从单一厂商特性向开放 REST catalog 协议演进，
  与 [The_Enterprise_Data_Catalog_2e](../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md) 的
  "目录是控制面"论纲在 2026 年的工业实践里互为注脚。
- 给读者的核对建议：凡本册标 ⚠️ 的演进句，都应在决策前用当期文档重验——降级册的诚实纪律。
