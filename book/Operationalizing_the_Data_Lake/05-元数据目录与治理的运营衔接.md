## 5.1 论题：目录即运行时（catalog as runtime）

治理文档回答"应该怎样"，目录回答"现在怎样"。运营化把治理压进目录的四个运行时对象：

| 对象 | 治理语义 | 运营语义 |
|---|---|---|
| 表登记（含 owner） | 数据域归属 | 告警路由的终点 |
| 模式注册（schema） | 契约 | 写侧闸门的判据来源 |
| 血缘边（lineage） | 影响范围 | 回填/删除的爆炸半径计算器 |
| 标签（PII/等级） | 政策对象 | 查询改写的输入（脱敏视图） |

无 owner 的表=无值班表的医院。文档面：UC 以目录为策略载体 ✅
https://docs.databricks.com/en/data-governance/unity-catalog/index.html ；
Glue Catalog 面 ✅ https://docs.aws.amazon.com/glue/latest/dg/welcome.html 。

## 5.3 血缘的运营三分法

1. **作业血缘**（表→表经作业）：回填计划器，03 章拓扑分层的输入；
2. **列血缘**（口径追溯）：报表事故定责与"改一列影响哪些指标"的静态回答；
3. **文件血缘**（快照→文件清单）：02/04 章孤儿清理的合法性来源。
多数团队只有 1、缺 2、几乎没有 3——而湖的运营事故恰恰三次都需要。

三类血缘的采集成本序是 3 < 1 < 2（文件血缘最便宜：它是表格式元数据的免费副产品；
列血缘最贵：需要引擎/编译器配合 ⚠️）。运营上应从"最便宜的"开始补，
而非从"演示最好看的"（列血缘图谱 UI）开始——这是目录项目烂尾的头号成因（通识判断，⚠️ 无书目背书）。

## 5.4 🔧 本机类比（4 组，全部**非本书平台行为**）

**🔧组1 血缘闭包一条 SQL**。SQLite 边表 `edge(a,b)` 四边
（bronze→silver→gold_a、bronze→gold_b→report），递归 CTE 自 report 上溯，
实测上游闭包=`[bronze, gold_b, silver...]`（输出样例含 bronze/gold_b 全链节点）。
→ "删除 bronze/2026-01 会影响谁"这类问题的最小可执行形态；爆炸半径=闭包计数。

**🔧组2 标签驱动策略**。表 `tag(tbl,col,tag)` 实测分布
`[('FINANCE',1),('PII',1),('RAW',1)]`，按 `tag='PII'` 查出被屏蔽列
`fact_orders.order_id` 并生成拒绝式视图（`SELECT ... WHERE 0` 演示策略生效）。
→ "政策即查询改写"的教学模型；UC/Ranger 类产品是其工业体（⚠️ 细节以各家文档为准）。

**🔧组3 schema 注册与来样兼容**。`schema_ver(bronze_click,1,'a,b')` 为登记契约，
来样 `a,b,c` 与登记表精确比对，实测**不匹配→拒收**（allowed=0）。
→ 对位 §5.1 第二行：演进不是读侧宽容问题，而是**登记先行**的写侧流程（02 章组3 的实验面推论）。

**🔧组4 目录自动发现**。DuckDB `glob` 扫 parts/ 目录，实测登记进 `catalog` 表：
`[('parts', 4 files, 4000 rows)]`。→ 冷启动编目（先盘后治）的十分钟路径；
与 §5.2 目录专册的"手工编目优先于自动发现"主张构成张力——运营立场：**自动发现打底、
人工认证升格**，两级台账缺一不可。

## 5.5 治理运营化的验收题（抄送给自己）

1. 随机指一张表，5 分钟内报出 owner、契约版本、上游闭包、最近一次破线；
2. 指一列，说出它被哪些政策标签覆盖、以何种机制生效；
3. 宣布删除一个 18 个月前的分区，血缘+清单能否给出**免审名单**（影响=0 证明）；
4. 目录不可用时，写闸门是否仍能独立运行（控制面与数据面的降级边界 ⚠️ 常考常新）。
四题过三，治理才算"在运行"，不在"墙上"。

## 最新演进与工业实践

- 2023–2026 目录面的开放化：REST catalog 协议与跨引擎元数据互认成为生态主线 ⚠️（表述保守），
  与 UC 线（✅ §5.1）形成"厂商一体化 vs 协议开放"的长期张力；
- 血缘采集从"作业日志推断"向"引擎原子上报"演进 ⚠️，§5.3 的文件血缘（长期缺位项）
  随表格式元数据规范开放而首次具备低成本实现路径；
- "治理即代码"（policy-as-code）在合规密集行业进入采购需求 ⚠️；本册 §5.4 组2 的教学模型
  仍是其可演示的最小核——先让策略成为一次查询，再让它成为一次部署；
- 与治理线诸册的分工再述：治理线回答**为什么与由谁**，本册回答**何时跑与坏了怎么办**，
  目录是两线唯一需要共享的表。
