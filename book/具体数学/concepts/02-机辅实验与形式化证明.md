# 专篇：机辅实验与形式化证明

> **一句话**：Knuth 在本书里反复做的不是「证明」，而是「**先算一堆值，猜出一个式子，再想办法证明它**」——这条链路在 2020 年代被拆成了两半：机器负责前半段（符号计算），形式化助手负责后半段（机器证明）。

---

## 本章地图

| 阶段 | 1990 年代的做法 | 2020 年代的做法 | 责任划分 |
| --- | --- | --- | --- |
| 观察 | 用 Mathematica 手算小值表 | `sympy` 生成小值表 + OEIS 匹配 | 机器 |
| 猜测 | 人凭直觉猜闭式 | `sympy` 的 ` summation`、`hyper` 反推候选 | 机器为主 |
| 验证 | 数值比对前 n 项 | 高精度 `mpmath` 比到 10³ 位 | 机器 |
| **证明** | 「易证」四个字 | Zeilberger 的 WZ 方法 / Lean 的 `induction` | **人为主** |
| 分发 | 印刷成书 | 存成脚本，可重跑 | 机器 |

## 核心精讲

> **教学示意，不编译、不运行，也不参与构建。**

### Knuth 的工作流：算 → 猜 → 证

```python
from fractions import Fraction

# 第一步：算。用精确分数，绝不用 float
def observe(n):
    return [Fraction(sum(Fraction(1, k) for k in range(1, m + 1)), 1)
            for m in range(1, n + 1)]

# 第二步：猜。看差分，找模式（有限差分表是全书最常用的「猜」工具）
def differences(seq):
    return [b - a for a, b in zip(seq, seq[1:])]

def diff_table(seq):
    rows, cur = [], seq
    while len(set(cur)) > 1:
        rows.append(cur)
        cur = differences(cur)
    return rows

# 第三步：证。这一步机器只能给「结构」，给不了「洞察」
```

### 形式化：把归纳变成一条命令

```lean
-- 形式化侧（示意，不编译不运行）：把第 1 章的河内塔闭式写进定理
theorem towers_of_hanoi (n : Nat) :
  tower_moves n = 2^(n + 1) - 1 := by
  induction n with
  | zero => rfl
  | succ k ih => simp [tower_moves, ih]
```

> 关键观察：**1990 年代的「易证」在 2020 年代可以是一条 tactic**。但书里那些真正有洞察的证明（如 Apéry 对 `ζ(3)` 的证明、约瑟夫问题的分段解）**至今无法被 tactic 替代**——机器擅长机械步骤，不擅长「你为什么想到这一步」。

## 版本演进

| 阶段 | 演进要点 |
| --- | --- |
| **1977–** | Knuth 用 TeX/METAFONT 并鼓励读者「抓错」，确立了「机辅 + 可追溯」的写作方式 |
| **1976** | Gosper 的 `Hacklang` 决策过程：不定和式的自动判定 |
| **1993** | Zeilberger 的 WZ 方法：超几何恒等式的自动证明 |
| **1996** | 《A = B》：把「机器证明恒等式」写成方法论 |
| **1994 / 1998** | 具体数学第 2 版与首次 errata；作者持续发布勘误，是机辅写作传统的延续 |
| **2000s** | SageMath 与 ALEPH 的开源化，「用计算机做实验数学」变成常规操作 |
| **2021–** | AlphaProof / AlphaGeometry 等：大模型 + 形式化助手；Lean 的数学库沉淀速度爆炸 |
| **2023–** | 形式化证明进入竞赛与工业界（如压缩算法、密码协议的形式化验证进入主流供应链流程） |
| **2026** | 「**猜 → 证**」的分工成为默认：符号计算负责「可能是真的」，形式化负责「一定是真的」 |

## 近年研究与工业界开源实践（2015–2026）

**趋势**：2020 年代最重要的变化不是「机器算得更快」，而是「**机器进入了证明环节**」。形式化验证从航空航天与密码学，扩展到**编译器、区块链、以及大型软件系统的核心不变量**；而符号计算则退居「给人提供候选」的位置。

| 仓库 | star | 说明 |

| `sympy/sympy` | **14967★** | 机辅实验的主力：算小值表、反推闭式、验证恒等式 |
| `mpmath/mpmath` | **1212★** | 高精度验证：对到 10³ 位仍成立才敢猜 |
| `numpy/numpy` | **32828★** | 大规模数值实验与蒙特卡洛模式发现 |
| `scipy/scipy` | **15038★** | 数值方法与优化，为符号结果做数值兜底 |

## 常见误区与本书需修正之处

| 问题 | 说明 |
| --- | --- |
| 🔧 **本书的「用机器算着玩」只做到第一步** | 作者本人明确鼓励实验，但全书没有把「机器验证」系统化为一节方法论；2020 年代这应当成为独立方法 |
| 🔧 **「易证」式的跳过在形式化时代不可接受** | 第 5、6 章多处出现「易证」，在 Lean 里是一个必须写出来的 tactic；这构成了 1994 年写法与 2026 年要求之间的代差 |
| **把数值验证当成证明** | 前 n 项一致 ≈ 100% 错的概率很低，但**不是证明**；本书偶尔用「对到 n=10^4」来暗示正确性，读者不应照抄这个习惯 |
| 🔧 **形式化代价远高于书里的想象** | 任何形式化一条引理的成本远高于手算；工业界只在关键不变量上做，本书未讨论这个取舍 |
| 🔧 **AI 辅助形式化是 2020 年代最大的增量，本书完全没有** | 从 AlphaProof 到各类「自动形式化」工具，把「把证明翻译成 tactic」这件苦活大幅压缩；这是本书时代背景之外的内容 |
| **工具选型随年份漂移** | 书里用 Mathematica/MIX/Metafont，今天用 SymPy/Lean；**方法论（算-猜-证）比工具寿命长得多**——这才是值得从本书带走的东西 |
