### ⚠️ 任务口径纠错（必须写清楚的一条）

委托任务给的署名是 "**Sathis de Silva & Danilledo Ramnarine, Apress/Springer 2023**"。逐项核查结果：

- Crossref（书目 DOI 库）按标题、按"作者+出版社 Apress"多路检索，**均无**这两位作者的湖仓专著记录；
  Apress 2022 年同主题书是另一本《The Azure Data Lakehouse Toolkit》（Ron L'Esteve，ISBN 9781484282328/335，✅ Crossref 实抓）。
- 与"de Silva / Ramnarine"相邻的公开检索命中全部是无关文献（医学、音乐等）。
- 而**书名 + ISBN 9781098153007 + O'Reilly 书页 URL 三者一致指向 Thalpati 的这本书**。

结论：任务书目的"作者/出版社/年份"与"书名/ISBN/书页"属于**两本（其实是一本）书的张冠李戴**。
本目录按可完全核实的 **Thalpati / O'Reilly** 口径建档；"de Silva & Ramnarine / Apress 2023"记录为
**❌ 查证不存在（按此口径）**，留此备忘，不作为本目录任何文件的依据。

## 五、逐章一句话结论速览（评审速览版）

| 章 | 一句话结论 |
| --- | --- |
| 01 | 湖仓是"外置的表语义"三层结构，平台视角只管第 2–3 层的组合方式 |
| 02 | 每代架构都是一笔成本转移；可比口径只有全栈 TCO，湖仓优势在负载组合而非单价 |
| 03 | 把对象存储当"不可变 + 按请求计费"的介质来经营，运维税公式背下来 |
| 04 | 表当前状态必须唯一权威；REST catalog 收敛的是接口，不收敛策略归属 |
| 05 | 存算分离有 L1/L2/L3 三档；每加一个引擎就加一份目录/权限/缓存税 |
| 06 | 治理外置到目录层才跨引擎生效；删除权在湖仓是四次物理传播，不是 DELETE 一条语句 |
| 07 | 用例→SLA→参数→分层→格式，顺序反了就是为技术而技术 |
| 08 | 落地形态按"谁拥有目录"分五型；事故四件套全是纪律问题而非格式缺陷 |

## 九、三条硬结论（先给答案，再读章）

1. **本书的不可替代性在"平台中道"**：格式书（Delta/Hudi/Iceberg/Paimon 各姊妹目录）教你机制，
   Inmon 派（The_Data_Lakehouse）教你理论，本书教你**在预算、人力、合规约束下把零件装起来并能退出**——
   04/07/08 三章是这一立场最纯的部分。
2. **"目录是单点"是全书最可带走的心智模型**：存储可复制、计算可替换，唯"表当前状态的权威指针"
   不可多头（04 章）；一切事故复盘几乎都能回溯到目录纪律（08.2）。
3. **读本书必须自带 2024–2026 时间补丁**：成书于 Iceberg V3 定稿、Tabular 被收购、Polaris/UC
   开源竞赛爆发之前夜；各章末「最新演进与工业实践」即本目录代打的时间补丁，全部来源经可达性核验。
