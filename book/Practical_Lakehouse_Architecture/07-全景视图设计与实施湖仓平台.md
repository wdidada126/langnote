## 7.1 设计法：用例 → SLA → 分层，顺序不可反

```
第1步 用例清单：BI 报表 / 自助分析 / 特征工程 / 内部 agent 检索 / CDC 镜像 / 合规导出
第2步 每用例三数：新鲜度(分钟?小时?) × 并发(5? 500?) × 扫描模式(点查? 全表聚合?)
第3步 反推架构参数：
      新鲜度 → 提交频率 → compaction 税(→03章) → 谁付(→02章TCO)
      并发   → 计算面选型(→05章) 与结果缓存层
      扫描   → 分区/聚类策略与统计配置(→03章)
第4步 分层承诺：bronze(原始+不变) / silver(清洗+契约) / gold(语义+SLA)
第5步 才轮到格式与厂商选型(→ Engineering 12章评分卡)
```

常见反顺序（先定 Databricks/Snowflake 再找用例）是平台烂尾第一因。

## 7.4 迁移六步法（从数仓/Hadoop 湖迁入）

1. **圈地**：按域选首个试点（高价值 + 低政治），不做全量平移；
2. **格式先行、引擎后置**：先让数据以开放表格式可被第二引擎读出，再谈换引擎
   （对照：[../Engineering_Lakehouses_with_Open_Table_Formats/12-格式选型与迁移.md](../Engineering_Lakehouses_with_Open_Table_Formats/12-格式选型与迁移.md)）；
3. **双写与对账**：迁移期新旧并行，对账作业（行数+校验和+抽样语义）是验收唯一语言；
4. **目录切换演练**：把"当前指针"的回切作为上线前必做军演（→ 04 章单点论）；
5. **退役门**：旧平台读流量连续 N 周为零才删，删前做合规删除四份账（→ 06.4）；
6. **回迁权**：全程保证能从新平台导出为中立格式（防止迁移变成再锁定）。

## 7.7 90 天实施日历（最小可信平台版，对应 7.1–7.4 的压缩交付）

```
D0–D15  用例圈地与三数采集（7.1 第1–2步）；选定试点域：高价值低政治
D10–D25 目录与格式决策会：按 04.6 问答 + Engineering 12 评分卡出选型纪要（含退出条款）
D20–D40 入湖带打通：一条 CDC 管道端到端（bronze 表可查，含对账作业雏形）
D35–D55 加工带：契约三件套（schema/质量门/新鲜度）上线到 silver；维护作业有 owner（03.7）
D50–D70 服务带：第二个引擎经目录独立读出同一张表（7.4 第2步的验收动作）
D65–D80 控制带最小集：血缘自动采集 + 成本标签 + 表维护积压看板（7.5 KPI 前四项）
D75–D90 演练日：指针回切 + 合规删除 runbook 走一遍（04.8 / 06.8），出事故剧本库存
```

纪律：日历允许整体右移，不允许合并删除演练日——它是一次性验证"平台是否真的拥有退出权"的时刻。

## 7.8 实施现场 FAQ（从评审会议室抄来的真问题）

**Q：老板要求三个月"全量迁移完成"，日历只覆盖一个试点域，怎么办？**
A：把 7.4 第 1 步的"圈地"谈判前置为项目第一交付物。全量平移在湖仓语境里= 把旧平台的债
按表逐一格式化重组，周期是试点的 N 倍而非 1 倍；用试点域的三数对账结果去重设期望值。

**Q：数据产品团队说契约太重，先跑起来再补？**
A：允许降"门槛"不许降"接口"——质量门可以设松（告警不阻断），但 schema 与新鲜度承诺必须
第一天就写进表属性；可后补的是执法力度，不可后补的是承诺记录（无记录的承诺补写即造假）。

**Q：双写对账差异一直收敛不到零？**
A：停功能开发查三处：时区/精度归一化、乱序更新的幂等性、软删除语义映射。90% 的差异
藏在这三处，与湖仓无关——这是迁移项目最费人力也最不像湖仓问题的部分（对照：
[../Apache_Hudi_Definitive_Guide/10-构建端到端的湖仓解决方案.md](../Apache_Hudi_Definitive_Guide/10-构建端到端的湖仓解决方案.md) 的验证节）。

## 核心概念速览（中英对照）

- **用例驱动设计** — workload-driven design：从负载三数反推架构参数，反对先选厂商。
- **新鲜度** — freshness：用例到数据的时差，决定提交频率与全链运维税。
- **数据契约** — data contract：层间交接的 schema+质量门+SLA 三件套。
- **双写对账** — dual-run reconciliation：迁移期新旧并行的唯一验收手段。
- **指针回切** — pointer rollback drill：以目录指针回切为内容的上线前军演。
- **退役门** — decommission gate：旧平台流量清零后才物理删除的纪律。
- **回迁权** — exit right：全程可导出中立格式，防止迁移即再锁定。
- **控制带** — control plane band：调度/血缘/成本/准入等横切能力的统称，常缺席架构图。
- **过渡视图** — transitional view：表合并/拆分期给下游的稳定假面。
- **维护积压** — maintenance backlog：最老快照年龄等表维护欠账指标。
- **平台/产品分界** — platform vs data product：目录与税归平台，语义与契约归产品。
