## 2. 交互与开发工具（⚠️ 转述）

- SQL*Plus：脚本化操作基座（变量/替换符/SET 调参/执行计划展形）⚠️；SQL*Plus 与 SQL Developer 的定位差=终端 vs IDE。
- SQL Developer：免费图形端，含数据建模/迁移工作台 ⚠️；导游册时代它刚接棒 Oracle 的开发者门户叙事。
- APEX（Application Express）：浏览器端低代码，成书年代已入版图 ⚠️——产品全景移交 [09 章](09-高可用集群与Oracle产品版图.md)。
- 🔧 对照（非 Oracle）：sqlite3 CLI 的"点命令全家桶"（.dump/.backup/.schema）一个二进制里塞下本章三个抽屉——嵌入式哲学的工具观：工具=文件操作；Oracle 的工具观：工具=对实例的服务调用（⚠️）。

## 3. 数据搬运线（⚠️ 转述）

- SQL*Loader：控制文件描述"字符流→表"映射；直接路径 vs 常规路径（绕过/经过 buffer cache）⚠️——接 [03 章](03-实例内存与后台进程.md) 分区图。
- 外部表：把"装载"反转为"查询文件当表"⚠️——仓库装载窗口的主力（[08 章](08-仓库实施分区物化视图与装载.md) 接口）。
- 数据泵：master 进程+并行 worker、目录对象(DIRECTORY)+dumpfile 形态、METADATA_ONLY 与重映射 ⚠️——"逻辑导出"与"物理搬运"的中间物。
- Transportable tablespace：跨平台搬数据文件+字典侧打包 ⚠️——直接复用 [02 章](02-物理存储结构与表空间.md) 分层图，导游册的"结构即工具"示范。

## 4. 备份恢复线（⚠️ 转述；纵深在 #66/#42，登记不链/实链见互链节）

- RMAN：目标库通过服务器会话执行；备份集 vs 镜像拷贝、保留策略、增量+归档的 PITR（point-in-time recovery）⚠️；控制文件/SPFILE 备份意识 ⚠️。
- 恢复类型分界（导游册必画）：实例恢复（SMON 自动，redo 前滚+undo 回滚，[03 章](03-实例内存与后台进程.md)）vs 介质恢复（RMAN RESTORE+RECOVER，人工触发）⚠️。
- 🔧 T15 把"实例恢复"压缩成可测形态：子进程事务中途 `os._exit(9)` 留热日志 → 主连接重开实测读到旧行（未提交被回滚）、热日志文件仍驻留至下一写者清理——"恢复者惰性开工"的最小演示（非 Oracle）。
- 🔧 T9 在线备份类比：`Connection.backup()` 实测整库热复制 40960→40960 字节、`PRAGMA integrity_check` 返回 ok——"边服务边取一致性副本"的最小形态；RMAN 的多步（备份集/归档/校验/保留策略）⚠️ 是其企业化展开。

## 5b. 🔧 最小复现代码（非 Oracle）

```python
import sqlite3, duckdb, os
src = sqlite3.connect("g1.db"); dst = sqlite3.connect("g1_backup.db")
src.backup(dst); dst.close()                    # 🔧 T9 在线整库热复制
print(sqlite3.connect("g1_backup.db")
      .execute("PRAGMA integrity_check").fetchone())  # 🔧 ('ok',)
d = duckdb.connect()
d.execute("SELECT count(*), SUM(amt) FROM read_csv_auto('sales.csv')")
d.execute("COPY (...) TO 'out.parquet' (FORMAT PARQUET)")  # 🔧 T10 装载三合一
with open("dump.sql", "w") as f:                # 🔧 逻辑导出（expdp 意象）
    for line in src.iterdump(): f.write(line + "\n")   # 🔧 实测 2005 行文本
```

- 读码要点 1：backup+integrity_check = "备份的备份意识"（第三问）最小实现。
- 读码要点 2：iterdump 是纯逻辑文本，对应"字典定义+数据 INSERT"双段——与数据泵"元数据/数据分离控制"（METADATA_ONLY）⚠️ 同一设计轴。
- 读码要点 3：read_csv→COPY→Parquet 三连是 SQL*Loader+外部表+导出的一次覆盖；Oracle 侧等价物需要三个工具（⚠️），开源侧一个引擎——工具谱系密度差即本章量化教材。

## 6. 工具选型的导游册心法（本目录解读）

- 按"数据移动方向"选工具：入湖/入仓（Loader/外部表）→ 库内搬（CTAS/数据泵）→ 出门（导出/审计）——先画箭头再翻工具箱。
- 按"是否经 SQL 层"判代价：直接路径类绕过 buffer cache（⚠️），🔧 侧同构物是 DuckDB `COPY` 直写：本次实测 CSV→Parquet 361 字节秒完成，全程无共享缓冲概念。

## 核心概念速览（中英对照）

- **SQL*Plus** — 脚本化命令行基座 ⚠️。
- **SQL Developer** — 免费图形 IDE ⚠️。
- **APEX** — Application Express：浏览器端低代码 ⚠️。
- **SQL*Loader** — 字符流装载器；直接/常规路径 ⚠️。
- **外部表** — External Table：文件当表查询 ⚠️。
- **数据泵** — Data Pump (expdp/impdp)：master+并行 worker 的逻辑搬移 ⚠️。
- **传输表空间** — Transportable Tablespace：跨平台文件级搬结构 ⚠️。
- **RMAN** — 备份恢复主工具：备份集/镜像/PITR ⚠️。
- **介质恢复** — Media Recovery：RESTORE+RECOVER 的人工线 ⚠️。
- **DBCA** — 数据库配置助手 ⚠️。
- **Connection.backup()** — 🔧 SQLite 在线整库复制（实测 40960B 往返）。
- **点命令** — sqlite3 CLI 工具集：🔧 一进程三抽屉的极简对照。
- **integrity_check** — 🔧 最小备份验证（实测返回 ok）。
- **直接路径** — Direct Path：绕开 SQL/缓冲层的装载通道 ⚠️。
- **master 进程** — Data Pump 的指挥进程，worker 归其调度 ⚠️。
- **ADR** — Automatic Diagnostic Repository：故障工件仓库 ⚠️。
- **VACUUM** — 🔧 SQLite 压缩重整：[02 章](02-物理存储结构与表空间.md) 高水位话题的开源逆操作。
- **Parquet** — 列式文件格式：🔧 DuckDB COPY 实测落点（361B，见 §5b）。

## 最新演进与工业实践

- **Oracle 侧**：数据泵持续为逻辑迁移主栈（跨版本/字符集升级场景 ⚠️ 转述）；EM 叙事让位于 Cloud Control→OCI 控制台/CLI+Terraform 的舰队管理 ⚠️ 转述；RMAN 之外 SBT/云备份通道成为默认选项 ⚠️。
- **开源对照（🔧 现行）**：SQLite 工具面 = CLI 点命令+backup API+`VACUUM`；DuckDB `COPY`/`read_csv_auto` 实测把"装载+导出+格式转换"三合一（本次 CSV→Parquet 361B），湖格式读写是其原生-extension 生态 ⚠️。
- **DBT/工作流接管**：ETL 编排（Airflow/dbt）事实上接管了本书"OWB/装载工具"抽屉的多数场景；装载的"工具问题"变成"编排问题" ⚠️ 类比，本系列仓线各册承接。
- **备份即代码**：快照+对象存储生命周期策略使 RMAN 式"保留策略"话题平移为 bucket policy（云数据常见）⚠️ 转述；🔧 T9 的"文件级副本+校验"仍是理解 RPO/RTO 的最小手感。
