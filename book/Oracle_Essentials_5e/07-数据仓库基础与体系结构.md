> 章名与章号为 ⚠️ 主题重构（[00 §二降级声明](00-总览与阅读地图.md)）。Oracle 有数仓血统（V7 起并行查询/分区/物化视图是招牌），导游册必留仓库篇章。Oracle 侧一律 ⚠️ 转述；🔧 为 SQLite/DuckDB 实测，非 Oracle。

## 1. DSS 与 OLTP 的分裂（⚠️ 转述）

- 两种负载谱系：OLTP=高频短事务/规范化模式/并发密集；DSS=低频重查询/反规范化模式/吞吐密集——导游册的经典双列表。
- 度量差异：OLTP 看 TPS/响应时间；DSS 看**扫描吞吐与查询墙钟**——[02 章](02-物理存储结构与表空间.md) 的块/多块读在此换成第二套算术 ⚠️（成本模型纵深在 [#23 CBOF/02-全表扫描.md](../Cost_Based_Oracle_Fundamentals/02-全表扫描.md)）。
- 数据仓库定义三关键词（Inmon 式口径，⚠️ 转述）：面向主题、集成、时变、非易失四特征常被导游册引用；Kimball 维度建模为其对台版本。
- 决策支持谱系：报表→即席查询→OLAP→数据挖掘；本章管前两个+OLAP 概念，后段移交 #74 主题域（登记不链）。

## 2. 维度建模：星型与雪花（⚠️ 转述 + 🔧）

- 事实表=业务事件+外键+可加度量；维表=分析语境属性；星型=事实居中直连各维；雪花=维再规范化（连接层数↑、扫描局部性↓）⚠️。
- 可加/半可加/不可加度量决定聚合下推自由度（比率类不可加是经典陷阱）⚠️。
- 缓慢变化维 SCD1/2/3：导游册级点到；Type-2 代理键机制在 [08 章](08-仓库实施分区物化视图与装载.md) 装载线复用。
- 🔧 **T11a · 星型落地与聚合**（非 Oracle）：本次实测在 SQLite 建 dim_store(100 行)+fact_sales(30 万行)，`SELECT SUM(amt) FROM fact_sales JOIN dim_store ON store_id WHERE region='R1'` 耗时 155.2ms，结果 13499865000.0——星型本体在两开源引擎零门槛可建，"仓库结构"不是专有资产，**专有资产是扫描吞吐工程**（⚠️：并行/多块读/分区裁剪）。
- 🔧 **T12a · 同数据换引擎**（非 Oracle）：DuckDB 经 `sqlite_attach` 挂同一 SQLite 文件跑同查询实测 31.2ms（5 倍级差）——本章教学点：查询形态相同、执行引擎不同，正是"仓库=负载决定架构"论断的显微镜。

## 2b. 🔧 星型落地最小复现（非 Oracle；数字=本次实测）

```python
import sqlite3
s = sqlite3.connect("g5.db")
s.execute("CREATE TABLE dim_store(store_id INTEGER, region TEXT)")
s.execute("CREATE TABLE fact_sales(store_id INTEGER, day INTEGER, amt REAL)")
# 🔧 dim_store 100 行 / fact_sales 300,000 行装载后：
s.execute("SELECT SUM(amt) FROM fact_sales f JOIN dim_store d"
          " ON f.store_id=d.store_id WHERE d.region='R1'")
# 🔧 实测 155.2ms -> (13499865000.0,)
import duckdb
d2 = duckdb.connect(); d2.execute("CALL sqlite_attach('g5.db')")
d2.execute("SELECT d.region, SUM(f.amt) FROM fact_sales f"
           " JOIN dim_store d USING(store_id) GROUP BY 1")
# 🔧 实测 31.2ms（同一数据、同一形态、换执行引擎）
```

- 三条带走观察：① 星型是**建模约定**不是引擎特性；② 5 倍级差来自列存+向量化执行，不来自模式本身；③ 事实表列（day/store_id）低基数化后，[05 章](05-数据字典与动态性能视图.md) T7 的"贫瘠统计"仍能支撑合理解释计划——统计饥饿≠计划失控，这是 Oracle 仓库叙事里常被夸大的落差 ⚠️。

## 2c. SCD 速记表（⚠️ 转述 + 🔧 落地形态）

| 型 | 策略 | 🔧 开源最小形 | 仓库后果 |
|---|---|---|---|
| SCD1 | 覆盖旧值 | UPDATE 维表 | 历史无痕 |
| SCD2 | 新增版本行+代理键 | INSERT 新行+valid 区间 | 时点归因可用 |
| SCD3 | 增列存前值 | ALTER 加列 | 仅一步历史 |
- 导游册义务：解释"为什么事实表要存代理键而非自然键"——SCD2 的时点归因唯一解 ⚠️；🔧 侧 SQLite 无内建代理键机制，需手工维护 version 列（本表第三列即最小协议）。

## 3. OLAP 概念层（⚠️ 转述）

- 立方体(cube)与聚合格：度量×维子集的组合空间；物化哪些格子=存储/刷新/加速的三角权衡——该权衡在 [08 章](08-仓库实施分区物化视图与装载.md) 落为 MV 设计。
- 上钻/下钻/旋转（roll-up/drill-down/pivot）为分析动作词汇表 ⚠️；SQL 侧对应 GROUP BY 族/ROLLUP/CUBE/PIVOT ⚠️。
- Oracle 侧产品词：OLAP 选件/CONVEX 血统→Cube-Organized Materialized Views ⚠️（成书年代话题，现状 ⚠️ 多数被分区+表函数替代）。
- 🔧 词汇对照（非 Oracle）：DuckDB 原生支持 `GROUP BY ROLLUP`/`CUBE` 与 PIVOT/UNPIVOT（SQL 标准分析扩展族）——本章动作词汇在开源侧有直接对应物；SQLite 仅部分（聚合子集+视图手搓）。

## 4. 仓库体系结构版图（⚠️ 转述）

- 数据流主干：源系统→抽取(ETL 的 E)→清洗/一致性(T)→装载(L)→仓库(当前值+历史)→集市(部门切片)→报表/OLAP 前端 ⚠️；08 章承接 T/L 细节。
- 两种建仓路线（导游册保留的史学视角）：Inmon 自下而上（仓库先于集市）vs Kimball 自上而下（维度总线驱动集市）⚠️；现代湖仓被指为第三条路 ⚠️（本目录类比，非原书）。
- 元数据角色：技术元数据（[05 章](05-数据字典与动态性能视图.md) 的字典）+业务元数据（目录/血缘）——两线在治理册分头展开，本章登记接口。
- 单一数据视图(single version of truth)口号与其工程代价（口径漂移、迟到维、代理键断层）⚠️ 转述级。

## 核心概念速览（中英对照）

- **DSS** — Decision Support System：面向分析决策的负载族统称 ⚠️。
- **事实表/维表** — Fact/Dimension Table：事件与语境，星型的两极。
- **星型模式** — Star Schema：事实居中直连各维 ⚠️（🔧 已落地演示）。
- **雪花模式** — Snowflake Schema：维的规范化延长 ⚠️。
- **可加性** — Additivity：度量能否跨维聚合的安全属性。
- **缓慢变化维** — SCD：维属性随时间变异的记录策略 ⚠️。
- **OLAP 立方体** — Cube：度量×维子集的聚合空间 ⚠️。
- **上钻/下钻** — Roll-up/Drill-down：聚合格子的行走方向。
- **数据集市** — Data Mart：仓库的部门切片 ⚠️。
- **单一数据视图** — Single Version of Truth：仓库的口号与债务 ⚠️。
- **一致性维度** — Conformed Dimension：跨集市共享的维，Kimball 总线节点 ⚠️。
- **退化维** — Degenerate Dimension：无独立维表、内嵌事实表的维度（订单号类）⚠️。
- **代理键** — Surrogate Key：维表时点身份的技术主键 ⚠️（🔧 需手工协议）。
- **维度建模** — Dimensional Modeling：Kimball 方法名 ⚠️。
- **位图索引** — Bitmap Index：低基数 DW 列的专有索引形态（⚠️，深论在 CBOF/08）。
- **ETL** — Extract/Transform/Load：仓库供给链的三段工序名 ⚠️。
- **Bus Matrix** — 总线矩阵：Kimball 集市×维度的一致性规划表 ⚠️。
- **GROUP BY ROLLUP/CUBE** — 聚合扩展族：⚠️ Oracle 与 🔧 DuckDB 双侧可写的集合语法。

## 最新演进与工业实践

- **Oracle 侧**：In-Memory Column Store（12c 起）把"仓库形态"塞进实例内存列存区 ⚠️ 转述，构成导游册"行存/列存合流"的最佳当代注脚；Oracle 自有 OWB 退场、装载工具让位第三方 ⚠️。
- **范式迁移**：湖仓（Delta/Iceberg/Hudi）+ 云仓（Snowflake/BigQuery）事实上接管了"仓库体系结构"教科书版图；本章的星型/SCD/立方体词汇在 dbt 语义层获得第二春 ⚠️ 类比（本系列湖仓/dbt 册在盘）。
- **开源对照（🔧 现行）**：DuckDB 以单机进程内列存直接跑通星型+ROLLUP/CUBE 全词汇（本次实测挂 SQLite 源 31.2ms 聚合），使"仓库=集群"的旧等式在中小体量彻底失效——导游册该章的历史使命变成"讲清负载决定架构"这条元原则。
- **HTAP 回响**：OLTP/DSS 分裂论在 2020 年代被复制+列存镜像（如各引擎的 row/column hybrid）部分缝合 ⚠️ 转述；本目录视角：07 章双列表仍是理解一切"缝合方案"代价的坐标系。
