# 03 实例内存与后台进程（⚠️ 推定重构章 · 对应原书"Instance Structure"主题域）

> 章名与章号为 ⚠️ 主题重构（[00 §二降级声明](00-总览与阅读地图.md)）。本章是全书技术密度最高的一格：SGA/PGA/后台进程三件套。Oracle 行为一律 ⚠️ 转述；🔧 均为 SQLite/DuckDB 实测，**非 Oracle**。

## 1. 实例是什么（⚠️ 转述）

- 实例 = SGA（共享内存区）+ 一组后台进程 + 服务器进程；同一数据库可被多实例挂载（→ [09 章](09-高可用集群与Oracle产品版图.md) RAC 的伏笔）。
- 启动序列 NOMOUNT→MOUNT→OPEN 分别对应"进程+SGA 起来/控制文件挂上/数据文件与 redo 打开"⚠️，在 [02 章](02-物理存储结构与表空间.md) 的文件三分法上逐层解锁。
- 导游册口径：实例是"临时运行体"，数据库是"持久物"；断电后实例消失、数据库在，恢复靠 redo（09 章接口）。
- "先有内存再有数据库"的观测证据：V$INSTANCE 活着而文件可离线（⚠️ 与 [05 章](05-数据字典与动态性能视图.md) 的 V$ 定义呼应）。

## 2. SGA 分区图（⚠️ 转述）

| 区 | 装什么 | 关键机制词 |
|---|---|---|
| Database Buffer Cache | 数据块镜像 | 脏块/LRU/检查点 |
| Shared Pool | 库缓存(解析后的SQL)+字典缓存 | 硬解析/软解析/绑定变量 |
| Redo Log Buffer | 重做条目暂存 | LGWR 刷盘时机 |
| Large Pool | 共享服务器/并行/RMAN 大块内存 | 免碎片化 |
| Java Pool / Streams Pool | 对应选件 | 按需存在 |

- Buffer Cache：块读入后按"热/冷"子区管理 ⚠️；DBWn 只负责把脏块**滞后**写回数据文件——"检查点是脏块的截止期"是本章最重要的一句话 ⚠️。
- Shared Pool：解析账本所在——同一 SQL 第二次执行应"软解析"命中；这是 [#42 TOP/12-解析.md](../Troubleshooting_Oracle_Performance_2e/12-解析.md) 全章与 [#23 CBOF/01](../Cost_Based_Oracle_Fundamentals/01-成本究竟指什么.md) "解析成本"的公共前提 ⚠️。
- Redo Log Buffer 的"环形+顺序落盘"性格决定 LGWR 永远是提交路径上的最短板 IO（⚠️ 与 🔧 T5 的 WAL 追加写同构）。
- 分区尺寸配比（db_cache_size/shared_pool 等）在自动内存管理（AMM/ASMM）普及后从"手艺"退化为"审计项" ⚠️——[PT2e/03-内存结构调优.md](../Oracle_Performance_Tuning_2e/03-内存结构调优.md) 仍保留手工配平视角。

## 3. 后台进程名录（导游册式 ⚠️ 转述）

- **DBWn**：写脏块（检查点/超时/缓冲区满触发）；一个可派生 W00x 组 ⚠️。
- **LGWR**：redo 缓冲→联机日志；提交即催 LGWR（"commit 等 LGWR 不等 DBWn"= WAL 原则的 Oracle 名）⚠️。
- **CKPT**：推进检查点、更新文件头/控制文件 SCN ⚠️。
- **SMON**：实例恢复（前滚 redo+回滚 undo）、临时段清理 ⚠️——🔧 T6 组演示了"恢复者"的最小可测形态。
- **PMON**：清理失败用户进程、释放锁/恢复会话 ⚠️。
- **ARCn**：归档；**RECO/LCK0/MMON/MMNL** 等按配置存在 ⚠️（AWR 采样即 MMON 家产，[05 章](05-数据字典与动态性能视图.md) 接口）。
- 服务器进程 vs 客户进程 vs 并行从属（P00x）三层"非后台"进程 ⚠️ → [04 章](04-网络连接与服务器进程.md) 展开。

## 4. 🔧 类比实测组（非 Oracle；数据源见文末注脚）

**T4 · 缓冲池与内存限额**（🔧）：SQLite `PRAGMA cache_size` 默认 **-2000**（负数=KB，约 2MB 页缓存）；改 `-64000` 实测生效返回 (-64000,)。DuckDB `SET memory_limit='256MB'` 实测返回 `244.1 MiB`（十进制/二进制口径差），`threads`=16。
→ 对照（⚠️）：Oracle 的 db_cache_size/pga_aggregate_target/memory_target 是同一问题的"多区共享内存"版本；SQLite 只有单池、DuckDB 一池管全部——分层深度差即本章的存在理由。

**T5 · WAL 三件套与检查点**（🔧）：`journal_mode` 从 delete → **wal** 实测生成 `.db-wal`（16512B）+ `.db-shm`；`wal_autocheckpoint`=1000 页；连接关闭时 WAL 被 checkpoint 合并、附属文件消失（实测列表仅剩主库文件）。
→ 对照（⚠️ 转述）：WAL≈redo 日志（LGWR 先行落盘）、autocheckpoint≈CKPT 推进、关连接合并≈DBWn 滞后写回；**同构到"两段式+检查点"为止**，SQLite 无脏块共享缓冲池概念。

**T6 · 单写者 vs 多进程并发**（🔧）：连接 A `BEGIN IMMEDIATE` 期间，连接 B 同语句实测报 `database is locked`（timeout=0.05s）。
→ 对照（⚠️）：Oracle 多服务器进程并发读写同一块靠 buffer cache 驻留+行级锁+块内 ITL（⚠️ 术语转述）；SQLite 整库写锁是最小可行并发模型——从"锁的粒度"反推 Oracle 内存为何必须共享。

**进程↔旋钮映射表（🔧 侧为实测值）**：

| Oracle 机制（⚠️） | SQLite 旋钮（🔧） | DuckDB 旋钮（🔧） |
|---|---|---|
| Buffer Cache/DBWn | cache_size=-64000 | memory_limit 总池 |
| Redo Buffer/LGWR | WAL 文件追加 | .wal 先行(527.9KiB 实测) |
| CKPT | wal_autocheckpoint=1000 | 连接关闭合并 |
| 并行从属/进程池 | 无（单写者锁） | threads=16 |

## 5. PGA：服务器进程的私有工作区（⚠️ 转述）

- 排序区/哈希区/会话内存/游标私有状态在 PGA ⚠️；溢出落 TEMP 表空间（[02 章](02-物理存储结构与表空间.md) 接口）。
- 自动 PGA 管理（aggregate+target）成书时代已是默认 ⚠️——与 🔧 DuckDB `memory_limit` 全局预算、SQLite `cache_size` 连接级预算并置，恰好是"预算粒度谱系"三点定位：进程私有 → 连接私有 → 进程全局。
- 工作案例（⚠️ 转述级示意，非实测）：大排序 SQL → PGA 不足 → TEMP 段扩张 → V$PGASTAT/等待事件 "direct path read temp" 显形——导游册式的"一条链记住三章"（02/03/05）。

## 6. 观测与调参入口速记（⚠️ 转述，导游册式点名）

## 核心概念速览（中英对照）

- **实例** — Instance：SGA+后台进程的运行体，与持久数据库相对。
- **SGA** — System Global Area：实例共享内存总称 ⚠️。
- **Database Buffer Cache** — 数据块镜像池 ⚠️。
- **Shared Pool** — 库缓存+字典缓存 ⚠️。
- **Redo Log Buffer** — 重做暂存区 ⚠️。
- **DBWn / LGWR / CKPT / SMON / PMON / ARCn** — 后台进程六件套 ⚠️。
- **检查点** — Checkpoint：脏块截止期与 SCN 推进 ⚠️。
- **PGA** — Program Global Area：服务器进程私有内存 ⚠️。
- **AMM/ASMM** — 自动内存(A)管理：配比手艺的制度化 ⚠️。
- **WAL** — Write-Ahead Log：🔧 SQLite/DuckDB 先行日志，redo 类比锚点。
- **journal_mode** — 🔧 delete/wal 两模式切换（实测生成 -wal/-shm）。
- **database is locked** — 🔧 单写者拒绝错误（并发粒度类比锚）。
- **cache_size / memory_limit** — 🔧 两引擎内存预算旋钮（实测值已登记）。
- **NOMOUNT/MOUNT/OPEN** — 实例启动三台阶 ⚠️。
- **ITL** — Interested Transaction List：块内并发记账结构（⚠️ 术语转述）。
- **Large Pool** — 大块内存专区：共享服务器/RMAN/并行落此 ⚠️。
- **库缓存** — Library Cache：解析产物驻留区（shared pool 的一半）⚠️。
- **GRD** — Global Resource Directory：RAC 缓存融合的总账（⚠️ 术语级，[09 章](09-高可用集群与Oracle产品版图.md) 接口）。

## 最新演进与工业实践

- **Oracle 侧**：19c/23ai 默认 AMM/ASMM 化、大页(Large Pages)与 SGA 硬化为运维基线 ⚠️ 转述；MMON 家族的 AWR licensing 议题持续是社区热点 ⚠️。
- **开源对照（🔧 现行）**：SQLite 仍是"连接级页缓存+WAL"极简两件套；DuckDB 1.5.x 的 buffer manager+统一 memory_limit+16 线程池（本次实测）展示列存分析引擎的"小 SGA"形态。
- **教学迁移**：SGA/PGA 分层在课堂侧被 PG（shared_buffers+work_mem 两级）接管为通用教具；Oracle 版叙事保留的价值在**进程协作复杂度**（DBWn 组/LMS 等）⚠️。
- **诊断工具链**：本章对象全部在 V$SGA*/V$BGPROCESS 类视图可观测（→ [05 章](05-数据字典与动态性能视图.md)）；AWR 快照即 MMON 产物 ⚠️ 转述。
- **内存目标化**：现代版本以 SGA_TARGET/PGA_TARGET 自调为默认姿态 ⚠️ 转述；🔧 侧最接近的概念是 DuckDB 统一 memory_limit 全局预算（实测口径与三引擎预算粒度见 §T4 及名册对照表）。
- **取证注脚**：本章 🔧 数字复现自 `D:\develops\tmp\dbwave_w7_oraess\experiments.py`（G2.1/G2.2 组）与 `exp2.py`（G2.3 组）；未安装/未启动任何 Oracle 组件。
- **容器时代的变体**：K8s 上跑 Oracle 时 SGA=容器内存限额的分配问题被调度器放大（社区经验 ⚠️ 转述）；同题在 SQLite 侧几乎不存在（🔧 无共享内存结构），是"架构决定运维面"的好对照。
- **一句话带走**：实例的三件套里，内存分区决定"谁看得见什么"，后台进程决定"谁替谁干活"，恢复决定"断电后谁先动手"——三个问题各答一遍=本章读完。
