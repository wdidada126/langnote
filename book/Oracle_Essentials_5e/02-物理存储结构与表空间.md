# 02 物理存储结构与表空间（⚠️ 推定重构章 · 对应原书"Database Structures"主题域）

> 章名与章号为 ⚠️ 主题重构（[00 §二降级声明](00-总览与阅读地图.md)）。本章是全书"文件与逻辑分层"的第一格地图，也是本波任务指定的 🔧 重点章（表空间/文件结构类比）。Oracle 行为一律 ⚠️ 转述；🔧 均为 SQLite/DuckDB 实测，**非 Oracle 行为**。

## 1. 三级分层总图（⚠️ 转述）

Oracle 的存储叙事自顶向下恒为三层，导游册必画这张图：

```
数据库(逻辑) ─ 表空间 ─ 段 ─ 区间 ─ Oracle 块(=IO 原子)
   │ 映射
物理文件：数据文件 *.dbf ×N、控制文件、联机重做日志
```

- **数据库 vs 实例**：数据库是磁盘上的持久物，实例是内存+进程的运行物（03 章）；一个数据文件同时刻只属一个数据库 ⚠️。
- **块（block）**：Oracle 逻辑 IO 单位（典型 8K），不同于 OS 扇区/页；`DB_BLOCK_SIZE` 建库定死 ⚠️（12c 起可有多种块大小的可插拔库，⚠️ 转述）。
- **区间（extent）**：按区分配的最小连续块组；段由若干区间拼成，区间可散落在同一表空间的多个文件里——这是"逻辑连续/物理离散"的教科书对照 ⚠️。
- **段（segment）**：表/索引/回滚段/缓存物化视图等各是一类段；`DBA_SEGMENTS` 可查 ⚠️。
- **表空间（tablespace）**：段的逻辑容器=若干数据文件的分组；SYSTEM/SYSAUX/UNDO/TEMP/USER 表空间分工、本地管理 vs 字典管理、BIGFILE 单文件大表空间均为此域常见话题 ⚠️。

## 2. 三类物理文件（⚠️ 转述）

- **数据文件**：段的实际载体；表空间=1..N 文件，文件可 AUTOEXTEND ⚠️。
- **控制文件**：数据库身份/文件清单/检查点 SCN 等元信息，惯例多路复用 ⚠️。
- **联机重做日志**：LGWR 顺序写 redo（组/成员结构），实例恢复的唯一必需物（03/09 章接口）⚠️。
- 归档日志（ARCn 产物）把重做从"恢复必需"升级为"备份体系一部分" ⚠️——RMAN 话题移交 06 章。

## 3. 🔧 类比实测组（本波硬义务 ≥4 组之主力；全部标非 Oracle）

**T1 · SQLite 文件头=单文件微缩全局**（🔧 实测，非 Oracle）：
Python 建 4096 页库、插 2000 行后读前 100 字节：magic `SQLite format 3\0`（偏移 0–15）、偏移 16 处页大小 4096、偏移 28 根页号 9、偏移 32 空闲链计数 0；`PRAGMA page_count`=9 → 36864 字节 = 9×4096。
→ 对照：SQLite 把"库结构元信息+全部段"塞进一个文件的固定页里；Oracle 用控制文件+数据文件头+块内层级的多文件分工（⚠️ 转述）——**页≈块**是本章最有用的一条类比，extent/freelist 概念 SQLite 用页级空闲链替代。

**T2 · ATTACH 多文件≈表空间分组**（🔧 实测，非 Oracle）：
`ATTACH DATABASE` 挂入 `ts_users.db`、`ts_dw.db`，`PRAGMA database_list` 返回三行（main/users/dw）——一个连接同时"看见"三个文件、跨库查询可行。
→ 对照：Oracle 表空间是"段的容器+文件的分组"，ATTACH 是"查询的容器+库的分组"，都解决"逻辑名空间 vs 物理文件清单"的解耦；但 SQLite 无区间/段概念，跨文件放置由整库粒度决定。

**T3 · DuckDB 数据库块与 WAL**（🔧 实测，非 Oracle）：
建 5 万行表后 `PRAGMA database_size` 返回块大小 **262144**（256KB）、数据库磁盘体积列"0 bytes"而 WAL 列 **527.9 KiB**——新数据尚在 WAL，未 checkpoint 进主文件。
→ 对照：Oracle " redo 先行、脏块滞后"（LGWR/DBWn，⚠️ 转述）与 DuckDB" WAL 先行、块滞后"惊人同构；但 Oracle 块 8KB 是 IO 原子，DuckDB 256KB block 是列存压缩单元——类比只到"两段式落盘"为止。

**T4 · 段/区间 vs 页的粒度差**（🔧 实测推论，非 Oracle）：
同一 T1 库执行 `PRAGMA freelist_count`=0：删除大量行后页整体进空闲链复用，而表/索引不"缩区间"——SQLite 的最小再分配单位是页；Oracle 段可 DEALLOCATE 区间回给表空间（⚠️ 转述）。粒度层级表：

| 层级 | Oracle（⚠️） | SQLite（🔧） | DuckDB（🔧） |
|---|---|---|---|
| IO 原子 | 块 8K | 页 4K | block 256K |
| 分配组 | 区间(=N 块) | 页（无组） | row group |
| 容器 | 段→表空间 | 表=根页树 | 表 |
| 文件分组 | 表空间→N 数据文件 | 库=1 文件（ATTACH 拼接） | 库=1 文件+WAL |

## 4. UNDO/TEMP 与"表的存储选项"（⚠️ 转述）

## 5. 表空间名录与角色（导游册式清单 ⚠️ 转述）

| 表空间 | 角色一句话 | 常配话题 |
|---|---|---|
| SYSTEM | 字典+系统段所在地 | 建库脚本产物（06 章 DBCA） |
| SYSAUX | 卸载 SYSTEM 的辅佐者（AWR/EM 仓库等）⚠️ 11g+ | 空间增长治理 |
| UNDO | 回滚+读一致性段容器 | 保留时长（闪回接口，09 章） |
| TEMP | 排序/哈希溢出临时段 | PGA 关系（03 章） |
| USER/业务 | 应用段主场 | 本地管理/BIGFILE/自动扩展 |
| 只读表空间 | 备份优化手段 | 仓库装载窗口（08 章） |

- 读图提示：本表是"分层图的管理面投影"——左列名字全部活在 05 章字典视图（DBA_TABLESPACES）里可查 ⚠️。
- 🔧 对照（非 Oracle）：SQLite/DuckDB 没有"角色化容器"层——ATTACH 出来的 users/dw 文件（T2）只是命名空间拼接，无 UNDO/TEMP 之类生命周期角色；这个"缺层"本身就是最好的教学对照。

## 核心概念速览（中英对照）

- **Oracle 块** — Block：逻辑 IO 原子，典型 8KB（⚠️）。
- **区间** — Extent：段的最小连续分配单位，块数组 ⚠️。
- **段** — Segment：表/索引/回滚等的存储实体 ⚠️。
- **表空间** — Tablespace：段的逻辑容器，映射到 N 个数据文件 ⚠️。
- **数据文件** — Datafile：*.dbf，表空间的物理载体 ⚠️。
- **控制文件** — Control File：数据库身份与文件清单元信息 ⚠️。
- **联机重做日志** — Online Redo Log：LGWR 顺序写的恢复必需物 ⚠️。
- **UNDO/TEMP 表空间** — 回滚与排序溢出专用容器 ⚠️。
- **BIGFILE** — 单文件大表空间 ⚠️。
- **页头（SQLite）** — Page/Header：🔧 magic+页大小+根页+空闲链的 100 字节门面。
- **ATTACH（SQLite）** — 多文件挂接：🔧 多库一连接。
- **WAL（DuckDB）** — Write-Ahead Log：🔧 实测 checkpoint 前主文件为 0 字节。
- **AUTOEXTEND** — 数据文件自动扩展属性 ⚠️。
- **SCN** — System Change Number：检查点与恢复的时钟 ⚠️。

- **Oracle 侧**：19c/23ai 延续 OMF/AUTOMATIC_storage、大 SGA 下的闪回数据区等默认化路线；可插拔库让"一库多块大小"成为常态 ⚠️ 转述（docs.oracle.com 本次无法 curl 校验，只述不引）。
