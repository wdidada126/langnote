# 05 数据字典与动态性能视图（⚠️ 推定重构章 · 对应原书"Data Dictionary/Dynamic Performance Views"主题域）

> 章名与章号为 ⚠️ 主题重构（[00 §二降级声明](00-总览与阅读地图.md)）。本章讲 Oracle 的"双目录"：静态字典 + 动态性能视图。Oracle 侧一律 ⚠️ 转述；🔧 为 SQLite/DuckDB 实测，非 Oracle。

## 1. 双目录总纲（⚠️ 转述）

- **静态数据字典**：描述"结构"——表/列/约束/权限/段/表空间，持久于 SYSTEM 表空间（[02 章](02-物理存储结构与表空间.md)）；用户面是 DBA_/ALL_/USER_ 三级前缀视图族，元查询入口 DICTIONARY/`DICT` ⚠️。
- **动态性能视图（V$）**：描述"此刻"——SGA/会话/锁/等待/IO 统计，源自内存结构、实例重启即清零 ⚠️；C$ 为 RAC 全局化变体（→ [09 章](09-高可用集群与Oracle产品版图.md) ⚠️）。
- 底层规律：字典视图→基表（如 `SYS.TAB$`/`COL$` 类，⚠️ 术语转述）；V$→X$（固定表，内存直读）——"字典可备份、V$ 不可备份"是最常被导游册引用的一条实用分界 ⚠️。
- 命名语义：DBA_=全库可见（需权限）/ALL_=当前用户可见/USER_=当前用户拥有——三级同一问题三种问法 ⚠️。

## 2. 字典三板斧查询式（⚠️ 示意，非原书文本）

```sql
-- 结构考古：某表住在哪、多大
SELECT tablespace_name FROM dba_tables  WHERE owner='HR' AND table_name='EMP';
SELECT segment_name, bytes/1048576 mb   FROM dba_segments WHERE segment_name='EMP';
-- 空间拼图：表空间余量
SELECT tablespace_name, SUM(bytes)/1048576 free_mb FROM dba_free_space GROUP BY 1;
-- 统计之家：优化器输入面
SELECT table_name, num_rows, last_analyzed FROM dba_tab_statistics WHERE owner='HR';
```

- 每式都可翻译到 🔧 侧执行：`PRAGMA table_info` / `sqlite_master` / `sqlite_stat1`（见 §4 T7）——语法可对照，纵深不可对照。
- 权限审计：`DBA_TAB_PRIVS`/`DBA_ROLE_PRIVS`/`DBA_SYS_PRIVS`（纵深版=波内兄弟 #61 主题域，登记不链）。
- 依赖追踪：`DBA_DEPENDENCIES` 与无效对象重编译工作流 ⚠️。

## 2b. 🔧 目录三板斧的最小可跑版（非 Oracle）

```sql
-- 🔧 SQLite：结构考古（对应 §2 第一式的开源最简形）
SELECT type, name, tbl_name FROM sqlite_master WHERE tbl_name='emp';
PRAGMA table_info(emp);              -- 列名/类型/可空/主键，实测 3 列返回
-- 🔧 SQLite：空间拼图？——无 dba_free_space 对应物，
--    最接近的是 PRAGMA page_count / freelist_count（空闲页计数）
SELECT (SELECT page_count FROM pragma_page_count()) AS pages,
       (SELECT freelist_count FROM pragma_freelist_count()) AS free_pages;
-- 🔧 DuckDB：SQL 标准目录族
SELECT table_name FROM information_schema.tables
WHERE table_schema='main';
SELECT column_name, data_type FROM duckdb_columns();
```

- 判读：§2 四式里只有"结构考古"与"统计之家"（ANALYZE 后查 sqlite_stat1）能原样翻译；"表空间余量"式在 🔧 侧**没有概念对应物**——因为没有表空间（[02 章](02-物理存储结构与表空间.md) T2 结论的目录面回声）。
- 这个"半式可译"的比例本身就是导游册价值：字典查询面越可移植，说明引擎的存储抽象越薄。

## 3. V$ 家族的观测地图（⚠️ 转述）

| 视图族 | 观测对象 | 下游纵深 |
|---|---|---|
| V$SESSION/V$PROCESS | 会话↔服务器进程 | [03 章](03-实例内存与后台进程.md) 进程模型 |
| V$SGA*/V$PGASTAT | 内存配平 | [PT2e/03](../Oracle_Performance_Tuning_2e/03-内存结构调优.md) |
| V$SYSSTAT/V$SESSION_WAIT | 统计与等待事件 | [PT2e/02](../Oracle_Performance_Tuning_2e/02-等待事件与响应时间分析.md)、[TOP/02](../Troubleshooting_Oracle_Performance_2e/02-关键概念.md) |
| V$SQL/V$SQLAREA | 库缓存驻留与解析 | [TOP/12-解析.md](../Troubleshooting_Oracle_Performance_2e/12-解析.md) |
| V$SQL_PLAN | 执行计划 | [CBOF/14-10053跟踪文件.md](../Cost_Based_Oracle_Fundamentals/14-10053跟踪文件.md) |
| V$DATAFILE/V$TABLESPACE | 存储面 | [02 章](02-物理存储结构与表空间.md) |

- AWR/ASH（快照与活动会话历史）是 V$ 的"时间维度扩展" ⚠️：MMON 定期采样落仓库表、7/14 天保留默认 ⚠️——导游册一节点到，实操移交诊断系各册（[TOP/05](../Troubleshooting_Oracle_Performance_2e/05-不可复现问题的事后分析.md)）。
- 使用礼仪（社区通识 ⚠️ 转述）：V$ 直读有闩锁成本，高频轮询不如取 AWR 快照——"观测本身会扰动被观测系统"的最小说明。
- 动态视图的"重启清零"属性决定了：容量趋势类问题必须走 AWR，现场态问题走 V$——两问分流是本章的带走方法。

## 3b. 观测分流速查（⚠️ 转述；本章带走方法的结构化）

| 问题形态 | 第一入口 | 为什么 |
|---|---|---|
| "这表有什么列/谁建的" | DBA_TAB_COLUMNS | 结构=字典持久面 |
| "此刻谁在等什么" | V$SESSION+等待族 | 运行态只活在内存 ⚠️ |
| "上周三凌晨的负载尖峰" | AWR 快照报告 | V$ 已重启清零 ⚠️ |
| "这条 SQL 为什么慢" | V$SQL_PLAN→10053 | 计划驻留库缓存 ⚠️（[TOP/12](../Troubleshooting_Oracle_Performance_2e/12-解析.md)） |

- 分流原则一句话：**问结构查字典、问此刻查 V$、问过去查 AWR**——三面各自保鲜期不同，混用必得假答案 ⚠️。

## 4. 🔧 类比实测组（非 Oracle；数据源见文末注脚）

**T7 · SQLite 的单级目录与"贫瘠统计"**（🔧）：`sqlite_master` 实测只存 type/name/tbl_name/rootpage/sql 五列——对象定义即全部；`PRAGMA table_info(emp)` 返回三列结构。`ANALYZE` 后新增 `sqlite_stat1=('emp', None, '2000')`：无索引则只有一行**基数**。
→ 对照（⚠️）：Oracle 统计面是 DBA_TAB_STATISTICS+直方图+列使用跟踪的多表体系——[#23 CBOF/07-直方图.md](../Cost_Based_Oracle_Fundamentals/07-直方图.md) 的全部难题在 SQLite 世界不存在，因为其优化器输入只有"行数+索引深度"。
**T8 · DuckDB 的目录纵深**（🔧）：`information_schema.tables` 实测返回表清单 `[('t',)]`；`duckdb_tables()` 元函数列（database_name/database_oid/schema_name/schema_oid/table_name/table_oid/comment/tags…）与 `duckdb_columns()` 同构于 SQL 标准目录族；本次星型库经 `sqlite_attach` 挂入后聚合实测 31.2ms（[08 章](08-仓库实施分区物化视图与装载.md) 复用）。
→ 对照：DuckDB 目录"宽而浅"（多视图、无权限/统计历史），Oracle"宽而深"（权限/审计/统计保留期）——目录纵深≈企业特性清单的投影，本章教学价值在此。
**合成观察**：T7+T8 = "字典=可查询的元数据视图，V$=可查询的运行状态"两类在开源栈各有一半对应物；SQLite/DuckDB **没有 V$ 类视图**（无共享内存运行体可暴露，呼应 [03 章](03-实例内存与后台进程.md) 定义）。

## 核心概念速览（中英对照）

- **数据字典** — Data Dictionary：结构元数据的持久视图族（DBA_*/ALL_*/USER_*）⚠️。
- **动态性能视图** — Dynamic Performance (V$) Views：内存运行状态的实时投影 ⚠️。
- **X$ 固定表** — Fixed Tables：V$ 的内存直读底层 ⚠️。
- **DICTIONARY/DICT** — 字典的自描述入口 ⚠️。
- **统计信息** — Optimizer Statistics：行数/块数/选择度/直方图族 ⚠️。
- **DBMS_STATS** — 统计收集包：自动任务窗口的执行体 ⚠️。
- **V$SQL** — 库缓存驻留可被目录查询 ⚠️。
- **AWR/ASH** — 负载仓库/活动会话历史：V$ 的时间维度扩展 ⚠️。
- **UTLRP** — 字典重编译脚本：升级后的对象复活仪式 ⚠️。
- **sqlite_master** — SQLite 唯一目录表：🔧 五列极简元数据。
- **sqlite_stat1** — ANALYZE 产物：🔧 实测仅存基数/索引前缀串。
- **duckdb_tables()** — DuckDB 目录元函数：🔧 SQL 标准风格宽视图。
- **information_schema** — SQL 标准目录视图族：🔧 DuckDB 实测可查。

## 最新演进与工业实践

- **Oracle 侧**：统计自动化（AUTO 选项/列使用跟踪/统计保留期与历史回滚）持续加深 ⚠️ 转述；目录纵深在 23ai 时代加入向量索引等对象类型 ⚠️。
- **开源对照（🔧 现行）**：SQLite 发展出 stat4/spatial 扩展统计但仍是"贫瘠统计"家族 ⚠️ 转述；DuckDB 持续加密元函数族（duckdb_settings/duckdb_columns 等，本次实测两函数可用）。
- **工业观测栈**：Prometheus/Grafana 时代把"V$ 轮询"规范化为 exporter 模式（Oracle 侧存在社区 exporter ⚠️ 转述，本波不引 URL）；导游册的"学会查 V$"升级为"学会看指标基线+会翻 AWR"。
- **目录即治理**：数据目录平台（DataHub/OpenMetadata 类）与引擎内字典是两层世界，本章仍是后者根概念的入口 ⚠️ 类比；治理线各册承接前者。
