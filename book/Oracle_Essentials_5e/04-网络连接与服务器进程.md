# 04 网络连接与服务器进程（⚠️ 推定重构章 · 对应原书"Connectivity/Communications"主题域）

> 章名与章号为 ⚠️ 主题重构（[00 §二降级声明](00-总览与阅读地图.md)）。本章讲"客户端如何够到实例"：Oracle Net Services 家族与进程模型。Oracle 侧一律 ⚠️ 转述（含 Wikipedia 存活佐证）；🔧 均为 SQLite/DuckDB 类比，非 Oracle。

## 1. 连接栈一层图（⚠️ 转述）

- 应用（JDBC/OCI/.NET 驱动）→ Oracle Net（会话层协议，跑在 TCP/IP 之上）→ 监听器 listener → 服务器进程 → 实例（[03 章](03-实例内存与后台进程.md)）。
- 三个配置文件分工：`listener.ora`（服务端注册）/`sqlnet.ora`（命名方法等）/`tnsnames.ora`（本地别名）⚠️；12c 起动态服务注册话题加重 ⚠️。
- 易错概念对：数据库名 vs **服务名(Service)** vs 实例名 vs SID——导游册标准提醒："连接字符串指向的是服务"⚠️。
- 佐证（链接存活经本次搜索引擎确认）：Wikipedia "Oracle Net Services" 词条独立存在，佐证该子域知识体量 ⚠️。

## 2. 连接串解剖（⚠️ 示意 + 🔧 对照）

tnsnames 别名的典型展开（⚠️ 语法示意，非原书文本、非实测）：

```
salespdb =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = scan-vip)(PORT = 1521))
    (CONNECT_DATA =
      (SERVICE_NAME = orclpdb1)
      (SERVER = DEDICATED)))
```

- 逐字段读法：PROTOCOL/PORT=端点；SERVICE_NAME=实例侧的服务注册名（不是库名也不是 SID）；SERVER=进程模型选择（下节）。
- Easy Connect `host:1521/service` 是同串的免配置文件压缩形态 ⚠️。
- 🔧 对照（非 Oracle）：SQLite 连接串 `file:app.db?mode=ro&cache=shared&timeout=5000`——URI 的 scheme+路径+query 三段恰好映射"协议+端点+行为参数"；本次实测 `mode=ro` 段生效（读成功/写拒绝），而 `cache=shared` 类跨会话共享在 Windows 构建受限 ⚠️ 转述级。

## 3. 进程模型在本章的投影（⚠️ 转述）

- 专用服务器(dedicated server)：一客户端一服务器进程，隔离好、开销随连接数线性涨 ⚠️。
- 共享服务器(shared server)：调度器+公共进程池，面向高连接数低活跃场景；代价是失去会话级私有状态亲和 ⚠️。
- 12c 增量的 DRCP（数据库常驻连接池）⚠️：折中方案——池化服务器进程而保留专用会话语义（若本书覆盖 12c，此话题在版本分叉处，本目录只登记不分叉）。
- 连接生命周期=会话(session)/游标(cursor)的诞生与死亡：故障排查线的入口（[TOP/12-解析.md](../Troubleshooting_Oracle_Performance_2e/12-解析.md) 的解析发生在服务器进程私有+共享池交界 ⚠️）。

## 4. 故障域阶梯（⚠️ 转述；排错手册 = 波内兄弟 #66 主题域，登记不链）

| 层 | 症状示例 | 判据 |
|---|---|---|
| 网络 | 超时/拒绝 | ping/traceroute、端口不通 |
| 监听 |Listener 未起/端口漂移 | lsnrctl status 类 ⚠️ |
| 注册 | 服务未动态注册 | 服务列表不含目标 ⚠️ |
| 认证 | 口令/OS 认证失败 | ORA-01017 类 ⚠️ |
| 会话 | 连接成但资源拒 | 进程/会话配额、TNS-12516 类 ⚠️ |
- 自下而上的排除法是本章"带走方法"；🔧 对照：SQLite 的故障域阶梯塌缩成"文件存在性/权限/锁"三格（🔧 实测 `mode=ro` 写拒绝落在"权限"格）。

## 5. 🔧 类比实测组（非 Oracle）

**T4b · "打开方式即连接串"类比**（🔧）：
`file:` URI + `mode=ro` 实测只读打开成功、写入被拒（`attempt to write a readonly database`）——连接参数全部声明在"URL"上，与 tnsnames 参数串同构：**都是"端点+行为参数"的声明**。
**T6b · 双进程抢写与连接池动机**（🔧）：
第二写者 `BEGIN IMMEDIATE` 实测 `database is locked`（timeout 0.05s）——没有进程池可复用、没有锁等待退让，"连接了但拿不到写锁"即失败。反推 Oracle 共享服务器/DRCP 的存在理由：专用进程模型在连接风暴下 fork 成本失控 ⚠️ 转述。
**T3b · DuckDB 单进程内嵌=“无网络栈”对照**（🔧）：
DuckDB 1.5.5 以进程内库形态工作（`threads=16` 是进程内并行，非多主机）——Oracle Net 整层在本机开源栈里**没有对应物**；这恰是"企业级=网络数据库"论断的反面教材：嵌入式形态的能力边界=无多机共享。

**T2b · 多文件挂载当"多端点"用**（🔧，非 Oracle）：
`PRAGMA database_list` 实测返回三行（main/users/dw）——一个连接同时挂三个"端点"，命名空间隔离但没有独立协议栈/认证面。
→ 对照（⚠️ 转述）：Oracle 的 dblink/多个 tnsnames 别名才是"真多端点"：每端点各自的网络与认证域；ATTACH 是"共享一切的同进程端点"。连接抽象谱系一端（URI 参数）→ 中端（ATTACH/dblink）→ 另一端（tnsnames+listener），本章用 🔧 把两端钉住、中间留给 ⚠️。

## 5b. 实操贴士三条（⚠️ 转述级）

- 连接串先怀疑 SERVICE_NAME 写错，再怀疑网络：注册类故障远多于协议类（阶梯 §4 第 3 格最脆）⚠️。
- 应用侧池化参数与 DB 侧进程上限要一起看：池 max 超过 `processes` 配额即 TNS-12516 类风暴 ⚠️。
- 共享服务器不是性能开关而是**连接经济**开关：低活跃海量连接才回本，OLTP 热会话走专用 ⚠️。

## 核心概念速览（中英对照）

- **Oracle Net** — Net Services：跑在 TCP/IP 上的会话层私有协议栈 ⚠️。
- **监听器** — Listener：端口上为服务分派新连接的进程 ⚠️。
- **tnsnames.ora** — 本地服务别名库 ⚠️。
- **服务名** — Service Name：连接字符串的正确指向物 ⚠️。
- **Easy Connect** — host:port/service 免配置文件命名 ⚠️。
- **专用服务器** — Dedicated Server：一会话一进程模型 ⚠️。
- **共享服务器** — Shared Server：调度器+进程池复用 ⚠️。
- **DRCP** — Database Resident Connection Pooling：服务端常驻连接池 ⚠️。
- **游标** — Cursor：会话内解析产物的句柄 ⚠️。
- **l snrctl** — 监听器命令行管家（⚠️ 术语转述）。
- **故障域阶梯** — Fault-domain ladder：自下而上排除法的方法论骨架 ⚠️。
- **调度器** — Dispatcher：共享服务器模型的进程分派者 ⚠️。
- **SCAN** — Single Client Access Name：11gR2+ 的客户端接入抽象 ⚠️（[09 章](09-高可用集群与Oracle产品版图.md) 接口）。
- **URI mode=ro** — 🔧 SQLite 只读打开参数（连接串类比锚）。
- **进程内并行** — In-process concurrency：🔧 DuckDB threads 形态，与多主机共享相对。
- **sqlnet.ora** — 客户端/服务端命名解析与追踪开关配置 ⚠️。
- **连接风暴** — Connection Storm：故障切换后重连自放大失效模式 ⚠️（[09 章](09-高可用集群与Oracle产品版图.md) 的词汇钩）。

## 最新演进与工业实践

- **Oracle 侧**：连接托管在云产品线（Autonomous DB 的专用/中等/低优先池 ⚠️ 转述）成为默认叙事；on-prem 仍靠 DRCP/中间件池化 ⚠️。
- **生态对照**：JDBC 池(HikariCP)事实标准化使"应用侧池化"挤压"服务端共享服务器"的历史舞台 ⚠️ 转述——本章选型天平在 2020 年代整体左移到应用侧。
- **开源嵌入式路线**：SQLite WAL 多读单写、DuckDB 进程内——"无监听器架构"在边缘/分析场景成为正解，网络数据库退守多主机共享场景（🔧 本目录实验佐证其能力边界）。
- **可观测性**：会话级等待/SQL Trace 的工业实现（EM/AWR、商用 APM）持续把"连接层隐形上游"显性化 ⚠️ 转述（本波网络受限，不引 URL）。
- **接入治理左移**：限流/熔断在网关与中间件层全局化，弱化了 Oracle 侧共享服务器叙事的新增部署 ⚠️ 转述——本章"三形态选型"天平的当代读数。
- **认证线接口**：本章的信任边界（口令/OS/Kerberos）是波内兄弟 #61 Oracle Security 的入口格；该目录落盘后由主代理在谱系表升级为实链。
