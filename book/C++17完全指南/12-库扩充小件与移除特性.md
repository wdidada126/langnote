# 12 库扩充小件与移除特性——零碎处见真章

## 核心概念速览（中英对照）

- **最大公约数/最小公倍数** — `std::gcd` / `std::lcm`（`<numeric>`）：`lcm` **溢出即运行时 assert**（实测），`-DNDEBUG` 下变 UB。
- **钳位** — `std::clamp(v, lo, hi)`：在 `<algorithm>` 而不是 `<numeric>`（实测踩坑注①）。
- **采样** — `std::sample`： reservoir 抽样，**输出保持原相对顺序**（实测），要 `<random>` 的真 URBG。
- **搜索器** — `default_searcher` / `boyer_moore_searcher`（`<functional>`）：把子串算法作为函数对象注入 `std::search`。
- **`_v` 变量模板** — type traits variables：`is_same_v` 终结 `::value` 时代（`06` 折叠的编译期近亲）。
- **节点抽取** — node handle / `extract` / `merge`：map 元素整只搬走，key 的 `const` 在手上期间可改（实测）。
- **就地插入二式** — `try_emplace` / `insert_or_assign`：把 `operator[]` 的两种意图拆开，前者**键已存在时不动用 move**。
- **共享互斥** — `std::shared_mutex` + `std::scoped_lock`：多读单写与「同时锁 N 把」的 RAII（实测 4 读者并发进入）。
- **多态内存资源** — PMR / `std::pmr::monotonic_buffer_resource`：运行期注入分配策略，栈缓冲可做到**零上游分配**（实测）。
- **超对齐 new** — over-aligned allocation（P0035R4 ✅）：`alignas(64)` 的对象 `new` 出 64 对齐指针（实测）。
- **字符转换** — `to_chars` / `from_chars`（`<charconv>`）： locale 免疫、零分配、`{ptr, ec}` 报错；**部分解析成功 ec=0**（实测）。
- **`std::launder`** — 指针洗牌：给「原地替换对象后沿用旧指针」发许可证；实测无运行期效果（它是给优化器/UB 判定看的）。
- **移除 vs 保留** — removed vs deprecated：语言特性（动态异常规范）硬报错；库旧件（`auto_ptr` 等）libstdc++ 15 **仅警告、编译照过**（实测，本章最震惊条目）。

注①：`clamp` 头文件归属实测为 `<algorithm>`；漏 include 时报 `clamp is not a member of std`。

## 分组实测

### 1. 数值三件套（`<numeric>` + `<algorithm>`，已实测 g++ 15.2 -std=gnu++17）

```cpp
std::gcd(12, 18) == 6;    std::gcd(-12, 18) == 6;   // 结果恒非负（实测）
std::lcm(4, 6) == 12;
std::lcm(INT_MAX, 3);     // 实测 abort：numeric:212: Assertion '!__overflow' failed.
                          // 且 abort 吞掉未 flush 的 stdout——前面的 printf 一起消失
std::clamp(11, 0, 10) == 10;  std::clamp(-1, 0, 10) == 0;  std::clamp(5, 0, 10) == 5;
std::sample(src9, out4, std::mt19937{42});  // 实测输出 "1 2 7 9"：子集随机、相对顺序稳定
```

`midpoint`/`lerp`/三参 `hypot` 是 **C++20** 加进来的（实测 gnu++17 无 `std::midpoint`；gnu++20 得
`midpoint(INT_MAX,1)=1073741824`——这正是 midpoint 的存在理由：`(a+b)/2` 会溢出）。`lerp` 在 `<cmath>`（实测缺 include 报错）。

### 2. `_v` 变量模板（一行证明）

```cpp
static_assert(std::is_same_v<decltype(std::is_same_v<int,int>), const bool>); // 实测通过：_v 本身是 constexpr bool
static_assert(std::is_execution_policy_v<std::execution::parallel_policy>);   // 11 章同款，实测通过
```

### 3. map 的节点手术（实测输出原样）

```cpp
m.try_emplace("a", X{});        // a=1 size=1：键已存在时 X{} 不会被 move（insert 老是把 payload 掏空）
m.insert_or_assign("k", 9);     // k=9 inserted=0：已存在则赋值
auto nh = m.extract("a");       // m.size=0，节点在我手上
nh.key() = "b";                 // 实测可行：extract 后 key 不再是 const —— 改键不用删+重分配
m.insert(std::move(nh));        // b=1
c.merge(d);                     // d.k=9 d.x=5 整节点搬进 c，d.size=0；键冲突的元素留在 d 自己处理
```

### 4. 搜索器（实测）

```cpp
std::search(hay, std::boyer_moore_searcher(ndl))   // 三种 searcher 全命中下标 3：
// default=3 bm=3 bmh=3（都是下标3）
```

价值在**多次搜索同一 needle**：BM 预处理一次，后面每次 `search` 摊薄成本；一次性查找用 `default_searcher` 或直接 `std::search`。

### 5. 并发小件（实测）

```cpp
// 4 线程 shared_lock(shared_mutex) 并发进入 —— max_readers_inside=4
// std::scoped_lock l(m1, m2);  // CTAD 一次锁两把，实测 OK（05 章 CTAD 的实战样本）
// 有读者在场时独占 try_lock 返回 0（实测）——shared_mutex 不排队、可饿死写者，需自己配策略
```

### 6. PMR 与超对齐（实测）

```cpp
std::pmr::monotonic_buffer_resource ubuf{&cr};      // cr = 我的 CountingResource（上游）
std::pmr::vector<int> v(&ubuf);                     // 1000 次 push_back：
// 实测经 cr 观测到 4 次上游分配、共 9216 字节（几何翻倍扩块）
char buf[4096];
std::pmr::monotonic_buffer_resource onStack(buf, sizeof buf);
// 100 次 push_back 全程用栈缓冲：cr 的分配计数保持原值（实测未触发新分配）
struct alignas(64) CacheLine { int a, b; };
CacheLine* p = new CacheLine{};  // 实测 (uintptr_t)p % 64 == 0：P0035R4（wg21 可达 ✅）的兑现
std::hardware_destructive_interference_size  // 实测本机 = 64
```

monotonic 资源**只进不回**：适合「一批对象同生共死」的请求级作用域，不适合长寿容器。
`hardware_destructive_interference_size` 在 ARM/Apple 上有 128 的先例 ⚠️ 本机只证了 x86 的 64。

### 7. `<charconv>`：三行一个契约（实测输出全部原样）

```
to_chars int: 123456789 ec=0        to_chars base16: ff        to_chars double: 3.14159 ec=0
from_chars: 12345 ec=0 consumed=5   from_chars "12x45": w=12 ec=0 q=2（部分成功！）
from_chars "99999999999999999999": ec=34(result_out_of_range) z=0
from_chars " 12": ec=22(invalid_argument)（不吃空格、不吃 +/- 前缀、不吃 locale）
```

双契约：`from_chars` 失败时 `ptr` 指向**停在哪儿**告诉你哪儿错了，而 `ec` 为 `result_out_of_range` 时**值根本没写**（z=0 原封不动）——
「先判 ec 再用值；ec=0 也要看 ptr 是否到终点」。浮点版 `to_chars` 的「最短往返」本机 GCC 15 已支持；
C++17 当年允许实现缺席，老 GCC（<11）只给整数版 ⚠️。

### 8. `std::launder`：契约型工具（实测「无事发生」）

```cpp
X* p = ::new (buf) X{1, 2};        // X 有 const 成员 n
::new (buf) X{3, 4};               // 原地替换
// 实测 -O0 与 -O2：p->n 都读出 3，launder(p)->n 也是 3 —— 没有可观察差异
```

这恰恰是要如实记录的地方：`launder` 是**给优化器的语义公告**（「旧指针指向的是新对象」），不是运行时机器。
写它是因为不写就属于 UB、而 UB 的免费午餐哪天都会收回去（含 const 成员/union 激活成员切换场景）。

### 9. `to_underlying`：提案说 A，实现住在 B（实测）

P1682R3（标题 *`std::to_underlying` for enumerations*，wg21 可达 ✅）最终把它放进了 **`<utility>`**。
实测：gnu++17/20 均无；gnu++23 + `#include <utility>` 通过（`macro=202102 val=3`）；
gnu++23 只 `#include <type_traits>` 则报 `'to_underlying' is not a member of 'std'`。
记宏名、忘头文件，是新特性最常见的「查无此人」。

### 10. 移除与弃用：语言重，库轻（实测对比）

| 项目 | C++17 地位 | g++ 15.2 实测 |
| --- | --- | --- |
| 动态异常规范 `void f() throw(int)` | 已移除 | **硬错误**：`ISO C++17 does not allow dynamic exception specifications`（`noexcept` 接管） |
| `std::result_of<...>::type` | 已移除（换 `invoke_result`） | 硬错误：`'type' is not a member of 'std::result_of<int(char)>'`（17 档实测） |
| `std::auto_ptr` | 已从标准移除 | **警告后编译通过**：`'std::auto_ptr' is deprecated: use 'std::unique_ptr' instead` |
| `std::random_shuffle` | 已移除 | 同上：`deprecated: use 'std::shuffle' instead` |
| `std::bind1st` / `std::unary_function` | 已移除 | 警告通过（`bind1st` 荐 `std::bind`；`unary_function` 裸弃用） |
| `std::iterator` 基类 | 已弃用 | 17 档警告；**gnu++14 档零警告**（实测差异） |

结论比清单本身重要：**「C++17 移除了 X」≠「你的编译器会拒绝 X」**。语言特性说删就删；库旧件各家实现常留
deprecated 兼容层（MSVC 有 `_HAS_...` 开关族，本机未验 ⚠️）。审计 C++17 合规时，跑 `-std=c++17 -Werror=deprecated`
把警告升级成错误，才是可执行的清单。

## 权衡

「小件」的共同债：**语义契约换样板消失**。`try_emplace` 少写一次「先 find 再决定」；`clamp` 少写一个顺序陷阱
（自己写 `min(max(...))` 的求值顺序坑）；`sample` 少写一次会泄漏顺序的洗牌。收益是代码短了，代价是上面每个
⚠️/实测点都在提醒你：**新零件也有新契约**（溢出 assert、部分成功、头文件归属）。

## 相邻概念对比

- **vs `07`/`08` 语义组件**：optional/variant 改变「类型如何表达」；本章改变「API 如何收尾」——工程上后者每天碰十次。
- **vs `10` filesystem 的双头 API**：`from_chars` 只有 ec 版、永不抛——同一家族里越新的部件越克制。
- **vs C 的 `sprintf`/`atoi`**：charconv 是无 locale、无分配、可验证的替代品；性能敏感序列化路径的默认选择。

## 最新演进与工业实践

**标准之后**
- **C++20** 收下本章的续集：`std::span`、`<bit>`（`has_single_bit`/`bit_ceil`）、`midpoint`/`lerp`、`to_array`、`starts_with`（实测见 `09`）——「小件流水线」没停。
- **C++23**：`to_underlying` 正式可用（实测门槛 gnu++23 + `<utility>`）；`expected` 等更大件见 `07`。
- 移除清单继续变重：C++20 起 `volatile` 复合赋值等被禁（⚠️ 细节未核，不展开）。

**工业实践与开源口径**
- **abseil**（`abseil/abseil-cpp`，00 当日实测 ≈18.1k★）：走的是与本章完全同构的路——先在工程里沉淀小工具，
  再等标准收编（其字符串/算法小件库早于 C++17 多年）。
- 高性能容器库普遍把「元素整只搬走」（extract/merge 的等价物）当卖点：C++17 的 node handle 是这波实践的标准语言地基 ⚠️（具体库未逐一核验）。
- 数字↔文本的高频转换路径（协议编解码、日志）里，charconv 是 `sprintf` 的现代替代；它与格式化库（如 `00` 收录的 fmt）的分工：
  一个管**契约**（locale 无关、可验证），一个管**表达**（对齐/精度/自定义类型） ⚠️ 集成细节未核。

## 常见误区

1. **「lcm 溢出是未定义行为所以查不到」——libstdc++ 给你 assert**（实测 abort 原文）；但 `-DNDEBUG` 后就真没人管了。
2. **「sample 输出是乱序的」——实测保持原相对顺序**（reservoir）；想要随机顺序自己再 shuffle。
3. **「try_emplace 和 insert 差不多」——键存在时 insert 可能已把你的实参 move 走**（载荷变空壳）；try_emplace 承诺不动用。
4. **「from_chars 返回 ec=0 就是全部解析」——`12x45` 实测 w=12 ec=0**：必须自己比较 `ptr` 与期望终点。
5. **「launder 是运行时函数」——实测两档优化无差异**：它是优化器契约；别指望它「修复」旧指针读新对象的 UB。
6. **「std::iterator 基类还能用」——libstdc++ 15 警告、新标准已弃**：手写迭代器请齐五个 typedef（`00` 地图里的 `12` 条目）。
7. **「编译过 = 代码符合 C++17」——auto_ptr 实测编译过**：合规审计要开 `-Werror=deprecated`，别信默认档位。
