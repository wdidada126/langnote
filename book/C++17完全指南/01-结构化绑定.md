# 01 结构化绑定（Structured Bindings）

> 覆盖原书 **Part I 第 1 章**（Structured Bindings）。
> 一句话：**把「一个对象里的若干成员」拆成若干可以书写的名字**，用于 tuple-like 与聚合的解包。
> 对应单文件形态：[../C++17完全指南.md](../C++17完全指南.md)；系列导航：[../C++系列·总索引.md](../C++系列·总索引.md)。

## 核心概念速览（中英对照）

- **结构化绑定** — structured bindings：`auto [a, b] = e;` 引入的不是普通变量，而是一组**绑定名（identifiers）**，它们各自指代 `e` 的某个成员或元素。
- **绑定说明符** — binding attributes：`auto&` / `const auto&` / `auto&&` 决定这组名字是引用还是拷贝；`auto[x, y]` 这种「说明符带方括号」的写法是错的。
- **别名而非新变量** — aliases, not new variables：绑定名与其背后的对象同寿命、同实体，所以 `decltype(x)` 给出的类型**不能直接**当作「成员类型」使用。
- **tuple-like 类型** — tuple-like type：有 `std::tuple_size` / `std::get` 特化的类型（`std::pair`、`std::tuple`、`array`）都能拆。
- **拆包成员访问** — hidden rvalue/reference member access：编译器在背后造一个「未命名对象」，绑定名是它成员的别名。
- **循环内结构化绑定** — structured bindings in range-for：`for (auto& [k, v] : map)` 是本特性最高频的用法。
- **聚合初始化花括号省略** — brace elision：与结构化绑定无关，但常在同一段代码里一起踩到（见 `03`）。
- **不可访问成员** — inaccessible member：含私有/保护非静态成员的类型**不能**被拆（实测被 g++ 拒绝）。

| 问题 | 本章的答复 |

## 动机：没有它之前代码长什么样

三个高频场景在 C++14 里都要「多写一遍名字」：

```cpp
// 🔧 C++14 时代
// 1) map 遍历
for (const auto& kv : m) { use(kv.first, kv.second); }        // kv 这个名字纯属多余
// 2) 多返回值
auto res = std::minmax(v.begin(), v.end());                   // 得记住哪个是 first
use(res.first); use(res.second);
// 3) tuple 解包
auto& a = std::get<0>(t); auto& b = std::get<1>(t);          // 三个模板实参 + 类型要写对
```

C++17 之后三处都能写成「按位置命名」：

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17 通过并运行
for (auto& [key, val] : m) { val += 1; std::printf("%s=%d\n", key.c_str(), val); }   // 直接改到 map 里的值
auto [minIt, maxIt] = std::minmax(v.begin(), v.end());
auto [a, b, c] = tup;                                          // 类型自动推，无需写 std::get<N>
```

**收益不是「少打几个字」**，而是把「位置」和「语义名字」绑在一起：读代码的人不必再去查 `tuple` 的类型定义
才知道第 2 个元素是什么。

## 机制：编译器到底做了什么

`auto [a, b] = p;` 的等价展开（概念模型，不是可编译代码）：

```text
对于表达式 E 与 声明 auto [a, b] = E;
  1. 令 e 为一个未命名对象，用 E 初始化（因此 E 只被求值一次）
  2. 按 E 的类型类别挑成员：
     - 数组类型            → e[0], e[1]
     - 所有非静态数据成员都是公有且同类可见 → e.m1, e.m2（按声明顺序）
     - tuple-like 类型     → std::get<0>(e), std::get<1>(e)
  3. a, b 成为上述实体的别名；若声明带 & / const，别名保留引用性质
```

三类可拆对象与限制（**实测**见下）：

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17 全部通过（含 static_assert 版本）
struct Point { int x; int y; };                    // 1) 聚合/普通类：公有非静态成员
auto [a, b] = Point{1, 2};                         //    数量必须匹配成员个数
a = 10;                                            //    拷贝语义：改 a 不影响原对象

auto& [ra, rb] = p;                                // 2) 引用绑定：ra 就是 p.x 的别名
ra = 42;                                           //    实测：p.x 变为 42

std::array<int, 2> arr{{3, 4}};                    // 3) 数组（注意 double brace 视初始化情况）
auto [e0, e1] = arr;

std::tuple<int, double, char> tup{5, 6.0, 'c'};    // 4) tuple-like：走 std::get<N>
auto [t0, t1, t2] = tup;

auto [x, y] = f();                                 // 5) 函数返回 prvalue 也能直接拆
```

### 四个「不是变量」的后果（实测）

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17
// (1) 不能取结构化绑定名的地址后再假设它是「那个对象的成员变量」——它是别名
// (2) decltype 给出的是**被别名实体的声明类型**，不带你声明时写的引用层次（实测，注意与直觉相反）
std::map<std::string, int> m{{"k", 1}};
auto& [k, v] = *m.begin();                       // k 别名 pair<const Key, T>::first
static_assert(std::is_same_v<decltype(k), const std::string>, "不是 const std::string&");
static_assert(!std::is_reference_v<decltype(k)>); // 实测为假：decltype 会剥掉引用的外层写法
v += 5;                                          // 但通过 k/v 仍能改到容器里的值（引用别名生效）
// (3) 数量必须与成员/元素个数严格一致（实测诊断：only 2 names provided for structured binding）
// (4) C++17 标准文本不允许 lambda 直接捕获结构化绑定名（见下方「重要更正」）
```

**关于 (4) 的重要更正**（本目录实测推翻常见说法）：

```cpp
// 🔧 已实测 g++ 15.2：以下代码在 -std=gnu++17 与 -std=c++17 -pedantic-errors 下均编译通过
std::pair<int,int> p{1, 2};
auto [a, b] = p;
auto f = [&]{ return a + b; };      // 捕获结构化绑定名
```

也就是说，**「C++17 里 lambda 不能捕获结构化绑定」这条口径在 GCC 15 上已经不适用**：该限制被作为
缺陷修复回移（社区一般以 CWG #2340 记录 ⚠️ 编号未逐字核实），较新的 GCC 直接接受。
写跨版本代码时别把它当「安全可用」，因为老版本 GCC/Clang 与 MSVC 的旧模式仍会拒绝。

### 负例（实测被拒）

```cpp
// 🔧 已实测 g++ 15.2 -std=gnu++17 拒绝
struct HasPriv { HasPriv(int a, int b) : x(a), y(b) {} private: int x; public: int y; };
int main() { HasPriv h{1, 2}; auto [a, b] = h; }
// 错误原文：cannot decompose inaccessible member 'HasPriv::x' of 'HasPriv'
```

拆开私有成员之所以被禁，是因为拆分需要**逐成员的公开可见性**；这条限制让「拆一个类」不能成为
绕开封装的后门。要拆私有类，只能给它自己写一个返回 tuple 的成员函数。

## 权衡

| 决策点 | 用结构化绑定 | 用传统写法 |
| --- | --- | --- |
| 一次性读取 tuple 的 3 个值 | ✅ 短、有语义名 | 老手一眼看懂 `std::get<1>` |
| 只读一个成员 | ❌ 必须把全部成员都命名，多余 | ✅ `p.first` |
| 需要把成员传给模板/取类型 | ⚠️ `decltype` 给的是**成员声明类型**（实测会剥掉你写的 `&`），容易推错 | ✅ 成员访问类型明确 |
| 老编译器 + lambda 捕获 | ⚠️ 见上（旧实现会拒） | ✅ 无风险 |
| 拆一个有 20 个成员的结构 | ❌ 语法上不允许部分拆分 | ✅ |

**关键限制汇总**：必须拆**全部**非静态成员（没有「部分解包」，`auto [a, _] = p;` 里的 `_` 仍是真名字，
会和别的 `_` 冲突且不表「忽略」）；不能指定成员名；绑定名不是变量（不能用 `decltype(decltype(a))` 这类技巧绕开别名规则 ⚠️ 具体措辞请核对标准原文）。

## 相邻概念对比

- **vs `std::tie`**：`std::tie(a, b) = f();` 要求 `a, b` **已存在**且左值；结构化绑定是**声明**，且能拆聚合。
  `tie` 走拷贝/赋值，结构化绑定走引用别名，语义更贴近「就地观察」。
- **vs 拷贝到局部变量**：`auto a = p.first; auto b = p.second;` 是真的两个变量，`decltype(a)` 干净、可被
  lambda 捕获；代价是失去「一次求值」与别名语义。
- **vs 成员引用**：`auto& x = p.first;` 一行一个，长而啰嗦，但对 `pair` 的 `first` 有 const 陷阱（`operator[]` 的
  `value_type` 是 const，需要引用绑定才能改）。
- **vs `std::apply`/折叠**：多返回值用结构化绑定；把 tuple **展开成函数实参**则用 `std::apply`（见 `12`）。
- **C++26 展望**：反射类提案会让「按名字拆」变得可能（不必再依赖成员顺序），但截至本目录写作时该能力
  对结构化绑定语法本身**没有影响** ⚠️（提案清单见 `00`）。

## 最新演进与工业实践

**标准之后**
- **lambda 捕获**：如上，缺陷修复后主流实现（GCC 15 实测）已允许；跨版本项目建议仍写
  `auto [a, b] = p; auto c = a;` 显式拷贝后再捕获，最稳。
- **C++20 _range-based for with initializer**（P0614R1，Apple C++ 支持表核实编号 ✅）可与结构化绑定组合：
  `for (auto [k, v] : std::views::filter(m, pred))` 这类写法今天已是默认风格，`views`/ranges 请参
  [../现代C++实战30讲/16-未来篇Concepts-Ranges-协程.md](../现代C++实战30讲/16-未来篇Concepts-Ranges-协程.md)。
- **C++23/26 未改动**结构化绑定本身；相关讨论集中在「能否绑定成员指针/部分绑定」，无进入工作草案的定论 ⚠️。

**工业实践与开源口径**
- **protobuf / gRPC C++ 的生成代码**大量返回 `std::pair`/`std::tuple`；主流项目（含 Abseil，
  `abseil/abseil-cpp`，GitHub API 实测 **≈18.1k★**，2026-09-26）风格指南允许结构化绑定遍历 map，但
  不建议用它替代「只取一个值」的场景——与本文件的权衡表一致。
- **`folly::expected` / `tl::expected`**（`TartanLlama/expected`，实测 **≈1.9k★**）常与结构化绑定配合解包
  「值+错误码」；这也是为什么 `07` 章强调 optional 只能表达「没有」而不能表达「为什么没有」。
- **代码扫描器口径**：clang-tidy 无专门检查项；但 `-Wall` 下「拆了不用其中某个名字」不会警告
  （因为绑定名不是变量，`[[maybe_unused]]` 也不能加在绑定名上 ⚠️ 请按需实测你的编译器版本）。

**给读者的三条纪律**
1. 只在**全部成员都要用到**时拆；否则用成员访问。
2. 需要 `decltype`、模板实参、lambda 捕获时，先 `auto x = a;` 复制成真变量。
3. 拆 `std::map` 元素时写 `auto& [k, v]`（引用）而不是 `auto [k, v]`（拷贝），否则改不到容器里的值——
   上面 `val += 1` 的实测正是这条的证据。
