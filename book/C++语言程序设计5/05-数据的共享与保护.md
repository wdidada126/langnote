## 1 动机

前四章在**单个源文件**内活动，本章处理"多个文件共享一个程序"的全部麻烦：
名字在哪活、活多久、谁能碰、碰了怎么防。这一章的教学核心——链接性、生存期、ODR——
恰是 C++ 区别于"带类的 C"的**工程属性**：它决定程序能不能拆文件开发。
5.8.2"编译、连接与执行"把 01 章埋的线收回来。

## 2 机制

### 2.1 生存期×作用域×链接性：三维表格

| | 块作用域 | 文件作用域 |
| --- | --- | --- |
| 自动（栈） | 局部变量 | — |
| 静态 | `static` 局部变量 | 全局变量、`static` 文件级（内部链接）、`extern`（外部链接） |
| 动态 | `new` 出的堆 | 同左 |

C++11 补第四种：`thread_local`（线程生存期）——并发章的接口（
[../C++并发编程实战2/03-线程间共享数据.md](../C++并发编程实战2/03-线程间共享数据.md)）。
静态局部变量"首次执行到声明处才初始化、且线程安全"（Meyers 单例的机制底座，C++11 保证）。

### 2.2 静态成员的"类外定义"为什么存在

C++98/11 规则：类内是**声明**，定义必须在且仅在一个 .cpp（🔧 实测少了 `int Counter::total;`
即链接期 undefined reference——教材 5.3.1 的规定由此得来，不是玄学）。
C++17 的 `inline static int total = 0;` 取消这条（inline 变量 = 允许多处定义、链接器合并，🔧 实测通过）。
`static const int` 类内初始化是 C++98 就有的**特例**（整型常量），但 odr-use（取地址）仍需类外定义——
这是教材没展开、面试常埋的坑。

### 2.3 const 正确性是一条类型链

常对象→只能调常成员函数→常成员函数里 `this` 是 `const T*`→想改谁就得谁 `mutable`；
常引用绑定临时量可延长寿命（`const T& r = T();` 机制在 03 章栈帧视角上叠加"临时量寿命"规则）。
重载决议吃 const（`f(T&)` vs `f(const T&)`）——教材 5.8.1"先 const 后非 const"原则的机制依据。

### 2.4 预处理与 ODR 的因果链

`#include` 是文本展开：头文件被 N 个 .cpp 包含 → 类内联函数/静态成员定义若写进头文件，
链接期多份定义 → **要么** 头文件守卫 + 内联/模板豁免 ODR，**要么** 类外定义只写一份。
5.6 的三条组织规则（接口 .h / 实现 .cpp / 守卫）全是这条机制的补丁。
宏的另一面：无类型、无作用域、文本替换出事故（02 章 SQUARE 实测）——条件编译之外皆可替换。

## 3 权衡

- **友元 vs 公共接口**：`operator<<` 需要访问私有成员，给友元=破封装换便利；
  现代替代是暴露窄接口（getter 足够时）或干脆用成员 `std::format` 支持（见 11 章文件）。
- **外部变量 vs 参数传递**：全局共享写起来省事、推理成本高（谁改的？）——工业共识：
  全局可变状态是并发时代的第一公敌（[../C++并发编程实战2/00-总览与阅读地图.md](../C++并发编程实战2/00-总览与阅读地图.md) 整本在此接棒）。
- **静态成员 vs 单例**：教材给的是"类级共享数据"工具；单例是它的 OO 化包装（带初始化时机问题）——
  静态局部方案（Meyers singleton）靠 §2.1 的线程安全初始化胜出。
- **头文件 vs 前置声明**：能指针/引用就前置声明——编译防火墙的第一块砖（06 章组合实例再收，
  延伸见 [../大规模c++程序设计/02-组件：物理设计的原子单位.md](../大规模c++程序设计/02-组件：物理设计的原子单位.md)）。

## 4 相邻概念对比

| 对比项 | 差异点 | 备注 |
| --- | --- | --- |
| 作用域 vs 生存期 | 名字可见范围 vs 对象存在时长 | `static` 局部：作用域小生存期大 |
| `static` 文件级 vs 匿名命名空间 | 都能内部链接；后者适用于类型 | 教材 5.6.2 提了两派 |
| `const` 成员函数 vs `mutable` | 逻辑 const vs 按需开洞 | 缓存/互斥量是合法用途 |
| 友元函数 vs 友元类 | 点 vs 面授权 | 友元类是"全家都进来"，更罕见 |
| `#ifndef` 守卫 vs `#pragma once` | 标准 vs 实践通用 | 后者非标准但主流编译器全支持 |
| `#include` vs 模块 import | 文本复制 vs 编译好的语义 | C++20 模块见"最新演进" |

## 最新演进与工业实践

1. **inline 变量（C++17）** 一处终结静态成员定义仪式（🔧 实测 ch05_old/new 对照，见 §实测）。
2. **`#pragma once`/include-guard 之外**：C++20 模块（`import`）从机制上消灭文本包含——
   ⚠️ 本目录样本未涉及（教学工程普及度仍低），仅指出方向；构建依赖视角见
   [../现代C++实战30讲/12-工具漫谈与构建依赖.md](../现代C++实战30讲/12-工具漫谈与构建依赖.md)。
3. **匿名命名空间** 已是唯一推荐写法；`extern "C"` 是 10 章之外与 C 交界的常备胶水
   （[../C++API设计/07-C++用法与符号导出.md](../C++API设计/07-C++用法与符号导出.md)）。
4. **常正确性的现代红利**：`std::string_view`/`std::span` 的只读视图语义、`noexcept` 查询、
   constexpr 全局——全都站在"const 是类型的一部分"这块地基上（教材给了地基，现代建筑在其上）。
5. **宏的退役清单**：常量→`constexpr`；条件编译→留（配置构建仍是正统）；包含守卫→`#pragma once`
   或模块；日志/断言宏→模板+可变参（`std::source_location` C++20 取 `__FILE__` 衣钵）。
   条款对照：[../Effective_Modern_C++/03-转向现代C++.md](../Effective_Modern_C++/03-转向现代C++.md)。
6. **编译/链接工具链**：`nm/objdump/readelf` 看符号绑定；`-fno-common`（GCC10 默认）修历史 ODR 灰区；
   LTO 跨 TU 优化把"多文件"在优化层重新焊回一起。

### 🔧 教材写法 vs 现代写法双编译实测（本机 MinGW g++ 15.2.0）

```text
ch05_old.cpp  -std=gnu++11 ✅：静态成员类外定义 int Counter::total = 0; → total+limit = 102
              （删掉类外定义则链接期 undefined reference——教材规则的机制证明）
ch05_new.cpp  -std=gnu++23 ✅：inline static int total = 0 + static constexpr kLimit
              → total+limit = 102（输出相同，仪式消失）
```
