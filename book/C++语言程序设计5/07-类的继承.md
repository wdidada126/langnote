## 1 动机

继承是 OO 四大特征里唯一"造新类型"的机制：派生类=基类+增量。本章同时发放全书最重的
两张账单——**布局账**（7.8.2 派生类对象内存布局）和**初始化责任账**（构造/析构次序、虚基类谁构造）。
教材考试在"给出代码问输出"，机制层真相是：派生类对象不过是**排好序的基类子对象与成员的拼接**，
构造次序只是布局次序的镜像。

## 2 机制

### 2.1 布局：先排基类，再排成员，对齐填充

非虚单继承：`Derived` 布局 = `Base` 子对象 + 新增成员（🔧 实测 `sizeof(Normal)=8`：两个 4 字节 long 直拼）。
多继承：两基类子对象顺序排，第二个基类偏移非零——`this`  adjustments 由此产生。
**虚继承付税**（🔧 实测表）：

```text
sizeof(Base)=4 → Left(含虚Base)=16 → Derived(虚基菱形)=40
对照非虚：Normal(单继承)=8；无虚基的 Left 只含 Base+成员=8
税=每对象 8 字节（本例）：偏移存进对象头部，经它间接寻址虚基类
```

布局与两跳寻址的完整推导见 [../深度探索C++对象模型/03-Data语意学.md](../深度探索C++对象模型/03-Data语意学.md)
与 [../深度探索C++对象模型/06-执行期语意学.md](../深度探索C++对象模型/06-执行期语意学.md)；
本教材实测数字与其 Itanium/MSVC 对照章（08-专题）同一数量级。

### 2.2 构造/析构次序的因果

次序：**虚基类（最派生类负责）→ 直接基类（声明序）→ 成员（声明序）→ 本体**。
为什么虚基类由最派生类构造？——若每条继承路径都构造，共享子对象会被反复重建；
只有"最派生者"全局可见，担责唯一。后果：虚基类构造**绕过**中间类的初始化列表——
中间类写 `Base(args)` 无效于最终对象，这是教材 7.5.3 的机制底色。
析构严格逆放（🔧 实测 ch07_virtual 构造序 Base→Left→Right→Derived）。

### 2.3 遮蔽不是重载

派生类声明 `f` 后，基类的 `f(int) f(double)` 全部不可见（哪怕签名不同）——名字查找按**名字**
在继承链上找，找到即停。解药：`using Base::f;`（把重载集拉回来）或 `B::f` 限定。
教材 7.5.1 给了作用域分辨符，`using` 声明点到为止；成员函数默认实参与遮蔽的叠加坑见 03 章 §2.2 同款分析。

### 2.4 类型兼容规则与切片

`B b = d;` 值复制：只拷 B 子对象（**切片**——派生增量蒸发，且再调不到虚函数）。
`B* p = &d;` `B& r = d;` 不切片，只换视角——这是 8 章动态绑定的前提。
反向 `D* pd = pb;` 非法（不是每个 B 都是 D），需要显式向下转型（§下一段）。

## 3 权衡

- **继承深度 vs 组合灵活**：每层继承都加深布局与名字推理成本；"为复用代码而继承"是设计债
  （7.8.1 的教材立场与 [../C++编程惯用法/06-考虑继承的设计.md](../C++编程惯用法/06-考虑继承的设计.md) 同调）。
- **private 继承**：语法上 is-implemented-in-terms-of，工程上几乎总被"成员+using 暴露窄接口"替代
  （空基类优化 SBO 场景除外——教材未提，延伸见对象模型 07 章）。
- **虚基类的两难**：菱形数据共享才值得付 §2.1 的税；纯接口菱形（全抽象类）现代标准直接说
  "别 MI 实现，只 MI 接口"——见"最新演进"。
- **向下转型**：`static_cast` 快但错转即 UB；`dynamic_cast` 运行时验证、失败回 nullptr——
  频繁需要 downcast 本身是设计坏味道（8 章虚函数/访问者的解药预告）。

## 4 相邻概念对比

| 对比项 | 差异点 | 备注 |
| --- | --- | --- |
| public/protected/private 继承 | 基类成员访问级的三种映射 | private 继承≈组合+可覆写 |
| 遮蔽 hiding vs 重写 overriding | 查找层 vs 分派层 | 重写必须 virtual 签名同（8 章） |
| 虚基类 vs 普通重复基类 | 一份共享（+税）vs 多份并存（+二义） | 🔧 两形态均实测 |
| 复制构造派生类 | 基类部分靠基类复制构造 | 编译器生成版即按成员含基类 |
| 组合 vs 委托 | 结构复用 vs 行为转发 | 转发样板多时用函数成员返回引用缓解 |

## 最新演进与工业实践

1. **继承训练的现代收缩**：主流指南把"实现继承"（带数据的非虚基类派生）列为高危，
   保留**接口继承**（纯抽象基类，08 章）与少量模板 CRTP（09 章）。
   Core Guidelines C.126/C.128"优先 make 函数"、Class.hierarchy 一簇——[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md)。
2. **`override`/`final`（C++11）**：把"遮蔽当重写"的静默事故变编译错误——本目录在
   [08-多态性.md](08-多态性.md) 给了完整实测（静默失败 vs 编译失败对照）。
3. **虚继承税的现代解法**：接口对象零数据（空 vptr 共享）后，虚基类的**数据**动机基本消失；
   依赖注入（构造传接口指针）替代"共享基类状态"。
4. **继承构造 `using Base::Base;`（C++11）**：转发构造样板清零，教材 4.3.3 委托构造的兄弟特性。
5. **内存布局教学工具**：`/d2cgtypename`(MSVC)、`clang -Xclang -ast-dump`、C++ Insights——
   把 §2.1 的账可视化；布局权威仍推
   [../深度探索C++对象模型/08-专题-现代编译器视角Itanium与MSVC.md](../深度探索C++对象模型/08-专题-现代编译器视角Itanium与MSVC.md)。
6. **设计史坐标**：多重继承的争论（本教材 7 章的谨慎立场）在 Stroustrup 亲述里有完整档案——
   [../C++语言的设计与演化/07-多重继承与类概念的精炼.md](../C++语言的设计与演化/07-多重继承与类概念的精炼.md)。

### 🔧 教材写法 vs 现代写法双编译实测（本机 MinGW g++ 15.2.0）

```text
ch07_amb.cpp     -std=gnu++98 ❌（预期）：非虚菱形 → error: request for member 'f' is ambiguous
                 （2 candidates: Base::f 经 Left / Base::f 经 Right）——二义现场
ch07_virtual.cpp -std=gnu++11 ✅：virtual 继承消歧；实测布局税
                 sizeof: Base=4 Left=16 Right=16 Derived(virtual)=40 Normal=8
                 构造序 Base→Left→Right→Derived；d.a/l/r 访问正常
ch07_new.cpp     -std=gnu++23 ✅：现代替代形态——纯接口 Renderer + final 实现 OpenGL
                 + 组合进 Canvas（unique_ptr 持有）：canvas draws via OpenGL
```

结论：教材教的"虚基类解决菱形"技术上完全成立，同时实测暴露其税（40 vs 8）；
现代口径优先"接口+组合"，把虚继承留给真正共享状态的历史协议。
