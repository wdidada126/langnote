## 2 机制

### 2.1 一次虚调用的解剖

`p->area()`（p 为 `Shape*`）编译成：取对象首字 vptr → 查表 area 槽 → 间接调用。
三条前提缺一不可：①经指针/引用 ②虚**函数**（不是数据/不是静态/不是构造）③签名精确匹配（协变返回除外）。
由此显然的考点：构造函数里调虚函数**不分派**（此刻 vptr 还停在当前层——"半出生对象没有完整人格"，
构造次序的 vptr 逐层改写机制见 [../深度探索C++对象模型/06-执行期语意学.md](../深度探索C++对象模型/06-执行期语意学.md)）；
虚函数不能被内联（调用点不知目标——去虚化 devirtualization 是优化器的例外通道）；
切片值拷贝后 vptr 已换成基类的，多态当场死亡。

### 2.2 虚析构的账

`delete pb;`（pb 静态型 `Base*`、实际指 Derived）→ 非虚析构只跑 `~Base`，派生成员资源泄漏。
规则：可能当多态基类 ⇒ `virtual ~B() = default;`。成本：vptr 已在（有虚即有 vptr），虚析构不再加钱。
🔧 实测（ch08_old）虽聚焦在签名错配，但"基指针 delete"路径同型。

### 2.3 运算符重载：成员还是友元

8.2 的规则表本质是**左操作数决定归属**：`a+b` 若要隐式转换左操作数（如 `"ab" + string`），
只有非成员（通常友元）形式能参与转换——成员形式的左操作数是 this，不接受隐式临时量。
`<<`/`>>` 左操作数是流，必须非成员；`=` `()` `[]` `->` 只能成员。
现代加分项：二元对称运算符（`+ - * ==`）优先**非成员不可改名自由函数**（Sutter 风格：ADL 找到，
封装不破——延伸 [../More_Effective_C++/02-操作符.md](../More_Effective_C++/02-操作符.md)）。

### 2.4 抽象类=接口；纯虚可以带实现

`class B { virtual void f() = 0; };` 不可实例化；但纯虚**允许**给函数体——派生显式 `B::f()` 调用
（供"强制重写、可选复用公共部分"，即 §下一段 NVI 的近亲）。

## 3 权衡

- **运行时多态税**：每调用一次内存间接 + 内联失能 + vptr 每对象 8 字节。
  替代阶梯：模板（编译期分派，零开销但代码膨胀/错误吵）→ `std::function`/函数表（一次装箱）→
  `std::variant + std::visit`（封闭集合、穷举检查，现代"多态"主推）→ 虚函数（开放集合才值）。
- **NVI 惯例**：public 非虚壳统一做前置/后置/锁，protected 虚钩——继承设计章的工程化延续。
- **RTTI 的体面**：频繁 `dynamic_cast` 分派=类层次当 switch 用，虚函数或访问者（visitor）才是本分；
  `typeid` 在序列化/日志的合理使用是它的正当职业。

## 最新演进与工业实践

1. **`override` 纪律（C++11）**：所有重写必写 override、所有终叶必写 final。🔧 实测对照
   （ch08_old vs ch08_err）：忘写→**运行时静默错误**（area 实得 0）；写 override→**编译期拦截**
   （"marked 'override' but does not override"）。一条标记换一档错误等级。
2. **`std::variant + visit`（C++17）**：封闭类层次的多态替代——穷举由类型系统检查、
   无 vptr、可内联。开放集合才回虚函数。链接：[../C++标准库/04-容器.md](../C++标准库/04-容器.md)
   （variant 节）、[../C++20设计模式/01-导论-模式体系与C++20惯用法.md](../C++20设计模式/01-导论-模式体系与C++20惯用法.md)。
3. **运算符打印的现代形态——deducing this（C++23）**：🔧 实测（ch08_new）一个
   `template<class Self> void dump(this Self&&)` 成员同时适配左值/右值/链式，
   取代"成员版 + 友元版"两份样板；通用 `operator<<` 也由此可一个模板通吃全类层次
   （约束到 `has_dump` 概念）。
4. **`std::function` 的装箱税**：可调用对象统一存储靠堆或 SBO + 一次间接——"比虚函数还贵"是常见误解，
   但异构集合场景它仍是不二之选（[../Effective_Modern_C++/06-lambda表达式.md](../Effective_Modern_C++/06-lambda表达式.md) Item 34）。
5. **流运算符的式微**：`operator<<` 当用户级打印正被 `std::format` 的 `formatter` 特化取代——
   见 [11 章文件](11-流类库与异常处理.md) 的实测；`to_string`/`lexicographical` 各回各家。
6. **多态测试接缝**：虚接口是"用 mock 替身做单测"的经典挂点；但现代主张注入点用
   `std::function`/concepts 约束的模板，mock 成本更低。

### 🔧 教材写法 vs 现代写法双编译实测（本机 MinGW g++ 15.2.0）

```text
ch08_old.cpp  -std=gnu++11 ✅（带警告）：Rect::area(int) 手滑错签名，无 override
              编译过（-Woverloaded-virtual 提示 'area' was hidden）、运行 p->area() = 0
              —— 多态静默失效的完整现场
ch08_err.cpp  -std=gnu++11 ❌（预期）：同款错签名 + override →
              error: 'double Rect::area(int) const' marked 'override', but does not override
ch08_new.cpp  -std=gnu++23 ✅：override/final 纪律版虚分派正常（area=12）；
              deducing this 成员 dump 实测通过
```
