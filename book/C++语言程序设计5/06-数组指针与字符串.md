## 1 动机

指针是 C++ 最锋利也最割手的工具，本章占教材 63 页——分量即重视。
它的真实主题有三：**地址算数**（数组/指针互为方言）、**手工生命周期**（new/delete + 深浅复制）、
**字符串的三代同堂**（char[] / string / string_view 视角）。6.8.2 罕见地正面讲"指针安全性隐患"，
说明作者已意识到工具的危险等级。

## 2 机制

### 2.1 数组名何时"不"退化

表达式中数组名→`&arr[0]`，但三例外：`sizeof(arr)`（编译期要知道整个对象，🔧 实测数组内 20、
函数形参内 8——**形参根本是指针，退化已在签名发生**）、`&arr`（类型 `int(*)[5]`，`+1` 跳整个数组）、
字符串字面量初始化 char 数组。指针步长 = `sizeof(T)` 的机制：地址算数按元素刻度，
`p[n] ≡ *(p+n)` 是定义而非巧合。

### 2.2 new/delete 的两幕剧

`T* p = new T(args)` = ①`operator new` 要内存 ②在内存上**构造**；`delete p` 逆放。
`new T[n]` 需要记录 n 以便 `delete[]` 逐个析构——数组的 cookie 机制解释了**为什么 new/new[]
与 delete/delete[] 必须配对**。构造函数抛异常时：内存自动归还、对象析构不跑（半出生者不办葬礼）——
这条 12 章异常安全还会再用。🔧 实测（ch06_old）`strcpy` 把 9 字节灌进 `char[8]`：
本例侥幸没崩（写穿的是栈上邻隙），但 GCC 以 `-Wstringop-overflow` 明明白白喊出
"writing 9 bytes into a region of size 8"——**没崩 ≠ 没错**，本章最重要的安全课。

### 2.3 vector 的成长账本

连续内存 + size + capacity；`push_back` 满则**倍增扩容**——旧内存搬家导致一切
指针/迭代器/引用失效（教材 6.4 点到）。`reserve()` 预分配；`shrink_to_fit` 反向。
vector 不存 `T[]` 而是三指针式账本——`sizeof(vector)` 是常数（三个指针），与元素数无关，
这解释了它按值传递为什么"浅"而复制构造"深"。

### 2.4 字符串三代目

char[]：`'\0'` 定长协议，越界即事故（§2.2 实测）。string：托管 + SSO（短串驻留对象内部
免堆分配，多数实现的 15/22 字符阈值）；`c_str()` 与 C API 互操作时 string_view 登场（见"最新演进"）。
string 的 `operator+` 是 8 章运算符重载的预演。

## 3 权衡

- **裸 new vs 容器/智能指针**：裸 new 的每一条罪（泄漏、悬垂、双删、配对错）都来自
  "所有权不在类型里"。现代第一姿势：能用 vector/string 不用裸数组，能 `make_unique` 不裸 new。
- **数组 vs vector 做成员**：定长 `std::array<T,N>`（C++11，教材未讲）是裸数组的零开销替身。
- **返回指针 vs 返回索引/迭代器**：容器会搬家（§2.3），返回下标比返回指针稳。
- **C 风格强转 `(T*)p` 的四合一暴力** vs 四种命名 cast 各表心意（6.8.3 讲 const_cast；
  `dynamic_cast` 要到 8 章 RTTI 才闭合）。

## 4 相邻概念对比

| 对比项 | 差异点 | 备注 |
| --- | --- | --- |
| 指针 vs 引用 | 可空/可重绑定/有算术 vs 别名三不 | 6.8.1 正题；底层引用常按指针实现 |
| `unique_ptr` vs `shared_ptr` | 独占零开销 vs 引用计数带原子税 | 默认 unique，确需共享再升级 |
| `new T[n]` vs `vector<T>` | cookie+手管 vs 账本+RAII | 教材 6.3/6.4 的并置即暗示答案 |
| `string` vs `string_view` | 拥有 vs 借用 | 悬垂风险从指针转嫁到视图，生命周期仍要人看 |
| `shared_ptr` vs `weak_ptr` | 强引用维持寿命 vs 只看不续命 | 断环与缓存的标准搭配 |
| 指针的指针 vs 指针引用 | `T**` vs `T*&` | 二维数组/出参指针两用途 |

## 最新演进与工业实践

本章是"现代写法对照"密度最高的一章（教材 6.8.2 自己列了隐患，现代标准给了答案）：

1. **裸数组/裸 new → RAII 三件套**：`std::vector`（C++98 已有但普及晚）、`std::array`（C++11）、
   `std::unique_ptr`/`make_unique`（C++11/14）。🔧 实测（ch06_old/new）同一求和任务：
   旧侧 `int* + n` 参数对（sizeof 陷阱现场）+ strcpy 溢出；新侧 `std::span` 一步到位，
   长度随行、函数内 sizeof 陷阱消失。条款：
   [../Effective_Modern_C++/04-智能指针.md](../Effective_Modern_C++/04-智能指针.md)（Item 18–22）。
2. **"指针 + 长度"参数 → `std::span`（C++20）**：非持有连续视图；vector/C 数组/initializer 通吃。
   只读首元素序列用 `std::string_view`（C++17）——🔧 实测 `report("langnote")` 零拷贝。
3. **所有权进类型系统**：Core Guidelines R.3/R.11（不传裸指针做所有权）、F.7（只读参数用 span/view）——
   [../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md)。
4. **手工深浅拷贝 → 零法则**：见 [04 章](04-类与对象.md) §最新演进的实测；6.5 的账在 RAII 成员下自动清。
5. **`malloc/free` 与 `new/delete` 混用**：教学里并列（教材提了 C 库函数），工业里隔离——
   自定义分配器走 `pmr`（C++17，[../STL源码剖析/02-空间配置器.md](../STL源码剖析/02-空间配置器.md) 是同一问题的源码级前传）。
6. **调试视角**：越界在 Debug/ASan 下当场爆，Release 下静默——🔧 本机实测 strcpy 溢出"侥幸正常"，
   对照工具：[../C++代码调试的艺术/06-内存检查.md](../C++代码调试的艺术/06-内存检查.md)（VLDump/UMD/ASan 线）。
7. **迭代器即泛化指针**：6.2 的指针算数在 10 章以迭代器五档重讲——退化、失效规则一一对应，
   学本章时把"vector 会搬家"背下来，10 章直接复用。
