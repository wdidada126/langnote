## 1 动机

这是"把程序写对"的地基章：类型决定位模式解释（衔接 [01-绪论.md](01-绪论.md) 补码/浮点），
表达式决定求值纪律，控制结构决定算法落地。教材口径覆盖到 `auto/decltype`（C++11），
**表达式求值顺序、转换的静默伤害**恰是考试只考"值是多少"、工作要问"为什么这样设计"的分界。

## 2 机制

### 2.1 表达式即"函数调用 + 临时量"

`a + b * c` 脱糖为 `operator+(operator*(b,c), a)`：每个运算符调用产生一个**右值临时量**。
这个视角此刻只用其一半——解释左值/右值、为什么 `i++` 不能当赋值左侧；
另一半（自定义 `operator+`）在第 8 章兑现。`++i` 返回自增后对象的引用、`i++` 返回旧值副本，
机制差一次拷贝，循环里用前缀是零成本习惯。

### 2.2 求值顺序：教材的"未定义"沉默（⚠️ 原书未展开）

`f(g(), h())` 两实参谁先算标准不规定；`printf("%d %d", i, ++i)` 直接 UB。
规则演进：C++11 给初值列表/函数参数定序；**C++17（P0145R3）大幅加强**——`a = b + c` 先算右侧、
`v[i] = i++` 从 UB 转为良定义。读旧代码用"同序列点内改两次即可疑"筛查，写新代码用
"一行只做一件有顺序含义的事"纪律。编译器态度亦变：clang `-Wunsequenced`、
GCC 亦报 `-Wsequence-point`（🔧 实测 §5 中 GCC 对宏双求值原样喊出 "operation on 'i' may be undefined"）。

### 2.3 类型推断的双轨

`auto` 套用**按值传参**规则：`auto x = arr;` 数组退化成指针、`auto y = ref;` 引用被剥掉；
`decltype(expr)` 保留表达式类别（是左值就带 `&`）。`std::decay`/引用限定 `auto&` 是补票工具。
教材 2.5 讲到了双轨存在，未讲"为何不一致"——这是 `decltype` 服务于完美转发（第 9/10 章伏笔）的必然。

### 2.4 输入失败是"状态位"不是异常

`cin >> n` 遇非数字：n **不被赋值**（不是变 0），流进 fail 态，后续提取全部空转——
必须先 `cin.clear()/cin.ignore()` 再重试。C++11 起失败才把 n 置 0（措辞差异常考）。
第 11 章的 `exceptions()` 开关正是这条状态机机制的接口化。

## 3 权衡

- 隐式转换让 `int i = 3.9;` 静默截尾——便利归转换，安全归 `static_cast<int>(3.9)` 显式表态；
  统一初始化 `int x{3.9};` 从 C++11 起**拒绝窄化**，是标准在"便利 vs 静默错误"里首次明确选后者。
- 控制结构语法（2.4 节篇幅最大）本身无权衡；权衡在**圈复杂度**：嵌套三层就该查表/早退。
- `while(1)` 与 `for(;;)` 机器码相同（编译器规范化），纯属可读性站队。
- `sizeof` 是编译期运算符：`sizeof(i++)` 不求值 i——"哪一半被执行"正是考试与机制的接缝。

## 4 相邻概念对比

| 对比项 | 差异点 | 备注 |
| --- | --- | --- |
| `const` vs `constexpr` | 运行期只读（值可运行时定）vs 编译期可求值 | `constexpr` 蕴含 `const` |
| `#define` 常量 vs `const` 常量 | 文本替换无类型无作用域 vs 进符号表可查错 | 宏还活着只为条件编译 |
| `#define` 宏函数 vs constexpr 函数 | 参数按文本代入可多次求值 vs 调用语义只求值一次 | 🔧 实测 SQUARE(i++) 双求值（§5） |
| `typedef` vs `using` | 前者不能模板别名 vs `template<class T> using V = std::vector<T>;` | 第 9 章用得到 |
| `auto` vs `decltype` | 初始化表达式推"值类型" vs 表达式推"声明类型" | 见 §2.3 |
| `if/else` vs `switch` vs 查表 | 二/多路分支 | 分支 ≥4 路查表常数时间且免新 bug |

## 最新演进与工业实践

教材止于 C++11 口径，本章对应的现代基线（全部 🔧 实测，见 §5）：

1. **`#define` 常量 → `constexpr` 变量**：有类型、有作用域、可进 `static_assert`；
   C++17 起命名空间级 `inline constexpr` 变量单头文件定义（第 5 章的链接机制解释"为什么以前不行"）。
2. **函数宏 → constexpr 函数**：`SQUARE(i++)` 双求值事故（🔧 实测 i 从 1 变 3、GCC 报序列点警告）
   在 `constexpr` 函数里结构上不可能——参数只求值一次是函数调用语义。
3. **`scanf` → `std::from_chars`（C++17）**：不依赖 locale、返回出错位置、无 UB；`cout` 格式化 →
   `std::format`（C++20，fmt 同源），见 [11-流类库与异常处理.md](11-流类库与异常处理.md) 的集中实测。
4. **布尔可读性**：`b = x < y` 直接写，勿 `if (x<y) b=true; else b=false;`。
5. **统一初始化 `{}` 至今仍是教学争议点**（窄化守卫 vs `vector{3}` 读作"一个元素 3"），
   C++26 扩展 P2687（initializer list 里临时量寿命）⚠️ 本目录未展开、按扩展名引用。
6. **工具链口径**：g++ 从 GCC 11 起默认 `-std=gnu++17`（GCC 发行说明 ✅ 通行记载），
   教材的 C++98 风格代码在新编译器下大多仍合法——"能编译"与"是现代写法"是两回事。
7. **参考口径**：[../C++CoreGuidelines解析.md](../C++CoreGuidelines解析.md)（编号条目）在类型/表达式条目上
   与本章一一对应；cppreference 可查任意运算的"求值顺序保证从属哪个标准版本"。

### 🔧 教材写法 vs 现代写法双编译实测（本机 MinGW g++ 15.2.0）

```text
ch02_old.cpp  -std=gnu++98 ✅ 输入 "2.5 3" 实测：
   SQUARE(i++) = 2  (i 变成 3)     ← 宏双求值，编译器警告为证
   area = 19.6349                   ← #define PI 3.14159 的三位小数面积
   （编译期 -Wsequence-point: operation on 'i' may be undefined ×2）
ch02_new.cpp  -std=gnu++23 ✅ constexpr kPi + constexpr area() + from_chars 解析 "2.5"：
   area = 19.6350, kPi = 3.14159265358979
   static_assert(area(1.0) > 3.14) 编译期通过——宏时代不可想象
```

同一数学问题，两侧差异：宏版本吃掉一次 `i++` 的 UB 风险、π 精度被作者手敲锁死；
`constexpr` 版本副作用不可能、精度可加位、错误编译期暴露。
注：ch02_old 首跑无输入时 scanf 返回 0、计算段整体跳过——"输入失败静默"正是 §2.4 的机制演示，
补喂 `2.5 3` 后才出现上面的输出。
