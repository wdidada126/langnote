## 1 动机

第 11 章把 IO 从"工具"升格为"类库标本"——学生第一次通读一条继承+多态的真实层级；
第 12 章则补上前 11 章所有例子的沉默前提：**出错了怎么办**。教材口径 `try/throw/catch`
完整、RAII 点到（12.6.2）、`noexcept` 收编（12.6.3）——两章合看，正好是 C++98 到 C++11
"错误处理现代化"的第一程。第二程（C++17/23）在本文件"最新演进"。

## 2 机制

### 2.1 流是带状态机的对象

`cout` 每次 `<<` 检查/更新状态位；进入 fail 后所有输出变哑，直到 `clear()`。
`endl` = `'\n'` + flush（循环里是性能税——教材未教的常识）。
`tie()` 默认 `cin` 读前 flush `cout`，这解释"提示语不 flush 就看不到"的经典新手谜案。
文件流打开失败**不抛异常**（状态位），要异常需显式 `exceptions(ios::failbit)`——
"流失败静默、异常失败loud"的双轨是本章最大设计考古点（D&E 有 Stroustrup 本人对 IO 错误处理
取舍的亲述：[../C++语言的设计与演化/09-异常处理的设计之争.md](../C++语言的设计与演化/09-异常处理的设计之争.md)）。

### 2.2 格式状态的粘性

`setw` 只作用**下一次**输出（一次性），`fixed/setprecision` 却**常驻**流——
11.2 表格背后的机制：宽度存在调用里，其余存在流的 `fmtflags`/`precision` 字段里。
所以打印对齐表格要么每次重设 `setw`，要么打包进局部 `ostringstream`（教材综合实例的用法）。

### 2.3 抛出即展开：资源账的两种命运

`throw` 后编译器沿栈回收：局部对象析构（栈展开），**裸 `new` 的堆不析构**——
🔧 实测（ch11_old）把泄漏点画在抛出路径上；RAII（智能指针/容器/锁）把"资源寿命=对象寿命"
焊死后，栈展开从事故现场变成清洁工。构造中抛：对象不完成、析构不跑，成员/基类按已构造部分逆序回收
（07 章构造次序的反向应用；12.3 节正题）。

### 2.4 捕获顺序与按值抛出

catch 按**书写序**匹配（先派生后基类，写反则基类吞掉一切）；按值捕获小异常对象是共识
（`catch (const exception&)` 防切片防拷贝）；`catch(...)` 是最后的降落伞不是解决方案。
重抛用 `throw;`（保留原对象）——`throw e;` 会**切片**成静态类型（12.2 冷知识，08 章切片机制回响）。

## 3 权衡

- **异常 vs 错误码**：异常=跨层传播免费、控制流可审计性差、实时/禁异常环境出局；
  错误码=就近处理繁琐、易被忽略（`[[nodiscard]]` 是补丁）。Google 风格指南历史禁异常 ⚠️（通行记载，
  未逐字复核本版措辞）；本教材两轨都教，工业按域选边。
- **`noexcept` 的赌注**：承诺违约→`terminate()`（12.6.3）；收益在容器搬移策略（移动需 noexcept
  才敢用）、优化与接口文档三处——[../Effective_Modern_C++/08-微调与全书收束.md](../Effective_Modern_C++/08-微调与全书收束.md)。
- **串行化方案**：Boost.Serialization（教材 11.6.2 示范）带版本兼容与类注册，重；
  现代轻场景用 JSON/二进制手写/反射（C++26 反射 ⚠️ 尚未落地）。

## 4 相邻概念对比

| 对比项 | 差异 | 备注 |
| --- | --- | --- |
| 文本 vs 二进制文件 | 换行转换/格式易读 vs 原样字节 | 跨平台交换慎存裸内存（01 章字节序债） |
| `endl` vs `'\n'` | 附带 flush | 热路径性能差一个量级的误会常源于此 |
| `cerr` vs `clog` | 无缓冲/不锁同步 vs 走 cout 缓冲 | 崩溃前的遗言发 `cerr` |
| `ostringstream` vs `sprintf` | 类型安全/自动扩容 vs 快但 UB 风险 | 06 章 strcpy 实测的同族教训 |
| 析构函数抛异常 | 展开中再抛=terminate | 析构/移动/swap 的 noexcept 三重奏 |
| `terminate`/`set_terminate` | 最后防线与告替身 | 12.2 的兜底机制 |

## 最新演进与工业实践

1. **`std::format`（C++20）终结 iomanip 三件套**：🔧 实测对照（ch11_old/new）——
   旧侧 `setw(8)<<fixed<<setprecision(2)<<3.14159` 需要流、操纵符、顺序记忆，格式状态粘在流上；
   新侧 `format("{:>8.2f}", 3.14159)` 纯函数、编译期查格式串（非法格式直接编译错，
   连本次实测的 `{:032b}` 非法写法都被当场拦下——01 章事故样本）。
   ⚠️ 环境注脚：本机 MinGW 15.2 的 `<print>` 链接缺符号，format 侧一切正常。
2. **`std::expected<T,E>`（C++23）——错误处理第三轨**：🔧 实测（ch11_new）`ratio(6,0)`
   返回 `unexpected("division by zero: 0")`，调用方 `if(r)…else r.error()` 被强制表态。
   教学口径：可预期失败→expected；真异常→throw；两者共存的现代分工正在成形。
   深挖：[../现代C++实战30讲/05-异常与错误处理的现代化.md](../现代C++实战30讲/05-异常与错误处理的现代化.md)。
3. **`throw` 的收窄**：动态异常规范 `throw()` C++11 弃用、C++17 移除，`noexcept` 接管
   （[../C++编程惯用法/09-异常.md](../C++编程惯用法/09-异常.md) 对该死刑有考古级实测）；
   条款对照 [../More_Effective_C++/03-异常.md](../More_Effective_C++/03-异常.md)。
4. **宽字符/UTF 的换轨**：教材 11.6.1 是 `wchar_t`/`wostream` 时代方案；现代共识 **UTF-8 为执行字符集**
   （C++20 P1048/RxM 口径）、`std::u8string`/`char8_t`（C++20）、Windows API 边界才回 UTF-16——
   全景：[../现代C++实战30讲/07-Unicode与多文字世界.md](../现代C++实战30讲/07-Unicode与多文字世界.md)。
5. **异常路径的调试装备**：gdb `catch throw` 停抛出点、`catch` 断点+栈回溯——异常安全的最强
   教学工具：[../C++代码调试的艺术/03-Linux下gdb调试基本功能.md](../C++代码调试的艺术/03-Linux下gdb调试基本功能.md)。
6. **`std::source_location`（C++20）取代 `__FILE__/__LINE__` 宏**：日志与断言的现代注入口（05 章宏退役清单的续集）。
7. **文件 IO 的现代替身**：`std::filesystem`（C++17）管路径/存在性/遍历——
   `ifstream in(path); if(!in)` 的"存在吗"问题不再靠试开；`mmap` 场景读
   [../C++服务器开发精髓.md](../C++服务器开发精髓.md) 的 IO 章。

### 🔧 教材写法 vs 现代写法双编译实测（本机 MinGW g++ 15.2.0）

```text
ch11_old.cpp  -std=gnu++98 ✅：iomanip 流格式化 + 按值抛 int + 抛出路径上的裸 new 泄漏现场
              实测输出（顺序含缓冲交织注脚）：
              format demo:     3.14|
              caught int 0 (到底是哪个函数的哪个错误？)   ← 类型不携带语义
              1.5 / ifstream failbit = 0                  ← 打开失败走状态位
ch11_new.cpp  -std=gnu++23 ✅：std::format "{:>8.2f}"；std::expected 两路返回：
              format demo:     3.14
              error: division by zero: 0
              6/4 = 1.50
```

同题对照：错误信息从"约定 catch(int) 里的 0 表示除零"升级为"类型系统里的 expected"；
格式化从"流上三条操纵符"收敛为"一个编译期校验的格式串"。
