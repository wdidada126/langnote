## 概念与机制

Kotlin 标准库的核心设计✅：**读写接口分离**。`kotlin.collections.List/Set/Map` 是只读
视图类型，`MutableList/MutableSet/MutableMap` 才声明 `add/remove/put`。`listOf(...)`
返回的是只读接口实例（✅ 底层可能是 `java.util.ArrayList` 的包装，但静态类型里根本没有
增删方法，误用直接编译失败）。要点：

- **只读 ≠ 深度不可变**：`List<MutableList<Int>>` 外层只读、内层可改；✅ Kotlin 没有
  语言级"冻结"原语。⚠️ 推定书中会强调"不可变性靠构造纪律"而非类型强制。
- **结构性共享（structural sharing）**：`xs.map{}.filter{}` 每步产生新集合；⚠️ 书中是否
  讲持久化数据结构（persistent data structure，如 Cons-list/树）未证——Kotlin 标准库
  **不含**此类结构，链式操作的共享只发生在元素引用层面，不发生在 spine 层面 ✅。
- **data class**：✅ `copy()` 生成改动一份的新实例，是"不可变更新"的语言级入口；
  `val` 属性＋全参构造使浅比较 `==`（`equals` 自动生成）可用。
- **运算返回新集合**：`+`/`+`元素/`-`元素/`union`/`minus` 全部返回新列表✅，
  对只读 `List` 调用 `+` 得到的静态类型仍是 `List`（保持只读传播）。

⚠️ 推定本章在书中的对应讲法：以 `List` 为主线演示 map/filter/fold 组合子＋不可变更新
模式，可能与 01 章合并为一个"基础"部分。

## 成对代码：命令式 → 函数式改写

🔧 自写未实测。场景：订单列表筛选＋改状态＋汇总金额。

```kotlin
data class Order(val id: Int, val amount: Double, val paid: Boolean)

// 命令式：原地改集合＋改元素（Order 若为 var 类）
fun processImperative(orders: MutableList<Order>): Double {
    var i = 0
    while (i < orders.size) {                // 边遍历边删，经典事故点
        if (!orders[i].paid) orders.removeAt(i) else i++
    }
    var sum = 0.0
    for (o in orders) sum += o.amount
    return sum
}
```

```kotlin
// 函数式：全程只读输入、新集合输出
fun process(orders: List<Order>): Double =
    orders.filter { it.paid }
          .sumOf { it.amount }               // 无中间可变状态

// 不可变"更新"：copy 出改后新元素，原列表不动
fun markPaid(orders: List<Order>, id: Int): List<Order> =
    orders.map { if (it.id == id) it.copy(paid = true) else it }

fun main() {
    val base = listOf(Order(1, 9.9, true), Order(2, 4.0, false), Order(3, 20.0, true))
    val paid2 = markPaid(base, 2)
    check(process(base) == 29.9)             // 旧列表不受影响
    check(process(paid2) == 33.9)            // 新列表含改后订单
}
```

## Java / C++ 对照

| 主题 | Kotlin ✅ | Java ✅ | C++ ✅ |
| --- | --- | --- | --- |
| 只读集合 | `List` 接口无 add | `Collections.unmodifiableList` 包装（运行期抛 `UnsupportedOperationException`，静态仍可声明 add） | 无标准不可变容器；`const std::vector` 仅禁本对象修改 |
| 不可变值对象 | `data class` | `record`（Java 16+） | 无语法糖，手写 const 成员；`operator==` 手写 |
| 浅/深不可变 | 浅，靠纪律 | `List.of` 深一层但元素仍可变 | `constexpr` 对象编译期冻结是唯一"真不可变"路径 |
| 更新模式 | `copy()` / `+` | 无（Stream 收集新集合） | 拷贝构造／`std::apply` 式返回副本 |

关键落差：Java 的 unmodifiable 是**运行期守卫**（可被强转绕过、静态类型撒谎），Kotlin 的
只读是**编译期类型分裂**（读写两套接口）——后者更接近函数式意图✅。C++ 两条都没有，
`const` 正确性是全部负担（对读本目录 [C++20模板元编程](../C++20模板元编程/00-总览与阅读地图.md)
时注意此差异）。

单文件 `ch02.kt`：

1. **编译期守卫验证**：`val xs: List<Int> = mutableListOf(1,2)` 后调用 `xs.add(3)`，
   确认 kotlinc 报"unresolved reference"——坐实读写接口分离✅。
2. **别名泄漏实验**：`val view = xs as MutableList` 强转成功后改元素，观察 `xs` 同步变化
   （listOf 包装同一实例 ⚠️ 预期），记录"只读是类型戏法还是真保护"边界。
3. **data class copy 共享**：嵌套 `data class Outer(val inner: Inner)`，`o.copy()` 后改
   `inner`（若 Inner 可变）验证两副本同时变——演示浅不可变。

## 核心概念中英对照

| 英文 | 中文 | 一句话 |
| --- | --- | --- |
| immutable data | 不可变数据 | 构造后内容不再改变 |
| read-only interface | 只读接口 | 类型层面无增删方法 |
| structural sharing | 结构性共享 | 新旧集合共享未改动部分 |
| persistent data structure | 持久化数据结构 | 函数式风格的不可变容器（本书是否覆盖 ⚠️） |
| data class | 数据类 | 自动生成 equals/hashCode/copy 的类 |
| defensive copy | 防御性拷贝 | 进出边界复制以防共享篡改 |
| aliasing | 别名 | 两名指同一可变对象，纪律破坏之源 |
| shallow vs deep immutability | 浅/深不可变 | 外层冻结 vs 连同引用链冻结 |
