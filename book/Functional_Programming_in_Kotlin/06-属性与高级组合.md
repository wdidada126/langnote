## 核心机制（续 01–05）

01 引用透明立了"效应=值可替换"的地基，05 给了组合工具（andThen/compose/记忆化）；本档
回答"组合什么"——把 Reader/Writer 效应与 Gen 测试器编码成值，并用属性（律）检验组合。

**Reader**：✅ Kotlin 函数类型一等，`Reader<E,A>` 就是 `(E)->A` 的 typealias，无需新类型；
`ask = { e -> e }`、局部特化=lambda 捕获。FPtr 红宝书用 typeclass+隐式 dictionary 组织
Reader（⚠️ 谱系记忆）；Kotlin **无 HKT、无 typeclass** ✅（写不出 `Functor<F<_>>`），读者
单子的"通用性"退化为对具体函数类型的扩展。

**Writer**：`Pair<W,A>` + Monoid 累积日志。红宝书路线是 `WriterT` monad transformer 堆叠；
Kotlin 无 transformer ✅，只能显式传合并函数（dictionary 变实参——这就是 00 档预告的
"表达力落差"第一现场 ⚠️ 书中如何粉饰此落差待验）。

**Gen 属性**：`Gen<A>` = 从种子到值的纯函数 ✅ 可编码（确定性靠自带小 RNG，不靠
kotlin.random ✅ 口径）；`Prop` = 对 Gen 样本断言全体成立。红宝书的 shrinking（失败样例
收缩）在 Kotlin 无生态支持 ⚠️，预计书中省略或粗化。

```kotlin
// 🔧 自写未实测：三效应最小编码
typealias Reader<E, A> = (E) -> A
data class Writer<W, A>(val logged: Pair<W, A>) {
    fun <B> zip(o: Writer<W, B>, acc: (W, W) -> W, m: (A, B) -> A): Writer<W, A> =
        Writer(acc(logged.first, o.logged.first), m(logged.second, o.logged.second))
}
data class Gen<A>(val sample: (Int) -> A) {
    fun <B> map(f: (A) -> B): Gen<B> = Gen { f(sample(it)) }
}
fun <A> Gen<A>.holds(n: Int = 100, p: (A) -> Boolean): Boolean = (0..<n).all { p(sample(it)) }
```

## 批判读法

- 效应编码为值是教学立场；工程线 2026 已走协程/效果构造器，本书（2021）是前朝代数化
  写法——读其**律思维**（combine 满足幺半群律可换实现），不读其 IO 选型（00 裁决延续：
  学院派体操不与工程规范混背）。
- 无 typeclass 后高阶签名爆炸（zip 要传 acc/m 两函数），若书中仍宣称"与 Scala 等表达"
  即为夸大，检验处在此 ⚠️。
- 若整章照搬红宝书练习线（Gen/Prop/shrinking 全链），对 Kotlin 生态过度工程化 ⚠️。

## 核心概念中英对照

| 英文 | 中文 | 一句话 |
| --- | --- | --- |
| Reader / Writer effect | 读者/写者效应 | 环境输入 / 附加日志的值级编码 |
| monoid | 幺半群 | 结合律+单位元的合并结构，Writer 的地基 |
| dictionary-passing | 字典显式传参 | 无 typeclass 时的模拟法✅ |
| property-based testing | 属性测试 | 以生成器+断言代例子断言 |
| generator (Gen) | 生成器 | 种子→值的纯函数 |
| shrinking | 样例收缩 | 失败输入最小化（Kotlin 无生态 ⚠️） |
| higher-kinded type | 高阶kind | Kotlin 缺失✅，通用容器抽象之埂 |
| monad transformer | 单子变换器 | 效应堆叠的 Scala 路线，本书不可复制 |
| type-level composition | 类型级组合 | TS 对照物，见 TLT 02 |
