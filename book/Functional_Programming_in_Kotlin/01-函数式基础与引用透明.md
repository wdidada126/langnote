## 概念与机制

**引用透明（referential transparency）**：一个表达式可被它的返回值替换而程序行为不变。
它蕴含两个条件：无副作用（不改状态、不做 IO）＋同输入同输出。⚠️ 推定本书以此作为全书
"函数式"的定义起点（FP in Scala 谱系的开法，本谱系说法待证）。

**纯函数（pure function）**：满足上两条的函数。Kotlin 的关键事实是——✅ 编译器**不强制
也不检查**纯度：没有 `pure` 关键字，没有效果系统；`(Int) -> Int` 类型的函数完全可以
`println` 或写全局 `var`。纯性是约定，不是类型保障。这与 C++ `constexpr`（✅ 至少给出
"可 purity 的编译期声明路径"）形成对照，是本档观察"表达力落差"的第一站。

Kotlin 支撑函数式风格的✅语言设施：

| 设施 | 事实口径 |
| --- | --- |
| 函数类型 `(A) -> B` | 一等公民，可作参数/返回值/属性类型 |
| `val` | 引用不可重新赋值；不保证指向对象内部不可变 |
| lambda `{ x -> ... }` / 闭包 | 捕获外层 `val` 值；捕获 `var` 允许但破坏引用透明 |
| 对象表达式 `object : ... {}` | 可替代单例函数载体，但社区惯用顶层函数/扩展函数 |
| 高阶函数 `fun <A,B> f(g: (A)->B)` | 标准库 `map/filter/fold` 全部构建于此 |

⚠️ 推定书中会以"替换模型（substitution model）"讲解求值过程，即逐步把调用展开为值，
与 Kotlin 实际的"每次调用真跳函数"无冲突——替换模型是**推理工具**不是执行语义 ⚠️。

## 成对代码：命令式 → 函数式改写

🔧 以下均为自写代码，未实测。

**命令式原版**（累加＋打印副作用混在一起）：

```kotlin
var total = 0
fun addAndReport(x: Int): String {          // 既改全局又输出不同结果：双重不纯
    total += x
    println("now: $total")
    return "added $x"
}
fun sumImperative(xs: List<Int>): Int {
    var acc = 0
    for (x in xs) acc += x                  // 循环可变状态
    return acc
}
```

**函数式改写**（纯核心＋副作用边界分离）：

```kotlin
// 纯核心：同输入同输出，可替换为常数
fun sum(xs: List<Int>): Int = xs.fold(0) { acc, x -> acc + x }
assert(sum(listOf(1, 2, 3)) == 6)           // 1+2+3 可直接替换 6，行为不变

// 边界：把 IO 隔离在最小的壳里，核心保持可测试
data class Report(val n: Int, val total: Int)
fun report(xs: List<Int>): Report =
    Report(xs.size, sum(xs))
fun printReport(xs: List<Int>) = println(report(xs))  // 唯一不纯处
```

改写要义⚠️（推定书中表述方向）：**不消灭副作用，而是把它赶到类型边界上**，
核心逻辑全部引用透明，从而可缓存、可并行、可单测而无需 mock。

## Java / C++ 对照

| 主题 | Kotlin ✅ | Java ✅ | C++ ✅ |
| --- | --- | --- | --- |
| 函数作值 | `(A)->B` 函数类型 | `Function<A,B>` 接口对象 | `std::function<int(int)>` 类型擦除包装 |
| 纯度强制 | 无（约定） | 无（`Stream` 文档建议无副作用但不管） | `constexpr` 编译期候选；C++23 `std::impure` 提案未进标准 |
| 不可变局部绑定 | `val` | `final` 局部变量 | `const auto` |
| 求值替换推理 | 手算 | 手算 | `constexpr` 时编译器真按替换求值 |

C++ 的 `std::function` 与 Kotlin 函数类型的实质差异：前者是**运行期多态盒子**（堆分配
可选、调用有间接开销），后者直接编译为 `FunctionN` 接口调用，✅ 但 Kotlin 也没有把
"这个函数是纯的"写进任何一处类型。

## 核心概念中英对照

| 英文 | 中文 | 一句话 |
| --- | --- | --- |
| referential transparency | 引用透明 | 表达式可用其值替换而行为不变 |
| pure function | 纯函数 | 无副作用＋同输入同输出 |
| side effect | 副作用 | 修改外部状态或做 IO |
| substitution model | 替换模型 | 逐步用值替换调用的求值推理法 |
| first-class function | 一等函数 | 函数可作值传递 |
| higher-order function | 高阶函数 | 以函数为参数或返回值的函数 |
| closure | 闭包 | 连同捕获环境打包的函数 |
| imperative | 命令式 | 以语句改状态为组织原则 |
| declarative | 声明式 | 以"是什么"而非"怎么改"为组织原则 |
