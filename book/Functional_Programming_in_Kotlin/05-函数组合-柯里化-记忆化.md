## 概念与机制

**函数组合（composition）**：`(g ∘ f)(x) = g(f(x))`。✅ Kotlin 标准库提供两个扩展：
`(A->B).andThen(C->B 之后)` 与 `(B->C).compose(B->C 之前)`——精确口径：
`f andThen g` 先 f 后 g；`g compose f` 先 f 后 g。仅覆盖**一元**函数组合。

**柯里化（currying）**：`((A, B) -> C) -> (A -> (B -> C))`，多参变一元链。✅ 关键事实：
Kotlin **没有内建 curry/部分应用语法糖**——历史上 `f.partial(...)`/反引号部分应用
在 1.0 前被移除✅；现状是手写：`curry :: { a -> { b -> ... } }` 形态或直接用默认参数/
lambda 捕获。⚠️ 推定书中会自建 `curry/uncurry` 并借它讲类型构造方向性
（`Either<E,A>` 的 `Either<E>` 部分应用即"带错误类型的容器族"这种讲法 ⚠️ 待书证）。

**记忆化（memoization）**：纯函数的"值→缓存"包装：`memoize f == f`（外延相等）当且仅当
f 纯——这是 [01](01-函数式基础与引用透明.md) 引用透明的直接红利。✅ Kotlin 惯用两件套：
`by lazy`（委托，线程安全模式默认）做零参缓存；`mutableMapOf` 闭包做参→值缓存。
⚠️ 推定书中会展示 fibonacci 指数→线性改写（FP 教学标准节目，谱系推定）。

```kotlin
// ✅ 口径：by lazy 是属性委托，首次访问求值并缓存（lazy 的默认线程模式 SAFELY_PUBLISHED）
val heavy: Int by lazy { expensiveComputation() }

// 🔧 手写一元记忆化骨架（自写未实测）
fun <A, B> ((A) -> B).memoized(): (A) -> B {
    val cache = HashMap<A, B>()
    return { a -> cache.getOrPut(a) { this(a) } }
}
```

**组合**——命令式管道 vs 函数命名管线：

```kotlin
// 命令式：中间变量串行穿针
fun transformImperative(s: String): Int {
    val t = s.trim()
    val u = t.lowercase()
    return u.length
}
// 函数式：管线本身成为可复用的值
val trim = { s: String -> s.trim() }
val lower = { s: String -> s.lowercase() }
val size = { s: String -> s.length }
val pipeline = trim andThen lower andThen size        // ✅ andThen 左结合
val pipeline2 = size compose lower compose trim       // 等价写法，读向相反
check(pipeline("  AB ") == pipeline2("  AB "))
```

**柯里化**——多参配置函数 → 分步特化：

```kotlin
// 原版：一次给全
fun money(symbol: String, amount: Double, digits: Int): String =
    "$symbol${"%.${digits}f".format(amount)}"

// 🔧 手写 curry：按依赖顺序逐参特化（无内建 curry✅，只能lambda塔）
fun <A, B, C, R> f3(f: (A, B, C) -> R): (A) -> (B) -> (C) -> R =
    { a -> { b -> { c -> f(a, b, c) } } }
val moneyC = f3(::money)
val usd = moneyC("$")                                 // 部分应用：冻结符号
check(usd(1234.5)(2) == "$1234.50")
```

**记忆化**——指数 fib → 线性：

```kotlin
// 命令式（其实这版高效但不引用透明地共享状态）
fun fibImperative(n: Int): Long {
    var a = 0L; var b = 1L
    repeat(n) { val t = a + b; a = b; b = t }
    return a
}
// 函数式＋记忆化：纯递归定义保持不变，memoized 补性能
val fib: (Int) -> Long =
    { n -> if (n < 2) n.toLong() else fibM(n - 1) + fibM(n - 2) }.memoized()
lateinit var fibM: (Int) -> Long                      // 🔧 递归绑定技巧，待实验验证
```

（fibM 的递归自绑定是🔧已知脆弱点——`by lazy` 版本更稳，写成
`val fib: (Int)->Long = memoize { n, rec -> ... }` 传参形态；微实验第 2 项裁决哪种能跑。）

## Java / C++ 对照

| 主题 | Kotlin ✅ | Java ✅ | C++ ✅ |
| --- | --- | --- | --- |
| 组合子 | `andThen/compose`（一元） | `Function.andThen/compose`（同构） | 无标准；手写lambda套嵌或范围适配器（_ranges 的 views 思路近似） |
| 柯里化 | 无内建，lambda 塔✅ | 无内建；`Function<A,Function<B,C>>` 手排 | 模板参数天然"编译期柯里化"；运行期靠 `std::bind` 部分绑定 |
| 部分应用 | lambda 捕获 | `BiFunction` 转 `Function` 手写 | `std::bind(f, _1, 42)`——`std::function` 为对照载体 |
| 记忆化 | `by lazy` / 闭包 HashMap | `computeIfAbsent`（Map 级） | 手写 `unordered_map` 缓存；`constexpr` 时编译期即全缓存 |
| 函数类型 | `(A)->B` 一等 | 接口 `Function`（擦除装箱） | `std::function` 类型擦除 / 模板参数零开销 |

Java `Function<A, Function<B, C>>` 与 Kotlin lambda 塔是**同构不同糖**：两边都没有
语言级 curry；C++ 的 `std::bind` 是运行期部分应用、类型擦除代价明显，与模板"编译期
部分特化"形成两条路线——对读 [C++20 模式章](../C++20模板元编程/07-模式和惯用法.md)。

| 英文 | 中文 | 一句话 |
| --- | --- | --- |
| function composition | 函数组合 | 输出接输入拼新函数 |
