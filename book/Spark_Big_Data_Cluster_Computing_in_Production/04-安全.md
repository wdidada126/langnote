# 04 安全（豆瓣实抓章题：第4章 安全；原书英文章题未实证 ⚠️）

> 书目：Spark: Big Data Cluster Computing in Production（Wiley, 2016, ISBN 978-1-119-25401-0，Ilya Ganelin/Ema Orhian/Kai Sasasaki/Brennonn York 著）。
> 精读重构声明：章题 ✅ 豆瓣目录栏实抓；小节为 ⚠️ 推定讲解域（依 DNB 副题「in Production」语义与 2.x 官方安全文档域），非原书文本。总纲见 [00-总览与阅读地图](00-总览与阅读地图.md)。

## 1. 本章问题域：集群化的安全面（⚠️ 讲解框架）

单机脚本没有的安全面，作业上了集群全部出现：driver/executor 间 RPC、事件日志与 shuffle 文件里的明文数据、Web UI 的信息泄露、多租户队列的越权读取、密钥随作业分发。**安全边界的划分以「集群管理器底座」为骨架**——本章与 `02-集群管理.md` 互为表里：YARN 提供 Kerberos 域、DC/OS 提供内部 CA/marathon 授权、K8s 提供 RB4 面（后者名未预检 URL 故只给概念 ⚠️）。

## 2. ⚠️ 推定小节 A：认证——RPC 与底座票据

- 2016 现实：Spark 内部 RPC 默认**无认证**；`spark.authenticate` 开关提供基于共享密钥的 shuffle 流认证（配置名 ✅ 见 https://spark.apache.org/docs/latest/configuration.html 200 预检），全域 Kerberos 委托给底座（YARN 文档域 ✅ https://hadoop.apache.org/docs/stable/hadoop-yarn/hadoop-yarn-site/YARN.html）。
- 生产断言 ⚠️：在共享集群上，「网络可达=可注入」是 2.0 时代的默认威胁模型；防火墙段隔离 driver/executor 端口是第一道实际防线。

## 3. ⚠️ 推定小节 B：传输加密与 UI 暴露面

- Spark 2.x：HTTP 服务器 TLS 支持仍属残缺（`spark.ui.ssl` 家族彼时不存在 ⚠️ 时代断言）；History Server / application UI 默认**明文+无鉴权**——UI 泄露（环境变量里的云密钥、broadcast 变量内容）是经典事故路径 ⚠️。
- 实务答案：UI 置于反代+认证之后、或按网络段封闭（通用运维实践 ⚠️ 非原书条文）。

## 4. ⚠️ 推定小节 C：数据面与密钥面

- 明文工件清单：eventLog、shuffle 数据、broadcast 临时文件、缓存 RDD——都在 HDFS/本地盘上，**静态加密要么靠底座（HDFS 透明加密/KMS）要么没有** ⚠️。
- 密钥分发的两难：作业要读云存储就得带凭证；2016 常见反模式=把 access key 硬编码进 jar/属性文件随 `--jars` 全集群分发 ⚠️（通用反模式陈述）。
- 授权：数据级 ACL 不由 Spark 引擎执行，由存储/查询层（后续时代=Ranger 类，标题级 ⚠️）承担——引擎侧只认「能提交作业的人」。

## 5. ⚠️ 推定小节 D：多租户隔离

队列配额（02 章）≠安全隔离：同节点混部 executor 的**侧信道面**（共享盘、共享主机、日志互读）是 YARN 时代企业审计必答题 ⚠️；隔离等级的完整光谱属云仓/OS 域，本册只登记 Spark 侧挂点。

## 6. 🔧 实测（SQLite/DuckDB 类比·非本书 Spark 引擎行为）

**🔧 实测组 7（静态明文，SQLite 3.45.3）**：方法——读 `exp3.db`（02 章实验产物）文件头 16 字节=`SQLite format 3\x00`（ASCII 魔数、非加密容器），再以零凭证 `sqlite3.connect` 读出全部行 `[('0',), ('0',)]`；另 python sqlite3 标准库无 `PRAGMA key` 类加密原语可调用。
观察：**「有 ACL/有 WAL」不等于「静态加密」**——文件在场即可读，正是 §4「eventLog/shuffle 明文工件」的单机同构：Spark 引擎不管静态加密，正如 SQLite 不管。
⚠️ 边界：类比止于「存储层明文工件的可读性」，**非本书 Spark 引擎行为**。

**🔧 实测组 8（只读底座拒绝静默新建，DuckDB 1.5.5）**：方法——`duckdb.connect('exp4_ro.duckdb', read_only=True)` 对不存在文件；结果 `IOException: ... in read-only mode: database does not exist`。
观察：**权限/模式的降级必须显式失败而非静默兼容**——对应安全设计原则：认证/加密开关要「fail closed」，2016 Spark 很多默认值是 fail open（无认证、明文 UI）⚠️ 引申类比，非 Spark 实测。
⚠️ 非本书 Spark 引擎行为。

## 8. 工件-风险-缓解矩阵（⚠️ 本目录方法论提炼；威胁模型工件化的落地表）

| 工件 | 暴露面（2016 默认 ⚠️） | 泄露内容 | 缓解（时代答案） |
|---|---|---|---|
| RPC 通道 | 无认证、随机端口 | 任务数据/指令 | `spark.authenticate`（✅ 键名）+网络段隔离 |
| Application UI | 明文、无鉴权 | 环境变量、云密钥、表样本 | 反代+认证，或按段封闭 ⚠️ |
| History Server | 同上且长期在线 | 全部历史作业 | 认证前置+日志留存分级 ⚠️ |
| eventLog | HDFS/本地明文 | 执行画像+部分数据引用 | 存储层加密/ACL（引擎不管，🔧 组 7） |
| shuffle 文件 | 本地盘明文 | RDD 片段 | 底座盘加密、任务后清理 ⚠️ |
| broadcast 临时件 | driver/executor 本地 | 全量小表 | 控制广播体积=控制泄露半径 ⚠️ |
| 作业归档 `--jars` | 全集群分发 | 硬编码密钥 | 凭证外置/KMS ⚠️ |
| 容器日志 | RM/底座聚合面 | 打印进日志的数据 | 日志脱敏规范 ⚠️ |

## 9. 生产加固检查单（⚠️ 讲解框架，按本章四小节顺序）

- [ ] 认证：RPC 认证开关评估；底座 Kerberos/票据路径确认（§2）。
- [ ] 网络：driver/executor 端口段收敛策略；UI 不暴露于办公网（§3）。
- [ ] 传输：UI/history 前置反代 TLS+认证（§3）。
- [ ] 静态：eventLog/shuffle 所在存储的加密与 ACL 核对（§4，🔧 组 7 自证引擎不管）。
- [ ] 密钥：扫描 `--jars` 归档与配置内的长期凭证；改短期委托（§4）。
- [ ] 多租户：混部节点侧信道面登记；高敏租户独占节点池评估（§5）。
- [ ] 审计：提交人-作业-数据域三元可回溯（02 章 RM 日志+eventLog 合成）。
- [ ] 演练：一次「UI 被抓」推演，验证密钥轮换流程（通用 ⚠️）。

## 10. 常见误区四条（⚠️ 讲解框架）

1. 「引擎版本新=安全」——安全面演进远慢于 API 演进，逐项对文档（✅ configuration 页）核实，不靠版本信仰。
2. 「有 Kerberos 就全域可信」——底座票据管「谁能提交」，不管「作业间互看」（§5 隔离≠认证）。
3. 「日志不碰数据」——eventLog/UI 携带表名/样本/变量的案例屡见（§8 矩阵前两行的现代版 ⚠️）。
4. 「公有云免检」——托管内化了底座加固，但**工件清单仍归你**（数据面风险不随 SKU 转移 ⚠️ 方向陈述）。

## 12. 2016 默认 vs 2026 默认对照（⚠️ 量级断言，逐项以当期官方文档为准；键名域 ✅ https://spark.apache.org/docs/latest/configuration.html）

| 面 | 2016（本书语境 ⚠️） | 2026（本会话可证部分） | 结论 |
|---|---|---|---|
| RPC 认证 | 默认关 | 开关仍在（✅ 键名存在） | 仍是「选做题」，网络段仍是主力缓解 |

## 核心概念速览（中英对照）

- **内部 RPC** — Internal RPC（driver↔executor）：2.0 时代无认证默认面，威胁模型核心。
- **shuffle 认证** — spark.authenticate：以共享密钥认证 shuffle 流连接（配置名 ✅ 官方文档）。
- **Kerberos 委托** — Delegation Token/Kerberos：身份体系外包给底座（YARN 域）的 2016 主流答案 ⚠️。
- **明文工件** — Sensitive Artifacts：eventLog、shuffle 文件、broadcast 临时件、缓存盘——静态泄露面清单。
- **UI 暴露面** — Web UI Exposure：History Server/application UI 默认无鉴权的经典事故路径 ⚠️。
- **反代加固** — Reverse Proxy + Auth：给明文 UI 套认证的行业通用解 ⚠️。
- **静态加密** — Encryption at Rest：引擎不管、存储层（HDFS/KMS）管——🔧 组 7 的类比结论。
- **密钥分发** — Credential Distribution：凭证随作业归档扩散的反模式风险 ⚠️。
- **fail closed** — Fail Closed：安全开关缺失依赖时显式拒绝服务（🔧 组 8 类比对象）。
- **多租户隔离** — Multi-tenancy Isolation：队列=配额≠隔离；侧信道面另算 ⚠️。
- **审计面** — Audit Trail：谁提交了什么作业=底座 RM 日志+eventLog 合成 ⚠️。
- **威胁模型工件化** — Artifact-based Threat Modeling：按数据工件而非协议列风险的本章方法论标签。

## 最新演进与工业实践

- **TLS 补课**：3.x 起 HTTP 服务器（含 UI）TLS 配置落地、RPC 认证粒度增强（官方 configuration/UI 文档域 ✅ https://spark.apache.org/docs/latest/configuration.html 可达，逐条键名 ⚠️ 不展开）；「UI 默认裸奔」的 2016 断言在今天新装+正确配置下部分失效 ⚠️。
- **列级/行级权限外置**：表格式（Iceberg/Delta 权限模型）+ catalog 授权成为 2024–2026 数据面主战场——引擎安全更薄、catalog 更安全，与 00 §4 湖仓册互链一致（[Use_Iceberg_with_Spark·00总览](../Use_Iceberg_with_Spark/00-总览与阅读地图.md) ✅ 在盘）。
- **工作负载身份**：K8s 时代以 service account/短期凭证替代「密钥进 jar」反模式（概念级 ⚠️，本会话 K8s addons 文档 ✅ 200，其余链接未预检不引）。
- **私有域实践**：金融/政务仍按本册 §2–5 工件清单做加固评审；公有云域安全随托管服务内化（方向陈述 ⚠️）。
- **治理纵深回看**：SQL 授权语义本体在盘上 SQL 系列册群（候选见 [数据库系列·总索引](../数据库系列·总索引.md) ✅），本章只登记 Spark 侧挂点；DOI/论文面无（安全章无经典论文锚点，依纪律不硬凑）。
- **回读建议**：本册 01/02/03/04 的安全叙事合起来是「前云原生时代」的完整基线对照——2026 做任何 Spark 平台评审时，先用 §4 工件清单过一遍，再用当期官方文档核对哪些已内建，防止把 2016 恐吓当现状、也防止把现状当 2016。
