> 书目：Spark: Big Data Cluster Computing in Production（Wiley, 2016, ISBN 978-1-119-25401-0，Ilya Ganelin/Ema Orhian/Kai Sasasaki/Brennonn York 著）。
> 精读重构声明：章题 ✅ 豆瓣目录栏实抓；小节为 ⚠️ 推定讲解域（依 DNB 副题语义与 2.x 时代公开运维文档域），非原书文本；引擎级调优（任务/内存语义）归 [Spark_The_Definitive_Guide·00总览](../Spark_The_Definitive_Guide/00-总览与阅读地图.md) 与波内 #216 HPS 登记域，本章专讲**「集群生产视角」的调优**——参数来自资源模型而非仅代码。总纲见 [00-总览与阅读地图](00-总览与阅读地图.md)。

## 1. 本书调优观：三角约束（⚠️ 讲解框架）

2016 生产语境下，调优=在 **executor 芯数 × executor 数量 × 单容器内存** 三角里，对着底座约束（YARN 队列容量/节点形态、Mesos offers 粒度）求解：

1. 芯数决定一个 executor 内并行 task 数的上限；
2. executor 数量决定跨节点并行度与 shuffle 落盘分散度；
3. 内存切给执行（task）与缓存（storage）的比例是容器级决策，不是 JVM 级玄学。
   ——三角的**任一边都要在底座配额内取整**（YARN Container 对齐），这是「集群管理章」与「调优章」的咬合缝 ⚠️。

## 2. ⚠️ 推定小节 A：并行度与分区

- 读入分区数≈初始并行度；shuffle 后并行度由 `spark.sql.shuffle.partitions`（2.x 默认 200，配置名 ✅ 官方 https://spark.apache.org/docs/latest/configuration.html 200 预检）决定——2016 时代最常见的生产第一课：**默认 200 对大作业太小、对小作业太大** ⚠️。
- 倾斜处理三板斧（通用实践 ⚠️ 非原书小节）：加盐打散热键、热点单独广播连接、提高 shuffle 分区让热键摊薄。🔧 组 1 的量化形态见 `01-成功运行Spark作业.md`。

## 3. ⚠️ 推定小节 B：shuffle 与本地盘

- 2.0 时代 sort shuffle 落本地盘：**磁盘带宽与容器本地盘容量是 YARN 多 executor 混部节点的第一瓶颈** ⚠️（DiskValidator 类运维概念属 YARN 公开文档域）。
- 内存模型：execution/storage 双池、spill 阈值——语义细节属引擎域，本册只在「容器规格怎么定」层面引用；深度回指 [Spark_The_Definitive_Guide·00总览](../Spark_The_Definitive_Guide/00-总览与阅读地图.md)。

## 4. ⚠️ 推定小节 C：缓存与复用

- `cache()/persist()` 的 storage 内存占比来自容器配额切分；跨作业复用走 Tachyon/Alluxio 前置（2016 叙事 ⚠️，本项目盘上湖仓册群 [Data_Lakehouse_in_Action·00总览](../Data_Lakehouse_in_Action/00-总览与阅读地图.md) ✅ 已验名为后日替代形态）。
- 广播变量替代大表 shuffle 连接——模式库形态见 [Advanced_Analytics_with_Spark_2e·00总览](../Advanced_Analytics_with_Spark_2e/00-总览与阅读地图.md)（在盘 ✅）。

## 5. ⚠️ 推定小节 D：观测驱动调优

- 无 eventLog/History Server 回放（见 `01-成功运行Spark作业.md` §3）则调优=盲调；task 失败率、shuffle spill、GC 时间三条曲线是 2016 版「可观测三件套」⚠️。
- 与波内 #216 HPS（High Performance Spark 2e，同波在建）的分工：HPS 走代码级纵深，本册走**容器/底座规格级**——同一参数 `--executor-cores`，HPS 问「几个最优」，本册问「节点上还放得下几个容器」。

## 6. 🔧 实测（DuckDB 1.5.5·非本书 Spark 引擎行为）

**🔧 实测组 5（并行度-吞吐近线性，DuckDB PRAGMA threads）**：方法——物化 3000 万行表（k=i%64, v），分别 `PRAGMA threads=1/4/8` 跑全表 GROUP BY，墙钟 **1.166s / 0.324s / 0.168s**。
观察：**线程 1→8 吞吐 ×6.9（并行效率 ≈86%）**，对应「executor 总芯数↑→吞吐↑但边际递减」的方向；且本例 k 基数仅 64——并行度天花板=分组键基数（见组 1），**追加线程撞不到天花板之上**。
⚠️ 边界：DuckDB 单进程共享内存，无 shuffle/容器/网络，类比止于「并行度与数据分布决定可扩展上限」，**非本书 Spark 行为**。

**🔧 实测组 6（热键单桶拖尾，DuckDB 同表）**：k2 列含热键 -1（3 万行，其余 63 键各 ≈47.4 万行），`GROUP BY k2 ORDER BY 2 DESC`：threads=1/4/8 墙钟 **0.142 / 0.051 / 0.023s**。
观察：**加线程对「桶内聚合」类查询收益被并行执行器掩盖，倾斜代价在分布式引擎才现形（单长尾 task）**——单机测不出 Spark 的「木桶效应」这一事实本身就是重要类比结论：**调优验证必须在真实并行形态上做**。
⚠️ 非本书 Spark 引擎行为；脚本与 db 文件在 `D:\develops\tmp\dbwave_w8_spwiley\`（exp2.duckdb，64MB）可复跑。

## 7. 本章要点回收

1. 「生产调优」的对象首先是**资源形态**（容器规格×数量×底座配额），其次才是参数；顺序反了就是在替底座的坏配置打补丁 ⚠️（本书视角提炼）。
2. 倾斜/分区/shuffle 三主题的因果用 🔧 组 1/5/6 本机可复跑；量化的是**结构性因果**，不是 Spark 数值。
3. 版本落差老实录：本书成稿于 Spark 2.0 前后（AQE 尚不存在），今天的「默认参数直觉」多数来自 3.x AQE 自适应时代 ⚠️——把本章当「前 AQE 时代的调优人类学」。

## 8. 前 AQE 时代参数速查（键名 ✅ 见官方 https://spark.apache.org/docs/latest/configuration.html，200 预检；「2016 直觉」列为本目录讲解 ⚠️）

| 参数（✅ 官方键名） | 管什么 | 2016 生产直觉 ⚠️ | AQE 后还调吗 ⚠️ |
|---|---|---|---|
| `spark.executor.instances` | executor 个数 | 按队列容量取满 | 配动态分配后少写死 |
| `spark.executor.cores` | 单容器并行度 | 4–5 芯甜点（HDFS 客户端限制传说） | 仍要定形态 |
| `spark.executor.memory` | 容器内存 | execution/storage 二八开起步 | 变化不大 |
| `spark.default.parallelism` | RDD 路径并行度 | 总芯数×2~3 | SQL 路径被替代 |
| `spark.sql.shuffle.partitions` | shuffle 后并行度 | 默认 200，大作业手动上调数百~数千 | AQE 自动合并小分区，常可不管 |
| `spark.sql.adaptive.enabled` | AQE 开关 | **2016 不存在** | 3.x 起新基线 |
| `spark.memory.fraction` | 执行+存储内存占比 | 默认 0.6，GC 差时下调 | 谨慎动 |
| `spark.dynamicAllocation.enabled` | executor 伸缩 | 多租户队列必备 | 云/批常态开 |
| `spark.eventLog.enabled` | 留观测证据 | 必开（01 §3） | 不变 |
| `spark.rpc.message.maxSize` | RPC 帧上限 | broadcast 超限急救 | 少见 |

## 9. 一次调优的标准工作流（⚠️ 讲解框架，与本书容器视角对齐）

1. **先测量后动参**：History Server 回放定位最长 stage（01 §3 的检查单保证有日志可放）。
2. **判形态**：CPU 密集 / IO 密集 / shuffle 重——三种病各自的药不同 ⚠️。
3. **动底座级**：容器芯数/内存/个数（§1 三角），对齐队列配额（02 §9 映射表）。
4. **动引擎级**：并行度、广播/倾斜处理（§2）。
5. **复测对比**：记录前后墙钟与资源·秒，而非只看快慢——2016 的「调优日志」就是今天 cost model 数据的雏形 ⚠️。
6. **止损线**：三轮无改善即怀疑数据形态/代码（回指 TDG API 语义），不要陷入参数玄学。

## 11. 「调优对象」三代变迁（⚠️ 讲解框架，收尾视角）

- 第一代（本书 2016）：调**容器与参数**——引擎不自适应，人是优化器。
- 第二代（3.x AQE）：调**开关与预算**——运行时重规划吃掉大半手工分区学。
- 第三代（托管/云 2024–2026）：调**SKU 与 SLO**——形态学交给平台，人管成本与时效目标 ⚠️（方向陈述）。
- 恒常不变层：数据分布（倾斜）、观测先行（先测量后动参）、底座配额意识——本册 🔧 组与 §9 工作流练的就是这三样，跨代有效。

## 核心概念速览（中英对照）

- **执行器芯数** — executor-cores：容器内并行 task 上限；三角约束的第一边。
- **shuffle 分区数** — spark.sql.shuffle.partitions：2.x 默认 200；最常被改错的参数 ⚠️ 时代断言。
- **数据倾斜** — Skew：热键把负载压进单桶；🔧 组 1/6 的类比对象。
- **加盐** — Salting：热键加随机前缀打散再合并的通用手法 ⚠️。
- **广播连接** — Broadcast Join：小表全量下发免 shuffle；容量边界=driver 内存。
- **溢写** — Spill：执行内存不足落盘；shuffle 时代的节点磁盘杀手。
- **自适应查询执行** — AQE（3.x 才有）：运行时重规划分区/连接——本书时代的缺位者，读法见 §7.3 ⚠️。
- **动态分配** — Dynamic Allocation：按负载增减 executor，队列利用率特性。
- **存储内存分数** — storage/execution MemoryFraction：容器内存切分的底座级决策 ⚠️。
- **History 回放** — History Server Replay：调优的观测入口（见 01 §3）。
- **本地盘带宽** — Local Disk Throughput：混部节点第一瓶颈（2016 运维共识 ⚠️）。
- **并行效率** — Parallel Efficiency：🔧 组 5 实测 ≈86% 的对象；单进程类比值，非 Spark 数据。
