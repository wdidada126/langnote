# 第 10 章 附加信息（原书 pp.421-444）

> 执行器里取 `Runnable` 结果、ForkJoinPool 未控异常处理、阻塞队列做生产者-消费者、监测 `Thread`/`Semaphore`、生成并发随机数。本书是「杂项配方拾遗」，补前几章未覆盖的实用钩子。

## 一、本章地图

| 主题 | 关键 |
| --- | --- |
| Runnable 结果 | 用 `FutureTask`/`Callable` 包 Runnable 取结果 |
| ForkJoin 异常 | `getException` / `isCompletedAbnormally` |
| 生产者-消费者 | `BlockingQueue` 解耦（见 7 章/《之美》concepts/阻塞队列） |
| 监测 | JMX `Thread`/`Semaphore` |
| 并发随机数 | `ThreadLocalRandom`（🔧 别用 `Math.random`/`Random` 共享） |

## 二、核心精讲

### 2.1 🔧 `ThreadLocalRandom`
- `ThreadLocalRandom.current().nextXxx()`：每个线程一份种子，**无共享争用**（🔧 `java.util.Random` 内部 CAS 一个原子种子，高并发下是瓶颈；`Math.random` 内部也是共享 `Random`）。

### 2.2 ForkJoin 未控异常
- `ForkJoinTask` 抛异常后用 `isCompletedAbnormally()` / `getException()` 取；`get()` 会重新抛出（🔧 不像 `ExecutorService.submit` 把异常藏在 `Future`，ForkJoin 默认会传播到 `commonPool` 的 `UncaughtExceptionHandler`）。

### 2.3 生产者-消费者用阻塞队列
- `ArrayBlockingQueue`/`LinkedBlockingQueue` 天然解耦生产/消费速度，自带阻塞（🔧 比手写 `wait/notify` 安全；注意 `LinkedBlockingQueue` 默认 `Integer.MAX_VALUE` 是无界，可能 OOM，见《之美》concepts/阻塞队列）。

## 三、版本演进 / 论文 / 前沿

- 论文：JDK 7 引入 ForkJoin + `ThreadLocalRandom`（更易用）；JEP 356（JDK 17）升级 `Random` 默认算法为 LXM（更高质量、更快）。
- 工业界：Disruptor 用环形 buffer 做极高吞吐生产者-消费者（stars 18.5k）；JCTools 提供 `Spsc/Mpsc` 无锁队列（3.9k）。

## 四、常见误区 / 本书需修正之处

| # | 误区 | 修正 |

| 1 | "并发里用 Math.random" | 改用 ThreadLocalRandom |
