# 第 11 章 并发编程设计（原书 pp.445-）

> 设计原则：尽可能用不可变对象、对锁排序避免死锁、用原子变量替代同步。本书收尾章，把前 10 章配方提炼成「设计准则」，与 Goetz 第 2/4 章「线程安全设计」、黄文海 6 章「线程安全设计技术」形成三层呼应。

## 一、本章地图

| 原则 | 要点 |
| --- | --- |
| 不可变优先 | `final` 字段 + 不逸出（见 Goetz 3 章安全发布） |
| 锁排序 | 固定全局顺序获取多把锁，破除死锁环 |
| 原子变量替代同步 | 读多写少用 `AtomicXxx`/`VarHandle` 降低开销 |
| 缩小同步范围 | 开调用（open call）减少持锁时间（见葛一鸣 4 章） |

## 二、核心精讲

### 2.1 不可变对象（immutable）
- 所有字段 `final`、不提供 mutator、构造不逸出 `this`、引用类型也不可变或安全发布（🔧 不可变对象**天然线程安全**，无需同步；是 Goetz「线程安全三策略」之首：不可变/线程封闭/加锁）。

### 2.2 🔧 锁排序避免死锁
- 多把锁按**全局固定顺序**获取（如按对象 identity hash 或显式序号），杜绝 A→B 与 B→A 的交叉等待（🔧 另两招：限时 `tryLock`、单锁替代；死锁检测见黄文海 7 章活性故障）。

### 2.3 原子变量替代同步
- 读多写少、状态简单时，`AtomicInteger`/`AtomicReference` + CAS 比 `synchronized` 读路径无锁（🔧 但复杂复合状态仍要锁或 `StampedLock`；JDK 8+ `LongAdder` 分流高并发计数，见《之美》concepts/LongAdder）。

## 三、版本演进 / 论文 / 前沿

- 论文：Goetz《Java Concurrency in Practice》第 2/4 章；Adve-Hill DRF-SC（TPDS'93，数据竞争自由即顺序一致）；Hewitt Actor 模型（不可变消息，IJCAI'73）。
- 工业界：Immutables/Lombok `@Value` 自动生成不可变类；Vavr/Functional Java 提供持久化不可变集合；kotlinx `immutable` 模块。
- 前沿：JDK 21 虚拟线程 + 结构化并发（JEP 453/505），把「显式锁设计」大量替换为「作用域取消 + 不可变数据传递」，设计层进一步简化。

## 四、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "final 字段=不可变" | 引用字段也要不可变/安全发布 |
| 2 | "多锁随便获取" | 固定顺序，否则死锁 |
| 3 | "原子变量万能" | 复合状态仍要锁/StampedLock |
| 4 | "构造里 publish this" | 逸出导致部分构造可见 |
| 5 | "2026 还手写锁" | 优先虚拟线程+结构化并发+不可变 |
