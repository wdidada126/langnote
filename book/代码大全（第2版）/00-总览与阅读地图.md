# 《代码大全（第 2 版）》总览与阅读地图

> **一句话**：这本书把「写代码」从玄学还原成一门可以拆解、可以训练、可以度量的工艺——全书写的是构造，但真正的主题是**复杂度管理**。
> 原书 *Code Complete: A Practical Handbook of Software Construction*, 2nd ed., Steve McConnell, Microsoft Press, **2004-06-09**，960 页，ISBN **978-0-7356-1967-8**（电子版 978-0-7356-9125-4）。
> 第 1 版 1993，ISBN 978-1-55615-484-3，获 1993 年 Jolt Award。

**大纲版在此**：`book/代码大全.md`（含完整中译目录的 Rapid Recap 式单文件）。**本目录是深度重写版**，两者并存、互链；大纲版不做删除、不做修改，本目录承担全部深度笔记内容。

> 关于版本的一处更正：任务书里写的「中译本清华大学出版社 **2022-07**」，经 WebSearch 核实，实际印次为 **2022-06**（纪念版，ISBN 9787302583646）；另有 **2026-04** 的「普及版」，ISBN 9787302712091。两者目录完全一致（第 1–34 章 + 第 35 章「更多信息来源」），本文以纪念版为准。

## 4. 本书刻意规避 / 未覆盖的缺口

顺带说清「它不回答什么」，避免读者把 900 页当百科全书用：

- **不做架构级设计**：Ch5 的设计启发式停在「类与子程序」这一层。真正的模块边界、依赖方向、分层与端口适配器，请看 `book/架构整洁之道*`、`book/软件架构设计/`（相关散篇）。本书明确说「架构不是它的主题」。
- **不展开并发与并行的构造细节**：第 2 版写于 2004 年，多线程只有粗浅小节。想看正确写法请看 `book/C++并发编程实战2/` 或 `book/多处理器编程的艺术2/`。
- **不覆盖数据科学与 ML 系统**：没有特征管道、没有实验管理、没有训练/服务一致性（training-serving skew）。ML 系统的问题域与本书假设的「一次性交付的软件」差别很大。
- **不做形式化与类型论**：它的「正确性」是工程意义的，不是证明意义的。
- **不做需求工程的学科展开**：Ch3 只有半章，需求的质量属性只有清单式总结。
- **不做性能工程**：Ch25/26 只讲「代码调整」，不含性能剖析方法论、缓存层次、SIMD、内存分配器调优。

## 6. 跨书对照表：这本讲什么，那些讲什么

一句话分工：**代码大全 = 构造工艺，代码整洁之道 = 可读性，重构 = 安全重组，架构整洁之道 = 依赖方向。**

| 关注面 | 本书（第 2 版） | 邻近笔记 | 分工 |
| --- | --- | --- | --- |
| **构造工艺** | ✅ 全覆盖，且是全书的唯一主场 | — | 本书给出从需求前置到 daily build 的**全过程工艺**；其他书都只取其中一段 |
| **可读性** | Ch31 布局、Ch32 自文档代码（注释策略） | `book/代码整洁之道/`（Bob 大叔 *Clean Code*，2008）+ 散篇 `book/C++代码整洁之道.md` | 本书是**百科式**列举「有什么招」；《代码整洁之道》是**主张式**「就这么办」，更少但更狠。建议本书读完后用它做清单自查 |
| **安全重组** | Ch24 重构（策略、安全重构、何时重构） | 原书 *Refactoring*（Fowler et al., 1999；第 2 版 2019）；本仓库暂无单独目录，相关散篇为 `book/大话重构.md`、`book/Java程序员修炼之道.md` | 本书讲**什么时候该动、怎么判断值得动**；Fowler 讲**动的具体手法目录与自动化守卫**。两者互补，本书偏判断，Fowler 偏手法 |
| **依赖方向** | Ch5 只到「类与包」层次，不做依赖方向论证 | `book/架构整洁之道/`（Bob 大叔 *Clean Architecture*，2017） | 本书的「信息隐藏」是**模块内**的；架构整洁之道处理的是**跨模块**的控制反转与依赖单向。本书是它的前置，不是替代 |
| **模式词汇** | Ch5.3「查阅常用的设计模式」点到为止 | `book/设计模式GoF/` | GoF 提供**命名与结构词汇**，本书提供**何时不该用它**的判断经验（第 2 版明确警告过度使用继承与模式） |
| **语言与求值** | 示例语言陈旧（C++03 / Java 1.4 时代） | `book/计算机程序的构造和解释（原书第2版）/` | SICP 讲的是**抽象与求值的心智模型**，与本书的**工程惯例**互补；读 SICP 让人理解「为什么递归与高阶函数有效」，读代码大全让人知道「怎么把它写进团队规范」 |

## 8. 写作约定

每个章节文件固定七个小节：

1. `## 本章地图`（表格：节 | 内容 | 结论）
2. `## 核心精讲`（含教学示意代码，**不编译、不运行、不参与构建**）
3. `## 版本演进`（第 2 版相对第 1 版的修订 + 2015–2026 新发展）
4. `## 经典论文与原始文献`（表格：论文 | 出处 | 贡献，**全部真实可查**）
5. `## 近年研究与工业界开源实践（2015–2026）`（趋势 + 表格，star 用 `gh api` 实测）
6. `## 常见误区与本书需修正之处`（表格 ≥5 行，若干行以 🔧 开头）
7. `## 与其他章 / 其他书的联系`

> **阅读本书的正确姿势**：不要把 900 页线性读完。先读 Ch1–Ch5 建立框架，再按手头问题跳读 Ch10–Ch13（变量）、Ch14–Ch19（语句）、Ch31–Ch32（布局与注释）三块，最后回 Ch20–Ch24（质量、协同、调试、重构）形成闭环。每章末尾的 check-list 是本书真正的交付物。
