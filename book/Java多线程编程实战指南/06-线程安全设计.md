# 第 6 章 保障线程安全的设计技术（原书 pp.240-272）

> **设计层保障线程安全**：从源头减少同步需求——不可变对象、线程封闭、栈封闭、委托、开放调用。与《实战》4 章"组合对象"互补，本书把它们系统化成"设计技术清单"。

## 一、本章地图

| 技术 | 关键 |
| --- | --- |
| 不可变对象 | `final` 字段 + 不暴露引用 → 天然线程安全（见《艺术》3 章 final） |
| 线程封闭 | 仅单线程访问（栈封闭 / ThreadLocal） |
| 栈封闭 | 局部变量不逃逸 → 无需同步 |
| 委托 | 把线程安全委托给已有线程安全组件（ConcurrentHashMap 等） |
| 开放调用 | 不在持锁时调用外部方法（避免死锁/存活问题） |
| 同步集合 | `Collections.synchronizedXxx` vs `ConcurrentXxx`（后者更高并发） |

## 二、核心精讲

### 2.1 不可变对象（最省心）
- 所有字段 `final`、引用对象也不可变、构造器 `this` 不泄漏 → 跨线程可见且不可改（JSR 133 final 语义）。
- 例：`String`、`Integer`、值对象 DTO。

### 2.2 线程封闭
- **栈封闭**：局部变量在线程栈，天然不共享。
- **ThreadLocal**：线程私有副本（🔧 线程池下 value 强引用泄漏，见《之美》ThreadLocal 专篇；现代用 `ScopedValue` JDK 25）。
- **Ad-hoc 封闭**：靠"约定"不共享 → 脆弱，不推荐。

### 2.3 委托
- 组合多个线程安全组件，且组件间无跨组件不变性 → 整体线程安全（如类含 `AtomicLong` + `ConcurrentHashMap`）。
- 若有跨组件不变性（如"size 必须 == map.size()")，需额外锁。

### 2.4 开放调用（避免嵌套锁）
- 持锁时不调用外部（可重写）方法 → 防止"协作对象间死锁"（见《实战》10 章）。
- 用 `Collections.unmodifiableXxx` / 防御性拷贝控制发布。

## 五、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "加了锁才安全" | 不可变/封闭更安全且无开销 |
| 2 | "final 一定安全" | 构造器 this 泄漏则失效 |
| 3 | "ThreadLocal 无泄漏" | 池下 value 强引用泄漏；remove/ScopedValue |
| 4 | "synchronizedXxx 够用" | 高并发用 ConcurrentXxx |
| 5 | "持锁调用外部方法没事" | 可能死锁；用开放调用 |
