# 第 5 章 线程间协作（原书 pp.179-239）

> 线程间通信机制全景：`wait/notify`、`Condition`、生产者-消费者、栅栏、流水线、自定义同步器。与《艺术》4 章 + 《实战》14 章互补，本书重"协作模式与陷阱"。

## 一、本章地图

| 机制 | 语义 |
| --- | --- |
| `wait/notify/notifyAll` | 监视器条件变量；必须 `while` 判条件谓词 |
| `Condition` | 多等待集；优于 `wait/notify` |
| 生产者-消费者（流水线） | 队列解耦阶段 |
| 栅栏/门闩 | `CyclicBarrier`/`CountDownLatch`（见《艺术》8 章） |
| 自定义同步器 | 基于 AQS（见《艺术》5 章） |

## 二、核心精讲

### 2.1 `wait/notify` 四道鬼门关（与《艺术》4/《实战》14 章一致）
- **必须 `while` 判条件谓词**（过早唤醒 + 被抢）；**必须配 `synchronized`**；`wait` 释放锁；`notifyAll` 更安全。
- 经典误用：用 `if` 判、忘了配锁、用 `notify` 漏唤醒。

### 2.2 `Condition` 优于 `wait/notify`
- 一个 `Lock` 多等待集；`await`/`signal` 语义清晰；推荐新代码用。

### 2.3 协作模式
- 流水线：阶段间用阻塞队列；阶段失败传播（用 `CompletableFuture` 链，见第 9 章）。
- 🔧 现代替代：结构化并发 `StructuredTaskScope` 把"多子任务协作"变成作用域级（JEP 453/505）。

## 三、版本演进 / 论文 / 前沿

- Hoare "Monitors" (CACM 1974)；JEP 453/505（结构化并发）。
- 开源：RxJava 48k / kotlinx 13.8k（响应式替代 wait/notify 的"等通知"）。

| # | 误区 | 修正 |
