# 第 2 章 多线程编程的目标与挑战（原书 pp.31-79）

> **本书独有的"价值观"章节**：开宗明义讲清楚"为什么要用多线程、它要付出什么代价"。把"正确性、安全性、活跃性、性能"作为并发程序的四个目标，并逐一列出挑战。这是 Goetz《实战》第 1 章的工程化展开。

## 一、本章地图

| 主题 | 关键 |
| --- | --- |
| 四个目标 | 正确性（结果对）/ 安全性（无_invariants 被破坏）/ 活跃性（该发生总发生）/ 性能（快+可伸缩） |
| 三个挑战 | 安全性（竞态）/ 活跃性（死锁活锁）/ 性能（开销） |
| 串行 vs 并行 | 单线程正确性简单，但吞吐受单核限；并发换吞吐但引入三者挑战 |
| 上下文切换/内存开销 | 线程不是免费午餐（见《艺术》1 章） |

## 二、核心精讲

### 2.1 四个目标
1. **正确性**：单线程下结果正确。并发下仍要正确（无数据竞争）。
2. **安全性（线程安全）**：无不变性被违反（如计数器不丢更新、对象不半构造）。
3. **活跃性**：死锁/活锁/饥饿之外，期望"该发生的总发生"（任务终会完成）。
4. **性能**：吞吐与可伸缩性（Amdahl，见《实战》11 章 + 之美 Amdahl 专篇）；并发的"代价"在此显现。

### 2.2 三大挑战对应三对矛盾
- 安全性挑战 → 竞态（Race）：交错导致不变性破坏。
- 活跃性挑战 → 死锁/活锁/饥饿：大家都动不了或谁都过不去。
- 性能挑战 → 上下文切换/同步开销/内存可见性强制的屏障：并发反而更慢（争用高时）。

### 2.3 关键结论
- 并发不是"默认更快"：只有**有并行度且同步开销可控**时才更快（见《实战》11 章 Amdahl）。
- 设计优先级：**先正确性/安全性，再活跃性，最后性能**。为性能牺牲安全是头号错误。

## 三、版本演进

- 始终是并发编程的不变框架；JDK 21 虚拟线程降低了"线程贵"带来的性能挑战，但安全性/活跃性挑战不变。

## 六、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "并发一定更快" | Amdahl：有串行部分就到不了线性 |
| 2 | "先优化性能" | 先安全/活跃，否则测得越快错得越离谱 |
| 3 | "能跑就正确" | 竞态只在特定交错出现；用测试/工具验证 |
| 4 | "性能问题靠加线程" | 受资源/争用；可能更慢 |
