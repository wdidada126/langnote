# 第 3 章 Java线程同步机制（原书 pp.80-147）

> 同步机制的"全景"：内置锁 `synchronized`、显式锁 `Lock`/`ReentrantLock`、读写锁、`volatile`、原子变量、CAS——对比各自语义、开销、适用。与《艺术》5 章（源码）/《实战》13-15 章（设计）互补，本书重"怎么选"。

## 一、本章地图

| 机制 | 语义 | 适用 |
| --- | --- | --- |
| `synchronized` | 互斥+可见，JVM 托管 | 大多数互斥场景（默认首选） |
| `ReentrantLock` | 可中断/超时/公平/多条件 | 需高级特性时 |
| `ReentrantReadWriteLock` | 读写分离 | 读多写少 |
| `volatile` | 可见+有序（非原子） | 状态标志/单写多读 |
| 原子变量/CAS | 无锁原子 | 热点计数/无锁结构 |
| `StampedLock` | 乐观读 | 🔧 读极频繁 |

## 二、核心精讲

### 2.1 `synchronized`：默认首选
- 优点：JVM 托管（不会忘 unlock）、JDK 6 后性能已追平 `ReentrantLock`（轻量级/自旋/消除/粗化）。
- 缺点：不可中断、无超时、非公平、单一条件队列 → 需这些时用 `Lock`。

### 2.2 显式锁的选择（与《实战》13 章一致）
- 只在需要"定时/可中断/公平/多条件"时用 `ReentrantLock`。
- `ReentrantReadWriteLock`：读多写少提速；写频繁/写饥饿时更慢 → 🔧 考虑 `StampedLock` 乐观读（JDK 8）。

### 2.3 `volatile` vs 锁（与《艺术》2/3 章一致）
- `volatile`：可见+有序，**不原子**；适合状态标志（如 `volatile boolean stopped`）、单写多读。
- 复合操作（`i++`、check-then-act）必须锁或 `Atomic*`。

### 2.4 原子变量与 CAS（与《艺术》7 章 / 《实战》15 章一致）
- `Atomic*`：无锁原子，高争用热点用 `LongAdder`（分段）。
- CAS 自旋有开销；ABA 用 `AtomicStampedReference`。
- 🔧 `Unsafe` JDK 21+ 废弃 → `VarHandle`（JEP 193/471/498）。

## 三、版本演进

- **JDK 5**：`Lock`/`Atomic*` 引入。
- **JDK 6**：`synchronized` 性能反超（偏向/轻量级/自旋/消除）。
- **JDK 8**：`StampedLock`/`LongAdder`。
- **JDK 9**：`VarHandle`。
- **JDK 15+**：偏向锁移除（JEP 374）；**JDK 21+**：`Unsafe` 废弃，虚拟线程下 `synchronized` pin 平台线程（JDK 24 起多数已解）。

## 六、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "Lock 更快所以用 Lock" | JDK 6+ synchronized 更快且不易漏解锁 |
| 2 | "volatile 原子" | 只可见+有序；i++ 非原子 |
| 3 | "读写锁一定快" | 写频繁更慢；考虑 StampedLock 🔧 |
| 4 | "AtomicLong 可伸缩" | 热点用 LongAdder |
| 5 | "手写 Unsafe" | 🔧 JDK 21+ 废弃；VarHandle |
| 6 | "虚拟线程照用 synchronized" | 会 pin；JDK 24 起多数已解，否则用 Lock |
