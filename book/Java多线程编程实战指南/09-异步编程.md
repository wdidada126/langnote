# 第 9 章 Java异步编程（原书 pp.333-359）

> 异步编程演进：回调 → `Future` → `CompletableFuture` → 响应式。与《之美》`concepts/CompletableFuture与异步编排.md` + 冷血第 8 章互补，本书重"为什么异步 + 模式选择"。

## 一、本章地图

| 方式 | 语义 | 痛点 |
| --- | --- | --- |
| 回调 | 完成时调函数 | 回调地狱（嵌套） |
| `Future` | `get()` 拉结果 | 阻塞、不能组合 |
| `CompletableFuture` | 推式 + 组合 | 异常沿链、线程模型 |
| 响应式 | `Flow`/RxJava | 学习曲线、背压 |

## 二、核心精讲

### 2.1 从回调到 `CompletableFuture`
- 回调地狱：多层嵌套回调难读难错。
- `CompletableFuture`：`thenApply`/`thenCompose`/`thenCombine`/`allOf`/`anyOf` 链 + `exceptionally`/`handle` 异常传播（详见《之美》专篇 / 冷血第 8 章手写）。
- 线程模型：默认 `ForkJoinPool.commonPool()`，或用 `Executor` 参数；`*Async` 不带 Executor 可能由调用者执行。

### 2.2 响应式（JDK 9 `Flow`）
- `Publisher`/`Subscriber`/`Subscription`/`Processor` + 背压（`Subscription.request(n)`）。
- 实现：RxJava（48k）、Reactor（5.2k）。
- 适用：高吞吐流式；代价：调试难、栈迹丢失。

### 2.3 🔧 现代替代
- 虚拟线程让"异步"部分回归"同步写法"（`await` 由 JVM 挂起，不占平台线程）→ 许多回调/CompletableFuture 场景可回归直写（JEP 444）。
- 结构化并发 `StructuredTaskScope` 替代"`CompletableFuture` + 手动异常/取消"（JEP 453/505）。

## 三、版本演进

- **JDK 5**：`Future`。**JDK 8**：`CompletableFuture`。**JDK 9**：`Flow`（响应式流规范）。**JDK 21+**：虚拟线程 + 结构化并发。

## 六、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "异步一定快" | 仅释放线程才有收益；CPU 密集无 |
| 2 | "get() 不卡" | 阻塞；设超时 |
| 3 | "异常自动处理" | 沿链；用 exceptionally/handle |
| 4 | "新代码全用 CF" | 批量改 StructuredTaskScope；IO 可回归虚拟线程直写 |
