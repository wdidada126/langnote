# 第 10 章 Java多线程程序的调试与测试（原书 pp.360-377）

> 并发程序的"可观测性"：打印/调试器在并发下不靠谱，要靠线程 dump、JFR、jcstress。与《实战》12 章（测试方法论）互补，本书重"调试实战 + 工具清单"。

## 一、本章地图

| 手段 | 用途 |
| --- | --- |
| `jstack`/`jcmd` | 线程栈 / 死锁自动报告 |
| 日志 + 线程名 | 区分线程上下文（MDC） |
| JFR | 生产低开销录制：锁等待/阻塞/GC |
| jcstress | JMM / 内存可见性模糊测试 |
| 断点调试 | 并发下会改变时序，慎用 |

## 二、核心精讲

### 2.1 `jstack` / `jcmd`
- `jstack <pid>` 看所有线程栈；`jcmd <pid> Thread.print` 等价。
- 自动检测 Java 级 monitor 死锁（含等待链）；`ReentrantLock` 死锁看 "ownable synchronizers" 段或 JFR。

### 2.2 日志与线程上下文
- 用 `Thread.getName()` 带业务 ID；日志框架 MDC 注入线程/请求上下文（🔧 虚拟线程下 MDC 传递要注意，用 `ScopedValue` 更稳）。

### 2.3 JFR（生产级）
- JDK 9+ 开源；低开销持续录制，看"锁等待/阻塞/ GC 停顿/ 分配"三位一体 → 定位"卡在哪"。

### 2.4 jcstress（验证 JMM）
- 专门模糊测试 happens-before / volatile / final / 原子类；多架构 CI 跑（见《实战》12 章 + 之美测试方法论专篇）。

### 2.5 调试器陷阱
- 断点/单步会**改变调度时序**，让竞态"消失" → 用日志 + dump + jcstress，而非单步。

## 三、版本演进

- **JDK 5**：`jstack`。**JDK 9**：JFR 开源。**JDK 8**：JMH（微基准）。**JDK 21+**：jcstress 多架构。

## 六、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
