# 第 7 章 线程的活性故障（原书 pp.273-309）

> **本书特有亮点章**：把"程序卡住"系统分类——死锁、锁死（lock-ordering 外的变体）、活锁、饥饿，并给出诊断与规避。与《实战》10 章互补，本书补"故障分类学 + 实战诊断"。

## 一、本章地图

| 故障 | 定义 | 规避 |
| --- | --- | --- |
| 死锁 | 循环等待锁，全卡住 | 锁定序 / 超时 `tryLock` / 一次性申请 |
| 锁死 | 等待永远不成立的条件（如 `wait` 无人 `notify`） | 保证终会通知 |
| 活锁 | 都忙但谁都前进不了（互相谦让） | 退避 + 随机 |
| 饥饿 | 一直拿不到资源（低优先级/不公平） | 公平锁 / 提优先级 |

## 二、核心精讲

### 2.1 死锁（与《实战》10 章一致）
- 四必要条件：互斥、占有且等待、不可剥夺、循环等待。
- 规避：① **锁定序**（全局统一顺序，破坏循环等待）；② **超时**（`tryLock(timeout)`，破坏"占有且等待"）；③ 一次性申请全部资源。
- 诊断：`jstack`/`jcmd Thread.print` 自动报告 Java 级 monitor 死锁。

### 2.2 锁死（Lock-Convoy / 条件永不成立）
- 线程 `wait()` 等待某条件，但逻辑上该条件**永远不会被其他线程置真**（如通知逻辑 bug）→ 永久等。
- 与死锁区别：死锁是"互相等对方释放锁"，锁死是"等一个永不发生的信号"。

### 2.3 活锁（Livelock）
- 两线程不断"检测冲突→退让→又冲突"，都在运行但谁也完不成（如两个礼貌的人互相让门）。
- 规避：退避 + 随机抖动（避免同步退让）。

### 2.4 饥饿（Starvation）
- 低优先级线程/不公平锁下长期拿不到 CPU 或锁 → 一直不能前进。
- 规避：公平锁、`ReentrantLock(true)`；避免持有锁做重活。

## 三、版本演进 / 论文 / 前沿

- Goetz《实战》10 章；Holt "Comments on Deadlock" (1971)；Dijkstra 资源分配图。

## 五、常见误区 / 本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "死锁只能重启" | jstack 定位 + 定序/超时预防 |
| 2 | "wait 总会被唤醒" | 锁死：信号永不至；保证终会 notify |
| 3 | "活锁是死锁" | 活锁线程在跑但无进展；加随机退避 |
| 4 | "高优先级一定不被饿" | 仍可能；用公平锁 |
| 5 | "新代码手写锁编排" | 结构化并发作用域取消，避免卡死 |
