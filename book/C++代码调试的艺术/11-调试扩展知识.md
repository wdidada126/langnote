# 11 调试扩展知识（对应原书第 11 章）

> 对应原书第 11 章「调试扩展知识」（✅ 章名双源核实）。节级目录（⚠️ 据豆瓣阅读电子书页 TOC）：
> 11.1 Windows驱动开发调试入门、11.2 WinDbg简介、11.3 Linux内核驱动开发简介、
> 11.4 Linux内核转储文件调试分析。豆瓣第 2 版页摘要另示 VS2022 调试新特性内容（约当本章末节 ⚠️ 节号未核实）。
> 用户态调试器技能在本章全部「升一层」：目标从进程变成内核，扰动从卡顿变成蓝屏。

## 核心概念速览（中英对照）

- **内核调试** — kernel debugging：调试器与目标内核经串行/网络(1394/以太网)/KDNET 通道连接；
  WinDbg 是 Windows 正统，gdb(+kgdb)/crash 是 Linux 两大件。
- **内核模式转储** — memory.dmp（Windows）/ vmcore（Linux kdump）：整机崩溃快照；分析工具与符号体系与用户态**不通用**。
- **WinDbg** — 微软调试 shell：`!` 扩展命令生态（ext.dll/kdext.dll），表达式语言+数据模型查询（DML）。
- **WDF/WDM** — Windows 驱动框架：KMDF 对象（WDFDEVICE…）带专用调试扩展 `!wdfkd`；驱动崩溃域 IRQL/paging behavior 概念。
- **kd> 命令谱** — `k`栈 `lm`模块 `!analyze -v`自动归因 `dt`类型 dump `!pool`堆 `!irp` IO 请求包：驱动调试黑话表。
- **kdump/kexec** — Linux 崩溃后转储机制：第一内核预留 crashkernel 内存，panic 时 kexec 进捕获内核写出 vmcore。
- **crash 工具** — Linux 内核 vmcore 分析器（crash 项目）：`bt`/`ps`/`files`/`dev -d`/`log`——用「内核数据结构视图」读转储。
- **kgdb** — 内核 gdb 前端：早经串口 + `early_param debug`，今多走 kdb 内壳；活体内核单步会锁死调度——观察点慎用。
- **LOCKDEP/KASAN** — 内核自带 Sanitizer 群 ⚠️（与本书第 6 章同思想的内核实现）：启动参数开，抓锁序反例与越界。
- **驱动签名/测试签名** — Windows 驱动调试的现实门槛：`bcdedit /set testsigning on` 是本地实验标配。
- **VS2022 调试新特性** — 第 2 版增量 ⚠️（摘要级）：临时断点、依赖断点等（第 2 章演进节已展开，此处只作版本落点）。

## 动机：为什么「扩展知识」其实是「边界知识」

用户态调试器的所有便利（随便暂停、看变量、进程死了无所谓）在内核态一笔勾销：

1. **暂停=全系统冻结**：断点挂起时看门狗超时、集群摘除、磁盘缓存不刷——gdb 式「停在循环里观察」在内核等于制造事故；
2. **崩溃=整机**：DPC_WATCHDOG/IRQL 违规/内核空指针直接 BSOD/panic，现场只存在于转储里；
3. **符号=另一套宇宙**：内核 PDB/vmlinux 与用户态 DLL/ELF 不通用，WinDbg/crash 的「类型即视图」
   （`dt _EPROCESS`）要求你**读数据结构而非读源码行**。

所以本章的正确打开方式不是学写驱动（那是 WDK/Linux 内核书的领域），而是获得**边界感**：
知道哪类问题的现场在内核侧、用什么命令取、以及为什么取现场本身就是一门工程。

## 机制：四条内核取证线

### Windows 活体线（11.1+11.2 前半）

```text
🔧 目标机: bcdedit /set debug on /set testsigning on; 配 netkd (以太网 KD)
🔧 主机:   WinDbg → File→Kernel Debug→Net → 连上即 kd>
kd> !analyze -v              ← 蓝屏后先分析转储，活体抓现行
kd> lm                       ← 已载驱动与地址区间（第 5 章模块视图的内核版）
kd> dt nt!_KTIMER 0xffff...   ← 类型化读内存：DWARF/PDB 的裸威力展示
kd> !wdfkd.wdfdevicetree      ← 框架对象树（KMDF 专属）
kd> !irp 0xffff...            ← IO 请求包排队/卡点：设备 hang 的锁持有图等价物
```

第 10 章的 Win32 调试 API 在这里换成 **KdDebuggerDataBlock**+串口/网络 KD 协议——事件循环的宿主从
「调试器进程」换成「第二台机器的内核钩子」，模型同源（这是把本书 2/10 章串起来的那根线）。

### Windows 事后线：蓝屏转储

`C:\Windows\Minidump\*.dmp`（小）/ `MEMORY.DMP`（全）——WER 的内核分支；`!analyze -v` 的
`BUGCHECK_CODE`/`FAILURE_BUCKET_ID` 是搜索的钥匙。驱动级分析必备 PDB 链：微软符号服务器给系统件，
自家驱动 PDB 进同一符号路径（第 2/9 章符号纪律的内核延伸）。

### Linux 事后线（11.4，工业主力）

```bash
🔧 崩溃侧: 内核带 CONFIG_KEXEC/KDUMP；crashkernel=256M 预留；systemctl status kdump
🔧 产物:    /var/crash/127.0.0.1-2026-.../vmcore + vmcore-dmesg.txt
🔧 分析:    $ crash /usr/lib/debug/.../vmlinux-$(uname -r) vmcore
crash> bt          # panic 栈（符号化要求 vmlinux/debuginfo 版本严格匹配——第 9 章 build-id 教训的内核版）
crash> log | tail  # 最后 dmesg：panic 前先知道谁在抱怨
crash> ps -m; files <task>   # 以内核数据结构为视图的「进程列表/打开文件」
```

`crash` 的哲学与 gdb 对 core 完全不同：**它不映射源码行，而是重放内核的链表/radix-tree 原语**
（`list`/`tree` 命令族）。第 4 章的「锁持有图」在内核态的对应物即 `bt` + `rq` 自旋锁字段考古。

### Linux 活体线（kgdb/kdb，慎用）

`nokaslr`+`kgdboc=ttyS0,115200 kgdbwait` → gdb 连串口（第 7 章远程拓扑的原教旨版）。
kdb 的 `cmdline`/`lr`（回溯）在调度断点里救急；**活体内核下软件断点改的是只读映射区，
kgdb 有特殊 patch 通道**（第 10 章字节改写机制的内核注脚）。

## 权衡：内核问题何时不该上调试器

| 症状 | 首选 | 原因 |
| --- | --- | --- |
| 蓝屏/panic（已死） | 转储分析（kd/crash） | 现场唯一入口 |
| 偶发 hang/延迟 | 采样/追踪（ETW+wpr、perf/ftrace/bpftrace） | 断点扰动不可接受（第 4 章同源教训的内核版） |
| 驱动泄漏/UAF | Driver Verifier / KASAN（第 6 章护栏的内核版） | 「当场断」范式，不靠人 |
| 锁序告警 | LOCKDEP 日志 | 编译器/内核已替你建了锁图 |

**分工原则**：调试器抓「确定性单次事故」，追踪系统抓「概率性时序」，Sanitizer 抓「不变量违背」——
本章四类问题按此归位，比「先开 WinDbg 再说」高效一个数量级。

## 相邻概念对比

- WinDbg vs gdb：同为 CLI 正统，WinDbg 赢在**数据模型**（`dt`+扩展命令把 OS 结构当类型系统暴露），
  gdb 赢在**语言求值**（表达式/Python）；新蓝 WinDbg 在补 gdb 式脚本短板（.nettrace/时间旅行）。
- crash vs gdb-on-vmcore：前者内核对等物，后者会把内核地址当用户地址问——行号可看、结构不可导航 ⚠️ 表述凭记忆。
- TTD（WinDbg Time Travel Debugging）：用户态进程级 rr（第 6 章演进）——`tt -t` 录制 trace 后可
  `g -` 倒带；它与 rr 是本章「边界外」的最后一块拼图：**回放调试已是两家平台各自的标配**。
- rr/Intel PT/eBPF/TTD 四者在「事后现场」上的取舍矩阵散见各章演进节，此处总装：
  确定性回放（rr/TTD）> 硬件轨迹（PT，生产可用但需解码）> 观测注入（eBPF，最广但只有你预埋的点）。

## 最新演进与工业实践

- **WinDbg 统一化**：微软把 WinDbg 作为 Windows 调试的单一门面（microsoft/windebug 仓库开源化开发，
  经典引擎+新 UI），用户态/内核态/转储/TTD/DUMPGB 全在一个 shell——原书 11.2「WinDbg 简介」在 2026
  的等价教程入口。
- **Linux 内核可观测合流**：eBPF（iovisor/bcc、libbpf）把「内核调试」日常化为**生产可常驻**的追踪层；
  bpftrace 一行 `kprobe:vfs_read` 顶过去半本 kgdb 教程——但结构性取证（vmcore）仍归 crash。
- **云厂商 crash 管线**：GCP/AWS 实例 panic → 自动 kdump → 对象存储 → 符号匹配（按内核版本仓）——
  第 8 章崩溃平台的内核镜像，debuginfod 机制同样服务于此（第 9 章）。
- **Windows 驱动工程**：WDF 驱动 + 测试签名 + `!wdfkd` 仍是硬件行业的日常；但微软战略重心向
  **用户态驱动化（UMDF）+ 硬件抽象**迁移——内核态 bug 面在收缩（⚠️ 趋势判断为本笔记观点）。
- **VS2022 侧（第 2 版增量 ✅ 摘要级）**：临时/依赖断点、异常设置模块化过滤——第 2 章演进节的清单在
  内核调试里**没有对位物**（WinDbg 生态自给自足），这是「IDE 调试器有天花板」的又一证据。
