> ⛔ 全档基于 2012 前代语境起算（*Pro TypeScript*，Fenton，Apress 2012，TS 0.8 前夜）；本档从 0.8 出发看十一年演化。
> ⚠️ 凡 0.8 时代细节凭记忆，以原书影印/版权页为准；**全部年代/版本号凭记忆，未破墙，整档 ⚠️**。
> 证据三态：✅=本机 node v22.14 `--experimental-strip-types` 实测｜⚠️=记忆/推断｜🔧=可复演实验位。

## 一、0.8 语境锚点

2012 年的 TS：基元 + `any` + 不推断的泛型雏形 + 自家 `class/module/enum`。今天年表里的一切尚未发生（机制清单见 02 档）。⚠️
- 00 档「差异猎奇」读法对本档同样管束：判读产出是「现代读者 6 小时穿过 2012」的地图，不是现代机制教科书的替身。
- 本书 2012 年的读者无法预见：类型层日后会长成自成一门的语言——本档回答「爆发为何在那个时间窗」（why），「爆了什么」在 02 档（what）。⚠️ 判读

## 二、阶段分段（Stroustrup 年表读法迁移 ⚠️）

| 阶段 ⚠️ | 标签 | 代表机制 |
|---|---|---|
| 0.8–1.x | 语法奠基期 | 泛型雏形、联合 1.4、字面量 1.8、`as` 与 `<T>` 并立 |
| 2.0–2.8 | 严格性+ratchet 期 | `strictNullChecks`、`--strict` 聚合、映射 2.1、条件 2.8 |
| 3.0–3.9 | 推断深化期 | `unknown`、元组参与泛型/rest、`const` 断言 3.4 |
| 4.0–4.x | 模板化爆发期 | 模板字面量类型、递归条件、key remapping、变长元组（4.1 为震中 ⚠️） |
| 5.x | 原生对齐期 | 标准装饰器、与 TC39/Node 擦除管线合流（`--experimental-strip-types` 即此段产物 ✅） |

## 三、演化判读：为何 3.0→4.x 是推断与模板化的爆发期（⚠️ 全节为归纳，非一手）

1. **前置件齐备论**：条件类型（2.8）+ 映射 over 元组（3.1）+ `const` 泛型（3.4）恰是模板字面量类型（4.1）的三块前置件——爆发不是灵感而是**依赖链凑齐**，与 C++「模板机制先于概念库」的错峰演化同构。⚠️
2. **需求压强论**：React/Redux/Vue 级大型库要在类型层复刻 API 形状（路由名、action 名、i18n key），`any` 逃生口在 strict 普及后不够用——类型层语言从「描述数据」被推向「计算字符串」，4.1 一版连发模板字面量+递归条件+key remapping 即压强释放。⚠️
3. **兼容红利论**：TS 的铁律是「类型层随便加、JS 语法不许破」（对照 C++ 为兼容背 ABI 债）——纯擦除架构使每次类型层创新**零运行时成本**，演化速率因此远高于宿主语言；本仓 ✅ 实测（01 档第 2 条）证明 2012 代码换断言写法即在今日原样跑，兼容律的直接印证。⚠️ 判读
4. **ratchet 单向性**：`strictNullChecks` 之后每一版把「默认宽松」向「默认严格」拧一格，推断类特性（收窄、控制流分析）恰好只在严格环境下发光——爆发期与 ratchet 期重叠不是巧合。⚠️
5. **演化不必皆为加法**：C++ 的 1985–1993 是特性沉积期，TS 的 4.x 是类型层沉积期，而 5.x 反成「减法期」——标准化装饰器替换私货、与原生 JS/Node 管线合流、逐步把语法主权还给 TC39。对照 Stroustrup 年表读法，这是「沉积→收束」两拍节奏的又一实例。⚠️ 归纳
- 反事实注脚：若 Anders 2012 年就把条件类型放进 0.8，本书Ⅲ部会直接变成《Type Level TypeScript》的前身——时代差距是机制差距，不是智力差距。⚠️ 修辞
