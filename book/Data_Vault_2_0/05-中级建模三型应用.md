# 第 5 章 中级建模：三型的应用（Intermediate Data Vault Modeling）

> 目录取证：章题与 5.1 Hub Applications / 5.2 Link Applications / 5.3 Satellite Applications ✅ 实抓自 Elsevier 官方 TOC。正文为精读重构，模式口径以 DV 2.0 公开标准为据。

## 1. 本章定位

第 4 章给出三型的「宪法」，本章是三型的「判例法」：真实世界里每个型体都有若干合法变体，用对则模型十年不改，用错则退化成 ER 泥潭。按官方小节三分法组织。

## 2. 5.1 Hub 应用（✅）

- **角色扮演（Role Play）**：同一 Hub 在不同关系中以不同身份出现（客户既是「购买者」又是「推荐人」）。规则：**不复制 Hub 表**，在 Link 的不同成员槽位引用同一 `hk_customer`；集市层需要「Buyer Customer」「Referrer Customer」两种维度时再各自展开。
- **多源业务键**：CRM 的 `C1` 与大机的 `0000000C1` 是否同一人？**先各自建 Hub 行（保真），再用 same-as Link 宣布等价**（见 5.2），绝不在装载时改写 BK（trim/大小写归一属同化决策，放 Business Vault/第 13 章）。
- **层级入 Hub 与否**：组织树、物料 BOM 的父子关系是关系不是属性 → Link（自环 Hub 的 parent-child link），层级展开用 Bridge（第 6 章）；「当前父节点」的时态由 link 效果性承担。
- **Hub 上禁止的诱惑**：给 Hub 加 status/effective 列、加第二个 BK（变成复合 Hub=事实上的 Link）、用代理键替代散列键（1.0 回潮）。
- 🔧 多源塌缩的边界行为实测（DuckDB）：`SELECT DISTINCT md5(bk)` 装载使双源 C1 塌为一行；若 BK 字符串多一个空格即两行——**Hub 层不做 TRIM**，该行为是特性而非缺陷（同化留给 same-as 与第 13 章匹配流程）。

## 3. 5.2 Link 应用（✅）

- **Same-as Link（同义链接）**：`L_SAMEAS_CUST(hk_customer_a, hk_customer_b, eff_from, eff_to)`——两个 BK 等价的**时态声明**（可能今天才在 MDM 里确认等价，也可能明天被推翻），因此带效果性。消费端（集市/查询）用同化视图把等价键归一。
- **多活跃链接（Multi-active Link）**：一个「唯一有效」假设失效的场景（同一客户同期多个保单、同一订单多承运人）→ 关闭效果性、以 Link Satellite 记录每个关系的独立状态。
- **非依赖链接（Independant Link，⚠️ 术语以书中为准未核，社区标准含此型）**：把业务规则/角色定义直接指向散列值（指向「哈希了某属性值」的伪 Hub），用于规则表达，Business Vault 常用。
- **自环与多维**：客户推荐客户（自环）；「谁-在何时-何地-干了什么」的多方事件用 4~6 成员 Link（订票 = 客户×航班×渠道×日期槽位），**度量大的一边交给 Link Satellite 或事实化 Hub**，不塞进 Link 本体。
- **可空成员**：关系未知时空着（`NULL`），禁止 `UNKNOWN-000` 假键；查询端的缺省处理放集市层，这是「保真」契约的延伸。
- **效果性的维护成本**：闭旧行意味着对 Link 的一次 UPDATE——这是 Vault「只追加」的**唯一例外家族**（部分实现改为「新行开、旧行不动，视图算 min(eff)」的纯追加方案），⚠️ 书中采纳哪种实现未逐页核对。🔧 实测：DuckDB 里按 UPDATE 闭旧行 + 插新行完成换会场景，查询 `eff_from<=t<eff_to` 即得任意时点关系。

## 4. 5.3 Satellite 应用（✅）

- **角色卫星/多实例卫星（Role-Play Satellite）**：同一类描述挂在不同父键槽位（地址卫星可挂客户也可挂门店）——靠**复合父键**（Link 当父）而非复制表。
- **时间戳卫星 vs 经典卫星**：高频小变（GPS 轨迹、传感器读数）→ 时间戳卫星（每变一行，无哈希差比较）；低频宽描述 → 经典哈希差卫星。选错方向的代价：卫星爆炸或历史丢失。
- **依赖卫星（Dependent Satellite）**：仅当「一行新数据的某列首次出现该值」才写？——依赖卫星语义是**只保存与源首次见到的差异**，社区评价低、2.0 标准不鼓励；⚠️ 书中立场按此常识理解，未核原文页码。
- **哈希差设计三问**：哪些列参与哈希（排除元数据列）、列序与 NULL 规范化（`concat_ws` + `coalesce`，否则 NULL↔'' 抖动会造假变更）、大文本列要不要踢出哈希组（🔧 实测中 `coalesce` 处理直接决定重放批次 0 新增的结果）。
- **切分粒度经验法**：一颗粒卫星 15~30 列为宜（宽度过宽→伪变更风暴；过碎→JOIN 爆炸），⚠️ 具体数字为社区通行经验，书中原话未核。

## 5. 三型应用的组合示例（订票域）

```text
H_CUSTOMER ← L_BOOKING(customer, flight, channel) → H_FLIGHT / H_CHANNEL
   │S_CUST_ATTR(经典)            │L_S_BOOKING_AMT(Link卫星: 金额修订史)
   │S_CUST_SCORE(时间戳)          └eff: L_CUST_AGENT(客户-当前经纪人, 多活跃关闭)
SAMEAS: L_SAMEAS_CUST(CRM_C1 ≡ MDM_000C1, eff区间)
```

## 5.5 变体选择决策表（把本章判例压缩成一页，重构）

| 情境 | 选什么 | 别选什么 |
| --- | --- | --- |
| 同一 Hub 两种业务语义（买/荐） | Role Play（Link 槽位区分） | 复制两张 Hub |
| 同实体多源两套 ID | 两 Hub 行 + same-as Link | 装载时字符串归一 |
| 「当前 X」且历史也要 | Link + effectivity | 卫星里塞 current 标志 |
| 同期允许多个有效关系 | 多活跃 Link + Link Sat | 强行 effectivity（丢行） |
| 高频逐变遥测属性 | 时间戳卫星 | 哈希差经典卫星 |
| 低频宽描述 | 经典哈希差卫星 | 时间戳卫星（历史爆炸） |
| 父子/BOM/持股 | 自环 Link（存事实）+ Bridge（集市展开） | 只建 Bridge（丢源事实） |
| 值域/码表 | Reference 表 | 为币种建 Hub 全家桶 |
| 关系未知但事实已发生 | Link 成员留 NULL | UNKNOWN 假键 |
| 只想透传一列 | 载荷/卫星搭车 | 新开一颗单列卫星（碎表化） |

## 5.6 same-as 的时态语义一例（T-SQL 风格重构）

```sql
-- 2015-06: CRM 的 C1 与 大机 的 000C1 被 MDM 裁决为同一人（裁决出处=工单 MDM-77）
INSERT INTO L_SAMEAS_CUST(hk_a, hk_b, eff_from, eff_to, record_source)
VALUES (md5('C1'), md5('000C1'), '2015-06-01', '9999-12-31', 'MDM:MDM-77');
-- 消费端归一视图（集市取材经此，见 13.10）
CREATE VIEW V_CUST_IDENTITY AS
SELECT COALESCE(b.bk, a.bk) AS golden_bk, a.bk AS alias_bk
FROM H_CUSTOMER a LEFT JOIN L_SAMEAS_CUST s ON s.hk_a=a.hk AND s.eff_to='9999-12-31'
                  LEFT JOIN H_CUSTOMER b ON b.hk=s.hk_b;
```

要义：same-as **有生效区间**——裁决本身也是历史（今天合并、明天分拆都是合法事件）；「黄金 ID」在 Vault 里永远是一个视图/投影，不是一行物理真相。

## 5.7 卫星切分的两个失败案例推演（判例法，重构）

- **切太粗**（客户全属性一锅卫星，50 列含 GPS）：每次定位上报→整行 50 列复制一条卫星行，存储放大 40 倍且哈希差失去「语义事件」含义。解药：快慢分家（时间戳卫星独立）。
- **切太细**（每列一颗卫星，50 颗）：任何「客户当前画像」都要 50 路时态 JOIN——PIT 构建成本爆炸、生成器产出物失控。解药：按**共同变更原因**分组（会一起变的住一起）。
  经验口径：单卫星 15–30 列、变更原因单一（⚠️ 数字为社区通行经验，非书中原话）。

## 5.8 FAQ

- **Q：Link 和「事实表」是一回事吗？** 形似神异：Link 只存关系身份与效果性、全历史、面向集成；事实表存度量+粒度、面向聚合（第 7 章）。度量在 Vault 侧住 Link Satellite（全历史版），进集市才被裁剪。
- **Q：效果性维护的 UPDATE 会不会破坏「只追加」？** 会破坏物理追加，但社区两流派之一（纯追加+视图求闭区间）可完全避免；重要的是**旧关系的失效是事件，不是抹除**（🔧 本目录实测为「闭区间」版：UPDATE 旧行 eff_to + 插新行；纯追加版逻辑等价，未另行实测）。
- **Q：依赖卫星还许不允许用？** 2.0 标准语境不鼓励（语义含混、装载特例多）；其合理需求（首见值）可用「带来源的哈希差+条件装载」表达（⚠️ 书中最终立场未核）。

## 5.9 中级建模评审清单（判例法的「庭审程序」，重构）

1. 每个新 Hub 问一句：它会不会其实是个码值？（→ Reference 分流）
2. 每个新 Link 问：唯一有效假设成立吗？（→ 5.5 决策表）
3. 每颗卫星问：列组会一起变吗？变更源是同一个吗？（→ 5.7 切分）
4. 所有多源实体：same-as 队列有出口吗？（→ 5.6 视图 + 13.9）
5. 自环层级：深度上限/多父允许吗？（→ Bridge 需求预告，6.2）
6. 时间戳卫星：抽样率与保留期声明了吗？（→ 2.1 容量轴）
7. 任何「先硬编码再说」的决定：登记为裁决 backlog（→ 3 章工作包切片）。

## 核心概念速览（中英对照）

- **角色扮演** — Role Play：一 Hub 多语义使用，不复制物理表。
- **同义链接** — Same-as Link：两业务键等价的时态声明。
- **多活跃链接** — Multi-active Link：同期允许多个有效目标的关系（关效果性）。
- **非依赖链接** — Independant Link：指向散列值的规则链接（Business Vault 用具）。
- **自环链接** — Self-referencing/Recursive Link：同 Hub 的父子/推荐关系。
- **可空成员** — Nullable Link Member：关系未知时留空，不造假键。
- **角色卫星** — Role-play Satellite：可挂多种父键的卫星。
- **时间戳卫星** — Timestamped Satellite：逐变存行、无哈希差的高频卫星。
- **依赖卫星** — Dependent Satellite：仅首见值入库的卫星，标准不鼓励。
- **效果性维护** — Effectivity Maintenance：闭旧开新的链接更新语义（append 的唯一例外家族）。
- **同化** — Harmonization：多源值/键归一的 Business Vault 决策。
- **NULL 规范化** — NULL Normalization：哈希差前统一 NULL 表示，防伪变更。
- **保真优先** — Source-preservation First：装载层零改写，决策后置。

## 最新演进与工业实践

- **宏库对判例的直接实现**：AutomateDV 把多活跃链接、效果性换会（当前有效切换）等本章判例固化为宏与配置项（官方站 https://automate-dv.com/（curl 403 反爬，域名解析正常，仅作存在性引用）；仓库 https://github.com/Datavault-UK/automate-dv ，2026-09 实测可达），把 5.2 的每条判例变成配置项；datavault4dbt 同样内建 same-as/effectivity 模板（https://github.com/ScalefreeCOM/datavault4dbt ）。
- **PIT 取代「查历史」的手工 JOIN**：2.0 后期社区把时态查询全面推向 PIT 物化/视图化（第 6 章），本期的反模式（在消费端手写 `eff_from<=x<=eff_to`）已成历史。
- **主数据即 same-as 的生产者**：MDM 系统（第 9 章）输出黄金记录映射 → 装载为 same-as Link；现代替代是实体解析服务（Senzing 开源自托管、各云 MDM SaaS）——same-as 语义与「身份图（identity graph）」概念一一对应（⚠️ 类比属笔记观点）。
- **CDC 与 same-as 的分工**：Debezium/Fivetran 类管道负责「取到源的最新事实」，same-as 负责「企业宣布两个键等价」——两者不可互相替代，这是 2024–2026 湖仓实践中常见的概念混淆点（社区博客多次辨析，⚠️ 未择定单一出处）。
