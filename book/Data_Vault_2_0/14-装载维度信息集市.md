# 第 14 章 装载维度信息集市（Loading the Dimensional Information Mart）

> 目录取证：章题与 14.1–14.7 小节题 ✅ 实抓自 Elsevier 官方 TOC（Business Vault 作中间层 / 物化 / PIT+Bridge 虚拟化 / 时间维 / 用 PIT 做质量 / 参照数据 / 集市中的哈希键）。正文为精读重构；🔧 为本机 DuckDB 1.5.5 实测。

## 1. 本章的地位：双层架构的接缝处

全书两大方法论（Vault 骨干 + 维度表达）在第 7 章会师、在本章**开工**：如何把三型+PIT+Bridge 变成 BI 能吃的星型，以及哪些情况下根本不变。14.1–14.7 就是这套决策树的七个节点。

## 2. 14.1 以 Business Vault 为集市的中间层（✅）

- 集市**只从 Business Vault 取材**（已同化、已裁决、已计算），绝不直连 Raw——保证「报表口径 = 企业口径」而非「源系统方言」；
- 集市构建输入清单：目标 Hub/卫星组 → 其 PIT、相关 Bridge、Reference 标准值、same-as 归一视图；
- 这层选择让 Kimball 的「维度重定义」成本锐减：维度口径变了=换一个卫星组合/PIT 切面，骨干毫发不动（对照 Kimball 工具箱中「维度再工程」之痛：[../数据仓库工具箱3.md](../数据仓库工具箱3.md)）。

## 3. 14.2 物化集市 / 14.3 用 PIT+Bridge 虚拟化（✅）

两条供给路线与选择函数：

| 决策变量 | 物化星型（14.2） | 虚拟（PIT/Bridge 直供，14.3） |
| --- | --- | --- |
| 查询延迟/并发 | 高要求→物化 | 探索型/低并发→视图 |
| 聚合复用度 | 高（口径收敛） | 低（长尾问题） |
| BI 工具限制 | 拖拽式工具（Tableau/SSRS） | SQL  fluent 团队 |
| 装载窗口成本 | 有额外物化批 | 无 |
| 存储 | ×N 份 | ×1（骨干即真相） |

- 物化装载的形状与第 12 章同族：`INSERT ... SELECT ... FROM pit JOIN sat ...` 的幂等批；维表用代理键（此时自增键无害，集市可重建）；
- 虚拟路线的 2015 年痛点=手工时态 JOIN 性能，🔧 今日 ASOF JOIN 一行（见 [06-高级建模PIT与Bridge.md](06-高级建模PIT与Bridge.md)）即解，虚拟化可行性大增——本章决策表在 2026 年应向虚拟侧整体平移一格（本目录判断 ⚠️）。

## 4. 14.4 时间维 / 14.5 用 PIT 实现质量追溯 / 14.6 参照数据（✅）

- **14.4 时间维**：日历表物化+「业务时点」列（PIT 的 load_dts）双轨；书中处理 24/7 与财务日历多角色日期（OrderDate/ShipDate 各建角色维，与 Kimball 角色维实践一致 ⚠️ 细节未核）；
- **14.5 PIT 做质量**：争议报表→PIT 复原「当日报表所见数据版本」→ 与当前版本 diff→ 定位是数据变了还是逻辑变了（把第 13 章审计落到集市层的具体手段）；
- **14.6 参照数据**：集市侧码值取自 Reference 标准层，允许集市做**最后一步显示翻译**（语言/别名），但翻译表也是版本化工件。

## 5. 14.7 集市中的哈希键（✅）

本章最具争议也最务实的小节：**信息集市可以、常常应该继续用哈希键做外键**（dim FK = 其父 Hub 的 HK）：

- 利：跨集市一致性（同一 HK 到处通）、免去代理键翻译层、与骨干无缝（视图/物化都省一跳映射）、多引擎并行友好；
- 弊：人不可读（BI 开发者无法肉眼 JOIN——缓解：维度表同时暴露 BK 列）、64/128-bit JOIN 与手工粘贴的摩擦；
- 书中结论（按 TOC 语境与作者一贯立场 ⚠️）：物化大表可用代理键省空间，**虚拟层/中型集市直接带 HK**；这条「视情况」给两派都留了门，也是附节讨论的活靶。

## 6. 🔧 实测：从 Vault 导出一张「订单项+客户语境」事实宽表

DuckDB 1.5.5，沿用 04/06 章数据（3 Hub、2 卫星源、1 Link/booking 事实）：

```sql
SELECT b.bk, b.flight, b.bdate, s.name, s.tier AS tier_at_booking, s.recsrc
FROM bookings b JOIN sat_cust s ON s.hk = md5(b.cust)
WHERE s.ldts = (SELECT max(ldts) FROM sat_cust s2
                WHERE s2.hk=s.hk AND s2.recsrc=s.recsrc
                  AND s2.ldts <= CAST(b.bdate AS TIMESTAMP));
-- 实测输出（节选）：B3|F200|2015-06-10|Alice|VIP|CRM 与 B3|F200|...|GOLD|OMS
```

两点观察：①「按订单时点取属性」即 14.2 物化维的胚胎；②同一事实因多源 lineage 出行×2——集市必须在出口前经 same-as/裁决选列（13.10），**重复行不是 bug 而是未裁决状态的显形**，与第 13 章「受管的模糊」互证。

## 6.5 从 PIT 生成 SCD2 维的参考式（14.2 的核心件，重构示意）

```sql
INSERT INTO DIM_CUSTOMER (sk, hk, bk, name, tier, valid_from, valid_to, is_current)
SELECT seqNEXTVAL, p.hk, p.bk, p.name, p.tier,
       p.as_of, LEAD(p.as_of) OVER (PARTITION BY p.hk ORDER BY p.as_of) - 1day,
       IFF(valid_to IS NULL, 1, 0)
FROM (SELECT *, ROW_NUMBER() OVER (PARTITION BY hk, tier_hash ORDER BY as_of) rn
      FROM V_CUSTOMER_PIT) p          -- 口径=裁决后身份（经 13.10 视图）
WHERE p.rn = 1;                        -- 每口径版本只出一次维行
```

与卫星的区别立即显形：维行的 `valid_from` 是**企业生效口径**（可含回填/批延迟），不是源观察时刻——SCD2 值得独立存在的原因尽在其中。

## 6.6 虚拟化集市的视图包（14.3 的最小可行形态，重构）

```sql
CREATE VIEW VM_FACT_BOOKING AS
SELECT b.hk_link, b.hk_cust, b.hk_flight, b.book_dts,
       a.tier AS tier_at_book, f.route_code
FROM L_BOOKING b
ASOF JOIN V_CUSTOMER_PIT a ON a.hk=b.hk_cust AND a.as_of<=CAST(b.book_dts AS DATE)
ASOF JOIN V_FLIGHT_PIT   f ON f.hk=b.hk_flight AND f.as_of<=CAST(b.book_dts AS DATE);
-- 🔧 连接件本目录已在 DuckDB 1.5.5 实测可跑（§6）；引擎无 ASOF 时以 §6.5 的 max(ldts) 相关式替代
```

虚拟包上线前的三道闸：①BI 端查询计划抽检（视图展开是否炸 JOIN）；②PIT 刷新时刻=报表快照时刻（口径漂移窗）；③权限在视图层收口（14 章出口纪律）。

## 6.7 物化/虚拟决策流程（14.2×14.3 汇总成一图，重构）

```text

        │否

```

## 6.8 FAQ

- **Q：集市能不能保留 raw 卫星原值列？** 能——把「原始值 vs 标准值」并排做维属性（两列），是 13 章双出口在集市侧的便宜实现。
- **Q：多个集市要不要共用物化星型？** 共用=新的一致性维度问题（版本/刷新互踩）；本书隐含答案：共用 PIT/BV 上游，集市各自投影（附节 §6-2 的教训由此而来）。
- **Q：14.7 的 HK 直留策略今天还成立吗？** 在云仓/湖引擎上更强（定长键分区/聚簇友好 ✅ 属一般性工程判断 ⚠️ 非实测）；BI 粘贴可读性缺陷用「维表并带 BK+短码列」缓解。

## 核心概念速览（中英对照）

- **集市装载** — Mart Loading：由 Business Vault 生成星型的批过程。
- **物化/虚拟化** — Materialized / Virtualized Mart：落表 vs 视图直供。
- **取材纪律** — Single Upstream Rule：集市只饮 Business Vault。
- **口径切面** — Slice of Definitions：换卫星组合=换维度口径。
- **角色日期维** — Role-Playing Date Dimension：下单日/发货日各一维。
- **版本复原** — Version Restoration：PIT 重现当日报表所见数据。
- **显示翻译** — Display Translation：集市层码值→本地语言别名。
- **集市哈希键** — Hash Keys in Mart：以 HK 充当集市外键的取舍。
- **代理键豁免** — Surrogate Key Exemption：集市层可安全用自增键（可重建）。
- **lineage 重复行** — Lineage Duplication：多源未裁决致事实多行的显形。
- **决策表** — Decision Table：物化 vs 虚拟的选择函数。
- **重算投影** — Recomputable Projection：集市=骨干的可弃影子。
- **出口权限** — Mart-side Security：行级权限最后施加处。
