# 第 10 章 元数据管理（Metadata Management）

> 目录取证：章题与 10.1–10.5 小节题（Meta Mart / Metrics Vault / Metrics Mart / Error Mart）✅ 实抓自 Elsevier 官方 TOC。正文为精读重构。

## 1. 10.1 什么是元数据（✅）

书中采用三分类的工业口径：

- **技术元数据**：表/列/键/映射清单/ETL 包配置——生成式 ETL（第 12 章）的燃料；
- **业务元数据**：术语表、口径定义、KPI 归属——集市目录的可信标签；
- **操作元数据**：每次装载的批日志、行数、时窗、错误计数——本章四个「元数据结构」的主体。

与第 3 章咬合：SDLC 3.0 的 KPI 驱动交付，其 KPI 数据来源正是本章的操作元数据。

## 2. 架构：四个元数据结构（✅ 小节齐备）

### 2.1 Meta Mart（10.2）

- 装载过程的**自描述账本**：每次批（batch）一行头表 + 每张目标表一行明细——源文件/行数、抽取起止、装载起止、影响行数、哈希差过滤数；
- 实现朴素：普通数据库表（书中用与 Vault 同库或独立 meta 库，⚠️ 细节未核），由 ETL 控制流自动写入；
- 用途第一问「昨晚 3 号客户卫星到底进了多少行」不再翻 SSIS 日志。

### 2.2 Metrics Vault（10.3）

- 把**质量/运营度量当数据管**：行数偏差、重复率、键覆盖率、时效延迟等按「指标即事实」入自己的小 Vault（指标定义=Hub/Reference，观测值=事实卫星）；
- 体现 Vault 自反性：数仓治理自身也走三型纪律——这是全书最容易被忽略的「吃自己狗粮」设计。

### 2.3 Metrics Mart（10.4）

- Metrics Vault 的星型出口：供运维仪表盘与 SLO 复盘（第 3.3 节评审的数据面输入）；
- 典型度量：装载时窗趋势、SLA 违约次数、按源系统的错误密度。

### 2.4 Error Mart（10.5）

- **错误行不丢弃、带上下文归档**：拒绝原因码+原始载荷+批次指针进 Error Mart，与第 13.3「坏数据的价值」同一条哲学线（坏数据是发现源系统缺陷的探测器）；
- 修复回路：Error Mart → 工单 → 源端或映射修正 → 重放该批（append-only 保证重放安全）。

## 3. 元数据与血缘（本章能力边界的诚实刻画）

- 书内血缘=**映射清单驱动的操作级血缘**（源表→目标实体→批次），支撑「报表数字追到源文件」的审计问题；列级动态血缘非本章目标（2015 年业界工具亦弱，⚠️ 书中论述范围未核）；
- 与第 11.3/11.4（load_dts/record_source）共同构成行级审计链：任一集市数字 ≈ 批次(Meta Mart) + 实体版本(卫星时态) + 源出处(record_source) 三元组可复原。

## 4. 落地清单（重构自本章实操）

1. 先建 Meta Mart 四件套表结构并嵌入装载框架（手写或用模板生成器自动织入）；
2. 指标字典先行：只登记「能在评审会上讲出口」的 15±10 个指标，拒绝大而全；
3. Error Mart 给原因码建立 Reference 表（第 6.3 复用）；
4. 每迭代的 3.3 评审强制以 Metrics Mart 截图为议程第一项（方法论闭环）。

## 4.5 Meta Mart 参考骨架（10.2 的落地形状，重构示意 ⚠️ 非书中原表）

```sql
CREATE TABLE META_BATCH (batch_id INT PK, batch_ts TIMESTAMP,
  src_system VARCHAR, stage_files VARCHAR, started_dts TIMESTAMP,
  ended_dts TIMESTAMP, status VARCHAR);                 -- 批头：一次装载一行
CREATE TABLE META_BATCH_LOG (batch_id INT FK, entity VARCHAR,   -- 实体明细：一表一行
  rows_read INT, rows_new INT, rows_filtered INT,       -- rows_filtered=哈希差挡掉的
  runtime_ms INT, reason_codes VARCHAR);                -- 非空即有行进 Error Mart
```

「读入/新增/过滤」三计数是本节最可复用的设计：**过滤数异常飙升=源在重放或映射失配，新增数=0 而读入巨大=假增量**——两个报警器免费送你。

## 4.6 Metrics Vault 度量目录示例（10.3 样例，重构）

| 度量 | 计算式（自 Meta/业务表） | 归属 KPI |
| --- | --- | --- |
| 装载时窗 p95 | META_BATCH 滑窗 | SLA |
| 键覆盖率 | distinct(HK in Mart)/distinct(HK in Hub) | 完整性 |
| 多源冲突率 | L_SAMEAS 待裁决对数/Hub 行数 | 身份治理 |
| 卫星膨胀率 | 卫星日增/实存（滚动） | 变更健康度 |
| 错误密度 | Error Mart 行/百万读入 ×源系统 | 供应商质量 |

## 4.7 Error Mart 骨架与工单回路（10.5）

```sql
CREATE TABLE ERR_MART (err_id, batch_id, entity, reason_code,   -- 6.3 的 Reference 外键
  payload_json VARCHAR,           -- 原始坏行全上下文
  first_seen_dts, status VARCHAR, -- OPEN/ASSIGNED/FIXED/REPLAYED/WONTFIX
  ticket_ref VARCHAR);            -- 第 13 章工单互指针
```

REPLAYED 状态由「修复后重放该批」动作自动翻转（重放安全，12 章契约），Error Mart 因此兼职**修复看板**。

## 4.8 一条血缘问答的推演（本章能力自证）

「2015-06 月报第 3 行的 1,204 是怎么来的？」
1. 月报口径定义（业务元数据）→ 指向 DIM_CUSTOMER+FACT_BOOKING 的某版本；
2. 集市装载批 → Meta Batch（某日）；
3. 事实行的 HK → L_BOOKING（record_source='OMS'）→ 卫星版本=PIT 当日切面；
4. 卫星 → stage 文件批次 → 源表快照。四跳全部有账可查 = 第 10+11+12 章的合奏。

- **OpenLineage** — 开放血缘事件规范（OLF），书内自造账本的标准化后继（现状补充 ⚠️ 本次未实测其站点）。

## 4.9 元数据最小启动包（反「大而全」的实施顺序，重构）

第 1 周：META_BATCH+META_BATCH_LOG 两表进装载框架（12 章栅栏落点现成）；
第 1 月：Error Mart+原因码 Reference（13 章需要它先跑通）；
第 1 季：Metrics Vault 五度量（4.6 表）+ 评审会硬引用（3.3 闭环）；
此后按需长业务元数据——顺序错了（先上术语表大盘）是常见的死法（⚠️ 书中是否点名未核，本目录按反模式整理）。

## 核心概念速览（中英对照）

- **技术元数据** — Technical Metadata：结构/映射/配置类元数据。
- **业务元数据** — Business Metadata：术语与口径定义。
- **操作元数据** — Operational Metadata：运行时批次日志类事实。
- **元数据集市** — Meta Mart：装载账本的查询层。
- **指标金库** — Metrics Vault：质量/运营度量的 Vault 化存储。
- **指标集市** — Metrics Mart：度量的星型出口。
- **错误集市** — Error Mart：拒绝行带上下文归档。
- **原因码** — Rejection Reason Code：错误分类字典。
- **批次** — Batch/Load Cycle：一次端到端装载的原子单元。
- **血缘** — Lineage：数据从源到消费者的可追路径。
- **重放安全** — Replay-safe：append-only 使批次重跑不破坏历史。
- **自反性** — Self-referentiality：治理数据也按治理架构存放。
- **SLO/SLA** — Service Level (Objective/Agreement)：装载时效承诺。
- **数据面评审** — Data-driven Review：以度量开迭代会（3.3 的输入）。

## 最新演进与工业实践

- **元数据标准与协议**：2020s 的开放标准接棒了书中自造账本——**OpenLineage**（事件模型）+ **ODCS**（开放数据合约规范，与 Error/指标语义直接对应）+ **DataHub/OpenMetadata/OpenLineage 生态** 取代单机 Meta Mart（⚠️ 各书未及，属本目录补充现状）。
- **dbt 内置化**：dbt run results / metadata.json 天然是 Meta Mart；Elementary（https://github.com/elementary-data/elementary ）把运行监控+异常检测做成 dbt 包形态的 Metrics Mart（社区现状通识，仓库信息 ⚠️ 本次未逐一实测，仅 https://docs.getdbt.com/ 于 2026-09 验证可达）。
- **数据可观测性商品化**：Monte Carlo、Soda、Bigeye 等把「错误集市+指标集市」升级为商品（转述 ⚠️）。
- **湖仓表格式自带的操作元数据**：Delta 事务日志/Hudi timeline/Iceberg snapshots 已记录每批文件级变更——书中 Meta Mart 的「批次账」下沉为表格式职责，人读账本只剩业务指标层（对照 [../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md](../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md)、[../Apache_Hudi_Definitive_Guide/00-总览与阅读地图.md](../Apache_Hudi_Definitive_Guide/00-总览与阅读地图.md)）。
