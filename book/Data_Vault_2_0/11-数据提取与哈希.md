# 第 11 章 数据提取（Data Extraction）

> 目录取证：章题与 11.1–11.10 小节题 ✅ 实抓自 Elsevier 官方 TOC（11.2 Hashing in the Data Warehouse、11.8 Sourcing the Sample Airline Data 等）。正文为精读重构。

## 1. 11.1 暂存区的作用（✅）

Stage 在 Vault 架构中不是「ETL 临时工」，而是**合同签署前的大门**：

- 全列落地（源有什么列存什么列，含无建模价值列——Payload 的家，⚠️ 书内定位推定）；
- 只加三样东西：批次号、`load_dts`、`record_source`；
- 哈希在这里算：进入 Vault 前所有 HK/哈希差已就绪，Vault 装载 SQL 退化为纯 INSERT…WHERE NOT EXISTS（第 12 章），从而可并行；
- 类型宽容：暂存层宁可 VARCHAR 化保真，类型裁决发生在进 Raw Vault 的映射里（清洗在第 13 章的框架下讲）。

## 2. 11.2 数仓中的哈希（✅）——2.0 的技术心脏

- **两类哈希物**：
  - 哈希键（HK/LK）：输入=业务键（可含源系统标识的多代哈希）；目的=定长、并行、跨源；
  - 哈希差（HD）：输入=卫星属性组（按列序拼接+NULL 规范化）；目的=变更检测。
- **算法选择（2015 年书中语境）**：MD5(128-bit) 为社区默认；SHA 系可选；核心告诫是**哈希值永不反推、不参与业务计算，键的语义在 BK 列**。⚠️ 原书算法对比表未逐页核对。
- **碰撞数学**（本章的诚实小节）：128-bit 下按生日悖论，数十亿键才有可忽略概率；64-bit 截断在亿级即进入需要监控的区间——「键宽=风险预算」是本章留给工程决策的公式（数字为通行口径 ⚠️ 书中原话未核）。
- 🔧 本机演示（DuckDB 1.5.5）：`md5(concat_ws('||', name, tier))` 作哈希差，重放同批 0 新增、改一列即追加——变更检测的充要演示（脚本 `dbwave_datavault2`）。

## 3. 11.3 装载日期 / 11.4 记录来源（✅）

- `load_dts`：**进入仓库的物理事务时刻**（批次统一取值，非源系统时间戳、非日历时间）——所有 PIT/审计的时间轴锚点；业务时间（valid_from 等）是另一族列，两者混淆=时态灾难；
- `record_source`：字符串枚举（源系统/文件/表名），回答「这行是谁说的」；与 Meta Mart（第 10 章）的批次号合起来构成行级溯源；
- 两列+卫星 PK 设计（hk+ldts）是第 12 章一切装载 SQL 的骨架。

## 4. 11.5–11.10 源类型学与航司样例（✅）

- 源分类（小节名即目录）：平面文件（11.6）、历史数据（11.7：只读回填、常缺 record_source 需合成）、反规范化源（11.9：宽表拆回多实体，**不预设源是干净的**）、MDS 主数据源（11.10，第 9 章下游）。
- **航司样例库**（11.8，✅ 小节实抓）：客户-机票-航班-飞机的贯穿案例：
  - `H_CUSTOMER/H_FLIGHT/H_AIRCRAFT/H_TICKET`；订票/出票关系进 Link；地址/等级/机型参数各归卫星；
  - 样例贯穿第 12/14 章的装载与集市生成，SQLDBM 生成其 DDL（第 8/12 章自动化同线索，⚠️ 实体名以书中 ER 图为准未逐核）。
- 提取策略学（本章综述口径）：全量快照 vs 增量（时间戳/审计表/CDC/日志挖掘——2015 年 CDC 已普及，本书仍主推轻量文件/快照，⚠️ 倾向程度未核）；每种策略都必须能被 stage 三件套（批次/load_dts/record_source）消化。

## 5. 提取层三条铁律（重构）

1. 源系统变更（加列）只允许惊动 Stage，不允许惊动 Vault 三型（新列要么进卫星要么留 Payload）；
2. 提取失败=批次失败，禁止半批入仓（原子性在文件/批次粒度声明）；
3. 一切删除请求先变成「带删除原因卫星的事件」，物理清数据走合规流程而非 ETL。

## 4.5 哈希计算规范草案（11.2 的工程化写法，重构示意）

```sql
-- Stage 视图：三件套+两哈希在出口一次算清（此后 Vault 侧零计算）
SELECT
  md5(cust_id)                                   AS hk_customer,   -- 单代：BK 本体
  md5(cust_id || '|' || record_source)           AS hk_customer_src,-- 多代：含源标识
  md5(concat_ws('||',
        upper(trim(name)),
        coalesce(tier,'~N'),                      -- NULL 显式哨兵，防伪变更
        coalesce(phone,'~N'), 1))                 AS hash_diff,
  load_dts, record_source, src_cols.*
FROM stg_customer;
```

纪律四条：①哈希只在 Stage 算（第 12 章依赖）；②参与哈希的列序**版本化**（改列序=改哈希=全表假变更，需迁移批）；③NULL 用显式哨兵而非默认值；④大文本/CLOB 踢出哈希组、改挂「长度+首尾切片」或独立卫星（🔧 本目录实测未涉大文本，此条为社区通行口径 ⚠️）。

## 4.6 源类型学与提取策略矩阵（11.5–11.10 汇总，重构）

| 源类型 | 提取法 | 幂等策略 | 特别注意 |
| --- | --- | --- | --- |
| 平面文件（11.6） | 文件名/批次登记+全文件重放 | 批次号+哈希差 | 编码/换行/千分位的保真 |
| 数据库快照（11.5） | 时间窗全抽 | 哈希差天然去重 | 快照时刻=load_dts 锚 |
| 历史回填（11.7） | 一次性灌入 | 只读、禁重放 | 合成 record_source、合成 load_dts 标记「回填批」 |
| 反规范化宽表（11.9） | 拆分为多实体视图 | 每实体独立哈希 | 一个源行→多 Hub 行，错误放大×N |
| CDC 流（书中轻、今天重） | 日志/触发捕获 | 事务序+批次折叠 | 乱序到达用 load_dts 定序 |
| MDS 主数据（11.10） | 版本视图拉取 | 版本好=天然幂等键 | 见第 9.9 时序 |

## 4.7 三条铁律的反例推演（11 章末，重构）

- 违铁律 1（源加列惊动 Vault）：为源新列重建卫星/重跑哈希→ 全史假变更；正解：新列进**新卫星**（变更频率分组不变，老卫星零扰动）。
- 违铁律 2（半批入仓）：卫星进了、父 Hub 没进 → 引用完整性靠装载顺序的契约被击穿（无 FK 兜底！），下 PIT 出现幽灵键。
- 违铁律 3（ETL 物理删除）：源端删了一行「错误数据」→ 集市重算时口径漂移、审计断链；正解：删除也是事件（deletion 卫星/状态列）。

## 4.8 FAQ

- **Q：为什么哈希放 Stage 而不是 BI 侧现算？** 放 Stage=一次计算、全体物化、可索引；现算=每次全扫重算且跨引擎表达式漂移风险（浮点/NULL 语义差异会造出假变更）。
- **Q：BK 本身要归一（TRIM/大小写）吗？** Raw 层不归一（保真），同化在 Business Vault/same-as（第 5/13 章）——🔧 本目录 Hub 实测中「多一个空格=两个键」正是该契约的直接后果。
- **Q：源没有可靠业务键怎么办？** 组合键哈希（多列 BK 拼接）+ 匹配引擎（13.9）补身份；连组合特征都没有→概率键，裁决全部显式留痕（same-as 的 record_source 写算法版本）。

## 4.9 提取管道 Runbook 要点（11.6–11.10 的运维面，重构）

- 文件类：到达断言（存在+大小>0+mtime 滞后窗）→ 编码探测 → 行数对账（源尾单/校验和）→ 登记批次；
- 快照类：抽取时刻写入 load_dts 前统一取「窗口右端点」，防同批多快照混时刻；
- CDC 类：事务序折叠（同键同批取末态前，保留中间态与否=显式决策，默认保留=卫星语义）；
- 回填类：独立「历史批」通道，合成时间戳打 `backfill` 标（Error/审计视图可过滤）；
- 一切失败语义：重试 3 次→批次挂起+告警，禁止部分提交（12 章栅栏前提）。

## 4.10 Stage 契约摘要（给上下游的接口文档骨架，重构）

- 入口：源行原样+`file_id/batch_id`；出口：+`load_dts/record_source/hk_*/hd`；
- 不变式：同一 (hk,hd) 在任意重放中字节级一致（列序/NULL 哨兵/编码固定）；
- SLA：到达→可装载延迟、行数对账误差=0；
- 版本：哈希列集变更=契约大版本（需迁移批+登记），新列追加=小版本（老 hd 不重算）。

## 核心概念速览（中英对照）

- **暂存区** — Staging Area：源数据的保真着陆区，哈希计算发生地。
- **哈希键** — Hash Key：业务键哈希，HK/LK 的统称。
- **哈希差** — Hash Diff：属性组哈希，卫星变更检测器。
- **多代哈希** — Multi-generation Hashing：哈希的哈希（含源标识）以表达同义/角色。
- **生日悖论** — Birthday Paradox：碰撞概率随键数平方增长的直觉模型。
- **NULL 规范化** — NULL Normalization：拼接哈希前统一空值表示。
- **装载时间戳** — Load Date (load_dts)：批次进入仓库的物理事件时刻。
- **记录来源** — Record Source：行的出处标记列。
- **业务时间 vs 装载时间** — Valid Time vs Transaction Time：两族时态列的分野。
- **平面文件源** — Flat File Source：CSV/定长文件类提取。
- **历史回填** — Historical Load：一次性只读灌入既往数据。
- **反规范化源** — Denormalized Source：宽表型源，需在装载时拆回实体。
- **CDC** — Change Data Capture：捕获源变更的提取技术族。
- **载荷透传** — Payload Pass-through：无建模价值列随行存档。
- **航司样例** — Airline Sample：贯穿全书的演示域。

## 最新演进与工业实践

- **CDC 成为默认提取**：Debezium（Kafka Connect 生态）+ 各托管服务（Qlik Replicate、Fivetran/Airbyte 类）接过了书中「文件+快照」的担子；Fivetran 与 dbt 2024–2025 合并（dbt+Fivetran 并购）使「源→stage 保真→dbt 算哈希」成为 dbt 系 Vault 项目主流管线（并购为公开新闻，⚠️ 细节未展开）。
- **哈希函数的引擎内建**：Snowflake `HASH()`（64-bit，官方文档）、Databricks `xxhash64`/`md5`、DuckDB `hash()`——多代哈希可直接 SQL 表达式实现，书中需要 UDF/预计算的时代结束；「64-bit 是否够用」的键宽再争论在 2024–2026 社区持续（Snowflake 官方示例即用 64-bit ⚠️ 转述）。
- **湖格式的原子批次**：批次三件套与 Iceberg/Delta 快照机制同构——「批次失败=快照不可见」由表格式免费提供（对照 [../Apache_Iceberg活用入門/00-总览与阅读地图.md](../Apache_Iceberg活用入門/00-总览与阅读地图.md)、[../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md](../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md)）。
- **时间旅行对 record_source 的部分替代**：引擎 time travel 能答「何时写入」，但答不了「谁说的」——源出处标记列仍不可废（本目录观点，⚠️ 无书内依据）。
