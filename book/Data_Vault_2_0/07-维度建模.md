# 第 7 章 维度建模（Dimensional Modeling）

> 目录取证：章题与 7.1 Introduction / 7.2 Star Schemas / 7.3 Multiple Stars / 7.4 Dimension Design ✅ 实抓自 Elsevier 官方 TOC。本章是全书与 Kimball 体系正面相遇之地；对照精读请配 repo [../数据仓库工具箱3.md](../数据仓库工具箱3.md) 与本目录 [附-Kimball与DataVault分工与混用.md](附-Kimball与DataVault分工与混用.md)。

## 1. 本章在书中的角色

第 4–6 章建好了 Vault 骨干，第 7 章笔锋一转：**面向人的分析仍然需要维度模型**——作者并不否定 Kimball，而是把维度建模整体**降格/安置**到信息集市层：星型不再直接对抗源系统，它从 Vault 里长出来。这一章是「为什么集市层仍用星型」的教科书，第 14 章才是「怎么从 Vault 生成星型」的操作手册。

## 2. 7.1 导论 / 7.2 星型模式（✅）

- 星型=事实表（业务事件的度量+外键集）+ 非规范化维表（分析者要的语境属性）。与 Vault 的三型逐项对照：

| 关注点 | Vault（第 4 章） | 星型（本章） |
| --- | --- | --- |
| 服务对象 | 集成/审计/全历史 | 聚合查询/BI 易用性 |
| 键 | 散列业务键 | 代理键（自增/序列即可） |
| 变更 | 只追加 | 允许 SCD1 覆盖、SCD2 拉链 |
| 宽表恐惧 | 属性必须切卫星 | 维度尽量宽（反规范化） |
| NULL | 未知就留空 | 常用 `Unknown` 成员行 |

- 事实表三型（与 Kimball 第 3 版同口径，转述见 [../数据仓库工具箱3.md](../数据仓库工具箱3.md)）：事务事实（一行一事件）、周期快照（时点余额/库存）、 accumulating snapshot（里程碑管道）。⚠️ 书中三分法的展开程度未逐页核对，口径以 Kimball 原文为据。
- 粒度声明（grain）优先：集市设计从「事实粒度」出发——这一点两派完全一致。

## 3. 7.3 多星 / 一致性事实（✅）

多个事实表共享维度的星座（fact constellation）：Bookings 与 TicketRefunds 共享 H_FLIGHT 派生的 `DIM_FLIGHT`。书中立场：共享维度**必须**出自同一 Vault 实体（同一 PIT+卫星组合同化而来），从结构上杜绝 Kimball 最怕的「同名不同义维度」——一致性维度（conformed dimension）在 Vault 架构里不是纪律问题，而是**生成来源唯一**的工程问题。这是对 Kimball 总线矩阵难题的一个釜底抽薪式回答（⚠️ 「釜底抽薪」为笔记评价）。

## 4. 7.4 维度设计（✅）

本章给出的维度设计检查单（精读重构口径）：

1. **维度来源三选一**：由 Hub+卫星集（实体维）、由 PIT 时点快照（角色/时点维）、由 Reference 表+其同化映射（值域维）；
2. **退化/杂项维**：票据号等直接留事实；低基数标志位打包 junk dim；
3. **层次**：自然层级内嵌维表列（city→country），可变层级走 Bridge（第 6 章）；
4. **时间维**：日历表生成物（7.4 与 14.4 各讲一半，⚠️ 具体分工为推定）；
5. **维度的历史策略**：集市侧 SCD2 拉链即可——因为全历史真身永远在 Vault 卫星里，集市的历史只是「投影」，投影可以重做。这是双层架构最被低估的红利：**维度的 SCD 策略从「不可逆决策」降级为「可重算视图」**。

## 5. 常见误区（本章警示集，重构）

- 把星型直接当 EDW 硬扛多源：冲突解决逻辑挤进 ETL 存储过程，Kimball 工具箱里「维度工程」逐渐变成「数据清洁工」——书以此为双层论据（对应第 1 章痛点与 [../数据仓库工具箱3.md](../数据仓库工具箱3.md) 的乐观立场形成张力）。
- 在集市里再做一次全历史：卫星已存历史，集市 SCD2 只保「报表口径所需深度」，重复拉链=双份成本。
- 用 View 直连 Vault 当集市而不做 PIT：查询端被迫写时态 JOIN，BI 工具性能塌方（解法见第 14 章物化/虚拟化权衡）。

## 5.5 Kimball 4 步法在双层架构中的执行位（对照表，本目录整理）

| 4 步 | 纯 Kimball 路线 | 本书双层路线 |
| --- | --- | --- |
| ① 选业务过程 | 总线矩阵行 | 同（不变，第 3 章按此切工作包） |
| ② 定粒度 | 事实表设计第一刀 | 同 + 与 Link/Link-Sat 的粒度对表（②在两层各说一遍） |
| ③ 选维度 | 维表工程（重头戏） | 从 Hub/PIT/Reference **生成**维表（7.4 三选一来源） |

## 5.6 订票域星型草图（第 14 章开工图的预告，重构）

```text
                 DIM_CUSTOMER(scd2)      DIM_FLIGHT      DIM_DATE(role: 订票/出行)
                        ▲                    ▲                 ▲
        FACT_BOOKING(bk_surrogate, cust_fk, flight_fk, book_date_fk,
                     fly_date_fk, amount, channel_key)   ← 粒度：一票一航段
                        ▲
                 DIM_CHANNEL / junk: IS_PROMO, IS_GROUP
生成链：H_CUSTOMER+卫星 →(same-as 归一+PIT 时点)→ DIM_CUSTOMER；L_BOOKING → FACT_BOOKING
```

注意两处「翻译」：HK→集市代理键（14.7 允许直留 HK 则跳过）；裁决后身份→维表单行（13.10）。集市侧的一切自洽都以这条生成链存在为前提。

## 5.7 维度设计检查单（7.4 操作化，重构）

1. 每维声明来源实体（Hub/卫星组/Reference 路径），无来源的列不得入维；
2. SCD 策略显式标注（默认 SCD2；仅当「当前值即口径」才 SCD1）并验证可重算性；
3. 层级列与 Bridge 不混用（同一棵树只能有一种展开方式供 BI）；
4. 角色维命名规范（DIM_DATE_BOOKING / DIM_DATE_FLYING 视图化 DIM_DATE）；
5. 未知成员策略：`-1 Unknown` 仅用于**关系确实未知**（与 5.2 可空 Link 对齐），禁用 `0`/空串；
6. 一致性核对：本维与他集市的同名维**同哈希源**（HK/生成链一致才算 conformed）。

## 5.8 FAQ

- **Q：有了 Vault 为什么还要星型，PIT 宽视图不够吗？** 够——14.3 就是给这条路留的门；但拖拽式 BI、KPI 卡片、订阅报表仍偏爱预 JOIN 的星型（读频决定，见 14 章决策表）。
- **Q：SCD2 和卫星历史是否重复？** 角色不同：卫星是**源观察史**（谁何时说了什么），SCD2 是**报表口径史**（企业何时认定变更生效）；13.5/14.4 把两者对齐后，重复是投影的本钱。
- **Q：本书第 7 章值得让只读 Kimball 的人读吗？** 值得——它是最干净的「维度建模依赖了什么隐含假设」的镜像（把工具箱里被默认为理所当然的「源会伺候维度」反转过来）。

## 核心概念速览（中英对照）

- **星型模式** — Star Schema：事实表+反规范化维表的分析结构。
- **星座/多星** — Fact Constellation：共享维度的多星型集合。
- **事务事实表** — Transaction Fact Table：一行一个业务事件。
- **周期快照** — Periodic Snapshot Fact：固定时点的存量事实。
- **累积快照** — Accumulating Snapshot：里程碑管道型事实。
- **粒度** — Grain：事实表一行代表的细节层级。
- **一致性维度** — Conformed Dimension：跨集市同义同构的维度。
- **缓慢变化维** — SCD（Slowly Changing Dimension）：维度历史策略（SCD1 覆盖/SCD2 拉链）。
- **角色维度** — Role Dimension：同一维按不同语义复用（下单日/发货日）。
- **退化维度** — Degenerate Dimension：只有键没有属性的维度（票据号）。
- **杂项维** — Junk Dimension：低基数标志位的打包维。
- **投影可重算** — Recomputable Projection：集市历史可自 Vault 全历史重建的红利。
- **时点快照维** — Point-in-Time Dimension：自 PIT 生成的任意时刻维度。
- **值域维** — Reference/Coded Dimension：源自 Reference 表的码值维。
