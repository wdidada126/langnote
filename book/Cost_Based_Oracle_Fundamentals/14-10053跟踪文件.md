# 14 · The 10053 Trace File（10053 跟踪文件）

> 原书第 14 章（压卷）⚠️ 精读重构：章题 ✅ 实抓（Springer/Crossref），小节自拟；trace 结构与开关为文档/社区转述，一律 ⚠️。

## 本章定位

前 13 章的验证工具章：**10053 是优化器把自己的全部心思（统计快照、谓词选择度、每次变换尝试、每个候选路径的成本算式、每次竞价胜负）写下来的事件**。Lewis 的立场：不读 10053 的 CBO 知识都是二手传闻；读通它，本书前 13 章的每一条公式都能在真实系统里逐数复核 ⚠️。

## 14.1 开与关 ⚠️ 转述

```sql
ALTER SESSION SET EVENTS '10053 trace name context forever, level 1';
-- 执行目标 SQL（必须硬解析：新语句或先 FLUSH SHARED_POOL / 改一个注释）
ALTER SESSION SET EVENTS '10053 trace name context off';
-- trace 文件落 user_dump_dest / diag 目录（ADR 路径按版本 ⚠️）
```

- 关键操作学：**软解析不产生 10053**（优化只发生在硬解析），复现计划漂移时常需绑新字面量或清游标强制硬解析 ⚠️。
- 与 10046 的分工（Lewis 常画的一张对照 ⚠️）：**10053 记"决定"，10046 记"执行"**——前者回答"为什么选这个计划"，后者回答"这个计划慢在哪"；调优闭环 = 10053 定位病因 + 10046/ASH 验证疗效。
- 产物体量：一条稍复杂 SQL 的 trace 动辄上万行（本书时代即如此，现代版本更长），Lewis 的读法是**按段跳读**而非通读 ⚠️。

## 14.2 Trace 结构地图（重构 ⚠️ 转述）

| 段 | 内容 | 对应章 |
|---|---|---|
| HEADER/参数表 | 版本、隐含参数、系统统计、MBRC | 01 |
| OPTIMIZER STATISTICS | 表/列/索引统计 dump（含直方图端点表） | 02/03/04/07 |
| 谓词段（kkqdmp/op 类） | 每条谓词及推导式（transitive closure 产物）与 sel 值 | 03/06 |
| TRANSFORMATION 段 | 每次变换尝试、应用/回退及原因 | 09 |
| 控制块（SCB/JTF/JO） | 连接组、顺序搜索的现场 | 10/11/12/13 |
| 路径定价段 | 每个候选：公式逐项代入（blevel/leaf/CF/sel…）与 COST 输出 | 02/04/11/12/13 |
| FINAL | 胜者计划、总成本 | 全书 |

- 训练建议（精读重构 ⚠️ 非原书逐字）：拿 04 章公式手算一遍 COST，与 trace 打印值对表，误差即你对模型理解缺口的度量。

## 14.3 用 10053 裁决五种日常争论 ⚠️ 转述

1. **索引为何不用**：看该索引定价段的三项分解，通常死于 CF 项（→ [05-聚簇因子.md](05-聚簇因子.md)）。
2. **全表扫描为何显贵/便宜**：核对 blocks 与有效 MBRC（→ [02-全表扫描.md](02-全表扫描.md)）。
3. **改写为何无效**：变换段里找"已尝试但成本更高"，转修统计（→ [09-查询变换.md](09-查询变换.md)）。
4. **绑定变量之罪**：谓词 sel 是否等于 peeked 值的 sel（→ [06-选择度组合难题.md](06-选择度组合难题.md)）。
5. **HJ/NL 之争**：找连接组竞价段的两个 COST 与乘数输入（→ [11-嵌套循环连接.md](11-嵌套循环连接.md)、[12-哈希连接.md](12-哈希连接.md)）。
- 案例库接口：改写类争论的判例整理见 [../Oracle查询优化改写技巧与案例.md](../Oracle查询优化改写技巧与案例.md)；10053 是其"为什么这样改有效"的解释器 ⚠️。

## 14.4 阅读技巧与安全 ⚠️ 转述

- 定位术：按对象名/`COST:`/`sel:` 正则跳段；同一语句多子游标时先对 `SQL_ID` 与 peeked binds 头块 ⚠️。
- 生产纪律：会话级开启、用毕即关；勿在共享服务器/连接池路径长期挂着（trace 体量与解析开销 ⚠️）。
- 版本敏感：段名与格式逐版本漂移（8i→10g 本书基线；11g 起增 bind capture/ACS 行、12c 起增 adaptive/指令行，皆 ⚠️ 转述），**结构与公式不变、字面锚点会变**——读旧 trace 教程要配版本。

## 14.5 现代等价物速览（详见文末演进节）⚠️ 转述

- 计划取证日常化：`DBMS_XPLAN.DISPLAY_CURSOR(format=>'ALLSTATS LAST')` 给出逐行 EST/ACT/实际耗时，覆盖 10046 的大部分日常职能（→ [../Oracle12c数据库应用与开发/07-SQL性能诊断与调优实践.md](../Oracle12c数据库应用与开发/07-SQL性能诊断与调优实践.md)）。
- 但"为什么选它"（决策过程）至今没有官方一等公民接口，10053 仍不可替代；官方文档只给到事件级说明、细节以社区解读为主 ⚠️。

## 14.6 片段读法示范（伪 trace，仅为版式示意 ⚠️ 非真实 dump 转录）

```
OPTIMIZER STATISTICS
  Table: MAIN.T1  Alias: T1
    stat: num_rows=500000 blocks=16000 degree=1 ...
    Column: C1  sel: 0.000002  ndv: 1000000  density: ...
BEGIN PREDICATE INFO
  kkoqbc: pop query cost for SEL Info
  Expression (1,5): ("T1"."C1"=5)
  OPT_EXPLAIN: Considered Table Scan (cost=520.00 ...)
  ...
  KSOSQ: considered index IX_T1_C1
    cost: blevel=2 lblks=22000 cf=450000 ...
    selpath p[0]: ssel=0.000002 cost=5.00
FINAL: Best cost=5.00 for plan hash 0x....
```

读法逐行对应：
- `num_rows/blocks` 行 → 02 章扫描定价输入；
- `sel:` 行 → 03 章规则表的现场打印；
- `Considered Table Scan (cost=520)` → 1.8 的"成本读表"第一步；
- `blevel/lblk/cf + selpath` → 04 章三项式逐项代入；
- `FINAL: Best cost` → 竞价胜者；同 SQL 多次解析对比此行的 plan hash 即漂移取证。
- 真实段名因版本而异（⚠️ 本片段为教学重构，不是任何版本的原样输出）。

## 14.7 一套可执行的 10053 工作流（Checklist）

1. 冻结现场：记录 SQL_ID/计划哈希/参数快照（`V$SQL` 系，名 ⚠️ 转述）。
2. 会话级开 10053 → 强制硬解析执行 → 关事件（14.1 语法）。
3. 定位头块：版本、优化器参数、系统统计——写进取证笔记（跨环境比对用）。
4. 统计快照块与字典对表：不一致 = 解析期缓存/异步统计作业问题（5.6 步 2 同款）。
5. 顺读谓词 sel 与变换尝试，标出与手算不符的行（3.6/9.6 流程反用）。
6. 在定价段找到胜者与败者成本，做"差额归因"：哪个乘数贡献了 80% 差值。
7. 处方试验：改统计/参数后重跑同一 trace 对比 FINAL 行——**以 trace 差异为疗效判据**，而不是"看起来好了"。
8. 归档：trace 片段+手算过程入库，形成团队 CBO 案例集（本书时代 Lewis 博客即此文化的公共版，✅ https://jonathanlewis.wordpress.com/ ）。

## 核心概念速览（中英对照）

- **10053 事件** — trace event 10053：输出优化器决策全过程的诊断事件。
- **硬解析前提** — hard parse requirement：只有触发优化才产 trace。
- **10046 事件** — SQL trace：记录执行期等待/绑定/统计，与 10053 互补。
- **控制块** — SCB / JTF / JO：语句控制块、连接表、连接顺序搜索结构（名 ⚠️ 转述）。
- **定价段** — access path cost dump：逐候选打印公式代入与 COST 的段落。
- **sel 值** — selectivity dump：谓词估算选择度的打印形态。
- **变换回退** — transformation rollback：trace 中"应用后又被弃"的记录。
- **参数表** — parameter dump：优化器环境（含隐含参数）的头段。
- **ADR/diag 目录** — 诊断框架落盘路径（11g+ ⚠️）。
- **游标子级** — child cursor：同一 SQL 多计划时逐一代价对应。
- **EST/ACT 对照** — 计划行估算与实际：DISPLAY_CURSOR ALLSTATS 职能。
- **可复现性** — repro：以 trace 头块（版本/参数/统计）复刻决策现场。

## 最新演进与工业实践

- **trace 更大更结构化（11g–23ai ⚠️ 文档转述）**：绑定窥视/ACS 信息、动态采样、SQL 指令、自适应子计划决策全部入 trace；现代一条 E-Business/数仓级 SQL 的 10053 常达**十万行量级**，社区通行做法是脚本切片而非人读全档 ⚠️。新式语法 `ALTER SESSION SET EVENTS 'trace[oracle_rdbms_sql_compile] disk database.diagnostic_level high'` 一类内核 trace 组件接口（名以 ⚠️ 转述，官方支持面有限）。
- **决策外的取证层产品化**：SQL Plan Management（11g+）以 baseline/evolve 把"决策漂移"关进灰度流程；SQL Tuning Advisor/SQL Profile（10g+）把统计修正建议化；ASH/AWR/ADDM（10g→19c，23ai 里 ADDM 与 ASH 深度整合，官方自动诊断线）替代本书时代手工翻 trace+Statspack 的多数日常——19c 性能管理指南（✅ 可达：https://docs.oracle.com/en/database/oracle/oracle-database/19/tgdba/ ）为现行总入口 ⚠️。
- **可观测性工业惯例**：2024–2026 实践栈≈`SQL Monitoring（实时逐行）→ ASH（历史采样）→ 10053（终审取证）`三层；"为什么"类问题仍回到本章 ⚠️。
- **开源对照**：PostgreSQL `EXPLAIN (ANALYZE, BUFFERS)` + `trace_sort`/`optimizer trace`（PG 无 10053 等价物，社区补丁式讨论），对照 [../PostgreSQL技术内幕_查询优化深度探索.md](../PostgreSQL技术内幕_查询优化深度探索.md)；通用优化器调试方法在 [../数据库查询优化器的艺术.md](../数据库查询优化器的艺术.md)。
- **论文与谱系**：System R 时代即有"优化器解释器/why 查询"思想（EXPLAIN 家族，谱系注记 [../../db/db.md](../../db/db.md)）；Selinger 1988（✅ DOI：https://doi.org/10.1145/50202.50214 ）论文附带的成本推导展示就是 10053 的学术原型。
