# 04 · Simple B-tree Access（B 树索引基础访问）

## 本章定位

全书被引用最多的一章：把 01 的成本单位和 03 的选择度装进 **B 树索引访问的定价公式**。读懂本章，"为什么这个索引明明建了 CBO 却装看不见"就有了可计算的答法。索引对象/运维操作层在 [../Oracle12c数据库应用与开发/05-索引与约束.md](../Oracle12c数据库应用与开发/05-索引与约束.md)，本章管代价侧。

## 4.1 参与定价的四个索引统计 ⚠️ 文档转述

| 统计量 | 英文 | 在公式里的角色 |
|---|---|---|
| 层级数 | blevel（分支层） | 每次索引探查的固定过路费 |
| 叶子块数 | leaf_blocks | 区间扫描的索引侧顺序成本基数 |
| 不同键值数 | distinct_keys | 前导列有效选择度分母 |
| 聚簇因子 | clustering_factor | 回表成本的主乘数 → [05-聚簇因子.md](05-聚簇因子.md) |

另有 `num_rows`（索引行数）与 `avg_leaf_blocks_per_key` / `avg_db_blocks_per_key`（10g 起可选，本书时代已有）⚠️。

## 4.2 范围扫描成本公式（重构转述）⚠️ 文档转述

Lewis 在本书给出的简化模型（对 9i/10g ⚠️）：

```
cost ≈ blevel + 1                          ← 定位起点：根到叶的一条腿
     + ceil( leaf_blocks × eff_sel )       ← 索引侧：扫过的叶子块（按多块读打折）
     + rows_returned × (CF / rows_index)   ← 表侧：每次回表近似一次单块读
```

- `eff_sel`（effective index selectivity）：只有复合索引**前导连续可用列**的谓词参与，其余谓词的行都要"多走一步"回表过滤——这是"把等值列放前、范围列放后"这类排序建议的可计算依据 ⚠️。
- `rows_returned = num_rows × 谓词组合选择度`（→ [03-单表选择度.md](03-单表选择度.md)、[06-选择度组合难题.md](06-选择度组合难题.md)）。
- 三项的杠杆结构：blevel 是常数；叶子项随区间宽度线性；**回表项才是指数级杀手**，因为 CF 可以是行数量级 ⚠️。
- 唯一扫描（index unique scan）≈ blevel+1 + 1 次回表；唯一索引范围扫描（index unique range scan）介于两者之间（谓词不全覆盖唯一键时）⚠️。
- 跨引擎对照：PostgreSQL 的同型公式（`cpublksize/ceil(index pages)` 结构、clustering 由 pg_stats 相关性刻画）见 [../PostgreSQL技术内幕_查询优化深度探索.md](../PostgreSQL技术内幕_查询优化深度探索.md) ⚠️ 文档级对照。

## 4.3 何时索引必胜/必败（公式推论）⚠️ 文档转述

- 必胜：谓词把 `rows_returned` 压到很小 **且** CF 接近块数量级（数据按键聚簇）。
- 必败：区间宽（回表项爆炸）或 CF≈行数（每行一个新块）。此时与 FTS 的"块数/MBRC"（→ [02-全表扫描.md](02-全表扫描.md)）相比毫无竞争力。
- **索引快速全扫描（index fast full scan）**：把索引段当"窄表"做多块全扫，成本结构同 FTS——覆盖查询（不需要回表）时它常胜；排序需求时它因顺序不保证而败 ⚠️。
- 回表列全在索引里（覆盖）时第三项归零，"加列进索引换免回表"的定价逻辑即此 ⚠️。

## 4.4 跳过扫描与其他访问方式 ⚠️ 文档转述

- Index skip scan（9iR2+）：前导列 NDV 小时优化器"虚拟拆分"前导值逐个探查，定价里乘上前导 distinct 因子；Lewis 的告诫：前导列 NDV 一大，成本公式第一项立刻失控 ⚠️。
- Descending index / 函数索引改变的是"键有序性"而非公式形状 ⚠️。
- 分区索引（local/global）改的是每个统计量的作用域：local 索引按分区各自带 CF/leaf_blocks，优化器对每分区独立定价再做裁剪汇总 ⚠️。

## 4.6 三项公式数字走查（示意，非实测 ⚠️）

表 T：100 万行 / 2 万块；索引 IX(T.c1)：blevel=2, leaf_blocks=22000, CF=900000, distinct_keys=100 万。
谓词：`c1 = :v`（选择性 1/100 万，返回 1 行）。

1. 索引探查：blevel + 1 ≈ 3。
2. 叶子项：leaf × eff_sel = 22000×1e-6 ≈ 0.022 → ceil = 1。
3. 回表项：rows_returned × CF/rows = 1 × 0.9 ≈ 1。
4. 合计 ≈ 5 —— 点查碾压 FTS（2.7 步 3 的 Cost≈2000+）。
把谓词换成 `c1 BETWEEN a AND b`（覆盖 20 万行）：
- eff_sel=0.2 → 叶子项 4400；回表项 20 万×0.9 = 18 万 → 索引方案 ~18.4 万 vs FTS ~2000：**CBO 弃索引是数学正确**。
- 若同表按 c1 聚簇重建（CF→2 万）：回表项变 20 万×0.02 = 4000，叶子+回表 ≈ 8400，仍输给扫描，但 5% 以内区间已可翻盘——"聚簇改变竞价曲线斜率"的直观来源。

## 核心概念速览（中英对照）

- **层级数** — blevel：根到叶的分支层数，索引探查固定成本。
- **叶子块数** — leaf_blocks：索引区间扫描的顺序成本基数。
- **不同键值数** — distinct_keys：前导列有效选择度的分母。
- **聚簇因子** — clustering_factor：键序扫描引发的表块切换数，回表定价乘数。
- **有效索引选择度** — effective index selectivity：前导连续谓词列实际可用的选择度。
- **索引范围扫描** — index range scan：定位+有序遍历叶子链表+回表。
- **索引快速全扫描** — index fast full scan：索引段当窄表全扫，多块读、无序。
- **索引唯一扫描** — index unique scan：至多一键，成本≈blevel+2。
- **跳过扫描** — index skip scan：低 NDV 前导列的虚拟拆分探查。
- **覆盖索引** — index-only access：谓词与投影列全在键内，回表项归零。
- **回表** — table access by index rowid：按 rowid 单块读表，每行一次。
- **局部索引** — local index：按表分区各自维护统计与定价作用域。
- **键压缩** — index key compression：前缀重复值合并存储，直接压低 leaf_blocks 定价输入。
- **不可见索引** — invisible index：对优化器隐藏但持续维护，"拔索引"灰度通道（现代运维 ⚠️）。
- **B*树** — B*tree：默认索引形态，右侧块 50% 预留供顺序 INSERT 分裂，影响 leaf_blocks 量级。

## 最新演进与工业实践

- **自动索引（19c+，文档转述 ⚠️）**：`DBMS_AUTO_INDEX` 依据负载建/验/弃索引，内部仍是成本模型+SQL 执行验证双闸门——本书公式仍是其"候选成本初筛"的骨架；见官方性能管理指南（✅ 可达：https://docs.oracle.com/en/database/oracle/oracle-database/23/tgdba/index.html ）。
- **列存视角的替代**：In-Memory Column Store 与 Exadata 智能扫描让"免回表"价值下降（扫描即列裁剪），但行级点查场景 B 树定价公式仍是唯一真理解释（产品文档转述 ⚠️）。
- **统计增强**：12c 起索引统计收集默认路径与 `GATHER_INDEX_ONLY` 等行为有调整（文档转述 ⚠️），CF 的采样失真比本书时代小，但行迁移破坏 CF 的机制不变。
- **开源同构**：PostgreSQL/B-tree 成本模型文献（含 `random_page_cost` 与相关性校正的当代讨论）可对照 [../PostgreSQL技术内幕_查询优化深度探索.md](../PostgreSQL技术内幕_查询优化深度探索.md)；通用原理在中译原创书 [../数据库查询优化器的艺术.md](../数据库查询优化器的艺术.md) 有跨引擎版叙述。
- **论文线**：B 树访问路径定价原型即 Selinger 1988 的 index 代价式（✅ DOI：https://doi.org/10.1145/50202.50214 ）；谱系见 [../../db/db.md](../../db/db.md)。
