# 08 · Bitmap Indexes（位图索引）

> 原书第 8 章 ⚠️ 精读重构：章题 ✅ 实抓（Springer/Crossref），小节自拟；结构与成本行为为文档/社区转述，一律 ⚠️。

## 本章定位

位图索引是 Oracle 索引家族里的"异类"：为**决策支持（低基数列、大范围过滤、并发 DML 低）**而生。Lewis 此章做两件事：把压缩位图的物理结构画清楚，然后给出**位图路径的定价逻辑**——为什么多条件位图 AND 在数仓里近乎免费，而它在 OLTP 里是锁灾难。与 04 章 B 树形成镜像，与 [../Oracle12c数据库应用与开发/05-索引与约束.md](../Oracle12c数据库应用与开发/05-索引与约束.md) 的对象操作层互补。

## 8.1 物理结构：压缩游程 ⚠️ 转述

- 每个键值段存的不是逐行 ROWID，而是元组：`(key, start_rowid, end_rowid, run_count/compressed bits)`——一个 ROWID 区间内每行 1 bit，1/0 表示有无该键值 ⚠️。
- 推论（Lewis 的可计算直觉 ⚠️）：
  - 表按该列聚簇 → 每键值一个宽区间，位图极小、扫描极快；**位图索引自带"聚簇检验"**。
  - 键值乱序分布 → 区间碎片化，索引膨胀、压缩率崩。
- 多键值列（组合位图 / key-collapsed bitmap）把若干低基数列编进同一结构，对应数仓星型模型的维度列组合 ⚠️。

## 8.2 查询机制与定价 ⚠️ 转述

- 单索引使用：定位键值 → 解出位图 → 位为 1 的 ROWID 区间回表（`BITMAP INDEX SINGLE/MERGE` 计划行形态）。
- **多索引位图合并**：`BITMAP AND/OR/MINUS`（计划行名 ⚠️ 转述）在索引层对位图做布尔运算，**先把结果集压到最小再一次性回表**——B 树组合做不到，这是"多条件低基数过滤位图必胜"的机制。
- 成本构成：键区间定位费 + 区间覆盖的表块单块费（同 05 章聚簇逻辑）+ 无缓存折算项；谓词再多，只要落在已建位图的列上，后续条件近乎"贴边免费" ⚠️。
- `bitmap → rows → table access` 的转换（BITMAP CONVERT TO ROWIDS）按计划需要行源时插入；优化器对**纯 COUNT/GROUP BY** 可直接在位图上做，无需回表 ⚠️。
- 分区表 local 位图：每分区独立小位图，扫描并行+分区裁剪协同，数仓标配 ⚠️。

## 8.3 为什么 OLTP 禁用：DML 锁语义 ⚠️ 转述

- 更新一行可能翻转一个宽区间位图的压缩段，**锁粒度扩到整个键值区间**；高并发异值更新互相排队，"一行 UPDATE 卡半个表" ⚠️。
- 唯一性约束列、频繁点更新列、跨行事务链路上的表：一律回避（原书立场经社区转述 ⚠️）。
- 与函数索引/虚拟列的组合在 11g+ 才成熟（演进节）。

## 8.4 位图 vs 其他路径的判据（精读重构）⚠️ 转述

| 负载特征 | 首选 |
|---|---|
| 低基数列等值/IN、多谓词组合、读多写少 | 位图（或多列组合位图） |
| 高基数键点查、顺序写 | B 树（04 章） |
| 范围大且回表占比高 | 全表扫描（02 章） |
| 高并发 DML | 位图禁用区 ⚠️ |

- 数仓建模侧的索引策略与聚合层次治理另见 [../数据库高效优化.md](../数据库高效优化.md) 与 [../Oracle12c数据库应用与开发/13-高并发系统的架构与设计.md](../Oracle12c数据库应用与开发/13-高并发系统的架构与设计.md)（前者给路径经济学、后者给并发禁区，互证 ⚠️）。

## 8.6 位图竞价走查（场景示意 ⚠️ 非实测）

星型场景：事实表 F（5 亿行、10 万块）挂三列位图（gender NDV=2、state NDV=50、band NDV=6）；维度过滤经子查询折成 F 上的三个低基数谓词。

1. 单谓词 `gender='M'`：sel≈0.5 ⇒ 位图解出 2.5 亿行——回表账崩溃，**单低基数谓词位图无胜算**（与 FTS 比只多"免行解析"一点）。
2. 三谓词 AND：索引层 `BITMAP AND` 把 0.5×0.02×0.2≈0.002 ⇒ 百万级行**再回表**；回表量按聚簇块切换定价（04/05 同构）。
3. 对照 B 树方案：无任一列 NDV 撑得起 range scan（第 2 列起就退化），组合索引又要求列序——位图的"布尔合并"是唯一能把三个等值同时吃进索引层的结构 ⚠️。
4. 对照 HJ 星型方案（无位图时）：维度子查询→连接，成本进入 10–12 章体系；`STAR_TRANSFORMATION`（09 章）本质就是把方案 3 的位图合并塞进连接计划 ⚠️。
5. 结论口径：位图赢在"**谓词多、基数低、单谓词都不死**"的组合区间——这是 8.4 表的机理版。

## 8.7 数仓落地流程（重构清单 ⚠️）

- [ ] 维度列盘点：对每个可能被过滤的列测 NDV 与谓词频次（column_usage 思路 ⚠️）。
- [ ] 组合位图取舍：常用"状态×类型"二元组 → key-collapsed 一个对象 vs 两个独立位图（AND 合并已够则不再组合）。
- [ ] 装载窗口：bulk load 前 `UNUSABLE`（分区级）装载后重建，避开区间锁与维护税 ⚠️。
- [ ] 并发验证：混合格式 DML 压力测试（位图表与 B 树表同事务的锁面），OLTP 混负载直接否决 ⚠️。
- [ ] 统计面：位图索引的 distinct_keys/leaf 含义异化（8.5），竞价观察以计划形态+行数为准。
- [ ] 演进评估：同负载在列存（In-Memory/开源 OLAP）上的对照成本——决定继续投资位图还是迁移（文末演进）。

## 8.9 位图的经济学边界（重构总结 ⚠️ 转述）

把 8.2/8.6 的账拆成三个可判定的量：

| 量 | 记法 | 位图友好 | 位图敌对 |
|---|---|---|---|
| 键值宽度（行/键） | rows per key | 大（低 NDV） | 小（高 NDV） |
| 谓词合取数 | #predicates | 多（AND 层数≥2 才回本） | 单谓词 |
| 结果占比 | sel 组合后 | 越小越好 | 接近半表（不如扫描） |

- 推论一：**位图是"合取折扣"生意**——单谓词永远不建位图，两谓词看场景，三谓词以上才显威力（8.6 步 1–2）。
- 推论二：与 B 树复合索引的替代关系：高 NDV 前导列的组合，B 树能做的位图不必做；B 树做不动的"任意子集多低基数列"才是位图领地 ⚠️。
- 推论三：更新频率是第三轴——前两轴再合适，OLTP 写并发一票否决（8.3）。
- 教学自测句："位图索引之于数仓，如聚簇因子之于 OLTP"——一个是合取定价的核心乘数，一个是回表定价的核心乘数。

## 核心概念速览（中英对照）

- **位图索引** — bitmap index：键值对 ROWID 区间压缩位图的索引结构。
- **游程压缩** — run-length compression：(起 ROWID, 止 ROWID, 位串) 的存储单元。
- **键值区间** — key range / ROWID range：一段位图的覆盖范围，锁与成本的粒度。
- **位图合并** — bitmap AND/OR/minus：索引层布尔交并差，先过滤后回表。
- **位图转行** — bitmap conversion to rowids：位图世界到行源世界的计划边界算子。
- **组合位图** — key-collapsed bitmap：多低基数列编入同一索引。
- **锁放大** — lock escalation to range：DML 锁住整个键值区间，OLTP 禁区根因。
- **基数（列）** — cardinality of column：distinct 值数，位图适用性的第一判据。
- **位图连接** — bitmap join index（9i+）：预物化维表键到位图的 ⚠️ 特性。
- **局部位图** — local bitmap index：分区表每分区独立位图。
- **免回表聚合** — index-only aggregate on bitmap：COUNT/GROUP BY 直接在位图完成 ⚠️。
- **压缩率** — bitmap compression ratio：区间数×位密度的健康度读数，膨胀即聚簇报警。
- **合取折扣** — conjunction discount（本目录术语）：多谓词在索引层合并带来的"越 AND 越便宜"效应。

## 最新演进与工业实践

- **版本现实（2024–2026）**：位图索引仍是 19c/23ai 的现役特性（文档转述 ⚠️）；但数仓侧角色被两件事挤压——In-Memory Column Store 与 Exadata 智能扫描让"多条件低基数过滤"由列存向量化扫描承担，Oracle 自动索引（19c `DBMS_AUTO_INDEX`）默认**不**建位图 ⚠️，官方性能管理指南（✅ 可达：https://docs.oracle.com/en/database/oracle/oracle-database/23/tgdba/index.html ）。
- **函数索引/虚拟列联动**：11g+ 虚拟列上的位图与扩展统计组合，缓解 06 章相关性问题在数仓的落点（文档转述 ⚠️）。
- **开源对照**：PostgreSQL 的 bitmap index 已废弃、以 bitmap scan（位图扫描执行算子，多索引 AND 后一次回表）继承其"索引层合并"思想——机制在 heap 上、结构非持久位图；逐点对照 [../PostgreSQL技术内幕_查询优化深度探索.md](../PostgreSQL技术内幕_查询优化深度探索.md)。列存引擎（ClickHouse/DuckDB 的 min-max+跳数索引）则是同一"先粗筛后精读"哲学的现代形态 ⚠️ 概念级对照。
- **数据仓库方法论**：星型模型下位图/连接位图的取舍，在 Kimball 体系与 Inmon 体系中位置不同，参见 [../数据仓库工具箱3.md](../数据仓库工具箱3.md) 与波内 [#169《Building the Data Warehouse》](../Building_the_Data_Warehouse/00-总览与阅读地图.md)（已落盘，00 互链义务波尾闭环）。
- **论文线**：位图压缩与布尔合并的学术脉络（O'Keefe 1995 经典位图论文等，未核 DOI ⚠️ 不给链接）；Oracle 侧定价仍复用 Selinger 框架的"页引用"逻辑（✅ DOI：https://doi.org/10.1145/50202.50214 ）。
