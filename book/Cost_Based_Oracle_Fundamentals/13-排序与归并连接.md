# 13 · Sorting and Merge Joins（排序与归并连接）

> 原书第 13 章 ⚠️ 精读重构：章题 ✅ 实抓（Springer/Crossref），小节自拟；排序成本式为社区转述的本书代表性形态，一律 ⚠️。

## 本章定位

排序是"每个方法都可能顺带承担的税"：MERGE JOIN 必须先排序、GROUP BY/DISTINCT/ORDER BY 无处不在、HJ 溢出也写成排序形态。Lewis 罕见地把**排序自身的成本模型**单列一章——因为它是全书唯一"盘写"进模型的地方，也是"同一 SQL 因排序需求换掉整条连接策略"的枢纽 ⚠️。

## 13.1 排序成本模型 ⚠️ 转述

- 三段账：**读输入（块数/MBRC 折算）→ 归并段（run）写盘 → 最终趟读回**。
- 归并趟数由 workarea 能同时容纳的 run 数决定（`sort_area_size`/PGA 管理时代的 `_sort_area_...` 家族，名 ⚠️ 转述）；每多一趟乘约 2 倍临时段 I/O——与 12 章 multipass 同构 ⚠️。
- 优化器的粗化假设（本书时代 ⚠️）：按输入量的固定比例估可用内存、按行宽估块均行数；**宽行（LOB 定位器/大 avg_row_len）导致每块行数少、run 数多、成本爆炸**——"加一列到 SELECT 列表成本跳变"在排序在场时是真的（对照 02 章"列不参与扫描定价"，差异正来自排序宽度项）⚠️。
- 无盘排序（全内存）时模型仍记"读写各一轮"，导致轻排序被高估、重排序仍低估的多面失真 ⚠️。

## 13.2 有序性作为货币：索引消排序 ⚠️ 转述

- `ORDER BY` 可由有序访问路径免费供给：B 树按键序输出（04 章）、位图路径无序需 `BITMAP SORTED ROWIDS` 转换（名 ⚠️ 转述）、merge 侧天然吃有序流。
- 于是计划空间出现"便宜扫描+贵排序" vs "贵索引+免排序"的跨维度竞价——GROUP BY 同理；这是"索引为排序而建"的成本学合法性来源 ⚠️。
- top-N（`ROWNUM<=n` + ORDER BY）：stopkey 允许边产序边终止，模型对其终止概率的估算长期粗糙（01 章 1.4 呼应）；12c 的 top-n 分析增强 ⚠️（演进节）⚠️。
- 并行排序的重分布（按排序键哈希分发，名 ⚠️ 转述）把网络/临时段成本叠进同一定价 ⚠️。

## 13.3 MERGE JOIN 定价 ⚠️ 转述

```
cost(A MJ B) ≈ cost(排A) + cost(排B) + 扫描A + 扫描B + 归并比较项
```

- 与 HJ 的对照（Lewis 式讨论 ⚠️）：MJ 多付两次排序、少担 HJ 的内存溢出乘数风险，换来**输出有序**与**可提前终止**；输入已有序（索引供序）时 MJ 成本骤降为"两扫一归并"。
- 等值范围扩展：非等值连接（`<`,`BETWEEN`）上 MJ 是少数被定价的选项，10 章非等值基数+本节排序税合成其全部知识 ⚠️。
- 倾斜友好度：MJ 对单值热点不像 HJ 那样桶偏（顺序流），但会产生"同值笛卡尔段"的真实耗时，模型只按基数记 ⚠️。
- 版本现实：MJ 在现代 Oracle 里的出场率远低于 9i 预期（HJ+自适应挤压其生态位，文档转述 ⚠️）。

## 13.4 GROUP BY/DISTINCT 的排序侧 ⚠️ 转述

- sort group by 与 hash group by 的竞价：输入有序则 group 免排序（接 13.2 索引供序链）⚠️。
- DISTINCT 在连接前的"先去重再连接"变换（09 章 place/aggregation 类）以排序/哈希去重成本换行数收缩 ⚠️。
- 数仓聚合治理的规范层（预聚合/汇总表）见 [../数据库高效优化.md](../数据库高效优化.md)——替模型承担本章税的工程解。

## 13.6 排序成本核算走查（示意 ⚠️ 非实测）

对象：10 万行 × 行宽 200B 的行源需 ORDER BY 非索引列；workarea 示意可容 2 万行/run。

1. 读输入：按 02 章账（行源是表则块数/MBRC；是连接中间结果则继承其成本行）。
2. 产 run：10 万 ÷ 2 万 = 5 个 run，各写盘一次（写出块数 = 行数×行宽/块净空间）。
3. 归并趟数：内存能同时吃 4 路归并 ⇒ 至少 1 趟（5→4→? 需两趟，示意 ⚠️）；每趟"读 run+写结果"翻倍临时 I/O。
4. 成本形态 ≈ 输入读 + 5 写 + 2 读 + 1 写 ≈ 输入 + 8 个"行源块量级"轮次——行宽×2 时 run 数×2，成本超线性恶化（13.1 宽行税）。
5. 竞价出口：给该列建索引（免 1–4 全链，改付 04 章探查税）或 12c 前接受 MJ 顺手吃掉已序输入（13.7 决策矩阵）。
6. 与 12.6 同表并算：同一行源若既是 HJ 输入又要 ORDER BY，HJ 无序短板会强制追加本段全账——"选 HJ 省的钱被排序吃回去"的定量版本 ⚠️。

## 13.7 SMJ / HJ / NL 三方法决策矩阵（本章视角 ⚠️）

| 维度 | NL | HJ | SMJ |
|---|---|---|---|
| 输入有序要求 | 外有序即可 | 无 | 必须双排序（或索引供序） |
| 输出有序性 | 保外层序 | 无序 | 保连接键序 |
| 提前终止(stopkey) | 友好 | 不友好 | 友好 |
| 基数高估敏感度 | 乘次数，线性放大 | 几乎不放大 | 排序项随量放大 |
| 内存溢出乘数 | 无（无大内存件） | 有（multipass） | 有（多趟归并） |
| 倾斜敏感度 | 低（逐行探查） | 高（桶偏） | 中（同值段） |
| 生态位 | 小外层×精内层 | 大×大无序 | 已序/需序/非等值 |

- 表读法（Lewis 式 ⚠️）：优化器三套成本式是这张定性表的定量影子；"计划反常"先定位表里哪一维被基数误差污染。

- 补记两条易混（⚠️ 转述）：
  - `DISTINCT` 与 `GROUP BY` 在计划里同为"收敛行源"，定价输入相同（行数×宽度×有序性），改写互换不改变成本账、只改变可读性；

## 核心概念速览（中英对照）

- **归并段** — run：一次内存排序产出、参与后续归并的有序块段。
- **趟数** — passes：排序读写盘轮次，multipass 即成本倍增器。
- **排序区** — sort_area_size / workarea：控制单 run 容量的内存配额。
- **宽行税** — row-width penalty：avg_row_len 经"每块行数"放大 run 数的机制。
- **临时段** — temporary segment：溢出排序的盘上载体。
- **有序供源** — order-preserving path：索引扫描等免排序来源。
- **停止键** — stopkey：top-N 提前终止的计划形态与估算盲区。
- **归并连接** — sort merge join（SMJ）：双排序后顺序归并，输出有序。
- **非等值连接** — non-equi join：MJ 主场，基数估算高难区。
- **sort vs hash group by**：聚合的两种供给方式，竞价含输入有序性。
- **重分布排序** — parallel key distribution：并行下按键分发再做局部排序。
- **PGA 竞争** — workarea contention：多游标共抢自动内存管理配额的现实约束。
- **保序货币** — order as currency（本目录术语）：有序性在计划竞价中的可折算价值。
- **消排序** — sort elimination：以索引供序/输入有序免掉排序段的总称。
- **块宽折算** — rows-per-block 推导：avg_row_len → run 数 → 成本的中间账，兼作"归并段复用窗口"的约束源。

## 最新演进与工业实践

- **自适应与 top-n 改进（12c+，文档转述 ⚠️）**：自适应计划对排序/连接方法的执行期纠偏；top-n 与 NPF（nth value）类算子的成本估算细化（具体增强点以 ⚠️ 转述为限）。
- **内存与溢出监控现代化**：19c/23ai 的 SQL Monitoring 直接显示每计划行的内存/临时段用量与 one-pass 标记（转述 ⚠️，指南入口 ✅ 可达：https://docs.oracle.com/en/database/oracle/oracle-database/19/tgdba/ ）；ADDM→ASH 路线下"排序风暴"可由临时段 IO 事件画像自动点名（转述 ⚠️，同 [../Oracle12c数据库应用与开发/07-SQL性能诊断与调优实践.md](../Oracle12c数据库应用与开发/07-SQL性能诊断与调优实践.md)）。
- **Result Cache 与向量化**：11g 的 client/server result cache 与 12c In-Memory 改变"重复排序"的经济学（产品文档转述 ⚠️）；Exadata 智能扫描下排序仍属 host 侧成本。
- **跨引擎对照**：PG 的外部归并排序（`work_mem` 超限落盘、`log_executor_memory` 观测）与 merge/agg 策略选择，逐点在 [../PostgreSQL技术内幕_查询优化深度探索.md](../PostgreSQL技术内幕_查询优化深度探索.md)；通用排序代价在 [../数据库查询优化器的艺术.md](../数据库查询优化器的艺术.md)。
- **论文线**：外部排序成本进入优化器的经典形态见 Selinger 1988 的 sort 代价项（✅ DOI：https://doi.org/10.1145/50202.50214 ）；SMJ/HJ 的算法比较现代研究（hash 优势论证系，未逐条核 DOI ⚠️ 不给链接）持续，本书模型仍是"为什么优化器有时坚持选 SMJ"的唯一工程解释。
