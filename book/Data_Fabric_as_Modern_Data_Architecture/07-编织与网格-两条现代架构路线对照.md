# 07 · 编织与网格：两条现代架构路线对照

> 主题章（⚠️ 推定归属本书"路线之辩"部分；00 §4 义务的展开）。fabric 与 mesh 是湖仓之后仅有的两个"总架构级"叙事，也是本系列读者最容易站错队的地方。本章以 **#201《Data Mesh》目录版**（实链 [../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md)，盘上已验收）为对照面，给出二维全表、合流形态与"什么时候都不选"的第三种答案。

## 7.1 一句话对撞（承 00 §4）

- fabric：**元数据驱动的自动化集成**——集中语义、分布数据、逻辑统一、自动装配。卖"发现与连接"。
- mesh：**组织驱动的架构重构**——领域自治、数据产品、平台赋能、联邦治理。卖"所有权与产品化"。

两者共享的底座判断：湖仓之后"再建一个大一统存储"是死路；分歧在统一性从哪来——fabric 从**平台上的机器语义**来，mesh 从**组织契约**来。

## 7.2 全维度对照表

| 维度 | fabric | mesh（#201 口径） | 裁决要点 |
|---|---|---|---|
| 统一性来源 | 集中元数据+图谱+语义层（03/04 章） | 域边界+产品契约+联邦策略（#201 05 章） | 机器语义快但脆（采集断供即退化），组织契约慢但稳 |
| 数据移动假设 | 逻辑优先、搬运最小（4.2） | 产品内自持、域间走契约出口 | mesh 默认"域内物化"，与 fabric 零拷贝理想相抵 |
| 平台角色 | 运行时（L2-L5 主动执行） | 赋能平台（自助基础设施），**刻意不做中央数据平面** | 对平台团队权力想象完全不同 |
| 治理形态 | 策略随元数据下发（08 章） | 联邦治理+策略即代码（#201 05 章） | fabric 治理自动化强、协商机制弱；mesh 反之 |
| 组织前提 | 低：现有人力+平台即可起步 | 高：需领域真的能养产品团队 | **企业没准备好 mesh 时，fabric 常被当安慰剂**（⚠️ 社区共识转述） |
| 规模失效点 | 语义采集/对账跟不上资产增速 | 域团队能力参差→产品质量塌方 | 两边都在人的环节漏水 |
| 消费体验 | 搜索+推荐+统一入口（5.6） | 产品市场+契约目录（#201 10-11 章） | 可叠加：mesh 供 L6，fabric 供 L3-L5 |
| 时间观 | 缝合存量（G1-G4 全都要） | 重构增量（新场景按域组织） | 存量占比决定 fabric 先发优势 |
| 证据强度 | ✅ 官方定义多口径并存（02.2） | ⚠️ 落地案例多自述、少公开量化 | 两者评估都要自带滤镜（对照 #201 00 的体裁声明） |

## 7.3 正交合流：常见组合形态（⚠️ 重构分类）

1. **mesh 骨架 + fabric 神经系统**（判断上最稳）：域/产品契约按 mesh 组织，跨域发现、血缘、影响分析与策略下发按 fabric 的 L3-L5 提供——mesh 的联邦治理恰好需要 fabric 的元数据平面当执行器。对位 #201 08 章多平面平台架构：fabric 组件天然填其"治理平面/观察平面"。
2. **fabric 先行收编存量，mesh 只管增量**：存量重系统（ERP/核心库）不动组织只上语义层；新业务域按产品化组建。演进式混合，09 章路线图即按此假设。
3. **mesh 先行、fabric 补账**：产品市场建起来后发现跨域组合消费才是主需求，回头买目录/图谱——此时 fabric 是 mesh 的**互补采购**而非路线否定。
4. 平台厂商的"都答应"：catalog 里画产品、语义层里塞契约（6.5 三阵营全在试）——⚠️ 除非 7.2 的裁决要点逐项过关，否则是话术合流。

## 7.4 第三种答案："都不选"的合理情形

- 单一业务线、<5 个系统：一个仓/一湖+轻目录（6.7 部门级）足够，上任何"总架构"都是负债。
- 强合规孤岛行业：数据跨域流动本身被制度禁止时，fabric 的"连"与 mesh 的"产品化"都失去主场景；治理册的基本功先行（实链 [../Understanding_Data_Governance/00-总览与阅读地图.md](../Understanding_Data_Governance/00-总览与阅读地图.md)）。
- 数仓重建窗口期：直接按开放表格式+标准 catalog 起手（[../Architecting_an_Apache_Iceberg_Lakehouse/00-总览与阅读地图.md](../Architecting_an_Apache_Iceberg_Lakehouse/00-总览与阅读地图.md)），架构债最小——**两条叙事本质都是在为"改不动的存量"打补丁**。

## 7.5 论证史补遗：为什么 2022-2023 辩得最凶

mesh（2020 起）与 fabric（2019 Gartner 起）几乎同时出生却互相指认对方为旧范式回潮：mesh 批 fabric=中央团队复辟（数据湖 2.0），fabric 批 mesh=把集成问题外包给不会做集成的域。本目录复盘（⚠️ 立场）：两批评各中的——**没有中央语义平面的 mesh 会在跨域组合处重建烟囱；没有域契约的 fabric 会把语义裁决权交给付不出人的中央委员会**。7.3-1 组合形态是对双方批评的同时应答。#202 兄弟册（登记不链）把 fabric×mesh×AI 三线并陈，正反映辩题已收敛为"分工而非胜负"。

## 7.6 判例演练：同一需求两条路线怎么解

需求："风控要用运营侧三张高频变更表+外部征信源，交付形态为特征表，周更→日更。"

| 步骤 | mesh 解 | fabric 解 |
|---|---|---|
| 权属 | 运营域作为属主域"发布产品"，契约定字段/新鲜度 | 不动权属，语义层登记实体"客户"跨源映射 |
| 供给 | 域团队自建产品管道（域内物化） | L5 生成/推荐管道，可能直读+按 4.2 判定物化 |
| 组合 | 征信源=另一域或外采适配器产品 | 图谱把外部源挂进同实体，虚拟化直读（G2 类比） |
| 变更 | 契约版本化，消费方按版升级 | 事件回路自动重排物化并通知（G3/G5 类比） |
| 薄弱点 | 域团队排期=交付上限 | 三表语义对账质量=正确性上限 |

判例结论（⚠️）：高变更、跨域、交付节奏受制于人→mesh 弱于 fabric；权属清晰、域有能力、口径需协商→fabric 弱于 mesh。**按需求特征混合路由，而不是按信仰选边**——这是本章唯一该被记住的可操作结论。

## 7.7 mesh 四原则 ⇄ fabric 七层映射表

| mesh 原则（#201） | fabric 对应层 | 合流接口 |
|---|---|---|
| 领域所有权 | L6 契约注册的属主字段 + L3 属主标签 | 属主变更双写，以 mesh 侧为源 |
| 数据即产品 | L6 交付面 + 4.4 API 织 | 产品目录=发现面的高级货架 |
| 自助平台 | L2 联邦+L5 回路（平台自动化面） | 平台供回路 runtime，域供规则 |
| 联邦计算治理 | L4 标签本体 + L5 策略下发（8.2） | 联邦政策编译进策略平面执行 |

读法：左列缺右列则原则空转（无执行体）；右列缺左列则中央集权复辟（无权属）。

## 7.8 辩论常见误解五连

1. "mesh 反平台"——mesh 反的是中央数据平台，其平台工程含量更高（#201 自助原则）。
2. "fabric 中心化=单点"——L3-L5 可联邦部署，集中的是**语义**不是**数据**（02.3 铁律 1 的推论）。
3. "选边后不能再换"——7.3 组合形态按工作负载路由（7.6），换的是配比不是信仰。
4. "小公司只配 fabric"——小公司两样都不配（7.4 第一条），一个仓库一个目录就够。
5. "AI Agent 时代 mesh 已死/fabric 已死"——两者都只是为"谁来裁决语义"提供不同场所（7.5），Agent 把裁决频率放大而未消除需求。

## 7.9 混合组织试点方案（一页版）

选 2 域（1 强 1 弱）+1 中央平台组：强域按 mesh 产品化（契约/SLA 自签），弱域由平台组代持按 fabric 回路托管（出生治理+物化开关）；半年比较五数：交付周期、口径事故数、消费方满意度、元数据覆盖率、人力成本。⚠️ 预期结果（社区案例转述）：弱域托管线胜在速度与覆盖，强域产品线胜在口径稳定与复用——据此定下一年配比，而非定教派。

## 7.12 一分钟裁决卡

跨域组合多、变更快、域团队弱 → fabric 机制占优；权属政治重、口径协商必需、域成熟 → mesh 机制占优；两者都不显著 → 维持现状+轻目录（7.4）。
