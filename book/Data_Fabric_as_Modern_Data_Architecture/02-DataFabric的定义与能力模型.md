# 02 · Data Fabric 的定义与能力模型

> 主题章（⚠️ 推定归属本书的"立论"部分）。fabric 是数据领域**定义权争夺最激烈**的术语：分析机构、虚拟化厂商、集成厂商、云厂商各有一版。本章先给出可辩护的最小定义，再展开能力模型与反定义。✅ 处为官方文档取证（状态码 200 实测），⚠️ 处为转述。

## 2.1 一个可辩护的最小定义

**Data fabric = 以统一元数据（技术/业务/运营三类）为地基、以语义模型（知识图谱）为索引、以主动元数据（active metadata）为执行回路，对跨异构系统的数据做"发现—理解—连接—编排—交付"的架构层。**

分解为五个必答项（任何自称 fabric 的产品必须能逐项回答）：

| 必答项 | 问题 | 缺项后果 |
|---|---|---|
| 元数据地基 | 三类元数据从哪采集、多久更新？ | 退化为一次性盘点文档 |
| 语义索引 | 词项/实体/关系图谱如何机器可推理？ | 检索停留在字符串匹配 |
| 主动回路 | 元数据能否触发下游动作（推荐/策略/管道）？ | 只是目录，不是 fabric（05 章判据） |
| 逻辑优先 | 消费是否可"不搬运"完成？ | 重蹈 ETL 拷贝债（04 章） |
| 组合交付 | 跨源数据能否按需组装为 API/数据集/特征？ | 停在"看得见连不上" |

## 2.2 源流与口径：Gartner→IBM→厂商

- **Gartner（源）** ⚠️：2019 年前后提出 data fabric 概念，定位为"跨平台数据管理的设计理念"，主张利用元数据与知识图谱实现自主化的数据集成；其原始报告付费墙内（本次 gartner.com 直引 403，列 00 禁引清单），转述依据为 IBM/Denodo 等对其的公开引用。
- **IBM 定义 ✅**（https://www.ibm.com/think/topics/data-fabric ）：IBM 将 data fabric 描述为一种**集成数据管理与治理的方法/架构层**，横跨组织全部数据源，覆盖数据准备与分析交付，核心构件包括元数据管理、知识图谱、数据虚拟化，目标是"正确数据在正确时间到正确地点"，并强调其**不要求数据搬迁**的混合/多云适配。中文口径同页 ✅ https://www.ibm.com/cn-zh/think/topics/data-fabric 。
- **Denodo 口径 ✅**（https://www.denodo.com.cn/zh-hans/tags/data-fabric ，200 实测）：虚拟化厂商把 fabric 叙述为"建立在统一访问层之上的数据管理架构"，其内容集反复以"fabric≠产品而先是架构"为题——⚠️ 注意其商业动机：Denodo 的落点是让虚拟化成为 fabric 的运行时。
- **Informatica 口径 ✅**（https://www.informatica.com/resources/articles/modern-data-architecture.html ）：把 fabric 列入现代数据架构选项谱系并给出与 lakehouse/mesh 的选型语境（⚠️ 同动机注：其落点是 Intelligent Data Management Cloud 的元数据驱动叙事）。

> 取证说明：以上四组 URL 为 2026-09-27 本机 curl 实测 200（Gartner 除外）；云厂商文档域（cloud.google.com 等）本环境不可达（000），AWS 侧仅发现 DMS 文档一处历史残留页（200 但正文无 fabric 内容，00 禁引清单已录）——**这本身是工业信号**：云厂商并未接受"fabric"作为产品品类名，而是把它化整为零进 catalog/governance 产品线（⚠️ 推论）。

## 2.3 能力模型：三层五面

把 2.1 必答项整理成本目录用的能力模型（⚠️ 重构工具，非原书图表）：

```
交付面   数据产品/API/特征/自助分析   ← 组合交付(必答5)
编排面   管道·策略·SLA 自动执行       ← 主动回路(必答3)
发现面   搜索·推荐·血缘·影响分析      ← 语义索引(必答2)
────────── 以上运行于 ──────────
语义层   知识图谱/本体/业务词表        ← 统一语义
元数据层 技术+业务+运营 三合一采集     ← 地基(必答1)
────────── 以下为非自建底座 ──────────
访问层   虚拟化/查询联邦/连接器        ← 逻辑优先(必答4)
存储层   湖仓/仓/事务库(原样保留)      ← 不替换原则
```

关键设计判断（⚠️ 本书立场推定）：
1. **fabric 的自建面只有语义层+元数据层+三面运行时**；存储与计算一律复用——这把它与"新平台"类提案（含同名 Microsoft Fabric，见 06.6）区隔开。
2. **访问层允许物理退化**：当虚拟化性能不划算时，fabric 应能自动决定"何时物化拷贝"——即 04 章的逻辑⇄物理开关。
3. **交付面对齐 mesh 语言**：fabric 的交付单元（可发现的 API/数据集）与 mesh 的数据产品在"产品化"语义上同构，为 07 章合流埋线。

## 2.4 反定义：fabric 不是什么

| 常见误读 | 辨析 |
|---|---|
| "fabric=某个中间件产品" | 是架构范式；产品是能力载体（2.2 各家口径差异即证） |
| "fabric=更花的目录" | 无主动回路（必答 3）的目录只是 catalog（对照 ../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md 的目录定义） |
| "fabric=湖仓升级包" | 湖仓解决存与算，fabric 解决找与连；正交可叠加（01 章 1.1） |
| "fabric=数据网(mesh)的厂商版" | 组织哲学相反：mesh 分权，fabric 集语义不分权运行（07 章全表） |
| "上了 fabric 就不需要治理" | 恰相反：策略下发是编排面核心职责，治理被内建而非外包（08 章） |
| "fabric 会淘汰 ETL" | 管道仍在，变化是管道由元数据**生成/推荐**而非手写（05 章） |

## 2.5 判据清单（PoC 时直接可用）

评估"是否真 fabric"的最小实验组（本目录方法论，🔧 类比见 03-05 章）：

1. 给一词项（如"客户收入"），系统能否在**不预先登记该词**的情况下跨 5 系统给出候选集并附置信度？（考语义索引）
2. 任一源表 schema 变更后，血缘下游消费者列表能否在分钟级自动更新并被通知？（考采集新鲜度+主动回路）
3. 同一指标在两个部门定义冲突时，系统能否展示冲突而非静默取一？（考语义层表达力）
4. 一个跨源取数请求，系统会先虚拟化直读还是自动物化？决策依据是否可见？（考逻辑⇄物理开关）
5. 新数据源接入 30 天后，自动打标覆盖率是多少？（考 AI 辅助元数据，10 章）

五题全"能"才配 fabric 之名——多数平台级目录产品在第 2、4 题露底（⚠️ 转述自社区评测共识，无一手取证，列此供验证）。

## 2.6 三句官方定义的逐句比对（✅ 页面均在 00 清单）

| 定义切面 | IBM 页表述 ⚠️转述 | Denodo 叙事侧重 ⚠️ | Informatica 侧重 ⚠️ |
|---|---|---|---|
| 本体 | 方法+架构层 | 架构（先于产品） | 架构选型之一 |
| 核心构件 | 元数据、图谱、虚拟化 | 虚拟化+语义 | 智能元数据 |
| 目标句 | 对的数据在对的时间到对的地方 | 统一访问体验 | 可组合的可信数据 |
| 对存储态度 | 不要求搬迁 | 不要求搬迁 | 与湖仓并置 |
| 隐含卖点 | 全栈平台可卖 | 运行时可卖 | 集成云可卖 |

结论：构件清单趋同、动机分化——**读 fabric 文献时把"定义"与"落点"分栏记忆**可防叙事绑架。

## 反问三则（通用加压测试）

1. "这套说法十年前的 EII/主数据/元数据管理演讲里是不是听过？"——听过，差别在三点：运营元数据升格（3.1）、回路带护栏（5.2）、AI 补人力欠账（10.1）。三点同时缺的"fabric"就是旧酒。
2. "没有 fabric 企业不也活着？"——活着≠在扩张；集成债按资产数平方增长，fabric 是**扩张期**方案，缩编期企业 7.4 的"都不选"更诚实。
3. "先买平台还是先改组织？"——先跑 9.4 的十六周脚本：它同时测量两件事，答案来自数据而不是布道。

## 最新演进与工业实践

- **定义收敛迹象（2024→2026）**：✅ 实测 IBM 于 2025 改版后的 think 站点仍维持"方法+架构层"双口径（URL 见 2.2），Denodo 中文站内容集聚焦"fabric 落地四件套：目录/图谱/虚拟化/集成"（✅ https://www.denodo.com.cn/zh-hans/tags/data-fabric ）——两家在**构件清单**上已趋同，分歧只剩"谁是运行时"。
- **分析机构动态 ⚠️**：Gartner 已为 Data Fabric Platforms 设立市场指南品类（文档 403 不可直引，仅可证实其存在性——本次 403 响应页本身即索引证据）；这意味着 fabric 从"架构话语"完成"采购品类"的制度化，09 章选型语境以之为背景。
- **开源侧反向动作 ⚠️**：开放 catalog 谱系（Iceberg REST catalog/Polaris 等，见 [../Architecting_an_Apache_Iceberg_Lakehouse/00-总览与阅读地图.md](../Architecting_an_Apache_Iceberg_Lakehouse/00-总览与阅读地图.md)）在 2025-2026 成为事实标准底座，商业 fabric 叙事被迫下沉兼容——"自带上层语义+复用开放 catalog"成为新采购姿势（推定，待 #174 兄弟册波尾闭环）。
