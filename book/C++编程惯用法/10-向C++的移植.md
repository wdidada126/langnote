# 10 · 向 C++ 的移植（⚠️ 推定章）

> 本目录是 *C++ Strategies and Tactics*（Murray 编，SIGS 1993；中译《C++编程惯用法》，人民邮电 2012）的
> 章节目录版笔记。章名/章序 ⚠️ 推定（依据见 [00](00-总览与阅读地图.md)）；本章以"C 代码向 C++ 移植/
> 两语言互操作"主题综述口径写作。1993 年这是**主流工程问题**（存量 C 代码 >> C++ 项目），
> 今天它退居为"FFI/ABI 边界问题"，但当年的很多答案恰好沉淀成了现代的边界纪律。
> 单文件大纲：[../C++编程惯用法.md](../C++编程惯用法.md) ｜ 总览：[00-总览与阅读地图.md](00-总览与阅读地图.md)

## 核心概念速览（中英对照）

- **增量移植** — incremental porting：一次一个模块从 C 迁入 C++，两套代码长期共存——当年唯一可行的迁移路径
- **名字改编** — name mangling：C++ 为重载/作用域把类型编进链接名；C 链接名保持朴素——互操作第一道墙（🔧 实测对照）
- **`extern "C"`**：链接规范开关而非存储/调用约定魔法——C++ 侧给 C 库挂号的正规通道，也是 C 侧导出接口的门面
- **语言接口（language linkage）** — linkage specification（标准措辞雏形）：以某一语言的 ABI 子集暴露接口；
  "C 是 ABI 通用语"的 1993 版本表述
- **布局兼容子集** — layout-compatible subset：`struct` 无构造/虚/私有成员时与 C 同布局——跨边界传数据的依据
- **反向移植（C 化）** — porting to C（当年现实需求）：C++ 写原型、按 C 子集重写交付嵌入式平台——今天对应"核心逻辑纯 C++、
  边界 C ABI"的分层
- **平台移植** — portability（1993 隐痛）：不同编译器方言/字节序/对齐的手工条件编译地狱——CI 与 clang/gcc 双轨时代的新形态
- **包装层（wrapper layer）** — thin C wrapper：在 C 库外面包一层值语义/RAII 类——移植工程的第一块脚手架，
  即今天"RAII 封装 FFI"的前身

## 一、动机：迁移不是开关，是三十年共存

1993 团队的真实处境：AT&T 式 C 工具链 + 新买的 C++ 编译器共用一个产品；
"重写"是奢侈品，"共存"是日常。本章主题的综述因此聚焦三类边界问题：
**(a)** 链接边界（mangling 对不上、调用约定差异）；**(b)** 内存边界（谁分配谁释放跨语言走火）；
**(c)** 生命周期边界（C 的 `malloc` 产物进不了 C++ 构造体系，反之析构产物 C 侧不知情）。
这三个问题**没有随 C++ 演进而消失**，只是从"全量移植"语境挪到了"FFI/插件/系统调用"语境——
这正是本章今天仍值得一读的理由。

## 二、机制：边界上逐层发生的翻译（🔧 实测）

**链接名层**。🔧 实测样本 10_externc.cpp（g++ 15.2 编译目标文件后 `nm` 实录）：

```text
000000000000000f T _Z15cpp_style_entryi     ← 无 extern "C"：改编名，参数类型入名
0000000000000000 T c_style_entry            ← extern "C"：与 C 编译器产出同名
```

一个符号之差，就是"能链上/链不上"的全部区别。机制要点：`extern "C"` 只改**链接名规范**，
不改类型系统——C++ 侧重载仍合法，但同名重载带不同参数会撞 C 链接名（只能有一个）。

**布局层**。C 兼容 struct 规则（无虚函数/无非静态成员函数要求按标准措辞收敛，实质不变）：
`struct Point { int x, y; };` 在两侧逐字节一致——跨边界传数组/DLL 结构体依赖的正是这条例。
一旦加 vptr（16 字节起步，见 🔧 03 章实测）或改变访问布局，兼容即告破碎。

**生命周期层**。当年三大纪律的 1993 表述与今日同构：
边界一侧分配的对象**必须**同一侧释放（跨 CRT 堆的经典事故今天仍在）；
C 句柄进 C++ 世界立即套上"构造即接管、析构即归还"的薄类（03 句柄章技术的 FFI 应用）；
C 回调进 C++ 世界不许携带 this 裸捕（对象寿命没人管）——cookie 参数就是当年的 `void* this`。

## 二点五、一个跨边界调用的完整清单（当年移植手册的压缩版）

C++ 侧包装一个 C 库函数 `int parse(const char* s, Result* out);` 需要逐层过的检查点：

1. **声明层**：`extern "C" {` 包住**函数声明**（宏与 inline 定义不参与链接，包了也无意义——10 号误区）；
2. **类型层**：参数/返回只用布局兼容子集（`const char*`、POD `struct`、`size_t`）；出现 `std::string`
   或带 vptr 对象即跨 ABI（🔧 03 章 sizeof 账）；
3. **生命周期层**：`Result*` 谁分配谁释放写进注释并配单测；理想形态是立即套 RAII 壳
   （03 句柄技术的 FFI 应用：构造接管裸指针、析构调 `result_free`）；
4. **异常层**：C 帧不认识展开表——**禁止异常越过本边界**，在包装层 catch 转错误码（09 章分层并用裁决的落点）；
5. **全局态层**：C 库的 `errno`/静态缓冲与 C++ 静态初始化顺序互不候账——边界函数尽量无状态。

这五条在 1993 是"移植项目组内部维基"的内容；今天它们逐条进了风格指南与 sanitizer 检查器——
**本章技术退役的方式不是被发明推翻，而是被制度化吸收**。

## 三、权衡

- **包装层厚度**：薄到只剩签名转发（快、但 C 语义泄漏进 C++ 客户代码）与厚到全量值语义
  （安全、但维护一层影子 API）。当年按"移植预算"权衡；今天按"边界信任等级"权衡——结构相同。
- **早绑定 vs 晚集成**：逐文件移植让每次合入可测（增量测试），代价是长期双语言状态里
  约定漂移；1993 无 CI，全靠移植清单（checklist）文化——其精神由 sanitizer/覆盖率继承。
- **反向交付到 C**：为嵌入式/工具链把 C++ 逻辑退回 C 子集，等于自愿放弃整条泛型轴；
  现代对应解是"核心纯标准 C++ + 导出 C ABI 面"，让 C++ 特性止步于库边界内（见演进节的插件/共享库做法）。

## 四、相邻概念对比

| 边界类型 | 1993 手法 | 现代手法 | 未变的物理定律 |
| --- | --- | --- | --- |
| C 库进 C++ | extern "C" 头 + 手工包装类 | 同上 + 自动生成（bindgen/cargo-llvm） | mangling 与 ABI 由 C 侧定义 |
| C++ 库出 C | 导出 C 接口 + 不透明句柄 | 同上（行业默认 ABI 面） | 虚表布局是隐式契约（05/03 章债） |
| 异常过界 | 禁止（当年也不支持） | 禁止；边界转错误码 | 展开器互不认识 |
| 内存跨界 | 同侧分配释放纪律 | 同侧 + 分配器注入 | 不同堆/不同 CRT 不兼容 |
| 全局初始化 | 顺序未定义的 C 静态对象 vs C++ ctor | 同上 + magic statics 解局部 | 静态初始化顺序灾难仍无语言总解 |

- **MEC++ 的同题条款**：Item 34/35（"像 C 一样程序会慢且不安全"/"从 C 移植要警惕"）与本卷主题同时代、
  互补——条款版展开见 [../More_Effective_C++/06-杂项讨论.md](../More_Effective_C++/06-杂项讨论.md)，
  其中 `extern "C"`/名字改编/数组退化的账本比本卷更细。
- **Google Style / abseil 的裁决**：Google 风格指南明令**禁止 C 风格转换与危险子集**，同时
  在其系统代码里以"C ABI 边界 + C++ 内部"分层（如 protobuf 的 C++ 核心 + 各语言绑定）；
  abseil（https://github.com/abseil/abseil-cpp ）整体走"新 C++ 纯头文件库、避免 C 遗留宏"路线——
  当年"向 C 靠拢以求兼容"的引力，被"向现代 C++ 收敛 + 边界留 C 面"的裁决替代。
- **现代 FFI 工具箱**：`extern "C"` 与 `#[no_mangle]`/`extern "C"` in Rust、`ctypes/cffi`、WASI/
  插件 ABI 头文件（`dlsym` 一个 `extern "C" register_plugin`）——1993 移植章的问题清单逐条可映射，
  只有"全量迁移"的社会语境消失了。
- **fmt/GSL 的边界示范**：GSL 的 `span`/`not_null` 常被用作"C 指针参数进 C++ 的第一道类型化"
  （接 C 的 `T*, size_t` 对 → `span`）；fmt 的 C++20 `std::format` 收编 printf 阵营的最后一块
  （`%d` 类格式串检查——当年移植里"日志不动"的豁免被收回）。
- **经典出处（核实口径）**：Stroustrup《The C++ Programming Language》历代版本自带"C 兼容"附录，
  是当年移植军规的正统源头；本卷章与之的关系更像"工程案例集"。⚠️ 本节未核对中译本具体页码，
  引原文请回英文原书。

## 常见误区与自查

1. 以为 `extern "C"` 改调用约定/结构布局——它只管名字（Windows 上 `__stdcall` 之类另有其人，
  见互链的 C++API 设计符号导出章）。
2. 把 `struct` 加了虚函数继续当 C 结构传——🔧 sizeof 与布局当场变（16 vs 8），跨 DLL 即 UB。
3. C 头文件里用 `#ifdef __cplusplus extern "C" {` 包裹**宏定义**——包裹无效且诱发误解：宏不参与链接。
4. 自查：你项目与 C 库的边界有几处没有类型化包装（裸指针+裸 size 参数满天飞）？
   把它们逐个换成 `span`/`not_null` 即是本章的 2026 作业。
