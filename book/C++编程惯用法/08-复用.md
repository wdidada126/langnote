## 核心概念速览（中英对照）

- **软件复用** — software reuse：以既有制品（设计/代码/测试）替代新写——1993 的"软件工程圣杯"叙事
- **黑盒复用 / 白盒复用** — black-box / white-box reuse：调库 vs 继承框架类改行为；各自的代价在当年就标好价
- **框架** — framework：反转控制（IoC）的可扩展半成品应用——"你不联系我，我联系你"
- **热点** — hot spot：框架中预留的可变点；用继承做=白盒热点，用参数/配置做=黑盒热点
- **类库** — class library：控制权在客户的应用零件集；与框架的分界=谁拥有 main 循环
- **应用框架时代病** — application framework（1993 热潮）：MacApp/框架库军备竞赛的产物，多数被历史淘汰，
  其结构洞见（IoC/热点/钩子）存活于今天的引擎与 SDK
- **复用资产化** — reuse as asset management（现代回看）：复用率的分母是"维护成本"不是"键盘小时"
- **可复用单元的尺寸谱** — granularity of reuse：函数<类<组件<库<框架<产品线（1993 已成的分类学）
- **二次设计** — re-engineering for reuse：把一次性代码改造成可复用件要付出的抽象税

## 一、动机：1993 复用是信仰，本卷试图给它装上账本

OOP 时代对复用的许诺一波三折：子程序→模块→类库→继承树→框架，每一代都宣称"这次成真"。
本章主题的综述价值不在布道，而在三笔冷静的账：
**(a)** 复用的收益按"设计决策的复用"计价，不按代码行——抄一份 200 行不如复用一次正确抽象；
**(b)** 每种复用机制自带耦合税：继承复用绑定基类演化（06 章纪律）、模板复用绑定实现可见（07 章）、
句柄复用绑定计数正确（03 章）；**(c)** 框架是复用产品的最高形态，也是抽象税最重的形态——
"框架强迫你按它的形状思考"这句话的敬意与警告各占一半。

## 二、机制：一张 1993 复用机制选型矩阵（重构口径）

| 复用需求 | 当年的首选机制 | 机制要点 | 暗账 |
| --- | --- | --- | --- |
| 共享算法/数据结构 | 类库 + 值语义对象 | 编译期契约（弱） | 表示暴露→重编译风暴（03 章解） |
| 扩展库内行为 | public 继承 + 虚钩子 | 运行期注入（框架的血管） | 脆弱基类（06 章纪律） |
| 参数化类型族 | 模板 | 编译期注入 | 膨胀 + 报错地狱（07 章） |
| 拼装正交能力 | MI/类参数 | 接口合成 | 二义/vbtable（05 章） |
| 共享昂贵对象 | 引用计数句柄 | 延迟复制 | COW 线程毒（03 章） |
| 跨进程复用 | ——（不存在） | 当年用 DLL 裸 C 接口硬凑 | 名字改编/ABI（10 章接棒） |

🔧 实测锚点（06_callback，g++ 15.2 实录）：1993 实现"可扩展回调点"的两种正统机制——
函数指针+`void*` cookie 与 ABC 纯虚基类——与现代 `std::function`+lambda 并存同测：
`sizeof(std::function<void(int)>)=32`（空捕获 lambda 仅 1 字节、进小缓冲免堆），ABC 对象含 vptr 8 字节。
**机制选型矩阵的第一次大洗牌**就发生在这里：单方法热点从继承树迁到可调用对象，
双方法以上才回到类层次。

## 三、权衡

- **复用 vs 可理解性**：热点越多、行为越依赖"框架在你没看的地方做了什么"——调试负担转嫁给每个用户。
  1993 框架消亡史的共同死因；今天 SDK 文档用"显式生命周期图"还债。
- **抽象税前置**：为复用设计=为想象中的第二用户设计；猜错方向比不复用更贵。
  现代裁决（YAGNI/规则 3 次再抽象）语言化不了，仍是纪律。
- **复用单位**：函数→对象→组件→库→框架→产品线，尺寸每升一级，抽象税与耦合税同时上涨——
  本章全部讨论可以还原为这一条单调性。
  依赖越"反转"，迁移越昂贵。这是 03/10 章 ABI 论题的组织学镜像。

## 三点五、1993 框架尸检：三个死因的现代对照

综述当年盛极一时的 Application Framework（MacApp 谱系、各 GUI/数据库大框架——具体点名 ⚠️
本卷未可考，不代录），其消亡路径惊人一致，而每条都反着长成了今天的形态：

| 当年死因 | 机制细节 | 现代解药 |
| --- | --- | --- |
| 钩子调用序不可知 | 派生钩子何时被框架回调全凭源码考古 | 生命周期显式化（组件状态机/文档化回调序）；🔧 04_nvi 的"流程焊死"是语法起点 |
| 全树重编译 | 框架头文件人人 include，改一处崩全站 | 03 章句柄/防火墙思想的工业化：pimpl + 稳定 C ABI 面（10 章） |
| 单继承税 | 一切扩展必须挂进框架基类族 | 依赖注入 + 插件注册表；🔧 M8 的 `std::function` 吞掉单方法扩展点 |

结论：**框架作为一种产品死于抽象税失控，框架作为一种思想（IoC/热点/反转控制）活得比谁都好**——
今天每一个"你写回调、我定时钟"的运行时，都是本章概念的再保险。

## 四、相邻概念对比

- **复用 vs 重写**：1993 已承认"重写常常更便宜"；现代版表述：复用决策=维护责任转移决策。
  判据没变的一直是那道题：抽象错了时，**不复用的损失 vs 维护一个错误抽象的损失**，后者几乎总大。
- **框架 vs 库**：IoC 与否；框架=你扩展它，库=你调用它。
- **框架 vs 应用服务器/引擎（现代回声）**：游戏引擎、Web 框架、React 式"控制反转 UI"
  是 1993 框架论的直系后代——概念谱系迁移，账（抽象税/热点调试）一分没少。
- **继承复用 vs 参数复用**：本卷双手互搏的焦点（04/06 vs 07），1997 后 Loki/STL 时代由
  "类型集开放吗"给出判据。

## 最新演进与工业实践

- **机制选型的现代清算**：
  - 引用计数 COW 句柄 → `shared_ptr`（线程安全计数、无 COW；🔧 见 03 章对照）；
  - ABC 回调树 → `std::function` + lambda（🔧 实测 M8）；
  - 白盒继承热点 → policy 类/CRTP（编译期）与依赖注入（运行期注册表）双轨；
  - 框架"上帝对象" → 组合式微内核 + 插件 ABI（`extern "C"` 工厂导出；对应
    [../C++API设计/11-脚本绑定与插件扩展.md](../C++API设计/11-脚本绑定与插件扩展.md)）。
- **Google Style / abseil 的裁决**：Google 的规模化复用方案是**monorepo + 依赖声明 + 公共库治理**
  （abseil 即其溢出，https://github.com/abseil/abseil-cpp ，配合 LTS 分支策略）——
  "复用单位=带版本与兼容承诺的库"取代"复用单位=继承树"，是本章论题的组织级终局。
- **包生态**：vcpkg/Conan/CMake `FetchContent` 把 1993 手工拼装类库的编译-链接噩梦
  变成清单文件问题；但"找对抽象"的税一分没降——工具换了，纪律未变。
- **经典文献（核实口径）**：
  - Coplien《Advanced C++ Programming Styles and Idioms》（Addison-Wesley, 1992）——本卷同年代、
    同主题（框架/惯用法/类参数）的更系统大部头；两处可互证：任务简报提及的 Coplien 与本章主题吻合，
    但**本卷中其文具体篇目未能核实** ⚠️，引用观点请以 1992 原书为准；
  - 《C++ Gems》（Lippman 编，Cambridge UP, 1996）——同类 C++ Report 文章精选集，
    可作"文集型知识载体"的参照物；

## 常见误区与自查

1. "复用率"当 KPI——1993 的框架军备竞赛已演示过古德哈特定律的全息版本。
2. 把框架当"大号类库"卖——不解释 IoC 与隐藏调用序的框架文档都是不合格品（当年与今天同罪）。
3. 见 lambda 就拆回调 ABC——两方法以上、需要身份/状态的扩展点仍该有类型（别把 04 章纪律也扔了）。
4. 自查：你最近一次"继承类库获得扩展点"，后来基类升级时你的覆盖还编译得过吗？——那便是白盒复用的债息。
