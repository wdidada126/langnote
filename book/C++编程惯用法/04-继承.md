## 核心概念速览（中英对照）

- **子类型多态** — subtype polymorphism：基类指针/引用在运行期分派到派生实现——1993 年"复用+扩展"的主引擎
- **公有继承即 is-a** — public inheritance means "is-a"：继承不是"借用实现"的许可证，是类型承诺
- **虚函数** — virtual function：契约的运行时兑现通道；一次 vptr 取表间接（🔧 实测对象含 vptr 后 16 字节，见"机制"）
- **纯虚函数** — pure virtual function：把契约与实现分离的声明；抽象类的原子
- **虚析构** — virtual destructor：经基指针 delete 派生对象的唯一正确出口；1993 已是军规，今天仍是（有条件地）
- **对象切片** — object slicing：按值传派生对象丢派生部分——继承的第一类静默事故
- **私有继承** — private inheritance："按实现继承"的通道，1993 年争论焦点之一；后来 largely 让位给组合 + `[[no_unique_address]]`
- **覆盖 vs 重载 vs 遮蔽** — override / overload / hiding：1993 年名字查找的三大坑，`override` 关键字（C++11）才把拼写错误显性化
- **脆弱基类问题** — fragile base class（后起之名）：改基类悄悄弄坏派生类——继承复用的结构性税

## 一、动机：继承在 1993 是被供起来的，也是被滥用的

"对象技术"营销高峰期的 1993 年，复用承诺几乎全押在继承上：类库=继承树，扩展=派生，
定制=覆盖。本卷继承章的综述贡献不在新奇，而在**把边界说清**：
什么时候继承是类型建模（is-a），什么时候只是偷懒抄实现（has-a 冒充 is-a），
以及一经继承就自动生效的语言事实（切片、虚分派、构造析构顺序）会给设计埋下什么。
今天重读，这一章的正确率惊人地高——因为语言后来没有推翻这些机制，只是**收窄了它的推荐场景**。

## 二、机制：一条继承链上同时发生的事

🔧 实测样本 03_mi.cpp 的基类部分（g++ 15.2 实录）：`sizeof(Base)=16`（一个 `int` + vptr，x64 下
含对齐），`struct L : Base { int y; }` 仍是 16（尾填充复用）。机制清单：

1. **分派账本**：经 `Base*` 调 `f()` 时读 vptr → 槽位 → 间接跳；经值/静态类型调用则直调。
   "多态只对指针/引用生效"不是口诀，是这条布局事实。深度展开在
   [../深度探索C++对象模型/04-Function语意学.md](../深度探索C++对象模型/04-Function语意学.md)（同波次目录版，已核实存在）。
2. **类型账本**：`L*` 可隐式转 `Base*`；🔧 实测多路情形两个 `Base*` 甚至不同址（见 05 章）——
   静态类型系统与指针恒等等式在继承下不成立。
3. **生命周期账本**：构造自基至派、析构自派至基；构造/析构期虚调用**不越过当前层**（vptr 被逐层切换）。
   1993 年靠纪律背下来的这条，正是 06 章 NVI 雏形的机制根。
4. **值语义的反例**：`void f(Base b)` 收到 `L` 实参时静默截尾——切片。数组按基类步长遍历派生对象
   则是切片成批发生（MEC++ Item 3 的经典事故）。

## 二点五、案例讨论：一次 delete 的完整旅程（当年背口诀，今天看账本）

`Base* pb = new Derived; delete pb;` 在 1993 年靠口诀记忆（"基类析构要虚"），机制长这样：

1. `operator delete` 需要先知道**销毁谁**——查 `pb` 指向对象的 vptr，取" deleting destructor "
   槽（MSVC D0/D2、Itanium `_ZN...D0Ev` 形态），间接跳进 `Derived::~Derived`；
2. 派生体析构完 → 链上自动逐层调基类析构 → 最后回到 deleting 版本把 40 字节（🔧 03 章实测尺寸量级）
   归还分配器；
3. **若 `~Base` 非虚**：第 1 步查不到、直调 `Base::~Base` 再按 `sizeof(Base)` 释放——
   派生部分从未被销毁 + 释放尺寸错误，UB 的每一步都发生在编译成功之后。

这条链也解释了为什么"虚析构"与"有虚函数"近乎等价决策：vptr 反正已经在对象头上（🔧 实测
`Base` 含一个虚函数即 16 字节），析构槽不加尺寸、只加一次间接；真正贵的是**演化约束**——
基类析构一旦虚化，改不回非虚就是破坏性变更。1993 军规因此完整表述为：
"要么整个类为多态设计（虚析构+文档化契约，06 章纪律），要么明确禁止被继承使用"。

## 三、权衡

- **表达力 vs 耦合**：继承把派生类焊死在基类的表示与行为细节上（改基类危险即"脆弱基类"）；
  换来的是框架级的扩展点。1993 类库（如各种 Application Framework）用整库命运赌这个权衡。
- **虚调用税**：一次取表 + 断内联 + 断去虚化；在解释器/游戏主循环这类按元素热路径里，这笔税
  后来催生"能模板/`variant` 就不要虚函数"的现代分层（见 07/08 章互链）。
- **析构选择**：多态基类要 public 虚析构；非继承用途的类**既不写虚析构也不把析构设 protected**
  则是 UB 通道——当年只有半条军规，今天两条都有规则号。

## 三点五、当年惯用法 → 问题 → 现代替代（本章三例）

1. **"public 继承 + 覆盖任意 public 虚函数"** → 问题：基类不变式对派生者零防御（客户还能直调钩子）
   → 现代替代：06 章 NVI/C.128 语法化；钩子不外露。
2. **"用 protected 数据成员向派生类开放复用"** → 问题：表示泄漏=基类永久冻结，1993 大型框架的
   头号演化阻力 → 现代替代：protected 只留访问器/构造缝，表示走 03 章句柄私有化。
3. **"基类指针当万能回调（每个扩展点一个 ABC）"** → 问题：🔧 实测每个 such 对象自带 vptr 税 +
   堆分配 + 类型擦除缺失（见 06 章对比表）→ 现代替代：单方法扩展点直接 `std::function`
   （实测 32 字节、小捕获免堆），多方法才回类层次。

三例共同构成本章的现代判决：**继承没有错，错的是 1993 把继承当作唯一扩展轴**——
类型轴（模板/concepts）与值轴（可调用对象）解锁后，继承收缩到"开放类型集 + 共享契约"的本命位。

## 最新演进与工业实践

- **语言给继承加的护栏**：`override`/`final`（C++11）终结拼写错误型漏覆盖；协变返回、
  `= delete` 封拷贝让"仅堆多态对象"（MEC++ Item 27 的招）有了标准姿势。
- **Google Style / abseil 的裁决**：Google 风格指南对继承的现行态度是"谨慎使用，接口要文档化其
  线程安全等约定"；其实现里多态优先窄接口、少层深树（abseil 库中继承树普遍 ≤2 层，可仓库内自查）。
  1993 "框架即深继承树"的形态在工业代码里已让位于组合 + 函数对象注入。
- **单方法接口的退位**：🔧 实测（06_callback）一个纯虚回调 ABC 的对象也要 8 字节 vptr + 一次堆/栈绑定，
  而 `std::function`（实测 sizeof=32，小捕获免堆）+ lambda 直接吞掉这条需求——
  当年"策略模式=继承树"的相当部分今天=闭包。模式谱系的现代重排见
  [../C++20设计模式/13-状态与策略.md](../C++20设计模式/13-状态与策略.md)。
- **编译期多态的分流**：CRTP（MEC++/Loki 谱系，见 [../More_Effective_C++/08-补编-从MEC++到Loki定制技法谱系.md](../More_Effective_C++/08-补编-从MEC++到Loki定制技法谱系.md)）
  与 C++23 deducing-this 继续蚕食"为复用而继承"的动机；运行时多态收缩到"开放类型集"的本命场景。
- **经典文献（核实口径）**：Stroustrup《The Evolution of C++》（HOPL-II，1993；作者页
  http://www.stroustrup.com/hopl2.html 可下载）给出虚函数/多重继承进入语言时的争论原貌——
  引用"当年为什么这样设计"时它是比本卷更正统的出处。

## 常见误区与自查

1. "public 继承 + 基类无虚析构" 经 `delete pb` 即 UB——1993 口诀"有虚函数就给虚析构"今天仍对；
   反向新增：不需要多态删除就把析构设 protected（封 delete 基指针）。
2. 用 `protected` 数据成员做"继承复用"——表示泄漏给全树，基类从此不能演化；改 protected 访问器都算改良。
3. 派生类里"重载"基类函数忘了 `using Base::f;`——同名遮蔽，老坑今天仍不报警（只给 `-Woverloaded-virtual` 级提示）。
4. 自查：给你一个 `Stack` 类，"继承它得到 `BoundedStack`" 类型上成立吗？`is_a` 答"否"（契约被收紧违 LSP）——
   这就是当年该章最想让读者练出的直觉。
