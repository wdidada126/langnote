## 核心概念速览（中英对照）

- **数据抽象** — data abstraction：以"可执行操作 + 不变式"定义类型，表示细节对使用者不可见
- **抽象数据类型** — Abstract Data Type (ADT)：数据抽象概念落地为类型的那套操作契约
- **信息隐藏** — information hiding：Parnas 1972 提出——按"设计决策"而非"流程图"切模块，隐藏的是**会变的**东西
- **表示无关性** — representation independence：换掉内部表示不波及使用者，是复用的前提
- **不透明指针** — opaque pointer：C 式实现句柄的招：`typedef struct Rep* Handle;` 定义留在 .c 里
- **接口/实现分离** — interface/implementation separation：1993 语境靠"把头文件当契约"达成；现代由编译器参与达成
- **程序抽象** — procedural abstraction：把"怎么做"折叠进"做什么"命名的函数/成员函数
- **过程式契约** — operational contract：每个操作用注释写明前置/后置条件——当年的"接口文档即类型系统"
- **类型屏障** — type barrier：用新类型而非裸 int/指针承载领域概念，防混用
- **接口概念化** — interface-as-concept（现代回看）：一组合法操作的集合本身是"概念"，C++20 concepts 才把它写进语言

## 一、动机：1993 年为什么把"抽象"放在第一席

1993 年的现场：C++ 刚有第一份手册（ARM, 1989），**标准还在途中**（C++98 尚有五年）；
"面向对象"正从学术词变成采购需求，而多数团队的真实水平是"用 C++ 写带 class 的 C"。
本卷把抽象列为首题，综述式地回答三个当时的实际问题：

1. 复用到底复用什么？——不是复用代码行，而是**复用一套操作契约**（类库/框架的共同前提）；
2. 没有命名空间、没有访问检查工具的年代，怎么防止使用者戳破表示？——把"不可见"落成
   private + 不透明指针 + 头文件纪律；
3. 从小例子到真系统，抽象层次怎么搭？——C-ADT（`Stack*` + `StackPush`）是最小完整样本。

这一章的**方法论价值大于技术细节价值**：它教的是"先把类型设计对，再谈继承模板"的思维顺序，
这条主张越过 33 年仍是公理；具体写法（无模板的参数化、无 `const` 成员函数的时代习惯）则多数已退役。

## 二、机制：抽象的三层落地（当年写法）

**第 1 层：C 式 ADT——不透明指针 + 自由函数。**表示藏进 .c，头文件只给类型名和函数族：

```cpp
// 🔧 示意（对照实样本 g++ 15.2 -std=gnu++23 编译运行实录，见"9 7"输出）
typedef struct StackRep* Stack;      // 客户端永远拿不到 StackRep 的定义
extern Stack StackNew(int capacity);
extern void  StackDispose(Stack);
extern void  StackPush(Stack, int);
extern int   StackPop(Stack);
struct StackRep { int *elems; int top, capacity; };   // 定义只出现在实现文件
```

**第 2 层：class 把契约搬进类型系统。**private 使"表示不可见"从君子协定变成编译错误；
构造/析构使不变式有了"建立点/清算点"。🔧 实测（01_adt_c_vs_class.cpp）：同一栈 ADT 的两种实现
运行结果一致（`C-ADT: 9 7` / `class: 9 7`），差别全在编译期——忘了 `StackDispose` 编译器不管，
忘了 `delete[]` 也一样不管；而 `s2 = s;`（浅拷贝）在当年是真实事故源，
今天用 `= delete` 一行封死（示例中即如此写）。

**第 3 层：契约仍留在注释。**1993 年的天花板：`pop 不得在空栈上调用`这类不变式**没有任何语言机制**
承载，只能靠文档与运行时断言。这正是后来 concepts（操作集合可检查）、GSL（前置/后置条件可标注）
要填的坑——当年不是没想到，是没有载体。

## 三、权衡

- **抽象税**：不透明指针每次操作至少一次解引用 + 一次跳转；1993 硬件上这笔税显眼，章内立场是
  "该付"——因为另一头省的是维护与复用的税。现代编译器内联 + LTO 基本退掉这税，结论不变但理由换了。
- **粒度**：ADT 切太细（一个类型一个文件）放大编译依赖；切太粗（上帝类）毁掉表示无关性。
  这架天平后来被 Lakos 的物理设计理论化（见互链）。
- **表达力换检查**：C-ADT 里 `Stack` 退化成 `void*` 满天飞的时代，类型屏障形同虚设；
  class 换回屏障，代价是引入构造/析构的心智负担——本卷全书都在还这笔账。

抽象税的三个可拆成分（当年一本账，今天三本账）：

| 成分 | 1993 成本 | 2026 成本 | 备注 |
| --- | --- | --- | --- |
| 间接寻址 | 显著（无内联） | 近乎归零（LTO/内联） | `->` 一跳可被吃掉 |
| 堆分配 | `StackNew` 必 malloc | 可用 small-buffer/池 | 税源从指针移到分配器 |
| 心智 | 读注释才能懂契约 | 概念/文档双轨 | 这头**没有**降税——concepts 只覆盖操作侧 |

## 三点五、相邻概念对比前先分清：本章的"抽象"不是"抽象类"

1993 文本里 abstraction 一词指**类型设计层面**的表示隐藏；今天初学者常把它与 `virtual` 抽象类
（语言设施）混为一谈。区分标准一句话：**去掉全部 class 关键字，C-ADT 的抽象还成立吗？**
成立——所以抽象不寄生于继承；抽象类只是抽象的第 ⓷ 种实现手段（另两种：模板参数化=第 07 章，
函数对象=第 08 章 🔧 实测）。本目录 04/06 章对继承的全部纪律讨论，前提都是本章把这个层级关系摆正。

## 四、相邻概念对比

| 概念 | 关注点 | 1993 载体 | 现代载体 |
| --- | --- | --- | --- |
| 封装 | 表示不可见 | private（可被 friend 绕过） | private + pimpl + 模块 |
| 抽象 | 操作契约完备且最小 | 注释契约 | concepts/requires 可检查 |
| 多态 | 一契约多实现 | 继承+虚函数（第 4/6 章） | 虚函数/模板/`variant` 三轨 |
| 复用 | 契约+实现的再利用 | 类库（第 8 章） | 包管理 + 泛型组件 |

## 最新演进与工业实践

- **接口文档 → 可检查概念**：1993 写在注释里的"T 必须有 push/pop"，C++20 用
  `template <typename S> requires StackLike<S>` 交给编译器。🔧 实测（05a/05b）：无约束模板的
  报错发生在**函数体内部**（g++ 15.2 实录：`no match for 'operator+'`，指向实例化深处），
  有约束版报错**移到调用点**（`constraints not satisfied` + 失败表达式逐条列出）——
  行数不一定更少（20 对 7），但报错主体从"实现细节"换成了"接口契约"，这正是抽象的语法化。
- **契约注释 → GSL**：前置/后置条件用 `Gsl::Expects/Ensures`（微软 Guideline Support Library，
  https://github.com/microsoft/GSL ）标注，可挂检查器——当年"注释即契约"的现代直系后裔。
- **不透明指针 → 语言设施**：C++23 `module` 从链接名与翻译单元层面砍掉"头文件泄表示"的老问题；
  过渡方案见 [03 句柄章](03-句柄.md)。
- **Parnas 1972**（"On the Criteria To Be Derived from Decomposition of Systems"，IEEE 纪念转载）
  仍是本章所有论证的公共底座；引用它不需要本书语境也成立。
- 工业样本对照：fmt（https://github.com/fmtlib/fmt ）把"格式化"做成带编译期检查的最小接口，
  是"操作契约 + 表示无关"在 2020 年代最干净的教科书实现。

## 常见误区与自查

1. 把"getter/setter 全覆盖 public 字段"当封装——接口等于表示，表示无关性为零。这算过 1993 年的章评吗？
2. `typedef struct Rep* Handle` 后给客户端发 `void**`——类型屏障自毁。
3. 认为"抽象=虚基类"。抽象首先是**类型设计**，继承只是其第 N 种实现手段（第 4/6 章会展开这个纠偏）。
4. 自查题：给你的 `Date` 类型列出最小操作集，并指出哪些不变式今天仍然只能活在注释里——
   那些就是 GSL/concepts 的用武之地。
