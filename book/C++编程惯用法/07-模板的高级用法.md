## 核心概念速览（中英对照）

- **参数化复用** — parameterized reuse：以类型为参数复用算法/容器——与继承复用正交的第二条复用轴
- **函数/类模板** — function/class template：1993 已可用但坑遍布：无 `typename` 前缀、模板定义常须进头文件
- **特化** — specialization：全特化当年已可用；偏特化从未进标准（1993 若干编译器私有扩展——考古点）
- **延迟解析** — lazy parsing（cfront 现实）：依赖名到实例化点才查——当年"模板=带宏检查的文本"心智的成因
- **两阶段名称查找** — two-phase name lookup（1998/DR 后确立）：无关名定义期查、依赖名实例化期查——对 1993 写法的正式清算
- **显式实例化** — explicit instantiation：把实例化从使用点剥出集中管理（编译时间治理，深度探索 07 章同款问题）
- **接口即约束（文档时代）** — interface-as-document：`T` 要满足什么只能写注释——直到 concepts 才有载体（🔧 实测见下）
- **traits 思想的前史** — traits（1990s 中后期成型）：用类型萃取参数化差异——本卷语境最多到"按类型重载转发"的雏形
- **代码膨胀** — code bloat：每实例一份代码——1993 反对模板的头号账目，至今仍是体量权衡

## 一、动机：模板在 1993 是"新语法"，不是"新范式"

1993 年的现实：STL 尚未发布（HP 代码进标准要等到 1994/98），泛型编程这个词还没被 Stroustrup
在 1997 论文里加冕。模板的用法主流是**容器类与类型安全的工具函数**，写作体验被三件事支配：
实例化模型未定（cfront 文本式延迟解析 vs 前端预解析的编译器分裂）、报错在模板体内爆炸、
约束全靠注释。本章主题综述的价值不在这些技术细节（大多退役），而在它坚持的立场：
**类型参数化的复用与继承参数化的复用是两条腿，缺一条的复用战略是跛的**——这个论断在 GoF 年代
（继承独大）有超前性，在今天（concepts/泛型容器遍地）是常识。

## 二、机制：一个"当年写法"如何被语言逐步拆弹

**当年（1993 语境典型形态，🔧 示意）**：

```cpp
template <class T> class Stack { ... };      // 无 typename 关键字；成员模板要写 "T::Link* p;"（嵌套依赖名歧义时代）
template <class T> T max(T a, T b) { return a < b ? b : a; }
// 约束：注释——"T 必须有 operator< 且值语义"
```

三个历史断层：`typename` 歧义（成员类型 vs 静态成员）在标准化中被 `typename` 前缀立法解决；
"模板定义放哪"随实例化模型收敛成"定义可见即可用（头文件/显式实例化二选一）"；
约束表达则一路走到 C++20。最后这条的今昔对照🔧 实测（05a/05b，g++ 15.2 实录）：

```text
# 05a 无约束：错误在函数体深处
05a...: error: no match for 'operator+' (operand types are 'NoPlus' and 'NoPlus')
        ← 指向模板体第 5 行"实例化中"
# 05b concepts 约束：判决提前到调用点
05b...: error: no matching function for call to 'add_v2(NoPlus&, NoPlus&)'   ← 指向 main 调用处
        note: constraints not satisfied
        note: the required expression '(a + b)' is invalid
```

诚实读数：本例中 concepts 版报错**行数反而更多**（20 vs 7）——它的红利不是"短"，而是
**责任归属**：从"你的实现内部编译不过"变成"你未满足接口契约"。这正是把 1993 注释契约
搬进类型系统的机制含义。

## 三、权衡

- **类型安全 vs 膨胀**：每实例一份代码/调试符号——1993 的对策是"公共体 + 类型外壳"（把与 T 无关的
  代码下沉到非模板基类，`std::vector<T>` 现代ABI里仍有等价物：`__vector_base`）。
- **编译期检查前置的代价**：实例化晚 ⇒ 报错晚且迷惑（当年 -fpermissive 式自救）；检查早（concepts）
  ⇒ 表达约束本身成为新维护面。
- **模板 vs 继承复用的选型**（本章与 04/06 章的合题）：类型集开放（框架钩子）→ 虚函数；
  类型集编译期已知 → 模板。1993 只能在两者间手工押注，今天有 `if constexpr`/concepts 让混合策略可写。

## 三点五、机制切片：为什么"约束上移"是质变而不是包装

🔧 实测两份报错的信息结构（05a/05b 实录节选）：

```text
05a: In instantiation of 'T add_v1(T, T) [with T = NoPlus]'
     error: no match for 'operator+'   ← 主语：实现体（第 5 行模板内部）
05b: error: no matching function for call to 'add_v2(NoPlus&, NoPlus&)'   ← 主语：调用式（main 第 8 行）
     note: constraints not satisfied
     note: the required expression '(a + b)' is invalid                    ← 契约逐条对账
```

差别在**判决发生在哪一层**：无约束时编译器"先接受、进门后再验"，错误报告是验尸报告；
concepts 把它变成"门口验、不过即拒"，错误报告成了**接口契约的对照清单**。
对 1993 语境的读者，这意味着那章注释里"T 须支持 + 与值语义"第一次有了会生气的守门人——
当年写给"人"看的接口文档，今天写给"编译器"看。

## 四、相邻概念对比

| 时代 | 约束表达 | 名称查找 | 报错落点 | 代表 |
| --- | --- | --- | --- | --- |
| 1993 (ARM/cfront) | 注释 | 全延迟 | 实例化体内 | 本章语境 |
| C++98 | 注释 + SFINAE 雏形 | 两阶段（DR 后收紧） | 体内，附带"实例化自…"栈 | STL 入标前后 |
| C++11/14 | `static_assert` + 类型特征 + 标签分发 | 同 | 可引到调用点（`T=` 模板参显示） | EMC++ 时代 |
| C++20+ | **concepts/requires** | 同 | **调用点 + 失败表达式枚举**（🔧 实测） | fmt/abseil 全面可用 |

## 最新演进与工业实践

- **concepts 接管接口文档**：1993 注释"T 须可比较可拷贝"今天写成
  `template <std::regular T>`（标准概念库：`copyable/regular/invocable` 等，cppreference
  https://en.cppreference.com/w/cpp/language/constraints ）；自定义契约用 `requires` 表达式。
  本目录 🔧 实测即其效果样本。
- **变参模板终结"重复代码墙"**：当年为 N 元组写 N 份模板或预处理器循环；C++11 变参 + 折叠表达式
  一把收编。谱系与实操见 [../C++模板元编程.md](../C++模板元编程.md) 与 [../C++20模板元编程.md](../C++20模板元编程.md)。
- **fmt 的头号工业案例**：fmt（https://github.com/fmtlib/fmt ，其格式字符串编译期检查并入 std::format，
  提案 P0645，作者 Victor Zverovich）展示的正是"模板替代文本宏式 printf"的终局形态——
  当年"类型安全变参"之争，模板赢了 `varargs`。
- **abseil/GSL 的裁决**：abseil 大量使用"窄模板 + static_assert 前置"而非深模板元编程（其
  `bit_cast` 即概念约束的先声）；GSL（https://github.com/microsoft/GSL ）用类型特征把契约
  （`not_null`、`span` 界检查）做成可组合的模板组件。Google 风格对"模板复杂度"的态度：
  优先简单泛型，元编程需评审——当年"膨胀恐惧"在准则层的回声。
- **对象模型侧的配套演化**：实例化模型/ELM/extern template 的正式叙述在
  [../深度探索C++对象模型/07-站在对象模型的尖端.md](../深度探索C++对象模型/07-站在对象模型的尖端.md)；
  SGI STL 的 traits 实战在 [../STL源码剖析/03-迭代器与traits.md](../STL源码剖析/03-迭代器与traits.md)。

## 常见误区与自查

1. 拿 2010 后的模板心智读 1993 文本会低估其艰难：那里**没有** SFINAE 工具箱、没有类型特征、
   多数编译器连成员模板都残缺——"当年的技巧"先当考古读。
2. "concepts 让报错变短"——🔧 实测证伪（至少不必然）；正确收益是**报错主体=接口契约、位置=调用点**。
3. 代码膨胀在现代对策下（`extern template`、去虚化、`if constexpr`）大多可控——
   1993 的恐惧不该变成 2026 的禁令，也不该反过来无视。
4. 自查：你的模板库最近一次让人崩溃的报错，在 `requires` 化之后能少读几层实例化栈？
