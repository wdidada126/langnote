## 核心概念速览（中英对照）

- **类不变式** — class invariant：对象在任何公开操作前后必须成立的约束，构造建立、析构清算
- **三法则** — Rule of Three（后起之名）：需要手写析构的类，几乎一定也要手写拷贝构造与拷贝赋值——1993 年尚无此名，坑已在
- **浅拷贝陷阱** — shallow copy pitfall：默认成员拷贝对裸指针资源是双重释放的引信
- **常正确性** — const-correctness：把"逻辑上只读"标注进类型；1992 年前后正是该词的风口
- **友元** — friend function/class：受控的表示访问授权，当年被用作运算符重载与跨类协作的出口
- **值语义 vs 引用语义** — value vs reference semantics：拷贝即得独立副本，还是拷贝即共享（靠句柄实现，见 03 章）
- **成员初始化列表** — member initialization list：进入函数体前完成初始化的唯一通道
- **委托式职责** — delegation of responsibility（后起之名）：类把子任务转交给成员对象——"组合优先于继承"的原子形态
- **最小接口** — minimal interface：每个公开成员都是未来的维护债——1993 已见雏形的主张
- **代理成员** — surrogate member（当代回看）：用 `= delete`/`= default` 精确裁剪特殊成员函数——语言 2011 年才给的工具

## 一、动机：把"类型设计"从风格升格为工程

1993 年的 C++ 项目事故榜上，前几名几乎都出自类的默认行为：忘写拷贝语义导致的**双重释放**、
构造顺序导致的**半初始化对象**、public 表示被客户端直捅导致的**改一处崩全站**。本章主题的综述立场
是明确的一条：**类的默认行为是危险的起点，不是可用的终点**——每个特殊成员函数都要"设计或不设计"，
且要留下书面理由（今天叫 `= delete` 加注释）。

## 二、机制：1993 年的类设计检查单（重构口径）

那个年代可迁移成"检查单"的核心机制（🔧 完整可编译对照见 [03 章](03-句柄.md) 的句柄示例——它就是
一张行走的检查单）：

1. **有自有资源吗？**有 → 析构必须写；写了析构 → 立刻怀疑拷贝构造/赋值也要写（三法则的事前形态）。
   1993 年的标准做法是干脆**禁止拷贝**：把拷贝构造/赋值声明为 private 且**永不定义**——
   链接期炸弹代替静默浅拷贝。
2. **构造完成时不变式成立吗？**当年的事故高频点是"init() 二段式构造"——构造函数只置零，
   等调用方补 init()，中间对象半死不活。现代解法是"构造即完全"或工厂函数返回 `optional`。
3. **只读操作标 const 了吗？**1992 年 Stroustrup 专门写过 const-correctness 的推广文章（公开文献，
   广为转载），本卷时代这被视为专业度的分水岭。
4. **成员拷贝是位拷贝还是深拷贝？**🔧 实测（01_handle_body，节选）：
   `LegacyHandle b = a;` 若没写深拷贝构造，`b_` 与 `a_` 指向同一 `LegacyBody`（40 字节），
   两行 `delete` 即堆损坏——本目录写作时曾在探针里真实复现过这类崩溃（0xC0000374），
   绝非寓言。

## 二点五、案例讨论：一个 1993 类的尸检报告

综述口径下的"当年典型类"（🔧 示意，问题点逐条标注）：

```cpp
class String {            // 当年自制 string 几乎人人写过——事故密度最高的样本
    char* p_;
public:
    String(int n = 0) { p_ = n ? new char[n] : 0; }   // ① 空指针表示"空"，无不变式锚点
    ~String() { delete[] p_; }                        // ② 写了②却没写③④——三法则裸奔
    char* data() { return p_; }                       // ③ 表示直接外流，const 版缺失
};
// 默认拷贝 = 位拷贝 → ④ 双重释放；默认 operator= → ④' 同上 + 自赋值毁对象
```

尸检结论与修复路径（现代版 15 分钟内可编译）：① → 构造即分配或 `= delete` 默认构造；
②③④ → 全部删除，成员换 `std::unique_ptr<char[]>`/`std::string`，五件套自动正确——
**这正是"最新演进"一节 Rule of Zero 论点的微缩证明**：1993 检查单的每一项，
今天要么被类型吸收（智能指针），要么被关键字吸收（`= delete`）。
当年必须会写①–④才专业；今天必须会**识别**别人代码里的①–④才专业。

## 三、权衡

- **接口宽窄**：每多一个 public 成员，未来的 ABI 与演化空间就窄一分。1993 年没有 `final`、
  没有可见性两重性（`PROTECTED:` 之类测试后门），章内的处方只有一条："拿不准就别放"。
- **友元的度**：运算符重载与非成员工具需要访问表示；friend 声明多了，private 名存实亡。
  后世演化出"公开但仅约定可访问"的替代（顶层函数依赖最小公开接口——MEC++ Item 33 的思路同源）。
- **值语义的税**：深拷贝安全但贵。1993 年的折中就是引用计数句柄（第 03 章）——
  这是全书章与章咬合最紧的一处：类设计的问题，句柄章给出答案，异常章再指出答案的裂缝。

## 四、相邻概念对比

| 维度 | 1993 写法 | 语言后来的回答 |
| --- | --- | --- |
| 禁拷贝 | private 未定义拷贝 | `= delete`（C++11，意图显式、报错在声明点） |
| 转移资源 | 手写 swap 指针 / 干脆禁止 | `= default` 移动构造（C++11） |
| 二段构造 | 构造 + init() | 单一强不变式构造 / 工厂 + `optional` |
| 只读承诺 | 文档 | 成员函数 `const` 重载 + `std::as_const` |
| 半初始化防御 | 断言 | 类不变式测试 + UBsantitizer 时代 |

## 最新演进与工业实践

- **三法则 → 零/五法则**：现代共识"能 `= default` 就 `= default`，能不写就不写"（Rule of Zero）；
  一旦要写析构则五件套一起表态（Rule of Five）。C++ Core Guidelines
  （https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines ）"Classes"一节有专条，
  本笔记不逐字引规则号以免出错；其精神即 1993 检查单的机械化。
- **`= delete`/`= default` 是本章检查单的语言化**：private-未定义技巧 2026 年只剩考古价值；
  现代替代的条款级展开见 [../More_Effective_C++/01-基础技法.md](../More_Effective_C++/01-基础技法.md)
  （Meyers 1996 已在替 1993 的坑打补丁）。
- **智能指针接管资源记账**：自有资源用 `std::unique_ptr` 成员后，五法则全体自动正确
  （🔧 实测对照见 03 章：modern 版 `sizeof` 同为 8 字节，析构打印各归其位，零手写代码）。
- **abseil/GSL 的裁决**：abseil（https://github.com/abseil/abseil-cpp ）的类型
  （`string_view`、`Span`）示范"值语义 + 非拥有"的新一代类设计模板；GSL 的 `not_null`、
  `Guideline Support Library` 把"构造函数不接受空"变成类型。当年"最小接口 + 强不变式"的口号
  在这两处有了工业样板。
- **多作者文集的文献提醒**：SIGS/C++ Report 系出版物为非正式商业刊物，无稳定 DOI；
  引用本卷某段观点到正式场合时，请以中译本 + 原卷版权页互证（⚠️ 本目录未能逐章核到原作者）。

## 常见误区与自查

1. "我没写析构，所以不需要管拷贝"——反过来才成立：写了析构就要过一遍五法则。
2. private 未定义的拷贝在 C++11 后已非最优：`= delete` 报错更早且可被 grep。
3. const 成员函数里 `const_cast` 回改成员——逻辑 const 被当物理 const 用，1993 与今天都是坏味道；
   真要缓存请 `mutable`。
4. 自查：你最近一次写的持有裸资源的类，五件套各自的语义是什么？写不出来说明 1993 的坑你还站着。
