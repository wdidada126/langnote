## 核心概念速览（中英对照）

- **句柄/本体** — handle/body（亦作 body/handle、echo 结构前身）：把类的表示拆成"轻薄句柄 + 堆上本体"两半
- **pimpl** — pointer to implementation：handle/body 的当代定名，句柄章与它的血缘一查即穿
- **编译防火墙** — compilation firewall：客户端只依赖含裸指针的前置声明头，本体改动不触发重编译
- **值语义外包** — value semantics on top of shared/heap state：句柄让 `Stack s2 = s1;` 语法像值、机制随你选（深拷贝/共享/写时复制）
- **写时复制** — copy-on-write (COW)：引用计数句柄的招牌优化——共享到第一次写才拆伙；多线程时代败北（见 MEC++ 考）
- **三法则的爆点** — Rule of Three hotspot：句柄类正是"必须手写全套拷贝语义"的极端情形
- **对象大小解耦** — sizeof decoupling：🔧 实测句柄 8 字节 vs 本体 40 字节——栈上足迹与表示彻底脱钩
- **析构点规则** — destruction-point rule（现代回看）：`unique_ptr` 析构要求本体完整类型——pimpl 的头号新手坑
- **ABI 屏障** — ABI barrier：句柄隔住的不只是编译期，还有二进制兼容（C++API 设计章谱系的源头之一）

## 一、动机：第 02 章欠的两笔账，句柄一次还清

1993 年类设计的两大痛点：**(a)** 深拷贝贵、禁拷贝又太绝，客户端想要"像 int 一样用"的共享对象；
**(b)** 头文件里写死表示成员，改一个私有字段全项目重编译（当年编译时间就是工资）。
handle/body 同时回应两者：类只存一个指向本体的指针；拷贝策略在句柄层自由选择（深拷贝/引用计数/禁拷贝），
表示变化被 `->` 挡在实现文件内。这是 C++ 史上最早被系统讲授的"**用一次间接换两种自由**"的交易。

## 二、机制：拆开的两半各干什么（🔧 实测支撑）

🔧 实测样本 01_handle_body.cpp（g++ 15.2 -std=gnu++23 -O0 -Wall，实录输出）：

```cpp
class LegacyHandle {                       // 1993 形态：裸指针 + 手写全套
    LegacyBody* b_;
public:
    LegacyHandle()  : b_(new LegacyBody) {}
    LegacyHandle(const LegacyHandle& o) : b_(new LegacyBody(*o.b_)) {}
    LegacyHandle& operator=(const LegacyHandle& o) {
        LegacyBody* t = new LegacyBody(*o.b_); delete b_; b_ = t;   // 先建后拆：异常安全写法当年已存在
        return *this;
    }
    ~LegacyHandle(){ delete b_; }
};
```

实测输出与解读：

```text
sizeof(LegacyHandle)=8 sizeof(LegacyBody)=40
sizeof(Modern)=8 sizeof(std::string)=32
modern=modern
end
legacy body dtor
legacy body dtor
```

- **sizeof 账**：句柄恒为一机字（8），本体的 40 字节被搬进堆——栈上数组、成员内嵌都不再受表示摆布；
- **生命周期账**：两个 `LegacyHandle` 在 `main` 末尾（"end" 之后）各自打印一次析构——手写 `delete` 的
  纪律在此闭环；谁漏写，谁泄漏；
- **拷贝策略账**：赋值运算符里"先 new 后 delete"的顺序，是 1993 已出现的自赋值/异常安全雏形。

**现代形态的同一个交易**——`std::unique_ptr<Impl>` 版 pimpl：sizeof 依旧 8，三法则缩成
"析构与移动操作出类外各 `= default` 一行"。但语言埋了一个新坑：

🔧 实测样本 01b（widget.h / widget.cpp / main_bad.cpp 三文件，头文件里 `~Widget() = default;`）：

```text
error: invalid application of 'sizeof' to incomplete type 'Widget::Impl'
note: required from 'constexpr std::unique_ptr<...>::~unique_ptr()'   ← widget.h:7 处
```

析构在类内默认化时，`unique_ptr` 删除器在**包含它的翻译单元**里Instantiate，而那里 `Impl` 不完整——
**pimpl 的析构（及移动赋值）必须出类外定义**。1993 年裸指针版没有这个坑，也没有这个保护：它默许你忘。

## 三、权衡

- **一次间接的运行时税**：每次成员访问多一跳且打断内联；`Stack` 之类小对象感知明显。换来的是编译防火墙
  与 ABI 稳定——1993 与今天的账本一致：**大系统付间接税，买构建与演化的复利**。
- **堆分配税**：句柄构造必有一次 new；现代优化是"句柄本体合并分配"（一次性分配 + placement new），
  这已越出当年工具箱。
- **COW 的甜与毒**：引用计数句柄让拷贝近乎免费，读到才拆写——单线程黄金年代近乎无懈可击；
  线程共享时代计数竞争毁掉一切，且"看起来像值"的隐式拆伙是语义炸弹。`std::string` 标准明令禁 COW
  （MEC++ Item 29 与 C++11 定论，见互链），本章技术树最肥的一根枝就此锯掉。

## 四、相邻概念对比

| 手段 | 隔离编译依赖 | 隔离 ABI | 隐藏表示 | 拷贝策略自由 | 代价 |
| --- | --- | --- | --- | --- | --- |
| 直接成员 | ✗ | ✗ | 仅 private | ✗ | 零 |
| handle/body（1993 裸指针） | ✓ | ✓ | ✓ | ✓ | 手写三法则，漏则 UB |
| unique_ptr pimpl | ✓ | ✓ | ✓ | 移动-only（默认） | 析构出类外；一次堆分配 |
| 抽象基类+工厂 | ✓ | 半（vtable 布局要守） | ✓ | 智能指针管 | 多态税 + 堆 |

## 最新演进与工业实践

- **智能指针接管 handle 语义**：裸 handle 的手写记账退役为 `std::unique_ptr`（拥有）/
  `std::shared_ptr`（共享）两型；cppreference: https://en.cppreference.com/w/cpp/memory/unique_ptr 。
  当年"禁止拷贝靠 private 未定义"的招，今天 `= delete` 或换 `unique_ptr` 成员即自动成立。
- **pimpl 的标准化再讨论**：SG14/相关提案（如 P0841 家族对"用语言设施生成防火墙"的探索）未改变手写现状——
  今天 pimpl 仍是纯纪律型惯用法（⚠️ 具体提案命运未逐一复核，此处仅陈述"语言未接管"这一可核事实）。
- **Google Style / abseil 的裁决**：Google C++ 风格指南（https://google.github.io/styleguide/cppguide.html ）
  在头文件依赖一节事实上站队"能前置声明就别 include"，pimpl 是大仓标配手法之一；
  abseil（https://github.com/abseil/abseil-cpp ）的 `absl::Mutex` 等对外类普遍以 opaque 成员收口。
  句柄章的编译防火墙论点，在百万文件级 monorepo 里被放大成第一等工程约束。
- **两条直系后裔**：API/ABI 谱系 → [../C++API设计/02-不透明指针与Pimpl.md](../C++API设计/02-不透明指针与Pimpl.md)；
  物理设计谱系 → [../大规模C++程序设计/05-编译防火墙：隔离技术.md](../大规模C++程序设计/05-编译防火墙：隔离技术.md)。
  两处都是本章论点的工业化成熟形态，读它们等于读"句柄章的 2019 年修订版"。
- **fmt 对照**：fmt（https://github.com/fmtlib/fmt ）用 `format_context` 一类不透明句柄传递
  格式化状态——handle 思想在"库接口设计"里的当代存活样本。

## 常见误区与自查

1. `unique_ptr` pimpl 把 `~T() = default;` 写在头文件类内——🔧 实测报 `incomplete type`（见上）；
   移动赋值同理要出类外。这是 pimpl 使用率的头号事故。
2. 认为 pimpl 只为"藏代码"——它同时是**构建系统**优化（改实现不重编用户）与 **ABI** 优化
   （加成员不改句柄大小）；在开源发布库上第二条更值钱。
3. 多线程环境仍写引用计数 COW——1993 的甜枝已被语言史锯断，别接回来。
4. 自查：你项目里最近一次"改私有成员导致全量重编译"的痛，值不值得用一个句柄换？
