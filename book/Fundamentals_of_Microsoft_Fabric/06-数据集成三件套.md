## 6.2 Dataflow Gen2：低代码面的 M 引擎

✅ 同页要点：Gen2 与 Power BI 数据流同源不同代——
Gen2 输出可落 Lakehouse/Warehouse 等多种目标，不再绑死数据集。

⚠️ 评审要点：

- M 引擎的谓词下推/增量刷新语义决定"哪些源能快"；
- 跨异构源大 join 不该用它硬扛——那是 04/05 章引擎的活；
- 清洗分层观点与 [../bigdata/12-数据质量与工程实践.md](../bigdata/12-数据质量与工程实践.md) 对位。

## 6.3 Pipelines：ADF 血统的编排器

✅ pipeline-overview（访问 2026-09-27）：
活动目录含 Copy、Notebook、Warehouse job、IfP/ForEach、Lookup、Execute Dataflow 等；
触发支持日程/事件/依赖；SSIS 集成线存在（⚠️ 包部署模型与 IR 依赖为转述）。

设计判据（⚠️ 教学重构）：**Pipeline 管"何时与失败后怎样"，不管理"逐行怎么变"**——
重变换下沉到 Dataflow/Spark/T-SQL，编排器保持薄。

盘上对位：调度通识 [../bigdata/11-调度资源与运维.md](../bigdata/11-调度资源与运维.md)；
编排/流处理理论边界见 [../Streaming_Systems/00-总览与阅读地图.md](../Streaming_Systems/00-总览与阅读地图.md)（该册主讲流理论，调度仅边角——如实标注，勿高估覆盖），更宽书目见 [../数据库系列·总索引.md](../数据库系列·总索引.md)。

## 6.4 Mirroring：从"复制工具"到"源端零改动架构"

✅ mirroring/overview（访问 2026-09-27）：支持 SQL Server/Oracle 等数据库镜像进 Fabric（CDC 持续捕获，落 Delta/仓表，可查询）。
2025→2026 扩张方向（⚠️ 转述，逐源状态以当日页为准）：Azure VM 上的 SQL Server/Oracle 支持、镜像语义增强。

与 03 章 Shortcut 的对照：**Shortcut 是"不搬"，Mirroring 是"自动搬"**——
前者零拷贝受源端可用性约束，后者近实时但吃容量与湖存储。
判据（⚠️）：

- 源可停机维护 → Copy 批量；
- 源要 7×24 且要湖内可加工 → Mirroring；
- 源允许直接挂读 → Shortcut。

消息线提醒：Eventstream 也常被归入"集成"，但它属于实时分析面（07 章），分界看**目标是不是 KQL 事件域**。

## 6.5 Copy 与 Shortcut 的成本直觉：🔧 EXP-1 复用（非 Fabric 行为）

03 章 EXP-1 的"复制=线性成本、指针=常数成本"量纲同样适用于 Copy vs Shortcut 决策：
100 万行复制 14.9 ms、指针 1.2 ms（DuckDB 1.5.5，2026-09-27）。
把它乘上真实行数与刷新频率，就是月度容量账单的形状。
⚠️ Fabric 侧 CU 消耗构成不同，不可本机等价——只借量纲、不借数字。

## 6.7 三源示例：一个需求单怎么写（⚠️ 案例重构）

需求："CRM 表 + 文件网关 CSV + SAP 日志，T+1 供报表。"

- CRM（可停机）：Pipeline Copy 夜间批 → Lakehouse bronze；
- 文件网关（小、分析师要改口径）：Dataflow Gen2，让分析师自维护 M 步骤；
- SAP 日志（量大、只读）：Shortcut 外挂原文件湖，gold 层才物化。

一份方案三种工具，接缝全部记入 10 章评审清单第 1 条。

## 核心概念速览（中英对照）

- **Dataflow Gen2** — Dataflow Gen2：Power Query/M 引擎的 Fabric 化托管形态。
- **管道** — Pipeline：活动编排容器（控制流+Copy Job+触发器）。
- **副本作业** — Copy Job：Pipeline 内的异构存储间搬运活动。
- **数据库镜像** — Database Mirroring：源库 CDC 持续复制入湖/仓。
- **变更数据捕获** — CDC（Change Data Capture）：以事务日志读增量、源零改动。
- **增量刷新** — Incremental refresh：Dataflow/模型侧只处理变化的机制族。
- **SSIS 集成** — SSIS integration：既有包在 Fabric 托管 IR 上运行的兼容层（⚠️）。
- **薄编排厚计算** — Thin orchestration：编排器只管时序失败，重活下沉引擎。
- **数据移动** — Data movement：把源数据物理搬进 Fabric 的动作族统称。
- **外部共享** — External sharing：跨租户分发 OneLake 数据的受控出口。
- **源端负担** — Source-side load：CDC 类方案在源系统账上留下的日志/查询成本（⚠️ 本目录术语）。
- **换轨窗口** — Cutover window：ADF/Synapse 资产切入 Fabric 集成的平行运行期（⚠️ 教学用语）。
