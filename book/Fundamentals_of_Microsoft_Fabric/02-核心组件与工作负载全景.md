## 2.2 item 词汇表：平台的最小可部署单位

⚠️ 转述 + ✅ 页面证据：Fabric 一切资源皆 item。按文档目录可枚举的常见类型：

- 数据类：Lakehouse、Warehouse、KQL Database、Mirrored Database；
- 计算类：Notebook、Spark Job Definition、Pipeline、Dataflow Gen2、ML Experiment/Model、dbt Project；
- 消费类：Semantic Model、Report、Dashboard、Paginated Report；
- 目录/治理类：OneLake Catalog 条目、数据应用（data app）。

**关键设计**：item 有"湖仓系"（数据+计算耦合于 OneLake 路径）与"纯计算/纯呈现"两类，
前者才产生湖存储账单（⚠️ 计费与 item 类型的映射未逐条实证，登记缺口）。

## 2.4 概念澄清三连（评审现场高频误解，⚠️ 教学重构）

1. **Lakehouse ≠ Warehouse**：前者是"目录+表格式+Spark"（写优化在文件层），后者是"完整 T-SQL 事务引擎+列存索引"
   （✅ 官方给专页 https://learn.microsoft.com/en-us/fabric/fundamentals/decision-guide-lakehouse-warehouse ，05 章展开）。
2. **OneLake ≠ 一个巨大 Blob 桶**：是带层级命名空间、目录、权限、Shortcut 的**逻辑统一层**，物理按租户/区域分布（✅ onelake-overview；03 章）。
3. **Dataflow Gen2 ≠ Pipeline**：前者是 Power Query 数据变换引擎（低代码 ETL），后者是活动编排器（含 Copy Job）
   （✅ 两页分属 https://learn.microsoft.com/en-us/fabric/data-factory/dataflows-gen2-overview 与 /fabric/data-factory/pipeline-overview ，2026-09-27）。

## 2.7 端到端演练：一个假想需求走三圈（⚠️ 案例重构）

需求："每月 2 TB SAP 导出 + 50 张运营表，供财务自助与月结审计。"

- 第一圈（保守派）：Mirroring 进 Lakehouse + T-SQL 视图 + Direct Lake 报表；
- 第二圈（仓派）：Pipeline 落地 Warehouse + 存储过程月结逻辑 + 同报表面；
- 第三圈（开放派）：S3 原样 Shortcut 挂载 + 外部 Spark 加工 + 只把 gold 层搬进 Fabric。

三圈各对应 06/05/03 章判据；**没有标准答案，只有被记录下来的取舍**——这就是"设计端到端方案"的动词含义。

## 2.8 全景自测题（⚠️ 教学构造）

给三个需求：(a) SAP 数据落地供财务自助；(b) 传感器秒级看板；(c) 为 ML 特征库做回溯。
参考答案：(a) Mirroring/数据集成 + Lakehouse + Direct Lake；(b) Eventstream → KQL DB → 实时看板；(c) Lakehouse + Spark + 时间旅行（04 章）。
**能用一池容量三件全接，就是"全家桶"的卖点；任何一件需要跨云，就是开放格式派的主场**——这个二分法请贯穿 03–08 章使用。

## 2.9 复习卡：三条线画完这张图（⚠️ 教学构造）

合上书，按这三条线自画全景，画不出的部分回查对应小节：

1. **纵线（数据流）**：源 → 集（6.1 三件套）→ 存（OneLake）→ 算（湖/仓双引擎）→ 流（KQL）→ 析（语义层）——2.1/2.5；
2. **横线（治理流）**：租户开关 → 容量 → 工作区角色 → item/路径 ACL——2.4 之误解表第 1 条；
3. **币线（成本流）**：一切计算同池 CU、一切表同湖存储——2.6 与三巨头的分计价差异。

三线交点即 05 章决策指南、09 章三层塔、10 章评审清单的立足处。

## 核心概念速览（中英对照）

- **工作负载** — Workload：Fabric 按人群切分的六大产品面（DE/DW/DS/RTI/PBI/ADF）。
- **item** — Item：可部署最小单位，权限与计量的挂靠对象。
- **数据工程枢纽** — Data Engineering hub：Lakehouse/Notebook 文档域入口。
- **dbt 作业** — dbt job on Fabric：以 dbt 项目驱动的 Fabric 计算项（✅ 文档页存在）。
- **接缝设计** — Seam design：端到端方案中工作负载之间交接点的选型。
- **多引擎单湖** — One lake, many engines：同份文件被 Spark/T-SQL/REST 三 API 读取。
- **低代码 ETL** — Dataflow Gen2：Power Query M 引擎的托管化形态。
- **编排器** — Orchestrator (Pipeline)：活动/依赖/控制流容器，含 Copy Job。
- **持续复制** — Mirroring：源库 CDC 式近实时入湖，不改源。
- **外部分享** — External Data Sharing：跨租户暴露 OneLake 数据的受控通道。
- **数据应用** — Data app：寄宿 Fabric 的非报表应用形态（⚠️ 名录转述）。
