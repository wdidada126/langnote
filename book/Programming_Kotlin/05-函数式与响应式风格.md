## 核心概念速览（中英对照）

- **引用透明** — referential transparency：同输入同输出、无副作用；函数式段的动机叙事根，
  与 01 章"不可变优先"同轴。
- **函数类型与函数组合** — function type / composition：`(A) -> B` 是一等公民；`andThen`/`compose`
  组合子 **stdlib 不自带** ⚠️（2018 语境用 Arrow 等第三方，生态事实非书中逐字）。
- **尾递归优化** — `tailrec`：编译器把自尾调用摊成循环，栈安全由注解**核验**而非祈祷 ✅。
- **惰性三形态** — laziness：`by lazy {}`（单次memoize 求值）、`Sequence`（拉取式管道，02 章）、
  `?: run {}`/`getOrPut`（表达式位延迟）。机制各异，别混称。
- **记忆化** — memoization：stdlib 无 `memoize`，惯用 lazy + Map 手搓 ⚠️ 凭记忆不写死。
- **响应式（2018 义）** — reactive streams (2018 sense)：观察者/回调/背压概念地图 + Future 组合子，
  **只当历史语境读**（00 裁决）；现代对应物一律回协程/Flow（见 [06 章](06-并发与异步-2018时效降权.md)）。

## 机制：写给老手写 Java/C++ 的人

1. **Kotlin 函数式="JVM 务实派"而非"纯语系"**：没有类型类、没有强制 IO 类型（`Arrow` 之前），
   没有自动柯里化（`(a)(b)` 需手写 `(A) -> (B) -> C`，对照 Scala 多参数列表）。Venkat 叙事切近
   Scala 风格 ⚠️ 评价性，落到 stdlib 只有 map/filter/fold 家族 + 函数类型 + `inline`。与 02 章
   合并读：**机制段（inline/Sequence）不过时，风格段（响应式）过时**。
2. **`tailrec` 的"核验"语义**：标了 `tailrec` 但不在尾位 → **编译错** ✅——优化失败不静默降级，
   契约强于 C++ 约定式；对照 Java 至今无 TCO，同算法只能手写 while。
3. **`lazy` 是属性委托不是通用 thunk**：`val x by lazy { ... }` 线程安全默认
   `SYNCHRONIZED` 模式 ✅（可传 `LazyThreadSafetyMode` 三档）；C++ 对照 `static` 局部量
   初始化（Magic Statics）同味，但 Kotlin 把它做成了可组合到任意 `val` 上的库原语。
4. **响应式概念地图（2018 读法）**：书中观察者→回调→Future→背压的演进叙事作为**问题史**照读；
   解法一律替换：`CompletableFuture.thenApply` 链 → 协程顺序代码；RxJava `Observable` → `Flow`；
   背压 `Publisher/Subscriber` 协议 → `Flow` 的挂起即天然背压 ⚠️（后句是官方叙事概括，非书中原文）。
5. **DSL 与函数式段的接缝**：带接收者 lambda（04 章）+ 高德夫内联 = 类型安全 builder；
   `html { body { ... } }` 的观感来自函数组合风格而非新语法——本书最强段 ⚠️ 的机制根在本章可摸到。

## 易错点

- **`tailrec` 只认自尾调用**：互递归（f 调 g、g 调 f）不优化且不报错⚠️（会编译通过但栈照常
  溢出🔧 待实测确认），把互递归硬改单函数尾式是常见练习。
- **`by lazy` 的异常不缓存**：初始化块抛异常时 `lazy` **不**记忆失败，下次访问重跑🔧 预期行为
  待实测；依赖"失败只发生一次"的假设会翻车。
- **函数引用 `::f` 与 lambda `{ f(it) }` 不等价**：前者不新建捕获层、且对重载解析更严格 ✅；
  性能叙事里两者可互换是迷思🔧，`inline` 参数处传 `::f` 还可能失去内联🔧 具体规则待实测。
- **响应式段用 2018 API 抄进现代项目**：`CompletableFuture` 阻塞式 `join` 混在 `suspend` 语境
  = 线程钉死（见 06 章账本）；`Observable` 忘 dispose 的泄漏换成协程时代"取消要协作"，心智可迁移代码不可。

## 🔧 微实验（未实测，kotlinc 可用后逐条回填）

1. **tailrec 栈存亡对照**：`tailrec fun count(n: Int): Int = if (n == 0) 0 else count(n - 1)`
   以 `count(1_000_000)` 跑通；去掉 `tailrec` 改非尾式（`1 + f(n-1)`）预期 `StackOverflowError`。
2. **lazy 三模式**：`by lazy { }` 默认、`lazy(LazyThreadSafetyMode.NONE) { }`、
   `lazy(VALIDATION)` 多线程重复求值探针（打线程名计数）。🔧 预期与官方 KDoc 一致。
3. **手搓 memoize**：`fun <A, B> ((A) -> B).cached(): (A) -> B { val m = mutableMapOf<A, B>(); return { a -> m.getOrPut(a) { invoke(a) } } }`
   以斐波那契计时对比裸递归——验证"stdlib 无 memoize、getOrPut 可顶"。
4. **2018 响应式化石对照**：Java 8 `CompletableFuture.supplyAsync().thenApply()` 链 vs 同逻辑
   `runBlocking { withContext(Dispatchers.IO) { ... } }`（需协程库待环境）——仅作 API 形态记录，语义裁判在 06 章。
