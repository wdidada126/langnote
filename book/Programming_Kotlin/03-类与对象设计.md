## 核心概念速览（中英对照）

- **主构造器即签名** — primary constructor：`class User(val id: Long, var name: String)`，
  参数声明与属性声明合一，对照 Java 三段式（字段+构造参数+逐行赋值）。
- **init 块与属性初始化次序**：`init` 与属性初始化器按文本顺序交织执行——构造逻辑的"单一时间轴"。
- **数据类** — data class：编译器为构造器参数生成 `equals/hashCode/toString/copy/componentN`；
  是"值语义记录"，不是"DTO 万能胶"。
- **单例三种形态**：`object`（饿汉单例）、`companion object`（类内静态位，可实现接口）、
  `object : Expr {}` 表达式（匿名类替代，闭包捕获而非 this 捕获 ✅）。
- **密封类** — sealed class：编译期封闭的和类型（sum type），`when` 穷尽检查的载体；函数式 ADT 的 JVM 表达。
- **类委托** — class delegation：`class Repo(private val impl: Dao) : Dao by impl`，
  GoF 装饰/适配器的样板消除。

## 机制：写给老手写 Java/C++ 的人

1. **属性的"样板"是编译器的工作不是你的**。Java 一个不可变值对象手写 40 行（字段+构造+get+
   equals+hashCode+toString）；C++ 靠 `struct` + 默认成员 + 手写 `operator==` 或引入 boost::ut。
   Kotlin `data class` 一行收编前五项——但注意**只收编构造器参数**：body 里声明的属性
   不进 `equals/toString/copy` ✅，这条边界是绝大多数"数据类 equals 不认新字段"事故的根。
2. **`copy` 是浅拷贝**：与 C++ 默认拷贝构造同义——成员是引用则共享。嵌套修改要
   `u.copy(address = u.address.copy(...))` 手工穿层，对照 C++ 里靠值嵌套自动深拷的差别。
3. **sealed 的和类型闭环**：`sealed class Expr { data class Num(val v: Double) : Expr(); ... }` +
   `when (e) { is Num -> ..., is Add -> ... }` 无 `else` 也能编译 ✅（分支穷尽由编译器核验）。
   这正是 Venkat 函数式叙事（本书"模式"段 ⚠️ 推定）在 JVM 上的落点：
   C++ 用 `std::variant + std::visit` 做同一件事，Java 21 的 sealed+record+pattern matching 是
   迟到多年的同构复刻。2018 语境记住一条限制：sealed 子类当年必须**同文件**（1.1 起同包同编译单元，
   1.5 放宽到同包不同文件 ⚠️ 演变依据官方发布记录，登记即可）。
4. **object 与 Java 单例写法**：Effective Java 的枚举单例/holder  idiom 全部被 `object` 一句话取代，
   线程安全由类初始化语义保证 ✅（JVM 规范层面，与 Java `static final INSTANCE` 同级）。
   给 Java 调用方暴露静态入口需 `@JvmStatic`——互操作税，见易错点。
5. **委托是"组合优先"的语言化**：`by impl` 生成的转发方法与 C++ 手写 `impl->call()` 样板等价，
   但与 GoF 装饰器的本质差别是**默认全转发、按需覆写**——装饰一半写一半是最危险的用法（漏转发
   静默绕过装饰层）。
6. **伴生对象不是 static**：`companion object` 是真实单例对象，可实现接口、可命名、可被反射看到
   （`Companion` 类存在）；对照 Java `static` 成员"无对象宿主"。跨语言洁癖者才写 `@JvmStatic`。

## 易错点

- **data class 里的数组属性**：生成的 `equals/hashCode` 对 `Array<T>` 走引用语义 ✅——
  `data class Row(val cells: Array<Int>)` 两个内容相同的 Row 不相等。解法：用 `List<Int>`，
  或手写 equals 走 `contentEquals` 并在类注释立此存照。
- **data class 塞 var 属性**：`copy` + `var` 组合出来的"可变态记录"破坏 `hashCode` 稳定性
  （进 HashSet 后改字段即失联）。判据：data class 参数一律 `val`，要可变的就不是值语义。
- **init 与属性初始化顺序**：`init { println(name) }` 排在 `val name = ...` 之前时打印的是
  尚未赋值的属性——编译可能直接报" Property 'name' must be initialized"🔧 具体诊断形态待实测。
  规则只有一条：**按文本顺序执行**。
- **sealed 与 abstract 混淆**：sealed 不是"更严的 abstract"，它的价值全在穷尽检查；
  加了 `else -> Unit` 等于自废武功（IDE 不再提示漏分支）。
- **匿名 object 表达式的捕获语义**：Kotlin 的 `object : Listener { ... }` 里 `this` 指 object
  本身还是外层类，取决于书写形态（对照 Java 匿名内部类的 `Outer.this` 显式限定了历史）——
  需要外层引用写 `this@OuterClass`。
- **委托生命周期陷阱**：`val dao: Dao by lazy { ... }` 是**属性委托**（lazy 是 stdlib 函数），
  与**类委托** `: Dao by impl` 的 `by` 是同一关键字的两种语法——读到 `by` 先看它在继承列表里还是属性后。

## 🔧 微实验（未实测）

1. **data class 生成物合同**：
   ```kotlin
   // 🔧
   data class P(val x: Int, var y: Int)
   val a = P(1, 2); val b = a.copy(y = 9)
   check(a == P(1, 2))                 // equals 按构造参数
   check(a != b)
   val (x, c) = a                      // component1/component2 解构
   check(x == 1 && c == 2)
   val m = mapOf(a to "k")             // toString 输出 "P(x=1, y=2)" 形态
   ```
2. **sealed 穷尽性的正反例**：
   ```kotlin
   // 🔧
   sealed class Ev { object Click : Ev(); data class Key(val c: Char) : Ev() }
   fun desc(e: Ev) = when (e) { is Ev.Click -> "click"; /* 漏 Key */ }
   // 预期：编译错（非表达式 when 缺 else 且不穷尽）；补上 is Ev.Key 分支后通过
   ```
3. **类委托漏转发的行为验证**：`class LoudDao(private val d: Dao) : Dao by d` 只覆写 `save`，
   测试 `query` 是否绕过装饰器（预期：绕过——这正是"默认全转发"双刃剑的另一面）。
4. **@JvmStatic 互操作对照**：同一段 Kotlin `companion object { fun make() }`，
   Java 侧分别以 `P.Companion.make()` 与加注解后的 `P.make()` 调用，编译对照输出差异。

## 中英对照表

| 英文 | 中文 | 一句注 |
| --- | --- | --- |
| primary constructor | 主构造器 | 参数即属性，签名即文档 |
| init block | 初始化块 | 与属性初始化按文本序交织 |
| data class | 数据类 | 值语义记录；仅构造参数入合同 |
| copy (shallow) | 浅拷贝复制 | 嵌套 var+copy 是危险组合 |
| destructuring | 解构 | componentN 的消费端 |
| sealed class | 密封类 | 编译期封闭和类型 |
| exhaustiveness | 穷尽性 | when 免 else 的凭证 |
| object declaration | 对象声明 | 饿汉单例语言化 |
| companion object | 伴生对象 | 真对象，非 static |
| class delegation | 类委托 | `by` 消除 GoF 样板 |
| property delegation | 属性委托 | 同名 `by` 的第二语法 |
| value class (ex-inline) | 值类 | 2018 叫 inline class，实验期 |
