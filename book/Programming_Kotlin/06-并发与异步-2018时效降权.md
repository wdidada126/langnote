## 二、逐条取代账本（书中 2018 解法 → 现代对应物）

| 书中/2018 语境解法 ⚠️ | 当时理由 | 现状裁决 |
|---|---|---|
| `Thread(Runnable {}).start()` / SAM 转换建线程 | 语言无并发原语 | **已被协程时代取代 ⚠️**：`launch/async` + Dispatcher；裸线程=管理灾难 |
| `ExecutorService` + `Future.get()` | 线程池复用 | **已被协程时代取代 ⚠️**：`withContext`/`await`；`get()` 阻塞钉线程，且取消语义残缺 |
| `CompletableFuture.thenApply/thenCompose` 链 | 回调组合子 | **已被协程时代取代 ⚠️**：顺序代码+挂起函数天然扁平；组合子链=没有 async/await 时代的补丁 |
| 回调/监听器风格异步（含 RxJava `Observable`） | 事件源多 | **已被协程时代取代 ⚠️**：单向流→`Flow`，请求-响应→`suspend`；05 章响应式概念地图的解法列在此收口 |
| `Atomic*`/`synchronized` 全武行做协调 | 共享可变+锁 | **半取代**：协调层换 channel/`Mutex`/结构化作用域；JMM 层（volatile/原子）**仍是底层事实** ✅ 不废 |
| "协程=green thread 预立项"式展望 | — | 兑现且超出：Kotlin 协程≠虚拟线程；JVM 虚拟线程（Loom, Java 21）是**平行的另一条线** ⚠️ 书后演进，登记不展开 |

## 三、跨语言对照：suspend ↔ await（JS Promise 一系）

- 语法同构：`suspend fun` 挂起点 ≈ JS `await`；`Deferred<T>` ≈ `Promise<T>`；`Deferred.await()` ≈ `await p`。
- 机制分道：**JS Promise 是单事件循环上的回调排队**（无真并发，CPU 段仍独占 tick）；
  **Kotlin 协程挂起不占线程、可跨多线程 Dispatcher 恢复** ✅。
- 失败路径：Promise `reject` 不捕获即静默（unhandledrejection）；协程未处理异常沿
  Job 结构**向上传播取消父作用域** ✅（结构化并发语义）——两种"忘记处理异步错误"的代价形态。
- 链接锚：对照位挂靠 [../TypeScript系列·Runtime_vs_Type_System专题.md](../TypeScript系列·Runtime_vs_Type_System专题.md)
  （📌 磁盘实测该档现存主题是类型擦除，**尚无 Promise/await 节**——本对照系本档自补，
  已在"欠账"登记请 TS 专题侧收编或改立锚）。协程现代裁判一律回

## 四、易错点（2018 代码搬进现代项目的爆点）

- **`Future.get()` 写进 `suspend` 上下文**：阻塞的是协程所在线程，池小即全局停摆——
  正确姿势 `runInterruptible(Dispatchers.IO) { f.get() }` 或干脆桥 `await()` ⚠️ API 名凭记忆🔧。
- **`runBlocking` 进库代码**：它是**main/测试/桥接**专用胶水 ✅，库函数里等同把调用方线程焊死。
- **`GlobalScope.launch` 当万能替代 new Thread**：无结构化作用域=泄漏与错误吞噬的老病复发，
  协程版"fire and forget"比线程版更隐蔽 ✅ 官方明诫。
- **取消不是中断**：`Job.cancel()` 靠挂起点协作；纯 CPU 循环不检查 `isActive`/不挂起则**永不响应取消** ✅
  ——对照 `Thread.interrupt()` 的抢占式直觉，迁移者最容易在这里"取消无效"。
- **ThreadLocal 语义在协程下漏**：挂起-恢复可换线程，ThreadLocal 值随线程不随协程——
  MDC/安全上下文类设施要换 `CoroutineContext` 元素携带 ✅。

## 五、🔧 微实验（未实测；需 kotlinc + kotlinx-coroutines 双前置）

1. **钉线程演示**：单线程池上 `Future.get()` 链式两任务 → 死锁现场；同逻辑 `async/await` 版通过。
2. **挂起不占线程**：`newSingleThreadContext("one")` 上 `delay(1000)` 期间另一协程能否复用该线程
   ✅ 预期能（打印线程名验证）。
3. **协作式取消反例**：`while (!isActive) spinCpu()` 的 `launch` 取消不掉，加 `yield()` 后可掉。
4. **JS 对照沙盒**：node 下 `await` 卡 CPU 段阻塞 timer 的最小脚本 vs JVM 实验 2——
   把"单事件循环 vs 多线程 Dispatcher"差异做成可见输出（脚本可先于 kotlinc 环境跑🔧 未跑）。
