# 02 · 集合与函数式操作

> 主题切分（对应 [00 总览](00-总览与阅读地图.md) 骨架表"集合与函数式：高阶函数、惰性"段，
> 不冒充原书章名）；🔧 代码凭记忆重敲、本环境无 kotlinc，未实测。
> 2018 时效注：本节 API（map/filter/sequence/groupBy 等）自 Kotlin 1.0 起高度稳定，
> 是全书**最不过时**的段落之一 ✅（判断依据为官方 API 演进记录，非书中内容逐字）。

## 核心概念速览（中英对照）

- **只读/可变双接口** — read-only vs mutable interfaces：`List`/`MutableList`、`Set`/`MutableSet`、
  `Map`/`MutableMap`；只读≠不可变（immutable），只是"此视图不给写方法"。
- **高阶函数** — higher-order function：以函数为参数/返回值；stdlib 集合操作的骨架（`filter`、`map`、`fold`）。
- **inline 函数** — `inline fun`：stdlib 的高阶函数几乎全 `inline`，lambda 不建对象、无 `Function` 包装开销——
  这是 Kotlin 与 Java Stream 性能叙事的第一分歧 ✅。
- **惰性求值** — laziness via `Sequence`：`asSequence()` 把逐元素管道化，对照 Java Stream 但机制不同
  （Kotlin 是拉取式单元素推进；集合版操作是逐操作全量物化）。
- **reified 类型实参**：`inline fun` 的类型参数可具化，`filterIsInstance<T>` 一类在集合章首次露脸（详见 04 章）。

## 机制：写给老手写 Java/C++ 的人

1. **"只读"是编译期承诺，不是运行期冻结。** Java 有 `Collections.unmodifiableList`（包装视图，
   底层改了就穿帮）与 `List.of`（真不可变）两件套；Kotlin 的 `List<T>` 默认拿到的可能就是
   `ArrayList`——✅ 官方明确警告：把 `MutableList` 强转回去照样能写。所以"防御性只读导出"
   靠的是接口隔离与纪律，不是内存保护。C++ 的 `const std::vector<T>&` 是同一层次的约定：
   const 只挡编译器，挡不住 `const_cast`。
2. **管道风格对照**：`list.filter { it.age >= 18 }.map { it.name }.sorted()` 与 Java
   `stream().filter().map().sorted()` 形状相同，差异全在机制：
   - Kotlin 集合版每步**新建中间集合**（O(n) 空间 × 步数）；Java Stream 天然惰性。
   - Kotlin `asSequence()` 版才是惰性单元素推进，且 lambda 内联后**无 Stream 管道搭建开销**。
   - C++ 老手视角：集合版≈多次 `std::copy_if` 建中间 vector；sequence 版≈range-v3 的
     view 组合（D4 Ranges 之前的手写感）。
3. **reduce/fold 的分工**：`fold(initial) { acc, x -> }` 有初值、结果类型可与元素类型不同；
   `reduce` 无初值、空集合抛异常。Java 的 `reduce` 对应 fold 家族，命名陷阱在 Kotlin 里反转。
4. **分组与聚合形态学**：`groupBy { key }` → `Map<K, List<V>>`；`associate { it.id to it }` →
   `Map<K, V>`；`groupingBy { it }.eachCount()` 惰性计数（对照 Java `Collectors.groupingBy`
   的 reduce 组合子复杂度，Kotlin 一行）。`to` 是中缀构造 `Pair` 的糖——DSL 感的最小样本，
   为 05 章埋伏笔。
5. **运算符家族**：`list1 + list2`（新建并集列表）、`map + entry`（新建并集映射）、
   `list - element`（新建减去）——全部**返回新集合**、不改原集合 ✅，与 C++ 的
   `insert/erase` 原地修改、与 Java 无运算符重载的历史形成双对照。

## 易错点

- **`readOnly()`/`readOnlyView` 幻觉**：`val view = mutable.asReadable()`（stdlib 实验家族）或
  手工 `Collections.unmodifiableList` 都挡不住 `(view as MutableList).clear()`。要真不可变，
  2018 年代用 `list.of` 不存在、Kotlin 也无 `List.of`——惯用 `toList()` 复制 + 纪律 ⚠️
  （Kotlin 1.9 起才有稳定的只读标准不可变集合实现细节，属书后演进，登记不展开）。
- **sequence 上的副作用顺序**：`asSequence().map { println(...) }.first()` 只处理到满足为止——
  中间操作**不是**"整批执行"，与 Java Stream 同直觉但和 Kotlin 集合版（全量）相反；两种风格
  混用团队最常见的 bug 是"以为 map 已全部执行"。
- **`groupBy` vs `associate` 混淆**：后者键重复会**后者覆盖前者**，静默丢数据；需要
  "重复键都保留"的是 `groupBy`，需要"重复键报错"的用 `associate` 之后自查 size。
- **`sortedBy { it.key }` 与 `sortedByDescending`**：Kotlin 用 selector 免写 `Comparator`，
  对照 Java `Comparator.comparing`——但 selector 版**不能链式 thenComparing**，多键排序要
  `sortedWith(compareBy({ it.a }, { it.b }))`，新手常卡在"第二个键往哪儿挂"。
- **对 `Map` 迭代解构**：`for ((k, v) in map)` 靠 `component1/component2`（Pair 系），
  写 `for (e in map)` 得到的是 `Map.Entry` 视角的 `Pair` 拷贝 ✅——性能敏感处用
  `for ((k, v) in map.entries)` 与 iterator 的语义差异🔧 需实测确认。

## 🔧 微实验（未实测）

1. **中间集合成本可见化**：
   ```kotlin
   // 🔧 凭记忆，未编译
   val big = (1..1_000_000).toList()
   val eager = big.filter { it % 3 == 0 }.map { it * 2 }        // 分配两个百万级中间 List
   val lazy1 = big.asSequence().filter { it % 3 == 0 }.map { it * 2 }.take(10).toList()
   // 预期：lazy1 只处理前 30 个左右元素；计时 + -verbose:gc 观察分配差
   ```
2. **只读视图的"逃逸"**：
   ```kotlin
   // 🔧
   val src = mutableListOf(1, 2, 3)
   val ro: List<Int> = src                    // 接口层只读
   (ro as MutableList<Int>).add(4)            // 强转逃逸——预期编译通过、运行成功
   check(src == listOf(1, 2, 3, 4))           // 证明"只读非冻结"
   ```
3. **reduce 空集炸点**：`emptyList<Int>().reduce { a, b -> a + b }` 预期抛
   `UnsupportedOperationException`/`NoSuchElementException` ⚠️ 异常类名待实测订正；
   同款需求用 `fold(0)` 安全。
4. **groupingBy 惰性计数**：`(1..100).groupingBy { it % 7 }.eachCount()` 与
   `groupBy` 版对比 GC 行为（实验 1 同法）。

## 中英对照表

| 英文 | 中文 | 一句注 |
| --- | --- | --- |
| read-only interface | 只读接口 | `List` 无写方法 ≠ 对象冻结 |
| higher-order function | 高阶函数 | 集合操作的骨架 |
| inline function | 内联函数 | lambda 零对象开销的机制根 |
| sequence | 序列 | 拉取式惰性管道 |
| intermediate operation | 中间操作 | map/filter 类，惰性版不即时执行 |
| terminal operation | 末端操作 | toList/first/count 类，触发推进 |
| fold / reduce | 左折叠 / 归约 | 有无初值、空集行为不同 |
| groupBy / associate | 分组 / 关联 | 重复键保留 vs 覆盖 |
| destructuring declaration | 解构声明 | `for ((k, v) in …)` 的来源 |
| spread operator | 展开运算符 | `listOf(*arr)`，对照 C++ initializer 转发 |
