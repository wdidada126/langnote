# 04 · 对象表达式与作用域函数

## 核心概念速览（中英对照）

- **对象表达式** — object expression：`object : Listener { ... }`，JVM 匿名类的 Kotlin 形态，
  无"effectively final"捕获限制（对照 Java，见机制 1）。
- **this 限定别名** — labeled this：嵌套 `object :` / 作用域函数里用 `this@Outer`、`this@run`
  指名要哪一层的接收者（object/companion 单例形态见 03 章）。
- **作用域函数五件套** — scope functions：`let`/`run`/`with`/`apply`/`also`（+`takeIf`/`takeAlso`
  两枚过滤器）。选型只有两个正交维度：**上下文是 `this`（接收者）还是 `it`**、**返回接收者还是 lambda 结果**。

## 机制：写给老手写 Java/C++ 的人

1. **捕获语义是本章最容易被 Java 直觉带偏的一处**。Java 匿名内部类只能捕获 effectively final
   局部变量；Kotlin 的 object 表达式与 lambda 统一按"变量引用"捕获——`var` 装箱成 `ObjectRef`
   随闭包携带，后续修改**可见** ✅。C++ 对照：近似 `[&]` 引用捕获，但装箱后由 GC 兜底，无悬垂引用事故。
2. **五件套选型矩阵**（✅ 官方文档给的就是这张表）：
   | 函数 | 隐式参数 | 返回 | 惯用场景 |
   |---|---|---|---|
   | `let` | `it` | lambda 结果 | 空安全转换 `x?.let { ... }`、限缩作用域 |
   | `run` | `this` | lambda 结果 | 对象上跑一段计算 |
   | `with` | `this` | lambda 结果 | 对同一接收者连写一串调用（非扩展，可空安全需先判） |
   | `apply` | `this` | **接收者** | 构造后配置（builder 风）——05/DSL 段的地基 |
   | `also` | `it` | **接收者** | 附带副作用（日志/校验）不改链路 |
3. **作用域函数是 DSL 的最小机制核**：类型安全 builder DSL（本书最强段 ⚠️ 评价性、见 00）=
   `apply`/带接收者 lambda + 带接收者函数类型；`StringBuilder().apply { ... }` 与 `buildString { ... }` 是同构的两级抽象。
4. **函数内 object 与匿名类实例数**：顶层/对象内的 `object` 是单例；**函数体内**的 object
   表达式每次调用**新建实例** ✅——"要捕获状态又不想建类"的窗口，亦是 `ReturningFunctions`
   惯用法（方法返回对象表达式替代 visitor 接口族）的载体 ⚠️ 章名凭记忆。
5. **`takeIf` 是类型过滤器不是布尔门**：`x.takeIf { it > 0 }` 返回 `T?`——把"判断"折进"值"，
   与 elvis 串联 `x.takeIf { p } ?: fallback` 是表达式导向（01 章）的收尾样品。

## 易错点

- **`with` 不吃空安全**：`x?.let { ... }` 合法，`with(x)` 对 `x: T?` 直接编译错（需 `x?.let { with(it) {...} }`
  或先强转）——`with` 是普通函数不是扩展 ✅，新手链式改写到此处必卡。
- **`apply` 里混用 `it`**：`apply` 上下文是 `this` 没有 `it`；写出来编译错或在**外层**作用域静默
  指错对象。嵌套两层 `apply`/`also` 时 `it`/`this` 各有两层，不贴 `this@run` 式别名就是雷。
- **作用域函数套娃**：`x.let { it.apply { ... }?.also { ... } }` 语法全对、可读性归零。
  判据（社区共识 ⚠️ 非官方）：同一层里超过一个作用域函数就该拆命名局部量。
- **把 `also` 当 `apply` 用**：两者返回语义同为接收者、参数形态相反（`it` vs `this`）——
  apply 里显式写 `it` 才是静默 bug 源🔧 诊断信息待实测订正。
- **object 表达式实现的接口里有状态时**：每调用新建实例（机制 4）使"监听器去重/单例假设"
  全部失效——注册两次拿到两个对象，`===` 不等。

## 🔧 微实验（未实测，kotlinc 可用后逐条回填）

1. **var 捕获装箱验证**：
   ```kotlin
   // 🔧 凭记忆，未编译
   var counter = 0; val inc = { counter++ }   // lambda 与 object 表达式同一捕获机制
   repeat(3) { inc() }; check(counter == 3)   // Java 匿名类此处根本编不过
   ```
   配 `javap -c` 观察 `ObjectRef.int` 字段，证实装箱 ✅ 预期。
2. **五件套返回矩阵断言**：同一接收者分别过 `let/run/with/apply/also`，`check` 返回值
   是否 `===` 接收者、lambda 内 `this`/`it` 可否编译——预期与机制 2 表逐格一致。
3. **嵌套别名与实例数**：`with(sb) { sb.apply { append(this) } }` 打 `identityHashCode` 验证两层
   接收者；`fun listener() = object : Listener { }` 调两次比 `===`，预期 false。
