## 核心机制

### nn.Module：参数注册的容器协议

- 继承 `nn.Module`、`__init__` 里挂子模块（`nn.Linear` 等）、`forward` 里写数据流——参数发现全靠这层容器协议：挂进 module 属性的子模块/Parameter 才被 `.parameters()` 收集、才吃优化器（✅）。对照 Chollet/Keras 的「层即对象、`Sequential` 拼装」（../DeepLearningWithPython2e.md，✅ 在盘）：Keras 走声明式堆叠，PyTorch 走「普通 Python 属性 + 显式 forward」——后者用 dynamic graph 换来控制流自由（✅），代价是忘在 `__init__` 注册就静默无梯度。
- 另一种写法：直接拿 `torch.nn.functional.relu(x)` 函数式调用配自建权重（✅）——官方文档两种口径并存，短书选哪种 ⚠️ 未核；机制上二者完全等价（✅）。

### 训练循环五拍：手写而不可省

- 标准节拍（✅）：前向 `y=model(x)` → `loss=criterion(y,t)` → `optim.zero_grad()` → `loss.backward()` → `optim.step()`。零梯度那拍源于 01 册的累加语义（✅）——忘写不报错、只让 loss 诡异震荡，是新手第一大坑（✅ 机理）。
- 对照 ../深度学习入门.md（✅ 在盘）：那里用纯 NumPy 手推链式法则逐层写反传播；PyTorch 把同套数学交给 autograd，训练循环即「手搓流程的自动微分版」——两书互为显影，读完任一本另一本的机制章都变简单（✅ 定性）。

### 损失与优化器：接口即约定

- `nn.MSELoss`（回归）/`nn.CrossEntropyLoss`（分类，**内含 softmax**，喂 logits 不喂概率，✅ 高频口径）；`optim.SGD(model.parameters(), lr=...)`、`optim.Adam` 自适应步长（✅）。对照 Raschka（../MachineLearningWithPyTorchAndScikitLearn.md，✅ 在盘）的 sklearn→PyTorch 映射表：同一批 ML 概念两框架两写法，Raschka 的对照列可当本档第二意见。
- `CrossEntropyLoss` 期望类别索引标签（long 型）而非 one-hot（✅）——短书若用 one-hot 再手配 softmax ⚠️，属于可容忍的绕路但非现行惯例。

### 验证节拍：训练循环的镜像半环

- 每 epoch 后跑验证集：`model.eval()` + `torch.no_grad()` 包前向、只算 loss 不调 step（✅ 口径；eval/no_grad 细则见 [05 册](05-工程注意与延伸.md)）——短书常把半环省成「test acc 一行 print」⚠️，工程上是数据泄漏与 BN 语义错的高发地。
- epoch/batch 双层循环的外拍负责调度与打点（✅ 惯例）：学习率调度器 `torch.optim.lr_scheduler.*` 按官方文档口径通常置于 `optimizer.step()` 之后推进（✅）。

## 核心概念中英对照

- **模块** — nn.Module：以属性树注册参数的网络构件基类。
- **前向传播** — forward：数据流经模型的显式函数。
- **优化器** — optimizer：按 .grad 更新参数的步长策略对象。
- **交叉熵损失** — CrossEntropyLoss：logits+类别索引口径的分类损失。
- **梯度清零** — zero_grad：五拍循环中对抗累加语义的固定拍。
- **小批量训练** — mini-batch training：分批前向反向的采样式优化。
