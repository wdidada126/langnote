## 2. 两个总指标：响应时间与吞吐

- **响应时间（response time）= 服务时间（service time）+ 队列/等待时间**。单条 SQL 的墙钟时间减去其执行本身，剩下的都是"在等什么"——这是等待接口存在的原因 ⚠️。
- **吞吐（throughput）= 单位时间完成的工作量**，受最强资源约束。调优的悖论：为吞吐做的批量/并行改造（如加大 SGA、开并行）常常恶化单请求响应时间；反之亦然 ⚠️。
- 9i/10g 时代的通说纪律：**先定基线（baseline），再谈改动**。Statspack 快照对（见 `08`）就是当时的"基线留档"手段 ⚠️。

## 3. 调优的层次模型（⚠️ 通说重组）

```
应用设计（SQL 写法/访问路径/连接管理）   ← 改这里最便宜，见 07
  ↑
实例结构（内存/文件/并发参数）          ← 本册重心，见 03/04/05
  ↑
操作系统与硬件（CPU/IO 栈/网络）        ← 见 04
```

- 通说警句（时代共识，非原书引文）：**"70% 的性能问题诞生在 SQL 与应用设计"**——但本书路线坚持把"结构层"先讲清楚，因为不读懂 buffer cache 就无法解释 `db file sequential read` ⚠️。
- 决策顺序：症状采集 → 定位层次 → 该层内找瓶颈资源 → 参数/SQL 双路修 → 复测基线。TOP 2e 把这条路走成了工程化决策树（✅ 实证于 [../Troubleshooting_Oracle_Performance_2e/01-性能问题.md](../Troubleshooting_Oracle_Performance_2e/01-性能问题.md)），本册在 2006 年提供的是它的"原料层"。

## 4. 9i → 10g 的代际背景（理解本册"年轮"）

- **内存管理**：9i 手工分 `db_block_buffers`×`db_block_size`；10g 起 `SGA_TARGET` 自动共享内存管理（ASMM）⚠️——本册 2e 恰好骑在代际线上，通说会同时给两代参数（⚠️ 推定）。
- **统计仓库**：8.1.7 的 Statspack（免费、手工 snap）与 10g 的 AWR（自动、需 Diagnostics Pack 许可）并存 ⚠️；2e 成书时 AWR 尚新，重心仍在 Statspack（⚠️ 推定）。
- **优化器**：CBO 已确立（RBO 遗存于 `optimizer_mode=RULE`），`dbms_stats` 与系统统计（CPU_IO_STATS）刚进 10g ⚠️——深挖见 [../Cost_Based_Oracle_Fundamentals/14-10053跟踪文件.md](../Cost_Based_Oracle_Fundamentals/14-10053跟踪文件.md)。
- **闪回/undo**：9i 自动 undo 管理取代回滚段手工条带；10g 引入 undo 保留与闪回查询 ⚠️（`05` 章主题）。

## 5. "读什么视图"：方法论的仪表盘点法（⚠️ 通说）

10g 时代结构派 DBA 的标准仪表组（视图名以官方 26/19 文档根为现行锚点，✅ URL 见文末两节）：

| 层 | 视图 | 回答的问题 |
|---|---|---|
| 总等待 | `V$SYSTEM_EVENT` | 实例级"时间都花在哪" |
| 会话等待 | `V$SESSION_EVENT` / `V$SESSION_WAIT` | 单会话画像 / 当下在等 |
| 锁冲突 | `V$LOCK` / `V$SESSION`（blocking 列） | 谁堵谁 |
| SQL 画像 | `V$SQL` / `V$SQLAREA` | 按 gets/reads/sorts 抓 TOP SQL |
| 结构水位 | `V$SGA`、`V$DB_CACHE_ADVICE`、`V$LATCH` | 池子够不够、闩睡不睡 |

注意：`V$` 视图族在 23ai/26ai 依旧健在（✅ 文档根可达，见 `02` 文末），但**采集许可与自动化程度**已完全改写方法论（AWR/ASH/ADDM/云化），这是本册"演进节"的共同主线。

## 6. 常见误区（时代通说 ⚠️）

1. **命中率崇拜**：`v$sysstat` 的 buffer cache hit% 99→99.5 毫无意义，等待事件绝对量才可信；10g 起连 advisory 都不再鼓励"唯命中率论" ⚠️（TOP 2e 亦同判，✅ 见 [../Troubleshooting_Oracle_Performance_2e/04-不可复现问题的实时分析.md](../Troubleshooting_Oracle_Performance_2e/04-不可复现问题的实时分析.md)）。
2. **参数玄学**：改 `_underscore` 参数前没有等待证据 = 赌博 ⚠️。
3. **见 SQL 就调**：结构饥饿（共享池太小 → 库缓存闩争用 → 解析排队）会伪装成"SQL 慢"；结构派先查 `03`/`05` 再写 hint ⚠️。
4. **忽略设计债**：泛型表、缺约束、行迁移等物理设计问题，调参数治不了（TOP 2e Ch1 十类反模式 ✅ 同判）。

## 7.1 补充剧本：一次 2006 式调优的完整九步（⚠️ 时代通说重构，非原书流程）

1. **立案**：记录症状（谁、何时、多慢、业务影响）——没有工单式记录的调优=玩参数。
2. **冻结**：确认对比期内无统计重收集/无发布/无数据批灌（三大自然变量 ⚠️）。
3. **取总账**：Statspack 快照对（接 `08` 章）或 `V$SYSTEM_EVENT` 差值，按 DB time 排序（接 `02` 章）。
4. **归域**：头部等待映射到内存/IO/并发/SQL 四域之一（本目录 `03–06`）。
5. **立假设**："如果 X 是因，则改 Y 后 Z 指标应降 W%"——不可证伪的假设不进变更单。
6. **单变量实验**：一次一个参数/一条 SQL，沙箱优先。
7. **复测**：同口径快照对比，写下"预期 vs 实测"。
8. **回滚或推广**：无效假设立刻撤销（参数回退比新增容易，因为你有基线）。
9. **归档**：把本案写进机构知识库——2006 年叫 Word 文档，今天叫 runbook。

（此九步是本目录对"结构派方法论"的操作性重写 ⚠️；其 2014 工程化版本见 TOP 2e Ch1/Ch3 ✅。）

## 核心概念速览（中英对照）

- **响应时间** — Response Time：服务时间 + 队列等待时间之和，单请求视角总账。
- **吞吐** — Throughput：单位时间完成事务/查询数，系统视角总账。
- **基线** — Baseline：调优前后同口径测量留档，无基线不调优。
- **等待接口** — Wait Interface：Oracle 把会话时间拆为命名等待事件的插桩体系（`V$SESSION_EVENT` 族）⚠️。
- **结构派调优** — Structural Tuning：先讲内存/文件/闩锁部件模型、后谈 SQL 的 2000 年代路线（本册通说定位 ⚠️）。
- **症状派调优** — Symptom-driven Tuning：以问题分类树组织工具的路线（TOP 2e 代表 ✅）。
- **ASMM** — Automatic Shared Memory Management：10g 起 `SGA_TARGET` 自动分配池大小的机制 ⚠️。
- **Statspack** — Statistics Pack：8.1.7 起的免费快照式统计仓库，AWR 的前身 ⚠️。
- **命中率谬误** — Hit-ratio Fallacy：以比率而非等待绝对量决策的反模式 ⚠️。
- **TOP SQL** — Top-SQL Analysis：按逻辑读/物理读/解析次数从 `V$SQL` 抓头部语句 ⚠️。
