# 04 IO与存储结构调优 — Oracle Performance Tuning, 2e（精读重构）

> ⚠️ 主题重组口径（[00-总览与阅读地图.md](00-总览与阅读地图.md) §3/§8）。文件布局、检查点与重做日志的 9i/10g 模型，
> Oracle 行为一律 ⚠️ 转述 + 官方文档锚 ✅；本章 🔧 类比面有限（IO 栈不可本机模拟），如实声明。

## 1. 一个块的旅行：调优者视角的 IO 栈（⚠️ 通说）

```
SQL → 缓冲缓存查找（命中→完） 
    → 未命中：db file ... read → OS read() → 驱动/多路径 → 阵列缓存 → 盘
写：buffer dirty → DBWn 批量写（checkpoint 驱动）；redo 先行 → LGWR 组提交
```

- 关键守恒 ⚠️：**改数据前 redo 必须先落盘（WAL）**，所以"提交慢"多半先查 LGWR 链而不是数据盘。
- 单块 vs 多块读（`sequential`/`scattered`）在栈底是两种完全不同的 IO 形态：随机小读看队列深度与 IOPS，顺序多块读看吞吐与预取。
- 本章没有可跑的 🔧：SQLite/DuckDB 的"IO"全在 OS page cache 与 mmap 层，内核不暴露可比等待面；硬类比只误导，故如实 ⚠️（纪律声明见 00 §8）。

## 2. 数据文件布局学（2006 年最值钱的一章之一 ⚠️）

1. **文件数与条带**：让热段跨盘均摊（ASM/条带化后弱化 ⚠️）；同一盘混放置业文件与热数据 = 磁头震荡。
2. **重做分离**：redo 组成员与数据文件、归档分盘——LGWR 是延迟敏感型，不能排队在扫表 IO 后面。
3. **temp 独立**：排序/哈希溢盘走临时表空间，独立高速盘；`sort_area` 不够时它是第二战场（接 `03` 章 PGA）。
4. **undo/rollback 分离** ⚠️：回滚段密集写与数据写争同一队列；9i 自动 undo 后靠表空间分离延续该思想。
5. 块尺寸选择 ⚠️：OLTP 小块省"读放大"、DSS 大块省"每行开销"；9i 多块池让"按表选块"成为可能（代价：缓存被切碎，`03` 章）。

## 3. 检查点（Checkpoint）病理学（⚠️ 通说）

- 目标函数：把脏页写出摊平，使实例恢复时间可控；触发线：超时（`fast_start_io_target`/10g `checkpoint_interval` 等）+ 日志切换（`log_checkpoint_timeout`/`log_checkpoint_interval`）双轨 ⚠️。
- 症状对照表 ⚠️：

| 症状（当时视图/事件） | 病因 | 动作 |
|---|---|---|
| `free buffer waits` | DBWn 写不过来，LRU 空不出 | 加 DBW 进程数/查 IO 栈 |
| `write complete waits` | 正写的块被抢读 | 同上 + 减小块写批 |
| `log switch` 频繁 + `checkpoint` 尖峰 | redo 太小/超时太短 | 扩成员/降频 |
| 恢复时间长（10g MTTR 目标） | 脏页积压 | 10g `FAST_START_MTTR_TARGET` 统一口径 |

- **10g 代际点**：MTTR 目标把一堆检查点暗参数收敛为一个"几分钟恢复"意图 ⚠️；DBWn 从单进程进化到sets（`db_writer_processes`）——本册 2e 恰在此转折 ⚠️ 推定。

## 4. 重做日志与归档（⚠️ 通说）

- 组循环写：一个组满→切换（switch）→CKPT 触发检查点→归档器搬走→该组可覆写。所以 **switch 频率是"redo 尺寸 × 提交率"的合谋结果**：太快（>6/min 经验线 ⚠️）加大检查点压力与归档竞争；太慢拉长恢复。
- 提交路径等待：`log file sync`（会话等 LGWR 确认）+ `log file parallel write`（LGWR 等盘）——**两行构成"提交延迟"的标准读法**，至今在 26ai AWR 里同构（✅ guide 根见文末）。
- NOLOGGING/直接路径装载 ⚠️：`INSERT /*+ APPEND */` + `ALTER TABLE NOLOGGING` 换装载速度，代价是恢复粒度受损（需备份兜底）；归档模式与 `ARCHIVE_LOG` 参数族是 RMAN 策略的地基（`08` 章工具语境）。
- standby/Data Guard 的日志传输在 2e 时代（9i/10g）已是标配话题 ⚠️，本册按通说有专节（推定）。

## 5. OS 层交叉仪表（⚠️ 时代配方）

Oracle 等待说"慢"，OS 证据说"为什么慢"：`iostat -x`（%util/await/svcm_sz）、`vmstat`（si/so=交换！2006 年头号杀手）、`top`（CPU 队列）、文件系统选择（RAW/异步 IO：`filesystemio_options=SETALL` vs `use_async_io` 老参数 ⚠️）。10g 后 ODM（oracledbasm）/ASM 把这条链内化 ⚠️。

## 6. DSS/批量视角（本册通说会有的"另一半"⚠️）

- 并行执行（DOP）：从属进程 + PX 缓冲统计、`PX` 等待族；"DOP 过配 = 等待搬家"是当时的警语 ⚠️。
- 大表扫描路径：多块读 + 直接路径读（绕过缓存防污染）+ 段预取；与位图索引/物化视图配合的星型模型调优正在兴起（对位精读：[../Cost_Based_Oracle_Fundamentals/08-位图索引.md](../Cost_Based_Oracle_Fundamentals/08-位图索引.md)）。
- 装载与变换：直接路径装载（SQL*Loader path=direct）+ 后建索引 + NOLOGGING 三件套 ⚠️。

## 7.1 补充：redo 尺寸估算与日志切换审计（⚠️ 时代配方）

估算式（通说教学版）：`组大小 ≈ 峰值时段每秒重做生成率 × 期望切换间隔（如 15–20 分钟）`。

```
生成率取证：V$SYSSTAT 'redo size' 两次快照差 / 秒数
（本册时代用 Statspack 报告的 redo per-second 段取此率 ⚠️）
现状审计：V$LOG 组数 × 成员 × 字节；V$LOG_HISTORY 的 switches_per_day
判定：切换 >~200/天 ⚠️ 经验线 → 扩成员或减生成
```

- 减生成的正路（顺序即优先级 ⚠️）：查"逐行提交放大"（`07`）→ 大事务拆分（分批提交而非分批语句 ⚠️ 两语义）→ 装载路径改直接路径（有恢复代价）→ 最后才是"加盘"。
- 参数考古 ⚠️：`LOG_BUFFER`（环形区大小）常见误解=调它提速提交——提交落盘由 LGWR 组提交决定，缓冲只影响高并发下的 `log buffer space` 罕见病。

## 7.2 块大小与"读放大/每行开销"跷跷板（⚠️ 通说）

| 负载 | 小块(2/4k) | 大块(16/32k) |
| --- | --- | --- |
| OLTP 随机单行读 | 赢：一次只搬运需要的行 | 输：读放大×块竞争↑ |
| DSS 范围扫/全扫 | 输：每行 CPU 开销↑ | 赢：一次多块、排序省 |
| undo 高频改 | 赢：CR 重建搬运小 | 视情况 |
| 超长行表 | 行链接风险 | 缓解 |

- 迁移代价 ⚠️：改库块尺寸需 `DB_nK_CACHE_SIZE` 开池 + 表移动（`ALTER TABLE MOVE`）+ 索引重建——2006 年的"大手术"，今天云上的"选实例规格"。
- `db_block_checksuming`（9i 引入 medium/typical）⚠️：每块校验和=用 CPU 换坏块早发现，是"结构派也管可靠性"的标本（对读 [../Database_Reliability_Engineering/00-总览与阅读地图.md](../Database_Reliability_Engineering/00-总览与阅读地图.md)）。

## 7.3 IO 栈交叉验证清单（⚠️ 时代 OS 课收口）

1. `iostat -x`：await 与 %util 双高 → 盘饱和，等待事件必然同步恶化（`db file ...` 族时延 ↑）。
2. `vmstat 1`：si/so 非零 → **OS 在换页，先杀交换再谈 SGA**（2006 头号伪调优病；今天对应容器内存限额误配）。
3. 文件系统：RAW vs FS vs ASM 的异步 IO 路径差异（`filesystemio_options` 只对 FS 有意义 ⚠️）。
4. 多路径/阵列缓存策略（写透 vs 回写）直接改写 `log file parallel write` 基线 ⚠️——redo 盘的"电池保护写缓存"是当时的标准答案。
5. 一切 Oracle 侧"IO 慢"结论都应能在 OS 侧找到同窗口的对应曲线，找不到就回到统计口径（快照窗口错位）⚠️。

## 7.4 一页记忆卡（⚠️ 自测）

1. 提交慢的三处分界？——LGWR 盘（parallel write）、组提交节拍（应用提交率）、远端同步（standby）。
2. 单块读 vs 多块读各查什么 OS 指标？——IOPS/队列深度 vs 吞吐/预取。
3. 为什么"加 DBWR 进程"能治 `free buffer waits`？——脏页写出并行度=IO 通道利用率的乘法项 ⚠️。
4. MTTR 目标改小时发生什么？——检查点更勤、脏页更浅、写更碎——用恢复时间换 IO 平稳度 ⚠️。
5. temp 盘为何常背锅？——`direct path read/write (temp)` 出现先问 PGA 预算（`03`），别先换盘。

## 核心概念速览（中英对照）

- **DBWn** — Database Writer：批量写脏页的后台进程组。
- **LGWR** — Log Writer：redo 组提交落盘进程，延迟敏感。
- **检查点** — Checkpoint：脏页水位推进事件，决定恢复起点。
- **MTTR 目标** — Fast-Start MTTR Target：10g 以恢复时间意图统一检查点参数 ⚠️。
- **日志切换** — Log Switch：redo 组满即换组，触发检查点与归档。
- **log file sync / parallel write** — 提交与写盘的成对等待事件。
- **free buffer waits / write complete waits** — 缓存饥饿与写回竞争的两面 ⚠️。
- **直接路径装载** — Direct-Path Load：绕过 SQL 层缓冲的批量装载（APPEND/SQLLDR direct）。
- **NOLOGGING** — 不记日志选项：换装载速度、牺牲部分可恢复性 ⚠️。
- **条带化** — Striping：跨盘均摊 IO 的布局技术（ASM 的内建前提）。
- **DOP** — Degree of Parallelism：并行执行度。

## 最新演进与工业实践

- **文档锚 ✅（2026-09-28 curl 200）**：文件/内存/IO 调优主链仍在 Tuning Guide（https://docs.oracle.com/en/database/oracle/oracle-database/26/tgdba/index.html ；19 版同构 https://docs.oracle.com/en/database/oracle/oracle-database/19/tgdba/index.html ）；ASM 与存储细化在 Storage 文档族（仅引 guide 根，小节页未验 ⚠️）。
- **布局学的消亡与转生** ⚠️：条带/分离/预取知识被 **ASM、云块存储（Exadata/OCI 本地 NVMe 池化、EBS/持久盘）**吸收——今天"把 redo 放快盘"变成"选对存储层/预配 IOPS"，等待事件名没变、因果链从磁头变成配额与限速。
- **提交路径新面** ⚠️：高并发小事务让 `log file sync` 从"LGWR 慢"扩展为"提交风暴"——12c 起 **group commit + 高效提交（high priority commit）**、19c 的 **SCN 松弛/提交延迟优化**；PG/MySQL 各自以 group wakeup/binlog group commit 应对同题（跨引擎互见 [../高性能mysql.md](../高性能mysql.md)、[../PostgreSQL_10_High_Performance_3e/00-总览与阅读地图.md](../PostgreSQL_10_High_Performance_3e/00-总览与阅读地图.md)）。
- **DSS 侧** ⚠️：并行执行被自治/弹性扩缩接管一部分（OCI Autonomous JSON/TP 自动 DOP），但"过配 = 等待搬家"未变；In-Memory 列存 + Hybrid Partitioned Tables 让"大扫描"从 IO 题变成向量化 CPU 题——与 DuckDB 的列式故事同代（对位精读 [../DuckDB_Up_and_Running/00-总览与阅读地图.md](../DuckDB_Up_and_Running/00-总览与阅读地图.md)、[../DuckDB_in_Action/00-总览与阅读地图.md](../DuckDB_in_Action/00-总览与阅读地图.md)）。
- **工业实践**：SAN/NAS→对象存储湖仓（Exadata 与 Iceberg 互通线 ⚠️ 见 [../Apache_Iceberg活用入門/00-总览与阅读地图.md](../Apache_Iceberg活用入門/00-总览与阅读地图.md)）；本册"文件布局"作为手艺在自建库外的世界里只存词汇表。
