# 07 应用设计与数据访问调优 — Oracle Performance Tuning, 2e（精读重构）

> ⚠️ 主题重组口径（[00-总览与阅读地图.md](00-总览与阅读地图.md) §3/§8）。"从会话到往返"的应用侧课：
> 连接管理、数组接口、事务边界、PL/SQL 卸载与字符集暗坑；Oracle 行为 ⚠️ 转述，🔧 以 SQLite/DuckDB 批量往返类比（非 Oracle）。

## 1. 为什么结构派书要写"应用"章（⚠️ 立场）

等待账本（`02`）里最贵的时间常常不在实例内：轮询式取行把网络往返写进响应时间、逐行提交把 LGWR 打成节拍器、连接风暴让调度进程满负荷。2006 年 O'Reilly 系多作者书脉（本册通说 ⚠️）的特殊贡献正是把"客户端/驱动/SQL 形状"与实例结构放进同一张因果图。

## 2. 会话与连接经济学（⚠️ 通说）

- 专用服务器模型：1 会话=1 服务器进程=一份 PGA；千人直连=内存与上下文切换税。三层解法谱 ⚠️：
  1. **连接池**（Druid/HikariCP 的前辈：Oracle Connection Cache、Tuxedo/TPAM、中间件 JBoss 池）。
  2. **共享服务器**（Shared Server/MTS：调度器+少量公共进程，为"低活跃会话海"设计；代价=每条消息过调度器，高吞吐反受害）。
  3. **池+代理**（10g `DRCP` 数据库驻留连接池把池搬进实例——本册成书时 DRCP 尚未落地，属 11g 补写，⚠️ 标注）。
- 度量 ⚠️：`V$SESSTAT` 的"解析调用数/重做量/逻辑读"三联，是"每业务动作成本"的原子单位；应用团队第一次看到"一次点击=3800 逻辑读"的震撼课由此开始。

### 🔧 类比：往返次数的支配地位（SQLite/DuckDB，非 Oracle）

`python sqlite3` 单机无网络，但"每次执行携带新文本 vs 预编译复用"仍是同一道题的缩影：对 1 万参数组，逐条 `execute("...VALUES(?)", v)` 与 `executemany`+单一预编译语句的差是解析/绑定管线复用之差（DuckDB 线更极端——见 `08` 章引用的跨书实测：`executemany` 1M 行 270s vs `INSERT…SELECT`/append 0.12s，约 2000×，✅ 实证记录于盘上 `DuckDB_in_Action` 波次登记）。**批量接口赢在"次数"，不在"单次数据量"**——这就是下一节 array interface 的全部世界观。

## 3. 数组接口：把 N 次往返压成 1 次（⚠️ 通说；本册招牌课 ⚠️ 推定）

- 谱系：Pro*COBOL `ARRAY` 宿主数组 → OCI array DML → JDBC batch/`defineArrayType` → PL/SQL **批量绑定**（`FORALL` + `BULK COLLECT`，9i 起）。
- 语义：一次网络调用携带 n 组绑定值；行处理仍在实例内循环，**省的是往返与调用边界，不是算法** ⚠️。
- 三坑 ⚠️：
  1. `SAVE EXCEPTIONS` 后错误游标语义与部分提交边界；
  2. 批大小曲线（10→100→1000 收益递减，内存与行锁持有时间上升）；
  3. 驱动透传假象（某些 JDBC 配置下 batch 仍逐条发——抓 10046 验真身）。
- 读侧对称物：预取（prefetch rowset）与 `arraysize/arrayfetch`（SQL*Plus）；`V$SQL` 的 fetch 次数是"往返真话"。

## 4. 事务边界与提交设计（⚠️ 通说；接 `05` 章）

- 逐行提交=回滚段频繁裁剪 + `log file sync` 节拍放大 + 一致性窗口碎片；**"一个业务动作=一个事务"** 是最便宜的调优。
- 自治事务（`PRAGMA AUTONOMOUS_TRANSACTION`，9i）：审计日志的蜜罐——它偷走父事务的 undo/锁账本，滥用即一致性事故 ⚠️。
- DDL 隐式提交、`SELECT FOR UPDATE` 与 `NOWAIT` 策略复习 → `05` 章病理表。

## 5. 在数据库里计算：PL/SQL 卸载的边界（⚠️ 通说）

- 往返税决定了"循环 1 万次拿 1 万行改 1 万行"应写成 1 条 UPDATE/一个 FORALL——**数据密集逻辑向引擎靠，控制密集逻辑向应用靠**。
- PL/SQL 引擎/SQL 引擎上下文切换（9i 前昂贵，9i 缓存优化 ⚠️）；`NOCOPY`、包状态与 PGA 驻留。
- 形状选择 ⚠️：纯 SQL > PL/SQL > 外部过程（Java/C）> 应用循环；"SQL 能表达"优先。
- 教材代际对位（✅ 在盘）：[../Oracle12c数据库应用与开发/09-PLSQL编程基础.md](../Oracle12c数据库应用与开发/09-PLSQL编程基础.md)（若该文件在盘；否则退链其 00）、[../OracleSQL高级编程.md](../OracleSQL高级编程.md) 与 [../Oracle编程艺术：深入理解数据库体系结构（第3版）.md](../Oracle编程艺术：深入理解数据库体系结构（第3版）.md)（游标/共享池机理）。

## 6. 数据类型与字符集的隐形税（⚠️ 通说）

- 类型选错 ⚠️：`VARCHAR2(4000)` 满配滥用 → 行宽膨胀 → `04` 章块密度、`03` 章缓存效率双杀；`NUMBER` vs 定宽数值；DATE 含时分秒的误读。
- 字符集：AL32UTF8 迁移时代（9i/10g 正好启动）——**跨集转换使索引失效**：列侧 `CONVERT`/隐式转换让"索引可用谓词"变全扫 ⚠️；会话/库/客户端三件套 `NLS_LANG` 错配=乱码工单之源。
- 约束即性能 ⚠️：不建外键的老教条（锁链与递归检查的 9i 恐惧）被 10g 的延迟约束与并行直载解锁——正解："约束建全 + 索引配套"（`05` 章 §2 外键索引事故互证）。

## 7. 设计期检查单（⚠️ 收口）

| 检查 | 一次做错的代价 |
|---|---|
| SQL 用绑定 + 批处理接口 | 往返×行数，见 §3 |
| 事务边界=业务动作 | undo/锁/redo 三账本连坐 |
| 取数带行数与列裁剪 | 预取失效、网络放大 |
| 热路径无 DDL/无自治事务 | 字典缓存/共享池风暴（`03`） |
| 字符集与类型全链一致 | 索引失效 + 行宽膨胀 |

## 7.1 补充：驱动 × 批量能力一览（本册时代 ⚠️ 通说；今天普遍增强）

| 驱动/接口 | 批量写 | 批量读（预取） | 备注 |
|---|---|---|---|
| OCI（C） | 数组 DML | row prefetch | 能力最全，其他层的底座 ⚠️ |
| Pro*C/Pro*COBOL | 宿主数组 | OPEN/FETCH 循环+预取 | 银行系主力 ⚠️ |
| JDBC thin | `addBatch/executeBatch` | `setFetchSize` | 假批处理陷阱：需驱动真透传（验 10046）⚠️ |
| ODP/.NET | ArrayBind | FetchSize | 同陷阱 ⚠️ |
| PL/SQL | `FORALL` | `BULK COLLECT LIMIT` | 库内批量正典 |
| SQL*Loader | direct path | — | 与 `04` NOLOGGING 连用 ⚠️ |

- 批大小的双 U 形账 ⚠️：太小=往返没省透；太大=单调用驻留长（锁/undo 峰值、PGA 数组内存）；100–1000 经验带，压测定夺。
- 读侧对称纪律：报表"取回百万行再在应用里过滤"=把 `06` 章谓词工作搬给网络——**能在 SQL 里做的别搬出来**。

## 7.2 连接拓扑三种世界（⚠️ 通说文字图）

```
A 胖客户端直连        B 三层+中间件池          C 池+共享服务器混合
app──(会话×N)──实例   app──池(maxConn)──实例    会话海──调度器──公共进程×k
痛点: PGA/进程数爆炸   痛点: 池参数与事务亲和     痛点: 调度器串行、吞吐税
```

- 选型判据 ⚠️：活跃比（真在跑 SQL 的会话/总会话）低→ B/C；高并发低延迟 OLTP→ B（专用+池）为主；"会话数千+、每会话偶发请求"→ C 才有正收益。
- 度量 ⚠️：`V$SESSION` 的 STATUS=INACTIVE 占比、共享服务器队列视图（`V$QUEUE`/`V$DISPATCHER` 系）为 B/C 世界的体检单。

## 7.3 设计期反例五连（⚠️ 时代课收口）

1. 存储过程里 `LOOP SELECT INTO + COMMIT` 逐行——改 FORALL/一条 SQL（§3/§4 合治）。
2. 用 `ROWNUM` 分页却 SELECT *（列宽放大 × N 页重复排序）。
3. 会话级临时表当队列（DELETE+INSERT 风暴，段头竞争 `05`）。
4. 以字符串拼 IN 列表（版本爆炸 `03/06` + 注入安全双坑）。
5. 报表 SQL 与 OLTP 共库共实例不隔离（峰值互伤——结构派能解释、架构师该预防 ⚠️）。

## 7.4 一页记忆卡（⚠️ 自测）

1. 往返税的三处计账？——网络 RTT、调用边界（解析/执行/取回分离）、驱动隐式逐行。
2. 池 vs 共享服务器的分界指标？——会话活跃比；高活跃下共享服务器是负优化 ⚠️。
3. FORALL 的两种引擎形态？——语句压缩发送 vs 逐语句执行（不同版本年代行为有别，验 trace 为准 ⚠️）。
4. 为什么"改批量"常顺手解决锁问题？——持锁时间从 n 行×RTT 缩到 1 调用（`05` 章 TX 队列化标本）。
5. 字符集税的当代等价物？——类型不匹配的隐式转换（JSON/向量列与谓词形状错配 ⚠️）。

## 核心概念速览（中英对照）

- **往返** — Round-Trip：应用与实例一次调用-应答的网络+协议成本单元。
- **连接池** — Connection Pooling：会话资源复用层（应用池/DRCP 两级）。
- **共享服务器** — Shared Server (MTS)：调度器+公共进程应对会话海 ⚠️。
- **批量绑定** — Array Bind / FORALL：一次调用携 n 组值 ⚠️。
- **BULK COLLECT** — 批量取值：PL/SQL 侧对称数组接口。
- **预取** — Prefetch：驱动层多行打包降低 fetch 往返。
- **V$SESSTAT** — 会话统计：每次业务动作的逻辑读/解析/重做原子账。
- **自治事务** — Autonomous Transaction：独立提交域，审计蜜罐 ⚠️。
- **上下文切换** — Context Switch：PL/SQL↔SQL 引擎搬运税。
- **NLS/AL32UTF8** — 字符集与转换：跨集谓词使索引失效的元凶 ⚠️。
- **卸载** — Offloading：把数据密集逻辑迁入实例内执行。
