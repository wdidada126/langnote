## 2. Statspack 报告读法（⚠️ 通说四步）

1. `exec perfstat.statspack_snap` 前后对（或 `spdoc` 出文档）；阈值与层级参数（snap_level 5/6/7=SQL 深度）先定。
2. **头部读**：负载概况（DB time/每秒重做/解析调用）→ 实例效率段（命中率只看趋势不看达标 ⚠️，`01` 章谬误条互证）。
3. **等待段读**：top timed events 按 DB time 占比 → 归因到 `02–05` 章结构域。
4. **SQL 段读**：按 解析数/gets/reads/sorts 五榜取交集，头部进 10046 细案。

- 常见坑 ⚠️：无基线对比的单期报告=噪音；STATS 与 STATSPACK 术语混写；`STATSPACK` 与 `AWR` 的 RETENTION 策略差异（前者手动清理）。
- TOP 2e 的"没有 Diagnostics Pack 也能查"双轨写法（✅ 同上链）是本节内容的 2014 权威重写。

## 3. 参数面：本册时代的"热参数名录"（⚠️ 通说重组；全部按史前清单读）

| 域 | 9i/10g 热参数 | 一句话语义 |
|---|---|---|
| 内存 | `SGA_TARGET`/`DB_CACHE_SIZE`/`SHARED_POOL_SIZE`/`PGA_AGGREGATE_TARGET` | 池预算（`03`） |
| 块 | `DB_BLOCK_SIZE`/`DB_nK_CACHE_SIZE` | 块尺寸与多池（`04`） |
| 日志 | `LOG_BUFFER`/`LOG_CHECKPOINT_*`/`FAST_START_MTTR_TARGET` | 切换与检查点（`04`） |
| 并发 | `PROCESSES`/`SESSIONS`/`TRANSACTIONS`（派生上限） | 会话上限（`05`/`07`） |
| 优化器 | `OPTIMIZER_MODE`/`CURSOR_SHARING`/`STATISTICS_LEVEL` | 计划与解析（`06`） |
| undo | `UNDO_MANAGEMENT`/`UNDO_TABLESPACE`/`UNDO_RETENTION` | 回滚域（`05`） |
| IO | `FILESYSTEMIO_OPTIONS`/`DBWR_IO_SLAVES`/`DB_FILES` | 异步与写手 |

- 使用纪律 ⚠️：参数只在等待证据指向时动、一次一个、留基线回退；隐藏参数（`_`开头）不进生产变更单。
- 2026 对照：上述大半被 ASMM/MM 自动面与自治层接管（⚠️，见文末），但 **19c 自建库** 参数面仍与表高度重合——这恰是"2006 章面还没死透"的证明。

## 4. 全书方法论总纲（⚠️ 收口）

```
基线（Statspack/AWR 快照对）
  → 账本（DB time 上等待占比 = 02）
    → 归因（内存/IO/并发/SQL 四域 = 03/04/05/06）
      → 分层处置（应用批量与形状 07 → 结构与参数 03–05 → 计划纠偏 06）
        → 复测（回到基线）
```

与近邻书的三向坐标：症状工程化→TOP 2e（✅）；成本公式解剖→CBOF（✅）；块级机理→《Oracle编程艺术》（✅）；本册=2006 年 O'Reilly 视角的"全景底座"（⚠️ 按主题重组）。

## 5.1 补充：一段"报告头"怎么读（⚠️ 合成教学样例，非原书/真实数据）

```
Snap 区间:  08-14 09:00 -> 08-14 11:00 (120 min)   负载特征: OLTP
DB time:    9,600 s（=平均 8 个会话在忙）
redo/s:     1.2 MB   逻辑读/s: 210k   物理读/s: 3.4k
硬解析/s:   340 ⚠️(与整体工作量不成比例=解析病信号)
Top timed events:
  db file sequential read   41%  (avg 6ms ⚠️ 偏高→查 IO 栈 04)
  latch: shared pool        12%  (→06 解析+03 池)
  log file sync              7%
```

四行判读（⚠️）：DB time/秒≈并发活跃会话数——先给"系统忙度"定标；redo/s 与物理读/s 的组合告诉你"写型 or 读型战场"；硬解析率独立成段（结构派特色，`03` 章）；头部两事件若跨两个域，先解更上游者（此处：解析风暴→闩，属一因两症）。

## 5.2 调优变更单模板（⚠️ 时代工程遗产）

| 字段 | 内容要求 |
|---|---|
| 症状 | 时间段+受影响业务+量化（P95 从 x→y） |
| 基线证据 | 快照对编号 + top 事件截图/段 |
| 假设 | 因果句式（若…则…）+ 证伪条件 |
| 变更 | 对象/值/前后/回退步骤 |
| 观察窗 | 复测口径与通过线 |
| 结案 | 预期 vs 实测差值 + 知识条目链接 |

- 与 `01` 章九步一一对应 ⚠️；"回退步骤缺失不予受理"是 2006 年就开始被写进 runbook 的金句。

## 核心概念速览（中英对照）

- **Statspack** — Statistics Pack：perfstat 模式下的手工快照对报告系统 ⚠️。
- **snap_level** — 快照深度：5 含 SQL、6/7 加更难观测项 ⚠️。
- **AWR** — Automatic Workload Repository：10g 自动基仓库（Diag Pack 许可）⚠️。
- **ADDM** — Automatic Database Diagnostic Monitor：AWR 上的自动因果建议 ⚠️。
- **DB time** — 数据库时间：AWR 报告总账与等待占比分母 ⚠️。
- **SQL Tuning Advisor** — SQL 调优顾问：单语句统计/结构/改写/计划四建议流 ⚠️。
- **SQL Access Advisor** — 访问顾问：物化视图/索引/分区的批量方案 ⚠️。
- **动态性能视图** — V$ Views：实例内仪表的 SQL 界面。
- **热参数名录** — Tuning Parameters：内存/日志/并发/优化器/IO 五域参数群 ⚠️。
- **基线回退** — Baseline Rollback：一次一参、可回退的变更纪律 ⚠️。
