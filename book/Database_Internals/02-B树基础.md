## 核心概念速览（中英对照）

- **二分查找树** — Binary Search Tree (BST)：每节点两叉的有序树，随机插入下期望高 O(log n)，最坏退化成链表。
- **自平衡树** — Self-Balancing Tree（AVL/红黑）：用 O(1) 旋转维持高度界；作者论点：它们是为「比较次数」优化，不是为「页读取次数」优化。
- **磁盘块** — Disk Block：IO 的原子单位（HDD 扇区聚合成块、SSD 为 flash page），读 8 字节和读 16KB 成本几乎相同。
- **B 树** — B-Tree：多叉、矮胖、所有叶等高的平衡树；M-路搜索树是它的抽象原型。
- **B+ 树** — B+ Tree：值只存叶层、内部节点纯做路由、叶间可链式串联——工程现实中的「B 树」几乎都是 B+ 树。
- **分隔键** — Separator Key：内部节点的键不存数据，只声明「≤ 我走左边，> 我走右边」的边界。
- **扇出** — Branching Factor / Fanout：一页能容纳的分隔键数决定，键越小扇出越大、树越矮。
- **查找复杂度** — Lookup Complexity：O(log_F N)，F 为扇出；换成 IO 次数量纲后树高即成本。
- **节点分裂** — Node Split：页满则一分为二、父层插分隔键，可能级联向上，树高 +1。
- **节点合并** — Node Merge：下溢页与兄弟归并或借键，可能级联向上传播收缩。
- **计数键问题** — Counting Keys：在 B 树里维护子树大小以支持 rank/select（有序集合 ZRANK 类操作），每节点都要随分裂更新，代价不菲。

## 动机：为什么平衡树还不够

比较模型下 AVL 很完美；磁盘模型下它很糟糕——**每次比较都可能踩一次随机 IO，且节点只有 2 叉**。
树高 log₂(10⁹) ≈ 30 意味着最坏 30 次页读；而扇出 F=200 的 B 树三级就装下 8×10⁶ 个键
（200³），三页封顶。本章的论证链是：IO 原子单位是页 → 节点应填满一页 → 一页塞得下几百键 → 树必须矮胖。
另一-half 是介质论：HDD 的寻道（毫秒级）与 SSD 的读放大（页 vs 擦除块尺寸错配）决定了
「顺序读友好、随机读克制」是所有盘上结构的共同信仰。

## 机制：形状、约定与手术

### 1. 从 BST 到 B 树的变形记

```text
BST(AVL):  节点=1键2叉   高度=log₂N      每层一次页读  → 30 层 = 30 IO
B树:       节点=一页N键  高度=log_F N     F=页容量/键大小 → 3~4 层封顶
关键洞察: 把「平衡」从「高度差≤1」放松为「页内填满率≥50%」，
         换来扇出提升两个数量级——磁盘时代的第一次大权衡。
```

### 2. 分隔键与查找：树是路由表

```text
内部节点: [k1 | k2 | k3]，子指针 c0..c3
不变式: c0 全 ≤ k1；c1 ∈ (k1, k2]；...（本书采用「左≤，右>」⚠️ 约定方向随实现翻转）
查找 = 沿路径每页做一次二分（键在页内有序，比较成本内存价），直到叶层拿值。
```

### 3. 分裂与合并：树的免疫手术

```text
分裂（写满触发）:            合并（下溢触发）:
  页[1..m] 插入第 m+1 键        页只剩 < F/2 键
  → 中位数升父层，页一分为二     → 向兄弟借键；借不到则并入兄弟
  → 父层满则继续分裂            → 父层下溢则继续（可能塌树高）
要点: 分裂/合并都只在一条根→叶路径上发生，O(log_F N) 页写；
     「半满」不变式保证不会振荡（借/还 amortized 有界）。
```

### 4. 计数键：为 rank 付出的额外账

在每节点记「子树键数」即可支持「第 k 小/某键排名」，但分裂、借键、合并都要同步维护一组计数器，
写路径变长。Redis zset 用跳表 + span 解决同类问题（本仓库 [../Redis设计与实现.md](../Redis设计与实现.md)），
B 树派（如 LMDB 的 cursor count）则靠页内计数 ⚠️。

### 5. 手推一遍：F=4 的 B+ 树插入 1..9（🔧 教学示意）

```text
页容量: 最多 3 个键。 插入 1,2,3:      [1|2|3]
插入 4 → 满，中位数 3 升父:            父:[3]  左[1|2] 右[3|4]
继续 5,6:                              父:[3]  [1|2] [3|4|5|6]→满
插 6 后分裂:                           父:[3|5] [1|2] [3|4] [5|6]
7..9 全进最右页，9 使 [7|8|9] 分裂 → 10 升父 → 父满 → 根分裂 → 树高 +1
观察: ① 树高只随「根分裂」增长；② 分裂点总在中间 → 页永远 ≥ 半满；
     ③ 每一步只触碰一条根→叶路径 = 2~3 页读 + 1~2 页写。
```

## 权衡

| 维度 | 二叉平衡树 | B 树 | 代价挪去哪了 |
| --- | --- | --- | --- |
| 优化目标 | 比较次数 | 页读取次数 | 旋转 → 分裂/合并 |
| 节点大小 | 常数 | 一页（KB 级） | 内存碎片 → 缓冲池管理（第 5 章） |
| 平衡手段 | 旋转 O(1)/次 | 页半满 + 手术 | 单键操作 → 整页拷贝 |
| 顺序扫 | 中序回溯 | 叶链一跳一跳（第 4 章补） | 树形 → 链表混合 |

HDD vs SSD 一节留下本书一个重要伏笔：**SSD 上「随机读 ≈ 顺序读」的民间说法只对读成立，
写要面对擦除块（可达 MB 级）——这正是第 7 章 FTL/LSM 互怼的战场。**

## 相邻概念对比

- **B 树 vs B+ 树**：B 树值散布所有层（更新近叶时可能碰到内部节点存的数据）；B+ 树值全在叶、内部纯路由、可挂兄弟链——本章名义讲 B 树，结论多为 B+ 树。
- **B 树 vs 跳表**：跳表用随机层数换平衡、纯内存友好；B 树用页填充换 IO 次数。第 7 章会看到跳表以 memtable 形态回到磁盘阵营。
- **B 树 vs LSM**：都是「矮胖有序」，差别在原地点（更新一个键=更新一条路径）还是延迟点（更新=追加，整理=另算）——第 7 章全景对比。
- **与论文对照**：Comer 1979《The Ubiquitous B-Tree》是本章的祖师爷读物；本仓库 [../../paper/doi_10.1145_191839.191884/00-精读笔记.md](../../paper/doi_10.1145_191839.191884/00-精读笔记.md) 精读的 AlphaSort 则展示了「把页当缓冲区做外部排序」的同源思想。

## 常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「AVL 旋转 O(1) 所以比 B 树分裂便宜」 | 盘上成本按页算：AVL 一次插入触碰 log₂N 个页，B+ 树只触碰 log_F N 个 |
| 2 | 「B 树节点越大越好」 | 大到页读不完/缓存命中率崩，且分裂搬运整页；扇出受页大小与键大小夹逼 |
| 3 | 「SSD 没有寻道所以介质无关」 | 写粒度错配与 GC（FTL）造成长尾；第 7 章用 LSM 的顺序写正面回应 |
| 4 | 「树高只差一层」 | 一层 = 一次随机 IO ≈ 100μs；百万 QPS 系统里一层树高就是一个数量级的容量 |
