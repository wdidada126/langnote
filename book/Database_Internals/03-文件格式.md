> 上一章说「节点=一页」，这一章回答：**一页的字节到底怎么排，才能既紧凑又经得起介质腐化。**

## 核心概念速览（中英对照）

- **二进制编码** — Binary Encoding：放弃文本/XML，用定长或自描述的长度前缀序列化，换解码速度与体积。
- **变长字符串编码** — Length-Prefixed vs Null-Terminated Strings：前者 O(1) 取长、需读前缀；后者省一字节但扫描定长。
- **位打包** — Bit-Packing（Booleans/Enums/Flags）：把布尔、枚举、标志位压进位图，一列百万 bool 只占 125KB。
- **槽式页** — Slotted Page：页头维护 (槽号 → 偏移+长度) 目录，数据区从两端相向生长；移动记录只需改槽目录。
- **单元（Cell）** — Cell：槽式页里的一条记录/键值，页内布局的最小搬运单位。
- **稳定槽号** — Stable Slot ID：逻辑地址 (页号, 槽号) 与物理偏移解耦，父层分隔键可以引用槽号而非字节偏移。
- **变长数据外溢** — Overflow / External Storage：超过页阈值的大字段挪进专门页，主记录留指针。
- **版本化** — Versioning：在页/文件头写格式版本号，让老数据文件在新引擎下仍可辨认。
- **校验和** — Checksumming：页级校验发现静默腐化（silent data corruption）；只能检测、不能修复。
- **撕裂页** — Torn Page：写入中途掉电导致页只落了一半，新旧字节混杂；checksum 大概率能发现（不能预防）。

## 动机：为什么「页格式」值得一整章

磁盘不会礼貌地失败——它可能返回**看起来合法但内容错位**的字节（固件 bug、线缆衰减、介质老化）。
而 B 树的全部不变式（键有序、分隔键正确、叶链完整）都建立在「页内字节位置精确」上。
所以页格式要同时解决三件事：**空间效率**（一页尽量多装键）、**寻址稳定**（记录可以挪位而不惊动上层引用）、
**损坏可测**（坏页要能自证坏）。本章的编码→页→校验三层结构就是按这三问组织的。

## 机制：从字节到页

### 1. 编码层：定长、前缀、位图三件套

```text
整数     : 定长(u8..u64) 或 varint（小值省字节，大值多付续位）
字符串   : [len:u32][bytes...]  或  [bytes...][\0]   —— 前者支持 O(1) 跳过
布尔数组 : 位图，1e6 个 bool = 125KB（对比逐字节存 1MB）
混合记录 : 先定长区，再变长区，中间放「变长字段偏移表」
```

作者反复强调的通用原则（General Principles）：**能定长不前缀、能位图不字节、解析代码要能只靠头部信息决定读多少**——
后者是为「部分读」（只读页头就能跳过整页）服务，为第 5 章缓冲池的预读与第 7 章 SSTable 的块索引埋线。

### 2. 页层：slotted page 的双端夹逼

```text
┌──────────┬───────────┬───────────────┬───────────┬──────────┐
│ 页头      │ 槽目录     │  空闲区        │ 数据区↓   │ 大字段溢出│
│ id/类型   │ (0)→96,32 │   （相向       │ (1)→...   │  指针区↑ │
│ 槽数/占用 │ (1)→128,40 │   吞噬）      │ (2)→...   │          │
└──────────┴───────────┴───────────────┴───────────┴──────────┘
删除中间某槽 → 回收其字节到空闲区，槽号保留为空洞；
插入新记录 → 分配空洞或新槽；整理时移动数据、只改槽目录 → 逻辑地址不变。
```

这套设计的核心红利：**父节点的分隔键只需记「第 7 槽的键」，不需要记字节偏移**——
页内整理、删插挪位都不传染给树的上层。InnoDB 的数据页（page directory + heap）是同一思想的变体。

### 3. 耐久层：版本与校验

- Versioning：文件头/页头带格式版本，滚动升级时新旧格式共存（并配第 4 章的 vacuum 做迁移）。
- Checksumming：每页带校验和（CRC32 级别），读页即验；发现坏页后按第 5 章 WAL 重做或从副本/备份拉取。
- 撕裂页防线（⚠️ 本书展开程度以原文为准；机制属公认知识）：`full_page_writes`/双写缓冲——把整页作为原子单位重写，配合 WAL 避免半新半旧。

补充两条编码层的「南北之战」（书中在二进制编码一节讨论 ⚠️ 细节口径）：
**字节序**（大端/小端）与**对齐**（自然对齐省 CPU、紧凑排布省字节）——
盘上格式通常约定一种序、读时按需翻转；页内偏移若不对齐，二进制解码器就要处理跨字边界，
这就是很多引擎「列区按 8B 对齐、变长区随意」的由来。

### 4. 两个字节级算例（🔧 教学示意）

```text
① varint 对账: 值 127 → 1 字节(0x7F)；值 300 → 2 字节；值 1e12 → 5 字节。
   一列 1e9 个「多数 <128 的计数器」: 定长 u64 = 8GB；varint ≈ 1.1GB + 解析循环。
   但块索引若想 O(1) 跳到第 k 行，varint 变长直接判死刑 —— 空间与随机寻址互斥。

② slotted page 记账: 页 4KB，页头 32B，槽项 4B，记录均长 200B。
   设装 n 条: 32 + 4n + 200n ≤ 4096  →  n ≤ 17.7 → 17 条，密度 83%；
   若无槽目录(紧凑数组): 19 条但删一条要移动 ~9 条记录 → 写放大反噬。
   槽目录那 4B/条，买的是「页内记录可原地户口迁移」。
```

## 权衡

| 选择 | 得到 | 付出 | 替代方案 |
| --- | --- | --- | --- |
| varint | 空间（小值占 1B） | 解码要循环、偏移不可预测 | 定长 + 压缩 |
| 槽目录 | 挪位稳定、部分读 | 页头开销、间接一跳 | 紧凑数组 + 全页重排 |
| 大字段溢出页 | 主记录密度、扫描快 | 读大字段多一次随机 IO | 内联 + 压缩 |
| 页校验和 | 腐化可测 | CPU；且防不了「写对位置但内容错」的逻辑 bug | 端到端校验（原书 12 章 Merkle 是其分布式版） |
| 槽号做逻辑地址 | 上层引用稳定 | 槽号空洞要回收、跨页比较多一层 | 直接用字节偏移（快但脆） |

## 相邻概念对比

- **本章 vs 第 1 章布局**：第 1 章讲「记录按行还是按列」是文件间格局；本章讲「一页内字节怎么排」是页内格局，尺度差两个数量级。
- **slotted page vs SSTable 块**：LevelDB/RocksDB 的 data block 也用「块尾重启点 + 前缀共享编码」解决同样的「键太占地方」问题（本目录 `07`）；不同点是 SSTable 不可变，槽目录可以整块省掉。
- **checksum vs 备份/副本**：校验和只回答「坏没坏」，修复靠冗余——单机靠 WAL+备份，分布式靠复制（原书 11 章）与反熵（原书 12 章，本目录 `09`），这是本书把文件格式放进 Part I 的深意：**故障模型要先在字节层立起来**。
- **与 DDIA「编码与演进」**：DDIA 讲 schema 层兼容（ Avro/protobuf），本书讲更底层的字节页格式；两者正交。

## 常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「页大小=文件系统块大小」 | 数据库页（4–16KB）通常 ≥ 扇区/flash 页，是逻辑 IO 原子单位，与介质块解耦 |
| 2 | 「有了校验和就不怕坏页」 | 校验和是烟雾报警器，不是灭火队；修复路径必须预先设计（重做/重取副本） |
| 3 | 「变长字段越多越好」 | 变长区打乱页内偏移可预测性，需要偏移表；定长列+位图是页密度的护城河 |
| 4 | 「删了记录空间就回来了」 | 槽目录会留空洞，碎片积累要整理（第 4 章 defrag/vacuum 主题） |
