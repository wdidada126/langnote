# 第 4 章 B 树的实现（Implementing B-Trees）

> 覆盖原书第 4 章：Page Header（Magic Numbers、Sibling Links、Rightmost Pointers、Node High Keys、
> Overflow Pages）/ Binary Search（含 Indirection Pointers）/ Propagating Splits and Merges（Breadcrumbs、
> Rebalancing）/ Right-Only Appends / Bulk Loading / Compression / Vacuum and Maintenance
> （Fragmentation Caused by Updates and Deletes、Page Defragmentation）/ Summary。
> 上一章定了页的语法，这一章把 B+ 树从伪代码变成能过冬的实现——**全是教科书不讲的边角，
> 但每个边角都对应一次线上事故**。

## 核心概念速览（中英对照）

- **页头** — Page Header：页类型、页数、事务槽等元数据区；引擎辨认「这页归我管」的第一现场。
- **幻数** — Magic Number：页头里的常数签名，打开文件先验身，防止拿错引擎读坏/读错格式。
- **兄弟链** — Sibling Links：叶层左右指针，把树的一角缝成链表；范围扫描免回溯。
- **最右指针** — Rightmost Pointer：内部节点指向最右孩子的兜底指针，配合高键让「插入最大键」不触父层。
- **节点高键** — Node High Key：节点记录自身上界（而非仅靠父层分隔键），使子树可独立自证范围。
- **溢出页** — Overflow Pages：大键/大值链出去的外部页，保持主树页内密度。
- **间接指针二分** — Binary Search with Indirection Pointers：先按槽目录跳再页内定位，避免对变长记录做字节级二分。
- **分裂传播** — Propagating Splits：叶分裂→父插入→父满再分裂，沿路径向上；树高只在根分裂时 +1。
- **面包屑** — Breadcrumb ⚠️（译名）：记录本次操作走过的根→叶路径，传播手术时免二次下查。
- **单调追加** — Right-Only Appends：插入键大于树内所有键时，新键全进最右页，B+ 树退化为顺序日志。
- **批量装载** — Bulk Loading：外部排序后自底向上造树，或用右倾快速路径，导入成本从 n·log 降为 ~n。
- **碎片整理** — Page Defragmentation：更新/删除攒出的空洞与乱序，靠在线整理或离线 vacuum 回收。

## 动机：伪代码 B 树为什么活不过生产

教科书版本假设「节点是结构体、指针随便改」。现实里：节点是盘上的页（改之前要先读回来）、
指针是 (页号,槽号)（要防悬空）、范围查询要横扫百万键（不能每次回根）。
本章每个小节都在补一个这种裂缝。作者的例子很具体：**无兄弟链的树做 `WHERE x BETWEEN a AND b`
要执行 k 次「回根再下降」；有链之后是 1 次下降 + k-1 次横向跳。**

## 机制：五组工程决定

### 1. 页头字段学：让页自我描述

```text
PageHeader: [magic | version | page_id | type(leaf/inner/overflow) |
             n_slots | rightmost_child | sibling_left | sibling_right | high_key?]
设计哲学: 页是自治公民——拿到任意一页，不查上下文就能知道
  我是谁(magic/version)、我装什么(type)、我的键范围(high key)、我的邻居(siblings)。
```

高键与父层分隔键是**冗余**的（可以互相推出），冗余换来的是：插最大键走最右指针直达，
不必从根带锁下降——这是「读放大换写路径缩短」的微操。

### 2. 分裂传播与面包屑

```text
插入触发链: 叶满 → 分裂 → 父插分隔键 → 父满? → 递归
朴素实现: 每层分裂后重新从根查找父页（多 log 次读）
面包屑:   下降时把路径压栈；手术时弹栈改父 —— 但栈要带「页版本」，
         因为并发下父页可能已被他人分裂（槽号失效）→ 第 5 章锁协议接管。
```

### 3. 右倾世界：追加负载的免费午餐

UUID 主键 vs 自增主键的经典账（MySQL 圈反复讨论，本章给了结构解释）：

```text
自增:  99% 的插入落在最右叶 → 顺序 IO、缓存命中率高、无中途分裂
UUID:  插入随机散落全树 → 每键一次页读+页写+分裂，写放大失控
```

**时间序列数据库用 B+ 树不是不能，而是要靠「右倾」把 B+ 树用成 LSM。**

### 4. Bulk Loading 与压缩

- 自顶向下（逐条插入）成本 n·log n 次页触碰；自底向上先把数据排序、按页宽切段造叶、
  再逐层生成内部节点，成本 ≈ 数据量一遍扫。
- 页内压缩（前缀共享、列式编码见第 3 章）提高扇出；但**压缩键要能不解压比较前缀**，
  否则每次二分都全页解压，得不偿失 ⚠️（作者立场：视实现而定）。

### 5. 碎片与 vacuum

```text
删除 → 页半空但仍占缓存；更新 → 页内挪记录攒缝隙；
症状: 同样键数，扫描要读的页数变多（空间放大在 B 树里的形态）。
处方: 页内整理（defrag 单页，槽目录重排）+ 全库 vacuum（重写，需额外空间与 IO 预算）。
```

## 权衡

| 决定 | 换来 | 付出 |
| --- | --- | --- |
| 兄弟链 | 范围扫 O(k) | 分裂时要缝链（跨页原子性 → 第 5 章） |
| 高键+最右指针 | 追加路径免带锁下降全树 | 页头冗余、更新时多维护一处 |
| 面包屑 | 传播手术省重查 | 栈内页可能过期，须版本校验 |
| 压缩扇出 | 树更矮、IO 更少 | CPU 解压、无法二分比较的键反而更慢 |
| 在线 vacuum | 空间回收、碎片治理 | 与前台抢 IO，需限速 |

## 常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「随机主键只是慢一点」 | 它摧毁的是整棵树的缓存局部性，QPS 差距可到一个数量级 |
| 2 | 「有了高键就可以不要父节点」 | 高键优化的是特定路径（最右/范围端点），一般查找仍靠分隔键下降 |
| 3 | 「vacuum 是奢侈品」 | 不 vacuum 的 B+ 树空间放大持续累积，扫描成本单调恶化 |
| 4 | 「bulk load 就是关索引导入再重建」 | 关索引重建是通用解；本章讲的是「利用排序流自底向上造树」的正解，代价是并发窗口设计 |
| 5 | 「magic number 是多余的仪式」 | 它是第一道防线：防止半写文件、跨引擎误读、版本错配在「打开瞬间」而不是「跑崩之后」才暴露 |
