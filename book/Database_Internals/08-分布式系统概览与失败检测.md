## 核心概念速览（中英对照）

- **共享状态** — Shared State in a Distributed System：多机读写同一份数据；网络延迟让它只能是「协议构造出来的幻觉」。
- **分布式计算谬误** — Fallacies of Distributed Computing：八条新手假设（网络可靠、延迟为零、时钟可信……）条条皆假（Lan/Druschel 等，书中列举）。
- **时钟与时间** — Clocks and Time：物理钟会漂移（clock skew）、NTP 只给概率上界；逻辑时钟（Lamport）放弃物理真实、保因果序 ⚠️ 书中以 Spanner TrueTime 收尾。
- **不完全失效** — Partial Failure：一部分节点在处理请求时死掉，其余仍活着——单机世界不存在的原罪。
- **网络分区** — Network Partition：连通性断裂把「一个集群」变成「几个各自正确的孤岛」。
- **级联失效** — Cascading Failures：超时重试/负载转移把单点故障放大成雪崩（Sloth 论文式反例，书中引用）。
- **两将军问题** — Two Generals' Problem：不可靠信道上无法让双方都「确知对方确知」——共识需要假设信道足够好。
- **FLP 不可能性** — FLP Impossibility：异步系统中哪怕一个崩溃故障，也没有确定性共识算法能保证终止——给「超时」留了活门。
- **同步模型** — System Synchrony：同步/异步/部分同步（partial synchrony，Dwork 等）三档；Paxos/Raft 的正确性不依赖时钟，终止性依赖。
- **失效模型** — Failure Models：崩溃（crash）、 omission（漏收漏发）、拜占庭（arbitrary）三档，检测难度与算法代价逐级暴涨。
- **失败检测器** — Failure Detector：Chandra-Toueg 抽象：只能输出「怀疑」，完备性（强/弱）与准确性（强/弱）互相让步。
- **心跳与 ping** — Heartbeats and Pings：超时判死；超时值=「网络最慢 × 安全系数」，静态值必然两头挨打。
- **Phi 累积检测器** — Phi-Accrual Failure Detector：不判死活、输出「此刻无响应的怀疑度 φ」连续值，阈值交调用方（Cassandra/Akamai 采用）。
- **外包心跳** — Outsourced Heartbeats：把「谁还活着」交给第三方共识组（如 Consul/ZooKeeper 型架构），监控者与被监控者解耦。

## 动机：为什么 Part II 从「哲学」讲起

第 13/14 章的 2PC 与共识各有一个「不可能性」在旁边站岗：**两将军**告诉协调者协议为什么永远差一步确认，
**FLP** 告诉共识为什么必须引入超时/随机/部分同步假设。作者先把这些「不能做什么」钉死，
再谈失败检测「能做什么」——这一对是本目录 `10`/`11` 两章一切权衡的宪法。

## 机制：从故障分类到故障怀疑

### 1. 故障谱系与检测难度

```text
crash-stop     : 死了且不再说话       → 心跳+超时可高置信检测
crash-recovery : 死了又活(可能带旧状态) → 重启要带任期/epoch（→ 第 14 章 term）
omission       : 活着但消息丢了        → 端到端重传/ACK 才能暴露
byzantine      : 任意行为(说谎)        → 只能靠多数+签名(PBFT, n>3f)
```

### 2. 超时的两难与 phi 的解法

```text
固定超时 T: T 太小 → GC 停顿/慢网络误杀（把活人判死，触发不必要的选举/副本切换）
            T 太大 → 真死无人管，RTO 拉长
phi-accrual: 统计心跳间隔分布(指数滑动) → φ = -log10(1 - F(t_gap))
   输出不是 bool 而是连续怀疑度: φ=2 可容忍、φ=8 几乎必死 —— 调用方自选阈值
   本质: 把「网络抖动多大」从常量变成在线学习的分布
```

超时派之外，第 9 章还给两味药：**timeout-free**（CHL 算法：靠「无法同时满足的等待证明对方在」，教学价值 > 实用价值）
与 **gossip 检测**（SWIM：怀疑→让邻居代 ping，把 O(n²) 全连接监控摊成 O(n·log n) 采样——与本目录 `09` 的 gossip 传播同一家族）。

### 3. 「反过来问」：Reversing the Failure Detection Problem

章末反转很有意思：不是「证明它死了」，而是「证明它活着才升级权限」——
**租约（lease）**思想（第 10/14 章复用）：默认谁都不是领导/有锁方，持续证明存活才持有特权；
误判「活人死」由超时背锅，误判「死人活」被租约到期自动纠正。

### 4. 八条谬误与一次真实事故剧本（🔧 示意）

```text
谬误清单(本书列举口径): 网络可靠 / 延迟为零 / 带宽无限 / 拓扑不变 /
  只有一个中心 / 没有成本 / 时钟同步 / 不需要安全 —— 条条皆假。
剧本: 机房 A/B 双活，A 侧 NTP 源故障钟快 3s。
  t=0   客户端在 A 写入 x=1，TS(A钟)=1003
  t=0.1 客户端在 B 读 x，快照 TS(B钟)=1000 → "我的写还没发生" → 读己之写被破坏
  检测器视角: A/B 心跳正常，没人"死"——这是时间故障，不是成员故障。
教训: 谬误不是段子；每一条都有对应的协议补丁(重传/超时/租约/NTP/TSO/防火墙)。
```

## 权衡

| 决策 | 选项 A | 选项 B | 判据 |
| --- | --- | --- | --- |
| 时钟 | 物理钟+PTP（Spanner 路线） | 逻辑/混合钟（HLC） | 是否需要「带误差棒的瞬间」做快照定序 |
| 检测 | 拉模型（中心轮询） | 推模型（心跳/gossip） | 规模 O(n) vs O(n²) 的通信预算 |
| 超时 | 静态 | phi 自适应 | 负载/网络方差大小；可调参数量 |
| 分区策略 | 保可用（各自接单） | 保一致（拒绝写入） | CAP 三角，本目录 `09` 细算 |
| 故障转移 | 自动（检测器驱动） | 人工（值班确认） | 误判代价 vs MTTR；金融写路径常选后者 |

## 相邻概念对比

- **两将军 vs FLP**：前者说「不可靠信道上连『达成共识可达』都不能确认」，后者说「异步+一故障 ⇒ 确定性共识不能保证终止」；
  工程上两记重锤都由「部分同步 + 随机超时/领导者」拆弹（第 14 章）。
- **失败检测器 vs 共识组**：CHL/phi 是「怀疑者」，Paxos 法定人数是「裁决者」；生产系统常用后者裁决前者（外包心跳节）。
- **本章 vs DDIA 第 8–9 章**：DDIA 的「不可靠广播/时钟」与本章一一对应，但 DDIA 直接进结论；本书把检测器的形式性质（完备/准确）讲得更学术。
- **与 [../../courses/数据库系统/15445/README.md](../../courses/数据库系统/15445/README.md) 的关系**：课程不讲 Part II；分布式补课在 MIT 6.824（本仓库 [../MIT 6.824 Distributed Systems.md](../MIT%206.824%20Distributed%20Systems.md)）。
- **与 [../设计数据密集型应用.md](../设计数据密集型应用.md) 第 8/9 章**：不可靠网络与「真的时间」两章与本章几乎一比一对译，适合前后脚读。

## 常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「超时到了就是死了」 | 超时只能给出「怀疑」；误杀引发的选举抖动比真死更伤（Cassandra phi 的动机） |
| 2 | 「NTP 同步了就能拿时间戳排序」 | 钟漂+闰秒+vmsteal；要排序要么因果逻辑钟、要么带误差棒的 TrueTime |
| 3 | 「FLP 说明 Paxos 不可能」 | FLP 打的是「异步+确定性+必终止」三角；Paxos 放弃必终止（部分同步下才终止），正确性不受影响 |
| 4 | 「拜占庭是实验室玩具」 | 公有链/多云互不信任场景就是它的现实版；本书给 PBFT 一节正名 |
| 5 | 「gossip 心跳 = gossip 传播，一件事」 | 检测用「怀疑扩散」，传播用「事实扩散」，收敛语义不同；同一套传输内核、两张账单 |

## 思考题

1. 你的服务 GC 停顿 P99=2s、心跳超时设 3s：用 phi 的思想重述「该阈值该为什么是错的」，并给一个动态策略。
2. 用「怀疑完备性/准确性」语言描述：把检测器阈值调低，换来什么、赔上什么？画四象限（强/弱完备 × 强/弱准确）。
3. 外包心跳（Consul 型）在「监控集群自己被分区」时发生什么？它把故障域收敛到哪了？
4. 把本章八条谬误逐条对到你会用的一个真实中间件上，各写一句「它靠什么补丁活着」。
