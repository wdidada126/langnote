## 核心概念速览（中英对照）

- **拷贝写** — Copy-on-Write (COW)：改节点=复制整条根路径后切换根指针；原地更新的对立面，天然原子、天然快照。
- **抽象节点更新** — Abstracting Node Updates：把「改一页」收敛为「换一页」的接口，让上层树形不关心页内手术——COW 与 lazy 共享的底层抽象。
- **惰性 B 树** — Lazy B-Tree：把对某子树的更新攒成「脏子树标记」，读路径顺手整理；连续区间更新从 O(k·log n) 摊到 O(log k + log n)。
- **WiredTiger** — WiredTiger：MongoDB 默认引擎 ⚠️（版本现状以官方为准），「页级增量 + 修改向量（modify vector）」的惰性整理代表 ⚠️ 细节按本书口径。
- **LAT 树** — Lazy-Adaptive Tree：在内存里攒更新、按热度阈值自下而上转「显式节点」；写吞吐逼近日志结构。
- **FD 树** — FD-Tree（Fragmented-logarithmic Mapping）：把键切成固定宽度片段沿树下降逐段匹配，层数=⌈键宽/片宽⌉，免平衡手术。
- **分数级联** — Fractional Cascading：相邻层按 1/b 比例互含带链接的键，跨层查询从 k 层×log 降为 log N + k。
- **对数游程** — Logarithmic Runs：把「追加序列」表示成大小 2^i 的不可变有序块森林，插入=归并若干块——B 树阵营向 LSM 概念借力。
- **Bw 树** — Bw-Tree：无锁内存映射页 + (基页,增量页) 映射表；写=追加增量并 CAS 换映射。
- **更新链** — Update Chains：Bw 树中一页的「原版 + 一串 delta」，读要链上归并，后台 consolidation 压平。
- **比较并交换** — Compare-and-Swap (CAS)：硬件原子指令；「值没变才换指针」使无锁树成为可能，也带来 ABA 问题。
- **结构修改操作** — Structural Modification Operation (SMO)：分裂/合并等改树形的操作；Bw 树用「逻辑父 + 辅助映射页」把 SMO 拆成可 CAS 的小步。
- **缓存无关树** — Cache-Oblivious B-Tree：不知缓存容量/行大小，仅靠 van Emde Boas 递归折叠布局逼近最优层穿越。

## 动机：第 4/5 章欠的三笔账

1. **写路径账**：改一个键要沿路 O(log n) 页做手术，每页一把闩 + 一份 WAL（第 5 章）。
2. **并发账**：分裂传播要同时钉住父子页，锁顺序稍有不慎即死锁。
3. **层穿越账**：节点=页在 SSD/内存时代显得太「胖」，CPU 缓存行级访问效率被浪费。

本章六个家族各答一笔或几笔：COW 答 1+2，lazy 答 1，FD/级联/游程答 3 与特殊负载，Bw 答 1+2+3 的内存变体，cache-oblivious 纯答 3。

## 机制：三个代表深挖

### 1. COW / LMDB：不传播，只换根

```text
原地: 叶变 → 父变 → … → 根变（沿途锁+日志）
COW : 叶' = 复制(叶)+改; 父' = 复制(父)换指针; … 根' 就绪
      提交 = CAS(根指针, 旧根 → 新根)   一步原子，旧树整体仍是快照
副作用清单:
  - 空间单调膨胀 → free list 页复用（事务化）
  - 兄弟链难存（页号不再相邻）→ LMDB 用「逻辑页号=序」⚠️ 变通
  - 长读事务钉住旧根 → 写者见膨胀后强制让读者重试（LMDB reader table）
```

免 WAL 的秘密：**页永不原地改，崩了就没有「半新半旧」**——第 5 章的撕裂页/undo 问题被结构消解。

### 2. Lazy 家族：把「整理」推给下一次读

```text
更新子树 T:  不碰 T，只在祖先挂「+Δ」标记（整棵子树同一增量的批量改）
读取键 k :   沿路收集标记 → 若命中脏子树，顺手把 Δ 物化下去（摊还）
连续区间更新 [a,b): O(log(b-a)+log n) —— 原地派要逐键 O((b-a)·log n)
```

LAT 的「自下而上攒、攒够转显式」与 FD 树的「定深分段」都把 B 树写路径的**常数**砍下来；
代价统一是：读要合并标记、GC/整理线程常驻。

### 3. Bw-tree：CAS 树上的 B 树

```text
映射表: state  = 页id → 指针
页形状: base page + delta chain(最新在前)
写: delta 记录(键,op) → CAS(state, old指针, new指针带 delta)   无闩无锁
SMO: 分裂=挂一个辅助「路由页」，原父页逻辑保留、指向子页 —— 把大手术拆成链式 CAS
后台: consolidation 压 delta 链; mapping GC 回收被 CAS 替换的旧版本(防 ABA 靠版本号)
```

Bw 是「把 LSM 的 append + 后台整理思想搬回 B 树页语义」的最直白尝试——
与本目录 `07` 读 LSM 时形成镜像。

### 4. FD 树速写：深度不再由「平衡」决定（🔧 示意）

```text
键视为比特流，每层消费 w 位:
  层0 匹配键[0:w] → 层1 匹配键[w:2w] → … 深度 = ⌈键宽/w⌉ 恒定
插入: 沿既有前缀走到分叉点挂新边 —— 无分裂、无合并、无再平衡
收益: 写路径 = 常数页 + 少量节点创建；天然适配「追加流」
代价: 键区间查询退化为多分支 DFS；页内结构要重新发明(子表/有向边)
一句话: 它不是「更快的 B 树」，是「拿前缀换平衡手术」的 trie-B 树混血。
```

## 权衡

| 家族 | 削平的山 | 新垒的山 |
| --- | --- | --- |
| COW | 传播锁、撕裂页、快照免费 | 空间膨胀、写放大整路径、碎页 |
| Lazy | 区间更新成本 | 读路径复杂化、整理线程 GC |
| FD/级联 | 特殊负载（前缀/多级区间） | 通用性差、实现极难 ⚠️ 书中评估：收益负载依赖 |
| Bw | 闩锁竞争、页手术 | delta 链读放大、依赖 GC 与 CAS 正确性 |
| cache-oblivious | 层穿越常数 | 理论漂亮；作者对实际收益持保留 ⚠️ |

## 相邻概念对比

- **COW vs LSM**：都「不改旧页」；COW 仍是树（单键查找 O(log n) 页读、无多源归并），LSM 放弃树形换追加。判据：**要不要保持「每个键一条路径」的读形状**。
- **Lazy B 树 vs RocksDB 的 range delete**：整子树挂标记 ≈ LSM 的区间墓碑，都在解决「批量删/改不该逐键付钱」。
- **logarithmic runs vs 分层 LSM**：游程森林的「归并大小 2^i 块」就是 size-tiered compaction 的树内投影——第 7 章见正主。
- **LMDB vs WiredTiger vs InnoDB**：本仓库 [../mysql/01-InnoDB与MySQL的架构.md](../mysql/01-InnoDB与MySQL的架构.md) 走第 5 章原地路线，LMDB 走 COW、WiredTiger 走 lazy——三种页更新哲学各有一个活样本。

## 常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「COW 没有并发问题」 | 没有锁但有版本膨胀与「读者钉住旧代」问题；LMDB 的 reader 槽设计即为此 |
| 2 | 「无锁=更快」 | CAS 在高冲突下空转重试，Bw 论文用 delta 链摊薄；无锁只是把等待搬到另一处 |
| 3 | 「变体多说明 B 树不行」 | 恰恰说明 B 树的「单路径读」形状太值钱，所有人都想保住它再修其余 |
