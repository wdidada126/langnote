# 第 4 章　透明多级分流系统

> 原书第 4 章讲「请求从浏览器到服务端，沿途经过的每一级该怎么分流、怎么缓存、怎么提速」。
> 这是架构师视角的「流量路径」一章：**透明**指业务代码无需感知这些层级，多级指从客户端缓存到服务端缓存层层设防。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 4.1 客户端缓存 | 强制缓存（Cache-Control/Expires）、协商缓存（ETag/Last-Modified） | 能不请求就不请求，是成本最低的一级 |
| 4.2 域名解析 | DNS 递归/权威、解析与调度 | DNS 是流量入口的「第一跳路由」 |
| 4.3 传输链路 | 连接数优化、传输压缩、QUIC | 减少 RTT、复用连接、压缩载荷 |
| 4.4 内容分发网络 | 路由解析、内容分发、CDN 应用 | 把内容推到离用户最近，缩短物理距离 |
| 4.5 负载均衡 | 数据链路层(L2)/网络层(L3)/应用层(L7)、均衡策略 | 把流量摊到多实例，是横向扩展的关键 |
| 4.6 服务端缓存 | 缓存属性（命中率/失效/穿透/雪崩）、缓存风险 | 缓存是「以空间换时间」，但引入一致性风险 |

## 核心精讲

（以下为教学性梳理，示意均**教学示意，不参与构建**。）

### 4.1 客户端缓存：两道闸门

```text
# 教学示意，不参与构建
强制缓存:  Cache-Control: max-age=3600  -> 浏览器在 1h 内直接用本地副本，不发请求
协商缓存:  ETag: "v1"  -> 请求带 If-None-Match: "v1"，服务端 304 即「没变，用本地」
```

- 强制缓存连请求都省了；协商缓存省的是**传输体**，但仍有一次 RTT。两者结合是前端性能第一杠杆。

### 4.3 传输链路：QUIC 是 2021 后的关键变量

- 传统 HTTPS over TCP：建连要 1–3 个 RTT，队头阻塞（一个丢包堵住整条流）。
- **QUIC（RFC 9000，2021）**基于 UDP，0-RTT/1-RTT 建连、流级多路复用、内建加密，
  把「传输层」重新设计了一遍。本书 4.3.3「快速 UDP 网络连接」写的正是它。

### 4.5 负载均衡：三层打法

| 层级 | 代表 | 依据 | 特点 |
| --- | --- | --- | --- |
| L2/L3 | LVS/IPVS、硬件 F5 | MAC/IP | 极快、无应用感知 |
| L4 | LVS、HAProxy(TCP) | IP+端口 | 能按连接分流 |
| L7 | Nginx、Envoy、APISIX | URL/Header/Cookie | 能按内容路由，最灵活 |

- **均衡策略**：轮询、加权、最少连接、一致性哈希（会话保持）、地域就近。

### 4.6 服务端缓存：收益与三类事故

- 收益：命中即免 DB，延迟从 ms 降到 μs。
- 风险：**穿透**（查不存在的 key）、**击穿**（热点 key 失效瞬间打爆）、**雪崩**（大批 key 同时失效）。
  对策分别是空值缓存/布隆过滤器、互斥重建、错峰过期。

## 版本演进

- **本书无第二版**；本节写 2021 年口径 → 2026 年视角的变化。
- **HTTP/3 + QUIC 已落地**：本书 4.3.3 写于 QUIC 标准化（RFC 9000，2021）前后，2026 年主流浏览器与 CDN 已默认 HTTP/3。
- **边缘计算（Edge）把多级分流推到网络边缘**：CDN 厂商进化成「边缘函数（Edge Functions）」平台，本书 4.4 的 CDN 仅是静态分发，需补边缘计算。
- **服务网格接管 L7 分流**：Envoy/Sidecar 在应用层做精细路由（见 [15-服务网格.md](15-服务网格.md)），与 4.5 L7 负载均衡边界模糊化。
- **eBPF 加速负载均衡与可观测**：Cilium 等用 eBPF 在更底层做 LB（🔧 见 [12-容器间网络.md](12-容器间网络.md)）。

## 近年研究与工业界开源实践（2015–2026）

- **反向代理 / 网关 / L7 LB**：`nginx/nginx`（31736★，2026-09-27 实测）是事实标准；`haproxy/haproxy`（6876★）长于高并发 L4/L7；`apache/apisix`（17167★）是云原生 API 网关；
  `envoyproxy/envoy`（28995★）是服务网格数据平面（见第 15 章）。
- **服务端缓存**：`redis/redis`（76487★）是分布式缓存事实标准；Varnish 是经典 HTTP 加速器（star 数未能核实，未杜撰）。
- **边缘/CDN**：Cloudflare、Akamai、Fastly 等为商业代表；Fastly 的 Lucet/Wasm 边缘运行时与后来 V8 isolate 思路相关（🔧 见第 15 章 WASM 补丁）。
- **QUIC/HTTP3**：`nginx` 与 `envoy` 均已支持 HTTP/3；`curl`、`chromium` 默认启用。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「缓存加了就一定快」 | 命中率、失效策略、穿透/雪崩才是关键，盲目加缓存反而拖垮后端 |
| 2 | 「负载均衡就是轮询」 | 轮询只是最粗策略；一致性哈希保会话、最少连接保热点均衡，需按场景选 |
| 3 | 「HTTPS 必然慢」 | TLS1.3 + 会话复用 + QUIC 已把握手成本压到极低 |
| 4 | 「CDN 只加速静态资源」 | 现代 CDN 已演进为边缘计算平台（函数/KV/流处理） |
| 5 | 🔧 4.3 缺 HTTP/3 全面落地 | RFC 9000(2021) 后 HTTP/3 已成主流，本书写于过渡期 |
| 6 | 🔧 4.4 缺边缘计算 | 边缘函数/边缘 KV 把分流逻辑下沉到网络边缘，超出 2021 视野 |
| 7 | 🔧 4.5 与服务网格 LB 边界模糊 | 本章 L7 LB 与第 15 章 Sidecar 路由高度重叠，需统一视角 |
