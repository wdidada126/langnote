# 第 5 章　架构安全性

> 原书第 5 章是架构师视角的「安全基线」：认证（你是谁）、授权（你能干啥）、凭证（凭什么信你）、
> 保密（数据别被偷看）、传输（链路别被窃听/篡改）、验证（提交的数据别是毒药）。
> 这一章把安全拆解成六个可工程化的环节，是后面第 9 章「零信任网络」的理论与标准底座。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 5.1 认证 | 认证标准（Kerberos/OAuth/OIDC）、认证实现 | 先解决「证明身份」，是安全链条第一环 |
| 5.1.1 认证的标准 | 口令/多因子、SAML、OAuth2、OIDC | 标准决定互操作；OIDC 是今日的身份层事实标准 |
| 5.1.2 认证的实现 | 服务端校验、多因子、WebAuthn/Passkey | 实现要防重放、防暴力 |
| 5.2 授权 | RBAC、OAuth 2 | 认证之后，按策略决定「能做什么」 |
| 5.2.1 RBAC | 角色-权限模型 | 用角色中介用户与权限，降低管理复杂度 |
| 5.2.2 OAuth 2 | 授权框架（四种授权模式） | 让第三方「受限地」代表用户访问资源 |
| 5.3 凭证 | Cookie-Session、JWT | 会话状态的两种承载方式 |
| 5.3.1 Cookie-Session | 服务端存状态、Cookie 持 ID | 服务端可控、易吊销；需集中存储 |
| 5.3.2 JWT | 自包含令牌（签名、可过期） | 无状态、易横向扩展；但吊销难 |
| 5.4 保密 | 保密强度、客户端加密、密码存储与验证 | 敏感数据别明文，密码用慢哈希 |
| 5.5 传输 | 摘要/加密/签名、数字证书、传输安全层（TLS） | 链路层防窃听/篡改/伪装 |
| 5.6 验证 | 输入校验、防注入、防越权 | 不可信输入一律当作攻击 |

## 核心精讲

（以下为教学性梳理，示意均**教学示意，不参与构建**。）

### 5.1–5.2 认证与授权的分工

```text
# 教学示意，不参与构建
认证(Authentication): 你是谁？   -> 用户名+口令 / Passkey / OIDC IdP 签发身份断言
授权(Authorization):  你能干啥？ -> RBAC(角色=权限集合) / OAuth2 scope(令牌携带可访问范围)
```

- 常见混淆：**认证≠授权**。拿到身份证（认证）不代表能进金库（授权）。

### 5.3 凭证：Cookie-Session vs JWT

| 维度 | Cookie-Session | JWT |
| --- | --- | --- |
| 状态 | 服务端有状态 | 客户端自包含、无状态 |
| 吊销 | 删服务端会话即可 | 需短过期 + 黑名单/刷新令牌 |
| 扩展 | 需共享会话存储（Redis） | 天然横向扩展 |
| 风险 | Session 劫持 | 令牌被盗即用（直到过期） |

### 5.4 保密：密码永远不存明文

- 存储用**慢哈希 + 盐**：bcrypt / scrypt / Argon2，目的是让暴力破解成本极高。
- 验证时比对哈希，永不明文比较。

### 5.5 传输：TLS 是底线

- 摘要（完整性）、加密（机密性）、签名（不可否认）三件套；
- **TLS 1.3（RFC 8446，2018）**把握手压到 1-RTT、移除不安全套件；HSTS 强制 HTTPS。

## 版本演进

- **本书无第二版**；本节写 2021 年口径 → 2026 年视角的变化。
- **Passkey / WebAuthn 取代口令**：本书 5.1.2 仍以口令为主，2026 年 Passkey（FIDO2/WebAuthn）已成主流无口令方案。
- **OAuth 2.1 整合**：把 Implicit 流移除、统一 PKCE，本书 5.2.2 的四种模式需更新为 2.1 视角。
- **零信任从理念到落地**：NIST SP 800-207（2020）后，SPIFFE/SPIRE、mTLS 成为服务间身份标准，与第 9 章衔接更紧（🔧 见 [09-可靠通信.md](09-可靠通信.md)）。
- **机密计算（Confidential Computing）/Enclave**：把保密从「传输中/静态」延伸到「使用中」，本书 5.4 未及。
- **Post-Quantum 加密**：NIST 2024 年 standardized 后量子算法，长期视角需评估 TLS 套件迁移。

## 近年研究与工业界开源实践（2015–2026）

- **密钥与凭证管理**：`hashicorp/vault`（36300★，2026-09-27 实测）是动态密钥/加密即服务的事实标准；
- **授权策略引擎**：`open-policy-agent/opa`（12275★）用 Rego 做统一策略决策；`open-policy-agent/gatekeeper`（4282★）把 OPA 接入 K8s 准入控制；
- **证书自动化**：`cert-manager/cert-manager`（14091★）是 K8s 内 TLS 证书自动签发/轮换的事实标准（对接 Let's Encrypt）；
- **服务身份/零信任**：`spiffe/spire`（2558★）签发工作负载身份（SPIFFE ID + SVID），是第 9 章零信任的落地基座；
- **身份提供方**：Keycloak（Red Hat 开源 IdP，支持 OIDC/OAuth2/SAML，star 数未能核实，未杜撰）是本章 5.1/5.2 的常用工程实现。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「认证=授权」 | 二者正交：认证证明身份，授权决定权限 |
| 2 | 「JWT 比 Session 更安全」 | 只是状态模型不同；JWT 难吊销，泄露即滥用直到过期 |
| 3 | 「密码加密存储」 | 密码用**哈希+盐**（不可逆），不是加密（可逆） |
| 4 | 「HTTPS 就绝对安全」 | TLS 防链路窃听，不防应用层越权/注入，需配合 5.6 验证 |
| 5 | 🔧 5.1.2 缺 Passkey/WebAuthn | 无口令（FIDO2）已成主流，口令时代正在落幕 |
| 6 | 🔧 5.2.2 缺 OAuth 2.1 与 PKCE | Implicit 流已被弃用，公客户端强制 PKCE |
| 7 | 🔧 5.4 缺机密计算 | 「使用中加密」(Enclave) 是新边界，超出 2021 视野 |
| 8 | 🔧 5.5 缺后量子加密迁移 | NIST 后量子标准(2024) 推动 TLS 套件长期迁移 |
