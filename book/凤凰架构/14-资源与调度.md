# 第 14 章　资源与调度

> 原书第 14 章讲容器之上「如何把资源分配给工作负载」：资源模型（请求/限制）、QoS 与优先级、
> 驱逐机制、默认调度器。这是「不可变基础设施」真正运转起来的调度大脑——没有它，容器只是散兵。

## 本章地图

| 节 | 内容 | 结论 |
| --- | --- | --- |
| 14.1 资源模型 | request/limit、CPU/内存单位 | 用声明式约束让调度器「量体裁衣」 |
| 14.2 服务质量与优先级 | QoS 三档、PriorityClass | 资源紧张时保谁弃谁，由 QoS/优先级决定 |
| 14.3 驱逐机制 | 节点压力驱逐、Pod 驱逐 | 节点资源告急时按 QoS 有序回收 |
| 14.4 默认调度器 | 过滤(预选)+打分(优选)、扩展点 | 把 Pod 放到「最合适」的节点 |

## 核心精讲

（以下为教学性梳理，示意均**教学示意，不参与构建**。）

### 14.1 资源模型：request 与 limit 不是一回事

```text
# 教学示意，不参与构建
resources:
  requests: { cpu: "250m", memory: "256Mi" }   # 调度依据：保证至少分到这么多
  limits:   { cpu: "500m", memory: "512Mi" }   # 运行上限：超 CPU 被 throttle，超内存被 OOMKill
```

- **request 影响调度**（够不够放得下），**limit 影响运行**（会不会被限流/杀掉）。两者设错会要么浪费要么频繁 OOM。

### 14.2 QoS 三档（决定「先杀谁」）

| QoS | 条件 | 驱逐优先级 |
| --- | --- | --- |
| Guaranteed | request==limit（CPU 与内存都配齐） | 最后被驱逐 |
| Burstable | 部分配 request/limit | 中间 |
| BestEffort | 全不配 | 最先被驱逐 |

- 关键结论：**想稳，就配成 Guaranteed**；可牺牲的批处理就放 BestEffort 占空闲资源。

### 14.4 默认调度器：预选 + 优选

- **预选（Filter）**：剔除不满足约束的节点（资源够吗？亲和性满足吗？）；
- **优选（Score）**：对剩余节点打分（资源均衡、亲和/反亲和、拓扑分散）；
- 二者之外还有**绑定（Bind）**。整套是插件化框架，可自定义。

## 版本演进

- **本书无第二版**；本节写 2021 年口径 → 2026 年视角的变化。
- **调度器框架（Scheduling Framework）成熟**：本书 14.4 写于插件化早期，2026 年调度已是「多扩展点（Filter/Score/Reserve/Permit…）」的框架，插件生态完备。
- **🔧 批处理/AI 调度**：`volcano-sh/volcano`（批调度，star 未单独实测）与 `kubernetes-sigs/kueue`（队列配额，star 未单独实测）解决 AI/大数据训练的 Gang 调度、队列管理，本书 14.4 仅覆盖在线服务调度。
- **🔧 异构/GPU 调度**：GPU、NPU、拓扑感知（NUMA）、设备插件成为常态，超出本书通用资源模型。
- **🔧 FinOps / 成本治理**：调度开始纳入成本维度（Spot/抢占、bin-packing 降本），与第 16 章方法论呼应，本书 14.x 纯技术无成本视角。
- **🔧 弹性伸缩体系**：HPA（指标）/VPA（垂直）/CA（节点扩缩）/KEDA（事件驱动）组合成熟，调度延伸到「动态容量」。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「request 和 limit 一样」 | request 管调度、limit 管运行，语义不同 |
| 2 | 「不设 limit 更自由」 | 不设 limit 易成 BestEffort，出事最先被杀 |
| 3 | 「调度器只放得下就行」 | 优选决定均衡与故障域分散，影响可用性与成本 |
| 4 | 「节点满了才驱逐」 | 基于 QoS 的软/硬驱逐阈值早于真正耗尽即触发 |
| 5 | 🔧 14.4 缺调度框架扩展点 | 2026 调度是插件化框架，本书仅概述预选优选 |
| 6 | 🔧 缺批处理/AI 调度 | Volcano/Kueue 解决 Gang 调度，超出在线服务 |
| 7 | 🔧 缺异构/GPU 调度 | 设备插件与拓扑感知已成常态 |
| 8 | 🔧 缺 FinOps/成本治理视角 | 调度应纳入成本，与第 16 章方法论结合 |
