# 08 · 功能设计（原书 Ch10 Functional design pp.107-123，DOI 尾号 .00010-1 ✅；正文 ⚠️ 精读重构）

> 工序 5。功能设计回答"治理程序对外提供什么服务、按什么流程交付"——它是 09 章组织设计的**需求方**（先定服务再配权力），也是 12 章工具选型的**规格书来源**（工具需求从流程里长出来，不是反过来）。

## 8.1 服务的四条主流程（⚠️ 重构骨架）

治理程序对全企业的"服务目录"（本目录用语）：
1. **口径裁决**：定义/术语/指标冲突的受理-审理-裁定-发布闭环；输出裁定书（进决策日志，🔧E2 语义在 11 章）。
2. **变更审批**：数据标准/关键模型/分类分级的变更通道；与工程变更流程的接口位写死（谁在谁之前、并行还是串行）。
3. **例外豁免**：申请-限期-复审-公开登记；豁免登记簿是程序诚实性的物证（无豁免通道的审批流程必然催生绕行，02 章 2.5 的流程版答案）。
4. **问题升级**：一线质量问题（数据缺陷工单）向裁决与标准修订的上升路径；与 [../数据清洗.md](../数据清洗.md) 的执行面分界——清洗修数据，本流程修"让数据坏掉的规则"。
第五条服务线（2026 新增，见演进节）：生成用数授权与退出。

## 8.2 文档塔的程序化：政策-标准-规程如何流转

概念分层与 #189 谱系 04 章同构（实链 [../Understanding_Data_Governance/04-政策标准与规程.md](../Understanding_Data_Governance/04-政策标准与规程.md)，本册不重复论证）；本章的施工视角（⚠️ 重构）：
- **起草回路**：标准由 steward 起草→委员会批准→**随发布列车生效**（挂 07 章班车效应）→复审到期触发重批。每份政策带四个元字段：生效窗、复审期、责任人署名、执行器落点（无落点不生效——此条将 #189 谱系 02 章判例三"无落点政策退休"落为流程设计）。
- **术语表运营**：单源发布+别名登记（业务侧允许的私有别名与报表侧禁入的边界，即 06 章某反例的流程实现）。
- **版本纪律**：政策变更走新版本行不改历史（🔧E1 时窗语义在文档塔的直用，实验详表见 09 章）。

## 8.3 标准与建模的接口

数据标准落地最终表现为模型约束——本章功能设计需向建模职能交付"标准到约束"的映射规约（⚠️ 重构要点）：命名/码值/域完整性/业务规则四类标准各有归属层（逻辑模型/物理 DDL/校验规则/应用层）。盘上对读：[../Data_Model_Patterns/00-总览与阅读地图.md](../Data_Model_Patterns/00-总览与阅读地图.md)（合同/事件类模式的标准化承载）、[../Database_Modeling_and_Design_5e/00-总览与阅读地图.md](../Database_Modeling_and_Design_5e/00-总览与阅读地图.md)（规范化与约束表达）。治理不替建模做设计决策，治理**规定设计决策记录在哪、由谁批准、如何被引用**——此句是功能设计与数据管理的分界定义（回 01 章 1.3）。

## 8.4 元数据与血缘的采集需求（向 12 章工具递交规格书)

⚠️ 重构：裁决流程要能调证据，由此反推采集规格：
- 谁改的、谁批的、依据哪版标准 → 操作元数据+决策日志（E2 的字段设计输入）。
- 口径影响面 → 血缘查询能力（"改这个字段要通知谁"=血缘册的影响分析场景，实链 [../数据血缘分析原理与实践.md](../数据血缘分析原理与实践.md)）。
- 术语到物理列的引用链 → 业务-技术元数据映射（目录册功能位，工具锚 [../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md](../The_Enterprise_Data_Catalog_2e/00-总览与阅读地图.md)）。
需求评审判据：每条采集需求必须能说出"哪道流程的哪个环节消费它"——说不出即库存式采集（2012 年元数据仓库高坟场，12 章再论）。

## 8.5 服务级承诺：治理程序的自我 SLA

功能设计区别于制度汇编的关键件（⚠️ 重构立场）：程序对外承诺时限——裁决受理 N 日内排审、裁定 M 日内送达、豁免申请 K 日答复（数值由 05 章基线+消化力预算定，⚠️ 不设通用推荐值）。无 SLA 的治理服务=官僚环节（02 章治理税质疑的自证）；SLA 违约统计同时是 07 章效率账的成本侧科目（对称记账）。

## 8.6 安全与合规流程的借道与分立

访问审批/分级分类的**权力与执行**归安全体系（盘上对位 [../数据安全架构设计与实战.md](../数据安全架构设计与实战.md) 的分级与安委会叙事，⚠️ 转述），治理程序分立持有：**分级标准本身的裁决权**与例外豁免登记。两体系接口=标准单源（治理发布）+执行单轨（安全落地）+事件互通（越权案例反哺标准修订）。混同（治理自建权限系统或安全自改分级口径）是双头事故高发源（06 章多头体的流程投影）。

## 8.7 判例两则（⚠️ 教学重构）

- **豁免登记簿救审计**：某制造商标准强推遇三系统豁免申请，全部限期登记并公开；外部审计以登记簿为抽样框，三笔豁免均有复审记录——"诚实的例外"比"纸面的 100% 合规"得分高（8.1-3 防腐物证）。
- **库存式采集坟场**：某行元数据平台按"全量采集"立项，两年采了 40 万条技术元数据，裁决流程一条都调不到（无消费环节设计，8.4 判据缺席）；工具预算续期失败，功能设计补课重来——**先流程后采集**的十年老坑，2026 年换了名字（"目录先建后治理"）继续有人跳。

## 8.8 自检问答

1. 问：四主流程各输出什么物证？——答：裁定书/审批记录/豁免登记簿/升级工单链（8.1）。
2. 问：政策四元字段？——答：生效窗、复审期、责任人、执行器落点（8.2）。
3. 问：治理与建模的分界句？——答：治理不替设计决策，规定决策记录在哪、谁批、如何被引用（8.3）。
4. 问：采集需求评审判据？——答：能指到消费流程的具体环节（8.4）。
5. 问：SLA 违约统计的双重身份？——答：服务诚实性证据+效率账成本科目（8.5）。

## 8.10 四流程泳道一览（⚠️ 教学重构文字泳道）

```
口径裁决：申请人(任意) → 程序办(受理/编号/定审期) → steward初审(案卷代拟)
        → 办公会/委员会(终裁,依生效版原则条款) → 裁定书发布(进日志) → 术语表/标准更新
变更审批：工程变更单 → 影响面查询(血缘,8.4) → 标准符合性检查 → 批准/驳回(带条款引用)
        → 发布列车生效(07 章班车) → 后评估登记
例外豁免：申请(理由+成本+期限) → steward建议 → 办公会批(限期) → 豁免登记簿(公开)
        → 到期复审(续批/整改令) → 归档为案例教材(11.3)
问题升级：缺陷工单(一线/清洗) → 根因判定(是否规则性) → 规则性问题转标准修订提案
        → 进入变更审批流 → 结案回写质量账(7.10 指标注册表消费位)
```
读法：**四线在"程序办受理编号"处共用同一工单宇宙**，在"裁定书/登记簿"处共用同一日志存储（E2）——流程分立、账本统一是功能设计的合流点；四线各自断点（无复审/无归档/无回写）即 11.6 大修对象。

## 8.11 常见误读与澄清

| 误读 | 澄清 |
|---|---|
| "流程越多治理越细" | 四线是完备集：新增流程先问并入哪条主线（流程通胀=税负增生，2.5） |
| "SLA 数值照抄行业模板" | 数值必须来自本组织 05 基线与消化力预算（8.5） |
| "豁免批了就是漏洞" | 无豁免通道必然绕行（8.1-3）；批得诚实的豁免是通道活性证明 |
| "治理流程上 OA 即完成" | 无执行器落点字段=纸流程（8.2）；OA 是载体不是落点 |
| "与安全体系合并成一个委员会省事" | 分立接口设计（8.6）；合并=双头事故的制度化预制件 |

## 核心概念速览（中英对照）

- **服务目录** — Service Catalog：治理程序对外交付的裁决/审批/豁免/升级流程集（本目录框架词）。
- **口径裁决** — Adjudication：定义冲突的受理-审理-裁定-发布闭环。
- **豁免登记簿** — Waiver Register：限期例外的公开登记，程序诚实性物证。
- **上升路径** — Escalation Path：数据缺陷工单向标准修订转化的通道。
- **执行器落点** — Enforcement Anchor：政策指定的机器或流程执行位置，无落点不生效。
- **消费判据** — Consumption Test：元数据采集需求必须挂钩流程环节的立项纪律。
- **治理 SLA** — Governance Service Levels：程序对裁决/豁免时限的对外承诺。
- **双头事故** — Dual-Head Incident：治理与安全就同一标准各自行使权力的失控形态。

## 最新演进与工业实践

- **第五条服务线的法定化**：EU AI Act（✅ https://eur-lex.europa.eu/eli/reg/2024/1689/oj）高风险系统的"数据治理与管理"义务使**训练/验证/测试数据的采集授权、清洗规程与偏见检测**成为需流程承接的新服务线（⚠️ 条文的工程化转述）；GDPR 删除权（✅ https://gdpr-info.eu/art-17-gdpr/）则要求"退出"流程跨副本/备份/派生数据集可执行——血缘册的影响分析（实链 [../数据血缘分析原理与实践.md](../数据血缘分析原理与实践.md)）从效率工具升为合规执行器。
- **政策即数据→即代码的两级跳**：政策四元字段在 2026 年可直接映射为目录/引擎侧的机器可读策略标签（policy-as-code；机制实链 [../Data_Mesh/05-联邦计算治理原则.md](../Data_Mesh/05-联邦计算治理原则.md)）；"执行器落点"由概念约定变为可编译字段——本册 8.2 的文档塔是这一跳转的纸面前身（⚠️ 史观判断）。
- **治理即 API**：裁决/豁免流程的平台形态是工单+审批工作流 API，与 CI 打通后豁免成为流水线的可审计旁路（⚠️ 生态通识；工具锚 EDC 册）。
- **湖仓 catalog 承接采集需求**：Open Table Format 统一 catalog 使"谁改的、依据哪版"类操作元数据在表事务层原生可得（盘上 Iceberg 线登记：波 1~3 已收官目录，本册仅名目对位不展开）。
- **SLA 度量入监管口径**：删除权响应时限（GDPR 一月框架 ⚠️ 条文级）等法定时钟使部分治理 SLA 脱离自治承诺、进入可罚范围（合规线互读 #189 谱系 08 章，实链）。
