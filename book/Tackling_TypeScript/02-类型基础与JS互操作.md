# 《Tackling TypeScript》段笔记 02 · 类型基础与 JS 互操作

> ⚠️ 段名凭记忆与站体例拟（骨架 Ⅱ：原始类型、对象、数组、函数 ✅ 出自 00 档）。00 档判语：本段与 Learning TS 重叠带「速过」——故本笔记不重讲语法，只记「已知 JS 事实 ↔ 类型层话术」的映射表与互操作坑位。

## 一、核心机制：基础类型带（面向 Java/C++/Kotlin 对照）

本段的真实读者收益：把写熟的 JS 直觉逐条翻译成类型层名词，并标出**哪些检查在运行时真实存在、哪些只是编译期话术**（一句话公理 ✅ 专题档）。

- **原始类型**：`number` 只有一个 double——对照 Java 数值塔（int/long/double 各有溢出语义）与 C++ int32/int64：整数安全上限 2^53-1，位运算截 32 位 ⚠️ 语言规范通识；`string`/`boolean` 之外，TS 世界有**两种缺失**（`null` 继承自 JS、`undefined` 管变量/属性缺席），对照 Kotlin 单一 `T?` 与 Java 的 null 一统——双缺失是互操作噪音首源。
- **strictNullChecks**：开/关是两个世界 ⚠️ 凭记忆与 tsconfig 文档口径——关闭时 null 可赋给一切类型，类型系统的「非空」城墙整体消失；Kotlin 读者应把该 flag 理解为「是否启用可空类型系统」，这是本段对 Java/C++ 者最陡的一根陡坡。
- **对象=结构匹配**：字段的有无与类型即身份，无类名参与——对照 Java/C++ 标称类、Kotlin interface（名义实现 `: Foo`）；新鲜字面量的多余属性检查是一次性礼仪 ⚠️ 记忆口径，经变量转手即失效——结构类型的宽容与陷阱同源于此。
- **数组与元组**：`T[]` 只是被注解的普通 Array，运行时零元素墙——对照 **Java 数组协变有 ArrayStoreException 真拦截（⚠️ 专题档 Java 列口径），TS 同类位置完全裸奔**（本会话实测 ✅：`Dog[]` 里塞进 string 无报错，崩在 `.breed.toUpperCase()`）；`[number, string]` 元组反而是类型层真产物（长度/索引类型受控，运行时仍是普通数组）。
- **函数**：参数/返回注解、可选参数 `?:`、剩余参数——形状即签名；`f.length` 只数 JS 形参 ✅ 专题实验 A（交集/联合注解不改变任何反射事实）。

## 二、JS 互操作：进入类型世界的四个门
以下四条的共同判据只有一条：**这条机制在运行时真实存在吗**——存在者（门 2）是防线，不存在者（门 1/3 的谎言面）是 05 章反例库的原料。
1. **any 入口**：JSON.parse、无类型三方 JS、DOM 旧签名——一个 any 即可把谎言运进任何注解（01 章传染链 ✅）；现代口径优先 `unknown` + 守卫收窄 ⚠️ 社区共识非逐字。
2. **运行时真实存活的检查**（擦除世界里的仅存者，本会话实测 ✅）：`typeof`、`Array.isArray`、`instanceof`（查的是 JS 原型链真实结构）、`in`（查键存在）——收窄语法借这些**原生运算符**生效；`x is Foo` 类型谓词函数本身编译后只是一个普通返回 boolean 的函数，谓词注解零痕迹 ✅ 专题口径。
3. **@types  ambient 声明**（详见 [04-工程与渐进迁移.md](04-工程与渐进迁移.md)）：类型与实现二重身，可能撒谎——声明文件说 `string` 而运行时给 `number`，编译器无从得知。
4. **`any` vs `unknown`**：二者运行时**完全同一**（都是被擦除的注解，值照原样流，本会话 any_json.ts ✅ 即证）；差异全在编译期门条——any 免检放行、unknown 强制先守卫再使用。选择 unknown 不买到任何运行时安全，只买到「逼你写守卫」的检查期纪律——又一处「TS 价值全在编译期」的落点（01 章裁决的工程微缩版）。

## 三、批判读法
- 本段是全书「最不值得精读」的段（00 档 ✅ 判语），但对 Java/C++ 者有一处不可替代：它示范**如何把类型注解当作对既有 JS 事实的文档**，而非新语言特性——注解不改变运行时（`f.length=1` ✅），改了直觉里的「声明即构造」。
- `number` 单类型对 Java/C++ 人是双刃：无溢出陷阱也无整型语义，货币/ID 场景须升 bigint 或约定 ⚠️；与 Kotlin `Int/Long` 名义区分对照，结构类型世界连「数值种类」都不表达。
- 双缺失（null/undefined）在 strict 下收敛为可教，但边界（DOM 事件、JSON）永远漏 undefined——非空断言 `!.` 是「我又撒谎一次」的专用工具（归 05 章反例库 ⚠️）。
- 「速过」的正确姿势：按上面三节做**勾选式查缺**——凡某条 JS 事实你早已凭直觉掌握（如 undefined 的三种来源），类型层词条可直接跳过；本段唯一必须精读的机制点是「哪些运算符在运行时真实存活」（第二节门 2），它是 03/05 全部收窄与守卫讨论的地基。
- 教学顺序的隐藏假设：Rauschmayer 以「先 JS 语义后类型话术」推进 ⚠️ 凭记忆与站体例——Java/C++ 转来的读者若 JS 语义本身欠账（原型链、this 绑定、属性枚举），应先补 Learning TS 再回本段，否则映射表两栏都悬空。

## 四、🔧 微实验（本会话 node v22.14 --experimental-strip-types 真跑）
- `guard.ts` ✅：unknown 入参经 `typeof === "number"` / `Array.isArray` / `"kind" in u` 三层守卫各归其位——守卫的「实」在 JS 运算符，不在类型层；`null` 落入 other 分支证明 `typeof null === "object"` 的历史包袱仍由你背着。
- `covar.ts` ✅：`Dog[]` 经 `as unknown as unknown[]` 塞入字符串，`JSON.stringify` 照单全收，`.map` 崩——数组元素类型无运行时墙（对照 Java 列 ArrayStoreException ⚠️ 书目口径）。
- 引用专题实验 A ✅：`type/interface/implements` 零痕迹、`private` 字段在 keys、`f.length=1`。
- 复演口径备注：以上均为**运行时裸奔面**实测；本段所有「类型报错面」论断（strict 开关差异、可选参数检查）无独立 tsc 不可测，一律 ⚠️ 存目（专题档第五节同款欠账）。
