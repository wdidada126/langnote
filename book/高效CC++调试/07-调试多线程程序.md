## 核心概念速览（中英对照）

- **竞争条件** — race condition：程序正确性依赖多线程交错的**时机**；数据竞争是其最常见子类
- **数据竞争** — data race：两个线程非同步地访问同一内存位置且至少一写——C++ 内存模型下的未定义行为
- **锁集分析** — lockset analysis（FIO 算法）：TSan 判定「无公共锁保护的并发读写对」的理论基础
- ** happens-before** — happens-before：时序偏序；「看起来有序」≠「有保证有序」，fence/atomic 才建立边
- **死锁** — deadlock：循环等待锁；四条件（互斥/持有并等待/不可剥夺/循环等待）破其一即解
- **活锁/优先级反转** — livelock / priority inversion：不死但不动；忙等与调度介入的两大隐疾
- **线程交错** — thread interleaving：一次具体的指令时序排列；压测=采样交错空间
- **确定性回放** — deterministic replay：录制全部非确定性输入（syscall 返回值、时钟、线程调度决策）后离线重演——rr 与 WinDbg TTD 的共同原理
- **thread apply all** — GDB 全线程命令：对每个线程执行 `bt` 等命令，死锁取证第一步
- **无锁区记录** — record critical regions（7.4 故事）：竞态无法单步时，改为「事后审计」——给关键区加时间戳日志再比对交错

## 1. 动机：单步调试器是「按暂停看照片」，竞态是「电影」

调试器暂停=全线程停止（或指定 all-stop/non-stop 模式），这恰好摧毁竞态的发生条件——
[03 篇](03-内存损坏.md) 已给实测：同一无同步计数程序，**-O0 三连错**（1074548 / 1506840 / 1231216，期望
2000000），**-O2 三连「对」**（2000000）。两个变量同时说明：竞态与优化都独立地操纵「可见性」。
多线程排障的第一问不是「哪个线程错了」，而是「**这到底是竞态、还是逻辑/内存问题？**」（7.2）。

## 2. 机制

### 2.1 「它是竞争条件吗」的鉴别流程（7.2）

1. **降维**：单线程化（并发度=1、顺序喂相同数据）还能复现 → 不是竞态，回 [03 篇](03-内存损坏.md)；
2. **扰动**：人为改交错（usleep/切换点注入/调线程亲和性）后现象随扰动移动 → 强竞态信号；
3. **形态**：值错乱但结构完整、错误位置漂移、崩溃在随机分配器调用里（对照 02 篇元数据路径）；
4. **检测器**：TSan 一击定案（机制=锁集+向量时钟，报告给的是「可能造成竞争的访问对」，
   即使本次交错未出错——这是它比压测强的地方）。

### 2.2 调试竞争条件的工具箱（7.3）

- **压测+扰动**：`taskset`、`sched_yield`、随机睡眠——廉价但覆盖随机；
- **关键区日志（7.4 故事「记录重要区域」）**：给共享对象的每次变更打「线程 id+序号+时间戳」环形缓冲，
  事后重建交错。本质是把竞态问题降维成**日志分析**问题——与 8.1「重现错误」互为表里；
- **watchpoint 跨线程版**：GDB `watch var` + `schedule-multiple`/non-stop 模式能抓「谁写的」，但全停语义
  仍然改变交错，适合**低频**损坏（一次写坏永久坏）不适合高频竞态；
- **TSan / rr / TTD**：见「最新演进」。

### 2.3 死锁（7.5）

取证三步（gdb 现场，🔧 **已实测**——本机 GDB 17.1 + Windows 目标，对 race 演示程序
`info threads`/`thread apply all bt 3` 工作正常；顺带可见 Windows 线程栈顶是
`ntdll!ZwWaitForWorkViaWorkerFactory` 这类线程池等待帧）：

```text
(gdb) info threads                    # 线程清单与当前栈顶
(gdb) thread apply all bt 5           # 全线程栈摘要 → 人手一张「等锁图」
(gdb) p *mutex                        # glibc: __data.__owner = 持有者 tid → 构建 wait-for 图找环
```

Windows/MSVC 栈：WinDbg `!lock`（自动找环）与 `~*k`；VS 附加工具：并行监视器+死锁中断（IntelliTrace
时代遗留能力）。判环要点：持有并等待的「持有」侧要同时看——两线程各持一把、互等对方手里那把，
才是经典 AB-BA；单看等待侧只是阻塞不是死锁。

**预防侧**（书内+演进合并）：锁层次（lock level 注解/`-Wthread-safety`，clang 独有）、
`std::scoped_lock(m1,m2)`（C++17 死锁避免算法）、RAII 锁（理论纵深见
[../C++并发编程实战2/00-总览与阅读地图.md](../C++并发编程实战2/00-总览与阅读地图.md)）。

### 2.4 竞态复现的强化配置清单

把「1% 概率」推到「几乎必然」的可操作组合（全部适用于 Linux；Windows 侧除 taskset 外多数可用
或已有对位）：

1. **放大临界区**：嫌疑区两侧插 `usleep(1)`/`sched_yield()`，拉开窗口而不是消除它；
2. **制造竞争热度**：把无关但同锁的第三线程加进来，改变交错分布；
3. **绑核与调频**：`taskset -c 0,1` 收进同一 cache 域复现伪共享类问题，或分到双核复现真并行；
4. **压力注入**：`stress-ng --cpu 8` 抬调度噪声，让低优先级路径被抢占；
5. **GDB 侧**：`set non-stop on` + `schedule-multiple` 只停肇事线程，部分恢复「边跑边看」的观测能力
   （all-stop 默认全停，这正是它喂大 Heisenbug 的原因）；
6. **终局手段**：以上皆无效→ 转记录-回放（rr/TTD），用无限次回放换确定性。

清单的排序即成本排序：改代码 < 改环境 < 换观测模式 < 换工具链——与 [08 篇](08-调试方法论与复现.md)
「假设-实验循环」的最廉价可证伪实验原则一致。

## 3. 权衡

- **TSan 成本模型**：约 5–15× 运行时、2–10× 内存，且只报**实际执行到的**交错——适合全量回归不适合作
  生产守护；压测适合「已知疑点」放大但不保证抓到。
- **原子化 vs 锁**：把共享改 `std::atomic` 消除的是数据竞争；**不变量跨多字段时 atomic 保不了**（
  两个各自原子的写=一个可撕裂的更新）——需要 seq_cst 域或事务性包装。
- **记录-回放 vs 传统调试**：rr/TTD 给出「任意时刻任意线程」的时间机器，代价是平台绑定（见下节）与
  录制体积；常规 bug 用断点仍更轻。

## 4. 相邻概念对比

- **数据竞争 vs 竞争条件**：后者是前者超集？相反——竞态可不含数据竞争（两个「各自安全」的操作
  时序错误，如 check-then-act），数据竞争在 C++ 标准里直接 UB。TSan 抓数据竞争；
  纯竞态（如两队列互相转发造成 ping-pong 活锁）靠时序断言。
- **竞态 vs 内存损坏**：判据（本仓库统一）：单线程化仍复现→损坏/逻辑；只有并发复现→竞态；
  崩溃进分配器两种可能都有，先看是否「确定性地址」。
- **死锁 vs 活锁 vs 饥饿**：三者都「不动」；dump 全部线程栈：阻塞在不同锁=死锁候选，忙转=活锁，
  只有受害者「不动」其余欢跑=饥饿/优先级反转。

## 最新演进与工业实践

- **TSan（Google）**：Serebryany & Iskhodzhanov, *ThreadSanitizer: Design of an LLVM-Instruction-Based
  Lockset Analyzer*, CGO 2009（会议+年份通行记载；Crossref 未检索到 DOI ⚠️ 已实测查询未果）。
  平台：Linux/macOS；**MinGW-w64 不提供**；MSVC `/fsanitize=thread` 自 VS2022 17.x 提供
  （docs `learn.microsoft.com/cpp/build/reference/fsanitize` 实测可达；具体版本号 ⚠️ 未细核）。
- **rr（mozilla/rr）**：Linux/x86-64 专用；`rr record ./prog && rr replay`，回放中反向 continue、
  时间旅行断点、gdb 全命令面。把「竞态只在 1% 交错出现」变成「一次录制无限回放」——
  本书 8.4.1 的 rr 在 2026 年的成熟度远超成书时（支持 Python 脚本化、`rr ps`、容器内记录）。
- **WinDbg TTD**：Windows 原生时间旅行（1703+），`ttd -r` 录制/回放，监控视图自动比对「该变量何时被改」，
  UI 级「反向调试」（learn.microsoft.com 文档实测可达 HTTP 200）。与 rr 的取舍=平台+开销（TTD 更重）。
- **Replay debugging SaaS**：Undo LiveReplay/rrweb 类商业录制进入 CI 的探索 ⚠️ 前沿观察，不展开。
- **前移**：`-Wthread-safety`（clang）注解锁层次；Rust `Send/Sync` 证明「不传共享」在编译期——
  C++ 侧最接近的是 TSan 进 CI+静态数据竞争检测（clang-tidy `concurrency-*` ⚠️ 规则成熟度一般）。
- **开源仓库逐点对应**：`llvm/llvm-project` compiler-rt/tsan（锁集实现）、`mozilla/rr`（调度决策录制）、
  `google/sanitizers`（issue 样例库，竞态样本信手拈来）、`gdb`（non-stop / `schedule-multiple`）。
- **并发纵深**：内存序/无锁结构的「为什么」请去 [../C++并发编程实战2/00-总览与阅读地图.md](../C++并发编程实战2/00-总览与阅读地图.md)；
  本章只解决「怎么发现它坏了」。
