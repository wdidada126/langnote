## 核心概念速览（中英对照）

- **内存泄漏** — memory leak：分配后失去全部引用而程序未死；「无引用」判定=水平搜索（04 篇）的应用场景
- **RAII** — Resource Acquisition Is Initialization：以对象生命期拥有资源；泄漏防治的第一基石（14.1）
- **伪泄漏** — pseudo-leak/retained memory：设计上常驻的池/缓存/写时复制，被监控误报——14.2「分析」的重点
- **协程帧** — coroutine frame：挂起点间的局部状态被搬到堆上帧对象——调试器断链的根源（15.1）
- **挂起点** — suspension point（15.2「切分点」）：co_await/co_yield 处；「函数没有返回却不再执行」的新形态
- **promise 类型** — promise type（15.3「协程之诺」）：协程与框架的契约层；unhandled_exception/return_value 钩子
- **gdbserver / gdb-remote** — 远程桩协议：目标机跑精简 stub，开发机全量 GDB；`target remote :1234`
- **VS 远程调试** — msvsmon：Windows 远程调试器监视进程，与 16.2 对应（操作版在其书第 7 章）
- **容器调试** — container debugging：PID/挂载/权限视角收窄的进程；`kubectl debug` 临时调试容器、
  ephemeral container 注入工具
- **CrashLoopBackOff** — K8s 崩溃循环（故事10）：探针失败/启动即崩时的事件循环；取证=上一实例日志+core 持久化
- **liveness failure** — 存活探针失败（故事11）：进程活着但不响应——死锁/暂停过长被平台「误杀」的现场
- **左移** — shift left（第 18 章主旨）：把发现错误的时点从运行推向编译/评审/CI——「尽量不要调试」的工程学
- **PE / Minidump（附录 B）** — Windows 侧镜像与现场容器：与第 6 章 ELF/core 一一互译
- **JNI 混合调试** — mixed-mode debugging（附录 A）：Java 帧与 C++ 帧跨语言回溯，两套栈两套符号

## 1. 动机：后五章是调试的「场景与出口」

14–17 章给四个具体场景（泄漏、协程、远程、容器），18 章收束全书立场：**最好的调试是不需要调试**。
附录则是平台与语言的两侧翼（Windows 镜像、混合语言）。

## 2. 机制要点

### 2.1 内存泄漏（第 14 章）

- **判定链**：监控曲线（14.2 分析先行：区分真泄漏/伪泄漏/正常增长）→ LSan/ASan 的 leak 报告
  （按分配栈聚合）→ 无法重编时拿两份 core 做「对象集差」（11 章 Core Analyzer 水平搜索：
  「这次还在、且无任何引用」者即候选）；
- **RAII 为什么是基石**（14.1）：泄漏=「忘记还」，RAII 把「还」编译进析构；残留泄漏集中在
  环引用（weak_ptr 破环）、裸 new 进容器、跨模块所有权交接三处；
- **循环内的慢性泄漏**：每小时 1KB 比启动即崩更难——趋势监控+定期快照 diff 是唯一现实手段。

### 2.2 协程（第 15 章）

调试断裂点与对策：

- 协程帧在堆、恢复经调度器间接调用——回溯在 suspend 处「断头」，`bt` 看不到「谁 await 了我」；
  对策：帧内自存 caller 句柄/任务链 ID 日志（可调试性设计，08 篇 8.2）；
- 同帧可重入多次（循环里的 await）：断点命中数≠源码路径数，条件断点要带帧地址；
- 15.2「切分点」的工程含义：一个函数被切成 N 段任意交错——把「函数」原子性假设从心智模型里删掉；
- 15.3「协程之诺」：promise.unhandled_exception 决定异常去哪里——忘了接=异常消失的新式 Heisenbug；
- 附录 C 的简单示例正是最小观察对象：`coroutine_handle`/`promise_type`/三件套手写一遍，
  框架行为全部可见。

### 2.3 远程调试（第 16 章）

- GDB 路径：目标机 `gdbserver :1234 ./app`，开发机 `target remote :1234`；符号留在开发机
  （set sysroot + solib-search-path），目标机可以零 DWARF——**镜像与符号分家**的极端形态（01/06 篇）；
  `attach pid`、条件断点、non-stop 模式全套可用；
- VS 路径：目标机装 msvsmon 监视器，VS 附加；嵌入式/跨架构（ARM 目标 x64 宿主）是共同主战场；
- 安全红线：gdbserver 无认证，只在内网卡/SSH 隧道后用；生产机禁驻守、用「一次性复现会话」。

### 2.4 容器世界（第 17 章 + 故事10/11）

- 容器内视角缺失：无 ps/无 /proc 全量、PID 1 语义（不收割僵尸→0 PID 耗尽=故事7 容器版）、
  信号默认处理被 init 改写——`kubectl exec` 装工具 vs `kubectl debug --container`（ephemeral 调试容器）
  注入 distroless 环境；
- **CrashLoopBackOff 取证流水线**：`kubectl logs --previous` 拿崩前 stdout → core 持久化到 PV 或
  coredump 管道（hostPath 挂载 /proc/sys/kernel/core_pattern 的容器版限制要特权）→
  离线 gdb/core 分析（[06 篇](06-进程镜像与CoreDump.md)）；
- **liveness failure**：探针超时→平台重启→现场蒸发。对策分两层：预置「超时前自 dump」
  （SIGQUIT 钩子/perf event 触发），以及把探针窗口当性能预算而非调试参数（故事11 的真正教训）。

### 2.5 尽量不要调试（第 18 章）与附录

- 18.1 编译器前移：`-Wall -Wextra -Werror` + clang-tidy（`-Wstringop-overflow` 类实证见
  [03 篇](03-内存损坏.md)：一条告警本可省一场 hunt）+ 静态分析；
- 18.2 简短实验代码：怀疑点写成 20 行 repro，比在 5 万行里插桩快——最小复现的预防性用法；
- 18.3 日志与监控：结构化日志+分级（trace 常关可远控开启）、指标四金（延迟/流量/错误/饱和）；
  日志=「延迟的断点」，监控=「统计的 watchpoint」；
- 18.4 最佳实践：所有权显式化（智能指针/`std::span` 边界）、错误即时上抛（`std::expected`）、
  小接口+契约注释；
- **附录 A**：JNI 混合栈要两套符号两套工具（jdb+gdb 双附加、`CheckJNI`）；Java 帧里的 C++ 崩溃
  看 hs_err_pid 日志的 native 栈段；
- **附录 B**：PE 与 ELF 互译清单（节表↔段表、导入表↔GOT、SEH/VEH↔信号、Minidump↔core）；
  Windows 现场：WER 注册表策略+`procdump -ma`。

## 3. 权衡

- **LSan 常开 vs 关闭**：CI 必开；生产靠内存水位+快照 diff 代替（泄漏报告在异步分配器下误报率不低）。
- **协程框架的调试税**：任务级 ID 链日志每次挂起都写，吞吐换可见性——高扇出服务器要分级采样。
- **容器「不可变基础设施」vs 调试需求**：distroless 镜像安全但无 shell——ephemeral container/
  调试专用 sidecar 是折中；core 出容器走 coredump 管道而非手 exec。

## 4. 相邻概念对比

- **泄漏 vs 悬垂（03 篇）**：一个「没人用却占着」，一个「有人用却没主」；前者找引用图孤点，
  后者找引用图脏边——同一张图两种查询。
- **协程调试 vs 线程调试（07 篇）**：协程把「时序不确定性」收进单线程调度器，数据竞争消退、
  交错路径依旧；工具上 TSan 不再适用，改用任务图/await 链可视化。
- **第 18 章 vs 全书**：前面是「如何 debug」，本章是 debug 的成本函数——每类机制章都留了左移接口
  （告警/TSan/自检分配器/Sentry 管线）。

## 最新演进与工业实践

- **C++20/23 协程工具化（2026 现状）**：LLDB 已有协程感知的任务展开（`coroutine list` 类扩展 ⚠️ 成熟度
  按版本），GDB 侧靠社区 xmethod 打印协程帧；libunifex/std::execution（P2300，C++26）路线下
  「调度器+任务图」可视化组件开始出现；可调试性设计（保存 task context 标签）仍是主流答案。
- **远程/容器调试平台化**：Dev Containers、Telepresence、Grafana Beyond 类「进集群调试」产品；
  Delve 模式的 headless dlv + 前端分离在 C++ 对应 `gdb --interpreter mi`/lldb-dap 远程化。
- **左移工具链**：clang-tidy（bugprone-*/concurrency-* 族）、cppcheck、CodeQL 进 PR 门禁；
  `-ftrivial-auto-var-init=pattern` 让未初始化读当场可辨（GCC12+/clang16+ 默认可用 ⚠️ 版本按发行说明）。
- **Windows 平台适用性**：MSVC `/W4 /analyze` + VS 快照调试器（Snapshot Debugger，2024 起 Intellitrace
  后继 ⚠️ 前沿观察：微软官方 Preview 演进中）；WSL2 内 Linux 工具链完整可用（本章 Linux 工具本机
  Windows 原生不可用的现实解）。
- **AI 辅助（⚠️ 前沿观察）**：K8s 事故摘要+日志问答（LLM 读 `logs --previous` 提假设）与
  自动 repro 生成（AutoCodeRover，arXiv:2404.05427 实测存在）已进演示期；生产采纳以「人审假设」为界。
- **开源仓库逐点对应**：`google/sanitizers`（LSan）、`gdb`（remote/gdbserver）、`kubernetes/kubernetes`
  （kubectl debug）、`google/breakpad`（附录 B 管线化）。
