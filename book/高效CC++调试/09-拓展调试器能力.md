## 核心概念速览（中英对照）

- **GDB Python API** — `gdb` 模块：在调试器进程内执行的 Python 3 绑定：读符号、读内存、控断点、发命令
- **美观打印器** — pretty printer：注册到类型/正则上的 `__call__(val) → 字符串` 函数，接管 `print` 渲染
- **xmethods** — GDB 扩展方法：`vec.at(3)` 在调试器里调用你定义的 Python 方法，而非被调试进程代码
- **程序化断点** — `gdb.Breakpoint` 子类：`stop()` 返回假值=静默记录现场继续跑——断点变探针
- **条件求值语言** — convenience variables（`$pc` 等）与 `gdb.parse_and_eval`：在 Python 与目标语言间搬运值
- **自定义命令** — `define … end`（9.2）：GDB 脚本宏，`$arg0..` 位置参数；零依赖版自动化
- **命令文件** — `-x cmds.gdb` / `source`：把会话固化为可评审、可复跑的取证脚本
- **init 文件** — `~/.config/gdb/gdbinit`（及安全目录机制）：团队共享的 `set auto-load safe-path` 配置
- **LLDB SB API** — ScriptBridge（`lldb.SBTarget` 等）：LLDB 侧对等物，Python/Lua 双绑定
- **环形缓冲打印** — 9.1.4「更快地调试 bug」的代表技术：用 Python 断点回调把日志写进调试器侧内存

## 1. 动机：手册命令只能调「别人的程序」

GDB 的交互命令是**单值查询**（print 一个表达式），而排障需要的是**遍历与聚合**：
「把这 10 万个元素的链表沿 next 走一遍找环」「每次进 foo 都记下 $rdx 然后继续」「这个容器按业务语义
显示」。9.1/9.2 的共同主题：**把调试会话从问答变成程序**。原书立场（也是本章骨架）：
重复第 3 次的操作就该变成命令，第 10 次就该变成断点回调。

## 2. 机制

### 2.1 美化打印器（9.1.1/9.1.2）

注册流程三步：`gdb.printing.register_pretty_printer(objfile, reg)`，其中 reg 是
`add_pretty_printer(正则, 工厂)`；工厂按类型造出 printer 类（`to_string()`/`children()` 协议）。
标准库容器（libstdc++）自带打印器脚本（`share/gdb/python/libstdcxx/`），MinGW 装好即有
`p myvec` 直出 `[0]=1, [1]=2…`。业务结构体则自己写——本质是「把 [04 篇](04-C++对象布局.md) 的布局知识
写成 20 行 Python」。

### 2.2 程序化断点=探针（9.1.5「使用Python设置断点」）

🔧 **已实测**（本机 GDB 17.1，MinGW 栈；用命令文件驱动）：

```text
$ cat cmds6.gdb
python
import gdb
print("py-in-gdb:", 40+2)
end
break main
run
python
b = gdb.Breakpoint("checksum")
print("bp addr:", b.location)
end

$ gdb -batch -x cmds6.gdb ./opt0.exe
py-in-gdb: 42
...
Breakpoint 2 at 0x7ff687f9144f: file opt.cpp, line 3.
bp addr: checksum
```

关键差别：`gdb.Breakpoint` 子类可在 `stop()` 里 `gdb.lookup_symbol` 取值、写进 Python 列表、
`return False` 让目标继续跑——**调试器不暂停地采集数据**；9.1.4 的「更快调试」全建立在此：
竞态关键区日志（[07 篇](07-调试多线程程序.md) 7.4）、越界写快照、命中率统计都用它，
一次 continue 采集万次事件。

### 2.3 把会话固化（9.1.3/9.1.6/9.2）

- `define dump-lock` … `end`：纯 GDB 宏（无 Python 依赖，嵌入式 gdb 也常见只有宏层）；
  `$arg0` 传栈帧号，`while`/`if` 齐备；
- 9.1.6「命令行启动程序和设置断点」= `gdb -batch -ex …` 一行式，CI 里做「崩溃自动摘要」；
- 工程习惯：调试脚本进仓库（`tools/debug/*.gdb`），工单里附脚本+core 链接而不是截图——8.2.1 知识保留的执行形态。

### 2.4 踩坑实录：Windows + MSYS bash 的引号/编码问题

🔧 **已实测（负面样本，同样是「拓展能力」的一部分）**：

- MSYS/Git-Bash 会把 `-ex "print $pc"` 里的 `$pc` 当 shell 变量展开成空串，导致 GDB 参数错位
  （症状：`Excess command line arguments ignored` / `No executable specified`）——
  **改用命令文件 `-x cmds.gdb` 或多参数分开引用**即愈；
- GDB 17.1 在 CP65001 代码页下偶发 `could not convert 'checksum' from the host encoding
  (CP65001) to UTF-32` 警告（无害；切换控制台代码页或设 `set logging charset` 可消）；
- `info proc mappings` 在 Windows 原生目标返回 `Not supported on this target`（[06 篇](06-进程镜像与CoreDump.md)
  实测），改用 `info files`/`maintenance info sections`。

## 3. 权衡

- **Python vs 宏**：Python 表达力完整但有版本兼容与启动成本；`define` 宏零依赖、适合塞进
  嵌入式/现场最小化环境（只带一个 .gdbinit 就能干活）。
- **断点回调的隐性开销**：每次命中都跨进 Python（微秒级×高频=可感减速），高频探针优先条件表达式
  （C 层求值）过滤，或 `condition` + 采样计数。
- **auto-load 安全**：可执行文件自带 `.gdbinit`/Python 段默认被禁（`set auto-load safe-path`
  白名单制）——拓展能力与供应链安全的天平，按目录放行而非全局打开。

## 4. 相邻概念对比

- **GDB Python vs LLDB Python**：概念对位——printer ↔ `type_summary`/`SummaryProvider`；
  Breakpoint callback ↔ `target.BreakpointSetPassState`/`runScriptedStep`；lldb 的 SB API 分层
  更「对象化」，gdb 的更「命令式」。LLDB 官方 Python 文档 `lldb.llvm.org/use/python.html`（实测 200）。
- **调试器内脚本 vs 外部工具（DAP/IDE 插件）**：前者能直接读目标内存与类型，后者做 UI 与协作；
  VS Code 的 C++ 扩展里 `expression evaluation` 本质还是把表达式甩给 gdb/lldb。
- **美化打印 vs 反序列化调试**：打印器假设类型可信；core 里对象可能半毁（04 篇垂直搜索），
  所以 Core Analyzer 类工具宁可逐字 dump 也不贸然「渲染」——健壮性 vs 表达力。

## 最新演进与工业实践

- **libstdc++/libc++ 打印器内置化**：现代发行版开箱可用；自定义类型走 `.gdb_index`+`dwz` 降低大工程
  符号加载延迟（配合 [01-调试符号与调试器.md](01-调试符号与调试器.md) 演进节）。
- **DAP 生态**：`gdb`/`lldb-dap` 让「脚本化调试」体验进入 VS Code/Zed 断点面板（条件断点、日志断点
  由前端翻译成 MI/DAP 命令）；更深的 Python 逻辑仍建议落在命令文件里。
- **生产侧同款思想**：eBPF 的 bpftrace 单行脚本 = 内核态的「程序化断点」（[11 篇](11-系统级观测与崩溃上报.md)），
  9.1.4 的环形缓冲在 Linux 内核里对应 `trace_pipe`/perf ring buffer——同一设计模式的两个实现。
- **平台适用性（本仓库双栈）**：MinGW GDB 自带 Python3（本次实测确认）；MSVC 栈的「拓展」位由
  WinDbg 的 JavaScript/C++ 引擎扩展承担，思路一致、API 不同。
- **开源仓库逐点对应**：`gdb`（`gdb/python/lib/gdb/printing.py`）、`llvm/llvm-project`
  （lldb/examples/synthetic 打印器样例库）。
