## 核心精讲

### 1. 标签驱动的策略栈（转述 ⚠️）
```sql
-- 教学示意，非书中原文
CREATE TAG if not exists pii;
ALTER TABLE users MODIFY COLUMN email SET TAG pii='email';
CREATE MASKING POLICY email_mask AS (val string) RETURNS string ->
  CASE WHEN CURRENT_ROLE() IN ('ANALYST') THEN '***' ELSE val END;
ALTER TABLE users MODIFY COLUMN email SET MASKING POLICY email_mask;
```
- **自动标签传播**：CTAS/视图/装载/血缘图内下游对象继承标签（✅ object-tagging/propagation）——
  治理从"逐列配置"变为"追源头"。
- 脱敏策略 ✅ https://docs.snowflake.com/en/user-guide/security-column-ddm-intro 、
  标签绑定形态 ✅ https://docs.snowflake.com/en/user-guide/tag-based-masking-policies
- 行级 ✅ https://docs.snowflake.com/en/user-guide/security-row-intro
- **JOIN policies** ✅ https://docs.snowflake.com/en/user-guide/join-policies 、
  标签绑定 ✅ https://docs.snowflake.com/en/user-guide/tag-based-join-policies
  ——限定哪些列集合允许互相 JOIN（标签对偶声明），查询被策略拒绝时按报错语义回退改写 ⚠️。
  这是"进阶"色彩最重的一页：重识别攻击面被正式纳入策略模型。

### 2. 策略 vs 视图方案的裁决（方法论 ⚠️）
RLS 老写法（安全视图/共享视图 ✅ https://docs.snowflake.com/en/user-guide/views-secure ）与策略
新写法的对偶：视图=逻辑显式、链路可见；策略=隐式挂物理表、穿透所有访问路径（含外部引擎读
Iceberg——见 10.4）。2026 口径：**新系统策略优先，存量视图不必迁移** ⚠️。

## 常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "有了角色链就不用策略" | RBAC 管"能否碰对象"，策略管"碰见什么形状的数据" |
| "脱敏只在查询时做" | 共享/下游对象经标签传播自动带入，导出面才是真边界 |
| "行策略比视图安全" | 两者威胁模型不同：策略防绕过，视图防泄漏逻辑；可叠加 |
| "JOIN policy 防的是越权" | 防的是**合法可见列的重识别组合**，语义更细 |
| "血缘只是文档" | 2026 形态下它是变更影响面分析与标签传播的执行通道 |

## 核心概念速览（中英对照）

1. **对象标签** — object tag：可复用的元数据变量，治理的"变量名"。
2. **标签传播** — tag propagation：血缘下游自动继承标签（✅200）。
3. **动态脱敏** — dynamic data masking：列级策略按角色/上下文换形。
4. **行访问策略** — row access policy：挂表的行过滤器。
5. **JOIN 策略** — join policy：声明允许的关联列集合，防重识别。
6. **重识别** — re-identification：合法可见列拼出隐私的攻击面。
7. **血缘图** — data lineage：对象上下游可视化与影响面分析。
8. **外部血缘** — external lineage：BI/服务侧对象注册进图。
9. **Horizon Catalog** — 托管治理目录：策略随 Iceberg REST 穿透外部引擎。
10. **安全视图** — secure view：行数受限的共享视图（策略的对偶老方案）。
11. **ACCESS_HISTORY** — 访问审计视图：机器可读侧的取证源 ⚠️。
12. **策略穿透** — 客户端不可见改写：策略体系的核心工程性质（🔧类比=视图注入）。
