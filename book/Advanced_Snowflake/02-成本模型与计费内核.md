## 核心精讲

### 1. credit 流模型（转述 ⚠️）
一个账户的 credit 消耗 ≈ Σ(仓库尺寸×运行秒数) + 云服务小时配额 + 其他托管服务（自动聚簇、搜索
优化索引字节、Snowpipe serverless 算力、QAS 外溢、AI 函数 token——后四类是"进阶账单"的主要暗物质）。
官方成本模型页与计量视图：
✅ https://docs.snowflake.com/en/user-guide/cost-understanding
✅ https://docs.snowflake.com/en/sql-reference/account-usage/warehouse_metering_history
关键口径：**每档尺寸的每小时 credit 率不同且按云区域/合同浮动**——本册不复刻费率表（⚠️ 会变），
方法=从 `WAREHOUSE_METERING_HISTORY` 拉真实秒级数据自算。

### 2. 云服务层的隐性账单（转述 ⚠️）
查询解析/优化、元数据维护、克隆簿记、自动聚簇的后台重排，都会消耗 cloud services credits；
官方口径存在"每小时前 60 秒×尺寸比例内免费"的经典经验规则 ⚠️（以页内为准）。
✅ https://docs.snowflake.com/en/user-guide/cost-controlling-controls
✅ https://docs.snowflake.com/en/user-guide/tables-auto-reclustering
✅ https://docs.snowflake.com/en/user-guide/search-optimization-service

### 3. 归因三件套（转述 ⚠️）
- **QUERY_TAG**：会话/查询级打标，进 `QUERY_HISTORY`/`MONITORING` 视图，按团队/应用汇总。
  会话参数正典页：✅ https://docs.snowflake.com/en/sql-reference/parameters
  ✅ https://docs.snowflake.com/en/user-guide/ui-snowsight-activity
- **Budgets（2024+ 新面）**：按维度（如标签）聚合计量的"软账本"+周期动作（自定义/cycle-start 动作）。
  ✅ https://docs.snowflake.com/en/user-guide/budgets
  ✅ https://docs.snowflake.com/en/user-guide/budgets/custom-budget
- **资源监视器（硬闸）**：credit 配额触发 SUSPEND/NO_ACTION 分级，账户级兜底。
  ✅ https://docs.snowflake.com/en/user-guide/resource-monitors
自拟教学示意（非书中原文）：
```sql
ALTER SESSION SET QUERY_TAG = '{"team":"risk","env":"prod"}';
SELECT user_name, query_tag,
       SUM(credits_used_total) OVER (PARTITION BY query_tag) AS tag_credits
FROM snowflake.account_usage.query_history
WHERE start_time >= DATEADD(day,-7,CURRENT_TIMESTAMP());
```

### 4. 存储侧成本（转述 ⚠️）
存储按**压缩后**月均字节计费；Time Travel/Fail-safe 窗口内的历史版本、零复制克隆的共享底层数据、
Iceberg 托管表自带快照链，都构成"看不见的存储"。
✅ https://docs.snowflake.com/en/user-guide/data-availability
✅ https://docs.snowflake.com/en/user-guide/data-cdp-storage-costs
✅ https://docs.snowflake.com/en/user-guide/data-failsafe
✅ https://docs.snowflake.com/en/user-guide/data-time-travel

### 5. 优化决策树（转述 ⚠️ 汇总）
先归因（tag/budget 找出 TOP 消耗）→ 再分层（裁剪/聚簇/缓存解决大扫描；仓库尺寸解决真并发）→
后托管（QAS/Adaptive Compute 换弹性）→ 最后才是砍窗口（Time Travel 天数/聚簇键数量/索引字节）。
✅ https://docs.snowflake.com/en/user-guide/query-acceleration-service
✅ https://docs.snowflake.com/en/user-guide/warehouses-adaptive
✅ https://docs.snowflake.com/en/user-guide/performance-query-warehouse-size

## 常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "成本=仓库尺寸×时间" | 云服务费+托管服务（聚簇/搜索索引/Snowpipe/AI）可占显著份额 |
| "挂起仓库就省钱，随便挂" | 冷缓存把成本转嫁给下一次扫描；应配合负载时段设自动挂起窗 |
| "资源监视器=Budgets" | 前者硬闸可停仓，后者是聚合账本与周期动作，语义不同层 |
| "克隆复制了存储" | 零复制克隆只共享元数据引用；**但克隆后的分叉会累积独立字节** |
| "标签是可选装饰" | 没有标签归因，Adaptive/托管服务的账单无法审计回团队 |

## 核心概念速览（中英对照）

1. **credit** — 计费单位：算力/服务消耗的通用货币，费率随尺寸与区域浮动。
2. **秒级计量** — per-second billing：仓库运行秒累计、出账粒度分钟 ⚠️。
3. **云服务费** — cloud services credits：解析/优化/元数据/后台维护的共享控制面消耗。
4. **查询标签** — query tag：JSON 字符串归因钩子，账单审计的最小成本手段。
5. **预算** — budgets：按规则聚合 credit 消耗并施加周期/自定义动作的软账本（2024+）。
6. **资源监视器** — resource monitor：credit 配额硬闸（告警→suspend→kill 分级）。
7. **计量历史视图** — WAREHOUSE_METERING_HISTORY：秒级真实用量的取数入口。
8. **压缩后字节** — compressed bytes：存储计费口径；微分区列存压缩决定分子。
9. **影子存储** — Time Travel/Fail-safe/克隆分叉的历史字节（存储账单常被低估处）。
10. **查询加速服务** — QAS：用共享弹性算力溢出消化突发，按秒计 credit。
11. **归因→分层→托管→砍窗** — 成本优化的四步决策顺序（方法论 ⚠️）。
12. **FinOps 基线** — 上 Adaptive Compute 前先建立可回放的账单基线（实践口径 ⚠️）。
