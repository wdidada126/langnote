## 核心精讲

### 1. 仓库尺寸与算力档位（转述 ⚠️）
官方口径：虚拟仓库是一组**计算集群**，尺寸逐档翻倍算力（约 2×/档）；查询在仓库内被切成跨节点
并行片段。与"单机核数"的直觉差异：**尺寸买的是聚合 I/O+CPU，不是延迟下限**——小查询在 4XL 上不会
按比例变快（裁剪/缓存才是它的杠杆，第 3/4 章）。
✅ https://docs.snowflake.com/en/user-guide/warehouses-overview

### 2. 多集群与伸缩策略（转述 ⚠️）
`MIN/MAX CLUSTER COUNT` + `SCALE_UP/SCALE_DOWN_POLICY`（经济/平衡/最大化）控制并发外扩；集群按
查询亲和性（同集群读同表吃缓存）分片。进阶要点：
- **伸缩是粗粒度的**：一个集群整组起落，秒级到分钟级 ⚠️；
- **挂起-恢复的成本语义**：恢复后本地缓存冷 → 首查可能显著慢（结果缓存另有 24h/1 周窗 ⚠️）；
- 队列监控：Query History 的 `QUEUED`/`QUEUED_LOAD`/`QUEUED_MONITOR` 状态细分归因（第 2 章计费联动）。
✅ https://docs.snowflake.com/en/user-guide/warehouses-multicluster
✅ https://docs.snowflake.com/en/user-guide/performance-query-warehouse-queue
✅ https://docs.snowflake.com/en/user-guide/performance-query-warehouse-max-concurrency
✅ https://docs.snowflake.com/en/user-guide/ui-snowsight-activity

### 3. Adaptive Compute：从"调参"到"委托"（转述 ⚠️，2025+ 新面）
官方已上线 **Adaptive Compute** 页：平台按工作负载自动决定仓库的伸缩与形态，管理员从
"选尺寸/调 cluster policy"转为"设边界"。对读前波 TDG-09「最新演进」节的 Summit 2025 公告口径：
方向一致，本册按文档页为准登记（⚠️ 细节以页内为准）。
✅ https://docs.snowflake.com/en/user-guide/warehouses-adaptive
✅ https://docs.snowflake.com/en/user-guide/warehouses-tasks
✅ https://docs.snowflake.com/en/user-guide/performance-query-warehouse-size
✅ https://docs.snowflake.com/en/user-guide/performance-query-warehouse-cache

### 4. 负载分叉：Snowpark 优化仓库与混合工作负载
分析 SQL、Snowpark 数据工程、hybrid 事务表三类负载对计算形态要求不同；官方提供
**Snowpark-optimized warehouses**（内存配比不同的档位）。进阶判断法：先看工作负载画像
（Performance Explorer/CoCo，第 5 章），再定仓库拓扑，而不是反过来。
✅ https://docs.snowflake.com/en/user-guide/warehouses-snowpark-optimized
✅ https://docs.snowflake.com/en/user-guide/performance-explorer
✅ https://docs.snowflake.com/en/user-guide/analyze-workload-performance-coco
✅ https://docs.snowflake.com/en/user-guide/tables-hybrid-best-practices

### 5. 与成本模型的耦合（预埋第 2 章）
计算层每个旋钮都直接映射 credit：尺寸×时长、集群数×时长、恢复预热、QAS 外溢算力
（✅ https://docs.snowflake.com/en/user-guide/query-acceleration-service ）。"进阶"的标志就是把
架构题全部翻译成账单题——见 [02-成本模型与计费内核.md](02-成本模型与计费内核.md)。

## 常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "仓库越大任何查询都越快" | 点查瓶颈在裁剪/缓存，大仓库白烧 credit |
| "多集群 MAX 越高越稳" | 伸缩滞后于突发，队列积压仍会发生；先做负载隔离 |
| "挂起=删除" | 挂起保留对象与元数据，恢复快、缓存部分保留；自动挂起是默认计费卫生 |
| "Adaptive Compute 免思考" | 预算护栏（Budgets/资源监视器，第 2 章）仍是人设的 |
| "云服务层免费" | 元数据/优化等服务按小时收 cloud services credits，正常应有比例告警机制 |

## 核心概念速览（中英对照）

1. **虚拟仓库** — virtual warehouse：按需起停的 MPP 计算集群组，尺寸=算力档位。
2. **多集群伸缩** — multi-cluster scaling：以并发为单位外扩集群，MIN/MAX+策略控制。
3. **伸缩策略** — scaling policy：经济/平衡/最大化三档的外扩激进度偏好。
4. **查询队列** — query queueing：容量满时的显性背压，QUEUED_LOAD 等状态归因。
5. **本地缓存** — local (SSD) cache：仓库节点的数据缓存，挂起/扩缩会扰动命中。
6. **结果缓存** — result cache：相同查询文本的直接返回通道，跨仓库生效 ⚠️。
7. **自适应计算** — Adaptive Compute：平台托管仓库形态与伸缩的新范式（2025+）。
8. **Snowpark 优化仓库** — Snowpark-optimized warehouse：面向高内存数据工程负载的档位。
9. **查询加速服务** — Query Acceleration Service (QAS)：仓库外溢的共享算力池。
10. **混合表** — hybrid tables：为事务型低延迟负载另开的存储/计算形态。
11. **性能画像** — Performance Explorer/CoCo：按工作负载切片的观测工具面。
12. **云服务层** — cloud services layer：解析/优化/元数据的共享控制面，按 credit 计费。
