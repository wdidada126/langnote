## 二、IQP 族谱（版本→特性→管理员动作）⚠️ 转述 + ✅ 总览

- 2017 代：批处理模式内存授予反馈、自适应 Join、表变量…（起步代）⚠️。
- 2019 代：标量 UDF 内联、表变量延迟编译、批处理内存反馈百分比化前夜 ⚠️。
- 2022 代（✅ IQP 页点名）：**Last Execution Mode Memory Grant Feedback**（按上次执行模式给授予）、**Parameter Sensitive Plan Optimization**（一查询多计划按参数分布出牌，治参数嗅探）、以及跨代特性的持续增强 ⚠️ 细节以页面为准。
- 管理员动作：升级切 160 前，在 QS 里圈出"历史上内存授予异常/嗅探敏感"的查询做对照集；切后按周看这些查询的运行分布 ⚠️ 做法。
- 内核纵深：优化器代价模型与计划的物理算子 → [../SQL_Server_2012_Internals/07-查询执行优化与计划缓存.md](../SQL_Server_2012_Internals/07-查询执行优化与计划缓存.md)、[../SQL_Server_2014_Query_Tuning/00-总览与阅读地图.md](../SQL_Server_2014_Query_Tuning/00-总览与阅读地图.md)（2014 册=优化器调优纵深）。

## 三、统计信息供给侧

- 官方机制 ✅ https://learn.microsoft.com/en-us/sql/relational-databases/statistics/statistics：直方图+统计头，自动创建/更新开关、`UPDATE STATISTICS` 手动档、增量统计（大表分区级）。
- 老化画像 ⚠️：大批量写入后统计过期→基数估计崩→计划劣化——"今天怎么突然慢了"的第一嫌疑人；自动更新的阈值触发在超大表上迟钝（老公式问题，新代有改进 ⚠️ 以文档为准）。
- 例行处方 ⚠️（社区共识非官方数值）：大表每日/每周增量或全量 `UPDATE STATISTICS ... WITH RESUME` 类节奏，配合 QS 回归告警验证"保养有没有用"。
- 与 06/02 章牵连：统计读写吃 tempdb；权限面 `SHOW_STATISTICS` 类细节 ⚠️。

## 五、列存储：仓库负载默认姿势

- 官方概览 ✅ https://learn.microsoft.com/en-us/sql/relational-databases/indexes/columnstore-indexes-overview：段（segment）+字典压缩、批处理模式向量执行、CCI（聚集列存）为主表形态。

## 六、自动调优：引擎自学 DBA 部分手艺

- 官方框架 ✅ https://learn.microsoft.com/en-us/sql/relational-databases/automatic-tuning/automatic-tuning：以 Query Store 为数据底座，库级三能力——**强制回归计划**、**放弃次优计划**、**CREATE INDEX 推荐**（后者仅 Azure 侧 ⚠️ 口径）；配置在 INHERIT/自定义间选。
- 使用姿势 ⚠️：先"观察模式"跑两周看推荐清单，再逐能力开启；每次自动动作都要进告警流（接 10 章作业警报），否则"引擎偷偷改了计划"会变成新的不可解释故障。
- 与 IQP 的关系：自动调优管"计划选择"，IQP 管"执行期自适应"——两层反馈回路互补 ⚠️ 观念图。
- 风险登记 ⚠️：自动强制计划掩盖统计老化根因——每周复盘推荐日志，把"引擎在替你圆场"的问题清单交回开发侧。

## 七、参数嗅探剧本（管理员版）

1. 识别：同查询计划多、耗时分布双峰；QS 按查询看"计划数×运行统计"矩阵 ⚠️。
2. 急救：`OPTION (RECOMPILE)` 局部化、计划清理（影响面大慎用）、查询存储强制稳定计划（08 章保险箱）⚠️。
3. 根治：升级到 2022+ 兼容级启用 Parameter Sensitive Plan Optimization（IQP 页 ✅）；或应用侧按选择性参数拆分存储过程路径 ⚠️ 转述。
4. 复盘：把典型嗅探案例入知识库，标注"数据分布拐点"（偏斜列上的值域是根变量）⚠️。

## 九、常见坑清单（⚠️ 转述整理，非原书条文）

1. **切兼容级不看 QS 对照**：160 的自适应行为改变计划分布，"升级红利"变"升级事故" ⚠️。
2. **统计更新不看查询反馈**：保养完不验证回归查询的耗时分布，白做 ⚠️。
3. **REBUILD 全库一把梭**：不分表大小/使用度，维护窗口爆掉且日志暴涨（04 章联动）⚠️。
4. **CCI 上高频小事务写入**：delta store 堆积成扫描瓶颈，组压缩节奏没进监控 ⚠️。
5. **自动调优开了不看日志**：引擎强制计划的动作没进告警流，某天"计划为什么变了"无人能答 ⚠️。
6. **临时 OPTION(RECOMPILE) 长期化**：急救手段变成长期 CPU 税，嗅探根治被拖延 ⚠️（七·2/3）。
7. **UDF 内联后性能反向**：2019 代特性在复杂函数上计划变化不可预期，灰度验证缺位 ⚠️。

## 核心概念速览（中英对照）

- **智能查询处理** — Intelligent Query Processing (IQP)：按兼容级激活的自适应执行特性族。
- **内存授予反馈** — Memory Grant Feedback：按上次执行修正内存授予，spill 自校正回路。
- **参数敏感计划优化** — Parameter Sensitive Plan Optimization：2022 代一查询多计划的嗅探解药。
- **自适应 Join** — Adaptive Join：运行期在散列/嵌套循环间换形的 2017 代成员。
- **统计信息** — Statistics：直方图+采样头，基数估计的供给侧。
- **增量统计** — Incremental Statistics：分区级统计维护，超大表保养利器。
- **碎片整理** — Reorganize/Rebuild：在线整理与重建的两种索引保养档。
- **列存储索引** — Columnstore Index：段+字典压缩、批处理向量执行的仓库形态。
- **delta store** — 差分区：CCI 的未压缩缓冲带，组压缩节奏对象。
- **自动调优** — Automatic Tuning：以 QS 为底座的计划强制/放弃自动化层。
- **参数嗅探** — Parameter Sniffing：首参定计划、他参受连累的估计事故。
- **计划强制** — Plan Forcing：把选定计划钉死的 QS/提示手段。
- **查询存储模式** — Query Store Mode：READ_WRITE/只读两档的留档开关。
