## 一、三层账本：库 ⊃ 文件组 ⊃ 文件

- 每个数据库至少一个主数据文件（.mdf）+ 一个日志文件（.ldf）；次数据文件（.ndf）挂在文件组下 ⚠️ 转述；对象→文件组→文件→页/区的归属链是容量与 IO 规划的全部主语。
- 系统四库的存储角色 ⚠️：master（实例账本）、model（新库模板——tempdb 每次启动由它重生）、msdb（作业/备份历史，与 [10-自动化作业与混合云运维.md](10-自动化作业与混合云运维.md) 直接相关）、资源库（隐藏只读模板对象源）。
- 文件不可跨库共享、日志文件不属于任何文件组——"日志是独立账本"这一点在 04 章备份链里回报。
- 内核纵深：页/区/指针结构逐字节讲解在 [../SQL_Server_2012_Internals/02-数据库与数据库文件.md](../SQL_Server_2012_Internals/02-数据库与数据库文件.md) 与 [04-表存储.md](../SQL_Server_2012_Internals/04-表存储.md)；本章保持管理视角（怎么分、怎么长、怎么搬）。

## 二、页与区：8KB 宪法 ⚠️ + 🔧 类比

- SQL Server 以 8KB 页为 IO/分配原子单位，区（extent）=8 连续页，混合分配策略对小表省空间 ⚠️（机制详见 #56 04 章）。
- 🔧 **实验 E6（SQLite 3.45.3，非本书引擎行为）**：journal/临时空间形态族谱实测——依次设置 `PRAGMA journal_mode=delete/truncate/persist/memory/wal/off`，六种全部设置成功并回读确认（`[delete, truncate, persist, memory, wal, off]`）。
  - 类比读法：SQL Server 的恢复模型（FULL/SIMPLE/BULK_LOGGED）与 SQLite 的日志模式族是**同一定理的两套命名**——"日志留多久、脏页何时回写主文件、崩溃后谁负责重放"。`memory/off` ≈ 把耐久赌在内存/运气上（绝不用于生产）；`delete`（每次事务截断日志）≈ SIMPLE 的"日志不保值"；`wal`（日志长驻追加）≈ FULL 的日志链形态。**非本书引擎行为，仅通用机制演示。**
  - 附带观察：SQLite 默认 `page_size=4096`（页头 hex 可读），对比 SQL Server 固定 8KB ⚠️——页大小是引擎的"宪法单位"，决定碎片、对齐与 IO 模式的一切下游结论（SQLite 页概念详见 [../The_Definitive_Guide_to_SQLite_2e/00-总览与阅读地图.md](../The_Definitive_Guide_to_SQLite_2e/00-总览与阅读地图.md)）。
- 容量单位换算纪律：文件增长量、VLF（虚拟日志文件，04 章）、分配位图页（PFS/GAM 每 8088 页管辖一区族 ⚠️）共用"页"这个基本量——报表口径先换算再汇报。

## 三、文件组战术

- **默认即平铺**：不建文件组时所有对象进 PRIMARY——小库够用，大库是隐患 ⚠️。
- 常见分组法 ⚠️ 转述：①按生命周期（历史数据 readonly FG，备份可降级为一次性）；②按热冷 IO（FG 绑不同卷）；③按分区对齐（分区函数边界 ↔ FG 一一对位，滚动归档 SWITH PARTITION 的底座）。
- `ALTER TABLE ... MOVE` / 重建索引指定 `ON FG` 是对象搬家的两种姿势；文件组搬家≠文件搬家，别混 ⚠️。
- 只读文件组的备份红利：readonly FG 备份一次终身有效（直到变回读写）——大历史库备份窗口的主要压缩器 ⚠️，与 04 章文件组备份衔接。
- 表分区视图 `sys.partitions` 与 FG 的对位核查是"分区建了但没分区"类事故的标准体检 ⚠️；分区内部结构见 [../Pro_SQL_Server_Internals/10-数据分区.md](../Pro_SQL_Server_Internals/10-数据分区.md)。

## 四、自动增长与容量治理

- 文件自动增长（AUTOGROWTH）是**同步阻塞操作**：增长瞬间该文件上的写入排队等待；默认 1MB 增量在高写入库上等于反复点刹车 ⚠️ 转述——处方：按容量规划预置大小+合理定长（% vs MB 之争以 MB 可预期性优先）。
- 日志文件（.ldf）增长与 VLF 碎片：频繁小增长造出海量小 VLF，拖慢启动/备份/还原 ⚠️——04 章日志维护给出压缩与重建节奏。
- 容量巡检脚本面（DBA 习惯） ⚠️：逐文件`size/max_size/growth` + 卷剩余空间 + 月度增长率三表合一；msdb 备份历史辅助"哪库在长"。
- 磁盘告警与配额：Windows 卷快照/LVN 扩展属于 OS 侧功课，本册边界外，但巡检表必须含一列 ⚠️。

## 五、特殊存储位一览（管理视角点到即止）

- FILESTREAM/FILETABLE：BLOB 出库进 NTFS，事务与路径双一致性 ⚠️（内部结构见 [../SQL_Server_2012_Internals/06-特殊存储与特殊索引.md](../SQL_Server_2012_Internals/06-特殊存储与特殊索引.md)）。
- 列存储段（columnstore segment）与大表压缩：存储收益在 09 章性能线讲，此处只登记"CCI 有独立存储形态" ⚠️ ✅ 概览 https://learn.microsoft.com/en-us/sql/relational-databases/indexes/columnstore-indexes-overview。
- 内存优化文件组：Hekaton 表落在 `MEMORY_OPTIMIZED_DATA` 型 FG（容器文件族），备份/HA 语义与普通 FG 不同 ⚠️ ✅ 入口 https://learn.microsoft.com/en-us/sql/relational-databases/in-memory-oltp/introduction-to-memory-optimized-tables。

## 七、常见坑清单（⚠️ 转述整理，非原书条文）

1. **% 增长混用**：同一库有的文件按 %、有的按 MB，容量预测直接失真——统一按 MB 定长 ⚠️。
2. **日志文件当数据文件缩**：ldf 上 SHRINKFILE 造成 VLF 碎片与索引重建风暴，"省空间"变"赔性能" ⚠️。
3. **分区对位假成功**：分区函数建了、FG 没对位，所有分区仍挤 PRIMARY——`sys.partitions` 核查缺位 ⚠️。
4. **readonly FG 忘了它会变读写**：一次 `ALTER ... READ_WRITE` 让"终身备份"假设破产 ⚠️。
5. **tempdb 与用户库同卷**：版本风暴来时互相踩踏，02/03 章联动的头号规划债 ⚠️。
6. **FILESTREAM 卷不支持加密/压缩特性**：NTFS 特性依赖清单没查就启用 ⚠️。

## 八、实操速查卡（⚠️ 社区通行写法示意，非本书实测）

```sql
SELECT db.name, f.name, f.type_desc, f.size*8/1024 AS size_mb,
       f.growth, f.is_percent_growth
FROM sys.master_files f JOIN sys.databases db ON db.database_id=f.database_id;

ALTER DATABASE Sales MODIFY FILE (NAME=SalesData2, SIZE=51200MB, MAXSIZE=UNLIMITED, FILEGROWTH=1024MB);
ALTER TABLE dbo.Fact MOVE TO FG_2024;   -- 搬家到目标文件组（重建语义，窗口操作）
```

- 巡检三表：文件尺寸表、卷剩余表、月度增长差报表——容量会的入场券 ⚠️。

## 核心概念速览（中英对照）

- **文件组** — Filegroup：逻辑存储容器，对象到文件的中间层与备份单位。
- **主数据文件** — Primary Data File (.mdf)：每库一个，携带系统页起点。
- **次数据文件** — Secondary Data File (.ndf)：可选，扩充卷与 IO 面。
- **日志文件** — Log File (.ldf)：不属于文件组的 WAL 账本，04 章主角。
- **页** — Page (8KB)：IO/分配宪法单位，一切碎片与增长的度量衡。
- **区** — Extent：8 连续页的分配块，小表混合分配省空间。
- **PFS/GAM** — 分配位图页族：空间归属的元数据账，tempdb 争用之源。
- **自动增长** — Autogrowth：同步阻塞的文件扩容动作，定长策略的坑位。
- **VLF** — Virtual Log File：日志文件内部分段，碎片影响启动与备份。
- **只读文件组** — Read-only Filegroup：历史数据的"备份一次"红利开关。
- **表分区** — Table Partitioning：水平切分对位多文件组的伸缩术。
- **FILESTREAM** — FILESTREAM：BLOB 交给 NTFS、事务保持一致的混合存储。
- **journal_mode** — SQLite 日志模式族（🔧E6）：delete/truncate/persist/memory/wal/off，恢复模型的通用语义对照物。
- **填充因子** — Fill Factor：索引页预留空隙的写放大/空间放大平衡钮。
- **条带化** — Striping：多卷分摊文件 IO 的布局手段，多文件方案的物理前提。
