## 一、Agent：实例的值班管家

- 官方域 ✅ https://learn.microsoft.com/en-us/sql/ssms/agent/sql-server-agent：msdb 存全部定义（作业/警报/操作员），Agent 服务启动类型与凭据是 01/06 章已埋的两颗雷 ⚠️。
- 三件套 ⚠️：作业（Job，多步骤+调度+目标服务器）、警报（Alert，按事件号/严重级/性能条件触发）、操作员（Operator，通知路由：邮件/pager 老制）；通知面现代化后多接 webhook/工单系统 ⚠️ 转述。
- 事件驱动：错误号警报（如 823/824/825 严重 IO 错误、1205 死锁）接 08 章观测面——"警报=已知故障的自动初诊"⚠️。
- 作业历史与清理：`sp_purge_jobhistory` 节奏写进策略，msdb 膨胀是经典慢性病 ⚠️。

## 二、作业工程化清单

1. **失败语义先写**：每步骤的on_success/on_fail 跳转、重试（次数+间隔）——网络闪断类步骤给重试，数据正确性类失败**不要**重试 ⚠️。
2. **代理账户（Proxy）**：子系统需要特定凭据时用 Credential+Proxy 隔离，别让 Agent 服务账户兼职干杂活（最小权限回 06 章）⚠️。
3. **脚本版本化**：`CREATE JOB` T-SQL 入仓评审，SSMS 手点=不可审计 ⚠️（实践立场）；环境差异用变量模板处理。
4. **备份作业模板**（接 04 章）：FULL 周级+LOG 分钟级+DIFF 日级三段式，含"备份后校验+异地副本落位+还原演练季度提醒"三个尾巴 ⚠️。
5. **保养作业模板**（接 09 章）：统计巡检/索引节奏/QS 报告/DBCC CHECKDB 分级排班（PHYSICAL_ONLY 日、全检周）⚠️。
6. **密钥与证书到期提醒**（接 07 章）：把证书到期日做成警报——"锁好钥匙后把钥匙清单烧掉"的事故要防 ⚠️。

## 三、维护计划 vs 脚本 vs 社区框架

- 维护计划（Maintenance Plans，SSMS 图形向导生成 SSIS 包）⚠️：上手快、可控性弱、跨环境搬运差——小单机可，规模运维不推荐当主力。
- 自写 T-SQL/PowerShell：可控可评审，但要自建日志/重试/断点续跑——工程成本 ⚠️。
- 社区框架（Maintenance Solution 类开源脚本）：久经生产、参数化好，升级期做一次兼容复核 ⚠️ 指路（github: Ola Hallengren's SQL Server Maintenance Solution，未经逐 commit 核验仅作路标）。
- 路线判据 ⚠️（观点）：实例数 <10 用框架省事；>50 自建控制面（作业即代码+集中报表）；跨 Windows/Linux 混合车队时脚本层必须双栈。

## 四、多实例：老手艺与新工具

- 中央管理服务器（CMS）+注册组：一条 T-SQL 扇出到 N 实例取基线/配置 diff ⚠️ 转述——"这台为什么不一样"问题的官方廉价解。
- Policy Based Management：条件+面+评估模式三件套，把配置合规写成可持续评估的策略（防漂移）⚠️；与 02 章"配置审计面"直接衔接。
- 现代替代：GitOps 化的 DSC/Ansible 与专用 fleet 工具承担同样职责 ⚠️ 转述。

## 五、Linux 侧自动化世界

- 配置面：`mssql-conf` 文件+服务重启生效流 ✅ https://learn.microsoft.com/en-us/sql/linux/sql-server-linux-setup；与 Windows 注册表/SSMS 图形面是两套变更通道 ⚠️。
- 调度面：Linux 无 Agent 图形等价物——作业化用 cron/systemd timer+sqlcmd/mssql-tools 脚本承接；Agent 作业在 Linux 实例同样存在（2017+ 引入）但周边工具链不同源 ⚠️ 转述。
- 容器面：镜像+entrypoint 初始化脚本；持久卷与探针是 K8s 里 SQL Server 的两条腿 ✅ 概念 https://learn.microsoft.com/en-us/sql/linux/sql-server-linux-overview ⚠️ 细节以文档为准。
- 日志面：错误日志位置/权限模型与 Windows Eventlog 不同谱，采集器要分叉 ⚠️。

## 六、混合云：本地实例的云端延伸

- Azure VM 上的 SQL Server：IaaS 扩展（自动备份/补丁评估）与存储最佳实践（数据/日志/tempdb 分盘）⚠️ 转述。
- Synapse Link 出湖（01 章云桥主线）：近实时分析复制走 CDC 语义，运维关注初始同步窗口与变更积压 ⚠️ ✅ 总览 https://learn.microsoft.com/en-us/sql/sql-server/what-s-new-in-sql-server-2022。
- 备份到 URL + 异地：04 章备份链的云化出口；SAS/凭证轮换并入密钥台账（07 章）⚠️。
- 身份统一：Entra ID 让本地实例进 SSO/条件访问体系（06 章）⚠️。
- 边界提醒 ⚠️：混合不是"全云"——合规数据驻留、带宽成本与故障域独立性是 2024–2026 架构评审的三把常尺。

## 九、常见坑清单（⚠️ 转述整理，非原书条文）

1. **作业成功≠备份成功**：CHECKSUM/VERIFYONLY 尾巴没挂，绿的其实是坏文件 ⚠️（04 章联动）。
2. **警报只发邮件无人认领**：通知链路=废纸；值班表与升级路径要写进操作员定义 ⚠️。
3. **msdb 历史无限增长**：purge 策略缺位，作业列表卡成幻灯片 ⚠️。
4. **代理账户密码过期**：作业半夜静默失败，早晨集体补作业 ⚠️（06 章联动）。
5. **维护计划与脚本双轨并行**：同一库两拨保养互相踩窗口 ⚠️。
6. **Linux 侧照抄 Windows 作业思路**：systemd/cron 语义不同谱（环境变量/日志去向），移植要重验 ⚠️。
7. **混合云链路当内网用**：Synapse Link/备份到 URL 的带宽与延迟 SLA 没进容量表 ⚠️（六）。

## 核心概念速览（中英对照）

- **SQL Server Agent** — 实例值班管家：作业/警报/操作员三件套的执行服务。
- **作业** — Job：多步骤+调度+目标服务器的自动化单元。
- **警报** — Alert：按错误号/严重级/性能条件的事件触发器。
- **代理账户** — Proxy：子系统专用凭据，最小权限的执行马甲。
- **维护计划** — Maintenance Plan：SSMS 图形化 SSIS 保养向导。
- **CMS** — Central Management Server：一条语句扇出多实例的老手艺。
- **策略管理** — Policy Based Management：配置合规的持续评估框架。
- **mssql-conf** — Linux 配置入口：替代注册表/图形面的变更通道。
- **作业即代码** — Jobs as Code：T-SQL 脚本入仓评审的自动化工程观。
- **Synapse Link** — 云出湖通道：本地→云仓的近实时 CDC 复制。
- **备份到 URL** — Backup to URL：备份链的 Azure Blob 出口。
- **运维日历** — Operations Calendar：保养/演练/盘点节奏的总排期表。

## 最新演进与工业实践

- Agent 能力补齐：SSMS/文档线持续把作业面推向与 Windows 对等 ✅（agent 页 200 验真）；Linux 车队普遍用 cron+容器 sidecar 承接周边自动化 ⚠️ 转述。
- 自动化栈迁移：社区从纯 T-SQL 作业转向 PowerShell/dbatools（github: sqlcollaborative/dbatools ⚠️ 指路未逐 commit 核验）做跨平台备份/迁移/巡检编排。
- GitOps 化 DBA：作业脚本+策略断言进仓库，CI 校验后再部署——"数据库变更即基础设施代码"在 2024–2026 成为大厂常态 ⚠️ 转述；数据工程侧自动化视角的开源读物互读 [../DuckDB_in_Action/00-总览与阅读地图.md](../DuckDB_in_Action/00-总览与阅读地图.md)、[../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md](../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md)。
- Azure 混合服务面：SQL VM IaaS 扩展、托管实例的自动运维替代大量本地 Agent 作业；本地侧留下"可带走的脚本"是避免锁定（lock-in）的保险 ⚠️ 观点。
