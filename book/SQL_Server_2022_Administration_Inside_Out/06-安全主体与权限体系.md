## 一、认证：你是谁

- Windows（域/本地）认证与 SQL Server 认证（`sys.sql_logins`）双轨 ⚠️；混合模式才同时开门，纯 Windows 环境关掉 SA 与 SQL 认证是基线加固第一步 ⚠️。
- 登录≠用户：登录（login）是服务器级主体，进库要映射成数据库用户（user）——containment 部分 contained 用户可只存库内（迁移友好）⚠️。
- 密码策略挂钩 Windows（复杂度/过期）；证书/非对称密钥/Asymmetric Key 也可成为登录体（服务间认证冷门路）⚠️。
- Entra ID（原 Azure AD）接入：2022 起本地实例可用云身份做连接主体 ✅ 概念见 What's new ✅ https://learn.microsoft.com/en-us/sql/sql-server/what-s-new-in-sql-server-2022（Entra 集成条目）；具体授权链 ⚠️ 转述。

## 二、主体族谱与角色

- 服务器级：`sys.server_principals`——登录、固定服务器角色（sysadmin/security/serveradmin…）、服务器角色（自定义 SERVER ROLE）⚠️。
- 数据库级：`sys.database_principals`——用户、应用角色（APPROLE，无登录的"身份马甲"）、数据库角色（固定 db_owner/db_datareader… + 自定义）⚠️。
- 成员继承：角色是权限的"邮筒"——把人挂角色、给角色发权限，两线解耦是审计可维护性的根 ⚠️。
- 高危角色清单 ⚠️ 转述：sysadmin（无视一切检查）、securityadmin（可改自己权限≈变相 sysadmin）、db_owner（库内全能+可 ALTER DATABASE 面外溢）——季度盘点这三类成员是 Inside Out 式体检项。
- #56 内核册对应：主体的 SID/令牌如何穿过连接与上下文切换，见 [../SQL_Server_2012_Internals/01-体系结构与SQLOS.md](../SQL_Server_2012_Internals/01-体系结构与SQLOS.md) 的登录会话链 ⚠️；本节只讲"名分账本"。

## 三、权限代数：GRANT / DENY / REVOKE

- 三态语义 ⚠️：GRANT 给、DENY 一票否决（优先级高于任何 GRANT 路径）、REVOKE 撤销此前语句（不是 DENY 的反操作——"恢复未定义"而非"恢复允许"）。
- Securable 层级：实例 ⊃ 端点/登录/数据库 ⊃ 架构 ⊃ 对象 ⊃ 列——权限自上而下继承、DENY 就近否决 ⚠️；官方权限矩阵页（permissions 专页当前不可达，404 弃引 ⚠️ 缺口如实登记；概念以 Learn 站内 securable 层级图为准绳 ⚠️）。
- 模块签名与 EXECUTE AS：存储过程可"换马甲"以所有者上下文运行（签名证书发权限，免直接表权限外露）⚠️；`EXECUTE AS` 的上下文与回退（WITH CALLER/自毁句柄）是应用越权事故的高发区 ⚠️。
- 审计语句面：`sys.fn_builtin_permissions`、`DATABASE_PRINCIPAL_ID()`、权限视图三件套 ⚠️ 转述。

## 四、最小权限工程清单

1. 应用连接专用低权账户：只授 EXECUTE+必要 SELECT/DML，禁表直访 ⚠️。
2. 服务账户不进 sysadmin；链接服务器凭据（Credential）映射代理身份 ⚠️。
3. 数据库邮件/CLR/xp_cmdshell 按需开关：xp_cmdshell 默认关、开必审计 ✅ 配置面见 server-configuration-options ✅ https://learn.microsoft.com/en-us/sql/database-engine/configure-windows/server-configuration-options-sql-server。
4. 对象级权限用角色模板+脚本化发放，禁止手点 SSMS 对话框留无痕 ⚠️。
5. 每季度跑"权限快照 diff"（sys.database_permissions 全表存档对比）⚠️ 做法，非官方条文。

## 五、两道细筛：RLS 与动态脱敏

- 行级安全（RLS）：安全策略+谓词函数把"谁能看见哪些行"做成策略而非视图土法 ⚠️ ✅ https://learn.microsoft.com/en-us/sql/relational-databases/security/row-level-security。
- 动态数据 masking（DDM）：列上挂掩码函数，非特权主体查询自动脱敏；注意它是**展示层**遮蔽（SELECT INTO/BI 导出可绕过）不是加密 ⚠️ ✅ https://learn.microsoft.com/en-us/sql/relational-databases/security/dynamic-data-masking。
- RLS vs 视图 vs WHERE：三案的成本/可维护性对比是应用团队的经典三角选择 ⚠️——RLS 赢在"策略与 SQL 解耦"，输在谓词函数的执行计划可读性。
- 加密层（TDE/AE/Ledger）是"细筛之后"的另一族武器 → [07-加密防线与Ledger可信账本.md](07-加密防线与Ledger可信账本.md)。

## 七、常见坑清单（⚠️ 转述整理，非原书条文）

1. **DENY 想当然**：以为 DENY 库级能盖住对象级 GRANT——deny 生效于"授予路径"层面，具体到列/对象的授权要逐路径核 ⚠️。
2. **应用角色与 Windows 组混设**：APPROLE 激活后原用户权限挂起，报表作业"突然全灭" ⚠️。
3. **db_owner 发得太慷慨**：等于把库内安全模型外包给应用团队 ⚠️。
4. **执行上下文忘了回退**：EXECUTE AS 后没 CALLER/没签名，越权链在存储过程里传家 ⚠️。
5. **脱敏当加密卖**：BI 导出 `SELECT INTO` 绕过掩码，合规口径被拆穿 ⚠️（DDM 官方边界，见 ✅ masking 页）。
6. **contained 用户跨库信任断裂**：库自带身份搬家友好，但跨库资源访问语义完全不同 ⚠️。
7. **RCSI 与权限混淆**：快照隔离是并发模型不是可见性控制，RLS 才是行过滤 ⚠️（02/08 章联动）。

## 八、实操速查卡（⚠️ 社区通行写法示意，非本书实测）

```sql

FROM sys.server_principals sp LEFT JOIN sys.database_principals dp ON dp.sid=sp.sid;

SELECT * FROM sys.database_permissions WHERE class_desc='OBJECT_OR_COLUMN';
CREATE ROLE app_reader; GRANT EXECUTE, SELECT TO app_reader;
DENY VIEW DEFINITION TO guest;
```

## 核心概念速览（中英对照）

- **主体** — Principal：可被授/拒权限的身份单位（登录/用户/角色）。
- ** securable** — 安全对象：实例/库/架构/对象/列的权限挂载层级。
- **固定服务器角色** — Fixed Server Role：sysadmin 等内置权杖，盘点重点。
- **数据库角色** — Database Role：库内权限邮筒，自定义角色解耦审计。
- **DENY 优先级** — Deny Precedence：任一 DENY 路径否决全部 GRANT 路径。
- **contained 数据库** — Contained Database：用户只存库内、迁移即身份随行。
- **执行上下文** — Execution Context (EXECUTE AS)：模块运行时借用的身份马甲。
- **模块签名** — Module Signing：证书给过程发权限、不外露表级直访。
- **行级安全** — Row-Level Security (RLS)：谓词函数+安全策略构成的行过滤。
- **动态数据脱敏** — Dynamic Data Masking：按主体权限自动遮蔽列值（非加密）。
- **Entra ID 认证** — Microsoft Entra ID：云身份进入本地实例主体族。
- **xp_cmdshell** — 扩展存储过程 shell 面：默认关闭的高危开关。
- **孤儿用户** — Orphaned User：库内用户失去登录映射的断点态，迁库经典残留。
- **服务器角色** — Server Role：可自定义的服务器级权限邮筒（2012+ 分层补全）。
