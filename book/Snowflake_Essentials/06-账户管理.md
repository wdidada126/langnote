# 06 账户管理（Account Management）

> 原书章：Ch.6 "Account Management"（pp.115–137），DOI `10.1007/978-1-4842-7316-6_6` ✅（Crossref 章级寄存实证；预检命中章即此章）。
> 口径：页码区间一手实证；机制均为「官方文档转述 ⚠️ + ✅ URL」；云仓不可实测，无 🔧（分配见 00）。

## 阅读目标

1. 分清组织（Organization）/账户（Account）/云与区域（Region）/版本（Edition）四层选择树。
2. 会读账户级参数与资源监视器（Resource Monitor）的治理语义。
3. 建立"多账户策略"的入门直觉：环境隔离、区域驻留、版本分级。

## 1. 租户层级与选型维度

- **组织→账户**：一个组织下多账户，账单纯合并按组织出（⚠️ 转述，✅ https://docs.snowflake.com/en/user-guide/admin-account-management）。
- **云×区域（Region）**：账户创建时锁定云厂商与区域，决定数据驻留（合规第一约束）与跨区共享拓扑（⚠️，✅ https://docs.snowflake.com/en/user-guide/intro-regions）。
- **版本（Edition）**：Standard / Enterprise / Business Critical（成书口径含 VPS 变体；⚠️），差异挂三大件——Time Travel 上限（标准版 1 天 vs 企业版最长 90 天）、Failover/DR、安全增强（Tri-Secret、私有连接）（⚠️ 转述，✅ https://docs.snowflake.com/en/user-guide/intro-editions）。
- 易混点：版本不是"性能档位"（性能在仓库尺码，Ch.10）——版本买的是**功能与合规面**（⚠️）。

## 2. 账户标识、登录域与联系人

- 账户标识：组织名-账户名 → 登录 URL 前缀（Ch.2 呼应）；同组织内不可重名（⚠️，✅ admin-account-management）。
- 域名验证（自定义登录域）与 SSO 路由绑定，属账户管理外圈（⚠️，✅ https://docs.snowflake.com/en/user-guide/admin-domain-verification，经索引登记）。
- 计费联系人、试用期转正流程在 Admin→Account Details（⚠️ 考古+现行混合口径）。

## 3. 参数体系（⚠️ 转述，✅ https://docs.snowflake.com/en/sql-reference/parameters）

| 层级 | 设置方式 | 例子 |
| --- | --- | --- |
| 账户级默认 | `ALTER ACCOUNT` | 时区、网络策略、Data Retention in Days |
| 角色级 | `ALTER ROLE` | 会话默认仓库/库 |
| 用户级 | `ALTER USER` | 默认角色、MFA 开关 |
| 对象级 | `CREATE/ALTER <obj>` | warehouse 的 AUTO_SUSPEND |
| 会话级 | `ALTER SESSION` | 临时覆盖 |

- 动态参数（会话新建即生效）vs 静态参数（需对象重建）——排障时先查参数落点层级（⚠️）。

## 4. 资源监视器与信用治理

- Resource Monitor：绑账户或仓库，设信用阈值与动作（预警→ suspend→ 到 SUSPEND_IMMEDIATE 停全部计算），月度周期（⚠️，✅ https://docs.snowflake.com/en/user-guide/resource-monitors）。
- 成书期实践：给开发账户绑低阈值监视器防"账单事故"（Ch.2 易错 3 的制度解）（⚠️）。
- 2026 演进位：Horizon **Budgets** 把"监视器+告警+成本中心"整合进 UI（✅ https://docs.snowflake.com/en/user-guide/budgets）——本章概念的直接后代。

## 5. 多账户策略（⚠️ 转述）

- 环境隔离：dev/test/prod 分账户（数据不串、账单分账、故障域分离）vs 同账户分库——入门册给出前者为协作安全默认（⚠️ 评述）。
- 区域就近：消费者所在区域放副本账户 + 跨区共享/复制（Ch.14 呼应）。
- 试用→生产→并购：账户盘点表（区域/版本/联系人/监视器四列）是入门 DBA 的第一件行政工件（⚠️ 教学建议）。

## 6. 章内易错与疑问

- **易错 1**：区域选错想迁移——不可原地换区，只能新账户克隆+回灌（Ch.9 克隆在此复用，⚠️）。
- **易错 2**：把 Data Retention 调到 0 省 Time Travel 存储——顺带失去 UNDROP 与查询历史回溯窗口（⚠️，✅ data-time-travel）。
- **易错 3**：资源监视器绑仓库后以为"账户有底"——账户级阈值需单独绑（⚠️）。
- **疑问**：为什么账户管理单列一章而不并进安全？答：账户是**计费与驻留**单元，用户角色才是**授权**单元——治理轴不同（Ch.7 分野）。

## 扩展深读点：选型决策树与账户台账模板

### 账户四问决策树（⚠️ 综合本章口径）

```
新账户立项？
├─ 数据主权在哪？→ 区域/云选定（不可逆，先合规后性能）
├─ 需要 0–90 天回溯/Tri-Secret/读写分离副本？→ Enterprise/BC（版本三问见下）
├─ 环境隔离级别？→ dev/test/prod 分账户 vs 同账户分库（故障域×账单×权限三轴权衡）
└─ 谁兜底账单？→ Resource Monitor（账户级+仓库级各绑一个，勿只绑其一）
```

### 版本三问（Standard/Enterprise/BC 的入门版判据，⚠️ 转述）

1. Time Travel 需要超过 1 天吗？（决定 Enterprise 起）
2. 需要客户密钥参与（Tri-Secret）/私有网络链路（Privatelink）吗？（决定 BC 起）
3. 需要账户级复制/故障切换作 DR 吗？（Enterprise+ 能力面）

### 账户台账模板（入门 DBA 第一件行政工件）

| 字段 | 例值 | 来源 |
| --- | --- | --- |
| 组织-账户标识 | ORG-PROD | Ch.2 登录 URL 前缀 |
| 云×区域 | AWS us-east / 锁定不可迁 | Ch.6 |
| 版本 | Enterprise | Ch.6 三问 |
| 保留期/监视器阈值 | 30 天 / 10k credits 月 | Ch.6/9 |
| 计费联系人/PO | … | Snowsight Admin |

### 多账户成本一句话判断

- 分账户的账单代价是"监视器×N、联系人×N、参数基线漂移风险×N"，换来的是**故障域、合规驻留、分账三件确定性**——入门期用"环境×区域"两轴就够，第三轴（业务线）等组织树逼你再加（⚠️ 教学评述）。

## 最新演进与工业实践

- **成本治理换代（2024→）**：Resource Monitors 保留，但官方主推 Budgets（账户级+自定义、软/硬上限、按角色配额）（✅ https://docs.snowflake.com/en/user-guide/budgets）——本章的"账单事故防御"升级为声明式产品。
- **账户管理 UI 换代**：Classic 内嵌 Account Manager 下线（旧文档路径实测 404），账户操作并入 Snowsight Admin（✅ admin-account-management 现行页）。
- **跨区域读副本（⚠️ 主题登记）**：账户复制（Account Replication，✅ https://docs.snowflake.com/en/user-guide/account-replication-intro）把"区域就近"从手工双写变成托管主备——2022 年后成熟，本章未及。
- **工业实践**：平台工程团队以 Terraform/Flux 式声明管理账户矩阵（组织树、参数基线、监视器模板即代码）；FinOps 看板直接吃 `ORG_USAGE`/`ACCOUNT_USAGE` 视图（⚠️ 转述）——入门读者的账户管理预期已从"会点界面"提高到"能读账单 API"。
