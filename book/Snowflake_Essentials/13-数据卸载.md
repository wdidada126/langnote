# 13 数据卸载（Unloading Data）

> 原书章：Ch.13 "Unloading Data"（pp.283–298），DOI `10.1007/978-1-4842-7316-6_13` ✅（Crossref 章级寄存实证）。
> 口径：页码区间一手实证；机制「官方文档转述 ⚠️ + ✅ URL」；含 🔧 类比实验 G6 卸载半（本机 DuckDB 实跑，**非 Snowflake 行为**）；示意 SQL 自拟。

## 阅读目标

1. 默写卸载语法骨架：`COPY INTO @stage FROM <query> ...`，与装载章互为镜像。
2. 掌握多文件分片三旋钮：`MAX_FILE_SIZE`、`PARTITION BY`、并行度直觉。
3. 分清卸载的四大用途：归档、下游投递、湖侧导出、跨云搬家。

## 1. 镜像语法（⚠️ 转述，✅ https://docs.snowflake.com/en/sql-reference/sql/copy-into-location）

```sql
COPY INTO @DEMODB.SALES.MY_STAGE/exports/orders_
FROM (SELECT * FROM DEMODB.SALES.ORDERS WHERE placed_at >= '2022-01-01')
FILE_FORMAT = (TYPE = PARQUET)
HEADER = TRUE                       -- CSV/JSON 可加表头（Parquet 忽略）
MAX_FILE_SIZE = 64000000
PARTITION BY (placed_at::DATE)
OVERWRITE = FALSE;
```

- 与装载同族参数（FILE_FORMAT/PATTERN 语境互换），差异点三条：**FROM 可以是子查询**、HEADER/OVERWRITE/SINGLE_HEADER 只在此侧出现、输出可进内部或外部 Stage（⚠️，✅ https://docs.snowflake.com/en/user-guide/intro-summary-unloading）。
- 卸载同样消耗仓库、按秒计费——"导出是写操作也是算力开销"的入门账单认知（⚠️）。

## 2. 分片与并行（本章技术心脏）

- 单文件上限触发自动切片：`files/*.csv.gz` 序号命名（⚠️）；`MAX_FILE_SIZE` 设目标分片字节。
- `PARTITION BY (expr)` 按表达式**强制分文件**（如按日）——投递给按天消费的下游时首选（⚠️，✅ https://docs.snowflake.com/en/user-guide/data-unload-overview）。
- 并行度来源：仓库多集群/多节点对子查询的分片输出（成书口径 ⚠️）；大导出的吞吐调优在调优册"端到端"章展开。
- 格式选择口径（⚠️ 成书期）：CSV=人读/legacy 投递；JSON=API 形下游；**Parquet=列式大导出主推**（压缩+类型保真，跨云湖侧通用——演进节见其成为主干道）。

## 3. 取回文件与消费端

- 内部 Stage 下载：`GET @stage/file ./local/`（SnowSQL）或 Stage UI 浏览下载（⚠️，✅ https://docs.snowflake.com/en/user-guide/data-load-local-file-system-stage 经索引）。
- 外部 Stage 直读：导出到 S3/Blob/GCS 后下游原生消费，"卸载即发布"（⚠️）。
- 归档链：导出→对象存储生命周期策略降温——数仓与湖的成本接力（⚠️ 评述）。

## 4. 🔧 类比实验：卸载的两端在本机（非 Snowflake 行为）

本机 DuckDB 1.5.5 实跑（2026-10-02，输出摘录，与 12 章同一次运行）：

```
re-read: [(1, 'ann'), (2, 'bob')] parquet bytes: 332
```

- `COPY stg TO 'out.parquet' (FORMAT PARQUET)` ≈ `COPY INTO @stage ... TYPE=PARQUET`；`read_parquet` 回读验证往返保真——"导出→他人可读"的最小闭环心智。
- **非 Snowflake 行为声明**：本机一步直达文件系统，无 Stage/凭据体系、无 MAX_FILE_SIZE/PARTITION BY 分片协议、无 HEADER 家族开关、无计费与仓库参与。第 2 节三旋钮全部未被本机触及——导出的工程难度在"多文件协议与投递语义"，不在格式编码本身。

## 5. 章内易错与疑问

- **易错 1**：CSV 卸载忘 `HEADER=TRUE`、下游按名解析全挂；`SINGLE_HEADER=TRUE` 是"多文件只第一份带表头"的配套开关（⚠️ 成书后增补项，演进注）。
- **易错 2**：`OVERWRITE` 默认 FALSE——重跑同名即跳过，"为什么我的新数据没出去"的元凶（⚠️）。
- **易错 3**：子查询里用 `ORDER BY` 想稳定分片序——并行输出不承诺全局序，需 PARTITION BY 表达分片意图（⚠️）。
- **疑问**：卸载值得独立一章？答：成书期"仓→湖/下游"的搬家需求爆发，且语法镜像处陷阱密集；16 页恰是"导出不是装载倒放"的教材宣言（⚠️ 评述）。

## 扩展深读点：投递协议三查与格式选择表

### 对外投递三查（发布手册化，⚠️ 实践综合）

1. **幂等查**：重跑是否产生双份？`OVERWRITE` 策略+唯一命名分区（PARTITION BY 日期/客户）二选一；消费方按清单文件（manifest）核对。
2. **完整查**：行数/校验和/最大时间戳三指标随导出落盘——下游拒收有依据（Ch.12 对账的镜像）。
3. **可读查**：格式/压缩/表头与消费方解析器对表（HEADER 与 SINGLE_HEADER 的组合最易翻车，易错 1）。

### 格式选择表（⚠️ 成书口径+现况注）

| 格式 | 给谁 | 优势 | 注意 |
| --- | --- | --- | --- |
| CSV | 人/legacy 系统 | 通用 | 类型保真弱，需 HEADER |
| JSON | API 形下游 | 嵌套原生 | 体积大 |
| Parquet | 湖/分析引擎 | 列式压缩+类型保真 | 消费方需支持嵌套语义 |
| ORC/AVRO | Hadoop 谱系 | 生态位 | 成书期支持面较小 ⚠️ |

- 跨云搬家特例：导出对象存储+生命周期降温（§3 归档链）——"卸载即发布"与 Ch.14 "不搬家共享"构成导出需求的完整决策面。

### 卸载 FAQ 三问

- **Q1 导出要仓库吗？** A：要——COPY INTO @stage 是计算动作（读写+压缩），账单按秒计（Ch.10 联动）；这是"导出也要调优"的根因。
- **Q2 怎么保证下游拿到"完整一天"？** A：按日 PARTITION BY 收口+当日单仓批量导出+manifest 清单，三重奏胜过逐小时增量刷写（⚠️ 投递直觉）。
- **Q3 卸载文件要不要加密？** A：出仓即脱离平台加密域（信封加密管不到你的桶）——桶侧加密/脱敏列前置是合同条款高发点（Ch.7 边界外推，⚠️ 评述）。
- **Q4 能不能把卸载当共享用？** A：能但降级——导出即快照，失去 Ch.14 live 语义与细粒度授权；"该共享还是该导出"的分水岭：**消费方要不要实时、要不要你能撤权**。
- 收束一句：本章的 16 页真正教的是**边界感**——数据的仓内责任止于 COPY 完成，此后桶策略/生命周期/合同接管（⚠️ 评述）。

- 与 Ch.12 互为镜像的复习法：把两章的 File Format 参数表并排贴在一张 A4 上，装载侧缺的（TRANSFORM/增量）在右、卸载侧缺的（HEADER 家族/PARTITION BY）在左——一张纸带走全书 253–298 页的语法主干。

## 最新演进与工业实践

- **Parquet 主干道化（2022→2026）**：AVRO/Parquet 支持成熟、嵌套类型与压缩选项（✅ https://docs.snowflake.com/en/sql-reference/sql/copy-into-location 现行页参数族）；"Snowflake→湖"的导出默认答案从 CSV 换成 Parquet/Iceberg（⚠️ 社区共识）。
- **导出语义被共享蚕食**：Ch.14 的 live sharing 让"为消费而导出"的场景收缩，卸载回归**归档/合规快照/跨云容灾**三用途（⚠️ 评述）。
- **声明式回灌闭环**：unload→Iceberg 外部表/托管表回流成"开放格式摆渡"模式（✅ https://docs.snowflake.com/en/user-guide/open-data-sharing 经索引），与 Advanced 册 11 章推定深潜（⚠️ 降级册）互文。
- **工业实践**：投递协议三查（幂等 OVERWRITE/命名分区/校验清单）进发布手册；大导出用专用低配仓+夜间挂起窗口以隔离账单（Ch.10 知识的导出应用）（⚠️ 转述）。
