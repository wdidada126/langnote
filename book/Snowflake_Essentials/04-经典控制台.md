# 04 Web 界面：经典控制台（Snowflake Web Interface: Classic Console）

> 原书章：Ch.4 "Snowflake Web Interface: Classic Console"（pp.39–73），DOI `10.1007/978-1-4842-7316-6_4` ✅（Crossref 章级寄存实证）。
> 口径：页码区间一手实证；本章是全书**时代烙印最重**的一章——Classic Console 已于本笔记成文前退役（文档页 404 实证见演进节），内容以「成书期界面考古 ⚠️ + 现行文档对照 ✅」双轨书写；机制转述一律标 ⚠️。

## 阅读目标

1. 复原成书期（2022）主界面的四货架结构与导航逻辑。
2. 理解"货架→子页"如何对应账户管理动作（仓库/库/用户角色）。
3. 建立 Classic→Snowsight 的控件迁移映射，能读懂 2022 年前的教程截图。

## 1. 成书期地位：为什么单独开一章

- 本书写作时（2021 底寄存 DOI，✅ 00 取证），Classic Console 是**唯一 GA 界面**，Snowsight 还是章名带 "Preview App" 的预览品（第 5 章）——两章并立是过渡期快照。
- 35 页篇幅（pp.39–73）说明当时"界面即操作主战场"：入门者的大部分肌肉记忆在此养成。

## 2. 四货架结构（⚠️ 成书期考古转述，按公开截图与文档记忆重构）

| 货架 Shelf | 内容 | 对应本册章节 |
| --- | --- | --- |
| Home | 登录落地页、向导卡片 | Ch.2 |
| Data | 库/表浏览、Data Loader 向导 | Ch.8/12 |
| Workspace | Worksheets（SQL 工作表）+ Queries 历史 | Ch.9 |
| Admin | Warehouse / Databases / Users & Roles 三子页 | Ch.6/7/10 |

- Workspace 工作表：多语句编辑、`Cmd/Ctrl+Enter` 执行、结果表格下载 CSV（⚠️）。
- Admin→Warehouse：尺码 T 恤下拉、最小/最大集群数、挂起分钟数——与 `ALTER WAREHOUSE` 参数一一对应（✅ 参数表 https://docs.snowflake.com/en/sql-reference/sql/create-warehouse）。
- Admin→Users & Roles：图形化建用户、给角色授权——与 Ch.7 的 GRANT 语句双通道（⚠️）。
- 登录形态：`https://<account>.<region>.snowflake.com` 根路径即 Classic（⚠️；如今该域名整体归 Snowsight，见 05 章）。

## 3. Data Loader 向导（装载的 GUI 前身）

- 五步向导：选表 → 选文件（本地上传进内部 stage）→ 选文件格式 → 预览映射 → COPY（⚠️ 考古转述）。
- 本质是 `PUT + COPY INTO` 的表单封装——第 12 章命令行路径的 GUI 等价物（✅ https://docs.snowflake.com/en/sql-reference/sql/copy-into-table）。
- 局限（也是后来 Snowsight "Load Data" 重做的原因）：无法管理外部 stage、看不到管道历史（⚠️）。

## 4. 界面考古要点与易错

- **易错 1**：读到 2022 前教程里的 "shelves" 一词以为是比喻——它是 Classic 的正式导航术语（⚠️）。
- **易错 2**：在旧截图里找"角色层级可视化"——Classic 没有，需 SQL `SHOW GRANTS`；层级图是 Snowsight 后加（⚠️）。
- **考古方法论**：本章所有界面描述均为 ⚠️ 级（不可实测、原 UI 已下线）；需要界面证据时以盘上 TDG 11 章（Snowsight 主体）与现行文档为准（✅）。
- **疑问**：为什么保留本章而不并入 05？答：忠实原书目录结构；且"两界面并立"正是理解本书年代学的钥匙——旧运维手册、博客示例大量滞留 Classic 词汇。

### 术语考古小词典（旧教程黑话→今义）

- "Shelf/货架"→导航分组；"Data Product（Classic 旧义）"→Data Marketplace→**Collaboration Listings**（308 实证链见演进节）；"Preview App"→Snowsight 本体；"Card（仪表盘卡）"→Dashboards/Cards 现行族。
- 阅读 2021–2023 外部资料时的三步清洗：①UI 截图按上表对位；②术语换血按词典替换；③SQL/权限/装载语义原样保留——本章的教学价值即在于给你这套"考古滤镜"。

## 考古案例：如何读懂一张 2021 年的操作截图（方法论示范）

以"旧教程：在界面上挂起仓库"一张典型截图为例，演示四步考古法：

1. **定代**：看导航条有无 shelves 字样——有=Classic（本章）；左侧竖导航+卡片=Snowsight（05 章）。
2. **定位**：截图高亮区映射到货架——Warehouse 操作在 `Admin→Warehouses` 子页，下拉选 size、分钟框填 suspend。
3. **换语义**：把控件读成 SQL 意图——该页每个旋钮都是 `ALTER WAREHOUSE ... SET` 的参数（✅ create-warehouse 参数族），**控件会死、SQL 意图不朽**。
4. **验证现行**：到 Snowsight 对位页（04 §迁移表）确认能力仍在且行为一致；不一致处以 ✅ 文档为准、截图降级为"历史行为"。

**为什么值得练**：2022–2024 的社区材料库（博客/课程/认证真题截图）大量滞留 Classic 词汇；掌握本法后，本册 04 章就从"过时章"变成"全书唯一的文献学工具章"。

### 本章存废判断（元评论）

- 判据：概念寿命=SQL 语义 > 权限模型 > 界用术语 > 像素级 UI。本章四货架图属于最后一类——所以本目录把本章 35 页原文（pp.39–73）缩为"结构+迁移表+方法论"三件套，删无遗产的细节。

### 考古三步口诀（承案例小结）

- **一看导航定代，二读控件译 SQL，三验现行再动手**——三步走完，任何 2022 前界面材料都能安全降级为"意图说明文"。
- 配套习惯：给旧材料贴"UI 已废/SQL 仍活"双标签入团队 KB；引用旧截图必须附 Snowsight 对位链接（04 §迁移表编号即可用坐标）。
- 残余价值清单：本章仍值得整体保留的三件——①货架→功能域的心智映射（仓库/库/用户三管理面自此定型）；②Data Loader 五步=装载语义的白话版（Ch.12 复习用）；③"界面两章并立"的出版史样本（00 §10 年代学论据）。
