# 09 查询与克隆数据（Querying and Cloning Data in Snowflake）

> 原书章：Ch.9 "Querying and Cloning Data in Snowflake"（pp.197–222），DOI `10.1007/978-1-4842-7316-6_9` ✅（Crossref 章级寄存实证）。
> 口径：页码区间一手实证；机制「官方文档转述 ⚠️ + ✅ URL」；含 🔧 类比实验 G2/G3（本机 SQLite 实跑，**非 Snowflake 行为**）。

## 阅读目标

1. 掌握 DML 全家桶（INSERT/UPDATE/DELETE/MERGE）在"无索引无锁表焦虑"模型下的用法边界。
2. 会用 Time Travel 三件套：`AT/BEFORE` 查询、`UNDROP`、保留期设定。
3. 理解零复制克隆（zero-copy clone）的元数据本质与三大工程用途。

## 1. 查询与 DML（⚠️ 转述）

- SELECT 侧本章走标准 ANSI SQL + Snowflake 扩展（`ILIKE`、`QUALIFY`、半结构化路径 `col:tag`——Ch.11 前哨）（⚠️，✅ https://docs.snowflake.com/en/sql-reference/sql/select 经索引登记）。
- DML 侧：UPDATE/DELETE 即行级覆盖写新微分区（copy-on-write），无锁表窗口但**高频小批 UPDATE 会碎化微分区、伤裁剪**——调优册 04 章的病根在此（⚠️ 跨册伏笔）。
- MERGE 作为 CDC 落地标准件（`WHEN MATCHED/NOT MATCHED`），与 Stream 搭配成增量管道雏形（⚠️，✅ merge 命令页经索引）。

## 2. Time Travel：把"备份"变成查询语法（⚠️，✅ https://docs.snowflake.com/en/user-guide/data-time-travel）

```sql
-- 自拟示意：查昨天此刻的数据
SELECT * FROM DEMODB.SALES.ORDERS AT(OFFSET => -60*24);
-- 按时间戳查
SELECT * FROM DEMODB.SALES.ORDERS BEFORE(CONVERT_TIMEZONE('UTC','2022-02-01 12:00:00'));
-- 找回被删对象
UNDROP TABLE DEMODB.SALES.ORDERS;
```

- 保留期：默认 1 天；Standard 上限 1 天、Enterprise 0–90 天（Ch.6 版本约束在此兑现）；0=放弃保险但省存储费（⚠️）。
- 恢复边界：Time Travel 期内用户自助（UNDROP/AT）；期满进入 **Fail-safe**（约 7 天，仅官方可救，⚠️ 成书口径）——"自助窗口 vs 托管黑箱"的两段式设计。

## 3. 零复制克隆：元数据级快照（⚠️，✅ https://docs.snowflake.com/en/user-guide/object-clone）

- `CREATE TABLE/SCHEMA/DATABASE ... CLONE <src>`：只复制**元数据指针**，数据仍共享同一批微分区；源与克隆各自后续写入才产生分叉存储（⚠️）。
- 三用途：dev/test 环境秒级重建、发布前回归基线、故障时对照取证（可克隆历史版本做考古副本）。
- 克隆是 Time Travel 的"固化剂"：`CLONE ... AT(...)` 把任意时点钉成新对象（⚠️）。
- 计费直觉：克隆本身近乎零存储费，差异增量计费（⚠️）。

## 4. 🔧 类比实验：为什么"零复制"与"90 天回溯"是平台魔术（非 Snowflake 行为）

本机 SQLite 3.45.3 实跑（2026-10-02，输出摘录）：

```
== G2 clone analog: SQLite CTAS = physical copy ==
file grew 1871872 -> 3739648 bytes (+1867776) after CTAS
== G3 Time Travel analog: transaction rollback only ==
mid-txn rows: 19900
after rollback rows: 20000
journal_mode: ('wal',)
```

- **G2 解读**：SQLite 的 `CREATE TABLE t_copy AS SELECT *` 让库文件翻倍（+1.87MB）——传统引擎"复制=搬数据"；Snowflake 克隆只搬元数据、不搬字节。**类比的用处在于反衬：本机世界做不到，才见出"存储层驻留对象存储+多版本元数据目录"架构的含金量。**
- **G3 解读**：SQLite 仅在**当事务内**能 ROLLBACK（19900→20000 复原）；一旦提交，新连接无法回到任何历史时点（WAL 只保并发读一致，不保可查询旧版本）。Snowflake 把"回滚"延展为跨会话、0–90 天、SQL 可寻址的 Time Travel——同样是反衬而非验证。
- **非 Snowflake 行为声明**：以上实验在本机 SQLite 完成，无对象存储卸载、无版本链目录；数字只证明"复制即搬数据/提交即失旧版"的单机基线，供读者建立对照直觉。

## 5. 章内易错与疑问

- **易错 1**：把 CLONE 当备份策略——克隆不防"对象被彻底 PURGE"（保留期+Fail-safe 之后数据真删）（⚠️）。
- **易错 2**：克隆链上继续克隆的误解——克隆间无依赖性能惩罚是设计特性，但权限需重新 GRANT（克隆不继承授权语义，⚠️ 转述）。
- **易错 3**：UNDROP 只能在**当前 schema/库上下文**找回同名删除物，二次删除会覆盖旧版本可救位（⚠️）。
- **疑问**：UPDATE 频繁的业务表怎么救？答：控制批大小+按谓词列聚簇（→ Tuning 04/05 章）、或改 CQRS 式追加表（⚠️ 工程共识）。

## 扩展深读点：恢复 SOP 与克隆工程守则

### 事故类型→恢复动作 SOP（⚠️ 综合本章口径）

| 事故 | 黄金窗口 | 首选动作 | 兜底 |
| --- | --- | --- | --- |
| 误删表/schema/库 | 保留期内 | `UNDROP <obj>`（先核同名占位，易错 3） | 从克隆副本重建 |
| 误 UPDATE/DELETE 部分行 | 保留期内 | `AT/BEFORE` 查询圈出旧值→MERGE 回填 | 整表 `CLONE ... AT(...)` 后切换 |
| 需历史基线跑回归 | — | 克隆+transient 库组合（隔离且省费） | — |
| 超期数据找回 | Fail-safe（约 7 天，托管黑箱 ⚠️） | 提官方工单 | 无（此后真删除） |

- 窗口公式感：可自助期=`DATA_RETENTION_TIME_IN_DAYS`（账户默认 1、Enterprise 可调 0–90，Ch.6 联动）；克隆可把"任意时点"固化为长期对象——**Time Travel 是动词，克隆是名词**。

### 克隆工程守则三条（⚠️ 社区实践转述）

1. 命名带源与时刻（`<src>_CLONE_<yyyymmdd>`），台账登记克隆链（防 Ch.9 易错 2 的权限孤儿）。
2. 克隆≠备份：跨账户/跨区域副本交给 account replication 或导出（Ch.13），克隆只防"同账户内的时间事故"。
3. 影子库节奏：CI 每轮"clone→truncate/注入→测试→丢弃"，存储费只随 delta 走。

### 两句话记住本章心脏

- **Time Travel 管时间轴（找回过去），Clone 管空间轴（固化当下）**；账户保留期给前者定长，delta 存储给后者定价，Fail-safe 是两者都失效后的托管暗房（⚠️ 综合口径）。

## 最新演进与工业实践

- **克隆语义扩张（2022→）**：库/schema/表/动态表皆可克隆已成常态（✅ object-clone），并衍生 **account replication**（跨区域账户级读副本，DR 场景，✅ https://docs.snowflake.com/en/user-guide/account-replication-intro）——Time Travel 管"时点"、复制管"地点"的正交二维成型。
- **Fail-safe 叙事淡化（⚠️）**：对外宣传收敛到 Time Travel+备份产品化（Snowflake "Backups" 主题页经索引登记 https://docs.snowflake.com/en/user-guide/backups），托管兜底条款入合同细则。
- **Dynamic Tables 改写 DML 教义（2023→）**：增量管道官方化后，"高频 MERGE 手工件"降级为 legacy 模式（✅ 族页 https://docs.snowflake.com/en/user-guide/dynamic-tables/cloning 200 实证）；碎化治理则升级 **Adaptive Data Layout**（平台自动聚簇决策，⚠️ 转述）——本章两大痛点的两端都被产品吸收。
- **工业实践**：CI/CD 里"每测试轮 clone+truncate 影子库"、事故响应"UNDROP SOP + 克隆取证副本"是 2026 团队手册的常见两页（⚠️ 社区共识转述）。
