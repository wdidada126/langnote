# 14 数据共享、数据交换与市场（Data Sharing, Data Exchanges, and the Snowflake Data Marketplace）

> 原书章：Ch.14 "Data Sharing, Data Exchanges, and the Snowflake Data Marketplace"（pp.299–328），DOI `10.1007/978-1-4842-7316-6_14` ✅（Crossref 章级寄存实证）。
> 口径：页码区间一手实证；机制「官方文档转述 ⚠️ + ✅ URL」；全章无 🔧（类比组分配见 00）；示意 SQL 自拟。

## 阅读目标

1. 讲清"不复制数据即可共享"的机制三角：SHARE 对象 + 次级库 + live 引用。
2. 会搭最小共享链（提供方/消费方双侧），并说出安全视图的过滤角色。
3. 分场景：私有数据交换（Organization 内/伙伴）⇄ 公开市场（Marketplace）⇄ 无账户读者的 Reader Account。

## 1. 机制内核：共享=授权的另一张脸（⚠️ 转述，✅ https://docs.snowflake.com/en/user-guide/data-sharing-intro）

- 提供方三步（自拟示意）：

```sql
CREATE SHARE MY_SHARE;
GRANT USAGE ON DATABASE DEMODB TO SHARE MY_SHARE;
GRANT USAGE ON SCHEMA DEMODB.SALES TO SHARE MY_SHARE;
GRANT SELECT ON TABLE DEMODB.SALES.ORDERS TO SHARE MY_SHARE;  -- 或安全视图
```

- 消费方一步：`CREATE DATABASE DEMODB_SHARED FROM SHARE provider_org.provider_acct.MY_SHARE;` → 得到**次级库**（Ch.8 埋线回收），此后提供方侧数据变化**实时可见**——无快照、无搬运（⚠️，✅ https://docs.snowflake.com/en/user-guide/data-sharing-provider）。
- 计费与治理要点：消费方查询用自己的仓库付算力，提供方不担消费计算；共享对象仍可被消费方误用面靠授权粒度控制（⚠️ 免责式共享=只授视图）。
- **Reader Account**：给无 Snowflake 账户的对手开轻量账户读共享（成书期能力 ⚠️，✅ https://docs.snowflake.com/en/user-guide/data-sharing-reader-create 经索引）。

## 2. 过滤共享与行级安全（⚠️，✅ https://docs.snowflake.com/en/user-guide/data-sharing-secure-views）

- 安全视图（Ch.8 定义在此兑现）：`CREATE SECURE VIEW V_ORDERS_FR AS SELECT * ... WHERE country='FR'`，消费方只见命中行、无法从计划/元数据反推过滤逻辑（⚠️）。
- 组合拳：按客户出视图矩阵 vs 掩码策略共享（后代方案，演进节）——"共享前整形"与"共享中策略"两条路线（⚠️）。

## 4. 章内易错与疑问

- **易错 1**：以为共享要"导出/投递"——机制是元数据授权+读时跨账户引用，Ch.13 卸载是另一条路（对照记忆）。
- **易错 2**：直接共享基表忘 schema USAGE——SHARE 授权链与用户授权链同构（Ch.7 词汇复用）。
- **易错 3**：把 live 共享当版本快照——消费方看到的永远是**当下**，需合同层面约定变更责任（⚠️ 治理评述）。
- **疑问**：为什么入门册把共享写成压轴章？答："数据云=平台+协作网络"（Ch.1 总纲）的实证闭环，也是 Snowflake 区别于一切传统数仓的招牌能力（⚠️ 编排评述）。

### 运营 FAQ

- **Q1 消费方把次级库当备份用？** A：live 语义决定其非快照——需时点固化就让消费方在自己账户 `CLONE`（Ch.9 能力跨库生效，⚠️）。
- **Q2 共享侧权限改了何时生效？** A：GRANT/REVOKE 即时作用于后续查询；消费方会话可能持旧上下文——排障先看 `SHOW GRANTS ON SHARE`（Ch.7 词汇）。
- **Q3 市场挂牌的技术前提？** A：一个干净的 schema+安全视图/脱敏表+列表描述——"共享前整形"的工程化版本；计费型列表另涉商务条款（⚠️ 成书期雏形注）。

## Live 共享治理四则（把"易错 3"变成制度）

1. **合同层**：共享对象清单（share inventory）随协议附件冻结，增删走变更单——live 语义意味着"你随时可能在改别人的生产"。
2. **结构层**：消费方只见专用 schema（共享前整形），基表 schema 永不出让——比逐对象打勾防误操作。
3. **变更层**：列增删/重命名前先查消费方依赖（安全视图定义可 `SELECT GET_DDL('VIEW',...)` 侧审），破坏性变更双跑一段。
4. **计量层**：提供方无法直接看到消费方查询账单，但可共享审计与列表运营指标对接——协作商务面由此长出（⚠️ 治理评述，演进节 Listing 运营同理）。
