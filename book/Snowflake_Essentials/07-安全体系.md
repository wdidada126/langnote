## 阅读目标

1. 画出系统角色与自定义角色的分层图，说出 GRANT 链的方向纪律。
2. 区分四道外部防线：认证（MFA/SSO/密钥对）、网络策略、加密、访问审计。
3. 建立"最小特权 + 角色链"的入门工程习惯。

## 1. 主体模型：用户与角色（⚠️ 转述，✅ https://docs.snowflake.com/en/user-guide/security-access-control-overview）

- 用户=登录主体；**权限全部挂角色**，用户经角色得权——直挂用户是反模式（⚠️ 纪律）。
- 系统角色：`ORGADMIN / ACCOUNTADMIN / SECURITYADMIN / USERADMIN / PUBLIC`（前四者可被"链入"，PUBLIC 人人继承）（⚠️）。
- 角色链模式：`SYSADMIN ← DEVELOPER ← 业务角色`，管理面与数据面分离——TDG 05 章同款口径（⚠️）。
- 用户类型三分：person / service（程序化，密钥对）/ password（legacy 口径）（⚠️，✅ https://docs.snowflake.com/en/user-guide/admin-user-management）。

## 2. GRANT 语义（自拟示意 SQL，非书中原文）

```sql
CREATE ROLE ANALYST_RO;
GRANT USAGE ON WAREHOUSE ANALYST_WH TO ROLE ANALYST_RO;
GRANT USAGE ON DATABASE DEMODB TO ROLE ANALYST_RO;
GRANT SELECT ON ALL TABLES IN SCHEMA DEMODB.SALES TO ROLE ANALYST_RO;
GRANT ROLE ANALYST_RO TO ROLE PUBLIC;      -- 或到人：GRANT ROLE ... TO USER alice
```

- 注意 `ON ALL TABLES IN SCHEMA` 只覆盖**当时存在**的对象，未来新表需 `GRANT ... FUTURE GRANTS`（⚠️ 入门第一大坑，✅ security-access-control-considerations）。
- 权限粒度：对象级 USAGE/SELECT/... 与层级继承（库→schema→表非自动，逐级授）（⚠️）。

| 通道 | 成书期 | 2026 |

## 4. 网络与加密

- **网络策略**：账户级/子网级 ALLOWED/BLOCKED IP 列表 + 二级因子网络策略（"网外必须 MFA"组合，⚠️，✅ https://docs.snowflake.com/en/user-guide/network-policies；后代：Network Policy Advisor，经索引登记）。
- **加密**：传输 TLS、静态 AES-256 信封加密、密钥自动轮换、Snowflake 全托管无客户可见密钥（BC 版本 Tri-Secret Secure 客户参与解锁链）（⚠️，✅ https://docs.snowflake.com/en/guides-overview-secure）。
- **审计面**：`QUERY_HISTORY / LOGIN_HISTORY / ACCESS_HISTORY` + Snowsight Activity（⚠️，✅ https://docs.snowflake.com/en/user-guide/access-history）。

## 5. 章内易错与疑问

- **易错 1**：给角色授库 USAGE 忘授 schema USAGE——层级两缺其一即不可见（⚠️）。
- **易错 2**：网络策略只加 ALLOWED 忘 BLOCKED 0.0.0.0/0——默认全通语义误读（⚠️ 排障高频）。
- **易错 3**：把 PUBLIC 当 guest 沙盒——它人人继承，别往上挂敏感权（⚠️）。
- **疑问**：为什么安全章 36 页、对象章 21 页？答：Apress 六顾问合写把"企业采购焦虑面"（认证/网络/审计）写得最厚——恰反映 2022 年云仓进企业的关键阻力在安全论证（⚠️ 评述）。

## 扩展深读点：角色链样例与安全排障表

### 一套可直接默写的最小角色链（⚠️ 综合本章口径，自拟示意）

```
ACCOUNTADMIN（仅管理员日常登录之外的应急面）
 └─ SECURITYADMIN ──创建/授予自定义角色──┐
 └─ USERADMIN ──建用户并指派默认角色─────┤
     SYSADMIN（对象所有者主流角色）       │
      └─ ANALYST_RO ← GRANT USAGE/SELECT ─┘（Ch.2 的 DEMODB 全挂这里）
          └─ PUBLIC（只链入"人人可看"层，敏感权绝不入）
```

- 纪律三条：人经角色间接触权；对象尽量归 SYSADMIN/专用属主角色（防"私有对象孤儿"）；改默认角色链用 `GRANT ROLE ... TO ROLE ...`，用户仅 `GRANT ROLE ... TO USER`。

### 安全排障速查表（入门高频五案）

| 症状 | 第一假设 | 验证动作（⚠️） |
| --- | --- | --- |
| 表在但查不了 | schema USAGE 缺（易错 1） | `SHOW GRANTS OF ROLE` 逐级核对 |
| 新表集体失踪 | 只授了 ON ALL（易错 Future） | `GRANT ... ON FUTURE TABLES` |
| 同人不登录=网络问题 | 网络策略只 ALLOWED 未收口 | 核 ALLOWED/BLOCKED 与 second factor 规则 |
| 服务账号 401 | 密钥对过期/公钥未挂 | `DESCRIBE USER` 看 RSA_PUBLIC_KEY 指纹 |
| MFA 弹而不通 | Authentication Policy 绑错层级 | 核 账户/角色/用户 三层的策略落点 |

### 安全论证文书四问（2022 年上云评审的本章映射）

1. 数据在谁家/哪区？→ 平台加密托管+区域锁定（Ch.3 存储层、Ch.6 区域）。
2. 谁能看见什么？→ 角色链+未来授权纪律（§1–2）。
3. 从哪能登录？→ 网络策略×认证策略双闸（§3–4）。
4. 出了事怎么追责？→ ACCESS_HISTORY/Login History 留痕（§4 审计面）。

- 本章 36 页厚度的读法：把 §1–4 当"技术层"、把四问当"采购层"——同一套能力两种目录，答辩与落地都够用。

## 最新演进与工业实践

- **策略面大扩容（2022→2026）**：RBAC 之外长出一整层**数据访问策略**——掩码策略（✅ https://docs.snowflake.com/en/user-guide/tag-based-masking-policies）、行访问策略、聚合策略、对象标签（Aggregation Policy 经索引登记）；成书期"安全=身份+网络"的教义已扩为"身份+网络+列行级数据治理"。
- **Horizon 治理产品化（2024→）**：上述策略+分类分级+合规中心打包为 Horizon（✅ https://docs.snowflake.com/en/guides-overview-govern 经索引），审计默认全开成一等公民。
- **认证硬化（⚠️）**：密码逐步退场（策略强制 MFA/PMK；服务主体走密钥对/程序化身份，✅ https://docs.snowflake.com/en/user-guide/api-authentication 主题）；SCIM+SSO 成企业标配三件套。
- **工业实践**：角色模板即代码（Terraform）+ 权限漂移检测（对比 `GRANTS_TO_ROLES` 快照）；最小特权审查周期化——本章的"纪律"在 2026 年已产品化为可扫描的工件（⚠️ 转述）。
