# 03 数据云架构（Snowflake Data Cloud Architecture）

> 原书章：Ch.3 "Snowflake Data Cloud Architecture"（pp.25–37），DOI `10.1007/978-1-4842-7316-6_3` ✅（Crossref 章级寄存实证）。
> 口径：页码区间一手实证；机制描述全部为「官方文档转述 ⚠️ + ✅ URL」；云仓不可实测，本章 🔧 段用本机 DuckDB 1.5.5 做**概念类比（非 Snowflake 行为）**。

## 阅读目标

1. 画出三层架构图并说出每层的物理载体（对象存储/云厂商 VM/托管服务）。
2. 解释微分区、自动裁剪、聚簇三件套如何替代手工索引。
3. 分清"三层"与"四组件"两种讲法的对应关系。

## 1. 三层结构（官方关键概念页口径）

```
┌─────────────────────────────────────────────┐
│ Cloud Services Layer 云服务层（托管）          │  SQL 优化器/事务/元数据/认证
│   └─ "Shared Services"：微分区统计、Time Travel│  ✅ intro-key-concepts
├─────────────────────────────────────────────┤
│ Virtual Compute Layer 虚拟计算层               │  多集群 MPP 仓库（EC2/Blob/GCS 上的 VM）
│   └─ T恤尺码 XS..4XL + 1..10 集群             │  （Ch.10 深讲，⚠️）
├─────────────────────────────────────────────┤
│ Database Storage Layer 存储层                  │  云对象存储上的加密微分区
│   └─ 列式压缩、自动切分、自动重聚簇              │  （⚠️ 转述）
└─────────────────────────────────────────────┘
```

- 三层各自独立伸缩：这是 Ch.1 "解耦"的结构性展开（✅ https://docs.snowflake.com/en/user-guide/intro-key-concepts）。
- 本书另一处（TDG 同题材）称四组件（Storage/Compute/Cloud Services/数据消费者 UI），与本册三层不矛盾，只是把 UI 单列（⚠️ 辨析登记）。

## 2. 存储层：微分区与自动裁剪

- 装载时数据被切成 **50–150MB 压缩微分区**（⚠️ 成书口径数字），每分区维护列级 min/max、distinct 等统计（⚠️）。
- 查询谓词按统计做**分区裁剪（partition pruning）**：不命中的分区根本不读——这就是"无索引"的谜底之一（⚠️ 转述，✅ https://docs.snowflake.com/en/user-guide/performance-query-warehouse-size 系列页）。
- **自然聚簇 vs reclustering**：装载顺序决定初态簇度；平台后台按需重聚簇（Enterprise 起聚簇键，⚠️ 版本门槛转述）。
- 存储层对用户的暴露面只有"压缩后字节数"——计费项，不是运维项（⚠️）。

## 3. 🔧 类比实验：本机 DuckDB 的 row-group zone map（非 Snowflake 行为）

云仓不可实测；用已装 DuckDB 1.5.5 复现"列存统计裁剪"的**概念原型**（2026-10-02 本机实跑，输出摘录）：

```
duckdb 1.5.5 | sqlite3 3.45.3
== G1 zone map / pruning analog (DuckDB row groups) ==
filtered count: (501,) wall 0.0030s
PLAN: ['│   Type: Sequential Scan   │', '│          Filters:         │']
```

- 实验内容：200k 行表按 `BETWEEN 100000 AND 100500` 过滤，501 行、亚毫秒；EXPLAIN 显示顺序扫描带 Filters（DuckDB row group 级 zone map 自动生效，无需建索引）。
- 类比点：与微分区 min/max 裁剪同属"**统计代替索引**"流派（概念类比）。
- **非 Snowflake 行为声明**：DuckDB 是嵌入式进程内分析引擎——无对象存储卸载、无多集群、无按秒计费、无云服务商；行数规模与分区大小均与 Snowflake 微分区规格不同。本实验仅演示裁剪思想，不构成对 Snowflake 机制的任何验证。

## 4. 计算层与服务层要点（各章回看锚）

- 计算层：仓库=可启动/挂起的 MPP 集群；同数据多仓库并发读写靠服务层事务与克隆（Ch.9/10）。
- 服务层：全局元数据目录（含 Time Travel 版本链，Ch.9）、优化器、SQL 解析、认证授权（Ch.7）、自动诊断（Query Profile，Tuning 册对象）。
- 缓存三层直觉：本地 SSD 数据缓存（仓库内）→ 结果缓存 → 查询结果缓存 24h（⚠️ 数字为成书口径转述）。

## 5. 章内易错与疑问

- **易错 1**：以为"没有索引=没有优化空间"——正解：优化=让数据装载顺序贴合过滤列（聚簇键），见 [../Tuning_the_Snowflake_Data_Cloud/04-微分区.md](../Tuning_the_Snowflake_Data_Cloud/04-微分区.md)。
- **易错 2**：把云服务层当成"可以扩容的对象"——它对用户不可见、不可配，唯一旋钮在仓库侧（⚠️）。
- **疑问**：shared-nothing 派会问"数据在对象存储上，扫描带宽从哪来？"——答：仓库本地 SSD 缓存 + 并行预取；这就是 scale-up（大仓库）与反复查询变快的原因（⚠️ 转述）。

## 扩展深读点：一条查询的三层穿行记（机制串联）

以 `SELECT count(*) FROM ORDERS WHERE placed_at >= '2022-01-01'` 为例走完整链（⚠️ 转述综合）：

1. **接入**：Snowsight/SnowSQL → 认证（Ch.7）→ 服务层解析 SQL、校验对象权限与当前角色上下文。
2. **规划**：服务层优化器读**全局元数据**（表版本链、微分区统计），生成裁剪后的分区清单与执行计划；若结果缓存命中则直接返回（Ch.10 三件套）。
3. **供算**：DML/查询需 RUNNING 仓库——SUSPENDED 则按 AUTO_RESUME 拉起（启动延迟在此，Ch.2 FAQ 机制版）。
4. **扫描**：计算集群从对象存储拉目标微分区，命中列进本地 SSD 缓存——首查慢/再查快的分层缓存现场（本节易错 2 的答案）。
5. **提交**：结果回服务层记账（QUERY_HISTORY credits_estimated），更新元数据快照版本——为 Ch.9 的 Time Travel/克隆提供可寻址的"下一版"。

**读法提示**：五步里用户能配置的只有第 3 步（尺码/集群/挂起）与第 1 步（授权）——"三层架构"的入门体感就是"你只摸得到两层半"。

## 架构流派对照卡（读本章的定位镜）

| 流派 | 代表 | 分片/分布 | 与 Snowflake 关系 |
| --- | --- | --- | --- |
| Shared-nothing MPP | 传统一体机数仓 | 数据按节点分片 | 被"中央对象存储"替代（免 rebalance） |
| Shared-disk | 经典 RAC 类 | 共享块存储 | 形似神异：Snowflake 共享的是对象存储+托管元数据 |
| Lakehouse 派 | Iceberg/Delta 生态 | 开放表格式于对象存储 | 2022 年并行叙事，后经托管表合流（演进节） |
| Snowflake 三层 | 本册 Ch.3 | 微分区+多集群共享数据 | 自成谱系：兼取两派运维面与一派开放性 |

## 核心概念速览（中英对照）

| 中文 | 英文 | 一句话定义 |

| 云服务层 | Cloud Services Layer | 元数据/事务/优化器/认证的托管大脑 |

## 最新演进与工业实践

- **自适应计算（Adaptive Compute，2024→）**：仓库尺码概念被平台自动代理（ sizing/多集群/挂起全托管，管理员看"Query Engine Metrics"），本章"人肉选尺码"教学口径已进入历史；文档 IA 亦重组为 performance-query-warehouse-* 系列（✅ https://docs.snowflake.com/en/user-guide/performance-query-warehouse-size）。
- **开放表格式分流**：Iceberg 托管表把"存储层=私有微分区"的绝对性打开缺口，冷数据可驻留开放格式、热数据回填（✅ 索引入口 https://docs.snowflake.com/en/user-guide/open-data-sharing）；盘上 Advanced 册 11 章有推定深潜（⚠️ 降级册）。
- **向量/AI 负载改架构叙事**：对象存储+计算层之上叠加 Cortex 推理面（✅ https://docs.snowflake.com/en/guides-overview-ai-features）——2022 年架构图中不存在的一层。
- **不变的教学内核**：三层图与"统计替代索引"仍是所有官方培训（SnowPro Core 大纲）第一章的骨架（⚠️ 转述）；本册 + TDG + Tuning 三处的架构章互读即得完整横截面。
