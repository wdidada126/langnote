## 核心精讲

### 1. 三态对象＝三档"保留承诺"
| 形态 | Time Travel 上限 | 存储计费 | 典型用途 |
| --- | --- | --- | --- |
| Permanent | 随账户版本（标准 1 天/企业至多 90 天 ⚠️） | 是 | 生产正式表 |
| Transient | 0–1 天（无 Fail-safe ⚠️） | 是（数据）+元数据 | 中间层、可重算数据 |
| Temporary | 0 | 仅会话内元数据 | 会话级暂存，会话结束即灭 |

保留语义细节以官方 https://docs.snowflake.com/en/user-guide/tables-temp-transient ✅ 与
https://docs.snowflake.com/en/user-guide/data-time-travel ✅ 为准（转述 ⚠️）。

### 2. 命令面速写（教学示意，非书中原文）
```sql
USE ROLE SYSADMIN; USE WAREHOUSE COMPUTE_WH;
CREATE OR REPLACE TRANSIENT DATABASE DEMO3B_DB;
CREATE SCHEMA DEMO3B_DB.SALES;
CREATE TABLE DEMO3B_DB.SALES.ORDERS(
  id BIGINT PRIMARY KEY DEFAULT 0        -- PK 不校验重复 ⚠️（注释性约束）
 ,amount DECIMAL(18,2) NOT NULL          -- NOT NULL 是强校验 ⚠️
 ,raw VARIANT);                          -- 半结构化列（第 4 章主场）
CREATE VIEW V_ORDERS_OK AS SELECT * FROM ORDERS WHERE amount > 0;
CREATE MATERIALIZED VIEW MV_DAY AS
  SELECT dt, SUM(amount) AS amt FROM ORDERS GROUP BY dt;   -- 物化视图改写查询 ⚠️
CREATE STAGE MY_STG;
CREATE FILE FORMAT MY_CSV TYPE='CSV' FIELD_DELIMITER=',' SKIP_HEADER=1;
CREATE STREAM ORDERS_CHG ON TABLE ORDERS;           -- 消费增量
CREATE TASK T_MERGE WAREHOUSE=COMPUTE_WH SCHEDULE='USING CRON 0 * * * * UTC'
  AS MERGE INTO ORDERS_DWD t USING ORDERS_CHG s ON t.id=s.id
     WHEN MATCHED THEN UPDATE SET amount=s.amount
     WHEN NOT MATCHED THEN INSERT (id, amount) VALUES (s.id, s.amount);
```

### 3. Stream + Task＝官方"穷人版 Flink"
STREAM 记录自上次消费以来的 DML 变更（insert/delete/update 行对，metadata 列 `$UPDATE_TYPE` ⚠️ 转述），
TASK 是带调度/依赖的 SQL 执行器。二者组合支撑 medallion（bronze→silver→gold）分层刷新——
同一思想在开放湖仓的开源替身是 **Hudi 增量查询 / Iceberg change feeds / Delta CDF**：
[../Delta_Lake_Definitive_Guide/07-高级特性-DV与CDF.md](../Delta_Lake_Definitive_Guide/07-高级特性-DV与CDF.md)、
[../Apache_Hudi_Definitive_Guide/04-从Hudi读.md](../Apache_Hudi_Definitive_Guide/04-从Hudi读.md)。

## 常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "PK/FK 会阻止脏数据" | 仅元数据声明，供 BI/优化器参考；完整性自己保证 |
| "物化视图要手动刷新" | 基表 DML 后由系统维护，但会产生额外 credit（第 8 章归因） |
| "STAGE 就是文件系统" | stage 是带权限/加密的对象；外部 stage 也只是指向云存储的句柄 |
| "STREAM 一直攒着没事" | 未消费的流阻碍基表保留清理的语义要盯（转述 ⚠️，细节以官方流文档为准） |
| "Temporary 表省所有钱" | 省存储不省计算：写临时表照样烧仓库 credit |

## 核心概念速览（中英对照）

1. **可授权对象** — securable object：可被 GRANT 的账户内实体总称。
2. **永久/瞬态/临时数据库** — permanent / transient / temporary database：三档保留承诺的对象形态。
3. **模式** — schema：库内容器；标准模式与 Duplicate（共享）模式两类。
4. **约束（注释性）** — informational constraints：PK/FK 不校验；NOT NULL 强校验。
5. **标识列** — identity column：AUTOINCREMENT 的全局唯一代理键。
6. **物化视图** — materialized view：预聚合且自动维护、可参与查询改写。
7. **安全视图** — secure view：不泄漏定义、行级 MAC 的载体。
8. **阶段（对象）** — stage：内部/外部文件暂存点，COPY 的两端。
9. **文件格式对象** — file format：CSV/JSON/Parquet/ORC/Avro/XML 的解析器声明。
10. **流（对象）** — stream：表/视图之上的变更数据捕获（CDC）游标。
11. **任务（对象）** — task：受调度的 SQL 作业单元，支持依赖 DAG。
12. **UNDROP** — undrop：把 DROP 掉的对象从保留态拉回。
13. **血缘图** — lineage graph：Snowsight 的对象依赖可视化。
