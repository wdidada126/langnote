## 核心精讲

### 1. 微分区：机制卡片（✅ 数字直引官方页）
> "micro-partition contains between **50 MB and 500 MB of uncompressed data**（压缩后更小），列式存放，
> 每个分区自动记录各列值域等元数据；**无需用户定义或维护**分区。"
> —— https://docs.snowflake.com/en/user-guide/tables-clustering-micropartitions ✅200（转述大意）

推论：
- 装载顺序≈物理顺序：`ORDER BY` 在 COPY/INSERT 里决定初始聚簇质量（书中惯用技巧）。
- 过滤列与写入排序不对齐 → 值域互相覆盖 → 裁剪失效 → 扫描量爆炸。教科书镜像：数据布局与索引选择
  → [../数据库系统概念6/11-索引与散列.md](../数据库系统概念6/11-索引与散列.md)。

### 2. 聚簇诊断与手术
```sql
-- 教学示意，非书中原文
CREATE TABLE EVENTS (...) CLUSTER BY (dt, region);            -- 建表即声明
ALTER TABLE EVENTS CLUSTER BY (dt);                           -- 在线改
SELECT SYSTEM$CLUSTERING_INFORMATION('EVENTS','(dt)');        -- 命中率/分区数/深度画像
-- 聚簇健康度还有第二诊断函数 SYSTEM$CLUSTERING_PERCENTAGE（整体命中率一数值）⚠️
ALTER TABLE EVENTS RECLUSTER CUBE_SIZE = 1024000000
  WHERE dt >= '2026-01-01';                                   -- 手动手术；后台自动聚簇为持续计费 ⚠️
```
键选择法（书中方法论重述）：取**高频等值/范围谓词列**、按谓词组合顺序给键；
低选择率/频繁更新列慎入 ⚠️。对照：官方
https://docs.snowflake.com/en/user-guide/tables-clustering-keys ✅200。
**湖仓镜像**：Iceberg 隐藏分区=用表达式换"布局即查询习惯"；Delta Liquid Clustering=免选桶数；
Paimon=排序键。三家解法同题不同卷：
[../Apache_Iceberg活用入門/03-隐藏分区与分区演化.md](../Apache_Iceberg活用入門/03-隐藏分区与分区演化.md)、
[../Delta_Lake_Definitive_Guide/09-性能调优.md](../Delta_Lake_Definitive_Guide/09-性能调优.md)、

### 3. 搜索优化服务（Search Optimization）
为高频点查/全文包含（`CONTAINS`/`LIKE '%x%'`）建服务端优化结构；列上 `ADD SEARCH OPTIMIZATION`，
按索引字节收存储费 ⚠️。官方：https://docs.snowflake.com/en/user-guide/search-optimization-service ✅200。

### 4. 诊断命令面（Query Profile 时代）
- `EXPLAIN <query>`、Snowsight Query Profile（节点图+真实统计+问题行高亮）；
- `information_schema.query_history` / `ACCOUNT_USAGE.QUERY_HISTORY` 找 TOP 耗时/耗 credit 查询（ch09.sql 实抓样例即用此 ⚠️）；
- `QUERY_TAG` 归因 + `query_history_by_session`。教科书：执行计划与代价
  → [../数据库系统概念6/12-查询处理.md](../数据库系统概念6/12-查询处理.md)、[13-查询优化.md](../数据库系统概念6/13-查询优化.md)；
  MySQL 的 EXPLAIN 肌肉记忆迁移 → [../mysql/15-EXPLAIN详解.md](../mysql/15-EXPLAIN详解.md)。

### 5. 缓存与"预热"现象（转述 ⚠️）
结果缓存（同文命中，1 周窗）、本地缓存（仓库 SSD，随挂起衰减）、远程缓存（云存储读放大低）三层。
首查慢/二次快多半是裁剪+缓存共同作用；压测前需 warm-up 的设计是社区惯例 ⚠️。

### 6. 本地代理实验（不冒充 Snowflake）
用 DuckDB 在 10GB TPC-H 上：(a) 乱序 lineitem vs 按 l_orderdate 重排后，range 过滤的扫描字节差；
(b) 1 万小 Parquet vs 合并后查询时延——模拟"初始聚簇+小文件"两大命题。方法记录于此，结论不外推到 Snowflake ⚠️。

## 常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "没有索引所以查不动只能加仓库" | 先看裁剪失效三因：布局错/谓词含函数/类型隐转 |
| "聚簇键越多越好" | 键有优先级与组合爆炸，聚簇成本也计费 |
| "物化视图总是快" | 维护成本摊在基表 DML 上，低复用即亏 |
| "Query Profile 好看=便宜" | 快≠省：credit 按墙钟，多集群并发才是账单大头（第 8 章） |

## 核心概念速览（中英对照）

1. **微分区** — micro-partition：50–500MB（未压缩）自动列式存储单元，裁剪的基本粒度。
2. **数据裁剪** — pruning：以值域统计跳过无关微分区。
3. **聚簇** — clustering：把表数据按聚簇键物理重排（自动+手动 RECLUSTER）。
4. **聚簇信息** — SYSTEM$CLUSTERING_INFORMATION：命中率/深度/维护需求诊断函数。
5. **搜索优化服务** — search optimization service：点查/包含查询的托管索引式加速。
6. **查询画像** — Query Profile：执行计划可视化+运行时统计。
7. **EXPLAIN** — 预估计划查看命令（与真实 Profile 对照用）。
8. **结果缓存** — result cache：相同查询文本的结果短时复用。
9. **本地/远程缓存** — local/remote cache：仓库 SSD 与云存储读路径上的两级数据缓存 ⚠️。
10. **AUTO_ANALYZE** — 自动统计收集开关：影响优化器估卡 ⚠️。
11. **物化视图** — materialized view：预聚合改写候选（第 3 章定义，本章调优视角）。
12. **小文件问题** — small file problem：过度细碎输入损伤装载与查询双侧。
13. **查询标签** — query tag：性能与 credit 归因的挂钩。
