## 核心精讲

### 1. 保留时间线（一图背诵，转述 ⚠️，数字 ✅ 已核官方页）
```
DML/Drop 发生
   ├─ Time Travel 窗口（0–1 天默认；企业版至多 90 天）：任意 AT/BEFORE、UNDROP，用户可见可控
   ├─ Fail-safe（固定 7 天，不可查询不可 UNDROP，仅厂商协助/取证 ⚠️）
   └─ 彻底不可恢复 → 只能靠 外部导出/跨区复制/共享快照 兜底
```
官方源：https://docs.snowflake.com/en/user-guide/data-time-travel ✅200。
**本地对照（代理实验）**：MySQL undo retention/闪回窗口是同一问题的单机版 →
[../mysql/20-undo日志.md](../mysql/20-undo日志.md)、[../mysql/X1-时间追踪专题.md](../mysql/X1-时间追踪专题.md)；
教科书口径 → [../数据库系统概念6/16-恢复系统.md](../数据库系统概念6/16-恢复系统.md)。

### 2. Time Travel 三面用法
```sql
-- 教学示意，非书中原文
-- ① 查询面：改坏前的时点
SELECT * FROM ORDERS BEFORE(STATEMENT => '0190b0a5-...');   -- 按查询 ID
SELECT * FROM ORDERS AT(OFFSET => -60*30);                  -- 30 分钟前
-- ② DML 回滚面：从历史时点建影子表，再原子换名
CREATE OR REPLACE TABLE ORDERS_BAK AS
  SELECT * FROM ORDERS AT(TIMESTAMP => DATEADD('hour',-2,CURRENT_TIMESTAMP()));
ALTER TABLE ORDERS     SWAP WITH ORDERS_BAK;    -- 换名回滚，回滚点即 2 小时前
-- （书中惯用 CLONE 恢复与换名两条路径；具体语义以官方文档为准 ⚠️）
-- ③ 对象复活面
DROP TABLE ORDERS;           UNDROP TABLE ORDERS;
DROP SCHEMA S1;              UNDROP SCHEMA S1;          -- 连带子对象
DROP DATABASE D1;            UNDROP DATABASES LIKE 'D1';
```
机制注脚（转述 ⚠️）：微分区不可变 + 元数据版本链，使"倒回"零数据搬运；与开放格式对照：
Delta 的 `RESTORE`/时间旅行（[../Delta_Lake_Definitive_Guide/04-表维护-时间旅行与VACUUM.md](../Delta_Lake_Definitive_Guide/04-表维护-时间旅行与VACUUM.md)）、
Iceberg 快照回滚（[../Use_Iceberg_with_Spark/04-时间旅行与元数据表.md](../Use_Iceberg_with_Spark/04-时间旅行与元数据表.md)）、
Paimon 的 tag/branch（[../Apache_Paimon_Streaming_Lakehouse/10-Tag分支与时间旅行.md](../Apache_Paimon_Streaming_Lakehouse/10-Tag分支与时间旅行.md)）。

### 3. 零复制克隆（Zero-Copy Clone）
`CREATE TABLE T_DEV CLONE T_PROD`：只复制元数据指针，共享底层微分区；之后任一侧的修改才产生新存储；
克隆链上**不可再 Time Travel 越链**（细节 ⚠️ 以官方文档为准）。三大场景：
1. 生产数据秒级"逻辑拷贝"给开发/测试（不付两份存储）。
2. 升级/重构前的廉价快照点。
3. 配合共享做数据产品基线（第 10 章）。
对照实验（本地代理）：硬链接/CoW 文件系统或 `sqlite3 .clone` 思路演示"元数据分叉"——教学示意。

### 4. 保留期与成本的三角权衡
延长 DATA_RETENTION_TIME_IN_DAYS：弹性↑、误删保险↑、**存储费与"垃圾驻留"↑**；0 天库表则彻底省钱但裸奔。
第 8 章成本视图里"未用的保留存储"要在 ACCOUNT_USAGE 找出来 ⚠️。

### 5. 账户安全与合规面（转述 ⚠️）
- 静态加密（对象存储层自带）+ 传输 TLS；**密钥层级与 BYOK/HYOK**（客户自持云 KMS key ⚠️）。
- 事件（Event Schedule/Alert）：登录失败风暴、对象变更、复制延迟→ 邮件/webhook。
- 认证清单（SOC 2 Type II、ISO 27001、PCI、HIPAA BAA、FedRAMP Moderate/High ⚠️ 以官方信任中心为准）。
- 与 [05-访问控制.md](05-访问控制.md) 的关系：加密+网络=外圈，权限+标签=内圈，恢复+留痕=最后圈。

## 常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "Time Travel=备份" | 同区同账户，区域级灾难不救；灾备要靠复制/导出 |
| "UNDROP 万能" | 过窗口即死；Fail-safe 期用户不可自助 |
| "克隆会复制数据所以贵" | 零复制：只有分叉后的变化计费 |
| "retention 设 0 就不付存储费" | 只免 Travel 层保留费，当前数据存储照付 |
| "被共享方改坏会影响我" | 共享是只读引用，对方 DML 不可达你的基表 |

## 核心概念速览（中英对照）

1. **时间旅行** — Time Travel：保留窗口内按时间戳/偏移/查询 ID 读历史态的能力。
2. **保留期** — data retention period：Time Travel 窗口的账户/对象级参数。
3. **故障保险** — Fail-safe：Time Travel 之后 7 天的不可访问最后保留层。
4. **UNDROP** — undrop：从回收态复活表/模式/数据库。
5. **零复制克隆** — zero-copy cloning：只复制元数据、按分叉计费的对象克隆。
6. **AT / BEFORE 子句** — 时点读语法：时间点/偏移/语句 ID 三种锚。
7. **微分区不可变** — immutable micro-partitions：DML 以新替旧，历史因此可寻。
8. **BYOK/HYOK** — bring your own key / hold your own key：客户自持密钥的加密层级。
9. **网络策略** — network policy：登录 IP 白名单（与 5 章共用）。
10. **事件与告警** — events & alerts：对象变更/安全信号的推送钩子。
11. **数据分类标签** — classification & tags：治理侧的敏感度登记。
12. **恢复演练** — restore drill：用 CLONE 到影子库做"备份可用性证明"。
