## 核心精讲

### 1. 三层架构（背诵级）
转述 ⚠️（https://docs.snowflake.com/en/user-guide/intro-key-concepts）：

| 层 | 职责 | 弹性 |
| --- | --- | --- |
| **云服务层**（Cloud Services） | SQL 解析/优化/编译、元数据与统计、访问控制、故障检测、伸缩编排 | 内部多可用区冗余，用户不可见不可配 |
| **虚拟计算层**（Virtual Warehouses） | 查询的实际执行：MPP 计算集群，节点间 shared-data-nothing；本地 SSD 缓存微分区 | 秒级启停、分钟级扩缩；**同数据多仓库隔离** |
| **持久存储层**（Cloud Storage） | 底层云对象存储（S3/ADLS/GCS）上的**专有加密列式微分区** + 元数据 | 近乎无限、按量计费；对所有仓库可见（数据共享而非复制） |

三条推论（书中反复使用）：
1. **装载与查询解耦**：DML 由仓库完成，存储层只增不改（微分区不可变）→ 无传统索引/无 vacuum 运维负担 ⚠️。
2. **计算互不干扰**：ETL 仓库与 BI 仓库读同一份存储，成本归因清晰（第 8 章）。
3. **Time Travel/克隆便宜**：恢复与克隆只动元数据指针，不动数据（第 7 章）。

### 2. 虚拟仓库命令面（教学示意，非书中原文）
```sql
USE ROLE SYSADMIN;
CREATE WAREHOUSE WH_ETL
  WAREHOUSE_SIZE = 'MEDIUM'      -- Gen1: 每升一级 credit 翻倍（X-Small=1/h）⚠️
  AUTO_SUSPEND = 300             -- 秒；悬停后本地缓存保留约一个悬停周期 ⚠️
  AUTO_RESUME = TRUE
  INITIALLY_SUSPENDED = TRUE;    -- 建完先睡，防"建即烧钱"
ALTER WAREHOUSE WH_ETL SET WAREHOUSE_SIZE = 'LARGE';   -- 可在线改
ALTER WAREHOUSE WH_ETL SET MAX_CLUSTER_COUNT = 4 MIN_CLUSTER_COUNT = 1
  SCALING_POLICY = 'ECONOMY';
SHOW WAREHOUSES;  DESCRIBE WAREHOUSE WH_ETL;
```
要点 ⚠️ 转述：仓库尺寸/多集群语义以 https://docs.snowflake.com/en/user-guide/warehouses-overview
与 https://docs.snowflake.com/en/user-guide/warehouses-multicluster 为准；
Gen2（Standard/Economy）仓库计费模型已改（见第 8 章最新演进），**书中"逐级翻倍"表是 Gen1 口径**。

### 3. 微分区（此处只建立概念，机制主场在第 9 章）
所有表数据切成 **50–500 MB（未压缩）的微分区**，列式存放，每分区带列值范围等元数据；
查询靠元数据裁剪（pruning）跳过无关分区——**这就是 Snowflake"不需要 DBA 建索引"的底气** ✅（原文直引数据区间：
https://docs.snowflake.com/en/user-guide/tables-clustering-micropartitions）。
对照开放格式：Parquet row-group + min/max 统计是同一思想的开源版 →
[../bigdata/09-存储与文件格式.md](../bigdata/09-存储与文件格式.md)。

### 4. 高可用 vs 灾备的分界
- **区域内**：云服务层无状态多活、存储层云厂商自带跨 AZ 冗余 → 官方称自动处理 AZ 级故障 ⚠️。
- **跨区域/跨云**：需显式配置**账户复制与故障转移**（Replication & Failover，复制数据库/仓库/用户等元数据与
  数据副本，可将账户提升为只读备、再提升为主）：https://docs.snowflake.com/en/user-guide/database-replication-failover ✅200。
  书出版时（2022）该功能仍在早期形态，作者只给了"重建账户+共享回补"的旧口径 ⚠️。

## 常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "加大仓库解决并发" | 尺寸解决**单查询快慢**，并发靠**多集群**（MAX_CLUSTER_COUNT） |
| "存储层是用户可摸的 S3" | 专有加密格式+内部元数据，用户不可直接操作（Iceberg 托管表才打开这层，见最新演进） |
| "仓库挂起=数据被清" | 只停算力与（部分）缓存；数据在存储层永远在线 |
| "多集群仓库随便加" | 只有查询/物化视图/DML 等场景支持多集群；且成本随集群数线性涨 |
| "跨区域容灾默认就有" | 必须显式建复制（Replication），否则区域整挂即业务中断 |

## 核心概念速览（中英对照）

1. **存算分离** — separation of storage and compute：存储与计算独立伸缩、互不阻塞的架构范式。
2. **云服务层** — cloud services layer：SQL 分析、优化、元数据、治理与编排的"大脑"，多可用区高可用。
3. **虚拟仓库** — virtual warehouse：按需启停的 MPP 计算集群，账单与性能的第一控制点。
4. **shared-data-nothing（计算层）** — 仓库内节点各算各分片，靠 shuffle/广播汇合。
5. **多集群仓库** — multi-cluster warehouse：同一仓库自动增减集群以吸收并发波峰。
6. **自动挂起/恢复** — auto-suspend / auto-resume：空闲即停、来活即醒的省钱机制。
7. **缩放策略** — scaling policy：ECONOMY/STANDARD，多集群增减的激进程度。
8. **微分区** — micro-partition：50–500MB（未压缩）列式不可变存储单元，自带裁剪元数据。
9. **数据裁剪** — pruning：用微分区统计跳过无关数据的读取策略。
10. **云对象存储层** — database storage：S3/ADLS/GCS 上的专有加密存储，全仓库共享。
11. **账户复制与故障转移** — replication & failover：跨区域/跨云的账户级灾备机制。
12. **Gen1/Gen2 仓库** — warehouse generation：两代算力-计费模型（后者分 Standard/Economy）。
