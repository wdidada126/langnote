## 核心精讲

### 1. 批量装载命令面
```sql
-- 教学示意，非书中原文
CREATE OR REPLACE STAGE EXT_S3
  URL='s3://bucket/orders/' CREDENTIALS=(...)  -- 或 STORAGE_AWS_ROLE_ARN（IAM role 为推荐姿势 ⚠️）
  FILE_FORMAT = (TYPE='JSON');

CREATE OR REPLACE TABLE ORDERS_RAW(v VARIANT, mf STRING, modif TIMESTAMP);
COPY INTO ORDERS_RAW(v, METADATA$FILENAME, METADATA$FILE_LAST_MODIFIED)
  FROM @EXT_S3/files/ PATTERN='.*2022-08.*\.json(.gz)?'
  ON_ERROR='ABORT_STATEMENT';                  -- 错误策略 ⚠️ 另有 CONTINUE/SKIP_FILE/'n'

-- 装载账本三视图：审计与幂等的依据
SELECT * FROM TABLE(INFORMATION_SCHEMA.LOAD_HISTORY(
  TABLE_NAME => 'ORDERS_RAW', START_TIME => DATEADD('day',-1,CURRENT_TIMESTAMP())));
```

### 2. Snowpipe 语义（与自建调度器对账）
- 一条 `CREATE PIPE ... AS COPY INTO ...` + 云事件通知（SQS/SNS、Event Grid、Pub/Sub）+ 自动列目录兜底 ⚠️；
  官方页 https://docs.snowflake.com/en/user-guide/data-load-snowpipe-intro ✅、
  自动通道 https://docs.snowflake.com/en/user-guide/data-load-snowpipe-auto ✅。
- **计费差异**：COPY 烧你仓库的 credit；Snowpipe 按文件/数据量收服务费（serverless，无需仓库常开）⚠️。
- backlog/`PIPE` 监控视图与告警是生产化关键（转述）。
- 对照本地开源形态：自建 Airflow + DuckDB 批量装载的"事件驱动改造"练习 →
  [../bigdata/11-调度资源与运维.md](../bigdata/11-调度资源与运维.md)。

### 3. 半结构化直通：文件到 VARIANT 一步
外部暂存 CSV/JSON/Avro/ORC/Parquet/XML 全部可进；JSON→VARIANT 直接落列，schema 演化容忍缺列（自动补 NULL）⚠️。

### 4. 流式与 CDC
- **Snowpipe Streaming REST API/Kafka Connector**：行级微批直写表，端到端秒级 ⚠️；替代旧"文件+pipe"低延迟档。
- 入仓后的增量分发：STREAM 对象消费 + MERGE（第 3 章）；湖仓对位物：Hudi 的 delta streamer / Flink CDC →
  [../Apache_Paimon_Streaming_Lakehouse/11-Flink集成与CDC入湖实践.md](../Apache_Paimon_Streaming_Lakehouse/11-Flink集成与CDC入湖实践.md)。
- 卸载回流：`COPY INTO @stage FILE_FORMAT=(TYPE='PARQUET') HEADER=... PARTITION BY ...`（目录切分）⚠️，
  官方卸载页 https://docs.snowflake.com/en/user-guide/data-unload-overview ✅。

### 5. 装载路径上的"隐藏性能账"
微分区数量与大小在装载期成形：小文件风暴 → 微分区碎片 → 后续查询裁剪变差；官方建议装载侧攒够
MB 级文件再喂（转述 ⚠️，https://docs.snowflake.com/en/user-guide/data-load-overview ✅）。
本地代理实验：DuckDB 读 1 万个小 Parquet vs 合并后的对比，直观感受"入场布局"的价值 →
[../bigdata/09-存储与文件格式.md](../bigdata/09-存储与文件格式.md)。

## 常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "COPY 失败会留半表" | COPY INTO 以文件/批为单位事务，失败即回滚，账本可查 |
| "Snowpipe 一定更快" | 高频小文件下 backlog 排队反而高；批量 COPY 大文件吞吐占优 |
| "外部表≈已入仓" | 外部表无 Time Travel/无聚簇/查询走外部扫描，SLA 差一档 |
| "PATTERN 能替代分区设计" | 目录分区（/dt=）仍决定扫描成本与清单速度 |
| "卸载就是 SELECT 导出" | UNLOAD 是 COPY INTO @stage 的镜像路径，带分区与压缩参数 |

## 核心概念速览（中英对照）

1. **批量装载** — bulk loading：COPY INTO 一次性吞文件。
2. **Snowpipe** — 托管事件驱动装载服务，serverless 计费。
3. **外部 stage** — external stage：指向 S3/ADLS/GCS 的带凭证句柄。
4. **文件游标** — file list/copy history：已装载文件账本，幂等之源。
5. **模式匹配** — PATTERN：装载正则过滤。
6. **错误策略** — ON_ERROR：ABORT/CONTINUE/SKIP_FILE/n 的容错档位。
7. **元数据列** — METADATA$FILENAME 等：装载期注入的文件指纹列。
8. **自动推断** — INFER_SCHEMA/AUTODETECT：文件列型自识别。
9. **流式通道** — Snowpipe Streaming：行级 API 直写。
10. **外部表** — external table：直读 stage 的表抽象。
11. **卸载** — UNLOAD：COPY INTO @stage 出文件。
12. **管道积压** — backlog：pipe 未处理文件堆积监控量。
13. **SCD** — slowly changing dimension：装载后的拉链/合并策略族。
14. **装载历史视图** — COPY_HISTORY / LOAD_HISTORY：按文件粒度的幂等审计账本。
15. **文件格式对象** — file format：CSV/JSON/Parquet 等解析参数的可复用具名对象。
