## 核心精讲

### 1. 角色设计的推荐骨架（书中范式）
```sql
-- 教学示意，非书中原文
USE ROLE SECURITYADMIN;
CREATE ROLE DATA_STEWARDS;  CREATE ROLE ANALYST_RW;  CREATE ROLE ANALYST_RO;
GRANT ROLE DATA_STEWARDS TO ROLE SYSADMIN;      -- 治理链：新角色挂到 SYSADMIN 之下
GRANT CREATE SCHEMA, CREATE DATABASE ON ACCOUNT TO ROLE DATA_STEWARDS;
GRANT USAGE ON DATABASE SALES_DB TO ROLE ANALYST_RW;
GRANT USAGE ON ALL SCHEMAS  IN DATABASE SALES_DB TO ROLE ANALYST_RW;
GRANT SELECT, INSERT, UPDATE ON ALL TABLES IN SCHEMA SALES_DB.PUBLIC TO ROLE ANALYST_RW;
GRANT OWNERSHIP ON TABLE SALES_DB.PUBLIC.ORDERS TO ROLE DATA_STEWARDS
  COPY CURRENT GRANTS;                          -- 所有权转移语义 ⚠️
GRANT ROLE ANALYST_RO TO USER bob;
```
三条经验（转述 ⚠️ + 社区共识）：
- **不要用 ACCOUNTADMIN 干日常**；用 SECURITYADMIN/USERADMIN 分权治理。
- **GRANT 沿层级下沉、沿业务上浮**：SYSADMIN→资源管理者→使用者。
- **角色组（role group，2024+）与"access control grants"页**给出现成对照表：
  https://docs.snowflake.com/en/user-guide/security-access-control-overview ✅200。

### 2. Future grants（默认权限）与 2025 变更伏笔
`GRANT USAGE ON FUTURE SCHEMAS IN DATABASE d TO ROLE r` 让之后创建的 schema 自动带权。
**注意 ⚠️**：中文社区 2024–2026 有大量"为何未来授权需要 ACCOUNTADMIN"的讨论——授权默认模型
（哪些 CREATE 隐式带 GRANT、谁可授 ON FUTURE）经历过行为变更，读 2022 书稿时必须叠加官方 release notes 校准：
https://docs.snowflake.com/en/release-notes/2024/8_41 ✅200（示例周记，逐条变更以页内为准）。

### 3. MAC：行级与列级的三板斧
| 工具 | 粒度 | 定义 |
| --- | --- | --- |
| 安全视图（Secure View） | 行/列 | 查询改写 + 不向使用者暴露定义；共享场景主力（第 10 章）：https://docs.snowflake.com/en/user-guide/views-secure ✅200 |
| Row Access Policy | 行 | 策略函数按 user/session 谓词决定可见行 ⚠️ |
| Masking Policy | 列/单元格 | 动态脱敏（哈希/置空/格式保留）⚠️ |
| 标签（Tag） | 任意对象 | 分类分级挂到列上，策略按标签绑定（policy referencing tags）⚠️ |

标签驱动是 Snowflake 治理的**独特卖点**：湖仓开放栈直到近期才有对等物（Unity/UC、Lance、Polaris 等 ⚠️ 转述），
对照 [../The_Data_Lakehouse/10-软数据与描述性数据.md](../The_Data_Lakehouse/10-软数据与描述性数据.md)、
[../Engineering_Lakehouses_with_Open_Table_Formats/09-Catalog与互操作.md](../Engineering_Lakehouses_with_Open_Table_Formats/09-Catalog与互操作.md)。

## 常见误区

| 误区 | 事实（转述 ⚠️） |
| --- | --- |
| "PUBLIC 角色无关紧要" | 新对象常默认授予 PUBLIC，治理第一步是清点 PUBLIC 权 |
| "角色继承随便挂" | 挂错父角色=权限泄漏链；SECURITYADMIN 只挂不建资源 |
| "有 WHERE 就是行级安全" | 直连表即绕过；行级安全必须用 policy/安全视图 |
| "密钥对=更安全的密码" | 密钥对免密码但需轮换与绑定策略；服务账号才用 |

## 核心概念速览（中英对照）

1. **RBAC** — role-based access control：以角色为中介的授权模型。
2. **DAC** — discretionary access control：对象所有权驱动的 GRANT/REVOKE。
3. **MAC** — mandatory access control：标签/策略强制的不可协商控制。
4. **角色链** — role hierarchy：角色 GRANT 角色形成的继承 DAG。
5. **所有权** — ownership：对象创建角色的最高权，GRANT OWNERSHIP 可转移。
6. **默认权限** — default privileges：作用于将来对象的自动授权。
7. **future grant** — ON FUTURE 子句：为同容器内后续创建的对象预授权。
8. **安全视图** — secure view：行级过滤且定义保密的视图。
9. **行访问策略** — row access policy：按会话身份裁剪可见行。
10. **掩码策略** — masking policy：按身份动态脱敏列值。
11. **标签** — tag：可挂到任意对象/列的分类分级注解。
12. **网络策略** — network policy：IP 级登录白名单。
13. **密钥对认证** — key pair authentication：公钥注册到用户、私钥签名登录。
14. **PUBLIC 角色** — PUBLIC role：所有用户自动所属的隐式角色，授权审计重点。
