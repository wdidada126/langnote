## 核心精讲

### 1. 认证矩阵（10.1/10.3–10.6）

```properties
# 教学示意：coordinator etc/config.properties 的安全段
http-server.http.enabled=false            # 关明文
http-server.https.enabled=true
http-server.https.port=8443
http-server.authentication.type=PASSWORD   # 或 CERTIFICATE / OAUTH2 / JWT / KERBEROS
access-control.name=file
```

- 口令文件（密码 + `auth.user.password`）是入门路；LDAP 接企业目录（✅ [security/ldap.html](https://trino.io/docs/current/security/ldap.html)）；证书认证即 mTLS（CN 映射用户名）；Kerberos 走 SPNEGO 服务于 UI/JDBC（✅ [security/kerberos.html](https://trino.io/docs/current/security/kerberos.html)）。
- **TLS 终结在 coordinator**：客户端↔coordinator 全加密；coordinator↔worker 在书稿（393/394 前后）起步支持内部 HTTPS——483 时代「内部加密 + 网络分段」组合已是合规基线（✅ 官方 [security/overview.html](https://trino.io/docs/current/security/overview.html)；逐属性 ⚠️ 不展开）。
- 自签证书的正确姿势（10.4）：自建 CA → 签服务器/客户端证书 → 客户端信任 CA 而非单证书；书中 openssl 流程在 483 文档 security 章节有对位页 ⚠️ 细节以现文为准。

### 2. 授权：文件规则的粒度账（10.2/10.7）

```properties
# 教学示意 etc/规则文件（file-based access control）
group.readonly.name=analysts
group.readonly.members=alice,bob
user.admin=name:trino-admin; groups=admin
catalog.hive.name=hive; allowed-query-types=*,...
schema.hive.sales.name=sales; allowed-groups=readers
table.hive.sales.orders.name=...; 
```

- 模型：catalog→schema→table 的 allow-list 规则，查询类型（SELECT/INSERT/DML…）分粒度；**默认全拒**兜底策略 ⚠️ 规则语义以 483 文档为准。
- 两本账：Trino 侧规则管「谁能查什么」；源端凭据/权限管「connector 用什么身份访问」（`query.min-scheduled-task-memory` 之类无关，connector properties 里的 user/password/keytab 才是源端身份）。生产实践：connector 用低权限账号 + Trino 规则做人群细分，**impersonation** 补齐审计真实性（10.8）。
- 483 增量：基于规则文件之上出现 OPA/外部策略引擎与 range 分区式控制等选项的文档线 ⚠️（官方 security 目录可检索，逐页未全抓）。

### 3. Kerberos + Hive 链路（10.6/10.8）

`hive.impersonation.enabled=true` + core-site 的代理规则 + HDFS Ranger/Sentry 式下游控制：查询以「终端用户身份」落到 HDFS/ metastore——审计与配额才真实。392 书稿的 Hadoop 安全世界观与 2026 的（云化 + 去 Kerberos 化，转向 OAuth2/JWT/云 IDaaS）正在换轨：跟书练用口令+LDAP 即可，老 Hadoop 集群才回 Kerberos（经验 ⚠️）。

### 4. 集群分离（10.9）：安全也讲爆炸半径

拆集群的三种理由（书中框架，今天仍成立）：

| 维度 | 拆法 | 典型动机 |
| --- | --- | --- |
| 负载 | 交互 vs 批量 ETL | 大查询饿死 BI（12 章资源组的硬解版） |
| 数据域 | 敏感域独立 catalog 集/独立集群 | 合规隔离、connector 凭据隔离 |
| 租户 | 每租户一集群/一 control 层 | SLA 与计费边界 |

483 时代多租户还叠加了资源组、query 级属性与 catalog 权限的「软隔离」选项——先软后硬（组织决策 ⚠️）。

### 5. 安全部署的最小配方与完整配方

```properties
# 教学示意：最小配方（内部实验集群）
http-server.http.enabled=false
http-server.https.enabled=true
http-server.keystore-path=etc/keystore.jks   # 密钥库相关属性名以 483 文档为准 ⚠️
http-server.authentication.type=PASSWORD
access-control.name=file                       # 至少给 default 拒绝规则
```

完整配方的分层记忆：**传输层**（TLS 外+内、强密码套件）→ **身份层**（LDAP/OAuth2/mTLS/Kerberos 择一主 + 一备）→ **授权层**（规则/策略引擎 + 源端低权限 + impersonation）→ **审计层**（事件监听外发 + 查询日志入库）→ **边界层**（网络分段 + 集群分离）。每层失效都有下一层兜底，才叫安全架构；单层裸奔就是本章所有误区的公分母。

### 6. 凭证保管清单

keytab、LDAP bind 密码、JKS 口令、云 AK——统一进 secret 管理（Vault/KMS/挂载文件权限 600），配置文件里只留路径引用；证书到期日历化监控（13.1 的 GitOps 让「换证书」=「改一次 PR」）。

## 常见误区

- 认证开着、Web UI 明文裸奔：`http-server.http.enabled=true` 遗留或 8080 未关，内省面全漏。
- 以为 Trino 授权 = 数据授权：行/列级脱敏在 Trino 文件规则里粒度有限，需要 Ranger/策略引擎或视图层兜底 ⚠️ 能力边界以现文档为准。
- LDAP 连接没配 `ldap.user-name-pattern` 导致「密码对了也 403」——规则模式与过滤器各管一段。
- connector 里塞超级用户：全集群共用一个 root 凭据 = Trino 授权形同虚设；按源端最小权限发账号。
- 只加密外部、worker 明文，云内网被旁路取证：「内部通信不加密」在合规审计里是硬伤（10.3 演进节）。

## 核心概念速览（中英对照）

1. **认证** — authentication：确认「你是谁」：口令/LDAP/证书/OAuth2/JWT/Kerberos。
2. **授权** — authorization：确认「你能查什么」：规则式访问控制。
3. **mTLS** — certificate authentication：双向证书，CN→用户映射。
4. **SPNEGO** — Kerberos web 握手：UI/JDBC 的票据接入方式。
5. **keytab** — keytab：服务票据的无密码凭据文件。
6. **impersonation** — 代理用户：connector 以终端用户身份访问 Hadoop 栈。
7. **文件访问控制** — file-based access control：规则文件里的 allow-list 模型。
8. **TLS 终结** — TLS termination @ coordinator：外部加密的架构位置。
9. **内部加密** — internal communication encryption：coordinator↔worker 链路 HTTPS。
10. **自签 CA** — self-signed CA：用自建根签名的证书体系。
11. **查询类型权限** — allowed query types：SELECT/DML/DDL 分级放行。
12. **默认拒绝** — deny-by-default：规则未覆盖即禁止的兜底姿态。
13. **集群分离** — cluster segregation：以部署边界做硬隔离。
14. **Ranger** — Apache Ranger：下游行/列级与脱敏的常见补位。
15. **审计链** — audit trail：impersonation + 事件监听器的合体产物。

## 最新演进与工业实践

- **认证线**：392→483 期间 **OAuth2 与 JWT 认证**进入主干并持续打磨（官方 security 文档目录含对应对话页；引入版本 ⚠️ 未逐版核）；云托管（Galaxy/Athena 类）普遍以 SSO/OIDC 为门面，Kerberos 占比下降（趋势转述 ⚠️）。
- **授权线**：规则文件之外，社区/厂商侧向「策略即代码」（OPA 类）与 Ranger 集成演进 ⚠️ 主干页未逐抓；RBAC 原生化仍是长话题。
- **内部通信加密**与 **事件监听/审计 API**（Event Listener 接 SIEM）是当前审计合规的主通道 ✅（docs 导航 Administration 分区；具体属性 ⚠️）。
- **工业实践**：「对外 OAuth2/JWT + 对内 mTLS + 源端低权限 + 下游 Ranger/策略引擎 + 查询全量审计」的五段式在金融/合规行业成为湖上 SQL 的标准安全栈（组合为通行实践描述 ⚠️ 非逐家引用）。
- **零信任视角**：worker 无状态 + 拉取式 exchange 使「网络位置不换信任」易落地，Trino 因此比传统数仓更早适配零信任改造（架构属性推论 ⚠️，回 [04 章](04-Trino架构.md)）。
