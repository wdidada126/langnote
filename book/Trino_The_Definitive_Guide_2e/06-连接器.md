## 核心精讲

### 1. Hive connector：书稿时代的主干（6.4）

概念栈：HDFS/对象存储 + Parquet/ORC 文件 + Hive metastore 表登记。关键配置三件：metastore 类型、HDFS/Web 初始化、`hive.non-managed-table-writes-enabled` 等写闸门（属性名以 483 页 ✅ [connector/hive.html](https://trino.io/docs/current/connector/hive.html) 为准）。

```sql
-- 教学示意：CTAS —— 湖上「查询即建表」的原子姿势
CREATE TABLE hive.sales.web_logs_parq AS
SELECT * FROM kafka.default.web_logs WHERE dt >= date '2022-01-01';
-- CTAS 在 Trino 是单条原子语句：选格式/分区在 WITH 子句声明
CREATE TABLE t (col1, col2) WITH (format='PARQUET', partitioned_by=ARRAY['dt']) AS SELECT ...;
```

- **CTAS 语义要点**：一次查询完成「建表 + 写入 + 元数据登记」，失败不留半表；分区列必须放 SELECT 末尾——这是与 Spark `CREATE TABLE ... AS` 的第一处方言差异（对照 [../bigdata/04-SparkSQL与结构化数据.md](../bigdata/04-SparkSQL与结构化数据.md)）。
- **INSERT**：`INSERT INTO ... SELECT` 走 connector 写路径；Hive 外表写入受非托管表开关约束（6.4 口径 ⚠️ 逐属性未核）。

物化视图（6.4/6.5 书稿重点）✅ 语法页存活至今：[sql/create-materialized-view.html](https://trino.io/docs/current/sql/create-materialized-view.html)。

```sql
-- 教学示意
CREATE MATERIALIZED VIEW hive.sales.hourly_rev
  REFRESH EVERY 1 DAY
  GRANT REFRESH ON ... -- 483 语法含 GRANT，书稿为裸 MV 语句 ⚠️
AS SELECT hour, sum(total) FROM orders GROUP BY hour;
SELECT ... FROM some_view_that_rewrites USING MV;  -- 优化器自动改写命中
```

- 392 基线：MV 仅 Hive connector 支持、**刷新是定时全量重算**（REFRESH EVERY），查询改写用视图基表匹配；「增量物化视图」当时没有。
- 483 现状 ✅：MV 语法扩到 Iceberg/Delta 等 native 线（各 connector 页支持矩阵为准），「自动改写 + 手动/定时 REFRESH」模型不变，增量维护仍非引擎职责（趋势判断 ⚠️）。

### 2. 表格式三入湖路（6.5 的今昔）

书稿（392）：Iceberg = Hive connector 的 `iceberg.enabled=true` 模式（**Hive+ 扩展**形态），Delta 同走 Hive 侧。483 现状（✅ 三页均 200 实抓）：

| connector | 形态 | 页 |
| --- | --- | --- |
| Iceberg | **独立 native connector**，支持 spec v1/v2、v3 实验性 | [connector/iceberg.html](https://trino.io/docs/current/connector/iceberg.html) |
| Delta Lake | 独立 native connector | [connector/delta-lake.html](https://trino.io/docs/current/connector/delta-lake.html) |
| Hive | 仍为存量湖主干 | [connector/hive.html](https://trino.io/docs/current/connector/hive.html) |
| Hudi | 存在（版本状态读页为准 ⚠️） | [release-483 导航含 Hudi 节，connector 页未单抓](https://trino.io/docs/current/release/release-483.html) |

- Iceberg 的 metastore 选项（HMS/JDBC/REST 等）是湖仓控制面之争的缩影，深入协议看 [../Apache_Iceberg活用入門/00-总览与阅读地图.md](../Apache_Iceberg活用入門/00-总览与阅读地图.md)、[../Use_Iceberg_with_Spark/00-总览与阅读地图.md](../Use_Iceberg_with_Spark/00-总览与阅读地图.md)；Delta 写侧看 [../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md](../Delta_Lake_Definitive_Guide/00-总览与阅读地图.md)；Paimon/Flink 写侧看 [../Apache_Paimon_Streaming_Lakehouse/00-总览与阅读地图.md](../Apache_Paimon_Streaming_Lakehouse/00-总览与阅读地图.md)。
- **读 Trino 侧 Iceberg 的增值点**：ACID/时间旅行/隐藏分区在查询面的表现、`DELETE`/MERGE 支持、统计接入（Puffin）——逐条以 connector 页现文为准。

### 3. JDBC 型与 NoSQL 型的映射哲学（6.2/6.6）

- PostgreSQL/MySQL 等：一张 catalog = 一个库的镜像；下推能力最强（谓词/limit/聚合），因为「翻译回去还能跑」。
- MongoDB/Redis/Cassandra/ES：需要手写 table 描述文件（schema 文件化），「表」是对无 schema/弱 schema 世界的投影；详例在 07 章。
- 联邦价值公式：`SELECT` 跨 PG 行存 + Hive 湖 + Kafka 日志 = 不用搬数据的 join（07 章展开）。

### 4. 彩蛋三件套（6.7/6.8/6.9）

```sql
-- 教学示意：JMX connector 把引擎自身变可观测表
SELECT * FROM jmx.current."trino.execution:name=QueryManager";
-- black hole：测扫描上限（输出全丢）
CREATE TABLE bh AS SELECT * FROM huge_table;  -- connector 为 blackhole
-- memory：演示 CTAS→INSERT→SELECT→DROP 全生命周期
```

12 章监控会把 JMX connector 再用一次：**「用 SQL 监控 SQL 引擎」**是 Trino 独有气质的入门体验。

## 常见误区

- 以为 CTAS 到处能用：connector 不支持写则语句直接报错（能力矩阵查对应页，别背清单）。
- 把 392 的 `hive.iceberg.enabled` 老路配到 483 新集群：native Iceberg 与 Hive-Iceberg 扩展两代形态混谈（升级必读对应 connector 页历史节 ⚠️）。
- 物化视图当「实时视图」：REFRESH EVERY 的窗口内 MV 就是陈旧数据；要求实时的场景应直查基表或用流式引擎（与 Flink 分工见 [../基于Apache_Flink的流处理.md](../基于Apache_Flink的流处理.md)）。
- JDBC connector 过度下推幻觉：跨库 join 的中间结果仍回 Trino 交换，不是「全下推」。
- memory connector 上生产：重启全丢，它只是玩具与回归夹具。

## 核心概念速览（中英对照）

1. **连接器实例** — connector instance：catalog 化的 connector 部署，携带独立配置。
2. **下推** — pushdown：谓词/投影/limit/聚合作废在源端先算，省回传。
3. **CTAS** — CREATE TABLE AS SELECT：原子建表+写入的湖上主力语句。
4. **物化视图** — materialized view：预计算结果表 + 优化器自动改写 + 定时 REFRESH。
5. **非托管表** — non-managed table：外表写入受开关约束的 Hive 概念。
6. **metastore** — Hive metastore：表/分区登记的目录服务，connector 配置的第一选择。
7. **分区表** — partitioned table：`partitioned_by` 声明，扫描裁剪的元数据来源。
8. **分桶** — bucketing：Hive 桶与 join 重分布复用的基础（4.7 呼应）。
9. **表格式** — table format：Iceberg/Delta/Hudi 之于文件的「协议层」。
10. **隐藏分区** — hidden partitioning：Iceberg 卖点，在 Trino 写侧语法体现 ⚠️ 细节看表格式书。
11. **JDBC 型连接器** — JDBC-based connector：把关系库镜像成 catalog 的族系。
12. **schema 文件** — table schema descriptor：NoSQL/消息系统「造表」的声明文件。
13. **black hole** — black hole connector：吞输出的基准测试 sink。
14. **JMX 连接器** — JMX connector：引擎自监控 SQL 化。
15. **能力矩阵** — connector feature matrix：读写/MV/统计支持按 connector 各异，以文档页为准。
