## 核心技术清单

- DuckDB 作为"应用的后端仓库"：Web 应用进程内嵌一个只读/低并发 DuckDB + Parquet 数据文件，零数据库运维。
- Streamlit 的心智：每次交互全脚本重跑 → DuckDB 查询必须缓存，否则每次点击重扫 10 分钟。
- `st.connection` 走 SQLAlchemy 方言 duckdb-engine（第三方 driver，非官方 duckdb Python 包——两条路要分清）。
- Superset 连 DuckDB：SQLAlchemy URI `duckdb:///path.db`；Superset 的异步查询/缓存与 DuckDB 单进程模型摩擦（Gunicorn 多 worker 各自开库）。
- 部署边界：Community Cloud 适合 demo；真生产 Superset 要 Redis/Postgres 元数据库 + 并发方案。

## 🔧 实测说明

⚠️ 本章未做端到端 UI 实测（Streamlit/Superset 属重型 Web 栈，与本书该章验证点"能连、能查、能出图"相比成本高）。已做的等价验证：

## 易错点与陷阱

- **Streamlit 每交互重跑 = 每交互重开 DuckDB 查询**：不做 `st.cache_data` 会把 0.04 s 的聚合变成"点一下等一次全量扫描 ×N"；连接对象用 `st.cache_resource`（一个连接多处共享线程安全策略要确认）。
- **应用与笔记本的并发模型不同**：Streamlit Cloud 单进程时问题不大；自建多 worker 时**每个 worker 各开一份 DuckDB**，写库互踩（文件锁，见 12 章实测）——Web 层只读化或改 MotherDuck。
- **Superset 的 Jinja 时间宏生成的是字符串 SQL**：粘进 DuckDB 前注意方言差异（`TO_DATE`/interval 写法）。
- **Virtual dataset 滥用**：从任意 SQL 建 dataset 会让 Superset 的过滤/钻取包裹进子查询，复杂 SQL + DuckDB 优化器交互下可能丢下推——常用模型应落成物理表/视图。
- **parquet 直连 vs 库文件直连**：Superset 指 `duckdb:///` 库文件时，别的应用同时写它会锁死；BI 链路推荐指向**只读视图 + 定时刷新的 Parquet**。
- Community Cloud 装不了非 PyPI 依赖与二进制扩展：httpfs 等扩展首次 INSTALL 需要网络与写权限，secrets 里给 S3 凭据而非硬编码。

## 核心概念速览（中英对照）

- **脚本即应用** — Script-as-app（Streamlit 模型）：无前端代码的数据应用。
- **结果缓存** — st.cache_data：按输入哈希缓存查询结果。
- **资源缓存** — st.cache_resource：缓存连接/引擎等单例对象。
- **SQLAlchemy 方言** — duckdb-engine：BI 工具经 ORM 层连 DuckDB 的桥。
- **数据集** — Dataset（Superset 的查询抽象层）。
- **虚拟数据集** — Virtual dataset：以任意 SQL 定义的逻辑表。
- **图表/仪表盘** — Chart / Dashboard：BI 资产两级组合。
- **资产导出** — Export/Import YAML：Superset 配置的版本化搬运。
- **进程内后端** — In-process backend：应用自带数据库、零服务。
- **冷启动查询** — Cold query：新进程首查含文件打开/元数据读取的开销。

## 最新演进与工业实践

- **Streamlit 侧**：官方 `streamlit[duckdb]` 教程线长期把 DuckDB 作为默认分析后端（社区文档 ⚠️）；1.x Streamlit 新增 `st.connection` 工厂与自定义组件流，2024–2026 年"Parquet + DuckDB + Streamlit"成为数据应用最小栈的说法广泛流传（定性）。
- **Superset 侧**：Superset 3.x（2024 后）重做数据集 UI 与 SQL Lab 权限；DuckDB 作为数据源的支持由 duckdb-engine 维护（⚠️ 未逐一 curl 版本证据，判读为社区实践）。
- **格局**：嵌入式 BI 应用（Quarto/Observable + DuckDB Wasm 浏览器内查询）分流了"轻量看板"场景——浏览器里直接 `read_parquet` 远程 S3 已是可生产形态（duckdb-wasm 官方文档入口 ✅ https://duckdb.org/docs/stable/clients/overview）。
- **建议的 2026 生产形态**：管道（08 章）物化 Parquet/DuckLake → 应用层用只读 DuckDB 或 MotherDuck → UI 层 Streamlit/Superset；避免让 Web 层直接持有可写库文件。
