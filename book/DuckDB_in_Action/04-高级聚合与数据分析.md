# 04 · Advanced aggregation and analysis of data（高级聚合与数据分析）

> 覆盖原书第 4 章。目录来源：✅ Manning 官方 TOC 实抓。本章是全书 SQL 含金量最高的一章：grouping sets、窗口、QUALIFY/FILTER、PIVOT、ASOF JOIN、LATERAL——分析 SQL 的"重武器"。

## 内容规格（小节地图，✅ 实抓）

- **4.1 Pre-aggregating data while ingesting**：在 `COPY`/CTAS 时就做聚合落表（"摄取即预聚合"），拿小表跑报表。
- **4.2 Summarizing data**：`SUMMARIZE`/`SUMMARIZE (SAMPLE ...)` 出列画像（null 率/极值/直方图）。
- **4.3 On subqueries**：标量子查询当表达式用、EXISTS/IN 子查询与相关子查询。
- **4.4 Grouping sets**：`GROUP BY GROUPING SETS ((a),(a,b),())` 一条查询出"明细+小计+总计"，配 `grouping()` 标维度。
- **4.5 Window functions**：4.5.1 PARTITION BY；4.5.2 ROWS/RANGE 帧；4.5.3 **命名窗口** `WINDOW w AS (...)`；4.5.4 `lag/lead/first_value` 帧内取相邻行。
- **4.6 Conditions and filtering outside the WHERE clause**：4.6.1 HAVING（聚合后过滤）；4.6.2 **QUALIFY**（窗口结果过滤——BigQuery 方言的开源化）；4.6.3 **FILTER 子句**（`count(*) FILTER (cond)` 条件聚合，替代 CASE 海）。
- **4.7 The PIVOT statement**：行转列 `PIVOT (agg FOR col IN (v1,v2))`，以及 UNPIVOT。
- **4.8 Using the ASOF JOIN**：不等值时序连接——"取不大于 t 的最近一条"，金融 tick/指标对齐神器；配 `FROM_TO_READ` 变体。
- **4.9 Using table functions**：`range()`、`glob()`、`read_parquet()`、`pragma_list()`、`duckdb_settings()` 等返回表的函数。
- **4.10 Using LATERAL joins**：右表可引用左表列的逐行相关连接；逗号语法 `, LATERAL (...) x`。

## 核心技术清单

- 集合运算全家：GROUPING SETS / CUBE / ROLLUP（+ `grouping()`/`grouping_id()`）。
- 窗口帧：ROWS/RANGE/GROUPS、EXCLUDE CURRENT ROW、`IGNORE NULLS`。
- 命名窗口复用：`WINDOW w AS (PARTITION BY s ORDER BY t)`，同查询多处 `OVER w`。
- QUALIFY 让"每组 Top-1"退化为 `row_number() OVER ... QUALIFY rn=1`，免套壳子查询。
- FILTER 子句让多口径聚合一行写完（次数/金额/去重）。
- ASOF JOIN：`a ASOF JOIN b ON a.k=b.k AND a.t>=b.t`，支持内连接（LEFT 变体语法见陷阱）。
- PIVOT/UNPIVOT 是语句级（`FROM x PIVOT (...)`），不是函数。
- LATERAL 与"相关标量子查询"等价但可返回多行/多列。

## 🔧 实测（10 万行 sales 表，逐条点验）

| 语法 | 结果 |
| --- | --- |
| `GROUP BY GROUPING SETS ((region),(region,product))` | ✅ 两种粒度并集 |
| `ROLLUP(region)` 带总计 | ✅ 3 行正常 |
| `avg(amount) OVER (PARTITION BY region ORDER BY id ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)` | ✅ 移动平均 |
| `row_number() OVER (PARTITION BY region ORDER BY amount DESC) rn ... QUALIFY rn=1` | ✅ 每组最大 10 行 |
| `count(*) FILTER (amount>50)` vs `FILTER (amount<=50)` | ✅ 49904/50096 |
| `FROM t PIVOT (sum(amount) FOR product IN (1,2,3))` | ✅ 3 列宽表；缺失组合为 NULL |
| `a ASOF JOIN b ON a.k=b.k AND a.t>=b.t` | ✅ 匹配到 t=8 的最近行 |
| `LEFT ASOF JOIN` | ❌ Parser Error（`LEFT_ASOF` 亦 ❌；成书版可用性与当前差异见陷阱） |
| `s, LATERAL (SELECT count(*) m FROM sales t WHERE t.region=s.region) x` | ✅ 相关右表逐行生效 |
| `SELECT * FROM range(3)` 表函数 | ✅ |
| 预聚合：`COPY (SELECT plant, sum(mwh) FROM read_csv_auto('big.csv') GROUP BY ALL) TO 'agg.parquet'` | ✅ 5M 行 CSV→1000 行聚合 Parquet 一次过（<1 s，配合 05 章链路） |

## 易错点与陷阱

- **ASOF 连接的方向语义**：`a.t >= b.t` 是"取 b 中 ≤ a.t 的最近值"；写成 `<=` 且放错表会静默给你空结果。LEFT 语义的版本/语法在 1.5.5 本机两次 Parser Error（⚠️ 具体以 https://duckdb.org/docs/stable/clients/overview ✅ 文档入口查 asof 页为准），需要左语义时先用 `UNION`/`COALESCE` 手工兜。
- **PIVOT 的 IN 列表要写死值**：动态列需要预查询拼 SQL（或 UNPIVOT 反推）——报表宽表别用 PIVOT 硬扛 schema 漂移。
- **QUALIFY 与 WHERE 的顺序心智**：执行序 WHERE→GROUP→HAVING→窗口→QUALIFY；在 QUALIFY 里引用非窗口列要确认上游没改名。
- **FILTER 里放相关子查询**会被物化每行执行——把条件列先投影出来。
- **命名窗口里再写帧**：`OVER w (ROWS ...)` 的覆盖语法各版本支持度不一，跨版本迁移时展开写。
- **LATERAL 性能**：本质是相关执行，右侧是"每左行一次小查询"，百万级左表时先想窗口方案。
- **ASOF/窗口在大 Parquet 直查时**仍要全量物化分区（无持久 shuffle 统计），第 10 章的执行器视角能解释。

## 核心概念速览（中英对照）

- **分组集** — GROUPING SETS：一条查询多个分组粒度并集。
- **立方/卷积** — CUBE / ROLLUP：全子集/层级前缀的 grouping sets 糖。
- **窗口帧** — Window frame：ROWS/RANGE/GROUPS 定义的移动计算窗。
- **命名窗口** — Named window：`WINDOW w AS (...)` 复用窗口定义。
- **QUALIFY** — 窗口过滤子句：对窗口函数结果行过滤。
- **FILTER 子句** — Filtered aggregate：`agg(...) FILTER (WHERE cond)` 条件聚合。
- **行转列** — PIVOT / UNPIVOT：宽↔长透视语句。
- **时序最近邻连接** — ASOF JOIN：不等值键上"最近不晚于"匹配。
- **表函数** — Table function：返回表值的函数（read_parquet/range/glob）。
- **侧连接** — LATERAL join：右支可引用左支列的相关连接。
- **预聚合** — Pre-aggregation：摄取时物化聚合结果换查询延迟。
- **列画像** — Data profile / SUMMARIZE：null 率/分布/极值摘要。

## 最新演进与工业实践

- **ASOF JOIN 家族扩展**：2024–2026 文档线持续维护 `ASOF`/`LEFT_ASOF` 与 tolerance 讨论（⚠️ 本机实测差异见上；社区侧 ClickHouse 的 `ASOF JOIN` 多键语义与 DuckDB 不同，跨引擎迁移要重写 ON）。
- **窗口 GROUPS 模式与 EXCLUDE**：1.x 已 GA，对齐 PG/Oracle 方言；`lag(... IGNORE NULLS)` 在 IoT 清洗里成为标准写法（社区实践，⚠️ 无权威链接）。
- **QUALIFY/FILTER 的扩散**：Snowflake/BigQuery 原创 → DuckDB 开源化 → ClickHouse、Databricks 跟进（定性判断）。
