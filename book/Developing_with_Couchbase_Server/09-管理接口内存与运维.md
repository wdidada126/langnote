## 2. 内存模型：配额、水位线、驱逐

✅ [Memory](https://docs.couchbase.com/server/current/learn/buckets-memory-and-storage/memory.html) 要点：

- 每个服务都要配内存配额（Query/Eventing 等除外）；
- 高/低水位线（`memoryHighWatermark` / `memoryLowWatermark`）触发对桶的驱逐；
- 每个桶绑定一个**驱逐策略（ejection policy）**；Ephemeral 桶另有策略；
- 8.0 起：这些参数进了桶 REST API，默认 `memoryLowWatermark=75`、`memoryHighWatermark=85`、`warmupBehavior=background`、`expiryPagerSleepTime=600`、`accessScannerEnabled=true`（✅ [rest-bucket-create](https://docs.couchbase.com/server/current/rest-api/rest-bucket-create.html) + ✅ [whats-new](https://docs.couchbase.com/server/current/introduction/whats-new.html)），并从 `cbepctl` 移除同名旧参数。

🔧 **E3（持久化档位）的运维含义**：同一段写入代码，仅改「承诺强度」一个参数就出现 43 180 → 2 143 ops/s 的 20× 落差（SQLite WAL，`synchronous` OFF→FULL，5000 次提交，本机实跑）。**默认值不是性能最优值**：桶的 eviction/durability/watermark 三项组合决定你的尾延迟曲线——这句话对任何引擎成立。

## 3. 桶参数：2014 与 2026 的字段对照

| 参数 | 2014 基线（⚠️ 推定） | 2026（✅） |
|---|---|---|
| 类型 | memcached / couchbase（disk-focused / memory-optimized 两种变体） | `couchbase` / `ephemeral`；**Memcached 桶已在 8.0 移除** |
| 引擎 | couchstore（单一） | `couchstore` / `magma`（8.0 新默认 Magma+128 vBucket） |
| vBucket | 1024 固定 | 1024（Couchstore）或 128/1024（Magma） |
| 驱逐 | `last_accessed` / `noflag` 等 | `value only` / `full eviction` / `no eviction`（✅ [buckets](https://docs.couchbase.com/server/current/learn/buckets-memory-and-storage/buckets.html)），且 8.0 支持**不重启改策略**（✅ whats-new） |
| TTL | 单文档过期 | 单文档 + 桶/集合 **maxTTL**（✅ [expiration](https://docs.couchbase.com/server/current/learn/data/expiration.html)） |
| 副本 | 0–3 | 0–3 不变（✅ [replication-architecture](https://docs.couchbase.com/server/current/learn/clusters-and-availability/replication-architecture.html)） |
| 压缩 | 视图/文档碎片整理 | ✅ [compression](https://docs.couchbase.com/server/current/learn/buckets-memory-and-storage/compression.html) + Magma 的自动整理（⚠️ 细节以页为准） |
| 存储设置 | 磁盘路径/配额 | ✅ [storage-settings](https://docs.couchbase.com/server/current/learn/buckets-memory-and-storage/storage-settings.html)，8.0 新增文件系统占用上限（✅ whats-new） |

## 4. 隔离与爆炸半径：collection 作为运维单位

🔧 **E7/E7b（本机 SQLite，非 Couchbase 行为）**：把 3 个 SQLite 文件 `ATTACH` 成「3 个桶」，桶内用 `scope__collection` 前缀表模拟层级。

- 跨桶查询耗时 **0.27ms**（一次连接里 join 两个文件）；
- `detach database billing` 仅 **0.04ms**：一个桶的消失对其他桶零影响；
- 三个文件大小各 132 KiB，独立可备份。

映射到真实产品的意义：collection 级 flush/删除、独立 maxTTL、独立索引、独立 XDCR 管道，让「一个租户搞坏整个桶」这类事故有了结构化的遏制手段（✅ [manage-scopes-and-collections](https://docs.couchbase.com/server/current/manage/manage-scopes-and-collections/manage-scopes-and-collections.html)）。

## 核心概念速览（中英对照）

- **REST 管理 API** — `/pools/default/...`：桶/节点/再平衡的自动化接口，2014 至今同源。
- **couchbase-cli / cbstats / cbq** — 官方 CLI 三件套：建集群、看统计、跑查询。
- **内存配额** — Memory Quota：每服务的内存预算，100MiB/1GiB 是 Magma-128/1024 的门槛差。
- **水位线** — Watermark（low/high）：触发驱逐的内存压力线，默认 75/85。
- **驱逐策略** — Ejection Policy：value only / full eviction / no eviction。
- **warmup** — 重启预热：`background/blocking/none` 三档（8.0 统一为 `warmupBehavior`）。
- **maxTTL** — 桶/集合级默认与最大过期时间。
- **cbbackupmgr** — 备份工具：仓库、加密、增量、保留期与 prune。
- **cbimport/cbexport** — 批量迁移与装载工具（含 CSV/JSON）。
- **RBAC** — 角色化权限：与认证域（本地/LDAP）配合。
- **加密-at-rest** — 静态加密：8.0 原生支持并可对接 KMS。
- **指标手册** — metrics reference：按服务分类的可观测契约。
- **在线再平衡** — 不改服务的重分布：运维窗口的核心操作（第 2 章）。
- **平台支持矩阵** — 8.0 增删 OS 列表（含 Windows Server 2025 加、2019 移除）。

## 最新演进与工业实践

1. **8.0 的默认行为变更必须进变更单**：Magma+128 成为新桶默认、Memcached 桶移除、`cbepctl` 若干参数删除——官方明确要求升级前核对部署脚本（✅ [whats-new](https://docs.couchbase.com/server/current/introduction/whats-new.html)）。
2. **平台矩阵刷新**：8.0 新增 RHEL 10 / Oracle Linux 10 / Alma 10 / Debian 13 / Windows Server 2025，移除 Ubuntu 20.04、Windows Server 2019、SLES 12 等（✅ whats-new「Platform Support」段）——2014 书里的安装矩阵今天 100% 失效。
3. **服务可动态增删**：`index/n1ql/fts/cbas/eventing/backup` 可在既有节点上改并自动再平衡（✅ whats-new）⇒ 「加一个查询节点要换机器」的老经验作废。
4. **备份生命周期产品化**：保留期 + 定时 prune + 依赖保护（✅ whats-new + ✅ [manage-backup-and-restore](https://docs.couchbase.com/server/current/manage/manage-backup-and-restore/manage-backup-and-restore.html)）。
5. **托管运维的减法**：Capella 把配额/再平衡/升级/备份变成控制台与 API 动作（✅ create-database / billing 页），自建集群的「运维面知识」在云上转化为「选型与预算知识」。
