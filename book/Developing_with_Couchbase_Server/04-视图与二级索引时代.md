# 04 · 视图与二级索引时代

> 主题域：MapReduce 视图作为 2014 年「唯一能按值查询」的手段，如何被 GSI + SQL++ 取代，以及 spatial/FTS 的续命路径。
> 章号/章名 ⚠️ 精读重构；✅ 为官方文档原句/URL；🔧 为本机类比。

## 1. 2014 的现实：KV 之外只有视图

基线（⚠️ 推定该书口径，机制本身 ✅ 由现存文档证实）：

- 想「按国家找机场」，不能扫键，只能**预先声明一个视图**：`map(doc)` 发出 `(key, value)`，服务器把它排成持久化的、按 key 排序的 B-tree（`_design/<ddoc>/_view/<name>`）。
- 视图是**最终一致**的：官方原句「Views are eventually consistent compared to the underlying stored documents.」（✅ [views-intro](https://docs.couchbase.com/server/current/learn/views/views-intro.html)）
- 文档要**落盘**后才进视图索引；带 expiry 的文档在过期分页器清理时才从索引移除（✅ 同页）。

## 2. 视图的四种查询姿势（以及它们今天的替身）

| 姿势 | 视图语法要素 | 2026 替身（✅） |
|---|---|---|
| 前缀/范围扫描 | `startkey`/`endkey` + 数组键序 | SQL++ 的 `GSI` 复合索引 + `BETWEEN`/`LIKE` |
| 降序、翻页 | `descending`、`skip/limit`、`range` 续传 | `OFFSET/LIMIT` 或键集分页 |
| 聚合 | `reduce` + `group=true`、`group_level` | `GROUP BY`（Query）或 Analytical Service |
| 陈旧度控制 | `stale=false / update_after / ok` | GSI 近实时；视图的 `stale` 概念整体退役 |
| 结果改写 | list/show 函数（JS） | 子查询/表达式，或 Eventing 预处理 |
| 地理 | spatial views（bounding box 发射） | Search Service 的 geo 查询 |
| 全文 | FTS（3.0 期起步） | Search Service（成熟）+ 向量检索混合 |

## 3. 🔧 实测：视图的成本结构（SQLite 物化表类比，非 Couchbase 行为）

用 20 万个 JSON 文档（`src(key, doc)`）模拟一个桶，把视图当成物化索引表 `v_airport(country, faa, key)`：

- **全量重建 200000 行：0.19s**（等价 `stale=false` 的全量 index build；真实集群里这是按 vBucket 分片并行、且会拖慢读写的高成本动作）。
- **增量只补尾段 1000 行：0.9ms**（等价 `stale=update_after` / `ok` 的读旧写新）→ 两者相差 **≈210×**，这就是 2014 代码里到处写 `stale=ok` 的全部动机：**牺牲新鲜度换延迟**。
- 索引化后的范围查询（`country='US' AND faa>? LIMIT 10`）：**0.06ms** 返回 10 行——视图一旦建好，前缀扫描本身极快，痛点始终在**构建与维护**。
- 倒排类比（E4b，Search Service 的替身）：SQLite **FTS5** 建 30000 文档索引 **0.14s**，`runways AND US` 命中 7433、查询 **1.5ms**。

**结论（跨版本成立）**：二级索引不是免费的读加速，而是「把一次昂贵的全量计算摊到每次写 + 一段陈旧窗口」。理解这一点，才理解为什么官方最终选择「近实时 GSI」而不是继续优化视图。

## 4. 视图的死刑判决书（✅ 原句）

https://docs.couchbase.com/server/current/learn/views/views-intro.html：

> "**Views are deprecated in Couchbase Server 7.0 and later versions. Views support in Couchbase Server will be removed in a future release.** Instead of views, use indexes and queries using the Index Service (GSI) and the Query Service (SQL++). **Views will not run on the newer Magma storage engine.**"

三条含义：

1. 2014 年那本书的核心技能（design doc / reduce / list 函数）在 2026 属于**存量维护技能**，新项目不应再选。
2. 迁移不是可选：新默认存储引擎 Magma 上视图**根本跑不了**（联动 [01-Couchbase定位与文档键值模型.md](01-Couchbase定位与文档键值模型.md) 第 3 节、[02-集群架构与vBucket映射.md](02-集群架构与vBucket映射.md) 第 2 节）。
3. 官方为过渡留了台阶：视图索引可被 Query 使用（✅ [learn/views/view-indexes-for-n1ql](https://docs.couchbase.com/server/current/learn/views/view-indexes-for-n1ql.html)），生产迁移清单见 ✅ [views-production](https://docs.couchbase.com/server/current/learn/views/views-production.html)、查询样例见 ✅ [views-query-samples](https://docs.couchbase.com/server/current/learn/views/views-query-samples.html)、schemaless 索引进阶见 ✅ [views-schemaless](https://docs.couchbase.com/server/current/learn/views/views-schemaless.html)。

## 5. GSI + SQL++：替代者的形状

- ✅ 查询语言参考（标题即品牌）：`SQL++ for Query Reference` — https://docs.couchbase.com/server/current/n1ql/n1ql-language-reference/index.html ，正文原句「The Couchbase implementation of SQL++ was formerly known as N1QL.」
- ✅ 索引侧：[Index Service](https://docs.couchbase.com/server/current/learn/services-and-indexes/services/index-service.html)（GSI，近实时、可分布式、支持覆盖索引/偏索引/表达式索引）；查询侧：[Query Service](https://docs.couchbase.com/server/current/learn/services-and-indexes/services/query-service.html)。
- ✅ 与 SQL 的差别被单列成页：[n1ql-versus-sql](https://docs.couchbase.com/server/current/learn/data/n1ql-versus-sql.html)。
- ✅ 交互式入口：[Query Workbench](https://docs.couchbase.com/server/current/tools/query-workbench.html)、[cbquery report gen](https://docs.couchbase.com/server/current/cli/cbqueryreportgen.html)、REST：[n1ql-rest-query](https://docs.couchbase.com/server/current/n1ql-rest-query/index.html)。
- 2014→2026 的写法迁移示范（同一诉求两代方案）：

```text
旧（视图）：GET /default/_design/airport/_view/by_country?startkey=["US"]&endkey=["US",{}]&limit=10
新（SQL++）：CREATE INDEX ix_airport ON bucket(scope.collection)(country, faa);
            SELECT country, faa, META().id FROM `bucket`.`scope`.`collection`
            WHERE country="US" AND faa>$1 ORDER BY faa LIMIT 10;
```

（⚠️ 语法骨架依据 ✅ collection 相关 DDL 页：[collectionops](https://docs.couchbase.com/server/current/n1ql/n1ql-language-reference/collectionops.html)、[createcollection](https://docs.couchbase.com/server/current/n1ql/n1ql-language-reference/createcollection.html)；非本机可执行代码——本机没有 Couchbase。）

## 6. 全文与地理：视图的两个私生子活下来了

- ✅ [Search Service](https://docs.couchbase.com/server/current/learn/services-and-indexes/services/search-service.html)：官方定位「supports the creation of specially purposed indexes for Full Text Search」；2026 它同时是 **Search Vector index** 的宿主（见下第 7 节）。
- 检索请求/响应的形状（评分、命中、耗时、错误）在 ✅ [fts-search-response](https://docs.couchbase.com/server/current/fts/fts-search-response.html) 与 ✅ [fts-scoring](https://docs.couchbase.com/server/current/fts/fts-scoring.html)；高可用索引与零停机升级见 ✅ [fts-high-availability-for-search](https://docs.couchbase.com/server/current/fts/fts-high-availability-for-search.html)、✅ [zero-downtime-index-upgrades](https://docs.couchbase.com/server/current/fts/fts-high-availability-for-search-zero-downtime-index-upgrades.html)。
- 2014 的 spatial views → 今天走 Search 的 geo 查询（⚠️ 转述；spatial views 的独立文档路径在 8.0 sitemap 中已不存在，只有 `5a_views.html` 这类对照段仍留在 analytics 模块）。
- 🔧 E4b 的 FTS5 数字（30000 文档 0.14s 建索引 / 1.5ms 查询）只是「倒排索引不是魔法」的直觉校准，**不代表** Search Service 的分片与副本模型。

## 7. 向量索引：二级索引家族的第三代

✅ [vectors-and-indexes-overview](https://docs.couchbase.com/server/current/vector-index/vectors-and-indexes-overview.html)：

- 索引算法含 **Flat（暴力，无优化：官方「Searches using this index use a brute-force method」**）、IVF 与 **HNSW 图索引 IVF 质心**的组合（Hyperscale/Composite 均「always use IVF as the basis … use a Hierarchical Navigable Small World (HNSW) graph to index the IVF's centroids」）；
- **量化（Quantization）** 换空间与速度、牺牲精度（官方类比 lossy 图像压缩）；
- **四种相似度度量**（含 Euclidean/L2、cosine 等）；
- 8.0 新增两类由 Index Service 承载的 GSI 向量索引：**Hyperscale Vector**（单向量列、十亿级、低内存）与 **Composite Vector**（向量 + 标量列，先标量过滤再做相似检索）；Search Vector 用于「向量 + 文本/地理」混合检索（✅ [whats-new](https://docs.couchbase.com/server/current/introduction/whats-new.html)）。
- 7.6 期文档路径仍在（✅ `sitemap-server.xml` 含 `/server/7.6/vector-search/vector-search.html` 等 10 条），证明「向量检索在 7.6 已成型、8.0 扩成家系」。
- 🔧 E8/E8b/E8c：纯 Python 暴力余弦 20000×64 = **0.25s/查询**；DuckDB 100000×64 用 `list_cosine_similarity` 暴力 = **0.79s/查询**；加 `WHERE id % 5 = 0` 预过滤 → **0.03s**。这组数字精确复刻了 Composite Vector index 的卖点：**先缩小候选集，相似度扫描就便宜 25 倍**。盘上深读：[../Vector_Databases/03-相似度度量与向量空间.md](../Vector_Databases/03-相似度度量与向量空间.md)、[../Vector_Databases/05-ANN索引之二-从NSW到HNSW.md](../Vector_Databases/05-ANN索引之二-从NSW到HNSW.md)、[../Vector_Databases/06-向量数据库产品图谱与架构.md](../Vector_Databases/06-向量数据库产品图谱与架构.md)、[../Vector_Databases/07-应用-语义搜索RAG与混合检索.md](../Vector_Databases/07-应用-语义搜索RAG与混合检索.md)。

## 8. 视图时代代码的迁移判定表（工程 checklist）

| 症状 | 判定 | 处置 |
|---|---|---|
| 视图只做点查前缀 | 易迁 | 建 GSI + 改 SQL++ |
| 依赖 `reduce` 做实时聚合 | 中 | 小聚合走 Query；大扫描迁 Analytical Service（✅ [analytics/introduction](https://docs.couchbase.com/server/current/analytics/introduction.html)） |
| 依赖 `stale=ok` 隐藏延迟 | 陷阱 | GSI 近实时，但**索引滞后仍存在**：改成分支/超时兜底 |
| list/show 函数做投影 | 易 | SQL++ 表达式 |
| 键里编码租户 | 结构问题 | 迁 collection（✅ [scopes-and-collections](https://docs.couchbase.com/server/current/learn/data/scopes-and-collections.html)） |
| 桶用 Magma | 强制 | 必须迁（视图不支持，✅ 原句） |

## 核心概念速览（中英对照）

- **视图** — View：由 map 函数产出的、按 key 排序的持久化二级索引，2014 年唯一的按值查询手段。
- **设计文档** — Design Document (`_design/<ddoc>`)：存放 map/reduce/list/show 函数的特殊文档。
- **reduce / group_level** — 聚合与其粒度：视图版 GROUP BY。
- **stale** — 陈旧度参数：`false/update_after/ok`，用新鲜度换延迟（🔧 实测差 ≈210×）。
- **全局 vs 本地索引** — global/local index：跨节点聚合视图 vs 单节点分片视图。
- **spatial view** — 地理视图：以 bounding box 为键的视图，今天由 Search 的 geo 承接。
- **GSI** — Global Secondary Index：由 Index Service 维护的近实时分布式二级索引。
- **SQL++ / N1QL** — 查询语言：官方现名 SQL++，「formerly known as N1QL」。
- **键空间** — Keyspace：查询目标（桶/scope/collection），视图时代即桶名。
- **覆盖索引** — Covering Index：查询字段全在索引里，免去回表。
- **全文检索服务** — Search Service (FTS)：独立倒排索引服务，现兼作向量索引宿主。
- **向量索引** — Vector Index：Flat/IVF/HNSW 及 8.0 的 Hyperscale/Composite/Search 三类家族。
- **量化** — Quantization：压缩向量以省内存与算力，代价是精度。
- **预过滤** — Pre-filtering：在向量比对前用标量条件缩小候选集（🔧 实测 25× 收益）。
- **混合检索** — Hybrid Search：向量 + 文本/地理/标量条件共同决定结果。

## 最新演进与工业实践

1. **一句话现状**：视图 = 弃用（7.0+）、且在 Magma 上不可运行，官方要求转 GSI + SQL++（✅ 原句，见第 4 节）。
2. **品牌与文档路径的错位**：URL 仍是 `/n1ql/...`，标题已是 `SQL++ for Query`（✅）——写自动化链接时以 sitemap 为准，方法见 [00-总览与阅读地图.md](00-总览与阅读地图.md) 第六节。
3. **SQL++ 作为统一门面**：Query（✅ n1ql-language-reference/index）、Analytics（✅ [analytics/1_intro](https://docs.couchbase.com/server/current/analytics/1_intro.html) 标题即「SQL++ for Analytics」）、向量函数（✅ [vectorfun](https://docs.couchbase.com/server/current/n1ql/n1ql-language-reference/vectorfun.html)、✅ [createvectorindex](https://docs.couchbase.com/server/current/n1ql/n1ql-language-reference/createvectorindex.html)）共用一族语法；`ARRAY/VECTOR` 类型进入语言层（⚠️ 细节以对应页为准）。
4. **分析侧双轨**：老的 Analytics Service（MPP、operational analytics，✅ [analytics-service](https://docs.couchbase.com/server/current/learn/services-and-indexes/services/analytics-service.html)）与新的 Analytical Service（列存、SQL++、Delta 化连接）并存期是 2024–2026 的最大困惑点；8.0 里 `cbas` 仍是可动态增删的服务名（✅ whats-new），因此**服务标识 `cbas` ≠ 新 Analytical Service**，选型时以文档站点入口为准（✅ https://docs.couchbase.com/sitemap-analytics.xml / `sitemap-enterprise-analytics.xml` 在 sitemap 索引中在档）。
5. **RAG 工程视角**：官方把向量检索定位为「让应用在不依赖外部服务的前提下加相似度搜索」（✅ vectors-and-indexes-overview 首段原句），配套 REST/SDK/UI 三条路（✅ [run-vector-search-rest-api](https://docs.couchbase.com/server/current/vector-search/run-vector-search-rest-api.html)、✅ [run-vector-search-sdk](https://docs.couchbase.com/server/current/vector-search/run-vector-search-sdk.html)、✅ [fine-tune-vector-search](https://docs.couchbase.com/server/current/vector-search/fine-tune-vector-search.html)）；产品化的 embedding 生成走 AI Data Plane（✅ https://www.couchbase.com/products/ai-services/ ）。
6. **索引可观测性**：慢查询与计划分析用 ✅ [tools/query-monitoring](https://docs.couchbase.com/server/current/tools/query-monitoring.html) 与 ✅ [n1ql-rest-settings](https://docs.couchbase.com/server/current/n1ql-rest-settings/index.html)；指标口径见 ✅ [query-service-metrics](https://docs.couchbase.com/server/current/metrics-reference/query-service-metrics.html) / [index-service-metrics](https://docs.couchbase.com/server/current/metrics-reference/index-service-metrics.html)。
7. **迁移节奏建议（⚠️ 工程经验转述）**：先「视图 → GSI」保功能，再「桶 → collection」保多租户，最后「Couchstore → Magma」保性能，三步不要合并成一次变更。
