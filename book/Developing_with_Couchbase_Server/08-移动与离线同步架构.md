# 08 · 移动与离线同步架构

> 主题域：把数据放到设备端、再把它可靠地收回集群——2014 年由 CBL/Sync Gateway 承担，2026 年由 Couchbase Lite 4.x + Capella App Services + Edge Server 承担。
> 本章主题在本书 2014 覆盖面为 ⚠️ 推定；2026 现状全部 ✅ 到 docs.couchbase.com。

## 1. 问题结构（不随版本变化）

离线优先应用要同时满足：

1. 本地毫秒级读写（设备端要有完整数据库 + 索引）；
2. 网络断断续续、可长时段不可用；
3. 多设备 + 服务端同时改同一文档 → 冲突；
4. 不能把所有数据同步给所有设备（权限、体积、隐私）；
5. 设备可能丢失/被盗 → 服务端要有权威副本与访问控制。

这五条决定了它**不是**「一个慢一点的 REST 缓存」，也不是「XDCR 的又一个方向」（[07-跨数据中心复制与多活.md](07-跨数据中心复制与多活.md) 讲过 LWW 的代价，设备端的分区容忍性更强）。

## 2. 三层角色

| 角色 | 职责 | 2026 载体（✅） |
|---|---|---|
| 设备端数据库 | 存文档、建索引、跑查询、记录变更 | Couchbase Lite（✅ https://docs.couchbase.com/couchbase-lite/current/index.html ，文档站 1535 页，版本目录含 4.0/3.4/3.3） |
| 同步中介 | 认证、通道（channel）过滤、与集群双向复制 | **Capella App Services**（✅ https://docs.couchbase.com/app-services/index.html ）；自建路径仍是 Sync Gateway（✅ `sitemap-sync-gateway.xml` 在 sitemap 索引中在档） |
| 权威存储 | 桶/collection + 索引 + 分析 | Couchbase Server / Capella（✅ 见 [00-总览与阅读地图.md](00-总览与阅读地图.md) 第六节） |

**命名沿革（✅ 可证）**：文档站的独立站点名已是 `app-services`，并提供 `migrating/on-prem-to-capella.html`（✅ 从自建迁到托管的指南存在）与 `migrating/migrate-sync-metadata.html`（✅）——即「自建 Sync Gateway → 托管 App Services」是被官方支持的迁移路径。

## 3. 同步机制的语义要点（✅ 概念 + ⚠️ 细节转述）

- ** Pull/Push 双向、增量、可断点续传**（持续复制 vs 一次性复制两种模式）。
- **通道/过滤**：按用户/租户决定设备上能看到哪些文档（服务端 JavaScript 过滤器；✅ app-services 侧的对应物是 App Endpoint 的访问控制与校验：✅ [about-access-control](https://docs.couchbase.com/app-services/app-endpoints/about-access-control.html)、✅ [access-control-data-validation](https://docs.couchbase.com/app-services/app-endpoints/access-control-data-validation.html)、✅ [import-filters](https://docs.couchbase.com/app-services/app-endpoints/import-filters.html)）。
- **冲突解决**：设备端与服务端各自的 rev 树 + 可插拔解决器（✅ Lite 侧专页 https://docs.couchbase.com/couchbase-lite/current/android/conflict.html ）。
- **Delta 同步**：只传差异以省流量（✅ [delta-sync](https://docs.couchbase.com/app-services/app-endpoints/delta-sync.html)）。
- **XATTR 用于同步元数据**（✅ [xattrs-for-app-services](https://docs.couchbase.com/app-services/app-endpoints/xattrs-for-app-services.html)）⇒ 与第 6 章「别把元数据塞正文」的纪律同源。
- **resync**：过滤器逻辑变更后重算通道归属（✅ [resync](https://docs.couchbase.com/app-services/app-endpoints/resync.html)）——2014 书里没有的运维动作，今天它是权限模型可演化的前提。

## 4. 与集群侧机制的接口

- 设备写的文档最终进入某个 collection，然后与所有其他写一样被 GSI/Search/向量索引消费（[04-视图与二级索引时代.md](04-视图与二级索引时代.md)）；
- 与 XDCR 叠加时冲突面变大（✅ [xdcr-active-active-sgw](https://docs.couchbase.com/server/current/learn/clusters-and-availability/xdcr-active-active-sgw.html)）；
- 设备端事件可用 **Eventing** 做加工（✅ [eventing-service](https://docs.couchbase.com/server/current/learn/services-and-indexes/services/eventing-service.html)：「near real-time handling of changes to data; whereby code is executed either in response to mutations, or as scheduled by timers」）；
- 🔧 类比（E6b/E6c，第 7 章脚本）：设备离线 3 天后回传的写，与「时钟偏斜下的物理后写落败」是同一类算术——LWW 不认业务时间，**必须让业务字段（如 `updatedAt` + 版本号）参与合并决策**，而不是指望数据库替你做。

## 6. 架构决策清单

1. **需要离线写吗？** 只读缓存 → 直接用服务端 + HTTP 缓存即可，别引入 Lite（复杂度陡增）。
2. **同步单位是什么？** 用户/项目/工单 → 用 channel / App Endpoint 边界表达（对应服务端 collection，[06-数据建模与键空间设计.md](06-数据建模与键空间设计.md)）。
3. **谁是权威？** 冲突合并必须有业务规则（字段级合并 / 最后编辑者胜出 / 人工裁决），把规则写进解决器而不是散落在 UI。
4. **带宽预算**：开启 delta sync（✅ 页在档），文档体积与大字段（base64 图片）是首要敌人。
5. **权限变更如何生效？** 靠 resync（✅），把「改过滤器必须评估 resync 成本」写进发布纪律。
6. **端侧 AI**：设备端向量检索 + 服务端 Hyperscale 向量索引可做「就近召回 + 中心召回」两级（✅ 两侧页均在档，见第 5 节与 [10-从2014基线到2026演进手册.md](10-从2014基线到2026演进手册.md)）。

## 核心概念速览（中英对照）

- **离线优先** — Offline-first：设备端持有完整可写数据库，网络只是同步通道。
- **Couchbase Lite (CBL)** — 设备端嵌入式数据库，支持查询/全文/向量检索。
- **Sync Gateway / App Services** — 同步中介：自建 vs 托管的两种形态，托管现称 App Services。
- **Couchbase Edge Server** — 面向端侧部署的同步服务形态（✅ sitemap-couchbase-edge-server.xml）。
- **通道** — Channel：把文档子集分发给特定设备/用户的过滤单位。
- **App Endpoint** — 托管形态下的对外端点，含访问控制与数据校验。
- **Pull/Push 复制** — 双向增量同步，可持久化进度。
- **Delta Sync** — 只同步差异部分以省带宽。
- **rev 树** — 修订历史：设备端冲突检测的元数据结构。
- **冲突解决器** — Conflict Resolver：把业务合并规则写进代码的位置。
- **resync** — 过滤器变更后重建通道归属的运维动作。
- **XATTR 承载同步元数据** — 不把 `_rev` 类字段混进业务正文。
- **设备加密** — Database/At-rest Encryption：端侧与 Edge 侧的数据保护。
- **持续复制** — Continuous Replication：长连接式实时同步。
- **端云双召回** — 设备向量索引 + 服务端 Hyperscale 向量索引协同的检索布局。
