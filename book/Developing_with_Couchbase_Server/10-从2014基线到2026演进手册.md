### 3.2 向量检索（AI 数据线）

- 三类索引：**Search Vector / Hyperscale Vector / Composite Vector**（✅ [whats-new](https://docs.couchbase.com/server/current/introduction/whats-new.html)、✅ [vectors-and-indexes-overview](https://docs.couchbase.com/server/current/vector-index/vectors-and-indexes-overview.html)）
- 算法：Flat（暴力）、IVF + HNSW 质心图、量化（✅ 同页原句，见 [04-视图与二级索引时代.md](04-视图与二级索引时代.md) 第 7 节）
- 操作面：✅ [create-vector-search-index-ui](https://docs.couchbase.com/server/current/vector-search/create-vector-search-index-ui.html)、✅ [run-vector-search-sdk](https://docs.couchbase.com/server/current/vector-search/run-vector-search-sdk.html)、✅ [pre-filtering-vector-search](https://docs.couchbase.com/server/current/vector-search/pre-filtering-vector-search.html)、✅ [fine-tune-vector-search](https://docs.couchbase.com/server/current/vector-search/fine-tune-vector-search.html)、✅ [vector-index-best-practices](https://docs.couchbase.com/server/current/vector-index/vector-index-best-practices.html)、✅ [hyperscale-reranking](https://docs.couchbase.com/server/current/vector-index/hyperscale-reranking.html)
- 端侧：✅ [couchbase-lite android/vector-search](https://docs.couchbase.com/couchbase-lite/current/android/vector-search.html)
- 🔧 实测校准：本机暴力扫 100000×64 单查询 0.79s（DuckDB `list_cosine_similarity`）；预过滤后 0.03s ⇒ **「先缩小候选集」的收益比换 ANN 算法更早兑现**（非 Couchbase 行为）。深读：[../Vector_Databases/05-ANN索引之二-从NSW到HNSW.md](../Vector_Databases/05-ANN索引之二-从NSW到HNSW.md)、[../Vector_Databases/08-评测基准与工程实践.md](../Vector_Databases/08-评测基准与工程实践.md)。

### 3.3 分析侧：Analytics Service 与 Analytical Service

- 旧的 **Analytics Service**（MPP、operational analytics）：✅ [analytics-service](https://docs.couchbase.com/server/current/learn/services-and-indexes/services/analytics-service.html)，服务标识仍是 `cbas`（✅ whats-new 动态服务列表）。
- 新的 **Analytical Service**（列存、SQL++）：产品文档以独立 sitemap 存在 → ✅ `https://docs.couchbase.com/sitemap-analytics.xml` 与 `https://docs.couchbase.com/sitemap-enterprise-analytics.xml`（两者均在 sitemap 索引中在档）；本册未逐页抓取其正文，**二者并存期的取舍请按需复核 ⚠️**。
- 🔧 直觉校准：同一份 100 万行数据，行存扫描 433ms vs 列存 4.3ms（≈102×，E5b/E5c 本机实跑）——这就是「操作 KV 引擎 + 独立分析引擎」这类架构存在的算术理由。

## 5. 概念续命表：书里哪些东西今天仍然成立

| 仍成立（跨版本） | 依据（本册 🔧/✅） |
|---|---|
| 键是唯一性单位、点查是最快路径 | ✅ [learn/data/data](https://docs.couchbase.com/server/current/learn/data/data.html) |
| CAS 是单键并发控制的全部 | 🔧 E2（无 CAS 丢失率 100%） |
| 二级索引 = 用写成本换读延迟 | 🔧 E4（0.19s 全量 / 0.9ms 增量） |
| 副本与 durability 是三角权衡 | ✅ [durability](https://docs.couchbase.com/server/current/learn/data/durability.html) + 🔧 E3（20× 档差） |
| 分片需要一个中间层以控制迁移比例 | 🔧 E1（74.77% → 25.0%） |
| 逻辑过期 ≠ 物理删除 | 🔧 E2c/E2c2（宽限期实删 0 行 / 真删 10000 行） |
| 多活并发写必丢一方 | 🔧 E6b（A 存活 0 / B 存活 5000） |
| 文档要能装进一次内存操作 | ✅ 值/文档模型 + ⚠️ 上限值随版本 |

## 核心概念速览（中英对照）

- **View 时代** — View Era：以 MapReduce 视图为唯一二级索引的 2014–2019 阶段。
- **GSI** — Global Secondary Index：近实时分布式二级索引，视图的法定继承者。
- **SQL++** — SQL++：跨 Query/Analytics 的统一语言，前称 N1QL。
- **Collection** — 集合：租户/类型隔离的一等对象，取代键前缀与多桶方案。
- **Magma** — 新默认存储引擎：LSM 式，配 128 vBucket，视图不支持。
- **Hyperscale Vector Index** — 面向十亿级单向量列、低内存的向量索引。
- **Composite Vector Index** — 向量 + 标量列，先过滤后相似检索。
- **Search Vector Index** — 与全文/地理混合的向量索引（Search Service 承载）。
- **Analytical Service** — 列存分析引擎，SQL++ 门面（与旧 Analytics Service 并存期）。
- **Capella** — 托管服务：集群即 Database，控制台/API 取代手搓 REST。
- **App Services** — 托管移动同步（原 Sync Gateway 云化）。
- **Edge Server** — 端/边缘侧同步服务形态。
- **MCP Server** — 让 AI 编码代理访问集群的官方服务面。
- **AI Data Plane** — 官方 AI 数据线（内嵌向量化 + 检索）。
- **Bucket Rank** — 再平衡时的桶优先级（7.6+）。

## 最新演进与工业实践

1. **今天选 Couchbase 的三条真实理由**（✅ 支撑）：键值级点查 + 文档模型（✅ [document-data-model](https://docs.couchbase.com/server/current/learn/data/document-data-model.html)）；把搜索/向量/分析作为同集群的独立服务（✅ [search-service](https://docs.couchbase.com/server/current/learn/services-and-indexes/services/search-service.html) / [analytics-service](https://docs.couchbase.com/server/current/learn/services-and-indexes/services/analytics-service.html) / ✅ vectors 页）；以及托管化后的多设备同步（✅ [app-services/index](https://docs.couchbase.com/app-services/index.html)）。
2. **今天选型要先回答的问题**：是否接受「多服务多节点」的运维面（✅ 动态服务增删只是缓解）；是否需要 1000 collection 之外的更细隔离（✅ 上限原句）；视图存量能否迁 GSI（✅ 弃用原句）；是否愿意把分析放另一条引擎（✅ E5b/E5c 的 102× 算术）。
3. **许可证与版本线**：Community Edition 与 Enterprise 的当前条款本册**未取证**（⚠️ 缺口；✅ 官方下载页对程序化抓取返回 403：https://www.couchbase.com/downloads/ ），引用前请人工确认。
4. **升级路径纪律**：8.0 的三项默认变更（Magma-128、Memcached 桶移除、`cbepctl` 参数删）都可能让旧自动化脚本静默失败（✅ whats-new）；跨版本升级步骤与影响以 ✅ [upgrade-procedures](https://docs.couchbase.com/server/current/install/upgrade-procedures.html)、✅ [upgrade-feature-availability](https://docs.couchbase.com/server/current/install/upgrade-feature-availability.html) 为准。
