| 主题 | 本书位置 | 2026 年的现状 |

## 核心精讲

### 通用配置读取器骨架（13.4 的浓缩版，教学示意，不编译、不运行、不参与构建）

```antlr
// 教学示意代码，不编译、不运行、不参与构建
// Config.g4：一个「通用配置」语法骨架
grammar Config;
key   : ID ;
value : INT | FLOAT | STRING | '{' valueList '}' | '[' valueList ']' ;
valueList : value (',' value)* ;
entry : key '=' value ';' ;
config : entry* EOF ;
ID : [a-zA-Z_][a-zA-Z_0-9.-]* ;     // 点号也允许出现，方便命名空间式 key
INT : [0-9]+ ; FLOAT : [0-9]+ '.' [0-9]+ ;
STRING : '"' ~["\\]* '"' | '\'' ~['\\]* '\'' ;
WS : [ \t\r\n]+ -> skip ;
```

### 诊断输出的形状（工程要点，教学示意）

```java
// 教学示意代码，不编译、不运行、不参与构建
class ErrorListener extends BaseErrorListener {
  @Override public void syntaxError(Recognizer<?,?> r, Object offending,
                                    int line, int col, String msg, RecognitionException e) {
    System.err.printf("config.cfg:%d:%d: 语法错误: %s%n", line, col, msg);
    System.err.printf("  %s%n  %s^%n", sourceLines.get(line - 1), " ".repeat(col));
  }
}
```

### 语法高亮 / IDE 支持的最小骨架（13.5 的「改源码」场景，教学示意）

```python
# 教学示意代码，不编译、不运行、不参与构建
from lark import Lark, Token
p = Lark(r"""start: (entry WS*)* ; entry: NAME WS* "=" WS* value ";" WS* ;
             value: NUMBER | STRING ; NAME: /[a-z_][a-z0-9_]*/i ;
             NUMBER: /\d+/ ; STRING: /"[^"]*"/ ; WS: /\s+/ ; %ignore WS""",
         parser="lalr")

def tokenize(text):                     # 只做词法，也能喂高亮
    from lark.lexer import TraditionalLexer
    return TraditionalLexer(p.options['lexer'], p.options['parser'], None).tokenize(text)

# 生产级做法：Tree-sitter 的 highlight query —— 语法文件直接产出配色
```

### lark 版「配置读取器」（Python 对照，教学示意）

```python
# 教学示意代码，不编译、不运行、不参与构建
import json
from lark import Lark, Transformer, v_args

class ToJson(Transformer):
    def KEY(self, tok): return tok.value
    def INT(self, tok): return int(tok)
    @v_args(inline=True)
    def pair(self, k, v): return (k, v)
    @v_args(inline=True)
    def obj(self, *pairs): return dict(pairs)

p = Lark(r"""start: (pair ";"+)* ; pair: NAME "=" value ; value: INT | NAME ;
             %import common.CNAME -> NAME %import common.INT %import common.WS %ignore WS""")
print(json.dumps(dict(ToJson().transform(p.parse("a = 1; b = c;"))), ensure_ascii=False))
```

## 常见误区与本书需修正之处

| 误区 / 需修正之处 | 说明 |
| --- | --- |
| 🔧 中译本出版年份较早（2012-03），书中「语言应用」案例与今天的工具链不同代 | 请把 StringTemplate 案例当作**模式学习材料**，工具换成当代 equivalents（Jinja2 / `text/template` 等，见 `09-翻译与模板生成.md`） |
| 🔧 本书几乎没有讲「错误恢复的系统设计」 | 只提到 `DefaultErrorStrategy`；建议补读 Grimm（PLDI 2011）与 Tree-sitter 的容错解析 |
| 🔧 本书对「IDE 支持」只一笔带过 | 现实里语法文件的产出物（highlight query、LSP 协议）本身就是一门工程；参 `book/设计模式GoF/08-模式在现代语言中的演化.md` 关于「语言吃掉模式」的讨论 |
| 「生成的代码不好调试」是天生如此 | 可以用 source map、模板内嵌行号、以及让生成物保留注释骨架；本书 13.8 的机器码案例也说明「生成物可读」是可实现的目标 |
| 「配置格式越宽松越好」 | 宽松 = 歧义 = 无法给出好诊断；13.4 的通用配置读取器正是反例：宽松语法会让后续所有分析失效 |
| 「语言应用写完了就交付」 | 真正的成本在 13.5/13.7 这类「改源码」与「格式化」：它们要求保留全部细节，往往要重做一遍树结构 |
