# 第 4 章 中间表示的建造（语法树）

> **一句话**：语法树不是「解析的副产品」，而是**下一阶段唯一的输入**——所以选它时你真正决定的是「哪些信息留、哪些丢、谁来持有父节点」；P.8–P.11 给出四种树形，从「什么都留」的 CST 到「只留需要」的不规则异构树。

## 核心精讲

### P.8 Parse Tree（CST）与 P.9/P.10/P.11 的形状（教学示意）

```text
// 输入：print(1 + 2);
// P.8 Parse Tree（CST，全部语法细节都在）
stat
 └─ print ( expr ) ;
     └─ BinOp
         ├─ INT 1
         └─ INT 2

// P.9 Homogeneous AST（节点类型高度统一）
BinOp(+, IntLit(1), IntLit(2))

// P.10 Normalized Heterogeneous AST（同类归组）
add
 ├─ number      → 1
 └─ number      → 2

// P.11 Irregular Heterogeneous AST（一规则一节点，且带父指针）
PrintStmt {
  expr: AddExpr { left: IntExpr{value:1}, right: IntExpr{value:2}, parent: <this> }
  parent: <this>
}
```

### 一棵带父指针的节点骨架（P.11 常用形态，教学示意）

```java
// 教学示意代码，不编译、不运行、不参与构建
class Node {                     // 教学用节点：visitor / 父指针 / 位置信息
  int type; String text; int line, charPosInLine;
  Node parent; List<Node> children = new ArrayList<>();
  void addChild(Node c) { c.parent = this; children.add(c); }
  <T> T dispatch(Visitor<T> v) {   // 双分派：节点决定调哪个 visit
    switch (type) {
      case ADD:  return v.visitAdd((AddNode) this);
      case PRINT:return v.visitPrint((PrintNode) this);
      default:   throw new UnsupportedOperationException();
    }
  }
}
```

### visitor 的用法（与 GoF 的差别就在 `dispatch` 这一行，教学示意）

```java
// 教学示意代码，不编译、不运行、不参与构建
interface Visitor<T> {
  T visitAdd(AddNode n);
  T visitPrint(PrintNode n);
}

class EvalVisitor implements Visitor<Integer> {
  public Integer visitAdd(AddNode n)  { return n.left.dispatch(this) + n.right.dispatch(this); }
  public Integer visitPrint(PrintNode n) { return n.expr.dispatch(this); }
}
```

### ANTLR 侧：让 grammar 直接产出树（教学示意）

```antlr
// 教学示意代码，不编译、不运行、不参与构建
grammar Calc;

@header { import java.util.*; }

expr returns [Object value]        // 返回值的语法动作式写法（ANTLR 3 风格）
      : e1=expr ADD e2=expr   { $value = ((Integer)$e1.value) + ((Integer)$e2.value); }
      | INT                   { $value = Integer.valueOf($INT.text); }
      ;

// 更现代的写法：带标签的替代项 + 语法动作（ANTLR 4 风格）
prog : ID '=' e=expr ';'    # assign
     | e=expr ';'           # exprStmt
     ;
```

### lark 侧：CST → 自定义 Transformer（教学示意）

```python
# 教学示意代码，不编译、不运行、不参与构建
from lark import Lark, Transformer, v_args

class AstBuilder(Transformer):
    @v_args(inline=True)   # 关掉自动 AST，手动构造
    def assign(self, name, value): return ("=", name, value)
    def number(self, tok): return ("num", int(tok))

p = Lark(r"""start: assign | number ; assign: NAME "=" INT ";" ; %import common.CNAME -> NAME %import common.INT %ignore WS""")
ast = AstBuilder().transform(p.parse("x = 42;"))   # 边遍历边建 P.9/P.10 形态的树
```

## 版本演进

| 阶段 | 形态 |
| --- | --- |
| 语法动作时代（ANTLR 1/2） | 直接在 grammar 里 `{$value = ...}`，不产树，边解析边算（syntax-directed translation） |
| ANTLR 3 | tree grammar + rewrite rules（`-> ^(AST ...)`）成为主流；StringTemplate 与树语法联动 |
| 2013（ANTLR 4） | 弃用 tree grammar，改用 `*_baseVisitor` / `*_baseListener`；把树构造时机从「语法动作」挪到「遍历阶段」 |
| 2015–2026 | 树的形态进一步分化：**IDE 需要保留全部细节的 CST**（Tree-sitter 的 tree 就是），**编译器需要极简 AST**（rustc 的 HIR/THIR、TS 的 checker AST 都是分层的）；「树的分层」成为共识 |

## 近年研究与工业界开源实践（2015–2026）

**趋势**：真正的工程里没人只用一棵树。**分层**（lexical AST → CST → typed AST → HIR → MIR/SSA）成了标准做法；本书的「一棵树走到底」是教学简化。

| 仓库 | star（2026-09-25 `gh api` 实测） | 说明 |
| --- | --- | --- |
| `tree-sitter/tree-sitter` | **27,043★** | 产出的树带 `NamedNode`、`byte/range`，就是 P.8 CST 的现代版本 |
| `apple/swift` | **70,401★** | 分层 AST：Syntax（CST）→ AST → SIL → LLVM IR，逐层丢信息 |
| `rust-lang/rust` | **119,150★** | AST → HIR（抹掉宏展开细节）→ MIR（显式控制流）→ LLVM IR |
| `antlr/antlr4` | **19,014★** | 默认 parse tree，可换 visitor/listener 构造 P.9–P.11 |
| `lark-parser/lark` | **5,991★** | `Transformer` 就是 P.13 外部 visitor 的 Python 形态 |
| `llvm/llvm-project` | **40,649★** | 单一 IR 路线的极致：树被彻底放弃，取而代之的线性 SSA |

## 常见误区与本书需修正之处

| 误区 / 需修正之处 | 说明 |
| --- | --- |
| 🔧 本书采用「一棵树走到底」，真实编译器几乎都分层 | 现代实现普遍是 Syntax/tree → typed AST → HIR → IR；建议直接读 `apple/swift` 或 `rust-lang/rust` 的分层设计 |
| 🔧 本书基于 ANTLR 3 的 `-> ^(AST ...)` 重写语法 | ANTLR 4 已改为 visitor/listener + 语法动作；重写示例请参照 `book/antlr4权威指南.md` |
| 🔧 中文版纪年较早，示例依赖 StringTemplate 与 tree grammar | StringTemplate 项目已几近停滞（见 `09-翻译与模板生成.md`）；新项目请用模板引擎的替代品或自增代码生成 |
| 「CST 太占内存，只用 AST」 | 对格式化工具、IDE、代码转换（codemod）来说，**CST 里那点「多余」的括号正是你要的信息** |
| 「异构 AST 一定最好」 | 每个规则一个节点类 = 每个规则一个 visitor 分支；改一次语法要同步改一堆类，维护成本随语法规模线性上涨 |
| 「树建好就锁死了」 | 本书之后的工具（重写、标注）都要往树上加信息；建议让节点预留 `scope`/`type` 字段而不是事后替换节点类型 |
