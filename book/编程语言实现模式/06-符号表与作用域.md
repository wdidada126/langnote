# 第 6–7 章 符号表、作用域与符号解析

> **一句话**：符号表不是一个 `HashMap`，而是**「按作用域组织的、需要按规则修整的、还要在解析时增量维护」的一套结构**——P.16–P.19 从单一作用域一路演进到类层次作用域，是全书最容易低估工作量的一块。

## 核心精讲

### 作用域栈的骨架（P.16/P.17，教学示意，不编译、不运行、不参与构建）

```java
// 教学示意代码，不编译、不运行、不参与构建
class Symbol {
  String name; Kind kind;          // VAR / FUNC / TYPE
  Type type; int line; Scope enclosing;
}

class Scope {                       // 一个作用域 = 一张符号表 + 一个父指针
  Map<String, Symbol> symbols = new LinkedHashMap<>();
  Scope parent;
  Symbol lookup(String name) {
    for (Scope s = this; s != null; s = s.parent) {   // 沿链上溯 = 最近嵌套规则
      Symbol r = s.symbols.get(name);
      if (r != null) return r;
    }
    return null;                                       // 未声明
  }
  void define(Symbol s) {
    Symbol prev = lookupHere(s.name);
    if (prev != null) throw new SemanticError(s.name + " already defined at line " + prev.line);
    symbols.put(s.name, s);
  }
}
```

### visitor 里维护作用域栈（P.17 的典型用法，教学示意）

```java
// 教学示意代码，不编译、不运行、不参与构建
class ScopeBuilder extends CalcBaseVisitor<Void> {
  Deque<Scope> stack = new ArrayDeque<>();
  Scope current() { return stack.peek(); }

  @Override public Void visitBlock(BlockContext ctx) {   // 进入 block 压栈、离开弹栈
    stack.push(new Scope(current()));
    for (StatContext s : ctx.stat()) visit(s);
    stack.pop();
    return null;
  }
  @Override public Void visitVarDecl(VarDeclContext ctx) {   // 声明时入表
    current().define(new Symbol(ctx.ID().getText(), Kind.VAR, ctx.type()));
    return visitChildren(ctx);
  }
  @Override public Void visitVarRef(VarRefContext ctx) {     // 引用时解析
    Symbol sym = current().lookup(ctx.ID().getText());
    if (sym == null) throw new SemanticError("undefined: " + ctx.ID().getText());
    return null;
  }
}
```

### 类作用域（P.19，教学示意）

```java
// 教学示意代码，不编译、不运行、不参与构建
class ClassScope extends Scope {
  ClassSymbol owner;                        // 这是「类作用域」的关键差别
  boolean isVisible(Symbol s, boolean fromThisClass) {
    switch (s.visibility) {                 // 可见性检查也是作用域的一部分
      case PUBLIC:  return true;
      case PRIVATE: return fromThisClass && s.enclosing == this;
      case PROTECTED: return fromThisClass || s.enclosing instanceof ClassScope;
    }
    return false;
  }
}
```

### 现代语言实现的对照（TypeScript 风格，教学示意）

```typescript
// 教学示意代码，不编译、不运行、不参与构建
type Scope = {
  parent: Scope | null
  bindings: Map<string, Symbol>
  resolve(name: string, allowForwardReference = false): Symbol | undefined
};
// 关键点：resolve 需要 allowForwardReference —— 函数声明可前置引用，
// 局部变量不可；这一条规则决定了「声明前扫一遍」的预扫阶段是否存在。
```

### Python / lark 侧的最小符号解析（教学示意）

```python
# 教学示意代码，不编译、不运行、不参与构建
class ScopeResolver:
    def __init__(self): self.stack = [{}]
    def current(self): return self.stack[-1]
    def visit_Block(self, node):                 # 手写遍历，而非生成 visitor
        self.stack.append({}); self.visit_children(node); self.stack.pop()
    def visit_Name(self, node):
        if node.ctx == "Store": self.current()[node.id] = node
        elif node.id not in self._lookup(node.id): raise SemanticError(f"{node.id} not defined")
```

## 版本演进

| 阶段 | 形态 |
| --- | --- |
| 1970s | 符号表 = 一张扁平表 + 偏移分配；Pascal 的嵌套作用域让「栈式符号表」成为标准 |
| 属性文法时代 | 符号信息直接随语法动作填入表（本书 Ch6 的写法） |
| ANTLR 3/4 | 作用域构建从语法动作移入 visitor（`pushScope/popScope`）；AST 节点挂 `scope`/`decl` 字段 |
| 2015–2026 | 「符号解析」变成独立编译器 pass（Go: types2；Rust: 名字解析 pass；TS: binder）；并且要支持**增量重解析、跨文件、IDE 的 go-to-definition** |

## 常见误区与本书需修正之处

| 误区 / 需修正之处 | 说明 |
| --- | --- |
| 🔧 本书把符号表构建放在语法动作 / 简单 visitor 里 | 现代实现把「名字解析」做成**独立的 pass**，并支持跨文件；建议照 `rust-analyzer/rust-analyzer` 的 pass 划分来组织 |
| 🔧 中译本出版较早，中文语境下常见「符号」译法混乱（symbols 有时译「符号」有时译「标记」） | 建议统一：symbol = 符号，token = 词法单元，mark = 标记 |
| 🔧 「Symbol Table 只是一个 Map」 | 真实实现还要处理：前向引用、遮蔽（shadowing）、重复定义诊断、可见性、成员布局、IDE 的位置映射 |
| 「函数可以随便互相调用」 | 支持前向引用意味着要多一遍预扫；不支持则要求「先声明后使用」。这是语言设计决定，不是实现细节 |
| 「类作用域和块作用域一样」 | 类作用域要额外处理继承链查找、可见性、初始化顺序、以及 `this` 的隐式绑定 |
| 「符号表建完就不用了」 | 优化阶段（内联、去虚拟化）持续向符号表写入约束；见 `book/LLVM编译器原理与实践.md` 的 pass 交互 |
