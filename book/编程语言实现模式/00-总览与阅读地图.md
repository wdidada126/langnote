# 《编程语言实现模式》总览与阅读地图

> **一句话**：这本书不讲编译原理理论，而是把「一切处理语言应用的程序」（配置读取器、源码分析器、翻译器、代码生成器、解释器）拆成 **31 个可复用模式 P.1–P.31**，每个模式给出数据结构、算法与策略，示例代码用 Java。
> *原书*：*Language Implementation Patterns: Create Your Own Domain-Specific and General Programming Languages*，Terence Parr，Pragmatic Bookshelf，**2009-12 首印**（P1.0 printing，Dec 2009；排版版本 2010-01-13），正文 **xix + 374 页**，附 bibliography（p.370）与 index（p.372）。ISBN-13 **978-1-934356-45-6**，ISBN-10 **1-934356-45-X**。
> *中译本*：Terence Parr 著，李袁奎 译，尧飘海 审校，**华中科技大学出版社 2012-03**，ISBN **9787560977003**，374 页（部分渠道标 388 页，以书脊为准），定价 72 元。

**大纲版单文件在此**：`book/编程语言实现模式.md`（含豆瓣链接与 2020–2026 的跨年摘录）。**本目录是深度重写版**，两者并存、互链；大纲版不删不改，本目录承担全部深度笔记内容。

## 3. 阅读路线建议

## 4. 版本演进时间轴（ANTLR 1 → 4 → 2020 年代的解析器生态）

| 年份 | 事件 |
| --- | --- |
| 1989 | Purdue 的 **PCCTS**（Purdue Compiler Construction Tool Set）立项，ANTLR 的直接前身 |
| **1992** | **ANTLR 1** 随 PCCTS 1.00 发布（1992-04-10）：基于 **LL(k)**，靠手写 syntactic predicate（语法谓词）做任意前看 |
| **1998** | **ANTLR 2**：Parr & Quong 发表 *ANTLR: A Predicated-LL(k) Parser Generator*（SIGPLAN Notices 33(4)，PLDI 1998），谓词式 LL(k) 成型 |
| **2006–2007** | **ANTLR 3**：把 LL(k) 的静态 DFA 构造做到自动生成；引入 tree parser、StringTemplate 深度耦合；目标是「生成可读的递归下降代码」 |
| **2009-12** | **本书出版**（基于 ANTLR 3 与 StringTemplate 的世界观） |
| **2013-01** | **ANTLR 4.0** 发布（与 *The Definitive ANTLR 4 Reference* 同期）：核心变化是 **ALL(\*)**——自适应 LL(\*)，用 adaptivePredict() 在运行时按需扩展前看，并支持**直接左递归** |
| 2014–2017 | ANTLR 4 稳住局面：错误恢复改进、多目标运行时（C#、Python、Go、Swift 等）、`CommonTokenStream` / `TokenStream` 抽象成为标配 |
| 2020 | **ANTLR 4.9**：R / Go / Python3 / C# 等运行时补上 **typed bridge**（带类型的强类型 API 版运行时） |
| 2021 | **ANTLR 4.12.0** 新增 **TypeScript** 运行时目标（官方仓库运行时目录因此重排） |
| 2024-08 | **ANTLR 4.13.2** 为目前最新的稳定版（BSD-3-Clause，工具仍是 Java 写的） |
| 2015–2018 | **Tree-sitter** 崛起（2015 年项目起步，2018 年论文发表于 ICSE）：**增量解析 + enyel 错误容忍 + 语义树，为 IDE 而生**，直接吃掉了 ANTLR 在编辑器插件场景的份额 |
| 2004（回看） | Ford 的 **PEG** 论文定义了「有序选择、无歧义」的解析表达式文法，催生 `lark`、`peg`、Rust 的 `nom`/`combine` |
| 2015–2026 | **Rust 生态**：`nom`（字节/parser 组合子）、`combine`、`peg`、`chumsky`（2019+）、`tree-sitter` 绑定；Rust 自己的 `syn`（读 compiler 侧 AST） |
| 2018–2026 | **TypeScript 侧**：ANTLR 的 TS 运行时补位、`chevrotain`（2017+）成为「可调试的手写式 LL(k) 生成器」代表 |
| 2022–2026 | **LLM 时代**：大模型让「生成一门 DSL 并立刻可用」的成本骤降，语法文件（.g4 / grammar.js）反而成了**人类与模型共享的机器可读契约**；「语言即 DSL / 配置即语言」重新获得关注，但**诊断质量、IDE 体验、歧义消解**这些本书关心的主题依然没变 |

> 一句话概括这条时间轴：**ANTLR 解决了「怎么写语法」，Tree-sitter 解决了「怎么让语法在编辑器里毫秒级可用」，而 2022 年之后大模型改变了「为什么需要一门 DSL」的论证方式**。

## 5. 本书刻意规避 / 未覆盖的缺口

| 缺口 | 说明 | 补到哪里 |
| --- | --- | --- |
| **类型系统与类型检查器细节** | Ch8 只有 P.20–P.23 四个模式，属于「够用的玩具类型系统」；没有 subtyping、没有多态推断的完整算法（Hindley-Milner 只一笔带过），没有 generics 的 erasure / substitution 细节 | 本仓库中无系统的类型系统专篇，建议配合 *Types and Programming Languages*（TAPL）与 `book/现代编译原理-虎书.md` |
| **IR 与优化编译器后端** | 本书的 P.26–P.28 只做到「字节码汇编器 + 栈式/寄存器式 VM」；**没有 SSA、没有 IR、没有寄存器分配、没有指令选择** | `book/LLVM编译器原理与实践.md`、`book/深入理解LLVM.md`、`book/高级编译器设计与实现.md`、`book/自己动手写编译器链接器.md` |
| **并发 / 并行语义的实现** | 语言实现器本身的并发没讲；本书产出的解释器/VM 是单线程玩具 | `book/C++并发编程实战2/`、`book/多处理器编程的艺术2/` |
| **形式化语义** | 不讨论 operational / denotational / axiomatic semantics | `book/计算的本质.md` |
| **错误恢复的系统性方法** | 只在解析章节顺带讲 `DefaultErrorStrategy`；没有对错误恢复做独立、系统的讨论 | 见 `10-工程实践与综合案例.md` 的横切小节 |
| **StringTemplate 已趋于停滞** | Ch12 的技术骨架基于 StringTemplate 4，该引擎已进入维护状态 | 见 `09-翻译与模板生成.md` 与 `07-类型规则与静态检查.md` 的「常见误区」小节 |
| **通用主体语言为 Java** | 所有示例用 Java 表述，ANTLR 目标语言也是 Java 生态 | 见各章「跨语言对照」 |
