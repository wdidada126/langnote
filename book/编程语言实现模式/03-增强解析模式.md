# 第 3 章 增强解析模式（回溯、记忆与语义谓词）

> **一句话**：当 LL(1) 的前看不够用时，你有三条出路——**退回去重试**（P.5 回溯）、**记住结果别再算**（P.6 Memoizing）、**用语义信息直接指路**（P.7 谓词）；三条路各自有明确代价，选错就是「语法能跑但慢到不能上线」。

---

## 本章地图

| 节 / 模式 | 内容 | 结论 |
| --- | --- | --- |
| 3.1 Parsing with Arbitrary Lookahead | 为什么需要任意前看；语法本身可以改写以避免它 | 「加前看」是最后手段，「改语法」是首选手段 |
| 3.2 Parsing like a Pack Rat | Packrat parsing：记忆化递归下降 | O(n) 时间、O(n) 空间，代价是内存与「动作时机」 |
| 3.3 Directing the Parse with Semantic Information | 用语义谓词把决策权交给已有信息 | 谓词不是万能药：它让语法不再是纯语法 |
| P.5 Backtracking Parser | 一路试错、失败则回退 | 写起来最省事、跑起来最贵；适合小输入 |
| P.6 Memoizing Parser | 缓存 `(规则, 位置) → 结果` | 把指数时间压成线性；代价是无法在回溯中做副作用 |
| P.7 Predicated Parser | `{条件}?` 语义谓词控制选项可用性 | 表达力强、可调试；但语义与语法纠缠，工具链会猜错 |

## 核心精讲

### 歧义语法的三种写法对照（教学示意，不编译、不运行、不参与构建）

```antlr
// 一个经典的歧义：statement 从哪个分支开始，取决于后面有没有 '('
stmt : ID '(' ')' ';'          # 过程调用
     | ID '(' expr ')' ';'     # 带参数的调用
     | ID '=' INT ';'          # 赋值
     ;
// 注意：当输入是 "f(x);" 时，ANTLR 需要前看 2 个 token 才能决定；
// 手写 LL(1) 解析器在这里就必须改写语法，例如：
stmt : ID ( '(' args ')' | '=' expr ) ';' ;   // 把公共前缀 ID 提出来
```

### P.5 回溯解析器的骨架（教学示意）

```java
// 教学示意代码，不编译、不运行、不参与构建
class BacktrackingParser {
  String input; int pos;
  boolean memoFail;              // 失败也要记，避免重复试错

  boolean parseStmt(int pos) {   // 注意：返回「成不成功」而不是「结果」
    int save = this.pos;
    if (tryCall(pos))    { this.pos = pos; return true; }
    if (tryAssign(pos))  { this.pos = pos; return true; }
    this.pos = save; return false;
  }
  boolean tryCall(int at) { pos = at; if (!match(ID)) return false; if (!match(LPAREN)) return false; return match(RPAREN); }
  boolean tryAssign(int at) { pos = at; if (!match(ID)) return false; return match(EQ) && match(INT); }
}
```

> P.5 的**结构性代价**：每个动作都可能被执行多次。所以**不能在回溯解析里写有副作用的动作代码**（建符号表、报错误必须先做一遍）。这是本书后面几章反复强调的纪律。

### P.6 Memoizing（Packrat）骨架（教学示意）

```java
// 教学示意代码，不编译、不运行、不参与构建
class PackratParser {
  Map<Long, Object> memo = new HashMap<>();   // key = (ruleIndex << 32) | position
  Object rule_call(int ruleIdx, int pos) {
    Long key = ((long) ruleIdx << 32) | pos;
    if (memo.containsKey(key)) return memo.get(key);
    push(pos); Object r = callRule(ruleIdx); pop();
    memo.put(key, r); return r;               // 结果（或 FAIL）都缓存
  }
}
```

### P.7 语义谓词（教学示意）

```antlr
// 教学示意代码，不编译、不运行、不参与构建
grammar Attr;

// 只有在符号表显示该 ID 是变量时才走这个分支
stat : ID '(' ')' ';'   {isVar(currentScope, $ID.text)}? ;
// 语法谓词（ANTLR 3 式，ANTLR 4 里要小心使用）：先试探能否匹配
syn : {hasSyntacticContext()}? . ;
```

```java
// 教学示意代码，不编译、不运行、不参与构建
boolean isVar(Scope scope, String name) {
  return scope.lookup(name) instanceof VariableSymbol;   // 谓词里查符号表
}
```

### PEG / lark 侧的对照（教学示意）

```python
# 教学示意代码，不编译、不运行、不参与构建
# PEG 的「有序选择」天然等价于本书的「回溯 + 优先级」，但要求无歧义
from lark import Lark
g = Lark(r"""
    start: statement+
    statement: call | assign
    call: NAME "(" ")" ";"
    assign: NAME "=" INT ";"
    %import common.CNAME -> NAME
    %import common.INT
""")
# Earley 解析器还能处理「左递归」，但仍坚持「第一个成功的选项胜出」的 PEG 语义
```

## 版本演进

| 阶段 | 形态 |
| --- | --- |
| 1998（ANTLR 2） | syntactic predicate `{...}?`（语法谓词）与语义谓词一起登场：用**动作代码**做前看 |
| 2002 | Ford 提出 PEG 与 **Packrat parsing**，把「记忆化 + 有序选择」标准化 |
| 2006（ANTLR 3） | 谓词成为一等语法元素；同时引入 llk() 参数允许手动指定前看 |
| 2013（ANTLR 4） | **ALL(\*)**：生成器自己决定前看多长，谓词从「必需的驱动手段」退化为「逃生舱」 |
| 2008 | Warth 等人证明 **Packrat 解析器可以支持左递归**（在 PEG/Allen 框架下改写规则），但代价是语法不再是上下文无关文法 |
| 2015–2026 | 工业界多数用 **Earley（lark/Earley parser）或增量 LR（Tree-sitter）** 取代纯 Packrat；Packrat 的记忆化思想被吸收进各类组合子库 |

## 常见误区与本书需修正之处

| 误区 / 需修正之处 | 说明 |
| --- | --- |
| 🔧 「回溯解析器写起来快，先用着」 | 回溯是 O(指数) 的；一旦输入从 10 行涨到 1000 行就会挂。要么加记忆化（P.6），要么**改写语法** |
| 🔧 「语义谓词能解决一切」 | 谓词里读外部可变状态（符号表、全局变量）会让语法失去可分析性：编辑器无法静态补全、无法增量重解析、无法给语法写测试。ANTLR 官方也建议优先靠语法消歧 |
| 🔧 本书的谓词写法是 ANTLR 3 时代的 `{...}?` | ANTLR 4 仍支持 semantic predicate，但推荐用带标签的替代项 + 重写规则替代；示例请以 `book/antlr4权威指南.md` 为准 |
| 「Packrat 就是缓存」 | Packrat 的代价是**每次调用都建一棵子树**，内存占用与输入长度同阶；在大文件上要先测 |
| 「PEG 比 CFG 更强大」 | 恰恰相反：PEG 是**更弱**的 formalism（不能表达真正的歧义、不能表达上下文相关的某些构造），换来的是「无歧义 + 实现简单」 |
| 「谓词里查符号表是标准做法」 | 这是本书的权宜之计；现代语言前端普遍改用「两遍：先建作用域，再解析」或先产生产物再标注的做法 |
