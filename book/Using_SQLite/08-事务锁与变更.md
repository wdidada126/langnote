## 1. 锁协议：不是表锁行锁，是"文件状态机"

rollback journal 模式下的五级阶梯（[lockingv3.html](https://sqlite.org/lockingv3.html) ✅）：
`UNLOCKED → SHARED → RESERVED → PENDING → EXCLUSIVE`

- 读者拿 SHARED（多读者并存）；写者先 RESERVED（全库仅**一个**写者可以进）；
- 提交时升 PENDING（挡住新读者）→ EXCLUSIVE（等旧读者散尽）→ 回写 journal → 降回；
- `BEGIN DEFERRED`（默认，惰性升锁）/`IMMEDIATE`（开局就 RESERVED）/
  `EXCLUSIVE`（开局就 EXCLUSIVE）三档控制升锁时机——**写事务先 IMMEDIATE 可避免
  "读→写升级死锁"**（书中金句，🔧 实验 B 复现）。

busy handler：锁冲突返回 SQLITE_BUSY，应用可选 立即失败/`sqlite3_busy_timeout`
指数重试/自定义回调（04/05 章已实测 timeout 行为：等 1.10 s 至写者提交）。

## 2. journal 模式族（书中原表 + 2026 复核）

| 模式 | 机制 | 要点 |
| --- | --- | --- |
| DELETE（默认） | 每页复制进 `db-journal`，提交即删 | 崩溃恢复=重放/删除热日志 |
| TRUNCATE / PERSIST | 日志截零 / 保留文件头复用 | 减少 create/unlink 抖动 |
| MEMORY | 日志在内存 | 崩溃即弃——**不保证回滚持久** |
| WAL | 改动追加 `db-wal`，主文件延迟合并 | 读写互不阻塞（下表实测） |

WAL 关键条款（[wal.html](https://sqlite.org/wal.html) ✅ 口径）：一写多读仍然成立；
读者看快照（MVCC 式）；自动 checkpoint 默认 1000 页（🔧 compile_options
`DEFAULT_WAL_AUTOCHECKPOINT=1000` 亲验）；**-shm/-wal 使"单文件"承诺失效**（01 章实验 C）；
不支持网络文件系统上的库（NFS 锁语义不足）。

🔧 WAL 并发与体积实测（本会话）：
- 写事务进行中：DELETE 模式下读者（timeout=50ms）报 `database is locked`（耗时 0.306 s），
  WAL 模式读者 0.001 s 读到旧快照——**读写不互斥**的直接证据；
- 提交吞吐：200 个单行事务，DELETE 359.6 txn/s vs WAL 1577.5 txn/s（**4.4×**，
  WAL 摊薄了每事务 fsync）；
- 5000 行提交后：`-wal` 61,832 B、`-shm` 32,768 B；
  `PRAGMA wal_checkpoint(TRUNCATE)` → `(0,0,0)`，-wal 归 0 B（🔧 动作式 pragma 亲验）。

## 3. savepoint：嵌套事务与"部分回滚"

SQLite 的 savepoint 比别家多了两个超能力（[lang_savepoint.html](https://sqlite.org/lang_savepoint.html) ✅）：
**可在 autocommit 下独立使用**（等效事务）、**ROLLBACK TO 不弹出栈**（可重试）。

🔧 实测嵌套语义：

```
BEGIN; INSERT 1; SAVEPOINT outer; INSERT 2;
SAVEPOINT inner; INSERT 3; ROLLBACK TO inner; RELEASE inner;
ROLLBACK TO outer; RELEASE outer; COMMIT;
→ 表内容: [(1,)]
```

inner 回滚只丢 3；outer 回滚丢 2（含已 RELEASE 的 inner 段）；1 存活。
`RELEASE` = 合并出栈而非"提交"——这条栈语义书中讲透，2026 依旧是最常被误解的点。
autocommit 下 `SAVEPOINT s1; INSERT; RELEASE s1` 等效一个隐式事务（🔧 rows=1 亲验）——
ORM/迁移器"无脑包 savepoint"策略的合法性来源。

## 4. Changes：DML 之后的三个数

- `sqlite3_changes()`：最近一条 DML 的行数（🔧 CLI/Python 均见 04/05 章）；
- `last_insert_rowid()`：最近插入的 rowid（3.19.0 起对"非 rowid 别名"列不再更新——
  ⚠️ 细节引官方 c3ref 页叙事，未专项实测）；
- `total_changes`：连接累计（🔧 2 次 INSERT 后从 1→3 亲验）。
RETURNING（3.35.0 ✅ lang_returning.html）把"三步取数"折成一步（🔧 实验见下节第 6 点与 10 章）。

## 5. 在线备份：`sqlite3_backup_*` 与"热拷不等于备份"

[backup.html](https://sqlite.org/backup.html) ✅：备份 API 逐页拷 + 允许源库持续写；
CLI `.backup`、Python `Connection.backup()` 都是它的马甲。
书中警句（"直接 cp 正在写的库文件是自杀"）由 DBRE 笔记实验化：
[../Database_Reliability_Engineering/07-数据作为生产资料与备份恢复.md](../Database_Reliability_Engineering/07-数据作为生产资料与备份恢复.md)
🔧 演示了热拷贝拿到撕裂页的构造；本章从正面补数据。

🔧 在线备份实测：9.2 MB 源库（3 万行），`src.backup(dst, pages=1000, progress=cb)` →
**0.05 s** 完成，progress 回调 3 次（9.2 MB ÷ 4096 B ≈ 2,250 页 ÷ 1000 页/步 = 3 步），
目标文件 9,236,480 B 字节级完整。CLI 端 `.backup` 同样 5.7 MB 一次成功（03 章）。

## 6. 🔧 复合实验：UPSERT + RETURNING（现代事务姿势）

`INSERT INTO kv VALUES('a',1) ON CONFLICT(k) DO UPDATE SET v=v+1 RETURNING k,v`
→ `('a', 2)`（Python 3.45.3 一次往返拿到冲突后的新值，🔧 亲验）。
3.8 时代要两条语句 + 事务包裹（书中"先 UPDATE 判断 changes() 再 INSERT"的仪式）
如今一条 DML 终结——第 4 节"Changes 三数"的现代用法因此降半级。

## 7. 与 InnoDB 对读（系列视角）

| 维度 | SQLite（rollback/WAL） | InnoDB |
| --- | --- | --- |
| 锁粒度 | 文件级状态机（全库一写者） | 行级锁 + gap |
| 读写冲突 | DELETE 模式读写互斥于提交窗口；WAL 读写不互斥 | MVCC 永不互斥 |
| 回滚介质 | journal（页镜像）/ WAL 帧 | undo log |
| 并发上限来源 | 单写者 + fsync 位置 | 锁冲突 + redo 组提交 |

对读入口：[../Understanding_MySQL_Internals/08-并发访问与锁定.md](../Understanding_MySQL_Internals/08-并发访问与锁定.md)、
[../Understanding_MySQL_Internals/11-事务.md](../Understanding_MySQL_Internals/11-事务.md)。
一句话总结：**SQLite 用"限制并发"换来"消灭协调开销"**——单机写者不超载时它反而是
延迟最低的 ACID 方案（🔧 WAL 单事务提交毫秒级）。

## 核心概念速览（中英对照）

- **三种 BEGIN** — DEFERRED/IMMEDIATE/EXCLUSIVE：升锁时机三策略
- **五级锁** — SHARED/RESERVED/PENDING/EXCLUSIVE/UNLOCKED：文件锁状态机
- **SQLITE_BUSY** — busy：写者位被占/升级受阻的可重试信号
- **热日志** — hot journal：崩溃残留的 journal，下次打开自动回滚的依据
- **journal_mode** — 日志模式：DELETE/TRUNCATE/PERSIST/MEMORY/WAL 五族
- **WAL 索引** — wal-index（-shm）：WAL 帧可见性的共享内存索引
- **检查点** — checkpoint：把 WAL 帧回灌主库的动作；TRUNCATE/PASSIVE/FULL 三档
- **savepoint 栈** — savepoint stack：命名嵌套回滚点，ROLLBACK TO 不弹栈
- **RELEASE** — 释放保存点：合并到父层而非提交
- **changes()** — 影响行数 / **total_changes()** 连接累计 / **last_insert_rowid()**
- **备份 API** — sqlite3_backup_init/step/finish：页粒度、允许并发写的在线拷贝
- **RETURNING** — 3.35+：DML 直接产出受影响行
