# 05 · 空间索引（Spatial Indexing）

> 原书 Chapter 5 "Spatial Indexing"，pp.177–196（✅ Crossref，DOI …_5）。20 页短章：
> geography/geometry 两类型之上的四叉树式索引世界。⚠️ 叙事重构，✅ 口径锚 Learn。

## 本章主线

空间查询的谓词（`STIntersects/STDistance/STContains`）无法被 B+ 树线性化——一维有序
对二维对象无意义。SQL Server 用**两级网格 + 四叉树**把平面离散化为可索引的单元序列；
本章讲格网选型（cells-per-object / bounding box）与"空间索引只到粗过滤"的认知框架。⚠️

## 5.1 两类型与坐标系 ⚠️ 转述 + ✅ 概念

- geometry（平面）与 geography（椭球面，米制）方法集部分同名，距离/面积语义随类型分叉；
  选型错误 = 索引建了、答案算错。✅ 官方总览：
  https://learn.microsoft.com/en-us/sql/relational-databases/spatial/spatial-indexes-overview
- 空间列必须先有表级 CHECK/非空约束等前置（版本口径 ⚠️），再建 SPATIAL 索引，
  之后才能谈格网参数。

## 5.2 格网 tessellation：四叉树 + 单元格编码 ⚠️/✅

- 两级格网（high/medium/low 密度组合）+ 对象包围盒（automated grid 或
  cells-per-object 1–8192，默认 8192 ⚠️ 以 URL 内文档为准）：对象被切成重叠/非重叠
  单元集合，索引键=单元编码。
- 经验法则（原书立场的 ⚠️ 重构）：**对象尺寸离散度**决定格网密度——大小对象混存时，
  统一格网必顾此失彼；对策是**按对象尺度拆表/拆索引**（如点状 vs 面状分离），把
  "一个索引服务一种密度"作为设计目标。
- 大对象退化：切分单元数触发对象级索引粒度变粗（tessellation 溢出为水平条带等退化形态）
  ⚠️ 转述，✅ 概念见上 URL。

## 5.3 粗过滤/精过滤两段式 ⚠️/✅

- 空间索引只完成 MBR 粗过滤（bounding box 相交），`ST*` 精确谓词在精过滤阶段逐行复核
  ——计划里"索引 seek + 过滤谓词残留"是**常态而非缺陷**，勿据此误判索引失效（对位
  第 14 章计划判读）。✅ 文档明确两级处理语义。
- 推论：高重叠数据集上空间索引的"选择性红利"有限；STDistance 半径查询受格网+精过滤
  双重成本支配。⚠️

## 5.4 维护与可用性 ⚠️ 转述

- 空间索引不支持 ONLINE 重建（版本口径 ⚠️ 转述，以 Learn 页面为准）、体积随对象复杂度
  膨胀（多边形顶点数=切碎成本）；批量装载同样适用"先装载后建索引"。
- 与 XML 章同款监控盲区：常规 DMV 对空间索引使用效果的呈现有限，须以查询级 IO/时间
  对比验证。⚠️

## 5.5 🔧 类比说明（诚实登记：格网语义不强行类比）

- SQLite 侧只有可选 R*Tree 虚拟表模块，本波 python 3.45.3 内核是否编译 R*Tree 未验证，
  且其结构（R-tree）与 SQL Server 四叉树格网**不同谱系**——强行类比会传递错误结构认知，
  故本册空间章**不造 🔧 实验**，记 ⚠️ 不可类比（波纪律允许"不能类比如实登记"）。
- 可迁移的一般性结论仅需纸面推演：一维 B+ 树对 (x,y) 区间查询的失效演示，在第 11 章

## 5.8 判读 FAQ

- **Q：空间列能同时有普通 B+ 树索引吗？**
  A：不能。空间索引与普通二级索引互斥于同列；围绕空间列的标量列（区域码/时间戳）照常可索引，混合谓词靠它们先裁。
- **Q：为什么建了空间索引还全表扫？**
  A：谓词形态不支持粗过滤（如函数嵌套过深）或选择性太差；先看计划是否出现空间索引查找算子。
- **Q：格网参数能在线改吗？**
  A：改参数=重建索引，而空间索引重建受限（§5.4）——调参演练应在等价小副本上做。
- **Q：点数据和面数据同表对吗？**
  A：混合是大忌
- **Q：STDistance 带半径最优解是什么？**
  A：半径谓词写成中心圆 buffer 相交（吃粗过滤）再精过滤距离，而非逐行 STDistance——两段式的 SQL 表达。
- **Q：geography 能存超出 180 度的多边形吗？**
  A：边界经线问题
- **Q：空间索引体积为什么远超预期？**
  A：顶点数驱动切碎数；简化几何（Reduce/重采样）常比调格网更省。
- **Q：和 PostGIS 的 R-tree 谁更好？**
  A：范式同、结构异：两者都是“索引出候选+精判”；差异在生态（投影/算子完备度），选型按平台而非结构。
- **Q：本章能 🔧 吗？**
  A：不能

空间索引的度量语言是“候选集缩小率”而非“碎片率”；用错仪表是本章最常见的自伤。

## 核心概念速览（中英对照）

1. **geometry/geography** — 平面/椭球面两空间类型：同名方法、不同度量语义。
2. **MBR** — minimum bounding rectangle：最小包围盒，粗过滤的比较对象。
3. **格网化** — tessellation：把对象切分为网格单元集合的索引预处理。
4. **两级格网** — two-level grid：高层四叉树+低层细分密度的组合编码。
5. **cells per object** — 对象单元数（默认上限 8192 ⚠️）：控制切碎粒度的核心旋钮。
6. **包围盒模式** — bounding box（BOT/BLT/BMB 等 ⚠️ 缩写口径）：以对象外接框定义格网范围。
7. **粗过滤** — primary filter：索引完成的 MBR 相交候选生成，不保证精确。
8. **精过滤** — secondary filter：对候选逐行执行真实 ST* 谓词。
9. **对象退化** — object degradation：超复杂/超大对象的格网溢出与索引增益衰减 ⚠️。
10. **按密度拆表** — density-aligned partitioning：点/小面/大面分离，每索引服务单一尺度。
11. **ONLINE 限制** — rebuild restriction：空间索引重建的联机能力弱于常规索引 ⚠️/✅。
12. **ST* 方法族** — STIntersects/STDistance/STContains：谓词形态决定索引收益上限。
