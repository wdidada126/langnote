# 08 · 索引神话与最佳实践（Indexing Myths and Best Practices）

## 本章主线

神话的共同结构：**把"某场景下成立的局部经验"升格为"无条件规则"**。本章逐条拆解并给出
各神话背后的真实变量（选择性、键宽、写模式、统计状态）——每条辟谣都是前 7 章知识
的组合应用。⚠️

## 8.1 逐条清表 ⚠️ 重构（每条=神话/真相/依据章）

1. **"索引越多读越快"** → 每个非聚簇索引都在每次写路径上收税（S8 实测写放大见 §8.3）；
   依据：ch1/ch2。
2. **"每列都该建单列索引"** → 单列索引栈在组合谓词前诱发 index intersection/回表风暴；
   复合键按谓词形态设计。依据：ch2/ch11 + S3。
3. **"覆盖索引总是更好"** → 肥叶子的存储/维护成本转嫁给全部写路径与缓存命中；
   低频查询配高成本覆盖=亏本。依据：ch2 §2.4 + dbstat 页数比 🔧。
4. **"碎片必须每天整理"** → 碎片伤害读的路径局部性，但小表/低读表的整理收益盖不过
   重建 I/O；维护应由证据驱动。依据：ch9/ch13。
5. **"GUID 主键必须加 NEWSEQUENTIALID 就万事大吉"** → 换生成器不换分布问题：非单调
   聚簇键的热页与树分裂模式要看**插入时键的时序局部性**。依据：ch1/ch2。
6. **"提示（hint）能救坏计划"** → 提示冻结计划于静态假设，统计漂移后成事故放大器；
   先修统计/参数化，提示是最后手段（第 12 章承接）。✅
   https://learn.microsoft.com/en-us/sql/t-sql/queries/hints-transact-sql-query
7. **"缺失索引 DMV 说建就建"** → DMV 是"愿望清单"（假设完美索引、不计组合代价）；
   裁决必须过使用率与体积两关。依据：ch13。
8. **"SQL Server 升级自动更快"** → 新基数估算也可能翻转旧计划；升级=回归测试工程。
   依据：ch15 方法论。⚠️

## 8.2 最佳实践的"条件化重写" ⚠️

把常见最佳实践的祈使句改写为"当 X 时做 Y，观测 Z 决定撤销"：
- 当查询以等值+返回窄行命中低频表 → 复合键前缀=等值列序，INCLUDE=常需列，观测回表数；
- 当写多读少 → 索引数量本身是性能变量，观测每索引的写税；
- 当选择性差（命中>20-30% ⚠️ 经验带宽）→ 覆盖的意义从"消灭回表"变成"减少扫描列"，
  可能不如接受堆扫（S3 中 `status='C'` 走不了 ix_cov 前缀 seek 的同构证据）。

## 8.3 🔧 本机类比：写税计时（非本书引擎行为）

环境：python sqlite3 3.45.3，orders 已挂 PK+4 二级索引（含 3 列覆盖索引与 1 个部分索引）：

```
INSERT 20,000 行（含全部索引维护）：0.127s（同一事务批量，WAL 内）
REINDEX ix_cov（重建 1128 页覆盖索引）：0.234s
```

- 读数：一次索引重建的成本 ≈ 单次 2 万行插入的 1.8 倍——"重建索引=大操作"的量级直觉；
  写税本身未做无索引对照组计时（如实登记，不虚构对比数字）。
- 迁移到 SQL Server：量级/函数形状不同（日志、页结构、锁模型），**只取"重建与插入同量级
  可观"这一个定性结论**。⚠️

## 8.7 判读 FAQ

- **Q：破除神话会不会滑向“什么都不用做”？**
  A：不会——辟谣的落点是“换成条件式”，条件仍需数据支撑；空对空反经验同样是迷信。
- **Q：有没有仍然成立的老规矩？**
  A：少数几条：外键列要有索引、取证窗跨重启、删索引先看依赖——它们的共同点是可证伪。⚠️
- **Q：社区工具评分卡算新神话吗？**
  A：若把分数当判决就是；当线索进 §13.4 流程则不是——工具结论与执行之间的流程厚度即神话防线。
- **Q：领导要求“按手册把索引建满”怎么办？**
  A：用 §2.7 式页数/写税账本把讨论翻译成容量语言，给试点窗口与回滚点——神话战争靠证据速胜。
- **Q：我的经验明明有效，为何被列神话？**
  A：神话化的不是经验而是“无条件”；8.2 的重写法给每条经验保留了它成立的前件。
- **Q：阈值 10%/30% 彻底不能用？**
  A：可作为默认起点，不可作为理由——“为什么这张表是 30%”答不出时阈值已成咒语。
- **Q：提示与自动调优能共存吗？**
  A：叠加使用要先定归属：人工强制与平台修正互相回滚的事故在混合模式里高发 ⚠️ 判断。
- **Q：怎么向新人讲神话章？**
  A：一条一个事故
- **Q：辟谣清单会过期吗？**
  A：会：神话随自动化迁移（“托管即免检”在长成新的），方法论层（测量优先）永不过期。

本章的自检标准只有一个：你能否为现行实践写出它成立的条件与被打破时先出现的症状？

## 核心概念速览（中英对照）

1. **索引神话** — indexing myth：脱离变量的局部经验被升格为无条件规则的圈层迷信。
2. **条件化重写** — conditionalization：把祈使式最佳实践改写为"当X做Y观测Z"。
3. **写税** — write tax / write amplification：每次 DML 为每个索引付出的维护成本。
4. **索引愿望清单** — missing index wishes：DMV 建议不计组合与存储代价的理想态。
5. **index intersection** — 索引交叉：多单列索引结果合并的执行策略，栈式设计的反噬。
6. **热页** — hot page：单调/非单调键下集中承接插入的叶页。
7. **时序局部性** — temporal locality of keys：键生成序与页分裂模式的关系度量。
8. **经验选择率带** — selectivity rule-of-thumb：回表/扫描翻转点的粗阈值，非定律 ⚠️。
9. **提示冻结** — hint freezing：USE PLAN/FORCE 类手段使计划脱离再优化的风险。
10. **证据驱动维护** — evidence-driven maintenance：以使用率与碎片证据触发维护。
11. **回归测试工程** — regression on upgrade：基数估算变化引发的计划翻转过渡管理。
12. **测量优先** — measure-first：本章一切结论的元规则，与 ch15 同句。
