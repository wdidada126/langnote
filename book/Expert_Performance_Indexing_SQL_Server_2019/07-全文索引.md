# 07 · 全文索引（Full-Text Indexing）

> 原书 Chapter 7 "Full-Text Indexing"，pp.213–228（✅ Crossref，DOI …_7）。特化索引四连
> 收官章：词级倒排世界。⚠️ 叙事重构，✅ 锚 Learn（搜索栈总览页）。

## 本章主线

`LIKE '%word%'` 是对 B+ 树世界观的求饶；全文索引把列内容**分词为词表**、以倒排结构
支持 CONTAINS/FREETEXT/PREFIX 等语义。本章定位：全文索引是"搜索引擎的最小内核"在
关系引擎内的投影——够用于文档检索型 SQL 场景，且带来独立于 DMV 体系的运维面。⚠️

## 7.1 组件模型：目录/爬取/分词 ⚠️/✅

- Full-Text Catalog（逻辑容器）→ Full-Text Index（每表一个，基于唯一单列索引键）→
  Word Breaker（按语言切词）+ Stemming（词形归一）+ Stoplist（停用词过滤）。
  ✅ 组件语义官方页：https://learn.microsoft.com/en-us/sql/relational-databases/search/full-text-search
- 前置条件：表需有**单列唯一键索引**作为全文键——第 01/02 章"键选窄而稳"的立场在此
  直接复用（宽多列唯一键=全文维护税）。⚠️

## 7.2 更新跟踪三档 ⚠️ 转述

- CHANGE_TRACKING（异步补差）/ MANUAL（显式 populating）/ INCREMENTAL（随写跟踪，
  2012 后有 FULL 后台合并 ⚠️ 口径）：吞吐与新鲜度的三角；批量装载场景配
  STOP/START FULL-POPULATION 节奏（与第 09 章"后建/暂停维护"同构）。
- 语义提醒：全文索引**不是**事务内即时可见——"写完查不到"多为爬取延迟而非 bug。⚠️

## 7.3 查询语义与计划位置 ⚠️/✅

- CONTAINS（词/前缀/邻近/权重）vs FREETEXT（语义泛化+自动断句）——前者可控、后者宽松，
  生产查询建议 CONTAINS 显式化。✅ 函数族见上 URL。
- 全文命中经"全文查找→键回表→常规算子"两段完成；高命中词使回表成本反超（第 02 章
  账本 + 第 08 章选择性批判在此汇合）。⚠️

## 7.4 🔧 本机类比：SQLite FTS5 倒排最小模型（非本书引擎行为）

环境：python sqlite3 3.45.3（内核含 FTS5 模块，实测可建虚拟表）：

```
CREATE VIRTUAL TABLE docs USING fts5(title, body);
-- 插入 3 行英文语料
SELECT title, snippet(docs,1,'[',']','...',10) FROM docs
 WHERE docs MATCH 'index* OR tree';
→ ('SQL Server indexing','clustered [index] is a balanced [tree]')
SELECT title FROM docs WHERE docs MATCH 'vacuum AND snapshot';
→ ('Postgres internals',)
```

- 读数：`index*` 前缀匹配、布尔组合、snippet 高亮全部由**词级倒排**支撑，无需扫行——
  与 §7.3 的两段式语义同构（FTS5 同样先出 docid 再取内容）；SQL Server 的 word
  breaker/stemming/stoplist 在此分别退化为 FTS5 默认 unicode61 分词器，**功能面更窄**，
  类比止于"倒排消灭子串扫描"一条。
- 对照组（同库）：无 FTS 时对 body 做 `LIKE '%index%'` 必为全表扫——第 01 章 S1 实验的
  全文版重演。

## 7.5 何时外置搜索引擎 ⚠️ 重构判断

- 需要相关性排序（BM25 级）、跨表联合检索、中文分词深度定制、聚合式搜索体验 → 外置
  （ES 类）；需要与事务数据 join、权限过滤、体量中等 → 引擎内全文更省运维面。
- 本书立场（⚠️ 重构）：全文索引是"检索需求的关系内解"，别把它当搜索平台养。

## 7.8 判读 FAQ

- **Q：LIKE '%x%' 能借全文索引吗？**
  A：不能，语义体系不同（子串 vs 词）；前缀需求用全文 CONTAINS 'x*'，中缀词内匹配是两边共同的盲区。
- **Q：中文能用 Full-Text 吗？**
  A：取决于词breakers 装载清单（官方语言集有限 ⚠️）；中文场景常需外置分词或换谱系——§7.5 外置判断的第一条硬指标。
- **Q：全文索引能覆盖查询返回列吗？**
  A：倒排不存内容
- **Q：停止词改了要重建吗？**
  A：stoplist 变更影响后续爬取结果；存量词表的清理节奏与是否 FULL population 需按版本口径评估 ⚠️。
- **Q：全文目录可以多于一个吗？**
  A：可以
- **Q：CONTAINS 加权怎么读？**
  A：ISABOUT/weight 只影响 RANK 序，不影响命中集——排序需求与过滤需求分开设计。
- **Q：全文索引算 DDL 变更敏感项吗？**
  A：列加宽/表结构约束变更可能触发全文重建任务；变更单里它不是“mute”配角。⚠️
- **Q：FTS5 🔧 实验能类比多深？**
  A：止于“倒排消灭子串扫”一条：FTS5 无权限联动、无爬取模型、无 RANK 集成——超出的相似是巧合。
- **Q：和向量检索怎么分工？**
  A：词面 vs 语义

全文章的判读单位是“词”；所有 B+ 树直觉（选择性、覆盖、碎片）在此先做词汇化翻译再套用。

## 核心概念速览（中英对照）

1. **全文目录** — full-text catalog：全文索引的逻辑容器与填充调度单元。
2. **全文索引** — full-text index：词→文档键的倒排结构，每表一个。
3. **全文键** — full-text key index：必需的单列唯一索引，倒排回指的锚。
4. **分词器** — word breaker：按语言把文本切为词元的组件。
5. **词干化** — stemming：walk/walked 归一为同词的形态归并。
6. **停用列表** — stoplist：抑制高频无区分度词的过滤器。
7. **CHANGE_TRACKING** — 变更跟踪：异步捕捉 DML 供增量爬取的机制。
8. **完全填充** — full population：索引重建式的全量爬取。
9. **CONTAINS** — 谓词：词/前缀*/邻近/加权的可控全文匹配。
10. **FREETEXT** — 谓词：自动断句泛化的宽松语义匹配。
11. **爬取延迟** — crawl lag：DML 到全文可查之间的窗口，非 bug 是模型。
12. **倒排索引** — inverted index：词到文档表的结构，🔧 FTS5 实验同构体。
