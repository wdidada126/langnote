# 12 · 查询策略（Query Strategies）

> 原书 Chapter 12 "Query Strategies"，pp.439–460（✅ Crossref，DOI …_12）。22 页：
> 索引侧把结构做对之后，查询侧的配套工程——SQL 写法与参数化如何不辜负好索引。⚠️ 重构。

## 本章主线

同一张完美索引表，可被四种查询写法糟蹋：非 SARGable 谓词、隐式转换、参数嗅探、
临时对象误用。本章站索引一侧反观查询——"索引失效"的半数病因住在 SQL 文本里。⚠️

## 12.1 SARGable 谓词改写 ⚠️/✅ 概念

- 谓词列上的函数/运算、前导通配 LIKE、`OR` 混合列 → 定位前缀被销毁，退化为扫（§1.1
  规则的负面清单版）；改写方向=把计算移到常量侧（`d>=X AND d<X+1day` 型）。
- 隐式转换：列类型与字面量/参数类型不匹配时**转换发生在列上**，索引 seek 直接出局
  ——参数 dtype 对齐是驱动/存储过程层的索引工程。✅ 概念域见
  https://learn.microsoft.com/en-us/sql/t-sql/statements/create-index-transact-sql 生态页群 ⚠️ 定位
- 递归 CTE/游标场景的索引配合（tally 表替代）⚠️ 重构，本册不外推。

## 12.2 参数嗅探与计划缓存 ⚠️ 转述 + ✅ 概念页

- 首参定型：编译期以嗅探值+统计估行数，计划进缓存被复用——倾斜数据下"一次嗅探、
  万人陪葬"；对策谱系（重构 ⚠️）：OPTION(RECOMPILE)（编译税换贴脸计划）、局部变量+
  OPTIMIZE FOR、查询存储强制计划（§10.3 ✅）、数据分层拆分。✅ 提示语义：
  https://learn.microsoft.com/en-us/sql/t-sql/queries/hints-transact-sql-query
- 2019 相关口径（⚠️ 转述）：表变量延迟编译（deferred compilation）+ 合成统计（TF 2389
  族）显著缓解"表变量=行数黑箱"的经典顽疾——把表变量从"不可优化区"拉回可估区。

## 12.3 临时对象策略：#temp / 表变量 / TVP / 内联 ⚠️ 转述

- 决策矩阵（重构 ⚠️）：需要统计与二次索引→#temp（可建索引，tempdb 有维护面）；
  小行数即生即灭→表变量（2019 后估算已改善）；跨过程传集合→TVP（只读，历史上一表
  一索引 ⚠️ 口径）；单行逻辑→直接内联派生表，别让"习惯性 temp"吃 tempdb 版本存储。
- tempdb 是索引策略的暗面（2019 系统表内存优化正是为压 tempdb 元数据争用 ⚠️ ch3 同引）：
  ✅ 官方概念页：https://learn.microsoft.com/en-us/sql/t-sql/statements/create-table-transact-sql
  （临时表语法与生命周期语义所在）。
- 🔧 类比（非 SS 行为）：sqlite3 3.45.3 中
  `CREATE TEMP TABLE t_top(...); INSERT ... SELECT ... GROUP BY; CREATE INDEX ti_top ON t_top(n);`
  随后 `SELECT status FROM t_top WHERE n>100` → `SEARCH t_top USING INDEX ti_top (n>?)`——
  "先聚合落 temp、再为下钻建索引"的两段式在 SQLite 完整可行，正是 #temp+索引工作流
  的最小同构体；表变量类比=不带索引的 CTE 物化（SQLite 无表变量对象，如实 ⚠️）。

## 12.4 连接策略与索引形态 ⚠️/✅ 概念

- 嵌套循环（点查驱动，吃 seek 索引）/哈希（宽集 build，吃扫描）/合并（双有序，吃键序）
  ——索引设计时**预判 join 算法**：给 NL 配 seek 路径、给 Merge 配同序键，避免"索引
  建了、算法没用"。✅ join 物理算子属引擎文档常识域 ⚠️ 定位。
- 半连接/EXISTS 与 IN 的索引消费形态（外键列必须有索引——孤儿索引探测同款论证 ⚠️）。

## 12.5 分页与 Top-N ⚠️ 重构

- `ORDER BY ... OFFSET/FETCH` 的索引红利：键序匹配则读到 N 即止；表达式排序/无键序
  支撑则全量排序落 tempdb——分页 API 是索引设计的 SLA 前端。
- 深分页反模式（OFFSET 100000）的索引救法=键集续传（seek 到上页末键），为第 14 章
  案例分析埋点。⚠️

## 12.8 判读 FAQ

- **Q：改写 SQL 和加索引冲突时先做谁？**
  A：先改写
- **Q：参数化到底该 ON 还是 OFF？**
  A：复用率高的等值模板配好统计可 ON；形态多样+倾斜严重先 RECOMPILE 观察，再逐族收紧——没有全局答案。
- **Q：表变量还“禁止优化”吗？**
  A：2019 已半解（§12.2）；大行数中间集仍首选 #temp：索引自由+统计持久是表变量给不了的。
- **Q：FORCE ORDER 何时合法？**
  A：应急闸门
- **Q：深分页改 keyset 对 API 的代价？**
  A：失去随机跳页
- **Q：TVP 与 XML/JSON 打包传参怎么选？**
  A：结构化列类型走 TVP；自由文本/半结构走 JSON；打包字符串是反模式的温床。
- **Q：隐式转换的常态化防线？**
  A：连接层/存储过程参数 dtype 与列类型强一致+代码评审项——索引救不了类型漂移。
- **Q：游标全错吗？**
  A：快进只读游标对行级外部调用仍合理；错的是用它替代集合运算——先看关系代数能否表达。
- **Q：嗅探治理能自动化吗？**
  A：QS 强制/自动调优已部分接管；人工侧留观：回退检测阈值与豁免清单。✅/⚠️

查询章的一句话总纲：索引承诺的快，SQL 文本有权先扣一半——判案先看谓词、参数与类型三张牌。

## 核心概念速览（中英对照）

1. **SARGable** — 可定位谓词：能把计算推到常量侧、保留列上键序语义的谓词形态。
2. **隐式转换** — implicit conversion：dtype 不匹配时发生在列侧、杀死 seek 的静默杀手。
3. **参数嗅探** — parameter sniffing：编译期首参值钉死缓存计划的行为。
4. **OPTION(RECOMPILE)** — 即编译提示：以编译税换当前参数贴脸计划。
5. **OPTIMIZE FOR** — 编译期假定值提示：倾斜场景的折中瞄准具。
6. **强制计划** — plan forcing：经查询存储把坏回退钉回好计划的闸门。✅
7. **延迟表变量编译** — deferred table variable compilation：2019 起表变量行数可估化 ⚠️。
8. **#temp 策略** — temp table strategy：需要统计/索引的中间结果落地形态。
9. **TVP** — table-valued parameter：只读集合入参，跨过程传表的标准通道。
10. **嵌套循环索引** — NL-friendly index：为驱动侧点查准备的 seek 路径。
11. **合并连接键序** — merge join order：双输入同序时索引顺序即免费排序。
12. **键集分页** — keyset pagination：以末键 seek 替代深 OFFSET 的续传法。
13. **tempdb 暗面** — tempdb cost：临时对象策略背后的版本存储与元数据争用。
