# 03 · 索引元数据与统计信息（Index Metadata and Statistics）

> 原书 Chapter 3 "Index Metadata and Statistics"，pp.91–162（✅ Crossref，DOI …_3）。
> 72 页的第二大章：SQL Server 如何"知道"索引里有什么，以及优化器如何据此决策。⚠️ 叙事重构。

## 本章主线

索引元数据目录（sys.indexes 家族）+ 统计信息（直方图/前导列密度）是同一枚硬币的两面：
前者告诉引擎"有什么结构"，后者告诉引擎"结构里数据长什么样"。统计信息过期 = 隐形坏计划
的头号来源——这是本章（及第 13/14 章监控分析）的因果起点。⚠️

## 3.1 目录视图家族 ⚠️ 转述 + ✅ 概念

- `sys.indexes`（逻辑定义）、`sys.partitions`（分区行集）、`sys.allocation_units`（分配单元：
  IN_ROW_DATA / ROW_OVERFLOW_DATA / LOB_DATA）三层串联描述任意索引的物理存在；
  `sys.index_columns` 记录键序与 is_included_column。✅ 视图存在性口径与 Learn 一致。
- 实用组合：以 partition + allocation_unit 联查得到每索引每分区的 row_count/reserved，
  是第 13 章"索引体积盘点"的基础查询（原书示例代码逐条未核对 ⚠️）。

## 3.2 统计对象：CREATE STATISTICS 与直方图 ⚠️ 转述 + ✅ URL

- 统计信息≠索引：单列/多列统计对象独立存在；缺列统计时 SQL Server 可自动生成
  （AUTO_CREATE_STATISTICS），自动更新由行变更阈值触发（2019 起为渐进式阈值，
  TF 2371 历史包袱在 15.x 的行为口径 ⚠️ 转述）。✅ 官方总览：
  https://learn.microsoft.com/en-us/sql/relational-databases/statistics/statistics
- DBCC SHOW_STATISTICS 三结果集：头部（最后更新时间/行数）、密度（前导组 distinct 值）、
  **直方图**（≤200 bucket：range_hi_key/equality/range/avg_rows）——等值与区间估算的原料。⚠️
- 2019 亮点（本册记为 ⚠️ 转述，官方 URL 可复核）：合成统计（synthetic statistics，TF 2389
  家族）用于内存中表变量行数的快速估算；tempdb 系统表内存优化（memory-optimized metadata）。

## 3.3 统计过期如何制造事故 ⚠️ 重构论证链

1. 批量 ETL 后大量键值新增 → 直方图 range_hi_key 停在旧值；
2. 优化器对"直方图外"谓词按外推规则估行数 → 估算塌方；
3. 错估行数 → 选错 join 类型/错误 DOP/内存授予失真 → 计划回退。
- 对策分层：UPDATE STATISTICS（全量/采样比）、维持计划、错峰重建；第 09 章维护闭环承接。

## 3.4 统计与索引选型互动 ⚠️

- 索引提供"可达路径"，统计决定"走不走"；同一索引在不同统计状态下可呈现"建了不用"的
  假象——先查统计新鲜度再删索引，是第 13 章未使用索引裁决的前置程序。
- 过滤索引的谓词与统计的交互（筛选条件上的数据分布仍受全表统计支配）⚠️ 转述，
  对位第 11 章。

## 3.5 🔧 本机类比：ANALYZE 与 sqlite_stat1（非本书引擎行为）

环境：python sqlite3 3.45.3，orders 200k 行；将 status 更新为高度倾斜（'Z'≈199800 行，
其余个位数），对比 OR 谓词计划并读取统计目录：

```
ANALYZE 前: SCAN orders USING COVERING INDEX ix_cov
sqlite_stat1: ix_cov '200000 40 39 1' | ix_partial '39 1'
              ix_date_status '200000 596 381' | ix_orders_cust '200000 40'
ANALYZE 后: SCAN orders USING COVERING INDEX ix_cov （计划未变）
```

- 读数①：sqlite_stat1 的 `200000 40 39 1` = 行数+前导列平均重复度链——SQL Server 密度
  向量的极简同位体；`ix_partial '39 1'` 直接把"部分索引只描述小子集"写进统计。
- 读数②（诚实记录）：本例 ANALYZE 前后计划**未翻转**——SQLite 代价模型对该 OR 查询
  无更优候选；这不否定"统计过期致错计划"，只说明该引擎在此形态下鲁棒。SQL Server 的
  对应现象需真机复现，本机**不实测、不伪装** ⚠️。

## 3.9 判读 FAQ

- **Q：统计对象和索引是一回事吗？**
  A：不是。索引是可达路径，统计是路径的地图；同一列可以“有索引无统计”（表达式谓词列），也可以“有统计无索引”（纯估计用）。
- **Q：删索引前为什么先查统计新鲜度？**
  A：统计过期时优化器会“装看不见”索引，usage_stats 一片空白被误判零读——先 UPDATE STATISTICS 复测再下判决。
- **Q：直方图 200 桶够吗？**
  A：对高倾斜多峰数据是硬上限：桶外推区间的估计失真常是坏计划首因；对策为关键列手动 FULLSCAN+分区级统计。⚠️
- **Q：表变量在 2019 还“没有统计”吗？**
  A：半对：仍无持久统计对象，但合成统计/延迟编译已让行数不再是恒 1 黑箱——具体 TF 组合生效条件 ⚠️ 转述，升级后实测。
- **Q：AUTO_UPDATE 异步刷新会咬人吗？**
  A：会：阈值刚越线的那批查询仍用旧统计（异步不阻塞），批量作业后的头几分钟是回退高发窗——与 ch12 嗅探叠加成经典双杀。
- **Q：采样率怎么选？**
  A：规模越大同等采样已越密；倾斜表用固定行数语义（SAMPLE n ROWS）更稳；大表 FULLSCAN 的维护税要进窗口预算。⚠️ 经验
- **Q：多列统计什么场景必须手动建？**
  A：复合键之外的高相关列组（外键对、状态+日期）——AUTO_CREATE 只补单列，join 选择性靠单列密度必失真。
- **Q：sys.dm_db_stats_properties 干嘛用？**
  A：统计健康度的巡检入口：last_updated/行变更计数字段支撑“过期清单”报表，是 ch13 监控面板的数据源。⚠️ 视图名以 Learn 为准
- **Q：统计会被自动删吗？**
  A：drop_index 连带删其统计；反向不成立——索引没了，其借用的统计可能仍在，孤儿统计定期盘点。⚠️

统计章的通病是“把估计失真误诊为索引缺位”。FAQ 的九问全部指向同一纪律：任何索引裁决之前，先让统计站到当天。

## 核心概念速览（中英对照）

1. **统计对象** — statistics object：独立于索引的列分布描述（直方图+密度）。
2. **直方图** — histogram：≤200 桶的键值区间分布，等值/范围估算原料。
3. **前导列密度** — leading-column density：distinct 值倒数形式的平均重复度。
4. **自动统计** — auto-created statistics：查询触发时对谓词列补建的单列统计。
5. **自动更新阈值** — auto-update threshold：行变更数越线后异步重算统计的机制。
6. **采样率** — SAMPLE PERCENT：统计重建读取行占比，全扫与鲁棒性的权衡。
7. **sys.indexes/partitions/allocation_units** — 目录三层：逻辑定义→分区→分配单元。
8. **IN_ROW_DATA/LOB/ROW_OVERFLOW** — 分配单元三型：宽行与大值的物理分家。
9. **合成统计** — synthetic statistics：2019 起为表变量等内存结构即时估算行数 ⚠️。
10. **内存优化元数据** — memory-optimized tempdb metadata：tempdb 系统表迁内存表 ⚠️。
11. **行数估计失真** — cardinality misestimate：统计外推/过期导致的优化器误算总根。
12. **DBCC SHOW_STATISTICS** — 统计查看命令：头/密度/直方图三结果集。
13. **sqlite_stat1** — SQLite 统计目录表：🔧 类比直方图/密度的最简观察面。
