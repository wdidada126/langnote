# 10 · 索引工具（Indexing Tools）

> 原书 Chapter 10 "Indexing Tools"，pp.319–351（✅ Crossref，DOI …_10）。工具箱章：
> 官方件 + DMV 查询 + 社区工具三层。⚠️ 逐条为重构归纳（工具生态本身变化快，演进节加重）。

## 本章主线

工具不产生决策，只把第 01–09 章的观测面变成可查询的报表。本章按"设计期辅助 →
使用率取证 → 计划回放"三类整理工具谱，并给每个官方件标注它的**假设盲区**——
误用工具比没有工具更危险（第 08 章神话 7 的回声）。⚠️

## 10.1 设计期辅助 ⚠️/✅

- SSMS 建索引向导/脚本化：生成器立场（默认 FILLFACTOR/选项模板）需人工复核，
  脚本化后走变更流程而非点鼠标直连生产。⚠️
- Database Engine Tuning Advisor（DTA）：以工作负载文件为输入给索引/物化视图建议——
  本书立场（⚠️ 重构）：建议质量受"假设完美索引+不计维护成本"限制，输出当**候选清单**
  而非执行单；DTA 属微软明示的低调维护状态（"deprecation 口径 ⚠️ 转述，本册核不到
  专页 200 URL，不给链接"），后继思路分流到查询存储分析与自动调优（§10.4/演进节 ✅）。

## 10.2 使用率取证：DMV 查询族 ⚠️/✅

- `sys.dm_db_index_usage_stats`（user_seeks/scans/lookups/updates，实例启动起算）、
  `sys.dm_db_operational_stats...`（2019 新增叶级操作统计家族 ⚠️ 视图全名以 Learn 为准）、
  `sys.dm_db_missing_index_*` 四件套（组/细节/列组/语句）。✅ DMV 体系存在性；
  本册未能核到 missing-index 专页 200 URL（404），⚠️ 如实登记，判读规则见第 13 章。
- 关键工程点（重构 ⚠️）：usage_stats 在重启/故障转移后清零——**取证窗口要覆盖
  完整业务周期（含月度批/季结）**，否则"零读索引"判决是伪证。

## 10.3 计划与运行时观测 ⚠️/✅

- 执行计划采集：SHOWPLAN XML、`sys.dm_exec_query_plan`、Query Store（强制启用为默认
  选项的口径自 2016 起 ⚠️ 转述）✅：
  https://learn.microsoft.com/en-us/sql/relational-databases/performance/monitoring-performance-by-using-the-query-store
- Extended Events：索引相关事件族（如自动统计更新、内存授予类）挂模板采集，把
  "偶发回退"变成可回放事件流。✅
  https://learn.microsoft.com/en-us/sql/relational-databases/extended-events/extended-events
- 第三方/sp_ 系社区工具（存储过程族，盘上无专册）：登记为生态坐标，⚠️ 不作内容依据。

## 10.4 工具链与自动化 ⚠️/✅

- 云测 Automatic Tuning（索引创建/删除 + 强制计划修正两类 force）作为"工具即平台"的
  形态进入第 08 章神话清单；自管环境对应物=作业化巡检报表。✅
  https://learn.microsoft.com/en-us/sql/relational-databases/automatic-tuning/automatic-tuning
- 工具输出进入变更管理：建议→沙箱验证（等价数据量/统计）→灰度→回滚脚本四步。⚠️

## 10.5 🔧 本机类比：三层工具的最小对应物（非本书引擎行为）

环境：sqlite3 CLI 3.50.6 / python 3.45.3 / duckdb 1.5.5——手边"无第三方工具"的最小工具链：

```
设计期:   EXPLAIN QUERY PLAN（SQLite）/ EXPLAIN ANALYZE（DuckDB）
使用率:   pragma_index_list('orders') → 含 partial 标志；sqlite_stat1（ANALYZE 产物）
取证盲区: SQLite 无 usage_stats 同位物 → 只能靠自写查询计数器/审计日志
```

- 读数：SQL Server 的 DMV 便利度是**真机独有红利**；换到任何开源引擎，"索引使用证据"
  都得自己造——把 §10.2 的工程纪律（取证窗口/重启清零）内化后，工具差异就不再是门槛。
- DuckDB 的 EXPLAIN 树里 Projections 列裁剪与 Filters 残留（D1/D2）演示了"无索引
  引擎"的计划观测面：工具章的通用心法=**读计划，不读工具结论**。

## 10.8 判读 FAQ

- **Q：工具给出的建议顺序能照抄吗？**
  A：不能：建议集内部常互相覆盖（宽复合吃掉三条窄的），合并去重后才是候选清单。
- **Q：DMV 报表和 SSMS 界面哪个可信？**
  A：同源不同窗：界面聚合会抹掉 index_id 粒度；裁决级取证永远回到 DMV 明细查询。
- **Q：自动调优的创建要人工审吗？**
  A：云测默认自动+自动回滚；审的对象是“策略配置与例外表”而非每条动作——否则回到手工时代。
- **Q：没有第三方工具的隔离环境怎么办？**
  A：官面（QS/XEvent/DMV 快照作业）覆盖 95% 需求；§10.5 🔧 演练证明账本可自建——缺的是纪律不是软件。
- **Q：工具版本比引擎新/旧要紧吗？**
  A：采集视图随版本增列（2019 新增叶级统计），旧工具读不到新面≠不存在——以 Learn 文档域为版本锚。
- **Q：Excel 出的裁决算合规留存吗？**
  A：裁决产物需可重放（查询+快照+时间窗绑定）；电子表格快照若无采集脚本，审计时不可复原。
- **Q：社区 sp_ 脚本能直接进生产吗？**
  A：只读采集类
- **Q：DTA 还有学习价值吗？**
  A：有
- **Q：工具链最大的一处坑？**
  A：“报表即真相”：所有计数都有窗口与重启语义，读报表的人必须知道账本的起止时刻。

工具箱章的元规则：每个工具输出都先过“采集口径三问”（何时采/采什么/多久清零），再谈结论。

## 核心概念速览（中英对照）

1. **DTA** — Database Engine Tuning Advisor：工作负载→索引建议的官方设计期工具 ⚠️/✅。
2. **usage stats** — 使用率统计：per-index 的 seeks/scans/lookups/updates 累计账本。
3. **missing indexes** — 缺失索引 DMV：假设完美索引的愿望清单，非执行单。
4. **重启清零** — counter reset on restart：取证窗口必须跨越实例生命周期的原因。
5. **SHOWPLAN XML** — 计划 XML：机器可读计划，回归比对的基础格式。
6. **Query Store** — 查询存储：计划历史+运行统计的持久黑匣子。✅
7. **Extended Events** — 扩展事件：轻量事件流采集框架，偶发问题的回放器。✅
8. **operational stats** — 叶级操作统计 DMV 家族（2019 增强 ⚠️ 名口径）。
9. **建议四步流程** — 建议→沙箱→灰度→回滚：工具输出进入变更管理的通道。
10. **读计划不读结论** — plan-over-tool：跨引擎通用的工具心法 🔧 佐证。
11. **pragma_index_list** — SQLite 索引目录 pragma：🔧 最小工具链的"使用率缺位"参照。
12. **取证窗口** — evidence window：覆盖月批/季结的统计观测时长设计。

  §10.3/§10.4）；SSMS/Azure Data Studio→独立工具线的整合 ⚠️ 转述。
- 工业实践：2024–2026 的索引治理平台化形态=DMV 定时采集→时序库→准入/裁决看板，
  本章三层（设计/取证/回放）在平台里各有对应模块；小团队可直接以开源 exporter 化
  usage_stats 起步。⚠️ 判断
