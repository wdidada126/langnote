## 12.1 Part II 的用意：把 16 步变成「可裁可派」的清单

Part I 逐步叙述，Part II 横向切五刀，把同一批活动按不同管理维度重排成矩阵。五表**互为索引、配套使用**：
先定「选哪些步」（01 章 Guide）→ 用「活动依赖图」排先后 → 用「Task/Subtask + WBS」拆包 → 用「资源分配」
排人 → 用「准入准出与交付物」定验收门禁。这正是本书把 BI「从艺术变工程」的落点。

## 12.2 五张矩阵逐一（Ch 17–21 ✅）

- **17 Resource Allocation Matrix（资源分配矩阵）**：横轴步骤/角色、纵轴任务——谁在何时投入多少，识别
  关键人瓶颈与并行轨道（01 章）的资源冲突。
- **18 Entry & Exit Criteria and Deliverables Matrix（准入准出与交付物矩阵）**：每步的**入口条件/出口验收/
  交付物**——本册「四件套模板」中 Deliverables/Risks 的表格化，是质量门禁蓝本。
- **19 Activity Dependency Matrix（活动依赖矩阵）**：活动间前后置/并行关系，据此排 CPM 关键路径（04 章）。
- **20 Task/Subtask Matrix（任务/子任务矩阵）**：把活动分解到可派工的子任务粒度。
- **21 Practical Guidelines Matrix（实践指南矩阵）**：每步的「最佳实践/常见坑」浓缩成对照表。

## 12.3 Appendix·工作分解结构（WBS ✅）

附录给出可**裁剪定制**的 WBS（官方目录 ✅「Appendix. Work Breakdown Structure」，Preface 提到随书 CD 附
可直接改用的 WBS 模板）。WBS 把选定的开发步骤展开成「阶段→活动→任务→子任务」树，是 04 章项目计划与
本文件 Task 矩阵的**合体输出物**，也是把本书方法搬进真实项目管理系统（MS Project/Jira 类）的接口。

## 12.4 五表联动的使用法（⚠️ 编者综合）

1. 依 01 章 Guide 选定本主动性要走哪些步（不是每次 16 步全走）。
2. 用 **19 依赖矩阵**排出可行顺序与并行度 → 找 **CPM** 关键链。
3. 用 **20 Task 矩阵 + 附录 WBS** 拆到可派工。
4. 用 **17 资源矩阵** 填人，冲突处回到步骤取舍。
5. 用 **18 准入准出矩阵** 为每步设 DoD（完成的定义），用 **21 指南矩阵** 贴作评审清单。

## 12.5 为什么这套「矩阵化」在 BI 里格外重要

BI 项目干系人多、活动碎、跨组织依赖强，纯散文流程易失控。本书用**正交矩阵**把「同一批工作的多种切法」
固化，使项目经理能像查表一样派工与验收——这是它对「过程维」（区别于建模维）最实质的贡献，也与
[01](01-开发步骤导论与BI项目生命周期框架.md) 章「四件套模板」首尾呼应。

## 12.8 五表落地检查清单（⚠️ 编者综合）

- 是否**只走选定的步**（裁剪），而非默认机械跑满 16 步？
- 活动依赖矩阵是否与 01 章并行轨道一致、无环路？
- 每步出口是否都写了**可验收的 DoD**（对应 18 矩阵）？
- 资源分配矩阵是否暴露了**关键人单点**风险？
- 实践指南矩阵（21）是否被贴作评审会前清单，而非束之高阁？
- 附录 WBS 是否已按本主动性的规模裁枝，再搬入项目管理系统？

## 12.9 阅读自测（附答案要点 ⚠️ 编者）

- **问：五张矩阵之间是何关系？** 答：对同一批活动做资源/交付/依赖/任务/指南五种**正交切分**、配套查表。
- **问：准入准出矩阵（18）的现代落点是？** 答：发布门禁 / release checklist（CI 自动执行）。
- **问：指南矩阵（21）的现代落点是？** 答：建模/BI 评审清单与平台内嵌 lint 规则。
- **问：附录 WBS 与哪步直接接口？** 答：Step 3 项目计划（→ [04](04-项目规划与需求定义.md) 章）。
- **问：为何「裁剪」是这套方法的关键？** 答：主动性规模不同，全量执行即沦为官僚负担。

## 核心概念速览（中英对照）

- **速查矩阵** — At-a-Glance Matrices：把 16 步按资源/交付/依赖/任务/指南五维重排的可执行表。
- **资源分配矩阵** — Resource Allocation Matrix：步骤×角色的投入映射，识别关键人瓶颈。
- **准入准出与交付物矩阵** — Entry & Exit Criteria & Deliverables Matrix：每步入口条件/出口验收/工件（质量门禁）。
- **活动依赖矩阵** — Activity Dependency Matrix：前后置/并行关系，供 CPM 排程。
- **任务/子任务矩阵** — Task/Subtask Matrix：分解到可派工粒度。
- **实践指南矩阵** — Practical Guidelines Matrix：每步最佳实践与常见坑对照。
- **工作分解结构** — Work Breakdown Structure（WBS）：阶段→活动→任务→子任务的可裁剪树（附录）。
- **裁剪定制** — Tailoring：按主动性选择应走哪些步、复用哪些 WBS 分支。
- **完成的定义** — Definition of Done（DoD）：18 矩阵出口准则的现代表述。
- **正交切分** — Orthogonal Views：同一批工作的多种查表视角。

## 最新演进与工业实践

2002→2026 对位（官方源 ⚠️ 转述 + URL 于 2026-10-02 验 200 ✅）：

- **静态矩阵 → 动态项目/数据平台**：五表 + WBS 从纸面迁入工单系统（Jira/MS Project）与 **DAG 编排**
  （Airflow/Dagster），活动依赖矩阵 19 直接变成可运行 DAG，准入准出矩阵 18 变成 CI 门禁。
- **交付物矩阵 → 数据契约 + DoD 测试**：出口验收从人工勾选升级为**自动质量测试 + schema 契约**，随流水线
  强制执行（对位 [../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md](../Analytics_Engineering_with_SQL_and_dbt/00-总览与阅读地图.md)）。
- **资源矩阵 → 数据产品 owner/RACI**：谁投入/谁负责沉淀为**数据产品的域 owner 与 RACI**，与治理一体化
  （⚠️ `https://learn.microsoft.com/en-us/fabric/data-warehouse/semantic-models` ✅ 200 把「口径负责人」写进
  语义模型元数据；对位 [../Data_Mesh/00-总览与阅读地图.md](../Data_Mesh/00-总览与阅读地图.md)）。
- **指南矩阵 → 平台内嵌最佳实践**：常见坑与处方被平台产品化为**性能/成本顾问与 lint 规则**（如语义层/目录
  内置规范检查，⚠️ `https://docs.getdbt.com/docs/build/semantic-models` ✅ 200）。
- **WBS → 用例/价值流规划**：附录可裁剪 WBS 演化为 **use-case / value-stream 规划 + roadmap 工具**，但
  「按主动性选择走哪些步」的**裁剪思想**仍是本书独有、且被敏捷数据团队沿用；工业实践中，成熟组织常把 18
  准入准出矩阵直接实现为**发布门禁清单（release checklist）**，把 21 指南矩阵实现为**建模/BI 评审清单**。
