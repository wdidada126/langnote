> 原书第 7 章是**交付现代化的第一半**：把微服务打包成容器镜像、用容器运行，打通「开发→部署」
> 的最后一公里。评价「表面」指内容偏 Docker 基础、缺 Kubernetes 编排与云原生全貌。

## 核心精讲

（以下为教学性梳理，伪代码/SQL 均**教学示意，不参与构建**。）

### 7.2 镜像构建要点

```dockerfile
# 教学示意，不参与构建
FROM eclipse-temurin:17-jre   # 用精简基础镜像, 别用完整 OS
COPY app.jar /app/app.jar
ENTRYPOINT ["java","-jar","/app/app.jar"]
# 要点:
#  - 分层: 依赖层与代码层分离, 利用缓存加速重建
#  - 瘦身: 多阶段构建(multi-stage)只保留运行所需
#  - 可复现: 固定版本, 不用 latest, 保证不可变
#  - 非root运行: 安全基线
```

### 7.3 容器编排的核心问题

| 问题 | 说明 |
| --- | --- |
| 调度 | 把容器放到哪台机器，考虑资源/亲和性 |
| 网络 | 容器间互通、服务发现、对外暴露（Ingress） |
| 存储 | 有状态服务的持久化卷（与无状态容器分离） |
| 自愈 | 容器挂了自动拉起 |
| 弹性 | 按负载自动扩缩（HPA） |

### 7.4 容器与服务化部署

- 一个微服务 = 一个镜像 = 一组（可多副本）容器；配置通过环境变量/配置中心注入，
  镜像本身不可变（与第 8 章 CI/CD 衔接）。
- 容器天然适配**水平扩容**（加副本）与**蓝绿/金丝雀发布**（与第 2 章迁移开关呼应）。

## 版本演进

- **本书无第二版**；本节写 2017 年口径 → 2026 年视角的变化。
- **🔧 Kubernetes 成为编排事实标准**：书里 7.3 还停留在「多容器怎么管」的雏形。
  2026 年 `kubernetes/kubernetes`（128015★）已是容器编排唯一主流，调度/网络/存储/自愈/弹性
  全部平台化；`docker/docker`（72137★）退居「构建与运行时之一」。
- **🔧 容器与 Service Mesh 融合**：Istio（istio/istio 38408★）的 sidecar 以容器形态注入，
  治理（发现/限流/熔断/mTLS）与业务容器解耦（与第 1 章 Mesh 补丁闭环）。
- **🔧 不可变基础设施 + GitOps**：镜像+声明式 YAML 成为唯一真相源，部署即「改 Git→自动同步」，
  与第 8 章 DevOps 闭环。
- **🔧 云原生存储/有状态**：StatefulSet、CSI、Operator 让数据库/消息等也能云原生化管理。
- **🔧 安全左移**：镜像扫描、非 root、最小权限、seccomp/AppArmor 成为容器安全基线。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「容器 = 轻量虚拟机」 | 容器共享内核、进程级隔离；不是完整 OS，生命周期更短 |
| 2 | 「一个容器跑一堆服务」 | 一容器一进程/一服务，便于弹性与故障隔离 |
| 3 | 「用 latest 标签没问题」 | 必须固定版本，保证镜像**不可变、可复现** |
| 4 | 「容器化就实现了 DevOps」 | 容器化只是交付单元标准化，还需 CI/CD + 编排（第 8 章） |
| 5 | 🔧 本书 7.3 缺编排全貌 | 2026 年 Kubernetes 是默认编排，单容器管理已无独立意义 |
| 6 | 🔧 本书缺容器与 Mesh 融合 | sidecar 容器化注入，治理彻底下沉（见 01 章补丁） |
| 7 | 🔧 本书缺 GitOps/不可变基础设施 | 部署应声明式、Git 驱动，而非手敲命令 |
| 8 | 🔧 本书容器安全几乎未提 | 镜像扫描、非 root、最小权限是 2026 年基线 |
