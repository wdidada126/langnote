## 核心精讲

（以下为教学性梳理，伪代码/SQL 均**教学示意，不参与构建**。）

### 5.2 调用链的核心模型（Dapper 三件套）

```text
# 教学示意，不参与构建
Trace : 一次完整请求(如"下单")的全局链路, 用一个全局 TraceID 标识
Span  : 链路中的一个节点(一次 RPC/一次方法), 有自身 SpanID 和父 SpanID
        span 含: 服务名/方法/起止时间/标签/日志/状态
Annotation: span 内的关键时间点(CS/SR/SS/CR: 客户端发/服务端收/服务端回/客户端收)

跨服务传递:
  请求头带上 traceId + 当前 spanId(baggage), 下游据此新建子 span, 父=收到的 spanId
  -> 全链路串成树
```

| 概念 | 作用 |
| --- | --- |
| TraceID | 把分散在 N 个服务的日志/span 归到同一次请求 |
| SpanID | 标识一次调用节点；parentSpanID 表达嵌套/顺序 |
| 业务链 | 在调用链之上叠加业务语义（如「支付→风控→入账」），便于业务排障 |

### 5.3 系统五段式

1. **采集（埋点）**：框架拦截器/agent 自动埋点（或手动 API），生成 span；
2. **上报**：异步批量上报到 collector（带采样，防雪崩）；
3. **处理（Processor）**：聚合、补全（ip→机房/owner）、计算耗时与依赖；
4. **存储**：按 trace 聚合存储（Cassandra/ES 等），支持按 traceId/服务/时间检索；
5. **展示**：拓扑图、火焰图、慢调用下钻、依赖分析。

> 调用链与第 4 章日志的**关键连接点**：在日志里打上 TraceID，就能从一条报错日志一键跳到
> 整条链路，定位「是哪个下游慢了」。这正是今天 OpenTelemetry 统一语义在做的事。

## 版本演进

- **本书无第二版**；本节写 2017 年口径 → 2026 年视角的变化。
- **🔧 OpenTelemetry 成为标准**：书里自研私有协议。2026 年
  `open-telemetry/opentelemetry-collector`（7600★）定义了**统一的 Trace/Span/Metric/Log 语义**，
  各语言 SDK、各后端（Jaeger/SkyWalking/Zipkin/Tempo）互通，不再锁定。
- **🔧 成熟开源实现**：`apache/skywalking`（24963★，Java 友好、自研探针、带拓扑）、
  `jaegertracing/jaeger`（23244★，CNCF 毕业，Go）、`openzipkin/zipkin`（17467★，Dapper 正统后裔）。
- **🔧 eBPF 无侵入采集**：书里靠代码埋点/agent 字节码增强。2026 年可用 eBPF 在内核层抓
  网络/系统调用，零代码侵入产出调用链（与第 4/6 章补丁同源）。
- **🔧 采样与成本治理**：全量上报在大数据量下不可行；头部/尾部采样（tail-based sampling）
  成为标配，只保留异常/慢链路全量。
- **🔧 服务网格天然产生链路**：Istio（istio/istio 38408★）的 Envoy sidecar 自动产出调用链，
  无需业务埋点——与第 1 章 Mesh 补丁闭环。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「调用链 = 监控」 | 调用链是**排查手段**之一，须与指标/日志组成可观测性三支柱 |
| 2 | 「TraceID 只在网关生成就行」 | 必须在**每一次跨服务调用**中透传（请求头 baggage），否则链路断裂 |
| 3 | 「全量上报才准」 | 大数据量下全量不可行；应头部/尾部采样，保留异常链路 |
| 4 | 「调用链能替代日志」 | 互补：链路给「哪里慢」，日志给「为什么错」，需 TraceID 打通 |
| 5 | 「埋点越细越好」 | 过细埋点带来性能与存储开销；按业务边界埋点 |
| 6 | 🔧 本书 5.3 自研私有协议 | 2026 年 OpenTelemetry 已是标准，应优先采用而非造轮子 |
| 7 | 🔧 本书缺成熟开源对照 | SkyWalking/Jaeger/Zipkin 可直接落地，不必从零自研 |
| 8 | 🔧 本书缺服务网格自动链路 | Mesh sidecar 天然产出调用链，业务零埋点（见 01/07 章补丁） |
| 9 | 🔧 本书缺 eBPF 无侵入采集 | 采集从字节码增强演进到内核层无侵入 |
