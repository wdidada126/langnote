## 核心精讲

（以下为教学性梳理，伪代码/SQL 均**教学示意，不参与构建**。）

### 6.1–6.2 应急的两条法则与一条铁律

- **海恩法则**：每起严重事故前，都有 29 次轻微事故、300 起未遂先兆、1000 起隐患。
  → 重视监控告警的**小信号**，把事故消灭在先兆期。
- **墨菲定律**：只要可能出错，就一定会出错。→ 设计时必须假设依赖会挂、网络会抖、磁盘会满。
- **铁律：先恢复、后定位**。线上第一目标是**止血**（重启/回滚/限流/降级/切流），
  不是马上查清根因。查清根因可以等流量恢复后慢慢做。

### 6.3 技术攻关方法论（通用套路）

```text
# 教学示意，不参与构建
1. 锁定现象: 什么指标异常?(RT/QPS/错误率/CPU/内存/GC/磁盘)
2. 圈定范围: 哪个服务/接口/机器/时间段? 是否变更引起(对比变更时间线)?
3. 收集证据: 线程栈(jstack)/堆(jmap)/GC日志/慢SQL/链路(第5章)
4. 提出假设: 是锁竞争? 内存泄漏? 慢调用雪崩? 依赖故障?
5. 验证假设: 针对性观测(火焰图/Arthas watch)/灰度验证
6. 止血+根治: 先临时止血, 再修复根因, 加监控防复发
```

### 6.5 高效治理脚本（本书列出的几把「瑞士军刀」）

| 脚本 | 用途 |
| --- | --- |
| show-busiest-java-threads | 找出 CPU 最高的 Java 线程，定位到栈 |
| find-in-jar / grep-in-jar | 在 jar 包里搜类/字符串，排查类冲突、版本问题 |
| jar-conflict-detect | 检测 classpath 下的类冲突（NoSuchMethodError 的元凶） |
| http-spy | 拦截/观察 HTTP 请求，看真实进出参数 |
| show-mysql-qps | 看 MySQL 实时 QPS/慢查询，定位数据库瓶颈 |

### 6.6 JVM 监控命令（应急第一箱）

- `jstack`：抓线程栈，看死锁/阻塞/热点；
- `jmap`：dump 堆，分析内存泄漏（配合 MAT/VisualVM）；
- `jstat`：看 GC 统计，判断是否 GC 频繁/Full GC 停顿；
- `jinfo`：看/改 JVM 运行参数；
- `jad`（Arthas）：反编译线上类，确认部署的代码版本。

## 版本演进

- **本书无第二版**；本节写 2017 年口径 → 2026 年视角的变化。
- **🔧 Arthas 成为 Java 诊断标配**：书里 6.6 还靠 jstack/jmap 手搓。2026 年
  `alibaba/arthas`（37557★）提供 `watch/trace/tt/jad/thread` 等命令，**在线诊断无需重启**，
  是本书脚本集合（6.5）的集大成者。
- **🔧 火焰图 + async-profiler**：书里靠经验看线程。2026 年用 async-profiler 出
  CPU/alloc/锁火焰图，几秒定位热点（见 [../性能之巅.md](../性能之巅.md)）。
- **🔧 eBPF 无侵入**：`bcc`/perf 在内核层抓系统调用/网络/文件，无需改代码（与第 4/5 章补丁同源）。
- **🔧 混沌工程演练**：书里谈被动应急；2026 年用 `pingcap/chaos-mesh`（7916★）、
  `netflix/chaosmonkey`（17151★）主动注入故障，把应急能力变成可演练的肌肉记忆。
- **🔧 可观测性闭环**：应急不再靠登机器敲命令，而是 **Grafana/APM 告警 → 链路下钻 → 日志**
  在控制台完成（见第 4/5 章）。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「先定位根因再恢复」 | **先止血**（重启/回滚/限流/降级），恢复后再查根因 |
| 2 | 「登机器敲 jstack 才专业」 | 现代应急在可观测控制台完成，登机器是最后手段 |
| 3 | 「重启能解决一切」 | 重启是止血不是根治；不查根因必复发，且可能掩盖证据 |
| 4 | 「告警都是误报」 | 海恩法则：小信号是事故先兆，必须追因 |
| 5 | 「加机器能解决性能问题」 | 先剖析（火焰图）定位瓶颈，可能是锁/GC/慢SQL |
| 6 | 🔧 本书 6.6 只列 jstack/jmap | 2026 年 Arthas(37557★) 在线诊断无需重启，是标配 |
| 7 | 🔧 本书 6.5 脚本靠手搓 | 这些脚本能力已被 Arthas/诊断平台产品化 |
| 8 | 🔧 本书缺火焰图/eBPF | 性能瓶颈定位从「看线程栈」升级到「火焰图/内核级观测」 |
| 9 | 🔧 本书谈被动应急缺演练 | 混沌工程主动演练，应急能力才能可靠 |
