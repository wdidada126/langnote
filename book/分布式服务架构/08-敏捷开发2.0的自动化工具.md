## 核心精讲

（以下为教学性梳理，伪代码/SQL 均**教学示意，不参与构建**。）

### 8.1 敏捷开发 2.0 与 DevOps

- **敏捷 1.0**：小步快跑、迭代、拥抱变化（Scrum/Kanban）。
- **敏捷 2.0 / DevOps**：把「开发→测试→部署→运维」的墙打通，**开发自己对自己的服务负责**
  （You build it, you run it），用自动化消弭手工交接的摩擦。
- **解决的痛点**：发布靠运维手工操作 → 易错、慢、不可回滚。

### 8.2 持续集成 / 交付 / 部署（CI/CD）

```text
# 教学示意，不参与构建
CI (持续集成):  代码提交 -> 自动构建+单测 -> 产出可部署产物(见第7章镜像)
CD (持续交付):  CI 通过后 -> 自动部署到测试/预发 -> 一键(或自动)上生产
CD (持续部署):  连生产也自动部署(需强测试+灰度+可回滚兜底)
区别: 交付=随时可发(人工点); 部署=自动发
```

## 版本演进

- **本书无第二版**；本节写 2017 年口径 → 2026 年视角的变化。
- **🔧 GitOps 成为声明式交付标准**：书里 8.3 的 Jenkins 自由风格任务偏「命令式」。2026 年主流是
  **GitOps**——把期望状态写进 Git，Argo CD/Flux 自动让集群收敛到该状态，审计/回滚都靠 Git 历史。
- **🔧 流水线即代码（Pipeline as Code）**：Jenkinsfile、GitLab CI YAML、Tekton 等把流水线
  纳入版本管理，与代码同生命周期。
- **🔧 K8s 原生交付**：部署目标从「机器 + SaltStack」变成「K8s 集群 + 声明式 YAML/Helm」，
  与第 7 章容器化闭环（见 [07-服务的容器化过程.md](07-服务的容器化过程.md)）。
- **🔧 DevSecOps / 安全左移**：镜像扫描、SAST/DAST、密钥管理嵌进流水线，而非上线前才查。
- **🔧 可观测性数据也进流水线**：发布后自动看 SLO/错误率（见第 3/4/5 章），异常自动暂停发布。

## 近年研究与工业界开源实践（2015–2026）

- **CI/CD 引擎（本书 8.3 本体）**：
  - `jenkinsci/jenkins`（26590★）、`saltstack/salt`（15677★）、`docker/docker`（72137★）、
    `git/git`（未单独核实 star，分布式版本控制事实标准），均为 2026-09 可核实或公认。
- **🔧 现代流水线/GitOps**：
  - Tekton、Argo CD、Flux（star 未逐一核实）实现流水线即代码与声明式交付；
  - GitHub Actions、GitLab CI 等托管式 CI 在 2026 年广泛使用。
- **🔧 与云原生闭环**：CI 产出镜像 → 推镜像仓库 → GitOps 同步到 `kubernetes/kubernetes`（128015★），
  与第 7 章容器化、第 1 章微服务交付形成完整链路。
- **🔧 发布策略工程化**：蓝绿/金丝雀/滚动更新由 Service Mesh（istio/istio 38408★）与
  K8s 原生支持，配合第 2 章迁移开关完成平滑发布。

## 常见误区与本书需修正之处

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | 「上了 Jenkins 就是 DevOps」 | DevOps 是文化+自动化+度量+共享，工具只是载体 |
| 2 | 「CI 就是自动编译」 | CI 必须含**自动化测试**，否则只是「能编译」 |
| 3 | 「持续部署 = 一直发生产」 | 视风险而定；多数用持续交付（人工点发），高风险才全自动 |
| 4 | 「SaltStack 管一切」 | 2026 年目标环境是 K8s 声明式，配置管理重心上移 |
| 5 | 🔧 本书 8.3 工具偏命令式 | 2026 年 GitOps/Pipeline-as-Code 把流程版本化、声明式 |
| 6 | 🔧 本书缺 GitOps | 期望状态存 Git、自动收敛，是 2026 年标准交付模型 |
| 7 | 🔧 本书缺安全左移 | DevSecOps 把扫描/密钥管理嵌进流水线，而非事后 |
| 8 | 🔧 本书缺发布可观测 | 发布后自动盯 SLO，异常自动暂停，应与第 3/5 章联动 |
