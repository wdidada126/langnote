# 03 · 相似度度量与向量空间（Similarity Metrics）

> 覆盖本目录主题结构第 3 章（⚠️ 主题构造，见 [00-总览与阅读地图.md](00-总览与阅读地图.md)）。度量函数是向量数据库里最小的"接口契约"：建库、建索引、查询三端必须用同一个度量，而度量之间在归一化前后会呈现完全不同的行为。本章 🔧 把"余弦=归一化内积=欧氏序同构"这三条等价律在小数据上逐条跑穿。

## 内容规格（小节地图，⚠️ 推定）

- **四大常用度量**：欧氏距离 L2、余弦相似度 cosine、点积/内积 IP、（汉明距离——服务于哈希向量，LSH 一节提及）。
- **几何关系**：单位球面上 cos θ 与弦长 d₂ 单调等价：`d₂² = 2 − 2·cos θ`；因此归一化后 L2 索引可原样服务 cosine 需求（生产引擎普遍这么偷换，HNSW/vss 都提供 `metric='cosine'` 但内部常按 L2 建）。
- **IP 的非度量性**：内积不满足三角不等式、受模长支配——"热门文档偏置"的根源；精确 top-k 内积检索需要 MIPS 变换或 NNS 落库（SparQ/角度传递一系算法 ⚠️ 定性转述）。
- **归一化策略**：写入时归一化（推荐）vs 查询时归一化 vs 不归一化存原始模长信息（长度当置信度/热度）——三种选择的工程后果。
- **度量与索引的兼容矩阵**：PQ/IVF 天然 L2 语义；图索引对度量几乎无要求（只要能比较距离）；LSH 超平面法天然 cosine（角度）。

## 核心技术清单

- cosine = `a·b / (|a||b|)`；IP = `a·b`；L2 = `√Σ(a−b)²`；L2² 与 cosine 在归一化域内**排序完全等价**（无需开方）。
- 单调变换不改 top-k：工程上索引内部多用"距离平方/负相似度"省开方。
- `array_cosine_distance` / `array_l2_distance` / `array_inner_product`（DuckDB vss 三件套 ✅ 官方文档 https://duckdb.org/docs/stable/extensions/vss.html 200 已验）。
- pgvector 的 operators：`<->`(L2) `<=>`(cosine) `<#>`(负 IP)，并各有索引用法（✅ README 转述，仓库 https://github.com/pgvector/pgvector 200 已验）。
- ES 的 `dense_vector` 只认 `cosine/dot_product/l2_norm/max_inner_product` 四种 similarity 参数（⚠️ 文档转述，URL 见下）。

## 🔧 实测：等价律与 IP 陷阱（玩具实现，非生产引擎行为）

数据同 01 章（10,000×64，DuckDB 生成）；top-10、100 查询；脚本 `exp_a.py` A2 段。

1. **归一化域等价律**：对每条查询分别在"L2 归一化后的库"上取 cosine-top10 与 L2²-top10——**100/100 条查询两个集合完全相等**。这就是"cosine 产品底下跑 L2 索引"合法性的机器证明。
2. **IP 陷阱**：在**未归一化**原始向量上，cosine-top10 与内积-top10 **100/100 不一致**——本数据集模长随簇中心幅度浮动，内积榜被大模长点霸榜；换成真实嵌入（文本长度/热度差异）同样成立。
3. **单点算术验证**（随手复算，非性能）：取一对向量手算 `d₂²` 与 `2−2cos`，浮点误差内相等——等价律的最小可复算证据。
4. **成本口径**：以上比较用的余弦实现与 01 章暴力一致（182.7 ms/q 纯 Python / 10.8 ms DuckDB SQL）——度量选择本身不改变复杂度，改变的是"哪些索引能用什么度量"。

## 易错点与陷阱

- **三端不一致**：建库用余弦、索引按 L2（未归一化！）、查询再套余弦——三者只在归一化后重合；任何一端忘归一化，结果悄悄变坏且不报错。
- **"dot_product 更快所以选它"**：快是省了归一化除法，语义却含模长权重——除非你**故意**想让热度参与排序（推荐系统常如此），否则用 cosine。
- **汉明只配二值/哈希向量**：把 float 向量强转 bit 再算汉明=信息毁灭；汉明服务的是 LSH/SQH 的签名空间（04 章）。
- **开方是浪费**：比较场景下一律用 d₂²（单调不变），生产实现全这么干，本玩具库亦然。
- **度量写进索引元数据**：换度量必须重建索引（pgvector/DuckDB vss 的 metric 都是建索引参数）——把它当 schema 的一部分管理。

## 度量×索引×产品对照表（把本章等价律投影到选型现场）

| 度量 | 天然适配索引 | 典型产品参数 | 归一化要求 | 一句话性格 |
| --- | --- | --- | --- | --- |
| cosine | 超平面 LSH、HNSW(metric=cosine)、IVF+内积胞心 | Qdrant `Cosine`、vss `metric='cosine'`、pgvector `<=>` | 必需或引擎内代做 | 只看方向，尺度免疫 |
| L2 | PQ/IVF 码本、HNSW、DiskANN | ES `l2_norm`、FAISS `IndexL2` | 无（但等价律要它） | 看绝对位置，量化系亲爹 |
| IP | 需 MIPS 化或球形变换；HNSW 直接跑不保证精确 | ES `dot_product`、Milvus `IP` | 禁（模长即语义） | 热度放大器 |
| 汉明 | LSH 签名、BHNSW、二进制 PQ | Milvus `HAMMING`、pgvector 二值索引 `<~>` | 先二值化 | 比特计数，最便宜 |
- 读法：左列锁"排序语义"，中列锁"能建什么索引"，第四列是 06 章产品对比时的对表键——三列都对上才谈调参。
- 本玩具库实测口径：cosine=L2²=IP(归一化域) 三者 top10 完全一致（实测 1 的 100/100 即其证据），所以 04/05 章各索引统一在"归一化+点积"一个坐标系里跑——生产同理，先把坐标系焊死再谈算法。

## 高维距离集中（为什么 d 变大后所有度量都变"迟钝"）

- 现象：d→∞ 时任意两点距离方差相对均值收缩——"最近邻"与"平均邻居"的差距消失，贪心/剪枝的信号变弱。
- 玩具侧证据：本数据 d=64 时暴力 top10 与第 11~50 名的余弦分差肉眼可分（01 章双实现一致）；把维度随机抬到 512（其余不动）会让 IVF/PQ 的候选内排序进一步失焦（定性推论 ⚠️，未单独跑）。
- 工程对策三连：训练侧降维/白化（OPQ 的旋转、PCA 到 128~256）、索引侧升 M/升 nprobe 换召回、架构侧换稀疏表示——三条都在吃"信息-速度"汇率。

## 新引擎接入时的度量契约测试（三条 SQL/三行代码，半天省一个月）

1. **等价律回归**：任取 100 条向量，库内 cosine 索引 top10 与"导出后纯代码 L2² top10"对拍——不相等即归一化链路有洞（本册 A2 就是该测试的玩具实现）。
2. **模长敏感探针**：构造一对"方向相同、模长差 10 倍"的向量入库：cosine 域应并列第一、IP 域应明确分先后——分不清=度量参数没生效。
3. **索引/暴力双跑**：同查询分别走 ANN 索引与全表暴力（关索引或 `SET enable_index=off` 类开关），统计 top10 重合率——这就是 08 章影子评测的最小形态。
- 三条都过，才允许团队在 schema 里写"metric: cosine"；不过，回去查 02 章的预处理器。
- 生产变体：pgvector 可用 `SET hnsw.ef_search`+同 SQL 暴力对拍（✅ 仓库 README 示例形态转述）；ES 用 `knn` vs `script_score` 全扫对拍（⚠️ 文档转述）——接口不同、姿势同源。

## 四度量公式与适用面一屏（抄写级速查）

| 度量 | 公式 | top-k 方向 | 归一化后 | 典型适用 |
| --- | --- | --- | --- | --- |
| L2² | Σ(aᵢ−bᵢ)² | 越小越像 | 与 cos 同序 | PQ/IVF 码本、图像特征 |
| cosine | a·b/(|a||b|) | 越大越像 | =IP | 文本句向量主流 |
| IP | a·b | 越大越像 | =cos | 热度/置信度语义保留 |
| Hamming | Σ[aᵢ≠bᵢ] | 越小越像 | — | LSH 签名、二值索引 |
- 实现注脚：本册玩具库把全库预归一化后，cosine 退化为一次点积——A2 的 100/100 就是这张表第二三行的实验形态。
- 陷阱重申：表中"归一化后"列仅在**库与查询同时**归一化时成立——半归一化比不归一化更危险（错得难以察觉）。

## 核心概念速览（中英对照）

- **欧氏距离** — L2 distance：几何直线距离，平方形式保序。
- **余弦相似度** — Cosine similarity：夹角余弦，尺度不变。
- **内积/点积** — Inner product (IP)：含模长信息，非度量。
- **汉明距离** — Hamming distance：二进制签名位差异数。
- **单调变换** — Monotone transform：不改 top-k 排序的函数复合。
- **MIPS** — Maximum inner product search：内积检索的专门问题类。
- **归一化域** — Normalized/spherical space：单位球面，cos↔L2 同构。
- **度量兼容矩阵** — Metric-index compatibility：哪个索引支持哪个度量。
- **halfvec/int8 量化** — 低精度存储下的度量保真问题。
- **签名空间** — Signature space：LSH 哈希位所在的空间，汉明适用。

- **产品侧度量面**：Qdrant（`distance: Cosine|Euclid|Dot|Manhattan`）、Milvus（IP/L2/Hamming/Jaccard 全家桶）、Weaviate（cosine 默认+dot/ l2）均为建集合时固定参数——"度量即 schema"是行业共识（⚠️ 各官方文档转述，仓库链接见 01 章演进节，均 ✅ 200）。
