# 02 · 向量嵌入：把世界变成坐标（Embeddings）

> 覆盖本目录主题结构第 2 章（⚠️ 主题构造，见 [00-总览与阅读地图.md](00-总览与阅读地图.md)）。嵌入是全书价值链的第一环："内容 → 向量"这一步的质量上限，决定了后面所有索引与产品的效果上限。本章 🔧 用纯标准库的词袋哈希嵌入把"嵌入=几何化"与"哈希=有损压缩"两个抽象讲透。

## 内容规格（小节地图，⚠️ 推定）

- **嵌入的直觉**：把文本/图像/音频映射到 R^d，使"语义相近 ⇒ 几何相近"；距离即相似度是全部后续算法的唯一前提。
- **从统计到神经**：共现矩阵/TF-IDF/LSA（前深度学习时代）→ word2vec/GloVe/FastText → 句向量（Sentence-BERT 系）→ 大模型嵌入 API（OpenAI text-embedding 系、Cohere、开源 BGE/GTE 系）。
- **向量属性**：维度（64~3072）、模长与信息含量（归一化与否决定 03 章度量选择）、稀疏 vs 稠密（SPLADE 一句带过）。
- **模型即接口**：换嵌入模型=换坐标系，旧向量全部作废——"嵌入版本管理"是工程一等公民。
- **多模态对齐**：CLIP 式图文同空间嵌入，为 07 章多模态检索埋线。

## 核心技术清单

- 上下文相关 vs 静态词向量（一词一向量 → 一句一向量）。
- 句向量训练目标：对比学习（相近对拉近、随机对推开）——理解这一点才明白"为什么余弦有效"。
- 维度与成本：ANN 的 O(N·d) 与索引内存都随 d 线性/超线性膨胀（08 章基准里 d 是隐变量）。
- 归一化：绝大多数文本嵌入输出建议 L2 归一化后存（cosine=点积，索引选择面最大）。
- 哈希嵌入（hashing trick）：不用词表、O(1) 内存的降级嵌入——本章玩具版主角。

## 🔧 实测：哈希词袋嵌入（纯标准库玩具实现，非神经嵌入、非生产行为）

语料=6 句自造英文短文本（猫垫子/狗公园/股市/汽车四类）；嵌入=`md5(词) % dim` 计数向量（稳定哈希，绕开 PYTHONHASHSEED 随机化）；脚本 `exp_e.py`。

1. **原始词袋余弦矩阵**：doc0="the cat sits on the mat" vs doc1="the cat is on the mat" 相似度 **0.875**（近义句），vs 股市句 **0.289/0.0**——"几何距离≈语义关系"的最初体验。
2. **碰撞可视化**：24 个不同词 → 128 维只占用 22 个桶：**2 对词碰撞**；换 256 维仍碰 2 次（本例巧合），这就是 hashing trick 的"维度↑碰撞↓但非消失"。
3. **TF-IDF+归一化后**：doc0 vs 近义 doc1=**0.482**（公共词 the/on 被 idf 压低是主因）；doc0 vs 无关句=**0.043**——不为 0 的那点分数正是第 2 条的碰撞噪声，"无关≠零距"在嵌入空间是常态。
4. **确定性**：同文本两次嵌入逐维相等 ✅——嵌入函数必须是纯函数，否则索引/查询两侧坐标系错位。
5. **规模感**：玩具 dim=128；生产中 OpenAI text-embedding-3-large 为 3072 维（可截断）、BGE 系 512~1024 常见（⚠️ 文档转述）——d 差 24 倍，01 章的暴力成本还要再乘 24。

## 易错点与陷阱

- **词形不回滚**：`cat` 与 `cats` 是两个桶（实测 3 中 doc2 分数归零的直接原因）——真实嵌入靠子词切分（BPE）缓解此问题。
- **忘存模型版本**：查询嵌入与库嵌入必须来自同一模型同一版本，否则相似度是噪声——库表里给每行带 `embedding_model_version` 字段是 2024 后的通行做法（⚠️ 社区共识，非本书原文）。
- **未归一化就建内积索引**：模长大的旧文档霸榜——03 章 IP 陷阱的成因在这章就埋下（存前归一化是最便宜的保险）。
- **把嵌入当数据库主键**：向量是"可模糊匹配的坐标"，不是等值键；业务约束（唯一性、外键）仍要放元数据列。
- **跨语言混存**：非专门训练的多语言模型下，中英同义句距离可以比英文近义词更远——混合语料要先验证模型的跨语对齐能力。

## 2026 视角补注

- 嵌入模型更替节奏：MTEB 排行榜（https://huggingface.co/spaces/mteb/leaderboard ）上名次半年一洗，但"向量维度膨胀+套娃表征截断（Matryoshka）"是 2024–2025 少见的与数据库直接相关的趋势——Matryoshka 向量让同一份嵌入支持 64/256/1024 维多档检索，直接改写了 04 章量化与 08 章成本模型（概念转述 ⚠️）。
- pgvector 官方 README 的用法示例即以 OpenAI 嵌入为输入（✅ https://github.com/pgvector/pgvector 200 已验），"模型在库外、向量在库内"仍是主流形态；库内直调模型（如 DuckDB/PG 的 http 扩展玩法）是边缘实践。

## 嵌入选型五问（换模型=换坐标系，所以选型是数据库决策不是 ML 决策）

1. **维度对钱包的影响**：raw 内存=N×d×4B；d 从 384→1536 是 4 倍存储+4 倍暴力打分。Matryoshka 模型允许"截到 512 维存、查询用 512、重排用 1536"——把第 1 问变成运营策略（截断后需重归一化，见补注）。
2. **度量约定**：模型卡说用 cosine 还是 dot？多数句向量模型训练目标即对比 cosine——存储侧归一化后两者等价（03 章实测一），不听话的模型会把全库排序带偏。
3. **上下文与指令前缀**：部分模型族（BGE/e5/instructor 系）要求 query 与 document 使用不同前缀——忘了加=用错坐标系，recall 断崖（社区高频坑，⚠️ 转述）。
4. **分词/子词边界语言覆盖**：中英混排/代码嵌入要选多语言或代码专训模型；用错语料训练的模型，"近义跨语言对"距离可能大于"无关同语言对"（02 章陷阱的模型侧）。
5. **服务面**：API 模型（版本停更、限流、价格漂移）vs 自托管开源模型（GPU 成本+升级重灌）——嵌入推理是"每次读写都要过的关键路径"，SLA 归数据库团队还是算法团队要预先说清。

## 向量列的数值解剖（存进数据库之前先看清它长什么样）

- **每维分布近似零均值小方差高斯**：训练后嵌入的直方图没有"整数字段"的结构——这解释了为什么 B-tree/等值索引对向量列完全无用，而"距离+剪枝"类结构（04/05 章）通吃。
- **维间强相关**：有效维度（PCA 谱衰减）常只有名义维度的 30~60%——随机投影 LSH（04 章）在低内在维度上表现更好；高内在维度（近白噪声嵌入）是所有索引的共同敌人。
- **模长语义**：归一化=丢弃模长信息；有些场景模长携带文档长度/置信度（03 章 IP 陷阱的另一面）——"要不要归一化"必须先问"模长有没有语义"。
- **稀疏向量对照组**：SPLADE 类学习型稀疏表示只在非零维有值，天然可解释、可借用倒排索引——与本章稠密向量是并行的两条嵌入路线（本册以稠密为主线）。
- **量化耐受度**：嵌入训练时若加了量化感知/噪声扰动，int8/binary 量化后掉点更少（⚠️ 定性转述）——"模型侧为存储侧让利"是 2024+ 的新接口。

## 🔧 追加实测：为什么哈希嵌入只当教具（玩具实现，非生产行为）

1. **可分性对照**：本章 6 句语料里"近义句对 0.875 / 无关句对 ≤0.401"有清晰分层（实测 E1）；但把语料换成同主题长文档，词袋余弦立即挤在 0.7~0.95 窄带——**统计嵌入的分辨率随语料变难而塌缩**，神经嵌入（对比学习训练）正是为这个区间而生。
2. **碰撞税**：E2 实测 24 词/128 桶已碰 2 对——生产词表十万级时 128~512 维哈希桶的碰撞会系统性地给无关词"拉近"；维度每翻倍碰撞减半是粗糙直觉，生日悖论下真实衰减更快。
3. **确定性纪律**：E5 的"同文本两次嵌入逐维相等"在改用内建 `hash()` 后立刻失效（跨进程随机盐）——**嵌入函数任何非确定性都会让"库内向量 vs 查询向量"来自两个坐标系**；本玩具为此专门换成 md5 稳定哈希，一行代码换来可复现，工程含义放大到生产即"模型版本+前处理版本双锁定"。

## 嵌入服务的工程形态（读写两端的 pipeline 才是难点）

- **写路径**：原文→（清洗/切块）→嵌入推理→归一化→（向量+元数据+模型版本）落库。峰值瓶颈几乎总在嵌入推理（GPU/CPU 批推理吞吐），不在向量插入——扩容先扩推理。
- **读路径**：查询→同一前处理（指令前缀/语言检测）→嵌入→KNN。写读两侧共用一个"预处理器"对象是最低安全配置；两侧各写一份预处理代码=未来事故报告上的两行。
- **批式重灌**：换模型/换切块=全量重嵌入。通行做法是双库蓝绿（新旧坐标系各一库+别名切换），Milvus 别名/Pinecone 双 index/手工 PG schema 切换皆此形态（⚠️ 文档转述）。
- **增量一致性**：原文被改，向量必须同事务窗口内更新——向量与元数据"半更新"状态会让新旧坐标系混排（03 章等价律瞬间失效）。
- **成本结构**：嵌入推理一次、检索每查询一次——"写时计算、读时复用"决定了读多写少场景嵌入费用占比低；反过来流式高频写场景，嵌入服务就是主成本项（06 章写读画像的由来）。
- **可观测性三件套**：嵌入延迟分位、归一化前后模长分布（数据漂移探针）、查询-文档嵌入距离直方图（分数分布突变=坐标系或模型出事的早期信号）。

## 嵌入与降维/量化的关系（第一张多米诺骨牌）

- 嵌入的"有效维度"低于名义维度（3 章距离集中的另一面）→ 降维/白化（PCA、OPQ 旋转）几乎无损——这是 04 章量化能活着的先决条件。
- Matryoshka/截断思路=模型训练时主动制造"前缀可用"的维度嵌套：检索用低维档、重排用高维档——**一次嵌入多档工作点**，把 08 章"曲线"部分前移进了模型侧。
- 二值化（sign bits）是截断的极限形态：每维 1 bit，汉明距离替代浮点打分（03/04 章谱系）；训练侧加 quantization-aware 损失的模型掉点明显更小（⚠️ 定性转述）——**压缩预算要从"选模型"就开始花，而不是到索引层才想起来**。

## 嵌入层常见误解纠偏（读者自检五题的答案页）

1. **"维度越高越准"**：分辨率与信息两回事——2048 维噪声嵌入打不过 384 维精调嵌入（MTEB 同代模型的常识）；先选对训练目标，再谈维度。
2. **"相似度是概率"**：cosine 0.86 不意味着"86% 相关"——分数只在同一模型同一分布内可比，跨模型不可解释（08 章阈值都必须自校准的根因）。
3. **"嵌入一次训练终身受益"**：语料与查询词汇随业务演化，分数分布漂移先于 recall 崩塌出现——2 章"可观测三件套"就是给这件事装烟雾报警器。
4. **"向量可以当特征塞进任意模型"**：向量空间的方向语义只对相似度检索有意义；直接喂给树模型常常不如回到原始特征（经验之谈 ⚠️）。
5. **"开源模型自建最省钱"**：万级文档、日查询百次的规模，任何自建都是负资产——先 API/库内推理，规模逼迁时再算 TCO（06 章决策树第 3 问）。

## 核心概念速览（中英对照）

- **嵌入** — Embedding：对象到定长实数向量的保语义映射。
- **词袋** — Bag of words：忽略词序的计数表示，本章玩具基底。
- **哈希技巧** — Hashing trick：md5 取模代替词表 ID，O(1) 内存、有碰撞。
- **TF-IDF** — 词频×逆文档频率加权，压低 `the` 类通用词。
- **子词/BPE** — 词形切分，缓解未登录词与词形变化。
- **句向量** — Sentence embedding：一段文本一个向量。
- **对比学习** — Contrastive learning：拉近正样本对、推开负样本对的训练目标。
- **多模态对齐** — CLIP 式图文同空间。
- **Matryoshka 嵌入** — 套娃维度截断，一库多用。
- **嵌入版本漂移** — Embedding drift：模型更新导致新旧向量不可比。
