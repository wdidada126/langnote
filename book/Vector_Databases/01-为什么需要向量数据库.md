# 01 · 为什么需要向量数据库（Why Vector Databases）

> 覆盖本目录主题结构第 1 章（⚠️ 主题构造，非原书实章清单，取证声明见 [00-总览与阅读地图.md](00-总览与阅读地图.md)）。本章回答三问：非结构化数据为什么"进不了"传统检索？嵌入把语义变成了什么几何对象？以及"最近邻为什么必须索引"——本章 🔧 用 10,000×64 玩具数据集把暴力检索的代价量出来。

## 内容规格（小节地图，⚠️ 按公开简介与通行教材结构推定）

- **从关键词到语义**：LIKE/BM25/倒排对"意思相近"无能为力；同义、改写、多语言、图片音频都要求按"语义距离"检索。
- **AI 数据基础设施**：LLM 时代三件套——嵌入模型（向量化）、向量数据库（存与找）、RAG（用）。本书副标题 "From Embeddings to Applications" 即这条价值链（✅ 书名/主题域与 O'Reilly 官方书目描述一致，见 00 取证）。
- **精确最近邻的代价**：无索引时每次查询 O(N·d)；规模 × 维度 × QPS 三者相乘就是墙。
- **向量数据库 = 数据库**：它不只是索引库——schema、元数据过滤、增删、副本分片、多租户、运维 SLA 一个不少（后续 06/07 章展开）。
- **与相近概念的边界**：全文检索（ES）、知识图谱（Neo4j）、缓存（Redis）都有相似检索能力，本书立场是"专用引擎 + 向量原生存储格式"。

## 核心技术清单

- 相似检索（similarity search）≈ ANN（approximate nearest neighbor）：接受召回率换延迟/内存。
- 度量族：余弦/内积/L2（03 章）、汉明（哈希向量）。
- 索引族全景（本书及全系列的骨架，先给地图）：
  - 倒排聚类类：IVF / IVFADC（FAISS 血统）→ [04-ANN索引之一-哈希与量化.md](04-ANN索引之一-哈希与量化.md)
  - 量化压缩类：PQ / OPQ / SQ → 同上
  - 哈希类：LSH 及其现代变体 → 同上
  - 图类：NSW → HNSW → DiskANN/Vamana → [05-ANN索引之二-从NSW到HNSW.md](05-ANN索引之二-从NSW到HNSW.md)
- 评测三坐标：recall@k × QPS × 内存（08 章，与 ANN-Benchmarks 论文口径对齐）。
- 生产数据集血统：SIFT1M、GIST、Deep1B、SBS/GIST 系基准（ann-benchmarks.com ✅）。

## 🔧 实测：暴力检索到底多贵（玩具实现，非生产引擎行为）

环境：Python 3.13.2 标准库（无 numpy）+ DuckDB 1.5.5（Python 包）；数据=DuckDB 生成 10,000×64 维、60 簇高斯玩具向量集（`vgen.py`，脚本在 `D:\develops\tmp\dbwave_w3_vectordb\`）；查询 100 条（从库内点扰动生成）；top-10。

1. **纯 Python 暴力余弦 KNN**：平均 **182.7 ms/查询（QPS≈5.5）**，100 查询对 DuckDB 独立算出的暴力 ground truth **recall@10=1.000**——两套独立实现（Python list 循环 vs DuckDB 向量化 SQL）排序完全一致，先给"正确性锚点"，后面的 ANN 都拿它当考卷。
2. **DuckDB SQL 暴力**（`SELECT id FROM points ORDER BY list_cosine_similarity(v, ?) DESC LIMIT 10`）：单查询 warm 首条 **10.8 ms**；参数化循环 20 条 **60.9 ms/q**（含每查询全表 DOUBLE[]→函数逐列计算）。同机器同数据，**引擎向量化执行 ≈ 纯 Python 的 3–16 倍**——但仍是 O(N)：数据到 1 亿条时这两行都会变成分钟级，这就是 ANN 索引存在的理由。
3. **规模外推（算术，非实测）**：10k→1M→100M 线性外推，Python 暴力单查 182 ms→18 s→30 min；即使 DuckDB 的 10 ms 档，100M 也是 100 s/查询——暴力=正确但不可上线，与 ANN-Benchmarks 论文"exact NN 只做 ground truth"的定位一致（→ [../../paper/ANN-Benchmarks-%20A%20Benchmarking%20Tool%20for%20Approximate%20Nearest%20Neighbor%20Algorithms__1807.05614/00-精读笔记.md](../../paper/ANN-Benchmarks-%20A%20Benchmarking%20Tool%20for%20Approximate%20Nearest%20Neighbor%20Algorithms__1807.05614/00-精读笔记.md)）。

## 易错点与陷阱

- **"向量数据库=FAISS"**：FAISS 是索引库（无持久化/无过滤一致性保证/无分布式），本书讨论的是带数据库语义的产品——这一辨析在 06 章产品图谱再展开。
- **拿玩具规模下结论**：本章 1 万条、64 维的一切数字都不可外推到生产的千万级/1536 维；量级感受≠容量规划。
- **先选索引再选度量**：度量（余弦/内积/L2）决定索引能用什么（例：PQ 的 ADC 是 L2 语义），顺序反了要返工。
- **recall 分母没锚定**：所有"召回率 0.97"必须先说清 ground truth 怎么来的（本章=DuckDB 暴力），否则数字无意义（08 章评测方法）。
- **忽略过滤条件**：真实查询几乎都带 WHERE（租户 id、时间范围），纯 KNN benchmark 与生产体感的差距在 07 章实测。

## 2026 视角补注

- "数据库内向量"已成 2024–2026 主战场：SQL Server 2025 原生 `VECTOR` 类型、Oracle 23ai AI Vector Search、PostgreSQL+pgvector、Elasticsearch dense_vector knn（各官方文档见 03/06 章演进节 ✅ 链接已验）——本章"通用数据库 vs 专用引擎"的问题意识正是当下格局的预演。
- 嵌入模型代际更替极快（MTEB 榜单 https://huggingface.co/spaces/mteb/leaderboard 定性 ⚠️），但"向量+ANN+过滤"的数据库抽象保持稳定——读本书应重算法与架构、轻具体模型名。

## 复杂度与成本模型（把本章实测折成三条公式）

- **在线公式**：`查询成本 ≈ 命中字节数 × 每维每次打分成本`。暴力命中全库（10k×64×4B≈2.5 MB）；ANN 索引把命中字节压到 1/k 量级，代价是召回率税。
- **离线公式**：`内存 ≈ raw(N·d·4B) + 索引结构 + 标量元数据`。64 维玩具里 raw 才 2.5 MB、索引结构反而更贵——**小数据下 ANN 是负优化**，这解释了为什么 DuckDB/嵌入式路线在万级~十万级规模活得很好（06 章）。
- **外推公式（算术，非实测）**：01 章暴力 171 ms@10k → 每千条 ≈17 µs；100 万条 ≈17 s、1 亿条 ≈2850 s/查询（纯 py 口径）。DuckDB 列式 10 ms@10k → 亿级仍要 100 s 量级——**常数改善救不了线性项**，这是全书存在的数学前提。
- 三轴预算：延迟轴（ANN 索引）、字节轴（量化，04 章）、正确性轴（重排池，04/07 章）——任何产品参数都能归到这三轴之一，读 06 章前先装好这个压缩包。

## 辨析五连（本章概念最容易混的边界）

1. **相似检索 vs 全文检索**：前者比较连续几何距离（可近似、可截断），后者比较离散词项匹配（布尔可判、可解释）；混合检索=两者并联（07 章），不是互相替代。
2. **相似检索 vs 聚类**：聚类是离线无监督分组（训练查询不可知），IVF 的 k-means 只是"给检索用的分区"——目标函数一样，KPI 完全不同（分组纯度 vs 胞均匀度/边界损失，04 章实测可见）。
3. **ANN 引擎 vs 向量数据库**：faiss/hnswlib/scann 提供 `build/search`，不提供持久化、过滤一致性、WAL、多租户、副本——本册 06 章的全部讨论都发生在这条线以下。
4. **近似 vs 随机**：ANN 对同一查询可返回稳定结果（确定性图遍历），"近似"指放弃精确 top-k 而非引入随机性；随机化只来自 LSH 的哈希种子与训练采样（04 章）。
5. **召回率 vs 精度**：top-k 检索里两者退化为 recall@k 与"命中集合内真近邻占比"——k 固定时一体两面；RAG 场景另加"答案正确率"这第三层（07/08 章分层归因用）。

## 向量工作负载画像（后续章节反复引用的三张"形状"）

- **写少读多**：文档库/知识库——索引可以重、查询要快，HNSW 全内存合理（05 章）。
- **写读各半流式**：风控特征/日志近重复——段模型+延迟索引化是刚需，LSM 思想回归（06 章）。
- **强过滤中召回**：多租户+权限+时间窗——纯 KNN benchmark 全部失真，07 章实测 3 种姿势的差距就是这一画像的预算表。
- 读法：任何"X 库比 Y 库快 30%"的宣称，先问它属于哪张形状——形状不同的评测互相打架是常态而非异常。

## 一个向量的旅程（本册章节的心智主线）

1. **出生**（02 章）：一段文本/一张图过嵌入模型，得到一个 768 维浮点数组；出生证上写着模型名+版本+度量约定。
2. **落户**（03 章）：归一化、定度量——决定它今后"跟谁近"的坐标系规则；入库那一刻规则焊死。
3. **编网**（04/05 章）：索引把它连进倒排胞/哈希桶/近邻图——从此查询不再遍历全村，只走"路"。
4. **上班**（06/07 章）：查询向量持同款出生证入场，带着 WHERE 条件在索引上贪心/扫桶，top-k 出去拼进 LLM 提示词。
5. **体检**（08 章）：影子查询与对拍持续估它的召回率；模型换代=全城拆迁重灌（02 章版本漂移的回旋镖）。
- 用法：读任何一章前先定位"在讲旅程的第几步"——产品评测吵翻天的一半原因，是各方站在不同步上比同一件事。

## 核心概念速览（中英对照）

- **向量嵌入** — Vector embedding：把对象映射为定长数值向量，距离≈语义差。
- **相似性检索** — Similarity search：按距离而非精确匹配取回 top-k。
- **精确最近邻** — Exact nearest neighbor (brute force)：O(N·d) 全量扫描，只做基准。
- **近似最近邻** — Approximate nearest neighbor (ANN)：以召回率换速度/内存的索引检索。
- **召回率** — Recall@k：ANN 前 k 命中真前 k 的比例。
- **QPS/延迟** — Throughput/latency：ANN 评测的另两轴。
- **元数据过滤** — Metadata filtering：WHERE 条件与 KNN 的组合语义（07 章）。
- **度量** — Metric/distance：cosine、L2、IP、hamming 等打分函数。
- **基准数据集** — Benchmark dataset：SIFT/GIST/Deep1B 等带 ground truth 的数据。
- **RAG** — Retrieval-augmented generation：向量检索作为 LLM 的外置记忆。
