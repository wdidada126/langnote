# 第 20 章 秒杀系统架构

> 高并发大流量典型场景：秒杀架构——动静分离、CDN、缓存预热、库存防超卖、限流（令牌桶/漏桶）、削峰（MQ）、降级、热点隔离。本书收尾，把并发原理升到系统架构层。与尼恩 14/15 章、之美 concepts 互补。

## 一、核心精讲

### 20.1 🔧 分层防护
- 前端：按钮置灰 + 验证码 + 限频；接入层：CDN 静态化 + Nginx 限流；服务层：本地缓存 + Redis 预减库存；数据层：MQ 削峰异步落库（🔧 逐层拦掉流量，只让少量请求到 DB）。

### 20.2 防超卖
- Redis 原子 `DECR`（库存预判）+ 数据库乐观锁/`UPDATE ... WHERE stock>0` 最终扣（🔧 幂等去重防重复下单）。

### 20.3 限流降级
- 令牌桶（Guava `RateLimiter`/Sentinel）、漏桶；熔断降级（🔧 Sentinel（阿里，stars 21k）/Resilience4j（9.6k））。

## 二、版本演进 / 论文 / 前沿

- 论文/文献：令牌桶/漏桶（Turner 1986）；Sentinel/Resilience4j 实践。
- 工业界：Sentinel（21k）、Redisson、RocketMQ（22k 削峰）、Redis（69k）。
- 开源 stars（2026-09）：redis 69k / rocketmq 22k / sentinel 21k.

## 三、常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "靠 DB 扛秒杀" | 逐层拦 + MQ 削峰 |
| 2 | "Redis 扣完即终态" | DB 乐观锁兜底防超卖 |
| 3 | "不限流" | 令牌桶/Sentinel 限流 |
| 4 | "重复下单不去重" | 幂等键去重 |
