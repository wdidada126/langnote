# 第 19 章 分布式锁架构

> 单机锁（`synchronized`/`ReentrantLock`）跨 JVM 失效 → 分布式锁：Redis（`SETNX`/Redlock）、ZooKeeper（临时顺序节点）、数据库（唯一索引/乐观锁）。本书从架构层讲选锁与可靠投递。与尼恩 13/14 章、之美 concepts 互补。

## 一、核心精讲

### 19.1 🔧 三种实现对照
- **Redis**：`SET key value NX PX ms` + Lua 解锁（防误删）+ 续期看门狗（🔧 快，但主从切换可能失锁；Redlock 争议：Martin Kleppmann 质疑其时钟依赖）。
- **ZooKeeper**：临时顺序节点 + 前驱监听（🔧 CP 可靠，防误删；吞吐低，见尼恩 13 章）。
- **数据库**：唯一索引/乐观锁版本号（🔧 简单但 DB 压力大，非高并发首选）。

### 19.2 关键坑
- 锁过期但任务未完（续期）；误删他人锁（value 校验）；不可重入（Redisson 可重入）。

### 19.3 选型
- 高频/允许偶失 → Redis（Redisson）；强一致/低频 → ZK/etcd（🔧 etcd Raft，见尼恩 13 章）。

## 二、版本演进 / 论文 / 前沿

- 论文：Lamport 面包店算法（1974）；Redis `SETNX` 官方分布式锁文档；Redlock（antirez 2016）与 Kleppmann 反驳（2016）；Raft（Ongaro 2014）。
- 工业界：Redisson（24k）、Curator（ZK 锁）、etcd（48k）。
- 开源 stars（2026-09）：redis 69k / redisson 24k / etcd 48k / zookeeper 12k.

## 三、常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "Redis 锁绝对可靠" | 主从切换失锁；强一致用 ZK/etcd |
| 2 | "不校验 value 就删" | 误删他人锁 |
| 3 | "锁过期任务必完" | 需续期看门狗 |
