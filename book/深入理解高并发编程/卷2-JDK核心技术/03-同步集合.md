# 第 3 章 同步集合

> `Vector`/`Stack`/`Hashtable` 与 `Collections.synchronizedXxx` 同步包装器，以及它们的缺陷（全表锁、迭代需手动同步、复合操作仍不安全）。本书「先讲被淘汰方案」再引并发集合，是很好的认知铺垫。

## 一、核心精讲

### 3.1 🔧 同步集合的缺陷
- `Vector`/`Hashtable` 每个方法 `synchronized`，**全局一把锁** → 吞吐低（🔧 JDK 早期遗留；现代用 `ArrayList`/`HashMap` + 外部同步，或并发集合）。
- 同步包装器迭代仍需手动 `synchronized(map)`，否则 `ConcurrentModificationException`。
- 复合操作（`check-then-act`，如 `if(!map.containsKey(k)) map.put(...)`）即使单方法安全也仍竞态（🔧 用 `ConcurrentHashMap.putIfAbsent`）。

## 二、版本演进 / 论文 / 前沿

- 文献：JDK 1.0/1.2 遗留集合；JSR 166 引入 `java.util.concurrent` 取代。
- 工业界：`ConcurrentHashMap`（JDK8+ 桶级锁）、Caffeine。
- 开源 stars（2026-09）：JDK 23.4k / caffeine 17.9k.

## 三、常见误区

| # | 误区 | 修正 |
| --- | --- | --- |
| 1 | "Vector 线程安全就够" | 全局锁，吞吐低 |
| 2 | "包装器迭代安全" | 需手动 synchronized |
| 3 | "单方法安全=复合安全" | 用 putIfAbsent |
