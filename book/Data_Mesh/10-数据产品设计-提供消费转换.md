# 第 12 章 Design Providing, Consuming, and Transforming Data（设计数据的提供、消费与转换）

> 机工中译第 12 章「设计数据的消费、转换和服务」。小节 ✅ 实抓：Providing Data / Consuming Data / Transforming Data / Recap。本章是全书最"工程"的一章：数据产品接口与管道的形态学。

## 1. 三动词框架：提供 / 消费 / 转换

每个数据产品的运行时被拆为三个可独立演化的关注面：
- **Providing（提供）**：产品把数据以什么接口对外承诺（出口 ports）；
- **Consuming（消费）**：产品作为消费者从他产品取数（入口 ports）；
- **Transforming（转换）**：入口到出口之间的加工逻辑（产品的"内核"）。
六边形架构（ports & adapters）被明确援引：**转换逻辑与接口适配彼此隔离**，同一内核可同时供应批快照、流变更、SQL 视图多种出口——这是"多态政策/多形态接口"在单产品尺度的实现方式。

## 2. Providing Data（提供接口形态学）✅

她列举并比较接口族（⚠️ 细节按通行术语重构）：
- **批量数据集**（文件/表：Parquet/Iceberg 类开放格式，snapshot + time travel 语义）；
- **流**（append-only 主题/CDC 变更流，消费位点语义）；
- **查询服务**（SQL 端点、API、GraphQL——低延迟小负载）；
- **嵌入式/物化视图**（为特定消费者拉取式就近部署，跨域大查询的反制）。
设计要点：**接口选择=对消费者旅程承诺的翻译**，不是技术偏好；同一产品多接口并存时，契约按接口分别声明（新鲜度、顺序、一致性语义各异）。
物理层选型今天直接查 [Practical_Lakehouse_Architecture](../Practical_Lakehouse_Architecture/03-存储湖仓架构的核心.md) 与 [Use_Iceberg_with_Spark](../Use_Iceberg_with_Spark/)（落盘自检确认目录版存在后保留本链）。

## 3. Consuming Data（消费侧设计）

- 消费的默认姿势应是**声明假设**（schema/新鲜度/顺序依赖写清楚）而非默认信任——把"隐式依赖"变成"显式契约校验"，第 5 章政策关卡才有执行面。
- 跨接口消费模式：推拉权衡、事件驱动 vs 定时批、断点恢复/幂等要求（与 DDIA 流处理章的术语完全可互译，见 [设计数据密集型应用](../设计数据密集型应用/11-流处理.md)）。

## 4. Transforming Data（转换逻辑设计）

- 转换应可重放、可回滚、分区可补（backfill 是一等设计约束而非运维事故）；
- 声明式/数据即代码：转换逻辑 + 接口定义 + 契约同仓版本化；
- 编排归编排平面（第 10 章），产品内核不背跨产品调度的责任。

## 5. 🔧 契约与 schema 演进的本地最小演示（思想演示，⚠️ 非原书实验）

> 原书无代码；本节用 DuckDB（本机 Python duckdb 1.5.5 实跑 ✅）演示本章"接口承诺 + 兼容性"的概念机制。脚本：`D:\develops\tmp\dbwave_mesh\dp_contract_demo.py`（repo 外零产物）。编排侧本应配 Dagster 类工具做契约检查钩子，⚠️ 本环境未装未跑，仅作概念指位。

演示内容与输出（✅ 实跑结果摘录）：
1. 发布 `sales.orders` v1.0.0：schema（order_id INTEGER, domain VARCHAR, amount DECIMAL(4,1), order_date DATE）+ 接口声明，生成契约摘要 `schema_digest`（sha256 前 12 位）；
2. 消费者带摘要读取：`consumer v1: [('sales', Decimal('125.5'))]` —— 校验通过才消费；
3. **加法演化** `ADD COLUMN channel` → 摘要变、旧列无损：语义上 minor bump（1.1.0）兼容，但演示同时显示**严格全 schema 哈希**会误伤老消费者（`old consumer (strict full-schema hash) FAILS -> ... use subset/wa1 compatibility`）——即工业 schema 注册表演进检查用**宽进严出/子集兼容**（reader/writer schema 对，BACKWARD/FORWARD/FULL 模式）而非整表哈希的原因；
4. **破坏性演化** `RENAME COLUMN amount` → 检出"被删列 `{amount}`"，必须 major bump（2.0.0）且**不得原地替换 v1 接口**，新旧接口并行供应一段窗口。
结论（🔧 实测支持的概念点）：兼容性判定=「旧消费者假设 ⊆ 新接口供给」的集合关系，可完全机器化——这正是第 5 章"计算治理"与本章"接口契约"的交点，也与 [设计数据密集型应用](../设计数据密集型应用/04-编码与演化.md) 模式演化三模式（writer-reader 等）互证。

## 接口形态对比表（§2 形态学速查 ⚠️ 细节按通行工程术语补充）

| 接口 | 语义承诺 | 新鲜度 | 适配场景 | 契约校验点 |
|---|---|---|---|---|
| 批数据集（表/文件+快照） | 一致性视图、time travel | 小时~天 | BI 聚合、训练集 | schema 兼容、行数/空值率断言 |
| 流（append/主题/CDC） | 顺序、位点、exactly-at-least-once | 秒~分 | 事件驱动下游、镜像 | 顺序假设、schema 注册表 |
| 查询服务（SQL/API） | 低延迟点查与谓词下推 | 实时 | 应用集成、探索 | 配额、模式响应 |
| 物化/嵌入式 | 就近、预聚合 | 按刷新策略 | 大 join 反制、边缘消费 | 刷新 SLA、缓存失效 |
关键论点（书内）：**选择接口=承诺翻译**；表内"契约校验点"列即 🔧 演示中摘要/集合判定可机器化的对象。

## 兼容性规则速记（与工业注册表对齐 ⚠️ 转述 + 🔧 演示佐证）

- Writer→Reader 演化六模式（DDIA 术语）：可选字段新增=双向后兼容；删必填字段=破坏；语义改名=破坏（等同删+增）；类型放宽（int→long）多数引擎兼容、需声明；约束收紧（nullable→非空）对写入方破坏；默认值变更=语义破坏（结构兼容最具欺骗性）。
- 🔧 演示复现的两条判定：全 schema 哈希过严（误伤加法演化）、**列集合包含判定**过松（漏语义变更）——工业解法是 reader/writer 双向 schema 对 + 人工语义评审兜底（默认值/口径变更走 major，规则外）。
- 版本并行窗口策略：major 变更时 v1/v2 共供 ≥ 一个消费者迁移周期；目录上以"弃用倒计时"公开（第 14 章生命周期）。

## 常见疑问（FAQ）

**Q1：ports/adapters 会不会导致适配代码爆炸？**
A：会，且书内承认这是自治的代价；平台脚手架的适配器模板库把成本压成配置（§6 工程化方向）。
**Q2：流和批要不要统一成"一个表"（Kappa/lakehouse 路线）？**
A：她保持多接口并列（承诺按接口分别声明）；Iceberg 类"批流同表"是物理收敛，承诺面仍需分开——两层不矛盾。
**Q3：契约测试消费者要配合写代码吗？**
A：理想态（消费者驱动契约）要；现实中多以"假设声明表 + 平台回放"替代（机制对照 [设计数据密集型应用](../设计数据密集型应用/04-编码与演化.md)）。
**Q4：转换逻辑放内核还是编排平面？**
A：逻辑本体在内核（产品自治），调度与依赖解析在编排平面（§4/第 10 章分工）；把转换拆到编排器是"伪产品化"高发区。
**Q5：🔧 演示能当生产方案吗？**
A：不能——它只证明兼容性判定的可机器化性质；生产需注册表持久化、双向 schema、历史版本保留与回滚（工程清单见演进节工具）。
**Q6：产品内核能直接读别产品的存储吗？**
A：不能——消费只走声明接口（第 9 章共享接口的产品内化）；直连他域表是 mesh 判定"耦合违规"的第一信号，应在关卡 lint 中拦截（🔧 演示的 manifest 即可 lint 对象）。

## 核心概念速览（中英对照）

- **提供-消费-转换** — Providing / Consuming / Transforming：产品运行时的三关注面切分。
- **端口与适配器** — Ports & Adapters：内核与接口隔离的六边形架构移植。
- **出口接口族** — Output Interface Families：批数据集/流/查询服务/嵌入式物化。
- **假设声明** — Declared Assumptions：消费侧显式写出 schema/新鲜度/顺序依赖。
- **可重放** — Replayability：转换可从源重建目标的能力约束。
- **补数一等公民** — Backfill as First-class：回填纳入设计而非运维事故。
- **契约摘要** — Schema Digest：接口结构的可校验指纹（🔧 演示）。
- **子集兼容** — Subset / WA1 Compatibility：兼容性=旧假设⊆新供给的集合判定（🔧 演示）。
- **宽进严出** — Reader/Writer Schema Pair：读写模式分离的演进机制（🔧 概念对照）。
- **大版本并行窗口** — Major Version Coexistence：破坏性变更时新旧接口共供期（🔧 演示）。
- **数据即代码** — Data as Code：转换+契约+定义同仓版本化。
- **幂等消费** — Idempotent Consumption：位点恢复不重复不丢失（DDIA 术语桥）。
