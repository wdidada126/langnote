# 第 5 章 Principle of Federated Computational Governance（联邦计算治理原则）

> 机工中译第 5 章。小节 ✅ 实抓：Apply Systems Thinking to Data Mesh Governance / Apply Federation to the Governance Model / Apply Computation to the Governance Model / Transition to Federated Computational Governance / Recap。本章是四原则里最抽象、也最容易被 implementations 偷工的一章。

## 1. 治理问题的重新定义

- 她先拆掉两个旧答案：**中心化治理委员会**（审批制、瓶颈、与域现实脱节——EDW 时代遗产）与**无治理自治**（域各建各的，网络互操作性坍塌——"数据封建化"）。
- 新定义：治理 = **在保持域自治的前提下，最大化跨域互操作性的决策机制**。关键词是"最大化"而非"统一"：接受一定异质性，换取全局可组合性。
- 控制论框架：用**调节回路（feedback loop）**而非**审批回路（approval loop）**思考——政策效果要可观测、可回摆（这与其反复引用的 Cybernetics / Stafford Beer 谱系一致，⚠️ 转述其思想来源段）。

## 2. Apply Systems Thinking（系统思维）

- 把"数据网络"看作复杂适应系统的治理对象：局部规则通过全局涌现影响彼此，故政策需**内插自治**（interpolated autonomy）——自治程度是全局变量，按风险连续调节，而非全有全无。
- 三个政策作用面（后两节展开）：全局互操作政策、域本地政策、数据产品政策。

## 3. Apply Federation（联邦制）✅ 小节名，内容 ⚠️ 重构转述

- 联邦治理体（global federation）由各域代表 + 平台团队 + 治理专家组成，职责是**制定全局政策集并持续调节**，不是逐表审批。
- 政策三层结构：
  1. **全局政策（global）**：跨域必须一致的少数硬约束——身份与访问模型、互操作标准（语义协议/接口协议）、隐私与安全底线、合规；
  2. **域政策（domain）**：域内自由裁量（建模规范、质量门槛、生命周期）；
  3. **产品政策（product）**：单产品对用户承诺的契约面（SLA、许可条款）。
- "联邦"的组织学含义：域派员入联邦、联邦无常驻官僚规模上限——避免治理中心自身膨胀成新瓶颈；此机制多家公司实践变形为"数据治理虚拟委员会 + 政策即代码仓库"（⚠️ 实践观察转述）。

## 4. Apply Computation（计算化）——本章真正的创新点

- 主张：**政策不落成代码就等于没有政策**。计算治理 = 把三层政策实现为可执行工件，嵌入平台横切层：策略引擎、自动合规检查、合约校验、访问决策。
- 政策的三种计算形态（⚠️ 术语转述）：**automated（自动化执行，如访问控制/格式校验）/ audited（审计型，如定期扫描）/ hedged（对冲型，如实时质量预算熔断）**。
- **多态政策（polymorphic policy）**：同一意图（如"个人信息保护"）在批产品/流产品/不同引擎上有不同机器实现，全局政策只管"验证通过与否"，不管实现——这是 she 对"标准化 vs 自治"张力的关键技术回答。
- 治理即产品（governance as a product）：政策能力以平台服务方式向域团队提供，配指标（合规覆盖率、政策误伤率）与反馈通道。
- 机制级对应物：OPA（策略即代码）、Iceberg 目录级 ACID/分支、契约测试——DDIA [第 4 章编码与演化](../设计数据密集型应用/04-编码与演化.md) 给出了"计算化政策"里兼容性检查的微观算法基础。

## 5. Transition（过渡）

- 从"人肉委员会"迁到"联邦 + 计算"：先盘政策（哪些真正需要全局一致？她的答案通常少得出人意料）、再政策即代码化、后建立调节度量。
- 风险自认：计算治理依赖平台抽象，平台弱则治理弱——与第 4 章互为死锁/互锁的两面。

## 6. 批判视角

- 本章与第 2 章共同构成 mesh 被批评最重的部位：组织学处方缺乏激励学分析（奖励怎么发在第 16 章仅列提纲）；2023 后实际存活下来的更多是"计算"半句（policy-as-code），"联邦"半句（跨域代表制）罕有真运转者。
- GDPR/数据主权对"域跨境组合"的现实约束，书内处理被欧洲从业者批评为乐观（⚠️ 转述，不引具体文献）。

## 三层政策×三形态执行矩阵（⚠️ 由 §3–§4 交叉归纳的速查表）

| 政策示例 | 层级 | 执行形态 | 机器工件 |
|---|---|---|---|
| 个人敏感字段默认行级过滤 | 全局 | 自动化 | 目录 ABAC 策略（OPA/Cedar 类） |
| 数据产品必须声明 owner+契约 | 全局 | 自动化（发布关卡） | CI 门禁校验 manifest 必填项 |
| 训练数据禁止含欧盟 PII 原始行 | 全局 | 审计+对冲 | 定期扫描 + 分级拦截 |
| 域内维度建模命名规范 | 域 | 自动化（脚手架默认） | lint 规则集 |
| 产品新鲜度 SLA 与预算 | 产品 | 自动化+对冲 | SLO 定义 + 错误预算冻结 |
| 访问许可条款（限内部分析） | 产品 | 自动化 | 机器可读 license 字段（→第 14 章） |
| 政策变更评审 | 全局/域 | 人+审计 | PR 评审流 + 变更记录（流程即治理） |
"自动化/审计/对冲"三形态与层的笛卡尔积即 her 说的"计算化"全貌：政策=数据×控制×回路的组合。

## 常见疑问（FAQ）

**Q1：联邦体开会没人来怎么办（委员会僵尸化）？**
A：书内隐含对策：把联邦的产出限定为**可执行工件**（政策代码+调节参数），开会只是评审 PR；产出非工件的治理体必然僵尸化——2024 年后的实践复盘与此判断一致（⚠️ 转述）。

**Q2：政策冲突（全局 vs 域）仲裁规则？**
A：全局政策仅存硬约束（规模纪律），冲突时全局优先但变更需回路证据（影响评估）；域在硬约束外全权。书未给仲裁程序细节，属留白。

**Q3：计算治理需要多强的平台？**
A：硬耦合（§5 自认）：无横切关卡宿主则政策回到文档。这也是"平台原则先于治理原则落地"的工业现实成因。

**Q4：AI 模型成为治理对象吗？**
A：本书只管分析型数据；模型消费数据的合规（如 AI Act）是其后压力，见"最新演进"。#202（待建）正面处理。

**Q5："多态政策"与"标准实现库"如何防重复造轮？**
A：政策参考实现库（可组合策略模板市场）是自然延伸；Open Policy Agent 的库生态就是本章构想的自发实现（⚠️ 生态转述）。

## 核心概念速览（中英对照）

- **联邦计算治理** — Federated Computational Governance：全局一致 + 本地自治 + 策略即代码的第三条路。
- **内插自治** — Interpolated Autonomy：自治度随风险连续调节的治理变量。
- **调节回路** — Feedback Loop：以观测-回摆替代审批-放行的控制论治理观。
- **数据封建化** — Data Feudalism：无治理自治的塌缩形态（各自为政不可组合）。
- **三层政策** — Global / Domain / Product Policies：政策作用面分层。
- **多态政策** — Polymorphic Policy：同一政策意图的异构机器实现与统一验证。
- **政策即代码** — Policy as Code：治理规则以可版本化工件表达与执行。
- **自动化/审计/对冲** — Automated / Audited / Hedged：政策执行的三种计算形态（⚠️ 转述术语）。
- **治理即产品** — Governance as a Product：治理能力平台化交付并度量。
- **互操作性底线** — Interoperability Baseline：全局政策仅收敛"硬约束"的规模纪律。
- **合规覆盖率** — Compliance Coverage：治理体系的自度量指标。
- **OPA / Cedar 类策略引擎** — Policy Engine：本章主张的当代工业载体（⚠️ 选型注记）。
