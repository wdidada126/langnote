## 4. 本书在数据库系列中的定位

本书是**理念/范式书**（sociotechnical paradigm），不是引擎/实现书：它回答"分析型数据该如何组织所有权、产品化与治理"，几乎不给任何可运行代码。在本系列中充当"去中心化一侧的思想极点"，与以下已落盘笔记分工：

| 兄弟笔记 | 分工关系 |
|---|---|
| [Practical_Lakehouse_Architecture](../Practical_Lakehouse_Architecture/00-总览与阅读地图.md) | 湖仓解决**存储/计算底座**（表格式、目录、引擎）；mesh 解决**组织与所有权拓扑**。mesh 书中平台层问题正由湖仓书实操回答 |
| [The_Data_Lakehouse](../The_Data_Lakehouse/00-总览与阅读地图.md) | Kimball 视角的湖仓与基础数据；与 mesh 的"领域去中心化"形成集中式 vs 分布式对照 |
| [设计数据密集型应用](../设计数据密集型应用/00-总览与阅读地图.md) | DDIA 第 4 章"编码与演化"（schema 演化/兼容性）是 mesh"数据产品契约"的机制级微观对应物 |
| [大数据之路](../大数据之路.md) | 阿里数据中台：与 mesh 同期、方向相反的"中心化"答卷——中台收编 vs mesh 下放 |
| [数据架构之道](../数据架构之道.md) | 数据架构与治理总纲，联邦治理可在其治理框架里对照定位 |
| [Building_the_Data_Warehouse](../Building_the_Data_Warehouse/00-总览与阅读地图.md) | Inmon（#169，同波已落盘）：集中式企业数据仓库 vs 去中心化 mesh 的方法论对话——本系列离本书论点最近的对照组 |

### 辨析登记（防混档，任务硬要求）

1. **本书 ≠ #200《Implementing Data Mesh》**。#200 是本工程补充清单上的**另一本书**（实现向；本环境未抓到其权威元数据，目录/作者⚠️待其落盘时在双方 00 互登记辨析），两书同题材不同书，**只互链、不并档**。
2. **本书 ≠ #202《Data Fabric and Data Mesh Approaches with AI》**。#202 为 fabric 与 mesh 对比 + AI 应用的书（**待建**，⚠️ 细节以其落盘取证为准），亦只互链不并档。
3. **本书 ≠ 一切"数据网格"中文原创书**：机工中译名"权威指南"易与各类国产 mesh 书混淆；认原作名 `Data Mesh: Delivering Data-Driven Value at Scale` 与作者 Dehghani 为准。
4. **书名谱系**：《Data Mesh 权威指南》（机工 2023）与《数据网格（影印版）》（东南 2023）是**同一英文原书**的中译与影印两个版本，本目录英文目录以影印版页实抓为准，中文小节名以当当中译目录为准。
