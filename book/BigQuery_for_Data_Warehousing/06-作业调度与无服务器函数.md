## 一句话主题

第 10 章解决「谁来按点按序触发作业」——GCP 上四种调度器的选型；第 11 章解决「轻逻辑挂在哪」——事件驱动的 Cloud Functions 作为仓库的胶水层。两章合起来把 Ch.5–9 的手工动作升级为可值守的自动化。

## Ch.10 Scheduling Jobs：调度器选型

### 10.1 四路选项（⚠️ 2020 转述 + 重构对比）

| 调度器 | 触发对象 | 适合场景 | 主要代价 |
| --- | --- | --- | --- |
| Scheduled Queries（原生） | 单条 SQL（参数化 `${param}` + cron） | 仓内派生表/定时聚合，无外部依赖 | 只管 SQL，不管管道依赖 |
| Cloud Scheduler | PubSub/HTTP → 触发 bq/Dataflow | 简单的「到点跑个命令」 | 依赖链要自己拼 |
| Cloud Composer（托管 Airflow） | 任意 DAG：BQ+Dataflow+GCS+HTTP | 多任务依赖、回填、跨系统编排 | 环境常驻成本+运维心智 |
| Transfer Service | 源→仓周期性拷贝（GCS/S3/JDBC） | 标准源的免代码搬运 | 定制性弱 |

- Composer 概览 ✅ https://docs.cloud.google.cn/composer/docs（镜像 2026-10 实测 200；该路径为新版文档根）。
- 作者选型口诀（重构）：**「一条 SQL 能闭环→原生 scheduled query；单命令到点→Scheduler；有依赖图/要回填→Composer；标准源搬运→Transfer」**——调度工具越重，团队债务越重。

### 10.2 参数化与回填（本章工程要点）

- 时间参数惯用法：调度周期注入 `${execution_date}`，SQL 内 `TIMESTAMP_SUB(CAST('${x}' AS TIMESTAMP), INTERVAL 1 HOUR)` 圈定增量窗口——定时查询模板的变量替换是 2020 原生能力；
- 回填（backfill）哲学：任何增量 SQL 都要能「指定历史窗口重跑且结果幂等」——与 Ch.5 的 WRITE_TRUNCATE+装饰器同构（见 [03-批量装载与流式摄入.md](03-批量装载与流式摄入.md)）；Composer 的 `catchup=True/False` 决定新 DAG 是否自动补历史，作者强调**上线第一天就要写进 runbook**；
- 失败语义：重试次数、告警去重、失败依赖冻结下游——Airflow 的 `depends_on_past` 在数仓语境是防雪崩关键开关。

### 10.3 值守三件套（重构）

- 完成时间曲线（同环比告警，接 Ch.12）；SLA 表（每张消费级视图标注「几点必准」）；值班轮值与一键重跑手册——作者把这三件称「仓库的物业制度」。

## Ch.11 Serverless Functions with GCP：胶水层

### 11.1 Cloud Functions 定位（⚠️ 2020 转述）

- 事件驱动的单函数计算：触发器三大家——GCS 对象最终一致事件、PubSub 消息、HTTP/Webhook；部署即弹性，按调用-时长计费；
- 与仓库的三种典型接法（作者用例线重构）：
  1. **GCS→load 触发器**：文件落地即起装载作业（把 Ch.5 的定时轮询改造成事件驱动，新鲜度从小时到分钟）；
  2. **Webhook→insertAll**：第三方回调 JSON 直接入仓（小流量流式，Ch.6 的轻量档，见 [03-批量装载与流式摄入.md](03-批量装载与流式摄入.md)）；
  3. **告警→富化/路由**：Billing/监控告警触发函数，查仓补上下文再发工单——观测闭环的自动化端（Ch.12 联动）。

### 11.2 边界与纪律（重构）

- 函数不是管道：单调用超时上限（2020 gen1 约 9–540s 档）、内存封顶、无状态——**超过「轻胶水」的活儿交给 Dataflow/Ch.7**；
- 并发放大防护：insertAll 经函数代理时，上游风暴=函数并发×行速率双超限——必须配 PubSub 缓冲（✅ https://docs.cloud.google.cn/pubsub/docs/overview 镜像 200），别裸连；
- 身份纪律：函数以部署态服务账号访问 BigQuery，最小权限 role（viewer/writer 分档）+ 禁默认 SA 惯例——治理线在 Ch.14 收口（见 [08-数据治理与长期适应.md](08-数据治理与长期适应.md)）；
- 观测免费午餐：函数日志自动进 Cloud Logging，request_id 与 BigQuery job_id 串联可追全链路（Ch.12 展开）。

### 11.3 Cloud Run 的阴影（2020 前瞻，⚠️）

- 作者当时已提示：需要「完整运行时的弹性服务」（长连接、较大依赖、自定义超时）时 Cloud Run 比 Functions 合适；2024–2026 的实践中胶水层重心确实移向 Cloud Run gen2（含 GCS 触发），见文末演进。

- **原生定时查询**（示意，参数替换语法 ⚠️ 转述）：

```sql
-- 每小时增量汇聚；调度变量 ${execution_date} 由平台注入
INSERT INTO ds.hourly_stats
SELECT TIMESTAMP_TRUNC(created_at, HOUR) hr, COUNT(*) c
FROM ds.events
WHERE created_at >= TIMESTAMP_SUB(CAST('${execution_date}' AS TIMESTAMP), INTERVAL 1 HOUR)
  AND created_at <  CAST('${execution_date}' AS TIMESTAMP)
GROUP BY 1;
```

- **Airflow 最小依赖图**（Composer 伪码，形状记忆用）：

```python
with DAG("orders_pipeline", schedule_interval="0 2 * * *",
         catchup=False, default_args=dict(retries=2, depends_on_past=True)) as dag:
    load   >> dedupe >> aggregate >> qa_assert
    qa_assert.fail_alert = on_failure_notify_pubsub
```

- 值守三档告警（重构自 10.3）：**没跑成**（调度缺勤）→ Scheduler/DAG 层告警；**跑成但晚**（超时曲线）→ 完成时刻同环比；**跑成但错**（断言失败）→ 质量 SQL 出 false 即 paging——三类各配一条静默去重规则，否则值班第一周就被噪声淹没；

def on_file_finalized(event, context):

## 附二：调度与胶水误区五条（重构速查，⚠️ 非原书内容）

- 误区1「catchup 打开是保险」：错误日期循环重放比不重放更贵，默认 False+手动回填演练；
- 误区2「定时查询能管依赖」：单 SQL 无上游感知，跨源依赖必须升 DAG 层（或 Dataform 类断言，见演进节）；
- 误区3「函数重试=可靠」：无幂等键的重试=重复写入发生器，胶水层自带去重责任（Ch.6 insertId/装饰器覆写兜底）；
- 误区4「事件驱动全面优于轮询」：GCS 事件有最终一致重复投递，轮询+水位反而更可审计——按事故成本选型，不按时髦度；
- 误区5「告警越多越安全」：三类告警（缺勤/超时/断言）+去重之外的告警都是值班士气腐蚀剂。

## 核心概念速览（中英对照）

- **定时查询** — Scheduled Query：BigQuery 原生的 cron 化单 SQL 作业，支持参数替换。
- **云调度器** — Cloud Scheduler：GCP 托管 cron，经 PubSub/HTTP 触发下游。
- **DAG** — Directed Acyclic Graph：任务依赖图；Composer/Airflow 的调度单元。
- **回填** — Backfill：以历史时间参数重放增量作业至幂等结果的过程。
- **追赶模式** — Catchup：Airflow DAG 创建后自动补跑历史区间开关。
- **依赖冻结** — depends_on_past：上游未成则下游今日实例不放行的防雪崩开关。
- **传输服务** — Transfer Service：GCS/S3/JDBC 等标准源的托管周期拷贝。
- **事件驱动函数** — Cloud Function：GCS/PubSub/HTTP 触发的按用计费胶水计算。
- **Webhook 入仓** — Webhook Ingest：第三方回调经函数转 insertAll 的轻流式路径。
- **部署态身份** — Runtime Service Account：函数/作业实际持有权限的服务账号。
- **请求-作业串联** — Request-to-Job Trace：函数 request_id 与 BQ job_id 的对账线索。
- **胶水层** — Glue Layer：不承担变换主责、只做触发/转写/路由的轻计算位。

## 最新演进与工业实践

- **调度原生位扩张（2021–2026）**：Dataform 于 2020 收购、2022-06 GA——声明式 SQL 工作流（断言/声明/调度依赖一体）直接吃掉了本章「Composer 管仓内 SQL」的大部分用例（✅ https://docs.cloud.google.cn/dataform/docs/overview 镜像 200）；BigQuery 侧 scheduled query 增强参数与物化视图自动刷新（⚠️ 转述）重叠调度管理面。
- **Functions gen2 → Cloud Run 统一**：2022 起 gen2 运行时把 Functions 并入 Cloud Run 底座（超时放大、GCS 事件直连），作者 2020 年的「阴影」判断兑现为平台路线；轻量胶水默认落 Cloud Run gen2 ⚠️（canonical cloud.google.com/functions 本环境 000，不给 ✅）。
- **Composer 演进**：Airflow 3.x 代际迁移与 Image-based 部署成为主流形态（⚠️ 转述；✅ 文档根 https://docs.cloud.google.cn/composer/docs 镜像 200）。
- **工业实践（2024–2026）**：数仓调度评审单新增三项——回填演练留痕、失败预算（月度 SLA 损耗上限）、事件链路死信处理；「一条 SQL 能闭环就不上 DAG」仍是 FinOps 共识第一原则。Snowflake 线对位的调度/编排（Tasks/Tasks Graphs）差异登记于 [../Snowflake_The_Definitive_Guide/00-总览与阅读地图.md](../Snowflake_The_Definitive_Guide/00-总览与阅读地图.md)。
