## 一句话主题

第 14 章回答「谁的数据、谁能看、怎么合规」；第 15 章回答「平台在变、组织在变，三年后这个仓库还成立吗」。两章是本书管理视角的顶点：治理是静态切面，适应是动态切面，合起来才是「仓库作为产品」的完整生命周期观（呼应 Ch.1/2 的立项宣言，见 [01-入住BigQuery与仓库项目启动.md](01-入住BigQuery与仓库项目启动.md)）。

## Ch.14 Data Governance：静态切面

### 14.1 权限三栈（⚠️ 2020 转述）

- **IAM 栈**：项目/数据集/表级角色（`roles/bigquery.dataViewer` 等预置角色 + 自定义角色最小化），✅ https://docs.cloud.google.cn/bigquery/docs/access-control（镜像 200）；
- **数据集访问栈**：dataset-level 授权 UI 与 `specialGroup:allAuthenticatedUsers` 的危险性——作者点名反面教材：公共数据集便利与私有仓库泄漏只隔一次手滑；
- **列级栈**：policy tags 绑定敏感分类（PII/财务），列级访问控制（column-level security）在 2020 为 GA 前夜/初 GA（⚠️ 版本注）——敏感列按 tag×角色放行，是数仓与合规工具链的接口点；
- 三栈合读：**行级控制 2020 缺位**（仅视图绕行），演进见文末——这是老册读者最需要补的认知差。

### 14.2 分类、目录与血缘（重构）

- 分类先行：装载时按 Ch.3 敏感级别标注（列注释/policy tag/labels 三选一落地，见 [02-数据盘点与成本管控.md](02-数据盘点与成本管控.md)）；
- 数据目录：Data Catalog 给表/列挂 tag 模板与业务描述，✅ https://docs.cloud.google.cn/bigquery/docs/data-catalog（镜像 200）；作者把它定位为「治理的台账系统」——没有台账的规则都是装饰；
- 血缘：2020 年 BigQuery 原生血缘尚未 GA，作者用「命名规范+信息模式作业史反推」土法——工程圈此后被 Dataform/dbt 的 DAG 显式血缘替代（见 [06-作业调度与无服务器函数.md](06-作业调度与无服务器函数.md)）；
- 合规动作清单（重构）：被遗忘权的行删除 SOP（DML+备份桶同删，Ch.8 技法）、数据驻留（区域锁定，Ch.1 约束）、访问复核（季度 IAM recommender 化）。

### 14.3 治理的组织面（作者本色段）

- 三角色：数据 Owner（业务）、Steward（质量与文档）、平台 Admin（权限与成本）——作者反复强调 **治理失败首先是组织失败**：技术开关（policy tag/审计日志）只是给组织决策装上执行器；
- 治理税 vs. 治理债：流程收税过重消费者绕行（影子数据集），过轻则合规债滚利——2020 疫情远程办公期的放权教训被作者用作案例素材。

## Ch.15 Adapting to Long-Term Change：动态切面

### 15.1 平台变动的既定事实清单（2020 视角重构）

- 方言迁移：legacy SQL→Standard SQL 的弃用时间表——作者策略：**所有新资产只写 Standard**，存量按消费热度倒排迁移；
- API/入口换代：`bq`/REST/客户端库的版本节奏，SDK 依赖锁版本进 CI；
- 定价与配额调整是常态：Ch.4 成本模型设季度复审闹钟（账单异动>20% 触发重估）；
- 产品更名与合并（Data Studio→后见演进；BigQuery 家族扩张）：**文档时效性=风险面**，作者要求关键决策记录引用快照而非活链接——本目录的 ✅/⚠️ 三态标注可视为该原则的执行版。

### 15.2 资产的长期维护手艺（重构）

- Schema 演化协议：加列自由、删列公告期（至少一个消费周期）、改类型=新列并行走私切换——与 Ch.5「显式 schema 入库」同源的 DDL 版本化（Git）；
- 消费者合同：每张对外视图标注 owner/SLA/变更通知渠道；破坏性变更走「新 URL 新视图、旧视图公告退役」双轨；
- 反脆弱预算：每年留出 10–15% 工程时间偿还「加速折旧债」（迁移/重构/文档），作者称之为**仓库的产品化税率**；
- 退出预案：数据可导出性年检（抽一张大表 export→异引擎能读，如 Parquet 出仓验证锁定对冲，呼应 Ch.2 反锁定条款）。

### 15.3 组织适应（收尾升华段）

- 从项目团队到产品团队：值班制、路线图公开、需求漏斗——Ch.2 章程的「终点」改写为 v1 里程碑；
- 度量换代：从「表数量/作业数」虚荣指标转向「消费覆盖度/新鲜度达成率/单位成本业务价值」；
- 作者结语精神：仓库不会「完成」，只会「被用得值」或「被荒掉」——治理与适应是同一枚硬币的两面。

- 季度治理巡检单（三角色会签，重构）：离职/转岗 grant 清零、policy tag 覆盖率抽检（敏感列清单 vs 实际挂标）、行删除请求 SOP 演练记录、驻留区域与新增消费地核对、目录台账新鲜度（描述/owner 非空率>95%）；
- **schema 演化变更单字段**（15.2 的表单化）：变更类型（加列/删列/改型/退役）→ 受影响消费者清单（血缘反推）→ 公告期起止 → 双轨窗口计划 → 回滚步骤 → 断言测试（对账 SQL 版本号）；作者式提醒：**没有公告期的删列=没有预告的裁员**；
- 反脆弱预算演练脚本（年度）：抽 1 张 1TB 级表 `bq extract` Parquet 出仓 → DuckDB/异引擎挂载查询通过 → 记录耗时与失真列清单 → 归档为「退出预案体检报告」——与 Ch.13 类比实验（🔧 E1/E2）同一份 Parquet 语言，形成锁定对冲闭环；
- 思考题（5 道）：T1 列级控制与脱敏（后时代能力）分别挡住哪类泄漏？T2 allAuthenticatedUsers 事故里「便利」与「默认值」谁的责任大？T3 治理税过重导致影子数据集，如何用产品手段（自助申请+自动过期）降税？T4 被遗忘权行删除为何必须连带备份桶？T5「平台变动清单」如何写进团队日历而不变成废纸？

## 核心概念速览（中英对照）

- **最小权限** — Least Privilege：以角色粒度给恰好够用的访问，治理第一律。
- **预置角色** — Primitive/Predefined Role：平台封装好的权限包，自定义角色是收紧手段。
- **策略标签** — Policy Tag：列上绑定敏感分类，驱动列级访问控制的元数据。
- **列级安全** — Column-Level Security：按 tag×角色放行列访问的细粒度机制。
- **行级安全（缺位）** — Row-Level Security Absence：2020 需视图绕行的能力空洞（后已补）。
- **数据目录** — Data Catalog：跨资产台账：描述、tag、术语表的统一挂装点。
- **血缘** — Lineage：资产间上下游依赖图，2020 靠反推、后成原生能力。
- **被遗忘权** — Right to Erasure：GDPR 删除请求在列存仓库的执行 SOP。
- **数据主权/驻留** — Data Residency：区域锁定与跨区访问合规约束。
- **弃用时间表** — Deprecation Schedule：legacy SQL 等旧能力的官方退役节奏。
- **消费者合同** — Consumer Contract：视图级 owner/SLA/通知义务的明示约定。
- **产品化税率** — Productization Tax Budget：年度偿还技术债的工程时间配比。
- **退出预案** — Exit Drill：定期导出验证以对冲供应商锁定。

## 最新演进与工业实践

- **治理原生化（2021–2026）**：行列级安全双双补齐——**行访问策略**（Row Access Policy，2024 前后 GA ⚠️ 转述）终结视图绕行时代；动态数据掩码（Dynamic Data Masking，2024 ⚠️，canonical 文档页本波镜像实测 404，不给 ✅）替代部分 policy tag 粗过滤；KMS/CMEK 客户管理加密成为企业合规标配（✅ 概览 https://docs.cloud.google.cn/bigquery/docs/access-control 镜像 200）。
- **目录与血缘升维**：Data Catalog 并入 Dataplex「统一目录」（Universal Catalog，2023–2024 路线 ⚠️ 转述；✅ https://docs.cloud.google.cn/dataplex/docs/overview 镜像 200），BigQuery 原生血缘图 GA 进 Console——14 章的土法反推成历史；Knowledge Engine/AI 自动打标把「分类先行」从人工 SOP 变半自动流水线（⚠️）。
- **适应面的新变量**：BigQuery Edition/性能档切换、Gemini in BigQuery 的 NL 生成 SQL 进入消费者工作流（2024–2025 ⚠️ 转述）；15 章「平台变动清单」今天必须加一行**模型与数据共治**（向量检索、LLM 上下文的治理归入同一台账，衔接 [10-BigQueryML与Jupyter公共数据集.md](10-BigQueryML与Jupyter公共数据集.md)）。
- **工业实践（2024–2026）**：数据合同（data contracts）与策略即代码（IAM/Policy Intelligence 模拟器、Terraform 管 grant）成为大中型组织的 14 章落地形态；治理组织从委员会制转向嵌入式 data steward 轮岗——作者「治理首先是组织问题」的论断在 2026 的 mesh/fabric 文献中仍是共识轴心，谱系对位 [../Data_Governance_in_the_Era_of_AI_2e/00-总览与阅读地图.md](../Data_Governance_in_the_Era_of_AI_2e/00-总览与阅读地图.md)。
