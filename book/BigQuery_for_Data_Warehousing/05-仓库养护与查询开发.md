## 一句话主题

第 8 章是「仓库养起来」：分区/生命周期/备份/权限卫生的日常运维；第 9 章是「仓库用起来」：Standard SQL 方言的查询开发手艺。两章构成书的中枢——数据进来了（Ch.5–7），本章保证它**不腐烂**且**问得出结果**。

## Ch.8 Care and Feeding：日常养护清单

### 8.1 数据保鲜与生命周期（⚠️ 转述）

- 表级 `requirePartitionFilter`：强制分区谓词，防止裸查询扫全史——分区表上线即配这把闸（接 Ch.4 四旋钮，见 [02-数据盘点与成本管控.md](02-数据盘点与成本管控.md)）；
- 分区过期（partition expiration）与表过期（default_table_expiration_days）：合规驱动的数据最小化，**设错=不可逆丢数**，作者要求过期策略进变更评审（Ch.15 回收，见 [08-数据治理与长期适应.md](08-数据治理与长期适应.md)）；
- 时间旅行（Time Travel）：2020 年能力窗口有限（⚠️ 预览转述）；7 天窗口 + FOR SYSTEM_TIME AS OF 后来才成熟，是误删/误 UPDATE 的第一道后悔药——✅ https://docs.cloud.google.cn/bigquery/docs/time-travel（镜像 200）。

### 8.2 修正与迟到数据（本章与 Ch.6 的暗线）

- 三种修正姿势按代价排序：**分区装饰器整日覆写**（重跑幂等，最简）> **DML**（UPDATE/DELETE/MERGE，2019–2020 GA，按行改但消耗 slot、破坏长期折扣资格）> **影子表交换**（schema 大改时 `CREATE TABLE new LIKE + INSERT + 原子 swap`）；
- 迟到数据的仓内收敛：流式表按业务键 `MERGE ... WHEN MATCHED AND source.arrival_ts > target.arrival_ts` 的 last-write-wins 去重视图——Ch.6 说的「去重终究是下游 SQL 责任」在这里落账（见 [03-批量装载与流式摄入.md](03-批量装载与流式摄入.md)）；
- DML 副作用登记：写放大计入 slot 时、被改表失去「未修改」长期折扣资格——养护操作本身也是成本行为。

### 8.3 备份与恢复的现实主义（重构）

- 平台承诺的是可用性不是防手滑：跨项目/跨区域复制（`bq cp`/transfer）、snapshot decorator 只读快照（⚠️ 2020 预览）、导出 GCS 归档三件套；
- 作者运维观：**备份频率跟着可承受 RPO 定，而不是跟着技术能力定**——一页 runbook（谁、何时、恢复到哪）胜过无人执行的每日快照。

### 8.4 卫生类例行动作（重构清单）

- 空/僵尸表季检（INFORMATION_SCHEMA 最后访问视图驱动）；权限最小化复审（谁还留着离职同事的 grant）；命名与注释抽检（Ch.14 数据目录的前置）；成本异常周报（Ch.12 观测指标，见 [07-云日志与BigQuery进阶.md](07-云日志与BigQuery进阶.md)）。

## Ch.9 Querying the Warehouse：查询开发手艺

### 9.1 方言基线与入口（⚠️ 转述）

- Standard SQL（2017 起官方推荐，legacy SQL 弃用线进行中）：类型严格、需要 UNNEST 而非 legacy 的 EVERY/IN 子查询魔法；入口——Console 编辑器、`bq query`、API jobs、以及 BI 工具经 ODBC/JDBC 或原生连接器；
- 查询以 **job** 计量：dry-run 估字节（Ch.4 事前闸）、按 slot 排队、结果集默认限 100MB（超出走 extract/export）；
- 脚本化：`DECLARE`、`BEGIN...EXCEPTION` 错误处理、临时表（`CREATE TEMP TABLE`）把多步逻辑装进单脚本——作者把「一段能跑的 SQL」与「一个能交付的查询程序」分界画在脚本能力上。

### 9.2 BigQuery 特色构造（本章篇幅最大处，重构）

- **嵌套与重复**：`STRUCT/ARRAY` 列、`UNNEST(...) WITH OFFSET` 展开、点号路径访问——仓库关系代数与文档模型的混血处，对位精读 [../Google_BigQuery_TDG/08-高级查询.md](../Google_BigQuery_TDG/08-高级查询.md)（盘上已验名）；
- **通配表**：`FROM data.events_*` + `_TABLE_SUFFIX`——按日分表时代的跨表扫描语法（分区表成熟后地位下降，见演进节）；
- **函数库三板斧**：近似计算 `APPROX_QUANTILES/COUNT(DISTINCT)`（TB 级分位数的工程妥协）、`SAFE_CAST/IFNULL` 容错族、窗口函数全谱（帧/排除语义按 ANSI 走）；
- **UDF/TVF**：SQL UDF 参数化表达式复用、JS UDF 处理地理/解析怪需求（冷启动与扫描成本提醒）、表值函数封装子查询族——治理视角下「UDF 是逻辑的 npm 包」；
- JOIN 策略：分布键对齐（分桶/聚簇列做 join key）、小表 broadcast（2020 引擎自动，无需 hint）、`TABLESAMPLE` 抽样探查大表 join 可行性。

### 9.3 查询风格=账单风格（与 Ch.4 闭环）

- 反模式清单：`SELECT *`、无分区谓词、对嵌套列整列 UNNEST 后再过滤、结果缓存不友好的分钟级微变查询、把 JS UDF 放进 TB 主链路；
- 正模式：先 dry-run 后上线、列裁剪从视图层固化、`QUALIFY`（2020 后加入的窗口过滤语法糖，⚠️ 版本注）压缩套娃子查询；
- 作者教学线：每章结尾「动手题」多以 Console 即席查询为载体——查询是消费者的日常，也是治理数据的投票行为（坏查询被供数团队看见的通道见 Ch.12/14）。

## 附：养护 SQL 配方与查询练习场（自拟教学示意，⚠️ 非原书内容）

- **last-write-wins 去重模板**（Ch.6 承诺的兑现，Standard SQL）：

```sql
MERGE `ds.events` AS t
USING (
  SELECT * FROM (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY event_id ORDER BY arrival_ts DESC) rn
    FROM `stg.events_raw`
  ) WHERE rn = 1
) AS s
ON t.event_id = s.event_id
WHEN MATCHED AND s.arrival_ts > t.arrival_ts
  THEN UPDATE SET t.payload = s.payload, t.arrival_ts = s.arrival_ts
WHEN NOT MATCHED THEN INSERT (event_id, payload, arrival_ts)
  VALUES (s.event_id, s.payload, s.arrival_ts);
```

- **嵌套展开练习**（示意数据：订单+行项目数组）：

```sql
SELECT o.order_id, line.sku, line.qty
FROM `ds.orders` o, UNNEST(o.lines) AS line
WHERE o.order_date = "2020-01-01";           -- 分区谓词前置=账单纪律

-- QUALIFY 版窗口过滤（语法晚于本册，⚠️ 版本注）
SELECT * FROM `ds.events`
QUALIFY ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY ts DESC) = 1;
```

- **巡检 SQL 三件**（跑在 INFORMATION_SCHEMA 上，机制 ⚠️ 转述）：僵尸表清单（最后访问>90 天）、无分区谓词作业榜（近 7 日 statement 粗筛）、未设过期的数据集盘点——输出接 Ch.12 观测表，形成养护工单源；
- 备份分层口诀：**热（时间旅行 7 天内）→温（跨项目 clone/snapshot）→冷（export 到 GCS 归档）**——每层标注恢复演练频次，没演练过的备份视为不存在（Ch.8.3 作者原话的精神重构）；
- 练习场设计：用免费额度造一张千万行事实表（生成列 `GENERATE_ARRAY` 展开）、装成「乱序聚簇错误版」与「正确分区+聚簇版」两表，同一查询各跑 dry-run 对比 estimatedBytesProcessed——把 E1/E2 的 🔧 直觉换算成真平台的字节数（读者自测，本目录不代跑）；
- 思考题（5 道）：T1 MERGE 修正当月分区为何会重写整分区字节？T2 影子表 swap 期间消费者查询的一致性风险窗口在哪？T3 `requirePartitionFilter` 对 BI 工具的副作用如何在上线前沟通？T4 UNNEST 后再过滤与先过滤再 UNNEST 的扫描量差异机理？T5 结果缓存对带 `CURRENT_TIMESTAMP()` 的查询为何永不命中？

## 核心概念速览（中英对照）

- **分区过滤强制** — requirePartitionFilter：分区表必须带分区谓词才可执行的护栏属性。
- **分区过期** — Partition Expiration：分区自动老化的保留时限，合规最小化的执行器。
- **时间旅行** — Time Travel：按历史时点查询/恢复表数据的窗口能力。
- **装饰器覆写** — Partition Decorator Overwrite：以 `table$day` 整日幂等重写的修正姿势。
- **DML** — Data Manipulation Language：UPDATE/DELETE/MERGE 行级改写，slot 计费且破坏长期折扣。
- **影子表交换** — Shadow Table Swap：新建表灌数后原子替换原表的 schema 迁移术。
- **快照装饰器** — Snapshot Decorator：`table@TIMESTAMP` 只读历史切片引用。
- **UNNEST** — Unnest：将 ARRAY 列展开为行，WITH OFFSET 保留原下标。
- **通配表** — Wildcard Table：`*_` 后缀跨同构表族的扫描语法。
- **近似函数** — Approximate Functions：APPROX_* 用可控误差换 TB 级可算性。
- **TVF** — Table-Valued Function：返回表的参数化函数，逻辑复用的仓内包。
- **QUALIFY** — Qualify：对窗口函数结果直接过滤的子句（晚于本册出版加入）。
- **结果缓存命中** — Cache Hit：相同 SQL 短期复用既有结果，免二次扫描费。
