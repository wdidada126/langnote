## 核心概念速览（中英对照）

- **对象模型** — object model：语言特性（对象/继承/虚函数/模板）到内存布局与指令生成的落地约定；本书语境是 MSVC x64
- **反汇编** — disassembly：把 `.text` 目标码还原成汇编，观察「取 vptr→查槽→间接 call」的证据链
- **调试符号** — debug symbols（PDB/CodeView vs DWARF）：把地址、偏移翻译回源码名与成员布局的元数据
- **内存窗口** — memory window：VS 里直接看对象字节；GCC 世界的等价物是 gdb `x/` 与 objdump `-s`
- **名称改编** — name mangling：`_Z3useP4Base` 一类把类作用域/重载编码进链接符号的方案
- **虚表指针** — virtual table pointer (vptr)：多态对象开头的表指针，本目录一切观察的原点
- **编译单元** — translation unit：源文件+头文件的预处理闭包；模板重复实例化（见 09）以它为粒度
- **调用约定** — calling convention：x64 下 `this` 走 `rcx`（Microsoft x64），参数走 rdx/r8/r9

## 动机：为什么第一章不讲对象模型、先讲「怎么看见」

对象模型的全部争议都是**布局与指令**的争议：`sizeof` 是多少、vptr 在第几个字节、这次调用是否
查了表。语言标准只承诺语义（「调用虚函数时按动态类型分派」），不承诺实现——所以**没有观察手段，
对象模型只能靠背诵**。书的路线是：装 VS 2019，用调试器的内存窗口/反汇编窗口/监视窗口把每个
论断当场看一遍。这条路线的价值不在于工具本身，而在于把「教材断言」降级为「可复验实验」的习惯。

## 机制：一次「看见虚函数表」的两条工具链路线 🔧已实测

同一件事（证明「多态 = 对象头 8 字节 + 查表间接 call」），MSVC 与 GCC 世界的取证方式：

**路线 A（书的路径，MSVC）**：Debug 窗口 → Disassembly 勾选「Show Source/Locals」，
在 `b->f()` 处看 `mov rax, [rcx]` / `call qword ptr [rax]`；内存窗口里对 `b` 地址看首 8 字节
即 vptr 指向的 `Derived::`vftable'`（VS 会符号化显示）。⚠️ 本节 MSVC 界面细节按通行记载描述，本机无 VS 未实测。

**路线 B（本目录实测路径，MinGW g++ 15.2 win32 + binutils objdump/nm）**：

```cpp
// e1_virt.cpp —— 已实测编译 g++ -std=gnu++23 -O0 -c
struct Base { virtual void f(); void g(); };
struct Derived : Base { void f(); };
void use(Base* b){ b->f(); b->g(); }   // 一个虚、一个非虚，对照
```

`objdump -d --no-show-raw-insn` 实测输出（节选）：

```asm
mov 0x10(%rbp),%rax     ; rax = b
mov (%rax),%rax         ; rax = [b] —— 取 vptr
mov (%rax),%rdx         ; rdx = [vptr+0] —— 取槽 0（f）
call *%rdx              ; 虚调用：目标地址运行时才知道
call 2b <_Z3useP4Base+0x2b>  ; b->g()：非虚，编译期直调
```

**三行取表 + 一次 `call *reg`**：这就是 03 章所有讨论的机器真相；`nm` 同屏还能看到直调目标
`U _ZN4Base1gEv`（未定义引用，链接期解析）。虚函数调用与否，在**同一函数体内**留下两种调用形态——
对比即证据。

**看见 vtable 本身**（🔧已实测）：链接后 `nm e12.exe | grep _ZTV`：

```text
0000000140004570 R _ZTV7Derived          ; R：只读数据段
...r .rdata$_ZTV7Derived                  ; PE 的 COMDAT 段名直接写着 vtable 归属
```

vtable 是**每类一张的只读全局对象**（符号 `_ZTV` + 类名），住在 `.rdata`；对象里只放它的地址。
这与「函数不在对象里」（02 章）互为印证。RTTI 符号（`__si_class_type_info`）也同屏可见——07 章伏笔。

## 权衡：观察工具的得与失

| 维度 | VS 内存/反汇编窗口 | objdump/nm/gdb | Compiler Explorer (godbolt) |
| --- | --- | --- | --- |
| 即时性 | 运行期看活对象 ✅（vptr 实值） | 需断点+`x/` 命令 | 编译期看生成码 ✅ |
| 可脚本化 | 弱 | 强 | 强（HTTP API） |
| 多编译器对照 | 无 | 需装多工具链 | ✅ 一键 GCC/Clang/MSVC |
| 教学门槛 | 图形化低 | 命令行高 | 最低 |

书的 MSVC 路线有个真优势：**调试器能把 vptr 符号化成 `Derived::`vftable'`**，初学零解码成本；
开源路线的优势是**同一份源码可横向对照 MSVC/GCC/Clang 的布局差异**——本目录实测注明 win32 ABI
与 ELF ABI 数字有别，正是靠后者才暴露得出来（见 10 篇）。

## 相邻概念对比

- **Debug vs Release**：调试用 `-O0` 保留完整间接调用形态；`-O2` 下编译器会内联/去虚化（03/07 实测
  `final` 案例直接变 `mov $0x2a,%eax`），「看不见 vcall」不代表不存在——观察对象模型必须锁 `-O0`。
- **地址 vs 偏移**：内存窗口给绝对地址，对象模型关心**相对偏移**（vptr@0、成员按 offsetof）；
  后者跨 ASLR 稳定，godbolt/nm 类工具天然占优。
- **标准承诺 vs 实现事实**：C++ 标准管语义，布局归 ABI（Itanium C++ ABI 文档/MSVC 实现）。
  「vptr 在偏移 0」是 ABI 惯例不是标准条文——本目录所有数字都带「实测于某 ABI」的限定，这正是 01 章教的姿势。

## 最新演进与工业实践

- **2020→2026 工具换代**：VS 2019 → VS 2022（x64 调试器与反汇编窗口持续增强，C++ DevKit）；
  开源侧 llvm-objdump/`gdb -ex 'layout asm'` 与 **Compiler Explorer** 已成机制类内容的事实标准配图工具。
- **DWARF5/PDB5 的紧凑调试信息**（GCC 11+/MSVC 2019 起默认 `/Zi` 路线）让「对象布局」可被
  `llvm-dwarfdump` 直接导出成员偏移——2020 年只能靠内存窗口人肉看，现在可程序化断言布局回归。
- **C++20 modules 改变「编译单元」边界**：传统 TU 概念（本章节语汇）在模块化工程里变成
  header unit/BMI 的图结构；排障时符号仍按 mangled name 出现，但 `nm` 里模块初始化符号
  （如 `_ZTW` TLS 表项、module init）会成新常客。教材的 VS 工程路线无此负担，工业新库需另学。
- **工业代码对应**：Chromium/LLVM 的 CI 大量使用 `nm`/`objdump`/`readelf` 脚本断言符号与段
  （如导出白名单检查），即本章方法论的规模化形态；本目录 09 章 `extern template` 的 T→U 实测同款。
- 论文/文档索引：Itanium C++ ABI 规范（cxxabi.org，无 DOI 的社区规范文档 ⚠️ 版本随 GCC 演进）；
  反汇编观感可配合 [../C++代码调试的艺术.md](../C++代码调试的艺术.md) 与 [../高效CC++调试.md](../高效CC++调试.md)。

## 工具对照速查：同一观察目标的命令卡 🔧已实测（右列）

| 观察目标 | MSVC/VS（书的路径 ⚠️ 界面未本机实测） | MinGW + binutils（本目录实测） |
| --- | --- | --- |
| 看 vcall 指令形态 | 反汇编窗口停在调用行 | `g++ -O0 -c x.cpp && objdump -d --no-show-raw-insn x.o` |

## 读「看不见的东西」的三个常见误读

1. **把栈地址当对象地址**：调试器里 `b` 与 `&b` 一屏之隔；vptr 判读必须以「对象首地址」为锚，
   栈槽地址（`lea` 出来的临时）会让人误判「vptr 不在偏移 0」。
2. **在优化构建里找 vcall**：`-O2` 起编译器可能把虚调用直调化/内联化（03 篇 `final` 案例实测消失），
   「反汇编里没有查表」≠「语言语义不是多态」——这是所有机制类观察的第一戒律。
3. **把 mangling 当 ABI 本体**：`_Z3useP4Base` 与 MSVC 的 `?use@@YAXPEAVBase@@@Z` 只是**名字方案**
   （Windows 导出层还能用 `extern "C"` 抹平）；真正决定布局的是 ABI 而非符号拼法——别拿符号名推布局。

## 自查三问

1. 一段源码里 `b->f()` 是 `call *reg` 而 `b->g()` 是 `call imm`，说明什么？（虚/非虚的分岔）
2. `_ZTV7Derived` 为什么是 `R`（只读段符号）而不是 `T`（代码段）？（vtable 是数据，不是代码）
3. 为什么所有布局数字必须注明 ABI 与 `-O` 级别？（win32/ELF 有别；`-O2` 会毁掉观察现场）
