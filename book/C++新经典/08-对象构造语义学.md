## 核心概念速览（中英对照）

- **构造语义学** — construction semantics：每个构造点上编译器**额外注入**的活（vptr 重指、成员/基类递归构造、静态注册）
- **初始化顺序** — initialization order：基类→虚基类（最派生代发）→成员**按声明序**→构造体；初始化列表的书写序无权发言（-Wreorder 实测）
- **默认构造成本** — default constructor cost：`Tr t;` 展开成「按序构造每个带构造的成员」的调用串——聚合类越深越贵
- **vptr 的逐段重指** — vptr staging：构造函数序言先把 vptr 设成**本层**表，故构造期虚调用降格（07 篇实测 `1B`）
- **临时对象** — temporary object：prvalue/按值传参/返回等场景物化，**全表达式末尾**统一析构（异常展开除外）
- **拷贝构造的浅拷贝本质** — bitwise-ish copy：按成员逐一拷贝——数据好复制，**语义**（所有权、vptr）要自己管
- **零/三/五规则** — rule of zero/three/five：特种成员函数的隐式生成矩阵所支撑的设计守则
- **魔法静态** — magic statics（C++11）：函数局部静态的线程安全一次性初始化（实测两次调用只打一次 init）
- **静态析构注册** — static destruction registration：构造成功才回炉注册；退出按构造完成逆序（实测）
- **保证拷贝消除** — guaranteed copy elision（C++17，P0135R1）：prvalue 不再必经临时对象——实测改变**能否编译**

## 动机：「构造函数体里那几行」只是冰山露出的帽尖

书第 6 章的核心教学动作：在构造调用处单步跟进，看到 vptr 赋值、成员逐个构造、基类先行、
`atexit` 式注册……这些都不在你写的代码里。把「一个定义 = 一堆展开」讲透，
才能真正理解：为什么初始化列表顺序要紧、为什么拷贝类要小心 vptr、
为什么全局对象构造次序是未定义大陆（static initialization order fiasco）。

## 机制一：时间轴全序实验 🔧已实测（g++ 15.2 -std=gnu++23 -O0）

```cpp
struct Tr{ int id; Tr(int i):id(i){printf("+%d ",id);} Tr(const Tr&o):id(o.id){printf("c%d ",id);} ~Tr(){printf("-%d ",id);} };
Tr g(0);                       // 全局
void use(){ Tr t(9); }         // 栈对象+临时
void ms(){ static int x = (printf("magic init\n"), 42); (void)x; }
struct WithDtor{ ~WithDtor(){ printf("w\n"); } };
int main(){ printf("enter main\n"); use(); ms(); ms(); static Tr s(77); WithDtor w; printf("exit main\n"); }
```

实测输出：

```text
+0 enter main
+9 -9 magic init
+77 exit main
w
-77 -0
```

逐条读数：
1. `+0` 在 `enter main` **之前**——全局对象在 main 入口前由 CRT 初始化循环构造；
2. `+9 -9` 相邻——栈对象于作用域尾析构；临时对象按「全表达式末尾」规则同屏可见；
3. `magic init` 只打一次——函数局部静态**首次执行到才初始化**，之后是普通静态变量；
   C++11 起该初始化**线程安全**（once 语义），旧 98 代码的多线程竞态坑就此封死（对照
   [../深入应用C++11.md](../深入应用C++11.md) 的 C++11 特性清单）；
4. 退出序 `w → -77(静态局部) → -0(全局)`：**构造完成序的逆序**——标准对同 TU 静态存储期对象的规定动作；
   跨 TU 的全局互依则是 fiasco 大陆，解法（Meyers singleton/依赖注入）见 02 篇 EMC 互链。
5. 虚基类最先由最派生代发——把本例换成 06 篇的菱形（实测 `B→V1→V2`），次序铁律同源：**先地基后楼层、逆序退房**。

## 机制二：初始化列表的「假顺序」 🔧已实测

```cpp
struct Bad{ int b; int a; Bad():a(b),b(3){} };  // 声明序 b 在前
```

实测编译警告三连：`'Bad::a' will be initialized after [-Wreorder]` / `'int Bad::b'` /
`when initialized here`——**成员永远按声明序初始化**，列表书写序只是摆设；
`a(b)` 读到的 `b` 取决于 b 是否已在前面完成（本例构造体执行时 b=3、a 拷贝到旧值——数字会骗人，
把声明序换过来 `a` 就是垃圾值）。这就是「把列表按声明序抄一遍」成为核心规范（C++ Core Guidelines
G.r31/R初）的对象模型依据；`-Wreorder` 是它的最小 CI 抓手。
另注：**初始化列表才是唯一初始化**——构造体里是赋值不是初始化（成本账在 Lippman 02 篇展开）。

## 机制三：拷贝/赋值与 vptr、所有权

- 隐式拷贝=逐成员复制：**vptr 不在成员里**（它是隐藏段，编译器在新对象构造完重指目标类表），
  所以「拷贝后类型正确」是编译器兜底的少数直觉之一；
- 但**语义所有权**无人兜底：裸指针成员的浅拷贝双释放是书时代经典事故，C++11 后标准答案=
  智能指针成员化（Rule of Zero）或删除拷贝——矩阵详见
  [../Effective_Modern_C++/03-转向现代C++.md](../Effective_Modern_C++/03-转向现代C++.md) 与
  [../深度探索C++对象模型/05-构造析构拷贝语意学.md](../深度探索C++对象模型/05-构造析构拷贝语意学.md)；
- 析构函数若是虚的，`delete basePtr;` 经表调对派生析构（03/04 篇机制）；**非虚析构删基类指针=UB**——
  07 章绑定表的负面推论。多态基类配 `virtual ~B() = default;` 的当代口径（含 protected 非虚替代案）
  在 [../Effective_Modern_C++.md](../Effective_Modern_C++.md) 的 Item 里已成文。

## 机制四：临时对象与 C++17 的编译期地震 🔧已实测（-std 对比）

```cpp
struct NoCopy{ int i; NoCopy(int x):i(x){} NoCopy(const NoCopy&)=delete; };
NoCopy mk(){ return NoCopy(1); }
int main(){ NoCopy n = mk(); }
```

实测：`-std=gnu++14` 两处 **error: use of deleted function**（返回路径需要可访问拷贝构造，
即使复制省略实际发生——旧标准里「省略」是许可不是义务）；`-std=gnu++17` **编译通过**。
这就是保证拷贝消除：prvalue 直接初始化目标存储，**无需存在拷贝/移动构造**（P0135R1，
wg21 短链实测 302）。教材（2020，MSVC 默认语言模式已 14/17 混杂）最容易一带而过的正是这条——
它把「工厂函数返回禁拷贝对象」从技巧升级为语言保证。

## 权衡与相邻概念对比

- **构造成本的两本账**：时间账（本篇：注入调用串）vs 空间账（02 篇 sizeof）；
  聚合深嵌套类的「默认构造雪崩」是编译期+运行期双付。
- **全局 vs 局部静态 vs 线程局部**：析构次序都服从「构造逆序」，但可见性域与线程语义不同——
  `thread_local` 的析构随线程结束走，与 atexit 池两套队列（并发书语境见
  [../C++并发编程实战2/02-线程管控.md](../C++并发编程实战2/02-线程管控.md)）。
- **vs 异常展开**：机制一的全表达式析构在抛出时改道「栈展开逐帧析构」——RAII 的全部意义；
  书未展开，可去 [../C++标准库.md](../C++标准库.md) 异常篇与 Effective 系补。

## 最新演进与工业实践

- **C++17/20/23 对构造语义的三连改**：保证拷贝消除（17，机制四实测）；
  聚合初始化含基类子对象（C++20）；`std::construct_at`/`start_lifetime_as`（C++20/23）
  把「手动放置构造」标准库化（placement new 的显式替代）。
- **静态初始化与线程**（Crossref 实测 DOI）：B. Boehm, *Threads cannot be implemented as a library*,
  PLDI 2008, DOI [10.1145/1064978.1065042](https://doi.org/10.1145/1064978.1065042)——
  魔法静态的 once 语义、静态析构与线程退出的竞态，正是该文「库层并发原语边界」论证的靶场；
  配合 10 篇所引其同作者内存模型续作对读。
- **工业样本**：Google style 禁止带副作用的全局构造（`InitOnce`/显式 init 函数替代）；
  Chromium `base::NoDestructor` 干脆**不析构**静态对象，以换退出次序确定性（弃内存回收、保无竞态退房）——
  机制一第 4 条的工业极端形态；Qt 全局插件表、LLVM 的 `ManagedStatic`（历史）都是同题工程答案。
- **排障抓手**：`nm` 里找 `__cxa_atexit`/`atexit` 引用可断言静态注册存在；
  MSVC 侧看 `__dyn_init`/CRT init 段 ⚠️（本机无 VS，文档口径）。
