## 核心概念速览（中英对照）

- **函数语义学** — function semantics：成员函数=「加了 this 参数的普通函数」+ 一套绑定策略
- **静态绑定** — static binding：调用目标在编译/链接期定死（非虚函数、自由函数、构造/析构体内的虚调用）
- **动态绑定** — dynamic binding：目标=运行期 vtable 槽内容（虚函数经基类引用/指针调用时）
- **this 传参** — `this` as first argument：实测 x64 反汇编里 `this` 走首参寄存器（Microsoft x64 的 `rcx`），成员函数不占对象空间（02 篇）
- **默认实参静态绑定** — default argument static binding：虚函数的默认实参按**静态类型**取——经典多态陷阱 No.1
- **运行时类型信息** — RTTI：`typeid`/`dynamic_cast` 依赖的 typeinfo 元数据体系；vtable 头部挂着它（01 篇实测 `__si_class_type_info` 符号同屏）
- **`dynamic_cast` 下行检查** — checked downcast：沿继承图比对 typeinfo，失败指针版返 `nullptr`/引用版抛 `bad_cast`
- **内联扩展** — inline expansion of virtuals：静态类型已知（如 `Derived d; d.f();`）或 `final`/去虚化后，虚调用就地展开为直调/内联
- **`-fno-rtti`**：工业大项目（LLVM 等）常关 RTTI 省码与提速度，用 `llvm::dyn_cast` 式手写类型标签替代

## 动机：把「调到谁」拆成两条时间线

03/04 篇看清了 vcall 的**指令形态**；本章回答**语义分岔**：同样是 `p->f()`，
什么时候编译器敢写死地址、什么时候必须查表、什么时候查的是另一张「表」（typeinfo）。
把静态/动态绑定两条时间线分开，后面所有「多态陷阱」（默认实参、private virtual、
构造期调用）都只是「把错误的时间线套到了这个调用上」。

## 机制一：绑定分岔的判别程序 🔧已实测

判别只有三步（实测指令形态与 01 篇同款）：

1. **函数是不是虚的**（声明链上有 `virtual`）；
2. **调用是不是经基类的指针/引用**——`Derived d; d.f();` 类型已知，GCC 直接内联展开
   （实测 `-O0` 下同样消失，静态类型即动态类型的**语法事实**，不是优化施舍）；
3. **在不在构造/析构上下文**——在，则强制降回当前层（见机制四）。

非虚成员 → `call _ZN4Base1gEv`（链接期符号直调）；虚+基类通道 → `mov (%rax),%rax; call *%rdx`。
**动态绑定是「指针/引用的静态类型 < 对象动态类型」时的追偿机制**，不是虚函数的日常形态。

## 机制二：RTTI——表头的第二张表 🔧已实测

```cpp
struct B{ int v; B(){ /* 构造内 */ g("B ctor"); } virtual void g(const char* s){ printf("B::g %s %s\n", s, typeid(*this).name()); } };
struct D : B{ D(){ g("D ctor"); } void g(const char* s) override { printf("D::g %s %s\n", s, typeid(*this).name()); } };
```

实测输出（`-std=gnu++98` 与 `-std=gnu++23` 行为一致，仅 `override` 语法有无之别）：

```text
B::g B ctor 1B      // typeid(*this) 构造期「跟着表走」：此刻 vptr 还是 B 的
D::g D ctor 1D
```

- `typeid(*p)`（p 为基类指针、指向 D）实测打印 `1D`——**对多态对象** typeid 走动态判定
  （实现上即读 vptr 指向的表头 typeinfo）；对非多态类型/表达式则静态（`typeid(*p)` 里 p 是
  非虚类的情况就是静态——这是最常被误读的分支）。
- `dynamic_cast<D*>(p)==&d` 实测 `ok`：下行转型沿 typeinfo 链查「是不是我」，
  多继承下还要带着 04 篇的偏移调整返回正确的 D 地址——所以它比 `static_cast` 贵一个量级。
- 链接产物印证：`nm` 里 `_ZTV7Derived` 与 `__si_class_type_info` 构造引用同屏（01 篇实测）——
  RTTI 与 vtable 是**同一份表头数据的两个视图**。MSVC 的 locator 列排布与 Itanium 不同 ⚠️ 文档口径。

## 机制三：多态陷阱集——全是时间线错配

- **默认实参静态绑定**：`B::vf(int i = 1)` 被 `D::vf(int i = 2)` 覆写；`B* p=&d; p->vf();`
  实测调到 `D::vf`（动态）却收到 `1`（默认值按 p 的静态类型取）——书与 Effective 系皆列为大忌；
  解法：NVInterface（非虚接口 + 虚实现），把参数层钉在静态面上
  （对照 [../深度探索C++对象模型/04-Function语意学.md](../深度探索C++对象模型/04-Function语意学.md) 与
  [../More%20Effective%20C++.md](../More%20Effective%20C++.md)）。
- **private virtual 之雷**：基类私有虚函数可被派生类**同名同签名函数覆写**（vtable 按签名配对，
  不经名字查找），于是「看似私有的实现」被外面接管；堵法：接口公开化 + 用 `final` 锁定，或干脆
  避免依赖私有虚（More Effective 系语）。
- **函数重载与覆写同名的解析顺序**：名字找到即停（04 篇平局规则的延伸）——派生类
  只声明 `f(int)` 会**隐藏**基类 `f()`；`using Base::f;` 是标准解药。

## 机制四：构造/析构期的绑定降格（与 08 篇交界）🔧已实测

机制二输出已给出铁证：B 构造里调虚函数，落的是 `B::g`。机器解释（08 篇展开）：
**构造期间 vptr 由构造函数逐段重指**——此刻它仍指向「当前层」的表，
于是「派生类尚未出生」的状态不可能被虚调用误触。析构镜像同理。
这条「时间线第 3 步」是纯虚在构造里被调→未定义行为/`__cxa_pure_virtual` 的根源。

## 权衡：动态绑定的税与 RTTI 的税

| | 静态绑定 | vcall | typeid/dynamic_cast |
| --- | --- | --- | --- |
| 时点 | 编译/链接 | 运行 | 运行（元数据比对） |
| 成本 | 0 | 2 load+间接跳转 | 表头再走链，多继承更贵 |
| 谁付 | 所有人 | 多态通道 | 用了才付；`-fno-rtti` 可整类免单 |

工业取舍：LLVM 全局 `-fno-rtti` + 手写 `llvm::cast_info` 标签（`dyn_cast`）；
游戏引擎热路径把 vcall 换成 `switch`+指针表（03 篇手动 vcall 的合法化变体）。
代价对比的量化研究（vcall vs 解释器式表分派）在社区基准（如 v8 的 handler 表、
ECS 库的 archetype 分派）反复出现——没有单篇公认 DOI，此处不冒引 ⚠️。

## 相邻概念对比

- **绑定（binding）vs 决议（overload resolution）**：决议发生在「选哪个函数体」，
  绑定发生在「这个调用体地址何时钉死」；虚函数是「决议静态、目标动态」的分裂态。
- **`static_cast` vs `dynamic_cast` vs C 风格**：前者信任静态类型（含 04 篇偏移调整，零检查）、
  中者查表、后者是前两者的无纪律混合——对象模型视角是「谁对布局/表头负责」。
- **RTTI vs `std::variant` 访问者**：后者把「运行时类型」显式化成判别式，编译期枚举全部候选——
  C++17 后多态的第二条路（对照 [../C++20设计模式/14-模板方法与访问者.md](../C++20设计模式/14-模板方法与访问者.md)）。

## 最新演进与工业实践

- **教材滞后点补位**：语言层对绑定/RTTI 规则在 C++11→23 间几乎零改动（这正是对象模型内容的保质期）；
  可确证的演进集中在**编译器侧**：去虚化武器库（03 篇所引论文，DOI 10.1145/3135932.3135947，
  Crossref 实测）与 **CFI**：Clang `-fsanitize=cfi` 给间接 call 加类型守卫——vtable/typeinfo
  元数据在安全域的第二春。
- **工业样本**：libstdc++ 的 `__cxa_demangle`（实测输出 `1D` 即 itanium mangling 的 typeinfo 名，
  demangle 后才是 `D`）——排障工具链必配；Qt 元对象系统（moc）本质是**自带 RTTI 替代表**，
  先于 C++11 实现了信号槽级别的动态类型查询，对照 [../C++新经典_设计模式.md](../C++新经典_设计模式.md) 的模式语境。
