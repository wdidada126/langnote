## 核心概念速览（中英对照）

- **模板实例化** — template instantiation：把「类型参数化的蓝图」物化为真实函数/类代码的过程——模板章的 vtable 时刻
- **按需惰性实例化** — lazy (use-on) instantiation：类模板**只实例化被用到的成员函数**（实测：不调 `unused()` 则其中错误不报）
- **隐式实例化** — implicit instantiation：使用点触发、由编译器在**每个 TU** 各自生成
- **显式实例化定义** — explicit instantiation definition：`template struct Box<int>;` 把代码收进单一 TU
- **外部模板声明** — `extern template`（C++11）：告诉其余 TU「别再实例化，链接期找我」——实测 nm 里 `T`→`U`
- **弱符号/COMDAT 折叠** — weak symbol / COMDAT folding：多 TU 重复产物由链接器合一——「重复但不冲突」的机制名
- **模板代码的可见性契约** — header-only contract：隐式路线要求定义随声明可达——头文件膨胀的制度根源
- **类模板实参推导** — CTAD（C++17，P0091R3）：`Box b{42}` 免写 `Box<int>`
- **概念** — concepts（C++20）：把「实例化点才炸」的错误前移为「约束不满足即拒」，SFINAE 的正规军替代
- **两阶段名字查找** — two-phase name lookup：模板内非依赖名在定义期查、依赖名在实例化期查（GCC 严格、MSVC 历史宽松 ⚠️ 现状以文档为准）

## 动机：模板没有「运行时」——它的全部魔法发生在编译/链接期

前六章的对象模型好歹在加载出的镜像里看得见（01 篇方法论）；模板的产物在**符号表**里：
同一个 `Box<int>::show` 可能出现在 37 个 `.o` 中，链接器负责收拾。
第 7 章（全书压轴）因此不是「再讲一点语法」，而是把**实例化时机、重复与抑制、多文件组织**
这套链接期经济学讲完——也是教材与工业工程（编译时间、二进制体积）接缝最多的一章。

## 机制一：惰性实例化的边界 🔧已实测

```cpp
template<class T> struct Box{
  void used(){ }
  void unused(){ static_assert(sizeof(T)==0, "boom"); }
};
int main(){ Box<int> b; b.used(); }          // 编译通过
// 改成 b.unused(); → 同一行立即报错：static assertion failed: boom
```

- `Box<int>` 本身「存在」≠ 全部成员「存在」：**用点才物化**（函数模板同理：推导出实参才实例化本体）。
- 两个直接工程后果：① 未调用成员里的语法/类型错误**静默逃逸**——泛型库的暗雷必须靠
  显式实例化或 concepts 要求来照；② 只要不碰，重依赖成员不拖编译时间——
  「把慢的放旁边」策略空间由此而来。
- 类模板与函数模板的分野一句话：**类的「定义」在被使用时实例化，但成员各自再用各自触发**；
  函数模板则一旦选中推导就实例化整个函数体。

## 机制二：隐式重复实例化与 `extern template` 🔧已实测（nm 对比）

单 TU 内两个函数先后用 `Box<int>::show`，`nm e9_tpl.o` 只见一份（编译器 TU 内已合一）；
**跨 TU** 才是主战场：

```cpp
// box.h
template<class T> struct Box { T v; void show(); };
extern template struct Box<int>;        // 抑制声明：本 TU 们，别再生成
// box_inst.cpp
template struct Box<int>;               // 唯一定义点：代码进这里
// use1.cpp / use2.cpp：#include "box.h" 后调用 b.show();
```

实测 `nm`：
```text
box_inst.o:  .text$_ZN3BoxIiE4showEv    // 定义落此
use1.o:      U _ZN3BoxIiE4showEv        // 外部模板生效：只剩未定义引用
```

没有 `extern template` 时，use1.o/use2.o 各自带一份折叠前的完整机器码（链接器再挑一份）——
这就是「模板代码全在头里 → 编译时间爆炸 → 二进制里 60% 是重复合体」链条的中间环节。
收益侧：TU 编译提速、体积去重；赌注侧：**实例化点若含只在该 TU 可见的特化/局部类型**，
extern 声明与实际生成不一致会翻车（ODR 灰色区）。
Linux/ELF 侧的对应物是 weak 符号（nm 显示 `W`，链接器合并）⚠️ 本机 win32 已用 COMDAT 段名演示同一事实；
MSVC 无 `extern template` 年代靠 `/OPT:ICF` 事后折叠——三家殊途同归，书取 MSVC 视角。

## 机制三：实例化是「成本中心」——编译时间与体积的账

模板程序的时间花在：解析（头文件）→ 实例化（每个使用点）→ 代码生成 → **链接期折叠**。
工具抓手（2026 现实）：`clang -ftime-trace` 直接画出三段时间饼；`-fdump-stats`（GCC 14 系）
统计符号体积分布；链接器 `--print-map` 看折叠前后。
「把 `Box<int>` 收进库 + extern 声明」是机制二的规模化形态——标准库自己就这么干
（libstdc++/MSVC STL 对 `locale`、`codecvt` 等热点模板有显式实例化清单文件 ⚠️ 清单细节按各库文档）。
STL 侧的实例化经济学另见 [../STL源码剖析/01-STL概论与版本简介.md](../STL源码剖析/01-STL概论与版本简介.md)
（SGI 时代「函数模板尽量收进 .cpp」的设计自述）。

## 相邻概念对比

- **实例化 vs 重载决议**：决议选「哪个模板/哪个函数」，实例化把选中的**生成出来**；
  「模板专一匹配」错误多卡在决议，「依赖名报错」卡在实例化——排障先分层。
- **显式特化 vs 重载 vs 约束**：三件旧/新利器——特化改蓝图本身、重载换候选、
  concepts 只**筛候选**不改生成（这是「概念不改变实例化语义、只改变可懂度」的一句话版本）。
- **模板 vs 虚函数**：编译期多态与运行期多态的成本结构对照（vtable 税 vs 每 TU 重复码税），
  回到 03 篇；两线合并的工业样本：CRTP（静态多态）。

## 最新演进与工业实践

- **C++17 CTAD**（P0091R3，wg21 短链实测 302）：推导指南补齐「用点免写参数」；
- **C++20 concepts**：把机制一第 2 条「未用成员错误静默逃逸」与 SFINAE 可读性问题一并工程化解决；
  `Box` 加约束的等价写法与错误信息前后对比，是本章在 2026 的最值得补课时；
  C++23 起标准库全面以 concepts 表述要求（ranges 约束体系）；
- **C++20 modules**：模板实例化仍在消费者 TU 发生，但**接口可达性**由 BMI 接管——
  机制二的「头文件传染」在新体系里转化为分区/可见性设计问题 ⚠️ 工具链尚在成熟期；
- **工业样本**：fmtlib/`std::format` 用「把格式化核心收进非模板 extern 链接核 + 薄模板壳」
  驯服模板膨胀（编译时间敏感库的标准手法，机制三的当代名案）；
  Eigen/Blaze 反向而行（全模板换内联质量）——一控一放，权衡坐标即本篇；
