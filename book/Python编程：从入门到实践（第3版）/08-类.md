## 核心精讲

教学示意，不参与构建：

```python
class Dog:
    def __init__(self, name, age):   # 构造器
        self.name = name
        self.age = age

    def sit(self):                    # 方法
        return f"{self.name} is sitting."

my_dog = Dog("Willie", 6)
print(my_dog.sit())

# 继承
class SourcedDog(Dog):
    def __init__(self, name, age, source):
        super().__init__(name, age)   # 无参 super()（3.x 推荐）
        self.source = source

    def sit(self):                     # 重写
        return f"{self.name} (from {self.source}) sits."
```

## 版本演进

- 3.x：`super()` 无参形式（自动推断）已成常态，原书若写 `super(Child, self)` 属旧式但合法。
- 3.7 `__init_subclass__`（PEP 487）提供元类轻量替代。
- 3.10 `dataclasses`（PEP 557，3.7 引入）可替代手写样板类：`@dataclass class Point: x: int; y: int`。
- 3.12 `@override`（PEP 698）让「确实重写了父类方法」可被静态检查。

## 近年研究与工业界开源实践（2015–2026）

- 大量「纯数据」类用 `dataclasses`/`pydantic` 取代手写 `__init__`。
- 优先组合而非继承；接口用 `typing.Protocol`（PEP 544）而非强制基类。

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
|---|---|---|
| `super(Child, self)` 显式调 | 旧式冗余 | 用无参 `super()` |
| 所有建模都用类 | 简单数据用类过重 | 用 `dataclass`/namedtuple/`TypedDict` |
| 深继承层级 | 脆弱、难改 | 组合 + Protocol |
| 公开属性随意改 | 不封装 | 需保护用 `_name` 约定或 property |
