## 核心精讲

教学示意，不参与构建：

```python
# 被测函数
def get_formatted_name(first, last):
    return f"{first} {last}".title()

# 用 pytest（推荐）：以 test_ 开头，用 assert
def test_format():
    assert get_formatted_name("ada", "lovelace") == "Ada Lovelace"

# 用 unittest（标准库）
import unittest
class NamesTestCase(unittest.TestCase):
    def test_full(self):
        self.assertEqual(get_formatted_name("a", "b"), "A B")
    def setUp(self):
        self.sample = "x"
```

运行：`pip install pytest && pytest`（pytest 自动收集 `test_*`）。

## 版本演进

- `unittest` 自 2.1 即有；今天仍可用但写法繁琐。
- 🟢 **pytest 是事实标准**：fixture、`@pytest.mark.parametrize`、`pytest.raises` 捕获异常。
- 3.11 `ExceptionGroup`（PEP 654）让「多处断言失败一起报告」更自然。
- 类型检查 `mypy`/`pyright` 与 lint `ruff` 是测试的补充层。

## 近年研究与工业界开源实践（2015–2026）

- CI（GitHub Actions）里 `ruff + mypy + pytest` 三件套成标配。
- 属性测试 `hypothesis`、覆盖率 `coverage.py`、性能 `pytest-benchmark`。
- 异步测试用 `pytest-asyncio`/`anyio`。

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
|---|---|---|
| 主推 unittest | 行业已转 pytest | 新项目用 pytest；unittest 仅维护旧代码 |
| 测试靠 print | 不可回归 | 用 assert + 测试框架 |
| 忽略类型检查 | 漏一类错误 | 加 mypy/pyright |
| 测试只在本地跑 | 易遗忘 | CI 自动跑 |
