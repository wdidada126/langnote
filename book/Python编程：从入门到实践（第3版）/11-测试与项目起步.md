## 核心精讲

教学示意，不参与构建：

```python
# 项目推荐结构
# alien_invasion/
#   alien_invasion.py     # 入口
#   settings.py           # 配置
#   ship.py               # 飞船类
#   game_functions.py     # 辅助函数
#   test_game_functions.py

# 给一个纯函数写 pytest
def add_score(current, gained):
    return current + gained

def test_add_score():
    assert add_score(0, 100) == 100
    assert add_score(50, 50) == 100
```

运行：`cd alien_invasion && pip install pytest pygame && pytest`。

## 版本演进

- 原书用 `unittest` 起步；今天直接用 pytest 更顺（见 [10-测试代码.md](10-测试代码.md)）。
- `pyproject.toml`（PEP 621）放项目元数据与 pytest 配置：`[tool.pytest.ini_options] testpaths = ["."]`。

## 近年研究与工业界开源实践（2015–2026）

- 游戏/项目用 `pyproject.toml` + `uv` 管理依赖，替代裸 `pip install`。
- 测试优先（TDD）在大型项目里普遍。

## 常见误区与本书需修正之处

| 原书说法 | 问题 | 2026 正确写法 |
|---|---|---|
| 用 unittest 起手 | 繁琐 | pytest 起手 |
| 项目无依赖锁定 | 换机跑不起来 | 用 `uv`/`pip-tools` 锁 `requirements` |
| 把所有逻辑堆一个文件 | 难测 | 按职责拆模块 + 测试 |
