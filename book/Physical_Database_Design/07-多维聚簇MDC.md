# 第 8 章 · 多维聚簇 MDC（Multidimensional Clustering）

> 精读重构，非原书文本。页 143–166。元数据与取证见 [00-总览与阅读地图.md](./00-总览与阅读地图.md)。

## 本章定位

本书最具"IBM 特色"的一章：MDC 是 DB2 UDB 的私有物理组织（表被切成**块**，块由若干维度列的值组合定义），对应第 2 章的"块/扩展索引"与第 3 章的 FETCH 代价——**用多维物理共位替代索引回表**。2026 年回望，它是所有"micro-partition + zonemap / 稀疏主索引"方案的直系祖先。

## 精读重构要点

### 8.1 结构：块、维度、块索引

- 普通表：行按插入序散落，聚簇索引只沿**一维**排列行；范围分区也只沿**一维**切。MDC 的动机：分析负载同时带多个低基数维度谓词（date、region、product_line、channel），一维聚簇照顾不了其余维度。
- 机制：为表声明**聚簇维度列**（可多个）；插入时行落入"维度值组合"对应的块（block，块 = 页的连续组，块大小可调）；同一维度组合的行物理共位。
- **块索引（block index）**：每维度每块一个位图条目（哪块含有值 v）——位图思想搬到块粒度；多维谓词做块位图 AND，得到候选块集，然后只读候选块。
- 块内不再需要每维度建完整 B+ 树；高基数列或精确点查仍配普通行级索引（块索引负责"粗筛到块"，行索引负责"细定位到行"）。

### 8.2 收益来源与代价模型位置

- 收益 = 扫描削减：候选块数 / 总块数 远小于谓词行选择性时，I/O 近似"只读相关块"——本质是把第 3 章的聚簇比从一维推广到多维（见 [03-查询优化与计划选择.md](./03-查询优化与计划选择.md)）。
- 代价：
  - **空间**：块按维度组合数膨胀（组合数 = Π NDV_dim），稀疏组合产生空洞块；作者给的空间开销分析与"维度选择纪律"（只选低基数、强相关于负载的列）是本章最有复用价值的方法论；
  - **写路径**：插入需要块路由与块索引维护，高维组合下插入尖峰明显；
  - **块大小权衡**：大 I/O 友好但空洞多；小空间友好但元数据膨胀。

### 8.3 MDC vs 范围分区 vs 一维聚簇（重建对比表）

| 维度 | 范围分区（第 7 章） | 聚簇索引/表 | MDC（本章） |
|---|---|---|---|
| 切分依据 | 一维值域 | 一维键序 | 多维值组合 |
| 运维语义 | 滚动生命周期/备份 | 弱 | 中（块重组 REORG） |
| 查询语义 | 单维剪枝 | 单维 FETCH 摊薄 | 多维粗筛 |
| 空间风险 | 低 | 低 | 空洞膨胀 |
| 典型负载 | 时序大表 | OLTP 主访问 | 星型分析 |

- 结论式立场：负载带**≥2 个常用低基数维度**且空间预算允许时 MDC 占优；单维时序主谓词用范围分区；OLTP 保持一维聚簇/普通表 + 二级索引。
- 维护操作：块需要 REORG/consolidate 回收空洞——"聚簇质量"是随时间衰减的状态量（为第 9 章动态负载讨论铺垫，见 [08-相互依赖问题与计数抽样.md](./08-相互依赖问题与计数抽样.md)）。

### 8.4 设计流程（与第 4 章拼合）

MDC 维度选择同样走"负载抽取 → 维度组合候选 → what-if（块数估计 → 剪枝收益）→ 空间预算截断"流程；块索引与行级索引、物化视图之间存在顶替关系——三者在预算内联合选择才是完整解（这正是第 9/12 章的论题）。

## 阅读提示（2026 视角）

MDC 作为产品特性始终未出 DB2，但作为**思想**统治了当代扫描型引擎：块 ≈ row group / micro-partition；块索引位图 ≈ zonemap/min-max + bitmap skipping；"维度组合共位" ≈ clustering key / liquid clustering / sort key。读本章等于读 zonemap 的 2007 年原型。

## 🔧 本机实测（DuckDB 1.5.5）

方法：400 万行表，列 a 递增有序建表（物理有序 ≈ 完美聚簇）vs 打乱建表（a=random）；查询 `SELECT count(b) FROM t WHERE a BETWEEN 100000 AND 130000`（命中约 3 万行），各 5 次均值。

- 有序：1.70ms；乱序：4.27ms——同一数据同一查询，**仅物理布局差异**约 2.5 倍。
- 机制归因：行组级 min/max 统计剪枝（zonemap）：有序时每行组值域不重叠、命中行组极少；乱序时每个行组 min/max 都覆盖查询区间、全量扫描。**这即是本章块索引/8.2 收益模型的现代等价**，也验证了 [06-分区·共享无度与范围分区.md](./06-分区·共享无度与范围分区.md) 的"剪枝收益 = 布局与谓词相关性"论断。

## 本章论证链

1. 分析负载的特征是**多低基数维度同时过滤**，一维聚簇/一维分区结构上照顾不全；
2. MDC 的解法：把"共位"从一维推广到多维——行按维度组合落块，块索引做粗筛；
3. 收益与负载维度数正相关、与空间膨胀（Π NDV）负相关 → 维度选择纪律是本章最难的外课；
4. 与范围分区/聚簇索引不是替代而是**分工**（8.3 对比表）：运维语义、单维主谓词、多维粗筛各管一段；
5. 聚簇质量随插入衰减（空洞/漂移）→ MDC 把"物理布局"变成需要持续运维的**状态量**——这一观点直接通到 2026 年湖仓的 rewrite/clustering 维护作业。

## 典型场景重构（示例，数字非原书 ⚠️）

- 场景 A（MDC 完胜）：10 亿行销售事实表，90% 查询带 `region AND product_line AND quarter`，三列各 <200 值——三个单列 B+ 树互相拖累（AND 合并成本高），MDC 一次块 AND 读 3% 的块；
- 场景 B（MDC 反噬）：把高基数 `customer_id` 选进聚簇维度 → 组合数爆炸、几乎每行一块 → 块索引巨大+空洞率 90%——**维度必须是低基数且成组出现在谓词里**；
- 场景 C（与分区协作）：事实表按日期范围分区（滚动装载）+ 分区内按 (region,channel) MDC——布局三问（06 文件）的标准答案组合。

## 常见误读

- 把 MDC 读成"DB2 古董"：块/位图粗筛的骨架在 zonemap/micro-partition/liquid clustering 里活着（见"最新演进"节），🔧 实测的 2.5× 差距就是它的现代显灵；
- 忽视空洞成本把 MDC 当免费午餐：维度组合的笛卡尔积是真实预算项；
- 以为 MDC 消灭行级索引：粗筛到块 ≠ 定位到行——高价值查询仍需行索引补刀（8.4）。

## 核心概念速览（中英对照）

- **多维聚簇** — Multidimensional Clustering (MDC)：按多维值组合把行共位在块内的表物理组织
- **块** — Block：MDC 的存储单元，页的连续组，由维度值组合标识
- **块索引** — Block Index：维度值→块的位图映射，多维谓词 AND 粗筛
- **维度选择** — Dimension Selection：低基数、多谓词、负载相关的聚簇维度挑选纪律
- **空洞块** — Sparse/Hollow Block：维度组合未用满造成的空间膨胀
- **块大小** — Block Size：I/O 摊薄与空间浪费的调节旋钮
- **聚簇衰减** — Clustering Decay：插入/更新使布局偏离理想维度共位的渐进退化
- **REORG/块整合** — Block Consolidation：回收空洞、恢复聚簇质量的维护操作
- **粗筛+细定位** — Two-tier Filtering：块索引粗到块、行索引细到行的分工
- **顶替关系** — Subsumption across Structures：MDC、索引、视图在同一预算内互相替代
- **布局相关性收益** — Layout-Predicate Correlation：剪枝收益的本质来源（🔧 实测 2.5×）
- **micro-partition** — Micro-partition：MDC 块的当代直系后代（Snowflake/DuckDB 行组）

## 最新演进与工业实践

- **zonemap/稀疏索引成为扫描引擎标配**：DuckDB 行组 min/max（🔧 上节实测）、ClickHouse 稀疏主索引 + skip index、Oracle Exadata Storage Index、PG BRIN（块级值域索引，思想即"块索引"；官方文档入口 https://www.postgresql.org/docs/current/ ✅ 域名可达，BRIN 专页名 ⚠️ 未逐页验证）——"按块排除"从 DB2 私有特性变成开源共识。
- **聚簇键产品化**：Snowflake clustering key + automatic reclustering、BigQuery 分区表 + 簇列、Databricks **Liquid Clustering**（2024 起替代"改分区表达式"路线，clustering 可在线演化，ZORDER 物理共位多维值——本章 8.3 对比表与 8.4 流程的当代实现）⚠️ 转述，官方文档 URL 本机不可达。
- **Iceberg 侧的等价物**：sort order 表属性 + `rewrite_table_data` 维护作业做"聚簇质量恢复"（对应 8.3 的 REORG 衰减问题）；规范见 https://iceberg.apache.org/spec/ （✅ 可达），repo 深读 [../Apache_Iceberg活用入門/08-表维护操作.md](../Apache_Iceberg活用入門/08-表维护操作.md)。
- **Z-Order/Hilbert 多维布局**：MDC 用"块哈希到维度组合"，当代用空间填充曲线（Z-Order）近似同一目标；Delta/Iceberg/Spark 的 `DistributeBy(zorder)` 类实践 ⚠️ 转述。
