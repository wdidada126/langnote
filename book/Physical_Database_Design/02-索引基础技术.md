# 第 2 章 · 索引基础技术（Basic Indexing Methods）

> 精读重构，非原书文本。页 15–29。元数据与取证见 [00-总览与阅读地图.md](./00-总览与阅读地图.md)。

## 本章定位

全书索引线的"词典章"：把 DB2（及其时代理所当然覆盖的各商用库）的索引类型一次摆清——为第 4 章"选择"和第 9/11 章"代价"提供词汇。注意本书是**设计者视角**的索引分类学，不是实现视角（实现去 [../Database_Internals/02-B树基础.md](../Database_Internals/02-B树基础.md) 和 [../mysql/06-B树索引.md](../mysql/06-B树索引.md)）。

## 精读重构要点

### 2.1 B+ 树索引的一般形状

- 条目 = 键值 + RID（行定位器，页号:槽号）；叶子层链表支持范围扫描；非叶子仅导航。
- 关键设计变量（本章埋线，后续章收账）：
  - **复合键的顺序**（哪个列在前）→ 影响可服务的谓词形态（第 4 章）；
  - **是否覆盖**（INCLUDE/追加尾列）→ 消灭回表 → 第 11 章 FETCH 代价；
  - **聚簇程度**（clustering）→ 回表命中率 → 与第 7/8 章分区/聚簇直接联动。
- Dense/Sparse：二级索引实践上几乎全 dense（每键一入口），sparse 只在聚簇组织的第一键层出现——教材口径见 [../数据库系统概念6/11-索引与散列.md](../数据库系统概念6/11-索引与散列.md)。

### 2.2 索引家族清单（按本章展开顺序重构）

- **唯一索引 / 非唯一索引**：唯一性既是约束也是键扩展技巧的入口（非唯一索引以 RID 补尾键保唯一）。
- **复合索引（Composite/Multi-column）**：最左前缀法则；等值列在前、范围列殿后；ORDER BY 对齐省排序。
- **降序索引（DESC index）**：服务 `ORDER BY a ASC, b DESC` 这类混合方向。
- **位图索引（Bitmap index）**：每个键值一个位向量，按页/块压缩存储；低基数列（性别、状态码）上的扫描与位运算神器，**写并发差**（锁整个位向量的粒度问题）——OLAP 专用武器，对应第 14 章数仓场景（见 [12-数据仓库OLAP与反范式化.md](./12-数据仓库OLAP与反范式化.md)）。
- **倒排索引（Text search index）**：词项 → 文档列表，服务 CONTAINS/全文检索，属性上一般不算"普通二级索引"。
- **XML 层级索引（hierarchy index）**：DB2 pureXML 时代特色，路径表达式求值用；今天读来可平移到 JSON 多值索引/函数索引。
- **扩展索引 / 聚类扩展（Cluster/Extent indexing）**：以页或块（extent）为粒度的粗粒度索引条目——这是 MDC 块索引（第 8 章，见 [07-多维聚簇MDC.md](./07-多维聚簇MDC.md)）的近亲。
- **哈希索引**：等值极速、无范围能力；在分区里作为分布手段（第 6 章哈希分区）比作为访问方法更重要（见 [06-分区·共享无度与范围分区.md](./06-分区·共享无度与范围分区.md)）。

### 2.3 类型选择的粗规则（重建）

- 高基数 + 选择性点查/范围 → B+ 树；
- 低基数 + 大表扫描/多谓词组合 → 位图；
- 覆盖需求 → 复合 + 附加列；
- 表达式谓词（函数包列）→ 函数索引/表达式索引（DB2 GENERATED 列 + 索引是等价路线）；
- 混合方向排序 → 降序复合索引。
- 章末立场：**索引类型决定"能不能"，索引选择决定"值不值"**——把"值不值"全部推给第 4/9/10 章。

### 2.4 索引的隐性代价清单

写放大（每索引每 DML 一次额外维护）、空间、优化器计划扰动（新索引可能诱发坏计划）、备份/重加载窗口、统计维护义务。清单式列出，为第 12 章自动设计器的"净收益"评估铺垫。

## 阅读提示（2026 视角）

本章的"类型清单"如今已膨胀为**索引超市**（PG 一家就有 btree/hash/GIN/GiST/SP-GiST/BRIN），但本章的**决策语法**（基数×负载形态→类型）仍然有效且更稀缺：2026 年的自动索引器做的正是这套粗规则的机器化。

## 🔧 本机实测（SQLite 3.45.3）

方法：30 万行表 `t(a,b,c)`，查询 `SELECT b FROM t WHERE a BETWEEN 100000 AND 110000`；对照普通二级索引 `ix_a(a)` vs 覆盖索引 `ix_ab(a,b)`，20 次均值。

- 计划差异（EXPLAIN QUERY PLAN 实抓）：`SEARCH t USING INDEX ix_a (a>? AND a<?)` vs `SEARCH t2 USING COVERING INDEX ix_ab (a>? AND a<?)`——SQLite 显式标注 COVERING，即"消灭回表"。
- 耗时：非覆盖 5.520ms vs 覆盖 4.716ms（本机同规模下约 15% 收益；表越大/行越宽收益越高——回表在 DB2 语境叫 FETCH，见 [09-查询执行计划与物理设计.md](./09-查询执行计划与物理设计.md)）。
- 部分索引验证：`CREATE INDEX ix_part ON t2(c) WHERE a % 100 = 0` 仅当查询带 `a % 100 = 0` 谓词时被选用（`SEARCH t2 USING INDEX ix_part (c=?)`），否则回退 `SCAN t2`——"索引只服务它能证明的子集"，与本章谓词形态匹配思想一致。

## 典型场景重构（示例，数字非原书 ⚠️）

- 场景 A（低基数列组合过滤）：1 亿行订单表，`status`(5 值)+`channel`(20 值) 组合谓词——三个单列 B+ 树互相拖腿（AND 合并位图化才公平），位图索引一个顶仨；但若该表每秒数百更新，位图立刻不可用（写退化）→ 位图只在装载后建或数仓表上用；
- 场景 B（列表页排序）：`ORDER BY ts DESC LIMIT 20` 高频——降序复合索引或反向扫描 B+ 树可把"全表排序"变成"取前 20 个键"，是本章"方向性"条目最赚钱的用法；
- 场景 C（半结构谓词）：JSON 路径过滤——函数索引/表达式索引（DB2 GENERATED ALWAYS AS 列 + 索引）是 2007 年给"hierarchy index 之外"的标准答案，今天对应 PG jsonb GIN / MySQL 多值索引。

## 常见误读

- 把本章当"索引实现详解"：磁盘格式/分裂去 Database_Internals；本章只管**选型词汇表**；
- 认为索引类型可以"后期再加"：位图 vs B+ 树的选择牵动**写路径与锁模型**，是结构性决定，后期换型=重做物理设计；
- 忽视 DB2 特色条目（hie/扩展索引）的价值：它们是第 8 章 MDC 块索引的**前置概念**，跳过 2.2 后半将读不懂 07 文件。

## 核心概念速览（中英对照）

- **B+ 树索引** — B+-tree index：键序叶子链表结构，点查与范围扫描通吃的默认索引
- **RID** — Record Identifier：行物理定位符（页号+槽号），二级索引条目的载荷
- **复合索引** — Composite index：多列拼接键，最左前缀决定可用谓词形态
- **覆盖索引** — Covering index：键列包含全部所需输出列，免除回表/FETCH
- **降序索引** — Descending index：键含方向，服务混合方向 ORDER BY 免排序
- **位图索引** — Bitmap index：键值→压缩位向量，低基数列大扫描利器、写并发差
- **倒排索引** — Inverted index：词项→文档 postings，全文检索专用结构
- **哈希索引** — Hash index：签名桶等值查找，无范围能力的极端
- **块/扩展索引** — Block/Extent index：以页组为条目粒度的粗索引，MDC 的前置概念
- **写放大** — Write Amplification：每索引对每次 DML 的额外维护写
- **计划扰动** — Plan Perturbation：新索引改变既有查询计划的副作用
- **函数索引** — Function/Expression index：以表达式值为键，服务包装列的谓词

## 最新演进与工业实践

- **索引超市化**：PostgreSQL 的 CREATE INDEX 家族（btree/hash/gist/spgist/gin/brin）与部分索引/覆盖（INCLUDE）已是事实标准，见官方文档 https://www.postgresql.org/docs/18/sql-createindex.html （✅ curl 验证可达）；本书 2.3 的"粗规则"可直接映射到该菜单。
- **位图索引的平民化**：OLAP 引擎把位图思想内建为默认（ClickHouse 的稀疏主索引 + Data Skipping Index、DuckDB 行组 min/max zonemap 🔧 见 [07-多维聚簇MDC.md](./07-多维聚簇MDC.md) 实测节）；专门的 BITMAP 类型在 PG 生态以扩展形式存活 ⚠️ 转述。
- **覆盖/回表的当代对应**：MySQL 8 的二级索引回表代价与 ICP 讲解见 [../mysql/07-B树索引的使用.md](../mysql/07-B树索引的使用.md)；InnoDB 无真 INCLUDE，用"虚拟二级索引列"思路规避 ⚠️ 转述。
- **学习型索引**：The Case for Learned Index Structures（Kraska et al., SIGMOD 2018，DOI 10.1145/3183713.3196909，✅ Crossref 200 校验）提出用模型替代本章 2.1 的 B+ 树导航层；2024–2026 工业落地仍限于只读/低更新键空间（RACE、PGXlearned 类扩展），主流引擎的默认索引仍是 B+ 树 ⚠️ 转述。
- **JSON 时代的"XML 索引"平移**：MySQL 多值索引、PG GIN on jsonb、DuckDB 半结构化 zonemap——本章 hie index 的历史生态位由 json 索引接管。
