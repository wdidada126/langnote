# 01 · 第 1 章 Evolution of Decision Support Systems（决策支持系统的发展）

> 章题与小节题 ✅ 取自 Wiley 官方 Contents PDF；正文为依据 Inmon 公开著述的**精读重构**，非原书文本。

## 1. 本章在全书中的职能

第 1 章是全书的「病理报告」：Inmon 不先定义数据仓库，而是先证明**没有架构的信息环境必然烂掉**。他讲决策支持（DSS）从 1960s 批处理报表到 1980s 随机分析的演化，指出每条路径都停在「取数难」这堵墙前。本章末尾的「Monitoring the Data Warehouse Environment」则提前立起全书的运维基调：环境是被设计出来的，也要被监控着活下去。

## 2. The Evolution：三段式技术驱动（✅ 小节实据）

官方小节序列：`The Evolution → The Advent of DASD → PC/4GL Technology → Enter the Extract Program → The Spider Web`。

- **直接存取存储设备（DASD）出现前**：只有磁带批处理，报表由程序生成为死纸，用户与数据之间隔着穿孔卡。
- **DASD + 查询工具**：用户第一次能「碰」数据；COBOL 抽取程序成为第一代数据服务。
- **PC / 4GL 技术**：取数权下放到桌面，需求爆炸；抽取程序数量从每系统几个变成几百个。
- **蜘蛛网（The Spider Web）**：每一个新需求拉出一根新的抽取管线，操作型系统之间织成网状点对点取数——本章的核心意象，也是 Inmon 全部后续教义要拆掉的东西。

## 3. 自然演化架构的四宗罪（✅ 小节实据）

`Lack of Data Credibility / Problems with Productivity / From Data to Information / A Change in Approach`：

1. **数据不可信**：同一「销售额」在不同抽取管线中有不同过滤条件，管理层会上两个数字打架，最终没人信任何数字。⚠️ 转述 Inmon 通说。
2. **生产率问题**：程序员沦为「取数劳工」，80% 工作量耗在重复抽取；口径没有沉淀，人走口径失。
3. **从数据到信息**：操作型数据库存的是「可更新的业务状态」（当前余额），决策需要的是**历史与集成**（过去六个月的趋势、跨系统的客户视图）——这是两种本质上不同的数据形态，不是同一数据库加台机器。
4. **方法变迁**：Inmon 的诊断——问题不在工具而在**架构**：需要「体系结构化环境」（The Architected Environment，✅ 小节题）。

## 4. Architected Environment 与数据集成

- 架构化环境 = 把「为决策供数」从副业变成有独立设计、独立数据模型、独立生命周期的一等公民环境。
- **数据集成在架构化环境中**（Data Integration in the Architected Environment，✅ 小节题）：集成发生在数据进入环境时（一次性），而不是每次消费时（N 次）——这是 Inmon 与「先存起来用的时候再拼」路线的千年分歧原点，对位湖仓争论见 [../The_Data_Lakehouse/00-总览与阅读地图.md](../The_Data_Lakehouse/00-总览与阅读地图.md)。
- **Who Is the User? / The Development Life Cycle / Patterns of Hardware Utilization**：决策用户与操作用户读写模式互补（读多写少、扫宽行少、高峰在夜间与月初），因此混部必然互相踩踏——为第 14 章「资源竞争」与第 16 章 ODS 埋线。
- **Setting the Stage for Re-engineering**：数据仓库项目是对企业数据的一次再工程，操作型系统反而因此减负（不再伺候取数请求）。

## 5. Monitoring the Data Warehouse Environment

Inmon 的开篇即运维视角：环境要有容量、响应、数据量增长三类监控指标，数仓不是「建成即完成」而是「建成即运营」。对位 2026：可观测性（observability）与数据 SLA 见各章末节。

## 7. 本章金句式论断（⚠️ 依 Inmon 一贯立场重建，非引文）

## 术语溯源小词典

- **Architected Environment**：Inmon 1990s 文章高频词，4 版仍为核心；中文诸译「体系结构化环境/架构化环境」（本目录从机工译「体系结构化环境」✅）。
- **Spider Web**：亦作 spaghetti 类比的前身；两派论战常用其漫画化版本 ⚠️。
- **Extract Program**：COBOL/SQL 宿主时代产物，字面即「抽取程序」，是 ETL 之 E 的前身化石 ⚠️。
- **Data vs Information**：Inmon 的固定对子，非香农信息论用法，指「业务状态」vs「决策燃料」两种数据形态 ⚠️ 立场说明。

## 核心概念速览（中英对照）

- **蜘蛛网架构** — Spider Web Architecture：点对点抽取管线交织成网，口径不可追溯的病根
- **体系结构化环境** — Architected Environment：为决策支持显式设计的集成数据环境，与操作型环境分立
- **数据可信性** — Data Credibility：同一指标全域唯一口径，管理层敢于拍板的前提
- **从数据到信息** — From Data to Information：业务状态（可更新）与历史集成数据（只追加）的形态跃迁
- **决策支持系统** — Decision Support System (DSS)：随机、探索性、跨域的取数与分析需求总称
- **4GL/抽取程序** — Extract Program：仓库化之前服务一次需求的临时取数代码，生产率之坑
- **DASD** — Direct Access Storage Device：磁盘直访，使随机查询成为可能的硬件前提
- **开发与运维分离** — Development Life Cycle (DLC)：环境生命周期中建设阶段与运营阶段的区分
- **环境监控** — Monitoring the Warehouse Environment：容量/响应/增长的常设观测，先于任何 BI 工具
- **再工程舞台** — Setting the Stage for Re-engineering：数仓建设顺带完成企业数据资产的一次系统性重排

## 最新演进与工业实践

- **2026 现状对位（⚠️ 转述）**：「蜘蛛网」的当代形态是 API/作业/Notebook 互相取数的「数据意大利面」；治理话语从 architected environment 迁移到 data platform / data governance。Inmon 的「集成一次、处处复用」仍是数据中台与 lakehouse「统一入口」叙事的底层公理（见 [../大数据之路.md](../大数据之路.md) 与 [../The_Data_Lakehouse/01-让数据可信与基础数据.md](../The_Data_Lakehouse/01-让数据可信与基础数据.md)）。
- **云数仓消解「混部踩踏」的一半**：Snowflake 用独立 virtual warehouse 做读写与负载隔离，BigQuery/Redshift 用独立槽位/并发配额（⚠️ 转述，见 [docs.snowflake.com](https://docs.snowflake.com/en/)，curl 200）。Inmon「操作型与分析型必须分环境」的硬件理由弱化，**逻辑理由（口径与历史）不变**。
- **可观测性产业**：Monte Carlo、Great Expectations 一类数据 SLO 工具承接了本章「monitoring」的教义 ⚠️。
- 🔧 **本机演示（方法可复现）**：用 DuckDB 建两张同源表模拟「两口径打架」——对同一 orders 表分别加 `WHERE amount>50` 与不加过滤做 sum，差异立现；再建唯一一张集成原子表供全部下游查询，对账一致。原型脚本在工程临时目录 `dbwave_bdw/proto_edw.py`（DuckDB 1.5.5，Python）。官方书目与目录实证：[Wiley 产品页](https://www.wiley.com/en-us/Building+the+Data+Warehouse%2C+4th+Edition-p-9780764599446)、[官方 Contents PDF](https://media.wiley.com/product_data/excerpt/45/07645994/0764599445.pdf)。
- **延伸阅读（repo 内）**：[../数据仓库工具箱3.md](../数据仓库工具箱3.md)（对立诊断）、[../数据库系统概念6/20-数据仓库与数据挖掘.md](../数据库系统概念6/20-数据仓库与数据挖掘.md)（中立定义）。
