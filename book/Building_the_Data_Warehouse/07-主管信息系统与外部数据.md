## A 部分 · 第 7 章：主管信息系统（EIS）

### 7.1 EIS 的历史包袱（✅ EIS — The Promise / A Simple Example）

EIS/ESS 是 1980s–90s 的「高管驾驶舱」：预置指标、图形化、下钻。Inmon 写作时的行业现状：EIS 多自建私有数据管道，从操作型系统直接拉数——这恰是他第 1 章批判的蜘蛛网在高管层的变体。本章的任务是把 EIS「接回」仓库地基。

### 7.2 下钻是仓库的合约（✅ Drill-Down Analysis / Supporting the Drill-Down Process）

- 下钻（drill-down）= 从汇总逐级到细节。**EIS 的下钻承诺只有在仓库里才兑现有保证**：汇总层可秒答、细节层原子完整（第 2 章五级架构 + 第 4 章「聚合不可逆」）。
- 支撑下钻的设计要求：聚合路径与仓库分层一一对应、维度键全链路同义——⚠️ 转述其通说（原书此节具体机制未实抓）。
- 与 Kimball 对照：工具箱3 把下钻视为星型的天然特权（维度即下钻轴）；Inmon 说下钻轴由**粒度层**保证，星型只是展示加速——同一 UX，两种本体论（[../数据仓库工具箱3.md](../数据仓库工具箱3.md)）。

### 7.3 事件映射（✅ Event Mapping）

EIS 屏上的红点要能回答「为什么」：事件映射=把 KPI 异动连回仓库中的**事件记录**（第 3 章事件/快照二分），使驾驶舱可审计。2026 对位：指标平台（metrics layer）的血缘下钻（⚠️ 转述，dbt/AtScale 类，[getdbt.com](https://www.getdbt.com/) curl 200）。

### 7.4 「到哪里取数据」与两个错误答案（✅ Where to Turn）

- 错误一：直接从操作型系统拉——高管查询拖垮生产库（第 1 章硬件利用模式）；
- 错误二：EIS 自带影子数据库——口径双轨（第 1 章可信性）；
- 正解：**以仓库为基底**（The Data Warehouse as a Basis for EIS ✅）。

### 7.5 细节数据进 EIS 的悖论（✅ Detailed Data and EIS / Keeping Only Summary Data in the EIS）

Inmon 的名段：EIS 工具里**只存汇总数据是教条，但「细节留在仓库、EIS 按需下钻访问」是合约**——「只存汇总」与「永远取不到细节」是两回事 ⚠️（转述）。对位 2026：BI 工具直连云仓、缓存只存聚合，正是该架构的复刻（⚠️ 转述）。

## B 部分 · 第 8 章：外部数据（External Data）

### 8.1 外部数据入仓的三个理由（✅ External Data in the Data Warehouse）

行业基准（benchmarking）、竞争对手价格/宏观指标/天气等上下文（⚠️ 通说转述）；仓库不止装企业内部史，「内部业绩 vs 外部环境」的对照分析才有决策含金量——这是第 5 章「上下文与内容」的消费端。

### 8.2 存储与建模的不对称（✅ Storing External Data / Modeling and External Data / Different Components of External Data）

- 外部数据**粒度粗、脏、不可重取**（供应商改口径/过期）——与内部原子数据相反；Inmon 主张：外部数据单独主题域、保留原始到货文件（⚠️ 转述）、与内部模型之间**用时间+地域键松耦合**，不做强制外键。
- 2026 对位：这就是数据集市化采购（Snowflake/Databricks Marketplace）、外部源落 bronze 层再清洗的湖仓工序（[../Apache_Hudi_Definitive_Guide/](../Apache_Hudi_Definitive_Guide/)、[delta.io](https://delta.io/)）⚠️。

### 8.3 元数据、二级报告与存档（✅ Metadata and External Data / Secondary Reports / Archiving External Data / Comparing Internal Data to External Data）

- 外部数据**没有装载管道可溯**，故其元数据必须自带出处、版本、许可条款——比内部数据更重（接第 17 章依从：用外部数据做财务对标要留证）。
- 二级报告（secondary reports ✅）：外部数据的再分发合规与呈现层裁剪 ⚠️。
- 内外比较（Comparing Internal Data to External Data ✅）：同名异义（行业「客户流失率」≠自家口径）是基准分析的头号坑——先对齐定义再比数字。

## C · 🔧 合并演示（DuckDB 可复现）

把「EIS 下钻合约」与「外部数据松耦合」压进一个最小实验：内部 `sales_fact_atomic` + 外部基准表 `ext_benchmark(month, region, avg_growth)`（无外键，仅按月+region 连接）；驾驶舱视图只引聚合层，`下钻`即回 `sales_fact_atomic` 逐单（🔧 复用 `dbwave_bdw/proto_edw.py` 的原子表，加一条 JOIN 外部表的月增速对照查询即可重放）。结论（🔧 本机）：聚合层与原子层对账相等保证下钻不撒谎；外部表缺月时 LEFT JOIN 产生 NULL 而非错值——「外部脏但可标注」的最小治理形态。

## 核心概念速览（中英对照）

- **高管信息系统** — Executive Information System (EIS)：预置 KPI+图形化+下钻的高管决策界面
- **下钻分析** — Drill-Down Analysis：从汇总逐级深入细节的交互式查询路径
- **下钻合约** — Drill-Down Contract：汇总可秒答且细节可回查，由仓库分层背书
- **事件映射** — Event Mapping：KPI 异动连回仓库事件记录的审计链
- **以仓库为基底** — Warehouse as Basis for EIS：驾驶舱禁直读操作型、禁自建影子库
- **只存汇总教条** — Keeping Only Summary Data：EIS 端存聚合、细节留仓库的分工论
- **外部数据** — External Data：行业基准/价格/宏观等非企业自产数据
- **不可重取性** — Non-replayable External Data：外部源会变脸，须留原始到货
- **松耦合对接** — Loose Coupling：内外数据以时间+地域键弱连接，禁强制外键
- **二级报告** — Secondary Reports：外部数据的再分发合规与呈现裁剪
- **同名异义坑** — Internal vs External Semantics：基准比较前先对齐定义口径
