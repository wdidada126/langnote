# 11 · 第 13 章 The Relational and the Multidimensional Models as a Basis for Database Design（关系模型和多维模型数据库设计基础）

> 章题与小节题 ✅ 取自 Wiley 官方 Contents PDF；正文为**精读重构**。英文原书约 357–376 页。本章是 Inmon vs Kimball 论战的**主战场文件**：三角互链的正面交锋在此落位。

## 1. 两个模型的各自陈述（✅ The Relational Model / The Multidimensional Model / Snowflake Structures）

Inmon 先公平地各给一段定义：关系模型=集合+谓词+范式化的实体关系；多维模型=事实表+维度+度量+层次（✅ 中译 13.1/13.2/13.3 同构）。他不否认多维「表达分析语义更自然、查询路径更短」——分歧在**它配不配当企业数据基底**。

- **雪花结构（Snowflake ✅）**：他点名雪花的规范化是「把规范化搬进集市的妥协」——维度再切分，牺牲易用换完整 ⚠️ 转述；Kimball 则公开偏好星型反雪花（[../数据仓库工具箱3.md](../数据仓库工具箱3.md) 维度建模技术）。

## 2. 区别的根源（✅ Differences between the Models / The Roots of the Differences）

Inmon 的历史考据（⚠️ 具体人物与年代按其转述口径，未实抓原文页）：**多维模型源自 Codd 1970 年代后的「信息表达」路线与 1980s 立方体产品（Essbase 一系）的工程实践；关系模型源自 Codd 的关系代数与 SQL 标准化**。两条路从诞生目的就不同：一个为「人怎么想分析」，一个为「机器怎么保一致」。这决定了他整章的论证轴：**多维赢在表达，关系赢在集成**。

## 3. 四连论证：关系型 EDW 的不可替代性（✅ 小节题全实据）

1. **Reshaping Relational Data（重建关系型数据）**：把仓库建成多维大杂烩，日后要「重塑」的代价远大于在关系层之上派生多维——方向不可逆：关系→多维可派生，多维→关系难还原 ⚠️ 通说（接第 4 章聚合不可逆论）。
2. **Indirect Access and Direct Access of Data（直接/间接访问）**：多维 cube 是**预解答**（直接访问，快但封闭），关系层是**未解答的问题空间**（间接访问，经查询层翻译）——企业要的「支持将来未知需求」只能由后者担保。
3. **Servicing Future Unknown Needs（支持将来未知的需求）**：他的招牌论点——**多维模型是「已知需求」的物化；任何维度组合的缺席=该分析的缺席**。仓库资产存续 20 年，需求假设只保鲜 2 年（⚠️ 措辞重建，论点有据）。Kimball 的回应式方案（总线矩阵+一致性维度预留组合空间，工具箱3 总线章）承认「维度组合要预先规划」——恰是 Inmon 攻击的软肋位。
4. **Servicing the Need to Change Gracefully（支持适度变化的需求）**：新模式（新维度/新度量）在关系层=加表加列，在 cube 层=重定义+重聚合+历史回填——**变更弹性**是关系底座的第二担保。

## 4. 独立数据集市：点名批评（✅ Independent Data Marts / Building Independent Data Marts）

- Inmon 给「独立集市」（直接从源系统喂、无企业集成层，暗指 Kimball 式逐个集市起步 ⚠️ 社区通说指涉）列的病理清单：口径孤岛、维护成本随集市数平方增长、无单一事实来源、ETL 网状化——**蜘蛛网在集市层的复现**（第 1 章回环）。
- 对照读物：Kimball 在 [../数据仓库工具箱3.md](../数据仓库工具箱3.md) 第 1/2 章把「conformed dimension 作保的总线」作为独立集市的解药——双方都骂「无总线孤岛」，分歧在**总线是否必须经规范化 EDW 中转**：Kimball 答「不必」，Inmon 答「必须」。
- 三角第三方 Data Vault 的裁决视角：[../Data_Vault_2_0/附-Kimball与DataVault分工与混用.md](../Data_Vault_2_0/附-Kimball与DataVault分工与混用.md) 与 [../Data_Vault_2_0/07-维度建模.md](../Data_Vault_2_0/07-维度建模.md)——DV 承认 EDW 需要集成骨干（挺 Inmon 的命题），但否认 3NF 宽连接是可维护的骨干（反 Inmon 的教条）：**本章论点的当代最优裁判**。
- 湖仓立场：[../The_Data_Lakehouse/12-对照章-Inmon理论与开放表格式实现.md](../The_Data_Lakehouse/12-对照章-Inmon理论与开放表格式实现.md) 给「关系型 EDW→开放表格式」的实现映射；Inmon 晚年把这条论战降调（湖仓可兼收），是 00 所述「自我修订」的展开。

## 6. 🔧 演示：「未知需求」的构造性实验（DuckDB，可复现）

- 原子层 `sales_fact_atomic`（含 `qty` 列但**从未被任何集市使用**）；
- 场景 A（关系底座）：新需求「按件均单价分析」到达→直接对 EDW 写 SQL，零 ETL 交付 🔧；
- 场景 B（cube 底座）：预聚合表 `mart_customer_sales(cust,month,amt,qty)` 若无 qty 列，同一需求必须改 ETL 重跑历史 🔧（用 dropping 列/重建模拟回填成本）；
- 结论（本机）：**未被预见的列就是未被预见的分析**——多维侧缺席=需求不可答，关系侧在场=随时可答；Inmon 论点的 20 行 SQL 证明。
- 对位诚实声明 🔧：演示不含「星型+一致性维度同样可加事实列」的 Kimball 反驳实验——实际工程里二者都有解，差别在**默认路径**成本；结论强度限于「EDW 存全列原子是更稳的保险」。

## 本章论证链复原（⚠️ 依 ✅ 小节序列重建的推理骨架）

1. 双模并立，先各给公平陈述（357–361）；
2. 分歧溯源：一个为「人怎么想分析」、一个为「机器怎么保一致」（363）；

## 核心概念速览（中英对照）

- **多维模型** — Multidimensional Model：事实+维度+度量的分析表达结构（cube 理论）
- **雪花结构** — Snowflake：维度再规范化的折中形态，Inmon 视为集市内规范化妥协
- **直接访问 vs 间接访问** — Direct/Indirect Access：预答（cube 内建）与未答空间（关系+查询翻译）
- **未知需求担保** — Servicing Future Unknown Needs：关系型仓库的核心存在理由
- **优雅变化支持** — Servicing Change Gracefully：新维度/度量的低成本扩展性
- **重塑不对称** — Reshaping Asymmetry：关系可派生多维，多维难还原关系
- **独立数据集市** — Independent Data Marts：绕开企业集成层的直达集市，Inmon 的头号病理
- **总线矩阵（对照件）** — Bus Matrix：Kimball 对维度组合规划的解法
- **一致性维度（对照件）** — Conformed Dimensions：跨集市同义维，两派共享的底线
- **集成骨干（DV 裁判）** — Integration Backbone：DV 挺 EDW 命题、反 3NF 宽连接教条
