# 07 管道优化与执行剖析——阶段次序、索引、溢盘与 explain

> 第 3 波 · #127《Practical MongoDB Aggregations》(Paul Done, Packt, 2024) 精读重构 · 章 7/8。
> 红线与取证口径同 [01-管道骨架与过滤排序.md](01-管道骨架与过滤排序.md)；本章一切"引擎行为"均为文档转述 ⚠️，时延数字来自 SQL 侧复现 🔧。

## 1. 本章主题

本书标题里的 "optimal" 全在这一章兑现：管道优化的第一性原理是**阶段次序纪律**（Mongo 优化器只做有限的阶段重排），第二性是**索引与选择率**，第三性是**内存预算与溢盘**。SQL 侧同一张卷子由优化器代答——本章 🔧 时延对照表量出的正是"代答与自答"的差距结构。

取证：✅ https://www.mongodb.com/docs/manual/core/aggregation-pipeline-optimization/ 、✅ https://www.mongodb.com/docs/manual/reference/command/aggregate/ （allowDiskUse 参数所在页）、✅ https://www.mongodb.com/docs/manual/reference/method/cursor.explain/ （curl 实验）。

## 2. 优化军规（官方文档线 ⚠️ 转述 + 本册 SQL 侧实证 🔧）

### 2.1 次序三板斧

1. **$match 前置**：最早减行，能吃索引；文档明言管道优化器只做 $match/$project 的有限上提——不等价关系优化器的全局重排。
2. **$sort 靠索引**：管道开头 $sort 可复用索引序免排序 ⚠️（复合索引的排序方向匹配规则在 5.x 后有增强 ⚠️）。
3. **$project 裁剪趁早**：把文档瘦成下游需要的列，等效 SQL 的列裁剪但需手动（Q2 全拆聚合 vs 半拆聚合的 2 倍时延差即其缩影 🔧）。
- 反例族（本章的"错题本"）：$unwind 后再 $match（03 章）、$facet 各面重复全扫（05 章）、窗口当 $group（06 章）——三处正文各自埋过雷，在此合账。

### 2.2 内存墙与溢盘

- 阶段内存上限 100MB（$group/$sort/$facet 等），超限报错；`allowDiskUse:true` 放行溢盘（5.3 起服务端默认值可配 ⚠️）——对位 SQL：SQLite 临时 B 树/filesort 溢盘默认发生、DuckDB 外部算子 spill 开关（ORDER BY/HASH JOIN 可溢 ⚠️ 转述 duckdb 文档）。
- 16MB 文档天花板管输出形状、100MB 上限管阶段私产，两笔账别混（00 第十三节消歧卡第 7 对）。

### 2.3 $expr 与 SARGability

- find 里用 $expr 即绕开索引常规路径（聚合表达式语言的"方言夹层"）⚠️；SQL 同款律：`WHERE f(col)` 不可索引化（函数包列）。$expr 是 $lookup 管道形里引用外层键的必需品，成本账要按相关子查询算。

### 2.4 剖析工具箱

- `explain()`/aggregate 命令 explain 模式：输出阶段树+是否用索引+COLLSCAN 标记 ⚠️ 转述；对位 `EXPLAIN QUERY PLAN`（SQLite）与 `EXPLAIN`/`EXPLAIN ANALYZE`（DuckDB ✅ https://duckdb.org/docs/sql/query_syntax/unnest 同域文档树）。
- 运行时账本：currentOp/serverStatus 的 workingSet、千问量级 ⚠️；SQL 侧对应 profile/pg_stat 家族（[../高性能mysql.md](../高性能mysql.md) 的慢日志方法论完全同构）。

- 结论一（对"列存一定快"祛魅 🔧）：Q4/Q4b/Q9 三处 SQLite 反超——**写法结构（原生游标/小物化）> 存储形态标签**；管道同理：mongod 的 $lookup 走索引嵌套循环还是哈希、$sort 走内存还是溢盘，也远比"版本快慢"重要 ⚠️（mongod 执行器选择转述官方注记）。
- 结论二（代价结构的移植）：比值列即"手工阶段次序的价值区间"——SQL 优化器代答能省 3–17×，管道不自带这个代答，所以本书把"次序"写成第一军规 ⚠️ 主张转述。

## 4. 分片下的聚合执行（⚠️ 全节文档转述，不实测）

- 路由分两支：$group 等"可分治阶段"下推到各分片跑 **partial+final 两阶段**（对位 SQL 分布式引擎的 partial aggregate/exchange 算子——[../设计数据密集型应用.md](../设计数据密集型应用.md) 的分布式聚合术语表同源）、不可分治阶段上收 mongos 再跑；$sort 全序要全局归并、$facet 面内独立下推 ⚠️。
- 移植判据 🔧 化：本册 Q3/Q11 的"局部先聚后全量再聚"写法（SQL 里无害，引擎自行分拆）在管道里手动做就是两阶段——两阶段 $group 的手感用 SQLite 复现过（先组内 sum 再组间 sum，结果同值），语义等价、动机不同（省网络搬运）。
- 危险信号（转述 ⚠️）：分片聚合把 20 万行收进 mongos 做全局 $sort/$facet = 单机内存墙提前引爆；SQL 侧同款反模式是"broadcast 全表 shuffle 排序"。

## 5. 常见误区

1. **指望优化器救次序**：上提只覆盖 $match/$project 有限形态（$expr 挡路、$addFields 改名会拆桥 ⚠️）；军规先于优化器。
2. **索引当万能**：$lookup 命中集再大也不走 from 集合索引之外的路；覆盖索引/部分索引与管道前缀的匹配要逐条 explain 验（工具 ✅ cursor.explain 页）。
3. **allowDiskUse 当免死金牌**：放行溢盘≠免费，慢与占用照付（SQL 侧 spill 同罪 🔧 常识+文档 ⚠️）。
4. **拿 explain 的窗口期读数**：分片下 explain 展示的是路由+分片两支计划 ⚠️，单看 mongos 段会低估下推收益。
5. **过度 $project 裁剪**：裁太狠丢 tie-breaker 键/审计字段，$sort 平局与回滚诊断双双受害（01 章平局实验的回旋镖）。

**管道的性能账=次序（自答）+索引（选择率）+内存墙（预算）三本分册；SQL 把三本都装进优化器，本族 🔧 比值列就是"语言不帮你做"那部分的价签。**

## 7.5 管道变慢的五种第一诊断动作（按性价比排序）

1. **看阶段树**：`explain()` 输出里找 COLLSCAN 与"下推/未下推"两支 ⚠️（✅ https://www.mongodb.com/docs/manual/reference/command/aggregate/ 命令参数）；SQL 侧对照 `EXPLAIN QUERY PLAN`（SQLite）/`EXPLAIN ANALYZE`（DuckDB）🔧 本册全部组均先跑计划再计时。
2. **数行数台阶**：逐阶段 `$count` 探针（或直接看 explain 各 stage 的 docsUpdated/input 计数 ⚠️）——放大点（unwind/lookup）与坍缩点（match/group）的位置决定成本形状；本册 2.49×/行 就是 Q4 的台阶高度 🔧。
3. **问次序**：把每个 $match 前移一格重跑（或等价 SQL 加谓词），时延差即"次序税"报价——Q2（拆后滤 465.5ms）vs Q1（拆前滤 5.9ms）就是教科书样本 🔧。
4. **查索引匹配**：from 集合 foreignField、$match 前缀、$sort 方向与复合索引三元组逐一核对 ⚠️ 转述优化页。
5. **估内存**：$group/$sort/$facet 输入行数×文档宽 vs 100MB——超了要么两阶段化、要么 allowDiskUse、要么改架构（08 章物化）。

## 7.6 优化器代答清单（SQL 帮你、管道要你做的六件事）

| SQL 优化器日常 | 管道里的责任人 |
|---|---|

| 列裁剪 | 手写 $project/$unset（02） |
| join 顺序/算法选择 | $lookup 形态与索引自选（04） |

## 7.7 慢管道错题本（本册八章伏笔总回收）

- 03：unwind 后 $match（放大 2.49× 白花）；04：lookup 后 $match 右表（LEFT 误杀）；05：facet 重复全扫；06：窗口替 $group（行数不坍缩）；02：$project 混用 inclusion（编译期错）；01：$skip 深分页（线性烧）🔧 六案均给过数字或反例。

## 核心概念速览（中英对照）

1. **阶段次序军规** — stage-order discipline：$match/$project 前置，别赌优化器重排。
2. **有限重排** — limited rerooting：Mongo 管道优化器的上提能力边界（$match/$project）。
3. **两阶段聚合** — partial+final grouping：分片下推的分治式 $group，对位分布式 exchange。
4. **内存墙** — 100MB stage limit：$group/$sort/$facet 的阶段私产上限，超限报错。
5. **allowDiskUse** — disk spill opt-in：放行阶段溢盘的聚合命令开关。
6. **16MB 天花板** — document size limit：输出文档形状上限，与内存墙两笔账。
7. **SARGability** — 可索引谓词性：$expr/函数包列破坏常规索引路径，两侧同律。
8. **explain 阶段树** — pipeline explain：aggregate 命令/cursor.explain 的计划输出 ⚠️ 转述。
9. **COLLSCAN** — collection scan：无索引全扫标记，管道慢的第一嫌疑人。
10. **覆盖索引** — covered query：免回表索引，管道前缀 $match+$sort 的理想形态。
11. **下推/搬运** — pushdown vs shuffle：分片聚合的两条路，本册 4 节判据。
12. **spill 免费幻觉** — spill fallacy：溢盘放行≠零成本，SQL/Mongo 同罪。
