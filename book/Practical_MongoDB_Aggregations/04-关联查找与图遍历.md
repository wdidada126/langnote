# 04 关联查找与图遍历——$lookup 三形态与 $graphLookup

> 第 3 波 · #127《Practical MongoDB Aggregations》(Paul Done, Packt, 2024) 精读重构 · 章 4/8。
> 红线与取证口径同 [01-管道骨架与过滤排序.md](01-管道骨架与过滤排序.md)。

## 1. 本章主题

文档模型"能免 join 就免 join"，但分析场景绕不开跨集合关联——$lookup 是 Mongo 补上的 JOIN 作业，$graphLookup 补的是**递归闭包**（SQL 侧叫 recursive CTE）。本章是全册 SQL 对照最吃重的一族：等值 JOIN、带子查询的 JOIN、跨库 JOIN（ATTACH 先例）三形态各有对位，图遍历则直接对位递归查询论文线。

取证：$lookup ✅ https://www.mongodb.com/docs/manual/reference/operator/aggregation/lookup/ 、$graphLookup（301→现行页）✅ https://www.mongodb.com/docs/manual/reference/operator/aggregation/graphlookup/ （curl 实验）；SQLite/DuckDB 递归 CTE 语法以本册 Q9/Q9b 真跑为准（专页 URL 未验证，按 00 纪律不列）。

## 2. $lookup 三形态精读

### 2.1 等值形（3.2）：`from/localField/foreignField/as`

- 语义=LEFT JOIN，但右行**装进数组字段** `as`，左行永不消失（除非下游自己 $unwind 丢弃）——与 SQL 行乘积的形状差是本族第一课。
- "数组字段对数组字段"（localField 与 foreignField 皆数组）在 SQL 无直接语法，需双 UNNEST+去重回组——Mongo 原生支持，文档世界的主场。
- 🔧 Q5 用 `LEFT JOIN … WHERE c.cid IS NULL` 反测"不命中集"：200 无档案客户贡献 **8,048** 单，两引擎同值。

### 2.2 管道形（3.6，unwind:false 同版）：`let + pipeline`

- 把子管道带进 ON 条件——对位 SQL 的 **LATERAL 子查询/相关子查询**（本册 DuckDB 拆平写法就是 LATERAL 族）。
- 右表列可裁剪、可再聚合：等价 `JOIN LATERAL (SELECT sum(…) FROM … WHERE x=outer.y)`；$lookup 管道形还多出"结果仍是数组字段"的形状承诺。
- 本书式主张（⚠️ 转述）：复杂关联优先管道形，把过滤/投影下推进子管道 = SQL 优化器替你做的谓词下推，这里要亲手做。

### 2.3 跨实例形态与 ATTACH 先例

- 3.7 起 $lookup 可打 Atlas Data Lake/联邦（Atlas Search 联动另议）⚠️ 转述，本机不验。
- **SQL 侧同款问题、同款解法**：跨引擎关联用 `ATTACH 'demo.db' AS sdb (TYPE sqlite)`——本册 🔧 Q5 第三跑即"DuckDB 本地表 ⇄ SQLite 表"混查（12.3ms，8,048 一致）；580 万行量级的写回/读回/下推实测见 [../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md](../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md)（ATTACH 宇宙一节 ✅ 盘上先例），MotherDuck/湖仓的跨目录 ATTACH 同谱系。

## 3. $graphLookup：管道里的递归闭包

- 语义：对每个输入文档，从 startWith 出发沿 connectFromField→connectToField 反复展开，深度 connectField 限幅、maxDepth 截断，结果装进数组——**每行带自己的一棵子树**（这是 SQL 递归 CTE 没有的"逐行闭包"形状，SQL 要逐行跑或加 key 分组模拟）。
- 🔧 Q9：root 向下 6 层全展开=**126 节点**（SQLite 0.7ms/DuckDB 9.0ms，一致）；Q9b：叶 `root.1.2.1.1.1` 向上回溯 **5 跳**（0.6/6.4ms）。两世界同值 ✅，但注意 SQL 递归 CTE 是"全局一次算完"，$graphLookup 是"逐文档算"——成本结构差异归 07。
- 家族对位：SQLite/DuckDB 亦有表函数 `cycle`/`REFERENCES` 语法糖（DuckDB 1.5 的 `FROM children(…)` 存储过程式写法）与 `TRANSITIVE CLOSURE`（duckpgq）⚠️ 未在本册演示；Neo4j 线（兄弟册 #88，✅ 波尾闭环（2026-09-27）：[../Neo4j_The_Definitive_Guide/00-总览与阅读地图.md](../Neo4j_The_Definitive_Guide/00-总览与阅读地图.md)）补图查询的正统表达。

## 4. MQL⇄SQL 对照表（本章族）

| 管道 | SQL | 实测组 |
|---|---|---|
| $lookup 等值形 | LEFT JOIN … ON a=b（行乘积形状差） | Q5：8,048 / 1,525 |
| $lookup + $unwind:false | LEFT JOIN 不放大行数 | Q5 第一跑 |
| $lookup pipeline 形 | JOIN LATERAL (子查询) ON TRUE / 相关子查询 | Q2/Q4 的 LATERAL 拆平同族 |
| $lookup 跨数据源（Atlas） | ATTACH (TYPE sqlite/mysql/postgres) 跨目录 | Q5 duckdb-attach 12.3ms；DUAR 09 先例 |
| $graphLookup 向下 | WITH RECURSIVE d AS (… UNION ALL …) | Q9：6 层 126 |
| $graphLookup restrictSearchWithMatch | 递归体内加 WHERE | Q9 depth<9 截断 |
| 逐行闭包 vs 全局递归 | 需按输入键分组的二次 join | ⚠️ 形态差，不硬对 |

## 5. 🔧 实测组（复现语义，非 mongod 行为）

- **Q5-1 不命中计数**：`LEFT JOIN customers … IS NULL` = 8,048 单（SQLite 71.1ms / DuckDB 11.9ms / DuckDB-ATTACH-SQLite 12.3ms）——三跑同值，跨引擎无漂移；对应"200 无档案客户"样本设计。
- **Q5-2 命中再聚合**：tier='gold' 关联后 distinct 客户 = **1,525**（SQLite 108.1 / DuckDB 15.2ms）——管道形 $lookup 里先 $match 右表再回流的等价写法。
- **Q9/Q9b 递归双向**：向下 6 层 126 节点、向上 5 跳——两引擎逐字一致（写法完全同一串 SQL，方言零分歧，SQLite/DuckDB 递归 CTE 语法在此重合）。
- **方法注**：递归 CTE 的"先物化再 join"执行序在 SQLite 是默认行为（本册实测 0.7ms 级别即因全局物化便宜）；mongod 的 $graphLookup 若逐文档展开，126×200,000 的成本想象（⚠️ 不实测不承诺），是 07 章"关联形态选择"的主论据。

## 6. 常见误区

1. **忘了 $lookup 结果可以是空数组**：下游直接 `$unwind:'$cust'` 会静默丢行——等价 INNER JOIN 写法忘了 LEFT 本意（🔧 Q4b 的 20 条教训复用）。
2. **在 $lookup 之后才过滤右表**：`{$lookup…}, {$match:{'cust.tier':'gold'}}` 把"无档案行"误杀（LEFT 变 INNER）；正解=管道形下推 $match 进子管道。SQL 侧 `WHERE` 打在 LEFT JOIN 右表列同罪。
3. **等值形不加索引**：from 集合 foreignField 无索引=每左行全表扫（转述官方性能注记 ⚠️ https://www.mongodb.com/docs/manual/core/aggregation-pipeline-optimization/ ）；SQL 侧无索引 JOIN 同罚。
4. **$graphLookup 无 maxDepth**：环图不终止（官方文档明示 ⚠️）；SQL 递归 CTE 靠 UNION 去重天然终止、SQLite 3.44+ 亦有 CYCLE 子句 ⚠️——方言终止机制不同族，移植要重设护栏。
5. **拿 $lookup 当两阶段聚合的替代**：跨分片 $lookup 与分片键的关系（从分片收集广播）在 SQL 侧对应 shuffle/broadcast join 选择——两侧都别凭直觉（07 章）。

## 8. 本章一句话

**$lookup 把 SQL 优化器的三项服务（谓词下推、连接形状、跨源搬运）收回到你手里，$graphLookup 则给你一棵自带递归 CTE 的树——本章的 8,048 与 126 两个数，分别量出了"不命中"和"闭包"两族的对照精度。**

## 8.5 $lookup 形态选择决策表

| 场景 | 推荐形态 | 理由 | SQL 同题 |
|---|---|---|---|
| 等值关联、右表小 | 等值形+from 索引 | 最省，命中率高 | hash/嵌套循环由优化器定 |
| 右表需过滤/聚合/裁剪 | 管道形（let+pipeline） | 谓词下推亲手做 | LATERAL 子查询 |
| 只要存在性判断 | 管道形内 $limit:1 + $size | 免全量搬运 | `EXISTS (…LIMIT 1)` 心智 |
| 多对多数组字段 | 等值形（数组对数组） | Mongo 原生免双拆 | 双 UNNEST+回组（昂贵） |
| 跨实例/湖 | Atlas 联邦 $lookup | 形同本地、账不同 | ATTACH（DUAR 09 先例 ✅） |
| 防环/限深遍历 | $graphLookup+connectField | 逐行闭包形状 | 递归 CTE+护栏（CYCLE ⚠️） |

## 8.6 ATTACH 演示语法块（🔧 Q5-attach 实际执行序）

```sql
-- DuckDB 1.5.5，本机实跑（非 mongod）：
ATTACH 'D:/develops/tmp/dbwave_w3_mongoagg/demo.db' AS sdb (TYPE sqlite);
SELECT count(*) FROM main.orders o
LEFT JOIN sdb.customers c ON o.cust = c.cid
WHERE c.cid IS NULL;          -- -> 8048（12.3ms，与本地表同值）
DETACH sdb;                    -- 干净脱钩（DUAR 09 同款纪律）
```

- 注：ATTACH 读 SQLite 走 DuckDB 的 sqlite_scanner，count 谓词可下推原生库（大表红利见 DUAR 09 的 580 万行 0.09s 实测 ✅）；本册小表差异不显，口径如实。
- `$lookup` 跨源形态在 mongod 侧依赖 Atlas 联邦/驱动连接串，本机不可验 ⚠️——本节是"问题同构"而非"行为同构"的演示。

## 8.7 孤儿行审计模板（由 Q5 反测泛化）

管道版：`[$lookup(cust→c), $match:{c:{'$size':0}}, $group:{_id:'$cust',n:{$sum:1}}]`；SQL 版：`LEFT JOIN … IS NULL GROUP BY`。移植验收先跑孤儿审计——**8,048 这类数字比"join 成功"更能暴露两世界 NULL/缺字段分歧**（呼应 00 第五节纪律 2）。

## 核心概念速览（中英对照）

1. **$lookup** — lookup stage：管道内左外关联，右行装入数组字段。
2. **等值形/管道形** — equality vs pipeline syntax：$lookup 的两种写法，后者≈LATERAL 相关子查询。
3. **let 变量** — lookup let bindings：向外层文档取键注入子管道，ON 条件的替身。
4. **unwind:false** — no-unwind option：关闭 $lookup 自动展开的开关（等值形）。
5. **不命中集** — non-matching set：LEFT JOIN … IS NULL 反测的孤儿行，Q5=8,048。
6. **$graphLookup** — graph lookup stage：逐文档递归展开子树，带深度限幅与过滤护栏。
7. **递归闭包** — transitive closure：connect 字段反复自连接的数学名，SQL 用 recursive CTE。
8. **WITH RECURSIVE** — SQL 递归 CTE：种子 UNION ALL 递归体，本册双向遍历 126/5。
9. **maxDepth/connectField** — graph 限深三件套：无 connectField 即无限递归（环图风险）。
10. **ATTACH** — DuckDB 跨目录挂载：`TYPE sqlite` 直读行存库，$lookup 跨源形态的 SQL 镜像。
11. **广播/洗牌** — broadcast vs shuffle：跨分片与跨表关联的两种搬运哲学（两侧通用词汇）。
12. **谓词下推** — predicate pushdown：把过滤推进子管道/子查询，$lookup 管道形的存在理由。

## 最新演进与工业实践

- **版本线**：$lookup=3.2、管道形+unwind:false=3.6、$lookup 可进视图（views，7.0 扩展 ⚠️）、Atlas $lookup 联邦/数据湖（7.x+ 转述）；$graphLookup 自 3.4 后语法冻结至今（稳定=可沉淀模式）。
- **SQL 侧**：LATERAL 已是三大家标配（SQLite 3.37+/DuckDB/PG）；DuckDB 图扩展 duckpgq 提供 Cypher 子集与闭包算子 ⚠️（本册未装，不在 🔧 内）；SQLite 3.44+ 递归护栏 `CYCLE`/`ORDER CYCLE` ⚠️。
- **工业实践**："文档先拆平、维表走 $lookup 管道形、重分析 ATTACH 出去"是 Mongo+DuckDB 双引擎报表栈的常见分工（本册 Q5 即缩影 🔧）；跨库一致性检查（两侧同 SQL 同值 8,048）被用作管道移植的验收门。
