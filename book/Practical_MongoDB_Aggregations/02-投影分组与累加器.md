# 02 投影分组与累加器——$project/$addFields/$group/$set/$unset

> 第 3 波 · #127《Practical MongoDB Aggregations》(Paul Done, Packt, 2024) 精读重构 · 章 2/8。
> 组织法与红线同 [01-管道骨架与过滤排序.md](01-管道骨架与过滤排序.md)：不冒造章号；Mongo 不装不跑 ⚠️；🔧 为 SQLite/DuckDB **语义复现**。

## 1. 本章主题

投影族（$project/$addFields/$set/$unset）与分组族（$group + 累加器）是管道的"加工车间"：前者改**单个文档的形状**，后者把流**压成聚合行**。对应 SQL 的 `SELECT 表达式 / GROUP BY + 聚合函数 + HAVING`。这是 MQL 与 SQL 语义重合度最高、但**方言差最琐碎**的一族——差异全藏在 NULL/缺字段/数组累加器里。

取证：累加器与表达式列表 ✅ https://www.mongodb.com/docs/manual/reference/mql/aggregation-stages/ （group 专页 ✅ https://www.mongodb.com/docs/manual/reference/operator/aggregation/group/ 、match ✅ …/match/ 同批 curl 200 实验）。

## 2. 逐阶段精读

### 2.1 $project vs $addFields/$set：替换视图 vs 增量视图

- $project 是"白名单"：未列出的字段**消失**；等价 SELECT 列表。带 `_id:0` 关掉默认主键，SQL 无此"默认带出"怪癖。
- $addFields（4.3 起别名 $set）是"打补丁"：保留全部原字段、增/改命名字段；SQL 侧 `SELECT *, expr AS new`。
- $unset（5.0 起并入 $set:null 语境）反向裁剪；SQL 无"减列"语法，只能全列手抄——管道在"字段演化"场景表达力更强的一例。
- 表达式语言：$cond/$switch/$multiply/$concat… 与 SQL CASE/算术/字符串函数逐一对位（本册 Q2/Q3 全部用到 `$cond⇄CASE WHEN`、`$multiply⇄qty*price`）。

### 2.2 $group：管道的 GROUP BY，但"必须全表达"

- `_id` 即分组键（可以是单字段、文档复合键、常量 null=全局一组 ⇄ 无 GROUP BY 的整表聚合）。
- 累加器对位表：$sum⇄SUM、$avg⇄AVG、$min/$max⇄MIN/MAX、$first/$last⇄(窗口化的) row_number 选取、$push/$addToSet⇄list()/set 聚合（DuckDB `list()` ✅ https://duckdb.org/docs/sql/aggregates ；SQLite 只能用 group_concat 退化模拟——**本册 Q10 实测两侧同序列**）。
- $stdDevPop/$stdDevSamp、$median/$percentile（8.x）：SQL 侧 SQLite 全无、DuckDB 全有——引擎能力差在此族最刺眼（🔧 环境注：SQLite 3.45.3 无 STDDEV，DuckDB 1.5.5 有 ✅）。
- **没有 HAVING 关键字**：分组后过滤要靠追加一个 $match——"阶段顺序敏感"在本族的具象（SQL 优化器自动处理，管道要人肉处理）。

## 3. MQL⇄SQL 对照表（本章族）

| 管道 | SQLite 🔧 | DuckDB 🔧 | 差异点 |
|---|---|---|---|
| {$addFields:{total:{$multiply…}}} | `SELECT *, qty*price AS total` | 同左 | Mongo 缺字段→null→算术整体 null；SQL NULL 传染同律 |
| {$group:{_id:'$cust', t:{$sum:'$total'}}} | `GROUP BY cust` + SUM | 同左 | 无键文档在 Mongo 自成一组，SQL NULL 分组同位但显示不同 ⚠️ |
| $match(sum>3000) 后置 | `HAVING sum(...)>3000` | 同左 | 管道=两阶段，SQL=一阶段，语义等价 |
| $push:'$status' | `group_concat(status,'\|')`（保序需子查询技巧） | `list(status)` | SQLite 无原生数组聚合，**保序不可靠**（Q10 注记） |
| $addToSet | `group_concat(DISTINCT …)` | `list_distinct` | 同上退化模拟 |
| {$project:{a:1,_id:0}} | 手写列清单 | 同左 + `SELECT * EXCLUDE (a)` 糖 | DuckDB 的 EXCLUDE/REPLACE 恰是 $unset/$set 的现代版 |

## 4. 🔧 实测组（复现语义，非 mongod 行为）

**Q2 addFields**（拆 items 后过滤 `qty*price>1500` 的行数）
- SQLite 465.5ms / DuckDB 128.2ms → **6,502**（一致 ✅）。
- 解读：$addFields 计算列不增行不删行；过滤发生在拆平之后，等价 SELECT 表达式+谓词。

**Q3 group+后置 match**（A 订单客户级消费、阈 3000）
- 两引擎 → **5,000 组全部过阈，max=51,109.50**（SQLite 649.1ms / DuckDB 134.9ms）。
- 解读：$group 与 HAVING 的拆分演示——管道里是 `[$group, $match]` 两步，SQL 一步；数字相同，代价结构不同（Mongo 每步物化，见 07）。

**Q10 $push 聚合**（客户 c0042 前 9 单状态序列）
- SQLite：`A|C|C|A|B|A|B|B|A`（0.4ms，group_concat+有序子查询）；DuckDB：`['A','C','C','A','B','A','B','B','A']`（9.4ms，list()）。
- 两侧同序同值 ✅；**注记**：SQLite 的 group_concat 不承诺顺序，须先在子查询 ORDER BY 再拼接（本演示即此写法）——对应 $push 在无序流上"顺序取决于上游阶段"的同款告诫 ⚠️。

**Q11 复用组**（分组后 $sort+$limit，Top-3 客户 51,109.50/50,143.07/50,007.68）：见 01 章；本组证明"分组族+骨架族"拼接与 SQL 折叠后完全等值。

## 5. 逐步互译演练："客户分层画像"一步三板

| 步 | MQL | SQL | 备注 |
|---|---|---|---|
| 1 | {$addFields:{band:{$switch…}}} | `CASE WHEN … END AS band` | 表达式一一对位 |
| 2 | {$group:{_id:'$band', n:{$sum:1}, skus:{$addToSet:"$items.sku"}}} | `GROUP BY band` + COUNT + list_distinct | 数组字段作分组键需先 $unwind（转 03） |
| 3 | {$match:{n:{$gte:100}}} | `HAVING COUNT(*)>=100` | 后置过滤阶段化 |

反面练习：给 Q3 的 SQL，让读者回写 MQL——多数人会忘记第 3 板要拆成独立 $match，把 HAVING 塞进 $group 的 `_id` 里，这是新手在管道世界的头号方言事故 🔧 演练观察（社区问答高频型 ⚠️）。

## 6. 常见误区

1. **$project 里混用包含/排除**（`{a:1, b:1}` 与 `_id:0` 除外）：SQL 无此约束，移植进管道会报 "Cannot do inclusion on field… " ⚠️ 转述官方报错线。
2. **把 $group 的 $first/$last 当确定性算子**：输入无序时结果随计划变，与 SQL 裸 MIN/MAX 无关；要"最新一单"须先 $sort 或用 $setWindowFields（06）。
3. **累加器里再嵌套聚合**（`{$sum:{$sum:…}}`）：管道禁止，SQL 同样禁止——但 SQL 有窗口函数后门，Mongo 的后门叫 $group 后接 $project，或 5.0 的 $setWindowFields ⚠️。
4. **忽略 null≠缺字段**：`{$group:{_id:'$mid'}}` 中"字段值为 null"与"字段不存在"会**归并进同一组**（SQL 的 NULL 组同位，但表达式判空手段不同）；本演示特意保留空数组/无档案样本复现该族差异。
5. **用 $project 做过滤**：$project 不删文档（只能输出 null 字段再补 $match）；SQL 的 SELECT 表达式同样不管行去留——两世界的"列操作不碰行"铁律。

## 8. 本章一句话

**投影与分组族：SQL 的一个 SELECT 被管道切成 $project→$group→$match 三块板——每板都能对译，但"板的次序"从优化器的私事变成了你的公事。**

## 8.5 累加器速查对位表（$group 全家 ⇄ SQL）

| Mongo 累加器 | SQLite 3.45.3 | DuckDB 1.5.5 | 备注 |
|---|---|---|---|
| $sum / $avg / $min / $max | ✔ 原生 | ✔ 原生 | 完全同德 |
| $push / $addToSet | group_concat 模拟（保序需子查询） | list()/list_distinct ✅ | Q10 实证 |
| $first / $last | 无（MIN(ts) 技巧替代） | `first()/last()` + ORDER BY 承诺 ⚠️ | 无序即不确定（2.2） |
| $stdDevPop/Samp | ❌ | ✔ stddev_pop/stddev_samp | 引擎能力差实证 🔧 |
| $median/$percentile（8.0） | ❌ | ✔ median/quantile_cont | Mongo 补齐 SQL 统计糖 |
| $count / sum of literal | COUNT(*) | COUNT(*) | 对位无损 |
| $mergeObjects | ❌ | ✔（JSON 层手工） | 文档折叠无 SQL 原生 |
| $ accumulator JS 自定义 | ❌ | ❌（宏近似） | Mongo 独有，代价是不可索引不可下推 ⚠️ |

## 8.6 空值语义三连测（移植 checklist）

1. `$sum` 遇非数字字段静默忽略、遇数组不自动摊（要 `$sum:{'$map'…}` 或先拆平）；SQL `SUM` 遇 TEXT 在 SQLite 亲和下混入 0/1 怪账 🔧（演示未触发，纪律入文）。
2. `$avg` 分母=参与计数而非组大小——与 SQL AVG 同律；用 `$sum/$size` 手搓会翻车。
3. `$group:{_id:{y:'$ts'}}` 复合键分组 ⇄ `GROUP BY a,b`：全 NULL 键在 SQL 仍是一组、Mongo 缺键合并同组——两侧"NULL 组"都在，报表标签需显式补"未知"档（🔧 Q7 空数组单的教训复用）。

## 核心概念速览（中英对照）

1. **$project** — project stage：白名单式字段裁剪/派生，等价 SELECT 列表。
2. **$addFields/$set** — addFields/set stage：增量打补丁式加/改字段，保留原形状。
3. **$unset** — unset stage：减列；SQL 侧仅 DuckDB `EXCLUDE` 有糖。
4. **$group** — group stage：按 _id 键压流，配累加器输出聚合文档。
5. **累加器** — accumulator：$sum/$avg/$push/$addToSet 等在组内折叠的算子。
6. **$push/$addToSet** — push/addToSet accumulators：有序数组/去重数组聚合，对位 list()/list_distinct。
7. **HAVING 阶段化** — post-group $match：分组后过滤必须是独立 $match 阶段。
8. **表达式语言** — aggregation expressions：$cond/$switch/$multiply 等，跨 find/$match/$project 通用。
9. **null 与缺字段** — null vs missing：分组归并行为相近、判空表达式不同族的移植陷阱。
10. **$first/$last 不确定性** — non-deterministic accumulators：无序输入下的"组内首末"不承诺稳定。
11. **物化中间流** — materialized stage output：管道每步产出新文档流，区别于 SQL 算子折叠。
12. **列操作不碰行** — column ops don't drop rows：$project 系与 SELECT 表达式的共同边界。

- **版本线**：$set/$unset（5.0）、$accumulator 自定义累加器（6.0 实验 ⚠️）、$median/$percentile（8.0 ✅ https://www.mongodb.com/docs/manual/release-notes/ ）——本族是 2022–2024 演进最活跃的表达式区；本书 7.0 基线覆盖到 $set/$unset 全量。
