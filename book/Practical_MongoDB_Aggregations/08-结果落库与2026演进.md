## 2. 精读

### 2.1 $out：物化的粗暴形态

- 收尾阶段，把流写成**另一个集合**（可对跨库，受限多因素 ⚠️ 转述版本注记）；语义=整表替换心智（先写临时再原子换 ⚠️）。
- SQL 对位 `CREATE TABLE agg_result AS SELECT …`（本册 🔧 顺手可做：DuckDB `CREATE TABLE top_cust AS …` 与 Q11 同值 51,109.50——演示过 ATTACH 写回 SQLite 的同族动作见 [../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md](../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md) ✅ ATTACH 写路径 3.16s/580 万行先例）。
- 坑：$out 后无输出文档（下游阶段全空转）⚠️；SQL 的 CTAS 同样"无返回行"，同德。

### 2.2 $merge：管道里的 upsert/ETL 语义

- `into/on/whenMatched/whenNotMatched` 四旋钮：whenMatched 可为 replace/keepExisting/merge 或**再挂子管道**（=SQL `ON CONFLICT DO UPDATE SET …` 的表程式扩展）；whenNotMatched insert/discard/error。
- 幂等设计学：$merge 是 Mongo 侧"可重跑的管道"的支点（模式库/物化视图刷新全靠它）——与 SQL 侧 MERGE INTO（17 标准）三句对位：MATCHED→whenMatched、NOT MATCHED→whenNotMatched、USING 子查询→整条管道 ⇄ 完全同构。
- 工程护栏（转述 ⚠️）：on 键唯一性、并发 $merge 同目标、非分片目标库限制；SQL MERGE 的并发锁语义同样要读你引擎的手册——两个世界都别裸写。

### 2.3 物化视图化：本册所有 🔧 组的归宿

- 生产形态：定时管道（cron/Atlas 任务）跑聚合→$merge 进结果集→应用读结果集——对位 SQL 的 MV/快照表刷（互链 [../数据仓库工具箱3.md](../数据仓库工具箱3.md) ETL 章、[../设计数据密集型应用.md](../设计数据密集型应用.md) 预计算节）。
- 增量难题两侧同题：全量重算 vs 拉窗口增量合并（$merge 子管道里 $function？⚠️ 慎用），SQL 侧对应 CDC/incremental view maintenance——流式姊妹题（兄弟册 [../Streaming_Databases/00-总览与阅读地图.md](../Streaming_Databases/00-总览与阅读地图.md) #167，✅ 波尾闭环（2026-09-27）：**终章挂点**）。

## 5. 🔧 收尾组：ATTACH 写路径复用（DUAR 09 先例小尺度复刻）

- 方法：DuckDB 1.5.5 `ATTACH 'out.db' AS o (TYPE sqlite)` → `CREATE TABLE o.top_cust AS SELECT cust, round(sum(qty*price),2) … LIMIT 3`（Q11 同一查询落库）。
- 结果：三行与 Q11 逐值一致（c3945: 51,109.50 / c1603: 50,143.07 / c3065: 50,007.68）✅；再 `DETACH` 后以纯 SQLite 打开 out.db 可查到该表（管道⇄SQL 的"落库+换引擎读"闭环）。
- 注记：580 万行量级的写回实测（3.16s/140MB）与下推读回（0.09s）见 [../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md](../DuckDB_Up_and_Running/09-云端DuckDB与MotherDuck.md) ✅——$out/$merge 在 SQL 世界的成本结构由该先例背书，本册不重复烧机。

## 6. 常见误区

1. **$merge 的 on 键选了非唯一字段**：多行命中时行为未定义级混乱 ⚠️（官方注记：取首条）；SQL MERGE 直接报"matched multiple times"——Mongo 更沉默，护栏要自己上。
2. **whenMatched:'merge' 当全量 replace 用**：merge=字段级叠加（旧文档未被覆盖字段保留），replace=整文档换；SQL 侧 `DO UPDATE SET …` 逐列写 vs 整行插新，语义梯度不同——本族最易静默出错处。
3. **$out 后面接阶段**：静默无输出（07 章"次序"的终局形态）；管道自检应把 $out/$merge 永远排最后一板。
4. **物化结果集不设对账**：$merge 落库后与源集合漂移（口径/迟到数据）——双引擎对账法（本册 §5 三值逐查）是最低成本保险 🔧。
5. **把 $vectorSearch 当通用 join/过滤**：打分语义、索引依赖（Atlas Search 索引须先建）都不同于常规阶段 ⚠️；选型前读 [../Vector_Databases/00-总览与阅读地图.md](../Vector_Databases/00-总览与阅读地图.md)（#124，✅ 波尾闭环（2026-09-27））。

## 8.5 $merge 四旋钮 ⇄ MERGE INTO 逐句对位表

| $merge 侧 | SQL MERGE 侧 | 实测锚 |
|---|---|---|
| into: "results" | `MERGE INTO results` | §5 CTAS/ATTACH 同族动作 🔧 |
| on: {cust:"$cust"} | `ON tgt.k=src.k` | Q11 三值对账 |
| whenMatched:"replace" | `DO UPDATE SET … 全列`（近似） | 2.2 误区 2 |
| whenMatched:"merge" | `DO UPDATE SET 指定列`（列级叠加心智） | 同上 |
| whenMatched:"keepExisting" | `DO NOTHING` | — |
| whenMatched:[子管道] | `DO UPDATE SET … FROM (相关子查询)` | LATERAL 族（04） |
| whenNotMatched:"insert" | `THEN INSERT` | — |
| whenNotMatched:"discard"/"error" | 省略 WHEN NOT MATCHED / 触发约束报错 | — |
| （无 whenMatchedAndNotMatchedBySource） | `WHEN NOT MATCHED BY SOURCE` | Mongo 缺位，两侧删除语义要外挂 $match+$out 全量重建 ⚠️ |

## 8.6 物化刷新三档（全量/窗口增量/事件增量）

| 档 | 管道写法 | SQL 同题 | 适用 |
|---|---|---|---|
| 全量重算 | 整管道 + $merge/$out | CTAS 或 TRUNCATE+INSERT | 小表/口径敏感（先测空集纪律） |
| 窗口增量 | 首板 $match 近 N 天 + $merge 覆盖近桶 | DELETE+窗口 INSERT / MERGE | 报表迟到数据（Q13 时间桶族 🔧） |
| 事件增量 | Change Streams 驱动 + $merge 单键 upsert | CDC+UPSERT | 高新鲜度；流式姊妹题归 #167（00 第六节） |

- 验收模板即本册法：双引擎同 SQL 逐值对账（§5 三值、Q3/Q6/Q7 全部互验）——**落库不是终点，对账才是** 🔧。

## 核心概念速览（中英对照）

1. **$out** — out stage：管道结果整仓写集合，之后无输出流。
2. **$merge** — merge stage：into/on/whenMatched/whenNotMatched 四旋钮的管道 upsert。
3. **whenMatched 子管道** — pipeline whenMatched：冲突时再跑一段管道，SQL DO UPDATE 的表程式扩展。
4. **MERGE INTO** — SQL:17 标准语句：与 $merge 三句对位的关系侧原语。
5. **CTAS** — create table as select：$out 的 SQL 同义动作。
6. **物化视图** — materialized view：聚合结果定期落库供读，本族的生产归宿。
7. **幂等重跑** — idempotent rerun：$merge 支撑的"可重复执行"设计目标。
8. **对账** — reconciliation：结果集与源口径漂移的显式校验（本册双引擎逐值法 🔧）。
9. **Aggregation Builder** — mongosh/Compass 交互搭管道的图形入口 ⚠️。
10. **$vectorSearch** — 向量检索阶段：Atlas 向量线并入聚合族，深题归 #124。
11. **DETACH** — DuckDB 脱钩：跨引擎落库闭环的收尾动作（DUAR 09 先例）。
12. **迟到数据** — late arrivals：物化刷新与流式增量共同的口径难题。
