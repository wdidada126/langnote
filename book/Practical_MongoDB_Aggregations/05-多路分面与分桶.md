# 05 多路分面与分桶——$facet/$bucket/$bucketAuto

> 第 3 波 · #127《Practical MongoDB Aggregations》(Paul Done, Packt, 2024) 精读重构 · 章 5/8。
> 红线与取证口径同 [01-管道骨架与过滤排序.md](01-管道骨架与过滤排序.md)。

## 1. 本章主题

一次扫描、多份答案：**$facet** 把管道叉成并行输出桶（每个桶是完整子管道），**$bucket/$bucketAuto** 把连续值域切成离散组。三者共同补齐了 SQL 侧"GROUP BY 只能给一组答案"的多路复用与分箱短板——本族是"分析型管道"的标志阶段，也是 🔧 对照里 SQL 写法分歧最大的一章（GROUPING SETS/NTILE/CASE 各就各位）。

取证：✅ https://www.mongodb.com/docs/manual/reference/operator/aggregation/facet/ 、✅ https://www.mongodb.com/docs/manual/reference/operator/aggregation/bucket/ 、$bucketAuto ✅✅ https://www.mongodb.com/docs/manual/reference/operator/aggregation/bucketauto/ （curl 200 实验）。

## 2. 精读

### 2.1 $facet：一入多出的"分面"

- 形如 `{$facet:{页A:[子管道…], 页B:[子管道…]}}`：单文档输出，每键一个结果数组。3.4 引入。
- 价值=**同一份上游扫描服务多个视角**（电商搜索的"品牌/价格带/评分"分面统计是其命名来源）；SQL 侧要么跑 N 条查询（N 次扫描），要么 CTE/GROUPING SETS/FILTER 折叠。
- 形状差关键 🔧：$facet 的多个面**行数可以完全不同**（各面独立 $limit），GROUPING SETS 各集共享一张表的形状——语义对位是"N 个标量子查询拼一行"或"UNION ALL 打标签列"，而不是原生同构。
- 官方警告（转述 ⚠️）：各面并行但共享内存预算，面多且重时与 $group 一样会撞内存墙（07 章）。

### 2.2 $bucket：显式边界的分箱器

- `groupBy/boundaries/default` 三件套：边界升序数组、越界入 default 桶、**空桶不出现**。
- SQL 对位=CASE WHEN 阶梯（本册 Q7 写法）；DuckDB 无 width_bucket（🔧 实测报 `Scalar Function width_bucket does not exist`——对位方案排除法实证），PG 有、SQLite 无，**CASE 是唯一通行翻译**。
- 与 $group 的分工：$bucket 是"排序+区间选择"的轻量件，不跑累加器组合大聚合时比手拼 $cond+$group 快且可读 ⚠️ 转述官方注记。

### 2.3 $bucketAuto：自动等频分箱

- `buckets:N` 自动找边界使各桶**计数尽量相等**；granularity 可把边界吸附到 1-2-5 系列等"漂亮数"。
- SQL 对位=NTILE(N) OVER (ORDER BY x)（本册 Q7 第四跑：两引擎 625×8 整齐等频，1,468? 见数字）——但 $bucketAuto 输出的是**每桶边界区间文档**（min/max/count），NTILE 输出的是行标签，还要再 $group 一次才同形；"两步合一"vs"两步"的形状差。
- 内部算法（bucket 数不整除时如何摊、二级拆分 ⚠️ 官方注记）与 NTILE 的"余数摊前几桶"细节不同族：等频是目标、非逐位承诺 🔧 Q7 桶 625 整除看不出，不整除数据上两侧尾差会现形（本册数据集 5,000 客户/8 桶恰整除，注明局限）。

## 3. MQL⇄SQL 对照表（本章族）

| 管道 | SQLite 🔧 | DuckDB 🔧 | 备注 |
|---|---|---|---|
| $facet 两面 | 多标量子查询拼一行 / CTE+UNION ALL | `FILTER (WHERE …)` 一行多列 | Q6 |
| $bucket 显式界 | `CASE WHEN t<700 …` | 同左（width_bucket ❌ 实测不存在） | Q7-1 |
| 空桶行为 | 需外挂生成序列补齐 | 同左 | $bucket 空桶缺席，SQL CASE 天然不产空组 |
| $bucketAuto | `ntile(8) OVER (ORDER BY t)` 再 GROUP BY | 同左 | Q7-2，625×8 |
| granularity 吸附 | ❌ 无对位糖，手工 round | 同左 | Mongo 独有卖点 |
| default 兜底桶 | `ELSE 'other'` | 同左 | 一一对位 |

## 4. 🔧 实测组（复现语义，非 mongod 行为）

- **Q6 facet**（SQLite 293.1ms 一行三值）：A 订单 distinct 客户=**5,000**；含至少 1 件商品的订单=**199,980**；单客户最多订单数=**63**。DuckDB 拆两跑 13.4ms/13.4ms 得 5,000/63（中间值 199,980 与 Q4b 交叉验证一致 ✅）。三面共扫一次上游 vs 分面各自成问，正是 $facet 的省与 SQL 各写各的直白。
- **Q7 bucket**（订单级金额三档+兜底）：`[0,700)=60,721`、`[700,1400)≈60,087`、`[1400,2100)=44,086`、`>=2100=35,106(SQLite)/35,126(DuckDB)`（SQLite 1,324.7ms / DuckDB 265.1ms）。**20 之差**是拆平丢弃 vs 保留的形状差（见 [03-数组拆平与文档重塑.md](03-数组拆平与文档重塑.md) Q4b）——分箱族把上游任何行去留决定都放大成"对不平账"，这是本章最重要的移植课。
- **Q7 bucketAuto/NTILE**（客户级 8 桶）：两引擎逐桶 **625**（SQLite 3,405.7ms / DuckDB 198.2ms）✅ 完全等频同值；整除性局限已声明（2.3）。
- **空桶实验** 🔧（附）：Q7 分箱若加档 `t<0`，SQL CASE 组不出现、$bucket 亦跳过空边界桶 ⚠️ 推定（官方 default 语义注记）——两侧"空组隐身"同德；报表要显式零行须自备序列。

## 5. 常见误区

1. **$facet 每个面都重扫上游**：面内子管道从 facet 输入起步（同一批文档进各面），但各面的 $group 各自烧内存/溢盘——"省扫描"不省聚合 ⚠️ 转述。
2. **boundaries 越界忘 default**：$bucket 会**整管报错**（文档落入无家可归区间）；CASE ELSE 忘写=悄悄丢行——两世界的"静默丢 vs 响亮错"行为相反 🔧 CASE 无 ELSE 归 NULL 组实证。
3. **$bucketAuto 当直方图用**：它给桶边界文档，不保证边界是"人话数"，不带 granularity 的报表刻度会丑（SQL 侧同理，NTILE 无吸附）。
4. **拿 GROUPING SETS 硬对 $facet**：集数不同/带 $limit 的面/各面不同形——能对的只有"同 GROUP BY 键多聚合表达式"这最规整的子集。
5. **facet 键序当输出序** ⚠️：BSON 文档键序不承诺，SQL 列序固定——下游按位取列的代码移植即翻车（对位纪律：按名取列）。

## 7. 本章一句话

**$facet/$bucket/$bucketAuto 把"多份答案、离散化答案"写进语言——SQL 侧要靠 GROUPING SETS、CASE、NTILE 三件拼出来的东西，本族一条管道收编，代价是内存账和边界账全归你管。**

## 7.5 $facet 的四种 SQL 替身（能力递减序）

| 替身 | 写法骨架 | 能表达的面 | 实测 |
|---|---|---|---|
| FILTER 一行多列 | `count(DISTINCT x) FILTER (WHERE …)` | 同键不同谓词的多计数 | Q6 duckdb 5,000/63（13.4ms）🔧 |
| GROUPING SETS | `GROUP BY GROUPING SETS ((a),())` | 同聚合不同键集 | 面键集相同才可用 |
| CTE+UNION ALL 打标签 | `SELECT '面A', … UNION ALL SELECT '面B', …` | 任意面，列型须统一 | Q6 sqlite 一行三值（293.1ms）🔧 |
| N 条独立查询 | 应用层拼装 | 全通用，N 次扫描 | 管道版=$facet 的反面教材 |

- $facet 独占位：**面内独立 $limit + 数组输出形状**（每面各自 Top-K）——SQL 四种替身都做不到"一行装 N 个不同形数组"，最接近的是 `to_csv/struct` 打包，已是方言体操。

## 7.6 分箱族跨引擎能力卡（本册实测口径）

| 能力 | $bucket/$bucketAuto | SQLite 3.45.3 | DuckDB 1.5.5 |
|---|---|---|---|
| 显式边界 | boundaries+default | CASE 阶梯 ✅ | CASE 阶梯 ✅ |
| 等频 | buckets:N | NTILE ✅（Q7 625×8） | NTILE ✅（同值） |
| 漂亮边界吸附 | granularity ✅ | ❌ 手工 | ❌ 手工（hist() 非等频 ⚠️） |
| 空桶保留 | ❌ 不现形 | ❌ GROUP BY 天然 | ❌ 同 |
| width_bucket | —（概念即 $bucket） | ❌ | ❌ **实测报 no such function** 🔧 |
| 输出形状 | 桶边界文档 | 标签列+二次聚合 | 同左 |

## 7.7 练习：把电商搜索页写成管道+SQL 双语

题面：商品集合按"品牌 facet（各品牌在售数）+ 价格带 $bucket + 评分 $bucketAuto(5)"一面响应。
- 管道：`$facet:{brands:[…], price:[…], rating:[…]}` 三面各带子管道；
- SQL：UNION ALL 打标签列（三形状不合一时）或三条查询并行发；
- 检验点：三面的"总数口径"是否与主结果集 $match 一致（Q7 的 20 之差教训复用 🔧）。

## 核心概念速览（中英对照）

1. **$facet** — facet stage：单入多出分面，各面独立子管道、行数可各异。
2. **分面统计** — faceted counting：搜索页"品牌/价格带"多视角计数，$facet 命名来源。
3. **$bucket** — bucket stage：显式 boundaries 分箱，越界靠 default，空桶不现形。
4. **$bucketAuto** — bucketAuto stage：自动等频 N 桶，granularity 吸附漂亮边界。
5. **等频分箱** — equi-frequency binning：每桶计数尽量相等，对位 NTILE 非逐位承诺。
6. **GROUPING SETS** — SQL 多组集：对位 $facet 最规整子集（同键多聚合）。
7. **FILTER 子句** — aggregated FILTER：DuckDB 一行多面糖（Q6 实测载体）。
8. **CASE 阶梯** — CASE ladder bins：跨引擎唯一通行的 $bucket 翻译（width_bucket 在 DuckDB ❌ 实测缺失）。
9. **NTILE** — SQL 窗口分位函数：等频分箱原语，需二次 GROUP BY 才同 $bucketAuto 之形。
10. **空组隐身** — empty-group elision：CASE/$bucket 共德，报表补零自备序列。
11. **对不平账** — reconciliation gap：上游行去留决定在分箱处放大成桶差（20 之差实证）。
12. **内存墙** — memory limit：$facet 各面共享预算，撞墙处置归 07。
