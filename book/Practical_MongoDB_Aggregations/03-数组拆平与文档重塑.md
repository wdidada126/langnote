# 03 数组拆平与文档重塑——$unwind/$replaceRoot/$replaceWith/$unionWith

> 第 3 波 · #127《Practical MongoDB Aggregations》(Paul Done, Packt, 2024) 精读重构 · 章 3/8。
> 红线与取证口径同 [01-管道骨架与过滤排序.md](01-管道骨架与过滤排序.md)。

## 1. 本章主题

文档模型与关系模型的**分水岭就在数组**：内嵌数组让"一单多品"原生存在，而聚合要对其做统计，必须先"拆平"（explode）。$unwind 是拆平本尊，$replaceRoot/$replaceWith 做拆后整形，$unionWith 在流入口合并多源——本族对位 SQL 的 `UNNEST/json_each/UNION ALL`，也是 🔧 演示里**行数放大系数**最直观的组。

取证：$unwind ✅ https://www.mongodb.com/docs/manual/reference/operator/aggregation/unwind/ （curl 200 实验）；SQL 侧 UNNEST ✅ https://duckdb.org/docs/sql/query_syntax/unnest 、JSON1 表值函数 ✅ https://www.sqlite.org/json1.html 。

## 2. 逐阶段精读

### 2.1 $unwind：三个开关决定行数去向

- 基本形 `{$unwind:'$items'}`：数组 N 元素→N 行；**空数组/缺字段的文档默认被丢弃**（等价 INNER JOIN UNNEST）。
- `preserveNullAndEmptyArrays:true`：空数组文档以"items 字段消失"的形态保留一行（等价 LEFT JOIN UNNEST）🔧 Q4b 专门复现该开关。
- `includeArrayIndex:'idx'`：带出下标，SQL 侧 DuckDB `unnest ... WITH ORDINALITY`/SQLite `json_each.key` 同位 ✅。
- 拆嵌套数组=两次 $unwind ⇄ 两次 UNNEST（笛卡尔放大，代价同样平方）。
- 军规：**$unwind 前务必 $match**——10 万行拆成 25 万行再过滤，是本书标题"optimal pipelines"最常点名的反例 ⚠️ 转述+🔧 放大系数实证。

### 2.2 $replaceRoot/$replaceWith：拆后整形

- $replaceRoot:{newRoot:'$sub'}：把子文档提升为输出文档，父级字段全丢——SQL 无直接语法，最接近"子查询投影重命名+WHERE 非空"；管道一行完成。
- $replaceWith（5.0 别名）= $replaceRoot 的糖。
- 组合技 `$unwind + $replaceWith` ⇄ `UNNEST … SELECT elem.*`（DuckDB 可直接对展开列投影）；本演示拆 items 后取 [sku,qty,price] 三列即该组合的列式等价。
- 风险：newRoot 指向非文档值会整条管道报错（SQL 无此"形状异常即中断"文化，NULL 一路宽容 ⚠️）。

### 2.3 $unionWith：多源并流

- 在管道**中途**并另一集合（可带各自子管道）进主流——比 SQL `UNION ALL` 强在"合并点自由"；SQL 只能在 SELECT 层拼。
- 3.8 引入 ⚠️；分片下跨分片语义有告诫（转述官方版本注记，本环境不验）。
- 与 $lookup 的抉择（先 join 还是先 union）归 [04-关联查找与图遍历.md](04-关联查找与图遍历.md)。

## 3. MQL⇄SQL 对照表（本章族）

| 管道 | SQLite 🔧 | DuckDB 🔧 | 行数语义 |
|---|---|---|---|
| $unwind:'$items' | `FROM orders, json_each(items)` | `CROSS JOIN LATERAL (SELECT UNNEST(CAST(items AS JSON[])) e)` | N→Σlen，空数组丢 |
| +preserveNullAndEmptyArrays | `LEFT JOIN json_each … ON 1=1` 或补 `WHERE items='[]'` | `UNNEST(CASE WHEN len=0 THEN [NULL] ELSE arr END, true)` | 空数组保 1 行 |
| +includeArrayIndex | `j.key` | `generate_subscripts` / WITH ORDINALITY 心智 | 下标列 |
| $replaceRoot:'$x' | 手工重投影 | `SELECT (e).*` 展开文档 | 形状替换 |
| $unionWith:other | `UNION ALL`（同构表） | 同左 + `read_json_multi` 类源 | 并流不重排 ⚠️ Mongo 不承诺序 |
| 拆嵌套数组×2 | 两层 json_each | 两层 UNNEST | 平方放大 |

## 4. 🔧 实测组（复现语义，非 mongod 行为）

**Q4 unwind 行数放大**
- A 订单 100,081 单 → $unwind 等价展开 **249,112 行**（SQLite 105.5ms / DuckDB 935.3ms，一致 ✅）。放大系数 2.49。
- 附组：全库拆平后按 SKU 聚合找销冠——SQLite 1,468.5ms → `sku025: 6,556,355.39`（DuckDB 同值另测）。
- 解读时延反直觉点：本组里 **DuckDB 拆 JSON 反而慢**（LATERAL+逐元素 CAST 的行式写法），SQLite 的 json_each 是原生 C 游标——"列存一定快"在拆平族上不成立，写法结构决定一切；换 `json_extract(items,'$[*]')` 批量路径可翻盘（本册未做，留 ⚠️ 断言不入数字）。

**Q4b preserve 开关语义**
- `items='[]'` 的订单共 **20 条**：LEFT JOIN json_each 写法（SQLite 38.7ms）与 UNNEST([NULL]) 写法（DuckDB 100.1ms）都得到 20 ✅——preserveNullAndEmptyArrays:true 的行数去向复现成功。
- 连带发现 🔧（Q7 对照暴露）：**默认丢弃模式下，拆平内联再分桶，20 条空数组单直接蒸发**（SQLite 桶总和 199,980 vs DuckDB 保留写法 200,000，顶桶差 35,106 vs 35,126 恰为 20）——管道里"unwind 吃掉空数组"引发的统计缺口，与 SQL 里 INNER/LEFT JOIN UNNEST 的缺口同因同果；聚合报表对不平账的经典源头。

## 5. 拆平族的成本模型（文档⇄关系共同数学）

- 设 p50 数组长度 ℓ，$unwind 把每下游阶段的行数×ℓ：Q3（02 章）在**拆前**过滤 A 得 100,081 行，拆后立刻 249,112 行——之后每加一个 $group/$sort，代价按 2.5 倍台阶走。
- SQL 同构结论（本册实测）：Q10 组里 SQLite 全拆聚合 1.47s vs 半拆聚合 0.71s，比值≈ℓ；与"先聚后拆"（管道：$group 用 $sum 于数组上⇄SQL 相关子查询）互译可省一次放大，但失去按元素分组能力——**拆平点=语义与成本的交换点**。
- 书式心法（⚠️ 依 Aggregation Schema 公开主张转述）：拆平越早越接近 OLAP，越晚越接近 OLTP；管道设计=选交换点。

## 6. 常见误区

1. **$unwind 后忘记下标**：再 $group 回原文档形状时排序错位（恢复数组需 $push+includeArrayIndex+按 idx 排——SQL 侧 `list(order BY ordinal)` 同理）🔧 Q10 序问题同源。
2. **拿 preserve:true 当默认**：20/200,000=0.01% 的样本能翻出 35,106→35,126 的桶差；真实业务里空数组占比高时，两个选择差出报表几个百分点。
3. **拆嵌套数组写成一次 unwind**：`$unwind:'$a.b'` 只拆一层；两层要两板，中间用 $replaceRoot 提形——漏板=行数永远对不上（SQL 双 UNNEST 同坑）。
4. **$replaceRoot 指到字符串字段**：整管中断 ⚠️；防御写法先 $match:{x:{'$type':'object'}}。
5. **$unionWith 后立刻 $group 全局**：忘了两源字段名不齐→同键分裂两组；SQL UNION ALL 的列对齐纪律在此更严（Mongo 是文档，缺列=缺失而非 NULL）。

## 8.6 三家 SQL 拆平方言卡（移植备忘）

- SQLite：`FROM t, json_each(col)`（逗号即 LATERAL 心智 ✅ https://www.sqlite.org/json1.html ）；`j.key`=下标、`j.value`=元素；LEFT JOIN 版需 `ON 1=1 + j.key IS NULL` 或改用 `unnest()`（3.46 起，本环境 3.45.3 未含 ⚠️）。
- DuckDB：`CAST(col AS JSON[])` + `UNNEST(...)`（SELECT 列内展开）或 `CROSS JOIN LATERAL`（本册写法）✅ https://duckdb.org/docs/sql/query_syntax/unnest ；原生 LIST 列免 JSON 解析，`UNNEST(list_col)` 直通。
- 管道对照：`$unwind` 三开关=SQL 的 INNER/LEFT × ORDINALITY × 元素/文档投影三个自由度——**先定行数口径、再写下标、最后整形**，此序在三个方言里都不出错。

## 核心概念速览（中英对照）

1. **拆平** — unwind/explode：把数组每元素展开成独立文档流行的操作，SQL 名 UNNEST。
2. **行数放大** — row amplification：拆平后行数=Σ数组长度，本册实测系数 2.49。
3. **preserveNullAndEmptyArrays** — unwind option：空数组/缺字段文档保留与否的开关，≈INNER/LEFT 之分。
4. **includeArrayIndex** — unwind option：带出元素下标，对位 WITH ORDINALITY/json_each.key。
5. **$replaceRoot/$replaceWith** — root replacement：子文档提升为输出文档，父字段全弃。
6. **$unionWith** — union stage：管道中途并入他集合流，强于 SQL UNION ALL 的合并点自由度。
7. **json_each** — SQLite JSON1 table function：文本 JSON 数组的拆平游标（✅ sqlite.org/json1.html）。
8. **CROSS JOIN LATERAL** — SQL 侧：引用左行表达式做逐行拆平，本册 DuckDB 写法。
9. **拆平点** — explode point：管道中选"先聚合还是先展开"的语义/成本交换位。
10. **形状异常即中断** — root-not-object error：$replaceRoot 指向非文档值的硬性失败，SQL 无此文化。
11. **两阶段恢复** — regroup-after-unwind：拆平+聚合后再 $push 回数组需下标保序。
12. **归一化税** — denormalization tax（本册比喻）：内嵌数组查询时对关系代数惯例的补偿成本。
