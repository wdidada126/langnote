## 11.1 前期准备（Getting Ready）

- **容量模型先行**（本册方法论重构）：
  - 摄取侧：峰值事件率×单事件字节×保留天数 → topic 分区与 broker 盘；
  - 处理侧：Streams 实例数=最大分区数约束、state store 大小=键数×窗口驻留（08 章 join 窗、09 章 upsert 键）；
  - 服务侧：QPS×查询成本（01/E5 的窗宽算术）+ 段数×副本 → Pinot server 内存与核；
- **SLO 三件套**：新鲜度（分组件拆解：消费滞后/段可见/查询 P99）、可用性、成本上限——没有分解 SLO 就没有可运维性；
- **故障剧本预写**：Kafka 断链重放幂等（依赖 09 upsert/05 段去重）、Pinot 段损坏回填（batch push 冷路径）、状态全丢重建（Streams 从 changelog/最早 offset 重放的时间预算）；
- 数据契约：schema 演进评审流（07 章信封变更的生产化）、生产者兼容性承诺（⚠️ 书内流程不转述，登记为通识做法）。

## 11.2 部署平台（Deployment Platforms）

三档形态的权衡表（重构，⚠️ 书具体推荐不裁定）：

| 档 | 形态 | 得 | 失 |
|---|---|---|---|
| 托管 | Confluent Cloud/Pinot 云托管（⚠️ 商品名现状以官方为准） | 运维面最小 | 成本曲线黑箱、迁移锁入 |
| K8s | Operator/Helm 化 Kafka+Pinot+Streams | 弹性与声明式 | 有状态负载值守门槛高 |
| VM/裸金属 | 经典中间件运维 | 可控/心智简单 | 扩容慢、人肉重 |

- Streams 应用特论：它是"无状态部署物+有状态本地盘"的混合体——滚动升级需状态迁移预算（分区重分配+changelog 恢复 ⚠️ 行为以官方文档为准），K8s 上宜 StatefulSet 或走"重建态"策略；
- Pinot 特论：Controller/Broker/Server 的角色分置、租户与副本拓扑、deep store 对象存储化（⚠️ 转述位）——段不可变性让 Pinot 比多数数据库更早吃到 S3 红利（与 13 章存算分离主题互扣）；
- 网络与租户：查询面（公网用户）与服务层之间必须过 API 网关/缓存，杜绝直Broker（安全+防查询风暴，06 章反模式的生产版）。

## 11.3 后期管理（Ongoing Management）

- 巡逻清单（按数据流向）：生产者错误率→consumer lag→处理器状态大小/恢复时间→段生成速率/可见延迟→查询 P99/QPS→前端缓存命中；
- 三大慢性病变：
  1. **基数蠕升**：高基数维度进倒排/星树使内存曲线爬（09 章高基数键警告的生产化）；
  2. **窗口漂移**：业务改"最近 N 分钟"没人记账，成本随窗宽线性涨（E5 算术）；
  3. **僵尸拓扑**：改口径后旧 Streams 应用未下线，双写两张表（口径分裂之源，09 章同源原则反面）；
- 成本控制面：冷热分层（保留策略+realtime→offline 段下沉湖仓，接 [../Data_Lakehouse_in_Action/00-总览与阅读地图.md](../Data_Lakehouse_in_Action/00-总览与阅读地图.md)）；
- 升级节奏：Kafka/Pinot 版本跟进的兼容矩阵评审（⚠️ 不给出具体版本建议）；
- 复盘钩子：每次事故回答"新鲜度在哪一段破了"——把 01/03 分类表当事故分类法复用。

## 核心概念速览（中英对照）

- **新鲜度 SLO** — Freshness SLO：分组件承诺的数据年龄上限。
- **容量三段论** — Ingest/Process/Serve Sizing：总线、状态、段三类预算。
- **消费滞后** — Consumer Lag：摄取侧健康度的第一指标。
- **段可见延迟** — Segment Visibility Lag：写入到可查的服务层时差（⚠️）。
- **状态重建预算** — State Restore Budget：全丢重放的时间/资源上限。
- **重放幂等** — Replay Idempotency：断链重放不脏化终态（依赖 upsert）。
- **托管/K8s/裸机三档** — Managed/K8s/Bare-metal：运维面-成本-可控性的三角。
- **有状态滚动升级** — Stateful Rolling Upgrade：Streams 实例换血的状态迁移问题。
- **基数蠕升** — Cardinality Creep：高基数维度慢性抬高内存。
- **僵尸拓扑** — Zombie Topology：退役不彻底造成的双口径写路。
- **查询风暴防线** — Query Storm Defense：网关/缓存隔离公网与引擎。
- **冷热分层** — Hot/Cold Tiering：段下沉湖仓的成本手术。
