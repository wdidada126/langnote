# 04 谓词与命题：关系模型的逻辑地基

> ⚠️ 原书归属推定：Part II 逻辑章。Date 把关系模型奠立在**一阶谓词逻辑**上：
> 每个 relvar 对应一个谓词，每个元组对应一个命题。理解「谓词—命题—断言」是理解 NULL/约束的钥匙。
> 所有 SQL/代数式为 🔧 自拟教学示意，非书中原文。

## 核心概念速览（中英对照）

- **谓词** — predicate：含自由变量的命题函数，代入具体值后得真值；如 `x 供应 y 给 j`。
- **命题** — proposition：谓词代入常量后得到的、可真可假的陈述。
- **断言** — assertion：数据库中被声明为「真」的命题集合（relvar 的当前值就是真命题集）。
- **元组即命题** — tuple as proposition：一条元组表达「把各属性值代入该谓词得到的命题」。
- **关系即真命题集** — relation as set of true propositions：一个 relvar 的值 = 使谓词为真的代入集合。
- **开语句** — open statement：变量未定的语句，代入前无真值。
- **论域** — domain of discourse：谓词变量取值所及的范围（与属性域相连）。
- **限制谓词** — restriction predicate：`σ` 里的条件即一个谓词，限制 = 只留使之为真的元组。
- **闭合性** — truth-preservation：算子作用于「真命题的关系」仍得真命题的关系。

## 核心精讲

### 4.1 三个词，别混

- **谓词（predicate）**：形如 `P(x, y)`，x、y 是自由变量。它本身**没有真值**，是一个「等待填值才有真假」的函数。
- **命题（proposition）**：`P('S1', 'London')`，变量被常量替换，现在有确定真值（真或假）。
- **断言（assertion）**：我们**宣称某命题为真**并记入数据库。一个 relvar 在任一时点的值，正是「当前被断言为真的那批命题」。

🔧 例：relvar `S(SNO, CITY)` 关联谓词 `sno 位于 city`。某元组 `(S1, 'London')` 断言命题「S1 位于 London」为真。数据库就是关于这个谓词的一阶断言集合。

### 4.2 关系 = 真命题的集合（核心论断）

Date 反复强调：**理解关系，就是理解它背后那个谓词**。一张 `SPJ(SNO, PNO, JNO, QTY)` 不是「无意义的四元组堆」，它表达谓词：

> 「供应商 sno 在数量 qty 下把零件 pno 供应给项目 jno」

于是每个元组是一句为真的话，整个关系是「当前所有为真的话」。**这决定了什么叫「更新」**：插入 = 断言一个新命题为真；删除 = 撤回一个断言；更新 = 撤旧的、断言新的。

这个视角还直接给出**为什么要避免冗余/重复元组**（03 章）：同一个命题断言两次没有信息增量——`{t} ∪ {t} = {t}`。逻辑里幂等，关系里自然去重。

### 4.3 限制就是「对谓词求真」

回顾 02.2：`σ_{STATUS > 20}(S)` 中的 `STATUS > 20` 本质是一个谓词 `g(x)`。限制 = 只保留使 `g` 为真的元组（= 只保留使复合命题为真的断言）。因此 SQL 的 `WHERE` 子句不是「过滤指令」，而是「在已断言为真的命题上再叠加一个谓词约束，取其合取为真者」。

🔧 复合谓词：

```sql
-- 🔧 自拟：状态>20 且 城市为 London 的供应商
SELECT * FROM S WHERE STATUS > 20 AND CITY = 'London';
```

代数：`σ (STATUS>20) ∧ (CITY='London') (S)`。合取 `∧` 就是下一章的 AND——谓词的逻辑结构决定了过滤结构。

### 4.4 键是「唯一性谓词」

候选键（01、08）用逻辑说就是一个谓词约束：

> 「不存在两个不同元组在键属性上相等」

即 `∀ t1, t2 ∈ R : t1[K] = t2[K] ⇒ t1 = t2`。这把「键」从「一个特殊索引」还原为「一条关于世界的公理」——这正是声明式约束（10 章）的动机：把规则写成谓词交给系统，而不是写进触发器代码。

### 4.5 量词：EXISTS 与 FORALL 是谓词的粘合剂

只有原子谓词还不够，关系代数里那些「跨元组」的运算，本质是用一阶**量词**把谓词粘起来。两个关键量词：

- **存在量词 `∃`（EXISTS）**：`∃x P(x)` = 「至少有一个 x 使 P 真」。它对应半连接（semijoin）与 SQL 的 `EXISTS` 子查询。

  🔧 「供应过任何零件的供应商」：

  ```text
  代数： π_SNO(SP)                     -- 半连接 S ⋉ SP 的投影形式
  逻辑： S(sno) 且 ∃pno SPJ(sno, pno, …)
  SQL ： SELECT * FROM S s WHERE EXISTS (SELECT 1 FROM SP sp WHERE sp.SNO = s.SNO)
  ```

  `EXISTS` 只关心「子查询非空」，返回**二值**真/假——这正是 4.2「断言为真」的直接实现，也是 06.4 里它比 `NOT IN` 稳的原因：它不把「有没有匹配」交给 3VL。

- **全称量词 `∀`（FORALL）**：`∀x P(x)` = 「对所有 x，P 都真」。它对应**除法**（02.6）与「全部满足」类查询。

  🔧 「供应了全部零件的供应商」：

  ```text
  逻辑： ∀pno ( P(pno) ⇒ ∃qty SPJ(sno, pno, qty) )   -- 每个零件都被该供应商供应
  代数： π_SNO,PNO(SP) ÷ π_PNO(P)
  ```

  `∀` 在关系代数里没有直接算子，须靠 `÷` 或双 `NOT EXISTS` 表达——**这解释了为什么『所有都…』类查询在 SQL 里最难写对**（02.6、13.2）。

量词还是**连接**的逻辑内核：自然连接 `R ⋈ S` 相当于把两谓词用合取（∧）并起再 existential 消去连接变量；「R 与 S 在共享属性上匹配」就是「存在一组值同时满足两谓词」。用谓词-量词的眼光看连接/除法/EXISTS，是本章给后文（尤其 06、13）准备的透镜。

### 4.6 缺失值为何是逻辑麻烦（预告）

二值逻辑（真/假）在「一切属性都有确定值」时够用。但现实里会出现「值未知」或「属性不适用」。用 NULL 填进去，就要求逻辑接受**第三个值 UNKNOWN**——而这会摧毁「排中律」「每个命题非真即假」的许多等价变形（德摩根、双重否定、`∀/∃` 与补集的关系）。Date 的倾向：**用 Placeholder / 分解 relvar 消除缺失值，而不是引入 3VL**。

## 常见误区

| # | 误区 | 纠正视角 |
| --- | --- | --- |
| 1 | 「元组只是数据，没有含义」 | 元组是命题，含义来自 relvar 关联的谓词（4.1/4.2） |
| 2 | 「插入=写一行」 | 插入=断言一个命题为真；受唯一性谓词约束（4.2） |
| 3 | 「WHERE 是过程指令」 | WHERE 是对谓词求真的声明（4.3） |
| 4 | 「主键只是加速查找的索引」 | 主键是「唯一性公理」，先于任何实现（4.4） |
| 5 | 「NULL 只是特殊值」 | NULL 破坏二值假设，牵动所有等价式（4.6/05/06） |
| 6 | 「EXISTS 和 NOT IN 完全等价」 | EXISTS 返回二值；`NOT IN` 遇 NULL 坍缩为空（4.5/06.4） |
| 7 | 「『所有都…』用 JOIN 硬凑就行」 | `∀` 需除法/双重否定，是逻辑上最难的一类（4.5/02.6） |
