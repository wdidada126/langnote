# 02 关系代数与封闭性

> ⚠️ 原书归属推定：Part I 关系代数章。关系代数是本书的「纠偏参照系」——每个可疑 SQL 写法，
> 都能写成一个代数等价式，两者不一致处就是 bug。本文件给出六个原始算子 + 若干派生算子与**封闭性**。
> 所有代数/SQL 式为 🔧 自拟教学示意，非书中原文。

## 核心概念速览（中英对照）

- **投影** — projection（`π`）：去掉若干属性，得到「只含保留列」的关系；对应 SQL 的 SELECT 列表。
- **限制** — restriction（`σ`）：按谓词筛元组；对应 SQL 的 WHERE。
- **θ连接** — theta join（`⋈_θ`）：笛卡尔积后按跨关系条件筛选。
- **自然连接** — natural join（`⋈`）：同名字属性自动等值后合并的 θ 连接特例。
- **并** — union（`∪`）：两个**同头**关系元组合并（集合语义，自动去重）。
- **差** — difference（`−`）：属于 A 但不属于 B 的元组。
- **交** — intersection（`∩`）：可由差派生，`A ∩ B = A − (A − B)`。
- **笛卡尔积** — product（`×`）：两关系所有元组的两两拼接。
- **改名** — rename（`ρ`）：更改属性名，用于避免连接时的名字冲突。
- **封闭性** — closure：每个算子的输入是关系、输出也是关系，故可任意嵌套成表达式。
- **关系表达式** — relational expression：由算子嵌套构成的、求值为一个关系的式子。
- **扩展关系代数** — extended RA：除、像（image）、约束连接等派生算子。

## 核心精讲

### 2.1 六个原始算子

关系代数只需要六个原始算子即可表达全部（有限）关系运算：

| 算子 | 符号 | 改变的维度 | 一句话 |
| --- | --- | --- | --- |
| 限制 | σ | 基数 | 按谓词筛元组 |
| 投影 | π | 度 | 删属性 |
| 并 | ∪ | — | 同头合并 |
| 差 | − | — | 只在前者 |
| 笛卡尔积 | × | 度↑基数↑ | 全组合 |
| 改名 | ρ | （名字） | 消除命名冲突 |

交、连接、除都是派生。**记住「度由 π/×/⋈ 动，基数由 σ/∪/− 动」**，写等价式时按这个维度核对就不易错。

### 2.2 限制（σ）与 SQL WHERE 的微妙差异

🔧 代数：`σ (S.STATUS > 20) (S)`。语义：只保留使谓词为 **TRUE** 的元组。

SQL 里 `WHERE S.STATUS > 20` 也「只保留真」，但 SQL 是 **3VL**：当 `STATUS` 为 NULL 时比较得 UNKNOWN，元组被丢弃。表面上结果一致，**根子不同**：

- 代数里谓词是二值的（真/假），NULL 在纯关系模型里**不该存在**（缺失值处理见 06、07）。
- SQL 的丢弃是「unknown 不满足」的副作用，一旦把 `>` 换成 `<>`、放进 `NOT`、或用作聚合，unknown 的行为立刻暴露矛盾（06 章的坑）。

### 2.3 投影（π）与「天然去重」

🔧 需求：「列出所有有供货记录的供应商编号」。

```text
代数： π SNO (SPJ)      -- 结果是一个关系，自动无重复
SQL ： SELECT SNO FROM SPJ          -- 返回带重复的行（bag）！
SQL ： SELECT DISTINCT SNO FROM SPJ -- 才等价于 π
```

这就是本书最典型的「SQL 惯用错误」之一：**投影在关系代数里是集合运算，天然去重；SQL 默认不去重**。忘记 `DISTINCT` 往往不是性能问题而是**语义错误**（下游把重复当多实例）。展开见 03、09 章。

### 2.4 θ连接与自然连接

- θ连接：`A ⋈_{A.x < B.y} B` = `σ_{A.x < B.y}(A × B)`。
- 自然连接：当两关系有同名属性时，只保留该属性**相等**的组合，并在结果里把重复的同名列合并为一列。

SQL 用显式 `JOIN ... ON` 表达 θ/等值连接，用 `NATURAL JOIN`（少见且危险）勉强对应自然连接。🔧 等值连接：

```text
代数： SP ⋈ S                       -- 按共同属性 SNO 自然连接
SQL ： SELECT * FROM SP JOIN S ON SP.SNO = S.SNO
```

关键区别：SQL 的 `SELECT *` 会把 `SP.SNO` 和 `S.SNO` **两列都留下**，自然连接只留一列。这个「多留一列」是连接后基数/投影出错的常见来源（见 08 章外键、09 章 DISTINCT）。

### 2.5 封闭性（closure）——为什么能嵌套

封闭性是关系代数的架构性优点：**算子吃关系、吐关系**，因此任意嵌套仍是一个关系。这带来三个后果：

1. 子表达式可当关系使用（视图、派生表在「理想 SQL」里也是关系）。
2. 优化器可自由重排等价表达式（连接交换律/结合律）。
3. SQL 只有在把查询结果当**值**时才守封闭性；一旦结果被当作「有行序、有重复的表」传递，封闭性就被打破（ORDER BY 子查询破坏可组合性——03 章）。

工程印证：[../../courses/数据库系统/15445/projects/06-mini-sql](../../courses/数据库系统/15445/projects/06-mini-sql) 用表达式树 + 火山（volcano）迭代器实现算子，每个算子输入/输出都是「一个表值流」——这正是封闭性的可执行版本（🔧 该实现处理的是 bag，见 09 章差异）。

### 2.6 派生算子：除法与「全部」

**除（division, `÷`）** 对应「所有 … 都 …」类查询：

🔧 需求：「找出供应了**全部**零件的供应商」。

```text
代数： (SP) ÷ (π PNO (P))
SQL ： SELECT SNO FROM SP SP1
       WHERE NOT EXISTS (SELECT * FROM P WHERE P.PNO NOT IN
                         (SELECT PNO FROM SP WHERE SNO = SP1.SNO))
```

SQL 没有除法算子，只能双重否定 `NOT EXISTS ... NOT IN` 模拟——不仅啰嗦，`NOT IN` 遇到子查询里的 NULL 会整体变 UNKNOWN 从而「查不到」（06 章陷阱）。**代数的除法天然规避该坑**，这就是本书让你用代数校准 SQL 的价值。

## 常见误区

| # | 误区 | 纠正视角 | 详见 |
| --- | --- | --- | --- |
| 1 | `SELECT SNO FROM SPJ` 等价于 `π SNO` | 少了 DISTINCT，是 bag 不是关系 | 09 |
| 2 | `JOIN` 后 `SELECT *` 无害 | 多留连接键列，改变度，下游易错 | 2.4 |
| 3 | `WHERE col > 20` 丢 NULL 无所谓 | 换成 `<>`/`NOT`/聚合时行为矛盾 | 06 |
| 4 | 子查询里放 ORDER BY 也行 | 破坏封闭性：值不该带「行序」 | 03 |
| 5 | 「NOT IN 子查询」= 代数差 | 子查询含 NULL 时结果坍缩 | 06、08 |
