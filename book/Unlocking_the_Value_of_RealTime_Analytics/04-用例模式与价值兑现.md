# 04 用例模式与价值兑现

> ⚠️ 重构章：对应原书约 7–9 个推定小节域（价值叙事册的"举证"部分：用例档案与兑现度量）。
> 用例清单为 REPORT 体裁通行五件套 + 重构细节，凡具体数字案例均不可核 → 只给结构不给数值。

## 1. 用例筛选矩阵：先决"值不值"，再决"能不能"

⚠️ 重构框架：以两轴给候选用例打分——
- **纵轴 决策频率×单次价值**：该决策每天发生多少次、每次错/晚的代价；
- **横轴 新鲜度弹性**：把延迟从 T+1 压到分钟/秒，决策质量提升多少。

右上角（高频 × 高弹性）才配行动级管道；其余按 01 章分档降级。这个矩阵是短册对
"为技术而技术"反模式（01 §4）的正面解法。

## 2. 五件套用例档案（⚠️ 重构叙事，技术对位为实）

### 2.1 风控与欺诈拦截
- 商业叙事：唯一消费窗口在"交易授权前"的用例——延迟即坏账，新鲜度档位天然行动级。
- 技术对位：特征必须**时点正确**（🔧 E4，02 章：ASOF 语义溢价 ≈13× 但毫秒级，必买）；
  模型特征与训练样本的"特征快照"一致性是离线/在线一致性问题（系列侧：波7 册特征工程挂点）。

### 2.2 个性化与转化优化
- 商业叙事：会话内决策（推荐位、文案、定价），窗口以秒计；价值以转化率差度量，
  天然 A/B 可归因——ROI 论证最"干净"的用例。
- 技术对位：写入即可见（🔧 E1 教训：消费者连接别持长事务）；特征存储的可见性延迟
  直接吃掉新鲜度预算。

### 2.3 运营监控与异常检测（IoT/遥测/SLA）
- 商业叙事：从"事后报告事故"到"事中缩短 MTTR"；价值=停机成本×缩短时长。
- 技术对位：高基数流聚合 + 运营级档位即可（微批足够，🔧 E2 曲线说明不必逐条承诺）；
  告警链路的新鲜度要度量到"人看到"（02 §6 最后一公里）。

### 2.4 实时数据产品与近零 ETL 供给
- 商业叙事：把内部实时资产打包成对外 API/嵌入式分析——从成本中心转收入侧的兑现路径。
- 技术对位：零 ETL/表流融合形态（对位 [Streaming Databases 总览](../Streaming_Databases/00-总览与阅读地图.md)
  零 ETL 章；Confluent Tableflow 类管道，URL 见演进节）。

### 2.5 实时 ML 与决策智能
- 商业叙事：模型上线后仍需新鲜输入；"模型快、数据旧"是 2023 前后最常见的落地翻车形态。
- 技术对位：训练-服务偏斜（training-serving skew）治理 = 时点正确（E4）+ 版本化特征快照；
  与 fabric 侧的语义登记对位（[Data Fabric Architectures 总览](../Data_Fabric_Architectures/00-总览与阅读地图.md)）。

## 3. 价值兑现的度量学（⚠️ 重构清单）

1. **前置基线**：上实时管道前，先用 T+1 数据跑一版决策回放，测"新鲜度弹性"真实值——
   防止把相关性收益记在实时头上。
2. **双指标制**：延迟指标（数据年龄分位数）与价值指标（拦截率/转化率/MTTR）必须同板展示，
   任一单独优化都会说谎。
3. **衰减审计**：每季度复查用例档位——业务节奏变化会让"行动级"退化为"运营级"（省钱），
   或反向升级。
4. **负空间承认**：多数企业 60%+ 的分析负载永远停留在复盘级（⚠️ 定性判断，非书中数据）；
   RTA 成功不等于全量实时化。

## 4. 用例反档案：三类不值得上实时的负载（⚠️ 重构）

1. 低频高值但**窗口以天计**的决策（合同审批、季度规划）——工作流系统比管道重要。
2. 新鲜但**无人有权即时行动**的指标——先解决授权，再解决延迟。
3. 源本身**不产生新事实**的数据（静态主数据）——缓存+变更通知即可。

## 6. 价值兑现仪表盘最小件（⚠️ 重构设计）

把 §3 度量学固化成五块常设面板（缺一即兑现不可证）：

| 面板 | 指标 | 数据来源 | 判读 |
|---|---|---|---|
| P1 新鲜度 | 数据年龄 P50/P95/P99（按管道×档位） | 服务层埋点（03 §1 三口径） | 长尾破线=事故前兆 |
| P2 窗口命中 | 决策窗口内完成决策的比例 | 决策日志时间戳差 | 行动级用例的核心 KPI |
| P3 价值差 | 拦截率/转化率/MTTR 的实时前后对照 | 业务系统+A/B | 归因须有回放基线（§3.1） |
| P4 档位成本 | 每管道月度运行成本 ÷ 服务决策次数 | FinOps 标签 | 单价飙升=错配信号 |
| P5 追赶水位 | 积压时长、重放吞吐、保留期余量 | 总线/处理层指标 | 余量<最坏追赶=风险 2 未闭环 |

- 设计纪律：P1/P2 同板（快≠有用）、P3/P4 同板（值不值钱、贵不贵）——双指标制（§3.2）的
  面板化表达。
- 组织挂钩：P2/P3 归数据产品 Owner（05 §3），P4 归平台组，P5 归 SRE 值班。

## 7. 本章要点回顾

1. 用例先过"频率×新鲜度弹性"矩阵，右上角才配行动级。
2. 风控/个性化是时点正确+可见性双要求用例（🔧 E4/E1）。
3. 运营监控用微批档位即可（🔧 E2 汇率），别为看板买秒级承诺。
4. 数据产品化是 RTA 从成本转收入的兑现路径（零 ETL 形态）。
5. 实时 ML 的瓶颈常在数据新鲜度而非模型。
6. 前置基线+双指标+衰减审计构成兑现度量学三件套。
7. 承认负空间：多数负载永远值得留在复盘级。

## 核心概念速览（中英对照）

1. **用例矩阵** — Use-case Matrix：决策价值×新鲜度弹性的二维筛选框架。
2. **新鲜度弹性** — Freshness Elasticity：缩短延迟对决策质量的边际改善率。
3. **决策回放基线** — Decision Replay Baseline：用旧新鲜度数据重放决策以测真实弹性的方法。
4. **欺诈拦截窗口** — Authorization-time Window：交易授权前的唯一有效决策窗口。
5. **时点正确特征** — Point-in-time Features：以决策时刻可见值构建的模型输入（E4 关联）。
6. **训练-服务偏斜** — Training-Serving Skew：离线与在线特征口径不一致导致的模型退化。
7. **MTTR 缩短** — MTTR Reduction：异常实时检测的核心价值指标。
8. **数据产品化** — Data Productization：内部实时资产对外 API 化的兑现形态。
9. **近零 ETL** — Near-zero ETL：以订阅/直连替代复制的供给模式（对位 Streaming Databases）。
10. **双指标制** — Dual-metric Governance：延迟与业务价值指标同板考核。
11. **档位衰减审计** — Tier Re-audit：定期复查用例新鲜度档位的治理动作。
12. **负空间** — Negative Space：明确不上实时的负载清单，RTA 规划的一半。
