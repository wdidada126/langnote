## 核心概念速览（中英对照）

- **mpl::for_each** — for each on types：编译期遍历类型序列，**为每个类型实例化一个默认对象并把访函数调用在其上**——TMP 输出通向运行期代码的第一座桥。
- **类型探访** — type visiting（9.1.2）：以 visitor 模式消费编译期序列；Hana `if_else/union_` 与 `std::variant` visit 的先祖语义。
- **实现选择的三件套** — if 语句 vs 类模板特化 vs 标签分派（9.2）：同一段"按条件选实现"的三种写法谱系——运行期分支、编译期分支、混合分支。
- **标签分派** — tag dispatch（9.2.3）：把类型信息装进**空标签对象**作为**函数实参**，借重载决议选路——traits（类型层）与多态（值层）的接头人。
- **对象生成器/工厂** — factory（9.3）：按编译期条件产出不同类型对象的构造点（`factory<C>` + 特化）。
- **结构选择** — structure selection（9.4）：编译期条件**改变类的存储布局**（特化选成员），如"有指针语义则启用 intrusive 链表节点"。
- **类复合** — class composition（9.5）：编译期决定"要不要多带一个基类/成员"（空基优化 EBO 的正式化）。
- **函数指针作为模板实参** — function pointer as template argument（9.6）：C++98 无 lambda 时把"运行期行为"注入模板的通道。
- **类型擦除** — type erasure（9.7）：把编译期类型信息折进统一运行期接口（`mpl::any`/`boost::any`）——编译期→运行期的**降维**方向，与 for_each 互补。
- **CRTP** — curiously recurring template pattern（9.8）：基类以派生类为模板参数；静态多态、接口生成器（"生成函数"= 批量生成成员）。
- **显式管理重载集** — explicit overload-set management（9.9）：用转换优先级/参数包装控制重载决议（SFINAE 之前的"手刹"）。
- **sizeof 技巧** — sizeof trick（9.10）：`sizeof(探测<T>)` 在不实例化危险体的前提下读取编译期性质——概念检查与诊断的底层铆钉。

## 常见误区

- **误区一：标签分派"就是 if constexpr 的前身所以可以忽略"**。两者语义仍有差：标签分派经过**重载决议**
  （可对不同标签族同时存在多分支、可被偏序选择），`if constexpr` 是**函数体内的语句级**开关；
  接口需要"对每种标签暴露不同的可见签名"时，标签分派（或约束重载）仍是正确工具。
- **误区二：`mpl::for_each` 的访函数能捕获运行期状态**。MPL 访函数按临时对象传值（9.1 契约），
  捕获靠对象成员——运行时 lambda 习惯直接照搬会编译失败或静默丢状态。
- **误区三：类型擦除=性能损失**。擦除同时是**解耦**手段（编译期依赖从接口中消失，物理设计受益，
  回链 [../大规模c++程序设计.md](../大规模c++程序设计.md) 的编译防火墙主题）；
  只算运行期账会低估它的工程价值。

## 动机：TMP 若不跨界就只是自嗨

第 1 章 1.5 承诺的红利（"消灭运行期分支/提前特化"）全部发生在**另一个进程（编译器）的世界**里。
用户真正要的是：编译期算出的结论能**改变运行期行为**，或让运行期对象携带编译期知识。本章的设施
每一条都站在这条边界上：

- **编译期→运行期**：`mpl::for_each`（9.1，类型打印是其演示载荷）、工厂（9.3）、结构选择（9.4）。
- **运行期→编译期**：类型擦除（9.7）反向——**隐藏**运行期对象的真实类型，让统一接口接管分派。
- **两侧同时在场**：标签分派（9.2.3）最典型：标签是编译期产物（traits 取出），却以**函数实参**身份参与
  运行期重载决议；CRTP（9.8）让基类在编译期"知道"派生类是谁，生成的却是普通运行期内联调用。

9.2 的"三件套"排序本身就是教学法：先问"这个决定运行期能知道吗"——不能→特化（类型级）；
能但类型能力不同→标签分派（重载级）；完全动态→ if。今天的读法：把这三档换成
"`if constexpr` / concepts 重载 / virtual+variant"。

## 机制：跨界代码长什么样

```cpp
// 🔧 9.1 风: 编译期序列 → 每个类型在运行期各打印一次(历史语境: mpl::for_each 需 Boost ⚠️)
struct print_type { template <class T> void operator()(T) const { std::printf("%s\n", name_of<T>()); } };
mpl::for_each<types>(print_type());   // "types 里每个类型" → N 次带临时对象的调用

// 🔧 9.2.3 标签分派(已实测 g++ 15.2: tag dispatch old = 5)——第 2 章 it_cat 案例的正式形态
count_dist_impl(a, b, typename it_cat<It>::type{});

// 🔧 9.7 类型擦除: mpl::any 把"某个满足概念的具体函数对象"装箱成统一 operator() 调用
mpl::any<predicative_>(f);            // 编译期: 检查 f 满足概念; 运行期: 虚表式调用
```

已实测 g++ 15.2 的现代对照（同机 `dispatch_old_new.cpp`，`-std=gnu++23`）：

```cpp
template <class It>
long count_dist_new(It a, It b) {
    if constexpr (std::is_convertible_v<typename std::iterator_traits<It>::iterator_category,
                                        std::random_access_iterator_tag>)
        return b - a;
    else { /* 逐步走 */ }
}
```

要点：`if constexpr` 把"标签作为实参参与重载决议"的整段机器码替换成**同一函数体内的两条编译期通路**——
9.2 的教学三段论今天合并为"if constexpr + 约束重载"两段。类型擦除一侧则被 `std::function/std::any/
std::variant + visit` 接管；已实测 `std::visit` 输出（`visit: len=32`）。

## 权衡

- **for_each 的临时对象契约**：MPL 访函数必须接受**按值传入的临时对象**（编译期"存在性证明"），这逼出了
  9.1.1 用重载取 `typeid(T)` 的技巧；代价是访函数无法按引用捕获状态——`std::variant` 的 visit 无此限制。
- **标签分派 vs 特化**：标签走重载（函数级扩展、可见性好），特化走类模板（类型级、无重载集）；
  滥用标签会产生"标签爆炸"（每个能力一个标签结构体）——C++20 concepts 以"约束偏序"终结这场选择。
- **类型擦除的边界税**：擦除换得运行期统一接口，付出堆分配/间接调用（9.7 手工 vs 自动路线之争即"虚表谁生成"）。
- **CRTP 的代价**：基类生成成员导致派生类完整类型依赖（不能在成员里用 `this->` 的自由度受限），
  当年靠 9.9 的"显式管理重载集"打补丁；今天 reflection 路线（P2996）直接消灭"手工生成函数"需求。
- **相邻对比**：类型擦除（9.7）vs tag 多态（9.2）——分派发生地的镜像；EBO 类复合（9.5）vs 运行期组合；
  函数指针模板实参（9.6）vs C++11 lambda + `auto` NTTP（20）——"行为注入模板"的两代通道。

## 最新演进与工业实践

- **C++11 变参模板改写本章全部规则**：`for_each` 的类型版被 `(f(Ts{}), ...)` 折叠取代；工厂被
  `if constexpr` 构造器取代；结构选择被"成员模板 + 约束偏序"或 simply `std::tuple` 组合子取代。
  **已实测**：`new_style.cpp` 中 `std::apply + 折叠` 遍历 tuple 元素（输出 elem size=4/1/8）。
- **C++17 `std::variant` + `visit`**：9.1.2 "类型探访"的标准化——编译期序列的 visitor 语义在值层复活；
  `std::function`/`std::any` 完成 9.7 的官方化。
- **C++20**：concepts 吸收标签分派（约束重载比标签可读）；lambda 进模板参数要等 C++20 的
  结构化绑定式 NTTP ⚠️（确切说：字面量类类型 NTTP 允许闭包对象作模板实参自 P0732/P1433 路线，
  落地版本细节请以标准文本核对，本目录不下结论 ⚠️）。
- **C++23/26 与反射**：P2996（[已核实当前 R13 *Reflection for C++26*](https://wg21.link/p2996)）落地后，
  "遍历一个类的所有成员并生成代码"（9.3/9.5/9.8 的动机总和）将不再需要 CRTP+宏组合。
- **工业实践**：类型擦除的当代高规格实现见 folly 的 `Poly`/`Function`（CRTP + 手工 vtable 的现代大家伙，
  [facebook/folly](https://github.com/facebook/folly) 仓库已核实活跃）；abseil 提供 `absl::AnyInvoking`、
  `absl::FunctionRef` 等同类设施（[abseil/abseil-cpp](https://github.com/abseil/abseil-cpp) 已核实活跃）。Boost.Fusion（本书思想的异构容器延伸）仓库
  [boostorg/fusion](https://github.com/boostorg/fusion) 已核实未归档——
  任务主题"fusion 前夜"的史实在此：本书 9.7 的 `mpl::any` + 5 章序列就是 Fusion 的直接前身，
  Fusion→Hana 的谱系见 [10 章文件](10-附录与从MPL到现代C++的替代.md)。
