## 核心概念速览（中英对照）

- **序列（类型序列）** — type sequence：持有一串类型（可含整型外覆器）的编译期容器；`Sequence` 概念的一切模型。
- **序列概念** — Sequence concept：`begin/end/front/back/at/size/empty` 构成的接口法律（5.5），MPL 库与用户代码之间的契约。
- **编译期迭代器** — compile-time iterator：指向序列某个位置的"类型游标"；与序列一样是纯类型，无对象层存在。
- **随机访问 O(1) 律** — constant-time complexity requirement：MPL 对 `at`/迭代器 `++`/`--` 要求常数时间（5.4.3）——运行时 vector 不要求 `++` O(1)？要求，但**运行时允许摊还，MPL 不允许**，因为"摊还"在类型层没有意义。
- **可扩展性** — extensibility（5.5.2）：序列模型能否被 `push_front/push_back` 生成新序列（函数式"不可变+复制"语义，无原地修改）。
- **关联式序列** — associative sequence（`mpl::map/set`，5.5.3/5.5.4）：按键类型查找的类型层字典；键=类型本身。
- **整型序列外覆器** — integral sequence wrapper（`mpl::range_c`、`mpl::list_c` 一族，5.9）：把"一串整型常量"当序列用（序列的元素是外覆器）。
- **序列派生** — sequence derivation（5.10）：让自定义类**继承**某个序列实现来自动满足概念——当年 C++ 无 concepts 时的"接口实现"技巧。
- **iterator_range** — iterator range：以首末迭代器对表示的"切片序列"，视图章（第 7 章）的前身。
- **Concepts（5.1 一词）** — concepts：此处指 Alexander Stepanov 意义上的"接口需求文档"，非 C++20 语言设施——本书是"概念"一词被正式带入 C++ 标准提案运动（concepts GCC extension）之前的现场记录。

## 机制手推：为什么 list 满足遍历却难满足随机访问

```text
list<T1..Tn> 的实现形态(嵌套 next 链):
  begin = 链首节点; ++ = "取下一个节点类型" → 常数时间 ✔
  at(list, 7) = 沿链走 7 步(7 层偏特化递归) → 实例化 7 个中间类型, 非常数 ✘
vector<T1..Tn>:
  at = vector_iterator<vector<T1..Tn>, 7> → 一次模板实参代入, 常数 ✔
  push_front → 必须重建整个实参列表 → O(n) 复制 ✘(对比 list 的 O(1) 结构共享)
结论: 两种"复杂度人格"互斥; MPL 的选择是 vector 为默认公民、list 标注能力降级。
这直接解释了第 6 章为什么给 list 提供 O(1) 插删"家族"而给 vector 提供 O(1) at ——
概念法律(5.5)写的是"保证什么", 不是"都能做什么"。
```

5.11 的 tiny 序列（目录名如此）则是第三种人格：**为极短序列（n≤ 编译器实参上限）手工编码表示**，
教学目的是"亲手满足一遍全部法律"——等价于运行时课程里"自己实现一个 vector 并用 STL 测试套件验收"。

## 常见误区

- **误区一：把 MPL 序列当 std::vector 的"编译期版"乱用**。没有原地修改、没有迭代器失效问题，
  但每次"修改"都是复制/结构共享；朴素循环式写法会变成 O(n²) 实例化。
- **误区二：以为 `mpl::map` 的键是字符串/名字**。键就是**类型本身**；"按名字找成员"在语言给出反射前无解，
  所以当年的"结构体反射"全靠宏（附录 A）或手工 traits 编码（第 2 章）。
- **误区三：继承（5.10）= 满足概念**。继承只保证接口在场，不保证复杂度律；违约的实现能编译但会让
  第 6 章算法悄悄退化——这正是 C++20 concepts 也管不了、仍需文档的那一半契约。

## 动机：为什么类型层也需要"迭代器抽象"，而不是只要 vector

第 1–4 章建立的元函数语言只处理"点"（单个类型/值）。真实需求全是"列"：

- 类型集上的算法（transform/fold/find，第 6 章）需要一个**统一遍历协议**，否则每个算法×每种容器是乘法爆炸；
- 算法作者（MPL 维护者）与容器作者（用户，5.11"编写你自己的序列"）之间需要**契约**——这正是 5.1/5.4/5.5
  三节把 STL 概念逐字翻译过来的原因；
- STL 隐喻还带来**可教育性**：会 `std::for_each` 的人看 10 分钟就能用 `mpl::for_each`。

## 机制：概念法律与两种序列实现路线

```text
Sequence 概念的最小法律(5.5 归纳):
  S::size            : 元素个数(编译期常量)
  begin(S)/end(S)    : 迭代器对; ++/-- 常数时间; deref(i) 取元素类型
  at(S, n)           : 随机访问, 常数时间  ← 这条法律决定实现形态
Front/Back/Empty 等由以上推导(固有操作, 5.7)
```

**实现路线一（链式）**：`mpl::list<T1,...,Tn>` 由嵌套 `next` 单向链生成——`push_front` 是 O(1) 结构共享
（函数式持久化结构的味道），但 `at(S, n)` 要走到第 n 个节点，违反常数律 → list 被"降级"为
"只保证前向遍历"的模型 ⚠️（细节以原书 5.8.1 措辞为准）。
**实现路线二（向量式）**：`mpl::vector<T1..Tn>` 把元素平铺进一个类模板实参列表，`begin(S)` 返回
`vector_iterator<S, 0>`，`at`/`++` 直接是**整型常量运算**——常数律天然满足。5.11 的 tiny 序列教学构造
则展示第三种：用**位打包/枚举**把小序列塞进极小编译期表示 ⚠️（该节名"构建 tiny 序列"，通行记载如此）。
`range_c<int,0,N>`（5.8.4）是整型序列外覆器路线的代表：**只存区间端点**，按需物化元素，不产生 N 个实例。

**迭代器概念**（5.4）复刻 STL 三级标签（前向/双向/随机访问），用途与 STL 完全相同：算法按能力选实现。
**序列相等性**（5.6）：两个序列相等⇔逐元素类型相等（结构等价而非类型等价）——MPL 里 `vector<int,float>` 与
另一种实现若逐位一致即"相等"，这条法律是 `equal` 算法与 map 键比较的地基。

## 权衡

- **O(1) 常数律的代价**：vector 式实现把"编译期内存布局"摊开成 N 个模板实参，受当年**模板实参数量上限**
  （各编译器 17–1024 不等，第 10 章附录 D 可移植性表）钳制；`range_c` 用惰性绕开实例化数量，但只适用于整型区间。
- **不可变 vs 可修改**：类型层没有赋值，所有 `push_back/remove` 返回**新序列**（5.5.2 可扩展性）；
  写算法时的心智负担接近纯函数式编程——好处是共享与推导安全，坏处是朴素 `transform` 链的中间序列成本。
- **继承式概念满足（5.10）vs C++20 concepts**：当年"继承=接口+默认实现"，代价是无法表达"不继承但合法"的鸭子模型、
  错误信息含混（第 7 章案例来源）；C++20 `requires` 把契约搬进约束表达式。
- **相邻对比**：`list` vs `vector`（结构共享 vs 常数律）；`map` vs 手写 `find + if` 链（键查找 O(log n) 树实现 vs
  线性）；`iterator_range` vs `vector_c` 切片（视图零拷贝 vs 复制）。

## 最新演进与工业实践

- **C++11 变参模板终结了"实参上限"问题**：`std::tuple<int, float, double, ...>` 无数量硬限，`mpl::vector` 的
  头号历史约束消失；`std::integer_sequence/I` 成为 `range_c` 的官方替身（`std::make_index_sequence<N>` 即
  `iota`，STL/MPL 两边的"range_c"从此同名同义）。
- **C++14/17**：变量模板+折叠让"遍历"本身常常不再需要迭代器抽象——对 tuple 做 `get<Is>` 折叠即完成
  `mpl::for_each` 大半工作（边界版本见第 8 章）；`std::variant` 自带 `index/monostate` 等"序列内建查询"。
- **Hana**：把 MPL 的 Sequence 概念用 C++14 constexpr 实现重写为**值层概念**（`hana::Sequence` 要求类型与值统一），
  占位符式接口文档化程度远超 MPL；[boostorg/hana](https://github.com/boostorg/hana) 已核实未归档（维护模式）。
- **工业实践**：新库的类型层容器普遍直接用 `std::tuple` + `index_sequence`（folly 的 `Tuple`/`Function` 系、
  各类 RPC 框架的参数打包），"自定义序列模型"场景萎缩到与"异构编译期容器"绑死的窄域（反射元数据、
  DSL 类型推导）。诊断体验：MPL 序列误用（给 `at` 传越界常量）当年以"实例化回溯+内部迭代器类型名"呈现；
  今天的 `std::tuple_element_t` 越界是清晰的静态断言（libstdc++/libc++ 均有专文信息）。
