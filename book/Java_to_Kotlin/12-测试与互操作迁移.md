## 机制：Java 原形 → Kotlin 翻法 → 重构步序

**Java 原形（JUnit4 测 06 档 Builder）** 🔧：

```java
public class SearchQueryTest {
    @Test public void defaultsPageSize() {
        SearchQuery q = new SearchQuery.Builder().term("kotlin").build();
        assertEquals(20, q.getPageSize());
    }
    @Test(expected = IllegalStateException.class)
    public void blankTermRejected() { new SearchQuery.Builder().term("  ").build(); }
}
```

**Kotlin 翻法（生产走完 06 档后，测试的两副面孔）** 🔧——面孔 A：还没转的 Java 测试遇 `data class`，`new SearchQuery("kotlin")` 编译失败，边界决定二选一：构造器加 `@JvmOverloads` 或留薄 Builder 门面到 Java 调用清零（06 档步序⑤）；**测试红 = "边界残量"信号**。面孔 B（转成 Kotlin 的同测试）🔧：

```kotlin
class SearchQueryTest {
    @Test fun `default page size`() {
        assertEquals(20, SearchQuery(term = "kotlin").pageSize)   // 属性直接读
    }
    @Test fun blankTermRejected() {
        assertThrows(IllegalArgumentException::class.java) {      // require 抛 IAE
            SearchQuery(term = "  ")
        }
    }
}
```

**重构步序**（迁移期测试策略，⚠️ 归纳）：① 转换**前**确认该文件被绿测试覆盖（测试即预言机，01 档循环第 0 环）；② 转文件、惯用化，**保持 Java 测试原样**再编译再跑——行为不变由旧预言机担保；③ 新测试一律 Kotlin（JUnit5 + `assertThrows`，或 `kotlin("test")`）；④ 旧 Java 测试缓转、允许长期共存（混编构建层 01 档已立）；⑤ `@JvmXxx` 边界残量计数入仪表盘，随 Java 调用清零而删；⑥ 构建链：Gradle Kotlin DSL，`compileTestKotlin→compileJava` 顺序与主源码集同构（01 档实验 2 的测试版）。

## 老手易错点与批判读法（画像：Java/C++ 经验者）

- **别同时转产品和它的测试**：两处同变则红绿失义——"每步可编译可测试"（01 档主线）在测试侧的推论是**一次只动一侧**（⚠️ 归纳立场）。
- **data class 的 equals 会静默救活烂断言**：`assertEquals(旧Bean, 新Bean)` 转后可能从"恰好过"变"永远过"——结构相等掩盖实体 id 漂移，转前按 04 档判据补强断言。
- **反引号测试名与 Java 工具链**：surefire 老版本对含空格方法名的报告兼容 ⚠️ 传闻级，升级混合构建时留意。
- **C++ 对照**：测试是"编译器视图变化"的唯一预言机——类似 C++ 迁移里 ABI 差分器的角色；Kotlin 没有 ABI 检查器，所以步序②"旧测试原样跑"不可省略。
- **批判一句**：`@JvmXxx` 注解族是**债的显式记账**不是惯用化成果——某文件长期挂着多个注解就是"还没真转完"的仪表盘读数（🔧 实验 1 建此读数）；数量应随迁移单调递减。
