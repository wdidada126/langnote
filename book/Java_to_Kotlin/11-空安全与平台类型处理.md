## 机制：Java 原形 → Kotlin 翻法 → 重构步序

**Java 原形（隐式 null 约定，无注解）** 🔧：

```java
public class ReportService {
    public String format(Report r) {          // null 进 null 出：只有口头约定
        if (r == null) return null;
        StringBuilder sb = new StringBuilder();
        for (Row row : r.getRows()) {          // getRows() 可能返回 null——凭记忆
            if (row.getLabel() != null) sb.append(row.getLabel());
        }
        return sb.toString();
    }
}
```

**中间态（IDE 转换产物——平台类型满屏跑）** 🔧：`fun format(r: Report?): String?` 里 `for (row in r.rows)`——`rows` 是 `(Mutable)List<Row!>!`，"外层可 null"与"元素平台态"两重未知一个不拦；`row.label` 亦 `String!`。

**终态（边界收敛 + 内核非空）** 🔧：

```kotlin
// 第 0 刀在 Java 侧补注解：public @Nullable String format(@NonNull Report r)
class ReportService {
    fun format(r: Report): String =        // 注解生效后签名收敛为 T / T?
        r.rows.orEmpty()
            .mapNotNull { it.label }
            .joinToString()
}
// 注解来不及补的过渡形态：入口处一次性防御固化（?: error("boundary")），内核只与收敛后类型打交道
```

**重构步序**（⚠️ 归纳）：① **登记**——被 Kotlin 消费的 Java 公共 API 上 `T!` 出现点列清单（返回/参数/泛型实参三类）；② **由内而外补注解**，先补最热边界；③ 补不到的点做**入口防御**（`orEmpty/filterNotNull/?: error`），当场定空不拖延；④ Kotlin 内核签名只允许 `T` 与 `T?`，`!!` 按 03 档红线逐个歼灭；⑤ 泛型实参单独处理（`List<String!>!` 复合态最阴）；⑥ 全局选项收紧（JSR-305 严格模式类开关 ⚠️ 旗标名未核）。

收敛对照表（⚠️ 归纳）：

| 平台类型出现位 | 形态 | 收敛手段 |
|---|---|---|
| Java 返回值 | `getName(): String!` | `@Nullable/@NonNull`；过渡 `?: 默认` |
| Java 参数 | 赋给 `T` 处织入隐式断言 | 入口显式校验，错误信息定界 |
| 泛型实参/数组 | `List<String!>!` / `Array<String!>` | 元素级 `filterNotNull/mapNotNull` + 外层 `orEmpty` |
| 覆盖无注解 Java 接口 | 签名可选 `T` 或 `T?` ⚠️ 弹性未验 | 一经调用方使用即定死，先内后外 |
| Kotlin 导出给 Java | 非空参/返默认发 `@NotNull` ✅ 语言事实 | Java 侧 IDE 检查白捡 |

## 老手易错点与批判读法（画像：Java/C++ 经验者）

- **错误行号不可信**：平台类型赋非空 `T` 时断言织在**赋值点**，NPE 却炸在后续解引用——迁移期排障先怀疑"类型边界记账错位"（🔧 实验 2 亲手复现）。
- **注解家族互不兼容**：jetbrains / jsr305 / jakarta / JSpecify 的注解目标（TYPE_USE vs 方法/参数）与语义各异，混用约等于没用——项目内统一一族并从 JSpecify 方向收敛 ⚠️（03 档同款欠账）。
- **可空性是类型的属性不是位置的属性**（03 档主旨的边界版）：`format(r: Report?)` 把口头约定写进签名，比"文档里写 may return null"强一个数量级。
- **C++ 对照**：平台类型 ≈ dlopen 进来的无契约引用——头部（注解）补不全，检查器就装死；补注解是**还 Java 时代欠债**不是 Kotlin 新税，预算按每跨界类 3–5 处估 ⚠️ 推断。
- **异常史话**：KotlinNullPointerException/TypeCastException 自 1.4 起归并为 NullPointerException ⚠️ 版本口径——读老 stacktrace 别被旧异常名误导。
- **批判一句**：把全部 `T!` 收敛成 `T?` 是另一种偷懒——内核到处 `?.`/`?:` 只是把 null 传染合法化；正确终态是边界防御一次、内核非空贯穿（对照 [08 档](08-从命令式到函数式风格.md) 的"管道裸奔"警告）。

## 核心概念中英对照

| 中文 | 英文 | 一句话 |
|---|---|---|
| 平台类型 / 灵活类型 | platform type (`T!`) / flexible type | 未标注 Java 类型的可空未知态 / 编译器内部称呼 ⚠️ 术语对应待验 |
| 空性注解 | nullness annotations | `@Nullable/@NonNull` 契约标记 |
| 简单名识别 | simple-name recognition | 按注解类名而非全限定包匹配 ⚠️ 口径 |
| 入口防御 | defensive boundary check | 跨界处一次性把 `!` 收敛成 `T`/`T?` |
| 断言织入 / 空性导出 | assertion injection / nullability export | 赋非空处隐式检查 / Kotlin 产物自动生成 `@NotNull` |
| 覆盖弹性 | override flexibility | 无注解接口方法实现时可任选 `T`/`T?` |
