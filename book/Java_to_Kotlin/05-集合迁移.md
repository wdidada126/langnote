## 机制

### 第 6 章：容器的 Kotlin 化

**重构前** 🔧：

```java
List<Order> orders = new ArrayList<>();
Map<String, List<Order>> byCity = orders.stream()
    .collect(Collectors.groupingBy(o -> o.getCustomer().getCity()));
```

**中间态**（转换产物：Java 集合 API 原样搬运） 🔧：

```kotlin
val orders: MutableList<Order> = mutableListOf()
val byCity: Map<String, List<Order>> = orders.stream()
    .collect(Collectors.groupingBy { it.customer.city })
```

**终态**（Kotlin 集合操作 + 只读接口优先） 🔧：

```kotlin
val orders: List<Order> = emptyList()
val byCity: Map<String, List<Order>> = orders.groupBy { it.customer.city }
```

要诀（⚠️ 归纳）：Kotlin **只读/可变是类型分层的**——`List` ≠ `ArrayList` 的继承关系，而是 `List` ⊃ `MutableList` 的接口分层；声明一律写只读接口（`List/Map/Set`），只在确实需要就地修改处用 `Mutable*`。`map/filter/groupBy/distinctBy/sortedBy/sumOf/count` 家族替代大部分 stream 中间操作，`toList/toMap` 收尾。

### 第 13 章：从流到可迭代对象再到序列

本章标题即工序：**先别急着上 Sequence**。三步辨析：

| 机制 | 求值 | 对应物 | 适用 |
|---|---|---|---|
| Iterable（for/`map`/`filter`） |  eager，每步建中间集合 🔧 | 老式 for 循环 | 中小集合，可读性优先 |
| `Sequence` | lazy，逐项流水 | Java `Stream` | 链式中间操作多、集合大、需短路 |
| Java `Stream` | lazy，可 parallel | — | 跨语言边界时不得不用 |

**重构前** 🔧：

```java
long total = orders.stream()
    .filter(o -> o.getStatus() == PAID)
    .map(o -> o.totalWithVAT(taxRates))
    .reduce(0L, Long::sum);
```

**中间态**（`asSequence()` 一键平移） 🔧：

```kotlin
val total = orders.asSequence()
    .filter { it.status == PAID }
    .map { it.totalWithVAT(taxRates) }
    .sum()
```

**终态**（按数据规模定形：小集合直接 eager 单表达式；大管道保留 Sequence） 🔧：

```kotlin
val total = orders.filter { it.status == PAID }.sumOf { it.totalWithVAT(taxRates) }
// 管道确属大数据量时：
val totalLazy = orders.asSequence().filter { ... }.map { ... }.sum()
```

陷阱清单：`parallelStream` 没有 Sequence 对应物——Kotlin Sequence 单线程 ⚠️（通行事实）；迁移时删 parallel 前必须确认吞吐来源，否则性能回退（见 🔧 实验 2）。

### 第 14 章：从可累积对象到转换对象

Java 的累积器癖好：`Collectors`、手写 for 累加、`StringBuilder` 拼装的"收集器类"。Kotlin 偏好**转换对象**：把"我往容器里不断 add"改成"输入→输出的纯函数"。

**重构前（可累积对象）** 🔧：

```java
public class LineFormatter {
    private final List<String> out = new ArrayList<>();
    public LineFormatter add(String s) { out.add(s.trim()); return this; }
    public String result() { return String.join("\n", out); }
}
// 用法：new LineFormatter().add(a).add(b).result();
```

**终态（转换对象/纯函数）** 🔧：

```kotlin
fun formatLines(inputs: List<String>): String =
    inputs.map { it.trim() }.joinToString("\n")
```

判据（⚠️ 归纳）：累积器对象存在的全部理由通常是**跨循环携带状态**；一旦改成 `map/reduce/groupingBy` 形态，状态消失，函数取代类。`fold` 是 Java `reduce`（无 identity 版语义差异 ⚠️）与自写累加循环的统一替身。

### 第 15 章：从封装集合到类型别名

Java 保护集合不变式的传统手段：包一层类、只暴露 `add/remove/size`（Effective Java 第 97 条 Item ⚠️ 通行记载）。第 15 章给出轻量替代：**当包装类只是"换名的 List"、无额外不变式时，用 typealias 去掉一层**。

**重构前（封装集合类）** 🔧：

```java
public class OrderHistory {
    private final List<Order> orders = new ArrayList<>();
    public void add(Order o) { orders.add(o); }
    public List<Order> asList() { return List.copyOf(orders); }
}
```

**终态（类型别名 + 值对象）** 🔧：

```kotlin
typealias OrderHistory = List<Order>   // 语义命名，零运行时层

// 需要的操作写成该"域类型"的扩展函数（联动 10 章）：
fun OrderHistory.latest(): Order? = lastOrNull()
```

分界线（⚠️ 归纳）：**有不变式才包装**（如"金额非负、同币种才可加"→ 独立类，见 04/07 档）；只是给 `List<Order>` 起域名的，typealias 即可。

## 老手易错点（画像：Java/C++ 经验者）

- **`mapValues` 不复制值的坑** 🔧：对 `Map<K, List<V>>` 做变换时，只读视图语义下容易误共享可变列表——与 04 档的浅拷贝同源。
- **Sequence 的"多次迭代"**：Sequence 默认不可重复遍历（Iterator 一次性），Java Stream 同样只能消费一次——两边直觉一致，但 Kotlin 报错时机更友好。
- **eager `map` 建中间集合**：链三段 `filter+map+sorted` 在 List 扩展下生成三个临时集合；C++ 人应像对待"返回 vector 的链式调用"一样看数据规模——小数据无所谓，热路径上 Sequence 才是对位物。
- **`toList()` 的防御性复制**：`List<Order>` 参数来自 Java 侧时可能是 `MutableList` 别名，跨界交接要 `toList()` 固化。
- **typealias 不是新类型**：`OrderHistory` 与 `List<Order>` 可互相赋值、重载无法区分——它只治可读性，不治类型安全。要强类型回到 02 档的 value class。
- **C++ 对照**：`groupBy` ≈ `std::ranges::views::group_by`（且后者限制更多）；`asSequence().map{}...` 更接近ranges 的 lazy view 链——理解 ranges 的人秒懂 Sequence，反之 Java Stream 出身的人要克制"万物皆 Sequence"。

## 🔧 微实验设计（未执行，方案自写）

1. **eager vs lazy 中间集合计数**：给 `listOf(1..10^6)` 链上 `filter+map`（List 版）与 Sequence 版，用 `-XX:+PrintGCTaskTime` 前的简易分配计数器（或 JOL/`ThreadMXBean`）比较分配量。
2. **parallel 回退复现**：CPU 密集 `map` 10^7 元素，`parallelStream` vs `asSequence` vs 协程分块，记录倍数 ⚠️ 预期 parallel 占优——迁移时必须人工补并发。
3. **fold 等价性**：自写 for 累加与 `fold(initial){...}` 对 1000 组随机输入断言同值；同时测顺序敏感性（非结合运算下 fold 与 parallel reduce 的分歧）。
4. **typealias 类型安全边界**：定义两个 typealias（`Money=Long`、`Distance=Long`），写 `pay(Money)` 传 `Distance` 编译通过的实证——引出"何时必须升级 value class"。
5. **`asSequence` 与 `sequenceOf` 差异**：对生成式数据（斐波那契无限列）用 `generateSequence` 写 20 行取前 N 项，对比 Java `Stream.iterate` 写法长度。

## 核心概念中英对照

| 中文 | 英文 | 一句话 |
|---|---|---|
| 只读集合接口 | read-only collection interface (`List`) | 承诺不就地修改的视图，Kotlin 默认声明类型 |
| 可变集合接口 | mutable collection interface (`MutableList`) | 显式允许 add/set/remove |
| 立即求值 | eager evaluation | List 扩展每步产出新集合 |
| 惰性求值 | lazy evaluation | Sequence/Stream 逐项或按需产出 |
| 序列 | `Sequence`/`kotlin.sequences.Sequence` | Kotlin 的惰性管道原语 |
| 折叠/归约 | fold / reduce | 累积器循环的函数式替身 |
| 转换对象 | transformer (vs accumulator) | 输入→输出的纯函数取代携带状态的收集器 |
| 类型别名 | `typealias` | 给类型起域名，无运行时新类型 |
| 防御性复制 | defensive copy (`toList`) | 边界处固化可变引用 |
