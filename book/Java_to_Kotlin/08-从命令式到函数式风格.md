## 机制：Java 原形 → Kotlin 翻法 → 重构步序

**Java 原形（携带状态的累积循环）** 🔧：

```java
public Map<String, Long> totalByCity(List<Order> orders) {
    Map<String, Long> totals = new HashMap<>();
    for (Order o : orders) {
        if (o.getStatus() != Status.PAID) continue;
        String city = o.getCustomer().getCity();
        long gross = o.totalWithVAT(taxRates);
        if (totals.containsKey(city)) totals.put(city, totals.get(city) + gross);
        else totals.put(city, gross);
    }
    return totals;
}
```

**中间态（IDE 转换产物——语法 Kotlin、形状 Java）** 🔧：`for (o in orders)` + `totals[o.customer.city] = (totals[...] ?: 0L) + gross`——可提交的一小步：行为不变、编译通过，但可变 map + 循环控制流原封不动。

**终态（单表达式管道）** 🔧：

```kotlin
fun totalByCity(orders: List<Order>): Map<String, Long> =
    orders.filter { it.status == Status.PAID }
        .groupBy({ it.customer.city }, { it.totalWithVAT(taxRates) })
        .mapValues { (_, grosses) -> grosses.sum() }
```

**重构步序**（⚠️ 归纳）：① **识别循环形状**——映射/过滤/累积/查找/谓词/纯副作用遍历六形之一；② 形状与 stdlib 同名操作直换（`map/filter/firstOrNull/any/all/count/forEach`）；③ 携带状态改 `fold/sumOf/groupBy+mapValues`（呼应第 14 章"累积器→转换对象"，05 档）；④ `break/continue/label` 换短路操作（`takeWhile/firstOrNull`），**不用非局部 return 硬凹函数式**；⑤ 给管道起域名（顶层纯函数），复杂策略以函数参数化（联动 [10 档](10-接口与函数类型.md)）。

迁移对照表（⚠️ 归纳，review checklist）：

| 命令式形状 | 函数式对位 |
|---|---|
| 累加器 + `containsKey` 判存 | `groupBy{}.mapValues{}` / `fold` / Map `update` |
| `continue` 跳过 / `break` 早停 | `filter` / `takeWhile` · `firstOrNull` |
| `for (i in indices)` 索引循环 | `mapIndexed` / `zip` / `windowed` |
| 嵌套 for + 条件配对 | `flatMap` 笛卡尔 + `filter`（慎防空爆） |
| 条件计数器 `if(...) n++` / 循环拼串 | `count { }` / `joinToString` |
| 遍历中就地 remove | `filterNot` 重建只读集合（05 档类型分层） |

## 老手易错点与批判读法（画像：Java/C++ 经验者）

- **函数式不是目的**：本书度量是"揭示意图 + 每步可编译可测试"（01 档主线），不是 lambda 密度——需要三行注释才懂的 `fold` 链配不上一个自明的 for；保留命令式有时是更惯用的 Kotlin（⚠️ 归纳立场）。
- **eager 中间集合成本**：List 扩展链每步物化（05 档第 13 章辨析），大数据先 `asSequence()` 再谈风格；C++ 人把 `views::filter|transform` 直觉得成零开销时，记住 Kotlin List 版不是 ranges，Sequence 才是对位物。
- **`forEach { }` 里的副作用 = 变相 for**：只有整链能收成单表达式时才值得改造；纯 `forEach` 替换 `for` 是零收益抖动。
- **短路时机漂移**：`any/firstOrNull` 自带提前退出，但 `filter` 后接 `forEach` 多建中间集合且不再早停——逐条核对退出时机（🔧 实验 2）。
- **`!!` 与平台类型不因函数式而消失**：管道里 `it.customer.city` 一串平台访问，风格漂亮空安全裸奔——与 [11 档](11-空安全与平台类型处理.md) 合流才闭环。

## 🔧 微实验设计（未执行，方案自写）

1. **等价性对拍**：中间态版与终态版对 1000 组随机订单断言同值；10^6 规模记分配差（方法同 05 档实验 1）。
2. **退出时机显微**：`filter+forEach` 与带 break 循环在同一输入下的副作用执行计数对比。
3. **非局部 return**：inline `forEach` 内 `return` 跳出外层函数与 Java break 对照，标可读性红线；另以 `zipWithNext/windowed(2)` 替换索引相邻差循环，统计行数与越界面。

## 核心概念中英对照

| 中文 | 英文 | 一句话 |
|---|---|---|
| 命令式/函数式风格 | imperative / functional style | 语句改状态 vs 表达式说"是什么" |
| 累积循环 | accumulator loop | 携带可变状态边遍历边聚合 |
| 循环形状 | loop shape | 六分类映射/过滤/累积/查找/谓词/遍历 ⚠️ 本档归纳 |
| 短路求值 | short-circuit evaluation | `any/firstOrNull` 的提前退出 |
| 非局部返回 | non-local return | inline lambda 里 `return` 跳出外层函数 |
| 纯函数 | pure function | 同输入同输出无副作用（14 章题材入口） |
