## 机制：这本书的主线句式

全书每一章都是同一个动作：**识别一个 Java 惯用法 → 用一小步把它换成 Kotlin 惯用法 → 每步保持可编译、可测试**。第 1–2 章给出的是"项目级"的那一步，而不是"语法级"。

重构的三层舞台（⚠️ 归纳）：

1. **构建层**：Maven/Gradle 里让 Java 与 Kotlin 源码混编。
2. **模块层**：选一个叶子模块整体转 Kotlin，其余保持 Java。
3. **类/成员层**：IDE 一键转换 + 手工惯用化（第 3 章以后）。

### 第 2 章的核心工序：项目迁移三段

**重构前（纯 Java 项目，Gradle 风格示意）** 🔧：

```java
// build.gradle（Groovy DSL 示意）
plugins { id 'java' }
sourceCompatibility = '17'
// src/main/java/com/shop/Order.java —— 全部 Java
```

**中间态（Kotlin 与 Java 共存，互操作层）** 🔧：

```kotlin
// build.gradle.kts —— java 与 kotlin 插件并存
plugins {
    java
    kotlin("jvm") version "2.0.21" // 版本号示意 ⚠️ 以当时最新为准
}
kotlin { jvmToolchain(17) }
// 布局：src/main/java 与 src/main/kotlin 并行；
// 先转依赖图叶子模块（如 utils），核心模块继续留 Java。
```

终态在 1–2 章语境下不是"全项目 Kotlin"——本书立场 ⚠️（归纳）是**允许长期混合**：转换工具产出的 Kotlin 文件必须再过一遍惯用化（即本书 3–22 章），否则只是"用 Kotlin 语法写 Java"。

**终态（一个已惯用化的叶子模块的构建侧）** 🔧：

```kotlin
plugins { kotlin("jvm") }
dependencies {
    testImplementation(kotlin("test"))
}
// src/main/kotlin/com/shop/pricing/*.kt —— 该模块不再 import 任何 Java 类库 idiom
// （Optional / Bean / static util 均已被 3–12 章的模式替换）
```

### IDE 转换工具的正确定位

`Convert Java File to Kotlin File` 的产物 = 本书后续 20 章的**起点代码**：能编译、行为不变，但保留 Java 味（显式类型、`;`、`fun xxx(): Unit`、`get/set` 模板、`@JvmStatic` 乱飞）。工作循环是"转换一个文件 → 按对应章节惯用化 → 跑测试 → 提交"。

## 老手易错点（画像：Java/C++ 经验者）

- **把"能编译"当"已迁移"**：自动转换只完成语法翻译；Java 惯用法（getter/setter、Optional、checked 异常链）原样保留时，你只是养了一个写 Kotlin 方言的团队。⚠️ 归纳，本书反复强调。
- **第一个模块就挑依赖图核心**：正确顺序是叶子先行；核心模块与 Java 模块循环依赖时混编会卡死（Kotlin 编译器需要 Java 侧先出 stub）。
- **kapt/KSP/annotation processor 断裂带**：Lombok 与 Kotlin 混编坑最密——转一个模块就要重验一条构建链，别一次性换。
- **对照 C++ 的经验**：这就像把头文件体系迁到 modules——互操作层（wrapper）的预算通常比想象大；C++ 的 ODR/链接顺序之痛对应这里的 Java↔Kotlin 混编编译顺序（见 🔧 实验 2）。
- **platform type 是迁移期最大的静默炸弹**：Java 方法签名无 `@Nullable/@NonNull` 注解时，Kotlin 侧看到的是 `String!`，空安全在边界处失效——第 4 章的 nullable 迁移正是治它。

## 🔧 微实验设计（未执行，方案自写）

1. **转换质量打分**：取本仓 `courses/` 任一 CS61B Java 作业类，用 IntelliJ 转换后逐例打分：`;` 残留数、显式类型标注数、`!!` 引入数、`Unit` 返回数——四项即"Java 味浓度"基线，读完 3–12 章后复测应归零。
2. **混编编译顺序**：`kotlinc` 先编 Kotlin 引用 Java 类、`gradle` 的 `compileKotlin`→`compileJava` 两阶段各做一次；再构造一个 Java↔Kotlin 循环依赖样本，观察报错误导性（预期：需要 extract interface 解开）。
3. **platform type 爆破**：写一个无注解 Java `String identity(String s)`，Kotlin 侧 `identity(null)` 编译通过、运行 NPE；加 `@Nullable` 后编译期即拒——亲手验证"空安全止于边界"。
4. **叶子优先策略实证**：在一个三层小项目（core→data→utils）里先转 core，记录构建改造成本；再开一个新分支先转 utils 对比。⚠️ 结论预期但未实测。

## 核心概念中英对照

| 中文 | 英文 | 一句话 |
|---|---|---|
| 重构 | refactoring | 保持行为不变的逐步结构改造（Martin Fowler 定义，本书 ⚠️ 推定沿用） |
| 混合构建 | mixed-language build / interop layer | Java 与 Kotlin 源码在同一模块共存编译 |
| 一键转换 | automated conversion (IntelliJ) | 语法级翻译工具，产出惯用化的起点 |
| 惯用化 | idiomatization ⚠️ 本书用词未逐字核实 | 把转换产物改成 Kotlin 习惯写法 |
| 平台类型 | platform type (`T!`) | Kotlin 编译器对未标注 Java 类型的"未知可空性"表示 |
| 叶子模块 | leaf module | 依赖图中不被他模块依赖的模块，迁移首选 |
| 工具链 | toolchain (Gradle/Maven, JDK) | 混编期最先受冲击的构建侧设施 |
