## 机制：Java 原形 → Kotlin 翻法 → 重构步序

**Java 原形（接口当"函数的盒子"）** 🔧：

```java
interface LineRule {
    boolean accept(String line);
    String transform(String line);
}
List<String> report(List<String> lines, LineRule rule) {
    List<String> out = new ArrayList<>();
    for (String l : lines) if (rule.accept(l)) out.add(rule.transform(l));
    return out;
}
// 调用：report(lines, new LineRule() { ... });  // 匿名内部类样板
// Comparator 家族：list.sort((a, b) -> a.getName().compareTo(b.getName()));
```

**中间态（IDE 转换产物）** 🔧：`object : LineRule { ... }` 表达式替换匿名类，接口本体与两跳调用链原样保留——语法 Kotlin，设计仍 Java。

**终态（函数类型入参）** 🔧：

```kotlin
fun List<String>.report(
    accept: (String) -> Boolean,
    transform: (String) -> String,
): List<String> = filter(accept).map(transform)

lines.report(accept = String::isNotBlank, transform = String::trim)
// 盒子拆掉：LineRule 接口删除；两个策略槽各自成为函数参数。

list.sortedWith(compareBy { it.customer.city })   // Comparator 家族对位
```

**重构步序**（⚠️ 归纳）：① 鉴别"函数盒子"——单方法、无状态、不被继承的接口才有资格；② API 参数类型改函数类型（多参槽拆多参数，配合 `typealias` 恢复文档性）；③ 调用处 lambda/函数引用供给，Java 调用方经 SAM 转换照样传 lambda；④ 稳定策略升为顶层函数/`val` 常量；⑤ 确有**多方法/状态/身份**的接口不拆——改"组合 + 函数类型槽"混合形态；⑥ Kotlin 侧全消费后删接口，Java 实现者存在时先 `@Deprecated` 过渡（联动 [12 档](12-测试与互操作迁移.md)）。

迁移对照表（⚠️ 归纳）：

| Java idiom | Kotlin 对位 |
|---|---|
| `Runnable`/`Callable<V>` 入参 | `(() -> Unit)` / `(() -> V)` 参数（协程对位见 00 档并发段） |
| 自定义单方法回调接口 | 函数类型参数 + `typealias Handler = (Event) -> Unit` |
| 匿名内部类 | lambda / 带捕获的 `object` 表达式 |
| 方法引用 `Foo::bar` | `Foo::bar`（属性也可是引用目标） |
| `java.util.function.*` | 内置函数类型；跨界边界保留 JDK 接口 |
| 接口默认实现（Java 8） | Kotlin 接口默认可带实现；"不属于抽象的便利"→ 扩展函数（05 档锚点） |
| 静态工具类 | 顶层函数 / 扩展函数（推定第 16–17 章区间 ⚠️） |
| 模板方法（抽象类留槽） | 高阶函数收函数参数填槽 |
| 策略模式类层级 | 函数值即可；枚举化策略→sealed（联动 [07 档](07-从Visitor到代数数据类型.md)） |

## 老手易错点与批判读法（画像：Java/C++ 经验者）

- **函数类型装不下多方法**：`LineRule` 两方法就不能合成一个 `(String)->...`——硬拆成两个参数或保留接口；"接口是协议、函数是插槽"，别把状态机塞成参数列表（⚠️ 归纳判据）。
- **Kotlin 接口不自动 SAM**：lambda 只能喂 **Java** 方法或 `fun interface`（Kotlin 1.4+ 的函数接口声明 ✅ 语言事实）；迁移中自建回调若想让 lambda 直入，写 `fun interface`。
- **JVM 签名变形**：`(String)->Boolean` 跨回 Java 是 `Function1<String, Boolean>` 带装箱——公开 API 给 Java 消费时参数仍用 `java.util.function` 系（🔧 实验 2 用 javap 验证）。
- **lambda 无身份**：两个结构相同的 lambda 不保证 `==`，把"策略可比较"设计丢了时须升回对象（函数引用/顶层 val 才有稳定身份，🔧 实验 3）。
- **C++ 对照**：函数类型 ≈ `std::function`，函数引用 ≈ 函数指针，lambda 捕获 ≈ 闭包对象——但 Kotlin lambda 每调用可新建对象，热路径成本要按 `std::function` 的账来算而非模板内联；inline 参数是这里的"模板化"出口。
- **批判一句**：把所有回调接口无差别换成函数类型会失去扩展缝（加一个方法=改所有调用签名）；书是重构指南不是函数式宣传册，判据仍是"每步可编译 + 意图揭示"。

## 核心概念中英对照

| 中文 | 英文 | 一句话 |
|---|---|---|
| 函数类型 | function type (`(A) -> B`) | 把"可调用的东西"写进类型系统 |
| 单抽象方法接口 | SAM interface | 只有一个抽象方法的接口（函数盒子） |
| 函数接口 | `fun interface` | Kotlin 侧允许 lambda 直入的 SAM 声明 |
| SAM 转换 | SAM conversion | lambda 自动适配接口参数（仅 Java 接口自动） |
| 函数引用 | function reference (`::`) | 具名可调用值，带身份 |
| 高阶函数 | higher-order function | 收/发函数值的函数 |
| 扩展函数 | extension function | 无继承介入给类型加"便利方法" |
| 类型别名 | typealias | 给函数类型起域名，零运行时层（15 章同款工具） |
