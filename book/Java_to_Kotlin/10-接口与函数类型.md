## 机制：Java 原形 → Kotlin 翻法 → 重构步序

**Java 原形（接口当"函数的盒子"）** 🔧：

```java
interface LineRule {
    boolean accept(String line);
    String transform(String line);
}
List<String> report(List<String> lines, LineRule rule) {
    List<String> out = new ArrayList<>();
    for (String l : lines) if (rule.accept(l)) out.add(rule.transform(l));
    return out;
}
// 调用现场：report(lines, new LineRule() { ... });  // 匿名内部类样板
// Comparator 家族：list.sort((a, b) -> a.getName().compareTo(b.getName()));
```

**中间态（IDE 转换产物）** 🔧：`object : LineRule { ... }` 替换匿名类，接口本体与两跳调用链原样保留——语法 Kotlin，设计仍 Java。

**终态（函数类型入参）** 🔧：

```kotlin
fun List<String>.report(
    accept: (String) -> Boolean,
    transform: (String) -> String,
): List<String> = filter(accept).map(transform)

lines.report(accept = String::isNotBlank, transform = String::trim)  // 盒子拆掉
list.sortedWith(compareBy { it.customer.city })                       // Comparator 族对位
```

**重构步序**（⚠️ 归纳）：① 鉴别"函数盒子"——单方法、无状态、不被继承的接口才有资格；② API 参数改函数类型（多槽拆多参，配 `typealias` 恢复文档性）；③ Kotlin 调用处给 lambda/函数引用，Java 调用方经 SAM 转换照样传 lambda；④ 稳定策略升顶层函数/`val`；⑤ 确有**多方法/状态/身份**的接口不拆——改"组合 + 函数类型槽"混合形态；⑥ Kotlin 侧全消费后删接口，Java 实现者存在先 `@Deprecated` 过渡（联动 [12 档](12-测试与互操作迁移.md)）。

迁移对照表（⚠️ 归纳）：

| Java idiom | Kotlin 对位 |
|---|---|
| `Runnable`/`Callable<V>` 入参 | `(() -> Unit)` / `(() -> V)` 参数（协程对位见 00 档并发段） |
| 自定义单方法回调接口 | 函数类型参数 + `typealias Handler = (Event) -> Unit` |
| 匿名内部类 / 方法引用 | lambda / `Foo::bar`（属性亦可作引用目标） |
| `java.util.function.*` | 内置函数类型；跨界边界保留 JDK 接口 |
| 接口默认实现（Java 8） | Kotlin 接口可带实现；"不属于抽象的便利"→扩展函数（05 档锚点） |
| 模板方法/策略类层级 | 高阶函数收槽；枚举化策略→sealed（联动 [07 档](07-从Visitor到代数数据类型.md)） |

## 老手易错点与批判读法（画像：Java/C++ 经验者）

- **函数类型装不下多方法**：`LineRule` 两方法不能并成单个 `(String)->...`——硬拆两参数或保留接口；"接口是协议、函数是插槽"，别把状态机塞成参数列表（⚠️ 归纳判据）。
- **Kotlin 接口不自动 SAM**：lambda 只能喂 **Java** 方法或 `fun interface`（Kotlin 1.4+ 函数接口声明 ✅ 语言事实）；自建回调若想收 lambda 直入，写 `fun interface`。
- **JVM 签名变形**：`(String)->Boolean` 跨回 Java 是 `Function1<String, Boolean>` 带装箱——公开 API 给 Java 消费时参数仍用 `java.util.function` 系（🔧 实验 2 javap 验证）。
- **lambda 无身份**：结构相同的两个 lambda 不保证 `==`——需要"策略可比较"时用函数引用/顶层 val 取稳定身份（🔧 实验 3）。
- **C++ 对照**：函数类型 ≈ `std::function`，函数引用 ≈ 函数指针，捕获 lambda ≈ 闭包对象——但 Kotlin lambda 每次调用可新建对象，热路径按 `std::function` 记账而非模板内联；`inline` 参数是这里的"模板化"出口。
- **批判一句**：无差别函数化会失去扩展缝（加一方法=改全部调用签名）；本书是重构指南不是函数式宣传册，判据仍是"每步可编译 + 意图揭示"。

## 核心概念中英对照

| 中文 | 英文 | 一句话 |
|---|---|---|
| 函数类型 | function type (`(A) -> B`) | 把"可调用"写进类型系统 |
| 单抽象方法接口 | SAM interface | 只有一个抽象方法的接口（函数盒子） |
| 函数接口 / SAM 转换 | `fun interface` / SAM conversion | Kotlin 侧收 lambda 的声明 / lambda 自动适配（仅 Java 接口自动） |
| 函数引用 / 高阶函数 | function reference (`::`) / HOF | 具名可调用值带身份 / 收发函数值 |
| 扩展函数 | extension function | 无继承介入给类型加"便利方法" |
| 类型别名 | typealias | 给函数类型起域名，零运行时层（15 章同款工具） |
