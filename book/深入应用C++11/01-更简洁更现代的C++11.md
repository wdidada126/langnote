## 核心概念速览（中英对照）

- **自动类型推导** — auto type deduction：由初始化物反推变量类型，按值语义时发生数组/函数衰减、剥顶层 const。
- **decltype** — decltype：从表达式的**语法形态**原样取类型，引用与 const 一并保留；`decltype((x))` 因括号变引用。
- **返回类型后置** — trailing return type：`auto f(args) -> T`，让返回类型能引用形参/`this`。
- **别名模板** — alias template：`template<class T> using P = T*;`，可模板化的"typedef"。
- **列表初始化** — braced initialization：`{}` 通吃一切初始化场景，附带**禁止窄化**的编译期保险。
- **窄化转换** — narrowing conversion：`{}` 上下文被禁止的丢精度/丢位转换（`double→int`、`int→char`）。
- **基于范围的 for** — range-based for：`for (auto&& x : c)`，脱糖为 `begin/end` 循环。
- **可调用对象包装器** — std::function：类型擦除的统一调用接口，能持有函数指针/闭包/绑定对象。
- **绑定器** — std::bind：用 `_1/_2` 占位符生成部分求值可调用对象。
- **lambda 表达式与闭包** — lambda / closure：编译器合成的带 `operator()` 匿名类；捕获即数据成员。
- **元组** — tuple：异构、编译期定长的值序列，`tie` 做解包赋值。

## 一、动机：C++98 的"写三遍类型"病

C++98 里 `map<string, vector<int>>::iterator it = m.begin();` 这类代码把类型信息写了两遍且易错；
匿名可调用对象（函数指针 + 上下文指针）几乎无法直接表达；`vector<int> v(3.5);` 悄悄窄化成 3。
C++11 这一章的每个特性都对着一个"重复/失真"病灶：**把类型判断交还给编译器和标准库**。

## 二、机制

### 2.1 auto 与 decltype 是同一套规则的正面和反面
`auto x = e;` 走模板实参推导（按值）：引用被剥、顶层 const 被剥、数组退化为指针。
`decltype(e)` 完全不看值只看语法：变量名返回声明类型；非变量表达式按值类别返回 `T` / `T&`。
返回类型后置存在的理由：`template<class A, class B> auto add(A a, B b) -> decltype(a + b)`——
`decltype` 需要**看到形参**，而前置写法时形参还没进作用域。C++14 补上 `auto` 返回类型推导后，
这条语法从"刚需"降级为"风格"。

### 2.2 lambda 闭包的真实布局：它就是函数对象
`[a, &b](int x) { return a + b + x; }` 脱糖为编译器合成类：

```cpp
// 🔧 示意（非原书逐字）
struct Closure {
    A a;            // 值捕获 → 构造时拷贝进成员
    B& b;           // 引用捕获 → 成员是引用
    auto operator()(int x) const { return a + b + x; }  // 默认 const！
};
```

三条推论全部可实测：① 值捕获在**定义点**求值，不在调用点；② `mutable` 只是去掉 `const`；
③ 捕获越少闭包越小，`std::function` 装得下的门槛（小对象优化，libstdc++ 为 16 字节
——⚠️ 通行值，本次未反汇编复核）就取决于闭包尺寸。这解释了为什么 `[=]` 全值捕获在
`std::function` 场景可能多一次堆分配。

### 2.3 std::function 与 bind 的类型擦除成本
`std::function<int(int)>` 是"指针 + 虚表式调用协议"的手写等价物：目标可调用对象要么放进内联
缓冲区（SBO），要么堆上 new；调用时一次间接跳转，且**不能被内联**。`std::bind` 的产物也是
一个存储了实参拷贝的闭包类。所以本书工程章（第 8 章命令模式、第 9 章线程池）里 function/bind
并用，而今天口径是"能模板就模板，非擦除不可才 function"。

### 2.4 列表初始化的重载诡雷
`vector<int> v{5};` 长度为 1（元素 5），`vector<int> v(5);` 长度为 5（5 个 0）——
`initializer_list` 重载在重载决议中**优先级最高**。这就是 1.3.4"防止类型收窄"的代价与红利并存。

## 三、权衡与实战提示

- `auto` 丢掉代理类型可见性：`auto b = vec_bool[0]` 得到的是 `vector<bool>::reference` 代理而非 `bool`（详见 [../Effective_Modern_C++/02-auto.md](../Effective_Modern_C++/02-auto.md)）。
- 引用捕获的 lambda 生命周期：异步保存闭包时引用捕获几乎必悬垂（第 15/16 章 task/asio 场景的核心纪律）。
- `std::bind` 求值时机不透明、不可内联；lambda 表达力是它的超集。bind 仅存"占位符转发"独苗场景。

## 四、相邻概念对比

| 对比项 | 差异一句话 |
| --- | --- |
| auto vs decltype | 一个按值推导会衰减，一个按语法原样保留 |
| lambda vs 手写函数对象 | 同一种东西，闭包类字段 vs 成员变量；lambda 赢在定义点就近捕获 |
| std::function vs 模板参数 | 擦除换统一接口，输掉内联与堆成本；头文件 API 用 function，内部算法用模板 |
| tuple vs struct | tuple 匿名可拼装可算法化（tie/apply），struct 有名字自文档 |

## 五、实测（🔧 三档：g++ 15.2，gnu++11/17/23，`D:\develops\tmp\cppsnippets_cpp11\ch01.cpp`）

```text
gnu++11: 编译失败——error: 'make_unique' is not a member of 'std'（同文件里 lambda 初始化捕获也是 14 特性）
gnu++17: OK  输出 "lambda ret 0 / tie 42,cosmos / bindings 42,cosmos"
```

- `static_assert(is_same<decltype(y), int>)` 与 `is_same<decltype(z), const int&>` 三档皆绿：auto 衰减 vs decltype 保引用，规则十年未变。

- 结构化绑定输出与 `tie` 输出同值：`42,cosmos`——17 档起 `tie` 的"先声明后解包"两步并为一步。

## 六、最新演进与工业实践

- **C++14**：泛型 lambda（`[](auto x)`）、初始化捕获、`auto` 返回类型推导——本章一半"未竟之事"两年内补齐。
- **C++17**：CTAD 让 `std::pair p(1, 2.0);` 免写模板参数（P0091R4，wg21.link/p0091 实测解析至 r4）；`if constexpr` 取代一部分 SFINAE 样板（P0292R2 实测）。展开见 [../C++17完全指南/05-类模板实参推导CTAD.md](../C++17完全指南/05-类模板实参推导CTAD.md)。
- **C++20**：lambda 进入常量表达式；`[this]` 隐式捕获弃用倾向（捕获 `*this` 由引用改按值的口径修正）。ranges 的惰性管道让"lambda + 算法"成为主流写法（P0896R4，实测解析）。
- **C++23**：`static operator()`（lambda 可无 this）；`std::expected` 补"可失败调用"返回值（P0792R14 实测，详见 [03 章](03-type_traits与可变参数模板.md)）。
- **工业侧**：Google/Chromium 风格对 `std::function` 的堆分配有专文告诫，abseil 提供 `absl::AnyInvocable/AnyFunction`（[abseil-cpp](https://github.com/abseil/abseil-cpp)，实测 2026-09：约 18k star，release 20260817.0）作为带移动语义的替代——本书自研的 function 用法在 2026 年可整体平移到该族。
- **bind 的退场**：C++23 起 `<functional>` 的 bind1st/bind2nd 等早已移除，`std::bind` 仍在但社区口径（Core Guidelines F.50 类）是"优先 lambda"。⚠️ 条款号未逐字核实。
