> 覆盖原书 4.1 shared_ptr / 4.2 unique_ptr / 4.3 weak_ptr（含返回 this、解循环引用）/ 4.4 托管第三方库内存。
> 大纲形态见 [../深入应用C++11.md](../深入应用C++11.md)；返回 [00-总览与阅读地图.md](00-总览与阅读地图.md)。

## 核心概念速览（中英对照）

- **独占所有权指针** — unique_ptr：move-only，析构即 delete，默认零额外开销。
- **共享所有权指针** — shared_ptr：引用计数对象，拷贝廉价（计数 ++）、跨线程计数原子。
- **控制块** — control block：存强/弱计数、删除器、分配器与对象指针的堆元数据，一对象多块即 UB。
- **弱引用指针** — weak_ptr：不延长生命期的观测者，`lock()` 判活取共享指针。
- **enable_shared_from_this** — 从 this 安全升出 shared_ptr 的标准基类（内部即一个 weak_ptr）。
- **自定义删除器** — custom deleter：把 `fclose/sqlite3_close/free` 等归还协议接入析构，托管 C API 句柄。
- **循环引用** — circular reference：shared_ptr 互锁使计数永不为零，所有权图须有一边改 weak。
- **空基优化** — empty base optimization：无状态删除器被存进 unique_ptr 的基类，尺寸不翻倍。
- **资源获取即初始化** — RAII：本章一切的地基；智能指针 = RAII 对堆指针的制度化。

## 一、动机：把"谁释放"从注释搬进类型

C++98 的裸指针 + 手册约定是泄漏/双删/悬垂的温床（[../提高C++性能的编程技术/08-引用计数.md](../提高C++性能的编程技术/08-引用计数.md)
展示了当年手写计数器的全部代价）。C++11 智能指针三件套把所有权语义做成类型：
`unique_ptr` 说"只有我"，`shared_ptr` 说"我们计数"，`weak_ptr` 说"我只看着"。书中 4.4 进一步
把这套协议伸向第三方 C 库——这正是 [10 章](10-消息总线与SQLite封装.md) SmartDB 托管 `sqlite3*`/`sqlite3_stmt*` 的底座。

## 二、机制

### 2.1 控制块：shared_ptr 的全部复杂度所在
一个 `shared_ptr` 对象只是两个裸指针 `{T*, control_block*}`；计数不在对象上而在块里。
`make_shared` 把 **对象与块合并为一次分配**（省一次 new、数据局部性更好），代价是：只要还有
weak_ptr 存在，整块（含已析构的对象内存）都不能归还——"make_shared 的延迟释放问题"。
手动 `shared_ptr<T>(new T)` 则是两块分离，对象先亡、块随 weak 走。
两条红线：**同一裸指针构造两个 shared_ptr**（两个独立计数，双删）与 **vector<shared_ptr> 无锁
并发改计数**（计数原子 ≠ 指针变量本身线程安全）。

### 2.2 unique_ptr 是零开销抽象的标本
删除器是模板参数：默认删除器无状态 → 空基优化，`sizeof(unique_ptr<T>) == sizeof(T*)`。
自定义删除器若有状态（如函数指针）则尺寸翻倍——4.4 托管 C API 时，**函数指针删除器优于
lambda 捕获**（捕获了东西的 lambda 让 unique_ptr 变大）。"声明在类内、定义在实现文件"的
析构函数是 Pimpl 配 unique_ptr 的必修课（不完全类型在默认析构展开点必须完整）。

### 2.3 weak_ptr 与"返回 this"
`enable_shared_from_this` 内部预置一个 weak_ptr，对象由 shared_ptr 接管时自动初始化；
`shared_from_this()` = `weak.lock()`。裸写 `return shared_ptr<T>(this)` 是本书点名的一票否决——
它新建第二个控制块，与 2.1 的第一条红线同罪。循环引用解法不是"更小的 shared_ptr"，
而是**把所有权图的一条边降格为观测边**（父持子 shared、子持父 weak，析构序实测可见）。

### 2.4 为什么 shared_ptr 能"随身带删除器"而 unique_ptr 不能
控制块本身是个以"对象类型 + 删除器类型 + 分配器类型"为模板参数的类层次，删除器作为**数据成员**
存在块里——所以 `shared_ptr<T>` 类型本身不含删除器信息，`shared_ptr<FILE>` 用 `fclose` 删除器构造后，
拷给任何持有者都走同一块、同一个 `fclose`（🔧 实测 use_count 序列成立的前提）。对比 2.2：
unique_ptr 把删除器放进**类型参数**（空基优化），零开销但换删除器即换类型。一处的"胖类型"
换来另一处的"瘦类型+胖堆块"，这是两种指针最容易被忽略的设计对偶。
`weak_ptr::lock()` 的内部协议是"观察计数（weakcount 上另设的原子计数）+ CAS 升强计数"，
所以对象析构后、块回收前，`lock()` 稳定返回空——这就是"能问还活着吗"的实现学。

## 三、权衡与实战提示

- shared_ptr 不是"更方便的指针"而是"共享所有权的显式协议"；默认答案应是 unique_ptr + 借用裸指针/引用。
- 跨线程拷贝 shared_ptr 安全但锁竞争在控制块上（实测 `use_count` 的原子自增就是争用点）；
  高频场景改用消息总线复制数据（[10 章](10-消息总线与SQLite封装.md)）或 `atomic<shared_ptr>`（C++20）。
- 托管第三方内存时**删除器必须与分配 API 成对**：`sqlite3_free` vs `free` 错配是教科书级事故。
- 别把 shared_ptr 塞进"逻辑共享"场景当作全局变量捷径：对象图若本质是树/DAG，用 unique_ptr 拥有 +
  裸指针观察的显式模型（EMC Item 22），shared 只留给真正的"共同拥有"。
- 从容器/参数视角记一条传递律：按值拷 shared（付原子税）、按 `const&` 借（免）、按 `shared_ptr&&` 移动（转所有权）——
  本书代码里三种都出现过，读 8/9 章线程池与 IoC 时按这条律对照。

## 四、相邻概念对比

| 对比 | 差异一句话 |
| --- | --- |
| unique_ptr vs 裸指针+RAII类 | 同一件事，前者标准、可移动、可进容器 |
| shared_ptr vs intrusive_ptr | 计数在堆块 vs 计数在对象内；后者省一次分配但侵入类型定义 |
| weak_ptr vs 裸观测指针 | 前者能问"还活着吗"，后者永远不能 |
| make_shared vs new | 单分配 + 异常安全，但生命周期与 weak 耦合 |
| shared_ptr 删除器 vs unique_ptr 删除器 | 数据成员进堆块（类型瘦、块胖）vs 模板参数进基类（类型胖、零堆） |
| weak_ptr vs 过期通知回调 | 前者"拉"（lock 判活），后者"推"（析构时反查登记表）；观察者场景常用后者换掉轮询 |

## 五、实测（🔧 三档：g++ 15.2，gnu++11/17/23，`ch04.cpp`）

```text
gnu++11: 编译失败——error: 'make_unique' is not a member of 'std'（它属于 C++14，本书只能自研，见 cosmos SharedptrUtil.hpp）
gnu++17: OK 输出序列：
  FILE owned, use_count=1        ← shared_ptr<FILE> + fclose 删除器（4.4 机制）
  open 7 → s.use_count=1         ← unique_ptr 移动到 shared_ptr：所有权升级免删除器
  B dtor → A dtor                ← weak 边断开循环，双双正常析构
  copy shared -> use_count=2     ← 拷贝即强计数 ++
gnu++23: 同 17
```

- 析构打印顺序（B 先 A 后）验证了"shared 环 + weak 破口"的可析构性；换成两个互指 shared_ptr
  则两行都不打印（泄漏）——本实验的对照组，机制层结论与书一致。
- 🔧 探针实测 `sizeof(std::shared_ptr<int>)=16`（x86_64 两枚裸指针）：与 2.1 "对象只是
  `{T*, control_block*}`"的论断逐字节吻合——计数不在对象上，也不在指针上，只在块里。

## 六、最新演进与工业实践

- **C++14**：`make_unique` 入库（实测 gnu++11 的缺失即历史现场）。
- **C++17**：过对齐类型的 `new` 保证（aligned new，P0035R4，wg21.link/p0035 实测解析）——在此之前
  `shared_ptr<T>(new T)` 对 `alignas(64)` 类型可能拿回未对齐内存（[06 章](06-便利工具与其他特性.md) 对齐实验的暗坑）；
  `weak_ptr::to_string/from_string` 进库；`enable_shared_from_this` 允许 `this` 参数重载。
- **C++20**：`std::atomic<std::shared_ptr>` 与 `atomic<weak_ptr>` 自由函数废弃转专门特化——智能指针
  跨线程共享的"要不要加自己的锁"有了标准答案。
- **C++23**：`std::out_ptr/in_ptr` 终结"`unique_ptr::get()` 出参喂 C API"的玄学写法（本书 4.4 的
  最后一块胶带被标准化撕掉）。⚠️ 提案号未逐条实测，特性名+版本为准。
- **工业侧**：Chromium 以 `raw_ptr` 加固观测指针（PartitionAlloc 项目），abseil `WrapUnique/Nullability`
  同样指向"所有权注释进类型"；Sanitizers（ASan/LeakSanitizer）成为"防泄漏"的第一道工程防线——
  智能指针协议 + 动态检测双轨，正是本章 2026 年的完整形态。
- **当年自研物现状**：cosmos 的 `SharedptrUtil.hpp`（weak 版 make、enable 辅助）职责已被标准吸收，
  作为教材仍有价值（实测仓库仍在，未归档）。
