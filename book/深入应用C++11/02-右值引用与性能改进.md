## 核心概念速览（中英对照）

- **左值/右值（值类别）** — lvalue / rvalue：可否取地址、是否将亡物的语法分类，移动语义的输入信号。
- **右值引用** — rvalue reference `T&&`：绑定将亡物、为其延长生命期并开启"窃取"重载。
- **移动语义** — move semantics：`std::move` 强制转右值 + 移动构造/赋值窃取资源，O(1) 替代深拷贝。
- **移动保证** — move guarantee / `move_if_noexcept`：标准库只敢移动 noexcept 可移动的对象。
- **转发引用（万能引用）** — forwarding reference：`T&&` 且 T 正在推导时左右通吃的形参形态。
- **引用折叠** — reference collapsing：`& &`、`& &&`、`&& &` → `&`；`&& &&` → `&&`。
- **完美转发** — perfect forwarding：`std::forward<T>(x)` 按实参原值类别透传，构造参数不丢身份。
- **就地构造** — emplace：容器在节点存储上直接构造元素，跳过临时对象与其移动。
- **哈希容器** — unordered container：桶数组 + 冲突链，平均 O(1) 换取无序遍历与 rehash 停顿。
- **保证的拷贝消除** — guaranteed copy elision：C++17 起 prvalue 初始化不再要求可访问的拷贝/移动构造。

## 二、机制

### 2.1 `std::move` 不移动任何东西
它是一个无条件 cast：`static_cast<T&&>(lval)`。真正的移动发生在被重载决议选中的**移动构造函数**里。
所以"给类加移动语义"= 自己写窃取式移动构造/赋值 + 记得抑制拷贝（五规则），语言只负责把"我可以被窃取"
这个信号传到重载决议。

### 2.2 移动与异常安全的耦合：`move_if_noexcept`（本章机制层核心）
`vector` 扩容搬迁旧元素时必须维持**强异常安全保证**：若搬一半抛异常要能回滚。拷贝天然可回滚，
移动会把源对象掏空——除非源对象的移动承诺**不抛**。于是标准库用
`move_if_noexcept`：`is_nothrow_move_constructible` 为真才移动，否则退回拷贝。
手写移动构造忘标 `noexcept` 的类，在 vector 里得到的待遇就是实测里那次多余的拷贝。

### 2.3 完美转发 = 值类别穿隧道的两个零件
零件一：`template<class T> void f(T&&)` 中的 `T&&` 是转发引用，接左值时 `T=A&`，
由引用折叠规则折回 `A&`；接右值时 `T=A`，保持 `A&&`。零件二：`std::forward<T>(x)` 用 `T`
里存的"当年推导结果"还原类别。缺一件：只写 `T&&` 不用 forward 是"能接但不能传"；
只写 `const A&` + 拷贝转发则右值身份永久丢失。

### 2.4 emplace 的真实收益与两类翻车
收益：`emplace_back(args...)` 把 args 完美转发进节点存储上的 placement new，临时对象整个消失
（对比 `push_back(T(args...))` 至少一个临时 + 一次移动/拷贝）。翻车一：`emplace` 绕过
`insert` 的"先查重"逻辑，map 上可能白白构造又被销毁；翻车二：显式被删/私有构造函数在
emplace 路径上才会报错，报错点从调用方挪进模板深处（诊断变差是当年实感，GCC 后来大幅改善）。⚠️

## 三、权衡与实战提示

- 移动对象处于"有效但未指定"状态：继续使用须先重赋值；`moved-from` 语义要写进类文档。
- 哈希容器换走的是**遍历有序性与最坏保证**：rehash 使迭代器失效、DoS 场景哈希碰撞退化——当年本书用
  `unordered_map` 优化查找表，今天高敏路径先看 abseil `flat_hash_map`/`btree_map`（见下文演进）。
- 转发引用进公开 API 是接口污染（吞掉一切重载）——EMC Item 30 的"按值 + move 替代方案"对照
  [../Effective_Modern_C++/08-微调与全书收束.md](../Effective_Modern_C++/08-微调与全书收束.md)。

## 四、相邻概念对比

| 对比项 | 差异一句话 |
| --- | --- |
| `std::move` vs `std::forward` | 无条件 cast vs 依推导历史条件 cast |
| 转发引用 vs 右值引用 | 差别在 T 是否**正在被推导**且直接绑定实参 |
| emplace vs insert | 就地构造 vs 先物化元素再放入；前者省一次搬运、后者诊断友好 |
| unordered vs map | 平均 O(1) 无序 vs O(log n) 有序 + 迭代器稳定 |

## 五、实测（🔧 三档：g++ 15.2，`ch02.cpp` / `ch02b.cpp`）

```text
ch02 三档全过，关键读数：
  move_if_noexcept: copies=1 moves=2   ← 故意不标 noexcept 的移动构造，扩容搬迁退回拷贝
  elision copies=0（三档同值：gcc 连 gnu++11 都实际消除了这份拷贝——红利在 C++17 才制度化）
  unordered: inserted=0 v=a            ← emplace 遇已有键不覆盖
ch02b（prvalue 返回 + 拷贝/移动构造全删的类型）:
  gnu++11: 编译失败 error: use of deleted function 'NoCopy::NoCopy(NoCopy&&)'
  gnu++17/gnu++23: 编译通过、无运行输出（纯静态差异）
```

ch02b 是"三档诊断差异"的标本：C++11 时代 `T t = T();` 即使拷贝构造被删也编译不过——消除是
"允许但不保证"；C++17 起 prvalue 与目标对象是**同一个对象**，删光的类型照样通过（P0135R1，
wg21.link/p0135 实测解析至 r1）。`noexcept` 门槛实验三档行为一致：**这条规则至今没变**，
只是 C++20 起析构/新表达式隐式 noexcept 让"忘标"场景变少 ⚠️（隐式规则细节见 [06 章](06-便利工具与其他特性.md)）。

## 六、最新演进与工业实践

- **C++14**：`std::make_unique` 补齐（移动时代工厂三件套齐）。
- **C++17**：保证的拷贝消除（P0135R1 实测）改写 2.1/2.2 节论证——返回值不再需要"移动或消除"二选一；
  结构化绑定让 `pair` 返回值可读（P0217R3 实测，见 [../C++17完全指南/01-结构化绑定.md](../C++17完全指南/01-结构化绑定.md)）；
  `unordered_*` 获得节点句柄 `extract/merge/insert_or_assign`，"查重再插"的两步竞态合一。
- **透明比较器与异构查找**（C++14）：`unordered_map<string, X, std::hash<>, equal_to<>>` 配
  `is_transparent` 后可用 `string_view` 查、零临时——本书"字符串 key 查找表"场景的当代正解。
- **ranges（C++20，P0896R4 实测）/ 容器生态**：Google 内部哈希表开源为 abseil SwissTable
  `flat_hash_map`（[abseil/abseil-cpp](https://github.com/abseil/abseil-cpp)，实测 release 20260817.0）；
  leveldb 的 MemTable→跳表、以及其后继生态同样向 abseil 靠拢（leveldb 最新发布仍停在 1.23，
  经 GitHub API 实测，见 [10 章](10-消息总线与SQLite封装.md) 存储对账）。2015 年"标准 unordered 够用"
  的判断，今天在高吞吐路径上默认让位给 flat/btree 家族。
- **提案对账**：CTAD P0091R4、if constexpr P0292R2（wg21.link 实测）把"完美转发给构造函数"的一半
  用例直接变成 `std(A, B)` 免转发。
