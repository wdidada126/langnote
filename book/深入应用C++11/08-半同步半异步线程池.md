## 核心概念速览（中英对照）

- **半同步半异步** — half-synchronous half-asynchronous (HSHA)：调用方按同步语义提交，执行侧异步排队消费，两种世界由队列解耦。
- **同步队列** — synchronized queue：mutex + 双条件变量（不空/不满）+ 容量上限的阻塞生产消费容器。
- **有界队列背压** — bounded queue backpressure：队列满时阻塞提交方，把过载信号还给上游。
- **任务类型擦除** — type-erased job：`function<void()>` 装 `packaged_task` 闭包，签名统一进队列。
- **结果通道** — future/promise 过墙：任务在线程 A 执行、结果在调用线程 B 的 `get()` 取出。
- **result_of 返回类型推导** — `std::result_of<F(Args...)>::type`：submit 签名里替用户算出 future 类型（C++11 时代写法，后被 invoke_result_t 取代）。
- **哨兵停机** — sentinel shutdown：往队列塞特殊任务/标志位通知工人退场，C++20 前无标准中止协议。
- **异常过墙** — exception transport：任务抛出的异常须存进 shared state，在 get() 处重抛——packaged_task 白送。
- **线程数决策** — IO 密集 vs CPU 密集：池大小 ≈ 核数（计算）或按阻塞比放大（IO），经典 HSHA 调参题。

## 一、动机：每请求一线程的账单

2015 年国内服务端主流还是 pthread 手工池或"每连接一线程"。`std::thread` 普及后第一个要还的债
就是线程创建/调度成本与无上限并发，本书用第 9 章给出 C++11 化的标准答案：队列 + 固定工人 +
future 结果通道。这个骨架今天仍活在asio 的 `thread_pool`、TBB 的 `task_group_adaptor`、
各类 RPC 框架的 worker 里——**它就是"线程池"的当代原型形态**。

## 二、机制

### 2.1 SyncQueue：第 5 章协议的组合验证
`put/take` 各自 `unique_lock + wait(pred)`：谓词把"虚假唤醒 + 丢通知 + 容量竞争"三类事故一起消化；
双条件变量（not_empty/not_full）分开唤醒生产端与消费端。析构停机要 `close()` 广播，
worker 依 "空且 closed" 退出——**这是 C++20 stop_token 出现前唯一的标准姿势**。

### 2.2 submit 的三段式类型体操
```cpp
// 🔧 书中机制复刻（实测 ch08.cpp，非原书逐字）
template <class F, class... Args>
auto submit(F&& f, Args&&... args)
    -> std::future<typename std::result_of<F(Args...)>::type> {
    using R = typename std::result_of<F(Args...)>::type;
    auto task = std::make_shared<std::packaged_task<R()>>(
        std::bind(std::forward<F>(f), std::forward<Args>(args)...));
    auto fut = task->get_future();
    q_.put([task] { (*task)(); });      // shared_ptr：packaged_task 不可拷贝，只能共享持有
    return fut;
}
```
三个零件各管一事：`forward` 保值类别（02 章）、`packaged_task` 管结果与异常过墙（05 章）、
`shared_ptr` 管"可调用对象进 `function<void()>` 时生命周期自治"（04 章）。**本章是全书特性合奏
浓度最高的一章**——面试级拆解题。

### 2.3 半同步半异步的"度"在哪
调用 `submit` 后立刻 `get()` → 对调用方退化为同步；不 `get` → 完全异步；`wait_for` 定时 → 混合。
HSHA 的"半"是**用法决定**而非实现决定，接口把选择权留给 future。

### 2.4 停机协议的三个难点（读 ch08.cpp 的对照清单）
① **先关后醒**：`close()` 必须置标志再 `notify_all`，顺序颠倒且谓词不含 closed 分支时 worker
永睡（🔧 探针即此形状；谓词版 `wait(lk, []{ return !q_.empty() || closed_; })` 把事故挡在谓词层）。
② **join 点唯一**：析构里 join 全部 worker 前，须保证没有任何任务还引用 `this`/队列——
submit 返回的 future 若被用户扣着不取，任务本体仍会跑完，析构等待是正当的；反过来
detach 停机就是把悬垂合法化（05 章 2.2 的 terminate 裁决在这里回收）。
③ **任务不吞池**：一个任务自死锁（见"三"节第 2 条）会让"剩余队列 + join"整体挂死——
停机路径测试必须与过载测试同批设计，muduo 的"所有测试都跑一遍 stop 序列"是同一纪律。

## 三、权衡与实战提示

- 队列容量是过载策略的化身：无界=内存换延迟（雪崩预备），有界=背压或拒绝（`try_submit` 加策略位）。
- 任务里再 submit 并同步等待 = 经典自死锁（工人数不足时环形等待）；延续链（then）才是安全组合（见 [11 章](11-LINQ并行任务与异步网络.md)）。
- `std::function<void()>` 的任务装箱税（堆分配 + 间接调用）在百万级小任务场景显著——TBB 式工作窃取
  与任务袋结构是工业解法，本书 15 章 TaskCpp 的 `task` 对象即同题。

## 四、相邻概念对比

| 对比 | 差异一句话 |
| --- | --- |
| 线程池 vs async 每任务起线程 | 受控复用 + 排队 vs 无上限并行；后者是"谁 get 谁跑"的放大器 |
| 哨兵停机 vs stop_token | 前者要占一个队列位且协议私有，后者标准语言级（C++20） |
| HSHA vs Reactor/Proactor | 线程解耦请求/处理两段；后两者是 I/O 事件模型，组合使用（asio 把两章都覆盖了） |
| packaged_task vs 手写 promise | 异常自动进 shared state；手写要自己 catch + set_exception |

## 六、最新演进与工业实践

- **C++14/17**：`std::invoke`/`invoke_result_t` 取代 `result_of`（已废弃，23 档弃用警告）；
  `shared_mutex` 让池内统计可读多写少。
- **C++20**：`std::jthread` + `stop_token`：**哨兵停机退役**——worker 谓词直接查 `st.stop_requested()`，
  析构自动 request_stop+join（本机 gnu++23 语法探针通过，运行受限同第五节）；`counting_semaphore`
  替代手写"并发上限闸门"。
- **C++26 方向**：senders/receivers（P2300R10，wg21.link/p2300 实测解析至 r10）把"队列+池+结果通道"
  三件套抽象成 `schedule/start` 执行器协议；std 池将不再是手写题。
- **工业池现状对账**：Intel TBB 已移交开源——仓库 [uxlfoundation/oneTBB](https://github.com/uxlfoundation/oneTBB)
  （原 oneapi-src 组织迁移至 UXL Foundation，API 实测：最新 release v2023.1.0，2026-07-13；push 2026-09-25
  活跃）；asio 自带 `asio::thread_pool`（[chriskohlhoff/asio](https://github.com/chriskohlhoff/asio)，
  实测 2026-07 仍活跃）——本书第 16 章的 I/O 框架如今内置了本章的池。PPL（微软并发运行时）
  随 Windows 平台策略趋于存量维护 ⚠️（通行记载，官方 deprecation 公告未逐字核实）。
- **中文语境延伸阅读**：陈硕《Linux 多线程服务端编程》的 muduo 单 Reactor 多线程模型
  （[../Linux多线程服务端编程.md](../Linux多线程服务端编程.md)）给出同题的"网络框架视角"答案，
  与本章 HSHA 互相补位。
