## 核心概念速览（中英对照）

- **线程安全局部静态** — thread-safe local static（magic statics）：C++11 §6.7 起，局部静态量初始化被保证"一次且仅一次、其余线程等待"。
- **双检锁** — double-checked locking：magic statics 出现前的手工替代品，内存序不写对即是错误教材。
- **观察者与令牌反注册** — observer + token：注册返回句柄，凭句柄注销，解决"回调悬挂"。
- **访问者双分派** — visitor / double dispatch：accept-visit 手工两跳，被 `variant + visit` 单跳替代。
- **overloaded 惯用法** — overloaded lambda set：把一组 lambda 合成一个重载集喂给 `std::visit`。
- **命令对象** — command：动作 + 参数 + 撤销的封包；`std::function` + lambda 让 GoF 的抽象基类瘦身成一行。
- **对象池** — object pool：预生成/回收昂贵对象；C++11 的 move 语义让"归还"成为类型化协议。
- **删除拷贝、保留移动** — move-only type：池内句柄回到池外必须有唯一所有权，拷贝=双归还=UB。
- **设计模式的"特性税"** — idiom tax：每个 GoF 模式在 C++98 里用样板缴纳的成本，C++11 逐项退税。

## 一、动机：GoF 的 C++98 实现是"特性缺位的补偿装置"

本书第二篇第一篇的过渡章。它的论点值得单独记：很多模式的重量级形态（抽象工厂的嵌套类、
命令的继承树、访问者的 accept）不是设计需要，而是**语言缺位时的人肉编译**。C++11 补上
闭包、移动、静态初始化协议后，同一模式的实现体积塌缩一个量级。

## 二、机制

### 2.1 单例：从双检锁到一行 static
C++11 起 `static Config c;` 在 `instance()` 内的初始化本身就是原子协议（编译器插入守卫变量 +
锁等待，GCC 实现名 guard variable / `__cxa_guard_acquire` ⚠️ 通行记载）。此前所有
DCLP 教材的 memory_order 问题一夜清零。退税的代价：析构期线程安全不再管（atexit 语义），
`Config(Config&) = delete` 仍要手写——C++11 没有 `= default` 也能生成拷贝的旧账（五规则）。

### 2.2 观察者：闭包即 Handler 接口
GoF 的 `Observer` 抽象基类 + `attach(this)` 被替换为 `std::function<void(Args...)>` 容器；
lambda 捕获观察者状态，**生命周期问题从"接口不匹配"转为"捕获悬垂"**——token 反注册 +
`weak_ptr`（[04 章](04-智能指针与内存管理.md)）是两道标准解法。实测：lambda 版观察者三档全绿，
累加器 `copy += v` 即闭包携带状态的直观证据。

### 2.3 访问者：variant 把双分派降维成单分派
手工访问者的三座山：前向声明互指、accept 每类重写、新增元素类型改全套。
`std::variant` 把"元素类型集"提到声明里，`std::visit` 以索引表一次性分派；
`overloaded : Ts... { using Ts::operator()...; }` 借**继承构造 + 构造重载**把 lambda 集
拼成重载集——这正是本章把 01/03/06 章特性合奏的现场。实测踩坑：`overloaded(a,b,c)` 圆括号写法
在 gnu++17 编译失败（聚合初始化当时只认花括号），**圆括号聚合初始化是 C++20 放宽**——
三档差异不是书本条文，是本机编译器的红字。

### 2.4 命令与对象池
命令模式 = `std::function` + lambda 捕获参数（撤销栈就是一个 `vector<Cmd>`，线程池的任务队列
是它的并发化——直接引出 [08 章](08-半同步半异步线程池.md)）。对象池的 C++11 化：池交出
`unique_ptr<Obj, 归还删除器>`，借出/归还由所有权转移自动完成；删除器捕获池指针是这套协议的
唯一胶水（实测池三档通过）。

### 2.5 单例的第二代问题与对象池的两派协议
magic statics 只解决"唯一实例的**获取**线程安全"这一代问题；留下的第二代是**销毁顺序**
（用户线程还在跑，单例先被 atexit 拆了）与**可测试性**（全局实例无法替换成假对象）。工业界的
两个折中：`NoDestructor` 式"永不析构单例"（把销毁顺序问题连根拔掉，代价是资源不回收）与
干脆放弃单例改走依赖注入（第 9 章 IoC 的主线动机）。对象池同样有两派协议：**预生成派**
（构造时备齐 N 个，适合并发上界已知）与**按需+归还派**（unique_ptr+删除器，容量随峰值伸缩）——
本书取后者，C++17 `pmr` 的 pool resource 今天把这条做成了标准件（见第六节）。

## 三、权衡与实战提示

- 单例是全局可变状态的门面；本书用它讲语言协议，工程上先问"能不能依赖注入"（[09 章](09-AOP库与IoC容器.md)）。
- magic statics 不保证"你只有一个"：构造 `=delete`、拷贝赋值 `=delete` 仍须手写，语言只保证初始化执行一次。
- 通知循环若允许观察者中途注销：先拷贝回调表再调用（或加锁快照）——"回调里注销自己"是观察者模式
  最高频事故位，与 01 章 range-for 失效是同一族问题。
- `std::function` 观察者的调用税（间接 + 可能堆分配）在热路径上换模板参数或内联 handle 向量。
- 访问者改 `visit` 后，"新增操作零成本、新增类型改全套"的权衡方向**反了**（variant 类型集是封闭的）——
  两类扩展频率要按业务估清再选。

## 四、相邻概念对比

| 对比 | 差异一句话 |
| --- | --- |
| magic statics vs call_once | 语义等价（一次初始化），call_once 还能保护非静态对象 |
| GoF visitor vs std::visit | 双分派/开放元素集 vs 单分派/封闭类型集 |
| function 命令 vs 成员函数指针 | 后者语言层残缺（绑定问题/不可携带状态），前者是标准闭包 |
| 对象池 vs make_unique | 分配器不同，所有权协议相同：unique_ptr + 自定义删除器就是池的接口 |
| token 反注册 vs weak_ptr 观察 | 前者显式"摘挂钩"，后者自动"看不见"；都治悬垂，但生命周期语义差一档（注销时点 vs 存活判据） |
| 池归还删除器 vs 手工 put_back | 所有权转移协议 vs 额外 API 纪律：前者误用编译期即错，后者运行期才炸 |

## 五、实测（🔧 三档：g++ 15.2，gnu++11/17/23，`ch07.cpp`）

```text
gnu++11: OK  singleton same=1 / obs1 saw 3 / obs2 acc=3 / "C++11: visit 需要手写双分派或 boost::variant"
gnu++17: OK  singleton same=1 / obs1 saw 3 / obs2 acc=3 / variant visit: ab(string)
gnu++23: OK  同 17
诊断样本：17 档对 overloaded(...) 圆括号初始化报 no matching function；改花括号后通过——
          聚合初始化圆括号放宽属 C++20（本目录 00 总表第 07 行"实测踩坑"项）。
```

- `singleton same=1` 三档皆绿：同一份"局部静态"源码，C++11 起合法且线程安全；C++03 时代是数据竞争
  ——本机工具链已无 C++03 档，前一句话按标准史记载而非实测，特此标注。
- 11 档打印"visit 需要手写双分派或 boost::variant"：`std::variant` 段以 `#if __cplusplus >= 201703L`
  隔离，本身就是"本书年代无标准访问者"的编译期证据。

## 六、最新演进与工业实践

- **C++17**：`std::variant/visit` 让 2.3 的自研访问者退休（P0088R3《Variant: a type-safe union for C++17》，
  标题经 wg21 文档实测核验）；CTAD（P0091R4 实测）使 `overloaded{...}` 免写模板参数——overloaded
  惯用法今天可以不带推导指南直接花括号用。
- **C++20**：模式书的当代总纲是 Dmitri Nesteruk《Design Patterns in Modern C++20》
  （本仓库 [../C++20设计模式.md](../C++20设计模式.md)，机工中译 2022，ISBN 9787111716228 已在总索引核实）——
  concepts 约束模板方法、ranges 重写迭代器、coroutine 重写异步命令链；本书五个模式在那本书里
  全部换了形态。
- **C++23**：`deducing this`（对象池/CRTP 的接收者语法现代化 ⚠️ 提案号未实测，特性名为准）。
- **工业侧**：单例在 Google/Chromium 代码规范里被登记为"仅限无状态或进程级资源"；abseil
  `base::NoDestructor`（实测 [abseil-cpp](https://github.com/abseil/abseil-cpp) 活跃，20260817.0）
  专门处理"静态析构顺序"——它和 magic statics 一起构成 2026 年单例的完整语境。
- **对象池现状**：内存池主线在分配器层（[../提高C++性能的编程技术/04-单线程内存池.md](../提高C++性能的编程技术/04-单线程内存池.md)），
  C++17 `pmr`（`monotonic_buffer_resource`）+ C++23 `instantiate_pool_resource` 把"池"标准化成
  `std::polymorphic_allocator`——本书模式的池实现今天可整体替换为标准资源适配器。
