## 核心概念速览（中英对照）

- **时长** — duration：`时长 = 数值 × 单位` 编译期表达，`duration_cast` 转换显式截断。
- **时点** — time point：`时钟 + 时长偏移` 的绝对刻度，`now()` 的返回物。
- **三种时钟** — system / steady / high_resolution clock：墙钟可回拨、steady 单调只用于测间隔。
- **数值↔字符串** — `to_string / stoi / stod`：告别 sprintf/atoi 的类型不安全转换（但会抛异常、本地化）。
- **委托构造函数** — delegating constructor：一个构造调另一个构造，替代 `Init()` 公共函数（无重赋值的原子性）。
- **继承构造函数** — inheriting constructor：`using Base::Base;` 免手写转发样板，**但虚不继承语义**。
- **原始字面量** — raw string literal：`R"( ... )"` 零转义，正则/JSON/嵌入脚本友好。
- **final / override**：多态护栏——`override` 把"以为覆盖了其实在重载"变成编译错误；`class final` 关继承与虚优化门。
- **对齐说明符/查询符** — alignas / alignof：布局约束与其编译期查询。
- **最大基本对齐** — `max_align_t`：新类型超此对齐即"过对齐"，C++11 时 `new` 不保证满足。
- **对齐缓冲** — aligned_storage / aligned_union：为 placement new 预备满足对齐的裸字节。
- **非定长操作** — std::align：在缓冲内把指针推进到对齐边界（自己实现对齐分配的零件）。

## 一、动机：把"散件"收进标准库

## 二、机制

### 2.1 chrono：单位进类型，错乘即编译错
`duration<Rep, Ratio>` 让 `milliseconds(50) + seconds(1)` 先统一为公共单位再相加；
`steady_clock` 走 OS 单调计数器（Windows 上是 QueryPerformanceCounter 一系，⚠️ 通行记载），
`system_clock::time_point` 可转 `time_t` 落库（[10 章](10-消息总线与SQLite封装.md) 的 timestamp 列）。
实测本机 50ms sleep 观测 53–68ms：**Windows 时钟粒度与线程调度双重影响**，测间隔要取多次中位数。

### 2.2 构造复用的展开现场
委托构造在**进入目标构造体前**完成被委托构造的全部初始化——成员初始化列表"先跑一遍完整的"，
不是"补洞"。继承构造函数 `using Base::Base` 展开为一组**非虚**转发构造：多态基类构造签名变了，
派生类不会报错而是悄悄失配，这是它和虚函数语义不打交道的坑。

### 2.3 final/override 的编译器红利
`override` 是纯检查器；`final` 则给去虚化提供**证明**——编译器可把 `final` 虚调用直转静态调用
（实测对照见 [../提高C++性能的编程技术/02-虚函数开销与模板继承.md](../提高C++性能的编程技术/02-虚函数开销与模板继承.md) 的 vcall 机制）。
析构标 `final` 还切断"派生类析构也虚"的连锁。

### 2.4 对齐：三个数字与两代规则
`alignof(T)` 类型自带；`alignas(N)` 抬高它；`max_align_t` 是"普通 new 保证达到的天花板"
（实测本机 =16）。关键分代：**C++11/14 里 `new` 过对齐类型是 UB**——分配器只按 `max_align_t`
对齐；C++17 引入带 `align_val_t` 的 sized/aligned new 运算符才算制度化（P0035R4，wg21 实测解析；
libstdc++ 的 `__builtin_aligned_alloc` 落地细节 ⚠️）。实测中还有个 MinGW 现场：gnu++11 档
`std::max_align_t` 名字不存在、只有全局 `::max_align_t`（17 档两者皆有）——标准与实现的
历史缝隙样本。`aligned_storage` 则是 [03 章](03-type_traits与可变参数模板.md) 自研 optional 的基座，
`std::align` 用于对象池里手推对齐（[07 章](07-C++11重思设计模式.md) 对象池）。

## 三、权衡与实战提示

- `stoi/stod` 抛异常 + 本地化小数点；解析外部协议文本用 `from_chars`（无 locale、无异常、可测速）。
- 转换的双代机制：`to_string(double)` 走 `%f` 定点 6 位——🔧 实测 `3.14159` 打成 `3.141590`，
  尾零就是该定点格式；`from_chars` 则是"指针区间入、error_code+消耗位出"的零异常协议，
  浮点版标准化在 C++17 但 libstdc++ 落地晚得多（gcc 11 前后 ⚠️），本书年代实际不可用。
- range-based for 内做 `push_back`/删除元素 = 迭代器失效事故（书 1.4.2 细节与本章工具组合时的真实雷）。
- 伪共享防御要 `alignas(64)` 但别迷信 64：以 `std::hardware_destructive_interference_size`（C++17，
  gcc 支持晚，⚠️）或目标机实测为准。
- 委托构造 + 虚函数是禁区：被委托的"目标构造"先完整跑完，若其中触发虚调用，派生层尚未参与初始化——
  与 2.2 的"半初始化窗口"是同一族问题（构造期虚调用永远只到当前层）。

## 四、相邻概念对比

| 对比 | 差异一句话 |
| --- | --- |
| steady_clock vs system_clock | 测间隔用前者（不回拨）；落库/跨机用后者 |
| 委托构造 vs 公共 Init() | 语言级复用 vs 手工补丁；前者无"半初始化"窗口 |
| override vs 手写同名签名 | 前者编译期对账，后者静默失配 |
| alignas vs malloc(roundup) | 类型层声明 vs 运行期手算，前者编译器全权布局 |
| 原始字面量 vs 转义串 | `R"(…)"` 保留所见即所得；正则/JSON 里转义地狱的直接解药 |
| duration_cast vs 隐式转换 | 收窄必显式（截断），放宽自动（无损失）——单位错误在类型层被拦 |

## 五、实测（🔧 三档：g++ 15.2，gnu++11/17/23，`ch06.cpp`）

```text
gnu++11: OK  slept ms=68 / to_string=3.141590 / stod=2.71828 / conn localhost:1234 t=30
             alignof(CacheLine)=64 / max_align_t(global)=16 / ptr64aligned=1
             ——注意：浮点 from_chars 段未启用（C++17 特性）；std::max_align_t 在本机 11 档不存在，须用全局名
gnu++17: OK  追加 from_chars=2.71828 consumed=7（"2.71828abc" 精确停在 7 字节）
gnu++23: OK  追加 C++20 floor 换算 90h=5400min、std::format "3.14 works"
踩坑实录：alignas(64) 写在函数内匿名 struct 声明上，本机首测 alignof 仍报 4；
          把 alignas 移到 namespace 级类型定义后 alignof=64——教学代码从此按类型写对齐。
```

- 委托构造链 `Connection() : Connection("localhost",1234)` 三档行为一致，输出 `localhost:1234 t=30`。
- `std::format` 只在 23 档通过（11/17 档编译该段即 error）：格式化这条线 2015→2020 的演进被三档夹住。
- `sleep_for(50ms)` 多次实测读数 53–68ms：Windows 计时粒度 + 调度延迟的合成账单——chrono 测间隔
  的正确姿势（取中位数/多次运行）从本章起就应当示范给读者。

## 六、最新演进与工业实践

- **C++14**：chrono 字面量（`42ms`、`1h`——`std::chrono::literals` 系，gcc 从 4.9 起可用）；
  构造函数完全继承的修补迭代。⚠️ 具体小版本支持差异未逐一实测。
- **C++17**：`from_chars/to_chars` 进入 `<charconv>`（整型 + 浮点；本书年代只有 to_string/stod 可用）；
  aligned new（P0035R4 实测解析）；`shared_mutex`（顺带归并发线）。
- **C++20**：chrono 日历与时区（`year_month_day/sys_days/locate_zone`，"时区库"是本章 6.1 的完全体；
  libstdc++ 对 time_zone 数据依赖 OS，支持进度 ⚠️）；`std::format`（实测 23 档可用）；`char8_t`
  与 UTF-8 字面量（P0482R6 实测解析）；`std::assume_aligned`。宽窄字符小节在 2026 年的正确姿势是
  `std::u8string + UTF-8 一路走到底`——参 [../现代C++实战30讲/07-Unicode与多文字世界.md](../现代C++实战30讲/07-Unicode与多文字世界.md)。
- **C++23**：`std::print`（P2093R14 实测解析）、`if constexpr` 化的属性小件……与本章直接相关的是
  `std::start_stop_item`？——否，那是执行器线；本章的 C++23 增量主要是 `to_chars` 补种类 ⚠️。
- **算法小节（7.5）后话**：`iota/all_of/mismatch` 之后，C++20 ranges 算法（`std::ranges::iota_view`）
  把"造序列"从容器物化改成视图惰性——与 [11 章](11-LINQ并行任务与异步网络.md) LINQ→ranges 主线汇合。
- **constexpr 交汇**：本章多数工具（duration 运算、to_chars 的编译期子集）在 C++20/23 已可 constexpr 化，
  与 [../Effective_Modern_C++/08-微调与全书收束.md](../Effective_Modern_C++/08-微调与全书收束.md) 的 constexpr 条款及
  [../现代C++实战30讲/08-模板编译期多态与编译期计算.md](../现代C++实战30讲/08-模板编译期多态与编译期计算.md) 构成同一读群。
