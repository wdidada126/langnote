## 一句话总结
现有内存动态图存储（DGS，如 LLAMA、Aspen、LiveGraph、Teseo、Sortledton）在「读/写/空间/并发」上各有所长却从未被系统比较；本文提出一套统一抽象与测试框架，量化出它们普遍存在的「内存开销大、忽视现代架构访存、细粒度并发控制代价高」三大瓶颈，为下一代实时图存储指明改进方向。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：很多图分析（社交网络、风控、知识图谱）需要**一边读图、一边改图**——例如不停插入边、同时跑查询。这种「动态图」要求存储结构既要快读又要快写，还不能把内存撑爆。本文把这类系统统称为 **DGS（In-Memory Dynamic Graph Storage，内存动态图存储）**。
- **为什么难**：读和写天然冲突——给每个点维护邻接表便于读，但频繁插入边会让邻接表反复搬迁、锁竞争剧烈；反之追求写快又会拖慢读。此外现代 CPU 的缓存/内存层级对访存模式很敏感，设计稍有不慎就慢。
- **几类主流解法（表格）**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 版本化增量（log-structured） | LLAMA | 不改原数据，追加增量版本 | 读需合并版本，空间/合并开销大 |
| 细粒度更新 | Aspen、LiveGraph | 对邻居逐条维护版本与检查 | 高并发下锁/版本代价高 |
| 事务化邻接表 | Teseo、Sortledton | 用事务/并发结构管理邻接表 | 实现复杂，空间放大明显 |
| 静态CSR（对照基线） | CSR | 连续数组存邻接 | 读极快但几乎不可动态写 |

- **本文属于哪一类**：本文**不是提出新存储**，而是「裁判」——提出统一抽象 + 通用测试框架，把上述 DGS 拉到同一条起跑线对比。
- **2-3 个必懂关键名词**：
  - **CSR（Compressed Sparse Row）**：图存储的静态黄金基线，把每个点的邻居连续排成数组，读最快但难改。
  - **空间开销（space overhead）**：为支持动态更新额外付出的内存，常以「相对于 CSR 的倍数」衡量。
  - **并发控制（concurrency control）**：多读多写同时发生时，保证结果正确且高效的机制；细粒度锁在「高度数顶点（热点）」上极易争用。

## 1. 问题背景与动机
- **前人工作简述**：已有多种 DGS（LLAMA、Aspen、LiveGraph、Teseo、Sortledton 等），各自在读写、空间、并发上取舍不同，但彼此差异巨大、缺乏统一比较口径。
- **前人 N 个缺陷/未解决问题（逐条）**：
  1. **缺乏系统研究**：没人用同一抽象把多种 DGS 的「读/写/空间/并发」做公平拆解，设计选择全凭各论文自说自话。
  2. **空间开销被低估**：文中量化发现 Aspen 比 CSR 多用 3.3~10.8x 内存，最优细粒度方法也比 CSR 多 4.1~8.9x，内存放大严重。
  3. **忽视现代架构访存**：现有方法常忽略现代 CPU 的内存访问特性，导致相比连续存储方法性能下降。
  4. **细粒度并发控制代价高**：尤其维护每邻居的版本与检查，带来严重的效率与空间问题，并在高度数顶点上出现显著争用。

## 2. 核心方法
- **最直观类比**：把 DGS 比作「一摞不断被涂改又被人同时翻看的通讯录」；前人各做了一本自己的本子，本文则造了一把「统一的尺子 + 同一个翻本子动作」，让所有本子用同一方式被测量。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：多种现有 DGS 实现 + 统一的设计抽象（把「邻接表如何组织、如何支持读/写/并发」抽象成若干维度）。
  2. **关键操作**：基于该抽象实现**通用测试框架**，在统一实验设置下逐个跑读/写/混合负载，记录空间、延迟、吞吐。
  3. **输出**：量化各技术的性能因子与瓶颈结论（空间倍数、访存影响、并发争用），并指出未来方向。
- **形式化要点**：核心是「DGS 设计抽象」——把读写支持、空间开销、并发控制拆成可独立度量的维度；借此定位性能因子。
- **理论性质/保证**：本文是实证性系统研究（非理论证明），给出的是**测量结论与瓶颈洞察**，而非算法最优性保证。

## 4. 实验结论（概览）
- **对比基线**：CSR（静态基线）+ 现有 DGS（LLAMA、Aspen、LiveGraph、Teseo、Sortledton 等）。
- **数据集/指标**：空间开销（相对 CSR 的倍数）、读/写/混合负载的性能、并发争用表现；🔧 具体数据集与曲线查原论文。
- **结论方向（摘要给出的已核实数字）**：
  - 空间：Aspen 比 CSR 多 **3.3~10.8x**；最优细粒度方法比 CSR 多 **4.1~8.9x**。
  - 现有方法常因忽视现代架构访存而性能下降。
  - 细粒度并发控制（尤其是高度数顶点）存在严重效率与空间问题。

## 7. 2026 视角（🔧）
- 实时图分析（风控、社交、知识图谱增量更新）对动态图存储需求持续走强；如何在不爆内存的前提下兼顾高并发读写，仍是图数据库内核的硬骨头。
- 近年趋势：把「版本化增量」与「连续存储 + 批量重排」结合、针对 NUMA/持久内存优化访存、用无锁结构缓解高度数顶点争用。具体系统矩阵 🔧 查当年综述/基准。

## 8. 新手学习路线
- **10 分钟**：读 arXiv 摘要 + 本文第 0、1 节，理解「DGS」「CSR 空间开销」「细粒度并发」三词。
- **30 分钟**：跑仓库基准，对比 CSR 与各 DGS 在「只读 / 只写 / 混合」下的空间与吞吐差异。
- **进阶**：精读论文的「统一抽象」章节，按维度拆解一个 DGS（如 LLAMA）的设计，思考如何降低其空间放大。
