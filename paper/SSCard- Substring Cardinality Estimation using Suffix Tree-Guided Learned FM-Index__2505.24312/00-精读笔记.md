## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：查询优化器在生成执行计划前，要估计每个算子（尤其是过滤/连接）会返回多少行，这个估计值叫 cardinality（基数）。估计差 → 选错计划 → 慢几十倍。本文专门处理「子串查询」（SQL 的 LIKE 谓词）的基数估计。
- **为什么难**：子串匹配不像等值/范围查询有现成直方图可用；子串组合极多，传统方法要么靠规则（采样/直方图）要么靠机器学习，但两者都缺乏误差上界（error bound），可能给出离谱估计，拖累整个查询计划。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 规则式直方图/采样 | 传统 DBMS 统计信息 | 列上建直方图、随机抽样 | 简单但不擅长子串，长尾误差大 |
| 学习式估计 | 各类 learned cardinality estimator | 训练模型拟合数据分布 | 准，但无误差界，易过拟合、难解释 |
| 字符串索引 + 计数 | FM-Index / suffix tree / suffix array | 直接在下标结构上数出匹配数 | 精确但原始结构太大；需压缩与近似 |

- **本文属于哪一类**：把「FM-Index（紧凑全文本下标）」扩展成可多字符串、用后缀树组织、再用样条插值近似，属于「字符串索引 + 学习型近似 + 误差界」的混合路线。
- **2-3 个必懂关键名词**：
  - **FM-Index**：一种基于 Burrows-Wheeler Transform (BWT) 的紧凑全文本下标，能在很小空间内支持子串计数/定位。
  - **后缀树 (suffix tree) / 后缀数组**：把字符串所有后缀组织起来的结构，天然适合子串查询。
  - **q-error**：估计值/真实值 与 真实值/估计值 中的较大者；越接近 1 越准，是基数估计的常用误差指标。

## 1. 问题背景与动机
- **前人工作简述**：基数估计有规则式（直方图、采样）和机器学习式两大类，被大量研究用于各种查询；它们的估计能力已被充分探讨。
- **前人缺陷/未解决问题（逐条）**：
  1. **缺误差界**：规则式和 ML 式方法都没有严格的 error bound，估计可能偏差极大 → 优化器选到次优计划。
  2. **子串场景被忽视**：LIKE 这类子串谓词在真实负载里常见，但少有方法专门、高效且带保证地处理它。
  3. **空间 vs 精度难两全**：想要精确计数往往要存很大的索引；想要小索引又容易失准。
  4. **长短模式差异大**：短模式匹配数量多、分布特殊，通用方法处理不好。
  5. **增量更新缺失**：数据变化后重建代价高，少有考虑低成本增量维护。

## 2. 核心方法
- **最直观类比**：把整张表的文本列想成一本超长书；FM-Index 像这本书的「紧凑目录」，能回答「某个词出现了几次」。SSCard 进一步把目录按「后缀树」重新编排，让查短词时又快又省；再用「样条插值」这条平滑曲线去近似那些不值得精确存的部分，同时给误差画一条红线（误差界）。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：若干字符串列（可多列/多表，论文扩展 FM-Index 支持「多字符串自然支持」）。
  2. **关键操作一**：用「剪枝后的后缀树 (pruned suffix tree)」来组织 FM-Index。后缀树结构让短模式的基数可精确估计；通过 pushup 操作把信息上推压缩，对大字母表且字符分布倾斜的数据压缩率很高。
  3. **关键操作二**：引入样条插值 (spline interpolation) 并附误差界，在「空间占用」与「估计精度」之间做可调权衡。
  4. **关键操作三**：双向估计算法 (bidirectional estimation) + 增量更新策略 (incremental update)，提升估计质量并支持数据变化时的低成本维护。
  5. **输出**：给定子串模式，输出其匹配行数的估计值（带误差界）。
- **形式化要点**：核心是把 FM-Index 从「单字符串」扩展到「多字符串」；用后缀树做结构组织与压缩；用样条 + 误差界控制近似。超参数包括插值粒度/误差界阈值（🔧 具体参数名请查正文）。
- **理论性质/保证**：样条插值带 error bound（这是相对前人「无界」的关键改进）；其余多为工程/经验性质。🔧 误差界的具体形式与证明待精读补充。
