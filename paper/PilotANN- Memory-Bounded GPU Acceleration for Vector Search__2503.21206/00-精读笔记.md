## 一句话总结
纯 GPU 跑向量检索受显存大小限制、纯 CPU 图索引又不够快；PilotANN 把「图遍历」拆成三段，用 GPU 跑压缩向量的粗筛、用 CPU 大内存跑完整向量的精排，显存不够也能搜，还能快 3.9–5.4 倍。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：在亿级高维向量里毫秒级找最近邻（ANNS）。GPU 算得快但显存小；CPU 内存大但慢；怎么既要快、又要能装下超大数据集？
- **为什么难**：图索引（如 HNSW）效果好但要存完整向量，GPU 显存放不下十亿级数据；全放 GPU 会被「显存墙」卡死。
- **几类主流解法**：

| 路线 | 代表 | 直觉 |
|------|------|------|
| 纯 CPU 图索引 | HNSW、NSG | 准但慢，吃 CPU |
| 纯 GPU | Faiss GPU、CAGRA | 快但显存受限 |
| 量化压缩 | PQ、RaBitQ | 省内存但损精度 |
| 混合 CPU+GPU | **PilotANN** | GPU 粗筛 + CPU 精排 |

- **本文属哪类**：混合（hybrid）路线——既用 GPU 并行、又借 CPU 大内存突破显存限制。
- **2-3 个必懂关键名词（直觉解释）**：
  - **top-k 图遍历**：从某点出发，沿「邻居里更近的点」一路贪心走，收集最近的 k 个候选。
  - **SVD 降维向量**：把高维向量压成低维近似，GPU 上算距离更快，但只是粗筛。
  - **entry selection（入口选择）**：选好查询的「起跑点」，起跑点好，GPU 利用率才高。

## 1. 问题背景与动机
- 前人工作简述：ANNS 已是深度学习（尤其生成式模型检索）的基础设施；CPU 图索引（HNSW 等）高效但算力不足，GPU 方案快但受显存约束。
- 前人缺陷/未解决问题（逐条）：
  1. **CPU 图索引算力不够**：即便最优的图方法，也难满足越来越大的向量维度与数据量。
  2. **GPU 显存是硬墙**：纯 GPU 方案装不下超大数据集（显存 << 数据规模）。
  3. **缺少显存有界的混合方案**：如何优雅地同时用上 CPU 的大 RAM 与 GPU 的并行，是开放问题。

## 2. 核心方法
- **最直观类比**：像「GPU 是反应超快的实习员，CPU 是记性超好的老员工」——实习员先用缩略图快速翻一遍挑出可疑对象，老员工再用完整档案做最终确认。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **三段式分解 top-k 图遍历**：
     - 阶段一：GPU 上用 **SVD 降维后的压缩向量**做子图遍历（粗筛，快且省显存）。
     - 阶段二：CPU 用**完整向量**做 refinement（精排）。
     - 阶段三：CPU 做 precise search（精确搜索定最终结果）。
  2. **fast entry selection**：改进搜索起点选择，最大化 GPU 利用率。
  - 输出：top-k 近邻，且数据集可大到 GPU 显存的 12 倍。
- **形式化要点**：核心是「把遍历的计算按精度分层，GPU 跑低精度高密度计算、CPU 跑高精度低密度计算」；超参包括 SVD 维度、各阶段阈值（🔧 见原论文）。
- **理论性质/保证**：无严格理论界，以系统设计与实测为主。

## 4. 实验结论（概览）
- 对比基线：CPU 图索引（如 HNSW 系）、GPU 方案（🔧 具体基线查原论文）。

- 结论方向（摘要给出的已核实数字）：
