## 一句话总结

给"AI 能不能从乱糟糟的数据湖里自己拼出一条分析流水线、最后得出洞察"造了一场 standardized 考试：104 道人工整理的真实难题。结论是——AI 能写得出像样的解题思路，但真正能把端到端流水线跑通的很少。

## 0. 给新手的阅读前置（背景知识地图）

- **子方向解决什么大问题**：企业数据湖里堆着 CSV、日志、文档、图片等不干净、半结构化/非结构化的数据。回答一个业务问题（"哪类用户流失最快？"）需要抽取、清洗、集成、分析、建模一整条流水线，还要领域知识。能不能让 AI 智能体端到端地自动完成？首先得有一把可靠的尺子来量。
- **为什么难**：任务之间有依赖（前一步的输出决定后一步怎么写）；要跨多个数据源找对文件；答案是开放式的分析结论而非单点查询；错误会沿流水线放大。
- **几类主流解法/评测形态**：

| 形态 | 直觉 | 例子 |
|------|------|------|
| 单点任务基准 | 只测一个环节（清洗/集成/问答） | 各类 data cleaning / entity matching benchmark |
| 文档抽取系统 | LLM 把文档变成可查询表 | EVAPORATE（本仓库同方向） |
| 端到端智能体流水线 | 一个/多个 agent 规划并执行整条链 | 本文的 DS-Guru 参考框架 |
| **端到端基准** | 量"整套流水线"做得好不好 | **本文（KramaBench）** |

- **本文属哪类**：端到端基准（benchmark），既给任务也给综合评估框架，分开考核"流水线设计"与"单个数据任务实现"。
- **关键名词直觉解释**：
  - *data-to-insight pipeline*：从原始数据到分析结论的一串数据处理步骤，可看作"多步的数据科学工作流"。
  - *数据湖（data lake）*：什么格式都往里扔的原始数据仓库，区别于先建模再入库的数据仓库。
  - *DS-Guru*：作者实现的单智能体参考解法（相当于考试的标准答卷机器），用来给 8 个 LLM 统一出题环境。

## 1. 问题背景与动机

- 前人工作：数据科学智能体、LLM 数据系统（如 EVAPORATE 做 LLM 文档抽取视图、CHORUS 做多模态数据探索）各管一段；AI benchmark 多聚焦代码生成或单轮问答。
- 前人的缺陷（论文动机）：
  1. 已有基准几乎都从"干净数据"出发，没有测"从不干净、多源、半/非结构化数据湖出发"的全链路能力；
  2. 现有评测不区分"会设计流水线"和"会实现每个任务"两种能力，失败原因无法定位；
  3. 真实洞察需要领域知识与项目特定判断，通用基准覆盖不了；
  4. AI 模型在推理与代码生成上很强，但其端到端编排复杂流水线的真实水平缺少量化证据。

## 2. 核心方法

- **最直观类比**：一场"数据科学综合大考"。出题人（作者团队）从 6 个领域的真实数据湖里精心整理出 104 道题，每题附标准解题步骤（krama 一词即指这种步骤序列）；考生（AI 系统）要先写出解题步骤设计，再逐步实现，阅卷系统分别给"步骤设计"和"每步实现"打分。
- **具体做法（输入→关键操作→输出）**：
  1. 基准构成：104 个人工整理并解答的挑战，覆盖 1700 个文件、24 个数据源、6 个领域（真实数据湖设置）；
  2. 评估框架：对流水线设计（规划质量）与单个数据任务实现（每步正确性）分别评估；
  3. 参考框架 DS-Guru：单智能体，负责规划流水线并调度各数据任务的实现；
  4. 实验：8 个 LLM 驱动 DS-Guru，并测试开源/闭源的单智能体与多智能体系统。
- **形式化要点**：每个挑战定义为〈数据源集合、问题、参考 krama（步骤图）、参考答案〉；评估按步骤图逐节点对齐（🔧 评分细节查原文评估节）。
- **理论性质**：无理论保证；核心贡献是基准设计与大规模实证。

## 3. 变体 / 工程版

- 提供"完整数据湖"与"检索完美（oracle）"两种难度设置，用来分离"找数据"与"做任务"两类失败。

## 4. 实验结论（概览）

- 对比系统：8 个 LLM（开源 + 闭源）驱动的 DS-Guru，以及多个单/多智能体系统（🔧 具体系统名单查原文）。
- 数据集：本基准自身（104 挑战 / 1700 文件 / 24 数据源 / 6 领域）。
- 指标：端到端准确率、任务识别率、单任务完整实现率。
- 已核实的关键数字（来自 arXiv 摘要）：
  - 完整数据湖设置下，最佳系统端到端准确率仅 **55%**；
  - 即使检索完美（oracle），上限也只有 **62%**；
  - 领先 LLM 最多识别 **42%** 的重要数据任务，但只能完整实现 **20%** 的单个数据任务。
- 结论方向：当前智能体能处理孤立的数据科学任务、能写出"看似合理"的流水线草稿，但端到端可运行性差，瓶颈主要在任务实现而非设计。

## 7. 2026 视角（🔧）

- "数据智能体（data agent）"是 2025-2026 年数据库社区最热方向之一，各大模型厂商的深度研究/数据分析类产品本质上都在解 data-to-insight 问题；KramaBench 这类端到端基准成为衡量"AI 数据工程师"水平的参照系。
- 摘要给出的差距（识别 42% / 实现 20%）说明：单纯堆更大的模型不够，需要更强的工具调用、数据检索与长流程编排，这正是后续智能体框架与语义算子（semantic operators）方向的用武之地。

## 8. 新手学习路线

- **10 分钟**：读摘要记住 4 个数字（104 题 / 55% / 62% / 20%）与"设计 vs 实现"双轨评估思想。
