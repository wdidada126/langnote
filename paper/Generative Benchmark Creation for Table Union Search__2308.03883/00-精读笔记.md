## 一句话总结
手工标注的表联合搜索基准既贵又不可扩展，本文用生成式 AI 模型「按需造表」，构建了一个包含「可联合 / 不可联合但相关」表对的新基准，结果发现现有所有方法在新基准上都大幅掉分（最优方法 MAP 仅约 60%），说明旧基准偏简单、新基准能更细致地暴露方法缺陷。

## 0. 给新手的阅读前置（背景知识地图）

**大问题**：数据湖（data lake）里堆着成千上万张表，用户手里有一张表，想知道湖里哪些表能和它「拼接」（union）起来变成更大的表——这就是 Table Union Search（表联合搜索）。它是数据发现（data discovery）的核心任务之一，直接决定数据湖能不能被有效利用。

**为什么难**：两张表「能不能联合」不是语法问题，而是语义问题——列名可以完全不同（`price` vs `cost`）、取值可以部分重叠，甚至同一实体在不同表里有不同写法。传统合成数据生成器（如 TPC 套件）能精确控制数据规模和分布，但**无法生成「语义」**，所以这类任务只能靠专家手工挑选、标注真实数据来做基准。

**主流解法分类**：
| 类别 | 思路 | 代表 |
|------|------|------|
| 基于 Schema/元数据 | 比较列的语义类型、模式相似度 | 早期 union search 系统 |
| 基于数据内容/关系 | 看取值集合的包含关系、值分布 | SANTOS（本仓库有笔记） |
| 基于 LLM | 直接让大模型判断表对 unionability | 本文提出的 LLM 方法 |
| 基准构建 | 手工策展 vs 本文的生成式方法 | Santomartino Baseline、alt-gen（本文） |

**本文属哪类**：基准构建——不提出新的搜索算法作为主角，而是解决「怎么公正地考所有人」的问题。

**关键名词直觉解释**：
- **Unionable（可联合）**：两张表存在（不一定是全部列的）对应关系，使得 union 之后结果在语义上连贯。
- **Non-unionable but related（不可联合但相关）**：两张表共享话题甚至部分列语义，但整体上 union 不连贯——这类「迷惑项」是测试方法判别力的关键，手工基准里很难成对获得。
- **MAP（Mean Average Precision）**：信息检索指标，衡量「正确答案在排序结果里是不是靠前」，越高越好。

## 1. 问题背景与动机
- **前人工作简述**：数据管理长期依赖 TPC 等合成基准推动系统进步；但语义类任务（union search、schema matching、data discovery）的基准只能手工构建。表联合搜索方面，SANTOS 等系统推动了任务定义，相关基准有 Santomartino Baseline 等手工数据集。
- **前人缺陷（逐条）**：
  1. 手工策展与标注**不稳健、不可扩展**：每张表都要人工判断 unionability，成本高。
  2. **基准本身的稳健性存疑**：没有人知道这些手工基准覆盖了多广的「难度谱」。
  3. **无法系统研究假阳性/假阴性**：手工基准里「不可联合但相关」的负例太少，导致方法做错了也测不出来。
  4. 合成数据生成路线对语义任务**天然失效**——语义没法用参数分布定义。

## 2. 核心方法
- **最直观类比**：以前是「从野外抓真鸟来考识别系统」，本文改成「用 AI 按配方造鸟」——可以精确控制哪里像、哪里不像，想造多少迷惑项就造多少。
- **具体做法（输入→关键操作→输出）**：
  - 输入：真实种子数据 + 期望的表属性（如「这两张表应有 3 列语义对齐、值分布部分重叠」等控制参数）。
  - 关键操作：用生成式 AI 模型（文本生成模型）按指定属性条件生成结构化表格；通过控制生成指令/条件制造「可联合」对与「相关但不可联合」对。
  - 输出：一个新基准，包含成对的 unionable / non-unionable-but-related 表。
- **配套贡献**：提出并评测了一个基于 LLM 的新表搜索方法，在全部基准上与既有方法同台比较。
- **理论性质**：本文为实证/基准类工作，无算法理论保证；核心「保证」是生成的表属性可控，从而可以构造已知真值的测试用例。

## 4. 实验结论（概览）
- **对比对象**：近年既有的表联合搜索方法（含 SANTOS 一系）+ 本文新提出的 LLM 表搜索方法。
- **数据集**：既有手工基准 + 本文 alt-gen 新基准。
- **指标**：MAP（平均精度均值）。
- **结论方向**：
  1. 新基准对所有方法都更难：最优方法 MAP 约 60%，比其在手工基准上的成绩低超过 30 个百分点。
  2. 新基准首次支持对假阳性/假阴性的系统分析——手工基准做不到。
  3. LLM 方法在新基准上同样面临挑战，说明这不是「老方法不行」的问题，而是任务本身比旧基准呈现的更难。
- 🔧 各方法精确 MAP 数值请查原论文表后补。

## 7. 2026 视角（🔧）
- LLM 成为数据发现/表搜索的事实标准工具：2025 年后大量工作用 LLM 做 unionability、schema matching 判断，本文的 LLM 表搜索方法是较早的系统评测之一。
- 「生成式造基准」思路已被更广泛采用：合成 benchmark、数据自举（self-instruct 风格造表）在 data lake 数据发现中常见。
- 工业上数据湖目录（如各类 lakehouse catalog）开始集成语义搜索能力，表联合搜索从学术任务走向产品功能。
