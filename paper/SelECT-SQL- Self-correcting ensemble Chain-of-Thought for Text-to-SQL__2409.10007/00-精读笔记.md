## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：用大模型把自然语言问题转成 SQL；关键瓶颈是模型对 schema/问句/SQL 子句的细腻理解容易出错。
- **为什么难**：开箱即用的 LLM 很强但离专家级仍有明显差距，尤其需要同时理解库结构、语义、SQL 语法时易错。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 微调小模型 | RESDSQL、RAT-SQL | 训专用 encoder | 准但贵、迁移弱 |
| 上下文学习 + CoT | ACT-SQL、DIN-SQL | 用思维链分步推理 | 灵活、吃提示质量 |
| 自纠错 | SELF-DEBUG、本文 | 生成后自查修正 | 提升明显、成本高 |
| 集成 | 多候选投票 | 多路径取优 | 稳但更慢更贵 |

- **本文属哪类**：上下文学习路线，且把 CoT、自纠错、集成三者**算法化组合**而非简单堆砌。
- **关键名词直觉**：
  - **Chain-of-Thought (CoT)**：让模型先写出「推理步骤」再给答案，减少一步到位的跳跃错误。
  - **self-correction（自纠错）**：模型先生成 SQL，再基于执行反馈/自我检查修正。
  - **ensemble（集成）**：多次/多策略生成若干候选，按一致性或校验选最优。

## 1. 问题背景与动机
- 前人工作简述：LLM 开箱即用（off-the-shelf）在 Text-to-SQL 表现出色，但离专家级仍有显著差距；错误多发生在需要细腻理解 schema、问句与 SQL 子句时。
- 前人缺陷/未解决问题（逐条）：
  1. **单遍生成易错**：一次生成 SQL 难以覆盖复杂语义与 schema 约束。
  2. **已有 CoT/纠错零散**：前人多单独用 CoT 或单独纠错，缺少把三者稳定组合的框架。
  3. **弱模型天花板**：GPT-3.5 类较弱模型如何逼近甚至超过 GPT-4 结果是开放问题。

## 2. 核心方法
- **最直观类比**：像学生写 SQL——先打草稿（CoT），再自己检查改错（self-correction），最后把几份作业交差让老师挑最好的（ensemble）。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：自然语言问题 + 数据库 schema + 少量示例（in-context）。
  2. **关键操作**：算法化地组合 (a) CoT 分步推理、(b) 自我纠错（对生成 SQL 修正）、(c) 集成多候选；以 GPT-3.5-Turbo 为基模型。
  3. **输出**：最终 SQL（取集成后的最优候选）。
- **形式化要点**：贡献在于「如何把三种技术组合成稳定 pipeline」，而非提出新模型；具体组合顺序/投票规则以原论文为准 🔧。
- **理论性质/保证**：无形式化保证；以实证 SOTA 为主。
