## 一句话总结
它把「两条 SQL 有多语义相似」建模成一张隐式图上的最短路径问题：每条查询是一个节点，节点之间的「编辑步」按语义差异加权，求两查询间最低代价的编辑序列，就得到可量化的语义距离——比纯语法比对更接近人工阅卷。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：在教学/日志分析里，经常要判断「这两条 SQL 是不是在做同一件事」。传统做法要么只比语法字符串，要么只判「是否完全等价」，都不足以给「接近但不等价的答案」打分。
- **为什么难**：语义相同可以有无数种写法（别名、子查询展开、join 顺序）；等价判定是困难的，而「近似相似」更需要连续的度量。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 语法相似 | 编辑距离/树编辑 | 比 AST 文本差异 | 快但忽略语义 |
| 等价判定 | 定理证明 | 证明结果集相等 | 只能二值，无「接近度」 |
| 图最短路径（本文） | sql-query-distance | 编辑步加权为语义距离 | 连续可解释，代价较高 |

- **本文属哪类**：第三类，用图上的最短路径给出「语义距离」这一连续量。
- **2-3 个必懂关键名词**：
  - **语义距离（semantic distance）**：与相似度相反，数值越大越不相似；本文用它量化「两条查询差多远」。
  - **编辑（edit）**：把一条查询变成另一条的最小语义操作单元，带权重。
  - **最短路径**：在隐式图上找两节点间总权重最小的编辑序列，即最省力的「改写路线」。

## 1. 问题背景与动机
- 前人工作简述：已有 SQL 相似度方法多依赖语法比较，或仅能判断语义等价。
- 前人缺陷/未解决问题（逐条）：
  1. **只看语法**：同一语义的不同写法被判为「很不相似」。
  2. **只能等价判定**：对「部分正确/接近正确」的回答无法给出连续分数。
  3. **缺乏可解释性**：教学场景需要让学生看懂「差在哪」，旧方法难提供。

## 2. 核心方法
- **最直观类比**：把每条 SQL 想象成地图上的一个城市，城市间修「改写公路」，公路越长代表改写语义代价越大；问「A 城到 B 城怎么走最省力」，那条最省力路线的总长就是语义距离。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：两条待比较的 SQL 查询。
  2. **建隐式图**：每条查询是节点；节点之间的转移称为 edits，按语义不相似度加权。
  3. **求最短路径**：用最短路径算法找出两查询间代价最低的编辑序列。
  4. **输出**：该序列总代价 = 量化的语义距离。
- **形式化要点**：核心是把「语义差异」定义为图上带权编辑序列的最优代价；权重设计决定度量质量（具体权重函数 🔧 见论文/代码）。
- **理论性质/保证**：给出一个可量化的距离度量（满足距离基本直觉）；是否为严格度量（三角不等式等）🔧 以原文为准。
