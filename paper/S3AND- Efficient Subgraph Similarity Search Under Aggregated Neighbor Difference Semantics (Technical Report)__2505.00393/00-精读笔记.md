## 一句话总结
在「大数据图里找和查询图相似的所有子图」这一经典难题上，S3AND 提出一种新的相似度语义（既看关键词、又看结构邻居差异），并配套两种剪枝 + 一套索引，让真实图和合成图上的搜索又快又准。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：给定一个查询图 q 和一张巨大数据图 G，找出 G 中所有与 q「相似」的子图。应用广：社交网络（找相似社群结构）、生物信息（找相似分子/蛋白质网络）、知识图谱发现。
- 为什么难：子图同构（判断两个图是否完全一样）本身已是 NP-hard；「相似」比「完全一样」更松，但候选爆炸更严重，必须靠剪枝与索引压缩搜索空间。
- 几类主流解法：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 图同构/编辑距离 | 经典 VF2、GED | 严格匹配或最小编辑代价 | 精确但极慢 |
| 基于特征/嵌入 | 图神经网络嵌入 | 把图映射成向量再检索 | 快但语义易丢 |
| 基于邻居/局部结构 | Nass 等 | 用邻居结构度量相似 | 平衡速度与精度 |

- 本文属哪类：在「邻居结构 + 关键词」双语义下做相似搜索，强调剪枝与索引。
- 2-3 个必懂关键名词：
  - Subgraph Similarity Search（子图相似搜索）：在数据图中检索与查询图相似（非必须完全同构）的子图。
  - Graph Edit Distance（图编辑距离）：通过增删改边/点把一图变另一图的最小代价，传统相似度量。
  - Pruning（剪枝）：提前丢掉不可能是答案的候选，缩小搜索空间。

## 1. 问题背景与动机
- 前人工作简述：以往子图相似搜索多用图同构、图编辑距离等度量。
- 前人缺陷/未解决问题：
  1. 传统度量要么太严（同构）要么计算太贵（编辑距离），难以同时兼顾关键词语义与结构语义。
  2. 缺少一种把「节点关键词」与「邻居结构差异」统一起来度量的新语义。
  3. 大规模图上缺乏高效剪枝与索引来支撑这种新度量。

## 2. 核心方法
- 最直观类比：找「长得像」的小团体——不仅要成员名字（关键词）对得上，还要各自的朋友圈（邻居结构）也差不多；先按名字筛、再按朋友圈差异打分。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：查询图 q（带关键词）、数据图 G。
  2. 关键操作：
     - 提出新语义 S³AND（聚合邻居差异语义下的子图相似搜索）：同时考虑关键词与图结构（在全新的关键词/结构匹配语义下）。
     - 设计两种剪枝：keyword set 剪枝 与 aggregated neighbor difference lower bound pruning（聚合邻居差异下界剪枝），排除候选顶点/子图。
     - 构建一套索引机制加速提出的查询应答算法。
  3. 输出：G 中与 q 相似（按 S³AND 语义）的子图集合。
- 形式化要点：相似度由「关键词匹配 + 聚合邻居差异下界」联合界定；下界用于安全剪枝（不会误杀真答案）。具体公式与超参数见原论文 🔧。
- 理论性质/保证：剪枝基于「下界 ≤ 真实距离」的单调性，保证不漏检（🔧 严格证明见原文）。
