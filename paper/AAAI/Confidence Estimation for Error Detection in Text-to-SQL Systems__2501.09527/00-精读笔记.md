## 一句话总结

Text-to-SQL 模型错了还不自知怎么办？给系统装一个「心里有数」的模块：用基于熵的置信度估计 + 选择性分类器判断「这个 SQL 我敢不敢交给用户」，并比较 T5、GPT-4、Llama 3 谁的自信最有参考价值。

## 0. 给新手的阅读前置（背景知识地图）

- **子方向解决什么大问题**：LLM 生成的 SQL 大多数时候对，但在生产环境中「错了还信誓旦旦」比「承认不会」危害更大。错误检测要让系统在给出 SQL 的同时给出可信度，进而决定是否拒绝回答/请求人工确认。
- **为什么难**：LLM 的输出概率并不等于正确概率（校准差）；生成 SQL 的错误来源多样（问题本身无关、SQL 语法错、语义理解错），置信信号对不同错误类型的敏感度不同；太保守会拒答太多（覆盖度低），太激进则风险高——覆盖-风险（coverage-risk）权衡。
- **几类主流解法**：

| 路线 | 思路 | 特点 |
|------|------|------|
| 直接置信度 | 用 token 概率/自洽性（self-consistency）估计 | 简单，但 LLM 校准差 |
| 选择性分类（selective classifier） | 学一个外部「敢/不敢」分类器，配合熵等不确定性信号 | 本文路线 |
| 执行校验 | 跑 SQL 看是否报错/自洽 | 只能抓硬错，抓不住语义错 |

- **本文属哪类**：选择性分类器 + 基于熵的置信度估计，并系统比较三种模型范式的校准性。
- **关键名词直觉**：
  - *校准（calibration）*：模型说「80% 有把握」时，是否真的约 80% 的比例是对的。
  - *熵（entropy）*：输出的不确定性度量——分布越「纠结」熵越高，越可能出错。
  - *覆盖-风险权衡*：敢答的题占比（coverage）与敢答部分中的出错率（risk）之间的跷跷板。

## 1. 问题背景与动机

- 前人工作：LLM Text-to-SQL（GPT-4、T5 系、Llama 系）准确率已高但远非完美；选择性分类与置信度估计在分类任务上成熟，但在 Text-to-SQL 生成场景的系统研究少。
- 前人的缺陷（逐条，由摘要推出）：
  1. LLM 的泛化能力之外，缺乏对其预测「可信度」的度量，用户无从判断何时该信；
  2. 模型自带的置信信号校准不足，不能直接当错误检测器用；
  3. 不同架构（encoder-decoder vs decoder-only vs ICL）谁更「自知之明」缺乏横向比较；
  4. 不同错误类型（无关问题 vs 错误 SQL 生成）如何被置信信号区分，未被揭示。
- 本文动机：把选择性分类器引入 Text-to-SQL，量化覆盖-风险权衡，并做跨架构校准比较。

## 2. 核心方法

- **最直观类比**：考试时除了答题，还要给每道题标注「把握度」。老师只批改你标「有把握」的题——标注越准（把握度真实反映对错），你的总分越好看。本文就是训练这个「标注把握度」的能力。
- **具体做法（输入→关键操作→输出）**：
  1. 输入：自然语言问题 + schema + 模型生成的 SQL；
  2. 关键操作：(a) 计算输出的熵作为不确定性信号（🔧 熵的粒度——token 级/序列级——查原文）；(b) 训练一个外置的选择性分类器，融合熵等特征，输出「该置信/该弃答」决策；(c) 先测各模型自带置信的校准度，再用校准技术（calibration techniques）改善；
  3. 输出：每条预测的置信分与弃答决策，绘制覆盖-风险曲线。
- **形式化要点**：选择性预测框架下最小化 risk 约束下最大化 coverage（🔧 精确目标函数查原文）。
- **理论性质**：实证为主；核心结论（T5 校准优于 GPT-4 ICL 与 Llama 3）来自实验。

## 4. 实验结论（概览）

- 对比对象：三种范式的 Text-to-SQL 模型——encoder-decoder 的 T5、in-context learning 的 GPT-4、decoder-only 的 Llama 3（摘要明确）。
- 数据集：🔧 具体基准（疑为 Spider 系，查原文后补）。
- 指标：覆盖-风险曲线、错误检测表现、校准度指标（如 ECE 🔧 查原文确认）。
- 结论方向（摘要核实）：
  1. T5 比 GPT-4（ICL）和 Llama 3 校准更好，因此外置熵基选择性分类器在 T5 上表现更好；
  2. 高置信的选择性分类器更擅长发现「问题本身不相关」类错误，而不是「SQL 生成错误」类——置信信号对错误类型有偏。

## 7. 2026 视角（🔧）

- Text-to-SQL/Agent 产品的落地瓶颈已从「准确率」转向「可靠性」：置信度估计、弃答机制、执行反馈校验成为生产 pipeline 标配；LLM 语义熵、self-consistency、verifier 模型等方法快速演进。本文「不同架构校准差异 + 置信信号对错误类型的偏置」这两个观察，对设计混合校验层（先置信过滤再执行验证）有直接指导意义。
