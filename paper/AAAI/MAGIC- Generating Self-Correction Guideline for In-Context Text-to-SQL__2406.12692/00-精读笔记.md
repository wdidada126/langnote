## 一句话总结

让 LLM 修 SQL 的「修错指南」别再靠专家手写了：用 manager、correction、feedback 三个智能体盯着一个 Text-to-SQL 方法在训练集上的失败案例，自动迭代写出一套针对性纠错指南——实验表明这套自动指南比人类专家手写的还好用。

## 0. 给新手的阅读前置（背景知识地图）

这个子方向解决什么大问题？
LLM 生成 SQL 后免不了出错：选错列、漏 join、条件写反。「自我修正（self-correction）」就是让模型回头看自己的 SQL、改到对为止。但「怎么改」不能凭空改——需要一份自纠正指南（guideline）：比如「遇到 GROUP BY 结果异常，先检查是否漏了 HAVING」。以往这份指南是领域专家手写的，本文回答的问题是：指南能不能自动生成？

为什么难？
1. 人工指南贵且盲：写指南耗时耗力，而且人无法穷举 LLM 会犯的所有错误模式；
2. 盲改有风险：没有针对性指南的自我修正，容易「改对变改错」（原对被改坏），文献中此类现象屡见 🔧；
3. 错误模式因模型而异：GPT-4 和小模型犯的错不一样，指南必须针对具体 LLM 的失败分布定制。

主流解法分类：

| 路线 | 思路 | 代表 |
|------|------|------|
| 人工指南修正 | 专家手写纠错规则注入 prompt | DIN-SQL 的 self-correction 模块 |
| 执行反馈修正 | 跑 SQL、拿报错回炉重写 | 各类执行反馈方法 |
| 编辑链修正 | 把修正建模为多轮编辑序列 | CoE-SQL |
| 自动生成指南 | 用 LLM 自动归纳错误、产出指南 | 本文 MAGIC |
| 强化学习修正 | 用 RL 训练修正能力 | CSC-SQL |

本文属哪类：第四类——把「写指南」这个上游环节自动化，属于 meta 层面的贡献：不是让 LLM 修得更好，而是让「教 LLM 怎么修」的东西更好。

关键名词直觉解释：
- 自纠正指南（self-correction guideline）：一份给修正环节看的「错题本 + 修法手册」，在修正 prompt 中作为指令注入。类比：编程规范/Code Review Checklist——不改代码本身，但让每个改代码的人少犯错。
- In-Context Text-to-SQL：不微调模型、纯靠上下文提示做 Text-to-SQL 的一类方法（ICL 路线）。
- 训练集失败案例：在一个有标准答案的数据集上跑基线方法，把「生成错的（问题，SQL，正确答案）」三元组攒起来——这是智能体们用来「归纳错误模式」的原材料。

## 1. 问题背景与动机

前人工作简述：
- DIN-SQL 等把自我修正作为流水线一环，但其修正指令来自人工模板；
- 执行反馈类方法依赖数据库报错，但语义性错误（能跑但结果错）报错抓不到；
- 各类修正研究表明「有指导的修正 > 盲改」，指导从哪来是空白。

前人缺陷 / 未解决问题（逐条，均为摘要明示）：
1. 人工指南制作费力：靠人类专家手写，成本高、难扩展。
2. 人的盲区：人工指南受限于「人类识别 LLM 全部潜在错误模式的能力」——LLM 的错误分布与人的直觉不重合，人会漏。
3. 缺自动化闭环：没有一种「从失败案例自动归纳指南、再迭代精炼」的系统化方法。

## 2. 核心方法

最直观类比：三个「教练」带一个「运动员」。教练组把运动员过往比赛录像（训练集失败案例）逐条复盘：correction 教练起草纠错手册，manager 教练统筹分派与流程，feedback 教练检验手册是否真能减少失误，反复迭代直到手册稳定。运动员（基线 Text-to-SQL 方法）拿着最终手册上场，失误率下降。

具体做法（输入 → 关键操作 → 输出）：
- 输入：某个 LLM 基线方法在训练集上的失败案例集合。
- 关键操作（三智能体协作，摘要明示分工）：
  1. Manager agent：统筹迭代过程，组织失败案例的分派与指南的更新流程 🔧（具体调度细节以论文为准）；
  2. Correction agent：针对失败案例生成/修订自我纠正指南——「这类错该怎么改」；
  3. Feedback agent：评估指南在失败案例上的修正效果，反馈问题驱动下一轮精炼。
- 迭代精炼：模拟人类「复盘-总结-再验证」的循环，但全程无人工介入。
- 输出：一套针对该 LLM 错误模式定制的自纠正指南，随后注入 In-Context Text-to-SQL 的修正环节。
- 附加产出：指南天然是一种「错误分类学」，使修正过程可解释——能看清 LLM 自我修正成败的原因（摘要明示）。

形式化要点/理论性质：无理论定理；属实证型多智能体方法 🔧（智能体 prompt 与迭代终止条件查论文）。

## 7. 2026 视角（🔧）

- 「自动生成纠错资产」的思想已溢出 Text-to-SQL：Agent 系统中「自动归纳失败模式、沉淀为规则库」成为 AgentOps/可观测性的常见做法。
- 修正研究的重心逐渐从「推理期补救」转向「训练期强化」（执行奖励 RL、自我一致性训练）；推理期指南的价值转向可解释性与调试而非纯刷分。
- 生产里 Text-to-SQL 系统普遍保留某种修正环节，执行反馈 + 少量自动归纳规则是务实配置；MAGIC 的三智能体复盘架构适合作为离线「错题本工厂」。
