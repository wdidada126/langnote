## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：Text-to-SQL 用大模型（LLM）把自然语言转成 SQL；但数据库 schema 信息冗长、用户意图复杂，单轮直接生成容易错。
- **为什么难**：长 schema 让提示噪声大；复杂意图难以一次生成正确 SQL；单模型自一致性（self-consistency）投票有天花板。
- **几类主流解法**：

| 路线 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 单轮提示 | 早期 LLM | 直接生成 SQL | 简单，但长 schema 易错 |
| 自一致性 | self-consistency | 同模型多采样投票 | 有效但有上限 |
| 跨模型一致性 | 本文 PET-SQL | 多模型交叉验证 | 突破单模型天花板 |

- **本文属哪类**：LLM 时代 Text-to-SQL 的「提示增强 + 两轮精修 + 跨模型一致性」路线。
- **2-3 个必懂关键名词（直觉解释）**：
  - **reference-enhanced representation（参考增强表示）**：在提示里加入 schema 信息与从表随机采样的单元格值，引导 LLM 生成 SQL。
  - **schema linking（模式链接）**：把 SQL 里提到的实体正确对应到数据库表/列。
  - **cross-consistency（跨一致性）**：用多个不同 LLM 的结果互相印证/投票，而非单个模型自己多采样。

## 1. 问题背景与动机
- **前人工作简述**：LLM 少样本（in-context learning）Text-to-SQL 取得显著成果，但面对冗长数据库信息与复杂意图仍有挑战。
- **前人缺陷/未解决问题（逐条）**：
  1. **长 schema 噪声大**：数据库信息冗长，干扰生成。
  2. **复杂意图难一次成**：单轮生成准确率低。
  3. **自一致性有上限**：同一模型内多采样投票收益有限。

## 2. 核心方法
- **最直观类比**：单轮生成像「凭印象一次写 SQL」；PET-SQL 像「先查资料写好初稿（PreSQL），再请专家对照数据库目录精修终稿，最后让几位不同背景的评委交叉核对选出最靠谱的版本」。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：自然语言问句 + 数据库 schema（可能很长）。
  2. **关键操作（两阶段框架）**：
     - **提示表示**：提出 **参考增强表示**，包含 schema 信息与随机采样的单元格值；
     - **第一阶段**：检索 question-SQL 对作 few-shot，提示 LLM 生成**初步 SQL（PreSQL）**；解析 PreSQL 提到的实体做 **schema linking** 压缩有用信息；
     - **第二阶段**：用链接后的 schema 简化提示，让 LLM 生成**最终 SQL**；
     - **后处理**：用**跨不同 LLM 的一致性（cross-consistency）**而非单模型自一致性来筛选/投票。
  3. **输出**：更准确的 SQL。
- **形式化要点**：核心是「两轮生成 + 跨模型一致性」；超参为 few-shot 数量与一致性阈值（具体🔧查原论文）。
- **理论性质/保证**：以实验验证在 Spider 上达新 SOTA。
