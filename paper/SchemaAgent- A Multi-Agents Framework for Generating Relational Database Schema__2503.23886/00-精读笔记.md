## 一句话总结
普通人不会设计数据库表结构，而现有 Text-to-SQL 又默认表已经设计好了。本文首次系统定义「Text2Schema」问题——把一段自然语言需求直接变成关系数据库表结构，并提出多智能体框架 SchemaAgent（含反思/检查角色与纠错机制），还开源了 381 对需求-表结构基准。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：建数据库第一步是「schema 设计」（设计哪些表、每表哪些列、主外键）。这需专业经验；非技术人员往往只会用 Excel/文件，导致冗余与不一致。Text2Schema 让普通人用自然语言需求直接生成表结构，再衔接 Text-to-SQL 做数据操作。
- **为什么难**：schema 设计含实体识别、规范化、关系建模，远难于「已有表上写查询」；此前研究几乎空白，也缺基准数据。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 人工设计 | DBA | 经验驱动 | 质量高但门槛高 |
| Text-to-SQL | 大量工作 | 已有 schema 写查询 | 不解决建表 |
| 本文 | Text2Schema / SchemaAgent | 需求→schema 多智能体 | 补上上游空白 |

- **本文属哪类**：首次系统定义「需求→关系 schema」生成问题，并用多智能体框架求解。
- **2-3 个必懂关键名词**：
  - **Text2Schema（需求到表结构）**：把自然语言需求转成关系数据库 schema 的新问题。
  - **Multi-Agent Framework（多智能体框架）**：多个分工角色（含反思/检查）协作完成任务。
  - **Schema Design（schema 设计）**：设计表/列/约束以组织数据。

## 1. 问题背景与动机
- **前人工作简述**：Text2SQL 大量工作可把自然语言转成 SQL，但都**预设数据库 schema 已设计好**。
- **前人缺陷/未解决问题**：
  1. schema 设计本身需要领域专家，门槛高；非技术人员难以跨越。
  2. 直接从文本需求生成 schema 的研究**尚未被探索（unexplored）**。

## 2. 核心方法
- **最直观类比**：过去 AI 只会「给你一张现成的表格，帮你写查询」；本文让 AI 先当「数据库架构师」——读懂你的业务需求，画出表结构蓝图，还安排一个「审核员」反复挑错修正。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：自然语言的需求描述。
  2. **关键操作**：
     - 系统定义新问题 **Text2Schema**：把自然语言需求转成关系数据库 schema。
     - 提出 **SchemaAgent**：基于 LLM 的**多智能体框架**，模仿人工 schema 设计流程——给不同智能体分配专门角色并协作细化各自子任务。
     - 引入专门的**反思（reflection）与检查（inspection）角色**，以及**错误检测与纠正机制**跨阶段查错改错。
     - 构建并开源一个基准，含 **381 对「需求描述—schema」**。
  3. **输出**：关系数据库 schema（表结构）。
- **形式化要点**：以角色化多智能体模拟人工设计；纠错机制跨阶段闭环。具体角色与流程见原论文 🔧。
- **理论性质/保证**：以经验为主（🔧 原文未强调理论保证）。
