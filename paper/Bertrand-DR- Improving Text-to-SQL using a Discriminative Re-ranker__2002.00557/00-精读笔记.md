## 一句话总结

生成式 Text-to-SQL 模型输出的 beam 里，正确 SQL 常在候选列表中却排不到第一。本文训练一个 **schema 无关的 BERT 判别式重排器**，从 beam 候选里"挑出最好的那条"——把它套在两个 SOTA 生成模型上，当时冲到 Spider 榜单第 4 名。

## 0. 给新手的阅读前置（背景知识地图）

- **大问题**：Text-to-SQL = 自然语言 → SQL。生成模型每题会输出一串候选（beam），但排序第一的未必正确；"正确答案明明在候选里却没被选中"是纯生成路线的常见痛点。
- **为什么难**：生成模型按语言似然排序，而似然高低与 SQL 语义正确性并不等价。
- **主流做法对比**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 生成式端到端 | SQLNet/RAT-SQL 类 | 直接解码 SQL | 主流；排序可能次优 |
| 判别式打分 | 打分器选候选 | 对候选逐一判别 | 与生成器互补（本文） |
| 执行反馈 | 执行结果过滤 | 跑一遍选对的 | 需要可执行环境 |

- **本文属于哪类**：第二类——生成器之上的重排层。
- **必须先懂的名词**：
  - **beam search 输出**：解码时保留的 k 个最高概率候选序列。
  - **判别式 vs 生成式**：判别式给"输入-候选对"打分排序；生成式直接产出文本。
  - **schema 无关（schema-agnostic）**：重排器不绑定特定数据库模式，跨库泛化。

## 1. 问题背景与动机

- 前人工作：多个生成式 Text-to-SQL 模型在 Spider 上竞逐；重排序思想在机器翻译等任务已被证明有效。
- 未解决的问题：
  1. 生成器的 beam 排序未被充分利用——正确候选常常"在而未顶"；
  2. 生成器与判别器在不同查询难度下各自强弱不明，缺组合指导。

## 2. 核心方法

- 类比：作文比赛先让 10 位作者各交稿（beam 候选），再请一位严格评委逐篇打分（重排器），奖杯发给评委眼中的第一名，而不是按"交稿顺序"。
- 具体做法（输入 → 操作 → 输出）：
  1. 取生成模型（两个 SOTA）的 beam 候选作为输入；
  2. 用 **BERT 微调的判别分类器**对每个（问题, 候选 SQL）对打分，架构为 schema 无关的 GNN 判别网络（GNNDiscrimNet，配套开源 notebook）；
  3. 按判别分数重排，输出新 top-1。
- 分析贡献：跨**查询难度等级**对比生成器与重排器的相对强弱，并给出两者如何组合的指导（🔧 具体难度分级与结论见原文）。

## 3. 变体 / 工程版

- 重排器即即插即用组件；论文同时给出与生成模型的组合策略（何时信任谁 🔧）。

## 4. 实验结论（概览）

- 对比设置：两个 SOTA Text-to-SQL 生成模型 ± 重排器；基准 Spider。
- 结论方向（摘要明确给出）：
  - 重排器在"最佳候选在列表中但不在首位"的情形下稳定带来提升；
  - 应用后达到当时 **Spider 榜单 top 4**；
  - 🔧 精确 exact match / execution accuracy 数字查原文表格后补。
