## 一句话总结
Desbordante 是一个开源数据剖析（data profiling）工具，专门去挖「函数依赖、数据约束、关联规则」这类复杂统计规律；它强调工业级（高效、可扩展、抗崩溃、给解释），并通过 Python 把重活卸载给 C++ 核心，在 Demo 里演示了拼写错误检测、去重、异常检测三件事。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：Data Profiling（数据剖析）是数据质量的第一道关——自动发现数据里隐藏的规律（如「邮编决定城市」）与脏数据（重复、错值、异常）。
- 为什么难：复杂统计规律（functional dependency、约束、关联规则）计算贵；现有系统难和数据科学家常用工具打通；没有「为什么没找到规律」的解释，难以落地。
- 几类主流解法：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 规则/约束发现 | 各类 FD/key 发现器 | 枚举+剪枝找规律 | 准但慢、解释弱 |
| 统计剖析库 | pandas profiling | 描述性统计 | 浅、无复杂规律 |
| 工业级剖析器 | Desbordante | 高效+可扩展+解释 | 工程复杂 |

- 本文属哪类：工业级、可解释、与 Python 生态打通的剖析器。
- 2-3 个必懂关键名词：
  - Functional Dependency（函数依赖，FD）：若 A 列的值确定后 B 列的值必确定，则称 B 函数依赖于 A（如身份证→出生日期）。
  - Data Profiling（数据剖析）：对数据集自动发现统计特征与质量问题的过程。
  - Python integration offloading：把昂贵的运算放到 C++ 核心做，Python 只负责调用，兼顾易用与性能。

## 1. 问题背景与动机
- 前人工作简述：数据剖析在现代数据驱动行业很关键，尤其是复杂统计规律的发现与校验。
- 前人缺陷/未解决问题（逐条）：
  1. 难与数据科学家工具集成：多数复杂统计剖析系统没好好接入从业者日常工具链。
  2. 非工业级：现有系统没面向工业级负载设计，规模一大就吃力。
  3. 不给解释：找不到某规律时，不说明「为什么没找到」，导致规律「悬在空中」、应用面窄。

## 2. 核心方法
- 最直观类比：Desbordante 像一个「会写体检报告的数据医生」——不只告诉你哪里有病，还解释为什么这么判断，并且能处理医院级别的大病历量。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：一张（或多张）待剖析的表。
  2. 复杂规律挖掘：在 C++ 核心高效发现函数依赖、数据约束、关联规则等。
  3. 解释机制：当某规律未被发现时，给出可理解的原因说明（弥补前人空白）。
  4. Python 集成：把代价高昂的操作 offload 到 C++ 核心，Python 侧轻量调用。
  - 输出：发现的规律 + 质量问题诊断（如拼写错误、重复、异常）。
- 形式化要点：以「工业可用性」为设计目标——高效、可扩展、抗崩溃、可解释；核心在 C++/Python 协同与解释模块（🔧 算法细节见论文）。
- 理论性质/保证：无理论最优性保证；贡献在系统设计与可解释性工程。
