## 一句话总结
不用「一次自回归生成一个 SQL」这种容易翻车的方式，Metasql 先把一句自然语言问题拆成一组合法语义「元数据」，用它们约束模型生成一批候选 SQL，再用学习排序（learning-to-rank）从中挑出全局最优的那个——可无缝套在已有 Text-to-SQL 系统上提点。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：Text-to-SQL（自然语言接口到数据库，NLIDB）让不懂 SQL 的人用自然语言查数据。主流模型（seq2seq 或大模型）通常用自回归（auto-regressive）方式一个字一个字地生成单条 SQL。
- 为什么难：一次只生成一条 SQL，如果中途走偏就得到错误结果；且「最佳 SQL」未必是概率最高的那一条。
- 几类主流解法（表格）：

| 路线 | 直觉 | 代表 |
|------|------|------|
| 单条自回归生成 | 直接生成唯一 SQL | 多数 seq2seq / LLM 方案 |
| 采样+重排 | 生成多个再选最好 | DIN-SQL、本文 Metasql |
| 判别式重排序 | 训练一个 re-ranker 打分 | Bertrand-DR |

- 本文属于：采样+重排路线，提出统一的「generate-then-rank」框架，且与已有 NLIDB 即插即用。
- 关键名词直觉：
  - 查询元数据（query metadata）：问题描述里「语义的基本构件」，如涉及哪些表/列、聚合类型等，用来指导生成。
  - learning-to-rank：用机器学习给候选排序，挑最优。

## 1. 问题背景与动机
- 前人工作简述：神经 seq2seq 与大模型已把整体翻译准确率推过 70%，但「单条自回归生成」易产生次优甚至错误翻译。
- 前人的缺陷/未解决问题（逐条）：
  1. 只生成单条 SQL，一旦生成走偏无法挽回。
  2. 缺乏一种能灵活注入语义约束、又能全局择优的统一框架。
  3. 改进方案难以直接复用已有 NLIDB，工程代价大。

## 2. 核心方法
- 最直观类比：写作文不要一次写定稿，而是先列提纲（元数据），写几版草稿，再让老师挑最好的一篇——Metasql 就是「列提纲→写多版→挑最好」。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：一句自然语言问题。
  2. 关键操作：
     - 先把问题语义拆成一组可能的查询元数据（语义基本构件）；
     - 用这些元数据作为语言约束，引导底层翻译模型生成一批候选 SQL；
     - 用 learning-to-rank 算法对候选打分，挑出与问题最匹配的那个。
  3. 输出：全局最优的 SQL 查询。
- 形式化要点：元数据充当「语义约束 + 候选生成控制器」，重排阶段做全局优化而非贪心单条。
- 理论性质/保证：以实证为主，无形式化保证。
