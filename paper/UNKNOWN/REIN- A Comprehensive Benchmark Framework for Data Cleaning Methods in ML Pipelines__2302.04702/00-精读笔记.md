## 一句话总结
REIN（benchmark 叫 REIN1）首次系统评估「数据清洗方法对下游 ML 模型的影响」：它测了 38 种错误检测与修复方法，在 14 个公开数据集、多种 ML 模型上回答「清洗到底有没有用、在哪有用」——补上旧方法普遍忽视下游模型需求的大缺口。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：真实表格数据常有缺失值、异常值、重复、格式违规、不一致等脏数据；ML 模型质量依赖干净数据。但「清洗方法好不好」以往多在「清洗后数据更干净」层面评，不关心对 ML 的影响。
- 为什么难：清洗与下游模型脱节，清洗的收益难以量化，方法众多（38 种）无从比较。
- 几类主流解法（清洗方法）：

| 类型 | 代表 | 思路 |
|------|------|------|
| 缺失值处理 | 均值/插补 | 填值 |
| 异常检测 | 离群识别 | 去噪 |
| 去重/一致性 | 实体解析 | 消歧 |

- 本文属哪类：基准（benchmark）框架，不是单一清洗算法。
- 2-3 个必懂关键名词：
  - 数据清洗（data cleaning）：修正脏数据使其适合分析/建模。
  - 错误检测/修复（error detection/repair）：先发现错误再修正的两步。
  - 下游 ML 模型：清洗后数据要喂的模型（分类/回归等）。

## 1. 问题背景与动机
- 前人工作简述：大量数据清洗方法被提出，但多数忽视下游 ML 模型需求。
- 前人缺陷/未解决问题（逐条）：
  1. 与 ML 脱节：清洗方法的潜力在 ML 流水线中未被揭示。
  2. 缺系统基准：没有全面框架比较 38 种方法对 ML 的影响。
  3. 必要性与位置不清：「清洗是不是必要步骤、放在哪」无系统答案。

## 2. 核心方法（基准设计）
- 最直观类比：REIN 像「清洗方法高考」——把 38 个考生（清洗法）放到 14 套真题（数据集）上，用不同评分官（ML 模型）打分，最后给出「谁在哪种题上管用」的榜单。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：含真实/合成错误画像的 14 个公开数据集。
  2. 覆盖方法：38 种简单与高级的错误检测+修复方法。
  3. 下游评测：多种 ML 模型训练并对比性能。
  4. 输出：回答「清洗必要性与位置」的研究结论（benchmark 报告）。
- 形式化要点：核心是「清洗方法 × 数据集 × ML 模型」的三维基准；超参数为错误画像与模型选择（🔧 见论文）。
- 理论性质/保证：不适用（实证基准）。
