## 一句话总结
大家都知道大预训练模型带有对不同人群的社会偏见，会放大既有刻板印象；而 Text-to-SQL 恰恰被大量用于行政/管理类行业，一个不公平的查询结果可能造成严重后果。但现有 Text-to-SQL 模型都是在 Spider、WikiSQL 这类「干净、中性」的数据集上训练评测的，这种理想条件掩盖了偏见，使之在真实应用中才暴露出来。本文系统性地发现并分类 Text-to-SQL 模型中的社会偏见：总结了结构化数据中可能出现的偏见类别，构建测试基准，并揭示「任务准确率相近的模型，其偏见程度可能差别很大」，同时给出用该方法论发现与评估下游任务偏见的做法。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：Text-to-SQL 不只是「翻译得对不对」，还要问「翻译得公不公平」。当同一个问题只因涉及的人群不同（性别、种族、年龄、地域等）就得到不同结果时，就出现了社会偏见。
- 为什么难：偏见不体现在 aggregate 的准确率上——两个准确率一样的模型可以有完全不同的偏见率；而且主流基准本身是干净中性的，测不出来。
- 几类主流解法：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 通用模型偏见评测 | NLP 公平性基准（词向量/掩码语言模型类） | 测模型表示与生成中的刻板关联 | 成熟，但不针对结构化查询 |
| 数据侧去偏 | 重加权、去偏语料 | 从训练数据消除偏差 | 通用，但对 SQL 结构无针对性 |
| 任务内偏见基准（本文） | 本文的测试基准与分类法 | 在 Text-to-SQL 的结构化数据上构造对照问题 | 直击场景；需要精心设计对照集 |
| 输出侧约束/审计 | 规则校验、结果审查 | 对生成 SQL 与结果做公平性检查 | 可部署，但覆盖有限 |

- 本文属于哪一类：任务内的社会偏见分类体系 + 基准构建 + 方法论（偏诊断而非治疗）。
- 必懂关键名词：
  - social bias（社会偏见）：模型对特定人口群体（gender / race / age / 地域等）表现出系统性差异或刻板关联。
  - structured data bias（结构化数据中的偏见）：偏见不只来自自然语言，也可能来自表的内容、取值分布与 schema 设计。
  - test benchmark with controlled pairs（对照式测试集）：只改变「人群属性」这一变量、其余保持不变，对比模型输出是否改变。
  - task accuracy vs bias rate：任务准确率（翻译对不对）与偏见率（是否因人群而异）是两个正交指标。

## 1. 问题背景与动机
- 前人工作简述：大型预训练语言模型被证实携带针对不同人口群体的社会偏见，会放大社会既有刻板印象；NLP 领域已有若干偏见评测方法。Text-to-SQL 方向则长期以 Spider、WikiSQL 等基准上的准确率为主要目标。
- 前人缺陷/未解决问题（逐条）：
  1. 下游场景被忽视：Text-to-SQL 主要用于行政/管理行业，不公平决策后果严重，但偏见问题未被系统研究。
  2. 训练/评测数据过于干净：模型在 Spider、WikiSQL 等干净中性数据集上训练，掩盖了偏见。
  3. 偏见会在真实场景暴露：实验室里看不出的问题，上线后才出现。
  4. 缺少分类体系：不清楚「结构化数据上的 Text-to-SQL 偏见」到底有哪些类别。
  5. 缺少可操作的方法论与基准：无法系统发现、量化与比较不同模型的偏见程度。

## 2. 核心方法
- 最直观类比：判断一个翻译系统是否公平，不是问它「平均分多少」，而是给它两道只差一个人群词的题，看它给的 SQL（以及查出来的结果）是不是不一样。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：Text-to-SQL 模型 + 结构化数据库（schema 与内容）。
  2. 总结偏见类别：归纳在结构化数据上、Text-to-SQL 模型中可能出现的社会偏见类别（categories）。
  3. 构建测试基准：按这些类别构造测试基准（bench），使偏见可被量化。
  4. 发现与评估：展示如何用该方法论在下游 Text-to-SQL 任务中发现并评估社会偏见。
  5. 输出：偏见类别体系 + 基准 + 各模型的偏见评估结果（关键发现：准确率相近的模型偏见率可相差很大）。
- 形式化要点：核心是「controlled variation of demographic attribute」式的测试设计；摘要未给出偏见的具体度量公式 🔧。
- 理论性质/保证：无（评测与分析方法论）。

## 4. 实验结论（概览）
- 对比基线：多个 Text-to-SQL 模型（具体清单 🔧 查原论文）。
- 数据集：本文构建的测试基准（基于结构化数据；规模与来源 🔧 查原论文）。
- 评价指标：任务准确率与偏见率（bias rate）两类指标并列。
- 结论方向：
  - 揭示了 Text-to-SQL 模型中确实存在可被发现与分类的社会偏见。
  - 关键发现：任务准确率相近的模型，其社会偏见的发生率可能相差很大——即准确率不能代表公平性。

## 7. 2026 视角（🔧）
- LLM 时代的 Text-to-SQL 大量用在 BI、政务、HR、金融风控等场景，公平性与合规审计成为上线前置条件（与隐私、可解释性并列）；「准确率一样但偏见不同」这一洞见今天更受重视。
- 实践趋势：在评测集中加入公平性/鲁棒性子集、对生成 SQL 做结果层面的差异审计、以及在提示与 schema 描述中避免诱导性措辞。
- 本文的方法论（构造只变人群属性的对照问题）已成为同类审计的通用做法。
- 本节为趋势性判断；具体合规要求与最新基准 🔧 查当年资料。

## 8. 新手学习路线
- 10 分钟：读摘要 + 第 0、2 节，理解「准确率 ≠ 公平性」这一核心结论。
- 30 分钟：自己构造 5 组对照问题（只换人群属性），在任意开源 Text-to-SQL 模型上跑，比较生成的 SQL 与执行结果是否不同。
- 进阶：读论文的偏见类别体系与基准构造规则；对多个模型画出「准确率-偏见率」散点图，验证是否存在相关性；思考如何把偏见指标并入 CI 评测。
