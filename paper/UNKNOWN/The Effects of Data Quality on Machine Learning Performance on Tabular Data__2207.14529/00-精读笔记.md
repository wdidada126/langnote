## 一句话总结
训练数据脏一点，模型到底会坏多少？本文系统性地往表格数据里注入六种「数据质量缺陷」，用 19 种常见机器学习算法跑分类、回归、聚类三类任务，并区分「污染训练集 / 污染测试集 / 两者都污染」三种情形，用实验回答了「数据质量如何影响 ML 性能」这个长期靠直觉判断的问题。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：数据质量（data quality）是数据治理的核心议题——数据准不准、全不全、一致不一致，直接决定下游分析/建模能不能信。
- **为什么难**：
  - 质量的维度很多（准确性、完整性、一致性……），不同维度对模型的影响机制完全不同；
  - 「脏」的影响还取决于脏在哪：训练集脏 vs 测试集脏，后果不一样；
  - 不同模型对脏数据的敏感度差别很大（树模型 vs 线性模型 vs 聚类）；
  - 以往多是零散案例，缺少大范围、可对照的实证研究。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 清洗/修复 | 规则清洗、BClean、PClean、RTClean | 检测并修正错误值/缺失值 | 直观有效，但可能引入偏差 |
| 质量评估与监控 | 数据剖析（profiling）、质量指标 | 先量化质量再决定是否用 | 不修数据，只给决策依据 |
| 鲁棒建模 | 抗噪损失、鲁棒统计 | 让模型本身不怕脏 | 通用，但往往牺牲干净数据上的性能 |
| 缺陷注入与基准 | Badgers、REIN | 人为造脏，做可控对照实验 | 可复现，是本文采用的路子 |

- **本文属于哪一类**：**缺陷注入式的实证基准研究**——不提出新算法，而是给出一张「质量维度 × 算法 × 污染位置」的大表。
- **必懂关键名词**：
  - **数据质量维度（data quality dimensions）**：如 accuracy（准确性/是否有错值）、completeness（完整性/是否缺失）、consistency（一致性/是否自相矛盾）等；本文涉及六个维度 🔧 完整清单见原论文。
  - **污染位置（pollution scenario）**：脏数据被喂进训练阶段、测试阶段，还是两者都喂——三种情形结论不同。
  - **表格数据（tabular data）**：行列结构的关系表，区别于图像/文本，是数据库与 ML 交叉的典型场景。

## 1. 问题背景与动机
- 前人工作简述：可信 AI（Trustworthy AI）的呼声越来越高，业界普遍认同「训练/测试数据要在准确性、完整性、一致性等多个质量维度上达标」。数据清洗与质量评估领域已有大量工具和方法。
- 前人的缺陷 / 未解决问题（逐条）：
  1. **缺大范围实证**：多数论文只研究某一种质量缺陷对某几种模型的影响，没有横跨多维度 × 多算法的系统性对照。
  2. **任务覆盖不全**：已有研究多集中在分类，回归与聚类（尤其是无监督的聚类）涉及较少。
  3. **污染位置未区分**：很多实验默认「训练测试一起脏」，无法回答「测试数据脏一点点会不会毁掉评估结论」这类实际问题。
  4. **缺少可复现的注入工具**：不同论文注入脏数据的方式不统一，结论难以互相印证。
  5. **只有直觉没有量化**：从业者常说「数据质量很重要」，但不知道「重要到什么程度、哪个维度最要命」。

## 2. 核心方法
- **最直观类比**：这像一次「食材可控掺假」的对照实验——同样的菜谱（算法），同一批食材（数据集），只在盐、水、油（六个质量维度）上按剂量掺假，再看成品（模型性能）怎么变；而且分别试「调料时掺假」（训练）和「品尝时掺假」（测试）。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：若干表格数据集 + 19 种流行 ML 算法（覆盖分类、回归、聚类） + 六个数据质量维度。
  2. **关键操作一：定义并注入质量缺陷**。对每个维度设计注入方式（如制造缺失、重复、不一致、错误值等 🔧 具体注入算子见原论文/仓库），并按强度分级。
  3. **关键操作二：三场景对照**。分别在「仅污染训练集」「仅污染测试集」「两者都污染」三种情形下训练与评估。
  4. **关键操作三：跨算法横评**。同一份脏数据喂给 19 种算法，观察性能下降幅度的分布差异。
  5. **输出**：质量维度与模型性能之间的经验关系，以及一份供从业者参考的讨论与建议。
- **形式化要点**：核心是「可控实验设计」——把质量维度作为自变量、性能作为因变量，其余条件保持不变；超参数包括污染强度、注入维度组合、算法集合 🔧。
- **理论性质 / 保证**：无理论保证（🔧 论文定位为实证研究），结论是经验性的、与所选数据集/算法集合绑定的。

## 3. 变体 / 工程版（如有）
- **三场景版本**：同一套实验在「训练脏 / 测试脏 / 全脏」三种配置下各跑一遍，是本文方法上最有辨识度的设计。
- **工具化**：仓库 `dq4ai` 把注入与评测流程固化，便于别人在自己的数据上复现同类实验 🔧 具体接口以 README 为准。

## 4. 实验结论（概览）
- 对比基线：不是「方法 vs 方法」的对比，而是**同一算法在干净数据 vs 不同质量缺陷数据上的自身对照**；横向则比较 19 种算法的敏感度差异。
- 数据集：多份表格数据集（摘要未列出具体名称与规模 🔧 查原论文/仓库）。
- 评价指标：分类/回归/聚类各自的标准性能指标（如准确率、误差、聚类质量指标 🔧 具体指标名查原论文），以「相对干净基线的性能下降」为核心观察量。
- 结论方向：数据质量缺陷确实会显著损害模型性能，且**影响程度随质量维度、污染位置、算法类型而变**。🔧 **摘要未给出任何具体数字**，论文结尾有 extensive discussion 总结观察；精确数字请查原论文图表后补入。
- 阅读提示：真正的价值在论文的讨论部分——「哪种缺陷最致命、哪类算法最抗造、测试集脏会怎样」这类可操作结论都在那里 🔧。

## 5. 开源代码与动手实践
- 仓库地址：https://github.com/hpi-information-systems/dq4ai
- 语言：Python（🔧 版本与依赖以 README 为准）
- 典型流程（**教学示意**，以 README 为准 🔧）：
  ```bash
  # 1) 克隆仓库，按 README 安装依赖
  git clone https://github.com/hpi-information-systems/dq4ai
  # 2) 选一份表格数据集，先跑「干净基线」，记录性能指标
  # 3) 注入一种质量缺陷（如缺失值），逐步加大污染比例，画性能下降曲线
  # 4) 换成「只污染测试集」，对比与「只污染训练集」的差异
  # 5) 换一种算法（如决策树 vs 线性回归），比较谁更抗脏
  ```
  这是新手理解「数据质量」最便宜的一条路：不用懂复杂理论，看曲线往下掉就懂了。

## 7. 2026 视角（🔧）
- 随着基础模型兴起，「表格数据上的 ML」从手写特征工程转向预训练/表格基础模型，但**数据质量仍是决定上限的硬约束**；业界在 lakehouse 里普遍部署了质量监控与数据契约（data contract）。
- 研究方向从「静态表质量」走向「流式质量监控、血缘驱动的质量定位、以及 LLM 辅助的清洗」。
- 本文这类「大规模实证基准」的价值反而在上升——新模型不断出现，需要一个稳定的尺子来判断它们对脏数据的敏感度。本节为趋势性判断 🔧。

## 8. 新手学习路线
- **10 分钟**：读摘要 + 第 0 节，记住「6 个质量维度 × 19 种算法 × 3 种污染场景」这个实验骨架。
- **30 分钟**：用 dq4ai 或 Badgers 在自己熟悉的一份表格数据上注入缺失值，画出「污染比例 → 准确率」曲线。
- **进阶**：精读论文的讨论章节，整理出「哪类算法对哪类缺陷最敏感」的对照表；再用 REIN 验证「清洗之后能恢复多少」；思考测试集污染对「模型选型」这一决策本身的危害。
