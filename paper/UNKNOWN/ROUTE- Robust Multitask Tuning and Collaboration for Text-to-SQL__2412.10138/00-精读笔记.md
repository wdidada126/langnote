## 一句话总结
最强 Text-to-SQL 多依赖闭源大模型（如 GPT-4）的上下文学习，难以私有化落地。ROUTE 用「多任务监督微调（SFT）+ 多任务协作提示（MCP）」提升开源小模型的综合能力：不仅教它写 SQL，还教它做 schema linking、噪声纠正、续写，再用多任务协作减少幻觉，从而在 8 个开源模型、5 个基准上取得领先。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：Text-to-SQL 把自然语言转成 SQL。当前 SOTA 常靠闭源大模型（GPT-4）的「上下文学习（ICL）」——给几个示例就让模型生成 SQL。但这对隐私、成本、离线部署都不友好，难以在开放场景落地。
- 为什么难：开源小模型直接生成复杂 SQL 容易错；单纯 SFT 只教「写 SQL」一种能力，模型对 schema 结构、噪声、生成中断等子问题缺乏专门能力，容易幻觉（hallucination，编造不存在的表/列）。
- 几类主流解法（表格）：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 闭源 ICL | GPT-4 类 | 多示例提示直接生成 | 强但贵、难私有化 |
| 单任务 SFT | 传统微调 | 只教写 SQL | 能力单一、易幻觉 |
| 多任务 SFT | 本文 ROUTE | 同时教 SQL 生成 + 子任务 | 能力更全、更鲁棒 |
| 多 Agent 协作 | MAC-SQL 等 | 多个模型分工 | 强但推理成本高 |

- 本文属于哪一类：开源模型的多任务监督微调 + 协作提示，强调「显式多任务能力」来最大化 Text-to-SQL 表现。
- 2-3 个必懂关键名词：
  - SFT（Supervised Fine-Tuning，监督微调）：用「输入-输出」标注数据把预训练模型调成专做某任务的模型。
  - Schema Linking（模式链接）：把问题里的词对应到数据库具体的表/列，是写对 SQL 的前提。
  - 幻觉（Hallucination）：模型编造不存在的表名、列名或逻辑，是 Text-to-SQL 的常见错误源。

## 1. 问题背景与动机
- 前人工作简述：LLM 让 Text-to-SQL 大幅进步，但 SOTA 卡在闭源模型的 ICL 上，限制开放场景适用性；已有 SFT 方法多只做「SQL 生成」单一任务。
- 前人的缺陷/未解决问题（逐条）：
  1. 闭源依赖：最强方法依赖 GPT-4 的 ICL，难私有化/低成本部署。
  2. 任务单一：现有 SFT 只教写 SQL，模型对 schema linking、噪声纠正、续写等子能力弱。
  3. 幻觉难抑：生成 SQL 时易编造结构，缺乏协作机制来纠偏。

## 2. 核心方法
- 最直观类比：只让学徒「照着抄最终答案」容易抄错还自作主张；ROUTE 像给学徒排了「先认表结构、再改错、再续写、最后写 SQL」的一套多工种训练，还让这些工种互相核对，减少瞎编。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 多任务 SFT：用多种与 SQL 生成相关的合成训练数据做监督微调，除写 SQL 外，额外引入 schema linking、噪声纠正（noise correction）、续写（continuation writing） 等任务，增强模型对 SQL 语法的理解与生成质量。
  2. 多任务协作提示（MCP, Multitask Collaboration Prompting）：受 LLM Agent 协作模式启发，让多个 SQL 相关任务互相协作，在生成 SQL 时减少幻觉。
  3. 输出：更鲁棒、更准确的开源模型 Text-to-SQL 能力。
- 形式化要点：训练目标覆盖多任务损失；MCP 在推理时以协作提示组织子任务；🔧 具体损失/提示模板查原文。
- 理论性质/保证：论文以实验为主，强调多任务带来的「理解增强」与「幻觉减少」（🔧 理论分析查原文）。
