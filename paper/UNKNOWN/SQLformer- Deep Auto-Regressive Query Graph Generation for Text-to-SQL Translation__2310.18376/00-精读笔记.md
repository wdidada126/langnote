## 一句话总结
SQLformer 把「生成 SQL」重新定义为「按广度优先规范顺序、自回归地生成 SQL 的抽象语法树（AST）图」，并在编码器/解码器中注入由「表/列选择」引导的结构归纳偏置，从而在六个主流 Text-to-SQL 基准上达到 SOTA。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：让不懂 SQL 的人用自然语言提问，系统自动产出可执行 SQL。难点在于「自然语言」与「SQL 语法/数据库模式」之间的对齐。
- **为什么难**：(1) 不同数据库的 schema 千差万别，模型要适配未见过（unseen）的库；(2) SQL 是强语法结构，生成必须合法且可执行；(3) 自然语言歧义多，同一句话可能对应多种 SQL。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 序列到序列（Seq2Seq） | 早期 LSTM/Transformer | 把 SQL 当平铺 token 串生成 | 简单，但易生成非法 SQL |
| 基于骨架/草图 | RAT-SQL、RESDSQL | 先抽 SQL 骨架（SELECT/FROM/WHERE…），再填槽 | 结构更稳，仍需分步 |
| 图/树结构生成 | **SQLformer** | 把 SQL 当 AST 图、按规范顺序自回归生成 | 显式建模层级结构，对齐更准 |
| 预训练+大模型 | STAR、近期 LLM | 用大规模语料预训练再微调 | 能力强，但成本高、可解释弱 |

- **本文属哪类**：图/树结构生成 + Transformer 自回归，属于「结构化生成」路线。
- **2-3 个必懂关键名词**：
  - **AST（抽象语法树）**：SQL 解析后的树形结构；根是查询，子节点是 SELECT 列、表、条件等。
  - **自回归（auto-regressive）**：像写句子一样，一个 token/节点接一个地生成，每步依赖前面已生成部分。
  - **归纳偏置（inductive bias）**：人为给模型「先验结构提示」，这里是用「选中了哪些表/列」引导生成，减少瞎猜。

## 1. 问题背景与动机
- **前人工作简述**：Text-to-SQL 多用 Seq2Seq 或草图填充，已能在 Spider 等基准上取得不错成绩；但面对未见过数据库、自然语言与 SQL 语法对齐仍是痛点。
- **前人缺陷/未解决问题（逐条）**：
  1. 多数模型把 SQL 当线性 token 序列，忽略了 SQL 内在的层级树结构，易产生语法/语义错误。
  2. 对「表/列选择」这一关键中间信号利用不足，解码时缺乏结构引导。
  3. 在未见过（unseen）数据库上的泛化能力与对齐鲁棒性受限，阻碍实际落地。

## 2. 核心方法
- **最直观类比**：传统方法像「逐字默写一句 SQL」；SQLformer 像「先画好 SQL 的树状骨架，再按约定顺序（广度优先）把每个节点补全」，并且旁边一直贴着「用到了哪些表/列」的便签来指导落笔。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：自然语言问题 + 数据库 schema（表、列、类型）。
  2. **编码**：编码器注入「结构归纳偏置」——显式建模问题与 schema 中表/列的选择关系。
  3. **解码**：把 SQL 表示为图（AST），按 **Breadth-First Search（BFS）规范顺序** 自回归地逐个生成节点，使树结构得以被序列模型稳定学习。
  4. **输出**：合法的 SQL 查询（AST → 可执行 SQL）。
- **形式化要点**：核心是把 SQL 查询 AST 以图形式、BFS 规范序展开为生成序列；超参/网络细节以原论文为准（🔧）。
- **理论性质/保证**：未给出理论最优性保证；卖点是结构偏置带来的对齐与泛化改善（🔧 实验为主）。

## 7. 2026 视角（🔧）
- Text-to-SQL 已从「小模型+结构偏置」全面转向「大模型（LLM）+ 少样本/微调」范式；但 SQLformer 这类「显式结构生成」思想仍被用于提升可解释性与降低幻觉。
- 近年趋势：LLM 主导（如 GPT/开源 SQL 模型）、self-consistency、执行反馈纠错的 Agent 框架。本节为趋势判断（🔧 以当年基准为准）。
