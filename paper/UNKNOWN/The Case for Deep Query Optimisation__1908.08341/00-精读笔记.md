## 一句话总结
传统查询优化把「物理算子」当成不可再拆的积木块；本文主张把这层抽象再打碎一层，用更细粒度的「子构件」来拼计划（Deep Query Optimisation，DQO），并且可以把预先拼好的构件固化成「物化算法视图（MAV）」反复复用——就像物化视图缓存的是数据，MAV 缓存的是「一段算法」。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：一条 SQL 进来，数据库要决定「先扫哪张表、用什么 join 算法、走不走索引、要不要并行」——从成千上万种等价执行方案里挑代价最低的那个。这就是查询优化（Query Optimisation，QO），是数据库里最核心的优化问题。
- 为什么难：候选计划空间随表数指数爆炸；代价估计（cardinality/cost）本身就有误差；而可选方案又被「物理算子」的固定粒度限制住了——你只能选 `HashJoin` 或 `SortMergeJoin`，不能选「HashJoin 的分区函数 + 自定义的探测顺序」。
- 几类主流解法：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 经典代价优化 | System R / Selinger 风格动态规划 | 枚举 join 顺序 + 物理算子，按代价模型选最优 | 成熟稳，但计划空间被固定算子集限制 |
| 转换/重写规则 | Cascades、Calcite、Orca | 用规则做等价变换，搜索更灵活 | 表达力强，规则库维护成本高 |
| 学习型优化 | Balsa、Lero、DQ（深度强化学习） | 用 ML 学代价或学策略 | 能跳出代价模型误差，训练/泛化成本高 |
| 代码生成 | Hyper、NoisePage、LLVM codegen | 把计划编译成机器码，算子边界变软 | 快，但优化与生成的耦合复杂 |

- 本文属于哪一类：既不是纯学习，也不是纯规则——它属于「把算子拆得更细，扩大优化搜索空间」这一路线，是经典代价优化的「加深版」。
- 必懂关键名词：
  - 物理算子（physical operator）：可直接执行的最小单位，如 hash join、hash-based grouping、index scan。
  - MAV（Materialised Algorithmic View，物化算法视图）：把「一段算子的实现/子构件组合」预先计算并固化下来的视图——缓存的是算法而不是结果数据。
  - AVSP（Algorithmic View Selection Problem）：决定「哪些 MAV 该在什么时候物化」，类比经典的物化视图选择问题。

## 1. 问题背景与动机
- 前人工作简述：自 System R 以来，主流优化器都遵循「逻辑算子 → 物理算子 → 代价模型 → 动态规划/规则搜索」的范式；算子是实现者手写的固定黑盒，优化器只能在算子之间做选择，无法进入算子内部重新组合。后来出现自适应/学习型优化（以及本文作者此前在「算法视图」方向的工作 🔧），开始松动这层边界。
- 前人的缺陷 / 未解决问题（逐条）：
  1. 抽象层次太浅：所谓「物理」算子其实是一大段代码的封装，内部还有分区、探测、聚合等更细的构件，优化器看不见也就无从选择。
  2. 只在「算子级」枚举：计划搜索只枚举算子组合，错过了「子构件级」的大量等价（且可能更优）实现。
  3. 算子实现无法复用与预计算：不同查询里重复出现同一段算子逻辑，每次都从头生成，没有类似物化视图的复用机制。
  4. 「物理」一词本身含糊：论文专门质疑 'physical' 与 'physical operator' 的提法，认为这层术语固化了思维。
  5. 缺少配套的选择问题：即便有可物化的算法构件，也没有回答「物化哪些、何时物化」。

## 2. 核心方法
- 最直观类比（论文自己用的生物学类比）：传统 QO 像「用现成器官拼一个生物」；DQO 像「下探到细胞甚至蛋白质层面去拼」——可选组合多了几个数量级，性能上限更高，但你要付出的搜索代价也更大。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：一条 SQL（逻辑计划）+ 代价模型 + 一组可用的算子实现。
  2. 关键操作一：拆开「物理算子」。把例如 hash-based grouping 这样的算子拆成更细的子构件（分区策略、哈希表布局、探测/聚合方式等 🔧 具体拆分清单见原论文），让优化器能看见内部。
  3. 关键操作二：子构件级的（子）计划枚举。用这些子构件在离线（编译/准备期）与查询时两个阶段枚举候选（子）计划，再由代价模型筛选。
  4. 关键操作三：合成 MAV。把反复出现的算子/组件组合预计算并固化成 Materialised Algorithmic Views，供后续查询直接复用（等价于「预编译 + 缓存的算法」）。
  5. 输出：一个由细粒度子构件拼出的物理计划，加一套 MAV 物化决策（即求解 AVSP）。
- 形式化要点：核心是「搜索粒度」这一维度的加深；超参数包括：拆到多细（子构件粒度）、枚举在离线还是查询时进行、物化哪些 MAV（即 AVSP 的解）。论文定位为 vision/agenda 型论文，未给出完整形式化最优性证明 🔧。
- 理论性质 / 保证：无显式理论保证（🔧 论文以构想 + 初步实验为主）；可预期的性质是「搜索空间单调变大 ≥ 浅层 QO 的可行解集合」，因此理论上最优代价不劣于浅层 QO，但搜索开销随之上升——这正是论文提出的开放问题 (1)。

## 3. 变体 / 工程版（如有）
- MAV 的两种用法：离线预计算 + 查询时合成，对应论文列出的研究方向 (2)。
- AVSP 作为新问题：类比「物化视图选择」，需要按工作负载决定 MAV 集合，是本文点名留给大家的研究方向 (3) 🔧。
- 工程落地形态：仓库中的 `Deep-Query-Optimization` 项目提供了围绕该构想的实验代码（具体内容以 README 为准 🔧）。

## 4. 实验结论（概览）
- 对比基线：论文把一个曾经被称为「hash-based grouping」的「物理算子」拿出来，单独做 micro-benchmark，同时也放进启用 DQO 的动态规划里做端到端对比（基线即不拆分的浅层 QO 版动态规划）。
- 数据集 / 负载：论文未在本摘要中列出数据集名 🔧（推测为合成/标准关系负载，需查原论文 Experiments 章节）。
- 评价指标：算子自身执行时间、以及在 DQO 动态规划下得到的整体计划代价/执行时间 🔧。
- 结论方向：拆细之后确实能构造出与「标准 hash-based grouping」不同的实现，并且在 DQO 动态规划中可被纳入比较——说明「深度优化」这条路走得通。🔧 摘要未给出具体加速数字，精确表格请查原论文 Table 2/3/5 与 Figure 4 后补入。
- 论文结尾给出一份 DQO 研究议程（research agenda），而非一个已收敛的系统。

## 7. 2026 视角（🔧）
- 查询优化在 2026 仍是数据库系统的核心壁垒：产业界主流仍是「经典代价优化 + 少量自适应/学习组件」，学习型优化器尚未大规模接管生产。
- 本文提出的「算子内部可组合 + 算法可物化」思想，与后来的代码生成（codegen）、向量化执行引擎、以及「编译型」数据系统（如用 MLIR/LLVM 做计划编译）是同一股趋势的不同侧面。
- 「缓存算法而不只是缓存数据」这个提法，在向量检索时代的「算子融合、kernel 复用」语境下依然有回响。本节为趋势性判断，具体落地情况 🔧 查当年资料。

## 8. 新手学习路线
- 10 分钟：读完摘要 + 本笔记第 0、2 节，抓住一句话：DQO = 把算子拆细后再枚举。
- 30 分钟：读懂「hash-based grouping」被拆开的例子（论文 Experiments 部分），并对着 Figure 4 看子构件组合带来的差异 🔧。
- 进阶：精读论文对 'physical operator' 的术语质疑部分；思考 AVSP 与经典「物化视图选择」的对应关系；尝试用 Balsa/JoinGym 之类的环境做一组「浅层 vs 深层」的对照实验；阅读作者后续的算法视图相关工作 🔧。
