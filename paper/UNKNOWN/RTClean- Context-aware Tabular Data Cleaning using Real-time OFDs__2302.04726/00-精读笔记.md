## 一句话总结
机器学习类应用（智能家居、辅助医疗、自动驾驶）高度依赖训练/推理数据的质量，但老清洗方法看不到「数据分布漂移和错误模式随场景变化」这种上下文。RTClean 用「从实时上下文模型动态抽取的函数依赖（OFD）规则」来自动清洗，并以智能家居为案例证明它在检测与修复准确率上优于一组基线。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：表格数据清洗（data cleaning）是发现并修复数据里错误/缺失/不一致的过程。对依赖数据的 ML 应用（智能家居、辅助医疗、自动驾驶）而言，数据质量直接决定系统安不安全、准不准。
- **为什么难**：真实数据的**错误模式会随上下文变化**——比如不同时间段、不同传感器、不同用户场景下，哪些值算「异常/错误」是不同的。静态清洗规则跟不上这种分布漂移。
- **几类主流解法（表格）**：

| 方法 | 代表 | 思路 | 对上下文的处理 |
|------|------|------|----------------|
| 统计/规则清洗 | 传统 ETL 规则 | 固定阈值/规则 | 不看上下文漂移 |
| 概率编程清洗 | PClean、BClean | 用概率模型建模 | 建模但不实时跟随上下文 |
| 函数依赖清洗 | 经典 FD/OFD | 用「列间约束」发现错误 | 静态约束 |
| **本文 RTClean** | 实时 OFD | 从实时上下文动态抽规则 | 跟随上下文漂移 |

- **本文属于哪一类**：基于**约束（函数依赖）**的清洗，但约束是**实时、上下文感知**抽取的。
- **2-3 个必懂关键名词**：
  - **数据清洗（data cleaning）**：检测并修复错误/缺失/不一致数据。
  - **函数依赖（FD, Functional Dependency）**：如「邮编决定城市」这类列间约束，违反它就提示可能出错；OFD 是其在特定上下文下的有序/条件变体。
  - **上下文模型（context model）**：实时刻画当前数据分布与错误画像的模型，RTClean 从中抽规则。

## 1. 问题背景与动机
- **前人工作简述**：ML 应用广泛但受数据质量制约；已有清洗方法多无法利用上下文信息，难以跟踪数据分布漂移与相应错误画像的变化。
- **前人的缺陷/未解决问题（逐条）**：
  1. **无上下文**：现有清洗方法不能利用上下文信息。
  2. **跟不上漂移**：难以跟踪数据分布偏移与关联的错误画像变化。
  3. **缺乏动态规则**：规则多为静态，无法随实时场景更新。

## 2. 核心方法
- **最直观类比**：老清洗像「贴一张固定标语：温度超过 100 度就是错」；但智能家居里夏天和冬天、客厅和冰箱的「正常温度」不同。RTClean 像「实时观察当前环境，动态总结出『这个房间此刻温度该在什么范围』的规则」，按当下上下文判断并修。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：实时流式/批量的表格数据 + 一个**实时上下文模型（live context model）**。
  2. **关键操作**：从上下文模型中**动态抽取函数依赖规则（OFD）**，用这些实时规则做自动清洗（检测异常 + 修复）。
  3. **输出**：上下文感知的、修复后的干净表格。
- **形式化要点**：核心是「实时 OFD 抽取 + 基于规则的检测/修复」；🔧 具体 OFD 定义与抽取算法查原文。
- **理论性质/保证**：论文以实验为主，给出检测/修复准确率提升（🔧 理论分析查原文）。
