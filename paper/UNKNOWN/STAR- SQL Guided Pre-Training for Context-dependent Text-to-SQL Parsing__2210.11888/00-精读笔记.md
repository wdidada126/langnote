## 一句话总结
做多轮「对话式 Text-to-SQL」时，同一张表会在多轮里被反复引用，STAR 用两个预训练任务——追踪「每轮后表结构状态变了什么（SST）」和「把语义相近的问句拉近、相远的分开（UDT）」——来让模型更懂上下文，并在 SParC、CoSQL 上拿到 SOTA、登顶榜单。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：Text-to-SQL 把自然语言转成 SQL。context-dependent（上下文相关）指多轮对话场景——用户后一轮的问题依赖前几轮（例：第一轮「显示销量最高的产品」，第二轮「只要 2020 年的」）。模型必须理解「上下文状态」与「问句间依赖」。
- 为什么难：
  - 对话里大量省略/指代（代词、「它」「这个」「再按价格排」）要靠历史推断；
  - 表结构（schema）随轮次被逐步筛选/限定，状态在演化；
  - 问句之间语义有强相关（同义改写、追问），也有干扰项。
- 几类主流解法：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 端到端序列模型 | RAT-SQL、RESNET 系 | 把 schema + 问句喂给模型直接解码 SQL | 强但单轮为主，多轮靠拼接历史 |
| 预训练语言模型微调 | BERT/GPT 系 + 表格预训练 | 在大规模语料上先学表格/文本表示 | 表示强，但少显式建模对话状态 |
| 上下文/对话状态建模 | 历史拼接、对话状态追踪 | 显式维护多轮上下文 | 更懂依赖，但常需专门设计 |

- 本文属于哪一类：「预训练 + 显式上下文状态」路线——在预训练阶段就注入 schema 状态追踪与问句依赖建模。
- 2-3 个必懂关键名词：
  - schema state（表结构状态）：某一轮过后，SQL 对表列的选定/过滤情况（哪些列被用、哪些值被限定）。
  - contrastive learning（对比学习）：把「语义相似」的样本拉近、「不相似」的推远，从而学到更鲁棒的表示。
  - context-dependent Text-to-SQL：多轮对话式的自然语言转 SQL，典型数据集 SParC、CoSQL。

## 1. 问题背景与动机
- 前人工作简述：已有预训练（如 TaBERT、GAP 等）多面向单轮 text-to-SQL；多轮方法常简单拼接历史或加注意力，缺少对「上下文状态演化」与「问句间语义依赖」的专门建模。
- 前人缺陷/未解决问题（逐条）：
  1. 忽略 schema 状态随轮次演化：前面轮次对表的筛选没有被显式表示和传递。
  2. 未显式建模问句间语义依赖：同义追问、干扰问句没被区分。
  3. 缺高质量多轮对话语料做预训练：可用的大规模 context-dependent 语料不足。
  4. 表示易混淆：相关/不相关问句的表示若拉不开，模型在长对话里容易跑偏。

## 2. 核心方法
- 最直观类比：像秘书记笔记——每聊一轮就更新「当前筛选条件清单」（SST），并把意思相近的提问归到一类便于复用（UDT）。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：多轮 Text-to-SQL 对话（每轮含自然语言 utterance + 对应 SQL）。
  2. 关键操作一：构建语料。论文构造了一个高质量、大规模的 context-dependent Text-to-SQL 对话语料用于预训练。
  3. 关键操作二：Schema State Tracking (SST) 目标。把上下文相关 SQL 的 schema 状态表示成 schema-states，通过预测并更新每个 schema slot 的值，来追踪和探索对话中的 schema 状态变化。
  4. 关键操作三：Utterance Dependency Tracking (UDT) 目标。采用加权对比学习（weighted contrastive learning），在同一对话内把语义相似的 NL utterance 拉近、把不相似的推远。
  5. 输出：预训练好的 STAR 模型（含参数与 checkpoint），微调后用于下游多轮解析。
- 形式化要点：SST 以 schema slot 为单位进行状态预测/更新；UDT 用加权对比损失对齐语义表示。超参数含对比学习权重/温度（🔧 具体值请查正文）。
- 理论性质/保证：无显式理论保证，以经验性 SOTA 为主。🔧 损失函数与训练细节以论文原文为准。
