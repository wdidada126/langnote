## 一句话总结
真实场景里的 Text-to-SQL 解析器既要**泛化**（同分布、零样本、组合泛化三个层次都要能扛），又要**鲁棒**（问题换个说法也不能崩）。以往工作往往只解决其中某一条。本文提出 TKK 框架，把学习过程拆成**任务分解（Task decomposition）→ 知识获取（Knowledge acquisition）→ 知识组合（Knowledge composition）**三个阶段分阶段学习，让模型学到的是通用的 SQL 知识而不是表面的虚假规律（spurious patterns），最终在 Spider、SParC、CoSQL 上取得当时最优表现。

## 1. 问题背景与动机
- 前人工作简述：Text-to-SQL parsing 研究众多，从端到端生成到中间表示、从图编码到预训练微调，评测主要集中在 Spider 等基准；鲁棒性方向也有专门工作（如同义词替换鲁棒性研究）。
- 前人的缺陷 / 未解决问题（逐条）：
  1. **只解决单一挑战**：大多数已有工作只针对**某一个**特定的泛化或鲁棒性挑战，缺少综合视角。
  2. **泛化层次覆盖不全**：没有把 i.i.d.、zero-shot、compositional 三层放在一起系统性地提升。
  3. **鲁棒性研究零散**：针对输入扰动的工作与针对泛化的工作各做各的。
  4. **模型易学虚假规律**：端到端训练容易让模型捕获 spurious patterns 而非通用 SQL 知识，这是泛化失败的根源。

## 2. 核心方法
- **最直观类比**：学外语时，一口气背整段对话（端到端）很容易「背熟了课本、换个场景就懵」；TKK 像一套分阶段教材：先**拆**成语法点（任务分解），再**逐个**把语法点练扎实（知识获取），最后**练把语法点组合起来**说新句子（知识组合）。这样学到的是规则本身，而不是课本里的句子。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：Training 用的 Text-to-SQL 数据（问题 + schema + SQL）+ 一个待训练解析器。
  2. **关键操作一：Task decomposition（任务分解）**。把 Text-to-SQL 的学习任务拆成多个可分别攻克的阶段/子任务。
  3. **关键操作二：Knowledge acquisition（知识获取）**。在各个阶段分别获取相应的知识（使模型学到的是通用 SQL 知识，而不是虚假规律）。
  4. **关键操作三：Knowledge composition（知识组合）**。把各阶段学到的知识组合起来用于完整的解析任务。
  5. **输出**：一个在三层泛化与鲁棒性上都更强的 Text-to-SQL 解析器。
- **形式化要点**：核心是「分阶段学习课程（staged learning）」的设计——阶段如何切分、每阶段学什么、如何组合；超参数包括阶段划分方式与组合策略 🔧 具体见原论文。
- **理论性质 / 保证**：🔧 摘要未给出理论保证（论文以实证为主）；可确认的设计目标是让模型「**获取通用 SQL 知识而非捕获虚假规律**」。

## 7. 2026 视角（🔧）
- LLM 时代，Text-to-SQL 的绝对精度被大模型大幅推高，但**泛化与鲁棒性问题并未消失**：换库、换措辞、换数据模型依然会让系统出错。
- 「分阶段学习」在大模型语境下演化为「分步骤提示/分解式 prompting」与「先骨架后细节」的生成策略——思想与 TKK 一脉相承。
- 更重要的是本文的评测观：**不要只报一个总分**，要分别报告 i.i.d. / zero-shot / compositional / 扰动下的表现。这已成为领域的共识做法。本节为趋势性判断 🔧。

## 8. 新手学习路线
- **10 分钟**：读摘要 + 第 0 节，记住 TKK 三个字母各代表什么，以及「三层泛化 + 鲁棒性」这个四象限。
- **30 分钟**：从 Spider 里挑 10 条样本，手工把问题做同义词替换，看看你熟悉的模型会不会答错——先建立「鲁棒性真的会崩」的直观感受。
- **进阶**：精读 TKK 的阶段划分与组合策略；对照 Dr.Spider 做一次系统的扰动评测；思考在 LLM 时代，这套「分阶段学」应该如何改造成「分阶段提示」。
