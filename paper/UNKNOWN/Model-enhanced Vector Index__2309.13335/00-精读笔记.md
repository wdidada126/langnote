## 一句话总结
稠密向量检索（embedding-based）快且能更新，但模型质量有天花板；纯深度生成检索（生成文档 id）质量高却被「长序列解码慢、无法增量更新文档」卡住。MEVI 用一套可微的模型增强索引：先用残差量化（RQ）码本把「深度生成」和「向量检索」桥接起来，先把查询解成少量「语义虚拟簇 id」，再在簇内用成熟向量做细粒度精搜——在 MSMARCO / Natural Questions 上更好，且服务延迟与稠密检索相当。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：向量检索（embedding-based retrieval）把文档/查询编码成向量，建索引后按相似度找最相近文档，因低延迟、不错召回而被广泛用于文档检索。但还有一类深度生成检索（deep generative retrieval），直接由模型「生成」文档 id，模型质量更高。
- 为什么难：深度生成检索有两个硬伤——（1）要一步步解码出唯一文档 id，服务延迟不可接受；（2）文档增删时难更新。稠密检索则受限于表示能力。
- 几类主流解法（表格）：

| 路线 | 直觉 | 代表 |
|------|------|------|
| 稠密/向量检索 | 向量近邻搜索 | FAISS、HNSW、CAGRA |
| 深度生成检索 | 模型直接生成文档 id | DSI 等 generative retrieval |
| 本文：模型增强索引 | 深度模型 + 向量索引桥接，兼顾质量与效率 | MEVI |

- 本文属于：把深度检索的「可微优势」注入向量索引，兼顾质量与可服务性。
- 关键名词直觉：
  - 残差量化（Residual Quantization, RQ）码本：把向量逐级量化成「码本索引序列」，可用来给文档编「语义 id」。
  - twin-tower（双塔）表示模型：查询塔 + 文档塔分别编码，产出可比较的向量。
  - 虚拟簇 id（virtual cluster id）：先粗定位到的「候选文档群」的语义标签，缩小精搜范围。

## 1. 问题背景与动机
- 前人工作简述：向量检索靠 embedding 索引，低延迟、可增删文档；深度生成检索质量更高但延迟高、不支持文档更新。
- 前人的缺陷/未解决问题（逐条）：
  1. 深度生成检索服务延迟不可接受（长序列逐步解码唯一文档 id）。
  2. 深度生成检索难以支持文档更新（id 空间变动）。
  3. 稠密检索表示能力受限，模型质量不如深度检索。

## 2. 核心方法
- 最直观类比：找人时，与其报出「身份证完整号码」（慢且字典一变就失效），不如先说「他在 3 号楼 2 层」（少量语义簇 id），再到那一层按相片（向量）细找——MEVI 就是「先生成粗簇 id，再簇内向量精搜」。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：查询（及文档集）。
  2. 关键操作：
     - 用 twin-tower 表示模型做基础编码；
     - 用 RQ 码本桥接「序列到序列深度检索」与「embedding 模型」，使索引可微；
     - 为大幅降延迟：不用长序列解码唯一文档 id，而是先用少量步数生成候选文档的若干语义虚拟簇 id，再借助成熟的 embedding 向量在候选簇内做细粒度精搜。
  3. 输出：相关文档（兼顾质量与低延迟）。
- 形式化要点：核心是「RQ 码本桥接 + 虚拟簇粗定位 + 向量细搜」的两段式可微索引。
- 理论性质/保证：以实证为主，无形式化最优性保证。
