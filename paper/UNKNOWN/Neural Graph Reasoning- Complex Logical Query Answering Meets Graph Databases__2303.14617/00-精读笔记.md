## 一句话总结
这是一篇把「复杂逻辑查询回答（CLQA）」和「图数据库」缝合起来的综述：先系统梳理多跳逻辑推理的研究谱系，再提出「神经图数据库（NGDB）」概念——用神经网络把图存成可学习的存储 + 会做查询规划执行的引擎，既能统一建模多模态特征，又能在图不完整时照样答出东西。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：传统图数据库（如 Neo4j）靠精确匹配回答查询；但真实图往往不完整，且查询可能是「A 的朋友里谁既在 X 又在 Y」这种多跳逻辑组合。CLQA 研究如何在可能不完整的图上做这种复杂逻辑推理。
- 为什么难：多跳 + 逻辑算子（交/并/非/存在）组合爆炸；图缺边时传统 DB 直接答不出。
- 几类主流解法：

| 方法 | 思路 | 优缺点 |
|------|------|--------|
| 符号图查询 | 精确匹配 | 准但怕缺边 |
| 嵌入法（KGE） | 把图嵌到低维再算 | 能抗缺边但难组合逻辑 |
| 神经图数据库（本文） | 学习式存储+引擎 | 灵活但复杂 |

- 本文属哪类：综述 + 新概念提案（Neural Graph Databases）。
- 2-3 个必懂关键名词：
  - CLQA（Complex Logical Query Answering）：多跳 + 逻辑组合的答案推理。
  - NGDB（Neural Graph Database，神经图数据库）：由神经图存储 + 神经查询引擎组成。
  - latent embedding store（隐空间嵌入存储）：把图信息压进向量，统一建模多模态特征。

## 1. 问题背景与动机
- 前人工作简述：CLQA 是图机器学习里新兴任务，社区已有一批工作沿理论与系统两条线扩展。
- 前人缺陷/未解决问题（逐条）：
  1. 缺乏统一 taxonomy：已有工作零散，缺少从图类型/建模/查询类型/数据集/指标多角度的系统分类。
  2. 传统图 DB 抗缺边能力差：图不完整时传统 DB 无法恢复答案。
  3. 多模态特征建模不统一：不同模态（文本/数值/结构）难以在同一框架表达。

## 2. 核心方法
- 最直观类比：传统图数据库像「死记硬背的通讯录」，缺一条记录就查不到；神经图数据库像「会推理的秘书」，即使通讯录不全，也能根据已知关系猜出答案，还能把照片、备注一起记。
- 具体做法（输入 → 关键操作 → 输出）：
  1. Neural Graph Storage（神经图存储）：图存储 + 特征存储 + 用编码器把信息嵌成 latent embedding 存起来。
  2. Neural Query Engine（神经查询引擎）：给定查询，学会做查询规划与执行，和存储交互取回正确结果。
  - 输出：复杂逻辑查询的答案集合。
- 形式化要点：NGDB = 存储（图/特征/嵌入三件套）+ 引擎（规划+执行）；核心创新是「学习式存储 + 查询驱动执行」（🔧 架构细节以论文为准）。
- 理论性质/保证：综述性质，无单一理论保证；提出方向与未解问题清单。
