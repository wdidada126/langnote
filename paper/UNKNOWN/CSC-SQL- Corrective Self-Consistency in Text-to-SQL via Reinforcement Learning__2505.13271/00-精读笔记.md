## 一句话总结
Text-to-SQL 里，多数投票（Self-Consistency）可能选平庸答案，自我纠错（Self-Correction）常常只修语法——CSC-SQL 把两者合并：选出两个最高频的 SQL 候选喂给「合并修订模型」做纠错，再用强化学习（GRPO）把生成和修订两个模型一起练强。

## 0. 给新手的阅读前置（背景知识地图）

**子方向解决什么大问题**：**Text-to-SQL** = 把自然语言问题（「上季度销售额最高的三个品类？」）翻译成可执行的 SQL。LLM 时代这个任务 Accuracy 已很高，但难题变成了**如何榨干模型的最后几个点**——尤其是测试时的算力换准确率。

**为什么难**：
- 单次生成容易在小错误上翻车（列名、JOIN 条件、聚合边界）；
- 推理时的增强手段各有盲区（见下表）。

**几类主流解法**：

| 路线 | 代表 | 缺陷 |
|------|------|------|
| Self-Consistency（自洽） | 同一问题并行采样 N 次，**多数投票**选众数答案 | 众数未必是最优——「平庸但高频」的答案可能赢 |
| Self-Correction（自纠错） | 让模型回头检查并修改自己的输出 | 实践中往往只抓到**语法错误**，语义/逻辑错误难自察 |
| 强化学习微调 | 用可执行结果等奖励做 RL | 奖励设计与训练稳定性是门槛 |
| **本文：两者融合 + RL（CSC-SQL）** | 双候选合并修订 + GRPO | — |

**本文属哪类**：推理时扩展（test-time scaling）× 强化学习微调的交叉路线。

**关键名词直觉解释**：
- **Self-Consistency（SC）**：一道题让模型答 20 遍，得票最多的答案胜出——利用「正确答案往往收敛」的统计直觉；
- **GRPO（Group Relative Policy Optimization）**：DeepSeek 提出的 RL 算法——对同一题采样一组答案，以组内相对优势（比组平均好多少）作为奖励信号训练，免去训练一个庞大的价值网络；
- **合并修订（merge revision）**：把两个候选 SQL 的差异（比如两处不同的 WHERE 条件）交给一个修订模型「取长补短」，而不是从头重写。

## 1. 问题背景与动机
- 前人工作简述：LLM 在把自然语言问题转成 SQL 上已很强；Self-Consistency 与 Self-Correction 这类**测试时扩展**技术可通过增加推理算力提升 SQL 生成准确率。
- 前人缺陷（摘要明示，逐条）：
  1. **Self-Consistency**：多数投票后选出的可能是**次优输出**（suboptimal）——高频 ≠ 正确；
  2. **Self-Correction**：通常只能处理**语法层面**的错误，对语义/逻辑错误无能为力；
  3. 两条路线各自为战，没有一套「投票选优 + 交叉修订 + 强化学习」的整合机制。

## 2. 核心方法
- **最直观类比**：考试后对答案。别人是「全班投票选人数最多的答案」（可能全错）或「自己检查一遍」（查不出自己的盲区）。CSC-SQL 的做法：让两个成绩最好（得票最高的两个答案）的同学**互相比对卷子**，把两份答案的分歧点交给一位「修订老师」裁断合并；而这位老师和答题的同学，平时都用「对答案得分」的方式反复训练（RL）。
- **具体做法（输入→关键操作→输出）**：
  - 输入：自然语言问题 + 数据库 schema；
  - 关键操作：
    1. **并行采样**：对同一问题并行采样多个 SQL；
    2. **双候选选择**：挑出**出现频率最高的两个**输出（而非只取众数）；
    3. **合并修订**：将两个候选喂入**合并修订模型（merge revision model）**做纠错/融合；
    4. **GRPO 强化学习**：用 GRPO 同时微调 **SQL 生成模型**与**修订模型**，显著提升输出质量；
  - 输出：修订后的最终 SQL。
- **形式化要点**：GRPO 的组内相对奖励优化（策略以组平均表现为基线）🔧 公式与奖励设计（是否用执行结果奖励）查原文后补。
- **理论性质**：无新理论保证；贡献在于组合设计与 RL 训练的工程有效性。
