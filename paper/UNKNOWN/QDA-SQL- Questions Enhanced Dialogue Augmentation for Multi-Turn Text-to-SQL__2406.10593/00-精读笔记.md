## 一句话总结
微调 LLM 做 Text-to-SQL 很有效，但多轮对话里常有歧义或答不了的问题。QDA-SQL 用 LLM 自动生成多种类型的多轮问答对来做数据增广，并加入「校验+纠正」机制，让微调后的模型 SQL 更准、也更会处理复杂/不可答问题。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：Text-to-SQL 微调 LLM 效果好，但真实场景多是多轮对话（用户追问、澄清、改需求）。多轮里问题常含糊或根本答不了，模型容易翻车。
- 为什么难：多轮上下文依赖强；歧义/不可答问题若直接生成 SQL 会出错；高质量多轮训练数据稀缺。
- 几类主流解法：

| 方法 | 思路 | 优缺点 |
|------|------|--------|
| 单轮微调 | 标准 SFT | 简单但弱多轮 |
| 多轮数据增广 | QDA-SQL | 补多轮样本+纠错 |
| 对话自玩 | Self-Play | 自动造对话 |

- 本文属哪类：面向多轮 Text-to-SQL 的数据增广（data augmentation）方法。
- 2-3 个必懂关键名词（直觉解释）：
  - Multi-Turn Text-to-SQL（多轮文本转 SQL）：在连续对话上下文中把每轮问题转成 SQL。
  - Data Augmentation（数据增广）：用模型/规则造更多训练样本，提升泛化。
  - Unanswerable questions（不可答问题）：对话里数据库无法回答的提问，需要模型识别而非硬编 SQL。

## 1. 问题背景与动机
- 前人工作简述：微调 LLM 在特定领域 Text-to-SQL 很成功，但多轮场景因歧义/不可答问题而困难。
- 前人缺陷/未解决问题（逐条）：
  1. 多轮问题复杂：歧义、不可答、上下文依赖让微调模型易出错。
  2. 缺多样训练数据：覆盖多类型问题的多轮样本不足。
  3. 无校验/纠正机制：生成的多轮样本质量参差不齐，直接训会带噪。

## 2. 核心方法
- 最直观类比：像给客服新人做「情景演练」——不仅生成各种正常对话，还特意造「听不清（歧义）」「这问题我答不了（不可答）」的对话，并且每次演练后都有「复盘校验」纠正错误，练出来的新人更稳。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 多类型问答对生成：用 LLM 生成多种类型的多轮 Q&A 对（含歧义/不可答等）。
  2. 校验+纠正机制（validation and correction）：在生成流程中引入校验与纠正，处理复杂多轮问题。
  3. 微调增强：用增广数据微调模型，提升 SQL 准确率与处理复杂/不可答问题的能力。
  - 输出：更鲁棒的多轮 Text-to-SQL 微调模型 + 开源生成脚本与测试集。
- 形式化要点：核心是「问题增强的多轮对话增广 + 校验纠正」；超参为生成类型分布与纠正轮数（🔧 见原论文）。
- 理论性质/保证：以实证为主。
