## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：Data Discovery（数据发现）是数据治理/数据湖里的关键能力——在成千上万张表组成的湖里，找到「能回答我这个问题」的表或字段。
- 为什么难：主流系统（Google Datasets、各类开放数据门户）只支持关键词搜索，答不了复杂语义问题；而让模型学会「问题 → 相关表」需要大量人工标注的训练数据，代价高。
- 几类主流解法：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 关键词搜索 | Google Datasets、开放门户 | 字符串匹配 | 简单但答不了语义问题 |
| 表嵌入检索 | 表/字段向量化 | 语义相似召回 | 需标注训练数据 |
| 自监督/合成数据 | Solo | 自动造训练样本 | 免标注但需设计合成策略 |

- 本文属哪类：自监督数据发现——核心是把「造训练数据」这一步自动化。
- 2-3 个必懂关键名词：
  - Data Discovery（数据发现）：从数据目录/湖中检索出与用户需求相关的数据集或字段。
  - Self-supervised（自监督）：不靠人工标注，而是用算法自动生成「问题-答案」训练对。
  - Relevance Model（相关性模型）：判断某个表/字段是否真能回答用户问题的打分模型。

## 1. 问题背景与动机
- 前人工作简述：已部署的数据发现系统多为关键词搜索；少量 learned 方法能理解语义，但依赖昂贵标注。
- 前人缺陷/未解决问题（逐条）：
  1. 只支持关键词：通用受众友好，但无法回答自然语言问题。
  2. 训练数据昂贵：learned discovery 系统需要人工收集训练数据，限制了实用性。
  3. 端到端缺位：已有方法没把「自监督造数据 + 表表示 + 相关性模型」完整串起来。

## 2. 核心方法
- 最直观类比：与其请人给每道题配标准答案（贵），不如让系统自己出题、自己批改，练出能理解问题的「阅卷老师」。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：数据湖中的大量表格。
  2. 自监督造数据：设计策略自动合成「自然语言问题」及其对应的「相关表」标签（🔧 合成策略细节见论文）。
  3. 表表示（table representation）：把表编码成适合模型的向量表示，喂给模型。
  4. 相关性模型：针对合成问题训练，能判断表与问题的相关度。
  5. 端到端整合为 Solo：三者结合，形成可回答 NL 问题的发现系统。
  - 输出：针对用户自然语言问题，返回相关表/字段。
- 形式化要点：要同时解决三个子问题——自监督策略、表表示、适配合成问题的相关性模型；核心超参在合成问题的方式与表编码器（🔧 见论文）。
- 理论性质/保证：无理论最优性保证；贡献在系统设计 + 实证超越 SOTA。
