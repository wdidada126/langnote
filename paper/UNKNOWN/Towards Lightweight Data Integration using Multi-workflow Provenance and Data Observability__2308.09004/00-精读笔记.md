## 一句话总结
科学发现常常要同时在超算、云和边缘上跑好几条工作流（训练、仿真、分析），但每条工作流各记各的日志，事后想「把这些数据合起来一起分析」几乎要靠人工拼；本文提出 **MIDA**，用「数据可观测性（data observability）+ 适配器 + provenance」在**不改动用户代码、不做插桩**的前提下，后台截获数据流，把领域数据、血缘和遥测数据在运行时汇入一个统一数据库，用户可以直接下查询做集成分析；实测在 Summit 超算上跑 **10 万个任务 / 1680 个 CPU 核、最高 276 块 GPU** 并行的真实材料科学分布式深度学习用例，开销接近零。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：现代科研不是「一个脚本跑一次」，而是多学科、跨设施（HPC 超算 + 云 + 边缘）协作，**多条工作流（multi-workflow）**同时跑。要回答的科学问题往往需要把这些工作流产生的数据合在一起看。
- **为什么难**：工具多（Dask、MLflow、各HPC 调度器……）、环境异构、数据格式与元数据口径不一；HPC 上还必须高效执行，不能为了记录把性能拖垮。
- **几类主流解法**：

| 方法 | 代表思路 | 优缺点 |
|------|---------|--------|
| 事后手工整合 | 人工导出日志、拼表 | 灵活但不可复现、不可扩展 |
| 插桩式 provenance 系统 | 要求用户在代码里显式调用记录 API | 语义准，但侵入性强、用户不愿改代码 |
| 工作流管理系统内置记录 | 绑定单一 WMS | 单工作流好用，跨系统/跨设施就断 |
| 数据可观测性 + 适配器（本文） | 后台截获数据流、按适配器解析并统一入库 | 轻量、非侵入，但依赖适配器覆盖度 |

- **本文属于哪一类**：**数据可观测性 + 适配器 + provenance** 的轻量运行时集成路线。
- **必懂关键名词**：
  - **provenance（数据血缘/溯源）**：数据是谁、在什么参数下、由哪一步产生的元信息；可复现性的基础。
  - **data observability（数据可观测性）**：不需要改代码，就在系统侧「看见」数据是怎么流动的（类比可观测性里的 tracing/metrics）。
  - **FAIR**：Findable, Accessible, Interoperable, Reusable——科研数据的治理目标。
  - **user steering（用户引导）**：让用户在运行时看到分析结果并据此调整实验走向。

## 1. 问题背景与动机
- 前人工作简述：provenance 系统和工作流管理系统（WMS）已能记录单条工作流的执行信息；数据集成研究也长期关注跨源对齐与清洗。
- 前人缺陷/未解决问题（逐条）：
  1. **跨设施割裂**：HPC 与云/边属不同世界，已有方案难以贯通 Edge-to-Cloud continuum。
  2. **多工具割裂**：Dask、MLflow 等并行系统与 ML 工具各自记录，口径不一致。
  3. **侵入性**：许多 provenance 方案要求用户对代码插桩（instrumentation），落地阻力大。
  4. **重**：为「记录」付出可观运行时开销，在 HPC 大规模并行下不可接受。
  5. **不可 steering**：数据往往事后才整合，无法在运行时支撑用户交互式引导。

## 2. 核心方法
- **最直观类比**：不是让每辆车（工作流）手写行车日志，而是在路上装摄像头和传感器（可观测性适配器），后台自动把车流汇总到一张实时地图（统一数据库）上。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：运行中的多条工作流（如 Dask 任务流 + MLflow 实验记录）产生的领域数据、provenance、遥测数据。
  2. **可观测性截获**：定义数据可观测性策略，通过**适配器（adapter）**在后台拦截数据流，**无需用户插桩**。
  3. **运行时集成**：把这些异构数据在运行期整合进**一个统一数据库**。
  4. **输出**：一个可直接下「user steering query」的集成数据视图。
- **形式化要点**：MIDA 定义 (a) 面向不同并行系统与机器学习工具的**可观测性策略**，(b) **适应性/适配方法（adaptability methods）**；摘要未给超参数 🔧。
- **理论性质/保证**：无理论保证；核心工程性质是「非侵入（no instrumentation）+ 近零开销（near-zero overhead）+ 运行时可用」。

## 5. 开源代码与动手实践
- 仓库地址：https://github.com/ornl/flowcept （占位符保留，ORNL 官方组织下的实现）
- 语言：🔧（同类系统多为 Python，以 README 为准）
- 典型流程（教学示意，以 README 为准 🔧）：
  ```bash
  # 1) 安装可观测性库
  pip install flowcept
  # 2) 在你的 Dask / MLflow 脚本外几乎不改代码地启用适配器
  # 3) 运行工作流，数据/血缘/遥测被后台截获写入统一数据库
  # 4) 对统一库下发 user steering query 做集成分析
  ```
- 许可与资源提醒：🔧 商用前确认 LICENSE；HPC 环境需确认调度器与存储权限，大规模运行前先在单机小规模验证开销。
