## 一句话总结

相似性哈希把数据点压成一串「指纹」（sketch），但现有索引大多只会搜二进制指纹、且不支持数据更新。DyFT 用一棵动态字典树（filter trie）同时搞定二进制与整数指纹的「可增删」相似搜索——在 2.16 亿点的真实数据集上比当时最强方法快约 6000 倍、内存只剩 1/13。

## 0. 给新手的阅读前置（背景知识地图）

子方向解决什么大问题：在海量数据里找「和查询对象最相似」的点（去重、近重复检测、聚类、推荐都靠它）。逐个算距离太慢，于是先用相似性保持哈希把每个点压成短指纹：相似的对象指纹也相似，只在指纹之间搜索即可。

为什么难：
- 传统哈希（MinHash、SimHash）只产出二进制指纹，距离就是汉明距离，索引方法成熟；
- 新一代哈希（如 consistent weighted sampling / GCWS）产出整数指纹以保持加权 Jaccard 等更丰富的相似度——但「整数指纹」之间的距离不再是简单汉明距离，现有二进制指纹索引要么不适用要么低效；
- 真实数据集是动态的（不断插入新数据），而多数索引方法只支持静态构建或更新代价高。

几类主流解法：

| 路线 | 代表 | 直觉 |
|------|------|------|
| 分块多索引哈希 | HmSearch、GV（Gog & Venturini） | 把指纹切成若干块，按块建倒排，查询时分块枚举候选 |
| 空间划分树 | 本文 DyFT | 把指纹按前缀组织成字典树，天然支持动态插入 |
| 图/量化索引（向量检索侧） | HNSW、PQ 等 | 面向原始向量，不针对 sketch 的离散距离 |

本文属哪类：第 2 类——动态树形索引，是首个同时支持二进制与整数 sketch、且支持动态更新的方法。

关键名词直觉解释：
- Sketch（草图/指纹）：数据点的压缩表示，原始相似度被保留为指纹间的某个离散距离（汉明距离或其整数推广）。
- Filter（过滤器）：指纹的前缀片段。两串指纹距离不超过 r 的必要条件是它们至少共享某个近似的过滤器——先按过滤器粗筛，再做精确验证。
- Trie（字典树）：按符号逐位分支的树。DyFT 把「过滤器」当树的节点，插入删除像查字典一样只动局部。

## 1. 问题背景与动机

- 前人工作：相似性保持哈希研究已从二进制 sketch（SimHash、MinHash）演进到整数 sketch（如 GCWS，保持加权 Jaccard 相似度）。检索侧，HmSearch 用「多变量哈希」处理二进制 sketch；Gog & Venturini 提出针对整数 sketch 的多索引哈希。
- 前人的缺陷（本文逐条给出动机）：
  1. 面向二进制 sketch 为主：多数相似搜索方法为二进制 sketch 设计，对整数 sketch 不适用或低效；
  2. 静态假设：大多方法对动态数据集（随时间插入/更新）不适用或效率差，而现代真实数据集持续更新；
  3. 可扩展性瓶颈：对超大（上亿点）数据集，现有方法的内存与查询时间都难以承受。

---

## 2. 核心方法

- 最直观类比：图书馆不是按书的全文排架，而是按书名前缀排。想找「书名和某本只差几个字」的书，顺着前缀走、在可能的分叉附近翻找即可；新书随时插进对应位置，不用重排整馆。
- 具体做法（输入 → 关键操作 → 输出）：
  - 输入：一批整数（或二进制）sketch + 查询 sketch + 半径 r；
  - 关键操作 1（过滤器）：把 sketch 划分成若干段，段值作为过滤器；距离不超过 r 的两个 sketch 必然在若干过滤器上「近似相等」——以此作为剪枝的必要条件；
  - 关键操作 2（动态 trie）：把过滤器组织成一棵 trie（树节点对应过滤器），数据点挂在叶子；插入 = 沿树下行、必要时分裂节点，因此天然支持动态更新；论文还给出多种节点表示（MART、ART、数组）以平衡内存与速度；
  - 输出：所有与查询距离 ≤ r 的 sketch（range search），查询时按过滤器枚举候选、再逐一精确验证。
- 形式化要点：核心是一条剪枝引理——若两 sketch 距离 ≤ r，则它们在特定划分下的若干过滤器组合必然「匹配」（🔧 精确引理表述与块数公式查原论文；官方代码中 DyFT+ 变体的块数按 ⌊r/2⌋+1 取值）。
- 理论性质：剪枝保证无漏报（不漏掉真实近邻），即该方法是过滤-验证框架下的精确 range search，而非概率性 ANN（🔧 定理编号与证明细节查原文）。

## 3. 变体 / 工程版

- DyFT 多种节点表示（官方仓库实测列出）：`mart_index`（MART 表示）、`art_index`（ART 自适应基数树表示）、`array_index`（数组表示）；
- DyFT+（multi-index 变体）：`mi_frame<T>` 包装任意 DyFT 实现，用多套索引分块降低候选量；
- 仓库同时实现了对比基线：HmSearch 的 1-var（HSV）与 1-del-var（HSD）版本、GV 多索引哈希（`gv_index`）。

## 4. 实验结论（概览）

- 对比基线：HmSearch（HSV/HSD，二进制/整数 sketch 的多变量哈希代表）、GV 多索引哈希（Gog & Venturini）。
- 数据集：大规模真实数据集（如经 SimHash/GCWS 生成的 sketch；官方仓库提供 SIFT、MNIST 衍生的小型示例数据）。
- 指标：查询时间、索引构建时间、内存占用、可扩展性（随数据量增长）。
- 结论方向（摘要已明示）：DyFT 在可扩展性、时间性能、内存效率上全面占优——在 2.16 亿点的超大数据集上，相似搜索比当时最强方法快约 6000 倍、内存降至 1/13。
- 🔧 各数据集上的精确耗时/内存曲线查原论文第 VI 节后补。

## 5. 开源代码与动手实践

- 仓库：https://github.com/kampersanda/dyft ，语言 C++17（需 g++ ≥ 7.0 或 clang ≥ 4.0），依赖 CMake ≥ 3.0 与 Boost ≥ 1.42。
- 典型流程（教学示意，以 README 为准 🔧）：
  1. `cmake .. && make -j` 编译，可执行文件落在 `build/bin`；
  2. 准备数据：二进制 sketch 为 64 位二进制格式（可用 `src/simhash.cpp` 按 Charikar's SimHash 生成）；整数 sketch 用 TEXMEX 的 bvecs 格式（可用作者的 consistent_weighted_sampling 仓库按 GCWS 生成）；
  3. 跑 range search 基准：`./bin/range_search_int_dyft data/mnist.scale.cws.bvecs ... -R 4 -N 64 -B 4 -A art -K 3`（-A 选节点表示，-K 选块数）；
  4. 跑构建/插入基准：`./bin/build_index_int_dyft ...`（逐条插入并按数量级报告统计）。
- 许可与资源提醒：MIT License（README 明示）；含作者自带的命令行解析与 tinyformat 头文件依赖；数据格式有严格要求（bvecs），新手建议先用仓库 `data/` 目录自带的 10K/1K 级小数据上手。

## 7. 2026 视角（🔧）

- 主流向量检索（FAISS、HNSW 图索引、量化压缩）处理的是原始向量与欧氏/内积距离；sketch 侧方法的价值集中在离散相似度（加权 Jaccard、编辑距离类）场景——文本近重复检测、实体对齐、集合相似性连接等。
- 动态性如今是共识需求：流式入库、增量更新成了向量数据库（Milvus、Qdrant 等）的标配能力，DyFT 这类「索引结构原生支持插入」的设计思路与这一趋势同向。
- sketch 路线在工业界的典型落点仍是去重/阻塞（blocking）预处理阶段，与精确向量检索互补而非替代。
