## 一句话总结
为了让 Text-to-SQL 模型真正「跨数据库通用」，SADGA 把自然语言问题和数据库 schema 都用「图」来表达，再用一套「结构感知的双图聚合」学会问题与表/列之间的对应关系，撰写时拿到 Spider 榜第三。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：跨域 Text-to-SQL 的核心难点是——训练过的模型要能套到「从没见过的数据库结构」上。关键在两件事：(i) 怎么编码「问题+schema」；(ii) 怎么学「问题里的词」与「表/列」之间的链接。
- **为什么难**：不同数据库的表列命名天差地别；问题里的词可能对应多张表、多个列；结构信息（主外键、表间关系）传统序列化编码容易丢失。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 序列编码 | 早期 Seq2Seq | 把问题+schema 当序列 | 丢结构 |
| 图建模 | RAT-SQL、SADGA | 用图显式表达 schema 关系 | 链接更准、算力更贵 |
| 草图槽位 | RYANSQL、RESDSQL | 模板填空 | 结构可控 |
| 大模型 | 后续 LLM 系 | 直接生成 | 强但贵 |

- **本文属哪类**：图建模路线，强调「双图（问题图 + schema 图）聚合」。
- **2-3 个必懂关键名词**：
  - **Question-Schema Linking（问题-schema 链接）**：判断问题里哪些词指向哪张表/哪一列。
  - **Graph Aggregation（图聚合）**：在图上把邻居信息汇聚到节点，得到结构感知的表示。
  - **Cross-domain（跨域）**：测试库 schema 与训练库不重叠。

## 1. 问题背景与动机
- **前人工作简述**：Text-to-SQL 多用序列或简单注意力编码问题+schema，跨域泛化受限。
- **前人缺陷/未解决问题**：
  1. 编码方式对「问题」和「数据库 schema」缺乏统一的、结构感知的表达，泛化差。
  2. 问题-schema 链接方法未能充分利用 schema 内部的图结构（主外键、表列层级）。

## 2. 核心方法
- **最直观类比**：把「问题」和「数据库表结构」各画成一张关系网，再让两张网「对对联」——通过结构感知的聚合，弄清楚问题里的每个词该落到哪张表的哪一列。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：自然语言问题 + 数据库 schema。
  2. **关键操作**：
     - 用 **图结构** 为问题与 schema 提供统一编码模型（二者都建成图）。
     - 在统一建模之上，设计 **structure-aware aggregation（结构感知聚合）**，学习「问题图」与「schema 图」之间的映射。
     - 该方法含三件套：**Global Graph Linking（全局图链接）**、**Local Graph Linking（局部图链接）**、**Dual-Graph Aggregation Mechanism（双图聚合机制）**。
  3. **输出**：SQL（跨域）。
- **形式化要点**：以图神经网络式聚合捕获结构，双图交互得到链接表示；超参/层数见原论文 🔧。
- **理论性质/保证**：以经验为主，无严格理论保证（🔧 原文未强调）。
