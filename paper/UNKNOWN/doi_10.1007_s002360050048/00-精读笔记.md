## 一句话总结
LSM-tree 把「随机写」摊平成「顺序写 + 后台归并」：写先入内存有序组件 C0，满了顺序落盘成差量文件（run），后台周期性 k 路归并控制差量堆积——用「读稍慢、写极快」的权衡换来了廉价盘上的高写吞吐，是今天几乎所有写优化 KV 存储的骨架。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：磁盘时代「一次随机寻道约 10ms」，B-tree 原地更新每写一条都要多次随机 I/O；写密集负载被寻道彻底拖垮。
- **为什么难**：写要快，读也不能太慢，还要控制空间；三者互相拉扯。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 取舍 |
|------|------|------|------|
| 原地更新 B-tree | 传统 RDBMS | 点查 O(log) 快 | 写要多次随机 I/O，写吞吐差 |
| 纯日志/归档 | LFS 思路 | 写全顺序 | 读要扫全部历史 |
| LSM-tree | **O'Neil 等 1996** | 内存缓冲 + 顺序落盘 + 后台归并 | 写极快、读稍慢、空间需回收 |

- **本文属哪一类**：写优化存储结构（LSM 谱系源头）。
- **2-3 个必懂关键名词**：
  - **C0 / run（差量）**：C0 是内存里的有序缓冲；run 是落盘的一段按 key 有序的增删集（类比：便签 vs 印好的差量页）。
  - **compaction（归并）**：后台把多个 run 合并成一个，顺手清掉被删的旧值（类比：把几版草稿合并成正稿）。
  - **写放大 / 读放大 / 空间放大**：现代对 LSM 三难权衡的统称（原文用「吞吐/查询响应/实时性」三指标表述，名词是后人回读）。

## 1. 问题背景与动机
- 前人工作简述：B-tree 原地更新读友好但写残酷；纯日志写友好但读要全扫；Rosenblum/Ousterhout 的 LFS（日志结构文件系统）已提出「追加 + 后台清理」。
- 前人缺陷/未解决问题（逐条）：
  1. B-tree 每次插入/删除要触碰根到叶多页且物理散落，写密集下吞吐被寻道钉死。
  2. 纯日志查询必须扫历史，读不可接受。
  3. 缺一个能把「写转成顺序」又不让「读崩掉」的折中结构——这正是 LSM-tree 的定位。

## 2. 核心方法
- **最直观类比**：把数据库想成图书馆。B-tree 像「每改一个字就要把整本书对应页撕掉重印」（随机写很贵）；LSM 像「先在便签 C0 上记改动，便签写满就把这一叠差量顺序印成一册 run，后台图书管理员定期把几册差量合并成正稿」——绝大多数查询只看最新的几册，旧册只在合并时才碰。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. 输入：键值对的插入/删除。
  2. 关键操作：写先追 WAL（可选）→ 进 C0 内存有序表 → C0 写满顺序落盘成一个 run → 后台周期性把全部 run 做 k 路归并（新值覆盖旧值、墓碑屏蔽旧值）。
  3. 输出：一个内存 C0 + 磁盘 run 序列组成的键值结构，支持点查/范围查。
- **形式化要点**：论文用「插入吞吐 / 查询响应 / 实时性（最近 t 秒数据全在内存、故障只丢 t 秒）」三指标定价；多级推广 C0→C1→…→Cn 逐级几何增长，把每条记录重写次数控制在 O(层数)。
- **理论性质/保证**：实时性保证（C0 驻留时间决定最近写入可见性）；合并预算约束「merge 耗时 < t（C0 写满周期）」，否则写请求排队（即后来的 write stall）。

## 3. 变体 / 工程版（如有）
- 单级 C1（run 键域重叠）与多级 Cn（逐级键域不重叠）两种形态；现代 LevelDB/RocksDB 即「L0 重叠 + L1..Ln 不重叠、size ratio≈10」的工程化。
- 开源后继：LevelDB（2011，Google）、RocksDB（2012–，Facebook/Meta）——把本文骨架参数化、闪存化。

## 4. 实验结论（概览）
- 对比基线：参数化代价模型 + 模拟，对比 B-tree 与 LSM（含单级/多级）。
- 指标：插入吞吐 vs 内存预算、点查/范围查响应。
- 结论方向（定性，原笔记核实记录标注未逐字复核数字）：同等内存下 LSM 写吞吐高出 B-tree 约一个量级且不随内存缩小急剧恶化；代价是点查/范围查响应劣于 B-tree。🔧 精确数值请查原论文 Table/Figure 后补入。

## 7. 2026 视角（🔧）
- LSM 是写优化存储的默认答案：TiKV、CockroachDB、Cassandra、MyRocks、DynamoDB 底层均是其变体。
- 即便闪存时代，「随机页重写（含 GC/擦除）仍构成放大」，顺序化理由只是换了物理机制；compaction 的读/写/空间三放大仍是活跃研究方向（如 Monkey、Wacky、RUM Conjecture）。
- 新趋势：LSM 上湖（Paimon/Delta 用对象存储 + compaction 语义）、KV 分离、FPGA 卸载 compaction。具体 SOTA 🔧 查当年综述。

## 8. 新手学习路线
- **10 分钟**：读摘要 + 本笔记第 0、2 节，理解「C0 + run + 归并」与三放大直觉。
- **30 分钟**：用 LevelDB/RocksDB 写个 Put/Get 小程序，观察 SSTable 文件生成与 compaction 触发。
- **进阶**：读 Bigtable 与 RocksDB 笔记；推导「merge 耗时 < t」的 stall 临界条件；理解 Bloom filter 如何把点查探测降到内存位判定。
