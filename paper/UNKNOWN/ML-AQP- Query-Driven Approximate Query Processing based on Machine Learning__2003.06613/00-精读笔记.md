## 一句话总结
等精确聚合查询太慢又太贵？ML-AQP 用机器学习「记住房间答过哪些查询」，为新查询**估算**一个近似聚合答案——可以跑在分析师本机或作为服务，响应快、钱/算力/能耗都低，且能和云上分析系统配合。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：**近似查询处理（AQP, Approximate Query Processing）**针对「SELECT COUNT/SUM/AVG … GROUP BY」这类聚合查询，不扫全量数据，而是给出**足够好、极快**的近似答案。对大规模分析、交互式探索很有用。
- **为什么难**：要在「速度/成本」与「精度」间权衡；传统 AQP 多用采样/预计算，对多样查询的泛化有限。
- **几类主流解法**（表格）：

| 路线 | 直觉 | 代表 |
|------|------|------|
| 采样估计 | 对数据采样后估算 | 经典 AQP |
| 预计算/小波 | 预聚合加速 | 各类概要结构 |
| **本文：查询驱动 ML** | 从「已回答的查询」学模型估新查询 | ML-AQP |

- **本文属于**：用机器学习做查询驱动的 AQP，强调「利用历史查询知识」。
- **关键名词直觉**：
  - **AQP**：用近似换速度的聚合查询处理。
  - **查询驱动（query-driven）**：模型从「过去回答过的查询」中学规律，而非只从数据本身。
  - **轻量 ML 模型**：小而快的模型，可放本机/当服务，不必依赖重型云。

## 1. 问题背景与动机
- **前人工作简述**：组织越来越依赖数据驱动决策，大规模分析重要；但分析师常苦等精确结果，转向云厂商又面临成本上升。
- **前人的缺陷/未解决问题**（逐条）：
  1. 精确聚合查询**慢且贵**，云上成本随规模上升。
  2. 传统 AQP 对多样/历史查询利用不足。
  3. 缺少一种能**部署在本地/作为轻量服务**、低延迟低成本的近似方案。

## 2. 核心方法
- **最直观类比**：老会计不用每次重算总账，而是凭「以前算过的类似报表」快速估个八九不离十——ML-AQP 就是让模型从「历史查询答案」里学出这种估算直觉。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：历史已回答的查询及其结果 + 新查询。
  2. **关键操作**：利用**先前已回答查询**获得的知识，构建 **ML 模型**来估算新查询的结果；系统轻量，可存分析师本机或部署为服务。
  3. **输出**：新聚合查询的**近似答案**（低响应时间、低货币/计算/能耗成本）。
- **形式化要点**：核心是「查询驱动」地用历史查询训练估算模型，与云分析系统协同。
- **理论性质/保证**：以实证为主，无形式化保证。
