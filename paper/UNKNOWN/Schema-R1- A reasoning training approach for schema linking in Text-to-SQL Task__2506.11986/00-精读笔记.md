## 一句话总结
Text-to-SQL 里「先选对表/列」（schema linking）是成败关键。现有微调是「死记答案」式训练，推理能力弱。Schema-R1 改用「强化学习 + 推理样本」来训练 schema 链接模型，过滤准确率比已有方法提升 10%。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：Text-to-SQL 通常分两步——先 schema linking（根据问题预测要用哪些表/列），再生成 SQL。链接错了，SQL 必然错。
- 为什么难：表/列众多，问题措辞与字段名常不一致；微调模型若只「背答案」，遇到新表述就懵，缺乏真正推理。
- 几类主流解法：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 序列标注/分类 | 早期 linking | 直接预测列 | 快但缺推理 |
| 解耦生成 | RESDSQL | 先链接再骨架 | 结构清晰 |
| 强化学习推理 | 本文 Schema-R1 | RL + 推理样本 | 推理强但需样本 |

- 本文属哪类：用强化学习训练 schema linking 的推理能力。
- 2-3 个必懂关键名词：
  - Schema Linking（schema 链接）：预测问题所需的表名/列名。
  - Rote-learning（死记式学习）：只优化拟合 ground-truth，缺乏推理。
  - Reinforcement Learning（强化学习）：用奖励信号引导模型学习推理路径。

## 1. 问题背景与动机
- 前人工作简述：当前 schema linking 微调多采用「死记式（rote-learning）」范式，过度拟合 ground-truth 链接结果。
- 前人缺陷/未解决问题：
  1. 这种范式牺牲了模型的推理能力。
  2. 根因在于：为下游任务获取「高质量推理样本」很困难。

## 2. 核心方法
- 最直观类比：过去是让学生背标准答案（死记），考试换种问法就卡壳；本文改为「给少量带推理过程的例题 → 先监督热身 → 再用奖励机制（RL）逼出真正会推理的能力」。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：自然语言问题 + 数据库 schema。
  2. 关键操作（Schema-R1 三步）：
     - 构造小批量高质量推理样本。
     - 监督微调（SFT）做冷启动初始化。
     - 基于规则的强化学习（rule-based RL）训练。
  3. 输出：具备更强推理能力的 schema linking 模型。
- 形式化要点：以规则奖励引导推理路径学习；冷启动 + RL 两阶段。具体奖励函数/超参见原论文 🔧。
