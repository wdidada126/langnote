## 一句话总结
Codd 1970 把「数据的逻辑表示」从「物理存储结构（指针、链、访问路径）」中剥离出来：逻辑层只剩一种对象——关系（表），其语义是谓词的真值外延，其操作是封闭的关系代数，其语言是非过程化的；用户只说「要什么」，怎么做交给系统——这就是「数据独立性」的根基，也是 SQL 与今天一切关系数据库的源头。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：1960 年代末「大型共享数据库」靠层次/网络模型，数据的逻辑结构与物理存储（指针、链、记录顺序）暴露给用户，应用与存储耦合，schema 演化被物理布局锁死。
- 为什么难：要让多个用户、多套程序并发读同一份数据，且存储结构能自由演化而不改程序——这在导航式模型下几乎不可能。
- 几类主流解法（当时格局）：

| 方法 | 代表 | 思路 | 取舍 |
|------|------|------|------|
| 层次模型 | IBM IMS（1968） | 树 + 父子指针 | 导航快但耦合物理、难共享演化 |
| 网络模型 | CODASYL DBTG | 图 + 集合指针 | 灵活但仍暴露指针语义 |
| 关系模型（本文） | Codd 1970 | 表 + 谓词语义 + 非过程化语言 | 数据独立，但被疑「慢/不可实现」 |

- 本文属哪一类：数据库理论奠基（数据模型层）。
- 2-3 个必懂关键名词：
  - 关系（relation）：集合论中笛卡尔积的子集，即「无重复、无内部次序」的表；属性值取自「域」。
  - 数据独立性：物理独立性（改存储结构程序不变）+ 逻辑独立性（改 schema 少改程序）。
  - 非过程化（declarative）：用户描述「结果满足什么条件」，不描述「从哪条索引进、沿哪条链走」——优化器决策权由此产生。

## 1. 问题背景与动机
- 前人工作简述：层次/网络模型靠「用户带指针游走」获得性能；但程序正确性依赖「知道数据在磁盘上怎么串」，多程序共享时易不一致。
- 前人缺陷/未解决问题（逐条）：
  1. 数据依赖问题：应用逻辑与存储细节（指针/顺序/访问路径）耦合，改存储必改程序。
  2. 可共享性问题：导航式模型下，两个程序对「同一棵树」可能因持有不同指针路径而不一致。
  3. 非过程化语言可行性的空白：当时常识认为「检索必须告诉机器怎么取数」，声明式被视为学术空想。

## 2. 核心方法
- 最直观类比：把数据库想成「一组被断言为真的命题」（如「雇员 e 名为 n，在部门 d」）。你不需要知道这些命题写在哪个抽屉、按什么顺序排——你只管问「找出部门 d 里所有雇员」，系统自己决定怎么找。这就像图书管理员不要求你记住每本书在几号架，只让你说「要什么主题的书」。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：用户对「大型共享数据银行」的查询需求。
  2. 关键操作：① 用集合论与一阶谓词逻辑定义关系、域、元组；② 给每个关系配一个谓词（表 = 谓词的外延）；③ 定义封闭的关系运算（投影/选择/连接/并/差）；④ 主张非过程化数据子语言 + 两层数据独立（物理/逻辑）。
  3. 输出：一套数学严格、可形式化论证「查询能否表达、优化是否保义」的数据模型。
- 形式化要点：关系 = D1×…×Dn 的任意子集；禁止关系作域（即第一范式 1NF 原始表述）；信息单源原则（一切信息以表中值表示）；运算封闭性（查询结果仍是关系，可继续组合、定义视图）。
- 理论性质/保证：模型可被数学证明「语言能否表达某查询」（关系完备性，1972 续文补全）；优化保义的前提——语言不携带过程信息——由此确立。

## 3. 变体 / 工程版（如有）
- 本论文是模型提出；后续 Codd 1972（关系完备性）、1971/1979（完整性/空值）、1990《RM/V2》（部分放宽 1NF）逐步发展；工程实现由 System R/SEQUEL→SQL 完成。
- SQL 是「关系代数 + 元组演算」的工程混合体，并在多处偏离模型（重复行、NULL 三值逻辑、ORDER BY 带语义）。

## 4. 实验结论（概览）
- 本文为理论论文，无性能实验；其「结论」是逻辑论证而非测量。
- 论证结论方向：关系模型在「可共享性、数据独立、可形式化」上严格优于层次/网络模型；性能担忧交给「非过程化语言 + 优化器」解决。
- 历史验证（非本文实验）：SQL/DS(1982)、DB2(1983)、Oracle V2(1979) 相继商业化；2005 年后列存+向量化/编译执行彻底逆转「关系=慢」的判断。🔧 具体年份/数据以史料为准。

## 7. 2026 视角（🔧）
- Codd 的关系模型 + SQL 是过去 50 年数据库的默认心智；即便 NoSQL/NewSQL/湖仓兴起，对外 API 仍多为关系/SQL（TiDB/Spanner/CockroachDB 等）。
- 被反复修正处：1NF 禁令被对象关系/JSON 突破；SQL 不等于关系模型（Codd 生前屡批）；分布式/CAP 对「一张全局大表」假设施压，但接口抽象经受考验。
- 新趋势：AI 辅助 SQL、向量/多模态与关系融合、存算分离下的关系执行引擎重构。具体演进 🔧 查当年综述。

## 8. 新手学习路线
- 10 分钟：读摘要 + 本笔记第 0、2 节，理解「表 = 谓词外延」「用户只说要什么」。
- 30 分钟：对照 §2 用 `EMP`/`DEPT` 两表走一遍「非过程化查询 = 谓词存在量词」的演算，体会与 CODASYL `FIND...` 导航写法的本质差异。
- 进阶：读 System R 笔记看模型如何落地；思考「1NF 禁令为何 1970 被禁、今天为何放宽」；读 Neumann 2011 理解「关系慢」如何被证伪。
