## 一句话总结
LLM 做 Text-to-SQL 时，一次生成的 SQL 经常不是最好的。XiYan-SQL 的核心思想是**不要指望一次生成命中，而是「多生成、再挑优」**：先用 Schema Filter 筛出多套相关 schema，再用**多个生成器**产生一批**高质量且多样**的候选 SQL，最后用一个**带候选重组策略的选择模型**挑出最优解。为了让候选真正多样，作者用**多任务微调**增强模型的「SQL—文本」内在对齐能力，并通过在不同 SQL 格式上微调，造出风格各异的多个生成模型。结果：**BIRD 基准上 75.63% 的新 SOTA**，**Spider 测试集上 89.65% 的 SOTA**。

## 1. 问题背景与动机
- **前人工作简述**：LLM 具备很强的语义理解与代码生成能力，被广泛用于 Text-to-SQL。已有工作主要靠提示工程、微调、或多智能体协作来提点。
- **前人缺陷 / 未解决问题（逐条）**：
  1. **单次生成不可靠**：依赖一次生成命中，缺乏系统性的「多候选 + 选优」机制。
  2. **候选多样性不足**：同一模型多次采样的候选往往高度同质，「选了也白选」。
  3. **Schema 输入噪音**：把完整 schema 全塞进去，既浪费上下文又引入干扰。
  4. **模型缺少「SQL—文本」的内在对齐能力**：普通微调不足以让模型真正理解 SQL 结构与自然语言意图之间的对应。
  5. **缺少有效的选优模型**：即便有了多个候选，如何从中挑出最优 SQL 仍缺少成熟方案。

## 2. 核心方法
- **最直观类比**：写 SQL 像招标。XiYan-SQL 的流程是：**先确认招标范围（Schema Filter 筛出相关表）→ 请好几家风格不同的设计院各出一份方案（多生成器）→ 由一个评审委员会（选择模型）在把方案重新整理归类之后（候选重组）选出中标方案**。关键在于「设计院风格不同」——作者是**通过在不同 SQL 格式上分别微调**来刻意造出这种差异的。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：自然语言问句 + 数据库 schema。
  2. **组件一：Schema Filter（模式过滤模块）**。过滤并**获得多套相关的 schema（multiple relevant schemas）**，而不是只用一套。
  3. **组件二：多生成器集成（multi-generator ensemble）**。用多个生成器产出**高质量且多样（high-quality and diverse）**的候选 SQL。其实现要点有两条：
     - **多任务微调策略（multi-task fine-tuning strategy）**：用于增强 SQL 生成模型在「SQL 与文本之间的内在对齐（intrinsic alignment between SQL and text）」上的能力；
     - **用不同的 SQL 格式分别微调**，从而构造出**具有不同生成风格（distinct generation styles）**的多个生成模型。
  4. **组件三：选择模型（selection model）**。实现一个**带候选重组策略（candidate reorganization strategy）**的选择模型，用来**挑出最优 SQL 查询**。
  5. **输出**：最终选定的一条 SQL。
- **形式化要点**：
  - 三个组件的组合顺序：**过滤 → 多生成 → 选优**，是一个典型的 generate-then-rank 框架。
  - 关键设计变量：多套 schema 的数量、生成器的个数与各自对应的 SQL 格式、候选重组的具体规则；🔧 具体设置与超参见原论文。
- **理论性质 / 保证**：无论文层面的理论保证；论文强调 **effectiveness and robustness（有效性与鲁棒性）**，并给出全面的实验分析。

## 7. 2026 视角（🔧）
- 本文代表了 LLM 时代 Text-to-SQL 的一类主流工程范式：**把「一次生成」改造成「生成—排序/选择」的 pipeline**，并用微调把「多样性」变成可控变量。这个范式与推理模型（reasoning model）、强化学习（RL）路线并行存在，且经常被组合使用。
- 75.63%（BIRD）这样的数字在 2025 年属于第一梯队；今天榜单可能已经变化，但**「多生成器 + 选优」这一框架本身仍然通用**，且容易与更新的基座模型叠加。
- 近年趋势：把执行反馈（execution feedback）直接用作奖励做 RL、把选择模型换成「执行结果投票 + 语义校验」、以及把整个 pipeline 的成本（推理次数）作为优化目标。本节含趋势判断，最新榜单数字 🔧 需查当年公开评测。
