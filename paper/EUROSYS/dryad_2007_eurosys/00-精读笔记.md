# Dryad: Distributed Data-parallel Programs from Sequential Building Blocks — 精读笔记

> EuroSys 2007 · Isard, Budiu, Yu, Birrell, Isard（Microsoft Research，⚠️ 名单以原文为准）
> 三态标注：✅ 论文硬写事实 / ⚠️ 记忆或二手归纳 / 🔧 本地可复演实验

## 一、基本信息

| 项 | 内容 |
|---|---|
| 会议 | EuroSys 2007 |
| 定位 | 把任意数据并行计算表达为**有向图（顶点=进程，边=数据集）**，运行时自动布线容错——"比 MapReduce 更通用"的宣言书 |
| 后继 | CosmosScope ⚠️、与erna（Trill/Fluency）流式化 ⚠️；理念汇入 Spark DAG 与 Flink dataflow（⚠️） |

## 二、问题史：MapReduce 的两把锁

- MapReduce 只有"map→shuffle→reduce"两级骨架：迭代算法要外层脚本反复起作业；不规则 DAG（多输入 join、流水线）表达别扭（✅ 论文 §1 对照，作者明说 MR 是 Dryad 的受限特例）。
- 目标：用户交**顺序程序片段**（任意 .exe），Dryad 交**图拓扑**；分片、缓冲、重试、调度全归运行时（✅）。

## 三、编程模型

### 3.1 顶点、边与线格式

- 顶点：黑盒进程，多入多出；边=数据集，四种物理形态：文件/目录、**管道**（同机）、TCP 流、共享内存队列（✅ 四通道原文枚举）。
- 线格式（line format）：CSV/记录分隔自定义；分区四模式：File-per-partition / Directory / Blob / 自定义（⚠️ 术语凭记忆）。

### 3.2 关键抽象：控制器不控制

- 用户进程对"自己拿到第几分片"无感知——调度器按数据位置就近投放，失败重跑换分片输入即可（✅ 大意）。

## 四、运行时

- **JobGraph 提交 → 控制器展开虚拟边到物理拓扑 → 节点管理器**（每机一个）拉起进程、接线（✅）。
- 容错：进程退出码/超时判失败，重跑顶点；边数据可检查点（✅ 论文对 checkpoint 着墨浅 ⚠️）。
- 调度：以数据位置为轴的贪心+反压（边满阻塞上游）；与 VC/Scavenger 集群治理层对接（⚠️）。

## 五、评测（✅ 定性）

- 论文案例：页面规范化流水线（15+ 顶点混合 map/reduce/自定义节点）、层次聚类、近邻图——迭代与多分支场景 MR 需 N 个作业，Dryad 一个图（✅ 核心对比）。
- Sort 基准：与当时 Pangu 内部系统比吞吐持平或更优（⚠️ 数字凭图表）。

## 六、批判读法

- **容错粒度是顶点级全量重跑**：无 RDD 式血缘细粒度恢复，长 DAG 一个上游失败重刷一片——Spark  lineage 正是打这点（⚠️ 对照 [[rdd_2012_nsdi]]）。
- 无交互/内存复用抽象：迭代靠用户手工把中间数据落成"循环边"（DryadLINQ 的 fixed point 是编译层糖 ⚠️）。
- Microsoft 内部生态（DryadLINQ/Scope/Polar）从未真正开源，论文成了绝响文献；引用热度远不及同代 MR/Spark（✅ 事实，⚠️ 原因=生态而非技术）。
- 与 FlumeLite 绑定：数据流语言层论文另发（⚠️ 未建）。

## 七、🔧 本地微实验（非本书引擎行为）

1. **手搓图执行器**：JSON 描述 DAG（顶点=脚本、边=临时文件），拓扑排序+子进程调度，边满即阻塞（反压）。
2. **四通道对比**：同一 1GB 数据走"文件中转/本机管道/socket"三种接法，测总耗时。
3. **顶点重跑**：kill 中间顶点让其输出文件半截损坏，验证"下游未读前重算即可"的幂等要求。
4. **迭代回环**：用两顶点循环边模拟固定点（PageRank 3 轮），对比每轮重起"作业"的开销。
5. **近数据调度**：模拟数据分布不均的节点表，贪心就近投放 vs 轮询，计跨机流量。

## 十、最新演进与工业实践

- Dryad 本体随 Scope/Cosmos 演化进 Azure 分析栈，从未开源；学术叙事被 Spark DAG+lineage 接管（⚠️）。
- 通用 dataflow 思想活到今天：Beam/Dataflow 模型、Flink 作业图、Tez/DAG-on-YARN——"顶点黑盒+边数据集"已是行业默认语法（✅ 判断）。
- 2024–2026：流批一体（Naiad 的 timely dataflow 血统在 Materialize/Differential 中延续）回头看，Dryad 论文的"迭代与不规则图"命题才算真正关闭（⚠️ 判断）。
