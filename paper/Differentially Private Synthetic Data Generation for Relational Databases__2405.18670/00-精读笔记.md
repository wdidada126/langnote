## 一句话总结
以前几乎所有差分隐私（DP）合成数据方法都只针对「一张大宽表」，这篇论文给出了第一个能把**任意现成 DP 机制**组合起来、直接对**多表关系数据库**做合成数据生成的算法——合成的各表之间还能保持外键引用完整性（referential integrity）。

## 0. 给新手的阅读前置（背景知识地图）
- **大问题**：想在共享/发布数据时保护隐私（差分隐私是当前数学上最严格的主流定义），同时合成数据还得「像真数据」、能支撑统计分析和模型训练。单表场景已有大量工作（如各类 DP GAN、边际分布机制），但现实数据几乎都是**多表**的：订单表引用客户表、明细表引用订单表……
- **为什么难**：
  1. 多表之间的联合分布维度爆炸，直接学联合分布不可行；
  2. 合成出来的表必须满足**引用完整性**（外键真的能对上），否则像「假数据库」；
  3. DP 的隐私预算要分配到多张表 + 表间关系上，如何组合是开放问题。
- **主流解法分类（直觉）**：
  | 类别 | 思路 | 代表 |
  |------|------|------|
  | 单表 DP 生成 | 对一张表学 DP 分布再采样 | PATE-GAN、边际机制等 🔧 |
  | 拍平成主表 | 把关系库 join 成一张宽表再用单表法 | 本文批评的对象 |
  | 本文所属 | **机制无关的「关系层后处理」**：迭代修正合成表之间的关系，逼近低阶边际分布并保持引用完整性 | 本文 |
- **关键名词直觉**：
  - *差分隐私（DP）*：加一条记录或删一条记录，算法输出几乎不变——别人无法反推出「你在不在数据里」。
  - *低阶边际分布*：只看一两个列的联合统计（如「年龄段 × 是否购买」），是合成数据保真度的常用标尺。
  - *引用完整性*：子表外键的每个取值都必须在父表主键中真实存在。

## 1. 问题背景与动机
- **前人工作**：DP 合成数据机制（直方图/边际分布类、生成模型类如 DP-GAN 系 🔧）基本都假设「单一数据源、单张表」——这是摘要中作者明确点出的现状。
- **前人缺陷（逐条）**：
  1. **拍平损耗**：把关系库 flatten 成一张 master 表，空间开销大、高维稀疏，DP 噪声也更难对付；
  2. **无关系保证**：分别对每张表独立做 DP 生成，表间外键关系对不上，合成库不是合法关系库；
  3. **机制绑定**：多数方法是「一整套新机制」，无法复用已优化的单表 DP 机制。

## 2. 核心方法
- **最直观类比**：像「校对一本多人合写的书」——先各自写好每章（各表独立用现成 DP 机制生成），再反复对照情节是否连贯（表间关系），不一致就修订，直到「章节内的细节分布」和「章节间的引用关系」都尽量贴合原书。
- **输入→关键操作→输出**：
  - 输入：真实关系库 + 任选的现成 DP 机制 + 隐私预算；
  - 关键操作：**迭代精化（iterative refinement）**——反复调整各合成表之间的「关系」（外键/对应关系），最小化合成表在**低阶边际分布**上的逼近误差，同时**始终维持引用完整性**；
  - 输出：一张完整的 DP 合成关系数据库。
- **形式化要点**：算法定位为**可组合任意已有 DP 机制的元算法**；对低阶边际分布做近似误差最小化 🔧（精确的目标函数/误差界定义查原论文后补）。
- **理论性质/保证**：摘要明确给出两类保证——(1) 算法整体满足差分隐私；(2) 有理论效用（utility）保证。精确定理表述与界 🔧 查原论文后补。
