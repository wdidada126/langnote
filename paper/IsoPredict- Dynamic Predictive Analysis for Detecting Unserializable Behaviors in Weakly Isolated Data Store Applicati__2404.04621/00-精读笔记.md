## 一句话总结
IsoPredict 是首个针对「弱隔离级别数据存储上的应用」的动态预测分析工具：它从应用在一次**可串行化**执行中观察到的行为出发，利用 SMT 求解器推断「同样的操作序列在更弱的隔离级别下是否可能表现出**不可串行化**的行为」，从而在不真正构造弱隔离环境的情况下预测出隔离违规。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：事务隔离保证「并发执行看起来像某种顺序执行」。但主流数据存储默认跑在弱隔离级别（Read Committed、Snapshot Isolation 等）上以换取性能，这允许一些并发异常（如写偏斜 write skew）。应用开发者往往踩进这些「看不见的坑」，导致数据不一致。
- **为什么难**：直接测试弱隔离很困难——异常只在特定并发交织下出现，压测很难命中；且需要真实地在弱隔离环境下反复执行。
- **几类主流解法**（表格）：

| 路线 | 直觉 | 代表 |
|------|------|------|
| 黑盒 checking | 真跑并发事务，检查是否违反隔离保证 | IsoVista、Efficient Black-box Checking of SI |
| 差分测试 | 比较不同隔离级别/系统的行为差异 | Differentially testing DB transactions |
| 运行时 oracle 构造 | 在引擎内构造隔离性 oracle | Detecting Isolation Bugs via Transaction Oracle |
| **本文：预测式分析** | 跑一次「好执行」，离线求解「坏执行」 | IsoPredict |

- **本文属于**：预测式（predictive analysis）路线，把「找 bug」从运行时碰运气变成离线的约束求解问题。
- **关键名词直觉**：
  - **可串行化（Serializable）**：最强隔离级别，并发结果等价于某一种串行顺序。
  - **弱隔离（weak isolation）**：为性能放松约束的隔离级别，允许特定并发异常。
  - **SMT 求解器**：给定一组逻辑约束，求是否存在满足的赋值（如 Z3）；本文用它来「脑补」出可能存在的坏调度。

## 1. 问题背景与动机
- **前人工作简述**：隔离性测试已有黑盒 checking、差分测试、运行时 oracle 构造等工作，但它们通常需要**真实地在弱隔离环境下反复执行**，成本高且覆盖率受并发调度运气影响。
- **前人的缺陷/未解决问题**（逐条）：
  1. 真实弱隔离压测要构造并发交织，命中异常的概率低、成本高。
  2. 覆盖率受限于运行时「运气」，难以系统性枚举可能的坏调度。
  3. 缺少一种「只观察一次好执行，就离线推断坏执行」的方法。本文据称是**首个**面向弱隔离数据存储应用的动态预测分析。

## 2. 核心方法
- **最直观类比**：考试时老师不必让全班真的去犯每个可能的错误，而是看过一个「正确答卷」后，用规则推导「如果换个评分标准，这份卷子会不会出错」——IsoPredict 就是用约束求解「推导」出可能的坏调度。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：应用在**可串行化**隔离下运行一次，记录完整事务历史（事务集合、读写键、时间顺序）。
  2. **关键操作**：把「如果改成弱隔离级别，这段历史允许哪些重排」编码为一组 SMT 约束；不可串行化则编码为「存在一个最终状态不等价于任何串行顺序」的目标。
  3. **输出**：若求解器给出可行解，即预测出一个隔离违规，并给出具体反例调度供开发者复现与修复。
- **形式化要点 / 新技术**：方法处理「应用行为发散（divergent application behavior）」、求解「相互递归的约束集（mutually recursive constraints）」，并在覆盖率、精度与性能间做平衡。
- **理论性质/保证**：论文报告约 **99%** 预测出的不可串行化行为经检验确实可行（可被复现），即预测有高可行性保证；误报率低。

## 7. 2026 视角（🔧）
