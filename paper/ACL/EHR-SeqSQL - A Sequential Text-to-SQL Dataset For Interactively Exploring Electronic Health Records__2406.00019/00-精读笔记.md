现实里医生查病历从来不是"一问就走"，而是连着追问好几轮。EHR-SeqSQL 是第一个带"上下文相关的连环追问"的医疗 Text-to-SQL 大型基准：上一句问"某患者的血检结果"，下一句"那再和上周比呢"——它专门考察模型能不能记住上文、组合出新查询，还顺手关注"生成的 SQL 跑得快不快"。

## 0. 给新手的阅读前置（背景知识地图）

### 0.1 这个子方向在解决什么大问题
Text-to-SQL：把自然语言问题自动翻译成 SQL，让不会写 SQL 的人直接查数据库。放在电子健康记录（EHR）场景，就是让医生/护士用嘴"查库"——问"这位病人过去 48 小时的血钾趋势"，系统生成 SQL 在 MIMIC 类数据库上执行。

### 0.2 为什么难
- **EHR 数据库巨大且复杂**：上百张表、时间序列型的检验/用药/诊断记录，远比学术 Spider 类玩具库复杂；
- **单轮假设不真实**：真实探索是多轮的——"上一问"的结果是"下一问"的上下文，模型必须懂指代（"那他呢""再排除掉出院的"）；
- **组合爆炸**：问题表述千变万化，模型要在没见过的组合上仍然正确（组合泛化）；
- **效率被忽视**：医疗库动辄上亿行，生成的 SQL 若是低效的嵌套查询，实际不可用。

### 0.3 主流解法一览
| 路线 | 直觉 | 代表 |
|------|------|------|
| 单轮跨域解析 | 一次问答翻译一句 SQL | Spider 系、T5/BERT 编码器系列 🔧 |
| 多轮/对话式 | 维护对话状态，逐轮改写或增量生成 | CoSQL、SParC 🔧 |
| LLM 时代方法 | 大模型 + 提示词/微调直接生成 | 各类 LLM-for-Text-to-SQL（本仓库收录甚多） |
| **医疗序列式基准（本文所属）** | 提供真实多轮 + 组合泛化 + 效率三合一的医疗评测集 | **EHR-SeqSQL**（前身为 EHRSQL） |

### 0.4 三个关键名词的直觉解释
- **序列式/多轮 Text-to-SQL**：多个问题串成一个探索会话，后面的提问常常省略主语或对象，必须结合前文才能翻译。
- **组合泛化（compositional generalization）**：模型见过"查血检"和"查 2020 年以后"，就要会答"查 2020 年以后的血检"——把已知部件组装成没见过的整体。
- **效率 token**：数据集在 SQL 中加入专门设计的 token，用于引导模型生成执行更高效的查询写法（如显式区分不同执行策略 🔧，细节查原文）。

## 1. 问题背景与动机

### 1.1 前人工作简述
- 同一团队 2022 年发布的 **EHRSQL**（NeurIPS 2022 D&B，本仓库收录）建立了医疗 Text-to-SQL 的单轮实用基准：问题来自 222 名医院员工、基于 MIMIC-III 与 eICU、含时间表达与不可回答问题；
- 通用多轮基准（CoSQL、SParC 等 🔧）推动了对话式解析，但都不在真实医疗库上；
- 大模型在单轮 Text-to-SQL 上进步迅速，多轮 + 真实库 + 组合泛化的评测却长期缺位。

### 1.2 前人的缺陷 / 未解决问题（据摘要归纳）
1. **交互性缺位**：text-to-SQL 解析中关键但探索不足的三个维度之一——没有序列式/上下文相关的医疗基准；
2. **组合性缺位**：缺少专门测组合泛化的划分与测试集，模型"背模板"还是"真会组合"分不清；
3. **效率缺位**：几乎没人评测生成 SQL 的执行效率，而真实 EHR 库上效率就是可用性；
4. **规模**：此前没有大规模的序列式医疗 text-to-SQL 数据集（摘要称 EHR-SeqSQL 是最大且首个）。

## 2. 核心方法

### 2.1 最直观类比
如果说 EHRSQL 是驾照笔试（一问一答考知识），EHR-SeqSQL 就是路考（连着变道、超车、看指示牌，每一步都依赖上一步）。考官（数据集）还会扣"油耗分"（SQL 执行效率）。

### 2.2 具体做法（输入 → 关键操作 → 输出）
- **输入**：在 EHRSQL 基础上构造的序列式问题集（自然语言多轮对话）+ 医疗数据库 schema；
- **关键操作**：
  1. 构建**规模最大且首个**包含序列式、上下文相关问题的医学 text-to-SQL 基准；
  2. 设计专门的数据划分 + 新测试集，专门评估**组合泛化**能力（训练/测试的问题组合方式不同）；
  3. 在 SQL 查询中集成**专门设计的 token**，以提升（模型生成 SQL 的）执行效率；
- **输出**：逐轮生成的 SQL；评测维度覆盖准确率 + 组合泛化 + 执行效率。

### 2.3 形式化要点
- 序列式问题的形式化：第 t 轮问题的语义依赖第 1..t-1 轮的问题与答案 🔧（形式化定义查原文 §3）；
- 组合泛化划分的具体构造方式（如按 SQL 结构/原子模板切分）🔧。

### 2.4 理论性质 / 保证
基准类论文无算法理论保证；其"理论贡献"在于评测维度的设计（交互性、组合性、效率三轴）。

## 7. 2026 视角（🔧）
- **多轮是 LLM 时代的主战场**：2024 年后 Text-to-SQL 研究重心转向 agent 式多轮探索、schema 大规模裁剪与上下文管理；EHR-SeqSQL 提前把评测对准了这一形态 🔧；
- **工业地位**：医疗 BI/病历问答产品（各 EHR 厂商的 AI 助手）需要的第一课就是"多轮 + 不可回答检测 + 合规"，本基准的三轴设计（交互/组合/效率）被后续医疗 NLP 评测广泛参照 🔧；
- **趋势**：与不可回答性检测、隐私合成数据（摆脱 PhysioNet 门槛）、执行效率感知的 SQL 生成的进一步结合 🔧。

## 8. 新手学习路线
- **10 分钟**：读本笔记 §0.2/§0.4，理解"多轮/组合泛化/效率"为什么是三个独立短板；
- **30 分钟**：读原文摘要与引言，对照 EHRSQL 论文摘要，画出"单轮 → 序列式"扩展了什么；
- **进阶**：申请 PhysioNet 凭证后复现一个基线 🔧；重点跑组合泛化测试集，观察单轮 vs 多轮方法的差距；再读 CoSQL 与 CoE-SQL 补多轮方法谱系。
