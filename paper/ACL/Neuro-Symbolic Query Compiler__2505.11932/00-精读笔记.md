## 一句话总结
RAG 系统经常「听不懂」复杂、嵌套、有依赖的搜索意图；QCompiler 借语法书和编译器设计，先用一套最小够用的 BNF 文法把复杂查询形式化，再分「翻译→词法句法解析→递归下降执行」三步把查询编译成抽象语法树（AST），叶子节点的原子子查询更精准，从而显著提升 RAG 答复杂查询的能力。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：RAG（检索增强生成）先检索再生成。简单问题好办，但「先找 A，再基于 A 找 B，最后排除 C」这种嵌套/有依赖的复杂意图，普通 RAG 容易检索不准、答非所问。
- 为什么难：复杂查询有结构（嵌套、依赖），纯向量检索难以表达；需要像编译器一样「先解析结构再分步执行」。
- 几类主流解法：

| 方法 | 思路 | 优缺点 |
|------|------|--------|
| 单轮向量检索 | 整句检索 | 简单但怕复杂 |
| 查询分解 | 拆成子问题 | 直观但易失结构 |
| 神经-符号编译（本文） | BNF 文法 + AST 执行 | 保结构、可组合 |

- 本文属哪类：神经-符号（neuro-symbolic）查询编译，把编译器技术引入 RAG 检索。
- 2-3 个必懂关键名词：
  - BNF（Backus-Naur Form，巴科斯范式）：用来定义编程语言语法的形式文法；本文用它定义查询语言。
  - AST（Abstract Syntax Tree，抽象语法树）：把查询解析成的树结构，叶子是最原子的子查询。
  - recursive descent（递归下降）：一种自顶向下解析文法、生成 AST 的经典编译技术。

## 1. 问题背景与动机
- 前人工作简述：RAG 在资源受限、复杂查询下识别搜索意图仍是难题。
- 前人缺陷/未解决问题（逐条）：
  1. 复杂/嵌套意图识别差：此前方法难处理有嵌套结构和依赖的查询。
  2. 缺乏形式化与结构保持：直接检索易丢结构，子查询不原子，检索/生成都不准。

## 2. 核心方法
- 最直观类比：把一句复杂问话像编译程序一样处理——先写一套「查询语法书」（BNF），再把问话逐字解析成「语法树」，最后像运行程序一样从树叶（最小子问题）往上执行。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 设计最小充分 BNF 文法 G[q]：形式化复杂查询，兼顾完备性与最小冗余。
  2. Query Expression Translator（翻译器）：把自然语言查询翻成该文法下的表达式。
  3. Lexical Syntax Parser（词法句法解析器）：解析成 AST。
  4. Recursive Descent Processor（递归下降处理器）：沿 AST 执行，叶子原子子查询保证检索精度。
  - 输出：可执行 AST → 精准检索与生成。
- 形式化要点：核心是「最小充分 BNF + 三件套（翻译/解析/执行）」；叶子原子性是精度关键（🔧 文法与执行细节以论文为准）。
- 理论性质/保证：文法层面保证「完备且最小冗余」的设计目标；具体收敛性以论文为准。
