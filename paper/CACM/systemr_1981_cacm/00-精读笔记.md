## 二、问题史与项目史（✅ 大事记）

- 1970 Codd  relational 论文（⚠️ 未建档）只有数学没有机器；IBM 内部"层次/网状派"与"关系派"对赌，System R 为证明"关系可商用"而立项（✅ 叙事）。
- 里程碑：SEQUEL 语言（1974）→ 首个 NULL/视图/授权实现 → 分布式原型（R* 前身，⚠️ 另文）→ 1978 停止开发但直接催生 IBM SQL/DS 与 Oracle（✅ 史实：Larry Ellison 读了论文）。
- 论文动机：给"内部实验系统"写验尸报告，把可移植的结论留给工业（✅ 自述）。

## 三、设计贡献清单（本文即教科书目录，✅ 各节主题）

| 子系统 | 贡献 | 后世 |
|---|---|---|
| 语言 | SEQUEL→SQL：声明式、集合操作 | 一切 |
| 优化器 | 存取路径 DP 代价选择 | [[selinger_1979_sigmod]] |

| 安全 | 视图+GRANT 授权模型 | SQL 安全子系统 |
| 应用 | ISAM→"RDRS 运行时"、与 COBOL 混编 | 嵌入式 SQL |

## 四、论文自认的教训（✅ §7 精神，⚠️ 条目凭记忆）

- NULL/三值逻辑语义含糊是"设计债"（后成 SQL 兼容地狱第一坑）（✅）。
- 视图更新、授权粒度（视图授权传递）未解透（✅）。
- 优化器对复杂查询/更新代价失准（✅ → 四十年基数估计史的起点）。
- 性能目标达成度：与当时商用层次系统同台，"够用但不碾压"（⚠️ 数字凭原文表）。

## 五、批判读法

- 胜利者叙事：论文写"我们证明了关系可行"，未写"网状阵营也证明了关系不可行的反例不存在"——科学贡献与工程宣传需分开读（⚠️）。
- 设计快照=1978 冻结：1981 发表时 ORACLE V2/V3 已商品化，复盘文天然是**博物馆标本**，勿当设计手册（⚠️）。
- 分布式一节仅占角注——R*（1980s）才是 System R 的下一幕（⚠️ 对照 "Two Foreign Keys" 类 R* 论文，如 Gray 的 "The Transaction Concept" ⚠️）。
- 灰（Gray）署名在此文：事务处理的"ACID 命名史"重要节点（ACID 一词归 Haerder 1981/Gray 1983 ⚠️ 文献学）。

## 六、🔧 本地微实验（非本书引擎行为）

1. **三值逻辑 NULL**：SQL 里 `x=NULL`/`NOT(NULL)`/聚合忽略 NULL 的全家桶复现，写断言总结。
2. **页式存储手工版**：固定 4KB 页文件存变长记录（slot 目录+偏移），体会"页+槽"设计的普适性。
3. **锁+死锁检测**：两线程交叉更新两行，观察 SQLite 死锁/超时行为。
4. **WAL 恢复**：追加日志文件+每页 before-image，kill 进程后重放 undo/redo 到一致。
5. **视图授权**：Postgres 里建视图+GRANT，感受 1981 设计的当代余温。

## 九、最新演进与工业实践

- "回到起源"引用学：SQL 标准缺陷（NULL、join 语法）考古全部引此文；文献计量上 System R 论文是数据库史引用锚（✅）。
- Postgres/SQLite 的现代演进常以"System R 没做对的"为卖点（如真 NULL 语义辩论、无页式包袱的存储格式）（⚠️ 判断）。
- 2024–2026：云厂商 SQL 兼容性战争（Snowflake/Databricks 抢 Oracle 负载迁移）仍按 System R→SQL 标准这条祖谱定价（⚠️ 判断）。
