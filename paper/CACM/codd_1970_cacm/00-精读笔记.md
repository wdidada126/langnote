> 三态标注：✅ 论文硬写事实 / ⚠️ 记忆或二手归纳 / 🔧 本地可复演实验

## 二、问题史：层次/网状数据库的真病

- 1970 现实：IMS/IDMS 时代，应用与**物理链接（指针链）**焊死——改存储结构=改程序；"数据共享"被存取路径绑架（✅ §1 诊断）。
- Codd 的观察：用户思维里数据是**表**（断言/谓词），不是图；查询语言应只依赖"值的结构"（✅ 立场句）。
- 大胆之处：不写实现（明确说"实现留给工程 ⚠️ 原文态度"），只立**逻辑模型+关系代数/微积分接口**（✅）。

## 三、模型核心（✅ 论文定义）

1. **关系**：域上的笛卡尔子集；元组/属性/度（degree）术语在此定型；空关系/重复元组被排除（✅ 原教旨——SQL 的 bag 语义是后世背叛）。
2. **规范化**：每个属性只含**原值**（atomic），禁止重复组/嵌套（✅ 1NF 起源；论文 §2 的"非规范关系"例证）。
3. **两类语言**：关系代数（操作接口）与谓词微积分（声明接口）"表达力等价"（✅ 论文以"高/低级语言"预告了 SQL/QUEL 分岔）。
4. **存储独立性公设**：优化器自行选路径（索引/散列仅"存取路径"目录项），逻辑层不得泄漏物理（✅ 全文最革命一句）。
5. 信息原则（⚠️ 更完整表述在 Codd 1979 十二规则）：一切信息以关系值表达，包括元数据。

## 四、批判读法

- 论文对**性能质疑零回答**——"关系慢"的十年论战（CODASYL 阵营）由此而来，System R 是实验回答（✅ 谱系）。
- 原教旨三禁（NULL、重复行、有序表）被 SQL 全部破戒：今日 SQL 的兼容性地狱几乎每条都能指回这里（⚠️ 对照 Codd 晚期"数据库子"悔恨文）。
- "声明式+优化器"信仰=本文最大的赌注：四十年后仍靠优化器买单（学习式优化是其最新注脚 ⚠️）。
- 阅读建议：与 [[systemr_1981_cacm]] 对读=理论→工程的最短路径；与 Date 教科书读法则失去历史张力（⚠️ 评注）。

## 五、🔧 本地微实验（非本书引擎行为）

1. **指针网 vs 表**：手工建"部门-雇员"两版（链表示例+外键表），删除一个索引字段体验"路径耦合"。
2. **1NF 破戒演示**：SQLite 存"爱好,逗号串"列，跑 LIKE 查询，感受非原子的代价。
3. **代数等价**：同一查询写关系代数（py 集合操作）与 SQL 两版，证明输出一致。
4. **存储独立**：Postgres 建/删索引，EXPLAIN 前后对比——逻辑查询一字未改（✅ 论文主张的活演示）。
5. **bag 之罪**：`SELECT DISTINCT` 忘写导致重复行传播进聚合，体会 Codd 禁重复的先见。

- SQL 标准=本文的工程妥协版；Property Graph/数组模型等"非关系复兴"仍在回应它的边界（⚠️）。
- Datalog（差分计算/材料化视图）让关系微积分以新工程形态复活——Naiad/Materialize 线（库内已建）数学根基在此（✅）。
