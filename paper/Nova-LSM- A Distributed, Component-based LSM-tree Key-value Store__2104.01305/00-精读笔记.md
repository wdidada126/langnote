## 一句话总结
云时代讲究把单体存储「拆组件」按需组装；Nova-LSM 把 LSM-tree KV 存储拆成用 RDMA 通信的若干组件，存储与计算分离、SSTable 块打散到多个存储节点并用 power-of-d 负载均衡、运行时动态建 range 并行 compaction，结果对有偏访问负载比单体 LevelDB/RocksDB 快好几个数量级，还自带弹性。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：LSM-tree（Log-Structured Merge-tree）是 RocksDB/LevelDB 等 KV 存储的底层结构，写性能好。Nova-LSM 研究如何把它**分布式化、组件化**，以适配云上的弹性与性能需求。
- **为什么难**：单体 LSM 在单机上耦合存储与计算；分布式化要解决节点间通信、负载均衡、compaction（合并）并行化、弹性伸缩。
- **几类主流解法**：

| 方法 | 思路 | 优缺点 |
|------|------|--------|
| 单体 LSM（LevelDB/RocksDB） | 单机结构 | 成熟但有偏负载下退化 |
| 分布式 KV（如 Bigtable 系） | 整体分布式 | 扩展好但组件耦合 |
| 本文 Nova-LSM | 组件化 + RDMA | 弹性、抗偏负载 |

- **本文属哪类**：LSM-tree 的分布式/组件化系统实现，属存储与索引。
- **2-3 个必懂关键名词**：
  - **LSM-tree（日志结构合并树）**：用顺序写 + 后台合并实现高写吞吐的索引结构。
  - **SSTable（Sorted String Table）**：LSM 落盘的有序文件；本文把它的块打散到多存储节点。
  - **compaction（合并）**：后台把多层小文件合并成大文件、清理过期数据的开销操作。

## 1. 问题背景与动机
- 前人工作简述：云基础设施推动把单体存储拆成可组装组件；LSM KV 是典型候选。
- 前人缺陷/未解决问题（逐条）：
  1. **存储与计算耦合**：单体 LSM 不便在云上弹性伸缩与共享带宽。
  2. **有偏负载下退化**：访问倾斜时单体系统（LevelDB/RocksDB）性能骤降。

## 2. 核心方法
- **最直观类比**：把「一个人又存又算」的小仓库，改造成「一群专门仓库 + 一群专门计算工」用高速公路（RDMA）相连——存的东西分散到多个仓库、谁闲往谁那放，合并也分头并行干。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **组件化拆分**：把 LSM KV 拆成用 RDMA 通信的组件，存储与处理分离，处理组件可共享存储带宽/空间。
  2. **SSTable 块打散**：把 SSTable 的块散布到任意多个存储组件，并用 power-of-d 做负载均衡。
  3. **动态 range + 并行 compaction**：运行时动态构造 range 来并行化 compaction、提升性能；每个组件有可配的扩展性旋钮。
  - 输出：一个弹性、高性能的分布式 LSM KV 系统。
- **形式化要点**：核心是「组件解耦 + RDMA + 块级打散 + 动态 range compaction」（🔧 一致性/容错细节以论文为准）。
- **理论性质/保证**：无显式理论保证；以「有偏负载下快数个数量级 + 弹性」实证为主。
