## 一句话总结
纯 Seq2Seq 模型做 Text-to-SQL 常被架构限制拖累。SeaD 不改解码结构、而是给模型加「schema 感知去噪」的辅助训练任务（模拟输入被侵蚀/打乱再还原），并改进执行引导解码，从而在 WikiSQL 上刷新 SOTA，证明「朴素 Seq2Seq 的潜力被低估了」。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：Text-to-SQL 的「端到端」做法是用 Seq2Seq（编码器-解码器）直接把「问题+schema」生成 SQL 字符串。难点在模型容易生成语法错、链接错列的 SQL。
- **为什么难**：SQL 有严格语法与结构；朴素 Seq2Seq 对结构化数据建模弱；执行引导（EG）解码原有局限。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 约束解码 | 早期 | 限制解码空间 | 保语法但僵 |
| 槽位填充 | SQLNet/RYANSQL | 模板填空 | 结构可控 |
| 去噪预训练 | 本文 SeaD | 辅助任务增强建模 | 不改架构即提点 |
| 大模型 | 后续 LLM | 直接生成 | 强但贵 |

- **本文属哪类**：Seq2Seq + schema 感知去噪的端到端路线。
- **2-3 个必懂关键名词**：
  - **Seq2Seq（序列到序列）**：编码器读入、解码器生成序列的模型范式。
  - **Denoising（去噪）**：把输入加噪再还原，作为辅助训练任务，提升结构建模。
  - **Execution Guided (EG) Decoding（执行引导解码）**：用 SQL 能否执行来筛选/引导解码。

## 1. 问题背景与动机
- **前人工作简述**：Text-to-SQL 中 Seq2Seq 模型因架构限制常表现次优。
- **前人缺陷/未解决问题**：
  1. 多数改进靠「约束解码」或「改造成槽位填充」，绕开 Seq2Seq 本身。
  2. 现有执行引导（EG）解码对生成式模型的适配有限。

## 2. 核心方法
- **最直观类比**：与其给孩子换一套考试格式（改架构），不如平时多做「看被涂改的卷子复原」的训练（去噪），让他更懂题目结构；再在考试时加一道「交卷前先试跑」的把关（执行引导解码）。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：自然语言问题 + 数据库 schema。
  2. **关键操作**：
     - 用 **Schema-aware Denoising（SeaD）**训练 Seq2Seq：包含两个去噪目标，让模型从**侵蚀（erosion）**与**打乱（shuffle）**两种噪声中还原输入或预测输出。
     - 去噪目标作为**辅助任务**，更好地建模 S2S 生成中的结构化数据。
     - 改进并提出 **clause-sensitive execution guided（EG）decoding（子句敏感执行引导解码）**，克服原 EG 解码对生成式模型的限制。
  3. **输出**：SQL（端到端）。
- **形式化要点**：以噪声注入构造自监督信号强化结构理解；EG 解码按子句粒度筛选。具体噪声/解码细节见原论文 🔧。
- **理论性质/保证**：以经验为主（🔧 原文未强调理论保证）。

## 7. 2026 视角（🔧）
- 端到端 Seq2Seq 已被预训练/大模型范式取代，但「去噪式自监督增强结构理解」的思想仍广泛用于 SQL 生成与代码生成；EG 解码与执行反馈是今日 LLM 路线的核心组件。
- 趋势：Spider/BIRD 取代 WikiSQL 成为主基准；执行反馈 + 自洽成为标配。本节为趋势判断，具体数字 🔧 查当年评测。
