## 一句话总结

「这两张表能不能 union 到一起」这件事，人怎么看、机器学习怎么看、LLM 又怎么看？本文用认知实验发现：人判断有可挖掘的规律，ML 能显著增强人的原始判断，而人与 LLM 结合通常比单打独斗更好。

## 0. 给新手的阅读前置（背景知识地图）

- **大问题**：数据湖里有成千上万张表，做数据发现（data discovery）时想知道哪些表**可联合（unionable）**——即字段语义对应、值域兼容，可以纵向拼成一张大表。这是数据湖分析、训练数据搜集的基础环节。
- **为什么难**：unionability 不只是「列数相同」这种结构问题，而是**语义问题**——两个列名不同、值分布不同的列可能语义等价；反之列名相同的列也可能语义不合。判断需要世界知识。
- **几类主流解法**：

| 类别 | 直觉 |
|------|------|
| 基于 schema/元数据 | 比较列名、类型、注释等元信息 |
| 基于实例内容 | 比较列值分布、词袋、嵌入 |
| 基于图/关系 | 利用表间关系与知识图谱（如本仓库 SANTOS） |
| 人工规则 + 学习模型 | 把人类判断习惯编码成特征训练分类器 |

- **本文属哪类**：偏**人因/认知实验 + 机器学习建模**的交叉研究，是「Human-in-the-Loop 数据科学」视角下的 unionability 研究。
- **关键名词直觉**：
  - *Unionability（可联合性）*：两张表能否安全纵向合并的判断。
  - *Human-in-the-Loop*：人不是被替代，而是作为决策环节之一嵌入系统。
  - *认知调查（experimental survey）*：让真人受试者对表对做判断，分析其准确率、偏差与决策依据。

## 1. 问题背景与动机

- 前人工作：SANTOS、Pylon 等系统用 schema/内容/关系信号做联合搜索； Generative Benchmark Creation for Table Union Search 等工作提供评测基准（见本仓库互链）。
- 缺陷/未解决问题（逐条）：
  1. unionability 判断的**人类视角几乎无人研究**——现有系统全自动，但没人量化「人到底怎么判断、错在哪」。
  2. 人类判断的**原始表现不高**，缺少把「人类直觉」转化为可计算特征并提升的框架。
  3. LLM 时代「能不能直接让 LLM 判 unionability」缺乏与人类表现的对照证据。
  4. 面向未来的 HI-L 数据发现系统缺一块「人与机器如何分工」的实证地基。

## 2. 核心方法

- **最直观类比**：像研究「医生看片子的直觉」——先让一批受试者做判断并记录过程，找出人类判断的规律；再把规律做成特征喂给分类器，帮人「放大直觉」；最后请出 LLM 选手，看它与人类单挑或组队谁更强。
- **具体做法（输入→关键操作→输出）**：
  - 输入：表对样本（unionable / 不可联合两类）。
  - 关键操作 1：设计并开展**实验调查**，收集人类受试者对表对 unionability 的判断。
  - 关键操作 2：**分析人类决策**（准确率、偏差、判断依据），提炼观察。
  - 关键操作 3：基于观察构建**机器学习框架**，用于增强（boost）人类的原始表现。
  - 关键操作 4：**初步研究** LLM 与人类的对比，考察组合方案。
  - 输出：人类决策规律 + 一个提升 unionability 判断的 ML 框架 + 「人机组合优于单独任一」的初步结论。
- **形式化要点**：🔧 实验设计细节（受试者数、表对数量、特征列表、所用模型）请查原文。
- **理论性质**：无理论保证，属实证研究。

## 4. 实验结论（概览）

- 对比对象：人类受试者、基于人类观察构建的 ML 框架、LLM，以及人机组合。
- 数据集/素材：自建实验调查中的表对样本。🔧 具体规模与来源查原文。
- 指标：判断准确率等。🔧 精确数字查原文后补。
- 结论方向：
  1. ML 框架能**显著提升人类原始表现**；
  2. LLM 表现与人类相比各有强弱，**两者结合通常优于单独使用**；
  3. 为 Human-in-the-Loop 数据发现系统奠定基础。

## 7. 2026 视角（🔧）

- LLM 在 schema matching / 表理解上的能力被大量验证（本仓库 SMUTF、ReMatch、Schema Matching with LLMs 等条目），但本文提醒：**人的判断依然是校准与最终把关的重要资源**，纯自动判断的误差来源需要认知层面的解释。
- Human-in-the-Loop 数据发现是 SIGMOD/VLDB 持续的工作坊主题（HILDA 等）；2026 年的趋势是「LLM 打草稿 + 人类确认 + ML 特征兜底」的三明治式系统。
- 数据湖/湖仓一体平台中 union search 正成为元数据服务的一部分，认知研究的结论可指导交互设计（何时该询问用户）。
