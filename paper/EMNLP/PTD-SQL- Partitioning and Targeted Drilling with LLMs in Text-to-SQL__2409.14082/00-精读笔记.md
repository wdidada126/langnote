## 一句话总结
SQL 解法套路相对固定，适合「分门别类地学」。PTD-SQL 把查询按类型分组（Partitioning），让 LLM 专注学某一类题的解题思路，再对薄弱点做「定向精练（Targeted Drilling）」，在 Spider 和 BIRD 上追平或超越此前 SOTA。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：Text-to-SQL 用 LLM 把问题转成 SQL。和数学题、常识推理不同，SQL 答案有相对固定的「套路」；能不能按题型分类、针对性训练，是提分关键。
- **为什么难**：LLM 对不同类型的 SQL（多表 join、嵌套、聚合等）掌握程度不一；一刀切提示效果有限。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 少样本/CoT | 通用提示 | 给例子/思维链 | 简单但难针对性 |
| 分治提示 | **PTD-SQL** | 题型分组 + 定向精练 | 针对薄弱点提分 |
| 多模型集成 | XiYan-SQL 等 | 多生成器融合 | 强但贵 |

- **本文属哪类**：基于 LLM 的 Text-to-SQL，强调「分类思维（categorical thinking）+ 定向精练」。
- **2-3 个必懂关键名词（直觉解释）**：
  - **Partitioning（分治/分组）**：把查询按类型/难度分组，让模型分别学每类的「解题思路」。
  - **Targeted Drilling（定向精练）**：在模型能力边界处做针对性训练/提示，类似「哪里不会练哪里」。
  - **Spider / BIRD**：两个主流 Text-to-SQL 基准（跨域 / 含数据库内容）。

## 1. 问题背景与动机
- 前人工作简述：LLM 在 Text-to-SQL 展现强推理力；但与数学/常识推理不同，SQL 解法有固定模式。
- 前人缺陷/未解决问题（逐条）：
  1. **缺分类式学习**：未充分利用「SQL 套路固定」这一特性做按类型专项提升。
  2. **泛化不均衡**：模型在不同难度/题型上表现参差，边界能力不足。
  3. **未做针对性精练**：现有方法少有在能力边界做「定向 drilling」来补强。

## 2. 核心方法
- **最直观类比**：像备考——先把题库按题型分类（分区），每类集中刷对应的解法；再针对自己总错的那几类（薄弱点）做定向特训，分数提升最明显。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **Query Group Partitioning（查询分组）**：把查询按类型/模式分组，让 LLM 专注学单一题型的思路。
  2. **Targeted Drilling（定向精练）**：在模型能力边界处做针对性训练/提示，补强薄弱题型。
  3. **跨难度/题型泛化**：验证该方法在不同难度与问题类别上的推理增益。
  - 输出：更准的 Text-to-SQL 生成（尤其中等/边界难度题）。
- **形式化要点**：核心是「分组 + 定向精练」的提示/训练策略；超参为分组粒度与精练数据选取（🔧 见原论文）。
- **理论性质/保证**：以实证为主；发现「不同初始水平模型在定向精练后均有显著提升，类似人类进步」。
