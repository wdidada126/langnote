## 一句话总结
真实业务里的「专家提问」往往带行业公式和口径（比如「毛利率」「同比增速」），只有表结构没有这些领域知识，模型根本翻译不出来；本文先造了一个中文的领域知识密集型基准 **KnowSQL**，然后不靠疯狂标注新样本，而是把领域知识整理成一份「公式化知识库（formulaic knowledge bank）」，再提出 **ReGrouP** 框架在解析时把这份知识用起来，在 KnowSQL 上整体提升 **28.2%**。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：Text-to-SQL（NL2SQL）要把自然语言问题翻译成能在数据库上执行的 SQL，让不懂 SQL 的人也能查数。经典基准（WikiSQL、Spider）假设「问题里的词都能在表结构上找到对应」。
- **为什么难**：真实场景是「知识密集型」的——问题的关键概念并不等于某个列名，而是需要用领域知识推导出来的量（例如需要按某个公式做四则运算、按某口径过滤）。此时模型即使 schema linking 全对，也写不出正确 SQL。
- **几类主流解法**：

| 路线 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| Seq2Seq + schema encoding | RAT-SQL、LGESQL | 把表结构编码进图/关系，再解码 SQL | 通用强，但依赖问题词与 schema 的表面对应 |
| 预训练 + 微调 | BERT/T5 系 | 大规模语料预训练再微调 | 基线强，缺领域知识仍是短板 |
| 额外知识注入 | 本文 ReGrouP、知识库/公式库 | 显式引入领域知识并在解析时使用 | 知识覆盖处提升大，需要构造知识源 |
| 数据增广/标注更多样本 | 各类 augmentation | 加标注数据覆盖新领域 | 成本高，换个领域又要重标 |

- **本文属于哪一类**：**额外知识注入**路线，且刻意选择「造知识库」而不是「标更多数据」。
- **必懂关键名词**：
  - **schema linking（模式链接）**：把问题里的词对齐到表/列上；是 Text-to-SQL 的核心中间步骤。
  - **formulaic knowledge（公式化知识）**：以公式形式表达的领域知识（如「利润 = 收入 − 成本」），可作为知识库条目被检索与复用。
  - **semantic parsing（语义解析）**：把自然语言解析成可执行的形式化表示（此处即 SQL）。

## 1. 问题背景与动机
- 前人工作简述：主流 Text-to-SQL 研究在 Spider、WikiSQL 等基准上快速进步，模型通过关系感知编码、图神经网络、预训练语言模型把「问题 → schema → SQL」这条链路做得很好。
- 前人缺陷/未解决问题（逐条）：
  1. **假设过强**：隐含假设「不需要额外领域知识就能解析」，而真实专家问题常常需要领域知识。
  2. **缺基准**：没有公开基准系统刻画「需要领域知识才能解析」这一类问题，导致该问题被低估。
  3. **靠标注的解法不可扩展**：直观做法是为新领域标注大量新问题-SQL 对，但成本高、换领域要重来。
  4. **知识没有结构化载体**：即便有领域知识，也缺少能被模型检索、组合、代入的表示形式。

## 2. 核心方法
- **最直观类比**：与其给厨师（模型）多做一万道菜（标注样本），不如给他一本「菜谱公式手册」（公式化知识库），做菜时按手册查公式套用。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：一个领域相关的自然语言问题 + 该领域的数据库 schema + 领域知识来源。
  2. **构造知识库**：把这些领域知识组织成 **formulaic knowledge bank**（公式化知识库），作为领域知识底座。
  3. **解析框架 ReGrouP**：在解析过程中利用这份公式化知识——先检索/选择相关的知识条目，再把它们引导进 SQL 的生成（具体模块名与网络结构 🔧 以论文正文为准）。
  4. **输出**：符合领域口径的可执行 SQL。
- **形式化要点**：核心思想是「知识以公式形式表达 + 解析时动态使用」，而不是把知识硬编码进训练数据；摘要未给具体超参数 🔧。
- **理论性质/保证**：无（本文为经验性方法与基准研究）。

## 7. 2026 视角（🔧）
- Text-to-SQL 已整体进入「LLM + 智能体」时代：主流做法是用大模型做 schema linking、多候选生成与执行反馈自纠，少量样本提示即可跨库。
- 本文的洞见（**领域口径/公式知识是瓶颈，且应显式建模**）不但没有过时，反而在企业 BI、财务、指标平台上更突出——今天常以「指标语义层 / 业务术语表 / metric layer」的形式存在。
- 本节为趋势性判断；具体 SOTA 与榜单数字 🔧 查当年 BIRD/Spider 榜单。
