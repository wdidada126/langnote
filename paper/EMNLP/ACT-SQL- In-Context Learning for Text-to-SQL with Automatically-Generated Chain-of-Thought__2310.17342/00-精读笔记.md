## 一句话总结

针对大模型做 Text-to-SQL 时「手工写思维链（CoT）样例又贵又费人力」的痛点，作者提出 **ACT-SQL**：用**类似「模式链接（schema linking）」的自动方法**生成**自动思维链（auto-CoT）**示例，整个流程**无需人工标注**；且每条查询**只调用一次 LLM API**（省钱），并把方法扩展到**多轮 Text-to-SQL**；在 Spider 开发集上取得当时上下文学习类方法的 SOTA。

## 0. 给新手的阅读前置（背景知识地图）

### 0.1 什么是 Text-to-SQL
- 把**自然语言问题**自动翻译成**可执行的 SQL**。例如「每个部门工资最高的员工是谁？」→ 一段 SQL。
- 应用：让不懂 SQL 的业务人员直接问数据库；是「自然语言接口」的核心任务。

### 0.2 什么是 In-Context Learning（上下文学习）
- 不微调模型，而是**在提示（prompt）里塞几个「示例（few-shot）」**，让大模型照着学。例：给 3 个「问句→SQL」样例，再问第 4 个，模型照格式答。
- 直觉：像考前看几道例题，临场套用，而不是重读整本教材。

### 0.3 什么是 CoT（Chain-of-Thought，思维链）
- 让模型**先「想一步」再给答案**，例如先列出「涉及哪些表、哪些列」，再写 SQL。
- 手工写 CoT 样例**费人力和钱**；「auto-CoT」就是**自动生成**这些中间推理步骤。

### 0.4 必懂名词
- **Schema Linking（模式链接）**：判断问题里哪些词对应数据库的哪张表 / 哪个字段——Text-to-SQL 的关键子任务。
- **Spider**：最著名的跨领域 Text-to-SQL 评测集。

## 1. 问题背景与动机：前人工作的缺陷

1. **手工 CoT 样例成本高**：已有的 few-shot + CoT 方法，示例里的「推理步骤」靠人写，既费人力又贵（要反复调 prompt）。
2. **调用 API 次数多 = 烧钱**：很多方法为一条查询要多次调用大模型（如先生成步骤、再生成 SQL），成本高。
3. **多轮场景覆盖不足**：真实对话常是多轮的（追问、补充），单纯单轮方法不够用。

> 一句话：要把 CoT 的「效果好」和「自动、省钱、能多轮」结合起来。

---

## 2. 核心方法：ACT-SQL

### 2.1 直觉类比
把 ACT-SQL 想成「请了一位不用发工资的助教」：它先自己把几道 SQL 题的「解题步骤」写好当例题（auto-CoT），再把这些例题连同新题一起交给大模型；大模型看例题照做即可——而且**整件事只问大模型一次**。

### 2.2 具体做法
1. 设计 CoT 提示，其生成方式与 **schema linking** 类似（自动定位问题中涉及的表 / 列）。
2. 用 **ACT-SQL 方法自动生成 auto-CoT 示例**，全程**无需人工标注**。
3. **单次 API 调用**生成一条 SQL（cost-saving）：把示例与查询一次性喂给模型，而不是多轮往返。
4. 将上下文学习扩展到**多轮 Text-to-SQL**：处理对话上下文中的追问与指代。

### 2.3 核心思想
- 把「人工 CoT」替换为「**自动、基于模式链接的 CoT**」，在保持（甚至提升）效果的同时，大幅降低标注与调用成本。
