## 0. 给新手的阅读前置（背景知识地图）

这个子方向解决什么大问题？
Text-to-SQL 要把「自然语言问题 + 数据库 schema（表/列定义）」翻译成可执行的 SQL。LLM 时代有两条路： prompting（免训练，靠 in-context learning）和 SFT（监督微调，把能力训进模型权重）。本文属于 SFT 路线，目标是让中等规模开源模型（而非闭源巨兽）也能打。

为什么难？
- Schema linking 是瓶颈：真实库动辄几百列，模型必须先"挑出"与问题相关的表/列，再生成 SQL；挑错则全错。
- 多阶段流水线又慢又贵：早期 SFT 方案把 schema linking 和 SQL 生成拆成两个模型/两个阶段，训练复杂、误差级联、推理两次前向。
- 噪声鲁棒性差：输入 schema 里混入无关甚至干扰性的表/列（真实场景常态），模型精度大幅下滑。

主流解法（表格）
| 路线 | 代表 | 局限 |
|------|------|------|
| Prompting（zero/few-shot + CoT） | C3、DIN-SQL、XiYan-SQL 等 | 依赖闭源大模型，推理成本高 |
| 多阶段 SFT（先 linking 后 generation） | 早期 fine-tuned parser | 流水线复杂、误差级联 |
| 单阶段联合 SFT（本文） | JOLT-SQL：统一损失同时学两项任务 | 需要构造噪声样本增强鲁棒性 |

关键名词直觉解释
- Schema Linking：从整个数据库 schema 中"圈出"和问题相关的表与列——像先在目录里划重点，再写答案。
- 判别式 schema linking（discriminative）：不让模型逐字"读出"相关列（生成式），而是对每个候选列做"相关/不相关"判别打标，更省 token、更快。
- Confusion-aware Noisy Schema Sampling：训练时故意往 schema 里注入"容易混淆的干扰列/表"（比如名字相似、语义相近的），逼模型学会无视噪声——类似打疫苗。

## 1. 问题背景与动机
LLM 推动下 Text-to-SQL 进步巨大，但 SFT 路线存在被作者点名的缺陷：

1. 流水线复杂：已有 SFT 方法常把 schema linking 与 SQL 生成拆成多阶段（先预测相关 schema，再喂给生成模型），训练管线难维护，两阶段误差会级联放大。
2. 噪声 schema 下不鲁棒：真实数据库充满与问题无关的表/列，甚至有命名相近的"迷惑项"；现有 SFT 模型在此类噪声下精度明显下降。
3. 效率不够好：多阶段推理（两次前向）与生成式 linking（逐 token 读出 schema 元素）拖慢训练与推理。

动机：能不能用一个模型、一个损失、一次前向同时把两件事做好，并系统性地对噪声免疫？

## 2. 核心方法
最直观类比：训练一个学生做填空题时，不只给干净试卷，还故意在卷面写一堆无关公式（噪声），并同步教他"先划掉无关内容（判别式 linking）再答题（SQL 生成）"，且两门课用同一张成绩单（统一损失）评分。

具体做法（输入 → 关键操作 → 输出）
- 输入：自然语言问题 + 数据库 schema（训练时可能被注入噪声）+ 目标 SQL。
- 关键操作：
  1. 判别式 schema linking：将 linking 建模为对 schema 元素的二分类判别任务，配合 local bidirectional attention（让问题与候选 schema 元素局部互看，强化"问题-列"对齐，而不是只靠单向注意力）；
  2. 混淆感知噪声采样（confusion-aware noisy schema sampling）：构造训练样本时，按"混淆度"采样无关表/列混入输入（如名字/类型相近的干扰项），并配合 selective attention（选择性注意力）机制，让模型学会聚焦真相关元素；
  3. 联合损失（joint loss）：schema linking 的判别损失与 SQL 生成损失加权合并，单阶段端到端微调，无需两阶段流水线。
- 输出：对每个 schema 元素的相关性判别 + 最终 SQL 查询（一次前向即可推理）。

## 4. 实验结论（概览）
- 数据集：Spider 与 BIRD（两大主流 Text-to-SQL 基准；BIRD 更接近真实库规模与脏数据）。
- 指标：执行准确率（execution accuracy）。
- 结论方向：
  - 在同尺寸开源模型中达到 SOTA 执行准确率；
  - 相较多阶段 SFT 基线，训练与推理效率显著提升（单阶段、判别式 linking 省 token）；
  - 噪声 schema 条件下鲁棒性优于对比方法。

## 7. 2026 视角（🔧）
- SFT 与 RL 微调是 2025-2026 年 Text-to-SQL 的主战场之一：单阶段联合训练（本文）与强化学习路线（如本仓库 Arctic-Text2SQL-R1、Graph-Reward-SQL）并行发展。
- 中小开源模型 + 高效微调被认为是最有落地性价比的方案，工业界 Text-to-SQL 产品多采用「检索/schema 剪枝 + 微调小模型 + 执行校验」的组合。
- 噪声鲁棒性（干扰列、缺失注释、大 schema）已成为标准评测维度，BIRD 系与各类 robustness benchmark（Dr.Spider 等）持续演进。
