## 一句话总结
开源大模型做 Text-to-SQL 时，"零样本思维链"几乎没用、"不用思维链直接 DPO"也只有零星提升——ExCoT 把两件事绑在一起：让模型先写思维链再写 SQL，并且只用"SQL 跑得对不对"（执行准确率）作为反馈来做 DPO 迭代训练，把 LLaMA-3 70B 在 BIRD dev 上从 57.37% 拉到 68.51%。

## 0. 给新手的阅读前置（背景知识地图）

- 子方向解决什么大问题：Text-to-SQL 需要精确推理（理解问题 → 对齐 schema → 组合 SQL）。闭源模型靠提示就能不错，但开源模型怎么用后训练补齐这一步？本文回答：把 Chain-of-Thought（CoT） 与 偏好优化（DPO） 结合，反馈信号只用可自动验证的执行结果。
- 为什么难：
  1. 零样本 CoT 对 Text-to-SQL 收益极小（模型会"假装推理"）；
  2. 普通 DPO 需要人类偏好标注或奖励模型，贵且噪声大；
  3. SQL 恰好有独特优势——执行结果可以机器验证，如何把这种可验证信号喂给偏好优化是关键设计点。
- 几类主流解法（表格）：

| 路线 | 思路 | 局限 |
|------|------|------|
| 提示工程 / ICL | few-shot、schema 链接提示（C3、DIN-SQL 等） | 不改模型权重，上限受限 |
| SFT 微调 | 用 (问题, SQL) 对监督微调 | 学模仿，不学"对错" |
| DPO/RLHF | 依据偏好对优化 | 常需人工偏好或奖励模型 |
| 本文：执行反馈 + CoT + DPO | 用执行准确率自动构造偏好对，且强制 CoT 参与 | 需要可执行的数据库环境 |

- 本文属哪类：后训练路线（CoT 引导 + 偏好优化），反馈信号是"执行结果"。
- 关键名词直觉解释：
  - CoT（Chain-of-Thought）：让模型先输出一步步推理再给答案；
  - DPO（Direct Preference Optimization）：不用训奖励模型，直接拿"好答案 vs 差答案"的偏好对微调模型；
  - off-policy / on-policy DPO：off-policy 用（旧模型/外部模型）生成的偏好对；on-policy 用当前模型自己采样生成的偏好对，随训练迭代更新（本文两者并用）。

## 1. 问题背景与动机

- 前人工作简述：Text-to-SQL 有 Spider、BIRD 两大基准；开源模型微调（SFT）与提示工程已有大量工作；DPO 作为免奖励模型的偏好优化方法在通用任务上流行。
- 前人的缺陷 / 未解决问题（逐条）：
  1. 零样本 CoT 在 Text-to-SQL 上几乎没有增益——作者明确点出这一"直觉失效"现象；
  2. 不做 CoT 直接上 DPO，提升也很有限（作者实验观察：marginal improvements）；
  3. 主流偏好优化依赖奖励模型或人工偏好标注，成本高、且与 Text-to-SQL 的"可执行验证"特性不匹配；
  4. 开源模型与闭源模型在 Text-to-SQL 上差距明显，需要一种只靠自动信号就能迭代放大的训练框架。

## 2. 核心方法

- 最直观类比：驾校练车不改车（模型架构），只改教学方式——让学员先口述驾驶计划（CoT），再上路（生成 SQL），教练不看口才只看"有没有撞车"（执行结果），每次把"顺利到达 vs 撞车"的两条路线摆在一起让学员反思（DPO 偏好对），如此循环往复。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：开源 LLM（如 LLaMA-3 70B、Qwen-2.5-Coder）、训练问题集与可执行数据库；
  2. 关键操作：构造"CoT 推理 + SQL"的生成格式；对每个问题采样多个候选解，用执行准确率自动判定好坏，构成偏好对；交替进行 off-policy 与 on-policy DPO 迭代优化；
  3. 输出：推理时先产出 CoT 再产出 SQL 的开源模型。
- 形式化要点：反馈信号 = 执行准确率（execution accuracy）；无需奖励模型、无需人工偏好标注。🔧 DPO 目标函数与偏好对构造的具体细节（正确解/错误解的筛选阈值、迭代轮数等）查原论文后补。
- 理论性质/保证：无理论证明，属方法 + 实证型论文。

## 4. 实验结论（概览）

- 对比基线：零样本 CoT、无 CoT 的 DPO、SFT 等设置下的同底座模型（🔧 完整基线名单查原论文表格后补）；
- 数据集：BIRD（dev 与 test）、Spider（test）；
- 指标：执行准确率（execution accuracy）；
- 结论方向（以下数字出自 arXiv 摘要，已核实）：
  - LLaMA-3 70B：BIRD dev 57.37% → 68.51%；Spider test 78.81% → 86.59%；
  - Qwen-2.5-Coder 呈现类似量级的提升；
  - 最佳模型在单模型设定下取得 BIRD 与 Spider 双料当时最优，BIRD test 达 68.53%；
