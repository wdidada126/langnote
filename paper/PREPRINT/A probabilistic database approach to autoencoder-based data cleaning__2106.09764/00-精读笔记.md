## 一句话总结
用一个自编码器学出数据内部的结构与依赖，再借助「概率数据库」把每个可疑值的修复证据分成强弱，从而实现近乎自动、且带不确定性解释的数据清洗。

## 0. 给新手的阅读前置（背景知识地图）
- 这个子方向解决什么大问题：数据质量（脏数据、缺失、错值）是数据科学的大威胁。数据清洗旨在自动发现并纠正错误值，让人少做手工校对，直接决定下游分析 / 模型的可靠性。
- 为什么难：① 监督式清洗需要大量「已清洗」标签，代价高昂；② 纠正是「硬」决策还是「软」概率，需要建模不确定性；③ 要解释「为什么修这个值」，需要显式的证据。
- 几类主流解法：

  | 方法 | 代表 | 思路 | 优缺点 |
  |------|------|------|--------|
  | 规则 / 约束 | 数据质量规则、FD/CFD | 用领域规则找冲突 | 可解释；规则难写全 |
  | 统计 / 机器学习 | 聚类、分类器 | 学分布检测异常 | 需标签或强假设 |
  | 深度学习 | 去噪自编码器 | 学重建分布来修值 | 端到端；难解释 |
  | 概率数据库 | 本文 | 用概率表示修复的不确定性 | 可解释；建模复杂 |

- 本文方法属于哪一类，与前身关系：属于「自编码器 + 概率数据库」混合路线；前身是用自编码器做异常检测 / 重建的工作，本文额外引入概率数据库来量化修复证据。
- 2-3 个必须先懂的关键名词（直觉解释）：
  1. **自编码器（autoencoder）**：一种神经网络，训练目标是「输入 ≈ 输出」，从而被迫学出数据的紧凑结构；输入有错值时，重建值往往更接近真实。
  2. **概率数据库（probabilistic database）**：把数据表示为带概率的多种可能世界，每个值 / 每个修复都附带置信度，而非单一确定值。
  3. **弱证据 vs 强证据**：对某个可疑值，模型「较不确定」的修复依据叫弱证据，「较确定」的叫强证据；概率数据库用不同概率表示二者。

## 1. 问题背景与动机
- 前人工作简述：传统数据清洗依赖规则或需要干净训练数据；自编码器类方法能学出数据分布并用于重建 / 纠错，但通常只给「一个点估计」，不显式建模不确定性。
- 前人 N 个缺陷 / 未解决问题（逐条）：
  1. 许多清洗方法需要干净数据作监督，成本高、难以规模化。
  2. 修复决策常是「硬」的，没有对「该不该修、修成什么」的不确定性建模。
  3. 缺乏把「为什么修这个值」的证据以可解释、可量化方式表达的机制。

## 2. 核心方法
- 最直观类比：先让模型「读懂」这份数据长什么样（自编码器学出规律），再像侦探一样给每个可疑格子找证据——证据强的就大胆改，证据弱的就保守处理，并且把每条证据的把握度都记下来。
- 具体做法（输入 → 关键操作 → 输出）：
  - **输入**：带噪声 / 可疑值的数据（分类型与数值型概率数据）。
  - **关键操作**：① 训练一个「数据清洗自编码器」，让它学出数据的结构与依赖，用作识别并纠正可疑值的证据；② 用**概率数据库**方法，把属性值修复的「弱证据」和「强证据」分别表示出来（即每条修复附带不同置信度）。
  - **输出**：带概率的修复建议（哪些值该改、改成什么、把握多大）。
- 形式化要点：核心是把修复证据用概率数据库的语义建模，给出理论框架；主要超参是自编码器的结构与训练设定（🔧 具体以原论文 / 代码为准）。
- 理论性质 / 保证：论文提供了理论框架（证明层面的形式化）；经验上显示能从分类与数值概率数据中去除显著数量的噪声。一个重要实用结论是：方法**不需要干净数据**即可工作，但手动清洗一小部分能显著提升表现。
