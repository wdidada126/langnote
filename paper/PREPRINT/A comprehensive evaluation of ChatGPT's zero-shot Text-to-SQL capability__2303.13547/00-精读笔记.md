## 一句话总结
这是**首个系统评测 ChatGPT 做 Text-to-SQL（自然语言转 SQL）** 的工作：在 12 个覆盖不同语言/设定/场景的基准上做零样本（zero-shot，不给训练样本）测试，结论是 ChatGPT 已具备相当强的转写能力，虽整体距当时 SOTA 仍有差距，但在某些场景（ADVETA/RPL）零样本甚至超过需微调的 SOTA。

## 0. 给新手的阅读前置（背景知识地图）
- **这个子方向解决什么大问题**：Text-to-SQL 让不懂 SQL 的人用自然语言问数据库（「去年销售额最高的产品是什么？」→ 自动生成 SQL）。它是自然语言接口（NLIDB）与语义解析的核心应用，直接关系到数据分析平民化。
- **为什么难**：自然语言有歧义、数据库 schema 复杂、用户问题涉及多表 JOIN/聚合/嵌套，且**训练数据稀缺、跨库跨领域泛化难**。传统做法靠大量标注数据微调专用模型。
- **几类主流解法**（简化对比）：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 规则/模板 | 早期 NLIDB | 手工映射语言到 SQL | 可控但难泛化 |
| 序列到序列模型 | 各类 Seq2Seq | 端到端学 NL→SQL | 需大量标注 |
| 预训练 + 微调 | T5/BERT 系、专门 Text-to-SQL 模型 | 在 Spider 等上微调 | 精度高，但需训练数据、易过拟合基准 |
| 大语言模型零样本（本文关注） | ChatGPT/GPT 类 | 仅用提示（prompt）直接生成 SQL | 免训练、泛化好，但精度/可控性波动 |

- **本文方法属于哪一类**：属于「**大语言模型零样本 Text-to-SQL 评测**」——不是提出新模型，而是**系统性评估** ChatGPT 在 zero-shot 设定下的能力边界。
- **2-3 个必须先懂的关键名词**：
  - **Text-to-SQL**：把自然语言问题转换为可在数据库执行的 SQL 语句的任务。
  - **零样本（zero-shot）**：不提供任何该任务的训练/示范样本，直接让模型凭提示作答；与「少样本（few-shot，给几个例子）」「微调（fine-tuning）」相对。
  - **SOTA（state-of-the-art）**：某一基准上当前最好成绩；本文把零样本 ChatGPT 与「需要微调的 SOTA 模型」做对比。

## 1. 问题背景与动机
- **前人工作简述**：在 ChatGPT 出现前，Text-to-SQL 的 SOTA 多由在 Spider 等基准上**微调过的专用模型**占据；大模型（LLM）的代码/语义能力虽受关注，但「ChatGPT 这种对话式大模型在 Text-to-SQL 上到底行不行、行到什么程度」缺乏全面评测。
- **前人未解决 / 痛点（逐条，据摘要）**：
  1. 缺乏**首个**对 ChatGPT Text-to-SQL 能力的**全面分析**。
  2. 已有评测往往只在单一基准（如 Spider）上做，未覆盖**不同语言、不同设定、不同场景**的多样性。
  3. 不清楚零样本 ChatGPT 与「需微调的 SOTA」之间真实的差距与各自的相对优势场景。

## 2. 核心方法
- **最直观类比**：就像给一个从没见过考试卷的「超级考生」发题目（只给说明、不给例题），看他在 12 套风格迥异的试卷上能拿多少分，再和「刷过同类题的尖子生」比一比。
- **具体做法（输入→关键操作→输出）**：
  - **输入**：自然语言问题 + 数据库 schema + 提示（prompt，zero-shot 设定，不提供训练样例）。
  - **关键操作**：在 **12 个基准数据集**上做实验，这些数据集覆盖**不同语言、不同设定、不同场景**；以 zero-shot 方式让 ChatGPT 生成 SQL，并与当时需要微调的 SOTA 模型对比。
  - **输出**：一份覆盖多维度的大规模评测结果，刻画 ChatGPT 的强项与差距，并把 ChatGPT 生成的数据公开。
- **形式化要点（点出核心思想）**：核心思想是「用**广度（12 个异构基准）**而非单点来评估一个通用大模型的能力边界」；关键设定是 **zero-shot**（超参数层面即「不给示例」）。🔧 具体 prompt 模板、是否用自一致性（self-consistency）等细节以原论文为准。
- **理论性质 / 保证**：这是**实证评测论文**，不提供理论保证；贡献在于「系统性结论 + 公开数据」。

## 3. 变体 / 工程版（如有）
- 摘要点名一个具体场景 **ADVETA (RPL)**：在该设定下，**零样本 ChatGPT 甚至比需要在 Spider 上微调的 SOTA 模型高出 4.1%**（🔧 该百分点的具体指标/口径以原论文为准）。这说明在某些场景，免训练的通用大模型已具实用竞争力。
- 作者把 **ChatGPT 生成的数据公开**于 https://github.com/THU-BPM/chatgpt-sql，便于后续研究复现与扩展。

## 4. 实验结论（概览）
- **数据集**：**12 个基准**，覆盖不同语言、设定、场景（🔧 具体 12 个数据集名称、各自规模以原论文为准）。
- **对比基线**：与当时各基准上的 **SOTA 模型**（需微调）比较。
- **结论方向概述（摘要明示）**：
  1. ChatGPT 具备**很强的 Text-to-SQL 能力**；
  2. 与当时 SOTA 仍有**差距**，但考虑这是 zero-shot（无训练），表现已「令人印象深刻（impressive）」；
  3. 在 ADVETA (RPL) 场景，零样本 ChatGPT 甚至**超过需微调的 SOTA 4.1%**，显示实用潜力。

## 7. 2026 视角（🔧）
- Text-to-SQL 已成为大模型「数据分析/Agent」能力的标准评测与落地场景之一；从 ChatGPT 到各类开源/闭源大模型，zero-shot / few-shot Text-to-SQL 已广泛用于对话式 BI、NL 查数。近年趋势是在更大模型、更强提示（如思维链、schema 链接）与「text-to-SQL Agent」上持续刷新 SOTA（🔧 当前最佳模型与基准以最新榜单为准）。

## 8. 新手学习路线
- **10 分钟**：读摘要 + 第 0 节，弄懂 Text-to-SQL 是什么、zero-shot 与微调的区别、本文「首个全面评测」的定位。
- **30 分钟**：精读第 2、4 节，理解「12 个异构基准」的广度意义与 ADVETA(RPL) 反超 SOTA 的案例，并跑通仓库里的一个最小评测脚本（以 README 为准 🔧）。
- **进阶**：自己用一套 prompt 模板在 Spider 的 dev 集上测 ChatGPT（或任一开源模型），对比 exact match 与 execution accuracy，体会 zero-shot 的强项与典型失败模式（如复杂 JOIN、嵌套子查询）。
