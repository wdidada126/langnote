## 一句话总结
学习型查询优化器以前爱「预测每个查询计划的绝对执行时间」，但延迟动辄差几个数量级，很难预测准。COOOL 换了个务实思路：不猜绝对耗时，只学「哪个计划更快」的相对排序（Learning-To-Rank），再以 hint 形式推荐给 DBMS——训练更快、可解释、还能一个模型跨多个数据集。

## 0. 给新手的阅读前置（背景知识地图）

- 子方向解决什么大问题：查询优化器决定一条 SQL 怎么执行（join 顺序、扫描方式等），选错计划可能慢百倍。传统基于代价的优化器（CBO）依赖代价模型与基数估计，统计信息过期或分布复杂时就出错。学习型优化想用机器学习补这个短板。
- 为什么难：
  1. 直接把 DBMS「整个换成学习型优化器」代价太高、不可解释、出了错难归因；
  2. 预测绝对延迟极难：同一查询的不同计划，延迟可能从毫秒跨到小时；
  3. 硬件/数据一变，预测模型就失效。
- 主流解法几类（表格）：

| 类别 | 直觉 | 代表工作 |
|------|------|----------|
| 学习型基数/代价估计 | 修好优化器的「输入」 | MSCN、NeuroCard 等基数模型 |
| 端到端学习型优化器 | 模型直接选计划/join 顺序 | Neo、Balsa |
| per-query hint 推荐 | 保持原优化器，仅按查询推荐 optimizer hint | Bao（regression 版）；本文 COOOL（ranking 版） |
| 传统调参 | 调优 DBMS 全局参数 | Ottertune 等 |

- 本文属于：per-query hint 推荐类，是 Bao 一类工作的「回归 → 排序」升级版。
- 关键名词直觉：
  - optimizer hint：写在 SQL 里的小指令（如 PostgreSQL 的 pg_hint_plan 扩展语法），强制优化器采用某个计划（如「用 hash join」），是「不动优化器内核、只给建议」的低侵入手段。
  - Learning-To-Rank（LTR）：推荐系统里常用的学习目标——不预测绝对分数，只要求模型把「更好的项」排在前面。
  - join-order-benchmark（JOB）：一个多表 join 的真实负载基准，学习型优化论文的常用考场。

## 1. 问题背景与动机

- 前人工作简述：机器学习进入查询优化的三条路——学习代价建模、学习基数估计、端到端学习优化器——都有代表工作；Bao 提出务实的 per-query hint 推荐方案，让 DBMS 保留原优化器，仅由模型推荐 hint 集。
- 前人缺陷/未解决问题（逐条，摘要明确点名两点）：
  1. 回归框架预测绝对延迟不可行：同一查询各计划的延迟可跨多个数量级，回归模型在这种长尾分布上预测极难（预测值差一点，计划选择就翻转）；
  2. 每个数据集要单独训练模型：跨库/跨负载不能复用，限制了实际落地；
  3. （隐含）学习型方法普遍被诟病训练久、不可解释、集成成本高——本文以此为设计约束。

## 2. 核心方法

- 最直观类比：以前是让学生（模型）给每道菜精确打「多少卡热量」（绝对延迟），太难；现在只让学生把菜单从健康到不健康排序（相对排序），点菜时选第一名就行——任务简单得多，也稳得多。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：查询及其候选计划的特征表示（计划结构、操作符、基数/代价信息等 🔧 特征细节查原文）；
  2. 关键操作：用 Learning-To-Rank 方法训练模型，学习查询计划代价的相对排序分数——同一查询的候选计划互相比较，快的排前；并设计了跨数据集的统一模型训练方式（解决「一库一模型」问题）；
  3. 输出：对每条查询，把最优计划对应的 hint 推荐给 DBMS 执行（实现于 PostgreSQL）。
- 形式化要点：排序分数 s(plan) 满足：对同查询的两计划 p1、p2，若 latency(p1) < latency(p2) 则应学得 s(p1) > s(p2)；论文给出理论论证：这种排序目标在区分不同延迟计划上是有效的（可分辨性证明，🔧 定理细节查原文）。
- 理论性质/保证：证明了 COOOL 的排序学习能正确区分延迟不同的计划（摘要宣称 "theoretically valid to distinguish query plans with different latencies"）。

## 4. 实验结论（概览）

- 平台与数据集：PostgreSQL 上实现；join-order-benchmark（JOB）与 TPC-H。
- 对比基线：PostgreSQL 原生优化器；Bao 类最先进（SOTA）方法。
- 指标：查询延迟/优化质量（🔧 精确指标定义查原文，如 geometric mean latency 改善）。
- 结论方向：单数据集任务与多数据集统一模型任务上均优于 PostgreSQL 与 SOTA；实验还从表示学习视角解释了排序为何优于回归。

## 7. 2026 视角（🔧）

- 「不动内核、按查询推荐计划」是学习型优化里最先落地工业的路线之一；云厂商（如华为 GaussDB、AWS、阿里）均公开提及基于学习的计划选择/自适应优化（🔧 各家细节以公开资料为准）。
- 趋势：(1) LTR/对比学习目标在计划选择上被广泛采用，替代绝对延迟回归；(2) 跨库可迁移（unified model）成为卖点；(3) 与自适应执行（中途换计划）结合。COOOL 在「排序目标 + 跨数据集 + 可解释性」三点上正是这波趋势的早期代表。
