## 0. 给新手的阅读前置（背景知识地图）

- **子方向解决什么大问题**：Text-to-SQL 要把自然语言问题翻译成可在真实数据库上执行的 SQL。BIRD-SQL 是贴近真实脏数据的大基准，SOTA 的执行准确率（EX）距人类专家仍远，且顶尖方案又慢又贵（反复调用大模型）。
- **为什么难**：schema 大而杂、问题有歧义、数据有噪声；排行榜上「堆算力」（多次采样+自洽投票+GPT-4）能提分但成本爆炸。
- **几类主流解法**：

| 路线 | 代表直觉 | 代价 |
|------|----------|------|
| 微调专用模型 | 用标注数据训练/微调一个 SQL 专精模型 | 要数据与训练管线 |
| Prompt + ICL | 给大模型塞 schema + few-shot 示例 | 每问都花大模型钱 |
| 检索增强（RAG） | 检索相似问句/示例/文档拼进 prompt | 检索库质量决定上限 |
| 候选生成+重排 | 多次生成再投票/重排 | 准确但慢且贵 |

- **本文属哪类**：微调 + 多样化 RAG + 输入输出格式工程的组合拳，主打「低成本高 EX」。
- **关键名词直觉解释**：
  - *EX（execution accuracy）*：生成的 SQL 在数据库上跑出来的结果与标准答案一致即算对，是 BIRD-SQL 官方指标。
  - *RAG（检索增强生成）*：先从库里检索相关示例/信息，再让 LLM 基于这些上下文作答。
  - *BIRD-SQL*：一个包含大表、脏数据、外部知识的真实感 Text-to-SQL 基准（对比 Spider 更接近工业现实）。

## 1. 问题背景与动机

- 前人工作：LLM 时代的 Text-to-SQL 在 BIRD-SQL 上以执行准确率衡量仍远低于人类专家水平；榜单头部方法靠昂贵模型与多次调用堆精度。
- 前人缺陷（论文摘要逐条指出）：
  1. **准确率天花板**：SOTA EX 距人类专家仍差距明显；
  2. **速度与成本**：最准确的方法速度慢、调用成本高，难以实用；
  3. **输入输出格式粗放**：常规 prompt 形式没有充分挖掘 LLM 的 SQL 能力。

## 2. 核心方法

- **最直观类比**：考试想提分，要么请名师（GPT-4）反复讲题（多次采样），要么自己刷错题本（微调）+ 准备一叠精选例题卡片（RAG），考前扫一眼就能答题。Dubo-SQL 证明：卡片准备得足够「多样化」+ 刷够题（低成本微调），普通学生（GPT-3.5 Turbo）也能考赢名师裸考。
- **具体做法（输入 → 关键操作 → 输出）**：
  - 输入：自然语言问题 + 数据库 schema（BIRD-SQL 任务）；
  - 关键操作：
    1. **多样化检索增强**：检索多路、多来源的上下文（示例对、相似问句等），拼装进 prompt；
    2. **低成本微调**：在标注数据上微调较小模型，习得 SQL 生成能力；
    3. **输入/输出格式工程**：设计新的 prompt 输入格式与答案输出格式，帮助 LLM 提升 EX；
  - 输出：可执行 SQL。
- **两个版本**：
  - **Dubo-SQL v1**：主打微调路线，使用低成本 GPT-3.5 Turbo；
  - **Dubo-SQL v2**：改用 GPT-4 Turbo，并用 RAG 替代微调，进一步提升 EX。
- **形式化要点/理论性质**：工程方法论文，无定理级保证；核心贡献是系统设计与评测结果。

## 3. 变体 / 工程版（如有）

- v1（微调 + RAG + GPT-3.5 Turbo）与 v2（RAG 替代微调 + GPT-4 Turbo）本身就是同一框架的两个工程变体，体现了「预算-精度」可调的设计哲学。

## 4. 实验结论（概览）

- 对比基线：BIRD-SQL 排行榜上的 SOTA 方法（含基于 GPT-4 的方案）🔧 具体基线清单查论文。
- 数据集：**BIRD-SQL**（dev 集与留出测试集 holdout test set）。
- 指标：执行准确率（EX）。
- 结论方向（摘要核实）：
  1. **v1 在 BIRD-SQL 留出测试集上创下 EX 新纪录**；
  2. v1 仅用 GPT-3.5 Turbo 却**超越了使用更昂贵 GPT-4 的次优模型**，并领先次优 GPT-3.5 方案 **20% 以上**；
  3. **v2 在 dev 集上性能更高**（RAG + GPT-4 Turbo）。
- 🔧 精确 EX 数字（v1/v2 在 dev 与 test 的具体分值）查原论文后补。

## 7. 2026 视角（🔧）

- BIRD-SQL 与 Spider 2.0 已成为 LLM 时代 Text-to-SQL 的两大标杆；「schema linking + 多样化 few-shot 检索 + 候选选择」的 RAG 配方成为工业界标准打法。
- 趋势：用强模型蒸馏微调开源小模型（降低推理成本）、SQL 生成与代理（agent）式执行验证结合、以及把外部知识/业务术语表纳入检索源。
- 本文验证的「低成本模型 + 好检索可以打赢贵模型裸考」结论，正是当前企业落地选型（自托管小模型 vs API 大模型）的核心论据之一。

- **10 分钟**：读摘要 + 本笔记第 0 节，记住「v1 微调省钱创纪录、v2 RAG 换装再抬分」。
- **30 分钟**：读 BIRD-SQL 官网/论文了解 EX 与 dev/test 划分；浏览 dubo-sql 仓库 README，对照论文看 prompt 模板长什么样。
