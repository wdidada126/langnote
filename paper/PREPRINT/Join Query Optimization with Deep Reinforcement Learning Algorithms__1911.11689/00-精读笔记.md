## 一句话总结

本文提出 FOOP（Fully Observed Optimizer）——一个基于深度强化学习（DRL）的连接顺序优化通用框架：把连接顺序搜索建模为「完全可观测」的马尔可夫决策过程，框架本身与具体 RL 算法解耦，可插拔不同学习算法；实验发现 PPO（策略梯度类）显著优于 Q-learning 类算法，且多模型 ensemble 还能进一步改进结果。

## 0. 给新手的阅读前置

- **连接顺序优化（join order optimization）是什么**：一条 SQL 多表连接查询有很多种执行顺序（join order），不同顺序的代价可能相差几个数量级。传统优化器用动态规划（小查询）或启发式（大查询）来选顺序，但估计误差会让选择失控。
- **为什么要用 RL**：连接顺序搜索天然像「下棋」——每一步选一张要连接的表/一种连接方式，最终目标是最小化总执行代价。RL 智能体通过与环境（代价模型/真实执行）交互试错来学出策略。
- **需要的背景**：MDP、Q-learning 与策略梯度（PPO）的基本区别（value-based vs policy-based）；join tree 的概念（left-deep/bushy）；代价估计（cardinality estimation）的基本概念。
- **一句话读法**：这篇是 2019 年的早期探索性工作，价值在于「框架通用性 + 算法横向对比」；如果你是新手，建议先读它建立框架视角，再去读 Balsa、Lero 等更成熟的后续工作（见第 6 节）。

## 1. 问题背景与动机

- 传统基于代价的优化器（CBO）依赖基数/代价估计，估计误差在大连接查询上会被放大，导致次优计划。
- 2015 年前后开始出现学习型查询优化（learned query optimization）的探索，但各工作大多绑定特定算法与特定场景，难以横向比较「到底哪种 RL 算法更适合这个问题」。
- 作者动机：提供一个**算法无关**的 DRL 框架（FOOP），在统一的问题建模下系统比较不同 RL 算法在连接优化上的表现，回答「用哪种 RL 算法、怎么用」。
- 名字中的 Fully Observed 指：智能体在每一步都能完整观测到当前状态（已连接的表集合等），即把问题建模为完全可观测 MDP，而不是像部分工作那样做部分观测。

## 2. 核心方法

1. **建模为 MDP**：状态 = 当前已连接的表/中间结果集合；动作 = 选择下一个参与连接的表或连接方式；奖励与最终计划代价挂钩。
2. **框架与算法解耦**：FOOP 定义统一的状态/动作/奖励接口，DQN（Q-learning 类）、PPO（策略梯度类）等算法均可作为「插件」接入同一框架训练。
3. **横向对比**：在同一框架、同一数据与代价模型下比较不同算法，得到明确结论——**PPO 显著优于 Q-learning 类算法**。
4. **ensemble 改进**：训练多个模型并对它们的结果做集成，可进一步降低次优计划的概率。

## 3. 方法细节

- **动作空间设计**：从「尚未连接的表」中选择下一步连接对象，逐步构造连接树；完全可观测的状态表示使策略网络能直接利用全局信息（具体的状态编码/网络结构 🔧 待补）。
- **奖励设计**：以计划执行代价（或其代理指标）构造奖励，具体归一化/稀疏奖励处理方式 🔧 待补。
- **PPO vs Q-learning 的直观解释**（论文结论）：value-based 方法（Q-learning/DQN）在这类大动作空间、奖励延迟的问题上收敛与稳定性欠佳；策略梯度（PPO）通过策略直接优化 + 信任域约束更稳。
- **ensemble**：多个独立训练的策略对同一查询给出计划候选，取代价最优者（具体集成策略 🔧 待补）。
- 实验所用数据集（如 JOIN Order Benchmark / StackExchange 等）、代价模型是真实执行还是估计器 🔧 待补。

## 4. 实验结论（概览）

- **结论要点**（据摘要）：
  - PPO 显著优于 Q-learning 类算法（同一框架下的受控对比）；
  - ensemble 能带来额外改进。
- 「显著优于」的具体幅度、对比了哪几种算法、基准查询集与统计口径 🔧 待补（需精读原文实验章节）。
- **可复现实验**：官方代码 https://github.com/heitzjon/mt-join-query-optimization-with-drl （仓库名中的 `mt` 指向其研究项目背景；许可与运行环境 🔧 使用前请自行确认）。

## 5. 局限与讨论

- 作为 2019 年的早期工作：未（在 arXiv 元数据层面可见）给出正式发表 venue，影响力主要通过后续工作体现；实验规模与后续 SOTA 工作相比偏小 🔧。
- 优化目标与代价模型的耦合：若使用估计器作代理，学习到的策略会继承估计误差（这正是后续 Balsa 等工作用真实执行反馈改进的点）。
- 泛化性：训练出的策略对未见过的查询模板/数据分布的迁移能力 🔧 待补。
- 论文的价值更多在「方法论与算法比较」层面，而非提出一个可直接投产的优化器。

## 6. 与同方向论文的关系（本仓库互链）

FOOP 是学习型查询优化（LQO）方向上「RL 算法比较」的早期代表，建议与下列仓库内论文对照：

| 相关论文 | 仓库位置 | 关系 |
|----------|----------|------|
| Balsa: Learning a Query Optimizer Without Expert Demonstrations | `paper/SIGMOD/Balsa- Learning a Query Optimizer Without Expert Demonstrations__2201.01441` | 后续成熟工作：不依赖专家演示、用真实执行反馈训练，回应了「代理代价模型误差」问题 |
| Lero: A Learning-to-Rank Query Optimizer | `paper/VLDB/Lero- A Learning-to-Rank Query Optimizer__2302.06873` | 换一条技术路线：不做单计划生成，而是对候选计划做 pairwise 学习排序 |
| Is Your Learned Query Optimizer Behaving As You Expect? (PVLDB 17) | `paper/VLDB/Is Your Learned Query Optimizer Behaving As You Expect- A Machine Learning Perspective__2309.01551` | 对 LQO 做系统化 ML 视角评测；同一作者团队（Stockinger）的后续工作，正好回应「LQO 是否真的更好」 |
| POLAR: Adaptive and Non-invasive Join Order Selection via Plans of Least Resistance | `paper/VLDB/POLAR- Adaptive and Non-invasive Join Order Selection via Plans of Least Resistance__p1350-justen.pdf` | 非侵入式 join order 选择路线，可与 FOOP 的「替换式优化」对照 |
| Debunking the Myth of Join Ordering (2025) | `paper/PREPRINT/Debunking the Myth of Join Ordering- Toward Robust SQL Analytics__2502.15181` | 从另一面质疑：join ordering 在现代分析场景是否真有那么重要 |
| Hype or Heuristic: Quantum Reinforcement Learning for Join Order Optimisation | `paper/UNKNOWN/Hype or Heuristic- Quantum Reinforcement Learning for Join Order Optimisation__2405.07770` | 把 RL 框架延伸到量子 RL 的同问题研究，可视为 FOOP 式「算法横向比较」思路的延续 |

**谱系一句话**：FOOP（2019，RL 算法框架化比较）→ Balsa（2022，无演示自举训练）→ Lero（2023，学习排序）→ 系统评测（2023-2025，检验 LQO 的真实价值）；JoinGym（2023）则把「训练与评测环境」本身标准化。

## 7. 新手学习路线（给谁读/怎么用）

- **适合读者**：想进入学习型查询优化方向的新手（用它建立「连接优化 = MDP」的框架认知）；要做 RL 算法选型比较的工程团队；研究 RL 在组合搜索问题中应用的读者。
- **实践建议**：先跑官方仓库复现 PPO vs Q-learning 的对比，理解状态/动作/奖励设计；再决定是否引入更现代的 LQO 方案。不要直接把 FOOP 当生产可用优化器。
- **延伸阅读顺序建议**：本文 → Balsa → Lero → 2309.01551（冷静的评测视角）。
