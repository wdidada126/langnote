## 一句话总结

要测试"数据质量监控系统"好不好使，你得先制造脏数据。Badgers 是一个可扩展的 Python 库，**按需生成带缺陷的数据**——异常值、类别不均衡、分布漂移等，覆盖表格、时间序列、文本等多种模态，专门给数据质量类实验当"造污器"。

## 0. 给新手的阅读前置（背景知识地图）

- **大问题**：AI/ML 应用对数据质量极其敏感。要评估"脏数据会不会把模型搞坏"或"质量监控器能不能报警"，必须先有**可控、可复现的脏数据**。真实数据脏得千奇百怪却不可控，所以需要合成缺陷。
- **为什么难**：缺陷类型繁多（离群、缺失、漂移、不均衡、噪声……），且不同数据模态（表格/时序/文本）注入方式完全不同；还要保证"除了注入的缺陷，其他统计性质尽量不变"，否则实验失真。
- **主流做法对比**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 手工脚本 | 各论文自带污染代码 | 随写随用 | 不可复用、难复现 |
| 基准数据集自带脏版 | 部分竞赛数据 | 开箱即用 | 缺陷类型固定 |
| 统一缺陷生成库 | **Badgers**、Desbordante 等 | 把缺陷类型做成可组合的生成器 | 可扩展、可复现（本文路线） |

- **本文属于哪类**：第三类的通用 Python 实现，强调"库"而非"数据集"。
- **必须先懂的名词**：
  - **数据质量缺陷（deficit）**：数据中偏离预期特性之处，如离群点、概念漂移。
  - **概念漂移（drift）**：数据分布随时间变化，常见于时序/流数据。
  - **模态（modality）**：数据的形态，本文支持表格、时序、文本等 🔧（完整清单见文档）。

## 1. 问题背景与动机

- 前人工作：各数据质量研究团队各自实现注入脚本；部分工具聚焦单一缺陷类型（如只做异常检测评测集）。
- 未解决的问题：
  1. 缺陷生成逻辑散落在各处，无法跨研究复用；
  2. 多模态支持稀缺；
  3. 缺少统一的扩展接口，新增缺陷类型要大改代码。

## 2. 核心方法

- 类比：像"调料包工厂"——每 种缺陷是一个独立调料包（生成器），你选数据（菜）、选缺陷（调料）、控制剂量（参数），工厂按配方产出脏数据。
- 具体做法（输入 → 操作 → 输出）：
  1. 输入：干净数据集 + 缺陷类型 + 缺陷参数（比例、幅度等）；
  2. 通过统一的生成器接口（可插拔）对数据施加变换；
  3. 输出：带缺陷的数据集（保持其余统计特征，🔧 具体保真机制见文档/源码）。
- 设计要点：**可扩展性**优先——新增一种缺陷只需实现一个生成器类，不用改库的其他部分；按模态组织生成器家族。
