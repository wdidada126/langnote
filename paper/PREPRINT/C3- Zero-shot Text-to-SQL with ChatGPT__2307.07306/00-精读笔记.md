## 一句话总结

不训练、不微调，只用 ChatGPT 零样本做 Text-to-SQL：把"清晰提示（CP）+ 带提示的校准（CH）+ 一致性输出（CO）"三招组合起来，在 Spider 测试集上拿下 82.3% 执行准确率，成为当时的零样本 SOTA。

## 0. 给新手的阅读前置（背景知识地图）

- 子方向解决什么大问题：传统 Text-to-SQL 模型要在目标领域标注数据上微调；LLM 时代想问的是——不训练、直接问（zero-shot），ChatGPT 能把自然语言翻成 SQL 吗？瓶颈从"训练"转移到"怎么把数据库信息喂进 prompt"。
- 为什么难：
  - 数据库 schema 很大，prompt 放不下全部表/列，要先检索相关的表和列；
  - ChatGPT 对数字/条件有系统性偏差（倾向按字符串排序理解数值、忘记 DISTINCT 等），需要"校准"；
  - 一次生成不稳定，需要输出层面的后处理。
- 几类主流解法：

| 路线 | 代表 | 特点 |
|------|------|------|
| 微调式语义解析 | RAT-SQL、BRIDGE、RESDSQL | 需目标领域训练数据 |
| LLM 零样本 prompting | 本文 C3、DIN-SQL 等 | 不训练，靠 prompt 设计 |
| LLM 微调/专用模型 | CodeS 等 | 折中路线 |

- 本文属哪类：LLM 零样本 prompting 路线的系统化代表作。
- 关键名词直觉：
  - Clear Prompting（CP）：把 prompt 分成"清晰的三段式"——指令区、数据库 schema 区（含相关表/列/单元格值）、问题区，各部分用显式标记隔开；
  - Calibration with Hints（CH）：在 prompt 里塞"提示"来矫正模型已知偏差（比如提醒它 DISTINCT、按值域理解比较条件），属于对模型 bias 的外部校准；
  - Consistent Output（CO）：对输出做一致性处理（如多个候选/规范化后选择），保证输出稳定可用。

## 1. 问题背景与动机

- 前人工作：BRIDGE/RAT-SQL 等微调模型在 Spider 榜推进；GPT-3/ChatGPT 出现后，少量工作测试了 LLM 做 Text-to-SQL，但零样本成绩远落后于微调模型，且 prompt 构造随意。
- 前人缺陷（论文针对的问题）：
  1. 已有零样本尝试成绩低，缺乏系统化的 prompt 设计方法论（输入、模型偏差、输出三层面各管各的）；
  2. schema 太大时直接全量塞 prompt 效果差、成本高；
  3. ChatGPT 在 Text-to-SQL 上的系统性偏差没有被针对性处理。
- 动机：给零样本 Text-to-SQL 一套端到端的系统化处理方案，验证纯 prompting 能否逼近甚至超过微调模型。

## 2. 核心方法

- 最直观类比：向一位很聪明但没见过你家数据库的实习生派活：先把任务说明、数据库说明书、你的问题分三个清楚的小节写给他（CP）；再附一张"常见坑提醒"小抄（CH）；最后收到回复后按统一规矩检查、挑选（CO）。
- 具体做法（输入→关键操作→输出）：
  1. 输入：自然语言问题 + Spider 数据库 schema；
  2. Clear Prompting：用 GPT-3.5 embedding 先做 schema linking（召回问题相关的表与列），再构造结构化 prompt：指令 / DB 信息（含相关 schema、单元格值提示）/ 问题三段分明；
  3. Calibration with Hints：向 prompt 注入针对性提示，矫正 ChatGPT 的已知偏差（模型 bias 层面）；
  4. Consistent Output：对模型输出做一致性处理（输出规范化/多候选一致性选择，具体机制 🔧 查原论文）；
  5. 输出：SQL 查询，直接在数据库上执行。
- 形式化要点：零样本设定下不更新任何参数；方法定义为三元组 C3 = (CP, CH, CO)，分别作用于模型输入、模型偏差、模型输出三个正交层面。
- 理论性质/保证：无定理；贡献在于系统化的实验验证与各组件消融。

## 5. 开源代码与动手实践

- 仓库地址：https://github.com/bigbigwatermalon/c3sql （官方实现；2026-09-27 确认存活）
- 语言：Python（依赖 OpenAI API）。
- 典型流程（README 核实，2026-09-27）：
  ```bash
  # 1) 准备 Spider 数据
  mkdir data
  unzip spider.zip
  mv spider/database .
  mv spider data
  # 2) 运行推理（预测结果写入 predicted_sql.txt）
  bash run_c3sql.sh
  # 3) 评测：在 generate_sqls_by_gpt3.5.py / column_recall.py / table_recall.py
  #    中填入 openai.api_key，再克隆官方评测器 test-suite-sql-eval
  git clone https://github.com/taoyds/test-suite-sql-eval third_party/
  python third_party/test-suite-sql-eval/evaluation.py --gold dev_gold.sql \
      --pred predicted_sql.txt --db database --table data/spider/tables.json --etype all
  ```

## 7. 2026 视角（🔧）

- C3 是"LLM + 检索式 schema linking + 结构化 prompt"配方的标志性早期工作，该配方至今仍是工业 Text-to-SQL（BI Copilot、ChatBI）的骨架；
- 2024-2026 年主流已演进为：专用 Text-to-SQL 模型（CodeS）、多生成器集成（XiYan-SQL）、强化学习对齐（Arctic-Text2SQL-R1），Spider 推理成绩远超 82.3%，但 C3 的三层面拆解（输入/偏差/输出）仍是分析新方法的好框架；
- "输出一致性"思想演化为 self-consistency 多采样投票，成为 LLM SQL 生成的标配技巧 🔧。
