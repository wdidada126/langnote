## 一句话总结

数据湖里堆着一堆邮件、网页、文档之类的非结构化文件，EVAPORATE 用 LLM 把它们变成能 SQL 查询的表格——更妙的是它不逐篇去问大模型，而是让 LLM 写"抽取程序"，挑出好的用弱监督集成，处理 1 万篇文档平均省 110 倍的 token。

## 0. 给新手的阅读前置（背景知识地图）

- 子方向解决什么大问题：数据管理社区的老梦想——给系统喂任意半结构化/非结构化文档，自动吐出可查询的表格（"结构化视图"），全程无需人工建模或领域定制训练。
- 为什么难：文档类型千差万别（邮件、论文、财报……），传统信息抽取系统每换一类文档就要重写规则/重训模型；用 LLM 直接逐篇抽取又贵得离谱（1 万篇文档 × 每次几千 token）。
- 几类主流解法：

| 路线 | 直觉 | 代价/质量 |
|------|------|-----------|
| 领域定制 NER/IE 模型 | 每类文档单独训练 | 便宜但无通用性 |
| LLM 直接抽取 | 每篇文档都过一遍大模型 | 质量高、成本爆炸 |
| LLM 合成代码 | 让 LLM 写抽取函数，代码复用 | 便宜但质量掉 |
| 本文 EVAPORATE-CODE+ | 写一堆候选函数 + 弱监督集成挑出好组合 | 便宜且质量反超直接抽取 |

- 本文属哪类：LLM 驱动的数据湖结构化视图系统，核心贡献是把"直接抽取 vs 代码合成"两条路线的取舍讲清楚并给出第三条路。
- 关键名词直觉解释：
  - *结构化视图*：对非结构化语料的一个"虚拟表"，每行是一篇文档、每列是抽取出的属性，之后可正常 SQL 查询。
  - *代码合成*：不让 LLM 直接输出抽取结果，而是输出 Python 函数，函数可以廉价地跑在所有文档上。
  - *弱监督（weak supervision）*：不追求单个标注完美，而是把多个"不太准"的来源投票/加权集成，得到比单个来源更可靠的结果（Snorkel 思想）。

## 1. 问题背景与动机

- 前人工作：信息抽取领域有大量领域定制系统；数据社区曾尝试规则/众包构建视图；2023 年前后 LLM 展示了零样本抽取能力，但成本问题普遍被回避。
- 前人的缺陷（论文动机）：
  1. 最先进系统为保准确率做出简化假设并依赖领域特定训练，换一类文档就失效；
  2. LLM 逐文档直接抽取质量最好，但 token 成本随文档量线性增长，真实数据湖规模下不可行；
  3. 简单的代码合成虽便宜，抽取准确率却远低于直接抽取，之前没有系统办法兼顾成本与质量；
  4. 缺少在多个真实场景、规模化文档集上的系统评测。

## 2. 核心方法

- 最直观类比：要从 1 万份简历里建一张"姓名/学历/工作年限"表。直接抽取 = 请资深 HR 逐份看（贵且准）；代码合成 = 让 HR 写一套筛选规则交给实习生跑（便宜但规则常出错）；EVAPORATE-CODE+ = 让 HR 写出几十套规则，再用少量抽查结果判断"哪套规则在哪些字段上可信"，加权投票出最终表格——只抽查一小部分，成本近似实习生，质量反超资深 HR。
- 具体做法（输入→关键操作→输出）：
  1. 输入：异构文档语料（每个场景约 1 万篇）+ 目标 schema 的自然语言任务描述；
  2. 让 LLM 少量阅读文档，发现候选属性并生成大量候选抽取函数（代码）；
  3. 对文档做亚线性采样，用 LLM 在样本上评估各函数输出，通过弱监督集成学出每个函数的权重（好的函数权重高）；
  4. 输出：全语料上的结构化视图（虚拟表），供 SQL 查询。
- 形式化要点：两条本质策略被形式化为"每文档调用 LLM"（成本线性）与"每文档运行合成函数"（成本近零）；弱监督集成把函数输出当作弱标注源建模（🔧 数学形式查原文第 3-4 节）。
- 理论性质：LLM 遍历次数相对文档量是亚线性的，这是成本优势的来源（实证性质，非渐进理论证明）。

## 3. 变体 / 工程版

- EVAPORATE（基础版）：对比直接提示与代码合成两条策略；
- EVAPORATE-CODE+（扩展版）：生成大量候选函数 + 弱监督集成，质量超过直接抽取，且只需对文档做亚线性 LLM 遍历——论文的推荐形态。

## 4. 实验结论（概览）

- 基线：LLM 直接抽取、朴素代码合成，以及当时最先进的信息抽取/视图构建系统（🔧 名单查原文实验节）。
- 数据集：16 个真实评测场景，每场景约 1 万篇文档（涵盖多种文档类型）。
- 指标：抽取质量（F1 类指标 🔧）与 LLM 处理 token 量。
- 已核实的关键数字（来自 arXiv 摘要）：EVAPORATE-CODE+ 在 16 个场景中平均减少 110 倍的 LLM 处理 token 量，同时质量优于直接抽取与最先进系统。
- 结论方向：代码合成的成本-质量权衡真实存在，但"多候选 + 弱监督集成"可以同时拿到便宜与高质量。

## 7. 2026 视角（🔧）

- 本文的"代码合成 + 弱监督集成"是后来"语义算子/语义查询优化"浪潮的先声：2025 年起 LOTUS、Palimpzest 等系统把 LLM 调用当作可优化的查询算子，核心仍是"能用便宜算子就不用贵模型"。
- 110 倍 token 节省的思路在今天演化为：小模型/蒸馏模型粗筛 + 大模型精审的级联，已成为 LLM 数据系统工程的标配。
