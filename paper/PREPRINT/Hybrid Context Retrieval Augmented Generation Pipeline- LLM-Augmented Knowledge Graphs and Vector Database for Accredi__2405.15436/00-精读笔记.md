## 一句话总结

商学院维护 AACSB 认证报告是个「翻海量文件、对着标准逐条写证据」的苦活。本文把机构数据与 AACSB 标准同时存进知识图谱 + 向量数据库两个知识库，用混合检索增强 LLM 生成报告内容，并用 RAGAs 框架验证了效果。

## 0. 给新手的阅读前置（背景知识地图）

- 大问题：RAG 要回答「既需要精确事实、又需要语义相似文本」的问题。纯向量检索擅长「意思相近」，但对结构化、多跳、精确关系（哪个课程支撑哪条标准）容易出错；纯知识图谱擅长精确关系，但对模糊的自然语言查询不友好。
- 为什么难：认证报告写作横跨两类需求——「标准 4.2 要求什么」（结构化事实）与「我校有哪些类似做法可以引用」（语义检索）。单一检索方式顾此失彼。
- 几类主流解法：

| 类别 | 直觉 |
|------|------|
| 纯向量 RAG | 文本切块→嵌入→检索最相似的块 |
| 纯 KG-RAG | 把知识整理成图，按图查询/遍历 |
| 混合 RAG（本文） | 两库并行检索，融合上下文后再生成 |
| 微调 LLM | 把领域知识直接训练进模型（成本高、更新难） |

- 本文属哪类：混合 RAG 的垂直领域应用系统（高等教育认证），并尝试了 LLM 自动构建 KG。
- 关键名词直觉：
  - *AACSB 认证*：国际商学院的权威质量认证，需要定期提交长篇报告证明符合多项标准。
  - *知识图谱（KG）*：用「实体—关系—实体」三元组组织的知识库，擅长精确问答。
  - *RAGAs*：一个评测 RAG 系统质量的框架，包含答案相关性、答案正确性、忠实度等指标。

## 1. 问题背景与动机

- 前人工作：通用 RAG 管线（向量检索为主）已广泛使用；KG + LLM 的结合研究逐渐增多。
- 缺陷/未解决问题（逐条）：
  1. 认证报告撰写极其耗时：需要人工对照数十条 AACSB 标准翻检机构内部数据。
  2. 纯向量 RAG 难以处理「标准 ↔ 课程/证据」这类结构化对齐关系。
  3. 人工构建 KG 成本高，领域缺乏「用 LLM 半自动建 KG」在该场景的实践验证。
  4. 缺少面向认证报告这一任务的、可评估的端到端 RAG 管线。

## 2. 核心方法

- 最直观类比：给报告撰写者配一个「双引擎资料员」——一位拿着索引卡片（向量库）擅长「按意思翻找类似材料」，一位拿着关系网（KG）擅长「精确回答 A 标准对应哪些课程」。两人各交一份资料清单，写作者（LLM）汇总后成稿。
- 具体做法（输入→关键操作→输出）：
  - 输入：机构内部数据（课程、师资、流程等）+ AACSB 标准数据。
  - 关键操作 1：把两类数据分别写入向量数据库与知识图谱两个知识库。
  - 关键操作 2：KG 构建走两条路——人工构建 与 LLM 增强构建（LLM Augmented Knowledge Graph），并做对比。
  - 关键操作 3：查询到来时，两个知识库并行检索，融合混合上下文。
  - 关键操作 4：LLM 基于混合上下文生成报告辅助内容。
  - 输出：有双重依据（grounded）支撑的报告草稿片段，供机构利益相关者使用。
- 形式化要点：管线即「query → {向量检索, KG 检索} → context fusion → LLM generation」，端到端用 RAGAs 评测。🔧 KG 模式（schema）、两库融合策略细节查原文。
- 理论性质：应用系统论文，无理论保证。

## 4. 实验结论（概览）

- 评测框架：RAGAs。
- 对比设置：不同检索/生成配置（含两种 KG 构建方式下的管线表现）。🔧 具体基线与消融配置查原文。
- 指标：answer relevancy（答案相关性）、answer correctness（答案正确性）等 RAGAs 指标。
- 结论方向：管线在 answer relevancy 与 answer correctness 两项上取得最优表现。

## 7. 2026 视角（🔧）

- 「向量库 + KG 混合 RAG」在 2025–2026 已成为企业级 RAG 的常见架构（GraphRAG 类方案大热），本文是较早一批把混合 RAG 用于垂直行政/合规文书场景的实践报告。
- LLM 自动/半自动构建 KG（从文档抽取三元组）如今在 LangChain/LlamaIndex 等生态有现成组件，本文的人工 vs LLM 建图对比仍是理解取舍的好案例。
- RAGAs 等评测框架已被广泛采用，「answer correctness + relevancy」的组合是事实型 RAG 评测的常见起点。
