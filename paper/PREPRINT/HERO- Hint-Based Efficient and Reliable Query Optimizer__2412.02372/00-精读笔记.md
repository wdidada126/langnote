## 一句话总结
不改数据库内核一行代码，靠给查询「递提示」（hint：索引选择、连接顺序、并行度 dop 等）来加速工作负载——HERO 用「可解释的上下文感知模型集成 + 图存储」取代黑盒神经网络，保证推荐永不劣化、推理快、训练省预算，在 JOB 基准上拿到 3 倍延迟改善。

## 0. 给新手的阅读前置（背景知识地图）

- 大问题：查询优化器（cost-based optimizer, CBO）依赖基数/代价估计，估错就选错执行计划，慢查询由此而生。「学习型优化」想让数据/经验来纠偏。
- 为什么难：① 计划空间指数级；② 探索本身要真的执行查询，代价高；③ 生产环境绝不能「越优化越慢」（可靠性）；④ 黑盒 NN 模型难调试、推理慢。
- 主流解法：

| 路线 | 直觉 | 代表 | 弱点 |
|------|------|------|------|
| 学习基数/代价估计 | 修 CBO 的输入 | MSCN/BayesCard 等 | 估计准≠计划好 |
| 端到端计划选择 | 直接学/选计划 | Balsa、Lero、Bao 系 | 黑盒、退化风险 |
| hint 优化（HBO） | 不改内核，挑「计划器旋钮」组合 | Bao、AutoSteer、HERO | 搜索空间指数大、无通用 hint |

- 本文属于：hint 路线（HBO），创新点在「可靠 + 快推理 + 可解释」三合一。
- 关键名词直觉：
  - Hint：发给优化器的指令（如 PostgreSQL 的 `pg_hint_plan`），强制它按指定方式生成计划——相当于「不修发动机，只调旋钮」。
  - dop（degree of parallelism）：查询并行度。HERO 把并行度也当 hint 的一部分，这是它相对前作的重要扩展。
  - JOB（Join Order Benchmark）：IMDB 数据上的 113 条多连接分析查询，学习型优化领域的标准考卷（通说 🔧）。

## 1. 问题背景与动机

- 前人工作：Bao、AutoSteer 等证明了 hint 优化的可行性（仓库 README 明引这两篇为主要前作）；另一支 NN 端到端计划优化路线也在发展。
- 前人缺陷（依摘要与 README 逐条）：
  1. 可靠性缺失：基于 NN 的 hint 推荐可能建议出更慢的计划（劣化），生产不可接受；
  2. 探索代价：hint 空间指数级，且探索一个「点」的成本 = 真的执行一次查询；
  3. 推理慢：NN 推理时延高，不适合在线逐查询决策；
  4. 黑盒不可调试：出问题无法解释，部署阻力大；
  5. 搜索空间窄：既有 HBO 工作基本只考虑算子级 hint，未纳入并行度（dop）这类系统级旋钮。

## 2. 核心方法

- 直观类比：一个老练的 DBA 记得住「上回这种查询用 hash join + dop=8 快」——HERO 把这位 DBA 的经验做成系统：新查询来了先看它和「见过的查询」像不像（基于计划树的度量），直接复用相似查询的最佳 hint；不放心时再做局部搜索补实验，且训练时间有预算上限。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：SQL 工作负载（查询 + 执行环境）；
  2. 关键操作：
     - 训练期：预算受控的训练流程 + 局部搜索算法，在 hint 空间里探索查询行为（收集计划、运行时间），解决指数空间探索问题；
     - 存储：把见过的 (查询计划特征 → hint → 实测性能) 放进图存储；
     - 推理期：上下文感知的模型集成（ensemble of context-aware models）基于相似查询给出可靠 hint——核心原则是「不冒险」，只在有把握时建议偏离默认；
  3. 输出：每条查询的 hint 集（含 dop），交给 DBMS 生成执行计划。
- 形式化要点：hint 空间定义为算子级 hint × 并行度的组合；可靠性目标形式化为「推荐延迟 ≤ 默认计划延迟」（🔧 精确形式化与树相似度度量定义查原文）。
- 理论性质：无理论证明类声明；工程保证是「可靠性优先 + 可解释（模型非黑盒）」。

## 4. 实验结论（概览）

- 对比基线：既有 NN 系 hint 优化方法（摘要称实验性证实了它们的可靠/效率/推理三挑战）；🔧 完整基线清单查原文。
- 数据集/基准：标准基准（JOB 为主，README 的 hbo_bench 提供数据底座）。
- 指标：查询延迟、训练预算、推理时间、劣化率。
- 结论方向（摘要明示）：
  1. 优化能力接近「粗粒度 hint 可达的最优」；
  2. 加入 dop 控制后，在 JOB 基准上取得 3× 延迟改善（自称树立新标准）；
  3. 推理比既有方案快 5–40×（README 明示），且模型可解释、易调试。
