## 一句话总结
DBA 想搞清楚「到底是哪些查询、因为哪些共同特征而变慢」，本文用数据挖掘里的子群发现（Subgroup Discovery）自动从海量 SQL 工作负载里挖出「同时满足某条模式、又同时推高执行时间等指标」的查询子集，并配一个可视化工具辅助定位根因。

## 0. 给新手的阅读前置（背景知识地图）
- 这个子方向解决什么大问题：在真实生产环境里，一个数据库实例每天可能跑成千上万条 SQL。当系统变慢时，DBA 想知道的不是「某一条 SQL 慢不慢」，而是「是否存在某一类 SQL（比如都是带某类 JOIN + 某环境变量 + 某告警组合）系统性地拖慢了系统」。这就是工作负载级的慢查询归因 / 模式挖掘。
- 为什么难：单条 SQL 慢可能因为锁、缺索引、数据倾斜；但要在「查询语句特征 × 环境配置 × 运行时指标 × 数据库告警」这样一个巨大组合空间里，自动找出「哪一组特征组合，对应着目标指标（如执行时间）异常偏高」的子集，搜索空间是组合爆炸的，且人很难凭经验穷举。
- 几类主流解法（简化对比）：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 人工 + 执行计划 | DBA 手查 EXPLAIN | 逐条看查询计划找瓶颈 | 可解释，但无法规模化、依赖经验 |
| 聚类 / 异常检测 | 对查询向量聚类 | 把相似查询分组再找异常组 | 能发现群体，但「为什么慢」的解释性弱 |
| 关联规则挖掘 | Apriori 类 | 找特征共现 | 与子群发现相近，但目标函数不同 |
| 子群发现（本文） | SD / 模式挖掘 | 显式优化「子群相对目标的偏差」 | 直接产出可解释的「如果…则慢」规则，适合归因 |

- 本文方法属于哪一类：属于子群发现 / 规则挖掘这一类，把它从通用数据挖掘迁移到「SQL 工作负载分析」这个具体场景，并提供了面向 DBA 的可视化。
- 2-3 个必须先懂的关键名词：
  - 子群发现（Subgroup Discovery, SD）：给定一个目标变量（如执行时间），在所有「特征组合（模式）」构成的搜索空间里，找出那些「目标变量分布显著偏离整体」的数据子集，并给每条模式打分排序。直觉：「哪一类人更容易得病」这类问题就是 SD 的经典应用。
  - 模式（pattern）：本文里模式定义在「查询子句组合 + 环境变量 + 数据库告警/指标」之上，例如「使用了子查询 且 缓存命中率低 且 出现死锁告警」。
  - 目标度量（target measure）：想解释或优化的量，如执行时间、I/O 通信量；SD 找的是「让目标度量异常高/低的子群」。

## 1. 问题背景与动机
- 前人工作简述：传统数据库自带有慢查询日志、EXPLAIN 执行计划、以及各种监控告警，但这些信息是「逐条 / 逐指标」的；把分散的信号自动综合成「可解释的慢查询根因假设」仍主要靠 DBA 经验。
- 前人未解决 / 痛点（逐条，据摘要）：
  1. DBA 能轻松定位「反复出问题的单条查询」，但难以自动识别「只共享部分属性的查询子集」——即一类查询共同构成了某种模式，又同时推高了目标指标（如执行时间）。
  2. 模式的定义空间极大（查询子句、环境变量、数据库告警、运行指标的交叉组合），自动、可解释地发现这些模式在可解释 AI（XAI）语境下很重要，但缺乏现成工具。
  3. 这类数据挖掘技术对 DBA 来说「并不显然好上手」，需要配套的交互式知识发现工具。

## 2. 核心方法
- 最直观类比：把整个 SQL 工作负载看成一张大表，每行是一条查询及其各种属性（用了什么子句、当时环境变量、有没有告警、执行多久）。SD 就像在问：「在无数种属性组合里，哪一种组合下的查询，平均比整体慢很多？」挖出来的组合就是一条「根因假设」。
- 具体做法（输入→关键操作→输出）：
  - 输入：一段时间内的 SQL 工作负载（含查询文本/子句、环境配置变量、数据库告警与监控指标、以及目标度量如执行时间、I/O 量）。
  - 关键操作：把「子群发现」这一通用数据挖掘框架实例化到 SQL 工作负载场景——即定义好「模式」如何在上述多类特征上组合、选择用于衡量「子群相对整体偏差」的质量函数（quality measure，如加权相对准确率 WRAcc 类，🔧 论文具体采用的函数以原文为准），并在巨大搜索空间里搜索/剪枝出高分模式。
  - 输出：一组「模式 → 目标度量异常」的假设（例如「某类查询模式 + 某环境变量 ⇒ 执行时间显著偏高」），作为帮助定位问题与根因的候选解释；并提供一个可视化工具做交互式知识发现。
- 形式化要点（点出核心思想）：核心思想是「用可解释的、带质量打分的描述性规则，替代黑盒的异常分数」；超参数主要是「模式的语言偏置（允许哪些特征参与组合）、质量阈值、搜索深度」等（🔧 具体设置见原论文）。
- 理论性质 / 保证：SD 本身是成熟的规则挖掘范式，提供的是可解释假设而非因果证明；文中方法重在「发现可解释的子群」与「可视化辅助」，并非给出因果根因的算法保证。
