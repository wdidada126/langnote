## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：Learned Data Structures（学习数据结构）想把 ML 与传统数据结构结合，用「预测」代替「精确查找」，换取时间/空间上的改进。两个支柱是 Learned Bloom Filter 和 Learned Index。
- **为什么难**：传统索引（B 树等）是确定性的、可证明的；换成神经网络后，准确性、延迟、内存都变成需要权衡的黑箱；且硬件趋势（GPU/TPU 优于 CPU）让人想用神经网络当积木，但缺乏系统证据。
- **几类主流解法**：

| 路线 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 学习索引（预测位置） | CDF-based learned index | 用模型预测 key 的位置 | 省内存，但训练/精度敏感 |
| 学习过滤器 | Learned Bloom Filter | 用模型减少误判 | 已在过滤器上大量用 NN |
| 本文关注 | 用 NN 做索引基石 | 对比 NN 作为索引组件 | 揭示 NN 并非即插即用 |

- **本文属哪类**：学习索引方向里的「适用性与基准」研究——聚焦「神经网络是否适合作为 Learned Index 的构建块」。
- **2-3 个必懂关键名词（直觉解释）**：
  - **Learned Index（学习索引）**：用模型（如回归/神经网络）学习数据的累积分布，直接预测某个 key 在有序数据中的大致位置，取代/加速 B 树。
  - **Learned Bloom Filter**：用神经网络判断「某个元素是否在集合里」，比经典 Bloom Filter 更省空间——这是 NN 已成功落地学习数据结构的例子。
  - **原子学习索引（atomic learned index）**：本文基准平台所针对的、最小粒度的学习索引单元。

## 1. 问题背景与动机
- **前人工作简述**：Learned Bloom Filter 已广泛用神经网络改进过滤器；但 Learned Index 这个支柱里，「是否用神经网络做构建块」几乎没人系统研究过。
- **前人缺陷/未解决问题（逐条）**：
  1. **NN 在索引中缺席**：学习数据结构两大支柱里，索引一侧缺少 NN 的系统性使用与对比。
  2. **硬件叙事未被验证**：「GPU/TPU 将取代 CPU、从而利好 NN 作索引基石」只是一种感知上的范式变化，缺实验支撑。
  3. **缺乏基准**：没有针对「原子学习索引」的比较实验平台来衡量 NN 的适用性。

## 2. 核心方法
- **最直观类比**：大家都说「用乐高电机代替发条能让时钟更好」，但没人真测过；本文第一次把各种电机装进钟里跑分，发现「得专门定制电机才行」。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：若干候选神经网络结构，作为「原子学习索引」的构建块。
  2. **关键操作**：搭建基准平台，系统地对比不同 NN 在索引任务上的时间/空间表现；评估它们相对传统结构的优劣。
  3. **输出**：实验结论——直接用现成 NN 并不理想，需要为索引专门设计高度定制化的神经网络。
- **形式化要点**：核心贡献是「首个」（first）关于 NN 作 Learned Index 构建块的对比实验分析；超参为不同网络结构与索引负载（具体🔧查原论文）。
- **理论性质/保证**：以提供「方法学上重要」的实证基础为主，无新理论保证。
