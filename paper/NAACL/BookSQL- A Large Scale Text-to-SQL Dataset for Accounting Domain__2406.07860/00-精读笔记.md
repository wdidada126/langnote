## 一句话总结

会计/财务领域的"Spider 级"数据集：10 万条自然语言查询-SQL 配对 + 百万条记录的会计数据库，实测发现包括 GPT-4 在内的 SOTA 模型在这个领域都有明显短板——专业领域 Text-to-SQL 还没被解决。

## 0. 给新手的阅读前置（背景知识地图）

- **子方向解决什么大问题**：Text-to-SQL 要把"上个季度各部门差旅费是多少"这样的自然语言问题自动翻译成 SQL。全球会计数据库的使用者大量是**非技术人员**（记账员、财务、审计），最需要自然语言查询接口，但主流数据集几乎不覆盖这个领域。
- **为什么难**：会计领域有自己的领域词汇（借贷、科目表、会计期间）、复杂的模式结构（试算平衡、多表关联记账），通用模型缺乏这类先验知识；且会计查询对**数值精确性**要求极高，差一位小数就是事故。
- **几类主流解法/数据集**：

| 数据集 | 领域覆盖 | 特点 |
|--------|---------|------|
| WikiSQL | 跨领域、单表 | 规模大但 SQL 简单 |
| Spider | 跨领域多表 200+ 数据库 | 复杂 SQL，但无会计领域 |
| BIRD | 跨领域、含脏数据 | 侧重真实大数据 |
| **BookSQL** | **会计/财务垂直领域** | 领域专精，考察领域知识 |

- **本文属哪类**：资源论文（resource paper）——贡献数据集+基准实验，而非新模型。
- **关键名词直觉**：
  - **Text-to-SQL**：自然语言问句 → SQL 查询的语义解析任务；
  - **跨领域（cross-domain）泛化**：模型没见过目标数据库的 schema，要靠 schema 描述迁移能力；
  - **执行准确率（execution accuracy）**：模型生成的 SQL 跑出来的结果集与金标准一致才算对——领域里数值、日期口径错一点就全错。

## 1. 问题背景与动机

- 前人工作：WikiSQL、Spider 等大规模数据集推动了跨领域 Text-to-SQL 的发展（摘要明确点名 WikiSQL、Spider）；GPT-4 等大模型在通用基准上表现强劲。
- 前人缺陷（摘要明确指出）：
  1. 现有数据集**领域广但缺失关键垂直领域**，尤其是金融与会计（finance and accounting）；
  2. 会计数据库全球广泛使用且用户大量为**非技术人员**，却没有配套的领域数据集来训练/评测 NL 查询模型；
  3. 因此无从知晓/提升 SOTA 模型在会计领域的真实水平。
- 动机：用领域数据集填补空白，并实测现有最强模型（含 GPT-4）暴露性能差距，为后续领域专用模型研究铺路。

## 2. 核心方法

- **最直观类比**：给 Text-to-SQL 研究者出一套"会计从业资格考试题库"——题目全部用会计行话提问，答案是对真实会计账套执行的 SQL，专门考模型"懂不懂财务"。
- **具体做法（输入→关键操作→输出）**：
  1. **构建**会计领域数据库：百万级（1 million）记录的会计/财务数据库（字段涵盖科目、分录、期间等会计结构，schema 细节 🔧 查原论文）；
  2. **标注**约 **100k** 条自然语言查询-SQL 配对；
  3. **基准评测**：把当时的 SOTA Text-to-SQL 模型（含 **GPT-4**）放到 BookSQL 上做实验分析；
  4. **输出**：数据集＋基线成绩＋差距分析，指向"需要为该领域开发更专注的模型"。
- **形式化要点**：标准 Text-to-SQL 定义：给定数据库 schema S 与问题 q，生成 SQL y 使执行结果与金标准一致；数据集形式化为三元组 (DB, q, y) 的集合。
- **理论性质/保证**：资源论文无理论定理；贡献在于领域覆盖与规模（100k 配对 / 1M 记录）。

- **对比模型**：当时的 SOTA Text-to-SQL 模型，包括 **GPT-4**（摘要确认"including GPT-4"；其他具体模型与版本 🔧 查原论文）。
- **数据集**：BookSQL（100k NL-SQL 对、1M 记录会计数据库）。
- **指标**：Text-to-SQL 评测惯用指标（执行准确率/精确匹配，具体口径 🔧 查原论文）。
- **结论方向（摘要核实）**：所有被测模型在 BookSQL 上均呈现**显著性能差距（significant performance gaps）**——会计领域对现有模型依然困难，值得开发领域专用模型。

## 7. 2026 视角（🔧）

- 2024-2026 年 LLM 时代，垂直领域 Text-to-SQL 成为热点：BIRD、各领域基准层出不穷，通用模型在 Spider 类基准逼近上限后，**领域差距**（会计、医疗、法律）成为新战场——BookSQL 是这一趋势的先行证据之一；
- 会计/ERP 场景的商业落地（BI Copilot、财报问答）普遍采用"schema linking + 领域术语词典 + SQL 校验"管线，纯端到端仍不达标；
- 🔧 2026 年最强模型在 BookSQL 上的最新成绩待查（原论文成绩已成历史基线）。
