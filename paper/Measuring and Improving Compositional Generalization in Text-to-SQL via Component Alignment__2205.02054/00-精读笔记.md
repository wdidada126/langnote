## 一句话总结
Text-to-SQL 模型在「训练没见过的问法组合」上会崩；本文把句子拆成带 SQL 子句标注的「子句碎片」，再重新拼出新组合（Spider-CG），用这个新基准证明现有模型确实退化，并通过「在碎片上训练」显著提升组合泛化能力。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：Text-to-SQL 是把自然语言问题翻译成 SQL 的任务。理想情况下，模型应能把学过的「词语/结构」自由组合，回答训练时没见过的问法——这叫**组合泛化（compositional generalization）**。
- **为什么难**：神经网络容易「死记」训练分布；一旦测试时的问法是已知部件的新组合，性能就大幅下降。此前很多改进靠「词级（word-level）合成数据」或「特定数据集切分」来制造组合偏置，并不直接针对句子结构。
- **几类主流解法**（表格）：

| 路线 | 直觉 | 代表 |
|------|------|------|
| 词级合成数据 | 随机拼词造训练样本 | 早期数据增强方法 |
| 数据集切分 | 用特定 split 制造组合偏置 | 各类 composition split |
| **本文：子句级碎片** | 把句子切成带 SQL 子句标注的碎片再重组 | Spider-SS / Spider-CG |

- **本文属于**：数据构造/评测路线，提出「子句级（clause-level）」而非词级的组合样本生成。
- **关键名词直觉**：
  - **组合泛化**：能举一反三地把已知零件拼成新整体。
  - **Spider**：经典跨域 Text-to-SQL 基准，含多表数据库与自然语言问句。
  - **SQL 子句（clause）**：SELECT / WHERE / GROUP BY 等组成部分；本文把句子和这些子句一一对应。

## 1. 问题背景与动机
- **前人工作简述**：组合泛化在 NLP 普遍困难；Text-to-SQL 里已有一些基于词级合成数据或特定数据集切分的工作来引入组合偏置。
- **前人的缺陷/未解决问题**（逐条）：
  1. 多数改进停留在**词级**合成，没有在「句子—SQL 子句」的结构层面对齐。
  2. 缺少一个直接衡量「子句级组合能力」的benchmark。
  3. 不清楚「每个子句碎片都在训练里见过、但新组合没见过」时模型是否会退化。

## 2. 核心方法
- **最直观类比**：学说话时，你会把「主谓宾」零件拆开练，再组合成没说过的新句子；本文就是先造出这种「可拆解的句子零件库」，再考模型能不能拼出新的。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：Spider 数据集的自然语言问句 + 对应 SQL。
  2. **关键操作**：把每个问句切成**子句（sub-sentence）**，并为每个子句标注其对应的 SQL 子句，得到新数据集 **Spider-SS**；再把 Spider-SS 的子句按不同方式组合，构造 **Spider-CG** 来专门测试组合泛化。
  3. **输出**：一组用于「度量 + 训练」的数据集；在此基础上把若干 SOTA 模型改为在 Spider-SS 的碎片化数据上训练。
- **形式化要点**：核心是「子句 ↔ SQL 子句」的组件对齐（component alignment）；训练时以碎片为单位而非整句。
- **理论性质/保证**：本文以实证为主，无形式化最优性保证。

## 4. 实验结论（概览）
- **对比基线**：若干 SOTA Text-to-SQL 模型（在原 Spider 上训练）。
- **数据集**：Spider-SS（训练/对齐用）、Spider-CG（组合泛化测试用）。
- **结论方向**（摘要给出）：现有模型在 Spider-CG 上**性能显著退化**，即便每个子句碎片训练时都见过；把模型改为在 Spider-SS 的碎片化数据上训练后，**组合泛化性能提升**。
