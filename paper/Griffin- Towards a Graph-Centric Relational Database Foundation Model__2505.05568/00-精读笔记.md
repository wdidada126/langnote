## 一句话总结
给关系数据库造一个"基础模型"：一个在海量关系表/图数据上预训练好的通用编码器，换一个新数据库、换一个任务（分类、链接预测、节点回归等）不用从零训练，直接微调甚至零样本上手——把 NLP 里"预训练 + 下游适配"的成功配方搬进数据库世界。

## 0. 给新手的阅读前置（背景知识地图）

**子方向解决什么大问题**：数据库上的机器学习任务（数据分类、异常检测、链接/关系预测、属性推断……）传统做法是"一个任务训一个模型"——每个新数据集都要重新收集特征、重新训练。NLP/CV 已被"基础模型（foundation model）"范式改造（一个 GPT/CLIP 通吃多任务），数据库领域一直没有对应的"通用底座"。Griffin 要回答：**能不能造一个跨数据库、跨任务通用的模型？**

**为什么难**：
1. **关系数据异构**：每个数据库 schema 不同、列的类型五花八门（类别、数值、文本、时间戳）、表与表之间通过外键形成任意图结构——不像图像有统一像素网格、文本有统一 token 表；
2. **任务多样**：点级/边级/图级任务并存（节点分类、链接预测、回归……），单一输出头不够；
3. **图结构本身就是信息**：关系数据的关键信号藏在"谁连接谁"里，需要消息传递类归纳偏置，但 MPNN 在超大规模异构图上又贵又难训；
4. **迁移性要求**：模型必须在没见过的 schema/数据集上工作，不能依赖"每个库一份专属词汇表"。

**几类主流解法**：

| 路线 | 代表思路 | 短板 |
|------|---------|------|
| 逐任务小模型 | 传统 ML on 表 | 无法迁移，重复建设 |
| 表格基础模型 | TabPFN 等（单表、小数据） | 不建模表间关系（外键图） |
| 图基础模型（通用域） | 图预训练 + 提示 | 多针对单一图/同质图，非关系数据库语义 |
| LLM-based | 用 LLM 读表内容 | 昂贵、数值/结构推理弱 |
| **图中心 RDB 基础模型（本文）** | 统一编码器 + 任务解码器，把 RDB 整体看成图 | 预训练数据与算力门槛 |

**本文属哪类**：第四类中的"图中心（graph-centric）"路线——把关系数据库（多表 + 外键）整体建模为异构图，在其上做基础模型。

**关键名词直觉解释**：
- **基础模型（foundation model）**：在大规模多样化数据上预训练、可适配大量下游任务的模型（如 GPT）。关键词是"一次预训练，处处适配"。
- **MPNN（消息传递神经网络）**：图神经网络的主流范式——每个节点每轮从邻居"收集"信息并更新自身，几轮后节点就带上了 k 跳邻域的信息。
- **cross-attention**：一组表示"看着"另一组表示做加权读取（如任务 query 去数据编码里取信息）；本文用它把任务与数据解耦连接。
- **关系数据库即图**：表 = 节点类型（行 = 节点），外键 = 边——于是任何 RDB 都可看作一张异构时序图，这是本文的建模基石。

## 1. 问题背景与动机

**前人工作简述**：表格侧有针对单表的基础模型尝试（TabPFN 等）与 LLM 表格理解；图侧有图预训练/图基础模型研究，但多针对同质图或单域数据；数据库学习（learned DBMS）方向已有大量"单任务专用模型"（基数估计、索引调优等，见本仓库众多 learned DB 论文）。**专为关系数据库整体设计、统一多任务的基础模型此前是空白**。

**前人缺陷/未解决问题（逐条）**：
1. **已有小模型只针对单一 RDB 任务**：无法跨任务、跨数据集复用，每个任务重头训练；
2. **缺乏统一的数据编码**：类别、数值、元数据特征各有最佳处理方式，已有方法要么全按类别处理丢异数值序，要么全按数值丢类别语义；
3. **缺乏统一的任务接口**：点分类、链接预测、回归等任务的输出形式不同，缺一个统一解码框架；
4. **关系结构利用不足**：表格基础模型不看外键图，通用图基础模型不懂 RDB 的 schema 语义与时序性；
5. **规模门槛**：要在真实大规模异构时序图上预训练才能谈"基础模型"，此前工作少有这个量级的实践。

## 2. 核心方法

**最直观类比**：把每个关系数据库想象成一座城市：表是街区、行是建筑、外键是道路。Griffin 先"看遍千万座城市"学会城市通用规律（预训练），之后来到任何一座新城，稍加适应就能回答各类问题（分类、预测谁和谁相连等），不用在城市里从零当学徒。

**具体做法（输入 → 关键操作 → 输出）**：
- **输入**：一个关系数据库（多表、外键关系、行数据），编码为大规模异构（时序）图。
- **关键操作**：
  1. **高级特征编码器**：分别针对类别特征、数值特征、元数据特征设计编码器，把任意 schema 的行统一映射进共享表示空间（解决"异构 schema"问题）；
  2. **增强型 MPNN**：在异构图上做消息传递，捕捉关系数据的复杂性（表间外键连接、时序演化）；对标准 MPNN 做增强（🔧 具体增强点查论文方法章）；
  3. **cross-attention 模块**：任务表示与数据表示之间做交叉注意力，实现"一个编码器、多种任务"的解耦——任务作为 query 主动从数据编码中提取所需信息；
  4. **新型 aggregator**：改进多邻居/多源信息的聚合方式（🔧 细节查论文）；
  5. **统一数据编码器 + 任务解码器**：预训练在单表与关系数据集上进行，下游通过微调/迁移适配各类任务。
- **输出**：任务相关预测（分类标签、链接、回归值等，取决于挂载的任务解码器）。
- **形式化要点**：模型 = 特征编码 → 异构图消息传递 → cross-attention 任务读取 → 任务头；预训练目标跨数据集/跨任务统一（🔧 具体预训练损失与自监督目标查论文）。

**理论性质/保证**：无理论证明；卖点为实证上的跨数据集迁移与低数据表现。

## 4. 实验结论（概览）

- **预训练规模**：在单表与 RDB 数据集上预训练；评测所用大规模异构、时序图（从各领域 RDB 抽取）**跨度超过 1.5 亿节点**（数字来自论文摘要）。
- **对比基线**：各下游任务上单独训练的模型（per-task 专用模型）。
- **指标**：各任务的对应指标（准确率、AUC 等 🔧 逐任务清单查论文）。
- **结论方向**（来自论文摘要）：
  - 性能与单独训练的模型**相当或更优**；
  - **低数据场景表现突出**（few-shot/低标注量下优势最明显——基础模型范式的典型特征）；
  - 对**新数据集与新任务展现出强迁移性**。

## 7. 2026 视角（🔧）
- "数据库基础模型"在 2025-2026 年成为热门叙事：Griffin 是关系数据库侧的首批认真尝试（ICML 2025），与表格基础模型（TabPFN 系）、图基础模型三条线正在收敛。
- 低数据/零样本迁移是当前最被看好的落点：企业新库冷启动、数据目录自动打标、RDB 上的即席预测任务。
- 开放问题：超大规模 RDB 的预训练成本、schema 漂移的持续适应、与 LLM 智能体的分工（结构编码交给基础模型，语义推理交给 LLM）。
- 🔧 该方向最新工作（后续会议版本、竞品模型）持续涌现，需定期跟踪。
