## 一句话总结
很多生产 DBMS 声称支持某隔离级别却藏着隔离 bug；IsoVista 是第一个覆盖多隔离级别、且「既不错报也不漏报」的黑盒校验系统，比 SOTA 更快，还能把违规现场画出来方便调试，并附带校验器自身的性能评测接口。

## 0. 给新手的阅读前置（背景知识地图）
- 子方向解决什么大问题：事务隔离级别（READ COMMITTED、SNAPSHOT ISOLATION、SERIALIZABLE 等）是 DBMS 正确性的核心。生产系统（PostgreSQL、MariaDB 等）近年被测出不少隔离 bug——声称的级别没真正保证。需要工具去「揪 bug」。
- 为什么难：① 现有校验器对部分隔离级别刻画不全，会漏报；② 在事务依赖图里找环/SMT 求解开销大，高并发下更慢；③ 返回的反例难懂（如不满足的子句），不好调试；④ 缺少覆盖多级别的统一系统。
- 几类主流解法（隔离校验）：

| 路线 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 黑盒随机压测 | Elle、PolySI 等 | 高并发灌负载，再从历史找异常 | 通用；刻画不全会漏报 |
| SMT 求解 | 若干校验器 | 把依赖约束编码进 SMT 求解 | 严谨；贵 |
| 可视化反例 | 本文 IsoVista | 把违规场景画出 | 好调试；需配套实现 |

- 本文属哪类：黑盒 +  faithful 多级别刻画 + 高效 + 可视化，是前述工作的集大成。
- 2-3 个必懂关键名词：
  - 隔离级别（Isolation Level）：DBMS 承诺「并发事务之间互不干扰到什么程度」的档位，档位越高越安全越慢。
  - 黑盒校验（Black-box Checking）：不读 DBMS 源码，只通过发事务、观察历史来判定是否违反隔离保证。
  - 误报/漏报（False Positive / Missed Bug）：误报=把没问题的判成有 bug；漏报=真 bug 没查出来——IsoVista 声称两者都不发生（基于 faithful 刻画）。

## 1. 问题背景与动机
- 前人工作简述：已有隔离校验器（PolySI 查 SI、Plume 查弱隔离、Elle 等）多采用随机黑盒测试。
- 前人缺陷/未解决问题（逐条）：
  1. 对部分隔离级别刻画不完整 → 漏报关键 bug。
  2. 在依赖图找环或 SMT 求解开销大，高并发更明显。
  3. 反例难懂（如不满足子句），难调试。
  4. 缺少覆盖多级别、面向开发者与校验器自身的统一平台。

## 2. 核心方法
- 最直观类比：DBMS 像一家银行，隔离级别是「柜台承诺的防插队规则」。IsoVista 像一位不进后台、只在窗口外反复办业务并盯监控的审计员——它把「各档规则」记全（faithful 刻画），既不会冤枉银行（无误报），也不会漏掉插队（无漏报），还能把违规瞬间画成图给银行看。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 输入：被测 DBMS + 高并发随机事务负载。
  2. faithful 刻画：对一系列隔离级别给出完备的形式化定义，保证不漏不误。
  3. 高效检查：在收集到的事务历史上做比 SOTA 更高效的判定（扩展 PolySI/Plume 思路）。
  4. 可视化：把违规场景画成易理解的图。
  5. 输出：是否违反某隔离级别 + 违规可视化 + 校验器自身性能画像。
- 形式化要点：核心是「多级别 faithful 刻画 + 高效判定 + 可视化」；建立在先验 PolySI（SI 完备校验）与弱隔离校验工作之上。
- 理论性质/保证：声称在所覆盖级别上既无 false positive 也无 missed bug（基于刻画完整性）。

## 3. 变体 / 工程版（如有）
- 提供用户友好的界面做可视化与 profiling，并可对「隔离校验器本身」在不同负载下做性能基准（面向校验器开发者）。

## 4. 实验结论（概览）
- 对比基线：SOTA 隔离校验器。
- 数据集/指标：不同并发负载；指标为检查效率、漏报/误报、可视化可用性。
- 结论方向（摘要已核实）：相比 SOTA 有更优的检查效率，并可视化违规场景、支持对校验器做性能画像。
