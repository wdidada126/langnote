> 三态标注：✅ 论文硬写事实 / ⚠️ 记忆或二手归纳 / 🔧 本地可复演实验

| 项 | 内容 |

## 二、问题史：Shard-anything 为什么痛苦

- 2013 年主流扩展法=应用层分库分表：跨分片 join/事务/再平衡全是业务代码的债（✅ 论文 §1 抱怨清单）。
- 纯 NewSQL 当时两条路：内存型（H-Store/Volt ⚠️）牺牲容量；Share-nothing MPP 牺牲 OLTP 写并发（⚠️）。
- F1 命题：**分片细节对 SQL 不可见**——索引即表、目录即数据库，分片只是放置问题（✅ 核心口号）。

## 三、架构

### 3.1 分层

- SQL 引擎（无状态，可任意拉起）→ **Load-Data-Store**（块缓存+目录）→ Spanner（全局事务+有序键空间）（✅ 三层图）。
- F1 客户端库嵌进应用/负载均衡层；列式分块（block = 行区间打包）做缓存与传输单位（✅）。

### 3.2 模式管理与分布式目录

- Schema/分片信息作为**事务性表**存 Spanner，变更走事务；各 F1 实例靠 watch/轮询收敛（✅）。
- 模式演进在线：加列/迁移两阶段（backfill 用任务框架，⚠️ 细节凭记忆：论文称 interleaved 表与任务状态表）。

### 3.3 Interleaved tables（ interleaved 表）

- 子表按父表前缀共置：`广告 ← 创意` 父子行落在同分片区间——局部性用**模式声明**而非手工 rowkey 拼接（✅ F1 招牌特性）。
- 直接继承自 Percolator 时代"用 schema 换 join"实践，后进 Spanner interleaving 语法（⚠️ 谱系）。

### 3.4 索引即表 + 异步索引维护

- 索引是独立 Spanner 表；写主行与写索引行**同事务**保证原子（✅）。
- **Storing index / 部分异步**：为吞吐允许索引短暂滞后 + backfill 状态机（✅ 论文有"index build 渐进"章节 ⚠️ 术语凭记忆）。
- 全球读：只读事务可 pin 时间戳跑异地副本（✅ 依赖 Spanner 外部一致性）。

## 四、评测与运维（✅ 定性 + ⚠️ 数字凭记忆）

- 论文曲线：随分片数近似线性的吞吐/容量增长；热点靠再分裂+迁移（Spanner split point）自动处理（✅ 机制）。
- 广告业务真实负载：数千分片、PB 级（⚠️ 论文口径量级）。
- 再平衡全程在线、无需停机是论文最强调的运维卖点（✅）。

## 五、批判读法

- F1 论文像 Spanner 说明书的 SQL 附录：**共识、TrueTime、迁移全部外置**——单独读 F1 学不到分布式内核，只学到"SQL 层如何设计以不打扰底座"（⚠️）。
- Interleaved 表是双刃剑：父键前缀绑定造成热点（big-parent 问题），后来 Spanner 官方文档自己加警告（⚠️ 后话）。
- 异步索引滞后语义=最终一致的窗口，广告场景可容忍，金融场景未必——论文对"可容忍清单"写得乐观（⚠️）。
- 与 Aurora [[aurora_2017_sigmod]] 对照：F1 赌"通用事务 KV+SQL 层"，Aurora 赌"专用存储下推"；后者把复制日志化更彻底（⚠️ 判断）。

## 六、🔧 本地微实验（非本书引擎行为）

1. **索引即表**：SQLite 里主表+索引表同事务写，手动模拟"索引滞后"：延迟提交索引事务，测读到旧索引的后果。
2. **Interleaved 局部性**：造父子两表，按"父前缀打包"与"哈希分布"两种布局，统计一次父查子扫描的块数。
3. **在线模式演进**：加列走"声明→双写→backfill→切读"四步，写 JSON 状态机模拟崩溃恢复续传。
4. **块缓存**：以 50 行/块打包 JSONL，模拟行式读取 vs 块式读取的 I/O 次数。
5. **分片再平衡**：按 key 区间中点分裂+迁移记录（模拟 split point），统计查询路由表更新量。

## 九、最新演进与工业实践

- F1 随 Google 广告栈演化，论文停更于 2013；其思想经 Spanner 公开 API（interleaved 表、storing index、在线 DDL）进入商用（✅ 映射）。
- CockroachDB/TiDB 把"SQL 层与 KV 层分离"走成标准架构（CockroachDB VLDB 2020、TiDB 白皮书 ⚠️）。
- PostgreSQL 生态用 Citus 补分片，走的是 F1 反面——分片语义泄漏给用户（⚠️ 对照）。
- 2024–2026：向量索引作为"索引即表"的新条目（异步回填状态机原样复用）——F1 的模式演进框架被追认为在线索引的模板（⚠️ 判断）。
