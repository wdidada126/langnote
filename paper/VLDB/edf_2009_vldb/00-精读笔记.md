## 二、问题史：为什么"一次编译永久执行"不成立

- Selinger 式优化器的三块地基：准确统计、静态代价、计划定型（✅ 对照 [[selinger_1979_sigmod]] 本批已建）。
- 现实裂缝：湖上数据量级+漂移、交互式负载（同查询不同选择性）、资源争用（多租户下 I/O 延迟非平稳）（✅ §1 例证线）。
- 已有补丁谱：查询重优化（re-optimization）、Eddies 路由（⚠️）、mid-query statistics——各自局部有效，缺**统一决策框架**（✅ 论文定位）。

## 三、核心机制：代价驱动的执行期决策

### 3.1 模型化"不确定性"

- 把基数估计写成**分布**而非点值；统计误差（直方图 bin 内的不确定）传播成计划代价的期望与方差（✅ 招牌：query cost under uncertainty）。
- 决策目标：最小化"期望代价+尾部风险"，可在两个候选子计划间**按运行中证据切换**（✅）。

### 3.2 动态算子选择框架

- 每个 join 节点维护"候选实现（hash/merge/index）×当前证据"的评估，执行中途发现估计偏差超阈值即**重入优化决策**（保留中间结果，⚠️ 切换成本论文有公式）。
- 与 re-optimization 的区别：不是全树重编，而是**局部代价重估+带记忆的切换**（✅ 大意）。

### 3.3 统计在线更新

- 谓词结果即样本：执行反馈（实际选择率）更新估计模型（✅ 与自调优查询网络同调）。

## 四、评测（✅ 定性）

- 构造统计偏置与负载漂移场景：EDF 在"估计严重失准"工况下把计划拉回近最优，静态计划劣化数倍（⚠️ 曲线以图表为准）。
- 论文诚实展示"估计准确时"EDF 无增益且有决策开销（✅ 适用边界）。

## 五、批判读法

- 与 Eddies 的路线张力没完全解决：tuple 路由（细粒度）与 plan 切换（粗粒度）各有适配域，统一框架偏概念（⚠️）。
- 不确定性传播的"直方图内均匀"假设本身又是点估计式信仰——套娃偏差（⚠️ 对照学习估基数线，库内 NeuroCard/FLAP 等已建档 ⚠️）。
- 工程化最难的是**内存与中断语义**：切换时刻的缓冲池状态、客户端游标可见性，论文回避（⚠️）。
- 历史判决：思想被吸收、品牌未存活——Spark AQE（运行时重规划）、SQL Server 自适应 join、Orbit 系"查询内优化"全是 EDF 的远亲（✅ 判断）。

## 六、🔧 本地微实验（非本书引擎行为）

1. **切换收益复现**：造选择性误判 10 倍的表对，静态 hash join vs "中途检测偏差→改索引/嵌套"，计总时间。
2. **方差代价**：给基数估计加 ±50% 噪声分布，比较"期望最小"与"最坏最小"计划的选择差异。
3. **执行即采样**：limit-K 早停测选择率 vs 全量真值，量化在线更新误差。
4. **切换成本**：实现"丢弃半程 hash 表重建"的代价项，画切换阈值敏感性曲线。
5. **多租户扰动**：另一进程抢 I/O（后台 dd 模拟），观察"重优化 vs 静态"完成时间分布。

## 九、最新演进与工业实践

- Spark AQE 的"局部重规划+合并 shuffle 分区"= EDF 命题的工程子集；SQL Server 自适应 join 反馈阈值是其商用孪生（⚠️）。
- 学习式优化（Bao/Lero 库内已建档）把"决策切换"升级为"行为模型选择"，不确定性建模仍是共同底座（⚠️ 判断）。
- 湖仓统计不可信（开放格式无 ANALYZE 纪律）让运行时自适应从奢侈品变必需品（⚠️ 判断）。
- 2024–2026：LLM 辅助重规划/解释进入商业 BI——"边跑边改"的认知化终局与 EDF 同源（⚠️ 判断）。
