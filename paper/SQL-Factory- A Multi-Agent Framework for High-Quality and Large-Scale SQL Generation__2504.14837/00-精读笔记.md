## 一句话总结
高质量 SQL 语料是智能数据库（尤其 Text-to-SQL）的命脉，但人工标注太贵；SQL-Factory 用三个协作的智能体团队（生成 / 扩展 / 管理）自动造出大规模、多样化、低成本的 SQL——在 4 个基准上造出 30 万+ 条 SQL、API 花费不到 200 美元，且生成的查询能显著提升下游模型表现。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：Text-to-SQL 等智能数据库任务需要大量「自然语言问题 + SQL」配对语料来训练/微调模型；人工标注昂贵。
- **为什么难**：自动生成 SQL 既要**多样性**又要**成本可控**；且很多方法对复杂 schema 的表「一视同仁」，没用好结构丰富的表。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 人工标注 | Spider 等 | 专家写配对 | 准但极贵 |
| 单模型生成 | 各类 LLM 生成 | 直接让 LLM 造 SQL | 多样性/成本难兼顾 |
| 多智能体 | 本文 SQL-Factory | 生成/扩展/管理分工 | 多样+低成本 |

- **本文属哪类**：多智能体（multi-agent）自动化 SQL 生成框架。
- **2-3 个必懂关键名词**：
  - **Text-to-SQL**：把自然语言问题转成可执行的 SQL。
  - **Multi-Agent（多智能体）**：多个分工协作的模型角色共同完成任务。
  - **SQL 语料（corpus）**：用于训练/评测的大量 SQL 样本集合。

## 1. 问题背景与动机
- 前人工作简述：已有自动 SQL 生成方法在推进，但仍受限。
- 前人缺陷/未解决问题（逐条）：
  1. **多样性与成本难兼顾**：现有生成方法在「多样」和「省钱」上顾此失彼。
  2. **忽视 schema 复杂度**：很多方法对所有表一视同仁，没利用结构丰富的表。
  3. **标注昂贵**：人工收集查询语料成本高，凸显自动生成价值。

## 2. 核心方法
- **最直观类比**：像开工厂——「研发组」用强模型想新款式（多样查询结构），「量产组」用轻量模型放大好款式，、「管理组」调度产线并质检，三者配合既多又快又省。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：数据库 schema（含结构丰富度不同的表）。
  2. **Generation Team（生成团队）**：用强 LLM 探索多样的查询结构。
  3. **Expansion Team（扩展团队）**：用轻量 LLM 把有前景的模式规模化放大。
  4. **Management Team（管理团队）**：自适应调度流程并评估合成查询质量。
  - 输出：大规模、多样化、高质量的 SQL 语料。
- **形式化要点**：模块化三团队框架，在多样性/可扩展性/成本间权衡；核心在管理团队的调度与质量评估（🔧 细节见论文）。
- **理论性质/保证**：无理论最优性保证；贡献在系统设计与实证（多样性提升、下游收益）。
