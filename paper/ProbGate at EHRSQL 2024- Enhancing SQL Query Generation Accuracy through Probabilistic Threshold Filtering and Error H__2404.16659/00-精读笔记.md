## 一句话总结
医疗领域的 Text-to-SQL 有个坑：有些问题数据库根本答不了（不可答）。ProbGate 用「熵 + 对数概率」给生成的 SQL 打分，自动把低置信度、不可答的结果过滤掉，即使拿不到模型内部参数也能用，提升实际可用性。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：Text-to-SQL 把自然语言问题转成 SQL 去查数据库。医疗（EHR）场景尤其有价值，但难点是——很多提问其实「数据库答不了」（比如问了表里没有的信息）。
- **为什么难**：模型可能「自信地生成错误 SQL」；而医疗答错后果严重。如何识别并拦下「不可答/低质量」查询，是关键。
- **几类主流解法**：

| 方法 | 思路 | 优缺点 |
|------|------|--------|
| 直接生成 | 微调 LLM 出 SQL | 简单但会瞎答 |
| 置信度过滤 | 用概率阈值拦低质 | 需模型参数 |
| **ProbGate** | 熵+对数概率门控 | 无需内部参数也能用 |

- **本文属哪类**：Text-to-SQL 的**可靠性/不可答检测**方向。
- **2-3 个必懂关键名词（直觉解释）**：
  - **Text-to-SQL**：把「人话问题」变成可在数据库执行的 SQL 语句。
  - **EHR（电子健康记录）**：医疗场景的数据库，字段多、隐私敏感。
  - **Unanswerable query（不可答查询）**：数据库里没有足够信息来回答的问题。

## 1. 问题背景与动机
- 前人工作简述：深度学习语言模型显著提升了 Text-to-SQL，在医疗病历检索上有前景；微调模型能把医疗询问转成 SQL。
- 前人缺陷/未解决问题（逐条）：
  1. **不可答查询难识别**：医疗场景中「答不了的问题」很常见，但模型往往照生成不误。
  2. **缺无需内部参数的过滤**：很多方法依赖模型内部参数，实际拿不到。
  3. **语法/模式错误未处理**：生成的 SQL 可能有语法错误或与表结构不符。

## 2. 核心方法
- **最直观类比**：像银行柜员在办业务前先判断「这业务我们能不能办」——ProbGate 就是给每个生成的 SQL 做「能不能办、靠不靠谱」的闸门，不靠谱就拦下。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **微调模型生成 SQL**：把医疗询问转成 SQL 查询。
  2. **熵法识别不可答**：引入基于 entropy（熵）的方法识别并过滤不可答结果。
  3. **对数概率过滤低置信度**：用 log probability 分布过滤低置信度 SQL。
  4. **真实库执行纠偏**：在真实数据库上执行查询，缓解语法与 schema 错误。
  - 输出：经过门控过滤、更可靠的 SQL 结果。
- **形式化要点**：核心是「概率阈值门控（entropy + log-prob）」；超参为阈值（🔧 见原论文）。
- **理论性质/保证**：以实证为主；强调「无需模型参数也可使用」的实用性。
