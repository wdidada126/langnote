## 一句话总结

ANN-Benchmarks 是一套**内存式近似最近邻（ANN）算法的统一评测框架**：它用标准接口把各类 k-NN 算法接入同一组公开数据集，自动扫描参数、用多种「精度-性能」指标对比，并生成图片 / LaTeX / 交互网页可视化；它让「选哪个 ANN 算法、怎么调参」这件事从玄学变成可复现的排行榜——并且长期维护、持续反映 SOTA 现状。

## 0. 给新手的阅读前置（背景知识地图）

### 0.1 为什么需要 ANN 基准
- ANN 算法**种类繁多**（HNSW、IVF-PQ、ScaNN、Annoy、FAISS 各路……），但**同一算法在不同数据、不同参数下表现天差地别**。
- 论文各自报数字、数据集不统一，读者很难横向比较。ANN-Benchmarks 解决的就是「**公平、可复现地比一比**」。

### 0.2 评测看什么指标
- **Recall（召回率）**：找回的真正近邻占全部近邻的比例（越接近 1 越好）。常用 recall@k、recall@10。
- **QPS（每秒查询数）**：吞吐，越高越好。
- **经典权衡曲线**：横轴 recall、纵轴 QPS，曲线越靠左上越优——这就是「精度-性能权衡」。

### 0.3 必懂名词
- **k-NN / ANN**：精确近邻 vs 近似近邻（见同仓库 SSG 样板 §0）。
- **标准数据集**：SIFT1M / SIFT1B（图像特征）、GIST1M、DEEP1B（深度特征）、NYTimes、Glove 等，ANN-Benchmarks 内置。

## 1. 问题背景与动机：前人工作的缺陷

在 ANN-Benchmarks 之前：
1. **缺乏统一接口**：每个算法用自己的数据格式、自己的评测脚本，难以「 apples-to-apples 」比较。
2. **参数调优靠手写**：算法常有一堆超参数，人工试错既慢又不全，结论不可复现。
3. **可视化零散**：结果多以零散表格出现，难一眼看出「哪种算法在什么区间最优」。

> 一句话：本文要把 ANN 评测变成「插上算法就能跑、自动扫参、自动出图」的公共服务。

---

## 2. 核心方法：统一接口 + 自动扫参 + 多指标可视化

### 2.1 直觉类比
把 ANN-Benchmarks 想成「算法选秀舞台」：所有选手（算法）用同一套规则、同一批考题（数据集）、同一把尺子（指标）上台，系统自动给每个人拍不同参数下的成绩，并做成一眼可比的成绩单。

### 2.2 具体做法
1. **标准接口**：每种 k-NN 算法只需实现「建索引 / 查询」两套钩子，即可接入。
2. **统一数据集**：内置多个公开标准数据集，统一下载与格式。
3. **自动参数扫描**：配置系统对每种算法的参数做范围扫描，免去手工调参。
4. **多质量指标 + 可视化**：支持多种（近似）质量度量，前端可输出图片、LaTeX 图、带交互图表的网站。

### 2.3 核心思想
- 把「算法比较」工程化、标准化，让结果**可复现、可累积**；短期帮用户选型，长期帮算法设计者做自动调参与研究。

- 典型流程（**教学示意，非逐字复制；以仓库 README 为准** 🔧）：

## 7. 2026 视角（🔧 给今天的读者）

- ANN-Benchmarks 已是**向量检索领域的事实上基准**，几乎所有向量库（FAISS、Milvus、Qdrant 底层的 HNSW/DiskANN）都绕不开它。
- 新趋势：面向**十亿级 / 磁盘 / 过滤检索（filtered ANN）**的扩展基准正在出现；选型时仍建议先跑 ANN-Benchmarks 看真实权衡。
