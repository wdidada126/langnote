## 二、问题史：geo 复制 SQL 的三个不肯

- 不肯放弃 ACID：单区 Postgres 生态迁移需求真实，NewSQL 必须给真事务（✅）。
- 不肯付 TrueTime 税：专用原子钟/GPS 不可普及——HLC（软件混合逻辑时钟）替代，代价是**有界不确定性**（⚠️ 论文假设：时钟漂移有界，无硬件保证）。
- 不肯锁死云厂商：多云/混合部署，Raft 分范围共识而非全局 Paxos（✅）。

## 三、架构分层

| 层 | 组件 | 要点 |
|---|---|---|
| SQL | 解析/优化器（Cascades 化改造 ⚠️ 自研+借鉴并存）、向量化执行（⚠️ 演进项） | Postgres 线协议兼容（✅） |
| KV | 分布式事务（2PC over Raft）、租约（range lease） | 时间戳=HLC 复合（✅） |
| Storage | RocksDB LSM + Range（64MB 目标分裂） | 每 range 一组 Raft 副本（✅） |

### 3.1 一致性机制三件套（✅ 论文 §4）

- **Raft per range**：复制组随分片分裂迁移，共识局部化（✅）。
- **Lease + 心跳续约**：range 内串行读走 leader 租约免共识轮（✅ 优化路径）。
- **混合时钟 HLC**：逻辑单调+物理近似；外部一致性靠"有界不确定性 Δ"上等待（bounded staleness）——读新鲜度是**可调参数**而非硬件恩赐（✅ 招牌折衷）。

### 3.2 事务路径

- 乐观（1PC for single range）+ 悲观（行锁表 ⚠️ 版本差异）双模式；跨 range 走异步 2PC（✅ 论文核心：写协调者流水线化降 RTT）。
- 隔离级别：可串行化；快照读依赖时间戳（✅）。

### 3.3 可用性语义

- 网络分区时：多数派侧继续读写，少数派拒绝（CP 立场，✅ 论文明说与 Cassandra AP 取舍对立）。
- 跨区延迟治理：事务重试、优先级队列、租约转移代价（✅ §7 运维叙事）。

## 四、评测（✅ 定性）

- TPC-C 改造+YCSB：跨洋事务吞吐受 RTT 支配，2PC 流水线化显著优于教科书实现（✅ 曲线方向）。
- "活过 AZ 故障 RPO=0"（多数派存活前提下 ✅，措辞注意）。

## 五、批判读法

- HLC 的 Δ 假设是**信仰之 leap**：物理时钟漂移超出假设窗口时外部一致性静默受损——Spanner 用硬件把问题消灭，Cockroach 用参数把问题摊开（✅ 对照，争议点诚实）。
- Range 分裂+每 range 一组 Raft：小 range 风暴（调度/心跳税）是运维史老伤（⚠️）。
- 论文性能数字与自家博客营销口径混同，学术基准（TPC-C 合规性）长期缺席（⚠️）。
- 与 TiDB 对读最佳：同问题同工具（Raft+LSM+SQL），TiDB 走 PD 中心调度+TSO 神谕，CRDB 走去中心租约——两种"元数据服务"哲学分野（⚠️ 判断）。

## 六、🔧 本地微实验（非本书引擎行为）

1. **HLC 模拟**：两节点互发消息携带(物理,逻辑)对，注入 ±20ms 漂移，验证单调性与 Δ 等待窗口。
2. **Raft 小群**：5 进程 JSON 日志复制，kill 多数派观察写入拒绝（CP 行为复现）。
3. **租约读**：leader 本地缓存读免共识 vs 每读一轮共识，测延迟对比。
4. **分片分裂**：key 空间超阈值二分，统计"迁移期间请求转发"的重试成本。
5. **异步 2PC**：两 range 分布式提交，把 prepare 并行化前后各跑 1000 次，计 RTT 节省。

## 九、最新演进与工业实践

- v21+ serverless 层、声明式模式变更、向量化执行器与地理分区（REGIONAL BY ROW）把"geo-SQL 可用化"产品化（⚠️）。
- 与 Postgres 生态的张力缓解：CRDB 自认"兼容子集"，生态兼容是长期战争（⚠️）。
- 开源 NewSQL 三强（TiDB/Cockroach/YB）2024–2026 全面向量列+HTAP 化——论文作为"共识+HLC+SQL"范式的开源宣言持续被引（⚠️ 判断）。
