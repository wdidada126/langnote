# Eddies: Continuously Adaptive Query Processing — 精读笔记

> SIGMOD 2000 · Avnur & Hellerstein（UC Berkeley，✅ 二人确定）
> 三态标注：✅ 论文硬写事实 / ⚠️ 记忆或二手归纳 / 🔧 本地可复演实验

## 一、基本信息

| 项 | 内容 |
|---|---|
| 会议 | SIGMOD 2000 |
| 定位 | 把"静态计划"炸成**元组路由器**：每个算子对每条元组自主报价（ready/affinity），调度器持续重排执行序（✅ 招牌意象） |
| 谱系 | TelegraphCats 线（Hellerstein 组）→ 本文 → 下游自适应查询处理（AQP）整个亚学科；EDF（库内 [[edf_2009_vldb]] 本批已建）为其"计划级"表亲 |

## 二、问题史：为什么"编译时优化"注定错过

- 优化器三宗罪（✅ §1）：统计过期（数据在查中变）、参数运行期才知（谓词值/资源争用）、多计划各有局部最优（join 序在不同选择率下翻转）。
- 已有补救（re-optimization/Adaptor ⚠️ 同期线）以"块"为粒度太粗——Eddies 把决策权下沉到**元组**（✅ 极端立场）。

## 三、核心机制

### 3.1 路由器调度

- 每元组每时刻问所有**可用算子**："你处理我要多久（cost）、我多快能被你消费（ready）、你多希望吃我（affinity）"（✅ 查询/反馈协议）。
- Scheduler 维护全局队列按分数派发；算子间无固定边——边是涌现的（✅ "无计划执行"）。

### 3.2 统计自学习

- 执行即采样：实测选择率/耗时回流估计器，调度随数据反馈漂移自动收敛（✅ 在线学习原型）。

### 3.3 正确性边界

- 阻塞算子（排序/聚合/去重）不兼容"逐元组自由流"：Eddies 引入**元组块+完成条件**近似处理，但明确自认排序类是其阿喀琉斯（✅ 论文坦承 ⚠️ 机制细节）。

## 四、评测（✅ 定性 + ⚠️ 凭图表）

- 实验场景：数据漂移/多目标（延迟 vs 内存）下显著优于静态计划与粗粒度重优化；单查询开销大（每元组决策）是代价（✅）。

## 五、批判读法

- 元组级决策=每行一次调度税：论文自己用批量摊销缓解，实践中批越大越退回"块级自适应"——**粒度与开销的钟摆注定停在中间**（⚠️ 判断，Spark AQE 即中间态）。
- 无代价上界证明：调度启发式的收敛性是经验叙事（⚠️ 理论债）。
- 阻塞算子困境后来被差分/增量计算（Naiad [[naiad_2013_sosp]] 已建）以另一方式解开：不是取消计划，而是让"部分结果"成为一等公民——两篇对读是 AQP 的辩证法（⚠️ 判断）。
- 遗产判定：品牌死亡、基因扩散（EDF/AQE/学习优化器皆带 Eddies 血点 ✅ 判断）。

## 六、🔧 本地微实验（非本书引擎行为）

1. **元组路由玩具**：两 filter+一 join 写成"报价函数"，随机到达元组按 ready×affinity 派发，对比固定序。
2. **在线选择率**：limit 早停采样更新谓词估计，观察调度序随真实分布翻转的时点。
3. **粒度钟摆**：同一负载跑"每元组决策 vs 每 1k 块决策"，画总开销/质量曲线。
4. **阻塞算子塞进流**：给 hash agg 设"块完成即部分输出"，体验 Eddies 的妥协设计。
5. **漂移风暴**：中途切换数据分布，静态计划 vs 路由器计划的完成时间对比。

## 九、最新演进与工业实践

- "边执行边学"已是商用优化器标配词（自适应 join、动态并行度）——Eddies 的极端版未胜选，温和版全面渗透（✅）。
- 流式与交互式引擎（Materialize 增量、Druid 实时）在算子层复活"部分结果+反馈"叙事（⚠️）。
- 2024–2026：LLM Agent 执行长链工具调用时的"每步重规划"与元组路由结构同构——论文作为"决策粒度连续谱"的原型被跨域引用（⚠️ 判断）。
