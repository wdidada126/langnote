## 一句话总结
图片-文本这类「双模态数据」做混合向量查询时，用户每次给两个相似度分配的权重 α 都可能不一样，传统做法只对某个固定 α 建索引、α 一变性能就崩；DEG 用一张「动态边导航图」把所有 α 的最短路都编码进同一张图，α 怎么变都能高效准确地查。

## 0. 给新手的阅读前置（背景知识地图）
- 大问题：近似最近邻搜索（ANNS）研究「给一个向量，在海量向量里快速找出最相似的几个」。但现实中数据常是双模态的（如一张图配一段文字，各自有一个向量），用户希望按「图文加权混合相似度」来排序——这叫混合向量查询（HVQ）。权重参数 α ∈ [0,1] 由每次查询动态指定。
- 为什么难：图索引（如 HNSW/NSG 这类导航图）的每条边都是「为某种相似度度量精心挑选的邻居」。α 一变，两两向量的相似度排序就变了，同一张图可能对 α=0.3 很好、对 α=0.8 很差。Naive 方案是给每个 α（或一组离散 α）各建一张图，空间和维护成本爆炸。
- 主流解法几类：

| 路线 | 直觉 | 代表 |
|------|------|------|
| 多索引 | 每个 α 值建一张图，查询时选 | 简单但空间开销大 |
| 单索引+过滤/投影 | 把双模态压成单向量或做属性过滤 | 精度受限 |
| 动态单图（本文） | 一张图兼容所有 α，查询时按需激活边 | DEG（本文） |

- 关键名词直觉：
  - Pareto 前沿：在一组「随 α 变化」的候选邻居里，去掉那些「无论 α 取多少都比不过别人」的点，剩下的就是 Pareto 前沿——一张图里每个节点只需保留这些点作为候选邻居。
  - 相对邻域图（RNG）剪枝：图索引常用的一种剪边规则——若某邻居能被另一个更近的邻居「顺路到达」，这条边可剪掉。DEG 把该规则做成「按 α 动态生效」。
  - 活跃区间（active range）：DEG 给每条边标注一个 α 区间，查询时根据当前 α 决定这条边是否可用。

## 1. 问题背景与动机
- 前人工作：HVQ 通常对固定 α 建 ANNS 索引；图索引构建中的 RNG 等剪枝策略是面向单一距离度量设计的。
- 前人缺陷（据摘要归纳）：
  1. 固定 α 索引：当查询的 α 随场景动态变化时，性能显著退化；
  2. 为多组 α 各建索引：空间与维护成本高；
  3. 双模态相似度是「两个距离的加权和」，不是单一度量，现有图构建算法无法直接复用。

## 2. 核心方法
- 最直观类比：一张地图上，白天和夜晚「最短路径」会变。DEG 不是画两张地图，而是在每条路上标注「白天可用 / 夜晚可用 / 全天可用」，导航时按当前时段跳过不可用的路。
- 输入 → 关键操作 → 输出：
  1. 输入：每个对象两个向量（如图片向量+文本向量）；
  2. 构建阶段：(a) 贪心 Pareto 前沿搜索——为每个节点求出「对所有 α 都近似最近」的候选邻居集；(b) 动态边剪枝——从候选集确定最终边，并给每条边分配一个「活跃的 α 区间」；(c) edge seed 方法加速查询起点选择；
  3. 输出：一张 Dynamic Edge Navigation Graph，查询时按用户给定的 α 只激活活跃区间覆盖该 α 的边，做贪心导航搜索。
- 形式化要点：对象相似度 = α·sim_1 + (1−α)·sim_2；剪枝条件在「按 α 变化的度量族」上逐段成立。
- 理论性质：摘要未给出严格理论保证；正确性/精度依赖 Pareto 前沿候选集对全 α 范围的覆盖（🔧 证明细节见原文）。

## 3. 变体 / 工程版（如有）
- 暂无已知独立变体；DEG 的三个组件（Pareto 前沿候选、动态 RNG 剪枝、edge seed）可视为对一般图索引的通用改进思路（🔧）。

## 4. 实验结论（概览）
- 对比基线：现有 HVQ 方法（对固定/离散 α 建索引的方案）（🔧 具体名单查原论文）。
- 数据集：真实世界双模态数据集（🔧 名称查原论文）。
- 指标：精度-效率 trade-off（recall/QPS）、索引构建时间。
- 结论方向：在 α 动态变化场景下，DEG 优于现有方法；单张图在所有 α 上都保持稳定的精度-效率权衡。

## 7. 2026 视角（🔧）
- 混合/过滤向量查询已从「学术新问题」变成向量数据库标配需求（Milvus、pgvector 等均支持属性过滤与多路召回）；「一次构建、多查询模式复用」的动态索引思路正成为热点。
- 多模态检索（图文、音视频）驱动了 α 类参数化查询的大量应用；相关方向还有 filtered ANN、range-filtering ANN（如本仓库 iRangeGraph 条目）。
