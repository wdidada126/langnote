## 一句话总结

Text-to-SQL 领域 SOTA 都靠闭源大模型（ChatGPT/GPT-4），又贵又不安全。CodeS 给出一套 1B–15B 的全开源模型：在 StarCoder 上用 SQL 语料增量预训练，配合提示构造与双向数据增强，小模型在 Spider、BIRD 等几乎所有难的 Text-to-SQL 基准上刷新了开源 SOTA。

## 0. 给新手的阅读前置（背景知识地图）

- 这个子方向解决什么大问题：让不会写 SQL 的人用自然语言查数据库（「上季度华东区销量前十的产品是哪些？」→ 生成 SQL）。这是数据库自然语言接口（NLIDB）几十年来的核心命题，LLM 时代迎来了转折点。
- 为什么难：① schema linking——数据库几十上百张表、几百列，模型要挑出相关的表和列；② 领域差异——换一个新数据库（新业务术语、新表结构）性能骤降；③ 鲁棒性——同义改写、拼写变化、缺失信息都会让模型翻车。
- 几类主流解法：

| 解法 | 直觉 | 代表 |
|------|------|------|
| 闭源 LLM + 提示工程 | 直接调 GPT-4 加精心设计的 prompt | DAIL-SQL、C3 等 |
| 微调开源通用模型 | 在 Spider 等基准上微调 CodeLLaMA 等 | 各类 fine-tune 方案 |
| 专用开源模型（增量预训练） | 用 SQL 语料继续预训练一个代码模型 | 本文 CodeS |

- 本文属于：第三类——不是「调 API」也不是「简单微调」，而是从头造一个领域专用基础模型。
- 关键名词直觉解释：
  - 增量预训练（incremental pre-training）：在已有预训练模型（StarCoder）基础上，用领域语料（SQL 相关文本）继续训练，把领域知识「灌」进模型，而非从零训练。
  - Schema linking：把问题中的词与数据库的表/列对上，是 Text-to-SQL 最大的瓶颈之一。
  - Spider / BIRD：Text-to-SQL 两大权威基准——Spider 偏跨域结构泛化，BIRD 做大规模真实数据库 + 需要外部知识，更难。

## 1. 问题背景与动机

- 前人工作简述：LLM 出现后 Text-to-SQL 精度大跃升，但 SOTA 方法（DAIL-SQL、C3、CHESS 等）几乎都依赖 ChatGPT/GPT-4 做提示学习或结果选择。
- 前人缺陷/未解决问题（逐条，论文自述）：
  1. 模型架构不透明：闭源模型看不见内部结构，无法做研究分析与定制。
  2. 数据隐私风险：企业数据库 schema 和问题内容发给第三方 API 有泄密隐患。
  3. 推理开销大：闭源大模型调用昂贵，难以大规模部署到企业内部系统。
  4. （隐含）现成开源模型不经 SQL 特化训练，直接微调也难以匹敌闭源模型精度。

## 2. 核心方法

- 最直观类比：CodeS 像把一个「英语流利但没学过医的程序员」（StarCoder）送去医学院（SQL 语料增量预训练），再配上临床规培（提示构造 + 数据增强的微调），最后成为一名专精「听懂人话写 SQL」的专科医生。
- 具体做法（输入 → 关键操作 → 输出）：
  1. 增量预训练：构建专门筛选的 SQL 中心语料（SQL 相关代码与文本），在 StarCoder 基础上继续预训练，得到 1B/3B/7B/15B 四档模型；
  2. Schema linking（模式过滤）：用 schema item classifier（模式过滤器）先给问题筛选相关的表/列，缩短上下文、聚焦模型注意力；
  3. 提示构造：精心组织 prompt 呈现数据库模式与问题；
  4. 双向数据增强（bi-directional data augmentation）：针对「快速领域适配」设计——双向指 SQL↔自然语言两个方向的生成式增强，用少量样本快速适配新领域；
  5. 微调：在 Spider/BIRD 及真实金融、学术数据集上做 SFT；
  6. 输出：SQL 查询。
- 形式化要点：任务为 y = f(q, S)（自然语言问题 q + 数据库模式 S → SQL y）；CodeS 的贡献是把 f 实例化为「领域增量预训练的 LLM + 模式过滤 + 增强微调」的完整开源管线。
- 理论性质/保证：无理论保证；贡献在训练方法论与开源实证结果。

## 3. 变体 / 工程版（如有）

- 模型系列：CodeS-1B / 3B / 7B / 15B（Hugging Face：seeklhy/codes-1b 等）。
- 配套组件：`text2sql-schema-filter`（2024.4 发布的 3B 中英双语模式过滤器，可独立使用）；`text2sql-demo`（可自建的在线演示）。
- 训练脚本：仓库含 DomainAdaptation（领域适配）、增量预训练语料下载、DeepSpeed + Accelerate 分布式训练配置。

## 4. 实验结论（概览）

- 对比基线：闭源 LLM 提示方法（ChatGPT/GPT-4 系）与开源模型微调方案。
- 数据集：Spider（跨域权威基准）、BIRD（大规模真实库）、鲁棒性诊断集 Spider-DK / Spider-Syn / Spider-Realistic / Dr.Spider、两个真实场景数据集（金融、学术）。
- 指标：执行准确率（Execution Accuracy）等 Text-to-SQL 标准指标。
- 结论方向（论文摘要自述，经核实）：CodeS 以小得多的参数量在几乎所有挑战性 Text-to-SQL 基准上达到新的 SOTA 精度与鲁棒性（对 Spider、BIRD 及各鲁棒性诊断集均验证）。

## 5. 开源代码与动手实践

- 仓库地址：https://github.com/ruckbreasoning/codes （SIGMOD 2024 官方源码）
- 语言：Python（Hugging Face transformers + DeepSpeed + Accelerate 训练/推理栈）。
- 典型流程（教学示意，依据官方 README 整理）：
  1. 环境：安装 Java（评测需要）+ conda 环境 + PyTorch + requirements.txt + SimCSE；
  2. 下载：data.zip（预处理数据）、sic_ckpts.zip（模式过滤器权重）、Spider 官方评测脚本；
  3. 推理复现：跑 `run_few_shot_evaluations.sh`（少样本）或 `run_sft_evaluations.sh`（微调后）；
  4. 训练：Stage1 训练 schema item classifier（`train_sic.sh`）→ Stage2 训练 CodeS（`train_codes.sh`，DeepSpeed ZeRO-2，官方用 8×A800-80G，bf16）；
  5. 增量预训练：下载语料 → `tokenize_pt_corpus.py` → `pre_train.sh`（全局 batch 4,194,304 tokens）。
- 许可与资源提醒：Apache-2.0（代码+权重）。⚠️ 复现训练需要 8 卡 A800 级资源；普通玩家建议直接下载 HF 权重做推理，或跑 1B 档微调。

## 7. 2026 视角（🔧）

- CodeS 证明了「小而专」开源模型在 Text-to-SQL 的可行性与性价比，此后领域内开源专用模型与 agent 化方案并行发展。
- 2025 年以来趋势：① 检索增强 + 模式过滤成为企业级 Text-to-SQL 系统标配；② 多生成器集成与执行反馈修正（如 XiYan-SQL）把精度推向新高；③ 评测从静态基准走向真实企业数据平台场景。
- 工业落地中，数据安全与私有化部署需求让 CodeS 这类 Apache-2.0 开源模型具备直接商用价值。
- 🔧 本节为趋势性评述，最新 SOTA 与产品动态以公开资料为准。

## 8. 新手学习路线

- 10 分钟：读本笔记 + 论文摘要，理解「为什么不用 GPT-4 而要自己造模型」的三大理由。
