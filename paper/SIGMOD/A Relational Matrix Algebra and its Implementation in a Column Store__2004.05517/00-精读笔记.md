## 一句话总结

分析型查询常常要**在同一份数据上混合使用「关系代数（SQL 那一套）」和「线性代数（矩阵乘法那一套）」**。以往系统只能在实现层打补丁来桥接二者。本文在**逻辑层**提出 **RMA（Relational Matrix Algebra，关系矩阵代数）**：把线性代数无缝并入关系模型，所有操作都在「关系（表）」上做、结果也是关系，**无需额外数据结构**，并在 **MonetDB 列存**中实现验证其可行与高效。

## 0. 给新手的阅读前置（背景知识地图）

### 0.1 关系 vs 矩阵：两套语言
- **关系代数**：SQL 背后的代数，数据以「表」组织，操作是选择、投影、连接、聚合等。
- **线性代数**：机器学习/统计常用，数据以「矩阵」组织，操作是矩阵乘、转置、求逆等。
- 现实分析（如带特征的聚合、PCA、回归）既要 SQL 过滤，又要矩阵运算。

### 0.2 为什么「桥接」很难
- 关系系统和线性代数系统各自用不同数据结构（表 vs 矩阵），**互相转换有开销、易出错**，而且割裂导致优化器难以统一优化。

### 0.3 关键名词
- **列存（column store）**：数据库按列而非按行存储，对分析型扫描极快（如 MonetDB、Vertica）。
- **闭包（closure）**：代数里「操作结果仍是同一种对象」。RMA 的亮点是**闭环在「关系」上**——矩阵运算进出都是表。
- **在库分析（in-database analytics）**：不把数据导出到 Python/R，直接在数据库里完成分析。

## 2. 核心方法：RMA（关系矩阵代数）

### 2.1 直觉类比
过去像「两个说不同语言的人（SQL 与矩阵）要合作，得靠翻译在中间传话（实现层转换）」。RMA 的做法是**给矩阵运算也发一张「表语身份证」**：所有矩阵操作都用「关系（表）」来表达，结果也是表，于是两套语言统一成一种，无需翻译。

### 2.2 步骤与核心性质
1. **提出 RMA**：在关系模型内无缝集成线性代数操作。
2. **保持闭包（closed）**：所有 RMA 操作都在关系上执行、也产出关系，**不需要额外数据结构**。
3. **消除二分法**：矩阵与关系不再是割裂的两种东西，而是统一在同一代数下。

### 2.3 理论 / 实现性质
- 逻辑上自洽、闭环；
- 在 **MonetDB 列存**中实现，证明方案可行；
- 实证评测表明，对**混合工作负载（既有 SQL 又有线性代数）**，在库分析表现良好。
