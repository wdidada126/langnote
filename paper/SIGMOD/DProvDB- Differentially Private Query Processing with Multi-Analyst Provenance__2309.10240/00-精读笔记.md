## 一句话总结

把数据库的「隐私预算」当做一个由多个数据分析师共享的钱包：DProvDB 用细粒度的「隐私溯源」记录每个分析师各花了多少预算，从而在固定总预算下尽可能多地、尽可能准地回答大家的查询。

## 0. 给新手的阅读前置（背景知识地图）

- 子方向解决什么大问题：数据持有方想开放敏感数据给分析者查询，但不能泄露个人信息。差分隐私（DP）通过给查询结果注入可控噪声，提供可数学证明的隐私保证。核心矛盾是「隐私预算」：噪声加多了结果没用，加少了隐私守不住，而预算是随查询次数累积消耗的。
- 为什么难：预算是全局、累积、不可再生的。当不止一个分析师共享同一份数据时，如何「分蛋糕」就成了系统设计问题——分得不公平或浪费都会直接降低可用性。
- 几类主流解法：

| 路线 | 代表 | 直觉 |
|------|------|------|
| 语言层 DP 框架 | PINQ | 在查询语言层加噪声，预算按查询统一扣 |
| 优化代理模型 | FLEX | 用可学习的代理机制提升预算利用效率 |
| 优化器层 DP | PrivateSQL | 把 DP 约束做进查询优化器 |

- 本文属哪类：在上述系统思路上引入「多分析者 + 权限/信任分级 + 隐私溯源（provenance）」的细粒度预算管理，属系统与算法结合的 DP 数据库方向。
- 关键名词直觉解释：
  - *隐私预算（privacy budget, ε）*：一个「泄露额度」总账本，每答一次查询都会扣一点，扣完就不能再问。
  - *隐私溯源（privacy provenance）*：像数据库 provenance 记录「结果从哪来」一样，这里记录「每次查询的隐私损失归谁」。
  - *信任/权限级别*：不同分析者被滥用风险不同（如内部员工 vs 外部承包商），可据此分配不同的预算份额。

## 1. 问题背景与动机

- 前人工作：PINQ、FLEX、PrivateSQL 等系统已把 DP 落到实用查询引擎中，让分析者可以在可证明的隐私保证下查询敏感数据。
- 前人缺陷（论文摘要逐条指出）：
  1. 不区分分析者：现有设计把所有分析者当成一个无差别的整体；
  2. 单一实体视角 → 分配不公平：把大家当一个人看，预算消耗无法公平分摊到每个分析者头上；
  3. 互不串通视角 → 预算浪费：把大家当成互不串通的独立方、各自独立应答查询，同一个统计被问多次就重复扣预算，浪费总量。

## 2. 核心方法

- 最直观类比：公司食堂的餐补额度。以前要么全公司共用一个钱包（谁都用不知道谁花了多少），要么每人各发一个钱包（同一道菜被十个人各问一次，公司重复扣十次钱）。DProvDB 相当于给每人发一张带记账功能的饭卡，财务能看到每笔扣款归属，并能按职级（信任级别）给不同的人不同的额度。
- 具体做法（输入 → 关键操作 → 输出）：
  - 输入：多个分析师（带各自权限/信任级别）针对同一敏感数据库的查询流 + 一个固定的总隐私预算；
  - 关键操作：为多分析者场景构建细粒度隐私溯源框架，追踪并归因每一次查询造成的隐私损失到单个分析者；在此框架上设计预算分摊算法，按分析者的权限级别分配预算份额；
  - 输出：在固定总预算下，最大化「能被较准确回答的查询数量」的应答方案。
- 形式化要点：以 DP（ε 预算）为约束，把「预算分摊 + 查询应答」形式化为一个带归因（per-analyst privacy loss accounting）的优化目标，目标是最大化可准确回答的查询数（具体优化式与算法细节查原论文 🔧）。
- 理论性质：作为 DP 系统，每个查询应答保持差分隐私保证；隐私损失可精确归因到每个分析者（🔧 完整定理表述查 PACMMOD 版）。

## 3. 变体 / 工程版（如有）

- 官方仓库中实验代码含两种任务模式：`RRQ` 与 `EQW`，以及一个名为 BrownianMechanism 的机制分支（来自仓库提交记录，具体语义查 README/论文 🔧）。
- 系统实现构建在 Chorus（uvm-plaid/chorus，一个 Scala DP 查询框架）之上，作为 git 子模块集成。

## 4. 实验结论（概览）

- 对比基线：把分析者视为单一实体的应答方式 vs 互不串通独立应答的方式（与 DProvDB 的分级分摊策略对比）🔧 具体基线系统查原论文。
- 数据集：UCI Adult 数据集 + TPC-H 1GB（由官方仓库 README 核实）。
- 指标：固定隐私预算下的查询回答可用性（如查询可回答数量 / 误差）🔧 精确数字查原论文后补。
- 结论方向：利用多分析者间的预算统筹与权限分级分摊，可以在不放松隐私保证的前提下比「一刀切」的预算策略回答更多、更准的查询。

## 7. 2026 视角（🔧）

- DP 数据库方向自 PINQ 以来已形成「语言层 → 优化器层 → 多主体预算治理」的演进脉络；多分析者/多利益方的预算分摊在今天的数据共享、数据市场与联邦分析场景里愈发重要。
- 工业侧 DP 落地主流包括 Google 的 DP 工具集（如 DP-on-Beam/PipelineDP）、OpenDP、以及各家云厂商的隐私分析服务（本条为方向性概述，具体产品对照 🔧）。
- 后续趋势：DP 与差分隐私式学习（DP-ML）、合成数据、可信执行环境（TEE）的组合方案是近年热点。
