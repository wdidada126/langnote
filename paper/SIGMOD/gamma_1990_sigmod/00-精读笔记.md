# Gamma — An Introduction to a Partially Relational Database Machine — 精读笔记

> PVLDB 1989 / 正式系统文 "The Design and Implementation of the Gamma Database Machine" (SIGMOD 1990, DeWitt et al.)（⚠️ 版本二说，本档以 SIGMOD 1990 设计实现文为主锚）
> 三态标注：✅ 论文硬写事实 / ⚠️ 记忆或二手归纳 / 🔧 本地可复演实验

## 一、基本信息

| 项 | 内容 |
|---|---|
| 会议 | SIGMOD 1990（DeWitt, Schneider 等，Wisconsin）· "数据库机"时代压轴 |
| 定位 | 共享无（shared-nothing）**水平分区数据库机**：几十个处理器各带磁盘+内存，Ethernet 互联，SQL 式操作符流水线（✅） |
| 同代三角 | Gamma（分区+操作符并行）· Bubba/⚠️ · Teradata DBC（商用先驱）；Prisma/DBX（1993 ⚠️ 本批未建，可后补） |

## 二、问题史：VLSI 梦碎后的"机器"是什么

- 1980s "数据库机"运动（直接执行关系语言的专用硬件 ⚠️ 背景）败给通用 CPU 摩尔定律——Gamma 的转型答案：**机器=现成处理器阵列+并行分区算法**（✅）。
- 命题：并行度从"操作符间"转向"操作符内"（partitioned execution），代价模型回答"多少处理器才不白搭"（✅）。

## 三、核心设计（✅ §2–§4 主题）

- **水平分区**（round-robin/区间）打散到各节点；查询=操作符树，每操作符在本地分区并行（✅）。
- **数据重分布（re-partitioning）一等公民**：join 两侧按键重分区（"shuffling"）——分布式 join 的 shuffle 原型（✅ 谱系：现代 Spark/Trino 术语直承）。
- 操作符：select/project/join/aggregate/transitive closure（图闭包作为一等操作符，✅ 特色）。
- 事务：分区局部原子+跨分区两阶段；死锁检测中心环检测（⚠️ 细节凭记忆）。
- 容错：节点故障→查询失败重启；无细粒度恢复（✅ 论文坦率）。

## 四、评测（✅ 定性 + ⚠️ 凭图表）

- 加速比实验：join 随节点数近线性到通信拐点；聚合类扩展最好、跨分区事务类最差（✅ 结论方向）。
- "扩展公式"（scaleup）：数据与机器同比扩大时响应近似恒定（✅ 论文对 scaleup/partial-speedup 的区分是并行 DB 度量学模板）。

## 五、批判读法

- 硬件昂贵（64 节点实验平台）与"为特定应用造机器"的局限，宣判了数据库机叙事终结——并行 DB 的正确容器是通用集群（⚠️ 史评）。
- 论文重心在算法与加速比，**成本/调度均衡（skew、异构）**几乎未触——此后三十年 MPP 的所有运维事故都在这两条空白里（⚠️）。
- 闭包操作符的"递归 SQL 先声"意义大于实现（✅ 对照 SQL:1999 递归 CTE）。
- 与 Redshift（SIGMOD 2012 ⚠️ 未建）对读有趣：Redshift 论文几乎重述 Gamma 世界观（列存除外）——MPP 是轮回而非线性进步（⚠️ 判断）。

## 六、🔧 本地微实验（非本书引擎行为）

1. **分区 join**：multiprocessing N 进程各持不相交键段，本地 join+跨段 shuffle 文件，测加速比曲线找拐点。
2. **round-robin vs 区间**：范围查询占比不同下两种分区的数据搬运量对比。
3. **重分布代价**：广播小表 vs 两侧 shuffle，按表大小比例画决策边界（呼应 [[grace_hash_join_1990_sigmod]] 本批已建判据）。
4. **闭包迭代**：递归 SQL 求传递闭包，轮次×行数感受"操作符即程序"。
5. **scaleup 复测**：数据×N 且进程×N，响应时间近恒定的成立/崩塌条件。

## 九、最新演进与工业实践

- "数据库机"死于通用硬件经济学，分区+shuffle 借 Hadoop/Spark 还魂（✅ 判断）。
- MPP 商用线（Teradata→Snowflake/Redshift/ClickHouse）的每个卖点都能在 Gamma 找到原型段落；论文是"读现代 MPP 的密钥"（⚠️ 评价）。
- 2024–2026：Serverless MPP（自动分区数）把 Gamma 的"选几台机器"问题交给平台——问题消失即论文胜利（⚠️ 判断）。
