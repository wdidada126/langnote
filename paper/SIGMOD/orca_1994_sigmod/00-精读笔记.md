# Query and Data-Flow Optimization in ORCA (Orca) — 精读笔记

> 常见引本：Graefe, "Query and Data-Flow Optimization in ORCA"（1994，或 1993 VLDB 原型文；亦常引 "Next Century Challenges" 中的 Orca 线）· SIGMOD Bulletin / VLDB，⚠️ 版本二说请并读
> 三态标注：✅ 论文硬写事实 / ⚠️ 记忆或二手归纳 / 🔧 本地可复演实验

## 一、基本信息

| 项 | 内容 |
|---|---|
| 系统 | ORCA（Optimized Research Compiler Architecture，AT&T Bell Labs，Graefe 主笔）|
| 定位 | 把 Volcano/ExODUS 的"规则+搜索"工程化成**可扩展代价模型 + 通用搜索框架**，SQL 编译进多后端 |
| 谱系 | Volcano/Cascades（库内 [[volcano_1993_edbt]] 已建）→ ORCA → Greenplum（2010s 开源复活，✅ 后续段） |

## 二、问题史：Selinger 式 DP 的三个天花板

1. 计划空间被左深树/固定算子表写死，加一种物理属性要改核心代码（✅ 对照 [[selinger_1979_sigmod]]）。
2. 代价规则与枚举逻辑缠绕，难移植到新硬件/新算子（✅）。
3. 并行流式计算（dataflow）没有一等优化器框架（✅ 论文动机：ORCA 同时优化 SQL 与 dataflow 图）。
→ 答案：**搜索框架与领域规则彻底解耦**——memo 存等价表达式，规则任意改写，代价按"属性要求+物理属性"递推（✅ Cascades 三件套成型）。

## 三、核心机制

### 3.1 Memo 与表达式组

- 查询→逻辑表达式插入 **memo**（等价类森林）；每组按"所需物理属性"分多个**最优分组**（⚠️ 术语：group/properties/provenance 三结构，细节以原文为准）。
- 规则分两类：**变换规则**（逻辑→逻辑，等价改写）与**实现规则**（逻辑→物理）——规则库即扩展点（✅ 招牌设计）。

### 3.2 自顶向下派生 + 自底向上计价

- 搜索以"目标属性请求（E-cost/explore 任务栈）"驱动：派生者（derivers）拆子目标，优化者递归比价——与 Selinger 自底向上 DP 方向相反（✅）。
- 剪枝靠"上界成本 + 约束传播"；任务栈机器可打断复用（⚠️ 实现细节凭记忆）。

### 3.3 双查询语言与 dataflow

- ORCA 上层：SQL 前端 + **dataflow 图语言**（流式算子优化同源）——为 Bell Labs 的 Locus/Parallel 遗产服务（⚠️ 谱系判断）。
- 编译后端：生成 C 代码（轻量编译执行思想早于 HyPer ⚠️ 评价口径）。

## 四、评测（✅ 定性）

- 论文给的多为案例演示（join 重序、聚合下推、并行流水线），系统级基准薄弱（⚠️）。
- 真实战绩在工业：Microsoft SQL Server 优化器（后称"Cardinality Estimation 70/SQL Server 7 时代的新优化器"）由 Cascades 落地，ORCA 论文是其公开学术版（✅ 判断）。

## 五、批判读法

- 规则库穷举之痛：Cascades 强大但**规则组合爆炸**，工程调参（搜索时间预算、规则启用集）变成黑魔法——SQL Server 每代都在调（⚠️）。
- 论文对**统计/基数估计**几乎不谈（复用 Volcano 时代模型）：框架再优雅，垃圾进垃圾出；Greenplum ORCA 多年后被 GP 自家"planner 回退开关"打脸即此因（⚠️）。
- "可扩展性"有边界：新**逻辑**算子（窗口/递归）仍要改核心派生器；扩展点只对物理多样性友好（⚠️）。
- 阅读建议：与 Volcano'93 并读——前者给搜索引擎，后者给操作语义（✅）。

## 六、🔧 本地微实验（非本书引擎行为）

1. **迷你 memo**：3 表连接的等价表达式哈希表（交换/结合规则各 2 条），统计去重前后搜索节点数。
2. **逻辑/实现规则二分**：同一 hashjoin/nestedloop 实现规则挂到不同逻辑 join 上，感受"规则与枚举解耦"。
3. **自顶向下 vs DP**：同一空间分别实现两种搜索，对比找到首个可行解与最优解的时间。
4. **属性下推搜索**：给计划节点加"要求排序列"位，实现最小化排序次数的分支定界。
5. **代价上界剪枝**：先用贪心解定上界，记录 DP 中被剪枝的分支比例。

## 九、最新演进与工业实践

- Greenplum 7 默认 ORCA、ClickHouse/StarRocks 等新一代部分回归"简化 DP+规则混合"；ORCA 开源仓库维护至今（⚠️）。
- Calcite 把"逻辑优化=规则 DAG、物理搜索=Volcano/Cascades 混合"商品化，是本文思想的教科书化（⚠️）。
- 学习式优化（Bao ⚠️ 库内已建档）不改框架、只换引导策略——Cascades 的规则接口恰好成为"学习+规则"混合的理想挂载点（✅ 判断）。
- 2024–2026：AI 生成计划候选+优化器验证的"生成式优化"叙事里，memo+规则体系是现成的安全护栏（⚠️ 判断）。
