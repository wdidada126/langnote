## 一句话总结
Relational Playground 是一个给学生玩的小工具：把「写 SQL」和「关系代数（数据库引擎内部表示查询的方式）」双向对应起来展示，帮入门者直观理解「我写的 SQL 在引擎眼里长什么样」——补足只教 SQL 却不懂执行原理的短板。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：数据库入门课常只教写 SQL（实用），但学生不懂查询在引擎内部如何被表示与处理（关系代数），导致「会写但不懂原理」。
- **为什么难**：关系代数是抽象的内部表示，学生难建立它与 SQL 的对应直觉。
- **几类主流解法（教学）**：

| 方法 | 代表 | 思路 |
|------|------|------|
| 黑板推导 | 课堂教学 | 手画代数树 |
| 交互工具 | **Relational Playground** | SQL↔代数双向可视化 |

- **本文属哪类**：教学工具（系统论文），非新算法。
- **2-3 个必懂关键名词**：
  - **关系代数（relational algebra）**：选择 σ、投影 π、连接 ⋈ 等运算符，是查询的逻辑表示。
  - **SQL**：声明式查询语言，用户写「要什么」。
  - **二象性（duality）**：同一查询在 SQL 与关系代数下是等价的两种面孔。

## 2. 核心方法（工具设计）
- **最直观类比**：像「中英双语对照卡」——左边写 SQL，右边同步显示关系代数，学生改一边、看另一边怎么变，自然建立两种语言的映射。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：学生写的 SQL（或代数）。
  2. **双向映射**：工具把 SQL 与关系代数对应展示。
  3. **输出**：可探索的「SQL↔代数」可视化界面。
- **形式化要点**：核心是 SQL 与关系代数等价表示的互显；超参数为展示粒度（🔧 见论文/工具）。
- **理论性质/保证**：不适用（教学工具）。
