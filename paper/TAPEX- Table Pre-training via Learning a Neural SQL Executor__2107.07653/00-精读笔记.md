## 一句话总结
表格预训练难在「没有大规模高质量的表格语料」。TAPEX 的妙招是：自动合成大量「可执行的 SQL + 执行结果」，让语言模型去**模仿 SQL 执行器**（给表 + SQL，预测执行输出）。这样模型被迫学会表结构与 SQL 语义，于是在四个下游数据集上都刷新了当时的 SOTA（WikiSQL 弱监督指称准确率 89.5%、WikiTableQuestions 57.5%、SQA 74.5%、TabFact 84.2%）。

## 0. 给新手的阅读前置（背景知识地图）
- **这个子方向解决什么大问题**：让模型「先懂表格，再解任务」——即表格预训练（table pre-training），下游可以接表格问答、事实核查等任务。
- **为什么难**：
  - 无结构文本有海量语料，而**大规模高质量表格语料缺**；
  - 表格是二维结构，语言模型的序列建模不直接适配；
  - 下游任务需要「结构化推理」（筛选、聚合、比较），纯文本预训练学不到。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 掩码语言建模式表格预训练 | TAPAS 类 | 在表格 + 文本上做 MLM 类目标 | 简单，结构化推理弱 |
| 合成可执行程序做监督 | **TAPEX** | 合成 SQL 与其执行结果，让模型学「执行」 | 推理能力强，依赖 SQL 合成质量 |
| 大规模表格指令微调 | TableGPT2 等 | 用「查询-表格-输出」三元组微调 | 通用性强，成本高 |
| LLM 直接推理 | 通用 LLM + prompt | 不做专门预训练 | 零成本接入，稳定性一般 |

- **本文属于哪一类**：第二类——**首个**用合成可执行程序做表格预训练并取得 SOTA 的工作。
- **必懂关键名词（直觉版）**：
  - **神经 SQL 执行器**：不给模型写执行引擎，而是让它「学着像执行引擎那样输出答案」。
  - **合成语料（synthetic corpus）**：程序自动生成 SQL 并在表上跑出结果，规模与质量可控。
  - **denotation accuracy（指称准确率）**：预测答案与标准答案一致就算对（比「SQL 完全一致」宽松）。

## 1. 问题背景与动机
- 前人工作简述：语言模型预训练在无结构文本上大获成功，也出现了若干表格预训练尝试。
- 前人缺陷 / 未解决问题（逐条）：
  1. **表格语料稀缺**：缺少大规模、高质量、带结构监督的表格数据；
  2. **结构化推理能力不足**：把表格当纯文本预训练，学不会筛选/聚合/比较这类操作；
  3. **下游提升有限**：此前的表格预训练方法在下游任务上的增益不大。

## 2. 核心方法
- **最直观类比**：想让学生精通表格，就让他刷大量「给表 + SQL，写答案」的练习题——刷熟了，表的结构和 SQL 的语义就内化成了直觉。
- **具体做法（输入 → 关键操作 → 输出）**：
  - 输入：大量表格 + 自动合成的**可执行 SQL 查询**及其**执行输出**。
  - 关键操作：
    1. **自动合成语料**：在表格上自动生成大量可执行的 SQL，并跑出执行结果（这就是「 diverse, large-scale and high-quality synthetic corpus」）；
    2. **预训练任务**：让 seq2seq 语言模型在给定「表 + SQL」的条件下预测执行输出，即**模仿 SQL 执行器**；
    3. **下游微调**：把预训练模型用于表格问答、事实核查等任务。
  - 输出：一个「懂表结构和 SQL 语义」的预训练模型。
- **形式化要点**：核心是「合成 SQL 的采样/生成策略」与「执行器模仿目标」；基座模型与规模 🔧 查原论文。
- **理论性质 / 保证**：**无**理论保证（论文以预训练设计与实验为主 🔧）。

## 3. 变体 / 工程版（如有）

## 4. 实验结论（概览）
- 对比基线：此前的表格预训练方法，以及各数据集上当时的 SOTA 系统。
- 数据集：**四个**基准数据集（含 WikiSQL、WikiTableQuestions、SQA、TabFact）。
- 评价指标：denotation accuracy（指称准确率）与 accuracy。
- 结论方向（摘要给出的已核实数字）：
  - TAPEX 大幅超过此前的表格预训练方法，并在**全部四个**数据集上取得新的 SOTA；
  - WikiSQL 弱监督 denotation accuracy → **89.5%**（+2.3%）；
  - WikiTableQuestions denotation accuracy → **57.5%**（+4.8%）；
  - SQA denotation accuracy → **74.5%**（+3.5%）；
  - TabFact accuracy → **84.2%**（+3.2%）。
- 🔧 各数据集的基线绝对值与消融请查原论文 Table 后补入。

## 7. 2026 视角（🔧）
- 「合成数据 + 执行反馈」至今仍是提升表格/SQL 推理最有效的手段之一，也是大模型后训练（RLVR 类方法）的数据来源思路。
- 表格预训练本身已融入通用大模型能力：现在的做法更多是「生成 SQL/代码 + 沙箱执行」，而不是单独训一个表格模型。
- 本节为趋势性判断，具体数字 🔧 查当年资料。

## 8. 新手学习路线
- **10 分钟**：读摘要 + 本笔记 §0、§2，理解「模仿 SQL 执行器」这个预训练任务。
