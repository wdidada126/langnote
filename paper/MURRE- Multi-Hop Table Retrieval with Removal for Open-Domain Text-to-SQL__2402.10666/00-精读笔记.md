## 一句话总结
开放域 Text-to-SQL 要先从海量库里「检索出和问题相关的表」再生成 SQL；MURRE 发现单跳检索不够、而直接套用问答里的多跳又会越检越偏，于是提出「每检索一轮就把已找到的信息从问题里删掉」，逼着检索器去找还没找到的相关表，平均比之前 SOTA 高 5.7%。

## 0. 给新手的阅读前置（背景知识地图）
- **子方向解决什么大问题**：Text-to-SQL 通常假设「数据库已经给定」。但真实场景（开放域）里可能有成千上万个库/表，得先帮模型挑出「该看哪几张表」，这一步叫 table retrieval（表检索），再做 SQL 生成。
- **为什么难**：一张表往往不够，问题涉及多张表（多跳）；而且检索错了，后面 SQL 再强也白搭。
- **几类主流解法**：

| 方法 | 代表 | 思路 | 优缺点 |
|------|------|------|--------|
| 单跳检索 | 直接用 question 向量找最像的表 | 简单 | 多表问题漏检 |
| 多跳检索（QA 式） | 开放域 QA 的多跳 | 迭代补充上下文 | 易检出「和已检表相似但无关」的表 |
| 本文 MURRE | 多跳 + 剔除已检索信息 | 逼模型找新表 | 更准，但实现更复杂 |

- **本文属哪类**：表检索（retrieval）阶段的方法创新，属于「开放域 Text-to-SQL 的前置模块」。
- **2-3 个必懂关键名词**：
  - **open-domain Text-to-SQL**：数据库不预先给定，先检索再生成。
  - **multi-hop retrieval（多跳检索）**：分多步逐步找齐相关表/文档，而非一步到位。
  - **retrieval-augmented（检索增强）**：先拿相关上下文喂给生成模型，再产出答案。

## 1. 问题背景与动机
- 前人工作简述：开放域 Text-to-SQL 一般先做表检索再生成 SQL；多跳检索在开放域问答里已被证明有用。
- 前人缺陷/未解决问题（逐条）：
  1. **单跳检索天花板低**：一次检索只能找到和问题表面相关的表，涉及多张表的问题容易漏。
  2. **直接套 QA 多跳会跑偏**：QA 的多跳靠「用已检索文档补充问题」；但 Text-to-SQL 的问题本身已包含全部所需信息，再补充反而让检索器去抓「和已检表相似但和问题无关」的表。

## 2. 核心方法
- **最直观类比**：找资料时，如果你已经找到了 A 表的内容，就把它从「待办清单」里划掉，逼自己去看还没翻过的 B、C 表，而不是反复翻和 A 差不多的东西。
- **具体做法（输入 → 关键操作 → 输出）**：
  1. **输入**：用户问题 + 海量候选表集合。
  2. **多跳 + 剔除（Removal）**：每一轮检索前，把「上一轮已经检索到的信息」从问题表示中移除，让检索器的 query 只剩下「还没被满足的部分」。
  3. **迭代**：重复检索→剔除，直到凑齐相关表集合。
  - 输出：一组与问题相关的表，交给后续 SQL 生成器。
- **形式化要点**：核心是「query 重写/降维」——每轮用「原始问题 − 已检索信息」作为新检索向量；迭代轮数即主要超参（🔧 具体以论文为准）。
- **理论性质/保证**：无理论保证；以Empirical 提升为主。

## 3. 变体 / 工程版（如有）
- 剔除策略可替换为不同的「信息擦除」方式（如掩码、相减、重述），是与具体检索器解耦的前置模块，易插到现有开放域 Text-to-SQL 流水线里。
