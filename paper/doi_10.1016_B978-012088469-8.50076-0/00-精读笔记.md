## ② 背景与它回应的问题

### 2.1 2004 年前后的"不确定数据"语境

彼时"概率数据库"不是一个新词，而是一堆各说各话的局部系统。论文的相关工作一节把前人分成两类（这个二分本身就是这篇论文的立论骨架）：

- **外延式（extensional）系统**：直接把概率当成列上的实数，用简单公式在算子之间传播。
  - Cavallo & Pittarelli (VLDB'87)：同一关系内的 tuple 事件**互斥**；
  - Barbara, Garcia-Molina & Porter (TKDE 1992) 的 probabilistic data 模型：tuple 独立，但属性可能不精确（由此产生互斥事件），并且要求每个关系存在一组"确定性属性构成主键"；
  - Dey & Sarkar：放宽键的限制，但只允许包含键的投影；
  - ProbView (Lakshmanan, Leone, Ross, Subrahmanian, TODS 1997)：不假设独立性，但要用户手工提供组合策略，且用区间概率而非点概率。
  - 论文的批评（原话大意）：这些系统**没有一个能正确处理任意合取查询**。
- **内涵式（intensional）系统**：用符号事件表达式（复合物件）跟踪相关性，语义精确但代价高；这一路可追溯到 Kripke 的可能世界语义、AI 里的概率逻辑（Ng & Subrahmanian 1992；Bacchus/Grove/Halpern/Koller 1996；Fagin & Halpern），数据库侧的代表是 Fuhr & Röllke 的概率关系代数（ACM TOIS 1997）以及 Daley/后续工作。

同期还有另一条不基于概率的路线：VAGUE (Motro)、DISCOVER、X-Rank、DBExplorer、Agrawal/Chaudhuri/Das/Gionis 的单表打分排序——它们只处理单表，连接查询上的语义是 ad hoc 的。

### 2.2 问题到底是什么

数据集成、数据清洗、IR 风格的近似匹配（拼错的常量、模糊谓词、本体距离、q-gram）会持续产生"带置信度的 tuple"。用户想要的是：**把一条结构完整的 SQL（含连接、子查询、group-by、聚合、存在/全称量词）打上不确定谓词，仍然有明确语义，并且结果按概率排序返回**。

这带来一个具体的算法问题。设概率数据库 Dp，其语义是可能世界上的分布 pwd(Dp)。查询 q 的"真答案"是答案集合上的分布 qpwd(Dp)，它可能有指数多种答案（若某关系有 n 个 tuple，可能世界就有 2^n 个）。返回它是不可行的，于是论文要求返回**每 tuple 的 rank**：

    rank_q(t) = Σ { Pr_q(S) | S 是可能答案集合且 t ∈ S }

即"t 出现在答案中的概率"，输出是一张带 Rank 列的表 qrank(Dp)，按 Rank 排序——这就是"像 IR 一样返回 rank"的数据库版本。

**核心难点**（论文用一整节例子讲清楚，是本文最好的教学材料）：即使基表中各 tuple 事件相互独立，**中间结果里的 tuple 事件也不再独立**（投影会把多个 tuple 合成一行、连接会让两行共享同一个原子事件）。于是"逐算子套公式"的概率传播会算错，而且**同一查询的不同执行计划给出不同（且多为错误）的概率**。这就是这篇论文的全部张力所在。

论文给出的经验性动机：TPC-H 的 10 条查询，把所有 WHERE 谓词都替换成不确定匹配后，只有 2 条落入"没有正确高效计划"的类（期刊版引言，会议版实验部分与之吻合：Figure 6 只画了 Q1–Q6、Q9、Q10 共 8 条有安全计划的查询）。

## ③ 技术内容精读

### 3.1 表示：事件属性 + 函数依赖

论文的模型定义刻意用关系代数的语言（这是它比同时代 AI 风格表述更适合数据库人的原因）：

- 原子事件集 `AE`，每个 `e ∈ AE` 有 `Pr(e) ∈ [0,1]`，原子事件之间**独立**；`⊥ ∈ AE` 表示不可能事件，`Pr(⊥)=0`。
- 复合物件（complex event）：由原子事件用 `∨, ∧, ¬` 构成，`E` 是其集合。
- **概率关系** `Rp` = 普通关系 + 一个特殊的事件属性 `E`，其值是复合物件。
- 恒含函数依赖 `Attr(R) → Rp.E`：保证同一 tuple 不会挂两个不同事件（要挂一个合取式）。
- 记 `eR : U^k → E` 为函数式表示（不出现的事件取 `⊥`）。
- 若某概率关系中**每个 tuple 挂的是互不相同的原子事件**，会议版称之为 **extensional probabilistic relation**（期刊版改称 **tuple-independent**，即后来通称的 TI 模型）；否则称 intensional。

可能世界语义（一句话）：world r 的概率 = `Pr(∧_{t∈r} eR(t) ∧ ∧_{t∉r} ¬eR(t))`，可以验证所有 world 概率和为 1；带函数依赖时，任何非零概率的 world 必然满足由 `Σp` 投影出的确定性依赖 `Σ`。

**查询语义**：`Pr_q(S) = Σ_{D : q(D)=S} Pr(D)`。这个定义的好处是"对任何在确定数据库上有定义的查询都成立"——不需要为概率扩展重写查询语言，只需给一个求值算法。

**表示能力完备（期刊版 Thm 1）**：任意可能世界分布 W（即任意 U 上有限实例集合上的概率分布）都能被某个概率数据库 Dp 精确表示。证明用递归二分：对 2^k 个实例，用 2^k − 1 个独立变量构造两两互斥的事件 `fW(Di)`，再令 `eR(t) = ∨_{Di ∋ t} fW(Di)`。这条定理的实际含义是：**模型层面不存在表达力短板，短板全在求值算法上**。

### 3.2 两条求值路线：intensional 正确但贵，extensional 便宜但错

**内涵式（符号事件，期刊版图 6）**：把 `π, σ, ×` 替换为 `πi, σi, ×i`，中间 tuple 携带事件表达式：连接取合取，投影取析取，选择按谓词真值保留/置 `⊥`。

- 期刊版 Thm 2：对合取查询，`pwd(q_i(Dp)) = q_pwd(Dp)`，即内涵式与可能世界语义**等价**（对每个 world 逐 tuple 归纳，不依赖计划形状）。于是 `qrank(Dp) = Pr(q_i(Dp))`。
- 不可用的原因有两条：(a) 投影会让事件表达式膨胀，最坏情形与数据库同阶，算子的每 tuple 代价不再是常数；(b) 对每个 tuple 求 `Pr(e)` 本身就是 **#P-complete**（Valiant；即使无否定的单调公式也难，Provan & Ball 的 bipartite monotone 2-DNF 计数）。

**外延式（数值概率，期刊版图 8）**：把事件表达式换成实数：

    Pr_σe(P)(t)   = Pr_P(t) 若 c(t) 真，否则 0
    Pr_πe(P)(t)   = 1 − Π_{t': π(t')=t} (1 − Pr_P(t'))        ← 独立并
    Pr_×e(P)(t,t') = Pr_P(t) · Pr_P(t')                        ← 独立积

这三条公式**假设输入之间独立**。论文的示例（会议版图 4/5，期刊版图 4/5）非常干净：

- 基表 Sp 有两个 tuple `s1(0.8), s2(0.5)`，Tp 有一个 tuple `t1(0.6)`，查询 `q(u) :- Sp(x,y), Tp(z,u), y=z`。
- 计划 `π_D(Sp ⋈_{B=C} Tp)`：连接结果两行共享原子事件 `t1`，不独立；`π` 用独立并公式给出 **0.636**，而真值是 **0.54**（= 0.24+0.24+0.06）。**错。**
- 计划 `π_D(π_B(Sp) ⋈_{B=C} Tp)`：先把 Sp 投影到 B（0.8⊕0.5 = 0.9，两个事件本就不相关于 Tp 的事件），再连接、再投影，得 **0.54**。**对，而且对任意该 schema 上的实例都对。**

结论：不是"外延式不行"，而是**存在一类计划，其外延求值恰好正确**。找出并刻画这类计划，就是本文的主任务。

### 3.3 safe plan：定义与判定定理

> **定义（会议版 Def 4.4 / 期刊版 Def 1）**：给定 schema `R*p, Σp` 和查询 q 的一个计划 P。若对**该 schema 的所有实例 Dp** 都有 `P_e(Dp) = qrank(Dp)`，则称 P 是 **safe（安全）** 的。

> **算子安全判定（会议版 Thm 4.5 / 期刊版 Thm 3）**：设 q, q' 是不共享关系名的合取查询，在 tuple-independent schema 上，`Σp(q)` 是由原始依赖 + 连接等值产生的双向依赖 + 选择常量依赖构成的"诱导依赖闭包"，`Head(q)` 是输出属性集。则：
> 1. `σe` 在 `σ(q)` 上**恒安全**；
> 2. `×e` 在 `q × q'` 上**恒安全**（不共享关系 ⇒ 事件互不相干 ⇒ 独立性成立）；
> 3. `π^A1…Ak_e` 在 `π^A1…Ak(q)` 上安全，**当且仅当**对每个概率关系 `Rp ∈ PRels(q)`：
>
>        A1,…,Ak, Rp.E → Head(q)      在 Σp(q) 下可推出   (Eq. 1)

第 3 条的直觉是全部要点：投影会把多个输入 tuple 折叠成一个输出 tuple，只有当"没有任何原子事件同时出现在两个折叠组里"时独立并公式才成立；Eq. 1 正是"事件到输出键的函数依赖"这一条件的 FD 表述（投影属性 + Rp 的事件 → 输出属性，意味着事件不跨组泄漏）。

> **反向（会议版/期刊版 Thm 4，期刊版）**：若一个只含选择/投影/连接的关系代数计划是 safe 的，则它**每个算子都必须是 safe 的**——即 safe 计划 = 全安全算子计划，不存在"单步都不安全但整体抵消"的侥幸。证明靠两件事：只有投影会引入误差，且**误差是单侧的（只会高估）**，因此复合时不能相互抵消。这个"单侧误差"观察后面还用于 least-unsafe plan。

### 3.4 Safe-Plan 优化算法（本文的工程内核）

先给两个图论化的术语（期刊版 Def 2/3）：

- **connected**：查询含连接条件 `Ri.A = Rj.B` 且 `Ri.A` 或 `Rj.B` 不在 `Head(q)` 中，则称 Ri、Rj 相连；否则 separate。
- **separation**：`Rels(q)` 的一个划分 (S, T)，使任意跨块关系对都 separate。

算法（会议版 Algorithm 1 / 期刊版 Algorithm 1，自顶向下）：

```
Safe-Plan(q):
  if Head(q) = Attr(q):            # 无需投影 ⇒ 投影自由计划恒安全
      return 任意计划（连接/选择的任意顺序）
  for A in Attr(q) − Head(q):      # 尝试把每个待消属性"尽量晚"地投影掉
      q_A := 把 A 加入 head 的查询
      if π^Head(q)_e 在 π^Head(q)(q_A) 上安全:      # Eq. 1 判定（FD 闭包）
          return π^Head(q)( Safe-Plan(q_A) )
  # 没有任何"安全的晚期投影" ⇒ 最后一个算子必然是连接
  按约束图 G(q) 的连通分量把 q 切成 q1 ⋈c q2（separation）
  if 不存在这样的切分: return error("no safe plans exist")
  return Safe-Plan(q1) ⋈c Safe-Plan(q2)
```

`G(q)`：节点是 `Rels(q)`，边是"因某属性不在 head 中而相连"的关系对。**G(q) 连通 ⇒ 无安全计划**（除非该查询本就不需要晚期投影）。

三个值得记住的细节：

1. **"投影尽量晚"** 是算法的形状：先试所有晚期投影，实在不行才切连接。因为连接总是安全、投影才危险，所以一切以"把危险算子推到 head 属性足够多、事件已被 FD 锁住的位置"为目标。
2. **切分方式不唯一，但"任一分离切分都能导出安全计划"**（期刊版 Thm 5）——因此切分选择可以交给传统代价优化器，只需在其目标函数上加"连接顺序偏好"（期刊版 Thm 9/10 给出 5 条形如交换律/结合律/投影级联/投影下推/投影上抬的**可靠且完备**的变换规则：任意两个 safe 计划都可通过这组规则互推，这是"概率查询优化"的第一套代数）。
3. **期刊版 Thm 6（完备性）**：Safe-Plan 能找到所有存在安全计划的问题实例——即"算法返回失败 ⇔ 该查询无安全计划"。会议版给出可靠性（Prop 4.9，Soundness），完备性放到期刊版与理论分析章。

会议版 Example 4.8 完整跑通了 `q(D) :- Sp(A,B), Tp(C,D), B=C`：`A` 不能晚期投影（`π_{A,D}` 使 `π_D` 违反 Eq. 1），`B`、`C` 可以；切分后 `π_D(π_B(Sp) ⋈_{B=C} Tp)`，与 3.2 的手工答案一致。

### 3.5 复杂度二分：哪些查询在哪个模型下 #P-hard

这是"精读要点"里最需要精确讲清的部分。前提全部限定在 **tuple-independent（会议版称 extensional：`Σp` 只含平凡依赖 `Attrs(R) → Rp.E` 与 `Rp.E → Attrs(R)`）**，且 **每个关系至多出现一次（self-join-free）**。

**（1）单点 #P-hard 例（会议版 Thm 5.1 / 期刊版 Thm 7）**

    q() :- Lp(x), J(x,y), Rp(y)

Lp、Rp 是概率表，J 是**确定表**（加强结论）。数据复杂度 #P-hard。

归约：Provan & Ball 证明**二部单调 2-DNF 公式的赋值计数**（变量分为 X、Y，每个子句形如 `x_j ∧ y_k`）是 #P-complete。给定公式 φ，令 Lp = X 中变量、Rp = Y 中变量（独立、概率各 1/2），J = φ 各子句对应的 (x_j, y_k) 对。则 q 的唯一输出 tuple 的概率 = `#(φ) / 2^{|X|+|Y|}`，于是求 rank ≥ 求 `#(φ)`。这条归约的思想来自 Grädel, Gurevich & Hirsch 的 query reliability（PODS 1998）。

注意这个模式在**确定数据库上是平凡的**——它只是"两端带概率、中间一张确定桥表"的一条三目连接；概率语义把一个廉价查询变成计数难题，全部来自"投影把不独立的组折叠"。

**（2）主定理 / Fundamental Theorem（会议版 Thm 5.2 / 期刊版 Thm 8）**

记号：`S⁺` 是 `Σp(q)` 下 S 的闭包；`Attr0(R) = Attr(R)⁺ − Head(q)⁺`，即"由 R 决定、但不被输出属性决定"的属性集。

> 假设 #P ≠ PTIME，对每个关系至多出现一次的合取查询 q，下列等价：
> 1. q **含有**某个unsafe 结构（下文 3 的形式化模式）⇒（期刊版方向：q **无**安全计划）
> 2. q 的数据复杂度是 **#P-complete**
> 3. Safe-Plan 算法**失败**
> 4. 存在关系序列 `R0, R1, …, Rk, R_{k+1}` 与属性 `A1, A2`，使得
>    (a) `R0, R_{k+1}` 是概率关系；
>    (b) `Attr0(R0) ∩ Attr0(R1) ∋ A1` 且 `A2 ∉ Attr0(R0)`；
>    (c) `Attr0(Rk) ∩ Attr0(R_{k+1}) ∋ A2` 且 `A1 ∉ Attr0(R_{k+1})`；
>    (d) 对 `1 ≤ i ≤ k−1`：`Attr0(Ri) ∩ Attr0(R_{i+1}) ⊆ Attr0(R0) ∩ Attr0(R_{k+1})`。

用人话复述：**当查询里存在一条"从某个概率关系出发、穿过一段确定/共享属性、到达另一个概率关系"的路径，而这条路径上的中间属性都不被输出头决定、也不在两端之间直接可见时，任何计划都必须做一次不安全投影，于是这个查询等价于 2-DNF 计数**。条件 (d) 是"路径最短/不回头"的技术保证（防止把已经决定的属性当成连接媒介，否则查询其实可分解）。

- 期刊版 Corollary 1 把 (3) 化简为三个关系的局部模式（**概率表–任意表–概率表** 加两个"互相看不见"的属性 A1、A2），并给出一个极漂亮的纯语法表述：当 `Σp` 为空（只有平凡依赖）时，q 是 #P-complete **当且仅当** 它含有形如

      q(...) :- R0(x, …), R1(x, y, …), R2(y, …)      且 x, y ∉ Head(q)

  的子模式；**找不到这个模式 ⇒ PTIME，且存在 safe plan**（即"多项式可求值 ⟺ 存在外延正确计划"，这是本文最重要的结构性结论）。
- 期刊版用四个例子（Example 7 的 q1…q4）逐一说明每个技术条件的必要性：
  - 把 head 扩到 `A,B,C,D`（不需要投影）⇒ 立刻 safe ⇒ 说明为什么用 `Attr0`（要减掉 `Head⁺`）而不是 `Attr`；
  - 加一张 `S(U,U1)` 且 U 是键 ⇒ `Attr0(L)=∅` ⇒ safe（说明 `Head⁺` 而非 `Head`）；
  - 链长可以任意（q3 有 4 张表 ⇒ 说明需要序列而非固定三元组）；
  - 有交叉共享属性时（q4）满足 (a)(b)(c) 却违反 (d)，实际存在 safe plan ⇒ 说明 (d) 不可省。

**（3）模型维度上的对照（读这篇论文必须记住的"哪一类查询在哪个模型下难"）**

| 场景 | 求值结论 |
|---|---|
| 概率模型：tuple-independent（会议版 extensional）；查询：self-join-free 合取 | **二分**：命中 3-relation 路径模式 ⇒ #P-complete；否则存在 safe plan ⇒ PTIME（会议版 Thm 5.2） |
| TI + **无需投影**（投影自由 / head = 全部属性） | 恒 PTIME：连接与选择恒安全，任何计划都 safe |
| TI + **单关系带键**（key 保持投影） | 恒 safe（`Rp.E → Attr(R)` ⇒ Eq. 1 平凡成立）；Barbara 模型的"只允许含键投影"正是这条的特例 |
| 前人的 extensional 系统（Cavallo–Pittarelli / Barbara / Dey–Sarkar / ProbView） | 各自的局部正确性条件；会议版明确指出它们**都无法处理任意合取查询**，本文给出的是覆盖这些条件上下界的那条线 |
| **带 self-join 的概率关系** | 本文**未给二分**。会议版 §7 说明：同一关系自连接会破坏"关系不重复出现"的前提，可能造成 #P-complete（引 Grädel 等）；但带不确定谓词的查询里"同表出现两次"会因为两处谓词不同而生成两份独立事件（`R1p, R2p`），实践中近似绕开；Safe-Plan 则按**合取查询的每个 block 分别**处理（会议版原文表述，期刊版未展开）。期刊版把"是否存在与 Thm 8 类似、允许 self-join 的二分"和"带 sum/count/avg 与 HAVING 的查询复杂度"列为 open problem |
| 加 `∪`、`−`、`π+min/max` | 会议版 Thm 7.1 / 期刊版 Thm 11：`∪e`、`−e` 在 `P Rels(q) ∩ P Rels(q') = ∅` 时恒安全；`π_{A*,agg}`（min/max）安全的条件与 `π_{A*}` 相同。**sum/count 不在此列**（聚合值可能不在输入域中，需要枚举指数多 world），论文改为只报期望值；充分性有余、必要性不足；带这些算子的二分被明确留作 open |

### 3.6 "查询加权计数"到底是什么

论文没用一个单独的"weighted counting"章节名，但其内核就是它：

- 一个输出 tuple 的 rank = 它的 **lineage/事件表达式** `e(t)` 的概率；`e(t)` 是原子事件的单调/含否定布尔式；`Pr(e)` = 对所有原子事件赋值上的**加权和**（各原子事件权重 `p` 与 `1−p`），即带权模型计数（weighted model counting / 可靠性多项式求值）。
- Valiant：`#SAT` 是 #P-complete；Provan & Ball：即便限制到二部单调 2-DNF（无否定、每个子句跨部合取）仍然 #P-complete —— 论文的 hardness 归约直接用它。
- 于是"求 safe plan" = "把 lineage 公式改写成**可读一次（read-once）形状**"：safe plan 对应的正是事件表达式能表示为只含独立子式的与或树（这是论文没有明说、但后续把该工作推到"read-once function / 广义 read-once branching program"和"概率推理与知识编译复杂度对照"的直接接口，见 §④）。**这条读法是本笔记的解读，不是原文用语（原文用 FD 判定，未使用 read-once 术语）。**

### 3.7 没有 safe plan 时怎么办：两个可落地的退路

**（a）Least-unsafe plan（会议版 §6.1 / 期刊版 §7.1）** —— 定量化"错多少"：

- 对投影 `π^{A1..Ak}_e`，令 `B* = {A1..Ak, Rp.E} ∩ Attr(Rp)`，`C* = Head(q) ∩ Attr(Rp)`；`R_fpanout` = 固定 `B*` 时 `C*` 的期望不同值个数（可用 RDBMS 统计信息估计）。
- **degree of unsafety** := `max_{Rp ∈ PRELS(Q)} (R_fpanout − 1)`，safe 投影为 0。
- 把 Safe-Plan 的"必须按 separation 切"放松为"允许在非 head 属性上连接后再投影掉"，代价按 degree of unsafety 给边打标，**取最小割**（Stoer–Wagner 或最大流）⇒ 多项式时间内挑出"最不错误"的计划。
- 脚注里的严谨细节值得保留：估计器必须保证 `R_fpanout = 0` **仅在** FD 真成立时出现，否则优化器会偏向"期望安全"而非"真安全"的计划。

**（b）Monte-Carlo（会议版 §6.2 / 期刊版 §7.2）** —— 无偏近似：

1. 取 q 的 body `q'`：`Head(q') = Attr(q') = Attr(q)`，并额外返回所有事件属性 `E*`。此时**没有投影**，每行事件都是原子事件的合取。
2. 在 Dp 上按普通方式求值 `q'`（不算概率），按 `Head(q)` 分组；一组的 n 个 tuple 给出 DNF 式 `∨_{i=1..n} C_i`（每个 `C_i` 是合取），它就是该输出 tuple 的事件。
3. 求该 DNF 的概率。一般仍是 #P-complete（Valiant），但可用 **Karp–Luby（1983）对 DNF 采样的近似算法**：跑 `N ≈ 4nε⁻² ln(1/δ)`（会议版排版给出 `N ∝ 4n ln(2/δ)/ε²` 的形式）次，即可使误差 > ε 的概率 < δ，时间随 n 线性。
4. 论文补了一句工程判断：N 很小时可直接用精确算法，且这个选择**逐输出 tuple 独立**决定。

这两条退路的组合（快但可能偏的 least-unsafe、慢但可控误差的 MC）后来成了不确定数据系统处理 hard 查询的标准配方。

### 3.8 相关性的表达：repeated events 与 3NF 规范化（期刊版 §8.1）

模型允许"多个 tuple 共享一个事件"，靠的是函数依赖：`Casts.actorname → Casts.E` 表示"同一个演员的所有 tuple 要么一起在、要么一起不在"。这不改变结果的正确性但**显著改变语义**：独立事件下某演员出现 100 次会让其 rank 趋近 1，共享事件则不随重复次数增长。

论文给的处理程序（对算法是纯前置处理，不新增机制）：

1. **虚 schema 规范化**：对事件不唯一的 `T^p`，拆成确定表 `T1(…, EID)` + 概率表 `T2^p(EID)`；不真的搬数据，只是"视图"。
2. 查询里的 `T^p` 换成 `T1 ⋈_{EID} T2^p`。
3. 在新 schema 上跑 Safe-Plan。
4. 把 `T1`、`T2^p` 的解释代回计划（这些代回用的投影是**普通投影**，不做概率计算）。

示例：`S^p(C,D)` 上每个 D 值共享事件（`S.E → S.C`）⇒ 拆 `S1(C,D,EID)` 与 `S2^p(EID)`，`RP(A,B)` 不变，得 `π_x(RP ⋈ π_{B=EID}… )` 型安全计划。同时论文指出：如果直接在 `Product.category → Product.E` 下建事件，`category` 的投影会变不安全，正确做法是把 category 规范到单独的表里承载事件——**概率 schema 需要额外的范式直觉**，这是很实用的洞见。

**关键自陈（诚实边界）**：这套机制只覆盖"通过 FD 共享事件"这种**局部**相关性，任意 tuple 间依赖的高效表达被明确说"超出本文范围"。这也解释了为什么 BID（block-independent-disjoint，块内互斥、块间独立）这类模型在本文中只是"可用 FD 描述的一个特例"，而没有独立成章——见 §3.9。

### 3.9 关于"TI 与 complete 模型"的术语核对（重要）

任务书要求精读"tuple-independent (TI) 与 complete 概率模型"。按我读到的两版正文核对结果如下，必须如实标注：

- **"tuple-independent"**：**期刊版**明确使用该词（§3："If a probabilistic relation has a distinct atomic event for each tuple, we call it a tuple-independent probabilistic relation"）；**会议版用的是 extensional**（"extensional probabilistic relation"，脚注注明"等价于每个 tuple 一个独立原子事件"）。所以 TI = 本文的 extensional，是同义替换，不是另一个模型。
- **"complete 概率模型"**：我在**两版全文中都未检索到**作为模型名出现的 "complete model"。文中 "complete" 只出现在两类语境：#P-complete；以及"算法/变换规则是 complete（完备）的"（Proposition 4.9、Thm 6、Thm 10）。与"complete"最接近的两处实质内容是：
  1. **期刊版 Thm 1 的"表示能力完备性"**：任意可能世界分布可被某个概率数据库表示——这是"complete(ly expressive)"，说的是表示力，不是某个 tuple 级模型假设。
  2. **通过 FD 引入的互斥/共享事件（§3.8）**：它把 TI 推广到块结构（BID 一族：块内事件互斥、块间独立；块内概率和 = 1 的情形在文献里常被称为"complete BID"）。**"complete 模型"这一命名属于后续文献**（Dalvi & Suciu 的复杂度论文与概率数据库综述对 TI / BID / complete 等的整理），**在本文里没有对应章节，无法核实其在本论文中的定理表述**。
- 因此本笔记的写法是：**复杂度二分（§3.5）在本文里只对 extensional/TI 模型成立**；把它当成"对所有模型都成立"是误读。self-join-free 合取查询在 **BID 上的二分**是由后续工作给出（期刊版本文明确把带 self-join 的二分列为 open，见 §3.5 表末行）。若需引用"BID 上 self-join-free 合取查询 P/#P-hard 二分"，应引 Dalvi & Suciu 的后续论文，不要引本文。

### 3.10 系统形态与实验

论文的实现姿态很"数据库人"：**不改内核，做中间件**。把带近似谓词的 SQL 改写成"外延 SQL"，调用 T-SQL 函数算 3-gram 距离，交给 **Microsoft SQL Server** 执行，同时返回 tuple 与概率；用 Stanford movie 库做定性示例（"Kevin/1995/Copolla/Rain Man" 的排名结果，Top-5 从 0.110 递减到 0.059），用 **TPC-H 0.1GB** 做定量：把 10 条查询的所有 WHERE 常量拼错/改模糊（`part.container = 'PROMO PLATED GREEN'` → `'GREEN PLATE'`），精确执行时全部返回空集，以此构造"必须模糊匹配"的场景。

实验回答四个问题（对应会议版 §9 的 1/2/3/4 小标题）：

1. **Safe-Plan 多久失败一次？** 10 条里 8 条有 safe plan，2 条没有。
2. **safe plan 有多快？** 三条柱：safe plan、加上"每级丢弃概率为 0 的 tuple"的优化、不含不确定谓词计算时间的裸查询。结论：**时间主要花在算相似谓词上**，若谓词进内核收益巨大；对 Q3 概率计算几乎不额外花时间。
3. **朴素外延计划错多少？** 在 safe 查询上比较 naive plan 与 safe plan 的误差（Figure 7，部分查询平均误差高达百分之一百量级），说明"随便选个计划"不可接受。
4. **对无 safe plan 的查询，least-unsafe 比 naive 好多少？** 只有两个数据点不够，于是**手工造第三条查询 QQ**（lineitem 同时与 orders、suppliers 连接，fanout 更大），差别更明显（期刊版 Figure 15）。这个"数据点不够就造一条"的做法是论文自陈的实验局限。
