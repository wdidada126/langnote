在使用 `cmake --build .` 命令构建项目之后，通常会有一个安装步骤来将构建的可执行文件、库和其他资源安装到系统的适当位置。安装步骤的具体方式取决于项目的配置和您的系统环境。

一般来说，大多数 CMake 项目会在其根目录下提供一个 `install` 目标，您可以使用 `cmake --build . --target install` 命令来执行安装。这个命令会告诉 CMake 使用之前生成的构建系统来执行 `install` 目标，从而完成安装过程。

例如，如果您的项目使用 Unix Makefiles 生成器（这是默认情况），那么安装命令可能是这样的：


```bash
cmake --build . --target install
```
如果您的项目使用其他生成器，例如 NMake 或 MSVC，您可能需要相应地调整命令。

请注意，安装步骤可能需要管理员权限，因此您可能需要在命令前加上 `sudo`（在 Unix-like 系统上）或以管理员身份运行命令提示符（在 Windows 上）。

此外，一些项目可能还有其他的安装选项或步骤，例如设置环境变量、创建符号链接等。因此，最好查阅项目的文档或安装说明，以了解适用于您的项目的具体安装步骤。

类似GitHub Actions的服务有很多，它们都提供了持续集成和持续部署（CI/CD）的功能。以下是一些类似的服务：

Travis CI：Travis CI 是一种流行的持续集成服务，它与 GitHub 紧密集成，可以自动构建和测试代码。
CircleCI：CircleCI 是另一个流行的 CI/CD 工具，它提供了与 GitHub 的集成，以及强大的配置和扩展选项。
Jenkins：Jenkins 是一个开源的 CI/CD 服务器，它可以与多种版本控制系统（包括 Git）和构建工具集成，提供了高度的可配置性和扩展性。
GitLab CI/CD：GitLab 不仅是一个 Git 仓库托管服务，还提供了 CI/CD 功能。GitLab CI/CD 与 GitLab 的其他功能（如代码审查、问题跟踪等）紧密集成，使得整个开发流程更加顺畅。
Azure DevOps：Azure DevOps 是微软提供的一套完整的开发工具集，其中包括了 CI/CD 功能。Azure DevOps 可以与 GitHub 集成，也可以与 Azure 的其他服务（如云资源、数据库等）集成。
AWS CodePipeline：AWS CodePipeline 是亚马逊云服务（AWS）提供的一个 CI/CD 服务，它可以与 AWS 的其他服务（如 CodeCommit、CodeBuild、CodeDeploy 等）无缝集成。
以上这些服务都有各自的优点和适用场景，你可以根据项目的具体需求和团队的偏好来选择合适的服务。
