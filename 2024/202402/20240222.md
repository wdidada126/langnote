## 一、版本严格对应表（核心）

### MySQL 5.7 系列
- 5.7.x（所有） → 必须用 Boost 1.59.0
  - 高一点（1.60+）CMake 直接报错或 GIS 功能异常

### MySQL 8.0 系列（最常用）
- 8.0.11 ~ 8.0.18 → Boost 1.69.0
- 8.0.19 ~ 8.0.25 → Boost 1.70.0
- 8.0.26 ~ 8.0.33 → Boost 1.74.0
- 8.0.34 ~ 8.0.41 → Boost 1.77.0
- 8.0.42 ~ 8.0.43 → Boost 1.79.0

### MySQL 8.4 LTS（新长期支持）
- 8.4.0 ~ 8.4.2 → Boost 1.82.0

### MySQL 9.0+（创新版）
- 9.0.0 ~ 9.1.0 → Boost 1.84.0 / 1.85.0

> 官方原话：MySQL 编译只认一个硬编码的 Boost 版本，错版会直接报错或 GIS 结果错误。

## 二、为什么必须严格对应？
- MySQL 的 GIS 空间索引/函数深度依赖 Boost.Geometry，源码是按特定 Boost 版本开发、测试、对齐的。
- 不同 Boost 版本的：
  - 头文件接口
  - 模板实现
  - 命名空间
  - 常量定义
  都可能变，错版=编译失败/运行崩溃/空间查询结果错误。

## 三、编译时怎么指定（CMake）
```bash
# 示例：编译 MySQL 8.0.23（要求 Boost 1.70.0）
cmake .. -DWITH_BOOST=/path/to/boost_1_70_0
```
- 必须是解压后的源码根目录（不是系统安装目录）
- 目录名必须是 `boost_1_xx_x` 格式（CMake 正则校验）
