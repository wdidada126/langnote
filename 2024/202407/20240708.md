在Java中，函数调用时对于基本类型和对象类型的处理是不同的。

- 基本类型：对于基本数据类型（如 `int`, `char`, `boolean` 等），Java使用的是按值传递。这意味着在调用函数时，会将基本类型参数的值复制一份传递给函数，函数内部对该参数的修改不会影响到实际参数的值。
- 对象类型：对于对象类型（如数组、用户自定义对象等），Java使用的是引用传递，但本质上还是传值。在调用函数时，对象的引用（内存地址）被复制并传递给函数，因此函数内部对对象内容的修改会影响到原对象，但对引用本身的修改（如赋值为null或指向新对象）不会影响到实际参数。

举个例子：

假设我们有一个 `Swap` 函数，用于交换两个整数的值：

```java
public static void swap(int a, int b) {
    int temp = a;
    a = b;
    b = temp;
}
```

如果我们这样调用它：

```java
int x = 5;
int y = 10;
swap(x, y);
```

`x` 和 `y` 的值并不会交换，因为 `swap` 函数接收的是 `x` 和 `y` 的副本，而不是它们的实际引用。

现在考虑对象类型的例子：

```java
public static void modifyObject(List<Integer> list) {
    list.add(4);
}
```

调用该函数：

```java
List<Integer> myList = new ArrayList<>();
myList.add(1);
myList.add(2);
myList.add(3);
modifyObject(myList);
```

在这种情况下，`myList` 会被修改，因为在函数内部我们是在操作 `myList` 的引用所指向的对象，所以添加元素的操作影响了原列表。

总的来说，理解Java中的参数传递机制对于编写和调试Java程序至关重要，尤其是在涉及到状态改变和对象操作时。


看完就会用的C++17特性总结
作者：taoklin，腾讯WXG后台开发

extern "C"的主要作用是实现C++代码对C语言代码的调用，保证编译与链接的正确性。在C++编程中，extern "C"有着特别的意义和用途，它主要用于处理C++与C语言间的交互以及编译兼容问题。由于C++支持函数重载、类、模板等特性，其背后的名称修饰（name mangling）机制会将函数参数类型等信息编码到生成的目标文件中。而C语言并不支持这些特性，其目标文件中的函数名仅包含函数名本身，不包含参数类型信息。

从技术层面来看，extern "C"可以确保在C++代码中调用C语言编写的函数或使用变量时，编译器不会应用C++的名称修饰规则，而是按照C语言的方式处理。这样一来，人们就可以在C++项目中无缝地引入和使用C语言编写的库或代码模块。例如，当一个项目需要使用某个用C语言开发且未提供C++接口的第三方库时，通过extern "C"声明，人们可以直接在C++代码中引用这些库的头文件并调用其功能。

从实际应用场景来看，extern "C"同样在多人协作开发中发挥着重要作用。在这种开发模式下，不同团队成员可能更擅长或被要求使用不同的编程语言。例如，一些成员使用C++开发新功能，而其他成员负责维护旧的C语言代码库。通过extern "C"，C++代码可以方便地调用C语言模块，反之亦然，从而实现代码的有效整合和复用。

综上所述，extern "C"是连接C与C++代码的重要桥梁，不仅解决了编译和链接层面的兼容性问题，还为多语言混合编程提供了便利。在实际项目中合理使用extern "C"，能够有效提升代码的复用性和可维护性，同时保障不同语言之间的无缝交互。
