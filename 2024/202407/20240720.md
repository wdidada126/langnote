五种拷贝控制操作：拷贝构造函数、拷贝赋值运算符、移动构造函数、移动赋值运算符、析构函数。举例说明
在C++中，拷贝控制操作是管理对象复制和移动以及资源释放的重要机制。这包括拷贝构造函数、拷贝赋值运算符、移动构造函数、移动赋值运算符和析构函数。下面，我将通过例子来说明这五种操作：
1. 拷贝构造函数（Copy Constructor）
拷贝构造函数是一个特殊的构造函数，它用于创建一个新对象，作为另一个同类型对象的副本。

```cpp
#include <iostream>  
using namespace std;  
  
class String {  
public:  
    char* data;  
    size_t len;  
  
    // 构造函数  
    String(const char* str = "") {  
        len = strlen(str);  
        data = new char[len + 1];  
        strcpy(data, str);  
    }  
  
    // 拷贝构造函数  
    String(const String& other) {  
        len = other.len;  
        data = new char[len + 1];  
        strcpy(data, other.data);  
    }  
  
    // 析构函数  
    ~String() {  
        delete[] data;  
    }  
  
    // 省略其他成员函数...  
};  
  
int main() {  
    String s1("Hello");  
    String s2 = s1; // 调用拷贝构造函数  
    return 0;  
}
```
2. 拷贝赋值运算符（Copy Assignment Operator）
拷贝赋值运算符用于将一个对象的值赋给另一个同类型的对象。

```cpp
// 接着上面的String类  
  
// 拷贝赋值运算符  
String& operator=(const String& other) {  
    if (this != &other) { // 防止自赋值  
        delete[] data; // 释放旧资源  
        len = other.len;  
        data = new char[len + 1];  
        strcpy(data, other.data);  
    }  
    return *this;  
}  
  
// 使用  
String s1("World");  
String s3;  
s3 = s1; // 调用拷贝赋值运算符
```

3. 移动构造函数（Move Constructor）
移动构造函数用于从一个即将被销毁的对象（临时对象或右值）中“窃取”资源，而不是复制它们。

```cpp
// 接着上面的String类  
  
// 移动构造函数  
String(String&& other) noexcept : len(other.len), data(other.data) {  
    other.data = nullptr; // 避免析构时释放已转移的资源  
    other.len = 0;  
}  
  
// 使用  
String s4 = String("Hello, World!"); // 这里可能会调用移动构造函数，取决于编译器优化
```
4. 移动赋值运算符（Move Assignment Operator）
移动赋值运算符用于将一个对象的资源“窃取”到另一个对象中，然后使原对象处于有效但未定义的状态。

```cpp
// 接着上面的String类  
  
// 移动赋值运算符  
String& operator=(String&& other) noexcept {  
    if (this != &other) {  
        delete[] data;  
        data = other.data;  
        len = other.len;  
        other.data = nullptr;  
        other.len = 0;  
    }  
    return *this;  
}  
  
// 使用  
String s5 = String("C++");  
String s6;  
s6 = std::move(s5); // 调用移动赋值运算符
```

5. 析构函数（Destructor）
析构函数是特殊的成员函数，它在对象生命周期结束时自动调用，用于释放对象持有的资源。

```cpp
// 在String类中已定义  
~String() {  
    delete[] data;  
}
```
这些操作共同协作，确保对象在复制、赋值、移动和销毁时能够正确地管理资源，避免内存泄漏和其他资源管理问题。
在 CMake 中，include_directories() 命令用于指定编译器在搜索头文件（.h, .hpp 等）时应该包含的目录列表。这对于确保你的项目能够找到它所依赖的库的头文件非常重要。然而，需要注意的是，include_directories() 并不是用来包含 CMake 脚本或模块的，它专门用于处理 C/C++ 源代码编译时的头文件包含路径。
这里有一个 include_directories() 的基本用法示例：
cmake
# 假设你的项目依赖一个位于 /usr/local/include/mylib 的库  
include_directories(/usr/local/include/mylib)  
  
# 或者，如果你使用的是相对路径（相对于当前 CMakeLists.txt 的位置）  
# 假设 mylib 的头文件位于你的项目的一个子目录中  
include_directories(path/to/mylib)  
  
# 现在，在你的源代码中，你可以直接使用 #include <mylib/header.h>  
# 而不需要指定完整的路径
然而，随着 CMake 的发展，推荐使用 target_include_directories() 命令来代替 include_directories()，特别是在处理更复杂的项目时。target_include_directories() 允许你为特定的目标（如可执行文件或库）指定头文件搜索路径，这样可以更精细地控制哪些目标包含哪些头文件目录。

以下是 target_include_directories() 的一个示例用法：
cmake
# 创建一个可执行文件目标  
add_executable(my_app main.cpp)  
# 为 my_app 目标指定头文件搜索路径  
target_include_directories(my_app PRIVATE /usr/local/include/mylib)  
# 或者，如果你使用的是相对路径  
target_include_directories(my_app PRIVATE path/to/mylib)  
# 现在，只有在编译 my_app 时，CMake 才会将这些目录添加到头文件搜索路径中
在这个例子中，PRIVATE 关键字指定了这些包含目录仅对 my_app 目标可见，这有助于减少不同目标之间的依赖和潜在的编译问题。CMake 还支持 PUBLIC 和 INTERFACE 关键字，它们提供了更细粒度的控制，允许你指定哪些目录应该被链接到该目标的库所共享，或者仅作为接口传递给使用该目标的其他目标。

在你的代码中,应该先包含 `<stdio.h>` 头文件,然后再包含 `<jpeglib.h>` 头文件。这样可以确保 `FILE` 类型在使用 `jpeglib.h` 中的函数时已经被正确定义。
所以你的代码应该修改为:

```cpp
#include <stdio.h>
#include <jpeglib.h>
```
