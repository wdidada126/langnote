这个问题是由于CMake版本的兼容性问题导致的。

针对这个问题,您可以尝试以下几种解决方法:
1.升级CMake版本
   确保您使用的CMake版本是最新的,或者至少是3.20及以上版本。较新版本的CMake通常会更好地支持新的CMake策略。
2. 在CMakeLists.txt文件中手动设置CMP0091策略
   在您的CMakeLists.txt文件的开头添加以下代码:
   ```cmake
   cmake_minimum_required(VERSION 3.20)
   cmake_policy(SET CMP0091 NEW)
   ```
   这会将 CMP0091 策略设置为 NEW,从而解决该问题。
3. 使用 set_property(GLOBAL) 命令设置策略
   您也可以使用以下代码来设置 CMP0091 策略:
   ```cmake
   set_property(GLOBAL PROPERTY CMP0091 NEW)
   ```
   将这行代码添加到您的CMakeLists.txt文件中,同样可以解决该问题。
4. 在CLion中设置CMake版本
   在 CLion 中,您可以进入 "File" > "Settings" > "Build, Execution, Deployment" > "CMake" 菜单,并选择一个较新版本的 CMake。这可能会解决您在 CLion 中遇到的问题。

根据 CMP0091 的 CMake 文档,该策略在 CMake 3.15 及更高版本中引入,主要目的是:
对于使用 MSVC 编译器的项目,CMake 不再将 MSVC 运行时库选择的编译器标志自动添加到 CMAKE_<LANG>_FLAGS_<CONFIG> 缓存变量中。
取而代之的是,提供了 CMAKE_MSVC_RUNTIME_LIBRARY 变量和 MSVC_RUNTIME_LIBRARY 目标属性,用于程序化地选择 MSVC 运行时库。
如果这两个新的抽象变量/属性未设置,CMake 会使用默认值 MultiThreaded$<$<CONFIG:Debug>:Debug>DLL。这与之前的行为是等价的。
该策略的目的是为了简化 MSVC 运行时库的选择,并为项目提供更好的抽象和可编程性。
如果项目未更新到使用新的抽象,可以将 CMP0091 策略设置为 OLD 行为,以保持向后兼容性。
一旦 CMP0091 策略生效,整个项目树中都必须使用同样的行为。
因此,你之前提到的情况可能是由于项目尚未更新到使用新的抽象,而导致 CMake 仍然使用 OLD 行为。设置 CMP0091 策略为 NEW 可能会解决这个问题。
