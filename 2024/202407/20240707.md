poll
    基于结构体存储fd
    struct pollfd{
        int fd;
        short events;
        short revents; //可重用
    }
    解决了select的1,2两点缺点

epoll
    解决select的1，2，3，4
    不需要轮询，时间复杂度为O(1)
    epoll_create  创建一个白板 存放fd_events
    epoll_ctl 用于向内核注册新的描述符或者是改变某个文件描述符的状态。已注册的描述符在内核中会被维护在一棵红黑树上
    epoll_wait 通过回调函数内核会将 I/O 准备好的描述符加入到一个链表中管理，进程调用 epoll_wait() 便可以得到事件完成的描述符

    两种触发模式：
        LT:水平触发
            当 epoll_wait() 检测到描述符事件到达时，将此事件通知进程，进程可以不立即处理该事件，下次调用 epoll_wait() 会再次通知进程。是默认的一种模式，并且同时支持 Blocking 和 No-Blocking。
        ET:边缘触发
            和 LT 模式不同的是，通知之后进程必须立即处理事件。
            下次再调用 epoll_wait() 时不会再得到事件到达的通知。很大程度上减少了 epoll 事件被重复触发的次数，
            因此效率要比 LT 模式高。只支持 No-Blocking，以避免由于一个文件句柄的阻塞读/阻塞写操作把处理多个文件描述符的任务饿死。

1、SSD与传统磁盘相比，第一是没有机械装置，第二是由磁介质改为了电介质。SSD没有传统磁盘的寻道时间和延迟时间。
2、基于SSD的优化就是解决erase-before-write产生的写入放大的问题。
3、优化原理：
    a、将sequential logging修改为In-page logging，避免对相同位置的反复擦写。
    b.通过缓存写入的方式将大量的in-place update随机写入合并为少量顺序写入。
    c.利用SSD随机读写能力高的特点，减少写增加读，从而达到整体性能的提升。

POSIX标准确实有多个版本，并且随着技术的发展和需求的变化，它也在持续更新和演进。以下是一些关于POSIX标准版本和更新的信息：
1. POSIX标准最初源于1985年左右启动的一个项目，旨在确保UNIX操作系统间的互通性。
2. POSIX标准包括多个部分，例如基本功能定义、系统接口、Shell和相关工具以及基本原理。
3. 在1997年之前，POSIX包括了多个标准，如POSIX.1（核心服务）、POSIX.1b（实时扩展）、POSIX.1c（线程扩展）和POSIX.2（Shell和实用程序）。
4. 1997年之后，奥斯汀工作组开发了POSIX的修订版，被称为单一UNIX规范。例如，POSIX.1-2001是等同于单一UNIX规范第3版的一个标准。
5. 后续的更新包括了POSIX.1-2004和POSIX.1-2008，它们都是对POSIX.1-2001的更新和技术勘误表。
6. 目前最新的标准是POSIX.1-2017，它是IEEE标准1003.1-2017，也被称为IEEE信息技术标准-便携式操作系统接口(POSIX)基本规范的第7版。
7. POSIX标准是一个“活的”标准，会不断被行业专业人士更新和评审，以适应新的技术发展和应用需求。

综上所述，POSIX标准不仅具有多个版本，而且它是一个不断发展和更新的标准，以适应不断变化的技术和市场需求。

在提供的头文件中，<string.h>、<stdlib.h>、<stdio.h> 和 <stdarg.h> 属于标准库（C Standard Library），而其余的头文件属于 Linux（POSIX 标准或者特定的 Linux API）。
这些头文件的分类可以通过它们所属的领域和作用来理解。标准库头文件定义了 C 语言的核心功能，适用于所有的 C 语言开发环境。而 Linux 头文件则提供了操作系统级别的 API 访问，如网络通信、系统调用等，这些是特定于 Linux 或 Unix-like 系统的功能。
1. 标准库头文件:
   - `<string.h>`: 提供字符串处理函数，如 strcpy(), strcat(), strstr() 等。
   - `<stdlib.h>`: 包含通用函数，如内存分配 (malloc(), free()), 随机数生成， 以及其他杂项函数。
   - `<stdio.h>`: 提供输入输出功能，如 printf(), scanf() 等。
   - `<stdarg.h>`: 用于处理可变参数列表的宏。
2. Linux 或 POSIX 头文件:
   - `<unistd.h>`: 提供对 POSIX 操作系统 API 的访问，如系统调用和基本服务。
   - `<fcntl.h>`: 包含文件控制相关的宏和其他函数，用于管理文件描述符。
   - `<errno.h>`: 定义错误码和处理错误的函数。
   - `<netdb.h>`: 提供对数据库网络访问的API，如网络地址和域名解析。
   - `<sys/socket.h>`: 包含用于套接字编程的函数和数据结构。
   - `<netinet/in.h>`: 提供对网际网协议族的支持。
   - `<arpa/inet.h>`: 包括对 IP 地址操作的函数。
   - `<sys/types.h>`: 定义了基本的系统数据类型。
   - `<sys/socket.h>`: 与 `<sys/socket.h>` 相同，包含用于套接字编程的函数和数据结构。
总的来说，了解哪些头文件属于标准库，哪些属于 Linux 特有的库，对于编写可移植性强且高效的 C/C++ 程序至关重要。在编写跨平台应用程序时，应尽可能使用标准库，并在必要时通过条件编译来处理特定平台的代码，这样可以确保程序在不同环境下都能正常工作。
