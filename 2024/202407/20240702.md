std::move 是 C++11 版本中引入的一个重要新特性，它属于 C++11 引入的移动语义（Move Semantics）的一部分。移动语义旨在提高大型对象（特别是那些涉及资源管理的对象）的复制效率，通过允许资源从一个对象“移动”到另一个对象，而不是进行昂贵的复制操作来实现。这一机制主要通过右值引用（right-value reference）和移动构造函数（move constructor）以及移动赋值操作符（move assignment operator）来实现。
以下是关于 std::move 和 C++11 版本的详细归纳：
版本归属：
std::move 是 C++11 标准库中的一个函数模板，用于将左值引用转换为右值引用，从而允许对象通过移动语义进行资源转移。
主要作用：
std::move 本身并不移动任何数据，它只是将其参数转换为右值引用，使得对象可以被移动而非复制。这通常用于优化资源密集型对象的传递和赋值操作。
实现机制：
从实现上讲，std::move 基本等同于一个类型转换：static_cast<T&&>(lvalue);，其中 T 是左值的类型，lvalue 是需要被移动的左值。
使用场景：
当需要将一个对象的资源转移到另一个对象时，可以使用 std::move 来避免不必要的复制操作。这特别适用于那些管理动态内存、文件句柄、网络连接等资源的类。
与移动构造函数和移动赋值操作符的关系：
std::move 通常与移动构造函数和移动赋值操作符一起使用，以实现资源的有效转移。移动构造函数和移动赋值操作符允许对象通过接收另一个对象的资源来初始化或赋值，而不是创建新的资源副本。
性能优化：
在处理大型对象或资源密集型对象时，使用 std::move 可以显著减少内存使用和提高程序执行速度。这是因为移动操作通常只涉及资源的所有权变更，而不是实际的数据复制。
综上所述，std::move 是 C++11 版本中引入的一个关键特性，它对于提高程序的性能和效率具有重要意义。通过允许对象通过移动语义进行资源转移，std::move 使得 C++ 程序员能够编写出更高效、更节省资源的代码。

这篇文章主要介绍一种静态多态编程技术Curiously Recurring Template Pattern（CRTP），它通过在派生类中使用基类的模板参数来实现静态多态。CRTP使用一个模板类作为基类，派生类中，使用基类的模板参数作为派生类的类型参数，从而实现了静态多态。

在CRTP中，通过将派生类作为模板参数传递给基类，实现了基类对派生类的访问。由于CRTP使用的是静态多态，因此在编译时就能够确定函数调用的具体实现，从而避免了动态多态带来的运行时开销。

Linux .a .so
Win .lib .dll

macOS 除了支持 .dylib（动态库），也完全支持 .a（静态库）。
绝大多数时候，当你使用第三方提供的动态库时，对方会同时给你两个文件：一个大的 .dll（真正的实现代码）和一个小的 .lib（导入库）。你在开发时需要在项目中链接这个 .lib，发布程序时则需要和 .dll一起分发。
这是一个非常经典且重要的问题，答案也有一点绕。
简单直接的回答是：.lib 文件在 Windows 上既可以是静态库，也可以是动态库的“导入库”。具体是哪种，需要根据上下文判断。
下面我们来详细解释这两种情况。
情况一：.lib 作为静态库
这是最符合直觉的理解方式，与 Linux/macOS 上的 .a 文件类似。
•   是什么：静态库是一个或多个 .obj（对象文件）的集合。在编译（链接）时，链接器会将你的程序中实际用到的那部分代码从静态库中提取出来，并直接复制到最终生成的可执行文件（.exe 或 .dll）中。
•   特点：
    ◦   自包含：发布可执行文件时，你不需要再附带这个 .lib 文件。因为所有需要的代码都已经“静态”地包含在 EXE 里了。
    ◦   文件较大：如果多个程序都使用了同一个静态库，那么每个程序的体积都会变大，并且在内存中也会有多个该库代码的副本。
    ◦   无依赖：运行时不需要原 .lib 文件。
使用场景：当你希望程序部署简单，不希望有额外的依赖文件时。
情况二：.lib 作为动态库的导入库
这是 Windows 平台一个独特且关键的概念。这种情况下，.lib 文件本身不包含实际的函数代码。
•   是什么：它是一个小巧的“桥梁文件”或“导航文件”，专门用于链接阶段。它包含了动态库（.dll）中导出函数的名称和序号等信息，告诉链接器：“这些函数存在于某个 DLL 中，请在运行时去那里找”。
•   工作流程：
    1.  编译链接时：你的程序链接这个导入库（.lib）。链接器认为函数存在，顺利通过链接。
    2.  运行时：当你的程序启动时，Windows 的加载器会根据导入库中的信息，找到并加载对应的 .dll 文件，并将函数调用与 DLL 中的实际代码连接起来。
•   特点：
    ◦   文件很小：因为它只包含函数索引信息，没有实际的代码。
    ◦   必需依赖：你的程序运行时，必须在系统可以找到的路径下存在对应的 .dll 文件，否则程序会启动失败，提示“找不到 .dll”。
使用场景：绝大多数时候，当你使用第三方提供的动态库时，对方会同时给你两个文件：一个大的 .dll（真正的实现代码）和一个小的 .lib（导入库）。你在开发时需要在项目中链接这个 .lib，发布程序时则需要和 .dll 一起分发。

总结与对比
为了更清晰地理解，可以参考下表：
特性 静态库（.lib） 动态库的导入库（.lib）
本质 是代码的集合 是指向DLL的“地址簿”
文件大小 较大（因为包含实际代码） 非常小（只包含函数名、序号等索引信息）
链接阶段 代码被复制到最终的可执行文件中 仅记录依赖关系，指引链接器通过检查
运行时 不需要原.lib文件 必须有对应的.dll文件存在于系统路径
类比 像一本书，你把需要的几页复印到了你的报告里。 像一本书的目录，你报告里只写了“详见XX书第X页”，运行时需要把那本书放在旁边。
如何区分你手上的 .lib 文件是哪种？
1.  看文件大小：静态库通常比较大（几百KB到几MB甚至更大），而导入库通常很小（几十KB）。
2.  看开发环境：
    ◦   如果你在 Visual Studio 的项目属性中，将配置类型设置为静态库（.lib），然后编译，生成的 .lib 就是静态库。
    ◦   如果你将配置类型设置为动态库（.dll），编译后除了生成 .dll 文件，还会同时生成一个同名的 .lib 文件，这个 .lib 就是导入库。
3.  看配套文件：如果对方在提供 .lib 文件的同时，还提供了一个同名的、大得多的 .dll 文件，那么这个 .lib 几乎可以肯定是导入库。如果只有一个孤零零的 .lib 文件，那它很可能是静态库。
结论：
下次在 Windows 上遇到 .lib 文件，不要直接认为它是“静态库”。首先要问：“它是一个包含代码的静态库，还是一个用于链接 DLL 的导入库？” 这个区分是理解 Windows 程序链接和部署的关键。
