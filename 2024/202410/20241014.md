在Oracle数据库中，`ROWNUM` 是一个特殊的伪列，它返回结果集中的行号。`ROWNUM` 可以在子查询（子SQL）中使用，也可以在主查询中使用，但它的行为会有所不同。
1. 在子查询中使用 `ROWNUM`：
   当你在子查询中使用 `ROWNUM` 时，它会在子查询的结果生成之后才被应用。这意味着 `ROWNUM` 会为子查询返回的每一行分配一个唯一的行号。例如：

   ```sql
   SELECT * FROM (
     SELECT ROWNUM, column1, column2 FROM some_table
   ) WHERE ROWNUM <= 10;
   ```

   在这个例子中，`ROWNUM` 会为 `some_table` 中的每一行分配一个行号，然后外层查询会根据这个行号来过滤行。
2. 在主查询中使用 `ROWNUM`：
   如果你在主查询中使用 `ROWNUM`，它会在子查询的结果生成之前就被应用。这意味着 `ROWNUM` 会为整个主查询的结果集分配行号，而不是为子查询的每一行分配行号。例如：

   ```sql
   SELECT * FROM (
     SELECT column1, column2 FROM some_table
   ) WHERE ROWNUM <= 10;
   ```

在这个例子中，`ROWNUM` 会为整个查询结果集（即 `some_table` 的所有行）分配行号，然后过滤出前10行。

因此，`ROWNUM` 不是必须在子SQL中获取，但它的使用方式会影响结果集的处理方式。在实际使用中，你可以根据需要选择在子查询还是主查询中使用 `ROWNUM`。

在处理 `MultipartHttpServletRequest` 时，如果直接使用用户上传的文件名（如 `fileOrginName`），并且这个文件名没有经过适当的清理和转义，就有可能导致XSS（跨站脚本攻击）漏洞。这是因为攻击者可以在文件名中注入恶意脚本代码，当这个文件名在网页上显示时，恶意脚本就可能被执行。

为了修复这个漏洞，可以采取以下措施：
1. 文件名清理：对用户上传的文件名进行清理，去除或转义掉可能导致XSS的特殊字符。可以使用正则表达式来匹配并替换这些特殊字符。
2. 使用安全的API：在处理文件上传时，尽量使用安全的API，避免直接操作文件名和内容。
3. 内容安全策略（CSP）：通过设置HTTP响应头中的Content-Security-Policy，限制可以执行的脚本类型和来源，从而减少XSS攻击的风险。
4. 输入验证：对所有用户输入进行验证，确保它们符合预期的格式，对于文件名，可以限制只允许字母、数字和一些安全的符号。
5. 输出编码：在将文件名输出到页面之前，对其进行HTML编码，将特殊字符转换成它们的HTML实体编码形式。
6. 使用框架提供的XSS防护：如果你使用的是Spring框架，可以利用其提供的XSS防护功能。例如，创建一个自定义的XSS防护过滤器来处理输入数据，并阻止恶意脚本的执行。
7. 文件名重命名：在服务器端保存文件时，不要使用用户上传时的原始文件名，而是为文件生成一个新的、安全的名字。
8. 使用安全库：使用像Jsoup这样的库来清理HTML内容，防止XSS攻击。
9. 避免内联事件：避免在HTML中直接使用内联事件处理器，如`onclick`，`onerror`等，因为这些可以被用来注入恶意脚本。
10. 实时监测与应对：部署监控系统以实时检测潜在的XSS攻击行为，并快速响应和修复。

通过上述措施，可以有效地减少XSS攻击的风险，并保护网站和用户的安全。
