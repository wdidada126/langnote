java.lang.NoClassDefFoundError

`java.lang.NoClassDefFoundError` 和 `java.lang.ClassNotFoundException` 都是 Java 运行时异常，但它们出现的场景和原因有所不同。

### `java.lang.ClassNotFoundException`

`ClassNotFoundException` 是 `java.lang.Exception` 的子类，属于可检查异常（checked exception），可以在编译时被捕捉。当应用程序试图加载一个类时，如果 JVM 无法在 classpath 中找到这个类的定义，就会抛出这个异常。这通常发生在以下情况：

- 试图通过 `Class.forName()` 方法动态加载一个类，但该类不存在于 classpath 中。
- 程序试图加载一个不存在的类，或者类文件没有被包含在应用程序的 classpath 中。

处理 `ClassNotFoundException` 通常需要确保 classpath 配置正确，并且所有需要的类都在 classpath 所指定的路径下。

### `java.lang.NoClassDefFoundError`

`NoClassDefFoundError` 是 `java.lang.Error` 的子类，属于不可检查错误（unchecked error），它在运行时发生，并且不应该被应用程序通过 try-catch 语句捕获。这个错误表明类在编译时存在，但在运行时找不到，这通常是由以下原因引起的：

- 类路径配置错误：编译时的 classpath 和运行时的 classpath 不一致。
- JAR 文件冲突：项目中可能使用了两个或多个库，这些库依赖于同一个包的不同版本，导致运行时类加载冲突。
- JDK/JRE 兼容性问题：如果使用的 JRE 版本低于用于编译程序的 JDK 版本，可能会出现这个错误。
- 动态加载类失败：使用 `ClassLoader.loadClass()` 动态加载类时，如果找不到这个类，也会抛出这个错误。

解决 `NoClassDefFoundError` 通常需要检查运行时的 classpath，确保所有必要的类和资源文件都可用，并且没有版本冲突。

### 总结

- `ClassNotFoundException` 是一个异常，可以在编译时被检查，通常与动态类加载有关。
- `NoClassDefFoundError` 是一个错误，不能在编译时被检查，通常与 classpath 配置和运行时环境有关。

在实际开发中，应该尽量避免捕获 `NoClassDefFoundError`，因为它通常表示严重的运行时问题，这些问题需要通过修正配置或环境来解决，而不是通过代码逻辑处理。
