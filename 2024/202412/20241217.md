而对于一般应用来说，有 Nginx 就可以了。但 Nginx 一般用于七层负载均衡，其吞吐量是有一定限制的。为了提升整体吞吐量，会在DNS和Nginx之间引入接入层，如使用LVS(软件负载均衡器)、F5(硬负载均衡器)可以做四层负载均衡，即首先DNS解析到 LVS/F5，然后 LVS/F5 转发给 Nginx，再由 Nginx 转发给后端 Real Server。
对于一般业务开发人员来说，我们只需要关心到Nginx层面就够了，LVS/F5 一般由系统/运维工程师来维护。Nginx目前提供了HTTP(ngxhttp_upstream_module)七层负载均衡,而1.9.0版本也开始支持TCP(ngx stream upstream module)四层负载均衡。

`ngx_http_upstream_module` 是 Nginx 中的一个模块，它用于定义可以被 `proxy_pass`、`fastcgi_pass`、`uwsqi_pass`、`scgi_pass`、`memcached_pass` 和 `grpc_pass` 等指令引用的服务器组。这个模块允许你在 Nginx 配置中设置一个或多个上游服务器，以实现负载均衡和故障转移等功能。
以下是一些关于 `ngx_http_upstream_module` 的关键点：
1. 负载均衡方法：`ngx_http_upstream_module` 支持多种负载均衡方法，包括轮询（round-robin）、最少连接（least_conn）、IP哈希（ip_hash）等，允许你根据需要选择合适的负载均衡策略。
2. 会话保持：通过 `sticky` 指令，可以实现会话保持（session affinity），使得来自同一客户端的请求总是被路由到同一台上游服务器。
3. 健康检查：可以使用 `health_check` 指令对上游服务器进行健康检查，以确保请求只被发送到健康的服务器。
4. 动态配置：Nginx 还提供了动态可配置的服务器组，允许定期进行健康检查，并根据服务器的健康状态动态调整服务器组的配置。
5. 共享内存区：通过 `zone` 指令，可以将负载均衡策略数据存放在共享内存区，以便在多个 worker 进程之间共享。
6. 嵌入式变量：`ngx_http_upstream_module` 支持多个嵌入式变量，如 `$upstream_addr`、`$upstream_bytes_received`、`$upstream_bytes_sent` 等，这些变量可以在日志记录和变量赋值中使用。
7. Keepalive 连接：`keepalive` 指令用于激活上游服务器连接的缓存，减少连接建立和关闭的消耗，提升吞吐量的同时降低时间延迟。
8. Resolver 和 DNS 查询：`resolver` 指令允许配置 DNS 服务器，用于将上游服务器的域名解析为地址。
这些特性使得 `ngx_http_upstream_module` 成为 Nginx 中实现高性能和高可用性网络服务的关键模块。
proxy_pass  http://$host$request_uri;
在 Nginx 配置中，`proxy_pass` 指令用于将客户端的请求转发给上游服务器。你提供的配置行 `proxy_pass http://$host$request_uri;` 包含了一些变量和协议部分，下面是这行配置的详细解释：
1. `proxy_pass`：这是 Nginx 中用于指定代理目标的指令。
2. `http://`：这部分指定了代理请求使用的协议。这里使用的是 HTTP 协议。
3. `$host`：这是一个 Nginx 变量，它代表原始请求中的 `Host` 头部的值。这意味着代理请求将被发送到与客户端请求中指定的主机名相同的服务器。
4. `$request_uri`：这是另一个 Nginx 变量，它包含客户端请求的原始 URI。这意味着代理请求将包含客户端请求的完整路径和查询字符串。
将这些部分组合起来，`proxy_pass http://$host$request_uri;` 这条指令的作用是将客户端的请求完整地转发到与请求中 `Host` 头部值相匹配的上游服务器，同时保持请求的 URI 不变。
这种配置通常用在以下场景：
- 反向代理：当你想要将请求透明地转发到后端服务器，同时保持原始的主机名和请求路径时。
- 保持会话：如果你的应用依赖于特定的主机名或路径，这种配置可以确保请求被正确地路由。
这里有一个简单的例子，展示了如何在 Nginx 配置文件中使用这条指令：
```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://$host$request_uri;
    }
}
```

在这个例子中，所有发送到 `example.com` 的请求都会被转发到与请求中的 `Host` 头部值相匹配的上游服务器，同时保持请求的 URI 不变。

Nginx 提供了一系列内置变量，这些变量可以在配置文件中使用，以获取和操作请求相关的信息。以下是一些常用的 Nginx 内置变量：

1. `$remote_addr`：客户端的IP地址。
2. `$remote_user`：已认证的用户名。
3. `$request`：完整的原始请求行。
4. `$status`：请求的响应状态码。
5. `$body_bytes_sent`：响应过程中发送给客户端的字节数。
6. `$request_time`：请求处理的时间，单位为秒。
7. `$upstream_response_time`：后端服务器响应的时间，单位为秒。
8. `$upstream_addr`：代理请求发送到的后端服务器地址。
9. `$host`：请求中的 Host 头部的值。
10. `$request_uri`：请求的 URI，不包含查询字符串。
11. `$uri`：与 `$request_uri` 相同。
12. `$document_uri`：与 `$request_uri` 相同。
13. `$query_string`：请求的查询字符串部分。
14. `$arg_PARAMETER`：请求中的查询参数，例如 `$arg_page` 将返回 `page` 参数的值。
15. `$document_root`：当前 location 或 if 指令中使用的 root 指令的值。
16. `$server_name`：当前的 server_name 的值。
17. `$request_method`：请求的方法（如 GET、POST）。
18. `$http_HEADER`：请求中的任意头部字段，例如 `$http_Authorization`。
19. `$sent_http_HEADER`：响应中的任意头部字段，例如 `$sent_http_Location`。
20. `$cookie_COOKIE`：请求中的 Cookie 值，例如 `$cookie_sessionid`。

这些变量可以在 Nginx 的配置文件中用于各种目的，例如：

- 重写 URL 和头部字段。
- 条件判断和重定向。
- 访问控制和认证。
- 日志记录。

使用这些变量时，你可以直接在配置文件中引用它们，例如：

```nginx
location / {
    proxy_pass http://$host$request_uri;
    access_log /var/log/nginx/access.log combined;
    error_log /var/log/nginx/error.log;
}
```

在这个例子中，`$host` 和 `$request_uri` 被用于 `proxy_pass` 指令，以确保代理请求保留了原始请求的主机名和 URI。同时，`access_log` 和 `error_log` 指令使用了文件路径来记录日志信息。
