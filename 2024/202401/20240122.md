OpenSSL 是一个强大的安全工具箱，它提供了多种加密算法的实现，包括 RSA。下面是一个使用 OpenSSL 生成 RSA 密钥对、加密和解密数据的简单例子。

生成 RSA 密钥对
首先，我们可以使用 openssl genpkey 命令生成一个 RSA 私钥：

bash
`openssl genpkey -algorithm RSA -out private_key.pem -pkeyopt rsa_keygen_bits:2048`
这将会在当前目录下生成一个名为 private_key.pem 的文件，其中包含了一个 2048 位的 RSA 私钥。

然后，我们可以从这个私钥中提取出公钥：

bash
`openssl rsa -pubout -in private_key.pem -out public_key.pem`
这将会生成一个名为 public_key.pem 的文件，其中包含了与私钥对应的公钥。

使用 RSA 密钥对进行加密和解密
现在，我们可以使用这对密钥来进行加密和解密操作。假设我们有一个名为 plaintext.txt 的文件，我们想要使用公钥来加密它：

bash
`openssl rsautl -encrypt -pubin -inkey public_key.pem -in plaintext.txt -out encrypted.txt`
这将会生成一个名为 encrypted.txt 的文件，其中包含了使用公钥加密后的数据。

接下来，我们可以使用私钥来解密这个文件：

bash
`openssl rsautl -decrypt -inkey private_key.pem -in encrypted.txt -out decrypted.txt`
这将会生成一个名为 decrypted.txt 的文件，其中包含了解密后的原始数据。

注意事项
在实际使用中，RSA 加密通常用于加密小块数据或用于密钥交换，而不是直接用于加密大量数据。对于大量数据的加密，通常使用对称加密算法（如 AES），而 RSA 可以用于安全地交换这些对称加密算法的密钥。
在上面的例子中，我们没有对加密和解密操作进行任何填充（padding）。在实际应用中，填充是必要的，因为它可以提供额外的安全性。OpenSSL 支持多种填充模式，如 PKCS#1 v1.5 和 OAEP。
请确保您的私钥保持私密，并且只在需要的时候和可信任的实体共享公钥。

在同一台主机上配置两个 GitHub 密钥对可以实现通过不同的密钥对进行 `git clone`。要做到这一点，您可以使用 SSH 配置文件（`~/.ssh/config`）来指定不同的密钥对与不同的主机关联。

以下是一个示例 `~/.ssh/config` 文件的配置：

```plaintext
# 默认的 SSH 配置
Host github.com
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_rsa

# 第二个密钥对的 SSH 配置
Host github-edidada
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_rsa_second
```

在上面的配置中，我们使用了两个不同的 Host 条目。第一个 Host 条目是默认的配置，使用默认的密钥对文件 `~/.ssh/id_rsa`。第二个 Host 条目是针对第二个密钥对的配置，使用密钥对文件 `~/.ssh/id_rsa_second`。

现在，您可以使用 `git clone` 命令时，通过指定不同的远程主机别名来选择使用不同的密钥对。

例如，使用第一个密钥对进行克隆：

```shell
git clone git@github.com:username/repo.git
```

使用第二个密钥对进行克隆：

```shell
git clone git@github-second:username/repo.git
```

通过在 `git clone` 命令中指定不同的远程主机别名，可以选择使用不同的密钥对进行身份验证。

请确保将 `username/repo.git` 替换为实际的 GitHub 用户名和存储库名称。

这样，您就可以在同一台主机上使用不同的 GitHub 密钥对进行 `git clone` 操作了。
