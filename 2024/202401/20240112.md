gnulib-tool vs gnulib
gnulib-tool和gnulib的区别主要在于用途和功能。
gnulib-tool是一个用于管理共享库的构建工具，它将平台相关的特性和用户接口封装到了一个脚本文件中，简化了在不同系统上建立动态链接库的过程。它可以创建库，并通过一个统一的接口管理编译环境的本地功能特性。
而gnulib是一个支持多系统运行的GNU可移植性库，包含了一些基本的函数和数据类型，以便在不同的系统上进行开发。它提供了各种数学和科学计算的功能，如线性代数、解析函数、常微分方程、多项式等。gnulib的目标是提供跨平台的可移植性，使开发者可以在不同的操作系统上使用相同的代码进行开发。
总的来说，gnulib-tool主要关注于库的构建和管理，而gnulib则关注于提供跨平台的数学和科学计算功能。

C++处理Excel文件的库有以下几个：
1. xlnt：一个跨平台的C++库，用于读取和写入Microsoft Excel（2003及更高版本）文件。它提供了丰富的API，可以方便地操作Excel文件的各个部分，如单元格、工作表、图表等。
安装方法：在GitHub上下载源代码并按照说明进行编译和安装。
示例代码：

```cpp
#include <iostream>
#include <xlnt/xlnt.hpp>

int main()
{
    xlnt::workbook wb;
    wb.load("example.xlsx");

    xlnt::worksheet ws = wb.active_sheet();
    for (auto row : ws.rows(false))
    {
        for (auto cell : row)
        {
            std::cout << cell.to_string() << "\t";
        }
        std::cout << std::endl;
    }

    return 0;
}
```

安装方法：在GitHub上下载源代码并按照说明进行编译和安装。

在 CMake 中，`xxxConfigVersion.cmake` 文件（例如 `BoostConfigVersion.cmake`、`OpenCVConfigVersion.cmake` 等）用于描述某个库的版本信息。它通常由第三方库安装时生成，用于支持 `find_package()` 命令在查找包时进行**版本兼容性检查**。

这个文件中会定义几个关键变量：
###  1. `PACKAGE_VERSION`
这是当前找到的库的实际版本号（通常是字符串），比如：
```cmake
set(PACKAGE_VERSION "1.74.0")
```
- 表示你正在使用的库的具体版本。
- 该值通常从构建系统传入或通过解析库的头文件获取。
###  2. `PACKAGE_VERSION_EXACT`
这是一个布尔标志，表示是否要求精确匹配版本。
```cmake
set(PACKAGE_VERSION_EXACT FALSE)
```
- 如果为 `TRUE`：只有当请求的版本与 `PACKAGE_VERSION` 完全一致时才认为是兼容的。
- 如果为 `FALSE`：则允许使用兼容版本（见下文 `PACKAGE_VERSION_COMPATIBLE`）。
###  3. `PACKAGE_VERSION_COMPATIBLE`
这也是一个布尔标志，表示当前版本是否与请求的版本**兼容**。
```cmake
set(PACKAGE_VERSION_COMPATIBLE TRUE)
```
- 当用户使用 `find_package(XXX 1.74 REQUIRED)` 请求特定版本时，CMake 会调用 `XXXConfigVersion.cmake` 来判断当前版本是否兼容。
- 如果设置为 `TRUE`，表示当前版本可以满足请求版本的要求。
- 否则，如果设置为 `FALSE`，即使版本存在也不会被接受。
> 通常根据语义化版本规则来判断是否兼容，如：
> - 主版本相同，次版本更高 → 兼容
> - 主版本不同 → 不兼容
###  4. `PACKAGE_VERSION_UNSUITABLE`
这是一个可选字段，用于提供一个错误信息，说明为什么当前版本不适合使用。
```cmake
set(PACKAGE_VERSION_UNSUITABLE "Requested version is too new.")
```
- 如果设置了此变量，并且其内容非空，则无论 `COMPATIBLE` 是什么，都会导致 `find_package()` 失败，并输出此消息。
- 可以用来给出更清晰的错误提示。
## 示例场景
假设你有一个库安装了版本 `1.74.0`，它的 `BoostConfigVersion.cmake` 文件可能如下：
```cmake
set(PACKAGE_VERSION "1.74.0")

if("${PACKAGE_FIND_VERSION}" VERSION_EQUAL "1.74.0")
    set(PACKAGE_VERSION_EXACT TRUE)
else()
    set(PACKAGE_VERSION_EXACT FALSE)
endif()

if("${PACKAGE_FIND_VERSION_MAJOR}" EQUAL 1 AND
   "${PACKAGE_FIND_VERSION_MINOR}" LESS_EQUAL 74)
    set(PACKAGE_VERSION_COMPATIBLE TRUE)
else()
    set(PACKAGE_VERSION_COMPATIBLE FALSE)
endif()
```
这样：
- 如果你写 `find_package(Boost 1.74 REQUIRED)`，就能找到并成功。
- 如果你写 `find_package(Boost 1.75 REQUIRED)`，就会失败，因为主版本相同但次版本不兼容。
##  总结对比表
| 变量 | 类型 | 含义 |
|------|------|------|
| `PACKAGE_VERSION` | 字符串 | 实际安装的库版本号（如 `"1.74.0"`） |
| `PACKAGE_VERSION_EXACT` | 布尔值 | 是否要求精确匹配版本 |
| `PACKAGE_VERSION_COMPATIBLE` | 布尔值 | 当前版本是否兼容请求的版本 |
| `PACKAGE_VERSION_UNSUITABLE` | 字符串（可选） | 非空时显示版本不可用原因 |
##  使用建议
如果你自己编写一个 `MyLibConfigVersion.cmake`，你可以这样写：
```cmake
set(PACKAGE_VERSION "2.3.1")

# 检查是否精确匹配
if("${PACKAGE_FIND_VERSION}" VERSION_EQUAL PACKAGE_VERSION)
    set(PACKAGE_VERSION_EXACT TRUE)
else()
    set(PACKAGE_VERSION_EXACT FALSE)
endif()

# 判断是否兼容：主版本一致，次版本小于等于当前版本即可
if("${PACKAGE_FIND_VERSION_MAJOR}" EQUAL 2 AND
   "${PACKAGE_FIND_VERSION_MINOR}" LESS_EQUAL 3)
    set(PACKAGE_VERSION_COMPATIBLE TRUE)
else()
    set(PACKAGE_VERSION_COMPATIBLE FALSE)
    set(PACKAGE_VERSION_UNSUITABLE "Only version 2.x compatible where x <= 3")
endif()
```

在 CMake 构建系统中，以下文件都是用于管理和配置依赖项的配置文件：

1. `xxxConfig.cmake`：这是一个用于描述特定库或工具的配置文件。它定义了库或工具的相关设置、路径和选项，以及如何使用它们的信息。`xxx` 是库或工具的名称或标识符。
2. `xxxConfigVersion.cmake`：这个文件包含了用于版本管理的信息，例如库或工具的版本号。它通常与 `xxxConfig.cmake` 文件配套使用，以确保正确的版本匹配。
3. `xxxTargets.cmake`：这个文件包含了与库或工具相关的 CMake 目标的定义。它定义了库或工具的编译选项、链接选项以及与之关联的源文件。通常，这个文件会导入 `xxxConfig.cmake` 中定义的设置。

这些配置文件的作用如下：

- `xxxConfig.cmake` 文件提供了一个接口，使其他项目可以轻松地使用库或工具。它定义了库或工具的接口函数、路径和其他配置选项，以便用户可以方便地将其集成到自己的项目中。
- `xxxConfigVersion.cmake` 文件用于确保库或工具的版本兼容性。当其他项目引用库或工具时，它们可以检查所引用库或工具的版本是否与其期望的版本一致。
- `xxxTargets.cmake` 文件定义了与库或工具相关的 CMake 目标。这些目标可以用于编译、链接和使用库或工具。它们包含了与库或工具相关的编译和链接选项，以及与之关联的源文件和其他依赖项。

这些配置文件通常由库或工具的开发者提供，并与库或工具一起分发。其他项目可以使用这些配置文件来方便地使用和集成库或工具，而无需手动配置路径和选项。

请注意，实际的配置文件名称可能因具体的库或工具而异，`xxx` 只是一个示例标识符。每个库或工具的配置文件通常具有与其名称相关的文件名前缀。
