git reset之后，如何把reset的操作提交到远程仓库？
不加--hard，远程分支的代码，把本地覆盖掉了
在使用 `git reset` 命令重置提交历史之后，重置的操作并不会自动提交到远程仓库。`git reset` 命令主要用于本地分支的历史更改，而不会直接影响远程仓库。

如果您想将重置的操作提交到远程仓库，您可以使用 `git push` 命令来将本地分支的更改推送到远程仓库。但是，需要注意的是，如果使用了 `git reset` 命令来修改过去的提交历史，强制推送（`--force`）可能会导致远程分支与本地分支不一致，因此请谨慎操作。

以下是将重置的操作提交到远程仓库的一般步骤：

1. 使用 `git reset` 命令重置本地分支的提交历史。例如，如果您使用了 `git reset --hard HEAD~3` 命令来将分支回退到前三个提交，那么本地分支的提交历史将被修改。
2. 运行 `git push` 命令来将本地分支的更改推送到远程仓库。您可以指定远程仓库的名称和分支名称，例如：

```shell
git push origin <branch-name>
```

在上述命令中，将 `<branch-name>` 替换为您要推送的分支的名称。
请注意，如果您使用了 `git reset` 命令并修改了过去的提交历史，可能需要使用 `--force` 参数来强制推送更改。例如：

```shell
git push --force origin <branch-name>
```

强制推送会覆盖远程仓库中的提交历史，请确保您知道自己在做什么，并且在团队合作中与其他人协商好使用此操作的风险和影响。
