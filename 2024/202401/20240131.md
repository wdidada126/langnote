# 我直接复现你说的那个“傻逼行为”
## 错误代码（经典自杀）
```cpp
// 错误！！！
QString qs = "hello";
const char* ptr = qs.toStdString().c_str(); // 野指针诞生
```

## 为什么错？
因为：
1. `toStdString()` **返回一个临时 string 对象**
2. 这一行结束后，**临时对象直接被销毁**
3. `.c_str()` 返回的指针**指向的内存被释放了**
4. `ptr` 现在是 **悬空指针（野指针）**
5. 你再用它 → **随机崩溃、乱码、诡异问题**

---

# 为什么“写在一行就正常，另起一行就崩溃”？
## 行1：一行代码 → 侥幸正常
```cpp
printf("%s", qs.toStdString().c_str());
```
✅ 原因：
**临时对象在整条语句结束前不会销毁**
所以 `c_str()` 还活着。

---

## 行2：另起一行 → 直接崩溃
```cpp
const char* s = qs.toStdString().c_str();
printf("%s", s); // 💥 崩溃！
```
❌ 原因：
第一行结束后
**临时 string 已经被析构了！**
`s` 指向一块已经释放的内存。

这就是你说的：
**为什么一行可以，另起一行就不行！**

---

# 为什么说这种是“傻逼行为”？
因为：
1. **用原始指针托管对象生命周期**
2. **拿临时对象的内部指针**
3. **对象没了，指针还在到处传**
4. **代码看起来正常，运行随机炸**
5. **排查极难**

现代 C++ 的核心观点就是：
## **不要持有裸指针！不要持有临时对象的内部指针！**

# 现代 C++ 「野指针/悬空引用 自杀清单」
CodeReview 红线、生产必炸、严格禁止，适配 C++11/17/20，全覆盖你刚才 `QString::toStdString()+c_str()` 场景。

## 一、字符串经典自杀（最高频）
1. 保存**临时 std::string** 的 `c_str()`
```cpp
// 致命错误
const char* p = QString("a").toStdString().c_str();
const char* p = std::string("hello").c_str();
```
- 临时对象语句结束析构，指针悬空
- 现象：一行内用正常，拆两行必乱码/崩溃

2. 保存 `string::substr()` 临时的裸指针
```cpp
const char* sub = s.substr(0,3).c_str();
```
- substr 返回临时 string，生命周期结束直接释放

3. 函数返回局部 string 的 `c_str()`
```cpp
const char* GetMsg() {
    std::string t = "test";
    return t.c_str();
}
```

---

## 二、容器 & 迭代器 自杀行为
4. 容器扩容/删除后，继续使用**失效迭代器、指针、引用**
```cpp
std::vector<int> v{1,2,3};
int* p = &v[0];
v.resize(100); // 扩容重新分配内存
*p = 99;        // 悬空访问
```

5. 遍历中 erase 后，使用老旧迭代器
```cpp
for(auto it = vec.begin(); it != vec.end(); ++it){
    vec.erase(it); // 迭代器直接失效
}
```

6. 错误保存 map/unordered_map value 裸指针
容器节点重组、扩容后，value 地址失效

---

## 三、临时对象 悬空引用/指针
7. 绑定临时对象到**左值引用**
```cpp
int& r = 10;          // 非法
std::string& s = func_ret_temp();
```

8. 捕获临时对象的指针/引用并长期持有
函数出参、类成员保存临时对象地址

9. 类成员指针指向局部栈对象
```cpp
struct A{ int* p_; };
A a;
int x = 10;
a.p_ = &x; // 函数结束x销毁，成员指针悬空
```

## 四、内存手动管理 复古自杀（现代C++严禁）
10. 裸指针 `new/delete` 成对手写，不使用智能指针
11. `delete` 后不置空，重复删除、野指针复用
12. `void*` 强转乱用，越界访问堆内存
13. C 风格 `malloc/free` 混合 C++ 对象，不调用构造析构

## 五、Qt 专属高频坑（你遇到的场景）
14. `QString -> toStdString()/toUtf8()` 临时结果取地址、取c_str
15. 跨线程保存 `QObject*` 裸指针，对象销毁后悬空
16. 隐式共享容器临时解构，内部指针失效

## 六、生命周期 架构级红线
17. 任何场景：**只存对象、引用、智能指针；不存裸指针**
18. 禁止类成员持有短期生命周期外部裸指针
19. 异步回调、多线程全局缓存，保存临时资源指针
20. RAII 资源句柄提前析构，句柄指针残留

# 现代 C++ 三条保命铁律（根治所有问题）
1. **需要长期持有 → 存完整对象（std::string/容器/结构体），杜绝裸指针**
2. **短期只读传递 → 用 const 左值引用 `const T&`**
3. **必须托管生命周期 → 用 `std::unique_ptr / std::shared_ptr`，禁用裸指针
