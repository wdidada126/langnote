如何查看占用网络端口8090的进程什么时候挂掉的？
要查看占用网络端口8090的进程何时挂掉，您可以按照以下步骤操作：

对于Linux系统：

使用 netstat -tulnp | grep 8090 命令查找占用8090端口的进程及其PID。
使用 ps -p [PID] -o etimes= 命令查看该进程的运行时间，这将显示进程启动到现在经过的时间。如果进程已经结束，这个命令将不会返回任何结果。
对于Windows系统：

打开命令提示符，使用 netstat -ano | findstr :8090 命令查找占用8090端口的进程及其PID。
使用 tasklist /fi "pid eq [PID]" 命令查看进程信息。如果进程已经结束，这个命令将不会返回任何结果。
请注意，这些命令只能告诉您进程的运行时间或是否存在，而不能直接告诉您进程何时挂掉。如果进程已经结束，您可能需要查看系统日志或应用程序日志来确定进程结束的时间。

在g++编译器中，-fexceptions选项是用来启用或禁用异常处理的支持。当使用这个选项时，如果在源代码中使用了C++的异常处理机制（try, catch, throw等），编译器就会生成相应的代码来处理这些异常。

具体来说，-fexceptions选项会做以下几件事：
1. 启用C++异常处理机制，允许抛出和捕获异常。
2. 为每个函数生成额外的信息，以便在运行时能够正确地处理异常。
3. 可能会增加编译后的代码大小，因为需要包含额外的异常处理代码。

需要注意的是，如果你的代码没有使用C++的异常处理机制，那么使用-fexceptions选项是没有意义的，因为它不会对代码产生任何影响。

中CONFIG_FILE_NAME变量是“”为什么不是config.ini

在你的代码中，`CONFIG_FILE_NAME` 被定义为一个 `const std::string` 类型的变量，并赋值为 `"config.ini"`。但是你提到在实际运行时，这个变量的值变成了空字符串 `""`。

这种情况通常是由于变量初始化时被覆盖，或者是在代码的其他地方有意无意地将其值改为了 `""`。以下是一些可能的原因和检查方法：

1. 重复定义或修改： 检查代码中的其他部分是否有对 `CONFIG_FILE_NAME` 进行重新定义或修改。由于 `CONFIG_FILE_NAME` 是一个常量变量，如果在其他地方不小心重新定义或修改了它（尽管这种情况在编译时会报错），可能会导致值出现问题。

2. 未能正确初始化： 确保在变量定义时立即初始化，避免之后的逻辑错误。如果在多个地方使用 `CONFIG_FILE_NAME`，最好使用断点或打印调试信息，查看它的值在不同点是否发生了变化。

3. 编译器优化或链接问题： 在某些极端情况下，编译器优化可能会导致问题。尝试将代码简化，或者在不同的编译器优化级别下编译，查看是否能重现问题。

4. 代码覆盖：确保没有在代码的其他地方对该变量进行不合理的修改。可以通过全局搜索 `CONFIG_FILE_NAME` 来检查。

总结来说，这个问题通常不是定义 `const` 变量本身的问题，而是代码的其他部分不小心更改了该变量的值，或者定义时有不当操作。

在C++中，如果你希望一个变量在初始化后不能再被修改，通常可以使用`const`关键字来保证该变量只被赋值一次。例如：

```cpp
const std::string CONFIG_FILE_NAME = "config.ini";
```

在这种情况下，`CONFIG_FILE_NAME` 在初始化后将无法再被修改，任何尝试对其重新赋值的操作都会导致编译错误。这已经达到了“只能赋值一次”的效果。

然而，如果你希望在尝试重新赋值时立即得到错误提示，`const`变量已经提供了这一功能。尝试对`const`变量重新赋值会导致编译时错误。例如：

```cpp
CONFIG_FILE_NAME = "new_config.ini";  // 这会导致编译错误
```

如果你希望在代码中有某种机制，在运行时或编译时进一步保护某个变量防止被修改，可以考虑以下方法：

### 1. `const` 结合 `constexpr`
如果变量的值在编译时就可以确定，并且永远不会改变，可以使用 `constexpr` 来定义它，这样不仅保证了只被赋值一次，还能进一步优化编译：

```cpp
constexpr const char* CONFIG_FILE_NAME = "config.ini";
```

### 2. `static const`
对于类成员或者局部静态变量，也可以使用 `static const` 来保证其只在初始化时赋值一次且不能更改：

```cpp
static const std::string CONFIG_FILE_NAME = "config.ini";
```

### 3. 使用宏定义（不推荐）
虽然可以使用宏定义常量来避免后续修改，但这并不是推荐的方式，因为宏缺乏类型检查：

```cpp
#define CONFIG_FILE_NAME "config.ini"
```

### 4. 自定义赋值操作
如果你需要更复杂的逻辑来防止变量被重新赋值，可以通过将变量封装在一个类中，并自定义赋值操作。但这通常是过度设计，`const`关键字已经足够。

总结来说，`const`关键字已经提供了你需要的功能，即确保变量只被赋值一次且不可更改。如果尝试对其重新赋值，编译器会报错。
