这个错误的根本原因是由于在 `dynamic_ini_reader.c` 文件中重新定义了 `ini_handler` 函数，而这个函数名已经在 `ini.h` 头文件中被定义为了一个函数指针类型。C 语言中，函数和类型不能共享同一个名字，因此会引发这个编译错误。
### 解决方法
你需要重命名 `dynamic_ini_reader.c` 文件中的 `ini_handler` 函数，以避免与 `ini.h` 中的 `ini_handler` 类型名称冲突。可以按如下方式修改代码：
1. 重命名 `ini_handler` 函数：
   例如，将 `ini_handler` 函数重命名为 `handle_ini_setting` 或其他合适的名字。
### 修改后的代码示例：

```c
#include <stdio.h>
#include <stdlib.h>
#include "ini.h"

// 原先的 ini_handler 函数重命名为 handle_ini_setting
static int handle_ini_setting(void *user, const char *section, const char *name, const char *value) {
    // 处理 ini 文件内容的逻辑
    if (strcmp(section, "db") == 0 && strcmp(name, "user") == 0) {
        printf("db.user = %s\n", value);
    } else if (strcmp(section, "server") == 0 && strcmp(name, "port") == 0) {
        printf("server.port = %s\n", value);
    }
    return 1;
}

int main(int argc, char *argv[]) {
    // 读取 INI 文件
    if (ini_parse("config.ini", handle_ini_setting, NULL) < 0) {
        printf("Can't load 'config.ini'\n");
        return 1;
    }
    return 0;
}
```

查看mysql server执行了哪些sql？
要记录 MySQL 服务器执行的所有 SQL 语句，可以使用 MySQL 5.7 提供的 `general_log` 功能。这个功能会将所有执行的 SQL 语句记录到一个日志文件或数据库表中。下面是如何将这些日志记录到 MySQL 数据库表中的步骤：

### 1. 启用 `general_log`
   首先，确保 MySQL 的 `general_log` 功能是开启的。你可以通过以下命令检查和启用它。

   ```sql
   -- 查看当前 `general_log` 状态
   SHOW VARIABLES LIKE 'general_log%';

   -- 启用 `general_log`
   SET GLOBAL general_log = 'ON';
   ```

### 2. 将日志记录到表
   默认情况下，`general_log` 记录到文件中。你可以将其配置为记录到 MySQL 数据库的表中。

   ```sql
   -- 将日志记录方式设置为 TABLE
   SET GLOBAL log_output = 'TABLE';
   ```
   这样，MySQL 将会把所有执行的 SQL 语句记录到 `mysql.general_log` 表中。
### 3. 查看日志
   你可以直接查询 `mysql.general_log` 表来查看所有执行过的 SQL 语句。
   ```sql
   SELECT * FROM mysql.general_log;
   ```

### 4. 优化建议
   - 日志表可能增长得很快：因为记录了所有 SQL 语句，`general_log` 表可能会很快变得非常大。建议定期清理或归档此表。
   - 性能影响：启用 `general_log` 会增加 MySQL 的 I/O 负载，可能会对数据库性能产生负面影响。只在必要时启用，并在不需要时禁用它。

   ```sql
   -- 禁用 `general_log`
   SET GLOBAL general_log = 'OFF';
   ```

### 5. 配置持久化
   如果你想让这些设置在 MySQL 重启后依然有效，需要将这些配置添加到 MySQL 的配置文件（`my.cnf` 或 `my.ini`）中。

   在 `[mysqld]` 部分添加以下内容：

   ```ini
   [mysqld]
   general_log = 1
   log_output = TABLE
   ```

这样设置后，MySQL 服务器将会记录所有的 SQL 语句到 `mysql.general_log` 表中，你可以随时查询这些日志。

select argument from general_log limit 100;

mysql CONVERT()函数

MySQL 的 `CONVERT()` 函数用于在不同的数据类型之间转换表达式的类型，或者将字符串从一种字符集转换为另一种字符集。

### 语法
1. 数据类型转换：
   ```sql
   CONVERT(expr, type)
   ```

   - `expr`：要转换的表达式。
   - `type`：目标数据类型，可以是 `BINARY`, `CHAR`, `DATE`, `DATETIME`, `DECIMAL`, `JSON`, `SIGNED INTEGER`, `TIME`, `UNSIGNED INTEGER` 等。

2. 字符集转换：
   ```sql
   CONVERT(expr USING charset_name)
   ```

   - `expr`：要转换的字符串。
   - `charset_name`：目标字符集，例如 `utf8`, `latin1`, `ascii` 等。

### 示例

1. 数据类型转换：
   - 将字符串转换为整数：
     ```sql
     SELECT CONVERT('123', SIGNED INTEGER);
     ```

   - 将日期字符串转换为日期类型：
     ```sql
     SELECT CONVERT('2024-08-29', DATE);
     ```

2. 字符集转换：
   - 将字符串从 `latin1` 字符集转换为 `utf8` 字符集：
     ```sql
     SELECT CONVERT('Hello, World!' USING utf8);
     ```

### 注意事项
- 如果转换过程中出现不兼容的数据类型或字符集，MySQL 可能会返回 `NULL` 或引发错误。
- 对于字符集转换，目标字符集必须在 MySQL 安装中支持。
### 应用场景
- 数据类型转换在处理不同类型的数据时非常有用，例如将字符串转换为数值类型以进行数学运算。
- 字符集转换则用于处理多语言文本数据，尤其是在需要统一字符编码或进行数据迁移时。

### 实际例子

1. 将字符串转换为浮点数：
   ```sql
   SELECT CONVERT('123.45', DECIMAL(5,2));
   ```

2. 将字符串从 `utf8` 转换为 `latin1`：
   ```sql
   SELECT CONVERT('こんにちは' USING latin1);
   ```

上例中的字符串是日语的 "Hello"，在 `utf8` 编码下显示正确，但如果转换到 `latin1` 可能会导致数据丢失或乱码，因为 `latin1` 不支持这些字符。
