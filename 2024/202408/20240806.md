为什么不用new


在C++中，return Article(); 和 return new Article(); 这两行代码在用途、语义和内存管理上有根本的不同，这也是为什么在大多数情况下你不会使用 new 来返回一个对象的原因。

return Article();
这行代码创建了一个Article类型的临时对象，并返回这个对象的拷贝（在C++11及以后的版本中，由于返回值优化（RVO）和移动语义的引入，这个拷贝可能会被省略）。
它返回的是一个Article类型的值，而不是指针。
这种方式非常安全，因为对象的生命周期由调用者管理（实际上是临时对象的拷贝），不需要手动释放内存。
return new Article();
这行代码在堆上动态分配了一个Article类型的对象，并返回指向这个对象的指针（Article*）。
它返回的是一个指针，这意味着调用者需要负责管理这个指针指向的内存。调用者必须确保在适当的时候使用delete来释放这块内存，否则会导致内存泄漏。
由于需要手动管理内存，这种方式更容易出错，也更难以维护。
为什么不用 new
内存管理复杂性：如上所述，使用new需要手动管理内存，这增加了代码的复杂性和出错的可能性。
异常安全性：如果在分配内存后但在返回指针之前发生异常，那么分配的内存将不会被释放，除非你有额外的异常处理逻辑来确保这一点。
现代C++标准：现代C++（特别是C++11及以后）鼓励使用智能指针（如std::unique_ptr和std::shared_ptr）来自动管理动态分配的内存。然而，即使在这种情况下，也通常推荐返回值而不是指针或智能指针，除非有明确的理由需要返回指针（例如，多态或生命周期管理需求）。
性能考虑：虽然现代编译器通常能够优化掉不必要的拷贝和移动操作，但在某些情况下，返回值可能会比返回指针引入更多的开销（尽管这种差异通常可以忽略不计）。然而，这种性能差异通常被内存安全性和代码清晰性的优势所抵消。
代码清晰度：返回值通常比返回指针更清晰、更易于理解。它直接表达了函数的输出类型，而不需要调用者去解引用指针或检查指针是否为nullptr。
综上所述，除非你有明确的理由需要返回指针（如多态或特殊的生命周期管理需求），否则在C++中通常建议返回值而不是使用new来返回指针。
