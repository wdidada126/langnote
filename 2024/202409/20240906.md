Undo Log（撤销日志）和Redo Log（重做日志）是数据库系统中两种重要的日志文件，它们在事务处理中起着关键作用。
1. Undo Log（撤销日志）：
Undo Log 记录了事务执行过程中对数据库所做的修改操作，以便在事务失败或需要回滚时可以恢复原始状态。当一个事务开始时，系统会为该事务分配一个唯一的事务ID，并记录下所有对该事务的修改操作。如果事务成功提交，则对应的 Undo Log 会被删除；如果事务失败或需要回滚，系统会根据 Undo Log 中记录的操作逆向执行，恢复到事务开始前的状态。
2. Redo Log（重做日志）：
Redo Log 记录了事务执行过程中对数据库所做的修改操作，但它与 Undo Log 不同，它的主要目的是在系统崩溃后恢复数据。Redo Log 记录的是已经提交的事务的所有修改操作，即使系统崩溃，只要 Redo Log 没有被清空，系统就可以通过重放 Redo Log 中的操作来恢复数据到崩溃前的状态。Redo Log 通常采用顺序写入的方式，以保证数据的一致性。
总结：
Undo Log 主要用于事务的回滚操作，而 Redo Log 主要用于系统崩溃后的恢复操作。两者都是为了保证数据库系统的一致性和可靠性。

JDK动态代理是Java反射机制的核心应用，通过java.lang.reflect.Proxy和InvocationHandler接口实现。当调用代理对象的方法时，会触发invoke方法，该方法可以拦截并增强原始方法调用。动态代理在运行时生成代理类，这些类继承Proxy并实现目标接口，通过InvocationHandler转发方法调用。

Java反序列化CC链是Apache Commons Collections库中的反序列化漏洞利用链，利用InvokerTransformer、ChainedTransformer等类构造恶意对象，在反序列化时执行任意代码。CC1利用AnnotationInvocationHandler的readObject方法触发LazyMap.get()，CC3利用TrAXFilter的构造方法触发TemplatesImpl.newTransformer()，CC6则通过HashSet.readObject()触发HashMap.put()最终调用LazyMap.get()。

类加载相关补充包括双亲委派模型、自定义类加载器、defineClass方法等。在反序列化攻击中，攻击者常利用URLClassLoader加载远程恶意类，或通过TemplatesImpl的defineTransletClasses方法加载字节码。ClassLoader的loadClass方法遵循双亲委派，而findClass方法可被重写实现自定义类加载逻辑，这是许多反序列化漏洞利用的关键点。

# 精炼整合版（可直接背、面试默写、笔记定稿）
## 一、JDK 动态代理（反射核心应用）
JDK 动态代理基于**Java 反射机制**，依托 `java.lang.reflect.Proxy` 类与 `InvocationHandler` 接口实现。
运行时动态生成代理类，代理类默认继承 `Proxy`、并**实现目标业务接口**；无法代理普通类，只能代理接口。

代理对象任意方法调用，都会统一分发到 `InvocationHandler.invoke()` 方法，实现**方法拦截、前置后置增强、参数改写、逻辑包装**。
动态代理无静态代理硬编码冗余，是 AOP、中间件 RPC 拦截层的底层基础。

## 二、Java 反序列化 CC 链（Commons Collections 漏洞链）
CC 链是利用 **Apache Commons Collections** 容器类特性构造的反序列化恶意调用链，反序列化触发 `readObject` 时自动链式回调，最终实现**任意代码执行**。
核心利用类：`InvokerTransformer`、`ChainedTransformer` 等反射调用包装类。

- **CC1**：利用 `AnnotationInvocationHandler.readObject` → 触发 `LazyMap.get()` 链式回调，执行恶意逻辑。
- **CC3**：依托 `TrAXFilter` 构造方法 → 触发 `TemplatesImpl.newTransformer()`，加载恶意字节码。
- **CC6**：通过 `HashSet.readObject` 反序列化流程 → 触发 `HashMap.put()`，最终路由到 `LazyMap.get()` 完成调用链触发。

本质：利用 Java 反序列化自动递归重建对象、自动执行 `readObject` + 容器懒加载回调 + 反射执行，达成无代码入口的命令执行。

## 三、类加载底层（反序列化漏洞关键支撑）
核心基础：**双亲委派模型、自定义类加载器、defineClass 字节码加载**。

1. 双亲委派：`ClassLoader.loadClass` 优先委托父加载器，顶层 Bootstrap → Extension → App → 自定义加载器，避免重复加载、沙箱安全隔离。
2. 自定义类加载器：重写 `findClass` 流程，外部读取字节码，调用 `defineClass` 把字节码转为 Class 类对象。
3. 漏洞利用关键点：
   - `URLClassLoader` 可加载**远程恶意类**；
   - `TemplatesImpl` 内部 `defineTransletClasses` 直接加载内置恶意字节码，是多条反序列化链的最终落脚点；
   - 突破双亲委派、自定义加载字节码，是反序列化漏洞实现代码执行的核心底层依赖。

# 串联总结（面试一句话压轴）
JDK动态代理基于反射运行时生成接口代理类，通过 InvocationHandler 实现方法拦截增强；CC 反序列化链利用 Commons Collections 懒加载容器与反射Transformer，借助不同入口类的 readObject 触发链式回调实现任意代码执行；而漏洞最终落地依赖类加载机制，通过自定义类加载器、defineClass、URLClassLoader 及 TemplatesImpl 字节码加载能力，完成恶意类载入与执行。
