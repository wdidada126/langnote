在Oracle中，我们可以使用ROWNUM伪列和子查询来实现分页。而在MyBatis中，我们可以通过编写动态SQL来实现分页。
以下是Oracle SQL的分页示例：
```sql
SELECT * FROM (
  SELECT t.*, ROWNUM rn FROM (
    SELECT * FROM your_table ORDER BY some_column
  ) t
  WHERE ROWNUM <= (pageNum * pageSize)
)
WHERE rn > ((pageNum - 1) * pageSize);
```
在这个例子中，`your_table`是你要查询的表名，`some_column`是你用来排序的列名，`pageNum`是当前页数，`pageSize`是每页显示的记录数。

接下来是在MyBatis中的实现方式：
首先，在你的Mapper接口中定义一个方法，例如：
```java
List<YourEntity> selectByPage(@Param("pageNum") int pageNum, @Param("pageSize") int pageSize);
```
然后，在对应的XML映射文件中，编写如下SQL语句：
```xml
<select id="selectByPage" resultType="YourEntity">
  SELECT * FROM (
    SELECT t.*, ROWNUM rn FROM (
      SELECT * FROM your_table ORDER BY some_column
    ) t
    WHERE ROWNUM <= #{pageNum} * #{pageSize}
  )
  WHERE rn > (#{pageNum} - 1) * #{pageSize};
</select>
```
注意，这里的`YourEntity`应该替换为你的实际实体类名，而`your_table`和`some_column`则应替换为你的数据库表名和排序列名。

你写的应该是 **App Governance Suite（简称AGS）**，国内常叫“应用治理套件”，是一类面向企业级应用的**代码扫描+安全合规+质量治理**一体化平台，并非单一工具。下面从定位、核心能力、技术构成、国内对应产品四方面讲清楚。

---

### 一、定位与核心定义
**App Governance Suite（AGS）**：企业级应用全生命周期治理平台，核心是**SAST（静态代码扫描）+ SCA（软件成分分析）+ 合规治理 + 流程闭环**，主打“代码安全左移、合规自动化、风险可治理”。
- 常见误写：AppGavernanceSuit（拼写错误，正确为 Governance / Suite）
- 国内对标：金融/政企常用的**自研代码扫描平台+合规治理模块**，如银行省分科技岗常用的内部安全治理工具。

---

### 二、核心功能（代码扫描是核心模块）
#### 1. 静态代码扫描（SAST，你关注的重点）
- 支持语言：Java/Go/Python/JS/C++/C# 等
- 检测能力：OWASP Top10、代码漏洞（SQL注入/XSS/反序列化）、代码规范（Sonar规则）、质量问题（重复代码/空指针）
- 技术引擎：自研AST（抽象语法树）+ 数据流分析 + 规则库（含国密/金融行业规则）
- 典型场景：开发IDE插件扫描、CI/CD流水线卡点、上线前全量审计

#### 2. 软件成分分析（SCA）
- 开源组件漏洞检测（如Log4j2、FastJSON）
- 许可证合规（GPL/MIT/Apache）、版本管理、依赖树分析

#### 3. 应用治理与合规
- 隐私合规（APP个人信息收集检测，适配《个人信息保护法》）
- 安全策略管理、漏洞闭环（工单/通知）、报表审计（等保/金融合规）

#### 4. 流程集成
- 对接GitLab/Jenkins/企业OA，实现“提交→扫描→卡点→修复→上线”全流程自动化

---

### 三、技术构成（底层和你之前学的Java/安全知识强相关）
1. **代码解析核心**：AST（抽象语法树）+ 控制流/数据流分析，和编译器前端原理一致
2. **漏洞检测引擎**：规则匹配（正则/语法模式）+ 语义分析（减少误报）+ 漏洞链识别（如CC链反序列化检测）
3. **类加载与字节码**：支持对Java字节码（.class）/Jar包直接扫描，用到**双亲委派、自定义类加载器、defineClass** 等底层知识（和你之前问的类加载/反序列化漏洞直接相关）
4. **规则库**：内置金融/政企专用规则（如银行COBOL代码规范、支付系统安全规则）

---

### 四、国内常见AGS类产品（银行/省分科技岗常用）
1. **银行自研平台**（如工行/建行/农行省分）
   - 名称：内部常叫“**应用安全治理平台**”“**代码扫描与合规系统**”
   - 特点：适配COBOL/Java混合架构，深度对接行内流程，省分科技岗负责运维/规则定制/问题闭环
2. **商业工具**
   - 国外：Checkmarx、SonarQube Enterprise、IBM AppScan
   - 国内：Gitee CodePecker（SCA+SAST）、百度移动应用安全治理平台、汉华信安APP合规检测系统

1. **合规硬性要求**：金融/政企必须做代码安全扫描+合规审计，是上线必备条件

在Oracle数据库中，`VARCHAR2` 是一种用于存储可变长度字符数据的数据类型。以下是关于 `VARCHAR2` 数据类型的一些重要信息：

- `VARCHAR2` 是 Oracle 数据库中用于存储可变长度字符串数据的主要类型之一。
- `VARCHAR2(size)` 中的 `size` 指定了该字段可以存储的最大字符数。
- `VARCHAR2` 和 `VARCHAR` 在 Oracle 中是等效的，但是在标准 SQL 中，`VARCHAR` 是用于可变长度字符数据的类型。
- Oracle 中的 `VARCHAR2` 类型不会在存储数据时用尾部空格填充字段值。
- `VARCHAR2` 数据类型适合存储可变长度的字符数据，例如姓名、地址等文本信息。

以下是一个简单的示例，演示了如何在 Oracle 数据库中创建一个表，其中包含一个 `VARCHAR2` 类型的列：

```sql
CREATE TABLE employees (
    employee_id NUMBER,
    first_name VARCHAR2(50),
    last_name VARCHAR2(50)
);
```
在这个示例中，`first_name` 和 `last_name` 列将存储最大长度为 50 个字符的可变长度字符串数据。
请注意，在实际使用中，您可以根据需要调整 `VARCHAR2` 类型的大小，以适应您的数据存储需求。
