# 一、Oracle SQL Developer 两种提交方式
## 方式1：点界面【提交】按钮（图形化）
Oracle SQL Developer 顶部工具栏有两个关键按钮：
- **Commit 提交**：绿色对勾图标
- **Rollback 回滚**：红色叉号图标

操作流程：
执行完 `INSERT / UPDATE / DELETE` → 点**绿色提交按钮** → 数据真正写入数据库，其他会话能查到。

## 方式2：SQL 命令提交 / 回滚（命令行）
### 提交
```sql
COMMIT;
```
### 回滚（放弃所有修改）
```sql
ROLLBACK;
```

---

# 二、核心原理（Oracle 必懂）
1. Oracle **默认事务不自动提交**
   执行 `INSERT/UPDATE/DELETE` 只是在**当前会话缓冲区**生效，**没真正落库**，别的窗口/别人查不到。
2. 必须手动 **COMMIT** 才会：
   - 数据持久化到磁盘
   - 释放行锁
   - 其他会话可见修改
3. 没提交前：
   - 自己会话能看到改后数据
   - 其他会话查到的还是旧数据
   - 还会**锁行**，别人改同一条数据会阻塞等待

---

# 三、设置自动提交（可选）
如果不想每次都手动点提交，可以开自动提交：
1. 顶部菜单：**工具 → 首选项**
2. 数据库 → 编辑器
3. 勾选 **自动提交**

开启后，执行完 DML 语句**自动 commit**，不用手动点按钮、不用写 `COMMIT;`

---

# 四、总结极简口诀
1. Oracle 默认**不自动提交**；
2. 增删改后要么点**绿色提交按钮**，要么执行 `COMMIT;`；
3. 没提交可 `ROLLBACK;` 撤销；
4. 想开自动提交在首选项里勾选即可。

在SQL查询中，WHERE、GROUP BY、和ORDER BY子句通常用于对数据进行筛选、分组和排序。这些子句在SQL语句中的顺序很重要，但它们并不是按照它们在语句中出现的顺序来执行的。了解这些子句的逻辑执行顺序对于编写有效和准确的查询至关重要。

虽然编写SQL查询时，这些子句的顺序通常是：

sql
SELECT ...  
FROM ...  
WHERE ...  
GROUP BY ...  
HAVING ...  
ORDER BY ...
但它们在数据库管理系统中执行的逻辑顺序实际上是这样的：

FROM：首先，从指定的表中检索数据。
WHERE：然后，根据WHERE子句中的条件过滤数据。WHERE子句在数据分组之前应用，因此它会影响哪些行被包括在分组操作中。
GROUP BY：接下来，根据GROUP BY子句中的列或表达式对过滤后的数据行进行分组。这一步会聚合数据，比如计算每个组的总和、平均值等。
HAVING（如果有的话）：HAVING子句在GROUP BY之后执行，用于过滤分组后的数据。与WHERE子句不同，HAVING可以包含聚合函数，因为它是在数据已经分组之后应用的。
SELECT：然后，根据SELECT子句中的指定选择列（包括任何聚合函数的结果）。注意，尽管SELECT子句在查询的开头，但逻辑上它是在过滤和分组之后执行的。
DISTINCT（如果使用了SELECT DISTINCT）：在选择了列之后，如果使用了DISTINCT关键字，则会移除结果集中的重复行。
ORDER BY：最后，根据ORDER BY子句中的列或表达式对结果集进行排序。ORDER BY是查询中最后执行的操作之一，因为它是在所有行都已经被选择、分组（如果有的话）和过滤之后才进行的。
了解这个逻辑顺序对于优化查询性能和编写正确的SQL语句至关重要。例如，知道WHERE子句在GROUP BY之前执行，可以帮助你避免在已经分组的数据上应用不必要的过滤条件，从而可能导致查询性能下降。同样，了解ORDER BY是最后执行的，可以帮助你理解为什么对包含大量行的结果集进行排序可能会非常耗时。
